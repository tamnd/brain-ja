 ## 解決策
 ## 問題の理解

 大きな整数と、その桁の合計に対するしきい値が与えられます。 1 回の操作で数値を 1 ずつインクリメントすることができますが、結果の数値の桁数の合計が十分に小さくなるまで、具体的には最大でも指定された制限以下になるまで、何回増分する必要があるかを知りたいと考えています。 

主な難点は、数値が最大 10^18 まで非常に大きくなる可能性があるため、すべての増分を素朴にシミュレートできないことです。 各テスト ケースは独立しているため、テスト ケースが多数ある場合でも、答えを迅速に計算する必要があります。 

桁合計関数は、ほとんどの増分ではスムーズに動作しますが、キャリーが 9 の長いサフィックスを伝播すると、急激に動作が低下することがあります。 この不規則な構造により、ナイーブ スキャンのコストが高くなる可能性があります。 

単純なアプローチでは、1 つずつ増分し、そのたびに桁の合計を再計算します。 これは、s が小さい n = 10^18 - 1 のような単純なケースではすでに失敗しており、数十億のステップが必要になります。 さらに悪いことに、桁合計の再計算は O(log n) であるため、全体の複雑さは完全に不可能になります。 

n が既に 999999999999999999 のような境界に近づいている場合、より微妙なエッジ ケースが表示されます。一度インクリメントすると、桁の合計が 162 から 1 にリセットされるため、最適な答えは桁の合計の動作が単調ではありません。 正しいソリューションは、滑らかな減衰に依存するのではなく、これらのジャンプの不連続性を考慮する必要があります。 

## アプローチ

 ブルートフォース戦略は簡単です。 n から開始して値を増やし、桁の合計を再計算し、最大 s になった時点で停止することを繰り返します。 これは問題定義に直接従うため、正解です。 

ただし、最悪のケースは、n が 10 のべき乗の大きな境界のすぐ下にあり、s が小さい場合に発生します。 たとえば、n = 999999999999999999 の場合、1000000000000000000 に到達するには 1 回の増分が必要になりますが、以前の構成で運が悪ければ、ブルート フォースによってすべての中間状態が試行されることになります。 より一般的には、ステップ数は 10^18 程度になる可能性があり、シミュレーションが不可能になります。 

重要な観察は、末尾に 9 が多く含まれる数字を交差させた場合にのみ、桁の合計が意味のある変化を起こすということです。 段階的に増分する代わりに、桁数の合計構造が大幅に小さい次の数値にジャンプするという観点から考えることができます。 

digit_sum(n + x) ≤ s となる最小の x を見つけたいと考えています。 x を反復するのではなく、キャリーの後に数字の接尾辞の一部が 0 になる形式の候補ターゲットを構築します。 具体的には、10 進表現の各位置について、右側のすべての桁が 0 になる次の数値に n を切り上げることをシミュレートします。 このような各丸めは、サフィックスのみに依存する値を追加することで達成でき、そのような候補は O(log n) のみです。 

境界候補ごとに、桁の合計を計算し、それが条件を満たすかどうかを確認します。 答えは、すべての候補の中で有効な最小増分です。 

これにより、すべての整数にわたる線形スキャンから桁境界のみのスキャンに問題が軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(答え × log n) | お(1) | 遅すぎる |
 | 桁境界の列挙 | テストあたり O(log n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 数字を簡単に操作できるように、n を文字列として表します。 アイデアは、さまざまな位置でキャリーを強制してみて、その結果の数値を観察することです。

1. 操作を容易にするために、n を数字配列に変換します。 これにより、大きな整数の算術演算ではなく、キャリーを直接推論することができます。 
2. 現在の数値の桁の合計を計算します。 すでに ≤ s である場合は、増分する必要がないため、すぐに 0 を返します。 
3. 数字配列内の各位置 i を、最下位側から最上位側に向かって繰り返します。 各位置は、キャリーが伝播する可能性のある潜在的な境界を表します。 
4. 各位置 i について、i までのプレフィックスを取得し、位置 i に 1 を加算し、i の右側のすべての桁をゼロに設定することによって、候補番号を作成します。 これは、n を次の 10^(k) の倍数に切り上げることをシミュレートします。 
5. この候補を整数に変換し、必要な増分の数 (候補 − n) を計算します。 
6. この候補の桁の合計が ≤ s であるかどうかを確認します。 「はい」の場合、その差を最小限に抑えて回答を更新します。 
7. すべての位置を確認した後、見つかった最小の有効な増分を返します。 

### なぜ効果があるのか

 n 以上のすべての有効なターゲット番号は、n を基準とした最後の非ゼロ桁の変化の位置に関連付けることができます。 最適な解は、桁上げ演算によって数字のサフィックスがクリアされる点、またはその直後に存在する必要があります。 考えられるサフィックスキャリーの境界をすべて列挙することで、桁の合計が大幅に低下する可能性のあるすべての構造点をカバーします。 このような 2 つの境界の間では、桁合計の動作は弱い意味で単調であるため、最適な解が見逃されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def digit_sum(x: int) -> int:
    s = 0
    while x:
        s += x % 10
        x //= 10
    return s

def solve_one(n: int, s: int) -> int:
    if digit_sum(n) <= s:
        return 0

    digits = list(map(int, str(n)))
    m = len(digits)

    # build prefix numbers
    best = 10**30
    cur = 0
    pow10 = 1

    # we try making suffix [i..end] become zeros by rounding up at i
    for i in range(m - 1, -1, -1):
        cur = cur + digits[i] * pow10
        pow10 *= 10

        # candidate is next multiple of pow10
        candidate = ((n // pow10) + 1) * pow10
        if digit_sum(candidate) <= s:
            best = min(best, candidate - n)

    return best

def main():
    t = int(input())
    for _ in range(t):
        n, s = map(int, input().split())
        print(solve_one(n, s))

if __name__ == "__main__":
    main()
```コードはまず、初期数値が既に桁合計の制約を満たしているかどうかをチェックします。 メイン ループは、10 の累乗の接尾辞境界を構築します。 境界の長さごとに、10 のべき乗の次の倍数、つまり少なくとも n を計算します。これは、その桁位置でキャリーを強制することに正確に対応します。 桁合計チェックにより、有効なエンドポイントのみが考慮され、必要な増分が最小限に抑えられます。 

微妙な点は、次の倍数を計算するときに天井分割を正しく処理することです。 これにより、手動による文字列操作が回避され、19999 が 20000 になるようなキャリー伝播チェーンに対して実装が堅牢に保たれます。 

## 実用的な例

 ここでは 2 つのケースを追跡します。1 つは増分が必要ない場合、もう 1 つは丸めが不可欠な場合です。 

### 例 1: n = 500、s = 4

 桁の合計 500、つまり 5 をチェックするので、増加する必要があります。 

| ステップ | 候補者 | n + x | 桁の合計 | 有効 |
 | --- | --- | --- | --- | --- |
 | i = 0 | 1000 | 1000 | 1 | はい |
 | i = 1 | 1000 | 1000 | 1 | はい |
 | i = 2 | 1000 | 1000 | 1 | はい |

 最有力候補は 1000 なので、答えは 500 です。 

これは、複数の境界の選択肢が同じ丸めターゲットに集約される可能性があり、最小距離のみが重要であることを示しています。 

### 例 2: n = 2178、s = 10

 最初の桁の合計は 18 なので、変更が必要です。 

| ステップ | 候補者 | n + x | 桁の合計 | 有効 |
 | --- | --- | --- | --- | --- |
 | i = 0 | 2180 | 2180 | 11 | いいえ |
 | i = 1 | 2200 | 2200 | 4 | はい |
 | i = 2 | 3000 | 3000 | 3 | はい |
 | i = 3 | 10000 | 10000 | 1 | はい |

 有効な最小値は 2200 − 2178 = 22 です。 

このトレースは、以前の桁を桁上げすると桁の合計が大幅に減少する可能性があること、およびすべての桁上げ境界をチェックする必要がある理由を示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | テスト ケースあたり O(log n) | 各桁の位置を 1 回だけ調べて、境界のある数値の桁の合計を計算します。 
| スペース | お(1) | 少数の整数と一時的な数字表現のみを保存します。 

合計桁数は最大 18 であるため、2 × 10^4 のテスト ケースであっても、解は制限内で簡単に実行されます。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    def digit_sum(x: int) -> int:
        s = 0
        while x:
            s += x % 10
            x //= 10
        return s

    def solve_one(n, s):
        if digit_sum(n) <= s:
            return 0
        best = 10**30
        digits = list(map(int, str(n)))
        m = len(digits)
        for i in range(m - 1, -1, -1):
            candidate = ((n // (10**(m - i))) + 1) * (10**(m - i))
            if digit_sum(candidate) <= s:
                best = min(best, candidate - n)
        return best

    out = []
    t = int(input())
    for _ in range(t):
        n, s = map(int, input().split())
        out.append(str(solve_one(n, s)))
    return "\n".join(out)

 ## 特殊なケース

 重要なエッジケースは、n がすべて 9 で構成されている場合です。 たとえば、n = 999、s = 1 です。アルゴリズムでは、桁の合計が 1 である 10 の次のべき乗である 1000 が考慮されるため、正しく 1 が返されます。単純な増分アプローチでは、すべての中間値を調べて失敗します。 

もう 1 つのケースは、n がすでに条件を満たしている場合です。 n = 1 および s = 1 の場合、桁の合計はすでに最小になっており、アルゴリズムは丸め候補を試行せずにすぐに 0 を返します。 

3 番目のケースには、1000000 のような非常に小さな s を持つまばらな数値が含まれます。 最適な答えを得るには、999999 に直接ジャンプする必要があります。これは、最初の非ゼロ桁でのキャリーによって正しい先行構造が生成される境界列挙によって取得されます。
