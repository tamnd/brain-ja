 ## 問題の理解

 長さ 2 のベース文字列とターゲット文字列が与えられます。 せいぜい変更が許される`k`基本文字列内の文字を、任意の位置を任意の小文字に置き換えます。 これらの変更を実行した後、変更された文字列内のサブシーケンスとしてターゲット文字列が何回出現するかを調べます。 

2 文字の文字列の部分一致`t = t0 t1`単なるインデックスのペアです`i < j`そのような`s[i] = t0`そして`s[j] = t1`。 このようなペアはすべて 1 つの出現に寄与するため、このタスクは、最初の文字が次の順序のペアの数を最大化することと同じです。`t0`そして2つ目は`t1`。 

構造は小さいです:`n ≤ 200`, したがって、3次または3次に近い動的計画法を使用することができます。 主な難点は、キャラクターの編集が許可されており、編集ごとに、ローカルだけでなくグローバルに作成される有効なペアの数が変更される可能性があることです。 

素朴に考えれば、それぞれの立場を独立して次のように決定することになるでしょう。`t0`、`t1`、または他のものですが、1 つの位置を変更すると、後または前のすべての位置のペアに影響するため、これは失敗します。 

小さなエッジケースは結合を示しています。 仮定する`s = "aaa"`そして`t = "aa"`。 すでに 3 つのサブシーケンスがあります。 もし`k = 1`、任意の 1 文字を次のように変更します`b`複数のペアを一度に破棄します。 貪欲なローカル変更は、編集を完全に回避する最適なソリューションを見逃してしまいます。 

別の微妙なケースが現れるのは、`t[0] == t[1]`。 次に、等しい文字のペアを数えます。これは、その文字のコピーを何個作成するかによって二次関数的に決まります。 これにより、個別のキャラクターと比較して、最適な直感が大幅に変化します。 

## アプローチ

重要な点は、変更された文字列全体を明示的に追跡する必要がないということです。 サブシーケンスの数はその数にのみ依存します。`t0`それぞれの前に文字が表示されます`t1`キャラクター。 これは、文字列の数を維持しながら、文字列を左から右に処理することを示唆しています。`t0`これまでに形成されたペアの数を確認しました。

 ## アルゴリズムのチュートリアル

 文字列を左から右に処理し、その数を記録する DP テーブルを構築します。`t0`私たちが作成したキャラクターとこれまでに結成したペアの数。 

1. 定義する`dp[i][j][a]`最初に処理した後のサブシーケンスの最大数として`i`文字、使用`j`修正、および作成済み`a`性格の出現`t0`。 ペア数は DP 値に暗黙的に格納されます。 
2.初期化`dp[0][0][0] = 0`。 文字が処理されないということは、ペアも存在しないことを意味します。`t0`文字。 
3. ポジションごとに`i`、現在のキャラクターを考慮してください`s[i]`。 3 つの意味のある役割のいずれかを割り当ててみます。`t0`、作ってください`t1`、または中立キャラクターとして無視します。 
4. 次のように割り当てた場合`t0`の数を増やします。`t0`1 倍します。次の場合、この選択には 1 回の操作が必要になる可能性があります。`s[i] != t0`。 
5. 次のように割り当てると、`t1`、その後、以前のすべての`t0`新しいサブシーケンスを提供します。 したがって、ペア数を現在の数だけ増やします。`t0`これまで見られた。 キャラクターを変更した場合、この選択のコストも 1 になる可能性があります。 
6. 中立キャラクターとして割り当てた場合、それは何も貢献せず、将来のカウントには影響しません。 
7. トランジションごとに、使用された編集数が以下の場合にのみ DP を更新します。`k`。 
8. すべてのポジションを処理した後の答えは、すべての有効な状態にわたる最大ペア数になります。 

重要な構造は、ポジション間の相互作用はカウントによるものだけであるということです。`t0`。 それがわかったら、`t1`決定的に貢献します。 

### なぜ効果があるのか

 どのプレフィックスでも、DP 状態は将来のゲインを計算するために必要なすべてを完全にキャプチャします。`t0`要素は、各フューチャーごとに新しいサブシーケンスの数を決定します。`t1`が生成され、累積ペア数はすでに固定されています。 すべての位置決定は、これら 2 つの量による将来の寄与にのみ影響するため、隠れた依存関係が失われることはありません。 すべての最適な編集シーケンスは 1 つの DP パスに正確に対応し、すべての DP 遷移は有効な編集の選択を表すため、すべての状態の最大値が最適な構成と一致する必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    s = input().strip()
    t = input().strip()
    a, b = t[0], t[1]

    NEG = -10**18

    # dp[j][c0] = max pairs, with j edits, c0 count of t0
    dp = [[NEG] * (n + 1) for _ in range(k + 1)]
    dp[0][0] = 0

    for ch in s:
        ndp = [[NEG] * (n + 1) for _ in range(k + 1)]

        for used in range(k + 1):
            for c0 in range(n + 1):
                cur = dp[used][c0]
                if cur == NEG:
                    continue

                # 1) make it neutral (anything except a or b)
                if used <= k:
                    if ndp[used][c0] < cur:
                        ndp[used][c0] = cur

                # 2) make it t0
                cost = used + (ch != a)
                if cost <= k:
                    ndp[cost][c0 + 1] = max(ndp[cost][c0 + 1], cur)

                # 3) make it t1
                cost = used + (ch != b)
                if cost <= k:
                    ndp[cost][c0] = max(ndp[cost][c0], cur + c0)

        dp = ndp

    ans = 0
    for used in range(k + 1):
        for c0 in range(n + 1):
            ans = max(ans, dp[used][c0])

    print(ans)

if __name__ == "__main__":
    solve()
```コードは、使用された編集と構築された数の 2 次元 DP を維持します。`t0`文字。 各反復では、次の位置のテーブルが再構築されます。 重要な実装の詳細は、`t1`、すぐに追加します`c0`スコアに合わせて、以前に配置されたすべての`t0`それとともに新しい部分列を形成します。 

常に次のことを保証するため、境界の処理は簡単です。`c0 + 1 ≤ n`を超えることはありません`k`あらゆるトランジションで編集します。

 ## 特殊なケース

 いつ`t[0] == t[1]`、同一の文字のすべてのペアが答えに貢献します。 DP はこれを自然に処理します。`t1`追加します`c0`、 そして`t0`そして`t1`同じ記号になります。 アルゴリズムは異なる文字を想定していないため、両方の役割が同じ文字に集約され、正しく蓄積されます。 

いつ`k = 0`、DP では編集なしのトランジションのみが許可されます。 変換パスは調査されないため、最終的な答えは、元の文字列内のサブシーケンスを数えるということになります。 

すべてのキャラクターが変身できるとき`t1`、最適な戦略は最大化することです`t0`早期に残りのポジションを`t1`、DPは増加することによって捕捉します`c0`最初にそれを悪用します。
