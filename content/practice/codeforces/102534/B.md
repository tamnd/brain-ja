 ## 解決策
 ## 問題の理解

 主催者は、T シャツの色を説明する値のリストを持っています。 色ごとに、その色のシャツの正確な数、またはその色のすべてのシャツの割合として値が書き込まれました。 元のシャツの合計数が欠落しているため、タスクはリスト全体を有効にする可能性があるすべての合計を見つけることです。 

選択した合計に対して`T`、値の場合`x`割合を表し、貢献します`T * x / 100`シャツ。 カウントを表す場合、正確に寄与します`x`シャツ。 すべての貢献度の合計は正確に一致する必要があります`T`。 

入力サイズは以下に達します`100000`、値は次のように大きくできます。`10^9`。 すべての小さな値には 2 つの解釈がある可能性があるため、「カウント」または「パーセンテージ」のいずれかへの値の可能なすべての割り当てを試みると、指数関数的な時間が必要になります。 多くの可能性のある合計を直接チェックすることさえ不可能です。 このソリューションでは、パーセンテージが 1 ～ 100 の範囲に制限されているという事実を利用する必要があります。 

厄介なケースは曖昧な値から生じます。 次のような値`50`カウントまたはパーセンテージを指定できます。 たとえば、次の入力を使用します。```
2
1 50
```有効な合計は`2`そして`51`。 合計`2`用途`1`カウントとして、そして`50`割合として。 合計`51`両方の値をカウントとして使用します。 常に最大でも値を扱うソリューション`100`パーセンテージが欠けてしまうため`51`。 

もう 1 つの特殊なケースは、すべての値がパーセンテージである場合です。 このステートメントでは少なくとも 1 つの正確なカウントが保証されているため、これは禁止されています。 例えば：```
3
20 30 50
```3 つの値すべてをパーセンテージとして選択すると、合計パーセンテージが得られます。`100`, しかし、シャツの枚数が決まっている色はないので、その解釈は否定されなければなりません。 

## アプローチ

 ブルート フォース アプローチでは、パーセンテージとして解釈される値のすべてのサブセットが試行されます。 すべてのサブセットについて、考えられる合計を導き出し、それを検証することができます。 考えられるすべての割り当てがチェックされるため、これは正しいですが、最大で`100000`価値観、諦める`2^100000`課題。 だけでも`30`あいまいな値の場合、ケースの数はすでに多すぎます。 

重要な観察は、次の値のみが含まれることです。`1`に`100`パーセンテージにすることもできます。 さらに重要なのは、選択したパーセンテージの合計が最大でも次の値でなければならないということです。`100`。 どのサブセットがこの制限を超えるパーセンテージ合計を作成したかを知る必要はありません。 どの金額が到達可能かを知る必要があるだけです。 

させて`A`すべての入力値の合計になります。 値のサブセットがパーセンテージとして解釈され、それらのパーセンテージの合計が次のようになると仮定します。`q`。 残りの値は固定カウントとして解釈されるため、それらの合計は次のようになります。`A - q`。 合計は以下を満たします。```
A - q + T * q / 100 = T
```並べ替えると次のようになります。```
T = 100 * (A - q) / (100 - q)
```到達可能なすべてのものに対して`q`より小さい`100`、答えの候補を計算し、割り算が正確かどうかを確認できます。 

残る唯一の困難は、少なくとも 1 つの値がカウントとして残るようにすることです。 選択したパーセンテージのサブセットにすべての要素が含まれている場合、割り当ては無効です。 すべての値の合計は通常より大きいため、`100`、これは配列全体の合計が最大でも次の場合にのみ問題になります。`100`。 

可能なパーセンテージの合計は、範囲にわたる小さなサブセット合計の動的プログラミングで見つけることができます。`0`に`100`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | 最適 | O(n + 100^2) | O(100) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての値の合計を計算します。`A`。 より大きい値`100`パーセンテージにすることはできませんが、それでも自然に合計に加わります。 
2. サブセット合計動的計画法を使用して、最大で次の値から到達可能なすべてのパーセンテージ合計を見つけます。`100`。 州`dp[x]`パーセンテージ値の有効な選択が合計パーセンテージを持つことを意味します`x`。 

限界はただ`100`したがって、動的計画法は、次の条件に関係なく一定のサイズになります。`n`。 
3. 到達可能なパーセンテージ合計ごとに`q`から`0`に`99`、計算します:```
numerator = 100 * (A - q)
denominator = 100 - q
```もし`numerator`で割り切れます`denominator`、結果の合計が候補になります。 

1. すべての値をパーセンテージ側に割り当てて作成された候補を拒否します。 これは次の場合にのみ発生します`A == q`すべての値が正であるためです。 
2. 残りの候補をすべて並べ替えて印刷します。 

これが機能する理由: すべての有効な解釈では、値の一部がパーセンテージとして選択されます。 合計式に影響を与えるサブセットからの唯一の情報は、パーセンテージの合計です。`q`。 動的プログラムはあらゆる可能性を見つけ出します`q`したがって、すべての有効な合計が考慮されます。 割り算チェックでは、計算された合計が整数であることが保証され、カウント側チェックでは、少なくとも 1 つの要素が正確な数値として解釈されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    total_sum = sum(a)

    dp = [False] * 101
    dp[0] = True

    for x in a:
        if x <= 100:
            for s in range(100 - x, -1, -1):
                if dp[s]:
                    dp[s + x] = True

    ans = set()

    for q in range(100):
        if not dp[q]:
            continue

        if total_sum == q:
            continue

        num = 100 * (total_sum - q)
        den = 100 - q

        if num % den == 0:
            ans.add(num // den)

    ans = sorted(ans)

    print(len(ans))
    print(*ans)

if __name__ == "__main__":
    solve()
```配列`dp`到達可能なパーセンテージの合計を格納します。 すべての入力値がサブセット内で最大 1 回使用されるように、逆方向に更新されます。 前方反復により、同じ値を複数回カウントできます。 

式は次の場合にのみ評価されます。`q < 100`。 正確な割合の合計`100`分母をゼロにしてしまいます。 このようなケースでは、すべての値がパーセンテージとして扱われる状況のみを説明できますが、正確なカウントが 1 つ存在する必要があるため、これは無効です。 

Python の整数はオーバーフローしないため、次の乗算は`100`入力値が大きい場合でも安心です。

## テストケース```python
import sys
import io

def solve_io(inp: str) -> str:
    old = sys.stdin
    sys.stdin = io.StringIO(inp)
    data = sys.stdin.readline

    n = int(data())
    a = list(map(int, data().split()))

    total_sum = sum(a)

    dp = [False] * 101
    dp[0] = True

    for x in a:
        if x <= 100:
            for s in range(100 - x, -1, -1):
                if dp[s]:
                    dp[s + x] = True

    ans = set()

    for q in range(100):
        if dp[q] and total_sum != q:
            num = 100 * (total_sum - q)
            den = 100 - q
            if num % den == 0:
                ans.add(num // den)

    res = str(len(ans)) + "\n" + " ".join(map(str, sorted(ans))) + "\n"

    sys.stdin = old
    return res

assert solve_io("2\n1 50\n") == "2\n2 51\n"
assert solve_io("3\n20 30 70\n") == "4\n120 125 140 300\n"

assert solve_io("1\n100\n") == "1\n100\n"
assert solve_io("4\n2 40 90 5\n") == "3\n137 470 840\n"
assert solve_io("3\n10 20 30\n") == "1\n60\n"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1 / 100`|`100`| 単一値と境界パーセンテージの処理 |
 |`2 / 1 50`|`2 51`| カウントまたはパーセンテージのいずれかの値 |
 |`3 / 10 20 30`|`60`| すべての値はカウントとして解釈されます。

 ## 特殊なケース

 値が可能な数と可能なパーセンテージの両方である場合、アルゴリズムはさまざまなパーセンテージの合計を通じて両方の可能性を考慮します。 入力の場合:```
2
1 50
```

`q = 0`合計を与える`51`、 その間`q = 50`合計を与える`2`。 どちらも答えに残ります。 

すべての値の合計が正確に可能なパーセンテージ合計になると、アルゴリズムはすべての値がパーセンテージになる無効な解釈を削除します。 入力の場合:```
3
20 30 50
```サブセットの合計`100`存在しますが、正確な数は残りません。 この問題には少なくとも 1 つの正確なカウントが必要であるため、解釈は破棄されます。 

大きな値が表示される場合、パーセンテージは最大値であるため、パーセンテージにすることはできません。`100`。 彼らは今でも貢献しています`A`、同じ数式がそれらを自動的に処理します。 たとえば、次のような値`1000000000`はカウント側にのみ留まることができるため、不要な分岐が防止されます。
