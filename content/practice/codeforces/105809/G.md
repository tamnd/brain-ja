 ## 解決策
 ## 問題の理解

 ビー玉のコレクションがあり、それぞれに整数が含まれています。 1 人のプレイヤー、セバスチャンが奇数のビー玉をすべて取ります。 もう一方のプレイヤー、セバスティアンは、偶数のビー玉をすべて受け取ります。 

勝者は、各プレイヤーが受け取ったビー玉の数によってのみ決定されます。 カウントが同じ場合は、セバスチャンが同点で勝ちます。 アウトプットしなければなりません`"Sebastian"`セバスチャンが厳密にセバスチャンよりも多くのビー玉を持っている場合。 それ以外の場合は出力します`"Notbastian"`。 

入力は整数で構成されます`n`、 に続く`n`大理石の価値。 実際の値は次のように大きくなります。`10^9`ただし、重要なのはそれらの同等性だけです。 以来`n`せいぜい`10^6`、各ビー玉を 1 回検査するアルゴリズムは簡単に十分に高速ですが、線形時間より大幅に高価なものは不要です。 100 万個の番号を使用すると、`O(n)`scan は約 100 万回の操作を実行しますが、これは制限内では取るに足らないものです。 

ミスの主な原因はタイルールです。 

考慮する：```
4
1 1 2 2
```奇数のビー玉が 2 つと偶数のビー玉が 2 つあります。 カウントが等しいため、セバスチャンが勝ち、セバスチャンが名前を保持しないことを意味します。 正しい出力は次のとおりです。```
Notbastian
```をチェックする不注意な実装`even_count >= odd_count`間違って印刷されてしまう`"Sebastian"`。 

もう 1 つの見落としやすいケースは、すべてのビー玉が 1 人のプレイヤーのものである場合です。```
3
2 4 6
```Sebastiàn は 3 つのビー玉すべてを取得しますが、Sebastian は何も取得しないため、正しい出力は次のようになります。```
Sebastian
```同じく：```
3
1 3 5
```与える```
Notbastian
```セバスチャンが受け取るビー玉がゼロだからです。 

## アプローチ

 最も直接的な解決策は、ルールを正確にシミュレートすることです。 すべてのビー玉について、その数が偶数か奇数かを判断し、対応するカウンタをインクリメントします。 最後に、ゲームの勝利条件に応じて 2 つのカウンターを比較します。 

Sebastian のビー玉と Sebastiàn のビー玉を別々の配列に明示的に格納し、それらのサイズを比較するという強引な解釈を想像することもできます。 ゲームの結果は各プレイヤーが受け取るビー玉の数のみに依存するため、これは正しいです。 ただし、カウントのみが重要であるため、追加のストレージは不要です。 

重要な観察は、大理石の値自体が同等以上の結果に影響を与えることはないということです。 大理石に含まれているかどうかは気にしません`2`または`1000000000`、偶数かどうかだけ。 これを認識すると、問題全体は偶数と奇数を数えるということになります。 

数えた後、セバスチャンは偶数ビー玉の数が奇数ビー玉の数より厳密に大きい場合にのみその名前を保持します。 同点を含む他のすべての状況は、`"Notbastian"`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 両方のプレイヤーのビー玉を明示的に保存する | O(n) | O(n) | 受け入れられるが不要 |
 | 偶数と奇数を数える | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む`n`そして`n`大理石の価値。 
2.初期化`even_count = 0`そして`odd_count = 0`。 
3. すべてのマーブル値をスキャンします。 
4. 値が偶数の場合はインクリメントします`even_count`; それ以外の場合は増分します`odd_count`。 
5. すべてのビー玉を処理した後、個数を比較します。 
6. もし`even_count > odd_count`、印刷`"Sebastian"`セバスチャンはビー玉をもっと持っているからです。 
7. それ以外の場合は印刷します`"Notbastian"`。 これには、セバスチャンがルールで勝つ同点の場合も含まれます。 

### なぜ効果があるのか

 すべてのビー玉は、パリティのみに基づいて、正確に 1 人のプレイヤーに属します。 偶数を数えるとセバスチャンが受け取ったビー玉の数が得られ、奇数を数えるとセバスチャンが受け取ったビー玉の数が得られます。 勝者はこれらのカウントを比較することによって完全に定義され、セバスチャンに同点が与えられます。 アルゴリズムはこれら 2 つの量を正確に計算し、指定された比較ルールを適用するため、常に正しい答えが生成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

even_count = 0

for x in a:
    if x % 2 == 0:
        even_count += 1

odd_count = n - even_count

if even_count > odd_count:
    print("Sebastian")
else:
    print("Notbastian")
```このソリューションは、配列に対して 1 回のパスを実行し、偶数の値をカウントします。 すべてのビー玉は偶数か奇数のいずれかであるため、奇数の数は次のように計算できます。`n - even_count`。 

最後の比較は厳密です。 これは最も重要な実装の詳細です。 使用する`>=`は、声明と矛盾して、セバスチャンに誤ってネクタイを授与することになるだろう。 

カウントが超過することはないため、オーバーフローの問題は発生しません。`n`、最大でも`10^6`。

まで`10^6`ビー玉の場合、リニア スキャンは簡単に十分に高速です。 メモリ使用量は入力サイズに関係なく一定に保たれます。

# helper: run solution on input string, return output string
import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    a = list(map(int, input().split()))

        return "Sebastian\n"
