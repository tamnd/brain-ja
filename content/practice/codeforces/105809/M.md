 ## 解決策
 ## 問題の理解

 平面上に 2 セットの無限の軸が揃った線があります。 

最初のセットには、所定の位置に垂直線が含まれています$x_i$。 2 番目のセットには、次の位置に水平線が含まれています。$y_j$。 

対角線セグメントは次から始まります$(h,0)$に$(h+l,l)$。 その傾きは$1$、そのセグメント上のすべての整数点は次の形式になります。$(h+t,t)$のために$0 \le t \le l$。 そのような点ごとに、対角線に垂直に、右を指す光線を発射します。 タスクは、どの描画線が最初にヒットするかを決定することです。 最初のヒットが垂直線の場合、次のように出力します。`A`その後に元のインデックスが続きます。 横線の場合は印刷します`T`その後に元のインデックスが続きます。 同点は水平線を優先して解決されます。 何もヒットしなかった場合は、印刷します`-1`。 

入力制限は重要な観察事項です。 我々は持っています$N+M \le 10^6$、 そして$l$にも到達できます$10^6$。 すべての光線に対して二分探索を実行するソリューションはすでに存在しているでしょう。$10^6 \log 10^6$これは許容範囲ですが、よりクリーンな線形スイープがあります。 すべてのレイをすべてのラインと比較するアプローチでは、次のようなものが必要になります。$10^{12}$操作は不可能であり、完全に実行不可能です。 

微妙なケースはジオメトリから生じます。 

考慮する：```
1 1
1
0
0 0
```唯一の光線は次から始まります$(0,0)$。 縦線は 1 単位離れていますが、横線はすでに開始点にあります。 正しい答えは次のとおりです。```
T0
```距離ゼロの交差点を無視する不注意な実装では、垂直線が誤って選択されてしまいます。 

もう 1 つの重要なケースは引き分けです。```
1 1
5
2
3 2
```ポイントとしては$(4,1)$、最も近い垂直交差と水平交差は光線に沿って同じ距離に発生します。 このステートメントでは水平線を選択する必要があるため、答えでは次を使用する必要があります。`T`、 ない`A`。 

最後に、光線の中には何にも当たらないものもあります。```
1 1
0
100
10 0
```レイは次から始まります$(10,0)$、右下に移動しますが、垂直線に到達できません。$x=0$、そしてすでに水平線の下にあります$y=100$。 正しい出力は次のとおりです。```
-1
```## アプローチ

 ブルートフォースのアイデアは単純です。 対角線上のすべての整数点について、その光線がすべての垂直線とすべての水平線と交差する場所を計算します。 光線に沿った最小距離の有効な交点を維持します。 これは、すべての候補を明示的に評価するため、正しいです。 残念ながら、$l+1$光線と最大$10^6$おおよその方向につながる線$10^{12}$最悪の場合のチェック。 

これを改善するには、単一の光線の形状を理解する必要があります。 

対角線は$y=x-h$、それに関するポイントは次のとおりです$(h+t,t)$。 

右を指す垂直光線には方向があります$(1,-1)$。 そのパラメトリック形式は次のとおりです。$$x=h+t+u,\qquad y=t-u,\qquad u\ge 0.$$縦ラインの場合$x=a$、交差点は次の場所で発生します。$$u=a-(h+t).$$これは次の場合にのみ有効です。$a \ge h+t$。 

すべての縦線の中で、最も小さいものだけが、$x_i$満足のいく$x_i \ge h+t$最初の垂直ヒットになる可能性があります。 

水平線の場合$y=b$、交差点は次の場所で発生します。$$u=t-b.$$これは次の場合にのみ有効です。$b \le t$。 

すべての水平線の中で最大のものだけが、$y_j$満足のいく$y_j \le t$最初の水平ヒットになる可能性があります。 

問題は、整数範囲に対する後続クエリと先行クエリのシーケンスになっています。 

として$t$から増加します$0$に$l$、値$h+t$も単調増加します。 つまり、2 回の線形スイープですべての光線を処理できるということです。 

垂直線の場合、最初の行へのポインタを保持します。$x$- 座標は少なくとも現在のものです$h+t$。 

水平線の場合、その最大の線へのポインタを保持します。$y$- 座標は最大でも現在のものです$t$。 

各ポインターは前方にのみ移動するため、全体の作業は直線的になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O((l+1)(N+M))$|$O(1)$| 遅すぎる |
 | 最適 |$O(N\log N + M\log M + l)$|$O(l)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての垂直線を次のように保存します`(x_position, original_index)`そして並べ替えて`x_position`。 
2. すべての水平線を次のように保存します。`(y_position, original_index)`そして並べ替えて`y_position`。 
3. あらゆる値について`t`から`0`に`l`、 させて`s = h + t`。 
4. ソートされた垂直配列にポインタを保持します。 現在の行が残っている間に前に移動します。`x < s`。 尖った線は、右側に最も近い垂直線 (そのような線が存在する場合) になります。 
5. 垂直距離パラメータを計算します。$$u_v = x_i - s$$有効な垂直線が存在しない場合は、距離を無限大として扱います。 
6. ソートされた水平配列内に別のポインタを保持します。 次の行は満たしますが、`y <= t`、ポインタを進めます。 
7. 尖った水平線が最大になります。`y_j <= t`、これはまさに光線が当たった最初の水平線です。 
8. コンピューティング$$u_h = t - y_j$$そのような水平線が存在しない場合は、距離を無限大として扱います。 
9. 2 つの距離を比較します。 

もし`u_h <= u_v`、水平線を出力します。 

それ以外の場合は縦線を出力します。 
10. 両方の距離が無限大の場合、出力`-1`。 

### なぜ効果があるのか

 固定光線の場合、すべての有効な垂直交差点には距離パラメータがあります。$$u=x_i-(h+t).$$有効な最小距離は最小値から求められます。$x_i$それはまだ少なくとも$h+t$。 垂直線が大きいほど、距離は長くなります。 

同様に、すべての有効な水平交差点には距離パラメータがあります。$$u=t-y_j.$$有効な最小距離は最大距離から得られます。$y_j$それはまだせいぜい$t$。 水平線が低いほど、距離が長くなります。 

アルゴリズムは常に、これら 2 つの最適な候補を正確に比較します。 1 つおきの線はさらに遠くにあるため、選択された線は正確に光線と交差する最初の線になります。 タイルールは次のように処理されます。`<=`比較では。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    xs = list(map(int, input().split()))
    ys = list(map(int, input().split()))

    h, l = map(int, input().split())

    vert = sorted((x, i) for i, x in enumerate(xs))
    hori = sorted((y, i) for i, y in enumerate(ys))

    ans = []

    pv = 0
    ph = -1

    for t in range(l + 1):
        s = h + t

        while pv < n and vert[pv][0] < s:
            pv += 1

        while ph + 1 < m and hori[ph + 1][0] <= t:
            ph += 1

        best_v = None
        dist_v = 10**30

        if pv < n:
            dist_v = vert[pv][0] - s
            best_v = vert[pv][1]

        best_h = None
        dist_h = 10**30

        if ph >= 0:
            dist_h = t - hori[ph][0]
            best_h = hori[ph][1]

        if dist_v == 10**30 and dist_h == 10**30:
            ans.append("-1")
        elif dist_h <= dist_v:
            ans.append(f"T{best_h}")
        else:
            ans.append(f"A{best_v}")

    print(" ".join(ans))

solve()
```ソートされた垂直配列により、後続ポインターを維持できます。 垂直線が現在の光線に対して左端になりすぎると、再び関連することはありません。`h+t`増えるだけです。 

水平スイープでは、同じ考え方を逆に使用します。 ポインタは常に最大のものをマークします`y`現在の値にすでに達しています`t`。 

無限値は非常に大きな整数で表されます。 これにより、特殊な場合の比較ロジックが回避されます。 

タイルールは次のように実装されます。`dist_h <= dist_v`。 それを厳密なものに変更すると、`<`等距離交差点では誤った答えが生成されます。

import io

def run(inp: str) -> str:

    import sys
    input = sys.stdin.readline

    n, m = map(int, input().split())
    xs = list(map(int, input().split()))
    ys = list(map(int, input().split()))
    h, l = map(int, input().split())

    vert = sorted((x, i) for i, x in enumerate(xs))
    hori = sorted((y, i) for i, y in enumerate(ys))

    ans = []
    pv = 0
    ph = -1

    for t in range(l + 1):
        s = h + t

        while pv < n and vert[pv][0] < s:
            pv += 1

        while ph + 1 < m and hori[ph + 1][0] <= t:
            ph += 1

        dv = INF
        dh = INF

        if pv < n:

        elif dh <= dv:
            ans.append(f"T{hori[ph][1]}")

 ## 特殊なケース

 ゼロ距離交差点を考えてみましょう。```
1 1
1
0
0 0
```のために`t = 0`、水平線は次の条件を満たします。`y = 0`、 それで`uh = 0`。 最も近い垂直線は、`uv = 1`。 以来`0 <= 1`、アルゴリズムの出力`T0`。 距離ゼロを無視する実装はここで失敗します。 

ネクタイを考えてみましょう。```
1 1
2
0
1 1
```のために`t = 1`、レイは次から始まります`(2,1)`。 距離を置いてすぐに縦線に到達`0`、水平線も離れていますが、`1 - 0 = 1`前のレイの場合。 比較には、`<=`したがって、等距離では常に必要に応じて水平線が正確に選択されます。 

到達不可能な構成を考えてみましょう。```
1 1
0
100
10 0
```すべての垂直線が開始点の左側にあるため、後続のクエリでは垂直線が見つかりません。 すべての水平線が光線の上にあるため、先行クエリでは水平線が見つかりません。 両方の距離が無限大になり、アルゴリズムは次のように出力します。`-1`。 これは幾何学的解釈と直接一致します。
