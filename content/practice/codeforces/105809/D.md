 ## 解決策
 ## 問題の理解

 2種類のトークンをご用意しております。 

最初の種類はラベルで構成されます`1, 2, ..., m`。 これらのトークンはそれぞれ一意であるため、ラベルは 1 つの配置内に最大 1 回しか出現できません。 

2 番目の種類は次のもので構成されます。`n`ラベルのコピー`0`。 これらのコピーは区別できないため、配置では値がどこにあるかだけが考慮されます。`0`どの物理ゼロトークンが使用されたかは表示されません。 

アレンジメントとは、その長さの順序付けられたシーケンスです。`L`からの任意の値を指定できます`1`に`n`。 

有効な長さごとに、ゼロ以外の各ラベルが最大 1 回使用されるというルールの下で、形成できる異なるシーケンスの数を数えなければなりません。 答えは必須です`10^9 + 7`。 

制約は、組み合わせによる計数ソリューションを示唆するのに十分小さいものです。 両方`m`そして`n`せいぜい`1000`、だから、`O(nm)`アルゴリズムは約 100 万回の反復を実行しますが、これは十分に高速です。 有効なシーケンスの数は指数関数的に増加するため、配置を強引に生成することは不可能です。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

仮定する`m = 1`そして`n = 1`。```
Input
1 1
```有効な取り決めは次のとおりです。`[0]`そして`[1]`、したがって、答えは次のとおりです`2`。 

ゼロ以外のトークンを含む取り決めのみをカウントするソリューションでは、誤って返されます。`1`。 

考慮する：```
Input
2 2
```長さ`2`などのアレンジメントが含まれています`[0,0]`、`[0,1]`、`[1,0]`、`[1,2]`、 そして`[2,1]`。 アレンジメント`[1,1]`トークンなので違法です`1`は一意であり、再利用できません。 ゼロ以外のラベルを再利用可能として扱うカウント式は過剰カウントになります。 

もう 1 つの重要なケースは、必要な長さが一意のラベルの数を超える場合です。```
m = 2, L = 5
```最大 2 つのゼロ以外のラベルを表示できます。 許可されるあらゆる式`k > m`ゼロ以外の個別のトークンは不可能な取り決めをカウントします。 

## アプローチ

 最も直接的なアイデアは、許容されるすべての長さのすべてのアレンジメントを生成し、それをセットに挿入することです。 すべての有効なシーケンスが明示的に構築され、1 回カウントされるため、これは正しいです。 

問題は、中程度の値であっても、アレンジメントの数が膨大になることです。 検索スペースは長さに応じて指数関数的に増大するため、総当たり攻撃は完全に不可能になります。 

シーケンスを生成する代わりに、シーケンスをカウントすることができます。 

長さを固定する`L`。 させて`k`は、取り決めで使用されるゼロ以外のトークンの数になります。 

ラベル以来`1..m`まさにユニークです`k`異なるラベルを選択する必要があり、選択したラベルはそれぞれ 1 回表示されます。 

まずはどれを選ぶか`k`間の地位`L`位置にはゼロ以外のラベルが含まれます。 これは貢献します$$\binom{L}{k}$$方法。 

さあ、それらを埋めてください`k`からの異なるラベルが付いた位置`1..m`。 

順序付けられた選択が必要です`k`個別のラベル、つまり$$P(m,k)=m(m-1)\cdots(m-k+1)$$方法。 

独立した選択肢を掛け合わせると、$$\binom{L}{k} P(m,k).$$すべての有効な値を合計する`k`長さのすべての配置をカウントします`L`。$$\text{count}(L)
=
\sum_{k=0}^{\min(L,m)}
\binom{L}{k} P(m,k).$$最後に、許可されているすべての長さを合計します。$$\text{answer}
=
\sum_{L=1}^{n}
\sum_{k=0}^{\min(L,m)}
\binom{L}{k} P(m,k).$$以来`m,n ≤ 1000`、この二重和は次のように評価できます。`O(nm)`事前計算された階乗と逆階乗を使用した時間。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | 指数 | 遅すぎる |
 | 最適 | O(nm) | O(m+n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む`m`そして`n`。 
2. 階乗を事前計算します。`max(m,n)`モジュロ`10^9 + 7`。 
3. フェルマーの定理を使用して逆階乗を事前計算します。 
4.あらゆる長さに対して`L`から`1`に`n`、反復します`k`から`0`に`min(L,m)`。 
5. コンピューティング$$\binom{L}{k}
=
\frac{L!}{k!(L-k)!}$$階乗と逆階乗を使用します。 
6. コンピューティング$$P(m,k)
=
\frac{m!}{(m-k)!}.$$7.追加$$\binom{L}{k}P(m,k)$$答えのモジュロ`10^9 + 7`。 
8. 最終的な合計を出力します。 

### なぜ効果があるのか

 あらゆる長さのアレンジ`L`何らかの数字が含まれている`k`ゼロ以外のラベルの数。 

一度`k`が固定されている場合、配置は 2 つの決定によって一意に決定されます。つまり、どの位置に非ゼロのラベルが含まれるか、およびどの順序付きの別個のラベルのセットがそれらの位置を占めるかです。 

要因`C(L,k)`ポジションの選択を考慮します。 要因`P(m,k)`個別のラベルの順序付けされた割り当てをカウントします。 すべての有効な配置は、そのような選択肢の 1 つのペアに正確に対応し、そのようなすべてのペアが有効な配置を生成します。 

有効なすべての合計`k`値はすべての配置を 1 回だけカウントします。 すべての長さを合計すると、問題内のすべての有効な配置がカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

m, n = map(int, input().split())

mx = max(m, n)

fact = [1] * (mx + 1)
for i in range(1, mx + 1):
    fact[i] = fact[i - 1] * i % MOD

inv_fact = [1] * (mx + 1)
inv_fact[mx] = pow(fact[mx], MOD - 2, MOD)

for i in range(mx, 0, -1):
    inv_fact[i - 1] = inv_fact[i] * i % MOD

def comb(a, b):
    if b < 0 or b > a:
        return 0
    return fact[a] * inv_fact[b] % MOD * inv_fact[a - b] % MOD

ans = 0
fact_m = fact[m]

for L in range(1, n + 1):
    limit = min(L, m)
    for k in range(limit + 1):
        perm = fact_m * inv_fact[m - k] % MOD
        ans = (ans + comb(L, k) * perm) % MOD

print(ans)
```階乗配列と逆階乗配列を使用すると、すべての組み合わせ値を一定時間で計算できます。 

順列数$$P(m,k)=\frac{m!}{(m-k)!}$$も同じテーブルから一定時間で取得されます。 

ネストされたループは、すべての有効なペアを反復処理します。`(L,k)`。 以来`L`決して超えない`1000`、合計の反復回数は約 100 万回であり、制限内に十分収まります。 

よくある間違いはケースを忘れることです`k = 0`。 この用語は、次のような完全にゼロで構成される配置を表します。`[0]`または`[0,0,0]`。 これらの取り決めは有効であり、カウントする必要があります。 

もう 1 つのよくある間違いは、`k > m`。 あるのは`m`個別のゼロ以外のラベルが利用できるため、そのような状態は不可能です。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

MOD = 10**9 + 7

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    m, n = map(int, input().split())

    mx = max(m, n)

    fact = [1] * (mx + 1)
    for i in range(1, mx + 1):
        fact[i] = fact[i - 1] * i % MOD

    inv_fact = [1] * (mx + 1)
    inv_fact[mx] = pow(fact[mx], MOD - 2, MOD)

    for i in range(mx, 0, -1):
        inv_fact[i - 1] = inv_fact[i] * i % MOD

    ans = 0

    for L in range(1, n + 1):
        for k in range(min(L, m) + 1):
            c = fact[L] * inv_fact[k] % MOD * inv_fact[L - k] % MOD
            p = fact[m] * inv_fact[m - k] % MOD
            ans = (ans + c * p) % MOD

    return str(ans) + "\n"

# provided sample
assert run("2 2\n") == "10\n", "sample 1"

# custom cases
assert run("1 1\n") == "2\n", "minimum size"
assert run("1 2\n") == "5\n", "single unique token"
assert run("2 1\n") == "3\n", "length one"
assert run("3 2\n") == "17\n", "all transition cases"
```| テスト入力 | 期待される出力 | 検証内容 |

 ## 特殊なケース

 次のことを考慮してください。```
1 1
```のために`L = 1`、アルゴリズムは次のように評価します`k = 0`そして`k = 1`。`k = 0`アレンジに貢献している`[0]`。`k = 1`アレンジに貢献している`[1]`。 

答えは次のようになります`2`、それは正しいです。 開始される実装`k`から`1`見逃すだろう`[0]`。 

考慮する：```
2 2
```のために`L = 2`、アルゴリズムが許可するのは`k = 0, 1, 2`。 

いつ`k = 2`、貢献度は$$C(2,2)\cdot P(2,2)=1\cdot2.$$これらはまさに`[1,2]`そして`[2,1]`。 

無効なシーケンス`[1,1]`そして`[2,2]`決して現れないので`P(2,2)`個別のラベルの順序付けされた選択をカウントします。 

考慮する：```
2 5
```長さは 5 ですが、ループにより制限されます。$$k \le \min(L,m)=2.$$存在するのは 2 つだけであるため、アルゴリズムは 3 つの異なるゼロ以外のラベルを使用しようとはしません。 これにより、一意性制約が正しく適用されます。
