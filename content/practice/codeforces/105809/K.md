 ## 解決策
 ## 問題の理解

 長さの配列が与えられます`n`そして限界`k`。 配列を可能な限り最小数の連続セグメントに分割したいと考えています。 すべてのセグメント内では、個別の値の数が次を超えてはなりません`k`。 

タスクは、有効なパーティションをすべてカウントすることではありません。 個別の値の制限を尊重しながら、配列全体をカバーするために必要なセグメントの最小数のみが必要です。 

制約は非常に明らかです。 配列の長さは次のとおりです`10^5`したがって、すべての部分配列を検査したり、すべての間隔にわたって動的プログラミングを実行したりするアルゴリズムは、コストが高すぎます。 アン`O(n²)`解決策には約が必要です`10^10`最悪の場合の操作は完全に不可能です。 線形時間に近いものが必要です。 

もう 1 つの有益な観察は、値の範囲から得られます。 すべての配列要素は次の条件を満たします`1 ≤ a[i] ≤ 1000`、 そして`k ≤ 1000`。 値が小さいため、スライディング ウィンドウ内の要素の周波数を維持するのは非常にコストがかかります。 

よくある間違いは、セグメントの長さのバランスをとると効果があると考えることです。 目的は、セグメントの数を最小限に抑えることだけです。 セグメントサイズ自体は無関係です。 

次の配列を考えてみましょう。```
3 1
1 2 3
```各セグメントには最大 1 つの異なる値を含めることができます。 唯一の有効なパーティションは次のとおりです。```
[1] [2] [3]
```答えは次のとおりです。```
3
```もう 1 つの見落としやすいケースは次のとおりです。```
5 2
1 2 1 2 3
```不注意な戦略は、セグメントにすでに含まれている時点で切断される可能性があります。`k`明確な価値観。 これにより、以下が生成されます。```
[1 2 1 2] [3]
```これは実際に最適であり、答えを与えます`2`。 

重要な詳細は、セグメントに正確に含まれる可能性があるということです。`k`明確な価値観。 次の要素を追加するとカウントがそれ以上増加する場合にのみ、カットする必要があります。`k`。 

3 番目のエッジ ケースは、すべての値が同一である場合です。```
3 1
1 1 1
```配列全体がすでに条件を満たしているため、答えは次のようになります。```
1
```繰り返される境界に遭遇するたびに新しいセグメントを盲目的に作成する実装は、ここで失敗します。 

## アプローチ

 最も直接的な強引なアイデアは、左から右にセグメントを構築し、すべての開始位置について、個別の値を数えながら、考えられるすべての終了位置を試してみることです。 セグメントを選択したら、残りのサフィックスを再帰的に調べます。 

すべての有効なパーティションを探索できるため、これが機能します。 問題は間隔の数です。 がある`O(n²)`サブ配列、個別のカウントを効率的にチェックしても、全体の複雑さは解消されません。 と`n = 10^5`、そのようなアプローチは絶望的です。 

重要な点は、最小限の数のセグメントのみが必要であり、各セグメントは個別の値の最大数によって制約されるということです。 

現在セグメントを構築しているとします。 次の要素を追加しても、最大でも個別の値の数が維持される限り、`k`、セグメントを延長することは決して害を及ぼすことはありません。 セグメントを長くすると、後のセグメントに残される要素が少なくなるだけです。 私たちの目標はセグメントの数を最小限に抑えることなので、常に現在のセグメントを可能な限り拡張する必要があります。 

これはすぐに貪欲な戦略を示唆します。 セグメントを開始し、セグメントに含まれる要素が最大である間は要素を追加し続けます。`k`個別の値、および次の要素が作成される瞬間`(k+1)`- 番目の個別の値を指定すると、現在のセグメントを閉じて、その要素から新しいセグメントを開始します。 

なぜこの貪欲な選択が最適なのでしょうか? 有効なパーティションは、現在のセグメントが終了する時点までに終了する必要があります。`(k+1)`-番目の個別の値が表示されます。 貪欲なセグメントは最も長い有効なセグメントです。 短い最初のセグメントをこの最長の有効なセグメントに置き換えても、後で必要なセグメントの数を増やすことはできません。 残りのサフィックスに対して同じ引数を繰り返すと、最適性が証明されます。 

なぜなら、値は最大でも`1000`、要素ごとに一定時間内に周波数と個別の値の現在の数を維持できます。 各要素は 1 回だけ処理されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 最適な貪欲な個別値のカウント | O(n) | O(1000) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 値の周波数配列を作成する`1..1000`。 
2. 1 つのセグメントと空の周波数構造から始めます。 
3. 配列を左から右に走査します。 
4. 現在値について`x`、現在のセグメントにすでに存在するかどうかを確認します。 
5. もし`x`は新しく、現在のセグメントにはすでに正確に含まれています`k`個別の値を追加してから`x`制約に違反することになります。 新しいセグメントを開始します。 

すべての周波数をリセットし、個別のカウンターをゼロにリセットし、答えを 1 つ増やします。 
6.挿入`x`周波数を更新することで現在のセグメントに変換されます。 
7. これが初めて発生した場合`x`現在のセグメントで、個別のカウンタを増やします。 
8. すべての要素を処理した後、セグメントの数を出力します。 

### なぜ効果があるのか

 どの時点でも、アルゴリズムによって維持される現在のセグメントは、現在の位置で終わる最長の有効なセグメントです。 新しい個別の値によってカウントが超過するたびに、`k`、すべての有効なパーティションは、その値の前に現在のセグメントを強制的に終了します。 貪欲な選択では、可能な限りカットを遅らせ、実現可能な最大のセグメントを生成します。 最初のセグメントが大きいほど、残りのサフィックスに小さい最初のセグメントよりも多くのセグメントが必要になることはありません。 この引数を繰り返し適用すると、可能な限り最小のセグメント数を持つパーティションが生成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())
a = list(map(int, input().split()))

freq = [0] * 1001
distinct = 0
ans = 1

for x in a:
    if freq[x] == 0 and distinct == k:
        ans += 1
        freq = [0] * 1001
        distinct = 0

    if freq[x] == 0:
        distinct += 1
    freq[x] += 1

print(ans)
```実装は貪欲な戦略に正確に従っています。 

変数`distinct`アクティブなセグメントに現在存在するさまざまな値の数を保存します。 周波数配列を使用すると、値がそのセグメント内で初めて出現するかどうかを一定時間で判断できます。 

微妙な部分は操作の順序です。 まず、現在の値を追加すると個別の値の制限を超えるかどうかを確認する必要があります。 新しいセグメントが必要かどうかを判断した後でのみ、値を挿入します。 

新しいセグメントが開始されると、現在の要素はその新しいセグメントに属します。 これが、挿入ロジックがリセット後に実行される理由です。 

値の範囲は次のように制限されます。`1000`したがって、周波数配列のリセットにかかるコストはわずかです。`O(1000)`時間。 せいぜい`n`セグメントが存在する可能性があり、`1000`が定数である場合、全体の複雑さは線形のままです。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    freq = [0] * 1001
    distinct = 0
    ans = 1

    for x in a:
        if freq[x] == 0 and distinct == k:
            ans += 1
            freq = [0] * 1001
            distinct = 0

        if freq[x] == 0:
            distinct += 1
        freq[x] += 1

    print(ans)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out

    solve()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out.getvalue().strip()

# provided samples
assert run("3 1\n1 2 3\n") == "3"
assert run("3 2\n1 2 3\n") == "2"
assert run("3 1\n1 1 1\n") == "1"

assert run("1 1\n7\n") == "1"
assert run("5 5\n1 2 3 4 5\n") == "1"
assert run("6 2\n1 2 1 2 1 2\n") == "1"
assert run("6 2\n1 2 3 1 2 3\n") == "3"

 ## 特殊なケース

 次のことを考慮してください。```
3 1
1 2 3
```アルゴリズムはセグメント数から始まります`1`。 読んだ後`1`の場合、セグメントには 1 つの異なる値があります。 読む`2`2 番目の個別の値が作成されますが、`k = 1`、新しいセグメントが始まります。 同じことが起こります`3`。 最終的な答えは、`3`、各セグメントに含まれる個別の値は 1 つだけであるため、これが最適です。 

ここで次のことを考えてみましょう。```

```最初の 4 つの要素を処理した後、セグメントには 2 つの異なる値が含まれます。`{1,2}`。 いつ`3`と表示される場合、それを追加すると 3 番目の個別の値が作成されます。 アルゴリズムは新しいセグメントを開始し、配置します。`3`そこには。 答えは次のようになります`2`。 配列全体に 3 つの異なる値が含まれるため、セグメントが 1 つあるパーティションは無効です。 

ついに：```

```個別のカウントが 1 を超えることはありません。 カットは必要なく、アルゴリズムが出力します。`1`。 これにより、すでに存在する値が繰り返し発生しても、個別の値の制限に影響を与えないことが確認されます。
