 ## 解決策
 ## 問題の理解

 配達記録のリストを渡されます。 各レコードには 3 つの整数が含まれます。`(product, material, submaterial)`2 人が別々に配達物を書き留め、そのメモが 1 つに統合されるため、同じ配達物が複数回表示される場合があります。 重複レコードは追加の配達を表すものではありません。 

すべての製品について、次の 2 つの数量を決定する必要があります。 

まず、その製品に関連付けられている異なる素材がいくつあるか。 

第二に、その製品に関連付けられている個別の副資材の数。 

出力には、製品 ID でソートされた製品ごとに 1 行が含まれている必要があります。 各行には次の内容が含まれます。`product_id distinct_materials distinct_submaterials`入力サイズが問題の重要な部分です。 レコードは最大 100 万件までありますが、製品 ID、マテリアル ID、およびサブマテリアル ID は最大 100 万件まで可能です。$10^{18}$。 値の範囲が大きいため、ID でインデックス付けされた配列は除外されます。 Python セットや辞書などのハッシュベースの構造が必要です。 

と$n = 10^6$、$O(n^2)$解決は全く不可能です。 平$O(n \log n)$許容可能ですが、線形または線形に近い解決策が望ましいです。 各レコードは 1 つの製品に関する情報のみを提供する必要があるため、ハッシュ テーブルは自然に適合します。 

微妙な点は、重複したトリプルによってどちらのカウントも増加してはいけないということです。 

考慮する：```
3
1 5 7
1 5 7
1 5 7
```正しい出力は次のとおりです。```
1 1 1
```単純に行をカウントする不注意な実装では、より大きな値が生成されてしまいます。 

もう 1 つの特殊なケースは、複数のサブマテリアルが同じマテリアルに属する場合です。```
3
1 5 1
1 5 2
1 5 3
```正しい出力は次のとおりです。```
1 1 3
```3 つの配信が存在する場合でも、異なるマテリアルは 1 つだけです。 

逆の状況も考えられます。```
3
1 1 9
1 2 9
1 3 9
```正しい出力は次のとおりです。```
1 3 1
```個別のマテリアルと個別のサブマテリアルは個別にカウントする必要があります。 

## アプローチ

 最も直接的な強引なアイデアは、各製品を個別に処理することです。 すべての製品について、納品リスト全体をスキャンし、その製品に属するすべての材料と副材料を収集します。 

製品の統計を計算するときにすべてのレコードが検査されるため、これは正しいです。 問題は効率です。 あれば$P$個性的な商品と$N$記録すると、作品は$O(PN)$。 最悪の場合、すべてのレコードが異なる製品に属し、$O(N^2)$操作。 と$N = 10^6$、これは実用的な限界をはるかに超えています。 

データの構造から、より良いアプローチが示唆されます。 各レコードは、それがどの製品に属しているかをすでに正確に示しています。 入力全体を繰り返しスキャンする代わりに、レコードを読み取りながら情報を集約できます。 

すべての製品について、次の 2 つのセットを維持します。 

1 つのセットには、その製品に見られるすべての個別のマテリアルが保存されます。 

もう 1 つのセットには、その製品に見られるすべての個別のサブマテリアルが保存されます。 

レコードのとき`(a, b, c)`読み込まれたら、単純に挿入します`b`製品のマテリアル セットに追加し、`c`製品のサブマテリアル セットに追加します。 

セットでは重複が自動的に削除されるため、レコードを繰り返しても最終的なカウントには影響しません。 

すべてのレコードを処理した後、製品の答えは 2 つのセットのサイズにすぎません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(PN) | O(N) | 遅すぎる |
 | 最適 | O(N) 平均 | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. レコード数を読み取る`n`。 
2. 製品 ID によってインデックス付けされた辞書を作成します。 
3. レコードごとに`(product, material, submaterial)`:

 マテリアルを製品のマテリアル セットに保存します。 

サブマテリアルをプロダクトのサブマテリアル セットに保存します。 

製品がこれまでに登場したことがない場合は、最初に 2 つのセットを作成します。 
4. すべてのレコードが処理されたら、製品 ID を並べ替えます。 
5. 並べ替えられた順序で各製品について:

 プロダクトIDを出力します。 

マテリアルセットのサイズを出力します。 

サブマテリアル セットのサイズを出力します。 

### なぜ効果があるのか

 固定製品の場合、その製品に関連付けられたすべての納品レコードにより、その材料が 1 つのセットに挿入され、その副材料が別のセットに挿入されます。 セットには、挿入された回数に関係なく、各値が最大 1 回含まれます。 

その結果、すべてのレコードが処理された後、マテリアル セットにはその製品に関連付けられた個別のマテリアルが正確に含まれ、サブマテリアル セットにはその製品に関連付けられた個別のサブマテリアルが正確に含まれます。 

すべてのレコードは一度処理され、正しい製品に貢献するため、最終的なカウントは要求された数量とまったく同じになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    products = {}

    for _ in range(n):
        a, b, c = map(int, input().split())

        if a not in products:
            products[a] = [set(), set()]

        products[a][0].add(b)
        products[a][1].add(c)

    out = []

    for product in sorted(products):
        materials, submaterials = products[product]
        out.append(
            f"{product} {len(materials)} {len(submaterials)}"
        )

    sys.stdout.write("\n".join(out))

solve()
```辞書`products`すべての情報を製品 ID ごとにグループ化して保存します。 

各製品ごとに、`products[a][0]`マテリアルのセットです`products[a][1]`サブマテリアルのセットです。 

新しいレコードが到着すると、両方の挿入は平均して一定時間行われます。 既存の値をセットに挿入しても何も変わらないため、重複した配信は自動的に消えます。 

出力には昇順の製品が必要なため、最後の並べ替えステップが必要です。 ディクショナリを直接反復処理すると、必要な順序が保証されません。 

ID は次のような大きさにすることができます$10^{18}$ですが、Python の整数は特別な処理を行わずにそれを処理します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N + P log P) | 記録の読み取りは直線的であり、製品のコストを分類します$P \log P$|
 | スペース | O(N) | すべての個別のマテリアルとサブマテリアルは一度保存できます。 

ここ$N$はレコードの数であり、$P$個別の製品の数です。 レコードが最大 100 万件あるため、これは一般的なコンテストの制限内に簡単に収まります。

import io

def run(inp: str) -> str:

    def solve():
        input = sys.stdin.readline

        n = int(input())
        products = {}

        for _ in range(n):
            a, b, c = map(int, input().split())

            if a not in products:
                products[a] = [set(), set()]

            products[a][0].add(b)
            products[a][1].add(c)

        out = []
        for p in sorted(products):
            out.append(
                f"{p} {len(products[p][0])} {len(products[p][1])}"
            )

        return "\n".join(out)

    return solve()

 ## 特殊なケース

 繰り返しの配信を考慮してください。```
3
1 5 7
1 5 7
1 5 7
```アルゴリズムが挿入する`5`マテリアルセットに 3 回挿入し、`7`サブマテリアル セットに 3 回挿入します。 セットには一意の値のみが格納されるため、最終的なサイズは両方とも 1 になります。出力は次のようになります。```
1 1 1
```1 つのマテリアルを共有する多くのサブマテリアルについて考えてみましょう。```
3
1 8 1
1 8 2
1 8 3
```素材セットは、`{8}`一方、サブマテリアル セットは`{1,2,3}`。 出力は次のとおりです。```
1 1 3
```1 つのサブマテリアルを共有する多数のマテリアルを考えてみましょう。```
3
1 1 9
1 2 9
1 3 9
```素材セットは、`{1,2,3}`サブマテリアル セットは残ったまま`{9}`。 出力は次のとおりです。```

```これらのケースは、製品ごとに 2 つの独立したセットを維持する必要がある理由を示しています。 単一の結合構造では、両方のカウントが正しく応答されません。
