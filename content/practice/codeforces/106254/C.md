 ## 解決策
 ## 問題の理解

 整数のコレクションが与えられたので、最大公約数に基づいてそれらのペア間の関係を分析する必要があります。 このタスクは、1 以外の共通因数を持たない、つまり gcd が正確に 1 である、順序付けされていないペアがいくつあるかを数えるというものです。 

入力は、1 行に配置された数値のリストとして理解できます。 位置の各ペアは値のペアを定義し、これらのペアのうち互いに素であるペアがいくつあるかを判断するように求められます。 出力は、このカウントを表す単一の整数です。 

この解決策を推進する主な制約は、直接のペアごとの比較がすぐに不可能になることです。 最大約 10^5 の数値がある場合、すべてのペアの gcd をチェックすると、最悪の場合、およそ 10^10 の演算が行われることになり、これは 2 秒の制限で処理できる範囲をはるかに超えています。 高速な gcd 実装を使用したとしても、このアプローチは 2 次成長により構造的に失敗します。 

いくつかの危険な状況については、覚えておく価値があります。 すべての数値が 1 の場合、すべてのペアは互いに素であるため、答えは n(n−1)/2 になります。 すべての数値が同じ素数の場合、どのペアも互いに素でないため、答えは 0 になります。配列に小さい値と大きい値が混在している場合、すべての素数の寄与が適切に考慮されていない限り、単純な除数チェックでは共有因数を見逃す可能性があります。 

## アプローチ

 ブルートフォースアプローチは簡単です。 インデックスのすべてのペアについて、2 つの数値の gcd を計算し、それが 1 に等しいかどうかを確認します。gcd は共有素数構造を直接キャプチャするため、これは正しいです。 問題はパフォーマンスです。n(n−1)/2 のペアがあり、各 gcd 計算には値のサイズで対数時間がかかるため、合計作業量は最悪の場合でも 10^10 回程度の演算になり、これは実行不可能です。 

重要な観察は、ペアごとの推論は間違ったレベルの抽象化であるということです。 2 つの数値が因数を共有するかどうかを尋ねる代わりに、視点を逆にして、与えられた整数 d で割り切れる数値がいくつあるかを尋ねます。 倍数の頻度を数えることができれば、約数に対する包含と排除を通じてペアの関係を再構築できます。 これはまさに、ディリクレ畳み込みとメビウス逆変換が設計された目的であり、局所的な約数の数をグローバルな共素構造に変換することです。 

視点を切り替えると、各数値がそのすべての約数に寄与し、ペアではなく約数にわたってカウントを集計できます。 次に、メビウス関数は、共有約数によって引き起こされる過剰カウントを修正し、gcd が正確に 1 であるペアからの寄与のみを残します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n² log A) | お(1) | 遅すぎる |
 | メビウス / 約数の数え方 | O(A log A + n√A) | O(A) | 承認済み |

 ここで、A は配列内の最大値です。 

## アルゴリズムのチュートリアル

1. まず、配列内の最大値を決定し、値に対する頻度配列を構築します。 これにより、各数字が何回出現するかを知ることができます。 
2. 線形またはふるいベースの方法を使用して、最大値までのすべての整数についてメビウス関数 μ(d) を事前計算します。 この関数は、素因数に対する包含と除外をエンコードし、後で共有約数にわたる過大なカウントを修正します。 
3. すべての整数 d について、配列内の d で割り切れる数値の数を計算します。 これは、d の倍数の周波数を合計することによって行われます。 このステップでは、問題をペアごとの相互作用から除数ベースの集計に変換します。 
4. これらの約数を、両方の数値が d で割り切れるペアの数に変換します。 各 d について、これは単純に cnt[d] 2 を選択します。これらの数値のペアは少なくとも d を公約数として共有するためです。 
5. μ(d) と d で割り切れるペアの数を乗算して、メビウス反転を適用します。 これにより、制御された交互の方法で gcd が 1 より大きいペアから寄与が除去され、gcd が 1 に正確に等しいペアのみが残ります。 
6. 最終累積値を出力します。 

重要な考え方は、すべてのペアが gcd の約数ごとに 1 回カウントされ、メビウス反転によってその gcd がちょうど 1 である寄与を分離するということです。 

### なぜ効果があるのか

 すべてのペア (a, b) は、gcd(a, b) を除算するすべての d に寄与します。 すべての d を合計し、量 cnt[d] が 2 を選択する場合、各ペアは、その gcd の約数の数に応じて複数回カウントされます。 Möbius 関数は、μ(1) のみが寄与する gcd(a, b) = 1 でない限り、これらの複数のカウントがキャンセルされるように重みを割り当てます。 これにより、最終的な合計には互いに素のペアのみが残ることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def mobius_sieve(n):
    mu = [0] * (n + 1)
    mu[1] = 1
    primes = []
    is_comp = [False] * (n + 1)

    for i in range(2, n + 1):
        if not is_comp[i]:
            primes.append(i)
            mu[i] = -1
        for p in primes:
            if i * p > n:
                break
            is_comp[i * p] = True
            if i % p == 0:
                mu[i * p] = 0
                break
            else:
                mu[i * p] = -mu[i]

    return mu

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    mx = max(a)

    freq = [0] * (mx + 1)
    for x in a:
        freq[x] += 1

    mu = mobius_sieve(mx)

    cnt = [0] * (mx + 1)

    for d in range(1, mx + 1):
        s = 0
        for m in range(d, mx + 1, d):
            s += freq[m]
        cnt[d] = s

    ans = 0
    for d in range(1, mx + 1):
        if cnt[d] >= 2:
            pairs = cnt[d] * (cnt[d] - 1) // 2
            ans += mu[d] * pairs

    print(ans)

if __name__ == "__main__":
    solve()
```実装は、除数の集計が効率的になるように度数テーブルを構築することから始まります。 メビウスふるいは、各数値が一定の償却時間で処理されることを保証するために、線形ふるいを使用して構築されています。 

の`cnt[d]`ループは核となる変換ステップです。各約数の倍数を調べて、その約数で割り切れる配列要素の数を累積します。 最後のループでは、μ(d) を使用して包含/除外を適用し、組み合わせペアのカウントと算術キャンセルを組み合わせます。 

微妙な点は順序です。メビウスの重みを適用する前に除数の数を計算する必要があります。 これらの手順を逆にすると、各重み付けされた項が何を表すかの解釈が壊れます。

 ## 特殊なケース

 次のような単一要素の配列`[7]`ゼロペアが生成され、アルゴリズムはこれを自然に処理します。`cnt[d] choose 2`値はゼロです。 

のようなすべての配列`[1, 1, 1]`すべてのペアが貢献しています`d = 1`のみ。 メビウスの合計は、μ(1) = 1 であるため、完全な組み合わせカウントに減少し、カウントがゼロであるため、より高い寄与はすべてキャンセルされます。 

次のような高度に複合的なセット`[6, 10, 15, 35]`重複する除数構造を作成します。 このアルゴリズムは、各共有除数バケットを正しくカウントし、真に互いに素なペアのみが残るように符号を交互に切り替えます。これは、gcd をペアごとに手動でチェックし、最終的な合計を照合することで検証できます。
