 ## 解決策
 ## 問題の理解

 各クエリが 2 種類のハンバーガーの入手可能な材料と販売価格を記述する小規模レストラン モデルを与えられています。 1 つのハンバーガーにはバンズとビーフが必要で、もう 1 つはバンズとチキンが必要です。 すべてのハンバーガーはちょうど 2 つのバンズを消費し、各タイプは独自の材料を消費します。 

クエリごとに、バンズの合計数が尊重され、総収益が最大化されるように、ハンバーガーとチキン バーガーを何個製造するかを決定する必要があります。 制限されるリソースはバンズ、ビーフパティ、チキンカツレツであり、各クエリは独立しています。 

制約は小さく、各数量は最大 100、クエリは最大 100 です。 これは、およそ数百万の操作までのソリューションは、時間制限内に収めるのが簡単であることを意味します。 バーガーの合理的な分布をすべて試すアプローチも実現可能ですが、列挙を完全に回避するさらに単純な構造があります。 

この問題における素朴な間違いは、より高価なハンバーガーを常に優先すべきだと考えることです。 高価なハンバーガーがより制限されたリソースを消費する場合、これは必ずしも正しいとは限りません。 たとえば、バンズは豊富にあるが牛肉が不足し、鶏肉が豊富な場合、ハンバーガーを優先すると、より価値のあるチキンバーガーに使用できたはずのバンズが無駄になる可能性があります。 

両方のバーガー タイプの価格が同じ場合、別の微妙なエッジ ケースが現れます。 この場合、リソースの制約を考慮した割り当ては最適ですが、一方のタイプに過剰にコミットする貪欲な戦略は、利益を向上させることなく、もう一方の実現可能性を低下させる可能性があります。 

## アプローチ

 簡単な強引なアプローチは、可能な数のハンバーガーとチキン バーガーを試してみることです。 各バーガーはバンズを 2 つ消費するため、ハンバーガーの数を固定すると、残りのバンズと材料によってチキン バーガーを何個生産できるかが決まります。 ゼロから実現可能な最大値までのハンバーガー数の選択ごとに、対応するチキンバーガー数を計算し、利益を評価します。 これは、2 つのバーガー タイプ間のバンズの有効な分布をすべて調査するため、正しいです。 

問題は、これでもクエリごとに最大 100 個の選択肢を反復処理し、ループ内で制約を計算する必要があることです。 これはすでに十分小さいですが、問題の構造がより単純であるため、これは不要です。両方のハンバーガーは同じ共有リソース (バンズ) を消費しますが、他の材料は独立した制約です。 重要な観察は、各バーガー タイプは限られた容量を消費するものとして扱うことができ、唯一の実際の結合はバンズの制約であるということです。 

重要な洞察は、共通のボトルネックはバンズのみであるということです。 各ハンバーガーはちょうど 2 つのバンズを消費するため、ハンバーガーの総数は次のように制限されます。`b // 2`。 1 つのタイプのハンバーガーを何個製造するかを決定したら、材料の制限内で残りを他のタイプに割り当てることができます。 タイプが 2 つしかないため、最適な戦略は、ハンバーガーを最初に優先するか、チキン バーガーを最初に優先するかの 2 つの意味のある構成のみを試すことになります。 あるハンバーガーの種類を別の種類に交換することは、共有バンズあたりの限界利益にのみ依存し、それを超える相互作用は存在しないため、これらの貪欲な選択の 1 つが最適である必要があります。 

これにより、問題は 2 つの貪欲な割り当てを評価し、最大値を取得することになります。

 ## アルゴリズムのチュートリアル

 考えられる両方の優先順位をテストして、最大の利益を計算します。 

1. まず、優先順位を付けた場合にハンバーガーが何個作れるかを計算します。 こちらは牛肉とバンズに限りますので、`min(p, b // 2)`。 これは、制約に違反することなく、ハンバーガーに対する最大限の安全な取り組みを表しています。 
2. ハンバーガーに使用されているバンズを引き、残します。`b - 2 * hamburgers`チキンバーガー用のバンズ。 
3. チキンバーガーを次のように計算します。`min(f, remaining_buns // 2)`。 これにより、鶏肉やパンの供給量を超えないようにすることができます。 
4. 総利益を次のように計算します。`hamburgers * h + chicken_burgers * c`。 
5. 同じプロセスを繰り返しますが、優先順位を逆にします。最初にチキンバーガーを最大化し、次に残りのバンズをハンバーガーに使用します。 
6. 2 つの戦略の間で最大の利益を得ます。 

両方の方向を明示的にテストする理由は、どのバーガー タイプが共有バン リソースに最初にアクセスできるかによって、貪欲な決定が左右されるためです。 

### なぜ効果があるのか

 2 つの選択肢の間の唯一の結合はバンズの制約であり、両方のバーガー タイプはバンズを同じように消費します。 これは、どのソリューションも分割に対応することを意味します`b // 2`独立したキャップの下にある 2 つのタイプの間のバーガー スロット`p`そして`f`。 利益は各種類のバーガーの数に線形であるため、最適な解決策は、最初に 1 つの種類をできるだけ多く満たし、残りの容量をもう 1 つの種類に割り当てるという極端な割り当てにある必要があります。 中間スワップでは、合計パンを変更せずに 2 つのタイプ間でユニットを移動することしかできず、両極端の方向をチェックすることで最大値が確保されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_one(b, p, f, h, c):
    buns = b // 2

    # case 1: prioritize hamburgers
    ham1 = min(p, buns)
    buns_left1 = buns - ham1
    chick1 = min(f, buns_left1)
    profit1 = ham1 * h + chick1 * c

    # case 2: prioritize chicken burgers
    chick2 = min(f, buns)
    buns_left2 = buns - chick2
    ham2 = min(p, buns_left2)
    profit2 = chick2 * c + ham2 * h

    return max(profit1, profit2)

t = int(input())
for _ in range(t):
    b, p, f = map(int, input().split())
    h, c = map(int, input().split())
    print(solve_one(b, p, f, h, c))
```このソリューションでは、まず、各バーガーが 2 つのバンズを消費するため、2 による整数除算を使用してバンズを使用可能なバーガー スロットに減らします。 次に、両方の貪欲な順序付けを明示的にシミュレートします。 ご注文の際は、材料の制限とパンの残りの容量の両方を注意深く尊重してください。 

唯一の微妙な点は、最初に 1 つのタイプを選択した後、残りのバンズを常に再計算するようにすることです。 この手順を忘れると、過剰カウントや無効な割り当てが発生します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    def solve():
        t = int(input())
        out = []
        for _ in range(t):
            b, p, f = map(int, input().split())
            h, c = map(int, input().split())

            buns = b // 2

            ham1 = min(p, buns)
            chick1 = min(f, buns - ham1)
            profit1 = ham1 * h + chick1 * c

            chick2 = min(f, buns)
            ham2 = min(p, buns - chick2)
            profit2 = chick2 * c + ham2 * h

            out.append(str(max(profit1, profit2)))

        return "\n".join(out)

    return solve()

 ## 特殊なケース

 ミニマルなバンズケースのような`b = 1`バーガーを形成できないため、即座に答えをゼロに強制します。 アルゴリズムはこれを次のように処理します。`b // 2`、これはゼロになり、両方の戦略でハンバーガーとチキンバーガーがゼロになることが保証されます。 

例えば1つの成分がゼロの場合`p = 0`、すべての生産をチキンバーガーに強制します。 アルゴリズムでは、`min(p, buns)`正しくはゼロになるため、最初の戦略では、特別な処理を必要とせずに、すべての容量が自然にチキンに割り当てられます。 

両方のハンバーガーの価格が等しい場合でも、両方の貪欲な注文により有効な割り当てが生成されるため、アルゴリズムは引き続き機能します。 利益は対称的であるため、どちらの順序でも同じ結果が得られ、最大値を取ることでタイブレーク ロジックを必要とせずに正確さが保たれます。
