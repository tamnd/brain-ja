 ## 解決策
 ## 問題の理解

 異なる非負の整数のマルチセットが与えられており、以下のプロセスをシミュレートする必要があります。`k`要素を追加します`(mex + max + 1) // 2`マルチセットに。 の`mex`セットの は存在しない最小の非負の整数であり、`max`が最大の要素です。 操作を行った後`k`場合によっては、マルチセットに含まれる **別個の** 整数の数を報告する必要があります。 

入力では複数のテスト ケースを指定します。 それぞれのケースが与えるもの`n`、初期マルチセット サイズ、`k`、操作の数、およびマルチセット内の個別の整数。 出力はケースごとに 1 つの整数です。 

制約は重要です。`n`まで可能です`10^5`、 そして`k`まで可能です`10^9`。 つまり、すべての操作をシミュレートすることは不可能です。 それぞれの加算後に何が起こるかを数学的に推論する必要があります。 の合計`n`すべてのテストケースにわたって`10^5`、余裕があるので`O(n log n)`テストケースごとの操作、ただし次のようなもの`O(k)`絶望的だ。 

微妙なエッジケースが発生するのは、`mex`より大きいです`max`。 たとえば、セットが次のような場合`{0,1,2}`そして`k=2`、`mex`は`3`そして`max`は`2`。 追加`(3+2+1)//2=3`複製が作成されるため、最初の操作では個別の要素の数は増加しません。 ただし、重複が許可された後は、新しいものを追加すると、`mex`現在より大きい`max`予想どおりに個別の数が増加します。 

不用意に実装すると、すべての操作がシミュレートされたり、処理に失敗したりする可能性があります。`k=0`、操作が実行されない場合には誤った結果が生成されます。 

## アプローチ

 ブルートフォースアプローチは簡単です。 操作ごとに計算します`mex`そして`max`、計算します`(mex + max + 1) // 2`を選択し、マルチセットに挿入します。 後`k`操作では、個別の要素をカウントします。 これが機能するのは、各ステップが問題定義に正しく従っているためです。 ただし、`k`まで`10^9`、これでは遅すぎます。 コンピューティングでも`mex`繰り返すと費用がかかる`O(n)`操作ごとに、与える`O(n*k)`それは実現不可能です。 

重要な観察は、プロセスがすぐに安定するということです。 させて`a = mex(S)`そして`b = max(S)`。 もし`a > b`、 それから`(a+b+1)//2 = a`、厳密には より大きいです`b`したがって、各操作は現在の最大値の後に次の整数を追加するだけです。 この場合、個別の要素の数は次のように増加します。`k`。 もし`a <= b`、 それから`(a+b+1)//2`間の数値を生成します`a`そして`b`。 この数値を追加すると、新しい要素 (セット内にない場合) または重複 (存在する場合) が導入される可能性があります。 ほとんどの場合、一度追加するだけで十分です。 その後、セットは変更されなくなります。`mex`は新しい数値と等しくなり、セットが安定します。 

したがって、考慮する必要があるシナリオは 2 つだけです。1 回の操作後にセットが安定するか、現在の数値を超えて新しい数値を追加するかのどちらかです。`max`。 これにより、問題がわかったら、テスト ケースごとの定数時間の計算に問題が削減されます。`mex`そして`max`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n*k) | O(n) | k が大きいと遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力配列を Python に変換します。`set`異なる要素を効率的に追跡します。 
2. を計算します。`mex`から反復することで`0`セット内に整数がなくなるまで上方向に進みます。 
3. を計算します。`max`組み込みを使用して`max()`関数。 
4. もし`k=0`、個別の要素の現在の数をすぐに返します。 
5. もし`mex`より大きい`max`、各操作は、より大きい新しい整数を追加します。`max`。 したがって、その後の個別の合計数は`k`オペレーションは`len(S) + k`。 
6. それ以外の場合は、候補となる新しい要素を次のように計算します。`(mex + max + 1) // 2`。 まだ存在しない場合はセットに追加します。 
7. 更新されたセットのサイズを返します。 

なぜ効果があるのか​​:`mex`常に最小の欠落要素と式をターゲットにしていることを保証します。`(mex + max + 1) // 2`現在の範囲内で新しい要素を生成するか、現在の最大値を超えてセットを拡張します。 いずれの場合も、次の場合、1 回の加算だけで個別カウントが変更される可能性があります。`mex <= max`; それ以上の操作では新しい数値は導入されません。`mex`現在セット内にある追加された要素に移動し、セットをすぐに安定させます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        arr = list(map(int, input().split()))
        S = set(arr)
        mex = 0
        while mex in S:
            mex += 1
        max_val = max(S)
        
        if k == 0:
            print(len(S))
            continue
        
        if mex > max_val:
            # Every operation adds a new number beyond current max
            print(len(S) + k)
        else:
            new_elem = (mex + max_val + 1) // 2
            S.add(new_elem)
            print(len(S))

if __name__ == "__main__":
    solve()
```このコードは、配列を O(1) メンバーシップ チェック用のセットに変換します。 コンピューティング`mex`欠落している番号が見つかるまで、0 から上に向かってスキャンする必要があります。 もし`mex > max_val`、単純に追加します`k`それぞれが現在の最大値を超えた個別の番号が連続して表示されます。 それ以外の場合は追加`(mex + max + 1)//2`セットはすぐに安定するため、1 回で十分です。 取り扱い`k=0`セットを誤って変更しないようにします。
