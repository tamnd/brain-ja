 ## 解決策
 ## 問題の理解

 いくつかの独立したテスト ケースが与えられています。 それぞれで偶数長の整数リストを受け取り、すべてのペアの合計が同じになるように数値をペアに分割できるかどうかを判断する必要があります。 各要素は 1 回だけ使用する必要があり、形成されたすべてのペアは単一の共通の目標合計を共有する必要があります。 

このタスクについて別の考え方をすると、配列を互いに素なペアに再配置しようとしており、すべてのペアが同じ値に「バランス」する必要があります。 課題は、ペアを明示的に構築することではなく、そのようなペアが存在するかどうかを判断することだけです。 

制約が十分に大きいため、ペアリングを明示的にテストしようとするアプローチは失敗します。 まで$5 \cdot 10^5$すべてのテスト ケースにわたる数を考慮した場合、ケースごとのペアの 2 次数さえ考慮する解決策は直ちに不可能になります。 このため、各テスト ケースを線形または線形に近い時間で処理する戦略を余儀なくされます。$O(n \log n)$またはそれ以上です。 

すべての値が同一である場合、または値が不均一な分布で繰り返される場合には、微妙な問題が発生します。 たとえば、すべての数値が同じ場合、すべてのペアの合計が同じになるため、常にペアリングが可能です。 一方、マルチセットが偏っていて、1 つのペアでは 1 つの候補合計のみが機能するが、すべてのペアでは一貫して機能しない場合、単純な貪欲ペアリングは、ペアリングの順序によっては実現可能性を誤って仮定したり、失敗したりする可能性があります。 

次のような誤解を招くケースを考えてみましょう。```
4
1 2 3 4
```隣接する要素を貪欲にペアにすると、合計は 3 と 7 になりますが、これはすぐに失敗します。 しかし、(1,4) や (2,3) のような代替の組み合わせでも合計は 5 と 5 になるため、このケースは実際には有効です。 これは、単純な戦略ではペアリングの順序が重要であり、ローカルな決定ではなくグローバルな不変条件が必要であることを示しています。 

## アプローチ

 ブルートフォース戦略では、配列の可能なすべてのペアを形成し、完全なペアがすべてのペアにわたって等しい和を生成するかどうかを確認しようとします。 これは、完全なグラフ内のすべての完全一致を探索することと同じです。$n$超指数関数的に成長する頂点。 剪定を行ったとしても、ペアの数は次のとおりです。$(n-1)!!$、たとえそれが不可能になる$n = 20$。 

重要な観察は、そのような組み合わせが存在する場合、目標合計は一意に決定される必要があるということです。 配列をソートするとします。 最小の要素と最大の要素を組み合わせると、必要な合計はすでに決定されています。 他のすべてのペアはこの同じ合計に準拠する必要があり、2 番目に小さいペアと 2 番目に大きいペアという厳密な構造が強制されます。 不一致が発生した場合、ペアリングを変更するとグローバル合計の一貫性が損なわれるため、代替のペアリングで状況を解決することはできません。 

これにより、すべてのペアリングの検索から、ソート後の単一の決定的なペアリング パターンの検証までの問題が軽減されます。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. 配列を読み取り、降順でない順に並べ替えます。 最適なペア構造は一致する極値に依存し、ソートによってこれらの極値が明確に明らかにされるため、ソートが必要です。 
2. 最初と最後の要素を使用して、候補となるターゲット合計を計算します。具体的には、$a[0] + a[n-1]$。 有効な構成では最小要素と最大要素がペアになっている必要があるため、有効なソリューションが存在する場合はこの値が強制されます。 そうしないと、それらを他の組み合わせに置き換えると、範囲が狭くなり、一貫性が損なわれるだけです。 
3. 2 つのポインターを使用して、1 つは先頭から開始し、もう 1 つは末尾から開始して内側に移動します。 各ステップで、現在の最小の残り要素と最大の残り要素から概念的なペアを形成します。 
4. このようなペアごとに、それらの合計が以前に計算した目標合計と等しいことを確認します。 いずれかのペアが逸脱した場合は、有効なペアが存在しないと直ちに結論付けます。 
5. すべてのペアが目標合計と一致する場合、有効なパーティションが存在します。 

重要な考え方は、最も外側の要素が固定されると、残りの構造が完全に決定されるということです。 一貫性を崩さずに再配置するための柔軟性は残されていません。 

### なぜ効果があるのか

 並べ替え後、有効な解決策が存在すると仮定します。 最小要素を最大値以外の要素と組み合わせます。 その場合、最大値は 2 番目に大きい値以下の値とペアになる必要があります。 これは、順序に応じて合計が元のターゲットを超えるか下回る 2 番目のペアを強制することになり、すべてのペアが同じ合計を共有するという要件に矛盾します。 

これにより、厳格なペアリング構造が作成されます。ソートされた配列は、端から内側に向​​かって対称的にペアになる必要があります。 目標合計は極端な要素によって固定されるため、すべてのペアが強制され、逸脱すると構成が無効になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        a.sort()

        target = a[0] + a[-1]

        ok = True
        i, j = 0, n - 1

        while i < j:
            if a[i] + a[j] != target:
                ok = False
                break
            i += 1
            j -= 1

        out.append("SI" if ok else "NO")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```解決策は、最小値と最大値が自然な最初の候補ペアになるように配列を並べ替えることから始まります。 有効な解にはその値と一致する何らかのペアリング構造が含まれている必要があるため、目標合計はこれらの極値からすぐに決定されます。 

2 ポインター ループでは、すべての対称ペアが同じ合計と一致するように強制されます。 ループだけが実行されます$n/2$反復するため、検証ステップは直線的です。 唯一の微妙な要件は、ループが始まる前にターゲットを計算する必要があることです。 動的に再計算すると、一貫性のないローカル調整が可能になるため、正しくありません。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべての値が同一である場合です。 入力の場合:```
6
7 7 7 7 7 7
```並べ替えると同じ配列が得られ、ターゲットは 14 です。すべてのペアの合計は 14 になるため、アルゴリズムは受け入れます。 ポインタ スキャンでは不一致が検出されることはなく、縮退した一様分布の正しさが確認されます。 

もう 1 つのエッジ ケースには負の数値が含まれており、並べ替えないと最適な組み合わせが明らかではありません。```
4
-3 -1 2 4
```並べ替えると得られるもの`[-3, -1, 2, 4]`、ターゲット = 1。ペアは (-3,4) と (-1,2) で、両方の合計は 1 になります。単純な隣接ペアリングが誤って失敗を示唆する場合でも、アルゴリズムは実行可能性を正しく識別します。 

3 番目のエッジ ケースは、1 つのペアだけが制約に違反する場合です。```
6
0 1 2 3 4 10
```ソートされた配列はターゲット 10 につながりますが、ペアリングにより不一致が早い段階で明らかになります。 このアルゴリズムは、代替ペアを探索せずにすぐに拒否します。これは、大規模な入力での効率を高めるために不可欠です。
