 ## 問題の理解

 いくつかの独立した道路セグメントが与えられ、各セグメントには既存のペイントされた横断歩道のストライプのセットが含まれています。 すべてのストライプは開始位置と幅によって記述されるため、それぞれが数直線上の連続した間隔を占めます。 これらのストライプは重なったり、隙間が残ったりする場合があります。 

町は、地域全体を新しい縞模様に塗り替えたいと考えています。 再ペイント後は、新しいストライプのみが表示されます。$k$彼らのうち。 新しいストライプはそれぞれ整数の幅を持ち、隙間なく接触できるようにするなど、配置する場所を自由に選択できます。 

目標は、多くても選択することです$k$少なくとも 1 つの古いストライプによってカバーされていたすべての位置を完全にカバーする新しい間隔。 すべての有効な再描画の中で、選択した新しいストライプの最大幅を最小限に抑えたいと考えています。 

したがって、基礎となるタスクは次のとおりです。$n$間隔、結合を最大で分割します$k$間隔は、最大間隔の長さができるだけ小さくなるようにします。 

入力サイズは最大で$10^5$テストケースごとの間隔、最大$1.5 \cdot 10^6$すべてのテストの合計。 セグメントに対してパーティションや動的プログラミングを明示的に試行しようとするソリューションは、ソートとマージ後に 2 次またはさらに悪い動作に向かってドリフトするため、非常に遅すぎます。 

ソート後の線形または線形に近いスキャンが必要であり、答えに対する二分探索と貪欲な実現可能性チェックを組み合わせたソリューションは実行可能です。 

間隔が重なり合うと、微妙な問題が発生します。 たとえば、すべての間隔が単一の連続領域に重なっている場合、答えは単にカバーされる全長の上限を次の値で割ったものになります。$k$ただし、マージされたカバレッジではなくエンドポイントを調べる単純な方法では、必要なセグメント数が過大評価されてしまいます。 

もう 1 つのエッジ ケースは、間隔がばらばらで、間隔が他のものと比べて非常に小さい場合です。$k$。 その場合、最適なソリューションでは、各小さなコンポーネントに独自のセグメントを割り当て、未使用の容量を割り当てます。$k$は関係ありません。 

## アプローチ

 強引な解釈では、間隔の和集合を最大どこで分割するかを決定しようとします。$k$連続する部分を調べてから、部分の最大長を評価します。 これは、マージされたカバレッジを分割するあらゆる方法を試すことを示唆しています。$k$グループ。 区間をソートして和集合にマージした後、セグメントに分割された連続的なカバーされたセットを取得するとします。 それでも、カットを最適に配置するには組み合わせが必要です。$k-1$潜在的な間のポイントをカット$10^5$候補地は指数関数的に多くの可能性をもたらします。 

より構造化された視点は、質問を逆にすると得られます。 セグメントの数を固定して最大長を最小化する代わりに、候補の最大長を固定します。$L$そして、最大でも次の値を使用してすべての結合間隔をカバーできるかどうかを尋ねます。$k$セグメント、それぞれの長さは最大$L$。 それが可能であれば、さらに小さい$L$うまくいくかもしれない。 そうでない場合は、増やす必要があります$L$。 この単調な動作が鍵となります。実行可能性は、次のように簡単になります。$L$成長します。 

修正の実現可能性を確認するには$L$では、最初に元の間隔を結合しないセグメントにマージします。 次に、マージされた各セグメントを個別にカバーする必要があります。 単一の連続した長さのセグメントをカバーする$X$少なくとも必要です$\lceil X / L \rceil$新しいストライプ。各ストライプは最大でもカバーできるため、$L$長さ。 これをすべてのマージされたセグメントで合計すると、必要なストライプの合計数が得られます。 合計が以下の場合$k$、候補者$L$有効です。 

これにより、問題は二分探索に帰着します。$L$、ソートとマージ後に各チェックが直線的な時間で実行されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 ここ$A$は端点の座標範囲です。 

## アルゴリズムのチュートリアル

 1. 各ストライプを間隔に変換します。$[a_i, a_i + l_i]$。 これらを開始位置で並べ替えることで、順序にギャップが生じることなくカバレッジを推論することができます。 
2. 重複する区間を結合しないセグメントにマージします。 ソートされた間隔をスキャンしながら、重複が発生する限り現在のセグメントを拡張します。 ギャップが現れたら、セグメントを閉じます。 このステップでは、問題を独立した連続領域に圧縮します。 
3. 候補の最大ストライプ幅が与えられた場合に、次の関数を定義します。$L$、すべてのマージされたセグメントをカバーするために必要なストライプの数を計算します。 長さの各セグメントに対して$X$、ストライプの最小数を次のように計算します。$\lceil X / L \rceil$。 これらの値をセグメント全体で合計します。 
4. 実現可能性をチェックします。必要なストライプの総数が最大でも$k$、 それから$L$で十分です。 そうしないと小さすぎます。 
5.二分探索$L$1 からすべての間隔にわたって可能な最大セグメント長まで。 
6. 最小値を返す$L$実現可能性が保たれます。 

重要なデザイン選択は、ストライプの実際の配置を決してシミュレートしようとしないことです。 各連続セグメントを長さで最適にパックする場合に必要な数だけを数えます。$L$ブロック。 これにより、組み合わせ配置ロジックが回避されます。 

### なぜ効果があるのか

 マージ後、各セグメントは完全にカバーされる必要がある最大の連続領域になります。 どのストライプでも最大でカバーできるのは$L$セグメントが互いに切り離されているため、セグメント間でカバレッジを分割しても、必要なストライプの数を減らすことはできません。 セグメント内では、無駄なカバレッジは新しいポイントをカバーするのに役立たないため、常に最適な戦略は、ギャップや無駄の重複を生じさせずにストライプを連続して配置することです。 これにより、$\lceil X / L \rceil$セグメントごとに必要かつ十分なテストが行​​われ、セグメント全体を合計することで正確な実現可能性テストが得られます。 

増加するため単調性が続きます$L$各セグメントに必要なストライプの数を減らすか維持することしかできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def merge(intervals):
    intervals.sort()
    merged = []
    for s, e in intervals:
        if not merged or merged[-1][1] < s:
            merged.append([s, e])
        else:
            merged[-1][1] = max(merged[-1][1], e)
    return merged

def needed(segments, L, k):
    cnt = 0
    for s, e in segments:
        length = e - s
        cnt += (length + L - 1) // L
        if cnt > k:
            return False
    return cnt <= k

def solve():
    T = int(input())
    for _ in range(T):
        n, k = map(int, input().split())
        intervals = []
        for _ in range(n):
            a, l = map(int, input().split())
            intervals.append((a, a + l))

        segments = merge(intervals)

        max_len = 0
        for s, e in segments:
            max_len = max(max_len, e - s)

        lo, hi = 1, max_len

        while lo < hi:
            mid = (lo + hi) // 2
            if needed(segments, mid, k):
                hi = mid
            else:
                lo = mid + 1

        print(lo)

if __name__ == "__main__":
    solve()
```コードは、各ストライプを閉じた間隔に変換し、重複部分をマージすることから始まり、後の推論では互いに素なセグメントのみが処理されるようにします。 マージ手順がなければ、間隔ごとに必要なストライプをカウントすると、重複する領域のカバレッジが 2 倍にカウントされてしまうため、この手順は重要です。 

の`needed`関数は候補の最大幅を評価します。 幅を計算します。$L$ストライプは、天井分割を使用してマージされたセグメントごとに必要です。 カウントオーバー時の早期停止$k$不必要な作業を防止し、大量の入力の下でもソリューションの効率を維持します。 

二分探索は可能な幅にわたって実行されます。 上限は、結合されたセグメントの最大の長さとみなされます。これは、任意の単一セグメントが常にそのサイズの 1 つのストライプでカバーされ、有効な自明な境界となるためです。
