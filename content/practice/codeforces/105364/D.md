 ## 解決策
 ## 問題の理解

 いくつかのテストケースが与えられています。 いずれの場合も、マリアは異なる色のディスクを所有しており、色ごとに彼女が同じディスクを何枚持っているかがわかります。 彼女は、すべてのディスクをいくつかの垂直タワーに分割したいと考えています。 

各タワーは対称条件を満たしている必要があります。つまり、色を上から下に読み取る場合、下から上に読んでも順序が同じになります。 言い換えれば、すべての塔は一連の色の回文です。 さらに、すべてのタワーはまったく同じ高さである必要があり、すべてのディスクはすべてのタワーで正確に 1 回使用される必要があります。 

課題は、形成できるこのような同じ高さの回文塔の最小数を決定することです。 

ソリューションを形成する重要な制約は、テスト ケースごとのすべてのディスクの合計が最大 10^9 まで、色の数が最大 10^4 までとなる可能性があることです。 これにより、明示的に塔を建設したり、配置をシミュレートしたりする建設は即座に除外されます。 有効な解決策は、問題を周波数に関する算術に圧縮する必要があります。 

微妙な点は、対称性によって各タワーの内部に構造が強制されることです。すべての色が鏡像ペアか、場合によっては単一の中間要素のいずれかに寄与します。 この制限により、問題が軽減されます。 

エッジケースは、分布が非常に不均一な場合に発生します。 たとえば、1 つの色しか存在しない場合、すべての円盤が回文を形成する必要がありますが、それらを 1 つの塔に積み重ねることができます。 もう 1 つの特殊なケースは、各タワーがレベルごとに 1 つの中心位置しかホストできないため、多くの色のカウントが奇数である場合です。 

レイヤーごとにタワーを貪欲に構築しようとする単純な試みは、グローバル パリティ制約が正しく考慮されていない場合、失敗する可能性があります。 たとえば、色ごとに奇妙な残りが蓄積することを考慮せずにタワーを順番に埋めようとすると、必要なタワーの数を過小評価する可能性があります。 

## アプローチ

 直接的なアプローチでは、タワーを明示的に構築しようとします。 可能であれば同じ色の組み合わせを繰り返し、残りを中心要素として配置して、一度に 1 つのタワーを構築しようとするかもしれません。 回文はペアとおそらく 1 つの中間要素から構築できるため、これは概念的に機能します。 

ただし、タワーの高さを固定したら、すべてのカラーがすべてのタワーに一貫して分散されるようにする必要があるため、このアプローチは複雑になります。 タワー建設をシミュレーションしようとすると、最大 10^9 のディスクを効果的に管理することになりますが、これは不可能です。 カウントのみを操作する場合でも、レベルを繰り返しシミュレートすると、すべての色にわたって繰り返しスキャンが行われ、パリティを解決するために必要な操作数が二次関数的に動作する可能性があります。 

重要な洞察は、視点を逆転させることです。 塔をどのように建てるかを問うのではなく、固定された数の塔がどのような制約を課すのかを尋ねます。 

k 個のタワーがあると判断した場合、各色カウント a_i をタワーごとに 1 つずつ、k 個のグループに分割する必要があります。 各グループは回文に寄与するため、各タワー内でペアの寄与という観点から考えることができます。ほとんどの色の出現は対称位置にわたってペアで使用する必要があり、タワーごとに最大 1 つの出現が中心として機能できます。 

これは、グローバルな実現可能性条件につながります。各タワーは、ペアになっていない中間要素を 1 つだけホストできるため、色ごとに、すべての色にわたって奇数の寄与が最大 k 個になるように、a_i を k 個のバケットに分配する必要があります。 

これにより、問題は、色分布ごとの奇数の寄与の総数に対応できる最小の k を見つけることに変換されます。 

最適な解決策は、k 個のタワーを設定した場合、各色がタワーごとに少なくとも a_i // k 回の使用に寄与し、残りの a_i % k がその色の追加アイテムを受け取るタワーの数を決定するという観察から得られます。 このような余分なアイテムはそれぞれ、タワー内の潜在的な「奇妙さの原因」となります。

したがって、固定 k について、残りに寄与する色の数を計算し、内部でペアにできるものを超えて、タワーが複数のペアになっていない中心要件を受け取らないように、これらの残りを割り当てることができるかどうかを確認します。 最小の k は、検索するか、実現可能性の単調性を観察することによって見つけることができます。 

実際には、直接的かつ最適な削減が得られます。答えは、タワー間で分割された最大周波数上限の最大値と、合計の奇数カウントによって引き起こされる制約です。

 ## アルゴリズムのチュートリアル

 回文構造全体に色をどのように分配できるかを推論して、塔の最小数を決定します。 

1. すべてのディスクの総和 S を計算します。 k 個の塔を持つ解はすべて同じ高さでなければならないため、各塔の高さは S / k となり、S を割るために k が必要になります。これにより、候補が即座に制限されます。 
2. 固定 k の場合、各色カウント a_i が k 個のタワーにどのように分割されるかを検討します。 各タワーは、すべてのタワーにわたって、floor(a_i / k) または Floor(a_i / k) + 1 つの色のコピーを受け取ります。 追加のコピーを受信するタワーの数は、正確に a_i % k です。 
3. 各タワーが回文であるということは、各タワー内で最大 1 つの色が対になっていない中心要素に寄与できることを意味します。 これは、すべての色にわたって、剰余によって引き起こされる「奇数の配置」の数が k を超えてはいけないことを意味します。 
4. 与えられた k に対して、残りの出現の総数 L = sum(a_i % k) を計算します。 残りのそれぞれは、不均衡としてタワーに配置する必要がある 1 つのユニットに対応します。 各タワーは回文性を損なうことなくそのようなユニットを最大 1 つまで吸収できるため、実現可能性には L <= k が必要です。 
5. 両方の制約を満たす最小の k を検索します。k は S を除算し、L <= k です。 k は最大でも S であるため、S の約数を反復処理するか、k に対する二分探索による単調チェックを使用します。 

### なぜ効果があるのか

 核となる不変条件は、k 個のタワーを持つ有効な構成では、各色が k 列に分割され、各列が 1 つのタワーに対応するということです。 残りの a_i % k は、完全な対称性を超えて色 i の余分な出現を受け取るタワーの数を正確にカウントします。 これらの余分なものが不均衡を引き起こす唯一の原因です。 各回文タワーはちょうど 1 つの中心の寄与を吸収できるため、すべての色にわたるそのような不均衡の合計数が k を超えることはできません。 逆に、この条件が当てはまる場合は、残りの要素を個別のタワーに割り当て、残りの要素を対称的にペアにすることで各タワーを完成させることができます。 これにより、実現可能性と不等式 L <= k の間の等価性が、合計サイズの可分性とともに確立されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(n, arr):
    total = sum(arr)

    # We try k from 1 to n? Actually k can be up to total, but we use divisors of total.
    # For each k, check feasibility.
    # We compute minimal k.
    best = total

    # iterate k up to sqrt(total) via divisors of total is too complex per case,
    # but n <= 10000 and sum total <= 1e9 so divisors approach is fine.

    # collect divisors
    divisors = []
    i = 1
    while i * i <= total:
        if total % i == 0:
            divisors.append(i)
            if i * i != total:
                divisors.append(total // i)
        i += 1

    divisors.sort()

    for k in divisors:
        leftover = 0
        for a in arr:
            leftover += a % k
            if leftover > k:
                break
        if leftover <= k:
            best = k
            break

    return best

def main():
    t = int(input())
    for _ in range(t):
        n = int(input())
        arr = list(map(int, input().split()))
        print(solve_case(n, arr))

if __name__ == "__main__":
    main()
```タワーの高さが等しいと各タワーのサイズが S / k になるため、実装では最初にディスクの合計数が計算されます。 次に、これらの k 値のみが等しい整数の高さを生成できるため、S のすべての約数を列挙します。 

各候補 k について、各色をサイズ k のグループに分割したときに現れる残りの部分の数を計算します。 モジュロ演算 a_i % k は、完全な対称ペアリングを超えてその色の追加ディスクを受け取るタワーの数を正確に取得します。 

変数`leftover`このような追加の貢献をすべて集約します。 これが k を超えると、各不均衡を個別のタワー中心位置に割り当てることが不可能になるため、候補 k は早期に拒否されます。 

実現可能性を満たす最初の k が昇順で最小値として返されます。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    def solve():
        t = int(input())
        out = []
        for _ in range(t):
            n = int(input())
            arr = list(map(int, input().split()))
            total = sum(arr)

            divisors = []
            i = 1
            while i * i <= total:
                if total % i == 0:
                    divisors.append(i)
                    if i * i != total:
                        divisors.append(total // i)
                i += 1
            divisors.sort()

            for k in divisors:
                leftover = 0
                for a in arr:
                    leftover += a % k
                    if leftover > k:
                        break
                if leftover <= k:
                    out.append(str(k))
                    break
        return "\n".join(out)

    return solve()

 ## 特殊なケース

 次のような単一色の入力の場合`a_1 = 15`、アルゴリズムは total = 15 を計算し、k = 1 と k = 15 をチェックします。k = 1 の場合、残り物はゼロであるため、1 つのタワーが有効であり、すべての同一の円盤を積み重ねることによって任意の回文を形成できるという事実と一致します。 

次のような非常に偏った分布の場合`1 1 1 1 100`、k 値が大きい場合、大きな色が残りのカウントを支配し、k が残りを分配するのに十分な大きさでない限り、実現可能性が失敗します。 残りの累積が早期に k を超えるため、アルゴリズムは中間 k を正しく拒否します。 

すべての値が偶数の場合、合計を分割するすべての k はバランスのとれた剰余構造を持つ傾向があり、実現可能性は主に割り算によって決まり、サブタスクの動作と一致します。
