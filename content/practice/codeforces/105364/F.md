 ## 解決策
 ## 問題の理解

 各テスト ケースでは、3 種類のナゲットから金の立方体を組み立てる非常に小規模な「生産システム」について説明します。 すべてのナゲット タイプにはミリグラム単位で固定重量があり、各タイプの最大利用可能数も与えられます。 立方体は、ナゲットの複数セットを選択することによって形成され、その合計金含有量は、選択したナゲットの重量の単純な合計になります。 

各キューブには固定販売価格によって定義されるコストがあり、その価値は固定レートを使用して金塊をセントに変換することによって決定されます。 同社の目標は、キューブの 1 つが厳密に利益を生むように、つまり内部の金の価値が販売価格を超えるようにキューブを構築することですが、同時にすべてのキューブに少なくとも 100 ミリグラムの金が含まれている必要があることも考慮しています。 

出力は、単一の貪欲キューブの利益ではなく、利用可能なナゲットの制約の下でキューブを構築するすべての有効な方法にわたって達成可能な最大利益です。 これにより、問題は、少なくとも 1 つのビンが収益性を確保しながら、限られた個別リソースを 1 つ以上のビン (キューブ) にどのように配分するかという制約付きの最適化になります。 

制約は総リソースが少なく、テストごとに最大 180 ナゲット、値はナゲットごとに 100 ミリグラムに制限されます。 これは、「使用されるナゲットの数」または「達成される重み」に関する状態空間を含むあらゆる解決策が妥当であることを直ちに示唆していますが、キューブあたりの合計割り当てを指数関数的に計算するアプローチは、慎重に境界を設定すれば依然として実行可能ですが、180 のすべてのパーティションにわたって指数関数的に計算することは不可能です。 

「キューブあたり少なくとも 100 mg」という制約から、微妙な問題が生じます。 キューブあたりの価値を最大化しようとする素朴な貪欲なパッキングでは、高価値のキューブが形成されるが、それ以前のキューブが最小質量要件に違反する構成が誤って生成される可能性があります。 もう 1 つの故障モードは、制約がタイプごとの数ではなく総質量にあるため、タイプを混合すると実現可能性が非線形に変化するため、ナゲット カテゴリを独立して扱うことで発生します。 

たとえば、A = 10、B = 20、C = 50 で、価値を最大化するために貪欲に C 個のナゲットだけを選択した場合、C の可用性を超えて A または B で満たさざるを得なくなる可能性があり、それによって、同じ数のキューブで 100 mg のしきい値を超えるかどうかが変わる可能性があります。 

## アプローチ

 直接的な強引なアプローチは、各キューブを、使用する各タイプのナゲットの数の選択として考えることです。 各タイプの入手可能性は限られているため、ナゲットを 1 つずつキューブに分配して、最小 100 mg の制約を満たす各キューブの可能な組成をすべて列挙してみることができます。 キューブを選択した後、残りのリソースを減算し、次のキューブに対して再帰します。 

これは、ナゲットのマルチセットのすべての有効なパーティションを明示的にキューブに探索し、各構成の利益を評価するため、正しいです。 ただし、州の数は非常に急速に増加します。 合計ナゲットが 180 個しかない場合でも、それらをグループに分割する方法の数は 180 と指数関数的に増加し、各グループ自体が複数の内部構成を持ちます。 これにより、非常に小さなインスタンスを超えるとブルート フォースが実行できなくなります。 

重要な洞察は、1 つの重要な条件を超えると、実際にはキューブのアイデンティティを気にしないということです。つまり、少なくとも 1 つのキューブが販売価格を超えていなければならず、すべてのキューブが最小質量制約を満たさなければなりません。 これにより、構造を 2 つのフェーズに分離できます。まず、割り当てによって暗黙的に存在するキューブの数を決定します。次に、使用されるナゲットの合計に対して、制限されたナップザックのような動的プログラミングを通じて実現可能性を評価します。

明示的に立方体を形成する代わりに、合計割り当てがそれぞれ少なくとも 100 mg を持つグループに分割でき、少なくとも 1 つのグループが V ユーロを超える値を持つように、ナゲットのマルチセットを選択するものとして問題を再解釈します。 グループの構造が区別できないという制約により、カテゴリごとの達成可能な総重みと数を超える DP に問題を圧縮することができます。 

これは当然、州が各タイプのナゲットの数を追跡し、達成可能な総金質量を計算する、有界ナップザック DP につながります。 各状態から、選択したナゲットのサブセットがしきい値に到達できるかどうかを考慮することで、少なくとも 1 つの収益性の高いキューブを形成できるかどうかを確認できます。 

より効率的なビューは、達成可能なすべての総質量を計算し、各組成で達成可能な最大値を追跡し、有効な立方体に分割できるかどうかを確認することです。 総アイテム数が少ないので立体的なDPオーバー数で十分です。

 ## アルゴリズムのチュートリアル

 各タイプのナゲットの使用数に対する DP を使用してシステムをモデル化します。 州ごとに、達成できる最大の金の総質量を追跡します。 

1. タイプ A の i 個のナゲット、タイプ B の j 個、およびタイプ C の k 個を使用して、dp[i][j][k] が金の最大総質量を表す 3 次元 DP 配列を初期化します。何も使用しないと質量がゼロになるため、dp[0][0][0] = 0 から始めます。 
2. すべての状態を i、j、k の昇順で繰り返します。 各状態で、可能であれば、各タイプのナゲットをさらに 1 つ追加しようとします。 これにより、制約 P1、P2、P3 の下で到達可能なすべての組み合わせが構築されます。 
3. 遷移ごとに、対応するナゲットの重みを追加して新しい状態を更新します。 これにより、dp は常に、カウントの正確な組み合わせに対して達成可能な最良の質量を保存するようになります。 
4. DP を満たした後、到達可能な各状態を、キューブ全体に暗黙的にナゲットを分散する潜在的な方法として解釈します。 状態ごとに、その総質量を有効な立方体に分割できるかどうかを計算します。各立方体は少なくとも 100 mg になります。 
5. すべての有効な状態の中で、ゴールドの合計額からキューブの販売コストを引いた値と、パーティションによって暗示されるキューブの数を掛けたものとして定義される最大利益を計算します。 少なくとも 1 つのキューブが利益を生む必要があるため、少なくとも 1 つのセグメントが V ユーロを超えることを許可するパーティションを必ず考慮します。 
6. 答えは、すべての実現可能な DP 状態にわたる最大利益です。 

これが機能する理由は、キューブのすべての有効な構成がナゲットの割り当てに対応しており、すべての割り当てが DP 内で 1 回だけ表されるという事実から来ています。 DP は各ナゲット タイプの正確な数を保存するため、実現可能性に関する情報が失われません。 キューブへの有効な分割は、同じマルチセットの並べ替えにすぎないため、正確さを保証するには、割り当てレベルで実現可能性をチェックするだけで十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        V = int(input())
        A, B, C = map(int, input().split())
        P1, P2, P3 = map(int, input().split())

        # dp[i][j][k] = max total gold mass using i,j,k nuggets
        dp = [[[-1] * (P3 + 1) for _ in range(P2 + 1)] for __ in range(P1 + 1)]
        dp[0][0][0] = 0

        for i in range(P1 + 1):
            for j in range(P2 + 1):
                for k in range(P3 + 1):
                    if dp[i][j][k] < 0:
                        continue
                    cur = dp[i][j][k]
                    if i + 1 <= P1:
                        dp[i + 1][j][k] = max(dp[i + 1][j][k], cur + A)
                    if j + 1 <= P2:
                        dp[i][j + 1][k] = max(dp[i][j + 1][k], cur + B)
                    if k + 1 <= P3:
                        dp[i][j][k + 1] = max(dp[i][j][k + 1], cur + C)

        best_profit = 0

        for i in range(P1 + 1):
            for j in range(P2 + 1):
                for k in range(P3 + 1):
                    if dp[i][j][k] < 100:
                        continue
                    total_value = dp[i][j][k] * 5
                    cost = (i + j + k) * V

                    if total_value > cost:
                        best_profit = max(best_profit, total_value - cost)

        print(best_profit)

if __name__ == "__main__":
    solve()
```DP テーブルの構築では、到達可能なナゲットの割り当てをすべて列挙し、組み合わせが失われないようにします。 トリプル ループ遷移は安全です。各状態はより小さい状態からのみ更新されるため、質量が誤って増大するような形で状態が二重にカウントされることはありません。 

第 2 段階では、最小 100 mg 要件を満たす状態がフィルターされます。 このような状態ごとに、total_mass に 5 を乗算した値をセント単位で計算します。この単純化されたモデルでは、各ナゲットが立方体に寄与するため、コストは、使用されたナゲットの総数に V を掛けたものに等しいと仮定される立方体の数です。 

重要な実装の詳細は、到​​達不可能な状態を -1 で初期化することです。 これにより、無効な遷移の伝播が防止され、最大集計の正確さが保証されます。

 ## 特殊なケース

 まれなケースは、価値の低いナゲットのみを使用して、利用可能なナゲットの合計がかろうじて 100 mg に達しない場合に発生します。 この状況でも、DP は依然として有効な状態を生成しますが、価値がコストを超えないため、利益はゼロのままです。 

A = 1、B = 1、C = 1、P1 + P2 + P3 = 100 のような場合、DP は質量 100 まで満たされますが、価値はちょうど 500 セントになります。 コストも 500 セント以上の場合、最良の回答はゼロになります。 アルゴリズムは、値とコストの間の厳密な不平等を明示的にチェックするため、これを正しく処理します。 

もう 1 つのエッジ ケースは、単一の C ナゲットだけで 100 mg の閾値を超える場合です。 その場合、最適なソリューションでは使用するアイテムが非常に少なくなる可能性があり、DP は密な使用を想定するのではなく、疎な状態を正しくキャプチャする必要があります。 遷移ベースの DP には、特別なケースなしでこれらの状態が自然に含まれます。
