 ## 解決策
 ## アプローチ

 ブルートフォース戦略は、考えられるすべてのセンターを試すことです$p$。 それぞれについて$p$、残りがすべてなくなるようにするために必要なフリップの数を計算します。$p$になる$R$そしてすべてが正しくなる$L$。 これは簡単です: 固定の場合$p$、すべての位置をスキャンし、必要な方向に対する不一致をカウントします。 それぞれの評価にかかる費用$O(n)$、そして、あります$O(n)$の選択肢$p$、につながる$O(n^2)$総仕事量。 と$n = 2000$、これは約 400 万文字のチェックですが、問題ありません。 

重要な観察は、各ポジションが構造化された方法で各候補センターに独立して貢献しているということです。 インデックスの文字$i$すべてのセンターにとって間違っています$p > i$もしそうなら$L$、すべてのセンターにとって間違っています$p < i$もしそうなら$R$。 これにより、中心が移動したときに寄与がどのように変化するかを事前に計算できます。 毎回最初から再計算するのではなく、$p$のプレフィックス数を維持できます。$L$およびサフィックスの数$R$で各コストを導き出します。$O(1)$。 

ブルート フォースから最適解への移行では、すべての分割ポイントが各インデックスがどちらの側に属するかのみを変更するため、コストは 2 つのプレフィックス/サフィックス統計の合計にすぎないことが認識されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (すべてのセンターを試し、毎回再計算) |$O(n^2)$|$O(1)$| 承認済み |
 | プレフィックス/サフィックスの事前計算 |$O(n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 問題を分割点の選択として書き直します$p$コストは次のようになります。 

1. 位置にある文字の数を数える$[0, p-1]$ではありません$R$, なぜなら、それらは最終的に次のようになるはずだからです。$R$。 
2. Count how many characters in positions$[p+1, n-1]$ではありません$L$, なぜなら、それらは最終的に次のようになるはずだからです。$L$。 
3. 位置を無視する$p$。 

プレフィックスの合計を計算します。$R$およびサフィックスの合計$L$。 

1. アレイを構築する`prefR`どこ`prefR[i]`何個保存するか`R`に登場するキャラクター`s[0..i-1]`。 これにより、分割の左側にすでに存在する正しい位置がいくつあるかを素早く数えることができます。 
2. アレイを構築する`sufL`どこ`sufL[i]`何個保存するか`L`に登場するキャラクター`s[i..n-1]`。 これにより、分割の右側に正しい位置がいくつ存在するかがキャプチャされます。 
3. 各分割候補位置について$p$、左側で必要なフリップの数を次のように計算します。$p - \text{prefR}[p]$、すべてがまだではないので、$R$反転する必要があります。 
4. 右側で必要なフリップの数を次のように計算します。$(n - p - 1) - \text{sufL}[p+1]$、すべてがまだではないので、$L$反転する必要があります。 
5. 全体の最小和を取る$p$。 

これが機能する理由は、固定中心の場合、最適な戦略では異なるインデックス間の相互作用を考慮する必要がないためです。 各インデックスは、その側に必要な方向にすでに一致しているか、反転する必要があります。 1 つのインデックスに対するフリップの選択は、他のインデックスの正確さに影響を与えないため、コストは独立した寄与にきれいに分解されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    s = input().strip()

    prefR = [0] * (n + 1)
    for i in range(n):
        prefR[i + 1] = prefR[i] + (1 if s[i] == 'R' else 0)

    sufL = [0] * (n + 1)
    for i in range(n - 1, -1, -1):
        sufL[i] = sufL[i + 1] + (1 if s[i] == 'L' else 0)

    ans = n
    for p in range(n):
        left_cost = p - prefR[p]
        right_cost = (n - p - 1) - sufL[p + 1]
        ans = min(ans, left_cost + right_cost)

    print(ans)

if __name__ == "__main__":
    solve()
```プレフィックス配列は、後に分割が配置されている場合に、左側の要件をすでに満たしている位置の数を追跡します。 サフィックス配列は、右側に対して対称的な役割を果たします。 すべての分割点にわたるループは、ターゲット位置のあらゆる可能な選択肢を直接評価し、ループ内の式はまさに不一致を独立したセグメントに分解したものです。 

よくある間違いは、ピボット インデックスを除外するのを忘れることです。$p$両側から。 もう一つは、左側が望むかどうかを混同している$R$または$L$、これはプレフィックスの合計の解釈を反転します。 最も安全な実装方法は、それぞれの側がどうなるかを明示的に書き留めてから、一致ではなく不一致をカウントすることです。

 ## 特殊なケース

 次のような単一方向の文字列の場合`LLLL`、すべての分割は少なくとも片側でゼロコストを生成し、プレフィックス配列とサフィックス配列が完全な均一性を捕捉するため、アルゴリズムはすべての分割を正しく評価します。 どの分割でも$p$、`prefR[p] = 0`そして`sufL[p] = n-p`、一貫して最小値がゼロになります。 

次のような交互文字列の場合`LRLRLR`、貪欲なアプローチは決定を揺るがす傾向がありますが、分割ベースの定式化では各候補センターを独立して分離します。 評価中$p = 3$バランスの取れた不一致数が直接得られ、アルゴリズムは以前の位置の影響を受けることなく最小の修正コストを正確に特定します。 

境界分割の場合$p = 0$そして$p = n-1$、片側が空いています。 プレフィックスまたはサフィックスの寄与が消えるため、数式は正しく削減され、エッジに特別な処理が必要ないことが確認されます。
