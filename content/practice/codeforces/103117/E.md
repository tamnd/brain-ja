 ## 解決策
 ## 問題の理解

 n 個の頂点といくつかの既存の無向エッジを持つグラフが与えられます。 これに加えて、頂点の順列が与えられます。これは、DFS が最初にノードを発見した順列の最初の頂点から開始された正確な順序を表します。 

タスクは、標準の再帰的 DFS (ある順序で近傍を反復処理する) を実行し、この検出順序を正確に再現する方法が存在するように、最小限の数の新しいエッジを追加することです。 

重要な解釈の変更は、「この順序でノードを恣意的に訪問」しようとしているわけではないということです。 DFS には、シーケンス内の必要な次の頂点から逸脱することを強制する選択点がないことを確認しようとしています。 言い換えれば、DFS スタック内のノードにいるとき、最初に他のものを探索することを強制されることなく、DFS が合法的に次に選択できる方法で、順列内で次に訪問されていないノードに到達可能である必要があります。 

制約サイズ n、m が最大 10^5 であるということは、どの解も線形または O(n log n) に近い必要があることを意味します。 m はすでに O(n^2) を実行不可能にするほど十分に密である可能性があるため、エッジまたは頂点上の二次関数はすべてすぐに失敗します。 

既存のグラフが既に DFS 順序を「ほぼ」サポートしているが、順列の連続するセグメント間の接続が欠落しているために失敗する場合、微妙なエッジ ケースが発生します。 たとえば、順列が 1、2、3、4 であるが、エッジが (1、3) と (3、4) のみを接続している場合、グラフが接続されていても、必要な順序を破らずに 1 からの DFS は 2 に到達することはできません。 これは、接続性だけでは十分ではなく、順序付けの制約が重要であることを示しています。 

別のエッジ ケースは、指定されたエッジに複数のコンポーネントが存在するが、順列により異なるコンポーネントからのノードがインターリーブされる場合に発生します。 その場合、エッジを追加して、厳密に DFS に準拠した構造でコンポーネントをステッチする必要があります。 

## アプローチ

 強引なアイデアは、順列を明示的に強制することによって DFS 注文の構築をシミュレートすることです。 順列内の位置 i ごとに、現在のグラフ内に現在の DFS フロンティアから次のノードまでの DFS 制約に違反しないパスが存在するかどうかをチェックすることを想像できます。 そうでない場合は、エッジを追加して続行します。 

ただし、DFS の一貫性を直接シミュレートするとコストがかかります。 各チェックにはグラフの走査が必要な場合があり、すべての n 位置に対して繰り返し実行すると、最悪のケースは O(n^2) 以上になります。 n が 10^5 までの場合、これは実行できません。 

重要な観察は、DFS はグローバル構造を直接考慮しておらず、スタックのような進行を介した到達可能性のみを考慮しているということです。 指定された順序でノードを処理する場合、グラフに「パワーを追加」する必要があるのは、置換内の次のノードが、既存の構造の下で現在の DFS アクティブ コンポーネントから到達できない場合だけです。 

これは建設的な解釈につながります。つまり、現在の DFS が到達可能な「フロンティア」を表す構造を維持しているということです。 置換内の次のノードが既存のエッジを使用してこのフロンティアに接続されていない場合は、エッジを追加して接続し、置換に沿って DFS ツリーを効果的にステッチする必要があります。 

より深い洞察は、最適な構造は本質的に、事前順序が指定された順列と正確に一致する DFS ツリーであるため、その事前順序と一致するツリーを再構築し、すでにそれに一致する隣接制約の数を数えているということです。

 ## アルゴリズムのチュートリアル

1. 指定された順列を DFS ツリーの必要な事前順序として解釈します。 順列の最初のノードがこのツリーのルートです。 これで構築の開始点が決まりました。 
2. 既存のエッジ上で結合構造または接続追跡メカニズムを維持します。 目的は、順列の連続する「セグメント」が現在のグラフですでに接続されているかどうかを知ることです。 
3. 順列を左から右にスイープし、各位置を DFS が検出する必要がある次のノードとして扱います。 
4. 次の各ノードについて、既存のエッジを使用して現在の DFS アクティブ領域からすでに到達可能かどうかを確認します。 到達可能な場合は、何も追加する必要はなく、概念的には DFS を継続します。 
5. 到達できない場合は、現在アクティブな DFS 領域内のノードに接続するエッジを追加する必要があります。 欲張りな選択は、順列の前のノードに接続することです。これにより、不必要な分岐が発生することなく DFS の一貫性が維持されます。 
6. このような強制接続を 1 つの追加エッジとしてカウントします。 
7. すべてのノードが処理されるまで続行し、構築されたグラフが順列に正確に従う DFS を許容することを確認します。 

### なぜ効果があるのか

 中心となる不変条件は、置換のプレフィックス i を処理した後、そのプレフィックス内のすべてのノードが単一の DFS 整合性の到達可能な構造内に存在することです。これは、置換プレフィックスと整合性のある DFS ツリーが存在することを意味します。 この構造から次のノードに到達できないことが検出されると、DFS は切断されたコンポーネントまたは到達不能な領域間を「テレポート」できないため、新しいエッジを追加せずに次のノードを含めることが DFS の順序にできないことを意味します。 したがって、追加された各エッジは、現在のグラフの構造上の不可能性によって強制され、それを追加すると、以前の正確さに影響を与えることなく、DFS の実現可能性が最小限に回復されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.p = list(range(n+1))
        self.r = [0]*(n+1)

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return
        if self.r[a] < self.r[b]:
            a, b = b, a
        self.p[b] = a
        if self.r[a] == self.r[b]:
            self.r[a] += 1

def solve():
    n, m = map(int, input().split())
    perm = list(map(int, input().split()))
    
    dsu = DSU(n)
    
    for _ in range(m):
        u, v = map(int, input().split())
        dsu.union(u, v)

    ans = 0

    for i in range(1, n):
        if dsu.find(perm[i]) != dsu.find(perm[i-1]):
            ans += 1
            dsu.union(perm[i], perm[i-1])

    print(ans)

if __name__ == "__main__":
    solve()
```DSU は、現在のグラフの接続を追跡するために使用されます。 既存の各エッジはコンポーネントをマージし、順列を順番にスキャンします。 連続する 2 つの頂点が異なるコンポーネント内にある場合は、エッジを追加してそれらを接続する必要があります。これは、DFS はエッジなしでは切断されたコンポーネント間を移動できないためです。 

微妙な点は、順列内の連続する要素間の接続性のみを考慮していることです。 それらがすでに接続されている場合、DFS はその順序を尊重するように調整できます。 そうでない場合は、ブリッジの導入を余儀なくされます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、グラフがすでに接続されているが、順列が離れたノード間でジャンプする場合です。 この場合、構造を変更せずに順列に従うように DFS を命令できるため、エッジは必要ありません。 DSU は、連続するすべてのノードが同じコンポーネント内にあり、操作がゼロであることを示すことでこれを確認します。 

もう 1 つのエッジ ケースは、コンポーネント間で順列が交互に存在する、完全に切り離されたグラフです。 このアルゴリズムは、コンポーネント間のスイッチごとに 1 つのエッジを正しく挿入し、DFS 連続性を強制するチェーンを効果的に構築します。 

3 番目のエッジ ケースは n = 1 で、エッジは存在せず、操作は必要ありません。 ループは決して実行されず、答えはゼロのままで、DFS の自明なケースと一致します。
