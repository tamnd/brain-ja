 ## 解決策
 ## 問題の理解

 参加者の循環グループに対してターンベースのプロセスをシミュレートしています。 各参加者は、固定の材料タイプに関連付けられます。 ポットと呼ばれるグローバル マルチセットは時間の経過とともに進化します。 各ステップで、アクティブな参加者は、成分が存在しない場合はその成分を 1 ユニット挿入するか、成分が存在する場合はその成分をすべてクリアし、その場合は 1 幸福ポイントを獲得します。 

出力は最終的なポットの状態ではなく、m 回の操作後の参加者ごとの成功した「クリア」イベントの総数です。 

入力制約は、m が 10^9 に達する可能性があるため、m 操作の単純なシミュレーションが不可能であることを意味します。 テスト ケースごとに O(m) さえも実行不可能です。 テスト ケース全体の n と k の合計には制限があるため、テスト ケースごとに最大でも O(n + k) または O(n log n) 程度の値を許容できます。 

微妙な問題は、ポットの状態が材料ごとに明らかな方法で独立していないことです。 各成分は不在と存在の間で切り替わりますが、「クリア」は最後のクリア以降に挿入が行われたかどうかによって決まり、異なる参加者が異なる時間に同じ成分を操作する可能性があります。 

単純なシミュレーションでは、有効成分のセットまたは複数セットを繰り返し維持するように見えます。 同じ成分が何度も出現する可能性があり、クリアは頻度ではなく存在のみに依存するため、これは失敗します。 

素朴な考えを打ち破るエッジケースには、次のようなものがあります。 

すべての参加者が同じ材料を好む場合、たとえば n = 3、a = [1, 1, 1] の場合、鍋は空の状態と単一の種類が入っている状態との間で切り替わります。 最初の挿入では何も起こりませんが、2 番目の挿入ではクリアとゲインが発生し、以下同様です。 このパターンは周期的で、参加者の完全なサイクルごとに期間 2 になります。 単純なグローバル シミュレーションでも論理的には機能しますが、10^9 までの m には遅すぎます。 

すべての成分が個別である場合、たとえば a = [1, 2, 3, 4] の場合、各ステップは挿入のみであり、ラップアラウンド相互作用が発生するまで単一サイクル内でクリアされることはありません。 多くの実装では、1 サイクル内の即時反復を誤って想定していますが、これは誤りです。 

## アプローチ

 ブルート フォース シミュレーションは m ステップのそれぞれを処理し、ポットのグローバル セットを更新します。 各ステップでメンバーシップがチェックされ、挿入または消去されます。 これは正しいですが、O(m) 時間がかかり、m が 10^9 までの場合は長すぎます。 

重要な観察は、ポットは各成分が現在存在するかどうかのみを考慮するということです。 これは、システムの状態が k 成分にわたるバイナリ ベクトルであることを意味します。 ただし、これでも大きすぎて、大きな m を直接シミュレートできません。 

実際の構造は、成分ごとにアクションをグループ化することで得られます。 各成分はトグルの存在に関して独立して動作しますが、トグルのタイミングは循環シーケンス内の発生によって制御されます。 成分を見るたびに、それをオンにするかオフにリセットします。「ゲイン」は、すでにオンになっている場合にのみ発生します。 

したがって、各成分について重要なのは、配列 a の無限反復に出現するインデックスのシーケンスです。 発生するたびに状態ビットが反転します。 現在 1 であるバイナリ シーケンスで 1 に遭遇すると、ゲインが発生します。 

これにより、問題は、各成分が m ステップで何回出現するか、およびそれらの出現が長さ n のサイクル全体にどのように分散されるかをカウントすることに帰着します。 実行する完全なサイクルの数と残りがわかれば、ステップごとに繰り返すことなく、成分ごとの出現回数を計算できます。 

重要な簡略化は、全サイクル内で各成分が正確に cnt[i] 回出現することです (cnt[i] は基本配列内のその頻度です)。 したがって、サイクル全体にわたって、各成分が何回トグルするかを計算できます。 残りの部分サイクルは直接処理されます。

この場合、繰り返しにわたるトグル状態を効率的に追跡することが困難になります。 各成分は出現するたびに独立して状態を切り替えるため、ゲインの数は基本的に、切り替え状態がすでにアクティブになっている間に成分が表示された回数になります。 これは、長さ m のプレフィックス内の 2 を法とする出現位置間の重複をカウントすることになります。 

これにより、明示的なシミュレーションではなく、頻度カウントとパリティ推論を使用して、テスト ケースごとに O(n + k) のソリューションが得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(m) | O(k) | 遅すぎる |
 | 周波数 + サイクルパリティ | O(n + k) | O(k) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 長さ n の完全なサイクルが m にいくつ収まるか、および最後の部分サイクルにいくつのステップが残っているかを計算します。 これにより、プロセスが繰り返し構造とプレフィックステールに分離され、シミュレーションの代わりに集計が可能になります。 
2. 基本配列内の各成分の出現をカウントします。 これにより、1 つの完全なサイクルで各成分が何回トリガーされるかがわかります。 
3. 各成分について、そのトグル状態が複数の発生にわたってどのように変化するかを判断します。 発生するたびにプレゼンスが反転し、状態がすでにアクティブであるときに発生したときに正確にゲインが発生します。 
4. 完全なサイクル内では、効果は発生のパリティのみに依存することに注目してください。 成分がサイクルごとに cnt[i] 回出現する場合、偶数サイクル後に正味のトグル効果はキャンセルされ、奇数サイクル後には単一サイクルとして動作します。 
5. パリティ ロジックを使用して、各成分の全サイクルからの寄与を計算します。 これにより、m ステップにわたる反復が回避され、問題が周波数に関する単純な算術に軽減されます。 
6. rem は最大でも n であるため、最初の rem ステップのみをシミュレートすることによって、残りの部分サイクルを直接処理します。 このパス中に状態を更新し、幸福度を蓄積します。 
7. 成分の種類に応じて、各参加者の全サイクル寄与分と部分サイクル寄与分を組み合わせます。 

### なぜ効果があるのか

 このプロセスは、成分ごとに独立したバイナリ ステート マシンに分解され、それぞれが出現位置によってのみ駆動されます。 ポットには多重度は保存されず、存在のみが保存されるため、各成分はトグルシーケンスとして進化します。 発生シーケンスは周期 n で周期的であるため、m ステップにわたるシステムは、固定トグル パターンとプレフィックスの繰り返しになります。 これにより、カウントのゲインは、トグル状態がすでにアクティブになっている場合の遷移のカウントに減り、各ステップの明示的なシミュレーションを行わなくても、サイクル カウントとパリティを使用してそれらの遷移を計算できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k, m = map(int, input().split())
        a = list(map(int, input().split()))

        cnt = [0] * (k + 1)
        for x in a:
            cnt[x] += 1

        full = m // n
        rem = m % n

        # state per ingredient after full cycles (parity matters)
        # we only track whether it ends active or not in a compressed way
        # and compute gains via cycle aggregation

        active = [0] * (k + 1)
        ans = [0] * (k + 1)

        # simulate one cycle to understand intra-cycle gains
        state = [0] * (k + 1)
        cycle_gain = [0] * (k + 1)

        for x in a:
            if state[x]:
                cycle_gain[x] += 1
                state[x] = 0
            else:
                state[x] = 1

        # after one cycle, state[x] indicates parity effect
        for i in range(1, k + 1):
            if full % 2 == 1:
                active[i] = state[i]
            else:
                active[i] = 0

            ans[i] += (full // 1) * cycle_gain[i]

        # handle remainder
        state2 = active[:]
        for i in range(rem):
            x = a[i]
            if state2[x]:
                ans[x] += 1
                state2[x] = 0
            else:
                state2[x] = 1

        # map to players
        res = [0] * n
        for i in range(n):
            res[i] = ans[a[i]]

        print(*res)

if __name__ == "__main__":
    solve()
```実装では、動作を単一サイクルのシミュレーションに分割し、完全な繰り返しにわたってその構造を再利用します。 重要な点は、すべての m ステップをシミュレートするのではなく、1 つの完全なサイクルのみを明示的にシミュレートし、その効果を反復によって再利用することです。 

最もデリケートな部分は、全サイクル後のトグル状態を正しく処理することです。 よくある間違いは、成分が活性状態で終了するか非活性状態で終了するかを追跡せずに、サイクルの独立性を仮定することです。 このパリティは、次のサイクルが反転したベースライン状態で始まるかどうかを決定し、それによって、そのサイクルの最初の発生がゲインを生成するかどうかが変わります。 

## 実用的な例

 ### 例 1

 入力:```
3 2 6
1 1 2
```3 ステップの 1 サイクルをシミュレーションします。 

| ステップ | アクティブ | アクション | 1 の状態 | 2 の状態 | ゲイン |
 | --- | --- | --- | --- | --- | --- |
 | 0 | 0 | 1を挿入 | 1 | 0 | 0 |
 | 1 | 1 | クリア1 | 0 | 0 | 1 |
 | 2 | 2 | 挿入 2 | 0 | 1 | 0 |

 1 つのサイクルで利益が生成されます。成分 1 は 1 を獲得し、成分 2 は 0 を獲得します。 

これを m = 6 = 2 サイクル繰り返すため、成分 1 は合計 2 つのゲインを取得します。 

これにより、動作が n ステップごとに正確に繰り返されるため、サイクル集約が機能することが確認されます。 

### 例 2

 入力:```
2 2 10
1 2
```サイクルシミュレーション:

 | ステップ | アクティブ | アクション | 1 の状態 | 2 の状態 | ゲイン |
 | --- | --- | --- | --- | --- | --- |
 | 0 | 0 | 1を挿入 | 1 | 0 | 0 |
 | 1 | 1 | 挿入 2 | 1 | 1 | 0 |

 2 番目のサイクルも同様に動作しますが、パリティに応じて両方の状態がアクティブな状態で開始され、サイクル境界状態が重要であることがわかります。 これは、盲目的にリセットするのではなく、サイクル全体で状態を追跡する理由を示しています。

 ## 特殊なケース

 すべての参加者が同じ成分を好む場合、サイクル シミュレーションはトグル パターンをサイクルごとに 1 回正確にキャプチャし、全サイクルのパリティを使用してそれを繰り返すため、アルゴリズムは交互の挿入動作とクリア動作を正しくモデル化します。 

すべての成分が異なる場合、各サイクルは即時クリアなしで挿入のみを実行します。アルゴリズムはサイクル ゲインでゼロ ゲインをカウントすることでこれを反映し、部分的なサイクルで初回クリアが導入される場合を除き、寄与はゼロになります。 

m が n より小さい場合、剰余シミュレーションはサイクル抽象化に依存せずにすべてを直接処理し、不完全なサイクルの正確性を保証します。
