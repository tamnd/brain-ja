 ## 問題の理解

 バイナリ文字列が与えられ、非常に具体的なローカル ルールに基づいて文字を繰り返し削除できます。`1`すぐに表示され、その後に`0`、これら 2 つの文字のうち 1 つだけを削除し、そのたびに文字列を縮小します。 どの文字を削除するかの選択は私たちの制御下にあり、そのような操作はいくつでも実行できます。 

目標は、長さを最小限に抑えることだけではなく、2 つのレベルの設定の下で可能な限り最高の最終文字列を生成することです。 最終文字列は常に短い方が好まれます。 2 つの結果が同じ長さの場合、辞書編集的に小さい方が優れているとみなされます。 

主な問題点は、削除が隣接するもののみ許可されることです。`10`したがって、文字列の構造はローカルに進化しますが、最適化基準はグローバルです。 このため、操作をシミュレーションしたくなりますが、どの文字を削除するかの選択の分岐により、さまざまな結果が考えられます。 

この制約は、目的のソリューションがテスト ケースごとに線形またはほぼ線形である必要があることを示唆しています。 すべてのテストの合計の長さが最大 ​​10^5 になると、ステップごとに 10^5 の操作を繰り返してもすでに制限を超えてしまうため、スワップまたは削除の二次シミュレーションはタイムアウトになります。 

微妙なエッジケースは、交互のパターンから生じます。 たとえば、`1010`、削除の選択肢が異なると残る文字列も異なり、より多くの文字列を保持することを優先すべきかどうかはすぐにはわかりません。`0`秒以上`1`s. もう 1 つの注意が必要な状況は、文字列がすでに単調である場合です。`000111`この場合、操作は実行できず、不正な貪欲ロジックが依然として不必要な変換を試行したり、境界を誤って処理したりする可能性があります。 

## アプローチ

 強引な解釈では、考えられるすべての動きをシミュレートすることになります。 各ステップで見つけられるのは、`10`ペアを削除するかどうかに応じて 2 つの状態に分岐します。`1`または`0`。 これにより、有効なペアの数が指数関数的に増加する可能性のある状態空間が作成されます。 最悪の場合、次のような文字列`101010...`には Θ(n) 個の有効なローカル移動があり、分岐により指数関数的な爆発が発生します。 メモ化しても、到達可能な文字列の数が多すぎて効率的に表現できません。 

重要な観察は、この操作では隣接する間の相互作用のみが許可されるということです。`1`そして`0`そしてそれは常に彼らの間の混乱を減らします。 任意の削除シーケンスという観点から考える代わりに、文字列が正規の形式に変換され、すべての部分が残っているとみなすことができます。`1`は相対的にできるだけ左にあります`0`s、無能力によって制約される`0`左に渡って移動する`1`削除に参加しない限り。 

より生産的な観点は、文字列をスキャンして最終的な答えを貪欲に構築することです。 私たちはスタックのような構造を維持します。`1`続いて`0`を使用すると、1 文字を削除できるため、局所的な反転を効果的に解決できます。 最適な戦略はキャンセルを繰り返すことと同じであることが判明`10`最小限の長さの結果の間で辞書編集上の最小限の構造を維持する方法での相互作用。 

これは単純な線形プロセスにつながります。つまり、スタックを使用して最適なキャンセルの効果をシミュレートします。 私たちが見るとき、`1`、それを押します。 私たちが見るとき、`0`、前のものをキャンセルしようとします`1`■ 辞書編集上の順序で最終文字列を最小限に抑えるのに有益な場合。 このプロセスは、利益が得られない場合に達成可能な最良の配置を維持することに要約されます。`10`削除が残っています。

 ## アルゴリズムのチュートリアル

 1. 文字列を左から右に繰り返し、最終結果を段階的に構築します。 すべてのステップで、現在のキャラクターが以前に見たキャラクターと対話できるかどうかを検討します。`10`パターン。 これは隣接するだけなので必要です。`1`そして`0`ペアは削除の対象となります。 
2. 答えの現時点で最良の部分構造を表すスタックを維持します。 処理する各文字は、許可された操作に基づいて追加されるか、キャンセルがトリガーされます。 
3. 遭遇したとき`1`、すぐにスタックにプッシュします。 あ`1`将来のキャンセルのパートナーとしてのみ役立ちます。`0`右側にあるので、ペアリングできるかどうかを確認するまで保管します。 
4. 遭遇したとき`0`、スタックの最上位を確認します。 ある場合`1`さらに、これを含む削除を実行できます。`10`ペア。 どちらの文字も削除できるため、辞書編集的に最終結果が小さくなるオプションを選択します。これは事実上、文字を削除することを意味します。`1`以前の構造を保存するのに役立つ場合は、そうでない場合は削除します。`0`。 
5. これを貪欲に繰り返すことで、考えられるすべての有益なキャンセルが確実に実行され、隣接するキャンセルは実行されません。`10`結果を改善できるペアは未解決のままです。 
6. 最後に、スタックには最後の最もきれいな文字列が含まれます。 

### なぜ効果があるのか

 核となる不変条件は、スタックが常に文字列を表し、それ以上のローカル操作では辞書編集または長さの目標を改善できないということです。 どれでも`10`長さを短縮したり、順序を改善したりするために依然として使用できるペアは、必然的に、`1`スタック内でその直後に`0`このようなケースは、処理された構造内で隣接した時点で常に解決されます。 これにより、アルゴリズムが有益な削除を延期したり、最終的に辞書編集的に最適な結果を悪化させるような削除を実行したりすることがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()

        stack = []

        for c in s:
            if c == '0':
                if stack and stack[-1] == '1':
                    stack.pop()
                else:
                    stack.append(c)
            else:
                stack.append(c)

        print(''.join(stack))

if __name__ == "__main__":
    solve()
```このソリューションは、各テスト ケースを独立して処理し、進化する候補文字列を格納するスタックを維持します。 実装に関する重要な決定は、問題を直ちに解決することです。`10`パターンを削除することで、`1`、この選択により、不要な辞書編集動作が防止されるため、`1`以前なら優位に立っていたポジションに固執しない`0`s.

 スタックにより、有益な削除にすぐに参加できない文字のみが保存されることが保証されます。 これにより、変換のバックトラッキングや完全なシミュレーションの必要がなくなります。

 ## 特殊なケース

 次のようなすでに非降順になっている文字列の場合`000111`、アルゴリズムはポップをトリガーせずにすべての文字をプッシュします。`10`ペアが存在します。 スタックは入力と同一のままであり、移動が不可能であるという事実と一致します。 

次のような交互文字列の場合`101010`、毎回`0`の後に表示されます`1`、アルゴリズムはすぐに 1 つをキャンセルします。`1`、構造が単一になるまで崩壊します。`0`残っています。 段階的なスタックの進化により、対象となるすべてのインタラクションが 1 回だけ消費され、遅延した最適化が必要ないことが確認されます。 

単一文字入力の場合、ループは 1 回実行され、次のいずれかを実行します。`0`または`1`スタックの相互作用がなく、些細な場合でも最小限の構造が正しく保存されます。
