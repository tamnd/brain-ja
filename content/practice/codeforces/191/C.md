 ## 解決策
 ## 問題の理解

 入力は都市のツリーを記述します。 都市の各ペア間には単純なパスが 1 つだけ存在するため、道路網は接続された非循環グラフを形成します。 

次に、いくつかの都市のペアが与えられます。 各ペアは 1 つの旅行を表します: 愚か者は都市から旅行します`a`街へ`b`木の中にあるユニークなシンプルな道に沿って。 For every road, we must count how many trips use that road.

 A direct interpretation would be: for every query`(a, b)`、からのパスを見つけます`a`に`b`そして、そのパスのすべてのエッジでカウントをインクリメントします。 これは論理的には正しいです。ツリーによってルートの一意性が保証されるからです。 

制約により、そのアプローチは即座に除外されます。 木には最大で`10^5`頂点もありえます`10^5`クエリ。 単一のパスには以下を含めることができます`O(n)`チェーン状のツリーなど、最悪の場合はエッジが発生します。 それは与える`O(nk)`になる可能性のある操作`10^10`、限界をはるかに超えています。 

木の構造は私たちにもっと強いものを与えてくれます。 2 つのノード間のすべてのパスは、通常 LCA と略される最低共通祖先を使用して表すことができます。 すべてのクエリですべてのエッジを明示的にウォークする代わりに、エンドポイントをマークし、後で 1 つの DFS でコントリビューションを集計できます。 

実装が不注意であると、いくつかのエッジケースは誤って処理されやすくなります。 

両方のエンドポイントが同じ都市であるクエリを考えてみましょう。```
3
1 2
2 3
1
2 2
```道路が使用されていないため、正しい出力は次のようになります。```
0 0
```空のパスをチェックせずにパスに沿って常にインクリメントする単純な実装では、誤ってエッジをカウントしてしまう可能性があります。 

一方のエンドポイントがもう一方のエンドポイントの祖先である場合、別の微妙なケースが発生します。```
4
1 2
2 3
3 4
1
2 4
```パスはエッジのみを使用します`(2,3)`そして`(3,4)`。 LCA 処理で LCA 自体ではなく LCA の親から 2 回減算すると、カウントが不正確になります。 

星型のツリーも正しさを強調します。```
5
1 2
1 3
1 4
1 5
2
2 3

```中心エッジの数は次のようになります。```
2 2 2 2
```すべての旅はルートを通過します。 多くのパスが 1 つのノードで重複しているため、サブツリーの蓄積における間違いは、そのような構成を過小評価することがよくあります。 

## アプローチ

 ブルート フォース ソリューションは、各クエリを個別に処理します。 すべてのペアについて`(a, b)`、それらの間のパスを見つけて、そのパス上のすべてのエッジを増分します。 

グラフはツリーであるため、これを行う 1 つの方法は、DFS または親クライミングを使用することです。 すべてのペアには単純なパスが 1 つだけあるため、これらのエッジにアクセスすることは問題の定義と直接一致するため、この解決策は正しいです。 

問題は規模だ。 単一のパスには以下が含まれる場合があります`n - 1`エッジ。 と`10^5`クエリの場合、最悪の場合の作業はおおよそ次のようになります。```
10^5 × 10^5 = 10^10
```これでは数桁遅すぎます。 

重要な点は、実際にはエッジをすぐに更新する必要がないということです。 各エッジを通過するパスの最終的な数だけが必要です。 

追加するとします`+1`クエリ パスの両方のエンドポイントで減算します。`2`LCAで。 後でリーフから上に向かって DFS を実行すると、各サブツリーはそれを通過するアクティブなパスの数を蓄積します。 

なぜこれが機能するのでしょうか?

 ノードを接続するエッジを想像してください`u`その親に。 集計後、次の場所に保存される値`u`をルートとするサブツリーに入るパスの数に等しい`u`サブツリー内にそれを残すパスの数を差し引いたものです。 まさにこれらの残りのパスは、間のエッジを横切る必要があります。`u`とその親。 

これにより、コストのかかるパスごとのエッジ更新が次のように変換されます。 

1. クエリごとの一定時間のエンドポイント マーキング。 
2. ツリー全体にわたる 1 つの DFS 蓄積。 

残る唯一の課題は、LCA を効率的に計算することです。 バイナリリフティングはそれを解決します`O(log n)`クエリごとに。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nk) | O(n) | 遅すぎる |
 | 最適 | O((n + k) log n) | O(n log n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力エッジからツリー隣接リストを構築します。 

DFS トラバーサルと祖先の前処理を可能にする構造が必要です。 
2. 任意のルート (通常はノード) から DFS を実行します。`1`。 

この DFS 中に、以下を保存します。 

- すべてのノードの親
 - すべてのノードの深さ
 - ノードをその親に接続するエッジインデックス

 これらの値は、LCA 計算と、入力順にエッジに回答を割り当てる両方の場合に必要です。 
3. バイナリリフティングテーブルを構築します。 

させて`up[v][j]`になる`2^j`ノードの - 番目の祖先`v`。 

これにより、一度に 1 つのエッジを登るのではなく、対数時間で上に移動することができます。 
4. あらゆるクエリに対して`(a, b)`、計算する`lca(a, b)`。 

次に適用します:

 -`cnt[a] += 1`-`cnt[b] += 1`-`cnt[lca] -= 2`これにより、すべてのエッジに直接触れるのではなく、パスが暗黙的にエンコードされます。 
5. ルートから 2 番目の DFS を実行します。 

すべての子サブツリーについて、その累積値を再帰的に計算し、それを現在のノードに追加します。 

子サブツリーが値を返す場合`x`、それではまさに`x`パスはその子とその親の間のエッジを横切ります。 
6. 返されたサブツリー値を、子を親に接続するエッジの答えとして保存します。 

各エッジはルート ツリー内の 1 つの子と親の関係に厳密に属しているため、すべてのエッジは 1 つの応答を取得します。 
7. 元の入力順序で回答を出力します。 

### なぜ効果があるのか

 各クエリは、パスの両方のエンドポイントに 1 つのユニットを追加します。 サブツリーの合計が上向きに集約されると、エンドポイント間の実際のルートに沿ったものを除き、パス内で寄与がキャンセルされます。 

引き算`2`LCA での修正が重要です。 これがないと、共有祖先領域は 2 回カウントされます。 キャンセル後、すべてのエッジは、そのエッジの一方の側からもう一方の側に交差するクエリ パスの数を正確に受け取ります。 

親間のエッジの場合`p`そして子供`u`、でのサブツリーの合計`u`は、そのサブツリー内のクエリ エンドポイントの数から、そこに完全に含まれる完全なパスの数を引いたものと等しくなります。 残りの不一致パスはすべてエッジを通過する必要があります`(p, u)`。 その数はまさに必要な答えです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(1 << 25)

LOG = 17 + 1

def solve():
    n = int(input())

    graph = [[] for _ in range(n + 1)]

    edges = []

    for idx in range(n - 1):
        u, v = map(int, input().split())
        graph[u].append((v, idx))
        graph[v].append((u, idx))
        edges.append((u, v))

    parent = [[0] * (n + 1) for _ in range(LOG)]
    depth = [0] * (n + 1)
    edge_id = [-1] * (n + 1)

    def dfs(v, p):
        parent[0][v] = p

        for to, idx in graph[v]:
            if to == p:
                continue

            depth[to] = depth[v] + 1
            edge_id[to] = idx
            dfs(to, v)

    dfs(1, 0)

    for j in range(1, LOG):
        for v in range(1, n + 1):
            parent[j][v] = parent[j - 1][parent[j - 1][v]]

    def lca(a, b):
        if depth[a] < depth[b]:
            a, b = b, a

        diff = depth[a] - depth[b]

        for j in range(LOG):
            if diff & (1 << j):
                a = parent[j][a]

        if a == b:
            return a

        for j in range(LOG - 1, -1, -1):
            if parent[j][a] != parent[j][b]:
                a = parent[j][a]
                b = parent[j][b]

        return parent[0][a]

    k = int(input())

    cnt = [0] * (n + 1)

    for _ in range(k):
        a, b = map(int, input().split())

        g = lca(a, b)

        cnt[a] += 1
        cnt[b] += 1
        cnt[g] -= 2

    ans = [0] * (n - 1)

    def dfs2(v, p):
        total = cnt[v]

        for to, idx in graph[v]:
            if to == p:
                continue

            subtotal = dfs2(to, v)

            ans[idx] = subtotal
            total += subtotal

        return total

    dfs2(1, 0)

    print(*ans)

solve()
```最初の DFS はツリーをルート化し、構造情報を記録します。 の`edge_id`配列は、どの入力エッジがノードをその親に接続するかを記憶します。 回答は DFS 順序ではなく元の入力順序で印刷する必要があるため、このマッピングが必要です。 

バイナリ リフティング テーブルには、距離の 2 乗で祖先が格納されます。 の値`LOG`満たせばいいだけ`2^LOG > n`。 と`n ≤ 10^5`, 18レベルあれば十分です。 

LCA 関数は、最初に深さを等しくしてから、親が一致するまで両方のノードを一緒に上方に持ち上げます。 これにより、クエリごとに対数的な複雑さが得られます。 

パスのエンコード手順がソリューションの中心です。 両方のエンドポイントに加算し、LCA から 2 回減算すると、ツリー上の差分配列スタイルの表現が作成されます。 エッジは直接更新されません。 

2 番目の DFS は蓄積を実行します。 子サブツリーから返される値は、そのサブツリーをその親に接続するエッジを横切るパスの数に等しくなります。 それが理由です`ans[idx] = subtotal`は正しいです。 

実装の微妙な詳細の 1 つは、小計を現在のノードに追加する前にエッジの回答を割り当てることです。 小計は、まさにそのエッジを通過するトラフィックを表します。 親合計に統合されると、その区別はなくなります。 

もう 1 つの詳細は再帰の深さです。 鎖状の木は奥行きがある場合があります`10^5`したがって、再帰制限を増やす必要があります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n + k) log n) | DFS の前処理は線形であり、各クエリには 1 つの LCA 計算が必要です。 
| スペース | O(n log n) | バイナリ リフティング テーブルがメモリ使用量を支配します。 

と`n`そして`k`どちらも最大`10^5`、この複雑さは簡単に制限に適合します。 約数百万の操作が実行されますが、注意深く実装すれば、これは Python の 2 秒の制限内に十分収まります。

## 特殊なケース

 クエリが同じノードで開始および終了する場合を考えてみましょう。```
3
1 2
2 3
1
2 2
```のLCA`(2,2)`は`2`。 更新シーケンスは次のようになります。```

cnt[2] += 1
cnt[2] -= 2
```したがって、正味の効果はゼロです。 サブツリーの集約中、すべてのサブツリーはゼロを返し、すべてのエッジの応答はゼロのままです。 これは、道路が通過しないことを正確にモデル化しています。

3 4
