 ## 解決策
 ## 問題の理解

 さまざまな兵士の信頼性があります。 すべての連続したサブ配列は、1 つの可能な警察グループを表します。 General は常に最も強力な未使用グループを最初に選択します。これは、すべての部分配列の合計が降順でソートされ、1 つずつ選択されることを意味します。 

当日選ばれたグループの信頼性が必要`k`。 言い換えれば、すべての中で、`n(n+1)/2`部分配列の合計を見つける必要があります。`k`- 番目に大きい値。 

配列には負の数値が含まれる場合があるため、部分配列が長いほど必ずしも良いとは限りません。 部分配列の和の最大値だけではなく、部分配列の合計のランキング全体が必要であるため、部分配列の最大合計手法だけでは十分ではありません。 

ここで実際の困難を強いるのは制約です。 部分配列の数はおよそ 2 次です。`n^2 / 2`。 のために`n = 10^5`、これは約になります`5 * 10^9`サブ配列は、明示的に列挙するには多すぎます。 すべての合計を保存するだけでも、数十ギガバイトのメモリが必要になります。 あらゆる解決策`O(n^2)`すぐには無理です。 

制限時間は 6 秒と長く、通常は、`O(n log^2 n)`または`O(n log n)`高度なデータ構造を備えたソリューションが期待されています。 

難しいのは、上部を構築するように求められていないことです。`k`直接合計します。 正しいアプローチは、答えを二分探索して、少なくともあるしきい値以上の合計を持つ部分配列の数を繰り返し数えることです。`x`。 

いくつかのエッジケースでは、単純な実装が静かに破壊されます。 

すべての数値が負である配列を考えてみましょう。 

入力：```
3 2
-5 -2 -7
```すべての部分配列の合計は次のとおりです。`[-5, -7, -14, -2, -9, -7]`降順でソート:`[-2, -5, -7, -7, -9, -14]`答えは`-5`。 

サブ配列が大きいほど常に強力であると仮定する不注意な実装は、すぐに失敗します。 

もう 1 つの微妙なケースは、合計が重複している場合に発生します。 

入力：```
3 4
1 1 1
```部分配列の合計は次のとおりです。`[1,2,3,1,2,1]`降順でソート:`[3,2,2,1,1,1]`4番目に大きい値は、`1`。 

カウントが厳密に大きい最初の値をバイナリ検索すると、`k`以上ではなく、`k`、重複すると off-by-one エラーが発生します。 

大きな値も重要です。 

入力：```
2 1
1000000000 1000000000
```最適な部分配列の合計は次のとおりです。`2000000000`。 

32 ビット整数を使用すると、ここでオーバーフローが発生します。 Python はこれを自動的に処理しますが、低レベルの言語では、あらゆる場所で 64 ビットの演算が必要になります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 すべての連続する部分配列を生成し、その合計を計算し、すべての合計をリストに格納し、リストを降順に並べ替えて、`k`- 番目の要素。 

プレフィックス合計により、サブ配列合計の計算が削減されます。`O(length)`に`O(1)`したがって、すべての合計コストを生成します`O(n^2)`。 分別するとコストがかかる`O(n^2 log n)`。 

これは小さな配列では機能しますが、`n = 10^5`サブアレイの数は約 50 億です。 それらを 1 回繰り返すことさえ不可能です。 

重要な観察は、実際にはすべての合計を正確に順序付ける必要はないということです。 必要な値は 1 つだけです。`k`- 番目に大きい。 この形式の問題は、次の質問に答えることができれば、はるかに簡単になることがよくあります。 

"少なくとも和を持つ部分配列はいくつありますか`x`？」

 この数を効率的に計算できると仮定します。 すると二分探索が可能になります。 

少なくとも`k`部分配列は少なくとも合計を持っています`x`、その場合、答えは少なくとも次のようになります`x`。 

未満の場合`k`サブ配列が到達する`x`、 それから`x`大きすぎます。 

これで、タスクは少なくとも合計を含む部分配列を数えるようになります`x`。 

プレフィックスの合計を次のようにします。`pref[i] = a[1] + ... + a[i]`サブアレイ`(l, r)`合計があります:`pref[r] - pref[l-1]`私たちが望んでいるのは:`pref[r] - pref[l-1] >= x`並べ替え:`pref[l-1] <= pref[r] - x`したがって、プレフィックスを左から右にスキャンしながら、それぞれ`pref[r]`以下を超えない以前のプレフィックスの合計の数が必要です`pref[r] - x`。 

これは古典的な順序統計の問題です。 

プレフィックス合計は非常に大きく負になる可能性があるため、プレフィックス合計を調整圧縮し、フェンウィック ツリーを使用して以前のプレフィックス合計の頻度を維持します。 

各カウンティングパスのコスト`O(n log n)`。 回答範囲にわたる二分探索では、別の対数係数が追加されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n² log n) | O(n²) | 遅すぎる |
 | 最適 | O(n log² n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. プレフィックスの合計を作成します。 

定義する：`pref[0] = 0`そして：`pref[i] = pref[i-1] + a[i]`すべての部分配列の合計は、2 つのプレフィックスの合計の差として記述できるようになりました。 
2. 答えを二分探索します。 

可能な最小の部分配列の合計は少なくとも`-10^14`、最大のものは最大です`10^14`、 なぜなら`n ≤ 10^5`そして`|a[i]| ≤ 10^9`。 

最大値を二分探索します`x`少なくともそうなるように`k`部分配列は少なくとも合計を持っています`x`。 
3. 固定閾値の場合`x`、有効な部分配列をカウントします。 

ポジションごとに`r`、以前のインデックスの数が必要です`l-1`満足のいく：`pref[l-1] <= pref[r] - x`これはプレフィックス頻度クエリになります。 
4. すべてのプレフィックス合計を座標圧縮します。 

フェンウィック ツリーは、任意の大きな整数ではなく、インデックスを処理します。 

すべてのプレフィックスの合計を収集し、並べ替えて、重複を削除します。 
5. プレフィックスを左から右にスキャンします。 

最初に挿入します`pref[0]`。 

それぞれについて`pref[r]`:

 挿入されたプレフィックスの合計がいくつあるかを確認します。`<= pref[r] - x`。 

この数を答えに追加します。 

次に挿入します`pref[r]`フェンウィックの木の中へ。 
6. カウント結果を二分探索内で使用します。 

カウントが少なくとも`k`、 それから`x`は実現可能なので、より大きな値を試してみます。 

さもないと、`x`は大きすぎるため、より小さい値を検索します。 
7. 二分探索が終了したら、実行可能な最大値を出力します。 

### なぜ効果があるのか

 適切なエンドポイントごとに`r`、アルゴリズムは、少なくとも部分配列の合計を生成する左端点を正確にカウントします。`x`。 すべての有効な部分配列は、次を満たすプレフィックス合計の 1 つのペアに対応します。`pref[r] - pref[l-1] >= x`フェンウィック ツリーは以前のプレフィックスの合計をすべて維持するため、すべてのサブ配列が 1 回だけカウントされます。 

実現可能性が単調であるため、二分探索は有効です。 少なくとも`k`部分配列は少なくとも合計を持っています`x`の場合、より小さなしきい値ごとに同じことが当てはまります。 この単調性により、二分探索が正確に収束することが保証されます。`k`- 番目に大きい部分配列の合計。 

## Python ソリューション```python
import sys
from bisect import bisect_right

input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, idx, val):
        while idx <= self.n:
            self.bit[idx] += val
            idx += idx & -idx

    def sum(self, idx):
        res = 0
        while idx > 0:
            res += self.bit[idx]
            idx -= idx & -idx
        return res

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    pref = [0]
    for x in a:
        pref.append(pref[-1] + x)

    coords = sorted(set(pref))

    def count_ge(x):
        fw = Fenwick(len(coords))
        total = 0

        pos0 = bisect_right(coords, pref[0])
        fw.add(pos0, 1)

        for i in range(1, n + 1):
            need = pref[i] - x

            cnt = bisect_right(coords, need)
            total += fw.sum(cnt)

            pos = bisect_right(coords, pref[i])
            fw.add(pos, 1)

        return total

    lo = -10**15
    hi = 10**15

    while lo < hi:
        mid = (lo + hi + 1) // 2

        if count_ge(mid) >= k:
            lo = mid
        else:
            hi = mid - 1

    print(lo)

solve()
```最初のセクションでは、すべての部分配列の合計が 2 つの値の差になるようにプレフィックスの合計を計算します。 これは、カウントを可能にする核となる変換です。 

フェンウィック ツリーには、以前に確認されたプレフィックス合計の頻度が保存されます。 プレフィックスの合計は負で非常に大きくなる可能性があるため、座標圧縮によりプレフィックスの合計がコンパクトなインデックス範囲にマップされます。 

機能`count_ge(x)`二分探索のカウントステップを実行します。 現在の各プレフィックス合計について`pref[i]`、以前のプレフィックス合計が次を満たす数をカウントします。```
pref[j] <= pref[i] - x
```への呼び出し`bisect_right`微妙ですが重要です。 厳密にはしきい値以下ではなく、しきい値以下の値が必要です。 使用する`bisect_left`ここでは、重複するプレフィックス合計が存在する場合、不正確な答えが生成されます。 

二分探索では、実行可能な最大の値が検索されます。 中間点の式:```
mid = (lo + hi + 1) // 2
```上向きにバイアスすることで無限ループを回避します。 

検索範囲は`±10^15`、すべての可能な部分配列の合計を安全にカバーします。

 ## 特殊なケース

 もう一度、すべてが陰性の場合を考えてみましょう。 

入力：```
3 2
-5 -2 -7
```プレフィックスの合計は次のようになります。`[0,-5,-7,-14]`確認するときは`x = -5`、アルゴリズムは正確に 2 つの有効な部分配列をカウントします。`[-5]`そして`[-2]`。 

フェンウィック ツリー ロジックはプレフィックスの合計のみを比較するため、引き続き機能します。 積極性についての仮定はどこにも現れません。 

次に、重複した合計について考えてみましょう。 

入力：```
3 4
1 1 1
```部分配列の合計を降順でソートします。`[3,2,2,1,1,1]`答えは`1`。 

カウント中に、複数のプレフィックス合計が同じ圧縮座標にマッピングされる場合があります。 使用する`bisect_right`すべての等しい値がクエリに含まれることを保証します。 それを次のものに置き換えると、`bisect_left`等しいプレフィックスの合計が誤って除外され、有効なサブ配列の数が過小評価されます。 

最後に、ランキング境界のケースを考えてみましょう。 

入力：```
2 2
5 -1
```部分配列の合計は次のとおりです。`[5,4,-1]`2番目に大きい金額は、`4`。 

二分探索では、少なくとも 2 つのサブ配列がしきい値に達するかどうかをチェックします。 で`x = 4`、カウントは正確に 2 です。`[5]`そして`[5,-1]`。 

で`x = 5`、サブ配列は 1 つだけが適格です。 

これは、バイナリ検索条件が次のようにする必要がある理由を示しています。```

```使用する`count > k`誤って正解を超えてしまう可能性があります。
