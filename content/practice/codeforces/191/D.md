 ## 解決策
 ## 問題の理解

 地下鉄システムを記述する無向接続グラフが与えられます。 すべてのエッジはトンネルであり、すべての頂点はステーションです。 グラフは頂点サボテンであることが保証されており、各頂点は最大でも 1 つの単純なサイクルに属します。 

地下鉄は 2 つのタイプの路線で構成されています。 

放射状の線は単なるパスです。 

円形の線は単純なサイクルです。 

すべてのトンネルは 1 つの回線に属しますが、駅は同時に複数の回線に属する場合があります。 

トンネルの回線への元の割り当ては失われています。 グラフだけから、このグラフを生成できる地下鉄路線の最小数と最大数を決定する必要があります。 

主な制限は、線がエッジを区切ることです。 すべてのエッジが正確に 1 つのラインに属し、すべてのラインが有効である限り、エッジを自由にパスまたはサイクルにグループ化できます。 

制約が大きいため、二次グラフ アルゴリズムは不可能です。 最大で$10^5$頂点と$3 \cdot 10^5$したがって、解はグラフ サイズにおいて線形に近くなければなりません。 すべてのパス分解をチェックしたり、接続を繰り返し再計算したりすると、ひどいタイムアウトが発生します。 

サボテンの性質は問題を完全に変えます。 一般的なグラフでは、多くの重複サイクルと複雑な分解が可能になります。 ここで、すべてのサイクルは、おそらく関節点を介する場合を除いて、他のすべてのサイクルから分離されています。 この構造により、局所的に推論することができます。 

見落としやすいエッジケースがいくつかあります。 

純粋なサイクルを考えてみましょう。```
3 3
1 2
2 3
3 1
```グラフ全体が 1 本の円形の線になる可能性があるため、最小の答えは 1 です。 すべてのエッジが長さ 1 のエッジの独自の放射状の線である可能性があるため、最大の答えは 3 です。 

不注意なツリーのみの式は、サイクルの動作が異なるため、ここでは失敗します。 

ここでパスを考えてみましょう。```
4 3
1 2
2 3
3 4
```グラフ全体がすでに 1 本の放射状の線であるため、最小値は 1 です。 各エッジは分離できるため、最大は 3 です。 

もう 1 つの注意が必要なケースは、分岐ツリーです。```
4 3
1 2
2 3
2 4
```最小値は 1 ではなく 2 です。頂点 2 の次数が 3 であるため、1 つのパスで 3 つのエッジすべてをカバーすることはできません。最適な分解はパスです。$1-2-3$そして$2-4$。 

接続成分またはサイクルをカウントするだけのソリューションでは、この次数制約が欠落します。 

最後の微妙な状況は、ツリーが接続されたサイクルです。```
5 5
1 2
2 3
3 1
3 4
4 5
```最小解ではサイクルは 1 つの円形の線に寄与し、一方、尾部は 1 本の放射状の線に寄与するため、答えは 2 になります。尾部をサイクルにマージしようとすると、頂点 3 を繰り返すことになり、これは禁止されています。 

## アプローチ

 ブルートフォースの観点は、エッジを有効なパスとサイクルに分解することを直接考えることです。 

最小の答えを得るには、可能な限りエッジを単純なパスと単純なサイクルにグループ化して、最小数のグループを検索します。 最大の答えを得るために、可能な限り積極的に分割しようとします。 

これは小さなグラフでも絶望的です。 ある木$m$エッジにはすでに指数関数的に多くのパス分解があります。 サイクルを追加すると、検索空間がさらに大きくなります。 まで$3 \cdot 10^5$エッジでは、完全な分解は完全に不可能です。 

画期的な進歩は、実際に 2 つのエッジを同じラインに属させる原因を理解することから生まれます。 

最大の答えを得るには、マージを強制するものは何もありません。 すべての単一エッジは、その端点間に長さ 1 エッジの放射状の線を独立して形成できます。 したがって、最大値はすぐに次のようになります。$$\text{max} = m$$最低限の答えは、本当の仕事がどこにあるのかということです。 

まず木に焦点を当てます。 ツリー エッジを最小数のパスに分解することは古典的な事実です。$$\left\lceil \frac{\text{number of odd degree vertices}}{2} \right\rceil$$なぜ？ すべてのパスは最大 2 つの奇数エンドポイントに寄与します。 パスの内部頂点はペアのエッジを消費します。 奇数次の頂点はパスの終点を強制します。 

サイクルを元に戻します。 

サボテンでは、すべてのサイクルが分離されています。 完全なサイクルは、パスの終点を作成せずにすべてのエッジを消費する 1 つの円形の線として捉えることができます。 サイクル頂点にアタッチされたツリーもパス処理が必要です。 

これは、すべてのサイクルを単一のスーパー頂点に圧縮することを示唆しています。 圧縮後、グラフはツリーになります。 サイクルコンポーネントはそれぞれ 1 つの必須ラインを提供し、残りのツリー構造は必要な放射状ラインの数を決定します。 

エレガントな観察は、すべてのサイクルを 1 つのオブジェクトで置き換えた後は、圧縮ツリー内の奇数次数をカウントするだけで済むということです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | 指数 | 遅すぎる |
 | 最適 | O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 隣接リストを使用して無向グラフを構築します。 
2. DFS を実行してすべてのサイクル頂点を検出します。 

グラフはサボテンであるため、すべての頂点は最大 1 つのサイクルに属します。 DFS 中に、祖先へのバック エッジに遭遇したときはいつでも、親ポインターを上向きに移動することによって、正確に 1 つの単純なサイクルを回復できます。 
3. あるサイクルに属するすべての頂点をマークし、それにサイクル ID を割り当てます。 

検出された各サイクルは、後で最小解のちょうど 1 つの円形ラインに寄与します。 
4. 各サイクルを単一のスーパーノードに圧縮します。 

サイクルに属さない頂点は通常のノードのままです。 サイクル内のエッジはすでに円形の線で覆われているため、消えます。 ツリーをサイクル頂点に接続するエッジは、サイクル スーパーノードに付随するエッジになります。 
5. 圧縮されたグラフで次数を計算します。 

すべてのサイクルが縮小され、元のグラフはサボテンであるため、圧縮されたグラフは常にツリーになります。 
6. 奇数の次数を持つ圧縮された頂点の数を数えます。 
7. 必要な放射状の線の数は次のとおりです。$$\max\left(1, \frac{\text{odd}}{2}\right)$$圧縮されたツリー部分の場合。 

特殊なケースは、グラフ全体が 1 サイクルであり、奇数の頂点がない状況を処理します。 

1. すでに循環線としてカウントされているサイクル数を加算します。 

より具体的には:$$\text{minimum} = \text{cycleCount} + \max\left(1, \frac{\text{odd}}{2}\right) - [\text{compressed graph has edges}]$$実装ではさらにクリーンな定式化が使用されます。 

すべてのサイクル エッジを精神的に削除すると、残りのフォレストには次のものが必要になります。$$\frac{\text{odd}}{2}$$パス。 

分離された各サイクルは 1 つの追加ラインに寄与します。 

1. 最大の答えは次のとおりです。$$m$$すべてのエッジが別々の放射状の線になる可能性があるためです。 

### なぜ効果があるのか

 サボテンのサイクルは決して重ならないため、圧縮されたグラフはツリーになります。 頂点の繰り返しは禁止されているため、円形の線は元の 1 つのサイクルと正確に一致する必要があります。 サイクルごとに 1 行未満を使用することは不可能です。 

サイクル エッジを削除した後、残りのすべてのエッジはフォレストに属します。 フォレストの最小パス分解は完全に奇数次数によって決定されます。 すべてのパスは 2 つの端点を提供するため、奇数次の頂点が端点として表示される必要があります。 それらを最適にペアリングすると、奇数の頂点のちょうど半分の数のパスが得られます。 

サイクル内で頂点を繰り返さないとサイクル エッジを放射状パスに結合できないため、サイクル ラインとツリー パスは独立しています。 この分離により最適性が保証されます。 

## Python ソリューション```python
import sys
sys.setrecursionlimit(1 << 25)
input = sys.stdin.readline

n, m = map(int, input().split())

g = [[] for _ in range(n)]

for i in range(m):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    g[u].append((v, i))
    g[v].append((u, i))

tin = [-1] * n
parent = [-1] * n
depth = [0] * n
used_edge = [False] * m

in_cycle = [-1] * n
cycle_count = 0

timer = 0

def dfs(v, pe):
    global timer, cycle_count

    tin[v] = timer
    timer += 1

    for to, eid in g[v]:
        if eid == pe:
            continue

        if tin[to] == -1:
            parent[to] = v
            depth[to] = depth[v] + 1
            dfs(to, eid)

        elif tin[to] < tin[v]:
            cur = v
            cyc = []

            while cur != to:
                cyc.append(cur)
                cur = parent[cur]

            cyc.append(to)

            for x in cyc:
                in_cycle[x] = cycle_count

            cycle_count += 1

dfs(0, -1)

comp_id = [-1] * n
ptr = 0

for v in range(n):
    if in_cycle[v] != -1:
        cid = in_cycle[v]
        if comp_id[v] == -1:
            for u in range(n):
                if in_cycle[u] == cid:
                    comp_id[u] = ptr
            ptr += 1

for v in range(n):
    if comp_id[v] == -1:
        comp_id[v] = ptr
        ptr += 1

deg = [0] * ptr
seen = set()

for v in range(n):
    for to, _ in g[v]:
        a = comp_id[v]
        b = comp_id[to]

        if a == b:
            continue

        if a > b:
            a, b = b, a

        if (a, b) in seen:
            continue

        seen.add((a, b))
        deg[a] += 1
        deg[b] += 1

odd = sum(d % 2 for d in deg)

min_lines = cycle_count + max(1, odd // 2)
max_lines = m

print(min_lines, max_lines)
```DFS は、祖先へのバック エッジを使用してサイクルを識別します。 グラフはサボテンであるため、各バック エッジは 1 つの単純なサイクルに正確に対応するため、親ポインターを登ることによってサイクルを回復するのは安全です。 

この実装では、サイクルに属するすべての頂点のサイクル ID が保存されます。 その後、同じサイクル ID を持つすべての頂点が 1 つの圧縮されたコンポーネントにマージされます。 

圧縮されたグラフでは、重複したエッジを避ける必要があります。 同じサイクル内の 2 つの元の頂点は両方とも外側の同じツリー頂点に接続する可能性があるため、同じ圧縮エッジが 2 回カウントされることを避けるために正規化されたペアのセットを使用します。 

最小の公式は注目に値します。 グラフにサイクルが 1 つしか含まれていない場合、圧縮されたグラフには次数 0 のノードが 1 つあるため、奇数カウントは 0 になります。それでも 1 つのライン、つまりサイクル自体が必要です。 そのため、式では次のことが使用されます。`max(1, odd // 2)`。 

すべてのエッジが独立して有効な放射状の線を形成するため、最大の答えは即座に得られます。
