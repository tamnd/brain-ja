 ## 解決策
 ## 問題の理解

 年代順に略称された王の名前のリストが与えられます。 各名前は小文字の文字列です。 私たちはこれらの名前のいくつかを選択して、元の順序を維持しながら王朝を形成するかもしれません。 

有効な王朝は 2 つの条件を満たさなければなりません。 

選択した各名前の最後の文字は、次に選択した名前の最初の文字と一致する必要があります。 これにより連鎖が生まれます。 

また、王朝は全体としてサイクルを形成する必要があります。これは、最初に選ばれた名前の最初の文字が、最後に選ばれた名前の最後の文字と等しくなければならないことを意味します。 

王朝名自体は選択されたすべての文字列を連結したものであるため、目的は選択されたすべての名前の合計の長さを最大化することです。 

重要な点は、文字列の最初と最後の文字だけが互換性にとって重要であるということです。 内部文字はトランジションに影響を与えることはありません。 名前の影響は単純にその長さです。 

制約によってソリューションが完全に形作られます。 最大で$5 \cdot 10^5$文字列なので二次関数は不可能です。 すべてのペア間の遷移を保存するだけでも、すでに大きすぎます。 各文字列の長さは最大 10 であるため、それぞれの名前を個別に処理するのは低コストですが、名前ごとの作業を一定時間に近づける必要があります。 

小文字は 26 個しかないため、アルファベットを使用した動的プログラミング ソリューションが実現可能になります。 開始文字と終了文字に基づく状態を使用するアルゴリズムは、最大でも$26^2 = 676$州、それは小さいです。 

間違ったソリューションを黙って破ってしまう可能性のあるエッジケースがいくつかあります。 

最初と最後の文字がすでに一致している 1 つの文字列を考えてみましょう。```
1
abca
```正解は 4 です。異なる文字列間の遷移のみを検索する不注意な実装では、誤って 0 が返されます。 

文字列をスキップする必要がある場合には、別の微妙なケースが発生します。```
3
abc
ca
cba
```最適な王朝は 1 番目と 3 番目の文字列を使用し、長さ 6 を生成します。次の互換性のある文字列で常にすぐに拡張する貪欲なアプローチは、次の文字列で停止します。`"abc" + "ca"`そしてより良い解決策を見逃してしまうのです。 

3 番目のトラップは、更新中に DP 状態を誤って上書きすることです。```
3
ab
bc
ca
```答えは 6 です。更新が不注意にその場で実行されると、現在の文字列が同じ反復内で複数回再利用され、実質的に不可能なチェーンが発生する可能性があります。 

最後に、有効なサイクルがまったく存在しない可能性があります。```
2
ab
bc
```選択されたサブシーケンスがサイクルを形成しないため、答えは 0 になります。最適なサイクルの代わりに最適なチェーンを返すのは間違いです。 

## アプローチ

 ブルートフォースのアイデアは単純です。 文字列のすべてのサブシーケンスを試し、隣接する文字列が正しく接続されているかどうかを確認し、シーケンス全体がサイクルを形成しているかどうかを確認します。 

これが機能するのは、ルールが隣接する文字列と全体の最初と最後の文字のみに依存するためです。 問題は部分列の数です。 と$n$文字列、あります$2^n$可能な選択。 たとえ$n = 50$、これはもう絶望的で、本当の限界は$5 \cdot 10^5$。 

より合理的なブルート フォースの亜種では、サブセットまたはグラフ パスに対する動的プログラミングが使用されますが、入力サイズが膨大であるため、それでも機能しません。 

問題の構造からは、より強力な観察が得られます。 すべての文字列は、次の 3 つの意味のある情報のみを提供します。 

最初の手紙。 

最後の手紙。 

長さ。 

アルファベットには 26 文字しか含まれていないため、可能な開始と終了のペアの数はごくわずかです。 正確なシーケンスを記憶する代わりに、考えられる開始文字と終了文字のペアごとに最適な合計の長さを記憶するだけで済みます。 

定義する：$dp[i][j]$= 最初の文字列が文字で始まる有効なチェーンの最大合計長$i$現在の最後の文字列が文字で終わるもの$j$。 

新しい文字列を処理するとき$a$に$b$長さのある$w$、次のことができます。 

この文字列のみからなる新しいチェーンを開始します。 

で終わる既存のチェーンをすべて延長します。$a$。 

これが可能なのは、互換性は境界文字の一致のみに依存するためです。 チェーンの完全な履歴は重要ではありません。 

可能な終了文字は 26 個しかないため、各文字列は約 26 回の遷移のみを実行します。 総作業量はおおよそになります$26 \cdot n$、簡単に制限内に収まります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(2^n)$|$O(n)$| 遅すぎる |
 | 最適なDP |$O(26 \cdot n)$|$O(26^2)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 負の無限大に初期化された 26 × 26 DP テーブルを作成します。 

州$dp[i][j]$文字で始まるチェーンの最大合計長を格納します$i$そして現在は手紙で終わっています$j$。 
2. 文字列を入力順に 1 つずつ処理します。 

キングは年代順に登場するため、順序を維持することが必須です。 
3. 現在の文字列については、以下を抽出します。 

- その開始文字$a$- そのエンディングキャラクター$b$- その長さ$w$4. この文字列のみを使用して新しいチェーンを開始します。 

アップデート：$$dp[a][b] = \max(dp[a][b], w)$$これは、単一の王を含む王朝を処理します。 

1. 現在次で終わるすべてのチェーンを拡張してみます。$a$。 

あらゆる可能な開始文字に対して$s$:$$dp[s][b] = \max(dp[s][b], dp[s][a] + w)$$これが機能するのは、現在の文字列が、最後の文字が最初の文字と等しいチェーンを合法的にたどることができるためです。 

1. 同じ反復中に現在の文字列を複数回再利用しないように注意してください。 

これを回避するには、更新する前に古い値をコピーするか、関連する列のスナップショットを使用して繰り返します。 
2. すべての文字列が処理されると、答えは次のようになります。$$\max(dp[c][c])$$26文字すべてにわたって$c$。 

王朝は、全体の最初と最後の文字が一致する場合にのみ有効です。 

### なぜ効果があるのか

 DP 状態は、将来の拡張に必要な情報を正確にキャプチャします。 

文字で始まる最適なチェーンがわかっているとします。$s$そして手紙で終わる$e$。 今後の文字列は、最初の文字が一致するかどうかのみをチェックできます。$e$。 チェーンに関するその他のことは何も重要ではありません。 

から文字列を追加すると、$a$に$b$、で終わるすべての互換性のあるチェーン$a$で終わる新しいチェーンになります$b$、合計の長さは現在の文字列の長さだけ増加します。 

すべての文字列は 1 回処理され、遷移は時系列順にのみ進むため、構築されたすべてのチェーンはキングの有効なサブシーケンスに対応します。 逆に、すべての有効な王朝はこれらの移行を通じて構築できるため、DP は最適な解決策を見逃すことはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = -(10 ** 18)

n = int(input())

dp = [[INF] * 26 for _ in range(26)]

for _ in range(n):
    s = input().strip()

    a = ord(s[0]) - ord('a')
    b = ord(s[-1]) - ord('a')
    w = len(s)

    old = [dp[i][a] for i in range(26)]

    dp[a][b] = max(dp[a][b], w)

    for start in range(26):
        if old[start] != INF:
            dp[start][b] = max(dp[start][b], old[start] + w)

ans = 0

for i in range(26):
    ans = max(ans, dp[i][i])

print(ans)
```DP テーブルには、文字の開始と終了のペアごとに達成可能な最適な合計長が格納されます。 無効な状態は非常に負の数で初期化されるため、正当なチェーンと区別できます。 

各文字列について、最初にその境界文字と長さを抽出します。 文字列はいつでもそれ自体で王朝を形成できるため、更新します`dp[a][b]`直接。 

微妙な部分は、以前のチェーンを安全に延長することです。 同じ文字列が複数回追加される可能性があるため、現在の反復中にすでに更新された値を読み取ることは避けなければなりません。 行:```
old = [dp[i][a] for i in range(26)]
```文字で終わるすべてのチェーンのスナップショットを作成します`a`現在の文字列を処理する前に。 

次に、互換性のある各チェーンが現在の文字列の長さだけ拡張されます。 

最後に、開始文字と終了文字が等しい州のみが有効な王朝を表すため、対角値の最大値を取得します。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    INF = -(10 ** 18)

    n = int(input())

    dp = [[INF] * 26 for _ in range(26)]

    for _ in range(n):
        s = input().strip()

        a = ord(s[0]) - ord('a')
        b = ord(s[-1]) - ord('a')
        w = len(s)

        old = [dp[i][a] for i in range(26)]

        dp[a][b] = max(dp[a][b], w)

        for start in range(26):
            if old[start] != INF:
                dp[start][b] = max(dp[start][b], old[start] + w)

    ans = 0

    for i in range(26):
        ans = max(ans, dp[i][i])

    return str(ans)

# provided sample
assert run("3\nabc\nca\ncba\n") == "6", "sample 1"

# no valid dynasty
assert run("2\nab\nbc\n") == "0", "no cycle"

# single valid string
assert run("1\nc\n") == "1", "single string cycle"

# choose non-adjacent strings
assert run("4\nab\nbc\nca\naa\n") == "6", "best subsequence"

# all equal letters
assert run("3\naa\naa\naa\n") == "6", "all chains compatible"

# off-by-one style chain
assert run("3\nab\nba\nab\n") == "6", "reuse all strings correctly"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1 / c`|`1`| 単弦王朝 |
 |`2 / ab bc`|`0`| サイクルが存在しません |
 |`4 / ab bc ca aa`|`6`| ベストアンサーは文字列をスキップする可能性があります |
 |`3 / aa aa aa`|`6`| 互換性のある状態が繰り返される |
 |`3 / ab ba ab`|`6`| 正しい遷移連鎖 |

 ## 特殊なケース

 単一の文字列がすでにサイクルを形成している場合を考えてみましょう。```
1
abca
```文字列は次で始まり、次で終わります。`a`したがって、処理中に次のように更新します。```

```最終的な対角線の最大値は 4 になりますが、これは正しいです。 以前のチェーンを拡張するだけのアルゴリズムでは、遷移が必要ないため、これを見逃してしまいます。 

ここで、文字列をスキップすることが最適な場合を考えてみましょう。```
3
abc
ca
cba
```加工後`"abc"`:```
dp[a][c] = 3
```処理`"ca"`作成します:```
dp[a][a] = 5
```処理`"cba"`以前のチェーンを直接拡張します。```
dp[a][a] = 6
```各状態は将来の遷移に対して持続するため、アルゴリズムは自然にすべてのサブシーケンスを探索します。 

最後に、危険なインプレース更新のシナリオを考えてみましょう。```
3
ab
bc
ca
```加工時`"bc"`、最初に、で終わるすべてのチェーンのスナップショットを作成します。`b`。 このスナップショットなしで更新すると、`dp[a][c]`同じ反復および再利用における後の遷移に誤って影響を与える可能性があります`"bc"`複数回。

```すべての遷移で、現在の文字列が処理される前に存在していた状態のみが使用されることが保証されます。
