 ## 解決策
 ## 問題の理解

 私たちに与えられた木は、`n`ノード、および 2 人用ゲームの複数ラウンド。 各ラウンドでは、石は 1 つのノードから始まります。 プレイヤーは交互に動き、石を非アクティブな隣に移動し、その隣をアクティブとしてマークします。 動けなくなったプレイヤーが負けとなります。 各ラウンドの後、すべてのノードが非アクティブにリセットされます。 開始ノードごとに、両方が最適にプレイしていると仮定して、最初のプレーヤーであるロンが勝つか、ハーマイオニーが勝つかを判断するように求められます。 

入力は次のように定義されたツリーです。`n-1`エッジ、続いて`t`ラウンドの開始ノード。 出力は`t`それぞれの行は「ロン」または「ハーマイオニー」のいずれかです。 この問題は難しいので、`n`は最大 2×10^5 になる可能性があるため、すべてのラウンドを単純にシミュレートすると遅すぎます。 重要なのは、ツリー構造と最適なプレイ ルールにより、すべてのラウンドに適用される事前計算が可能になるということです。 

明らかではないエッジ ケースには、リーフ ノードから開始する場合、ツリーの重心から開始する場合、および本質的にパスであるツリーが含まれます。 たとえば、木が長さ 3 の直線パスで、石が葉からスタートした場合、最初のプレイヤーが勝ちですが、中央からスタートすると結果が変わる可能性があります。 

## アプローチ

 素朴なアプローチは、各ラウンドを再帰的にシミュレートすることです。つまり、開始ノードからすべての可能な動きを列挙し、ノードをアクティブとしてマークし、現在のプレーヤーが勝利を強制できるかどうかを判断します。 これは原理的には正しいですが、再帰の移動ごとに O(n) 時間が必要になり、全体で O(2^n) 時間がかかる可能性があります。これは実行不可能です。`n`最大 2×10^5。 

最適なアプローチでは、**ツリー上のゲーム値** の構造、特に公平なゲームのための Sprague-Grundy の定理を利用します。 各ノードには、そのノードから始まるゲーム状態を表すグランディ番号を割り当てることができます。 ツリーの場合、ノードのグランディ数は、その子のグランディ数に 1 を加えたものとの XOR になります。 勝者を決定するにはパリティだけを知る必要があるため (ゼロ以外は最初のプレイヤーが勝つことを意味します)、解決策は単純化できます。ルートまたは開始ノードからリーフまでの距離を計算し、パスに沿った移動をカウントします。 開始ノードから葉までの距離の合計が特定の数値の意味で奇数の長さになる場合、最初のプレーヤーが勝ちます。 

より具体的には、勝者は、開始ノードのモジュロ 2 の深さとツリーの構造によって決定できます。開始ノードが、リーフへのすべてのパスに沿ったノードの総数が奇数である位置にある場合、Ron が勝ちます。 そうでなければ、ハーマイオニーが勝ちます。 これにより、開始ノードごとに O(n) の前処理と O(1) のクエリが可能になります。

 | --- | --- | --- | --- |
 | 素朴なシミュレーション | O(n・2^n) | O(n) | 遅すぎる |
 | ツリーゲーム分析 (Grundy) | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 整数の読み取り`n`そして`t`。 
2. 以下からツリーの隣接リストを構築します。`n-1`エッジ。 
3. BFS または DFS を使用して、任意のルートから各ノードの深さを計算します。 ここでの深さは、ルートからそのノードに到達するまでの移動数に対応します。 
4. ルートからツリー全体のパリティ値、つまりすべてのリーフの深さの XOR を計算します。 これでゲーム全体の数字が把握できます。 
5. 各ラウンドで開始ノードを読み取ります。`u_i`。 事前に計算された値を適切に XOR 演算することにより、有効な数値を決定します。 ゼロ以外の場合、Ron が勝ちます。 そうでなければ、ハーマイオニーが勝ちます。 
6. それに応じて「Ron」または「Hermione」を出力します。 

重要な洞察は、各ノードのグランディ数はその下のサブツリーにのみ依存し、ツリー上のゲームは互いに素なサブツリーに沿ったニンバー計算と同等であるということです。 

機能する理由: サブゲームの XOR は、公平なゲームの標準です。 アクティブ化制限により、移動は未訪問のパスにのみ行われることが保証されるため、移動が行われると各サブツリーは独立します。 ルートから深さを計算し、パリティを使用すると、最初のプレーヤーが利用できるオプションが正しく表示されます。 この不変式により、すべての開始位置にわたって正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(1 << 25)

def main():
    n, t = map(int, input().split())
    adj = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        adj[u - 1].append(v - 1)
        adj[v - 1].append(u - 1)

    depth = [0] * n
    def dfs(u, parent):
        for v in adj[u]:
            if v != parent:
                depth[v] = depth[u] + 1
                dfs(v, u)
    dfs(0, -1)

    total_nimber = 0
    for d in depth:
        total_nimber ^= d

    starts = list(map(int, input().split()))
    result = []
    for s in starts:
        s_idx = s - 1
        if (total_nimber ^ depth[s_idx]) != 0:
            result.append("Ron")
        else:
            result.append("Hermione")
    print("\n".join(result))

if __name__ == "__main__":
    main()
```DFS は、ノード 0 を基準としたすべてのノードの深さを計算します。`total_nimber`すべての深さの XOR を表し、ゲーム全体の数をキャプチャします。 開始ノードごとに、ノードの深さによって番号を調整します。 ゼロ以外の場合、最初のプレイヤーが強制的に勝利を収めることができます。 リーフから開始する、またはルートから開始するなどのエッジケースは自然に処理されます。

 ## 特殊なケース

 木が直線の道で、石が端から始まる場合、最初のプレイヤーはいつでも道に沿って移動して勝利を強制することができます。 中央から開始すると、ツリーが 2 つのパスに分割され、最初のプレイヤーの動きは各パスの番号の XOR によって決定されます。 DFS は両方のシナリオの深さを正確に計算し、正確なファースト プレーヤーの勝利検出を保証します。 ツリーがスターの場合、葉の位置を交換することはできないため、中心または葉から開始すると、アルゴリズムによって計算されたものと同じ出力が自動的に生成されます。
