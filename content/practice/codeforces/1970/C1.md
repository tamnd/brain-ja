 ## 解決策
 ## 問題の理解

 私たちに与えられた構造は、通常の意味での任意のツリーではなく、非常に限定されたものです。つまり、葉がちょうど 2 枚あります。 これは、おそらく一部の内部ノードを除いて、すべてのノードの次数が最大 2 であり、グラフ全体が本質的に単一のチェーンであることを意味します。 言い換えれば、ツリーは、エンドポイントを除き、各ノードが最大 2 つの隣接ノード (左に 1 つ、右に 1 つ) を持つ配列のように動作します。 

石は選択したノードから始まります。 プレイヤーは交互に、以前にアクティブ化されていない隣接するノードに石を移動します。 石が移動するたびに、新しいノードは将来の再訪問に対して非アクティブになるため、パスは常に単純になり、ノードを再訪問することはありません。 プレーヤーは、正当な手を持っていない場合に負けます。これは、石がチェーンの残りの未訪問部分の葉に座っているときに起こります。 

単一の開始位置について、最初のプレーヤーであるロンが最適なプレイの下で強制的に勝利するかどうかを判断するように求められます。 

制約はノード数としては最大 200,000 と大きくなりますが、存在するクエリは 1 つだけです。 これにより、分岐したり動きを明示的に探索しようとした開始位置ごとのゲームプレイのシミュレーションが即座に除外されます。 クエリごとの線形シミュレーションでも問題ありませんが、グラフ構造が折れて線になるため、考えられるパスやゲーム状態の数が指数関数的に増加するものは不要です。 

微妙なエッジ ケースは、開始ノード自体が元のツリーの葉である場合です。 その場合、考えられる手は 1 つだけであり、ゲームは内側への強制的なパスになります。 もう 1 つのエッジ ケースは、開始ノードが長いチェーンの中央にある場合です。この場合、選択は事実上左または右のみですが、構造的には両方向が対称です。 

## アプローチ

 ゲームについて考える強引な方法は、考えられるすべてのプレイ シーケンスをシミュレートすることです。 開始ノードから、まだ訪問していない隣接ノードに分岐し、移動がなくなるまで交互にターンします。 現在のノードと訪問したノードのセットによって定義された状態に対する DFS によって勝者を計算できます。 

問題は、状態空間が指数関数的に増大することです。 グラフはパスですが、可能なシーケンスの数は、境界に達するまでパスを左右に拡張するすべての方法に対応します。 最悪の場合、状態の数はパスに沿ったノードのサブセットに比例し、n で指数関数的になります。 

重要な簡素化は、開始ノードを修正すると、ゲームが 2 つの独立した直線方向 (チェーンに沿った左と右) に分割されることを認識することから来ています。 各移動は単純に 1 つのノードを消費することで一方の面を減らします。 方向選択以外の分岐構造はなく、初手以降は完全に構造が決定されます。 

したがって、ゲーム全体は、開始ノードの左側で利用可能なノードの数と右側で利用可能なノードの数という 2 つの山で構成される古典的なテイクアウェイ ゲームに縮小されます。 それぞれの移動により、どちらかのパイルからノードが 1 つだけ削除されます。 プレイヤーは交互に参加し、最後の手で勝者が決まります。 これはパリティの問題になります。最適なプレイではパリティの結果を変える分岐選択肢がないため、利用可能な手の総数によって勝者が決まります。 

勝者は、開始ノードからの利用可能な手の合計数が偶数か奇数かによって決まります。

 ## アルゴリズムのチュートリアル

1. まず、ツリーを暗黙的な線形順序に変換します。 木にはちょうど 2 枚の葉があるので、それを道として扱うことができます。 1 つの端点を見つけ、隣接する端点を通過して、ラインに沿った位置を割り当てます。 
2. このパスに沿ったすべてのノードの位置インデックスを記録します。 これにより、ノード ラベルからチェーンに沿った距離までのマッピングが得られます。 
3. 開始ノードについて、この線形順序付けでその左側にいくつのノードがあり、右側にいくつのノードがあるかを計算します。 
4. 各移動はパスに沿って新しいノードを訪問するため、ゲームで利用可能な移動の合計数は、開始ノードを除いたノードの数とまったく同じになります。 
5. プレーヤーは交互に移動し、各移動は残りのノードを 1 つだけ消費するため、結果はこの合計数が奇数か偶数かによってのみ決まります。 
6. 利用可能な手の合計数が奇数の場合、ロン (最初のプレイヤー) が最後の手を行い、勝ちます。 そうでなければハーマイオニーの勝ちです。 

なぜ効果があるのか

 グラフは単一のパスであるため、すべての合法的なプレイは、開始ノードから外側に単純なセグメントを拡張することに対応します。 到達可能性を変更する分岐はなく、方向の選択のみが変更されます。 一度方向を選択すると、その方向が使い果たされるまで完全に決定され、残りの動きが強制されます。 これにより、ゲームは固定長の一連の動きに縮小されるため、最適なプレイによって合計の動きの数が変更されることはなく、誰が最後の動きを消費するかのみが変更されます。 したがって、勝者は完全に残りのパス長のパリティによって決まります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, t = map(int, input().split())

adj = [[] for _ in range(n + 1)]
for _ in range(n - 1):
    u, v = map(int, input().split())
    adj[u].append(v)
    adj[v].append(u)

start = int(input().strip())

# find one endpoint of the path
end = 1
for i in range(1, n + 1):
    if len(adj[i]) == 1:
        end = i
        break

# build ordering along the path
order = []
prev = 0
cur = end

while True:
    order.append(cur)
    nxt = -1
    for nei in adj[cur]:
        if nei != prev:
            nxt = nei
            break
    if nxt == -1:
        break
    prev, cur = cur, nxt

pos = {node: i for i, node in enumerate(order)}

idx = pos[start]

left = idx
right = n - 1 - idx

moves = left + right

if moves % 2 == 1:
    print("Ron")
else:
    print("Hermione")
```この解決策は、最初に、リーフからもう一方のエンドポイントに到達するまで歩くことによって、ツリーの暗黙的な配列順序を再構築します。 この順序付けが完了すると、各ノードに位置インデックスが割り当てられます。 開始ノードのインデックスにより、パスが左右のセグメントに分割されます。 

重要な実装の詳細は、ゲームプレイをまったくシミュレートしないことです。 消費されるノードの数のみを計算します。これは常に n-1 です。 これにより、ロジックがパリティ チェックまで単純化されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, t = map(int, input().split())
    adj = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        adj[u].append(v)
        adj[v].append(u)

    start = int(input().strip())

    end = 1
    for i in range(1, n + 1):
        if len(adj[i]) == 1:
            end = i
            break

    order = []
    prev = 0
    cur = end
    while True:
        order.append(cur)
        nxt = -1
        for nei in adj[cur]:
            if nei != prev:
                nxt = nei
                break
        if nxt == -1:
            break
        prev, cur = cur, nxt

    pos = {node: i for i, node in enumerate(order)}
    idx = pos[start]
    moves = idx + (n - 1 - idx)

    return "Ron\n" if moves % 2 == 1 else "Hermione\n"

 ## 特殊なケース

 重要なエッジケースは、開始ノードがすでにチェーンのエンドポイントである場合です。 例えば：```
3 1
1 2
2 3
1
```トラバースによりパス [1, 2, 3] が得られます。 1 から開始すると、一方向のみが使用可能になります。 勝負はちょうど２手で右への強歩となる。 カウントは偶数であるため、パリティだけを考慮すると後手のプレイヤーが勝ちますが、実際のプレイでは、最初の手が方向を決定し、残りの選択肢が削除されます。 代替分岐がないため、線形縮小は依然として維持されます。 

もう 1 つのケースは、開始点が奇数長のチェーンのちょうど中央にある場合です。 両側の大きさは対称ですが、ロンが方向を選択すると、ハーマイオニーは同じ線に沿って応答することを余儀なくされます。 方向がコミットされると、移動の選択肢が再び導入されることはないため、結果は対称性ではなく、残りのノードの合計にのみ依存します。 

これらのケースは、モデルが空間的直感に依存せず、純粋にパスの固定長の性質に依存していることを確認します。
