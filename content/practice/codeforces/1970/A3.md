 ## 解決策
 ## 問題の理解

 単一の有効な括弧シーケンスが与えられます。これは、同数の開き括弧と閉じ括弧が含まれており、どのプレフィックスでも残高がゼロを下回ることがないことを意味します。 この文字列から、最初は「バランス シャッフル」と呼ばれる操作が適用されました。文字列内のすべての位置には、その文字の直前にプレフィックスのバランスが注釈として付けられ、その後、バランスを増やすことによってすべての位置が並べ替えられ、最初に大きなインデックスを取得することによって関係が解消されました。 そのソートされた順序で文字を読み取ると、新しい有効な括弧シーケンスが生成されます。 

タスクは、このプロセスを逆にすることです。 オリジナルのシーケンスを取得してそのシャッフルされたバージョンを生成する代わりに、シャッフルされた結果が与えられ、それを生成する固有のオリジナルのシーケンスを再構築する必要があります。 

重要な問題は、シャッフルでは明示的な位置構造が破棄され、プレフィックスのバランスによって引き起こされるグローバルな順序のみが保存されることです。 これを逆にするには、これらの制約と一致する順列を再構築する必要があります。 

入力サイズは 500,000 文字に達する可能性があるため、すべての順列を試行したり、再挿入をシミュレートしたりするなど、二次再構成戦略は直ちに除外されます。 どのソリューションも線形または線形に近いものである必要があり、並べ替えや優先順位の構造により、最悪でも O(n log n) になる可能性があります。 

微妙な点は、シャッフルが指定されたシーケンスではなく、元のシーケンスのプレフィックス バランスに依存することです。 したがって、入力文字列からこれらの残高を直接計算することはできません。 代わりに、バランスのとれた括弧シーケンスの構造特性から間接的にそれらを推測する必要があります。 

多くのポジションが同じプレフィックスバランスを共有する場合、エッジケースが発生します。 このような場合、タイブレーク ルールが重要です。つまり、ポジションは元のインデックスの降順に並べられます。 この 2 次順序を無視した単純な再構成では、バランスのグループ化が正しい場合でも、不正確なマッピングが生成されます。 

## アプローチ

 直接的なブルートフォース解釈では、出力内のどの文字が入力内のどの位置に対応するかを推測することによって、元のシーケンスを再構築しようとします。 すべての有効なバランスの取れたシーケンスをシミュレートし、シャッフルを適用し、指定された文字列に一致するものをチェックすることを想像することもできます。 シャッフルは全単射であるため、これは理論的には正しいですが、長さ n の平衡括弧シーケンスの数は、カタロニア数 (n で指数関数的) に応じて増加します。 n = 40 の場合でもこれは実行不可能になり、n = 500000 の場合は完全に不可能になります。 

重要な洞察は、シャッフルを文字列の変換としてではなく、元のシーケンスによって生成されたイベントの並べ替えとして再解釈することです。 各位置は、そのプレフィックス バランスとそのインデックスで構成されるペアに寄与し、シャッフルされたシーケンスは、(バランスの昇順、インデックスの降順) によって辞書順に並べ替えられたこれらのペアにすぎません。 

プロセスを逆にするということは、これらのペアの元のシーケンスを再構築する必要があることを意味します。 重要な観察は、元の残高を直接知ることはできないが、有効な括弧シーケンスの構造は知っているということです。すべての「(」は残高を増加させ、すべての「)」は残高を減少させ、残高の合計パスが Dyck パスを形成します。 

シャッフルは、元の Dyck パスのプレフィックスの高さを増やすことによって位置を順序付けします。 これは、パスのノードを最低の高さから最高の高さに、各レベル内で右から左に処理することに相当します。 この構造は、Dyck パスのツリー状の分解に対応し、各開き括弧がサブツリー間隔を定義します。

したがって、反転は、「レベル順序訪問」のマルチセットが指定されたシーケンスと一致する Dyck パスを再構築することになります。 アクティブなセグメントのスタックを使用して、これを貪欲に行うことができます。 シャッフルされたシーケンス内の各文字は、元の文字内でその文字の前に何個の開き括弧が存在する必要があるかを示します。これにより、文字の配置が一意に制約されます。 

これを確認するより具体的な方法は、(深さ, -インデックス) によってソートされた位置を再構成することですが、代わりに、元のシーケンス内の使用可能なスロットに対する優先構造を維持しながら、シャッフルされたシーケンスを左から右に消費するときに、一致しないオープンがいくつ存在する必要があるかをシミュレートすることによって深さを推測します。 

これにより、標準的な構造が得られます。実行可能性のバランスの制約を維持しながら、元のインデックスをキーとする優先キューを使用して、逆の並べ替え順序をシミュレートすることによって、各文字がどこに移動する必要があるかを事前に計算します。

 ## アルゴリズムのチュートリアル

 1. 指定されたシャッフルされた文字列のプレフィックスバランスを計算します。 これにより、シャッフルされた表現の深度プロファイルが得られ、元のレベルによるグループ化が間接的にエンコードされます。 
2. すべての位置について、計算された深さとそのインデックスを組み合わせます。 これらのペアは、シャッフル定義から継承された制約を表しており、深さの低い要素はソートされた元の順序で前に出現する必要があります。 
3. 深さを増やし、同じ深さ内ではインデックスを増やしてすべての位置を並べ替えます。 これにより、元のタイブレーク ルール (減少するインデックスを使用) が逆転し、元の訪問順序が効果的に再構築されます。 
4. 元のシーケンスが有効な Dyck パスでなければならないという事実を利用して、この再構築された順序の位置に文字を割り当てます。 残りのサフィックスのバランスを維持しながら、可能な限り「(」を配置します。
 5. 必要な左括弧の数のカウンターを維持します。 各位置で、「(」を配置することがバランスの取れたシーケンスを完成させる能力に違反するかどうかを決定します。違反する場合は、「)」を配置します。 
6. これらの決定に基づいて結果の文字列を構築します。 このシーケンスは復元されたオリジナルです。 

重要な制約は、シーケンスを完了する実現可能性を常に保証することです。 どのプレフィックスでも、「)」を配置しすぎると有効性が損なわれる危険性があるため、貪欲ルールでは「(」の残りの容量が考慮されます。

 ### なぜ効果があるのか

 シャッフルでは、元のシーケンスのプレフィックスの高さによって位置が順序付けされます。これは、ルート付きツリー表現の深さによって Dyck パスのノードを順序付けするのと同じです。 各深さレベルは元のシーケンスで連続した構造を形成し、インデックスを減少させることによる二次的な順序付けにより、各レベル内で一貫した右から左へのトラバースが保証されます。 

この順序を逆にすると、Dyck パスの元の走査順序が回復されます。 この順序が再構築されると、シーケンスが有効なバランスの取れたパスを維持するという要件により、括弧の割り当てが強制されます。 すべてのステップで、完全なシーケンスを完了する機能を維持する有効な選択肢が 1 つだけあり、これにより一意性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)

    # prefix balance of shuffled string
    bal = 0
    depth = []
    for c in s:
        depth.append(bal)
        if c == '(':
            bal += 1
        else:
            bal -= 1

    # reconstruct original order: sort by (depth asc, index asc)
    order = list(range(n))
    order.sort(key=lambda i: (depth[i], i))

    # build result
    res = [''] * n
    open_left = n // 2  # number of '(' needed

    # we decide greedily but respecting balance feasibility
    balance = 0
    for i in order:
        # try to place '(' if possible
        if open_left > 0 and balance + 1 <= n - (i + 1) - (open_left - 1):
            res[i] = '('
            balance += 1
            open_left -= 1
        else:
            res[i] = ')'
            balance -= 1

    print(''.join(res))

if __name__ == "__main__":
    solve()
```コードはまず、指定されたシャッフルされた文字列のプレフィックスのバランスを計算します。 これらの値は元のバランスではありませんが、シャッフルでキャラクターをグループ化する方法を定義するレベル指標として機能します。 

ソートのステップでは、シャッフルの順序付けルールの逆を再構築します。 増加する深さと増加するインデックスを使用すると、元の構造順序が復元されます。これは、シャッフルが増加する深さと減少するインデックスによってソートされていたためです。 

貪欲な再構築により、Dyck パスの有効性が強制されます。 変数`open_left`使用可能な左括弧がいくつ残っているかを追跡します。 ループ内の条件により、「(」を配置しても後でシーケンスを完了できなくなることがなくなります。これは、固定数の開きでバランスの取れた括弧を構築するための標準的な実行可能性チェックです。

 ## 特殊なケース

 エッジ ケースの 1 つは、シャッフルされた文字列内のすべての文字が非常に低いプレフィックス バランスに対応する場合です。 このような場合、ソートではほぼすべてのインデックスが深さ 0 でグループ化され、インデックスによるタイブレークによってすべてが決定されます。 貪欲な実現可能性チェックにより、必要な場所に開始括弧を早期に配置することが強制されるため、再構築は引き続き機能します。 

もう 1 つのエッジ ケースは、次のような完全にネストされたシーケンスです。`(((())))`、深さは厳密に増加してから減少します。 ソートにより非常に構造化された順序が生成され、再構築は分岐のない決定論的になります。 実現可能条件により、十分な開始ブラケットが配置されるまで閉じ括弧が延期されることが保証されます。 

最後のエッジケースは、次のような交互構造です。`()()()()`、深さが大きく振動する場所。 ここでは、多くの位置が同じ深さを共有し、インデックスの順序付けが主な構造になります。 局所的な構造ではなく実現可能性によってブラケットの正しいペアリングが強制されるため、アルゴリズムは引き続き正しく再構築されます。
