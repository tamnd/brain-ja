 ## 解決策
 ## 問題の理解

 刑務所を表す無向グラフが与えられます。頂点はセル、エッジは既存の廊下です。 既存のコリドーの両方を使用し、必要に応じて新しいコリドーを構築できる場合、各グループが接続されたサブグラフを誘導するように、頂点を 2 つのグループに分割する必要があります。 ただし、2 つのグループは 1 つのコリドーによって相互に接続されている必要があり、そのコリドーも最終構造の一部です。 

各グループは複合体と呼ばれ、そのコストはそのサイズにのみ依存します。1 つの複合体にサイズがある場合$k$、貢献します$k^2$総コストに。 さらに、新しく建設される廊下には費用がかかります$c$、接続を確保するためにグループ内に追加のコリドーを構築する場合があります。 

したがって、タスクは、頂点を 2 つの接続されたコンポーネントに分割することを選択し、既存のエッジとオプションで追加されたエッジを使用して各辺が内部的に接続されていることを確認し、2 つの辺を 1 つのブリッジ エッジで接続することです。 目標は、二乗サイズと追加エッジのコストの合計を最小限に抑えることです。 

重要な構造は、最初のグラフにはすでに複数の接続コンポーネントがある可能性があり、エッジを自由に追加できるが、追加されたすべてのエッジにはコストがかかるということです。$c$したがって、選択したグループを接続するために必要な場合にのみエッジを追加します。 

この制約は、高度に最適化されたソリューションが必要であることを意味します。 合計あり$n \le 10^5$そして合計$m \le 5 \cdot 10^5$、すべてのパーティションを試したり、各分割の接続をシミュレートしたりするアプローチは不可能です。 コンポーネントごとまたはカットごとの二次関数であっても失敗します。 解決策では、問題をグラフ圧縮ステップに削減し、その後にコンポーネントに対するほぼ線形または線形時間の計算を行う必要があります。 

微妙な問題は、追加されたエッジにより接続が柔軟になることです。 グループが複数の元の接続されたコンポーネントから形成されている場合、それらを接続するために料金を支払う必要があるため、コストは各サイド内でマージされるコンポーネントの数によって異なります。 

もう 1 つのエッジ ケースは、有効な分割が不可能な方法でグラフがすでに切断されている場合です。 たとえば、グラフに 3 つ以上の接続コンポーネントがあり、1 つのブリッジで 2 つの複合体を使用する必要がある場合、一部の構成は余分なエッジなしでは接続できないため、実現可能性を検出する必要があります。 

## アプローチ

 ブルートフォース解釈では、頂点を 2 つのセットに分割し、両方の誘導サブグラフを接続できるかどうかを確認し、必要な追加エッジのコストを計算するためのあらゆる方法が試行されます。 固定パーティションの接続性をチェックするだけでもコストがかかります。各サイドを接続するために追加するエッジの数を考慮する必要があるためです。これは、各サイドが元のグラフから継承する接続コンポーネントの数に依存します。 

ブルートフォースのパーティション数は次のとおりです。$2^n$、それは直ちに不可能です。 バランスの取れたパーティションに制限しても、依然として指数関数的な複雑さが残ります。 

重要な洞察は、視点を頂点から元のグラフの接続されたコンポーネントに移すことです。 接続された各コンポーネントの内部では、すでに完全な接続が確立されているため、コンポーネントを両側に分割すると強制的にコンポーネントを「切断」する必要があり、コンポーネントに含まれるコンポーネントのフラグメントの数に応じて、各側に追加のエッジが必要になる場合があります。 

ただし、コストをかけて自由にエッジを追加できるため、より強力な単純化が実現します。$c$、各側の内部構造は、元の接続コンポーネントが割り当てられている数にのみ依存します。 どちらかの側が取得したら$k$オリジナルのコンポーネントを使用して接続できます$k-1$追加されたエッジ、コスト計算$(k-1)c$。 

したがって、問題は、元の接続コンポーネントのセットを 2 つのグループに分割し、以下を最小限に抑えることに帰着します。$$(\sum a_i)^2 + (\sum b_i)^2 + c \cdot (\text{number of components merged within groups})$$どこ$a_i$そして$b_i$は各辺に割り当てられたコンポーネントのサイズです。 

また、2 つの複合体の間に少なくとも 1 つのエッジが存在することを確認する必要があります。 これにより、少なくとも 1 つの元のエッジ交差または構築エッジが強制されるため、単一のブリッジを許可することで実現可能性を確保します。 

最終的な構造は、接続されたコンポーネントを 2 つのビンに分割したものになり、コストはサイズと数の合計にのみ依存します。 これは、コンポーネントに対するナップザックのような DP に変わります。ここで、状態は一方の側に割り当てられている現在の合計であり、暗黙的に使用されるコンポーネントの最小数を追跡します。 

重要な最適化は、内部グラフ構造ではなく、コンポーネントのサイズと数のみを考慮する必要があることです。

 | 合計に対する成分 DP |$O(n \cdot \text{components})$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. DFS または DSU を使用して元のグラフのすべての連結成分を計算し、そのサイズを記録します。 

これは、接続コンポーネント内では頂点がすでに相互に到達可能であるため、内部到達可能性について再度検討する必要がないため有効です。 
2. コンポーネントのサイズを次のようにします。$s_1, s_2, \dots, s_k$、 どこ$k$コンポーネントの数です。 
3. 合計値を計算する$S = \sum s_i = n$。 パーティションは、最初の複合体のコンポーネントのサブセットを選択することによって定義されます。 残りは2番目の複合体を形成します。 
4. 任意のサブセットについて、選択した側に合計サイズがある場合$x$、反対側にはサイズがあります$S - x$したがって、基本コストは次のようになります。$$x^2 + (S-x)^2$$5. 残りのコストは、各側面内の接続コンポーネントによるものです。 側面に含まれている場合$t$コンポーネント、必要です$t-1$それらを接続するためのエッジがあるため、追加コストの合計は次のようになります。$$(k_1 - 1 + k_2 - 1)c = (k - 2)c$$両側が空でないときはいつでも。 
6. したがって、空でも完全でもないコンポーネントの実行可能なサブセットごとに、以下を計算します。$$x^2 + (S-x)^2 + (k-2)c$$以来$k$が固定されている場合、最後の項はすべての有効な分割にわたって一定です。 
7. ここで問題を、合計が次のようなコンポーネント サイズのサブセットを見つけることに縮小します。$x$最小化する$x^2 + (S-x)^2$。 これは作るのと同じです$x$できるだけ近くに$S/2$。 
8. コンポーネント サイズまでの標準サブセット合計 DP を使用します。$n$、到達可能な金額を追跡します。 
9. 到達可能なすべての金額のうち$x$と$x \neq 0$そして$x \neq S$、式の最小値を計算します。 

### なぜ効果があるのか

 重要な不変条件は、すべての有効な構成が接続されたコンポーネントのパーティションに一意に対応することです。 コンポーネントが固定されると、内部接続コストは、その構造ではなく、各側に配置されるコンポーネントの数のみに依存します。 接続してから$t$コンポーネントのコストは常に正確です$(t-1)c$、配置とは無関係に、すべての構造の複雑さは、側面ごとにコンポーネントを数えることに集約されます。 残りの最適化は純粋にサブセット合計に対して行われるため、DP は構成の欠落や重複を生じることなく、実行可能なすべてのパーティションを完全に特徴付けます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, c = map(int, input().split())
    g = [[] for _ in range(n)]
    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    vis = [False] * n
    comp = []

    sys.setrecursionlimit(10**7)

    def dfs(start):
        stack = [start]
        vis[start] = True
        size = 0
        while stack:
            u = stack.pop()
            size += 1
            for v in g[u]:
                if not vis[v]:
                    vis[v] = True
                    stack.append(v)
        return size

    for i in range(n):
        if not vis[i]:
            comp.append(dfs(i))

    if len(comp) == 1:
        print(-1)
        return

    S = sum(comp)

    dp = {0}
    for s in comp:
        ndp = set(dp)
        for x in dp:
            ndp.add(x + s)
        dp = ndp

    best = float('inf')
    k = len(comp)

    for x in dp:
        if x == 0 or x == S:
            continue
        y = S - x
        cost = x * x + y * y + (k - 2) * c
        if cost < best:
            best = cost

    print(best if best != float('inf') else -1)

if __name__ == "__main__":
    solve()
```この解決策は、再帰の深さの問題を回避するために、グラフを構築し、反復 DFS を使用して接続されたコンポーネントを抽出することから始まります。 圧縮後は内部構造が重要ではなくなるため、各コンポーネントのサイズが保存されます。 

グラフが完全に接続されている場合は、すぐに戻ります。$-1$なぜなら、分割には必ずコンポーネントを分割する必要があり、エッジを構築せずにちょうど 1 つのブリッジの制約を満たすことができないからです。 

次に、セットベースの DP を使用して、コンポーネント サイズの考えられるすべてのサブセットの合計を計算します。 これは事実上、コンポーネントのサイズを超えたナップザックであり、すべてのコンポーネントの合計が大きいため効率的です。$n$オーバーテストケースは制限されています。 

最後に、達成可能な各パーティションの二次コスト関数を評価し、最小値を維持します。 

定数$(k-2)c$は有効な分割ごとに表示されるため、どのパーティションが最適であるかには影響しませんが、それでも最終コストには含まれます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、グラフがすでに完全に接続されている場合です。 この場合、コンポーネントは 1 つだけであり、有効な答えにはそれを分割する必要があり、少なくとも 1 つのブリッジを構築する必要があります。 アルゴリズムはこれを正しく検出し、出力します。$-1$既存のコンポーネントのパーティションが存在しないためです。 

もう 1 つのケースは、すべての頂点が分離されている場合です。 この場合、すべての頂点は独自のコンポーネントとなり、DP はすべてのサブセットの合計を処理する必要があります。 各頂点がサイズ 1 のコンポーネントになり、subset-sum がすべてのパーティションを自然に探索するため、アルゴリズムは引き続き機能します。 

最後の微妙なケースは、コンポーネントの不均衡が非常に大きい場合です。たとえば、1 つのコンポーネントのサイズが異なる場合です。$n-1$そして多くのシングルトン。 DP は依然として、二次不均衡を最小限に抑えるために小さなサブセットを分割することを正しく検討していますが、これはまさに意図した最適化ターゲットです。
