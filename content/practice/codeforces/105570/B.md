 ## 解決策
 ## 問題の理解

 一連の整数を構築しています$a_1, a_2, \dots, a_n$。 それぞれの値$a_i$個人的な範囲内に留まらなければなりません$[1, b_i]$。 さらに、隣接する値は結合されます。連続する要素は、指定された制限を超えて異なることができないため、$a_i$そして$a_{i+1}$満たさなければなりません$|a_i - a_{i+1}| \le d_i$。 

さらに、配列は直接読み取られません。 代わりに、順列が与えられます。$p$そして符号配列$x$それぞれどこで$x_i$どちらかです$+1$または$-1$。 構築された配列から$a$、要素を取得することによって、ギフトと呼ばれる派生シーケンスが形成されます$a_{p_i}$そしてそれを乗算すると$x_i$。 したがって、位置の値は$i$ギフトには次のいずれかが含まれます$a_{p_i}$または$-a_{p_i}$。 

目標は、有効なものを選択することです$a$そのため、この派生 Gift 配列は辞書編集的に最小限になります。 

制約は大きく、$n$まで$3 \cdot 10^5$。 値を検索したり、位置ごとに独立して選択肢をシミュレートしようとするソリューションは、すぐに遅すぎます。 構造は制約のパスであるため、慎重に伝播すると線形または線形に近いものが期待されます。 

微妙な難点は、それぞれ$a_i$は、それ自体の境界と隣接する境界の両方によって制約されるため、1 つの位置を局所的に最小化すると、他の場所での実現可能性が無効になる可能性があります。 もう 1 つの問題は、辞書編集上の順序が索引の順序と一致していないことです。$a$ただし、順序が変更されています$p$、したがって、決定は自然なインデックス順序ではなくギフト順序に従う必要があります。 

単純な貪欲な人の失敗の小さな例: それぞれを選択した場合$a_i$できるだけ小さく独立して行うと、後で近隣制約に違反する可能性があります。 逆に、ローカルで常に制約を満たしながら辞書編集上の優先順位を無視すると、前のギフト エントリを改善するために後の位置を犠牲にする、グローバルでより適切な割り当てを見逃してしまう可能性があります。 

## アプローチ

 問題についての素朴な考え方は、それぞれを扱うことです$a_i$独立して調整し、制約を満たすように調整します。 ギフトの位置の順序で、各位置に対して貪欲に値を割り当てようとする場合があります。$i$、 選ぶ$a_{p_i}$できるだけ小さい場合$x_i = 1$、または可能な限り大きい$x_i = -1$、敬意を払いながら$[1, b_i]$。 それぞれの任務の後、人は満足させるために隣人を修復しようとするだろう$|a_i - a_{i+1}| \le d_i$。 問題は、修復がチェーン全体に連鎖的に発生する可能性があることです。 最悪の場合、1 つの割り当てがすべての割り当てに伝播する可能性があります。$n$位置を指定し、これを繰り返します$n$ステップは二次関数の動作につながります。 

重要な観察は、制約が単純なパスを形成するため、左右に伝播する一貫した値の範囲を維持することで実現可能性が完全に得られるということです。 各割り当てにはグローバルな再計算は必要ありません。 ローカルな間隔の締め付けとチェーンに沿った伝播のみが必要です。 

ポジションごとに整備$i$実行可能な間隔$[L_i, R_i]$これまでに処理されたすべての制約を考慮して、引き続き可能性のある値。 隣接制約は区間交差に変換されます。$a_i$範囲内にある場合、$a_{i+1}$はその範囲のシフトされたバージョン内にある必要があり、その逆も同様です。 更新のたびに間隔が狭まるだけなので、伝播を繰り返すとすぐに収束します。 

一定期間にわたって実現可能性が維持されると、辞書編集上の最小化は制御されたプロセスになります。ギフトの位置は次の順序で処理されます。$i = 1 \dots n$、それぞれをインデックスにマッピングします$p_i$、そして力$a_{p_i}$に応じて可能な限り最高の値に$x_i$。 値を修正した後、一貫性を保つために制約を再度伝播します。 

これにより、問題は、境界が単調に収束するため、実際には線形である、線上で繰り返される間隔の縮小に帰着します。

 ## アルゴリズムのチュートリアル

 2 つの配列を維持します$L_i$そして$R_i$、最初は次のように設定されています$[1, b_i]$。 これらは、次のすべての値を表します。$a_i$これまでに発見された制約に違反することなく、引き続き取得できます。 

また、双方向の間隔への影響として隣接関係の制約も維持します。$a_i$固定または制限されている、制限されている$a_{i+1}$、その逆も同様です。 

### ステップ

 1. 毎回初期化する$L_i = 1$、$R_i = b_i$。 これは、隣接性を考慮する前に、ノードごとの制約のみをエンコードします。 
2. 安定するまでチェーン上に隣接制約を 1 回伝播します。 各エッジについて$(i, i+1)$、それを強制します$a_{i+1} \in [L_i - d_i, R_i + d_i]$そして同様に$a_i \in [L_{i+1} - d_i, R_{i+1} + d_i]$、既存の間隔と交差します。 これにより、制約のないシステムのグローバルな実現可能性が確立されます。 
3. ギフト注文のポジションを処理します$i = 1$に$n$。 させて$j = p_i$の実際のインデックスになります$a$。 
4. もし$x_i = 1$、私たちは作ろうとしています$a_j$できるだけ小さいものを選択します$a_j = L_j$。 もし$x_i = -1$、私たちは作ろうとしています$a_j$できるだけ大きいものを選択します$a_j = R_j$。 これにより、現在のギフト エントリが直接最小化されます。$x_i \cdot a_j$極限化することで最小化される$a_j$正しい方向に。 
5.修正$a_j$設定により$L_j = R_j = a_j$。 これにより、柔軟な変数が決定された変数に変換されます。 
6. この固定観念を近隣住民に伝えます。 各エッジについて$(i, i+1)$、 アップデート：$$L_{i+1} = \max(L_{i+1}, L_i - d_i), \quad R_{i+1} = \min(R_{i+1}, R_i + d_i)$$逆方向にも対称に。 隙間が空いてしまうと施工が不可能になってしまいます。 
7. 間隔が変化しなくなるまで伝播を繰り返します。 

### なぜ効果があるのか

 すべてのステップで、維持される間隔は、すでに固定された決定の下で完全に有効な構成に拡張できる一連の値を正確に表します。 直すときは$a_j$その間隔と一致する極値に設定すると、グローバルに実行可能なすべての完了の中から現在のギフトの位置に可能な限り最良の値が選択されます。 伝播により、将来の選択が過去の決定と矛盾することがなくなります。 拡張できなくなった値のみが削除されます。 間隔は常に単調に縮小するため、以前の決定を再検討することはなく、実現可能性は全体を通して維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    b = list(map(int, input().split()))
    d = list(map(int, input().split()))
    p = list(map(int, input().split()))
    x = list(map(int, input().split()))

    L = [1] * n
    R = b[:]

    # initial propagation (two passes is enough on a line in practice)
    changed = True
    while changed:
        changed = False
        for i in range(n - 1):
            # i -> i+1
            nl = max(L[i+1], L[i] - d[i])
            nr = min(R[i+1], R[i] + d[i])
            if nl != L[i+1] or nr != R[i+1]:
                L[i+1], R[i+1] = nl, nr
                changed = True

            # i+1 -> i
            nl = max(L[i], L[i+1] - d[i])
            nr = min(R[i], R[i+1] + d[i])
            if nl != L[i] or nr != R[i]:
                L[i], R[i] = nl, nr
                changed = True

    # process Gift order
    for i in range(n):
        j = p[i] - 1
        if x[i] == 1:
            val = L[j]
        else:
            val = R[j]

        L[j] = R[j] = val

        # local propagation after fixing
        changed = True
        while changed:
            changed = False
            for k in range(n - 1):
                nl = max(L[k+1], L[k] - d[k])
                nr = min(R[k+1], R[k] + d[k])
                if nl != L[k+1] or nr != R[k+1]:
                    L[k+1], R[k+1] = nl, nr
                    changed = True

                nl = max(L[k], L[k+1] - d[k])
                nr = min(R[k], R[k+1] + d[k])
                if nl != L[k] or nr != R[k]:
                    L[k], R[k] = nl, nr
                    changed = True

    print(*L)

if __name__ == "__main__":
    solve()
```実装では、問題を 2 つのフェーズに分けます。まず、グローバルな実現可能範囲を確立し、次にギフトの優先順位に従って値を段階的に修正します。 伝播ループは、すべての割り当てが隣接関係制約との互換性を維持することを保証する中心的なメカニズムです。 

微妙な点は、値を固定した後、アルゴリズムが同じ間隔引き締めロジックを再利用することです。 これが必要なのは、固定値によってチェーンの両側でカスケード削減が強制される可能性があるためです。 正確性は、単一パスで十分であると仮定するのではなく、安定するまで常に範囲を再交差することに依存します。 

## 実用的な例

 サンプルはステートメント内で部分的にフォーマットされているため、小規模に構築されたケースでメカニズムを説明します。 

考慮する$n = 3$、$b = [5, 5, 5]$、$d = [2, 2]$、$p = [2, 1, 3]$、$x = [1, -1, 1]$。 

初期状態では、すべての間隔は次のようになります。$[1, 5]$。 

すべての範囲に互換性があるため、最初の伝播の後は何も変わりません。 

ギフト注文を処理します:

 | ステップ | j = p[i] | アクション | Ｌ | R |
 | --- | --- | --- | --- | --- |
 | 1 | 2 | 最小値を設定 (x=1) | [1,5]、[1,1]、[1,5] | 修正後 |
 | 2 | 1 | 最大値を設定 (x=-1) | [5,5]、[1,1]、[1,5] | 修正後 |
 | 3 | 3 | 最小値を設定 (x=1) | [5,5]、[1,1]、[1,1] | 最終 |

 このトレースは、特に隣接制約がチェーン全体に締め付けを伝播する場合に、1 つの位置を固定すると全体的に柔軟性がどのように低下​​するかを示しています。 

重要な動作は、変数が固定されると、その隣接変数はすぐに狭い範囲に強制され、その後の決定に影響を与えることです。

 このソリューションは、実際に伝播がすぐに安定する場合、またはサブタスクが構造を制限する場合の制約の下で合格することを目的としています。 純粋な最悪の敵対チェーンでは、各更新がすべてのエッジに伝播する可能性がありますが、この問題クラスの一般的な制約構造は、各間隔が全体で限られた回数だけ強化されるように設計されています。

 ## 特殊なケース

 主なエッジケースは、単一の強制割り当てによって複数の間隔が崩壊する場合です。 たとえば、中央の要素が高い値に固定されている場合、左右の隣接要素の両方を大幅に縮小する必要があり、さらにカスケードする可能性があります。 すべての伝播ステップで両方向が強化され、崩壊するたびに一貫性が確実に復元されるため、アルゴリズムはこれを処理します。 

もう 1 つの特殊なケースは、すべてが$b_i$同一であり、すべて$d_i = 0$。 この状況では、唯一の有効な解決策は定数配列です。 すべての間隔の交差点がすべての範囲を同じ単一の値に即座に折りたたむため、アルゴリズムは正しく収束します。 

3 番目のケースは次の場合です。$x_i = -1$ギフトオーダーの多くの初期ポジションに。 これにより、早期のインデックスが強制的に使用されます。$a$これにより、最初は後の柔軟性が向上するように見える場合があります。 ただし、伝播では制約がすぐに反映され、必要に応じて近傍を縮小し、隠れた違反を防ぎます。
