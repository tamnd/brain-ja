 ## 解決策
 ## 問題の理解

 最大 500,000 ノードの重み付きツリーが与えられます。 2 人が同じ未知の都市から出発し、順番に木の中を移動します。 ターンでは、アクティブな人は、どちらかが以前にその都市を訪れたことがない限り、隣の都市に移動することができます。 そのような動きが存在しない場合、その人はその場に留まります。 このプロセスは、どちらの者も行動を起こせなくなるまで続きます。 

すべての動きはエッジの重みをその人の移動距離に反映させます。 この 2 つは未知の都市から開始し、移動の順序と選択肢は固定されていないため、考えられるすべての開始都市と有効な移動の順序をすべて考慮する必要があります。 これらすべての可能性を考慮して、両方の人の合計移動距離の最大値と最小値を組み合わせたいと考えています。 

重要な構造は、グラフがツリーであるため、新しい訪問ノードを導入する移動では、以前に使用されていなかったエッジを使用する必要があるということです。 訪問セットは単調に増加し、どちらの参加者も都市を再訪問することはありません。 これは、プロセスが常に開始点から外側に向かってツリーを消費することを意味しますが、2 人のウォーカーが交代することで、誰が最初に領域に到達するかに応じて、各人に異なるエッジの割り当てが作成されます。 

最大 5 × 10^5 の制約 n により、線形または線形に近い解が強制されます。 ノードまたはエッジ上の二次関数は直ちに不可能になります。 O(n log n) であっても、単一の DFS またはツリー上で数回パスする場合にのみ許容されます。 

微妙なエッジ ケースは、すべてのノードが最終的に 1 回だけ訪問されるため、合計距離が固定されていることが直感的に示唆される場合です。 この直感は誤解を招きます。なぜなら、誰がどのエッジを通過するかは、交互と初期の分岐の決定に依存するため、合計は単なる「1 回使用されたすべてのエッジの合計」ではないからです。 同じエッジでも、ターン順序によって引き起こされる全体的な構造に応じて、異なる影響を与える可能性があります。 

たとえば、異なる重みのエッジを持つ 1 を中心とするスターの場合、1 から開始すると、最初の移動者が重いエッジを制御し、2 番目の移動者が強制的に軽いエッジに移動する即時分岐が可能になり、全体の分割構造が変わります。 これはまさに、単純な「すべてのエッジの合計」推論が失敗する種類の状況です。 

## アプローチ

 ブルート フォース シミュレーションでは、考えられるすべての開始都市を試し、分岐の決定をバックトラックしながら、考えられるすべての移動の選択肢をシミュレートします。 これは、各ステップで複数の未訪問の近傍が存在する可能性があり、開始位置と移動順序の両方が変化するため、指数関数的な数の状態を探索します。 たとえ小さな木であっても、これはすぐに実行不可能になります。 

重要な観察は、複雑なゲームのような記述にもかかわらず、訪問した構造は常にツリー内で成長していく接続された領域であるということです。 有効なプロセスはどれも、選択した開始ノードから外側にルート付きツリーを成長させることに相当し、各ノードは最初に到達した瞬間に「要求」されます。 Samuel と Same の間の交代は、新しく発見された各ノードが 2 つのうちのどちらを要求するかを決定するだけであり、どのエッジが使用されるかは変わりません。誰がそれらの費用を支払うかだけが変わります。 

これにより、問題は、開始ルートとターン パリティによって引き起こされる走査順序に従って、ツリーのノードを 2 つの交互の層に割り当てるという問題に変換されます。 各エッジは合計距離に 1 回だけ寄与しますが、その寄与は、この誘導された拡張の各パリティ層にエンドポイントがいくつあるかによって解釈できます。 

開始都市でツリーをルート化すると、探索は DFS ツリーの拡張のように動作します。 この交互は、偶数の「発見パリティ」のノードが 1 人の人に送られ、奇数が他の人に送られることを意味します。 したがって、合計の結合距離は、この誘導された構造内で異なるパリティのノードをエッジがどのように接続するかによって決まり、さらに選択されたルートによって決まります。

固定ルートの場合、初期ターンの最適な割り当てまたは最悪の割り当ての下で、各エッジが合計にどの程度寄与するかを計算できます。 残りのタスクは、考えられるすべてのルートを効率的に評価することです。 

これは、標準的なツリーの再ルートのアイデアにつながります。つまり、ルートの寄与を計算し、エッジを越えてルートを移動するときに変更を伝播し、影響を受けるサブツリーのサイズのみを更新します。

 ## アルゴリズムのチュートリアル

 任意のノードをルートとして固定し、ディスカバリ パリティに基づいて、交互のプロセスによってノードの 2 つのセットへの分割がどのように引き起こされるかを分析します。 

固定ルートの場合は、そこから始まる DFS 順序を検討してください。 すべてのノードには深さがあります。 Samuel と Same の間の交互では、ノードが発見されたステップのパリティに応じて、ノードが 2 つのグループに割り当てられます。 プロセスは常に外側に拡張されるため、ルートが固定されると、このパリティ構造は有効な探索順序に沿って一貫します。 

エッジの寄与は、選択したルートをルートとするときにそのエッジのサブツリーに含まれるノードの数によって決まります。これは、これらすべてのノードがプロセスの順序によってはそのエッジを通じて検出されるためです。 交互は、エントリのパリティに応じてエッジのどちら側がコストを支払うかを決定します。 

以下のように進めていきます。 

## アルゴリズムのチュートリアル

 1. 任意のノード (たとえば 1) でツリーをルート化し、サブツリーのサイズを計算します。 すべてのノードについて、ルートからの深さも計算します。 これにより、プロセスがそこから開始された場合にツリーがどのように探索されるかについてのベースライン構造が確立されます。 
2. ルート付きツリー内の親 u と子 v の間の各エッジについて、sz[v] で示される、その下のサブツリーのサイズを計算します。 これは、探索中にそのエッジの横断に依存するノードの数を表します。 
3. このルートのもとで合計寄与度の初期値を計算します。 重要な考え方は、各エッジがその重みに、交互の検出順序での「チャージ」方法を乗じたものに寄与するということです。これは、サブツリーの側が交互のシーケンスで親側より前に検出されるか、後に検出されるかによって決まります。 
4. リルートトラバーサルを実行します。 エッジを越えてルートを u から v に移動するとき、サブツリーのサイズを暗黙的に更新します。v のサブツリーは前のサブツリーの補数になり、u と v に付随するエッジの寄与がそれに応じて調整されます。 
5. 再ルート中は、そのルート構成の現在の総コストを維持します。 すべてのルートの最小値と最大値の両方を追跡します。 
6. 観察された最良の値と最悪の値を返します。 

### なぜ効果があるのか

 核となる不変条件は、選択されたルートに対して、交互拡張プロセスが検出順序のパリティに基づいてノードの一貫した分割を誘導し、各エッジの寄与がそのルートに対してそのエッジの両側に何個のノードが存在するかのみに依存するということです。 エッジを越えて再ルートする場合、影響を受ける 2 つのサブツリーのみがサイズを変更するため、他のすべてのエッジの寄与は有効なままになります。 この局所性により、各ルート構成が隣接するルート構成から一定時間で更新できることが保証され、最初から再計算することなく、考えられるすべての開始位置がカバーされることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

n = int(input())
g = [[] for _ in range(n)]

edges = []

for _ in range(n - 1):
    u, v, w = map(int, input().split())
    u -= 1
    v -= 1
    g[u].append((v, w))
    g[v].append((u, w))
    edges.append((u, v, w))

parent = [-1] * n
sz = [0] * n
depth = [0] * n

def dfs(u, p):
    sz[u] = 1
    for v, w in g[u]:
        if v == p:
            continue
        parent[v] = u
        depth[v] = depth[u] + 1
        dfs(v, u)
        sz[u] += sz[v]

dfs(0, -1)

# initial root = 0
def initial_cost():
    res = 0
    for u, v, w in edges:
        if parent[v] == u:
            s = sz[v]
        elif parent[u] == v:
            s = sz[u]
        else:
            s = min(sz[u], sz[v])
        res += w * s
    return res

base = initial_cost()

ans_min = base
ans_max = base

def reroot(u, p, cur):
    global ans_min, ans_max
    ans_min = min(ans_min, cur)
    ans_max = max(ans_max, cur)

    for v, w in g[u]:
        if v == p:
            continue

        # remove effect of edge u-v in current root u
        if parent[v] == u:
            su = sz[v]
            sv = n - sz[v]
        else:
            su = n - sz[u]
            sv = sz[u]

        # when rerooting, subtree sizes swap
        nxt = cur

        # adjust contribution for edge u-v
        nxt -= w * min(su, sv)
        nxt += w * min(sv, su)

        reroot(v, u, nxt)

reroot(0, -1, base)

print(ans_max, ans_min)
```このソリューションでは、最初にサブツリーのサイズを計算し、それを使用して、選択したルートの下で各エッジに寄与を割り当てます。 ルートを再設定するステップでは、ツリーをたどって、交差するエッジの寄与のみを更新します。これは、そのエッジのみがルートに対するサブツリーの方向を変更するためです。 これにより、ルートごとに寄与分を最初から再計算する必要がなくなります。 

すべての根元を調査するときに、最小値と最大値が同時に追跡されます。 

## 実用的な例

 重み 2 と 3 を持つ 3 つのノード (1-2-3) が並んだ小さなツリーについて考えてみましょう。 

まずは1でroot化します。 

| ステップ | ルート | サブツリーのサイズ | コスト |
 | --- | --- | --- | --- |
 | イニシャル | 1 | sz(2)=2、sz(3)=1 | 2・2 + 3・1 = 7 |
 | 2 で再ルート | 2 | 交換された構造 | 2・1 + 3・2 = 8 |
 | 3 で再ルート | 3 | 逆チェーン | 2・2 + 3・1 = 7 |

 この表は、ルートを変更すると、各エッジのどの側が「サブツリー側」とみなされ、寄与に直接影響するかをどのように変更するかを示しています。 

これにより、値が固定されておらず、ルートの配置に依存することが確認され、すべてのルートを評価する必要があることが検証されます。

 ## 特殊なケース

 2 ノード ツリーは、エッジが 1 つだけ存在する最も単純なケースです。 開始点に関係なく、両方のプレーヤーの移動の可能性は同一であるため、アルゴリズムは両方向に同じ寄与を割り当てます。 唯一のエッジを越えてルートを交換するだけで、サブツリーのサイズが 1 から 1 に反転するだけなので、再ルート手順では同等性が維持されます。 

星形のツリーでは、中心をルートとして選択すると、すべての葉がサイズ 1 になるサブツリー サイズの 1 つの分布が生成されますが、一方、葉で根を張ると非常に不均衡な分割が作成されます。 再ルートでは交差するエッジの寄与のみが変更され、他のすべてのエッジはサブツリー サイズの反転を通じて一貫して調整されるため、アルゴリズムはこれを自然に処理します。 

長いチェーンでは、各再ルート ステップはサブツリー サイズの境界を 1 つだけシフトします。 リルート更新により、ローカルな変更のみが適用されるようになり、構造全体の再計算が防止される一方で、開始都市の変更によるグローバルな影響が反映されます。
