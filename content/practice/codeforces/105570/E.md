 ## 問題の理解

 私たちは与えられています$N$競合他社。 各競技者$i$不明なパラメータがあります$h_i$、どれくらい早く終わるかを表します。 より小さい値$h_i$常に早い終了時間に対応するため、最終的なランキングはすべての順位と正確に一致します。$h_i$昇順で。 競合他社を分類すると、$h_i$、次の順列が得られます。$1..N$レース結果の説明。 

各競合他社は完全には明らかにしていない$h_i$、間隔だけ$[L_i, R_i]$。 有効な整数を選択する必要があります$h_i$その間隔の中で。 

さらに、最終的なランキングに関する部分的な情報 (配列) が提供されます。$p$、 どこ$p_i$競争相手の立場です$i$最終的な順序で、または$0$不明の場合。 最終的な結果が得られるように、欠落しているポジションを埋める必要があります。$p$の完全な順列になります$1..N$、そしてこの順列は、選択されたものによって引き起こされる順序と一致する必要があります。$h_i$。 

したがって、タスクは 2 つあります。 各競合他社に値を割り当てる必要があります$h_i \in [L_i, R_i]$そして、増加と一致する合計順序をそれらに割り当てる必要があります。$h_i$。 同時に、すでに固定されているランキング順位は$p$尊重されなければなりません。 

重要な観察は、$h_i$値は固定されており、それらを並べ替えることでランキングが完全に決定されます。 最終的な並べ替えにはタイを破る以上の自由はなく、区間内に留まりながら値をわずかに摂動させることができるため、タイは無視できます。 

制約は大きく、$N$まで$2 \cdot 10^5$。 これにより、すべての順列を試行したり、使用したりするソリューションは除外されます。$O(N^2)$実現可能性のチェック。 に近いものが必要です$O(N \log N)$、通常はソートまたは優先キューが関係します。 

間隔が狭くて重なっている場合、微妙なエッジケースが現れます。 たとえば、1 人の競合他社を早めに配置する必要があるが、その下限が非常に大きい場合などです。$L_i$、大規模な割り当てを余儀なくされる可能性があります$h_i$、その後の割り当てがブロックされる可能性があります。 別の失敗例は、各間隔が個別に実行可能であるにもかかわらず、固定されたランキング順位が間隔内で実現できない順序付けを強制する場合に発生します。 

## アプローチ

 直接的な試みは、競合他社のすべての順列を試し、それぞれの順列に対して、増加する値を割り当てることができるかどうかをシミュレートすることです。$h_i$間隔内の値。 順序が固定されている場合、実現可能性は簡単です。左から右にトラバースしてそれぞれを設定します。$h_i$単調性とその間隔を尊重しながら、できるだけ小さくします。 具体的には、以前の値が$t$、設定しました$h_i = \max(L_i, t+1)$を超えているかどうかを確認します。$R_i$。 

この強引なアイデアは正しいですが、完全に実行不可能です。$N!$順列、および 1 つの順列をチェックするだけでも$O(N)$、階乗時間を与えます。 

重要な洞察は、実際にはすべての順列を試す必要はないということです。 私たちが望む順列は、最終的な並べ替え順序とまったく同じです。$h_i$。 したがって、順列を推測して検証するのではなく、有効な代入が保証される順列を構築する必要があります。 

建設は貪欲なスケジュールの問題になります。 最終的な順序を左から右に構築します。 各ポジションで、将来のオプションを可能な限り柔軟に保ちながら、シーケンスの次に配置できる間隔で未使用の競合他社を 1 人選択します。 順序が決まったら、割り当てます$h_i$貪欲に。 

難しいのは次の競争相手をどう選ぶかだ。 正しい構造は、各競合他社をリリース時間のあるタスクとして見ることから生まれます。$L_i$そして締め切り$R_i$ただし、割り当てられた値は順序に沿って厳密に増加する必要があるという追加の制約があります。 これにより、問題は、早期に大きなジャンプを強いることを避ける順序の選択に変わります。 

標準的な貪欲な戦略が出現します。つまり、最小値を持つ利用可能な候補を常に選択します。$R_i$。 直感的には、締め切りが厳しい仕事を遅らせると、後で仕事ができなくなるリスクがありますが、早めに緩やかな間隔を選択しても、将来の柔軟性はそれほど制限されません。 

部分的に固定された順列も尊重する必要があります$p$。 これは、いくつかの位置が強制されることを意味します。$k$、 もし$p_k \neq 0$、その特定の競合他社を配置する必要があります。 その時点で実現不可能な場合、構築は即座に失敗します。

 ## アルゴリズムのチュートリアル

 最終的な順列を構築します$p'$左から右へ、同時に順序を決定します。 

1. まだ配置されていないすべての競合他社を収集します。 また、指定された部分順列によってどの競合他社がすでに固定されているかも追跡します。$p$。 ポジションを処理します$1$を通して$N$。 
2. 現在の時刻値を維持する$t$、最後に割り当てられたものを表します$h$構築された順序の値。 最初は$t = 0$。 
3. すべての未使用の競合他社を含むデータ構造を、昇順で維持します。$R_i$。 最小ヒープが適切です。 
4. 各ポジションで$k$、 もし$p_k$が修正された場合、その競合他社を選択しようとします。 それ以外の場合は、ヒープから候補を選択します。 
5. 候補者を検討する場合$i$、この位置で受け取る値を次のように計算します。$h_i = \max(L_i, t+1)$。 この値を超えると$R_i$、次に配置します$i$ここでは建設が不可能になります。 
6. 有効な候補者を選択する場合$i$、それを位置に割り当てます$k$、ヒープから削除して更新します$t = h_i$。 
7. いずれかの段階で有効な候補者が見つからない場合、回答は不可能です。 

最低限の理由$R_i$戦略が機能するのは、有効な解決策であれば、最終的にはすべての要素と、より小さい要素を配置する必要があるということです。$R_i$移動できるスペースが少なくなります。 それらを延期すると、許容範囲を超えるリスクが生じますが、早期に実行しても、必要な増加を超えて他の人の実現可能性を低下させることはできません。$t$。 

### なぜ効果があるのか

 どのステップでも、アルゴリズムは、以前に選択されたすべての割り当てが実行可能であり、厳密に増加していることを維持します。 残った要素の中から最小限のものを選ぶ$R_i$すべての有効なスケジュールをブロックするような形で、より制約の強い要素をより制約の少ない要素の後ろに延期することがないようにするためです。 

解決策が存在する場合、各ステップで選択された要素が最小値を持つ要素になるように、それを変換する方法が常にあります。$R_i$有効な補完に現れる可能性のあるすべての要素の中で。 この交換引数により、貪欲な選択によってすべてのソリューションが存在する場合に削除されないことが保証されます。 

施工後$p'$、割り当て$h_i$この順序での貪欲な実行は常に成功します。これは、構築によって明示的に次のことが保証されるためです。$h_i \le R_i$すべてのステップで実行可能性を高め、シーケンスの実現可能性を維持します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import heapq

def solve():
    N = int(input())
    p = list(map(int, input().split()))
    L = list(map(int, input().split()))
    R = list(map(int, input().split()))

    # convert p into position constraints
    pos_of = [-1] * (N + 1)
    fixed_at = [-1] * (N + 1)

    for i in range(N):
        if p[i] != 0:
            pos_of[i + 1] = p[i]
            fixed_at[p[i]] = i + 1

    used = [False] * (N + 1)
    heap = []

    # push all items into heap by R
    for i in range(1, N + 1):
        heapq.heappush(heap, (R[i - 1], i))

    res = [0] * (N + 1)
    t = 0

    for k in range(1, N + 1):
        chosen = None

        if fixed_at[k] != -1:
            i = fixed_at[k]
            # extract i from heap lazily
            temp = []
            found = False

            while heap:
                r, x = heapq.heappop(heap)
                if x == i and not used[x]:
                    found = True
                    break
                if not used[x]:
                    temp.append((r, x))

            for item in temp:
                heapq.heappush(heap, item)

            if not found:
                print("No")
                return

            chosen = i
        else:
            temp = []
            found = False

            while heap:
                r, i = heapq.heappop(heap)
                if used[i]:
                    continue
                hi = max(L[i - 1], t + 1)
                if hi <= R[i - 1]:
                    chosen = i
                    found = True
                    break
                temp.append((r, i))

            for item in temp:
                heapq.heappush(heap, item)

            if not found:
                print("No")
                return

        used[chosen] = True
        hi = max(L[chosen - 1], t + 1)
        t = hi
        res[chosen] = k

    # build final arrays
    p_out = [0] * N
    h_out = [0] * N

    for i in range(1, N + 1):
        p_out[i - 1] = res[i]
        h_out[i - 1] = max(L[i - 1], 0)  # placeholder

    # reconstruct h in order of p_out
    order = sorted(range(1, N + 1), key=lambda x: res[x])
    t = 0
    for i in order:
        hi = max(L[i - 1], t + 1)
        if hi > R[i - 1]:
            print("No")
            return
        h_out[i - 1] = hi
        t = hi

    print("Yes")
    print(*p_out)
    print(*h_out)

if __name__ == "__main__":
    solve()

第 2 フェーズでは再計算します$h_i$最終注文を使用します。 構築フェーズでは順序付けの実行可能性のみが保証され、2 番目のパスでは実際の数値割り当てが保証されるため、この分離は重要です。 

よくある落とし穴は、割り当てを試みることです。$h_i$順列構築中に、同時に順序付け制約を適用します。 これらのフェーズを分離しておくと、偶発的な依存関係ループが回避されます。
