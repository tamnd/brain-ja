 ## 解決策
 ## 問題の理解

 問題は、パンを焼く際の利益を最大化することです。 生地の量は決まっており、餡の種類も数種類あります。 特定の詰め物のパンは、生地とその詰め物のある程度の量を消費し、一定の利益をもたらします。 プレーンなパンは生地のみを消費し、それ自体で利益をもたらします。 課題は、総収益ができるだけ大きくなるように、あらゆる種類のパンを何個作るかを決定することです。 

入力により、生地の合計、詰め物の種類の数、およびプレーン バンズの要件が得られます。 それぞれの詰め物の種類は、その詰め物がどれだけ存在するか、1 つのパンに必要な詰め物の量、パンが消費する生地の量、およびそれが稼ぐ金額を記述します。 アウトプットとは、獲得できる最大の金額のことです。 

詰め物の種類は少ないですが、生地の量は多めです。 スタッフィング タイプの数は最大 10 であるため、スタッフィング タイプに対する指数関数または動的計画法ソリューションを使用できます。 ただし、生地の量は 1000 に達する可能性があるため、状態制限なしで可能な限りの数のバンズを試すソリューションでは、サイズが大きくなりすぎます。 検索と生地の量を DP 寸法として制御するには、少数の詰め物カテゴリを使用する必要があります。 

主な罠は、詰めパンを選んだ後に残った生地を処理することです。 プレーンなバンズは未使用の生地の詰め物として機能するため、答えは単純に詰めたバンズの最適な組み合わせではありません。 例えば：```
10 1 3 100
5 10 2 1
```正解は 300 です。 1 つの詰め物が 5 つしかないのに 10 単位必要なので、詰めパンを作ることはできません。そのため、プレーン バンズを 3 つ作る必要があります。 詰め物の選択肢のみを考慮し、プレーンなパンを忘れたソリューションでは、ゼロが出力されます。 

もう 1 つの注意が必要なケースは、詰め込みタイプの生地単位あたりの利益は劣りますが、限られた詰め込みを効率的に消費するため有用になる場合です。 例えば：```
10 2 5 1
100 1 5 10
2 10 1 100
```正解は 10 です。最初のタイプのパンを 2 つ作ることができます。 生地ごとに常に最良の価値を選択する貪欲なアプローチでは、より収益性が高いように見えるため、誤って 2 番目のタイプを選択する可能性がありますが、詰め込み制限によりそれが防止されます。 

## アプローチ

 直接的な総当りのソリューションでは、すべてのスタッフィング タイプに対して、可能なすべてのカウントが試行されます。 種類ごとにパンを何枚焼くかを決め、詰める量や生地の総使用量が妥当かどうかを確認します。 このアプローチは正しいものです。考えられるすべての組み合わせが検査されるため、最も有効な組み合わせが見つかる必要があります。 問題は、各スタッフィング タイプには最大 1000 個の可能なカウントがあり、最大 10 タイプでは組み合わせが多すぎることです。 最悪のケースは 1000^10 の可能性に近づきますが、これは不可能です。 

有益な観察は、スタッフィングの種類の数が少ないということです。 バンズのあらゆる流通を追跡する代わりに、詰め物の種類を 1 つずつ処理し、使用する生地の量ごとに達成可能な最高の利益のみを保存できます。 状態のサイズは生地の量によって制限され、わずか 1000 個です。 

詰め物タイプを加工するとき、私たちはそれを使ってできる限りの数のバンズを試します。 このタイプのバンズを k 個作ると、どれだけの詰め物と生地が消費され、どれだけの利益が追加されるかが正確にわかります。 これは有界ナップザック遷移です。 すべての種類の詰め物が処理された後、残りの生地はプレーン バンズに変換できるため、プレーン バンズの可能な限り最高の利益を各州に加算するだけです。 

ブルート フォースはすべての組み合わせを探索するため機能しますが、組み合わせの数が爆発的に増加するため失敗します。 DP が機能するのは、さまざまな詰め物の選択が、すでに費やされた生地の量と、まさに国が保管している利益によってのみ問題となるためです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(可能な数の積) | お(1) | 遅すぎる |
 | 最適 | O(m * n * 100) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 動的プログラミング配列を作成します。`dp[j]`正確に使用した後の最大利益を表します`j`これまでに処理された詰め物のタイプを含む生地のグラム数。 最初は、生地を使用しないと利益はゼロになります。 
2. 詰め物の種類ごとに、利用可能な詰め物から作ることができるバンズの最大数を計算します。 詰め物は限られた資源であるため、この数を超えることはできません。 
3. 以前の生地使用の可能性と、現在のタイプのバンズの可能性がある数のそれぞれについて、新しい状態を更新します。 作る`k`バンズが追加`k * d[i]`利益と消費`k * c[i]`生地。 
4. すべての種類の詰めパンを加工した後、すでに使用されている生地の可能な限りの量を考慮します。 残った生地はプレーンバンズにしか使えないので追加します。`(remaining dough / c0) * d0`その状態に。 
5. すべての最終状態の最大値が答えになります。これは、詰め物の有効な使用方法がすべて表現されており、残った生地にはプレーンなバンズが最適に詰められるためです。 

これが機能する理由: 不変条件は、スタッフィング型の接頭辞を処理した後、`dp[j]`あらゆる支出方法の中で可能な限り最高の利益を正確に蓄える`j`加工された種類のみを使用した生地のグラム数。 すべての遷移では、現在のスタッフィング タイプの追加を可能な限り何度でも考慮するため、すべての新しい有効な組み合わせがカバーされます。 プレーンパンは生地以外に資源が限られているので、最後に扱うことであらゆる解決策が完成します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, c0, d0 = map(int, input().split())
    items = []

    for _ in range(m):
        a, b, c, d = map(int, input().split())
        items.append((a // b, c, d))

    dp = [-1] * (n + 1)
    dp[0] = 0

    for limit, cost, value in items:
        ndp = [-1] * (n + 1)
        for used in range(n + 1):
            if dp[used] == -1:
                continue
            for cnt in range(limit + 1):
                new_used = used + cnt * cost
                if new_used > n:
                    break
                profit = dp[used] + cnt * value
                if profit > ndp[new_used]:
                    ndp[new_used] = profit
        dp = ndp

    ans = 0
    for used in range(n + 1):
        if dp[used] != -1:
            total = dp[used] + ((n - used) // c0) * d0
            if total > ans:
                ans = total

    print(ans)

if __name__ == "__main__":
    solve()
```コードはまず、各スタッフィング タイプを使用可能な制限に変換します。`a // b`すべてのパンが消費するため、そのタイプのパンの最大数です。`b`詰め物の単位とのみ`a`ユニットが存在します。 

DP 配列はスタッフィングの種類ごとに再構築されるため、遷移で同じスタッフィングが制限を超えて誤って複数回使用されることはありません。 到達可能な生地の量ごとに、内側のループは現在のパン タイプの可能なカウントをすべて試行します。 

最後のループでは、プレーンなパンが処理されます。 州にはすでに詰めパンからの利益が含まれており、残りの生地はできるだけ多くのプレーンバンに変換されます。 これにより、別の DP 次元が必要なくなります。 

遷移における境界条件は次のとおりです。`new_used > n`。 生地の制限を超えると、それ以上のカウントは不可能になるため、ループが停止する可能性があります。 Python の整数は最大利益範囲に十分な大きさがあるため、オーバーフロー処理は必要ありません。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    old = sys.stdin
    sys.stdin = io.StringIO(inp)
    data = sys.stdin.readline

    n, m, c0, d0 = map(int, data().split())
    items = []
    for _ in range(m):
        a, b, c, d = map(int, data().split())
        items.append((a // b, c, d))

    dp = [-1] * (n + 1)
    dp[0] = 0

    for limit, cost, value in items:
        ndp = [-1] * (n + 1)
        for used in range(n + 1):
            if dp[used] == -1:
                continue
            for cnt in range(limit + 1):
                nxt = used + cnt * cost
                if nxt > n:
                    break
                ndp[nxt] = max(ndp[nxt], dp[used] + cnt * value)
        dp = ndp

    ans = 0
    for i in range(n + 1):
        if dp[i] != -1:
            ans = max(ans, dp[i] + ((n - i) // c0) * d0)

    sys.stdin = old
    return str(ans)

 ## 特殊なケース

 詰めパンを 1 つでも作るのに十分な詰め物がない場合、アルゴリズムはそれらのトランジションを利用できないままにします。 この場合の場合:```
10 1 3 100
5 10 2 1
```スタッフィング制限がゼロになるため、`5 // 10 = 0`。 DP は空の詰め物の選択肢のみを保持し、最終ステップでは 300 の利益を得るために 3 つのプレーン バンズを作成します。 

最も収益性の高いと思われる詰め物が全体として最適な選択ではない場合でも、DP は完全な組み合わせを比較するため機能します。 で：```
10 2 5 1
100 1 5 10
2 10 1 100
```2 番目のタイプは、詰め物が限られているため、十分に使用できません。 遷移には最初のタイプの選択肢が含まれており、最終的な答えは 10 になります。 

すべての生地をプレーンバンズで使用する必要がある場合は、最終パスオーバーステートで自然に処理されます。 消費された生地がゼロの DP 状態は依然として有効であり、残りの生地の計算によりプレーン パンの最大数が生成されます。 これにより、特別なケースが必要なくなります。
