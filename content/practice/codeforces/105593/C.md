 ## 解決策
 ## 問題の理解

 最初は間に道路がない村のコレクションが与えられました。 各テスト ケースでは、村の数と建設可能な道路の最大数という 2 つの数値が記述されます。 

目標は、許可された数の道路を使用して村を接続し、2 つの村間の最大の最短経路距離ができるだけ小さくなるようにすることです。 一連の村全体を利用可能な道路で接続することができなければ、答えは不可能です。 

ここで重要なオブジェクトは、道路を構築した後に得られるグラフの直径、つまりエッジの数で表したノードのペア間の最大距離です。 すべての道路は重み付けされていないため、距離は単に最短パス上のエッジの数になります。 

制約範囲は非常に大きく、テスト ケースは最大 10^5、n と m の値は最大 5 × 10^8 です。 これにより、テストごとのシミュレーションやグラフ構築が即座に排除されます。 すべての解は、算術推論のみに依存して、テスト ケースごとに O(1) でなければなりません。 

単純なアプローチでは、グラフを明示的に構築し、さまざまなエッジ配置でその直径をテストしようとします。 この規模では隣接構造の構築や BFS の実行は不可能であるため、貪欲な構築でもすでに遅すぎます。 

m がすべてのノードを接続するために必要な最小値よりわずかに小さい場合、微妙な障害が発生します。 たとえば、n = 4 および m = 2 の場合、チェーン内の最大 3 つのノードを接続し、1 つを分離したままにすることができるため、グラフは切断され、有限の直径は存在しません。 m 個のエッジを配置した後の接続性を仮定する不注意な解決策は、不可能性を認識する代わりに、誤って有限の答えを出力してしまいます。 

## アプローチ

 ブルートフォースメンタルモデルは、エッジを 1 つずつ追加し、追加するたびに直径を再計算することを考えることです。 これは、各エッジがローカルで最短パスを変更し、各ノードからの BFS が距離を再計算できるため、小さなグラフで機能します。 ただし、これにはすでに評価ごとに O(n(n + m)) のコストがかかり、ここで n 自体は最大 5 × 10^8 になる可能性があるため、グラフを保存することさえ不可能になります。 

重要な単純化は、村の特定のラベル付けではなく、接続されたグラフの構造のみが重要であることを認識することです。 n 個のノードと m 個のエッジがある場合、最大距離を最小限に抑えるための最良の構成は、常に追加のエッジで強化されたツリー状の構造です。 n − 1 を超える余分なエッジは距離を短縮することしかできませんが、制限要因は接続が達成可能かどうかです。 

グラフが接続されると、最も距離効率の良い構造は、1 つの中心ノードが他の多数のノードに接続されるスター状の構成になります。 これにより直径が最小化されます。星の直径は 2 ですが、さらにエッジを追加すると、グラフが完成した場合にのみ直径をさらに 1 に減らすことができます。 

したがって、問題は 2 つの体制のチェックに帰着します。 まず、m がすべてのノードを接続するのに十分な大きさであるかどうか。それには m ≥ n − 1 が必要です。第 2 に、余分なエッジを持つ接続されたグラフの間で、冗長性 m − (n − 1) を考慮して直径をどの程度小さくすることができるかです。 エッジが追加されるたびに、ショートカットを効果的に追加することで最長のパスを短縮でき、極限構造は完成するまでますます高密度になります。 

重要な観察は、直径 1 のグラフは完全なグラフであり、n(n − 1) / 2 のエッジを必要とするということです。 n − 1 とそのしきい値の間に任意の数のエッジがあると、最適な最小直径が 2 である接続されたグラフが生成されます。n − 1 未満ではそれは不可能です。

 ## アルゴリズムのチュートリアル

 ### 最適な推論手順

1. m が少なくとも n − 1 であるかどうかを確認して、グラフが使用可能なエッジに接続できるかどうかを確認します。n ノード上の接続されたグラフには少なくともスパニング ツリーが必要であるため、これは接続された構造に必要なエッジの最小数です。 
2. m < n − 1 の場合、一部の村は孤立したままにしなければならず、すべてのペアにわたる有限の最大距離を定義できないため、すぐに -1 を出力します。 
3. グラフを接続できる場合、直径をどこまで小さくできるかを検討します。 直径 1 は、ノードのすべてのペアが直接接続されている場合にのみ可能であり、正確に n(n − 1) / 2 のエッジが必要です。 
4. m がこの完全グラフしきい値に達すると、すべてのノードが他のすべてのノードに隣接するため、1 を出力します。 
5. それ以外の場合は、出力 2 になります。これは、不完全な接続グラフは常に最長最短経路が最大 2 になるように編成でき、直径 1 を保証できる構造はありません。 

### なぜ効果があるのか

 この議論は極値グラフ構造に依存します。 接続されたグラフには常にスパニング ツリーが含まれるため、単一ノードまたは完全な構造でない限り、ベースラインは直径が少なくとも 2 のツリーになります。 エッジを追加すると、ショートカットを導入して最短パスを短くすることしかできませんが、すべてのペアが直接接続されるまでは、最短パスが中間ノードを使用する頂点のペアが少なくとも 1 つ存在し、直径が少なくとも 2 になります。すべての中間パスを削除する唯一の方法は、すべてのペアを直接接続することです。これは完全なグラフに一意に対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n, m = map(int, input().split())

        if m < n - 1:
            out.append("-1")
            continue

        # number of edges in complete graph
        max_edges = n * (n - 1) // 2

        if m == max_edges:
            out.append("1")
        else:
            out.append("2")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```最初のチェックでは、スパニング ツリーの下限を使用して接続を強制します。 2 番目は、完全なグラフのしきい値と比較します。これは、すべてのペアごとの距離が 1 に崩壊する唯一の状況です。他のすべては、接続は可能ですが、長さ 2 の最短パスを排除できるほど十分な密度ではない中間領域に分類されます。 

よくある間違いは、グラフが接続されると、答えは常に 2 であると仮定することです。これはほぼ正しいですが、直径がさらに崩れる完全なグラフ エッジ ケースを見逃しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    def solve():
        t = int(input())
        res = []
        for _ in range(t):
            n, m = map(int, input().split())
            if m < n - 1:
                res.append("-1")
            elif m == n * (n - 1) // 2:
                res.append("1")
            else:
                res.append("2")
        return "\n".join(res)

    return solve()

 ## 特殊なケース

 n = 2 の場合、動作により両方のしきい値が一緒に折りたたまれます。 エッジが 1 つあるとグラフは完全で直径は 1 ですが、エッジが 0 つあるとグラフは切断され、不可能になります。 n − 1 は 1 に等しく、n(n − 1)/2 も 1 に等しいため、アルゴリズムはこれをきれいに処理します。 

n = 5 や m = 9 など、ほぼ完成に近いグラフの場合、構造は接続されており、非常に密ですが、完成するには少なくとも 1 つのエッジがまだ欠けています。 直接接続されていない頂点のペアが少なくとも 1 組残っており、中間ノードを介して長さ 2 のパスが強制されるため、アルゴリズムはこれを直径 2 として正しく分類します。
