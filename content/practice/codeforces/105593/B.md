 ## 解決策
 ## 問題の理解

 サイズのグリッドから始めます$n \times m$ここで、すべてのセルには最初はゼロが含まれています。 時間の経過とともに、2 種類の操作が適用されます。 1 回の操作で行全体または列全体が反転され、0 が 1 に、1 が 0 に戻ります。 もう 1 つの操作では、長方形のサブグリッド内の値の合計を求めます。 

最大の難点は、何度も反転した後、すべてのセルの値がその行と列が何回切り替わったかに依存することです。 細胞$(i, j)$行に影響を与えるフリップのパリティが正確に 1 になる$i$そしてコラム$j$異なります。 これは、グリッドが明示的に保存されないことを意味します。 それはフリップ履歴によって暗黙的に定義されます。 

入力は複数の独立したテスト ケースで構成されます。 各テスト ケースは次元を提供します$n, m$そして一連の操作。 各操作は、行または列を切り替えるか、サブ四角形の合計をクエリします。 出力は、各合計クエリに対する答えです。 

制約は両方とも十分に大きいので、$n$、$m$、および操作の数$q$まで可能です$10^5$テスト ケースごとに、合計入力サイズの制限は次のとおりです。$10^5$。 これにより、操作ごとにグリッドを再構築またはスキャンするアプローチは直ちに除外されます。 クエリごとに 1 回の完全な再計算でも、$O(nm)$最悪の場合、実行可能な制限をはるかに超えます。 

単純なアプローチでは、完全なマトリックスを維持し、反転を直接適用しようとする可能性があります。 これは失敗します。各反転が行または列全体に接触し、コストがかかります。$O(n)$または$O(m)$、クエリにはコストがかかります$O(nm)$。 まで$10^5$操作すると、これが爆発します。 

部分的な最適化の試行では、別の微妙な障害モードが発生します。 行反転のみを追跡し、各クエリをセルごとに再計算すると、列反転が行反転と乗算的に相互作用するという事実を見落とす可能性があります。 たとえば、行 2 と列 3 をそれぞれ 2 回反転すると、パリティが正しく追跡されていない場合に誤って処理されやすいキャンセル効果が生じます。 

重要な構造上の観察は、各セルが 2 つのブール状態によってのみ決定されるということです。つまり、その行が奇数回反転されたかどうか、およびその列が奇数回反転されたかどうかです。 これにより、問題は動的な 2D グリッドから 2 つの進化する 1D ブール配列に軽減されます。 

## アプローチ

 ブルートフォースのアイデアは単純です。 グリッドを明示的に保守します。 各行または列の反転は、影響を受けるすべてのセルを反復して切り替えます。 各クエリは、要求された部分行列をスキャンし、値を合計します。 これは問題の定義を直接シミュレートするため、これは正しいです。 問題はコストです。行反転は$O(m)$、列反転は$O(n)$、クエリは$O(nm)$。 高密度の入力では、これは約$10^{10}$操作、またはさらに悪いことに、それは実行不可能です。 

この改善は、グリッドにはフリップのパリティを超える内部状態がないことを認識することによってもたらされます。 セル値を保存する代わりに、2 つのブール配列を保存します。1 つは行用、もう 1 つは列用で、それぞれが奇数回反転されたかどうかを示します。 

これが完了すると、任意のセルの値を計算できるようになります。$(i, j)$として：$$a_{i,j} = row[i] \oplus col[j]$$これにより、グリッドが構造化された XOR モデルに変換されます。 長方形上の合計は、ペアの数を数えるように書き換えることができます。$(i, j)$長方形の中で満足する$row[i] \neq col[j]$。 

クエリ四角形内で必要なのは、値 1 と 0 を持つ行の数と、値 1 と 0 を持つ列の数だけです。四角形の合計は、4 つの積の組み合わせになります。つまり、0 を持つ行と 1 を持つ列のペア、および 1 を持つ行と 0 を持つ列のペアです。 

これにより、クエリ範囲内の行および列インデックス セットに対するプレフィックス前処理後の各クエリが定数時間に短縮されます。 高速範囲カウントをサポートするために、行反転状態と列反転状態にわたるプレフィックス合計を維持するため、任意の間隔内に反転された行または列の数をカウントできます。 

行列のスキャンから 2 つの独立したバイナリ セットのカウントへの移行が、重要な単純化です。 これが機能するのは、行と列の操作が独立しており、分離可能な方法ですべてのセルに影響を与えるためです。

 ## アルゴリズムのチュートリアル

 1. 2 つの配列を維持する`row`そして`col`、最初はすべてゼロです。 これらは、各行および列のフリップ パリティを格納します。 
2. 行反転タイプの更新を処理するときに、`row[i]`。 列反転を処理するときに切り替えます`col[j]`。 これにより、繰り返される反転がペアでキャンセルされるため、状態がパリティのみに圧縮された状態が維持されます。 
3. すべてのクエリは範囲内の 1 と 0 の数のみに依存するため、これらの配列を超えるグローバル構造は事前計算されません。 
4. 長方形に関する質問に答える場合$[a, b] \times [c, d]$、次を計算します。

5. プレフィックスの合計を使用する`row`そして`col`これらの各カウントが計算されるように配列します。$O(1)$。 これは、範囲カウントからプレフィックスの差分までの標準的な削減です。 
6. ID を使用して最終的な合計を計算します。 

1 に等しいセルは、行パリティが列パリティと異なるセルであるため、合計は次のようになります。$$\text{ones} = r_0 \cdot c_1 + r_1 \cdot c_0$$### なぜ効果があるのか

 すべてのセルは、その行と列が奇数回反転されたかどうかのみに依存します。 行反転と列反転は相互に変換され、独立した操作であるため、最終状態はパリティ ベクトルによって完全に決定されます。 四角形の合計は、クエリ範囲内に出現する各パリティの行数と列数にのみ依存し、これ以上の詳細な構造は存在しません。 この不変性により、同じパリティ配列につながる一連の操作が同じ答えを生成することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m, q = map(int, input().split())

        row = [0] * (n + 1)
        col = [0] * (m + 1)

        # prefix arrays updated lazily via direct recomputation
        # but since constraints allow total size 1e5, we rebuild prefix when needed
        # we maintain current prefix sums after each toggle batch

        def build_row_prefix():
            pr = [0] * (n + 1)
            for i in range(1, n + 1):
                pr[i] = pr[i - 1] + row[i]
            return pr

        def build_col_prefix():
            pc = [0] * (m + 1)
            for i in range(1, m + 1):
                pc[i] = pc[i - 1] + col[i]
            return pc

        pr = build_row_prefix()
        pc = build_col_prefix()

        for _ in range(q):
            tmp = input().split()
            if tmp[0] == "1":
                typ = int(tmp[1])
                idx = int(tmp[2])
                if typ == 1:
                    col[idx] ^= 1
                else:
                    row[idx] ^= 1

                pr = build_row_prefix()
                pc = build_col_prefix()

            else:
                a, b, c, d = map(int, tmp[1:])
                r1 = pr[c] - pr[a - 1]
                r0 = (c - a + 1) - r1
                c1 = pc[d] - pc[b - 1]
                c0 = (d - b + 1) - c1

                ans = r0 * c1 + r1 * c0
                print(ans)

if __name__ == "__main__":
    solve()
```このコードは、行と列のパリティ配列を追跡することで、状態の更新をクエリ応答から分離します。 反転するたびに、プレフィックス配列が再構築され、定数時間の範囲カウントが可能になります。 クエリ計算はアイデンティティを直接実装します。$r_0 c_1 + r_1 c_0$、 どこ`r1`そして`c1`クエリ範囲内で反転された行と列の数です。 主な微妙な点は、インデックスは 1 から始まるため、プレフィックス配列は長さを指定して構築されることを覚えていることです。$n+1$そして$m+1$オフバイワンエラーを避けるため。

 範囲内の行: 1 つの反転された行、2 つの反転されていない行。 列: 1 つは反転、3 つは非反転。 したがって、結果は$2 \cdot 1 + 1 \cdot 3 = 5$実際には完全な分散に依存しており、XOR ルールの一貫性が確認されています。 

このトレースは、行と列の状態がどのように独立して変化するか、およびクエリがカウントのみにどのように依存するかを示します。
