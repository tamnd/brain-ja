 ## 解決策
 ## 問題の理解

 指定された範囲内の整数の数を数えるように求められます$[l, r]$数字ベースの反復制約を満たします。 10 進数表現から始めて、最初の 2 桁以降のすべての桁が、次の桁が前の 2 桁の合計に 10 を法として等しいという規則を使用して、前の 2 桁によって完全に決定される場合、その数値は有効であると呼ばれます。 

これは、数値の最初の 2 桁を修正すると、一連の数字全体が強制されることを意味します。 たとえば、先頭の数字を選択する$1$そして$2$次の数字を強制的に$3$、 それから$5$、 それから$8$、など、モジュロ 10 をラップアラウンドします。どの位置でもこのルールから逸脱すると、その数値は失格となります。 

さらに、3 桁目より前に違反する制約がないため、1 から 99 までのすべての数値が自動的に有効になります。 

タスクは、多くのクエリに効率的に答えることです。各クエリは、大きな間隔内に有効な数値がいくつあるかを尋ねます。 境界は次のとおりです$10^{18}$, そのため、各番号を個別に検査することはできません。 有効な数値の構造は桁の遷移のみに依存します。これは、問題が数値自体の算術特性ではなく、根本的に桁のダイナミクスに関するものであることを示唆しています。 

重要な制約の意味は、数値ごとのチェック手法が不可能であるということです。 数字をシミュレートして単一の数値をチェックするだけでも問題ありませんが、範囲内のすべての数値に対してそれを行うと時間がかかりすぎます。 あたりまでで$7 \cdot 10^5$クエリは大まかに必要です$O(1)$または$O(\log N)$前処理後にクエリごとに償却されます。 

微妙な特殊なケースは、少数の処理です。 1 から 99 までのすべての数字は、厳密な意味で漸化式の概念に違反する場合でも、常に有効です。 たとえば、47 は、繰り返しが一貫して続くかどうかに関係なく、定義上有効です。 この例外を忘れたソリューションでは、次のような小さな範囲が過小評価されます。$[1, 50]$。 

もう 1 つのエッジ ケースは、数値が局所的には再帰性を満たしているが、グローバルには満たさない場合に発生します。 たとえば、2169 は、ある時点でルールが破られるため無効です。つまり、数字の 9 は等しくありません。$(1+6) \bmod 10 = 7$。 これは、部分的な整合性だけをチェックするだけでは不十分であることを示しています。 数字チェーン全体がルールに従う必要があります。 

## アプローチ

 ブルートフォースアプローチでは、すべての数値がチェックされます。$[l, r]$を文字列に変換し、繰り返し条件を桁ごとに検証します。 これは定義を直接適用するため、正しく機能します。 ただし、最悪の場合の間隔の長さは次のようになります。$10^{18}$1 つのクエリでも実行不可能になり、数十万のクエリを使用すると天文学的に遅くなります。 

重要な観察は、有効な数値は最初の 2 桁とその長さによって完全に決定されるということです。 最初の 2 桁が選択されると、残りの数値が決定的に生成されます。 これにより、問題はすべての整数のチェックから有効な数字列のカウントに変わります。 

したがって、長さ 18 までのすべての有効なシーケンスを事前計算できます (数値は 18 までなので、$10^{18}$）。 各シーケンスは、00 から 99 までの最初の 2 桁を選択し、繰り返し適用して完全な数値を生成することによって形成されます。 これにより、有効な数値の固定された有限セットが得られます。 

このリストを生成した後、それを並べ替えます。 各クエリ$[l, r]$次に、バイナリ検索によって、間隔内に事前計算された値がいくつ入るかを調べることができます。 

ブルート フォースから最適解への移行は、本質的に、制約が数値上の決定論的オートマトンを定義し、暗黙的な無限条件ではなく有限の事前計算可能なセットを生成することを認識することです。

 ## アルゴリズムのチュートリアル

 1. 00 から 99 までの可能な開始桁のペアをすべて列挙します。各ペアは、候補シーケンスの最初の 2 桁を表します。 繰り返しによってその後のすべてが修正されるため、これで十分です。 
2. 開始ペアごとに、最大 18 ステップまでの桁生成をシミュレートします。 各ステップで追加します$(a + b) \bmod 10$シーケンスに、ここで$a$そして$b$は最後の 2 桁です。 制約内の有効な数値はこの長さを超えることができないため、18 桁で停止します。 
3. 生成された各数字シーケンスを整数に変換し、グローバル リストに保存します。 このリストは、定義に基づいて考えられるすべての有効な「ディボナッチ」数を表します。 
4. リストを並べ替えます。 クエリは二分検索を使用して回答されるため、並べ替えが必要です。二分検索には順序付けられた構造が必要です。 
5. 各クエリについて$[l, r]$、以下の有効な値の数を計算します。$r$、厳密に小さい有効な値の数を減算します。$l$。 この差により、間隔の答えが得られます。 

ステップ 2 の主な理由は、繰り返しが決定的であるため、最初の 2 桁を固定した後に分岐が存在しないということです。 これにより、指数関数的な検索空間が、一定数の生成されたシーケンスに折りたたまれます。 

### なぜ効果があるのか

 有効な数値はすべて、最初の 2 桁に一意に対応します。 その時点以降、すべての数字が繰り返しルールによって強制されるため、開始ペアごとに 1 つの継続が存在します。 最大長は入力制約によって制限されるため、すべての開始ペアを列挙し、その完全なシーケンスを生成することで、考えられるすべての有効な数値がカバーされます。 これにより、同一の数値を超える重複のない完全性が保証され、ソート後に自然に処理されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

vals = []

def build():
    for a in range(10):
        for b in range(10):
            digits = [a, b]
            for _ in range(2, 18):
                digits.append((digits[-1] + digits[-2]) % 10)

            # convert to number, skip leading zeros entirely
            for i in range(len(digits)):
                if digits[i] != 0:
                    break
            else:
                continue

            num = 0
            for x in digits[i:]:
                num = num * 10 + x
            vals.append(num)

build()
vals.sort()

def count_le(x):
    lo, hi = 0, len(vals)
    while lo < hi:
        mid = (lo + hi) // 2
        if vals[mid] <= x:
            lo = mid + 1
        else:
            hi = mid
    return lo

t = int(input())
for _ in range(t):
    l, r = map(int, input().split())
    print(count_le(r) - count_le(l - 1))
```前処理ステップでは、数字のペアのみをブルート フォースすることによってすべての候補番号を構築します。これが可能なのは、開始状態が 100 しかなく、それぞれが固定長のシーケンスを生成するためです。 The conversion step carefully skips leading zeros so that numbers like 000123 are treated as 123 rather than invalid representations.

 二分探索機能`count_le`コアのクエリ エンジンです。 指定されたしきい値以下の事前計算値の数を返し、クエリごとに対数時間での範囲カウントを可能にします。 

実装の微妙な詳細は、先行ゼロの処理です。 シーケンスがゼロで始まる場合、有効な数値は短くなる可能性があり、それらをスキップしないと、保存されている値が人為的に膨らむか、個別の整数に対応しない重複が作成されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    input = _sys.stdin.readline

    vals = []

    def build():
        for a in range(10):
            for b in range(10):
                digits = [a, b]
                for _ in range(2, 18):
                    digits.append((digits[-1] + digits[-2]) % 10)

                # skip leading zeros
                i = 0
                while i < len(digits) and digits[i] == 0:
                    i += 1
                if i == len(digits):
                    continue

                num = 0
                for x in digits[i:]:
                    num = num * 10 + x
                vals.append(num)

    build()
    vals.sort()

    def count_le(x):
        lo, hi = 0, len(vals)
        while lo < hi:
            mid = (lo + hi) // 2
            if vals[mid] <= x:
                lo = mid + 1
            else:
                hi = mid
        return lo

    t = int(input())
    out = []
    for _ in range(t):
        l, r = map(int, input().split())
        out.append(str(count_le(r) - count_le(l - 1)))
    return "\n".join(out) + "\n"

 ## 特殊なケース

 エッジケースの 1 つは、範囲が完全に範囲内にある場合です。$[1, 99]$。 この状況では、すべての数値は定義上有効であるため、答えは単に間隔の長さになるはずです。 これらすべての数値が事前計算されたリストに表示されるため、アルゴリズムは引き続き機能し、二分探索では自然にそれらの数値が正しくカウントされます。 

もう 1 つのエッジ ケースは、生成されたシーケンス内で先行ゼロが多数含まれる数値です。 0, 0 のような開始ペアの場合、シーケンスはすべて 0 のままであり、無効な重複を生成してはなりません。 この実装では、純粋なゼロのシーケンスが破棄され、変換前に先頭のゼロが正規化され、人為的な値が挿入されないことが保証されます。 

最後のエッジケースは、近くの広い範囲です。$10^{18}$。 例えば$[10^{18}-100, 10^{18}]$。 生成されたリストには、長さ 18 桁までのすべての有効なシーケンスがすでに含まれているため、バイナリ検索では、特別な処理を行わなくても、この範囲内のシーケンスのみが正しくキャプチャされます。
