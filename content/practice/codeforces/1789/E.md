 ## アルゴリズムのチュートリアル

 1. 配列をソートする$s$まだ並べ替えられていない場合。 これにより、後で単純な数値しきい値を満たす要素の数を迅速にカウントできるようになります。 
2. すべての個別の値を事前計算します。$a = \lfloor S/x \rfloor$として$x$からの範囲$1$に$S$。 これらの値は、連続した範囲を形成します。$x$どこ$a$は一定です。 グループ化する理由は、すべてのグループの表現可能性を再計算するためです。$x$は冗長です。 
3. 各ブロックについて、$a$が固定されている場合、対応する範囲を決定します。$x$。 この範囲内では、両方とも$\lfloor S/x \rfloor = a$そして$\lceil S/x \rceil$どちらかです$a$または$a+1$。 
4. 各ブロックをサブ範囲に分割します。$S$で割り切れます$x$。 割り切れる場合、両方のコインの価値は等しいため、表現可能性は次のことをチェックすることになります。$s_i$の倍数です$a$。 これは、整数除算を使用して効率的にカウントできます。 
5. 割り切れない場合は、コインを使用します。$a$そして$a+1$。 連続する整数は互いに素であるため、十分に大きな整数はすべて表現可能であり、それより小さい値は到達可能な剰余のモジュロをチェックする必要があります。$a$。 なぜなら$a$各ブロック内で が小さい場合、表現可能な残基のセットは安定し、事前計算できます。 
6. ブロックごとに、ブロックの数を数えます。$s_i$表現可能なセットに分類され、重み付けされたブロックの長さを乗算します。$x$、そして答えに蓄積されます。 
7. すべてのブロックの寄与をモジュロで合計する$998244353$。 

### なぜ効果があるのか

 このアルゴリズムは、ペアが$(\lfloor S/x \rfloor, \lceil S/x \rceil)$長い間隔にわたって一定である$x$、各区間内では、表現可能条件は固定の 2 生成半群にのみ依存します。 2 つの連続する整数によって生成される半群は予測可能な構造を持っているため、メンバーシップはモジュールの到達可能性と有限の例外セットに減ります。 グループ化により、そのような各構造が 1 回処理されることが保証され、ブロック全体の合計により、すべての構造の正確な寄与が保持されます。$x$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = list(map(int, input().split()))
        S = s[-1]

        # Precompute prefix counts for fast queries
        # We will use a simple boolean array for membership
        present = set(s)

        # For each x, compute f(x)
        # We exploit block structure of floor(S/x)
        ans = 0

        x = 1
        while x <= S:
            a = S // x
            l = x
            r = S // a

            # count f(x) for this block
            # for each s_i, check representability by (a, a or a+1)
            cnt = 0

            # helper: check representability for (a, a+1)
            # since constraints are large, we only need existence:
            # any s >= a*(a-1) is representable
            # otherwise brute check small range via modular DP

            limit = a * (a - 1)
            for v in s:
                if v >= limit:
                    cnt += 1
                else:
                    # check small DP up to a
                    # O(a) is safe because sum S over tests is small
                    reachable = [False] * (a + 1)
                    reachable[0] = True
                    for i in range(a + 1):
                        if reachable[i]:
                            if i + a <= a:
                                reachable[i + a] = True
                            if i + (a + 1) <= a:
                                reachable[i + (a + 1)] = True
                    if any(reachable[v % a]):
                        cnt += 1

            length = r - l + 1
            # sum of x over block
            sum_x = (l + r) * length // 2 % MOD

            ans = (ans + cnt * sum_x) % MOD
            x = r + 1

        print(ans % MOD)

if __name__ == "__main__":
    solve()

実装上の微妙なリスクは、コインの動作を再計算することなく、ブロック内の値ごとに表現可能性を独立してチェックできるという仮定にあります。 正しさは、セグメント内でコインのペアが変化しないという事実に完全に依存します。$x$1 つの計算内の値がロジックを壊す可能性があります。
