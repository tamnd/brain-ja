 ## 解決策
 ## 問題の理解

 個別の値を含む初期配列が与えられ、その後、一連の更新が与えられます。 各更新では 1 つの位置が変更され、更新のたびに配列には個別の値が含まれます。 これにより、配列のタイムラインが生成されます。元の配列、その後の各変更後、合計が得られるまでの配列です。$m+1$バージョン。 

バージョンのペアごとに$A_i$そして$A_j$、それらを連結し、その結合されたマルチセットに現れる個別の値の数を数えます。 タスクは、バージョンのすべてのペアにわたってこの値の合計を計算することです。 

問題を再解釈する有効な方法は、重複の観点から考えることです。 2 つの配列が連結される場合、個別の要素の数は次のようになります。$$|A_i| + |A_j| - |A_i \cap A_j|.$$すべての配列には常にサイズがあるため、$n$、問題は次のようになります。$$n + n - |A_i \cap A_j| = 2n - |A_i \cap A_j|.$$したがって、タスク全体は、バージョンのすべてのペアにわたる交差サイズを合計することになります。 

これにより、問題は「個別の結合をカウントする」という問題から「各値がどのくらいの期間存続し、バージョン間で重複するかを追跡する」という問題に変換されます。 

この制約により、単純なアプローチが失敗する理由が明らかになります。 まであります$2 \cdot 10^5$テスト ケース全体の操作の合計、つまりバージョンの数が多くなります。 バージョンのペアを直接比較するアプローチでは、$O(m^2)$、次の場合はまったく実行不可能です。$m$到達できる$2 \cdot 10^5$。 

微妙なエッジケースは、値が削除された後に再び現れることから発生します。 値はバージョン 0 に存在し、何らかの操作で消え、その後二度と表示されない場合があります。 別の値が遅れて導入され、永続化される可能性があります。 「各値はバージョンごとに独立して寄与する」と誤って仮定すると、重複を二重にカウントしたりキャンセルを見逃したりすることになります。 

落とし穴の小さな図:

 入力:```
n = 2, m = 1
A0 = [1,2]
A1 = [2,3]
```ペア:

 - (0,0): 2 つの異なる
 - (0,1): 3 つの異なる
 - (1,1): 2 つの異なる

 答え = 7。 

単純な試みでは、「各操作で 1 つの新しい値が追加されるので、変更を蓄積するだけ」と考えるかもしれませんが、これは交差がローカル更新だけでなくライフスパン全体の重複に依存することを無視しています。 

## アプローチ

 ブルート フォース戦略では、配列のすべてのバージョンを明示的に構築し、すべてのペアを比較します。 各ペアについて、結合内の個別の要素の数を計算します。 セットを事前計算したとしても、2 つのバージョンの比較にはコストがかかります$O(n)$、そして、あります$O(m^2)$ペア、につながる$O(m^2 n)$、限界をはるかに超えています。 

重要な観察は、配列全体の観点から考えるのをやめ、代わりに時間の経過とともに各値を個別に追跡することです。 

各値は常に 1 つの位置に表示されますが、後で置き換えられる可能性があります。 したがって、すべての値にはバージョンにわたって連続した「存続期間」があり、導入された瞬間から上書きされる瞬間まで存在します。 

次に固定値を考えてみましょう$x$。 バージョンごとに存在すると仮定します$[l, r]$。 次に、バージョンの任意のペアについて$(i, j)$、両方のバージョンに次のものが含まれる場合にのみ、交差に寄与します。$x$、両方の意味$i$そして$j$寝そべる$[l, r]$。 

したがって、各値は、その存続期間内で完全にバージョンのペアの数に正確に寄与します。これは次のようになります。$$\binom{len}{2} + len$$対角線のペア、より正確にはその区間内のすべての順序のないペアを含める場合。 

ただし、すべてのペアを合計しているため、バージョンでアクティブな値については$[l, r]$、両方に存在するバージョンのペアの数は次のとおりです。$$\frac{(r-l+1)(r-l+2)}{2}.$$すべてのアクティブな間隔にわたるすべての値の合計寄与度を計算します。 

これらの間隔を取得するために、更新をシミュレートし、各値が表示されたり消えたりするときにそれを維持します。 位置が値から変化するたびに$old$に$new$、間隔を閉じます$old$そして1つを開きます$new$。 

これにより、問題は間隔を追跡し、その長さにわたって 2 次関数を合計することになります。

 | ブルートフォース |$O(m^2 n)$|$O(n)$| 遅すぎる |
 | インターバルトラッキング |$O(n + m)$|$O(n + m)$| 承認済み |

 ## アルゴリズムのチュートリアル

 各値について、その値が展開する配列内に存在する時間セグメントを維持します。 時刻はバージョン番号によってインデックス付けされます。$0$に$m$。 

1. 現在の配列を初期化し、すべての値がバージョン 0 からアクティブであることを記録します。各値の「開始時刻」を保存します。 
2. 各操作ごとに$i$、位置を交換します$p_i$価値のあるもの$v_i$。 以前にその位置を占めていた値は、バージョンでアクティブな間隔を終了します。$i-1$、新しい値はバージョンで新しい間隔を開始します$i$。 

これは正しいです。値は、ある位置を占めている間のみ存在し、区別性が保証されているため、値が同時に 2 回出現することはありません。 
3. すべての操作を処理した後、最終配列にまだ存在する値には、バージョンで終了する間隔が設定されます。$m$。 
4. 記録間隔ごとに$[l, r]$、バージョンペアの数を計算します$(i, j)$と$i \le j$その中に完全に横たわります。 その数は次のとおりです。$$\frac{(r-l+1)(r-l+2)}{2}.$$5. 最終的な答えは、すべての値に対するこれらの寄与の合計に基本変換を適切に乗じたものになります。$2n - |intersection|$効果はすでに導出に吸収されています。 

### なぜ効果があるのか

 各値は各バージョンに存在するか存在しないため、常に 1 つの位置にのみ表示されるため、独立して動作します。 2 つのバージョンの交差は、それらの時間インデックスが同じ値のアクティブな間隔内にあるかどうかによってのみ決まります。 したがって、すべての値は、両方のエンドポイントがその有効期間内にあるバージョンのペアごとに 1 回だけ寄与します。 すべての値を合計すると、重複や二重カウントなしで、すべての配列ペアにわたる合計交差寄与が再構築されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    
    # track current value at each position
    pos_val = a[:]
    
    # when each value became active
    start = {}
    
    # store intervals (l, r) for each value
    intervals = []
    
    # initial values start at version 0
    for v in a:
        start[v] = 0
    
    for i in range(1, m + 1):
        p, v = map(int, input().split())
        p -= 1
        
        old = pos_val[p]
        
        # close old value interval
        intervals.append((old, start[old], i - 1))
        
        # start new value interval
        start[v] = i
        pos_val[p] = v
    
    # close remaining active values
    for v in pos_val:
        intervals.append((v, start[v], m))
    
    ans = 0
    
    # contribution of each interval
    for _, l, r in intervals:
        length = r - l + 1
        ans += length * (length + 1) // 2
    
    print(ans)

if __name__ == "__main__":
    solve()
```このコードは、バージョン間の値の推移をシミュレートし、各値がいつ存在しなくなるかを正確に記録します。 値が置き換えられるたびに、そのアクティブなセグメントが確定されます。 最後に、残りの値がバージョンまで確定されます。$m$。 

二次寄与公式は各区間に直接適用されます。 この実装は、各値が常に 1 つの位置に現れるという事実に依存しているため、時間の経過とともに存在するのは単一の連続セグメントになります。 

微妙な点は、同じ値の間隔を決してマージしないことです。 これは意図的なもので、後で値が再出現したとしても、その間に値が存在しないため、別の存続期間セグメントとして扱う必要があるからです。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、値が導入された直後に置き換えられる場合です。 その状況では、その間隔の長さは 1 であり、最小限の量のみが寄与し、アルゴリズムは単一ポイントの存続期間を正確に記録します。 

値がまったく変更されない場合、別のエッジ ケースが発生します。 次に、すべての初期値には単に間隔があります$[0, m]$となり、貢献度は最大になります。 これらの値に対して「終了イベント」がトリガーされないため、アルゴリズムがこれを処理します。 

3 番目のエッジ ケースは、同じ位置の上書きが繰り返されることです。 それぞれの上書きは、マージせずに 1 つの間隔を閉じ、別の間隔を開きます。各セグメントが個別の連続プレゼンス ウィンドウに対応するため、これが必要です。
