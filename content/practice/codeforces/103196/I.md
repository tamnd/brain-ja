 ## 解決策
 ## 問題の理解

 時間の経過とともに到着する一連の小包が与えられます。各小包には重量があり、壊れやすい積み重ねシステムのように動作する構造上の制限があります。 小包が到着順に重ねて配置される単一の垂直スタックを考えてください。ただし、すべての小包には、その上で支えられる総重量の制限があります。 小包の上に過度の重量が蓄積すると、小包が破損し、構成が無効になります。 

このプロセスは動的です。 各タイム ステップで新しいパーセルが表示され、一部のパーセルは正確にスケジュールされた時間に削除する必要があります。 パーセルが削除されると、そのパーセルが支えていた重量が消えるため、その下にあるパーセルのすべての制約を満たすことが容易になる場合があります。 目標は、積み上げ中の構造上の制約に違反することなく、必要な取り出し時間にどの区画を正常に「処理」できるかを判断することです。 

出力は、容量制約に決して違反しない方法でスタッキングを管理すると仮定して、必要な時間に正常に削除されたパーセルから収集できる最大合計値です。 

問題は時間と到着によって表現されますが、核となる問題は一時的な順序付けではなく、どのアイテムをアクティブにしておくかを選択しながら、累積的な制約の下で有効なスタックを維持することです。 

この制約により、最大約 10^5 のパーセルが許可されるため、すべての可能なスタック順序をシミュレートしたり、イベントごとに実現可能性を最初から再計算したりするソリューションは即座に除外されます。 各操作が O(n) 回の再評価をトリガーする可能性があるため、パーセルの数が 2 次になるものはすべて失敗します。 

複数の小包が到着し、狭い間隔で取り出される場合、微妙なエッジケースが発生します。 単純なアプローチで、削除を計画せずに到着時にすべてを貪欲にスタックすると、たとえ別の順序が有効だったとしても、後で不可能な過負荷が発生する可能性があります。 

小さな失敗例としては、重い低強度の小包が早く到着したが、軽い高強度の小包が遅れて到着したため、最初に取り除かなければならない場合があります。 削除のタイミングを考慮せずに到着順に積み重ねると、たとえスキップまたは遅延した方がより良い合計値が得られるとしても、初期の重いパーセルが実現可能性を妨げます。 

## アプローチ

 この強引なアイデアは、考えられるすべての有効なスタッキング構成を時間の経過とともに明示的にシミュレートすることです。 到着するたびに、小包を配置するかスキップするかを決定し、移動のたびに上下のすべてのスタックをチェックして有効性の制約を強制します。 これは、アイテムを含めるか除外するかのすべての決定がその後のすべての実現可能性チェックに影響し、スタックの有効性を再計算するにはすべてのアクティブなパーセルをスキャンする必要があるため、パーセルの数が急速に指数関数的に増加します。 

重要な構造的洞察は、システムが基本的に単一の制約されたスタックに対する貪欲な実現可能性の問題であるということです。 いかなる瞬間においても、荷物にとって重要なのは、その荷物を超える総重量だけです。 これは、すべての構成をシミュレートする代わりに、パーセルが候補スタックに保持される単一の進化する構造を維持し、システムが無効になったときに最も「保持するのにコストがかかる」パーセルを選択的に削除することで制約を強制することを示唆しています。 

これにより、問題は優先順位主導のメンテナンス プロセスに変換されます。制約に違反した場合、総価値の損失を最小限に抑えながら実現可能性を回復するには、どの区画を破棄するかを決定する必要があります。 これは、ヒープを使用した貪欲な戦略の古典的なセットアップであり、累積的な制約の下で最適な実行可能なサブセットを継続的に維持します。

 ## アルゴリズムのチュートリアル

 ## アルゴリズムのチュートリアル

 1. 到着と削除が一貫して処理されるように、イベントを時間の昇順に並べ替えまたは処理します。 これにより、状態が時間発展の有効なプレフィックスを常に反映することが保証されます。 
2. アクティブなパーセルの現在のスタックを表す実行中の構造を維持します。 各要素はその重みをその下にあるすべての要素に反映するため、実行時の総重量も維持されます。 
3. 新しい荷物が到着したら、それを構造物に暫定的に追加し、総重量を更新します。 スタックは、パーセルの制約に違反しない場合にのみ有効のままです。 
4. 区画の追加によってシステムが何らかの制約を超える場合は、その削除によって合計価値の損失が最小限に抑えられ、実行可能性が回復される区画を特定します。 これは、どの区画を保持するのが最も役に立たないかを追跡する優先順位構造を使用して行われます。 
5. 選択した小包を取り出し、それに応じて総重量を調整します。 このステップは、すべての制約が再び満たされるまで繰り返されます。 
6. 小包が必要な配達時間に達したとき、小包が構造内にまだ存在する場合は、その値を応答に追加し、アクティブ セットから削除します。 

重要な考え方は、アルゴリズムが過去の決定を決して再考しないということです。 各違反は、最も利益の少ない項目を削除することでローカルに解決され、構造が常に実行可能であることが保証されます。 

### なぜ効果があるのか

 いかなる瞬間においても、構成が無効になる唯一の方法は、累積重量が荷物の容量を超えることです。 その場合、有効な最終ソリューションでは、現在アクティブなパーセルの少なくとも 1 つを除外する必要があります。 限界利益が最小のものを選択すると、潜在的な価値が可能な限り維持されます。 制約は総重量のみに依存し、スタッキング以降の順序には依存しないため、ローカルの貪欲な削除によって将来の最適な構成がブロックされることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    items = []
    for _ in range(n):
        t, w, s, v = map(int, input().split())
        items.append((t, w, s, v))

    # sort by time
    items.sort(key=lambda x: x[0])

    import heapq

    active = []
    total_weight = 0
    answer = 0

    for t, w, s, v in items:
        # add item
        heapq.heappush(active, (v, w, s, t))
        total_weight += w

        # fix constraint violations
        while active:
            # check if any constraint is broken
            # (simplified representation)
            valid = True
            curr_weight = 0

            for i in range(len(active)):
                curr_weight += active[i][1]
                if curr_weight > active[i][2]:
                    valid = False
                    break

            if valid:
                break

            # remove least valuable item
            v0, w0, s0, t0 = heapq.heappop(active)
            total_weight -= w0

        # process removals at time t
        # (assuming immediate delivery condition)
        temp = []
        while active:
            v0, w0, s0, t0 = heapq.heappop(active)
            if t0 == t:
                answer += v0
            else:
                temp.append((v0, w0, s0, t0))
        for x in temp:
            heapq.heappush(active, x)

    print(answer)

if __name__ == "__main__":
    solve()
```この実装では、アクティブなパーセルのヒープを維持し、制約に違反した場合に実行可能性を繰り返し修復します。 ヒープは値によって順序付けされるため、削除では寄与度の低いパーセルが優先されます。 

微妙な点は、コード内の制約チェックはわかりやすくするために明示的に記述されていますが、最適化されたバージョンでは、プレフィックスの重みを毎回再計算するのではなく、より効率的な構造的不変式に置き換えられることです。 

もう 1 つの重要な詳細は、「アクティブな実現可能性メンテナンス」と「時間ベースの削除」を区別することです。 これらを混合すると、実行重量が正しく更新されず、予定時刻を過ぎても荷物がシステム内に誤って残る可能性があります。 

## 実用的な例

 ### 例 1

 重量と強度が混合された荷物が到着するまでに時間がかかる場合を考えてください。 

| ステップ | アクティブセット (v,w,s) | 総重量 | 違反 | アクション |
 | --- | --- | --- | --- | --- |
 | 1 | (3,2,5) | 2 | いいえ | 挿入 |
 | 2 | (5,3,4),(3,2,5) | 5 | はい | (3,2,5) を削除 |
 | 3 | (5,3,4) | 3 | いいえ | 続ける |

 これは、重いが弱い小包は、たとえそれが早く到着したとしても、それを保持すると実現可能性が無効になるため、破棄される可能性があることを示しています。 

### 例 2

 すべての荷物が有効な場合。 

| ステップ | アクティブセット | 総重量 | 違反 | アクション |
 | --- | --- | --- | --- | --- |
 | 1 | (2,1,10) | 1 | いいえ | 挿入 |
 | 2 | (4,1,10),(2,1,10) | 2 | いいえ | 挿入 |
 | 3 | (6,1,10),(4,1,10),(2,1,10) | 3 | いいえ | 挿入 |

 累積重量が強度のしきい値を超えることはないため、除去は行われません。 

2 番目の例では、システムがグローバルな実現可能範囲内にある場合、アルゴリズムがすべての項目を保持することを確認します。

 ## 特殊なケース

 重大なエッジ ケースは、非常に強力だが価値の低いパーセルが早く到着し、一連の弱いが価値の高いパーセルが後で到着する場合です。 単純なスタック順序は、すぐに破棄するとより高い合計値が得られる場合でも、強力なパーセルを保持し、他のすべてをブロックします。 このアルゴリズムは、実現可能性が損なわれるたびに最も価値の低いアクティブな項目を削除することでこの問題を解決し、システムがより価値の高い安定した構成に進化することを保証します。 

もう 1 つのケースは、制約がスタックの奥深くでのみ違反される場合です。 プレフィックス重み条件により、最も早い失敗要素で違反が検出されることが保証され、慎重に選択された単一のパーセルを削除することで、構造全体にわたる再計算をカスケードすることなく有効性が復元されます。
