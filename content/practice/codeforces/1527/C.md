 ## 解決策
 ## 問題の理解

 いくつかの配列が与えられ、各配列について考えられるすべての連続した部分配列を考慮します。 各部分配列について、その「重み」を、同じ値を含む配列内の位置のペアの数として定義します。 つまり、選択したセグメント内で、すべてのインデックス ペアを調べ、等しい要素を持つペアがいくつあるかを数えます。 

タスクは、配列のすべての部分配列の合計の重みを計算することです。 各部分配列を個別に評価するのではなく、配列全体に対してこの値を効率的に集計する必要があります。 

制約が非常に厳しいため、サブ配列を明示的に列挙するソリューションはすぐに遅すぎます。 各テスト ケースでは最大 100,000 個の要素が許可され、最大 100,000 個のテスト ケースが存在します。 すべてのテストにわたる合計の長さには制限がありますが、テストごとに 2 次または 2 次に近いアプローチを使用することは不可能です。 どのソリューションも、テスト ケースごとに線形に近いものでなければなりません。 

素朴なアプローチでは、すべての部分配列を生成し、それぞれの中にある等しいペアをカウントします。 これは、次のような非常に小さな入力ではすでに失敗します。`n = 10^5`サブ配列の数は O(n^2) であり、各サブ配列内のペアをカウントすると別の係数が追加されるためです。 

2 番目の一般的な落とし穴は、ペアが異なる部分配列に現れる頻度を正しく考慮せずに、値ごとの寄与を計算しようとすることです。 難しいのは、等しい要素のペアがグローバルに一度だけではなく、両方のエンドポイントを含むすべてのサブ配列に寄与することです。 

## アプローチ

 ブルートフォース戦略は、すべてのサブ配列を反復処理することから始まります。`[l, r]`、その中でペアの数を数えます`(i, j)`満足する`l ≤ i < j ≤ r`そして`a[i] = a[j]`。 これは、入れ子になったループとサブ配列ごとの頻度テーブルによって実行できます。 周波数を維持しながら拡大しても`r`、まだ O(n^2) 個の部分配列があり、更新カウントは O(1) なので、テスト ケースごとに O(n^2) になります。 と`n = 10^5`、これは実現可能な限界をはるかに超えています。 

重要な観察は、視点を反転することです。 最初に部分配列を合計する代わりに、最初に等しい位置のペアを合計します。 2 つのインデックスを取得します`i < j`と`a[i] = a[j]`。 このペアが重みに寄与するサブアレイの数を知りたいと考えています。 

サブ配列は、両方を完全に含む場合にのみ、このペアに寄与します。`i`そして`j`。 つまり、左端点`l`どこからでも構いません`1`に`i`、および適切なエンドポイント`r`どこからでも構いません`j`に`n`。 したがって、このペアは正確に次のように表示されます。`i * (n - j + 1)`サブアレイ。 

ここで問題は、すべての等しいペアにわたるこの寄与を合計することになります。 インデックスを左から右に処理し、各値がこれまでに出現した回数を維持します。 私たちが位置にいるとき`j`、以前のすべての発生`i`同じ価値が貢献する`i * (n - j + 1)`。 値ごとのインデックスの累計を維持することで、これを効率的に蓄積できます。 

これにより、問題はハッシュ マップを使用した単一パスに軽減されます。

 | 最適 | O(n) 償却 | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各値の出現を追跡しながら、配列を左から右に処理します。 各値について、これまでに出現した回数と、以前のインデックスの合計という 2 つの情報を維持します。 
2. 位置に到着したら`j`価値のあるもの`x`、この位置が以前に発生したペアとのペアにどの程度寄与するかを計算したいと考えています。`x`。 以前の各インデックス`i`ペアを形成して貢献する`i * (n - j + 1)`。 
3. これまでのすべてを繰り返す代わりに`i`、保存されているインデックスの合計を使用します。 もし`S[x]`は以前のすべてのポジションの合計です。`x`が表示され、その後の合計貢献度`j`は`S[x] * (n - j + 1)`。 
4. この投稿を回答に追加します。 
5. 次に、保存された状態を更新します。カウントをインクリメントして追加します。`j`合計に`S[x]`。 
6. 配列内のすべての要素に対してこれを繰り返し、合計の答えを累積します。 

### なぜ効果があるのか

 すべての有効なペア`(i, j)`値が等しい場合は、処理時に 1 回だけカウントされます。`j`。 その時点で、アルゴリズムはすでに以前のすべてのポジションを蓄積しています。`i`その価値のために。 このような各ペアは、正確に次のことに貢献します。`i * (n - j + 1)`サブ配列と乗算は、保存された合計を介して正しく集計されます。 各ペアはその右側のエンドポイントに一意に関連付けられるため、二重にカウントしたり省略したりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        # store: value -> (count, sum of indices)
        cnt = {}
        idx_sum = {}
        
        ans = 0
        
        for j, x in enumerate(a, start=1):
            if x in idx_sum:
                ans += idx_sum[x] * (n - j + 1)
                cnt[x] += 1
                idx_sum[x] += j
            else:
                cnt[x] = 1
                idx_sum[x] = j
        
        print(ans)

if __name__ == "__main__":
    solve()
```この実装は、寄与式を明確にするために 1 から始まるインデックスに依存しています。`(n - j + 1)`。 辞書`idx_sum`各値の以前のすべての位置の合計を追跡します。 新しいオカレンスを処理するとき、以前のオカレンスとのペアで完了するサブ配列の数をすぐに計算します。 

微妙な点は、明示的に使用する必要がないことです。`cnt`しかし、それを保持しておくことは、概念的に状態を完成させるのに役立ちます。 正確さは更新にかかっています`idx_sum[x]`現在のインデックスに使用した後。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        idx_sum = {}
        ans = 0
        
        for j, x in enumerate(a, start=1):
            if x in idx_sum:
                ans += idx_sum[x] * (n - j + 1)
                idx_sum[x] += j
            else:
                idx_sum[x] = j
        
        out.append(str(ans))
    
    return "\n".join(out)

# provided samples
assert run("2\n4\n1 2 1 1\n4\n1 2 3 4\n") == "6\n0"

# all equal
assert run("1\n5\n7 7 7 7 7\n") == "50"

# single element
assert run("1\n1\n42\n") == "0"

# alternating duplicates
assert run("1\n6\n1 2 1 2 1 2\n") == "18"

 ## 特殊なケース

 次のようなすべて同一の値の配列の場合、`[7, 7, 7, 7, 7]`、すべての新しい要素は、以前のすべての要素と相互作用します。 位置で`j`、保存された合計は次のように増加します`1 + 2 + ... + (j-1)`、それぞれを乗算します。`(n - j + 1)`。 このアルゴリズムは、サブ配列スパンを見逃すことなく、これらの増大する寄与を正確に蓄積します。 

単一要素の配列の場合、ペアはまったくありません。 ループは 1 回実行され、以前の出現は検出されず、保存されたマップは自明なままになります。 出力はゼロのままで、重みの定義と一致します。 

次のような交互の値の場合`[1, 2, 1, 2, 1, 2]`、各値は独立した発生チェーンを形成します。 この構造により、寄与がキーによって分離され、各ペアが正しいエンドポイントに到達した場合にのみ寄与するため、異なる値間の相互干渉が防止されます。
