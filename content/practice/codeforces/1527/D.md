 ## 問題の理解

 頂点が整数でラベル付けされたツリーがあります。`0`を通して`n - 1`。 個別の頂点の順序のないペアごとに`(u, v)`、それらを結ぶユニークでシンプルなパスに注目します。 そのパス上に現れるラベルは整数のセットを形成し、そのセットの MEX、つまり現れない最小の非負の整数を計算します。 

タスクは、すべての値をカウントすることです`k`から`0`に`n`、パス MEX が等しい頂点ペアの数`k`。 

ラベルは頂点に保存される任意の値ではありません。 頂点のラベルはまさにそのインデックスです。 これが問題の重要な構造的特性です。 

すべてのテスト ケースにわたる頂点の合計数は最大で`2 · 10^5`したがって、テスト ケースごとに線形または線形に近いものより実質的に悪い解決策は不可能です。 ある木`2 · 10^5`頂点には約が含まれます`2 · 10^10`順序のない頂点のペア。パスを列挙するアプローチは直ちに除外されます。 たとえ`O(n²)`アルゴリズムは大まかに実行します`4 · 10^10`最悪の場合の運用。 

この難しさは、パスを反復することなく間接的にカウントすることから生じます。 

ラベルを付けると微妙なエッジケースが表示されます`0`パス上にありません。 すべてのパスが欠落している`0`メキシコメキシコを持っています`0`、他のどのラベルが表示されるかに関係なく。 

例えば：```
0 - 1 - 2
```パス`(1,2)`ラベルが含まれています`{1,2}`そしてMEXを持っています`0`。 

もう 1 つの重要な状況は、頂点にラベルが付いている場合に発生します。`0,1,...,k-1`すべてが 1 つの単純な道に横たわることはできません。 その場合、パスにすべてを同時に含めることはできないため、MEX の答えは次のとおりです。`k`ゼロでなければなりません。 

例えば：```
    0
   / \
  1   2
```3つのラベル`{0,1,2}`一つの単純な道に横たわらないでください。 3 つの頂点すべてを含むパスは存在しないため、すべての頂点が存在することを要求するすべての答えはゼロになります。 

間違いの 3 番目の原因は、MEX の処理です。`n`。 メキシコ向け`n`の場合、パスには次のすべてのラベルが含まれている必要があります。`0`に`n-1`。 ラベルはまさに頂点であるため、そのようなパスはツリーのすべての頂点を訪問する必要があります。 これは、ツリー全体自体が単純なパスである場合にのみ可能です。 

## アプローチ

 ブルート フォース ソリューションでは、順序のない頂点のペアをすべて調べ、それらの間のパスを見つけ、そのパス上のラベルを収集し、その MEX を計算し、対応するカウンターをインクリメントします。 

2 つの頂点間のパスは LCA 前処理を使用して取得できますが、それでも`Θ(n²)`ペア。 と`n = 2 · 10^5`、これは完全に不可能になります。 

重要な点は、MEX 条件が小さなラベルによって定義されていることです。 

パスに MEX があるとします。`k`。 

それから：```
0,1,...,k-1 must all appear on the path
k must not appear on the path
```他には何も関係ありません。 

させて```
S_k = {0,1,...,k-1}
```パスは答えに貢献します`k`すべての頂点が含まれている場合`S_k`頂点を含まない`k`。 

重要な構造上の事実は、頂点のコレクションがすべて 1 つの単純なパスに属することができるのは、それらの頂点がツリーのパス セグメントに含まれている場合のみであるということです。 

定義する`L`そして`R`頂点を含む最小パスの端点として`0..i`。 

増やしながら`i`、私たちはこの道を維持します。 

頂点の場合`i`現在のエンドポイント構造にアタッチできない場合、頂点`0..i`単一の単純なパスには含まれなくなりました。 これが起こると、より大きなセットごとに、`0..j`も失敗し、残りの答えはすべてゼロになります。 

ソリューション全体は、ラベルを含むパスを維持することを中心に展開します。`0..i`次に、すべての頂点を含むパスを生成するエンドポイントのペアの数を数えます。`0..i-1`ただし頂点を除く`i`。 

カウント自体は、現在のパスの周囲のコンポーネントのサイズによって行われます。 

これにより、不可能なパス列挙問題が、動的に成長するパスに沿った一連のローカルなカウント操作に変換されます。

 ## アルゴリズムのチュートリアル

 ### 前処理

 ツリーの頂点をルートにします`0`。 

DFS を使用して次を計算します。 

- すべての頂点の親
 - サブツリーのサイズ
 - オイラーの入口と出口の時間

 オイラー間隔を使用すると、一定時間の祖先チェックが可能になります。 

### 小規模レーベルの路線を維持する

 現在のパスに次のすべてのラベルが含まれるようにします。`0`を通して`i`。 

最初に:```
L = 0
R = 0
```新しいラベルごとに`i`現在のパスを延長できるかどうかを判断します。 

可能性は 3 つだけです。 

1.`i`～からの道沿いにある`L`に`R`。 
2.`i`新しい左端点になることができます。 
3.`i`新しい適切なエンドポイントになる可能性があります。 

これらのどれも当てはまらない場合、頂点`0..i`単純なパスには含まれていません。 より大きな答えはすべてゼロになり、停止します。 

### 必要なラベルをすべて含むパスをカウントする

 頂点を仮定します`0..i-1`パス内に正確に含まれています`(L,R)`。 

ここで、パス全体を含むが頂点を含まないパスをカウントしたいとします。`i`。 

を含む任意のパス`(L,R)`接続されているリージョン内のエンドポイントを 1 つ選択する必要があります`L`そしてその先に接続されたリージョン内の別のエンドポイント`R`。 

有効な選択肢の数は、これら 2 つの領域のサイズの積です。 

これらのサイズは、サブツリー情報と祖先関係を使用して計算されます。 

### 連続する MEX 値間の包含/除外

 しましょう:```
f(i) = number of paths containing all vertices 0..i-1
```それから：```
answer[i] = f(i) - f(i+1)
```パスがカウントされるため、`f(i+1)`まさに頂点も含むものです`i`。 

これにより、頂点の条件が自動的に適用されます。`i`不在でなければなりません。 

### メキシコ 0

 メキシコ向け`0`、頂点を含まないパスが必要です`0`。 

頂点の削除`0`ツリーをコンポーネントに分割します。 

1 つのコンポーネント内に完全にあるパスは回避されます。`0`。 

コンポーネントにサイズがある場合`s`、それは貢献します:```
s(s-1)/2
```順序のない頂点ペア。 

すべてのコンポーネントを合計すると答えが得られます`0`。 

### メキシコ n

 値:```
f(n)
```はすでにすべての頂点を含むパスを表しています。 

これはまさに答えです`n`。 

### なぜ効果があるのか

 あらゆる段階で、維持されるエンドポイント`(L,R)`これまでに処理されたラベルを含む一意の最小パスを記述します。 新しく挿入された各頂点が 1 つのエンドポイントから現在のパスを拡張できる場合に限り、一連の頂点は何らかの単純なパスに属します。 その物件は一度故障すると二度と回復することができません。 

固定の場合`i`、ラベルを含むすべてのパス`0..i-1`最小パス全体を含める必要があります`(L,R)`。 このようなパスは、過去に広がる領域から 1 つのエンドポイントを選択することによって一意に決定されます。`L`そしてもう1つは過去に広がる地域から`R`。 これらの領域サイズを乗算すると、すべての有効なパスが 1 回だけカウントされます。 

メキシコ以来`i`含むことが必要です`0..i-1`そして除外する`i`、連続するカウントを減算すると、正確に希望の数量が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n = int(input())

        g = [[] for _ in range(n)]
        for _ in range(n - 1):
            u, v = map(int, input().split())
            g[u].append(v)
            g[v].append(u)

        parent = [-1] * n
        tin = [0] * n
        tout = [0] * n
        sz = [0] * n

        timer = 0

        stack = [(0, -1, 0)]
        while stack:
            v, p, state = stack.pop()

            if state == 0:
                parent[v] = p
                tin[v] = timer
                timer += 1

                stack.append((v, p, 1))
                for to in reversed(g[v]):
                    if to != p:
                        stack.append((to, v, 0))
            else:
                s = 1
                for to in g[v]:
                    if to != p:
                        s += sz[to]
                sz[v] = s
                tout[v] = timer

        def is_ancestor(a, b):
            return tin[a] <= tin[b] < tout[a]

        def on_path(x, a, b):
            return (
                is_ancestor(x, a) and is_ancestor(b, x)
            ) or (
                is_ancestor(x, b) and is_ancestor(a, x)
            )

        ans = [0] * (n + 1)

        total_pairs = n * (n - 1) // 2

        bad = 0
        for to in g[0]:
            if parent[to] == 0:
                s = sz[to]
            else:
                s = n - sz[0]
            bad += s * (s - 1) // 2

        ans[0] = bad

        f = [0] * (n + 1)

        L = 0
        R = 0

        def side_size(end, other):
            if is_ancestor(end, other):
                cur = other
                while parent[cur] != end:
                    cur = parent[cur]
                return n - sz[cur]
            return sz[end]

        f[1] = total_pairs

        alive = True

        for x in range(1, n):
            if not alive:
                break

            in_lr = on_path(x, L, R)
            in_lx = on_path(R, L, x)
            in_rx = on_path(L, R, x)

            if in_lr:
                pass
            elif in_lx:
                L = x
            elif in_rx:
                R = x
            else:
                alive = False
                break

            left_cnt = side_size(L, R)
            right_cnt = side_size(R, L)

            f[x + 1] = left_cnt * right_cnt

        for i in range(1, n):
            ans[i] = f[i] - f[i + 1]

        ans[n] = f[n]

        print(*ans)

solve()
```DFS は、親ポインター、サブツリーのサイズ、およびオイラー タイムスタンプを計算します。 これらは、後で必要になる唯一の構造データです。 

機能`is_ancestor`オイラー区間を使用します。 頂点`a`の先祖です`b`ちょうど、オイラーエントリー時刻が`a`の入場時間が含まれています`b`。 

維持されたペア`(L,R)`は、処理されたすべてのラベルを含む最小パスを表します。 新しいラベルが到着したとき、考えられる幾何学的関係は 3 つだけです。 どれも機能しない場合は、必要な頂点が単一のパスに収まらなくなり、以降のすべてのカウントがゼロになります。 

ヘルパーさん`side_size`パスの片側を越えて伸びる終点として機能する頂点の数を計算します。 式は、反対側のエンドポイントが現在のエンドポイントのサブツリー内にあるかどうかによって異なります。 

配列`f`しきい値より小さいすべてのラベルを含むパスの数を保存します。 連続した差により、正確な MEX 周波数が生成されます。 

よくある実装上の間違いは、次のことを忘れることです。`answer[0]`異なるカウント規則に従います。 メキシコ`0`パスは頂点を避ける必要があることを意味します`0`、頂点を削除することで最も自然にカウントされます。`0`そして、結果として得られる各コンポーネント内のペアを合計します。
