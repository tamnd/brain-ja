 ## 解決策
 ## 問題の理解

 バイナリ文字列と、それを交互に変更する 2 人のプレイヤー、アリスとボブが与えられます。 

移動によって、単一の変更が行われる可能性があります。`'0'`の中へ`'1'`1 ドルのコストで、または文字列全体を無料で反転できます。 反転は、現在の文字列が回文ではない場合にのみ使用でき、2 つの反転を連続して行うことはできません。 

すべてのキャラクターがそうなるとゲームは終了します`'1'`。 勝者は誰が最後の手を打つかによって決まりません。 代わりに、各プレーヤーが個人的に費やしたドルを蓄積し、合計コストがより少ないプレーヤーが勝ちます。 コストが等しいと引き分けが発生します。 

文字列の長さは最大 1000 で、テスト ケースの数は最大 1000 です。 長さの合計は十分に小さいため、テスト ケースごとの線形スキャンは簡単です。 課題は計算の複雑さではなく、ゲーム理論の構造を発見することです。 

いくつかの状況は驚くほど微妙です。 

考慮する：```
n = 3
s = 010
```この文字列はすでに回文になっており、中央にゼロが 1 つだけ含まれています。 アリスはそれを裏返して 1 ドルを使わなければなりません。 ボブは何も使いません。 結果は次のとおりです。```
BOB
```「奇数のゼロはアリスの勝ちを意味する」などの単純なルールはすぐに失敗します。 

もう 1 つの重要なケースは次のとおりです。```
n = 5
s = 00100
```これは 3 つのゼロがあり、そのうちの 1 つが中央にある回文です。 答えは次のとおりです。```
ALICE
```これは、アリスに有利な独特の特別な回文の位置です。 奇数のゼロを含むすべての回文を同じように扱うと、間違った結果が得られます。 

3 番目のトラップは、最初の文字列が回文ではない場合に表示されます。```
n = 4
s = 1010
```答えは次のとおりです。```
ALICE
```反転しても文字列の内容は変わりませんが、フリー反転でターンをパスできるとバランスが完全に変わります。 ゼロのみをカウントし、文字列が現在回文であるかどうかを無視する解決策は失敗します。 

## アプローチ

 最も直接的なアプローチは、ゲームを状態グラフとしてモデル化することです。 状態には、現在の文字列、その順番、および前の動きが逆転であったかどうかが含まれます。 各州からすべての合法的な動きを列挙し、ミニマックス検索を実行できます。 

ゲームは有限であるため、これは概念的に機能します。 支払われるたびにゼロの数が減り、最終的にゲームは終了します。 残念なことに、状態空間は指数関数的に増大します。 長さ 1000 の文字列にはすでに天文学的な数の可能な構成があり、明示的なゲーム検索は不可能です。 

重要な点は、ほとんどのビットの実際の配置は問題ではないということです。 重要なのは、不一致のミラーリングされたペアがいくつ存在するか、およびゼロがいくつ残っているかです。 

以下を定義しましょう:`diff`= ペアの数`(i, n-1-i)`登場人物が違うところ。 

もし`diff > 0`、文字列は回文ではありません。 

不一致のペアは、一致したペアとはまったく異なる動作をします。 プレイヤーが不一致ペア内のゼロを修正すると、同時に不一致の数が減り、ゼロが 1 つ消費されます。 反転は不一致が存在する場合にのみ意味を持ちます。 

この試合の公式分析では、すべてのポジションがいくつかのカテゴリーに分類されることが示されています。 最適なプレイのトランジションを実行すると、結果は非常にシンプルになります。 

非回文の場合:

 文字列全体に不一致のペアが 1 つだけ、ゼロが 2 つだけ存在する場合、ゲームは引き分けになります。 

回文以外の他のすべての位置はアリスの勝ちです。 

回文の場合:

 しましょう`z`ゼロの数になります。 

もし`z == 1`、ボブが勝ちます。 

もし`z`が等しい場合、ボブが勝ちます。 

もし`z`が奇数である場合、アリスは中心がゼロである特別な構成でのみ勝ちます。`z == 3`。 そうでなければボブが勝ちます。 

これらのケースは、コンテストの提出で使用される標準ソリューションを使用してさらにコンパクトに表現できます。

 ## アルゴリズムのチュートリアル

 各テスト ケースについて:

 1. ゼロの数を数えます。`z`。 
2. 不一致のミラーリングペアの数を数えます。`diff`。 
3. もし`diff == 0`、文字列は回文です。 回文のケースを処理します。 
4. 回文にゼロが 1 つだけ含まれている場合は、戻り値を返します。`"BOB"`。 
5. 回文に奇数のゼロとちょうど 3 つのゼロが含まれており、中央の文字が`'0'`、 戻る`"ALICE"`。 

これは、アリスが真の利点を得る唯一の回文位置です。 
6. 回文に奇数のゼロが含まれている場合は、戻り値を返します。`"ALICE"`。 
7. それ以外の場合は戻る`"BOB"`。 
8. もし`diff > 0`、文字列は回文ではありません。 
9. もし`diff == 1`、ゼロの合計数が 2 で、中心位置にゼロが含まれている場合、戻り値`"DRAW"`。 

ハード版特有の描画位置です。 
10. それ以外の場合は戻る`"ALICE"`。 

### なぜ効果があるのか

 ゲームは、誰がドルを費やすことを強制されるかを中心に展開します。 リバーサルは、文字列が回文でない場合にのみ存在する自由な動きです。 不一致が存在する場合、アリスは反転を利用して支出の圧力をボブに移すことができます。 

ゲーム全体の分析では、均等な支出につながる 1 つの対称構成を除いて、すべての非回文状態がアリスにとって有利であることが示されています。 この構成は、中央のゼロと 1 つの不一致のペアで構成され、全体でちょうど 2 つのゼロが生成されます。 

回文の場合、最初は逆転が利用できないため、ゲームは残りのゼロを誰が支払うかを決定することになります。 残りのゼロカウントのパリティが主に結果を決定しますが、有名な中央の 3 ゼロの場合は、アリスに追加の利点を与える唯一の例外です。 

これらの分類は網羅的であり、相互に排他的であるため、すべてのポジションは、実績のある 1 つの成果カテゴリに正確に分類されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n = int(input())
        s = input().strip()

        zeros = s.count('0')

        diff = 0
        for i in range(n // 2):
            if s[i] != s[n - 1 - i]:
                diff += 1

        if diff == 0:
            if zeros == 1:
                print("BOB")
            elif zeros % 2 == 1:
                print("ALICE")
            else:
                print("BOB")
        else:
            if diff == 1 and zeros == 2 and n % 2 == 1 and s[n // 2] == '0':
                print("DRAW")
            else:
                print("ALICE")

if __name__ == "__main__":
    solve()
```実装は分類に直接従います。 

最初のループでは、一致しないミラーリングされたペアをカウントします。 これは、現在位置が回文であるかどうか、および非対称ペアがいくつ存在するかを判断するのに十分です。 

回文の枝は驚くほど短いです。 ゼロが 1 つ残っている場合は、アリスがすぐに料金を支払わなければならないことを意味し、ボブの総コストが安くなります。 ゼロの数が奇数の場合はアリスが有利になり、偶数の場合はボブが有利になります。 

非回文ブランチには、1 つの特別な描画条件が含まれています。 その状態のすべての要素が重要です。 不一致のペアが 1 つ、合計で 2 つのゼロ、奇数の長さ、中央の 0 が必要です。 一部のパーツが欠けていると、他のアリスの勝ちポジションが引き分けとして誤ってラベル付けされます。 

再帰、動的プログラミング、シミュレーションは必要ありません。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline
    t = int(input())

    ans = []

    for _ in range(t):
        n = int(input())
        s = input().strip()

        zeros = s.count('0')

        diff = 0
        for i in range(n // 2):
            if s[i] != s[n - 1 - i]:
                diff += 1

        if diff == 0:
            if zeros == 1:
                ans.append("BOB")
            elif zeros % 2 == 1:
                ans.append("ALICE")
            else:
                ans.append("BOB")
        else:
            if diff == 1 and zeros == 2 and n % 2 == 1 and s[n // 2] == '0':
                ans.append("DRAW")
            else:
                ans.append("ALICE")

    sys.stdout.write("\n".join(ans))

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out

# provided sample
assert run("3\n3\n110\n2\n00\n4\n1010\n") == "ALICE\nBOB\nALICE"

# minimum size
assert run("1\n1\n0\n") == "BOB"

# special draw state
assert run("1\n3\n100\n") == "DRAW"

# odd palindrome with three zeros
assert run("1\n3\n000\n") == "ALICE"

# even-zero palindrome
assert run("1\n5\n00100\n") == "BOB"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1, "0"`|`BOB`| 可能な最小のインスタンス |
 |`3, "100"`|`DRAW`| 独自のハード バージョンの描画状態 |
 |`3, "000"`|`ALICE`| 奇数ゼロの回文 |
 |`5, "00100"`|`BOB`| 偶数ゼロ回文分類 |
