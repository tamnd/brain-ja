 ## 解決策
 ## 問題の理解

 同じ長さの 2 つの文字列が与えられています。 1 つの文字列 (これを参照文字列と呼びます) は、パターンのコレクションを定義します。この文字列のすべてのプレフィックスはパターンであり、各パターンには関連する重みがあります。 2 番目の文字列はクエリ文字列で、その部分文字列を繰り返し取得します。 

任意の部分文字列について、参照文字列の各プレフィックスがその部分文字列内に出現する頻度に応じてスコアを計算したいとします。 長さ i の接頭辞がクエリ ウィンドウ内の部分文字列として現れるたびに、答えに wi を追加します。 

したがって、問題は、2 番目の文字列に対する多くの範囲クエリに答えることになります。各クエリは、2 番目の文字列の部分文字列内にある最初の文字列のすべてのプレフィックスの重み付けされた出現回数の合計を要求します。 

制約が十分に大きいため、各クエリに対して各プレフィックスを個別にチェックするソリューションは失敗します。 n と m が最大 150,000 の場合、クエリごとの単純な O(n) では、最悪のケースですでに約 2.25e10 の操作が発生し、これは実現可能性をはるかに超えています。 

主要な構造上の問題は、プレフィックスの出現が大きく重複しており、各クエリが部分文字列であるため、パターン マッチを最初から再計算するのは無駄であることです。 

単純なアプローチが微妙に失敗するケースは、テキスト内で多くの接頭辞が大幅に重複している場合に発生します。 たとえば、S が「aaaaa」の場合、すべてのプレフィックスも「a」、「aa」、「aaa」などになり、T もすべて「a」になります。 このような場合、出来事は組み合わせ的に爆発的に発生します。 一致を明示的に列挙するメソッドは、ローカルで慎重に最適化したとしても、作業量を過剰にカウントしてタイムアウトになります。 

もう 1 つのエッジ ケースは、クエリが文字列のほぼ全体をカバーする場合です。 その後、クエリごとの前処理は、完全な一致構造を繰り返し再計算することと同等になり、再び二次動作に退化します。 

## アプローチ

 ブルートフォースのアイデアは単純です。 各クエリ部分文字列 T[l, r] について、S のすべてのプレフィックス pre_i を反復処理し、それが T[l, r] に出現する回数を数えます。 位置ごとの部分文字列の直接比較では、クエリごとに O(n) 位置にわたる O(n) パターン、つまりクエリごとに O(n^2) をチェックすることになります。 文字列比較のトリックを使用して部分文字列の一致を最適化したとしても、m 個のクエリにわたって繰り返しスキャンするのは依然として法外な作業です。 

重要な点は、すべてのパターンが同じ文字列のプレフィックスであるということです。 これは、それらが任意の文字列ではなく、S のプレフィックス ツリー内の単一のルートからノードへのパス上に存在することを意味します。各プレフィックスを個別に扱う代わりに、S をトライ パスとして扱うか、S のプレフィックス関数オートマトンを同等に使用できます。 

ここで、クエリ文字列 T を 1 回スキャンすることを考えてみましょう。 スキャン中に、各位置で終了する S の各プレフィックスが何回出現するかを維持できます。 これは、S に対して KMP オートマトンを使用することを示唆しています。S の接頭辞関数を構築し、S と T のマッチングをシミュレートし、各位置での最長の接頭辞一致を追跡します。 

ただし、S の完全一致だけではなく、すべてのプレフィックスのカウントも同時に必要です。 ここで、KMP 障害リンクの構造が役立ちます。状態に到達するたびに、それは S のプレフィックスでもあるサフィックスを暗黙的に表します。各状態はプレフィックスの長さに対応し、状態 x に到達すると、長さ x のプレフィックスがこの位置で終了することを意味します。 したがって、すべての位置は、x から下方の障害チェーンに沿ったすべてのプレフィックスに +1 を与えます。 

位置ごとに失敗の連鎖を辿ることを避けるために、プロセスを逆にします。 T の各位置を単一のプレフィックス長状態に +1 寄与するものとして扱い、次にプレフィックス関数ツリーの差分構造を使用して位置全体の寄与を集計します。 最後に、各状態のプレフィックス頻度を計算します。

すべてのプレフィックス長 i について、T 内で pre_i が何回出現するかがわかったら、やはり部分文字列に対する範囲クエリが必要になります。 部分文字列クエリを効率的にサポートするために、各状態が発生する位置を前処理し、T にわたるプレフィックスの合計を構築します。グローバル カウントの代わりに、概念的には配列 cnt[i][pos] を構築しますが、これは、出現の補助配列と位置にわたるプレフィックスの合計を使用したシングル パスを使用して実装されます。 

最後に、各クエリ [l, r] は、範囲内に完全にある pre_i の出現を乗じた wi の i の合計になります。これは、状態ごとに事前に計算された接頭辞合計配列、または終了位置によってインデックス付けされた平坦化された寄与配列を使用して答えることができます。 

最終ステップを確認するためのより明確な方法は、役割を逆にすることです。T の位置 j ごとに、どのプレフィックスの長さが j で終わるかが分かります。 重みの寄与を wi から j に分配するので、各位置は、そこで終わるすべての一致したプレフィックスからの寄与を累積します。 この場合、各クエリは単にこの寄与配列の範囲の合計になります。 

これにより、問題は KMP オートマトンの構築と T にわたる寄与の蓄積の維持に軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2m) | お(1) | 遅すぎる |
 | KMP + プレフィックス集約 | O(n + m) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 S をその接頭辞関数を使用してパターン オートマトンとして扱い、T を通じて一致を伝播します。 

1. S のプレフィックス関数配列を構築します。これにより、すべてのプレフィックスの長さに対して、サフィックスでもある次に長い適切なプレフィックスが定義されます。 
2. KMP オートマトンを使用してスキャン T をシミュレートします。 各位置 j で、j で終わるサフィックスと一致する S の最長のプレフィックスである状態 cur を維持します。 
3. 位置 j で状態 cur に到達すると、長さ cur の接頭辞が j で終わることがわかります。 障害リンクに沿ったすべてのプレフィックスの寄与を直接追加する代わりに、単一のイベントを記録します。位置 j がプレフィックス長 cur に寄与します。 
4. すべてのプレフィックスの発生を考慮して、障害リンク構造を通じてカウントを伝播します。 状態を長さの降順に処理し、状態から障害リンクにカウントをプッシュします。 これにより、長いプレフィックスが発生した場合、その短いプレフィックス サフィックスもすべてカウントされるようになります。 
5. 伝播後、長さ i のプレフィックスが完全な文字列 T 内に任意の場所で終わる部分文字列として出現する回数である occ[i] を取得します。 
6. 次に、これらの発生を位置ベースの貢献に変換します。 T の各位置 j について、その現在のオートマトン状態 cur[j] がわかります。 w[cur[j]] をグローバル寄与配列の位置 j に追加します。 
7. この寄与配列に対してプレフィックスの合計を構築します。 各クエリ [l, r] は、プレフィックスの合計を減算することによって回答されます。 

これが機能する理由は、各位置のオートマトンの状態がそこで終わる S の最長のプレフィックスを一意に識別し、障害リンクにより、すべての短いプレフィックスの出現が伝播を通じて 1 回だけ正確に考慮されることが保証されるという事実から来ています。 次に、寄与配列は、元の二重和の位置ごとの分解を T の位置にわたる独立した加算寄与にエンコードし、範囲クエリにプレフィックス和で答えることができるようにします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_kmp(s):
    n = len(s)
    pi = [0] * n
    j = 0
    for i in range(1, n):
        while j and s[i] != s[j]:
            j = pi[j - 1]
        if s[i] == s[j]:
            j += 1
        pi[i] = j
    return pi

def solve():
    n, m = map(int, input().split())
    S = input().strip()
    T = input().strip()
    w = list(map(int, input().split()))

    pi = build_kmp(S)

    occ = [0] * (n + 1)
    cur = 0

    for ch in T:
        while cur and (cur < n) and S[cur] != ch:
            cur = pi[cur - 1]
        if cur < n and S[cur] == ch:
            cur += 1
        occ[cur] += 1
        if cur == n:
            cur = pi[n - 1]

    for i in range(n, 0, -1):
        occ[pi[i - 1]] += occ[i]

    end_count = [0] * n
    cur = 0
    for ch in T:
        while cur and (cur < n) and S[cur] != ch:
            cur = pi[cur - 1]
        if cur < n and S[cur] == ch:
            cur += 1
        end_count[cur - 1] += 1 if cur > 0 else 0
        if cur == n:
            cur = pi[n - 1]

    contrib = [0] * n
    for i in range(n):
        contrib[i] = end_count[i] * w[i]

    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + contrib[i]

    out = []
    for _ in range(m):
        l, r = map(int, input().split())
        out.append(str(pref[r] - pref[l - 1]))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このソリューションは、S に対して KMP 障害構造を構築し、次に T をストリームとして処理して、各プレフィックス状態に到達する頻度を計算します。 2 番目のパスは、各位置で各プレフィックスが何回終わるかを正確にカウントするために必要です。 最後の寄与配列は、プレフィックスレベルの重みを位置レベルの重みに変換し、クエリの単純なプレフィックス合計を可能にします。 

微妙な点は、オートマトンが完全な一致長 n に達したときの遷移の処理です。 連続性を失わずに重複一致を許可するために、障害リンク状態にリセットします。

 ## 特殊なケース

 S = "a"、T = "a" のような最小限の文字列の場合は、オートマトンが単一の接頭辞の出現を正しくカウントするかどうか、および接頭辞の合計変換によって off-by-one エラーが発生しないかどうかをテストします。 計算全体は、w1 に 1 回だけ寄与する単一の状態に還元され、範囲クエリはその値を返します。 

S = "aaaaa" や T = "aaaaa" のような完全に繰り返しの文字列は、障害リンクの伝播を強調します。 すべての位置で複数のプレフィックス一致が同時に終了し、アルゴリズムは障害チェーンを通じて伝播するときにカウントが重複しないことを保証する必要があります。 occ 配列の累積により、各プレフィックス長が終了位置ごとに 1 回正確にカウントされることが保証されます。 

S = "abc" および T = "zzz" のような一致しないケースでは、KMP オートマトンが正しくリセットされ、古い状態が寄与配列に漏れないことが保証されます。 プレフィックス関数は繰り返しゼロに戻るため、すべての寄与はゼロのままであり、プレフィックスの合計は安定したままになります。
