 ## 解決策
 ## 問題の理解

 私たちは、すべての格子点が最初は同じデフォルト文字を持つ無限の 2D 整数グリッドに取り組んでいます。`"."`。 次に、このグリッドの領域を新しい文字で上書きする一連のペイント操作が与えられます。 更新には 2 つのタイプがあります。1 つは円内のすべての整数点を描画するもの、もう 1 つは軸に沿った長方形内のすべての整数点を描画するものです。 3 番目のタイプの操作では、以前のすべてのペイント効果が順番に適用された後、グリッドの有限サブ長方形を出力するように求められます。 

重要な解釈は、各操作が順番に適用され、前の色が上書きされるということです。 複数の形状が重なっている場合、後の操作により、影響を受ける点で前の色が完全に置き換えられます。 レンダリング クエリは、以前のすべての更新を適用した後の、境界領域の最終状態を単純に要求します。 

座標範囲は非常に大きく、最大 10^9 の大きさであるため、グリッドを明示的にシミュレートすることはできません。 ただし、すべてのレンダリング クエリの合計領域は小さく、合計で最大でも 10^4 です。 これは、実際のグリッド セルを実体化する必要がある入力の唯一の部分です。 他のすべての操作は、巨大な座標空間にわたって幾何学的に定義されます。 

単純な間違いは、すべての円または四角形の影響を受けるすべての点を反復しようとすることです。 最大 10^9 の半径の円には最大 10^18 の整数点が含まれる可能性があるため、単一の演算であっても明示的に展開することは不可能です。 もう 1 つの微妙な間違いは、操作順序を注意深く考慮せずにレンダー クエリを直接更新することです。 操作は以前の操作を上書きするため、最終的な色は、交差する操作の数ではなく、最新のカバー操作に完全に依存します。 

重要なエッジケースは、異なる形状の更新が重複していることです。 たとえば、長方形ペイントの後にレンダリング領域と部分的に重なる円ペイントが続く場合は、円がその領域内の長方形を完全にオーバーライドする必要があります。 順序を考慮せずに単一の最終グリッドを事前計算するアプローチは失敗します。 

## アプローチ

 ブルートフォースのアイデアは概念上単純です。ペイントされたすべてのポイントの辞書またはグリッド マップを維持します。 円または四角形の操作ごとに、その幾何学的領域内のすべての整数点を反復処理し、指定された色を割り当てます。 レンダリング クエリが到着すると、要求された領域を反復処理して、保存されている値を出力するか、`"."`未塗装の場合。 

これは問題定義を直接シミュレートするため、これは正しいです。 問題はランタイムです。 長方形は 2・10^18 の領域まで大きくなり、レンダリング領域は小さいにもかかわらず、更新が完全に支配します。 radius-r ディスク内のすべての整数点をチェックするのは O(r^2) であるため、円を拡張する場合はさらに悪いことになります。 最大 2000 回の操作では、これは完全に不可能です。 

重要な点は、グリッド全体を明示的にシミュレートする必要がないということです。 クエリを実行するのは小さな領域のみであり、それらの点の最終的な色のみが必要です。 形状をグローバルに拡張する代わりに、視点を逆にします。レンダリング クエリごとに、操作を逆の順序でチェックすることによって、要求された各ポイントの色を独立して直接計算します。 

固定点 (x, y) の場合、その最終的な色は、それをカバーする最後の操作によって決まります。 したがって、操作を逆方向にスキャンし、その点を示す操作が見つかったらすぐに停止します。 最大で合計 10^4 の合計クエリ ポイントのみを評価し、最大で 2000 の操作があるため、これにより、2×10^7 の幾何学的チェックという管理可能な上限が得られます。 

各チェックは定数時間です。長方形の包含は単純な不等式であり、円の包含は二乗距離のチェックです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースグリッドシミュレーション | O(総塗装面積) | O(グリッド) | 遅すぎる |
 | クエリごとの評価を逆にする | O(n · q) ただし、q ≤ 10^4 | O(1) おまけ | 承認済み |

 ## アルゴリズムのチュートリアル

 操作を一度処理して保存し、各レンダリング クエリに個別に応答します。 

1. すべての操作を読み取り、順番にリストに保存します。 レンダリングには最終状態のクエリが必要であり、後の操作で以前の操作がオーバーライドされる可能性があるため、これらをすぐに適用しようとはしません。 
2. レンダリング操作が発生すると、その長方形領域を点のリストに拡張します。 すべてのレンダリング領域の合計は最大 10^4 であるため、この拡張は安全です。 
3. レンダリング領域内の各ポイントについて、最後の操作から最初の操作まで逆方向に操作リストをスキャンします。 
4. 各操作について、現在のポイントをカバーしているかどうかを確認します。 

長方形の場合、x1 ≤ x ≤ x2 および y1 ≤ y ≤ y2 かどうかを確認します。 

円の場合、(x - cx)^2 + (y - cy)^2 ≤ r^2 かどうかを確認します。 
5. ポイントをカバーする逆の順序で見つかった最初の操作が、その最終的な色を決定します。 その文字を割り当て、その点のさらなるスキャンを停止します。 
6. ポイントをカバーする操作がない場合は、次のように出力します。`"."`。 

逆方向にスキャンする理由は、後の操作で以前の操作が上書きされるためです。 これにより、逆方向で最初に一致したものが、正確に最後に適用されたペイントであることが保証されます。 

### なぜ効果があるのか

 どの固定グリッド点でも、その最終的な色は、それを含む最新の操作にのみ依存します。 操作は順番に適用され、以前の値が上書きされるため、ペイント プロセスではセルごとに最後の書き込み者優先のルールが導入されます。 逆の順序でスキャン操作を行うと、最後のライターが直接再構築されます。 各ポイントは独立して評価されるため、グローバルな状態は必要ありません。正確性は、操作がそのポイントに影響を与えるかどうかを幾何学的包含チェックが正確に一致させるという事実から得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

ops = []
renders = []

n = int(input())
for _ in range(n):
    parts = input().split()
    if parts[0] == "Circle":
        x, y, r = map(int, parts[1:4])
        col = parts[4]
        ops.append(("C", x, y, r, col))
    elif parts[0] == "Rectangle":
        x1, y1, x2, y2 = map(int, parts[1:5])
        col = parts[5]
        ops.append(("R", x1, y1, x2, y2, col))
    else:
        x1, y1, x2, y2 = map(int, parts[1:5])
        renders.append((x1, y1, x2, y2))

out_lines = []

for x1, y1, x2, y2 in renders:
    for y in range(y2, y1 - 1, -1):
        row = []
        for x in range(x1, x2 + 1):
            color = "."
            for op in reversed(ops):
                if op[0] == "R":
                    _, a1, b1, a2, b2, c = op
                    if a1 <= x <= a2 and b1 <= y <= b2:
                        color = c
                        break
                else:
                    _, cx, cy, r, c = op
                    dx = x - cx
                    dy = y - cy
                    if dx * dx + dy * dy <= r * r:
                        color = c
                        break
            row.append(color)
        out_lines.append("".join(row))

sys.stdout.write("\n".join(out_lines))
```このソリューションはすべての操作をリストに保持し、レンダリングするまで評価を遅らせます。 レンダリングされた各セルは、独立して操作を逆方向にスキャンします。 出力はセルごとに明示的に必要であるため、レンダリング領域にわたるネストされたループが必要ですが、制約により、この合計作業量は少なく抑えられます。 

微妙な詳細は、問題では y2 から y1 まで出力する必要があるため、出力内の y に対する逆反復です。 この方向は、必要な視覚的方向を一致させるために重要です。 

円チェックでは二乗距離を使用して浮動小数点演算を回避し、整数演算の正確性を保証します。

 | --- | --- | --- | --- |

 ## 特殊なケース

 微妙なエッジ ケースは、レンダリング領域に、いかなる操作の影響も受けないポイントが含まれる場合です。 その場合、すべての操作をスキャンしても一致は見つからず、出力はそのまま残される必要があります。`"."`。 たとえば、遠くにある長方形だけをペイントして原点をレンダリングする場合、すべての点はそのままになるはずです。`"."`。 逆スキャンは色を割り当てずにすべての操作を実行するため、これを正しく処理します。 

もう 1 つのエッジ ケースは、円がその境界上の点にかろうじて接触する場合です。 状態も含めてなので`(u-x)^2 + (v-y)^2 <= r^2`、境界点には色を付ける必要があります。 整数の二乗距離チェックにより、浮動小数点エラーなしで正確に包含されることが保証されます。 

最後のエッジ ケースは、長方形と円が重なっている場合で、円は後で適用されますが、レンダリング領域と部分的にしか重なりません。 各セルは独立して操作を逆にチェックするため、影響を受けるセルのサブセットのみが円の色を選択し、他のセルは以前の操作またはデフォルトによって決定されたままになります。`"."`。
