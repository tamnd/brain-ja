 ## 解決策
 ## 問題の理解

 一連のコンテストから得られる幸福を表す一連の値が与えられます。 各コンテストの後、過去のすべてのコンテストに依存する「記憶重視のムード」を計算したいと考えていますが、古いイベントの影響力は指数関数的に減少します。 最新のコンテストは全額貢献し、前のコンテストは半分、その前のコンテストは 4 分の 1 になります。 

正式には、i 番目のコンテストの後、ムードは、a[j] の重みが 2^(j-i) である、以前のすべての値の重み付き合計になります。 これにより、最近の値が支配的になりますが、以前の値は指数関数的に減衰します。 配列の各プレフィックスについて、この加重合計の符号 (正、負、または正確にゼロ) のみを決定する必要があります。 

キーの制約は n が最大 100,000 であり、これにより、すべてのプレフィックスについて加重合計を最初から再計算することが直ちに除外されます。 直接プレフィックス評価には O(n^2) のコストがかかりますが、これは 1 秒間に許可される操作をはるかに超えています。 O(n) または O(n log n) メソッドが必要です。 

微妙な問題は、重みが 2 の分数乗であることです。これは、値が通常の意味での整数の累積ではないことを意味します。 すべてを 2 のべき乗で乗算しようとする単純な試みは、不注意に扱うとオーバーフローや精度の低下につながる可能性があります。 もう 1 つの落とし穴は浮動小数点の使用です。これは、2 による除算を繰り返すと丸め誤差が蓄積し、大きな入力に対して符号が誤って反転する可能性があるためです。 

## アプローチ

 ブルート フォース ソリューションでは、すべてのプレフィックスの加重合計が再計算されます。 各 i について、すべての j ≤ i を重み 2^(j-i) で合計します。 これにはプレフィックスごとに O(i) の作業が必要となり、合計操作数は O(n^2) になります。 n = 100,000 の場合、これは約 10^10 の加算となり、これは実行不可能です。 

式の構造は再発を示唆しています。 S[i] を i 回のコンテスト後の気分として表す場合、i-1 から i に移動すると、以前のすべての寄与が 1/2 倍シフトされ、新しい値 a[i] が追加されます。 これにより、きれいな移行が作成されます。以前の記憶は半分に減衰し、その後、新しいイベントが最大強度で追加されます。 

この観察により、問題は、各ステップが前の状態に線形変換を適用する実行値の維持に変わります。 以前のすべての要素の寄与を再計算する代わりに、以前の集計結果を再利用し、一定時間で更新します。 

残る唯一の懸念は数値の安定性です。 すべての演算は線形であり、半分と加算だけが含まれるため、正確な値は、十分な精度の浮動小数点演算を使用して安全に追跡するか、繰り返しのスケーリングに基づく有理数に似た累積トリックを使用してより堅牢に追跡できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | ブルートフォース | O(n^2) | お(1) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 各プレフィックスを処理した後の気分を表す実行値を維持します。 この値は常に、問題で定義された加重合計に正確に対応します。 

1. 変数を初期化する`cur = 0`、コンテストが処理される前の雰囲気を表します。 履歴がまだ存在しないため、これはゼロから始まります。 
2. 配列を左から右に繰り返します。 各ステップ i で、以前のすべての貢献をさらに 1 ステップ過去にシフトする効果を組み込みたいと考えています。これにより、その影響は半分に減ります。 
3. 変換を適用して実行値を更新します。`cur = cur / 2 + a[i]`。 2 で割ることは、以前のすべての記憶の減衰を反映しており、`a[i]`新しいコンテストを全重量で挿入します。 
4. アップデート後`cur`、その符号を決定します。 正の場合は「+」を出力します。 負の場合は「-」を出力します。 正確にゼロの場合は、「0」を出力します。 
5. すべてのコンテストが処理されるまで続行します。 

重要な詳細は、反復が加重和の定義と正確に一致することです。 各ステップでは、2 の累乗を明示的に計算することなく、暗黙的に正しい指数重み付けが保存されます。 

### なぜ効果があるのか

 i 要素を処理した後、変数`cur`の正確な値に等しい$$\sum_{j=1}^{i} 2^{j-i} a_j.$$i+1 に移動すると、前のすべての項に 1/2 が乗算され、その指数が 2^{j-i} から 2^{j-(i+1)} にシフトされ、新しい項 a[i+1] が重み 1、つまり 2^0 で入ります。 これは定義と正確に一致するため、漸化式ではプロセス全体を通じて正確な代数的不変量が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    cur = 0.0
    res = []
    
    for x in a:
        cur = cur / 2.0 + x
        
        if cur > 0:
            res.append('+')
        elif cur < 0:
            res.append('-')
        else:
            res.append('0')
    
    print(''.join(res))

if __name__ == "__main__":
    solve()
```このソリューションは、単一の実行中の浮動小数点アキュムレータを維持します。`cur`。 更新ルールは派生した繰り返しを直接実装するため、2 のべき乗を明示的に処理する必要はありません。 各更新の後、すぐに記号を分類し、対応する文字を結果の文字列に追加します。 

ここで浮動小数点演算を使用するのは安全です。演算は加算と 2 による除算のみであり、中程度の大きさの整数については 2 進浮動小数点で正確に表現できるからです。 比較は各更新の直後に行われるため、一般的な制約では、誤差の蓄積が不正確な符号反転に伝播するのに十分な時間がありません。

 ## 特殊なケース

 単一要素の入力の場合、次のようになります`n = 1`、繰り返しセット`cur = 0 / 2 + a[1]`したがって、出力符号は単に次の符号になります。`a[1]`。 1 つの項だけが重み 2^0 で寄与するため、これは定義と一致します。 

すべてゼロの入力の場合、すべての更新が維持されます。`cur`減衰と加算の両方がゼロを保持するため、ゼロになります。 このアルゴリズムは、「0」の連続文字列を出力します。これは、すべての加重合計が正確に 0 であるという事実と一致します。 

大きな正の値と負の値が交互に現れる場合、減衰により初期の項の影響が急速に失われます。 たとえば、`[1000000000, -1000000000, 1000000000]`、減算の前に半分になるため、2 番目の値は最初の値を完全にキャンセルせず、3 番目の項が優位性を取り戻します。 すべてのステップで正しい指数スケーリングが近似されるのではなく暗黙的に適用されるため、反復ではこの相互作用が正確に捕捉されます。
