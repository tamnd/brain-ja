 ## 解決策
 ## 問題の理解

 私たちには、少数の種類に分割された大量のカードのプールが与えられています。 タイプ$i$含まれています$a_i$異なるカードがあり、最初のカードを収集することだけを気にします$b_i$そのタイプの個別のカード。 

1 回の「リフレッシュ」で、プール全体から均等に 1 枚のカードが引き出されます。 そのタイプのカードがさらに必要な場合は、それを保持し、プールから効果的に削除します。 そのタイプのカードをすでに十分に集めている場合、引いたカードは役に立たず、すぐに元に戻されるため、プールのサイズは変更されず、何も進みません。 

プロセスはタイプごとに 1 回停止します$i$集められました$b_i$回。 タスクは、終了までに予想されるリフレッシュ数を正確な有理値モジュロとして計算することです。$998244353$。 

制約によって構造が明確になります。 種類数$m$カードの総数は最大 12 枚です$n$これは、次のような指数関数的な依存性を強く示唆しています。$m$多項式に依存するものは何でも受け入れられますが、$n$各サブセットには慎重な制御が必要です。 

単純なシミュレーションでは、すべての要件が満たされるまでカードのサンプリングとカウントの更新を繰り返します。 各シミュレーションが高速であっても、安定するまでに多くの実行が必要になる可能性があり、クーポン コレクターのようなプロセスのばらつきにより、これは使用できなくなります。 

より本格的なブルートフォース定式化では、状態を収集されたカウントのベクトルとして扱います。$(x_1, \dots, x_m)$、 どこ$0 \le x_i \le b_i$。 From each state, we branch into all possible next draws. 状態の数は$\prod (b_i+1)$まで爆発する可能性があります$1000^{12}$最悪の場合、これは完全に不可能です。 

主な問題点は、「無駄なドロー」は依然として時間を消費しますが、状態は変更されないため、タイプごとに独立したクーポン コレクターに単純に削減することができないことです。 

## アプローチ

 ブルート フォースの観点では、これをすべての部分コレクション状態にわたるマルコフ連鎖として扱います。 各遷移はカードを引くことに対応し、遷移は座標を 1 つ増やすか、状態を変更しないままにします。 これは正しいですが、状態空間が巨大であるため使用できません。 

構造の簡素化は、プロセスを拒否を伴う離散サンプリングではなく、連続時間のランダム イベント ストリームとして見ることから生まれます。 それぞれの種類$i$一定の確率で選ばれる$p_i = a_i / n$あらゆる段階で。 これは、時間を「ポアソン化」すると、各タイプの到着が独立したポアソン過程を形成し、収集のプロセスが形成されることを意味します。$b_i$アイテムは終了までの時間となります$b_i$-番目の到着手続き中$i$。 

したがって、各タイプには独自の完了時間があります$T_i$、ガンマ (または離散時間の負の二項) として分布し、答えは次の期待値です。$\max_i T_i$, すべてのタイプがその割り当てに達した場合にのみ終了するためです。 

これにより、結合マルコフ連鎖の問題が、独立した完了時間の順序統計に関する問題に変換されます。 

残りの困難は、これらの分布の最大値を含む期待値を計算することです。 標準恒等式は、生存確率の包含排除を使用して最大値を部分集合の合計に変換し、問題を部分集合の最小値の期待値の計算に軽減します。 各サブセットは独立して管理可能になるため、$m \le 12$。

 ## アルゴリズムのチュートリアル

 私たちはモジュラー算術で作業します$998244353$、すべての確率を剰余分数として扱います。 

1. それぞれのタイプを確率のある成功プロセスに変換する$p_i = a_i / n$。 これは、それぞれの描画を独立して選択するタイプとしてモデル化します。$i$一定の確率で。 
2. 収集時間を解釈する$b_i$タイプのアイテム$i$確率変数として$T_i$、の時間$b_i$レート付きベルヌーイ過程で - 回目の成功$p_i$。 
3. 合計完了時間が$T = \max_i T_i$すべてのタイプが完了する必要があるためです。 
4. ID を使用する$$\mathbb{E}[\max T_i] = \sum_{\emptyset \ne S \subseteq [m]} (-1)^{|S|+1} \mathbb{E}[\min_{i \in S} T_i].$$これにより、問題はサブセット全体の予想最小値の計算に軽減されます。 
5. 固定サブセットの場合$S$、計算する$\mathbb{E}[\min_{i \in S} T_i]$テール確率を使用すると、次のようになります。$$\mathbb{E}[\min T] = \sum_{t \ge 0} \Pr(\text{no } i \in S \text{ has finished by time } t).$$6. サブセットごとに$S$、後のカウントの分布を計算します。$t$多項 DP を使用してステップを実行し、長期にわたって DP 配列を維持して、生存確率を効率的に評価します。 
7. 畳み込みのような遷移を事前計算して、サブセットから拡張する$S$に$S \cup \{i\}$以前に計算された分布を再利用できます。 
8. 包含-除外式を使用してすべてのサブセットの寄与を結合し、最終的な期待値を取得します。 

### なぜ効果があるのか

 各サブセット$S$少なくとも 1 つのプロセスが実行するイベントを分離します。$S$検討されたものの中で最後に終了します。 包含-除外拡張により、重複する生存イベントからの最大値の分布が再構築されます。 ポアソン化モデルでは各タイプが独立して進化するため、サブセットの確率は多項構造を通じて考慮され、完全なベクトルではなくサブセットにわたる DP が可能になります。 各 DP 状態は必要なしきい値までの完全な切り捨てられたカウント分布をエンコードするため、アルゴリズムは部分的な進行状況に関する情報を失うことはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modinv(x):
    return pow(x, MOD - 2, MOD)

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    inv_n = modinv(n)
    p = [x * inv_n % MOD for x in a]

    size = 1 << m

    # dp[mask] will store expected value contribution for subset mask
    # computed via inclusion-exclusion over min expectations
    dp = [0] * size

    # precompute binomial-like DP for each type truncated at b[i]
    # ways[i][t][k] = probability that in t steps we see k occurrences of type i
    # (binomial distribution)
    ways = []
    maxb = max(b)

    for i in range(m):
        bi = b[i]
        pi = p[i]

        # only need up to bi occurrences
        w = [[0] * (bi + 1) for _ in range(n + 1)]
        w[0][0] = 1

        for t in range(1, n + 1):
            w[t][0] = w[t - 1][0] * (1 - pi) % MOD
            for k in range(1, bi + 1):
                val = w[t - 1][k] * (1 - pi)
                val += w[t - 1][k - 1] * pi
                w[t][k] = val % MOD

        ways.append(w)

    # compute survival probabilities for each subset
    for mask in range(1, size):
        # compute min expectation for this subset
        # via summing survival probabilities up to n
        res = 0
        for t in range(n + 1):
            prob = 1
            for i in range(m):
                if mask & (1 << i):
                    if b[i] <= n:
                        prob *= sum(ways[i][t][k] for k in range(b[i])) % MOD
                        prob %= MOD
            res = (res + prob) % MOD
        dp[mask] = res

    ans = 0
    for mask in range(1, size):
        bits = bin(mask).count("1")
        if bits % 2 == 1:
            ans = (ans + dp[mask]) % MOD
        else:
            ans = (ans - dp[mask]) % MOD

    print(ans % MOD)

if __name__ == "__main__":
    solve()
```この解決策は、モジュラー確率を使用してサンプリング プロセスを独立したベルヌーイ プロセスに変換することから始まります。 各タイプは時間の経過に伴う二項累積として処理され、必要なクォータで切り捨てられるため、終了したかどうかだけを気にするようになります。 

DP アレイ`ways[i][t][k]`そのタイプである可能性を追跡します$i$まさに現れた$k$何度か後$t$ステップ。 まとめ$k < b_i$そのタイプの確率を与えます$i$まだ未完成の時間です$t$、これは生存確率の構成要素です。 

次に、各サブセットがこれらの生存確率を集計し、包含排除によって予想される最大完了時間を再構築します。 

重要な実装の詳細は、完全な状態ベクトルを決して追跡しないことです。 すべての相互作用は、タイプごとの二項ダイナミクスと組み合わせてサブセット列挙にプッシュされます。

 ## 特殊なケース

 微妙なエッジケースが発生するのは、$b_i = 0$。 この状況では、そのタイプは停止条件に寄与しないため、最大値に影響を与えることはありません。 アルゴリズムでは、時間ゼロを超えると生存確率が常にゼロになるため、これは自然に処理され、サブセットの期待値が増加することはありません。 

もう一つのケースは次のような場合です。$b_i = a_i$これは、タイプが完全に使い果たされている必要があることを意味します。 二項 DP は依然として機能します。$b_i$意味のあるすべての状態を捕捉し、完全に枯渇するまで生存確率は厳密に減少します。 

いつ$m = 1$、包含と除外は単一のサブセットに折りたたまれます。 このアルゴリズムは、単一の負の二項期待値を計算することに帰着します。これは、有界プールの古典的なクーポン コレクターの公式と一致します。
