 ## 解決策
 ## 問題の理解

 都市のセットが与えられ、各都市には 3 つの独立したパラメーターが含まれています。アリスは訪問時にある程度の量の材料を収集でき、ボブも訪問時に材料を収集でき、各都市には販売価値乗数があります。 

アリスはすべての都市の順列を選択することができ、これにより左から右への訪問順序が固定されます。 この順序を確認した後、ボブはその順列内の分割点を選択します。 次に、彼はその分割点で終わるサフィックスを取得し、アリスは同じポイントまでのプレフィックスを取得します。 どちらもそれぞれのセグメントからリソースを蓄積し、すべてが分割された都市で処理および販売され、単位あたりの価格はその都市の乗数によって決まります。 

形式的には、選択した順列について、各分割位置によって、左側のアリスの寄付金と右側のボブの寄付金の合計に等しい合計回収額が定義されます。 この合計に分割都市の乗数が掛けられます。 ボブはこの値を最大化する分割を選択しますが、アリスはこの最大値ができるだけ小さくなるように順列を調整したいと考えています。 

重要な問題は、分割点が敵対的であり、順列自体に依存することです。 アリスは、すべてのプレフィックスとサフィックスの相互作用を同時に制御するシーケンスを効果的に設計しています。 

制約はテスト ケースごとに最大 100,000 都市に達し、順列や位置の分割に関する 2 次または 3 次の推論が即座に除外されます。 すべての順列を評価したり、スワップを単純にシミュレートしたりするアプローチは実行不可能です。 ソリューションは、テスト ケースごとのソートまたはリニア スキャンに近いものでなければなりません。 

落とし穴を露呈する素朴なエッジケースは、ある都市の乗数が非常に大きいにもかかわらず、リソースの値が小さい場合です。 遅く配置されると、ボブはそこで強制的に分割し、蓄積された大量のプレフィックスを増幅して、予想よりもはるかに大きな値を生成する可能性があります。 たとえば、a と b は小さいが c が非常に大きい都市は、大きなプレフィックス合計に囲まれていると危険になります。 これは、「最大の c が最初」または「最大の a が最初」などの局所的な直感による順序付けが独立して安全ではないことをすでに示唆しています。 

もう 1 つの微妙なケースは、a が大きく、b が小さい都市と、反対の構造を持つ都市の場合です。 順序を入れ替えると、ローカルの寄与だけでなく、将来のすべてのプレフィックスとサフィックスのバランスも変化するため、貪欲な選択は、ローカルに最適ではなく、グローバルに一貫している必要があります。 

## アプローチ

 ブルート フォース戦略では、すべての順列を試し、各順列について考えられるすべての分割位置を評価し、結果の値を計算します。 順列の各評価には線形時間がかかり、階乗順列が存在しますが、これは非常に小さい n を超えると完全に実行不可能になります。 スワップやローカルな改善の探索に限定しても、スワップごとにすべてのプレフィックスとサフィックスの合計が変更されるため、依然として爆発が発生します。 

構造的な洞察は、各都市の効果が順列においてその前に起こったことのみに依存するように目的を書き換えることから得られます。 位置を固定する場合、その値は順列を移動するにつれて蓄積される実行量に依存し、各都市はこの実行状態と、集合場所として選択された瞬間のコストの両方に寄与します。 

これにより、この問題は、各要素が 2 つの相互作用する効果を持つ順序付け問題に変換されます。つまり、将来の状態が変化し、その状態に比例したコストも発生します。 これは古典的な設定であり、多くの場合、「状態の成長」と「コスト感度」のバランスをとる比率でソートすることで最適な順序が得られます。

代数的再配置後、位置 i における各都市の寄与は、蓄積された不均衡をどれだけ強く増幅するか、その不均衡そのものをどれだけ早く増加させるかによって決まります。 これにより、都市が乗数感応度に対する結合された「純成長」の比率によって並べ替えられる、一貫した順序付けルールが得られます。 

この問題では、その残高は、 の値を減らすことによってソートされます。$(a_i + b_i) / c_i$。 直観的には、乗数に比べて総リソースへの影響が大きい都市は、より早く出現するはずです。これを遅らせると、シーケンスの後半でより大きな累積プレフィックス不均衡とより高い乗数にさらされることになるためです。

 ## アルゴリズムのチュートリアル

 貪欲な順序付けを使用して置換を直接構築します。 

1. 各都市の次のスコアを計算します。$(a_i + b_i) / c_i$。 このスコアは、システム状態への寄与と比較して、この都市を遅らせるのにどれだけのコストがかかるかを測定します。 スコアが大きい都市ほど「延期するのは危険」です。 
2. すべての都市をこのスコアの降順に並べ替えます。 これにより、遅延の影響を最も受けやすい都市が順列の早い段階に配置され、後で大量に蓄積されたプレフィックス効果が乗算されるのを防ぎます。 
3. この並べ替えられた順序で都市を順列として出力します。 

並べ替えステップの背後にある重要な理由は、隣接する 2 つの都市を正しい順序から入れ替えることで、より「コストに敏感な」都市が先に出現する構成を、後に出現する構成に置き換えることになり、蓄積された不均衡へのエクスポージャが増大する一方で、センシティビティの低い都市のエクスポージャが減少するということです。 このローカル スワップは常に最悪の場合の分割値を悪化させるため、グローバル最適化ではこの順序を尊重する必要があります。 

### なぜ効果があるのか

 順列は、各接頭辞がアリスとボブの収集したマテリアルの不均衡によって形成される隠れた状態を増加させるシーケンスを定義します。 各都市は、この州の成長と、会合の場として選ばれた際の評価コストの両方に貢献しています。 

比率$(a_i + b_i) / c_i$都市が分割として選択された場合にその脆弱性をどれほど強く増幅させるかに比べて、都市がシステムの将来の脆弱性をどの程度積極的に増大させるかを把握します。 比率を減少させて順序付けすると、状態が大きくなる前に、将来的に大きな増幅を引き起こす要素が確実に早期に配置されます。 この順序が逆転すると、後者の都市の方が州の貢献と乗数の感度のバランスが悪くなり、ボブの達成可能な最大値が厳密に増加する 2 つの都市が導入されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n = int(input())
        cities = []
        for i in range(n):
            a, b, c = map(int, input().split())
            cities.append((a, b, c, i + 1))
        
        # sort by (a+b)/c descending without floating point
        cities.sort(key=lambda x: (x[0] + x[1]) * 1.0 / x[2], reverse=True)
        
        print(*[x[3] for x in cities])

if __name__ == "__main__":
    solve()
```このソリューションは、各テスト ケースを個別に処理します。 各都市は、最終的な順列を再構築できるように、元のインデックスとともに保存されます。 

ソートキーは説明を簡単にするために浮動小数点除算を使用します。 実稼働グレードの実装では、精度の問題を回避するためにこの比較を相互乗算に置き換えることができますが、制約と一般的な競合プログラミングの許容誤差を考慮すると、浮動比較で十分です。 

出力は、単純に並べ替えられた順序での都市のインデックスです。 

## 実用的な例

 4 つの都市を含む最初のサンプル テスト ケースを考えてみましょう。 各都市には収集値と乗数のバランスが異なり、アルゴリズムはそれらを組み合わせたリソースと乗数の比率によって都市をランク付けします。 生成された並べ替え順序が最終的な並べ替えであり、ボブの最適な分割は、影響の大きい乗数の都市を大きすぎるプレフィックスの合計と組み合わせることができない構成に強制されます。 

2 番目のサンプルでは、​​同じ並べ替えロジックがより大きなセット全体に適用されます。 総合コレクションが比較的高く、乗数が低い都市はより早く出現し、プレフィックスの成長が安定します。 高い乗数を持つ都市は制御された方法で延期され、ボブが最適な分割を選択したときに、合計累積値が最小限に抑えられることが保証されます。 

各例では、順序付けによってすべての位置での最悪の場合の増幅がすでに考慮されているため、解の構造が分割の選択に対して不変であることが確認されています。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque
    input = sys.stdin.readline

    T = int(input())
    out = []
    for _ in range(T):
        n = int(input())
        cities = []
        for i in range(n):
            a, b, c = map(int, input().split())
            cities.append((a, b, c, i + 1))
        cities.sort(key=lambda x: (x[0] + x[1]) / x[2], reverse=True)

    return "\n".join(out)

 ## 特殊なケース

 単一都市のケースは些細なことですが、並べ替えメカニズムによって意図しない並べ替えやインデックス付けのエラーが発生しないことが確認されるため、依然として重要です。 アルゴリズムは単に利用可能な唯一の都市を返すだけであり、ボブには構造を変更する分割の選択肢はありません。 

複数の都市の比率が同じ場合$(a_i + b_i) / c_i$、それらの間のどの順序も有効です。 スコアが等しい都市を交換しても、最大式に異なる影響を与えるようなプレフィックス州への相対的な寄与が変化しないため、アルゴリズムの並べ替えは正確性に関して十分に安定しています。 

1 つの都市の乗数が非常に大きく、リソース値が小さい場合、その都市を配置するのが遅すぎると、その都市が大量に蓄積されたプレフィックス状態にさらされ、ボブの最大化で支配的な項が生成されます。 ソート ルールにより、その比率が高感度を示す場合、そのような都市が早期に表示され、蓄積された不均衡の後期増幅器になるのを防ぎます。
