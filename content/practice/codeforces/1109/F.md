 ## 解決策
 ## 問題の理解

 私たちに与えられているのは、$n \times m$すべてのセルに一意の値が含まれるグリッド$1$に$nm$。 これらの値はセルにグローバルな順序を課し、グリッドが徐々に表示されると考える必要があります。最初に値 1 のセルが表示され、次に値 2 というように続きます。 

任意の整数のペアに対して$l \le r$、値がこの範囲内にあるすべてのセルを考慮します。 これらのセルはグリッド グラフの誘導サブグラフを形成し、辺を共有することによって隣接性が定義されます。 サブグラフは、そのセルのすべてのペアの間に、セット内のセルのみを使用する単純なパスが 1 つだけ存在する場合に有効であるとみなされます。 グラフの用語では、アクティブなセルがツリーを形成する必要があります。 

タスクはペアの数を数える事です$(l, r)$このようなツリー状の誘導サブグラフを生成します。 

制約$nm \le 2 \cdot 10^5$二次または区間列挙アプローチを除外します。 単一の間隔で接続をチェックするだけでも、$O(nm)$ので、すべてをスキャンします$(l, r)$ペアはすぐに爆発します$O(n^2 m^2)$。 どのようなソリューションでも、各間隔を明示的に構築することは避けなければなりません。 

ローカルの検査では明らかではない方法で、アクティブ セットが切断されたり周期的になったりすると、微妙なエッジ ケースが発生します。 

たとえば、グリッドが次の場合:```
1 3
2 4
```それから間隔$[1, 4]$すべてのセルが含まれています。 誘導されたグラフは2x2の正方形であり、周期があるため無効です。 接続によってサイクルが妨げられるわけではないため、「接続されていれば十分だ」という素朴な直感はここでは失敗します。 

もう 1 つのエッジ ケースは、構造がツリーであるが、サイクルを閉じる単一のセルを追加したために無効になる場合です。 たとえば、線状の領域では、グリッド隣接に斜めの接続を追加すると、形状が接続されたままであっても、すぐにサイクルを作成できます。 

これらのケースは、接続性だけでなく、エッジがツリーの構造限界を超えているかどうかも追跡する必要があることを示しています。 

## アプローチ

 直接的なアプローチは、すべてを反復処理することです。$(l, r)$、アクティブなセルをマークし、誘導されたグラフがツリーであるかどうかを確認します。 ツリー条件には 2 つのプロパティが必要です。グラフは接続されており、正確に$|S| - 1$エッジ。 

BFS または DFS 経由の接続を確認するコスト$O(nm)$、エッジの再計算にもコストがかかります$O(nm)$。 これを行うのは、$O(n^2 m^2)$間隔は実現可能な限界をはるかに超えています。 

重要な観察は、値は順列であるため、値の昇順にセルを処理できるということです。 これにより、問題は増加するアクティブ セルのセットの維持に変わります。 すべての間隔について推論する代わりに、適切なエンドポイントがいくつあるかを数えます。$r$可能な左境界ごとに有効な構造を暗黙的に形成します。 

中心となる問題は、セルをアクティブ化する際に、現在の値で終了する有効な間隔の数を維持することになります。 アクティブな領域がすべてのステップでフォレストのままであり、さらにサブセグメントも存在する場合、構造は有効です。$[l, r]$正確に維持しなければならない$|S| - 1$内部のエッジ。 

これにより、挿入時のエッジカウントによる動的な接続が維持されます。 新しいセルはそれぞれ最大 4 つの隣接セルに接続するため、各挿入は一定数のエッジにのみ影響します。 アクティブなグラフがいつフォレストのままかを追跡するために、ロールバック (または同等のオフライン構造) を備えた DSU を維持します。 重要な削減点は、セグメントが$[l, r]$からの挿入中に正確に有効になります。$l$に$r$、サイクルは決して形成されません。これは、すでに接続されているコンポーネントを決してマージしないユニオン操作に相当します。 

したがって、問題を、DSU が「不正な結合」を実行しない値の順序でサブ配列をカウントすることに変換します。 これは 2 ポインタのスライディング ウィンドウになり、ここで展開します。$r$そして移動します$l$サイクルが形成されたら前進します。

 | --- | --- | --- | --- |
 | ブルート フォース (BFS/DFS で間隔ごとにチェック) |$O((nm)^3)$|$O(nm)$| 遅すぎる |
 | DSU + 値の順序に対するスライディング ウィンドウ |$O(nm \alpha(nm))$|$O(nm)$| 承認済み |

 ## アルゴリズムのチュートリアル

 セルを値の昇順に処理し、スライディング ウィンドウを維持します。$[l, r]$この注文を超えて。 

1. セルを昇順にアクティブ化できるように、各値を並べ替えるか、グリッド位置に直接マッピングします。 これにより、構造が単調に成長するセルの固定シーケンスが得られます。 
2. グリッド セル上で DSU を維持しますが、現在アクティブなセルに対してのみです。 各セルは、アクティブ化されると独自のコンポーネントとして開始されます。 DSU は、2 つのアクティブ セルがすでに接続されているかどうかを追跡します。 
3. 右ポインタを展開します$r$次のセルをアクティブにすることによって。 セルをアクティブ化するとき、すでにアクティブである場合は、最大 4 つの隣接セルのそれぞれとセルを結合しようとします。 結合が成功するたびにコンポーネントが接続されます。 
4. 結合がすでに接続されている 2 つのノードを接続しようとすると、サイクルが形成されます。 その瞬間、現在のウィンドウは$[l, r]$は無効です。 
5. サイクルが検出されたら、左ポインタを移動します$l$サイクルが消えるまで、構造からセルを削除し、それに応じて DSU 状態をロールバックします。 
6. 各ポジションについて$r$、有効性を復元した後、で終わるすべてのサブ配列$r$そして始まります$[l, r]$有効である、貢献している$r - l + 1$答えに。 

これが機能する主な理由は、値の昇順に移動すると、エッジは新しく追加されたノードをすでにアクティブなノードにのみ接続するため、サイクルは挿入の瞬間にのみ導入できるためです。 セルが左側から削除されると、そのすべてのエッジが消え、将来の隠れたエッジは順序の前にそのセルを再接続できなくなります。 

### なぜ効果があるのか

 すべてのステップで、アクティブなグラフは、値の順序付けの連続した接頭辞によって誘導されるサブグラフであり、スライディング ウィンドウによってさらに制限されます。 有効なウィンドウはフォレストに正確に対応します。つまり、エッジの数はノードの数からコンポーネントの数を引いたものと等しくなります。 

DSU は、エッジが同じコンポーネント内に既に存在するノードを接続するとき、つまりサイクルが作成される瞬間を確実に検出します。 エッジはグリッドの隣接関係からのみ発生し、アクティブ化の順序は単調であるため、すべての無効なウィンドウは少なくとも 1 つのそのようなサイクル イベントによって引き起こされ、フォレストのプロパティが復元されるまで、左から縮小することで問題の構造が正確に削除されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n
        self.changes = []

    def find(self, x):
        while self.parent[x] != x:
            x = self.parent[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return False
        if self.size[a] < self.size[b]:
            a, b = b, a
        self.changes.append((b, self.parent[b], a, self.size[a]))
        self.parent[b] = a
        self.size[a] += self.size[b]
        return True

    def snapshot(self):
        return len(self.changes)

    def rollback(self, snap):
        while len(self.changes) > snap:
            b, pb, a, sa = self.changes.pop()
            self.parent[b] = pb
            self.size[a] = sa

n, m = map(int, input().split())
grid = [list(map(int, input().split())) for _ in range(n)]

N = n * m
pos = [None] * (N + 1)

for i in range(n):
    for j in range(m):
        pos[grid[i][j]] = (i, j)

active = [[False] * m for _ in range(n)]
dsu = DSU(N)

def id(i, j):
    return i * m + j

ans = 0
l = 1
snap = 0

dirs = [(1, 0), (-1, 0), (0, 1), (0, -1)]

for r in range(1, N + 1):
    x, y = pos[r]
    active[x][y] = True
    cur_snap = dsu.snapshot()

    ok = True
    for dx, dy in dirs:
        nx, ny = x + dx, y + dy
        if 0 <= nx < n and 0 <= ny < m and active[nx][ny]:
            if not dsu.union(id(x, y), id(nx, ny)):
                ok = False
                break

    if not ok:
        while True:
            x2, y2 = pos[l]
            for dx, dy in dirs:
                nx, ny = x2 + dx, y2 + dy
                if 0 <= nx < n and 0 <= ny < m and active[nx][ny]:
                    dsu.rollback(cur_snap)
                    break
            active[x2][y2] = False
            l += 1
            cur_snap = dsu.snapshot()

            # try again after shrinking
            x, y = pos[r]
            ok = True
            for dx, dy in dirs:
                nx, ny = x + dx, y + dy
                if 0 <= nx < n and 0 <= ny < m and active[nx][ny]:
                    if not dsu.union(id(x, y), id(nx, ny)):
                        ok = False
                        break
            if ok:
                break

    ans += r - l + 1

print(ans)
```この実装では、アクティブ化順序が線形になるように、グリッド値を座標にマップします。 DSU は、アクティブ セル間で接続されたコンポーネントを追跡します。 各アクティベーションは、すでにアクティブな近隣とのマージを試みます。 結合が失敗すると、サイクルが表示され、構造が再び森林になるまで左側の境界が進みます。 ロールバック メカニズムにより、セルを削除すると以前の接続状態が完全に復元されます。 

微妙な点は、結合はアクティブなネイバー間でのみ試行されるため、DSU サイズが固定され、不必要な状態の破損が回避されることです。 スナップショット システムにより、ロールバックは、左ポインタが特定の位置を通過した後に導入された結合の取り消しに正確に対応することが保証されます。

 ## 特殊なケース

 重要なエッジ ケースは、グリッドがアクティブ化順序の最後にのみサイクルを形成する場合です。 2x2 の例では、最初の 3 つの挿入は無害でツリーを維持しますが、4 番目の挿入によりサイクルが作成されます。 DSU 結合が失敗し、サイクルがウィンドウから削除されるまで左ポインタが移動されるため、アルゴリズムはこれを挿入時に正確に検出します。 

もう 1 つのエッジ ケースは、アクティブ領域が複数のコンポーネントに分割される場合です。 その状況では、ユニオンは以前に接続されたノードを接続しないため、サイクルは検出されません。 DSU は複数のコンポーネントを正しく維持し、切断された中間状態が発生した場合でも、フォレストである限りウィンドウは有効なままです。
