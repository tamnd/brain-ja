 ## 解決策
 ## 問題の理解

 繰り返し変更とクエリが行われる整数の配列を維持しています。 配列は固定で始まりますが、時間の経過とともに、連続したセグメントを拡大縮小したり、単一の要素を分割して縮小したり、セグメント全体の合計を求める操作を適用したりします。 すべての合計は、指定された数値を法として報告する必要があります。 

主な問題は、配列が静的ではないことです。 1 回の更新で最大 100,000 の値を乗算することができ、そのような操作は最大 100,000 回あります。 各更新を影響を受ける各要素に直接適用する単純なシミュレーションでは、最大で$10^{10}$最悪の場合、2 秒で実行される処理をはるかに超えます。 

操作は非対称です。 範囲の乗算は均一で合計に対して分散的ですが、単一の位置の除算は局所的な逆演算であり、正確な値を慎重に保存しない限り、単純な範囲遅延では処理できません。 法も必ずしも素数ではないため、逆剰余に依存することはできません。 除算が保証されるのは、入力がモジュロを取る前に整数での割り算が保証されているためだけです。 

値が大きくなり、後で除算される前に繰り返し乗算される場合、微妙なエッジ ケースが発生します。 モジュロの下でのみ値を維持し、モジュラ逆行列を介して除算を適用しようとすると、非素数モジュライでは解決策が壊れます。 たとえば、次の場合$mod = 8$、2 による除算は反転できないため、演算が整数で有効であってもモジュラ逆論理は失敗します。 

もう 1 つの落とし穴は、遅延伝播を行わずに、合計を格納するフェンウィック ツリーに範囲乗算を直接適用できると想定していることです。 スケーリングが慎重に伝播されない限り、合計が誤って更新されます。 

## アプローチ

 ブルート フォース アプローチでは、配列を明示的に保存し、各クエリを直接処理します。 範囲乗算はセグメント内のすべてのインデックスを反復して乗算し、範囲合計は反復して累積します。 分割は 1 回の更新になります。 これは正しいですが、各乗算クエリにコストがかかるため、非常に遅くなります。$O(n)$、最悪の事態につながる$O(nq)$。 

問題の構造から、範囲更新と範囲クエリをサポートするデータ構造が必要であることがわかります。 合計演算は線形であり、乗算は加算に分配されます。つまり、セグメントに次の乗算が行われるかどうかを意味します。$x$、セグメントの合計にも乗算されます。$x$。 これはまさに、遅延伝播を備えたセグメント ツリーが活用できる構造です。 

複雑なのは、範囲の乗算と点の除算の両方が必要なことです。 重要な観察は、除算は単一の位置にのみ適用され、均等に除算されることが保証されていることです。 つまり、これを直接のポイント更新として扱うことができます。現在の値を位置に配置します。$p$、それを分割し、セグメント ツリー内のその点を更新します。 

したがって、セグメント ツリー内の各ノードは、そのセグメントの合計を維持します。 遅延タグは保留中の乗算因子を保存します。 乗算がノードに適用されると、その合計を乗算し、遅延乗数を累積します。 降下時には、この乗数を子供たちにプッシュします。 ポイント更新によりパスが上方向に再計算されます。 

これにより、点更新を伴う標準的な乗算遅延セグメント ツリーが生成されます。

 | 遅延乗算を使用したセグメント ツリー |$O(q \log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 各ノードがそのセグメントのモジュロの合計を格納するセグメント ツリーを維持します。`mod`、およびそのセグメント内のすべての要素に適用する必要がある保留中の乗算を表す遅延乗数。 

1. 初期配列からセグメント ツリーを構築します。 各リーフには 1 つの要素が格納され、内部ノードには子のモジュロの合計が格納されます。`mod`。 
2. 範囲乗算クエリの場合$(l, r, x)$、セグメントツリーをたどります。 ノードのセグメントが完全に内側にあるときは常に$[l, r]$、保存されている合計に次の値を掛けます。$x$モジュロ`mod`そしてその遅延タグを乗算します$x$。 これが機能するのは、そのセグメント内のすべての要素が均一にスケーリングされ、合計が同じ係数でスケーリングされるためです。 
3. ノードが部分的にクエリ範囲と重複する場合、続行する前にその遅延乗算器を子にプッシュします。 これにより、降下時の正確性が保証されます。 
4. 位置での除算クエリの場合$p$で、まず現在の値をクエリします。$p$。 これは、ツリーを下に移動し、パス上のすべての保留中の遅延乗算器を適用することによって行われます。 値を取得したら、それを次の値で割ります。$x$整数の除算を使用します。 
5. 新しい値を計算した後、次の時点でポイント更新を実行します。$p$、更新された値に設定します。 この更新により、セグメント合計の再計算が上向きに伝播されます。 
6. 範囲合計クエリの場合$(l, r)$では、標準のセグメント ツリー範囲合計クエリを実行し、必要なときに必ず遅延値がプッシュされるようにします。 

重要な考え方は、乗算は遅延かつ分散的に処理されるのに対し、除算は真の値を抽出した後の破壊的な点更新として処理されるということです。 

### なぜ効果があるのか

 すべてのノードで、保存された合計は常に、そのセグメントの上にあるすべての保留中の遅延要素を乗算したセグメントの真の合計を表します。 遅延伝播により、乗算が失われたり部分的に適用されたりすることがなくなります。 乗算は加算よりも分散されるため、セグメント レベルで乗算器を適用すると、個々の要素に手を加える必要がなく、合計の正確さが維持されます。 除算は常に、変更前に正確な現在値を抽出することによって解決され、モジュラー逆算や近似算術に決して依存しないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

class SegTree:
    def __init__(self, arr, mod):
        self.n = len(arr)
        self.mod = mod
        self.sum = [0] * (4 * self.n)
        self.lazy = [1] * (4 * self.n)
        self.arr = arr
        self.build(1, 0, self.n - 1)

    def build(self, v, tl, tr):
        if tl == tr:
            self.sum[v] = self.arr[tl] % self.mod
        else:
            tm = (tl + tr) // 2
            self.build(v * 2, tl, tm)
            self.build(v * 2 + 1, tm + 1, tr)
            self.sum[v] = (self.sum[v * 2] + self.sum[v * 2 + 1]) % self.mod

    def push(self, v):
        if self.lazy[v] != 1:
            x = self.lazy[v]
            for u in (v * 2, v * 2 + 1):
                self.sum[u] = self.sum[u] * x % self.mod
                self.lazy[u] = self.lazy[u] * x % self.mod
            self.lazy[v] = 1

    def range_mul(self, v, tl, tr, l, r, x):
        if l > r:
            return
        if l == tl and r == tr:
            self.sum[v] = self.sum[v] * x % self.mod
            self.lazy[v] = self.lazy[v] * x % self.mod
            return
        self.push(v)
        tm = (tl + tr) // 2
        self.range_mul(v * 2, tl, tm, l, min(r, tm), x)
        self.range_mul(v * 2 + 1, tm + 1, tr, max(l, tm + 1), r, x)
        self.sum[v] = (self.sum[v * 2] + self.sum[v * 2 + 1]) % self.mod

    def point_get(self, v, tl, tr, pos):
        if tl == tr:
            return self.sum[v]
        self.push(v)
        tm = (tl + tr) // 2
        if pos <= tm:
            return self.point_get(v * 2, tl, tm, pos)
        else:
            return self.point_get(v * 2 + 1, tm + 1, tr, pos)

    def point_set(self, v, tl, tr, pos, val):
        if tl == tr:
            self.sum[v] = val % self.mod
            return
        self.push(v)
        tm = (tl + tr) // 2
        if pos <= tm:
            self.point_set(v * 2, tl, tm, pos, val)
        else:
            self.point_set(v * 2 + 1, tm + 1, tr, pos, val)
        self.sum[v] = (self.sum[v * 2] + self.sum[v * 2 + 1]) % self.mod

    def range_sum(self, v, tl, tr, l, r):
        if l > r:
            return 0
        if l == tl and r == tr:
            return self.sum[v] % self.mod
        self.push(v)
        tm = (tl + tr) // 2
        return (self.range_sum(v * 2, tl, tm, l, min(r, tm)) +
                self.range_sum(v * 2 + 1, tm + 1, tr, max(l, tm + 1), r)) % self.mod

def solve():
    n, mod = map(int, input().split())
    arr = list(map(int, input().split()))
    q = int(input())
    st = SegTree(arr, mod)

    out = []
    for _ in range(q):
        tmp = input().split()
        t = int(tmp[0])
        if t == 1:
            l, r, x = map(int, tmp[1:])
            st.range_mul(1, 0, n - 1, l - 1, r - 1, x)
        elif t == 2:
            p, x = map(int, tmp[1:])
            cur = st.point_get(1, 0, n - 1, p - 1)
            st.point_set(1, 0, n - 1, p - 1, cur // x)
        else:
            l, r = map(int, tmp[1:])
            out.append(str(st.range_sum(1, 0, n - 1, l - 1, r - 1)))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```セグメント ツリーは最初の配列から 1 回構築されます。 各ノードは、合計と 1 に初期化された乗算遅延タグの両方を格納します。範囲乗算は両方の構造を一貫して更新するため、変換下でも合計は有効なままになります。 

除算クエリは、最初に遅延認識トラバーサルを使用してその位置の正確な値を取得し、次に整数除算を適用し、最後にツリーの一貫性を維持するためにポイント更新でそれを書き戻すことによって処理されます。 

範囲合計クエリは、格納された合計に完全に依存し、遅延伝播によって更新を拡張することなく正確性を保証します。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、同じ位置で乗算とそれに続く除算を繰り返すことです。 セグメント ツリーは、葉の正確な整数値を保持する必要があります。 そうしないと、値がモジュロでのみ追跡されると、除算が不整合になります。`mod`。 

もう 1 つのケースは、モジュラー逆数が存在しない合成数に等しいモジュラスです。 このソリューションでは、モジュロ ストレージを再適用する前に整数空間で除算を実行することで、逆算を完全に回避します。 

3 番目のケースは、大きな因数を使用した全範囲の乗算です。 遅延伝播により、すべての要素に直接触れることがなくなり、集計乗数のみが内部ノードに保存されるため、パフォーマンスの低下が防止されます。
