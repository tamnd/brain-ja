 ## 解決策
 ## 問題の理解

 この問題は、タップの速度に応じて時間の経過とともに増加または縮小する可能性がある初期の忍耐量を備えた「忍耐ボウル」をモデル化しています。 タップの速度はイベントによって不連続に変更できます。 特定の初期ボリュームから開始した場合、Sasha は、指定された時間間隔内で忍耐力がいつゼロに達するかをクエリできます。 イベント自体は時間的にはまばらであり、タイムスタンプから次のイベントまで (イベントがない場合は無期限に) 速度にのみ影響します。 クエリでは、イベントによって定義された段階的な一定の速度を考慮して、時間の経過に伴う忍耐の蓄積をシミュレートする必要があります。 

主な制約は、クエリの数です。`q`最大100,000回`t`最大 10^9、速度`s`範囲は -10^9 から 10^9 までです。 間隔が長くなる可能性があるため、これにより、毎秒にわたるブルートフォース シミュレーションが除外されます。 タイプ 3 の各クエリでは、潜在的に大きな範囲にわたって区分定数関数を統合する必要があります。 

最初の忍耐が必要な場合にエッジケースが発生します`v`タップ速度が忍耐力をゼロに減らさない場合、およびタイプ 3 クエリの間隔の開始後に最初のイベントが発生した場合、は非常に小さいかゼロになります。 たとえば、クエリが初期忍耐力 1 で 2 番目の 1 から 10 までを要求するが、最初のイベントの速度変化が負の速度の t=5 で発生する場合、デフォルトの速度 0 を使用する単純なシミュレーションでは、t=5 より前の期間を考慮できない可能性があります。もう 1 つの微妙なケースは、イベントが開始する瞬間に忍耐力がちょうど 0 に達する場合です。境界と浮動小数点演算に注意する必要があります。 

## アプローチ

 ブルートフォースアプローチでは、毎秒反復処理が行われます。`l`に`r`タイプ 3 の各クエリに対して、現在の速度を適用し、忍耐力がゼロに低下するかどうかを確認します。 これは正しいですが、間隔が最大 10^9 秒になる可能性があり、クエリが 10^5 あるため、最悪の場合は O(10^14) 操作が発生するため、遅すぎます。 

最適なアプローチは、イベント間のタップ速度が一定であるという観察を活用します。 一定速度の連続する各セグメントで忍耐力がいつゼロに達するかを計算するだけで済みます。 これにより、問題は、クエリ間隔に関連するイベントを反復処理し、一次方程式を解くことになります。`s`そして残りの忍耐力は`v`、ゼロまでの時間は`v/s`もし`s < 0`。 タイプ 1 およびタイプ 2 のクエリを効率的に処理するために、時間をキーにソートされた構造にイベントを格納し、それぞれ O(log n) での挿入、削除、および範囲クエリを許可します。 これにより、クエリごとの複雑さが O (秒単位の間隔の長さ) ではなく O (間隔内のイベントの数) に軽減されます。 

重要な洞察は、時間の経過に伴う忍耐の累積効果は区分的に線形であり、イベントの発生時にのみ傾きが変化するということです。 したがって、1 秒ごとにループするのではなく、イベントを順番に実行し、算術演算を適用することで、各クエリを正確にシミュレートできます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(q * (r-l)) | O(q) | 遅すぎる |
 | 最適 | O(q log q) | O(q) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 時間をキーとしたイベントのマップまたは順序付けられた辞書を維持します。 各エントリには速度が保存されます`s`それはその瞬間から始まります。 これにより、O(log n) 時間で挿入と削除が可能になり、ソートされた順序で反復できます。 
2. タイプ 1 クエリの場合、イベントを時間と速度とともにマップに挿入します。 
3. タイプ 2 クエリの場合は、マップからイベントを削除します。 
4. タイプ 3 クエリの場合`[l, r, v]`と重複するすべてのイベントを特定します。`[l, r]`。 事前にイベントがない場合`l`、最初のイベントまでは速度 0 であると仮定します。 これらのイベントを時系列順に繰り返します。 

4a. させて`curr_time`から始める`l`そして`curr_patience`で`v`。 

4b. 各イベントごとに、`t`スピードを持って`s`、次のイベントまでの期間、または次のイベントまでの期間を計算します。`r`。 速度が負であり、この期間内に忍耐力がゼロになる場合は、正確な秒を計算します。`burst_time = curr_time + curr_patience / abs(s)`そしてそれを返します。 

4c. それ以外の場合は更新してください`curr_patience += s * duration`そして前進する`curr_time`。 
5. インターバルの終わりの場合`r`忍耐力がゼロになることなく到達した場合は、-1 を返します。 

**効果がある理由:** いつでも、忍耐力は現在の速度に比例して増加します。 イベントは離散時間でのみ傾きを変更します。 関連するすべてのイベントを処理し、セグメント内で忍耐力がゼロに達する正確な瞬間を計算することで、シミュレーションは正確かつ効率的になります。 ソートされたマップを使用すると、すべてのセグメントが正しい順序で処理されます。 

## Python ソリューション```python
import sys
import bisect
input = sys.stdin.readline

from collections import OrderedDict

def main():
    q = int(input())
    events = OrderedDict()

    queries = []
    for _ in range(q):
        parts = input().split()
        queries.append(parts)

    # Maintain a sorted list of times for fast search
    times = []

    for parts in queries:
        if parts[0] == '1':
            t, s = int(parts[1]), int(parts[2])
            events[t] = s
            bisect.insort(times, t)
        elif parts[0] == '2':
            t = int(parts[1])
            del events[t]
            idx = bisect.bisect_left(times, t)
            times.pop(idx)
        else:
            l, r, v = int(parts[1]), int(parts[2]), int(parts[3])
            curr_time = l
            curr_patience = v

            # Find relevant events
            idx = bisect.bisect_left(times, l)
            if idx == 0:
                prev_speed = 0
            else:
                prev_speed = events[times[idx-1]]

            burst = -1

            while curr_time <= r:
                if idx < len(times):
                    next_time = times[idx]
                    speed = events[next_time]
                else:
                    next_time = r + 1
                    speed = prev_speed

                end_time = min(next_time, r + 1)
                duration = end_time - curr_time

                if prev_speed < 0:
                    time_to_zero = curr_patience / -prev_speed
                    if time_to_zero <= duration:
                        burst = curr_time + time_to_zero
                        break

                curr_patience += prev_speed * duration
                curr_time = end_time
                prev_speed = speed
                idx += 1

            if burst == -1:
                print(-1)
            else:
                print(f"{burst:.6f}")

if __name__ == "__main__":
    main()
```**説明:** 私たちは維持します`events`効率的な挿入と削除のための順序付けられた辞書内で、`times`高速範囲検索のためのソートされたリストとして。 タイプ 3 クエリの場合、間隔に重なるイベントを繰り返し、忍耐力に区分的線形更新を適用し、負の速度によってバースト時間が枯渇する可能性がある正確なタイミングでバースト時間を計算します。 最初のイベントの前の間隔は、デフォルトの速度 0 を使用して処理します。浮動小数点演算により、正しい小数バースト時間が保証されます。
