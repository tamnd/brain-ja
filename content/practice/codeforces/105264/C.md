 ## 解決策
 ## 問題の理解

 整数の配列が与えられ、限られた数の単位調整を実行できます。 各操作では 1 つの位置を選択し、その値を 1 だけ増減します。 せいぜい使用した後$k$このような操作では、値の多様性の観点から配列を可能な限り「均一」にすることが目標であり、配列内に残る個別の整数の数を最小限に抑えることを意味します。 

重要な自由は、すべての要素を同等にする必要がないことです。 異なる値の数を減らしたいだけなので、絶対差に等しいコストを払って、数値のグループを共通の値に近づけることによってそれらのグループをマージすることができます。 

制約は非常に明らかです。 テストごとの配列サイズは、すべてのテスト ケースの合計で最大 300 であるため、値に対する 2 次または 3 次の推論は問題ありません。 操作数$k$と同じ大きさにすることができます$10^{12}$これは、どのソリューションも段階的に運用をシミュレーションするのではなく、総コストの観点から推論する必要があることをすぐに示しています。 最小限の調整コストを効率的に計算し、予算内で統合できるグループの数を決定する必要があります。 

素朴な間違いは、貪欲に数値を最も頻度の高い値に向かって「プッシュ」できると考えることです。 これは、最適な結合値が既存の値であるとは限らず、グループ化の決定が相互作用するため、失敗します。 

たとえば、次のような配列を考えてみましょう。$[1, 10, 20]$小さなもので$k$。 貪欲な戦略ではすべてを 10 に変換しようとする可能性がありますが、最適な戦略では代わりに次のような 2 つのクラスターが形成される可能性があります。$[1, 10]$そして$[20]$予算に応じて。 もう 1 つの微妙なケースは、値が遠く離れているがまばらである場合です。 コストを正しく考慮しない限り、ソートされた順序で隣接するペアをマージすることが常に最適であるとは限りません。 

## アプローチ

 ブルートフォース ビューでは、最終的な個別のグループとして保持したい値を選択し、すべての要素をこれらのグループの 1 つに割り当て、選択した代表値に移動するコストを支払います。 グループを固定して選択した場合、ライン上のクラスタリング問題として最小コストを計算できます。 

どのグループを区別し続けるかを選択する方法が指数関数的に多く、グループごとに移動コストを計算する必要があるため、これはコストがかかります。 たとえ$n \le 300$、すべてのパーティションを列挙することは不可能です。 

重要な観察は、配列をソートした後、最適なグループが連続したセグメントに対応するということです。 それで終わると決めたら$g$個別の値の場合、ソートされた配列を効果的に分割しています。$g$各セグメントは、コストを最小化する単一の選択された値 (セグメントの中央値) にマージされます。 セグメントのコストは、その中央値に対する絶対差の合計となります。 

これにより、総コストが予算内に収まるように、ソートされた配列のパーティションをできるだけ少ないセグメントに選択することが問題になります。$k$。 以来$k$が大きい場合、コスト使用量を最大化するのではなく、セグメント数を最小限に抑えます。 

プレフィックス合計を使用してすべてのセグメントのコストを事前計算し、動的プログラミングを使用します。$dp[g][i]$最初にパーティション化するための最小コストです$i$要素を$g$セグメント。 答えは最小です$g$そのような$dp[g][n] \le k$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | ブルートフォース | 指数関数 | 指数関数 | 遅すぎる |

 ## アルゴリズムのチュートリアル

 まず、グループが直線上の間隔になるように配列を並べ替えます。これにより、コスト構造が凸型になり、適切に動作します。 

## アルゴリズムのチュートリアル

 1. 最適なグループ化で順序が尊重されるように、配列を非降順でソートします。 順序を超えて要素を混合すると、ソートされた構造内で再割り当てする場合と比較して、調整コストが常に増加するため、これは有効です。 
2. ソートされた配列のプレフィックスの合計を事前計算します。 これにより、前処理後に一定時間内にセグメント コストを高速に計算できます。 
3. セグメントごとに$[l, r]$、すべての要素を単一の値と等しくするための最小コストを計算します。 最適なターゲットは中央値要素であるため、コストを左右の部分に分割し、プレフィックスの合計を使用して計算します。 このステップではコスト表を作成します。 
4. 最初の状態を分割するための最小コストを計算する DP 状態を定義します。$i$要素を正確に入力する$g$グループ。 前回のカット位置を試してトランジション$j$、以前の最適なソリューションとセグメントのコストを組み合わせます$[j+1, i]$。 
5. 1 から 2 までのグループの可能な数を繰り返します。$n$、それぞれについて、アレイ全体に対して達成可能な最適なコストを計算します。 
6. コストが以下のグループの最小数$k$が答えです。 

重要な推論ステップは、一度並べ替えると、構造が線の分割に帰着し、セグメント内の最適なマージが常に中央値に達するということです。 

### なぜ効果があるのか

 ソートにより、交差割り当てにより不必要な距離が生じるため、コストを増加させることなく、最適なグループ化を連続セグメントに変換できます。 各セグメント内で、中央値は絶対偏差を最小化します。これは、セグメントの古典的な特性です。$L_1$ライン上の最適化。 DP は、考えられるすべてのセグメンテーションを調査し、次の構成が適用されることを保証します。$g$予算内で個別の最終値も可能ですので検討させていただきます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(n, k, arr):
    arr.sort()

    prefix = [0] * (n + 1)
    for i in range(n):
        prefix[i + 1] = prefix[i] + arr[i]

    def cost(l, r):
        m = (l + r) // 2
        median = arr[m]

        left_sum = median * (m - l + 1) - (prefix[m + 1] - prefix[l])
        right_sum = (prefix[r + 1] - prefix[m + 1]) - median * (r - m)
        return left_sum + right_sum

    INF = 10**18

    dp = [[INF] * n for _ in range(n + 1)]
    for i in range(n):
        dp[1][i] = cost(0, i)

    for g in range(2, n + 1):
        for i in range(n):
            best = INF
            for j in range(i):
                best = min(best, dp[g - 1][j] + cost(j + 1, i))
            dp[g][i] = best

    for g in range(1, n + 1):
        if dp[g][n - 1] <= k:
            return g

    return n

def main():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        arr = list(map(int, input().split()))
        print(solve_case(n, k, arr))

if __name__ == "__main__":
    main()
```コードは、配列を並べ替えることから始まります。これは、問題を間隔分割に限定するために不可欠です。 プレフィックス合計により、高速コスト評価に必要な定時間セグメント合計クエリが可能になります。 

の`cost(l, r)`関数は、中央値に基づく絶対偏差の式を実装します。 中央値インデックスでの分割により移動コストが最小限に抑えられ、プレフィックス合計によりセグメント合計を繰り返し再計算することが回避されます。 

DP テーブルは、グループの数に応じてソリューションを段階的に構築します。 各エンドポイントについて、以前のすべての分割ポイントを試します。$O(n^3)$複雑さが生じます。 以来$n \le 300$、これはまだ実現可能です。 

最後に、コストが以下を超えない最小数のグループをスキャンします。$k$、これは問題の目的と直接一致します。 

## 実用的な例

 ### 例 1

 入力:```
n = 4, k = 3
arr = [1, 2, 10, 11]
```ソートされた配列はすでに同じです。 

セグメントコストを計算します。 

| セグメント | 中央値 | コスト |
 | --- | --- | --- |
 | [1] | 1 | 0 |
 | [1,2] | 1 | 1 |
 | [10,11] | 10 | 1 |
 | [1,2,10] | 2 | 9 |
 | [2,10,11] | 10 | 9 |
 | [1,2,10,11] | 2 | 18 |

 ここで、DP はパーティションを考慮します。 

1 グループの場合、コストは 18 となり、現実的ではありません。 

2 つのグループの場合、最適な分割は [1,2] と [10,11]、コスト = 1 + 1 = 2 で、k に適合します。 

| グループ | 最高のコスト |
 | --- | --- |
 | 1 | 18 |
 | 2 | 2 |

 答えは2です。 

このトレースは、単一の中心を強制するのではなく、近さによってグループ化することが不可欠であることを示しています。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(n^3)$テストごと | 線形遷移によるグループおよびエンドポイントにわたる DP |
 | スペース |$O(n^2)$| すべてのプレフィックスとグループ数のコストを格納する DP テーブル |

 合計あり$n \le 300$、三次係数は制限内に留まります。 プレフィックス合計の最適化により、セグメント コストの計算に余分な要素が導入されなくなります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    def solve():
        t = int(input())
        out = []
        for _ in range(t):
            n, k = map(int, input().split())
            a = list(map(int, input().split()))
            a.sort()
            pref = [0]
            for x in a:
                pref.append(pref[-1] + x)

            def cost(l, r):
                m = (l + r) // 2
                med = a[m]
                left = med * (m - l + 1) - (pref[m+1] - pref[l])
                right = (pref[r+1] - pref[m+1]) - med * (r - m)
                return left + right

            INF = 10**18
            n = len(a)
            dp = [[INF]*n for _ in range(n+1)]
            for i in range(n):
                dp[1][i] = cost(0, i)

            for g in range(2, n+1):
                for i in range(n):
                    for j in range(i):
                        dp[g][i] = min(dp[g][i], dp[g-1][j] + cost(j+1, i))

            for g in range(1, n+1):
                if dp[g][n-1] <= k:
                    out.append(str(g))
                    break
        return "\n".join(out)

    return solve()

assert run("1\n5 100\n1 2 3 4 5\n") == "1", "large budget merges all"

 ## 特殊なケース

 主なエッジケースは次のような場合です$k = 0$。 この状況では調整は許可されないため、答えは単にすでに存在する個別の値の数になります。 すべてのセグメントのコストはゼロでなければならず、セグメントに同一の値が含まれている場合にのみゼロになるため、DP はこれを自然に処理します。 

もう 1 つの微妙なケースは、配列に大きなギャップがある場合です。$[1, 100, 101, 200]$。 単純な貪欲なマージでは、すべてを 1 つの値に近づけようとする可能性がありますが、最適なパーティショニングは次のような緊密なクラスターに分割します。$[100,101]$シングルトンは、セグメント コストがグローバル アトラクションではなく間隔ごとに正確に計算されるため、DP によってキャプチャされます。 

最後のエッジケースは次のような場合です$k$非常に大きく、最大で$10^{12}$。 これは数値オーバーフローの懸念を示唆する可能性がありますが、コストは次のように制限されているため、すべての計算は 64 ビットの範囲内に留まります。$n \cdot 10^9$、標準的な整数演算に安全に適合します。
