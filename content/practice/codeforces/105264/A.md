 ## 解決策
 ## 問題の理解

 私たちには、各プレーヤーが多くの「貢献」を報告するチームが与えられています。 貢献とは、得点したゴール、または他のプレーヤーのゴールを助けたアシストのいずれかです。 すべてのゴールには 1 人の得点者がおり、オプションで 1 人のアシスタントがいる場合もあります。 プレーヤーからの同じ貢献を、同じゴールの得点とアシストの両方に使用することはできず、各貢献は最終的な再構成で 1 回だけ使用されます。 

入力により、各プレーヤーが合計でどれだけの貢献を担当しているかがわかりますが、そのうちゴールやアシストが何回あったかはわかりません。 この部分的な情報から、合計で何ゴールが得点できたのか、具体的にはすべての選手の貢献数と一致する最小および最大のゴール数を決定する必要があります。 

主要な構造上の制約は、各ゴールが得点貢献を 1 つ消費し、オプションでアシスト貢献が 1 つ消費されることです。 これにより、分解の柔軟性が即座に制限されます。貢献度はグローバルに固定されますが、アシストとゴールの組み合わせは固定されません。 

すべての寄与度の合計は、テスト ケース全体で 3 · 10^5 に達する可能性があり、プレイヤーに対する二次推論や、ペアごとに寄与度を明示的に一致させようとする構築が除外されます。 テスト ケースごとに線形パスが必要です。 

すべての貢献が 1 人のプレイヤーに集中している場合、微妙なエッジケースが発生します。 たとえば、1 人の選手が 5 貢献度を持ち、他の選手全員が 0 貢献度を持っている場合でも、アシストがゴールを超えることはできないというルールを尊重する必要があります。 それらの間の一貫性を強制せずに、単に「それぞれの貢献が独立した目標または支援である」と仮定する単純なアプローチでは、支援される可能性のある構造が過大評価されてしまいます。 

もう 1 つの失敗例は、すべてのアシストが有効なゴールに関連付けられている必要があることを考慮せずに、貪欲にアシストを割り当てようとしたときに発生します。 たとえば、すべての貢献を自由にペアリングできるものとして扱うと、ゴールよりもアシストが多くなるという不可能な構成が生じます。 

## アプローチ

 ブルートフォース解釈では、A 合計貢献度のそれぞれをゴールまたはアシストとして割り当て、その結果の割り当てが有効なゴールにグループ化できるかどうかを検証します。 これは本質的に制約のある分割の問題になります。すべてのゴールには 1 つの得点者貢献と最大 1 つのアシスト貢献がなければなりません。 

最悪の場合、貢献にロールを割り当てる方法は 2^A 通りあり、無効な状態を早期に削除したとしても、構成の数は依然として A に応じて指数関数的に増加します。A が最大 3 · 10^5 であるため、これは完全に不可能です。 

重要な観察は、実際に重要な唯一のグローバルな制約は、合計の寄与と、そのうちのいくつをアシスト エッジにペアリングできるかのバランスであるということです。 各ゴールは、正確に 1 つの「必須ユニット」（得点者）と、オプションで 1 つの追加ユニット（アシスト）に貢献します。 したがって、G をゴール数、S を使用したアシスト数とすると、すべてのゴールは 1 つまたは 2 つの貢献を消費し、すべてを結び付ける単一の方程式が得られます。 

A = G + S

 構造的な制限は、すべてのアシストが何らかのゴールに属さなければならないため、S が G を超えることはできないということです。これにより、問題は組み合わせ代入問題ではなく、整数に対する単純な制限付き最適化になります。 

このことから、目標の最大化は S の最小化に対応し、目標の最小化は S ≤ G の下で S の最大化に対応します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースによる役割の割り当て | O(2^A) | O(A) | 遅すぎる |
 | 代数的制約の削減 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

1. すべての ai を合計して、貢献度 A の総数を計算します。 これは、ゴールとアシストに配分する必要がある「ユニット」の総数です。 
2. 各ゴールが少なくとも 1 ユニット、アシストがある場合は 2 ユニットを消費することに注意してください。 ゴールには変数 G を、アシストされたゴールには S を導入します。 
3. 各ゴールは 1 つのスコアラー ユニットに貢献し、各アシスト ゴールは 1 つの追加のアシスト ユニットに貢献するため、合計貢献度の制約を A = G + S として表します。 
4. すべてのアシストはゴールに属さなければならないという構造的制約を使用し、S ≤ G を強制します。 
5. G = A − S を不等式 S ≤ G に代入して S ≤ A − S を取得します。これは 2S ≤ A に簡略化されます。 
6. これから、S は整数でなければならないため、考えられる最大の S は Floor(A / 2) であると推定されます。 
7. ゴールの最小数を Gmin = A − Floor(A / 2) として計算します。これは ceil(A / 2) と同等です。 
8. S を最小化してゴールの最大数を計算します。これにより、S = 0 となり、Gmax = A となります。 

### なぜ効果があるのか

 貢献間の唯一の相互作用はアシストとゴールの組み合わせによるものであるため、構造全体が崩壊します。 個々の選手を抽象化すると、有効な構成はすべて、アシストと「ペアになった」ゴールの数によって完全に記述されます。 S ≤ G に違反する割り当てでは、ゴールよりも多くのアシストが必要になりますが、各アシストは個別のゴールに関連付けられる必要があるため、これは不可能です。 逆に、有効範囲内の任意の S は、S の貢献をアシストとしてペアにし、残りの貢献をアシストなしのゴールとして残すことによって実現できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        arr = list(map(int, input().split()))
        total = sum(arr)

        max_goals = total
        min_goals = (total + 1) // 2

        print(min_goals, max_goals)

if __name__ == "__main__":
    solve()
```この実装では、テスト ケースごとの寄与の合計を計算するだけですべてが削減されます。 合計がわかったら、残りのロジックは導出された式を直接評価します。 唯一の微妙な点は、合計の半分に整数の上限を使用し、(total + 1) // 2 として実装されており、これにより浮動小数点エラーが回避されます。 

## 実用的な例

 寄与が [3, 2, 1] として分散される入力を考えてみましょう。 合計は6です。 

最大の目標については、すべての貢献を個別の目標として扱い、6 つの目標を与えます。 

最小目標の場合、アシスト数を最大化しようとしますが、アシストが目標を超えることはできないという制約によって制限されます。 6 の半分は 3 なので、S = 3 アシスト ゴール、G = 3 合計ゴールとなります。 

| ステップ | 合計A | S が選ばれました | G = A − S |
 | --- | --- | --- | --- |
 | 開始 | 6 | 0 | 6 |
 | マックスSケース | 6 | 3 | 3 |
 | 結果 | 6 | 3 | 3 |

 これは、貢献度のちょうど半分をアシストとゴールの関係に組み合わせることで、ゴール数が最小限に抑えられることを示しています。 

次に[5]を考えてみましょう。 合計は5です。 

| ステップ | 合計A | S が選ばれました | G = A − S |
 | --- | --- | --- | --- |
 | 開始 | 5 | 0 | 5 |
 | マックスSケース | 5 | 2 | 3 |
 | 結果 | 5 | 2 | 3 |

 これは天井効果を示しています。1 つの貢献がアシストとペアになっていないため、追加の独立したゴールが強制されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque
    input_data = sys.stdin.read().strip().split()
    it = iter(input_data)

    t = int(next(it))
    out = []
    for _ in range(t):
        n = int(next(it))
        arr = [int(next(it)) for _ in range(n)]
        total = sum(arr)
        out.append(f"{(total + 1)//2} {total}")
    return "\n".join(out)

# minimum size
assert run("1\n1\n0\n") == "0 0"

# single player non-zero
assert run("1\n1\n5\n") == "3 5"

# all equal
assert run("1\n4\n1 1 1 1\n") == "2 4"

# mixed values
assert run("1\n3\n3 2 1\n") == "3 6"

# large balanced case
assert run("1\n5\n10 10 10 10 10\n") == "25 50"

 ## 特殊なケース

 貢献度がゼロの 1 人のプレーヤーは、最小値と最大値の両方がゼロになることを示しています。 アルゴリズムは合計 A = 0 を計算し、Gmin = (0 + 1) // 2 = 0 および Gmax = 0 を与え、これが可能な唯一の構成と一致します。 

1 人のプレーヤーの貢献度が奇数の場合、たとえば A = 5 の場合、アルゴリズムは Gmin = 3 を計算します。これは、最大 2 つのアシストをペアにすることができ、スタンドアロンの目標を形成する必要があるペアになっていない 1 つの貢献を残し、天井動作を正しく適用できるという事実を反映しています。 

すべてのプレーヤーが平等に貢献する場合 (たとえば、4 人のプレーヤーがそれぞれ 1 つの貢献をするなど)、合計は 4 で、最小値は 2 になります。これは、貢献を 2 つのアシスト ゴールにペアにすることに対応し、制約 S ≤ G が均等に飽和します。
