 ## 解決策
 ## 問題の理解

 n 個の頂点を持つツリーが与えられます。 正確に k 個の頂点を保持し、それらが引き起こす部分グラフを考慮することができます。 選択された頂点は引き続き接続されたツリーを形成する必要があるため、選択は元のツリーの接続された k ノードのサブツリーに効果的に制限されます。 

このような k 個の頂点のすべての選択肢の中で、最悪の場合に内部距離ができるだけ小さいものが必要です。 言い換えれば、選択した k 個のノード上で誘導されたツリーを取得し、最長の単純なパス上の頂点の数で測定されたそのツリーの直径を計算し、この直径を最小化したいと考えます。 

出力は単一の整数、つまりサイズ k のすべての接続されたサブツリーの中で可能な最小直径です。 

n ≤ 1000 という制約は十分小さいため、二次または三次アプローチはまだ合格する可能性がありますが、サブセットが約 2^1000 あるため、ノードのサブセットにわたる指数関数は直ちに実行不可能になります。 O(n^3) または O(n^2 log n) の解は許容されます。 

微妙な点は、任意の k 個のノードを選択することはできないことです。 選択したセットは接続されたサブツリーを誘導する必要があるため、元のツリーでは遠く離れているが、誘導された構造では切断されているノードを選択することは無効です。 これにより、接続が慎重に維持されない限り、貪欲な「最適なセンターを K 個選ぶ」という考えは排除されます。 

単純な誤解は、誘導された構造を無視して、元のツリー内のペアごとの最大距離を最小化するために k 個のノードを選択していると考えることです。 これにより、セットが切断され、より小さな値が誤って生成される可能性があります。 

## アプローチ

 この問題を考える直接的な方法は、サイズ k の考えられるすべての接続されたサブセットを考慮し、その直径を計算することです。 候補セットごとに、そのサブセットに限定されたすべてのペアの最短パスを計算したり、その中のすべてのノードから BFS を実行したりできます。 各サブセットはツリーを生成するため、隣接性が判明すると、その直径の計算は O(k) で実行できます。 

問題は、接続された k サブツリーを列挙することです。 DFS または BFS によってサブセットを拡大しようとしても、スターやパスなどの一般的なツリー形状では、そのようなサブセットの数は指数関数的に増加します。 パスでは、長さ k のすべての連続セグメントが有効で、これは O(n) ですが、スターでは、構造に注意しないと、サブセットの選択が組み合わせ的に大きくなります。 ブルートフォース列挙はすぐにノードのすべての組み合わせを試行することになりますが、これは不可能です。 

重要な観察は、どの木の直径も 2 つの端点によって制御されるということです。 2 つのノード u と v を、選択した k ノード サブツリーの潜在的なエンドポイントとして固定すると、それらを含む最適なサブツリーは、接続性を維持する方法で、u と v の間のパスに沿って、およびその周囲のノードを「埋める」ことを試みます。 最終的に誘導されたサブツリー内の u と v の間の距離は、本質的に直径を決定します。 

これは、問題を再構成することを示唆しています。k 個のノードを直接選択する代わりに、2 つのノード間の候補パスを検討し、そのパスをサブツリーの「背骨」として維持しながら、いくつのノードを含めることができるかを尋ねます。 ツリーをルート化し、距離を事前計算すると、ノードのペアごとに、それらを含む最小サブツリーの構造を評価できます。 そのサブツリー内のノードの数は、それらの間のすべての単純なパス上のすべての頂点の和集合のサイズであり、最小接続サブツリー内のノードを数えることと同じです。 

任意のペア (u、v) について、それらを接続する最小のサブツリーはそれらの間のパスの結合にすぎませんが、それは 2 つのエンドポイントにすぎません。 k 個のノードに到達するには、そのパスから外側に拡張する必要がありますが、拡張によって直径が増加するのは、より長いパスに沿って成長を強制する場合のみです。 したがって、最適な構造はパスの周りに「中心にある」サブツリーになる傾向があり、中心セグメントからの最大距離を最小限に抑えるように努めます。

これを形式化する標準的な方法は、答え D を二分探索し、直径が最大 D であるサイズ k の接続されたサブツリーが存在するかどうかを確認することです。固定 D の場合、サブツリーは、ある中心ノードまたはエッジの周囲の「半径 D/2」内に収まる必要があります。 これは古典的な木の半径と直径の関係です。木の直径 ≤ D は、すべてのノードが中心から ⌊D/2⌋ の距離内にある場合に限ります (奇数 D の場合、中心はエッジになります)。 

したがって、固定 D の場合、半径 r のボールに少なくとも k 個のノードが含まれるノードまたはエッジが存在するかどうかを尋ねます (r = D // 2)。 

これにより、問題はノードごとに、距離 ≤ r 内にノードがいくつあるかを計算するようになります。 さらに、D が奇数の場合は中心がエッジ上にある可能性があるため、各エッジを潜在的な中心として扱うことで中点も考慮します。 

O(n^2) 内のすべてのノードから BFS を介して距離を計算できますが、これで十分です。 次に、各候補中心について、半径 r 以内の到達可能なノードをカウントし、少なくとも k 以上に到達するノードがあるかどうかを確認します。 

したがって、最適解は、D に対する二分探索と O(n^2) の事前計算を組み合わせたものになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 接続されているすべての k サブツリーに対するブルート フォース | 指数 | O(n) | 遅すぎる |
 | 二分探索直径 + BFS 距離 | O(n^2 log n) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 すべてのノードから BFS を使用して、ツリー内のすべてのペアの最短パス距離を事前計算します。 グラフはツリーであるため、各 BFS は O(n) であり、合計は O(n^2) です。 

次に、答え D を 1 から n まで二分探索します。 

固定 D の場合、r = D // 2 と設定します。有効な中心が存在するかどうかを確認します。 

1. 各ノード u について、dist(u, v) ≤ r を満たすノード v の数を数えます。 そのようなカウントが少なくとも k であれば、u を中心として配置し、直径 ≤ D のサブツリーを構築できます。 
2. 奇数 D の場合、エッジ上にある中心も考慮する必要があります。 すべてのエッジ (u、v) について、中点の中心を想像します。 min(dist(u, w), dist(v, w)) ≤ r の場合、ノード w はこの中点の半径 r 内にありますが、より正確には、エッジ中心までの距離は、u または v を通過するパス上で min です。ツリーでは、これにより、w がいずれかの端点から r 内にあるかどうかを 1 段階の調整で簡単にチェックできます。これは、事前に計算された距離を使用して両方向を慎重にテストすることで処理できます。 
3. いずれかのノードまたはエッジ中心が条件を満たす場合、D は実現可能ですが、そうでない場合は実現できません。 
4. 実行可能な最小の D を二分探索します。 

この背後にある理由は、直径 D の木には中心 (ノードまたはエッジ) があり、すべてのノードがそこから ⌊D/2⌋ の距離内にあるためです。 逆に、そのような中心がその半径 r のボール内に少なくとも k 個のノードを持って存在する場合、それらの k 個のノードを選択することができ、それらは直径 ≤ D の接続されたサブツリーを形成します。 

これが機能する理由: 直径 D の接続されたすべてのサブツリーには、すべてのノードへの最大距離を最小化する中心があります。 その中心は、サブツリーのすべてのノードを含む半径 ⌊D/2⌋ のカバー ボールを引き起こします。 したがって、D の実現可能性は、何らかの有効な中心メトリックに少なくとも k 個のノードを含む半径 r のボールが存在することと同等であり、考えられるすべての中心をチェックすることにより、すべてのサブツリーが暗黙的にカバーされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import deque

n, k = map(int, input().split())
adj = [[] for _ in range(n)]
for _ in range(n - 1):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    adj[u].append(v)
    adj[v].append(u)

dist = [[0] * n for _ in range(n)]

def bfs(src):
    q = deque([src])
    d = [-1] * n
    d[src] = 0
    while q:
        u = q.popleft()
        for v in adj[u]:
            if d[v] == -1:
                d[v] = d[u] + 1
                q.append(v)
    dist[src] = d

for i in range(n):
    bfs(i)

def can(D):
    r = D // 2

    for u in range(n):
        cnt = 0
        du = dist[u]
        for v in range(n):
            if du[v] <= r:
                cnt += 1
        if cnt >= k:
            return True

    if D % 2 == 1:
        for u in range(n):
            for v in adj[u]:
                if u < v:
                    cnt = 0
                    for w in range(n):
                        duw = dist[u][w]
                        dvw = dist[v][w]
                        if min(duw, dvw) <= r:
                            cnt += 1
                    if cnt >= k:
                        return True

    return False

lo, hi = 1, n
ans = n
while lo <= hi:
    mid = (lo + hi) // 2
    if can(mid):
        ans = mid
        hi = mid - 1
    else:
        lo = mid + 1

print(ans)
```コードはまず、BFS を使用して各ノードからすべてのペアごとの距離を計算し、行列に格納します。 次に、実現可能性関数は、半径の特性評価を使用して、指定された直径境界が k ノードのサブツリーをサポートできるかどうかをチェックします。 

ノード中心チェックでは、各ノードから半径 r 以内にノードがいくつあるかをカウントします。 奇数直径のツリーの最適な中心はエッジ上にあるため、エッジ中心チェックは D が奇数の場合にのみ必要です。 

二分探索により、可能な最小の直径が絞り込まれます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque

    n, k = map(int, input().split())
    adj = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        adj[u].append(v)
        adj[v].append(u)

    dist = [[0] * n for _ in range(n)]

    def bfs(src):
        q = deque([src])
        d = [-1] * n
        d[src] = 0
        while q:
            u = q.popleft()
            for v in adj[u]:
                if d[v] == -1:
                    d[v] = d[u] + 1
                    q.append(v)
        dist[src] = d

    for i in range(n):
        bfs(i)

    def can(D):
        r = D // 2
        for u in range(n):
            if sum(1 for v in range(n) if dist[u][v] <= r) >= k:
                return True
        if D % 2 == 1:
            for u in range(n):
                for v in adj[u]:
                    if u < v:
                        cnt = 0
                        for w in range(n):
                            if min(dist[u][w], dist[v][w]) <= r:
                                cnt += 1
                        if cnt >= k:
                            return True
        return False

    lo, hi = 1, n
    ans = n
    while lo <= hi:
        mid = (lo + hi) // 2
        if can(mid):
            ans = mid
            hi = mid - 1
        else:
            lo = mid + 1

    return str(ans)

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、k = 1 の場合です。慣例により、任意の単一ノードはすでに直径 1 の有効なサブツリーです。 r = 0 の場合、各ノードはそれ自体をカウントするだけであり、D = 1 の場合には実現可能性が直ちに維持されるため、アルゴリズムはこれを処理します。 

もう 1 つのエッジ ケースは、k ≥ 2 の最適解が常に 2 である星型ツリーです。この状況では、中心ノードが半径 1 内のすべてのノードをカバーするため、二分探索はすぐに収束します。 ノードセンターがすでに実現可能性を支配しているため、エッジセンターロジックは必要ありません。 

最後の微妙なケースは、最適な構造が中心の周りのボールではなく、直感的にパス セグメントのように見える場合です。 そのような場合でも、直径を最小化するツリーは中央のノードまたはエッジの中心にあると見なされ、すべてのノードが対応する半径境界内に位置するため、半径ベースの特性評価は実現可能性を正しく捉えます。
