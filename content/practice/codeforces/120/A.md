 ## 解決策
 ## 問題の理解

 エレベーターに乗っている人について 2 つの情報が与えられています。 

最初の入力により、その人がどのドアに入ったか、つまり正面玄関か裏口かがわかります。 2 番目の入力は、その人がレール 1 またはレール 2 のどちらを保持していたかを示します。 

エレベーターは左右対称ですが、人がどちら側から入るかによって「左」と「右」の意味が変わります。 レール 1 は、正面玄関から入った場合は左側にありますが、裏口から入った場合は右側になります。 人は強い手でレールを握るので、VIP が左利きか右利きかを判断する必要があります。 

制約は非常に小さいです。 可能な入力の組み合わせは 4 つだけです。 

- フロント + レール 1
 - フロント + レール 2
 - バック+レール1
 - バック+レール2

 定数時間ソリューションはどれも十分な速度です。 すべての可能性を総当たりで検索しても、簡単に制限内に収まります。 

主な困難はパフォーマンスではなく、エレベーターの方向に関する混乱を避けることです。 不注意な実装では、レール番号が常に物理的に同じ側に対応していると想定する可能性がありますが、反対側のドアから入ると視点が変わるため、これは誤りです。 

この入力では、簡単な間違いが 1 つ発生します。```
back
1
```正しい答えは次のとおりです。```
R
```後ろから入る人には、レール 1 が左側ではなく右側に見えます。 常にレール 1 を左側にマップするソリューションでは、誤って印刷されます。`L`。 

もう 1 つの注意が必要なケースは次のとおりです。```
front
2
```正しい答えは次のとおりです。```
R
```正面入口から見て、レール 2 はライダーの右側にあります。 レール番号に基づいて左右を切り替えることを忘れると、間違った結果が生じます。 

## アプローチ

 ブルート フォース アプローチでは、考えられるすべての構成を手動でエンコードします。 ケースは 4 つしかないので、それぞれの条件ステートメントを直接書くことができます。 

例えば：

-`front + 1 -> L`-`front + 2 -> R`-`back + 1 -> R`-`back + 2 -> L`入力スペースが小さいため、これは機能します。 少数の比較のみを評価するため、時間計算量は一定です。 

ブルートフォースソリューションはすでに受け入れられていますが、ケースの背後にあるパターンを観察することでロジックをさらに単純化できます。 

正面から入る場合、レール番号は側面と直接一致します。 

- レール 1 は左手を意味します
 - レール 2 は右手を意味します

 後ろから入ると向きが逆になります。 

- レール1は右側になります
 - レール2は左側になります

 重要な観察は、答えはライダーの現在の視点からレールが左側に見えるか右側に見えるかによって決まるということです。 入口の方向によって、マッピングが正転か逆転が完全に決まります。 

これにより、4 つの組み合わせすべてを個別に扱うのではなく、問題を 1 つの単純な条件構造に減らすことができます。

 ## アルゴリズムのチュートリアル

 1. 玄関ドアを紐と読みます。 

値は次のいずれかです`"front"`または`"back"`。 
2. レール番号を読み取ります。 

値は次のいずれかです`1`または`2`。 
3. 人が正面玄関から入った場合は、レールを通常どおりに解釈します。 

レール 1 は左側にあるので、印刷します。`L`。 

レール 2 は右側にあるので、印刷します。`R`。 
4. 裏口から入った場合は、解釈を逆にします。 

レール 1 が右側にあるので、印刷します。`R`。 

レール 2 が左側にあるので、印刷します。`L`。 

### なぜ効果があるのか

 エレベーターの形状は固定されていますが、どの入り口を使用するかによってライダーの視点が変わります。 反対側から入ると左右の意味が入れ替わります。 

アルゴリズムは、この視点の変化を正確にモデル化します。 正面玄関の場合、レールの番号付けは自然な左から右の順序と一致します。 裏口の場合は順序が逆になります。 ライダーは常に強い方の手でレールを保持するため、レールの側面を識別することで、ライダーが左利きか右利きかを直接識別できます。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    door = input().strip()
    rail = int(input())

    if door == "front":
        if rail == 1:
            print("L")
        else:
            print("R")
    else:
        if rail == 1:
            print("R")
        else:
            print("L")

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    output = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return output

# provided sample
assert run("front\n1\n") == "L\n", "sample 1"

# custom cases
assert run("front\n2\n") == "R\n", "front entrance, right rail"
assert run("back\n1\n") == "R\n", "back entrance reverses orientation"
assert run("back\n2\n") == "L\n", "back entrance with second rail"
assert run("front\n1\n") == "L\n", "minimum valid configuration"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`front 2`|`R`| 正面玄関の正しいマッピング |
 |`back 1`|`R`| 視点反転の処理 |
 |`back 2`|`L`| 2 番目のレールの逆方向 |
 |`front 1`|`L`| 基本的な左側のマッピング |
