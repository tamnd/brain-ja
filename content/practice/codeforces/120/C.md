 ## 解決策
 ## 問題の理解

 蜂蜜の入った瓶がいくつかあり、各瓶にはある程度の量の蜂蜜が入っています。 ウィニーは、現在最も多くの蜂蜜が入っている瓶を繰り返し選択します。 

ウィニーが瓶を選ぶと、2 つのことが起こる可能性があります。 瓶の中身が以下の場合`k`キログラムの蜂蜜、またはウィニーがその瓶からすでに3回食べた場合、彼はその瓶に永遠に触れるのをやめ、残りの蜂蜜をピグレットに与えます。 そうでなければ、彼は正確に食べる`k`それからキロ離れていれば、瓶は将来のターンのために利用可能なままになります。 

このプロセスは、すべての瓶がピグレットに渡されるまで続きます。 ピグレットが最終的に受け取るハチミツの総量を計算する必要があります。 

制約はわずかです。 両方`n`そしてすべての`a[i]`せいぜい`100`。 直接シミュレーションでも十分に高速です。 蜂蜜の総量は最大でも`100 * 100 = 10000`、すべての食事動作により少なくとも 1 キロ体重が減ります。 最大検索を繰り返す単純なループでは、わずか数千回の操作しか実行されません。 

難しいのは、瓶がいつ取り外されるかを理解することです。 瓶は 3 回目の食事動作の直後には捨てられません。 ウィニーはちょうど 3 回瓶から食べることがあります。 jar は、後で再度選択された場合にのみ破棄されます。 

次の例を考えてみましょう。```
1 3
10
```ウィニーは 3 回食事をします。```
10 -> 7 -> 4 -> 1
```今、瓶はすでに3回食べられています。 再度選択すると、ピグレットに与えられます`1`残りキロ。 正しい答えは次のとおりです。```
1
```不用意に実装すると、3 回目の食事動作の直後に停止し、誤って与えられる可能性があります。`4`その代わり。 

もう 1 つの微妙なケースは、瓶がサイズよりも小さくなった場合に発生します。`k`いくつかの手術の後。```
1 5
14
```順序：```
14 -> 9 -> 4
```現在、瓶には次の量が含まれています`k`、ピグレットは受け取ります`4`。 答えはそうではありません`0`なぜなら、ウィニーは決して瓶を部分的に食べることがないからです。 

複数の jar が同じ最大値を共有する場合、もう 1 つのエッジ ケースが発生します。```
2 3
6 6
```どちらの瓶を最初に選択しても構いません。 各 jar は独立して動作するため、最終結果は依然として決定的です。 それぞれの瓶は、`0`2回お腹いっぱい食べた後、ピグレットは`0 + 0 = 0`。 

この観察は、シミュレーションよりもはるかに単純な解決策を示唆しています。 

## アプローチ

 最も直接的なアプローチは、説明どおりに Winnie をシミュレートすることです。 私たちはすべての瓶の中の現在のハチミツと、ウィニーが各瓶から何回食べたかを追跡します。 すべてのステップで、すべての jar をスキャンして現在の最大値を見つけます。 選択した瓶がすでに 3 回食べられている場合、または含まれている内容が以下の場合`k`、残りの蜂蜜を答えに追加し、考慮から外します。 それ以外の場合は減算します`k`そしてその食べるカウンタをインクリメントします。 

このシミュレーションは文字通りルールに従っているので正しいです。 これらの制約があるにもかかわらず、十分に高速です。 1 つの瓶につき、成功した食事動作は最大 3 回発生するため、最大でも 3 回しか成功しません。`3n`最大でも削減プラス`n`撤去。 すべてのステップですべての jar がスキャンされ、おおよその情報が得られます。`O(n^2)`操作。 

興味深い観察は、jar が互いに完全に独立していることです。 Winnie が同じまたは異なる jar を選択する順序は、個々の jar の最終的な残りには影響しません。 

単一の瓶の場合、`a[i]`ハニー:

 ウィニーがその量を下回るまでに 3 回未満しか食べられない場合`k`、ピグレットが受け取ります`a[i] mod k`。 

ウィニーが少なくとも 3 回食べることができれば、ウィニーは正確に取り除きます`3k`蜂蜜の合計が満たされると、瓶は次の選択時に破棄されます。 子豚が受け取ります`a[i] - 3k`。 

したがって、1 つの瓶に残っている蜂蜜は単純に次のようになります。```
max(a[i] - 3k, a[i] % k)
```さらにわかりやすい表現は次のとおりです。 

もし`a[i] < 3k`、ピグレットが得ます`a[i] % k`。 

そうしないと、ピグレットが`a[i] - 3k`。 

これにより、各 jar を 1 回処理するだけの問題が軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(n²) | O(n) | 承認済み |
 | 数学的観察 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む`n`そして`k`、次に、jar サイズの配列を読み取ります。 
2. に対する答えを初期化します。`0`。 
3. すべての jar を個別に処理します。 
4. 入っている瓶の場合`x`キロ:

 もし`x < 3 * k`, ウィニーは完全に食べる操作を 3 回完了することはできません。 彼は引き算をし続ける`k`可能な限り、そしてピグレットは最終的に残りを手に入れます`x % k`。 
5. それ以外の場合、ウィニーはこの瓶から正確に 3 回食べることに成功します。 

3 回の操作の後、瓶には次のものが含まれます。`x - 3k`。 次回、瓶が最大値になると、3 食制限に達したため、すぐにピグレットに渡されます。 
6. この瓶の正しい残りの量を合計の答えに加えます。 
7. 答えを印刷します。 

### なぜ効果があるのか

 それぞれの瓶は独立して進化します。 jar で実行できるアクションは減算のみです`k`または永久に削除します。 ウィニーは引き算ができる`k`どの瓶からでも最大 3 回まで。 

jar が以下で実行される場合`k`3 回の操作が行われるまでは、それ以上蜂蜜を食べることはできません。したがって、最終的な残りは正確に`x % k`。 

瓶が 3 回の操作に耐えた場合、Winnie は正確に削除します。`3k`蜂蜜の合計。 ルールではその瓶からそれ以上食べることは禁止されているため、残りの量は`x - 3k`ピグレットに直接行きます。 

すべての jar の最終的な寄与はそれ自体の初期値にのみ依存するため、これらの独立した結果を合計すると、正しい合計が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    ans = 0

    for x in a:
        if x < 3 * k:
            ans += x % k
        else:
            ans += x - 3 * k

    print(ans)

solve()
```最終的に残る蜂蜜は、ウィニーがその瓶から何回食べることができるかによってのみ決まるため、ソリューションは各瓶を個別に処理します。 

条件`x < 3 * k`が重要な観察です。 瓶の中身が以下の場合`3k`、ウィニーは削除できません`k`フルタイム3回。 残りの蜂蜜が少なくなったので、彼は最終的に止まります`k`、ピグレットは残りを受け取ります`x % k`。 

それ以外の場合、ウィニーはちょうど 3 つの食事動作を正常に実行します。 その後、同じ瓶からそれ以上食べることはできないルールなので、残った量は`x - 3 * k`。 

よくある間違いは、`<=`の代わりに`<`。 例えば：```
x = 9, k = 3
```ウィニーは正確に 3 回食べることができます。```
9 -> 6 -> 3 -> 0
```子豚が受け取ります`0`、 ない`9 % 3`偶然に。 厳密な不等式はこれを正しく処理します。 

すべての算術演算は、標準の Python 整数内に快適に収まります。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    ans = 0

    for x in a:
        if x < 3 * k:
            ans += x % k
        else:
            ans += x - 3 * k

    print(ans)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out.strip()

# provided sample
assert run("3 3\n15 8 10\n") == "9", "sample 1"

# minimum size
assert run("1 1\n1\n") == "0", "minimum case"

# exactly three full eats
assert run("1 3\n9\n") == "0", "exactly 3 operations"

# becomes smaller than k
assert run("1 5\n14\n") == "4", "remainder case"

# all equal values
assert run("4 2\n7 7 7 7\n") == "4", "all equal"

# maximum style values
assert run("3 1\n100 100 100\n") == "291", "large values"
```| テスト入力 | 期待される出力 | 検証内容 |

 ## 特殊なケース

 瓶がちょうど 3 回から食べられる場合を考えてみましょう。 

入力：```
1 3
10
```実行：```
10 -> 7 -> 4 -> 1
```この時点で、ウィニーはすでに 3 回食べているので、残りは`1`キロはピグレットに行きます。 アルゴリズムは以下をチェックします。```
10 >= 3 * 3
```ピグレットは次のように受け取ります。```
10 - 9 = 1
```これはシミュレーションと正確に一致します。 

ここで、3 回の操作を行う前に小さくなりすぎる瓶について考えてみましょう。 

入力：```
1 5
14
```実行：```
14 -> 9 -> 4
```残りの金額は以下の通りです`k`、それでピグレットは得ます`4`。 アルゴリズムは以下を使用します。```
14 < 15
```そして以下を計算します:```
14 % 5 = 4
```それは正しいです。 

最後に、複数の等しい最大値の jar を考慮します。 

入力：```
2 3
6 6
```各瓶は独立して進化します。```
6 -> 3 -> 0
```子豚が受け取ります`0`各瓶から最終的な答えを求めます`0`。 

Winnie が等しい瓶の中から選択する順序によって、最終的な残量が変わることはありません。そのため、瓶ごとの独立した式が有効です。
