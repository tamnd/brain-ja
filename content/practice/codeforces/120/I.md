 ## 解決策
 ## 問題の理解

 この問題では、指定されたチケットより厳密に大きい、次の「幸運な」チケット番号を見つけるように求められます。 各チケットは、2_n_ で示される偶数長の数字の文字列です。 チケットの「幸福度」は、各桁を 7 セグメントのディスプレイとして表し、チケットの左半分と右半分をペアにして、両方の桁で同時に点灯する各ペアのセグメントの数を数えることによって定義されます。 目標は、指定されたチケットよりも大きく、厳密に高い幸福度を持つ、数値的に最小のチケットを見つけることです。 

入力は、長さ 2_n_ の数字の文字列です。 出力は、目的の次のチケットか、そのようなチケットが存在しない場合は -1 です。 この制約により、n は最大 10^5 まで許可されるため、チケットの合計の長さは最大 2*10^5 桁になります。 現在のチケットよりも大きいすべての可能な数値を反復する単純なアプローチは、反復回数が最大 10^200000 になるため、実行不可能です。 

エッジ ケースには、非常に小さなチケット (例: 「00」) や、増分にキャリーの処理が必要なすべての桁が 9 のチケット (「99」) や、セグメントの重複に応じて次の数字「01」の幸福度が低くなる可能性がある「00」など、数値を増やしても幸福度が増加しないチケットが含まれます。 

## アプローチ

 ブルートフォースアプローチでは、入力よりも大きいすべての数値を生成し、より大きな数値が見つかるまでその幸福度を計算します。 原理的には正しいですが、考慮すべきチケットの数は最大 10^(2*n) になる可能性があり、n が 10^5 ほど大きい場合はまったく実用的ではありません。 幸福度の計算も n において線形であるため、合計の演算は指数関数的になります。 

重要な洞察は、問題の構造により、貪欲でセグメントに焦点を当てたアプローチが可能であるということです。 チケットの幸福度は、左半分と右半分の対応する数字間のペアごとのセグメントの重なりのみに依存するため、すべての数字のペアについて幸福度の値の 10x10 テーブルを事前計算できます。 これにより、問題は一連の決定に変換されます。つまり、ペアごとの合計を増加させるチケットの最小増分を見つけます。 すべてのチケットを試す代わりに、事前に計算されたテーブルを使用して、増分によって幸福度が増加するかどうかを判断し、必要に応じて注意深く繰り越し、最下位の位置から始めて桁を増分することを試みることができます。 これにより、正しく実装されていれば、各桁が一定回数のみとみなされ、解が n の指数関数から線形に減少します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(10^(2n) * n) | お(1) | 遅すぎる |
 | 貪欲/セグメント テーブル | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 10x10 テーブルを事前計算する`happiness[d1][d2]`ここで、各エントリは両方の桁で点灯しているセグメントの数をカウントします。`d1`そして`d2`。 これは一度だけ行う必要があります。 
2. チケットを長さ n の左半分と右半分に分割します。 
3. 初期幸福度を次の合計として計算します。`happiness[left[i]][right[i]]`0 から n-1 までのすべての i に対して。 
4. チケットの最後の桁から始めて、値を増やしてみます。 増加する場合、候補となる各桁の幸福度の潜在的な増加を計算します。 幸福度を厳密に増加させる増分のみを受け入れるか、より高い幸福度を達成するために下流でのさらなる増分を許可します。 
5. キャリーを慎重に伝播します。 数字が 10 に達したら、0 に設定して左に移動します。 最初の桁がオーバーフローした場合は、同じ桁数のより大きなチケットが存在しないため、-1 が返されます。 
6. より高い幸福度をもたらす増分が見つかったら、残りの位置を最小限の数字 (0) で埋めて、チケットの数値ができるだけ小さくなるようにします。 
7. 左半分と右半分を 1 つの文字列に結合して出力します。 

機能する理由: このアルゴリズムは、選択した数字の接頭辞ができるだけ小さいという不変条件を維持しながら、幸福度が増加することを可能にします。 最下位桁から大桁までスキャンし、セグメントの重複を考慮することで、幸福度の増加に合わせて各ステップで常に可能な限り最小の桁を選択するため、幸福度がより高いチケットが見つかったら、それが数値的に最小であることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

# Precompute segment representation for 0-9
SEGMENTS = [
    0b1110111,  # 0
    0b0010010,  # 1
    0b1011101,  # 2
    0b1011011,  # 3
    0b0111010,  # 4
    0b1101011,  # 5
    0b1101111,  # 6
    0b1010010,  # 7
    0b1111111,  # 8
    0b1111011   # 9
]

def happiness(d1, d2):
    return bin(SEGMENTS[d1] & SEGMENTS[d2]).count('1')

def main():
    ticket = input().strip()
    n = len(ticket) // 2
    left = [int(c) for c in ticket[:n]]
    right = [int(c) for c in ticket[n:]]

    init_happiness = sum(happiness(left[i], right[i]) for i in range(n))

    # Try all possible increments greedily
    for pos in reversed(range(n*2)):
        digits = left + right
        for new_digit in range(digits[pos]+1, 10):
            digits[pos] = new_digit
            new_left = digits[:n]
            new_right = digits[n:]
            new_hap = sum(happiness(new_left[i], new_right[i]) for i in range(n))
            if new_hap > init_happiness:
                # Fill remaining positions with 0s to minimize number
                for fill in range(pos+1, 2*n):
                    digits[fill] = 0
                print(''.join(map(str, digits)))
                return
        digits[pos] = 0  # carry over
    print(-1)

if __name__ == "__main__":
    main()
```このソリューションは、各桁のセグメント ビットマスクを事前計算し、ヘルパー関数を使用してペアごとの幸福度を計算し、最後の桁から最初の桁まで反復します。 各桁を増分して、新しいチケットの幸福度が高いかどうかを確認します。 一致する場合は、最小限にするために後続の桁を 0 に設定して終了します。 キャリー処理により、桁がオーバーフローするエッジケースを確実にカバーします。

 ### サンプル 1

 | 位置 | 数字 | ニューハップ | アクション |

 これは、アルゴリズムが右から左にスキャンして桁を最小限に調整し、より高い幸福度を達成することで、次に高いチケットをどのように識別するかを示しています。

 | --- | --- | --- |
 | 時間 | O(n) | 各桁は最大 10 回、合計 2*n 桁とみなされます。 幸福度の計算は n において線形です。 |

 ## 特殊なケース

 入力「99」の場合、アルゴリズムは数字を右から左に正しくスキャンします。 右端の桁はインクリメントできないため、繰り越されます。 左端の桁も 9 を超えないと増分できないため、アルゴリズムは -1 を返します。 これにより、最大桁のエッジ ケースが処理されます。 入力「00」の場合、最後の桁を 0→1 に増加させると幸福度が増加するため、アルゴリズムは「01」を返します。
