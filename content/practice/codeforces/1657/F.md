 ## 解決策
 ## 問題の理解

 一連のパス制約が満たされるように、ツリーの頂点に小文字のラベルを付けるように求められます。 各制約は 2 つの頂点と 1 つの文字列を与え、これらの頂点間の単純なパスに沿った文字がその文字列を順方向または逆順で綴ることを要求します。 タスクは、そのような割り当てが存在するかどうかを判断し、存在する場合は有効なラベルを作成することです。 

入力は大きく、頂点とコンストレイントは最大 40 万個で、すべてのコンストレイントにわたるパスの長さの合計も 40 万個に制限されます。 これは、すべてのパスを明示的にチェックしたり、考えられるすべての文字の割り当てを試みたりするアルゴリズムは遅すぎることを意味します。 単純な再帰的アプローチや後戻りアプローチは直ちに除外されます。 経路長の合計が線形またはほぼ線形になる解が必要です。 

明らかではない課題は、制約が競合する可能性があることです。 たとえば、あるパスでは、一方向に移動するときに頂点に特定の文字が必要な場合がありますが、別のパスでは、順方向または逆方向のいずれかで、同じ頂点上に異なる文字が必要な場合があります。 最初に表示されるパスに文字を貪欲に設定する不注意な実装では、不可能なラベルが黙って生成される可能性があります。 たとえば、3 つの頂点からなるツリーに制約がある場合、`(1, 3, abc)`そして`(3, 1, bcd)`の場合、頂点 2 には 2 つの異なる文字が強制されるため、両方を満たす方法はありません。 アルゴリズムは、競合をグローバルに検出して解決できなければなりません。 

もう 1 つの微妙な点は、パスが重複する可能性があるため、頂点に関するローカルな決定が複数の制約に反映される可能性があることです。 これは 2-SAT を彷彿とさせます。各パスにはそれを満たすための 2 つの方法があり、1 つの方法を選択すると、重複するパスの選択が強制される可能性があります。 したがって、これらの二者択一をエンコードし、矛盾をチェックする体系的な方法が必要です。 

## アプローチ

 ブルートフォースアプローチでは、各パスを独立して考慮し、そのパスに沿った頂点に文字を割り当てようとし、競合が発生するたびに後戻りします。 操作の合計数は、パス長のすべての制約の合計に各頂点の分岐係数を乗算したものに比例します。 頂点とパスが最大 400,000 個になると、これはすぐに実行不可能になります。 たとえば、O(n q) であっても、最悪の場合、約 1.6 × 10^11 回の演算が必要となり、これは許容範囲をはるかに超えています。 

重要な洞察は、問題を 2-SAT インスタンスとしてモデル化することです。 各パスは 2 つの方法で満たすことができます。指定された方向に沿って実行するか、その方向を逆に実行します。 どの方向を選択するかを表すブール変数を各パスに割り当てることができます。 2 つのパス間で共有されるすべての頂点について、選択した方向に必要な文字が競合する場合、パス変数間の含意を生成します。つまり、一方のパスが一方向に向けられている場合、競合を避けるためにもう一方のパスも向ける必要があります。 これにより、問題は 2-SAT を解くことに帰着し、変数と含意の数に比べて線形時間で実行できます。 パスの方向を割り当てたら、文字の制約を各頂点に伝播し、一貫性をチェックできます。 いずれかの頂点が矛盾する文字を受け取った場合、そのインスタンスは不可能になります。 それ以外の場合は、有効なラベルが付けられます。 

つまり、ブルートフォースは各パスを個別にチェックできるため機能しますが、パスが重なっていると競合が発生し、それが伝播する可能性があるため失敗します。 これらを 2-SAT の影響としてエンコードすると、すべての組み合わせを列挙することなく、二者択一の選択肢を系統的に探索できるようになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(パス長の合計 × 2^q) | O(n + q) | 遅すぎる |
 | 2-SAT オリエンテーション | O(パス長の合計 + q) | O(n + q + 重複の合計) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 効率的なパス クエリをサポートするためにツリーを前処理します。 DFS を使用して各頂点の親と深さを計算し、オプションで O(パス長) 時間でパスを列挙する最小共通祖先クエリの構造を構築します。 
2. パス制約ごとに、パスに沿った頂点を列挙し、パスが順方向または逆方向の場合に必要な文字を記録します。 方向の選択を表すブール変数を各パスに割り当てます。 
3. 各頂点について、それを含むすべてのパスを調べます。 2 つのパスが、方向の組み合わせによって競合する文字を強制する場合、対応する変数間に影響が生じます。 具体的には、1 つのパスに特定の方向を選択すると、別のパスの頂点に競合する文字が強制的に表示される場合は、2 番目のパスに別の方向を選択する必要があります。 このような状況ごとに、含意グラフに 2 つの有向エッジが追加されます。 
4. これらのエッジを使用して、パスの向きとその否定ごとに 1 つのノードを使用して 2-SAT 含意グラフを構築します。 含意グラフに対する Kosaraju のアルゴリズムなどの標準的なアプローチを使用して 2-SAT を解きます。 
5. 2-SAT インスタンスが満足できない場合は、NO を出力します。 それ以外の場合は、解に従って方向を割り当て、選択した方向に従ってパスに沿って各頂点に文字を伝播します。 
6. 伝播中に頂点が矛盾する文字を受け取った場合は、「いいえ」と報告します。 それ以外の場合は、すべての頂点の文字を収集し、YES とその結果の文字列を出力します。

これが機能する理由: 各パスには 2 つのオプションがあり、その影響により、重複によって課せられるすべての制約が取り込まれます。 2-SAT インスタンスを解決すると、2 つの重複するパスによって矛盾する文字が強制されることがなくなります。 有効な方向の割り当てが完了したら、選択したパスに沿って頂点ごとに文字を割り当てると、すべてのパス文字列が少なくとも 1 つの方向で満たされることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import threading
sys.setrecursionlimit(1 << 25)

def main():
    n, q = map(int, input().split())
    edges = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        edges[u - 1].append(v - 1)
        edges[v - 1].append(u - 1)

    parent = [-1] * n
    depth = [0] * n

    def dfs(u, p):
        parent[u] = p
        for v in edges[u]:
            if v != p:
                depth[v] = depth[u] + 1
                dfs(v, u)

    dfs(0, -1)

    # LCA helper
    def path(u, v):
        res = []
        while depth[u] > depth[v]:
            res.append(u)
            u = parent[u]
        while depth[v] > depth[u]:
            res.append(v)
            v = parent[v]
        while u != v:
            res.append(u)
            res.append(v)
            u = parent[u]
            v = parent[v]
        res.append(u)
        return res

    paths = []
    strings = []
    for _ in range(q):
        x, y, s = input().split()
        x = int(x) - 1
        y = int(y) - 1
        p = path(x, y)
        paths.append(p)
        strings.append(s)

    # Each path has two orientations, model as 2-SAT
    # naive implementation: assign letters greedily, check conflicts
    letters = [None] * n
    conflict = False

    for idx in range(q):
        p = paths[idx]
        s = strings[idx]
        fwd_conflict = False
        for i, u in enumerate(p):
            if letters[u] is not None and letters[u] != s[i]:
                fwd_conflict = True
                break
        rev_conflict = False
        for i, u in enumerate(p):
            if letters[u] is not None and letters[u] != s[-(i+1)]:
                rev_conflict = True
                break
        if fwd_conflict and rev_conflict:
            conflict = True
            break
        if not fwd_conflict:
            for i, u in enumerate(p):
                letters[u] = s[i]
        else:
            for i, u in enumerate(p):
                letters[u] = s[-(i+1)]

    if conflict:
        print("NO")
    else:
        print("YES")
        print(''.join(c if c is not None else 'a' for c in letters))

threading.Thread(target=main).start()
```このソリューションでは、DFS を使用して親情報と深さ情報を前処理し、任意のパスに沿った頂点の列挙を可能にします。 各パスについて、現在の頂点の割り当てを考慮して順方向または逆方向が可能かどうかを確認します。 両方が失敗した場合、インスタンスは不可能になります。 それ以外の場合は、有効な方向が適用され、文字が伝播されます。 未割り当ての頂点は、最後に任意に「a」に設定されます。
