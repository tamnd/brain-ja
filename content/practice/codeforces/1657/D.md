 ## 解決策
 ## 問題の理解

 Monocarp が一連のモンスターと戦うために分隊を募集する戦略ゲームのシナリオがあります。 各戦闘は空の分隊から始まり、Monocarp は最大で`C`戦闘ごとのコイン。 各ユニットのタイプにはコスト、1 秒あたりのダメージ、体力があります。 各モンスターには 1 秒あたりのダメージと合計体力があります。 戦闘は同時進行で行われます。つまり、Monocarp が勝利するのは、モンスターがチームの 1 ユニットを殺すよりも厳密に早くモンスターを倒した場合のみです。 

入力により、次の詳細が提供されます。`n`ユニットタイプと`m`モンスター。 出力では、モンスターごとに、Monocarp が勝つために費やす必要のある最小コインを報告する必要があります。 範囲内に組み合わせがない場合`C`コインが勝利をもたらします、私たちは戻ります`-1`。 

制約を考慮すると、`n`そして`m`まで可能です`3 * 10^5`コイン制限は最大`10^6`。 これにより、すべてのモンスターのタイプごとにすべてのユニット数を反復する単純なアプローチが除外されます。これには、潜在的に必要となる可能性があるためです。`O(n * C * m)`操作が大きすぎます。 

特定のタイプの単一のユニットでモンスターを倒すことができるが、複数のユニットの方がコストが安い場合、明らかではないエッジケースが発生します。 たとえば、安価なユニットはモンスターを倒すのに 5 枚のコピーが必要で、コストは 50 コインですが、高価だが強力なユニットはコピーが 1 つだけ必要で、コストは 30 コインです。 条件を満たす最初の型を常に採用する不用意な解法は、次善の答え、または不可能な答えを返す可能性があります。 

## アプローチ

 ブルート フォース アプローチでは、各ユニット タイプを考慮し、コイン制限内で採用できるユニットの数をすべて試します。 組み合わせごとに、モンスターがユニットを殺す前に分隊がモンスターを殺すかどうかをチェックします。 これは正確に機能しますが、最大で反復処理が行われるため、非常に遅すぎます。`C`それぞれのコイン`n`ユニットと`m`モンスターによる最悪の場合の操作回数は`O(n * C * m)`。 

重要な洞察は、戦闘状態がモンスターの体力に対する分隊の合計ダメージとユニットの体力に対するモンスターの合計ダメージの比率に依存するということです。 させて`k`タイプの単位数になります`i`。 分隊は怪物を倒す`H_j / (k * d_i)`数秒以内にモンスターがユニットを倒す`h_i / D_j`秒。 勝利には必要なもの`H_j / (k * d_i) < h_i / D_j`、これを単純化すると、`k > H_j * D_j / (h_i * d_i)`。 したがって、ユニットの種類ごとに、特定のモンスターを倒すために必要なユニットの最小数を計算できます。 対応する費用は、`ceil(k) * c_i`。 すべてのユニット タイプにわたって最小限のコストのみが必要です。 

なぜなら`C`まで可能です`10^6`、反復`k`直接は不要です。 コイン数ごとに達成可能な最大ダメージを事前に計算することで、次のような質問に答えることができます。`O(log C)`探索によるモンスターごとの時間。 ソートしてプレフィックスの最大値を維持する`damage * health`支配的な単位タイプ (より高価ですが、厳密には悪いもの) が答えに影響を与えないようにします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * C * m) | O(n * C) | 遅すぎる |
 | 最適 | O(n + C + m * log C) | O(C) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を初期化する`best`サイズの`C + 1`最高のものを追跡するために`damage * health`コインごとに最大で達成可能`C`。 最初はすべてのエントリをゼロに設定します。 
2. すべてのユニットタイプを繰り返します。 ユニットタイプごとにコストがかかる`c_i`、 ダメージ`d_i`、そして健康`h_i`、計算する`d_i * h_i`。 アップデート`best[c_i]`現在の値の最大値になり、`d_i * h_i`。 これにより、コストごとに最も効果的な単一ユニットのタイプがわかります。 
3. プレフィックスの最大値を`best`配列。 1 から 1 までのすべてのコインの価値について`C`、 セット`best[i] = max(best[i], best[i-1])`。 これにより、あらゆるコインの予算に対して、手頃な価格の最適なユニット タイプがわかります。 
4. モンスターごとに`D_j`そして`H_j`、計算する`threshold = H_j * D_j`。 ここでは最小のコイン数が必要です`k`そのような`best[k] > threshold`。 二分探索を実行します。`best`1 から 1 までの配列`C`。 
5. 有効な場合`k`見つかった、出力`k`。 それ以外の場合は出力`-1`。 

機能する理由: 戦闘状態が以下に減少します。`k * d_i * h_i > H_j * D_j`。 最大値を事前に計算することにより、`d_i * h_i`コイン数ごとにプレフィックス maxima を使用すると、不等式を満たす最小のコイン支出を検索することで、各モンスター クエリに答えることができることが保証されます。 支配的なユニットタイプはコインコストを最小値以下に下げることができません`k`見つかった。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, C = map(int, input().split())
best = [0] * (C + 1)

for _ in range(n):
    c, d, h = map(int, input().split())
    value = d * h
    if best[c] < value:
        best[c] = value

for i in range(1, C + 1):
    best[i] = max(best[i], best[i - 1])

m = int(input())
monsters = [tuple(map(int, input().split())) for _ in range(m)]
res = []

for D, H in monsters:
    left, right = 1, C
    ans = -1
    threshold = D * H
    while left <= right:
        mid = (left + right) // 2
        if best[mid] > threshold:
            ans = mid
            right = mid - 1
        else:
            left = mid + 1
    res.append(str(ans))

print(" ".join(res))
```最初のループは、`best`最大値を含む配列`d*h`コストあたりの価値。 2 番目のループでは、プレフィックス maxima を構築して、どのようなコイン予算でも最も効果的なユニットにアクセスできるようにします。 二分探索では、モンスターのしきい値を満たす最小のコイン支出がチェックされます。 整数演算を使用すると浮動小数点エラーが回避され、伝播の順序により、モンスターに勝つ可能性のある安価なユニット タイプを見逃すことがなくなります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + C + m * log C) | 構築する`best`O(n) で、O(C) でプレフィックス最大値、O(log C) で各モンスターの二分探索 |
 | スペース | O(C + m) |`best`配列サイズ C+1、モンスターリストサイズ m |

 このアルゴリズムは、n、m ≤ 3*10^5、C ≤ 10^6 の場合に効率的です。 二分探索により、最大数のモンスターであっても許容可能な時間内に処理されることが保証されます。
