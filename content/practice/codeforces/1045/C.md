 ## 解決策
 ## 問題の理解

 最大 10 万の頂点と最大 50 万のエッジを持つ接続された無向グラフが与えられます。 各クエリでは、指定された 2 つの頂点間の最短パス長 (エッジの数で測定) が求められます。 

重要な追加の制約により、グラフの構造が変わります。 すべての単純なサイクルには、そのサイクル上のすべての頂点がペアで接続されているという特性があります。 言い換えれば、あらゆるサイクルは単なるサイクルではなく、接続性という点ではクリークでもあります。 このプロパティにより、グラフはアーティキュレーション ポイントに沿って接着されたクリークの集合のように動作します。これはまさに、すべてのブロックがクリークであるブロック分解の定義構造です。 

タスクは、最大 20 万の最短パス クエリに効率的に答えることで、クエリごとのグラフ検索を排除します。 クエリごとの BFS または DFS にはそれぞれおよそ O(N + M) のコストがかかり、最悪の場合、許容範囲をはるかに超えてしまいます。 すべてのペアの最短パスのマルチソース前処理でさえ、時間とメモリの両方の制約により不可能です。 

グラフに大きく密なコンポーネントが含まれている場合、微妙なエッジ ケースが発生します。 たとえば、すべてのノードが 1 つのクリークを形成している場合、2 つの異なるノード間の答えは常に 1 になります。 単純な最短パス アルゴリズムでは、不必要な構造をたどることになり、クエリごとに時間が無駄になります。 もう 1 つのエッジ ケースはツリー状の構造で、答えは単純にツリーの距離です。 難しいのは、木の端とクリーク ブロックの混合物を一貫して処理することにあります。 

## アプローチ

 各クエリに対するブルート フォース アプローチは、ターゲットに到達するまでソース ノードから BFS を実行することです。 重み付けされていないグラフ上の BFS は最短のパス長を返すため、これは正しいです。 ただし、最悪の場合、各 BFS はすべての頂点とエッジに接触する可能性があるため、Q クエリの処理には O(Q(N + M)) のコストがかかり、入力制限には​​大きすぎます。 

重要な観察は、特殊なサイクル条件から得られます。 すべての単純なサイクルがクリークを形成する場合、グラフは、各コンポーネントが完全なグラフである二重接続コンポーネントに分解できます。 これは、各ブロック内で任意の 2 つの頂点の距離が 1 であることを意味します。 ブロック間では、関節点を介して動きが強制され、ブロックのツリー構造が形成されます。 

これにより、各コンポーネントがクリークであるコンポーネントのツリーに対する距離クエリの問題が軽減されます。 ブロックカットツリーを構築します。各ブロックはノードであり、アーティキュレーションポイントがブロックを接続します。 元の 2 つの頂点間の距離は、ブロック内のショートカット効果ごとにマイナス 1 の調整を加えて、このツリー内の対応するノード間の距離になります。 これは、深さの事前計算を備えた最小共通祖先 (LCA) を使用して処理できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとのブルート フォース BFS | O(Q(N + M)) | O(N + M) | 遅すぎる |
 | ブロックカットツリー+LCA | O((N + M) + Q log N) | O(N + M) | 承認済み |

 ## アルゴリズムのチュートリアル

1. スタックを備えた DFS を使用して、グラフを二重接続コンポーネントに分解します。 DFS のローリンク状態が見つかるたびに、頂点のブロックが抽出されます。 これが機能する理由は、アーティキュレーション構造がアーティキュレーション分割なしで最大部分グラフを自然に分離するためです。 
2. ブロックごとに、そのブロック内のすべての頂点をそのブロックを表す仮想ノードに接続します。 これにより、元の頂点とブロック ノードの間に 2 部構造が作成されます。 この変換は、ブロック ノードを通る 1 ステップとしてクリーク内距離をエンコードします。 
3. これらの接続からツリーまたはフォレスト構造を構築します。 結果として得られる構造はブロックカットツリーであり、ブロック間で重なり合うのはアーティキュレーションポイントのみであるため、非周期的であることが保証されます。 
4. 任意のノードでブロックカット ツリーをルートし、DFS または BFS を実行して、LCA クエリの深さとバイナリ リフティング テーブルを計算します。 ここでの深さは、交互の頂点ブロックのステップに対応します。 
5. ノード a と b の間の各クエリについて、ブロックカット ツリーで LCA を計算します。 ツリー内の生の距離は、深さの合計から LCA の深さの 2 倍を引いたものです。 
6. この生の距離を元のグラフの実際の最短経路長に変換します。 ブロック ノードを通過する各トラバースは実際のエッジの移動を表しますが、ブロック内の移動は崩壊するため、最終的な答えは (ツリー距離 + 1) // 2 になります。 

この最終的な変換が機能する理由は、元の頂点間の実際の各移動が、エンドポイントを除いてブロックカット表現の 2 つのステップに対応しているためです。 

### なぜ効果があるのか

 ブロックカット ツリーは、すべての二重接続コンポーネントをクリーク ハブに圧縮しながら、グラフのすべてのアーティキュレーション構造を保存します。 クリーク内では、あらゆる動きはブロック ノードを経由する 1 つのステップと同等であるため、最短パスがコンポーネントごとに複数の内部エッジを通過する必要はありません。 元のグラフ内のパスはブロックカット ツリー内のパスに一意に対応し、またその逆も同様であるため、最短パスの計算はツリー内の最短パスに帰着します。これはまさに LCA 距離の計算となります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

N, M, Q = map(int, input().split())
g = [[] for _ in range(N + 1)]

for _ in range(M):
    u, v = map(int, input().split())
    g[u].append(v)
    g[v].append(u)

# Tarjan for biconnected components
tin = [0] * (N + 1)
low = [0] * (N + 1)
timer = 0
st = []
comp_id = 0

# block-cut tree nodes:
# 1..N original nodes
# N+1..N+comp_count block nodes
bcg = [[] for _ in range(2 * N + 5)]

def dfs(u, p):
    global timer, comp_id
    timer += 1
    tin[u] = low[u] = timer
    st.append(u)

    for v in g[u]:
        if v == p:
            continue
        if tin[v] == 0:
            dfs(v, u)
            low[u] = min(low[u], low[v])
            if low[v] >= tin[u]:
                comp_id += 1
                comp_node = N + comp_id
                while True:
                    x = st.pop()
                    bcg[x].append(comp_node)
                    bcg[comp_node].append(x)
                    if x == v:
                        break
                bcg[u].append(comp_node)
                bcg[comp_node].append(u)
        else:
            low[u] = min(low[u], tin[v])

for i in range(1, N + 1):
    if tin[i] == 0:
        dfs(i, -1)

# LCA preprocessing
LOG = 20
up = [[0] * (2 * N + 5) for _ in range(LOG)]
depth = [0] * (2 * N + 5)
visited = [False] * (2 * N + 5)

def dfs2(root):
    stack = [root]
    visited[root] = True
    up[0][root] = 0
    while stack:
        u = stack.pop()
        for v in bcg[u]:
            if not visited[v]:
                visited[v] = True
                depth[v] = depth[u] + 1
                up[0][v] = u
                stack.append(v)

for i in range(1, N + 1):
    if not visited[i]:
        dfs2(i)

for k in range(1, LOG):
    for v in range(1, 2 * N + 5):
        up[k][v] = up[k - 1][up[k - 1][v]]

def lca(a, b):
    if depth[a] < depth[b]:
        a, b = b, a
    diff = depth[a] - depth[b]
    bit = 0
    while diff:
        if diff & 1:
            a = up[bit][a]
        diff >>= 1
        bit += 1
    if a == b:
        return a
    for k in range(LOG - 1, -1, -1):
        if up[k][a] != up[k][b]:
            a = up[k][a]
            b = up[k][b]
    return up[0][a]

def dist(a, b):
    c = lca(a, b)
    return depth[a] + depth[b] - 2 * depth[c]

for _ in range(Q):
    a, b = map(int, input().split())
    print((dist(a, b) + 1) // 2)
```この解決策は、グラフの隣接リストを構築することから始まります。 Tarjan スタイルの DFS は、検出と低リンク時間を使用して二重接続されたコンポーネントを識別します。 コンポーネントを完成させるたびに、スタックからノードをポップし、そのブロックを表す新しく作成された仮想ノードに接続します。 これにより、ブロックカット グラフが構築されます。 

2 番目の DFS は、バイナリ リフティング用の深さテーブルと親テーブルを構築します。 次に、LCA 関数がブロックカット ツリー内の距離を計算します。 最後に、頂点ノードとブロック ノードの交互構造を考慮した整数除算を使用して、ツリー距離を元のグラフ距離に変換します。 

ブロック ノードは N+1 から始まるため、インデックス付けには注意が必要です。 もう 1 つの微妙な点は、DFS が親の追跡により誤ってエッジをスキップしないようにすることです。 そうしないと、アーティキュレーションの検出が失敗します。

 ## 特殊なケース

 Tarjan 分解ではすべての頂点を含む 1 つのブロック ノードが生成されるため、単一の大きなクリークは正しく処理されます。 すべてのクエリは、ブロック ノードを介して距離を 1 に設定することによって解決されます。 

純粋なツリー構造も正しく処理されます。これは、すべてのエッジが独自の自明な二重接続コンポーネントになるためです。そのため、ブロックカットされたツリーは交互構造を持つ元のツリーになり、LCA 距離は標準のツリー距離まで減少します。 

ネストされたサイクルを含むグラフは、アーティキュレーション ポイントを介して接続された複数の重なり合うクリークに正しく圧縮され、ブロックカット ツリーにより、ブロック内のトラバースを過剰にカウントすることなく、最短パスが常にアーティキュレーション構造を尊重することが保証されます。
