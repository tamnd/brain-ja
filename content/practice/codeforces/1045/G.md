 ## 解決策
 ## 問題の理解

 数直線上に配置されたロボットのセットが与えられます。 各ロボットはある座標に座り、その位置を中心に固定された対称的な可視範囲を持ちます。 その範囲内では、他のロボットを「見る」ことができる可能性があります。 ただし、可視性だけではインタラクションには十分ではありません。 2 台のロボットは、両方がお互いを見ることができ、IQ 値が十分に近い場合、特に IQ 間の絶対差が最大 K 以下の場合にのみ通信します。 

このタスクは、相互の可視性と IQ の互換性という両方の条件を同時に満たす、順序付けされていないロボットのペアの数を数えることです。 

制約が十分に大きいため、すべてのペアにわたる二次比較はすぐに遅すぎます。 最大 100,000 台のロボットの場合、単純な O(N²) チェックでは約 10¹⁰ の比較が必要になりますが、これは 2 秒の許容範囲をはるかに超えています。 これにより、この問題を、値の制約が追加された幾何学的範囲カウント問題として扱う必要があります。 

微妙な点は、可視性には方向性があるということです。 ロボット A からロボット B が見えるということは、その逆を意味するものではありません。 ただし、この問題では相互通信が必要であるため、両方の可視性条件が同時に成立するペアのみをカウントする必要があります。 これにより、可視性が区間の交差点状態に効果的に変わります。 

エッジケースは、ロボットの範囲が広い場合や同じ位置にある場合に発生します。 たとえば、すべてのロボットが同じ座標にあるものの、IQ が異なる場合、可視性は重要ではありませんが、IQ フィルタリングが優先されます。 逆に、すべての IQ が等しいが範囲が狭い場合は、幾何学が優勢になります。 

単純な間違いは、相互の可視性を要求するのではなく、どちらかのロボットがもう一方のロボットを認識した場合にペアとしてカウントすることです。 もう 1 つの間違いは、可視性リストを個別に反復する場合にペアを二重にカウントすることです。 

## アプローチ

 ブルート フォース ソリューションは、ロボットのすべてのペアをチェックし、両方の状態を直接検証します。 各ペア (i, j) について、xj が i の可視範囲内にあるか、xi が j の可視範囲内にあるかを計算し、IQ の差を確認します。 これは正しいですが、一定時間ごとに N(N−1)/2 回のチェックを必要とするため、非常にコストがかかります。 N = 10⁵ では、これは実現不可能です。 

改善するには、相互可視性条件を単一の幾何拘束に変換する必要があります。 重要な観察は、相互可視性が xj ∈ [xi − ri, xi + ri] と xi ∈ [xj − rj, xj + rj] の両方を意味するということです。 これら 2 つの不等式は、xi と xj の間の距離が最大でも ri + rj でなければならないという 1 つの条件と同等です。 これにより、方向性が完全に削除され、ジオメトリが対称拘束に変わります。 

ここで、問題は |xi − xj| のようなペアを数えることになります。 ≤ ri + rj および |qi − qj| ≤ K.

 これは 2 次元の範囲制約です。1 つの次元は幾何学的 (位置と半径) であり、もう 1 つは限られた小さな IQ 差です。 K ≤ 20 であるため、IQ は非常に小さな値の範囲であり、ロボットを IQ でグループ化し、近くの IQ バケットのみを比較することを提案します。 

位置によってロボットを分類し、スイープ ラインまたは 2 ポインター構造を使用して候補を空間制約内に維持できます。 各ロボットについて、その可視範囲内にある以前に見たロボットの構造を維持します。 K が小さいため、IQ オフセットをキーとした複数のアクティブな構造を維持します。 これにより、最大 41 個の IQ バケットとの比較のみが可能になります。 

主な困難は、有効な間隔内に何台あるかについてのクエリをサポートしながら、位置によって順序付けされたアクティブなロボットの動的なセットを維持することです。 標準的な方法は、IQ クラスごとにバランスのとれたバイナリ インデックス構造を使用するか、2 つのポインターと位置を超えるスライディング ウィンドウを使用してソートされたリストを維持し、スイープ中にロボットを挿入することです。 

したがって、ソリューションは、位置によるスイープ、右側の可視境界が現在位置をカバーするアクティブなロボットの維持、および範囲内の互換性のある IQ のカウントに集約されます。

 ## アルゴリズムのチュートリアル

 1. 各ロボットを、その影響がその位置と半径によって表される間隔のようなエンティティに変換しますが、幾何学的制約を段階的に強制するために、ソートされた位置のスイープに依存します。 
2. ロボットを位置 x で並べ替えます。 ソートにより、任意のペアではなくスライディング ウィンドウを使用して可視性を推論できるため、ソートは不可欠です。 これにより、潜在的なパートナーのみが空間順序の昇順で処理されることが保証されます。 
3. 現在「アクティブ」なロボットを追跡するデータ構造を維持します。これは、ロボットの可視範囲が現在のスイープ位置まで広がることを意味します。 具体的には、ロボット i は、x ≤ xi + ri となる x に到達するとアクティブになり、x がこの範囲を超えると無関係になります。 
4. ソートされた順序で各ロボット j について、xj > xi + ri となるすべてのロボット i をアクティブ セットから削除します。 これらのロボットは右側には何も見えないため、将来ペアを形成することはできません。 
5. クリーンアップ後、位置が [xj − rj, xj + rj] 内にあるロボットのアクティブ構造をクエリします。 すべてのアクティブなロボットがスイープの構築によってすでに逆の条件を満たしているため、これにより相互の可視性が確保されます。 
6. クエリされた空間範囲内で、IQ が qj と最大 K だけ異なるロボットのみをカウントします。K が小さいため、IQ バケットを qj − K から qj + K まで反復し、それらのカウントを合計します。 
7. 現在のロボットをアクティブな構造に挿入し、その IQ によってインデックスを付け、将来のクエリに参加できるようにします。 

正確さは、位置 x にあるアクティブ セットに、可視間隔がまだ x をカバーしているロボットが正確に含まれているという不変条件を維持することに依存します。 これにより、カウントされたすべてのペアが相互可視性制約の一方向をすでに満たしていることが保証され、一方、空間クエリ ウィンドウを制限することによって 2 番目の方向が強制されます。 現在のロボットごとに以前のロボットのみをカウントするため、各ペアは 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    robots = [tuple(map(int, input().split())) for _ in range(n)]

    robots.sort(key=lambda t: t[0])  # sort by position

    # active list: (x, r, q)
    active = []
    ans = 0

    for xj, rj, qj in robots:
        new_active = []

        # remove expired robots (those that cannot see xj anymore)
        for xi, ri, qi in active:
            if xi + ri >= xj:
                new_active.append((xi, ri, qi))
        active = new_active

        # count valid pairs with current robot
        for xi, ri, qi in active:
            if abs(xi - xj) <= rj and abs(qi - qj) <= k:
                ans += 1

        # add current robot
        active.append((xj, rj, qj))

    print(ans)

if __name__ == "__main__":
    solve()
```コードはスイープのアイデアに直接従っていますが、ロジックを見やすくするために単純化された構造を使用しています。 アクティブ リストは、右側の可視境界がまだ現在の位置に到達しているロボットを表します。 期限切れにより、今後のインタラクションに参加できなくなったロボットは削除されます。 

計数ステップでは、空間制約と IQ 制約の両方をチェックします。 スイープでは xi ≤ xj であるため、空間条件は単純化されます。そのため、アクティブ ロボットの右側の境界だけが相互可視性にとって重要ですが、左側の境界はアクティブ セットの構築によって暗黙的に満たされます。 

実装上の微妙なリスクは、スイープによって順序付けが強制されることを忘れることです。 x を増加させながらロボットを処理するため、すべてのアクティブなロボットはすでに左側または同等に位置しており、対称チェックの必要がなくなります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N²) は最悪、O(N²) はナイーブ形式では効果的 | 各挿入はアクティブ セットをスキャンします。 
| スペース | O(N) | アクティブなロボットを保管する |

 スイープにより冗長なチェックが削減されますが、インデックス作成がないため、最悪の場合のパフォーマンスが 2 次的になります。 N = 10⁵ では、これでもまだ不十分ですが、これは、後で最適化されたソリューションが構築する中心となる構造上のアイデア、つまり比較をローカルのアクティブ ウィンドウに制限することを反映しています。 

意図された完全に最適なソリューションは、アクティブ リストを IQ バケットごとのインデックス付き構造に置き換え、空間クエリを対数または線形スライディング ウィンドウ操作に減らし、O(N log N) を達成します。

 ## 特殊なケース

 すべてのロボットが同じ位置を共有しているが、IQ が異なる場合を考えてみましょう。 例えば：```
4 1
0 5 1
0 5 2
0 5 3
0 5 10
```ここでは、すべての範囲が同じ点で完全に重なるため、すべてのペアが可視性を満たします。 このアルゴリズムでは、期限切れになるロボットがないため、すべてのロボットが同時にアクティブな状態を維持します。 次に、IQ の差が最大 1 であるペアのみをカウントするため、(1、2、3) のうち隣接する IQ ペアのみが寄与し、(10) のロボットは何も寄与しません。 

ここで極端な半径を考えてみましょう。```
3 10
0 100 5
50 100 14
200 100 6
```最初の 2 つのロボットはスイープ全体にわたってアクティブなままであり、空間制約と IQ 制約の両方を満たし、1 つの有効なペアを生成します。 3 番目のロボットは、処理されると以前のロボットから空間的に遠すぎるため、まったく寄与しません。 

最後に、最小 K = 0 を考えます。この場合、IQ 条件は厳密に等しくなります。 IQ ウィンドウが 1 つのバケットに折りたたまれ、同一の値のみがカウントされるため、このアルゴリズムは引き続き機能します。
