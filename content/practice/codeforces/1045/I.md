 ## 解決策

 ## 問題の理解

 複数の文字列セットが与えられているので、「適切なペア」を形成するインデックスの順序のないペアがいくつあるかを数える必要があります。 2 つの文字列を連結した後、結果の文字を回文に再配置できる場合、ペアは適切です。 

重要な観察は、連結から直接回文を形成する必要がないことです。 文字を自由に並べ替えることができるため、元の連結の構造はまったく問題になりません。 両方の文字列内の複数の文字セットのみが重要です。 

結合された文字列内で最大 1 文字が奇数頻度を持つ場合に限り、文字列を回文に並べ替えることができます。 これにより、問題は文字列の順序ではなく文字数のパリティに関する推論に変わります。 

したがって、各文字列は 26 ビット マスクで表すことができます。ここで、i 番目のビットは、その文字の頻度が奇数であるかどうかを示します。 2 つの文字列の場合、それらの連結にはマスクの XOR に等しいパリティ マスクがあります。 条件は次のようになります。XOR マスクには最大 1 ビットが設定されている必要があります。 

この条件が成り立つ場合、順序のないペア (i, j)、i ≠ j を数えます。 

制約は大きく、最大 100,000 個の文字列と最大 1e6 の合計長があります。 O(n^2) のペアリングは不可能であり、ペアごとのアルファベットの線形であっても遅すぎます。 O(n · 26) または O(n · 26 log n) に近いもの、あるいはより良いものとしては、O(n · 26) ハッシュまたは頻度集約が必要です。 

素朴な失敗モードは、文字列のすべてのペアを直接チェックしようとすることです。 ペアのチェックが O(26) であるとしても、最悪の場合、およそ 5e9 回の操作が必要となり、これは実行不可能です。 

もう 1 つの微妙な落とし穴は、条件を誤解していることです。一部の人は、連結自体が順列なしの回文である必要があると誤って考えているかもしれません。 それは、順序に依存する別の問題に変わり、間違った答えを生み出すことになります。 

エッジケースには次のようなものがあります。 

すべての文字数が偶数である単一の文字列。それ自体または他の偶数パリティ文字列と組み合わせることができます。 

複数の奇数ビットが異なる文字列。有効なペアを形成できません。 

マスクがゼロである「aaaaa」のような、繰り返しの多い文字列。 

## アプローチ

 ブルートフォース手法では、文字列のすべてのペアをチェックし、その連結が回文に変換できるものをカウントします。 各ペアについて、両方の文字列の文字頻度を計算し、それらを組み合わせて、奇数の頻度を持つ文字の数を数えます。 その数が最大 1 であれば、ペアは有効です。 各文字列の周波数ベクトルを事前計算したとしても、各ペアのチェックには依然として O(26) のコストがかかり、結果として O(n^2 · 26) となり、これは n = 100000 の制限をはるかに超えています。 

重要な洞察は、完全な周波数ベクトルをパリティ マスクに置き換えることです。 各文字列は 26 ビット整数になります。 次に、マスクの XOR のハミング重みが最大 1 であれば、ペアは有効です。つまり、マスクが等しい (XOR が 0) か、または 1 ビット反転だけ異なっているかのいずれかになります。 

これにより、問題はマスクごとに、以前のマスクがどれだけ等しいか、または 1 ビット異なるかを数えることに減ります。 これまでに見られたマスクに関する周波数辞書を維持します。 新しいマスクごとに、そのカウントと、ちょうど 1 ビット反転されたすべてのマスクのカウントをクエリします。 

これにより、複雑さが二次ペアリングから文字列あたり 26 クエリに軽減され、実際には線形になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n² · 26) | O(n) | 遅すぎる |
 | 最適 (ビットマスク + ハッシュ) | O(n · 26) | 最悪の場合は O(2²⁶)、現実的な場合は O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 以前に確認したパリティ マスクの頻度テーブルを維持しながら、文字列を 1 つずつ処理します。

1. 各文字列について、文字がその文字列内に奇数回出現する場合、ビット i が 1 となる 26 ビット マスクを計算します。 これは、回文の再配置に必要なすべてのパリティ情報をコンパクトに表します。 
2. 現在のマスクを頻度テーブルに挿入する前に、それと有効なペアを形成する以前のマスクの数を数えます。 2つのケースがあります。 まず、同一のマスクです。これは、XOR がゼロになり、すべてのパリティがキャンセルされるためです。 次に、マスクはちょうど 1 ビットだけ異なります。これは、共用体に奇数文字が 1 つだけ生成されるためです。 
3. 度数テーブルから直接、同一の前のマスクの数を追加します。 
4. 次に、26 文字すべてを反復処理し、現在のマスクの各ビットを反転して、それらのマスクの周波数を追加します。 各反転は、最終連結で 1 文字だけが奇数パリティを持つことを許可することに対応します。 
5. 寄与を数えた後、現在のマスクを度数テーブルに挿入します。 

各文字列は独立して処理され、2 番目のインデックスが現在の文字列で最初のインデックスがそれより前のペアのみをカウントするため、すべての有効なペアは 1 回だけカウントされます。 

### なぜ効果があるのか

 正確さは、回文順列条件をパリティ制約に帰着させることで得られます。 複数の文字セットを回文に再配置できるのは、最大でも 1 つの文字のカウントが奇数である場合に限られます。 2 つのマスクの XOR は、結合されたマルチセットのパリティを表します。 したがって、有効なペアは、ハミング重み ≤ 1 の XOR マスクに正確に対応します。頻度テーブルにより、ペアの後のエンドポイントを処理するときに、以前の互換性のあるマスクがすべて 1 回カウントされることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def mask_of(s: str) -> int:
    m = 0
    for c in s.strip():
        m ^= 1 << (ord(c) - 97)
    return m

n = int(input())
freq = {}

ans = 0

for _ in range(n):
    s = input().strip()
    m = mask_of(s)

    ans += freq.get(m, 0)

    for i in range(26):
        ans += freq.get(m ^ (1 << i), 0)

    freq[m] = freq.get(m, 0) + 1

print(ans)
```コアの実装は、各文字列のパリティ マスクの構築を中心に展開します。 XOR 累積はパリティを追跡する正しい方法です。文字が出現するたびにビットを切り替えることで、完全な周波数配列を保存せずに奇数カウントが正確に表現されるためです。 

カウントのステップでは、正確な一致と 1 ビットの違いを注意深く分離します。 現在の文字列はクエリ フェーズに含めないため、各ペアは 1 回だけカウントされます。

## テストケース```python
import sys, io

def solve():
    import sys
    input = sys.stdin.readline

    def mask_of(s: str) -> int:
        m = 0
        for c in s.strip():
            m ^= 1 << (ord(c) - 97)
        return m

    n = int(input())
    freq = {}
    ans = 0

    for _ in range(n):
        s = input().strip()
        m = mask_of(s)

        ans += freq.get(m, 0)
        for i in range(26):
            ans += freq.get(m ^ (1 << i), 0)

        freq[m] = freq.get(m, 0) + 1

    print(ans)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    try:
        solve()
        return ""
    finally:
        sys.stdin = old_stdin

# provided sample
assert run("3\naa\nbb\ncd\n") == "", "sample 1"

# all identical strings
assert run("4\naa\naa\naa\naa\n") == "", "identical strings"

# alternating parity
assert run("3\nab\nac\nad\n") == "", "mixed small case"

# single element
assert run("1\na\n") == "", "single string"

# maximum-like simple case
assert run("5\na\nb\nc\nd\ne\n") == "", "all single letters"

 | 同一の文字列 | すべてのペア | すべてゼロのマスク集約 |
 | ab、ac、ad | オーバーラップの増加 | 1 ビット遷移 |
 | 単一の文字列 | 0 | 基本ケースの正確性 |

 ## 特殊なケース

 厄介なケースは、すべての文字が偶数回繰り返されるなど、すべての文字列が同じパリティ マスクを持つ場合です。 例えば：```
3
aa
bb
cc
```各文字列はマスク 0 にマップされます。すべての新しい文字列が同一のマスク ルックアップを通じて以前のすべての文字列と一致するため、アルゴリズムはすべてのペアを正しくカウントします。 

もう 1 つのケースは、次のような文字列に複数の奇数文字が異なる場合です。```
2
abc
def
```どちらのマスクにも複数のビットが設定されており、XOR には複数のビットがあります。 同一のマスクも単一ビット フリップも一致しないため、アルゴリズムはそれらをカウントしません。これにより、無効なペアが正しく除外されます。 

最後に、単一文字の文字列で最小限のマスクをテストします。 各文字列は単一ビット マスクに寄与し、最大 1 文字の違いが異なるペアのみが適格となり、アルゴリズムはフリップ チェックを通じて正しく評価します。
