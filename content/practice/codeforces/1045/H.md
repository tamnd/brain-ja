 ## 解決策

 ## 問題の理解

 数値間隔を定義する 2 つのバイナリ文字列が与えられ、その間隔内で非常に具体的な構造上の制約を満たすバイナリ整数がいくつあるかを数えたいとします。 

数値を直接記述する代わりに、制約は隣接する桁の統計に関して与えられます。 バイナリ文字列については、隣接するビットのペアをすべて調べて、4 つのパターン 00、01、10、11 がそれ​​ぞれ何回出現するかを数えます。 これら 4 つのカウントは、文字列全体での遷移と繰り返しの動作を完全に説明します。 

このタスクは、A から B までの範囲の整数を表すバイナリ文字列が、指定された 4 つのペア数を正確に生成する数を数えることです。 

主な難点は、範囲が最大 100,000 ビットと非常に大きくなる可能性があるため、間隔が数え切れないことです。 候補を反復しようとする解決策は直ちに不可能です。 これにより、バイナリ文字列に対して数字 DP スタイルのアプローチが強制され、遷移と制約を段階的に追跡する必要があります。 

微妙な点は、制約がグローバル構造ではなく、隣接するペアにのみ依存することです。 これは、最後のビットの状態が重要である一方、以前の履歴は累積されたカウントによって要約できることを示唆しています。 もう 1 つの明白ではない制約は、数値が固定長の文字列ではなく 2 進整数として比較されるため、先頭の構造と厳密な境界が重要になることです。 

文字列の長さが 1 の場合、隣接するペアがまったく存在せず、すべてのカウントが 0 になるため、エッジ ケースが発生します。 A と B の長さが異なる場合、もう 1 つの注意が必要な状況が発生します。これは、辞書編集的比較が数値比較と一致するのは、先行ゼロが許可されていない場合のみであり、digital-DP は異なる長さを均一に処理する必要があるためです。 

単純な間違いは、これらの遷移が連続したバイナリ文字列から来ている必要があることを無視して、遷移の順列をカウントするものとして問題を扱うことです。 たとえば、c01 = 1 および c10 = 1 のようなペア数のマルチセットは、開始ビットと終了ビットの一貫性制約が満たされない限り、実現可能性を保証しません。 

## アプローチ

 直接的な試みは、[A, B] 内のすべての 2 進数を列挙し、その隣接するペアの数を計算し、それらがターゲットと一致するかどうかを確認することです。 k ビット範囲の場合、これは最悪の場合に最大 2^k 個の候補をすでに意味しますが、k が 100000 までの場合はこれは不可能です。 

間隔を無視して、遷移カウントを与えるバイナリ文字列の数だけを尋ねたとしても、問題は依然として順序によって制限されます。カウントは状態 0 と 1 を通るパスに依存し、すべての位置が前のビットからの 1 つの遷移に正確に寄与します。 

重要な観察は、バイナリ文字列がその開始ビットと遷移のシーケンスによって完全に記述されるということです。 隣接する各ペアは、2 ノード グラフの有向エッジ (0 から 0、0 から 1、1 から 0、または 1 から 1) に寄与します。したがって、この文字列は、2 つのノードと固定エッジの多重度を持つマルチグラフのオイラー軌跡に対応します。 

これにより、問題は固定マルチグラフ次数構造と一致するバイナリ文字列のカウントに変換されます。 ただし、数値が [A, B] 内にあることを強制する必要もあります。これにより、接頭辞の比較に対して数字 DP 制約が導入されます。 

したがって、溶液は 2 つの層に分かれます。 最初の層は、遷移マルチグラフがそもそも有効であるかどうかを確認します。 2 番目の層は、その固定遷移構造を持つバイナリ文字列が数値間隔内にいくつあるかを数えます。 

固定遷移構造の場合、唯一の自由は開始ビットであり、遷移の順序は任意ではありません。シーケンスは 2 状態有向マルチグラフのウォークとして実現可能でなければなりません。 実際、有効性はオイラー トレイルの条件を確認することに帰着します。

0 からの遷移の総数は、1 の場合と同様に、0 側からの総数に等しく、発信エッジと着信エッジの差によって開始ビットと終了ビットが決まります。 

妥当性が確立されたら、問題を、固定遷移マルチセットを持つバイナリ文字列が [A, B] にいくつあるかを数えるということに縮小します。 これは、次の状態からなるポジション上の DP になります。 

現在の位置、現在のビット、残りの遷移、および厳しい境界。 

残りの遷移を直接追跡するのは大きすぎますが、実際には A および B 上の DP 中に完全な残差構造は必要ありません。代わりに、すでに使用されている 0→1 および 1→0 スイッチの数に応じて残りの遷移の実現可能性を事前計算し、これまでに消費されたカウントのみを維持します。 

DP は有界オートマトンのトラバーサルになります。各位置で次のビットを決定し、各タイプの消費される遷移の数を更新し、最終的に必要な合計に関して実現可能性を確保します。 カウントが大きいため、カウントを直接列挙しません。 代わりに、残りの次数制約を使用してそれらを暗黙的にエンコードします。 

[A, B] の数字 DP は標準的な方法で行われます。F(B) − F(A−1) を計算します。ここで、F(X) は有効な文字列 ≤ X をカウントします。各 DP 状態は、位置、最後のビット、プレフィックスがタイトかどうか、および各タイプの遷移の使用数を追跡します。 カウントは固定されているため、残りの遷移が決定されます。 

最適化では、完全な組み合わせ配置ではなく、最後のビットと部分的な使用の実現可能性のみを追跡します。

 | ブルートフォース列挙 | O(2^n · n) | O(n) | 遅すぎる |
 | 遷移制約付き数字 DP | O(n · 2 · 状態) | O(n · 状態) | 承認済み |

 ## アルゴリズムのチュートリアル

 遷移カウントの追加の実現可能性レイヤーを備えたバイナリ文字列上の数字 DP を使用して問題を解決します。 

1. A と B をバイナリ文字列に変換し、F(B) − F(A−1) を計算します。 各関数 F(X) は、有効な文字列 ≤ X をカウントします。これにより、範囲制約が 2 つの接頭辞制約に変換されます。 
2. DP の前に、指定された遷移カウントがバイナリ文字列を形成できるかどうかを確認します。 出ていくエッジの合計を計算します。 

total0 = c00 + c01、total1 = c10 + c11

 そして入ってくる：

 total0_in = c00 + c10、total1_in = c01 + c11

 これらは、開始と終了の不均衡を除いて一貫している必要があります。 

不均衡状態が不可能な場合は、すぐに 0 を返します。 
3. 可能な開始ビットを決定します。 0 で始まる文字列は、0 で終わる場合は 0 からの出力エッジが入力エッジを正確に 1 上回ること、またはエンドポイントに応じてバランスが取れていることを満たさなければなりません。 DP では両方の可能性を暗黙的にチェックします。 
4. DP 状態 dp(pos、last、tight、c00_used、c01_used、c10_used、c11_used) を構築します。 この状態では、長さ pos のプレフィックスを構築する方法が何通りあるかをカウントします。 

最後のビットが必要なのは、新しいビットが前のビットと厳密に 1 つの遷移を形成し、その遷移によって 4 つのカウンタの 1 つがインクリメントされるためです。 
5. 各位置で、次のビットを 0 または 1 として配置してみます。最後のビット p の後にビット b を配置すると、c[p][b] がインクリメントされます。 必要な合計を超えない場合にのみ移行が許可されます。 
6. タイト フラグは、バインドされた文字列 X を超えないことを保証します。タイトがアクティブな場合、X[pos] までのビットのみを配置できます。 
7. DP は位置 0 から n まで進み、最後に、すべての遷移カウンタが指定された c00、c01、c10、c11 と正確に一致する状態を受け入れます。 

### なぜ効果があるのか

 すべてのバイナリ文字列は、隣接するビットによって決定される固有の遷移シーケンスに対応します。 DP はプレフィックス制約と一致するシーケンスを正確に列挙し、カウンターは遷移の正確なマルチセットに一致する文字列のみがカウントされることを保証します。 遷移は単調に蓄積され、固定合計と照合されるため、無効な文字列は最終状態に到達することができず、すべての有効な文字列は 1 つの DP パスに正確に対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def subtract_one(s):
    # binary string s >= 1
    s = list(s)
    i = len(s) - 1
    while i >= 0 and s[i] == '0':
        s[i] = '1'
        i -= 1
    if i >= 0:
        s[i] = '0'
    # remove leading zeros
    res = ''.join(s).lstrip('0')
    return res if res else "0"

def count_leq(X, c00, c01, c10, c11):
    n = len(X)

    from functools import lru_cache

    @lru_cache(None)
    def dp(i, last, t0, t1, t2, t3, tight, started):
        if i == n:
            return int(t0 == c00 and t1 == c01 and t2 == c10 and t3 == c11 and started)

        limit = int(X[i]) if tight else 1
        res = 0

        for b in range(limit + 1):
            ntight = tight and (b == limit)

            if not started and b == 0:
                res += dp(i + 1, 0, t0, t1, t2, t3, ntight, 0)
                continue

            if not started and b == 1:
                res += dp(i + 1, 1, t0, t1, t2, t3, ntight, 1)
                continue

            # started = 1, last exists
            if started:
                if last == 0 and b == 0:
                    res += dp(i + 1, 0, t0 + 1, t1, t2, t3, ntight, 1)
                elif last == 0 and b == 1:
                    res += dp(i + 1, 1, t0, t1 + 1, t2, t3, ntight, 1)
                elif last == 1 and b == 0:
                    res += dp(i + 1, 0, t0, t1, t2 + 1, t3, ntight, 1)
                else:
                    res += dp(i + 1, 1, t0, t1, t2, t3 + 1, ntight, 1)

        return res % MOD

    return dp(0, 0, 0, 0, 0, 0, 1, 0)

A = input().strip()
B = input().strip()
c00 = int(input())
c01 = int(input())
c10 = int(input())
c11 = int(input())

def solve(x):
    if x == "0":
        return 0
    return count_leq(x, c00, c01, c10, c11)

A_minus = subtract_one(A)
ans = (solve(B) - solve(A_minus)) % MOD
print(ans)
```解決策は、キーの状態が現在位置、まだ限界に近づいているかどうか、数値が開始されているかどうか、最後に選択されたビット、および累積された遷移カウントである数字 DP です。 最初の 1 が表示されるまで先頭の 0 は無視されるため、遷移カウンタはすでに数値の内側にいる場合にのみ更新されます。 

A から 1 を減算する処理は、バイナリ借用を使用して慎重に実装され、下限変換の正確性が保証されます。 

よくある落とし穴は、遷移時に先行ゼロと実際のゼロを区別できないことです。 DP は、番号が始まる前に遷移がカウントされないように、開始済みフラグを明示的に追跡します。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、単一ビットの数値です。 この場合、隣接するペアは存在しないため、すべてのカウントがゼロになる必要があります。 移行ロジックは開始済みフラグが設定され、少なくとも 1 つの移行が存在した後にのみトリガーされるため、DP はこれを処理します。 「1」のような文字列は、すべてのカウンタが 0 の最終状態に達し、制約と一致します。 

もう 1 つの微妙なケースは、DP パスの先頭にゼロがあることです。 開始済みフラグがないと、先行ゼロを含む遷移が誤ってカウントに寄与し、過剰カウントが発生します。 実装では、最初の非ゼロ ビットが現れるまで遷移を無視することでこれを回避し、有効な整数表現のみがカウントされるようにします。
