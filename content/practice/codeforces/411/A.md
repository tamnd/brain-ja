 ## 解決策
 ## 問題の理解

 パスワード文字列が「十分に複雑」かどうかを 4 つの基準に基づいてチェックするように求められます。 パスワードは、大文字、小文字、数字、およびいくつかの特殊文字を含む最大 100 文字のシーケンスです。 パスワードは、長さが 5 文字以上で、少なくとも 1 つの大文字、少なくとも 1 つの小文字、および少なくとも 1 つの数字が含まれている場合に受け入れられます。 

入力はパスワードを含む 1 行で構成されます。 出力は 1 つのメッセージです。パスワードがすべての要件を満たしている場合は「正しい」、そうでない場合は「弱すぎます」です。 

制約は非常に小さいです。 最大 100 文字ということは、パフォーマンスを気にせずに各文字を個別に複数回調べる余裕があることを意味します。 これにより、サブリニア スキャンへの最適化に関する懸念が排除されます。 

4 つの条件すべてを注意深くチェックすることが重要です。 長さだけをチェックする、または数字を考慮せずに文字だけをチェックする単純なアプローチでは、誤った結果が生じる可能性があります。 たとえば、入力`Abc!`大文字と小文字の両方と特殊文字が含まれているにもかかわらず、短すぎます。 入力`abcdef`は長く、小文字が含まれていますが、大文字と数字が含まれていないため、拒否される必要があります。 これは、部分的な準拠だけでは十分ではなく、4 つの条件すべてを検証する必要があることを示しています。 

## アプローチ

 ブルートフォースアプローチは簡単です。各条件を個別にチェックします。 まず、パスワードの長さを測定します。 次に、文字列をスキャンして、少なくとも 1 つの大文字、少なくとも 1 つの小文字、および少なくとも 1 つの数字が含まれているかどうかを確認します。 これは、文字列を 4 回個別にスキャンするか、4 つのフラグすべてを追跡する 1 回のパスで実行できます。 パスワードの長さは 100 に制限されているため、4 回のスキャンで最大 400 文字の検査が実行されますが、これは無視できる程度です。 

実装を簡素化する重要な洞察は、すべての文字タイプの要件を 1 回のパスでチェックできることです。 大文字、小文字、数字の 3 つのブール フラグを維持します。 文字列を反復処理すると、それに応じてこれらのフラグが更新されます。 パスの最後までにすべてのフラグが設定され、長さが十分であれば、パスワードは有効です。 これにより、複数の反復が回避され、概念的に単純になります。

 ## アルゴリズムのチュートリアル

 1. パスワード文字列を読み取ります。 まず最初に確認するのは長さです。 5 文字未満の場合は、これ以上パスワードを有効にするチェックができないため、すぐに「弱すぎる」と返されます。 
2. 3 つのブール変数を初期化します。`has_upper`、`has_lower`、 そして`has_digit`。 これらは、パスワードに必要な各タイプの文字が少なくとも 1 文字含まれているかどうかを追跡します。 
3. パスワードの各文字を繰り返します。 文字が大文字の場合は設定します`has_upper`に`True`。 小文字の場合は設定してください`has_lower`に`True`。 数字の場合は設定します`has_digit`に`True`。 
4. ループの後、次の 4 つの条件をすべてチェックします。`has_upper`、`has_lower`、 そして`has_digit`。 すべてを満たしている場合は、「修正」を印刷します。 それ以外の場合は、「弱すぎます」と出力します。 

機能する理由: このアルゴリズムは、必要な文字タイプの存在を表す 3 つのブール フラグを維持します。 文字列を反復処理すると、各文字が 1 回だけ評価されることが保証されます。 これを長さチェックと組み合わせることで、パスワードが誤って受け入れられず、すべての有効なパスワードが正しく認識されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

password = input().strip()

if len(password) < 5:
    print("Too weak")
else:
    has_upper = False
    has_lower = False
    has_digit = False
    
    for ch in password:
        if ch.isupper():
            has_upper = True
        elif ch.islower():
            has_lower = True
        elif ch.isdigit():
            has_digit = True
    
    if has_upper and has_lower and has_digit:
        print("Correct")
    else:
        print("Too weak")
```この解決策は、先頭または末尾の偶発的なスペースを処理するために空白をトリミングすることから始まります。 明らかに短いパスワードをすぐに拒否するために、最初に長さがチェックされます。 3 つのフラグが文字タイプを追跡します。 使用する`isupper()`、`islower()`、 そして`isdigit()`文字範囲を手動で比較する必要がなく、より安全で読みやすくなります。 最後に、単一の論理式で 4 つの条件すべてを評価することによって結果が決定されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = io.StringIO()
    sys.stdout = output
    password = input().strip()
    if len(password) < 5:
        print("Too weak")
    else:
        has_upper = has_lower = has_digit = False
        for ch in password:
            if ch.isupper():
                has_upper = True
            elif ch.islower():
                has_lower = True
            elif ch.isdigit():
                has_digit = True
        if has_upper and has_lower and has_digit:
            print("Correct")
        else:
            print("Too weak")
    return output.getvalue().strip()

# Provided sample
assert run("abacaba") == "Too weak", "sample 1"

# Custom cases
assert run("A1b2C") == "Correct", "mixed chars, exact length"
assert run("abc") == "Too weak", "too short"
assert run("ABCDE") == "Too weak", "uppercase only"
assert run("abcde123") == "Too weak", "missing uppercase"
assert run("Ab1!") == "Too weak", "exact 4 chars, fails length"
assert run("Abcdef1") == "Correct", "long enough, meets all"

 ## 特殊なケース

 特殊なケースには、主に境界線の長さと文字タイプの組み合わせが関係します。 のために`Ab1!`、アルゴリズムは最初に長さをチェックし、文字タイプをチェックする必要なしに即座に拒否し、短絡評価を示します。 次のようなパスワードの場合`ABCDE`の場合、アルゴリズムは大文字を正しく追跡しますが、小文字と数字のフラグが false のままであることを検出し、確実に「弱すぎます」を出力します。 これは、このアプローチが、off-by-one エラーや条件の欠落なしで長さと文字型の両方の境界を処理することを確認します。
