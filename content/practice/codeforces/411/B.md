 ## 解決策
 ## 問題の理解

 いくつかのコアといくつかのメモリ セルを備えたプロセッサをシミュレートしています。 時間はサイクルに分割されます。 サイクルごとに、各コアは何もしないコマンド、または特定のメモリ セルに書き込むコマンドのいずれかを受け取ります。 

興味深いのは、デッドロックがどのように発生するかです。 

同じサイクル中に、2 つ以上のアクティブなコアが同じメモリ セルに書き込みを試みると、競合が発生します。 その競合に関係するすべてのコアは永続的にロックされ、メモリ セル自体も永続的にロックされます。 

コアがロックされると、それ以降のコマンドはすべて無視されます。 メモリ セルがロックされると、誰もそのセルに再び正常に書き込むことができなくなります。 アクティブなコアが後ですでにロックされているセルに書き込もうとすると、そのコアもすぐにロックされます。 

すべてのコアについて、ロックされる最初のサイクルを特定する必要があります。 シミュレーション中にロックされなかった場合は、0 を出力します。 

制約は非常に小さいです。 コア、サイクル、メモリ セルの数はすべて最大でも 100 です。すべてのコアとすべてのサイクルに比例した作業を同時に実行するアルゴリズムでも、十分に高速です。 入力全体には最大 10,000 個の命令が含まれるため、高度な最適化よりも単純さと正確さが重要です。 

主な困難は効率ではなく、タイミング ルールを忠実に再現することです。 

簡単な間違いの 1 つは、同時書き込みを誤って処理することです。 

考慮する：```
2 1 1
1
1
```両方のコアがサイクル 1 中にセル 1 に書き込みます。 

正しい出力は次のとおりです。```
1
1
```そのサイクルで発生する一連の書き込みから競合が検出されるため、両方のコアが同時にロックされます。 コアを 1 つずつ処理する不用意なシミュレーションでは、最初の書き込みが成功し、2 番目のコアだけがロックされる可能性があります。 

もう 1 つの微妙なケースは、以前にロックされたセルに書き込むときに発生します。```
2 2 1
1 1
1 0
```サイクル 1 では競合が発生し、コアとセルの両方がロックされます。 

正しい出力:```
1
1
```バグのある実装では、サイクル 2 中にすでにロックされているコアに対してコマンドの実行が継続される可能性があり、これはステートメントに違反します。 

3 番目のエッジ ケースは、ロックされたセルへの書き込みが現在アクティブなコアに対してのみチェックされることです。```
2 2 1
1 0
1 1
```サイクル 1 では、コアとセルの両方がロックされます。 

正しい出力:```
1
1
```サイクル 2 中に、2 番目のコアはロックされたセルへの別の書き込みを試みますが、すでにロックされているため、何も起こりません。 コアがロックされると、再び参加することはありません。 

## アプローチ

 最も直接的なアイデアは、説明どおりにプロセッサを正確にシミュレートすることです。 

サイクルごとに、すべてのアクティブなコアを検査します。 コアがすでにロックされているセルに書き込みたい場合、そのコアはすぐにロックされます。 それ以外の場合は、すべての書き込みリクエストを宛先セルごとにグループ化します。 2 つ以上のアクティブなコアからのリクエストをセルが受信すると競合が発生し、参加しているすべてのコアとセル自体がロックされます。 

制約が小さいため、この単純なシミュレーションはすでに十分に高速です。 

さらに素朴な方法を試してみたとしましょう。 すべてのサイクルとすべてのセルについて、すべてのコアをスキャンして、誰が書き込みを希望しているかを確認できます。 それには大まかに必要になります$m \cdot k \cdot n$操作。 すべての値が 100 に等しい場合、これはわずか 100 万チェックですが、それでも許容範囲内です。 

ただし、サイクルの処理中に書き込みをグループ化する方がクリーンで自然です。 各命令はサイクルごとに 1 回検査され、実行時間が命令の総数に比例するシミュレーションが行われます。 

重要な観察は、アクティブなコアとロックされていないセルの現在のセットを使用して、すべてのサイクルを独立して処理できることです。 競合はその特定のサイクル中に行われた書き込みリクエストにのみ依存しますが、以前にロックされたコアとセルは永久に利用できないままになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nmk) | お(1) | 承認済み |
 | 最適なシミュレーション | O(nm) | O(n + k) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての命令を 2 次元配列に読み取ります。`cmd[i][j]`コアのコマンドです`i`サイクル中`j`。 
2. 配列を維持する`core_locked_time`、最初はすべてゼロです。 値がゼロの場合は、コアがまだアクティブであることを意味します。 
3. ブール配列を維持する`cell_locked`、最初はすべてのメモリセルに対して false です。 
4. 1 から 2 までのプロセス サイクル`m`。 
5. 現在のサイクルについて、メモリ セルから、このサイクル中に書き込みを試みるアクティブなコアのリストへのマッピングを作成します。 
6. すべてのコアを反復処理します。 

コアがすでにロックされている場合は、無視してください。 

コマンドが 0 の場合は無視します。 

ロックされたセルに書き込もうとした場合は、現在のサイクルをロック時間として直ちに記録します。 

それ以外の場合は、ターゲット セルの要求リストにコアを追加します。 
7. すべてのアクティブなコアを検査した後、このサイクル中にリクエストを受信したすべてのセルを検査します。 
8. セルに少なくとも 2 つのコアからの要求がある場合、競合が発生します。 

セルをロック済みとしてマークします。 

参加しているすべてのコアは、現在のサイクル中にロックされます。 
9. 次のサイクルに進みます。 
10. すべてのサイクルが処理された後、コアごとに記録されたロック時間を出力します。 

### なぜ効果があるのか

 各サイクルの開始時のアルゴリズムの状態は、問題で説明されているプロセッサの状態と正確に一致します。 ロックされたすべてのコアはそれ以降の実行から除外され、ロックされたすべてのセルは記憶されます。 

アクティブなコアがロックされたセルに書き込むと、ステートメントは直ちにロックされることを示します。 ステップ 6 では、まさにこのアクションが実行されます。 

ロックされていないセルの場合、競合の決定が行われる前に、現在のサイクルからのすべての書き込み要求が収集されます。 これはサイクルの同時性の性質と一致します。 セルは、そのサイクル中に少なくとも 2 つのアクティブなコアがセルへの書き込みを試みた場合にのみロックされ、参加しているすべてのコアは現在のサイクルをロック時間として受け取ります。 

ステートメントのすべてのルールが 1 回だけ、正しい時間的順序で適用されるため、シミュレーションでは常に実際のプロセッサーと同じ状態遷移が生成されます。 したがって、記録されたロック時間は正確です。 

## Python ソリューション```python
import sys
from collections import defaultdict

input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())

    cmds = [list(map(int, input().split())) for _ in range(n)]

    lock_time = [0] * n
    cell_locked = [False] * (k + 1)

    for cycle in range(1, m + 1):
        requests = defaultdict(list)

        for core in range(n):
            if lock_time[core] != 0:
                continue

            cell = cmds[core][cycle - 1]

            if cell == 0:
                continue

            if cell_locked[cell]:
                lock_time[core] = cycle
            else:
                requests[cell].append(core)

        for cell, cores in requests.items():
            if len(cores) >= 2:
                cell_locked[cell] = True

                for core in cores:
                    if lock_time[core] == 0:
                        lock_time[core] = cycle

    sys.stdout.write("\n".join(map(str, lock_time)) + "\n")

if __name__ == "__main__":
    solve()
```の`lock_time`配列には 2 つの目的があります。 値 0 はコアがまだアクティブであることを意味し、正の値はコアがロックされた最初のサイクルを記録します。 

コアを通過する最初のパスは、すでにロックされているセルへの書き込みによって発生する即時ロックを処理します。 これらのコアは現在のサイクルに正常に参加しないため、要求リストには挿入されません。 

2 番目のパスでは、グループ化されたリクエストを検査します。 すべてのリクエストは競合をチェックする前に収集されるため、同時書き込みは正しく処理されます。 これにより、書き込みを 1 つずつ処理し、最初にアクセスしたコアを誤って優先してしまうというよくあるバグを回避できます。 

条件`if lock_time[core] == 0`紛争ループ内では防御的になります。 実際には、リクエスト リスト内のコアを同じサイクル中にすでにロックすることはできませんが、チェックによってロジックが明示的になり、「最初のロック時間」プロパティが保持されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(nm) | 各命令は最大 1 回検査されます。 
| スペース | O(n + k) | ロックステータスとサイクルごとのリクエストグループを保存します。

import io
from collections import defaultdict

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    n, m, k = map(int, input().split())
    cmds = [list(map(int, input().split())) for _ in range(n)]

    lock_time = [0] * n
    cell_locked = [False] * (k + 1)

    for cycle in range(1, m + 1):
        requests = defaultdict(list)

        for core in range(n):
            if lock_time[core]:
                continue

            cell = cmds[core][cycle - 1]

            if cell == 0:
                continue

            if cell_locked[cell]:
                lock_time[core] = cycle
            else:
                requests[cell].append(core)

        for cell, cores in requests.items():
            if len(cores) >= 2:
                cell_locked[cell] = True
                for core in cores:
                    if lock_time[core] == 0:
                        lock_time[core] = cycle

    return "\n".join(map(str, lock_time))

 ## 特殊なケース

 同時競合の場合を考えてみましょう。```
2 1 1
1
1
```サイクル 1 では、両方のアクティブなコアがセル 1 を要求します。セル 1 の要求リストには 2 つのコアが含まれているため、アルゴリズムはセルと両方のコアをロックします。 出力は次のとおりです。```
1
1
```リクエストは競合が処理される前にグループ化されるため、どちらのコアも優先されません。 

ここで、すでにロックされているセルに書き込むことを考えてみましょう。```
3 2 1
1 0
1 0
0 1
```サイクル 1 ではセル 1 で競合が発生します。コア 1 と 2 がロックされ、セル 1 がロックされます。 

サイクル 2 中に、コア 3 はセル 1 への書き込みを試みます。アルゴリズムは、宛先セルがすでにロックされていることを検出し、直ちにロック時間 2 をコア 3 に割り当てます。 

出力:```
1
1
2
```最後に、すでにロックされているコアが今後のコマンドを受信することを考慮します。```
2 2 1
1 0
1 1
```サイクル 1 は両方のコアとセル 1 をロックします。サイクル 2 では、ロック時間がすでに記録されているため、2 番目のコアのコマンドは無視されます。 このアルゴリズムは、ロックされたコアからの命令を再度処理することはありません。 

出力：```
1
1
```これはプロセッサーの仕様に正確に一致し、コアが既にロックされた後でコアのロック時間を二重にカウントしたり変更したりすることを防ぎます。
