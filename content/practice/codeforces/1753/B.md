 ## 解決策
 ## 問題の理解

 整数の配列の階乗の合計が別の階乗で割り切れるかどうかを判断するように求められます。 より具体的には、配列が与えられます`[a_1, a_2, ..., a_n]`そして数字`x`。 どうか知りたいのです`(a_1! + a_2! + ... + a_n!)`で割り切れます`x!`。 それぞれ`a_i`最大でも`x`なので、これより大きい階乗を計算する必要はありません。`x!`。 

重要な制約は次のとおりです。`n`そして`x`それぞれ最大 500,000 まで可能です。 各要素の階乗を単純に計算してそれらを合計すると、おおよそのサイズの数値が必要になります。`x!`これは、どのデータ型でも処理できるよりもはるかに速く増加します。 20でも！ はすでに約 2.4×10^18 であるため、大規模な場合には単純な計算は不可能です。`x`。 これは、階乗を直接計算するのではなく、数学的に推論する必要があることを示しています。 

重要なエッジケースは、配列内の一部の要素が正確に一致する場合に発生します。`x`。 以来`x!`分割する`x!`を含む任意の合計`x!`は自動的に割り切れます`x!`少なくとも 1 つ含まれている場合`x!`。 もう 1 つの微妙なケースは、すべてが`a_i`未満です`x-1`。 その場合、合計は厳密に以下になります`x!`, したがって、割り切れることは不可能です。 たとえば、次の場合`x = 5`そしてすべて`a_i ≤ 3`、合計は最大で`n * 6 = 6n`より小さい`5! = 120`ない限り`n`巨大です。 ただし、合計は常に小さな階乗で構成されるため、明確なチェックは、`a_i`まさに`x`、答えは常に「はい」です。 それ以外の場合は、すべてを保証する必要があります`a_i ≥ x-1`割り切れるまでに。 

## アプローチ

 ブルートフォースアプローチは、各階乗を計算し、それらを合計し、次のように割り算をチェックすることです。`x!`。 これは原理的には正しいですが、次の場合はすぐに失敗します。`x > 20`階乗は標準の整数制限を超えており、計算に時間がかかりすぎるためです。 のために`n = 500,000`そして`x = 500,000`、階乗を計算することは完全に不可能です。 

重要な観察は、階乗が非常に速く成長するということです。 もしあれば`a_i`まさに`x`、`x!`分割するので、すぐに「はい」を返すことができます。 すべての要素が以下の場合`x`の場合、合計の最大階乗は次のようになります。`(x-1)!`。 より小さい任意の数の階乗の合計`x!`の倍数に到達できない`x!`、 なぜなら`x!`厳密にすべての合計より大きくなります`(x-1)!`条項。 これにより、問題は、配列内の最大要素が次の値に等しいかどうかという単純なチェックに減ります。`x`、「はい」を返します。 それ以外の場合は、「いいえ」を返します。 

このアプローチでは、実際の階乗計算がすべて回避され、配列サイズに対して線形時間で動作します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * x) | O(1) または O(x) | x が大きい場合は遅すぎる/実行不可能 |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 整数の読み取り`n`そして`x`。 
2. 配列を読み取る`a`長さの`n`。 
3. 配列内の最大値を計算します。 これにより、合計の最大の階乗が特定されます。 
4. 最大値が次の場合`x`、合計には次のものが含まれます`x!`、したがって、合計は次で割り切れます。`x!`。 「はい」を出力します。 
5. それ以外の場合、合計は厳密に以下より小さくなります。`x!`で割り切れない`x!`。 「いいえ」を出力します。 

なぜ効果があるのか​​:`x!`はすべてのより小さい階乗で割り切れますが、より小さい階乗の合計は決して次の倍数にはなりません。`x!`少なくとも 1 つの項が等しい場合を除く`x!`。 最大要素のみを追跡することで、この不変条件を効率的に取得します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n, x = map(int, input().split())
    a = list(map(int, input().split()))
    
    if max(a) == x:
        print("Yes")
    else:
        print("No")

if __name__ == "__main__":
    main()
```このソリューションは入力を効率的に読み取り、大規模な配列を処理します。 私たちが使用するのは`max(a)`手動で繰り返して比較する代わりに最大の要素を見つけるため、簡潔で効率的です。 階乗計算にはループがないため、整数のオーバーフローが回避されます。 また、中間階乗を保存する必要がないため、メモリが節約されます。 

## 実用的な例

 **例 1**

 入力:```

3 2 2 2 3 3
```| ステップ | 最大(a) | 状態 | 出力 |
 | --- | --- | --- | --- |

 ここで、最大の要素は 3 であり、`x=4`。 したがって`4!`階乗の合計を除算しません。 

**例 2**

 入力:```
7 3
3 2 2 2 2 2 1
```| ステップ | 最大(a) | 状態 | 出力 |
 | --- | --- | --- | --- |
 | 配列の読み取り | [3,2,2,2,2,2,1] | 最大(a)=3 | 3 == 3 → はい |

 最大の要素は以下に等しい`x=3`、したがって、合計には次のものが含まれます`3!`そしてそれは次で割り切れます`3!`。 

これらのトレースは、割り算には最大要素のみが重要であるというロジックを裏付けています。

 ## 特殊なケース

 場合について`n=1, x=1, a=[1]`、単一階乗であるため、アルゴリズムは正しく「はい」を出力します。`1!`等しい`x!`。 すべての要素が未満の場合`x`、 のような`n=3, x=10, a=[7,8,9]`、階乗の合計は以下より小さい`10!`したがって、アルゴリズムは正しく「No」を出力します。 これらのエッジ ケースは、最大要素チェックが、大規模な階乗を計算することなく、考えられるすべての割り算シナリオを確実に捕捉することを示しています。
