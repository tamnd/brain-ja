 ## 解決策
 ## 問題の理解

 のみで構成される配列が与えられます。`1`と`-1`s. 私たちのタスクは、この配列を連続したセグメントに分割することです。各セグメントには、最初の要素から 2 番目の要素、3 番目の要素から 4 番目の要素を引くなどとして定義された交互の合計が含まれます。 すべてのセグメントにわたるこれらの交互の合計の合計はゼロでなければなりません。 各要素は正確に 1 つのセグメントに属している必要があるため、セグメントは集合的に配列全体をカバーします。 

制約は、配列の長さを示します。`n`200,000 に達することもあり、すべての合計`n`テスト ケース全体の上限は 200,000 です。 2 秒の時間制限により、テスト ケースごとの線形の複雑さよりも悪いことが排除されます。 考えられるすべてのセグメント分割を試行する二次アプローチでは、非常に時間がかかりすぎます。 

配列の長さが奇数である場合、または配列要素がすべて同一である場合には、明らかではないエッジ ケースが発生します。 たとえば、配列`[1, -1, 1]`には、セグメントに分割する方法がありません。セグメントには、バランスのとれない合計が残りますので、交互の合計がゼロに相殺されます。 不注意なアプローチでは、合計をチェックせずに隣接する要素をやみくもにペアにしようとし、不正確なパーティションが作成される可能性があります。 次のような単一要素配列`[1]`または`[-1]`セグメントの合計がゼロになることはないため、これも不可能です。 偶数の長さと同じ数の配列`1`そして`-1`多くの場合簡単ですが、連続する要素が同一である場合は注意が必要です。 

## アプローチ

 ブルートフォースアプローチでは、配列をセグメントに分割し、各セグメントの交互の合計を計算し、合計がゼロかどうかを確認するためにあらゆる方法が試行されます。 これは原理的には正しいですが、長さの配列の場合です。`n`、パーティションの数が指数関数的に増加するため、これは実行不可能になります。`n`200,000まで。 各候補パーティションの交互の合計を計算するとオーバーヘッドが追加されるため、演算数は天文学的なものになります。 

重要な洞察は、長さ 2 の交互の合計は、同一の要素の任意のペアで簡単に計算できるということです。`[x, x]`貢献する`x - x = 0`、これは理想的です。 異なる要素のペア`[1, -1]`または`[-1, 1]`貢献する`1 - (-1) = 2`または`-1 - 1 = -2`。 これは、ゼロの交互合計の場合、奇数長の配列内のペアと場合によってはシングルトンのみを考慮する必要があることを意味します。 実際には、これは貪欲な構築につながります。配列の長さが偶数であれば、要素を常に長さ 2 のセグメントとしてペアにすることができます。 配列の長さが奇数ですべての要素が同じ場合は不可能です。 それ以外の場合は、最初に長さ 3 の 1 つのセグメントを作成して交互の合計のバランスをとり、その後残りの要素をペアにすることができます。 

この観察により、線形時間ソリューションが可能になります。つまり、配列をスキャンし、要素を長さ 1 または 2 のセグメントに貪欲に結合して、交互の合計が確実にキャンセルされ、セグメントを出力します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る`t`。 
2. テスト ケースごとに、配列の長さを読み取ります。`n`そして配列`a`。 
3. もし`n`は奇数で、すべての要素が同一です (`[1,1,1,...]`または`[-1,-1,-1,...]`)、印刷`-1`どのパーティションも条件を満たすことができないためです。 
4. それ以外の場合は、空のリストを初期化します`segments`。 
5. 配列の合計がゼロの場合、単一のセグメントを作成します`[1, n]`に追加します`segments`。 これが機能するのは、同じ数のセグメントを交互に合計するためです。`1`そして`-1`自動的にキャンセルとなります。 
6. 配列の長さが偶数の場合、配列を 2 ステップで繰り返し、セグメントを作成します`[i, i+1]`。 各セグメントには次のいずれかの合計が交互に表示されます。`0`または`2/-2`、しかしペアは全体的にバランスがとれています。 
7. 配列の長さが奇数だが、すべての要素が同一ではない場合は、長さ 3 の最初のセグメントを作成します。`[1, 3]`交互の合計を調整し、残りの要素をペアで繰り返します。`[4,5],[6,7],...`。 
8. セグメントの数に続いてセグメントのリストを出力します。 

機能する理由: 小さなセグメントの交互の合計を制御できます。 要素をペアにすることで、要素が等しい場合は必ずゼロサム セグメントを作成します。 配列が奇数で均一でない場合、単一の 3 要素セグメントが合計のパリティを調整して合計がゼロになります。 これにより、すべてのセグメントにわたる交互の合計の合計がゼロになることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        # all identical elements of odd length are impossible
        if n % 2 == 1 and all(x == a[0] for x in a):
            print(-1)
            continue
        
        segments = []
        i = 0
        while i < n:
            if i + 1 < n and a[i] == a[i+1]:
                segments.append((i+1, i+2))
                i += 2
            else:
                segments.append((i+1, i+1))
                i += 1
        
        print(len(segments))
        for l, r in segments:
            print(l, r)

if __name__ == "__main__":
    solve()
```このソリューションは、次を使用して入力を効率的に読み取ります。`sys.stdin.readline`大規模な配列の場合。 同一の要素をチェックすることで、不可能なケースを確実に回避できます。 貪欲ループは長さ 1 または 2 のセグメントを構築し、すべての要素が確実にカバーされるようにします。 境界条件はチェックによって処理されます。`i+1 < n`2 要素セグメントを作成する前に。 セグメントインデックスは必要に応じて 1 から始まります。
