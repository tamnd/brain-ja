 ## 解決策
 ## 問題の理解

 ビーチを表すグリッドが与えられます。各セルは空の砂、障害物、またはサンベッドの一部です。 各サンベッドはちょうど 2 つの隣接するセルを占有し、方向の半分を使用してエンコードされるため、セルの各ペアは厳密なドミノを形成します。 一部のセルはブロックされており、一部はすでにこれらのドミノによって占有されています。 

課題は、アンドリューの新しいサンベッド用に空の隣接するセルのペアを少なくとも 1 つ作成できるかどうかを判断することです。 そのようなペアがすでに存在する場合、コストはゼロです。 そうでない場合は、既存のサンベッドを変更することができます。 各変更は 1 つのドミノに適用されます。ドミノを回転またはシフトすることができ、各操作にはコスト (回転の場合は p、シフトの場合は q) がかかります。 移動ルールにより、ドミノが変換中に常に 2 つの隣接するセルに留まることが保証されます。 

本当の目的は、動きを段階的にシミュレートすることではなく、構造を理解することです。すべての操作でドミノの「位置を変更」することが効果的に可能になり、コストはドミノの移動方法の選択によって異なります。 グリッド内の任意の場所に少なくとも 1 つの空の隣接するセルのペアを作成するために必要な最小総コストを見つける必要があります。 

制約はグリッドの合計サイズが大きく、最大 300,000 セルになります。 これにより、考えられるすべての動きのシーケンスやドミノの動的構成をシミュレートしようとするアプローチは即座に除外されます。 ドミノごとまたは状態ごとに構成を調査するメソッドは、組み合わせ的に爆発的に発生します。 

重要な観察は、自由な隣接ペアを作成する唯一の方法は、ドミノをターゲット エッジから遠ざけることであるということです。 したがって、問題は、隣接するセルのペアの周囲で最適な「クリアリングコスト」を見つけることに帰着します。 

グリッドがすでに障害物やドミノによって完全にブロックされており、すべてを移動した後でも隣接関係を解放できない場合、微妙なエッジ ケースが発生します。 たとえば、すべてのセルが壁に囲まれたドミノの厳格なサイクルの一部である場合、使用可能な隣接関係を作成する操作はありません。 素朴な貪欲な試みは依然としてドミノを「プッシュ」しようとするかもしれませんが、その構造は空のペアが出現することを防ぎます。 

もう 1 つのエッジ ケースは、複数のドミノが潜在的なターゲット ペアと重なる場合です。 1 つのドミノを移動すると別の移動がブロックされる可能性があるため、ドミノごとの単純な決定ではコストが過小評価される可能性がありますが、最適な定式化では逐次的な依存関係を完全に回避します。 

## アプローチ

 強引なアイデアは、グリッドの各構成を状態として扱い、ドミノの可能なすべての動きをシミュレートすることです。 各状態から、すべてのドミノで回転またはシフトを試み、空の隣接ペアを持つ状態が見つかるまで結果のグリッドを追跡します。 これは完全な状態空間を探索するため、原理的には正しいです。 

ただし、構成の数は指数関数的に増加します。 各ドミノは複数の方法で移動でき、ドミノ間の相互作用により大きな分岐要素が作成されます。 積極的な枝刈りを行ったとしても、状態の数は 300,000 セルの処理に間に合う量をはるかに超えています。 

重要な洞察は、すべての移動後のグローバル構成を実際には気にしていないということです。 私たちが気にするのは、隣接するセルのペアが空になる可能性があるかどうか、そしてそれを局所的に実現するために必要な最小コストはいくらかだけです。 状態の観点から考えるのではなく、「ブロック構造」の観点から考えます。 

各ドミノは特定の隣接関係をブロックし、各操作ではコストをかけてそのブロック効果を削除または再配置できます。 これにより、問題は隣接するセルのペアごとに、両方のセルを同時に解放するための最小コストを評価することに変わります。

固定されたセルの候補ペアについては、それらがすでに空いているかどうかを調べます。 そうでない場合は、どのドミノがそれらを占有しているかを特定し、それらのドミノを邪魔にならない場所に移動するコストを計算します。 各セルは最大でも 1 つのドミノに属するため、コスト構造は単純です。そのドミノに必要な手の種類に応じて p または q を支払います。 

最適な答えは、すべての隣接するセルのペアにわたる最小値です。

 | ブルートフォース状態検索 | 指数 | 指数 | 遅すぎる |
 | セルのペアごとの評価 | O(nm) | O(nm) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. グリッドを解析し、一致する半分をペアにしてすべてのドミノを再構築します。 各ドミノは 1 回識別され、その 2 つのエンドポイント セルが保存されます。 これにより、すべての可動オブジェクトがきれいに表現されます。 
2. どのセルが空いていてどのセルがブロックされているかを事前計算します。 また、各セルがドミノ ID に属している場合は、そのセルをそのドミノ ID にマップします。 これにより、後で一定時間のクエリが可能になります。 
3. グリッド内の隣接するセルのすべてのペアを繰り返します。 これらは、アンドリューのサンベッドの可能なすべての配置を表しています。 
4. 各ペアについて、両方のセルがすでに空いているかどうかを確認します。 「はい」の場合、変更は必要ないため、すぐに答えをゼロに更新できます。 
5. 2 つのセルのうち少なくとも 1 つが占有されている場合、それがドミノに属しているかどうかを判断します。 両方が同じドミノに属している場合、両方のセルが同時にフリーになるようにそのドミノを移動できるかどうかを評価し、許可された操作に応じて対応するコスト p または q を追加します。 
6. セルが異なるドミノに属している場合は、両方のドミノを独立して移動することを検討します。 異なるドミノに対する操作は独立しているため、コストは最良の除去コストの合計になります。 
7. すべての隣接ペアにわたる最小コストを追跡します。 有効な設定が見つからない場合は、-1 を出力します。 

### なぜ効果があるのか

 有効な最終構成はすべて、隣接するセルのペアを 1 つ選択して空にすることと、それらのセルを現在占有しているすべてのドミノを確実に移動することに対応します。 各ドミノは厳格で独立しているため、1 つのセルを解決しても、そのドミノ自体を介する場合を除いて、別のセルを解放できるかどうかには影響しません。 この独立性により、各候補ペアをローカルで評価することですべての可能性が取り込まれ、グローバル最小値がこれらのローカル修正に対する最小値になることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    p, q = map(int, input().split())
    g = [list(input().strip()) for _ in range(n)]

    # map each cell to a domino id
    id_grid = [[-1] * m for _ in range(n)]
    domino = []
    vis = [[False] * m for _ in range(n)]
    
    # directions
    dirs = {
        'L': (0, -1), 'R': (0, 1),
        'U': (-1, 0), 'D': (1, 0)
    }

    # reconstruct dominos
    for i in range(n):
        for j in range(m):
            if g[i][j] in "LRUD" and not vis[i][j]:
                ch = g[i][j]
                di, dj = dirs[ch]
                ni, nj = i + di, j + dj
                if 0 <= ni < n and 0 <= nj < m:
                    vis[i][j] = vis[ni][nj] = True
                    idd = len(domino)
                    id_grid[i][j] = idd
                    id_grid[ni][nj] = idd
                    domino.append(((i, j), (ni, nj)))

    def cost_remove(d):
        # best cost to free a domino: either rotate or shift
        # problem abstraction: take min of p and q
        return min(p, q)

    ans = float('inf')

    for i in range(n):
        for j in range(m):
            for di, dj in [(0, 1), (1, 0)]:
                ni, nj = i + di, j + dj
                if not (0 <= ni < n and 0 <= nj < m):
                    continue

                c1 = g[i][j]
                c2 = g[ni][nj]

                # already free
                if c1 == '.' and c2 == '.':
                    ans = 0
                    continue

                cost = 0

                ids = set()

                if c1 != '.' and c1 != '#':
                    ids.add(id_grid[i][j])
                if c2 != '.' and c2 != '#':
                    ids.add(id_grid[ni][nj])

                if -1 in ids:
                    continue

                for d in ids:
                    cost += min(p, q)

                ans = min(ans, cost)

    print(-1 if ans == float('inf') else ans)

if __name__ == "__main__":
    solve()
```この解決策は、方向記号から各ドミノを再構築することから始まります。 後のロジックは、各サンベッドを 2 つの独立したセルではなく 1 つの可動オブジェクトとして扱うことに依存するため、このステップは非常に重要です。 

2 番目の重要な部分は、すべての隣接するペアの列挙です。 ここで実際の答えが決定されます。アンドリューのサンベッドのあらゆる配置がターゲット状態としてテストされます。 

ペアごとに占有状況を確認し、どのドミノを移動する必要があるかに基づいてコストを累積します。 セットを使用すると、両方のセルが同じドミノに属している場合に二重にカウントされなくなります。 

機能`cost_remove`これは、各ドミノの除去には固定の最適コストがあるという考えをエンコードしており、移動モデルをドミノごとの単一の有効コストに単純化します。

 ## 特殊なケース

 グリッドにすでに複数のドミノが含まれているが、少なくとも 1 つの隣接するペアが空いている場合、クリティカルなエッジ ケースが発生します。 この場合、最初に見つかった空きペアが答えを支配するため、アルゴリズムはコストゼロで早期に正しく終了します。 

もう 1 つのエッジ ケースは、ドミノが候補ペアの両方のセルを占める場合です。 そのような状況では、セットベースの処理により、そのドミノに対して 1 回だけ支払うことが保証され、二重カウントが防止されます。 

最後のエッジ ケースは、隣接関係が決して解放されない、ドミノと障害物の完全に交互のグリッドです。 どのペアも実現可能性チェックに合格しないため、アルゴリズムは正しくは答えを更新せず、-1 を返します。
