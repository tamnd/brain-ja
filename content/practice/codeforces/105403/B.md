 ## 解決策
 ## 問題の理解

 各テスト ケースでは 2 つのスコアの配列が提供され、1 つは Arturo に属し、もう 1 つは Benito に属します。 すべてのインデックスに対して値のペアがありますが、その組み合わせはまったく不明です。アルトゥーロの番号とベニートの番号を、希望する順序でさまざまなコンテストの問題に自由に割り当てることができます。 

各問題について、割り当てられた値がより大きい人がその問題に勝ちます。 アルトゥーロのスコアは常に偶数で、ベニートのスコアは常に奇数であるため、平等は決して起こらず、どの組み合わせでも厳密な勝者が生まれます。 

タスクは、単一の割り当てを再構築することではなく、2 つのマルチセットがどのように一致するかについて考えられるすべての組み合わせを推論することです。 値をペアにするあらゆる方法の中で、Arturo が勝つ比較の数を最大化したいと考えています。 

制約$N \le 5 \cdot 10^4$あらゆる解を最大でも強制的に$O(N \log N)$テストケースごとに。 二次関数の何か$N$40 件の大きなケースを並べ替えたりスキャンしたりすると、すでに制限を超えてしまうため、遅すぎます。 これは、組み合わせ代入検索ではなく、ソートされた配列に対する貪欲なマッチング戦略が必要であることを直ちに示唆しています。 

値が繰り返されると、微妙な問題が発生します。 アルトゥーロが小さな偶数を多く持ち、ベニートが小さな奇数と大きな奇数が混在している場合、それらを一致させる順序によって結果が大きく変わる可能性があります。 最小値同士の比較を慎重に調整しない単純な貪欲なアプローチは、すでに勝った試合で大きなアルトゥーロ値を無駄にする可能性があります。 

もう 1 つのエッジ ケースは、すべての Arturo 値がすべての Benito 値よりも大きい場合です。 その場合、答えは簡単です$N$ただし、早期に大量の Benito 値を消費する不注意な貪欲は、正しく実装されていない場合、依然としてマッチを無駄にする可能性があります。 

## アプローチ

 ブルートフォースソリューションでは、アルトゥーロの番号とベニートの番号の組み合わせのすべての組み合わせが試行されます。 各組み合わせについて、満たすポジションの数を数えます。$a_i > b_{\pi(i)}$。 これは探索します$N!$マッチング、さらには$N = 10$これはすでに実行不可能になっています。$10! \approx 3.6 \cdot 10^6$、そしてより大きな場合には完全に爆発します。 

重要な観察は、これが単調比較ルールを使用した完全な 2 部構造における最大マッチング問題であるということです。 両方の配列がソートされると、最適な戦略は同一性ではなく、相対的な順序のみに依存します。 できるだけ多くの「勝利」を維持する方法で、各 Arturo 値を Benito 値に割り当てたいと考えています。 

両方の配列をソートすると、可能な限り最小値と最小値のペアを作成するプロセスとして解釈できますが、勝つことが不可能な場合はスキップします。 この構造は、古典的な「ペアごとの比較で勝利を最大化する」という貪欲な問題と同じです。可能であれば、弱いアルトゥーロ値を使用して弱いベニト値を破るか、必要に応じてより強いベニト値に対してそれを犠牲にして、後の勝利のためにより強いアルトゥーロ値を保持します。 

これは当然、ツーポインタの貪欲戦略につながります。 両方の配列を徐々に並べ替えます。 私たちは両方の配列を通じてポインタを維持し、常に残りの最小の Benito 値に対してまだ勝つことができる最小の Arturo 値と一致しようとします。 アルトゥーロの現在の最小値がベニートの最小値よりも大きければ、私たちが勝利します。 そうしないと、この貪欲な構造では、アルトゥーロの現在の値がより大きなベニトの値に勝つことができないため、ベニトのポインタを進めて、その比較を損失として扱います。 

これにより、小さな試合で勝つことができた試合で大きなアルトゥーロ値を無駄にすることがなくなり、勝利の可能性を決して逃すことがなくなります。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. Arturo の配列と Benito の配列を非降順でソートします。 並べ替えは構造を明らかにするため不可欠です。一度並べ替えると、最適な一致をローカルで推論できるようになります。 
2. 2 つのポインターを初期化します。1 つは Arturo 用、もう 1 つは Benito 用で、どちらもソートされた配列の先頭から開始します。 また、アルトゥーロの勝利のカウンターを初期化します。 
3. 現在の Arturo 値と現在の Benito 値を比較します。 

アルトゥーロの値が大きい場合、これら 2 つを同じ問題に割り当て、アルトゥーロの勝利としてカウントします。 両方の値が消費されるため、両方のポインターを進めます。 

アルトゥーロの値がそれより大きくない場合、このアルトゥーロの値は残りの最小のベニトの値に勝つことができず、貪欲な構造を改善する方法でより大きなベニトの値にも勝つことができません。 したがって、ベニトのポインタを進めることでこのベニトの値を破棄し、事実上アルトゥーロの負け試合に組み合わせます。 Arturo ポインタは所定の位置に留まります。これは、この値が、後続のより小さい残りの Benito 値が存在する場合に勝てる可能性があるためです。 
4. ポインタの 1 つが配列の末尾に到達するまで、このプロセスを続けます。 
5. 記録された成功した比較の数は、アルトゥーロの可能な最大勝利数です。 

### なぜ効果があるのか

 重要な不変条件は、現在のポインターより前のすべての Benito 値は、合計勝利数を改善できない方法でペアになっているかスキップされているため、将来の勝利にはすでに「無関係」であるとみなされるということです。 同様に、各 Arturo 値は、残りの候補の中から可能な限り最良の対戦相手とすでに一致しているか、将来の比較のために保持されています。 

アルトゥーロが利用可能な最小のベニト値に勝てないときはいつでも、そのベニト値を他の場所で使用しても、今それを破棄するよりも多くの勝利を生み出すことはできないため、貪欲な決定は安全です。 逆に、アルトゥーロが最小のベニト値に勝つことができるときはいつでも、アルトゥーロを遅らせると後でより強いベニト値と一致する危険があるだけであり、勝利数を増やすことはできないため、それらを組み合わせるのが最適です。 

各ポインター ステップでのこの局所的な最適性により、シーケンス全体にわたるグローバルな最適性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        a.sort()
        b.sort()

        i = j = 0
        ans = 0

        while i < n and j < n:
            if a[i] > b[j]:
                ans += 1
                i += 1
                j += 1
            else:
                j += 1

        print(ans)

if __name__ == "__main__":
    solve()
```コードは複数のテスト ケースを読み取ることから始まります。 それぞれのケースで、モノトーンの貪欲スキャンを適用できるように、両方の配列がソートされます。 2 つのインデックスが配列を横断します。 アルトゥーロの現在値がベニートの現在値を超える場合、その一致をコミットし、両方のインデックスを進めます。 それ以外の場合は、現在の最小のアルトゥーロ候補には勝てないため、現在のベニトの値を破棄し、ベニトのリストを進めて、より弱い対戦相手を探します。 

重要な実装の詳細は、失敗の場合は Benito のポインタのみが進むということです。 そこで Arturo を進めると、後で勝つ可能性がある潜在的に有用な値が誤って破棄されてしまいます。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque

    input = sys.stdin.readline
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        a.sort()
        b.sort()

                ans += 1
                i += 1
                j += 1
            else:
                j += 1
        out.append(str(ans))
    return "\n".join(out) + "\n"

 ## 特殊なケース

 重要なエッジケースは、アルトゥーロが多数の小さな値を持ち、ベニートがいくつかの非常に大きな値と小さな値が混在している場合です。 戦略的にスキップせずに誤って順番にペアを組むと、小さな Arturo 値が大きな Benito 値に無駄になり、最終的なカウントが減少します。 

The greedy pointer strategy avoids this by always discarding Benito values that cannot be beaten by the current smallest Arturo candidate, preserving Arturo’s stronger values for future opportunities.

 もう 1 つの特殊なケースは、片側の値が均一であることです。 すべての Arturo 値が等しい場合、正確さはそれらが十分な Benito 値を超えるかどうかに完全に依存します。 比較は厳密にローカルであり、値の多様性を想定していないため、アルゴリズムはこれを自然に処理します。 

最後に、すべての値がすでに Arturo にとって有利な状態になったときに、ポインタが同期して進み、次の結果が得られます。$N$不要なスキップなしですぐに再生できます。
