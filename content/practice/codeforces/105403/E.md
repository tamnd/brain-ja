 ## 解決策
 ## 問題の理解

 まず、都市と双方向道路を表す接続された無向グラフから始めます。 政府は正確に選択したいと考えている`k`これらの道路を選択し、選択した各道路に方向を割り当てます。これにより、この操作の後でも、すべての都市が方向指定された道路のみを使用して他のすべての都市に到達できるようになります。 

重要な制約は、すべてのエッジの方向を指定することは許可されていないことです。`k`彼らのうち。 残りのエッジは方向性のないままであり、方向性のある移動には使用できません。 したがって、最終的な構造は、ピッキングによって形成された有向グラフになります。`k`元のグラフからエッジを抽出し、それぞれに方向を割り当てます。 

要件は強力です。結果として得られる有向グラフは、強く接続されたままでなければなりません。 つまり、頂点のペアごとに`u`そして`v`、からの有向パスが存在する必要があります。`u`に`v`。 

入力制約は、テスト ケースごとに線形に近い解決策が必要であることを意味します。 まで`2 * 10^5`テスト全体にわたるケースごとのエッジ、それより悪いもの`O(n + m)`または`O(m log n)`タイムアウトになる危険性があります。 これにより、組み合わせ検索ではなく、DFS または BFS ベースの構造分解が推進されます。 

素朴なアプローチでは、エッジのサブセットを選択して方向をテストしようとしますが、各試行後の強い接続性のチェックさえも線形であり、サブセットの数は指数関数的です。 これにより、ブルートフォースは即座に排除されます。 

いくつかの特殊なケースは、早期に切り分ける価値があります。 

もし`k = 0`、空の有向グラフが強く接続されているかどうかが尋ねられます。 これは次の場合にのみ可能です`n = 1`そうでない場合は、到達可能性がまったく存在しないため、不可能です。 

グラフがツリーの場合 (`m = n - 1`) の場合、すべてのエッジを方向付けしたとしても、有向サイクルを形成することはできません。 ツリーにはサイクルがないため、長期間にわたって強く接続することは不可能です。`n > 1`。 

最も重要な構造要件は、有向グラフの強力な接続性がすべての頂点をカバーするサイクルの存在を意味することです。 これは、バック エッジとサイクルを作成するには DFS ツリー構造に依存する必要があることを示唆しています。 

## アプローチ

 ブルートフォース手法では、次のすべてのサブセットが選択されます。`k`エッジを調整し、可能なすべての向きを試してください。 構成ごとに、強力な接続性について BFS/DFS チェックを実行します。 中程度の場合でも`m`、サブセットの数は`C(m, k)`、それは天文学的な大きさです。 各小切手にかかる費用`O(n + m)`, したがって、このアプローチはすぐに崩壊します。 

重要な点は、DFS スパニング ツリーを使用して強力な接続を強制できることです。 接続された無向グラフでは、DFS によってツリー エッジとバック エッジが生成されます。 ツリーのエッジはルート構造を定義し、バック エッジは上方向と下方向のトラバースを可能にするサイクルを提供します。 

このアイデアは、隣接する DFS レベル間で双方向の到達可能性を維持する方法で、DFS に沿ってエッジを配置することです。 ただし、すべてのエッジを方向付ける必要はありません。`k`彼らのうち。 これは、強力な接続を保証するのに十分な量の構造を形成するエッジのサブセットを選択できることを意味します。 

重要な事実は、グラフに少なくとも 1 つのサイクルが含まれている場合にのみ、グラフが強く接続された方向を持つことができるということです。より一般的には、すべてのツリー エッジがサイクルを形成する少なくとも 1 つのバック エッジによってサポートされているスパニング構造を抽出できます。 DFS はそのようなエッジを自然に露出します。 

任意のノードで DFS をルート化し、DFS ツリーを検討します。 あらゆる木の端`(u, v)`親から子への方向付けが可能です。 バックエッジごとに`(u, v)`ノードを祖先に接続すると、ノードを子孫から祖先に向けることができます。 これにより、DFS パスに沿って有向サイクルが作成されます。 

強力な接続を確保するために、すべてのエッジを使用する必要はありません。 すべての木のエッジがバック エッジで形成された少なくとも 1 つの有向サイクル上に位置するように十分なエッジを選択するだけで済みます。 標準的な構築では、すべてのツリー エッジと、各サブツリー エッジのサイクルを閉じるのに十分なバック エッジを取得します。 

グラフが接続されており、少なくとも 1 つのサイクルがある場合、いつでも次のセットを選択できます。`k`エッジには、場合によっては一部の調整を除いて、すべての DFS ツリー エッジが含まれます。`k`、残りの選択範囲を後ろの端で塗りつぶします。 実現可能性の条件は、次の場合にグラフがツリーではないことに帰着します。`k > n - 1`に到達するのに十分なバックエッジが存在することを確認します。`k`。 

したがって、建設的な戦略は、DFS を実行し、ツリー エッジとバック エッジを収集し、特定の順序でエッジを選択することです。最初にすべてのツリー エッジを取得し、次に、到達するまでバック エッジを追加します。`k`。 最後に、木の端を下に、後ろの端を上に向けます。 

重要な洞察は、DFS 分類によって既にエッジが接続構造を維持するエッジ (ツリー エッジ) とサイクルを作成するエッジ (バック エッジ) に分割されており、強力な接続には方向を閉じるのに少なくとも十分なサイクル エッジが必要であるということです。

 ## アルゴリズムのチュートリアル

 グラフがつながっていると仮定します。 

1. ノードから DFS を実行する`0`、DFS ツリーを記録します。 からのすべてのトラバースに対して`u`訪れていない人へ`v`、ストアエッジ`(u, v)`木の端として。 これにより、すべての頂点を構成するルート付きスパニング ツリーが構築されます。 
2. 隣接関係リストを探索しているときに、親ではないすでに訪問済みのノードが見つかった場合は、それをバック エッジとして記録します。 これらのエッジは、グラフ構造のサイクルを示します。 
3. DFS が終了すると、2 つの互いに素なエッジ セットができます。到達可能性構造を定義するツリー エッジと、サイクルを閉じるバック エッジです。 記録されたエッジの総数が 未満の場合`k`、十分なエッジを選択できないため、回答は不可能です。 
4. グラフがツリー (バック エッジが存在しない) の場合、`k > 0`、指定された設定では双方向の到達可能性をサポートするサイクルがないため、すぐに NO を返します。 
5. この順序でエッジを選択します。最初にすべての木のエッジを取得し、次に正確に収集するまでエッジを元に戻します。`k`エッジ。 到達する前にバックエッジがなくなってしまったら`k`、NOを出力します。 
6. 選択したツリーのエッジを DFS 順序で親から子に向けます。 これにより、ルートから下への到達可能性が保証されます。 
7. 選択したバックエッジを子孫から祖先に向けます。 これにより、DFS の祖先に沿った上向きの接続が確保されます。 

### なぜ効果があるのか

 DFS ツリーは、指向性のあるツリー エッジを使用してルートからすべてのノードに到達できることを保証します。 バック エッジは、任意のサブツリーからその先祖に戻るトラバースを可能にする有向サイクルを作成します。 すべてのノードにはバック エッジ チェーンを介してルートへのパスがあり、ルートからツリー エッジを介して下位へのパスがあるため、ノードのすべてのペア間で相互到達可能性が得られます。 不変条件は、すべてのサブツリーが祖先へ向かうバック エッジを少なくとも 1 つ持ち、有向構造が一方向の階層に退化するのを防ぐことです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    T = int(input())
    out = []

    for _ in range(T):
        n, m, k = map(int, input().split())
        adj = [[] for _ in range(n)]
        edges = []

        for i in range(m):
            u, v = map(int, input().split())
            adj[u].append((v, i))
            adj[v].append((u, i))
            edges.append((u, v))

        parent = [-1] * n
        used = [False] * m
        depth = [0] * n

        tree_edges = []
        back_edges = []

        def dfs(u):
            for v, eid in adj[u]:
                if used[eid]:
                    continue
                used[eid] = True
                if parent[u] == v:
                    continue
                if parent[v] == -1:
                    parent[v] = u
                    depth[v] = depth[u] + 1
                    tree_edges.append((u, v))
                    dfs(v)
                else:
                    back_edges.append((u, v))

        parent[0] = 0
        dfs(0)

        if len(tree_edges) + len(back_edges) < k:
            out.append("NO")
            continue

        if len(tree_edges) == n - 1 and k > len(tree_edges):
            out.append("NO")
            continue

        res = []
        for u, v in tree_edges:
            if len(res) < k:
                res.append((u, v))

        for u, v in back_edges:
            if len(res) < k:
                res.append((u, v))

        if len(res) < k:
            out.append("NO")
        else:
            out.append("SI")
            for u, v in res:
                out.append(f"{u} {v}")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装は DFS エッジ分類に依存しています。 の`used`配列により、各無向エッジが確実に 1 回処理され、重複した分類が回避されます。 ツリーのエッジは、新しい頂点を最初に発見したときに記録され、バック エッジは、親ではないすでに訪問した頂点に遭遇したときに記録されます。 

微妙な点は、無向隣接リスト内のエッジを二重にカウントしないようにすることです。 の`used[eid]`ガードは、各エッジが 1 回だけ分類されることを保証します。 

構築フェーズでは最初のものを選択するだけです`k`ツリーとバックエッジの結合からのエッジ。 方向規則は保存されたファイルに暗黙的に含まれます。`(u, v)`順序付け: ツリー エッジは DFS 方向に従い、バック エッジは遭遇すると子孫から祖先に格納されます。

 ## 特殊なケース

 ツリー入力はキーの制限を直接公開します。 例えば、`4 3 2`エッジが線を形成しているものには、DFS ではバック エッジがないため、トラバース後にはツリー エッジのみが存在します。 もし`k`を超える`n-1`の場合、選択はすぐに失敗し、アルゴリズムは正しく NO を返します。 

三角形などの完全に周期的なグラフでは、DFS が少なくとも 1 つのバック エッジを確実に生成します。 いつ`k = m`、すべてのエッジが選択され、方向は DFS 検出に従います。 バックエッジは上方への移動が可能であることを保証し、方向付けられた構造が根の生えた木に崩壊するのを防ぎます。 

最小限のグラフ`n = 1`そして`k = 0`違反する到達可能性の制約がないため、受け入れられます。 DFS は簡単に実行され、出力は空ですが、依然として強力な接続を空虚に満たしています。
