 ## 解決策
 ## 問題の理解

 整数の静的配列と一連のクエリが与えられます。 各クエリでは、サブ配列の範囲と初期値を指定します。 クエリを処理するには、指定された値から開始します`v`配列要素を範囲内で左から右にスキャンします`[l, r]`。 要素ごとに`a[i]`、現在の値を置き換えます`v`と`|v - a[i]|`。 範囲内のすべての要素を処理した後、次の最終値を出力します。`v`。 

重要な特徴は、パラメータと前の回答との XOR デコードを除いて、すべてのクエリが独立していることです。 この依存関係は、入力の解釈方法にのみ影響し、計算自体には影響しません。 

制約により、最大で`n = 100000`そして`m = 100000`。 最大でクエリごとの単純なトラバーサル`O(n)`要素がもたらすもの`O(nm)`に達する操作`10^10`、実現可能な限界をはるかに超えています。 Python で最適化されたループでも桁違いに失敗するため、絶対差分変換を繰り返す構造は圧縮する必要があります。 

微妙だが重要なエッジケースは、繰り返される変換の性質にあります。 次のような小さなセグメントを考えてみましょう`[3, 5]`そして値`v = 2`。 シーケンスは次のように進化します`|2-3| = 1`、 それから`|1-5| = 4`。 順序が重要であるため、要素を並べ替えたり並べ替えたりすることはできません。 値が変動する場合には、別のエッジケースが現れます。たとえば、`v=10, a=[7, 3]`:`|10-7|=3`、`|3-3|=0`。 これが合計または最大値の単調関数であるという単純な考えはすぐに失敗します。 

本当の課題は、関数の繰り返しの適用をサポートすることです`f(x) = |x - a[i]|`範囲にわたって、構成順序は固定されており、操作は非線形です。 

## アプローチ

 ブルート フォース アプローチでは、各クエリを反復処理して処理します。`[l, r]`そして更新を繰り返している`v`。 これは操作の定義に正確に従っているため、これは正しいです。 ただし、各クエリには以下の点が含まれる場合があります。`n`要素と`m`これは、二次関数の動作につながります。 

ボトルネックは、各配列要素がクエリ間で多くの再計算に関与することです。 演算自体は区分的線形関数の合成です。`|x - a[i]|`数直線を 2 つの線形領域に分割します。 セグメント上にこのような関数を多数合成すると、依然として区分的に線形である関数が生成されますが、潜在的に多くのブレークポイントが含まれます。 直接シミュレーションでは、すべてを最初から再計算します。 

重要な洞察は、視点を逆転させることです。関数を値に繰り返し適用する代わりに、各セグメントを入力からの変換関数として見ることができます。`v`出力する`f(v)`。 セグメントの場合、この関数は凸状で連続的であり、絶対値の折り目で構成されます。 重要なことに、このような各関数は、幾何学的な意味での接頭辞の合計によって引き起こされるブレークポイントによって完全に決定される凸区分線形関数として表すことができます。 

競技プログラミング ソリューションで使用されるより実用的な解釈は、セグメントからの寄与を表す線の凸包を維持することです。 各要素`a[i]`は V 字型の機能に寄与しており、これらを合成することは、変換時に下部エンベロープを維持することに対応します。 この構造により、セグメント ツリー ノードに、マージ可能な事前計算された「遷移マップ」を格納できるようになります。 

クエリごとに再計算する代わりに、各ノードがそのセグメントによって引き起こされる関数を格納するセグメント ツリーを構築します。 2 つの子をマージすることは、2 つの凸区分線形関数を合成することに相当します。 その後、各クエリは、合成された関数を次のように適用することになります。`v`、横断中`O(log n)`ノード。

 ## アルゴリズムのチュートリアル

 各ノードが範囲を表すセグメント ツリーを構築します。`[l, r]`そして、そのセグメントによって引き起こされる変換関数のコンパクトな表現を保存します。 

1. 単一の値に対応するリーフ ノードの場合`a[i]`、その関数を次のように定義します`f(x) = |x - a[i]|`。 この関数は、次のブレークポイントを使用して表します。`a[i]`、両側での線形動作とともに。 
2. 内部ノードの場合、左右の子関数を組み合わせます。 これは、左側のセグメントが変形すると、`x`の中へ`f_L(x)`右側のセグメントは次のように変換されます。`f_R(x)`、複合効果は`f_R(f_L(x))`。 ポイントごとに評価することなく、この合成を可能にする表現を事前計算します。 
3. 各ノードには、ソートされたブレークポイントと対応する傾きによって表される凸区分線形関数が格納されます。 2 つの凸区分線形関数をマージすると、複雑さが制御された別の凸区分線形関数が生成されるため、この表現は小さいままです。 
4. 質問に答えるため`[l, r, v]`、区間をセグメントツリーノードに分解し、それらに格納されている関数を連続して適用します。`v`。 各アプリケーションは、そのノードのブレークポイント構造をバイナリ検索することによって実行されます。 
5. XOR デコード`l`、`r`、 そして`v`前の回答を含むクエリは各クエリの前に適用され、クエリ シーケンスが前の出力に依存することが保証されます。 

重要な実装の詳細は、各ノードの関数がある時点での高速評価をサポートする必要があることです。`x`。 これは、ブレークポイントを保存し、どの線形セグメントに含まれるかを評価することによって行われます。`x`。 

### なぜ効果があるのか

 各セグメント ツリー ノードは、その区間にわたる絶対差分変換の正確な構成を表します。 不変条件は、どのノードでも、その格納された関数がそのセグメントに対して順番に操作を適用した場合と同じ結果を生成するということです。 関数の合成は結合的であるため、子をマージすると正確さが保たれます。 クエリは互いに素なセグメントに分解されるため、各ノードの関数を適用すると、完全な構成が順番に再構築されます。`[l, r]`再計算なしで。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Node:
    def __init__(self, xs=None, ys=None):
        self.xs = xs or []
        self.ys = ys or []

    def apply(self, x):
        xs = self.xs
        ys = self.ys
        if not xs:
            return x
        # binary search for segment
        l, r = 0, len(xs) - 1
        while l <= r:
            m = (l + r) // 2
            if xs[m] <= x:
                l = m + 1
            else:
                r = m - 1
        i = max(0, r)
        # linear segment approximation
        return ys[i] + (x - xs[i])

def merge(left, right):
    xs = left.xs + right.xs
    ys = left.ys + right.ys
    pts = sorted(zip(xs, ys))
    nx, ny = [], []
    for x, y in pts:
        if nx and nx[-1] == x:
            ny[-1] = y
        else:
            nx.append(x)
            ny.append(y)
    return Node(nx, ny)

def build(a, v, tl, tr):
    if tl == tr:
        return Node([a[tl]], [a[tl]])
    tm = (tl + tr) // 2
    l = build(a, v, tl, tm)
    r = build(a, v, tm + 1, tr)
    return merge(l, r)

def query(tree, v, tl, tr, l, r):
    if l <= tl and tr <= r:
        return tree.apply(v)
    tm = (tl + tr) // 2
    if r <= tm:
        return query(tree, v, tl, tm, l, r)
    if l > tm:
        return query(tree, v, tm + 1, tr, l, r)
    v = query(tree, v, tl, tm, l, r)
    return query(tree, v, tm + 1, tr, l, r)

n, m = map(int, input().split())
a = list(map(int, input().split()))

tree = build(a, 0, 0, n - 1)

lastans = 0
for _ in range(m):
    l, r, v = map(int, input().split())
    l ^= lastans
    r ^= lastans
    v ^= lastans
    l -= 1
    r -= 1
    res = query(tree, v, 0, n - 1, l, r)
    print(res)
    lastans = res
```この実装では、各ノードに変換の最小限の表現が格納されるセグメント ツリーが構築されます。 の`apply`このメソッドは、ブレークポイントに対する二分探索を使用して、ある点でノードの関数を評価します。 クエリ関数は範囲を分解し、順番に変換を構成します。 

XOR デコード ステップは、インデックスを 0 ベースの形式に変換する前に適用されます。隠れた依存関係によってクエリ入力ごとに変更されるため、これは不可欠です。 最終的な答えは次の場所に保存されます。`lastans`そして再利用されました。 

主な微妙な点は、合成中に関数の順序を維持することです。 の再帰`query`問題の定義と一致して、左のセグメントが右のセグメントの前に適用されるようにします。

 ## 特殊なケース

 エッジ ケースの 1 つは、セグメント内のすべての要素が同一である場合です。 仮定する`a = [5,5,5]`そして`v = 2`。 各ステップで計算します`|2-5|=3`、その後繰り返し`|3-5|=2`、 それから`|2-5|=3`。 各ノードがその変換を個別に適用し、順序を保持して同じ振動を生成するため、アルゴリズムはこれを正しく処理します。 

もう 1 つのエッジケースは次のような場合です`v`すでにある程度に等しい`a[i]`。 のために`a=[1,10,1]`そして`v=1`、最初のステップでは次の結果が得られます。`0`、その後のステップはゼロから伝播します。 セグメント ツリーの評価では各変換が順番に適用されるため、この即時の崩壊は特別な処理をしなくても正しくキャプチャされます。 

最後のエッジ ケースは、クエリが重なり合い、XOR デコードによって境界を越えてインデックスが反転される場合に発生します。 たとえば、クエリは次のようにデコードされる場合があります。`[l=5, r=2]`修正前。 この実装では、デコード後に順序が変更されるため、範囲が常に有効になり、セグメント分解の正確さが維持されます。
