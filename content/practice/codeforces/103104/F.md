 ## 解決策
 ## 問題の理解

 私たちにはバッテリーのコレクションと撮影場所のコレクションが与えられました。 各バッテリーのエネルギー量は固定されており、各場所で 1 回の記録セッションを完了するには固定量のエネルギーが必要です。 各バッテリーは最大 1 回使用でき、ある場所でバッテリーの使用を開始したら、中断したり交換したりすることなく、その場所の要件を完全に満たす必要があります。 

タスクは、完全に完了した場所の数が最大になるように、バッテリーと場所の間の組み合わせ戦略を選択することです。 各バッテリーは最大 1 つの場所に割り当てることができ、各場所に最大 1 つのバッテリーを割り当てることができます。 選択したバッテリーに必要な持続時間以上の容量がある場合、その場所は満たされます。 

この構造は、二部マッチングのような問題をすぐに示唆しますが、一般的なマッチング アルゴリズムには制約が大きすぎます。 代わりに、これは 2 つのマルチセットにわたる貪欲な割り当ての問題です。 

この制約は、O(N log N + M log M) または O(N + M log M) に近い値が必要であることを意味します。 N が 100000 まで、M が 300000 までなので、二次関数や M の N 倍さえも不可能です。 すべてのバッテリーと位置の組み合わせを試すソリューションは、最悪の場合、最大 3 × 10^10 の比較に達するため、明らかに実行不可能です。 

重要な構造上の詳細は、すべての撮影時間が 2 の累乗であることです。 これは、要件を昇順に処理し、繰り返される値を効率的に処理できるため、グループ化またはバケットベースの貪欲マッチングが効果的であることを示す強力なヒントです。 

いくつかの特殊なケースが重要です。 

注意深い順序付けをせずに、場所を満たすことができる最小のバッテリーを割り当てるという単純な欲張りは失敗する可能性があります。 たとえば、バッテリーが [5, 6] で要件が [4, 5] の場合、不注意な割り当てによって 5 → 5 および 6 → 4 が得られる可能性がありますが、これは問題ありませんが、間違った順序で貪欲に決定を覆すと、実装順序によっては 6 対 5 が無駄になり、4 が不一致のままになる可能性があります。 同一の要件が複数存在する場合、貪欲な選択は局所的な適合性ではなく全体的な最適性を考慮する必要があるため、別の微妙な失敗が発生します。 

## アプローチ

 ブルート フォース ビューでは、考えられるすべての方法でバッテリーを場所に割り当て、最もよく一致するバッテリーをカウントしようとします。 これは、ai ≥ bi の場合にエッジが存在する 2 部グラフですべてのマッチングを試行することに対応します。 たとえ貪欲な割り当てに限定したとしても、単純なシミュレーションではすべてのバッテリーをすべての場所に対してチェックすることになり、制限をはるかに超える O(NM) 時間の計算量が発生します。 

重要な観察は、必要なエネルギーを超えて場所のアイデンティティを保存する必要がないということです。 要件は単なるサイズであり、満たす数だけを考慮するため、問題は古典的な「容量 ≥ 需要の一致の数を最大化する」問題になります。 これは通常、両方の配列をソートし、最小値から最大値まで貪欲に一致させることで解決します。 

ただし、注意すべき点は、b_i が 2 の累乗であることです。 これにより、非常に限られた数の個別の要件値 (最大 31) が保証されます。 M を大きいものとして扱う代わりに、要件を指数でインデックス付けされた周波数バケットに圧縮することができます。 次に、小規模から大規模までの需要レベルに合わせてバッテリーを効果的にマッチングします。 

バッテリーを昇順に並べ替え、要件バケットを最小電力から最大電力まで処理します。 要件のサイズごとに、それを満たしながら可能な限り最小のバッテリーを割り当てるように努めます。 これにより、必要な場合を除き、小さな要件で大きなバッテリーを無駄にすることがなくなります。 

私たちはバッテリーを監視し、要求を満たすために貪欲にバッテリーを消費します。 両側がソートされ、前に進むだけなので、各要素は 1 回処理されます。

 ## アルゴリズムのチュートリアル

 1. すべてのバッテリー容量を読み取り、降順でない順に並べ替えます。 これにより、要件を満たすことができる最小の利用可能なバッテリーを常に使用し、後でより大きな需要が発生した場合に備えて、より大きなバッテリーを保存することができます。 
2. 2 の累乗値ごとに存在するリクエストの数を数えます。 bi = 2^j なので、周波数を配列 freq[j] に格納します。 これにより、入力が最大 31 のカテゴリに圧縮されます。 
3. ソートされたバッテリー配列の先頭でポインタ i を初期化します。 このポインターは、未使用の最小のバッテリーを表します。 
4. 可能な 2 のべき乗を最小から最大まで繰り返し、必要な容量の昇順で freq[j] を処理します。 これにより、常に簡単なタスクを最初に満たそうとすることが保証されます。 
5. 各要件レベル 2^j に対して、バッテリーを貪欲に割り当ててみます。 freq[j] > 0 および i < N の間、容量 ≥ 2^j のバッテリーが見つかるまで i を進めます。 存在しない場合は、このバッテリー範囲ではこのレベル以上の割り当てがこれ以上できないため、中断します。 
6. 有効なバッテリーが見つかったら、それを 1 つの要件に割り当て、i をインクリメントし、freq[j] をデクリメントして、応答カウンターをインクリメントします。 これにより、バッテリーと場所の両方が消費されます。 
7. すべての要件レベルが処理されるか、バッテリーがなくなるまで続行します。 

### なぜ効果があるのか

 このアルゴリズムは、貪欲な不変条件を維持します。つまり、どの時点でも、最小残存バッテリーは現在の要件レベルに対して小さすぎるか、そのレベルにとって可能な限り最良の選択であるかのいずれかになります。 バッテリーと要件は両方とも昇順に処理されるため、より大きなバッテリーをより小さな要件に割り当てるという逸脱は、満たされる割り当ての数を増やすことなく、将来のより大きな要件に対する柔軟性を低下させるだけです。 単調な構造により、要件に対してバッテリーがスキップされると、より小さな要件には決して役に立たなくなり、要件が増加すると、以前のバッテリーではそれ以上満たすことができなくなります。 これにより、合計カウントを向上させる可能性のある有益なスワップが防止されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    a.sort()

    freq = [0] * 31
    for x in b:
        freq[x.bit_length() - 1] += 1

    ans = 0
    i = 0

    for j in range(31):
        need = 1 << j
        while freq[j] > 0 and i < n:
            if a[i] >= need:
                ans += 1
                freq[j] -= 1
                i += 1
            else:
                i += 1

    print(ans)

if __name__ == "__main__":
    solve()
```この解決策は、バッテリーを常に昇順に消費できるように分類することから始まります。 周波数配列は、すべての撮影時間を 2 のべき乗のバケットに圧縮します。これは、マッチング ループ内の M への依存を取り除くため、非常に重要です。 

ポインタ i が逆方向にリセットされることはありません。 バッテリーが要件レベルに対して小さすぎると、その後のレベルでは役に立たないため、これは安全です。 各バッテリーは最大 1 回だけ考慮され、ソートされた配列全体の線形スキャンが保証されます。 

内側のループはバッテリーを消費するか、バッテリーを永久に破棄して、進行を保証します。

 ## 特殊なケース

 エッジケースの 1 つは、すべてのバッテリーが最小要件よりも小さい場合です。 この場合、ポインタ i は一致することなくすべての電池を進み、答えはゼロのままになります。 条件 a[i] < は前進のみをトリガーする必要があるため、アルゴリズムはすべての使用できないバッテリーを正しくスキップします。 

同一の要件値が多数ある場合には、別の特殊なケースが発生します。 頻度カウントを処理するため、各一致は正確に 1 単位のデマンドを消費し、バッテリーまたはデマンドが使い果たされるまでループが継続します。 同一の要件内の順序に依存しないため、病的な動作は発生しません。 

最後のエッジケースは、少数の非常に大きなバッテリーが多数の小さなバッテリーと並んで存在する場合です。 ソートにより、可能な限り小型バッテリーが最初に使用されるようになりますが、要件が増加すると、アルゴリズムは自然に大型バッテリーに移行します。 ポインターが逆方向に移動することはないため、大きな要件に備えて大きなバッテリーが自動的に保存されます。
