 ## 解決策
 ## 問題の理解

 原点を中心とした半径を持つ円形のホールが与えられます。$R$、 そして$n$その中に存在する人々。 各人物は平面内の点を占め、既存の人物のすべてのペアが少なくとも 2 単位離れていることが保証されます。 

既存のすべての人との距離が少なくとも 2 になるように、新しい人が立つことができる場所が円の内側または境界上に存在するかどうかを判断する必要があります。そのような点が存在する場合は、有効な点を出力する必要があります。 そうでない場合は、不可能であると出力します。 

幾何学的に、これは禁止領域を持つ円盤の実現可能性の問題です。既存のすべての人間は、自分の周囲に、立ち入ることを許可されていない半径 2 の閉じた円盤を定義します。 大きな円の内側で、これらの禁止された円盤のいずれにも覆われていない点を見つける必要があります。 

制約は大きく、最大で$10^5$したがって、すべての点のペアをチェックしたり、すべてのディスク間の単純な幾何学的交差テストを実行したりするソリューションは、すぐに遅すぎます。 候補位置の総当りチェックやペアごとの幾何学的構築には少なくとも 2 次時間が必要ですが、2 秒の制限の下では実行不可能です。 

有効な領域が大きな円の境界にのみ存在する場合、またはちょうど禁止されたディスク間の接線点にのみ存在する場合、微妙なエッジ ケースが発生します。 もう 1 つの注意が必要な状況は、境界上の他の場所に有効な点が存在するにもかかわらず、円の中心が無効である場合です。これは、単純な中心優先ヒューリスティックを破る可能性があります。 

## アプローチ

 直接的な強引なアイデアは、平面内のすべての点、または少なくとも禁止された円板と境界円の交点によって形成されるすべての意味のある候補を考慮することです。 自然な考えでは、有効な解は自由領域の中心か、制約の境界の交点、つまり円と円の交点 (禁止されたディスクと大きな円の間) またはペアごとのディスクの交点のいずれかに存在する必要があります。 これにより、すべての点のペアまたはすべての幾何学的交差イベントを考慮することになります。 

ただし、このような交点候補の数は$O(n^2)$なぜなら、どのペアの人々も一定数の交点を生成できるからです。 各候補者をすべての点に対してチェックしたとしても、これは次のようになります。$O(n^3)$、それは限界をはるかに超えています。 

重要な点は、すべての交点を考慮する必要はないということです。 代わりに、既存の各人物を制約を課すものとして扱います。つまり、その人物から距離 2 以内にいることはできません。 点が有効な場合、実現可能性の境界は外側の円に接触するか、少なくとも 1 つの禁止された円に接触する必要があります。 これは方向性を示唆しています。有効な解決策が存在する場合、1 つまたは 2 つの制約に関して「厳しい」候補点のより小さなセットをチェックするだけで十分です。 

標準的な削減は、ローカル ジオメトリから導出された慎重に選択された候補点の小さなセットをテストすることです。つまり、大きな円の中心と、各点について、原点からその点に向かう方向で、大きな円の境界に当たるか、ある点から正確に距離 2 に到達するまで外側に「押す」方向です。 実現可能な点が存在する場合、そのような方向ベースの候補の少なくとも 1 つがすべての制約を満たすことになります。 

これにより、問題はグローバルなペアワイズ ジオメトリから、ローカルな実現可能性チェックを伴う線形スキャンに軽減されます。

 ## アルゴリズムのチュートリアル

 禁止領域との最適な「最初の接触」はそのような方向に沿って表現できるため、原点であるか、原点から既存の点を通る光線上にある候補点を構築します。 

1. まず円の中心を確認します。$(0, 0)$。 すべてのポイントから少なくとも 2 単位離れていれば、すぐに有効な答えになります。 これは最も単純な実行可能な候補であり、不必要な作業を回避します。 
2. ポイントに存在する各人物について$p = (x, y)$、原点からへの方向ベクトルを計算します。$p$。 原点から始まり、向かって進む光線を考えると、$p$、次の影響を受ける実行可能な境界点$p$この方向に沿って、またはその近くになければなりません。 
3. 原点から向かって移動します。$p$2 つのイベントのいずれかが起こるまで: 大きな半径の円の境界に到達する$R$、またはちょうど距離 2 の点に到達します。$p$。 最初のイベントの制約は次のとおりです。$R$、2 つ目は、禁止されたディスクの外側に留まるようにします。$p$。 
4. この光線に沿って最も遠い有効な点を計算します。 これはスカラーを見つけることになります。$t$その点は$t \cdot \frac{p}{|p|}$両方を満たす$|t \cdot \frac{p}{|p|}| \le R$そして$|t \cdot \frac{p}{|p|} - p| \ge 2$。 これを 1D 制約として幾何学的に解決します。$t$。 
5. 境界からの制約は単純に次のとおりです。$t \le R$。 距離からの制約$p$の二次不等式になります$t$、禁止値の間隔を与えます。 実現可能な最大限のものを選択します$t$両方の制約の下で。 
6. このようにして得られた各候補点について、すべての点から少なくとも 2 単位離れているかどうかを確認します。 「はい」の場合は、すぐに出力します。 
7. 候補が機能しない場合は、有効な場所が存在しないことを出力します。 

### なぜ効果があるのか

 有効な解領域は、ディスク (ホール) とディスクの補体 (禁止ゾーン) の交差点です。 このような領域の境界は、常に外側の円または禁止された円の 1 つによって形成されます。 解決策が存在する場合、少なくとも 1 つの制約に対して「厳密」な、実行可能領域の境界上に点が存在します。 原点から各拘束中心に向かう光線を列挙することで、最初のブロック拘束が正しく識別される少なくとも 1 つの方向を確実に捕捉します。 これにより、実行可能な点が存在する場合、それがテストされた候補の中に表示されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import math

def dist2(x1, y1, x2, y2):
    return (x1 - x2) ** 2 + (y1 - y2) ** 2

n, R = input().split()
n = int(n)
R = float(R)

pts = []
for _ in range(n):
    x, y = map(float, input().split())
    pts.append((x, y))

def valid(x, y):
    if x * x + y * y > R * R + 1e-9:
        return False
    for px, py in pts:
        dx = x - px
        dy = y - py
        if dx * dx + dy * dy < 4.0 - 1e-9:
            return False
    return True

# check center
if valid(0.0, 0.0):
    print("Yes")
    print(0.0, 0.0)
    sys.exit(0)

# try candidates along each point direction
for px, py in pts:
    norm = math.hypot(px, py)
    if norm == 0:
        continue

    ux = px / norm
    uy = py / norm

    # binary search best t on [0, R]
    lo, hi = 0.0, R
    for _ in range(60):
        mid = (lo + hi) / 2
        x = ux * mid
        y = uy * mid
        ok = True
        for qx, qy in pts:
            dx = x - qx
            dy = y - qy
            if dx * dx + dy * dy < 4.0 - 1e-9:
                ok = False
                break
        if ok:
            lo = mid
        else:
            hi = mid

    x = ux * lo
    y = uy * lo
    if valid(x, y):
        print("Yes")
        print(x, y)
        sys.exit(0)

print("No")
```コードは、ヘルパー距離チェックを定義し、すべてのポイントを読み取ることから始まります。 の`valid`関数は、コアの実現可能性条件、つまり円の内側と半径 2 のすべての禁止されたディスクの外側をエンコードします。 

最初に原点をテストします。これは、原点がジオメトリに依存しない唯一の候補であり、ポイントがまばらな場合にパスすることが多いためです。 

各点について、原点から方向ベクトルを構築し、それを正規化します。 次に、半径パラメータに対する二分探索を使用して、この光線に沿って探索します。$t$。 述語は、候補点がすべての制約に対して有効であるかどうかをチェックします。 それが有効であれば、さらに外側に拡張しようとします。 それ以外の場合は、範囲を縮小します。 これにより、その方向に沿って実行可能な最も遠い点が確実に見つかります。 

最後に、最初に成功した候補を検証して出力します。 

実装の重要な点は、浮動小数点の安定性です。すべての比較では、境界有効点が誤って拒否される精度エラーを防ぐために、小さなイプシロン マージンが使用されます。

 ## 特殊なケース

 エッジケースの 1 つは、原点がすでに無効である場合です。 アルゴリズムは、これを直ちにスキップして方向候補に移動することでこれを処理します。 たとえば、点が中心の非常に近くに存在する場合、原点チェックは失敗し、解決策は光線ベースの候補に依存するため、時期尚早な拒否が発生しません。 

もう 1 つのケースは、すべての点が原点を中心とした完全な円上にある場合です。 その状況では、中心は無効になる可能性がありますが、禁止領域間に境界点が依然として存在する可能性があります。 光線探索では各角度方向が確実に探索され、バイナリ探索ではその方向の最大実現可能半径が見つかります。 

最後の微妙なケースは、正確な距離 2 に近い浮動小数点精度です。両方の比較方向でイプシロン調整を使用すると、正確に境界上の点が一貫して有効なものとして扱われることが保証され、丸め誤差による偽陰性が防止されます。
