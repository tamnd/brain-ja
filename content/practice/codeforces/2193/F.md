 ## 解決策
 ## 問題の理解

 宅配便の開始時間は$(Ax, Ay)$、すべての家を訪問し、最終的に到達する必要があります$(Bx, By)$。 

移動ルールが異常です。 彼は 1 ユニットを右に、1 ユニットを上に、または 1 ユニットを下に移動できます。 彼は決して自分の利益を減らすことはできない$x$-座標。 

この 1 つの制限によって、ルートのグローバル構造が完全に決まります。 家がもっと小さい場合$x$-他の家よりも調整されている場合は、遅くとも他の家を訪問する必要があります。 ある程度過ぎたら$x$、返品不可。 

2点の場合$x_1 \le x_2$、それらの間の最短の移動時間は$$(x_2-x_1)+|y_2-y_1|.$$右に移動することが唯一の増加方法であるため、水平部分は避けられません$x$。 

の合計$n$すべてのテストケース全体で最大でも$2 \cdot 10^5$。 配達注文の順列を考慮しようとする解決策は絶望的です。 平$O(n^2)$大雑把に実行するだろう$4 \cdot 10^{10}$最悪の場合の運用。 に近いものが必要です$O(n \log n)$または$O(n)$テストセットごとに。 

主な問題は、家が同じものを共有していることにあります$x$-座標。 水平方向の動きは固定されているため、最適化問題全体は、左から右にスイープしながら垂直方向にどのように移動するかを選択することになります。 

同時に 3 つの家を考える$x$:```
x = 10
y = 2, 5, 9
```このコラムを終了したら、$y=5$決して役に立ちません。 両極端を訪れるには$2$そして$9$、区間全体を横断する必要があります。 最適なルートはいずれかの極端なところで終了します。 任意の終了位置を維持する DP はステートを無駄にし、重要な構造を見逃すことになります。 

もう一つの簡単な間違いは、家を独立して扱うことです。 例えば：```
Ax=0 Ay=5
houses: (3,1), (3,10)
Bx=6 By=5
```両方の家が同じ列にあります。 最適なルートはこの間隔をカバーする必要があります$[1,10]$。 2 つの家を別々に見ると、その間隔の 1 回の掃除中にそれらを修理できるという事実が失われます。 

## アプローチ

 強引な観点は、すべての家をノードとして考え、最適な訪問順序を探索することです。 順序には大きな制約があるため、$x$決して減少することはありませんが、それでも可能性の数は膨大なままです。 と$n=2\cdot10^5$、サブセットまたは任意の順序に依存する状態は完全に実行不可能です。 

重要な観察は、異なるものの相対的な順序だけが重要であるということです。$x$-コーディネートが重要です。 同じものを持つ家$x$列を形成します。 柱に到着したら、右に進む前に、その柱にあるすべての家を整備する必要があります。 柱内での垂直方向の移動は制限されていないため、重要な情報は最も低いハウスと最も高いハウスだけです。 

させて$$l = \min y,\qquad h = \max y$$コラム用に。 

その列内のすべての家にサービスを提供するには、間隔全体をカバーする必要があります$[l,h]$。 そうすることで、最適なルートは次のいずれかで終了します。$l$またはで$h$。 覚えておく価値のある州はこれらだけです。 

これにより、問題は古典的な区間 DP に変わります。 それぞれが異なる$x$-座標は 1 つの間隔に寄与します$[l,h]$。 列を左から右に処理し、現在の列を下端または上端で仕上げる際の垂直コストを最小限に抑えます。 

水平距離はさらに単純です。 ルートを問わず、$$Bx-Ax$$右移動の単位は必須です。 最小垂直コストを計算し、この定数を最後に追加できます。

 ## アルゴリズムのチュートリアル

 ### 柱の構築

 それぞれの特徴について$x$、次を計算します。$$l_x = \min y, \qquad h_x = \max y.$$列を昇順に並べ替えます$x$。 

2 つの人工列を追加します。 

開始位置は次の列になります。$$l=h=Ay.$$終了位置は次の列になります。$$l=h=By.$$### DP 状態

 しましょう:$$dp[i][0]$$柱を終えた後の最小垂直距離であること$i$そしてその下端点に立っている。 

させて：$$dp[i][1]$$柱を終えた後の最小垂直距離であること$i$そしてその上部の終点に立っている。 

### トランジション

 列を仮定します$i$間隔がある$[l_i,h_i]$。 

に終了するには$l_i$、最終的には到達しなければなりません$h_i$そして下にスイープして戻ります。 インターバルの長さ$$h_i-l_i$$常に支払われます。 

エンドポイントから来た場合$y$前のコラムのコストは$$|y-h_i| + (h_i-l_i).$$したがって、$$dp[i][0] = \min \begin{cases} dp[i-1][0] + |l_{i-1}-h_i| + (h_i-l_i)\\ dp[i-1][1] + |h_{i-1}-h_i| + (h_i-l_i) \end{cases}$$同様に、終了するには$h_i$、最初に接続します$l_i$そして上向きにスイープします。$$dp[i][1] = \min \begin{cases} dp[i-1][0] + |l_{i-1}-l_i| + (h_i-l_i)\\ dp[i-1][1] + |h_{i-1}-l_i| + (h_i-l_i) \end{cases}$$### 最終的な答え

 人工終了列を処理した後の答えは次のとおりです。$$(Bx-Ax) + \min(dp[last][0],dp[last][1]).$$エンディング欄には、$l=h=By$したがって、どちらの状態も必要な目的地に到達していることを表します。 

### なぜ効果があるのか

 固定柱の場合、すべての家がその中にあります$[l,h]$。 すべての家を訪問するには、間隔全体をカバーする必要があります。 間隔がカバーされると、内側の地点で終了するルートは、代わりに端のいずれかで停止することで短縮できます。 したがって、下限と上限のエンドポイントは、すべての最適な部分解の完全な記述を形成します。 

DP は、前の列の考えられるすべての最適なエンドポイントと現在の列のすべての最適なエンドポイントを考慮します。 列は唯一実行可能な左から右の順序で処理されるため、すべての有効な配信ルートは 1 つの DP 遷移シーケンスに正確に対応し、すべての DP 遷移は有効なルートに対応します。 DP によって検出された最小値は、まさに達成可能な最小垂直距離です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n, Ax, Ay, Bx, By = map(int, input().split())

        xs = list(map(int, input().split()))
        ys = list(map(int, input().split()))

        cols = {}

        for x, y in zip(xs, ys):
            if x not in cols:
                cols[x] = [y, y]
            else:
                cols[x][0] = min(cols[x][0], y)
                cols[x][1] = max(cols[x][1], y)

        intervals = [(Ax, Ay, Ay)]

        for x in sorted(cols):
            l, h = cols[x]
            intervals.append((x, l, h))

        intervals.append((Bx, By, By))

        m = len(intervals)

        dp0 = 0
        dp1 = 0

        prev_l = Ay
        prev_h = Ay

        for i in range(1, m):
            _, l, h = intervals[i]

            ndp0 = min(
                dp0 + abs(prev_l - h),
                dp1 + abs(prev_h - h)
            ) + (h - l)

            ndp1 = min(
                dp0 + abs(prev_l - l),
                dp1 + abs(prev_h - l)
            ) + (h - l)

            dp0, dp1 = ndp0, ndp1
            prev_l, prev_h = l, h

        ans = (Bx - Ax) + min(dp0, dp1)
        print(ans)

solve()
```辞書は家を均等にグループ化します$x$- 最小値と最大値のみを調整して保存します$y$。 すべての内部の家は、間隔全体をカバーすると自動的に訪問されるため、無関係になります。 

DP は、完全なテーブルではなく、ローリング変数を使用して実装されます。 各遷移は前の列にのみ依存するため、すべての行を保存する必要はありません。 

微妙なディテールは人工的な終了列です$(Bx, By)$。 それがなければ、すべての住宅をメンテナンスするコストは計算されますが、家に到達するまでのコストは計算されません。 宛先を長さ 0 のもう 1 つの間隔として扱うと、遷移が均一になります。 

すべての計算は 64 ビット整数に快適に収まります。 座標到達$10^9$、合計の経路長は最大でもその数倍です。

 ## 特殊なケース

 次のことを考慮してください。```
1
3 1 5 4 5
2 2 2
1 5 10
```すべての家は同じものを共有します$x$。 間隔は$[1,10]$。 このアルゴリズムは、列全体をこれら 2 つの極端な値に圧縮します。 DP は、インターバルを 1 回カバーするコストを正確に支払います。 特別な処理は必要ありません。 

考慮する：```
1
1 1 3 5 3
3
10
```目的地は同じです$y$スタートとして。 よくあるバグは、最後の家から家に戻る最後の動きを忘れることです。 人工終了列は、DP にそのコストを自動的に含めることを強制します。 

考慮する：```
1
4 1 4 6 4
3 3 3 4
2 8 5 4
```3つの家が同時に現れます$x$。 アルゴリズムはのみを保存します$[2,8]$。 真ん中の家は、$y=5$すべてのルートが対象となるため、無関係です$[2,8]$必然的にそこを通過します。 これがまさに、間隔圧縮が正しい理由です。
