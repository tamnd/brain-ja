 ## 解決策
 ## 問題の理解

 整数の配列と固定増分値が与えられます。 1 回の操作で、配列内の任意の位置を選択し、その 1 つの要素を毎回まったく同じ量ずつ増やすことができます。 この操作は、任意のインデックスに対して何度でも繰り返すことができます。 問題は、その合計が目標値と正確に等しくなるように配列を変換できるかどうかです。 

重要な点は、要素を再配置したり、値を減算したりしないことです。 各操作は同じ値を加算するため、すべての操作は厳密に固定ステップ サイズで合計を増加させます。$x$正確に 1 つの要素に。 したがって、合計は非常に制御された算術的な方法で展開されます。 

制約は小さいです。$n \le 10$、$x \le 10$、 そして$s \le 100$。 これにより、パフォーマンスの複雑さに関する懸念がすぐに解消されます。 状態を強引に探索することさえ原理的には実現可能ですが、問題の構造は、直接の算術条件が到達可能性を完全に特徴付けることを示唆しています。 

現在の合計がすでに目標を超えている場合、微妙なケースが発生します。 すべての操作は合計を増やすだけなので、そのようなケースは直ちに不可能になります。 もう 1 つのエッジ状況は、目標合計と現在の合計の差がサイズの増分と互換性がない場合です。$x$。 たとえば、差が次で割り切れない場合、$x$、どのような一連の操作もターゲットに正確に到達することはできません。 

## アプローチ

 この問題を考える強引な方法は、操作をシミュレートすることです。 最初の配列から始めて、可能なすべてのインデックスの増分を繰り返し試行し、到達可能なすべての合計を追跡します。 各移動が合計を正確に増加させるため、$x$、これはすぐに不要になります。重要な状態は値の分布ではなく、現在の合計だけです。 

重要な観察は、各操作で合計が正確に変化することです。$x$、どのインデックスが選択されたかに関係なく。 これにより、問題全体が単一変数の到達可能性条件に分解されます。 最初の合計が$S_0$、その後$k$演算すると合計は次のようになります$S_0 + kx$。 問題は、負でない整数が存在するかどうかを確認することになります。$k$次のような:$$S_0 + kx = s$$これは次のことを確認するのと同じです$s \ge S_0$そして$s - S_0$で割り切れます$x$。 

アレイのそれ以上の構造は重要ではありません。

 ## アルゴリズムのチュートリアル

 1. 配列の初期合計を計算します。 これは、演算前の合計の可能な最小値を表します。 
2. この合計を目標値と比較します$s$。 初期合計が既に次の値を超えている場合$s$, どのような操作を行ってもそれを減らすことはできないため、答えは即座に「NO」です。 
3. 差を計算します$d = s - S_0$。 これは目標を達成するために必要な増加額の合計です。 
4. かどうかを確認します。$d$で割り切れます$x$。 各操作が正確に貢献します$x$、したがって、の倍数のみ$x$到達可能です。 
5. 両方の条件が成立する場合は「YES」を出力し、そうでない場合は「NO」を出力します。 

### なぜ効果があるのか

 合計は、適用される場所ではなく、実行される操作の数によって完全に決まります。 各操作は正確に加算します$x$グローバル合計に変換されるため、到達可能な合計はステップ サイズの初期合計から始まる等差数列を形成します。$x$。 インデックス選択のシーケンスがこの構造を壊すことはできないため、次のように割り切れます。$x$必要かつ十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, s, x = map(int, input().split())
        a = list(map(int, input().split()))
        
        total = sum(a)
        
        if total > s:
            print("NO")
            continue
        
        diff = s - total
        
        if diff % x == 0:
            print("YES")
        else:
            print("NO")

if __name__ == "__main__":
    solve()
```実装は派生条件に直接に従います。 最初の重要なステップは、テスト ケースごとに合計を 1 回計算することです。 これは制約の下では安全です。$n \le 10$。 合計が超過した場合の早期終了$s$正確性のためには必要ありませんが、不必要な算術チェックを回避します。 

割り算チェックは、すべての演算で合計が一定の増分で変化するという事実を捉えます。 どのインデックスが選択されるかをシミュレーションする必要はありません。

import sys, io

def run(inp: str) -> str:

 ## 特殊なケース

 初期合計がすでに目標を超えている場合、アルゴリズムはすぐに「いいえ」を返します。 たとえば、配列が次の場合、`[5, 5]`、$x = 1$、 そして$s = 9$、合計は 10 で、すでに 9 より大きくなっています。すべての操作は値を増やすだけであるため、値を下げるシーケンスはなく、初期のチェックで正しく拒否されます。 

差が割り切れないとき$x$、アルゴリズムは不可能な遷移を正しくブロックします。 たとえば、配列の場合`[1, 1, 1, 1]`、$x = 2$、 そして$s = 7$、最初の合計は 4 です。差は 3 で、すべての演算で合計が 2 ずつ変化するため、演算を組み合わせても正確に 7 に達することはありません。
