 ## 解決策
 ## 問題の理解

 同じ長さの 2 つの配列から始めます。 

どの位置でも、直接上書きできます。`a[i]`と`b[i]`。 置換することで値を右から左にコピーすることもできます。`a[i]`現在の値で`a[i+1]`。 

各クエリは部分配列の可能な最大の合計を要求します。`a[l..r]`これらの操作を任意の回数実行した後。 

重要な点は、すべてのクエリが独立しているということです。 別のクエリに答えるときに、あるクエリに対して行われた変更を保持する必要はありません。 

この制約により、各クエリの操作をシミュレートするアプローチは即座に除外されます。 すべてのテスト ケースにわたって、配列の合計サイズとクエリの合計数の両方が次の値に達する可能性があります。`2 * 10^5`。 アン`O(nq)`解決策には約必要になる可能性があります`4 * 10^10`これは 2 秒の制限をはるかに超えています。 各クエリに一定時間または対数時間で応答できるようにする前処理が必要です。 

問題の最も微妙な部分は、最終的にどのような値がその位置に現れるかを理解することです。 

考慮する：```
a = [3, 2, 1]
b = [1, 2, 3]
```ポジション 1 は最終的に次のようになります。`3`。 位置 3 を次のように設定します。`b[3]=3`、それを位置 2 にコピーし、次に位置 2 を位置 1 にコピーします。 

よくある間違いは、その立場を考えることです`i`どちらかしか選べない`a[i]`そして`b[i]`。 ここで、位置 1 は位置 3 から始まる値に到達します。 

もう 1 つの簡単な間違いは、位置の最適値を想定することです。`i`は厳密にその右側にある最大の要素です。 

考慮する：```
a = [10]
b = [1]
```正しい隣人はまったく存在しません。 位置 1 の正しい最大値はそのままです。`10`単に変更しないままにしておくだけでよいからです。 

3 番目の罠は、コピーされた値自体が次を使用して作成された可能性があることを見落としていることです。`b`。 

考慮する：```
a = [1, 1]
b = [1, 100]
```位置 1 は次のようになります。`100`最初に位置 2 を次のように設定することで、`100`そして左にコピーします。 元の配列のみに基づいた推論`a`この可能性を見逃しています。 

## アプローチ

 ブルート フォース ビューでは、各クエリに個別に応答します。 最適な操作シーケンスを決定し、要求されたセグメントで達成可能な最大合計を計算することもできます。 

操作が単純でローカルであるため、これは概念的に機能します。 問題は、可能な状態の空間を記述するだけでも膨大な量になることです。 まで`2 * 10^5`ポジションと`2 * 10^5`クエリ、クエリごとのシミュレーションは絶望的に遅いです。 

画期的な発見は、単一のポジションを研究することから始まります。 

インデックスを取得します`i`。 コピー操作を行うたびに、情報は右から左に移動します。 そのため、最終的に位置に表示される値はすべて`i`何らかの立場から生じたものでなければならない`j ≥ i`。 

位置で`j`、利用できる最大値は次のとおりです。```
max(a[j], b[j])
```維持することもできるので`a[j]`または上書きします`b[j]`。 

定義する：```
t[j] = max(a[j], b[j])
```次に、これまでに到達できる最大値`i`は：```
s[i] = max(t[j]) for all j ≥ i
```これは単に接尾辞の最大値です。 

位置に最終値がありません`i`超えることができる`s[i]`、到達可能なソースはすべて、 で始まるサフィックスにあるためです。`i`。 

さらに良いことに、アレイ全体`s`実際に達成可能です。 もし`t[i] = s[i]`、その値を位置に直接配置します`i`。 さもないと`s[i] = s[i+1]`, したがって、右からコピーします。 

これは、すべてのポジションについて次のことを意味します。```
best possible value at i = s[i]
```したがって、任意のクエリ間隔で可能な最大合計は、単に次の合計になります。`s[l..r]`。 

接尾辞の最大値配列を一度計算した後、接頭辞の合計を構築し、すべてのクエリに答えます。`O(1)`時間。

 | 最適 | テスト ケースごとに O(n + q) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ポジションごとに`i`、計算する```
t[i] = max(a[i], b[i])
```これはその位置の最大値です`i`それ自体がソースとして貢献できます。 
2. サフィックス最大配列を構築する`s`。```
s[n] = t[n]
s[i] = max(t[i], s[i+1])
```

`s[i]`これまでに到達可能な位置の最大値を表します`i`。 
3. プレフィックスの合計を構築します。`s`。```
pref[0] = 0
pref[i] = pref[i-1] + s[i]
```4. お問い合わせの場合`(l, r)`、 戻る```
pref[r] - pref[l-1]
```なぜなら、実現可能な最適な配列は正確に`s`。 

### なぜ効果があるのか

 位置に到達するすべての値`i`何らかの立場から生じたものでなければならない`j ≥ i`, すべてのコピーは左方向に移動するためです。 位置で利用可能な最大のソース値`j`は`max(a[j], b[j])`。 したがって、位置に最終値はありません`i`接尾語全体でこれらの数量の最大値を超える可能性があります。`s[i]`。 

これにより、すべての位置に上限が与えられます。 

配列`s`それ自体は達成可能です。 いつでも`t[i] = s[i]`、その値を位置に直接作成します`i`。 それ以外の場合、サフィックスの最大値は右のどこかから来ます。つまり、`s[i] = s[i+1]`、位置からコピーすることでそれを取得します`i+1`。 

各位置は同時にその上限に達する可能性があるため、最適な最終配列は正確に次のようになります。`s`、すべてのクエリの回答は、次の対応する間隔の合計です。`s`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n, q = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        s = [0] * n

        cur = 0
        for i in range(n - 1, -1, -1):
            cur = max(cur, a[i], b[i])
            s[i] = cur

        pref = [0] * (n + 1)
        for i in range(n):
            pref[i + 1] = pref[i] + s[i]

        ans = []
        for _ in range(q):
            l, r = map(int, input().split())
            ans.append(str(pref[r] - pref[l - 1]))

        out.append(" ".join(ans))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```最初のループは接尾辞の最大値を直接計算します。 変数`cur`右から左にスキャンしながら、これまでに確認された最大値を保存します。 以来`cur`常にすべての最大値に等しい`max(a[j], b[j])`処理されたサフィックスに代入する`s[i] = cur`証明で説明されている配列を正確に生成します。 

prefix-sum 配列では、1 から始まるインデックスが使用されます。 これにより、次のような場合の特別な処理が回避されます。`l = 1`、すべての間隔の合計が標準式になるため、次のようになります。```
pref[r] - pref[l - 1]
```すべての値は Python 整数に快適に収まります。 考えられる最大のクエリ合計はおおよそ次のとおりです。`2 * 10^5 * 10^4 = 2 * 10^9`、これでも 64 ビットの範囲内に十分収まります。

 ## 特殊なケース

 次のことを考慮してください。```
1
2 1
1 1
1 100
1 2
```我々は持っています`t = [1, 100]`したがって、接尾辞の maxima 配列は次のようになります。```
s = [100, 100]
```答えは`200`。 

見るだけの解決策`a`生み出すだろう`2`、位置 2 が最初に次になる可能性があるため、これは不正確です。`100`そして左に伝播します。 

ここで次のことを考えてみましょう。```
1
1 1
10
1
1 1
```正しい隣人は存在しません。 サフィックスの最大配列は次のとおりです。```
s = [10]
```答えは`10`。 

すべての値がコピーから取得される必要があると仮定するソリューションでは、単純に残す可能性が失われます。`a[1]`変わらない。 

最後に、次のことを考慮してください。```
1
3 1
3 2 1
1 2 3
1 3
```接尾辞の maxima 配列は次のようになります。```
s = [3, 3, 3]
```答えは`9`。 

これは中心の不変条件を裏付けています。つまり、すべての位置はそのサフィックスの達成可能なソース値の最大値によって制限されており、その制限は常に達成可能です。
