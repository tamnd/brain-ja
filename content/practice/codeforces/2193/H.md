 ## 解決策
 ## 問題の理解

 ツリーが与えられます。これは、次のように接続された非巡回グラフです。$n$頂点があり、各頂点には関連する整数値があります。 繰り返し実行できる操作は、残りの近傍の値の合計がその頂点自体の値とパリティが異なる場合に頂点を削除することです。 つまり、近傍の合計が奇数で頂点が偶数の場合、またはその逆の場合、それを削除できます。 削除されると、頂点とそのすべてのエッジが消え、隣接する頂点の合計が変化する可能性があります。 タスクは、このルールに従ってすべての頂点を順番に削除できるかどうかを判断し、可能であれば、有効な削除シーケンスを出力することです。 

制約は厳しいです:$n$まで可能です$2 \cdot 10^5$まであります$10^4$テストケース。 すべての頂点を繰り返しスキャンして削除可能な候補を見つける単純なシミュレーションでは、$O(n^2)$最悪の場合、上限に対して遅すぎる場合があります。 すべてのテスト ケースにわたる頂点の総数が線形に近いソリューションが必要です。 

キー エッジ ケースは、隣接する頂点がすべてそれ自体と同じパリティ合計を持つ頂点です。 木が小さい場合はこう言います$n = 3$値が [2, 1, 4] で、エッジがそれらを直線的に接続している場合、開始時にパリティ条件を満たす頂点がない可能性があります。 どのツリーも削除可能であると仮定する不用意なアプローチでは、誤って YES が出力されます。 もう 1 つの注意が必要なケースは、葉の多いツリーで発生します。葉を削除すると隣接する合計が変更され、以前にブロックされていた頂点を削除できるようになります。 アルゴリズムでは、動的に更新される近傍合計を注意深く考慮する必要があります。 

## アプローチ

 ブルートフォース手法は簡単です。各ステップですべての頂点をスキャンし、現在の隣接頂点の値の合計を計算し、合計のパリティが異なる頂点を削除します。 すべての頂点が削除されるか、そのような頂点が存在しなくなるまで繰り返します。 これは概念的には正しいですが、非常に非効率的です。 のために$n$頂点、各スキャンにかかる可能性がある$O(n)$、最悪の場合は実行します。$n$削除の結果、$O(n^2)$テストケースごとの操作。 大きなツリーの場合はタイムアウトになります。 

最適化するための重要な洞察は、パリティを尊重しながら深さ優先の方法でツリーを処理することです。 リーフが削除されると、その値はその親の近傍合計に影響を及ぼし、削除条件を満たす可能性があります。 ツリーを任意にルート化し、DFS を実行することで、ローカルでパリティ条件を確認しながら、事後探索で頂点を削除できます。 ポストオーダートラバーサルでは、頂点のすべての子が頂点自体の前に考慮されるようになり、毎回明示的に合計を再計算することなく、近傍合計の動的な更新を効果的にシミュレートします。 これにより複雑さが軽減され、$O(n)$テストケースごとに。 

ポストオーダー DFS が機能するのは、頂点のパリティが現在の隣接頂点の合計にのみ依存するためです。 最初に子を処理すると、除去効果が上向きに伝播することが保証されます。 すべてのサブツリーを処理した後でルート自体を削除できない場合、ツリーを完全に削除することはできません。

 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | DFS / ポストオーダー貪欲 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 頂点数を読み取る$n$および頂点値の配列$a$。 ツリーを表す隣接リストを作成します。 
2. 任意の頂点をルートとして選択します。 便利な選択は頂点 1 です。 
3. 現在の頂点の子を再帰的に処理する DFS 関数を定義します。 子ごとに、まずその子に対して DFS を呼び出します。 
4. すべての子が処理された後、現在の頂点のパリティとまだ削除されていない現在の隣接頂点の合計をチェックします。 パリティが異なる場合は、この頂点を削除可能としてマークし、削除シーケンスに追加します。 
5. ルートから到達可能なすべての頂点にアクセスするまで DFS を続行します。 いずれかの時点でサブツリー内の頂点を削除できない場合はバックトラックし、最終的にルートを削除できない場合は NO を宣言します。 
6. DFS 後、削除シーケンスにすべてのものが含まれている場合、$n$頂点の場合は、YES とシーケンスを出力します。 それ以外の場合は NO を出力します。 

機能する理由: 事後処理により、各頂点がその子の後に考慮され、隣接する合計が除去条件に正確に反映されるようになります。 リーフ頂点またはパリティが満たされた頂点は削除でき、削除の効果は親に伝播します。 不変条件は、各ステップで、頂点がシーケンス内にある場合、その時点でパリティ条件を満たすということです。 すべての削除が有効であり、最終的にはすべての頂点が考慮されるため、アルゴリズムは可能な場合には正しいシーケンスを生成します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(1 << 20)

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        adj = [[] for _ in range(n)]
        for _ in range(n - 1):
            u, v = map(int, input().split())
            u -= 1
            v -= 1
            adj[u].append(v)
            adj[v].append(u)
        
        removed = [False] * n
        result = []
        
        def dfs(v, parent):
            for u in adj[v]:
                if u == parent:
                    continue
                dfs(u, v)
            S_v = sum(a[u] for u in adj[v] if not removed[u])
            if (S_v % 2) != (a[v] % 2):
                removed[v] = True
                result.append(v + 1)
        
        dfs(0, -1)
        if len(result) == n:
            print("YES")
            print(" ".join(map(str, result)))
        else:
            print("NO")

if __name__ == "__main__":
    solve()
```隣接リストはツリーを効率的に表します。 ブール配列を使用します`removed`to track which vertices are already taken out. The DFS is post-order, so we first recursively remove children, then the current vertex if its neighbor sum parity allows. の`result`配列はシーケンスをキャプチャします。 慎重にインデックスを作成すると、頂点の出力が 1 から始まることが保証されます。 再帰制限を高く設定すると、深いツリーのスタック オーバーフローが防止されます。
