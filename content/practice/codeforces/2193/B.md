 ## 解決策
 ## 問題の理解

 1 から n までの数値の順列が与えられています。これは、この範囲内のすべての数値が 1 回だけ出現することを意味します。 この順列の単一の連続セグメントを選択し、それを逆にすることができます。 私たちの目標は、そのような反転を 1 回だけ実行して、辞書編集上可能な最大の順列を生成することです。 辞書編集的な比較は辞書の順序と同じように機能します。2 つのシーケンスが異なる最初のインデックスでは、番号の大きいシーケンスがより大きいと見なされます。 

入力として、複数のテスト ケースを受け取ります。 各テスト ケースから、順列の長さと順列自体がわかります。 各テスト ケースの出力は、辞書編集順でシーケンスを最大化する 1 つの最適なセグメント反転の結果として得られる順列です。 

制約により、n は最大 200,000 まで可能であり、すべてのテスト ケースにわたる n の合計も 200,000 であることがわかります。 二次関数は時間制限を超えるため、テスト ケースあたりの解は O(n) または O(n log n) に制限されます。 エッジ ケースには、長さが 1 または 2 の非常に小さい順列、すでに降順に並べ替えられている順列、および最大の数値が末尾にある順列が含まれます。 不注意なアプローチでは、最初の減少セグメントまたは最大値を含む最初のセグメントを反転するだけかもしれませんが、最適な反転にセグメントを最後まで伸ばすか、より小さい数値をスキップする必要がある場合、これは失敗する可能性があります。 

たとえば、与えられた`[3,2,1,4]`、素朴なアプローチは逆転するかもしれません`[3,2,1]`に`[1,2,3,4]`、辞書編集的には逆引きよりも小さくなります。`[3,2,1,4]`に`[4,1,2,3]`。 

## アプローチ

 強引なアプローチは、可能なすべてのインデックスのペア (l、r) を反転して試し、そのセグメントを反転し、その結果を辞書編集的に比較することです。 このようなセグメントは O(n^2) 個あり、各反転ではシーケンスをチェックするのに O(n) のコストがかかるため、総当たりアプローチは O(n^3) になります。 n が 2×10^5 までの場合、これは完全に不可能です。 

重要な点は、辞書編集上の最大順列は常に、前に移動できる最大の数から始まるということです。 セグメントを反転すると、任意の要素を最初の位置に移動できます。そのような移動の中で最適なのは、後続の数字をできるだけ大きく保つために必要なだけ要素を反転しながら、最大の数字を最初の位置に移動することです。 

具体的には、まず順列の最大要素を見つけます。 次に、配列の先頭からその最大要素のインデックスまでのセグメントを反転します。 これにより、最大の要素が先頭に配置され、シーケンスの残りの部分は、後で小さな数値が大きな数値を不必要にブロックしないようにする順序に従います。 これが機能するのは、最初の位置が辞書編集上の比較に優先するため、そこに最大の数値を配置することが常に最適であるためです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^3) | O(n) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、n と順列 p を読み取ります。 
2. p の最大要素の位置を特定します。 これをインデックスにしましょう`i_max`。 
3. 順列の開始から終了までのセグメントを反転します。`i_max`包括的な。 
4. 変更された順列を出力します。 

これが機能する理由は、最初の要素が辞書順で最も重要であるためです。 最大の要素を最初の位置に配置すると、可能な最大のプレフィックスが保証されます。 最大要素を超えて反転するか、最初に小さい要素を選択すると、最初の有効な値が減少するだけなので、より小さな辞書順列が生成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        p = list(map(int, input().split()))
        i_max = p.index(max(p))
        # Reverse from start to the max element's index
        p[:i_max+1] = reversed(p[:i_max+1])
        print(' '.join(map(str, p)))

if __name__ == "__main__":
    solve()
```このソリューションは、次を使用してすべての入力を効率的に読み取ります。`sys.stdin.readline`スピードのために。 Python を使用して最大値を見つけます。`max`そして`index`、O(n)です。 スライスの反転はその場で行われ、スペースを一定に保ちます。 Off-by-one エラーは、Python でのスライスは最後に排他的であることを覚えておくことで回避できます。`p[:i_max+1]`の要素が正しく含まれています`i_max`。 

## 実用的な例

 入力用`[3,2,1,4]`、`max(p)=4`インデックス 3 で。反転`[3,2,1,4]`先頭からインデックス 3 まで`[4,1,2,3]`、これは辞書編集上最大の順列です。 

| ステップ | p |
 | --- | --- |
 | オリジナル | [3,2,1,4] |
 | 逆転 0-3 | [4,1,2,3] |

 入力用`[3,1,2]`、`max(p)=3`インデックス 0 で。反転`[3]`葉`[3,1,2]`変わらない。 

| ステップ | p |
 | --- | --- |
 | オリジナル | [3,1,2] |
 | 逆転 0-0 | [3,1,2] |

 これらのトレースは、アルゴリズムが最大値がすでに前面にあることを正確に識別し、それ以外の場合は最大値を前面に押し出すことを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |

| スペース | O(1) おまけ | スライスのその場での反転。 入力配列が再利用される |

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = io.StringIO()
    sys.stdout = output
    solve()
    sys.stdout = sys.__stdout__
    return output.getvalue().strip()

# Provided samples

 ## 特殊なケース

 順列の長さが 1 の場合、次のようになります。`[1]`、セグメントを反転します`[0,0]`何もせずに正しく出力します`[1]`。 最大値がすでに最初の位置にある順列の場合、次のようになります。`[4,3,2,1]`、アルゴリズムは認識します`i_max=0`そして長さ 1 のセグメントを反転し、配列は変更されないままになります。 どちらのシナリオでも、アルゴリズムは不必要な逆転を実行せず、正確さを維持します。 次のような順列の場合`[2,1]`、アルゴリズムは次のように識別します`2`インデックス 0 の最大値として、反転は行わず、出力します。`[2,1]`正しく。
