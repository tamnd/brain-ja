 ## アルゴリズムのチュートリアル

 1.剣の強さを降順に並べ替えます。 これにより、しきい値の選択を解釈できるようになります$x$このソートされたリストのプレフィックスを選択する場合と同様です。 プレフィックスの長さは、使用可能な剣の数を直接示します。 
2. モンスター要件のプレフィックスの合計を計算します。$b_i$。 これにより、指定された数の剣で何レベルを完了できるかをすぐに判断できます。 
3. 考えられるプレフィックス長ごとに$k$(つまり、上部を使用します$k$最強の剣)、それに関連付けられた最適なしきい値を決定します。 自然な選択は、その接頭辞の中で最小の剣です。なぜなら、それが最大値だからです。$x$それはまだすべてを含みます$k$剣。 
4. それぞれについて$k$、完了できるレベルの数を計算します。 これが最大のインデックスです$i$prefix_sum[i] ≤ k となるようにします。 これは二分探索で見つけることができます。 
5. 候補者のスコアを次のように計算します。$x \cdot \text{levels}$、全体にわたって最大値を追跡します$k$。 

これが機能する理由は、最適なしきい値が剣を含めるか除外した場合にのみ変化するためです。 連続する 2 つの異なる剣の強さの間では、使用できる剣のセットは変化しないため、$x$は不要です。 

### なぜ効果があるのか

 固定しきい値の場合$x$、使用可能な剣のセットはまさに$a_i \ge x$。 同じ使用可能なセットを生成するすべてのしきい値の中で、増加する$x$実現可能性を変えることなくスコアを向上させます。 したがって、最適な選択は、$x$常にある程度の剣の強さに等しい。 これにより、検索空間が連続値から最大まで縮小されます。$n$各候補は、ソートされた強みのプレフィックスによって完全に特徴付けられます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from bisect import bisect_right

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        
        a.sort(reverse=True)
        
        pref = [0] * (n + 1)
        for i in range(n):
            pref[i + 1] = pref[i] + b[i]
        
        # precompute max level for k swords via binary search on prefix sums
        best = 0
        
        for k in range(1, n + 1):
            x = a[k - 1]
            # max levels with k swords
            levels = bisect_right(pref, k) - 1
            best = max(best, x * levels)
        
        print(best)

if __name__ == "__main__":
    solve()
```このソリューションでは、まず剣の強さを並べ替えて、すべての接頭辞が、あるしきい値の下で使用可能な剣の有効な選択肢に対応するようにします。 プレフィックスの合計は$b_i$「利用可能な剣の数」から「クリアできるレベルの数」に高速に変換できます。 

二分探索のステップは微妙です。`bisect_right(pref, k) - 1`合計要件が超えないレベルの最大数を返します。$k$。 これにより、レベルごとの消費のシミュレーションが回避されます。 

よくある間違いは、プレフィックス インデックスの意味を逆にすることです。プレフィックス合計配列の先頭には 0 が含まれるため、レベル カウントは慎重にオフセットする必要があります。 もう 1 つの間違いは、各テスト ケースで独立したプレフィックスの再計算が必要であることを忘れていることです。
