 ## 解決策
 ## 問題の理解

 この問題では、固定の攻撃力と体力を持つヒーローが、それぞれ独自の攻撃力と体力を持つ一連のモンスターと対峙することになります。 戦闘はターンレスですが同時に行われます。ヒーローがモンスターを攻撃すると、モンスターもその攻撃ダメージをヒーローに返します。 モンスターは体力がゼロ以下になると敗北し、ヒーローは体力がゼロ以下になると敗北します。 目標は、たとえ途中で死んでも、生き残るモンスターがいない限り、主人公がすべてのモンスターを殺すことができるかどうかを判断することです。 

入力は複数のテスト ケースで構成されます。 各テスト ケースには、ヒーローの攻撃、ヒーローの健康、モンスターの数、モンスターの攻撃のリスト、およびモンスターの健康のリストが含まれます。 出力は、テスト ケースごとに単純な YES または NO です。 

この制約により、すべてのテスト ケースで最大 10^5 のモンスターが許可され、モンスターの体力と攻撃力は最大 10^6 になります。 モンスターが死ぬまで攻撃ごとに体力を繰り返し減算する単純なシミュレーションでは、最悪の場合、時間がかかりすぎます。 たとえば、モンスターの体力が 10^6 でヒーローの攻撃が 1 の場合、各攻撃のシミュレーションにはモンスターごとに 10^6 回の反復が必要となり、実現可能な制限をはるかに超えます。 

モンスターが大きなダメージを与えても体力が低い場合、微妙なエッジケースが発生します。 不用意な貪欲なアルゴリズムにより、モンスターが任意の順序で攻撃され、主人公が早死にしてしまう可能性があります。 たとえば、体力 999 のヒーローに対して、体力 999 で攻撃力 1000 のモンスターが 1 匹いると、即死となります。 正解は「NO」ですが、必要な総ダメージを無視して攻撃回数だけを数えると、誤って「YES」と答えてしまう可能性があります。 

## アプローチ

 ブルートフォース手法では、あらゆる攻撃を明示的にシミュレートします。生きているモンスターを繰り返し選択し、その体力からヒーローの攻撃を差し引き、ヒーローの体力からモンスターの攻撃を差し引き、すべてのモンスターまたはヒーローが死ぬまで繰り返します。 これは正しいですが、テスト ケースごとに数百万の操作が必要になる可能性があり、制約を考慮すると遅すぎます。 

最適なアプローチは、各モンスターが与える合計ダメージは、それを倒すのに必要な攻撃の回数に比例するという観察を活用します。 各モンスターに必要なヒーロー攻撃の数は ceil(monster_health / hero_attach) です。 各攻撃には、モンスターの攻撃に等しいヒーローダメージがかかります。 これをすべてのモンスターで合計すると、ヒーローが各モンスターと単独で戦った場合にヒーローが受けるダメージの合計が得られます。 主人公は、彼の健康状態がこの合計から単一のモンスターの最大の攻撃を引いたものを超えるか等しい場合に生き残ります。 これが機能するのは、主人公がその攻撃で死んでも最後のモンスターを終わらせることができますが、他のモンスターは完全に生き残る必要があるからです。 並べ替えは不要です。 必要なのは、最大のモンスター攻撃力とすべてのモンスターの合計「実効ダメージ」だけです。 

ブルート フォースの推論は簡単ですが、O(n * max(b_i/A)) ですが、最適なアプローチはテスト ケースごとに線形で、制約内に完全に適合する O(n) です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * max(b_i / A)) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースごとに、ヒーローの攻撃を読み取ります`A`、主人公の健康状態`B`、モンスターの数`n`。 
2. モンスターの攻撃配列を読み取る`a`とモンスターの健康配列`b`。 
3. モンスターごとに、それを倒すのに必要な攻撃の数を計算します。 これは`(b_i + A - 1) // A`。 これにモンスターの攻撃力を掛けて、このモンスターが死ぬまでに与えるダメージの合計を求めます。 すべてのモンスターのこれらの値を合計します。 
4. 単一モンスターの最大の攻撃を特定する`max_attack`。 これは、主人公が最後のモンスターに対して受けることができるダメージを表します。これは、モンスターを倒した後に死ぬ可能性があるためです。 
5.主人公の健康状態が`B`与えられたすべての損害の合計からマイナスを引いた以上である`max_attack`、YESを出力します。 それ以外の場合は NO を出力します。 

機能する理由: 重要な不変点は、各モンスターの合計ダメージが、それを倒すのに必要な最小攻撃回数に基づいて計算されるということです。 モンスターの最大攻撃力を減算すると、主人公が最後のモンスターを倒しながら同時に死ぬ可能性があるというシナリオがモデル化されます。 これにより、主人公は問題の要件を満たし、生き残ったモンスターを残さずにすべてのモンスターを殺すことができます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    t = int(input())
    for _ in range(t):
        A, B, n = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        
        total_damage = 0
        max_attack = 0
        
        for ai, bi in zip(a, b):
            attacks_needed = (bi + A - 1) // A
            total_damage += attacks_needed * ai
            max_attack = max(max_attack, ai)
        
        if B >= total_damage - max_attack:
            print("YES")
        else:
            print("NO")

if __name__ == "__main__":
    main()
```ソリューションの各セクションは、アルゴリズムのウォークスルーに直接対応しています。 の`attacks_needed`計算では天井分割を使用して、必要な攻撃の数を正確に決定します。`total_damage`各モンスターからの潜在的なダメージを合計します。`max_attack`主人公が最後の攻撃で死ぬことを可能にするために使用されます。 ヒーローの体力が受けたダメージとまったく同じである単一のモンスターなどのエッジケースは、最終比較によって処理されます。`B >= total_damage - max_attack`。
