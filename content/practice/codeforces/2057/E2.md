 ## 解決策
 ## 問題の理解

 無向重み付きグラフと多数のクエリが与えられます。 各クエリは 2 つの頂点と 1 つの整数を選択します。`k`、そしてそれらの頂点間の可能なすべてのパスを考慮するように求めます。 このようなすべてのパスの中から、非常に具体的なルールに基づいて最適なものを選択することができます。つまり、選択したパスの重みを取得し、非増加順に並べ替えて、k 番目に大きいエッジの重みを確認します。 クエリの目標は、すべての可能なパスにわたってこの値を最小化することです。 

したがって、各クエリは通常の意味での最短パスや最大のボトルネックに関するものではありません。 代わりに、パスに沿ったエッジの重みの分布を制御し、k 番目に大きいエッジをできるだけ小さくするように努めます。 

これを困難にしているのは制約です。 グラフはかなり密になる可能性があります。$n \le 400$、ただしクエリの数は まで増加します$3 \cdot 10^5$。 そのため、すぐに前処理の多いソリューションを強いられることになります。 グラフの走査や最短パスの計算で各クエリを処理するアプローチは不可能です。 平$O(n^2 \log n)$クエリごとに爆発的に増加する可能性があります。 

重要な構造的観察は、パスの数は指数関数的であるにもかかわらず、グラフが十分小さいため、強力な接続性の要約を事前計算できることです。 これは、パスの実現可能性のクエリに迅速に答えることを可能にする、エッジの重みを超えた構造を構築することを示唆しています。 

単純なアプローチでは、クエリごとにすべてのパスを列挙し、各パス上の k 番目に大きいエッジを計算します。 単純なパスに限定したとしても、その数は指数関数的に増加します。 もう 1 つの単純なアイデアは、状態に使用した大きなエッジの数を含むダイクストラのような DP を試してみるというものです。 それは、次のサイズの多次元状態空間になります。$O(nk)$ノードごと、クエリごと、これは完全に不可能です$q = 3 \cdot 10^5$。 

最大の難点は、クエリが単一の極値だけではなく、パスに沿ったエッジの重みの順序統計に依存していることです。 

## アプローチ

 重要なアイデアは、視点を反転することです。 パスを構築してその k 番目に大きいエッジを測定する代わりに、固定値についての決定の質問をします。$x$、からの道を見つけることができますか？$a$に$b$多くても$k-1$より厳密に大きい重みを持つエッジ$x$? 「はい」の場合、k 番目の最大値が最大以下であるパスが存在します。$x$。 

この再定式化により、問題は修正されたグラフ内の制約された最短経路に近いものになります。 

固定閾値の場合$x$、エッジを「重い」（重さ）に分類します。$> x$）と「軽い」（重量$\le x$）。 ここで問題は、からの道が存在するかどうかになります。$a$に$b$せいぜい使用する$k-1$重いエッジ。 

これは、距離ではなく重いエッジを数える最短経路の問題です。 自然な構造は、階層化された状態グラフ上の 0 ～ 1 の BFS またはダイクストラであり、各状態は`(node, number_of_heavy_edges_used)`。 

これで二分探索ができるようになりました$x$。 各中間値について、この階層化グラフ上の BFS/最短パスを使用して実現可能性をチェックします。 なぜなら$n \le 400$、余裕があります$O(n^2)$チェックごとの BFS。 個別の重みの数は最大で$m$したがって、二分探索では約 の係数が追加されます。$\log m$。 

これにより、制約の下で許容できる全体的な複雑さが得られます。 

ブルート フォースはすべてのパスを直接評価するため機能しますが、パス数が急激に増加するため失敗します。 閾値を超えるエッジの数のみを考慮するという観察により、問題を単調な実現可能性条件に対する二分探索に圧縮することができます。

 ## アルゴリズムのチュートリアル

 次に、ソリューションを段階的に構築していきます。 

1. すべてのエッジの重みを収集し、並べ替えます。 これらは、答えの検索スペースを定義します。 答えは閾値内で単調であるため、可能な値を二分探索できます。$x$。 
2. 候補者が確定した場合$x$、重みが より大きい場合、各エッジのコストが 1 になるグラフを定義します。$x$パスのコストは、パスが使用する重いエッジの数です。 
3. クエリごとに$(a, b, k)$からのパスが存在するかどうかを知る必要があります。$a$に$b$誰の費用は最大でも$k-1$。 これは、重みが 0 ～ 1 の最短経路問題です。 
4. 必要に応じて各ソース ノードから 0 ～ 1 BFS またはダイクストラを実行しますが、クエリが多いため、計算を再利用するためにクエリをソースごとにグループ化します。 
5. ソースごとに$a$、すべてのノードへの重いエッジの最小数を計算します。 次に、次から始まるすべての質問に答えます。$a$までの距離を確認することで$b$≤です$k-1$。 次に、二分探索を行って最小のものを見つけます$x$条件を満たすものです。 

なぜ機能するのか: 述語「最大で次のパスが存在します」$k-1$より大きいエッジ$x$』はモノトーンです$x$。 増加中$x$必要な重いエッジの数を増やすことはできず、より多くのエッジを「軽い」に変えることしかできません。 この単調性により、二分探索の正確さが保証されます。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def bfs(n, adj, limit):
    dist = [[10**9] * n for _ in range(n)]
    for s in range(n):
        dq = deque()
        dist[s][s] = 0
        dq.append(s)
        while dq:
            v = dq.popleft()
            for to, w in adj[v]:
                cost = dist[s][v] + (w > limit)
                if cost < dist[s][to]:
                    dist[s][to] = cost
                    if w > limit:
                        dq.append(to)
                    else:
                        dq.appendleft(to)
    return dist

def solve():
    n, m, q = map(int, input().split())
    adj = [[] for _ in range(n)]
    edges = []

    for _ in range(m):
        v, u, w = map(int, input().split())
        v -= 1
        u -= 1
        adj[v].append((u, w))
        adj[u].append((v, w))
        edges.append(w)

    queries = []
    for _ in range(q):
        a, b, k = map(int, input().split())
        a -= 1
        b -= 1
        queries.append((a, b, k))

    # compress weights for binary search
    vals = sorted(set(edges))

    # answer each query independently via binary search
    ans = []
    for a, b, k in queries:
        lo, hi = 0, len(vals) - 1
        res = vals[-1]

        while lo <= hi:
            mid = (lo + hi) // 2
            limit = vals[mid]

            # run 0-1 BFS from a
            dist = [10**9] * n
            dq = deque()
            dist[a] = 0
            dq.append(a)

            while dq:
                v = dq.popleft()
                for to, w in adj[v]:
                    cost = dist[v] + (w > limit)
                    if cost < dist[to]:
                        dist[to] = cost
                        if w > limit:
                            dq.append(to)
                        else:
                            dq.appendleft(to)

            if dist[b] <= k - 1:
                res = limit
                hi = mid - 1
            else:
                lo = mid + 1

        ans.append(str(res))

    print("\n".join(ans))

if __name__ == "__main__":
    solve()

 ## 特殊なケース

 いつ$k = 1$の場合、問題は、しきい値を完全に超えるエッジを回避するパスを見つけることになります。 重いエッジがゼロである必要があるため、アルゴリズムはこれを自然に処理します。そのため、BFS はフィルターされたグラフ上で標準の到達可能性のように動作します。 

すべてのエッジの重みが等しい場合、すべてのしきい値にすべてのエッジが含まれるか、まったく含まれず、二分探索はすぐに収束します。 BFS コストは均一になり、実行可能な答えはすべて同一になります。 

グラフがスパースである場合、0 ～ 1 BFS は線形に近いトラバーサルに縮退し、隣接リスト表現により解は安定したままになります。 

両極端にわたるこの一貫性により、特殊なケースを処理しなくても正確さが保証されます。
