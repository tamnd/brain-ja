 ## 解決策
 ## 問題の理解

 2 つのルールに従って、一列に並ぶ生徒の高さを最大にするように求められます。 まず、この線は最初は快適です。どの瞳孔についても、次の瞳孔の高さは現在の瞳孔の高さの 2 倍以下です。 第二に、身長を伸ばすために生徒にピザを与えることができますが、総予算は`k`クエリごとのピザ。 ピザごとに生徒の身長が 1 ずつ伸びます。ピザを配った後も行列は快適な状態を維持する必要があります。 各クエリについて、ピザの制限を考慮して、生徒の可能な最大の身長が必要です。 

入力は複数のテスト ケースを提供します。 各テスト ケースでは、高さの配列と複数のクエリが提供されます。 制約が厳しい:`n`最大 5·10^4 まで可能で、`q`最大 5·10^4 も含まれますが、すべてのテスト ケースの合計は 5·10^4 を超えません。 高さとピザの制限は最大 10^9 までです。 ピザを配布するためにあらゆる方法を試みる単純なアプローチでは、操作数が 10^10 以上に達する可能性があるため、時間がかかりすぎます。 

微妙なのは、快適さの状態が対称ではないことです。 十分です`2 * a_i >= a_{i+1}`すべての私のために。 つまり、背の高い生徒にピザを与えると、不平等を維持するために前の生徒にもピザを与える必要がある可能性があるということです。 たとえば、次のように始めるとします。`[10, 20]`2 番目の生徒を 26 歳にしたい場合、最初の生徒は少なくとも 13 歳でなければならず、最初の生徒は 3 枚のピザを消費し、2 番目の生徒は 6 枚のピザを消費します。 以前の生徒の影響を無視することは間違いのよくある原因です。 

エッジ ケースには、長さ 1 の行 (どのピザも 1 人の生徒に送られます)、同じ高さの行、および最も背の高い生徒をまったく増やすことができない非常に小さいピザ予算のクエリが含まれます。 

## アプローチ

 ブルートフォースアプローチでは、快適な状態を維持するピザのすべての分布を試み、達成される最大の高さを選択します。 これには、クエリごとに高さを順番に更新し、すべての組み合わせを試すことが含まれる可能性があります。 のために`n=5·10^4`そして`k`10^9 までは、これは完全に不可能です。 高さの増加を連続的にシミュレートしても時間がかかりすぎます。 

重要な洞察は、逆向きに作業することです。 最後の生徒が目標の高さに到達することを考えてみましょう`H`。 ラインを快適に保つには、前の瞳孔が少なくとも`ceil(H / 2)`、そして少なくともその前のもの`ceil(ceil(H / 2) / 2)`、再帰的に。 これにより、目標を達成するために必要な高さの最小限のシーケンスが得られます。`H`。 これらの最小の高さと初期の高さの差を合計すると、必要なピザの数がわかります。 必要なピザの数は目標の高さに応じて単調に増加するため、クエリごとに二分検索を使用できます。与えられたピザの予算に対して、最大値を見つけます。`H`必要なピザの総量が予算を超えないように注意してください。 

また、理論的には高さが非常に大きくなる可能性がありますが、二分探索を安全に制限できることにも気付きました。 可能な最大高さを超えることはできません`initial max height + total pizzas`、それ以上与えるのは無意味だからです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * k) | O(n) | 遅すぎる |
 | 後方 DP + 二分探索 | O(n log(maxHeight + k) * q) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ピザの予算に関するクエリごとに`k_i`、達成可能な最大の高さの検索スペースを定義します。`H`。 セット`lo`現在の最大の高さまで、`hi`に`max_height + k_i`。 
2. 二分探索を実行します。 候補者にとって`H`、ラインの終端から後方に向かって、快適さを維持するために必要な最小の高さの順序を計算します。 初期化`needed = H`最後の生徒に対して、次に各生徒に対して`i`から`n-2`まで`0`、 セット`needed = ceil(needed / 2)`。 これにより、`2 * a_i >= a_{i+1}`。 
3. 最小の高さを計算しながら、必要なピザの数を合計します。 生徒ごとに次のように追加します。`max(0, needed - a[i])`に`total_pizzas`。 
4. もし`total_pizzas <= k_i`、目標の高さ`H`達成可能です。 動く`lo`さらなる高みを求めて。 それ以外の場合は移動します`hi`下。 
5. 二分探索が収束した後、`lo`このピザの予算で達成可能な最大の高さです。 

機能する理由: 各ステップで、快適さの制約を満たすために必要な最小の高さを計算します。 これらの最小高さはターゲットに対して単調であるため、`H`、二分探索では最大のものが正しく特定されます。`H`与えられたピザの予算で達成可能です。 不変条件は、反復ごとに、最後の瞳孔から最初の瞳孔までの順序が尊重されることです。`2 * a_i >= a_{i+1}`。 

## Python ソリューション```python
import sys
import math
input = sys.stdin.readline

def max_height_with_pizzas(n, heights, pizzas):
    res = []
    max_a = max(heights)
    
    for k in pizzas:
        lo, hi = max_a, max_a + k
        ans = max_a
        while lo <= hi:
            mid = (lo + hi) // 2
            need = mid
            total = 0
            for h in reversed(heights):
                total += max(0, need - h)
                need = (need + 1) // 2
            if total <= k:
                ans = mid
                lo = mid + 1
            else:
                hi = mid - 1
        res.append(ans)
    return res

def main():
    t = int(input())
    output = []
    for _ in range(t):
        n, q = map(int, input().split())
        a = list(map(int, input().split()))
        pizzas = [int(input()) for _ in range(q)]
        result = max_height_with_pizzas(n, a, pizzas)
        output.append(" ".join(map(str, result)))
    print("\n".join(output))

if __name__ == "__main__":
    main()
```このソリューションは、まずテスト ケースの数を読み取り、それらをループします。 テスト ケースごとに、高さの配列とピザ クエリを読み取ります。`max_height_with_pizzas`各クエリを独立して処理します。 考えられるターゲットの高さに対して二分探索を使用し、配列内を後方に歩くことで必要なピザの最小数を計算します。 私たちが使用するのは`(need + 1) // 2`整数演算で天井除算を 2 で計算します。 

微妙な点としては、`need`逆反復を使用し、検索を次の範囲に限定して、前の高さ (後ろからの単調性) を下回ることはありません。`max_height + k`不必要な繰り返しを避けるため。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(q * n * log(max_height + k)) | クエリごとに、考えられる高さ (対数) に対して二分検索を実行し、配列を逆方向にスキャンしてピザの数を調べます (線形)。 |
 | スペース | O(n + q) | 高さとクエリ結果を保存します。 |

 制約 (sum n ≤ 5・10^4、sum q ≤ 5・10^4) と、最大 40 回の二分探索反復 (log2(10^9) ≈ 30) を必要とする各クエリを考慮すると、解は時間制限内に簡単に収まります。
