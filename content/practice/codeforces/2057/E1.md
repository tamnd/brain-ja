 ## 解決策
 ## 問題の理解

 最大 400 個の頂点と最大 400 個のエッジを持つ接続された無向グラフが与えられます。 すべてのエッジには正の重みがあります。 クエリごとに 2 つの頂点が与えられます。`a`そして`b`、および数字`k`。 考えられるすべての単純なパスの中で、`a`に`b`では、パスに沿ったエッジの重みのマルチセットを考慮します。 これらの重みを非増加順に並べ替え、可能な限り最適なパスを選択した後、その並べ替えられたリスト内の k 番目の要素の値が必要になります。 

したがって、各クエリは最短パスや最小スパニング ツリー プロパティを要求しません。 代わりに、エンドポイント間の任意のパスを選択することができ、そのパスの統計、つまりそのパス上の k 番目に大きいエッジの重みを最適化しようとしています。 

この難しさは、パスが異なれば長さもウェイト分布も異なるという事実から生じます。 k に応じて、多くの中程度のエッジを持つパスの方が、大きなエッジが 1 つあるパスよりも優れている場合があります。 

という点では制約は小さい`n`そして`m`、どちらもテスト ケース セットごとに合計 400 に制限されていますが、クエリの数は 300,000 に達する可能性があります。 これにより、クエリごとのグラフの走査や最短パスの計算が即座に排除されます。 平`O(n^2)`per query would be far too slow.

 唯一の実行可能な方向は、各クエリにほぼ一定時間または対数時間で応答できるようにするグラフの前処理を大量に行うことです。 

微妙なエッジ条件は、この問題により、からのすべてのパスが保証されることです。`a`に`b`少なくとも`k`エッジ。 これにより、k がパス長を超える未定義のクエリが防止されますが、少なくとも k エッジの長さのパスを考慮する必要があることも意味するため、単純な「最短パス」ロジックでは直接的には十分ではありません。 

## アプローチ

 直接的なアプローチでは、間の単純なパスをすべて列挙します。`a`そして`b`、各パス上で k 番目に大きいエッジを計算し、すべてのパスの最小値を取得します。 これは概念的には正しいですが、完全に実行不可能です。 グラフ内の単純なパスの数は指数関数的に増加する可能性があり、頂点が 400 あるグラフであっても、これはすぐに手に負えなくなります。 

構造改革が必要だ。 重要な観察は、答えは、あるパスに沿って累積できる特定の重みしきい値のエッジの数にのみ依存するということです。 正確なエッジの重みを順番に推論する代わりに、答えの値を二分探索することができます。 

候補の重みを修正する`x`。 からのパスを見つけられるかどうかだけを気にするとします。`a`に`b`少なくとも含まれる`k`少なくとも重量のあるエッジ`x`。 そのようなパスが存在する場合、そのパス上の k 番目に大きいエッジの重みは少なくとも`x`。 それ以外の場合は以下より小さいです`x`。 

これにより、問題は単調な実現可能性チェックに変わります。これはまさに二分探索に必要なものです。 ただし、残りの困難は、多くのクエリに対してこの実現可能性を効率的に評価しなければならないことです。 

次に、グラフの構造を見てみましょう。 以来`n ≤ 400`、頂点のすべてのペアとエッジの重みによって引き起こされるすべての可能なしきい値の到達可能性情報を前処理できます。 標準的な方法は、エッジを重みでソートし、DSU に段階的に追加することです。 そうすることで、接続性を維持し、「最適なパス上にこのしきい値からのエッジがいくつ存在するか」を答えることができる方法でエッジの距離や数を追跡することもできます。 

簡単なバージョンでは、グラフが小さくて静的であるという事実を利用します。 すべてのペアの最短パスをエッジの数に関して前処理し、各ペアについてエッジの重みが最適パスに沿ってどのように蓄積されるかに関する情報も維持します。 より効果的な方法は、すべてのペアについて事前計算することです。`(u, v)`、少なくともウェイトのエッジの最大数`x`あらゆるパスに沿って、すべての異なる重量レベルに対応`x`。 

エッジの数が少ないため、重みを圧縮し、重みのしきい値ごとに、しきい値以上のエッジのみを含むグラフを構築できます。 このサブグラフでは、エッジの数に関して全ペアの最短パスを計算するか、接続性に制限された重み付けされていない意味での同等の最長パスを計算します (グラフが小さくて十分に密度が高いため、しきい値ごとに BFS/DP を実行できます)。 これにより次の表が得られます。`best[u][v][i] = maximum number of edges on a path from u to v using edges of weight ≥ w_i`。 

次に、各クエリは最小のインデックスを見つけることに帰着します。`i`そのような`best[a][b][i] ≥ k`。 これは、ソートされた個別の重みに対する二分探索です。 

なぜなら両方とも`n`そして`m`が最大 400、個別の重みが最大 400 の場合、この前処理は実行可能です。

 ## アルゴリズムのチュートリアル

 1. すべての個別のエッジの重みを抽出し、降順に並べ替えます。 これらは、エッジをフィルタリングするためのしきい値を定義します。 
2. 各閾値について`w_i`、重みが少なくとも次のエッジのみを含むグラフを構築します。`w_i`。 これにより、ネストされたグラフのシーケンスが作成され、それぞれが前のグラフのサブグラフになります。 このネストは構造を暗黙的に再利用できるため、非常に重要です。 
3. しきい値グラフごとに、行列を計算します。`dist[i][u][v]`からの任意の単純なパス上のエッジの最大数を表します。`u`に`v`そのしきい値グラフのエッジのみを使用します。 サイクルは許可されていますが、単純なパスの長さの増加には役立たないため、無向グラフ内の最長の単純なパス長を効果的に計算します。これは、BFS ツリー上の BFS または慎重に処理したコンポーネントごとのマルチソース BFS に削減されます。 実際には、グラフが小さいため、各ノードから BFS/DP を繰り返すだけで十分です。 
4. これらの値をしきい値全体に保存して、どのペアでも`(u, v)`と閾値`i`、使用可能なエッジの最大数がわかります。 
5. 各クエリについて`(a, b, k)`、しきい値を超えた二分探索。 中点閾値の場合`i`、どうかを確認してください`dist[i][a][b] ≥ k`。 「はい」の場合は、より高いしきい値を試すことができます。 そうでなければ、もっと下に行かなければなりません。 
6. 少なくとも許容できる最小のしきい値インデックスを出力します。`k`あるパス上のエッジ。 

### なぜ効果があるのか

 核となる不変条件は、しきい値にわたる単調性です。 エッジを使用したパスが存在する場合 ≥`w_i`少なくとも含まれる`k`エッジの場合、同じ特性が下限のしきい値にも当てはまります`w_j ≤ w_i`なぜなら、しきい値を下げてもエッジが追加されるだけであり、最適なパスでの到達可能性や使用可能なエッジの数を減らすことはできないからです。 この単調な構造により、バイナリ検索が有効であることが保証されます。 

2 番目の重要な特性は、固定しきい値の場合、エッジ数の最大化に関する最適なパスはペアごとに独立しているため、事前に計算できることです。 これにより、前処理後のクエリがグラフ構造から完全に切り離されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, q = map(int, input().split())
    edges = []
    weights = set()

    for _ in range(m):
        u, v, w = map(int, input().split())
        u -= 1
        v -= 1
        edges.append((u, v, w))
        weights.add(w)

    weights = sorted(weights, reverse=True)
    idx = {w:i for i, w in enumerate(weights)}
    T = len(weights)

    # adj per threshold
    adj = [[] for _ in range(T)]
    for u, v, w in edges:
        for i in range(idx[w] + 1):
            adj[i].append((u, v))

    # dist[t][u][v] = max number of edges from u to v in graph t
    dist = [[[0]*n for _ in range(n)] for _ in range(T)]

    for t in range(T):
        g = [[] for _ in range(n)]
        for u, v in adj[t]:
            g[u].append(v)
            g[v].append(u)

        for s in range(n):
            dp = [-1]*n
            dp[s] = 0
            stack = [s]
            while stack:
                x = stack.pop()
                for y in g[x]:
                    if dp[y] < dp[x] + 1:
                        dp[y] = dp[x] + 1
                        stack.append(y)
            dist[t][s] = dp

    for _ in range(q):
        a, b, k = map(int, input().split())
        a -= 1
        b -= 1

        lo, hi = 0, T - 1
        ans = T - 1

        while lo <= hi:
            mid = (lo + hi) // 2
            if dist[mid][a][b] >= k:
                ans = mid
                lo = mid + 1
            else:
                hi = mid - 1

        print(weights[ans])

if __name__ == "__main__":
    solve()
```前処理では、重みのしきい値の減少によってソートされたグラフの階層が構築されます。 しきい値ごとに、そのしきい値を満たすエッジのみを含む隣接リストを作成します。 次に、ソース ノードごとに、他のすべてのノードに到達可能なエッジの最大数を更新する緩和スタイルの DFS を実行します。 これは、重み付けされていないグラフ内の最長パスを効果的に計算することになります。これは、繰り返しアクセスしてもカウントが増加するだけであり、常に最もよく観察された値を保存するため、有効です。 

次に、各クエリはしきい値を超えて二分検索を使用します。 重要な詳細は次のとおりです`dist[t][a][b]`モノトーンです`t`, 効率的に検索できるようになります。

 ## 特殊なケース

 重要なエッジ ケースは、最適パスが迂回路を使用してエッジ数を k より大きくする場合です。 たとえば、三角グラフでは、最短パスのエッジは 1 つだけですが、別の頂点を通る長いパスは、古典的な最短パスの意味では最適ではない場合でも、k=2 を満たす可能性があります。 DFS はすべての単純な拡張機能を探索し、到達可能な最大の深さを保持するため、前処理によってこれが処理されます。 

もう 1 つのエッジ ケースは、エンドポイントは同じだが長さの分布が異なる複数のパスが存在する場合です。 このアルゴリズムは、しきい値ごとに達成可能な最大エッジ数を常に保存し、パス構造に関係なく、可能な限り最適な構成が考慮されるようにします。
