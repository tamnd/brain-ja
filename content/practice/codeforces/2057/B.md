 ## 解決策
 ## 問題の理解

 私たちは、ゴリラが特定の削除操作を使用して配列を効率的にクリアできるよう支援するように求められています。 この操作は、任意の連続する部分配列に対して機能します。つまり、その部分配列内の最小値を選択し、選択したセグメントからその最小値が出現するすべてを削除します。 要素が削除され、インデックスの番号が付け直されると、配列は縮小します。 目標は、配列が空になるまで、そのような操作をできるだけ少なく実行することです。 さらに、以下まで変更することができます。`k`これにより、これらの操作を実行する前に配列を単純化することができます。 

入力は複数のテスト ケースを提供します。 各テスト ケースは配列の長さで構成されます。`n`、変更の数`k`、および配列自体。 各テスト ケースの出力は、最適な置換の後に必要な最小限の操作数です。 の合計を考えると、`n`すべてのテスト ケースにわたって ≤ 10^5 である場合、各テスト ケースを効率的に、理想的には線形または線形に近い時間で処理する必要があります。 これにより、指数関数的になる可能性のあるすべての削除シーケンスを考慮する強引なアプローチが排除されます。 

重要なエッジ ケースは、すべての配列要素がすでに等しい場合、または次の場合に発生します。`k`配列を均一にするのに十分な大きさです。 たとえば、`a = [2, 3, 2]`そして`k = 1`、真ん中を変える`3`に`2`配列全体を 1 回の操作でクリアできます。 単純なアプローチでは、置換の可能性を考慮せずに、単純に任意の部分配列の最小値をカウントする可能性があり、最適な答えを生成できません。 

配列の値が頻繁に切り替わる場合、別の微妙な問題が発生します。 例えば、`a = [1, 2, 1, 2, 1]`そして`k = 2`のうちの 2 つを置き換えることができます`2`と一緒です`1`s、ギャップをマージし、操作の数を減らします。 の価値を無視した不用意なアプローチ`k`操作を過剰にカウントしてしまう可能性があります。 

## アプローチ

 ブルートフォース手法では、可能なすべての連続サブ配列に対して削除操作をシミュレートし、すべての削除と置換のシーケンスを試行します。 このアプローチは理論的には正しいですが、現実的ではありません。 長さの配列の場合`n`の場合、部分配列の数は O(n^2) であり、削除の追跡は組み合わせ的に増加します。 サイズ 1000 の小さな配列であっても、何百万もの可能性が生じますが、制約を考えるとこれは受け入れられません。 

問題を単純化する重要な観察は、必要な操作の数は、配列を左から右に順番にスキャンするときに遭遇する個別の値の数によって決まり、前の要素から値が何回変化したかを数えることです。 同じ数字の各「セグメント」は、賢く選択すれば 1 回の操作で削除できます。 まで変更することで、`k`要素を使用する場合、これらのセグメントの一部をマージして、操作の合計数を減らすことができます。 

配列内の最小の数値が`x`に等しくない数に遭遇するたびに、`x`、新しいセグメントが開始されますが、これには別の操作が必要になる場合があります。 したがって、最適な戦略は、配列を、選択した「アンカー」値 (通常は最初の要素) の出現によって区切られたシーケンスとみなして、異なる番号のセグメントがいくつ存在するかをカウントすることです。 置換を使用して、これらのセグメントの数を減らすことができます。 もし`k`セグメント間の異なる要素をすべて変更するのに十分な大きさである場合、操作の数を 1 に減らすことができます。それ以外の場合は、貪欲なアプローチを適用します。置換ごとに余分なセグメントを 1 つ削除できるため、操作の合計が減ります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | 最適 | テスト ケースあたり O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースごとに、配列を読み取ります。`a`そして許可される変更`k`。 操作数のカウンターを初期化します。`ops = 0`。 
2. 最初の要素を選択します`first = a[0]`アンカー値として。 この要素は、セグメントのカウントをガイドします。 この選択は、それに一致するように他の要素をいつでも変更できるため機能します。 
3. 最初の要素から始めて配列を走査します。 要素ごとに`a[i]`に等しいかどうかを確認します`first`。 そうであれば、続行します。 現在のセグメントに属します。 異なる場合は増分します`ops`削除が必要なセグメントを考慮して 1 ずつ増加します。 次をスキップ`k`要素、一致するように置き換えるシミュレーション`first`。 各置換は効果的にマージされます。`k`連続した異なる要素をアンカーされたセグメントに挿入する`first`。 
4. 配列の処理後、インクリメントします。`ops`最初のセグメントを考慮して、または配列が異なる値で始まる場合は 1 ずつ増加します。 出力`ops`最小限の操作数として。 
5. テスト ケースごとに繰り返します。 

機能する理由: すべての操作で、連続したブロック内の現在のセグメントの最小値のすべてのインスタンスが削除されます。 貪欲にアンカー値を選択し、最大で置き換えることにより、`k`要素を連続して配置する場合、操作ごとに削除される要素の数を最大化します。 この戦略により、変更不可能なセグメントごとに複数の操作が必要になることがなくなり、可能な限り多くのセグメントをマージできます。`k`許可します。 不変条件は、各操作と置換の後、残りのセグメントの数が達成可能な最小の削除を反映するということです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        
        ops = 0
        i = 0
        first = a[0]
        
        while i < n:
            if a[i] == first:
                i += 1
                continue
            ops += 1
            i += k
        print(max(1, ops))

solve()
```このコードは、各テスト ケースを読み取り、操作カウンターを初期化します。 アンカーに等しい要素をスキップして、配列を反復処理します。 異なる要素が見つかった場合、操作カウントをインクリメントし、次の操作をスキップします。`k`要素、その変換をシミュレートします。 最大値の 1 を出力し、`ops`すでに均一な配列を処理します。
