 ## 解決策
 ## 問題の理解

 2D 平面上の座標で表される一連の都市が与えられます。 4 人の商人が単一の分割点を使用して都市を分割したいと考えています$(x_0, y_0)$。 この分割は、各商人が相対的に 1 つの象限内の都市を取得するように機能します。$(x_0, y_0)$:

 - 販売者 1 は右上の象限を取得します ($x \ge x_0$、$y \ge y_0$）、
 - 販売者 2 は左上の象限を取得します ($x < x_0$、$y \ge y_0$）、
 - 販売者 3 は右下の象限を取得します ($x \ge x_0$、$y < y_0$）、
 - マーチャント 4 は左下の象限を取得します ($x < x_0$、$y < y_0$）。 

目標は選択することです$(x_0, y_0)$加盟店に割り当てられる都市の最小数が最大化されるようにします。 言い換えれば、可能な限り最もバランスのとれた分割が必要です。 出力は、この最大最小都市数です。$k$および対応する点$(x_0, y_0)$。 

制約は、すべてのテスト ケースにわたる都市の合計数が到達できることを示します。$10^5$。 あらゆる可能性を試す素朴なアプローチ$(x_0, y_0)$それは実行不可能です。$O(n^2)$可能性。 エッジケースには同一の座標を持つ都市が含まれており、慎重に扱わないと象限全体が空になる可能性があります。 

たとえば、すべての都市が$(0,0)$、どのように分割しても、少なくとも 3 つの販売者の都市はゼロになり、正しい出力は次のようになります。$k=0$。 

## アプローチ

 ブルートフォースアプローチは、考えられるすべてのことを繰り返すことです。$x_0$そして$y_0$都市の座標から、各象限に該当する都市の数を数えます。 これには必要になります$O(n^2)$テストケースごとの操作は遅すぎます。$n$まで$10^5$。 座標を並べ替えて各ペアの中点を試しても、$O(n^2)$最悪の場合。 

重要な観察は、バランスの取れた分割の場合、中央座標の近くにある分割点のみを考慮する必要があるということです。 x 座標と y 座標を個別にソートすると、最適な$x_0$に近いでしょう$n/2$-th 要素、および同様に$y_0$。 これにより、候補分割点が一定数の中央値に減ります。 

具体的には、次の値を考慮できます。$\lceil n/4 \rceil$-番目と$\lfloor 3n/4 \rfloor$ソートされた座標配列内の - 番目の位置。 この範囲内のどの点でも、どの商店も都市の 4 分の 3 を超え、最小値を最大化する 4 分の 1 以上を取得することが保証されます。 

この洞察により、問題は座標のソートと適切な中央値候補の選択に集約されます。 次に、候補の組み合わせを確認する必要があります。$x_0$そして$y_0$最大の最小カウントが得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 中央値に基づく選択 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、都市の数を読み取ります。$n$そして座標のリスト。 
2. すべての X 座標を個別に抽出して並べ替えてから、すべての Y 座標を個別に並べ替えます。 
3. 候補者を特定する$x_0$位置の座標としての値$n//4$そして$(3n)//4$ソートされた X 配列内。 候補者にも同じことをする$y_0$価値観。 これらの位置は四分位に対応します。 
4. 候補の組み合わせごとに$x_0$そして$y_0$、座標を 1 回通過して、4 つの象限のそれぞれにある都市の数を数えます。 
5. 候補ペアごとに 4 つの販売者全体の最小数を計算します。 
6. これらの最小カウントの最大値と、対応する分割点を記録します。 
7. 最大最小カウントを出力します。$k$そしてどれでも$(x_0, y_0)$それはそれを達成します。 

機能する理由: 四分位で分割点の候補を選択することで、最小値を最大化する下位四分位の都市数よりも少ない都市数を受け取る販売者が存在しないことが保証されます。 2 つの四分位境界間のどの点でも同じ最小分布が得られるため、一定数の候補座標のみを考慮する必要があります。 並べ替えにより、これらの四分位位置に確実にアクセスできるようになります。$O(1)$後$O(n \log n)$並べ替え。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        cities = [tuple(map(int, input().split())) for _ in range(n)]
        xs = sorted(x for x, y in cities)
        ys = sorted(y for x, y in cities)
        
        # candidate quartile positions
        x_candidates = [xs[n//4], xs[(3*n)//4]]
        y_candidates = [ys[n//4], ys[(3*n)//4]]
        
        best_k = -1
        best_point = None
        
        for x0 in x_candidates:
            for y0 in y_candidates:
                counts = [0, 0, 0, 0]  # merchants 1-4
                for x, y in cities:
                    if x >= x0 and y >= y0:
                        counts[0] += 1
                    elif x < x0 and y >= y0:
                        counts[1] += 1
                    elif x >= x0 and y < y0:
                        counts[2] += 1
                    else:
                        counts[3] += 1
                min_count = min(counts)
                if min_count > best_k:
                    best_k = min_count
                    best_point = (x0, y0)
        
        print(best_k)
        print(*best_point)

if __name__ == "__main__":
    solve()
```このコードは座標を並べ替えて、四分位候補を効率的に特定します。 各象限内の都市のカウントは、候補ごとに 1 つのループで行われます。これは、x 値の候補が 4 つと y 値の候補が 4 つしかないため、十分に高速であり、テスト ケースごとに最大 16 個のチェックが生成されます。
