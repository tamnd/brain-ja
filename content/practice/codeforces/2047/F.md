[CF 2047F - 皇帝のために!](https://codeforces.com/problemset/problem/2047/F)

 **評価:** 3100
 **タグ:** フロー、グラフ
 **解決時間:** 2 分 3 秒
 **確認済み:** いいえ

 ## 解決策
 ## 問題の理解

 都市の有向グラフがあります。 市`i`最初に含まれています`a_i`メッセンジャー。 

メッセンジャーは指示された道路に沿って移動できます。 メッセンジャーがすでに計画を知っていれば、旅行中にそれを運ぶことができます。 そのような使者が都市に到着すると、現在そこにいるすべての使者に計画のコピーを渡すことができます。 その瞬間から、新たに情報を伝えたメッセンジャー全員が旅行し、計画を広め続ける可能性があります。 

何かが始まる前に、既存のメッセンジャーを何人か選び、彼らに計画のコピーを直接手渡すかもしれません。 選択したメッセンジャーごとに初期コピーが 1 つかかります。 課題は、最初に配布されるコピーの数を最小限に抑えながら、すべての都市に少なくとも 1 人の情報提供者が訪問することを保証することです。 

メッセンジャーのいない都市が自動的に絶望的になるわけではありません。 まだ他所からの使者によって知らせられるかもしれない。 本当の問題は、既存のメッセンジャーの集合体がグラフを通じてすべての都市に届く方法で情報を伝播できるかどうかです。 

グラフには、テスト ケース全体で最大 200 個の頂点と 800 個のエッジが含まれます。 これらの数は、洗練された大規模グラフ手法には小さすぎますが、指数関数的な状態検索が不可能であるほど十分に大きいです。 この問題の評価は 3100 です。これは、難易度が計算規模ではなく、正しいグラフ フロー モデルを見つけることであるためです。 

最初の構造観察は、強く接続されたコンポーネントが分割不可能なユニットとして動作するということです。 SCC 内の 1 人のメッセンジャーが計画を学習すると、彼は SCC 全体を歩き回って、そこにいるすべてのメッセンジャーをアクティブにすることができます。 その後、その SCC 内のすべてのメッセンジャーがさらなる伝播に利用できるようになります。 

いくつかの特殊なケースは見落とされがちです。 

メッセンジャーのないコンポーネントを考えてみましょう。```
2 1
0 1
2 1
```都市 2 は都市 1 にメッセンジャーを送信できるため、答えは次のようになります。`1`。 ローカルメッセンジャーの数だけを見ると、都市 1 は使用できないと誤って結論付けられてしまいます。 

次に、次のことを考えてみましょう。```
2 2
0 0
1 2
2 1
```どこにもメッセンジャーはいません。 初期コピーを割り当てることはできません。 正しい答えは、`-1`。 

より微妙な例は次のとおりです。```
3 2
1 0 1
1 2
3 2
```シティ 2 にはメッセンジャーがいません。 どちらの側からも情報を得ることができますが、情報を 2 つの情報源都市間で移動することはできません。 まだ 2 つの初期アクティベーションが必要です。 単純にゼロ次数 SCC をカウントする貪欲な戦略では、メッセンジャーの可用性の制約を捉えることができません。 

## アプローチ

 強引な視点は、すべてのメッセンジャーを個別のリソースとして考えることです。 最初のコピーを受信するメッセンジャーのすべてのサブセットを試して、拡散プロセスをシミュレートすることができます。 グラフにメッセンジャーが 200 件でも含まれている場合、検索空間は指数関数的であるため、これはすぐに不可能になります。 

総当たり攻撃が魅力的に感じられる理由は、拡散には到達可能性の問題があるように見えるからです。 残念ながら、アクティブ化すると新しいアクティブなメッセンジャーが作成され、それらのメッセンジャーは独立して分岐する可能性があります。 さまざまなアクティベーションの選択肢間の相互作用は非常に複雑になります。 

重要な観察は、SCC 凝縮の後、グラフが DAG になることです。 1 つの SCC 内で 1 つのメッセンジャーをアクティブ化すると、その SCC のすべてのメッセンジャーがアクティブ化されます。 

させて$$b_u = \text{total number of messengers inside SCC } u.$$1回SCC`u`有効化されている場合、最大で貢献できます`b_u`世界的な拡散プロセスへのメッセンジャー。 

個々の動きを追跡するのではなく、フローの単位を 1 人のメッセンジャーの軌跡として扱います。 軌跡は凝縮 DAG 内を移動できます。 すべての SCC には、少なくとも 1 つの軌道が通過する必要があります。 SCC に次の内容が含まれている場合、`b_u`メッセンジャー、アクティブ化後に生成できるのは最大でも`b_u`独立した軌道。 

これにより、問題はコストに関するフローの実現可能性の問題に変わります。 軌道を手動で作成する場所の数を最小限に抑えながら、「すべての SCC を訪問する」という要件を満たす必要があります。 

結果として得られるモデルは、SCC DAG 上での最小コストの実現可能なフロー構築です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | 指数 | 遅すぎる |
 | SCC + 最小コストの実現可能なフロー |$O(K^3)$に$O(K^4)$実際には、$K \le 200$|$O(K^2)$| 承認済み |

 ここ`K`は SCC の数です。 

## アルゴリズムのチュートリアル

 ### 1. 強く結合したコンポーネントを圧縮する

 Tarjan のアルゴリズムを実行します。 

すべての SCC について、計算します$$b_u=\sum a_i$$その SCC 内のすべての元の頂点にわたって。 

グラフを凝縮グラフに置き換えます。 凝縮グラフは DAG です。 

SCC 内では、1 つのアクティブ化されたメッセンジャーがすべてのローカル メッセンジャーをアクティブ化できるため、総数のみが有効になります。`b_u`重要です。 

### 2. フローモデルを構築する

 すべての SCC について`u`、3つの頂点を作成します。```
A_u
B_u
C_u
```彼らの役割は次のとおりです。`A_u`この SCC に存在するメッセンジャーの数を制御します。`B_u`SCC の要件を表します。`u`少なくとも 1 回はアクティブ化する必要があります。`C_u`要件が満たされた後にアクティブ化された SCC を表します。 

### 3. モデルメッセンジャーの利用可能性

 SCCの場合`u`含まれています`b_u`メッセンジャー、追加```
Source -> A_u   capacity = b_u
```これは、せいぜい`b_u`軌道は、SCC がアクティブになった後、この SCC から始まる可能性があります。 

### 4. モデルマニュアルのアクティベーションコスト

 追加```
A_u -> B_u   capacity = 1, cost = 1
A_u -> C_u   capacity = INF, cost = 0
```最初のエッジは、SCC 内の 1 人のメッセンジャーに計画を手動で与えることに対応します。 

このコストを支払うことができるのは 1 つのユニットだけです。 

### 5. すべての SCC を強制的にアクティブ化する

 追加```
B_u -> C_u   capacity = 1, cost = -TAG
B_u -> C_u   capacity = INF, cost = 0
```どこ`TAG`は非常に大きな定数です。 

マイナスコストのエッジは、SCC を 1 回アクティブ化することで報酬を与えます。 

最適化では、すべての SCC に対してこの報酬を収集しようとします。 

### 6. DAG を介したモデルの伝播

 あらゆる凝縮エッジに対して```
u -> v
```追加```
C_u -> B_v   capacity = INF
```アクティブ化された SCC を離れる軌道は、後続の SCC をアクティブ化する場合があります。 

### 7. 実行可能フロー問題への変換

 標準の下限/実行可能フロー構造を追加します。 

承認されたソリューションで使用される実装では、スーパー ソースとスーパー シンクが作成され、すべての SCC が必須のアクティブ化フローを取得できるかどうかが確認されます。 

### 8. min-cost max-flow を実行します。 

実行可能フローが SCC ごとにアクティブ化される場合、得られるコストを`cost`。 

本当の答えは$$cost + K \cdot TAG$$すべての SCC が 1 つの人工報酬を提供したため`-TAG`。 

実現可能性が失敗した場合は出力`-1`。 

### なぜ効果があるのか

 フローの各単位は 1 つのメッセンジャーの軌道を表します。 

グローバルソースから SCC へのエッジ`u`その SCC から発信できる軌道の数を、そこにある利用可能なメッセンジャーの数に正確に制限します。 

通過中`B_u -> C_u`SCCの有効化に対応`u`。 負の報酬により、最適なソリューションは可能な限りすべての SCC をアクティブ化します。 

軌道は、DAG エッジを経由するか、手動でアクティブ化コストを支払うことによってのみ SCC に入ることができます。 したがって、アクティブ化されたすべての SCC は、以前にアクティブ化された SCC から到達するか、手動で開始されます。 

実行可能フロー制約により、すべての SCC が 1 つのアクティベーションを受け取ることが保証されます。 このようなすべてのソリューションの中で、最小コスト目標により、手動アクティベーションの数が最小限に抑えられます。 したがって、結果として得られる値は、まさに最初に配布されたプランの最小数になります。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

INF = 10 ** 9
TAG = 100000

class Edge:
    __slots__ = ("to", "cap", "cost", "rev")

    def __init__(self, to, cap, cost, rev):
        self.to = to
        self.cap = cap
        self.cost = cost
        self.rev = rev

class MinCostMaxFlow:
    def __init__(self, n):
        self.n = n
        self.g = [[] for _ in range(n)]

    def add_edge(self, u, v, cap, cost):
        a = Edge(v, cap, cost, None)
        b = Edge(u, 0, -cost, None)
        a.rev = len(self.g[v])
        b.rev = len(self.g[u])
        self.g[u].append(a)
        self.g[v].append(b)

    def min_cost_flow(self, s, t):
        flow = 0
        cost = 0

        while True:
            dist = [INF] * self.n
            inq = [False] * self.n
            pv = [-1] * self.n
            pe = [-1] * self.n

            dist[s] = 0
            q = deque([s])
            inq[s] = True

            while q:
                v = q.popleft()
                inq[v] = False

                for i, e in enumerate(self.g[v]):
                    if e.cap > 0 and dist[e.to] > dist[v] + e.cost:
                        dist[e.to] = dist[v] + e.cost
                        pv[e.to] = v
                        pe[e.to] = i
                        if not inq[e.to]:
                            inq[e.to] = True
                            q.append(e.to)

            if dist[t] == INF:
                break

            add = INF
            v = t
            while v != s:
                e = self.g[pv[v]][pe[v]]
                add = min(add, e.cap)
                v = pv[v]

            v = t
            while v != s:
                e = self.g[pv[v]][pe[v]]
                e.cap -= add
                self.g[v][e.rev].cap += add
                v = pv[v]

            flow += add
            cost += add * dist[t]

        return flow, cost

def solve():
    t = int(input())

    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))

        g = [[] for _ in range(n)]
        edges = []

        for _ in range(m):
            u, v = map(int, input().split())
            u -= 1
            v -= 1
            g[u].append(v)
            edges.append((u, v))

        dfn = [0] * n
        low = [0] * n
        in_st = [False] * n
        st = []
        comp = [-1] * n
        timer = 0
        comps = 0

        sys.setrecursionlimit(10000)

        def tarjan(v):
            nonlocal timer, comps

            timer += 1
            dfn[v] = low[v] = timer
            st.append(v)
            in_st[v] = True

            for to in g[v]:
                if not dfn[to]:
                    tarjan(to)
                    low[v] = min(low[v], low[to])
                elif in_st[to]:
                    low[v] = min(low[v], dfn[to])

            if low[v] == dfn[v]:
                while True:
                    x = st.pop()
                    in_st[x] = False
                    comp[x] = comps
                    if x == v:
                        break
                comps += 1

        for i in range(n):
            if not dfn[i]:
                tarjan(i)

        k = comps
        b = [0] * k

        for i in range(n):
            b[comp[i]] += a[i]

        S = 3 * k
        T = S + 1
        SS = T + 1
        TT = SS + 1

        mcmf = MinCostMaxFlow(TT + 1)

        mcmf.add_edge(T, S, INF, 0)

        for u in range(k):
            A = u
            B = u + k
            C = u + 2 * k

            mcmf.add_edge(S, A, b[u], 0)
            mcmf.add_edge(A, B, 1, 1)
            mcmf.add_edge(A, C, INF, 0)

            mcmf.add_edge(B, C, 1, -TAG)
            mcmf.add_edge(B, C, INF, 0)

            mcmf.add_edge(C, T, INF, 0)

            mcmf.add_edge(SS, C, 1, 0)
            mcmf.add_edge(B, TT, 1, 0)

        for u, v in edges:
            cu = comp[u]
            cv = comp[v]
            if cu != cv:
                mcmf.add_edge(cu + 2 * k, cv + k, INF, 0)

        flow, cost = mcmf.min_cost_flow(SS, TT)

        if flow != k:
            print(-1)
        else:
            ans = cost + k * TAG
            print(ans)

if __name__ == "__main__":
    solve()
```最初の部分では SCC を計算し、元のグラフをその凝縮 DAG で置き換えます。 アクティブ化がコンポーネント全体に即座に広がるため、SCC 内のすべてのメッセンジャー数がマージされます。 

フローの構築は上記のモデルに従います。 すべての SCC の 3 ノード ガジェットが重要な部分です。 同時にアクティブ化を強制し、メッセンジャーの作成を制限し、手動アクティブ化が使用される場合にのみコストを請求します。 

実現可能性のチェックは、SCC ごとに 1 つのアクティベーション ユニットを要求することによって実行されます。 結果の最大フローが SCC の数より小さい場合、一部の SCC は通知されず、答えは次のようになります。`-1`。 

大きな負の報酬エッジは慎重に使用する必要があります。 その唯一の目的は、可能な限りオプティマイザに強制的に SCC をアクティブにすることです。 フローが計算された後、足し戻します`K * TAG`本当の客観的価値を回復します。

1 2
2 3
3 1
```すべての頂点は 1 つの SCC に属します。 圧縮されたグラフには単一のノードがあり、`b=1`。 1 回の手動アクティブ化が SCC に入り、アクティブ化され、すぐに SCC 全体に通知されます。 答えは`1`。
