 ## 解決策
 ## 問題の理解

 次の 2 行行列が与えられます。`n`列。各セルには整数が含まれます。 列全体を何度でも交換できます。つまり、列内の両方の要素が一緒に移動します。 スワップを実行した後、左上のセルからパスを選択する必要があります`(1,1)`右下のセルへ`(2,n)`。 パスは右または下にのみ移動でき、その総コストはパス セル内の整数の合計になります。 目標は、このコストを最大化することです。 

最初の行と 2 番目の行には、負の数、ゼロ、または正の数を含めることができます。 この制約により、すべてのテスト ケースで合計で最大 5000 列が許可されます。つまり、テスト ケースあたりの複雑さが O(n²) を超えるアルゴリズムは遅すぎる可能性があります。 

エッジ ケースには、パスが即座に強制的に引き下げられる単一列の行列や、すべての数値が負である行列が含まれるため、最小の負のパスを選択することが重要になります。 不用意な解決策は、列を交換すると要素の順序を変更してより適切なパスを生成できること、またはパスには列シーケンスのある時点で 1 つだけ下への移動が含まれている必要があることを無視する可能性があります。 

## アプローチ

 ブルートフォース手法では、列の考えられるすべての置換を試してから、各置換に対する最適なパスを計算します。 それぞれの順列には、`n!`可能性があり、順列ごとにパスの計算は O(n) です。 これはすぐに手に負えなくなります`n = 10`。 

重要な点は、列の交換が完全に柔軟であるということです。つまり、列を好きなように並べることができます。 パスは常に次から始まります`(1,1)`そしてで終わります`(2,n)`。 右または下に移動する必要があります。これは、最初の行から 2 番目の行まで 1 回の「ターン」があることを意味します。 これにより、問題は、上の行から下の行への遷移がどの列で発生するかを決定することに変わります。 

「分割」ポイントを定義すると`k`、パスが行 1 から行 2 に移動する場合、最適なパスの合計は次のようになります。 

- 1列目からk列までの最初の行の合計
 - 2行目のk列からn列までの合計

 列の交換により列を任意に並べ替えることができるため、このパスを最大化する位置に最大の合計を配置してみることができます。 具体的には、最初の行のプレフィックスの合計と 2 番目の行のサフィックスの合計を事前計算し、テスト ケースごとに O(n) で各分割ポイントの合計コストを効率的に計算できます。 

重要な洞察は、最大パスは列を特定の順序で再配置した後の分割ポイントの選択に対応しているということです。つまり、上の行にとって「より良い」列は前に配置され、下の行に「より良い」列は後に配置されます。 これにより、貪欲な線形パスで最大値を計算できるようになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n!・n) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る`t`。 
2. 各テスト ケースについて、次の内容を読んでください。`n`そしてその2列は`a[0]`そして`a[1]`。 
3. 最初の行のプレフィックス合計を事前計算します。`prefix_top[i] = a[0][0] + ... + a[0][i]`。 
4. 2 行目のサフィックスの合計を事前計算する`suffix_bottom[i] = a[1][i] + ... + a[1][n-1]`。 
5.初期化`max_cost`負の無限大まで。 
6. 考えられるすべての分割点を反復処理します。`i`から`0`に`n-1`:

 - コンピューティング`current_cost = prefix_top[i] + suffix_bottom[i]`。 
- アップデート`max_cost`もし`current_cost`の方が大きいです。 
7. 印刷`max_cost`テストケースごとに。 

**機能する理由:** プレフィックスとサフィックスの合計は、分割までの最初の行と分割後の 2 番目の行の考えられるすべての寄与をキャプチャします。 列のスワップを使用すると、任意の列を任意のインデックスに配置できるため、各分割で独立して合計を最大化できます。 これにより、グローバル最大値が見つかることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    top = list(map(int, input().split()))
    bottom = list(map(int, input().split()))
    
    prefix_top = [0]*n
    suffix_bottom = [0]*n
    
    prefix_top[0] = top[0]
    for i in range(1, n):
        prefix_top[i] = prefix_top[i-1] + top[i]
    
    suffix_bottom[-1] = bottom[-1]
    for i in range(n-2, -1, -1):
        suffix_bottom[i] = suffix_bottom[i+1] + bottom[i]
    
    max_cost = -10**18
    for i in range(n):
        current_cost = prefix_top[i] + suffix_bottom[i]
        if current_cost > max_cost:
            max_cost = current_cost
    print(max_cost)
```プレフィックスの合計は、分割のすべての最上行の寄与を効率的に累積し、サフィックスの合計は最下行の寄与を累積します。 すべての分割点を反復処理することで、パス内のすべての可能な「ターン」をカバーします。 大きなマイナスのイニシャルを使用する`max_cost`負の数を正しく処理します。
