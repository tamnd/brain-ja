 ## 解決策
 ## 問題の理解

 私たちには指示された構造が与えられています`n`スキー場を表現したオブジェ。 それぞれのオブジェクトは山またはホテルです。 すべてのオブジェクトには、別のオブジェクトにつながる発信スキー トラックが最大 1 つありますが、ホテルには発信トラックがまったくありません。 これは、各ノードの出次数が最大 1 つであり、すべてのエッジが「次の」ノードを指し、最終的にホテルで終了する有向チェーンのコレクションを形成することを意味します。 

タスクは、ある山から始まり、ホテルで終わるまでスキー場に沿って段階的に進む有効なパスを選択することです。 このようなすべての有効なチェーンの中で、訪問したノードの数の点で最も長いチェーンを出力する必要があります。 

この構造は、各ノードが最大 1 つの発信エッジを持つことを暗示しているため、どの開始点からでも一意の前方ウォークが存在します。 本当の決断は、到達可能な最も深いホテルにつながる最適な出発山を選択することです。 

と`n ≤ 10^5`、どのような解も線形または線形に近いものでなければなりません。 すべての開始ノードを試してウォークをシミュレートする二次アプローチは、次のように劣化する可能性があります。`O(n^2)`長いチェーンでは遅すぎます。 グラフは実質的に有向チェーンのフォレストであるため、動的プログラミングまたはメモ化された走査ソリューションを期待する必要があります。`O(n)`。 

結果をキャッシュせずにすべての山から開始しようとすると、微妙な問題が発生します。 多くの開始点は長いサフィックスを共有する可能性があり、それらを繰り返し再計算すると、同じチェーンを繰り返し走査することになります。 

もう 1 つのエッジ ケースは、一部のノードが孤立したホテル (発信エッジも着信エッジも存在しない) である場合です。 このようなノードは長さ 1 の有効なパスを形成し、最大値で考慮する必要があります。 

## アプローチ

 強引なアイデアは、すべての山を出発点として扱い、途中の歩数を数えながらホテルに到着するまでその端をたどるというものです。 これは正しいです。グラフには前方への分岐がないため、各開始点は正確に 1 つのパスを定義します。 ただし、最悪の場合、グラフは長さの異なる単一の長いチェーンになります。`n`。 最初のノードから開始して横断します`n`2 番目のノードから開始して横断します`n-1`、など、おおよその結果につながります。`n + (n-1) + ... + 1 = O(n^2)`操作。 

重要な観察は、どのノードにも出力エッジが最大 1 つあるため、この構造は後方にマージするが前方に分岐することのない、互いに素なチェーンのコレクションであるということです。 これにより、メモ化を使用してホテルで終わるチェーンの長さをノードごとに計算できるようになります。 ノードからの長さがわかったら、再計算する必要はありません。 次のノードを最適なパスに保存することもできるため、再構築が簡単になります。 

これにより、問題は、発信次数 ≤ 1 の場合の関数グラフ内のサフィックスからホテルまでの最長距離を計算することに変わります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | 遅すぎる |
 | 最適 (関数グラフ上の DP) | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各ノードは、最大 1 つの発信エッジを持つものとしてモデル化されます。 すべてのノードについて、ターミナル ホテルに到達するまで出力エッジを繰り返したどることによって得られるパスの長さを計算します。 

1. 配列から暗黙的に送信隣接関係を構築します。`a`、 どこ`a[i]`次のノードまたはゼロです。 これにより、ノードごとに 1 つの後続者が与えられます。 
2. メモ化配列を維持する`dp[v]`から始まる最大パス長を保存します`v`そして`next[v]`再構築のためのポインタ。 また、再計算を避けるために、ノードがすでに計算されているかどうかも追跡します。 
3. 各ノードについて`v`すでに計算されている場合はスキップします。 それ以外の場合は、計算されたノードに到達するか、出力エッジのない終端ノードに到達するまで前方に歩いてチェーンの長さを計算します。 
4. チェーンの終端 (ホテルまたは発信エッジのないノード) に到達したら、それに基本値を割り当てます。`1`それ自体で長さのパスを形成するためです。 
5. 次に、通過したパスに沿って値を逆方向に伝播し、代入します。`dp[u] = 1 + dp[a[u]]`そして設定`next[u] = a[u]`。 これにより、各ノードがそのサフィックス チェーンの長さを確実に認識できるようになります。 
6. すべての dp 値を計算した後、すべての山の中から最大化する開始ノードを選択します。`dp[v]`。 
7. 最後に、次の手順を繰り返してパスを再構築します。`next[]`終了までのポインタ。 

重要な設計上の選択は、DP 伝播中に次のポインタを保存することです。これにより、再計算せずに正確な最大チェーンを再構築できるようになります。 

### なぜ効果があるのか

 各ノードには固有の順方向パスがあるため、その dp 値は次のノードにのみ依存します。 これにより、機能の依存関係が定義されます。 dp 値をシンクバックワードから解決することにより、すべてのノードの値が 1 回だけ固定されます。 すべてのエッジはメモ化中に最大 1 回処理されるため、矛盾した状態が発生することはなく、最終的に選択された開始点によって必然的にグローバルに最も長い有効なチェーンが生成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    typ = list(map(int, input().split()))
    a = list(map(int, input().split()))

    dp = [0] * (n + 1)
    nxt = [0] * (n + 1)
    vis = [False] * (n + 1)

    sys.setrecursionlimit(10**7)

    def compute(v):
        if vis[v]:
            return dp[v]

        path = []
        cur = v

        while cur != 0 and not vis[cur]:
            path.append(cur)
            cur = a[cur]

        if cur == 0:
            dp[cur] = 0

        for node in reversed(path):
            if a[node] == 0:
                dp[node] = 1
                nxt[node] = 0
            else:
                dp[node] = 1 + dp[a[node]]
                nxt[node] = a[node]
            vis[node] = True

        return dp[v]

    for i in range(1, n + 1):
        if not vis[i]:
            compute(i)

    start = 1
    best = -1
    for i in range(1, n + 1):
        if typ[i - 1] == 0:
            continue
        if dp[i] > best:
            best = dp[i]
            start = i

    path = []
    cur = start
    while cur != 0:
        path.append(cur)
        cur = nxt[cur]

    print(len(path))
    print(*path)

if __name__ == "__main__":
    solve()
```この実装では、まずパス圧縮スタイルのトラバーサルを使用してすべてのノードの dp 値を構築します。 再帰の代わりに、反復的に前方に進み、チェーンを保存してから、dp 値を後方に割り当てます。 これにより、長いチェーンでの再帰の深さの問題が回避されます。 

の`typ`配列は開始点を選択するときにのみ使用され、確実に山から開始します。 ホテルは問題が最初のものを必要とするため除外されます。`k-1`ノードは山になり、最後のノードだけがホテルになります。 

再構成では、`nxt[]`、DP の伝播中に埋められました。 これにより、O(k) の再構築時間が保証されます。 

## 実用的な例

 ### 例 1

 入力:```
5
0 0 0 0 1
0 1 2 3 4
```単一のチェーンがあります。`1 → 2 → 3 → 4 → 5`、5 はホテルです。 

| ステップ | ノード | 次へ | dp が割り当てられています |
 | --- | --- | --- | --- |
 | ビルド | 5 | 0 | dp[5]=1 |
 | ビルド | 4 | 5 | dp[4]=2 |
 | ビルド | 3 | 4 | dp[3]=3 |
 | ビルド | 2 | 3 | dp[2]=4 |
 | ビルド | 1 | 2 | dp[1]=5 |

 チェーンの最大長が 5 になるため、最適な開始山はノード 1 です。再構築されたパスは 1 → 2 → 3 → 4 → 5 に従い、正確であることが確認されます。 

### 例 2

 入力:```
4
0 0 1 1
0 3 0 0
```ここには 2 つのチェーンがあります。`2 → 3`そして`1`孤立していて、`3`そして`4`ホテルです。 

| ステップ | ノード | 次へ | DP |
 | --- | --- | --- | --- |
 | ビルド | 3 | 0 | dp[3]=1 |
 | ビルド | 2 | 3 | dp[2]=2 |
 | ビルド | 1 | 0 | dp[1]=1 |
 | ビルド | 4 | 0 | dp[4]=1 |

 最高の山はノード 2 で、パスを生成します。`2 → 3`。 これにより、アルゴリズムが複数のコンポーネントと分離されたノードを正しく処理していることが確認されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各ノードは DP 伝播中に最大 1 回アクセスされ、処理されます。 
| スペース | O(n) | dp、ネクスト ポインター、訪問追跡の配列 |
