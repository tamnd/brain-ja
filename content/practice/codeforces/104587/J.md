 ## 解決策
 ## 問題の理解

 標準的な 9 × 9 の数独グリッドが与えられます。 一部のセルにはすでに 1 から 9 までの数字が含まれていますが、空のセルはゼロで表されます。 課題は、バックトラックや高度なテクニックによって数独を完全に解くことではなく、非常に特殊な 2 つの人間流の推論ルールだけを繰り返しシミュレートすることです。 

最初のルールは、行、列、および 3 x 3 のブロック制約を考慮してセルに入力できる有効な数字が 1 つだけある場合、その数字をそこに配置する必要があることを示しています。 2 番目のルールは、行、列、またはブロック内で数字の可能な位置が 1 つしかない場合、その位置に配置する必要があるというものです。 

これ以上の進歩が不可能になるまで、これら 2 つのルールを繰り返し適用します。 このプロセスがグリッド全体を埋める場合、パズルは簡単として分類され、完成した数独が出力されます。 残りの空のセルで行き詰まった場合は、「簡単ではありません」と出力し、空のセルにドットを使用して部分的な状態を出力します。 

入力サイズは 9 x 9 に固定されているため、セルあたりの一定時間よりも多少高価なアルゴリズムでも許容されます。 これにより、漸近最適化に関する懸念が取り除かれ、演繹プロセスの正確さと慎重な状態更新に完全に焦点が移ります。 

微妙な失敗の主なケースは、停止が早すぎることに起因します。 安定するまでループせずに各ルールを 1 回だけ適用すると、1 つのセルを満たすと他の場所で新しい強制的な動きが可能になるという連鎖反応を見逃してしまいます。 

もう 1 つのよくある落とし穴は、制約の不適切な維持です。 たとえば、数字を配置した後、関連するセルの利用可能な候補を更新しないと、推定が失効します。 この問題の小さな例は、ブロックに数字を配置した後でのみ別のセルが強制される行に現れます。 伝播がないと、ソルバーはパズルが行き詰まっていると誤って判断します。 

## アプローチ

 強引な解釈は、数独を完全な制約充足問題として扱い、有効性を強制しながら空のセルで数字を再帰的に試すというバックトラック検索を試みることです。 これは正しいですが、2 つの決定論的推論ルールのみを許可するという問題の制限を完全に無視しています。 完全なバックトラッキングは指数関数的な可能性を探り、空のセルごとに最大 9 つの選択肢に分岐しますが、ここでは不要です。 

重要な観察は、これらのルールの下ではパズルの展開が単調であるということです。 各ステップはセルを埋めるか何も行わないかのいずれかであり、一度満たされるとセルは再び変更されません。 これは、固定点に到達するまで制約の伝播を繰り返すプロセスをシミュレートできることを意味します。 検索する代わりに、セルごとに有効な数字のセットを維持し、行、列、ブロックごとに、まだ不足している数字を追跡します。 セルまたは数字が強制されるたびに、更新をキューに入れ、その結果を伝播します。 

これにより、問題は固定サイズのグリッド上の制約伝播システムに変わり、安定するまで更新がカスケードされます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースバックトラッキング | O(9^(空のセル)) | お(1) | 遅すぎる |
 | 制約の伝播 (2 つのルール) | O(1) 償却 | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 各行、各列、および各 3 x 3 ブロックで欠落している桁という 3 つの制約セットを使用して、数独の状態をモデル化します。 また、現在の値のグリッドと強制割り当てのキューも維持します。 

### 1. 状態を初期化する

 グリッドを読み取り、対応する行、列、ブロックのセットから既に配置されているすべての数字を削除します。 これにより、最初の有効な候補空間が確立されます。 

### 2. 初期強制セルを計算する

すべての空のセルについて、その行、列、ブロックから許可された数字の交差を計算します。 正確に 1 桁が可能であれば、それを強制としてマークし、キューにプッシュします。 これは、単一値ルールに直接対応します。 

### 3. 数字の一意の配置を計算する

 各行、列、ブロックについて、欠落している数字をそれぞれチェックし、それを収容できる桁数を数えます。 カウントがちょうど 1 の場合、その配置もキューに入れます。 これにより、一意の場所ルールが実装されます。 

### 4. キューを反復的に処理する

 キューが空ではない間に、強制割り当てをポップし、数字を配置し、制約を更新します。 影響を受けるすべての行、列、ブロックについて、この配置によって新しい強制的な単一の候補が作成されるのか、それとも数字の新しい一意の配置が作成されるのかが再計算されます。 

各割り当てによって制約構造が変更され、新しい強制移動は更新後にのみ表示されるため、この伝達は不可欠です。 

### 5. 安定するまで繰り返します

 新しい強制的な動きがなくなるまで続けます。 その時点で、グリッドが完全に埋まっているか、許可されたルールを使用して推定できない空のセルがいくつか残っています。 

### なぜ効果があるのか

 このプロセスでは、キーの不変条件が維持されます。つまり、数字を割り当てるたびに、その時点で 2 つのルールの少なくとも 1 つの下で、それが唯一の有効な選択肢になります。 割り当ては隣接する可能性を取り除くだけであり、新しい可能性を導入することはないため、システムは単調です。 したがって、ルールが適用されなくなると、許可されたロジックの下ではそれ以上の推論は不可能になり、状態はこれらの制約の下で最大になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def block_id(r, c):
    return (r // 3) * 3 + (c // 3)

def solve():
    grid = []
    for _ in range(9):
        grid.append(list(map(int, input().split())))

    row_used = [set() for _ in range(9)]
    col_used = [set() for _ in range(9)]
    blk_used = [set() for _ in range(9)]

    empty = []
    for r in range(9):
        for c in range(9):
            v = grid[r][c]
            if v:
                row_used[r].add(v)
                col_used[c].add(v)
                blk_used[block_id(r, c)].add(v)
            else:
                empty.append((r, c))

    digits = set(range(1, 10))

    changed = True
    while changed:
        changed = False

        # Single Value Rule
        singles = []
        for r, c in empty:
            if grid[r][c] != 0:
                continue
            b = block_id(r, c)
            candidates = digits - row_used[r] - col_used[c] - blk_used[b]
            if len(candidates) == 1:
                val = next(iter(candidates))
                singles.append((r, c, val))

        # Unique Location Rule
        uniques = []

        for r in range(9):
            for d in digits - row_used[r]:
                pos = []
                for c in range(9):
                    if grid[r][c] == 0:
                        b = block_id(r, c)
                        if d not in col_used[c] and d not in blk_used[b]:
                            pos.append((r, c))
                if len(pos) == 1:
                    uniques.append((pos[0][0], pos[0][1], d))

        for c in range(9):
            for d in digits - col_used[c]:
                pos = []
                for r in range(9):
                    if grid[r][c] == 0:
                        b = block_id(r, c)
                        if d not in row_used[r] and d not in blk_used[b]:
                            pos.append((r, c))
                if len(pos) == 1:
                    uniques.append((pos[0][0], pos[0][1], d))

        for b in range(9):
            br, bc = (b // 3) * 3, (b % 3) * 3
            for d in digits - blk_used[b]:
                pos = []
                for i in range(9):
                    r, c = br + i // 3, bc + i % 3
                    if grid[r][c] == 0:
                        if d not in row_used[r] and d not in col_used[c]:
                            pos.append((r, c))
                if len(pos) == 1:
                    uniques.append((pos[0][0], pos[0][1], d))

        all_moves = singles + uniques

        for r, c, v in all_moves:
            if grid[r][c] == 0:
                grid[r][c] = v
                row_used[r].add(v)
                col_used[c].add(v)
                blk_used[block_id(r, c)].add(v)
                changed = True

    solved = all(grid[r][c] != 0 for r in range(9) for c in range(9))

    if solved:
        print("Easy")
    else:
        print("Not easy")

    for r in range(9):
        line = []
        for c in range(9):
            line.append(str(grid[r][c]) if grid[r][c] != 0 else ".")
        print(" ".join(line))

if __name__ == "__main__":
    solve()
```実装では、行、列、およびブロック制約の明示的なセットが保持されるため、候補チェックは一定時間のままになります。 メイン ループは両方のルール タイプを繰り返しスキャンします。 終了条件は、反復中に何らかの変更が発生したかどうかだけであり、固定点に確実に到達するかどうかです。 

実装の微妙な点は、すべての候補を段階的に更新するのではなく、反復ごとに再計算することです。 サイズが 9 x 9 に固定されている場合、これはより単純であり、一貫性のバグを回避できます。 

## 実用的な例

 ### 例 1 (完全に解決可能)

 初期の強制配置が存在する部分的に埋められたグリッドから開始します。 初期化後、一部のセルにはすぐに有効な候補が 1 つだけあります。 これらは単一値ルールを介して挿入されます。 

| 反復 | アクションの種類 | セルが満たされています | 理由 |
 | --- | --- | --- | --- |
 | 1 | 単一の値 | (0,2)=4 | 行/列/ブロック内の有効な数字のみ |
 | 2 | ユニークなロケーション | (1,4)=6 | 6 行にのみ配置 |
 | 3 | 単一の値 | (4,4)=9 | 制約が軽減される |
 | 4 | 最終的な塗りつぶし | 残りのすべてのセル | カスケードが完了します |

 数回の伝播ラウンドの後、すべての行と列が完全に拘束され、グリッドが完成します。 これは、ローカルな強制移動がどのようにグローバルに伝播するかを示しています。 

### 例 2 (スタック状態)

 初期推定が存在するものの、すべてのセルが完全には決定されない、より厳密なグリッドを検討します。 

| 反復 | アクションの種類 | セルが塗りつぶされています | 残りの空席 |
 | --- | --- | --- | --- |
 | 1 | シングル + ユニーク | いくつか | たくさん |
 | 2 | シングル + ユニーク | さらにいくつか | 削減 |
 | 3 | なし | なし | 変更なし |

 反復 3 では、行、列、またはブロック内で一意の候補を持つセルはなく、一意の位置を持つ数字もありません。 空のセルが残っている場合でも、システムは安定します。 

これにより、アルゴリズムが誤って推測を強制するのではなく、演繹力が枯渇したときを正しく識別していることが確認されます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、既に完成した数独がルール上無効であるか、減点の必要がない場合です。 アルゴリズムは引き続きループに入りますが、単一または一意の配置が見つからないため、すぐに停止し、実装に応じて Not easy または Easy を出力します。 演繹ルールを超えて数独の妥当性は検証されないため、この動作は問題の定義と一致しています。 

もう 1 つのエッジ ケースは、一連の更新の後にのみ移動が有効になるグリッドです。 たとえば、最初はセルに 2 つの候補がある可能性がありますが、一意の場所ルールによって関連するブロック セルを埋めると、強制されるようになります。 外側のループが繰り返されることで、各反復で制約が最初から再計算され、カスケードの欠落がないことが保証されるため、このような遅延した強制が最終的に発見されることが保証されます。
