 ## 解決策
 ## 問題の理解

 最大でも 10 × 10 の非常に小さな大文字のグリッドが与えられ、セルからセルへと歩いて特定の単語をこのグリッド上でたどることができるかどうかを知りたいと考えています。 ウォークは任意のセルから開始され、隣接するセル上を直線ステップで移動します。 重要な点は、単語の形成中に、パスの方向変更が制限された回数 (ちょうど k 回) だけ許可されることです。 

パスの各ステップは単語の 1 文字を消費します。 連続する位置は異なるセルでなければならないため、同じセルに留まったり、すぐに再訪問したりすることはできません。 動きの方向が 1 つのステップから次のステップに変わるたびに「ねじれ」がカウントされるため、方向は重要です。 

出力は単純な実現可能性チェックです。正確に k 方向の変更を使用しながら単語全体を綴るパスが存在するかどうかです。 

制約は空間次元が非常に小さく、r と c は最大 10、語長は最大 100 です。これにより、大規模な事前計算や重いグローバル構造を必要とするものは即座に除外されます。 代わりに、この構造は、グリッドの合計サイズがわずか 100 セルであり、方向の変更が単語の長さによって制限されるため、慎重に設計すれば州全体の検索が実行可能であることを示唆しています。 

最も微妙な制約は、正確なキンク数です。 多くの自然な DFS ソリューションでは、単語が形成できるかどうかのみを尋ねますが、ここではパスが正確なターン数と一致する必要があります。 これにより、無視できない状態の側面が生じます。 

いくつかの特殊なケースが自然に現れます。 

長さ 1 のワードは動きがないため興味深いため、キンクの数はゼロでなければなりません。 k > 0 であれば、即座に答えは不可能になります。 

もう 1 つのケースは、語長が 2 の場合です。隣接するセルに 2 つの文字が存在する場合でも、方向の変化は発生しないため、ねじれを数えようとしても無駄です。 したがって、k は再びゼロでなければなりません。 

最後に、文字が繰り返されるグリッドでは、非連続ステップでセルを再利用するという意味で、何度も再訪問する可能性があります。 素朴な解釈では、再利用を完全に禁止すると誤って判断される可能性がありますが、問題は連続するステップで同じセルに留まることを禁止するだけです。 

## アプローチ

 ブルートフォースソリューションでは、単語を綴るすべての可能なパスが試行されます。 最初の文字に一致するすべての開始セルから、各ステップで 4 つの方向すべてを再帰的に試行し、単語内の現在のインデックスとこれまでに使用された方向変更の数を追跡します。 あるセルから別のセルに移動するときは常に、同じ方向を維持するか、方向が変わった場合にはキンク数を増やします。 

最悪の場合、各ステップで最大 4 方向に分岐し、最大 100 の長さのパスを探索します。これにより理論上の上限は 4^100 に近くなりますが、これは枝刈りを行っても完全に実行不可能です。 

重要な観察は、グリッドが小さく、単語の長さが中程度であるため、動的検索で各位置を状態として扱うことができるということです。 本質的な構造は、問題が階層化されたグラフでの経路探索タスクであるということです。このタスクでは、各状態が単語内の位置とインデックスだけでなく、その状態に到達するために使用された方向と、これまでに使用されたターン数も記憶する必要があります。 

これにより、サイズ r × c × len(word) × 4 × k の状態空間にわたる DFS または BFS が得られます。 r と c は最大 10、k は最大 100 であるため、これはメモ化するには十分小さいです。 

特定の状態で単語を完成できるかどうかをキャッシュすることで、部分問題の再計算を回避します。 状態は、(row、col、index、direction、k_used)によって一意に決まります。 動きがキンクとしてカウントされるかどうかは方向によって決まるため、方向は重要です。 

遷移ルール​​は単純です。ある状態から、隣接するすべてのセルを試します。 同じ方向を維持すると、キンク数は変わりません。 方向を変えると、k_used がインクリメントされます。

これにより、指数関数的なパスの列挙が制御された状態の探索に変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(4^L) | O(L) | 遅すぎる |
 | 状態空間上のメモ化された DFS | O(r・c・L・4・k) | O(r・c・L・4・k) | 承認済み |

 ## アルゴリズムのチュートリアル

 この検索は、状態を超えたメモ化を伴う深さ優先のトラバースとして処理されます。 

1. グリッド セルにいること、単語の接頭辞と一致すること、特定の方向から到着したこと、およびこれまでに特定の数のキンクを使用したことを表す再帰関数を定義します。 この関数は、単語の残りを完成できるかどうかを返します。 
2. 最初の文字に一致する各セルから、4 方向すべてに動きを開始してみます。 最初の動きがキンクとしてカウントされないように、開始方向を未定義として扱います。 
3. 各再帰状態について、単語内のすべての文字が一致した場合は、すぐに成功を返します。 これ以上の移動は必要ないため、これが基本ケースです。 
4. 現在の位置から、隣接するセルへの 4 つの可能な移動すべてを検討します。 まず、移動がグリッド内に留まることを確認します。 また、次のセルが単語内の次の文字と一致することも確認します。 
5. それぞれの動きについて、それがねじれを引き起こすかどうかを計算します。 以前の方向が未定義であるか、新しい方向と等しい場合、キンク数は変わりません。 それ以外の場合は、1 ずつ増加します。 
6. キンク カウントが k を超えた場合、その分岐は再び有効になることがないため、直ちにその分岐を破棄します。 
7. 繰り返しの設定によって再計算がトリガーされないように、各状態の結果をメモ化します。 

重要なデザイン選択は、方向が状態の一部であるということです。 これがないと、トランジションによってキンク数が増加するかどうかを正しく判断できません。 

### なぜ効果があるのか

 グリッドを通るすべての有効なパスは、この DFS 表現における 1 つの状態シーケンスに正確に対応します。 状態は、将来の実現可能性を評価するために必要なすべてを完全にエンコードします。位置は利用可能な動きを決定し、インデックスは残りのターゲット キャラクターを決定し、方向はターンが導入されるかどうかを決定し、キンク カウントは制約を追跡します。 

メモ化により、各状態が 1 回だけ評価されることが保証されます。 状態空間は有限で小さいため、再帰は終了し、重複することなく可能なすべての有効なパスをカバーします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

r, c = map(int, input().split())
grid = [input().split() for _ in range(r)]

k = int(input().strip())
word = input().strip()
n = len(word)

dirs = [(-1, 0), (1, 0), (0, -1), (0, 1)]

# memo: (x, y, idx, dir, k_used)
# dir: 0..3, or 4 = undefined
from functools import lru_cache

@lru_cache(None)
def dfs(x, y, idx, d, used):
    if used > k:
        return False
    if idx == n - 1:
        return True

    for nd, (dx, dy) in enumerate(dirs):
        nx, ny = x + dx, y + dy
        if not (0 <= nx < r and 0 <= ny < c):
            continue
        if grid[nx][ny] != word[idx + 1]:
            continue

        if d == 4 or d == nd:
            nused = used
        else:
            nused = used + 1

        if dfs(nx, ny, idx + 1, nd, nused):
            return True

    return False

ans = False

for i in range(r):
    for j in range(c):
        if grid[i][j] == word[0]:
            for d in range(5):
                if dfs(i, j, 0, d, 0):
                    ans = True
                    break
        if ans:
            break
    if ans:
        break

print("YES" if ans and k >= 0 else "NO")
```グリッドは、O(1) アクセスの文字の行列として保存されます。 DFS 関数は、位置、ワード内のインデックス、最後の方向、現在のキンク数を含む完全な状態をエンコードします。 未定義の方向に対する特別な値として 4 を選択すると、最初の動きが誤ってキンクとしてカウントされなくなります。 

単語はどこからでも始まる可能性があるため、外側のループは最初の文字と一致する可能な開始位置をすべて試します。 また、最初のステップで方向カウントにペナルティが与えられないように、初期の未定義の方向も許可します。 

剪定の様子`used > k`すでに制約に違反しているパスの探索を避けるため、これは重要です。 

## 実用的な例

 最初のサンプル グリッドと、ねじれが許可されている単語「JAVA」について考えてみましょう。 

「J」を含む任意のセルから開始します。 有効な開始セルを選択し、単語をトレースしようとするとします。 

| ステップ | ポジション | インデックス | 方向 | 使用済みキンクス | アクション |
 | --- | --- | --- | --- | --- | --- |
 | 1 | (J を開始) | 0 | 未定義 | 0 | 開始 |
 | 2 | 次のセル A | 1 | 右 | 0 | 移動 |
 | 3 | 次のセル V | 2 | 右下 | 1 | ターン |
 | 4 | 次のセル A | 3 | 右下 | 1 | 続ける |

 このトレースは、移動方向が変化した場合にのみ方向変化がカウントされ、単語がキンク制限内で完了できることを示しています。 

ここで、複数のターンを必要とする単語に対して k が小さすぎるという失敗例を考えてみましょう。 

| ステップ | ポジション | インデックス | 方向 | 使用済みキンクス | アクション |
 | --- | --- | --- | --- | --- | --- |
 | 1 | スタートP | 0 | 未定義 | 0 | 開始 |
 | 2 | 移動 | 1 | 右 | 0 | 移動 |
 | 3 | ターン | 2 | ダウン | 1 | ターン |
 | 4 | ターン | 3 | 左 | 2 | ターンが k を超えます |

 この状況では、キンク カウントが許容制限を超えると、再帰は直ちにプルーニングされ、パスは拒否されます。 

これらのトレースは、状態が空間移動と方向変化のアカウンティングの両方を正しくキャプチャしていることを確認します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(r・c・L・4・k) | 各状態は位置、インデックス、方向、およびキンク数によって定義され、それぞれが 1 回計算されます。 
| スペース | O(r・c・L・4・k) | メモ化テーブルはすべての状態の結果を保存します。 

グリッドは非常に小さく、ワード長は 100 で制限されているため、状態を完全に拡張しても、制限時間内で状態の数は管理可能なままです。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    sys.setrecursionlimit(10**7)

    r, c = map(int, input().split())
    grid = [input().split() for _ in range(r)]

    k = int(input().strip())
    word = input().strip()
    n = len(word)

    dirs = [(-1, 0), (1, 0), (0, -1), (0, 1)]
    from functools import lru_cache

    @lru_cache(None)
    def dfs(x, y, idx, d, used):
        if used > k:
            return False
        if idx == n - 1:
            return True

        for nd, (dx, dy) in enumerate(dirs):
            nx, ny = x + dx, y + dy
            if not (0 <= nx < r and 0 <= ny < c):
                continue
            if grid[nx][ny] != word[idx + 1]:
                continue

            nused = used if (d == 4 or d == nd) else used + 1
            if dfs(nx, ny, idx + 1, nd, nused):
                return True

        return False

    ans = False
    for i in range(r):
        for j in range(c):
            if grid[i][j] == word[0]:
                if dfs(i, j, 0, 4, 0):
                    ans = True
                    break
        if ans:
            break

    return "YES" if ans else "NO"

 ## 特殊なケース

 単一文字の単語は基本ケースを直接テストします。 DFS は、n から 1 を引いたものに等しい idx に即座に到達し、移動や方向を考慮せずに、一致するセルから成功を返します。 

利用可能なグリッド接続よりも長いワードは、早期の枝刈りをテストします。 k が大きい場合でも、隣接する一致する遷移が存在しない場合、再帰は失敗します。これは、キンクの許容によって人為的なパスが作成されないことを示しています。 

k がゼロに等しい場合、直線パスが強制されます。 DFS は依然として全方向を探索しますが、方向が変更されるとすぐに分岐が無効になるため、完全に真っ直ぐな埋め込みのみが生き残ります。 

文字が繰り返される高密度のグリッドでは、即時セルの制約が尊重される限り、値の再訪が許可されます。 位置は常に状態の一部であるため、ステート マシンは、異なる位置での値の再訪と不正な即時反復を正しく区別します。
