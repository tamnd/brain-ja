 ## 解決策
 ## 問題の理解

 私たちは、親から子のリストを通じて間接的に説明される、根深い家族構造を与えられており、二人の人が系図的にどのように関係しているのかという質問に答えなければなりません。 

問題の核心は、ツリー内の 2 つのノードの関係が、最も低い共通の祖先とそこまでの距離のみに依存することです。 2 人の人物 A と B を選択した場合、最初にその最も近い共通の祖先 C を特定します。C から、A はある世代数下にあり、B はある世代下にあります。 これら 2 つの距離は、深さがどの程度不均一であるかに応じて、それらが兄弟であるか、ある程度のいとこであるか、または「除去」の数が多いいとこであるかを決定します。 

入力は、単一の根を持つツリーを直接与えるわけではありません。 代わりに、親子関係のいくつかの断片が提供されます。 これらのフラグメントは一緒になって、最大 100 個のノードを持つ 1 つの有効なツリーを形成します。 この小さな境界により、パフォーマンスを気にせずに各ノードから完全な祖先テーブルや BFS などの簡単な前処理を使用できるようになるため、重要です。 

重要な微妙な点は、根底にある距離は対称的であっても、関係は表現上は対称的ではないということです。 出力形式は、どのノードが表現の参照点とみなされるかによって異なります。また、ある人物が別の人物の直接の祖先であるという特殊なケースがあり、これにより文法構造が完全に変わります。 

ここで重要となるエッジ ケースは、一方のノードが他方のノードの祖先である場合、両方のノードが同じ深さにあるが兄弟ではない場合、およびそれらの一方が共通の祖先自体である場合です。 もう 1 つの微妙なケースは、「1st」、「2nd」、「3rd」などの序数の書式設定や、11、12、13 の特別な接尾辞規則であり、これにより単純な文字列の構築が崩れることがよくあります。 

## アプローチ

 各クエリに答える強引な方法は、ツリー内をルートまで繰り返し上向きに移動して両方のノードの祖先を計算し、最初の共通ノードを見つけることです。 ツリーのサイズは最大でも 100 なので、DFS を実行したり、親ポインターを保存して上向きに繰り返し歩いたりしてもコストはかかりません。 クエリごとに、親チェーンを再計算して比較することもできますが、それは冗長です。 

より構造化されたアプローチは、ツリー全体を 1 回前処理することです。 各ノードにはちょうど 1 つの親 (ルートを除く) があるため、親マップを構築し、入力フラグメントから隣接リストを構築することもできます。 次に、子として表示されないノードを見つけて、任意のノードをルートとして選択します。 そのルートから、BFS または DFS を使用して深さと直接の親ポインターを計算します。 

深さと親がわかったら、すべてのクエリは最小の共通祖先を見つけることになります。 n ≤ 100 の場合、より深いノードを段階的にリフトする単純な LCA でも十分ですが、完全な祖先テーブルを事前計算したり、単に親ポインターを保存して登ることもできます。 

LCA C を見つけた後、C から A および B までの距離 m および n を計算します。これら 2 つの値から、ステートメント内のルールを使用して関係カテゴリを直接決定します。 残りの作業は、文字列を正しくフォーマットすること、特に序数と特別な表現規則を処理することです。 

ブルートフォースに対する主な改善点は、クエリごとの祖先構造の再計算を回避できることです。 代わりに、1 回限りの O(n) コストを支払い、O(n) の最悪のケースで各クエリに応答します。これは十分に高速です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとのブルート フォース | O(n・p) | O(n) | 受け入れられます (小さな制約) |
 | 親経由の事前計算 + LCA | O(n + p・n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、親から子の記述からツリーを再構築します。 隣接リストと親マップの両方を保存します。 子として表示されないノードはすべてルートです。 

次に、ルートから DFS または BFS を実行して、各ノードの深さと親ポインターの 2 つの配列を計算します。

A と B の間のクエリに答えるために、A が B より深くないことを確認して正規化します。B より深い場合は、A がルートに近づくようにそれらを交換します。 

両方のノードが同じ深さになるまで B を上に持ち上げます。 これは、親ポインタを段階的にたどることによって行われます。 位置を合わせたら、同じノードで出会うまで両方を一緒に上に移動します。 そのノードは最下位の共通祖先 C です。 

m は深さ[A] − 深さ[C] として計算され、n は深さ[B] − 深さ[C] として計算されます。 

m が 0 の場合、A は B の祖先であり、n に応じて「子」、「孫」、または「曾孫」形式の表現を出力します。 m が n に等しい場合、n が 1 の場合は兄弟であり、そうでない場合は (n−1) 番目のいとこです。 m が n より小さい場合、定義から直接いとこと除去の公式を使用します。 

最後に、正しい文法規則を使用して、序数と「削除された回数」という単語をフォーマットします。 

### なぜ効果があるのか

 ツリー内のすべての関係は、最も低い共通の祖先と、そこまでの 2 つの距離によって一意に決定されます。 前処理により、これらの距離を確定的な時間で取得できることが保証されます。 LCA ステップでは、真に最も近い共有祖先を測定していることが保証されるため、計算された世代数は問題の正式な定義と正確に一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ordinal(x):
    if 10 <= x % 100 <= 20:
        suffix = "th"
    else:
        if x % 10 == 1:
            suffix = "st"
        elif x % 10 == 2:
            suffix = "nd"
        elif x % 10 == 3:
            suffix = "rd"
        else:
            suffix = "th"
    return f"{x}{suffix}"

def build_tree(t):
    children = {}
    parent = {}
    nodes = set()

    for _ in range(t):
        parts = input().split()
        s0 = parts[0]
        d = int(parts[1])
        kids = parts[2:]
        nodes.add(s0)
        children.setdefault(s0, [])
        for k in kids:
            children[s0].append(k)
            parent[k] = s0
            nodes.add(k)
    return children, parent, nodes

def lift(node, steps, parent):
    for _ in range(steps):
        node = parent[node]
    return node

def lca(a, b, parent, depth):
    if depth[a] > depth[b]:
        a, b = b, a
    while depth[b] > depth[a]:
        b = parent[b]
    while a != b:
        a = parent[a]
        b = parent[b]
    return a, b

def dfs(root, children, parent, depth):
    stack = [(root, None)]
    parent[root] = None
    depth[root] = 0

    while stack:
        u, p = stack.pop()
        for v in children.get(u, []):
            if v == p:
                continue
            parent[v] = u
            depth[v] = depth[u] + 1
            stack.append((v, u))

def solve():
    t, p = map(int, input().split())
    children, parent, nodes = build_tree(t)

    root = None
    for x in nodes:
        if x not in parent:
            root = x
            break

    depth = {}
    parent2 = {}
    dfs(root, children, parent2, depth)

    for _ in range(p):
        a, b = input().split()

        if depth[a] > depth[b]:
            a, b = b, a

        x, y = a, b
        while depth[y] > depth[x]:
            y = parent2[y]

        while x != y:
            x = parent2[x]
            y = parent2[y]

        l = x
        da = depth[a] - depth[l]
        db = depth[b] - depth[l]

        if da == 0:
            if db == 1:
                print(f"{a} is the child of {b}")
            elif db == 2:
                print(f"{a} is the grandchild of {b}")
            else:
                print(f"{a} is the great grandchild of {b}")
        elif da == db:
            if da == 1:
                print(f"{a} and {b} are siblings")
            else:
                print(f"{a} and {b} are {ordinal(da-1)} cousins")
        else:
            if da > db:
                a, b = b, a
                da, db = db, da
            c = da - 1
            r = db - da
            if c == 0:
                rel = "0th cousins"
            else:
                rel = f"{ordinal(c)} cousins"
            if r == 1:
                print(f"{a} and {b} are {rel}, 1 time removed")
            else:
                print(f"{a} and {b} are {rel}, {r} times removed")

solve()
```このソリューションでは、隣接リストを使用して完全なツリーを構築し、DFS を実行して親ポインターと深さを計算します。 各クエリは、最も低い共通の祖先が見つかるまでノードをリフティングし、距離を必要な関係形式に変換することによって解決されます。 

実装における主な微妙な点は、祖先のケースをいとこのケースとは別に正しく処理することです。 もう 1 つは、序数の書式設定が 10 代の例外に関する英語の規則に従っていることを確認することです。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、1 つのノードがまさにルートである場合です。 その場合、LCA はノード自体であり、深さの差によって他のノードが子、孫、またはより深い子孫であるかが直接決まります。 LCA が常に異なるものであると仮定する単純な実装では、このケースに誤ったラベルが付けられてしまいます。 

もう 1 つのエッジ ケースは、両方のノードが同じ親を共有する場合です。 これにより兄弟が生成され、深さの差がゼロであるがノードが同一ではない唯一のケースです。 アルゴリズムは、LCA の等価性と深さが等しいことにより、これを正しく検出します。 

最後の微妙なケースは、11、12、13 などの値の序数の書式設定です。この場合、接尾辞のルールが通常の最後の桁のロジックをオーバーライドします。 この実装では、「11 番目」のような誤った出力を避けるために、最後の 2 桁を明示的にチェックします。
