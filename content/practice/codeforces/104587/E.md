 ## 解決策
 ## 問題の理解

 英大文字、数字、スペース文字で構成される 37 文字の固定アルファベットが与えられます。 各文字には、0 ～ 36 の数値が決定的な順序で割り当てられます。A は 0 で始まり、Z は 25 まで、次に 0 ～ 9 の数字が 26 ～ 35 で、最後にスペースが 36 になります。 

入力は、サイズ n × n (n は最大 10) の正方行列と、その後に続く平文文字列を提供します。 暗号化プロセスでは、テキストを数値に変換し、サイズ n のブロックにグループ化し、モジュロ 37 算術で行列を使用して線形変換を適用します。 結果として得られる各ベクトルは文字に変換されて暗号文が生成されます。 

概念的には、問題は、入力文字列を小さな有限の整数リングにエンコードした後、入力文字列のチャンクに対して繰り返し適用される行列乗算です。 

n ≤ 10 という制約が重要な構造上の制限です。 これは、各変換が非常に小さく固定サイズであることを意味するため、ベクトルと行列を乗算するコストは約 100 回の演算で一定に制限されます。 主要な要素は入力文字列の長さであり、長くなる可能性がありますが、すべての文字はそのブロック内で独立して処理されます。 これにより、行列次元で超線形な処理を試みたり、非効率的に変換を再計算したりするアルゴリズムは即座に除外されます。 文字列に対する単純な線形スキャンで十分です。 

この設定では、いくつかの特殊なケースが自然に現れます。 1つ目はパディングです。 平文の長さが n で割り切れない場合は、残りの文字をスペースで埋める必要があります。 たとえば、n = 3 で平文が「ABCX」の場合、「A B C | X スペース space」をエンコードします。 パディングを忘れた不注意な実装では、最後の文字が削除されたり、不完全なベクトルが形成されたりして、不正確な暗号文の長さが生成されます。 

もう 1 つのエッジ ケースは、スペース文字自体であり、最高値 36 にマップされます。英数字のみを処理する単純な実装では、スペースでエラーが発生したり、インデックスが誤ってシフトされたりします。 たとえば、スペース マッピングを考慮せずに「A A」をエンコードすると、位置合わせが崩れ、出力が破損します。 

最後に、大きな平文文字列では、モジュラー演算を繰り返す際に注意が必要です。 値は小さいままですが、自動大きな整数を持たない言語では乗算を繰り返すとオーバーフローする可能性があります。 Python ではこれは問題になりませんが、他の言語ではすべての算術ステップでモジュロ リダクションを適用する必要があります。 

## アプローチ

 最も直接的なアプローチは、定義を文字通りシミュレートすることです。 各文字を数値に変換し、シーケンスをサイズ n のブロックに分割し、標準の行列ベクトル乗算を使用して各ブロックに行列を乗算し、各結果をモジュロ 37 で減算して、文字に戻します。 これは定義に正確に従っているため、正しいです。 

ブロックの場合、1 つの出力エントリを計算するには n 回の乗算と加算が必要で、ブロックごとに n 個の出力があります。 これにより、ブロックごとに n² 個の操作が行われます。 n ≤ 10 であるため、これはブロックあたり最大 100 回の操作であり、無視できる程度です。 長さ L の文字列に対して O(L · n²) の演算を実行します。これは小さな定数を使用して L 内で事実上線形です。 

マトリックスは変化せず、繰り返しのクエリやべき乗の要件がないため、この直接シミュレーションを超えた最適化の必要はありません。 重要な点は、変換が各ブロックに対してローカルであり、前のブロックに依存しないことです。

 | 直接シミュレーション | O(L · n²) | O(L) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### 1. 文字エンコーディングを構築する

文字から整数へのマッピング、およびその逆のマッピングを定義します。 各文字、数字、およびスペースには、0 ～ 36 の一意の値を割り当てる必要があります。この手順により、暗号化が純粋に整数に対して行われるようになります。 

### 2. マトリックスを読む

 n × n 行列を整数として保存します。 すべての演算は 37 を法とする線形変換であるため、前処理は必要ありません。 

### 3. 平文を数値形式に変換する

 文字列をスキャンし、各文字を対応する整数に変換します。 これにより、モジュラー算術空間でメッセージを表す値の配列が生成されます。 

### 4. 配列を n の倍数にパディングします。 

長さが n で割り切れない場合は、割り切れるまでスペースに対応する値を追加します。 これにより、すべてのブロックが完全であることが保証され、行列の乗算中の境界の問題が回避されます。 

### 5. 各ブロックを個別に処理する

 サイズ n の連続するブロックごとに、行列とベクトルの積を計算します。 各出力座標は、1 つの行列行とブロック ベクトルのドット積として、37 を法として計算されます。このステップでは、暗号化変換が適用されます。 

### 6. 結果を文字に変換します。 

すべてのブロックを処理した後、各数値をその文字表現にマッピングし直し、それらを最終的な暗号文に連結します。 

### なぜ効果があるのか

 各ブロックは、37 を法とする整数のリングに対する固定線形関数によって変換されます。行列の乗算は、入力ベクトルから出力ベクトルへの決定論的関数を定義します。 平文は互いに素なブロックに分割され、各ブロックは独立して変換されるため、全体的な変換はこれらの独立した線形マップを連結したものにすぎません。 ブロック間には相互作用がないため、正しさはモジュラー演算における単一の行列ベクトル乗算の正しさに帰着します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 37

# build mappings
chars = []
for c in range(ord('A'), ord('Z') + 1):
    chars.append(chr(c))
for c in range(ord('0'), ord('9') + 1):
    chars.append(chr(c))
chars.append(' ')

char_to_int = {ch: i for i, ch in enumerate(chars)}
int_to_char = {i: ch for i, ch in enumerate(chars)}

def main():
    n = int(input())
    mat = [list(map(int, input().split())) for _ in range(n)]
    s = input().rstrip('\n')

    vals = [char_to_int[ch] for ch in s]

    while len(vals) % n != 0:
        vals.append(char_to_int[' '])

    res = []

    for i in range(0, len(vals), n):
        block = vals[i:i+n]
        for r in range(n):
            acc = 0
            for c in range(n):
                acc += mat[r][c] * block[c]
            res.append(int_to_char[acc % MOD])

    sys.stdout.write(''.join(res))

if __name__ == "__main__":
    main()
```実装は、問題に必要な正確な文字エンコーディングを構築することから始まります。 これにより、数字とスペース文字に関するあいまいさが回避されます。 

行列のサイズは最大 10 × 10 であるため、行列は整数としてメモリに直接読み込まれます。プレーンテキストは整数のリストに変換され、長さが n で割り切れるまでスペース値が埋め込まれます。 これにより、固定サイズのブロックへのスライスが失敗しないことが保証されます。 

各ブロックは独立して処理されます。 ネストされたループ構造は意図的です。外側のループは出力行を反復し、内側のループはドット積を計算します。 モジュラー リダクションは、完全なドット積を合計した後にのみ適用されます。これは、Python の整数がオーバーフローしないため安全です。 

## 実用的な例

 ### 例 1

 n = 2、平文「AB」の小さな概念的なケースを考えます。 

| ステップ | ブロック | 計算 | 出力値 |
 | --- | --- | --- | --- |
 | 1 | [A、B] | 行ドット積 | [x, y] |

 A が 0 にマップされ、B が 1 にマップされ、行列が出力 1 と 2 を生成すると仮定します。逆変換後、2 文字の暗号文ブロックが得られます。 パディングが欠落している場合、最後のスペースが失われ、出力の長さが不正確になります。これは、パディングが不可欠である理由を示しています。 

### 例 2

 パディングが必要な場合は、n = 2 の「ABC」など、少し長い文字列を使用します。 

| ステップ | ブロック | 計算 | 出力値 |
 | --- | --- | --- | --- |
 | 1 | [A、B] | 行列変換 | [x, y] |
 | 2 | [C、スペース] | パディングされたブロック変換 | [p, q] |

 これは、最後の文字が単独で処理されるのではなく、パディング スペースと結合されて、一貫したブロック構造が保証されることを示しています。

 ## 特殊なケース

 パディングケースは最も重要な構造上のエッジケースです。 n = 3、平文「ABCX」を考えてみましょう。 エンコード後、4 つの値が得られます。 最後のブロックは[X,スペース,スペース]になります。 乗算中も、このパディングされたベクトルは完全に処理され、有効な暗号文セグメントが生成されます。 このアルゴリズムはブロック処理の前にスペース値を明示的に追加するため、部分的なブロックが解釈されることはありません。 

スペース文字自体も重要なケースです。 プレーンテキストにスペースが含まれている場合、スペースは 36 にマップされ、他のシンボルと同様に算術演算に参加します。 たとえば、[A、スペース、B] のようなブロックは [0、36、1] になります。 乗算ステップでは 36 を 37 を法とする通常の整数として扱うため、特別なケースは必要ありません。 

最後に、最小行列サイズ n = 1 は、文字ごとに適用される単純な 37 を法とするスカラー乗算に縮退します。 各ブロックには 1 つの値が含まれており、行列の乗算は 1 つの乗算ステップに削減されるため、同じループ構造によって自然に処理されます。
