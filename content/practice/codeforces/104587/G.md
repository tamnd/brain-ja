 ## 解決策
 ## 問題の理解

 私たちは、ラベル付けされたチームの進化するランキングを維持しています。$T_1$を通して$T_n$。 当初、ランキングはインデックスの昇順に固定されているため、$T_1$が最初であり、$T_n$最後です。 次に、一連の試合結果を処理します。各結果は、あるチームが別のチームに勝ったことを示します。 

各試合は、勝ったチームが現在、倒した負けたチームよりもランクが低い場合にのみランキングに影響します。 勝者がすでに上位にランクされている場合は、何も変わりません。 勝者のランクが低い場合は、影響を受けていないすべてのチームの相対的な順序を維持しながら、現在の位置から切り取って対戦相手の真上に再挿入することで、負けたチームのすぐ上に「昇格」します。 

したがって、このプロセスは、元のインデックスではなく、現在の位置の比較によって駆動される一連の安定したリスト挿入です。 出力は、すべての一致を時系列で処理した後の最終的な順序付けです。 

制約は小さく、$n \le 100$そして$m \le 100$。 これは、チーム数に対して 2 次または 3 次の動作を行うアルゴリズムはすべて安全であることを直ちに示唆しています。 パフォーマンスのボトルネックを心配することなく、配列の並べ替え操作を自由にシミュレートできます。 

複数の試合に同じペアが含まれる場合、または昇格が繰り返される場合に、微妙なエッジケースが発生します。 ランキングは動的であるため、最初の順位ではなく、試合時のチームの順位が重要になります。 

たとえば、最初に 3 つのチームがいるシナリオを考えてみましょう。$T_1, T_2, T_3$。 加工すれば$T_3$ビート$T_2$、 それから$T_3$上に移動します。 後でしたら$T_3$ビート$T_1$、2 番目の操作では、元の順序ではなく、更新された位置が使用されます。 初期インデックスのみを使用するソリューションはここで失敗します。 

もう 1 つの重要なエッジケースは、勝者がすでに敗者を上回っている場合です。 たとえば、現在の注文が$T_1, T_2, T_3$そして私たちは処理します$T_1$ビート$T_3$、指数がギャップを示唆しているにもかかわらず、何も変わりません。 条件は純粋に位置的なものです。 

## アプローチ

 直接シミュレーションするのは自然なことです。 ランキングを配列またはリストとして保持します。 試合ごとに、両チームの現在のインデックスを見つけます。 勝者がすでに敗者を上回っている場合は、何もしません。 それ以外の場合は、勝者を現在の位置から削除し、敗者の直前に挿入し、中間セグメントを 1 ステップ左に移動します。 

これは問題文に正確に従っているため、正しいです。 唯一の課題は、「セグメントを 1 つずつ移動する」操作をきれいに実装することです。 

ブルートフォースの複雑さは、位置の検索とリスト操作の実行から生じます。 チームのインデックスの各検索にはコストがかかります$O(n)$、挿入ごとに最大までシフトする必要があります。$O(n)$要素。 と$m$オペレーションの場合、総コストは$O(mn)$、最大でも$10^4$、簡単に制限内に収まります。 

バランスの取れたツリーやリンク リストなどの高度なデータ構造は必要ありません。$n$小さいです。 単純な配列と、チーム名をインデックスにマッピングする辞書 (または毎回インデックスを直接再計算) で十分です。 

重要な洞察は、ランキングがローカルのカット アンド インサート操作による並べ替えであるということです。 すべての操作は連続したセグメントにのみ影響し、内部順序が維持されるため、制約の下では直接シミュレーションがすでに最適化されています。

 ## アルゴリズムのチュートリアル

 ランキングを直接シミュレーションします。 

1. リストを初期化する`order`フォームにチームが含まれている`T1, T2, ..., Tn`。 これは常に現在のランキングを表します。 
2. 各試合でチームが$A$ビートチーム$B$、現在の位置を見つけます`order`。 リストをスキャンするか、維持されている場合はマッピングを使用します。 
3. の位置の場合$A$の位置より小さいです$B$、ランキングがすでに結果と一致しているため、何もしません。 
4. の位置の場合$A$の位置より大きいです$B$、 取り除く$A$現在の位置から。 
5.挿入$A$のインデックスで$B$。 これにより効果的に配置されます$A$真上$B$、介在するすべてのチームが 1 つずつ順位を下げます。 
6. すべての一致を順番に処理し続けます。 

微妙な点は、削除が挿入前に行われることです。そうしないと、インデックスが正しくシフトされません。 この操作は概念的にはカット アンド ペーストであり、交換やローカル調整ではありません。 

### なぜ効果があるのか

 ランキングは常にチームの順列であり、各操作では 1 つの新しい制約が強制されます。勝者は、以前は敗者が下位だった場合は、敗者のすぐ上に表示されなければなりません。 他のすべての相対順序は、それらを変更する追加の証拠が存在しないことを問題が明示的に示しているため、変更されません。 すべての操作ではルールに一致する単一のローカル修正のみが導入されるため、繰り返し適用すると時間が経っても正確さが維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n, m = map(int, input().split())
    order = ["T" + str(i) for i in range(1, n + 1)]

    for _ in range(m):
        a, b = input().split()

        ia = order.index(a)
        ib = order.index(b)

        if ia > ib:
            order.pop(ia)
            order.insert(ib, a)

    print(" ".join(order))

if __name__ == "__main__":
    main()
```実装はアルゴリズムにほぼそのまま従います。 リスト`order`現在のランキングを保存します。 各クエリは使用します`.index()`ポジションを見つけるためですが、これは許容されます。$n \le 100$。 条件`ia > ib`ランキングが試合結果と矛盾するケースを正確に捉えています。 

重要な実装の詳細は、挿入前に最初に勝者を削除することです。 挿入が先に行われた場合、インデックスが移動し、最終的な配置が不正確になります。 次のような文字列識別子の使用`"T3"`入力形式と直接一致し、解析のオーバーヘッドを回避します。

 ## 特殊なケース

 重要なエッジケースの 1 つは、チームが繰り返し勝利し、上昇を続ける場合です。 次の入力を考えてみましょう。```
4 3
T4 T3
T4 T2
T4 T1
```実行は次から始まります`T1 T2 T3 T4`。 

後`T4 beats T3`、ご注文となります`T1 T2 T4 T3`。 後`T4 beats T2`、になります。`T1 T4 T2 T3`。 後`T4 beats T1`、になります。`T4 T1 T2 T3`。 

すべてのステップで、アルゴリズムは次の要素を削除します。`T4`そして、他のすべての相対的な順序を維持しながら、それを対戦相手のすぐ上に再挿入します。 これは、グローバルな再計算を必要とせずに、複数の上向きの動きが正しく構成されていることを示しています。 

もう 1 つのエッジケースは、勝利が動きをトリガーしない場合です。 例えば：```
3 1
T1 T3
```初回注文は`T1 T2 T3`。 以来`T1`すでに上にあります`T3`、条件`ia > ib`失敗し、リストは変更されないままになります。 このアルゴリズムは不必要な変更を正確に回避し、無関係なセグメントの安定性を維持します。
