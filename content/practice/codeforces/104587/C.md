 ## 解決策
 ## 問題の理解

 入力内の各人は、正確に 1 つのオブジェクトを所有し、正確に 1 つのオブジェクトを必要とします。 私たちは各人をグラフ内の有向エッジとして考えることができます。つまり、現在所有しているオブジェクトから、必要なオブジェクトまでです。 すべてのオブジェクトは一意に所有され、一意に要求されるため、すべてのオブジェクトはソースとして 1 回、ターゲットとして 1 回だけ表示されます。 

有効な「数学的貿易チェーン」とは、最初の人が望んでいたオブジェクトが現在 2 人目によって所有され、2 人目の人が望んでいたオブジェクトが 3 人目によって所有される、という一連の人々のことです。 依存関係の連鎖をたどると、本質的には人々によって誘導された有向エッジに沿って歩いていることになります。 重要な制約は、このチェーンが一貫している場合にのみ取引が可能であるということであり、そのため構造が独立した有向サイクルになることが強制されます。 

このタスクは、これらの有向エッジによって形成される最長のサイクルを見つけて、その長さを関与する人の数で出力することになります。 少なくとも 2 の長さのサイクルが存在しない場合、答えは取引ができないということです。 

入力サイズは小さく、最大でも 100 人です。 これにより、単純なマッピングやトラバースを超えた重いグラフ機構の必要性が即座に排除されます。 テスト ケースごとに O(n²) または O(n) 個のソリューションさえあれば完全に十分です。 

微妙なケースは、マッピングが自己ループのみを形成する場合、つまり人がすでに持っているものを正確に求めている場合に発生します。 そのような人は貿易チェーンに貢献しません。 もう 1 つのエッジ ケースは、グラフがさまざまなサイズの複数の小さなサイクルに分解される場合です。この場合、単にサイクルの存在を検出するのではなく、最大のサイクルを正確に識別する必要があります。 

## アプローチ

 この問題によって引き起こされる構造は関数グラフです。すべてのノード (人) は、正確に 1 つの他のノード (目的のオブジェクトを所有する人) を指します。 オブジェクトの所有権は一意であるため、各ノードには 1 つの出力エッジと 1 つの入力エッジがあり、参加者全体に順列のような構造が形成されます。 

ブルートフォースアプローチでは、すべての人から開始して、繰り返しが検出されるまでチェーンを追跡し、サイクルの長さを記録しようとします。 各ウォークは決定的であるため、これはすでに最適に近い状態になっています。 ただし、不用意に実装すると、すべてのノードの走査が再開され、同じサイクルを繰り返し実行することになり、冗長な作業が発生する可能性があります。 最悪の場合、これは O(n²) になり、ここではまだ問題ありませんが、概念的には非効率です。 

重要な観察は、我々はばらばらのサイクルを扱っているということです。 各ノードは正確に 1 つのサイクルに属するため、ノードが一度訪問されると、そのサイクル全体がマークされ、再計算されることはありません。 これは、各サイクルを 1 回だけ抽出する単純な DFS のような、または訪問済みアレイのトラバーサルを示唆しています。 

したがって、すべてのノードを反復処理することができ、未訪問のノードが見つかるたびに、訪問済みのノードに戻るまでその出力エッジをたどり、有効な場合はサイクル長をカウントします。 答えはそのような最大の長さです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 各ノードからのブルート フォース ウォーク | O(n²) | O(n) | 承認済み |
 | 訪問済みマーキングによるサイクル分解 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、文字列の代わりに配列を操作できるように、オブジェクト名をインデックスに変換します。 これにより、ステップあたりの移動時間が一定になります。

1. 2 つのハッシュ マップを構築します。1 つはオブジェクト名を所有者インデックスにマッピングし、もう 1 つは所有者インデックスを目的のオブジェクト名にマッピングします。 最初のマッピングは、オブジェクトからその所有者に即座にジャンプできるため、不可欠です。 
2. 関数グラフ配列 next[] を構築します。ここで、next[i] は、私が欲しいオブジェクトを所有する人のインデックスです。 これにより、各ノードから他の 1 つのノードへの確定的なポインタが作成されます。 
3. すべてのノードに対して false に初期化された訪問先配列を維持します。 これにより、すでに処理したサイクルを再計算することがなくなります。 
4. 0 から n-1 までのすべてのノード i を反復します。 ノード i がすでに訪問されている場合は、以前に処理されたサイクルに属しているため、スキップします。 
5. ノード i が訪問されていない場合は、i から次のポインタに従って歩き始め、ノードを訪問済みとしてマークし、訪問済みのノードに戻るまで遭遇した一意のノードの数を数えます。 すべてのノードには出力エッジが 1 つだけあるため、この走査は必然的に 1 サイクル内に留まります。 
6. サイクル長が少なくとも 2 の場合、この値で回答を更新します。 
7. すべてのノードを処理した後、見つかった最大サイクル長を出力するか、サイクル長が 1 を超えない場合は有効なサイクルが存在しないことを報告します。 

正確かどうかは、一度サイクルに入るとそこから抜け出すことができないという事実にかかっており、各ノードには出力エッジが 1 つだけあるため、トラバースは分岐できません。 

### なぜ効果があるのか

 構築されたグラフは、オブジェクトの所有権と需要によって引き起こされる参加者のセットの順列です。 このようなグラフでは、すべての連結成分は有向サイクルです。 各サイクルは互いに素であり、すべてのノードは 1 つのサイクルにのみ属します。 トラバーサルでは、サイクル内のすべてのノードが 1 回だけマークされるため、サイクルの長さは重複や欠落なく正確に計算されます。 したがって、これらのサイクル長の最大値が、可能な限り最長の有効な貿易チェーンとなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    if n == 0:
        print("No trades possible")
        return

    owner_of = {}
    want = []
    names = []

    for i in range(n):
        name, have, need = input().strip().split()
        names.append(name)
        owner_of[have] = i
        want.append(need)

    nxt = [-1] * n
    for i in range(n):
        if want[i] in owner_of:
            nxt[i] = owner_of[want[i]]

    visited = [False] * n
    ans = 0

    for i in range(n):
        if visited[i]:
            continue

        cur = i
        cnt = 0
        path = []

        while not visited[cur]:
            visited[cur] = True
            path.append(cur)
            cnt += 1
            cur = nxt[cur]

            if cur == -1:
                cnt = 0
                break

        if cnt > 1:
            ans = max(ans, cnt)

    if ans == 0:
        print("No trades possible")
    else:
        print(ans)

if __name__ == "__main__":
    solve()
```このソリューションは、すべての参加者を読み取り、各オブジェクトからその所有者へのマッピングを構築することから始まります。 これは、私たちが「欲しい物」から、現在それを持っている人に直接ジャンプできるようにする重要な変換です。 

次のポインター配列は関数グラフをエンコードします。各人は正確に他の 1 人を指します。参加者間に目的のオブジェクトが存在しない場合は -1 を指します。 訪問された配列により、各ノードが 1 回処理されることが保証されます。 

トラバース中に、訪問したノードに遭遇するまでパスを蓄積します。 サイクルは互いに素であるため、この走査はちょうど 1 つのサイクルをキャプチャするか、チェーンが不完全な場合は中断します。 サイズ 1 は自分のアイテムが欲しい人に対応し、取引を形成しないため、サイズ 2 以上のサイクルのみを考慮します。 

微妙な点は、トラバーサル中にすぐに訪問したノードをマークすることで、他のサイクルからノードを再訪問することがなくなり、線形動作が保証されることです。

 ## 特殊なケース

 エッジケースの 1 つは、参加者全員が自分のアイテムを欲しがる場合です。 例えば：```
A X X
B Y Y
C Z Z
```各ノードはそれ自体を指します。 トラバーサルでは各ノードが個別にマークされますが、サイクル サイズは常に 1 であるため、有効な取引は記録されません。 アルゴリズムは「取引は不可能です」と正しく出力します。 

もう 1 つのケースは、有効なサイクルと孤立した自己ループの組み合わせです。 訪問された配列により、サイクルが 1 回検出されることが保証され、自己ループは答えに影響を与えないサイズ 1 のサイクルとして扱われます。 すべてのコンポーネントの最大値によっても、正しい最長の取引チェーンが得られます。
