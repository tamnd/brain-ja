 ## 解決策
 ## 問題の理解

 いくつかのテストケースが与えられています。 各テスト ケースは、数直線上に配置されたモンスターのセットと武器のセットを記述します。 すべてのモンスターは単一の整数座標に位置し、複数のモンスターが同じ位置を共有することができます。 各武器は数直線上の閉じた区間に対応しており、その武器を 1 回使用すると、その区間内に座標があるすべてのモンスターが破壊されます。 

課題は、すべてのモンスターが少なくとも 1 回破壊されるように、発砲する必要がある武器の最小数を決定することです。 各武器は最大 1 回使用でき、武器をスキップすることもできます。 すべての武器を使用してもすべてのモンスター座標をカバーできない場合、答えは不可能です。 

制約は、テスト ケースごとに線形または線形に近い解決策を提案します。 すべてのテスト ケースにわたるモンスターと武器の合計数は 3×10^5 によって制限されるため、全体として O(n log n) より悪いアプローチはタイムアウトになる危険性があります。 これは、ソートと貪欲な選択、または効率的な間隔処理と組み合わせたスイープライン構造を強く示唆しています。 

一部のモンスターがすべての間隔の外側にある場合、微妙なエッジケースが表示されます。 たとえば、モンスターが [1、10] の位置にあり、すべての銃が [2、5] 内の範囲のみをカバーする場合、すべての武器を使用したとしても、選択は 1 と 10 の両方をカバーできません。 正解は -1 で、ローカル カバレッジのみに焦点を当てた貪欲なアルゴリズムでは、部分的な進行で十分であると誤って想定される可能性があります。 

別の失敗例は、間隔が重なり合っているものの、ギャップを結合してカバーしていない場合に発生します。 たとえば、[1, 2, 3, 10] のモンスターと銃 [1, 3]、[2, 2]、[3, 3] は最初のクラスターとして有望に見えますが、10 個は未カバーのままです。 アルゴリズムは、貪欲にカバレッジを最大化するだけでなく、モンスターの位置のセット全体のカバレッジを明示的に保証する必要があります。 

## アプローチ

 この強引なアイデアは、各武器を二者択一の選択肢として扱うことです。つまり、それを手に入れるかどうかです。 武器のすべてのサブセットをシミュレートし、どのサブセットがすべてのモンスターの位置をカバーするかを確認します。 明らかに無駄な選択肢を削減したとしても、武器の数は指数関数的に増加する構造のままです。 最大 3×10^5 の武器では、これは不可能です。 

もう少し構造化された総当たり攻撃は、モンスターを分類し、カバーされていないモンスターごとに、それをカバーする任意の間隔を貪欲に選択し、さまざまな選択を再帰的に試みることです。 複数の間隔で同じモンスターがカバーされる可能性があり、その後の決定が将来のカバー範囲に影響するため、分岐係数は依然として大きすぎます。 

重要な観察は、モンスターが左から右まで最適にカバーされていれば、再考する必要がないということです。 モンスターを位置で分類する場合、最小の座標から最大の座標までスイープすることを考えることができます。 各ステップでは、現在のカバーされていない位置をカバーできる間隔のみを考慮します。その中で、カバー範囲を可能な限り右側に拡張する間隔を選択することが常に最適です。 これはインターバルカバーの古典的な貪欲な構造です。 

この問題の面白い点は、すべての間隔を使用する必要がないことです。 サブセットを選択します。 これは、一連の点をカバーする最小間隔と同じです。 任意のポジションに対して、そのポジション以降から始まる最適なインターバルを迅速に取得できるように、インターバルを前処理します。 

モンスターとインターバルの両方をソートします。 次に、間隔に対するポインタと、現在使用可能な候補間隔を保持するデータ構造を維持します。 リーチが最大になる間隔を選択を繰り返しながら、貪欲にモンスターを進めていく。

 | ブルートフォース | O(2^m・n) | お(1) | 遅すぎる |
 | 最適な貪欲なスイープ | O((n + m) log m) | O(m) | 承認済み |

 ## アルゴリズムのチュートリアル

1. モンスターの位置を昇順に並べ替えます。 これにより、ギャップを見逃すことなく、常に一貫した左から右の順序でカバレッジを処理できるようになります。 
2. すべてのガンを左のエンドポイントで並べ替えます。 これにより、現在のカバーされていないポジションに関連するようになるとすぐにインターバルをアクティブ化することができます。 
3. ガンの上のポインタと、右のエンドポイントをキーとする最大ヒープを維持します。 ヒープは、左端が最大でも現在のモンスターの位置にあるすべての間隔を表します。 
4. ポインタを初期化する`i = 0`モンスターと中古銃のカウンター。 
5. 現在のモンスターの位置について`x = monsters[i]`、すべての銃を押します`l <= x`山の中へ。 各プッシュには、間隔の右のエンドポイントが含まれます。 
6. ヒープから、右端が以下の間隔を繰り返し破棄します。`x`, それはもう現在のモンスターをカバーすることができないためです。 
7. ヒープが空になった場合は、残りの間隔でこのモンスターの位置をカバーできないことを意味するため、答えは不可能です。 
8. それ以外の場合は、右の最大のエンドポイントの間隔を取得し、それをワンショットとして使用し、移動します。`i`その右のエンドポイントよりも大きい最初のモンスターの位置に進みます。 

選択された各間隔は、効果的にできるだけ右に移動し、1 ステップで複数のモンスターをカバーできる可能性があります。 

### なぜ効果があるのか

 貪欲な選択は、カバーされていないモンスターの位置において、それをカバーできるすべての間隔の中で、最大の正しいエンドポイントを持つものを選択することが将来の可能性を決して減じないという事実に依存しています。 より早く終了する代替インターバルは、選択したインターバルがすでにカバーしているモンスターのサブセットのみをカバーできますが、少なくとも同量以上の作業が将来に残されます。 プロセスは常に左端のカバーされていないモンスターを進めるため、この局所的に最適な拡張により、全体的に最適な最小ショット数が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import heapq

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        monsters = list(map(int, input().split()))
        guns = [tuple(map(int, input().split())) for _ in range(m)]

        monsters.sort()
        guns.sort()

        heap = []
        j = 0
        ans = 0
        i = 0

        while i < n:
            x = monsters[i]

            while j < m and guns[j][0] <= x:
                heapq.heappush(heap, -guns[j][1])
                j += 1

            while heap and -heap[0] < x:
                heapq.heappop(heap)

            if not heap:
                ans = -1
                break

            r = -heapq.heappop(heap)
            ans += 1

            while i < n and monsters[i] <= r:
                i += 1

        print(ans)

if __name__ == "__main__":
    solve()
```このソリューションはモンスターと間隔を並べ替えて、単一の順方向パスでカバレッジを処理できるようにします。 ポインタ`j`各ガンが関連するときに必ず 1 回挿入されるようにします。 ヒープには適切なエンドポイントの候補が保存され、到達可能な最大のエンドポイントが常に抽出されます。 

右端が現在のモンスターの左側にある間隔はもう寄与できないため、無効な間隔を削除する内部クリーンアップ ループが必要です。 これがないと、ヒープが使用可能なカバレッジを誤って提案する可能性があります。 

前進`i`while ループを使用すると、選択した間隔でカバーされるすべてのモンスターが 1 ステップでスキップされ、不必要な繰り返し処理が防止されます。 

## 実用的な例

 モンスターが位置 [1、2、4] にあり、銃が [1、3]、[2、3]、[2、5] である小さなケースを考えてみましょう。 

両方のリストを並べ替えてから、次のシミュレーションを行います。 

| ステップ | 現在のモンスターX | ヒープ候補 (r) | 選択された間隔 | 移動後の私 |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | [3] | [1,3] | 2 |
 | 2 | 4 | [3,5] → [5] にクリーニング | [2,5] | 3 |

 1発目以降は1と2のモンスターが対象となります。 2打目は4つカバーするので2打で終わります。 

次に、モンスター [1、10]、銃 [1、3]、[4、6] という、カバレッジが不可能な失​​敗例を考えてみましょう。 

モンスター 1 では、[1,3] のみを選択でき、位置 4 に進みます。4 では、[4,6] のみが使用可能で、7 に進みます。7 では、それをカバーする間隔がないため、アルゴリズムは停止し、-1 を正しく出力します。 

これは、アルゴリズムがグローバル カバレッジの存在を想定しておらず、カバレッジ内のギャップを適切に検出していることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n + m) log m) | 各銃はヒープに 1 回出入りし、各モンスターは 1 回処理されます。 
| スペース | O(m) | ヒープは、ほとんどすべてのアクティブな間隔でストアします。 

すべてのテスト ケースの合計 n + m は最大 3×10^5 であるため、複雑さは制限内に問題なく収まります。 各操作は、管理可能なヒープ サイズで対数的に行われます。

 ## 特殊なケース

 モンスターが厳密に増加しているにもかかわらず、間隔が局所的にのみ重なっている場合、重大なエッジケースが発生します。 銃 [1, 3]、[2, 3]、[3, 4] を備えた入力モンスター [1、2、100] の場合、アルゴリズムは最初の 2 つのモンスターを 1 回のショットで正しくカバーしますが、間隔がその値に達しないため、その後 100 で失敗します。 x = 100 でヒープが空になり、-1 が生成されます。 

もう 1 つの微妙なケースは、多くの間隔が最初のモンスターの前に始まり、その前に終了する場合です。 モンスター [10] と銃 [1,5]、[2,6] の場合、ヒープはいっぱいになりますが、右側のエンドポイントが 10 未満であるため、クリーンアップ中にすべての間隔が破棄されます。アルゴリズムは、不可能であると正しく結論付けます。 

最後のエッジケースは重度のオーバーラップです: モンスター [1,2,3,4]、銃 [1,4]、[1,3]、[2,4]。 貪欲な選択は常に [1,4] を最初に選択し、すぐにすべてのモンスターをクリアします。 代替の最初のピックでも 2 番目のステップが必要となるため、アルゴリズムの最大リーチ戦略により不必要なショットが回避されます。
