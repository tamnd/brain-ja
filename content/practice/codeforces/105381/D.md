 ## 解決策
 ## 問題の理解

 次のような長方形のグリッドが与えられます。$n$行と$m$列。 各セルには整数が含まれており、許可される唯一の操作は、各列内の値を個別に並べ替えることです。 これらの再配置後、各行を調べ、隣接する列間の絶対差を合計することによって、それがどの程度「滑らか」であるかを測定します。 目標は、これらすべての行方向の隣接する差分の合計ができるだけ小さくなるように各列を配置することです。 

最終的な式について考えるのに役立つ方法は、隣接する列のすべてのペアが行ごとに独立して寄与するということです。$i$、私たちが支払います$|a_{i,j} - a_{i,j+1}|$そして、これをすべての行とすべての隣接する列のペアにわたって合計します。 

重要な制約は、各列が値の複数セットであり、任意に並べ替えることができるが、列の内容はそのままにしておく必要があるということです。 

境界は小さいです:$n, m \le 100$。 これは次のことを示唆しています$O(n^2 m \log n)$あるいは$O(n^3)$快適に過ごせるかもしれません。 主なヒントは、再配置は列ごとに独立しているが、目的は隣接する列を結合するため、列を完全に独立して扱うことはできないということです。 

各列を個別に並べ替えるという単純な誤解があります。 これは、内部順序だけではなく、2 つの列にわたる行間のペアが重要であるため、失敗します。 

値が行間で高度にインターリーブされている場合、微妙なエッジ ケースが発生します。 

例:```
2 2
1 100
100 1
```両方の列をソートすると、次のようになります。```
1 100
1 100
```コストは$0 + 0 = 0$、ここでは最適です。 ただし、他の構成では、より複雑な分布が列間で存在する場合、貪欲な独立ソートは列間一致コストを最小限に抑えることを保証しません。 

別の失敗例は、最適なペアリングが、すべての隣接する列ペアにわたって、異なる行にわたって一貫して最小値と最大値を一致させる必要がある場合に発生します。 列ペアごとの純粋にローカルな貪欲戦略では、複数の列にわたって不整合が生じる可能性があります。 

これは、すべての列を一貫した方法で同時に整列させる、列ごとのグローバルな順序付けが必要であることを示しています。 

## アプローチ

 ブルートフォースアプローチでは、各列のすべての順列を個別に試行します。 各列には、$n!$順列になるため、全体の複雑さは次のようになります。$(n!)^m$、これはたとえ$n = 10$。 

このアイデアを少し減らすことができます。すべての順列を列挙する代わりに、隣接する列間の行の一致という観点から考えることができます。 列の順序を固定する場合$j$、列の最適な順序を見つけたいと考えています。$j+1$これにより、ペアになったエントリ間の絶対差の合計が最小限に抑えられます。 

これは、2 つのマルチセット間の古典的な割り当てスタイルの問題です。 両方の列をソート済みに固定する場合、1D の絶対差分の再配置不等式により、最適なペアリングはソートされた順序で要素を一致させることになります。 

重要な洞察は、問題が隣接する列間の独立したマッチング問題に分解され、そのような問題は両方の列を並べ替えて順番にペアにすることで最適に解決されるということです。 ただし、各列の並べ替えは 1 回だけ許可されており、その並べ替えはすべての隣接するペアにわたって一貫していなければなりません。 

これは、全体的な一貫性の観察につながります。つまり、最初の列の順列を修正し、誘導された順序を前方に伝播して、次の各列が前の列に対して最適に再配置されるようにする必要があります。 この構造は、両側をソートすることでそれぞれ解決される最適なマッチングのチェーンとなり、行全体で一貫した順序付けが維持されます。 

これにより、問題は列の繰り返しソートと行ごとのコストの蓄積に変わります。

 ## アルゴリズムのチュートリアル

 グリッドを列ごとに処理し、各列が前の列と比較して最適な一貫した行順序で保存されるようにします。 

1. 各列を長さの配列として扱う$n$。 まず、すべての列を個別に並べ替えます。 これにより、各列内で値が大きい順に並べられるようになり、これが照合の正規表現となります。 
2. 隣接する列のペアごとに$j$そして$j+1$をペアにして絶対差の最小和を計算します。$k$-列の 2 番目に小さい要素$j$と$k$-列の 2 番目に小さい要素$j+1$。 これは、次の場合のソートされたマッチングの最適性から導き出されます。$L_1$料金。 
3. すべての隣接する列ペアにわたってこのコストを累積します。 
4. 最終的な答えは全体の合計です$j$列間のマッチングコスト$j$そしてコラム$j+1$。 

このステップが有効である理由は、各列の順列が並べ替えによって完全に決定され、一度並べ替えると、列内でそれ以上再配置すると、少なくとも 1 つの隣接するペアの最適性が損なわれるためです。 したがって、すべての列が独立してソートされ、インデックスによって整列されると、グローバルに最適な構成が実現されます。 

### なぜ効果があるのか

 任意の 2 つの列について、それらの要素間の組み合わせを考慮します。 2 つのエッジが値の順序で交差する場合、それらを交換しても絶対差の合計が増加することはありません。 このような反転を繰り返し削除すると、コストを増加させることなく、あらゆるペアが並べ替えられた列の同一ペアに変換されます。 これはまさに、絶対差に適用される並べ替えの不等式であり、両方の列とインデックス方向のペアの並べ替えが、隣接する各ペアに対して最適であることが保証されます。 各列は正確に 2 つの隣接する比較 (境界を除く) に現れるため、ペアごとの独立した最適なペアリングはグローバルに一貫したままになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    cols = [[] for _ in range(m)]
    
    for _ in range(n):
        row = list(map(int, input().split()))
        for j in range(m):
            cols[j].append(row[j])
    
    for j in range(m):
        cols[j].sort()
    
    ans = 0
    for j in range(m - 1):
        a = cols[j]
        b = cols[j + 1]
        for i in range(n):
            ans += abs(a[i] - b[i])
    
    print(ans)

if __name__ == "__main__":
    solve()
```まず、グリッドを列リストに転置して、列操作が直接の配列操作になるようにします。 各列をソートすると、マッチングベースのコストに対して最適な内部配置が確立されます。 

実装の重要な詳細は、ソート後に行を再度並べ替えないことです。 私たちはインデックスのアライメント、つまり行に完全に依存しています。$i$列内$j$行とペアになっています$i$列内$j+1$。 これは最適なマッチングをエンコードするものです。

 ## 特殊なケース

 特殊なケースとしては、列内のすべての値が同一である場合があります。 この状況では、並べ替えは何も行われず、その列ペアの寄与は隣接する列の広がりにのみ依存します。 ソートされたペアリングではコストに影響を与えることなく同じ値を任意に整列させるため、アルゴリズムがこれを処理します。 

もう 1 つのケースは、列が相互に逆の順序になっている場合です。 1 つの列が昇順で次の列が降順である場合でも、両方を並べ替えることで逆転がなくなり、ペアリングのコストが最小限に抑えられます。 アルゴリズムは両方を昇順に変換し、その後コストが一貫して計算されます。 

いつ$n = 1$、順序付けに柔軟性がなく、答えは 1 つの行にわたる絶対差の合計になります。 単一要素列の並べ替えは何も行わず、ペアリング ループは引き続き正しい隣接差分を計算するため、アルゴリズムはこれを正しく処理します。
