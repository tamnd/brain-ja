 ## 解決策
 ## 問題の理解

 各エッジに重みがある接続された無向グラフが与えられます。 固定閾値の場合$x$、概念的に、重みが より大きいすべてのエッジを「無視」します。$x$、最大でもウェイトのあるエッジのみを保持します$x$。 結果として得られるフィルター処理されたグラフでは、パスによって接続されている頂点もあれば、接続されていない頂点もあります。 

次に、元の頂点に色付けルールを定義します。 ウェイトのエッジのみを使用して頂点間にパスがない場合にのみ、2 つの頂点が同じ色を共有することが許可されます。$\le x$。 同様に、そのようなパスが存在する場合、それらは異なる色でなければなりません。 

これは、同じコンポーネント内の 2 つの頂点が有効なパスで接続されているため、フィルタリングされたグラフの接続された各コンポーネント内では、すべての頂点が個別の色を受け取る必要があることを意味します。 異なるコンポーネント間では制限がないため、頂点はコンポーネント間で自由に色を再利用できます。 

したがって、固定の場合、$x$、必要な色の最小数は、重みのあるエッジによって形成されるグラフ内の連結成分の数と正確に一致します。$\le x$。 

問題は次のようになります。各クエリは、指定された重みしきい値までのすべてのエッジを含むグラフ内の連結成分の数を求める多くのクエリに答える必要があります。 

制約は大きく、最大で$3 \times 10^5$頂点、エッジ、クエリ。 クエリごとに接続を最初から再構築するソリューションは、遅すぎます。 平$O(m \log m)$クエリごとに爆発的に増加する$10^{10}$操作。 これは、エッジを 1 回処理し、クエリにオフラインまたは段階的に応答する前処理戦略が必要であることを直ちに示唆しています。 

よくある落とし穴は、エッジをフィルタリングした後に BFS または DFS を使用してクエリごとに連結成分を個別に再計算しようとすることです。 各 BFS が次のとおりであるため、これは失敗します。$O(n + m)$と繰り返しました$q$最悪の場合、時間は 2 次になります。 

さらに微妙な間違いは、クエリを並べ替えるのに、クエリしきい値ごとに DSU を最初から再構築することです。 それはまた、あまりにも多くの作業を繰り返し、単調性を無視します。 

## アプローチ

 単一のクエリを修正すると$x$、総当りの方法は簡単です。重みのあるエッジのみを含むグラフを構築します。$\le x$、DFS または DSU を実行して連結成分を計算し、カウントを返します。 これは正しいです。接続性は完全にこれらのエッジによって定義されるからです。 

ただし、これをクエリごとに個別に実行すると、同じエッジ処理が何度も繰り返されることになります。 最悪の場合でも、各クエリはすべてのクエリをスキャンします。$m$エッジ、につながる$O(qm)$、到達できる$9 \times 10^{10}$操作。 

重要な観察は次のとおりです$x$増加する場合、エッジを追加するだけで、エッジを削除することはありません。 したがって、接続構造は単調に進化します。コンポーネントは時間の経過とともに結合するだけです。 これはまさに Disjoint Set Union 構造の設定です。 

すべてのエッジを重みで並べ替え、さらにクエリを次の基準で並べ替えるとします。$k$、増加をシミュレートできます$x$小さいものから大きいものまで。 頂点上で DSU を維持し、エッジがアクティブになるとエッジのエンドポイントをマージし続けます。 すべてのエッジをウェイトで処理した後$\le k$、DSU コンポーネントの数が答えです。 

任意のクエリ順序の正確さを維持するために、エッジを 1 回スイープしながら、並べ替えられた順序でクエリを処理します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとに再計算 (DFS/BFS) |$O(q(n+m))$|$O(n+m)$| 遅すぎる |
 | ソート + DSU スイープ |$O((n+m)\alpha(n) + q \log q)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 エッジとクエリの両方を重み/値の昇順に処理します。 

1. すべてのエッジを重みで昇順に並べ替えます。 これにより、しきい値の増加に関連するエッジが正確にアクティブ化されることが保証されます。$x$。 
2. クエリを元のインデックスとともに保存し、次の基準で並べ替えます。$k$。 これは、左から右への 1 回のスイープで回答できるようにするためです。 
3. 独自のコンポーネント内の各頂点を使用して DSU を初期化します。 現在のコンポーネントの数は初期値です。$n$。 
4. ソートされたエッジ リスト上にポインタを保持します。 各クエリ値について$k$、次のエッジに重みがある間にこのポインタを進めます。$\le k$、エンドポイントが異なるコンポーネントにある場合は結合します。 結合が成功するたびに、コンポーネント数が 1 つずつ減ります。 
5. 現在のクエリに対して該当するすべてのエッジが処理されると、現在の DSU コンポーネント数がそのクエリに対する正確な答えになります。 
6. 最終出力が入力順序に従うように、元のクエリ インデックスを使用して回答を配列に格納します。 

正確かどうかは、DSU が段階的にエッジを挿入しても接続を維持できるかどうかにかかっています。 エッジを追加してもコンポーネントを分割できないため、過去のマージを再考する必要はありません。 

### なぜ効果があるのか

 どのしきい値でも$k$、DSU には、重みを持つエッジによって形成されるサブグラフの接続されたコンポーネントが正確に含まれます。$\le k$。 有効なエッジの端点のみを結合し、無効な端点は決して含めないため、これは不変条件として当てはまります。 各結合はエッジの追加に対応し、パーティションを変更せずに 2 つのコンポーネントをマージするか、すでに接続されている頂点を接続します。 したがって、DSU パーティションは常に真の接続パーティションと一致し、すべてのクエリに対してコンポーネント数が正しくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n
        self.components = n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return
        if self.size[ra] < self.size[rb]:
            ra, rb = rb, ra
        self.parent[rb] = ra
        self.size[ra] += self.size[rb]
        self.components -= 1

n, m, q = map(int, input().split())

edges = []
for _ in range(m):
    u, v, w = map(int, input().split())
    edges.append((w, u - 1, v - 1))

edges.sort()

queries = []
for i in range(q):
    k = int(input())
    queries.append((k, i))

queries.sort()

dsu = DSU(n)
ans = [0] * q

ei = 0

for k, idx in queries:
    while ei < m and edges[ei][0] <= k:
        w, u, v = edges[ei]
        dsu.union(u, v)
        ei += 1
    ans[idx] = dsu.components

print("\n".join(map(str, ans)))
```DSU は、エッジが重みの増加順に追加されるにつれて、接続を動的に維持します。 の`components`このフィールドは、結合のたびに接続コンポーネントを最初から再計算することを避けるため、非常に重要です。 

微妙な点は、クエリはソートされた順序で応答する必要があるが、出力は元の順序で行う必要があることです。 インデックス追跡により、余分なオーバーヘッドを発生させずに正確性が保証されます。 

ユニオン操作は、以前は別々だった 2 つのセットがマージされた場合にのみコンポーネント数をデクリメントします。これにより、カウントがアクティブなグラフ内の接続コンポーネントの真の数を常に反映することが保証されます。

    parent = list(range(n))

    def find(x):

            parent[x] = parent[parent[x]]
            x = parent[x]

        nonlocal comp

 ## 特殊なケース

 重要なエッジ ケースは、すべてのエッジの重みがすべてのクエリよりも大きい場合です。 この状況では結合は決して起こらず、答えは常に次のようになります。$n$。 エッジ ポインターが決して前進せず、DSU がそのまま残されるため、アルゴリズムがこれを処理します。 

もう 1 つのケースは、すべてのエッジの重みがすべてのクエリ以下である場合です。 その後、すべてのエッジが 1 回処理され、グラフが接続されていれば、最終的な DSU 状態は完全に接続されます。 このアルゴリズムは 1 つのパスですべての結合を正しく実行し、その後のすべてのクエリは同じコンポーネント数を返します。 

より微妙なケースは、同じ値を持つクエリが繰り返される場合です。 並べ替えるとそれらがグループ化され、DSU の状態が単調であるため、同一のクエリはそれぞれ再計算せずに同じコンポーネント数を読み取ります。
