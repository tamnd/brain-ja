 ## 解決策
 ## 問題の理解

 各要素が重みを持つ一連の整数が与えられます。 このシーケンスから任意のサブシーケンスを選択することができます。つまり、順序を維持しながら要素を削除でき、そのサブシーケンスで計算される 2 つの異なる量を考慮します。 

まず、任意のシーケンスについて、増加する最長のサブシーケンス長を計算できます。 次に、選択したサブシーケンスについて、その要素の重みを合計します。 目標は、重みの点でできるだけ「重い」サブシーケンスを選択することですが、制限が 1 つあります。その LIS 長は、元のシーケンスの LIS 長より厳密に小さくなければなりません。 

したがって、LIS 自体を最小化したり計算したりするつもりはありません。 私たちは総重量を可能な限り維持しながら、少なくとも 1 ユニットの LIS 潜在能力を破壊する必要があります。 

制約は小さく、n は最大 100 です。これは、O(n³) または O(n⁴) のアプローチでもまだ合格する可能性があることをすぐに示唆していますが、LIS の構造は、より組み合わせた動的プログラミング ソリューションが存在することを強く示唆しています。 すべてのサブシーケンスを明示的に列挙する解決策は指数関数的であり、ここでは不要です。 

元の LIS が 1 の場合、微妙な例外ケースが発生します。その場合、すべてのサブシーケンスの LIS は最大 1 であるため、条件 f(a') < f(a) により f(a') = 0 が強制され、選択されたサブシーケンスは空でなければならず、答えは 0 になります。これは重要なエッジ ケースです。これがないと、単純なソリューションでは、元の LIS が 1 のときに空ではないサブシーケンスが誤って許可される可能性があります。 

もう 1 つの重要なシナリオは、シーケンスに繰り返し値が多数ある場合、またはシーケンスが減少していない場合です。 その場合、LIS は n に等しく、選択したサブシーケンスが厳密な増加の少なくとも 1 ステップを下回るようにする必要があります。 単純な「大きな重みをすべて取得する」戦略では、簡単に同じ LIS が保持され、制約に違反する可能性があります。 

## アプローチ

 ブルートフォース手法では、配列のすべてのサブシーケンスが試行されます。 各サブシーケンスについて、その LIS と重みの合計を計算します。 これは、すべての有効な候補をチェックするので正しいですが、部分列の数は 2ⁿ で、これは n = 100 の場合約 10⁹⁰ であり、実現可能性をはるかに超えています。 O(n²) のサブシーケンスごとに LIS を計算しても役に立ちません。 

重要な構造的観察は、LIS 制約が値の相対的な順序にのみ依存するのに対し、重みの累積はその構造に依存しないということです。 サブシーケンスの観点から考える代わりに、視点を反転します。各値から取得する要素の数を決定し、可能な最大長の完全に増加するチェーンを保持しないようにします。 

値 aᵢ は n によって制限されるため、値空間内の位置の観点から考えることができます。 シーケンスの LIS は、インデックスの増加に伴う増加する値の連鎖によって決定されます。 f(a') < f(a) を保証するには、元の構造のすべての最大 LIS チェーンから少なくとも 1 つの要素を切り離す必要があります。 That suggests a DP over LIS states.

 最初に元の配列の LIS 構造を計算し、プレフィックスと可能な LIS 長に対する dp を定義し、完全な LIS と一致するか厳密に下回るかを制御しながら、達成可能な最大の重みを追跡します。 自然な状態は次のようになります。各プレフィックス、および考えられる LIS の長さ ℓ ごとに、LIS が正確に ℓ または最大でも ℓ であるサブシーケンスの最大重みを追跡します。 

次に、最終的な ℓ が厳密に LIS(a) より小さくなければならないことを強制します。 これにより、問題は LIS 状態に関する制限されたナップザックに変わります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2ⁿ · n²) | O(n) | 遅すぎる |
 | LIS 上の DP 状態 | O(n² · L) | O(n・L) | 承認済み |

 ここで、L は最大でも n です。 

## アルゴリズムのチュートリアル

 まず、標準の O(n²) 動的プログラミングを使用して、元の配列の LIS 長を計算します。 この値を L₀ とします。 LIS が最大でも L₀ − 1 である部分列のみを受け入れます。

次に、DP テーブルを構築します。ここで、dp[i][ℓ] は、配列の最初の i 要素のみを使用して達成できる最大合計重みを表し、LIS 長が正確に ℓ であるサブシーケンスを形成します。 

1. dp を −∞ で初期化し、dp[0][0] = 0 を設定します。これは、LIS 0 および重み 0 の空のサブシーケンスを表します。要素が増加構造を意味しないため、これが唯一の有効な開始点です。 
2. 要素を 1 つずつ処理します。 各要素 i について、スキップするか取得するかの 2 つの可能性を考慮します。 LIS は変化しないため、スキップすると以前のすべての状態が直接保存されます。 
3. 要素 i をサブシーケンスの終わりとする場合、それを前の要素 j < i (a[j] < a[i]) の後に付加する必要があります。 このような遷移ごとに、任意の dp[j][ℓ] 状態を dp[i][ℓ+1] に拡張できます。 これにより、増加するサブシーケンスに厳密に大きな値を追加するため、LIS の長さがちょうど 1 だけ増加します。 
4. 遷移中、可能なすべての以前の j に対して dp[i][ℓ] を最大化し、各 LIS 長に対して達成可能な最良の重みを常に維持するようにします。 
5. すべての要素を処理した後、すべての dp 状態をスキャンしますが、0 から L₀ − 1 までの ℓ のみを考慮します。答えは、この範囲の最大 dp[n][ℓ] です。 

重要な設計上の選択は、LIS の長さを制御されたリソースとして扱うことです。 増加するサブシーケンスを拡張するたびに、LIS 容量の 1 ユニットが消費されます。 

### なぜ効果があるのか

 すべての有効なサブシーケンスは、要素を含めるかどうか、および要素を増加するサブシーケンスに連鎖させる方法の一連の選択に対応します。 DP はそのようなチェーンをすべて列挙しますが、結果として得られる LIS 長によってグループ化します。 昇順を維持するすべての遷移では LIS が 1 だけインクリメントされるため、これらの状態の外でサブシーケンスを形成することはできません。 ℓ < L₀ への制限により、元のシーケンスと比較して LIS の必要な厳密な減少が強制されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def lis_length(arr):
    n = len(arr)
    dp = [1] * n
    for i in range(n):
        for j in range(i):
            if arr[j] < arr[i]:
                dp[i] = max(dp[i], dp[j] + 1)
    return max(dp) if dp else 0

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    w = list(map(int, input().split()))

    L0 = lis_length(a)

    if L0 <= 1:
        print(0)
        return

    dp = [[-10**18] * (n + 1) for _ in range(n + 1)]
    dp[0][0] = 0

    for i in range(1, n + 1):
        ai = a[i - 1]
        wi = w[i - 1]

        # skip transition
        for l in range(n + 1):
            dp[i][l] = max(dp[i][l], dp[i - 1][l])

        # take transition
        for j in range(i):
            for l in range(n):
                if dp[j][l] < 0:
                    continue
                if j == 0 or a[j - 1] < ai:
                    dp[i][l + 1] = max(dp[i][l + 1], dp[j][l] + wi)

    ans = 0
    for l in range(L0):
        ans = max(ans, dp[n][l])
    print(ans)

if __name__ == "__main__":
    solve()
```実装では、まず配列全体の LIS を計算して、禁止境界を決定します。 その後、DP は段階的に状態を構築します。 スキップ遷移では、以前のすべての最良値が引き継がれます。 テイクトランジションは、昇順を維持する有効な前の位置の後に現在の要素を追加しようとします。 

微妙な点は、j = 0 仮想状態を介して任意の要素でサブシーケンスを開始できることを明示的に許可していることです。 これにより、特殊なケースの空のサブシーケンスが回避されます。 もう 1 つの重要な詳細は、l + 1 が範囲内にある場合にのみ、遷移を l + 1 にクランプすることです。 

## 実用的な例

 最初のサンプルを考えてみましょう。 

入力:```
n = 5
a = [1, 3, 2, 5, 4]
w = [100, 2, 4, 6, 5]
```a の LIS は 3、たとえば [1, 3, 5] です。 したがって、LIS が最大 2 のサブシーケンスを選択する必要があります。 

選択した状態の DP トレース:

 | 私 | 要素 | 最良の dp 状態 (ℓ → 重量) |
 | --- | --- | --- |
 | 0 | - | 0→0 |
 | 1 | 1 | 0→0、1→100 |
 | 2 | 3 | 0→0、1→100、2→102 |
 | 3 | 2 | 0→0、1→100、2→104 |
 | 4 | 5 | 0→0、1→100、2→106 |
 | 5 | 4 | 0→0、1→100、2→109 |

 ℓ = 3 を除外するので、答えは ℓ = 2 が最適です。これは、遷移に応じて [1, 3, 4] または [1, 2, 4] のような要素を選択することに対応し、重み 109 になります。 

このトレースは、DP が LIS の増加を制御しながら最適な重量を正しく蓄積していることを示しています。 

ここで、降順配列を考えてみましょう。 

入力:```
a = [5, 4, 3, 2]
w = [1, 2, 3, 4]
```LIS は 1 であるため、有効なサブシーケンスは LIS 0 でなければなりません。つまり、空である必要があります。 ℓ < 1 のみを考慮するため、DP は正しく 0 を返します。

 ## 特殊なケース

 次のような入力の場合:```
n = 3
a = [3, 2, 1]
w = [10, 20, 30]
```a の LIS は 1 であるため、空でないサブシーケンスは許可されません。 DP は dp[0][0] = 0 を初期化し、許容可能な有効な ℓ ≥ 1 状態を決して生成しません。 ℓ < 1 の最終スキャンでは 0 が返されます。 

対象:```
n = 3
a = [1, 2, 1]
w = [5, 100, 5]
```LIS は 2 です。最適な有効なサブシーケンスは LIS 1 を持つ必要があるため、増加する構造で 1 と 2 の両方を取ることは避けます。 DP はトランジションに応じて [2] または [1, 1] を選択でき、ウェイトを最大化しながら LIS 2 の構築を正しく回避します。 

これらのケースは、DP が最終サブシーケンスをフィルタリングすることによってではなく、構造的に LIS 制限を強制していることを示しています。
