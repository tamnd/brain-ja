 ## 解決策
 ## 問題の理解

 研究者の論文の被引用数のリストが、すでに昇順でない順にソートされています。 各数字は、特定の論文が引用された回数を表します。 タスクは、少なくとも H 個の論文の引用数が少なくとも H になるような最大の整数 H である H インデックスを計算することです。 

この定義を解釈する便利な方法は、最も引用された論文から順にソートされたリストをスキャンすることを想像することです。 位置 i (1 から始まるインデックス) では、この論文が依然としてサイズ i のグループの一部として適格であるかどうか、つまり引用数が少なくとも i であるかどうかを尋ねます。 答えは、この条件が当てはまる最大の位置です。 

制約 n は 10^6 まで大きくなるため、解は線形時間で実行される必要があります。 考えられるすべての H をチェックし、毎回配列をスキャンするなどの 2 次関数は、最悪の場合、最大 10^12 の演算を必要とし、合格しません。 

すべての引用数がゼロの場合、微妙なエッジ ケースが発生します。 たとえば、n = 5 で配列が [0, 0, 0, 0, 0] の場合、i ≤ ci を満たす位置はないため、答えは 0 でなければなりません。少なくとも 1 つの有効な論文を想定した単純な実装では、誤って 1 を返す可能性があります。 

すべての引用が大きい場合には、別の特殊なケースが発生します。 たとえば、[10, 10, 10] は、3 つの論文すべてが少なくとも 3 つの引用を満たしていることを満たしているため、個別に高い生の値も満たしているにもかかわらず、3 を返す必要があります。 制約は引用の大きさだけではなく、位置に関するものです。 

## アプローチ

 強引なアイデアは、0 から n までのすべての可能な候補値 H を試し、少なくとも H 個の論文に少なくとも H 個の引用があるかどうかを確認することです。 配列は降順でソートされているため、固定 H をチェックするには、ci < H となる最初のインデックスが見つかるまでスキャンし、有効な要素の数をカウントすることで実行できます。 このチェックには O(n) のコストがかかり、すべての H 値に対してこのチェックを行うと合計作業量は O(n^2) となり、n が 100 万までの場合は遅すぎます。 

重要な観察は、ソートされた構造から得られます。 引用は降順であるため、ci < i のインデックスに到達すると、配列が減少するだけなので、それ以降のすべての要素も失敗します。 これは、条件が壊れる最初の位置によって答えが決まることを意味します。 左から右に 1 回スキャンし、ci < i になったときにすぐに停止し、H インデックスとして i - 1 を返すことができます。

 ## アルゴリズムのチュートリアル

 ### 最適な戦略

 配列が既に非昇順にソートされているという事実を利用します。 

1. インデックス i = 1 の最初の論文から配列のスキャンを開始します。i は H インデックス グループの一部として検証しようとしている論文の数を表すため、引用数 ci を i と比較します。 これは、H-index の定義と直接一致します。 
2. 各位置 i について、ci ≥ i かどうかを確認します。 これが当てはまる場合、少なくとも i 件の引用を持つ少なくとも i 件の論文があるため、潜在的に少なくとも i の H インデックスを形成できる可能性があることを意味します。 
3. 条件が true である限り、前進を続けます。 それぞれの有効な位置は、可能な H インデックスを拡張します。 
4. 初めて ci < i の位置に遭遇したとき、停止します。 この時点では、i 番目の論文でさえ要件を満たしていないため、i - 1 より大きい H-index を持つことは不可能です。 
5. 最終的な答えとして i - 1 を返します。 条件を決して破らない場合、すべての論文は ci ≥ i を満たすため、答えは n になります。 

### なぜ効果があるのか

正しさは単調性から生まれます。 配列は降順でソートされるため、右に移動しても引用値が増加することはありません。 一方、必要なしきい値 i は各ステップでちょうど 1 ずつ増加します。 ci < i になると、すべての j > i について、cj ≤ ci と j > i の両方が成立することがわかり、cj < j も同様に成り立つはずです。 これにより、最初の障害点が、実現可能な最大の H インデックスが終了する正確な場所であることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    if n == 0:
        print(0)
        return
    
    c = list(map(int, input().split()))
    
    for i, val in enumerate(c, start=1):
        if val < i:
            print(i - 1)
            return
    
    print(n)

if __name__ == "__main__":
    solve()
```この解決策は、n とソートされた引用リストを読み取ります。 次に、単一パスを実行し、enumerate を使用して 1 から始まるインデックスを追跡します。 初めて引用値がそのインデックスを下回ったとき、前のインデックスを H インデックスとして返します。 そのようなブレークが発生しない場合、H インデックスは n と等しくなります。 

off-by-one の一般的な落とし穴は、条件内のインデックス付けが 1 ベースであるため、列挙は 1 から開始する必要があることを忘れていることです。もう 1 つの微妙な点は、入力リストが存在せず、答えが直接 0 になる n = 0 の処理です。 

## 実用的な例

 ### 例 1

 入力配列: [6、5、3、1、0]

 | 1 | 6 | 本当 | 続ける |

 入力配列: [10, 10, 10, 10]

 | 2 | 10 | 本当 | 続ける |
 | 3 | 10 | 本当 | 続ける |

 ブレークは発生しないため、答えは 4 です。これにより、すべての用紙が必要なしきい値を超えた場合にアルゴリズムが処理されることが確認されます。

import sys, io

 ## 特殊なケース

 空の出版物リストの場合、入力は n = 0 です。アルゴリズムは引用配列へのアクセスを試行せずにすぐに 0 を返します。これにより、無効な読み取りが回避され、論文がゼロの H-index を意味するという定義と一致します。 

[0, 0, 0] のような配列の場合、0 < 1 であるため、スキャンは i = 1 で失敗します。アルゴリズムは 0 を返し、単一の引用しきい値さえ満たさない論文がないことを正しく反映しています。 

[100, 100, 100, 100] のような完全に強力なデータセットの場合、スキャン中に中断は発生しません。 アルゴリズムは最後に到達し、4 つの論文すべてがすべての i について条件 ci ≥ i を満たすため、n = 4 を返します。
