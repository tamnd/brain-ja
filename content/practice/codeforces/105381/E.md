 ## 解決策
 ## 問題の理解

 1 から n までラベル付けされた小石から始めます。小石 i の重みは i です。 各移動では、現在利用可能な 2 つの小石が選択され、2 つのデバイスのうちの 1 つを通過します。 一方のデバイスは常に 2 つの入力のうち軽い方を返し、もう一方のデバイスは常に重い方を返します。 仕掛けを施した後は戻ってきた小石だけが次のラウンドに進みます。 このプロセスは正確に n − 1 回繰り返されるため、最終的には小石が 1 つだけ残ります。 

問題は、この 2 つのデバイスを自由に任意に使用できるわけではないということです。 ミニマイザーは最大で a 回使用でき、マキシマイザーは最大で b 回使用できます (a + b = n − 1)。問題は、最後に残る小石が正確に x になるような一連のペアリングとデバイスの選択が存在するかどうかです。 

このプロセスは比較を繰り返すように見えますが、重要な難点は、各操作が単なる比較ではなく、どの要素が生き残るかに偏りをもたらす強制選択ルールであることです。 プロセス全体は、どの値が最後まで存続できるかを形成する一連の消去法です。 

この制約により、すべてのエリミネーション ツリーに対するブルート フォースが不可能になります。 n が最大 1000 であっても、可能なバイナリ トーナメント構造の数はすでに n で指数関数的になっており、各ノードには 2 つの可能な操作タイプがあるため、直接列挙は実行可能な制限をはるかに超えて増加します。 

x が 1 または n の場合、微妙なエッジ ケースが発生します。 このような場合、最小または最大の要素を保持するのが「簡単」に見えるため、答えが常に可能であると誤って仮定する可能性がありますが、実現可能性は依然として、極値を強制的に存続させるのに十分な最小化操作または最大化操作があるかどうかに依存します。 

## アプローチ

 直接シミュレーションでは、各ステップで最小値を適用するか最大値を適用するかを選択して、消去のバイナリ ツリーを構築しようとします。 各構成は n 項目にわたる完全なペアリング構造に対応し、各内部ノードには操作タイプのラベルが付けられます。 これは巨大な状態空間につながります。ツリーの形状を固定したとしても、演算を割り当てる方法は 2^(n−1) 通りあり、カタルーニャ語の数の多くの形状が存在します。 これは大きすぎます。 

重要な観察は、比較の構造について考えるのをやめ、代わりに x の各辺でいくつの値を削除する必要があるかを追跡することです。 

最後に生き残るxについて考えてみましょう。 他の要素はすべて、ある時点で削除する必要があります。 各要素 y < x は、破棄する方法で選択された場合にのみ消滅します。 同様に、y > x の各要素も削除する必要があります。 重要な制約は、操作が 2 種類のみ存在するということです。ミニマイザーは常に小さい値を維持し、マキシマイザーは常に大きい値を維持します。 

これは次のことを意味します。 

- ミニマイザー操作では、最大 1 つの大きな要素を削除できます (小さい要素は保持されます)。 
- マキシマイザー操作では、最大 1 つの小さな要素を削除できます (大きな要素は保持されます)。 

したがって、操作を x の間違った側の要素を削除するための「ツール」として解釈します。 

x が生き残ることを確認するには:

 - x より小さい値はすべて、x を強制終了することなく削除できる必要があります。 
- x より大きいすべての値も、x を強制終了せずに削除できる必要があります。 

次に、何が必要かを考えてみましょう。 要素 y < x を削除するには、最終的に、それより大きいか等しい要素に対してマキシマイザー操作を実行して、要素が破棄されるようにする必要があります。 これにより、小さな要素の削除ごとにマキシマイザーの使用が 1 回消費されます。ただし、x が保護されている限り、削除は他の要素と慎重に組み合わせることができます。 

同様に、x より大きい各要素は、最小化演算を使用して削除する必要があります。 

したがって、実現可能性は、x より大きいすべての要素を削除するのに十分な最小化操作と、x より小さいすべての要素を削除するのに十分な最大化操作があるかどうかを確認することになります。 

カウントは簡単です。 

- x より大きい要素: n − x
 - x 未満の要素: x − 1

 したがって、次のものが必要です。 

- b ≧ n − x
 - a ≥ x − 1

a + b = n − 1 なので、これら 2 つの条件も十分です。 

これにより、問題全体が、構造に関係なく、カウントに関する単純な実行可能性チェックに集約されます。

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、n、a、b、および x を読み取ります。 値 x は、最後まで生き残りたい小石です。 
2. x より小さい要素がいくつあるかを計算します。 これは x − 1 です。これらの要素はすべて、x を決して削除しない方法で削除する必要があります。 
3. x より大きい要素がいくつあるかを計算します。 これは n − x です。 これらの要素も、x を維持しながら削除する必要があります。 
4. マキシマイザー操作が x より小さい要素をすべて削除するのに十分であるかどうかを確認します。 マキシマイザーはより大きな値を保持するため、使用するたびに 1 つの小さな要素を削除できると考えることができるため、≥ x − 1 が必要になります。 
5. ミニマイザー操作が x より大きい要素をすべて削除するのに十分であるかどうかを確認します。 ミニマイザーは小さい値を保持するため、使用するたびに 1 つの大きな要素を削除できるため、b ≥ n − x が必要になります。 
6. 両方の条件が成立する場合は「Yes」を出力し、そうでない場合は「No」を出力します。 

### なぜ効果があるのか

 x を除くすべての要素は、プロセス中に 1 回だけ削除する必要があります。 x に影響を与えずに小さい要素を削除する唯一の方法は、大きいパートナーを保持するマキシマイザー相互作用を使用することです。対称的に、x に影響を与えずに大きい要素を削除するにはミニマイザー相互作用が必要です。 各操作では、x の反対側から最大 1 つの要素を安全に削除できるため、必要な削除の合計数は、各操作タイプで使用可能な数と直接一致します。 これにより、必要十分条件が厳密に満たされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, a, b, x = map(int, input().split())
    
    need_maximizer = x - 1
    need_minimizer = n - x
    
    if a >= need_maximizer and b >= need_minimizer:
        print("Yes")
    else:
        print("No")
```実装は、導出された実現可能性条件を直接変換したものです。 各テスト ケースは一定時間内に独立して処理されます。 重要な詳細はマッピングの一貫性を保つことです。マキシマイザーの使用は x より小さい要素の削除に対応し、ミニマイザーの使用は x より大きい要素の削除に対応します。 

## 実用的な例

 陽性と陰性の 2 つのケースを追跡します。 

### 例 1

 入力:

 n = 5、a = 2、b = 2、x = 4

 要件を計算します。 

| ステップ | x − 1 | n − x | | b | 状態 |
 | --- | --- | --- | --- | --- | --- |
 | コンピューティング | 3 | 1 | 2 | 2 | - |
 | マキシマイザーをチェックする | 3 ≤ 2 | - | 失敗 | - | いいえ |
 | ミニマイザーをチェックする | - | 1 ≤ 2 | - | わかりました | - |

 十分なマキシマイザー操作がないため、x=4 の危険を冒さずに要素 1、2、3 をすべて安全に削除することはできません。 出力は「いいえ」です。 

### 例 2

 入力:

 n = 10、a = 0、b = 9、x = 7

 | ステップ | x − 1 | n − x | | b | 状態 |
 | --- | --- | --- | --- | --- | --- |
 | コンピューティング | 6 | 3 | 0 | 9 | - |
 | マキシマイザーをチェックする | 6 ≤ 0 | - | 失敗 | - | いいえ |
 | ミニマイザーをチェックする | - | 3 ≤ 9 | - | わかりました | - |

 ここでは最大化操作が欠けているため、7 より小さい要素をすべて安全に削除することはできません。 ミニマイザーの容量が大きくても、欠落している演算タイプを補うことはできません。 

## 複雑さの分析

| スペース | お(1) | 変数以外の追加構造はありません |

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline
    
    t = int(input())
    out = []
    for _ in range(t):
        n, a, b, x = map(int, input().split())
        if a >= x - 1 and b >= n - x:
            out.append("Yes")
        else:
            out.append("No")
    return "\n".join(out)

# provided samples (as given in statement image; only outputs shown there)
assert run("""2
5 2 2 4
10 0 9 7
""") == """Yes
No"""

# minimal case
assert run("""1
1 0 0 1
""") == "Yes"

# x = 1 edge
assert run("""1
5 0 4 1
""") == "Yes"

# x = n edge
assert run("""1
5 4 0 5
""") == "Yes"

# insufficient both
assert run("""1
5 0 0 3
""") == "No"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | n=1 の場合 | はい | 単一の要素は常に存続します。 
| x=1 境界 | はい | ミニマイザーのみが必要です |
 | x=n 境界 | はい | マキシマイザーだけが必要です |

 ## 特殊なケース

 n = 1 の場合、演算は存在しないため、可能な唯一の生存者は 1 です。この条件では、a = 0 ≥ 0 および b = 0 ≥ 0 が与えられるため、アルゴリズムは正しく Yes を返します。 

x = 1 の場合、x − 1 = 0 となるため、マキシマイザー操作は必要ありません。 他のすべての要素は、b ≥ n − 1 に一致するミニマイザーを使用して削除する必要があります。 

x = n の場合、n − x = 0 となるため、最小化演算は必要ありません。 小さい要素はすべて、a ≥ n − 1 に一致するマキシマイザーを使用して削除する必要があります。 

いずれの場合も、計算された不等式は、必要な操作タイプのみが制約されるという直観的な要件に正しく帰着します。
