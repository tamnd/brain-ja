 ## 解決策
 ## 問題の理解

 年を表す単一の整数が与えられており、それが非常に具体的な数値プロパティを満たすかどうかを判断する必要があります。 2 つの条件が同時に成立する場合、その年は有効です。 まず、年自体は完全な平方でなければなりません。これは、平方が年に等しい整数が存在することを意味します。 次に、年の 10 進数を合計する場合、その合計も完全 2 乗でなければなりません。 

入力サイズは非常に小さく、年は 999,999 で区切られます。 これにより、大量の前処理や高度なデータ構造などは即座に排除されます。 平方チェックや数字の処理を繰り返し実行するソリューションは、1 つの数値だけを処理するか、拡張した場合でもせいぜい少数のテスト ケースしか処理しないため、制限内で実行するのは依然として簡単です。 

唯一の微妙なケースは、完全平方チェックの管理を誤ったことに起因します。 よくある間違いは、精度エラーを修正せずに浮動小数点平方根を使用することです。 もう 1 つは、桁の合計が 0 のような理論的な場合にのみゼロになる可能性があることを忘れていることです。年は少なくとも 1 であるため、ここでは関係ありません。3 つ目の問題は、数値が正方形のパターンのように見える場合は 1 でなければならないと想定していることです。999999 のような値の場合は失敗します。実装が不十分な場合、丸めエラーや不正な整数チェックが発生する可能性があります。 

具体的なエッジ ケースは、サンプル 999999 です。桁の合計は 54 で、完全な正方形ではないため、数値が大きな正方形に近く、誤ったヒューリスティックを誘惑する可能性があっても、答えは「いいえ」になります。 もう 1 つは 2025 です。これは、2025 が 45 の 2 乗に等しく、桁の合計が 9 が 3 の 2 乗に等しいため、きれいに機能します。 

## アプローチ

 最も直接的なアプローチは、数値が完全な平方であるかどうかを計算し、その桁の合計を個別に計算して、その合計も完全な平方であるかどうかを確認することです。 どちらの演算も O(log y) であるため、これは簡単です。 唯一重要なコンポーネントは正方形チェックです。 

数値 n が完全な平方であるかどうかを確認する総当たりの方法は、1 から上のすべての整数 i を試し、i の 2 乗が n に等しいかどうかをテストすることです。 これは正しく機能しますが、1000 の 2 乗は 1,000,000 で制約制限をわずかに超えるため、可能な最大平方根は最大でも 1000 であるため、不要です。 このブルートフォースはすでに小さいものですが、平方根の直接的な数学的構造を無視しているため、概念的には劣っています。 

より良いアプローチは、組み込みの整数平方根または二分探索を使用して n の整数平方根を計算し、それを二乗することで n が再現されるかどうかを検証することです。 これにより、浮動小数点の問題が完全に回避され、決定的なチェックが行われます。 

桁の合計は 10 進数表現に対して 1 回のパスで計算され、同じ二乗チェック ロジックが再度適用されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース sqrt スキャン | O(√n) | お(1) | 受け入れられるが不要 |
 | 整数の 2 乗チェック + 桁の合計 | O(log n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 整数 y を入力として読み取ります。 これは私たちが直接評価する候補年です。 
2. 最後の桁の抽出と累積を繰り返して、y の桁の合計を計算します。 これにより、年の加法構造を表す 2 番目の数値 s が得られます。 
3. 整数演算を使用して r = Floor(sqrt(y)) を計算します。 次に、r * r が y に等しいかどうかを確認します。 そうでない場合、y は完全な正方形ではないため、すぐに拒否できます。 この手順により、浮動小数点精度の問題が回避されます。 
4. s に対して同じ平方検証を繰り返します。 t = Floor(sqrt(s)) を計算し、t * t が s に等しいかどうかを確認します。 これにより、桁の合計も構造的に完全な正方形になります。 
5. 両方のチェックに合格した場合は Yes を出力し、そうでない場合は No を出力します。 

### なぜ効果があるのか

正確さは 2 つの独立した特徴付けに基づいています。 数値が完全二乗であるのは、その整数の平方根を平方根に戻すと元の値が再現される場合に限ります。 すべての演算は整数ベースであるため、これにより近似エラーが完全に回避されます。 桁の和の変換は二乗プロパティとは独立しているため、個別に検証しても最初の条件には影響しません。 両方の条件は個別に必要十分であるため、それらの結合は問題の要件と正確に一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def is_square(x: int) -> bool:
    if x < 0:
        return False
    r = int(x ** 0.5)
    return r * r == x or (r + 1) * (r + 1) == x

y = int(input().strip())

digit_sum = 0
tmp = y
while tmp > 0:
    digit_sum += tmp % 10
    tmp //= 10

if is_square(y) and is_square(digit_sum):
    print("Yes")
else:
    print("No")
```機能`is_square`浮動小数点平方根を使用しますが、両方をチェックすることで考えられる丸め誤差を修正します。`r`そして`r+1`。 これは重要です。なぜなら、float からの直接キャストは、大きな正方形の近くで精度の限界が原因で切り捨てられる場合があるからです。 The digit sum computation is done iteratively to avoid string conversion overhead, though either method would be acceptable given the constraints.

 最後の条件は両方のチェックを直接結合し、両方のプロパティが同時に保持する必要がある論理要件に一致します。 

## 実用的な例

 ### 例 1: 2025 年

 桁の合計と平方ステータスを段階的に計算します。 

| ステップ | y | 桁の合計 | sqrt(y) チェック | sqrt(合計) チェック |
 | --- | --- | --- | --- | --- |
 | 開始 | 2025年 | 0 | - | - |
 | 数字スキャン後 | 2025年 | 9 | - | - |
 | スクエアチェックy | 2025年 | 9 | True (45² = 2025) | - |
 | 平方チェックサム | 2025年 | 9 | 本当 | 真 (3² = 9) |

 これにより両方の条件が同時に確認されるため、出力は Yes になります。 

### 例 2: 999999

 | ステップ | y | 桁の合計 | sqrt(y) チェック | sqrt(合計) チェック |
 | --- | --- | --- | --- | --- |
 | 開始 | 999999 | 0 | - | - |
 | 数字スキャン後 | 999999 | 54 | - | - |
 | スクエアチェックy | 999999 | 54 | 偽 | - |

 Since the first condition already fails, we stop early and return No. The digit sum being 54 is irrelevant once the first condition is violated, but even if checked, 54 is not a perfect square.

 これらのトレースは、拒否がどちらの条件でも独立して発生する可能性があることを示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    return main()

def main():
    import sys
    input = sys.stdin.readline

    def is_square(x: int) -> bool:
        if x < 0:
            return False
        r = int(x ** 0.5)
        return r * r == x or (r + 1) * (r + 1) == x

    y = int(input().strip())

    digit_sum = 0
    tmp = y
    while tmp > 0:
        digit_sum += tmp % 10
        tmp //= 10

    return "Yes" if is_square(y) and is_square(digit_sum) else "No"

# provided samples
assert run("2025\n") == "Yes"
assert run("999999\n") == "No"

# custom cases
assert run("1\n") == "Yes"   # 1 is 1^2, digit sum 1 is 1^2
assert run("2\n") == "No"    # not a square
assert run("16\n") == "No"   # 16 is square but digit sum 7 is not
assert run("81\n") == "Yes"  # 81=9^2, digit sum 9=3^2
```| テスト入力 | 期待される出力 | 検証内容 |

 | 1 | はい | 最小の有効な正方形の場合 |
 | 2 | いいえ | 非正方形の拒否 |

 ## 特殊なケース

 The smallest meaningful input is 1. The algorithm computes digit sum as 1 and correctly identifies both conditions as true since 1 is a perfect square.

 2 の場合、桁の合計は 2 になり、平方チェックはすぐに失敗します。 正方形チェックでは整数比較が使用されるため、浮動小数点エラーによって誤って正方形として分類されることはありません。 

16 の場合、4 の 2 乗は 16 であるため、数値は平方テストに合格しますが、桁の合計は 7 になります。2 番目のチェックでは正しく拒否されます。 

81 の場合、両方のチェックがきれいに合格します。 平方根は 9、桁の和も 9 で、どちらも 3 の 2 乗になります。 これにより、独立したチェックが干渉せず、両方が同時に満たされる必要があることが確認されます。
