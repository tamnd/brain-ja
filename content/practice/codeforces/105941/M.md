 ## 解決策
 ## 問題の理解

 次のような無向グラフが与えられます。`n`ノードと`m`既存の接続。 システムが損傷しているため、これらの接続には重複、サイクル、さらには無駄な自己ループが含まれる可能性があります。 ターゲット構成は、任意のノードのペア間に 1 つの単純なパスを持つ単一の接続された構造であり、すべてのノードのツリーに相当します。`n`ノード。 

1 回の操作で、欠落しているエッジを挿入することも、既存のエッジを削除することもできます。 目標は、そのような操作を最小限に抑えて、現在のグラフを有効なツリーに変換することです。 

出力は単一の整数、つまり必要なエッジの挿入と削除の最小数です。 

この制約により、最大 100 万個のノードとエッジが許可されます。 これにより、変換をシミュレートしたり、変更のたびに接続を再計算したりするソリューションは即座に除外されます。 オペレーションごとの線形時間戦略さえ不可能です。 構造は、通常、ほぼ線形の複雑さで、入力上の単一パスに削減する必要があります。`O(n + m)`。 

微妙な問題は、入力グラフがすでに切断されており、コンポーネント内に冗長なエッジが含まれている可能性があるという事実から生じます。 エッジのみをカウントする単純な戦略`n - 1`グラフが切断されている場合は失敗します。 

たとえば、次のように仮定します。`n = 4`そして、次の 2 つのコンポーネントがあります。`{1,2}`そして`{3,4}`、エッジは`(1,2)`のみ。 それから`m = 1`ですが、コンポーネントを接続する必要があるため、グラフには最終的なツリー構造内のエッジがまだ 1 つありません。 使い方を間違えると`max(0, m - (n - 1))`、答えは次のようになります`0`少なくとも 1 つのエッジを追加する必要があるため、これは間違っています。 

もう 1 つのエッジ ケースは自己ループです。 グラフに次のようなエッジが含まれている場合`(u, u)`、接続性には何も寄与しませんが、最適な変換で削除する必要がある余分なエッジとしてカウントされます。 これらを無視すると、削除が過小評価されることになります。 

## アプローチ

 この問題を直接考える方法は、グラフを最初から完全に再構築できると想像することです。 ターゲットは任意の木なので、正確に終了する必要があります`n - 1`すべてのノードをサイクルなしで接続するエッジ。 

この観点から、1 つの総当り戦略は、サイズのエッジの可能なサブセットをすべて列挙することです。`n - 1`、それらがスパニング ツリーを形成しているかどうかを確認し、元のグラフをそのサブセットに変換するために必要な編集の数を計算します。 これは概念的には正しいですが、完全に実行不可能です。 エッジサブセットの数は組み合わせによるものです`m`、サブセットごとの接続性のチェックも線形であるため、指数関数的な爆発につながります。 

重要な点は、実際には特定の最終ツリーを選択する必要がないということです。 現在のグラフが 1 つのスパニング ツリー構造からどれだけ離れているかを知る必要があるだけです。 これは 2 つの独立した効果に分かれます。 

まず、各接続コンポーネント内では、ツリーを形成するのに十分なエッジのみが必要です。 コンポーネントに`k`ノード、スパニングツリーは正確に使用します`k - 1`エッジ。 すべてのコンポーネントを合計すると、サイクルを作成せずに残すことができるエッジの最大数は次のようになります。`n - c`、 どこ`c`接続成分の数です。 

次に、それを超える余分なエッジを削除し、コンポーネントを接続するために必要な不足しているエッジを追加する必要があります。 したがって、削除の数は次のようになります。`m - (n - c)`、これは、広がるフォレストを越えるすべてのエッジを破棄する必要があるためです。 挿入数は、`c - 1`、接続する必要があるため、`c`コンポーネントを 1 つのツリーに統合します。 

これらを追加すると最終的な式が得られます`m - (n - c) + (c - 1)`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべてのツリーに対するブルートフォース | 指数 | O(n + m) | 遅すぎる |
 | DSU + コンポーネントの式 | O(n + m) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、目標の構造を無視して、グラフに現在いくつの連結成分があるかを理解する必要があります。 これは、すべてのエッジを処理する際に、Disjoint Set Union 構造を使用して実行できます。 

1. 各ノードが自身の親となる DSU を初期化します。 これは、各ノードが独立したコンポーネントとして開始されることを表します。 
2. すべてのエッジを反復処理します。`(u, v)`。 もし`u != v`、それらのコンポーネントを DSU にマージします。 自己ループはコンポーネントの数を決して減らすことがないため、接続の目的では無視されます。 
3. すべてのエッジを処理した後、存在する個別の DSU ルートの数を数えます。 この数値は連結成分の数です`c`。 
4. サイクルを形成せずに残ることができるエッジの数を計算します。 森の上`n`ノード`c`コンポーネントには最大でも含めることができます`n - c`エッジ。 
5. 欠失を次のように計算します。`m - (n - c)`余分なエッジはすべて削除する必要があるためです。 
6. 加算を次のように計算します。`c - 1`接続してから`c`コンポーネントを 1 つのツリーにまとめるには、常にその数のエッジが必要になります。 
7. 削除と追加の合計を出力します。 

なぜそれが機能するのかは、森林の構造に関係しています。 サイズの接続されたコンポーネント`k`には厳しい上限があります`k - 1`非循環のままにしておく必要がある場合はエッジを使用します。 コンポーネントを合計すると、グローバルな上限が与えられます。`n - c`。 この境界を超えるすべてのエッジは必ずどこかにサイクルを導入し、ツリー変換ではすべてのサイクル エッジを削除する必要があります。 フォレストに縮小されると、各コンポーネントは単一のスーパーノードのように動作し、接続します。`c`スーパーノードを単一のツリーにするには、正確に必要です`c - 1`新しいエッジごとにコンポーネントの数がちょうど 1 つ減るため、これは最小限になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n + 1))
        self.size = [1] * (n + 1)
        self.components = n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return
        if self.size[ra] < self.size[rb]:
            ra, rb = rb, ra
        self.parent[rb] = ra
        self.size[ra] += self.size[rb]
        self.components -= 1

def solve():
    n, m = map(int, input().split())
    dsu = DSU(n)

    for _ in range(m):
        u, v = map(int, input().split())
        if u != v:
            dsu.union(u, v)

    c = dsu.components

    deletions = m - (n - c)
    additions = c - 1

    print(deletions + additions)

if __name__ == "__main__":
    solve()
```DSU は、エッジを 1 回スキャンしている間、接続情報を維持します。 コンポーネント数は増分的に追跡されるため、入力後のグラフの走査を回避します。 

最終的な式は一度直接適用されます`c`知られています。 構造解析 (コンポーネント) と算術調整 (編集操作) を分離することで、ソリューションを線形に保つことができます。 

## 実用的な例

 次のグラフを考えてみましょう`n = 5`そしてエッジ`(1,2), (2,3), (4,5)`。 コンポーネントは次のとおりです。`{1,2,3}`そして`{4,5}`、 それで`c = 2`。 

DSU の進化を追跡します。 

| ステップ | エッジ | コンポーネント | c |
 | --- | --- | --- | --- |
 | 1 | (1,2) | {1,2}、{3}、{4}、{5} | 4 |
 | 2 | (2,3) | {1,2,3}、{4}、{5} | 3 |
 | 3 | (4,5) | {1,2,3}、{4,5} | 2 |

 加工後、`c = 2`。 欠失を次のように計算します。`m - (n - c) = 3 - (5 - 2) = 0`、および追加として`c - 1 = 1`。 結果は`1`これは、2 つのコンポーネントを接続するだけでよいという直観と一致します。 

ここで、完全に接続された三角形と追加のエッジを考えてみましょう。`n = 3`、エッジ`(1,2), (2,3), (1,3), (1,2)`。 このグラフには、`c = 1`。 

| ステップ | エッジ | c |
 | --- | --- | --- |
 | すべて処理済み | 重複したエッジを持つ三角形 | 1 |

 削除を受けます`m - (n - c) = 4 - (3 - 1) = 2`、追加`0`。 これは、サイクルと重複を排除するには 2 つのエッジを削除する必要があることを反映しています。

## 特殊なケース

 単一ノード グラフはすでにツリーになっているため、DSU は次のようにレポートします。`c = 1`、`m = 0`、操作はゼロです。 削除項と追加項の両方が消えるため、アルゴリズムは当然 0 を返します。 

完全に空のエッジセット`n > 1`生成する`c = n`。 式は次のようになります。`m - (n - c) = 0`削除と`c - 1 = n - 1`これは、分離されたノードからスパニング ツリーを構築する必要性に一致します。 

サイクルのみで構成されるグラフは単一のコンポーネントに折りたたまれます (`c = 1`）。 その後、アルゴリズムは正確に削除します`m - (n - 1)`エッジ。これは、すべてのサイクルをツリーに分割することに相当します。
