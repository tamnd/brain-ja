 ## 解決策
 ## 問題の理解

 正の整数に対して無限の無向グラフを構築するルールが与えられています。 それぞれの整数がノードです。 ノードの場合$n$、値を定義します$f(n) = n(n+1)$。 ノードが存在するときはいつでも$a, b$そのような$$f(n) = f(a)\cdot f(b),$$ノードを接続します$n$両方に$a$そして$b$方向のないエッジを持つ。 これはクエリごとの動的なプロセスではなく、グラフはすべての整数に対するこのルールによって完全に定義されます。 

各クエリは開始ノードを選択します$s$、値の範囲内のノードの数を尋ねます$[l, r]$から到達可能です$s$このグラフでは。 

問題は、グラフが関数の乗法関係を通じて暗黙的に定義されていることです。$f(n)$、まであります$10^5$最大値を含むクエリ$10^9$したがって、グラフの走査をシミュレートしたり、隣接関係を明示的に構築したりすることはできません。 

単純なアプローチでは、接続されたコンポーネントを次から拡張しようとします。$s$ただし、単一のノードでも多くの因数分解に分岐する可能性があります。$f(n)$、値は約まで成長します$10^{18}$。 そのため、すでに直接 BFS や DFS は不可能になっています。 

2 番目の微妙な問題は、到達可能性がローカルではないことです。$n$、それは因数分解構造内で局所的です。$f(n)$。 数値的に近い 2 つの数字は、それらが一致しない限り、完全に切り離される可能性があります。$f$-値は乗算的に整列します。 

構造を明らかにする小さなエッジケースがサンプルアイデアです。$f(3)=12$、 そして$12=2\cdot 6 = f(1)\cdot f(2)$、ノード$3$に接続します$1$そして$2$。 それでも$3$～と「数値的に関連」していない$1$または$2$、接続性は純粋に因子構造によって決まります。 

したがって、実際のタスクは、接続されているコンポーネントを特徴付けることです。$s$の算術的性質の観点から$f(s)$、次にノードの数を数えます。$[l,r]$その特徴を満たします。 

## アプローチ

 ブルートフォースの観点は、ノードから明示的にグラフを構築することです。$s$因数分解を繰り返す$f(n)$考えられるすべてのペアに$f(a)f(b)$、エッジを追加し、BFS/DFS を実行します。 これは、到達可能性の定義に直接従うため、原則として正しいです。 

失敗は組み合わせ爆発です。 から到達可能なノードのみを考慮した場合でも、$s$、検出された各ノード$n$のすべての因数分解を導入します$f(n)$、および値$f(n)$の順序です$n^2$。 これらを因数分解して組み合わせることを繰り返すと、フロンティアが急速に成長します。 横切って$10^5$クエリでは、これは完全に不可能になります。 

重要な観察は、エッジが純粋に次の乗算分解によって定義されるということです。$f(n)$。 つまり、接続は方法にのみ依存します。$f(s)$要素の幾何学的構造ではなく、$n$自体。 

ノードの場合$n$から到達可能です$s$からの道に沿って、$s$に$n$、すべてのステップは一部を分割することに対応します。$f(x)$2つの要因に分かれます。 これは、到達可能なすべてのノードが、次から導出される因子構造に対応することを意味します。$f(s)$、そして実際に唯一到達可能なのは$n$のためのものです$f(n)$分割する$f(s)$。 逆方向も成り立ちます。$f(s)$分割を繰り返すことで得られる$f(s)$有効に$f(\cdot)$- パスに沿った値。 

したがって、問題は次のようになります: 各クエリについて、因子$F = f(s) = s(s+1)$、すべての約数を列挙します$d$の$F$、そしてそれ自体が次のように書ける約数を数えます。$d = f(n) = n(n+1)$と$n \in [l,r]$。 

これにより、問題はグラフの到達可能性から除数の列挙と単純な二次チェックに変換されます。

 ## アルゴリズムのチュートリアル

 各クエリを個別に処理します。 

1. コンピューティング$F = s(s+1)$。 これは、到達可能なコンポーネントを完全に決定する重要な不変値です。$s$なぜなら、すべての到達可能性はこの数値の因子構造に帰着するからです。 
2. 要因$F$因数分解によって$s$そして$s+1$別に。 これら 2 つの数値は互いに素であるため、素因数分解が重複せず、除数の構築が簡素化されます。 
3. すべての約数を生成する$d$の$F$素因数分解から。 各約数は次の候補値を表します。$f(n)$到達可能なノードの場合。 
4. 各約数について$d$、有効なノード インデックスに対応するかどうかを確認します。$n$。 これには解決が必要です$$n(n+1) = d.$$判別式を計算します$D = 1 + 4d$。 もし$D$は完全な正方形であり、$(-1 + \sqrt{D})$偶数であれば、$n = (\sqrt{D}-1)/2$は整数の候補です。 
5.その場合$n$存在し、そこに横たわっている$[l,r]$、回答に含めてください。 
6. 合計数を返します。 

### なぜ効果があるのか

 グラフの構築では、エッジが 1 つの場合のみ許可されます。$f$-value は、積がそれに一致する他の 2 つに分割されます。 これにより、到達可能なノードが内部の因子構造に強制的に対応します。$f(s)$、すべてのステップで乗法分解が保存されるためです。 なぜなら$s$そして$s+1$は互いに素であり、すべての因数分解は$f(s)$は、2 つの部分の独立した因数分解の正確な組み合わせであるため、到達可能なすべての$f(n)$の約数でなければなりません$f(s)$、そのようなすべての約数は、到達可能な構造に対応します。 二次チェックにより有効なマッピングが行われます。$f(n)$値を一意のノード インデックスに戻します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import math
from collections import defaultdict

# sieve for primes up to sqrt(1e9)
N = 31650
is_prime = [True] * N
is_prime[0] = is_prime[1] = False
primes = []
for i in range(2, N):
    if is_prime[i]:
        primes.append(i)
        for j in range(i*i, N, i):
            is_prime[j] = False

def factor(x):
    res = defaultdict(int)
    for p in primes:
        if p * p > x:
            break
        while x % p == 0:
            res[p] += 1
            x //= p
    if x > 1:
        res[x] += 1
    return res

def gen_divisors(items, i=0):
    if i == len(items):
        yield 1
        return
    p, e = items[i]
    sub = list(gen_divisors(items, i + 1))
    cur = 1
    for _ in range(e + 1):
        for v in sub:
            yield v * cur
        cur *= p

def is_square(x):
    r = math.isqrt(x)
    return r * r == x

def solve():
    T = int(input())
    for _ in range(T):
        s, l, r = map(int, input().split())

        F = s * (s + 1)

        fac_s = factor(s)
        fac_t = factor(s + 1)

        total = defaultdict(int)
        for k, v in fac_s.items():
            total[k] += v
        for k, v in fac_t.items():
            total[k] += v

        items = list(total.items())

        ans = 0
        seen_n = set()

        # generate divisors iteratively
        def dfs(i, cur):
            nonlocal ans
            if i == len(items):
                d = cur
                D = 1 + 4 * d
                if is_square(D):
                    rt = math.isqrt(D)
                    if (rt - 1) % 2 == 0:
                        n = (rt - 1) // 2
                        if l <= n <= r:
                            if n not in seen_n:
                                seen_n.add(n)
                                ans += 1
                return

            p, e = items[i]
            val = 1
            for _ in range(e + 1):
                dfs(i + 1, cur * val)
                val *= p

        dfs(0, 1)
        print(ans)

if __name__ == "__main__":
    solve()
```実装は、以下の素数を準備することから始まります。$31650$、これは、以下の値を因数分解するのに十分です。$10^9$。 各クエリ要素$s$そして$s+1$それぞれの素指数を個別にマージし、指数選択に対して DFS を実行して、すべての約数を列挙します。$F$。 

各約数について、次のように表現できるかどうかをテストします。$n(n+1)$判別条件を使って。 これにより列挙が回避されます$n$直接、すべてを算術チェック内に保持します。 

小さいながらも重要な点は、理論的には異なる除数パスを同じものにマッピングできるため、セットを使用した重複排除です。$n$、そして問題は一意のノードを要求します。

 ## 特殊なケース

 エッジケースの 1 つは次のような場合です$s = 1$。 ここ$f(s)=2$は約数が非常に少なく、到達可能な唯一の構造は非常に限られた因数分解から得られます。 除数の列挙は一定サイズのセットに縮退するため、アルゴリズムはこれをきれいに処理します。 

もう一つのケースは次のような場合です。$s$プライムであり、$s+1$高度に複合的です。 因数分解は素の構造をマージしますが、分割したため、$s$そして$s+1$独立して、正確性の問題は発生しません。 

最後のエッジケースは次のような場合です$d$非整数を生成します$n$。 例えば$d=1$判別式を与える$5$、正方形ではないため、正確さに影響を与えることなく安全に破棄されます。
