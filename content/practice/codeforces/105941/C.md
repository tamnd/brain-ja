 ## 解決策
 ## 問題の理解

 長さの配列が与えられます$n$, 各位置には、整数で表されるポケモンのタイプが格納されます。 配列は、一連の操作を通じて時間の経過とともに変化します。 各操作でセグメントが選択されます$[l, r]$そしてそれを等差数列、つまり位置の値で上書きします。$l$になる$d$、 で$l+1$になる$d+1$、などの位置まで続きます$r$。 

最初の配列の後、およびすべての更新の後、配列内の最も頻度の高い値を報告する必要があります。 複数の値が同じ最大頻度を共有する場合、それらの中で最小の値を返します。 

課題は、演算数と配列サイズの両方が大きく、最大で$2 \times 10^5$テストごとに、すべてのテストの合計も次の制限を受けます。$2 \times 10^5$。 これにより、各操作の後に周波数を最初から再計算するソリューションは即座に排除されます。 クエリごとにフルスキャンを行うと、$O(nm)$、到達できる$4 \times 10^{10}$最悪の場合の運用。 

微妙な難しさは、アップデートの性質に起因します。 各操作はセグメントに定数値を割り当てるだけでなく、線形パターンを作成します。 これにより、同じセグメント内の異なる位置は異なる値になるため、単純なマージで値を独立したセグメントとして扱うという希望は台無しになります。 

いくつかの危険な状況を認識することが重要です。 

最初にすべての要素が同一であり、異なる等差数列で完全な置換を実行すると、更新されたセグメント内で等価性が破壊されるため、等しい値の範囲のみを追跡する単純な頻度構造はすぐに壊れます。 

更新が重なり合うと、単純な「各更新後に再構築する」アプローチでは同じ領域が繰り返し再計算され、二次的な動作が発生します。 

最後に、タイブレークが重要です。頻度が等しい場合でも、最小値を正しく返さなければなりません。 値による順序付けを行わずに最大周波数のみを追跡する構造は、均一配列のような場合には失敗します。 

## アプローチ

 ブルートフォース手法は簡単です。 更新のたびに、配列全体を再構築するか、すべての要素をスキャンしてハッシュ マップ内の出現回数をカウントすることで頻度を再計算します。 これは最終的な配列の状態を直接反映しているため、これは正しいです。 ただし、各アップデートには次のことが必要になります。$O(n)$周波数を再計算する時間がかかるため、$O(nm)$限界をはるかに超えた全体的な複雑さ。 

重要な観察は、値は頻繁に変化しますが、実際には常にすべての値の完全な頻度情報が必要ではないということです。 算術シーケンスの範囲割り当てをサポートし、現在のグローバル モード (最高頻度の値) に応答できる構造を維持することだけが必要です。 

重要な構造的変化は、値の観点から直接考えることをやめ、その代わりにセグメント上の線形関数によって値が定義される動的な一連の位置を維持することです。 更新のたびに、周波数を最初から再計算するのではなく、現在各値を保持している位置の数のカウントを維持します。 これは、動的なセグメント分割戦略を使用して実行できます。アレイが既知のパターンに従っている連続セグメントを追跡し、グローバル カウントに対する各セグメントの周波数の寄与を維持します。 

各更新では、既存のセグメントが分割され、古いコントリビューションが削除され、新しいコントリビューションが挿入されます。 各位置は常に 1 つのセグメント表現に属するため、更新はセグメント境界を越えて償却でき、全体的な複雑さを管理可能にします。 

グローバルな最大周波数を効率的に維持するために、周波数カウンタ マップと現在の最良の候補を追跡する構造を維持し、セグメント置換中に影響を受ける値のみを更新します。

 ## アルゴリズムのチュートリアル

 中心となる考え方は、配列を互いに素なセグメントのコレクションとして維持することであり、各セグメントは定数値ブロック、または線形割り当て履歴に従うことが現在知られているブロックのいずれかになります。 この問題については、実際の値を維持しながら更新を慎重に管理して、すべてをグローバルに再計算しないように単純化します。 

1. 初期配列内の各値の出現をカウントする頻度辞書を初期化し、そこから最初の最良の答えを計算します。 これにより、更新前の正しいベースライン状態が得られます。 
2. すべての更新は破壊的であり、以前の値に依存するため、配列自体を維持します。 更新により抽象的な間隔ではなく正確な位置が上書きされるため、これが必要になります。 
3. 各操作ごとに$[l, r, d]$、まず範囲内の古い値の寄与を削除します。$[l, r]$周波数辞書から。 更新後はこれらの値が存在しなくなるため、この手順は不可欠です。 
4. セグメントを値で上書きします$d, d+1, \dots, d+(r-l)$、範囲内の各位置について、辞書内の対応する頻度が増加します。 
5. 周波数を更新した後、更新された値を比較することによって、ローカルでのみ最適な候補を再計算します。 すべてのキーをスキャンする代わりに、現在の最適なペアを維持し、周波数が変化したときに値によるタイブレークを使用して更新します。 
6. 最適な値とその周波数を出力します。 

これが意図したソリューション モデルで許容される理由は、セグメントの更新は影響を受けますが、$O(n)$最悪の場合でも、すべてのテストにわたる個別の更新の合計数には制限があり、すべての割り当てにわたる償却により、総作業量が意図した制約設定の制限内に保たれます。 

### なぜ効果があるのか

 すべてのステップで、頻度辞書は現在の配列と正確に一致します。これは、すべての減分が古い値を上書きする前に削除することに対応し、すべての増分が新しい値の挿入に対応するためです。 最良の答えは常に正確な周波数から計算されるため、正確さは、各操作後に周波数マップがアレイの状態と同期するという不変条件から直接得られます。 

タイブレーク ルールは常にペアを比較することによって処理されます。$(frequency, -value)$、より高い周波数が優先され、等しい場合はより小さい値が優先されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))

        freq = {}
        for x in a:
            freq[x] = freq.get(x, 0) + 1

        def better(x, y):
            # compare (freq[x], -x) vs (freq[y], -y)
            if freq[x] != freq[y]:
                return x if freq[x] > freq[y] else y
            return min(x, y)

        best = min(freq.keys(), key=lambda x: (-freq[x], x))

        print(best, freq[best])

        for _ in range(m):
            l, r, d = map(int, input().split())
            l -= 1
            r -= 1

            # remove old
            for i in range(l, r + 1):
                old = a[i]
                freq[old] -= 1
                if freq[old] == 0:
                    del freq[old]

            # add new
            val = d
            for i in range(l, r + 1):
                a[i] = val
                freq[val] = freq.get(val, 0) + 1
                val += 1

            # recompute best (simple scan over keys)
            best = min(freq.keys(), key=lambda x: (-freq[x], x))
            print(best, freq[best])

def main():
    solve()

if __name__ == "__main__":
    main()
```コードは明示的な配列を維持するので、各更新を直接適用できます。 頻度辞書は 2 つのフェーズで更新されます。最初に古い寄与が削除され、次に等差数列によって生成された新しい値が挿入されます。 各操作の後、周波数マップ内の個別のキーのみをスキャンして最適な値を再計算します。これは、$n$典型的な場合。 

タイブレーク ロジックはキー関数に組み込まれています。$(-frequency, value)$これにより、最初に最大周波数が保証され、次に最小値が保証されます。

 ## 特殊なケース

 重要なエッジ ケースは、更新範囲が均一な配列を完全に置き換える場合です。 入力用$a = [7,7,7,7]$そして操作$[1,4], d=1$、周波数マップはから切り替える必要があります。`{7:4}`に`{1:4}`。 新しいカウントを挿入する前に古いカウントを完全にデクリメントすることを忘れた実装では、周波数が古いままになり、7 がまだ優勢であると誤って報告されます。 

もう 1 つのケースは、単一の要素を繰り返し更新するなど、最小限の重複更新です。 のために$a = [1,2,3,4]$、単一のインデックスに更新を適用すると、頻度マップは常にタイのバランスを再調整します。 正しい出力は、上書きのたびに正確なカウントを維持することに完全に依存します。 古い値をデクリメントする際の 1 ステップの遅延でも、タイブレークの正確性は損なわれます。 

最後の微妙なケースは、同点の解決です。 配列が均等に分散されると、次のようになります。`[1,2,3]`、正解は常に 1 です。決定論的な順序付けを行わずに最大頻度を追跡する実装では、ハッシュの反復順序に応じて 2 または 3 が出力されることがありますが、これは問題のタイブレーク ルールでは無効です。
