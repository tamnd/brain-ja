 ## 解決策
 ## 問題の理解

 長さのシーケンスが与えられます$n$、各要素は範囲内の整数です。$[0, m-1]$。 許可される主要な操作はグローバル循環シフトです。単一の整数を選択します。$k$、およびすべての要素$a_i$に置き換えられます$(a_i + k) \bmod m$。 このシフトは配列全体に均一に適用されるため、要素間の相対的な差は同じままで、モジュラー リング上の絶対位置のみが変化します。 

各整数は、独立して定義された値に寄与します。数値を 10 進表現に変換し、各桁に固定の「ホール カウント」を割り当て、数値のすべての桁にわたってこれらの値を合計します。 配列の合計スコアは、すべての要素のホール数の合計です。 シフト適用後$k$、このスコアを再計算し、すべての中で可能な最大値を求めます。$k \in [0, m-1]$。 

入力サイズの制約は、両方のことを意味します。$n$そして$m$と同じ大きさにすることができます$2 \cdot 10^5$。 これにより、すべてのシフトを試行し、完全な配列スコアを最初から再計算するソリューションは即座に除外されます。$O(n)$、それは次のことにつながるため、$O(nm)$、これは大きすぎます。 シフトごとにわずかに最適化された再計算であっても、依然として遅すぎます。 

2 番目に重要な側面は、値がポジションに対する任意の重みではないということです。 それらはシフト後の数値の値にのみ依存します。 これにより、構造が高度に規則的になります。すべての要素が、あるサイズの環状リング上の 1 つの位置に正確に寄与します。$m$、シフトすると、すべての寄与が一緒に回転するだけです。 

素朴だが微妙な間違いは、たとえば要素ごとに最適な個々のシフトを事前に計算することによって、シフト後に要素全体で独立性があると仮定することです。 同じグローバル シフトをすべての要素に同時に適用する必要があるため、これは失敗します。 もう 1 つのよくある落とし穴は、周波数分布をグローバルに回転させるのではなく、シフトによって値が独立して再分布されるかのように問題を扱うことです。 

これを具体的にするために、次のように仮定します。$m = 5$そして配列は$[1, 3, 3]$。 間違ったアプローチでは、要素ごとに最適なシフトを個別に計算する可能性がありますが、$k = 1$すべての値を一度に変更して、$[2, 4, 4]$、スコアは要素ごとの最適化ではなく、このジョイント構成に依存します。 

## アプローチ

 ブルートフォースのアイデアは単純明快です: あらゆる可能なシフトに対して$k$、変換された配列を計算し、穴の数を合計します。 それぞれについて$k$、これにはかかります$O(n)$、そして、あります$m$シフト、与える$O(nm)$。 と$n, m \le 2 \cdot 10^5$、これは次のことにつながります$4 \cdot 10^{10}$最悪の場合は操作が不可能になります。 

これを改善するために、計算を再編成します。 要素の移動という観点から考えるのではなく、視点を反転し、サイズの円の周りを流れる貢献という観点から考えます。$m$。 させて$cnt[x]$値の何倍になるか$x$が表示されるので、$f[x]$整数の穴数になる$x$。 シフト後$k$、値が出現するたびに$x$に移動します$x+k \bmod m$、貢献$f[x+k]$。 したがって、シフトの合計スコアは$k$は循環相関になります。$$g[k] = \sum_{x=0}^{m-1} cnt[x] \cdot f[(x+k) \bmod m]$$これは円形の畳み込みのような構造です。 重要な洞察は次のとおりです$g$は、標準的な畳み込みトリックを使用して効率的に計算できます。配列を拡張し、2 倍の領域で 1 つの畳み込みを使用することにより、循環依存関係を線形依存関係に変換します。 線形畳み込みを計算すると、各巡回シフトの合計は、畳み込み出力に対するスライディング ウィンドウの合計を介して回復できます。 

これにより、問題は、次のサイズの 1 つの畳み込みを計算することになります。$2m$で実行できます。$O(m \log m)$実際には FFT または NTT スタイルの方法を使用します (ここでは概念的には FFT で十分です)。

 | コンボリューション (FFT) |$O(m \log m)$|$O(m)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列内の各値の出現を配列にカウントします。$cnt$サイズの$m$。 これにより入力が周波数表現に圧縮されますが、シフトするだけで値が並べ替えられるため、これで十分です。 
2. 穴数関数を事前計算する$f[x]$みんなのために$x \in [0, m-1]$。 これは、各数値の桁の寄与を個別に合計することによって行われます。 このステップでは、桁プロパティをシフト構造から分離します。 
3. 寄与の重みを表す 2 番目の配列を構築します$f[x]$。 これは、循環ドメインに対するスコアリング関数として機能します。 
4.次の間の線形畳み込みを構築します。$cnt$そして$f$、両方をモジュロではなく整数のシーケンスとして扱います$m$。 これにより配列が生成されます$h$ここで、各インデックスは、インデックスの合計がその位置となるすべてのペアからの寄与を集計します。 
5. 巡回シフトをこの線形畳み込みのラップされたセグメントとして解釈します。 シフトごとに$k$、必要な値$g[k]$の連続セグメントを合計することで得られます。$h$長さの$m$、具体的にはインデックスから$k$に$k + m - 1$。 
6. これをプレフィックスの合計に変換します。$h$、それでそれぞれ$g[k]$前処理後は一定時間で取得できます。 
7. すべての最大値を返します$g[k]$。 

### なぜ効果があるのか

 核となる不変条件は、すべてのペアが$(x, i)$、 どこ$x$は配列内の値であり、$i$は桁寄与インデックスであり、シフトされた 1 つの構成で 1 回だけカウントされます。 畳み込みは、周波数とシフトされたスコアリング位置の間のすべてのペアごとの相互作用をエンコードします。 畳み込み出力のスライディング ウィンドウは、二重カウントや省略なしで周期的なラップアラウンドを再構築します。 畳み込みはすべてのインデックスの合計を徹底的に列挙し、ウィンドウ処理ではこれらの合計を巡回同値クラスに正確に分割するため、シフトごとに$k$これは、貢献の素かつ完全な集約に相当します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def hole_count(x):
    # standard digital hole mapping assumption:
    # 0->1, 4->1, 6->1, 8->2, 9->1 (others 0)
    mp = {'0':1, '4':1, '6':1, '8':2, '9':1}
    return sum(mp.get(c, 0) for c in str(x))

def fft_convolution(a, b):
    import numpy as np
    n = 1
    while n < len(a) + len(b) - 1:
        n <<= 1
    fa = np.fft.rfft(a, n)
    fb = np.fft.rfft(b, n)
    fc = fa * fb
    c = np.fft.irfft(fc, n)
    return [int(round(x)) for x in c]

def main():
    n, m = map(int, input().split())
    arr = list(map(int, input().split()))

    cnt = [0] * m
    for x in arr:
        cnt[x] += 1

    f = [0] * m
    for i in range(m):
        f[i] = hole_count(i)

    # linear convolution
    h = fft_convolution(cnt, f)

    # prefix sums for cyclic reconstruction
    for i in range(1, len(h)):
        h[i] += h[i - 1]

    best = 0
    for k in range(m):
        total = h[k + m - 1] - (h[k - 1] if k > 0 else 0)
        best = max(best, total)

    print(best)

if __name__ == "__main__":
    main()
```この実装では、まず配列を頻度表に圧縮します。これにより、シフトは個々の要素には依存せず、各値が出現する回数のみに依存するようになります。 ホールカウント機能は桁構造を分離し、モジュラーシフトロジックから独立させます。 

畳み込みステップは、循環シフト問題を単一の多項式乗算に置き換える核となる変換です。 結果の配列は、元の値とシフトされたターゲット値の間のすべてのペアごとの相互作用をエンコードします。 各シフトがこの線形化された表現上のラップされた間隔に対応するため、プレフィックス合計ステージが必要です。 

微妙な点は、浮動小数点 FFT が使用されるため、整数の畳み込み結果を確実に復元するには丸めが必要であることです。 すべての中間値が整数であり、一般的な制約の下では数値誤差が小さいままであるため、これは安全です。

 ## 特殊なケース

 すべての要素が同一である場合、まれなケースが発生します。 その状況では、シフトによって頻度分布は変更されませんが、どの桁の重みが適用されるかが回転します。 周波数配列にゼロ以外のエントリが 1 つしかない場合でも、畳み込みではすべての巡回アラインメントが評価されるため、アルゴリズムはこれを正しく処理します。 

もう一つの微妙なケースは次のような場合です。$m$に比べて小さい$n$。 周波数配列では多くの衝突が発生しますが、畳み込みは一意性ではなくカウントのみに依存するため、引き続き有効です。 

最後に、桁の寄与が大きく偏っている場合 (たとえば、少数の数値だけが非ゼロのホール カウントに寄与している場合)、それらの値は単に畳み込みのスパースの重みとして機能し、線形演算を通じてスパース性が維持されるため、解は依然として正しく動作します。
