 ## 解決策
 ## 問題の理解

 いくつかのテストケースが与えられています。 各テスト ケースは長さの配列を提供します$n$、すべての要素は次の範囲の整数です。$1$そして$n$。 目標は、この配列を次の順列に変換することです。$1 \ldots n$、からのすべての数字を意味します$1$に$n$最終配列に 1 回だけ出現します。 

許可される唯一の操作は、連続したセグメントを選択することです$[l, r]$そのセグメント内のすべての位置を上書きします。 セグメント内の各位置には、次のいずれかの値を割り当てることができます。$1$に$n$、他のものとは独立しているため、1 つの操作で配列のブロックを完全に再設計できます。 

タスクは、初期配列を有効な順列に変換するために必要なセグメント操作の最小数を決定することです。 

重要な点は、初期配列の構造を保持する必要はなく、順列である最終状態に到達する必要があるだけであるということです。 演算セグメント内で値を自由に割り当てることができるため、問題は、一度に 1 つの演算ブロック内でどの位置を固定するかを決定することになります。 

制約は小さいです。$n \le 40$、そしてせいぜい$10^4$テストケース。 これは、テスト ケースごとに指数関数的なシミュレーションが期待されていないことを強く示唆しています。 代わりに、テスト ケースごとの答えの構造は、線形または線形に近い時間で抽出可能でなければなりません。 

素朴な解釈は、最終的な順列を明示的に構築しようとするか、不一致を 1 つずつ貪欲に修正することです。 これは安全ですが、不必要に複雑になります。 

微妙な点の 1 つは、任意の順列が許容されるため、複数の最適な戦略が存在する可能性があることです。 これは、値の恣意的な再配置について推論するのではなく、単純な正規順列を自由にターゲットにできることを意味します。 

## アプローチ

 この問題を考える強引な方法は、最終的な順列の構築を段階的にシミュレートすることです。 各ステップで、任意のセグメントを選択して値を割り当て、配列内の競合を徐々に排除することができます。 ただし、各操作は間隔全体に影響し、割り当ての選択には制約がないため、膨大な分岐要素が発生します。 たとえ$n = 40$、考えられるすべてのセグメント シーケンスを探索することは完全に不可能です。 

重要な簡略化は、視点の変更によってもたらされます。最終的な順列にどの値が必要かを考える代わりに、特定のターゲットの順列を修正します。 最も便利な選択は恒等置換です$[1, 2, \ldots, n]$。 どのような順列も有効であるため、配列を恒等式に変換できれば完了です。 

さて、問題は純粋に位置の問題になります。 あらゆる指標を見ていきます$i$。 もし$a_i = i$、その位置はすでにターゲットと一致しており、操作は必要ありません。 もし$a_i \neq i$、次に位置を決めます$i$少なくとも 1 つの操作に含める必要があります。 

各操作は連続したセグメントをカバーするため、コストは、修正が必要なインデックスによって形成される連続したセグメントの数になります。 このような各セグメントは、その範囲を正確に上書きすることで 1 回の操作で修正できます。 

これにより、問題は、インデックスの最大の連続ブロックを特定することになります。$a_i \neq i$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | セグメント操作に対するブルート フォース | 指数 | O(n) | 遅すぎる |
 | 連続する不一致ブロックを数える | テスト ケースあたり O(n) | O(1) おまけ | 承認済み |

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. 配列を読み取り、概念的に各位置を比較します$i$そのインデックス付き。 値がすでに等しい場合$i$、それをすでに正しいものとして扱い、それに対して何も行いません。 
2. 左から右にスキャンして、現在の位置が「悪い」かどうかをマークします。$a_i \neq i$。 この分類は、答えを計算するために必要な唯一の情報です。 
3. 不良ポジションの新しい連続ブロックが開始される回数を数えます。 ブロックはその位置から始まります$i$もし$a_i \neq i$そしてどちらか$i = 1$または$a_{i-1} = i-1$。 
4. 単一の間隔操作で不正確な位置の連続範囲全体を再描画できるため、このような各ブロックは 1 つの操作に正確に対応します。 
5. これらのブロックの数をテスト ケースの答えとして出力します。 

### なぜ効果があるのか

 すべての操作は連続したセグメントのみを変更できるため、一緒に固定する位置のセットは単一の間隔内になければなりません。 逆に、不正確な位置の最大連続セグメントは、その間隔を正確に選択することで、常に 1 回の操作で修正できます。 単一の不良セグメントを複数の操作に分割してもメリットはありません。各分割は実行可能性を向上させることなく間隔の数を増やすだけであるためです。 

この結果は、コストがターゲット値とは異なるインデックスのセット内の連結成分の数と正確であるという事実からわかります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        ans = 0
        i = 0
        while i < n:
            if a[i] == i + 1:
                i += 1
                continue
            
            ans += 1
            j = i
            while j < n and a[j] != j + 1:
                j += 1
            i = j
        
        print(ans)

if __name__ == "__main__":
    solve()
```この実装は、テスト ケースごとに 1 回配列をスキャンするという考えに従っています。 不一致が見つかった場合は、不一致ブロックが終了するまで貪欲に右に拡張し、それを 1 回の操作としてカウントします。 その後、ポインタはブロックを飛び越えて、線形の複雑さを保証します。 

よくある落とし穴は、off-by-one インデックス付けです。問題は 1 ベースですが、Python は 0 ベースのインデックス付けを使用するため、比較には$a[i] == i + 1$。 もう 1 つの微妙な点は、ブロック全体を一度にスキップしなければならないことです。 ブロック内で 1 つずつインクリメントしても機能しますが、不必要に冗長になります。

これは、大きなカオスなセグメントであっても、それらが連続している場合には 1 回の再描画操作に崩壊することを示しています。

 ## 特殊なケース

 次のようなすでにソートされた配列の場合$[1,2,\ldots,n]$の場合、スキャンでは不一致ブロックが検出されず、操作が必要ないため、直接ゼロが出力されます。 

次のような完全に間違った配列の場合$[2,3,4,\ldots,1]$、すべての位置は最初は不良ですが、単一の連続ブロックを形成するため、アルゴリズムはそれを 1 つの操作に正しく圧縮します。 

次のような交互の正しさパターンの場合$[1,0,3,0,5,0]$有効な範囲に調整されると、アルゴリズムは分離された不良領域を個別にカウントします。これは、それぞれに個別の間隔操作が必要であることを反映しています。
