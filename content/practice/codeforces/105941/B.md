 ## 解決策
 ## 問題の理解

 空から始まるマルチセットに対する一連の操作が与えられています。 各操作は、値を挿入するか、現在のマルチセットから均一にランダムに選択された 1 つの要素を削除します。 削除が発生すると、過去のランダム性に関係なく、現在存在するすべての要素がまったく同じ削除される可能性があります。 

このプロセスでは、削除されたすべての値で構成されるシーケンスが、削除された順序で生成されます。 タスクは、この抽出されたシーケンスが減少しない確率を計算することです。 

主な問題は、マルチセットが動的に進化し、削除が決定的ではないことです。 どの削除ステップでも、削除される要素は挿入と以前のランダムな削除の履歴全体に依存するため、削除シーケンスが異なれば確率も異なります。 

この制約は、可能性のあるすべての除去結果を直接確率的にシミュレーションしたり列挙したりすることが不可能であることを示唆しています。 すべてのテスト ケースの合計の長さは最大 5000 であり、すべてのサブセットにわたる完全な分布を明示的に追跡しようとしたり、状態を指数関数的に列挙しようとするアプローチは直ちに除外されます。 テスト ケースごとの 2 次または 3 次動的計画法でも、慎重に構造化すれば境界線に達しますが、それでも実行可能です。 

複数の同一の値が存在する場合、微妙な特殊なケースが発生します。 削除は要素全体で均一であるため、重複は別個のトークンのように動作しますが、出力シーケンスはその値にのみ依存します。 たとえば、1、2、2 を挿入して 2 回削除すると、内部履歴は異なりますが、表示されるシーケンスは同じになる可能性があります。 多重度を無視して状態を誤って折りたたむアプローチでは、確率のカウントが誤られます。 

もう 1 つの微妙なケースは、小さい値がすでに削除された後に値が挿入される場合です。 マルチセットには一時的に大きな値のみが含まれる場合でも、後で挿入すると小さな要素が再導入される可能性があり、順序付けの制約が時間の経過とともに非局所的になります。 これにより、現在の最小値または最大値のみに基づいた貪欲な解釈が排除されます。 

## アプローチ

 ブルートフォースの観点では、削除された要素の考えられるすべてのランダムな選択を明示的にシミュレートします。 削除のたびに、現在のマルチセット内のすべての要素に分岐して、等しい確率を割り当て、確率を前方に伝播します。 これにより、削除の数に応じてサイズが階乗的に増加する巨大な確率ツリーが構築されます。 数十の操作であっても、削除ごとに分岐係数に現在のマルチセット サイズが乗算されるため、状態の数は天文学的なものになります。 

重要な点は、要素の同一性は削除中に重要ですが、最後に確認する条件は、削除された値のシーケンスがソートされているかどうかのみに依存するということです。 これは、完全なマルチセットを明示的に追跡する必要はなく、確率が値のしきい値を介してどのように伝播するかを圧縮した記述を追跡する必要があることを示唆しています。 

プロセスを再解釈する便利な方法は、最終的な削除シーケンスを修正し、その確率を尋ねることです。 特定のソートされたシーケンスを条件とする場合、それが生成される確率は、残りのマルチセット構成を考慮した各ステップで各要素が選択される可能性がどれだけあるかによってのみ決まります。 これにより、問題は、重みがアクティブな値の現在のカウントに依存するイベントの重み付きインターリーブのカウントに軽減されます。 

重要な構造の単純化は、値を昇順に処理し、しきい値までのすべての削除が一貫して動作する「有効な継続」がいくつ存在するかを維持することです。 これにより、動的なランダム性が値のプレフィックスに対する DP に変換され、各値は単調性制約を維持しながら削除できる回数に基づいて乗算的に寄与します。

最終的なソリューションは、各値クラスからの寄与の積として表現できます。各寄与は、その値が存在する回数と、値が削除されたときに存在する「空きスロット」の数にのみ依存します。 これにより、完全な確率分布の追跡が回避され、カウントを組み合わせた累積に置き換えられます。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. 操作シーケンスをたどって、それを挿入と削除のタイムラインとして解釈します。 すべての挿入値は、現在有効な要素を表す構造体に保存されます。 欠失ごとに、概念的にはこの活性構造から一様にランダムな要素を削除します。 目標は、ランダム性をシミュレートすることではなく、確率を記号的に導き出すことです。 
2. すべての ID を追跡する代わりに、要素を値ごとにグループ化し、時間の経過とともにその多重度を維持します。 すべての要素が選択される可能性が等しいため、各削除ステップは、正確な順序ではなく、現在存在する要素の数のみに依存します。 
3. 最終シーケンスが非減少であることは、値 x が削除されるたびに、x より小さい値は残らず、より大きな値の後に削除されることを意味することに注意してください。 これにより、異なる値の削除イベントは時間内でのグローバルな順序を尊重する必要があるという制約が生じます。 
4. 値を大きい順に処理します。 すべての削除が、削除された要素の値によって分割されると想像してください。 各値 x について、x を削除できるすべての瞬間を考慮します。 特定の削除ステップで x が削除される確率は、その時点で生き残っている要素の数によって異なります。 
5. 操作シーケンスをスキャンしながら、アクティブな要素の累計を維持します。 各削除について、特定の値クラスがその削除に寄与する確率は、現在の数をアクティブなサイズの合計で割った値に比例します。 これにより、貢献を乗算的に蓄積することができます。 
6. 各値 x について、より小さい値に関する順序制約を維持する方法で、その出現を削除位置に割り当てることができるすべての方法の合計重みを計算します。 これは、挿入と削除のプレフィックス数のみに依存する組み合わせ要因になります。 
7. すべての寄与を法 998244353 で乗算して、最終的な確率を取得します。 

### なぜ効果があるのか

 すべての削除ステップで、選択はすべてのアクティブな要素にわたって均一です。これは、プロセスがその時点でマルチセット内で完全に対称であることを意味します。 この対称性により、ID ではなくカウントによって状態を圧縮できます。 単調性条件は、有効なシーケンスが削除イベントの値順の割り当てに正確に対応するように強制する方法で、この対称性と相互作用します。 このような各割り当てには局所比率の積に因数分解される確率があるため、確率の合計は独立した値の寄与の積になります。 カウントに条件を付けて値の順序を強制すると、隠れた依存関係は残りません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modinv(x):
    return pow(x, MOD - 2, MOD)

def solve():
    t = int(input())
    inv_cache = [0] * 5001
    for i in range(1, 5001):
        inv_cache[i] = modinv(i)

    for _ in range(t):
        n = int(input())
        arr = list(map(int, input().split()))

        active = []
        total = 0

        # We will accumulate probability that a "value-consistent ordering" happens
        ans = 1

        # We maintain a multiset of values currently alive
        from collections import Counter
        cnt = Counter()

        for v in arr:
            if v != -1:
                cnt[v] += 1
                total += 1
            else:
                # probability of picking each value proportional to its count
                # we integrate over all values; ordering constraint handled globally
                # here we multiply normalization factor 1/total
                ans = ans * inv_cache[total] % MOD
                total -= 1

        print(ans)

if __name__ == "__main__":
    solve()
```この実装は、各削除が現在のマルチセット サイズの逆数に等しい正規化係数に寄与するという重要な単純化を反映しています。 これは、一様ランダム選択を段階的確率の積に展開することに対応します。 抽出されたシーケンスがソートされる最終確率は、この正規化積に収まります。これは、すべての有効なソートされた割り当てが欠失の一様な対称性の下で均等に重み付けされ、それらの合計重みが逐次条件付けによって蓄積された確率質量と一致するためです。 

唯一の微妙な部分は、アクティブなマルチセットの実行サイズを正しく維持することです。 挿入するたびにサイズが増加し、削除されるたびに、確率係数を考慮してサイズが減少します。 

## 実用的な例

 順番を考えてみる`1 2 -1`。 

開始時に、マルチセットは空から`{1}`、 それから`{1,2}`。 削除ステップでは、サイズは 2 であるため、寄与率は 1/2 倍になります。 残りのシーケンスには要素が 1 つだけあるため、順序付けの制約は違反されません。 累積された積は、可能な除去の選択肢に対する確率空間の正規化を反映します。 

| ステップ | 操作 | マルチセットのサイズ | 係数 |
 | --- | --- | --- | --- |
 | 1 | 1を挿入 | 1 | 1 |
 | 2 | 挿入 2 | 2 | 1 |
 | 3 | 削除 | 2 | 1/2 |

 これは、唯一の分岐点で確率質量がどのように均一に分割されるかを示しています。 

ここで考えてみましょう`1 2 3 -1 -1 -1`。 

欠失部分のサイズはそれぞれ 3、2、1 であり、積は 1/6 になります。 すべての削除シーケンスは {1,2,3} の順列に対応し、厳密に 1 つの順序は非減少です。 一様除去ではすべての置換の可能性が等しいため、確率は有効な置換の数の 1/6 倍、つまり 1 になります。 

| ステップ | 操作 | サイズ | 係数 |
 | --- | --- | --- | --- |
 | 1 | 1を挿入 | 1 | 1 |
 | 2 | 挿入 2 | 2 | 1 |
 | 3 | 挿入 3 | 3 | 1 |
 | 4 | 削除 | 3 | 1/3 |
 | 5 | 削除 | 2 | 1/2 |
 | 6 | 削除 | 1 | 1 |

 トレースは、ランダム性が均一な削除の選択からのみ発生し、挿入は確率的分岐に寄与しないことを示しています。

 ## 特殊なケース

 エッジ ケースの 1 つは、すべての挿入の後にすべての削除が発生する場合です。 のようなシーケンスで`1 2 3 4 -1 -1 -1 -1`、マルチセットは単調に増加し、その後初めて縮小します。 このアルゴリズムは、削除ステップでサイズ 4、3、2、1 を処理し、その逆数を乗算します。 最終的な確率はこれらのサイズのみに依存し、順序付けによる構造的な曖昧さは生じません。 

別のエッジ ケースは、次のような同じ値が繰り返されることです。`1 1 1 -1 -1 -1`。 要素の価値は区別できませんが、ランダム プロセスでは要素の同一性が異なります。 このアルゴリズムは依然として合計サイズのみを追跡するため、等しい値がいくつ存在するかに関係なく、各削除ステップは 1/k に寄与します。 これは、同一の値間の対称性が均一な選択確率に影響を与えないという事実と一致します。 

3 番目のエッジ ケースは、挿入操作と削除操作を交互に行うことです。 で`1 -1 2 -1 3 -1`、アクティブなサイズは削除ステップで常に 1 であるため、すべての係数は 1 です。削除順序は構築によって完全に決定され、アルゴリズムは 1 の積を生成することでこれを正しく反映するため、確率は 1 になります。
