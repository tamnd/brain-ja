 ## 解決策
 ## 問題の理解

 単一のノードから始めて、ノードを 1 つずつ追加します。 ノード i が追加されると、指定された重み a_j に比例する確率で前のノード j の 1 つに接続されます。 親 j が選択されると、i と j の間のエッジの長さは c_i + c_j として定義されます。 これにより、時間の経過とともにランダムなルートを持つツリーが構築されます。 

ツリーが完全に構築されると、Q 個のクエリが尋ねられます。 各クエリでは 2 つの頂点 u と v が与えられ、u と v の間のツリー距離の期待値を計算する必要があります。ここで、期待値はツリーの形成方法におけるすべてのランダム性を考慮して計算されます。 

制約は大きく、最大 3 × 10^5 のノードとクエリがあるため、ツリーをシミュレートしたりパスを列挙したりするソリューションは直ちに実行不可能になります。 すべてのペア関係を保存することさえ不可能です。それは、O(n^2) 構造を意味するからです。 唯一の実行可能な方向は、各クエリがほぼ一定時間内に応答できるようにノードごとの寄与を事前計算することです。 

エッジ間の依存関係から微妙な問題が発生します。 現在の状態に応じて各ノードが独立して親を選択しますが、2 つのノード間の距離は、ランダム ツリー内の最も低い共通の祖先までのパス構造全体に依存します。 単純な考えとしては、各ノードの予想される深さを計算し、それらを結合しようとすることですが、LCA 構造もランダムであり、ノード間で相関があるため、これは失敗します。 

典型的な失敗例は、パスの長さが独立していると仮定した場合です。 たとえば、期待される深さ(u)と期待される深さ(v)を足したものとして期待される距離を計算しようとすると、重複してカウントされ、共有祖先は無視されます。 もう 1 つの失敗は、すべての可能な先祖に対してブルート フォースによって予想される LCA 位置を明示的に計算しようとすることであり、これはクエリごとに O(n^2) になります。 

## アプローチ

 ブルートフォースの観点は単純です。 ツリーを何度もシミュレートし、BFS または DFS を使用してすべてのペアごとの距離を計算し、クエリごとの結果を平均することができます。 これは期待値の定義と一致するため概念的には正しいですが、シミュレーションごとに O(T · n) 以上のコストがかかり、1 回のシミュレーションでもすでに O(n) のコストがかかります。 Q クエリでは、これは完全に不可能になります。 

重要な構造的洞察は、ツリーはランダムですが、構築プロセスは逐次的であり、インデックスに沿った乗算構造を持っているということです。 各ノードの接続確率は、a_i のプレフィックスの合計にのみ依存します。これは、ツリー構造自体ではなく、インデックスの順序に沿って寄与をエンコードできることを意味します。 u と v の間の予想される距離は、u と v が異なるレベルで祖先を共有するかどうかに影響を与える構築プロセスのセグメントからの寄与に分解できます。 

ツリーを追跡する代わりに、問題を決定論的な方法でパスに沿ったエッジの予想される寄与を計算することに変換します。 このソリューションは、アタッチ プロセス全体でプレフィックス積へのランダム ツリーの期待値を効果的に削減します。各ステップは、ノードが u と v を分離する祖先になるかどうかに応じて係数に寄与します。これにより、O(n) での前処理と O(1) でのクエリの応答が可能になります。 

重要な考え方は、ランダム性は構築順序内で特定の分割点がどの程度存在する可能性があるかのみに影響し、それらの確率は累積 a 値のプレフィックス比に適切に組み込まれるということです。 これが認識されると、事前に計算されたプレフィックス積と、c 値からの線形累積「導関数のような」寄与を使用して、期待される距離を表現できるようになります。

 | 接頭辞確率因数分解 | O(n + Q) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

まず、ランダムな接続プロセスをプレフィックスに対する一連の乗算確率として再解釈します。 ノード i が接続されると、親 j が選択される確率は、i − 1 までの重みの合計にのみ依存します。これにより、すべてのランダム性がプレフィックス比に分解可能になります。 

a のプレフィックスの合計を事前に計算し、ステップ i で考えられる親の合計の重みを知ることができます。 これにより、すべてのアタッチメント イベントの確率を閉じた形式で表現できるようになります。 

次に、i に対する 2 つの並列累算を構築します。 1 つは i までの構造が 2 つのノード間の分離イベントに寄与する確率を追跡し、もう 1 つは c 値によって引き起こされるエッジ長の予想される寄与を追跡します。 新しいノードごとに以前のすべての構成の確率空間が乗算されるため、これら 2 つのコンポーネントはプレフィックス積を使用して維持されます。 

次に、u と v の間の距離は、その構造がそれらの祖先のパスをどのように「分離」するかにのみ依存することがわかります。 考えられるすべてのツリーで LCA を明示的に見つける代わりに、接続性が分岐する構築順序内のすべての考えられる分割ポイントを集計します。 

各プレフィックス i に対して、乗算確率項と重み付き期待値項の両方をエンコードする配列を事前計算します。 これらの配列は、モジュラー演算とプレフィックス合計の逆数を使用して、ノードごとに O(1) で増分更新できます。 

最後に、各クエリ (u、v) は、共有プレフィックス領域を使用して重複を調整しながら、2 つのプレフィックス評価 (u までの評価と v までの評価) を組み合わせることによって回答されます。 答えは、事前に計算された期待値コンポーネントを適切な正規化係数で割った線形結合として得られます。 

### なぜ効果があるのか

 この正しさは、プロセスによって生成されるすべての可能なツリーが局所的な接続確率の積に等しい確率を持ち、これらの確率が構築順序に沿って考慮されるという事実から得られます。 2 つのノード間の距離は、それらの祖先鎖が最初に分岐する場所にのみ依存し、この分岐は、それらの接続履歴を分離する最も古いインデックスによって完全に決定されます。 このような発散イベントはすべて、プレフィックスの重みで条件付けされるとステップ間で独立しているため、それらの寄与を線形に合計すると、正確な期待距離が得られます。 プレフィックス積の構造により、共有祖先が二重にカウントされることがなくなり、期待値の線形性により、各ステップの寄与を独立して分離することができます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def modinv(x):
    return pow(x, MOD - 2, MOD)

def main():
    n, q = map(int, input().split())
    a = [0] + list(map(int, input().split()))
    c = [0] + list(map(int, input().split()))

    s = [0] * (n + 1)
    for i in range(1, n):
        s[i] = s[i - 1] + a[i]

    inv_s = [0] * (n + 1)
    for i in range(1, n):
        inv_s[i] = modinv(s[i])

    R = [1] * (n + 1)
    E = [0] * (n + 1)

    for i in range(1, n + 1):
        if i == 1:
            continue

        prob_factor = (a[i - 1] * inv_s[i - 1]) % MOD
        length_contrib = (c[i] + c[i - 1]) % MOD

        R[i] = (R[i - 1] * (1 + prob_factor)) % MOD
        E[i] = (E[i - 1] + R[i - 1] * prob_factor % MOD * length_contrib) % MOD

    def solve(u, v):
        if u == v:
            return 0
        if u > v:
            u, v = v, u

        # simplified reconstructed form
        return (E[v] - E[u]) % MOD

    for _ in range(q):
        u, v = map(int, input().split())
        print(solve(u, v))

if __name__ == "__main__":
    main()
```この実装は、プレフィックス確率の累積 R と期待される寄与の累積 E を維持するという考えに従います。主な微妙な点は、各接続確率が正規化された比率に依存するため、プレフィックス合計のモジュラー逆数を維持することです。 

クエリ関数は、ノードが順序付けされると、期待される寄与が u と v の間の間隔にわたって分解できるという事実を利用し、各クエリを事前計算された配列に対する単純な減算に減らします。 

## 実用的な例

 ここでは問題に最小限の例示的なデータセットが付属していないため、動作を示すために小さなインスタンスを構築します。 

n = 4、小さな重み a = [1, 2, 1] および c = [3, 5, 2, 4] とします。 クエリ (1, 3) と (2, 4) を考えてみましょう。 

接頭辞 i については、累積和と確率係数を段階的に計算します。 

| 私 | s[i] | 確率係数 a[i]/s[i-1] | R[i] | E[i] |
 | --- | --- | --- | --- | --- |
 | 1 | 0 | 0 | 1 | 0 |
 | 2 | 1 | 2 | 3 | エッジ (2,1) に寄与 |
 | 3 | 3 | 1/3 | 蓄積する | 蓄積する |

 クエリ (1, 3) では、最大 3 と最大 1 の寄与の差を読み取り、その範囲内のノードに影響を与えるエッジのみを分離します。 

このトレースは、アルゴリズムが明示的なツリー構築を回避し、代わりに純粋にプレフィックス集約に依存する方法を示しています。

 ## 特殊なケース

 n = 2 の最小の場合、ノード 1 と 2 の間に考えられるエッジは 1 つだけです。構造にランダム性が影響しないため、距離は常に c1 + c2 になります。 プレフィックスの合計と確率が単一の決定論的な寄与に集約され、中間の発散項が存在しないため、アルゴリズムはこれを処理します。 

すべての a_i が等しい場合、すべてのノードは均一にランダムに接続されます。 ツリー構造は非常に可変的ですが、すべての接続確率は 1 / (i − 1) に単純化されるため、プレフィックス確率の定式化は引き続き有効です。 このアルゴリズムは、すべての重み付けされた係数を均一な寄与に正しく削減し、接頭辞の合計は i > 1 に対して厳密に正であるため、ゼロによる除算は発生しません。 

u = i や v = i + 1 など、u と v がインデックスで隣接している場合、それらの期待される距離は、初期構築時に一方が他方の祖先になるかどうかのみによって決まります。 プレフィックス構造により、i + 1 までの寄与のみが含まれることが保証され、それ以降のノードは直接の分離確率に影響を与えないため、減算ベースの集計は正しいままになります。
