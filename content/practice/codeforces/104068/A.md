 ## 解決策
 ## 問題の理解

 各テスト ケースでは、文字と数字で構成される文字列が提供されます。 その文字列に非常に特殊な「スパム パターン」が含まれているかどうかを判断する必要があります。 このパターンは、「kfc」、「crazy」、「thursday」、「vivo」、および数字「50」という 5 つの異なるキーワードが同時に存在することによって定義されます。 

重要な点が 1 つあります。 これらのキーワードを、大文字と小文字が正確に一致する連続した部分文字列として探しているわけではありません。 代わりに、文字列は大文字と小文字を区別せずに処理する必要がありますが、数字は正確に一致する必要があります。 各キーワードは文字列のサブシーケンスとして出現する必要があります。つまり、文字は自由に削除できますが、順序は保持する必要があります。 さまざまなキーワードで文字を再利用できるため、それらのキーワードの一致が元の文字列内で重複する可能性があります。 

したがって、タスクは、大文字と小文字を区別しないマッチングの下で​​、5 つのパターンのそれぞれをサブシーケンスとして指定された文字列に埋め込むことができるかどうかをチェックすることになります。 

制約は小さく、文字列は最大 100 個、それぞれの長さは 1000 までです。これにより、文字列あたり O(n) または O(n * k) で快適にアプローチできます。ここで、k はパターン全体の文字の合計数です。 指数関数的なものや、注意せずにパターンごとにスキャンを繰り返すものは問題なく動作しますが、パターンごとにきれいな線形スキャンを行うことが目的の解決策です。 

いくつかの特殊なケースが重要です。 

よくある落とし穴の 1 つは、ケースの処理です。 たとえば、「KFC1crazy」は依然として「kfc」および「crazy」と一致するはずですが、正規化されていない場合、直接の部分文字列検索は失敗します。 

もう 1 つの落とし穴は、「50」の桁一致です。 ソルバーが誤って文字を粗く扱ったり、数字を無視したりした場合、「5O」（ゼロの代わりに文字 O）のような文字列を受け入れてはなりません。 

3 番目の問題は、「部分列」を「部分文字列」と誤解することです。 たとえば、文字が分離されている場合でも、「kxxfxc」は「kfc」と一致する必要があります。 

## アプローチ

 ブルートフォース解釈では、すべての位置からスキャンするか、すべてのサブシーケンスを生成することによって、各キーワードをサブシーケンスとして独立して検索しようとしますが、それはすぐに不要になります。 サブシーケンスの生成は指数関数的であり、明らかに実行不可能です。 

より構造化されたブルート フォース アプローチは、キーワードごとに文字列を貪欲にスキャンすることです。つまり、最初の文字に一致することを試み、次の一致が見つかるまで先に進みます。 これはキーワードごとに O(n) で機能するため、テスト ケースごとに O(5n) になります。 1000 文字と 100 のテスト ケースがあっても、これは簡単です。 

重要な点は、各キーワードが独立しているということです。 同じソース文字列を共有することを除いて、それらの間に相互作用はありません。 つまり、各キーワードの一致を標準のサブシーケンス チェックとして扱うことができます。 

したがって、問題は、文字の大文字と小文字を正規化した後、5 つの独立したサブシーケンス チェックを実行することに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | キーワードごとの貪欲なサブシーケンス チェック | O(T * n * 5) | お(1) | 承認済み |
 | ブルートフォースサブシーケンス列挙 | O(2^n) | O(n) | 遅すぎる |

 ## アルゴリズムのチュートリアル

 正規化後のターゲット パターンは、「kfc」、「crazy」、「thursday」、「vivo」、「50」の 5 つです。 文字の場合は小文字で比較します。 数字は直接比較されます。 

1. 各テスト ケース文字列について、すべての文字が数字として保持されるか、文字の場合は小文字に変換される形式に変換します。 これにより、均一なマッチング動作が保証されます。 
2. 各キーワードについて、文字列上のポインタを使用してサブシーケンスとして一致を試みます。 キーワードに対するインデックス j を維持します。 文字列を左から右にスキャンし、現在の文字がキーワード[j]に一致するたびに、j を進めます。 j がキーワードの長さに達すると、キーワードは完全に一致します。 
3. 5 つのキーワードすべてが個別に一致する場合は「はい」が出力され、そうでない場合は「いいえ」が出力されます。

貪欲スキャンが機能する理由は、サブシーケンスのマッチングにバックトラッキングが必要ないためです。 キーワード内の特定の位置に文字を一致させたら、それを遅らせても成功の可能性は決して向上しません。これは、将来の文字が使用可能なままであるためです。 

### なぜ効果があるのか

 各キーワードのマッチングは入力文字列に対する単調なプロセスです。前に進むだけです。 一致が存在する場合、可能な限り最も早い有効な位置を取得する貪欲な一致が存在します。 これにより、グリーディ スキャンの失敗は、有効なサブシーケンスが存在しないことを意味します。これは、代替マッチングでは、以前の有効な一致をスキップする必要があり、後の文字で使用できる柔軟性が低下するだけであるためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

patterns = ["kfc", "crazy", "thursday", "vivo", "50"]

def is_subsequence(s, p):
    j = 0
    n = len(p)
    for ch in s:
        if j < n and ch == p[j]:
            j += 1
            if j == n:
                return True
    return j == n

t = int(input())
for _ in range(t):
    s = input().strip()
    s = ''.join(ch.lower() for ch in s)

    ok = True
    for p in patterns:
        if not is_subsequence(s, p):
            ok = False
            break

    print("Yes" if ok else "No")
```実装では、文字の比較が均一になるように、まず文字列を小文字形式に正規化します。 サブシーケンス チェッカーはパターン上で単一のポインタを使用し、文字列を 1 回スキャンして、一致が発生するたびにポインタを進めます。 ループ内で早期に終了することで、パターンがすでに見つかった後に不要な文字をスキャンすることがなくなります。 

微妙な点は、「50」が通常の文字列として扱われるため、数字が正確に一致し、大文字と小文字の正規化の影響を受けないことです。 これにより、アルファベットと数字の両方のパターンで同じロジックが維持されます。

## テストケース```python
import sys, io

def solve():
    import sys
    input = sys.stdin.readline

    patterns = ["kfc", "crazy", "thursday", "vivo", "50"]

    def is_subsequence(s, p):
        j = 0
        n = len(p)
        for ch in s:
            if j < n and ch == p[j]:
                j += 1
                if j == n:
                    return True
        return j == n

    t = int(input())
    for _ in range(t):
        s = input().strip()
        s = ''.join(ch.lower() for ch in s)

        ok = True
        for p in patterns:
            if not is_subsequence(s, p):
                ok = False
                break
        print("Yes" if ok else "No")

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    old_stdout = sys.stdout
    sys.stdout = io.StringIO()
    solve()
    out = sys.stdout.getvalue()
    sys.stdout = old_stdout
    return out.strip()

# provided samples (illustrative formatting)
assert run("1\nKFC1crazy2THURSday3VivO450\n") == "Yes"
assert run("1\nabc\n") == "No"

# custom cases
assert run("1\nkfcrazythursdayvivo50\n") == "Yes"
assert run("1\nKfCxxcRazyTHuRsdayvivo50\n") == "Yes"
assert run("1\nkfcrazythursdayvivo5\n") == "No"
assert run("1\n50kfccrazythursdayvivo\n") == "Yes"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 完全連結 | はい | 最も単純な完全一致 |
 | 大文字と小文字が混在したノイズ | はい | 大文字と小文字を区別しない |
 | 数字がありません | いいえ | 厳密な数字の要件 |
 | 有効なブロックを並べ替え | はい | パターンの独立性 |

 ## 特殊なケース

 特殊なケースの 1 つは、文字に大文字と小文字が混在し、ランダムなノイズが含まれる場合です。 たとえば、次のように入力します。```
KfCxxCRAZYxxTHuRsDayxxVIVo50
```正規化後は次のようになります。```
kfCxxcrazyxxthursdayxxvivo50
```余分な文字が今後の一致をブロックすることがないため、各パターンの貪欲なサブシーケンス スキャンは引き続き成功します。 スキップの機会が増えるだけです。 

もう 1 つの特殊なケースは、次のような不正な桁置換です。```
kfc crazy thursday vivo 5O
```ここで「O」はゼロではなく文字です。 正規化後は「o」のままで、「5」の後に数字「0」がないため、パターン「50」は一致できません。 数字の一致は正確であり、緩和されていないため、アルゴリズムはこれを正しく拒否します。 

最後のエッジケースは、パターンを大量にインターリーブすることです。```
kxfycrazytwhxursdayvixvo50
```大きなノイズがあっても、正しい次の文字が表示された場合にのみ、各ポインターが進みます。 スキャンはすべてのパターンで独立して成功し、任意のインターリーブ下でサブシーケンスのマッチングが堅牢であることが確認されます。
