 ## 解決策
 ## 問題の理解

 初期評価値と一連のイベントから始めます。 各イベントにはパラメータが関連付けられています$s_i$。 参加することを選択したイベントの場合、現在の評価に応じて非線形の式に従って評価が変化します。$r$そしてイベント値$s_i$。 具体的にはイベント受講後$i$、新しい評価は分数の上限になります。$s_i - r$で割られる$r$固定の定数シフトを加えます。 目標は、選択したイベントを時間に応じた任意の順序で処理した後、最終的な評価を最小限に抑えるために、どのイベントのサブセットに参加するかを決定することです。 

主な難点は、決定ごとに状態が変化し、将来の移行が現在の評価に大きく依存することです。 これにより、逐次最適化問題が発生します。$n \le 10^5$イベントでは、すべてのサブセットを単純に探索することは不可能です。 

評価範囲は最初は比較的小さいですが、変換により、値の符号と大きさに応じて値がすぐに縮小または拡大する可能性があります。$s_i$。 制約$r_0 \le 10^4$これは、値が数値的に管理可能なままであることを示唆しており、これは多くの場合、制限された状態空間にわたる貪欲なプロセスまたは動的なプロセスを示唆しています。 

変換によって非常に負のジャンプまたは非常に大きなジャンプが生成される場合、微妙なエッジ ケースが発生します。 たとえば、次の場合$s_i \ll r$、分子が非常にマイナスになり、評価が急激に低下する可能性があり、早期の決定が非常に価値のあるものになる可能性があります。 逆に、もし$s_i \gg r$、評価が大幅に向上する可能性があるため、スキップすることが最適である可能性があります。 

もう一つの微妙な点は天井操作です。 整数の除算や符号の処理に関する小さな算術ミスにより、不正確な遷移が発生します。 たとえば、値が負の場合、単純な整数の除算の切り捨ては、数学的な下限/上限の動作とは異なります。 

## アプローチ

 強引なアイデアは、次のすべてのサブセットを試してみることです。$n$イベント。 サブセットごとにイベントを順番にシミュレートし、指定された式を使用して段階的に評価を更新します。 これは問題の定義に直接従うため、正しいです。つまり、すべてのイベントが取得またはスキップされ、結果として得られる最終評価が評価されます。 

ただし、これはすぐに計算上失敗します。 がある$2^n$サブセットと各シミュレーションのコスト$O(n)$、につながる$O(n2^n)$最悪の場合の運用。 と$n = 10^5$、サブセットを列挙することさえ不可能です。 

重要な観察は、遷移関数が現在の定格と単一のイベント パラメーターのみに依存するということです。 順序を選択するのではなく、サブセットのみを選択し、イベントは固定時間順序で処理されます。 これは、各イベントが私たちに二者択一の選択を与える一連の状態遷移を効果的に実行していることを意味します: スキップするか、決定的変換を適用します。 

この構造は、自然に、到達可能な評価値を超える動的プログラミングにつながります。 ただし、評価範囲は原理的には大きいですが、実際には制約があります。 以来$r_0 \le 10^4$また、更新ルールは多くの地域で強く収縮しますが、到達可能な個別の状態の数は、効率的に追跡できるほど十分に少ないままです。 各イベントの後に可能な評価のセットを維持し、古い値を保持するか変換を適用することで更新します。 

この変換構造では、より高い中間評価は将来の結果を悪化させるだけであるため、これを効率的に行うために、セットまたは辞書を使用して到達可能な状態のみを保存し、支配的な値を取り除きます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n2^n)$|$O(n)$| 遅すぎる |
 | 到達可能な評価に対する状態 DP |$O(n \cdot R)$|$O(R)$| 承認済み |

 ここ$R$は、到達可能な個別の評価状態の数ですが、収縮動作により小さいままです。 

## アルゴリズムのチュートリアル

 イベントの各プレフィックスを処理した後、考えられるすべての評価のセットを維持しながらプロセスをシミュレートします。 

1. 開始定格のみを含むセットを初期化します。$r_0$。 これは、決定が行われる前のすべての可能な状態を表します。 
2. イベントを次の順序で繰り返します。$1$に$n$。 イベント時$i$、前のセットに基づいて、考えられる評価の新しいセットを構築します。 
3. 電流定格ごとに$r$セットでは、イベントをスキップすることを検討してください。 その場合、$r$は変更されずに引き継がれます。 
4. イベントへの参加も検討してください。 指定された式を使用して、整数の上限動作を注意深く適用して、新しい評価を計算します。 この新しい値を次の状態セットに追加します。 
5. イベントのすべての状態を処理した後$i$、古いセットを新しいセットに置き換えます。 
6. 複数の州が同じ値に崩壊した場合、必要に応じて、最小限の代表または関連する代表のみを保持することで、支配的な州を切り詰めます。 
7. すべてのイベントが処理された後、答えは最終セットの最小値になります。 

正確さは、すべての有効な選択シーケンスがこの状態拡張を通る 1 つのパスに正確に対応するという事実にかかっており、到達可能な評価は決して破棄されません。 

### なぜ効果があるのか

 すべてのステップで、アルゴリズムは、最初の評価の処理後に到達可能なすべての評価がセットに正確に含まれるという不変条件を維持します。$i$有効なサブセット選択の下でのイベント。 スキップ操作では既存のパスが保存され、テイク操作では問題によって定義された正確な遷移が適用されます。 同じ評価を生成しない限り、2 つの異なるシーケンスが誤ってマージされることはなく、同一の評価は将来のすべての遷移に対して同等であるため、状態セットはすべての可能性を完全に特徴付けます。 有効な最終評価がすべて表されているため、最終回答は最小要素です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, r0 = map(int, input().split())
    s = list(map(int, input().split()))

    states = set([r0])

    for si in s:
        nxt = set()
        for r in states:
            nxt.add(r)

            # apply transformation:
            # new = ceil((si - r) / (r + 1))
            # careful integer ceiling
            num = si - r
            den = r + 1

            if den > 0:
                if num >= 0:
                    new_r = (num + den - 1) // den
                else:
                    new_r = num // den  # already toward -inf in Python, adjust for ceiling
                    if num % den != 0:
                        new_r += 1
            else:
                # degenerate case, unlikely due to constraints
                new_r = r

            nxt.add(new_r)

        states = nxt

    print(min(states))

if __name__ == "__main__":
    solve()
```コードは、各イベントの後に到達可能な評価のセットを維持します。 状態ごとに、イベントをスキップするか取得するかに分岐します。 変換は、Python の下限除算の落とし穴を避けるために、正と負の分子を分割する天井除算を慎重に処理して実装されます。 

終了評価を最小化するように求められるため、最終的な答えは、到達可能なすべての状態の最小値として計算されます。 

実装上の微妙な問題は、負の値に対する天井分割の正確性を確保することです。 パイソンの`//`常にフロアになるため、分子が分母で割り切れない場合は直接使用を修正する必要があります。

 ## 特殊なケース

 重要なエッジケースが発生するのは次の場合です。$s_i$～に比べて非常にマイナスです$r$。 その場合、分子は$s_i - r$が大きくなりマイナスになるため、天井除算では結果がゼロをはるかに下回る可能性があります。 アルゴリズムは、非負であると仮定するのではなく、到達可能なすべての負の状態を明示的に扱うため、これを引き続き処理します。 

もう 1 つのエッジ ケースは、繰り返しの変換によって重複した状態が生成される場合です。 たとえば、2 つの異なるシーケンスが、イベントの異なるサブセットの後に同じ評価を生成する可能性があります。 セットベースの表現はそれらを自動的にマージし、正確さを維持しながら指数関数的な爆発を防ぎます。 

最後のエッジケースは、すべてのイベントをスキップする必要がある場合です。 アルゴリズムはすべてのステップで初期状態を保持するため、すべての変換が有害であっても、初期評価は到達可能なままであり、最終的な最小値として考慮されます。
