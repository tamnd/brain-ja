 ## 解決策
 ## 問題の理解

 時間の経過とともにジャガイモが次々と到着します。 各ジャガイモには到着タイムスタンプがあり、ジャガイモが機械に入ると、その「加熱しすぎた値」は時間とともに直線的に増加します。 いつでも、一度のアクションで機械内にあるジャガイモをすべて取り出すことができます。 このような各プルには、固定のペナルティと、その時点ですべてのジャガイモが蓄積した過剰調理の合計に等しい追加コストがかかります。 

課題は、すべてのジャガイモが最終的に 1 回だけ取り出され、すべてのコストの合計が最小限に抑えられるように、一連の取り出し時間を選択することです。 

入力は、減少しない到着時間のシーケンスです。 この単調性が重要なのは、ジャガイモを 1 つのプルにグループ化することを検討するときに、内部のジャガイモのセットが常に時間順で連続した接尾辞になるためです。 

n が 10^6 までの制約により、あらゆる解が線形または線形に近いものになります。 ペアごとの遷移、すべての間隔にわたる動的計画法、またはソートベースの二次マージを含むものはすべて失敗します。 それぞれのジャガイモを1回または一定回数処理する構造が必要です。 

k が大きい場合、重要なエッジ ケースが発生します。 プルにコストがかかる場合は、小規模なプルを多数行う方がよい場合があります。 k が 0 の場合は、できるだけ長く遅延させて、すべてを一度にプルする必要があるかもしれません。 もう 1 つのエッジ ケースは、グループ化の動作がマージによってコストが削減されるかどうかに影響されるため、到着時間が等しいかほぼ等しい場合です。 

構造を示す小さな例:

 入力:

 n = 3、k = 2

 t = [0、1、2]

 時刻 2 で 1 回引くと、コストは k + (2 + 1 + 0) = 5 になります。 

到着ごとに別々に 3 回引くと、コストは 3k = 6 になります。 

したがって、ここではグループ化が有益ですが、常にそうとは限りません。 

決定は完全に、タイムラインをセグメントに分割するかどうかにかかっています。 

## アプローチ

 ブルート フォース ビューから始めます。プルを実行する時間のサブセットを選択します。 各プルでは、​​前回のプル以降に到着したジャガイモのグループが定義されます。 配列をセグメントに固定分割する場合、セグメントのコストは選択したプル時間によって決まり、セグメント内では、最良のプル時間は最終到着時間になります。 

したがって、セグメントの境界を修正すると、コストを直接計算できます。各セグメントは、k にセグメント内の前回の到着時間と各到着時間の差の合計を加えたものに寄与します。 

ブルート フォースでは、n 個の項目のすべてのパーティションが列挙されます。 各ギャップはカットできるかカットできないかのどちらかであるため、これは本質的に 2^(n-1) 通りの可能性があります。 1 つのパーティションの評価が O(n) である場合でも、合計の複雑さは指数関数的になり、最大 10^6 の n では使用できなくなります。 

重要な観察は、コストが局所的に分解され、段階的に表現できるということです。 セグメントを拡張するときは、同じプル内で蓄積を続けるか、新しいプルを開始します。 これにより、現在の要素を最後のセグメントにマージするか、ここで切り取るかの古典的な決定が行われます。 

この問題を、実行セグメントのコストを動的に維持する線形スキャンとして再定式化します。 新しいジャガイモはそれぞれ、取り出されていない期間に応じて追加の待機コストに寄与し、各セグメントは固定の k に寄与します。 構造はどこにカットを配置するかを決定することに相当し、現在のセグメントを拡張することが新しいセグメントを開始するよりも悪いかどうかを維持することによって、最適な構造を貪欲に計算できます。これは、増分コストの増加を k と比較することに帰着します。 

これにより、最後のセグメントが i で終わる i までの最適コストを追跡し、プレフィックスの合計を使用して O(1) の遷移を更新する線形 DP が得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | 最適な DP / 貪欲なパーティショニング | O(n) | O(1) または O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

セグメントへの寄与が明確になるようにコストを書き換えます。 セグメントがインデックス r で終了し、l で始まるとします。 時間 t_r でプルするので、コストは (t_r - t_i) の [l, r] の k に i の合計を加算したものになります。 

t のプレフィックス合計を事前計算します。 この場合、セグメント コストは k + (r - l + 1) * t_r - (sum t[l..r]) になります。 

i を 1 から n まで処理し、最初の i 個のジャガイモを処理するための最小コストを表す DP 値を維持します。 最後のセグメントは i で終了するため、前のカットがどこにあったかを考慮します。 

## アルゴリズムのチュートリアル

 1. 時間はすでに減少していないため、ソートは不要です。 セグメントが連続した範囲に対応するように、この順序に依存します。 
2. O(1) でセグメント コストを評価できるように、到着時間のプレフィックスの合計を計算します。 これにより、各遷移内の合計の再計算が回避されます。 
3. 最初の i 個のポテトを処理するための最小コストとして dp[i] を定義します。 
4. 各 i について、最後のセグメントが j で始まり i で終わると考えてください。 移行は次のとおりです。 

dp[i] = dp[j] の j < i にわたる最小値 + コスト(j+1, i)。 
5. プレフィックス合計を使用してセグメント コストを展開します。 

コスト(j+1, i) = k + (i - j) * t[i] - (prefix[i] - prefix[j])。 
6. j 依存部分を分離するために項を並べ替えます。 

dp[i] = k + i * t[i] - prefix[i] + j < i の最小値 (dp[j] - j * t[i] + prefix[j])。 
7. 固定 i の場合、t[i] は最小化内で定数であるため、次の形式の行を格納する j 上のデータ構造を維持することに注目してください。 

value_j(x) = dp[j] + prefix[j] - j * x、

 x = t[i] で評価されます。 

これは凸包トリック構造で、傾きが -j で、j が増加するにつれて単調になり、実装に応じて償却 O(1) または O(log n) クエリが可能になります。 
8. 各 j を昇順に挿入し、将来の i の最良の候補を維持します。 t[i] でクエリを実行して dp[i] を計算します。 
9. dp[0] = 0 を初期化し、ベースライン j = 0 を含めます。 
10. 答えは dp[n] です。 

### なぜ効果があるのか

 各状態 j は、前のプル位置の選択を表します。 凸包変換は t[i] への線形依存性をエンコードし、単調な到着時間によりクエリ ポイントが減少しないことが保証されます。 これにより、最適性を損なう形で以前の行を再検討する必要がなくなりました。 すべての dp[i] は、考えられるすべての最後のセグメントの正確な分解から構築されるため、実行可能なパーティションは除外されず、すべてのパーティションは 1 つの遷移シーケンスに正確にマップされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    t = list(map(int, input().split()))
    
    if n == 0:
        print(0)
        return

    # prefix sums of t
    pref = [0] * (n + 1)
    for i in range(1, n + 1):
        pref[i] = pref[i - 1] + t[i - 1]

    # Convex hull trick with monotone slopes and queries
    hull = []  # each item: (m, b) representing m*x + b

    def add_line(m, b):
        # remove last if new line makes it obsolete
        while len(hull) >= 2:
            m1, b1 = hull[-2]
            m2, b2 = hull[-1]
            m3, b3 = m, b
            # check intersection condition
            if (b3 - b2) * (m2 - m1) <= (b2 - b1) * (m3 - m2):
                hull.pop()
            else:
                break
        hull.append((m, b))

    ptr = 0

    def query(x):
        nonlocal ptr
        if ptr >= len(hull):
            ptr = len(hull) - 1
        while ptr + 1 < len(hull):
            m1, b1 = hull[ptr]
            m2, b2 = hull[ptr + 1]
            if m1 * x + b1 >= m2 * x + b2:
                ptr += 1
            else:
                break
        m, b = hull[ptr]
        return m * x + b

    dp0 = 0
    add_line(0, 0)  # j = 0

    for i in range(1, n + 1):
        x = t[i - 1]
        best = query(x)
        dp0 = k + i * x - pref[i] + best
        add_line(-i, dp0 + pref[i])

    print(dp0)

if __name__ == "__main__":
    solve()
```この実装では、プレフィックスの合計を追跡して、再計算せずにセグメント コストを評価します。 DP 再帰は、各状態 j が線になる凸包構造に埋め込まれます。 傾きは -j、切片は dp[j] + prefix[j] で、遷移からの代数的並べ替えと一致します。 

ポインターベースのクエリは、勾配とクエリ ポイントの両方が単調であるため機能します。 ポインタは決して後方には移動しないため、償却された線形複雑度が得られます。 

よくある間違いは、dp 寄与に切片に prefix[j] が含まれている必要があることを忘れていることです。 これを省略すると、線形変換が壊れ、不正確なセグメント コストが生成されます。 

## 実用的な例

 入力を考慮してください:

 n = 3、k = 2

 t = [0、1、2]

 プレフィックスの合計 pref = [0, 0, 1, 3] を計算します。 

| 私 | x = t[i] | 最良のライン値 | dp[i] の計算 |
 | --- | --- | --- | --- |
 | 1 | 0 | 0 | 2 + 1*0 - 0 + 0 = 2 |
 | 2 | 1 | ラインからの分 | 2 + 2*1 - 1 + ベスト |
 | 3 | 2 | ラインからの分 | 最終的なマージと分割 |

 i = 3 では、構造は単一セグメントを優先し、dp[3] = 5 を生成します。 

このトレースは、初期の決定がより適切な長距離グループ化によってどのように上書きされるかを示しています。これはまさに凸包がエンコードしているもの、つまり各エンドポイントの以前の最良のカットです。 

次に、対照的なケースを考えてみましょう。 

n = 3、k = 10

 t = [0、1、2]

 ここでは k が優勢であるため、最良の解決策は単一のセグメントになります。 dp トランジションは常に、新しい効果的なブレークを導入するよりも、同じラインを延長することを好みます。 船体はまだ機能しますが、最適な前モデルを切り替えることはありません。 

これは、アルゴリズムが明示的なケースワークなしで両方の体制に自動的に適応することを示しています。

 ## 特殊なケース

 n = 1 の場合、有効なアクションは 1 回のプルのみであるため、コストは正確に k です。 アルゴリズムは dp[0] を初期化し、ベースライン j = 0 を使用して dp[1] を構築し、k + 0 を生成します。 

すべての到着時間が等しい場合、どのセグメント内でも、すべてのジャガイモの内部コストはゼロになります。 この決定は、プルの数を最小限に抑えることに帰着するため、k が分割を強制しない限り、アルゴリズムは事実上、すべての項目を 1 つのセグメントにマージすることを優先します。 凸包は同一のクエリ点に縮退しますが、単調構造は依然として正しい dp 遷移を返します。 

k = 0 の場合、最適な戦略は常に最後のプルを 1 回実行することです。 DP は新しいセグメントを開始しても何のメリットも得られず、ハルは継続的に j = 0 を最適なものとして選択し、すべての i の (t[n] - t[i]) の合計に等しい総コストを生成します。
