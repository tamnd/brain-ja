 ## 問題の理解

 私たちに与えられたのは、$n$labeled vertices that must become the leaves of a tree. 追加の頂点を追加することはできますが、それらの追加の頂点は互いに区別できず、最終ツリーでは追加されたすべての頂点の次数が正確に 3 でなければなりません。 Each original labeled vertex must end up with degree exactly 1, meaning every labeled vertex is a leaf.

 したがって、私たちが数えている構造は、すべてのラベル付けされた頂点が葉であり、すべての内部頂点が次数 3 を持つツリーです。ラベル付けされた葉上の隣接構造が異なる場合、2 つのツリーは異なるものとみなされます。 Internal vertices are not labeled, so renaming them does not create a new configuration.

 The input contains many test cases, each giving a value of$n$有効なツリーの数を 998244353 で割った値を出力する必要があります。 

この制約は、テスト ケースごとに線形であっても何も実行できないことを意味します。 まで$10^6$クエリと$n$までも$10^6$、テストごとの DFS、DP、または階乗のような再計算は、一度完全に事前計算されない限り遅すぎます。 ソリューションでは、1 回の前処理パスの後、各クエリを一定時間に短縮する必要があります。 

単純なアプローチでは、次数 3 の内部ノードを介してラベル付きのリーフを接続するツリー トポロジを列挙しようとします。 小さいものでも$n$、ラベルのないツリー形状の数は超指数関数的に増加します。 たとえば、$n=6$、内部ノードを介してリーフをグループ化するさまざまな方法により、すでに多くの組み合わせ構造が生成されており、直接生成することは不可能です。 

よくある失敗モードは、葉を 1 つずつ付けてローカルで選択肢を数えることによって「段階的にツリーを構築」しようとすることです。 多くの構築シーケンスが同じ最終的なラベルのない内部構造につながるため、これは非常に重要です。 

## アプローチ

 ブルートフォースの観点は、葉がラベル付けされた頂点とまったく同じであるツリーを構築することを考えることです。 すべての内部ノードは次数 3 を持つ必要があるため、各内部ノードは残りの構造を 3 つの部分に分割します。 ラベル付きの葉を、内部ノードを介して接続されたグループに再帰的に分割することを想像できます。 これはすぐに、ラベル付きセットのすべての 3 項分解にわたる計数問題になり、すべての分解は多くの等価なラベルなしの内部配置に対応します。 

重要な観察は、この構造が恣意的ではないということです。 すべての内部ノードの次数が 3 で、すべてのラベル付き頂点が葉であるツリーは、まさに根のない完全な二分系統樹です。 組み合わせ論の古典的な結果では、そのようなツリーの数は次のようになります。$n$ラベルが付いた葉は$$(2n - 5)!!$$1 から 2 までのすべての奇数の積です。$2n - 5$。 

この式は帰納的に導くこともできます。 木の数がすでにわかっている場合は、$n-1$葉の場合、新しいラベル付き葉を追加することは、既存のエッジを細分化し、新しい葉をアタッチすることに対応します。 ステップで$n$、まさにあります$2n-5$任意の有効なツリー内のエッジ。これにより乗法再帰が得られます。 

したがって、構造の列挙を完全に回避し、代わりに単純な積シーケンスを計算します。 

ブルート フォースは、指数関数的に多くのツリー形状を探索しようとするため失敗しますが、正しいビューでは、増分挿入により構造全体が単一の閉じた形式のプロダクトに折りたたまれます。

 ## アルゴリズムのチュートリアル

 計算は、次のすべての値を事前に計算することになります。$(2n-5)!!$最大まで$n$入力で。 

1. 基本ケースが次であることを確認します。$n = 3$、有効なツリーが 1 つだけ存在します。 これは次の事実と一致します$(2\cdot 3 - 5)!! = 1!! = 1$。 
2. 配列を維持する`dp[n]`どこ`dp[n]`有効なツリーの数を格納します$n$ラベルが付いた葉。 
3. エッジ挿入から派生した再帰を使用します。エッジの数を増やす場合は、$n-1$に$n$、利用可能な取り付け位置の数は$2n - 5$。 これにより、$$dp[n] = dp[n-1] \cdot (2n - 5)$$4. 事前計算`dp[n]`から繰り返し$n=3$最大入力値まで。 
5. クエリごとに直接出力`dp[n]`。 

計算は純粋に乗算であるため、すべての値は 1 回の線形スイープで構築されます。 

正確さは、すべての有効なツリーが持つ不変条件に基づいています。$n$ラベル付きの葉はまさに$2n-5$次数制約を維持しながら新しいリーフを挿入できるエッジ。 各挿入は可逆的であり、一意のより大きなツリーを生成するため、乗算では各拡張が 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def main():
    t = int(input())
    ns = [int(input()) for _ in range(t)]
    max_n = max(ns)

    dp = [0] * (max_n + 1)

    if max_n >= 3:
        dp[3] = 1
        for n in range(4, max_n + 1):
            dp[n] = dp[n - 1] * (2 * n - 5) % MOD

    out = []
    for n in ns:
        out.append(str(dp[n]))
    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    main()
```DP 配列は、クエリされた最大値まで 1 回構築されます。$n$。 各遷移には、対応するツリー内の利用可能なエッジの数から導出される奇数線形項が乗算されます。 クエリはルックアップによって一定時間内に応答されます。 

微妙な点は、次の初期化です。$n=3$。 このベースから開始すると、式内で無効な負のインデックスを扱うことがなくなります。 繰り返しは次からのみ有効です。$n \ge 4$。 

## 実用的な例

 シーケンスがどのように展開するかを確認するには、小さな値を考慮してください。 

のために$n=3$、次のように設定します。 

| n | dp[n] | 遷移 |
 | --- | --- | --- |
 | 3 | 1 | ベース |

 のために$n=4$:

 | n | dp[n] | 遷移 |
 | --- | --- | --- |
 | 3 | 1 | ベース |
 | 4 | 1 × 3 = 3 | 掛ける$2·4-5=3$|

 のために$n=5$:

 | n | dp[n] | 遷移 |
 | --- | --- | --- |
 | 3 | 1 | ベース |
 | 4 | 3 | 前のステップ |
 | 5 | 3 × 5 = 15 | 掛ける$2·5-5=5$|

 これは、葉が増えるにつれて予想される木のトポロジーの成長と一致します。 各ステップでは、立方体のツリーの拡大する組み合わせ構造を反映して、取り付け位置の数が厳密に増加します。

 ## 特殊なケース

 のために$n=3$、ツリーには内部構造がなく、答えは 1 でなければなりません。アルゴリズムはこの基本ケースを明示的に設定するため、より小さいインデックスで再帰が誤って適用されることはありません。 

大型用$n$、積は急速に成長しますが、モジュロ演算の下では管理可能なままです。 この実装では、乗算が常に 998244353 を法として削減されるため、オーバーフローが防止され、値の制限が維持されます。 

のために$n=4$、有効なツリーはちょうど 3 つあります。 これは、再発が活性化する最初の重要なケースであり、その要因が検証されます。$2n-5$利用可能な取り付け位置を正確にカウントします。
