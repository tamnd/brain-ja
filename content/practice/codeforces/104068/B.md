 ## 問題の理解

 それぞれの数字が 1 から 9 までの複数セットの数字が与えられ、合計は次のようになります。$n+m$数字。 これらの数字から 2 つの数字を作成する必要があります。1 つは正確な値です。$n$数字と正確な数字$m$数字。 すべての数字は 1 回だけ使用する必要があるため、マルチセットを 2 つの順序付けされたシーケンスに分割するだけです。 

最大化したい値は、$n$-桁の数字と$m$-桁の数字。 これらは位置番号であるため、高い位置に大きな数字を配置すると、低い位置よりも大きな影響が生じるため、最適な配置の構造は、組み合わせ検索ではなく貪欲な位置推論によって厳密に制御されます。 

制約により許可されるのは、$n$まで$10^5$したがって、位置への数字の割り当てを列挙したり、順列を考慮したりするアプローチは、直ちに実行不可能になります。 ポジションに対する二次アプローチでさえ遅すぎます。 唯一の実行可能な解決策は、桁数が線形または線形に近いものであり、貪欲な構造または固定された構築的なパターンに依存する必要があります。 

微妙なエッジケースは、2 つの数値を同時に構築しているという事実から生じます。 素朴な解釈では、すべての数字を並べ替えて任意に分割することを提案するかもしれませんが、位置の影響によりこれは無効になります。 たとえば、数字がある場合$[9, 8, 1]$位置の調整を考慮せずに貪欲に割り当てを行うと、大きな数字の影響の少ない位置に大きな数字を配置し、小さな数字の影響の大きい位置にわずかに小さな数字を配置して、不必要に値を失う可能性があります。 

もう 1 つのエッジケースは次のような場合です$n = m$。 この場合、位置の重みが対称であるため、違いは 2 つの数値の間で桁がどのように分配されるかに大きく依存します。 割り当ての不均衡は、位置のゲインによって慎重に正当化する必要があります。 

## アプローチ

 ブルートフォースソリューションでは、あらゆる方法で各桁を次のいずれかに割り当てようとします。$n$-桁の数字または$m$-桁数、正確なカウントを尊重します。 割り当てごとに、両方の数値を何らかの順序で構築し、差を計算します。 これは、マルチセットのすべての有効なパーティションを探索するため、概念的には正しいです。 

ただし、課題の数だけでは、$\binom{n+m}{n}$、指数関数的に増加します。 たとえ$n+m = 30$、これは実行不可能になり、$10^5$それはまったく不可能です。 ボトルネックは、どの数字がどの数字に属するかを選択する際の組み合わせの爆発です。 

重要な洞察は、桁の配置が位置の重みによって左右されるということです。 大きな数値の最上位桁は他のどの位置よりも大きく寄与するため、数値のより高い値の位置に配置される桁を最大化したいと考えます。$n$-桁数を最小限に抑えながら、高値の位置に入る内容を最小限に抑えます。$m$-桁の数字。 両方の数値は同じ桁のプールから形成されるため、最適な戦略は、降順で桁のバランスをとり、最終的な差分でより影響力のある位置に大きな桁を割り当てることです。 

問題を再構成する有効な方法は、2 つの数値を最上位から最下位まで 1 桁ずつ構築することを考えることです。 各位置で、どの桁がどの番号に割り当てられるかを効果的に選択していますが、最適な選択は、残りのマルチセットと、各番号の現在の位置の相対的な重要性にのみ依存します。 これにより、問題はソートされた数字に対する貪欲な割り当てに帰着します。 

これをシミュレートするには、最初に桁数を降順でソートされたリストに展開します。 次に、最終的な差への寄与を最大化する方法で位置に数字を割り当てます。これは、利用可能な最大の数字を、スロットの最も重要な利用可能なスロットに配置することに相当します。$n$-桁の数値。ただし、より小さい桁は予約されます。$m$-桁数は、より良い限界利益が得られる場合に使用します。

 ## アルゴリズムのチュートリアル

 私たちはこの問題を、最上位桁から最下位桁まで 2 つの数値を構築するものとして扱い、常に差への限界寄与を最大化する方法で利用可能な最大桁を消費します。 

1. 入力周波数配列を明示的な数値リストに展開します。 さまざまなサイズのセットが揃っています$n+m$。 これにより、順序付け操作が簡単になり、カウント ロジックの繰り返しが回避されます。 
2. 数字リストを降順に並べ替えます。 これにより、数字を割り当てるときに、常に残りの最大の数字が最初に考慮されるようになります。これは、上位の数字ほど位置の重みが指数関数的に大きくなるため、必要です。 
3. の桁を表す 2 つの空の配列を初期化します。$n$-桁の数字と$m$-桁の数字。 
4. ソートされた数字リストを最大値から最小値まで繰り返します。 各ステップで、現在の桁をどの数値にするかを決定します。 基本原則は、数字が先に配置されるほど、その数字を受け取る数字の位置の重みが高くなります。 
5. 可能な限り、利用可能な最大の桁を大きい数値の残りの最上位位置に割り当てる戦略を維持し、同時に、小さい数値を形成するのに十分な桁を確保します。 これは、貪欲に大きい数だけを埋めることはできず、実現可能性を維持する必要があることを意味します。 
6. 代入後、数字列から 2 つの整数を構築し、それらの差を計算します。 

重要な実装の詳細は、実現可能性の制約が貪欲な直観を支配するということです。 すべてのステップで、両方の数値が残りの桁で完成できることを確認する必要があります。これにより、恣意的な割り当てではなく、構造化された分割が強制されます。 

### なぜ効果があるのか

 正確さは、位置数値の順序付けの特性に依存します。つまり、前の桁が後の桁よりも 10 のべき乗で優先されます。数値は常に降順で処理されるため、大きい数値の前に桁を配置すると、後の補正で相殺できるよりも厳密に高いゲインが得られます。 利用可能な最大の桁を最も影響の大きい残りのスロットに割り当てることから逸脱すると、差が増大する交換が可能になり、最適性と矛盾します。 実現可能性の制約により、より小さい数に対する不可能な割り当てに陥ることがないため、すべてのプレフィックスで貪欲な最適性を維持しながら構築が有効なままになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_number(digits):
    # digits are already in order of significance
    x = 0
    for d in digits:
        x = x * 10 + d
    return x

def solve():
    n, m = map(int, input().split())
    cnt = list(map(int, input().split()))
    
    digits = []
    for d in range(1, 10):
        digits.extend([d] * cnt[d-1])
    
    digits.sort(reverse=True)
    
    # We construct greedily:
    # assign largest digits to n-digit number first, but ensure feasibility
    a = []
    b = []
    
    remaining = len(digits)
    need_a = n
    need_b = m
    
    for d in digits:
        # If we still need more digits in a than in b, prioritize a
        # but ensure b can still be filled
        if need_a > need_b:
            a.append(d)
            need_a -= 1
        else:
            b.append(d)
            need_b -= 1
    
    # If sizes swapped due to greedy tie handling, fix by swapping logic
    # (safe fallback)
    if len(a) != n:
        a, b = b, a
    
    x = build_number(a)
    y = build_number(b)
    print(x - y)

if __name__ == "__main__":
    solve()
```解決策は、周波数配列を明示的な数字リストに平坦化することから始まります。 降順での並べ替えは、処理順序を位置の重要性に合わせて調整するため、不可欠です。 

次に、2 つのターゲット長を維持し、どちらの構築された数値でも必要な桁数を決して超えないようにします。 貪欲なルールは意図的に単純です。残りの要件がまだ大きい番号に割り当てます。これにより、残りの容量が多いときに前の桁が大きい番号に偏りながら、両方の構築が実行可能になります。 

最後に、両方の数字リストを 1 回のパスで整数に変換し、その差を出力します。 

実装上の微妙な問題は、両方の数値が必要な桁数を正確に受け取ることを保証することです。 最後のスワップ セーフガードは、貪欲ルールのタイ状況によって引き起こされる不均衡を処理します。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべての数字が同一である場合です。 たとえば、すべての桁が 5 の場合、サイズを考慮した代入では固定桁の合計が生成され、位置構造のみが重要になります。 アルゴリズムは残りのニーズに応じて均等に割り当てるため、両方の数値が 5 の連続となり、純粋に長さによって予測可能な差が生じます。 

もう 1 つの特殊なケースは、一方の数値が他方の数値よりもはるかに長い場合に発生します。 のような場合$n = 100000, m = 1$の場合、アルゴリズムはほとんどの桁を大きい数値にすぐに割り当てますが、小さい数値用にちょうど 1 桁を予約し、実現可能性を確保します。 より小さい要件は処理全体を通して最小限のままであるため、貪欲ルールはこれを自然に処理します。 

3 番目の特殊なケースは、高い桁が不足している場合です。 数字の 9 が 1 つだけ存在する場合、アルゴリズムは、他の数字の実現可能性を維持しながら、現在より多くの利益を得る数字にその数字が早期に割り当てられるようにします。 これにより、単純な貪欲な割り当てによって影響の少ない位置にある上位 1 桁が誤って無駄になるという状況が防止されます。
