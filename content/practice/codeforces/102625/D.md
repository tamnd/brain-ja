 ## 解決策
 # 問題の理解

 初日は料金1からスタートします。 翌日ごとに、新しい料金は、2 倍、3 倍、または 1 増加の 3 つの操作のいずれかによって、前日の料金から取得する必要があります。 目標料金が与えられた場合`D`最終日の料金が正確に請求されるように、必要な最小日数を見つける必要があります。`D`。 また、その最小日数で目標に達する日次料金の有効なシーケンスを 1 つ出力する必要があります。 

入力には複数の独立したターゲットが含まれています。 最大目標はこれだけなので、`10^6`、意図したソリューションでは、表示される最大のターゲットまでのすべての可能な値を前処理することができます。 すべてのクエリから個別に検索を試みるソリューションでは、作業が無駄になります。`10^5`クエリ。 この規模では、`O(D)`または`O(maxD)`前処理アプローチは適していますが、クエリごとに多くのパスを個別に探索するアルゴリズムは、簡単に遅くなりすぎる可能性があります。 

主なエッジ ケースは、非常に小さな値や、最適なルートが最大の乗算をすぐに使用しない値の周囲に現れます。 たとえば、`D = 1`、答えは 1 日で、順序は次のとおりです。`1`。 開始状態を考慮するのではなく、移動から検索を開始する実装では、誤って長い応答が返される可能性があります。 

のために`D = 5`、最適な順序は次のとおりです。```
1 3 4 5
```出力は`4`日々。 可能であれば常に増やすという貪欲な戦略は、`1 2 4 5`、これは有効ですが、ここでも 4 日間あり、問題が隠れています。 値が大きい場合、やみくもに乗算を優先すると、より短いパスが失われる可能性があります。これは、有効な中間値に到達してしまうためです。`+1`後の乗算チェーンを有効にすることができます。 

のために`D = 10`、最も短いシーケンスの 1 つは次のとおりです。```
1 2 3 9 10
```答えは`5`日々。 親の選択ではなく距離だけを保存する方法では、正しい最小長は見つかりますが、必要な電荷シーケンスを再構成することはできません。 

# アプローチ

 直接的なブルート フォース ソリューションでは、考えられるすべての操作シーケンスをモデル化できます。 から始まる`1`、次のすべての組み合わせを試します。`+1`、`*2`、 そして`*3`到達するまで`D`。 これは正しいです。すべての正当なシーケンスが調査されるため、最初に見つかった最短のシーケンスが答えになります。 問題は可能性の数です。 後`k`までの日数があります`3^k`操作シーケンスが異なるため、これは指数関数的に増大し、適度に大きなターゲットであっても不可能になります。 

問題の構造により、より明確な見方が得られます。 すべての電荷値はグラフ内のノードです。 値から`x`、にはエッジがあります`x + 1`、`2x`、 そして`3x`これらの値が必要な最大ターゲットより大きくないときはいつでも。 すべての有効な電荷シーケンスは、まさにこのグラフ内のパスです。 すべての操作に 1 日かかるため、最短シーケンスはノードからの最短パスになります。`1`ノードへ`D`。 すべてのエッジのコストが等しいため、幅優先検索では最小日数が見つかります。 

ブルート フォース検索は、類似した部分シーケンスを繰り返し探索するため失敗します。 BFS は、同じ電荷値に達するすべてのパスをマージし、各状態を 1 回解決します。 訪問したすべての値の親を保存することで、ターゲットを見つけた後に正確なシーケンスを再構築できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(3^k) | O(k) | 遅すぎる |
 | 最適 | O(最大D) | O(最大D) | 承認済み |

 # アルゴリズムのチュートリアル

 1. すべての目標値を読み取り、最大の目標値を見つけます。`M`。 までの状態を構築するだけで済みます。`M`この問題では、有用な中間値が最終目的地を超えることはできないためです。 すべての操作はチャージを増加させるだけです。 
2.充電からBFSを実行する`1`。 到達したすべての充電の距離と、到達するために使用された前回の充電を保存します。 BFS キューにより、値が処理されるまでの日数が増加することが保証されます。 
3. 現在の充電ごとに`x`、次に考えられる 3 つの請求を試してください。`x + 1`、`2x`、 そして`3x`。 より大きい値を無視する`M`またはすでに訪問された値。 初めて値にアクセスするときは最短パスを経由するため、その親を永続的に固定できます。 
4. 各クエリについて`D`、から始めます`D`に到達するまで、保存された親を繰り返したどります`1`。 この収集されたリストを逆にして、毎日の料金シーケンスを正順に取得します。 

機能する理由: BFS は、2 日で到達可能なすべての状態の前に 1 日で到達可能なすべての状態を探索し、次に 3 日以内に到達可能なすべての状態を探索します。 したがって、最初に料金値に到達したときに、使用されるパスの操作数は可能な限り少なくなります。 親ポインタには、到達可能なすべての電荷への最短パスが 1 つだけ保存されているため、次からそれらをたどります。`D`に戻る`1`最適なシーケンスを再構築します。 

# Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    data = list(map(int, sys.stdin.buffer.read().split()))
    if not data:
        return

    t = data[0]
    queries = data[1:1 + t]
    limit = max(queries)

    parent = [-1] * (limit + 1)
    parent[1] = 0

    from collections import deque
    q = deque([1])

    while q:
        x = q.popleft()

        for y in (x + 1, x * 2, x * 3):
            if y <= limit and parent[y] == -1:
                parent[y] = x
                q.append(y)

    ans = []
    for d in queries:
        path = []
        cur = d
        while cur != 0:
            path.append(cur)
            if cur == 1:
                break
            cur = parent[cur]
        path.reverse()

        ans.append(str(len(path)))
        ans.append(" ".join(map(str, path)))

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```前処理部では最短パスツリーを一度構築します。 の`parent`配列には 2 つの目的があります。`parent[x] == -1`は値がまだ到達していないことを意味し、それ以外の場合は最短パスで以前の電荷を保存します。 

すべての操作のコストは等しいため、BFS の遷移順序は正確さに影響しません。 唯一必要な条件は、新しく検出されたすべての状態が 1 回追加されることです。 最大クエリを超える値は、より小さいターゲットで終わるパスの一部になることはできないため、無視されます。 

再構築中に、パスは次から逆方向に収集されます。`D`に`1`。 それを逆にすると、日次料金の順序が表示されます。 初日にはすでに初期料金が含まれているため、日数は操作の数ではなくシーケンス内の値の数です。`1`。 

# 実用的な例

 のために`D = 5`, BFS は次の最短パスを経由してターゲットに到達します。 

| 現在の充電量 | 操作 | 新しい料金 | 親が保存された |
 | --- | --- | --- | --- |
 | 1 | *3 | 3 | 1 |
 | 3 | +1 | 4 | 3 |
 | 4 | +1 | 5 | 4 |

 保護者の方をフォローして`5`与える`5 -> 4 -> 3 -> 1`、これを反転すると次のようになります。```
1 3 4 5
```この例は、より小さな増分を含むシーケンスが、乗算のみに焦点を当てた戦略に勝てる可能性があることを示しています。 

のために`D = 10`、考えられる BFS 再構築の 1 つは次のとおりです。 

| 現在の充電量 | 操作 | 新しい料金 | 親が保存された |
 | --- | --- | --- | --- |
 | 1 | *2 | 2 | 1 |
 | 2 | +1 | 3 | 2 |
 | 3 | *3 | 9 | 3 |
 | 9 | +1 | 10 | 9 |

 再構築されたシーケンスは次のとおりです。```
1 2 3 9 10
```これは、3 つの遷移すべてを考慮する必要がある理由を示しています。 の削除`+1`この操作により、一部の最適なパスが到達不能になります。 

# 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(最大D) | 各電荷値は 1 回訪問され、3 つの発信遷移があります。 |
 | スペース | O(最大D) | 親アレイと BFS キューには、到達可能な各料金の情報が保存されます。 |

 最大の目標は、`10^6`したがって、前処理では最大 100 万の州を訪問します。 これは簡単に制限内に収まり、最大で作業を繰り返す必要がなくなります。`10^5`クエリ。 

# テストケース```python
import sys
import io
from collections import deque

def solution(inp: str) -> str:
    old = sys.stdin
    sys.stdin = io.StringIO(inp)

    data = list(map(int, sys.stdin.buffer.read().split()))
    if not data:
        sys.stdin = old
        return ""

    t = data[0]
    queries = data[1:1+t]
    limit = max(queries)

    parent = [-1] * (limit + 1)
    parent[1] = 0
    q = deque([1])

    while q:
        x = q.popleft()
        for y in (x + 1, x * 2, x * 3):
            if y <= limit and parent[y] == -1:
                parent[y] = x
                q.append(y)

    out = []
    for d in queries:
        path = []
        while d:
            path.append(d)
            if d == 1:
                break
            d = parent[d]
        path.reverse()
        out.append(str(len(path)))
        out.append(" ".join(map(str, path)))

    sys.stdin = old
    return "\n".join(out)

 # エッジケース

 のために`D = 1`、BFS はすでに発見された答えから始まります。 再構築ループは直ちに停止し、単一の電荷を返します。`1`。 これにより、少なくとも 1 つの操作が必要であると想定するというよくある間違いを回避できます。 

などのターゲットに対して、`D = 5`、アルゴリズムは乗算パスを強制しません。 BFS は、すべての値から 3 つの選択肢をすべて探索し、各状態への最初の最短ルートを維持します。 保存された親チェーンが到達する`5`を通して`1 -> 3 -> 4 -> 5`、最小日数を指定します。 

最大限の目標に向けて`D = 1000000`の場合、アルゴリズムはこの値を超える状態を作成しません。 BFS は依然として有用な検索空間全体を 1 回カバーしており、親配列により別の検索を行わずに再構築が可能です。 BFS 中にすべての状態に距離が割り当てられたため、結果として得られるシーケンスの長さは最小限になります。
