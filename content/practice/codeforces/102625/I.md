 ## 解決策
 ## 問題の理解

 この問題では、指定された順序からジュニアの連続グループを 1 つ選択するように求められます。 最初から何人かのジュニアを削除し、最後から何人かを削除することもできますが、残りのジュニアは連続したままでなければなりません。 選択したセグメントに値がある場合`t1, t2, ..., tk`、その幸福度は次のように計算されます。`1*t1 + 2*t2 + ... + k*tk`。 可能な限り最大限の幸福が必要であり、ジュニアを選択しないことは許可されず、スコアは 0 になります。 

入力には、ジュニアの数と各ジュニアの幸福貢献値が含まれます。 出力は、連続したセグメントから取得できる最高のスコアを表す単一の整数です。 

到達できるジュニアの数`2 * 10^5`、各値の大きさは最大で`10^7`。 二次アプローチは次のように実行されます。`n^2 / 2`セグメントチェック、これは約になります`2 * 10^10`最悪の場合の運用。 これは通常の制限時間内に収まる時間をはるかに超えています。 線形または線形に近いアルゴリズムが必要です。`n log n`。 

値は負の値になる可能性があるため、空ではないセグメントが常に優れていると仮定するのは誤りです。 たとえば:

 入力:```
3
-60 -70 -80
```正しい出力は次のとおりです。```
0
```常に最初の要素で始まるメソッド、または常にセグメントを選択するメソッドは、たとえおやつを与えることが許可されていない場合でも、負の値を返します。 

もう 1 つの注意が必要なケースは、プレフィックスを削除した後にセグメントの重みが 1 から再開されることです。 たとえば:

 入力:```
6
5 -1000 1 -3 7 -8
```最高のセグメントは`[1, -3, 7]`、最初の値を含むセグメントではありません。 そのスコアは`1*1 + 2*(-3) + 3*7 = 16`。 選択したセグメント内の位置の代わりに元のインデックスを使用する不注意な実装では、間違った式が計算されます。 

## アプローチ

 直接的な解決策は、考えられるすべての連続セグメントを試してみることです。 からのセグメントの場合`l`に`r`を実行し、すべての要素にセグメント内の位置を乗算することで、そのスコアを計算できます。 これは定義に正確に従っているため、正しいです。 

ただし、`O(n^2)`可能なセグメント。 すべてのスコア計算がプレフィックス合計を使用して最適化されている場合でも、エンドポイントのすべてのペアをチェックするには、依然として約`4 * 10^10`エンドポイントの組み合わせ`n = 200000`が遅すぎます。 

重要な観察は、セグメントのスコアが、考えられる各左境界が線になる形式に変換できるということです。 プレフィックス合計を使用すると、すべてのセグメントの加重合計を再構築する必要がなくなり、データ構造は以前の最適な左境界を維持できます。 

させて`P[i]`までの値のプレフィックス合計になります。`i`、そしてさせてください`Q[i]`のプレフィックスの合計になります`index * value`、インデックスは 1 から始まります。 位置の後に始まるセグメントの場合`j`そして終わる`r`、そのスコアは次のとおりです。`Q[r] - Q[j] - j * (P[r] - P[j])`並べ替え:`Q[r] - j * P[r] + (j * P[j] - Q[j])`固定の場合`r`、`Q[r]`は一定です。 残りの式は行数の最大値を求めます。`y = -j * x + (j * P[j] - Q[j])`で`x = P[r]`。 

前の位置ごとに 1 つの行が作成され、新しいプレフィックスの合計がクエリになります。 プレフィックスの合計は負または正の値になる可能性があるため、Li Chao Tree を使用して任意のクエリ座標をサポートします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を左から右に処理しながらプレフィックスの合計を作成します。 維持する`P`、通常のプレフィックスの合計、および`Q`、重み付けされたプレフィックスの合計。 
2. 位置に対応する行を挿入`j = 0`要素を処理する前に。 これは、最初の要素からセグメントを開始することを表します。 ラインに勾配がある`0`そしてインターセプト`0`。 
3. ポジションごとに`r`、現在の値が含まれるようにプレフィックスの合計を更新します。 Li Chao ツリーのクエリは次のとおりです。`x = P[r]`。 返された最大行値にプラスした値`Q[r]`で終わる最適なセグメントを提供します`r`。 
4. 現在のプレフィックスを使用した後、この位置で作成された行を挿入します。 ラインは以下に基づいています`j = r`将来のセグメントがこの位置の後に開始される可能性があるためです。 
5. ジュニアを選択しないことは有効であるため、取得したすべての値とゼロの間の最大値を維持します。 

なぜ効果があるのか:

 あらゆるポジションで`r`、で終わるすべての可能なセグメント`r`ちょうど 1 つ前の位置に対応します`j`。 によって作成されたライン`j`その開始点を選択したことによる貢献を保存します。 現在のプレフィックス合計でクエリを実行すると、以前のすべての開始ポイントの中から可能な限り最良の開始ポイントが選択されます。 適切なエンドポイントが処理される際には、考えられるすべてのセグメントが考慮されるため、見つかった最大値がまさに達成可能な最高の幸福になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class LiChao:
    def __init__(self, xs):
        self.xs = xs
        self.tree = [None] * (4 * len(xs))

    def value(self, line, x):
        m, c = line
        return m * x + c

    def add_line(self, line, node=1, left=0, right=None):
        if right is None:
            right = len(self.xs) - 1

        mid = (left + right) // 2
        x_left = self.xs[left]
        x_mid = self.xs[mid]

        if self.tree[node] is None:
            self.tree[node] = line
            return

        cur = self.tree[node]

        if self.value(line, x_mid) > self.value(cur, x_mid):
            self.tree[node], line = line, self.tree[node]
            cur = self.tree[node]

        if left == right:
            return

        if self.value(line, x_left) > self.value(cur, x_left):
            self.add_line(line, node * 2, left, mid)
        elif self.value(line, self.xs[right]) > self.value(cur, self.xs[right]):
            self.add_line(line, node * 2 + 1, mid + 1, right)

    def query(self, x, node=1, left=0, right=None):
        if right is None:
            right = len(self.xs) - 1

        res = -10**30
        if self.tree[node] is not None:
            res = self.value(self.tree[node], x)

        if left == right:
            return res

        mid = (left + right) // 2
        if x <= self.xs[mid]:
            return max(res, self.query(x, node * 2, left, mid))
        return max(res, self.query(x, node * 2 + 1, mid + 1, right))

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    pref = [0]
    weighted = [0]

    s = 0
    w = 0
    for i, x in enumerate(a, 1):
        s += x
        w += i * x
        pref.append(s)
        weighted.append(w)

    lichao = LiChao(pref)

    ans = 0
    lichao.add_line((0, 0))

    for i in range(1, n + 1):
        best = lichao.query(pref[i])
        ans = max(ans, weighted[i] + best)

        j = i
        lichao.add_line((-j, j * pref[j] - weighted[j]))

    print(ans)

if __name__ == "__main__":
    solve()
```Li Chao Tree はラインをフォームに保存します`slope * x + intercept`。 ポジションについて`j`、傾きは`-j`そして切片は`j * P[j] - Q[j]`、再配置されたセグメント式と一致します。 

幸福度スコアの乗数は 1 から始まるため、プレフィックス配列では 1 から始まる位置が使用されます。 ゼロベースのインデックスを数式と混合すると、誤った答えが生じる一般的な原因になります。 

クエリは、現在位置の行を挿入する前に実行されます。 現在のプレフィックスをそれ自体で終わるセグメントの開始点として使用すると、空のセグメントが作成されるため、使用できません。 最初に挿入されたゼロ行は、最初のジュニアから始まるセグメントを処理します。 

Python の整数はオーバーフローしないため、大きな中間値は`index * value`安全を保ちます。

 ## 特殊なケース

 負の値のみを含む配列の場合、Li Chao ツリーは引き続き有効なセグメント値を生成しますが、最後のゼロとの比較により、正しい答えが維持されます。 入力の場合:```
3
-60 -70 -80
```挿入された各行は負の値またはそれより小さい値を生成するため、答えは残ります。`0`。 

最適なセグメントが大きな負のプレフィックスの後に始まる場合、アルゴリズムは初期の要素にコミットしません。 で：```
6
5 -1000 1 -3 7 -8
```正のセグメントの前のプレフィックス位置はすべて線で表されます。 各位置の最後にあるクエリにより、最適な開始点が自動的に選択され、セグメントが得られます。`[1, -3, 7]`そしてスコア`16`。 

すべての値が正の場合でも、アルゴリズムは選択したセグメント内の増加する重みを考慮する必要があります。 のために：```
4
1 2 3 4
```セグメント全体が選択され、`1 + 4 + 9 + 16 = 30`。 プレフィックス変換では、重み付けされたプレフィックスが使用されるため、これらの増加する乗数が保持されます。`Q`元の位置寄与を保存し、ライン補正により選択したセグメントの開始位置に戻します。
