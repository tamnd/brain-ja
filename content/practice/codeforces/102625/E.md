 ## 解決策
 ## 問題の理解

 問題は、座標の開始点 Ruby から伸びる線を記述します。`0`正門方面へ。 ガードは固定座標に立っており、各ガードは一定の時間間隔でのみアクティブになります。 カップルは、異なる整数の開始時間で Ruby から歩き始め、毎秒 1 単位の距離を移動します。 すべてのカップルについて、最初の警備員に会うまでに歩く距離を確認するか、報告する必要があります。`-1`誰にも会わずに最後まで辿り着いたら。 

座標の警備員`X`インターバル中はアクティブです`[L-z, R-z]`、 どこ`z`より小さい小さな正の値です`0.1`。 時間から始まるカップル`T`正確にこのガードに到達した後`X`秒、時間`T + X`。 捕まる条件は以下の通りです。`L - z <= T + X <= R - z`並べ替え:`L - X - z <= T <= R - X - z`入力値は整数ですが、`z`はわずかな正の部分です。 これにより、整数の境界が変更されます。 有効な最小の整数`T`は`L - X`、 なぜなら`L - X`まだより大きいです`L - X - z`。 有効な最大の整数`T`は`R - X - 1`、 なぜなら`R - X`分数がすでに大きすぎます`z`。 

したがって、すべてのガードは時間間隔を作成していると見なすことができます。`[L - X, R - X - 1]`この間隔内のすべての整数開始時間中に、そのガードはカップルを捕まえることができます。 

制限により、最大で許可されます`200000`警備員と`200000`カップル。 すべてのカップルをすべてのガードに対してチェックするアプローチでは、約`4 * 10^10`これは数秒で許される時間をはるかに超えています。 に近い解決策が必要です`O((M+N) log M)`。 

よくある間違いは、分数の効果を忘れることです。`z`。 例えば：```
1 1
0 1 5
5
```ガードはからアクティブになります`-0.1`に`0.9`。 カップルはコーディネートに到達します`5`時に`10`、したがって、答えは次のとおりです`-1`。 を使用した間違った変換`[L-X, R-X]`開始時刻が誤って含まれてしまう`-5`他の状況でのみ、境界を 1 つずらすことができます。 

もう 1 つの注意が必要なケースは、小数シフトを行わずに右エンドポイントに正確に到達するガードです。```
1 1
10 20 5
15
```カップルは時間通りに警備員に到着します`20`。 元のアクティブな間隔は次の時点で終了します。`19.9`, したがって、警備員はもう存在しません。 正しい出力は次のとおりです。```
-1
```間隔を整数のエンドポイントで閉じられたものとして扱うと、誤って出力される`5`。 

## アプローチ

 直接的なアプローチは、すべてのカップルを個別にシミュレートすることです。 開始時間ごとに、すべてのガードをチェックし、アクティブな間にカップルがそのガードに到達するかどうかを確認します。 複数のガードが一致する場合、カップルは最初に遭遇したガードで停止するため、最小の座標が維持されます。 これは動きを直接モデル化しているため正しいですが、最悪の場合はパフォーマンスが低下します。`M * N`小切手。 両方の値が等しい場合`200000`、これはおよそ 400 億件の比較になります。 

有益な観察は、クエリがすでに開始時間によってソートされていることです。 すべてのカップルについてすべての警備員に尋ねる代わりに、時間を一度だけ調べてみることができます。 各ガードは時間に応じてアクティブになります`L-X`時間が経つと活動が停止します`R-X-1`。 カップルを昇順に処理しながら、`T`、現在アクティブなガードの中で最小の座標を知る必要があるだけです。 

これにはプライオリティ キューで十分です。 ガードがアクティブになり始めると、その座標と終了時間を挿入します。 クエリに答える前に、終了時間が現在の開始時間より短いガードをすべて削除します。 ヒープに残っている最小の座標が、カップルが最初に遭遇するガードになります。

 ## アルゴリズムのチュートリアル

 1. すべてのガードを時間間隔に変換します。 座標の警備員用`X`、開始時間の間アクティブであるストア`L-X`に`R-X-1`。 コーディネート`X`出力する必要がある値であるため、間隔とともに保存されます。 
2. 変換されたすべてのガード インターバルを開始時間順に並べ替えます。 並べ替えは、カップルも昇順で到着するため、関連性が生じたときに正確にガードを追加できるため便利です。 
3. 最小の開始時間から最大の開始時間までカップルを処理します。 いくつかの質問に答える前に、変換された間隔が現在時刻以降に始まるすべてのガードを追加します。 これらは、このカップルまたはその後のカップルに影響を与える可能性のある唯一の新しいガードです。 
4. ガードの終了時間が現在のカップルの開始時間より短い間に、優先キューからガードを削除します。 そのような警備員はすでに活動を停止しています。 
5. ヒープが空の場合、ガードはカップルをキャッチできないため、出力`-1`。 それ以外の場合、ヒープ内の最小の座標が最初に検出されたガードになります。 

なぜ効果があるのか:

 いつでもクエリ時に`T`、ヒープには、変換された間隔に含まれるガードが正確に含まれます。`T`。 ヒープ内にないすべてのガードは、後で開始されるか、すでに期限切れになっています。 すべてのアクティブなガードの中で、カップルは物理的に最初に最小の座標に到達します。`X`は正しい答えを出します。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    data = input().split()
    if not data:
        return

    M, N = map(int, data)

    guards = []
    for _ in range(M):
        L, R, X = map(int, input().split())
        guards.append((L - X, R - X - 1, X))

    guards.sort()

    queries = []
    for _ in range(N):
        queries.append(int(input()))

    heap = []
    ans = []
    idx = 0

    for t in queries:
        while idx < M and guards[idx][0] <= t:
            start, end, x = guards[idx]
            heapq.heappush(heap, (x, end))
            idx += 1

        while heap and heap[0][1] < t:
            heapq.heappop(heap)

        if heap:
            ans.append(str(heap[0][0]))
        else:
            ans.append("-1")

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```ガード変換は、実装の中で最もデリケートな部分です。 終了時刻は次のとおりでなければなりません`R-X-1`、 ない`R-X`、正の値により、元の間隔はその整数時間の少し前に終了するためです。`z`。 

ヒープストア`(coordinate, ending_time)`。 最も近い警備員が必要なため、座標が優先されます。 終了時刻は保持されるため、期限切れのガードは後で削除できます。 

クエリは入力内ですでに並べ替えられているため、追加の並べ替えは必要ありません。 ポインタ`idx`前進のみに移動します。つまり、すべてのガードはヒープに 1 回入り、最大 1 回だけヒープから出ます。

## テストケース```python
import sys
import io
import heapq

def run(inp: str) -> str:
    old = sys.stdin
    sys.stdin = io.StringIO(inp)

    def solve():
        input = sys.stdin.readline
        M, N = map(int, input().split())
        guards = []
        for _ in range(M):
            L, R, X = map(int, input().split())
            guards.append((L - X, R - X - 1, X))
        guards.sort()

        heap = []
        idx = 0
        res = []

        for _ in range(N):
            t = int(input())
            while idx < M and guards[idx][0] <= t:
                heapq.heappush(heap, (guards[idx][2], guards[idx][1]))
                idx += 1
            while heap and heap[0][1] < t:
                heapq.heappop(heap)
            res.append(str(heap[0][0]) if heap else "-1")

        return "\n".join(res)

    out = solve()
    sys.stdin = old
    return out

 ## 特殊なケース

 カップルが到着したときにちょうど終了する警備員は、彼らを捕まえてはなりません。 入力:```
1 1
10 20 5
15
```変換された区間を与える`[5,14]`。 問い合わせ時間は`15`、これは間隔外であるため、ヒープは応答する前にガードを解除して返します。`-1`。 

カップルが到達できるときに正確に開始されるガードを含める必要があります。 のために：```
1 1
3 4 2
1
```変換された区間は`[1,1]`。 処理時間の前にガードが挿入されます`1`はアクティブのままで、答えは次のとおりです。`2`。 

同じ座標にある複数のガードも自然に処理されます。 ヒープには同じ座標を持つ複数のエントリが含まれている場合がありますが、最小値を返しても正しい停止距離が得られます。 同じ座標の間隔が重ならないという入力保証により、同時状態の競合によってあいまいさが生じるのを防ぎます。
