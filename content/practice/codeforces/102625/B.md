 ## 解決策
 ## 問題の理解

 同じ長さの 2 つの文字列があります。 最初の弦は開始時の配置で、2 番目の弦は到達したいターゲットの配置です。 移動は、隣接する 2 つの文字が異なるグループに属している場合にのみ許可されます。1 つのグループには次のような文字が含まれます。`a`、`c`、`e`、アルファベットの位置が奇数で、もう一方には次のような文字が含まれています。`b`、`d`、`f`、アルファベットの位置は偶数です。 このような隣接する文字は交換されてもよい。 

問題は、有効なスワップのシーケンスによって最初の文字列を 2 番目の文字列に変換できるかどうかです。 

各文字列の長さは次のとおりです。$10^5$。 これにより、可能性のあるスワップ シーケンスをシミュレートしたり状態を探索したりするアプローチは即座に除外されます。各位置で線形の数の選択肢があっても膨大な検索スペースが作成されるためです。 有効なソリューションでは、文字列を少数回検査する必要があります。$O(n)$または$O(n \log n)$というアプローチが適しています。 

主な罠は、文字のあらゆる並べ替えが可能であると仮定することから生じます。 例えば：```
Special:  ab
Elegant:  ba
```答えは`Yes`、 なぜなら`a`そして`b`異なるグループに属しており、直接交換できます。 

より微妙なケースは次のとおりです。```
Special:  abc
Elegant:  cba
```答えは`No`。 文字`a`そして`c`同じグループに属しているため、互いに交わることはありません。 2 つの文字列に同じ文字が含まれているかどうかだけをチェックする不注意な解決策では、このケースが誤って受け入れられてしまいます。 

もう 1 つのエッジ ケースは、文字列のグループ順序はすでに同じだが、グループの位置が異なる場合です。```
Special:  abcde
Elegant:  baced
```答えは`Yes`。 奇数位置のアルファベット文字の相対順序は次のとおりです。`ace`両方の文字列で、偶数位置のアルファベット文字の相対順序は次のとおりです。`bd`両方の文字列で。 許可されたスワップにより、これら 2 つのグループがどのようにインターリーブされるかを再配置できます。 

## アプローチ

 ブルート フォース ソリューションでは、有効なスワップを実行し、作成可能なすべての文字列を検索しようとします。 これは正しいです。到達可能なすべての状態が最終的に探索されることになりますが、状態の数は非常に急速に増加します。 長さの文字列$10^5$可能な配置が多すぎるため、このアプローチは使用できません。 

より単純ですが、それでも非効率的なアイデアは、現在間違った場所にあるキャラクターを繰り返し探し、隣接するスワップを使用して目的地に向かって移動することです。 それぞれの動きにかかる時間は$O(n)$多くのキャラクターに対してこれを行うと、$O(n^2)$操作。 と$10^5$キャラクター、それは周りにあります$10^{10}$最悪の場合の運用。 

重要な点は、この操作では異なるグループの文字が交換されるだけであるということです。 同じグループのキャラクターがすれ違うことはありません。 両方の文字列から偶数位置のアルファベット文字をすべて削除すると、残りの順序は同じになるはずです。 奇数位置のアルファベット文字をすべて削除した後も、同じことが当てはまります。 

これら 2 つのサブシーケンスは、変更できない唯一の情報です。 それらが一致すると、2 つの文字列は単に同じ 2 つのシーケンスの異なるインターリーブになります。 このようなインターリーブは、異なるグループの隣接する文字を繰り返し交換することで実現できます。これは、操作が 1 つのグループ要素を他のグループの要素間で正確に移動するためです。 

ブルートフォースはすべての合法的な動きに従うため機能しますが、可能な手が多すぎるため失敗します。 保存されたサブシーケンスに関する観察により、問題全体が 2 つの線形スキャンのチェックに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | 指数 | 遅すぎる |
 | 隣接移動の繰り返し | O(n²) | お(1) | 遅すぎる |
 | 保存されたサブシーケンス | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 両方の文字列を 2 つのサブシーケンスに分割します。 最初のサブシーケンスには奇数のアルファベット位置の文字が含まれ、2 番目のサブシーケンスには偶数のアルファベット位置の文字が含まれます。 これを開始文字列とターゲット文字列の両方に対して実行します。 
2. 最初の文字列の奇数位置の文字部分シーケンスと 2 番目の文字列の奇数位置の文字部分シーケンスを比較します。 

有効な交換では他のグループの文字の周囲に文字が移動するだけであるため、これらの文字の相対的な順序は決して変更できません。 
3. 偶数位置の文字部分列も同様に比較します。 

同じ理由が当てはまります。偶数位置の 2 つの文字は互いに入れ替わることはできません。 
4. サブシーケンスの両方のペアが同一の場合、次のように出力します。`Yes`。 それ以外の場合は、印刷します`No`。 

サブシーケンスが一致するということは、2 つの文字列が両方のグループ内で同じ固定順序を含んでいることを意味します。 残りの違いは、これら 2 つのグループがどのように混合されるかだけであり、これらの変更はまさに許可されたスワップによって作成できるものです。 

なぜ効果があるのか:

 有効なスワップはすべて、奇数位置のアルファベット 1 文字を偶数位置のアルファベット 1 文字と交換します。 このため、どちらのグループも内部秩序を変えることはできません。 到達可能なターゲットは両方のサブシーケンスを保持する必要があります。 

逆方向も成立します。 両方の部分列が一致すると仮定します。 奇数文字と偶数文字を、ターゲット注文にマージする必要がある 2 つのキューと考えてください。 元の文字列から開始して、隣接スワップにより、次に必要な文字を、目的の位置に到達するまで、どちらかのキューからもう一方のキューの文字にまたがって移動できます。 すべての交差した文字は反対のグループに属しているため、このような交換はすべて有効です。 このプロセスを繰り返すことでターゲット文字列が構築されるため、部分シーケンスの一致でも十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    t = input().strip()

    s_odd = []
    s_even = []
    t_odd = []
    t_even = []

    for c in s:
        if (ord(c) - ord('a') + 1) % 2 == 1:
            s_odd.append(c)
        else:
            s_even.append(c)

    for c in t:
        if (ord(c) - ord('a') + 1) % 2 == 1:
            t_odd.append(c)
        else:
            t_even.append(c)

    if s_odd == t_odd and s_even == t_even:
        print("Yes")
    else:
        print("No")

if __name__ == "__main__":
    solve()
```このコードは 4 つのリストを作成します。 最初の 2 つは、グループごとに区切られた開始文字列の文字を格納し、他の 2 つはターゲット文字列に対して同じことを行います。 

アルファベットの位置の計算には次のものを使用します。`ord(c) - ord('a') + 1`なぜなら`ord`ゼロからカウントを開始します`a`、問題のグループ化は 1 から始まります。 ここでパリティの計算が間違っていると、2 つのグループが入れ替わり、すべての答えが不正確になります。 

文字列の他のプロパティは到達可能性に影響を与えることができないため、最後の比較で十分です。 各グループ内の相対的な順序は、すべての有効な操作で生き残る唯一の情報です。

## テストケース```python
import sys
import io

def solve_case(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)

    s = sys.stdin.readline().strip()
    t = sys.stdin.readline().strip()

    s_odd = []
    s_even = []
    t_odd = []
    t_even = []

    for c in s:
        if (ord(c) - ord('a') + 1) % 2:
            s_odd.append(c)
        else:
            s_even.append(c)

    for c in t:
        if (ord(c) - ord('a') + 1) % 2:
            t_odd.append(c)
        else:
            t_even.append(c)

    ans = "Yes" if s_odd == t_odd and s_even == t_even else "No"

    sys.stdin = old_stdin
    return ans + "\n"

assert solve_case("cheel\nnaara\n") == "No\n", "sample 1"
assert solve_case("potha\nopath\n") == "Yes\n", "sample 2"

assert solve_case("a\na\n") == "Yes\n", "single character"
assert solve_case("ab\nba\n") == "Yes\n", "direct valid swap"
assert solve_case("abc\ncba\n") == "No\n", "same-group order cannot change"
assert solve_case("aaaaa\naaaaa\n") == "Yes\n", "all equal characters"
assert solve_case("aceg\ngeca\n") == "No\n", "large same-group reversal"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`a`に`a`| はい | 最小サイズとスワップなし |
 |`ab`に`ba`| はい | 異なるグループ間の直接交換 |
 |`abc`に`cba`| いいえ | 同一グループの順序保持 |
 |`aaaaa`に`aaaaa`| はい | すべての文字が同一 |
 |`aceg`に`geca`| いいえ | すべての文字が 1 つのグループに含まれる境界の場合 |
