 ## 解決策
 ## 問題の理解

 各科目の現在のスコアを表すマークの配列があります。 固定された順序で実行される操作がいくつかあります。 動作中`j`まで選択できます。`B_j`被験者を選択し、そのマークを値で上書きします`C_j`。 主題は何度でも選択できますが、最終的なマークに影響を与えるのは、主題を選択した最後の操作のみです。 

目標は、最終的なすべての得点の合計ができるだけ大きくなるように、すべての操作の被験者を選択することです。 

の値`N`そして`M`どちらも到達できる`100000`。 これにより、被験者の選択をシミュレートしたり、考えられる操作の割り当てをすべて試したりするアプローチが除外されます。 たとえ`O(NM)`メソッドは次のように実行されます`10^10`最悪の場合、1 秒の制限をはるかに超えた操作が行われます。 に近い解決策が必要です`O((N+M) log N)`。 

主なトラップは、操作の順序や役に立たない操作に起因します。 たとえば、操作によって高いマークが低い値で上書きされる可能性があるため、すべての操作を盲目的に適用することは正しくありません。 

次の場合を考えてみましょう。```
1 1
100
1 50
```正しい答えは、`100`。 常に操作を実行する不注意な解決策により、マークが に変わります。`50`そして価値を失います。 

別のケースは次のとおりです。```
3 2
5 1 4
2 3
1 5
```正しい答えは、`14`。 2 つの主題を次のように変更するため、最初の操作は無視する必要があります。`3`有害です。 2 番目の操作では、件名をマークで変更する必要があります。`1`に`5`。 最初から貪欲に操作を処理するソリューションでは、サブジェクトが最初の操作に費やされ、後のより適切な操作が使用されなくなる可能性があります。 

## アプローチ

 直接的なアプローチでは、操作ごとに、どのサブジェクトを置き換えるかを決定しようとします。 すべての操作で対象のさまざまなサブセットを選択できるため、可能な選択肢の数は指数関数的に増加します。 すべての操作に対して多くの候補対象をチェックする、より合理的なシミュレーションであっても、時間がかかりすぎます。 最悪の場合、すべての操作についてすべてのサブジェクトをチェックすると、すでにコストがかかります。`10^10`比較。 

この強引な方法は、被験者への演算の割り当てをすべて検討するため、正しいのですが、問題の構造により、それらの選択を明示的に行うことは回避できます。 

重要な観察は、サブジェクトに影響を与える最後の操作がその最終的な値を完全に決定するということです。 これは、操作を逆の順序で見ることができることを意味します。 操作を逆方向に処理する場合、後の操作ですでに選択されているすべての主題は固定され、再度触れることはできません。 残りの科目には元の採点がそのまま残っています。 

値を使用した逆の操作の場合`C`、現在の得点が以下の科目にのみ使用する必要があります。`C`。 この操作を使用することにした場合、同じ置換値を受け取るため、最良の被験者は最も小さいマークを持つ被験者になります。 これにより、問題は、データ構造から最小値を繰り返し取得し、より良い操作が見つかったときに値を増やすという問題に変換されます。 

最小ヒープには、まだ使用可能なサブジェクトが保存されます。 操作を逆方向に処理すると、最小のマークを貪欲に抽出し、それらを次のように置き換えることができます。`C`をクリックし、新しい値を挿入し直します。 各サブジェクトは、操作によって増加できる場合にのみ改善され、ヒープは常に可能な限り最良の候補を公開します。

 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | O(N) | 遅すぎる |

 ## アルゴリズムのチュートリアル

 1. すべての初期マークを最小ヒープに挿入し、それらの初期合計を計算します。 ヒープは、後の操作によって最終値がまだ固定されていないサブジェクトを表します。 
2. 逆の順序で操作を実行します。 手術の場合`(B, C)`、現在ヒープ内にある最小値を繰り返し確認します。 より小さい場合`C`に置き換えてください`C`、改善を加えて合計を更新し、`C`ヒープに戻ります。 

選択されたすべての被験者が同じ新しい値を受け取るため、最小値を選択することが最適です。 最大の改善は常に、現在の最小マークを置き換えることによってもたらされます。 
3. 次のいずれかの場合は、現在の操作の使用を中止します。`B`主題が改善されているか、利用可能な最小値がすでに少なくとも`C`。 

最小値が以上の場合`C`、他の使用可能な値も小さくないため、この演算を使用しても答えを増やすことはできません。 
4. すべての逆演算が処理された後、維持された合計を出力します。 

なぜ効果があるのか:

 逆方向に処理する際の操作を考慮してください。 前の操作で最終値に影響を与えることができないため、後の操作ですでに選択されているサブジェクトは固定されます。 残りの課題のうち、現状の運用で改善できるのはせいぜい`B`に値する`C`。 最適な選択は常に、`B`以下の最小値`C`より大きな値を代わりに置き換えると、増加が小さくなるからです。 ヒープにはこれらの候補が正確に保持されるため、すべての逆のステップで可能な限り最善のローカル決定が行われます。 各操作は、それをオーバーライドできるすべての操作の後に処理されるため、これらのローカルな選択がグローバルに最適な割り当てに結合されます。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))

    operations = []
    for _ in range(m):
        b, c = map(int, input().split())
        operations.append((b, c))

    heap = a[:]
    heapq.heapify(heap)

    ans = sum(a)

    for b, c in reversed(operations):
        used = 0
        while used < b and heap[0] < c:
            x = heapq.heappop(heap)
            ans += c - x
            heapq.heappush(heap, c)
            used += 1

    print(ans)

if __name__ == "__main__":
    solve()
```ヒープには、元の順序で後の操作に割り当てられていないすべてのマークが含まれています。 逆走査によってこの解釈が可能になります。 

合計は置換が発生するとすぐに更新されるため、操作のたびに配列を再構築する必要がなくなります。 Python の整数は、合計がおよそに達する可能性があるため、考えられる大きな合計を安全に処理します。`10^14`。 

ループ条件チェック`heap[0] < c`値を置き換える前に。 これにより、有害な置換が防止され、利用可能な有用なサブジェクト以上の削除も回避されます。 削除された値はすべて新しいマークとともに挿入されて戻されるため、ヒープが空になることはありません。 

## 実用的な例

 サンプル 1 の場合:```

5 1 4
2 3

```操作は最後から処理されます。 

| ステップ | 操作 | 前にヒープ | アクション | 合計 |
 | --- | --- | --- | --- | --- |
 | イニシャル | なし | [1、4、5] | 開始 | 10 |
 | 1 | (1, 5) | [1、4、5] | 1 を 5 に置き換える | 14 |
 | 2 | (2, 3) | [4、5、5] | 最小値が 3 を下回っていない場合は、何もしません。 14 |

 最初の逆の操作は、最後の操作が優先されるという事実を捉えています。 前の操作では残りの課題を改善できないため、無視するのが最適です。 

サンプル 2 の場合:```

1 8 5 7 100 4 52 33 13 5
3 10
4 30
1 4
```| ステップ | 操作 | 使用可能な最小値が変更されました | 合計 |
 | --- | --- | --- | --- |
 | イニシャル | なし | 変更なし | 228 |
 | 1 | (1, 4) | 1 が 4 になります | 231 |

 この例は、操作を元の順序で処理すべきではない理由を示しています。 後の操作では、前の操作で無駄になるサブジェクトが消費される場合があります。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((N + M) log N) | 各ヒープ操作には O(log N) のコストがかかり、有用な置換ごとに 1 つの値がヒープに挿入されます。 |
 | スペース | O(N + M) | ヒープには N 個のマークが格納され、操作リストには M 個のペアが格納されます。 |

 と`N, M <= 100000`、対数ヒープ操作は簡単に制限内に収まります。 メモリ使用量も直線的であり、利用可能なメモリを大幅に下回っています。 

## テストケース```python
import sys
import io
import heapq

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)

    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    ops = [tuple(map(int, input().split())) for _ in range(m)]

    heapq.heapify(a)
    ans = sum(a)

    for b, c in reversed(ops):
        for _ in range(b):
            if a[0] >= c:
                break
            x = heapq.heappop(a)
            ans += c - x
            heapq.heappush(a, c)

    sys.stdin = old_stdin
    return str(ans)

 ## 特殊なケース

 最初のエッジケースは、操作によってマークが減少する場合です。 のために：```
1 1
100
1 50
```ヒープは次から始まります`[100]`。 操作が処理され、最小ヒープ値が以上です`50`したがって、アルゴリズムは何もせず、答えを次のように保持します。`100`。 

2 番目のエッジ ケースは、初期の操作がその後のより適切な操作をブロックする可能性がある場合です。```
3 2
5 1 4
2 3
1 5
```アルゴリズムは最初に処理します`(1,5)`逆の順序で変更します`1`に`5`。 残りの値は次のとおりです。`4,5,5`、 それで`(2,3)`何も改善できません。 最終的な答えは、`14`、最適な選択に一致します。 

3 番目のエッジ ケースは、すべての操作に現在のマーク以下の置換値がある場合です。```
3 2
100 100 100
3 99
3 99
```ヒープの最小値は常に`100`より小さくない`99`。 どちらの操作も無視され、答えはそのまま残ります`300`。
