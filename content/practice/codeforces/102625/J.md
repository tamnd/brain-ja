 ## 解決策
 ## 問題の理解

 トークン マシンは、挿入された整数のセットを保存します。 有効なトークン番号は、直接挿入された値の 1 つではありません。 代わりに、XOR が 0 である空のサブセットを含む、格納された数値のサブセットを選択することによって取得できる任意の XOR 値です。 挿入のたびに、顧客は、可能なすべての個別の XOR 値のソート済みリスト内の特定の位置にあるトークンを要求します。 タスクは、挿入を続行しながら、これらの順序統計クエリに答えることです。 引用0検索0

 入力は最大で構成されます\(10^6\)操作。 挿入により、最大 1 つの整数が得られます。\(10^9\)、クエリは、生成されたすべての XOR 値のうち、有効な 1 インデックスの位置にある値を要求します。 操作の数が非常に多いため、クエリごとに \(O(\sqrt{q})\) を要するアプローチでも時間がかかりすぎます。 ビット操作あたりの一定時間に近い解決策が必要です。 値は 30 ビットに収まります。\(10^9 < 2^{30}\)、したがって、自然は空のサブセットです。 答えは次のとおりです。```text
0
```少なくとも 1 つの数値が保存されていると想定する不用意な解決策は、ここでは失敗します。 

もう 1 つの重要なケースは、重複挿入です。```text
3
1 5
1 5
2 2
```可能な XOR 値は次のとおりです。`0`そして`5`したがって、2 番目のトークンは次のようになります。```text
5
```独立した XOR 方向ではなく挿入された数をカウントすると、考えられるサブセット XOR が 4 つあると誤って考えることになります。 

最後の注意が必要なケースは、挿入された数値が線形に依存する場合です。```text
3
1 1
1 2
1 3
```3 番目の数字は新しい情報を追加しません。`1 XOR 2 = 3`。 生成された値は残ります`{0,1,2,3}`。 挿入するたびに値の数をやみくもに 2 倍にする方法では、オーバーカウントになります。 

## アプローチ

 直接的なアプローチでは、生成されたすべての XOR 値を保存します。 あれば\(k\)マシンには独立した番号があり、\(2^k\)異なるサブセットの XOR 結果。 すべてのサブセットを列挙し、その XOR を計算し、重複を削除し、結果を並べ替えて、インデックスによってクエリに答えることができます。 これは正しいです。考えられるすべてのトークンが 1 つのサブセット XOR から得られるからです。 問題は、\(k=60\)すでに不可能な量のデータが作成されており、独立した値の数は挿入の回数とともに増加する可能性があります。 最悪の場合の作業量は、\(O(2^k)\) 付近で指数関数的に増加しますが、これは不可能です。\(10^6\)操作。 

重要な観察は、XOR がバイナリ ベクトル空間における加算のように動作するということです。 挿入された数値によって任意の値のセットが作成されるわけではありません。 これらはビット全体に線形のスパンを作成します。 バイナリ線形基底には、このスパンの独立した方向が格納されます。 基本サイズの場合\(k\)、まさにあります\(2^k\)ユニークな XOR 結果。 

残りの課題は、\(n\)-すべての値を生成せずに、この順序付けられたスパン内で 番目に小さい値。 基底が特別な順序付けされた形式に縮小されると、すべての基底ベクトルが 1 つのバイナリ位置を独立して制御します。 答えのビットを最上位ビットから最下位ビットまで貪欲に決定できます。 各ビットで、そのビットがゼロに等しい生成値がいくつあるかがわかります。 要求された位置がそのグループ内にある場合、応答はこのビットをゼロのままにします。 それ以外の場合は、そのグループをスキップし、位置からそのサイズを減算し、ビットを 1 に設定します。 

ブルート フォースはベクトル空間を明示的に表すため機能しますが、空間が大きくなると失敗します。 空間がコンパクトな基底を持っているという観察により、同じ順序付けロジックを基底に直接実行することができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 |---|---|---|---|
 | ブルートフォース | \(O(2^k)\) | \(O(2^k)\) | 遅すぎる |
 | 最適 | \(O(30)\) クエリまたは挿入ごと | \(O(30)\) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 挿入された数値のバイナリ線形基底を維持します。 挿入されたすべての値について、既存の基底ベクトルを使用してその最も高い設定ビットを削除しようとします。 値がゼロになる場合、それはすでに前の数値で表されており、可能なトークンの数は増加しません。 それ以外の場合は、新しい独立した基底ベクトルとして保存します。 

2. 挿入が成功するたびに、ベースを縮小された形式に再構築します。 高位から低位までのすべてのビット位置について、下位のすべての基底ベクトルからそのビットを削除します。 これにより、各基底ベクトルが 1 つの固有のビットを担当することになり、特定のビットが 0 に等しい生成された値の数をカウントできるようになります。 

3. 位置に関する質問に答えるには\(n\)、ビットを上位から下位に処理します。 あると仮定します\(cnt\)下位ビットに影響を与える可能性のある基底ベクトルが残っています。 残りの可能性のうち、ちょうど半分は現在のビットが 0 に等しく、残りの半分は現在のビットが 1 に等しくなります。 ゼログループにはサイズがあります\(2^{cnt-1}\)。 

4. もし\(n\)がゼロ グループ内にある場合は、現在の応答ビットをゼロのままにします。 それ以外の場合は、ゼロ グループのサイズを減算して 1 グループに移動します。\(n\)、現在の応答ビットを 1 に設定し、続行します。 

5. もし\(n=1\)の場合、空のサブセットがソート順の最初の値であるため、アルゴリズムは当然 0 を返します。 

不変条件は、縮小基底が挿入されたすべての数値とまったく同じ XOR 空間を表しますが、すべての基底ベクトルが一意の最高ビットに寄与することです。 クエリ中に、各決定により、現在のビットに基づいて残りの XOR 値が 2 つの等しいサイズのグループに分割されます。 すべてのビットで正しい半分を選択すると、ソートされた順序に従います。そのため、すべてのビットを処理した後、構築された値は要求されたトークン番号とまったく同じになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAX_BIT = 30

basis = [0] * MAX_BIT
changed = True

def rebuild():
    for i in range(MAX_BIT - 1, -1, -1):
        if basis[i]:
            for j in range(i - 1, -1, -1):
                if (basis[i] >> j) & 1:
                    basis[i] ^= basis[j]

def insert(x):
    global changed
    for i in range(MAX_BIT - 1, -1, -1):
        if ((x >> i) & 1) == 0:
            continue
        if basis[i]:
            x ^= basis[i]
        else:
            basis[i] = x
            changed = True
            return

def kth(x):
    if changed:
        rebuild()
        changed = False

    ans = 0
    cnt = sum(1 for v in basis if v)

    for i in range(MAX_BIT - 1, -1, -1):
        if basis[i]:
            half = 1 << (cnt - 1)
            if x > half:
                x -= half
                ans |= basis[i]
            cnt -= 1

    return ans

def solve():
    global changed
    q = int(input())
    out = []

    for _ in range(q):
        p, n = map(int, input().split())
        if p == 1:
            insert(n)
        else:
            out.append(str(kth(n)))

    sys.stdout.write("\n".join(out))

solve()
```の`basis`配列には、考えられる最上位ビットごとに 1 つのベクトルが格納されます。 挿入中、バイナリ値に対するガウス消去法とまったく同じように、現在の数値が既存のベクトルによって減らされます。 すべてのビットが消失した場合、その数値は依存しており、可能なトークンのセットは変更されません。 

再構築操作は、通常の基底を縮小基底に変換します。 順序を検査する必要がなくても多くの挿入が発生する可能性があるため、このステップはクエリまで延期されます。 の`changed`フラグは不必要な繰り返しの削減を防ぎます。 

クエリ関数は、上位ビットから下位ビットまで縮小基底をたどります。 変数`cnt`現在のゼロ グループのサイズを決定するために、独立したベクトルがいくつ残っているかを追跡します。 Python の整数は、ここで使用されている 2 の累乗をオーバーフローせずに処理しますが、必要な最大値は 2 です。\(2^{30}\)。 

インデックスは 1 から始まります。 最初に生成されたトークンはゼロであるため、半減ロジックで指定された位置を直接使用する以外に特別な処理は必要ありません。 リダクションとクエリ順序は、リダクションされていない基底でクエリを実行すると並べ替え順序が維持されないため、最も間違いが発生する可能性が高い部分です。

 ## 特殊なケース

 空のマシンケースの場合:```text
1
2 1
```基底はゼロだらけのままです。 クエリには分割するベクトルがないため、可能な値は空のサブセット XOR (ゼロ) だけです。 クエリ ループには選択するビットがないため、アルゴリズムは 0 を返します。 

重複した値の場合:```text
3
1 5
1 5
2 2
```最初の挿入では、次のビット表現の基底ベクトルが作成されます。`5`。 同じベクトルがすでに存在するため、2 番目の挿入は完全にゼロになります。 クエリは 1 つの独立ベクトルのみを参照し、順序付けされた値を生成します。`0, 5`。 

依存値の場合:```text
3
1 1
1 2
1 3
```3 番目の挿入は既存の根拠によって削除されます。`3`はすでに次の XOR として表されています`1`そして`2`。 基底ランクは 2 のままであるため、生成されたシーケンスは依然として`0, 1, 2, 3`。 

大きな値の場合:```text
5
1 1000000000
2 1
2 2
2 1
2 2
```使用されている最高位ビットが 30 ビット制限に近づいています。 このアルゴリズムは依然として固定ビット位置のみをチェックするため、特別なケースは必要ありません。 縮小基底では、最上位ビットであってもゼロと非ゼロの選択肢が正しく分離されます。
