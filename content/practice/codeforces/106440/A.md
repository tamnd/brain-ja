 ## 問題の理解

 2 つの頂点グループが与えられます。 最初のグループには以下が含まれます$a$黒いノードと 2 番目のノードには次のものが含まれます$b$白いノード。 これらを使用して、無向の単純なグラフを構築する必要があります。$a+b$頂点。 

グラフは 2 つの条件を同時に満たさなければなりません。 まず、接続する必要があります。これは、すべての頂点が何らかのパスを介して他のすべての頂点に到達できることを意味します。 第 2 に、すべての頂点には、白の近傍と同じ数の黒の近傍がなければなりません。 つまり、どのノードでも$u$、すべての隣接するノードを見ると、それらのノードの中の黒いノードの数は白いノードの数と等しくなければなりません。 

自己ループや同じペア間に複数のエッジを作成しない限り、エッジを自由に追加できます。 すべての有効な構成のうち、エッジの数を最小限に抑えたいので、その最小値を達成する有効な構成を出力する必要があります。 構築が存在しない場合は、出力します$-1$。 

制約が意味するのは、$T$と同じ大きさにすることができます$10^4$、すべてのテスト ケースにわたるノードの合計数は最大で$10^6$。 これにより、テスト ケースごとに解が線形になるように強制されます。$a+b$すべてのテストを合計すると、すぐに制限を超える可能性があります。 

いくつかの特殊なケースは見落とされがちです。 

いつ$a=1, b=0$、頂点は 1 つであり、エッジは必要ありません。 グラフは自明に接続されており、次数条件は空虚に成立します。 

いつ$a=1, b=1$、黒の頂点が 1 つと白の頂点が 1 つあります。 それらを接続すると、各頂点には反対色の隣接頂点が 1 つあるため、条件が満たされ、答えは 1 つのエッジになります。 

より微妙なケースは、1 つの色が単独で存在するが、その数が複数である場合です。たとえば、$a=3, b=0$。 どのエッジも 2 つの黒い頂点を接続することになり、各エンドポイントには黒の隣接点のみが表示され、黒と白の隣接点の平等に違反します。 したがって、たとえグラフが構造的に接続できたとしても、解決策は存在しません。 

もう 1 つの微妙な失敗は、接続性だけが実現可能性を決定すると考えていることです。 例えば、$a=2, b=1$局所的にバランスを取ろうとすると、白い頂点には 2 つの黒い隣接点が存在する一方、各黒い頂点には 1 つの白い隣接点しか存在しないため、機能しません。 

主な問題点は、すべての頂点が 2 つのカラー クラス間の厳密なローカル平等制約を強制する一方で、グローバルな接続性も必要とすることです。 

## アプローチ

 単純なアプローチでは、すべての頂点で制約を直接適用してグラフを構築しようとします。 各頂点を貪欲に接続して、エッジを追加するたびに、両方のエンドポイントが同じ黒と白の近傍数を維持しているかどうかを確認することを試みることもできます。 すべてのエッジが 2 つの制約に同時に影響し、貪欲なローカル決定によって後で行き詰まりを強いられる可能性があるため、これはすぐに複雑になります。 たとえ後戻りしたとしても、可能なグラフの状態空間は頂点の数が指数関数的であるため、このアプローチは非常に小さい入力を超えると実行不可能になります。 

別の素朴な考えは、この状態を一種の二者バランス要件として解釈しようとすることです。 各頂点が 2 つのセットからの同数の近傍を必要とすることを考えると、最初に制約をペアにするか、次数の割り当てをシミュレートしてからエッジを構築しようとするかもしれません。 しかし、任意の次数の割り当てがグラフィカルであることは保証されておらず、実現可能性を検証するには、テスト ケースごとのフローやマッチングのようなものが必要になりますが、これでは遅すぎます。 

重要な観察は、この条件が非常に対称的であるということです。つまり、すべての頂点が黒と白の隣接する頂点を同じ数で扱います。 これは、エッジが局所的に調整されるのではなく、全体的にバランスのとれた構造に配置される必要があることを示唆しています。 

条件を再解釈する便利な方法は、色ごとにエッジの寄与を調べることです。 黒と白の頂点間の各エッジは、白の端点に 1 つの黒の近傍を与え、黒の端点に 1 つの白の近傍を与えます。 同じ色の内側のエッジは、その色の同じタイプの近傍数にのみ寄与するため、慎重にペアにしない限り、直ちに等価性が破られます。 これは、同じ色のエッジが役に立たないか有害であることを強く示唆しており、有効な構築ではエッジを回避する必要があります。 

黒と白の頂点の間の 2 部グラフに注目を限定すると、各黒頂点には白の近傍のみがあり、各白の頂点には黒の近傍のみが存在します。 その場合、条件は次のようになります。黒の近傍数はゼロであり、黒の頂点については白の近傍数もゼロであるため、すべての頂点について近傍の数はゼロでなければなりません。同様に白の頂点についても同様です。 これにより、強制的に空のグラフが作成され、頂点が 1 つしかない場合は接続できなくなります。 これは、以前の単純化が強引すぎるため、より構造化された混合構造が必要であることを示しています。 

正しい視点は、循環構造によって対称性を強制することです。この構造では、すべての頂点が交互の隣接関係を通じて各カラー タイプの 1 つの近傍を正確に認識します。 一貫して色を切り替えることができる最小限の接続された構造は、本質的にはサイクルまたはサイクルの結合ですが、接続性により単一のサイクルのような構造が強制されます。 

これは、グラフがシーケンス内で黒と白の頂点を交互に配置し、カウントを考慮したサイクルを形成する必要があるという考えにつながります。 ただし、純粋な交互サイクルには、同数の黒と白の頂点が必要です。 いつ$a \neq b$、各頂点がちょうど 1 つの黒と 1 つの白の近傍に接続されるように頂点をグループ化することで調整する必要があります。これは次数が少なくとも 2 であることを意味し、2 つの規則的な二部構造を強制します。 

最終的な洞察は、各頂点が色間で均等に分割された偶数の次数を持たなければならないため、単一ノードの自明なケースでない限り、すべての頂点の次数が少なくとも 2 でなければならないということです。 これにより、すべての頂点にわたって単一のサイクルを構築する方向に進みます。 サイクルでは、各頂点に正確に 2 つの隣接頂点が自動的に与えられ、サイクルの周囲で色が制御されたパターンで交互に配置されるようにすれば、等式制約を満たすことができます。 実現可能性は、すべての頂点が各色の近傍を 1 つ持つように頂点を配置することになります。これには、些細な場合を除き、両方の色が少なくとも 2 回出現する必要があります。 

これは建設的な解決策をもたらします。$a$そして$b$が少なくとも 1 の場合、各頂点の 2 つの近傍に 1 つの黒と 1 つの白が正確に含まれるように頂点を順序付けすることにより、単一サイクルの構築を試みることができます。 これは、一方の色が 1 で、もう一方の色が 1 より大きい場合を除き、可能です。その場合、少数派または多数派の固有の頂点で避けられない不均衡が生じます。 

この構造は最終的に、色の遷移を考慮しながらサイクル内で頂点をペアにする決定的な配線パターンになります。

 ## アルゴリズムのチュートリアル

 1. 些細なケースを最初に処理します。 もし$a+b=1$、単一の頂点がすでに接続されているため、0 エッジを出力します。 
2.次のいずれかの場合$a$または$b$が 0 で、合計が 1 より大きい場合は、-1 が出力されます。 両方の色がないと、エッジが存在すると、どの頂点も黒と白の隣接カウントを等しく満たすことができなくなります。 
3. どちらかの場合$a=1$または$b=1$もう一方が 1 より大きい場合は、-1 を出力します。 1 つの色の単一の頂点は、不均衡を生じずに、接続された構造内で隣接する頂点のバランスを同時に取ることはできません。 
4. それ以外の場合は、すべての頂点にわたって単一のサイクルを構築します。 最初に黒い頂点、次に白い頂点をリストし、交互に隣接するようにそれらをインターリーブします。 
5. 1 つの色がなくなるまで 1 つの黒と 1 つの白を繰り返し取得して頂点の順序を作成し、残りの頂点を追加します。 この順序により、可能な限り、サイクル内の隣接する頂点の色が常に交互になります。 
6. 頂点を接続する$i$に$i+1$、最後の頂点を最初の頂点に接続し直します。 これは正確に生成します$n$エッジどこ$n=a+b$。 
7. 構築されたエッジを出力します。 

### なぜ効果があるのか

 構築されたグラフは単一サイクルであるため、定義上接続されています。 すべての頂点の次数は正確に 2 であり、構築により、各頂点の 2 つの近傍が、一方が黒の近傍に寄与し、もう一方が白の近傍に寄与するように選択されます。 この順序により、局所的な位置で不均衡が発生する可能性がある場合は常に、サイクル内の他の場所で対称的に配置することによって不均衡が補償されることが保証されます。 各頂点は正確に 2 つのエッジに関与しており、サイクルでは指定された数に応じてできるだけ均等に色が交互に表示されるため、隣接する黒と白の数が等しくない頂点は存在しません。 このような順序付けが不可能な唯一のケースは、まさに、隣接関係の競合を強制せずに 1 つの色をサイクル全体に分散できないという縮退ケースであり、アルゴリズムでは除外されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    out = []

    for _ in range(T):
        a, b = map(int, input().split())

        n = a + b

        if n == 1:
            out.append("0")
            continue

        if a == 0 or b == 0:
            out.append("-1")
            continue

        if a == 1 and b > 1:
            out.append("-1")
            continue
        if b == 1 and a > 1:
            out.append("-1")
            continue

        blacks = list(range(1, a + 1))
        whites = list(range(a + 1, a + b + 1))

        order = []
        i = j = 0

        while i < len(blacks) and j < len(whites):
            order.append(blacks[i])
            order.append(whites[j])
            i += 1
            j += 1

        while i < len(blacks):
            order.append(blacks[i])
            i += 1

        while j < len(whites):
            order.append(whites[j])
            j += 1

        edges = []
        for i in range(n):
            u = order[i]
            v = order[(i + 1) % n]
            edges.append((u, v))

        out.append(str(len(edges)))
        for u, v in edges:
            out.append(f"{u} {v}")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```コードは各テスト ケースを独立して処理し、最初に解決策が不可能な縮退構成を除外します。 次に、黒と白の頂点をできるだけ均等にインターリーブしようとする頂点順序を構築します。 サイクル構築ステップは、追加のチェックを必要とせずに接続を保証するため、重要な構造上の選択です。 

最後のループは、順序内の連続する頂点を単純に接続し、最後にラップアラウンドします。 これは正確に保証します$n$単一頂点の場合を除き、テスト ケースごとのエッジ。これは個別に処理されます。

 ## 特殊なケース

 単一ノードの場合$a+b=1$エッジは生成されませんが、単一の頂点上の接続性は事実上真であるため、すべての要件を満たします。 

1 つの色のみと 2 つ以上の頂点を持つケースは、ただちに失敗します。これは、エッジが 1 つの色の近傍のみを導入することにより、端点で等価条件を破ることになるためです。 アルゴリズムは構築を試行する前に -1 を正しく返します。 

いつ$a=1, b>1$または$b=1, a>1$、接続されたグラフでは、一意の頂点が他の色の複数の頂点に強制的に隣接するため、その頂点での黒と白の近傍数のバランスを取ることが不可能になります。 早期の拒否により、無効なサイクルの構築が防止されます。 

残りのすべてのケースでは、両方の色に少なくとも 2 つの頂点があり、サイクル順序で隣接関係を均等に分散できるため、色の不均衡を強いることなくすべての頂点が対称の 2 つの隣接構造に参加します。
