 ## 解決策

 ## 問題の理解

 2 つの正の整数のシーケンスが与えられます。 連続したブロックを、そのブロックの合計に等しい単一の数値に繰り返し圧縮することができます。 これらの圧縮を両方の配列で個別に実行した後、結果として得られる配列が同一になるようにする必要があり、そのようなすべての可能性の中で、最終的に等しい配列の可能な最大長が必要になります。 それらを等しくする方法が存在しない場合は、不可能であると報告します。 

重要な解釈は、両方の配列をセグメントに分割し、各セグメントがその合計に等しい 1 つの値になるということです。 目標は、セグメント数を最大化しながら、対応するセグメントの合計が一致するように、両方の配列の共通のセグメント化を見つけることです。 

この制約により、最大 300,000 要素の配列が許可されます。 すべてのパーティションを試したり、指数関数的な分割を使用したりするソリューションは、直ちに不可能になります。 すべてのサブセグメントにわたる二次マージ戦略であっても、各要素が多くの潜在的なマージに参加するため、最悪の場合には遅すぎる可能性があります。 

いくつかのエッジ動作が重要です。 

一方の配列に 1 つの要素があり、もう一方の配列に複数の要素があり、その総和は一致するが、一致する部分和に分割できない場合、全体的な合計が一致しても、答えは得られません。 たとえば、A = [5]、B = [2, 3] は有効で長さ 1 が得られますが、A = [5]、B = [1, 4] も有効ですが、A = [5]、B = [2, 2, 1] は不可能です。これは、セグメンテーションが両側で整列した一致する連続合計を生成しないためです。 

もう 1 つの微妙なケースは、貪欲なマージが局所的には有益であるように見えても、将来の調整を損なう場合です。 たとえば、一方の配列が同じ合計に達する前に、一方の配列が累積しすぎた場合、合計の合計がまだ一致していても、後で位置合わせは不可能になります。 

## アプローチ

 強引なアイデアは、両方の配列を連続セグメントに分割するあらゆる方法を試し、セグメントの合計がペアごとに一致するかどうかを確認することです。 長さ n の配列を分割する方法の数は指数関数的であるため、n が約 30 の場合でもこれは実行不可能です。 

より構造化されたビューは、両方の配列を同時に実行し、貪欲にセグメントを形成することを想像することです。 すべての値が正であるため、セグメントを拡張すると部分和は厳密に増加します。 この単調性により、2 ポインタ シミュレーションが可能になります。A と B で現在のセグメントの合計を構築し、一方の辺が小さくなるたびに、それを進めます。 それらが等しい場合、セグメントをコミットしてリセットします。 

重要な観察は、以前の決定を再考する必要はまったくないということです。 値が正であるため、プレフィックスの合計が一致すると、そのセグメントは、両側の同期を維持する有効な最適なパーティションに強制的に挿入されます。 マージを遅らせようとした場合、セグメントの数は増やすのではなく減らすだけになります。これは、マージを早くすると境界がより整列するためです。 

これにより、両方の配列を 1 回スキャンしてセグメントの合計を貪欲に調整するという問題が軽減されます。

 ## アルゴリズムのチュートリアル

 2 つの累計 (各配列に 1 つずつ) と 2 つのポインターを維持します。 各ステップでは、両方の合計が一致するまで合計が小さい方の辺を拡張し、セグメントを記録します。

1. ポインタ i と j を 0 に初期化し、実行合計 sa と sb を 0 に初期化します。 
2. どちらの配列も使い果たされていない間、sa <= sb の場合は A[i] を sa に追加し、そうでない場合は B[j] を sb に追加します。 これにより、2 つの部分和を等しくすることが常に試みられます。 
3. sa が sb に等しい場合、一致するセグメントが 1 つ見つかります。 答えをインクリメントし、両方の合計を 0 にリセットします。 
4. 一方のポインタが最後まで到達しても、もう一方のポインタにまだ合計が残っている場合は、残りの側も完全に消費されていることを確認する必要があります。 そうしないとマッチングが不可能になります。 
5. ループの後、両方の合計がゼロで、両方のポインタが最後にある場合は、一致したセグメントの数を返します。 それ以外の場合は -1 を返します。 

常に小さい方の合計を拡張する理由は、有効な調整は最終的に合計を等しくする必要があり、小さい方の拡張を遅らせることは、セグメントの数を改善せずに等しさを先送りするだけであるためです。 

### なぜ効果があるのか

 すべてのステップで、アルゴリズムは、A および B 上の現在の部分セグメントが、仮想の有効なパーティションの次の不一致部分を表すことを維持します。 すべての数値が正であるため、セグメントの合計は単調増加するため、小さい方の辺を拡張することによってのみ等しさに到達できます。 等しい値に達すると、セグメント数を最大化するパーティションにその境界が強制されます。これは、両側がすでに一致しているポイントを越えてマージすると、後で新しい位置合わせを有効にすることなく、セグメントの数が厳密に削減されるためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    m = int(input())
    b = list(map(int, input().split()))
    
    i = j = 0
    sa = sb = 0
    ans = 0
    
    while i < n or j < m:
        if sa == sb:
            if sa != 0:
                ans += 1
                sa = sb = 0
        
        if sa <= sb:
            if i < n:
                sa += a[i]
                i += 1
            else:
                sa = float('inf')
        else:
            if j < m:
                sb += b[j]
                j += 1
            else:
                sb = float('inf')
    
    if sa == sb:
        if sa != 0:
            ans += 1
    else:
        print(-1)
        return
    
    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、2 つのポインターが各配列を 1 回だけスキャンし続けます。 コアの決定は、現在の累積合計を比較することによって制御されます。 一方の辺が小さいか等しい場合、その辺は拡張されます。 これにより、双方が後戻りすることなく同期して前進することが保証されます。 

1 つの配列が枯渇したときに無限のようなセンチネル値を使用すると、無限ループが防止され、不一致の検出が強制されます。 最終チェックでは、部分的に不一致の合計が残っていないことを確認します。

 ## 特殊なケース

 重要なエッジ ケースは、1 つの配列が早く枯渇しても部分和がゼロではない場合です。 この状況では、バランスをとるための要素が他に存在しないため、アルゴリズムによって不一致が強制されます。 たとえば、A = [1, 2]、B = [1, 1, 1]。 このプロセスでは最初の 1 が整列され、次に A が 2 を蓄積し、B が 1、1 を蓄積し、その後の一致のみが行われますが、順序が異なる場合、枯渇により最終的な等価性が妨げられます。 

もう 1 つのエッジ ケースは、両方の配列の最後で正確に一致する場合に発生します。 最終チェックでは、ループ終了後にそれ以上の反復が行われない場合でも、最後のセグメントがカウントされることが保証されます。
