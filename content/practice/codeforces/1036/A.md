 ## 解決策
 ## 問題の理解

 この図は、0 から 2n までの整数の x 座標の点から作られた破線です。 最初はすべての点が x 軸上にあるため、すべての y 座標はゼロになります。 シェイプを変更する唯一の方法は、奇数のインデックスのポイントを選択し、移動ごとにその高さを 1 単位ずつ増やすことです。 偶数インデックスのポイントは変更されません。 

高さが割り当てられると、連続する点が直線セグメントで接続され、多角形チェーンが形成されます。 「プロットの面積」は、このチェーンと x 軸の間の幾何学的面積です。 「プロットの高さ」は、単にすべての点の最大の y 値です。 

タスクは、最大高さをできるだけ小さくしながら、囲まれた領域の合計が正確に k になるように、奇数のインデックスが付いた各点を何回増やすかを選択することです。 

この制約では、n と k の両方を最大 10^18 まで許可します。 これにより、増分をシミュレートしたり構造を明示的に構築しようとするアプローチは即座に除外されます。 どのような解決策でも、問題を閉じた形式の式に圧縮するか、最悪の場合でも対数または定数時間の計算に圧縮する必要があります。 

ジオメトリを正しく解釈すると、微妙なエッジ ケースが発生します。 素朴な読者は、面積が各セグメントの形状に複雑に依存している、または隣接する奇妙な点間の相互作用が重要であると考えるかもしれません。 たとえば、隣接する奇数点を増やすと、共有セグメントの寄与が自明ではない形で変化するのではないかと疑う人もいるかもしれません。 それが本当であれば、たとえ小さな入力であっても、慎重な幾何学的累積が必要となるでしょう。 ただし、この直感は過度の複雑さと不正確な動的定式化につながります。 

もう 1 つの潜在的な落とし穴は、高さの変化を不均一に分散すると、均一に分散するよりも効率的に最大高さを下げることができると仮定することです。 これは、あるポイントを完全に埋めてから次のポイントに移動するなど、誤った貪欲な戦略につながることが多く、局所的には最適に見えても全体的には失敗します。 

## アプローチ

 この強引なアイデアは、奇数のインデックスが付けられた各点を変数として扱い、それらの間で単位の増分を分配するシミュレーションを行うことです。 増分ごとにジオメトリが更新され、割り当てのたびに総面積が再計算されます。 これには、n 個の位置にわたる k 増分のすべての分布を調査する必要があります。 状態の数は組み合わせによるもので、本質的には k を n 個の部分に分けた弱い合成の数であり、次のように増加します。$\binom{k+n-1}{n-1}$。 中程度の値であっても、これは完全に実行不可能です。 

重要な単純化は、エリアがどのように形成されるかを観察することから生まれます。 各セグメントは、高さ 0 の点を奇数の点に、またはその逆に接続します。 偶数のインデックスが付いた点は常に 0 に留まるため、奇数のインデックスが付いた点によって作成されるすべての「バンプ」は、隣接する各セグメント上に 1 つずつ、2 つの同一の三角形の寄与を形成します。 これら 2 つの半分は、その奇数点の高さにのみ比例する単一の線形寄与に結合されます。 これにより、ポジション間のすべての相互作用が削除されます。 

面積が独立した寄与の純粋な合計であることがわかると、問題は純粋に組み合わせの問題になります。k 個の同一ユニットを n 個の独立したバケットに分散し、最大バケット値を最小化したいと考えます。 これは、可能な限り均等化することで最適化が達成される、古典的な負荷分散構造です。 

最大高さを H に維持しようとすると、n 個の奇数位置のそれぞれが総面積に寄与できるのは最大でも H となるため、達成可能な最大面積は n・H になります。 これにより、H の実現可能条件が直ちに得られます。

 ## アルゴリズムのチュートリアル

 1. 奇数のインデックスが付いた各点を独立変数として解釈します$a_i$、何倍に増加するかを表します。 これにより、幾何学的問題が n 個の変数にわたる割り当て問題に変換されます。 
2. それぞれの方法を計算します。$a_i$地域に貢献します。 奇数点で単位が増加するたびに、隣接するセグメントにわたって 2 つの対称な半三角形が形成されるため、合計でちょうど 1 単位だけ面積が増加します。 これにより、総面積が次と等しいことが確立されます。$\sum a_i$。 
3. k 個の同一の単位を n 個の変数に分配するという問題として再定式化する$a_1, a_2, \dots, a_n$、目的は最小化することです$\max a_i$。 
4. 最大高さ H が固定されている場合、すべての変数が H に等しいときに可能な最大の合計が発生し、合計 n・H が得られることを観察します。 これは、実現可能性が必要であることを意味します$n \cdot H \ge k$。 
5. これより小さな値は k に対応できず、より大きな値は不要であるため、この不等式を満たす最小の整数 H を選択します。 
6. 次のように結論付けます$H = \lceil k / n \rceil$。 

### なぜ効果があるのか

 重要な不変条件は、面積が奇数指数の高さのマルチセットにのみ依存し、正確にそれらの合計になるということです。 変数間に結合がないため、合計を保存する再分配によって面積は変化しません。 したがって、固定合計の下で最大値を最小限に抑えることは、分布のバランスを可能な限り均等にすることになります。 均一性からの逸脱は、同じ総和限界を超えて容量を増加させることなく、最大値を増加させるだけです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())
print((k + n - 1) // n)
```実装全体は、天井分割の計算に帰着します。 重要な簡素化は、ジオメトリが付加的なモデルに折りたたまれるため、シミュレーションや構造構築が必要ないことです。 唯一注意すべき点は、整数上限除算が正しく実装されていることを確認することです。 を使用して`(k + n - 1) // n`浮動小数点の問題を回避し、最大 10^18 の大きな値を安全に処理します。 

## 実用的な例

 ### 例 1

 入力:```
4 3
```n = 4 個の奇数の位置が独立して寄与しています。 3 つの単位を 4 つの変数に分配します。 

| ステップ | 配布状況 | 電流最大値 | 合計額 |

 すべてのユニットは位置ごとに 1 を超えずに配置できるため、必要な最大高さは 1 です。 これは、数式 ceil(3/4) = 1 と一致します。

 入力:```

```ここでは、12 ユニットを 4 つのポジションに分散します。 

| ステップ | 配布状況 | 電流最大値 | 合計額 |

 | 1 | [3,3,3,3] | 3 | 12 |

 ここでは、分布は完全にバランスがとれているため、最大高さは 3 です。これは ceil(12/4) = 3 と一致し、すべての変数が同じレベルに達する必要があるという厳しいケースを示しています。

## テストケース```python
import sys, io

def solve():
    import sys
    input = sys.stdin.readline
    n, k = map(int, input().split())
    print((k + n - 1) // n)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    old_stdout = sys.stdout
    sys.stdout = io.StringIO()
    solve()
    out = sys.stdout.getvalue()
    sys.stdin = old_stdin
    sys.stdout = old_stdout
    return out.strip()

# provided sample
assert run("4 3\n") == "1"

# minimum case
assert run("1 1\n") == "1"

# evenly divisible
assert run("5 10\n") == "2"

# large skew case
assert run("3 1000000000000000000\n") == str((10**18 + 2)//3)

# k smaller than n
assert run("10 3\n") == "1"
```| テスト入力 | 期待される出力 | 検証内容 |

 | 5 10 | 2 | 均等分布 |
 | 3 10^18 | 天井分割の正確さ | 大きな境界値 |
 | 10 3 | 1 | k < n の動作 |

 ## 特殊なケース

 よくある誤解は、k が n より小さい場合です。 たとえば、入力の場合`n = 10, k = 3`、最適な戦略は、各ユニットを異なる位置に配置し、次のような高さを生み出すことです。`[1,1,1,0,...]`したがって、最大の高さは 1 です。数式は正しく返します。`ceil(3/10) = 1`、この直感と一致します。 

もう 1 つのエッジ ケースは、k が n で正確に割り切れる場合です。`n = 5, k = 10`。 最適な構成は完全に均一であり、すべての奇数点が 2 に設定されます。アルゴリズムは正確に 2 を返し、不均等な分布は合計の制約に違反することなく最大値をさらに減らすことができません。 

最後に、k が 10^18 などの非常に大きい場合でも、この解決策は分布の構築を回避し、整数演算のみに依存するため、オーバーフローやパフォーマンスの問題が発生しないことが保証されます。
