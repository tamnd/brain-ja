 ## 解決策
 ## 問題の理解

 整数グリッド上に描かれた直線セグメントのコレクションが与えられます。 各セグメントは 2 つの格子点を接続しますが、セグメント自体は、その傾きに応じて他の多くの格子点を通過する可能性があります。 セグメントは、必ずしもグリッド点でなくても、任意の点で互いに交差する場合があります。 

タスクは、これらのセグメントの少なくとも 1 つに存在する別個の整数座標点の数を数えることです。 点が整数の座標を持ち、端点や内部点を含む少なくとも 1 つのセグメント上のどこかにある場合、その点は有効であるとみなされます。 

制約が非常に厳しいため、平面上の単純な幾何学的スイープは不可能です。 座標は絶対値で 100 万にも達するため、バウンディング ボックス内の格子点の数は列挙するには多すぎます。 セグメントの数は最大でも 1,000 であり、これはすぐに次のことを示唆しています。$O(n^2)$インタラクションベースのアプローチは、約 100 万のペアごとの操作につながるため、許容されます。 

オーバーラップについて考えると、微妙な問題が生じます。 ラティス ポイントは、特に交点において、複数のセグメント上に存在することがあります。 単純にセグメントごとに格子点を個別にカウントすると、すべての交点が複数回カウントされるため、修正する必要があります。 

2 番目の微妙な点は、セグメント間の交差が整数座標で発生することが保証されていないことです。 2 つのセグメントは次のような有理点で交差することがあります。$(1.5, 2.25)$、問題は整数格子点のみを考慮しているため、これはまったく数えてはなりません。 

3 番目の特殊なケースは、多くのセグメントが同じ整数の交点を通過する場合です。 2 つのセグメントが同一直線上にあるわけではありませんが、複数のセグメントが 1 つのグリッド点で交差する可能性があるため、補正ではペアごとに互いに素な交差を仮定するのではなく、多重度を処理する必要があります。 

## アプローチ

 最も直接的なアプローチは、各セグメントを個別に扱うことです。 からのセグメントの場合$A$に$B$、その上の整数点のセットは、古典的な格子セグメント公式を使用して記述することができます。セグメント上の格子点の数は次のとおりです。$\gcd(|dx|, |dy|) + 1$、 どこ$dx = B_x - A_x$そして$dy = B_y - A_y$。 これが機能するのは、セグメントに沿った連続する格子点間の段差が、座標の差の最大公約数によって減少するためです。 

この値をすべてのセグメントにわたって合計すると、セグメント格子点の合計発生数が得られます。 セグメントがどの格子点でも重なり合わなければ、これは正しいです。 問題は、交点が複数のセグメントに属しているため、複数回カウントされることです。 

これを修正するには、共有格子点によって引き起こされる過剰カウントを減算する必要があります。 重要な点は、点が複数のセグメントに属する唯一の方法は、それが 2 つのセグメントの交点である場合であるということです。 同一線上にある 2 つのセグメントはないため、セグメントのペアは最大 1 回交差します。 したがって、セグメントのすべてのペアを列挙し、それらの交点を計算し、その交点が格子点である場合は、それを記録することができます。 

各格子の交点を通過するセグメントの数がわかれば、合計を修正できます。 に点が現れた場合$k$セグメントごとにカウントされます$k$単純合計では 回ですが、1 回としてカウントされる必要があるため、減算します。$k - 1$そのような点ごとに。 

これにより、問題は正確な算術演算によるセグメント ペアのジオメトリに帰着します。これは実現可能です。$n \le 1000$。

 ## アルゴリズムのチュートリアル

 個々のセグメントによってもたらされる合計格子点と、重複した交点の補正項の 2 つのコンポーネントを計算します。 

1. 各セグメントについて、次の式を使用してその格子点数を計算します。$\gcd(|dx|, |dy|) + 1$。 これらの値を累計して累計します。 この合計は各セグメントを独立して扱い、重複を無視します。 
2. セグメントのペアごとに、それらが幾何学的セグメントとして交差するかどうかを計算します。 これには、精度の問題を避けるために、浮動小数点演算ではなく行列式を使用して線の交差を解決する必要があります。 
3. 2 つのセグメントが内部または端点で交差しない場合は、それらを直ちにスキップします。 
4. それらが交差する場合は、外積を使用して正確な交点を計算します。 座標は、整数値の行列式から導出される有理数になります。 
5. 交点の座標が整数であるかどうかを確認します。 これには、両方の分子の値が行列の分母で割り切れることを検証する必要があります。 
6. 交差部分が格子点の場合、同じ格子点を共有するセグメントのペアの数を数えるハッシュ マップに交差部分を記録します。 
7. すべてのペアを処理した後、答えを調整します。 に現れる各格子の交点$k$セグメントが貢献する$k$セグメントの合計にはカウントされますが、寄与するのは 1 つだけであるため、減算します。$k - 1$記録された各ポイントごとに。 

### なぜ効果があるのか

 セグメント上のすべての格子点は、最初の gcd ベースの合計でセグメントごとに 1 回だけ計算されます。 過大数をカウントする唯一の理由は、異なるセグメントが同じ格子点を共有することができ、そのような共有点はそれらのセグメントの交点でなければならないことです。 セグメントは同一線上にないため、各ペアは最大 1 つの幾何学的交差に寄与するため、すべての共有格子点はペアごとの交差列挙によって完全にキャプチャされます。 多重度による修正により、最終結果では各格子点が正確に 1 回カウントされるようになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from math import gcd

def orient(ax, ay, bx, by, cx, cy):
    return (bx - ax) * (cy - ay) - (by - ay) * (cx - ax)

def in_seg(ax, ay, bx, by, cx, cy):
    return min(ax, bx) <= cx <= max(ax, bx) and min(ay, by) <= cy <= max(ay, by)

def intersect(a, b, c, d):
    ax, ay = a
    bx, by = b
    cx, cy = c
    dx, dy = d

    o1 = orient(ax, ay, bx, by, cx, cy)
    o2 = orient(ax, ay, bx, by, dx, dy)
    o3 = orient(cx, cy, dx, dy, ax, ay)
    o4 = orient(cx, cy, dx, dy, bx, by)

    if o1 == 0 and in_seg(ax, ay, bx, by, cx, cy):  # collinear endpoint cases
        return (cx, cy)
    if o2 == 0 and in_seg(ax, ay, bx, by, dx, dy):
        return (dx, dy)
    if o3 == 0 and in_seg(cx, cy, dx, dy, ax, ay):
        return (ax, ay)
    if o4 == 0 and in_seg(cx, cy, dx, dy, bx, by):
        return (bx, by)

    if o1 * o2 < 0 and o3 * o4 < 0:
        # proper intersection, compute exact point
        A = (bx - ax, by - ay)
        B = (dx - cx, dy - cy)
        C = (cx - ax, cy - ay)

        det = A[0] * B[1] - A[1] * B[0]
        if det == 0:
            return None

        t_num = C[0] * B[1] - C[1] * B[0]
        u_num = C[0] * A[1] - C[1] * A[0]

        if det < 0:
            det = -det
            t_num = -t_num

        if t_num % det != 0:
            return None
        if u_num % det != 0:
            return None

        t = t_num // det
        x = ax + A[0] * t
        y = ay + A[1] * t

        if in_seg(ax, ay, bx, by, x, y) and in_seg(cx, cy, dx, dy, x, y):
            return (x, y)

    return None

def solve():
    n = int(input())
    seg = []
    for _ in range(n):
        x1, y1, x2, y2 = map(int, input().split())
        seg.append(((x1, y1), (x2, y2)))

    total = 0
    for (x1, y1), (x2, y2) in seg:
        total += gcd(abs(x1 - x2), abs(y1 - y2)) + 1

    cnt = {}

    for i in range(n):
        for j in range(i + 1, n):
            p = intersect(seg[i][0], seg[i][1], seg[j][0], seg[j][1])
            if p is not None:
                cnt[p] = cnt.get(p, 0) + 1

    for v in cnt.values():
        total -= (v - 1)

    print(total)

if __name__ == "__main__":
    solve()
```コードはまず gcd 式を使用してセグメントごとの格子点を集計します。これにより、個々のセグメント上のすべての点が正しくカウントされます。 次に、浮動小数点エラーを回避するために方向テストを使用して、セグメントのすべてのペアの交差をチェックします。 交差が見つかると、正確な有理交差が計算され、可分性チェックを使用して完全性が検証されます。 最後に、格子の交点ごとの重複を減らすことで過剰カウントを修正します。 

よくある微妙な点は、同一線上にある端点の交差を個別に処理することです。これは、それらの交差が行列式ベースの交差公式をバイパスするためです。 もう 1 つの重要な詳細は、浮動小数点座標が格子条件チェックを静かに破ってしまうため、全体を通して整数演算を維持することです。 

## 実用的な例

 ### 例 1

 格子点で交差する 2 つの交差セグメントを持つ小さな構成を考えます。 

| ステップ | アクション | 合計 | 交差点マップ |
 | --- | --- | --- | --- |
 | 1 | セグメント 1 に格子点を追加します。 5 | {} |
 | 2 | セグメント 2 に格子点を追加 | 5 | {} |
 | 3 | (2,2) で交差点を検出 | 10 | {(2,2): 1} |
 | 4 | 修正を適用する | 9 | {(2,2): 1} |

 初期合計では、共有交差が 2 回 (セグメントごとに 1 回) カウントされます。 修正により重複が 1 つ削除され、正しい結合サイズが残ります。 

### 例 2

 同じ整数点で交差する 3 つのセグメントを考えてみましょう。 

| ステップ | アクション | 合計 | 交差点マップ |
 | --- | --- | --- | --- |
 | 1 | すべてのセグメントにわたって格子点を追加する | S | {} |
 | 2 | ペアの交差を検出 (同じ点にある 3 つのセグメント) | S | {(p): 3} |
 | 3 | 修正を適用する | S-2 | {(p): 3} |

 これは、多重度が重要である理由を示しています。 このポイントは 3 つのセグメントで共有されているため、2 回オーバーカウントされるため、それに応じて修正する必要があります。 

トレースは、アルゴリズムが交差部分のペアごとの独立性を仮定しておらず、代わりに完全な多重度を処理していることを確認します。

 ## 特殊なケース

 重要なエッジ ケースは、複数のセグメントが単一の整数点で交わる場合 (星型構成など) です。 その場合、すべてのペアごとの交差は同じ点を報告するため、アルゴリズムは、ペアの爆発ごとではなく、追加のセグメントの寄与ごとに 1 回のみ修正されることを保証する必要があります。 周波数マップは、同一の座標をグループ化することでこれを処理します。 

もう 1 つのエッジ ケースは、2 つのセグメントが共有エンドポイントで正確に交わる、エンドポイントのみの交差です。 これらは交差としてカウントする必要がありますが、浮動小数点計算をトリガーすべきではありません。 交差ルーチンの明示的なエンドポイント チェックにより、一般的なライン交差ロジックの前にエンドポイントが安全に処理されることが保証されます。
