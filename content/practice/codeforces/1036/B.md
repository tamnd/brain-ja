 ## 解決策

 ## 問題の理解

 ミハイルは無限のグリッド上を移動し、各ステップで隣接する 8 つのセルのいずれかに移動できます。 言い換えれば、各移動は、x 座標を最大 1 単位だけ変更し、y 座標を最大 1 単位だけ同時に独立して変更できます。 

クエリごとに、ターゲット セルと正確なステップ数が与えられます。 すべてのステップを使用した後、ミハイルがそのターゲットに正確に着地できるかどうかを判断する必要があります。着地できる場合は、それらのステップのうちのいくつが斜めの動き、つまり両方の座標が変化する動きであるかを最大化したいと考えています。 

斜めに移動すると、x と y の両方が変化するため、両方の座標に同時に 1 単位が寄与します。 非対角方向の移動は 1 つの軸にのみ影響します。 

q は最大 10^4、座標は最大 10^18 であるため、制約により O(q) または O(q log q) の解が求められます。 可能なウォークの数は k とともに指数関数的に増加するため、クエリごとのシミュレーションやパスの検索は不可能です。 

単純なアプローチでは、パリティと到達可能性を注意深く追跡せずに、パスを段階的に構築するか、貪欲な選択を使用するという観点から考えようとします。 主な失敗モードは、各対角ステップが両方の座標に同時に影響するという事実によって引き起こされるパリティ制約を無視することです。そのため、ターゲットに到達した後に残った「緩み」は有効な動きに分解できる必要があります。 

ターゲットが近いが k が大きい場合、微妙なエッジ ケースが発生します。 たとえば、(1, 0) に 2 ステップで到達することは可能ですが、1 ステップで到達することも可能であり、3 ステップで到達するかどうかは、パリティを破らずにステップを無駄にできるかどうかによって決まります。 ステップを最小化するのではなく、正確なステップ数を強制するため、素朴な最短経路の直感は失敗します。 

もう 1 つの隠れた落とし穴は、答えがマンハッタンの距離のみに依存すると仮定していることです。 これは斜めの動きを無視するため、必要なステップ数が効果的に削減されますが、それは両方の軸にまたがる結合的な方法に限られます。 

## アプローチ

 それぞれの移動により、1 つの座標または両方の座標が変更される可能性があります。 1 つのステップに注目すると、各軸の進行に最大 1 単位しか寄与しないため、重要な構造は、k 回の移動を使用して必要な変位 (n、m) をいかに効率的に「カバー」できるかということです。 

便利な考え方は、最終変位を 2 つの部分に分けることです。 d 回の斜めの動きを使用するとします。 各対角線方向の移動は同時に x と y の両方に 1 単位を寄与するため、そのような移動を d 回行った後、(n − dx, m − dy) を、実質的に純粋に水平または垂直の残りの k − d 回の移動でカバーする必要があります。 

最も難しいのは、実現可能性を判断し、d を最大化することです。 

ブルートフォース戦略では、0 から k までの d のすべての可能な値を試し、残りの変位が軸に合わせた移動のみを使用して k − d ステップで達成できるかどうかを確認します。 各 d について、次のことを確認します。 

残りの必要な x 移動と y 移動は、残りのステップが十分であり、正しいパリティ構造を持っていればカバーできます。 これにより、クエリあたり O(k) になりますが、k は 10^18 になる可能性があるため、これは不可能です。 

重要な洞察は、d を列挙することを避け、代わりに動きの形状について推論することです。 各ステップは、x のみ、y のみ、または両方に寄与するものとして分類できます。 d 回の対角移動を使用する場合、残りのステップは k − d であり、各ステップは 1 つの軸のみに寄与できるため、利用可能な「軸の寄与」の合計は k + d となります。 少なくとも x への寄与が n 個、y への寄与が m 個必要ですが、対角移動は両方を同時に助けます。 

これは、標準的なリソース割り当てビューにつながります。つまり、k ステップの予算の下で、x 要件と y 要件の間の重複を最大化したいと考えます。 最大オーバーラップは、実行可能性と残りのステップのパリティ制約の両方によって制約されます。

これを解決するきれいな方法は、すべての対角移動が最適に使用される場合、(n, m) に到達するために必要な最小移動数から開始することです。 その最小数は max(n, m) です。これは、各ステップで、一方がなくなるまで両方の座標を同時に減らすことができ、その後 1 つの軸だけが残るからです。 

k が max(n, m) より小さい場合は不可能です。 k が大きい場合、前後に移動することで迂回を挿入できます。これにより、位置を変更せずに 2 つのステップが消費され、パリティが維持されます。 したがって、到達可能性は、k が少なくとも max(n, m) であるかどうか、および追加のステップのパリティによってキャンセルが許可されるかどうかによって決まります。 

実現可能性が確立されると、対角移動の最大化は、両方の座標がまだ正である限り、x と y の縮小を貪欲に組み合わせることになります。 対角方向の移動の最大数は、小さい座標によって制限されますが、k 内の動きを同期させるために許容できるステップ数によっても制限されます。 

したがって、答えは本質的に、k ステップの下での x と y の進行の間の可能な最大の重複であり、残りのステップを中立サイクルとして使用できるかどうかによって調整されます。

 ## アルゴリズムのチュートリアル

 まず実現可能性を導き出し、次に斜めの動きを最大化します。 

1. 可能な限り両方の座標を減らすためにすべての移動が最適に使用される場合に必要な最小移動数を計算します。 このベースラインは max(n, m) です。これは、各移動で同時に各方向に最大 1 ユニットを減らすことができ、両方の座標を一致させる必要があるためです。 
2. k が max(n, m) より小さい場合は、最適な戦略でもターゲットに到達できないため、すぐに -1 を返します。 
3. k が max(n, m) に等しい場合、すべての手が無駄なく最適に使用されなければなりません。 この場合、両方の座標がまだ正であれば、すべての動きを対角線として選択できます。 対角移動の数は正確に min(n, m) です。 
4. k が max(n, m) より大きい場合、エンドポイントに影響を与えない余分な動きがあります。 1 つの迂回によって到達可能性の同等性が変化するため、これらの追加の移動は効果的にペアで行われます。 したがって、常に 2 ステップのサイクルを挿入できるため、k − max(n, m) は任意である必要があります。 
5. 小さい座標で許容される以上のオーバーラップを作成できないため、対角移動の最大数は min(n, m) によって制限されます。 
6. 最適な対角移動数として min(n, m) を返します。 

有用な解釈は、まず両方の座標をできるだけ一緒に消費するようにパスを調整し、その後、残りのステップを対角効率を低下させないアイドル サイクルとして費やすことです。 

### なぜ効果があるのか

 (0, 0) から (n, m) までのパスは、両方の軸または 1 つの軸のみに共同で寄与するステップに分解できます。 対角線の使用量を最大化する最良の方法は、両方がゼロ以外のままである限り、x と y の増分を一致させることです。 このようなペアのリダクションを min(n, m) 回実行した後、1 つの座標が使い果たされ、残りの進行状況はすべて軸に揃える必要があります。 

余分なステップは動きを無駄にするか、サイクルによって相殺されるため、ペアの削減の数を増やすことはできません。 したがって、対角移動の数の上限は min(n, m) であり、k が到達可能性にとって十分である場合は常に、この上限は常に達成可能です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

q = int(input())
for _ in range(q):
    n, m, k = map(int, input().split())

    mx = max(n, m)
    mn = min(n, m)

    if k < mx:
        print(-1)
        continue

    print(mn)
```### コードの説明

 このソリューションは、派生した構造を直接適用します。 実現可能性チェックでは、少なくとも max(n, m) 個の移動が必要であるという事実を利用します。 k が小さい場合、有効なパスは存在しません。 

実現可能性が成立すると、各対角移動は x 進行の 1 単位と y 進行の 1 単位のペアに対応するため、答えは min(n, m) になります。 追加の手順を実行しても、このペアリング容量は増加しません。 

この実装では、パスのシミュレーションを完全に回避し、純粋に座標ジオメトリに依存します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    q = int(input())
    out = []
    for _ in range(q):
        n, m, k = map(int, input().split())
        mx = max(n, m)
        mn = min(n, m)
        if k < mx:
            out.append("-1")
        else:
            out.append(str(mn))
    return "\n".join(out) + "\n"

 ## 特殊なケース

 重大なエッジケースは、1 つの座標がゼロの場合です。 たとえば、(5、0、5)。 このアルゴリズムでは、min(5, 0) = 0 回の対角移動が行われ、k ≥ max(n, m) であるため実現可能性が保たれます。 これは正しいです。すべての移動は軸に合わせて行う必要があるため、斜めの移動は不可能です。 

もう 1 つのケースは、k が正確に max(n, m) である場合です。 (3, 1, 3) の場合、結果は min(3, 1) = 1 です。実行には正確に 3 つのステップを使用する必要があり、1 つの対角ペアリングの後、残りのステップでエンドポイントを保持する必要があります。これは、軸のみの移動を慎重に使用する場合にのみ可能です。 

最後に、(2, 2, 100) のように、k が必要な値よりはるかに大きい場合、答えは 2 のままです。余分な 96 ステップは、エンドポイントを変更しない往復サイクルに吸収できるため、対角容量には影響しません。
