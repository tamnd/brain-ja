 ## 解決策
 ## 問題の理解

 私たちは 10 進数の「スパース」数値の概念を使って作業しています。数値を 10 進数で書くとき、その数値の最大 3 桁がゼロ以外であれば、その数値は有効であるとみなされます。 ゼロはどこにでも、どんな量でも出現できますが、実際の値を保持できるのは最大 3 桁までです。 

クエリごとに間隔が与えられます$[L, R]$, そして、その区間内でこのスパース性条件を満たす整数がいくつあるかを数えなければなりません。 

範囲のエンドポイントは次のとおりです$10^{18}$, したがって、最大 19 桁の数字を扱います。 各クエリには効率的に回答する必要があり、最大で$10^4$クエリ。 

制約の直接的な意味は、範囲内のすべての数値を反復することが不可能であるということです。 単一の間隔でも、次のように大きくなる可能性があります。$10^{18}$そしてそれを合計すると$10^4$クエリを使用すると、ブルート フォースが完全に不可能になります。 

主なエッジケースは、算術境界ではなく数字構造に由来します。 たとえば、1000000 と 1000001 のような数値は、隣接しているにもかかわらず、まったく異なる動作をします。 もう 1 つの微妙なケースは、上位に散在する 0 以外の数字がちょうど 3 つある数値です。この場合、位置制約を無視した単純な数え方では多重度を数え間違えてしまいます。 

## アプローチ

 ブルートフォースソリューションでは、すべての数値を反復処理します。$[L, R]$、ゼロ以外の桁をカウントし、カウントが最大 3 の場合はカウンターをインクリメントします。 これは論理的には正しいですが、各番号は最大 19 桁までスキャンする必要があります。 たとえ些細なことではないとしても、$R - L \approx 10^{18}$、これは実行可能な計算をはるかに超えています。 サイズのクエリを 1 つだけ考慮した場合でも、$10^6$、数字のスキャンによりボーダーラインになります。$10^4$クエリを実行すると完全に崩壊します。 

問題の構造は、値の反復処理から有効な数値を 1 桁ずつ構築することに視点を移すことを示唆しています。 「この数字は有効か」と問うのではなく、「X までに有効な数字がいくつ存在するか」を尋ねます。 これは古典的な数字 DP シナリオであり、制約は合計や順序ではなく、ゼロ以外の数字の数に依存します。 

重要な観察は、最大 19 桁の中から最大 3 つの桁を選択し、それらの桁にゼロ以外の桁を割り当てることによって、有効な数値が完全に決定されるということです。 位置が選択されると、数字は独立します。 これにより、カウントは、桁ごとの有界列挙の内部に埋め込まれた組み合わせ構造に変わります。 

したがって、関数を計算します$F(x)$: 内の有効な整数の数$[1, x]$。 各クエリは次のように回答されます。$F(R) - F(L - 1)$。 

計算するには$F(x)$、ポジションに対して数字 DP を実行し、すでに使用したゼロ以外の数字の数と、まだ接頭辞によって制限されているかどうかを追跡します。$x$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | ブルートフォース |$O((R-L)\cdot \log R)$|$O(1)$| 遅すぎる |
 | 桁DP |$O(19 \cdot 4 \cdot 2 \cdot 10)$クエリごと |$O(19 \cdot 4 \cdot 2)$| 承認済み |

 ## アルゴリズムのチュートリアル

 関数を定義します$F(x)$範囲内の有効な数値をカウントします$[1, x]$。 

1.変換$x$10 進数の配列に変換します。 これにより、最上位桁から位置ごとに推論することができます。 
2. DP 状態を定義する$dp[pos][cnt][tight]$、 どこ$pos$現在の数字のインデックス、$cnt$はすでに使用したゼロ以外の数字の数です、そして$tight$まだプレフィックスと一致しているかどうかを示します$x$。 
3. 各位置で、0 から 9 までのすべての可能な数字を試しますが、上限は現在の数字に制限されます。$x$もし$tight = 1$。 これにより、決して超過しないことが保証されます$x$。 
4. 各候補桁について、更新します。$cnt$数字がゼロ以外の場合は 1 を加算します。 これが 3 を超える場合、遷移は破棄されます。 
5. 次の位置に移行し、タイト フラグを更新します。現在の桁と正確に一致する場合にのみタイトなままになります。$x$。 
6. すべての位置を処理した後、すべての有効な状態を 1 つの有効な数値としてカウントします。 また、DP で先頭のゼロを自然に扱うことで、空の数値の解釈を確実に除外します。 
7. コンピューティング$F(R)$そして$F(L-1)$クエリごとに減算します。 

DP は、先頭に先行ゼロを許可することで、異なる長さの数値を自然に処理します。 これらの先行ゼロは非ゼロ制限にはカウントされないため、有効性に影響しません。 

### なぜ効果があるのか

 内のすべての数字$[1, x]$は、DP ツリー内の 1 つのパスに正確に対応します。各数字の選択により、一意のプレフィックスが定義されます。 DP は、すべての数値を重複することなく数字の接頭辞によって分割します。 非ゼロ桁の制約はローカルかつ単調に適用されます。つまり、ゼロ以外の桁が 3 桁を超えると、継続は有効性を回復できなくなります。 タイト フラグにより​​、上限を超えない数値のみがカウントされ、上限制限の正確性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from functools import lru_cache

def solve_case(x: int) -> int:
    if x <= 0:
        return 0
    digits = list(map(int, str(x)))
    n = len(digits)

    @lru_cache(None)
    def dp(pos: int, cnt: int, tight: int) -> int:
        if cnt > 3:
            return 0
        if pos == n:
            return 1

        limit = digits[pos] if tight else 9
        res = 0

        for d in range(limit + 1):
            new_cnt = cnt + (d != 0)
            new_tight = tight and (d == limit)
            res += dp(pos + 1, new_cnt, new_tight)

        return res

    return dp(0, 0, 1)

def solve():
    t = int(input())
    for _ in range(t):
        l, r = map(int, input().split())
        print(solve_case(r) - solve_case(l - 1))

if __name__ == "__main__":
    solve()
```この解決策は、上限の 10 進数表現に基づいて数字 DP を構築します。 再帰では、これまでに配置されたゼロ以外の数字の数が追跡されます。 その数が 3 を超えると、枝はすぐに剪定されます。 

タイト フラグは、標準の数字 DP の考え方を使用して実装されます。タイトが true の場合、次の数字は境界内の対応する数字を超えることはできません。 それ以外の場合は、0 ～ 9 の範囲を自由に指定できます。 

微妙な点の 1 つは、先行ゼロの処理です。 これらは通常の数字として DP に当然含まれますが、ゼロ以外のカウントは増加しないため、特別な処理を行わずに短い長さの数値を表すことができます。

    input = sys.stdin.readline

    def solve_case(x: int) -> int:
        if x <= 0:
            return 0
        digits = list(map(int, str(x)))
        n = len(digits)

        @lru_cache(None)
        def dp(pos: int, cnt: int, tight: int) -> int:
            if cnt > 3:
                return 0
            if pos == n:
                return 1

            limit = digits[pos] if tight else 9
            res = 0
            for d in range(limit + 1):
                new_cnt = cnt + (d != 0)
                new_tight = tight and (d == limit)
                res += dp(pos + 1, new_cnt, new_tight)
            return res

        return dp(0, 0, 1)

 ## 特殊なケース

 重要なエッジ ケースは、1000 や 1000000 など、正確に 10 のべき乗である数値です。これらは、ゼロ以外の数字が 1 つだけ含まれているため、有効である必要があります。 DP では、これらは、より高い位置に数字 1 を選択し、その他の位置にゼロを選択することによって発生します。 この遷移により、ゼロ以外のカウンタが 1 回だけ正しくインクリメントされます。 

もう 1 つの特殊なケースは、1000001 のような数値です。この場合、ゼロ以外の数字は長いゼロの連続によって区切られます。 DP は構造を圧縮しません。 各位置を独立して処理するため、距離に関係なく両方の非ゼロ桁が正確にカウントされます。 

最後に、境界ケース$L = 1$を定義することで処理されます$F(0) = 0$。 これにより、負の範囲が回避され、確実に減算が行われます。$F(R) - F(L-1)$特別な分岐なしで有効なままです。
