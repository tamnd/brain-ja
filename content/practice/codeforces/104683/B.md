 ## 問題の理解

 小文字の英字の文字列が与えられ、固定回数の操作を使用してそれを変更できます。 各操作では 1 つの文字を選択し、循環アルファベット内で 1 つ前または後ろに移動します。`a`続く`z`そして`z`続く`a`。 

タスクは正確に費やすことです`k`このような操作を実行すると、辞書編集上可能な限り最小の結果文字列が得られます。 各操作は 1 つのキャラクターにのみ影響し、コストは均一です。どちらかの方向に 1 位置移動すると、常に 1 回の移動がかかります。 

出力は、正確に分散した後の可能な限り最良の最終文字列です。`k`好きなようにキャラクター間を移動できます。 

ソリューションを形成する主な制約は、すべてのテスト ケースの合計の長さが最大であることです。`4 · 10^5`、 その間`k`と同じ大きさにすることができます`10^9`。 これにより、考えられるすべての変換のシミュレーションや、操作ごとの文字列全体の貪欲な再評価が即座に除外されます。 に比例して時間を費やすあらゆるアプローチ`k`不可能です。 また、1 つのキャラクターに余分な動きを費やすと、後でより悪い選択を強いられる可能性があるため、残りの予算を調整せずに各キャラクターを個別に扱うことはできません。 

微妙なエッジケースが現れるのは、`k`合計の「有用な」改善と比較して大きいです。 たとえば、文字列がすでにすべてである場合、`'a'`、すべての動きは辞書編集上の順序を改善せずに距離を増やすだけであるため、場合によっては文字を振動させることによって、すべての動きを消費する必要があります。 「文字だけを改善しよう」とする単純な貪欲な考えでは、残った予算を考慮することができず、間違った答えが生成されてしまいます。 

もう 1 つの注意が必要なケースはパリティにあります。 正確に使用する必要があるため、`k`場合によっては、辞書編集的に最適な構成に達した後でも、1 つの移動を無駄にせざるを得なくなることがあります。 このような無駄は、文字を前方に移動してから後方に移動するか、その逆に移動することによってのみ発生します。これにより、文字列は保持されますが、2 つの移動が必要になります。 これが重要になるのは、`k`残りは奇数です。 

## アプローチ

 ブルートフォースの観点は、各文字を独立して考え、その文字に対して考えられるすべての最終文字と、ポジション間での操作のすべての配分を試すことです。 単一文字の場合、次のように変換します。`s[i]`何かの手紙に`c`アルファベット上の最小円周距離がかかります。 正確にグローバル制約を無視すると、`k`、各キャラクターを貪欲に次のように変えることができます`'a'`もし可能なら。 問題は、正確に使用する必要があることです`k`せいぜい動く`k`、および移動は、残りの予算を通じてのみキャラクター間で相互作用できます。 

完全な総当たり攻撃では、可能なすべての割り当てが試行されます。`k`全体にわたる操作`n`位置とすべての可能なターゲット文字。 たとえコストに限定して注意を払ったとしても、操作を分散する方法の数は組み合わせによるもので、`O(k^n)`最悪の解釈では、まったく実行不可能です。 

重要な構造的観察は、辞書編集上の順序が主に以前の文字に依存しているということです。 これは、左から右への貪欲な戦略を示唆しています。理想的には、初期の文字をできるだけ小さくする必要があります。`'a'`なぜなら、そこでの改善は文字列の後の変更を支配するからです。 

キャラクターごとに、それを変換するための最小コストを計算します。`'a'`。 十分な予算があればそれを適用します。 それ以外の場合は、残っている予算をすべて使用して、できる限り近づけます。`'a'`できるだけ。 周期的な性質により、最適性を変えることなく残りの手を吸収できることが保証されます。残りの予算で達成可能な最良の文字を決定したら、残りのパリティは最終調整で処理できます。 

これにより、問題はグローバルな組み合わせではなく、実行予算に基づくキャラクターごとの決定に帰着します。

 ## アルゴリズムのチュートリアル

 1. キャラクターごとに`s[i]`、までの円周距離を計算します。`'a'`。 これにより、そのキャラクターを作成するために必要な最小限の移動数が得られます。`'a'`。 

これは次のように計算されます`min((c - 'a') % 26, ('a' - c) % 26)`。 
2. 予算が残っている場合`k`少なくともこの距離である場合は、距離を縮めます`k`それに応じて文字を次のように設定します`'a'`。 

前の文字をできるだけ小さくすると常に辞書編集上の順序が改善されるため、これは最適です。 
3. もし`k`必要な距離より短いため、到達できません`'a'`。 代わりに、キャラクターをできるだけ遠くに移動させます。`'a'`できる限り使用して`k`サイクル上はより安価な方向に進みます。 

これにより新たなキャラクターが誕生します`c' = (c - k) mod 26`または`(c + k) mod 26`に近い方`'a'`。 
4. 有用な削減をすべて消費すると、残りは`k`辞書編集構造を変更する必要はありません。 動きはペアで可逆的であるため、残りのバジェットは最終的な文字列とは無関係であるため、事実上無視できます。 

最終的な構成では、各プレフィックスがすでに可能な限り最小化されています。 

### なぜ効果があるのか

 核となる不変条件は、どの位置でも`i`処理する前に、すべての位置の辞書編集上の利点をすでに最大化しています。`< i`残りの予算を考えると。 辞書編集上の順序は左から右に決定されるため、後の操作では最適ではない前の文字を補うことはできません。 

循環コスト構造により独立性が保証されます。1 つのキャラクターを変換しても、他のキャラクターのコスト構造には影響しません。 したがって、各キャラクターをできるだけ近づけるという貪欲な選択は、`'a'`残りの予算内で可能な限り、局所的に最適であり、世界的に一貫性のあるものを選択します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def dist_to_a(c):
    x = ord(c) - ord('a')
    return min(x, 26 - x)

def move_towards_a(c, k):
    x = ord(c) - ord('a')
    if x >= k:
        return chr(ord('a') + x - k)
    else:
        k -= x
        return chr(ord('a') + (26 - k) % 26)

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n, k = map(int, input().split())
        s = list(input().strip())

        for i in range(n):
            d = dist_to_a(s[i])
            if k >= d:
                k -= d
                s[i] = 'a'
            else:
                s[i] = move_towards_a(s[i], k)
                k = 0

        out.append("".join(s))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```実装では各テスト ケースを個別に処理し、実行予算を維持します。`k`。 ヘルパーさん`dist_to_a`までの最小巡回距離を計算します。`'a'`、文字を完全に変換するか部分的にのみ調整するかを決定します。 

機能`move_towards_a`予算が足りない場合にも対応します。 キャラクターを次の方向に移動させます`'a'`必要に応じてアルファベットを包み込み、より安価な方向に。 これにより、ステップバイステップの動きを明示的にシミュレートすることが回避されます。 

前の文字が辞書編集上の順序で優先されるため、ループは厳密に左から右です。 予算は貪欲に更新されるため、以前のポジションへの支出を後悔することがなくなります。 

微妙な実装ポイントは、`k`が枯渇しても、それ以降の文字は変更されません。 さらに変更を加えても、以前の位置を再訪せずに辞書編集上の順序を改善できないため、追加のロジックを伝播する必要はありません。

 ## 特殊なケース

 重要なエッジケースは、文字列がすでに次のもので構成されている場合です。`'a'`キャラクターと`k`はゼロではありません。 この場合、すべての移動を使用する必要がありますが、辞書編集上の最小の文字列は変わりません。 アルゴリズムはこれを処理します。`dist_to_a`はゼロです`'a'`, そのため、予算は消費されず、キャラクターは変更されません。 残り`k`これ以上の改善は不可能であるため、意味がなくなりました。 

もう一つのケースは次のような場合です。`k`非常に大きいです。 各文字は独立して処理されるため、アルゴリズムは、到達するために必要以上に適用しようとすることはありません。`'a'`。 すべてのキャラクターを最小化すると、超過予算は当然無視されます。 

アルファベットの大文字小文字の回り込み（変形など）`'z'`、循環距離の計算では常に短い方向が選択されるため、正しく処理されます。 これにより、次の目的地に移動する際に、お金を使いすぎたり、より安価なルートを逃したりすることがなくなります。`'a'`。
