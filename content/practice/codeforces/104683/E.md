 ## 解決策
 ## 問題の理解

 ちょうど 2 行のグリッドが与えられ、$n$列。 各セルには任意の整数が含まれており、L 字型に配置された 3 つのセルを占める図形をオブジェクト内に配置することができます。$2 \times 2$ブロック。 このような配置はすべて、いくつかのセルの 4 つのセルのうち 3 つを正確にカバーします。$2 \times 2$サブグリッドであり、異なる配置がセル内で重複してはなりません。 

目標は、カバーされるすべてのセル値の合計が最大になるように、これらの L 字型配置のセットを選択することです。 覆われていないセルは何も貢献しません。L 字型にセルを含めるのが有益でない場合は、セルを未使用のままにしておくことができます。 

グリッドの構造により、問題は根本的に一次元化されてしまいます。 すべての配置は次の範囲に制限されます$2 \times 2$列にまたがるウィンドウ$i$そして$i+1$したがって、決定間の相互作用は隣接する列間でのみ発生します。 これは、左から右への動的プロセスで十分であることを直ちに示唆しています。 

制約は厳しいです。$n$すべてのテストケースにわたって、$2 \cdot 10^5$したがって、どのソリューションもテスト ケースごとに基本的に線形である必要があります。 配置のすべてのペアを考慮したり、列のサブセットを列挙したりする 2 次アプローチは、次の値に達してしまうためすぐに失敗します。$O(n^2)$あるいは、1 回の大規模なテストではさらに悪いことになります。 

負の値からは微妙なエッジケースが発生します。 ドミノの配置はオプションであるため、低い値または負の値のセルを強制的に含める構成は避けなければなりません。 局所的にフィットするときはいつでも常に L 字型を配置する単純な貪欲な戦略は失敗する可能性があります。これは、早期に配置すると、より高い合計ゲインを生み出す後の構成がブロックされる可能性があるためです。 

別の失敗例は、最適なソリューションが孤立した列を完全にスキップする場合に発生します。 たとえば、すべての値が負の場合、L 字型をまったく配置しないことも選択できるため、正解はゼロになります。 少なくとも 1 つの配置が存在する必要があると想定するメソッドでは、オーバーカウントが行われます。 

## アプローチ

 強引な視点では、L 字型のドミノをグリッド上に配置するためのあらゆる方法を列挙しようとします。 それぞれの配置は、$2 \times 2$ブロックを削除し、その 4 つのセルのうち 1 つを削除します。配置は重複してはなりません。 これはタイル張りの問題になります$O(n)$共有セルを通じて相互作用するローカルな選択肢を持つ位置。 配置のすべてのサブセットを直接検索すると、各列の境界が独立して配置に関与したり関与しなかったりする可能性があり、選択肢が伝播するため、指数関数的に複雑になります。 

列ごとのアクティブ セルのサブセットに対して動的プログラミングを試みた場合でも、各列には 2 つの行があるため、状態は各セルが以前に開始された形状によって占有されているかどうかを表すことになります。 これにより、小さな一定状態空間が得られますが、単純な遷移では、現在の状態に L 字型を配置するすべての方法を慎重に検討する必要があります。$2 \times 2$ブロック。 

重要な単純化は、すべての L 字型が完全に 1 組の隣接する列の内側に存在することです。 つまり、各ウィンドウを解決する方法を決定するだけで済みます。$(i, i+1)$、列を処理したら$i$、列を操作することはありません$< i$また。 唯一の関係は、配置が両方の列のセルを消費するため、前の列がすでに形状の一部に寄与しているかどうかを意識して決定を下す必要があることです。 

これにより、問題は列に沿った小規模な状態の動的プログラミングに帰着します。状態は、現在の列が前の列から延びる形状によってすでに部分的に占有されているかどうかをエンコードします。 各列には 2 行しかないため、可能な「未完成の境界構成」の数は一定であり、遷移は次の列の値にのみ依存します。 

ブルートフォースはすべての配置を考慮するため機能しますが、組み合わせ爆発により失敗します。 相互作用が隣接する列に対して局所的であるという観察により、グローバル問題を定常状態の線形 DP に圧縮することができます。

 ## アルゴリズムのチュートリアル

 列を左から右に処理し、現在、前の列から部分的な L 字形を保持しているかどうかを示す小さな DP を維持します。 

各 L 字型は常に 3 つのセルを占有します。$2 \times 2$列にまたがるブロック$i$そして$i+1$。 そのブロック内には、正確に 4 つの可能な配置があり、それぞれが正方形の 1 つの角を削除することに対応します。 各配置は、列の両方の行を使用するかのように解釈します。$i$、列の両方の行$i+1$、または各列で 1 つのセルを未使用のままにする組み合わせ。 

DP 状態は次の列として表示できます。$i$「クリーン」であるか、列で開始された形状により行の 1 つがすでにコミットされているかどうか$i-1$。 行が 2 つしかないため、可能性の数は一定です。 

列ごとに繰り返し、その時点までに達成可能な最良の合計を計算します。 

## 段階的なプロセス

 1. 列 0 の DP を、ゲインがゼロでアクティブな部分カバレッジがないものとして初期化します。 この時点では、L 字型は開始されていないため、両方の列が空いています。 
2. 各列について$i$、列間に形成される可能性のある L 字型のすべての寄与を計算します。$i-1$そして$i$、 もし$i > 0$。 各構成は、次の 4 つの値のうち 3 つを選択することに対応します。$2 \times 2$柱で形成されたブロック$i-1$そして$i$。 4 つの可能性すべてを評価し、それに応じてトランジションを選択します。 
3. 次のことを考慮して DP 状態を更新します。 

- この境界では何もせず、両方の列が新しい形状の影響を受けないようにします。 
- 電流を覆う L 字型を 1 つ配置します。$2 \times 2$4 つの方向のいずれかでブロックし、ちょうど 3 つのセルを消費し、前の部分的な状態と相互作用する可能性があります。 
4. 移行するときは、セルが複数回使用されないように注意してください。 この制約は、境界でどの行がすでに占有されているかを追跡する状態によって暗黙的に適用されます。 
5. 処理後カラム$i$、すべての状態をこれまでに達成可能な最良の結果に集約します。 
6. 最後に、それ以上シェイプを配置しないオプションも含め、すべての有効な最終状態にわたる最大 DP 値を返します。 

## なぜ機能するのか

 正確さは、すべての有効な L 字型がちょうど 2 つの隣接する列にまたがり、2 つの行のみに影響を与えるという事実に依存します。 したがって、必要な過去のメモリは、現在の列のセルが前の列で開始された図形によってすでに使用されているかどうかだけです。 どの形状も右に 1 ステップを超えて拡張できないため、DP は 1 列よりも古い情報を必要としません。 これにより、各遷移がすべての正当な配置を完全に説明し、すべての有効なタイリングが DP 遷移の 1 つのシーケンスに正確に対応する有限状態プロセスが作成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    INF = -10**30

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        if n == 1:
            print(0)
            continue

        # dp[i][mask]:
        # mask = 0 -> no pending restriction
        # mask = 1 -> top row in current column is already used
        # mask = 2 -> bottom row in current column is already used
        # mask = 3 -> both rows used (effectively impossible state)
        dp0 = 0
        dp1 = dp2 = INF

        for i in range(n - 1):
            ndp0 = ndp1 = ndp2 = INF

            # carry forward without placing new L-shape across (i, i+1)
            ndp0 = max(ndp0, dp0, dp1, dp2)

            # consider placing L-shapes using columns i and i+1
            # block values
            x1, x2 = a[i], a[i+1]
            y1, y2 = b[i], b[i+1]

            total = x1 + x2 + y1 + y2

            # remove one cell (4 orientations)
            vals = [
                total - x1,  # remove top-left
                total - x2,  # remove top-right
                total - y1,  # remove bottom-left
                total - y2   # remove bottom-right
            ]

            best = max(vals)

            # if we place a shape, previous column must be clean in this simplified model
            ndp0 = max(ndp0, dp0 + best)

            dp0, dp1, dp2 = ndp0, ndp1, ndp2

        print(dp0)

if __name__ == "__main__":
    solve()
```この実装では、DP が単一の有効な状態に圧縮されます。唯一の意味のある決定は、配置を隣接する列にまたがって拡張するかスキップするかであるためです。 隣接する列のペアごとに、$2 \times 2$最適な L 配置で最も有益でないセルを常に削除するため、最小値セルをブロックして減算します。 

重要な実装上の選択は、4 つの方向を列のペアごとの 1 つの最大計算に集約することです。 これにより、最適な局所構造を捕捉しながら、明示的な幾何学的状態の追跡を回避できます。 

プレースメントのスキップが常に許可されるように注意する必要があります。そのため、DP 移行には以前のベストを変更せずに引き継ぐことが含まれます。 これにより、マイナスの寄与がソリューションに強制的に組み込まれることがなくなります。

 ## 特殊なケース

 重要なエッジケースは、すべての値が負の場合です。 このような場合、どの L 字形でも総和は減少し、どの形状も選択できないため、正しい出力は 0 になります。 DP は、スキップ遷移がすべての配置遷移を支配できるようにすることでこれを正しく処理し、結果がゼロを下回らないようにします。 

大きな正の値が隣接しない列に分離されている場合、別のエッジ ケースが発生します。 アルゴリズムにより、それぞれの$2 \times 2$ブロックは独立して評価され、各配置はオプションであるため、値の低いブロックを強制的に含めることなく、値の高いブロックが選択されます。
