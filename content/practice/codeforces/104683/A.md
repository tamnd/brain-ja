 ## 解決策
 ## 問題の理解

 1 から n までの番号が付けられたカードのコレクションが与えられます。 クエリごとに、誰かが値 m を選択し、m で割り切れるすべてのカード番号の合計を求めます。 言い換えれば、1 から n までの範囲に現れる m の倍数ごとに合計を加えます。 

したがって、固定クエリの場合、項が n を超えない限り、m + 2m + 3m + … を計算することがタスクとなります。 これは、範囲内の m の倍数によって形成される等差数列の単純な合計です。 

入力には最大 100,000 の独立したクエリが含まれており、各 n は 1e9 までの大きさになります。 この組み合わせにより、クエリごとに最大 n までのすべての数値を反復するアプローチは直ちに排除されます。 n が大きく t も大きい場合、最悪のケースでは 1e14 程度の演算が必要となるため、倍数を 1 つずつ繰り返すことさえ不可能になります。 

主なエッジケースは、倍数の範囲の誤解から生じます。 単純な実装では、1 から n までループして割り切れ性をチェックしようとする可能性がありますが、これは明らかに実行不可能です。 もう 1 つの微妙な問題は、閉じた形式の存在に気付かずに誰かが蓄積しようとした場合のオーバーフローまたは精度です。Python はオーバーフローを回避しますが、それでも TLE になります。 

小さな例で構造を明確に示します。 n = 12 および m = 2 の場合、有効なカードは 2、4、6、8、10、12 で、それらの合計は 42 になります。n = 1 および m = 1 の場合、含まれる数字は 1 つだけであるため、答えは 1 になります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 各クエリについて、1 から n までのすべての整数をスキャンし、m で割り切れる整数を追加します。 これは定義に直接従うため、正しいです。 ただし、クエリごとに n 回の反復が実行されるため、t と n の両方が大きい場合、最悪の場合は 1e14 回の操作が行われ、これは制限をはるかに超えます。 

重要な観察は、合計に寄与する数値が正確に m の倍数であることです (m、2m、3m など、km ≤ n となる最大の k まで)。 このような項の数は、floor(n / m) です。 これを特定すると、問題は m でスケールされた最初の k 個の自然数を合計することになります。 

したがって、合計は次のようになります。 

m (1 + 2 + … + k)、ここで k = フロア(n / m)。 

最初の k 個の整数の合計は k(k + 1) / 2 なので、最終結果は次のようになります。 

m * k * (k + 1) / 2。 

これにより、各クエリが定数時間の演算に削減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | クエリごとに O(n) | お(1) | 遅すぎる |
 | 最適 | クエリごとに O(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. クエリの n と m を読み取ります。 これらは、カードの範囲と有効な倍数のステップ サイズを定義します。 
2. k = n // m を計算します。 すべての有効な項は i・m の形式であるため、これにより、[1, n] 内に収まる m の倍数の数が得られます。 
3. k * (k + 1) // 2 を使用して、1 から k までの整数の合計を計算します。これは、倍数のインデックス位置を表します。 
4. その結果に m を乗じて、インデックスから実際のカード値にスケールバックします。 
5. クエリの結果を出力します。 

### なぜ効果があるのか

 合計内のすべての有効な数値は、i・m として一意に記述することができます。ここで、i の範囲は 1 ～ k = Floor(n / m) です。 このマッピングは 1 対 1 であるため、カードの値を合計することは、スケーリングされた連続する整数のシーケンスを合計することと同じです。 このシーケンスは差が一定の算術演算であるため、閉じた形式に置き換えることで、すべての有効な入力の正確性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        k = n // m
        ans = m * k * (k + 1) // 2
        print(ans)

if __name__ == "__main__":
    solve()
```解決策は、問題を倍数の数え方に変換し、等差級数の公式を適用することに完全に依存しています。 整数の除算 n // m は、サイズ m の全ステップがいくつ範囲に収まるかを決定するため、非常に重要です。 m による乗算は、中間ステップでの不必要な増加を避けるために三角数を計算した後に行う必要がありますが、いずれにせよ Python は大きな整数を処理します。 

よくある間違いは、順序を逆にしたり、ループ内で m * i を繰り返し計算しようとしたりすることです。 もう 1 つの微妙な問題は、m > n の場合に k がゼロであることを忘れていることですが、整数の除算は当然このケースを正しく処理します。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

        n, m = map(int, sys.stdin.readline().split())
        k = n // m
        output.append(str(m * k * (k + 1) // 2))

 ## 特殊なケース

 m > n の場合、整数除算により k は 0 になります。 たとえば、n = 5、m = 10 と入力すると k = 0 が生成され、式は 0 * 1 / 2 * m = 0 と評価されます。これは、その範囲内で m で割り切れるカード番号がないという事実と一致します。 

m が n と等しい場合、k は 1 になり、結果は m * 1 = m となり、単一の有効な要素が正しくキャプチャされます。 

m = 1 の場合、1 から n までのすべての数字が含まれます。 式は n(n + 1)/2 となり、最初の n 個の整数の標準和と一致し、一般式がよく知られているケースに正しく縮退していることが確認されます。
