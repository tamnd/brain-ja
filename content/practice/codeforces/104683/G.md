 ## 問題の理解

 バイナリ文字列と固定ウィンドウ長が与えられます。$m$。 文字列は、すべての連続する部分文字列が同じ長さである場合にのみ有効であると見なされます。$m$正確に含まれています$k$もの。 つまり、次のサイズのウィンドウをスライドすると、$m$文字列全体にわたって、各ウィンドウは 1 に関して同一の母集団を持つ必要があり、その母集団は次のように固定されます。$k$。 

操作は何度でも適用できます。 各操作でセグメントが選択されます$[l, r]$そして、その中のすべてのビットを反転して、0 を 1 に、1 を 0 に変換します。 目標は、このようなセグメントの反転の数を最小限に抑えながら、初期文字列を有効な文字列に変換することです。 

制約$n \le 3000$の合計で$n$また、によって制限されます$3000$テスト ケース全体で意味するのは、$O(n^2)$あるいは、テスト ケースごとにわずかに悪い解決策であっても許容されますが、最悪の場合の 3 次的なものは避けなければなりません。 これは、位置またはプレフィックス状態に対する動的プログラミングまたは貪欲な構造を強く示唆しています。 

この問題の微妙な点は、有効性が重なり合うすべてのウィンドウにわたって定義されており、これにより位置が強く結合されることです。 各ウィンドウを個別に修正する単純なアプローチは失敗します。セグメントを反転すると、重なっている多数のウィンドウが同時に影響を受けるためです。 

2 番目のよくある落とし穴は、ターゲット パターンに一致するように各位置を貪欲に修正できると想定していることです。 明示的なターゲット文字列が指定されていないため、これは失敗します。 validity はグローバル制約であり、点ごとの等価制約ではありません。 

## アプローチ

 強引なアイデアは、考えられるすべての最終的な有効な文字列を考慮し、最初の文字列を各候補に変換するために必要なセグメント フリップの最小数を計算することです。 有効な文字列は、スライディング ウィンドウ制約を満たす一貫した割り当てを選択することによって完全に決定されます。 ただし、制約が重複しており、一貫した構成の数が指数関数的に増加するため、このような文字列を列挙することは不可能です。$n$。 

ターゲット文字列の候補を修正したとしても、あるバイナリ文字列を別のバイナリ文字列に変換するためのセグメント フリップの最小数を計算すること自体は自明ではありません。 これは差分のパリティに依存する古典的な区間反転問題になりますが、指数関数的に多くのターゲットに対してこれを行うと、このアプローチは実行不可能になります。 

重要な構造的観察は、制約が「長さのすべてのウィンドウ」であるということです。$m$まさに$k$one" は強い周期的な依存関係を強制します。位置から始まる 2 つの隣接するウィンドウを比較すると、$i$そして$i+1$、それらの合計は削除することによってのみ異なります。$s[i]$そして追加$s[i+m]$。 両方が等しい必要があるため、$k$、平等が得られます$s[i] = s[i+m]$。 これは重要な単純化です。文字列全体がステップ付きの独立したチェーンに強制されます。$m$。 

したがって、ウィンドウの観点から考える代わりに、問題を次のように変換します。$m$独立したシーケンス: インデックスが一致するモジュロを持つ位置$m$一貫性がなければなりません。 このようなチェーンはそれぞれ約固定長です。$n/m$、各チェーン内では、すべての値が同一であるか、反転後の最初の文字列によって引き起こされる強制パターンに従う必要があります。 

分解すると、問題は各剰余クラスについて、最終構成ですべて 0 にするかすべて 1 にするかを決定することになります。同時に、ウィンドウごとの合計数の制約を尊重し、正確に選択することになります。$k$周期性により、すべてのウィンドウで一貫性が保たれます。 

この場合、反転操作は古典的なコスト構造になります。各チェーンのセグメントを変換する必要があり、最適な戦略は、最小の反転を計算して各チェーンを均一にし、グローバル制約の下でチェーン全体の選択肢を結合することです。 これにより、各クラスが 0 または 1 に設定されるコストを持つ残差クラスに対する DP が発生します。

 ## アルゴリズムのチュートリアル

 重なり合う制約によって暗示される周期構造を利用して、ソリューションを構築します。 

1. 各ポジションごと$i$、それが剰余クラスに属していることがわかります。$i \bmod m$。 同じクラス内のすべてのポジションは、有効な構成において一貫して動作する必要があります。 これは、隣接するウィンドウの比較から直接得られ、位置距離の等価性を強制します。$m$別に。 
2. 各残基クラスについて$c$、位置のシーケンスを抽出します$c, c+m, c+2m, \dots$。 分離可能性を壊すような方法で異なるチェーンの要素を混合するウィンドウがないため、これらは独立したチェーンを形成します。 
3. チェーンごとに、そのチェーン内のすべての要素を 0 に等しくするコストと、それらをすべて 1 に等しくするコストを計算します。チェーン内の反転セグメントは、最小限の操作で均一のターゲットに一致するように常に最適に配置できるため、このコストは単に初期文字列との不一致の数です。 
4. 次に、ウィンドウ制約を再解釈します。 どの長さでも-$m$ウィンドウには正確な値が必要です$k$すべてのウィンドウには各残基クラスからの要素が 1 つだけ含まれているため、最終的な代入では正確に選択する必要があります。$k$値 1 が割り当てられる剰余クラスと、残りのクラス$m-k$クラスは0になります。 
5. したがって、ナップサックスタイルの DP を実行します。$m$残留クラス。 させて$dp[j]$正確に選択するための最小コストであること$j$これまでに処理されたクラスの中からクラスを選択します。 各クラスについて、0 または 1 に割り当てて遷移し、対応するコストを追加します。 
6. 答えは次のとおりです。$dp[k]$、正確に選択する必要があるため、$k$クラスは 1 つになります。 

微妙なのは、剰余クラスへの分解によって、グローバルに重複する制約がローカルな組み合わせ選択問題に変わるということです。 このステップがなければ、DP は依然として高度にもつれた状態空間上にあることになります。 

### なぜ効果があるのか

 正確さは、すべての位置が同じインデックスモジュロを持つという不変式に依存します。$m$有効な最終文字列内で同一である必要があります。 これにより、すべてのウィンドウ制約が、割り当てられる剰余クラスの数に関する制約 1 に減ります。すべてのウィンドウには、各クラスの代表が 1 つだけ含まれるため、ウィンドウごとの 1 の数は、1 として選択されたクラスの数に等しくなります。したがって、グローバル制約は、独立項目に対する固定カーディナリティ制約となり、これはまさに DP が強制するものになります。 コスト構造はクラス間で加算されるため、最適な下部構造が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m, k = map(int, input().split())
        s = input().strip()

        cost0 = []
        cost1 = []

        # compute cost per residue class
        for r in range(m):
            c0 = 0
            c1 = 0
            for i in range(r, n, m):
                if s[i] == '1':
                    c0 += 1
                else:
                    c1 += 1
            cost0.append(c0)
            cost1.append(c1)

        INF = 10**18
        dp = [INF] * (m + 1)
        dp[0] = 0

        for i in range(m):
            ndp = [INF] * (m + 1)
            for j in range(i + 1):
                if dp[j] == INF:
                    continue
                ndp[j] = min(ndp[j], dp[j] + cost0[i])
                ndp[j + 1] = min(ndp[j + 1], dp[j] + cost1[i])
            dp = ndp

        print(dp[k])

if __name__ == "__main__":
    solve()

その後、DP は正確に選択します$k$値 1 を割り当てるクラス。各遷移は、クラスの最終状態の決定に対応します。 クラスの数が 1 つだけであるため、2 次元 DP は小さく保たれます。$m$までのカウントのみを追跡します。$k$。 

微妙な実装の詳細は、DP 更新の方向です。まだ必要な状態の上書きを避けるために、クラスごとに新しい配列を構築します。 これにより、同じ反復内で部分的に更新された状態が誤って再利用されることが防止されます。
