 ## 問題の理解

 文字列が 2 つあります。`s1`そして`s2`。 最初の文字列はコピーされるべきテキストであり、2 番目の文字列は実際に書き込まれたテキストです。 コピー中には、文字を省略すること、または文字を別の文字に置き換えることの 2 種類の間違いが許容されます。 私たちは、そのような間違いを最小限に抑える必要があります。`s1`の中へ`s2`。 

2 つの操作の区別が重要です。 新しい文字を挿入することはできません`s1`。 その結果、`s2`を超えることはできません`s1`、そしてこの問題は、指定されたペアがこれらのルールの下で有効であることを保証します。 どの 2 文字が含まれているかに関係なく、置き換えると 1 つのエラーが発生し、1 文字を省略すると 1 つのエラーも発生します。 

どちらの文字列の長さも最大 1024 です。したがって、二次アルゴリズムは最大で約 100 万回の状態遷移を実行しますが、これは 1 秒の制限内で簡単に管理できます。 ただし、文字列を整列させるために可能なすべての方法を指数関数的に検索すると、この短い長さでも不必要にコストがかかることになります。 

不注意な実装が不正確になる可能性がある境界ケースがいくつかあります。 文字列がすでに等しい場合、たとえば、```

```答えは`0`。 文字がスキップされる可能性を考慮せずに文字が異なる位置をカウントする実装は、ここでは問題ありませんが、より一般的なケースでは失敗します。

## アプローチ

 最も直接的な総当たりのアイデアは、2 つの文字列間の可能なすべてのアラインメントを列挙することです。 現在の文字が等しい場合、それらを一致させることができます。 それらが異なる場合、いくつかの可能性があります。現在の文字を置き換えます。`s1`、またはそれを削除して、同じ文字との一致を試みます。`s2`～の後の立場に対して`s1`。 これらの選択肢を再帰的に検討することは正しいことです。なぜなら、すべての有効な間違いのシーケンスが、このデシジョン ツリーを通る 1 つのパスに対応しているからです。 

このアプローチの問題は、同じサフィックスに何度も到達することです。 多くのミスマッチを含む配列は、置換と欠失の間で繰り返し分岐する可能性があります。 最悪のケースでは、再帰パスの数はおよそ次のように指数関数的に増加します。`O(2^n)`ある長さの文字列の場合`n`。 と`n = 1024`、それはまったく不可能です。 

重要な観察は、部分問題の結果は 2 つの立場にのみ依存し、そこに至る歴史全体には依存しないということです。 最初の処理がすでに完了しているとします。`i`の登場人物`s1`そして最初の`j`の登場人物`s2`。 これらのポジション以前のすべてが完了しているため、関連する情報はペアのみです。`(i, j)`。 

これにより、問題は動的プログラミングに変わります。 させて`dp[i][j]`最初の変換に必要なエラーの最小数になります。`i`の登場人物`s1`最初に`j`の登場人物`s2`。 

州から`(i, j)`, 現在のキャラクターを終了するには 3 つの方法があります。 マッチングできるよ`s1[i-1]`と`s2[j-1]`等しい場合、または置き換える場合はコストがかかりません`s1[i-1]`と`s2[j-1]`異なる場合は 1 つかかります。 削除することもできます`s1[i-1]`に移動します。`(i-1, j)`1つかかります。 

への挿入に対応するトランジションはありません`s1`なぜなら、挿入は許される間違いの一つではないからです。 これが、通常の完全な編集距離の問題との唯一の大きな違いです。 

ブルートフォース再帰が機能するのは、これらと同じ選択肢を明示的に探索するためです。 動的プログラミングは、多くの異なる再帰的パスが同じに到達することを単純に認識します。`(i, j)`を状態にして、その最良の回答を 1 回保存します。

 ## アルゴリズムのチュートリアル

 1. しましょう`n = len(s1)`そして`m = len(s2)`。 DP テーブルを作成します。`dp[i][j]`変換に必要なエラーの最小数を表します`s1[:i]`の中へ`s2[:j]`。 
2.初期化`dp[0][0] = 0`。 空のプレフィックスを別の空のプレフィックスに変換する場合、間違いは必要ありません。 
3. 最初の列を次のように初期化します。`dp[i][0] = i`。 ターゲットのプレフィックスが空の場合、最初のすべてのプレフィックスが`i`の登場人物`s1`削除する必要がありますので、正確に`i`エラーは必要です。 
4. 最初の行を次のように初期化します。`dp[0][j]`誰にとっても不可能なこと`j > 0`。 挿入は許可されていない操作であるため、空のソース文字列から空でないターゲットを生成することはできません。 これらの状態は非常に大きな値で表すことができます。 
5. すべての状態を処理する`(i, j)`と`i >= 1`そして`j >= 1`。 まず、現在のキャラクターを両方消費することを検討してください。 もし`s1[i-1] == s2[j-1]`、これにより追加のエラーは発生しません。 それ以外の場合、ある文字を別の文字に置き換えるには 1 コストかかります。 
6. 削除も検討してください`s1[i-1]`。 これにより、状態が次のように変化します。`(i, j)`に`(i-1, j)`エラーが 1 つ追加されます。 
7. 文字の一致または置換と削除のコストのうち、小さい方のコストを計算します。 結果の値が次の最適な答えになります。`dp[i][j]`。 
8. テーブルを埋めたら、出力します。`dp[n][m]`これは、最初の文字列全体を 2 番目の文字列全体に変換することを表します。 

### なぜ効果があるのか

 不変条件とは、`dp[i][j]`最初のエラーを正確に変換するために、可能な最小数のエラーを常に保存します。`i`の登場人物`s1`まさに最初の部分に`j`の登場人物`s2`。 

状態に最適な変換を検討する`(i, j)`。 その最後のアクションは、最後の文字を両方とも消費する (つまり、それらが一致するか、一方が他方に置き換えられることを意味します) か、ソース プレフィックスの最後の文字を削除する必要があります。 これらはまさに再発によって考慮された遷移です。 各遷移は最終操作のコストを正確に追加し、前の状態自体が DP 不変式によって最適であるため、遷移全体で最小値を取ると、次の最適値が得られます。`(i, j)`。 基本ケースは、空のプレフィックスを含むすべての変換をカバーするため、不変式はテーブル全体に適用され、最終状態は必要な最小値になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s1 = input().strip()
    s2 = input().strip()

    n = len(s1)
    m = len(s2)

    INF = n + m + 1

    dp = [[INF] * (m + 1) for _ in range(n + 1)]
    dp[0][0] = 0

    for i in range(1, n + 1):
        dp[i][0] = i

    for i in range(1, n + 1):
        for j in range(1, m + 1):
            cost = 0 if s1[i - 1] == s2[j - 1] else 1

            # Match the two characters, or replace s1[i - 1].
            dp[i][j] = dp[i - 1][j - 1] + cost

            # Delete s1[i - 1].
            dp[i][j] = min(dp[i][j], dp[i - 1][j] + 1)

    print(dp[n][m])

if __name__ == "__main__":
    solve()
```最初の 2 つの入力行には 2 つの文字列が含まれているため、`strip()`末尾の改行を削除するには十分です。 入力形式に複数のテスト ケースはありません。 

DP テーブルには、`(n + 1) * (m + 1)`州。 最初の列は次のように初期化されます`i`なぜなら変換しているから`s1[:i]`空の文字列にするには、すべてを削除する必要があります`i`文字。 

最初の行はそのまま残ります`INF`を除いて`dp[0][0]`。 これは意図的なものです。 削除と置換のみを使用して空のソースから正の長さのターゲットを構築することはできません。 明示的に不可能な値を使用すると、偶発的な遷移による挿入操作の発生を防ぐことができます。 

通常の状態ごとに、`cost`は 0 または 1 のいずれかです。 現在のキャラクターが同意する場合、両方を消費してもコストはかかりません。 一致しない場合は、両方を消費すると 1 回の交換に相当します。 2 番目のトランジションでは、現在のソース キャラクタが削除され、ターゲットの位置は変更されないままになります。 

インデックスが使用するのは、`i - 1`そして`j - 1`なぜなら`dp[i][j]`長さの接頭辞を説明します`i`そして`j`。 これは、実装におけるオフバイワンの主な詳細です。 Python の整数にはオーバーフローの問題はなく、意味のある最大の答えは最大でも`n`、有効な入力によって次のことが保証されるため、`s2`から文字を削除し、文字を置換することで取得できます。`s1`。

ab
