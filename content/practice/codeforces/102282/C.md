 ## 解決策
 ## 問題の理解

 カタツムリは高さ 0 からスタートし、高さが 3776 メートルに固定されている富士山に登ります。 毎日、正確に上昇します`n`メートル。 登っても頂上に到達できなかった場合は、次の夜に滑り落ちます。`m`メートル。 問題は、カタツムリが高さ 3776 に達するまでに何日かかるのか、それとも決して到達できないのかということです。 

入力には日中の登りが含まれています`n`そして夜の滑り台`m`。 どちらの値も (10^9) まで大きくすることができますが、山の高さ自体はわずか 3776 です。出力は、カタツムリが頂上に到達した最初の日、または単語のいずれかです。`NEVER`。 

大きな境界は、`n`そして`m`複雑なデータ構造や反復アルゴリズムを強制しないでください。 実際、山の高さは非常に小さく固定されているため、毎日の直接シミュレーションでも、最も遅い場合でも最大 3776 回の登山が実行されます。`n = 1`そして`m = 0`。 1 秒の制限としては非常に小さいです。 それでも、算術ソリューションはより単純であり、一定時間で実行されます。 

単純な式が間違っている可能性がある境界ケースがいくつかあります。 もし`n >= 3776`、カタツムリは初日に頂上に到達します。 たとえば、`3776 100`、答えは`1`, なぜなら、カタツムリは最初の日中の登山中に高さ3776に到達し、山で一晩過ごすことがないからです。 

もし`n <= m`そして`n < 3776`、カタツムリは頂上に向かって永久に前進することはできません。 例えば、`5 5`与える`NEVER`。 昼と夜のサイクルが完了するたびに、カタツムリは同じ高さに戻ります。 と`5 6`、各サイクル後にさらに身長が失われます。 

もう 1 つのよくある間違いは、最後の登りを個別に処理せずに、正味の毎日の進行状況の計算式を適用することです。 のために`5 4`、完全な昼夜を経た後の正味の進歩はわずか1メートルですが、カタツムリは最後の日中の登りで頂上に到達し、その後滑り落ちることはありません。 正解は 3776 ではなく 3772 です。 

ケース`n = 0`も不可能な部類に属します。 例えば、`0 0`生成する`NEVER`、カタツムリは開始高さを決して離れることがないためです。 

## アプローチ

 単純な解決策はカタツムリをシミュレートします。 高さゼロから開始して繰り返し追加します`n`。 新しい高さが少なくとも 3776 であれば、現在の日が答えになります。 それ以外の場合は減算します`m`夜を表し、翌日に続きます。 これは物理的なプロセスに正確に従うため、その正しさはすぐにわかります。 

シミュレートされる最大日数はわずか 3776 日です。考えられる最も遅い登山ケースは次のとおりです。`n = 1, m = 0`したがって、ブルートフォース手法は最大 3776 回の反復を実行しますが、これは 1 秒の競技プログラミング プログラムが処理できる反復回数をはるかに下回ります。 (10^9) の巨大な上限`n`そして`m`この反復回数は増加しません。`n`カタツムリの終了が早くなるだけです。 

算術的な解決策は、完全な昼夜のサイクルを最終日から分離することで得られます。 最後の登りの前には、カタツムリは常に頂上の下にいます。そのため、丸一日とそれに続く夜では、カタツムリの高さは次のように変化します。`n - m`。 もし`n <= m`、その変化はプラスではなく、カタツムリが初日にすぐに頂上に到達しない限り、頂上に到達することは不可能です。 

仮定する`n > m`そして`n < 3776`。 後`k`昼も夜も完全にカタツムリは最高潮に達しています

 [
 k(n-m)。 
】

 次の日中の登山で頂上に到達するまでに必要な完全なサイクルの最小数は次のとおりです。 

[
 k(n-m) + n \ge 3776.
 】

 同様に、

 [
 k(n-m) \ge 3776-n。 
】

 そのような最小のもの`k`です

 [
 k = \left\lceil \frac{3776-n}{n-m} \right\rceil。 
】

 最後の登りは翌日なので、答えは`k + 1`。 

上限除算は次のように整数演算で実行できます。`(a + b - 1) // b`ポジティブな`a`そして`b`。 ここでそれは与えます

 [
 \frac{3776-n + (n-m)-1}{n-m}
 】

 整数の除算を使用します。 

2 つのアプローチには次のような複雑さがあります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(3776)、実質的には O(1) | お(1) | 承認済み |
 | 最適 | お(1) | お(1) | 承認済み |

 算術バージョンは、基礎となる推論を直接表現し、シミュレートされた高さを維持する必要がないため、推奨されます。 

## アルゴリズムのチュートリアル

 1.読む`n`そして`m`。 昼の登りと夜の滑りです。 
2. もし`n >= 3776`、印刷`1`。 カタツムリは最初の登山中に頂上に到達するため、夜間の移動を考慮する必要はありません。 
3. もし`n <= m`、印刷`NEVER`。 以来`n < 3776`前回のチェックの後、カタツムリは初日に頂上に到達することはできません。 完全な昼夜のサイクルごとに、その高さは次のように変化します。`n - m <= 0`, したがって、長期的には決して頂上に近づくことはできません。 
4. それ以外の場合は、1 つの完全な昼夜サイクルの純利益を次のように計算します。`n - m`。 この値は正であるため、サイクルを繰り返すと最終的にカタツムリは十分な高さまで移動します。 
5. 最後の登りまでに必要な完全なサイクル数を次のように計算します。`cycles = (3776 - n + (n - m) - 1) // (n - m)`。 

分子は、日中に 1 回登った後にまだ不足している高さを表し、天井分割は、その不足している高さをカバーできる最小の全サイクル数を見つけます。 
6. 印刷`cycles + 1`。 追加のものは、カタツムリが実際に頂上に到達する最後の日中の登山です。 

### なぜ効果があるのか

 重要な不変条件は、カタツムリがまだ頂上に到達していない間、完全な昼と夜が終わるたびに、その高さが正確に増加するということです`n - m`。 いつ`n <= m`、この増加は正ではないため、一連の完全なサイクルによってカタツムリが初日に到達できなかった高さに到達することはできません。 いつ`n > m`、 後`cycles`サイクルを完了すると高さが正確になります`cycles * (n - m)`、選択された天井分割により、これが日中の登りをもう 1 つ追加すると 3776 に達する最小サイクル数になります。最終日には次の夜がないため、答えは正確に次のようになります。`cycles + 1`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

HEIGHT = 3776

def solve():
    n, m = map(int, input().split())

    if n >= HEIGHT:
        print(1)
        return

    if n <= m:
        print("NEVER")
        return

    gain = n - m
    remaining = HEIGHT - n

    cycles = (remaining + gain - 1) // gain
    print(cycles + 1)

if __name__ == "__main__":
    solve()
```定数`HEIGHT`固定の頂上の高さを保存します。これにより、数式が読みやすくなり、コード内で値 3776 が散乱するのを防ぎます。 

最初の条件は、不可能条件の前にチェックする必要があります。 もし`n`少なくとも 3776 の場合、カタツムリは次の場合でもすぐに成功します。`m`よりもはるかに大きいです`n`。 例えば、`3776 1000000000`まだ答えがある`1`、夜間の滑りはカタツムリがすでに頂上に到達した後にのみ発生するためです。 

初日の成功例を除外した後、`n <= m`すべての全サイクルで非前向きな進歩があることを意味します。 カタツムリは頂上を目指していつまでも登ることができないので、`NEVER`は正しいです。 

残りのケースについては、`gain`厳密にポジティブです。 変数`remaining`最初の日中の登山後にまだ必要な距離です。 天井分割では、その距離をカバーするために必要な完全なサイクルの数がわかります。 決勝戦`+ 1`これらのサイクルが完了した後に発生する日中の上昇を説明します。 

Python の整数には任意の精度があるため、入力値が (10^9) に達しても、オーバーフローの問題は発生しません。 また、計算では全体で整数演算が使用され、浮動小数点の丸めの問題が回避されます。 

## 実用的な例

 最初のサンプルでは、`n = 5`そして`m = 4`。 カタツムリは昼夜サイクルを完了するたびにわずか 1 メートルしか上がらず、十分な回数のサイクルの後、次の日中の上昇で頂上に到達します。 

| 日の状態 | 登る前の高さ | 日帰り登山 | 上昇後の高さ | ナイトスライド |
 | --- | --- | --- | --- | --- |
 | 1 | 0 | +5 | 5 | -4 |
 | 2 | 1 | +5 | 6 | -4 |
 | 3 | 2 | +5 | 7 | -4 |
 | ... | ... | ... | ... | ... |
 | 3772 | 3771 | +5 | 3776 | なし |

 式は次のようになります`gain = 1`そして`remaining = 3771`。 したがって`cycles = 3771`、そして最終的な答えは`3772`。 最終日は、カタツムリが頂上に到着するとすぐに止まるため、以前の日とは異なる扱いを受けます。 

2 番目のサンプルについては、`n = 100`そして`m = 200`。 

| チェック | 値 | 結果 |
 | --- | --- | --- |
 |`n >= 3776`| 100 >= 3776 | 偽 |
 |`n <= m`| 100 <= 200 | 本当 |
 | 出力 | |`NEVER`|

 カタツムリは日中は 100 メートル進みますが、夜になると 200 メートル減ります。 正味の進歩はマイナスであるため、サイクルを繰り返しても頂上に近づくことはできません。 アルゴリズムは、シミュレーションを実行せずにこれを即座に検出します。

 ## 特殊なケース

 のために`0 0`、初日の状態`n >= 3776`は誤りであり、かつ`n <= m`それは本当です。 アルゴリズムは出力します`NEVER`。 シミュレーションでは高さが永久にゼロのままになるため、結果は一貫しています。 

のために`3776 1000000000`、カタツムリは最初の日中の移動中に正確に頂上まで登ります。 アルゴリズムは出力します`1`かどうかを確認する前に`n <= m`。 すでに頂上に到達してしまえば、夜間の大規模な滑り台は関係ないので、この順序は重要です。 

のために`1 0`、毎日1メートル貢献し、夜間の滑り台はありません。 カタツムリは 3776 日目に 3776 メートルに到達します。式は次のとおりです。`gain = 1`、`remaining = 3775`、 それで`cycles = 3775`そして結果は`3776`。 これは、固定された山の高さに対する可能な最大の答えです。 

のために`10 10`、完了した昼夜サイクルはすべて、純変化がゼロになります。 カタツムリは初日にわずか 10 メートルに達するため、3776 メートルに到達することはありません。`n <= m`条件は除算の前にこのケースを検出し、分母がゼロになることも防ぎます。 

のために`5 4`、カタツムリは 3772 日目に頂上に到達します。この式では、完全なサイクルに対してのみ 1 メートルの純ゲインが使用され、その後、日中の最後の登りが個別に追加されます。 毎日を完全なサイクルとして扱うと、サミット後の夜間の滑りを誤ってカウントし、間違った答えが生成されてしまいます。
