 ## 問題の理解

 入力は、頂点が人々であり、エッジが「真の友人」である人々のペアを表す無向グラフを記述します。 会社は確実につながっています。つまり、どのペアの人たちの間にも真の友人関係が連鎖することになります。 

その頂点を削除し、そのすべてのインシデントエッジが残りのグラフを切り離すとき、人はまさに会社の魂です。 標準的なグラフ用語では、このような頂点は関節点、またはカット頂点です。 

接続されたグラフのすべての関節点を見つけて、その番号を昇順に出力する必要があります。 何もない場合、最初の行は次のようになります。`0`そして 2 行目は空です。 

限界は`n <= 10^4`そして`m <= 10^5`。 グラフのサイズに比例するアルゴリズムは容易に適していますが、頂点ごとにグラフの走査を繰り返すアルゴリズムも潜在的に存在します。`10^4 * 10^5 = 10^9`十分な密度の入力でのエッジ操作。 1 秒という制限があるため、このアプローチは遅すぎます。 ターゲットは近くにあるはずです`O(n + m)`。 

誤って対処しやすい特殊なケースがいくつかあります。 可能な限り小規模な会社を考えてみましょう。```
2 1
1 2
```どちらかの人物を削除すると、頂点が 1 つだけ残り、接続されたグラフのままになります。 正しい出力は次のとおりです。```

```不注意な実装では、単に子があるというだけの理由で、DFS のルートをアーティキュレーション ポイントとして分類する可能性があります。 ルートがアーティキュレーション ポイントになる前に、ルートには少なくとも 2 つの DFS の子が必要です。 

もう 1 つの重要なケースはスターです。```

1 2
1 3
1 4
1 5
```正しい出力は次のとおりです。```

```頂点の削除`1`4 つの孤立した頂点が残りますが、リーフを削除すると、接続された星形が残ります。 頂点に低次の近傍があるかどうかだけをチェックしても、問題は解決されません。

## アプローチ

 直接的な解決策は、すべての人を個別に削除してみることです。 候補頂点ごとに、それを一時的に無視し、残りの頂点から DFS または BFS を実行し、まだ到達できる頂点の数をカウントします。 もしすべてなら`n - 1`頂点は到達可能ですが、候補者は魂ではありません。 それ以外の場合は、アーティキュレーションポイントです。 

これは正しいです。なぜなら、魂の定義は、人を取り除くとグラフが切断されるというものだからです。 1 回のトラバーサルでは、1 つの特定の削除後に接続がチェックされるため、すべての頂点を試行すると、考えられるすべての候補がチェックされます。 

問題は繰り返し作業です。 1 回の走査にかかるコスト`O(n + m)`まで実行します。`n`頂点、与える`O(n(n + m))`。 最大制限では、これはおおよそに達する可能性があります`10^4 * (10^4 + 10^5) = 1.1 * 10^9`頂点とエッジの訪問。 グラフも概念的にのみ繰り返し保存されますが、時間コストだけを考えるとこれは不適切です。 

重要な観察は、これらすべての削除実験がほぼ同じ質問をしているということです。 1 回の DFS 中に頂点を考慮します`u`およびその DFS サブツリーの 1 つがルートとなります`v`。 私たちが知る必要があるのは、そのサブツリーに、元に戻る何らかのエッジがあるかどうかだけです。`u`またはその先祖に`u`。 そうでない場合は、削除します`u`サブツリー全体をグラフの残りの部分から分離します。 

これは標準の DFS 値で要約できます。`tin[u]`そして`low[u]`。`tin[u]`の瞬間です`u`初めて訪問されました。`low[u]`から到達可能な最小の検出時間です。`u`0 個以上の DFS ツリー エッジを通過し、ツリー エッジではないエッジを最大 1 つ使用します。 

非ルート頂点の場合`u`、DFS の子`v`～の先祖から切り離されている`u`まさにいつ`low[v] >= tin[u]`。 このような子サブツリーには、バイパスできるエッジがありません。`u`、削除します`u`そのサブツリーを切断します。 

DFS ルートは特殊なケースです。 先祖がいないので、`low`比較はその状況を表しません。 ルートに少なくとも 2 つの DFS の子がある場合、ルートは正確にアーティキュレーション ポイントになります。 子が 1 つある場合、それを削除すると、DFS ツリー全体がその 1 つの子を介して接続されたままになります。 

ブルート フォースは、削除のたびにグラフを明示的にテストするため機能しますが、同じ接続情報が何千回も再計算されると失敗します。 の`tin`そして`low`これらの値を使用すると、1 つの DFS がこれらすべての削除に関する質問に同時に回答できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |`O(n(n + m))`|`O(n + m)`| 遅すぎる |

 ## アルゴリズムのチュートリアル

 1. 無向グラフの隣接リストを作成します。 各入力エッジ`(x, y)`両方に挿入されます`graph[x]`そして`graph[y]`, なぜなら友情は対称的だからです。 
2. 頂点から DFS を実行する`1`。 入力はグラフが接続されていることを保証するため、1 つの DFS がすべての頂点に到達します。 増加する検出時間を割り当てます`tin[u]`各頂点が最初に入ったとき。 
3. 頂点の処理中`u`、初期化します`low[u] = tin[u]`。 これは、他のエッジを考慮する前に、`u`発見時に自分自身に到達できる`tin[u]`。 
4. すべての隣人のために`v`の`u`、ツリーのエッジをすでに訪問したエッジから区別します。 もし`v`訪問されていないため、DFS を再帰的に実行します`v`。 再帰が終了したら、更新します`low[u]`と`low[v]`なぜなら、サブツリーから到達可能なすべての頂点は、`v`からもアクセス可能です`u`DFS ツリーのエッジを通過`u -> v`。 
5. DFS のすべての子供に対して`v`非ルート頂点の`u`、どうかを確認してください`low[v] >= tin[u]`。 この条件が当てはまる場合は、マークを付けます`u`アーティキュレーションポイントとして。 この不等式は、次のことを示します。`v`の厳密な祖先には到達できません`u`、 それで`u`これは、そのサブツリーから残りの DFS ツリーへの唯一の接続です。 
6. 訪問したネイバーが直接の親エッジではない場合、更新`low[u]`使用して`tin[v]`。 このようなエッジは、すでに発見された頂点に対するバックエッジであり、その発見時間は、現在のサブツリーがどこまで上方に逃げることができるかを表します。 
7. すべてのルートの DFS の子を数えます。 ルートに少なくとも 2 つの子がある場合は、それをアーティキュレーション ポイントとしてマークします。 ルートには親がなく、したがってその子がバイパスできる祖先も存在しないため、別のルールが必要です。 
8. 最後に、頂点をスキャンします。`1`を通して`n`。 マークされたすべての頂点をその順序で印刷すると、必要な昇順が自動的に与えられます。 

### なぜ効果があるのか

 中心的な不変条件は、DFS が頂点の処理を終了した後、`u`、`low[u]`から到達可能な最小の検出時間です。`u`の親エッジを通過しない のサブツリー`u`。 DFS の子を検討してください`v`の`u`。 もし`low[v] < tin[u]`、をルートとするサブツリー`v`～の祖先に達するエッジを持っている`u`、削除します`u`そのサブツリーは分離されません。 もし`low[v] >= tin[u]`、そのようなバイパスは存在しないため、そのサブツリーからその外側の頂点までのすべてのパスは通過する必要があります。`u`。 したがって`u`は、ルートを除いて、この条件が一部の子に当てはまるときのアーティキュレーション ポイントです。正しい条件は、少なくとも 2 つの子を持つことです。 

すべてのエッジは、この 1 つの DFS 中に隣接リストを通じてのみ検査されるため、同じ走査ですべてのアーティキュレーション ポイントが同時に決定されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    graph = [[] for _ in range(n + 1)]

    for _ in range(m):
        u, v = map(int, input().split())
        graph[u].append(v)
        graph[v].append(u)

    tin = [0] * (n + 1)
    low = [0] * (n + 1)
    is_cut = [False] * (n + 1)

    timer = 0

    sys.setrecursionlimit(2 * n + 10)

    def dfs(u, parent):
        nonlocal timer

        timer += 1
        tin[u] = timer
        low[u] = timer

        children = 0

        for v in graph[u]:
            if v == parent:
                continue

            if tin[v] == 0:
                children += 1
                dfs(v, u)

                low[u] = min(low[u], low[v])

                if parent != 0 and low[v] >= tin[u]:
                    is_cut[u] = True
            else:
                low[u] = min(low[u], tin[v])

        if parent == 0 and children >= 2:
            is_cut[u] = True

    dfs(1, 0)

    answer = [u for u in range(1, n + 1) if is_cut[u]]

    print(len(answer))
    print(*answer)

if __name__ == "__main__":
    solve()

の`tin`配列は訪問された配列としても機能します。 値がゼロの場合は、頂点がまだ検出されていないことを意味します。 一度割り当てられると、`tin[v]`は固定 DFS 検出時間であり、バック エッジを処理するときに正確に必要な値です。 

いつ`v`未訪問のネイバーである場合、DFS の子になります。 再帰呼び出しは更新する前に終了する必要があります`low[u]`、 なぜなら`low[v]`のサブツリー全体の後でのみ知られます`v`処理されています。 

訪問済みの近隣の場合、コードは次を使用します。`tin[v]`それよりも`low[v]`。 エッジ`(u, v)`直接の非ツリー エッジであるため、すでに検出されている頂点へのルートを提供します`v`; 許可する`low[v]`ここには、別のサブツリーからの情報が誤って含まれてしまいます。 

の`v == parent`チェックも必要です。 無向隣接リストでは、ツリー エッジから`u`その親に対しては、隣接するものとして表示されます。`u`。 そのエッジをバックエッジとして扱うと、誤って減少します`low[u]`。 

Python の再帰は実装上の主な懸念事項です。 パス グラフには次のものを含めることができます`10^4`DFS 再帰の深さが到達できるように頂点`10^4`。 再帰制限を上げると、Python のデフォルトの再帰深さの制限が回避されます。 検出時間は最長で 1 時間であるため、整数オーバーフローの問題はありません。`n`。

1 2
```DFS の開始時刻`1`、発見する`2`と返します。 ルートには子が 1 つだけあるため、ルート条件は`children >= 2`は誤りです。 頂点`2`削除すると頂点だけが残るため、カットされた頂点でもありません`1`。 答えは`0`。 

スターのために```
5 4
1 2
1 3
1 4
1 5
```頂点`1`は DFS ルートであり、4 つの子があります。 ルート条件により、それがアーティキュレーション ポイントとして直ちにマークされます。 各リーフには DFS の子がないため、非ルート条件を満たすものはありません。 結果はまさに頂点です`1`。 

完全なグラフについては```
4 6
1 2
1 3
1 4
2 3
2 4
3 4
```すべての DFS サブツリーには、前の頂点へのバック エッジがあります。 したがって、すべての非ルート候補について`u`、関連する各子は`low[child] < tin[u]`。 ルート以外の頂点はマークされず、残りの頂点は最初の子を経由して到達するため、ルートには DFS の子が 1 つだけあります。 答えは`0`。 

最大サイズのチェーンのグラフは次のようになります。```
10000 9999
1 2
2 3
3 4
...
9999 10000
```バックエッジがないため、すべての内部頂点に対して`u`、その子は満足します`low[child] = tin[child]`より大きい`tin[u]`。 からのすべての頂点`2`を通して`9999`したがって、アーティキュレーションポイントになります。 頂点`1`そして`10000`いずれかのエンドポイントを削除すると、接続されたチェーンが残るため、そうではありません。 DFS の深さが次の値に達するため、実装により Python の再帰制限が引き上げられます。`10000`、最後のスキャンでは頂点が昇順に出力されます。
