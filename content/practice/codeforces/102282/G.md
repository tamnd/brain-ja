 ## 解決策
 ## 問題の理解

 建物はエントランス、フロア、アパートメントに分かれています。 すべての入り口には正確に含まれています`n`フロア、およびすべてのフロアに正確に含まれています`m`アパート。 アパートの数は、ある入り口から次の入り口へと継続的に増加します。最初の入り口にはアパートが含まれています`1`を通して`n*m`、2 番目には次のものが含まれます`n*m`アパートなど。 

アパート番号を教えてもらいました`k`。 タスクは 2 つのことを決定することです: アパートの入り口`k`、そしてその入り口の中にあるそれを含むフロア。 

たとえば、`n = 3`そして`m = 4`、1つの入り口には次のものが含まれます`3 * 4 = 12`アパート。 アパート`1..4`アパートの1階にあります`5..8`アパートの2階にあります`9..12`3階にあります。したがって、アパートです`10`3階エントランス1に属します。 

3 つの入力値はすべて次のように大きくできます。`10^9`。 したがって、アパート、フロア、または入り口を 1 つずつ検査するソリューションには、最大約 10 億回の反復が必要になる可能性があります。 1 秒という制限の下では、それは私たちが望むものをはるかに超えています。 番号付けの構造により直接の算術式が得られるため、目的のソリューションでは定数時間と定数メモリを使用する必要があります。 

最初の境界ケースは次のような場合です。`k`は正確に割り切れます`m`。 例えば、`n = 3, m = 4, k = 8`出力を与える`1 2`。 アパートメント 8 は、2 階の最後のアパートメントです。次のような不注意な公式`k / m + 1`除算はゼロから始まる位置に基づいていなければならないことを忘れているため、階 3 が生成されます。 

2 番目の境界ケースは次のような場合です。`k`まさに入り口の最後のアパートです。 のために`n = 3, m = 4, k = 12`、正しい出力は次のとおりです。`1 3`。 アパートメント 12 はまだ入口 1 に属しています。`k // (n*m) + 1`直接実行すると、誤って入口 2 が生成されます。 

3 番目のケースは、最初のアパートです。 のために`n = 1, m = 1, k = 1`、答えは`1 1`。 最初にアパート番号を変更せずに通常の除算を使用する式では、ゼロから始まる答えや余分な増分が生成される危険があります。 

## アプローチ

 直接的な総当たりソリューションにより、番号付けをシミュレートできます。 アパート 1 から始めて、現在の入り口と階を追跡し、毎回次の階に移動します。`m`アパートメントに移動し、毎回次の入り口へ`n`床。 かつてのアパート`k`に到達すると、格納された入り口とフロアが答えになります。 これが機能するのは、アパート番号の割り当てに使用されるのとまったく同じ順序に従っているためです。 

問題は反復回数です。 最悪の場合は考えてください`n = 1`、`m = 1`、 そして`k = 10^9`。 アパートメントは各フロアに 1 つあるため、シミュレーションではすべてのアパートメントを処理する必要があります。`10^9`目標に到達する前にアパート。 フロア全体をスキップするより効率的なシミュレーションを使用しても、最悪のケースでは依然として最大で`10^9`フロアまたはエントランスのトランジション。 これは 1 秒という競技プログラミングの制限には適していません。 

重要な観察は、すべての入り口に正確に含まれているということです。`n*m`アパート。 以前のすべての入口をシミュレートする代わりに、どのブロックがどのブロックであるかを直接尋ねることができます。`n*m`連続したアパート番号には次のものが含まれます`k`。 その入り口がわかれば、必要なのは位置だけです。`k`その入り口の中。 同じ考え方がフロアにも当てはまります。どのフロアにも正確に含まれています。`m`集合住宅の場合、玄関内の位置によって階数が整数1で決まります。 

すべての境界を処理する最もクリーンな方法は、以下を考慮してアパート番号を一時的にゼロベースにすることです。`k - 1`。 最初のアパートの位置は 0 になり、1 階の最後のアパートの位置は になります。`m - 1`、最初の入り口の最後のアパートには位置があります`n*m - 1`。 整数の除算と剰余は、目的のグループと正確に一致します。

 ## アルゴリズムのチュートリアル

 1. 1 つの入口にあるアパートの数を次のように計算します。`n * m`。 これにより、グローバル アパートの番号付けにおける 1 つの完全なエントランス ブロックのサイズが得られます。 
2. 交換する`k`と`k - 1`概念的に計算する`(k - 1) // (n * m) + 1`入り口用に。 0 から始まる位置を 1 つの入口ブロックのサイズで割ると、ターゲットの前に完全な入口ブロックが何個発生するかがわかり、1 を加算すると、0 から始まるブロック インデックスが 1 から始まる入口番号に変換されます。 
3. コンピューティング`(k - 1) % (n * m)`アパートのゼロベースの位置を取得するには`k`その入り口の中。 残りは、ターゲットの前のすべての完全な入り口を破棄します。 
4. その位置を次の値で割ります。`m`そして次の 1 つを追加します。`(position_inside_entrance // m) + 1`。 あらゆるグループの`m`連続するポジションは 1 つのフロアに属するため、商は 0 から始まるフロアを識別します。 
5. 入口番号とフロア番号を印刷します。 

### なぜ効果があるのか

 しましょう`p = k - 1`。 各入り口には正確に含まれているため、`n*m`アパート、商`p // (n*m)`正確には、アパートの前に完成した入り口の数です`k`。 したがって、1 を追加すると正しい入り口が得られます。 残り`p % (n*m)`は、その入り口内のアパートのゼロベースの位置です。 各フロアに正確に含まれているため、`m`アパートメント、この余りをで割ります`m`はアパートメントの前の完全なフロア数を示し、1 を追加すると 1 ベースのフロアが得られます。 どちらの計算でも同じゼロベースの位置が使用されるため、フロアと入り口の端にあるアパートメントは正しいグループに割り当てられます。

入口の計算では、完全な入口サイズによる整数除算が使用されます。 床の計算では、まず入口内の剰余を取得し、次に次の値で割ります。`m`。 階数は現在の入り口内の位置のみに依存し、その前のすべてのアパートメントには依存しないため、順序が重要です。

## 実用的な例

 サンプル 1 の入力は次のとおりです。`3 4 10`。 それぞれの入り口には、`3 * 4 = 12`アパート。 ターゲットは 10 番目のアパートメントであるため、そのゼロベースの位置は 9 です。

サンプル 2 の入力は次のとおりです。`5 2 20`。 それぞれの入り口には、`5 * 2 = 10`アパート。 アパートメント 20 には、ゼロから始まる位置 19 があります。

 商`19 // 10`は 1 で、入口 2 になります。残りは 9 で、これがその入口の最後の位置です。 各フロアに2つのアパートメントがあるため、`9 // 2`は 4 で、床は 5 になります。結果は次のようになります。`2 5`。

## テストケース```python
import sys
import io

def solve():
    input = sys.stdin.readline
    n, m, k = map(int, input().split())

    apartments_per_entrance = n * m
    position = k - 1

    entrance = position // apartments_per_entrance + 1
    floor = (position % apartments_per_entrance) // m + 1

    print(entrance, floor)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()
    result = sys.stdout.getvalue().strip()

    sys.stdin = old_stdin
    sys.stdout = old_stdout

    return result

assert run("3 4 10\n") == "1 3", "sample 1"
assert run("5 2 20\n") == "2 5", "sample 2"

assert run("1 1 1\n") == "1 1", "minimum-size input"

    "large dimensions with target in the first entrance and first floor"
assert run("3 4 12\n") == "1 3", \

assert run("3 4 13\n") == "2 1", \

assert run("1000000000 1 1000000000\n") == "1 1000000000", \
    "target on the last floor when each floor has one apartment"

 ## 特殊なケース

 いつ`k`は最初のアパートメントであり、ゼロベースの位置はゼロです。 入力用`1 1 1`、エントランスブロックにはアパートが 1 つ含まれているため、`0 // 1 + 1 = 1`。 入口内の位置もゼロであり、`0 // 1 + 1 = 1`。 出力は`1 1`。 

いつ`k`がフロア上のアパートの数で正確に割り切れる場合、ターゲットは次のフロアではなく前のフロアにあります。 入力用`3 4 8`、ゼロベースの位置は 7 です。入口は`7 // 12 + 1 = 1`、床は`7 // 4 + 1 = 2`。 出力は`1 2`。 に直接基づく式`k // m`誤ってアパート 8 を 3 階に移動してしまいます。 

いつ`k`まさに入り口の最後のアパートであるため、ターゲットはその入り口に留まらなければなりません。 入力用`3 4 12`、ゼロベースの位置は 11 です。`11 // 12 = 0`、入口は 1 です。入口内の位置は 11 で、`11 // 4 + 1 = 3`したがって、出力は次のようになります`1 3`。 ゼロベースのシフトにより、境界が正しく動作します。 

いつ`k`入口境界の後の最初のアパートメントです。フロアを 1 にリセットする間、入口を増やす必要があります。入力の場合`3 4 13`、ゼロベースの位置は 12 です。`12 // 12 = 1`、したがって、入り口は 2 です。余りは 0 で、床が与えられます。`0 // 4 + 1 = 1`。 出力は`2 1`。 

最後に、大きな製品は算術上の問題を引き起こしてはなりません。 入力用`1000000000 1000000000 1000000000`、1つの入り口には次のものが含まれます`10^18`アパートのみを対象としていますが、`10^9`。 そのゼロベースの位置は、`999999999`、まだ最初の入り口と1階の中にあります。`999999999 // 1000000000 = 0`。 出力は`1 1`。 入り口には膨大な数のアパートが含まれているにもかかわらず、計算は一定時間です。
