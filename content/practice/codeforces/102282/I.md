 ## 解決策
 ## 問題の理解

 (n \times n) 個のグリッドがあります。 一部のセルには正の整数が含まれており、残りのセルにはゼロが含まれています。 すべての行とすべての列には、ゼロ以外のセルが 2 つだけ含まれている必要があります。 行 (i) の 2 つの数値の積は (y_i) に等しくなければなりませんが、列 (j) の 2 つの数値の積は (x_j) に等しくなければなりません。 グリッドに書き込まれるすべての数字は、他のすべての数字と異なっていなければなりません。 

入力は、(n)、(n) 個の必要な列積 (x_0,\ldots,x_{n-1})、(n) 個の必要な行積 (y_0,\ldots,y_{n-1}) で構成されます。 このステートメントは、有効なグリッドが少なくとも 1 つ存在することを保証するため、構築する必要があるのは 1 つだけです。 

グリッドを 2 部グラフとして表示するのに便利な方法です。 すべての行に 1 つの頂点を作成し、すべての列に 1 つの頂点を作成します。 ゼロ以外のセルは行と列の間のエッジとなり、セル内の数値がエッジのラベルになります。 すべての行と列に正確に 2 つの数値が含まれるため、すべての頂点の次数は 2 になります。 したがって、選択されたセルは偶数サイクルの集合を形成します。 各行または列に付随するラベルの積が規定されます。 

限界 (n \le 10) は、意図されたアプローチに関する主なシグナルです。 配置する数値は (2n \le 20) 個だけですが、その位置と値は行と列の両方で相互作用します。 任意のセルに対するブルート フォースは大きすぎますが、強制的な乗算構造に対する慎重なプルーニングによるバックトラッキング検索は十分に小さいです。 

商品数は最大1000個です。 これは、テーブルに配置されたすべての数値が、その数値を含む行の積を除算し、その列の積も除算するため、特に便利です。 したがって、すべての候補値は (1) から (1000) までの数の約数の範囲内にあり、ターゲットでは 2 つの異なる正の整数に因数分解できる可能性がほとんどありません。 

不用意に実装すると見逃される可能性のあるエッジケースがいくつかあります。 数値 (1) はセル値として許可されており、必須である場合があります。 例えば、```
2
2 12
3 8
```有効な出力があります```
1 3
2 4
```最初の行では (1) と (3) が使用されているため、(1) を無駄な要素として拒否すると、誤って解が削除されてしまいます。 

行積は、2 つのセル値が等しくなくても正方形になる可能性があります。 例えば、```
2
20 63
36 35
```によって解決できます```
4 9
5 7
```最初の行には積 (4 \cdot 9 = 36) が含まれています。 等しい値が禁止されていても、正方形 (36) のペア ((6,6)) のみを考慮するソルバーは失敗します。 

2 つの要素は異なる列に入力する必要があるため、その順序が重要です。 例えば、```
2
10 21
6 35
```解決策があります```
2 3
5 7
```因数 (2) と (3) は両方とも行積 (6) に属しますが、(2) のみが最初の列積 (10) に適合し、(3) は 2 番目の列積 (21) に適合します。 順序付けされていない因子ペアを、その向きが問題でないかのように扱うと、有効な配置が失われます。 

## アプローチ

 最も直接的な総当たりでは、行ごとに 2 つのセルを選択し、その積が必要な行積となる 2 つの値を選択します。 (n=10) の場合、位置のみを選択しても、すでに次の結果が得られます。 

[
 \binom{100}{2}^{10}=4950^{10}
 】

 値、列の制約、またはすべての値が異なる必要があるという要件を検討する前に、考えられる選択肢を検討してください。 これはおよそ (8.7\cdot10^{36}) 個の可能性があるため、セルごとの列挙は完全に非現実的です。 

有益な観察は、行積では任意の値が許可されないということです。 行の残りの積が (p) の場合、その 2 つの値は (ab=p) の因数ペア (a,b) でなければなりません。 (p\le1000) なので、そのようなペアはほとんどありません。 同じことが列にも当てはまります。 

さらに一歩進んで、すべての行と列を残りの積と残りの次数で表すことができます。 最初は、すべての頂点には次数 2 があり、その残りの積が元のターゲットになります。 エッジに値 (v) を配置するたびに、両方の端点の残りの積を (v) で割って、両方の端点の次数を 1 ずつ減らします。 

検索では常に、現在最も制限されている行または列が選択されます。 頂点に残りのエッジが 1 つだけある場合、その次の値は残りの積によって完全に決定されます。 どの反対側の頂点がそれを受け取るかを決めるだけで済みます。 頂点に残り 2 つのエッジがある場合、その因子ペアと 2 つの可能な反対の頂点を列挙します。 

これは、セルを検索するよりもはるかに小さいです。 さらに重要なのは、次数 2 の頂点を選択し、それを 2 つの近傍に接続すると、それらの近傍は次数 1 になります。 次に、検索により、結果のサイクルを通じて強制値が伝播されます。 ソリューションが複数のサイクルで構成されている場合、同じプロセスが別のコンポーネントに対して繰り返されます。 

(1000) を超えない積の場合、約数は最大 32 個であるため、非順序因数のペアは最大 16 個あります。 次数 2 の頂点には、2 つの異なる近傍の順序付き選択肢が最大 (n(n-1)) 個あり、可分性と一意性枝刈りの前に最大 (16\cdot10\cdot9=1440) 個の局所候補が得られます。 実際には、すべての候補が、選択した 2 つの近傍の残りの積を除算する必要があるため、候補数は大幅に少なくなります。

 | ブルートフォース | (O\left(\binom{n^2}{2}^n\right)) 値を選択する前 | (O(n^2)) | 遅すぎる |

 指数関数的な最悪の場合の限界は意図的に緩めに設定されています。 実際の検索は、(n\le10)、(1000) までの数の小さな約数、次数 2 の構造、および 1 つのエンドポイントが完了できなくなると失敗したすべての部分割り当てが拒否されるという事実によって制御されます。 

## アルゴリズムのチュートリアル

1. (n) 行と (n) 列を (2n) 頂点として扱います。 各頂点について、残りの積と残りの次数を保存します。 最初はすべての次数が 2 であり、残りの積が対応する入力値になります。 
2. すでに使用されているセル値のセットを維持します。 値は、グリッド内の他の場所に出現していない場合にのみ配置できます。 また、グラフは単純でなければならず、同じセルを 2 回選択できないため、どの行と列のセルがすでに占有されているかも維持します。 
3. 残りの次数が 1 である頂点の場合、その次のエッジ値が強制されます。 これは頂点の残りの積と等しくなければなりません。 その値が反対側の残りの積を分割し、接続セルがまだ使用されていない反対側の頂点を列挙します。 
4. 残りの次数が 2 である頂点の場合、残りの積のすべての因数分解 (a\cdot b=p) を 2 つの異なる値に列挙します。 因子ペアごとに、利用可能な 2 つの異なる対向頂点を選択します。 反対のプロダクトは 1 つの方向のみを受け入れる可能性があるため、(a) 最初の頂点と (b) 2 番目の頂点の両方の方向とその逆が考慮されます。 
5. 候補者を受け入れる前に、両方のエンドポイントでの即時の結果を確認してください。 エンドポイントが次数 0 になると、その残りの積は 1 になる必要があります。 1次になった場合、その残りの積はまだ使用できる値でなければなりません。 次数が 2 のままである場合、残りの積は 2 つの異なる未使用の値に因数分解されている必要があります。 これらのチェックは、再帰の前に不可能な分岐を破棄します。 
6. まだインシデント エッジを持つすべての頂点の中で、現在実行可能な候補が最も少ない頂点を選択します。 これは標準的な最小残存値の考え方です。 強制次数 1 の頂点は、その値がすでにわかっているため、特に価値があり、通常、隣接する可能性のある頂点は少数しかありません。 
7. 対応するセルに値を書き込み、残りの積を除算して度数を減らし、値とセルを使用済みとしてマークすることにより、選択した候補を適用します。 
8. すべての頂点の次数が 0 になるまで繰り返します。 この時点で、すべての行と列には 2 つの値が含まれ、残りの積はすべて 1 になり、すべてのセル値は個別になります。 構築されたグリッドが答えです。 

### なぜ効果があるのか

 不変条件は、すべての部分割り当てがすでに選択されたエッジの有効なセットを表し、すべての頂点について、その格納されている残りの積が、割り当てられていない入射エッジから依然として必要とされる積であるということです。 候補は、その値が両方のエンドポイント製品を分割し、残りの次数を尊重し、空のセルを使用し、グローバルに使用されていない場合にのみ考慮されます。 したがって、すべての再帰状態は依然として有効な完了に対応する可能性があります。 逆に、状態を有効に完了するには、次に選択される頂点は、次数が 1 の場合はその強制された残りの値を使用するか、次数が 2 の場合は実際に隣接する 2 つの頂点に接続された有効な因子ペアの 1 つを使用する必要があります。 検索ではそのような可能性をすべて列挙するため、唯一の有効な解決策を破棄することはできません。 入力によって解が存在することが保証されるため、一部の分岐はすべての次数が 0 の状態に到達します。

input = sys.stdin.readline

MAXV = 1000

factor_pairs = [[] for _ in range(MAXV + 1)]
for p in range(1, MAXV + 1):
    d = 1
    while d * d <= p:
        if p % d == 0:
            e = p // d
            if d != e:
                factor_pairs[p].append((d, e))
        d += 1

def solve(data: str) -> str:
    it = iter(data.split())
    n = int(next(it))
    x = [int(next(it)) for _ in range(n)]
    y = [int(next(it)) for _ in range(n)]

    if prod(x) != prod(y):
        return ""

    m = 2 * n

    rem = x[:] + y[:]
    deg = [2] * m

    ans = [[0] * n for _ in range(n)]
    used_mask = 0
    edge_mask = 0

    def edge_bit(v, u):
        if v < n:
            r, c = v, u - n
        else:
            r, c = u, v - n
        return 1 << (r * n + c)

    def neighbors(v):
        if v < n:
            return range(n, 2 * n)
        return range(n)

    def cell_coords(v, u):
        if v < n:
            return v, u - n
        return u, v - n

    def value_unused(v, mask):
        return (mask >> v) & 1 == 0

    def future_possible(u, value, mask, emask):
        if deg[u] <= 0:
            return False

        if rem[u] % value != 0:
            return False

        nr = rem[u] // value
        nd = deg[u] - 1

        if nd == 0:
            return nr == 1

        if value_unused(value, mask):
            pass

        if nd == 1:
            if nr <= 0 or nr > MAXV:
                return False
            if not value_unused(nr, mask):
                return False

            for w in neighbors(u):
                if deg[w] == 0:
                    continue
                bit = edge_bit(u, w)
                if emask & bit:
                    continue
                if rem[w] % nr == 0:
                    return True
            return False

        if nr <= 0 or nr > MAXV:
            return False

        for a, b in factor_pairs[nr]:
            if not value_unused(a, mask) or not value_unused(b, mask):
                continue
            for w1 in neighbors(u):
                if deg[w1] == 0:
                    continue
                bit1 = edge_bit(u, w1)
                if emask & bit1:
                    continue
                if rem[w1] % a != 0:
                    continue
                for w2 in neighbors(u):
                    if w2 == w1 or deg[w2] == 0:
                        continue
                    bit2 = edge_bit(u, w2)
                    if emask & bit2:
                        continue
                    if rem[w2] % b == 0:
                        return True
        return False

    def candidates(v, mask, emask):
        result = []

        if deg[v] == 0:
            return result

        if deg[v] == 1:
            value = rem[v]

            if value <= 0 or value > MAXV:
                return result
            if not value_unused(value, mask):
                return result

            for u in neighbors(v):
                if deg[u] == 0:
                    continue

                bit = edge_bit(v, u)
                if emask & bit:
                    continue

                if rem[u] % value != 0:
                    continue

                new_mask = mask | (1 << value)
                if not future_possible(u, value, new_mask, emask | bit):
                    continue

                result.append((u, value))
            return result

        for a, b in factor_pairs[rem[v]]:
            if not value_unused(a, mask) or not value_unused(b, mask):
                continue

            for u in neighbors(v):
                if deg[u] == 0:
                    continue
                bit_u = edge_bit(v, u)
                if emask & bit_u:
                    continue
                if rem[u] % a != 0:
                    continue

                for w in neighbors(v):
                    if w == u or deg[w] == 0:
                        continue
                    bit_w = edge_bit(v, w)
                    if emask & bit_w:
                        continue
                    if rem[w] % b != 0:
                        continue

                    new_mask = mask | (1 << a) | (1 << b)
                    new_emask = emask | bit_u | bit_w

                    if not future_possible(u, a, new_mask, new_emask):
                        continue
                    if not future_possible(w, b, new_mask, new_emask):
                        continue

                    result.append((u, a, w, b))

        return result

    failed = set()

    def dfs(mask, emask):
        if all(d == 0 for d in deg):
            return True

        key = (
            tuple(rem),
            tuple(deg),
            mask,
            emask,
        )
        if key in failed:
            return False

        best_v = -1
        best_candidates = None

        for v in range(m):
            if deg[v] == 0:
                continue

            cand = candidates(v, mask, emask)

            if not cand:
                failed.add(key)
                return False

            if best_candidates is None or len(cand) < len(best_candidates):
                best_v = v
                best_candidates = cand

                if len(best_candidates) == 1:
                    break

        v = best_v

        for cand in best_candidates:
            if deg[v] == 1:
                u, value = cand

                r, c = cell_coords(v, u)
                ans[r][c] = value

                old_rem_v = rem[v]
                old_rem_u = rem[u]
                old_deg_v = deg[v]
                old_deg_u = deg[u]

                rem[v] //= value
                rem[u] //= value
                deg[v] -= 1
                deg[u] -= 1

                bit = edge_bit(v, u)
                if dfs(mask | (1 << value), emask | bit):
                    return True

                rem[v] = old_rem_v
                rem[u] = old_rem_u
                deg[v] = old_deg_v
                deg[u] = old_deg_u
                ans[r][c] = 0

            else:
                u, a, w, b = cand

                r1, c1 = cell_coords(v, u)
                r2, c2 = cell_coords(v, w)

                ans[r1][c1] = a
                ans[r2][c2] = b

                old = (
                    rem[v], rem[u], rem[w],
                    deg[v], deg[u], deg[w]
                )

                rem[v] //= a
                rem[u] //= a
                deg[v] -= 1
                deg[u] -= 1

                rem[v] //= b
                rem[w] //= b
                deg[v] -= 1
                deg[w] -= 1

                bit1 = edge_bit(v, u)
                bit2 = edge_bit(v, w)

                if dfs(
                    mask | (1 << a) | (1 << b),
                    emask | bit1 | bit2
                ):
                    return True

                rem[v], rem[u], rem[w] = old[:3]
                deg[v], deg[u], deg[w] = old[3:]
                ans[r1][c1] = 0
                ans[r2][c2] = 0

        failed.add(key)
        return False

    dfs(used_mask, edge_mask)

    return "\n".join(" ".join(map(str, row)) for row in ans)

def prod(a):
    result = 1
    for v in a:
        result *= v
    return result

配列`rem`そして`deg`二部グラフの両側が含まれます。 頂点`0`を通して`n-1`は行を表し、頂点を表します`n`を通して`2*n-1`列を表します。 分割する`rem`そして減少します`deg`エッジを配置した後は、アルゴリズムからの数学的不変式が直接反映されます。

再帰的検索では、残りの最小値が使用されます。 未完成の頂点ごとに候補を生成し、候補リストが最小の頂点を選択します。 次数 1 の頂点は強制に近いことが多いため、最初の次数 2 の決定の後、探索は通常、ほとんど分岐せずにサイクル全体に伝播します。 

メモ化キーには、残りの積、残りの度数、使用された値、および占有セルが含まれます。 同じ製品を使用する 2 つの状態では、どのセルがすでに占有されているか、どの値がすでに消費されているかが異なる可能性があるため、これらすべてが必要です。 

Python の整数はオーバーフローしないため、積とビット マスクは安全です。 入力にはステートメントで指定されたとおりのテスト ケースが 1 つだけあるため、テスト ケースのループはありません。 

## 実用的な例

 ### サンプル 1

 入力は```
2
2 12
3 8
```最初の行には (3) の 2 つの異なる要素が含まれている必要があるため、可能性があるのは (1) と (3) だけです。 最初の列にはターゲット (2) があるため、(1) はそこに移動する必要があります。 2 番目の列には (3) が入ります。 残りの行にはターゲット (8) があり、唯一可能な配置は最初の列の (2) と 2 番目の列の (4) です。

```すべての行と列には正確に 2 つのエントリがあり、4 つの値は個別です。 この表は、次数 1 の頂点が強力である理由も示しています。最初の行が固定された後、各列にはちょうど 1 つのエッジが残るため、その値が強制されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(B^{2n})) 緩い最悪の場合、(B\le1440) | 各再帰的決定は少なくとも 1 つのエッジを割り当て、すべての次数 2 の決定では因子のペアと反対の頂点のペアのみが考慮されます。 
| スペース | (O(n^2 + S)) | グリッド、マスク、再帰状態、およびメモ化された失敗状態には、検索に比例したストレージが必要です。 

理論的な指数限界は意図的に保守的です。 (n\le10) の場合、完全なソリューションには 20 個の頂点と 20 個の占有セルしかありません。 除数制限により、各局所因子の選択は小さくなりますが、最小候補ヒューリスティックと前方チェックにより、ほとんどの分岐が即座に削除されます。 これは、指定された (1) 秒の制限の下で検索を実用的にするための構造です。 

## テストケース

 以下のテスト ハーネスは次のことを前提としています。`solve`ソリューションの関数は、同じファイルで使用できるか、同じファイルからインポートできます。 この問題では有効な回答が許容されるため、サンプルは正確にチェックされ、カスタム ケースは問題のすべての要件を検証するバリデーターでチェックされます。```python
import io
import sys

def run(inp: str) -> str:
    return solve(inp).strip()

def validate(inp: str, out: str) -> bool:
    data = list(map(int, inp.split()))
    n = data[0]
    x = data[1:1 + n]
    y = data[1 + n:1 + 2 * n]

    lines = out.strip().splitlines()
    if len(lines) != n:
        return False

    a = []
    for line in lines:
        row = list(map(int, line.split()))
        if len(row) != n:
            return False
        a.append(row)

    used = set()

    for i in range(n):
        values = [a[i][j] for j in range(n) if a[i][j] != 0]
        if len(values) != 2:
            return False
        if values[0] in used or values[1] in used:
            return False
        if values[0] <= 0 or values[1] <= 0:
            return False
        if values[0] * values[1] != y[i]:
            return False
        used.update(values)

    for j in range(n):
        values = [a[i][j] for i in range(n) if a[i][j] != 0]
        if len(values) != 2:
            return False
        if values[0] * values[1] != x[j]:
            return False

    return True

## 特殊なケース

 値 (1) は、他のすべての正の整数とまったく同様に処理されます。 最初のサンプルでは、​​行 0 に積 (3) があるため、因子のペアは (1,3) になります。 列積 (2) と (12) は、(1) を最初の列に押し込み、(3) を 2 番目の列に押し込みます。 ソルバーは (1) を特別なものとして扱うことはなく、そのビットは次のように記録されます。`used_mask`, したがって、2番目の(1)を後で導入することはできません。 

(36) のような二乗積の場合、因数ペア ジェネレーターは (\sqrt{36}) までのすべての約数 (d) を列挙し、個別のペア ((d,36/d)) を格納します。 したがって、(36) が正方形であっても ((4,9)) が考慮されます。 2 つのセル値は異なる必要があるため、ペア ((6,6)) は意図的に除外されています。
