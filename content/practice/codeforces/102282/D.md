 ## 解決策
 ## 問題の理解

 最大 (100 \x 100) 個のセルからなる長方形のグリッドがあります。 一部のセルは壁になっていて入ることができませんが、残りのセルは通過可能です。 1 つの移動可能なセルに最初はロボットが含まれています。 コマンドはロボットを 4 つの方向のうちの 1 つに正確に 1 セル移動させます。プログラムは、すべての動きがグリッド内に留まり、通過可能なセルに着地する場合にのみ有効です。 

プログラム全体を実行するとロボットが開始セルに戻るように、長さが最大 ​​(l) (l \le 30) である空でないプログラムをすべてカウントする必要があります。 たとえ同じセルにアクセスしたとしても、コマンド シーケンスが異なれば、プログラムも異なります。 

答えは何かを法として解釈されません。 長さが最大 ​​30 のプログラムの最大数は (4^{30}) 程度で、これは約 (1.15 \cdot 10^{18}) であるため、実装には 32 ビットを超える値を表現できる整数演算が必要です。 Python の整数はこれを直接処理します。 

グリッドには (10^4) 個のセルしかなく、プログラムの最大長はわずか 30 です。これは、すべてのセルとすべての可能な長さに対して何らかの状態を保持する必要があることを強く示唆しています。 (nml) または (4nml) に比例する計算は、容易に十分に小さくなります。 対照的に、すべてのコマンド シーケンスを列挙するには (l) で指数関数的な時間が必要ですが、(l=30) の場合は不可能になります。 

一見合理的に見える実装が間違った答えを与える可能性があるケースがいくつかあります。 

可能な限り最小の迷路を考えてみましょう。```
1 1 1
*
```正しい答えは、`0`。 空のシーケンスはロボットを最初のセルに戻しますが、問題は空のプログラムを明示的に除外します。 ゼロ移動後の開始位置の数で答えを開始し、それを含む実装では、誤った出力が行われます。`1`。 

2 番目の例は次のとおりです。```
1 3 2
=*.
```ロボットは真ん中からスタートします。 右に移動してから左に移動できるため、長さが最大 ​​2 の唯一の有効なプログラムは次のとおりです。`ПЛ`。 プログラム`ЛП`最初のコマンドはすぐに壁に入るため、無効です。 正しい出力は次のとおりです`1`。 中間の動きが壁にぶつかるとすぐにプログラムを拒否せず、最終位置のみをチェックするシミュレーションでは、無効なプログラムがカウントされる可能性があります。 

3 番目のケースは、許容される長さの境界を示しています。```
2 2 1
*.
..
```開始セルに戻る 1 つのコマンド プログラムはありません。 すべての移動は開始からのマンハッタンの距離の等価性を変更するため、偶数回移動した後でのみ復帰が可能です。 正しい出力は次のとおりです`0`。 一般的な off-by-one エラーは、初期状態をカウントしたり、誤って 1 つの余分な遷移を処理したりすることです。 

## アプローチ

 直接的なアプローチは、1 から (l) までの長さのすべてのコマンド シーケンスを生成することです。 シーケンスごとに、開始セルからロボットをシミュレートします。 すべての移動がグリッド内に留まり、壁を回避する場合は、最後のセルが開始セルであるかどうかを確認します。 

これは正しいです。考えられるすべてのプログラムが 1 回だけ生成され、シミュレーションは迷路の規則に正確に従うからです。 問題は配列の数です。 長さ (k) の (4^k) 個のプログラムがあるため、関連するすべての長さのプログラムの数は次のようになります。 

\frac{4^{31}-4}{3}、
 】

 これはすでに (1.5 \cdot 10^{18}) あたりにあります。 プログラムのシミュレートには (O(k)) の操作が必要なため、実際の総作業量は (\Theta(l4^l))、つまり (l=30) での基本動作チェック (4.5 \cdot 10^{19}) 回になります。 シミュレーション自体を最適化しないと、このアプローチを実行できません。 

ブルート フォースにこれほど多くの繰り返し作業が含まれる理由は、多くの異なるプログラムが同じ数のコマンドの後に同じセルに到達するためです。 2 つのプレフィックスが正確に (k) 回移動した後に同じセルに到達すると、それらの将来の可能性は同一になります。 プログラムの続行に必要な情報は、現在のセルとすでに使用されているコマンドの数だけです。 ロボットをそこに連れてきた正確な接頭辞はもはや重要ではありません。 

この観察は動的計画法に直接つながります。 させて`dp[r][c]`セル ((r,c)) で終了する、現在の長さの有効なプログラムの数を表します。 最初は、コマンドを実行する前に、開始セルに到達する方法は 1 つだけです。`dp[start] = 1`。 プログラムを 1 コマンド長く構築するために、すべての有効な状態は、最大 4 つの通過可能な隣接状態のそれぞれに移動できます。 そのカウントを対応する次の状態に追加します。 

正確に (k) 個のコマンドの状態を計算した後、開始セルの値は、ホームに戻る長さ (k) の有効なプログラムの正確な数になります。 (k=1,\dots,l) のこの値を合計すると、必要な答えが得られます。 初期状態は答えに追加されないため、空のプログラムは自動的に除外されます。 

ブルートフォース手法は、すべてのプログラムを明示的に表すため機能しますが、指数関数的に多くのプログラムが同じ中間状態を共有できるため、失敗します。 現在のセルと現在の長さのみが将来のすべての移動に影響するという観察により、そのようなすべてのプレフィックスを 1 つの DP 状態にマージできます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (\シータ(l4^l)) | 1 つのシミュレートされたパスの (O(l)) | 遅すぎる |
 | 最適 | (O(lnm)) | (O(nm)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. グリッドを読み取り、固有の開始セルを見つけます。 扱う`.`そして`*`横断可能なセルとして、一方`=`壁です。 ロボットがそこに配置されているため、開始セル自体は移動可能です。 
2. 2次元配列を作成する`dp`ゼロを含む場合、開始セルを次のように設定します。`1`。 これは、現在ロボットを初期位置に置いている単一の空のプレフィックスを表します。 空のプログラムは禁止されているため、この状態は回答に追加しません。 
3. から長さごとにトランジションを繰り返します。`1`を通して`l`。 通過可能なセルごとに、現在のウェイ数を取得し、その数を有効な隣接セルごとに分配します。 近傍は、その座標がグリッド内にあり、対応するグリッド文字がグリッド内にない場合にのみ有効です。`=`。 
4. 交換する`dp`新しく構築されたアレイを使用します。 この移行後、`dp[r][c]`は、((r,c)) で終わる、正確に現在の長さの有効なプログラムの数を意味します。 連続した長さに対して個別の配列を保持すると、遷移で同じ反復内で以前に作成された状態が誤って使用されることが防止されます。 
5.追加`dp[start_row][start_col]`答えに。 これらはまさに、現在の長さが反復番号であり、最終位置が元の位置である有効なプログラムです。 
6. すべての長さを加工した後、`l`、蓄積された回答を印刷します。 空ではない有効なプログラムはすべて、1 から 2 までの間で 1 つの長さだけを持ちます。`l`, したがって、正確に 1 回カウントされます。 

### なぜ効果があるのか

 不変条件は、正確に (k) 個の遷移を処理した後、`dp[r][c]`は、ロボットを開始セルから ((r,c)) まで移動させる、正確に (k) の長さの有効なコマンド シーケンスの数に等しくなります。 (k=0) については、開始セルに空のシーケンスが 1 つだけ存在し、他の場所には空のシーケンスが存在しないため、不変条件は true です。 移行中、すべての有効な長さ (k+1) のシーケンスには、隣接するセルで終わる一意の長さ (k) のプレフィックスがあり、その後に 1 つの有効な移動が続きます。 DP はまさにこれらの可能性を追加し、壁の中やグリッドの外へのあらゆる動きを拒否します。 したがって、不変式はあらゆる長さに対して成り立ちます。 特に、`dp[start]`after (k) move は、ホームに戻る長さ (k) の有効なプログラムを正確にカウントし、それをすべての正の長さにわたって合計すると、必要な答えが正確に得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, l = map(int, input().split())
    grid = [input().strip() for _ in range(n)]

    sr = sc = -1
    for r in range(n):
        for c in range(m):
            if grid[r][c] == '*':
                sr, sc = r, c

    dp = [[0] * m for _ in range(n)]
    dp[sr][sc] = 1

    answer = 0

    directions = ((-1, 0), (1, 0), (0, -1), (0, 1))

    for _ in range(l):
        ndp = [[0] * m for _ in range(n)]

        for r in range(n):
            for c in range(m):
                ways = dp[r][c]
                if ways == 0 or grid[r][c] == '=':
                    continue

                for dr, dc in directions:
                    nr = r + dr
                    nc = c + dc

                    if 0 <= nr < n and 0 <= nc < m:
                        if grid[nr][nc] != '=':
                            ndp[nr][nc] += ways

        dp = ndp
        answer += dp[sr][sc]

    print(answer)

if __name__ == "__main__":
    solve()
```グリッドは最初に文字列として保存されるため、セルが壁であるかどうかを確認するのは単純です。`grid[r][c] == '='`。 グリッドを読んでいると、ユニークな`*`セルは次のように記録されます`(sr, sc)`。 

初期の`dp`配列はゼロのコマンドに対応します。 開始位置にのみ到達する方法は 1 つあります。 この表現は、すべてのコマンドの長さに同じ遷移を適用できるため便利です。 

反復ごとに、`ndp`空から始まります。 ゼロ以外のすべての状態`dp`有効なプレフィックスのコレクションを表します。 4 方向のそれぞれについて、コードはグリッドにインデックスを付ける前に新しい座標をチェックします。 Python では配列の外側の座標に対してインデックス付けエラーが発生し、負のインデックスがリストの反対側のセルを参照してしまうため、この順序は重要です。 

条件`grid[nr][nc] != '='`両方を受け入れます`.`そして`*`。 ロボットは、他の通過可能なセルと同じように開始セル内を移動できます。これは、戻り経路をカウントするために不可欠です。 

古い配列は、すべての遷移が生成された後にのみ置き換えられます。 更新していたら`dp`その代わりに、反復の初期に到達した状態がすぐに再び使用される可能性があり、実質的に 1 つの DP ステップ中に複数のコマンドが許可され、不正確なカウントが生成されます。 

答えは完全な移行後にのみ更新されます。 したがって、最初の反復で追加される値は、空のプログラムではなく、長さがちょうど 1 のプログラムを表します。 Python の任意精度の整数を使用すると、オーバーフローの問題も解消されます。 コマンド シーケンスの理論上の数はおよそ (10^{18}) に達しますが、Python は結果の数を正確に表すことができます。

| 長さ |`dp[start]`| 累積回答 |

 ## 特殊なケース

 ### 空のプログラム

 のために```
1 1 1
*
```初期の DP 状態は`dp[0][0] = 1`, しかし、答えはゼロから始まります。 唯一の反復では 4 方向すべてを試行し、すべての方向がグリッドから離れるため、次の DP はすべて 0 になります。 最終的な答えは、`0`。 初期状態は遷移のソースとして使用され、それ自体が有効な答えとして使用されることはありません。 

### 無効な中間移動

 のために```
1 3 2
=*.
```最初の遷移は、列 2 の開始点から列 3 へのみ移動できます。左隣は壁で、他の 2 方向はグリッドの外側です。 最初のステップの後、スタートのカウントはゼロになります。 2 番目の移行中、ロボットは列 3 から開始位置に戻ることができ、`dp[start] = 1`。 したがって、答えは次のとおりです`1`。 

無効なシーケンス`ЛП`最初の遷移は壁をターゲットにしているため、DP には決して入りません。 したがって、DP は、無効なプログラムを、まさに無効になる時点で拒否します。 

### 奇数長の戻り値

 のために```
2 2 1
*.
..
```最初の遷移ではロボットが 2 つの隣接ロボットのうちの 1 つに送信されますが、どちらも開始ではありません。 したがって`dp[start] = 0`そして答えは`0`。 

同じ現象がグリッド グラフの奇数の長さごとに当てはまります。 移動するたびにパリティが切り替わります`r + c`, そのため、奇数回移動しても元のセルに戻ることはできません。 遷移カウントによってすでにエンコードされているため、アルゴリズムはこれを個別に検出する必要はありません。 

### 境界セル

 のために```
1 2 4
*.
```ロボットは開始セルから右への正当な移動を 1 つだけ行います。 2 番目のコマンドでは left を返す必要があります。 長さ 4 までのリターン プログラムのみが可能です。`ПЛ`そして`ПЛПЛ`、したがって、答えは次のとおりです`2`。 

境界チェック`0 <= nr < n`そして`0 <= nc < m`これらは、左、右、上、下のエッジを越える動きがカウントされないようにするものです。 

### 複数のパスが 1 つのセルに結合される

 のために```
2 2 4
*.
..
```2 回移動した後に戻る方法は 2 つあり、1 つは右に行って戻る方法、もう 1 つは下に行って戻る方法です。 4 つの移動の後、8 つの戻りプログラムがあり、合計で`10`。 

これはまさに、動的プログラミングが作業を節約する状況です。 いくつかの異なるプレフィックスが同じセルに到達する可能性があり、それらのカウントは 1 つの整数にマージされます。`dp[r][c]`。 次のコマンドが選択されると、これらすべてのプレフィックスには同じ将来のオプションが設定されるため、それらを 1 つのカウントとして保持しても情報が失われることはありません。
