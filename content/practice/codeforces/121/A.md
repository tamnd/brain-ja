 ## 解決策
 ## 問題の理解

 一定の間隔にわたる合計を評価する必要があります`[l, r]`。 すべての整数に対して`x`その範囲内で計算します`next(x)`、 どこ`next(x)`以上の最小の幸運な数字を意味します`x`。 

ラッキーナンバーとは、10 進数が 1 桁のみの正の整数です。`4`そして`7`。 例としては、`4`、`7`、`44`、`47`、`74`、`77`、 等々。 

仕事は幸運な数字を数えることではありません。 区間内のすべての整数について、次の幸運な数字の値を合計する必要があります。 

たとえば、次の場合`l = 2`そして`r = 7`:

 -`next(2) = 4`-`next(3) = 4`-`next(4) = 4`-`next(5) = 7`-`next(6) = 7`-`next(7) = 7`答えは`4 + 4 + 4 + 7 + 7 + 7 = 33`。 

制約は異常に小さいです。 間隔自体が非常に長くなる可能性があります。`r`届くかもしれない`10^9`したがって、からのすべての値を反復処理します。`l`に`r`最悪の場合は不可能です。 10 億の数値をループするには、2 秒の制限時間には時間がかかりすぎます。 

同時に、ラッキーナンバーの数は最大で`10^9`小さいです。 ここでのラッキーナンバーは最大 10 桁であり、各桁には 2 つの選択肢しかありません。`4`または`7`。 つまり、合計数は次のようになります。`2^1 + 2^2 + ... + 2^10 = 2046`数千の値を扱うのは簡単です。 問題全体は、このギャップを利用することを中心に設計されています。 

いくつかのエッジケースでは、不注意な実装が静かに破壊される可能性があります。 

考慮する：```
4 4
```答えは`4`、 なぜなら`next(4) = 4`。 より厳密に大きい最初のラッキーナンバーを検索するバグのある実装`x`間違って使用するだろう`7`。 

もう 1 つの注意が必要なケースは、間隔が複数のラッキー ナンバーの範囲にまたがる場合です。```
5 8
```正しい貢献は次のとおりです。 

-`5,6,7 -> 7`-`8 -> 44`したがって、答えは次のとおりです。```
7 + 7 + 7 + 44 = 65
```単純なグループ化の実装では、間隔内の最後の幸運な数字の後の末尾の処理を忘れてしまう可能性があります。 

大きな境界も重要です。```
999999999 1000000000
```両方の値の次の幸運な数字は次のとおりです。`4444444444`を超える`10^9`。 ラッキーナンバーだけを生成すると、`10^9`、正解を完全に見逃しています。 

## アプローチ

 ブルートフォースのアイデアは単純です。 すべての整数に対して`x`から`l`に`r`、以上の最小のラッキーナンバーを生成または検索します。`x`、それを答えに追加します。 

合計の定義が直接的なため、これは論理的に機能します。 問題はパフォーマンスです。 最悪の場合、間隔の長さは次のようになります。`10^9`。 たとえ`O(1)`値ごとの操作はすでに遅すぎるでしょう。 

ラッキーナンバーの構造は、より良い道を与えてくれます。 の値`next(x)`範囲全体にわたって一定に保たれます。 

たとえば:

 | x 範囲 | 次(x) |
 | --- | --- |
 | 1..4 | 4 |
 | 5..7 | 7 |
 | 8..44 | 44 |
 | 45..47 | 47 |

 すべての整数を個別に処理する代わりに、これらの範囲をブロックで処理できます。 

重要な観察は、幸運の数字の並べ替えられたリストがわかったら、2 つの連続する幸運の数字の間のすべての間隔が同じ値を繰り返し寄与するということです。 

現在のラッキーナンバーが`44`、前回のラッキーナンバーは`7`。 次に、からのすべての数字`8`を通して`44`貢献する`44`。 

つまり、次のことだけを行う必要があります。 

1. すべてのラッキーナンバーを生成します。 
2. 並べ替えます。 
3. 幸運の数字を調べて、どれだけの数字が得られるかを計算します。`[l, r]`各セグメントに分類されます。 

幸運な数字は約 2,000 しかないため、この解決策は非常に高速です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(r - l + 1) | お(1) | 遅すぎる |
 | 最適 | O(2^10) | O(2^10) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 再帰を使用して、最大 10 桁のすべてのラッキーナンバーを生成します。 

各ステップで、次のいずれかを追加します`4`または`7`現在の番号に。 これは、ラッキーナンバー構造の完全なバイナリ ツリーを調査します。 
2. 生成されたすべてのラッキーナンバーをリストに保存します。 

より大きい値も含めます`10^9`なぜなら`next(x)`上限に近い数値の場合は超過する可能性があります`10^9`。 
3. ラッキーナンバーを並べ替えます。 

再帰的生成では、ソート順は当然保証されません。 
4. 初期化します。 

-`ans = 0`-`cur = l`変数`cur`間隔内のまだ処理されていない最初の値を追跡します。 
5. ラッキーナンバーを昇順に繰り返します。 

ラッキーナンバーごとに`v`：

- もし`v < cur`、そのセグメントはすでに後ろにあるため、スキップします。 
- それ以外の場合は、からの間隔`cur`まで`min(r, v)`すべてが持っています`next(x) = v`。 
6. このセグメントに属する数値の数を計算します。 

カウントは次のとおりです。$\text{count}=\min(r,v)-cur+1$7. このセグメントの寄与を追加します。$\text{contribution}=v \times \text{count}$8. 移動`cur`このセグメントの後の最初の未処理の値に。 

セット：```
cur = v + 1
```9. 一旦停止`cur > r`。 

これで、間隔内のすべての値が考慮されました。 

### なぜ効果があるのか

 このアルゴリズムは、幸運な数字による数直線の分割に依存しています。 

ラッキーナンバーについては`v`、すべての整数は前のラッキーナンバーよりも厳密に大きく、最大でも`v`もっている`next(x) = v`。 

これらのセグメントは互いに素であり、一緒になって区間全体をカバーします。`[l, r]`。 

反復中に、`cur`は常に最初の未処理の整数を指します。 ラッキーナンバーを処理するとき`v`、次のラッキーナンバーが次の値に等しいすべての整数の寄与を正確に加算します。`v`。 進んでから`cur`に`v + 1`、処理された値は再検討されません。 

なぜなら、すべての整数は`[l, r]`まさに 1 つのセグメントに属している場合、最終的な合計は正しいです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

l, r = map(int, input().split())

lucky = []

def gen(x):
    if x > 10**10:
        return

    if x > 0:
        lucky.append(x)

    gen(x * 10 + 4)
    gen(x * 10 + 7)

gen(0)

lucky.sort()

ans = 0
cur = l

for v in lucky:
    if cur > r:
        break

    if v < cur:
        continue

    right = min(r, v)
    cnt = right - cur + 1

    ans += v * cnt
    cur = right + 1

print(ans)
```再帰的ジェネレーターは、繰り返し追加することによってあらゆる幸運な数字を構築します。`4`そして`7`。 

から始まる`0`は次の理由で便利です。 

-`0`それ自体は保存されません。 
- その子供たちは、`4`そして`7`。 

再帰の深さは小さく、最大でも 10 レベルなので、ここでは再帰は完全に安全です。 

停止条件は次を使用します`10^10`の代わりに`10^9`。 これは微妙ですが必要です。 もし`x = 10^9`、その次のラッキーナンバーは実際には`4444444444`、以下の値ではありません`10^9`。 

ソート後、メインループはラッキーナンバーを昇順に処理します。 ラッキーナンバーごとに`v`、間隔`[cur, min(r, v)]`貢献する`v`。 

行:```
cnt = right - cur + 1
```間違いやすいです。 間隔には両端が含まれるため、`+1`。 

もう 1 つの微妙な点は次のとおりです。```
cur = right + 1
```ない`v + 1`。 

仮定する`r < v`。 この場合、セグメントの一部のみが使用されます。 直接進む`v + 1`それでも論理的には機能しますが、使用すると`right + 1`実際に処理された境界と一致し、後でコードが変更された場合の間違いを回避します。 

Python の整数は大きな値を自動的に処理しますが、答えが 32 ビット整数の範囲を超える可能性があるため、これは重要です。

import io

def solve():
    input = sys.stdin.readline

    l, r = map(int, input().split())

    lucky = []

    def gen(x):
        if x > 10**10:
            return

        if x > 0:
            lucky.append(x)

        gen(x * 10 + 4)
        gen(x * 10 + 7)

    gen(0)

    ans = 0
    cur = l

        if cur > r:
            break

        if v < cur:
            continue

        cnt = right - cur + 1

        ans += v * cnt
        cur = right + 1

    print(ans)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out

    solve()

    sys.stdout = sys.__stdout__
    return out.getvalue().strip()

 ## 特殊なケース

 次の入力を考えてみましょう。```
4 4
```アルゴリズムは次から始まります`cur = 4`。 

ラッキーナンバーに到達すると`4`、範囲を処理します。```
[4, min(4, 4)] = [4, 4]
```貢献は次のとおりです。```
4 * 1 = 4
```それから`cur`になる`5`、ループが終了します。 出力は正しいです。`next(4)`は`4`、 ない`7`。 

次に、次のことを考えてみましょう。```
5 8
```関連するラッキーナンバーは、`7`そして`44`。 

アルゴリズムは以下を処理します。 

-`5..7`値を使用する`7`-`8..8`値を使用する`44`したがって、答えは次のようになります。```
7 + 7 + 7 + 44 = 65
```これにより、ラッキーナンバーの範囲間の遷移が正しく処理されることが確認されます。 

最後に、以下を調べます。```
999999999 1000000000
```両方の値の次の幸運な数字は次のとおりです。`4444444444`。 

反復がその幸運な数字に達すると、処理される範囲は次のようになります。```
999999999..1000000000
```カウント付き`2`。 

貢献度は次のようになります。```
2 * 4444444444 = 8888888888
```これは、なぜそれを超えて幸運な数字を生成するのかを示しています`10^9`必要です。
