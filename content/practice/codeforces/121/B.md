 ## 解決策
 ## 問題の理解

 10 進数の文字列と操作カウントが与えられます。`k`。 各操作では、部分文字列の左端の出現箇所が検索されます。`"47"`。 

部分文字列があるとします。`"47"`位置から始まります`x`1 から始まるインデックスを使用します。 

もし`x`は奇数なので、両方の数字を次のように置き換えます`'4'`、 それで`"47"`になる`"44"`。 

もし`x`が偶数の場合、両方の数字を次のように置き換えます`'7'`、 それで`"47"`になる`"77"`。 

文字列に何も含まれていない場合`"47"`まったく、操作には依然として 1 ステップが消費されますが、何も変わりません。 

タスクは、正確にその後の文字列を出力することです。`k`操作。 

制約によってソリューションが完全に形作られます。 文字列の長さは次のとおりです`10^5`、リニアスキャンでは管理可能です。 本当の難しさは、`k`と同じ大きさにすることができます`10^9`。 操作を 1 つずつシミュレートするアプローチは、各操作のコストが均等であれば失敗します。`O(1)`10 億回の反復は制限時間をはるかに超えているためです。 

単純な実装では、最初の検索を繰り返し行うことになります。`"47"`そしてルールを適用します。 検索コスト`O(n)`、最大で`10^9`オペレーションが行われるため、最悪のケースが発生します。`O(nk)`、 その周り`10^14`操作。 再スキャンを回避するために検索を最適化しても、プロセスが膨大な数のステップにわたって継続する可能性があるという問題が依然として残ります。 

難しいのは、変換によって新しいものが作成される可能性があることです。`"47"`近くのペア。 このプロセスは単調ではありません。 

次の例を考えてみましょう。```
4478
```最初`"47"`は偶数の位置 2 から始まるため、次のようになります。`"77"`:```
4478 -> 4778
```今では新しい`"47"`位置 1 に表示されます。```
4778 -> 4478
```プロセスは長さ 2 のサイクルに入ります。次の場合、単純なシミュレーションは永久に継続します。`k`大きいです。 

もう 1 つの微妙なケースは、エフェクトが重なっている場合に発生します。 

例：```
34747
```一番左の`"47"`消えるかもしれませんが、数字を変更するとすぐに別の文字が作成されます`"47"`それに隣接しています。 最初に間違った側を更新したり、隣接する位置を注意深く再チェックしなかったりすると、有効な変換がスキップされる可能性があります。 

3 番目のエッジケースは、アクティブな場合です。`"47"`のような 3 文字パターンの真ん中に位置します。`"447"`または`"477"`。 

例えば：```
447
```の`"47"`は位置 2 から始まり、偶数であるため、次のようになります。```
447 -> 477
```今、`"47"`左に移動します:```
477 -> 447
```再び無限の交替が得られます。 この構造を検出することが最適化の鍵となります。 

## アプローチ

 強引なアイデアはステートメントに直接続きます。 

各操作について:

 1. 左から右にスキャンして最初の項目を見つけます`"47"`。 
2. 存在しない場合は、文字列の変更を停止します。 
3. それ以外の場合は、パリティ ルールを適用します。 

このシミュレーションは、問題で説明されているプロセスを正確に再現しているため、正確です。 問題は走行時間だ。 

1回のスキャンに費用がかかります`O(n)`。 最悪の場合は以下の対応となる場合がございます。`10^9`操作。 実際の多くの場合、弦がすぐに安定したとしても、理論上の上限は不可能です。 

重要な観察は、各操作中に 1 つのローカル領域のみが変更されるということです。 さらに重要なのは、特定のパターンに遭遇すると、そのプロセスが期間 2 で周期的になるということです。 

のときに何が起こるかを見てください。`"47"`偶数の位置に表示されます。```
447 -> 477 -> 447 -> ...
```または、奇妙な位置で:```
474 -> 444 -> 447 -> 477 -> 447 -> ...
```短い過渡段階の後、システムは 2 つの状態の間で永久に振動します。 

これは、すべてをシミュレートする必要がないことを意味します`k`操作。 次のいずれかになるまでのみシミュレーションします。 

1.いいえ`"47"`残っています。 
2. 振動構造を検出します。 

サイクルが出現すると、残りの操作はパリティのみで解決できます。 

最適解は、左端の現在の位置を維持します。`"47"`そして、変更のたびに近くの位置のみを更新します。 すべての操作は、アクティブな位置をわずかに移動するか、サイクルに入ります。 安定化する前の真に異なる状態の総数は、最大でも線形です。

 ## アルゴリズムのチュートリアル

 1. 文字列を変更可能な文字配列に変換します。 
2. 左から右に 1 回スキャンして、最初に出現したものを見つけます。`"47"`。 
3. いいえの場合`"47"`存在する場合は、以降の操作では何も行われないため、文字列がすぐに出力されます。 
4. それ以外の場合は、現在の処理を繰り返します。`"47"`その間`k > 0`。 
5. ペアがインデックスから始まると仮定します。`i`0 から始まるインデックスを使用します。 

この問題では、パリティとして 1 から始まるインデックスが使用されます。 つまり:

 -`i`偶数 → 位置が奇数
 -`i`奇数 → 位置は偶数
 6. もし`i`が偶数の場合、ペアを次のように変更します`"44"`。 

この交換後は、近くのポジションのみ`i`新しいものを作成できる`"47"`。 具体的には、新しいペアが次の場所に出現する可能性があります。`i-1`またはそのままにします`i`。 
7. もし`i`は奇数です。ペアを次のように変更します`"77"`。 

繰り返しますが、重要なのは近くの位置だけです。 
8. 続行する前に、発振構成に入っているかどうかを確認してください。 

危険なケースは次のとおりです。 

- 次の桁が表示されている間に偶数位置で置き換えます。`'7'`- 前の桁が変更されている間に奇数の位置で置き換えます。`'4'`これらのパターンは即時 2 サイクルを作成します。 
このようなサイクルが検出された場合、最終状態は残りの演算回数が奇数か偶数かによってのみ決まります。 
10. それ以外の場合は、文字列全体を再スキャンするのではなく、ローカルで現在位置の更新を続けます。 

### なぜ効果があるのか

 不変条件は、各操作後に変更できるのは 1 つの連続するローカル領域だけであるということです。 交換中`"47"`と`"44"`または`"77"`多くても隣接するペアに影響を与えるため、左端のペアは`"47"`近くに留まるか、1 つの位置だけ移動できます。 

変換は決定的な 2 状態サイクルになるため、発振の検出は正確です。 このような構成に到達すると、2 回の操作ごとに同じ文字列が復元されます。 残りの効果はパリティのみに依存しており、パリティにより数十億の操作を安全にスキップできる可能性があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    s = list(input().strip())

    i = 0
    while i + 1 < n and not (s[i] == '4' and s[i + 1] == '7'):
        i += 1

    if i + 1 >= n:
        print("".join(s))
        return

    while k > 0 and i + 1 < n:
        if s[i] != '4' or s[i + 1] != '7':
            i += 1
            while i + 1 < n and not (s[i] == '4' and s[i + 1] == '7'):
                i += 1
            continue

        k -= 1

        if i % 2 == 0:
            s[i + 1] = '4'

            if i + 2 < n and s[i + 2] == '7':
                if k % 2 == 1:
                    s[i + 1] = '7'
                break

        else:
            s[i] = '7'

            if i - 1 >= 0 and s[i - 1] == '4':
                if k % 2 == 1:
                    s[i] = '4'
                break

            i -= 1

    print("".join(s))

solve()
```解決策は、最初の要素を見つけることから始まります。`"47"`ペア。 何も存在しない場合、文字列はすでに安定しています。 

メインループは常に現在の左端で動作します。`"47"`。 パリティ チェックでは、0 から始まるインデックスが慎重に使用されます。 索引`0`位置に対応する`1`、問題文では奇妙です。 

ペアが 1 から始まる奇数の位置から始まる場合、2 番目の桁のみが変更されます。`'7'`に`'4'`。 1 から始まる偶数の位置から始まる場合は、最初の桁のみが変更されます。`'4'`に`'7'`。 

周期の検出は微妙な部分です。 

次のように処理するとします。```
447
```の`"47"`インデックスから始まります`1`、偶数の位置に対応します`2`。 私たちは次のように変革します。```
447 -> 477
```今度は別の`"47"`すぐに左側に現れます。 文字列はこれら 2 つの状態を永久に繰り返します。 

残りのすべての操作をシミュレートする代わりに、パリティを使用します。 

- 残りの奇数の操作では、追加のフリップが 1 つ適用されます
 - 残りの操作でも現在の状態は変更されません。 

この実装では、操作ごとに正確に 1 桁が変更されます。 これにより、不必要な作業が回避され、全体の複雑さが線形に保たれます。
