 ## 解決策
 ## 問題の理解

 1 から _n_ までの数字の順列を調べ、数字 4 と 7 のみを含む整数である「幸運な数字」に焦点を当てるように求められています。この問題では、特に、1 から _n_ までの数字の辞書順に _k_ 番目の順列を見つけ、この順列内でそれ自体が幸運な数字である位置を占める数字の数を数えるよう求められています。 数値がこのカウントに含まれるのは、値とその位置の両方が幸運な場合のみです。 

入力は 2 つの整数を提供します: _n_ (順列のサイズ)、および _k_ (辞書順の順列の 1 から始まるインデックス)。 _k_ が順列の合計数 (_n_ 階乗) を超える場合、出力は -1 になるはずです。 それ以外の場合は、それ自体が幸運な位置の数字のカウントを出力する必要があります。 

制約は厳しく、_n_ は最大 10^9 まで可能です。 すべての _n_ を計算しています! 20 を超える _n_ の値については、20 のように並べ替えは実​​行できません。 単独では ~2.4×10^18 です。 これにより、順列を明示的に生成しようとする単純なアプローチが即座に排除されます。 エッジ ケースには、順列が自明である非常に小さい _n_ (1 または 2) と、部分階乗計算またはカットオフ ヒューリスティックを使用して処理する必要がある階乗が実際の計算を超えるほど十分に大きい _n_ が含まれます。 

不注意なアプローチでは、ライブラリ関数を使用してすべての順列を生成しようとする可能性があります。 入力用`n = 50`そして`k = 1`、メモリまたは時間の制限によりクラッシュする可能性があります。 もう 1 つの微妙なケースは 4 や 7 のような位置です。_n_ < 7 の場合、これらのインデックスは存在しないため、アルゴリズムは考慮される位置を順列の境界に正しく制限する必要があります。 

## アプローチ

 ブルートフォース手法は概念的には単純です。 1 から _n_ までの数値のすべての順列を生成し、辞書順に並べ替え、_k_ 番目の順列を選択し、そのインデックスを反復処理して、インデックスと値の両方が幸運な数字である位置をカウントします。 これは、小さい _n_ に対しては正しいですが、_n_ が生成されます。 順列はすぐに実行不可能になります。 _n_ = 15 の場合、1.3×10^12 の順列があります。 それらを並べ替えて _k_ 番目の順列にインデックスを付けることは、実際的な計算を超えています。 

重要な洞察は、_n_ が大きい場合、順列全体は必要ないということです。 この問題は幸運な数字についてのみ尋ねており、妥当な _n_ を下回る幸運な数字はほとんどありません。 たとえば、1000 未満では、ラッキー ナンバーは 50 個未満です。 したがって、_n_ > 15 の場合、幸運な位置の数は少なく、置換の残りは結果に影響しません。 これにより、最後の部分に集中できるようになります`min(n, 15)`階乗ベースの辞書編集上の計算の要素ですが、15 を超えるインデックスの辞書編集上の順序に影響を与えることができないため、前の要素は昇順になっています。 

これにより、問題は、最後のいくつかの要素についてのみ部分的な階乗ベースの順列を計算し、幸運の値に対して幸運のインデックスをチェックすることに軽減されます。 この観察により、_n_ が大きい場合でも問題は対処可能になります。

 ## アルゴリズムのチュートリアル

 1. _n_ までのすべてのラッキーナンバーを生成します。 これらは、どの位置と値が幸運であるかを特定するために使用されます。 数字の 4 と 7 を組み合わせた再帰的または反復的なプロセスを使用して、それらを生成できます。 
2. _n_ > 15 の場合、最初の値を修正します`n-15`要素を昇順に並べます。 最後の 15 個以下の要素が、_k_ 番目の辞書順列に達するように並べ替えられます。 15 なのでこれは実現可能です。 = 1.3×10^12、これは階乗計算に適合します。 
3. 最後の _k_ 番目の順列を計算します。`min(n,15)`階乗番号付けを使用する要素。 使用可能な要素のリストを初期化します。 各位置について、_k_ を残りの位置の階乗で除算し、_k_ を更新し、使用されている要素を削除することにより、どの要素がそこに移動するかを決定します。 
4. 固定プレフィックス (存在する場合) を配置し、その後に最後の要素の計算された順列を配置して、完全な順列を形成します。 
5. 順列の位置を繰り返します。 幸運な数字であり、幸運な値が含まれている各位置について、カウンターをインクリメントします。 
6. カウンタを出力します。 _k_ が最後のセグメントの合計順列を超えた場合、-1 を出力します。 

このアプローチが機能するのは、辞書編集上の順序が最後の 15 要素の順序のみに依存し、接頭辞が昇順で固定されているためです。 不変条件は、階乗除算が k 番目の順列の次の要素を正しく選択し、正確さを保証することです。 

## Python ソリューション```python
import sys
import math
input = sys.stdin.readline

def lucky_numbers_up_to(n):
    result = []
    def generate(x):
        if x > n:
            return
        if x > 0:
            result.append(x)
        generate(x*10 + 4)
        generate(x*10 + 7)
    generate(0)
    return result

def kth_permutation(arr, k):
    n = len(arr)
    k -= 1  # 0-based
    perm = []
    available = arr[:]
    for i in range(n, 0, -1):
        fact = math.factorial(i - 1)
        index = k // fact
        if index >= len(available):
            return None
        perm.append(available.pop(index))
        k %= fact
    return perm

def main():
    n, k = map(int, input().split())
    if n > 15:
        prefix_len = n - 15
        suffix_len = 15
    else:
        prefix_len = 0
        suffix_len = n
    
    total_suffix_perms = math.factorial(suffix_len)
    if k > total_suffix_perms:
        print(-1)
        return
    
    prefix = list(range(1, prefix_len + 1))
    suffix = list(range(prefix_len + 1, n + 1))
    
    perm_suffix = kth_permutation(suffix, k)
    if perm_suffix is None:
        print(-1)
        return
    
    perm = prefix + perm_suffix
    lucky_nums = set(lucky_numbers_up_to(n))
    
    count = 0
    for idx, val in enumerate(perm, 1):
        if idx in lucky_nums and val in lucky_nums:
            count += 1
    print(count)

if __name__ == "__main__":
    main()
```の`lucky_numbers_up_to`関数は再帰を使用してすべてのラッキーナンバーを生成します。 の`kth_permutation`関数は、階乗番号付けを使用して、0 から始まるインデックスを調整して k 番目の順列を計算します。 main 関数は、順列を固定プレフィックスと小さなサフィックスに分割することで、大きな _n_ ケースを処理します。 O(1) メンバーシップ テストのセットを使用すると、ラッキー ナンバーを数えるのが簡単です。 境界処理により、_k_ が可能な順列を超えた場合に -1 が出力されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(min(n,15)^2) | k 番目の順列の生成には、最大 15 個の要素を反復処理する必要があり、各ステップではリストからのポップを使用します。 
| スペース | O(min(n,15) + log(n)) | サフィックス、階乗リスト、およびラッキーナンバーを最大 n | 個まで保存します。 

n ≤ 10^9 の場合、このアルゴリズムは完全な順列を保存せず、階乗計算が 15! に制限されるため効率的です。
