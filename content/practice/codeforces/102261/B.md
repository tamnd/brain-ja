 ## 問題の理解

 シングルエリミネーショントーナメントで行われるチェスのゲームのリストが与えられます。 正確に (n=2^k-1) 個のゲームがあったため、トーナメントには (2^k) 人のプレイヤーと (k) 回のラウンドがあったはずです。 すべてのゲームについて、私たちが知っているのは 2 人の参加者だけであり、ゲームが行われたラウンドや誰が勝ったかはわかりません。 

このタスクは一度に 2 つの部分で構成されます。 まず、記録されたペアが有効なシングルエリミネーション ブラケットに属することができるかどうかを判断する必要があります。 第 2 に、そのような括弧が存在する場合は、決勝に進出した可能性のある 2 人のプレーヤーを出力する必要があります。 実際の勝者は不明であるため、ファイナリストは両方ともトーナメント勝者の可能性があります。 公式分析では、各参加者がプレイしたゲーム数を使用してラウンドを間接的に再構築します。 

(d(v)) をプレーヤー (v) が関与した記録されたゲームの数とします。 ラウンド (r) で負けたプレーヤーは正確に (r) ゲームをプレイできますが、ファイナリストはすべての (k) ラウンドをプレイします。 したがって、記録されたブラケットが有効である限り、2 人のファイナリストは正確に (d(v)=k) を持つプレーヤーでなければなりません。 

制約 (n\le 2^{16}-1=65535) は、最大 (65536) 個の個別の参加者が存在できることを意味します。 すべてのゲームを一定の回数読み取って処理するのは、1 秒であれば十分に高速ですが、ゲーム数の 2 次関数では、最大サイズでおよそ (4.3\cdot10^9) の演算がすでに必要になります。 線形または線形に近い解決策が必要です。 

基礎となるグラフを見るだけでは不十分な微妙なケースがいくつかあります。 たとえば、3つのゲームの場合```
3
A B
B C
C A
```すべてのプレイヤーは 2 回参加するため、不注意に実装すると、3 人の参加者がすべてファイナリストになる可能性があるとみなされる可能性があります。 正しい答えは、`NO SOLUTION`, 4 人のプレーヤーによるノックアウト トーナメントの 3 試合ではサイクルを形成できないためです。 問題は度数だけではなく、ゲームを有効なラウンドに分割できるかどうかです。 

2番目の重要なケースは、```
3
A B
C D
B C
```正しい出力は次のとおりです`B C`。 ここでは (A) と (D) は 1 回再生され、(B) と (C) は 2 回再生されます。 最初の 2 試合が第 1 ラウンドとなる可能性があり、`B C`決勝になるかもしれない。 入力順序が時系列順であると仮定する解決策は、たまたまこの例を受け入れる可能性がありますが、その仮定は一般に無効です。 

3 番目のケースは、同じ推定ラウンドに繰り返し参加する場合です。```
3
A B
A B
C D
```カウントは (d(A)=d(B)=2) および (d(C)=d(D)=1) です。 2つのゲーム`A B`どちらも参加人数が少ない方のラウンドに強制的に参加するため、同じプレイヤーが 1 ラウンドで 2 回プレイする必要があります。 正しい答えは、`NO SOLUTION`。 

## アプローチ

 直接的な総当たりアプローチでは、記録されたすべてのゲームを (k) ラウンドの 1 つに割り当てようとします。 ラウンド (r) には正確に (2^{k-r}) 個のゲームが含まれている必要があるため、ラウンドに (n) 個のゲームを割り当てることができる数は次のようになります。 

[
 \frac{n!}{\prod_{r=1}^{k}(2^{k-r})!}。 
】

 このような割り当てごとに、同じラウンドに 2 回出場するプレーヤーがいないかどうか、およびその結果のスケジュールがノックアウト トーナメントを形成するかどうかを確認できます。 各候補割り当ての検査には (\Theta(n)) の作業がかかるため、最悪の場合の操作数は次のようになります。 

[
 \シータ\左(
 n\cdot
 \frac{n!}{\prod_{r=1}^{k}(2^{k-r})!}
 \右）。 
】

 (n=7) の場合でも、これはすでに多くの可能性を考慮していますが、(n=65535) の場合、この式は完全に実行不可能です。 ブルート フォースは、有効な解決策が最終的に何を確立する必要があるかを示すため、概念的には便利ですが、参加数によって実際に決定される場合は、未知のラウンド数を独立した選択肢として扱います。 

重要な観察は、プレイヤー (u) と (v) の間のゲームがラウンド内に起こったに違いないということです。 

[
 \min(d(u),d(v))。 
】

 (d(u)=3) および (d(v)=5) と仮定します。 プレーヤー (u) は 3 試合目で参加をやめたため、(v) との試合は 3 試合目で最後の試合になる必要がありました。 したがって、ゲームはラウンド 3 に属します。すべての参加者数が判明すると、そのラウンドに関して自由は残されません。 

これにより、ゲームごとに疑似ラウンドを定義できるようになります。 (\min(d(u),d(v))=r) の場合、ゲーム ((u,v)) は擬似ラウンド (r) に属します。 実際のノックアウト トーナメントでは、ラウンド (r) にはちょうど (2^{k-r}) 個のゲームが含まれており、各プレーヤーはそのラウンドで最大 1 つのゲームに参加します。 注目すべき点は、これら 2 つの条件が必要なだけでなく、十分であるということです。 これは、公式ソリューションで使用される中心的な特徴付けです。 

なぜ十分であると考えられるのでしょうか? 疑似ラウンド 1 を考えてみましょう。少なくとも 1 つのゲームをプレイした人はラウンド 1 からトーナメントを開始する必要があるため、すべての参加者がそこに参加する必要があります。最初のラウンドが削除されると、残りのすべての参加者は実質的に 1 つ少ないゲームをプレイしたことになるため、同じ議論が 1 つ少ないラウンドのトーナメントに再帰的に適用されます。 これにより、(k) についての帰納法が得られます。 

結果として得られるアルゴリズムには、参加カウント、疑似ラウンドの割り当て、および各疑似ラウンドに必要な数の個別の参加者が含まれているかどうかのチェックのみが必要です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (\Theta\left(n\cdot\frac{n!}{\prod_r(2^{k-r})!}\right)) | (O(n)) | 遅すぎる |
 | 最適 | (O(n)) が期待されます | (O(n)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべて (n) のゲームを読み取り、各プレーヤーが何回発生したかを数えます。 この値を (d(v)) と呼びます。 これは、各ゲームのラウンドを推測するために必要な唯一の情報です。 
2. (k=\log_2(n+1)) を計算します。 入力は (n=2^k-1) を保証するため、Python では次のように直接取得できます。`(n + 1).bit_length() - 1`。 
3. 記録されたすべてのゲーム ((u,v)) について、計算します。 

[
 r=\min(d(u),d(v))。 
】

 ゲームを疑似ラウンド（r）にします。 参加カウントが小さいほど、すでに最後のゲームに到達した参加者が識別されるため、このゲームは後のラウンドで発生することはできません。 
4. 1 から (k-1) までのすべての疑似ラウンド (r) について、その内容が正確に含まれていることを確認します。 

[
 2^{k-r}
 】

 ゲーム。 実際のラウンドでは、開始時に (2^{k-r+1}) 人のプレイヤーがまだ生存しているため、まさにこの数の試合が行われます。 
5. 同じ疑似ラウンドに対して、参加者のセットを維持します。 ゲームのいずれかのエンドポイントがそのセットにすでに出現している場合は、入力を拒否します。 プレーヤーは、ノックアウト トーナメントの同じラウンドで 2 回プレーすることはできません。 
6. (d(v)=k) を持つすべてのプレイヤーを検索します。 以前のチェックに合格した場合、そのようなプレーヤーがちょうど 2 人存在する必要があります。 彼らはすべてのラウンドを勝ち残った唯一のプレイヤーであるため、ファイナリストの 2 名となります。 
7. これら 2 つの名前を出力します。 有効性チェックに失敗した場合は、出力します。`NO SOLUTION`。 

### なぜ効果があるのか

 不変条件は、擬似ラウンド (r) には、実際のラウンド (r) で発生したはずのゲームが正確に含まれるということです。 ゲーム ((u,v)) の場合、少なくとも 1 つのエンドポイントはそのゲームの直後にプレイを停止する必要があるため、そのラウンドは正確に (d(u)) と (d(v)) の小さい方になります。 したがって、有効なブラケットはゲームを他の場所に配置できません。 

すべての疑似ラウンドに正しいゲーム数があり、1 つの疑似ラウンド内で参加者が 2 回出現しない場合、最初の疑似ラウンドは有効な素の最初のラウンドの試合で構成されます。 各試合には参加カウント 1 のプレイヤー 1 名と継続するプレイヤー 1 名がいます。 その疑似ラウンドを削除すると、生き残っているすべてのプレーヤーの参加数が 1 つ減り、(k-1) ラウンドのトーナメントとまったく同じ条件が残ります。 基本ケースは 2 人のプレーヤー間の 1 つのゲームです。 帰納法により、ゲームのセット全体を有効なノックアウトブラケットとして配置できます。 

## Python ソリューション```python
import sys
from collections import Counter

input = sys.stdin.readline

def solve():
    n = int(input())
    games = [tuple(input().split()) for _ in range(n)]

    # n = 2^k - 1, so n + 1 = 2^k.
    k = (n + 1).bit_length() - 1

    degree = Counter()

    for u, v in games:
        degree[u] += 1
        degree[v] += 1

    rounds = [[] for _ in range(k + 1)]

    for u, v in games:
        r = min(degree[u], degree[v])

        if r < 1 or r > k:
            print("NO SOLUTION")
            return

        rounds[r].append((u, v))

    for r in range(1, k):
        expected = 1 << (k - r)

        if len(rounds[r]) != expected:
            print("NO SOLUTION")
            return

        used = set()

        for u, v in rounds[r]:
            if u in used or v in used:
                print("NO SOLUTION")
                return

            used.add(u)
            used.add(v)

    finalists = [name for name, cnt in degree.items() if cnt == k]

    if len(finalists) != 2:
        print("NO SOLUTION")
        return

    print(finalists[0], finalists[1])

if __name__ == "__main__":
    solve()
```最初のパスオーバー`games`ビルドします`degree`、これはアルゴリズムからの参加カウント (d(v)) に直接対応します。 あ`Counter`は、すべての姓を辞書のキーとして使用できるため便利です。 

2 番目のパスでは、各ゲームを次のように割り当てます。`rounds[min(degree[u], degree[v])]`。 入力により、ゲームの合計数が (2^k-1) の形式になることが保証されるため、`k`浮動小数点対数なしで復元できます。 ビット演算を使用すると、丸めの問題も回避できます。 

明示的な衝突チェックが必要なのは、疑似ラウンド 1 ～ (k-1) のみです。 これらのラウンドが特性を満たすと、残りのゲームが必然的に最終ラウンドを形成します。 コードには疑似ラウンド (k) が保存されていますが、それを個別に検査する必要はありません。 

セット`used`ラウンドごとに再作成されます。 これは、プレーヤーが複数の異なるラウンドに 1 回正当に出現する可能性があるため、必要です。 単に前のラウンドに登場したという理由だけで名前を拒否すると、後のステージに到達したプレイヤーを誤って拒否することになります。 

最後に、有効なトーナメントには、参加数 (k) を持つちょうど 2 人のプレーヤー、つまり 2 人のファイナリストがいます。 明示的な`len(finalists) != 2`check により、入力が構造上の前提条件に違反して初期のチェックが不十分になった場合でも、実装が堅牢になります。

 ## 特殊なケース

 3 人用サイクル```
3
A B
B C
C A
```(k=2) と次数 (d(A)=d(B)=d(C)=2) を与えます。 最小次数は常に 2 であるため、すべてのゲームは疑似ラウンド 2 に割り当てられます。疑似ラウンド 1 で必要なゲーム数は (2^{2-1}=2) ですが、それにはゼロが含まれるため、アルゴリズムは戻ります。`NO SOLUTION`。 これは、参加者の学位だけを十分なものとして扱うという間違いを捉えています。 

最小有効トーナメント```
3
A B
C D
B C
```度数は (1,2,2,1) です。 ゲーム`A B`そして`C D`は疑似ラウンド 1 に割り当てられますが、`B C`最初のラウンドには 2 つの独立したゲームが含まれ、2 番目のラウンドには 1 つの決勝が含まれます。 レベル2の2人のプレーヤーは次のとおりです。`B`そして`C`したがって、出力は次のようになります`B C`。 

繰り返されるゲーム事件```
3
A B
A B
C D
```度数は (2,2,1,1) です。 両方のコピー`A B`は疑似ラウンド 2 に割り当てられますが、`C D`は疑似ラウンド 1 に割り当てられます。疑似ラウンド 1 には正しいゲーム数がありますが、疑似ラウンド 2 には 1 つではなく 2 つのゲームがあります。 繰り返しの参加者によって曖昧さが生じる前に、カウント チェックによって拒否されます。 

最大サイズでは、(n=65535) は (k=16) と正確に (65536) 人のプレーヤーを与えます。 最初の疑似ラウンドには (32768) の素のゲームが含まれ、2 番目の疑似ラウンドには (16384) というように決勝まで続きます。 生成された最大テストはまさにこの構造に従い、全 16 ラウンドに登場する 2 人のプレーヤーは次のとおりです。`P32767`そして`P65535`。 この実装はブラケット ツリー自体を構築することはなく、参加数によって暗示されるラウンド構造を検証するだけです。そのため、同じ線形メソッドが最小および最大の有効なトーナメントを処理します。
