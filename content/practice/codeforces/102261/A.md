 ## 解決策
 ## 問題の理解

 (N) 個の各アラームは、それぞれの初期時刻 (t_i) に鳴り始め、その後 (X) 分ごとに繰り返されます。 複数のアラームが同時に鳴っても、アレクセイはその瞬間を一度だけ聞きます。 彼は、(K) 回目の明確な呼び出し時間を聞いた後、すぐに目を覚まします。 

タスクは、(K) 番目の個別の時間を見つけることです。 

制約は、すべての呼び出しイベントをシミュレートすることを除外するのに十分な大きさです。 (10^5) 個のアラームが存在する可能性がありますが、(X) と (K) は両方とも (10^9) に達する可能性があります。 単一のアラームは (K) 回鳴らす必要があるため、答え自体は約 (10^{18}) になる可能性があります。 最初の (K) イベントを明示的に生成するソリューションでは、最悪の場合 (O(KN)) の作業が必要になる可能性がありますが、これは完全に実行不可能です。 ほぼ線形の前処理とともに、答えのサイズに対する対数依存性が必要です。 

主なエッジケースは、アラームの同時発生によって発生します。 考慮する```
2 5 3
1 6
```両方のアラームがまったく同じ瞬間に鳴ります: (1,6,11,\ldots)。 3 番目の明確な呼び出し時間は (11) です。 すべてのアラームの鳴動を別個のイベントとして扱う不用意な解決策では、(1) と (6) が 2 回カウントされ、間違った答えが生成されてしまいます。 

もう 1 つの微妙なケースは、2 つの初期時間が同じ剰余モジュロ (X) を持つが、等しくない場合です。```
2 5 4
1 11
```最初のアラームは (1,6,11,16,\ldots) で鳴り、2 番目のアラームは (11,16,\ldots) で鳴ります。 2 番目のアラームは新しい呼び出し時間にまったく寄与しないため、4 番目の個別の時間は (16) になります。 すべての (t_i) を独立した等差数列として単純に保持すると、(11,16,\ldots) が 2 倍にカウントされます。 

逆の状況も重要です。 (X) を法とする異なる残基が衝突することはありません。 例えば、```
2 5 4
1 2
```(1,2,6,7,\ldots) を生成します。 (5) を法とした剰余が異なる数値は等しくならないため、2 つの数列は永遠に区別され続けます。 

## アプローチ

 直接的な解決策としては、すべてのアラームの中から最も早い次の呼び出し時刻を繰り返し検索し、それを 1 回カウントし、その瞬間に鳴るすべてのアラームを進めることができます。 これは文字通り、リンギングの瞬間のマージされたシーケンスをシミュレートするため、概念的には単純で正しいものです。 ただし、アラームが 1 つであっても (K) 個のイベントが生成される可能性があり、(K) が (10^9) になる可能性があります。 (N=10^5) の場合、すべてのアラームを維持するには、(NK) 個のオーダーで最大 (10^{14}) 個の操作が必要になる可能性があります。 優先キューを使用するより慎重なシミュレーションでも、少なくとも (O(K\log N)) を与える (K) 個の個別の瞬間を処理する必要がありますが、これは大きすぎます。 

便利な構造は、すべての進行にまったく同じステップ (X) があることです。 2 つのアラームは、開始時間が同じ剰余 (X) である場合に正確に同時に鳴らすことができます。 同じ残基クラスの 2 つの開始点が (a) と (b) (a<b) であると仮定します。 (b-a) は (X) の倍数であるため、2 番目のアラームの各鳴動時間は最初のアラームの鳴動時間でもあります。 したがって、各残基クラスの最も早い開始アラームのみが重要になります。 

すべてのアラームを各剰余モジュロ (X) の最も早い (t_i) に置き換えると、最大 (X) 個の関連する進行があり、それぞれは次のようになります。 

[
 s、\ s+X、\ s+2X、\ldots
 】

 ここで、(s) は最も早い開始時刻です。 

次に、候補時間 (T) を考えます。 (s) から始まる 1 つの進行について、(T) を超えない鳴動時間の数は次のとおりです。 

[
 \左\lフロア\frac{T-s}{X}\右\rフロア+1
 】

 (s\le T) の場合はゼロ、そうでない場合はゼロ。 異なる保持された数列はモジュロ (X) が異なる残基を持つため、重複することはありません。 したがって、これらのカウントを合計して、(T) までの個別のリンギングの瞬間の正確な数を取得できます。 

このカウントは単調です。増加 (T) すると、リンギングの瞬間のみが追加されます。 これにより、二分探索が適用できるようになります。 少なくとも (K) 個の異なるリンギング瞬間が発生した最小 (T) を二分探索します。 そのような最小の (T) は、まさに (K) 番目の呼び出し音の瞬間です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(K\log N)) 優先キューあり | (O(N)) | 遅すぎる |
 | 最適 | (O(N\log A)) | (O(N)) | 承認済み |

 ここで (A) は答えの大きさで、最大でも約 (10^{18}) であるため、二分探索には約 60 回の反復しかかかりません。 

## アルゴリズムのチュートリアル

 1. (N)、(X)、(K)、および開始時刻 (t_i) を読み取ります。 
2. 開始時間を剰余モジュロ (X) でグループ化します。 残りのすべてについて、最小の開始時間のみを保持します。 

2 つの開始の残りが同じ場合、後の進行は完全に前の進行の中に含まれます。 最小値を維持すると、二分探索が開始される前に、将来の重複した呼び出し音がすべて削除されます。 
3. カウント関数 (count(T)) を定義します。 保持されている開始時間 (s) ごとに、(s\le T) の場合、追加します。 

[
 \frac{T-s}{X}+1
 】

 整数の除算を使用します。 

結果として得られる値は、保持された進行が異なる残基を持っているため交差できないため、(T) またはそれ以前の個別のリンギングの瞬間の正確な数です。 
4. 答えを含む二分探索間隔を選択します。 可能な最も早い呼び出し時間は (\min(t_i)) です。 安全な上限は

 [
 \min(t_i)+(K-1)X。 
】

 最小時間から始まる 1 つの進行でも、その時点までに (K) 個のイベントが含まれるため、実際の答えはこれより大きくなりません。 
5. (count(T)\ge K)を満たす最小の(T)を二分探索します。 中間点のカウントがすでに少なくとも (K) である場合、答えは最大でもその中間点であるため、右側の境界を左に移動します。 それ以外の場合は、答えの方が大きいため、左側の境界を右に移動します。 
6. 最終的な左境界を出力します。 少なくとも (K) 個の個別のイベントが出現したのはこれが初めてであり、つまり、正確に (K) 回目の個別の呼び出し時間であることを意味します。 

### なぜ効果があるのか

すべての剰余モジュロ (X) について最も早いアラームのみを保持した後、削除されたすべてのアラームは、同じ剰余からの保持されたアラームによってすでに生成された瞬間のみを生成します。 したがって、保持された進行により、元のアラームとまったく同じ一連の呼び出し時間が生成されます。 

保持された進行には、(X) を法とするペアごとに異なる残基があるため、そのうちの 2 つが同時に鳴ることはありません。 したがって、各進行からのイベントの数を合計すると、任意の時点 (T) までの個別のイベントの正確な数が得られます。 このカウントは単調であるため、(count(T)\ge K) の最小 (T) は、正確に (K) 番目の個別のイベントの時間になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    N, X, K = map(int, input().split())
    t = list(map(int, input().split()))

    INF = 10**30
    earliest = {}

    for value in t:
        r = value % X
        if r not in earliest or value < earliest[r]:
            earliest[r] = value

    starts = list(earliest.values())
    first = min(starts)

    def count_events(T):
        total = 0

        for s in starts:
            if s <= T:
                total += (T - s) // X + 1
                if total >= K:
                    return total

        return total

    lo = first
    hi = first + (K - 1) * X

    while lo < hi:
        mid = (lo + hi) // 2

        if count_events(mid) >= K:
            hi = mid
        else:
            lo = mid + 1

    print(lo)

if __name__ == "__main__":
    solve()
```辞書`earliest`残差クラス圧縮を実装します。 鍵となるのは`value % X`、その値は、その残りを含む最小の開始時間です。 アラームが鳴っている瞬間だけが重要なので、実際のアラームの ID を保存する必要はありません。 

機能`count_events`二分探索で使用される単調述語を評価します。 条件`s <= T`最初の呼び出し時間が (T) 以降の場合、アラームはまだイベントを生成していないため、これが必要です。 アクティブな進歩のために、`(T - s) // X + 1`(s) 自体でイベントをカウントします。これが一般的な off-by-one エラーの原因です。 

早期復帰のとき`total >= K`最適化です。 カウントが (K) に達すると、その正確な大きい値は二分探索述語とは無関係になります。 

Python の整数には任意の精度があるため、大きな値になる可能性があります。`first + (K - 1) * X`オーバーフローしません。 固定幅の整数型を使用する言語では、ここでは 64 ビット整数が必要です。 

1 つの数列が から始まるため、多くの剰余クラスがある場合でも上限は有効です。`first`単独で (K) 個の鳴る瞬間が含まれています`first + (K - 1) * X`。 アラームを増やすと、(K) 番目のイベントを早くすることしかできません。

 ## 特殊なケース

 すべてのアラームの開始時刻が同じ場合、次のようになります。```
5 10 7
3 3 3 3 3
```明確な進行は 1 つだけです (3,13,23,33,43,53,63,\ldots)。 辞書には 1 つのエントリが含まれているため、`count_events(63)`は(7)、答えは(63)です。 個別の時刻ではなくアラームをカウントするシミュレーションでは、一度に 5 つのイベントが発生すると誤って認識されてしまいます (3)。 

2 つの開始点が (X) の倍数だけ異なる場合、次のようになります。```
2 5 4
1 11
```どちらの開始点にも剰余 (1) があります。 (11) からの数列は (11,16,21,\ldots) ですが、これはすでに (1,6,11,16,\ldots) に含まれています。 辞書には (1) のみが保持され、4 番目のイベント (16) が与えられます。 このため、単に等しい開始時間を削除するのではなく、残りによるグループ化が必要です。 

2 つのアラームの残基が異なる場合、それらのイベントは決して衝突しません。 のために```
2 5 4
1 2
```マージされたシーケンスは (1,2,6,7) で始まるため、答えは (7) になります。 count 関数は (count(6)=3) および (count(7)=4) を与えるため、二分探索は (7) を返します。 これにより、不十分な候補と最初の十分な候補の間の境界もテストされます。 

最低限のケース```
1 1 1
1
```進行は 1 つだけあり、最初のイベントを要求します。 二分探索の下限と上限は両方とも (1) であるため、ループは反復を実行せず、すぐに (1) を返します。 これにより、検索間隔には厳密に答えの後に始まるのではなく、答え自体が含まれることが確認されます。
