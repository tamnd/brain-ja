 ## 解決策
 ## 問題の理解

 Нужно проанализировать небользую программу на языке EX и для каждой объявленной функции определить, какие типы исключений могут выйти наружу из этой функции. Исключение считается возможным, если существует хотя бы один путь выполнения, на котором оно возникает и не подавляется окружающими`try ... suppress`。 

У программы есть четыре вида конструкций.`maybethrow E`создаёт возможность выбросить исключение`E`。 Вызов функции передаёт наружу любое исключение, которое может выйти из вызываемой функции. Блок`try { ... } suppress E1, E2, ...`あなたのことは、あなたが知っていることです。 Объявления функций находятся только на верхнем уровне, но функции могут вызывать друг друга в любом порядке и могут вызывать самих себя.

 Для каждой функции нужно вывести её имя, количество различных исключений, которые могут выйти из неё, и Пами исключения в лексикографическом порядке. Если различных исключений бользе`x`、достаточно вывести только`x`そうですね。 

Ограничение на`x`и число различных типов исключений равно`1000`、 а число вызовов функций также не превосходит`1000`。 Размер исходного текста может достигать миллиона символов. Это подсказывает разделить задачу на синтаксический разбор, линейный по размеру текста, и графовый анализ, зависящий в основном от числа функций、исключений и вызовов。 Перебирать все возможные цепочки вызовов или многократно пересчитывать полные множества исключений нельзя, Іиклы в графе вызовов могут заставить такой алгоритм делать очень много повторной работы.

 Первый неприятный случай связан с подавлением внутри вызываемой функции. 概要:```
1
2
func f() {
    try {
        maybethrow E
    } suppress E
}
func g() {
    f()
}
```年`f`ответ пустой, и для`g`тоже пустой. Исключение существует внутри тела`f`、 но оно не выходит из`try`。 Наивный подход, который просто добавляет все`maybethrow`в функцию、олибочно припизет`E`обеим функциям。 

Второй случай связан с подавлением именно вызывающей функции:```
1
2
func f() {
    maybethrow E
}
func g() {
    try {
        f()
    } suppress E
}
```У`f`ありがとう`E`、、、`g`ああ、ね。 Нельзя хранить только обычное ребро`g -> f`、потому что одно и то же вызываемое исключение может распространяться через один вызов и подавляться через другой。 

Третий случай возникает при вложенных обработчиках:```
1
1
func f() {
    try {
        try {
            maybethrow E
        } suppress X
    } suppress E
}
```

`E`подавляется внезним блоком, несмотря на то что внутренний блок подавляет только`X`。 Для конкретного места вызова нужно учитывать все окружающие`try`。 

Наконец、вызовы могут образовывать цикл:```
1
2
func f() {
    g()
}
func g() {
    f()
}
```Здесь ни одна функция ничего сама не выбрасывает, поэтому ответ для обеих функций пуст. Сам факт наличия цикла не создаёт исключение из ничего. Анализ должен находить только исключения、имеющие реальный источник。 

## アプローチ

 Самый прямолинейный вариант состоит в том, чтобы хранить для каждой функции множество известных исключений и многократно просматривать все вызовы. Если вызываемая функция уже умеет выбрасывать`E`、 то добавляем`E`вызывающей функции, если конкретный вызов не находится под подавляющим`try`。 

Такой подход корректен、потому что множество возможных исключений монотонно растёт。 В начале известны только исключения из`maybethrow`、 после этого информация распространяется по вызовам, а процесс заканчивается, когда больго ничего добавить ね。 

Проблема в количестве повторных проходов. При каждом проходе можно обнаружить только одну новую пару вида "функция может выбросить исключение"。 Таких пар не бользе`V * K`、、`V`это число функций, а`K`число типов исключений。 При каждом проходе приходится просматривать до`E`और देखें Даже при ограничениях порядка`1000`今日は`10^9`。 

Здесь помогает другая точка зрения. Зафиксируем один конкретный тип исключения`E`。 Теперь нам не нужно вычислять множества всех исключений одновременно. Нужно только ответить на вопрос, из каких функций может выйти именно`E`。 

問題が解決しました。 Если функция`f`いいえ`g`、 то после нахождения`E`×`g`мы можем попробовать добавить`E`×`f`。 Единственное дополнительное условие состоит в том, что конкретный вызов не должен находиться под обработчиком, और देखें`E`。 

Получается обычный обход графа。 Начальные верзины это функции, в которых`E`действительно может возникнуть и не подавляется непосредственно в месте возникновения. Затем BFS идёт от вызываемых функций к их вызывающим функциям. Каждое обратное ребро разреbolяено только тогда, когда окружающий вызов не подавляет`E`。 

Эта идея также соответствует опубликованному разбору задачи, где предлагается строить граф вызовов и независимо 問題は、それが原因です。 

После обработки всех типов исключений достаточно проходить их в лексикографическом порядке. Когда очередная функция получает исключение, добавляем его в ответ только если там ещё меньзе`x`элементов。 Поскольку исключения рассматриваются от меньзего к бользему, первые`x`добавленных значений автоматически являются требуемыми。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |`O(K * V * E)`|`O(V * K + E)`| 遅すぎる |
 | 最適 |`O(S + K * E + P)`|`O(S + V + E + P)`| 承認済み |

 Здесь`S`обозначает размер исходного текста,`K`Їисло типов исключений、`E`Їисло вызовов, а`P`число реально найденных пар "функция может выбросить исключение"。 В худвем случае`P`ограничено количеством источников и распространений, а при`E <= 1000`графовая часть остаётся небользой。

### なぜ効果があるのか

 Рассмотрим фиксированное исключение`E`。 Инвариант BFS состоит в том, что после заверления обхода функция посещена тогда и только тогда, когда существует цепочка реальных источников`E`и вызовов、по которой`E`доходит до этой функции, не попадая на вызов, подавляющий`E`。 

Все начальные верзины являются настоящими источниками`E`、 потому что исключение возникает через`maybethrow`и не подавляется его контекстом. При переходе по обратному ребру мы проверяем именно тот контекст, в котором находится вызов. Поэтому исключение добавляется к вызывающей функции только в случае, когда оно действительно может пройти Їерез этот вызов. Обратное направление обхода позволяет пройти любую конечную цепочку вызовов, а циклы безопасно обрабатываются массивом посещённых версин.

 Значит, после BFS множество посещённых функций точно совпадает с множеством функций, из которых может ボヘミアン`E`。 Поскольку все типы исключений обрабатываются в лексикографическом порядке, первые`x`исключений、попавлие в ответ каждой функции、являются`x`лексикографически наименьзими。 

## Python ソリューション```python
import sys
import re
from collections import deque

input = sys.stdin.readline

TOKEN_RE = re.compile(r"[A-Za-z0-9_]+|[{}(),]")

def solve():
    x = int(input())
    n = int(input())

    source = sys.stdin.buffer.read().decode()
    tokens = TOKEN_RE.findall(source)
    m = len(tokens)
    pos = 0

    func_id = {}
    func_names = []

    # Context data.
    # Every function gets one root context.
    parent = []
    owner = []
    suppress = []
    direct_throws = []

    # Each call is (caller_function, callee_name, context_id).
    calls = []

    # Exception name -> bit index.
    exc_id = {}
    exc_names = []

    def get_exc_id(name):
        eid = exc_id.get(name)
        if eid is None:
            eid = len(exc_names)
            exc_id[name] = eid
            exc_names.append(name)
        return eid

    for _ in range(n):
        if tokens[pos] != "func":
            raise ValueError("invalid program")

        name = tokens[pos + 1]
        pos += 2

        # ()
        if tokens[pos] != "(":
            raise ValueError("invalid function header")
        pos += 1
        if tokens[pos] != ")":
            raise ValueError("invalid function header")
        pos += 1

        if tokens[pos] != "{":
            raise ValueError("invalid function body")
        pos += 1

        fid = len(func_names)
        func_id[name] = fid
        func_names.append(name)

        root = len(parent)
        parent.append(-1)
        owner.append(fid)
        suppress.append(0)
        direct_throws.append(0)

        # Stack contains contexts whose blocks are currently open.
        # The root context represents the function body.
        block_stack = [root]

        while block_stack:
            tok = tokens[pos]

            if tok == "}":
                pos += 1
                ctx = block_stack.pop()

                if parent[ctx] != -1:
                    # The closing brace belongs to a try block.
                    if tokens[pos] != "suppress":
                        raise ValueError("missing suppress")

                    pos += 1
                    mask = 0

                    while True:
                        exc_name = tokens[pos]
                        pos += 1
                        mask |= 1 << get_exc_id(exc_name)

                        if tokens[pos] != ",":
                            break
                        pos += 1

                    suppress[ctx] = mask

                continue

            if tok == "try":
                pos += 1
                if tokens[pos] != "{":
                    raise ValueError("invalid try")
                pos += 1

                new_ctx = len(parent)
                parent.append(block_stack[-1])
                owner.append(fid)
                suppress.append(0)
                direct_throws.append(0)

                block_stack.append(new_ctx)
                continue

            if tok == "maybethrow":
                pos += 1
                exc_name = tokens[pos]
                pos += 1

                eid = get_exc_id(exc_name)
                direct_throws[block_stack[-1]] |= 1 << eid
                continue

            # The remaining statement form is a function call:
            # name ( )
            callee_name = tok
            pos += 1

            if tokens[pos] != "(":
                raise ValueError("invalid call")
            pos += 1

            if tokens[pos] != ")":
                raise ValueError("invalid call")
            pos += 1

            calls.append((fid, callee_name, block_stack[-1]))

    # Compute all effective suppression masks.
    # Parents are always created before children.
    effective = [0] * len(parent)

    for ctx in range(len(parent)):
        p = parent[ctx]
        if p == -1:
            effective[ctx] = suppress[ctx]
        else:
            effective[ctx] = effective[p] | suppress[ctx]

    # For every exception, keep the functions where it can originate
    # without already being suppressed.
    seed_by_exc = [[] for _ in exc_names]

    for ctx in range(len(parent)):
        possible = direct_throws[ctx] & ~effective[ctx]
        while possible:
            bit = possible & -possible
            eid = bit.bit_length() - 1
            seed_by_exc[eid].append(owner[ctx])
            possible -= bit

    # Reverse call graph:
    # rev[g] contains calls f -> g as (f, suppression_mask).
    rev = [[] for _ in func_names]

    for caller, callee_name, ctx in calls:
        callee = func_id[callee_name]
        rev[callee].append((caller, effective[ctx]))

    order = sorted(range(len(exc_names)), key=exc_names.__getitem__)

    answers = [[] for _ in func_names]
    seen = [0] * len(func_names)
    stamp = 0

    remaining = len(func_names)

    for eid in order:
        if remaining == 0:
            break

        seeds = seed_by_exc[eid]
        if not seeds:
            continue

        stamp += 1
        bit = 1 << eid

        q = deque()

        for f in seeds:
            if seen[f] != stamp:
                seen[f] = stamp
                q.append(f)

        while q:
            g = q.popleft()

            if len(answers[g]) < x:
                answers[g].append(exc_names[eid])
                if len(answers[g]) == x:
                    remaining -= 1

            for caller, blocked in rev[g]:
                if blocked & bit:
                    continue
                if seen[caller] == stamp:
                    continue

                seen[caller] = stamp
                q.append(caller)

    out = []

    for name, ans in zip(func_names, answers):
        out.append(name + ":")
        out.append(str(len(ans)))
        out.extend(ans)

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```Парсер использует регулярное выражение только для выделения идентификаторов и нескольких знаков пунктуации. Пробелы и переводы строк после этого вообще не имеют значения, поэтому программа одинаково работает с компактным и сильно разреженным форматированием исходника.

 жля каждого`try`Создаётся контекст с указателем на родителя. Сам список`suppress`появляется только после закрывающей`}`、 но это не мезбору, поскольку операции внутри блока уже ссылаются на созданный контекст. После получения списка подавляемых исключений маска контекста просто заполняется.

 Использование целого числа как множества исключений существенно упрощает работу с вложенными блоками. Операция`effective[parent] | suppress[ctx]`Сразу объединяет все окружающие обработчики。 Проверка одного исключения выполняется одной операцией`blocked & bit`。 

年`maybethrow`сохраняется не отдельная запись на каждое повторение, а битовая маска исключений, которые непосредственно Созникают в данном контексте. Это уменьзает объём памяти, особенно если один и тот же тип исключения выбрасывается много раз.

 После разбора имена функций вызовов разрезаются через`func_id`。 Обратный граф нужен потому, что BFS начинается с функций-источников. Если`g`жет выбросить`E`、то нас интересуют функции、которые вызывают`g`、 а не функции、которых вызывает`g`。 

Массив`seen`BFS にアクセスします。 Вместо этого используется возрастающий`stamp`。 для нового исключения достаточно увеличить`stamp`、после чего старые значения автоматически считаются неактуальными. Это избавляет от лисего прохода по всем функциям перед каждым обходом.

 Особенность остановки после`x`ответов состоит в том, что обход для самого исключения всё равно продолжается. Одна функция может уже иметь`x`результатов, а другая ещё только получить текущий тип. Исключение нужно распространить полностью, иначе можно случайно пропустить его для другой функции.

### Нет подавления, но несколько разных вызовов

 Если функция вызывает одну функцию под`suppress A`、а другую без обработчика、нельзя хранить единую маску для вызывающей функции. Каждое ребро получает маску своего собственного контекста. Именно поэтому два вызова одной и той же функции могут распространять разные подмножества исключений.

 ### Повторное возникновение одного исключения

 Если`maybethrow E`встречается сто раз в одной функции, результат всё равно содержит только одно`E`。 Битовая маска автоматически убирает дубликаты ещё во время разбора, поэтому размер данных не зависит от количества повторений одного типа исключения。 

### Функция объявлена после вызова

 При разборе вызова имя сохраняется как строка, а разрегение происходит после того, как прочитаны все объявления функций。 Поэтому программа вида```
