## アプローチ

 直接的な解決策は、左から右にコミットをクエリすることです。 コミットから始めます`1`、 それから`2`、最初の応答が返されるまで続行します`0`が表示されます。 最初に失敗したコミットは正確に`m`、以前のすべてのコミットが合格し、その後のすべてのコミットが成功するため、`m`それ以降は失敗します。 もし`m = n`、この方法には必要があります`n`クエリ。 

最大限に`n = 10^6`したがって、最悪の場合は 100 万クエリになります。 このプロトコルでは 25 個しか許可されないため、リニア スキャンは必要以上に遅いだけでなく、ほとんどの入力に対して無効になります。 

ブルートフォース手法が機能するのは、応答に最初の失敗を特定するのに十分な情報が含まれているためです。 重要な観察は、1 つのクエリで、クエリされた位置を特定するだけでなく、間隔全体を削除できることです。 クエリを実行するとします`mid`。 もし答えが`1`、 それから`mid`最初の失敗したコミットの前にあることがわかっているので、それまでのすべての位置`mid`捨てることができる。 もし答えが`0`、 それから`mid`はすでに失敗しているため、最初の失敗位置は またはそれより前である必要があります`mid`。 

これはまさに二分探索に必要な構造です。 間隔をあけております`[lo, hi]`含まれることが保証されているもの`m`。 中間点が成功すると、次のように変化します。`[mid + 1, hi]`、中間点が失敗すると、次のように変化します。`[lo, mid]`。 各クエリにより、考えられる回答の数が約半分になります。 

のために`n <= 10^6`、せいぜい`ceil(log2(10^6)) = 20`クエリが必要です。 これは制限の 25 をゆうに下回っています。

 ## アルゴリズムのチュートリアル

 1.セット`lo = 1`そして`hi = n`。 不変条件は、未知の最初の失敗したコミットであることです。`m`いつも内側にいる`[lo, hi]`。 
2. その間`lo < hi`、 選ぶ`mid = (lo + hi) // 2`そして印刷する`mid`。 標準出力を直ちにフラッシュし、審査員の応答を読みます。 
3. 応答が次の場合`1`、 専念`mid`テストに合格します。 以前のすべてのコミット以来`m`パスとすべてのコミット`m`それ以降は失敗し、`m`厳密に次より大きくなければなりません`mid`。 間隔を次のように置き換えます`[mid + 1, hi]`。 
4. 応答が次の場合`0`、 専念`mid`失敗します。 最初に失敗したコミットをその後にすることはできません`mid`、 なぜなら`mid`それ自体がすでに失敗しています。 間隔を次のように置き換えます`[lo, mid]`。

### なぜ効果があるのか

 あらゆる点で、`[lo, hi]`最初に失敗した真のコミットが含まれています。 最初はこれが真実です。なぜなら、`m`の間にあることが保証されています`1`そして`n`。 中間点が戻った場合`1`、単調性は次のことを示しています。`m > mid`ので、削除します`[lo, mid]`削除できません`m`。 中間点が戻った場合`0`、単調性は次のことを示しています。`m <= mid`ので、削除します`[mid + 1, hi]`削除できません`m`。 したがって、不変式はすべてのクエリで存続します。 

各反復では、間隔のサイズを維持しながら厳密に減少します。`m`。 最終的に`lo`そして`hi`平等になる。 唯一残っている可能な位置は真であるため、`m`、その位置が正しく印刷されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    lo = 1
    hi = n

    while lo < hi:
        mid = (lo + hi) // 2

        print(mid, flush=True)
        response = input().strip()

        if response == "1":
            lo = mid + 1
        else:
            hi = mid

    print("!", lo, flush=True)

if __name__ == "__main__":
    solve()

中間点は次のように計算されます。`(lo + hi) // 2`。 Python の整数はオーバーフローしませんが、十分な幅の整数型を持つ言語では同じ式も安全です。`n`だけです`10^6`。 

クエリは次のように出力されます`flush=True`。 これは対話型の問題では不可欠です。 フラッシュしない場合、Python はクエリを出力バッファーに保持し、プログラムが応答を待っている間、ジャッジを待機させたままにすることがあります。

## 特殊なケース

 いつ`n = 1`、初期間隔は`[1, 1]`したがって、ループはスキップされ、プログラムはすぐに出力します。`! 1`。 具体的なインプットとしては`1`、唯一のコミットは最初に失敗したコミットでなければならないため、有効な代替回答はありません。

最も一般的な off-by-one エラーは、クエリされたコミットが失敗した場合に発生します。 と`n = 5`そして`m = 3`、クエリする`3`返品`0`。 正しい新しい間隔は次のとおりです。`[1, 3]`、 ない`[1, 2]`、コミットするため`3`それ自体が最初の失敗かもしれません。 課題`hi = mid`その候補者を保持します。
