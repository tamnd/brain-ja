 ## 問題の理解

 非常に大きな非負の整数が 1 つ与えられます。$N$10進数で書かれます。 概念的には、この数値を 0 ～ 5 の数字を使用し、数値の 0 自体を除いて先頭に 0 を付けずに、6 進数で書き換えたいと考えています。 その表現を構築する代わりに、base 6 表現に含まれる桁数を決定するだけで済みます。 

したがって、タスクは純粋に次の表現の長さに関するものです。$N$底6で。 

制約$0 \le N < 10^{5{,}000{,}000}$重要なことを教えてくれます。$N$は、標準の整数型に収まるには大きすぎるため、組み込み型の算術演算を使用してこれをバイナリまたは基数 6 に直接変換することさえ不可能です。 入力は文字列として扱う必要があり、どのソリューションでも数値に比例する演算を回避する必要があります。$N$。 代わりに、10 進数のみをスキャンできます。 

重要な数学的観察は、答えは次の要素のみに依存するということです。$\lfloor \log_6(N) \rfloor + 1$のために$N > 0$、そして 1 の場合$N = 0$。 

単純な間違いは、繰り返し分割しようとすることです。$N$大きな整数演算を使用して 6 をゼロになるまで計算します。 原理的には正しいですが、最大 500 万桁の数値の各除算は次のように行われるため、これは実行不可能になります。$O(n)$、そして必要になるかもしれません$O(\log_6 N)$このような分割により、全体的な複雑さが生じます。$O(n \log N)$、最悪の場合には遅すぎます。 

もう 1 つの微妙なエッジ ケースは、先行ゼロです。 入力形式では先頭のゼロは明示的に禁止されていませんが、値を正しく解釈するには、「0」、「00」、「000」をすべて同じ数値として扱う必要があります。 それらすべての出力は 1 になるはずです。 

## アプローチ

 ブルートフォース手法は、10 進数の文字列を 6 で繰り返し除算し、桁ごとに長い除算をシミュレートし、数値がゼロになるまでの反復回数をカウントすることです。 各部門は文字列全体をスキャンします。$d$10 進数と基数 6 の長さは次のとおりです。$k$、複雑さは$O(d \cdot k)$。 最悪の場合、$d$最大 500 万に達する可能性があるため、このアプローチは完全に実行不可能になります。 

重要な洞察は、実際には基数 6 の数字自体が必要ではなく、その数だけが必要であるということです。 の桁数$N$基数 6 は比較によって決定されます$N$6 の累乗。数値を変換する代わりに、比較します。$N$と$6^k$。 これにより、問題は最小のものを見つけることに減ります。$k$そのような$6^k > N$、または同等の$k = \lfloor \log_6(N) \rfloor + 1$。 

以来$N$は 10 進数で文字列として与えられるので、同じく文字列として表される 6 のべき乗と比較できます。 可能な最大サイズを超えるまで、10 進数の 6 の累乗を事前計算します。これはすぐに起こります。$6^k$指数関数的に成長します。 10 進数 500 万桁であっても、base6 の長さはわずか約です$O(\log_6(10^{5{,}000{,}000})) \approx 2{,}000{,}000$したがって、必要なべき乗の数は入力サイズに比べて小さく、安全な限界まで事前計算できます。 

最後の戦略は、6 の累乗を文字列として段階的に計算し、長さと値を辞書順に比較することです。$N$。

 ## アルゴリズムのチュートリアル

 1. 入力された番号を読み取ります$N$文字列として指定し、先頭のゼロを削除します。 結果の文字列が空の場合は、数値をゼロとして扱い、すぐに 1 を返します。 これは、値が正確にゼロである縮退の場合を処理します。 
2. 6 のべき乗を「1」から始まる 10 進数の文字列として格納する変数を初期化します。これは、以下に対応します。$6^0$。 カウンタも初期化します$k = 0$、現在の指数を表します。 
3. 文字列ベースの乗算を使用して、現在の累乗を 6 で繰り返し乗算します。 乗算するたびにインクリメントします$k$。 これにより、$6^k$10進数形式で。 
4. それぞれの新しい電力を生成した後、それを比較します。$N$。 現在の電力が厳密に次の値よりも大きくなった場合、$N$、ループを停止します。 正しい桁の長さは次のようになります。$k$、 以来$6^k$を超える$N$、 意味$N$せいぜい収まる$k$基本6桁。 
5. 戻る$k$最終的な答えとして。 

正しさは、6 進数の数字の長さがまさに最小であるという事実から来ています。$k$そのような$N < 6^k$。 反復ごとに、追加の桁が必要な次のしきい値に移動します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def strip_leading_zeros(s):
    s = s.lstrip('0')
    return s if s else "0"

def compare_decimal_strings(a, b):
    if len(a) != len(b):
        return len(a) - len(b)
    if a == b:
        return 0
    return 1 if a > b else -1

def mul_small_decimal_string(num, x):
    carry = 0
    res = []
    for ch in reversed(num):
        cur = (ord(ch) - 48) * x + carry
        res.append(chr(cur % 10 + 48))
        carry = cur // 10
    while carry:
        res.append(chr(carry % 10 + 48))
        carry //= 10
    return ''.join(reversed(res))

def solve():
    s = strip_leading_zeros(input().strip())
    if s == "0":
        print(1)
        return

    power = "1"
    k = 0

    while True:
        cmp = compare_decimal_strings(power, s)
        if cmp > 0:
            print(k)
            return
        power = mul_small_decimal_string(power, 6)
        k += 1

if __name__ == "__main__":
    solve()
```コードはまず、先頭のゼロを削除して入力を正規化し、ゼロのすべての表現が一貫して動作することを保証します。 比較関数は、最初に長さを比較し、必要な場合にのみ辞書編集的に比較することにより、整数に変換せずに大きな 10 進数の文字列を処理します。 

乗算ルーチンは、文字列に適用される標準的な小学校の乗算です。6 を繰り返し乗算するだけなので、これで十分です。桁の増加は、問題が示す範囲内で管理可能です。 

ループは次の不変条件を維持します。`power`常に等しい$6^k$そして、この力が超えたときに正確に停止します$N$。
