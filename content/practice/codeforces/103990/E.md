 ## 解決策
 ## 問題の理解

 大きな整数が与えられます$k$、そしてその値を表現したいのです$k^2$2 つの特別な値の合計として。 各値は、整数でインデックス付けされた固定セットから取得されます。$x$範囲内で$1 \le x \le 2125$、およびインデックスに関連付けられた値$x$は$x^1$、それはまさに$x$自体。 

したがって、タスクは 2 つの異なるインデックスを選択することになります。$x < y$そのような$$x + y = k^2$$そして両方とも$x$そして$y$許容範囲内に収まります。 

すべての有効なペアのうち、最小化するペアを返さなければなりません。$x + y$。 すべての有効なペアはすでに満たされているため、$x + y = k^2$、この条件は実際にはすべてのソリューションにわたって一定です。 したがって、実現可能性が満たされた場合、ソリューションを区別する本当の制約は、最適化ではなく存在です。 

唯一の難点は、大きな制約があることです。$k$、 まで$4 \cdot 10^{18}$、これにより、$k^2$巨大で、64 ビットの範囲をはるかに超えています。 ただし、インデックスの範囲は小さく、最大 2125 までしかないため、有効な合計も非常に小さい間隔内に収まる必要があります。 

重要な構造的意味は、小さな境界領域内で整数のペアを検索しており、その合計が潜在的に巨大なターゲットに等しいということです。 これは、ほとんどの入力は不可能であり、非常に特殊な入力のみであることを即座に示唆しています。$k$値は有効な分解を生成できます。 

単純な間違いは、すべてのペアを反復しようとすることです。$(x, y)$かどうかを確認します$x + y = k^2$。 それは正しいですが、不必要です。 もう 1 つの間違いは、計算しようとすることです。$k^2$標準整数型で直接使用すると、大きな整数を持たない言語ではオーバーフローします。 Python はこれを回避しますが、推論は実際の計算ではなく境界に依存する必要があります。 

微妙なエッジケースは、ペアが存在しない場合です。 たとえば、次の場合$k^2 < 3$、範囲内の 2 つの異なる正の整数の合計を求めることはできません。 もう 1 つのエッジケースは次のような場合です$k^2$を超える$2125 + 2124 = 4249$この場合、許可されたドメイン内で可能な最大合計が制限されているため、有効なペアも存在しません。 

## アプローチ

 ブルートフォースアプローチは簡単です。 すべてのペアを反復処理します$(x, y)$と$1 \le x < y \le 2125$、それらの合計を計算し、それが等しいかどうかを確認します。$k^2$。 くらいあるので、$\frac{2125^2}{2} \approx 2.2 \cdot 10^6$ペアの場合、これは単独でもすでに実現可能です。 ただし、問題に複数のクエリが含まれている場合、または範囲の上限が大きい場合、このアプローチは非効率的になります。 解空間全体を直接列挙するため、その正しさは自明です。 

重要な点は、実際には両方の変数を検索する必要がないということです。 一度$x$選ばれて、$y$として完全に決定されます$k^2 - x$。 これにより、問題は 1 回のパスオーバーに変換されます。$x$、暗黙的に$y$有効であり、範囲内です。 

これにより、検索空間が 2 次から線形に縮小されます。 また、ペアを最小化したいという事実も利用します。$x + y$ただし、すべての有効なペアは同じ合計を共有するため、代わりにスキャンすることで暗黙的に最小化します。$x$昇順で最初の有効なペアを返します。

 ## アルゴリズムのチュートリアル

 ### 重要なアイデア

 ペアの一方の端点を修正し、もう一方の端点を推定します。 許可されたインデックス範囲内にあるペアのみを受け入れます。 

### ステップ

 1. 目標値を計算する$S = k^2$。 

固定幅の整数演算には依存しません。 概念的には、これは任意の精度の値です。 
2. 反復する$x$1 から 2125 まで。 

最初の有効なペアには自動的に可能な限り最小の値が含まれるため、昇順にスキャンします。$x$、これは最小化と一致します。$x + y$。 
3. それぞれについて$x$、計算する$y = S - x$。 

これは、次とペアになる唯一の候補値です。$x$目標金額を達成するために。 
4. かどうかを確認します。$y$は有効なインデックスです。つまり、$1 \le y \le 2125$。 

そうでない場合は、これを破棄してください$x$。 これにより、両方の要素が利用可能なセットから取得されるようになります。 
5. 確認する$x < y$。 

これにより、ペアの重複が回避され、区別性が保証されます。 もし$x = y$、それは 2 つの異なるオーブの要件に違反します。 
6. 有効なペアが見つかった場合は、出力します。$x$そして$y$、その後終了します。 

小さいものから大きいものまでスキャンするため、早期終了は正しいです$x$最低限の保証をする$x$、したがって最小限の$x + y$実現可能な解決策の中で。 
7. ループ後にペアが見つからない場合は、-1 を出力します。 

### なぜ効果があるのか

 このアルゴリズムは、すべての有効な解が 1 回の反復に正確に対応するという不変式に依存しています。$x$はペアの小さい方の要素です。 実行可能な分解に対して$S = x + y$、ループがその特定に到達したとき$x$、計算された$y$一致し、範囲チェックに合格します。 考えられるものをすべて列挙してみますので、$x$、有効なペアを見逃すことはできません。 順序付けにより、必要なタイブレーク ルールの下で最初の一致が最適であることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

k = int(input().strip())
S = k * k

LIMIT = 2125

for x in range(1, LIMIT + 1):
    y = S - x
    if 1 <= y <= LIMIT and x < y:
        print(x, y)
        break
else:
    print(-1)
```このコードは、合計条件の書き換えから得られる 1 次元検索を直接実装します。 ループ構造は重要です。`for ... else`パターンにより印刷のみが保証されます`-1`有効な分解が見つからない場合。 

微妙な実装ポイントは、Python の任意精度の整数を使用することです。$k^2$。 低レベル言語では、オーバーフローを避けるために慎重な処理が必要になりますが、ここでは安全に直接計算できます。 

条件`x < y`一意性を強制し、対称ソリューションの重複を防ぎます。 昇順にスキャンするので、$x$の場合、最初の有効なペアは自動的に辞書編集上最小となるため、タイブレーク ルールの下では最適になります。

 ## 特殊なケース

 ### 非常に小さい$k$のために$k = 1$、$S = 1$。 ループチェック$x = 1$、与える$y = 0$、これは無効です。 他に候補がないため、出力は -1 になります。 このアルゴリズムは、合計が実行可能な区間の外にある場合、不可能な分解を正しく拒否します。 

＃＃＃ 大きい$k$のために$k = 4 \cdot 10^{18}$、$S$天文学的に大きいです。 あらゆる人にとって$x \in [1, 2125]$、$y = S - x$許容範囲を大きく超えています。 アルゴリズムはすべての候補を拒否し、-1 を出力します。 これは、この方法が次のものの大きさに依存しないことを示しています。$k$、誘導合計のみ。 

### 仮説上の有効なケース

 ペアが存在する場合$(x, y)$そのような$x + y = k^2$、ループが到達すると$x$、計算された$y$正確に一致し、境界を通過します。 アルゴリズムはその時点で直ちに終了し、解の建設的な回復を通じて正確さを確認します。
