 ## 解決策
 ## 問題の理解

 値の配列と長い更新シーケンスが与えられます。 各クエリは、セグメント全体を定数ずつ増やすか、セグメントを定数値で上書きするか、または特定のサブ配列に特別な「バランスのとれた」プロパティがあるかどうかを尋ねます。 

サブ配列内にインデックス k が存在し、各要素を取得して k からの距離を乗算すると、符号付きの重み付き合計がゼロになる場合、そのサブ配列はバランスが取れていると見なされます。 言い換えれば、k は配列がシーソーのように完全にバランスをとるピボットのように機能し、左右の値が重み付けされた寄与に関して互いに打ち消し合います。 

タイプ 3 の各クエリは、この意味で特定のサブ配列のバランスを取ることができるかどうかを尋ねます。 問題は、配列が頻繁に変更されるため、クエリごとにすべてを最初から再計算することができないことです。 

この制約により、単純に部分配列のプロパティを再計算することが直ちに排除されます。 配列の長さは最大 100,000 ですが、演算数は 120 万に達する可能性があります。 クエリごとにセグメントをスキャンするソリューションでは、オペレーションごとに 1 回のリニア スキャンでも、最悪の場合約 10¹¹ のオペレーションが発生するため、必然的にタイムアウトになります。 

2 番目の重要な問題は、更新が単純なポイント変更ではないことです。 これらは範囲の追加と範囲の割り当てであり、両方とも一度に多くの位置に影響を与えます。 これにより、遅延伝播をサポートするデータ構造へとソリューションが推進されます。 

素朴なアプローチの微妙な失敗例は、「k の存在」条件の誤解から生じます。 たとえば、セグメント [1, 2, -1] について考えてみましょう。 単純な考えでは、中間点でバランスをチェックしたり、対称性のような動作を想定したりしようとするかもしれませんが、正しい状態は幾何学的直観ではなく加重和に依存します。 別の失敗例は、セグメント内のすべての値がゼロになる場合に発生します。 その場合、k のすべての選択が方程式を満たすため、答えは常に「はい」になる必要がありますが、ゼロのケースをチェックせずに合計で割ると、これを見逃しやすくなります。 

## アプローチ

 直接的なアプローチでは、セグメントを反復処理し、条件を最初から計算することで各クエリに応答します。 長さ m のセグメントの場合、値の合計とインデックスに値を乗算した加重合計の 2 つの量を計算します。 これらから、有効なピボットが存在するかどうかを導き出すことができます。 これは正しく機能しますが、各クエリのコストは O(m) であり、最大 120 万のクエリを使用すると、非常に遅くなります。 

重要な観察は、バランス条件がセグメント全体にわたる 2 つの集計値のみに依存するということです。 S を要素の合計として定義し、T を i * a[i] の合計として定義すると、条件は S と T の単純な代数方程式になります。これは、クエリ時にセグメント内の個々の要素を知る必要はなく、これら 2 つの集計だけを知る必要があることを意味します。 

問題が 2 つの異なる量の範囲の合計を維持することに帰着すると、その構造は標準になります。 セグメント ツリーは、間隔ごとに S と T を維持できます。 範囲の追加操作と範囲の割り当て操作は、これらの集計の更新に変換できます。 唯一の追加要素は、T がインデックスに依存するため、各ノードは値の合計だけでなく、値の変化によって重み付けされたインデックスの合計も格納する必要があることです。 

幾何学的バランシング条件からプレフィックス集計を使用した定数時間チェックへの変換により、ソリューションが効率化されます。 その後は、古典的な遅延伝播の問題です。

 | --- | --- | --- | --- |
 | ブルートフォース | O(nq) | お(1) | 遅すぎる |

 ## アルゴリズムのチュートリアル

各ノードが 3 つの情報 (セグメント内の値の合計、セグメント内のインデックスの合計、範囲割り当てと範囲追加のための遅延タグのペア) を保存するセグメント ツリーを維持します。 

明確にするために、len をセグメント長、idxSum をそのセグメント内のインデックスの合計とします。どちらもノード構造ごとに事前に計算されます。 

### 1. 各セグメント ツリー ノードの構造情報を事前計算します。 

各ノードは、その間隔 [l, r]、その長さ、およびその間隔内のインデックスの合計を知っています。 これにより、値が一様に変化する場合に加重合計を高速に再計算できます。 

これが必要な理由は、更新が値の大きさと位置の両方に依存するため、構造情報を動的な値から分離する必要があるためです。 

### 2. ノードごとに 2 つのアグリゲートを維持する

 各ノードは、a[i] の合計である S と、i * a[i] の合計である T を格納します。 これら 2 つの値は、セグメントのバランスのとれた状態を完全に表します。 

この削減が機能するのは、バランス方程式がこれら 2 つの合計の一次式に展開されるためです。 

### 3. ハンドル範囲の割り当て

 セグメントを定数 x に設定すると、S は長さの x 倍になり、T はインデックスの合計の x 倍になります。 以前の構造はすべて上書きされるため、遅延加算はクリアされます。 

これにより、個々の要素に触れる必要がなく、セグメントの一貫性が保たれます。 

### 4. ハンドル範囲の追加

 セグメント内のすべての要素に x を追加すると、S は x 倍の長さだけ増加します。 T はインデックスの合計の x 倍だけ増加します。 これは、各位置 i が x * i の追加の寄与を得るために機能します。 

### 5. 代数を使用してクエリに答える

 クエリ セグメントの場合、S と T を計算します。 

S が 0 に等しい場合、条件は T が 0 に等しいことを要求します。 両方がゼロの場合、どのピボットも機能するため、答えは肯定になります。 

S がゼロ以外の場合、ピボットは k = T / S です。答えは、k が整数で、セグメント境界内にある場合にのみ有効です。 

### なぜ効果があるのか

 重要な不変条件は、すべての遅延操作を適用した後、すべてのセグメント ツリー ノードについて、S と T が常に、表現されたセグメントの値の真の合計とインデックスの加重合計に正確に一致することです。 すべての更新ルールは各操作の代数的寄与を保存するため、情報が失われることはありません。 クエリ条件は、バランス方程式を解決可能な線形形式に書き直すことによって直接導出されるため、正確性は配列の構造特性ではなく算術一貫性の検証に帰着します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

class Node:
    __slots__ = ("s", "t", "add", "assign", "has_assign")
    def __init__(self):
        self.s = 0
        self.t = 0
        self.add = 0
        self.assign = 0
        self.has_assign = False

class SegTree:
    def __init__(self, a):
        self.n = len(a) - 1  # 1-indexed
        self.tree = [Node() for _ in range(4 * self.n)]
        self.build(1, 1, self.n, a)

    def build(self, idx, l, r, a):
        if l == r:
            self.tree[idx].s = a[l]
            self.tree[idx].t = a[l] * l
            return
        mid = (l + r) // 2
        self.build(idx*2, l, mid, a)
        self.build(idx*2+1, mid+1, r, a)
        self.pull(idx)

    def pull(self, idx):
        left = self.tree[idx*2]
        right = self.tree[idx*2+1]
        self.tree[idx].s = left.s + right.s
        self.tree[idx].t = left.t + right.t

    def apply_assign(self, idx, l, r, x):
        node = self.tree[idx]
        node.s = x * (r - l + 1)
        node.t = x * (r + r - (r - l)) * (r - l + 1) // 2  # sum i from l to r * x
        node.has_assign = True
        node.assign = x
        node.add = 0

    def apply_add(self, idx, l, r, x):
        node = self.tree[idx]
        node.s += x * (r - l + 1)
        node.t += x * (l + r) * (r - l + 1) // 2

        if node.has_assign:
            node.assign += x
        else:
            node.add += x

    def push(self, idx, l, r):
        node = self.tree[idx]
        if l == r:
            return
        mid = (l + r) // 2
        if node.has_assign:
            self.apply_assign(idx*2, l, mid, node.assign)
            self.apply_assign(idx*2+1, mid+1, r, node.assign)
            node.has_assign = False
        if node.add != 0:
            self.apply_add(idx*2, l, mid, node.add)
            self.apply_add(idx*2+1, mid+1, r, node.add)
            node.add = 0

    def update_add(self, idx, l, r, ql, qr, x):
        if ql <= l and r <= qr:
            self.apply_add(idx, l, r, x)
            return
        self.push(idx, l, r)
        mid = (l + r) // 2
        if ql <= mid:
            self.update_add(idx*2, l, mid, ql, qr, x)
        if qr > mid:
            self.update_add(idx*2+1, mid+1, r, ql, qr, x)
        self.pull(idx)

    def update_assign(self, idx, l, r, ql, qr, x):
        if ql <= l and r <= qr:
            self.apply_assign(idx, l, r, x)
            return
        self.push(idx, l, r)
        mid = (l + r) // 2
        if ql <= mid:
            self.update_assign(idx*2, l, mid, ql, qr, x)
        if qr > mid:
            self.update_assign(idx*2+1, mid+1, r, ql, qr, x)
        self.pull(idx)

    def query(self, idx, l, r, ql, qr):
        if ql <= l and r <= qr:
            return self.tree[idx].s, self.tree[idx].t
        self.push(idx, l, r)
        mid = (l + r) // 2
        s = t = 0
        if ql <= mid:
            s1, t1 = self.query(idx*2, l, mid, ql, qr)
            s += s1
            t += t1
        if qr > mid:
            s2, t2 = self.query(idx*2+1, mid+1, r, ql, qr)
            s += s2
            t += t2
        return s, t

def main():
    n, q = map(int, input().split())
    arr = [0] + list(map(int, input().split()))
    st = SegTree(arr)

    out = []

    for _ in range(q):
        tmp = input().split()
        if tmp[0] == '1':
            l, r, x = map(int, tmp[1:])
            st.update_add(1, 1, n, l, r, x)
        elif tmp[0] == '2':
            l, r, x = map(int, tmp[1:])
            st.update_assign(1, 1, n, l, r, x)
        else:
            l, r = map(int, tmp[1:])
            s, t = st.query(1, 1, n, l, r)
            m = r - l + 1
            if s == 0:
                out.append("Yes" if t == 0 else "No")
            else:
                if t % s != 0:
                    out.append("No")
                else:
                    k = t // s
                    out.append("Yes" if l <= k <= r else "No")

    print("\n".join(out))

if __name__ == "__main__":
    main()
```この実装では、セグメントごとに 2 つの独立した集計が維持されます。 1 つ目は値の合計で、2 つ目はインデックスで加重された値の合計です。 すべての更新は両方を一貫して変更し、遅延伝播により操作の構成における正確性が保証されます。 クエリ ロジックは、導出された代数条件を直接適用します。 

実装の微妙な点は、代入タグと追加遅延タグの間の相互作用です。 割り当ては以前の追加をオーバーライドする必要があり、押し下げられた場合は、さらに増分を適用する前に子の状態を完全にリセットする必要があります。 この順序を逆にすると、不正確な累積が発生します。 

もう 1 つの重要な詳細は、すべての計算が正確な整数演算に依存していることです。 Python は大きな整数を安全に処理するため、低レベル言語で発生するオーバーフローの問題を回避できます。 

## 実用的な例

 ### 例 1

 入力セグメント: [1、2、3]

 | ステップ | S (和) | T (加重和) | 決定 |
 | --- | --- | --- | --- |
 | クエリ全体 | 6 | 14 | チェックk |
 | k = T/S | | 14/6 整数ではありません | いいえ |

 整数ピボットが完全なキャンセルを生成しないため、セグメントのバランスが取れません。 

### 例 2

 入力セグメント: [1, 2, 1]

 | ステップ | S | た | 決定 |
 | --- | --- | --- | --- |
 | クエリ | 4 | 8 | k = 2 |
 | 境界をチェックする | | 2 の [1,3] | はい |

 これにより、インデックス 2 に有効なピボットが存在することが確認されます。

 ## 特殊なケース

 1 つの重要なエッジ ケースは、セグメントの合計がゼロになるときに発生します。 その状況では、S で除算することは不可能であるため、正しいロジックは、加重和もゼロかどうかを確認することに完全に切り替わります。 たとえば、値が正確に相殺されるセグメントを考えてみましょう。 このアルゴリズムは S = 0 を正しく検出し、「Yes」を返す前に T = 0 を検証して、無効な除算を回避します。 

計算されたピボット k が正確に境界上にある場合、別のエッジ ケースが発生します。 この条件では k がセグメント内にある必要があるため、k = l または k = r のような値が有効であり、実装では内部配置を想定するのではなく、この範囲を明示的にチェックします。 

最後の微妙なケースは、加算の後に割り当てが行われる、混合更新が繰り返される場合に発生します。 遅延伝播ロジックにより、定数の上書きを適用する前に、割り当てによって保留中の追加がすべてクリアされ、すべての子孫にわたって S と T の両方の一貫性が維持されます。
