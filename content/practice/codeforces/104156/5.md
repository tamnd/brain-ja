 ## 問題の理解

 私たちには次のようなシステムが与えられています$n$すべてのエンジンが同じ制御パラメータを受け取る$x$、これはグローバル電圧と考えることができます。 各エンジンはこの電圧に区分的に線形に反応します。 すべてのエンジン$i$閾値がある$z_i$。 電圧がこのしきい値以下の場合、エンジンは最初のモードになり、次の値に比例した出力を供給します。$a_i x$。 電圧がしきい値を超えると、エンジンの動作が切り替わり、パワーが低下します。$a_i z_i + b_i (x - z_i)$、つまり、傾きに応じて直線的に成長します。$b_i$ブレークポイントの後、連続性を維持しながら$z_i$。 

目標は、最小の整数電圧を選択することです$x$すべてのエンジン出力の合計が少なくとも$p$。 

制約はエンジンの数が少ないため、$n \le 100$、しかしターゲットパワー$p$と同じ大きさにすることができます$10^{12}$したがって、最終電圧も非常に大きくなる可能性があります。 これは、すべての状態を構築またはシミュレートすることによって答えが見つかるのではなく、むしろ検索することによって答えが見つかることを直ちに示唆しています。$x$そして、任意の固定電力の総電力を迅速に計算できるようになります。$x$。 

素朴なアプローチは、増加を試みることです$x$1 から順に計算し、毎回合計電力を計算します。 これは正しいですが、実行不可能な可能性があります。$x$くらいまで成長する必要があるかもしれない$10^{12}$、各評価コスト$O(n)$、につながる$10^{14}$最悪の場合の運用。 

エンジンが異なるしきい値でレジームを切り替える場合、より微妙な問題が発生します。 不用意に実装すると、1 つの式だけを誤って適用したり、エンジンが異なると動作が異なる時点で変化することを忘れたりする可能性があります。 たとえば、すべてのエンジンが異なる場合、$z_i$、関数の構造は、単一の線形関数ではなく、多くの「ねじれた」線の合計になります。 

重要な観察は、総電力が次の関数であるということです。$x$単調非減少であり、値のみにブレークポイントがある区分線形です。$z_i$。 これにより二分探索が行われます$x$関数を効率的に評価できる限り、有効です。 

## アプローチ

 ブルートフォース戦略は単純明快です。$x = 1$、合計電力を計算し、その値に達したら停止します。$p$。 各評価ではすべてのエンジンをスキャンし、以下に基づいてその寄与度を計算します。$x \le z_i$か否か。 これが機能するのは、関数が単調であるためです。したがって、必要な累乗を超えると、答えが見つかります。 ただし、最悪の場合、答え自体が非常に大きくなる可能性があり、最大で$10^{12}$反復、各コスト$O(n)$が遅すぎます。 

問題の構造は単調性を示唆しています: 増加$x$両方の勾配があるため、エンジンの寄与が減少することはありません。$a_i$そして$b_i$ポジティブです。 これにより、線形検索を二分検索に置き換えることができます。$x$。 残りの要件は、固定システムの総電力を迅速に評価する方法です。$x$。 

固定の場合$x$、各エンジンは一定時間内に独立して評価されるため、総出力の計算は次のようになります。$O(n)$。 十分に広い範囲にわたる二分探索と組み合わせることで、効率的な解決策が得られます。 

また、二分探索の安全な上限を決定する必要もあります。 単純な境界は$10^{18}$、最大傾きの合計でも次の制限があるため、$10^6$、そのような範囲を乗算すると、余裕で超えます$10^{12}$。

 ## アルゴリズムのチュートリアル

 問題を最小値を見つけるものとして扱います$x$単調関数となる$F(x)$少なくとも到達する$p$。 

1. 関数を定義する$F(x)$総電力を計算します。 各エンジンごとに$i$、 もし$x \le z_i$、私たちは使用します$a_i x$。 それ以外の場合は使用します$a_i z_i + b_i (x - z_i)$。 これにより、単純化エラーなしで区分定義が直接エンコードされます。 
2.二分探索範囲を設定する$[0, R]$、 どこ$R$答えを安全に含めるのに十分な大きさです。$10^{18}$。 これにより、必要な正確な最大電圧についての推論が回避されます。 
3. 中間点を繰り返し選択します$m$、計算する$F(m)$と比較してください。$p$。 
4. もし$F(m) \ge p$、私たちは答えが最大であることを知っています$m$なので、右の境界を次のように移動します。$m$。 それ以外の場合は、左側の境界を次の位置に移動します。$m + 1$。 
5. 検索が収束するまで続行し、左側の境界を出力します。 

それが機能する理由は単調性に関係しています。 各エンジンの貢献度は減少していません。$x$, したがって、それらの合計も減少しません。 一度値が$x$十分な値であれば、それより大きな値でも十分です。 これにより、二分探索が真の答えを決して破棄せず、常に最小の有効な答えに収束することが保証されます。$x$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, p = map(int, input().split())
engines = [tuple(map(int, input().split())) for _ in range(n)]

def power(x):
    total = 0
    for z, a, b in engines:
        if x <= z:
            total += a * x
        else:
            total += a * z + b * (x - z)
    return total

lo, hi = 0, 10**18

while lo < hi:
    mid = (lo + hi) // 2
    if power(mid) >= p:
        hi = mid
    else:
        lo = mid + 1

print(lo)
```機能`power(x)`は区分的定義の直接翻訳です。 二分探索では、以下のすべての値が一致するという不変条件が維持されます。`lo`が不十分であり、すべての値が以上である`hi`十分です。 選択された上限により、Python でのオーバーフローの問題が回避され、終了が保証されます。 

よくある落とし穴は、関数を誤って 1 つの線形形式に単純化しようとすることです。 これは、異なるエンジンが異なるポイントで勾配を切り替えるため、失敗します。 もう 1 つの微妙な問題は、二分探索における off-by-one の処理です。これは、ここでは常に最初の有効な値に向かって縮小することによって処理されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, p = map(int, input().split())
    engines = [tuple(map(int, input().split())) for _ in range(n)]

    def power(x):
        total = 0
        for z, a, b in engines:
            if x <= z:
                total += a * x
            else:
                total += a * z + b * (x - z)
        return total

    lo, hi = 0, 10**18
    while lo < hi:
        mid = (lo + hi) // 2
        if power(mid) >= p:
            hi = mid
        else:
            lo = mid + 1
    return str(lo)

# minimum case

# all equal thresholds

 ## 特殊なケース

 エッジ ケースの 1 つは、すべてのエンジンがたとえ小さいエンジンであってもすでにしきい値を超えている場合です。$x$。 たとえば、次の場合$x > \max z_i$、すべてのエンジンは常に 2 番目のモードになります。 評価関数は一貫して 2 番目の式を使用し、単調性が維持されるため、アルゴリズムはこれを引き続き正しく処理します。 関数は傾きのある単純な線形成長になるため、二分探索はすぐに収束します。$\sum b_i$。 

もう 1 つのケースは、エンジンがモードをまったく切り替えない場合です。$x$常にすべての下にある$z_i$。 そのシナリオでは、すべてのエンジンは常に最初の領域にあり、システムは単一の線形関数に還元されます。$\sum a_i x$。 評価では 2 番目の分岐が使用されないため、二分探索は依然として正しく動作します。 

より微妙なシナリオは、一部のエンジンが非常に大きな$z_i$、その他は非常に小さいです。 関数には複数の傾き変化がありますが、各評価で寄与が直接再計算されるため、アルゴリズムはブレークポイントを明示的に追跡する必要はありません。 正確さは、全体的な傾斜構造を事前に計算するのではなく、各ステップで正確な定義を評価することで得られます。
