 ## 解決策
 ## 問題の理解

 地図は`n x m`トロイダルグリッド。 上下左右の端の外側に移動すると、反対側に回り込みます。 開始部屋は左上隅です。 一部の部屋には のマークが付いたヒントが含まれています`X`。 

部屋にあるヒント`(i, j)`は、開始点から通常のマンハッタンまでの距離が小さいすべてのヒントがすでに収集された後にのみ利用可能になります。 距離はラッピングの動きには影響されません。`i + j`ゼロベースの座標を使用する場合。 すべてのヒント ルームを有効な順序で訪問する一連の動きを出力する必要があります。 

ディメンションは最大 100 なので、部屋の数は最大 10000 です。 すべての部屋から大量のグラフ検索を行うソリューションでは、すでに数億回近くの操作が必要になるため、不要です。 重要な制限はグリッドのサイズではなく、最初の訪問に必要な順序です。 マンハッタンの距離の増加に自然に追従する建設が必要です。 

よくある間違いは、スタート ルームから通常の DFS を実行することです。 DFS は、同じまたはそれより短い距離にある別の部屋にアクセスする前に、1 つのブランチに深く入ることができます。 例えば：```
3 3
S..
X..
..X
```部屋`(3,1)`1 つのベースのインデックスには距離があります`2`、 その間`(1,2)`距離がある`1`。 最初にダウンした DFS はその距離に入ろうとする可能性があります`2`距離を集める前に部屋`1`ヒント。 

もう 1 つの間違いは、一時的に距離を伸ばす動きを使用して斜めに移動することです。 たとえば、からの移動`(2,2)`に`(3,1)`下に降りて最初に入る`(3,2)`、距離が長く、まだロックされている可能性があります。 

ソリューションは、等しい距離のレイヤーにある部屋を訪問する必要があり、レイヤー内のすべての移動は、現在または前のレイヤーの部屋のみを通過する必要があります。 

## アプローチ

 直接的なアプローチは、次に利用可能なヒントを繰り返し検索することです。 すべての距離値について、BFS を実行し、現在到達可能なすべての部屋を見つけることができます。 BFS はロックされていない部屋のセットを尊重するため、これは正しいですが、繰り返しの検索は無駄です。 最悪の場合、10,000 の部屋があり、10,000 の部屋のグラフを何度も検索するのは必要以上に手間がかかります。 

重要な観察は、同じ距離にあるすべての部屋が 1 つの対角線上にあるということです。 対角線上にある連続した部屋は 2 回の移動で安全に訪問できます。 から移動する場合`(i, j)`に`(i-1, j+1)`、シーケンス`U, R`通り抜ける`(i-1, j)`、その距離は 1 つ小さくなります。 逆方向も同様に機能します。`L, D`。 

これにより、単純な斜めのスイープが得られます。 対角線を昇順に処理します。`i + j`。 すべての対角線の方向を交互にして、1 つの対角線の終点が次の対角線の始点の隣になるようにします。 すべての部屋は 1 回だけ訪問され、パスの長さは制限を下回っています。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O((nm)^2) | O(nm) | 遅すぎる |
 | 最適 | O(nm) | O(nm) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 距離に基づいてすべての対角線を生成します`d = i + j`から始まる`0`そして終わる`n + m - 2`。 対角線内の部屋の座標はすべてその合計とペアになります。 
2. 次の対角線に移動する前に、1 つの対角線を完全に横断します。 偶数番号の対角線の場合は、行インデックスが最大のものから最小のものまで部屋を訪問します。 奇数の対角線の場合は、方向を逆にします。 方向を交互にすることで、隣接する対角線が自然につながります。 
3. 対角線上にある部屋から次の部屋に移動する場合は、2 回移動します。 下行方向では使用します`U`それから`R`。 逆方向に使用する`L`それから`D`。 中間の部屋の距離は常に、処理される対角線よりも小さくなります。 
4. 2 つの対角線の間で、現在の対角線の終点と次の対角線の始点を結ぶ 1 つの移動を実行します。 順序が交互になっているため、これら 2 つの部屋は隣接しています。 

なぜ機能するのか: 対角線を処理する前`d`、距離が小さい対角線上のすべての部屋がすでに訪問されています。 斜めを歩きながら`d`、中間の部屋のみが対角線上にあります。`d`または小さな対角線上にあります。 より短い距離のヒントがすべて収集されるまで、ヒントは入力されません。 最後の対角線を終えた後、すべての部屋を訪問したため、考えられるすべてのヒントが回収されました。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    grid = [input().strip() for _ in range(n)]

    ans = []
    current = (0, 0)

    def move_to(a, b):
        nonlocal current
        x, y = current
        nx, ny = a, b

        while x > nx:
            ans.append('U')
            x -= 1
        while y < ny:
            ans.append('R')
            y += 1
        while x < nx:
            ans.append('D')
            x += 1
        while y > ny:
            ans.append('L')
            y -= 1

        current = (x, y)

    for d in range(n + m - 1):
        cells = []
        lo = max(0, d - (m - 1))
        hi = min(n - 1, d)

        if d % 2 == 0:
            for i in range(hi, lo - 1, -1):
                cells.append((i, d - i))
        else:
            for i in range(lo, hi + 1):
                cells.append((i, d - i))

        if cells[0] != current:
            move_to(*cells[0])

        for x, y in cells[1:]:
            cx, cy = current
            if x == cx - 1 and y == cy + 1:
                ans.append('U')
                ans.append('R')
            elif x == cx + 1 and y == cy - 1:
                ans.append('L')
                ans.append('D')
            else:
                move_to(x, y)
            current = (x, y)

        if d + 1 < n + m - 1:
            nd = d + 1
            nlo = max(0, nd - (m - 1))
            nhi = min(n - 1, nd)
            if nd % 2 == 0:
                nxt = (nhi, nd - nhi)
            else:
                nxt = (nlo, nd - nlo)
            if nxt != current:
                move_to(*nxt)

    print(''.join(ans))

if __name__ == "__main__":
    solve()
```コードでは、ルームに次のものが含まれているかどうかを確認する必要はありません。`X`。 空の部屋を訪問することは無害であり、すべての部屋を正しい順序で訪問することは、ヒント ルームのみを訪問するよりも強力な保証となります。 

対角線の生成ではゼロベースの座標が使用されるため、セルの距離は正確に`i + j`。 の`lo`そして`hi`値により、対角線が四角形の内側に実際に存在するセルに制限されます。 

対角セル間の移動は、任意の移動とは別に処理されます。 特別な 2 つの文字トランジションは、将来のロックされたレイヤーに決して足を踏み入れることがないことを保証するため、重要な部分です。 

## 実用的な例

 最初のサンプルの場合:```
4 5
S....
X.X..
.X...
...XX
```対角順序は次のとおりです。 

| 距離 | 方向 | 訪問したセル |
 | --- | --- | --- |
 | 0 | 下から上へ | (0,0) |
 | 1 | 上から下へ | (1,0)、(0,1) |
 | 2 | 下から上へ | (2,0)、(1,1)、(0,2) |
 | 3 | 上から下へ | (0,3)、(1,2)、(2,1)、(3,0) |

 生成されたパスは、より大きな距離のヒントに到達する前に、距離 1 のヒントを収集します。 有効なルートはすべて受け入れられるため、正確な出力はサンプルと異なる場合があります。 

2 番目のサンプルの場合:```
1 7
S.....X
```行は 1 つだけなので、対角線は一連の列になります。 アルゴリズムは列のすべての部屋を調べ、以前のすべての距離が処理された後でのみ最終ヒントに到達します。 

| 距離 | 現在の部屋 | アクション |
 | --- | --- | --- |
 | 0 | (0,0) | 開始 |
 | 1 | (0,1) | 対角処理 |
 | 2 | (0,2) | 対角処理 |
 | 3 | (0,3) | 対角処理 |
 | 4 | (0,4) | 対角処理 |
 | 5 | (0,5) | 対角処理 |
 | 6 | (0,6) | 最後のヒントを回収する |

 このケースでは、1 つの次元が 1 である場合にもこの構造が機能することが検証されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(nm) | すべての部屋は正確に 1 つの対角線上に配置され、1 回処理されます。 |
 | スペース | O(nm) | 入力グリッドと一時的な対角ストレージには最大 10,000 の部屋が含まれます。 |

 最大パス長にも制限があります。 対角線の内側に移動すると、隣接するペアごとに 2 回の移動が必要となり、20000 回未満の移動になります。 対角線間の接続により追加される追加の移動は 200 未満であり、必要な 30000 の制限を安全に下回ります。

 ## 特殊なケース

 グリッドに部屋が 1 つしかない場合、開始部屋の後には対角線はありません。 アルゴリズムは空のパスを出力しますが、収集するヒントがないため、これは正しいことです。 

すべての部屋にヒントがある場合、すべての部屋を訪問する必要があります。 新しく入った部屋はすべて現在の距離レイヤーまたは前の距離レイヤーに属しているため、斜めのスイープは引き続き機能します。 空のセルに関する簡単な仮定はありません。 

1 つの次元が 1 に等しい場合、斜めの横断は唯一の可能な方向に沿った直線の歩行になります。 対角線には最大でも 1 つのセルが含まれるため、遷移式は引き続き有効な隣接移動を生成します。 

ヒントが隣接する対角線に表示される場合、交互の順序が重要になります。 単純な行ベースのトラバーサルでは、近くのヒントにアクセスする前に、さらに遠い行に入る可能性があります。 距離レイヤーが主な順序付けルールであるため、対角順序はそれを防ぎます。
