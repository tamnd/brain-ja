 ## 問題の理解

 からの数値の順列が与えられます。`1`に`n`。 各魚の位置は最初は固定されており、ラインの乱れは、小さな強度の前に大きな強度が現れるペアの数です。 

1 回の操作で値を選択します`x`。 その後、それ以下の強度を持つ魚は、`x`前に移動すると、魚は力強くなります`x`が次に配置され、魚はより強いです`x`後ろに移動されます。 2 つのグループ内では、元の相対的な順序が維持されます。 タスクは値を選択することです`x`これにより、この安定したパーティションの後に、可能な限り最小の反転カウントが生成されます。 

の値`n`300万に達する可能性があります。 あらゆる可能性をチェックするソリューション`x`順列を再構築すると、二次作業が必要になるため、すぐに遅すぎます。 たとえ`O(n log n)`数百万の要素には、高価なデータ構造や不必要なメモリ割り当ての余地がほとんどないため、ソリューションは慎重に実装する必要があります。 

主なエッジケースは、選択された値自体が移動される唯一のものではないという事実から生じます。 この操作では、以下の値間のすべての反転も修正されます。`x`より大きい値`x`。 

例えば：```
Input:

```選択する`x = 4`命令を出します`2 1 3 4`、反転が 1 つあります。 を含む倒置法のみを除去する方法`x`そのペアがいなくなると寂しいだろう`(4,1)`そして`(4,3)`も修理されています。

## アプローチ

 直接的なアプローチは、選択されたすべての可能な値を試すことです`x`。 それぞれについて、安定した分割をシミュレートし、結果のシーケンスの反転をカウントできます。 これは、考えられるすべてのコマンドを検査するので正しいですが、遅すぎます。 がある`n`選択肢、および長さのシーケンスの反転を数える`n`少なくとも費用がかかる`O(n log n)`、与える`O(n^2 log n)`最悪の場合の運用。 

有益な観察は、次の連続値の答えは次のとおりであるということです。`x`非常に簡単な方法で変化します。 

させて`dp[x]`値を選択した後の反転回数になります`x`。 選択した後`x`、残りの反転は、正確に より小さい値間の反転です。`x`より大きい値の間で`x`。 から移動するとき`x`に`x + 1`、値を移動することによってのみ変更が発生します。`x`大きなグループから小さなグループへ。 

いつ`x`が小さいグループに入ると、その後に現れるより小さい値を持つ反転が作成されます。 いつ`x`より大きなグループを残すと、その前にあるより大きな値を持つ反転が削除されます。 したがって：```
dp[x + 1] = dp[x] + smaller_after_x - larger_before_x
```問題は、すべての値に対してこれら 2 つのカウントを維持することになります。 フェンウィック ツリーを使用すると、すでに処理された値とまだ処理されていない値の位置を対数時間でカウントできます。

 ## アルゴリズムのチュートリアル

 1. 順列の初期反転数を計算します。 これはまさに次の答えです`x = 1`すべての値が より大きいため、`1`一緒に留まり、元の反転だけが残ります。 
2. すべての値の位置を保存します。 遷移式は値が現在の値の前に現れるか後ろに現れるかによって決まるため、位置が必要です。 
3. 2本のフェンウィックツリーをポジション上に維持します。 最初のツリーには、現在のツリーよりも小さい値が含まれています。`x`。 2 番目のツリーには、現在のツリーよりも大きい値が含まれています。`x`。 
4. 反復する`x`から`1`に`n - 1`。 取り除く`x`2 番目のツリーから削除されます。これは、そのツリーがより大きなグループに属さなくなるためです。 以前にそのツリーに残っていた値の数`pos[x]`前のより大きな値の数です`x`。 
5. 最初のツリーに対して、その後の小さい値の数を問い合わせます。`x`。 差分を追加`smaller_after_x - larger_before_x`現在の答えに。 
6.挿入`x`次の遷移のためのより小さなグループの一部となるため、最初のツリーに追加されます。 スキャン中に確認された最小値を維持します。 

なぜ効果があるのか:

 選択されたすべての可能な値について、最終的な配置では、元の順列の 2 つの独立した部分が正確に保持されます。以下の値`x`および上記の値`x`。 ある選択肢から次の選択肢に移るときに変わるのは、現在の値がどちらの側に属するかだけです。 トランジション公式は、その動きによって作成および削除された反転を正確にカウントするため、すべての`dp[x]`順列を再計算せずに、前の値から値に到達します。 

## Python ソリューション```python
import sys
from array import array

input = sys.stdin.readline

def solve():
    data = sys.stdin.buffer.read()

    def gen():
        num = 0
        inside = False
        for c in data:
            if 48 <= c <= 57:
                num = num * 10 + c - 48
                inside = True
            elif inside:
                yield num
                num = 0
                inside = False
        if inside:
            yield num

    it = gen()
    n = next(it)

    pos = array('i', [0]) * (n + 1)

    bit = array('i', [0]) * (n + 1)

    def add(tree, i, v):
        while i <= n:
            tree[i] += v
            i += i & -i

    def query(tree, i):
        res = 0
        while i:
            res += tree[i]
            i -= i & -i
        return res

    inv = 0
    for i in range(1, n + 1):
        x = next(it)
        pos[x] = i
        inv += (i - 1) - query(bit, x)
        add(bit, x, 1)

    del bit

    small = array('i', [0]) * (n + 1)
    large = array('i', [0]) * (n + 1)

    for i in range(1, n + 1):
        large[i] += 1
        j = i + (i & -i)
        if j <= n:
            large[j] += large[i]

    cur = inv
    ans = inv
    total_small = 0

    for x in range(1, n):
        p = pos[x]

        add(large, p, -1)
        larger_before = query(large, p - 1)

        smaller_after = total_small - query(small, p)

        cur += smaller_after - larger_before
        if cur < ans:
            ans = cur

        add(small, p, 1)
        total_small += 1

    print(ans)

if __name__ == "__main__":
    solve()
```最初のフェンウィック ツリーは、元の反転数を計算するために 1 回だけ使用され、その後メモリを節約するために解放されます。 選択した値が発生する場所に基づいて遷移が行われるため、位置配列が必要です。 

2 番目のフェンウィック ツリーは、すべてのポジションがアクティブな状態で開始されます。 これは、まだ小さいグループに移行していない値を表します。 遷移を計算する前に、現在の値がこのツリーから削除され、より大きい値だけが残ります。`x`。 

変数`total_small`最初のツリー内の要素の合計数を毎回クエリする必要がなくなります。 現在の値は昇順に処理されるため、すでに挿入されている値の数とまったく同じになります。 

すべてのカウンターは Python 整数で保存されるため、反転カウントは安全に約 100 に達します。`n(n-1)/2`、これは 32 ビット整数よりも大きくなります。 Fenwick アレイでは、`array('i')`それらのエントリは周波数のみであり、符号付き 32 ビット整数に収まるため、最大の入力に対するメモリ使用量が十分に削減されます。

```初期の反転カウントはゼロです。 すべての遷移では値を維持または増加させることしかできないため、最小値はゼロのままです。
