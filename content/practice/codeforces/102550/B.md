 ## 解決策
 ## 問題の理解

 この問題は、各アイテムに価格があり、いくつかのアイテムのペアが互換性があるアイテムのコレクションについて説明します。 これら 3 つのアイテムのすべてのペアが互換性があるような、3 つのアイテムの最も安いセットを見つける必要があります。 グラフ用語では、すべての項目が頂点であり、すべての互換性のあるペアがエッジであり、三角形の最小合計重みが必要です。 三角形が存在しない場合、答えは次のようになります。`-1`。 

入力により、アイテムの数と互換性のあるペアの数が与えられ、その後に各アイテムの価格と互換性のあるペアのリストが表示されます。 出力は、相互に接続されたアイテムのすべてのトリプル間の価格の最小合計です。 

この制約は、すべてのトリプルを直接チェックするのは通常コストが高すぎるという事実に基づいて設計されています。 あれば`n`アイテムの場合、可能なトリプルの数は`n * (n - 1) * (n - 2) / 6`、立方体的に成長します。 たとえ数千の項目であっても、これは大きすぎるため、3 つのグループをすべて列挙することは避ける必要があります。 

主なエッジケースは、パスと三角形を混同したり、3 つのペアがすべて存在する必要があることを忘れたりすることによって発生します。 例えば：```
3 2
2 3 4
1 2
2 3
```答えは、`-1`。 アイテム`1, 2, 3`チェーンでつながっていますが、アイテムは`1`そして`3`互換性がありません。 1 つの項目に 2 つの隣接項目があるかどうかだけをチェックする不注意な解決策では、このケースが誤って受け入れられてしまいます。 

もう 1 つのケースは、有効なトライアングルが存在するが、トライアングルを形成していない安そうなペアが他にある場合です。```
4 4
10 1 2 100
1 2
2 3
3 1
1 4
```答えは、`13`、アイテムを使用する`1, 2, 3`。 4 番目のアイテムにはいくつかの頂点への安価な接続がありますが、三角形のメンバーを置き換えることはできません。 

最後の境界ケースは、グラフに長さ 3 のサイクルがまったくない場合です。```
4 3
5 5 5 5
1 2
2 3
3 4
```答えは、`-1`。 チェーンには多くのエッジを含めることができますが、三角形に近づく攻撃的なペアのペアは含まれません。 

## アプローチ

 直接的な解決策では、項目の可能なすべてのトリプルを検査します。 トリプルごとに`(i, j, k)`、必要な 3 つの互換性エッジが存在するかどうかを確認し、存在する場合は、それらの価格の最小合計を更新します。 考えられるすべての答えが考慮されるため、これは正しいです。 ただし、トリプルの数は、`O(n^3)`、各トリプルには定数時間のエッジ チェックが必要です。 大きなグラフの場合、これは数十億回の操作を意味しますが、これは現実的ではありません。 

有益な観察は、三角形には各ペアが接続される 3 つの頂点が含まれている必要があるということです。 すべてのトリプルを生成する代わりに、既存のエッジを反復処理できます。 端を見ると`(u, v)`、このエッジを含む三角形は、次の共通の近傍を使用する必要があります。`u`そして`v`。 それらの隣接リストの交差により、可能性のある 3 番目の頂点が正確に得られます。 

グラフには多くのエッジが存在する可能性があるため、これらの交差チェックを効率的に行う必要があります。 隣接セットを保存することで、一定の平均時間でのメンバーシップ チェックが可能になります。 すべてのエッジについて、より小さい隣接セットを反復処理し、各候補が他のエンドポイントにも接続されているかどうかをテストします。 発見されたすべての共通の近傍が三角形を形成し、答えを更新します。 

ブルート フォースは、考えられるすべての三角形がテストされるため機能しますが、不必要なトリプルが多すぎるため失敗します。 隣接交差アプローチでは、グラフ構造を使用して不可能な組み合わせを回避し、三角形に近いトリプルのみを検査します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n3) | O(n²) | 遅すぎる |
 | 隣接交差点 | スパース グラフの O(m * sqrt(m)) 平均 | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのアイテムの価格を保存し、すべての頂点の隣接セットを構築します。 各セットにはその頂点に直接接続されているアイテムが含まれているため、ペアに互換性があるかどうかをすぐに確認できます。 
2. すべてのエッジを横断する`(u, v)`グラフで。 このエッジを含む三角形には、両方に接続された 3 番目の頂点が必要です。`u`そして`v`。 
3. 2 つの隣接セットのうち小さい方を反復処理します。`u`そして`v`。 すべての候補頂点について`x`、どうかを確認してください`x`他のエンドポイントの隣接関係セットにも属します。 
4. このような頂点が存在する場合、3 つの頂点は有効な三角形を形成します。 コンピューティング`price[u] + price[v] + price[x]`そして答えを最小限に抑えます。 
5. すべてのエッジが処理された後、見つかった最小値を出力します。 三角形が見つからなかった場合は、印刷します`-1`。 

小さい隣接リストを反復処理する理由は、その側のすべての候補が 3 番目の頂点になる可能性があるためです。 小さい方をチェックすると、不必要なメンバーシップ テストの総数が減ります。 

なぜ効果があるのか:

 すべての有効な解は三角形であり、すべての三角形には 3 つのエッジが含まれます。 トラバーサル中に、アルゴリズムはこれらのエッジの少なくとも 1 つを処理します。 そのエッジを処理すると、三角形の 3 番目の頂点が隣接セットの交差に表示されるため、三角形が見つかります。 見つかったすべての三角形が評価され、最小合計が維持されるため、最終的な答えはまさに可能な限り安価な三角形になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    price = list(map(int, input().split()))

    adj = [set() for _ in range(n)]
    edges = []

    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        adj[u].add(v)
        adj[v].add(u)
        edges.append((u, v))

    ans = float("inf")

    for u, v in edges:
        if len(adj[u]) > len(adj[v]):
            u, v = v, u

        for x in adj[u]:
            if x in adj[v]:
                ans = min(ans, price[u] + price[v] + price[x])

    print(-1 if ans == float("inf") else ans)

if __name__ == "__main__":
    solve()
```繰り返し必要な操作は 2 つのアイテムが接続されているかどうかを尋ねることだけであるため、隣接セットが使用されます。 リストではすべての近傍をスキャンする必要がありますが、セットでは平均的な一定時間の検索が行われます。 

隣接セットのみを反復処理するとすべてのエッジが 2 回処理され、追加のブックキーピングが必要になるため、エッジ リストは個別に保存されます。 内側のループの前のスワップにより、小さい隣接セットが常にスキャンされることが保証されます。 

このアルゴリズムはグラフの処理中にグラフを変更しないため、順序の問題は発生しません。 価格合計は Python 整数で保存され、32 ビット制限を超える値は自動的に処理されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(m * sqrt(m)) 平均 | 各エッジは隣接関係の小さい側をチェックします。これは、意図したグラフの制限に対して効率的です。 |
 | スペース | O(n + m) | 隣接セットとエッジ リストにはグラフが保存されます。 |

 このソリューションは、可能なトリプルの 3 乗を回避し、既存のグラフ接続のみを調査します。 これにより、考えられる 3 つのグループをすべてチェックすることが不可能な大規模な疎グラフに適しています。
