 ## 解決策
 ## 問題の理解

 フィールドは長方形のグリッドで、最初はすべてのセルにアクティブな地雷が含まれています。 この過程で、細胞は 1 つずつ除去されます。 クエリでは、特定のセルから 4 つの方向のうちの 1 つに厳密に最も近い残りの地雷が尋ねられます。 垂直クエリの場合は同じ列のみを考慮し、水平クエリの場合は同じ行のみを考慮します。 

入力はグリッドの次元と一連の操作を記述します。 削除操作では、セルが完全に削除されます。 検索操作は、要求された方向でまだ削除されていない最も近いセルの座標を要求するか、そのようなセルが存在しないことを報告します。 

制限が主な困難です。 グリッドには最大 400 万のセルを含めることができ、最大 100 万の操作が可能です。 すべてのクエリに対して行全体または列全体をスキャンすると、コストがかかりすぎます。 最悪の場合、1 つのクエリで 2000 個のセルが検査され、すべての操作に対して約 20 億回のチェックが行われる可能性があります。 ソリューションには、操作ごとにほぼ一定の時間が必要です。 

削除操作には便利な特性があります。セルは消えるだけで、元に戻ることはありません。 これは、単調除去用に設計されたデータ構造を使用できることを意味します。 すでに削除されているセルをスキップするだけで済みます。 

いくつかの境界ケースでは、直接実装が壊れる可能性があります。 グリッドの端からのクエリには、すぐには考えられる答えが見つからない可能性があります。 例えば：```
1 3 3
l 1 1
r 1 3
u 1 2
```出力は次のとおりです。```
-1
-1
-1
```不用意に実装すると、検索中に開始セルが誤って含まれたり、グリッドの外に移動したりする可能性があります。 

もう 1 つのケースは、最も近いセルが削除されたが、さらに遠いセルがまだ存在する方向です。```
1 4 3
c 1 2
r 1 1
l 1 4
```出力は次のとおりです。```
1 3
1 1
```取り外し後`(1,2)`、適切なクエリはそれをスキップして検索する必要があります`(1,3)`。 最初に削除された位置で停止すると、誤った結果が得られます。 

最後の注意が必要なケースは、多数の削除後に検索が繰り返される場合です。```
2 2 4
c 1 1
c 1 2
d 1 1
r 2 1
```出力は次のとおりです。```
2 1
2 2
```この構造は、行または列の大部分が消失した後でも、残りのセルを見つけ続けなければなりません。 

## アプローチ

 簡単なアプローチは、どのセルがまだアクティブであるかを保存し、クエリごとに、アクティブなセルが見つかるまで要求された方向に一度に 1 歩ずつ歩くことです。 最初に見つかったアクティブ セルがまさに最も近いセルであるため、これは正しいです。 問題は繰り返し作業の量です。 2000 x 2000 のグリッドの場合、クエリは 1999 個のセルをスキャンする可能性があり、そのようなクエリが 100 万件あると、ほぼ 20 億の操作が必要になる可能性があります。 

重要な観察は、セルが削除されるだけであるということです。 二度と地雷を挿入する必要はありません。 行の場合、列が削除された後、その位置に到達する今後のクエリはすべて、すぐにその位置を飛び越える必要があります。 同じことがすべての列に独立して適用されます。 

これはまさに、素のセット スタイルの「ネクスト ポインター」構造によって処理される状況です。 各行について、次に残っている列と前の残りの列を見つけることができる構造を維持します。 各列について、次と前の残りの行を維持します。 セルが削除されると、そのセルを次に利用可能な位置に接続し、今後の検索から効果的に削除します。 

たとえば、行に列が含まれている場合、`1 2 3 4`そしてコラム`2`が削除されると、次のポインタが削除されます。`2`になる`3`。 今後の検索は次のとおりです`1`次のアクティブな列を要求すると、削除されたセルを自動的にジャンプします。 

4 つの構造を合わせると、ほぼ一定の償却時間であらゆる方向に応答できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(q * max(n, m)) | O(nm) | 遅すぎる |
 | 最適 | O(q α(nm)) | O(nm) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 4 つの素な集合構造を構築します。 すべての行について、「次の生きている列」構造と「前の生きている列」構造を保存します。 すべての列に対して、行に対応する 2 つの構造を格納します。 すべてのセルが存在するため、各構造は最初はそれ自体を指します。 
2. での取り外し操作の場合`(x, y)`、そのセルを行構造と列構造の両方から削除します。 next-pointer 構造体では、削除された位置を次の位置に接続します。 前のポインター構造体では、前の位置に接続します。 
3. 正しいクエリの場合`(x, y)`、行のネクストポインタ構造体に、次の後の最初のアクティブな列を問い合わせます。`y`。 結果が有効な列範囲外の場合、答えは存在しません。 それ以外の場合は戻ります`(x, result)`。 
4. 左クエリの場合は、行の前のポインタ構造を使用します。 up クエリの場合は、列の前のポインター構造を使用します。 下向きクエリの場合は、列のネクスト ポインター構造体を使用します。 

これが機能する理由は、変更が削除のみだからです。 削除された位置は常に、有効な回答である可能性のある最も近い位置にリダイレクトされます。 パス圧縮により、長いチェーンはすぐに崩壊するため、繰り返しのジャンプが非常に安価になります。 

### なぜ効果があるのか

 不変条件は、すべてのポインター構造体がその方向に最も近いまだ存在する位置を返すということです。 すべてのセルが存在し、すべてのポインターがそれ自体を指しているため、最初はこれが当てはまります。 セルが削除されると、その方向に最も近い生き残った隣接セルへのリンクに置き換えられます。 削除されたセルに到達する今後の検索は、削除後に見つかるはずだった位置に正確にリダイレクトされます。 セルは再度挿入されることはないため、更新によってこのプロパティが無効になることはありません。 

## Python ソリューション```python
import sys
from array import array

input = sys.stdin.readline

def find(arr, idx):
    root = idx
    while arr[root] != root:
        root = arr[root]
    while arr[idx] != idx:
        nxt = arr[idx]
        arr[idx] = root
        idx = nxt
    return root

def solve():
    n, m, q = map(int, input().split())

    row_size = m + 1
    col_size = n + 1

    row_next = array('H', [0]) * (n * row_size)
    row_prev = array('H', [0]) * (n * row_size)
    col_next = array('H', [0]) * (m * col_size)
    col_prev = array('H', [0]) * (m * col_size)

    for i in range(n):
        base = i * row_size
        for j in range(m + 2):
            if j <= m:
                row_next[base + j] = j
            if j <= m:
                row_prev[base + j] = j

    for j in range(m):
        base = j * col_size
        for i in range(n + 1):
            col_next[base + i] = i
            col_prev[base + i] = i

    out = []

    for _ in range(q):
        parts = input().split()
        typ = parts[0]
        x = int(parts[1]) - 1
        y = int(parts[2]) - 1

        if typ == 'c':
            rb = x * row_size
            cb = y * col_size

            row_next[rb + y] = find(row_next, rb + y + 1) - rb
            row_prev[rb + y] = find(row_prev, rb + y - 1) - rb

            col_next[cb + x] = find(col_next, cb + x + 1) - cb
            col_prev[cb + x] = find(col_prev, cb + x - 1) - cb
        elif typ == 'r':
            rb = x * row_size
            ans = find(row_next, rb + y + 1) - rb
            if ans > m - 1:
                out.append("-1")
            else:
                out.append(f"{x + 1} {ans + 1}")
        elif typ == 'l':
            rb = x * row_size
            ans = find(row_prev, rb + y - 1) - rb
            if ans < 0:
                out.append("-1")
            else:
                out.append(f"{x + 1} {ans + 1}")
        elif typ == 'd':
            cb = y * col_size
            ans = find(col_next, cb + x + 1) - cb
            if ans > n - 1:
                out.append("-1")
            else:
                out.append(f"{ans + 1} {y + 1}")
        else:
            cb = y * col_size
            ans = find(col_prev, cb + x - 1) - cb
            if ans < 0:
                out.append("-1")
            else:
                out.append(f"{ans + 1} {y + 1}")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```このコードは、すべての行と列の構造をフラット化された配列に格納します。 これにより、何百万もの個別の Python オブジェクトのオーバーヘッドが回避されます。 すべてのインデックスが最大 2000 であるため、`array('H')`すべての格納値は符号なし 16 ビット整数に収まるため、これで十分です。 

の`find`関数は、パス圧縮を使用した通常の素セット検索です。 最初のループは最終的に生き残る位置を見つけ、2 番目のループはパスを短縮して、後のクエリが高速になるようにします。 

削除順序は重要です。 このコードはまず、削除されたセルをその隣接セルに接続し、その後のクエリではそのセルが再び返されなくなります。 の`+1`そして`-1`クエリでは指定された位置の厳密に後または前にセルが要求されるため、オフセットも重要です。 

Python には整数オーバーフローの問題はなく、配列のサイズはグリッドの次元によって制御されます。 400 万セルを超える 4 つの構造体は通常の Python リストとしては大きすぎるため、コンパクトな配列を使用してメモリを節約することが必要です。

## 特殊なケース

 最初の境界ケースは、グリッドの端からのクエリです。 入力では:```

l 1 1
```アルゴリズムは列の前の列を要求します`0`ゼロベースのインデックス付けで。 先行構造はグリッドの外側のセンチネルの位置を返すため、答えは次のようになります。`-1`。
