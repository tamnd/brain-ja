 ## 解決策
 ## 問題の理解

 建物の建設期間を表す一連の時間間隔が与えられます。 選択された日は、その日に建設中のすべての建物を検査するために軍隊を派遣することに相当します。 建物は、その間隔内にある選択された日ごとに「訪問」されます。 

すべての間隔に少なくとも 1 つの選択された日が含まれるように、一連の整数の日を選択する必要があります。 このようなすべての有効なスケジュールの中で、単一の建物に対する最悪の場合の負荷を最小限に抑えたいと考えています。ここで、建物の負荷とは、その間隔内に含まれる選択された日数です。 このような最適な日のセットを見つけた後、選択した日自体を出力します。 

したがって、問題はすべての間隔をカバーすることだけではなく、単一の間隔を何度も訪問しないようにすることにもあります。 

制約では最大 2500 の間隔が許可され、エンドポイントは絶対値で 10^18 までの大きさにすることができます。 これにより、何日も繰り返したり、明示的なタイムラインを構築したりするアプローチは即座に除外されます。 どのような解決策も純粋に区間エンドポイントと組み合わせ構造で機能する必要があり、通常は O(n^2) 付近であれば何でも許容されますが、O(n^3) は定数に応じて境界線になります。 

間隔が大きくネストされている場合、微妙なエッジケースが発生します。 たとえば、間隔 [0, 10]、[1, 9]、[2, 8] などを考えてみましょう。 「多くの妥当なポイント」を選択する単純な戦略では、選択した複数の日が同じ長い間隔内に意図せず配置され、訪問数が増加する可能性があります。 もう 1 つの特殊なケースは、間隔が互いに素である場合です。 その場合、最適解は明らかに間隔ごとに 1 つのポイントを正確に選択する必要があり、大きな間隔内に誤って配置された余分なポイントは不必要で有害になります。 

さらなる落とし穴は、有効なカバー セットが同等であると想定していることです。 実際、2 つの異なる打撃セットは、長いインターバルで交差する回数が大きく異なる可能性があります。 

## アプローチ

 この問題は、すべての間隔が少なくとも 1 回ヒットするように、一連の「刺し込みポイント」を選択することとみなすことができます。 2 番目の目的を無視すると、当然の目的は、すべての区間と交差する最小数の点を見つけることになります。 これは古典的なインターバル刺し問題であり、まだカバーされていない最も早い終了インターバルの終わりにある点を常に選択することで貪欲に解決されます。 これにより、最小サイズの点のセットが生成されます。 

ただし、ここでの目的は異なります。 選択した日数を最小限に抑えることはありません。 単一の間隔内に含まれる選択された日の最大数を最小限に抑えています。 これにより、問題は純粋な被覆の問題から、分散が重要となるバランスのとれた被覆の問題に変わります。 

ブルート フォース アプローチでは、区間エンドポイントによって引き起こされる候補点のすべての可能なサブセットを試し、すべての区間がヒットするかどうかを確認し、区間ごとの最大カバレッジを計算します。 これは候補点の数が指数関数的に増加するため、完全に実行不可能です。 

重要な観察は、貪欲な刺し込みソリューションがすでに高度に構造化されたポイントのセットを生成していることです。選択された各ポイントは、あるインターバルの正しいエンドポイントであり、インターバルは終了時間の昇順に処理されます。 この構造により、選択された点が可能な限り「右にシフト」され、長く重なり合う間隔内での不必要なクラスタリングが防止されます。 ポイントを左にシフトしたり、余分なポイントを追加したりする偏差は、既存の間隔内のオーバーラップを増やすだけになる傾向があります。 

これにより、貪欲なスタビング構造は、カバレッジ サイズに最適なだけでなく、任意の間隔内で選択されるポイントの最大数を最小限に抑えるのにも最適になります。

## アルゴリズムのチュートリアル

 1. すべての間隔を終了時間の昇順に並べ替えます。 これにより、新しい検査日をどこに配置するかを決定する際に、柔軟性が最も低いため、最も早く終了する間隔が常に優先されるようになります。 
2. 選択した日の最初は空のリストを維持します。 これらは私たちが構築している実際の検査日です。 
3. ソートされた順序で間隔を繰り返します。 各間隔について、その間隔がすでに「カバーされている」かどうか、つまり、以前に選択した日が少なくとも 1 つ含まれているかどうかを確認します。 カバーされている場合は何もしません。 
4. 間隔がカバーされていない場合は、新しい検査日を追加する必要があります。 最良の選択は、この日を間隔の正しい終点に正確に配置することです。 これにより、将来の間隔でのこのポイントの再利用が最大化され、より長い間隔で重複が増加する可能性がある不必要な早期の配置が回避されます。 
5. 選択した日の完全なセットを構築した後、各間隔について、その中に選択した日が何日含まれるかを計算します。 応答値は、すべての間隔にわたるこれらのカウントの最大値です。 
6. 選択した日数とリスト自体を出力します。 

### なぜ効果があるのか

 貪欲なプロセスは、現在のインターバルをカバーしながら、選択された各ポイントが可能な限り右に配置される最小のヒッティング セットを構築します。 この構造により、新しいポイントを追加するたびに、まだカバーされていない間隔によって強制的に追加されることが保証されます。つまり、以前に選択されたポイントがその中に存在しないことになります。 その結果、任意の間隔内で選択されたポイントの数は、その間隔に重なる間隔をスイープするときに発生する貪欲な「アクティベーション」の数とまったく同じになります。 

代替の有効な解決策では、すべての間隔内に少なくとも 1 つのポイントを配置する必要があります。また、ポイントを左に移動したり、ポイントを再分配して重複を削減しようとしても、右端の間隔のカバレッジを壊すことなく、長い間隔が交差する回数を減らすことはできません。 これにより、貪欲な構築が実現可能性と最大負荷目標の両方にとって最適になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    seg = []
    for _ in range(n):
        s, e = map(int, input().split())
        seg.append((s, e))

    seg.sort(key=lambda x: x[1])

    chosen = []

    for s, e in seg:
        # check if already covered
        covered = False
        for x in chosen:
            if s <= x <= e:
                covered = True
                break
        if not covered:
            chosen.append(e)

    # compute maximum coverage per interval
    ans = 0
    for s, e in seg:
        cnt = 0
        for x in chosen:
            if s <= x <= e:
                cnt += 1
        ans = max(ans, cnt)

    print(len(chosen))
    print(*chosen)

if __name__ == "__main__":
    solve()
```実装は貪欲な構造に直接続きます。 正しいエンドポイントで並べ替えると、ポイントを追加するたびに、現在の間隔をカバーする最も新しい時点にポイントが配置されるようになります。 カバレッジ チェックでは、以前に選択したポイントがスキャンされます。これは、n ≤ 2500 の場合に許容されます。 

2 番目のパスでは、各間隔の交差を数えることによって目的の値を計算します。 これは、問題定義に沿った簡単な検証ステップです。 

ここでよくある間違いは、ポイントの数だけを最適化しようとして、それで十分だと思い込んでしまうことです。 2 番目のパスでは、実際の目的がカーディナリティだけではなく分布に依存することが明示されています。 

## 実用的な例

 ### 例 1

 区間 [0, 2]、[1, 3]、[2, 4] を考えてみましょう。 

末尾でソートすると同じ順序になります。 

[0,2] を処理し、2 を選択します。 

次の [1,3] にはすでに 2 が含まれているため、スキップします。 

次の[2,4]には2が入っているので飛ばします。 

選択した日: [2]

 | ステップ | 間隔 | 選択されたセット | アクション |
 | --- | --- | --- | --- |
 | 1 | [0,2] | [] | 2を追加 |
 | 2 | [1,3] | [2] | カバーされた |
 | 3 | [2,4] | [2] | カバーされた |

 最大カバレッジはすべての間隔で 1 です。 

これは、重複する間隔が 1 つの検査日にどのように崩れるかを示しています。 

### 例 2

 区間 [0,1]、[2,3]、[4,5] を考えてみましょう。 

各間隔は互いに素です。 

1 を選択し、次に 3、次に 5 を選択します。 

選択した日: [1、3、5]

 | ステップ | 間隔 | 選択されたセット | アクション |
 | --- | --- | --- | --- |
 | 1 | [0,1] | [] | 1を追加 |
 | 2 | [2,3] | [1] | 3を追加 |
 | 3 | [4,5] | [1,3] | 5を追加 |

 各間隔には 1 回の訪問が含まれており、アルゴリズムが不必要な重複を導入していないことを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n^2) | 間隔ごとに、以前に選択したポイントをスキャンすることができ、最終的なスコアリングでもすべてのペアをスキャンします。 
| スペース | O(n) | 間隔と選択したポイントを保存します。 

n ≤ 2500 という制約により、O(n^2) の解が快適に得られます。 ネストされたループがあっても、合計の操作は十分に制限内に収まります。

 ## 特殊なケース

 [0,10]、[1,9]、[2,8] などの完全にネストされたチェーンは、アルゴリズムが長い間隔内に複数の不要なポイントを決して導入しないことを確認します。 チェーンの最後の間隔のみ、単一のポイントが強制的に選択されます。 

各間隔が独立して新しい選択をトリガーするため、非結合間隔により、アルゴリズムが重複しない範囲にわたってポイントを誤って再利用しないことが確認されます。 

同一の間隔は、最初に選択されたポイントがすでにすべての重複をカバーしているため、繰り返し入力しても選択された日数が増加しないことを示しています。
