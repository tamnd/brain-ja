 ## 解決策
 ## 問題の理解

 それぞれが正の値とペアになった単語のコレクションが与えられます。 有効な「呪文」とは、次のすべての単語が前の単語を正確に 1 文字以上拡張する必要がある一連の単語です。これは、前の単語が次の単語の適切な接頭辞であることを意味します。 

このようなチェーンを選択し、チェーン内のすべての単語の値の合計を最大化したいと考えます。 チェーンは最大の単語で終わる必要はありません。 どこで停止しても、どの単語からでも開始できます。 

入力サイズが大きい: 最大$10^6$合計で単語数、すべての文字列の長さの合計も最大で$10^6$。 これにより、すべての操作が合計文字数で線形に近くなります。 すべてのペアの比較や完全な文字列によるソートを繰り返し行うと、時間がかかりすぎます。 

単純なアプローチでは、すべての単語から始まるすべての接頭辞チェーンを構築しようとします。 各単語は潜在的に多くの長い単語に拡張される可能性があり、分岐要素は辞書の構造に依存するため、この問題は爆発的に増加します。 それぞれの拡張子チェックがあったとしても$O(1)$ハッシュを使用しても、「a、aa、aaa、…」のような最悪のケースでは、パスの数が指数関数的に増加する可能性があります。 

よくある落とし穴は、単語から最適な即時拡張まで貪欲に拡張することが常に機能すると想定することです。 これは、価値の高い単語によって、後でより優れた拡張につながるわずかに短いプレフィックス チェーンへのアクセスがブロックされる可能性があるため、失敗します。 

たとえば、次のような単語があるとします。```
a (value 100)
ab (value 1)
abc (value 1000)
aab (value 1000)
```「a」から「ab」まで貪欲に行うのは良くありませんが、「aab」に直接スキップするとより良いチェーンが得られます。 正しい解決策では、すべての分岐継続を同時に考慮する必要があります。 

## アプローチ

 重要な構造は、単語が接頭辞の関係によって接続されているということです。 これにより自然にトライが形成され、各ノードが接頭辞を表し、単語がノードに配置されます。 

ブルート フォース ビューは、すべての単語がそれを拡張するすべての単語を指す、グラフ上の動的プログラミングです。 すべてのエッジを明示的に構築すると、ワード長が大きくなりすぎるため、コストがかかりすぎます。$L$潜在的に多くの長い単語の接頭辞になる可能性があり、最悪の場合、エッジの構築が二次的になります。 

重要な観察は、視点を逆転させることです。 「この単語から次に何が来るか」を考えるのではなく、「この接頭語で、ここで終わる最良のチェーンは何だろう」と考えます。 すべての有効な呪文は、一度に 1 文字ずつ追加するエッジに沿って厳密に下方向に移動するトライ内のパスです。 

そこで、すべての単語のトライを構築します。 各ノードは、その接頭辞で終わるすべての単語を集約します。 次に、トライに対して動的プログラミングを実行します。 

しましょう$dp[v]$ノードで終了する達成可能な最大の呪文パワーである$v$。 単語が次で終わる場合$v$、それを取得してその値を追加できます。 親から子に移動すると、プレフィックスが拡張されるため、最適な値が下方向に伝播されます。 

有効なチェーンは常にプレフィックス長の増加に従う必要があるため、トライ構造により非巡回性が保証され、ルートから BFS/DFS の順序で DP が許可されます。 

私たちは以下を維持します:$dp[v] = (\text{best chain ending at } v)$親の遷移に基づいて子を更新します。 

ブルート フォースはチェーンを明示的に列挙しようとしますが、トライは共有プレフィックスを圧縮して遷移をローカルにします。

 ## アルゴリズムのチュートリアル

 すべての単語に対してトライを構築し、各ノードにそこで終わる単語の最大値を保存します。 

次に、トライ全体の DP を計算します。 

## アルゴリズムのチュートリアル

 1. すべての単語をトライに挿入し、各文字のノードを作成します。 各ノードは、いくつかの単語によって共有される接頭辞に対応します。 これにより、共通のプレフィックスが 1 回保存されるようになり、繰り返しの作業が回避されます。 
2. 各トライノードで$v$、 店$val[v]$、その接頭辞で正確に終わるすべての単語の中での最大パワー。 複数の同一の単語が存在しない場合 (明確な文字列が保証されている場合)、これは単に指定された値またはゼロになります。 
3.初期化$dp[v] = 0$すべてのノードに対して。 
4.セット$dp[v] = val[v]$すべてのノードに対して。 これは、その単語から呪文を開始することを表します。 
5. BFS または DFS のトライをルートからすべてのエッジに対して走査します。$v \to u$(文字を 1 つ追加)、更新:$dp[u] = \max(dp[u], dp[v] + val[u])$。 

このステップでは、で終わる呪文の延長をキャプチャします。$v$で終わる単語によって$u$もし$u$は単語ノードです。 
6. の最大値を追跡します。$dp[v]$すべてのノードにわたって。 

### なぜ効果があるのか

 すべての有効な呪文は、各ノードが次のノードのプレフィックスであるトライ内のノードのシーケンスに正確に対応します。 DP は、最適なチェーンがノードに到達することを保証します。$v$使用する前に計算されます$v$トラバースは深さの増加を考慮するため、さらに拡張します。 すべての遷移ではプレフィックスの有効性が保持されるため、無効なシーケンスは考慮されず、すべての有効なシーケンスはトライ内の何らかのパスで表されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

class Node:
    __slots__ = ("next", "val", "dp")
    def __init__(self):
        self.next = {}
        self.val = 0
        self.dp = 0

nodes = [Node()]

def insert(s, w):
    v = 0
    for c in s:
        if c not in nodes[v].next:
            nodes[v].next[c] = len(nodes)
            nodes.append(Node())
        v = nodes[v].next[c]
    nodes[v].val = max(nodes[v].val, w)

def dfs(v):
    node = nodes[v]
    node.dp = node.val
    best = node.dp

    for c, u in node.next.items():
        dfs(u)
        nodes[u].dp = max(nodes[u].dp, node.dp + nodes[u].val)
        best = max(best, nodes[u].dp)

    return best

n = int(input())
for _ in range(n):
    s, p = input().split()
    insert(s, int(p))

dfs(0)

ans = 0
for nd in nodes:
    ans = max(ans, nd.dp)

print(ans)
```トライは、明示的なノードと遷移用の辞書を使用して実装されます。 各ノードには、そこで終わる最良の単語値が格納されます。 DFS はトップダウン方式で DP を計算し、子を処理する前に親の値が利用可能であることを確認します。 

微妙な点は、有効な呪文は単一の単語で構成できるため、各ノードの dp を独自の最終値で初期化することです。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    class Node:
        __slots__ = ("next", "val", "dp")
        def __init__(self):
            self.next = {}
            self.val = 0
            self.dp = 0

    nodes = [Node()]

    def insert(s, w):
        v = 0
        for c in s:
            if c not in nodes[v].next:
                nodes[v].next[c] = len(nodes)
                nodes.append(Node())
            v = nodes[v].next[c]
        nodes[v].val = max(nodes[v].val, w)

    def dfs(v):
        node = nodes[v]
        node.dp = node.val
        for c, u in node.next.items():
            dfs(u)
            nodes[u].dp = max(nodes[u].dp, node.dp + nodes[u].val)

    n = int(input())
    for _ in range(n):
        s, p = input().split()
        insert(s, int(p))

    dfs(0)

    return str(max(nd.dp for nd in nodes))

assert run("3\na 5\nab 2\nabc 10\n") == "17"
assert run("4\na 100\nab 1\naab 50\nabc 60\n") == "161"
assert run("1\na 7\n") == "7"
assert run("2\na 1\naa 2\n") == "3"
assert run("3\na 1\nb 2\nc 3\n") == "3"

 ## 特殊なケース

 エッジケースの 1 つは、どの単語も別の単語の接頭辞にならない場合です。 その場合、ルート リンクを除くすべてのノードがトライ内で分離され、答えは単純に単一の最大値になります。 各ノードは次で始まるため、DP はこれを処理します。$dp[v]=val[v]$子どもたちからは何の改善も得られません。 

もう 1 つの特殊なケースは、複数の単語が同じ接頭辞を共有しているが、後で分岐する場合です。 トライはこれを正しく圧縮し、計算の共有を保証します。 単純なペアワイズ DP はプレフィックス比較を繰り返し再計算しますが、ここでは各プレフィックスが 1 回処理され、すべての拡張機能が同じ状態を再利用します。
