 ## 解決策
 ## 問題の理解

 n 日という一連の時間が与えられています。 毎日、2 つの為替レートがあります。1 つはドル、もう 1 つはブラジル レアルで、どちらもエジプト ポンドで測定されます。 具体的には、di は i 日に 1 ドルで得られるエジプト ポンドの数、ri は i 日に 1 レアルで得られるエジプト ポンドの数です。 

各クエリは、s から e までの日の範囲と、数量 D と R のペアを記述します。Cris は、その範囲内で正確に 1 日 i を選択し、その日にすべての交換操作を実行します。 その選ばれた日に、彼女は D ドルと R レアルを交換します。正の値はエジプト ポンドへの外貨の売りを表し、負の値はエジプト ポンドを使用して外貨を買うことを表します。 利益総額はエジプトポンドで測定され、買いがマイナス利益に寄与している。 

為替は線形なので、決まった日 i の利益は D・di + R・ri になります。 クエリは、[s, e] のすべての i に対するこの式の最大値を求めています。 

したがって、毎日の i は点 (di, ri) に対応します。 各クエリはベクトル (D, R) を与え、それらの内積を最大化する部分配列内の点を見つける必要があります。 

最大 2×10^5 の制約 n、q により、クエリごとに二次関数が除外されます。 各クエリに対する単純なスキャンでは、最悪の場合、最大 4×10^10 の操作が実行されますが、これでは遅すぎます。 範囲が制限された最大内積クエリをほぼ対数時間でサポートする構造が必要です。 

素朴な考えによる微妙な失敗例は、日を di または ri で並べ替えることができると仮定することです。 これにより、範囲の制約が破られます。 たとえば、di が増加し、ri が減少した場合、D と R が競合すると、1 次元による並べ替えは最適性を失います。 

もう 1 つのよくある間違いは、単一のグローバル凸包を維持しようとすることです。 これは失敗します。各クエリがドメインを [s, e] に制限しているため、全体的な最適性がサブ配列の最適性に変換されません。 

## アプローチ

 ブルートフォースアプローチは簡単です。 各クエリについて、s から e までのすべての日にわたって反復し、D·di + R·ri を計算し、最大値を取得します。 これは問題の定義を直接評価するため、正しいです。 ただし、各クエリのコストは O(n) になる可能性があるため、合計の複雑さは O(nq) となり、最悪の場合は 4×10^10 の演算に達します。 それは実現可能な限界をはるかに超えています。 

重要な構造的観察は、毎日が固定の 2D 点 (di、ri) であり、各クエリがセグメントに制限されたその点セットの最大内積を要求していることです。 これは古典的な幾何学的クエリです。2D の範囲最大内積です。 

範囲クエリで静的ポイントを処理する標準的な方法は、セグメント ツリーです。 セグメント ツリーの各ノードは、日のセグメントをカバーします。 「このノードのセグメント内の最大ドット積」を効率的に答えることができれば、クエリごとに O(log n) 個のノードを組み合わせることができます。 

1 つのセグメント ツリー ノード内では、固定の点セットに対するクエリに答えるだけで済みます。 点の固定セットの場合、クエリ ベクトル (D、R) との最大内積は、常にそれらの点の凸包の頂点で得られます。 これにより、各ノード内の問題が、凸多角形の維持とそれに対する最大内積のクエリに軽減されます。 

凸包の場合、固定方向の内積は包に沿って単峰性であるため、包に対して二分探索 (または三分探索) を実行して、O(log m) の最良の点を見つけることができます。ここで、m は包皮のサイズです。 

これにより、各ノードがそのセグメントの凸包を格納するセグメント ツリーが得られます。 構築では、マージごとに線形時間で 2 つの凸包をマージし、O(n log n) の前処理を行います。 各クエリは O(log n) ノードを訪問し、ノードごとに O(log n) 検索を実行し、クエリごとに O(log^2 n) を生成します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nq) | お(1) | 遅すぎる |
 | セグメントツリー + 凸包 | O(n log n + q log^2 n) | O(n log n) | 承認済み |

## アルゴリズムのチュートリアル

 毎日 i を点 Pi = (di, ri) として表します。 クエリの目的は、D·di + R·ri の [s, e] における i の最大値を計算することです。 

インデックス 1 から n までのセグメント ツリーを構築します。 

1. 各ノードに単一の点 Pi が含まれるリーフ ノードを構築します。 一点の凸包は自明です。 
2. 内部ノードの場合、その左右の子の凸包をマージします。 2 つの凸多角形の結合の凸包を計算します。 これは、ソートされた包を結合し、結合されたリストに対して線形時間で標準の凸包構築を実行することによって行われます。 これが機能する理由は、両方の子ハルがすでに凸状であり、境界に沿ってソートされているためです。 
3. 各ノードは、そのハルを反時計回りの順序で格納します。 この順序付けは、内積の単調性による幾何学的検索を可能にするため、非常に重要です。 
4. クエリ [s, e] に答えるために、その区間を正確にカバーする O(log n) 個のセグメント ツリー ノードに分解します。 
5. 各ノードについて、そのノードのハル内の任意の点と (D, R) の最大ドット積を計算します。 ハルは凸状であるため、ハルの頂点に沿った関数としての内積は単峰性であるため、最大値を二分探索します。 
6. 対象となるすべてのノードの最大値を取得し、出力します。 

これを正しくする重要な考え方は、凸性により、線形目的関数がセットの極値点で最大値に達することが保証されるということです。 セグメント ツリーによりクエリ範囲内の点のみを考慮することが保証され、ハルにより極端な候補のみを効率的に考慮することが保証されます。 

### なぜ効果があるのか

 各セグメント ツリー ノードは、日のセグメント内の一連の点を正確に表します。 そのノードに保存された凸包は、線形関数に関するすべての極点を保存します。 D·x + R·y は点にわたる線形関数であるため、集合にわたる最大値は凸包の頂点で発生します。 セグメント分解により、[s, e] の外側の点が決して含まれないことが保証され、ハル プロパティにより、セグメント内の最適な点を見逃さないことが保証されます。 したがって、関連するすべてのノードの最大値を結合すると、クエリ範囲のグローバル最大値が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def cross(o, a, b):
    return (a[0] - o[0]) * (b[1] - o[1]) - (a[1] - o[1]) * (b[0] - o[0])

def build_hull(points):
    points.sort()
    if len(points) <= 1:
        return points

    lower = []
    for p in points:
        while len(lower) >= 2 and cross(lower[-2], lower[-1], p) <= 0:
            lower.pop()
        lower.append(p)

    upper = []
    for p in reversed(points):
        while len(upper) >= 2 and cross(upper[-2], upper[-1], p) <= 0:
            upper.pop()
        upper.append(p)

    return lower[:-1] + upper[:-1]

def dot(p, d, r):
    return p[0] * d + p[1] * r

def best_on_hull(hull, d, r):
    l, rr = 0, len(hull) - 1
    def f(i):
        return dot(hull[i], d, r)

    while rr - l > 3:
        m1 = l + (rr - l) // 3
        m2 = rr - (rr - l) // 3
        if f(m1) < f(m2):
            l = m1
        else:
            rr = m2

    best = -10**30
    for i in range(l, rr + 1):
        best = max(best, f(i))
    return best

class SegTree:
    def __init__(self, pts):
        self.n = len(pts)
        self.tree = [[] for _ in range(4 * self.n)]
        self.pts = pts
        self.build(1, 0, self.n - 1)

    def build(self, v, l, r):
        if l == r:
            self.tree[v] = [self.pts[l]]
            return
        m = (l + r) // 2
        self.build(v * 2, l, m)
        self.build(v * 2 + 1, m + 1, r)
        self.tree[v] = build_hull(self.tree[v * 2] + self.tree[v * 2 + 1])

    def query(self, v, l, r, ql, qr, d, rr):
        if ql > r or qr < l:
            return -10**30
        if ql <= l and r <= qr:
            return best_on_hull(self.tree[v], d, rr)
        m = (l + r) // 2
        return max(
            self.query(v * 2, l, m, ql, qr, d, rr),
            self.query(v * 2 + 1, m + 1, r, ql, qr, d, rr)
        )

def solve():
    n, q = map(int, input().split())
    d = list(map(int, input().split()))
    r = list(map(int, input().split()))

    pts = list(zip(d, r))
    seg = SegTree(pts)

    for _ in range(q):
        s, e, D, R = map(int, input().split())
        s -= 1
        e -= 1
        print(seg.query(1, 0, n - 1, s, e, D, R))

if __name__ == "__main__":
    solve()
```このコードは、各ノードがその間隔の凸包を格納するセグメント ツリーを構築します。 船体構造はスタンダードなモノトーンチェーン方式を採用。 クエリ処理では、間隔が O(log n) ノードに分割され、各ノードはその包に対する三項検索で評価されます。 

微妙な実装の詳細は、無効なセグメントに対して大きな負のセンチネルを使用することです。 これにより、ノードがクエリ範囲外にある場合に結果が誤って混合されることが回避されます。 

もう 1 つの重要な詳細は、ハルの構築でポイントが辞書編集順にソートされ、正しい凸ハルの形成が保証されることです。 凸多角形の内積は単峰性であるため、三分探索は機能します。 

## 実用的な例

 日数に対応するポイントを持つ小さなインスタンスを考えてみましょう。 

(1, 2)、(3, 1)、(2, 4)、および全範囲にわたる (D, R) = (2, 1) の最大内積を求めるクエリ。 

セグメントツリーがどのようにハルを結合するかを評価します。 

| ノードセグメント | 船体ポイント | (2,1) の最高の評価 |
 | --- | --- | --- |
 | [1] | (1,2) | 4 |
 | [2] | (3,1) | 7 |
 | [3] | (2,4) | 8 |
 | [4] | (1,2) | 4 |

 全範囲クエリの場合、すべてのハル ノードを比較し、ポイント (2,4) からの最大値である 8 を取得します。 

これは、(3,1) が 1 次元目では強いにもかかわらず、結合された線形目標が最適なトレードオフ ポイントを正しく選択していることを示しています。 

ここで、サブセットのみが許可される、たとえば (2,4) を除く、範囲制限のあるクエリを考えてみましょう。 この構造により、有効なノードのみが寄与することが保証されるため、結果は (D,R) に応じて (3,1) または (1,2) に正しく切り替わります。

 ## 特殊なケース

 特殊なケースの 1 つは、D と R が両方とも負の場合です。 このような状況でも、最適な戦略は内積を最大化する点を選択することですが、幾何学的に方向ベクトルを反転させます。 同じ凸包構造は、正の方向だけでなく任意のクエリ方向をサポートするため、引き続き機能します。 凸多角形の内積関数は方向に関係なく単峰性であるため、包殻の三分探索は引き続き有効です。 

もう 1 つのエッジ ケースは、すべての di、ri ペアがほぼ同一線上にある場合です。 その場合、凸包は線分に縮退します。 ハルの構築により中間点が折りたたまれて端点のみが残り、クエリがそれらの間を正しく選択するため、アルゴリズムは引き続き正しく動作します。 

最後のエッジ ケースは、s が e に等しい単一要素の範囲です。 セグメント ツリーは 1 つの点を含む葉包を直接返し、内積の計算は 1 回の乗算に減ります。これは一般的な公式と一致します。
