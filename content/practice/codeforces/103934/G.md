 ## 解決策
 ## 問題の理解

 いくつかの独立した文字列が与えられ、それぞれが英語の小文字で構成される名前を表します。 変換ルールは、文字列の新しいバージョンがどのように構築されるかを定義します。つまり、すべての文字がそのすぐ隣の文字とともに検査され、隣り合う文字の少なくとも 1 つがそれ自体と異なる場合、その文字は複製されます。 両方の近傍が存在し、その文字と等しい場合、その文字は単一の出現として保持されます。 

境界文字の場合、単一の既存の隣接文字のみが考慮されます。 最初の文字は 2 番目の文字とのみ比較され、最後の文字は最後から 2 番目の文字とのみ比較されます。 

出力は各入力文字列の変換されたバージョンであり、テスト ケース全体で順序が維持されます。 

制約は小さく、テスト ケースの数は最大 100、各文字列の長さは最大 100 です。これにより、文字列ごとの線形処理を超える最適化に関する懸念が即座に排除されます。 O(n²) メソッドでさえほとんど安全ではありませんが、その構造は、文字列ごとに O(n) のソリューションが意図されており、自然であることを強く示唆しています。 

同一の文字が連続して存在する場合、微妙なエッジケースが発生します。 たとえば、`"aaa"`、中央の文字は同一の隣接文字を持っているため重複すべきではありませんが、2 つの境界文字はそれぞれ片側に異なる欠損または境界条件があるため、重複する必要があります。 もう 1 つの特殊なケースは単一文字列です。この場合、隣接文字がまったく存在しないため、文字は常に 1 回複製されます。 

## アプローチ

 ルールを解釈する強引な方法は、すべての位置を反復処理し、その近傍を明示的にチェックすることによって各文字列を再構築することです。 位置 i の各文字について、i - 1 および i + 1 が存在する場合はそれらと比較します。 有効な近傍が異なる場合は、文字のコピーを 2 つ追加します。 それ以外の場合は追加します。 

このアプローチは、各位置が定数時間で処理されるため、文字列ごとにすでに線形時間で実行されます。 改善を検討する唯一の理由は、効率ではなく概念的な明確さです。 この制約により、単純な実装でも十分な速度が保証されます。 

重要な観察は、ルールが完全にローカルであるということです。 各位置はそのすぐ隣にのみ依存するため、グローバルな前処理や動的構造は必要ありません。 これは、文字列自体以外には何も保存せずに、単一の左から右へのパスでルールを直接シミュレートできることを意味します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 文字ごとの直接隣接チェック | 文字列あたり O(n) | O(1) おまけ | 承認済み |
 | シングルパスシミュレーション | 文字列あたり O(n) | O(1) おまけ | 承認済み |

 どちらも構造的には事実上同一です。 最適な解決策は、単にルールを最もクリーンに実装することです。 

## アルゴリズムのチュートリアル

 各文字列を個別に処理します。 

1. 文字列を読み取り、その長さを決定します。 各位置の動作はすぐ隣にのみ依存するため、前処理は必要ありません。 
2. 文字列内のインデックス i ごとに、文字を複製するかどうかを決定します。 i > 0 の場合は左の近傍をチェックし、i < n - 1 の場合は右の近傍をチェックします。いずれかの近傍が存在し、現在の文字と異なる場合は、この位置に重複のマークを付けます。 
3. ルールに応じて、現在の文字の 1 つまたは 2 つのコピーを出力に追加します。 このステップでは、問題で説明されている変換を直接実装します。 
4. すべての位置を処理した後、構築された文字列を出力します。 

各インデックスでの決定は純粋にローカルであるため、処理の順序は正確さに影響しません。 便宜上、左から右にスキャンするだけです。 

### なぜ効果があるのか

 各位置の出力は、それが完全に均一な近傍セグメントの一部であるかどうかによってのみ決まります。 文字が厳密に同一の文字で囲まれている場合 (または、境界条件により異なる隣接文字がない場合)、その文字は一度保存されます。 それ以外の場合は重複します。 ルールは他の位置での変換に決して依存しないため、段階的な変更を導入するステップはなく、各決定は独立して最終的です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def transform(s: str) -> str:
    n = len(s)
    out = []

    for i in range(n):
        left_diff = i > 0 and s[i] != s[i - 1]
        right_diff = i < n - 1 and s[i] != s[i + 1]

        if left_diff or right_diff:
            out.append(s[i] * 2)
        else:
            out.append(s[i])

    return "".join(out)

def main():
    n = int(input().strip())
    for _ in range(n):
        s = input().strip()
        sys.stdout.write(transform(s) + "\n")

if __name__ == "__main__":
    main()
```コアロジックは以下に含まれます`transform`。 小切手`left_diff`そして`right_diff`「隣り合う文字は異なる」という条件をエンコードします。 ブール フラグを使用すると、境界処理ロジックの繰り返しを回避できます。 

微妙な点の 1 つは、単一文字列の処理です。 この場合、両方の近隣チェックは安全に失敗するため、キャラクタは複製されず、意図した動作と一致します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | 文字列あたり O(n) | 各キャラクターは 1 回訪問され、最大 2 つの隣接キャラクターに対してチェックされます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    def transform(s: str) -> str:
        n = len(s)
        out = []
        for i in range(n):
            left_diff = i > 0 and s[i] != s[i - 1]
            right_diff = i < n - 1 and s[i] != s[i + 1]
            if left_diff or right_diff:
                out.append(s[i] * 2)
            else:
                out.append(s[i])
        return "".join(out)

    n = int(input().strip())
    res = []
    for _ in range(n):
        res.append(transform(input().strip()))
    return "\n".join(res)

# provided sample-style cases

assert run("1\naaa\n") == "aaaa", "all equal"

# custom cases
assert run("1\na\n") == "a", "single character"
assert run("1\nab\n") == "aabb", "all transitions"
assert run("1\nabba\n") == "aabb bbaa".replace(" ", ""), "symmetric pattern"
assert run("1\naabaa\n") == "aabbaa", "mixed block structure"

 ## 特殊なケース

 次のような単一文字入力`"x"`は、境界のみのルールを示しています。 アルゴリズムが評価するのは、`i > 0`そして`i < n - 1`false なので、両方の近隣チェックはスキップされます。 文字は一度追加され、`"x"`必要に応じて。 

次のような均一な文字列`"aaaaa"`内部安定性がどのように動作するかを示します。 インデックス 2 の場合、隣接するものは両方とも同一であるため、重複は発生しません。 近隣比較が 1 つ欠落しているため、インデックス 0 と 4 のみが重複し、その結果、`"aaaaaa aaaa"`これを単純化すると`"aaaaaa aaaa"`? 実際にルールを注意深く適用すると、`"a a a a a a a a"`として折りたたまれた`"aaaaaaaa"`連結後、境界重複の予期される動作のみに一致します。
