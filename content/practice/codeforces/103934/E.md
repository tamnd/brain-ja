 ## 解決策
 ## 問題の理解

 私たちは一列に並んだ一連の数字を維持しています。各位置はイチジクの木を表し、その位置の値がその木のイチジクの数です。 時間の経過とともに、シーケンスは、範囲内のすべての値に変換を適用する、範囲を定数値で上書きする、範囲の合計を求めるという 3 種類の操作によって変更されます。 

非自明な演算は、値 x をオイラーの合計関数 φ(x) に置き換える変換です。 この関数は、1 から x までの整数が x と互いに素であるものがいくつあるかを返します。 たとえば、φ(1) = 1、φ(2) = 1、φ(5) = 4、および φ(10) = 4 です。この操作を繰り返し適用すると、値は急速に縮小し、最終的にはすべてが 1 に崩壊し、その後はそれ以上のアプリケーションは何も実行しません。 

この制約では、n と q の両方が最大 200,000、値が最大 1,000,000 に設定されます。 これにより、クエリごとに要素ごとに変換を適用するソリューションは即座に除外されます。 O(nq) ですら大きすぎ、ループ内の要素ごとに O(q log n) さえも不可能です。 有効なアプローチでは、絶対に必要な場合を除き、範囲内のすべての要素に触れることを避け、φ がどのように動作するかの構造を利用する必要があります。 

φ 操作を繰り返すと、微妙な問題が発生します。 常に φ をセグメント内のすべての要素にプッシュダウンする単純なセグメント ツリーは、安定した値の再計算を回避しない場合、TLE になります。 もう 1 つの失敗例は、範囲の割り当てに起因します。セグメントが上書きされると、以前のすべての φ 履歴は破棄されなければなりません。そうしないと、古くなった遅延効果によって結果が破損する可能性があります。 

具体的な例として、最初にセグメントを考えてみましょう [4, 6]。 φ を 1 回適用すると [2, 2] が得られ、もう一度適用すると [1, 1] が得られます。 実装が安定化をチェックせずに盲目的に φ を適用し続けると、決して変化しない 1 を繰り返し処理するという無駄な作業が発生します。 

別の例には、代入オーバーライド変換が含まれます。 セグメントに φ が遅延適用され、後で x で上書きされる場合、以前の保留中の φ 操作が新しい値に影響を与えてはなりません。 遅延状態を適切にリセットしない構造では、誤った結果が生成されます。 

## アプローチ

 ブルート フォース ソリューションは、すべてのクエリの範囲内のすべてのインデックスを直接反復処理します。 タイプ 1 の場合、各 a[i] は φ(a[i]) に置き換えられます。 タイプ 2 の場合、x が割り当てられます。 タイプ 3 の場合、合計が計算されます。 これは正しいですが、各操作には O(R−L+1) のコストがかかるため、最悪の場合は O(nq) の動作が発生します。これは、n と q の両方が 200,000 に達すると、実行可能な制限をはるかに超えます。 

重要な観察は、φ が強い収縮挙動を示すことです。 x ≥ 2 の場合、φ を繰り返し適用すると、x はすぐに 1 に向かって減少し、1 に達すると固定されます。 これは、個々の配列要素が安定するまでに意味のある変更を行えるのは少数回だけであることを意味します。 特に、φ(x) は、要素ごとの繰り返し更新がまれになる方法で x を減少させます。 

これにより、各セグメントの合計と最大値の両方を格納するセグメント ツリーが可能になります。 最大値が重要です。セグメント内の最大値が 1 の場合、φ は内部のどの要素にも影響を及ぼさないことがわかっているため、そのセグメントを完全にスキップできます。 それ以外の場合は、1 より大きい値がまだ含まれているセグメントにのみ降下します。 

範囲の割り当ては、合計と最大値の両方を上書きし、保留中の φ 効果をクリアすることによって処理されます。 代入によって履歴が完全に置き換えられるため、遅延 φ 状態は保存されません。 

その結果、各リーフがすべてのクエリにわたって少数の実際の φ 更新のみを経験するセグメント ツリーが得られますが、内部ノードは最大制約を使用して作業を効率的にプルーニングします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nq) | O(n) | 遅すぎる |
 | 最大枝刈りを行ったセグメント ツリー | O((n + q) log n + 合計 φ 更新) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

各ノードがそのセグメントの合計とそのセグメント内の最大値を格納するセグメント ツリーを維持します。 

1. 初期配列からセグメント ツリーを構築し、すべてのノードで合計と最大値の両方を保存します。 これにより、合計クエリに答えて、セグメントが依然として φ 更新を必要とするかどうかを判断することができます。 
2. タイプ 3 クエリの場合、格納されているセグメント [L, R] の合計を返します。 これは、すべての更新で常に正しいセグメント合計が維持されるため、機能します。 
3. タイプ 2 クエリの場合、合計を (セグメント長 × x)、最大値を x に設定し、そのセグメント内の以前の変換状態を破棄することにより、[L, R] 内のすべての要素を x に割り当てます。 代入によって値が完全にリセットされるため、これは正しいです。 
4. タイプ 1 クエリの場合、セグメントに φ を再帰的に適用します。 セグメントの最大値が 1 の場合、φ(1) = 1 で何も変わらないため、セグメントを完全にスキップします。 この剪定により、無駄な作業の繰り返しを防ぐことができます。 
5. φ の適用中にリーフ ノードに到達した場合、その値を直接 φ(value) に置き換え、その合計と最大値を更新します。 
6. 子を更新した後、親ノードの合計とその子からの最大値を再計算します。 

実装の重要な詳細は、φ 更新がまだ 1 より大きい値を含むセグメントにのみプッシュされ、安定化された領域を再検討することに時間を無駄にしないようにすることです。 

### なぜ効果があるのか

 各ノードは、合計と最大値を通じてセグメントの現在の状態を正確に表します。 最大値は、それ以上の φ 操作でセグメントを変更できるかどうかの証明書として機能します。 φ(x) = x は、縮小が繰り返されるこのコンテキストでは x = 1 に対してのみ成立するため、セグメントが最大値 1 に達すると、タイプ 1 の操作では不変になります。 範囲の割り当ては、値と構造の両方を上書きすることでこの不変式をきれいにリセットし、古い変換が残らないようにします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXV = 10**6 + 5

# Euler totient precompute
phi = list(range(MAXV))
for i in range(2, MAXV):
    if phi[i] == i:
        for j in range(i, MAXV, i):
            phi[j] -= phi[j] // i

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.sum = [0] * (4 * self.n)
        self.mx = [0] * (4 * self.n)
        self.build(1, 0, self.n - 1, arr)

    def build(self, v, l, r, arr):
        if l == r:
            self.sum[v] = arr[l]
            self.mx[v] = arr[l]
            return
        m = (l + r) // 2
        self.build(v*2, l, m, arr)
        self.build(v*2+1, m+1, r, arr)
        self.pull(v)

    def pull(self, v):
        self.sum[v] = self.sum[v*2] + self.sum[v*2+1]
        self.mx[v] = max(self.mx[v*2], self.mx[v*2+1])

    def range_phi(self, v, l, r, ql, qr):
        if self.mx[v] == 1:
            return
        if l == r:
            self.sum[v] = phi[self.sum[v]]
            self.mx[v] = self.sum[v]
            return
        m = (l + r) // 2
        if ql <= m:
            self.range_phi(v*2, l, m, ql, qr)
        if qr > m:
            self.range_phi(v*2+1, m+1, r, ql, qr)
        self.pull(v)

    def range_set(self, v, l, r, ql, qr, x):
        if ql <= l and r <= qr:
            self.sum[v] = (r - l + 1) * x
            self.mx[v] = x
            return
        m = (l + r) // 2
        if ql <= m:
            self.range_set(v*2, l, m, ql, qr, x)
        if qr > m:
            self.range_set(v*2+1, m+1, r, ql, qr, x)
        self.pull(v)

    def range_sum(self, v, l, r, ql, qr):
        if ql <= l and r <= qr:
            return self.sum[v]
        m = (l + r) // 2
        res = 0
        if ql <= m:
            res += self.range_sum(v*2, l, m, ql, qr)
        if qr > m:
            res += self.range_sum(v*2+1, m+1, r, ql, qr)
        return res

def main():
    n, q = map(int, input().split())
    arr = list(map(int, input().split()))
    st = SegTree(arr)

    out = []
    for _ in range(q):
        tmp = list(map(int, input().split()))
        t, l, r = tmp[0], tmp[1]-1, tmp[2]-1
        if t == 1:
            st.range_phi(1, 0, n-1, l, r)
        elif t == 2:
            x = tmp[3]
            st.range_set(1, 0, n-1, l, r, x)
        else:
            out.append(str(st.range_sum(1, 0, n-1, l, r)))

    print("\n".join(out))

if __name__ == "__main__":
    main()
```セグメント ツリーには、ノードごとに合計と最大の 2 つの集計が保存されます。 Sum はタイプ 3 クエリを直接サポートしますが、maximum は不必要な φ の伝播を防ぐ枝刈りメカニズムをサポートします。 φ 演算は、制御された降下として実装されます。値 1 で完全に安定していないノードのみに入ります。リーフ ノードは、O(1) 遷移に対して事前計算されたテーブルを使用して φ を適用します。 

範囲の割り当ては両方の集合体を直接上書きし、当然のことながら、φ の効果に関する以前の構造的な仮定を消去します。φ は可逆的ではなく、遅延合成が正しく行われないため、これが必要になります。 

## 実用的な例

 配列 [4, 6, 5] を考えてみましょう。 φを全範囲に適用すると[2, 2, 4]となります。 

| ステップ | 操作 | 配列状態 | セグメント最大値 |
 | --- | --- | --- | --- |
 | 1 | イニシャル | [4、6、5] | 6 |
 | 2 | φ(1,3) | [2、2、4] | 4 |
 | 3 | 合計クエリ | 8 | 4 |

 このトレースは、φ が縮小値を更新する方法と、集計を通じて合計の一貫性がどのように保たれるかを示します。 

ここで、変換をオーバーライドする代入について考えてみましょう。 

| ステップ | 操作 | 配列状態 | セグメント最大値 |
 | --- | --- | --- | --- |
 | 1 | イニシャル | [2、2、4] | 4 |
 | 2 | セット(2,3)=3 | [2、3、3] | 3 |
 | 3 | φ(1,3) | [1、2、2] | 2 |

 これは、代入によって以前の変換履歴が完全にリセットされ、φ が新しい状態から継続されることを示しています。 

図示されている重要なプロパティは、φ 更新が履歴ではなく現在の値のみに依存するということです。そのため、現在の集計のみを保存するだけで十分です。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

 | 時間 | O((n + q) log n + 合計 φ 降下数) | 各クエリは関連するセグメント ツリー ノードのみに触れ、数回の φ 適用後に各要素は 1 になります。 
| スペース | O(n) | 合計と最大値のセグメント ツリー ストレージ |

## 特殊なケース

 重要なエッジケースは、すでに安定した値に対して φ の適用を繰り返すことです。 いくつかの演算後にセグメントがすべて 1 になる入力を考えてみましょう。 セグメント ツリーには、最終的にその領域の最大値 = 1 が格納されます。 [1, 1, 1] のような入力の場合、タイプ 1 の演算は任意の数で実行されても配列は変更されず、再帰降下は生成されません。 アルゴリズムは、すべてのノードで mx[v] == 1 をチェックし、すぐに返すことによってこれを処理します。 

もう 1 つのエッジ ケースは、部分的な φ 更新後の完全な上書きです。 セグメント [1, 8, 3] が φ によって部分的に [1, 4, 2] に削減され、タイプ 2 の操作によって同じセグメントが 7 に設定されるとします。合計と最大値の両方を完全に上書きしないと、古い φ 状態が持続し、将来の更新に誤った影響を与える可能性があります。 このアルゴリズムは、割り当てをノードのメタデータの完全な置き換えとして扱うことでこれを回避します。 

最後に、単一要素セグメントにより、リーフ遷移の正確さが保証されます。 10 のような要素の場合、φ(10) = 4、次に φ(4) = 2、次に φ(2) = 1 となり、その後安定します。 安定化が上向きに伝播すると、その祖先が最大値 = 1 を報告するため、セグメント ツリーは最終的にこのリーフの再訪問を停止します。
