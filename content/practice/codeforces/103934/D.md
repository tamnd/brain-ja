 ## 問題の理解

 つまり、すべてのアイテムは「1 つの素数が欠けている以外はすべて」という構造になっており、アイテムを購入するということは、どの素数を因数分解から除外するかを選択することに相当します。

主な難点は、各価格が最大 3000 個の素数の積であるため、関係する値が非常に大きいことです。 構造を利用しない限り、直接的な数値シミュレーションはすぐに実用的ではなくなります。 

素朴な懸念は、オーバーフローまたは表現の制限です。 固定幅の整数を使用する言語では、単一の価格を構築することさえ不可能です。 Python であっても、問題を構造的に軽減しなければ、このような大きな整数をやみくもに合計すると、パフォーマンスの問題が発生する危険があります。

もう 1 つの重要な状況は次のような場合です。$n = 1$。 この場合、項目は 1 つだけであり、問​​題はその 1 つの値が以下に等しいかどうかを確認することになります。$d$。

 ## アルゴリズムのチュートリアル

 ### 1. グローバルな製品構造を暗黙的に構築する

 明示的にビルドすることはありません$P$。 代わりに、各項目がどのように関連しているかを推論するだけです。$i$を除くすべての素数の積です。$a_i$。 これにより、素数のみを使用して項目を比較できるようになります。$a_i$、巨大な整数を形成することはありません。 

### 2. 欠落している素数によって項目を並べ替える

 インデックスを次のように並べ替えます。$a_i$は降順です。 これは、より大きな素数を削除するとより小さな積が得られ、より小さな素数を削除するとより大きな積が得られるため、項目は値の増加順に並べ替えられることを意味します。 

この順序付けは、システムを単調にするため、非常に重要です。より早い選択は、合計へのより強い寄与に対応します。 

### 3. 目標合計に向けてサブセットを貪欲に構築する

 アイテムは最大値から最小値の順に処理されます。 各ステップで、残りの必要な合計に収まるかどうかに基づいて、現在のアイテムを含めるかどうかを決定します。 

重みの構造によって引き起こされる優勢特性のため、この決定は決定的です。異なる素因数によって生じる乗法的なギャップのため、より大きな項目をより小さな項目の組み合わせから「構成」することはできません。 

### 4. 目標値との比較$d$当社は現在までの合計額を維持し、それが超過しないようにします$d$。 正確に一致させることができれば$d$結局のところ、答えはイエスです。 

### なぜ効果があるのか

 各項目は、共通の積からちょうど 1 つの素数を削除することに対応します。 これにより、欠落している素数が小さい項目が、欠落している素数が大きい項目よりも指数関数的に大きくなるという厳密な順序付けが作成されます。 すべての素数は個別であるため、小さい項目をキャンセルまたは再結合しても、大きい項目を正確に複製することはできません。 これにより、重みが超増加する貪欲なコイン システムと同様の標準構造が強制され、ローカルな決定がグローバルな最適性を無効にしないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    c = list(map(int, input().split()))

    # Build d as big integer product
    d = 1
    for x in c:
        d *= x

    # Build full product P
    P = 1
    for x in a:
        P *= x

    # Build item values: P / a[i]
    items = [P // x for x in a]

    # Sort by value descending (largest first)
    items.sort(reverse=True)

    total = 0
    for v in items:
        if total + v <= d:
            total += v

    print("S" if total == d else "N")

if __name__ == "__main__":
    main()
```この実装は、Python の非常に大きなプロダクトを処理できる能力に依存して、Python の大きな整数を使用して必要な値を直接構築します。 アイテム価格のリストは一度計算され、常に最大の寄与が最初に考慮されるように並べ替えられます。 

貪欲な蓄積ステップがソリューションの中核です。 目標金額を超えていない場合にのみ項目を追加します。超えてしまうと、$d$、残りの小さいアイテムを組み合わせても、異なるアイテム サイズ間の構造上の優位性によるオーバーシュートを補償することはできません。
