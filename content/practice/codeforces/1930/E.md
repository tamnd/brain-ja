 ## 問題の理解

 配列から始めます$$[1,2,3,\dots,n].$$値$k$プロセス全体で固定されます。 1 回の操作で、長さの部分列を選択します。$2k+1$。 選択した要素のうち、最初の要素を削除します。$k$そして最後$k$、真ん中のものだけを残します。 

元の配列は厳密に増加しており、要素のみを削除しているため、すべての最終状態は単に次のサブシーケンスになります。$[1,2,\dots,n]$。 

タスクは次のとおりです。$k$から$1$に$\lfloor (n-1)/2 \rfloor$、操作を何度でも実行した後に表示される異なるサブシーケンスの数を数えます。 

答えはモジュロで報告する必要があります$998244353$。 

制約は大きいです。 1 つのテストでできることは、$n=10^6$、およびすべての合計$n$価値観も$10^6$。 個々のサブシーケンスを検査するアルゴリズムは不可能です。$2^n$彼らのうち。 たとえ$O(n^2)$アルゴリズムは次のように実行します$10^{12}$最悪の場合の運用。 に近いものが必要です$O(n \log n)$全体$k$。 

難しいのは、どのサブシーケンスが到達可能であるかを正確に特徴付けることです。 

考慮する$n=5$そして$k=2$。 1 回の操作で長さのサブシーケンスを選択します$5$したがって、削除できる唯一の方法は、選択した中央の要素の両側にある 2 つの要素を削除することです。 唯一の重要な結果は、$[3]$。 「奇数の要素を持つサブシーケンスはすべて到達可能である」という単純な考えでは、多くの不可能な配列が誤ってカウントされてしまいます。 

もう一つの微妙なケースは、$k=1$そしてその後$[1,4]$で$n=4$。 2 つの要素が削除されました。これは次の倍数です。$2k$、しかしそれだけでは十分ではありません。 到達可能性は、削除された位置の数だけでなく、その構造にも依存します。 

問題の核心は、到達可能なサブシーケンスの明確な特徴付けを見つけることです。 

## アプローチ

 ブルート フォース ソリューションでは、すべての状態をサブシーケンスとして表示し、可能なすべての操作に対して BFS を実行します。 到達可能なすべての配列は最終的に検出されるため、これは正しいです。 

残念ながら、状態空間にはすでに$2^n$後続。 のために$n=30$これはすでに 10 億州を超えているため、このアプローチは実際の制約に達するずっと前に役に立たなくなります。 

重要な観察は、作戦はどのポジションが生き残るかにのみ依存するということです。 

最終的なサブシーケンスを長さのバイナリ文字列で表現します。$n$:$$1 = \text{element survives}, \qquad 0 = \text{element deleted}.$$各操作で正確に削除されます$2k$要素。 したがって、ゼロの合計数は次の倍数でなければなりません。$2k$。 

驚くべき事実は、この条件がほぼ十分であるということです。 

削除された要素の数を次のようにします。$2ck$。 空ではないサブシーケンスは、少なくとも以下のような生存位置が存在する場合にのみ到達可能です。$k$削除された要素はその左側にあり、少なくとも$k$削除された要素はその右側にあります。 

この特徴付けにより、問題は純粋なカウントに変わります。 

固定の場合$k$、 させて$2ck$削除された要素の数になります。 がある$$\binom{n}{2ck}$$正確なバイナリ文字列$2ck$ゼロ。 

ここで、不正な文字列、つまり少なくとも$k$両側にゼロ。 

不適切な構成では、非常に硬い形状になります。 せいぜい別として$k-1$左端付近と最大でゼロ$k-1$右端近くにゼロがある場合、残りのすべてのゼロは 1 つの連続したブロックを形成する必要があります。 そのブロックを単一のオブジェクトに圧縮した後、次の位置を選択します。$2k-1$間の特別なオブジェクト$$n-(2ck-(2k-2))+1$$合計ポジション。 これにより、$$\binom{n-2ck+2k-1}{2k-1}.$$したがって、固定の場合$k$、$$\text{answer} = 1+ \sum_{c\ge1} \left( \binom{n}{2ck} - \binom{n-2ck+2k-1}{2k-1} \right).$$余分な$1$ゼロの削除に対応する元の配列をカウントします。 

残りの作業は、二項係数の効率的な評価です。

### なぜ効果があるのか

 到達可能な最終配列は、生き残った位置のセットによってのみ表現できます。 

すべての操作で正確に削除されます$2k$要素なので、削除される位置の数は次の倍数である必要があります。$2k$。 到達可能な状態の特徴付けでは、生き残っている位置が少なくとも$k$両側の要素を削除しました。 

固定削除数の場合$2ck$、すべてのバイナリ文字列は良いか悪いかのどちらかです。 すべての文字列をカウントすると、$\binom{n}{2ck}$。 悪い文字列とは、まさに余分なゼロがすべて中央の 1 つのブロックに集約され、カウントが低下する文字列です。$\binom{n-2ck+2k-1}{2k-1}$。 

すべての文字列から不正な文字列を減算すると、その削除数に対して到達可能な構成の数が得られます。 すべての有効な倍数の合計$2k$、および変更されていない配列を追加すると、到達可能なすべての最終配列が 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353
MAXN = 10 ** 6 + 5

fact = [1] * MAXN
for i in range(1, MAXN):
    fact[i] = fact[i - 1] * i % MOD

inv_fact = [1] * MAXN
inv_fact[-1] = pow(fact[-1], MOD - 2, MOD)

for i in range(MAXN - 2, -1, -1):
    inv_fact[i] = inv_fact[i + 1] * (i + 1) % MOD

def C(n, r):
    if r < 0 or r > n or n < 0:
        return 0
    return fact[n] * inv_fact[r] % MOD * inv_fact[n - r] % MOD

t = int(input())

for _ in range(t):
    n = int(input())

    res = []

    for k in range(1, (n - 1) // 2 + 1):
        ans = 1

        limit = (n - 1) // (2 * k)

        for c in range(1, limit + 1):
            deleted = 2 * k * c

            ans += C(n, deleted)
            ans -= C(n - deleted + 2 * k - 1, 2 * k - 1)

        ans %= MOD
        res.append(str(ans))

    print(" ".join(res))

機能`C(n, r)`無効な引数を明示的に処理します。 これにより、圧縮カウント式が負の上限インデックスを生成する場合の微妙なバグが回避されます。 

固定の場合$k$、変数`c`のグループ数を表します$2k$削除が発生しました。 有効な最大値は次のとおりです。$\lfloor (n-1)/(2k) \rfloor$少なくとも 1 つの要素が存続する必要があるためです。 

表現```
C(n - deleted + 2 * k - 1, 2 * k - 1)
```圧縮後の不正な構成の数です。 を入手する`-1`ここでの用語の間違いは、オフバイワンの間違いの最も一般的な原因です。

 ## 特殊なケース

 ### 実行できる操作は 1 つだけです

 入力:```
1
5
```のために$k=2$、唯一可能な削除数は次のとおりです。$4$。 アルゴリズムは 1 つの項のみを評価します。$$1+\binom{5}{4}-\binom{4}{3} = 1+5-4 = 2.$$答えは正解です`2`、元の配列とシングルトン配列に対応します`[3]`。 

### 削除数は次の倍数です$2k$しかし、構成に到達できません

 テイク$n=4$、$k=1$。 生存者に対応するサブシーケンス`{1,4}`分割条件を満たす 2 つの要素を削除します。 単純な解決策では、それを自動的にカウントします。 

不正な構成の減算により、まさにそのようなケースが排除されます。 この式は、両側に少なくとも 1 つの削除された要素が存在する位置がないすべてのバイナリ文字列を減算します。 

だからこそ、最終的な答えは、`4`より大きな不正確な値の代わりに。 

### 可能な最大値$k$いつ$$k=\left\lfloor \frac{n-1}{2} \right\rfloor,$$内側のループは 1 回だけ実行されます。$2k$すでに近づいています$n$。 

例えば、$n=5, k=2$:$$\left\lfloor \frac{n-1}{2k}\right\rfloor = 1.$$実装では、特別なケースを使用せずにこれを自然に処理し、合計制限における境界エラーを回避します。
