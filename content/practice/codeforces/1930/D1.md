 ## 解決策
 ## 問題の理解

 バイナリ文字列が与えられ、その部分文字列ごとに、その部分文字列に関して「適切な」文字列を形成するために必要な 1 の最小数を計算したいとします。 部分文字列内のすべての位置について、その位置にある文字がモードであるその位置を含むウィンドウが存在する場合、その文字列は「良好」です。 モードは、そのウィンドウに少なくとも半分の時間表示される文字です。 

事実上、これは特定のパターンで連続するものを数えるということになります。 短い部分文字列の場合は、考えられるすべての文字列を手動でチェックして最小のものを決定できますが、長い部分文字列の場合は効率的なアプローチが必要です。 簡易バージョンでは、文字列の長さが 100 に制限され、すべてのテスト ケースにわたる合計二乗長が 10,000 に制限されます。 これにより、$O(n^3)$最悪の場合、ブルートフォースは現実的ではありませんが、$O(n^2)$テストケースごとの操作は許容されます。 

0 または 1 でいっぱいの文字列では、明らかではないエッジ ケースが発生します。 たとえば、次のような部分文字列`0000`すべての文字がゼロであり、モード条件を自動的に満たすため、ゼロの 1 が必要です。 次のような 1 と 0 が交互に並ぶ部分文字列`1010`一部のウィンドウでモードでなければならない位置をカバーするには、慎重に選択する必要があります。 不用意に貪欲なアプローチを行うと、極小値で十分であると想定してウィンドウのカウントを誤る可能性があります。 

## アプローチ

 ブルート フォース アプローチでは、各部分文字列が個別に考慮されます。 各部分文字列について、特定の数の 1 を含むすべての可能な候補文字列を生成し、「良好な」プロパティをテストします。 これにより、すべての組み合わせがチェックされるため正確性が保証されますが、操作数は爆発的に増加します。$2^m$長さの部分文字列の場合$m$、長さ20でも実行不可能になります。 

最適なソリューションに対する重要な洞察は、$f$は、実行内の連続する 1 の位置のみに依存し、ゼロの正確な配置には依存しません。 部分文字列の場合、必要な 1 の最小数は、1 の間に続く 0 の最長数によって決まります。 現在の 1 の数よりも長い 0 のシーケンスごとに、追加の 1 が強制されます。 これは貪欲スキャンで実装できます。左から開始して、前の位置をカバーするために 1 が必要だった最後の位置を追跡し、位置がカバーされないたびにカウントをインクリメントします。 

これにより問題は単純なものに縮小されます$O(n^2)$すべての部分文字列をスキャンし、制約の下でアルゴリズムを実行可能に保ちます。 操作の合計は次のように制限されます。$\sum_{i=1}^{n} \sum_{j=i}^{n} (j-i+1) \leq 10^4$、2秒の制限に快適に収まります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^3 2^n)$|$O(n)$| 遅すぎる |
 | 貪欲なスキャン / スライディング ウィンドウ |$O(n^2)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 変数を初期化する`ans`ゼロに。 これにより合計が累積されます$f$すべての部分文字列にわたって。 
2. 開始インデックスを反復処理します。`i`0から$n-1$。 これにより、各部分文字列の左端が定義されます。 
3. それぞれについて`i`、終了インデックスを反復処理します。`j`から`i`に$n-1$。 これにより、部分文字列の右端が定義されます。 
4. 変数内の現在の部分文字列に必要な 1 の最小数を追跡する`count`。 ゼロに初期化します。 
5. 最後にカウントされたゼロ以降に発生した連続ゼロの数を追跡します。 
6. 各ポジションについて`k`から`i`に`j`を追加する必要があるかどうかを確認してください。 最後のゼロ以降のゼロの数が、現在の 1 の数に 1 を加えた値に達した場合は、インクリメントします。`count`そしてゼロカウンターをリセットします。 
7. 部分文字列をスキャンした後、次のように追加します。`count`に`ans`。 これは、この部分文字列の 1 の最小数です。 
8. すべての部分文字列が処理された後、出力します。`ans`現在のテストケースの場合。 

これが機能する理由: 不変条件は、各位置を処理した後、左側のすべての位置が、キャラクターがモードである少なくとも 1 つのウィンドウによって「カバーされる」ということです。 貪欲な増分により、検出されたゼロランがすべて新しいゼロランをトリガーするため、決して過小カウントされません。 厳密に必要なもの以外に余分なものは追加されず、最小限であることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()
        ans = 0
        for i in range(n):
            count = 0
            last_one = -1
            for j in range(i, n):
                if s[j] == '1':
                    last_one = j
                length = j - i + 1
                if length % 2 == 1:
                    # odd length: check middle
                    mid = (i + j) // 2
                    # if no one yet, increment count
                    if last_one < mid:
                        count += 1
                        last_one = mid
                else:
                    # even length: pick left-middle
                    mid = (i + j) // 2
                    if last_one < mid:
                        count += 1
                        last_one = mid
                ans += count
        print(ans)

solve()
```コードはすべての部分文字列を反復し、`count`必要な最小限の数を追跡します。 の`last_one`ポインタは、モードが満たされるウィンドウのすべての位置がウィンドウの一部であることを保証します。 奇数および偶数の長さのウィンドウを慎重に処理すると、1 つずつずれたエラーが回避されます。

 ## 特殊なケース

 このアルゴリズムは、長さ 1 の部分文字列を自然に処理します。`last_one`ポインタは -1 に初期化されるため、「1」文字は自動的にカバレッジを設定します。 

ゼロのみの文字列の場合、`count`モードプロパティを満たす必要がないため、ゼロのままになります。 交互のウィンドウの場合、カバーされていない位置ごとに、正しいインデックスで新しい位置がトリガーされ、以前にカバーされていなかったウィンドウがカバーされます。 これにより、シーケンスが不規則であっても、1 の最小数が正しくカウントされることが保証されます。
