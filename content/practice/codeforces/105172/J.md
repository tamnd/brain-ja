 ## 問題の理解

 一連の整数が与えられているので、それを正確に切り分ける必要があります。$k$連続した作品。 シーケンスが分割されたら、各部分の内部を調べて、その部分内の合計が固定値と正確に等しいサブ配列の数を数えます。$x$。 パーティションの最終的なコストは、すべてのパーティションのこれらのカウントの合計です。$k$シーケンスを分割するすべての有効な方法よりもコストを最小限に抑えたいと考えています。 

重要な点は、すべてのセグメントが固定されると独立してコストに寄与しますが、どこをカットするかの選択はサブ配列のグループ化方法、つまり「合計が等しい」の数に影響するということです。$x$」の間隔は各セグメント内でカウントされます。 

制約$n \le 3000$そして$k \le 20$立方体的なものはすぐに提案してください$n$許容可能ですが、指数関数的な分割を伴うものや、すべてのパーティションのセグメント コストを最初から再計算するものは遅すぎます。 ここでの一般的なしきい値は約$n^2 k$、それは約です$1.8 \cdot 10^8$、境界線にありますが、最適化された DP では許容されます。 

単純な試みでは、分割するすべての方法を列挙しようとするでしょう。$k$セグメントがありますが、それは組み合わせ的に不可能です。$\binom{n-1}{k-1}$すでに天文学的な選択肢$n=3000, k=20$。 

2 番目の単純な間違いは、各セグメントの有効な部分配列の数を繰り返し再計算することです。 セグメントを固定したとしても、部分配列の数の合計を計算すると、$x$各セグメント内で$O(n^2)$それをパーティション検索内に埋め込むと、少なくとも$O(n^3)$あるいはさらに悪いことに。 

微妙なエッジケースは次のような場合です$k = n$。 この場合、すべてのセグメントの長さは 1 なので、1 より長い部分配列は存在しません。 答えは単純に次の要素の数です。$x$。 セグメントの長さが少なくとも 2 でなければならないと想定する DP はここで失敗します。 

もう 1 つのエッジケースは次のような場合です$k = 1$。 次に、まったく分割せず、合計が次のような完全な配列内のすべての部分配列をカウントするだけです。$x$。 これは、サブ配列カウント方法の正確性のベースラインとして機能します。 

## アプローチ

 まずブルートフォースの観点から考えます。 配列のパーティションを次のように修正すると、$k$セグメントを分割すると、各セグメントのコストを個別に計算できます。 For a segment$[l, r]$、合計を持つ部分配列の数$x$プレフィックスの合計とハッシュ マップを使用して計算できます。$O(r-l+1)$。 これはすでに与えられています$O(n)$したがって、セグメントごとに$O(nk)$固定パーティションの場合。 

問題は、パーティションが急激に多くなることです。 あらゆる方法で配置してみる$k-1$カットは不可能です。 

重要な観察点は、セグメント内のコストはグローバル構造ではなく、そのエンドポイントのみに依存するということです。 これにより、この問題は古典的なインターバル パーティション動的プログラミングの問題になります。 各セグメントの終了位置を段階的に決定する DP を定義します。 

移行を効率的に行うために、すべての間隔のコストを事前計算します。$[l, r]$、これはその中にある部分配列の数であり、その合計は$x$。 この前処理は次のように実行できます。$O(n^2)$開始点ごとのプレフィックス合計と周波数マップを使用します。 

このコスト テーブルが利用可能になると、問題は次のようになります。プレフィックスを分割する$1..i$の中へ$j$コストの合計を最小限に抑えるセグメント。 トランジションでは、以前のすべてのカット位置が試行されます。

 ## アルゴリズムのチュートリアル

 プレフィックスの合計を定義します$p[i]$、 どこ$p[i]$最初の合計です$i$要素。 これにより、部分配列の合計を一定時間で計算できるようになります。 

テーブルを事前計算します$cost[l][r]$、内部にあるサブ配列の数を数えます$[l, r]$正確に合計がある$x$。 固定ごとに$l$、延長します$r$そして、そのセグメント内で見られるプレフィックス合計のハッシュマップを維持します。 

次に DP を定義します。 

しましょう$dp[j][i]$プレフィックスを分割するための最小コストになります$1..i$正確に$j$セグメント。 

トランジションでは、位置から始まる最後のセグメントが考慮されます。$t+1$そして終わる$i$、 それで：$$dp[j][i] = \min_{t < i} dp[j-1][t] + cost[t+1][i]$$答えは$dp[k][n]$。 

### ステップ

 1. プレフィックスの合計を計算する$p[i]$。 これにより、定数時間の部分配列合計クエリが可能になります。 
2. 事前計算$cost[l][r]$みんなのために$1 \le l \le r \le n$。 それぞれについて$l$、拡張中にプレフィックス合計の周波数マップを維持します。$r$、その頻度を数えます$p[r] - p[i] = x$。 
3. DP 配列を無限大で初期化し、$dp[0][0] = 0$。 これは、ゼロセグメントに分割された空のプレフィックスを表します。 
4. セグメント数ごと$j$1から$k$、すべてを計算します$dp[j][i]$のために$i \ge j$。 
5. それぞれについて$i$、以前のカット位置をすべて試してください$t$から$j-1$に$i-1$、更新中$dp[j][i]$事前に計算された間隔コストを使用します。 
6. 戻る$dp[k][n]$。
