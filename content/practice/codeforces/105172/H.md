 ## 解決策
 ## 問題の理解

 長さのバイナリターゲットパターンが与えられています$n$、各列に 2 つのセルがある 2×n グリッドを記述します。 1 とマークされたセルは、配置されたタイルで 1 回だけ覆われなければなりませんが、0 とマークされたセルは覆われないままでなければなりません。 サイズ 1×2 と 1×3 のタイルを配置することができ、それらを回転させることができるため、グリッドの境界内に収まる限り、ドミノやトリミノを水平または垂直に配置することができます。 

各タイルは、行内または行全体で連続するセルをカバーし、タイルが重なることはできません。 タスクは、必要なすべての 1 セルを正確にカバーし、すべての 0 セルを回避するようなタイルの配置が存在するかどうかを判断することです。 

制約は合計すると大きくなります。$n$すべてのテストケースにわたって、$10^5$したがって、どのソリューションもテスト ケースごとに直線的な時間で実行する必要があります。 これにより、配置を組み合わせて探索しようとしたり、タイル構成のバックトラッキングを使用したりするアプローチは即座に除外されます。これは、中程度の分岐要素でも爆発的に増加するためです。$10^5$ポジション。 

微妙な問題は、タイルが水平方向に 3 つのセルにまたがることができるという事実から生じます。これは、ローカルな決定が依存関係を複数の位置に伝播する可能性があることを意味します。 最初のカバーされていない 1 セルにタイルを配置するローカルな妥当性のみをチェックする単純な貪欲な方法は、将来の矛盾を回避するより適切な長い配置をブロックする可能性があるため、失敗する可能性があります。 

いくつかの代表的な失敗パターンがこれを明らかにしています。 

次のようなセグメントを考えてみましょう。```
n = 3
top:    111
bottom: 111
```単純なアプローチでは、縦方向のドミノを列ごとに貪欲に配置しようとするかもしれませんが、許可された形状ですべてのセルを最適にカバーする方法は残されていません。 

別の例:```
top:    01101
bottom: 11111
```最も長いタイル (1×3) を常に最初の利用可能な位置に配置しようとする貪欲な場合、タイルの実行の最後に使用できないギャップが作成される可能性があります。 

これらのケースは、問題がローカル一致に関するものではなく、2 つの行間で連続する一致がどのように相互作用するかに関するものであることを示しています。 

## アプローチ

 ブルートフォース解釈では、各セルを決定点として扱います。カバーされていない 1 セルに遭遇するたびに、有効なタイル (垂直ドミノ、水平ドミノ、または水平 3 ブロック) を配置しようとします。 すべての配置を再帰的に試し、競合が発生した場合は元に戻します。 

これは、制約と一致するすべてのタイリングを調査するため、正しいです。 ただし、最悪の場合、各位置が複数のタイル配置に分岐し、一定の長さのタイルが配置される可能性があります。$n$指数関数的な分岐を生成します。 枝刈りを行っても、状態空間は指数関数的なままです。$n$、実行不可能になります$n = 10^5$。 

重要な観察は、2 行グリッド内の有効なタイリングの構造が高度に制約されていることです。 各列で重要なのは、配置の完全な履歴ではなく、水平方向に伸びるタイルからの「キャリーオーバー」効果があるかどうかです。 これにより、プロセスをローカル状態の貪欲スキャンに圧縮することができます。 

タイルの観点から考えるのではなく、グリッドを列ごとに再解釈します。 各列には 2 つのセルがあり、それらが必須 (1) か禁止 (0) かを考慮します。 左から右にスキャンし、以前の選択によって引き起こされた強制的な水平構造の中に現在いるかどうかを維持します。 

重要な単純化は、2×n ストリップでは、有効なタイリングを正規化して、1 が表示される最初の列で決定が貪欲に解決されるようにできることです。これは、長いタイル (長さ 3) は、両方の行にわたって必要なセルの連続ブロックと完全に位置合わせできる場合にのみ重要となるためです。 セグメント内の 2 つの行間の不一致が検出されると、問題は残りの 1 セルが制約されたパターンで一致できるかどうかを確認することになり、これは線形の実現可能性チェックに集約されます。 

したがって、この問題は、列を持たない列の最大連続セグメント (top=0 とbottom=0 を同時に) が、2 行タイリング ルールから導出されたローカル構成の小さなセットと互換性があるかどうかを検証することと同等になります。 これにより、定常状態遷移を伴う単一の左から右へのスキャンに減ります。

 ## アルゴリズムのチュートリアル

 各テスト ケースを個別に処理し、グリッドを左から右にスキャンします。 

1. 各列をペアとして解釈します$(a_i, b_i)$、それぞれが 0 または 1 です。両方が 0 の場合、禁止されたセルをタイルでカバーできないため、列は完全にブロックされ、そのような列は区切り文字として機能します。 
2. 配列を完全にブロックされた列で区切られたセグメントに分割します。 各セグメント内で、すべてのセルが 1 である場合は、必ず 1 回カバーされる必要があります。 
3. 各セグメントについて、有効なタイル配置を使用して現在の列の配置を拡張できるかどうかを示すローカルの実現可能性状態を維持します。 唯一の意味のある曖昧さは、2 列または 3 列にわたる水平タイルの使用を強制されるかどうかです。 
4. セグメントを反復処理し、列パターンに基づいて状態を更新します。 

- 列が (0,1) または (1,0) の場合、垂直方向の不均衡が発生し、局所的に解決するか、水平方向の配置に持ち込む必要があります。 
- 両方の行が 1 の場合、垂直方向のカバレッジを配置するか、水平方向の構造を開始するかを柔軟に選択できます。 
5. 重要な移行ルールは、不一致パターンに遭遇した場合は必ず、最大 2 列または 3 列以内で互換性のある継続とペアにできることを確認する必要があるということです。 ブロッキング不一致が発生したためにそのようなペアリングが不可能になった場合、拒否されます。 
6. 矛盾なくすべてのセグメントのスキャンが完了したら、承認します。 

この実装では、前の列が水平方向の継続のために「開いている」かどうかという 2 つの状態だけが重要であることに注目することで、このアイデアをさらに単純化します。 不一致の列を貪欲に一致させ、許可されたタイルの長さ内で解決できることを保証します。 

### なぜ効果があるのか

 2 行グリッド内の有効なタイルは、水平タイルが可能な限り左揃えで配置されるように変換できます。 この正規化により、行間に不一致が現れるたびに、その位置またはその前から始まる水平タイルによって直ちに不一致が消費されることが保証されます。 タイルの長さは最大 3 であるため、未解決の不一致は、境界のあるウィンドウを超えて伝播することはできません。 この制限された依存関係により、無効な構成によって後続の最大 2 つの列内で矛盾が強制されるため、ローカル状態の追跡のみでスキャンを正確に保つことができます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = input().strip()
        b = input().strip()

        i = 0
        ok = True

        while i < n:
            if a[i] == '0' and b[i] == '0':
                i += 1
                continue

            # process a segment without full-zero columns
            need = []
            j = i

            while j < n and not (a[j] == '0' and b[j] == '0'):
                need.append((a[j] == '1', b[j] == '1'))
                j += 1

            m = len(need)

            # dp state: 0 = no pending horizontal, 1 = pending
            dp0, dp1 = True, False

            for k in range(m):
                top, bot = need[k]

                new0 = new1 = False

                if dp0:
                    if top and bot:
                        new0 = True
                    elif top != bot:
                        new1 = True
                    else:
                        new0 = True

                if dp1:
                    if top and bot:
                        new0 = True
                    elif top != bot:
                        new0 = True
                    else:
                        new1 = True

                dp0, dp1 = new0, new1

                if not dp0 and not dp1:
                    ok = False
                    break

            if not ok:
                break

            i = j

        print("YES" if ok else "NO")

if __name__ == "__main__":
    solve()
```この実装では、完全にブロックされた列はどのタイルにも参加できないため、まずグリッドを完全にブロックされた列で区切られたセグメントに分割します。 各セグメント内では、水平方向の継続が保留されているかどうかを追跡する最小限の DP 状態が維持されます。 

各列で、トランジションでは、上部と下部のセルが両方必要か、1 つだけ必要か、またはまったく必要ないかが考慮されます。 不一致は純粋に垂直方向に解決できないため、水平方向のキャリー状態が強制されます。 DP は、そのようなキャリーがすぐに消費されるか伝播されることを保証しますが、セグメントの終わりに未解決のまま残されることはありません。 

実装の重要な詳細は、セグメント境界を正しく処理することです。 タイルはそれらの列を横切ることができないため、フルゼロの各列で状態をリセットする必要があります。 もう 1 つの微妙な点は、両方の DP 状態が同時に更新されるようにすることです。 古い状態と新しい状態を分離しないと、部分的に更新された遷移が無効に再利用される可能性があります。

 ## 特殊なケース

 主なエッジ ケースは、次のような完全にブロックされた孤立した列がグリッドに含まれる場合です。```
n = 7
top:    1110111
bottom: 1110111
```(0,0) の列は、問題を 2 つの独立した部分問題に分割します。 アルゴリズムはこの時点で状態を明示的にリセットし、水平タイルが誤ってバリアを横切らないようにします。 この列にまたがるタイルは直ちに禁止制約に違反するため、DP の再起動により正確さが保証されます。 

もう 1 つのケースは、長い交互パターンです。```
top:    101010
bottom: 010101
```ここでは、すべての列で不一致が強制されます。 DP 遷移は保留状態と解決済み状態の間で交互に行われ、アルゴリズムはこれらの依存関係が許容タイル長内でペアにできるかどうかを検出します。 各不一致は即時解決する必要があるため、ペアリングが失敗すると DP はすぐに不可能な状態に達し、必要に応じて正しく拒否されます。
