 ## 問題の理解

 いくつかの独立したテスト ケースが与えられています。 各テスト ケースには、整数のリストがあります。 このリストから要素を 1 つだけ削除することができます。 その後、残りの数値を見て値を選択しようとします$d$リストにまだ表示されており、削除された値よりも厳密に小さい値$c$。 私たちの目標は、削除とその結果の値を選択することです$d$となることによって$d$できるだけ大きいです。 

簡単に言うと、1 つの要素を「しきい値」として選択します。$c$、その出現を 1 つ削除し、残りの配列内でまだ より小さい最大の数値を探します。$c$。 私たちはそれを可能な限り最大限に高めたいと考えています$d$あらゆる選択肢の上で$c$。 

制約は小さく、各配列の要素数は最大 100 で、値も最大 100 です。これはすぐに 3 次または 2 次の解法でも受け入れられることを示唆していますが、それでもすべての削除を明示的にシミュレートするのではなく、ロジックを透過的にする構造を目指す必要があります。 

微妙な点は、要素の削除はその正確な値の可用性にのみ影響することです。 選ぶとしたら$d \neq c$、その後削除します$c$すべての出現を削除することはありません$d$。 これは、「削除して再計算する」というアイデアのほとんどが不必要なオーバーヘッドであることを意味します。 

考慮に値するエッジ ケースは、最大値が複数回出現する配列、または重複が多数存在する配列に由来します。 

すべての値が等しい場合、たとえば`3 3`、有効なペアがありません$d < c$なぜなら、何を削除しても、厳密にはこれより小さい値はないからです。 この問題により、少なくとも 2 つの異なる値が存在することが保証されるため、この状況が縮退的に発生しないことが保証されます。 

配列が`1 2 2`、1つを削除します`2`まだ残っています`1 2`、そして最高$d$まだです`1`。 単純なシミュレーションでは、最大値のみを削除すると答えが変わると誤って考える可能性がありますが、実際はそうではありません。 

## アプローチ

 ブルートフォースのアイデアは単純です。 あらゆるインデックスに対して$i$、 扱う$a[i]$削除された値として$c$。 削除した後、残りの配列をスキャンしてすべての値を確認します$a[j]$それはより小さいです$c$、それらの中で最大のものを取ります。 これには必要です$O(n)$削除ごとに作業が行われます。$O(n)$選択肢がある場合、全体の複雑さは次のようになります。$O(n^2)$テストケースごとに。 と$n \le 100$、これはすでに安全です。 

ただし、このアプローチでは同じ構造が繰り返し再計算されます。 重要な観察は、削除操作はほとんど無関係であるということです。値の 1 つの出現を削除しても、配列内に別の値が存在するかどうかは変わりません。 したがって、重要な唯一の質問は、厳密にこれより大きい値が存在するかどうかです。$d$。 そのような値が存在する場合、いつでもそれを次のように選択できます。$c$1 つの出現を削除しても影響はありません$d$。 

したがって、問題は最大値を見つけることになります$d$配列内に厳密に大きい値が少なくとも 1 つ存在するようにします。 これは、まさに一連の数値の中で 2 番目に大きい個別の値です。 

したがって、多重度を完全に無視して、一意の値だけを扱うことができます。

 ## アルゴリズムのチュートリアル

 1. 配列を読み取り、すべての個別の値を抽出します。 

重複によって値間の順序は変更されず、頻度のみが変更されるため、これにより重複が削除されます。 
2. 個別の値を降順に並べ替えます。 

並べ替えると、最大から最小までの明確なランキングが得られ、条件を直接エンコードします。$d < c$。 
3. このソートされた個別リストの 2 番目の要素を取得します。 

この値は、厳密にそれより大きい値が少なくとも 1 つある最大の数値です。 
4. テスト ケースに対してこの値を出力します。 

ステップ 3 の背後にある推論が、ソリューションの中核です。 任意の候補者$d$いくつか持っているはずです$c > d$。 それはすぐに意味します$d$最大個別値にすることはできません。 残りのすべての候補のうち、可能な限り最良の選択は、最大値をまだ下回る最大値、つまり 2 番目に大きい個別の値です。 

### なぜ効果があるのか

 しましょう$M$配列内の最大値になります。 任意の有効な$d$満たさなければなりません$d < M$、なぜなら、$d = M$として機能する厳密に大きな値はありません。$c$。 あらゆる値に対して$d < M$、いつでも選択できます$c = M$(または、$M$）を削除してください。 1 つの要素を削除しても、すべての要素が削除されるわけではないため、$d$、$d$配列に残ります。 したがって、最大値を除くすべての値が実現可能であり、その中で最大のもの、つまり 2 番目に大きい個別の値を選択することによって最大化します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        vals = sorted(set(a), reverse=True)
        print(vals[1])

if __name__ == "__main__":
    solve()
```このソリューションは、各テスト ケースを個別に読み取り、配列をセットに変換して重複を削除し、降順で並べ替えて、2 番目の要素を出力します。 唯一の微妙な要件は、配列に少なくとも 2 つの異なる値が含まれていることを確認することであり、これは問題文で保証されています。

    sys.stdin = io.StringIO(inp)

 ## 特殊なケース

 最大値が何度も出現する場合、出現する値を 1 つ削除しても、その値は配列内に残ります。 これは、最大値を次のように選択することが常に有効であることを意味します。$c$、より小さいすべての個別の値が候補として到達可能であることを保証します。$d$。 並べ替え前に重複が削除されるため、アルゴリズムはこれを自然に処理し、頻度が順序に影響を与えることはありません。 

連続する整数など、値が密にパックされている場合でも、2 番目に大きい個別の値は明確に定義されています。 たとえば、`[1, 2]`、答えは`1`いずれかの要素を削除しても、有効な値として機能できるのは 1 つの値だけであるという事実は変わりません。$d$。 

中間値の重複が複数ある場合。`[1, 2, 2, 3]`、余分な物の存在`2`s は個別の値の順序を変更せず、アルゴリズムは引き続き正しく返します。`2`。
