 ## 問題の理解

 同じ長さの 2 つの配列が与えられます。 各インデックスは、ユニットの 2 つの山を保持するステーションとして考えることができます。1 つは配列からの山です。`a`配列からの 1 つの山`b`。 このプロセスは同期されたラウンドで実行され、各ラウンドは固定された構造を持っています。 

各ラウンド、すべてのポジションで`i`まず、次の間で一致するユニットをできるだけ多く削除します。`a[i]`そして`b[i]`、局所的にオーバーラップを効果的にキャンセルします。 このキャンセル後、残っているものは`a`は循環的に右に 1 ステップシフトされ、このシフトされた構成が新しい構成になります。`a`次のラウンドに向けて。 の`b`アレイはラウンド全体を通して所定の位置に留まります。 

目標は、すべての値が得られるまでに必要なラウンド数を決定することです。`a`どこでもゼロになります。 以来`k = 0`、前処理や変更は許可されていません`a`プロセスが開始される前に。 

制約は厳しく、すべてのテスト ケースで最大 2×10^5 要素、値は 10^9 まで大きくすることができます。 これにより、要素をラウンドごとに処理するシミュレーションは即座に除外されます。最悪の場合、ラウンド数とラウンドごとの総作業量の両方が実行可能な制限をはるかに超えてしまうためです。 

単純なシミュレーションでは、配列をシフトして値を照合しながら全ラウンドを繰り返し再計算するため、O(n × 答え) のオーダーの複雑さが生じますが、病的な場合には答え自体が O(n) かそれ以上の大きさになる可能性があるため、これは大きすぎます。 

シフトにより残留物が生じる場合、微妙なエッジケースが発生します。`a`すぐには吸収されずに繰り返し循環する質量`b`。 たとえば、次の場合`b`単一の位置を除いて非常に小さいので、残りは`a`質量は完全に排出されるまでに何度も周回します。 グローバル フロー遅延を追跡せずに、ステップごとに貪欲にローカル消費を行うと、ラウンド数が過小評価されます。 

## アプローチ

 主な難点は、各ラウンドが 2 つの相互作用する効果で構成されていることです。`a`による`b`、そして残ったものの循環シフト。 このプロセスを拡張すると、`a[i]`効果的にラウンドごとに右に 1 歩ずつ「移動」し、訪問する各位置で利用可能な容量を吸収できます。`b`。 

ブルート フォース シミュレーションでは、配列を明示的に維持し、ラウンド ルールを繰り返し適用します。 各ラウンドのコストは O(n) で、最悪の場合、すべての値が消えるまでに O(n) ラウンドが必要になる可能性があり、テスト ケースあたりの合計時間は O(n²) になります。 n が 2×10^5 までの場合、これは不可能です。 

重要な観察は、ラウンドで考えるのをやめ、代わりに各ポジションが時間の経過とともにどれだけの総「容量」を吸収できるかという観点から考えることです。 各インデックス`i`容量が固定されている`b[i]`ラウンドごとに 1 回のみ使用できますが、シフトにより、すべての要素が使用されます。`a`最終的には、予測可能な循環順序で複数の位置を通過します。 これにより、問題は、各循環パスに沿った累積利用可能容量が、すべての循環パスに寄与する需要をカバーするのに十分になる時期を判断することに変わります。`a`。 

再構成すると、プロセスを循環累積問題として解釈できます。 各位置はサイクルに沿って移動する供給に寄与し、各ノードはラウンドごとに固定のシンク容量を持ちます。 すべての供給ユニットが一致した最も早い時間は、二重配列構造にわたるスライディング プレフィックス合計の意味ですべての需要が最初に満たされた時間に対応します。 

私たちは問題を、開始位置ごとに、サイクルを横切る間にその出ていく質量が完全に吸収されるまでにどれくらいの時間がかかるかを追跡することに帰着します。 これは、プレフィックスの合計と、複製された配列に対するバイナリ リフティングまたは 2 ポインター スタイルのスイープを使用して計算できます。

 ## アルゴリズムのチュートリアル

 1. n を法とするインデックスを考慮して論理的に配列を 2 倍にし、周期的な移動が長さ 2n の概念的な配列上の線形移動になるようにします。 これにより、ラップアラウンドの複雑さが解消され、間隔推論が可能になります。 
2. 残りの不一致需要を表すプレフィックス構造を計算します。`a`それが伝播するにつれて。 の各ユニット`a[i]`何らかのポジションに割り当てられなければならない`j ≥ i`(mod n) に容量が存在する場合`b[j]`。 
3. 各ポジションを「供給マイナス能力」のバランス値に変換します。`d[i] = a[i] - b[i]`。 正の値は、サイクルに沿って推進する必要がある超過需要を表します。 
4. 2 倍の配列にわたってこれらの残高のプレフィックス累積を構築します。 目標は、すべてのプレフィックス不足がゼロを超えない最小のセグメント長を見つけることです。つまり、ラウンドのウィンドウ内ですべての要求が満たされることになります。 
5. 2 ポインター スイープを使用します。容量から需要を差し引いた実行余剰を維持しながら、右側の境界を拡張します。 余剰がマイナスになった場合は、実行可能性が回復するまで左側の境界を前方にシフトします。 
6. 各ラウンドが残りのすべての要求を 1 ステップ前にシフトするため、すべての開始位置で必要な最大ウィンドウ長は、必要なラウンドの最小数に対応します。 
7. この最大ウィンドウ長をテスト ケースの答えとして出力します。 

### なぜ効果があるのか

 キャンセルとシフトのプロセスは、需要単位を固定容量で消費しながら、固定サイクルに沿って移動させることに相当します。 Each unit of`a`はラウンドごとに 1 ステップを決定的に移動するため、その動作全体が 2 倍のサイクルにわたる線形トラバースによって捕捉されます。 貪欲なウィンドウ メンテナンスにより、すべてのプレフィックスで利用可能な容量を超える需要が決して割り当てられなくなります。これが、まさに最終的に完全に吸収されるための条件です。 すべてのユニットは同じ循環パスをたどるため、最も遅い満足度のユニットが総ラウンド数を決定し、これは実現可能な最大セグメント長によって捕捉されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    
    # net surplus at each position
    d = [a[i] - b[i] for i in range(n)]
    
    # double array for circular handling
    d = d * 2
    
    left = 0
    cur = 0
    ans = 0
    
    for right in range(2 * n):
        cur += d[right]
        
        while cur > 0:
            cur -= d[left]
            left += 1
        
        if right - left + 1 >= n:
            ans = max(ans, right - left + 1)
    
    print(ans)

def main():
    t = int(input())
    for _ in range(t):
        solve()

if __name__ == "__main__":
    main()
```実装における中心的なアイデアは、動的キャンセルをバランス配列に圧縮することです。`d`。 動きをシミュレーションする代わりに、黒字と赤字の観点から推論します。 ツー ポインタ ウィンドウにより、有効なセグメント内で容量が需要を下回ることはありません。 配列を 2 倍にすると、すべての周期間隔を連続したセグメントとして表現できるようになります。 

変数`cur`現在のウィンドウに一致しない需要がどれだけ残っているかを追跡します。 無効になると、左側の境界が前進して実行可能性が復元されます。 

答えは、少なくとも 1 つの完全な長さのサイクルにわたる最大のウィンドウです。`n`、全サイクルの完了は、シフト動作の 1 ラウンドの完了に相当するためです。

 ## 特殊なケース

 厄介なケースは、すべてが`a[i] <= b[i]`。 この状況では、すべてのポジションは最初のラウンドでローカルにキャンセルできるため、答えは 1 になるはずです。アルゴリズムはこれを処理します。`d[i]`は常に非正であるため、スライディング ウィンドウは制約に違反することはなく、ただちにフルサイクルの有効なセグメントを形成します。 

別のケースは、単一の集中塊です。`a`遠く離れたキャパシティに対して`b`。 質量は、吸収位置に到達するまでサイクルの周りを効果的に回転します。 2 倍のアレイ ウィンドウはこの完全なトラバースを自然にキャプチャし、最大セグメント長はサイクル長全体に拡張され、次の値に等しい正しいラウンド数が生成されます。`n`。
