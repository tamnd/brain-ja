 ## 解決策
 ## 問題の理解

 私たちに与えられたゲームは、`n`メンバーが順番に開けようとする`l`のセットを使用してロックする`l + k`キー。 これらのキーのうち、正確には、`l`本物であり、それぞれが 1 つのロックを正確に開きますが、残りは`k`鍵は偽物です。 各メンバーは自分の番の間に 1 つの鍵を選択し、1 つの錠前で試します。全員が合理的です。つまり、以前の試行履歴を考慮して、錠を開ける確率が最大になる鍵と錠前を選択します。 ロックが開かれると、そのロックとそのキーは今後の考慮対象から除外されます。 

タスクは、各メンバーについて、この最適な戦略の下で成功した一致 (メンバーが開いたロック) の予想数を計算することです。 期待される数値は合理的ですが、剰余を報告する必要があります。$10^9 + 7$として$p \cdot q^{-1} \mod 10^9+7$、 どこ$\frac{p}{q}$期待値を表す分数です。 

この制約により、最大 100 個のテスト ケースが許可されます。`n`100まで、`l`最大5000、そして`k`最大25。すべての合計`l`すべてのテスト ケースが 5000 を超えることはありません。`l`5000 を超える任意のアルゴリズムを使用できます。$O(l^2)$テスト ケースごとのステップが遅すぎる可能性があります。 の小さな値`k`は、動的計画法または組み合わせ確率アプローチを示唆する、軽微な調整として扱うことができることを示します。 エッジケースには以下が含まれます`k = 0`(キーはすべて本物です)、`n = 1`(メンバーは 1 名のみ)、および`k \ge l`（偽のキーがたくさんあります）。 

考えられるキーロック履歴の数は階乗であるため、すべてのターンの単純なシミュレーションは失敗します。`l`そして組み合わせ`k`、これは大きすぎます。 

## アプローチ

 ブルートフォース手法では、すべてのターンをシミュレートし、すべてのロックのすべてのキーを試し、成功と失敗の可能性のあるすべての履歴を追跡します。 各ステップで、各キーで各ロックが開く確率を計算し、すべての可能性を前方に伝播します。 これは正しいですが、次のような理由から実行不可能です。$(l+k)!$一連のキー選択が必要であり、各ロックは複数回試行される可能性があるため、指数関数的に複雑になります。`l`。 

効率的なソリューションを導き出す洞察は、期待の対称性と直線性から生まれます。 毎ターン、メンバーがロックを開けるチャンスは、単に残りの本物のキーの数を残りのキーの数で割ったものです。 すべてのシーケンスをシミュレートする必要はありません。 純正キーの残数を追跡することで（`l_remaining`) と残りの合計キー (`total_remaining = l_remaining + k`)、ローテーションシーケンスモジュロを使用して、各ターンでの各メンバーの期待される成功を分数として計算できます。`n`。 

これにより、問題は動的プログラミングに帰着します。`l`ロックと`n`メンバー。 具体的に定義すると、`dp[locks_left][turn]`各メンバーが開始できる成功した試合の予想数として、`locks_left`次のターンの残りのロックはメンバーに属します`turn`。 繰り返しは、残りのキーの中からランダムにキーを選択し、追加することに基づいています。`1`本物であれば成功。 これは管理可能です。`l`最大でも 5000、`n`最大でも 100、そして`k`多くても25。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O((l+k)!) | O((l+k)!) | 遅すぎる |
 | 期待を伴う動的プログラミング | O(l * n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取ります。 テスト ケースごとに、次の内容を読んでください。`n`、`l`、 そして`k`。 
2. 配列を初期化する`expected`サイズの`n`各メンバーの期待される成功をすべて 0 から保存します。 
3. しましょう`l_remaining = l`そして`total_remaining = l + k`。 
4. ながら`l_remaining > 0`、モジュロの順序でメンバーを反復処理します。`n`。 
5. 現在のメンバーについて、成功の確率を次のように計算します。`p = l_remaining / total_remaining`。 追加`p`に`expected[member]`。 
6. デクリメント`l_remaining`による`p`（部分的に）そして`total_remaining`by 1。これは、整数シミュレーションではなく予想に基づいてロックとキーを削除することをモデル化します。 
7. すべてのロックが割り当てられるまで繰り返します。 終了後、期待される値はすべて分数になり、それぞれをモジュロに変換します。$10^9 + 7$モジュラーインバースを使用します。 
8. を印刷します。`expected`テストケースの配列。 

機能する理由: 私たちは期待値の線形性に依存しているため、各ロックを独立して扱うことができます。 期待値は直線的に加算されるため、その時点での成功確率を常に計算している限り、誰がどのキーを選択するかの正確な順序は関係ありません。 これは非常に重要です。これにより、シーケンスの組み合わせ爆発のシミュレーションが回避されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def modinv(x):
    return pow(x, MOD - 2, MOD)

t = int(input())
for _ in range(t):
    n, l, k = map(int, input().split())
    expected = [0] * n
    l_remaining = l
    total_remaining = l + k
    member = 0
    while l_remaining > 0:
        p_num = l_remaining
        p_den = total_remaining
        expected[member] = (expected[member] + p_num * modinv(p_den)) % MOD
        l_remaining -= 1
        total_remaining -= 1
        member = (member + 1) % n
    print(" ".join(map(str, expected)))
```このコードは逆モジュラーを使用して分数の剰余を計算します。$10^9 + 7$。 の`while`ループは正確に反復します`l`ロックごとに 1 回、期待される成功をメンバー間で分散します。 期待値の線形性を使用すると、組み合わせ列挙が回避されます。 オフバイワンエラーはデクリメントすることで回避されます。`l_remaining`そして`total_remaining`確率計算でそれらを使用した後。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    MOD = 10**9 + 7
    def modinv(x):
        return pow(x, MOD - 2, MOD)
    t = int(input())
    res = []
    for _ in range(t):
        n, l, k = map(int, input().split())
        expected = [0]*n
        l_rem = l
        total = l + k
        member = 0
        while l_rem > 0:
            p_num = l_rem
            p_den = total
            expected[member] = (expected[member] + p_num * modinv(p_den)) % MOD
            l_rem -= 1
            total -= 1
            member = (member + 1) % n
        res.append(" ".join(map(str, expected)))
    return "\n".join(res)
