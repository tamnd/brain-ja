 ## 解決策
 ## 問題の理解

 この問題では、次のグループが参加する連続ゲームをシミュレートするように求められます。`n`参加者はロックを解除しようとします`l`正確に使用してロックする`l`有効なキー。 各参加者は、固定された循環順序で一度に 1 つのターンを実行します。 各ターンで、参加者は鍵を開ける確率を最大にする鍵と錠前を選択します。 ロックが開けられたり、キーが正常に使用されたりすると、どちらも再度使用することはできません。 各参加者の予想成功一致数をモジュロで計算するように求められます。$10^9 + 7$。 

入力により複数のテスト ケースが提供されます。 各テスト ケースについて、参加者の数、ロックの数、偽のキーの数がわかります。 この簡単なバージョンでは、偽のキーの数がゼロであるため、すべてのキーで 1 つのロックを開けることができます。 

制約は中程度です: テスト ケースは最大 100 個で、すべてのテスト ケースにわたるロックの総数は 5000 に制限されます。これは、アルゴリズムの時間計算量がおおよそ 100 であることを意味します。$O(n \cdot l)$すべてのテスト ケースの合計が下に残るため、テスト ケースごとに実行することは可能です。$5 \cdot 10^5$操作。 エッジケースには、非常に小規模なゲーム (例: 1 ロック、1 参加者) や高度に非対称なディストリビューションが含まれます。$n > l$または$n < l$、誰がターンを取得するか、期待値がどのように分割されるかに影響を与える可能性があります。 

各ターンで考えられるすべてのランダムな選択をシミュレートしようとする単純なアプローチは、キーとロックの順列の数が階乗的に増加するため、組み合わせ的に爆発的に増加します。 不注意な実装では、モジュラー演算を行わずに確率を分数として追跡しようとする可能性があり、オーバーフローが発生する可能性があります。 もう 1 つの微妙な問題は、期待値が有理数であるため、逆剰余を正しく処理することです。 

## アプローチ

 ブルート フォース手法では、すべての参加者に対するキー試行の考えられるすべてのシーケンスを列挙します。 各シーケンスについて、各プレーヤーの成功数を計算し、すべてのシーケンスの平均を計算して期待値を見つけます。 このアプローチは原理的には正しいですが、次の点で要因となります。`l`そしてそれはまったく不可能です`l`5,000 件どころか 20 件程度の小さなものもあります。 

効率的なソリューションを実現するための重要な洞察は、期待の直線性です。 試行の順序に関係なく、参加者が開くロックの予想数は、参加者が順番にそのロックを開ける確率の各ロックの合計です。 参加者は最適に行動し、各キーは 1 つのロックに正確に対応するため、プレイヤーが自分の番で特定のロックを開ける確率は、残りのロックの数を循環順序で残りの参加者で割った単純な分数で表すことができます。 これにより、すべてのランダムな結果を列挙することなく、期待値を繰り返し計算できます。 

したがって、次の期待値を計算できます。`O(n * l)`各ロックを反復処理し、成功確率を参加者に順番に分配します。 モジュラー演算を使用して、分数を除算するときにモジュラー逆数を乗算して、精度の問題を回避します。

 ## アルゴリズムのチュートリアル

 1. 配列を初期化する`ans`長さの`n`ゼロ付き。 これにより、各参加者の予想される成功した一致数が保持されます。 
2. 1 から 1 までのすべてのロックを繰り返します。`l`。 で`i`- 番目のロック、参加者インデックスを次のように計算します。`(i-1) % n`。 これにより、ターンの周期的な順序が決まります。 
3.追加`1/l`選択した参加者の期待値に。 ここ`1/l`すべてのロックがいずれかのターンまでに解決される可能性が等しい場合に、ロックごとに期待される成功の割合を表します。 除算にはモジュラー算術を使用します。`l`の逆モジュールを乗算することにより、`l`モジュロ$10^9 + 7$。 
4. すべてのロックを処理した後、`ans`テストケースの配列。 
5. すべてのテスト ケースに対して繰り返します。 

これが機能する理由: 期待値の線形性により、各ロックを独立して考慮できます。 各参加者の貢献度は、順番があるすべてのロックで期待される成功の合計です。 循環ターン割り当てにより公平性が確保され、モジュラー逆関数を使用することで正確な合理的期待値がモジュロで維持されます。$10^9 + 7$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def modinv(x):
    return pow(x, MOD-2, MOD)

def solve():
    t = int(input())
    for _ in range(t):
        n, l, k = map(int, input().split())
        inv_l = modinv(l)
        ans = [0] * n
        for i in range(l):
            ans[i % n] = (ans[i % n] + inv_l) % MOD
        print(" ".join(map(str, ans)))

if __name__ == "__main__":
    solve()
```各セクションはアルゴリズムのステップに直接対応します。 のモジュラー逆関数を事前に計算します。`l`モジュロでの除算を処理します。 それから繰り返します`l`回、順番が回ってきた参加者の期待値を増加させます。 使用する`(i % n)`参加者を自動的に循環します。 モジュラー演算により、最終的な答えが正しい範囲内にあることが保証されます。

 ## 特殊なケース

 のために`n=1`そして`l=1`、唯一の参加者がロックを取得するため、期待される数値は 1 になります。アルゴリズムは次のように計算します。`1 * inv(1) = 1`。 

のために`n=3`そして`l=2`、最初の参加者が受け取ります`1/2`最初のロックの場合は、2 番目の参加者が受け取ります。`1/2`2番目のロックについて。 モジュラー算術変換`1/2`の中へ`500000004`。 アルゴリズムは参加者を正しく循環し、分数を割り当てます。 

すべてのケース`l < n`または`l > n`を使用して自動的に処理されます`(i % n)`インデックス作成。
