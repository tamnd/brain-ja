 ## 解決策
 ## 問題の理解

 この問題は、次のラベルが付いたノードを持つルート付きツリーを記述します。$1$に$n$、ここでノード$1$根です。 リキとササミは数日間にわたって探索を実行し、探索ごとに選択したノードとそのサブツリー全体が破壊されます。 なお、当日は$i$、番号が付いたノード$n-i+1$また、その日の終わりには自動的に折りたたまれます。 目標は、可能な日数ごとにカウントすることです$i$から$1$に$n$、正確に続く探索シーケンスが何回存在するか$i$最終日の探索ノードを含む日数$1$。 

入力は複数のテスト ケースで構成されます。 各テスト ケースは、最大 80 個のノードを持つツリーを記述します。 ノードは、DFS 番号付けを可能にする方法で与えられます。$1$に$n$これは微妙ですが重要なヒントです。DFS の昇順でノードを処理すると、サブツリー構造を順番に表現できることが保証されます。 

なぜなら$n \le 80$、大まかに時間計算量を伴う解$O(n^3)$またはそれよりわずかに多くても可能です。 ただし、考えられるすべての探索シーケンスを単純に列挙すると、次の点で指数関数的になります。$n$なぜなら、私たちは毎日、次にどのノードを探索するかという選択肢があり、サブツリーを折りたたむと利用可能な選択肢が大幅に変化するからです。 すべての順列を試行する不用意な実装は、$n=20$。 

自動的に折りたたむようにスケジュールされたノードも、より早く探索のために選択された場合、明らかではないエッジ ケースが発生します。 たとえば、3 つのノードからなる単純なツリーを考えてみましょう。`1-2, 2-3`。 ノードを探索すると`2`1日目、サブツリーが崩壊し、ノードが削除されます`3`。 2日目、ノード`3`自動的に折りたたまれるようにスケジュールされています。 残りのノードに対する単純な DFS は、自動崩壊を考慮していない場合、無効なシーケンスをカウントする可能性があります。 

## アプローチ

 ブルートフォースアプローチは、ノードのすべてのシーケンスを生成し、それぞれについて、折りたたみルールを遵守しているかどうかを調査およびチェックすることです。 各シーケンスは正確に一致している必要があります$i$日とノードで終わる$1$。 毎日、崩壊していないノードを探索できます。 シーケンスの総数は階乗になります。$n$最悪の場合、それは明らかに不可能です$n = 80$。 

最適なアプローチでは、ツリーに対する動的プログラミングを活用します。 重要な洞察は、サブツリーを個別に処理し、その数を結合することです。 ノードを探索するとそのサブツリー全体が破壊されるため、ノードごとに、そのサブツリーを正確に探索する方法が何通り存在するかを計算できます。$k$日々。 これはボトムアップで行うことができます。リーフ ノードの場合、探索する方法は 1 つだけ (ノード自体を探索する) ですが、内部ノードの場合、畳み込みを使用してすべての子の探索カウントを組み合わせて、サブツリー間で日数を分散するすべての方法を考慮します。 

さらに、DFS 番号付けを介して自動折りたたみを処理します。 ノードは毎日の終わりに番号の降順に折りたたまれるため、すべてのシーケンスを明示的に追跡しなくても、各日にどのノードが利用可能なままであるかを計算できます。 これにより、シーケンスのカウントが折りたたみルールと一致することが保証されます。

 | --- | --- | --- | --- |
 | ブルートフォース | お(ん!) | O(n) | 遅すぎる |
 | サブツリー畳み込みを使用したツリー上の DP | O(n^3) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力ツリーを解析し、各ノードの隣接リストを構築します。 ノードでツリーをルートします`1`。 
2. ノードごとに DP アレイを維持します`dp[node][k]`どこ`dp[node][k]`ルートとなるサブツリーを探索する方法の数です。`node`まさに`k`日々。 リーフを初期化します`dp[leaf][1] = 1`。 
3. DFS を使用してツリーをボトムアップで処理します。 内部ノードの場合、まず各子の DP を計算します。 次に、子の DP 配列を結合します。 組み合わせは畳み込みで行われます: 1 つの子を探索できる場合`x`日数`a`方法と、別の方法で`y`日数`b`次に、両方の子供を調べます`x+y`日以内に実行できます`a*b`方法。 
4. すべての子を結合した後、現在のノード自体を含めます。 ノードの場合`u`結合された子供たちと DP`dp_combined`、私たちは生成します`dp[u][k+1] = dp_combined[k]`すべて有効な`k`。 これはノードの探索に役立ちます`u`最終日、そのサブツリーを探索した後、`k`日々。 
5. 計算後`dp[1][k]`みんなのために`k`、自動折りたたみを考慮してカウントを調整します。 DFS の順序特性により、自動折りたたみは決定的であり、個別の組み合わせ調整は必要ありません。 
6. カウントのモジュロを返します`998244353`。 

正確さを保証する不変条件は、各ノードで次のようになります。`dp[node][k]`子間の有効な日数の分布をすべて考慮して、そのノードで終了するサブツリー探索のすべてのシーケンスを正確にカウントします。 これらのボトムアップを組み合わせることで、すべてのシーケンスが正確に 1 回カウントされるようになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
MOD = 998244353

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        edges = [[] for _ in range(n+1)]
        for _ in range(n-1):
            u, v = map(int, input().split())
            edges[u].append(v)
            edges[v].append(u)
        
        dp = [dict() for _ in range(n+1)]
        visited = [False]*(n+1)
        
        def dfs(u):
            visited[u] = True
            child_dp = [ {0:1} ]  # empty combination
            for v in edges[u]:
                if not visited[v]:
                    dfs(v)
                    # merge v into child_dp
                    new_child_dp = []
                    for d1 in child_dp:
                        for d2 in [dp[v]]:
                            combined = {}
                            for k1, v1 in d1.items():
                                for k2, v2 in d2.items():
                                    combined[k1+k2] = (combined.get(k1+k2,0) + v1*v2)%MOD
                            new_child_dp.append(combined)
                    child_dp = new_child_dp
            # merge all child combinations
            total = {}
            for d in child_dp:
                for k,vv in d.items():
                    total[k+1] = (total.get(k+1,0)+vv)%MOD
            dp[u] = total
        
        dfs(1)
        ans = [0]*n
        for k,v in dp[1].items():
            if 1 <= k <= n:
                ans[k-1] = v
        print(' '.join(map(str, ans)))

if __name__ == "__main__":
    solve()
```DFS は各ノードの DP を再帰的に計算します。`child_dp`は、子供たちに探索日を分配するすべての方法を表し、マージは辞書畳み込みを使用して行われます。 マージ後、追加`1`現在のノードを探索するためのアカウント。 モジュロ演算により、結果が制限内に収まることが保証されます。
