 ## 解決策
 ## 問題の理解

 1 から 1 までの整数の順列を構築するように求められます。$n$特別な性質を持つ。 順列の各プレフィックスについて、最初のプレフィックスの平均を計算します。$i$要素を取得し、その天井を取得し、それを呼び出します$c_i$。 これらの少なくともおよそ 3 分の 1 が含まれる場合、置換は有効です。$c_i$値は素数です。 この問題により、そのような順列が常に存在することが保証されます。 

入力は単純です: テスト ケースの数$t$、 に続く$t$整数$n$、それぞれは構築する順列のサイズを表します。 出力はそれぞれ、$n$、の 1 つの順列$1$を通して$n$プライムプレフィックスの上限条件を満たします。 制約により許可されるのは、$n$まで$10^5$そして$t$最大 10、つまり最大 10 まで見ることができます$10^6$合計要素。 線形よりも悪いソリューションは、$n$テストケースごとにタイムアウトになる可能性が高いため、$O(n)$または$O(n \log n)$アルゴリズムは許容されますが、$O(n^2)$遅すぎます。 

単純な落とし穴は、プロパティのすべての順列をチェックしようとすることです。 のために$n=5$、 がある$5! = 120$順列; のために$n=10^5$、すべての順列を繰り返すことは不可能です。 もう一つの微妙なケースは小さいです$n$、 例えば$n=2$。 ここで、接頭辞の天井は単なる要素そのものです。 より大きなものを想定した不用意なアプローチ$n$これらの最小サイズの入力では動作が失敗する可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、次のすべての順列が生成されます。$1$に$n$、それぞれの接頭辞の上限を計算し、素数がいくつあるかを確認し、必要な素数の数を満たす最初の順列を返します。 これは正確性を保証するので原理的には機能しますが、順列の階乗増加によりそれが不可能になります。$n>10$。 

重要な観察は、プレフィックスの合計のシーケンスが着実に増加し、連続する整数の平均の上限が最初のいくつかの要素の順序によって操作できることです。 最初に 2、次に 1、そして残りを昇順に配置すると、最初の数個が$c_i$値は小さな素数で、多くの場合 2 または 3 です。たとえば、次のようになります。`[2,1,3,4,5...]`最初のプレフィックスの上限が 2、2、2、3、3 であることを保証します。これにより、すでに複数の素数が得られます。$c_i$価値観。 これが機能するのは、最初のいくつかの整数の合計が平均を支配しており、小さな整数は早い段階で小さな素数の上限を生成するためです。 最初のプレフィックスで十分な素数が保証されると、残りの数値は自然昇順になります。 

したがって、最適なアプローチは建設的かつ線形です。素数の要件を満たすように最初のいくつかの数値を慎重に配置し、残りを追加します。 小さい場合には 2 と 3 を超える素数をテストする必要はありません$n$プレフィックスを追加することで、アルゴリズムをシンプルに保ちます。

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、次の内容を読んでください。$n$、順列のサイズ。 
2. もし$n$2、出力`[2,1]`。 これにより、両方のプレフィックスの上限が 2 と 2 の素数であることが保証されます。 
3. もし$n$3、出力`[2,1,3]`。 プレフィックスの上限は 2,2,2 であり、主要な要件を満たしています。 
4. のために$n\ge4$、順列を開始します`[2,1,3]`。 これにより、最初の 3 つの接頭辞の上限が素数になることが保証されます。 
5. 4 から までの残りの整数を追加します。$n$昇順で。 これにより、順列をすべての数値で満たしながら、先頭の小さな素数が保存されます。 
6. 構築された順列を出力します。 

不変条件は、最初のいくつかの要素が少なくとも$\lfloor n/3 \rfloor - 1$プレフィックス天井間の素数。 プレフィックスの平均は徐々にしか増加しないため、残りの数は既存の素数の数を減らしません。 これにより、ソリューションが問題の制約を満たすことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        if n == 2:
            print("2 1")
        elif n == 3:
            print("2 1 3")
        else:
            perm = [2,1,3] + list(range(4, n+1))
            print(*perm)

solve()
```このコードは、テスト ケースの数を読み取り、それらを反復処理し、以下に基づいて各順列を構築します。$n$。 特殊なケース$n=2$そして$n=3$最初のプレフィックスの上限は小さな素数である必要があるため、明示的に処理されます。 大型の場合$n$、パターン`[2,1,3,...]`プレフィックス上限の少なくとも 3 分の 1 が素数であることを保証します。問題の保証を考慮すると、これで十分です。 の`print(*perm)`ステートメントは、リストをスペースで区切られた値に展開します。

 ## 特殊なケース

 のために$n=2$、順列`[2,1]`が必要です。 プレフィックスの上限は 2 と 2 です。その他の順序、`[1,2]`、天井 1 と 2 が与えられ、素数が 1 つしか生成されませんが、これでは不十分です。 のために$n=3$、`[2,1,3]`天井 2,2,2 が生成されます。 素朴に使用した場合`[1,2,3]`の場合、天井は 1,2,2 となり、1 はプライムではありません。 のために$n>3$の後に数字を昇順に追加します。`[2,1,3]`順列を完了する間、最初の 3 つの素数の上限をそのまま維持するため、アルゴリズムは小さいものと大きいものの両方を処理します。$n$均一に。
