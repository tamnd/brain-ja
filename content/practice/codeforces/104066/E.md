 ## 解決策
 ## 問題の理解

 物語を形成する一連の単語が与えられます。単語は 1 つのスペースで区切られ、各単語は小文字のラテン文字のみで構成されます。 ストーリー全体は 1 つの長い文字列として見ることができますが、スペースはそれを単語の境界に分割する特殊文字です。 

タスクは、この結合された文字列内の位置に関するクエリに答えることです。 各クエリは、ストーリー全体の文字列 (文字を含むが、通常、問題ステートメントで説明されているクエリ モデルでのインデックス作成の目的でスペースは無視されます) 内のグローバル文字インデックスを提供します。また、どの単語にその文字が含まれるか、およびその単語内のその文字の位置という 2 つのことを決定する必要があります。 

したがって、核となる変換は、連結表現内の線形インデックスから、単語インデックスとその単語内の位置という座標のペアへの変換です。 

制約は、最大 10^5 ワードと最大 5・10^5 クエリを示し、合計文字長は最大 10^6 になります。 これは、単語または文字に対するクエリごとの線形スキャンが遅すぎることを直ちに意味します。 ソリューションでは、構造を 1 回前処理し、定数時間または対数時間で各クエリに応答する必要があります。 クエリごとのリニア スキャンは最悪の場合 5 · 10^11 演算に達しますが、これは 1 秒の制限の下では実行できません。 

単純ですがよくある間違いは、スペースを通常の文字として扱い、インデックス作成がスペースを飛び越えることを忘れることです。 もう 1 つの微妙な問題は、接頭辞の合計をセグメントにマッピングするとき、特にクエリが単語間の境界に正確にヒットするときの、off-by-one インデックス作成です。 

エッジケースは、単語の長さが 1 の場合、またはすべての単語が非常に短い場合に発生し、境界が頻繁に発生します。 たとえば、次のような物語があるとします。`"a b c"`、グローバル インデックスは緊密にマッピングされ、境界条件が重要になります。 単語の最後の文字を正確に指すクエリは、次の単語にまで波及してはなりません。 

## アプローチ

 ブルートフォースのアイデアは簡単です。ストーリー全体を文字列に連結し、クエリごとに k 番目の文字に到達するまで前方にスキャンします。 これは正しいのですが、位置を特定するには先頭からトラバースするか、正しいセグメントが見つかるまで単語を繰り返す必要があるため、最悪の場合、クエリごとに O(n) の作業が必要になります。 最大 5·10^5 のクエリと最大 10^6 の合計長を使用すると、同じプレフィックス構造の繰り返しスキャンが発生し、繰り返しの作業が発生します。 

重要な観察は、単語の境界が静的であるということです。 語長のプレフィックスの合計がわかったら、すべてのクエリは、指定された位置を超える最初のプレフィックスを検索することになります。 これにより、問題は単調配列内の繰り返し範囲の位置に変換され、バイナリ検索か、クエリが順番に処理される場合はより簡単に 2 ポインター スイープで解決できます。 

合計サイズはわずか 10^6 であるため、クエリごとのプレフィックス合計とバイナリ検索で十分かつ簡単です。

 ## アルゴリズムのチュートリアル

 まず、一連の単語をプレフィックス構造に変換します。プレフィックス構造は、スペースを含まない平坦化されたストーリー文字列の各単語の開始位置と終了位置を記述します。 

配列を維持します`pref`、 どこ`pref[i]`最初の文字の合計数を格納します`i`言葉。 

次に、各クエリはこの配列に対する検索問題になります。 

1. 語長の配列を構築します。 各単語はその文字数に影響します。 
2. 次のようにプレフィックスの合計を構築します。`pref[i]`単語の合計文字数です`[1..i]`。 これにより、単調増加シーケンスが得られます。 
3. クエリ位置の場合`x`、最小のインデックスを見つけます`i`そのような`pref[i] >= x`。 これにより、その文字が含まれる単語が識別されます。 
4. 単語が見つかったら、単語内の位置を次のように計算します。`x - pref[i-1]`。 

ステップ 3 が正しいかどうかは、プレフィックスの合計によってグローバル文字列が単語に正確に対応する連続した素のセグメントに分割されるという事実に依存しています。 

直接の二分探索で十分です。`pref`厳密に増加しています。 

### なぜ効果があるのか

 各単語は、平坦化されたストーリー文字列内の連続した間隔を占め、これらの間隔は重なりません。 プレフィックス配列は、各間隔の右端をエンコードします。 クエリ インデックスを超えるか等しい最初のプレフィックスを見つけることは、そのインデックスを含む間隔を見つけることと同じです。 間隔は連続的で順序付けられているため、このマッピングは一意で決定的です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    words = input().split()

    pref = [0] * (n + 1)
    for i in range(1, n + 1):
        pref[i] = pref[i - 1] + len(words[i - 1])

    def find_word(x):
        lo, hi = 1, n
        while lo < hi:
            mid = (lo + hi) // 2
            if pref[mid] >= x:
                hi = mid
            else:
                lo = mid + 1
        return lo

    for _ in range(m):
        x = int(input())
        i = find_word(x)
        prev = pref[i - 1]
        print(i, x - prev)

if __name__ == "__main__":
    solve()
```この実装では、前処理とクエリ処理が明確に分離されています。 プレフィックス配列は O(n) で 1 回構築されます。 各クエリでは、単語境界を越えた二分検索が使用されます。 

機能`find_word`off-by-one エラーを避けるために慎重に書かれています。 条件`pref[mid] >= x`これにより、右境界がクエリ インデックスより前にない最初の単語に到達することが保証されます。 

引き算`x - pref[i - 1]`グローバル位置を、選択したワード内のローカル オフセットに変換します。

## 複雑さの分析

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = io.StringIO()

    n, m = map(int, sys.stdin.readline().split())
    words = sys.stdin.readline().split()

    pref = [0] * (n + 1)
    for i in range(1, n + 1):
        pref[i] = pref[i - 1] + len(words[i - 1])

    def find_word(x):
        lo, hi = 1, n
        while lo < hi:
            mid = (lo + hi) // 2
            if pref[mid] >= x:
                hi = mid
            else:
                lo = mid + 1
        return lo

    for _ in range(m):
        x = int(sys.stdin.readline())
        i = find_word(x)
        output.write(f"{i} {x - pref[i - 1]}\n")

    return output.getvalue()

# sample-like test
assert run("3 3\nhell spirits fear\n1\n7\n10\n") == "1 1\n2 3\n2 6\n"

# minimum size
assert run("1 3\na\n1\n1\n1\n") == "1 1\n1 1\n1 1\n"

# boundary test
assert run("2 2\naa b\n2\n3\n") == "1 2\n2 1\n"

# all equal lengths
assert run("4 4\na b c d\n1\n2\n3\n4\n") == "1 1\n2 1\n3 1\n4 1\n"

# long word
assert run("1 1\nabcde\n5\n") == "1 5\n"

 ## 特殊なケース

 重大なエッジ ケースは、クエリが単語の最後の文字に正確に到達する場合です。 みたいな話で`"abc def"`、プレフィックスの合計は次のとおりです。`[3, 6]`。 クエリ`x = 3`2 番目の単語ではなく、最初の単語にマップする必要があります。 条件`pref[mid] >= x`左側の境界ワードに向かって等価性が確実に解決され、次のワードへの偶発的なオーバーフローが防止されます。 

もう 1 つの微妙なケースは、すべての単語の長さが 1 である場合です。この場合、接頭辞の合計は厳密に次のようになります。`1, 2, 3, ...`また、バイナリ検索では、各クエリをその正確な単語に正しくマップする必要があります。 各インデックスが一意のプレフィックス値と一致するため、アルゴリズムはこれを処理します。 

最後に、単語が 1 つしかない場合、すべてのクエリは自明に単語 1 にマップされ、位置はクエリ インデックスと同じになります。 プレフィックス配列は正しく縮退するため、実装では特別な大文字と小文字を区別する必要はありません。`[0, len(word)]`。
