 ## 解決策
 ## アプローチ

 ブルートフォースのアイデアは単純です。 クエリごとに、次のすべての数値を反復処理します。$[l, r]$, 試行除算を使用して各数値を因数分解し、多重度で現れる素数の数を数えます。 これは定義に直接従っているため、正しいです。 ただし、数値を因数分解すると、$10^5$試行分割費用について$O(\sqrt{n})$。 範囲内のすべての数値とすべてのクエリにわたって、これはおおよそ次のようになります。$O(q \cdot n \sqrt{n})$が遅すぎます。 

重要な観察は、各数値に対して計算される値がクエリに依存しないことです。 「多重度を持つ素因数の数」は、最大限界までのすべての整数の固定属性です。 すべての数値に対して 1 回計算すると、各クエリは小さなドメインにわたる範囲カウントの問題になります。 これにより、インデックス付けされたプレフィックス合計がすぐに提案されます。$k$: ごとに$k$、位置が次のプレフィックス配列を維持します。$i$数値をいくつ保存するか$\le i$まさに持っています$k$素因数。 次に、各クエリは減算によって一定時間内に応答されます。 

前処理自体は改良されたふるいを使用して効率的に行われます。 単に素数をマークするのではなく、最小の素因数を伝播するか、各倍数の因数カウントを直接累積します。

 | ふるい + 接頭語の合計 |$O(N \log N + q)$|$O(N \cdot 16)$| 承認済み |

 ## アルゴリズムのチュートリアル

 最大値までのすべての整数の素因数の数 (多重度を含む) を事前計算します。$N = 10^5$、次に、考えられるそれぞれのプレフィックスの合計を構築します。$k$。 

1. 配列を計算する`cnt[x]`素因数（多重度付き）の数を格納する$x$もっている。 これは、複数のふるいのようなトラバースを使用して行われます。 私たちが全盛期に達したとき$p$、因子数を次の倍数に伝播します。$p$、適切に増加します。 これにより、クエリごとに因数分解が繰り返されることがなくなります。 
2. 2 次元のプレフィックス配列を維持する`pref[k][i]`、 どこ`pref[k][i]`から何個の数値を保存します$1$に$i$まさに持っています$k$素因数。 これを 1 回のパスオーバーで埋めます$i$を使用して`cnt[i]`をクリックして正しいバケットを更新します。 
3. クエリごとに$(l, r, k)$、答えを次のように計算します。`pref[k][r] - pref[k][l - 1]`。 これが機能するのは、プレフィックス配列が累積頻度をエンコードしているためです。 
4. 各結果をすぐに出力します。 

前処理とクエリを明確に分離できる理由は、プロパティが数値ごとに静的であり、間隔に依存しないためです。 

正確さは、前処理後の不変式に依存します。`cnt[x]`の素因数の多重度の合計に等しい$x$、 そして`pref[k][i]`インデックスの数を正確にカウントします$i$満足する`cnt[i] = k`。 これらが成立すると、各クエリは事前に計算された周波数配列に対する直接範囲の合計になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXN = 100000
MAXK = 16

# smallest prime factor
spf = list(range(MAXN + 1))
for i in range(2, int(MAXN ** 0.5) + 1):
    if spf[i] == i:
        for j in range(i * i, MAXN + 1, i):
            if spf[j] == j:
                spf[j] = i

# count prime factors with multiplicity
cnt = [0] * (MAXN + 1)

for i in range(2, MAXN + 1):
    x = i
    c = 0
    while x > 1:
        p = spf[x]
        c += 1
        x //= p
    cnt[i] = c

# prefix[k][i]
pref = [[0] * (MAXN + 1) for _ in range(MAXK + 1)]

for i in range(1, MAXN + 1):
    for k in range(MAXK + 1):
        pref[k][i] = pref[k][i - 1]
    k = cnt[i]
    if k <= MAXK:
        pref[k][i] += 1

q = int(input())
out = []
for _ in range(q):
    l, r, k = map(int, input().split())
    if k > MAXK:
        out.append("0")
    else:
        out.append(str(pref[k][r] - pref[k][l - 1]))

print("\n".join(out))
```実装は、実際に対数時間ですべての数値を高速に因数分解することを保証する最小素因数ふるいを構築することから始まります。 次に、各数値は、最小の素因数で繰り返し除算することによって分解され、素因数の多重度に正確に対応するステップの総数が累積されます。 

プレフィックス テーブルは、単純な累積的な方法で構築されます。 各行は固定値に対応します$k$、各列はカウントをそのインデックスまで拡張します。 この構造により、クエリへの応答が 1 つの減算で行われることが保証されます。 

繊細なディテールが境界を成す$k$最大数なので16まで$10^5$素因数は 16 個を超えることはできません (なぜなら$2^{16} > 10^5$)、それより大きい値は安全に無視され、すぐにゼロが返されます。

 ## 特殊なケース

 厄介なケースは次のような場合です$k = 1$、素数のみをカウントします。 のような入力の場合$l = 2, r = 10, k = 1$の場合、それぞれの素因数が合計で 1 つだけあるため、アルゴリズムは 2、3、5、7 を正しくカウントします。 プレフィックス配列は素数性を特別に扱いません。 それは因子数から自然に現れます。 

もう 1 つの特殊なケースは、2 のべき乗のような数値です。 のために$x = 16$、因数分解は$2^4$、 それで$cnt[16] = 4$。 単純な個別素数解釈では、これを 1 として誤分類してしまいますが、ふるいに基づく多重度カウントは、最小の素因数による除算中に正しく 4 回増加し、$k = 4$。
