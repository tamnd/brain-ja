 ## 解決策
 ## 問題の理解

 最大 100 個の頂点と最大 200 個のエッジを持つ、接続された無向の単純なグラフが与えられます。 タスクは、グラフが同じ頂点セットに対して定義された 2 つのスパニング ツリーの結合として解釈できるように、各エッジに 3 つのラベルのいずれかを割り当てることです。 

ラベル付けルールは非対称です。最初のツリーは、ラベルが 1 または 3 のすべてのエッジを取得することによって形成され、2 番目のツリーは、ラベルが 2 または 3 のすべてのエッジを取得することによって形成されます。ラベル 3 のエッジは両方のツリーに属しているため、共有エッジとして機能します。 すべての頂点は、結果として得られる両方のサブグラフで接続されている必要があり、それらの各サブグラフも非巡回でなければなりません。 

したがって、最終出力は単なる色付けではなく、エッジ セットが一緒になって元のグラフのすべてのエッジをカバーする 2 つのスパニング ツリーが存在し、ラベル 3 が割り当てられたエッジが両方のツリー間で共有されているという証明書になります。 

制約は十分に小さいため、エッジ上の二次推論またはわずかに三次推論さえも許容されます。 ただし、構造要件はグローバルです。重みの最適化やローカル チェックは行わず、2 つの独立したスパニング ツリー制約を同時に適用します。 これは通常、制御された方法でグローバルな非周期性を維持しない限り、単純なエッジごとの割り当てや貪欲な選択は失敗することを意味します。 

5 つの頂点で完全なグラフなど、グラフが非常に密集している場合、微妙な失敗のケースが発生します。 このようなグラフでは、最初のスパニング ツリーを任意に選択し、残りのエッジを収容するように 2 番目のツリーを強制すると、2 番目のツリーの強制部分にサイクルが簡単に作成される可能性があります。 これらの強制エッジにすでにサイクルが含まれている場合、最初のツリーがどのように選択されたかに関係なく、完了することはできません。 

## アプローチ

 強引なアイデアは、2 つのスパニング ツリーを直接選択することです。 考えられるすべてのスパニング ツリー T1 について、すべてのスパニング ツリー T2 を試して、元のグラフのすべてのエッジがそれらの少なくとも 1 つにあるかどうかを確認できます。 スパニング ツリーの数は n で指数関数的であるため、すべてのスパニング ツリーを生成することさえ、小さなグラフを超えると実行不可能になります。 m が 200 までの場合、探索空間が膨大になるため、このアプローチはすぐに失敗します。 

重要な単純化は、対称的に考えるのをやめるということです。 一度に 2 つのツリーを構築するのではなく、最初に 1 つのスパニング ツリーを修正し、次に 2 番目のツリーが最初のツリーで使用されていないすべてのものを強制的に吸収します。 

T1 をグラフの任意のスパニング ツリーとする。 エッジが T1 にない場合は、すべてのエッジが 2 つのツリーの少なくとも 1 つに出現する必要があるため、エッジは T2 に属する以外に選択肢はありません。 これにより、T2 の強制エッジのセットが即座に決定されます。 残された唯一の自由は、T2 に T1 の一部のエッジも含めることができることですが、グラフの外側のエッジを含めたり、強制的なエッジを省略したりすることは許可されません。 

したがって、問題全体は次のようになります。スパニング ツリー T1 の外側のエッジのセットをスパニング ツリーに拡張できるようなスパニング ツリー T1 を見つけることができるか?

 同様に、F を T1 にないエッジのセットとして表す場合、F には既にサイクルが含まれていてはなりません。 F にサイクルが含まれる場合、T2 には F のすべてのエッジが含まれなければならず、ツリーにサイクルを含めることはできないため、T2 には強制的にサイクルが含まれます。 

F が非環状になるとフォレストが形成され、T1 からいくつかのエッジを追加してコンポーネントを接続することで、安全にスパニング ツリーに拡張できます。 T1 自体は接続されているため、F のコンポーネント間にはスパニング ツリーを完成させるのに十分なエッジが常に含まれています。 

これにより、問題全体が、補数がサイクルフリーであるスパニング ツリー T1 を見つけることに帰着します。

 | --- | --- | --- | --- |
 | スパニング ツリーのすべてのペアを試してみる | 指数 | O(n + m) | 遅すぎる |
 | 1 つのスパニング ツリーを修正し、補数を検証します。 O(nm) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

まず候補となる最初のツリーを構築し、それが有効な 2 番目のツリーを許可するかどうかを検証します。 

1. DFS または BFS を使用してグラフのスパニング ツリー T1 を構築します。 どのエッジがこのツリーに属しているかをマークします。 
2. T1 にない残りのエッジを考慮します。 このセットを F と呼びます。これらのエッジは、強制的に 2 番目のツリー T2 に属します。 
3. F にサイクルが含まれているかどうかを確認します。 これは、素のセット共用体構造を使用して行います。 F のエッジを反復処理し、それらの端点を結合しようとします。 同じコンポーネント内に既に存在する 2 つの頂点を結合しようとした場合、F には循環が含まれており、解は存在しません。 
4. F が非環式の場合、それがフォレストを形成することがわかります。 F のすべてのエッジから T2 の構築を開始します。 
5. 次に、T1 からエッジを 1 つずつ追加し、すべての頂点が接続されるまで、DSU 内のさまざまなコンポーネントを接続します。 T1 はスパニング ツリーであるため、これらのエッジは、T2 にサイクルを導入することなくすべてのコンポーネントを接続するのに十分です。 
6. T1 と T2 の両方を構築した後、色を割り当てます。 両方のツリーのエッジはカラー 3 を受け取ります。T1 のエッジのみがカラー 1 を受け取ります。T2 のエッジのみがカラー 2 を受け取ります。構造上、すべてのエッジが少なくとも 1 つのツリーに存在することが保証されます。 

これが機能する理由は、構造的不変条件に基づいています。つまり、T1 の外側のすべてのエッジが永続的に T2 に強制されます。 T2 が失敗する唯一の方法は、これらの強制エッジがすでに非周期性に違反している場合です。 そうでない場合、T1 の残りのエッジがフォレストのすべてのコンポーネントを接続するため、いつでもスパニング ツリーに拡張できる有効なフォレストが形成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.p = list(range(n))
        self.r = [0] * n

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return False
        if self.r[a] < self.r[b]:
            a, b = b, a
        self.p[b] = a
        if self.r[a] == self.r[b]:
            self.r[a] += 1
        return True

n, m = map(int, input().split())
edges = []
g = [[] for _ in range(n)]

for i in range(m):
    x, y = map(int, input().split())
    x -= 1
    y -= 1
    edges.append((x, y, i))
    g[x].append((y, i))
    g[y].append((x, i))

parent = [-1] * n
used = [False] * m
stack = [0]
parent[0] = -2

while stack:
    v = stack.pop()
    for to, ei in g[v]:
        if parent[to] == -1:
            parent[to] = v
            used[ei] = True
            stack.append(to)

t1 = set(i for i in range(m) if used[i])
t2_dsu = DSU(n)

ok = True
for i, (u, v, _) in enumerate(edges):
    if i not in t1:
        if not t2_dsu.union(u, v):
            ok = False
            break

if not ok:
    print("No")
    sys.exit()

# build T2 components connectivity using remaining T1 edges
for i in t1:
    u, v, _ = edges[i]
    t2_dsu.union(u, v)

color = [0] * m

for i, (u, v, _) in enumerate(edges):
    in_t1 = i in t1
    # edge in T2 iff not in T1 OR needed to connect in DSU view
    in_t2 = True  # all non-T1 edges are in T2; T1 edges also used to connect components

    if in_t1:
        # decide if it is also in T2 (if it connects different components)
        if t2_dsu.find(u) != t2_dsu.find(v):
            color[i] = 2
        else:
            color[i] = 3
            t2_dsu.union(u, v)
    else:
        color[i] = 2

# T1 edges are exactly tree edges from DFS
for i in t1:
    if color[i] == 0:
        color[i] = 1

print("Yes")
print(*color)
```このコードは、まず DFS を使用してスパニング ツリーを構築し、そのエッジを T1 候補としてマークします。 次に、残りのすべてのエッジが強制的に T2 に組み込まれるため、非循環構造を形成できるかどうかを検証します。 サイクルが現れると、すぐに拒否されます。 

その後、非 T1 エッジを必須として扱い、DSU を使用してサイクルが発生しないようにすることで、T2 を段階的に構築します。 最後に、各エッジが T1、T2、または両方に属するかどうかに応じて色を割り当てます。 

微妙な点は、T1 エッジが強制エッジ構造の異なるコンポーネントを接続する場合にのみ T2 に昇格されることです。 これにより、接続を完了するために必要な場合にのみそれらを使用することが保証されます。

 ## 特殊なケース

 重要なエッジケースは、グラフがすでにツリーになっている場合です。 その状況では、T1 はエッジ セット全体であるため、強制セット F は空になります。 空のエッジ セットは自明のことながら非巡回であり、T1 からのすべてのエッジを追加することで T2 を形成でき、その結果、両方のツリーが同一になります。 

もう 1 つのエッジ ケースは、スパニング ツリーの補部分に常にサイクルが含まれるグラフ (5 つ以上の頂点上の完全なグラフなど) です。 その場合、T1 を選択しても循環強制セットの作成が回避されるため、正しい出力は常に「No」になります。
