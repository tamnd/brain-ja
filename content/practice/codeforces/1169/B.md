 ## 解決策
 ## 問題の理解

 整数ペアのコレクションが与えられます。各要素の範囲は 1 からある上限までです。$n$。 私たちの仕事は、2 つの整数が存在するかどうかを調べることです。$x$そして$y$すべてのペアにこれら 2 つの整数の少なくとも 1 つが含まれるようにします。 言い換えると、$x$または$y$すべてのペアを「カバー」する必要があります。 そのような選択肢が存在する場合は、「YES」を出力します。 それ以外の場合は「いいえ」。 

制約は厳しいです:$n$そして$m$それぞれ最大 300,000 まで大きくなる可能性があります。 これにより、可能な限りすべてを繰り返すブルートフォースアプローチが即座に排除されます。$(x, y)$ペアで$O(n^2)$時間、それは可能性があります$9 \cdot 10^{10}$操作。 代わりに、ペアの構造を利用して、すべての組み合わせを明示的に考慮することを避ける必要があります。 

多くのペアが同じ要素を共有する場合、微妙なエッジケースが発生します。 たとえば、最初のペアが$(1, 2)$、時期尚早に選択する可能性があります$x = 1$そして見つけてみてください$y$他の場所でも、他のペアは次のようになります$(3, 4)$その選択は無効になります。 もう 1 つの注意が必要な状況は、ペアの異なるサブセットをカバーするために複数の候補ペアが存在するが、単一の選択肢がない場合です。$x$そして$y$すべてをカバーします。 たとえば、次のように入力します。```
4 3
1 2
3 4
1 3
```個々のペアが候補と「互換性がある」ように見えても、解決策はありません$x$または$y$。 

## アプローチ

 ブルートフォースアプローチは簡単です。すべてを反復処理します。$(x, y)$とペアにする$x < y$すべての入力ペアに少なくとも 1 つが含まれているかどうかを確認します。 これには、$O(n^2 \cdot m)$操作が遅すぎるため、$n, m \sim 3 \cdot 10^5$。 各候補ペアのチェックは線形です。$m$、しかし、候補ペアの二次数は法外です。 

重要な観察は、最初の入力ペアが、$(a_1, b_1)$、解候補を少なくとも 1 つ含める必要があります。 解決策が存在する場合は、次のいずれかです$x = a_1$または$x = b_1$(あるいはおそらく$y = a_1$または$y = b_1$）。 これにより、チェックする必要がある候補ペアの数が大幅に減少します。 最初のペアと、それと競合するペアから導き出される可能性の小さなセットを試すだけで済みます。 

アルゴリズムは次のように仮定して進みます。$x$最初の要素と等しい$a_1$、そして適切なものを見つけようとします$y$まだ含まれていない残りのペアをすべてカバーします$a_1$。 そうでない場合$y$存在する場合は、次の仮定でプロセスを繰り返します。$x = b_1$。 また、最初の「問題のある」ペアが含まれる組み合わせもチェックします。$x$。 これにより、候補ペアが最大 4 つのチェックに減り、アルゴリズムが効率的になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2 * m) | O(m) | 遅すぎる |
 | 最適 | O(m) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 最初のペアを取ります$(a_1, b_1)$そして仮定してみてください$x = a_1$。 を含まないすべてのペアを特定します。$a_1$。 何もない場合は、どれでも$y \neq x$十分であり、答えは「YES」です。 
2. カバーされていないペアのうち、最初のペアを選択します。$(c, d)$、試してみてください$y = c$または$y = d$。 残りのすべてのペアに次の少なくとも 1 つが含まれているかどうかを確認します。$x = a_1$または$y$。 「はい」の場合は「YES」を返します。 
3. 解決策が見つからない場合$x = a_1$、同じプロセスを繰り返します$x = b_1$。 
4. どちらの選択も有効な結果をもたらさない場合$y$、「いいえ」を返します。 

機能する理由: このアルゴリズムは、次の少なくとも 1 つが満たされる不変式に依存します。$x$または$y$各ペアに存在する必要があります。 アンカリングにより$x$最初のペアの 1 つの要素に関して、問題を単一の互換性のある要素を見つけることに縮小します。$y$。 どのソリューションにも最初のペアの要素が少なくとも 1 つ含まれている必要があるため、これら 4 つの候補を試すのは非常に困難です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def check(x, pairs):
    y_candidates = []
    for a, b in pairs:
        if a != x and b != x:
            y_candidates.append((a, b))
    if not y_candidates:
        return True
    c, d = y_candidates[0]
    for y in (c, d):
        if all(x in p or y in p for p in pairs):
            return True
    return False

def main():
    n, m = map(int, input().split())
    pairs = [tuple(map(int, input().split())) for _ in range(m)]
    
    a1, b1 = pairs[0]
    if check(a1, pairs) or check(b1, pairs):
        print("YES")
    else:
        print("NO")

if __name__ == "__main__":
    main()
```の`check`関数は候補に含まれていないペアを識別します$x$。 このようなペアごとに、両方の要素を可能なものとしてテストします。$y$。 の`all`機能により、すべてのペアが確実にカバーされます。 これにより、問題は最大 4 つの候補チェックに減らされ、すべてのコストのかかる反復が回避されます。$(x, y)$combinations. すべてのペアが最初の要素を含む、または競合するペアが 1 つだけであるなどのエッジ条件は自然に処理されます。

## 複雑さの分析
