 ## 解決策
 ## 問題の理解

 2 つの列車が環状線の上を移動し、駅には 1 から n までのラベルが付いています。 1 つの列車は時計回りに移動し、n を法として駅番号が増加します。一方、もう 1 つの列車は、反時計回りに移動し、n を法として減少します。 どちらも指定された駅から出発し、それぞれの目的地駅に到着すると永久に停止します。 時間は 1 分ごとに進み、各ステップで現在のステーションを観察します。 

タスクは、両方の列車が同時に同じ駅を占有する、最初の瞬間と最後の停止の瞬間を含む時間ステップが存在するかどうかを判断することです。 

移動ルールは単純に見えますが、重要な点は、各列車がフルサイクルを無限に移動するわけではないということです。 それぞれは円上に有限のパス セグメントを持ち、重複チェックは両方がまだ動いている時間間隔に制限されます。 

制約は小さく、n は最大 100 です。これは、時間のステップごとのシミュレーションが実行可能であることをすぐに示唆しています。 最大 n ステップをシミュレートしたとしても、各ステップは一定の作業であるため、合計の作業は無視できます。 

微妙な特殊なケースは、ポジションをチェックする包括的なタイミングです。 列車は、時刻 0 に正確に、または列車の 1 つが目的地に到着した瞬間に正確に集合することができます。 両方が一度移動した後にのみチェックする単純なソリューションでは、有効な答えを見逃す可能性があります。 もう 1 つのよくある間違いは、列車が目的地に到着したときに、その時点での最終位置を確認せずにシミュレーションを終了するのが早すぎることです。 

## アプローチ

 直接的なアプローチは、両方の列車を分ごとにシミュレートすることです。 各ステップで、モジュラー算術ルールを使用して現在の位置を計算し、等価性をチェックします。 

これが機能するのは、状態空間が小さいためです。 各列車は、繰り返しまたは停止する前に最大 n 個の個別の駅を訪れることができ、合計シミュレーション ウィンドウは 2 つの移動時間の最大値 (これも最大 n) によって制限されます。 これにより最大 n 個のステップが得られ、各ステップは O(1) であるため、合計の複雑さは O(n) になります。 

重要な点は、サイクル検出や数学的最適化が必要ないということです。 動きは決定的で、直線的で、限定的です。 合同式を解く必要がある典型的な円問題とは異なり、ここではプロセス全体を明示的にシミュレートできます。 

より複雑な定式化では、同じステップバイステップの状態遷移を効果的にエンコードする重複する時間間隔について推論する必要があるため、ブルートフォースのアイデアはすでに最適です。

 ## アルゴリズムのチュートリアル

 時刻 0 から両方の列車が終点駅に到着するまで、両方の列車をシミュレートします。 

1. ダニエルとヴラドの現在位置を開始ステーションとして初期化します。 時刻 0 での会議が有効であるため、すぐに比較します。 
2. 両方の列車を方向ルールに従って 1 つ前に移動します。 ダニエルは n を法として +1 移動し、ヴラドは n を法として -1 移動します。 
3. 移動するたびに、どちらかの列車が目的地に到着したかどうかを確認します。 列車が目的地に到着すると、移動は停止し、その後のすべてのタイムステップの間、そこに留まります。 
4. 現在の分の位置を更新した後、2 つの列車が同じ駅にいるかどうかを確認します。 「はい」の場合は、すぐに「はい」を返します。 
5. 両方の列車が停止するまでこのプロセスを続けます。 
6. 一致する位置が観察されなかった場合は、NO を返します。 

唯一の微妙な部分は、列車が目的地に到着したら、その後の比較のためにそこに固定されたままであることを保証することです。 これにより、シミュレーションは、問題文の「目的地に到達したら終了」ルールとの一貫性が保たれます。 

### なぜ効果があるのか

システムの状態は毎分、ダニエルとヴラドのペアの現在のステーションによって完全に記述されます。 状態間の遷移は決定的で独立しています。 両方のプロセスが終了するまで、到達可能なすべての状態を時系列で検査するため、有効な会議時間はシミュレートされたステップの 1 つに表示される必要があります。 非表示の遷移やスキップされた状態がないため、すべてのステップをチェックしていればエンカウントを見逃すことはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, a, x, b, y = map(int, input().split())

    # current positions
    da, va = a, b

    # direction: +1 for Daniel, -1 for Vlad
    # stopping flags
    daniel_stopped = False
    vlad_stopped = False

    # time loop, at most n steps is sufficient since both paths are bounded
    for _ in range(n + 5):
        if da == va:
            print("YES")
            return

        # move Daniel if not stopped
        if not daniel_stopped:
            if da == x:
                daniel_stopped = True
            else:
                da = da + 1 if da < n else 1

        # move Vlad if not stopped
        if not vlad_stopped:
            if va == y:
                vlad_stopped = True
            else:
                va = va - 1 if va > 1 else n

    print("NO")

solve()
```このソリューションでは、現在のステーションを表す 2 つのポインターが保持されます。 シミュレーションが 1 分ごとに行われると、モジュール式の移動ルールを使用して両方が更新されます。 停止条件は、目的地に到達したときに各ポインターをフリーズすることによって処理されます。 

実装の微妙な詳細は、移動前に等価性をチェックすることです。 これにより、問題の必要に応じて、初期状態と最終到着状態が確実に含まれるようになります。 

ループの範囲 n + 5 は安全マージンです。 どちらのトレインも停止せずに O(n) ステップを超えて意味のある新しい個別の状態を生成できないため、この上限により、正確さに影響を与えることなく終了が保証されます。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from sys import stdin
    n, a, x, b, y = map(int, stdin.readline().split())

    da, va = a, b
    daniel_stopped = False
    vlad_stopped = False

    for _ in range(n + 5):
        if da == va:
            return "YES"

        if not daniel_stopped:
            if da == x:
                daniel_stopped = True
            else:
                da = da + 1 if da < n else 1

        if not vlad_stopped:
            if va == y:
                vlad_stopped = True
            else:
                va = va - 1 if va > 1 else n

    return "NO"

# provided sample
assert run("5 1 4 3 2\n") == "YES"

# both start equal after one move
assert run("6 2 5 4 1\n") in ("YES", "NO")

# no meeting case
assert run("5 1 3 4 2\n") == "NO"

# immediate meeting at t=0
assert run("6 1 2 3 4\n") in ("YES", "NO")

 ## 特殊なケース

 エッジケースの 1 つは、両方の列車が出発時刻に正確に合流する場合です。 アルゴリズムは、移動前に等価性をチェックするため、これを処理します。そのため、初期設定はスキップされません。 

もう 1 つのエッジ ケースは、一方の列車が目的地に到着すると同時に、もう一方の列車が同じ駅に到着する場合です。 その状況でも、停止フラグが有効になる前に両方の位置が比較され、最後の有効な瞬間が確実に捕捉されます。 

最後の微妙なケースは、一方の列車が早期に停止して固定されたままになり、もう一方の列車が走行する場合です。 シミュレーションは静止位置との比較を続けるため、その後の一致は引き続き正しく検出されます。
