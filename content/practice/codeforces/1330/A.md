 ## 問題の理解

 参加者のコンテスト結果の履歴が与えられ、各結果がランク (順位) になります。 その後、さらに多くの将来のコンテストを想像することができます。`x`そして、将来のコンテストでの順位を任意に選択することができます。 

目標は、既存の結果とこれらの結果の両方を使用して、最小のポジ​​ティブ ランクをいくつ「カバー」できるかを判断することです。`x`仮想的な将来の結果。 言い換えれば、最大の整数が必要です`v`からのすべてのランクが`1`に`v`古い結果に少なくとも 1 回表示され、さらに次の選択肢がいくつかあります`x`追加の結果。 

重要な点は、今後のコンテストには任意のランク値を割り当てることができるため、不足しているランクを埋めることができる柔軟な「スロット」として機能するということです。 制約は、まさに次のことだけです。`x`そのようなスロット。 

入力サイズが小さいとしても、問題は基本的に、正の整数の接頭辞内の欠損値をカウントすることです。 

単純なアプローチでは、値の追加をシミュレートしたり、それぞれの実現可能性を貪欲にテストしようとします。`v`しかし、難しいのは、ランクの欠落が一定の範囲内でのみ問題となることを理解することです。 

現在の結果に重複したランクがすでに含まれている場合、微妙なエッジ ケースが発生します。 たとえば、すべてが`a_i = 1`、その場合、より高いランクが完全に欠落しており、将来のスロットでそれらをカバーする必要があります。 

もう 1 つの重要なエッジケースは次のような場合です。`x`すべてのギャップを埋めるのに十分な大きさです。その場合、不足しているランクを割り当てるのに十分な将来のコンテストがある限り、答えは入力に表示される最大値を超えることができます。 

## アプローチ

 強引なアイデアは、増やしてみるということです`v`1 から順に、それぞれ`v`からすべての数値をカバーできるかどうかを確認します。`1`に`v`既存の配列に加えて最大でも使用`x`余分な値。 修正の実現可能性を確認するには`v`のどの数字をマークしますか`[1, v]`すでに存在しています`a`、欠落している数を数え、この数が超えていないことを確認します。`x`。 

これが機能するのは、各欠損値を「作成」するには、今後少なくとも 1 つのコンテストが必要になるためです。 ただし、これをそれぞれ独立して行うと、`v`アレイを繰り返しスキャンする必要があるため、大まかに`O(n * max_value)`最悪の場合のテスト ケースごとに実行されますが、制約を考慮するとこれは不要です。 

重要な観察は、答えはプレフィックスから欠落している個別の整数の数によって決まるということです。`[1, v]`。 現在の配列のどの数値がこの範囲に該当するかを追跡すると、すでにカバーされている値の数を維持し、段階的に拡張できます。`v`欠損値の数が超えるまで`x`。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. 指定された配列内のすべての値に対する頻度または存在セットを構築します。 これにより、すでにどのランクを持っているかがわかります。 
2. から始める`v = 1`そしてカウンターを維持する`missing`、数字が何個あるかを表します`[1, v]`配列内に存在しません。 
3. それぞれについて`v`、配列内に存在するかどうかを確認します。 そうでない場合は増分します`missing`このランクは、次のいずれかを使用して「作成」する必要があるためです。`x`今後のコンテスト。 
4. 停止するタイミング`missing`より大きくなる`x`。 最後に有効な`v`が答えです。 

上方向にスキャンする理由は、次のように条件が厳密に難しくなるからです。`v`が増加します。 新しい番号はそれぞれ、コストが追加されないか (すでに存在する場合)、将来の限られた柔軟性を 1 単位消費します。 

### なぜ効果があるのか

 いつでもプレフィックスをカバー`[1, v]`その範囲内で欠落しているすべての数値が今後のコンテストで提供されるようにする必要があります。 今後の各コンテストは正確に 1 つのランクに貢献するため、修正できるのは次のとおりです。`x`欠損値。 アルゴリズムは必要な修正の数を正確に追跡します。`v`成長します。 不足している番号を渡す場合にのみ要件が増加するため、最初に要件を超えたときは`x`、それ以上大きくない`v`有効になる可能性があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, x = map(int, input().split())
        a = list(map(int, input().split()))

        present = [False] * 300  # safe upper bound: 100 + 100 + margin
        for v in a:
            present[v] = True

        missing = 0
        v = 0

        while True:
            v += 1
            if v < len(present) and not present[v]:
                missing += 1
            if missing > x:
                print(v - 1)
                break

def main():
    solve()

if __name__ == "__main__":
    main()
```このソリューションでは、まず入力内のすべてのランクのプレゼンス テーブルを構築します。 これにより、ランクがすでに存在するかどうかを定期的にチェックできます。 

それから増加します`v`一歩ずつ。 新しい数値が考慮されるたびに、不足している必要なランクの数が更新されます。 これを超えると`x`、前の値は達成可能な最大プレフィックスです。 

ループ制限は、最悪の場合でも、おおよそ まで考慮するだけで済むため安全です。`max(a_i) + x`。

 ## 特殊なケース

 すべての要素が同一の場合、次のようになります。`a = [1, 1, 1]`、ランクのみ`1`最初はカバーされています。 アルゴリズムはマークのみをマークします`1`存在し、増分はすべての場合にすぐに欠落します`v ≥ 2`。 小付き`x`、すぐに停止し、プレフィックスが拡張できる距離を正しく制限します。 

いつ`x = 0`、アルゴリズムは純粋なプレフィックス完全性チェックになります。 最初の欠落番号で停止しますが、これは今後のコンテストでギャップを補うことができないという事実と一致します。
