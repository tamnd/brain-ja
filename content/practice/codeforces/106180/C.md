 ## 解決策
 ## 問題の理解

 指示された道路で接続された一連の交差点が与えられています。 各道路は、意図した方向に無料で通過できますが、道路の方向に逆らった場合は、その道路に固有のペナルティを支払わなければなりません。 タスクは、間違った方向の道路を使用した場合に支払われるペナルティの合計を最小限に抑えながら、開始交差点 A から目標交差点 B まで移動することです。 逆転を許してもBに到達できない場合は、その旨を報告しなければなりません。 

設定を再解釈する有効な方法は、方向付けられた各道路が 2 つの可能性を提供するものとして見ることです。つまり、それに沿って無料で移動するか、何らかのコストをかけて道路に逆らって移動することです。 この問題は、道路を進むか逆行するかに応じて、エッジの重みが 0 または正の値を持つグラフ上の最短経路問題になります。 

通常、このタスクの Codeforces スタイルの定式化では、入力サイズにより最大 200k のエッジが許可されます。 これにより、すべてのパスを明示的に探索しようとするアプローチは即座に除外されます。 パスを列挙するメソッドや指数再帰を使用するメソッドは失敗します。 エッジの数に対して線形または対数線形に近い動作を探しています。 

同じ交差点のペアの間に複数の道路があり、異なる方向にある可能性がある場合、微妙なケースが発生します。 グラフを方向のないものとして扱うか、エッジを折りたたむ単純な実装では、「無料の前進移動」と「有料の逆方向移動」の区別が失われる可能性があります。 もう 1 つのよくある落とし穴は、すべての道路をコストが等しい双方向として扱うことです。これにより、方向に応じてペナルティを誤って過大評価または過小評価することになります。 

小さな説明的な例:

 入力:

 A = 1、B = 3

 道路:

 1 → 2 (順方向の場合はコスト 0、逆方向の場合はコスト 5)

 2 → 3 (前に進むとコスト0)

 両方のエッジを意図した方向に追跡できるため、正しい出力は 0 です。 

逆方向を常に許可されるものとして扱いながら方向性を無視する単純なアプローチでは、誤ってコスト 5 を割り当てたり、両方の方向を同等に扱ったりして、正確性が損なわれる可能性があります。 

## アプローチ

 この強引な考え方は、A から B に移動するためのあらゆる方法を検討し、道路を逆に通過するたびにコストを蓄積するものとして問題を扱うことです。 状態を超えて DFS または BFS を実行し、すべてのエッジの両方向を試行することを想像することもできます。 すべての有効なルートを探索するため、これは正しいですが、そのサイズはすぐに爆発します。 n 個のノードと m 個のエッジを持つ密なグラフでは、個別のパスの数が指数関数的に増加する可能性があり、慎重に追跡しない限り、単純なサイクルであっても無限の探索が発生する可能性があります。 

重要な観察は、これは隠れた最短経路の問題であるということです。 すべての道路は、その自然な方向へのゼロコスト遷移、または反対方向へのプラスコスト遷移のいずれかに寄与します。 このように再定式化すると、非負の重みを持つグラフに標準の最短パス アルゴリズムを適用できます。 この構造は特に優れています。ほとんどのエッジの重みが 0 であるため、効率的に優先順位を付けることができます。 

これは当然、0-1 BFS スタイルのソリューションまたはダイクストラのバリアントにつながります。 エッジの重みは 0 (順方向) または何らかの正の整数 (逆方向) であるため、優先キューを備えたダイクストラのアルゴリズムは A からすべてのノードへの最小ペナルティをきれいに計算し、B に到達すると停止します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | パス上のブルート フォース DFS | 指数 | O(n + m) | 遅すぎる |
 | 変換されたグラフ上のダイクストラ / 0-1 BFS | O(m log n) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 各道路を 2 つの有向トランジションに変換します。 元の方向のコストは 0 ですが、逆方向のコストはその道路のペナルティに等しいです。 

次に、A から B までの最短経路を計算します。

1. 各道路 u → v が、コスト 0 のエッジ u → v とコスト w のエッジ v → u に寄与する隣接リストを構築します。ここで、w は、その道路を逆転する場合のペナルティです。 この表現は、許可された両方の動きを明示的にエンコードします。 
2. すべてのノードに対して距離配列を無限大で初期化し、dist[A] = 0 に設定します。これは、各交差点に到達するための既知の最小ペナルティを表します。 
3. 開始ノード A をコスト 0 の優先キューにプッシュします。キューは常に、現在最も安価な既知の状態を展開します。 
4. キューが空ではない間に、暫定距離が最小のノードを抽出します。 このノードが B の場合、将来のすべてのパスは悪化するか同等になるだけなので、早期に終了できます。 
5. 現在のノードから到達可能な近隣ノードごとに、現在の距離にエッジ コストを加えたものとして候補距離を計算します。 この値が以前に記録された距離より小さい場合は、値を更新し、近隣をキューにプッシュします。 
6. 到達可能なすべての状態を処理した後、dist[B] がまだ無限大の場合は -1 を出力し、そうでない場合は dist[B] を出力します。 

正確さは、ノードが優先キューからポップされると、その距離がそのノードに到達するための最小のペナルティとして最終的に決定されるという事実にかかっています。 これにより、後で発見されたより安いルートを見逃すことがなくなります。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n, m, A, B = map(int, input().split())
    A -= 1
    B -= 1

    g = [[] for _ in range(n)]

    for _ in range(m):
        u, v, w = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append((v, 0))
        g[v].append((u, w))

    INF = 10**18
    dist = [INF] * n
    dist[A] = 0

    pq = [(0, A)]

    while pq:
        d, u = heapq.heappop(pq)
        if d != dist[u]:
            continue
        if u == B:
            break

        for v, w in g[u]:
            nd = d + w
            if nd < dist[v]:
                dist[v] = nd
                heapq.heappush(pq, (nd, v))

    print(-1 if dist[B] == INF else dist[B])

if __name__ == "__main__":
    solve()
```隣接リストの構築は中心的なモデリング手順です。 各入力道路は、非対称の重みを持つ 2 つの有向エッジになり、これが問題を標準の最短パス タスクに変換します。 

ペナルティが均一ではないため、プライオリティ キューが必要です。 異なるコストを持つ逆エッジが存在すると、単純な BFS は失敗します。 小切手`if d != dist[u]`古い状態の処理を回避します。これは、大きなグラフのパフォーマンスにとって重要です。 

## 実用的な例

 ### 例 1

 入力:

 A = 1、B = 3

 エッジ:

 1 → 2 (w = 4)

 2 → 3 (w = 2)

 私たちは以下を構築します:

 | ステップ | ノード | 距離 | アクション |
 | --- | --- | --- | --- |
 | 1 | 1 | 0 | 開始 |
 | 2 | 2 | 0 (前端) | リラックス 1 → 2 |
 | 3 | 3 | 0 (前端) | リラックス 2 → 3 |

 逆エッジを使用しないため、最終結果は 0 になります。 

これは、方向に従ってパスが存在する場合、アルゴリズムは完全にゼロコスト エッジによりそのパスを優先することを確認します。 

### 例 2

 入力:

 A = 1、B = 3

 エッジ:

 1 → 2 (w = 5)

 2 → 3 (w = 1)

 1 から 3 への直接の転送パスはありません

 | ステップ | ノード | 距離 | アクション |
 | --- | --- | --- | --- |
 | 1 | 1 | 0 | 開始 |
 | 2 | 2 | 0 | 1 → 2 に進む |
 | 3 | 3 | 1 | 2 → 3 を反転するか、利用可能な方向を使用する必要があります |

 ここで、アルゴリズムは最終的に、必要な逆転のためにコスト 1 を蓄積します。 

これは、ゼロコスト継続では十分でない場合にのみリバース エッジがどのように使用されるかを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(m log n) | 各エッジ緩和はヒープ プッシュをトリガーする可能性があり、各ヒープ操作には対数的な時間がかかります。 
| スペース | O(n + m) | 隣接リストと距離および優先キューのストレージ |

 この問題に特有の制約により、この複雑さが問題なく許容されます。 数十万のエッジでも、注意して実装すれば、対数係数は C++ または PyPy の 2 秒の制限に十分耐えられるほど小さいままです。

 ## 特殊なケース

 一般的なエッジ ケースは、グラフがすでに A から B の方向に完全に一貫している場合です。その場合、すべての逆エッジは無関係であり、アルゴリズムは重みがゼロのエッジに対して標準の BFS のように動作する必要があります。 距離は決して増加せず、結果はゼロのままです。 

もう 1 つのケースは、使用可能な唯一の接続で複数のエッジを順番に反転する必要がある場合です。 アルゴリズムは、逆遷移のチェーンに沿ってコストを蓄積することでこれを処理します。 各ステップでは、既知の値が改善された場合にのみ距離が更新されるため、長い逆方向のみのパスであっても、指数関数的に爆発することなく正しく探索されます。 

最後に、B が完全に到達不能になると、B に有限距離が割り当てられることなく、優先キューは最終的に空になります。距離配列は無限大のままで、出力は正しく -1 になります。
