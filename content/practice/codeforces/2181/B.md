 ## 解決策
 ## 問題の理解

 アリスとボブの間のターンベースのゲームをシミュレートするように求められます。 各プレイヤーは正の整数の配列から開始します。 自分の番では、プレイヤーは自分の配列から任意の要素を選択し、それを相手の配列の最大の要素に対して適用します。 選択した要素が対戦相手の最大要素と少なくとも同じ大きさである場合、その要素は削除されます。 それ以外の場合は、相手の最大要素が選択された値だけ減ります。 プレイヤーはアリスから始めて交互に動きます。 相手のアレイを空に減らした最初のプレイヤーが勝ちます。 

入力には複数のテスト ケースが含まれており、それぞれのテスト ケースには最大 100,000 個の要素の配列と最大 10^9 の要素値が含まれます。 すべてのテスト ケースのすべての要素の合計は 10^5 で制限されるため、各配列要素をテスト ケースごとに 1 回処理するアルゴリズムであれば実行可能です。 それぞれの動きをシミュレートする二次アルゴリズムでは、実行する演算が多すぎます。両方の配列に 10^5 要素がある場合、単純なシミュレーションでは O(n*m) 演算が実行され、これは 10^10 ステップになる可能性があり、3 秒の制限を大幅に超えます。 

一方のプレイヤーが対戦相手よりも大幅に大きな要素を持っている場合、微妙なエッジケースが発生します。 たとえば、アリスが [10] を持ち、ボブが [1,1,1] を持っている場合、アリスはボブの要素を繰り返し削除できます。 削減のために最大の要素ではなく任意の要素を選択する不用意なシミュレーションは、間違った勝者を示唆する可能性があります。 

## アプローチ

 ブルート フォースのアプローチは簡単です。ゲームをターンごとにシミュレートします。 各ターンで、相手の配列の最大要素を見つけ、自分の配列からいくつかの要素を選択し、演算を適用します。 1 つの配列が空になるまで繰り返します。 この方法は正しいですが、最大要素の検索と配列の更新を繰り返し行うには 1 移動あたり O(n log n + m log m) かかり、O(n + m) 回の移動が発生する可能性があるため、遅すぎます。最悪の場合、演算回数が 10^10 を超えることになります。 

重要な洞察は、最大の要素のみが重要であるということです。 各ターンでは、プレイヤーはいつでも自分の最大要素を選択して、対戦相手への効果を最大化できます。 これにより、ゲームは最大要素の比較に縮小されます。より大きな最大要素を持つプレイヤーが破壊のペースを効果的に制御します。 両方の配列の最大要素がわかれば、勝者はすぐに決定できます。アリスの最大要素が少なくともボブの最大要素であれば、アリスが先手有利となり勝ち、それ以外の場合はボブが勝ちます。 ゲームを段階的にシミュレーションする必要はありません。最適なプレイは結局のところ、相手の最大要素を減らすことになり、より小さい要素を選択すると厳密には悪くなるからです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O((n+m)^2) | O(n+m) | 遅すぎる |
 | 最大要素の比較 | O(n+m) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、アリスとボブの配列のサイズを読み取ります。 
2. アリスの配列を読み取り、最大要素を計算します。`max_a`。 
3. ボブの配列を読み取り、最大要素を計算します。`max_b`。 
4. 2 つの最大要素を比較します。 もし`max_a >= max_b`、アリスが勝ちます。 そうでなければ、ボブが勝ちます。 
5. 各テスト ケースの勝者を出力します。 

これが機能する理由: 不変条件は、各配列の最大の要素によって、相手の配列を破壊するために必要な最小移動数が決まるということです。 より小さい要素を選択しても、ゲームが速く終了することはありません。 したがって、最大要素を比較すると、完全な最適シミュレーションと同じ結果が得られます。 ゲームはターン制であり、アリスが最初に動くため、アリスの最大要素が少なくともボブのものであれば、最適なプレイのもとでアリスはいつでも最初にボブの配列を破壊できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
results = []

for _ in range(t):
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    
    if max(a) >= max(b):
        results.append("Alice")
    else:
        results.append("Bob")

print("\n".join(results))
```このソリューションは、次を使用して入力を効率的に読み取ります。`sys.stdin.readline`そして、アリスとボブの配列の最大要素をそれぞれ O(n) と O(m) で計算します。 結果をリストに保存し、行ごとの I/O が遅くなるのを避けるために、すべてを一度に印刷します。 実装上の微妙な選択は、最初の要素だけでなく、各プレイヤーの配列全体の最大値を計算することです。これを無視すると、最大の要素が配列の先頭にない場合に間違った答えが生成されてしまいます。

これらのトレースは、シミュレーションなしで最大要素を比較すると勝者を正しく予測できることを確認します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | テスト ケースあたり O(n + m) | 各配列の最大値の計算には線形時間がかかります。 
| スペース | O(1) 補助 | 最大値と結果リストのみを保存 |

 の合計を考えると、`n`そして`m`すべてのテスト ケースで 10^5 を超えず、操作の合計数は 2*10^5 以内に留まり、制限時間 3 秒を十分に下回ります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    t = int(input())
    results = []
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        results.append("Alice" if max(a) >= max(b) else "Bob")
    return "\n".join(results)

# Provided samples
assert run("2\n1 1\n70\n90\n2 3\n30 30\n20 20 40\n") == "Bob\nBob"

# Custom cases
assert run("1\n1 1\n100\n100\n") == "Alice", "equal max, first move wins"
assert run("1\n3 2\n5 10 15\n10 5\n") == "Alice", "Alice largest wins"
assert run("1\n2 2\n1 1\n2 2\n") == "Bob", "Bob largest wins"
assert run("1\n5 5\n1 2 3 4 5\n5 4 3 2 1\n") == "Alice", "equal largest, first move wins"
assert run("1\n1 3\n50\n10 20 30\n") == "Alice", "single vs multiple, max controls outcome"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1 1\n100\n100`| アリス | 最大値が等しい、先手有利 |
 |`3 2\n5 10 15\n10 5`| アリス | 大きい配列の最大値が優勢 |
 |`2 2\n1 1\n2 2`| ボブ | 相手アレイのマックスが優勢 |
 |`5 5\n1 2 3 4 5\n5 4 3 2 1`| アリス | 最大値が等しい、先手有利 |
 |`1 3\n50\n10 20 30`| アリス | 単一配列と複数配列、最大値が決定 |

 ## 特殊なケース

 アリス [5,5,5] とボブ [5,5] など、すべての要素が等しい配列の場合、最初の移動で最大要素が削除または減少し、アリスが最初に移動するため、アリスが勝ちます。 このアルゴリズムは、繰り返しの動きをシミュレートすることなく、最大値を正確に比較します。 1 つの非常に大きな要素を持つ配列の場合、最大の比較により、最大の要素を持つプレイヤーが決定的な優位性を持つことが保証されます。 単一要素配列を含む入力、0 または 1 つの移動が必要、およびすべてが等しい配列はすべて、この単純な最大要素比較で正しく処理されます。
