 ## 解決策
 ## 問題の理解

 正の整数のリストと初期値が与えられます。`x`。 リストの順序は任意に選択できます。 順序を選択したら、番号を 1 つずつ処理します。 処理された各数値は、現在の値をその数値で割った余りで置き換えられます。 目標は、最終的な値ができるだけ大きくなるように数値を配置することです。 

入力は、配列の長さ、配列値、および開始値で構成されます。 出力は、すべてのモジュロ演算が終了した後に残る最大値です。 モジュロ演算により、後の演算で回復できない情報が破壊される可能性があるため、順序は重要です。 

配列の長さは小さく、最大 21 ですが、値自体は非常に大きくなる可能性があります。 これにより、すべての順列の試行が除外されます。`21!`実行できる範囲をはるかに超えています。 ソリューションでは、数値の大きさではなく、少数の要素を活用する必要があります。 の状態空間`2^21`状態は約 200 万ですが、これは低レベル言語で実現可能であり、メモリ使用量に注意すれば Python でも管理可能です。 

よくある間違いは、より大きな除数を最初または最後に適用する必要があると想定することです。 たとえば、`x = 15`と数字`[5, 6, 7]`、最大の約数を最初に置くと、`15 % 7 = 1`、 それから`1 % 5 = 1`、 それから`1 % 6 = 1`。 最適な順序は`5, 7, 6`、生産`15 % 5 = 0`、`0 % 7 = 0`、`0 % 6 = 0`、これはまだ最適ではありません。 実際の答えは次のようにして得られます。`7, 6, 5`:`15 % 7 = 1`、`1 % 6 = 1`、`1 % 5 = 1`。 この例は、除数のサイズのみに基づいた貪欲な選択では、操作間の依存関係を把握できないことを示しています。 

もう 1 つのエッジ ケースは、一部の値がすでに小さい場合です。 現在の値が残りのすべての除数よりも小さい場合、今後のすべてのモジュロ演算ではその値が変更されません。 たとえば、次の入力を使用します。```
2
10 20
5
```答えは`5`。 現在の状態を考慮せずに変換を適用し続ける不注意な実装では、値が減少することが誤って期待される可能性があります。 

繰り返される値にも注意が必要です。 のために：```
3
5 5 100
12
```答えは`2`。 2 つの同一の約数は別個の演算であるため、両方を考慮する必要があります。 値をインデックス付き要素ではなくセットとして扱うと、有効な順序が失われます。 

## アプローチ

 直接的なアプローチは、可能な順序をすべて試してみることです。 各順列について、モジュロ演算をシミュレートし、最大の最終値を保持します。 考えられるすべての配置がチェックされているため、これは正しいです。 ただし、置換の数は、`n!`、そしてのために`n = 21`これは約です`5.1 * 10^19`可能性。 1 秒あたり 10 億回の操作を行っても、このアプローチは実用的ではありません。 

重要な観察は、多くの異なる命令が同じ中間状況に到達するということです。 いくつかの数値を使用した後、重要なのは、どの数値が使用可能であり、現在の値が何であるかだけです。 現在の値は常にモジュロ演算によって初期値から生成されるため、インデックスの特定のサブセットを処理した後に到達可能な最良の値を保存できます。 

使用されている要素のサブセットごとに、次に未使用の要素をそれぞれ追加してみます。 移行は、モジュロ演算をもう 1 つ適用するだけです。 がある`2^n`サブセット、および各サブセットは最大までチェックします`n`次の選択肢、約`n * 2^n`操作。 

重要な削減点は、サブセットを生成した正確な順序をまったく気にしないことです。 2 つの異なる次数が同じ要素セットを使用する場合、将来のモジュロ演算は現在値に関して単調であるため、大きい方の現在値のみが問題になります。 同じ残りの操作を適用した後、小さい電流値が大きい電流値よりも良くなることはありません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n! * n) | O(n) | 遅すぎる |
 | 最適 | O(n * 2^n) | O(2^n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を作成する`dp`どこ`dp[mask]`インデックスが設定されている要素を正確に使用した後に到達可能な最大電流値を表します。`mask`。 空のマスクは元の値から始まります`x`まだ操作が行われていないためです。 
2. すべてのマスクを繰り返し処理します。 到達可能な状態ごとに、マスクに含まれていないすべての要素を試します。 これは、順列で次の番号を選択することを表します。 
3. 選択した要素にモジュロ演算を適用します。 古いマスクと新しい要素を含む状態を、現在の内容と新しく取得した値の間の最大値で更新します。 
4. すべてのサブセットが処理されると、すべての配列要素が 1 回だけ使用されるため、完全なマスクには答えが含まれます。 

なぜ機能するのか: 不変条件は次のとおりです。`dp[mask]`要素を正確に使用した後、常に可能な限り最良の値を保存します。`mask`。 遷移では、可能なすべての次の選択肢が試行されるため、すべての部分的な順序付けの可能なすべての継続が調査されます。 同じ約数が適用される場合、将来のモジュロ演算で小さい開始値が大きい値を上回ることはできないため、サブセットの最大値のみを保持するのが安全です。 

## Python ソリューション```python
import sys
from array import array

input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    x = int(input())

    size = 1 << n
    dp = array('Q', [0]) * size
    dp[0] = x

    for mask in range(size):
        cur = dp[mask]
        if cur == 0 and mask != 0:
            continue
        remaining = ((1 << n) - 1) ^ mask
        while remaining:
            bit = remaining & -remaining
            i = bit.bit_length() - 1
            nxt = mask | bit
            val = cur % a[i]
            if val > dp[nxt]:
                dp[nxt] = val
            remaining -= bit

    print(dp[-1])

if __name__ == "__main__":
    solve()
```の`dp`配列の用途`array('Q')`通常の Python リストの代わりに。 状態は 200 万を超えるため、Python 整数オブジェクトを保存すると大量のメモリが浪費されます。 すべての入力は最大でも`10^18`。 

遷移ループは、次を使用して残りの要素から 1 つのセット ビットを抽出します。`remaining & -remaining`。 これにより、不必要な操作によるスキャンが回避され、余分なリストの作成も回避されます。 インデックスは次のように回復されます。`bit_length() - 1`。 

小切手`cur == 0`無駄な状態をスキップします。 現在の値がゼロになると、その後のすべてのモジュロ演算によってその値がゼロに保たれるため、その状態の子孫もすべてゼロになります。 最終的な状態は、`dp[(1 << n) - 1]`と同じです`dp[-1]`完全なマスクが最後のインデックスであるためです。

## テストケース```python
import sys
import io
from array import array

def solution(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))
    x = int(input())

    size = 1 << n
    dp = array('Q', [0]) * size
    dp[0] = x

    for mask in range(size):
        cur = dp[mask]
        if cur == 0 and mask:
            continue
        rem = (size - 1) ^ mask
        while rem:
            bit = rem & -rem
            i = bit.bit_length() - 1
            nxt = mask | bit
            val = cur % a[i]
            if val > dp[nxt]:
                dp[nxt] = val
            rem -= bit

    return str(dp[-1])

 ## 特殊なケース

 開始値がすでにすべての約数よりも小さい場合:```
2
10 20
5
```初期状態には値があります`5`。 次に考えられる選択肢は両方とも`5 % 10 = 5`または`5 % 20 = 5`。 以降の操作では値が変更されないため、フルマスク状態が維持されます。`5`。 

繰り返される要素の場合:```
3
5 5 100
12
```州は指数に基づいているため、DP は 2 つの 5 を統合しません。 1 つのパスは最初のパスを使用します`5`、別の人は2番目を使用します`5`、両方の操作は引き続き独立して使用できます。 最良の道は`100, 5, 5`、与える`12 % 100 = 12`、 それから`12 % 5 = 2`、 それから`2 % 5 = 2`。 

ゼロに達するパスの場合:```
4
2 4 8 16
1000000000000000000
```DP は、除数を適用した後に現在の値がゼロになる状態に遭遇する可能性があります`2`。 その状態からのすべての遷移はゼロのままであるため、これらの状態をスキップすることが正しいのです。 最終的な答えはまだゼロです。
