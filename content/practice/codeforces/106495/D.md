 ## 問題の理解

 私たちには、一連のステージにわたる制御されたプロセスとして解釈できるシステムが与えられており、各ステージでは隠れた状態に影響を与えるいくつかの確率的なアクションが提供されます。 一定の地平線を越​​えて$N$最後まで生き残る確率を最大化するには、各ステップで何をすべきかを決定する必要があります。 

あらゆるステップで、将来の生存可能性に影響を与えるアクションを 1 つ選択します。 行動の中には、資源（電池など）を集めることができるもの、生存に利益をもたらすものもありますがリスクを伴うもの（毒になる可能性のある食べ物など）、純粋に防御的なもの（安全に隠れるなど）もあります。 また、環境は各段階でランダムな脅威を導入します。十分なバッテリーがある場合にのみ対処できる光ベースの捕食者と、出現確率は不明だがプロセス全体で固定され、事前に均一に選択される希少な「巨大捕食者」です。 

疲労の制約もあります。スライディング ウィンドウの長さごとに少なくとも 1 回は食物を正常に摂取する必要があります。$H$、そうでなければ、他のすべてに関係なく、私たちは死にます。 バッテリーの在庫は容量によって制限されます$K$、ランプを使用すると、一度にちょうど 2 個のバッテリーが消費されます。 

目標は、リソースの獲得、脅威、中毒におけるすべてのランダム性を考慮して、生存確率を最大化するためのアクションを時間の経過とともに選択することです。 

入力サイズの制約$N \le 500$そしてスモールキャップ$K, H \le 12$時間の経過に伴う動的プログラミング ソリューションと、リソースと生存条件を記述するコンパクトな状態空間を強く提案します。 すべてのアクション シーケンスを直接列挙することは不可能です。これは、アクション シーケンスが指数関数的に増加するためです。$3^N$また、ポリシーに関する確率論的なシミュレーションでも、最適な決定を正確に把握することはできません。 

自明ではない困難は、バッテリー数、満腹タイミングの制約、確率的な脅威の処理など、複数の状態次元間の相互作用から生じます。 期待値を追跡するだけ、または時間ごとに最適なアクションを貪欲に選択する単純なアプローチは、早期の決定が将来の生存制約が満たされるかどうかに影響するため、失敗します。 

典型的な失敗例は、早期にバッテリーを貪欲に収集すると見た目は良くても、後で枯渇を引き起こす場合です。 たとえば、次の場合$H=2$、「探索バッテリー」を繰り返し選択すると、すぐに大きな資源を獲得できる可能性がありますが、最終的には確実な死につながる食糧不足の期間を強制されます。 バッテリーの使用が早すぎると、もう 1 つの微妙な問題が発生します。将来の補充の計画を立てずに、光に敏感なフェレットを生き延びるためにバッテリーを費やしてしまうと、後で避けられない遭遇が致命的になる可能性があります。

## アプローチ

 ブルートフォースソリューションでは、考えられるすべての意思決定シーケンスをシミュレートしようとします。$N$あらゆる確率的な結果に基づいて分岐します。 各ステップには 3 つのアクションがあり、各アクションには複数の確率的分岐 (バッテリーの獲得、食事の成功、中毒、捕食者の出現) があります。 これは、時間と状態空間の両方で指数関数的な爆発を引き起こし、ゆうに超えます。$10^{100}$中程度の場合でも実行可能なパス$N$。 

重要な観察は、ランダム性にもかかわらず、状態を正しく拡張した場合、システムはマルコフであるということです。 いつでも重要なのは、現在の時間インデックス、バッテリー数、最後に食料を消費してからの時間数だけです。 隠された「ジャイアントフェレット確率」は、全体にわたって均一であるため、分析的に統合できます。$[0,1]$つまり、これに関係する予想される生存寄与は、明示的にシミュレートするのではなく、積分後の決定論的な確率として表すことができます。 

これにより、問題は小さな離散状態空間にわたる動的計画法に帰着され、遷移は 3 つのアクションの 1 つを選択し、確率的結果を適用することに対応します。 DP は、パスを明示的に構築するのではなく、各状態以降の生存確率を追跡します。 

ブルートフォース手法は、すべての可能性を列挙するため概念的には機能しますが、時間の経過とともに各状態が乗算的に分岐するため失敗します。 DP アプローチが機能するのは、個別の意味のある状態の数が次の制限を受けるためです。$N \cdot K \cdot H$、遷移はアクションごとに一定時間で計算可能です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

## アルゴリズムのチュートリアル

 動的プログラミングテーブルを定義します$dp[i][b][h]$、時間から生き残る最大確率を表す$i$現在あることを考えると、最後まで$b$電池がなくなってしまった$h$最後に正常に食物を摂取してから数時間。 もし$h \ge H$、状態は直ちに無効になります。 

この表を時間から逆算して計算します$N$に$1$。 

1. 毎時すべての状態を初期化する$N+1$確率的に完全に成功する$1$、最後の時間を超えて生き残ることは成功を意味するためです。 
2. から何時間も繰り返します$N$まで$1$、計算するときに$dp[i]$、将来のすべての結果$dp[i+1]$はすでに知られています。 
3. 州ごとに$(b, h)$、隠れる、バッテリーを探す、食べ物を探すという 3 つの可能なアクションを評価します。 各アクションは、入力内の確率に基づいて次の状態の重み付けされた組み合わせを生成します。 

隠れることでフェレットにさらされたり、資源を消費したりすることはありません。 唯一の影響は、空腹感が 1 増加することです。移行は決定的です。$dp[i+1][b][h+1]$。 
4. バッテリーを検索すると、確率でバッテリーが 1 つ見つかる可能性があります$b_i$。 成功すると、バッテリーの数が容量まで増加します$K$。 いつものように空腹感が増します。 そこで、成功と失敗の 2 つの結果を組み合わせて、次のように重み付けします。$b_i$そして$1-b_i$。 
5. 食べ物を探すと、食べ物がない、安全な食べ物、有毒な食べ物という 3 つの結果が得られます。 安全な食べ物は空腹感を 0 にリセットし、中毒は即座にランニングを終了します。 これは、移行には生存確率乗数が含まれることを意味します。$1 - v_i$非致命的ブランチの場合。 
6. 選択は私たちが制御するため、各状態について 3 つのアクション値の最大値を取得します。 
7. 戻る$dp[1][S][0]$、で始まることを表します$S$バッテリーも必要だし、飢えのプレッシャーもない。 

### なぜ効果があるのか

 DP は、将来の生存確率が現在の時間、バッテリー数、満腹距離にのみ依存するという事実に依存しています。 すべてのランダム性は各ステップの遷移に局在しており、それらの遷移を平均化すると、追加の履歴情報が将来の結果に影響を与えることはありません。 これにより、拡張状態空間にわたって厳密なマルコフ特性が確立され、グローバルな最適性を失うことなく状態ごとに最適な決定を個別に行うことができるようになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

N, K, S, H = map(int, input().split())

b = [0.0] * (N + 1)
c = [0.0] * (N + 1)
v = [0.0] * (N + 1)
q = [0.0] * (N + 1)

for i in range(1, N + 1):
    bi, ci, vi, qi = map(float, input().split())
    b[i], c[i], v[i], q[i] = bi, ci, vi, qi

# dp[i][batteries][hunger]
dp = [[[0.0 for _ in range(H + 2)] for _ in range(K + 1)] for _ in range(N + 2)]

for bb in range(K + 1):
    for hh in range(H + 1):
        dp[N + 1][bb][hh] = 1.0

for i in range(N, 0, -1):
    for bb in range(K + 1):
        for hh in range(H):
            best = 0.0

            # 1) Hide
            best = max(best, dp[i + 1][bb][hh + 1])

            # 2) Search battery
            bb2 = min(K, bb + 1)
            val_battery = (
                b[i] * dp[i + 1][bb2][hh + 1] +
                (1 - b[i]) * dp[i + 1][bb][hh + 1]
            )
            best = max(best, val_battery)

            # 3) Search food
            # c[i] chance of food, but v[i] poison if found
            safe = dp[i + 1][bb][0]
            no_food = dp[i + 1][bb][hh + 1]

            val_food = (
                c[i] * ((1 - v[i]) * safe + v[i] * 0.0) +
                (1 - c[i]) * no_food
            )
            best = max(best, val_food)

            dp[i][bb][hh] = best

print(f"{dp[1][S][0]:.10f}")
```この実装は DP 定義を直接ミラーリングします。 三重にネストされたループは、時間、バッテリー数、および空腹状態に対応します。 それぞれのアクションは、その確率的な結果に対する期待値として評価され、その中から最良のものが採用されます。 

微妙な点は、バッテリー数をクランプすることです。`min(K, bb + 1)`これにより、在庫制限が確実に遵守されます。 もう 1 つは、飢餓を以下の値に制限することです$H$に達してから$H$は無効であり、それらの状態は有効な遷移とはみなされません。

 ## 特殊なケース

 重大なエッジケースは次のような場合です。$H=1$、つまり、1時間ごとに食物を摂取しないと即死につながるということです。 この状況では、他のすべてのアクションは次のステップで即座に無効になるため、DP は可能な限り食品の選択を強制する必要があります。 このような状態の遷移は、単一の実行可能なアクション パスに事実上崩壊します。 

もう 1 つのエッジケースは、バッテリー容量がすでにいっぱいである場合です。 バッテリ検索アクションでは、状態空間を誤って増加させるのではなく、余分なバッテリ ゲインを無視する必要があります。 トランジションでは正確さを確保するためにクランプを使用します。 

最後の微妙なケースは、食物の確率がゼロの場合です。 そのシナリオでは、食糧に依存するいかなる戦略も不可能となり、DP は時間の経過とともに飢餓の制約を満たすことができない州に生存確率ゼロを正しく割り当てます。
