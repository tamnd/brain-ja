 ## 解決策
 ## 問題の理解

 ライブラリには 1 から N までのすべての整数が含まれています。各整数は、その素因数を減少しない順序で記述することによって正規形式に変換されます。 次に、整数はこれらの因子シーケンスの辞書編集順に並べられ、各クエリは、この新しい順序で指定された位置にどの整数が現れるかを尋ねます。 

たとえば、数字の 12 は次のようになります。`[2,2,3]`、15 は`[3,5]`。 の最初の要素以来、`[2,2,3]`の最初の要素より小さいです`[3,5]`, 12が先に出てきます。 特別な数 1 には空の因子シーケンスがあり、空のシーケンスは空でないすべてのシーケンスよりも小さいため、常に 1 が最初になります。 

制約が非常に大きいため、すべての因子シーケンスを直接生成してすべての数値を並べ替えることは現実的ではありません。 N が 10^6 に達すると、大量の比較を伴う O(N log N) 付近のアプローチは Python ではすでに危険であり、解決策は線形に近いものでなければなりません。 クエリの数も多いため、順序を再計算して各クエリに答えることは不可能です。 注文は一度準備する必要があります。 

重要なエッジケースは、辞書編集上の異常な順序から生じます。 シーケンスは同じ要素で始まる長いシーケンスよりも小さいため、すべての拡張子の前に数値を指定する必要があります。 たとえば、入力の場合```
5 5
1
2
3
4
5
```その因子シーケンスが空であるため、順序は 1 から始まります。 残りの注文は、`[2]`、`[2,2]`、`[3]`、`[5]`、出力を与える```
1
2
4
3
5
```最初の素因数のみを比較する不注意な実装では、より大きな素数で始まるすべての数値の後に誤って 4 が配置されます。 

もう 1 つのよくある間違いは、要素の減少を許可することです。 12 の数列は次のとおりです。`[2,2,3]`、 ない`[3,2,2]`。 トラバーサルで大きな素数の後に小さな素数が許可される場合、無効な正規形式が作成されます。 たとえば、係数の減少を許可するトラバーサルでは、12 が 3 の子として誤って処理され、その後に 2 が続き、順序が変更される可能性があります。 

## アプローチ

 直接的なアプローチは、すべての整数の素因数シーケンスを計算し、N 個のシーケンスをすべて保存し、辞書編集的な比較を使用して数値を並べ替えることです。 必要な順序はこれらのシーケンスの順序とまったく同じであるため、これは正しいです。 問題はコストです。 最大 100 万個のシーケンスが存在する可能性があり、ソート中に長いシーケンスを比較すると、合計作業量が利用可能な制限を大幅に超える可能性があります。 

有益な観察は、標準形式が自然にトライを形成するということです。 ノードは素因数の接頭辞を表し、これも数値です。 たとえば、パス```
1 -> 2 -> 4 -> 12
```因子の接頭辞を表します```
[]
[2]
[2,2]
[2,2,3]
```このトライの深さ優先探索により、必要な辞書編集順序が正確に得られます。 シーケンスはその拡張子よりも小さいため、現在の番号はその子の前にアクセスされます。 次の素因数の昇順で子供たちが訪問されます。 

多くのエッジを保存する必要があるトライ全体を構築する代わりに、子を直接生成できます。 数値が現在の値 x を持ち、次の因数が素数インデックス i から選択される場合、すべての子は次のようになります。`x * prime[j]`のために`j >= i`。 現在のプライム インデックスを DFS に渡すと、非減少係数が自動的に適用されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 配列の比較に応じて O(N log N) またはそれより悪い | O(N log N) | 遅すぎる |
 | DFS 生成を試す | O(N + トラバーサル オーバーヘッド) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ふるいを使用して、N までのすべての素数のリストを作成します。 すべてのトライ ノードの子は辞書編集順に処理する必要があるため、走査には昇順の素数が必要です。 
2. 空の因子シーケンスを表すルートから深さ優先検索を開始します。 ルートは数値 1 に対応するため、回答順序に追加される最初の要素になります。 
3. 番号 x での DFS 中に、子を探索する前に、結果の順序に x を追加します。 これは、シーケンスが同じプレフィックスを持つすべての長いシーケンスの前に来るというルールを処理します。 
4. 許可される最小の素数インデックスから始めて、すべての素数 p を試します。 もし`x * p`最大 N、再帰的にアクセスします`x * p`同じ素数が再度使用される可能性があるため、同じ素数インデックスを維持します。 
5. 完全な順序付け配列を保存します。 その後、すべてのクエリに直接インデックスを作成して答えることができます。 

機能する理由: DFS は事前注文でトライを訪問します。 trie ノードは 1 つの正準因数シーケンスを表し、その子はそのシーケンスを 1 つの素因数で拡張する有効なすべての方法を表します。 Preorder では、短い等しいプレフィックスが最初に来るため、辞書順に一致して、ノードをその子孫の前に配置します。 素数の次数を増やして子を処理すると、最初の異なる因子の比較と一致します。 すべての整数には 1 つの非減少素因数分解があるため、すべての数値は 1 回だけ表示されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())

    sieve = bytearray(b'\x01') * (n + 1)
    if n >= 0:
        sieve[0] = 0
    if n >= 1:
        sieve[1] = 0

    primes = []
    for i in range(2, n + 1):
        if sieve[i]:
            primes.append(i)
            if i * i <= n:
                sieve[i * i:n + 1:i] = b'\x00' * (((n - i * i) // i) + 1)

    order = []

    sys.setrecursionlimit(1000000)

    def dfs(x, start):
        order.append(x)
        limit = n // x
        for i in range(start, len(primes)):
            p = primes[i]
            if p > limit:
                break
            dfs(x * p, i)

    dfs(1, 0)

    ans = []
    for _ in range(q):
        k = int(input())
        ans.append(str(order[k - 1]))

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```ふるいは、トラバーサルに必要な順序付き素数リストを作成します。 DFS 構造ではすでに有効な因数分解が保証されているため、すべての数値の最小の素因数を格納する必要はありません。 

再帰関数は現在の数値をすぐに保存し、可能な拡張子を調べます。 パラメータ`start`は、まだ選択できる最小の素数のインデックスです。 通過`i`の代わりに`i + 1`などの要因が繰り返されるため、必須です。`[2,2,2]`有効です。 

乗算チェックは次のように行われます。`limit = n // x`テストの代わりに`x * p <= n`繰り返し。 これにより、不必要な大きな中間値が回避され、境界条件が明確になります。 

最後の配列は内部で 0 から始まるインデックスを使用するため、クエリ位置`k`と答えられます`order[k - 1]`。

| 現在の番号 | 許可される次の素数インデックス | アクション | これまでのご注文 |
 | --- | --- | --- | --- |
 | 1 | 0 | 1 を追加 | 1 |
 | 2 | 0 | 2を追加 | 1,2 |
 | 4 | 0 | 4 を追加 | 1,2,4 |
 | 8 | 0 | 8を追加 | 1、2、4、8 |
 | 6 | 1 | 6を追加 | 1,2,4,8,6 |
 | 10 | 2 | 10 を追加 | 1,2,4,8,6,10 |
 | 3 | 1 | 3 を追加 | 1,2,4,8,6,10,3 |
 | 9 | 1 | 9を追加 | 1,2,4,8,6,10,3,9 |
 | 5 | 2 | 5 を追加 | 1,2,4,8,6,10,3,9,5 |
 | 7 | 3 | 7を追加 | 1,2,4,8,6,10,3,9,5,7 |

 これは、2 の子孫が 3 に移動する前に完了していることを示しています。`[2]`で始まるすべてのシーケンスよりも小さい`[3]`。 

より小さな例としては、次のようになります。```
5 5
1
2
3
4
5
```| 現在の番号 | 理由 | これまでのご注文 |
 | --- | --- | --- |
 | 1 | 空のシーケンスが最小です | 1 |
 | 2 | root の最初の子 | 1,2 |
 | 4 | 拡大`[2,2]`前に来る`[3]`| 1,2,4 |
 | 3 | 次のルートの子 | 1、2、4、3 |
 | 5 | 最後に残った子 | 1,2,4,3,5 |

 これにより、プレフィックス ルールが確認されます。 数字の 4 は 3 の前に表示されるため、`[2,2]`より小さい最初の因子から始まります`[3]`。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N + トラバーサル オーバーヘッド) | 各数値は 1 回生成され、各 DFS エッジは 1 つの素因数の加算に対応します。 |
 | スペース | O(N) | 回答配列には、数値ごとに 1 つの整数が格納されます。 |

 最大 N は 100 万であるため、順序を保存することが可能です。 トラバーサルでは、大規模なコレクションのソートが回避され、生成されたトライ構造に比例した作業のみが実行されます。

 ## 特殊なケース

 空の因子シーケンスの場合:```
1 1
1
```DFS はルートから開始され、すぐに 1 を記録します。制限内にある間は素数を乗算できないため、子はありません。 答えは 1 です。 

素因数が繰り返される場合:```

1
2
