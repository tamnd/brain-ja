 ## 問題の理解

 3 桁の数字を操作するように求められます。電話をかけます。`a`、`b`、 そして`c`それぞれの範囲は 0 から 9 です。タスクは、これら 3 つの数字の中から、合計が少なくとも 10 になるように別の 2 つの数字を選択できるかどうかを判断することです。これを繰り返します。`t`独立したテストケース。 そのようなペアが存在する場合、出力は単純な「YES」になり、考えられる 3 つのペアのいずれも合計が 10 に達しない場合は「NO」になります。 

制約は非常に小さく、各桁は最大 9 で、最大 1000 のテスト ケースがあります。 つまり、テスト ケースごとにペアが 3 つしかないため、テスト ケースごとに考えられるすべてのペアをチェックするソリューションでも高速になります。`(a, b)`、`(a, c)`、`(b, c)`。 3 つのペアと 1000 のテスト ケースを乗算すると、操作は 3000 しか得られず、時間制限をはるかに下回ります。 

注目に値するエッジケースには、すべての桁が小さい場合などがあります。`0 0 0`。 合計が 10 になるペアがないため、正しい出力は「NO」です。同様に、たとえば、すべての桁が大きい場合も同様です。`9 9 9`の場合、どのペアの合計も 18 になるため、答えは「YES」になります。 微妙なエッジとは、次のように 2 つの数字が境界線にある場合です。`1 9 0`-ここでは 1 ペアのみ`(1, 9)`条件を満たしています。 不注意なコードでは、ペアの数を数え間違えたり、同じ要素を 2 回合計しようとしたりして、間違った答えが返される可能性があります。 

## アプローチ

 ブルートフォースアプローチは簡単です。 各テスト ケースについて、考えられる 3 つの数字のペアをすべて検討し、それらの合計が少なくとも 10 であるかどうかを確認します。いずれかのペアが基準を満たす場合は、「YES」を出力します。 それ以外の場合は「NO」を出力します。 すべての組み合わせを検査するため、これは正しいことですが、一般に、入力セットが大きい場合、すべてのペアを検査するのは非効率的になる可能性があります。 3 つの要素に関しては、ブルート フォースは自明のことながら高速です。 

もう少し洗練されたソリューションの重要な洞察は、3 つのペアの合計をチェックするだけでよいということです。`(a + b)`、`(a + c)`、`(b + c)`。 これが機能するのは、条件が対称的でペアのみに依存し、要素が 3 つしかないため、これら 3 つの合計があらゆる可能性をカバーするためです。 並べ替えやより高度なデータ構造は必要ありません。 チェックはインラインで実行できるため、非常にシンプルで読みやすい実装になります。

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る`t`。 
2. 各テスト ケースについて、3 つの整数を読み取ります。`a`、`b`、 そして`c`。 
3. 考えられる 3 つのペアの合計を計算します。`a + b`、`a + c`、 そして`b + c`。 
4. これらの合計のいずれかが 10 以上であるかどうかを確認します。 
5. 少なくとも 1 つの合計が基準を満たす場合、「YES」を出力します。 それ以外の場合は「NO」を出力します。 

機能する理由: このアルゴリズムは、個別の数字のすべてのペアをチェックします。 この問題では、**任意のペア**の合計が 10 に達するかどうかのみを問うため、3 つのペアすべてをカバーすれば十分です。 これら 3 つを超える隠れたケースはないため、結果が正しいことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    a, b, c = map(int, input().split())
    if a + b >= 10 or a + c >= 10 or b + c >= 10:
        print("YES")
    else:
        print("NO")
```コードは最適なアルゴリズムを直接実装します。 私たちが使用するのは`sys.stdin.readline`高速入力のため、これは次の場合にさらに重要になります。`t`大きいです。 各テスト ケースは独立して処理され、条件は単純な論理 OR ステートメントで評価され、すべてのペアがチェックされることが保証されます。 使用する`>= 10`境界を正しくキャプチャできるようになります。 テスト ケースを読み取る以上のループはないため、複雑さは最小限に抑えられます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = []
    t = int(input())
    for _ in range(t):
        a, b, c = map(int, input().split())
        if a + b >= 10 or a + c >= 10 or b + c >= 10:
            output.append("YES")
        else:
            output.append("NO")
    return "\n".join(output)

# Provided samples
assert run("5\n8 1 2\n4 4 5\n9 9 9\n0 0 0\n8 5 3\n") == "YES\nNO\nYES\nNO\nYES", "sample 1"

# Custom cases
assert run("2\n0 0 0\n9 9 1\n") == "NO\nYES", "edge min and max"
assert run("1\n5 5 5\n") == "YES", "all equal and sum >= 10"
assert run("1\n1 2 3\n") == "NO", "all small numbers"
assert run("1\n0 9 1\n") == "YES", "boundary pair"
```| テスト入力 | 期待される出力 | 検証内容 |

 | 0 0 0 | いいえ | 最小桁、ペアなし ≥ 10 |

 ## 特殊なケース

 このアルゴリズムは、すべての桁がゼロであるというエッジ ケースを処理します。 入力`0 0 0`結果は合計 0、0、0 になります。基準を満たすものがないため、出力は「NO」になります。 最大桁数の場合`9 9 9`、すべての合計は 18 となり、「YES」となります。 次のような境界条件の場合`1 9 0`、それは正しく識別します`(1, 9)`ペアリングして「YES」を出力します。 アルゴリズムは 3 つの可能なペアすべてを明示的にチェックするため、すべての非自明なシナリオがカバーされます。
