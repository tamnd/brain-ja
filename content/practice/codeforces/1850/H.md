 ## 解決策
 ## 問題の理解

 各兵士には数直線上の整数の座標を割り当てる必要があり、複数の兵士が同じ座標を共有することができます。 すべての制約は 2 人の兵士を接続し、彼らの位置間の正確な符号付き距離を指定します。 フォームの制約`(a, b, d)`兵士の座標を強制します`a`兵士の座標と等しい`b`プラス`d`。 

タスクは、このようなすべての方程式を同時に満たす整数の割り当てがすべての兵士に存在するかどうかを判断することです。 

これは基本的に、各エッジが固定オフセットを持つ無向グラフに対する差分制約のシステムです。 重要な課題は、制約がサイクルを形成する可能性があり、サイクルの周りの暗黙の合計がゼロに打ち消されるかどうかに応じて、サイクルが一貫しているか矛盾しているかのいずれかになることです。 

入力サイズにより、テスト ケースごとに線形または線形に近い解が強制されます。 すべてのテスト ケースにわたるソルジャーの総数は最大 2×10^5 であるため、ノードごとにエッジを複数回再訪問したり、完全なペアごとの整合性チェックを試みたりするソリューションは、制限時間を超えることになります。 これにより、ブルートフォース割り当ての試行や、ノードごとに最初から緩和を繰り返すことが排除されます。 

複数の独立したパスが同じノードのペア間で異なる暗黙的な差異を定義する場合、微妙な失敗のケースが発生します。 たとえば、推測すると`x1 - x2 = 3`一本の道から、そして`x1 - x2 = 5`他の制約と直接矛盾する制約がない場合でも、システムは矛盾しています。 エッジのローカルな一貫性をチェックするだけの単純なアプローチでは、これを見逃してしまいます。 

もう 1 つの故障モードは、制約が合計がゼロ以外のサイクルを形成する場合です。 例えば、`1 -> 2 -> 3 -> 1`重り付き`+2, +2, -5`開始ノードに戻ると暗黙の値が変わるため、矛盾が生じます。 

## アプローチ

 直接的な試みは、座標を 1 つずつ割り当てて、制約を前方に伝播することです。 未割り当てのノードから開始して、その位置を任意にゼロに設定し、DFS または BFS を使用して、制約を使用して到達可能なすべてのノードを割り当てることができます。 すでに値を持つノードを割り当てようとすると、一貫性がチェックされます。 

この伝播が機能するのは、すべての制約が線形かつ加算的であるためです。そのため、接続コンポーネント内の 1 つのノードが固定されると、他のすべてのノードがそれに関連して決定されます。 この問題は、複数のパスが同じノードに異なる値を割り当て、不一致が明らかになった場合に発生します。 

それぞれの制約をエッジとして考えると`(b -> a)`重さで`d`、 意味`x[a] = x[b] + d`の場合、すべての接続コンポーネントは、すべての値がグローバル オフセットまで定義されるシステムになります。 唯一起こり得る失敗は、サイクルが非ゼロの合計を生成する場合です。その場合、ノードは強制的に 2 つの異なる値に等しくなるためです。 

これにより、問題は、重み付けされたグラフの各連結成分が一貫しているかどうかをチェックすることになります。 これは、ノード値を追跡しながら DFS を使用するか、潜在的な差異のある DSU を使用して行うことができます。 ポテンシャルを備えた DSU は特にクリーンです。各ノードは親とその親に対する相対オフセットを保存し、パス圧縮により一貫性が維持され、迅速な矛盾チェックが可能になります。 

2つのノードをマージする場合`a`そして`b`制約あり`x[a] = x[b] + d`、それらのセットを統合し、相対的な差異が以前に確立された構造と一致することを確認します。 両方のノードがすでに同じセット内にある場合は、暗黙的な差分が次と等しいかどうかを単純に検証します。`d`。 それ以外の場合は、ルート間の必要なオフセットをマージして記録します。

 ## アルゴリズムのチュートリアル

 DSU を使用します。各ノードは`x`2 つの情報を保持します: 共用体構造内の親と潜在的な情報です。`diff[x]`を表す`x[x] - x[parent[x]]`。 

1. 各ノードをポテンシャルゼロの独自の親として初期化します。 これにより、すべてのノードが制約が適用されない独立したコンポーネントとして開始されます。 
2. 関数を定義する`find(x)`パス圧縮を実行すると同時にポテンシャルを更新します。`diff[x]`常に正しい累積差分をルートに反映します。 
3. 関数を定義する`union(a, b, d)`強制するという意味`x[a] = x[b] + d`。 の根を計算します`a`そして`b`。 それらが異なる場合は、一方の根をもう一方の根に接続し、方程式が有効なままになるようにそのポテンシャルを設定します。 
4. もし`a`そして`b`すでに同じルートを共有している場合、保存されたポテンシャルによって暗示される差が等しいかどうかをチェックすることで一貫性を検証します。`d`。 そうでない場合は、そのシステムは不可能であると即座に判断します。 
5. すべての制約を処理します。 矛盾がなければ「YES」を出力し、矛盾がなければ「YES」を出力します。 それ以外の場合は「NO」を出力します。 

重要な考え方は、すべてのノードがその DSU ルートを基準とした相対的な位置を保存するということです。 2 つのノードが統合されると、それらの間の正確な制約が保存され、将来のすべてのクエリが以前のすべてのクエリと一貫性を保つことが保証されます。 

### なぜ効果があるのか

 どの時点でも、各 DSU コンポーネントは部分的に構築されたソリューションを表しており、すべてのノードがそのルートに対して明確に定義された座標を持っています。 同じコンポーネント内の 2 つのノードを接続する制約は、この相対構造と一致している必要があります。 すべてのマージではコンポーネントが結合された時点で一貫性が強制されるため、入力自体に合計重みがゼロ以外のサイクルが含まれていない限り、その後の操作でそのコンポーネント内に矛盾が生じる可能性はありません。 DSU は、同一コンポーネント制約が等価性チェックに失敗したときに、その状況を正確に検出します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n + 1))
        self.diff = [0] * (n + 1)

    def find(self, x):
        if self.parent[x] != x:
            px = self.parent[x]
            root = self.find(px)
            self.diff[x] += self.diff[px]
            self.parent[x] = root
        return self.parent[x]

    def get(self, x):
        self.find(x)
        return self.diff[x]

    def union(self, a, b, d):
        ra = self.find(a)
        rb = self.find(b)

        if ra == rb:
            return (self.get(a) == self.get(b) + d)

        # attach ra under rb
        self.parent[ra] = rb
        # we need: x[a] = x[b] + d
        # x[a] = diff[a] + x[ra], x[b] = diff[b] + x[rb]
        # so diff[ra] + x[ra] = diff[b] + x[rb] + d
        # since x[ra] becomes child of rb:
        self.diff[ra] = self.get(b) + d - self.get(a)
        return True

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        dsu = DSU(n)
        ok = True

        for _ in range(m):
            a, b, d = map(int, input().split())
            if not dsu.union(a, b, d):
                ok = False

        print("YES" if ok else "NO")

if __name__ == "__main__":
    solve()
```DSU 構造は、親ポインター ツリーと、各ノードがその親からどれだけ離れているかを格納する差分配列を維持します。 の`find`この関数はパス圧縮を実行して差分を蓄積するため、呼び出し後に各ノードはルートまでの距離を直接知ることができます。 

の`union`function は制約が強制される唯一の場所です。 2 つのノードがすでに接続されている場合、既存の暗黙の距離が新しい制約と一致するかどうかがチェックされます。 それらが別々の場合、一方のコンポーネントのルートを他方のコンポーネントの下に接続し、方程式が正確に成り立つようにオフセットを設定します。 

微妙な点は、パス圧縮後にすべての差異をルートを基準にして更新する必要があることです。 の式の正しさは、`union`に依存します`get(x)`完全に解決されたルート距離を返すため、両方の`a`そして`b`を通じてクエリされます`find`マージ オフセットを計算する前に。

 ## 特殊なケース

 重要なエッジ ケースは、同じペア間で制約が繰り返されることです。 DSU は、再度マージするのではなく、整合性をチェックすることでこれを処理します。 同じ方程式が 2 回提示された場合、2 番目の出現では何も変更されるべきではなく、共用体チェックによってその式が合格することが保証されます。 

もう 1 つのエッジ ケースは、間接パスによる自己一貫性です。 直接的な矛盾が存在しない場合でも、サイクルによって不一致が強制される可能性があります。 DSU は、ノードがすでに同じコンポーネント内にあり、新しい制約が評価される場合にのみこれを検出し、不整合を明らかにする等価性チェックをトリガーします。
