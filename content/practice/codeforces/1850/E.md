 ## 解決策
 ## 問題の理解

 各テスト ケースは正方形の画像のコレクションを記述します。 すべての画像の辺の長さ$s_i$大きめの正方形のボール紙の上に置きます。 ボール紙は均一な幅のフレームを形成します$w$画像の周囲だけでなく、画像自体の背後の領域もカバーします。 つまり、1枚の絵に使用されるボール紙の辺の合計は、$s_i + 2w$、その面積は$(s_i + 2w)^2$。 

すべての写真にわたって、ボール紙の総面積はこれらの個々の正方形の合計であり、この合計は次のように与えられます。$c$。 タスクは未知の整数を回復することです$w$、それを知って$w \ge 1$そして有効な解決策が保証されているということです。 

制約により、ソリューションは次の方向に進みます。$O(n)$または$O(n \log n)$テストケースごとに。 まで$2 \cdot 10^5$合計画像、可能なすべてを反復しようとする方法$w$値を指定したり、負荷の高い式を候補ごとに繰り返し再計算したりすると失敗します。 重要な難点は、$c$と同じ大きさにすることができます$10^{18}$したがって、中間計算では 64 ビット演算を安全に使用する必要があります。 

微妙な特殊なケースは、式の二次成長から生じます。 単純なアプローチでは、次の線形性が想定される可能性があります。$w$ただし、展開により両方に依存する交差項が生成されます。$s_i$そして$w$それらを無視すると、誤った集計が行われます。 

たとえば、誰かが各領域を次のように誤ってモデル化した場合、$s_i^2 + 2ws_i$、彼らは$4w^2$写真ごとの用語。 入力時$n=1, s_1=3, w=2$、正しい領域は次のとおりです。$7^2 = 49$ですが、線形化された式では次のようになります。$9 + 12 = 21$、これは明らかに間違っています。 

もう一つの失敗例は、単調性に気づかずに二分探索を試みた場合に発生します。 総面積は厳密に次のように増加するため、$w$が増加すると関数は単調になりますが、実装が正しくないと、非効率的に合計が再計算されることが多く、TLE が発生します。 

## アプローチ

 ブルートフォースのアイデアは簡単です。可能なすべての値を試してください。$w$、段ボールの合計面積を計算し、それが等しいかどうかを確認します。$c$。 候補者ごとに$w$を合計します$(s_i + 2w)^2$全体$i$。 以来$w$大きくなる可能性があるため、最初にそれをバインドする必要があります。 

合理的な最大値$w$すべてが$s_i$小さいし、$c$大きいです。 それぞれの用語が次のように成長するため、$4w^2$、推定します$w$くらいまで$10^9$。 この範囲までのすべての値を試すことは不可能であり、各チェックにコストがかかります$O(n)$、全体的に複雑になります$O(n \cdot 10^9)$、それは限界をはるかに超えています。 

重要な観察は、総面積が次の単調関数であるということです。$w$。 式を展開すると次のようになります。$$\sum (s_i + 2w)^2 = \sum s_i^2 + 4w \sum s_i + 4nw^2$$これは二次関数です$w$。 定数を一度計算してから、次のように解くことができます。$w$関数は厳密に増加しているため、二分探索によって$w \ge 1$。 それぞれの評価は、$O(1)$、問題は大きな整数範囲にわたる対数検索に軽減されます。

 ## アルゴリズムのチュートリアル

 1. 入力配列から 2 つの集計値 (すべての合計の合計) を計算します。$s_i$、およびすべての合計$s_i^2$。 これらにより、あらゆる領域の総面積を評価できるようになります。$w$すべての要素を反復することなく。 
2. 関数を定義する$F(w)$これは、展開された式を使用して段ボールの総面積を返します。$$F(w) = \sum s_i^2 + 4w \sum s_i + 4nw^2$$この関数は、完全な構成を一定時間で評価します。 
3. 二分探索範囲を設定します。$w$。 下限は 1 です。上限は、次のような大きな値に安全に設定できます。$10^9$、 以来$c$せいぜい$10^{18}$そして関数は二次関数的に増大します。 
4. 二分探索を実行します。$w$。 各中間点について$mid$、計算する$F(mid)$。 もし$F(mid) < c$、本当の$w$より大きくする必要があるため、左側の境界を上に移動します。 それ以外の場合は、右側の境界を下に移動します。 
5. 境界が収束するまで続けます。 最終的な値は最小値になります$w$そのような$F(w) \ge c$。 この問題は有効な解決策を保証しているため、これは正しい解決策と同じになります。$w$。 

### なぜ効果があるのか

 機能$F(w)$正の先行係数を持つ 2 次多項式です$4n$したがって、すべての人にとって厳密に増加しています$w \ge 0$。 これにより、バイナリ検索で正しい解がスキップされることがなく、検索空間が小さすぎる値と十分に大きい値に正しく分割されることが保証されます。 ソリューションの一意性は、厳密な単調性から生じます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, c = map(int, input().split())
        s = list(map(int, input().split()))

        sum_s = 0
        sum_sq = 0
        for x in s:
            sum_s += x
            sum_sq += x * x

        def F(w):
            return sum_sq + 4 * w * sum_s + 4 * n * w * w

        lo, hi = 1, 10**9

        while lo < hi:
            mid = (lo + hi) // 2
            if F(mid) < c:
                lo = mid + 1
            else:
                hi = mid

        print(lo)

solve()
```この実装では、各二分探索ステップが定数時間になるように、前処理と評価が分離されています。 Python では 64 ビット整数の使用が暗黙的に行われますが、低レベル言語では主なリスクは、$w^2$期間と累計額。 

二分探索条件には次のものを使用します。$F(mid) < c$これにより、現在の構成が厳密に小さすぎる場合にのみ正しく移動することが保証されます。 これにより、複数の中間値が理論的にオーバーシュートする可能性がある場合でも、正確さが維持されます。

 ## 特殊なケース

 重要なエッジケースは、次のような場合です。$s_i$は同一です。 そのような状況では、機能は特にスムーズになり、「推測」するという素朴な試みが必要になります。$w$単一の画像からの作成は、集約効果を無視するため失敗します。 アルゴリズムは前処理後の個々の要素に依存しないため、これを正しく処理します。 

もう 1 つのエッジケースは次のような場合です$n=1$。 方程式は単一の二次方程式に帰着します。$(s_1 + 2w)^2 = c$、これは直接平方根解を求める可能性があります。 二分検索は、特別な大文字と小文字を区別せずにこれを適切に処理します。 

大きな値$c$近く$10^{18}$ストレス整数演算。 二乗項$4nw^2$32 ビットの制限をすぐに超える可能性がありますが、Python の任意精度によりオーバーフローが回避されますが、C++ ではまさにこれが問題となります。`long long`が義務化される。 

単調な構造により、$w$が非常に大きい場合、ルートを明示的に計算したり、浮動小数点精度の問題を処理したりする必要がなく、検索は収束します。
