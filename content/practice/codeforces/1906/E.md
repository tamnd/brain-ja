 ## 解決策
 ## 問題の理解

 Merge Sort に似たルーチンのマージ ステップをリバース エンジニアリングするように求められますが、工夫が必要です。2 つの入力配列はソートされない可能性があります。 具体的には、単一の配列を受け取ります`C`長さの`2*N`～からのすべての整数を含む`1`に`2*N`まさに一度。 私たちのタスクは、それを 2 つの配列に分割することです`A`そして`B`長さの`N`それぞれ、標準のマージ ルーチンを実行すると、`A`そして`B`、再構築します`C`。 そのような分割が存在しない場合は、次のように出力する必要があります。`-1`。 

ここで重要なのは、マージ アルゴリズムを生の形式で理解することです。マージ アルゴリズムは常に、最初に残っている要素を比較します。`A`そして`B`そして小さい方を結果に追加します。 いつ`A`または`B`が空の場合は、他の配列の残りの要素を追加するだけです。 配列はソートされていない可能性があるため、「小さい方」チェックにより、アルゴリズムは、他方の配列の方が大きい場合にどちらかの配列を効果的に選択できます。 これは、私たちの仕事はソートではなく、生成された可能性のある有効なインターリーブを見つけることであることを意味します。`C`この比較ルールによって。 

与えられた`N`合計の長さは 1000 までです。`C`これは、O(N²) 演算を行うアルゴリズムはほとんど合格する可能性がありますが、著しく悪いアルゴリズムはタイムアウトになることを意味します。 この問題には、微妙なエッジ ケースもあります。つまり、前の要素がたまたま小さい場合、マージ アルゴリズムは一方の配列を他方の配列よりも「優先」する可能性があります。 たとえば、分割するような素朴なアプローチ`C`相対値を考慮せずに均等に計算すると、失敗する可能性があります。 例えば、`C = [2, 1, 4, 3]`に分割することはできません`A`そして`B`前半を素朴に代入するとマージルールが機能するようになります。`A`そして2番目に`B`。 

## アプローチ

 ブルートフォースアプローチは簡単ですが、非効率的です。 可能なすべてのパーティションを試すことができます`C`2 つの長さの配列に分割`N`そしてマージをシミュレートします。 がある`binomial(2N, N)`パーティションは、たとえ`N=20`、したがってこれは不可能です`N=1000`。 

重要な洞察は、ソートされていないバージョンのマージ アルゴリズムでは、マージがその配列から選択されるたびに、各配列が要素の減少シーケンスを維持することのみを必要とするということです。 より具体的には、次の要素が現れるたびに、`C`すでに割り当てられているすべての要素よりも大きい`A`または`B`、その配列の最後に配置できます。 要素が両方の候補配列の最後の要素より小さい場合、その要素はマージ プロセスに違反せずにどちらかの配列に入ることができません。 この観察により、問題は貪欲な分割: プロセスに集約されます。`C`の最後の要素を維持しながら左から右へ`A`そして`B`、そして、各新しい要素を最後の要素よりも大きい配列に割り当てます (または空の配列を開始します)。 どちらも機能しない場合は、出力します`-1`。 

別のビューは、処理することです`C`減少する要素の連続した「ブロック」を取得することによって。 このような各ブロックは、出現順に単一の配列に割り当てることができます。 これにより、ブロックが減少してもマージが時期尚早に他の配列から選択されることがないため、マージ アルゴリズムが要素を正しい順序で取得することが保証されます。 次にブロックを交互に割り当てます。`A`そして`B`両方の配列を指定した長さまで埋めるには`N`。 この欲張りブロックのアプローチは、各ブロックがマージ ルーチンと互換性のあるローカル順序を維持するため機能します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2N は N * N を選択) | O(N) | 実現不可能 |
 | 貪欲なブロック割り当て | O(N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 2 つの空の配列を初期化します。`A`そして`B`そして空の`current_block`リスト。 最後に処理された要素を追跡し、`last = infinity`。 
2. 各要素を反復処理する`x`で`C`。 もし`x > last`、それは新しい減少ブロックの始まりを示します。 現在のブロックをブロックのリストに追加してリセットします`current_block`。 次に追加します`x`に`current_block`そして更新します`last = x`。 
3. 繰り返した後、最後のブロックをブロックのリストに追加します。 
4. ブロックを交互に割り当てます。`A`そして`B`順番に。 1 つの配列が長さを超える場合`N`、それは不可能です。 出力`-1`。 ブロックによって配列が長くなる場合は、`N`、到達するために必要な数の要素のみを割り当てます。`N`残りの要素を他の配列に移動します。 
5. 割り当て後、両方の場合`A`そして`B`正確に長さを持っている`N`を出力します。 それ以外の場合は出力`-1`。 

これが機能する理由: 各ブロックは厳密に減少しており、マージ中にそのブロックの要素が割り当てられている配列から連続して選択されることが保証されます。 ブロックを交互に配置することで、どちらの配列もマージ比較によって順序どおりに要素を提供することが「強制」されることがなくなります。 マージ ルーチンは各配列の先頭のみを考慮し、減少するブロックは先頭に最大の要素があるため、比較では常に元の結果が得られます。`C`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

N = int(input())
C = list(map(int, input().split()))

blocks = []
current_block = []
last = float('inf')

for x in C:
    if x > last:
        blocks.append(current_block)
        current_block = []
    current_block.append(x)
    last = x
if current_block:
    blocks.append(current_block)

A, B = [], []
toggle = True  # alternate assignment

for block in blocks:
    if toggle:
        if len(A) + len(block) > N:
            remaining = N - len(A)
            A.extend(block[:remaining])
            B.extend(block[remaining:])
        else:
            A.extend(block)
    else:
        if len(B) + len(block) > N:
            remaining = N - len(B)
            B.extend(block[:remaining])
            A.extend(block[remaining:])
        else:
            B.extend(block)
    toggle = not toggle

if len(A) == len(B) == N:
    print(' '.join(map(str, A)))
    print(' '.join(map(str, B)))
else:
    print(-1)
```このソリューションでは、最初に厳密に減少するブロックを抽出します。`C`。 これにより、マージ アルゴリズムが 1 つの配列から連続して処理するセグメントがキャプチャされます。 交互の割り当てが完了します`A`そして`B`配列の長さの制限を尊重しながら。 境界の処理は微妙です。ブロックが大きすぎて 1 つの配列に収まらない場合は、ブロックを複数の配列に分割します。`A`そして`B`超過を避けるために`N`。 これがないと、次のようなエッジケースが発生します。`C = [5,4,3,2,1,6,7,8]`失敗する可能性があります。 

## 実用的な例

 **サンプル 1**:`C = [3,1,4,5,2,6]`| ステップ | 現在のブロック | 最後 | ブロック |
 | --- | --- | --- | --- |
 | 3 | [3] | 3 | [] |
 | 1 | [3,1] | 1 | [] |
 | 4 | [4] | 4 | [[3,1]] |
 | 5 | [4,5] | 5 | [[3,1]] |
 | 2 | [2] | 2 | [[3,1],[4,5]] |
 | 6 | [2,6] | 6 | [[3,1],[4,5]] |

 ブロック:`[[3,1],[4,5],[2,6]]`交互に割り当てます:`A = [3,1,2]`、`B = [4,5,6]`の合併`A`そして`B`再現する`C`。 

**サンプル 2**:`C = [1,2,3,4]`要素ごとに 1 つの減少ブロック:`[[1],[2],[3],[4]]`交互に割り当てます:`A = [1,3]`、`B = [2,4]`マージの結果`[1,2,3,4]`希望どおりに。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N) | ブロックの作成には 1 つのパス、配列への割り当てには 1 つのパス。 |
 | スペース | O(N) | ブロックと 2 つの配列 A と B を格納します。 

と`N <= 1000`、アルゴリズムは、1 秒の制限時間内で最大数千の操作を実行します。
