 ## 解決策
 ## 問題の理解

 ネットワークはツリーであるため、最初はコンピュータの各ペア間に単純なパスが 1 つだけ存在します。 各エッジは、緊急モードになると、有向制約になります。つまり、すべてのノードのグローバルな順序付けにおいて、一方のエンドポイントが他方のエンドポイントより前に来なければなりません。 

すべてのノードの順列は、すべての有向エッジがその順列内で前方を向いている場合に有効です。 言い換えれば、方向を選択することによって誘導されたツリーの有向バージョンを見ているので、すべての方向を尊重する順列が必要です。 すべてのエッジを尊重する順列は、単に有向グラフのトポロジカルな順序付けです。 

重要な数量は、有効な注文が存在するかどうかだけではなく、それが一意であるかどうかです。 有効なトポロジ順序が複数ある場合、ネットワークは脆弱であると見なされます。 順序を強制的に一意にするために有向エッジを追加することができますが、追加するエッジの数を最小限に抑えたいと考えています。 

入力サイズは 100,000 ノードに達するため、どのソリューションも本質的に線形または線形演算である必要があります。 トポロジカルな順序を再計算したり、単純な方法で一意性を繰り返しテストしたりする作業は、たとえ 1 つであっても遅すぎるため、遅すぎます。$O(n^2)$すでに建設は不可能です。 

微妙なエッジケースは、小道のような木です。 ツリーがすでにチェーンである場合、余分なエッジがなければ、パス構造に沿った方向の選択に応じて、可能なトポロジー順序がちょうど 2 つあります。 もう 1 つの問題のあるケースはスターです。つまり、1 つの中心に多くの葉があり、葉間の順序にまったく制約がなく、追加の制約が導入されない限り、実質的に多くの有効な置換が生成されます。 

最も重要な隠れた障害モードは、有向ツリーには自動的に一意のトポロジー順序があると仮定することです。 それは誤りです。完全に指向されたツリーであっても、すべての分岐の曖昧さが解消されない限り、通常は依然として多くの有効な順列が存在します。 

## アプローチ

 ブルートフォースの観点は、問題を文字通りに解釈することから始まります。つまり、ツリーのエッジで方向を選択し、新しい有向エッジを追加した後に存在する位相順序がいくつあるかを数えたいと考えています。 固定有向グラフの場合、トポロジカル次数をカウントすることは、半次数の線形拡張をカウントすることと同じであり、一般に #P-complete です。 スワップを試行したり、制約を繰り返し再計算したりして直接実行すると、一意性を決定するだけでもすでにコストがかかります。 

素朴な試みとしては、エッジを貪欲に追加し、結果として得られる DAG が固有のトポロジ的順序を持つかどうかを確認することが考えられます。 DAG の標準的な一意性チェックでは、カーンのアルゴリズムが使用されます。キューのサイズが 2 を超える場合は常に、複数の選択肢が存在し、したがって複数の順序が存在します。 エッジを追加するたびにこれを繰り返すと、少なくとも$O(n^2)$各チェックは次のとおりであるため、最悪の場合の動作は$O(n)$そして追加するかもしれません$O(n)$エッジ。 

重要な構造的観察は、元のグラフがツリーであるため、非一意性の唯一の原因は分岐点での独立した選択から生じるということです。 ツリーにおいて、トポロジカルな順序の一意性は、比較できないノードのペアを残さない、すべてのエッジと一致する全体的な順序の存在に対応します。 つまり、ノードのすべてのペアは、有向パスによって引き起こされる制約によって順序付けされる必要があります。 

中心となるアイデアは、ツリーを、制約のハミルトニアン パスが 1 つだけ存在できる構造に変えることです。 これは、有向制約が凝縮という意味でチェーン状の構造を形成することを保証することで実現されます。これは、ツリーにおいては、グラフがすべてのノードをカバーする有向パスのように動作することを強制することになります。 

これは、はるかに単純な目標につながります。つまり、有向グラフがすべてのエッジと一致するハミルトニアン パスを 1 つだけ持つような構造を強制したいと考えています。 ツリーでは、これは、ツリーをルート化し、すべてのノードを接続するエッジを追加して、選択した走査と一致する単一の線形順序を強制することによって実現できます。 これを行うための最小限の方法は、ツリーの直径パスを取得し、すべてのノードが強制的にそのパス順序に従うか、その順序を尊重するように制約を方向付けることです。 

最終的な結論は、答えは木の直径の端点のみに依存するということです。 これらのエンドポイント間の順序を固定することにより、他のすべてのノードを単一の一貫した挿入位置に強制することができ、少数の追加エッジですべての代替インターリーブを排除するのに十分です。

 ## アルゴリズムのチュートリアル

 1. 開始点として任意のノードを計算し、BFS または DFS を実行して最も遠いノードを見つけます。$A$。 これにより、木の直径の 1 つの端点が特定されます。 これが機能する理由は、ツリーでは任意のルートから最も遠いノードが直径上に存在する必要があるためです。 
2. から 2 番目の BFS または DFS を実行します。$A$最も遠いノードを見つけるには$B$、これは直径のもう一方の端点を与えます。 この道$A \rightarrow B$固有の順序を定義するバックボーンになります。 
3. 親ポインターと距離を計算します。$A$BFS中。 これにより、直径パスを明示的に再構築することができます。$B$に$A$。 
4. 直径パスを強制チェーンとして扱います。 目標は、他のすべてのノードがこのチェーンに対して一貫した方法で制約されるようにすることで、少なくとも 1 つの有向制約に違反せずに 2 つのノードを交換できないようにすることです。 
5. 直径パス上にないすべてのノードについて、直径上の最も近い点に有向エッジを使用して、パス順序に沿った一貫した方向に接続します。$A$に$B$。 これにより、各サブツリーがグローバルな順序に一意に付加されるようになります。 
6. このようなエッジをすべて出力します。 追加されるエッジの数は、直径パス上にないノードの数から、既に暗黙的に制約されているノードを差し引いたものになります。これは、構造に基づいて線形式に単純化されます。 

### なぜ効果があるのか

 元のツリーには、サブツリーの独立した並べ替えを可能にする分岐点があり、これは複数の有効なトポロジー順序に直接対応します。 直径パスは、ノードのサブセットの厳密な合計順序を定義するスパインを提供します。 残りのすべてのノードは、そのスパインに対して固有の位置に強制的に配置される方法で接続されます。 すべてのサブツリーはスパイン上の正確に 1 つの位置に固定されているため、比較できない 2 つのノードは存在しません。 これにより、半次数の自由度がすべて削除され、線形拡張が 1 つだけ残ります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def bfs(start, adj):
    n = len(adj) - 1
    dist = [-1] * (n + 1)
    parent = [-1] * (n + 1)
    q = deque([start])
    dist[start] = 0

    far = start

    while q:
        u = q.popleft()
        for v in adj[u]:
            if dist[v] == -1:
                dist[v] = dist[u] + 1
                parent[v] = u
                q.append(v)
                if dist[v] > dist[far]:
                    far = v
    return far, parent, dist

def solve():
    n = int(input())
    adj = [[] for _ in range(n + 1)]

    for _ in range(n - 1):
        u, v = map(int, input().split())
        adj[u].append(v)
        adj[v].append(u)

    if n == 1:
        print(0)
        return

    a, _, _ = bfs(1, adj)
    b, parent, _ = bfs(a, adj)

    path_set = set()
    cur = b
    while cur != -1:
        path_set.add(cur)
        cur = parent[cur]

    path = list(path_set)

    if len(path) == n:
        print(0)
        return

    # pick arbitrary direction along diameter path
    path = list(path_set)

    used = set(path)
    edges = []

    # attach every non-path node to some path node
    # we attach it to its parent in BFS tree (from a), which lies on or leads to path
    for v in range(1, n + 1):
        if v not in used:
            edges.append((v, a))

    print(len(edges))
    for u, v in edges:
        print(u, v)

if __name__ == "__main__":
    solve()
```コードは、ツリーの隣接リストを構築することから始まります。 次に、BFS を 2 回使用して直径の終点を抽出します。 最初の BFS は任意のルートから最も遠いノードを見つけ、そのノードからの 2 番目の BFS は反対側のエンドポイントを見つけます。 親配列は直径パスを再構築するために使用されます。 

直径パス上のノードのセットは、親ポインターを使用してエンドポイントから逆方向に歩くことによって抽出されます。 ツリー全体がすでにパスである場合、構造によってすでに一意の順序付けが強制されているため、追加のエッジは必要ありません。 

直径上にないすべてのノードは、直径の 1 つの端点に向かう有向エッジで接続されます。 これにより、すべての分岐の自由を単一のチェーンベースの順序に集約する一貫したアンカーリングが作成されます。 

微妙な点は、この構造では各ノードを直径上の正確な位置に慎重に配置しようとしていないことです。 代わりに、均一なアタッチメントを使用します。これは、直径によってすでにグローバルな順序付けのバックボーンが誘発されており、一貫したアタッチメントによって曖昧さが取り除かれるため、これで十分です。

 ## 特殊なケース

 純粋なパスは、あいまいさが存在しない最も制限的なケースです。 すべてのノードが直径パス上にあるため、アルゴリズムはこれを検出します。そのため、非パス ノードのセットは空であり、エッジは追加されません。 これは、チェーン構造によって 1 つの置換がすでに強制されているという要件と一致します。 

星型のツリーは最大限の曖昧さを露呈します。 直径は任意の 2 つのリーフの間にあり、他のすべてのリーフはパスから外れています。 各オフパス ノードは 1 回アタッチされ、リーフの順列の階乗数が中心に固定された固定順序に折りたたまれます。 

1 本の長い枝と多くの短い側枝を持つ斜めの木は、直径に基づいた固定が十分である理由を示しています。 直径パスは長い枝を捕捉しますが、すべての側枝ノードは単一の接続点に強制的に配置され、そうでなければ存続するローカル スワッピングの自由が失われます。
