 ## 解決策
 ## 問題の理解

 私たちは、巨大なサイズのグリッドでプレイされる 2 人用ゲームを分析するように求められています。$10^9 \times 10^9$。 各セルは黒または白のいずれかになります。 最初だけ、$N$特定のセルは黒で、その他はすべて白です。 プレイヤーは順番に黒いセルを選択します。 細胞のとき$(r, c)$からのセルの長方形領域が選択されます。$(1,1)$まで$(r,c)$が切り替わります: 黒のセルが白になり、白のセルが黒になります。 黒マスがなくなって動けなかったプレイヤーが負けとなります。 私たちのタスクは、両方が最適にプレイしたと仮定して、最初のプレーヤーが勝つかどうかを判断することです。 

入力は$N$に続く$N$整数のペア$(R_i, C_i)$最初の黒いセルを説明します。 出力は、最初のプレイヤーが勝った場合は単純に「FIRST」、そうでない場合は「SECOND」になります。 

グリッド サイズにより、直接シミュレーションが不可能になります。 と$N$まで$2 \cdot 10^5$、グリッド全体の状態を維持したり、大きな長方形を単純に切り替えたりすることはできません。 単一セルに対する各操作は次のとおりです。$O(1)$ただし、四角形内の影響を受けるすべてのセルを更新するには、最大で次の作業が必要になる可能性があります。$10^9 \cdot 10^9$操作。 明らかに、グリッドをシミュレートせずに勝者を計算するには、組み合わせの洞察に依存する必要があります。 

エッジケースには、複数の黒セルが小さい座標の行または列を共有する場合が含まれます。 たとえば、次のセル$(1,1)$それ自体のみを切り替え、セルは$(2,3)$を切り替えます$2 \times 3$矩形。 切り替えルールを誤解すると、すべての黒セルが独立しているという誤った仮定につながる可能性がありますが、これは真実ではありません。 

## アプローチ

 ブルート フォース アプローチでは、グリッドの状態を保存し、黒いセルを繰り返し、四角形を切り替え、交互にターンするというゲームのシミュレートを試みます。 各トグルは長方形の面積に比例し、最大で$10^9 \times 10^9$。 と$N=2\cdot 10^5$、総当たり攻撃には天文学的な時間がかかり、明らかに実行不可能です。 

重要な洞察は、組み合わせゲーム理論から得られます。 このゲームは **Nim** のマルチパイル版に似ています。 黒セルの「値」を次のように定義すると、$(r, c)$として$r \oplus c$、セルを選択してその四角形を切り替えることは、サイズの Nim パイルを削除することに対応します。$r \oplus c$。 XOR 演算が発生するのは、トグル パターンが小さな長方形内の一連の独立したサブゲームとして解釈できるためです。また、スプラーグ グランディの定理により、長方形のグランディ数は次のようになります。$(r, c)$は$r \oplus c$。 これにより、問題はすべての XOR の計算に減ります。$(R_i \oplus C_i)$初期の黒セル用。 XOR がゼロ以外の場合、最初のプレーヤーが勝利戦略を持っています。 それ以外の場合、2 番目のプレーヤーは勝つために最適にミラーリングできます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(N * min(R_i, C_i)^2) | O(10^9 * 10^9) | 遅すぎる |
 | XOR / Nim リダクション | O(N) | お(1) | 承認済み |

 XOR アプローチは次の理由により実現可能です。$N$せいぜい$2 \cdot 10^5$これにより、入力を単一パスで通過できるようになります。 

## アルゴリズムのチュートリアル

 1. 変数を初期化する`nim_sum`ゼロに。 これにより、黒のセルに対応するすべてのグランディ数値の XOR が累積されます。 
2. 座標の各黒セルについて$(R_i, C_i)$、計算する`R_i ^ C_i`そしてそれをXORします`nim_sum`。 これはボード全体の累積 Nim 値を表します。 
3. すべてのセルを処理した後、次のことを確認します。`nim_sum`はゼロです。 そうであれば、ボードは最初のプレイヤーにとって負けている Nim の位置にあるため、2 番目のプレイヤーが強制的に勝利します。 もし`nim_sum`がゼロでない場合、最初のプレイヤーはいつでも Nim 合計をゼロに減らす動きをすることができ、最終的には勝利を強制されます。 
4. 次の場合は「FIRST」を出力します。`nim_sum`ゼロ以外の場合は「SECOND」です。 

なぜ機能するのか: それぞれの黒いセルは$(r, c)$サイズの独立した Nim パイルとして機能します`r ^ c`。 XOR 和はすべての山の組み合わせをエンコードしており、標準的な組み合わせゲーム理論では、XOR 和がゼロの場合、プレーヤーが移動するのは損失であることが保証されます。 これにより、ゲームのダイナミクスを正しくモデル化しながら、巨大なグリッドの切り替えのシミュレーションを完全に回避できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    N = int(input())
    nim_sum = 0
    for _ in range(N):
        r, c = map(int, input().split())
        nim_sum ^= (r ^ c)
    print("FIRST" if nim_sum != 0 else "SECOND")

if __name__ == "__main__":
    main()
```コードは黒セルの数とその座標を読み取ります。 次の XOR を計算します。`r ^ c`各セルに対して実行中の XOR を維持します。`nim_sum`。 最終的な XOR により勝者が決まります。 重要な詳細は使用しています`^`XOR を使用し、大規模なグリッドをシミュレートする試みを回避します。

## 特殊なケース

 厄介なエッジケースは、すべてのセルが対角線上にある場合です。`(k, k)`。 このような各セルは、`r ^ c = 0`、 それで`nim_sum = 0`。 黒マスが多くても先手が勝つことはできません。 アルゴリズムは XOR を正しく計算し、「SECOND」を出力します。 もう 1 つの微妙なケースは、セルが最大許容座標にある場合です。 32 ビット整数を使用するとオーバーフローする可能性がある`r ^ c`, ただし、Python の整数は任意のサイズを処理できるため、この実装は安全です。 

のために`(1,1)`単独では、最初のプレーヤーは自分自身をトグルする以外に何もすることができず、これは負けのポジションになります。 アルゴリズムは正しく「SECOND」を出力します。 

このアプローチは、Sprague-Grundy 数値を直接エンコードし、グリッドをシミュレートせずに正確さを保証するため、すべてのエッジ ケースを処理します。
