 ## 解決策
 ## 問題の理解

 凸正多角形が与えられます。$N$側面。 各面$i$含まれています$A_i$その辺の境界セグメントに沿って均一に配置された特別な点。 サイドが分かれているので、$A_i + 1$等間隔の場合、これらの点はポリゴンの境界上にある離散化された頂点のように機能します。 

タスクは、3 つの同時制約を使用して、これらの特別な点を 3 つ選択して三角形を形成することです。 各特別な点は最大 1 回使用でき、すべての三角形はゼロ以外の面積を持つ必要があり、2 つの三角形が部分的にでも交差することは許可されません。 目標は、そのような三角形の数を最大化することです。 

制約は、ソリューションを線形または線形に近い動作に近づけます。$N$、 以来$N$到達できる$2 \cdot 10^5$そしてそれぞれ$A_i$と同じ大きさにすることができます$2 \cdot 10^9$。 すべての点を明示的に反復するアプローチは不可能です。なぜなら、点の総数は管理可能な合計によっても制限されず、各辺を独立して処理しても、演算は次のように比例するからです。$A_i$、それは不可能です。 

微妙な困難は、私たちが実際にユークリッド空間内の点の座標を操作しているわけではないことを理解することにあります。 ジオメトリは凸多角形の境界によって制約され、交差しない三角形のパッキングが周期構造に沿った間隔分割のように動作するように強制されます。 

貪欲に各辺内で独立して三角形を形成しようとすると、素朴な間違いが発生します。 たとえば、一方の辺に多くの点があり、もう一方の辺にはほとんど点がない場合、各辺で局所的に最適な三角形をペアリングすると、交差を避けてパッキング密度を最大化するために三角形が辺をまたがる必要があることが無視されます。 もう 1 つの間違った考え方は、すべてのトリプルが三角形を形成するため、これを「任意の 3k 点を選択する」ものとして扱うことです。 これは、交差制約がすべての選択肢をグローバルに結合しているため、失敗します。 

正しいアプローチでは、境界点を循環境界上の非交差トリプルにグループ化する方法を推論する必要があります。 

## アプローチ

 ジオメトリのことを少し忘れると、問題は次のようになります。エッジ上にグループ化された点の循環シーケンスがあり、各トリプルが交差しない三角形に対応するように、できるだけ多くのトリプルを分割したいと考えています。 

ブルートフォース解釈では、トリプルのすべてのサブセットを列挙し、有効な非交差三角形を形成しているかどうかを確認し、最大カーディナリティのサブセットを取得します。 これは組み合わせ的に爆発的です。 幾何学的検証を無視したとしても、互いに素なトリプルを選択する方法は数多くあります。$M$ポイントは次のとおりです$O(M!)$構造上、そして$M$それ自体は合計で明示的に制限されていません。 このアプローチはすぐに無効になります。 

重要な構造的洞察は、ポリゴンの境界がすべての点の循環的な順序付けを引き起こすということです。 このサイクルに沿ってすべての特別な点を配置すると、すべての有効な三角形は、サイクルを 3 つの円弧に分割する 3 つの頂点を選択することに対応し、非交差は層状構造を意味します。三角形は凸多角形の非交差弦のように動作します。 

問題は、エッジごとの多重度を持つ循環シーケンス上の互いに素な非交差トリプルの数を最大化することに帰着します。 重要な観察は、ポイントは等間隔であり、サイド内の再配置は異なるサイドにわたる交差構造に影響を及ぼさないため、サイド内の正確な位置ではなく、サイドごとのカウントのみが重要であるということです。 

それぞれの側面を解釈することができます$i$貢献するとして$A_i$利用可能な「トークン」。 各三角形は 3 つのトークンを消費しますが、実現可能性はトークンがサイクル全体でどのように分散されるかによって決まります。 制限要因は、交差を強いる不一致ポイントの残りを避けるために、ポリゴン全体で寄与のバランスをどの程度均等にできるかということになります。 

最適な戦略は貪欲なバランス プロセスに変わります。サイクルに沿ってポイントを蓄積し、連続する辺に十分な「余剰」があるときは常に三角形を形成し、将来のブロックを回避する方法で常にできるだけ早く三角形を閉じるようにします。 

これは、側面を横断しながら累積的な不均衡を追跡し、可能な限り 3 つのグループを貪欲に抽出することでモデル化できます。

 ## アルゴリズムのチュートリアル

 現在「利用可能」だが三角形でまだ使用されていない点の数を維持しながら、多角形の辺を順番に処理します。 

1. カウンタを初期化する`carry = 0`これまでに蓄積された未使用のポイントを表します。 
2.初期化`ans = 0`形成された三角形の数。 
3. 各辺を反復処理します。$i$1から$N$、追加$A_i$に`carry`。 
4.いつでも`carry >= 3`、現在のプールからできるだけ多くの三角形を形成し、増加します。`ans += carry // 3`、更新します`carry = carry % 3`。 
5. すべての面が処理されるまで続けます。 

この貪欲な抽出の背後にある理由は、三角形の形成を不必要に延期しない限り、利用可能な 3 つの境界点のセットは常に交差を強制することなく非縮退三角形に配置できるということです。 グループ化を遅らせると局所的な密度が高まるだけで、次のチームが新たな得点を追加したときにクロスを強制される危険性がある。 

### なぜ効果があるのか

 重要な不変条件は、処理後の側面です。$i$つまり、連続するグループ間に 2 つ以上の不一致点を残さない限り、交差を導入することなく、それらの相対位置を常に境界上に埋め込むことができます。 どの三角形も正確に 3 点を消費するため、残りを最大 2 に維持することで、将来の有効なグループ化を妨げる強制的な部分構造が蓄積されなくなります。 貪欲な抽出では、利用可能な点が 3 つあるたびに、その使用を遅らせても後で三角形の数を増やすことができないため、最大限のパッキングが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    A = list(map(int, input().split()))

    carry = 0
    ans = 0

    for x in A:
        carry += x
        ans += carry // 3
        carry %= 3

    print(ans)

if __name__ == "__main__":
    solve()
```実装は蓄積のアイデアに直接従っています。 変数`carry`できるだけ早く三角形を貪欲に形成した後、未使用の点がいくつ残っているかを表します。 整数の除算`carry // 3`各ステップで抽出できる三角形の数をカウントし、残りを前方に伝播します。 

微妙な点は、実際のポイント位置を保存したり、ジオメトリをシミュレートしたりすることは決してないことです。 正しさは、残りの構造に関して 3 を法とする合計カウントのみが重要であるという事実に完全に依存しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from sys import stdout
    out = io.StringIO()
    sys.stdout = out

    n = int(sys.stdin.readline())
    A = list(map(int, sys.stdin.readline().split()))

    carry = 0
    ans = 0
    for x in A:
        carry += x
        ans += carry // 3
        carry %= 3

    return out.getvalue().strip() if out.getvalue() else str(ans)

# minimum case

# all equal large-small mix
assert run("3\n2 2 2\n") == "2"

# edge: no triangles
assert run("3\n1 1 1\n") == "1"

# skewed distribution
assert run("5\n10 0 0 0 0\n") == "3"

 ## 特殊なケース

 まれなケースは、すべての点が単一の側にある場合に発生します。次に例を示します。```
N = 3
A = [10, 0, 0]
```アルゴリズムにより 10 ポイントが蓄積されます。`carry`、3 つの三角形が生成され、残り 1 が残ります。これは、すべての点が 1 つのエッジ上にあるとしても、それらは依然として凸多角形の有効な境界点であり、それらが区別できる限り、どのトリプルも有効な三角形を形成するという事実と一致するため、最大値は Floor(10/3) になります。 

もう 1 つの微妙なケースは、値がすべて 1 の場合です。```
A = [1, 1, 1, 1]
```累積により、最初の 3 つの寄与から正確に 1 つの三角形が生成され、未使用の点が 1 つ残り、別の三角形を形成できません。 貪欲なプロセスは、トリプルが使用可能になった後にグループ化を延期しないため、過剰なカウントを防ぎます。
