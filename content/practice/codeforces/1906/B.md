 ## 解決策
 ## 問題の理解

 それぞれオンまたはオフのランプの列と、ランプごとに 1 つのボタンの列があります。 各ボタンは、そのすぐ隣のランプにのみ影響します: ボタンを押す$i$ランプを切り替えます$i-1$そして$i+1$、存在する場合。 面白いのは、対応するランプが現在点灯している場合にのみボタンを押すことができるということです。 タスクは、初期のランプ構成を変換するために有効なボタンを押すシーケンスが存在するかどうかを判断することです。$A$ターゲット構成に$B$。 

入力は複数のテスト ケースを提供し、それぞれに多数のランプ/ボタンが付いています。$N$初期およびターゲットのランプ状態は 0 と 1 の文字列として表されます。 変換が可能であれば出力は「YES」、それ以外の場合は「NO」でなければなりません。 

境界により許可されるのは、$N$最大 200,000、テスト ケース全体の合計も 200,000 に制限されます。 これにより、直ちにあらゆることが排除されます$O(N^2)$各テスト ケースが大きくなる可能性があり、複数の入れ子になったループが時間制限を超える可能性があるためです。 テスト ケースごとに線形または線形に近いソリューションが実現可能です。 

エッジ ケースには、ボタンを押すことができないためすべてのランプが最初にオフになっている場合や、ランプを変更する必要があるが、隣接するボタンが使用可能またはアクティブになっていない場合が含まれます。 例えば、$A = 000$、$B = 010$中央のランプは隣接するボタンを押さないと切り替えることができず、隣接するランプがオンになっている必要があるため、これは不可能です。 

## アプローチ

 ブルート フォース ソリューションは、有効なボタンの押し方の可能なすべてのシーケンスをシミュレートします。 ランプごとに$i$ボタンを押してみることもできます$i-1$そして$i+1$可能な限りターゲットに合わせて。 原理的には正しいですが、シーケンスの数は次のように指数関数的に増加します。$N$、したがって、これはたとえ小さなものであっても実用的ではありません$N$。 もし$N$は 200,000 です。単純なシミュレーションでは、$2^{200000}$ステップ。 

重要な点は、ボタンを押すとその隣のボタンにのみ影響するということです。 したがって、問題は、適切なタイミングで押すと隣接するランプを反転できる少なくとも 1 つのランプの存在をチェックすることになります。 具体的には、インデックスのランプ$i$隣接するもののうちの 1 つを押すことによって間接的にのみ反転でき、その隣接するもの自体がオンになっている必要があります。 したがって、最初にオンになっているランプが少なくとも 1 つと、最初にオフになっているランプが少なくとも 1 つ存在するかどうかを確認するだけで済みます。 これにより柔軟性が保証されます。建設的な動きを使用して、近隣を切り替えて任意の目標状態に到達できます。 逆に、最初にすべてのランプがオンであるか、すべてがオフである場合は、プレス ルールに違反せずにランプを選択的に切り替える方法がないため、一部のターゲット構成に到達できない可能性があります。 

この洞察により、問題は 1 と 0 の数を数えるというものに集約されます。$A$ターゲットかどうかを確認します$B$均一な初期状態では不可能な変更が必要です。

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る$T$。 
2. 各テスト ケースについて、次の内容を読んでください。$N$、$A$、 そして$B$。 
3. もし$A$に等しい$B$を押す必要がないため、すぐに「YES」を出力します。 
4. かどうかを確認します。$A$contains at least one 0 and at least one 1.
 5. 両方が存在する場合は、「YES」を出力します。これは、積極的にボタンを押して近隣を切り替え、到達できるためです。$B$。 
6. もし$A$すべて 0 またはすべて 1 で構成されているかどうかを確認してください$B$マッチ$A$。 そうでない場合は、「NO」を出力します。 それ以外の場合は「YES」を出力します。 

これが機能する理由: 不変の条件は、オンとオフのランプが混在している限り、隣接するランプを押すことによって間接的に切り替えることができるということです。 すべてのランプが均一である場合、一部の切り替えが不可能になり、特定の目標状態に到達できなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        N = int(input())
        A = input().strip()
        B = input().strip()

        if A == B:
            print("YES")
            continue

        has_zero = '0' in A
        has_one = '1' in A

        if has_zero and has_one:
            print("YES")
        else:
            print("NO")

if __name__ == "__main__":
    solve()
```このソリューションでは、最初に自明な等価性がチェックされ、不必要な計算が回避されます。 の`has_zero`そして`has_one`flags は、建設的な切り替えに必要な最小限のプロパティをキャプチャします。 次のような境界条件$N = 3$または$N = 200,000$チェックは線形であるため、自然に処理されます。$N$。

 ## 特殊なケース

 最初にすべてのランプがオフで、ターゲットが少なくとも 1 つのランプのオンを必要とする場合、アルゴリズムは正しく NO を出力します。 のために`A = 0000`そして`B = 0010`、`has_zero`それは本当ですが、`has_one`は False であるため、コードは予想どおり NO を返します。 

最初にすべてのランプがオンで、ターゲットが少なくとも 1 つのランプをオフにする必要がある場合、コードは NO を返します。`has_zero`は偽であり、`has_one`は本当です。 

初期状態がターゲットと正確に一致する場合、アルゴリズムは等しいことを検出し、たとえ大きな値であっても直ちに YES を出力します。$N$。 

これらのチェックにより、境界や均一状態のシナリオが間違った結果を生成しないことが保証されます。
