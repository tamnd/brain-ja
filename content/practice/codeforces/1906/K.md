 ## 解決策
 ## 問題の理解

 各カードは 3 つの状態のいずれかになる可能性があります。 

カードは自分のデッキに入れることも、友達のデッキに入れることも、完全に破棄することもできます。 

あなたのデッキの XOR を次のようにします。`X`そして友達のデッキの XOR は次のようになります。`Y`。 次のように、これら 3 つの状態に割り当てられたカードの数を数えなければなりません。`X = Y`。 

最初の観察は、条件を書き直すことです。 

2 つのデッキは独立しているため、使用されるすべてのカードは、次のいずれかに正確に貢献します。`X`または`Y`。 したがって$$X \oplus Y$$どちらかのプレイヤーが使用したすべてのカードの XOR です。 

条件`X = Y`と同等です$$X \oplus Y = 0.$$したがって、次のように表すと、$U$少なくとも 1 人のプレイヤーが使用するカードのセットであれば、必要なのは$$\bigoplus_{i\in U} A_i = 0.$$一度そのようなセットが$U$内のすべてのカードが選択されます$U$どちらのプレイヤーにも独立して割り当てることができます。 それが生み出す$$2^{|U|}$$異なるデッキペア。 

問題は次のようになります。$$\sum_{\text{subset }U,\ \operatorname{xor}(U)=0} 2^{|U|}.$$制約があるからこそ、問題は面白くなります。 まであります$10^5$したがって、サブセットを明示的に列挙するアルゴリズムは不可能です。 値が満たされている$A_i \le 100000$これは、すべての値が 17 ビット内に収まることを意味します。 これは、XOR をベクトル空間上の演算として扱うことを強く示唆しています。$(\mathbb Z_2)^{17}$。 

よくある間違いは、XOR 値のみが重要であると考え、係数を忘れることです。$2^{|U|}$。 例えば：```
2
1 1
```ゼロ XOR サブセットは次のとおりです。`{}`、`{1,2}`。 それらの重みは$1$そして$4$、答えを与える$5$。 サブセットのみをカウントすると、誤って生成される$2$。 

もう 1 つの簡単な間違いは、デッキへのカードの割り当てを直接数えてから、両方のデッキの XOR を追跡しようとすることです。 のために```
2
1 1
```有効な割り当ては次のとおりです。```
discard, discard
S, T
T, S
S&T together impossible
both in S
both in T
```上記の加重サブセットの解釈と一致する、有効な結果は 5 つあります。 

3 番目の落とし穴は、すべての値が線形独立である場合に発生します。```
2
1 2
```唯一のゼロ XOR サブセットは空のサブセットであるため、答えは次のようになります。`1`。 すべての XOR 値が同じ頻度で現れると仮定するアプローチは、ここでは失敗します。 

## アプローチ

 ブルートフォースの解決策は簡単です。 

すべてのサブセットについて$U$、その XOR を計算します。 XOR がゼロの場合は、次のように加算します。$2^{|U|}$答えに。 これは正しいです。使用する各カードをどちらかのデッキに個別に割り当てることができるからです。 

問題は、$2^N$サブセット。 と$N=100000$、サブセットの数は天文学的に多くなります。 

代わりに、小さな値の範囲を利用する必要があります。 

重要な観察は、XOR が 17 ビットのベクトル空間に存在するということです。 させて$M = 2^{17}$。 カードごとに$A_i$、群代数要素を定義します$$f_i = e_0 + 2e_{A_i}.$$最初の用語を選択すると、カードが未使用であることを意味します。 2 番目の項を選択すると、カードが使用され、重みに貢献します。$2$。 

すべての係数を乗算すると、$$F=\prod_i (e_0+2e_{A_i}).$$の係数$e_x$XOR が次のとおりであるすべてのサブセットの合計重みに等しい$x$。 私たちの答えは次の係数です。$e_0$。 

これはまさに、ウォルシュ アダマール変換が XOR 畳み込みを対角化する設定です。 

キャラクターの場合$t$、$$\widehat f_i(t) = 1+2(-1)^{\langle t,A_i\rangle}.$$値は次のいずれかです$3$または$-1$。 

もし$$s_t=\sum_v \text{freq}[v]\cdot (-1)^{\langle t,v\rangle},$$それから$$\widehat F(t) = 3^{(N+s_t)/2} (-1)^{(N-s_t)/2}.$$逆ウォルシュ変換により、$$\text{answer} = \frac1M \sum_t \widehat F(t).$$現在、タスクはすべての計算に減らされています。$s_t$。 これらは、まさに周波数配列のウォルシュ アダマール変換値です。 

周波数配列には長さがあります$M=131072$したがって、1 つの FWHT にかかる費用は$$O(M\log M),$$それは約です$2.2\times10^6$操作性と簡単にフィットします。

 | 最適 |$O(2^{17}\cdot17)$|$O(2^{17})$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 周波数配列を作成する`freq`サイズの$2^{17}$。 
2. カードの価値ごとに$A_i$、増分`freq[A_i]`。 
3. Walsh-Hadamard 変換を適用します。`freq`。 

変身後は、`freq[t]`になる$$s_t = \sum_v \text{cnt}[v](-1)^{\langle t,v\rangle}.$$4. 事前計算能力$3$モジュロ$998244353$まで$N$。 
5. 変換された値ごとに$s_t$、計算する$$a=\frac{N+s_t}{2}, \qquad b=\frac{N-s_t}{2}.$$次に追加します$$3^a(-1)^b$$累計に。 
6. 最終的な合計に次の値を掛けます。$$(2^{17})^{-1} \pmod{998244353}.$$これにより、逆ウォルシュ アダマール正規化が実行され、XOR ゼロに対応する係数が得られます。 

### なぜ効果があるのか

 すべてのカードの要素$e_0+2e_{A_i}$重み付きサブセット定式化に関連する 2 つの可能性をエンコードします。 すべての係数を乗算すると、XOR 畳み込みを通じて XOR 値が累積され、次の係数が計算されます。$e_x$XOR が等しいサブセットの合計重みになります$x$。 

Walsh-Hadamard 変換は、XOR 畳み込みを点単位の乗算に変換します。 変換された各因子は次のいずれかであるため、$3$または$-1$、キャラクターでの製品$t$キャラクター値を持つカードの値が何枚あるかによってのみ決まります$+1$そして、人格的価値のあるものは何人ありますか$-1$。 これらのカウントは次によって決定されます。$s_t$。 

逆変換では、XOR 値の係数が$0$変換されたすべての値の平均です。 この係数はまさに数えるべき量です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353
BITS = 17
M = 1 << BITS

n = int(input())
freq = [0] * M

for x in map(int, input().split()):
    freq[x] += 1

h = 1
while h < M:
    step = h << 1
    for i in range(0, M, step):
        for j in range(i, i + h):
            x = freq[j]
            y = freq[j + h]
            freq[j] = x + y
            freq[j + h] = x - y
    h <<= 1

pow3 = [1] * (n + 1)
for i in range(1, n + 1):
    pow3[i] = pow3[i - 1] * 3 % MOD

ans = 0

for s in freq:
    a = (n + s) // 2
    b = (n - s) // 2

    term = pow3[a]
    if b & 1:
        term = MOD - term

    ans += term

ans %= MOD
ans = ans * pow(M, MOD - 2, MOD) % MOD

print(ans)
```周波数配列は、XOR 値によってインデックス付けされる唯一の構造です。 すべてのカード値は 17 ビットに収まるため、XOR 空間全体には正確に次の値が含まれます。$2^{17}$州。 

FWHT はインプレースで実行されます。 完了後、各位置に文字の合計が格納されます$s_t$。 これらの値はモジュール値ではなく、通常の整数です。 それらを整数として保持すると、計算時のパリティの問題が回避されます。$(N+s_t)/2$。 

表現```
if b & 1:
    term = MOD - term
```要素を実装します$(-1)^b$。 

最終的な乗算`pow(M, MOD - 2, MOD)`による除算を実行します$2^{17}$係数の下。

# helper: run solution on input string, return output string
import sys, io

def run(inp: str) -> str:
    MOD = 998244353
    BITS = 17
    M = 1 << BITS

    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n = int(input())
    freq = [0] * M

    for x in map(int, input().split()):
        freq[x] += 1

    h = 1
    while h < M:
        step = h << 1
        for i in range(0, M, step):
            for j in range(i, i + h):
                x = freq[j]
                y = freq[j + h]
                freq[j] = x + y
                freq[j + h] = x - y
        h <<= 1

    pow3 = [1] * (n + 1)
    for i in range(1, n + 1):
        pow3[i] = pow3[i - 1] * 3 % MOD

    ans = 0
    for s in freq:
        a = (n + s) // 2
        b = (n - s) // 2

        term = pow3[a]
        if b & 1:
            term = MOD - term

        ans += term

    ans %= MOD
    ans = ans * pow(M, MOD - 2, MOD) % MOD
    return str(ans) + "\n"

 ## 特殊なケース

 検討してください```
2
1 1
```有効なゼロ XOR サブセットは次のとおりです。`{}`そして`{1,2}`。 それらの重みは$1$そして$4$、答えを生み出す$5$。 各カードの生成要因は次のとおりであるため、アルゴリズムはこれを捕捉します。$e_0+2e_1$。 ウェイトはトランスフォームに直接組み込まれるため、特別な処理は必要ありません。 

考慮する```
2
1 2
```空でないサブセットには XOR ゼロはありません。 逆変換後、XOR 値 0 の係数は正確に次のようになります。$1$、空のサブセットに対応します。 このアルゴリズムは、XOR 周波数の均一性を前提としていません。 

考慮する```
3
1 2 3
```完全なサブセットには XOR があります$$1\oplus2\oplus3=0.$$答えは$$1 + 2^3 = 9.$$FWHT の定式化には、当然両方の寄与が含まれます。 空のサブセットが重みに寄与します$1$、完全なサブセットが重みに寄与します$8$。 

最後に、可能な最大の入力サイズを考慮します。$N=100000$。 アルゴリズムの実行時間は、可能なサブセットの数ではなく、17 ビット XOR 空間のみに依存します。 頻度カウントはすべての多重度を吸収し、複雑さは残ります。$O(2^{17}\cdot17)$。
