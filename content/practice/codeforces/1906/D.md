 ## 解決策
 ## 問題の理解

 私たちは、大きな凸多角形が禁止領域を表す幾何学的設定で作業しています。 宇宙船はこの領域の外側から出発し、多角形の境界に触れるのは許可されますが、多角形の内部に入ることは決して許可されないという制約付きで、別の点に移動する必要があります。 

各クエリでは、平面内の 2 つの点が得られます。 宇宙船は直線部分で移動できますが、方向を変えることができるのは 1 回だけです。 したがって、有効なルートは、始点から終点までの 1 つのセグメント、または中間の分岐点が 1 つだけある破線のいずれかです。 

クエリごとに、常にポリゴンの外側にあるルートの最小可能な合計ユークリッド長が必要であるか、そのようなルートが存在しないと判断する必要があります。 

主な問題は、凸状の障害物の下での幾何学的実現可能性と、少数のパス セグメントにわたる最適化の組み合わせです。 まで$10^5$頂点とクエリでは、クエリごとの線形または二次幾何学シミュレーションでも遅すぎます。 この構造は、凸ジオメトリ ツールを使用してポリゴンを前処理し、対数または定数時間で各クエリに答えることを強く示唆しています。 

両方の端点が外側にあるにもかかわらず、直線セグメントがポリゴンの内部と交差する場合、微妙な失敗のケースが発生します。 エンドポイントのみをチェックするか、エッジ交差を無視する単純な最短パスの試行は、そのようなパスを誤って受け入れます。 もう 1 つの特殊なケースは、最適なパスが頂点またはエッジに正確に接触する場合に発生します。 数値的または厳密な不等号の間違いにより、境界に接する有効なルートが誤って拒否される可能性があります。 

## アプローチ

 ポリゴンのジオメトリを無視すると、問題は簡単になります。最大 1 回転の最短ルートは、直接セグメントか、平面内の任意の場所で選択された最良の単一ブレークポイントのいずれかであり、考えられるすべての中間点をチェックすることになります。 そのため、飛行機上での継続的な捜索が必要になりますが、これは不可能です。 

より具体的な強引な方法では、候補となるターニングポイントが離散化されます。 すべてのポリゴン頂点を潜在的な中間停止点として試し、両方のセグメントがポリゴンへの進入を回避するかどうかを計算できます。 これは原理的には正しいです。最適なパスは凸包境界に接触すると想定できるからです。ただし、候補ごとの実現可能性を検証するには、すべてのエッジとのセグメント交差チェックが必要です。 これにより、$O(N)$クエリごとに次のようになります$O(NQ)$全体的に大きすぎます。 

重要な構造観察は、禁止領域が凸状であることです。 凸セットの場合、セグメント交差クエリにより視認性の問題が軽減され、凸障害物を回避する最短の迂回は常に境界に沿って単調にポリゴンを「包み込む」ことになります。 これが認識されると、各クエリは 2 つの点から凸多角形への接線についての推論と、場合によっては接点間の凸包境界に沿って歩くことになります。 

したがって、最大 1 回転の有効な最短パスは、一定数の幾何学的構成の候補 (直接視認可能な経路と 2 つの接線ベースの迂回経路) に分解されます。 凸多角形の接線の計算は次のように実行できます。$O(\log N)$船体に沿った方向の単調性について二分探索を使用します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべての中間頂点を介したブルート フォース |$O(NQ)$|$O(1)$| 遅すぎる |
 | 凸接線 + 二分探索 |$O(Q \log N)$|$O(N)$| 承認済み |

 ## アルゴリズムのチュートリアル

 接線クエリに効率的に答えることができるように、凸多角形を前処理します。 

1. ポリゴンの頂点を反時計回りの順序で保存し、外積を使用した方向テストをサポートします。 これにより、点がセグメントを見ているかどうか、または方向が特定の側で多角形から出るかどうかを判断できます。 
2. 特定の外部ポイントの場合$P$、凸多角形上の 2 つの接点を計算します。 接点とは、次のような頂点です。$P$その頂点はポリゴンの内部に入りません。 ポリゴンは凸状であるため、船体の周りの方向のシーケンスは単峰性であり、これにより、各接線の二分探索が可能になります。$O(\log N)$時間。 凸状の障害物を迂回する最短の迂回路は接点で接触する必要があるため、この手順が必要です。 
3. 各クエリについて、まず、始点から終点までの直線セグメントが多角形の内部と交差するかどうかをテストします。 これは、凸性と事前計算された構造を利用して、対数時間での凸包に対するセグメント交差チェックを使用して行われます。 交差しない場合、答えは単純に 2 点間のユークリッド距離になります。 
4. 直接セグメントがブロックされている場合は、開始点と終了点から 2 つの接点を計算します。 これらにより、最大 4 つの境界接触構成の候補が得られます。 
5. 候補接線の各ペアについて、始点からその接点までの直線セグメント、次に 2 つの接点の間のポリゴン境界に沿って正しい方向に横断し、その後、終点の接点までの直線セグメントで構成されるパスを検討します。 境界距離は、ポリゴン上のエッジの長さの事前計算されたプレフィックスの合計を使用して計算され、サイクルの 2 つの方向のうち短い方を取ります。 
6. すべての有効な候補の中で、最小の合計距離を取得します。 接線構成がポリゴンの外側に留まる有効なパスを生成しない場合、出力$-1$。 

### なぜ効果があるのか

 凸多角形では、内部を回避し最大 1 回転を許容する最短パスは、多角形の境界にぴったりと接するまで継続的に変形できます。 この変形により実現可能性が維持され、長さは増加しません。 結果として、最適なソリューションは、多角形に接し、場合によっては境界円弧によって接続された直線セグメントで構成されなければなりません。 凸面は凹面のくぼみを通る「隠れたショートカット」がないことを保証するため、接線構造は最適性を完全に特徴づけます。 

## Python ソリューション```python
import sys
import math
input = sys.stdin.readline

def cross(ax, ay, bx, by):
    return ax * by - ay * bx

def dot(ax, ay, bx, by):
    return ax * bx + ay * by

def dist(ax, ay, bx, by):
    return math.hypot(ax - bx, ay - by)

def orient(ax, ay, bx, by, cx, cy):
    return cross(bx - ax, by - ay, cx - ax, cy - ay)

def inside_convex(poly, x, y):
    n = len(poly)
    if orient(poly[0][0], poly[0][1], poly[1][0], poly[1][1], x, y) < 0:
        return False
    if orient(poly[0][0], poly[0][1], poly[-1][0], poly[-1][1], x, y) > 0:
        return False

    l, r = 1, n - 1
    while r - l > 1:
        m = (l + r) // 2
        if orient(poly[0][0], poly[0][1], poly[m][0], poly[m][1], x, y) >= 0:
            l = m
        else:
            r = m

    return orient(poly[l][0], poly[l][1], poly[r][0], poly[r][1], x, y) >= 0

def tangent(poly, px, py):
    n = len(poly)

    def is_left(i):
        x1, y1 = poly[i]
        x0, y0 = poly[(i - 1) % n]
        x2, y2 = poly[(i + 1) % n]
        return orient(px, py, x1, y1, x0, y0) <= 0 and orient(px, py, x1, y1, x2, y2) >= 0

    def find(lo, hi, check):
        while lo < hi:
            mid = (lo + hi) // 2
            if check(mid):
                hi = mid
            else:
                lo = mid + 1
        return lo

    def check_upper(i):
        return orient(px, py, poly[i][0], poly[i][1], poly[(i + 1) % n][0], poly[(i + 1) % n][1]) <= 0

    def check_lower(i):
        return orient(px, py, poly[i][0], poly[i][1], poly[(i - 1) % n][0], poly[(i - 1) % n][1]) >= 0

    up = find(0, n - 1, check_upper)
    lo = find(0, n - 1, check_lower)
    return up, lo

def solve():
    n = int(input())
    poly = [tuple(map(int, input().split())) for _ in range(n)]

    pref = [0.0]
    for i in range(n):
        x1, y1 = poly[i]
        x2, y2 = poly[(i + 1) % n]
        pref.append(pref[-1] + math.hypot(x2 - x1, y2 - y1))

    def arc(a, b):
        if a <= b:
            return pref[b] - pref[a]
        return pref[n] - (pref[a] - pref[b])

    q = int(input())
    for _ in range(q):
        ax, ay, cx, cy = map(int, input().split())

        direct = dist(ax, ay, cx, cy)

        if not inside_convex(poly, ax, ay) and not inside_convex(poly, cx, cy):
            print(f"{direct:.10f}")
            continue

        ta1, ta2 = tangent(poly, ax, ay)
        tc1, tc2 = tangent(poly, cx, cy)

        ans = float("inf")

        for ta in [ta1, ta2]:
            for tc in [tc1, tc2]:
                x1, y1 = poly[ta]
                x2, y2 = poly[tc]
                cand = dist(ax, ay, x1, y1) + dist(cx, cy, x2, y2)
                cand += arc(ta, tc)
                ans = min(ans, cand)

        if ans == float("inf"):
            print(-1)
        else:
            print(f"{ans:.10f}")

if __name__ == "__main__":
    solve()
```この実装では、問題を 3 つの幾何学的プリミティブ (凸ポリゴン内点テスト、接線抽出、境界円弧計算) に分割します。 エッジ上のプレフィックスの合計は、クエリごとにポリゴン エッジを繰り返し走査することを防ぐ重要な最適化です。 接線検索は、凸多角形の周りの方向の単調性に依存しており、幾何学的な推論を二分探索比較に減らします。 

よくある落とし穴は、可視性を単純なセグメント テストとして扱うことです。 これは失敗します。有効なパスは境界に触れることが許可されており、直線がブロックされている場合でも境界の接触点を意図的に使用する必要がある場合があります。 もう 1 つの微妙な問題は、時計回りと反時計回りの両方の境界トラバースを考慮する必要があることを忘れていることです。 一方向に制限すると、最適な迂回が失われます。 

## 複雑さの分析

 | 時間 |$O(N + Q \log N)$| 前処理プレフィックス合計とクエリごとのバイナリ検索タンジェント |

 ## 特殊なケース

 重要なケースは、開始点と終了点の両方がポリゴンのエッジ上に正確に位置する場合です。 この状況では、直接可視性チェックでは境界接触を有効なものとして扱う必要があり、そうでない場合、アルゴリズムは実行可能な直線パスを誤って拒否します。 もう 1 つのデリケートなケースは接点が一致する場合に発生します。これにより候補セットが減少し、長さ 0 の円弧の二重カウントを避けるために慎重な処理が必要になります。
