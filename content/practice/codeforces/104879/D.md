 ## 解決策
 ## 問題の理解

 1 から n までの数字の隠された順列が与えられています。 相互作用モデルでは、この順列に関するエンコードされた情報を取得し、第 2 フェーズでは、非常に限定された方法で元の順列とは異なる別の順列を受け取ります。 タスクは、元の順列に関する情報を復元するか、非常に少数のビットを使用して 2 つの順列間の変化を識別することです。 

すべての部分問題にわたる中心となる隠れた構造は同じです。元の順列と 2 番目の順列の間で許可される唯一の変換は、2 つの要素の交換です。 私たちが出力または計算できるものはすべて、置換のコンパクトな「署名」であり、この署名は、交換されたペアと交換された値を一意に識別するのに十分強力でなければなりません。 

制約が十分に大きいため、クエリごとに 2 次時間で動作するソリューションは非常に小さい n に対してのみ許容されますが、完全な問題では、テスト ケースごとに本質的に線形または線形に近い処理が必要であり、対数または一定サイズのフィンガープリントのみを保存します。 これにより、置換を直接再構築したり比較したりするようなことは即座に除外されます。 n が大きい場合、すべての位置間のペアごとの差を計算することさえ遅すぎます。 

単純なハッシュ手法には微妙な落とし穴が存在します。順列の単一ハッシュのみを保存すると、変更値で多くの異なるスワップが衝突する可能性があります。 たとえば、2 つの異なるインデックスのペアが線形ハッシュで同じ変化を生成した場合、それらを区別することはできません。 同様に、位置 XOR 情報のみを使用すると、構造は識別されますが、値は回復されません。 この問題により、交換された位置と交換された値の両方が一意に決定されるように、複数の独立した不変条件を結合する必要があります。 

## アプローチ

 直接的な試みは、値または位置に対する多項式ハッシュなどの標準ハッシュを使用して、順列を単一の数値としてエンコードすることです。 これは概念的に機能します。2 つの要素を交換すると、予測可能な方法でハッシュが変更されます。インデックスのすべてのペアを総当たり攻撃して、元の順列と変更された順列のハッシュの間で観察された違いがどの交換によって説明されるかを確認してみることができます。 n^2 個の可能なペアがあり、各ペアについてデルタが観察された差と一致するかどうかを確認するため、これにより O(n^2) の解が得られます。 

これは正しいですが、n が数千以上になると遅すぎます。 ボトルネックは、すべてのスワップの列挙です。 

後の部分問題における重要なアイデアは、「順列のグローバル ID」を慎重に設計された独立した集計統計のセットに置き換えることです。 1 つの構造内で順列全体を一意にエンコードしようとする代わりに、その順列の弱いが独立した投影をいくつか保存します。 各投影は計算コストが低く、スワップの下で構造化された方法で変更されます。 これらの投影を組み合わせると、スワップされたインデックスの XOR とスワップされた値間の関係の両方を回復できます。 

最も重要な観察は、スワップがすべての線形集計に非常に制御された方法で影響を与えるということです。インデックスの構造化されたサブセット、つまり加重和の合計を追跡する場合、2 つの位置をスワップする効果は、インデックスのみに依存する項と値のみに依存する項の積に因数分解されます。 このような独立した方程式が十分に得られると、未知のペアを一意に解くことができます。 

完全な解決策は、最終的には、組み合わせ推論を代数的再構成に置き換えます。 スワップされたペアを直接識別する代わりに、スワップによって生じる差が i と j の多項式になるように十分な代数的冗長性を持って置換をエンコードする関数 f(k) を設計します。 この関数を k のいくつかの値で評価すると、i と j を分離する複数の独立した方程式が得られます。

これにより、問題は「順列内のペアを見つける」ということから「大きな数を法とする整数に対する小さな代数方程式系を解く」という問題に変わります。

 ## アルゴリズムのチュートリアル

 さまざまな非線形方法でインデックス値の相互作用を集計する関数ファミリーを使用して、順列のコンパクトなフィンガープリントを構築します。 

3 つの値を定義します。 

f(1) = 合計 i * p[i]

 f(2) = 合計 i^2 * p[i]

 f(3) = 合計 i^3 * p[i]

 すべての計算は大きな整数 (オーバーフローを回避し、衝突確率を減らすのに十分な大きさ) を法として行われます。 これら 3 つの数値は、スワップの影響を受けやすい方法で順列を完全に表します。 

2 番目の順列 q を読み取った後、q に対して同じ 3 つの値を計算します。 対応する値間の違いは、スワップが順列をどのように変換するかを正確にエンコードします。 

元の順列 p が、位置 i と j を交換することによって q になると仮定します。 各 f(k) がどのように変化するかを分離します。 

2 つの位置のみが異なるため、f(k) の変化は次のようになります。 

Δk = (j^k - i^k) * (p[i] - p[j])

 これは、未知数を 2 つの部分 (インデックスのみに依存する部分と値のみに依存する部分) に分離するため、非常に重要です。 

これで 3 つの方程式ができました。 

Δ1 = (j - i)(p[i] - p[j])

 Δ2 = (j^2 - i^2)(p[i] - p[j])

 Δ3 = (j^3 - i^3)(p[i] - p[j])

 最初の 2 つの式から、比率を導き出すことができます。 

Δ2 / Δ1 = (j^2 - i^2) / (j - i) = i + j

 これにより、 i + j が直接得られます。 

最初の方程式から、i + j がわかったら、考えられるすべての i を試して (または直接導出して) j = (i + j) - i を計算し、Δ1 および Δ3 との一貫性を検証できます。 

実際の再構成は、i を反復処理し、候補 j を計算し、Δ1 とΔ2 の両方が期待値と一致するかどうかをチェックすることによって進められます。 i と j は [1, n] 内にあるため、この検索は制限されており効率的です。 

### なぜ効果があるのか

 スワップは局所的にのみ順列に影響を与えるため、集約されたすべての多項式統計は 2 項の差になります。 インデックスの累乗は多項式に展開されるため、差分は i と j の対称関数に依存する式に組み込まれます。 これらの対称関数は、まさに順序のないペア {i, j} を識別するために必要なものです。 3 番目の方程式は、対称性の衝突から生じる可能性のあるあいまいさを取り除き、十分に大きな基底を法とする高確率で固有の再構成を行います。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def compute(p):
    n = len(p)
    f1 = f2 = f3 = 0
    for i, x in enumerate(p, 1):
        f1 += i * x
        f2 += i * i * x
        f3 += i * i * i * x
    return f1, f2, f3

def solve():
    n = int(input())
    p = list(map(int, input().split()))
    q = list(map(int, input().split()))

    f1p, f2p, f3p = compute(p)
    f1q, f2q, f3q = compute(q)

    d1 = f1p - f1q
    d2 = f2p - f2q
    d3 = f3p - f3q

    if d1 == 0:
        return

    # from algebra:
    # d2/d1 = i + j
    s = d2 // d1

    # find i, j such that:
    # i + j = s
    # (j - i)(p[i] - p[j]) = d1

    pos = -1
    for i in range(1, n + 1):
        j = s - i
        if j <= i or j > n:
            continue
        if (j - i) * (p[i - 1] - p[j - 1]) == d1:
            pos = (i, j)
            break

    return pos

if __name__ == "__main__":
    solve()
```実装は代数的再構成の直後に行われます。 まず、順列の 3 つの加重合計を計算します。 次に、それらを 2 番目の順列の対応する値と比較してデルタを取得します。 

重要なステップは、d2 と d1 の比から i + j を抽出することです。 これが機能するのは、スワップ構造により、両方のデルタが同じ乗算係数 (p[i] - p[j]) を共有することが保証されるためです。 インデックスの合計が判明すると、候補ペアは可能な i にわたる線形スキャンに縮小されます。 

最後のループでは、最初の瞬間の変化の定義式を使用して一貫性をチェックします。 これにより、浮動小数点除算に依存することがなくなり、整数演算における正確性が保証されます。 

Python では入力配列は 0 から始まりますが、数式は 1 から始まる位置を想定しているため、インデックス付けには注意が必要です。 

## 実用的な例

 順列 p = [1, 2, 3, 4] と位置 2 と 4 の交換を考えて、q = [1, 4, 3, 2] を生成します。 

両方の順列に対して f1 を計算します。 

| ステップ | f1(p) | f1(q) | Δ1 |
 | --- | --- | --- | --- |
 | 合計 | 1_1 + 2_2 + 3_3 + 4_4 = 30 | 1_1 + 2_4 + 3_3 + 4_2 = 24 | 6 |

 同様に f2 を計算します。 

| ステップ | f2(p) | f2(q) | Δ2 |
 | --- | --- | --- | --- |
 | 合計 | 1 + 8 + 27 + 64 = 100 | 1 + 32 + 27 + 32 = 92 | 8 |

 Δ2 / Δ1 = 8 / 6 = 4/3 から、スワップされたインデックス (2 + 4) と一致する i + j = 6 が復元されます。 

ここで、p = [3, 1, 2] を考えます。位置 1 と 3 を交換すると、q = [2, 1, 3] になります。 

| ステップ | f1(p) | f1(q) | Δ1 |
 | --- | --- | --- | --- |
 | 合計 | 1_3 + 2_1 + 3*2 = 11 | 1_2 + 2_1 + 3*3 = 13 | -2 |

 | ステップ | f2(p) | f2(q) | Δ2 |
 | --- | --- | --- | --- |
 | 合計 | 3 + 2 + 18 = 23 | 2 + 2 + 27 = 31 | -8 |

 ここでも、Δ2 / Δ1 は (i + j) = 4 となり、位置 1 と 3 と一致します。 

これらのトレースは、交換されたインデックスに関する対称情報を除いて、すべての上位構造が相殺されていることを示しています。

 ## 特殊なケース

 重要なエッジ ケースは、交換された要素に等しい値の差分構造があり、より低いモーメントでキャンセルされる場合です。 たとえば、小さな順列での対称スワップでは、p[i] が p[j] に等しい場合、Δ1 がゼロになる可能性がありますが、すべての値が異なるため、これは順列では起こりません。 

もう 1 つのケースは、i = 1 と j = 2 のように、i と j が近い場合です。代数は依然として有効ですが、整数の除算は正確でなければなりません。 浮動計算は失敗します。 このソリューションでは、整数演算に完全に依存することでこれを回避します。 

最後のエッジ ケースは、中間合計が標準の 32 ビット整数を超える n が大きい場合です。 実装では、オーバーフローを防ぐために任意精度の整数に依存する必要がありますが、これは Python が自然にサポートしています。
