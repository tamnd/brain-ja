 ## 問題の理解

 順列が与えられています`p`これは、位置 1 から n まで固定順序で到着する値と考えることができます。 この注文を処理している間、マルチセットを維持します`A`。 ポジションを処理するたびに`i`、挿入します`p[i]`の中へ`A`。 位置の場合`i`が爆弾としてマークされている場合、現在の最大要素を直ちに削除します。`A`。 

爆弾の構成は、爆弾を配置する位置を選択するものですが、すべての位置が爆弾であるわけではないという制限があります。 すべての位置を処理した後、セットは`A`最終的には空ではなくなり、その最大要素はその構成のコストとして定義されます。 

別の順列も与えられます`q`。 の各プレフィックスに対して、`q`、それらすべての位置に爆弾を設置する必要があります。 プレフィックス長ごとに`i - 1`、他の場所に追加の爆弾を配置するすべての有効な方法における、可能な最小の最終コストを知りたいと考えています。 

タスクは、次のすべてのプレフィックスに対してこの答えを計算することです。`q`。 

主な難点は、爆弾は任意の要素を削除するのではなく、常に現在の最大値を削除することです。`A`、非ローカルな方法で以前の決定と後の決定を結合します。 

制約は次のとおりです`n = 300000`これにより、すべての爆弾構成にわたるシミュレーションや、クエリごとの繰り返しの再計算が除外されます。 どのソリューションも線形に近いか、`n log n`。 

単純なアプローチでは、各プレフィックスのプロセスをシミュレートしようとします。`q`、さまざまな追加の爆弾の配置を試します。 構成の数が指数関数的に増加するため、これはすぐに失敗します。 

2 番目の素朴なアイデアは、回答候補を修正することです`x`そして実現可能性をチェックします。 爆弾の効果は動的最大値に依存するため、そのチェックさえも簡単ではありません。 

素朴な推論を暴露するエッジ ケースには、すべての大きな値が早期に出現する構成、小さな要素の無駄な削除を爆弾に強制する構成、または必要な爆弾が含まれる場合が含まれます。`q`大きな値が表示される前に強制的に削除し、どの要素が存続できるかを変更します。 

## アプローチ

 プロセスを再解釈する便利な方法は、マルチセットの仕組みを一時的に忘れて、ボムが実際に行うことに集中することです。すべてのボムは 1 つの要素だけを削除し、常に現在存在する最大の要素を削除します。 これは、大きな値がまだ残っている場合、ボムは小さな値を削除しないことを意味します。 

ここで、位置ではなく値によってグループ化されたプロセスを考えてみましょう。 しきい値を固定するとします`x`そして、次の位置のみに注目してください。`p[i] >= x`。 これらのポジションは「重要なイベント」のように動作します。`x`最終的な最大値が少なくとも以下であるかどうかを判断するときには無関係です。`x`。 

ポジション内で`p[i] >= x`、連続したアクティブなポジションがセグメントを形成します。 セグメント内では、次の値よりも小さい値`x`表示される可能性がありますが、値が存在するかどうかには影響しません。`>= x`が最大候補として生き残る。 

重要な観察は、各セグメントが生き残る「高価値の代表」が最大 1 つであることです。 爆弾は代表を削除できますが、各爆弾はグローバルに 1 つの最大要素を正確に削除するため、爆弾ごとに 1 つだけ削除できます。 

したがって、しきい値に対して存在するセグメントの数がわかっている場合は、`x`、価値のある「生き残った候補者」が少なくとも何人いるかはわかっています。`x`すべてのキャンセル後も残ることができます。 

プレフィックスから強制爆弾を組み込むようになりました`q`。 もし持っていれば`k - 1`強制爆弾、せいぜい`k - 1`削除はすでに保証されています。 しきい値`x`すべてのセグメントが形成された後、削除されていないセグメント代表がまだ少なくとも 1 つ存在する場合、つまりセグメントの数が強制爆弾の数を超えている場合、最終的な答えとして実現可能です。 

したがって、それぞれについて`x`、位置間で形成されるセグメントの数を次のように計算します。`p[i] >= x`。 次に、どれを尋ねますか`k`このしきい値`x`有効です、つまり`segments(x) >= k`。 

クエリごとに直接答える代わりに、関係を反転します。`x`、すべてのプレフィックスを更新します`k`まで`segments(x)`考慮することで`x`答えの候補として。 これにより、範囲最大更新構造が得られます。

 ## アルゴリズムのチュートリアル

 1. 各値をマッピングする`v`の位置に`p`。 これにより、ポジションをアクティブ化する際に値を最大から最小まで処理できるようになります。 
2. Maintain a DSU over positions 1 to n. ポジションの値が現在のしきい値以上になると、そのポジションは「アクティブ」になります。 アクティブなポジションは、連続するインデックスの連結コンポーネントを形成します。 
3. 値をスイープします。`n`まで`1`。 価値を処理するとき`x`、その位置をアクティブにします。 これにより、すでにアクティブな隣接コンポーネントに接続しない限り、コンポーネントの数が 1 つ増加します。その場合、コンポーネントはマージされます。 
4. 変数を保持する`segments`アクティブな位置間の接続コンポーネントの数に等しい。 それぞれのアクティベーションが増加する可能性があります`segments`、マージするたびに減少します。 これは、しきい値に対して独立した高値ブロックがいくつ存在するかを追跡します。`x`。 
5. この値について`x`、私たちは今、どん​​な答えもそれを知っています`k`そのような`k <= segments`潜在的に持つことができる`x`最終的なコストとして。 なぜなら、`k - 1`強制削除では、すべてのセグメントの代表を削除することはできません。 
6. すべての範囲の更新を実行します。`k`で`[1, segments]`、可能な限り最良の回答を少なくとも次のように設定します。`x`。 
7. すべての値を処理した後、各インデックスが`k`最大値を保存します`x`の下で生き残ることができる`k - 1`強制爆弾、これはまさに必要な答えです。 

### なぜ効果があるのか

 値のしきい値を修正する`x`。 位置の部分配列では、`p[i] >= x`、コンポーネントの外部の要素は、より小さい値を通過せずに候補最大値をブリッジできないため、各接続コンポーネントは候補最大値を維持するという点で独立して動作します。 各コンポーネントは、すべての「最大の削除」に耐えることができる要素を最大 1 つだけ提供します。 各爆弾はちょうど 1 つのグローバル最大値を削除するため、各爆弾はそのようなコンポーネントの代表を最大 1 つ削除できます。 したがって、コンポーネントの数は、生き残ることができる高価値の候補の数になります。 最終的な最大値は少なくとも`x`少なくとも 1 つのコンポーネントがすべての強制削除で生き残る場合に限り、これは次と同等です。`segments(x) >= k`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

class DSU:
    def __init__(self, n):
        self.p = list(range(n + 1))
        self.sz = [1] * (n + 1)

    def find(self, a):
        while self.p[a] != a:
            self.p[a] = self.p[self.p[a]]
            a = self.p[a]
        return a

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return False
        if self.sz[a] < self.sz[b]:
            a, b = b, a
        self.p[b] = a
        self.sz[a] += self.sz[b]
        return True

def solve():
    n = int(input())
    p = list(map(int, input().split()))
    q = list(map(int, input().split()))

    pos = [0] * (n + 1)
    for i, v in enumerate(p, 1):
        pos[v] = i

    active = [False] * (n + 2)
    dsu = DSU(n)

    seg = 0
    best = [0] * (n + 2)

    for val in range(n, 0, -1):
        i = pos[val]
        active[i] = True
        seg += 1

        if i > 1 and active[i - 1]:
            if dsu.union(i, i - 1):
                seg -= 1
        if i < n and active[i + 1]:
            if dsu.union(i, i + 1):
                seg -= 1

        k = seg
        if k > 0:
            best[k] = max(best[k], val)

    ans = [0] * (n + 1)
    for k in range(1, n + 1):
        ans[k] = max(ans[k - 1], best[k])

    out = []
    for i in range(1, n + 1):
        out.append(str(ans[i]))
    print(" ".join(out))

if __name__ == "__main__":
    solve()
```この実装では、値のアクティブ化が単一のインデックスのアクティブ化に対応するように、まず値を位置に変換します。 DSU は、連続したアクティブなセグメントを効率的に維持します。 ポジションをアクティブにするたびに、セグメント数をインクリメントし、可能であれば隣接するポジションとマージし、結合が成功したときにセグメント数を修正します。 

配列`best[k]`可能なセグメント数ごとに、少なくともその数のセグメントを達成する最大値を収集します。 最後のプレフィックスの最大伝播は、これをすべての答えに変換します。`k`。 

微妙な点は、更新が次の時点でのみ行われることです。`best[segments]`、そして下に伝播します。 これは、値が有効な場合に機能するため、`segments = s`、それはすべての小さなものにも有効です`k`。

 ## 特殊なケース

 特殊なケースは、アクティベーションによって孤立したセグメントが繰り返し作成される場合に発生します。`p`高い値と低い値が交互に切り替わります。 この状況では、新しいそれぞれの高い値が独自のコンポーネントを形成してから、後でマージされます。 DSU ベースのセグメント カウンタは、この変動を正確に捕捉します。これは、すべてのアクティベーションがセグメント数を増やすことから始まり、その後、隣接マージによってセグメント数が減少するだけであるためです。 

別のケースは、最初の数個の強制爆弾位置が`q`の低い値に対応します`p`。 これらの初期の制約はセグメントの形成に直接影響を与えず、セグメントの形成は次の要素にのみ依存します。`p`、ただし、「消費」できるセグメントの数は制限されています。 アルゴリズムは、プレフィックス制約を通じてこれを暗黙的に処理します。`k`、小さいので`k`常に、より大きな候補の回答を継承します。 

最後の微妙なケースは、すべての大きな値が 1 つの連続したブロックに集まっている場合です。 ここで、セグメント数は多くのしきい値に対して 1 のままです。これは、すべての回答が一連の値の減少に崩壊することを意味し、爆弾の設置に関係なく 1 人の候補者だけが生き残るという直観と一致します。
