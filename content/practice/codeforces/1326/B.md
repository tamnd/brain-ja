 ## 解決策

 ## 問題の理解

 未知の配列の変換されたバージョンが与えられます。 元の配列には負ではない整数が含まれており、位置ごとに、前のすべての要素の最大値から別の値が導出されます。 次に、その最大値が現在の要素から減算されて、与えられた配列が生成されます。 

より具体的には、非表示配列内の各位置は、その左側でこれまでに確認された最大値の影響を受けます。 変換では、この実行最大プレフィックスを継続的に減算することにより、元の値が隠蔽されます。 

タスクは、指定された変換された配列を生成できる有効な元の配列を再構築することです。 複数の中間解釈が可能であるように見えますが、この問題では答えが一意であることが保証されています。 

この制約では最大 200,000 個の要素が許可されるため、各位置のすべての可能性を試行する二次再構成は直ちに除外されます。 O(n log n) さえすでに許容可能ですが、ここでは不要であるため、どのようなソリューションも線形時間、または最悪の場合でも線形に近い時間で動作する必要があります。 

微妙な点は、変換が純粋にローカルではないということです。 各値は最大プレフィックスに依存し、最大プレフィックスは以前に再構築されたすべての値に依存します。 これにより、プレフィックスの最大値がどのように変化するかを注意深く追跡せずに貪欲に値を割り当てようとする単純な試みを簡単に破ってしまう依存関係の連鎖が導入されます。 

よくある誤った考え方は、プレフィックスの最大値を推測することで各要素を独立して再構築できると想定することです。 これは失敗します。プレフィックスの最大値自体が以前に再構築された値に依存し、初期の不一致が前方に伝播し、後の再構築が無効になるためです。 

たとえば、プレフィックスの最大値が小さいままであると誤って仮定した場合、提供された差分がはるかに大きな隠れた値を意味する場合、後の制約に違反する値を再構築する可能性があります。 位置間の結合により、独立した再構築が不可能になります。 

## アプローチ

 ブルートフォース戦略では、隠されたプレフィックスの最大シーケンスを推測することによって、元の配列を再構築しようとします。 各インデックスで、以前の位置と一致する可能性のある以前の最大値をすべて試し、結果の再構成が指定された変換された配列と一致するかどうかを検証できます。 これは、各位置が多くの可能な最大状態に分岐する可能性があり、n 個の位置を超えると、最悪の場合指数関数的に増加するため、急速に爆発します。 

重要な観察は、変換によって、隠し配列とそのプレフィックスの最大値との間の決定的な関係が定義されるということです。 配列を左から右に処理すると、再構築されたプレフィックスの現在のプレフィックス最大値を維持しながら、元の値を再構築できます。 

インデックス i で、a₁ から aᵢ₋₁ までの接頭辞の最大値がすでにわかっている場合、定義により直接 xᵢ が得られます。 bᵢ = aᵢ − xᵢ なので、aᵢ = bᵢ + xᵢ と書き換えることができます。 これは、xᵢ が判明すると、aᵢ がすぐに修正されることを意味します。 aᵢ を計算した後、次のステップのためにプレフィックスの最大値を更新します。 

全体の再構成は、実行最大値を維持し、各ステップで直接式を適用することに帰着します。 この問題は、元の定義を逆に単純にシミュレーションしたものになります。

 ## アルゴリズムのチュートリアル

 以前に再構築されたすべての値の最大値を維持しながら、配列を左から右に再構築します。

1. 空のプレフィックスから開始します。これまでに確認された最大値は 0 です。これは、最初のプレフィックスの最大値が常に 0 であるという定義と一致します。 
2. 1 から n までのインデックス i ごとに、aᵢ を配置する前に現在のプレフィックスの最大値を計算します。 この値は正確に max(a₁, ..., aᵢ₋₁) であり、これを実行変数として維持します。 
3. 直接関係 aᵢ = bᵢ + current_max を使用して aᵢ を計算します。 これは、bᵢ が真の値とその位置での接頭辞の最大値との差として定義されているため機能します。 
4. aᵢ を計算した後、実行最大値を max(current_max, aᵢ) に更新します。 これにより、今後のポジションで正しいプレフィックス最大値が使用されるようになります。 
5. すべての値が再構築されるまで繰り返します。 

各ステップで現在の値と将来の状態の両方が決定的に修正されるため、ロジックをバックトラッキングする必要はありません。 

### なぜ効果があるのか

 すべての位置 i で、アルゴリズムは current_max が max(a₁, ..., aᵢ₋₁) に等しいという不変式を維持します。 aᵢ は bᵢ にこの値を加えたものとして計算されるため、変換の定義式を満たします。 最大値を更新すると、次の反復のために不変条件が保存されます。 各ステップでは bᵢ の生成に使用される正確な制約が適用されるため、再構成された配列は固有の有効な解になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
b = list(map(int, input().split()))

a = [0] * n

cur_max = 0
for i in range(n):
    a[i] = b[i] + cur_max
    if a[i] > cur_max:
        cur_max = a[i]

print(*a)
```解決策は、定義から直接再構築されたものになります。 変数`cur_max`再構築されたプレフィックスの最大プレフィックスを追跡します。 各位置について、まず、次の関係の逆関係を使用して、隠された元の値を計算します。`a[i]`、`b[i]`、およびプレフィックスの最大値。 次に、以降のインデックスの正確性を確保するために、実行最大値を更新します。 

よくある間違いは、計算前に最大値を更新することです`a[i]`。 これにより依存関係が逆転し、誤った結果が生成されます。`b[i]`更新された最大値ではなく、以前の最大値を使用して定義されました。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n = int(input())
    b = list(map(int, input().split()))

    a = [0] * n
    cur_max = 0

    for i in range(n):
        a[i] = b[i] + cur_max
        cur_max = max(cur_max, a[i])

    return " ".join(map(str, a))

# provided sample
assert run("5\n0 1 1 -2 1\n") == "0 1 2 0 3"

# minimum size
assert run("3\n0 0 0\n") == "0 0 0"

# strictly increasing hidden prefix
assert run("4\n0 1 2 3\n") == "0 1 2 3"

# large negative drop
assert run("3\n1000000000 -1000000000 -1000000000\n") == "1000000000 0 0"

# alternating pattern
assert run("5\n0 5 -3 10 -2\n") == "0 5 2 12 10"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 3 0 0 0 | 0 0 0 | オールゼロの安定性 |
 | 0 1 2 3 パターン | 0 1 2 3 | 単調な接頭辞の増加 |
 | 大幅なマイナス下落 | ピーク後 0 0 0 | 負の b 値の処理 |
 | 交互の値 | 一貫した再構築 | 動的最大値の更新 |

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべての b 値が 0 である場合です。 入力の場合:```
3
0 0 0
```アルゴリズムは cur_max = 0 から始まります。各ステップで a[i] = 0 が計算され、cur_max は決して変化しません。 出力はすべてゼロのままで、唯一の一貫した再構成と一致します。 

もう 1 つのケースは、b が大きなピークの後に大きな負の値を含む場合です。 例えば：```
3
1000000000 -1000000000 -1000000000
```i = 1 では、cur_max は 1000000000 になります。i = 2 および i = 3 では、大きなプレフィックスの最大値が減算されるため、計算された a[i] は毎回 0 になります。 その後、プレフィックスの最大値は変化せず、再構成は、各位置の前の最大プレフィックスである xᵢ の定義と一貫性を保ちます。
