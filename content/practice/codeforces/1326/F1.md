 ## 解決策

 ## 問題の理解

 最大 14 個の頂点を持つ小さな無向グラフが与えられ、どのペアの人々がお互いを知っているかを表します。 各入力行は隣接行列のビットマスク行であるため、2 人が接続されているかどうかをすぐに確認できます。 

タスクは、グラフやサブセットを直接列挙することではなく、すべての人々の順列を列挙することです。 頂点の順序ごとに、連続するペアを調べ、順列内の各隣接ペアがグラフ内のエッジを共有するかどうかをエンコードします。 これにより、次の長さのバイナリ文字列が生成されます。$n-1$。 各順列は、そのような文字列を 1 つだけ作成します。 

出力では、可能なすべての長さのバイナリ文字列が要求されます。$n-1$、整数ビットマスクとして解釈されるため、それを生成する順列の数をカウントする必要があります。 

重要な問題は、順列の階乗数です。 たとえ$n=14$、$14!$直接列挙するには大きすぎます。 出力スペースは$2^{13} = 8192$したがって、問題の構造は、順列ではなくサブセットによってインデックス付けされた状態空間に順列を圧縮することを強く示唆しています。 

密集したグラフからは微妙なエッジケースが発生します。 全員が全員を知っている場合は、隣接するすべてのペアが有効であるため、すべての順列ですべて 1 の文字列が生成されます。 この場合、回答配列のマスクに 0 以外のエントリが 1 つあります。$2^{n-1}-1$。 順列ごとに文字列を明示的に追跡しようとする素朴なアプローチは、たとえ出力が非常にまばらであっても、要因爆発により失敗します。 

グラフが空の場合は、別の特殊なケースが発生します。 この場合、すべての隣接関係はゼロになるため、すべての順列がすべてゼロの文字列に寄与します。 これにより、状態空間全体が再び崩壊し、グローバル構造を考慮せずに位置ごとに遷移を独立して処理しようとするメソッドは、誤ってオーバーカウントします。 

## アプローチ

 直接的な総当たりアプローチでは、すべてのものが生成されます。$n!$順列。 順列ごとに、バイナリ文字列を構築します。$O(n)$、それをハッシュし、そのカウンターをインクリメントします。 これは正しいですがコストがかかります$O(n! \cdot n)$、でもそれは不可能です$n=12$、ましてや$n=14$。 

問題の構造は、視点を逆転させることを示唆しています。 順列を構築するのではなく、順列を段階的に構築します。 どの時点でも部分的な置換が行われており、将来に関して重要な唯一の情報は、どの頂点が未使用のままであり、現在どの頂点が置換の最後にあるかということです。 バイナリ文字列は、新しい頂点を追加するにつれて段階的に決定されます。 

これにより、自然にサブセットに対する動的プログラミングが行われます。 使用された頂点のサブセットと部分順列の最後の頂点によって状態を表します。 このような状態ごとに、この状態からの置換を完了することによって生成できるすべての可能なサフィックス ビットマスクにわたる分布を維持します。 最終的な答えはすべての完全な順列にわたって集計されるため、完全なサブセットを持つ状態から上方に寄与を伝播できます。 

重要な観察は、遷移は最後の頂点と次に選択された頂点の間にエッジが存在するかどうかのみに依存するということです。 これは、各 DP 遷移が、既に配置されている頂点の数によって決定される位置で、進化するサフィックス マスク内の単一ビットを反転することを意味します。 順列を明示的に保存する必要はなく、サブセットの構造と位置のみを保存する必要があります。 

最終的なソリューションは、構築される部分ビットマスクを表す追加の次元を備えたサブセット DP になります。

 ## アルゴリズムのチュートリアル

 左から右へ順列を構築しますが、順列を保存する代わりに、部分的な構造をエンコードする DP 状態を追跡します。 

1. DP テーブルを定義します。$dp[mask][v]$はビットマスク上の辞書または配列で、頂点を正確に使用して順列を形成できる方法が何通りあるかを表します。`mask`そして頂点で終わる`v`、現在のプレフィックスの特定の隣接ビット履歴を生成します。 ビットヒストリー長は$|mask|-1$。 
2. 設定により基本ケースを初期化します。$dp[1<<v][v]$単一構成へ: 頂点から開始する 1 つの方法$v$空の隣接文字列を使用します。 隣接するペアが存在しないため、エッジの決定はまだ行われていません。 
3. サブセット サイズを 1 から 2 まで反復します。$n$。 州ごとに$(mask, v)$、新しい頂点を選択して順列を拡張することを検討してください。$u$入っていない`mask`。 この拡張により、順列内の位置が 1 つ追加され、隣接文字列の長さが 1 つ増加します。 
4. から移行する場合$v$に$u$、ペアかどうかを判断します。$(v, u)$エッジです。 存在する場合、追加される新しいビットは 1 で、それ以外の場合は 0 です。$dp[mask][v]$を 1 ビット左にシフトし、新しいビットを最下位に追加します。 
5. これらのシフトされた貢献を蓄積します。$dp[mask \cup \{u\}][u]$。 これにより、すべての部分置換が次で終わることが保証されます。$u$考えられるすべての隣接履歴を正しく保存します。 
6. すべての状態を処理した後は、サイズの完全なマスクのみを考慮します。$n$。 終了頂点ごとに$v$に保存されているすべてのビットマスクを集約します。$dp[(1<<n)-1][v]$最終回答配列に追加します。 

### なぜ効果があるのか

 すべてのステップで、DP 状態は、使用された頂点と終了頂点の指定されたセットと一致するすべての部分順列を正確に表します。 次の隣接性の決定は追加された最後にエッジのみに依存するため、ステップ間の唯一の依存関係は最後の頂点です。 各拡張はシーケンスに正確に 1 ビットを決定論的に追加するため、DP は部分置換とその生成されたビット履歴の間の 1 対 1 の対応を保存します。 ビットマスクは遷移を通じて明示的に伝達され、すべての順列は DP を通る 1 つのパスに正確に対応するため、2 つの異なる履歴が誤ってマージされることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    g = [input().strip() for _ in range(n)]

    size = 1 << n
    dp = [ [dict() for _ in range(n)] for _ in range(size) ]

    for i in range(n):
        dp[1 << i][i][0] = 1

    for mask in range(size):
        bits = bin(mask).count("1")
        if bits <= 1:
            continue
        for v in range(n):
            if not dp[mask][v]:
                continue
            cur = dp[mask][v]
            for u in range(n):
                if mask & (1 << u):
                    continue
                edge_bit = 1 if g[v][u] == '1' else 0
                new_mask = mask | (1 << u)
                nxt = dp[new_mask][u]
                for bm, cnt in cur.items():
                    nbm = (bm << 1) | edge_bit
                    nxt[nbm] = nxt.get(nbm, 0) + cnt

    full = (1 << n) - 1
    ans = [0] * (1 << (n - 1))

    for v in range(n):
        for bm, cnt in dp[full][v].items():
            ans[bm] += cnt

    print(*ans)

if __name__ == "__main__":
    solve()
```DP テーブルにはサブセットと終了頂点によってインデックスが付けられ、有効な部分順列のみを拡張することが保証されます。 辞書にはビット履歴のカウントが保存されます。 左にシフトすることは、新しい隣接関係の決定を追加することに対応します。 

初期化により、各単一頂点サブセットがニュートラル履歴に設定されます。 各遷移は、格納されているすべてのビット パターンを処理します。これは、同じ状態に到達する異なる部分順列が隣接履歴で依然として異なる可能性があるため、必要です。 

順列には固定の終点がないため、最終的な集約では、考えられるすべての終了頂点が結合されます。

 3 ノードの折れ線グラフを考えてみましょう。```

```ここでは、1-2-3 と 3-2-1 のみが、連続するノード間に 1 つのエッジを持つ有効な隣接パターンを生成します。 

DP は、遷移でエッジを使用するか非エッジを使用するかに基づいて順列を分割します。 0 または 1 を追加すると異なるマスクが生成され、これらは別々に保存されるため、履歴が分岐します。 これは、ビット履歴がマージされず、正確性が維持されていることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(n^2 2^n)$| 各サブセットの状態は最大で次のように遷移します。$n$次の頂点、および各遷移は保存されたビットマスクを処理します。 
| スペース |$O(n 2^n)$| DP はすべてのサブセットとエンドポイントの状態を保存します。

 ## 特殊なケース

 完全に接続されたグラフでは、すべての順列が 1 つの出力バケットにまとめられます。 DP は引き続きすべてのサブセット遷移を処理しますが、すべてのエッジ ビットが 1 であるため、すべての履歴が同一になり、最大ビットマスクのみがカウントを蓄積します。 

空のグラフでは、すべての遷移ビットが強制的にゼロになります。 すべての順列は同じすべてゼロのマスクを生成し、DP はすべてのマスクを正しく累積します。$n!$状態を誤って分割することなく、単一のエントリに順列を変換します。 

線形チェーンにより、特定の隣接パターンのみが隣接パターンを生成します。 DP はすべてのステップで有効なエッジと無効なエッジを区別する必要があり、ビット履歴が明示的に伝送されるため、単一の隣接関係の決定で異なる 2 つの順列は状態空間内で永続的に分岐します。
