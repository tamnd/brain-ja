 ## 解決策
 ## 問題の理解

 1 から n までの数値の順列が、1 から n の位置に配置されます。 非常に特殊な操作を使用してそれを再配置することができます。つまり、インデックスが正確に k だけ異なる要素のみを交換できます。 つまり、ポジションは、k 離れたポジションとのみ対話できる制約付きスワッピング システムを形成します。 

これに加えて、これらの制約付きスワップを実行する前に、任意の 2 つのポジション間で最大 1 回の任意のスワップを実行できます。 そのオプションのスワップの後、許容される距離 k のスワップのみを使用して、値 i が位置 i になる恒等配列に順列を完全にソートできるかどうかを知りたいと考えています。 

出力は最終的な順列ではなく、実現可能性の分類です。 置換が制限付きスワップ ルールの下ですでに並べ替え可能である場合は、0 を出力します。 任意のスワップを 1 つだけ使用した後でのみソート可能になる場合は 1 を出力し、それがなければソートは不可能です。 任意の 1 つのスワップでもソート可能にできない場合は、-1 を出力します。 

制約構造は、n が大きくなり、テスト ケース全体で合計最大約 2×10^5 になる可能性があることを意味します。 これにより、スワップをシミュレートしたり、クエリごとにグラフの走査を繰り返し実行したりするアプローチは即座に除外されます。 テスト ケースごとに線形時間に近い時間、理想的には O(n) が必要です。テスト ケースごとに O(n log n) またはそれより悪い回数を繰り返しても合格しますが、O(n^2) は明らかに不可能だからです。 

重要な隠れた構造は、許可されたスワップがすべてのインデックスを結合しないことです。 代わりに、ポジションを独立したチェーンに分割します。 

単純な推論を破る一般的なエッジ ケースは、k が大きいか 1 に等しい場合です。 

k = 1 の場合、すべての隣接するスワップが許可されるため、順列は常に制限なくソート可能です。 モジュラー制約を依然としてチェックする単純な実装では、接続がいっぱいになったことを忘れると、有効なケースが誤って拒否される可能性があります。 

k が 1 でない場合、たとえば n = 6、k = 3 の場合、位置は (1,4)、(2,5)、(3,6) のようなチェーンに分割されます。 位置 1 で終了するはずの値が別のチェーン (たとえば位置 2 または 3) で始まる場合、その値は位置 1 に到達することはできず、許可されたスワップのシーケンスによって問題が修正されることはありません。 

これらのチェーン全体でちょうど 1 つまたは 2 つの要素が「配置されていない」場合、微妙な障害が発生します。 貪欲な直観は、複数のスワップによってそのような状況を修正できると示唆するかもしれませんが、空きスワップは最大 1 つまでに制限されているため、矛盾しているコンポーネントの数を推論する必要があります。 

## アプローチ

 ブルート フォース ビューでは、スワップ グラフを明示的にシミュレートします。 エッジが i と i + k (有効な場合) を接続するインデックスに基づいてグラフを構築し、エッジに沿ったスワップを使用して各値を開始位置からターゲット位置にルーティングできるかどうかを確認します。 各接続コンポーネントは独立しているため、各コンポーネント内で順列が到達可能かどうかを事実上シミュレートする必要があります。 

直接シミュレーションでは、ソートされるまでパスに沿って要素が繰り返し交換されますが、各値が長いチェーンを複数回横断する可能性があるため、最悪の場合は O(n^2) の動作に低下する可能性があります。 構造が静的であるため、要素ごとの BFS であっても不要なオーバーヘッドはありません。 

重要な観察は、スワップによってグラフの接続されたコンポーネントが保持されるということです。 2 つの位置が同じコンポーネント内にない場合、許可されたスワップのシーケンスはその内容を交換できません。 したがって、各値はその開始位置のコンポーネント内に留まるように制約されます。 

これにより、問題はラベル付けの制約に集約されます。つまり、すべての値 i は、i 自体と同じコンポーネントに属する位置で開始する必要があります。 それがすべての i に対してすでに当てはまる場合、その順列はコスト 0 でソート可能です。

唯一の柔軟性は、コンポーネント間で 2 つの値を正確に移動できる、オプションの単一の任意のスワップから得られます。 つまり、最大 2 つのコンポーネント違反を修復できるということです。 間違ったコンポーネントに 3 つ以上の値がある場合、1 回の交換ではすべてを修正できません。 正確に 2 つが間違っている場合は、それらを交換することで両方が同時に正しいコンポーネントに到達するかどうかを確認できます。

 | スワップのグラフシミュレーション | O(n²) | O(n) | 遅すぎる |
 | コンポーネント + ミスマッチ分析 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、各値が現在どこにあるかを計算します。 pos[x] が値 x が出現するインデックスとなるように、配列 pos を構築します。 

次に、k によって課される構造的制約を決定します。 すべてのインデックス i は、i mod k によって完全に決定されるコンポーネントに属します。これは、±k の移動を繰り返しても剰余クラスが変更されることがないためです。 したがって、コンポーネントのメンバーシップは i mod k です。 

次に、すべての値 i をその必要な位置 i と照合します。 各値について、pos[i] mod k と i mod k を比較します。 

次のように進めます。 

1. pos 配列マッピング値を現在のインデックスに構築します。 これにより、O(1) 内の位置をクエリできるようになります。 
2. 1 から n までの各値 i について、pos[i] % k が i % k に等しいかどうかを確認して、その不一致条件を計算します。 一致する場合、その値は宛先への到達可能なコンポーネント内にすでに存在します。 
3. この条件を満たさない値をすべて収集して不良リストに入れます。 
4. bad が空の場合、順列はすでにソート可能であるため、0 を出力します。 
5. bad に 3 つ以上の要素がある場合は、-1 を出力します。これは、1 つのスワップが 2 つの値にのみ影響し、3 つを超えるコンポーネント違反を修復できないためです。 
6. bad にちょうど 2 つの要素 (a と b) がある場合、概念的にそれらの交換をシミュレートします。 スワップ後、a は pos[b] に配置され、b は pos[a] に配置されます。 これにより両方の制約が同時に修正されるかどうか、つまり pos[b] % k == a % k と pos[a] % k == b % k が修正されるかどうかを確認します。 
7. この条件が成立する場合は 1 を出力し、そうでない場合は -1 を出力します。 

正確かどうかは、スワップが 2 つの値にのみ影響し、許可されたスワップの下ではコンポーネントのメンバーシップが不変であるという事実にかかっています。 

### なぜ効果があるのか

 許可される操作は、接続コンポーネントが k を法とする固定剰余クラスであるグラフを定義します。 各コンポーネント内では、スワップによって任意の順列が許可されるため、到達可能性は各値がターゲット位置と同じコンポーネントで始まるかどうかによってのみ決まります。 この条件は必要かつ十分です。 

オプションのスワップは、コンポーネント間で値を移動する唯一の方法です。 正確に 2 つの値に影響を与えるため、最大 2 つの不一致を修正できます。 一連の制約付きスワップによってコンポーネントのメンバーシップが変更されることはないため、チェックは、不一致の値のセットが、それぞれが同時に正しい残基クラスに移動される方法でペアにできるかどうかを検証することに留まります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        p = list(map(int, input().split()))

        pos = [0] * (n + 1)
        for i, v in enumerate(p, start=1):
            pos[v] = i

        bad = []
        for v in range(1, n + 1):
            if (pos[v] - 1) % k != (v - 1) % k:
                bad.append(v)

        if not bad:
            print(0)
            continue

        if len(bad) != 2:
            print(-1)
            continue

        a, b = bad[0], bad[1]
        if ((pos[a] - 1) % k == (b - 1) % k and
            (pos[b] - 1) % k == (a - 1) % k):
            print(1)
        else:
            print(-1)

if __name__ == "__main__":
    solve()
```解決策は、スワップを直接追跡するのではなく、値の位置の観点から推論できるように、逆順列を構築することから始まります。 モジュロ算術では (i - 1) が使用されます。これは、問題のインデックスが 1 であるのは当然ですが、コンポーネントの構造はインデックスが 0 の形式の方がすっきりしているためです。 

実装の重要な詳細は、スワップを決してシミュレートしないことです。 剰余クラスについてのみ推論します。 これにより、パフォーマンスの問題と、スワップ順序の誤りによる微妙なバグの両方が回避されます。 

## 実用的な例

 ### 例 1

 入力:```
4 2
3 1 4 2
```位置を計算します: pos[1]=2、pos[2]=4、pos[3]=1、pos[4]=3。 

次に、モジュロ クラス mod 2 を比較します。 

値 1: pos=2 はクラス 0、ターゲット 1 はクラス 1、不一致

 値 2: pos=4 はクラス 0、ターゲット 2 はクラス 0、一致

 値 3: pos=1 はクラス 1、ターゲット 3 はクラス 1、一致

 値 4: pos=3 はクラス 1、ターゲット 4 はクラス 0、不一致

 とても悪い = [1, 4]。 

| ステップ | 値 | 位置 | pos mod 2 | 値 mod 2 | ステータス |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 1 | 2 | 0 | 1 | 悪い |
 | 2 | 2 | 4 | 0 | 0 | わかりました |
 | 3 | 3 | 1 | 1 | 1 | わかりました |
 | 4 | 4 | 3 | 1 | 0 | 悪い |

 ここで、1 と 4 を交換することで両方が修正されるかどうかを確認します。 スワップ後、1 は位置 3 (クラス 1) に、4 は位置 2 (クラス 0) に移動し、ターゲットと一致します。 したがって、出力は 1 になります。 

これは、単一のコンポーネント間スワップによって 2 つの不一致が解決される正確なケースを示しています。

 この場合、すべてが一致するため、出力は 0 になります。これは、残基のアラインメントが保存されている場合、逆順列でも距離 k のスワップでソート可能であることを示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque
    input = sys.stdin.readline

    t = int(input())
    out = []

    for _ in range(t):
        n, k = map(int, input().split())
        p = list(map(int, input().split()))

        pos = [0] * (n + 1)
        for i, v in enumerate(p, 1):
            pos[v] = i

        bad = []
        for v in range(1, n + 1):
            if (pos[v] - 1) % k != (v - 1) % k:
                bad.append(v)

        if not bad:
            out.append("0")
        elif len(bad) != 2:
            out.append("-1")
        else:
            a, b = bad
            if ((pos[a] - 1) % k == (b - 1) % k and
                (pos[b] - 1) % k == (a - 1) % k):
                out.append("1")
            else:
                out.append("-1")

    return "\n".join(out)

 ## 特殊なケース

 k = 1 の場合、すべてのインデックスは独自のコンポーネントに属し、実際にはスワップが不可能であることを意味します。 すべての値 i が既に pos[i] = i を満たしている必要があるため、アルゴリズムはこれを処理します。 そうでない場合は、不良が大きくなり、すでにソートされているか、スワップによって簡単に修正されていない限り、正しく -1 を返しますが、コンポーネントがシングルトンであるため、スワップも役に立ちません。 

k ≥ n/2 など、k が大きい場合、コンポーネントは非常に小さなチェーンになります。 各チェーンが分離されたままであり、不一致の検出がローカルな一貫性まで低下するため、残余チェックは到達可能性を引き続き正確に捕捉します。 

スワップには 2 つのエンドポイントが必要であるため、不一致が 1 つだけあるケースは 1 回のスワップでは修正できません。 不正なサイズが 1 であり、すぐに -1 を出力するため、アルゴリズムは当然それを拒否します。 

2 つ以上の不一致があるケースも早期に拒否されます。 これにより、1 回のスワップではコンポーネント全体で 2 つを超える値を修復できないため、部分的な修正についてより深い推論が必要なくなります。
