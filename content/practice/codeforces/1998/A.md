 ## 解決策
 ## 問題の理解

 ターゲットの中心点が与えられます$(x_c, y_c)$そして整数$k$。 このタスクは、何かを最適化したり、特別な構成を検索したりすることではありません。 正確に構築する必要があるだけです$k$算術平均が正確に一致する個別の整数座標点$(x_c, y_c)$。 

中心条件とは次のことを意味します。$$\frac{\sum x_i}{k} = x_c, \qquad \frac{\sum y_i}{k} = y_c$$同様に、$$\sum x_i = k \cdot x_c, \qquad \sum y_i = k \cdot y_c.$$生成されたすべての点の座標は、次の範囲内に収まる必要があります。$[-10^9,10^9]$、ただし、指定された中心座標は次の間のみにあります。$-100$そして$100$、 そして$k \le 1000$。 これは、許容される座標範囲に比べて非常に小さいため、ポイントを構築する際に非常に自由度が高くなります。 

すべての合計$k$テスト ケース全体の値は最大でも$1000$。 たとえ$O(k)$テストケースごとに構築するだけで十分です。 

主な危険は、誤って重複したポイントを作成したり、平均がほぼ正確なポイントを作成したりすることです。 答えは建設的であるため、生成されたすべての点は中心方程式を正確に満たす必要があります。 

考慮する$k=1$。 例えば：```
10 10 1
```単一点の中心として考えられるのはその点自体だけであるため、次のように出力する必要があります。```
10 10
```常に対称ペアを作成する構築は、利用可能なパートナー ポイントがないため失敗します。 

もう一つの微妙なケースは奇妙だ$k$。 

例えば：```
0 0 3
```対称ペアを 1 つだけ出力すると、次のようになります。```
1 0
-1 0
```我々には2点しかない。 合計を変更しないまま、3 番目の個別の点が必要です。 不用意に施工すると追加の可能性があります$(0,0)$既存のポイントを複製する場合でも。 

最後に、すべての点が区別できる必要があります。 例えば：```
0 0 2
```出力中```
0 0
0 0
```正しい中心を持っていますが、区別性の要件に違反しています。 

## アプローチ

 強引な考え方では、任意の整数点を検索し、その平均が目的の中心と等しいかどうかを繰り返しチェックします。 有効な構成が無数に存在するため、このような検索は最終的には成功します。 問題は、検索にかかる時間に意味のある上限がなく、正確性を保証することが困難になることです。 

中心の式の構造は、より明確なアプローチを提供します。 2つの点が中心に対して対称に配置されている場合、$$(x_c-d, y_c)$$そして$$(x_c+d, y_c),$$座標合計に対するそれらの寄与は、$$2x_c,\quad 2y_c.$$言い換えれば、ペアの平均はすでにちょうど中心になっています。 このような対称的なペアは、最終的な中心を変更せずにいくつでも組み合わせることができます。 

この観察は直ちに構造を示唆します。 

もし$k$偶数です、作成します$k/2$周囲の対称ペア$(x_c,y_c)$。 

もし$k$奇数である場合は、まず中心点自体を配置します。 その貢献はまさに$(x_c,y_c)$。 次に構築します$(k-1)/2$その周りに対称的なペア。 

距離の使用$1,2,3,\ldots$生成されたすべてのポイントが異なることを保証します。 

以来$k \le 1000$、使用する最大のオフセットは最大です。$500$したがって、すべての座標は許容範囲内に快適に収まります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 無制限 | 無制限 | 実用的ではない |
 | 最適 | O(k) | O(1) 出力を除く | 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む$x_c$、$y_c$、 そして$k$。 
2. 空の回答リストを作成します。 
3. もし$k$奇数です、中心点を追加します$(x_c,y_c)$答えに。 

この点は、合計に対する中心のコピーの 1 つだけを占めます。 
4. 距離ごとに$d = 1,2,\ldots,\lfloor k/2 \rfloor$に、次の 2 つの点を追加します。$$(x_c-d,\ y_c)$$そして$$(x_c+d,\ y_c).$$5. 生成されたすべての点を出力します。 

### なぜ効果があるのか

 生成されたすべてのペアは中心に対して対称です。 それらの座標の合計は、$$(x_c-d)+(x_c+d)=2x_c,$$そして$$y_c+y_c=2y_c.$$したがって、各ペアの平均値は$(x_c,y_c)$。 

もし$k$は偶数です、正確に$k/2$そんなペアたち。 座標の合計は次のようになります。$$kx_c,\quad ky_c,$$したがって中心は正しいです。 

もし$k$奇数なので、さらに含めます$(x_c,y_c)$。 残り$k-1$点は対称ペアを形成し、その合計寄与度は$$(k-1)x_c,\quad (k-1)y_c.$$中心点を追加すると、$$kx_c,\quad ky_c.$$すべての距離は異なるため、生成された 2 つの点が一致することはありません。 したがって、構築は常に生成します$k$必要な中心を持つ個別の整数座標点。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())

out = []

for _ in range(t):
    xc, yc, k = map(int, input().split())

    if k % 2 == 1:
        out.append(f"{xc} {yc}")

    for d in range(1, k // 2 + 1):
        out.append(f"{xc - d} {yc}")
        out.append(f"{xc + d} {yc}")

sys.stdout.write("\n".join(out))
```実装は構築の後に直接続きます。 

奇数の場合$k$、中心点が最初に放出されます。 これにより、必要な平均を維持しながら、不一致点が処理されます。 

このループは、中心からの距離を増加させて対称ペアを生成します。 異なる距離を使用すると、自動的に明確な点が保証されます。 最大距離は最大ですので、$500$、すべての座標は、$\pm 10^9$限界。 

浮動小数点演算はどこにも現れません。 この証明は正確な整数の合計に完全に依存しており、精度の問題は排除されています。
