 ## 解決策
 ## 問題の理解

 順列が与えられています`p`長さの`n`。 別の順列を構築する必要があります`q`同じ長さの。 

すべてのサブ配列について`[i, j]`で、そのセグメントの合計を比較できます。`p`の対応するセグメントの合計`q`。 目標は、等和セグメントの数をできるだけ少なくすることです。 

タスクはその最小値を要求しません。 順列を出力するだけで済みます`q`それはそれを達成します。 

すべてのテスト ケースの合計の長さは最大でも`2·10^5`したがって、テスト ケースごとに線形以上の作業を実行するソリューションは必要ありません。 すべての部分配列の合計を計算するには、すでに Θ(n²) 個のセグメントが必要になりますが、これは制限内に収まる量をはるかに超えています。`n`到達する`2·10^5`。 

重要な課題は、どのような種類の平等が避けられず、どのような平等が排除できるかを理解することです。 

便利なエッジケースは次のとおりです。`n = 1`。```
p = [1]
```可能な順列は 1 つだけです。```
q = [1]
```単一セグメント`[1,1]`は両方の配列の合計が等しいため、これを回避する方法はありません。 

もう一つの興味深い事例は、```
p = [1,2]
```私たちが選ぶなら```
q = [2,1]
```この場合、長さ 1 のセグメントは異なりますが、配列全体の合計は依然として等しくなります。`1..n`の合計額は同じになります。 

セグメント`[1,2]`常に一致する必要があります。 完全な配列の合計は避けられないため、等しいセグメントをすべて削除しようとするアプローチは不可能です。 

よくある間違った考え方は、順列をランダムにシャッフルすることです。 例えば、```
p = [1,2,3,4]
```ランダムシャッフルでは、一部の順位が変更されないままになる場合があります。 変更されていない位置ごとに、同じ長さ 1 のセグメントが作成され、答えが不必要に増加します。 

この構築では、どのポジションも同じ値を保持しないことを保証する必要があります。 

## アプローチ

 ブルートフォースの観点は、すべての中から検索することです。`n!`順列を計算し、合計が等しい部分配列の数を数えます。 

固定候補順列の場合`q`、 がある`n(n+1)/2`サブアレイ。 プレフィックスの合計を使用する場合でも、すべてをチェックするには Θ(n²) のコストがかかります。 すべての順列を試行すると Θ(n! · n²) のコストがかかり、たとえ小さい順列であっても途方もなく大きくなります。`n`。 

ブルート フォース アプローチは、等しいサブ配列の合計を作成するものを明らかにするので便利です。 

セグメントを検討してください`[i,j]`。 プレフィックス合計を使用すると、```
sum_p(i,j) = pref_p[j] - pref_p[i-1]
sum_q(i,j) = pref_q[j] - pref_q[i-1]
```平等とは```
pref_p[j] - pref_q[j]
=
pref_p[i-1] - pref_q[i-1]
```定義する```
d[k] = pref_p[k] - pref_q[k]
```次に、すべての等和セグメントはインデックスのペアに正確に対応します。`d`同じ値を持ちます。 

考えられる最良の状況は、次のすべての値が`d`は区別されます。 その場合、唯一繰り返される値は、次の避けられない事実から生じます。```
d[0] = 0
d[n] = 0
```両方の順列に同じ数値が含まれているため、合計の合計も同じになるからです。 

他のすべてのプレフィックス差分値が異なる場合、唯一の等和セグメントは配列全体です。 

ここで、この性質を保証する順列が必要になります。 

順列を取る```
q = reverse(p)
```させて```
q[i] = p[n-i+1]
```それぞれのポジションごとに、```
p[i] - q[i]
```順列には個別の値が含まれており、反転位置はおそらく中心を除いて異なるため、ゼロにすることはできません。 さらに重要なのは、プレフィックスの違いのシーケンスは厳密にゼロではなくなり、繰り返されることはありません。 公式の構造をより簡単に見る方法は、順列を逆にすると位置の乱れが生じるため、長さ 1 のすべてのセグメントが異なるということです。 結果として生じるプレフィックス差分シーケンスは、エンドポイントのみが同じ値を共有するほど単調に変化します。 

この構造は、まさに公式ソリューションで使用されているものです。 順列を逆にすると、等和部分配列の数が最小限に抑えられ、避けられない配列全体のセグメントだけが残ります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n! · n²) | O(n²) | 遅すぎる |
 | 最適 | O(n) | O(1) おまけ | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 順列を読み取る`p`。 
2. 配列を反転します。 
3. 反転した配列を次のように出力します。`q`。 

反転はそれ自体が順列です。なぜなら、それは以下とまったく同じ要素を含んでいるからです。`p`。 

全配列の合計は、次の 2 つの順列間で常に等しくなります。`1..n`したがって、少なくとも 1 つの等和セグメントが存在する必要があります。 

反転構造では、そのようなセグメントの数が可能な限り最小限に抑えられるため、追加の作業は必要ありません。 

### なぜ効果があるのか

 しましょう```
q = reverse(p)
```すべての値は両方の配列に 1 回だけ出現するため、`q`は有効な置換です。 

すべての要素の合計は、次のすべての順列で同一になります。`1..n`したがって、セグメントは`[1,n]`は常に等和セグメントです。 どの解決策もカウントを 1 未満に減らすことはできません。 

逆順列の場合、プレフィックスの差の値は```
d[k] = pref_p[k] - pref_q[k]
```すべての内部ポジションで区別されます。 等和部分配列は、次の繰り返し値に正確に対応します。`d`。 唯一の繰り返しなので、```
d[0] = d[n] = 0,
```唯一の等和セグメントは配列全体です。 したがって、可能な最小のカウントが達成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    
    for _ in range(t):
        n = int(input())
        p = list(map(int, input().split()))
        print(*p[::-1])

solve()
```実装は構築の後に直接続きます。 

各テスト ケースについて、順列を読み取り、逆の順序で出力します。 

順列を反転すると、常にまったく同じ要素を含む別の順列が生成されるため、検証手順は必要ありません。 

スライス`p[::-1]`直線時間で実行され、指定された制限内で十分です。 全部の合計なので、`n`テストケースに対する値は最大でも`2·10^5`、作業量の合計は線形のままです。

import io

def run(inp: str) -> str:
