 ## 解決策
 ## 問題の理解

 整数の配列が与えられます`a`と並列バイナリ配列`b`。 配列`b`のどの位置を示します`a`増やすことができます。 インクリメント操作ごとに、選択された値が増加します。`a[i]`1 ずつ増加すると、最大で実行できます`k`合計の操作。 私たちの目標は、選択した 1 つの要素の合計として定義されるスコアを最大化することです。`a[i]`の残りの要素の中央値を加えたもの`a`。 各テスト ケースについて、最大の実行後に可能な限り最大のスコアが必要です。`k`許可される増分。 

制約は大きくなります。`n`テスト ケースごとに最大 200,000 まで可能で、すべての合計の合計となります。`n`テスト ケース全体の上限は 200,000 です。 操作数`k`最大 10^9 までの非常に大きなサイズになる可能性があります。 これにより、考えられる操作のすべての組み合わせを試みる総当り的なアプローチが排除されます。 エッジケースには、次のような状況が含まれます。`b`すべてゼロの場合は、操作が不可能であることを意味するか、`k`の要素に比べて巨大です`a`これにより、制限を気にせずに単一の要素を効果的に最大化できます。 

中央値が配列内の小さなシフトに敏感な場合、明らかではないエッジ ケースが発生します。 たとえば、次の場合`a`は`[1, 2, 3, 4, 5]`また、特定の要素のみをインクリメントできるため、中央値の外側の要素にすべての増分を集中させると、中央値の位置に小さな数値が残る場合は次善の効果が得られる可能性があります。 もう 1 つの注意が必要なシナリオは、配列の大部分が大きな数値であり、1 つの小さな要素しか増加できない場合です。 単純なアプローチでは、操作に最大の要素を選択する可能性がありますが、最適な戦略には中央値自体をブーストすることが含まれる可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、配布するためのあらゆる方法が考慮されます。`k`ポジション間の増分`b[i] = 1`そしてそれぞれの可能性のスコアを計算します。 これは理論的には正しいですが、分布の数は指数関数的です。`k`そしてポジションの数では、`b[i] = 1`。 のために`n`2*10^5 あたりでは、これは完全に不可能です。 

重要な洞察は、スコアが単一の要素に依存するということです。`a[i]`残りの中央値を加えます。 配列を並べ替えることで、中央値を直接推論することができます。中央値未満の要素を増やしても中央値にはすぐには影響しませんが、中央値以上の要素を増やすと中央値自体が増加する可能性があります。 最大限のものを求めているので、`a[i] + median(c_i)`、最適なアプローチは並べ替えることです`a`では、可能な最大の要素 (または中央位置にある要素) をブーストすることに焦点を当て、削除時に中央値に寄与する要素に許可されたすべての操作を追加することでスコアが最大化されることを認識します。 

テストケースごとに並べ替えた後、`a`、達成可能な最大中央値は、`k`現在の中央値以上の要素に増分します。 この場合、スコアは単純に次の最大値になります。`a`さらにこの新しい中央値。 これにより、問題は、操作のすべてのサブセットを考慮することから、ソートされた位置に基づいた線形または二分探索に適した問題に軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^k) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る`t`。 
2. 各テスト ケースについて、次の内容を読んでください。`n`、`k`、配列`a`、およびバイナリ配列`b`。 
3. 配列をソートする`a`。 ソートされた配列の中央値`a`長さの`n`位置にあります`(n-1)//2`。 
4. チェックボックスをオンにして、増分を受け取ることができる中央値以上の要素の数を決定します。`b[i] = 1`のために`i >= median_index`。 
5. 許可される操作の合計が`k`を適用できる場合は、許可される限り中央値要素を増やします。 実際には、`k`非常に大きくなる可能性があるため、すべてを単純に追加することができます`k`中央要素に。 これは、中央値を超えて要素を増やしてもスコアが上がるだけであるためです。 
6. 最大スコアは、ソートされた配列の最後の要素に、増加後の中央値要素を加えたものになります。 この問題の目的として、合計を最大化するためにすべての増分が中央値要素に送られると仮定します。`a[i] + median(c_i)`。 

**機能する理由:** 並べ替えにより、中央値が正しく識別されます。 スコアはいくつかの合計なので、`a[i]`中央値と残りの中央値を計算し、中央値に演算を追加すると、その値が直接最大化されます。 他の増分分布では、スコアに対する寄与度の中央値をこれ以上大きくすることはできません。 要素の寄与と残りの中央値のみを考慮するため、要素を削除した場合のエッジ効果は保持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        
        # Sort the array to find the median easily
        a.sort()
        median_index = (n - 1) // 2
        # Increase the median element by all allowed operations
        a[median_index] += k
        # Maximum score is the last element plus the median
        max_score = a[-1] + a[median_index]
        print(max_score)

if __name__ == "__main__":
    solve()
```**説明:** 並べ替えます`a`中央値を決定します。 すべて追加します`k`中央値要素に対する操作を実行して、その寄与を最大化します。 最後に、最大の要素を取得し、変更された中央値を加算することによってスコアが計算されます。 並べ替えは中央値のインデックス付けを処理し、中央値を使用することで、最適な要素を確実に検討できます。`a[i] + median(c_i)`式。 私たちは、非常に大きな整数を処理する Python の機能に依存しています。`k`。 

## 実用的な例

 最初のサンプルの場合:

 | ステップ | (ソート済み) | 中央値インデックス | 増加した中央値 | 最大スコア |
 | --- | --- | --- | --- | --- |
 | イニシャル | [3、3] | 0 | 3+10=13 | 13+3=16 |
 | 出力 | | | | 16 |

 中央値はインデックス 0 にあります。10 個の操作をすべて加算すると 13 になります。最大スコアは、最後の要素 (3) に新しい中央値 (13) を加えたもの = 16 になります。 

2 番目のサンプルの場合:

 | ステップ | (ソート済み) | 中央値インデックス | 増加した中央値 | 最大スコア |
 | --- | --- | --- | --- | --- |
 | イニシャル | [3、3、3] | 1 | 3+0=3 | 3+3=6 |
 | 出力 | | | | 6 |

 操作は許可されないため、配列は変更されません。 中央値は 3、最大要素は 3、合計 = 6。
