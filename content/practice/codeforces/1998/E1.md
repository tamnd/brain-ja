 ## 解決策
 ## 問題の理解

 の行が与えられています$n$それぞれのボールには整数が書かれています。 繰り返し実行できる操作には、セット内の 2 つの隣接する値を選択することが含まれます。$S$そして相対的なサイズに従ってそれらをマージします。 具体的には、現在のセットの場合$S$インデックスのうち、任意のインデックスを選択します$l$それは最大値ではありません。次のインデックスを見つけてください$r$で$S$を選択し、どちらの値が大きいかに基づいて一方を他方にマージします。 これらの操作の目標は、縮小することです$S$単一の要素に至るまで。 プレフィックス長ごとに$i$、関数$f(i)$最終的なシングルトン インデックスの数をカウントします$j$これらのマージを慎重に実行することで実現できます。 

問題の簡単なバージョンでは、$x = n$したがって、テストケースごとに計算する必要があるのは、$f(n)$つまり、配列全体の可能な最終要素の数です。 各テスト ケースはサイズの配列を与えます$n$までの値$10^9$、すべてのテスト ケースの要素の合計数が次を超えません。$2 \cdot 10^5$。 この限界は、線形より悪いアルゴリズムはすべて、$n$制限時間を超える可能性があります。 等しい要素をマージする方法は指数関数的に多く存在するため、考えられるすべてのマージ シーケンスのブルート フォース シミュレーションは実行不可能です。 

すべての選択を試みる単純な実装は、値が繰り返されたり増加したりする配列では失敗します。 たとえば、配列では`[1, 2, 2, 1]`、不注意なアプローチでは単一のシーケンスのみを追跡する可能性がありますが、隣接する値が等しいため、正解には複数の選択肢が含まれるはずです。 

重要なエッジ ケースには、複数の要素が等しい配列、厳密に増加または減少している配列、最小の要素が複数の場所に出現する配列が含まれます。 単純な貪欲シミュレーションでは、これらのシナリオでは静かに過小カウントまたは過大カウントされる可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、考えられるすべての選択をシミュレートします。$l$到達可能なすべてのセットを追跡します$S$。 サイズの接頭辞の場合$i$、 がある$i-1$マージ操作の各ステップで、2 つの要素が等しい場合、選択肢があります。 シーケンスの数は等しい要素の数に応じて指数関数的に増加するため、これは中程度のレベルの場合でもすぐに実行不可能になります。$n$。 

より高速なソリューションを実現する重要な観察は、すべてのシーケンスをシミュレートする必要がないということです。 右から左に見ると、最後まで生き残ることができる位置のセットは、要素がその右側のすべての要素の合計と少なくとも同じ大きさかどうかによって決まります。 言い換えれば、マージが最適に行われたときにその右側のすべての要素を「吸収」するのに十分な大きさであれば、その位置は最終シングルトンになることができます。 これにより、問題が端からの線形スキャンに軽減され、実行中のサフィックスの合計が維持され、要素が必要なしきい値を満たす位置がカウントされます。 

この観察により、問題は指数シミュレーションから線形パスに変換されますが、これは制約を考慮すると許容可能です。

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、次の内容を読んでください。$n$そして配列`a`。 サフィックス合計変数をゼロと空のリストに初期化します。`can_survive`。 
2. 最後の要素から最初の要素まで繰り返します。 要素の場合`a[i]`、少なくとも現在のサフィックスの合計と同じくらい大きいかどうかを確認します。 そうであれば、この位置は最後まで存続できるため、先頭に追加します。`can_survive`。 
3. 以下を追加してサフィックスの合計を更新します。`a[i]`。 これは、その左側に残っている要素によって吸収されなければならない合計値を表します。 
4. 配列をスキャンした後、`can_survive`は`f(n)`、実際の生存指数は次のとおりです。`can_survive`自体。 
5. 各テスト ケースの長さを出力します。 簡易バージョンの場合、必要な出力はこれだけです。 

これが機能する理由は、マージが結合的であり、相対的なサイズのみに依存するためです。 ポジションは、削除されずにその右側のすべての要素を累積的に吸収できる場合にのみ存続できます。 右から左にスキャンして累計を維持することで、この要件を満たす位置を正確に考慮することができます。 必要な合計より小さい要素は、最終的なシングルトンになる前に必然的に削除されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    t = int(input())
    for _ in range(t):
        n, x = map(int, input().split())
        a = list(map(int, input().split()))
        
        suffix_sum = 0
        can_survive = []
        
        # Scan from right to left
        for i in range(n-1, -1, -1):
            if a[i] >= suffix_sum:
                can_survive.append(i+1)  # 1-based index
            suffix_sum += a[i]
        
        print(len(can_survive))

if __name__ == "__main__":
    main()
```の`suffix_sum`生き残った要素が吸収しなければならない合計値を表します。 インデックスを追加する`can_survive`逆順にすると、どの位置が最終シングルトンになり得るかを正確に識別できるようになります。 各インデックスに 1 を追加して、0 ベースの Python インデックス作成から 1 ベースの問題インデックス作成に変換します。 からのループ`n-1`に`0`各要素がそれ自体の前の右側にあるすべての要素の合計を参照し、必要な不変式を取得することを保証します。
