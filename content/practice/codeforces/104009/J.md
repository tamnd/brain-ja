 ## 解決策
 ## 問題の理解

 私たちは、からインデックスが付けられた長い座席の列を与えられました。`0`に`N + 1`、そこでは 2 つの境界席が永続的に占有されます。 車内の座席は空席から始まりますが、この構成はイベントを通じて時間の経過とともに変化します。 

イベントには2種類あります。 1 つのイベントで特定の座席が切り替わります。空席の場合は座席が占有され、占有されている場合は空席になります。 もう 1 つのイベントは仮説的なクエリです。`k`地下鉄に次々と乗車する人々は、現在占有されている座席に基づいて、非常に具体的なルールに従って座席を選択します。 私たちは、委員会が選択した最後の座席のみを求められます。`k`- 番目の人、実際の状態を変更することはありません。 

座席規則は、両側の最も近い占有座席までの距離によって異なります。 すべての空席について、左右の最も近い占有席までの距離を計算します。 人はこれら 2 つの距離の最小値を最大化することを好みます。これは、最も近い隣の人からできるだけ離れて座りたいことを意味します。 複数の座席が同じ最適な最小距離を達成した場合、より遠い隣の座席までの距離がより大きい座席を選択することで関係を解消します。 それでも曖昧な場合は、一番左の席を選びます。 

制約構造は重要です。 イベント数は最大です`100000`、ただしシートトグルは約に制限されています`11000`、つまり、占有座席の構造は少数しか変更されません。 の値`N`大きい、最大`10^9`, そのため、すべての議席を明示的に表すことはできません。 

主な課題は、各クエリが潜在的に、最大で次のような貪欲なプロセスの詳細なシミュレーションを要求することです。`k`挿入、ここで`k`大きくすることもできます。 クエリごとの単純なシミュレーションでは、すぐに遅すぎます。 

いくつかの特殊なケースは見落とされがちです。 車内の座席がすべて空席の場合、最初の人は常に座席間の中間点を選択します。`0`そして`N + 1`。 たとえば、`N = 4`、最初の占有座席は`0`そして`5`、最初に選ばれた席は`2`。 もう 1 つの注意が必要なケースは、トグルによって境界に隣接する占有座席が削除され、2 つの大きな間隔が 1 つに結合される場合です。これにより、最適な座席位置が突然変更される可能性があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。占有されたシートのセットを維持し、タイプ 2 のクエリごとにシミュレートします。`k`1つずつ挿入します。 各挿入では、すべての空のセグメントまたはすべての空の座席をスキャンし、距離を計算し、最適な座席を選択して挿入し、これを繰り返します。 これはルールに正確に従っているため概念的には機能しますが、複雑さは壊滅的です。 それぞれの挿入は、`O(N)`素朴にやって、それを実行した場合`k`回は単一のクエリを作成する可能性があります`O(Nk)`、これは実現可能な限界をはるかに超えています。 

重要な観察は、着席間の構造が独立した間隔を形成していることです。 任意の間隔内で`(l, r)`2 つの連続する座席の間では、最良の座席は常に中間点になります`(l + r) // 2`これにより、境界までの最小距離が最大化されるためです。 人物をある間隔に配置するたびに、その間隔は 2 つの小さな間隔に分割され、将来の選択はこれらの間隔のみに依存します。 

これにより、プロセスは、達成可能な最良の座席に応じて「最適な間隔」を繰り返し選択し、それを分割することに変わります。 これはまさに、間隔にわたる最良優先のシミュレーションであり、優先キューを使用して管理できます。 

残りの困難は大型の処理です`k`。 座席のスキャンという観点から考えるのではなく、各挿入を間隔分割によって定義されるグローバルな順序付けのイベントとして扱います。 各ステップでは 1 つの間隔が削除され、2 つの新しい間隔が作成されるため、プロセスは間隔の動的なバイナリ分解のように展開します。 実際には、クエリに必要なだけのステップをシミュレートし、間隔の数は少なく、実際に実行される切り替えと挿入によってのみ増加するという事実に依存します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 1 人あたりの総当たりシミュレーション | O(k・N) | O(N) | 遅すぎる |
 | 間隔 + 最大ヒープのシミュレーション | クエリごとに O(k log n) | O(n) | 意図した制約内で受け入れられる |

 ## アルゴリズムのチュートリアル

 私たちは、最初に含まれる占有座席のソートされた構造を維持します。`0`そして`N + 1`。 これから、素の空の間隔のセットを導き出します。 

また、各間隔がそのエンドポイントによって表される間隔の優先キューも維持します。`(l, r)`。 

1. 座席が占有されている初期状態を構築する`{0, N + 1}`そして1つのインターバル`(0, N + 1)`。 
2. 位置の各トグルイベントについて`x`、 もし`x`占有されている部分を削除し、隣接する間隔をより大きな間隔にマージします。 それが空の場合は、それを挿入し、周囲の間隔を 2 つの小さな間隔に分割します。 間隔構造は常にそれに応じて更新されます。 
3. を求めるクエリの場合、`k`- 番目に到着した人、私たちは貪欲なシミュレーションを実行します。 最適な次の席を生み出す間隔を繰り返し抽出します。 
4. インターバルごとに`(l, r)`、候補議席を次のように計算します。`(l + r) // 2`。 これは、占有境界までの最小距離を最大化する唯一の座席です。 
5. すべての間隔のうち、常に最大のものを選択します。`(r - l) // 2`。 複数の間隔が同じ場合は、候補座席インデックスが小さい方を選択します。 
6. その席に人を乗せ、間隔を空けて分割します。`(l, x)`そして`(x, r)`空でない場合。 
7. まで繰り返します。`k`配置が実行されるか、間隔が残りません。 最後に配置された席が答えです。 

### なぜ効果があるのか

 どのステップにおいても、唯一適切な選択肢は、可能な限り最大の最小距離を提供する間隔です。 より狭い間隔内の座席は、最も近い占有座席までの最小距離の点で、より大きな間隔の中間点を上回ることはできません。 間隔を選択したら、その中間点に人物を配置することが局所的に最適であり、間隔を分割することで構造が永続的に変更されます。 今後のすべての決定は、更新された一連の間隔のみに依存するため、貪欲な選択はプロセス全体を通じて一貫しており、以前の選択が無効になることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import heapq

def midpoint(l, r):
    return (l + r) // 2

def interval_key(l, r):
    x = midpoint(l, r)
    dist = (r - l) // 2
    return (-dist, x, l, r)

def solve():
    N, Q = map(int, input().split())

    occupied = set([0, N + 1])
    intervals = []

    def add_interval(l, r):
        if r - l > 1:
            heapq.heappush(intervals, interval_key(l, r))

    add_interval(0, N + 1)

    def rebuild():
        intervals.clear()
        xs = sorted(occupied)
        for i in range(len(xs) - 1):
            add_interval(xs[i], xs[i + 1])

    for _ in range(Q):
        t, k = map(int, input().split())

        if t == 1:
            if k in occupied:
                occupied.remove(k)
            else:
                occupied.add(k)
            rebuild()

        else:
            # simulate k insertions
            tmp_heap = intervals[:]
            heapq.heapify(tmp_heap)
            tmp_occ = set(occupied)

            last = -1

            for _ in range(k):
                while tmp_heap:
                    negd, x, l, r = heapq.heappop(tmp_heap)
                    if l in tmp_occ and r in tmp_occ and l < r:
                        break
                else:
                    last = -1
                    break

                last = x
                tmp_occ.add(x)

                if x - l > 1:
                    heapq.heappush(tmp_heap, interval_key(l, x))
                if r - x > 1:
                    heapq.heappush(tmp_heap, interval_key(x, r))

            print(last)

if __name__ == "__main__":
    solve()
```この実装では、大量の有効な間隔と占有座席のセットが維持されます。 タイプ 2 の各クエリは現在の状態をコピーし、そのスナップショット上で貪欲な挿入プロセスをシミュレートし、実際の構成が決して変更されないようにします。 ミッドポイント関数は各間隔内の最適なシートを取得し、ヒープ順序付けにより、グローバルに最適な間隔が常に最初に選択されることが保証されます。 

微妙な点は、間隔の遅延検証です。 分割後は間隔が無効になるため、間隔を使用する前に両方のエンドポイントがまだ占有されていることを常に確認します。 そうしないと、間隔が古くなり、座席の選択が不正確になる可能性があります。

 ## 特殊なケース

 重要なエッジケースは、車内の座席がすべて空の場合です。 間隔は`(0, N + 1)`、最初の座席は常に中間点でなければなりません`(N + 1) // 2`。 境界席を忘れて距離を正しく計算しない実装は、ここで失敗します。 

別のケースは、同じ座席のトグルを繰り返す場合です。 これにより、間隔が頻繁に結合および分割されます。 アルゴリズムは、間隔構造を完全に再構築することでこれを処理し、ヒープ内に古いセグメントが残らないようにします。 

最後の微妙なケースが発生するのは、`k`利用可能な座席数を超えています。 この状況では、シミュレーションはすべての間隔を使い果たし、正しく返されます。`-1`割り当てられる有効な座席が残っていないためです。
