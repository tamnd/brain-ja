 ## 解決策
 ## 問題の理解

 無向グラフのエッジのシーケンスが、固定された順序で表示されます。 エッジの順序を変更することはできませんが、このシーケンスを連続したブロックに分割することはできます。 各ブロックは、その内部のエッジを正確に使用して、独自の独立したグラフを形成します。 

ブロックごとに、それらのエッジによって形成されるグラフが 2 部構成であるかどうかを確認します。 有効なパーティションとは、すべてのブロックが 2 つの部分に分かれているパーティションであり、元のエッジ リストをそのようなブロックの可能な限り最小数に分割する必要があります。 

したがって、タスクは基本的にエッジ ストリームのオンライン セグメンテーションです。エッジを左から右にスキャンし、現在のブロックが 2 部構成でなくなるたびに、ブロックを切り取って新しいブロックを開始します。 

重要な制約は、ノードとエッジの数が両方とも最大 20 万になる可能性があるため、考えられるすべてのセグメントについて二部性を最初から再計算するアプローチは遅すぎるということです。 すべてのセグメント エンドポイントに対する単純な O(M²) の試みには、大きなサブグラフで繰り返し二部性をチェックすることが含まれますが、これは制限をはるかに超えています。 

微妙な失敗例は、複数のエッジにまたがる奇数のサイクルが原因でグラフが非二部になった場合に発生します。 たとえば、エッジ (1,2)、(2,3)、(3,1) は三角形を形成します。 単純なアプローチにより検出が遅れ、後でそれを「修正」しようとすると、3 番目のエッジが追加された時点ですでに二部性条件に違反しているにもかかわらず、エッジが誤って単一のセグメントにマージされる可能性があります。 

## アプローチ

 強引なアイデアは、現在のセグメントを維持し、新しいエッジが作成されるたびにグラフを再構築し、BFS または DFS を使用して二部チェックを実行することです。 二部構成であることは 2 色で簡単に検証できるため、これは論理的に機能します。 ただし、これをエッジごとに実行すると、各 BFS がほぼセグメント全体を横断する可能性があり、それを M 回繰り返すため、最悪の場合、総コストは O(M × (N + M)) になります。 M が 200000 までの場合、これは実現不可能です。 

重要な観察は、セグメントを一度切り取ってしまえば、過去の決定を再検討する必要がないということです。 セグメント内では、新しいエッジの追加によって 2 部構成のカラーリングに矛盾が生じるかどうかだけを知る必要があります。 これはまさに、パリティを備えた Disjoint Set Union 構造 (二部追跡を備えた DSU とも呼ばれます) が設計されたものです。 

私たちは、各ノードがその色を表す 2 つの状態に概念的に分割される DSU を維持します。 各結合操作では、エッジの端点が反対の色を持つ必要があります。 どこかの時点でこの条件が以前の割り当てと矛盾する場合、現在のセグメントは無効になるため、ここでカットする必要があります。 

したがって、現在のセグメントを 2 部構成のまま可能な限り貪欲に拡張します。 矛盾が発生すると、新しいセグメントが開始され、DSU がリセットされます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | セグメントごとの BFS を再計算する | O(平方メートル) | O(N) | 遅すぎる |
 | パリティ + グリーディ セグメンテーションを備えた DSU | O(M α(N)) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 現在のセグメント内の 2 部制約を追跡する DSU を維持しながら、エッジを左から右に処理します。 

1. 現在のセグメントの新しい DSU を初期化します。各ノードは、最初はパリティ制約のない独自のセット内にあります。 
2. 各エッジ (u、v) について、u と v を反対のパリティでマージしようとします。 これにより、現在のセグメントの 2 部カラーリングでは、u と v が異なるカラー クラスに属さなければなりません。 
3. u と v が同じパリティ要件を持つ同じ DSU コンポーネントに既に属している場合、このエッジを追加すると奇数サイクルが作成されます。 この時点で、現在のセグメントはもはや 2 部構成ではないため、前のエッジで終了するセグメントを終了します。 
4. セグメントが終了すると、それを記録し、DSU 状態をクリアして、現在のエッジから新しいセグメントを開始します。 
5. すべてのエッジを処理した後、セグメントの数を出力します。

重要な部分は、パリティがどのように保存されるかです。 各 DSU ノードは、親ポインターと、ノードの色が親の色と異なるかどうかを意味するパリティ値を保持します。 パス圧縮により構造とパリティの両方が一貫して更新されるため、2 つのノードの色が等しいか反対である必要があるかを常に計算できるようになります。 

### なぜ効果があるのか

 各セグメント内では、エッジが到着するにつれて、部分的な 2 部構成のカラーリングが効果的に構築されます。 DSU の不変条件は、処理されたエッジごとに強制された制約が一貫しており、奇数のサイクルが存在しないことです。 矛盾が現れた場合、それはまさにそのセグメント内に奇数のサイクルが発見されたことに相当し、これがグラフが二部構成にならない唯一の理由です。 これが発生するとすぐに切断するため、作成されたすべてのセグメントが二部構成のままであることが保証され、拡張が不可能になった場合にのみ切断するため、各セグメントの最大値が続きます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.rank = [0] * n
        self.parity = [0] * n  # parity to parent

    def find(self, x):
        if self.parent[x] == x:
            return x
        px = self.parent[x]
        root = self.find(px)
        self.parity[x] ^= self.parity[px]
        self.parent[x] = root
        return root

    def get_parity(self, x):
        self.find(x)
        return self.parity[x]

    def union(self, a, b):
        ra = self.find(a)
        rb = self.find(b)

        pa = self.get_parity(a)
        pb = self.get_parity(b)

        if ra == rb:
            return (pa ^ pb) == 1

        if self.rank[ra] < self.rank[rb]:
            ra, rb = rb, ra
            a, b = b, a
            pa, pb = pb, pa

        self.parent[rb] = ra
        self.parity[rb] = pa ^ pb ^ 1

        if self.rank[ra] == self.rank[rb]:
            self.rank[ra] += 1

        return True

def solve():
    n, m = map(int, input().split())
    edges = [tuple(map(int, input().split())) for _ in range(m)]

    dsu = DSU(n + 1)
    res = 1

    for u, v in edges:
        if not dsu.union(u, v):
            res += 1
            dsu = DSU(n + 1)
            dsu.union(u, v)

    print(res)

if __name__ == "__main__":
    solve()
```DSU は、親リンクに関連するパリティ情報を保存します。 Union 関数は、エッジの追加がまだ有効かどうかを返します。 False が返された場合は、矛盾が見つかったことを意味し、すぐに新しいセグメントを開始します。 

微妙な点は、切断時に DSU を完全にリセットすることです。 セグメントは独立したグラフであるため、セグメント間で情報が引き継がれることはありません。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import inf

    class DSU:
        def __init__(self, n):
            self.parent = list(range(n))
            self.rank = [0]*n
            self.parity = [0]*n

        def find(self, x):
            if self.parent[x] == x:
                return x
            px = self.parent[x]
            r = self.find(px)
            self.parity[x] ^= self.parity[px]
            self.parent[x] = r
            return r

        def get_parity(self, x):
            self.find(x)
            return self.parity[x]

        def union(self, a, b):
            ra, rb = self.find(a), self.find(b)
            pa, pb = self.get_parity(a), self.get_parity(b)
            if ra == rb:
                return (pa ^ pb) == 1
            if self.rank[ra] < self.rank[rb]:
                ra, rb = rb, ra
                pa, pb = pb, pa
            self.parent[rb] = ra
            self.parity[rb] = pa ^ pb ^ 1
            if self.rank[ra] == self.rank[rb]:
                self.rank[ra] += 1
            return True

    n, m = map(int, inp.splitlines()[0].split())
    edges = [tuple(map(int, x.split())) for x in inp.splitlines()[1:]]

    dsu = DSU(n+1)
    ans = 1

    for u, v in edges:
        if not dsu.union(u, v):
            ans += 1
            dsu = DSU(n+1)
            dsu.union(u, v)

    return str(ans)

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、最初のエッジによって現在の DSU 状態にすでに矛盾が生じている場合です。 その状況では、アルゴリズムはそのエッジのみを含む新しいセグメントを即座に開始し、リセットされた DSU によって古いパリティ情報が前方に漏洩しないようにします。 

もう 1 つのケースは、複数の奇数サイクルが重なったグラフです。 たとえば、密集した三角形のような構造は、セグメントの繰り返しカットを引き起こす可能性があります。 カットごとにすべての制約がリセットされるため、前のエッジが複雑な競合を形成した場合でも、現在のアクティブなセグメントのみが問題になります。 

最後の微妙なケースは、最後のエッジがサイクルを閉じる長いチェーンです。 DSU パリティは、同じコンポーネントの反対パリティ要件に違反した場合にのみ不整合を検出するため、このアルゴリズムは、矛盾が完了する正確なエッジまで障害を正しく遅延させます。
