 ## 解決策
 ## 問題の理解

 私たちには、それぞれ異なる身長を持つキツネザルの系統が与えられています。 キツネザルは現在、高さによって並べ替えられるのではなく、任意の順序で並べられています。 王は、このラインナップを、連続するキツネザルの選択された各セグメントが高さの昇順に内部的にソートされるものに変換したいと考えています。 

この操作は、配列全体のスワップを直接行うものではありません。 代わりに、最初に配列をいくつかの連続したセグメントに分割します。 各セグメントの料金は、作成するセグメントの数に比例した固定価格となります。 分割後、各セグメント内で隣接するスワップを実行でき、各スワップに 1 ユニットのコストがかかるため、各セグメントを自由にソートできますが、セグメント内で修正するすべての反転に対して支払いを行います。 

したがって、タスクは、総コストがセグメント数に定数を乗算し、各セグメントを並べ替えるのに必要な隣接するスワップの数を加えた合計となり、この総コストが最小化されるように、配列をセグメントに分割する場所を決定することです。 

入力は、キツネザルの数とセグメントを開始するためのコスト パラメーター、その後に高さの順列で構成されます。 出力は、隣接スワップを使用してすべてのセグメントをソートするために可能な最小の総コストです。 

n の制約は十分に大きいため、セグメントごとの 2 次または 2 次に近い推論は失敗します。 配列には最大約 3×10^5 個の要素を含めることができるため、考えられるすべてのセグメンテーション内で並べ替えを行う O(n^2) シミュレーションは不可能です。 どのような解決策も、通常は貪欲な構造または反転のグローバルな特性を使用した、線形または線形に近い償却推論に依存する必要があります。 

配列がすでにソートされている場合、微妙なエッジケースが発生します。 その場合、多くのセグメントに分割してもスワップコストはさらに削減されませんが、依然として固定セグメントコストは増加します。 局所的な障害が現れるたびに新しいセグメントを貪欲に開始する単純なアプローチでは、セグメント化が過剰になり、すべてを 1 つのセグメントに維持するという最適な選択を逃す可能性があります。 

配列が逆ソートされると、別のエッジ ケースが発生します。 この場合、ソートコストは最大になりますが、早期に分割することでセグメントごとの反転コストを削減できます。 ただし、分割が多すぎるとセグメントのオーバーヘッドが原因で優勢になる可能性があるため、ソリューションでは反転削減と固定コストのバランスを慎重にとる必要があります。 

## アプローチ

 ブルートフォースアプローチでは、配列を連続したセグメントに分割するためにあらゆる方法が試行されます。 セグメントごとに、各セグメントを個別に並べ替えるのに必要な隣接スワップの数を計算します。これは、そのセグメント内の反転をカウントするのと同じです。 これは正しいです。各セグメントは最終的には隣接するスワップを使用して完全にソートされ、反転数はまさにそのようなスワップの最小数であるからです。 

ただし、固定セグメンテーションの場合、反転カウントの計算には、フェンウィック ツリーまたはマージ ソートを使用して少なくとも線形または対数線形の時間が必要です。 セグメンテーションの数は指数関数的に増加するため、これはすぐに実行不可能になります。 セグメントエンドポイント上の動的プログラミングに限定した場合でも、O(n^2) の遷移が発生し、n が数十万までは遅すぎます。 

重要な洞察は、任意のセグメンテーションの観点から考えるのをやめ、代わりに、2 つの隣接するセグメントをマージすることが有益な場合を考えることです。 ある位置までの最適解がすでにあると仮定します。 最後のセグメントを拡張すると、インバージョン寄与分を除いてコストが変わらないか、削減する場合は追加のセグメントコストを支払わなければなりません。 決定は、マージによって生じる反転コストの増加が固定セグメントコストを上回るかどうかによってのみ決まります。

これにより問題は、反転回数を段階的に追跡する構造の維持に変わり、現在のセグメントを拡張することが有益かどうかを貪欲に決定できるようになります。 重要な観察は、反転の寄与はセグメント全体にわたって加算的であり、セグメントをマージすると、境界を越えた反転のみが変化するということです。 これにより、ランニングコストを抑えながら効率的に更新できるリニアスキャンが可能になります。

 ## アルゴリズムのチュートリアル

 1. 現在のセグメントと、要素が追加されるときに動的に反転をカウントできるデータ構造を維持します。 これが必要なのは、セグメントのコストがその反転数に完全に依存するためです。 
2. 配列を左から右に繰り返し、各要素を現在のセグメントに追加し、この挿入によって発生した反転カウントを更新します。 反転更新は、フェンウィック ツリーまたは値のバランスの取れた構造を使用して行われます。 
3. 各ポジションにおいて、現在のセグメントを継続することが有益であるかどうかを検討します。 決定は、現在のセグメントに要素を保持するコストと、ここで新しいセグメントを開始するコストの比較に基づいて行われます。これにより、反転累積はリセットされますが、固定セグメント コストが追加されます。 
4. 新しいセグメントを開始すると、反転追跡構造がリセットされ、その時点から処理が続行されます。 これにより、継続の限界反転コストが大きくなりすぎる配列が効果的に削減されます。 
5. すべてのセグメントコストと各セグメント内で計算されたすべての反転寄与の合計として総コストを累積します。 

これらの手順の後、すべての有効なセグメンテーションにわたる最小の総コストが得られます。 

### なぜ効果があるのか

 この正しさは、セグメント内の反転コストが他のセグメントから独立しているのに対し、セグメント間の反転はカットが行われると消滅するという事実から得られます。 各要素は、同じセグメント内のその後の要素に関係する反転にのみ寄与するため、カットを決定すると、以前の要素との今後の相互作用は永久に排除されます。 これにより、単調な構造が形成されます。継続よりも削減の方が安くなると、総コストを削減する方法で後で再度統合することは決して有益ではなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

def solve():
    n, x = map(int, input().split())
    a = list(map(int, input().split()))

    fw = Fenwick(n)
    cur_inv = 0
    segments = 1
    total = 0

    for i, v in enumerate(a):
        greater = fw.sum(n) - fw.sum(v)
        cur_inv += greater

        fw.add(v, 1)

        # decide whether to cut here
        # cut if keeping would be worse than paying new segment cost
        if cur_inv >= x:
            total += cur_inv
            segments += 1
            fw = Fenwick(n)
            cur_inv = 0

    total += cur_inv + segments * x
    print(total)

if __name__ == "__main__":
    solve()
```フェンウィック ツリーは、現在のセグメントに各値の要素がいくつ出現したかを維持します。 新しい値を挿入するときに作成される反転の数は、前に確認されたより大きい要素の数と正確に一致し、接頭辞の合計を使用して計算されます。 

貪欲なカット条件は、反転コストの蓄積と固定セグメントコストの支払いとの間のトレードオフを反映しています。 現在のセグメント内に蓄積された反転が高くなりすぎる場合、リセットするのが最適です。 

よくある落とし穴は、カットごとに反転カウントをリセットする必要があることを忘れていることです。 もう 1 つの微妙な問題は、ループの後に処理される最後のセグメントを含め、セグメント コストがセグメントごとに 1 回だけカウントされるようにすることです。

 配列は完全に反転しているため、反転が急速に増大し、早期のカットを余儀なくされます。 これは、局所的な無秩序が極端な場合、分割によって反転の蓄積が減少することを裏付けています。

| ステップ | 値 | 現在の反転 | アクション | セグメント |

 これは、最適な戦略が単一セグメントである基本ケースを示しています。

 ## 特殊なケース

 次のようなすでにソートされた入力の場合`1 2 3 4 5`、反転カウンタは決して増加しないため、アルゴリズムはカットをトリガーせず、セグメントを 1 つだけ生成します。セグメントを追加しても固定コストが増加するだけであるため、これが最適です。 

逆ソートされた入力の場合は次のようになります`5 4 3 2 1`、反転は各ステップで蓄積されるため、アルゴリズムは早期にカットされる傾向があります。 各カットは構造をリセットし、反転コストの二次的な増加を防ぎます。これは、無秩序がグローバルである場合に各セグメントを短くすべきであるという直観と一致します。 

のようなケースの場合`1 3 2 5 4 6`、反転は小さな孤立したペアで表示されます。 このアルゴリズムは、累積コストの増加が遅いため、セグメントをより長く保持します。これは、このアルゴリズムがグローバルな無秩序構造ではなくローカルな無秩序構造に敏感であることを示しています。
