 ## 解決策
 ## 問題の理解

 送信者がバイナリ文字列を受信し、それを非常に信頼性の低いチャネルを通じて送信する必要があるシステムが与えられています。 チャネルは、送信されたパケットの境界を保持しません。 代わりに、実際に送信されたものの循環シフトが到着します。 つまり、受信者には同じ文字が同じ順序で表示されますが、文字列は未知の位置で回転されています。 

エンコード手順により、元のバイナリ文字列を同じ長さの別の文字列に変換できますが、今回は 3 つの記号のアルファベットを使用します。 デコードのステップでは、エンコードされた文字列の循環ローテーションが与えられ、元のバイナリ メッセージを正確に復元する必要があります。 

重要な問題は、調整が失われることです。 エンコードされたメッセージがどこから始まったのかわからないため、どのようなソリューションも巡回シフトに対して堅牢である必要があります。 これにより、文字列内の絶対位置が文字列自体から復元できない限り、文字列内の絶対位置に依存するエンコーディングが即座に除外されます。 

n が 100000 までの制約は、線形または線形に近い構造が必要であることを意味します。 すべての回転を明示的にチェックしたり、すべてのシフトにわたってブルート フォース パターン マッチングによって位置合わせを試みたりすると、すべての n 回転と比較すると O(n^2) の動作が発生するため、遅すぎます。 

文字列を「固定」する方法を考えると、微妙なエッジケースが現れます。 特殊なシンボルで位置をマークし、それを基準にして再構築しようとすると、単純な考えでは位置が固定されていると仮定してしまいます。 しかし、このチャネルはその前提を打ち破ります。 マーカーはまだ存在しますが、そのインデックスは任意にシフトされるため、文字列の構造が回転不変の方法で原点を回復可能にしない限り、絶対的な原点を表すことはできません。 

もう 1 つの重要なエッジ ケースは n = 1 です。この場合、回転は簡単ですが、エンコードでは正しくデコードできる有効な 3 値文字列を生成する必要があるため、複数の部分への分割に依存する構築ではこれを明示的に処理する必要があります。 

## アプローチ

 直接的な総当たりのアイデアは、受信した文字列のすべての可能な回転を試し、それぞれをエンコード候補として解釈し、どれがバイナリ メッセージの有効なデコードに対応するかを確認することです。 これは、各回転の解釈と検証に O(n) の作業が必要であり、n 個の回転があるため、最悪の場合の O(n^2) の解決策にすぐに陥ります。 

重要な点は、実際にはすべての回転を試す必要はないということです。 代わりに、循環構造に一意の識別可能なアンカーが含まれるようにエンコードを設計することができます。これにより、文字列がどのように回転されたかに関係なく、文字列の一貫した線形化を回復できます。 一貫した線形順序を復元できれば、問題はバイナリ文字列と固定長の 3 値文字列間の決定論的なエンコードとデコードに帰着します。 

重要なアイデアは、3 進アルファベットの追加容量を使用することです。 長さ n のバイナリ文字列には 2^n 個の値があり、長さ n の 3 値文字列には 3^n 個の値があります。 循環等価性 (n 回転) を考慮した後でも、すべてのバイナリ文字列を 3 値文字列の回転クラスに一意に埋め込むのに十分なスペースがまだあります。 これにより、バイナリ メッセージを構造化された方法でエンコードし、正規化後に復元することができます。 

回転後も存続し、O(n) 時間で見つけられる一意の構造マーカーが含まれるように、エンコードされた文字列を構築します。 このマーカーを使用すると、受信した文字列を回転して標準形式に戻すことができます。 正規化後、デコードは直接逆マッピングになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 回転に対するブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | アンカーを使用した構造化巡回エンコーディング | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

循環文字列内に単一の明確なアンカーを作成し、残りの位置を使用してバイナリ メッセージのロスレス表現を保存するエンコーディングを構築します。 

1. バイナリ文字列を [0, 2^n) の範囲の整数値 x として解釈します。 これにより、メッセージを単一の数値として推論するコンパクトな方法が得られます。 
2. n による除算を使用して、x を 2 つの部分に分割します。 p = x mod n および r = x // n を定義します。 x = r * n + p であり、すべての有効なペア (r, p) が許容範囲内の固有の x に対応するため、この分解は可逆的です。 
3. 長さ n の 3 進文字列を構築します。ここで、ちょうど 1 つの位置が特殊記号「2」用に予約されており、他のすべての位置には r のビットがバイナリ形式で格納されます。 「2」の位置は p で、残りの n − 1 個の位置は r のビットで順番に埋められます。 
4. この 3 値文字列を送信します。 チャンネルが任意に回転させます。 
5. デコード時に、受信した文字列をスキャンし、一意に出現する「2」を見つけます。 この位置がアンカーとなります。 アンカーがインデックス 0 になるように文字列を回転し、正規表現を生成します。 
6. 残りの n − 1 シンボルには「0」と「1」のみが含まれるため、2 進数 r として読み取ります。 
7. 元の整数を x = r * n + p として再構築します。ここで、p は正規表現におけるアンカー位置です。 
8. x を n ビットのバイナリ文字列に変換して出力します。 

重要な考え方は、単一の「2」が回転下でも不変の同期ポイントとして機能し、デコードの一貫した原点を定義できるということです。 

### なぜ効果があるのか

 正確かどうかは、エンコードされた文字列に、バイナリ ペイロードの一部ではないシンボルが 1 つだけ含まれているという事実に依存します。 これにより、循環シフトには必ず 1 つの識別可能なアンカーが含まれることが保証されます。 アンカーが見つかったら、それを前方に回転させると、すべての回転クラスに固有の標準形式が生成されます。 

残りの位置は r の固定長バイナリ表現を形成し、文字列が整列されると回転の影響を受けません。 分解 x = r * n + p は許容範囲にわたって全単射であるため、r と p を復元すると元のメッセージが一意に決まります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def encode(n, s):
    x = int(s, 2)
    p = x % n
    r = x // n

    bits = list(bin(r)[2:])
    bits = ['0'] * (n - 1 - len(bits)) + bits

    res = ['0'] * n
    j = 0

    for i in range(n):
        if i == p:
            res[i] = '2'
        else:
            res[i] = bits[j]
            j += 1

    return ''.join(res)

def decode(n, s):
    s = list(s)
    p = s.index('2')

    # rotate so that '2' is at front
    s = s[p:] + s[:p]

    bits = []
    for i in range(1, n):
        bits.append(s[i])

    r = int(''.join(bits), 2)

    x = r * n + p
    return bin(x)[2:].zfill(n)

op = input().strip()
n = int(input())
s = input().strip()

if op == "Encode":
    print(encode(n, s))
else:
    print(decode(n, s))
```エンコードでは、メッセージを商と剰余の形式に明示的に分離します。 余りによって一意のマーカーを配置する場所が決まり、商が文字列の残りの部分を埋めます。 これにより、完全な単射性とデコード用の安定したアンカーの両方が保証されます。 

デコードにおける唯一の構造的な作業は、マーカーの位置を特定して回転することです。 その後のすべては単純なバイナリの再構築です。 

## 実用的な例

 ### 例 1

 n = 5 でバイナリ文字列が s = 10110 であると仮定します。 

x = 22 を計算します。次に、p = 22 mod 5 = 2 および r = 22 // 5 = 4、つまり 2 進数の 100 となります。 

「2」を位置 2 に配置し、r のビットを残りの位置に分配します。 

| ステップ | 配列の状態 |
 | --- | --- |
 | 開始 | _ _ _ _ _ |
 | p=2 に 2 を配置します。 _ _ 2 _ _ |
 | r ビットを埋める | 1 0 2 0 0 |

 次に、チャネルがそれを 00210 のような値に回転すると仮定します。 

デコーダは「2」を見つけて、それを前に回転して戻し、r = 100 を読み取り、x = 4 * 5 + 2 = 22 を復元し、10110 を再構築します。 

このトレースは、回転が回復性に影響を与えるのではなく、アライメントにのみ影響を与えることを示しています。 

### 例 2

 n = 4、s = 0110 とします。 

次に、x = 6、p = 6 mod 4 = 2、r = 6 // 4 = 1 (バイナリ 01) となります。 

私たちは以下を構築します:

 | ステップ | 配列の状態 |
 | --- | --- |
 | 開始 | _ _ _ _ |
 | 2位 | _ _ 2 _ |
 | rを塗りつぶす | 0 1 2 0 |

 回転後、2010 を受信したとします。デコーダーは一意の「2」を見つけて回転し、r = 01 を抽出し、x = 1 * 4 + 2 = 6 を再構築して 0110 を返します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各パスで文字列が 1 回処理され、整数変換は n | で線形に行われます。 
| スペース | O(n) | エンコード/デコードされた文字列とバイナリ バッファを保存します。

 ## 特殊なケース

 n = 1 の場合、r ビットを格納する残りの位置がないため、構築は縮退します。 この場合、バイナリ文字列には可能な値が 2 つしかないため、エンコーダは 0 → "0" および 1 → "1" を直接マッピングすることも、回転では何も行われないためマーカー ストラテジを自明に配置することもできます。 単一の文字が常にアンカーであるため、デコーダは引き続き機能します。 

r が正確に n − 1 ビットを必要とする文字列の場合、パディング ステップによりバイナリ表現がオーバーフローせずに適合することが保証されます。 n で除算すると、r が常にこの固定幅表現に対して十分に小さいことが保証されるため、切り捨ては発生しません。 

マーカーが位置 0 にある場合、回転は何も行わず、デコードは同様に進行します。 他の位置にある場合は、回転ステップによって一貫したビューが復元されるため、特別なケースは必要ありません。
