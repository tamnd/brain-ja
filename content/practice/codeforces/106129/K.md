 ## 解決策
 ## 問題の理解

 行に沿った建物の高さとして解釈される、1 から n までの数値の単一の順列を作成するように求められます。 2 つの整数 a と b は、それぞれ左端と右端から見たときに見える建物の数を表します。 建物は、その視点方向にある建物よりも厳密に高い場合、側面から見ることができます。 

左から左から右にスキャンして、新しい最大値に遭遇する頻度を数えます。 右から右から左にスキャンして、同じ種類の記録的最高値を数えます。 タスクは、左から正確に 1 つの見える建物、右から正確に b の見える建物を生成する順列が存在するかどうかを判断し、存在する場合はそのような順列を出力することです。 

制約 n ≤ 1000 は十分小さいため、O(n^2) の構築または単純な貪欲な構築戦略さえも許容されます。 ただし、問題の構造は、検索ではなく、直接組み合わせて構築することを示唆しています。 出力は 1 つの有効な順列にすぎないため、可能性を列挙する必要はありません。 

キーエッジ状況は、a と b が両方とも大きい場合に現れます。 たとえば、a = n および b = n の場合、両側ですべての要素が新しい最大値である必要がありますが、グローバル最大値は 1 つの位置にしか存在できないため、これは不可能です。 同様に、n > 1 で a = 1 および b = 1 の場合、両方の側で最大値がエッジのすぐ近くにあることが必要ですが、同時に発生することはできません。 これらの失敗は、a、b、n を結び付ける構造的な制約があることを示唆しています。 

## アプローチ

 強引なアイデアは、1 から n までのすべての順列を生成し、両側からの可視性をチェックすることです。 これは、順列ごとに O(n) の目に見える建物の数を直接計算できるため、概念的には正しいです。 ただし、nがあります！ 順列は、n = 10 の場合でも、10 以降は完全に実行不可能になります。 はすでに 360 万であり、n = 1000 は列挙アプローチをはるかに超えています。 

重要な観察は、視認性はスキャン中に「記録的最高値」がどれだけ表示されるかによって完全に決まるということです。 左側からはちょうど a の記録的最高値が必要で、右側からはちょうど b つの記録的最高値が必要です。 これらの記録的最高値は、グローバル最大値 n が常に両側から見え、中央のアンカーとして機能するという事実を除いて、独立して動作します。 

これは、最初に n の位置を固定し、配列を左側のセグメントと右側のセグメントに分割し、次に必要な数の記録的最高値を個別に生成できるように各辺を慎重に構築することを示唆しています。 n が固定されると、各辺が増加する最大値の必要な数に正確に寄与するように、残りの数値を配置できます。 

重要な構造上の制約は、可視性によって「消費」される位置の数を数えることから得られます。左側は n の前に a-1 個の追加の可視要素を提供し、右側は n の後に b-1 個の追加の要素を提供します。つまり、少なくとも a+b-1 個の位置が必要であり、これは n を超えてはなりません。

 ## アルゴリズムのチュートリアル

 順列を直接構築します。

1. まず、a + b − 1 ≤ n が成立するかどうかを確認します。 そうでない場合、必要なすべての目に見える「記録的最高値」と世界最大値を配列に収める方法はありません。 その場合は即座に「いいえ」を返します。 
2. 最大の要素 n の位置を固定します。 これをインデックス a (1 から始まるインデックス) に配置します。 これは、左側から正確に目に見える建物が必要であり、n を a 番目に見える建物として配置すると、それがその数に寄与する最終的な記録の高さになることが保証されるためです。 
3. n の左側のセグメント、つまり位置 1 から a-1 に、昇順に最小の数字 1、2、...、a-1 を入力します。 これにより、左からスキャンすると、このプレフィックス内のすべての要素が新しい最大値となり、n に達する前に正確に a-1 個の目に見える建物が生成されることが保証されます。 
4. 残りの最大の数値を降順に使用して、n の右側のセグメントを埋めます: n−1、n−2、...、n−(b−1)。 これにより、右からスキャンすると、これらの各要素が順番に新しい最大値になり、n の後に正確に b−1 個の目に見える建物が生成されることが保証されます。 
5. 残りの未使用の位置に、視認性に影響を与えない任意の順序で残った数字を入力します。 実際には、2 つの構造化セグメントが n の周囲に配置されると、a + b − 1 = n の場合、すべての数値がすでに使用されています。 それ以外の場合、中央のギャップは残りの利用可能な最小の数値で埋められます。 

### なぜ効果があるのか

 この構造では、順列を 3 つの領域 (厳密に増加するプレフィックス、最大要素 n、および厳密に減少するサフィックス) に分割します。 すべての新しい要素が以前のすべての要素を超えるため、プレフィックスは左から正確に a-1 のレコード高を保証します。 右からのスキャン中に検出されるすべての新しい要素は、その方向から遠く離れたすべての要素よりも大きいため、サフィックスは右から正確に b-1 個の記録的高さを保証します。 中心要素 n は一意のグローバル最大値であり、両方の可視性カウントにカウントされ、干渉することなく両方の制約を調整するブリッジとして機能します。 すべての数値が 1 回だけ使用され、可視性の寄与が両側で独立して制御されるため、結果として得られる置換は、長さの制約 a + b − 1 ≤ n が満たされる場合に常に有効です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, a, b = map(int, input().split())
    
    if a + b - 1 > n:
        print("no")
        return

    ans = [0] * n

    # place n
    pos = a - 1
    ans[pos] = n

    # left side: 1..a-1 increasing
    cur = 1
    for i in range(a - 1):
        ans[i] = cur
        cur += 1

    # right side: n-1 .. n-b+1 decreasing
    cur = n - 1
    for i in range(n - 1, n - b, -1):
        ans[i] = cur
        cur -= 1

    # fill remaining positions
    used = set(ans)
    cur = 1
    for i in range(n):
        if ans[i] == 0:
            while cur in used:
                cur += 1
            ans[i] = cur
            used.add(cur)

    print("yes")
    print(*ans)

if __name__ == "__main__":
    solve()
```このコードは、まず実現可能条件 a + b − 1 ≤ n を強制します。 次に、ゼロベースのインデックス付けで n を位置 a − 1 に配置することで、順列を固定します。 左側のプレフィックスは 1 から順に埋められ、厳密に増加する動作が保証されます。 右のサフィックスは、値が左から右に厳密に減少するように n − 1 から下に埋められます。これは、右から左の可視性を厳密に増加することと同じです。 残りのギャップは未使用の値で埋められます。ギャップは制御された増加領域と減少領域の間に厳密に存在し、構築された記録的な高さの構造を破壊するほど大きくないため、可視性に影響を与えることはできません。

 ## 特殊なケース

 a = 1 および b = 1 の場合、構築により強制的に n が両側から唯一見える建物になります。これは、他のすべての要素が両方向でその背後に隠れている場合にのみ機能します。 アルゴリズムは n を位置 0 に配置し、両側を空にするか最小限に埋めたままにします。 接頭辞や接尾辞を増やす必要がないため、構造はきれいに縮退します。 

a + b − 1 = n の場合、順列は完全に決定されます。すべての位置が、増加するプレフィックス、中心最大値、または減少するサフィックスのいずれかで使用されます。 柔軟な位置は残っておらず、正確な分割に至るまで構造は独自のものになり、アルゴリズムは連続したセグメントを埋めることによって自然に強制します。 

n が大きく、a と b が小さい場合、ほとんどの要素は中央の非拘束領域にあります。 これらの値は、構造化された部分の後に任意に入力されます。制御されたプレフィックスとサフィックスの外側に新しい記録を作成するほど大きくないため、可視性に影響を与えることはできません。
