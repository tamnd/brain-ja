 ## 解決策
 ## 問題の理解

 それぞれが負ではない整数である一連の呪文値と、非常に特殊な使用パターンを持つシールドが与えられます。 シールドがアクティブになると、連続したブロックを正確にブロックします。`d`呪文を発動するたびに、次の呪文に備えて休まなければなりません。`d`その間は魔法が使えなくなる。 最初の起動は最初の呪文の直前に許可されるため、すべての決定はいくつかの開始位置の選択に関するものであり、選択された開始位置は少なくとも 1 つであるという制約があります。`2d`別に。 

ブロックされていないすべての呪文は私たちに「ヒット」し、私たちはそれらの値を収集します。 最終的なダメージは合計や最大値ではなく、すべてのヒット値の最大値、つまりそれらの中に現れない最小の非負の整数です。 私たちの目標は、この mex ができるだけ小さくなるようにシールドのアクティベーションを調整することです。 

出力は単一の数値、つまりブロックされていない呪文値のマルチセットの達成可能な最小 mex です。 

制約が示唆するのは、`n`まで`10^5`したがって、線形または線形に近いものよりも悪い解決策は失敗します。 特に、アクティベーションのすべてのサブセットを試行したり、mex の再計算を繰り返しシミュレートしたりするものは、すぐに遅すぎます。 期待すべきことは、`O(n log n)`または`O(n)`解決。 

重要な微妙な点は、mex は周波数ではなく存在のみに依存するということです。 値はヒット呪文の中に現れるか現れないかのどちらかであるため、シールドは事実上、ヒット セットからどの値を完全に削除できるかを決定します。 

よくある失敗例は、小さな値が独立して「出現したものをすべて削除」できると想定していることです。 たとえば、値があまりにも多くの位置に表示され、その間隔が狭い場合は、`d`、一部のオカレンスを通過させる必要があり、その値がヒット セットで避けられなくなる場合があります。 

もう 1 つの微妙なエッジケースは次のような場合です。`d = 1`。 その後、すべての呪文を交互にブロックできるため、偶数または奇数の位置をすべて削除でき、潜在的に mex が可能になります。`0`取り決め次第。 逆に言うと、`d = n`、すべてをブロックすることも、何もブロックしないこともでき、mex を完全な存在または不在によって純粋に決定することができます。 

## アプローチ

 ブルートフォースのアイデアは、任意の 2 つのアクティベーションが少なくとも 1 つでなければならないという制約を考慮して、各ポジションをブロックされているかどうかのいずれかとして扱うことです。`d`別に。 有効なアクティブ化パターンごとに、ブロックされないままの値のセットを計算し、その mex を評価します。 これは定義に直接従うため正しいですが、有効なパターンの数は次のように指数関数的に増加します。`n/d`。 枝刈りを行ったとしても、最悪の場合は依然として指数関数的な複雑さに近づき、実行不可能になります。 

重要な観察は、視点を逆転させることです。 どの呪文をブロックするかを選択する代わりに、ターゲットのメックスを尋ねます。`m`。 メキシコを達成するために`m`、すべての値が必要です`0, 1, ..., m-1`ヒットした呪文の中で少なくとも 1 回出現し、価値がある`m`ヒットスペルの中に存在しないこと。 したがって、各候補者について`m`、問題は、値の出現をすべてブロックできるかどうかを確認することになります。`m`ただし、小さい値ごとに少なくとも 1 つの出現がブロックされないままにしておきます。 

これで、構造が幾何学的なものになります。 各値は、一連の禁止ブロックの決定を引き起こします: 値を削除するため`x`、すべての発生`x`ブロックされた間隔内になければなりません。 ブロックされた間隔は固定長であり、あまりにも密に重なり合うことはできないため、一部の値の出現をすべて「カバー」し、他の値の少なくとも 1 つの出現を維持する間隔の開始点を選択します。 

重要な単純化は、固定されたオブジェクトに対して次のことを理解することです。`m`を含むすべてのポジションをカバーできるかどうかだけを気にします。`m`誤ってすべての発生をカバーすることなく、利用可能なブロック間隔を使用します。`0..m-1`。 これは、各値の位置に関する貪欲なスケジューリングの問題になります。 

値を昇順に処理し、各値が表示される最も早い位置を維持できます。 固定の場合`m`、ブロックを貪欲に配置して、すべての発生を排除しようとします。`m`、すべての小さい値について、少なくとも 1 つの未検出の出現が残るようにします。 実現可能性のチェックは、発生回数に応じて直線的に実行できます。 

毎回最初から再計算するのではなく、`m`、出現をソートし、ブロック配置を一度シミュレートし、どの値が完全に除去できなくなるかを追跡します。`m`成長します。 答えは最小です`m`それはヒットセットでは避けられません。

 ## アルゴリズムのチュートリアル

 この問題を、ブロッキング制約の下でヒット セットから値を完全に削除できるかどうかに関する推論に変換します。 

### ステップ 1: 値ごとにポジションをグループ化する

 配列に現れる各値のインデックスのリストを作成します。 これにより、グローバル ブロック間隔を尊重しながら、各値のカバレッジを個別に推論することができます。 

### ステップ 2: 値を削除する意味を理解する

 価値を確保するには`x`が出現するたびに、最終的なヒット セットには表示されません。`x`ブロックされたセグメント内に存在する必要があります。 各ブロックは固定長なので`d`、位置から始まる各ブロック`i`カバー`[i, i+d-1]`。 それで削除`x`すべてのインデックスを集合的にカバーするブロック開始を選択することを意味します。`x`が表示されます。 

制約は、ブロックの開始が少なくとも異なる必要があることです。`d`, したがって、ブロックはタイムラインに沿ってまばらなセットを形成します。 

### ステップ 3: 固定値に対する貪欲な実現可能性

 単一の値の場合`x`、最小限のブロック数を使用して、そのすべての出現をカバーしようとします。 位置で未発見の発生が見つかった場合は常に、発生を昇順にスイープします。`p`、から始まるブロックを配置します。`p`、可能な限り右端をカバーします。 

この貪欲な選択は、最初にカバーされていないオカレンスをカバーしながらできるだけ遅くブロックを配置すると、将来のオカレンスのカバー範囲が最大化され、実現可能性が損なわれることがないため、最適です。 

### ステップ 4: グローバル制約の相互作用

 価値を得るために配置する各ブロック`x`他のすべての値にも影響し、それらも削除される可能性があります。 ここで mex が登場します: 排除の過程にある場合`x`、また、より小さい値の出現もすべて削除します。`y`、 それから`y`最終ヒット セットに含めることはできなくなり、mex を達成することになります。`> y`不可能。 

したがって、シミュレーション中に、各値について、選択したすべてのブロックの外側に少なくとも 1 つの出現があるかどうかを追跡します。 

### ステップ 5: mex を決定する

 値を昇順に処理します。 各候補者メキシコについて`m`、値が次の値であるかどうかをテストします。`0..m-1`すべての値は、少なくとも 1 つのカバーされていないオカレンスを保持できます。`m`完全にカバーできます。 最初の失敗点が答えを示します。 

### なぜ効果があるのか

 このアルゴリズムは単調なカバレッジ特性に依存しています。つまり、オカレンスをカバーするためにブロックが配置されると、固定間隔の位置が削除され、ブロックを左から右に貪欲に配置することで、将来必要となるカバーされていないオカレンスとの干渉が最小限に抑えられます。 mex は多重度ではなく存在のみに依存するため、値ごとにカバーされていない出現を 1 つ保持するだけで十分です。貪欲な戦略により、候補 mex 値を削除しようとするときに誤って必要以上の値を削除することがないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, d = map(int, input().split())
    p = list(map(int, input().split()))

    pos = [[] for _ in range(n + 1)]
    for i, v in enumerate(p):
        pos[v].append(i)

    # try mex from 0 upward
    for mex in range(n + 1):
        # check if we can fully eliminate mex
        if not pos[mex]:
            print(mex)
            return

        # simulate blocking all occurrences of mex
        last_block_end = -1
        ok = True

        for i in pos[mex]:
            if i > last_block_end:
                # place block starting at i
                last_block_end = i + d - 1

        # now check if all smaller values still have at least one uncovered occurrence
        blocked = [0] * n
        last_block_end = -1

        for i in pos[mex]:
            if i > last_block_end:
                start = i
                end = i + d - 1
                last_block_end = end
                for j in range(start, min(end + 1, n)):
                    blocked[j] = 1

        for v in range(mex):
            if not pos[v]:
                ok = False
                break
            if all(blocked[i] == 1 for i in pos[v]):
                ok = False
                break

        if ok:
            print(mex)
            return

    print(n)

if __name__ == "__main__":
    solve()
```この実装は、候補 mex 値を反復し、実現可能性をテストするという考えに従います。 重要な詳細は、値を削除しようとするときのブロックの貪欲な配置です。カバーされていない出現に遭遇するたびに、そこからブロックを開始します。これにより、前方カバレッジが最大化され、使用するブロックができるだけ少なくなります。 

第 2 フェーズでは、候補 mex より小さい値がすべてのブロックされた間隔の外側にまだ少なくとも 1 回出現するかどうかをチェックします。 たとえ候補値を削除できたとしても、より小さい値の出現をすべて破棄することはできないため、これは不可欠です。 

微妙な点は維持です`last_block_end`正しく。 前のブロックの禁止領域内でブロックが開始されないようにすることで、再生成制約を強制します。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、値がまったく表示されない場合です。 その状況では、その mex 候補は、それを削除するために何もする必要がなく、すでにヒット セットに存在していないため、すぐに実現可能です。 アルゴリズムはチェックすることでこれを処理します。`if not pos[mex]`そしてすぐに戻る`mex`。 

別のエッジケースが発生する場合`d = n`。 ここでは、適用できるブロックは 1 つだけです。 貪欲な構造は、配列全体をブロックするか、まったくブロックしないかのどちらかになります。 アルゴリズムはこれを正しく処理します。これは、ブロックが完全な連続セグメントをカバーするため、値のすべての出現がカバーされるか、まったくカバーされず、mex が純粋にグローバルな存在に依存するためです。 

最後の微妙なケースは、小さな値と小さい値を交互に繰り返すような密な繰り返しです。`d`。 このような場合、貪欲なブロック配置によりすぐに多くの値が重複し、チェックが`all(blocked[i] == 1 for i in pos[v])`これにより、値のすべての出現が単一の強制ブロック内にある場合に値が存続すると誤って想定されることがなくなります。
