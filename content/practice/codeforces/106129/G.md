 ## 解決策
 ## 問題の理解

 パスワードの数を次のように指定して、パスワードのコレクションを構築する必要があります。$n$、 どこ$n \le 1000$。 各パスワードは、印刷可能な ASCII 文字 (コード 33 ～ 126) 上の文字列であり、各文字列の長さは 8 ～ 12 でなければなりません。 

すべてのパスワードは、固定の構成制約を満たす必要があります。パスワードには、少なくとも 1 つの小文字、1 つの大文字、1 つの数字、および英数字以外の文字 (句読点や括弧などの印刷可能な記号を意味します) が 1 つ含まれている必要があります。 

個々の有効性を超えて、パスワードは編集距離の下で相互に十分に分離されている必要があります。 2 つの異なるパスワードの場合、一方をもう一方に変換するには、少なくとも 2 回の単一文字操作 (挿入、削除、または置換) が必要です。 言い換えれば、どのペアも同一であることはできず、また、どのペアも 1 回の編集だけで異なることはできません。 

出力は単純に$n$このようなパスワードは任意の順序で入力できます。 

制約は十分に小さいため、従来の意味でのパフォーマンス制限には対処していません。 本当の難しさは組み合わせの問題です。構成制約とグローバル編集距離制約の両方を保証しながら、多くの有効な文字列を体系的に生成する必要があります。 

小さなサフィックスまたはプレフィックスだけが異なるパスワードを生成しようとすると、微妙な失敗が発生します。 たとえば、次のようなベース文字列を修正すると、`Aa0!aaaa`最後の文字のみを変更すると、置換によって誤って編集距離 1 の文字列が生成される可能性があります。 次のような 2 つの文字列の長さだけが異なる場合、別の失敗ケースが発生します。`Aa0!abcd`そして`Aa0!abcde`、挿入により編集距離 1 にあります。 これらのパターンは、事後にチェックするのではなく、構築によって回避する必要があります。単純なペアごとのチェックでは、大規模な構築における微妙な衝突寸前を依然として見逃してしまうからです。 

## アプローチ

 ブルート フォース アプローチでは、候補文字列を生成し、以前に生成されたすべてのパスワードに対してすべての制約を検証しようとします。 以来$n \le 1000$各文字列の長さは最大 12 なので、編集距離を確認できます。$O(12^2)$ペアあたりの価格は安いですが、本当の問題は検索スペースの爆発です。 構造を持たないランダムまたは増分生成では、頻繁に衝突に近い状態が発生し、繰り返しの再生成が強制されます。 

重要な点は、アルファベットが大きく、必要な構造が非常に柔軟であることです。 これを検索問題として考えるのではなく、決定論的な構築問題として扱います。 私たちは、すべてのパスワードが少なくとも 2 の距離を自動的に保証する厳格な構造を共有する、小さな「テンプレート」セットを設計します。 

編集距離を少なくとも 2 に強制する最も簡単な方法は、すべてのパスワードが少なくとも 2 つの位置で異なるか、1 回の編集では解決できない構造的な違いがあることを確認することです。 信頼できる方法は、インデックスをエンコードするプレフィックスを修正することです。$i$、必要なすべての文字クラスを強制する定数のサフィックスを維持します。 インデックスのエンコードが変更される方法で行われた場合$i$少なくとも 2 つの文字を変更するか、長さクラスの配置を変更すると、必要な分離が自動的に取得されます。 

各パスワードを次のようにエンコードできます。 

必要な各クラスの有効な文字を 1 つ含む固定の 4 文字のコアと、その後に次の表現が続きます。$i$ベース 94 (または任意の ASCII セーフ範囲) で固定長にパディングされます。 これにより次のことが保証されます。 

1. すべての文字列は同一の構造と長さを持ちます。 
2. 固定コアは、すべての文字クラスの有効性を保証します。 
3. 個別のインデックスは、エンコードされたサフィックス内の少なくとも 1 つの位置で異なります。 
4. 長さが同じであるため、挿入/削除では 1 つのステップで 1 つの接尾辞を別の接尾辞に変換できません。 すべての変換には少なくとも 1 つの置換と少なくとも 1 つの追加操作が必要で、編集距離 ≥ 2 が保証されます。 

この構造により、ペアごとのチェックがすべて不要になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^2 \cdot L^2)$|$O(nL)$| 遅すぎる/信頼性が低い |
 | 構造化された建設 |$O(n \cdot L)$|$O(nL)$| 承認済み |

 ## アルゴリズムのチュートリアル

 決定的なテンプレートを使用して、各パスワードを個別に作成します。 

1. 必要なカテゴリを満たす 4 つの文字 (小文字 1 つ、大文字 1 つ、数字 1 つ、記号 1 つ) を修正します。 これらはどのパスワードでも同一のままであり、追加の作業を行わなくても有効性が保証されます。 
2. インデックスを表現する$i$(0から$n-1$) は、印刷可能な ASCII シンボルに対する高基数エンコードの固定長文字列として変換されます。 パディングによってすべてのエンコーディングが同じ長さになるようにします。 
3. 固定コアとエンコードされたインデックスを連結して、最終的なパスワードを形成します。 これにより、両方のコンポーネントが小さく制御されているため、長さが範囲内に収まることが保証されます。 
4. 構築された各文字列を出力します。 

これが機能する理由は、すべてのパスワードが、エンコードされたサフィックス内の少なくとも 1 つの位置で他のすべてのパスワードと異なるためです。 すべてのパスワードは同じ長さであるため、1 回の編集操作で変更できるのは 1 文字だけ、または 1 回の挿入/削除によるシフトだけですが、シフトでは 2 つの異なる固定長エンコーディングを調整することはできません。 したがって、あるパスワードを別のパスワードに変換するには、常に少なくとも 2 回の編集が必要です。 

維持される不変条件は、すべてのパスワードが固定プレフィックスと固定長を共有し、サフィックスは一意の識別子を固定長のアルファベットに注入的にエンコードするということです。 これにより、編集距離 1 内にペアが存在しないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def to_base(x, base, length, alphabet):
    s = []
    for _ in range(length):
        s.append(alphabet[x % base])
        x //= base
    return ''.join(reversed(s))

def solve():
    n = int(input().strip())

    lower = "abcdefghijklmnopqrstuvwxyz"
    upper = "ABCDEFGHIJKLMNOPQRSTUVWXYZ"
    digits = "0123456789"
    symbols = "!@#$%^&*()_+"

    core = lower[0] + upper[0] + digits[0] + symbols[0]

    alphabet = lower + upper + digits + symbols
    base = len(alphabet)

    suffix_len = 4

    res = []
    for i in range(n):
        suffix = to_base(i, base, suffix_len, alphabet)
        pw = core + suffix
        res.append(pw)

    sys.stdout.write("\n".join(res))

if __name__ == "__main__":
    solve()
```実装では、必要なカテゴリごとに 1 文字を使用して、固定された有効なプレフィックスを構築します。 サフィックスはインデックスの固定長ベース変換であり、一意性が保証されます。 

固定長エンコードの選択は重要です。固定長エンコードがないと、9 と 10 のような 2 つの数値が置換ではなく挿入によって異なる可能性があり、編集距離の要件が破られてしまいます。 パディングは、構造上の曖昧さを防ぎます。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque

    lower = "abcdefghijklmnopqrstuvwxyz"
    upper = "ABCDEFGHIJKLMNOPQRSTUVWXYZ"
    digits = "0123456789"
    symbols = "!@#$%^&*()_+"

    alphabet = lower + upper + digits + symbols

    def to_base(x, base, length, alphabet):
        s = []
        for _ in range(length):
            s.append(alphabet[x % base])
            x //= base

        suffix = to_base(i, base, 4, alphabet)

 ## 特殊なケース

 エッジケースの 1 つは、$n = 1$。 接尾辞エンコード 0 が有効な固定長ブロックを生成し、コアがすべての文字クラスを保証するため、この構造は引き続き機能します。 文字列が 1 つしかないため、比較の問題は発生しません。 

もう一つのエッジケースは、$n = 1000$ここで、固定のサフィックス長をオーバーフローしないベースエンコーディングに依存します。 接尾辞の長さが一定で、ベースが大きい (印刷可能文字数が 94 文字) ため、少なくとも次の値を表すことができます。$94^4$したがって、構造は衝突のない状態を保ちます。 

最後の微妙なケースは、コアとサフィックスの間の境界付近での挿入または削除により、編集距離が誤って 1 にならないようにすることです。 すべてのパスワードの全長は同じであるため、挿入または削除すると常に長さが変化し、固定長の 2 つの有効な出力間のマッピングが直ちに失敗します。 これにより、変換では置換のみが使用されるようになり、エンコードされたサフィックスが異なることで、文字列空間全体にわたって少なくとも 2 つの独立した文字の違いが保証されます。
