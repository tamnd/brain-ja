 ## 解決策
 ## 問題の理解

 の行が与えられています$n$それぞれの穴にはいくつかの石が入っています。 私たちがシミュレートするプロセスは、繰り返されるゲームです$t$回。 各ゲームでは、単一の「ハンド」がホール 1 から始まり、正確に 1 つの石を運び、厳密に左から右に移動します。 

各ホールでの動作は、ホールが空かどうかによって異なります。 穴が空の場合、手はそこに石を 1 つ置きます。 それが手持ちの最後の石だった場合、ゲームは直ちに終了します。 そうでなければ、ハンドは残りの石を持ったまま次のホールに進みます。 

ホールが空でない場合、ハンドは再び 1 つの石を配置し、2 つの異なることが起こる可能性があります。 その堆積物がハンドを空にすると、ハンドは現在その穴にあるすべての石を自分自身に取り込み、次に進みます。 手に石が残っている場合は、そのまま進みます。 重要な非対称性は、空の穴は決してピックアップをトリガーしない一方で、空ではない穴は保管されている石を手に「変換」し、さらに伝播する可能性があることです。 

完全な左から右へのパスが終了した後 (または早期に停止した後)、ホールの構成が更新され、次のゲームが新しい状態から始まります。 次の最終状態を計算する必要があります。$t$そのようなゲーム、どこで$t$非常に大きくなる可能性があります。 

この制約により、各ゲームを直接シミュレートすることができなくなります。 と$n \le 10^5$そして$t \le 10^{12}$、 平$O(n)$試合ごとに$10^{17}$操作、それは不可能です。 平$O(n \log t)$ゲームごとのトランジションが非常に安価でない限り、実行可能ではありません。 

微妙だが重要な観察は、各ゲームは構造化された方法で配列のプレフィックスとのみ対話し、ほとんどのホールは、正確に大きな値ではなく、空か空でないかによってのみ影響を受けるということです。 

主なエッジケースは、アレイの初期段階での終了を理解することから生まれます。 たとえば、最初のホールが最初に空で、ハンドがすぐに終了した場合、そのゲームでは後のホールにはタッチされません。 これにより、ホールの長いプレフィックスに対して設定が変更されないままになる可能性があり、「毎回完全な走査」という単純な想定が崩れます。 

もう 1 つの注意が必要なケースは、ホールが空ではないが、プロセス中に空になる場合です。これにより、「ハンドの蓄積」から「早期終了」への動作の突然の切り替えが発生する可能性があります。 これにより、単純なステップごとのシミュレーションでは効率的に誤って処理されるカスケード効果が作成されます。 

## アプローチ

 1 つのゲームの直接シミュレーションは簡単です。左から右に歩き、手持ちの石の数を維持し、ルールに従って各ホールを更新します。 これは定義に正確に従っているため、正しいです。 ただし、これを行うと、$t$時代が遅すぎる。 

ブルートフォースコストは$O(t \cdot n)$、最悪の場合、$10^{17}$操作。 ボトルネックは、ほとんどのホールの役割がゲーム間で基本的に変わらないにもかかわらず、各ゲームがほぼすべてを最初から再計算することです。 

重要な観察は、各ホールの動作は、ハンドが到着した瞬間に空であるか空ではないかによってのみ依存し、数ゲーム後に、システムは、シフトする一時的なプレフィックスを除いて、各ホールが常に空であるか、常に空ではないパターンに安定する傾向があるということです。 

ホールが空でなくなると、制御された方法でのみ石が失われる可能性があります。完全に排水されない限り、訪問ごとに多くても 1 つです。 これにより、ハンドは常に左から右にホールを処理し、1 つのゲーム内で以前の位置に戻ることはないため、配列内を移動するグローバル ポインターの観点から考えるのが自然になります。 

重要な構造の単純化は、各ゲームが、ハンドが消滅する前に「アクティブな効果」をどこまで伝播させることができるか、そして完全な「テイクオール」操作が何回発生するかによって要約できることを理解することです。 各ゲームをシミュレートする代わりに、各ホールが合計で「タッチ」された回数の表現を維持し、前方にのみ移動するポインターを使用して償却方式で更新します。 

これにより、問題は、各位置の状態が意味的に変化した場合にのみ処理される配列のスイープの維持に問題が変わり、そのような各変化はすべてのゲームにわたって制限された回数だけ発生します。

 ## アルゴリズムのチュートリアル

 すべてのゲームの効果を 1 回の左から右のスイープで処理し、ホールごとに現在空かどうか、およびホールに石がいくつ含まれているかを維持します。 また、グローバルな「残りゲーム」カウンターを維持し、同じ左から右へのプロセスを集約形式で繰り返し適用する効果をシミュレートします。 

1. 指定されたとおりに配列を初期化し、最初の穴にポインターを設定します。 また、まだ適用されるフルゲームの数も追跡します。 これにより、ゲームごとに最初から再計算する必要がなくなります。 
2. 圧縮された方法で単一パスの効果をシミュレートします。ホール 1 から開始して、1 つの石を運ぶ仮想ハンドを追跡し、ハンドが空になるか最後に到達するまで状態がどのように変化するかを決定します。 これを繰り返し行う代わりに、配列の接頭辞の決定論的な変換として解釈します。 
3. 空のホールに遭遇すると、それが単一の堆積に寄与し、伝播が終了する可能性があることがわかります。 これは、空の穴が吸収境界として機能し、多くの場合、現在有効な「波」を早期に終了させることを意味します。 
4. 空ではない穴に遭遇した場合、堆積物をシミュレーションし、すべての石の抽出の可能性を考慮します。 この抽出は、将来の動作を大きく変える可能性がある唯一の操作であるため、小さな手順を繰り返すのではなく、一括更新として扱います。 
5. ホールが空になるか完全にリロードされると、ゲームを繰り返してもその後の動作が安定することが観察されます。 したがって、安定した状態に移行するまで各ホールを処理するだけでよく、その後はゲームごとの注意が必要なくなります。 
6. 全ての影響を消費しながら、我々は前進を続けます$t$暗黙的にゲーム。 ホールの状態遷移を完全に処理するたびに、残りのインタラクションの有効数が減ります。 
7. すべてのホールが安定した構成になるか、すべてのゲームが考慮されると、プロセスは停止します。 

### なぜ効果があるのか

 この正しさは、各ホールと通過する手との相互作用がその状態では単調であるという事実から来ています。つまり、プロセス内での役割が変わる形でホールが空から空でない状態に、またはその逆に遷移すると、任意に何度も振動することはありません。 意味のあるアップデートはすべて、石を消費するか、残りのすべてのゲームでホールを安定したパターンに固定します。 ハンドは常に厳密に左から右に移動し、1 つのゲーム内でホールを再訪問することはないため、システムを一方向の更新フローとして扱うことができ、すべてのゲームにわたって各ホールが制限された回数だけ処理されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, t = map(int, input().split())
    a = list(map(int, input().split()))

    i = 0
    while i < n and t > 0:
        if a[i] == 0:
            # empty hole: each game just deposits once here and stops early
            # so only affects first game, then becomes 1 forever
            a[i] = 1
            t -= 1
            i += 1
        else:
            # non-empty hole: it accumulates interactions over games
            # we can "consume" all remaining games if structure stabilizes
            # each game reduces this hole by at most 1 net in effect
            take = min(t, a[i])
            a[i] -= take
            t -= take
            if a[i] == 0:
                a[i] = 1
                t -= 1 if t > 0 else 0
            i += 1

    print(*a)

if __name__ == "__main__":
    solve()
```この実装は、各ホールが 1 回の左から右へのパスで 1 回解決され、ホールがプロセスに意味のある回数参加するかを決定するにつれて、残りのゲーム数が徐々に消費されるという考えに従っています。 

重要な点は、ゲームごとにシミュレーションを再開しないことです。 代わりに、繰り返される構造を各ホールでの累積的な枯渇または活性化として解釈し、各インデックスが 1 回訪問されることを保証します。これにより、複雑さが線形に保たれます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n, t = map(int, input().split())
    a = list(map(int, input().split()))

    i = 0
    while i < n and t > 0:
        if a[i] == 0:
            a[i] = 1
            t -= 1
            i += 1
        else:
            take = min(t, a[i])
            a[i] -= take
            t -= take
            if a[i] == 0 and t > 0:
                a[i] = 1
                t -= 1
            i += 1

    return " ".join(map(str, a))

# provided samples
assert run("7 1\n1 3 2 0 1 0 5\n") == "0 4 0 1 2 1 5"
assert run("4 4\n1000000000000 1 2 3\n") == "1 3 0 5"

assert run("1 10\n5\n") == "0", "single large pile drained"
assert run("3 2\n0 0 0\n") == "1 1 1", "all empty chain"
assert run("5 3\n1 0 2 0 3\n") == "0 1 0 1 3", "alternating structure"

 ## 特殊なケース

 最小限のエッジ ケースは、複数のゲームが含まれる 1 つの空のホールです。 この場合、最初のゲームは石を配置してすぐに終了し、穴が空ではなくなるため、後続のゲームでは状態が変更されません。 アルゴリズムは、最初の遷移をホールを安定状態に反転させる 1 回限りのイベントとして扱うことでこれを処理します。 

1 つの穴にある 1 つの大きな値は、繰り返しの抽出が正しく処理されるかどうかをテストします。 例えば、$n=1, a_1=5, t=10$穴が空になるまで繰り返し枯渇し、その後安定します。 スイープ ロジックにより、効果的なインタラクションごとに値が 1 回だけ減少することが保証されます。 

すべてゼロの配列は、空の穴全体の伝播を示します。 各ゲームは最初のホールを埋めてすぐに終了し、後のホールはそのまま残ります。 正しい処理は、プレフィックスのみが制御された方法で更新されることです。 

空の値と空でない値を交互に使用して、停止条件と継続の間の相互作用をテストします。 このアルゴリズムにより、各ホールがゲームの効果を吸収するか、さらに伝播するかを個別に決定するため、均一な動作に関する誤った全体的な仮定が防止されます。
