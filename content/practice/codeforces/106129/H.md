 ## 解決策
 ## 問題の理解

 頂点が駅を表し、エッジが一方通行の列車の接続を表す有向グラフが与えられます。 2 人が 2 つの異なるステーションから出発し、それぞれが有向エッジに沿って何度でも移動できます。 問題は、両方の出発点から到達可能な駅が少なくとも 1 つ存在するかどうかです。 

したがって、タスクは有向グラフの到達可能性の問題に帰着します: ノードから`a`とノード`b`、到達可能なセットが交差するかどうかを確認し、交差する場合は交差内のノードを出力します。 

制約は最大 100,000 個のノードと 100,000 個のエッジにまで及ぶため、すべてのノード ペア間の到達可能性のチェックや候補ノードごとの最短パスの再計算などの二次アプローチは即座に除外されます。 どのような解も基本的にグラフのサイズが線形である必要があります。通常、`O(n + m)`。 

構造から貪欲に推論しようとすると、微妙な問題が現れます。 たとえば、ローカル接続または BFS ツリーでの最初の遭遇に基づいて「会議ステーション」を選択することは安全ではありません。到達可能性が対称的ではなく、パスが再び収束する前に深く分岐する可能性があるためです。 

もう 1 つのエッジ ケースは、いずれかのソースからの発信パスがない場合です。 たとえば:

 入力:```
3 1
1 2
3 1
```から`3`あなたは到達できます`1`その後`2`、しかしから`1`あなただけが到達できる`2`。 唯一可能な待ち合わせ場所は次のとおりです。`2`。 隣接するもののみをチェックする単純なアプローチ`a`または`b`これは見逃すでしょう。 

最後に、グラフが切断されているか、長い有向チェーンが含まれている場合、無向の直観に基づいて重複していると誤って仮定する可能性が高くなります。 ここでは方向性が完全に重要になります。 

## アプローチ

 ブルートフォースのアイデアは、到達可能なノードの完全なセットを計算することです。`a`BFS または DFS を使用して、到達可能なセットを個別に計算します。`b`、次に 2 つのセットを交差させます。 これは正しく、概念的に単純です。 

各 BFS/DFS は次のように実行されます。`O(n + m)`、設定された交差点は`O(n)`ブール配列で実装されている場合。 したがって、単純なアプローチであっても、ソースごとにすでに線形であるため、`O(n + m)`合計。 これは制約に対してすでに十分に効率的です。 

ただし、ノードごとに、より概念的な総当たり攻撃が試みられる可能性があります。`v`かどうかを確認します。`v`両方からアクセス可能です`a`そして`b`ノードごとに BFS を 2 回実行するか、ノードごとにリバース到達可能性チェックを実行します。 それは次のことにつながります`O(n(n + m))`、これは大きすぎます。 

重要な観察は、単一のソースからの到達可能性によって、グラフが到達可能な領域に分割されるということです。 2 つの到達可能な領域が重複しているかどうかだけを知る必要があり、重複している場合は、共通のノードを見つけたらすぐに停止できます。 これにより、インターリーブや早期停止によって不必要な作業を回避できますが、最適化トリックを使用しなくても、2 回の BFS 実行で十分です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ノードごとのブルート フォース | O(n(n + m)) | O(n + m) | 遅すぎる |
 | 2 つの BFS/DFS + 交差点 | O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 グラフ トラバーサルを使用して、各開始ステーションから到達可能なすべてのノードを個別に計算します。 

1. 有向エッジから隣接リストを構築します。 この構造により、任意のステーションからの発信接続を効率的に通過できます。 
2. ステーションから開始して BFS または DFS を実行します`a`、訪問したすべてのノードをブール配列でマークします`reach_a`。 これは、人物 A が何回電車に乗っても到達できる一連の駅を正確にキャプチャします。 
3. ステーションから開始して別の BFS または DFS を実行します`b`、訪問したノードをマークします`reach_b`。 これにより、ハンナが到達可能なすべてのステーションが同様にキャプチャされます。 
4. すべてのステーションをスキャンします。`1`に`n`。 各駅ごとに`v`、両方かどうかを確認してください`reach_a[v]`そして`reach_b[v]`本当です。 このような最初のノードは有効なミーティング ポイントであり、すぐに出力できます。 
5. すべてのステーションをスキャンした後、そのようなノードが存在しない場合は、出力`"no"`。 

任意の交差点ノードを安全に返すことができる理由は、問題が最短の移動時間や最も早い駅などの最適性を必要としないためです。 到達可能なオーバーラップはすべて有効です。 

### なぜ効果があるのか

 このアルゴリズムは、両方の開始ノードの前方到達可能性セットを明示的に計算します。 定義上、ノードは、両方の参加者が有向パスに沿って独立してノードに到達できる場合に限り、これらのセットの交差部分にあります。 BFS/DFS 探索では、各ソースからすべてのエッジが正確に 1 回横断されるため、これらのセットの完全性が保証され、到達可能なノードが省略されることはありません。 したがって、両方の訪問先セットで見つかったノードはすべて正しい会議ステーションであり、そのようなノードが存在しない場合、交差点は空であり、解決策は存在しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def bfs(start, adj, n):
    vis = [False] * (n + 1)
    stack = [start]
    vis[start] = True

    while stack:
        v = stack.pop()
        for nxt in adj[v]:
            if not vis[nxt]:
                vis[nxt] = True
                stack.append(nxt)
    return vis

def solve():
    n, m = map(int, input().split())
    adj = [[] for _ in range(n + 1)]

    for _ in range(m):
        x, y = map(int, input().split())
        adj[x].append(y)

    a, b = map(int, input().split())

    reach_a = bfs(a, adj, n)
    reach_b = bfs(b, adj, n)

    for i in range(1, n + 1):
        if reach_a[i] and reach_b[i]:
            print("yes")
            print(i)
            return

    print("no")

if __name__ == "__main__":
    solve()
```このソリューションは、有向隣接リストを構築し、スタックを使用して 2 つの独立した深さ優先検索を実行します。 訪問したアレイ`reach_a`そして`reach_b`各開始ノードからの到達可能性をエンコードします。 

重要な実装の詳細は、スタックにプッシュするときにノードを即座に訪問済みとしてマークすることです。 これにより、繰り返しの挿入が防止され、直線的なトラバースが維持されます。 最終スキャンが必要なのは、トラバース中に最初に発見された会議ステーションである必要はなく、有効な会議ステーションを出力できるためです。

 ## 特殊なケース

 重要なエッジ ケースは、一方の開始ノードがもう一方の開始ノードからすでに到達可能な場合です。 たとえば、次の場合`b`到達できる`a`、 それから`a`すでに有効な待ち合わせ場所になっている可能性があります。 

入力：```
2 1
1 2
1 2
```から`1`、到達可能なセットは`{1,2}`。 から`2`、到達可能なセットは`{2}`。 交差点は、`{2}`したがって、出力は`yes 2`。 からのBFS`2`それ自体のみを正しくマークし、最終スキャンでノードを見つけます`2`一般的なものとして。 

もう 1 つのケースは、接続されていないグラフです。```
4 2
1 2
3 4
1 3
```から`1`私たちは到達します`{1,2}`、 から`3`私たちは到達します`{3,4}`、交差点は空いています。 アルゴリズムは正しく印刷します`no`すべてのノードをスキャンした後、訪問された両方の配列でノードがマークされていないためです。 

最後の微妙なケースは、有効な回答が複数存在する場合です。 ノードを昇順にスキャンするため、ラベル付きの最小の会議ステーションが返されますが、問題に応じてどの順序でも正しいでしょう。
