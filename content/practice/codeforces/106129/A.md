 ## 解決策
 ## 問題の理解

 私たちは、テーブルの反対側に立っているプレイヤーの 2 つの列を含む、非常に構造化されたゲームをシミュレートしています。 左側には ℓ 人のプレイヤーがキューに配置されており、右側には r 人のプレイヤーが別のキューに配置されています。 あらゆる瞬間において、各キューの先頭のプレーヤーだけが重要です。彼らが向かい合って、一人がボールを打ち、そのプレーヤーはすぐに先頭の位置を離れ、反対側のキューの後ろに加わります。 これは決定論的な方法で無限に続きます。 

この問題で重要なのは、完全な構成ではなく、各ヒットの瞬間に現れるペアリングのシーケンスだけです。 各ヒットにより、左のキューの現在の先頭と右のキューの現在の先頭から構成されるペアが生成されます。 システムには 2 つの循環キューの可能な構成数が有限であるため、十分なヒットの後、最終的にこれらのペアの繰り返しが開始されます。 

入力により、2 つのキューの初期サイズである ℓ と r が与えられます。 課題は、ペアリング シーケンスの繰り返しが始まる前に、先頭の位置に何人の個別の順序付けられたプレーヤーのペアが現れるかを決定することです。 

このステートメントでは最大 10¹⁰ という非常に多くのヒット数について言及していますが、その値が実際のボトルネックではありません。 重要なのは、その規模が問題になるずっと前にシステムが周期的になるということです。したがって、必要なのはサイクルの構造を理解することだけです。 

制約 ℓ、r ≤ 10⁹ により、個々のヒットに対するシミュレーションは直ちに除外されます。 状態の数はℓとrの組み合わせで増加するため、キューの状態を保存することさえ不可能です。 これにより、プロセスの純粋に算術的または数論的な解釈が強制されます。 

素朴なシミュレーションを誤解させる可能性がある微妙な点は、プロセスが循環ローテーションにおける位置のみではなく、プレーヤーのアイデンティティに依存すると仮定していることです。 たとえば、ℓ = 2 および r = 2 の場合、システムは急速に循環し、プレーヤーがキュー間を移動し続けても、同じペアが再び表示されます。 シミュレーション手法では、2 つのシーケンスの繰り返し構成を検出する必要がありますが、これは直接管理するには大きすぎます。 

## アプローチ

 直接シミュレーションでは、両方のキューを明示的に維持し、先頭のプレーヤーを反対側の端に繰り返し移動します。 各ステップは O(1) ですが、各操作の後に構成が変更されるため、完全な状態が繰り返されるタイミングを検出する必要があります。 各キューはその要素を任意に並べることができ、追跡にはサイズ ℓ + r の構造のハッシュ化または完全な比較が必要になるため、可能な状態の数は膨大です。 それを無視しても、最大 10¹⁰ ステップをシミュレートすることは不可能です。 

重要な点は、実際には完全な状態は必要ないということです。 各ステップでどのペアが現れるかだけを考慮します。 システムの進化は完全に決定論的かつ対称的です。各ステップは、予測可能なモジュール パターンで「フロント ポジション」を進めます。 各プレイヤーは一定のリズムで両側を効果的に循環し、2 つのサイクル間の相互作用は相対的なサイズ ℓ と r によって完全に支配されます。 

これにより、問題は 2 つの独立した循環プロセスがいつ同期するかを理解することになります。 1 つのサイクルの長さは ℓ で、もう 1 つのサイクルは長さ r です。 各ステップでのペアリングは、これらのサイクルの位置合わせのみに依存します。 ペアのシーケンスは、lcm(ℓ, r) ステップ後に両方のサイクルが同時に元の配置に戻るときに正確に繰り返されます。 

各ステップでは 1 つのペアリングが作成され、サイクル全体が完了するまでペアリングは繰り返されないため、個別のペアリングの数は正確にこのサイクルの長さになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | キューを使用したシミュレーション | O(歩数) 以上 | O(ℓ + r) | 遅すぎる |
 | LCM を使用したサイクル分析 | O(log min(ℓ, r)) | お(1) | 承認済み |

## アルゴリズムのチュートリアル

 ### アルゴリズムのチュートリアル

 1. 2 つの回転キューのサイズを表す値 ℓ と r を読み取ります。 目標は、2 つのサイクルの相互作用パターンがいつ完全に繰り返されるかを判断することです。 
2. 各キューが循環構造のように動作することを観察します。キューのサイズに等しい固定回数の回転の後、すべてのプレーヤーが元の相対位置に戻ります。 これは、システムが長さ ℓ と r の 2 つの独立したサイクルによって駆動されていることを示唆しています。 
3. 各ステップでのペアリングは、これら 2 つのサイクルの相対的な配置のみに依存することを認識してください。 観察されたすべてのペアリングの完全な繰り返しは、両方のサイクルが同時に開始位置に戻った場合にのみ発生します。 
4. 両方のサイクルが再び揃う最小の時間ステップを計算します。これは、ℓ と r の最小公倍数です。 これは、両方の前線とすべての相対位置が初期構成と一致する最初の瞬間です。 
5. 反復前の各ステップで一意のペアが生成されるため、この値を個別のペアの数として返します。 

### なぜ効果があるのか

 このプロセスは、2 つの同期されたモジュラー カウンタとして見ることができます。1 つはモジュロ ℓ を進め、もう 1 つはモジュロ r です。 ステップ t で観察されるペアは、残基のペア (t mod ℓ、t mod r) によって完全に決定されます。 2 つのステップでは、両方の残基が同時に一致する場合にのみ同じペアリングが生成されます。これは、まさに t が ℓ と r の両方の倍数である場合に発生します。 最初のそのような時間は lcm(ℓ, r) であり、その時点までは、両方の残基の以前の衝突は発生しないため、すべてのペアは区別されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def lcm(a, b):
    import math
    return a // math.gcd(a, b) * b

def main():
    l, r = map(int, input().split())
    print(lcm(l, r))

if __name__ == "__main__":
    main()
```問題全体が最大公約数の計算と最小公倍数の導出に帰着するため、実装は意図的に最小限に抑えられています。 Python は大きな整数を安全に処理しますが、整数の範囲が固定されている言語でのオーバーフローの問題を回避するために、gcd による除算の後に乗算が実行されます。 

唯一の微妙な点は、gcd が最初に計算されるようにすることです。 書き込み`a * b // gcd(a, b)`数学的には正しいですが、計算上は`a // gcd(a, b) * b`中間値が小さく保たれるため、一般に安全です。 

## 実用的な例

 ### 例 1: ℓ = 2、r = 3

 t の値と 2 つのサイクルの暗黙のアライメントを追跡します。 

| ステップ t | t mod 2 | t mod 3 | ペアの一意性 |
 | --- | --- | --- | --- |
 | 0 | 0 | 0 | 新しい |
 | 1 | 1 | 1 | 新しい |
 | 2 | 0 | 2 | 新しい |
 | 3 | 1 | 0 | 新しい |
 | 4 | 0 | 1 | 新しい |
 | 5 | 1 | 2 | 新しい |
 | 6 | 0 | 0 | 最初の | を繰り返します

 完全な状態の最初の繰り返しは、lcm(2, 3) に等しい t = 6 で発生します。 6 つのステップすべてで明確なペアリングが生成されます。 

これは、ペアリング シーケンスがモジュール アラインメントによって正確に制御されていることを確認します。 

### 例 2: ℓ = 2、r = 2

 | ステップ t | t mod 2 | t mod 2 | ペアの一意性 |
 | --- | --- | --- | --- |
 | 0 | 0 | 0 | 新しい |
 | 1 | 1 | 1 | 新しい |
 | 2 | 0 | 0 | 最初の | を繰り返します

 ここでは、lcm(2, 2) = 2 に一致する 2 ステップ後にサイクルが繰り返されます。プレーヤーがキュー間を移動している場合でも、ペアリング構造は両方のサイクルが再調整された直後に繰り返されます。 

これは、キュー サイズが同一であると、システムが非常に短い周期構造に崩壊することを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(log min(ℓ, r)) | gcd 計算が支配的 |
 | スペース | お(1) | 少数の整変数のみが使用されます。 

制約により、ℓ と r は最大 10⁹ まで許容されるため、時間の経過に伴う線形シミュレーションは不可能です。 対数 gcd ベースの計算は、最悪の場合でも十分に高速です。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import math

    l, r = map(int, sys.stdin.readline().split())
    return str(l // math.gcd(l, r) * r)

# provided samples (interpreted)
assert run("2 3\n") == "6"
assert run("2 2\n") == "2"

# custom cases
assert run("1 5\n") == "5", "one side trivial cycle"
assert run("6 4\n") == "12", "non-coprime alignment"
assert run("10 1\n") == "10", "degenerate single cycle"
assert run("7 3\n") == "21", "coprime full expansion"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 5 | 5 | 単一要素サイクルの動作 |
 | 6 4 | 12 | gcd 削減効果 |
 | 10 1 | 10 | 片側の縮退キュー |
 | 7 3 | 21 | 共素のケースがフル lcm に達する |

 ## 特殊なケース

 1 つのキューのサイズが 1 の場合、システムは反対側で 1 つの回転サイクルに縮小します。 たとえば、ℓ = 1、r = 5 では、5 ステップごとに繰り返されるペアリング シーケンスが生成されます。 gcd(1, 5) = 1 であるため、リダクションは発生しないため、アルゴリズムは lcm(1, 5) = 5 を正しく返します。 

ℓ と r が等しい場合、すべての位置合わせは直ちに同期されます。 ℓ = r = 2 の場合、両方のサイクルが同期して進み、ペアリング シーケンスは正確に 2 ステップ後に繰り返されます。 gcd(2, 2) = 2 であるため、計算 lcm(2, 2) はこれを自然に処理します。 

ℓ と r が互いに素の場合、サイクルは ℓ・r ステップ後にのみ再調整されます。 たとえば、ℓ = 7 および r = 3 では、21 個の異なるペアの全長サイクルが生成されます。 gcd(7, 3) = 1 であるため、アルゴリズムはこの最大の動作を捕捉し、積は変更されません。
