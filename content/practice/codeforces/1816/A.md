 ## 解決策
 ## 問題の理解

 整数グリッドの原点と座標のターゲット点に座っているカエルから始めます。$(a,b)$。 カエルは格子点間でジャンプを実行できますが、開始点と終了点の間の直線セグメントはその端点以外の他の格子点を通過できないという意味で、各ジャンプは「クリーン」でなければなりません。 数論的に言えば、これは、$(x_1,y_1)$に$(x_2,y_2)$はまさに次の場合に有効です$\gcd(|x_2-x_1|, |y_2-y_1|) = 1$。 

タスクはジャンプの数を最適化することではなく、カエルが到達できることを保証することです。$(a,b)$このような有効なジャンプは最大 2 つであり、有効な構造を自由に出力できます。 

制約は大きく、座標は次のとおりです。$10^9$これにより、ポイントの反復またはグリッドの検索に依存するものはすべて即座に除外されます。 すべての解はテスト ケースごとに定数時間である必要があり、算術プロパティから直接明示的な座標を生成します。$a$そして$b$。 

単純なアプローチでは、常に次から直接ジャンプしようとする可能性があります。$(0,0)$に$(a,b)$。 これは次の場合にのみ機能します$\gcd(a,b)=1$。 もし$a$そして$b$共通因子を共有し、セグメントに中間格子点が含まれており、ジャンプは無効です。 この条件を無視した不注意なソリューションは、次のような入力に対して直ちに失敗します。$(4,4)$、 どこ$(0,0)\to(4,4)$通り抜ける$(1,1),(2,2),(3,3)$。 

したがって、中心的な課題は、両方のセグメントがプリミティブ ベクトル (gcd が 1 に等しい) になるように、最大​​ 1 つの中間格子点を挿入することです。 

## アプローチ

 強引なアイデアは、中間の格子点を探すことです。$(x,y)$両方とも$(0,0)\to(x,y)$そして$(x,y)\to(a,b)$は有効なプリミティブ セグメントです。 以来$x,y$までの範囲で可能$10^9$、これは実行不可能です。妥当な境界ボックスに制限しても依然として膨大な検索スペースが残り、各候補の gcd 条件をチェックするのは遅すぎます。 

重要な点は、検索する必要がまったくないということです。 両方のセグメントを強制的にプリミティブにする構造特性を持つ単一の中間点の存在を保証する必要があるだけです。 gcd 条件は、小さな互いに素なステップによって異なる点を選択するか、少なくとも 1 つの座標シフトが 1 であることを保証することを提案します。 

最も単純な構造上のトリックは、2 つのセグメントのうちの 1 つに、1 つの座標の差が 1 になるように強制することです。 フォームの任意のセグメント$(x,y)\to(x+1,y)$または$(x,y)\to(x,y+1)$1 の gcd は常に 1 であるため、 は常に有効です。これにより、ターゲットとほぼ一致する慎重に選択された中間点を導入することで、gcd 障害を「修正」する方法が得られます。 

堅牢な構造は、まず次のことから始まります。$(0,0)$次のような小さな摂動を使用して対称性を破る点まで$(a,b-1)$、$(a-1,b)$、または同様の亜種。 そして最後のジャンプは$(a,b)$1 つの座標で正確に 1 だけ異なるため、有効なセグメントが保証されます。 これが失敗する唯一のケースは、中間点が無効になる場合 (たとえば、1 を引くと 0 になる場合) ですが、これは直接ジャンプで個別に処理できます。 

これにより、問題は次のような小さなケースの分析に集約されます。$a$または$b$1に等しい。

 ## アルゴリズムのチュートリアル

 テストケースごとに個別に答えを作成します。 

1. もし$\gcd(a,b)=1$、単一のジャンプを出力します。$(0,0)$直接に$(a,b)$。 

これが機能するのは、プリミティブ ベクトルには内部格子点が含まれていないためです。 
2. それ以外の場合は、有効な中間点を強制することを目指します。 私たちが選ぶ$(a,b-1)$もし$b>1$、それ以外の場合は使用します$(a-1,b)$。 

これにより、最終ステップが 1 つの座標で正確に 1 だけ異なることが保証されます。 
3. 2 つのジャンプを出力します。最初は中間点へ、次に$(a,b)$。 
4. もし$a=1$または$b=1$、ダイレクトジャンプは常に有効なので、単一の動きを安全に出力できます。 

この構築は、どちらかの座標を 1 減らすと、1 つの座標の差が 1 になるため、gcd が 1 に等しい最終セグメントが保証されるという事実に基づいています。 

### なぜ効果があるのか

 正確さは、線分上の格子点の構造によって左右されます。 方向ベクトルがプリミティブである場合、つまり座標の差が互いに素である場合、整数点間のセグメントには中間格子点が含まれません。 

2 番目のセグメントに差分ベクトルがあることが確認された場合$(1,0)$または$(0,1)$の場合、そのセグメントは自動的に有効になります。 残りのタスクは、有効なセグメントを使用して中間点自体が原点から到達可能であることを確認することです。 構造によって、私たちが選択するとき$(a,b-1)$または$(a-1,b)$、少なくとも 1 つの座標は変更されず、もう 1 つは任意であるため、gcd 要件を、最大 1 つの調整ステップで選択した構造に対して常に成立する、より単純な形式に削減します。 

最大 2 つのジャンプが許可されており、最適化ではなく存在のみが必要なため、この構築で十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        a, b = map(int, input().split())

        # direct jump is always valid if gcd(a,b)=1, but even if not,
        # problem allows any valid construction up to 2 steps
        import math
        if math.gcd(a, b) == 1:
            print(1)
            print(a, b)
        else:
            # pick intermediate point
            if b > 1:
                x, y = a, b - 1
            else:
                x, y = a - 1, b

            print(2)
            print(x, y)
            print(a, b)

if __name__ == "__main__":
    solve()
```コードは、直接のケースと構築されたケースを分離します。 gcd チェックは出力を簡素化するためにのみ使用されますが、それを使用しない場合でも、すべての入力に対して 2 段階の構成で十分です。 

実装の重要な詳細は、中間点を安全に選択することです。 かどうかをチェックすることで、決して範囲外に出ないことを保証します。$b > 1$、そうでない場合は削減します$a$。 両方なので$a,b \ge 1$、少なくとも 1 つのブランチが常に有効です。 

## 実用的な例

 2 つの代表的なケースを追跡します。$(3,4)$そして$(4,4)$。 

### 例 1:$a=3, b=4$| ステップ | 現在のポイント | アクション | 次のポイント |
 | --- | --- | --- | --- |
 | 1 | (0,0) | gcd(3,4)=1、ダイレクトジャンプ | (3,4) |

 ベクトルはすでにプリミティブであるため、この構築では単一のジャンプを選択します。 

これは、互いに素な座標は中間格子点を含まないという不変条件を裏付けます。 

### 例 2:$a=4, b=4$| ステップ | 現在のポイント | アクション | 次のポイント |
 | --- | --- | --- | --- |
 | 1 | (0,0) | gcd(4,4)=4、プリミティブではありません | 中間を選択 |
 | 2 | (0,0) | (4,3) に移動 | (4,3) |
 | 3 | (4,3) | ファイナルジャンプ | (4,4) |

 最初のセグメントは有効です。$\gcd(4,3)=1$。 違いが次のとおりであるため、2 番目のセグメントは有効です。$(0,1)$。 

これは、1 つの座標を 1 減らすと公約数構造がどのように壊れるかを示しています。

## テストケース```python
import sys, io
import math

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        a, b = map(int, input().split())
        if math.gcd(a, b) == 1:
            out.append("1")
            out.append(f"{a} {b}")
        else:
            if b > 1:
                x, y = a, b - 1
            else:
                x, y = a - 1, b
            out.append("2")
            out.append(f"{x} {y}")
            out.append(f"{a} {b}")
    return "\n".join(out)

 ## 特殊なケース

 いつ$a=b=1$、原点からの直接セグメントはすでにプリミティブであるため、アルゴリズムはただちに 1 つのジャンプを出力します。 何かを改善するための有効な中間点はなく、構築では不必要な手順が正しく回避されます。 

1 つの座標が 1 に等しいとき、次のようにします。$(1,b)$、からの任意のセグメント$(0,0)$は自動的に有効になります。$\gcd(1,b)=1$。 したがって、このアルゴリズムは、座標 1 の点が原点からのプリミティブ光線上にあるという幾何学的事実と一致して、中間の構築を試みることなく単一ステップの解決策を生成します。 

両方の座標が等しく 1 より大きい場合、アルゴリズムは常に 2 段階の構築をトリガーします。 例えば、$(4,4)$になる$(4,3)\to(4,4)$。 最初のセグメントは、連続する整数が互いに素であるため、原点との公約数の共有を回避し、2 番目のセグメントは軸に揃えられています。
