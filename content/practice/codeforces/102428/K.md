 ## 解決策
 ## 問題の理解

 文字列があります`S`位置 (2、4、6、\ldots、2N) の住民を説明します。 キャラクター`H`多項式がその位置で正でなければならないことを意味しますが、`A`負でなければならないことを意味します。 

整数の係数と整数の根を持つ多項式が必要です。 その先頭の係数は (1) または (-1) のいずれかでなければならず、必要な符号を満たすすべての多項式の中で、その次数が最小でなければなりません。 次数と係数を出力するだけです。 

最初の有益な観察は、多項式は奇数の多重度の根を越える場合にのみ符号を変更できるということです。 (2i) と (2i+2) の 2 人の連続する市民を考えてみましょう。 必要な符号が異なる場合、多項式は開区間 ((2i,2i+2)) に奇数の根を持たなければなりません。 

すべての根は整数です。 厳密に (2i) と (2i+2) の間にある唯一の整数は (2i+1) です。 したがって、いつでも、`S[i] != S[i+1]`、多項式には奇数の多重度の根 (2i+1) が含まれている必要があります。 コピーは 1 枚で十分であり、複数枚取っても程度は上がります。 

これにより、可能な最小次数がすぐに得られます。 

[
 D=#{i\ne S_{i+1}}。 
】

 まさにこれらの根を使用して多項式を構築できます。 

[
 Q(x)=\prod_{S_i\ne S_{i+1}}(x-(2i+1))。 
】

 ルートは、符号を変更する必要がある連続する市民間で正確に発生するため、(Q) は正確に望ましい符号変化を持ちます。 最初の市民の記号が正しくなるように、(Q) を使用するか (-Q) を使用するかを選択するだけです。 

境界 (N\le10^4) は、最初は、この積の拡張には (O(N^2)) の作業が必要になる可能性があることを示唆しているかもしれませんが、これは Python では不快です。 係数限界は状況を完全に変えます。 多項式の次数が少なくとも 17 の場合、必要な正の奇数根が少なくとも 17 個含まれている必要があります。 このような 17 個のルートの最小の積は次のようになります。 

[
 3\cdot5\cdot7\cdots35
 =221643095476699771875、
 】

 これはすでに (2^{63}) より大きくなっています。 モニック多項式またはアンチモニック多項式の定数係数は、符号までのすべての根の積です。 したがって、次数 17 以上の有効な最小次数多項式は係数限界を満たすことができません。 

したがって、すべての有効な入力には (D\le16) が含まれます。 元の文字列にはまだ 10,000 人の国民が含まれている可能性がありますが、スキャン後に最大 16 の線形係数を乗算します。 

誤って処理しやすい特殊なケースがいくつかあります。 のために`H`、入力は`H`、符号の変化はなく、定数多項式 (P(x)=1) は正しいです。 常に少なくとも 1 つのルートを作成する不注意な実装では、非最小多項式が生成されます。 

のために`A`、入力は`A`、正しい多項式は (P(x)=-1) です。 先頭の係数は、次数が 0 の場合でも、最初に必要な符号から選択する必要があります。 

のために`HA`、唯一の遷移は位置 2 と 4 の間であるため、根は 3 でなければなりません。多項式 (x-3) は 2 で負、4 で正となり、必要なものとは逆になります。 正しい答えは、```
1
-1 3
```これは、最後のグローバル記号が無視できない理由を示しています。 

のために`AHA`、遷移が 2 つあるため、根は 3 と 5 になります。その積は次のようになります。 

[
 Q(x)=(x-3)(x-5)=x^2-8x+15。 
】

 (x=2) では、(Q(2)=3>0) ですが、最初の市民はエイリアンなので、多項式を否定して出力する必要があります。```
2
-1 8 -15
```遷移をカウントするだけで次数の等価性を忘れる不注意な実装では、この符号を間違える可能性があります。 

## アプローチ

 直接的なアプローチは、すべての遷移を特定し、対応する製品を一度に 1 つの要素ずつ拡張することです。 係数の境界を無視して、次数が (N-1) まで大きくなるようにすると、最悪のケースでは、長さが 10,000 の交互文字列になります。 この場合、因数は 9,999 個あり、それらを 1 つずつ乗算するには、

 [
 1+2+\cdots+9999
 =\frac{9999\cdot10000}{2}
 =49,995,000
 】

 係数の更新。 これは、Python ソリューションにとっては不必要に膨大な作業量です。 

それでも、総当たりの構築は数学的には正しいです。 すべての遷移により、根がその固有の整数ギャップに強制され、対応する線形係数を乗算することで、まさにその符号の変化が作成されます。 その弱点は、次数を潜在的に (O(N)) として扱うことです。 

重要な観察は、係数境界がそのような状況を防ぐことです。 すべての遷移で明確な正の奇数根が強制されるため、17 次の多項式には、その大きさが (2^{63}) を超える定数係数がすでに存在します。 したがって、有効なインスタンスには最大 16 個の遷移を含めることができます。 入力によるスキャンには依然として (O(N)) のコストがかかりますが、(D\le16) を使用した多項式の構築には (O(D^2)) のコストしかかかりません。 

これにより、非常に簡単な解決策が得られます。 文字列を 1 回スキャンし、隣接する 2 つの文字が異なるたびに奇数の整数 (2i+1) を収集し、係数 (x-r) を乗算します。 最後に、最初の文字に従って多項式全体の符号を選択​​します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 係数境界を使用しない単純な拡張 | (O(N^2))、最大 49,995,000 更新 | (O(N)) | 不必要に遅い |
 | 最適 | (O(N+D^2))、(D\le16) を使用 | (O(D)) | 承認済み |

 コンテストの公式ディスカッションでは、意図された (O(n^2)) アプローチとして直接乗算が説明されており、(2^{63}) 係数制限により有効な次数が実質的に最大 16 になることが指摘されています。 

## アルゴリズムのチュートリアル

 1. すべての隣接するペアをスキャンします`S[i]`そして`S[i+1]`。 それらが等しい場合、2 人の国民の間で符号を変更する必要はないため、そこにルートは必要ありません。 それらが異なる場合は、(2i+1) をルート リストに追加します。これは、厳密にシチズン位置 (2i) と (2i+2) の間にある唯一の整数であるためです。 
2. 採取した根の数を(D)とする。 すべての符号遷移には少なくとも 1 つの奇数多重度のルートが必要であり、その遷移を実行するには 1 つのルートで十分であるため、これは最小次数です。 
3. 係数リストで表される多項式 (Q(x)=1) から開始します。`[1]`。 すべての根 (r) について、(Q(x)) を (Q(x)(x-r)) に置き換えます。 現在の係数が降順で保存されている場合、(x-r) を乗算すると、次のように係数が変更されます。 
[
 b_j=a_j-ra_{j-1}。 
】
 最初の係数は (a_0) のままで、新しい最終係数 (-ra_D) が作成されます。 
4. (Q) が最初の市民 (x=2) ですでに正しい符号を持っているかどうかを判断します。 選択されたすべての根は 2 より大きいため、すべての因数 (2-r) は負になります。 その結果、
 [
 \演算子名{符号}(Q(2))=(-1)^D。 
】
 最初の文字が`H`、正の値が必要です。 もしそうなら`A`、負の値が必要です。 現在の符号が間違っている場合は、すべての係数を否定します。 
5. 出力 (D) とその結果の係数リスト。 ルートはまさに遷移点であり、すべてのルートの多重度は 1 であるため、入力文字列の文字が変わる場所で符号が正確に変わります。 

これが機能する理由: 2 人の連続する市民の間には、整数根 (2i+1) が 1 つだけ存在します。 における移行`S`その区間内で奇数のルートを強制するため、(2i+1) の少なくとも 1 つのコピーは避けられません。 そこにコピーを 1 つだけ配置し、最小限の学位を与えます。 選択されたすべてのルートは、その遷移に関連付けられた 2 人の市民の間に正確に存在するため、それを横切ると、多項式の符号が 1 回だけ反転されます。 したがって、最初の市民からグローバル サインが選択されると、隣接するすべてのサインが必要なパターンに一致します。 多項式は最終的なグローバル符号の前ではモニックであり、すべての根と係数は整数であるため、すべての出力要件が満たされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)

    roots = []

    for i in range(n - 1):
        if s[i] != s[i + 1]:
            roots.append(2 * i + 3)

    degree = len(roots)

    # Coefficients in decreasing order.
    # Initially Q(x) = 1.
    coef = [1]

    for r in roots:
        new_coef = [0] * (len(coef) + 1)

        for j, a in enumerate(coef):
            new_coef[j] += a
            new_coef[j + 1] -= r * a

        coef = new_coef

    # Q(2) has sign (-1)^degree because every root is > 2.
    # We want Q(2) > 0 for H and Q(2) < 0 for A.
    desired_positive = s[0] == 'H'
    q_at_2_positive = (degree % 2 == 0)

    if desired_positive != q_at_2_positive:
        coef = [-x for x in coef]

    print(degree)
    print(*coef)

if __name__ == "__main__":
    solve()
```最初のループは、アルゴリズム ウォークスルー ステップ 1 からの遷移検出を実装します。ゼロベースの Python インデックス付けを使用すると、インデックスの市民は`i`位置 (2i+2) があるため、市民間の整数`i`そして`i+1`は (2i+3) です。 これはよくある 1 点違いです。 

多項式乗算では、係数が次数の降順で格納されます。 もし`coef`を表します

 [
 a_0x^k+a_1x^{k-1}+\cdots+a_k,
 】

 次に、(x-r) を掛けると、

 [
 a_0x^{k+1}
 +(a_1-ra_0)x^k
 +\cdots
 +(a_k-ra_{k-1})x
 -ra_k。 
】

 2つの割り当ては、`new_coef[j]`そして`new_coef[j+1]`これらの貢献を正確に実装してください。 2 つの寄与を別々にしておくと、最初と最後の係数に対する特別な処理も回避されます。 

Python の整数はオーバーフローしないため、特別な 64 ビット演算は必要ありません。 この問題では、最終係数の大きさが (2^{63}) より小さく、正の根を加算して形成される中間多項式の係数の大きさが最終積の係数の大きさ以下であることが保証されます。 

最後の符号の計算では、すべての根が少なくとも 3 であるという事実が使用されます。(x=2) では、すべての因数 (2-r) が負になるため、次数が偶数の場合、否定されていない積は正確に正になります。 その符号が最初の市民の必要なステータスと一致しない場合、すべての係数が無効になります。 

入力文字列は 1 つだけであるため、テストケース ループは必要ありません。

 ## 特殊なケース

 単一の国民の場合、標識の変更が要求される間隔はありません。 入力あり`H`の場合、アルゴリズムは根を見つけず、次数 0 を取得し、多項式 (1) を維持します。 入力あり`A`、同様に次数 0 を見つけますが、定数多項式を (-1) に反転します。 遷移がないということは、まさに定数多項式が最適である条件です。 

可能な限り最小の遷移を実現するには、次のことを考慮してください。`HA`。 2 人の市民は 2 と 4 にいます。必要な記号が異なるため、奇数のルートが厳密にそれらの間に存在する必要があります。 整数は 3 だけであるため、多項式の最小次数は 1 であり、根は 3 でなければなりません。スケーリングされていない多項式 (x-3) は、2 と 4 に負と正の符号があるため、否定する必要があります。 結果は (-x+3) です。 

複数のトランジションについては、次の点を考慮してください。`AHA`。 必要な変更は位置 2 と 4 の間、および位置 4 と 6 の間で発生します。アルゴリズムは根 3 と 5 を選択し、次の結果を生成します。 

[
 Q(x)=(x-3)(x-5)=x^2-8x+15。 
】

 次数が偶数であるため (Q(2)>0)。 最初の文字は`A`したがって、多項式全体が否定されます。 

[
 P(x)=-x^2+8x-15。 
】

 2、4、および 6 の値には、必要に応じて負、正、負の符号が付けられます。 

連続 10,000 人など、変化がほとんどない大規模な母集団の場合`H`文字を含む場合、アルゴリズムは 9999 次の多項式を構築しません。 文字列全体をスキャンし、ゼロ遷移を見つけて、すぐに (P(x)=1) を返します。 これは、入力の長さと多項式の次数を別個の量として扱う必要がある理由を示しています。 

最後に、17 個のトランジションを持つ仮想の交互文字列について考えてみましょう。 このような入力では、少なくとも (3,5,\ldots,35) のルートが強制されます。 それらの積はすでに (2^{63}) を超えているため、その最小次多項式は係数限界を満たすことができません。 問題の保証により、そのような例は除外されます。 これが、(N\le10^4) と記載されているにもかかわらず、係数と係数の直接の乗算が安全である隠れた理由です。
