 ## 解決策
 ## 問題の理解

 各星には固定された位置があります`(X, Y)`そして明るさ`B`。 バーニーが写真全体を回転すると、プリンターが上から下にスキャンします。 回転後、より大きく変形した星`Y`座標は先に出力されます。 同じように変形した星`Y`座標も同時に印刷されます。 

回転により、明るい星はすべて、暗い星よりも低く見えないようにする必要があります。 星があれば`i`そして`j`持っている`B_i > B_j`、必要な条件は`Y'_i >= Y'_j`。 

回転中心は関係ありません。 同じベクトルですべての星を平行移動すると、変換されたすべての星が変化します`Y`同じ量だけ変化するため、新しい縦軸の方向のみが重要になります。 

その方向は単位ベクトルで説明できます`d`。 変換された点の垂直座標`p`への投影です`d`、つまり`p · d`。 したがって、問題全体は方向性を見つけることになります`d`そのような`(p_i - p_j) · d >= 0`すべてのペアに対して`B_i > B_j`。 

多くても`1000`星なので、最大でも`1000 * 999 / 2 = 499500`ペア。 アン`O(N^2)`このアルゴリズムは、約 50 万個のペア制約のみを意味するため、現実的です。 アン`O(N^3)`このアプローチでは、すでに約 10 億の基本操作が実行されますが、多くの候補ローテーションについてすべてのペアを繰り返しチェックするアルゴリズムは、およそ 10 億の基本操作を実行できます。`O(N^4)`そして大きすぎます。 

いくつかの詳細は誤って扱われやすいものです。 まず、明るさが等しいと順序付けの要件が課されません。 例えば、```
3
0 0 2
10 0 2
0 10 1
```答えがあります`Y`。 2 つの明るさ 2 の星を一緒に印刷することもでき、適切な方向で両方を明るさ 1 の星の上に配置することもできます。 等しい明るさを厳密な順序付けが必要なものとして扱う解決策は、このケースを誤って拒否することになります。 

第二に、投影における平等が許可されます。 考慮する```
3
1 0 2
-1 0 2
0 0 1
```唯一有効な方向は垂直方向です。 3 つの星はすべて同じように変換されます`Y`, そのため、2 つの明るい星は暗い星と同時に印刷されますが、これは許容されます。 答えは、`Y`。 厳密な使用法`>`の代わりに`>=`誤って生成してしまう`N`。 

第三に、すべての星は同じ明るさを持つ可能性があります。 例えば、```
3
0 0 7
1 2 7
4 -3 7
```答えがあります`Y`, 明るさの比較がまったくないからです。 どの回転も有効です。 

最後に、点が明るい点または暗い点の凸包の内側にある可能性があり、答えが不可能になります。 例えば、```
4
0 0 1
2 0 1
0 2 1
1 1 2
```答えがあります`N`。 明るさ 2 の星は、明るさ 1 の 3 つの星によって形成される三角形の内側に厳密に存在します。 線形投影では、内部点をすべての頂点より厳密に高くすることはできません。 いくつかの隣接する星だけをチェックする方法では、この全体的な矛盾を見逃す可能性があります。 

## アプローチ

 直接的な総当たり手法は、制約の形状から構築できます。 明るさが異なる星のペアごとに、有効な回転方向のセットが得られます。 これらすべてのセットの交差部分が、まさに問題を満たす回転のセットになります。 各制約には 2 つの境界方向があるため、すべての境界方向を候補として生成し、それに対してすべての輝度制約をテストできます。 あれば`K`関連するペアは最大でも`2K`候補の境界、およびすべての制約コストに対して 1 つの候補をテストする`O(K)`。 と`K = 499500`、これには約`2K^2`に近い`5 * 10^11`チェックが遅すぎます。 

ブルートフォースが概念的に機能する理由は、問題が実際には角度範囲の交差であるためです。 間違いは、考えられるすべての境界に対して交差全体を最初から再計算することです。 

重要な観察は、1 対の星が回転に恣意的な制限を与えていないということです。 より明るい星にしましょう`A`、暗い星ほど`C`、定義します`v = A - C`。 

方向性としては`d`、明るい星は暗い星よりも低く印刷されません。`v · d >= 0`。 

もし`a`の角度です`v`そして`θ`の角度です`d`、これは次のようになります`cos(θ - a) >= 0`。 

したがって、有効な方向は 1 つの閉じた半円を形成します。`a - π/2 <= θ <= a + π/2`。 

したがって、すべての明るさの制約は、正確に幅の角度間隔になります。`π`。 

ここでの問題は、最大約 50 万個の閉じた半円を交差させることです。 交差点を直接維持できます。 現在の実行可能な間隔を維持し、それを実数直線上に展開し、新しい半円ごとに、次の倍数だけシフトされたコピーを選択します。`2π`現在の間隔に最も近い値です。 現在の実行可能な間隔は最大でも長さがあるため、`π`、このコピーには、現在の間隔と重複する可能性のあるすべての部分が含まれています。 次に、2 つの通常の間隔を交差させます。 

これにより、すべての間隔のエンドポイントを並べ替える必要がなく、すべての制約に対してすべての候補をテストする必要がなくなります。 結果として得られるアルゴリズムは次のとおりです。`O(N^2)`時間と`O(1)`extra space apart from the input. 同じペアごとの角度制約の定式化は、コンテストのディスカッションでも説明されています。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N^4) | O(N^2) | 遅すぎる |
 | 最適 | O(N^2) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての星を読み取り、その座標と明るさを保存します。 座標はすべての幾何学的制約を決定するのに十分ですが、明るさは差分ベクトルがどの方向を向く必要があるかを示します。 
2. Examine every pair of distinct stars. 輝度値が等しい場合は、どちらの印刷順序でも許可されるため、そのペアをスキップします。 それ以外の場合は、ペアを明るい星から暗い星に向けて向きを変え、そのベクトルを呼び出します。`v`。 
3. 角度を計算する`a = atan2(v_y, v_x)`。 角度付きの垂直方向の候補`θ`ペアを正確に満たすのは`v · d >= 0`、これは以下と同等です`θ`閉じた区間に属する`[a - π/2, a + π/2]`。 
4. 最初の重要な制約を使用して、現在の実行可能な間隔を初期化します。`[L, R]`。 この間隔は意図的にラップされていない状態にしておくため、エンドポイントが外側にある可能性があります。`[0, 2π)`。 
5. 後続のすべての制約について、その定期的なコピーを考慮します。`[l + 2kπ, r + 2kπ]`。 中心が中心に最も近いコピーを選択してください。`[L, R]`。 現在の間隔とすべての制約間隔の両方が最大長であるため、`π`、現在の間隔と交差するコピーには、その間隔に最も近い中心がなければなりません。 選択したコピーを交差させます`[L, R]`。 
6. 新しい交差点が空の場合は、次のように出力します。`N`すぐに。 すべての有効な方向が両方の間隔に属している必要があるため、有効な回転は存在しません。 
7. すべてのペアが処理された後、実行可能な間隔がまだ空でない場合は、出力します。`Y`。 すべての明るさの値が等しい場合、制約は生成されないため、すべての方向が有効となり、印刷も行われます。`Y`。 

### なぜ効果があるのか

 不変条件とは、`[L, R]`は、これまでに処理されたすべての明るさの制約を満たす一連の回転方向を正確に表し、円角度空間が実線上に展開されます。 

1 対の星の場合、不等式は`v · d >= 0`は、有効な方向のちょうど 1 つの閉じた半円です。 現在の実行可能なセットをその半円と交差させると、新しいペアに違反する方向が正確に削除されます。 現在の間隔の長さが最大であるため、最も近い定期コピーを選択しても、可能な解決策が失われることはありません。`π`、2 つの半円は、その中心が最大でも次の場合にのみ重なり合うことができます。`π`別に。 したがって、有効な回転が存在する場合、すべての制約が適用された後でも、維持される間隔は空ではありません。 

閉じた間隔を使用すると、回転後に水平に整列する星も処理されます。 このような等価性はステートメントによって許可されているため、単一の方向から構成される実行可能な間隔が受け入れられる必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from math import atan2, pi

def solve():
    input = sys.stdin.readline

    n = int(input())
    stars = [tuple(map(int, input().split())) for _ in range(n)]

    half_pi = pi / 2.0
    two_pi = 2.0 * pi
    eps = 1e-12

    left = None
    right = None

    for i in range(n):
        xi, yi, bi = stars[i]

        for j in range(i):
            xj, yj, bj = stars[j]

            if bi == bj:
                continue

            if bi > bj:
                dx = xi - xj
                dy = yi - yj
            else:
                dx = xj - xi
                dy = yj - yi

            angle = atan2(dy, dx)
            l = angle - half_pi
            r = angle + half_pi

            if left is None:
                left = l
                right = r
                continue

            mid = (left + right) * 0.5

            # Shift the new semicircle by a multiple of 2*pi
            # so that its center is closest to the current interval.
            k = round((mid - angle) / two_pi)
            l += k * two_pi
            r += k * two_pi

            new_left = max(left, l)
            new_right = min(right, r)

            if new_left > new_right + eps:
                print("N")
                return

            left = new_left
            right = new_right

    print("Y")

if __name__ == "__main__":
    solve()
```入力はトリプルとして保存されます`(x, y, b)`。 ネストされたループは、順序付けされていないペアをすべて 1 回だけ検査するため、ペアが誤って重複することはありません。 

各ペアについて、コードは最初に等しい明るさを無視します。 それ以外の場合は、差分ベクトルが暗い星から明るい星に向かうようになります。 ベクトルを反転すると、必要な半平面が反転するため、この方向は重要です。`atan2`そのベクトルの方向を与えます。 減算と加算`π/2`有効な半円の 2 つの境界を示します。 間隔は意図的に正規化されていません。`[0, 2π)`ラップされていない区間の方が交差しやすいためです。 

表現```
k = round((mid - angle) / two_pi)
```現在の実行可能な間隔の中心に最も近い中心を持つ新しい間隔の定期コピーを選択します。 パイソン`round`ここでは、正確な半整数での動作は無害です。これは、2 つの等しく近いコピーのいずれかが同じ境界交差の可能性を与えるためです。 

アルゴリズムは浮動小数点数を使用して角度演算を実行するため、比較では小さなイプシロンが使用されます。 座標の境界は次のとおりです`10^4`、したがって、整数の差分ベクトルは次のように制限されます。`2 * 10^4`それぞれのコーディネートで。 個別の整数の方向を任意に近づけることはできないため、許容誤差は次のようになります。`10^-12`重要な幾何学的な分離よりも安全に小さくなります。 

Python では整数のオーバーフローは発生しません。実際、実装では大きな整数の演算は必要ありません。 唯一の数値演算は、`atan2`、足し算、割り算、角度の比較。

### ラップアラウンド間隔

 次のような間隔`[90°,270°]`次のように表す必要があるかもしれません`[-270°,-90°]`現在の実行可能な間隔が近づいたとき`-100°`。 アルゴリズムは、次の適切な倍数を追加することでこれを処理します。`2π`すべての間隔を強制的に挿入するのではなく、`[0,2π)`。 この手順を行わないと、有効な交差点は`0°/360°`境界が空であると誤って報告される可能性があります。
