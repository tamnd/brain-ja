 ## 解決策
 ## 問題の理解

 ケーキの境界線は、異なるフルーツが円形に並んでいます。 エッグフルーツを次のように表します。`E`そして柿`P`。 有効なスライスは、果物の連続した円形セグメントで構成され、最大で次のものが含まれます。`S`果物、少なくとも 1 つのエッグフルーツが含まれている必要があります。 

すべての果物は区別できるため、スライスはそれに含まれる位置の正確なセットによって識別されます。 以来`S < n`、 どこ`n`が果物の数である場合、考慮されるすべてのスライスは円の適切な部分になります。 したがって、開始位置とその長さを選択すると、果物のセットが一意に決定されるため、円間隔を直接カウントできます。 公式声明によると、`3 <= n <= 10^5`そして`1 <= S < n`、制限時間は 1 秒です。 

と`n`と同じくらい大きい`10^5`、考えられるすべての長さのすべての間隔を検査するアルゴリズムは高価すぎます。 最悪の場合には、`n(S)`そのような間隔といつ`S = n - 1`これはこうなる`n(n - 1)`、 について`10^10`間隔。 インターバルあたりの少量の一定量の作業であっても、1 秒の制限が許容する量をはるかに超えています。 本質的に線形な解決策が必要です。 

循環的な性質により、最初の自明ではないエッジ ケースが作成されます。 考慮する`PEPEP`と`S = 2`。 最初と最後の位置は隣接しているため、2 つは`P`端の文字は、2 つの柿からなる 1 つの円形のランを形成します。 文字列を通常の直線的なテキストとして扱うと、これら 2 つのパーシモンで構成される間隔が失われ、間違った答えが生成されてしまいます。 正しい答えは、`6`。 

オールパーシモンの場合も明示的な処理が必要です。 のために`PPPP`と`S = 1`、エッグフルーツが入っているスライスはないので、答えは次のようになります。`0`。 少なくとも 1 つのエッグフルーツが存在すると仮定するメソッドでは、存在しないエッグフルーツに誤ってアクセスしたり、無効な間隔をカウントしたりする可能性があります。 

許容される最小スライス サイズは、別の境界ケースです。 のために`EPE`と`S = 1`、単一の果物のスライスのみが許可されます。 まさに 2 つのエッグフルーツが該当するため、答えは次のようになります。`2`。 2 つ以上の長さの間隔を考慮することから始まるアプローチは、過大評価になります。 

ついに、`S`ケーキのほぼ全体かもしれません。 のために`EPPP`と`S = 3`、すべての有効なスライスは、長さが最大 ​​3 の適切な円形の間隔です。 円の長さは 4 なので、円全体を数えてはいけません。`S < n`許容範囲外であることを保証します。 

## アプローチ

 直接的な解決策では、すべての開始位置を列挙し、長さに達するまで一度に 1 つの果物ずつ間隔を延長できます。`S`。 拡張中に、`E`が出現し、条件を満たすたびに間隔を追加します。 これは正しいです。すべての有効なスライスには、開始位置が 1 つと、スライス間の開始位置が 1 つだけの長さがあるからです。`1`そして`S`、 そして`S < n`2 つの異なる表現が同じ果物のセットを記述することを防ぎます。 

問題は間隔の数です。 まさにあります`n`すべての長さで開始できる可能性があるため、総当たり法で検査します。`nS`間隔。 最悪の場合、`S = n - 1`、与える`n(n - 1)`、これはおよそ`10^10`いつ`n = 10^5`。 この時点で、他の単純な方法は使用できなくなります。 

重要な観察点は、`E`。 間隔内のすべてのフルーツが有効である場合、その間隔は無効です。`P`。 したがって、最大ですべての可能な長さの間隔の数から始めることができます。`S`そして全柿間隔の数を引きます。 

からのあらゆる長さに対して`1`を通して`S`、まさにあります`n`円形の間隔があるため、`n`可能な開始位置。 以来`S < n`、これらの間隔はすべてフルーツのセットとして区別されます。 したがって、候補スライスの総数は次のようになります。`n * S`。 

ここで、次の最大循環実行を 1 つ考えます。`r`連続した`P`果物。 すべてのすべて-`P`間隔は、そのような 1 回の実行内に完全に存在する必要があります。 固定長の場合`L`、 どこ`1 <= L <= r`、 がある`r - L + 1`ラン内のその長さのインターバル。 までの長さだけを気にします`S`、それでは`k = min(r, S)`。 走りが貢献する`(r) + (r - 1) + ... + (r - k + 1)`全て-`P`間隔。 この等差数列は次のように計算できます。`k * (r + 1) - k * (k + 1) / 2`。 

すべての最大値に対するこの寄与を合計すると、`P`run は、無効なスライスの完全な数を示します。 

唯一の微妙な点は、円上の最大ランを見つけることです。 文字列が次で始まり次で終わる場合`P`、これら 2 つの直線的な実行は、実際には 1 つの円形の実行です。 何らかのマージ ロジックを見つけることで、特別なマージ ロジックを回避できます。`E`そこでスキャンを開始します。 スキャンが開始されると、`E`、 毎`P`遭遇したランは 2 つのランの間に完全に含まれています`E`したがって、ランはリニア スキャンの境界を越えることはできません。

 ## アルゴリズムのチュートリアル

 1. 循環文字列を読み取る`B`、その長さ`n`、および最大スライス サイズ`S`。 まず、考えられるすべての適切な円間隔を数えてから、完全に柿で構成されている間隔を削除します。 
2. 以下から長さの間隔の合計数を計算します。`1`を通して`S`。 許容される長さごとに次のものがあります。`n`開始位置なので合計は`n * S`。 
3. 文字列に次のものが含まれているかどうかを確認します。`E`。 エッグフルーツがない場合、すべての間隔は無効になり、答えはすぐにゼロになります。 
4. を含む任意の位置を検索します。`E`その位置から円のスキャンを開始します。 これにより、実際に別の文字列を構築することなく、円形の文字列が効果的に回転します。 
5. 現在の長さを維持します`r`連続の`P`走る。 いつでも`P`が発生した場合、増分します`r`。 
6. いつでも`E`が発生した場合、その前の`P`実行が終了しました。 セット`k = min(r, S)`そして引きます`k * (r + 1) - k * (k + 1) / 2`答えから。 それからリセットしてください`r`ゼロに。 数式はすべてをカウントします-`P`この実行内に収まる最大の長さの間隔`S`。 
7. 結局のところ`n`位置が処理されたら、最終的な位置についても同じ計算を実行します。`P`走る。 スキャンを開始する`E`この最後の実行を最初の実行とマージする必要がないことを保証します。 
8. 残りのカウントを出力します。 これらは正確に、少なくとも 1 つを含む間隔です。`E`そして最大でも`S`果物。 

不変条件は、完了したすべての処理の後、`P`実行すると、答えは、許可される循環間隔の合計数から、処理された実行に含まれる無効な間隔を差し引いたものと等しくなります。 最大値`P`実行はばらばらであり、すべての実行は-`P`間隔はそれらのうちの 1 つに正確に属するため、無効な間隔が 2 回減算されることはありません。 残りのすべての間隔には少なくとも 1 つが含まれるため、`E`、最終的な値は正確に必要なスライス数になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def count_slices(B, S):
    n = len(B)

    # Every length 1..S has exactly n circular intervals.
    ans = n * S

    # If there is no eggfruit, every interval is invalid.
    if 'E' not in B:
        return 0

    # Start at an E so that no P-run crosses the scan boundary.
    start = B.index('E')
    p_run = 0

    for step in range(n):
        c = B[(start + step) % n]

        if c == 'P':
            p_run += 1
        else:
            if p_run:
                k = min(p_run, S)
                invalid = k * (p_run + 1) - k * (k + 1) // 2
                ans -= invalid
                p_run = 0

    # Process the final P-run, if any.
    if p_run:
        k = min(p_run, S)
        invalid = k * (p_run + 1) - k * (k + 1) // 2
        ans -= invalid

    return ans

def solve():
    B = input().strip()
    S = int(input())
    print(count_slices(B, S))

if __name__ == "__main__":
    solve()
```最初の計算では、`n * S`、アルゴリズムの最初の部分に対応します。 がある`n`許容される各長さの間隔と条件`S < n`それらの間隔のどれも円全体を表していないことを意味します。 

明示的な`E`チェックはすべてを処理します。`P`循環スキャンが開始される前の場合。 これがなければ、境界が卵の中にあることを保証しながらスキャンを開始する自然な位置が存在しません。 

スキャンではモジュール式のインデックス作成が使用されます。`(start + step) % n`、つまり、オリジナルを正確に参照します。`n`順番に位置を決めます。 文字列を複製する必要がないため、実装が単純になり、一定の補助スペースが使用されます。 

とき`P`走行終了、`p_run`はその正確な長さです。 ランに長さがある場合`r`、 のみ`k = min(r, S)`長さによって無効な間隔が発生する可能性があります。 表現`k * (r + 1) - k * (k + 1) // 2`の合計です`r, r - 1, ..., r - k + 1`。 すべての演算は整数演算です。 Python の整数の精度は任意ですが、最大の答えは次のとおりです。`10^10`なので、オーバーフローの心配はありません。 

最後の実行はループの後に処理されます。 通常、実行は次のときに処理されるため、これを省略したくなります。`E`は見つかりましたが、循環スキャンはまだ内部にある間に終了する可能性があります。`P`走る。 から開始`E`この最後の実行は、スキャン境界を越えて分割されるのではなく、完了します。

オールパーシモンのケースはスキャン前に処理されます。 のために`PPPP`と`S = 1`、ありません`E`そこからスキャン境界を確立する必要があり、より基本的には、考えられるすべてのスライスが無効になります。 すぐにゼロを返す方が簡単で正確です。
