 ## 解決策
 ## 問題の理解

 毎月、農民の富は、対応する値によって変化します。`A`。 その月の収入を追加すると、富はすぐにその期間に強制的に戻されます。`[L, U]`: 上記の値`U`なる`U`、および以下の値`L`なる`L`。 

クエリは開始月を返します`B`、終了月`E`、そして最初の富`X`。 何か月も申請しなければなりません`B`を通して`E`の修正も含めて順番に`[L,U]`毎月、最終的な財産を報告します。 

入力には次の 1 つの配列が含まれます。`N`月収、続いて`Q`独立したクエリ。 の値`N`そして`Q`どちらも到達できる`10^5`1 つのクエリですべてをカバーできる場合もありますが、`N`数か月。 公式アーカイブでは、3 秒の時間制限と 1024 MB のメモリ制限が与えられています。 と`10^5`クエリを毎月実行するアプローチでは、最大で次のクエリを実行できます。`10^10`月の移り変わり。 これにより、クエリごとの線形作業が排除され、前処理後にクエリごとにほぼ対数的な作業が必要になります。 

一見合理的な実装が間違っている可能性があるいくつかの特殊なケースがあります。 1 つ目は、修正が月末だけでなく毎月後に行われることです。 考慮する：```
2 1 10
-10 10
1
1 2 5
```富の順序は、`5 -> 1 -> 10`、したがって、答えは次のとおりです`10`。 最初に 2 つの収入を加算する不注意な解決策では、次の結果が得られます。`5`、下限によって 2 か月目の開始点が変更されたことが完全に欠落しています。 

2 番目のエッジ ケースは、ちょうど 1 か月を含むクエリです。 例えば：```
1 1 10
100
1
1 1 5
```答えは、`10`。 単一の月を空の間隔として扱ったり、収入を追加する前に補正を適用したりする理由はありません。 

3 番目のエッジ ケースは、一定になる変換です。 考慮する：```
2 1 10
8 -8
1
1 2 3
```から始まる`3`、最初の月は`10`、そして2番目は与えます`2`、したがって、答えは次のとおりです`2`。 この 2 か月が経過すると、十分に大きな開始値がすべて上限を超えてしまい、構成はもはや通常の変換ではなくなります。 総収入のみを格納する表現では十分ではありません。 

## アプローチ

 直接的なアプローチは簡単です。 すべてのクエリに対して、富を次のように初期化します。`X`、からスキャンします`B`を通して`E`、追加`A[i]`そして結果をクランプします`[L,U]`追加するたびに。 これは問題で説明されている毎月のプロセスに正確に従っているため、これは正しいです。 

問題は繰り返し作業の量です。 すべてのクエリが配列全体をカバーする場合、次のような問題が発生する可能性があります。`Q * N = 10^5 * 10^5 = 10^10`個々の月の更新。 各更新は一定時間であっても、それは制限時間内に収まる時間をはるかに超えています。 

有益な観察は、月の間隔全体を 1 つの関数として扱うことができるということです。 収入のある一ヶ月間`a`、変換は

 [
 f(x)=\min(U,\max(L,x+a))。 
】

 クランプ操作により前月の情報の一部が破壊される可能性があるため、最初はこれを組み合わせるのが難しいように見えます。 ただし、これらの変換のすべての構成には非常に小さな表現が含まれます。 

変換を次のように表します

 [
 f(x)=\min(hi,\max(lo,x+add))。 
]

ここ`add`関数の傾きが 1 である部分の変換を説明します。`lo`そして`hi`最後の下部プラトーと上部プラトーを説明します。 単一の月には次の表現があります`(a, L, U)`。 

最初の変換が次のようになっているとします。 

[
 f(x)=\オペレータ名{クランプ}(x+s_1,l_1,u_1)
 】

 そして次の変身は

 [
 g(x)=\オペレータ名{クランプ}(x+s_2,l_2,u_2)。 
】

 構成が必要です`g(f(x))`。 2 番目のクランプの前に、最初の関数の出力は次のようにシフトされます。`s2`, したがって、その有効範囲は次のようになります。`[l1+s2, u1+s2]`。 このずれた範囲が交差すると`[l2,u2]`、構成は

 [
 \オペレータ名{クランプ}
 \左(
 x+s_1+s_2、
 \max(l_1+s_2,l_2),
 \min(u_1+s_2,u_2)
 \右）。 
】

 シフトされた最初の範囲が完全に下にある場合`l2`、結果は常に`l2`。 完全に上にある場合`u2`、結果は常に`u2`。 

これにより、連続する月を結合するための一定サイズの連想演算が得られます。 セグメント ツリーは、各間隔の結合された変換を保存できます。 次にクエリを結合します`O(log N)`毎月訪問する代わりにツリーノードを訪問します。 

ブルート フォース手法は、すべての状態遷移を明示的にシミュレートするため機能しますが、同じ長い間隔を繰り返しシミュレートすると失敗します。 区間全体が 3 つの整数で要約できるという観察により、繰り返しのシミュレーションを範囲合成に置き換えることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 最悪の場合は O(NQ) | O(1) 入力以外 | 遅すぎる |
 | 最適 | O(N + Q log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての区間変換を次のように表します。`(add, lo, hi)`、意味

 [
 f(x)=\min(hi,\max(lo,x+add))。 
】

 収入のある単月`A[i]`は`(A[i], L, U)`農家が最初に追加するため`A[i]`そしてクランプします`[L,U]`。 
2. 2 つの変換を構成する方法を定義します。 最初の変換が次のようになっているとします。`(s1,l1,u1)`そして2つ目は`(s2,l2,u2)`。 最初の変換を適用した後、`s2`出力範囲を にシフトします`[l1+s2,u1+s2]`。 

もし`u1+s2 < l2`、すべての可能な値は 2 番目の変換の下限を下回るため、合成は定数関数になります。`l2`。 

もし`l1+s2 > u2`、すべての可能な値が 2 番目の変換の上限を超えているため、合成は定数関数になります。`u2`。 

それ以外の場合、2 つの範囲は重なり、その構成は次のように表されます。 

[
 s=s_1+s_2、
 】

 [
 lo=\max(l_1+s_2,l_2),
 】

 [
 hi=\min(u_1+s_2,u_2)。 
】
 3. セグメントツリーを構築します。 各リーフには変換が 1 か月間保存されます。 各内部ノードは、その左の子の変換とそれに続く右の子の変換の構成を保存します。 毎月の変換は可換ではないため、順序は重要です。 
4. お問い合わせの場合`[B,E]`では、標準の反復セグメント ツリー範囲クエリを使用して、その間隔をカバーする変換を収集します。 左側から選択されたノードは、自然な順序で構成されます。 右側から選択されたノードは、その側にすでに蓄積されているノードよりも前に発生するため、先頭に追加する必要があります。 
5. ID 変換を使用してクエリ アキュムレータを開始します。`(0,L,U)`。 有効な富はすべてそこにあるので、`[L,U]`、これは次のように機能します`f(x)=x`あらゆる可能な入力に対して。 選択したすべてのノードを左から右に構成します。 
6. 結果の変換を適用します`X`。 結果はまさに月後の富です`E`セグメント ツリー変換は、月ごとのオペレーションの構成を表すためです。`[B,E]`。 

### なぜ効果があるのか

 重要な不変条件は、すべてのセグメント ツリー ノードが、有効な開始資産に対するその期間内のすべての月の影響を正確に表すということです。 リーフは正確に月 1 回の更新であるため、正しいです。 2 つの隣接する間隔がマージされると、右の変換が左の変換の出力に適用されるため、親は完全な時系列シーケンスを表します。 帰納法により、クエリされた分解のルートは、要求された間隔全体を表します。 最終的な変換はクエリの初期値で評価されるため、`X`、毎月必要な修正をすべて行った後の、生み出される価値はまさに富です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def combine(s1, l1, u1, s2, l2, u2):
    """
    Return the transformation obtained by applying
    (s1, l1, u1) first and (s2, l2, u2) second.
    """

    shifted_l = l1 + s2
    shifted_u = u1 + s2

    if shifted_u < l2:
        return 0, l2, l2

    if shifted_l > u2:
        return 0, u2, u2

    return (
        s1 + s2,
        max(shifted_l, l2),
        min(shifted_u, u2),
    )

def main():
    n, L, U = map(int, input().split())
    a = list(map(int, input().split()))

    size = 1
    while size < n:
        size <<= 1

    # Each tree node stores (add, low, high).
    add = [0] * (2 * size)
    low = [L] * (2 * size)
    high = [U] * (2 * size)

    for i in range(n):
        add[size + i] = a[i]

    for i in range(size - 1, 0, -1):
        left = i << 1
        right = left | 1

        s1 = add[left]
        l1 = low[left]
        u1 = high[left]

        s2 = add[right]
        l2 = low[right]
        u2 = high[right]

        ns, nl, nu = combine(s1, l1, u1, s2, l2, u2)
        add[i] = ns
        low[i] = nl
        high[i] = nu

    q = int(input())
    out = []

    for _ in range(q):
        B, E, x = map(int, input().split())

        # Convert [B, E] to the half-open interval [B-1, E).
        left = B - 1 + size
        right = E + size

        # Identity transformation on [L, U].
        ls, ll, lu = 0, L, U
        rs, rl, ru = 0, L, U

        while left < right:
            if left & 1:
                ns, nl, nu = combine(
                    ls, ll, lu,
                    add[left], low[left], high[left]
                )
                ls, ll, lu = ns, nl, nu
                left += 1

            if right & 1:
                right -= 1
                ns, nl, nu = combine(
                    add[right], low[right], high[right],
                    rs, rl, ru
                )
                rs, rl, ru = ns, nl, nu

            left >>= 1
            right >>= 1

        # The right accumulator was built by prepending nodes,
        # so the complete interval is left_acc followed by right_acc.
        ss, sl, su = combine(ls, ll, lu, rs, rl, ru)

        x += ss
        if x < sl:
            x = sl
        elif x > su:
            x = su

        out.append(str(x))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    main()
```の`combine`関数は、ソリューションの数学的核心です。 最初の変換は、時系列順に一致して、2 番目の変換の前に適用されます。 2 つの素のケースは明示的に処理されます。そうしないと、計算された下限と上限が交差する可能性があり、有効なクランプ間隔を記述できなくなるからです。 

セグメント ツリーは反復レイアウトを使用します。 以降の位置に対応する葉`N`恒等変換として初期化されます`(0,L,U)`したがって、実際の間隔には影響しません。 クエリで使用されるのは、`[B-1,E)`これにより、内部的には右のエンドポイントが排他的となり、ツリーを移動する際の 1 つずつの調整が回避されます。 

反復範囲クエリでは右側から逆の順序でいくつかのノードが検出されるため、2 つのクエリ アキュムレータが必要です。 左側のアキュムレータは変換を追加し、右側のアキュムレータは変換を先頭に追加します。 最後に 2 つのアキュムレータを結合すると、元の左から右の順序が復元されます。 

Python の整数には任意の精度があるため、累積`add`値が最大であってもオーバーフローしません`10^5`莫大な収入`10^6`組み合わせることができます。
