 ## 解決策
 ## 問題の理解

 彫刻ベースは正の整数の配列で表すことができます

 [
 a_1、a_2、\ldots、a_S、
 ]

 ここで、(a_i) は (i) 番目のスタック内のブロックの数です。 正確に (S) のスタックと正確に (B) のブロックが必要なので、

 [
 a_1+a_2+\cdots+a_S=B、
 \qquad a_i\geq 1.
 ]

 スタックの順序が重要です。 たとえば、((1,4,1)) と ((4,1,1)) は異なる基数です。 

蓄積された水に関する条件には、有益な幾何学的な解釈があります。 彫刻を一度に 1 水平レベルずつ見てください。 どの高さでも、その高さに達したスタックは 1 つの連続した間隔を形成する必要があります。 同じレベルにブロックがあった場合、その隙間には両側にブロックがあり、水が残る場所ができます。 

したがって、スタック高さの順序は、最初は減少せず、次に増加しない必要があります。 言い換えれば、単一のピーク、おそらくプラトーがあるということです。 たとえば、((1,2,3,2,1)) は有効ですが、((1,3,1,2)) は無効です。これは、シーケンスがダウンし、その後再び上昇するためです。 

入力には、(S) スタック数と (B) ブロックの総数が含まれます。 どちらも最大 (5000) です。 公式コンテストの制限は 2 秒、1024 MB です。 

(5000) という境界は、すべての構成を列挙するものを除外します。 (B) から (S) 部分へのポジティブな組成の数は、

 [
 \binom{B-1}{S-1}、
 ]

 これは、中程度の値であっても膨大になります。 多項式時間の動的プログラムが必要です。 (O(SB)) ソリューションはすでに十分ですが、実装で (O(B-S)) メモリのみを使用するようにすることもできます。 

誤って処理されやすい境界ケースがいくつかあります。 (S=1) の場合、可能な配列は ((B)) のみであるため、すべての (B) に対して 1 つの塩基が存在します。 したがって、入力`1 5`答えは(1)です。 スタックの周囲に 2 つの側面が存在することを前提とした解決策は、このケースを誤って拒否する可能性があります。 

(S=2) の場合、2 つの占有位置の間にギャップは存在できないため、すべての正のペアが有効になります。 のために`2 5`の場合、4 つの配列 ((1,4)、(2,3)、(3,2)、(4,1)) はすべて有効なので、答えは (4) になります。 一意のピークを必要とする解では、((2,3)) と ((3,2)) が両方とも有効であるにもかかわらず、誤って破棄される可能性があります。 

(S=B) の場合、すべてのスタックには 1 つのブロックが含まれている必要があります。 結果的に答えは(1)となります。 のために`5000 5000`、可能な配列は (5000) 個だけなので、答えは (1) になります。 このケースでは、実装が余分なブロックを正しく処理しないこともチェックします。 

## アプローチ

 直接的なアプローチは、(B) のすべてのポジティブな構成を (S) 部分に列挙することです。 各構成について、高さをスキャンして、最初は減少せず、次に増加しないかどうかを確認できます。 これは正しいです。この状態は、水平レベルがなく、隙間があるのとまったく同じであるからです。 

このような構成は (\binom{B-1}{S-1}) 個あり、1 つを確認するには (O(S)) 時間がかかります。 

[
 O\left(S\binom{B-1}{S-1}\right)。 
]

 (S=2500) と (B=5000) では、これはすでに調べる必要があります。 

[
 \binom{4999}{2499}
 ]

 候補配列の数は天文学的に膨大です。 このブルートフォースは、考えられるすべての彫刻を直接テストするため機能しますが、作業のほとんどすべてが同じ小さな有効な形状を再発見することに費やされるため、失敗します。 

有益な観察は、個々のスタックの高さについて考えるのをやめ、代わりに水平レイヤーについて考えることです。 最下層には常にすべての (S) 位置が含まれます。 その上のすべてのレイヤーは、その下のレイヤーに含まれる連続した間隔である必要があります。 現在のレイヤーに幅 (s) がある場合、上位レイヤーは (1) から (s) までの任意の幅を持つことができ、その位置は左端点を選択することによって決定されます。 

これらのネストされた間隔をカウントするさらに簡単な方法があります。 現在の最下層に幅 (s) があり、その上に利用可能なブロック (b) があるとします。 現在のレイヤーの上の最初のレイヤーを考えてみましょう。 幅全体を占めるか、左端の位置を空のままにするか、右端の位置を空のままにするかのいずれかです。 左端と右端の位置が両方とも空の場合は 2 回カウントされるため、包含排他は次のようになります。 

DP(s-2,b)。 
]

 最初の項は、完全に完全な次の層を処理します。 第 2 項と第 3 項は、可能な 2 つの辺が空であることを処理し、減算によってそれらの重複が除去されます。 このコンパクトな反復は、最適解の背後にある重要な観察です。 

(S) ブロックの最下層は必須であるため、(b=B-S) を使用します。 したがって、(DP(S,B-S)) はまさに要求された答えです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O\left(S\binom{B-1}{S-1}\right)) | (O(S)) | 遅すぎる |
 | 最適なDP | (O(S(B-S))) | (O(B-S)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. (E=B-S) を各スタックに 1 つのブロックを入れた後に残るブロックの数とします。 幅 (s) のベース層内に追加ブロック (b) を配置する有効な方法の数 (DP(s,b)) を計算します。 

これにより、問題から必須の最下層が削除され、すべての (s) に対して (DP(s,0)=1) が作成されます。これは、追加のブロックを配置しない可能性が 1 つだけあるためです。 
2. 有効な彫刻を入れ子の水平間隔として解釈します。 レイヤーに幅がある場合、その上のすべてのレイヤーは、それらの位置内に含まれる連続した間隔でなければなりません。 

まさに無水状態です。 水平層が切断されると、両側のブロックとの隙間が残り、そこに水が溜まります。 
3. (s=1) の場合、追加ブロックの数ごとに可能な彫刻は 1 つだけです。 すべてのブロックは単純に 1 つのスタックを形成するため、

 [
 DP(1,b)=1。 
]
 4. (s\geq2) については、現在の width-(s) 層の上の最初の層を考慮します。 

このレイヤーがすべての位置を占める場合、ブロックを消費します。 残りの構造は、同じ幅と (b-s) ブロックを持つ有効な構造であり、次のようになります。 

[
 DP(s,b-s)。 
]
 5. 最初の上層が左端の位置を占めていない場合、その上にあるものはすべて残りの (s-1) 位置の内側にあります。 (DP(s-1,b)) のような構造が存在します。 

右端の位置が空の場合も同じ引数が適用され、別の (DP(s-1,b)) が与えられます。 
6. 両方の外側の位置が空である構築は、前の両方のケースでカウントされました。 このような構造は実際には (s-2) 位置内に存在するため、(DP(s-2,b)) に寄与します。 一度減算してみます。 

3 つのケースを組み合わせると、

DP(s-2,b)。 
]
 7. 増加する (s) と増加する (b) を使用して状態を計算します。 状態 (DP(s,b-s)) は同​​じ行に属しますが、小さい (b) を持ち、他の 2 つの状態はすでに計算された行に属します。 
8. 前の 2 行のみが必要です。 現在の行の場合、(DP(s,b-s)) は現在の行自体から読み取られるため、完全な 2 次元テーブルは必要ありません。 前の行とその前の行を保存し、現在の行を構築します。 
9. 最終的な答えは、(DP(S,B-S)) の縮小法 (10^9+7) です。 

### なぜ効果があるのか

 不変条件は、(DP(s,b)) が幅 (s) の最下層内に適合し、正確に (b) 個の追加ブロックを使用する有効な入れ子層構造を正確にカウントすることです。 すべての構造には固有の最初の上層があります。 そのレイヤーがいっぱいの場合、そのレイヤーは最初のケースにのみ属します。 いっぱいでない場合、その間隔は左側の境界、右側の境界、またはその両方を除外する必要があります。 2 つの片面のケースはそのような構造をすべてカバーしており、両面のケースを差し引くと唯一の重複が除去されます。 したがって、すべての有効な構造は 1 回だけカウントされ、無効な構造は導入されません。 元の彫刻は正確に幅 (S) の最下層に (B-S) 個の追加ブロックが続くため、(DP(S,B-S)) が必要な答えになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 1_000_000_007

def solve():
    S, B = map(int, input().split())
    extra = B - S

    # dp2 = DP(s - 2, *)
    # dp1 = DP(s - 1, *)
    # cur = DP(s, *)
    #
    # DP(1, b) = 1 for every b >= 0.
    dp2 = [0] * (extra + 1)
    dp1 = [1] * (extra + 1)

    if S == 1:
        print(1)
        return

    for s in range(2, S + 1):
        cur = [0] * (extra + 1)

        for b in range(extra + 1):
            value = 2 * dp1[b] - dp2[b]

            if b >= s:
                value += cur[b - s]

            cur[b] = value % MOD

        dp2, dp1 = dp1, cur

    print(dp1[extra])

if __name__ == "__main__":
    solve()
```問題には 1 つのテスト ケースが含まれているため、入力は 1 回読み取られます。 すべてのスタックには少なくとも 1 つのブロックが含まれている必要があるため、(B) から (S) をすぐに減算します。 

配列`dp1`そして`dp2`(s) の前の 2 つの値を表します。 最初は`dp1`は (DP(1,b)) であり、すべての (b) に対して (1) に等しくなります。`dp2`繰り返しは (s=2) から開始してのみ使用されるため、ゼロに初期化されます。そのため、(s=-1) に対して実際の行を定義する必要はありません。 

新しい幅ごとに`s`、`cur[b]`から始まる

 [
 2DP(s-1,b)-DP(s-2,b)。 
]

いつ`b >= s`、追加します`cur[b-s]`、つまり (DP(s,b-s)) です。 その状態は意図的に`b >= s`: 完全な新しいレイヤーにはちょうど (s) 個のブロックが必要なので、残っているブロックが (s) 個未満の場合は形成できません。 

Python の整数はオーバーフローしませんが、値は状態ごとにモジュロ (10^9+7) で減算されます。 減算により一時的に負の値が生成される可能性があるため、`% MOD`必要な範囲に正規化するために適用されます。 

現在の行は小さい値から計算する必要があります`b`大きい`b`、 なぜなら`cur[b]`に依存します`cur[b-s]`。 この順序付けは不可欠です。 ループを逆にすると、計算されていない状態が読み取られます。 

ローリング配列により、メモリが (O(S(B-S))) から (O(B-S)) に削減されます。 また、この実装では、再帰によって構造が直接カウントされるため、スタック高さの配列の構築が回避されます。

 # DP(3,0)+2DP(2,3)-DP(1,3)

行 (s=3) は不変式を直接確認します。 3 つのスタックと 6 つのブロックを持つ 8 つの有効なベースがあり、残りの 2 つのポジティブな構成には谷があり、水が蓄積します。 

### サンプル 2

 のために`S = 3`そして`B = 7`, (7-3=4) 個の余分なブロックがあります。 

| (s) | (DP(s,0)) | (DP(s,1)) | (DP(s,2)) | (DP(s,3)) | (DP(s,4)) |
 | --- | --- | --- | --- | --- | --- |

 | 3 | 1 | 3 | 5 | 8 | 12 |

 最終的な状態は、

 # DP(3,1)+2DP(2,4)-DP(1,4)

 # 3+2\cdot5-1

 1.

 ]

この例では、反復に減算項が必要な理由も示しています。 (DP(1,4)) を減算しない場合、中央のスタックに限定された構造は、左側の除外で 1 回カウントされ、右側の除外で 1 回カウントされます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(S(B-S))) | 行ごとに (S) 個の DP 行と (B-S+1) 個の状態があります。 |
 | スペース | (O(B-S)) | 前の 2 行と現在の行のみが保存されます。 |

 (S\leq B\leq5000) であるため、積 (S(B-S)) は最大約 (625) 万であり、(S=B/2) 付近に達します。 これは快適な多項式であり、強引に検討される膨大な数の合成を回避します。 メモリ使用量は (B-S) にのみ比例するため、最大の場合はテーブル全体 (5000\times5000) ではなく、行ごとに数千の整数が使用されます。

## 特殊なケース

 のために`1 5`、 (S=1) と (B-S=4) があります。 アルゴリズムは明示的なレベルに達します`S == 1`ケースと返品`1`。 可能なベースは 1 つだけ、つまり 5 つのブロックを含む 1 つのスタックだけです。 谷や周囲の 2 つの側面という概念は必要ありません。 

のために`2 5`の場合、追加ブロック数は (3) です。 最初の DP 行はすべて 1 です。 (s=2) の場合、再帰により (DP(2,0)=1)、(DP(2,1)=2)、(DP(2,2)=3)、および (DP(2,3)=4) が得られます。 最終的な答えは (4) で、4 つの可能な正のペアの合計が 5 になることに対応します。 これにより、誤って一意の最大値を要求したり、単調配列を拒否したりする実装が捕捉されます。 

のために`3 3`、余分なブロックはありません。 最下層にはすでに 3 つのブロックがすべて含まれているため、彫刻は ((1,1,1)) だけです。 DP は (DP(s,0)=1) で始まり、答えは次のとおりです。`1`。 これは具体的に次のことをチェックします`b-s`の場合はアクセスされません`b < s`。 

のために`5000 5000`、追加ブロック数はゼロです。 DP はスタック カウントを処理する必要がありますが、各行には状態 (b=0) のみが含まれます。 漸化式により (DP(s,0)=2DP(s-1,0)-DP(s-2,0)=1) が得られるため、最終的な答えは次のようになります。`1`。 これにより、ゼロ追加ブロック境界と最大入力次元の両方が検証されます。 

のために`4 8`、すべてのスタックは有効なベースの 1 つで高さ 2 を持ちますが、他にも多くの有効な単峰構成があります。 DP は (DP(4,4)=20) となります。 これにより、アルゴリズムが完全に対称的な形状だけではなく、すべての有効な形状をカウントしているかどうかがチェックされます。 

同様の問題に対して保持すべき重要なアイデアは、レイヤー ビューです。ギャップがない条件により、複雑な配列の高さ制限がネストされた間隔に変わることがよくあります。その後、最初のレイヤーは、どの境界に接触するかによって分類できます。
