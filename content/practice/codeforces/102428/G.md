 ## 解決策
 ## 問題の理解

 都市名は文字列です`C`。 写真は、任意の連続したセクションをキャプチャできます。`C`、つまり、のすべての部分文字列`C`可能性のある絵です。 写真を任意の順序で並べ、その内容を連結して友人の名前を取得する場合があります。 個々の画像内の文字を変更、反転、並べ替えることはできません。 

各友達の文字列について`P`の部分文字列の最小数が必要です。`C`その連結は正確には`P`。 都市名に含まれるどのセクションでも写真を撮影できるため、必要に応じて同じセクションを再度使用できます。 

たとえば、`C = MONTEVIDEO`、文字列`DEMONIO`次のように分割できます`DE | MON | I | O`。 すべての部分は、次の連続した部分文字列です。`C`、ピースは都市名の位置とは異なる順序で表示される場合があります。 答えは4つです。 

すべてのフレンド文字列の合計の長さは最大でも`2 * 10^5`。 都市文字列自体は固定テキストであり、そこからすべての可能な部分が抽出されます。 公式ジャッジは制限時間 2 秒とメモリ 1024 MB を与えます。 すべての友人のすべての可能な部分文字列を検査する解決策は、友人の長さが 2 次であり、これは約`2 * 10^10`ある長さの友人の候補部分文字列`2 * 10^5`。 それは制限時間内に処理できる量をはるかに超えています。 合計入力サイズにおいて基本的に線形の作業が必要です。 

一見合理的と思われる実装が間違っている可能性があるいくつかの特殊なケースがあります。 

考慮する```

2
A
B
```答えは次のとおりです。`1`そして`-1`。 必須の文字が都市の部分文字列を開始できなくなると、友達になることは不可能になります。 一致に失敗した後にピースの数を盲目的に増加させる実装では、報告する代わりに、誤って不可能なピースをカウントする可能性があります。`-1`。 

考慮する```

1
ABAB
```答えは`2`を使用して`ABA | B`。 貪欲な実装では、以前に使用された画像の一部でもあったキャラクターを含め、次の画像が友人の任意のキャラクターから開始できるようにする必要があります。 写真を市内の重複しない場所に制限すると、別の問題が解決されます。 

考慮する```

```答えは`3`を使用して`C | B | A`。 画像の順序に制限はありませんが、画像内の文字には制限がありません。 逆転する`ABC`入手する`CBA`は禁止されているので、1 枚の写真で全員を友達にすることはできません。 

ついに、```

```答えがあります`2`を使用して`AAA | A`。 市内の同じセクションを再度撮影することができるため、最初の写真がすでに使用されているという事実`AAA`可能な画像のセットからは削除されません。 

## アプローチ

 直接的なアプローチは動的プログラミングです。 させて`dp[i]`最初の画像を作成するために必要な画像の最小数になります。`i`友人のキャラクター。 位置から`i`、すべての終了位置を試すことができます`j`、どうかを確認してください`P[i:j]`内部のどこかで発生する`C`、更新します`dp[j]`。 

これは正しいです。すべての有効な構造には最終的なイメージがあり、DP はその最終的な部分文字列に対して可能なすべての選択を考慮するからです。 問題は、調べなければならない部分文字列の数です。 長身の友人`m`まさに`m(m+1)/2`空ではない部分文字列。 のために`m = 200000`、つまり`20000100000`、各候補者が市内に存在するかどうかを確認するコストを考慮する前に、約200億人の候補者がいます。 

都市のすべての部分文字列を前処理してセットにすることもできますが、それによって都市側に同じ二次関数の障害が発生します。 長さのある都市`L`もっている`L(L+1)/2`考慮すべき部分文字列の出現。 その後、定数時間のハッシュセット検索を行ったとしても、前処理はすでに大きすぎます。`L`大きいです。 

有益な観察は、実際には、考えられるすべての次の部分を考慮する必要はないということです。 現在接尾辞を構築しようとしているとします。`P[i:]`。 させて`G`～の最長のプレフィックスになる`P[i:]`の部分文字列として発生する`C`。 

選択する`G`常に、最初の写真を短いものを選択するのと同じくらい効果的です。 最初の写真に長さがある最適な構造を選択します。`k`、 どこ`k <= |G|`。 以来`G`それ自体は次の部分文字列です`C`、その構造の最初の数枚の写真を置き換えることができます。 もし`G`それらのピクチャの 1 つの内部で終わっている場合、そのピクチャの未使用のサフィックス自体が次の部分文字列になります。`C`、部分文字列のすべての部分文字列は、次の部分文字列でもあるためです。`C`。 したがって、さらに多くの画像を使用せずに構成を調整できます。 

これにより、友人のすべての位置で、都市内で発生する最も長いプレフィックスを取得するという貪欲なルールが与えられます。 

残りのタスクは、最長のプレフィックスをすばやく見つけることです。 接尾辞オートマトンは、文字列のすべての部分文字列を正確にコンパクトに表現したものです。 初期状態から始まり、友人のキャラクターのその後の遷移により、現在のプレフィックスが都市内でどれだけ長く発生し続けるかがわかります。 遷移が欠落している場合、現在のプレフィックスは可能な限り長いピクチャになります。 

ブルートフォース手法は、考えられるすべてのセグメンテーションを明示的に探索するため機能します。 候補ピースが二次関数的に多いため失敗します。 可能な限り長い最初の部分が常に短い最初の部分を置き換えることができるという観察により、問題は 1 つの最長のプレフィックスを繰り返し見つけることに帰着します。 接尾辞オートマトンは、これらの部分文字列チェックを線形時間で直接実行します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべての部分文字列を含むブルート フォース DP | O(L² + M²) 部分文字列前処理あり | O(L²) | 遅すぎる |
 | 最適な貪欲 + サフィックス オートマトン | O(L + M) | O(L) | 承認済み |

 ここ`L = |C|`そして`M`すべてのフレンド文字列の長さの合計です。 

## アルゴリズムのチュートリアル

 1. 都市文字列の接尾辞オートマトンを構築する`C`。 

オートマトンの接尾辞は最大でも`2L - 1`の部分文字列のセットを正確に示し、認識します。`C`。 初期状態から、文字遷移のシーケンスをたどることは、そのシーケンスが次の部分文字列である場合に正確に可能です。`C`。 
2. 友達文字列ごとに`P`、位置から開始`pos = 0`そして答えをゼロに設定します。 

この時点で`P[pos:]`まだ施工されていない部分です。 私たちは常に、この接尾辞をできるだけ多くカバーする 1 つの画像を選択したいと考えています。 
3. オートマトンの初期状態から開始して、以下を使用して遷移をたどります。`P[pos]`、`P[pos + 1]`、フレンドが終了するか、必要な移行が存在しないまで、同様に続きます。 

走査が消費すると仮定します`len`文字。 それから`P[pos:pos+len]`は都市の部分文字列ですが、次の文字でそれより長い部分文字列に拡張することはできません。 したがって、これはまさに可能な限り最長の最初の画像です。 
4. もし`len`ゼロ、出力`-1`。 

次で始まる都市の部分文字列はありません`P[pos]`, したがって、次に必要な文字を生成できる可能性のある画像はありません。 すべての構築が次にそのキャラクターを生成する必要があるため、フレンドを形成することはできません。 
5. それ以外の場合は、答えを 1 つ増やして先に進みます`pos`による`len`。 

消費されたプレフィックスは 1 つのピクチャで表されるようになりました。 次の画像は都市の独立した部分文字列であるため、接尾辞オートマトンの走査を初期状態から再開します。 
6. 友人のキャラクターがすべて消費されるまで繰り返します。 

すべての反復で少なくとも 1 人のフレンド キャラクターが消費されるため、最大でも 1 人のフレンド キャラクターが消費されます。`|P|`繰り返し。 

### なぜ効果があるのか

 位置から始まる 1 つの貪欲な反復を考えてみましょう`pos`。 させて`G`～の最長のプレフィックスになる`P[pos:]`それはの部分文字列です`C`。 有効な構造はすべて、何らかの部分文字列で始まる必要があります`X`の`C`、 そして`X`を超えることはできません`G`。 

最適な構築が始まると、`X`、その後、少なくとも次の画像が表示されるまで続けます。`|G|`文字がカバーされています。 最初の部分全体を 1 つの画像に置き換えます`G`。 もし`G`画像の途中で終了しても、その画像の残りのサフィックスは依然として次の部分文字列です。`C`, 次の写真になる可能性があります。 写真の枚数は増えません。 

したがって、最初の画像がまさに貪欲な選択となる最適な解決策が常に存在します。`G`。 取り外し後`G`、同じ引数が残りのサフィックスに独立して適用されます。 貪欲な反復にわたる帰納法により、アルゴリズムは可能な限り最小限の数の画像を生成します。 

接尾辞オートマトンは正確な値を提供します`G`なぜなら、成功したすべての遷移は次の部分文字列を拡張するからです。`C`、一方、最初の欠落した遷移は、もはやプレフィックスが発生できないことを証明しています。`C`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SuffixAutomaton:
    def __init__(self, s):
        self.next = [{}]
        self.link = [-1]
        self.length = [0]
        self.last = 0

        for ch in s:
            self.extend(ch)

    def extend(self, ch):
        cur = len(self.next)
        self.next.append({})
        self.length.append(self.length[self.last] + 1)
        self.link.append(0)

        p = self.last

        while p != -1 and ch not in self.next[p]:
            self.next[p][ch] = cur
            p = self.link[p]

        if p == -1:
            self.link[cur] = 0
        else:
            q = self.next[p][ch]

            if self.length[p] + 1 == self.length[q]:
                self.link[cur] = q
            else:
                clone = len(self.next)
                self.next.append(self.next[q].copy())
                self.length.append(self.length[p] + 1)
                self.link.append(self.link[q])

                while p != -1 and self.next[p].get(ch) == q:
                    self.next[p][ch] = clone
                    p = self.link[p]

                self.link[q] = clone
                self.link[cur] = clone

        self.last = cur

    def longest_prefix(self, s, start):
        state = 0
        pos = start

        while pos < len(s):
            nxt = self.next[state].get(s[pos])
            if nxt is None:
                break
            state = nxt
            pos += 1

        return pos - start

def solve():
    city = input().strip()
    n = int(input())

    sam = SuffixAutomaton(city)

    out = []

    for _ in range(n):
        friend = input().strip()
        pos = 0
        pieces = 0

        while pos < len(friend):
            length = sam.longest_prefix(friend, pos)

            if length == 0:
                pieces = -1
                break

            pos += length
            pieces += 1

        out.append(str(pieces))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```サフィックス オートマトンは、状態ごとに 3 つの情報を保存します。`length[v]`はその状態によって表される最大長です、`link[v]`はそのサフィックスリンクであり、`next[v]`出力される文字トランジションが含まれます。 この構築は、新しい遷移がオートマトンの構造に違反する場合の状態の複製を含む、標準の接尾辞オートマトン拡張手順に従います。 

の`longest_prefix`関数は常に状態 0 から開始します。 これが必要なのは、すべての写真が都市の任意の部分文字列であり、必ずしも都市の接頭語ではないためです。 初期状態から開始するということは、考えられるすべての部分文字列が利用可能であることを意味します。 

ループは最初の欠落した遷移で停止します。 ループで複数の文字が消費された場合、そのプレフィックス全体がその都市で発生していることがわかります。 トランジションが欠落していることは、トランジションをさらに 1 文字拡張することが不可能であることを証明しているため、一致する長さは最大になります。 

最も微妙な境界ケースは、最初の遷移が欠落している場合です。 それから`length == 0`、そして進んでいます`pos`アルゴリズムが永久にループしたり、画像を誤ってカウントしたりする可能性があります。 コードはすぐに返されます`-1`その友人のために。 

試合が成功すると、`pos`次の反復の前に、一致した長さ全体だけ進みます。 一致するプレフィックス全体がすでに 1 つの画像でカバーされているため、一度に 1 文字ずつ進みません。 

Python では整数オーバーフローの懸念はありません。 答えは最大でも友人の長さであるため、答え自体には 32 ビットの整数でも十分です。 

この実装では、遷移に辞書を使用します。 アルファベットには大文字の英字のみが含まれるため、各状態には最大 26 個の出力遷移があります。 26 要素の配列を固定すると、低レベル言語の辞書のオーバーヘッドを削減できますが、辞書を使用すると、線形漸近的な複雑さを維持しながら、Python の実装が大幅に簡素化されます。

## 複雑さの分析

 ## 特殊なケース

 不可能な最初の文字については、次のことを考慮してください。```
ABC
1
D
```オートマトンは初期状態から開始し、すぐに遷移を探します。`D`。 何もないので、最長のプレフィックスの長さは 0 になります。 アルゴリズムの出力`-1`。 カウントされません`D`一文字絵なので`D`都市部では発生しない。 

都市よりも長いが、完全に反復可能な部分で構成されている友人の場合は、次のように考えます。```
AAA
1
AAAA
```最初の走査で消費されるのは`AAA`これは市内で発生する最長のプレフィックスだからです。 残りのサフィックスは、`A`、それ自体が都市の部分文字列です。 答えは`2`。 オートマトンの再構築は一度だけであり、写真は選択すると消えるリソースではないため、同じオートマトンを繰り返し使用することができます。 

任意の画像の順序については、次のことを考慮してください。```
ABC
1
CBA
```最初のトラバースで見つかったもの`C`、次に、オートマトンの初期状態から開始して、`B`、その後、最後の走査で次のことがわかります。`A`。 答えは`3`。 このアルゴリズムは、都市内で選択された写真の位置を保存しようとはしません。これはまさに問題が許容することです。 

貪欲な境界の場合については、次のように考えます。```
ABA
1
ABAB
```最初の走査には次の時間がかかります`ABA`、これは都市の部分文字列であり、プレフィックスは使用できないためです。 残った友人は、`B`、もう一枚写真を撮ります。 答えは`2`。 次のような短い最初の選択肢`AB`も有効な構築にはつながりますが、答えを改善することはできません。これがまさに貪欲な証明の背後にある特性です。 

街そのものと同じ友人のために、```
SANTIAGO
1
SANTIAGO
```オートマトンは、トランジションの欠落に遭遇することなく、すべての文字に従います。 最長のプレフィックスの長さは 8 なので、友人全体が 1 回の反復で消費され、答えは次のようになります。`1`。 これにより、遷移が欠落しているために一致がクエリの終了ではなく、クエリの最後に到達する境界がチェックされます。
