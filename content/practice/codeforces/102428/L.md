 ## 解決策
 ## 問題の理解

 グリッドには N 行と M 列があり、すべてのセルは最初に次のいずれかにマークされています。`G`または`B`。 Javasar は正方形の領域を取得し、そこにアクセスしたときにその正方形内のすべてのセルが良好になるようにしたいと考えています。 

このルートの有益な部分は、一度に 1 行ずつ王国を横断できることです。 連続する 2 つの行の間では、彼は王国の外にいるため、MDT を自由に切り替えることができます。 したがって、各行を独立して変更しないままにすることも、完全に反転することもできます。 ある行に対して行われた選択と、別の行に対して行われた選択の間には相互作用はありません。 

これにより問題が大幅に変わります。 固定行の場合、セグメントが完全に正常になった時点で、そのセグメントは完全に正常になる可能性があります。`G`または完全に`B`。 行全体を反転できるため、実際の文字は重要ではありません。 したがって、候補正方形の場合、すべての行が正方形の列全体にわたって一定であればよいだけです。 異なる行には異なる文字が含まれる場合があります。 

たとえば、次のグリッドは、すべての行が個別に一定であるため、5×5 の適切な正方形を生成できます。```
GGGGG
BBBBB
GGGGG
BBBBB
GGGGG
```他の行は変更せずに、中央の行を反転できます。 

この制約により、両方の次元が 1000 に達することが許可されるため、100 万個のセルが存在する可能性があります。 O(NMmin(N,M)) アルゴリズムはすでに 10 9 演算に近づく可能性があり、Python では遅すぎます。 セル数、理想的には O(NM) の基本的に線形作業が必要です。 

不注意な解決策では見逃される可能性のあるエッジケースがいくつかあります。 次のような 1×1 グリッド```
B
```答えがあります`1`, because the single cell can be flipped. 最初に正常なセルのみをカウントするソリューションでは、誤ってゼロが返されます。 

もう 1 つの微妙なケースは、候補マス内で文字が変化する行です。 のために```
GGGG
GBBG
GGGG
```答えは`1`。 すべての個々のセルはその行を反転することで正常にできますが、中央の行には両方のセルが含まれるため、2×2 の正方形は機能しません。`G`そして`B`可能なすべての幅 2 の配置で。 各行セグメントが均一であるかどうかではなく、正常なセルの数のみをチェックするソリューションでは、答えが過大評価されてしまいます。 

最後に、行は互いに一致する必要はありません。 で```
GGG
BBB
GGG
```答えは`9`。 中央の行は反転され、他の 2 行はそのまま維持されます。 正方形全体に同じ元の文字を要求すると、この正方形が誤って拒否されます。 

## アプローチ

 直接解では、可能なすべての正方形を列挙できます。 すべての左上隅とすべての可能な辺の長さについて、正方形内のすべてのセルを検査し、各行が一定であるかどうかを確認できます。 これは、考えられるすべての候補を明示的にテストするため、正しいです。 

問題は繰り返し作業の量です。 1000×1000 グリッドの場合、考えられるすべての正方形を考慮してそのセルを検査する場合でも、

 k=1 ∑ 1000 k 2 (1001−k) 2

 セル検査、これは約 3.33×10 13 です。プレフィックス情報を使用して各候補正方形を一定時間でチェックしたとしても、依然として Θ(NMmin(N,M)) 個の候補があり、1000×1000 の正方形グリッドに対して約 10 9 個です。 

総当り攻撃が機能するのは、候補四角形がその行のすべてに十分に長い等しい文字の連続が含まれている場合に正確に有効であるためです。 重要なのは、これらの水平方向のランを明示的に表現することです。 

グリッドを左から右に処理します。 各セル (i,j) について、次のようにします。`run[i]`行 i の列 j で終わる連続する等しい文字の数になります。 たとえば、次の行`GGBBBG`ランレングスを生成する`1, 2, 1, 2, 3, 1`。 

現在列 j にいて、ランレングスがすべて少なくとも w であるいくつかの連続する行を考えてみましょう。 次に、それらの行はすべて、列 j で終わる同じ w 個のセルを持ちます。 それらの共通の w 列は、w 幅の長方形を形成します。 このような行が少なくとも w 行あれば、w×w の正方形ができます。 

これにより、すべての列がヒストグラムに変わります。 行 i の値は、その列で終了する水平ランレングスです。 高さ h のヒストグラム バーの場合、すべてのバーの高さが少なくとも h である最大の連続垂直間隔を見つけることができます。 その間隔の高さが v の場合、辺の正方形が得られます。 

分(h,v)。 

単調スタックは、列ごとの線形時間ですべてのバーのこれらの最大間隔を見つけます。 M 列と N 行があるため、完全なアルゴリズムは O(NM) です。

 | 最適 | O(NM) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. グリッドを読み取り、列を左から右に処理します。 各行の現在の水平ランレングスだけが必要なので、2 次元のランレングス配列を保持する必要はありません。 
2. 現在の列のすべての行について、現在の文字がそのすぐ左の文字と等しい場合、そのランレングスを 1 だけ増やします。 それ以外の場合は、ランレングスを 1 にリセットします。 この値は、その行内で現在の列で終わる連続した等しいセルの数を示します。 
3. この列のランレングスをヒストグラムとして扱います。 高さ h の行を考えます。 別の行の高さが少なくとも h である場合、両方の行には現在の列で終わる少なくとも h 個の等しいセルが含まれます。 したがって、高さが少なくとも h である高さ v の連続した間隔内のすべての行は、同じ h 列をサポートします。 
4. 増加する単調スタックを使用して、すべてのヒストグラム位置について、高さがより小さい上下の最初の行を見つけます。 これら 2 つの境界の間では、すべての行の高さが少なくとも現在の高さになります。 結果として得られる間隔は、この水平幅と互換性のある最大の垂直スパンです。 
5. 水平ランレングスを h とし、互換性のある最大垂直スパンを v とします。このヒストグラム バーを中心とする最大の正方形は、辺を持つことができます。`min(h, v)`。 正方形の面積を使用して答えを更新します。 
6. すべての列に対してこれを繰り返します。 遭遇した最大の領域が答えです。 

### なぜ効果があるのか

 不変条件は列 j のものです。`run[i]`は、右境界が j である行 i の定数文字セグメントの最大幅と正確に一致します。 列 j で終わり、辺が k の有効な正方形を考えてみましょう。 その k 行のそれぞれには、最後の k 個のセルが等しい文字として含まれている必要があるため、対応するすべてのヒストグラムの高さは少なくとも k になります。 少なくとも k の高さのバーの単調スタック間隔にはそれらの k 行が含まれており、アルゴリズムは少なくとも k の辺の正方形を構築できます。 逆に、ヒストグラム間隔から生成されたすべての正方形には、すべての行に十分な水平幅と十分な垂直行があるため、その正方形のすべての行は一定であり、独立して反転できます。`G`。 したがって、アルゴリズムによって検出された最大の辺は、まさに可能な最大の正方形の辺となります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    grid = [input().strip() for _ in range(n)]

    # run[i] = length of the equal-character segment in row i
    # ending at the current column.
    run = [0] * n
    answer = 0

    for j in range(m):
        # Build the histogram for this column.
        for i in range(n):
            if j > 0 and grid[i][j] == grid[i][j - 1]:
                run[i] += 1
            else:
                run[i] = 1

        # Find maximal vertical intervals for every histogram bar.
        stack = []

        for i in range(n + 1):
            current = run[i] if i < n else 0

            while stack and run[stack[-1]] >= current:
                p = stack.pop()

                if stack:
                    left = stack[-1] + 1
                else:
                    left = 0

                height = i - left
                side = min(run[p], height)
                if side * side > answer:
                    answer = side * side

            stack.append(i)

    print(answer)

if __name__ == "__main__":
    solve()
```最初のループは、リダクションに必要な水平情報を維持します。 現在の文字が前の文字と異なる場合、実行は次のようになります。`1`これは、幅の広い定数セグメントがこの位置で終了できないためです。 文字が一致すると前回のランが1つ伸びます。 

2 番目のループは、ヒストグラムの標準的な単調スタック処理です。 スタックには、ポップ操作後に厳密に増加するランレングスで行インデックスが格納されます。 より低い高さが表示される場合、ポップされたバーはすべて、右側で最初の小さな要素を見つけたばかりです。 残りのスタックトップは、左側の最初の小さな要素になります。 

変数`height`はその行数です`run[p]`は最小の高さです。 候補正方形の辺は、その水平幅とこの垂直高さの小さい方になります。 寸法を持つ長方形なので、最小値を取得した後でのみ辺を平方します。`run[p] × height`私たちにとって役立つのは、その最大の含まれる正方形を通してのみです。 

追加のセンチネルの位置`i == n`高さはゼロです。 残りのすべてのヒストグラム バーが強制的に処理されるため、個別のクリーンアップ ループが回避されます。 条件`>=`それよりも`>`意図的です。 等しい高さのバーは、そのうちの 1 つが最大間隔全体を表すようにマージされ、より狭い間隔が重複して境界が複雑になるのを防ぎます。 

Python の整数には任意の精度があるため、1000 2 =10 6 までの面積を計算するときにオーバーフローの問題は発生しません。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(NM) | すべてのセルは 1 つの実行値を更新し、一定数の単調スタック操作に参加します。 |
 | スペース | O(NM) | この実装では、入力グリッドに加えて、O(N) 個の実行配列とスタック配列を保存します。 |

 より正確には、補助アルゴリズム空間は O(N) ですが、入力グリッドの保存コストは O(NM) です。 N,M≤1000 の場合、100 万文字は簡単に管理でき、リニアタイム スキャンはセルごとに少量の一定量の作業のみを実行します。 

## テストケース```python
import sys
import io

input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    grid = [input().strip() for _ in range(n)]

    run = [0] * n
    answer = 0

    for j in range(m):
        for i in range(n):
            if j > 0 and grid[i][j] == grid[i][j - 1]:
                run[i] += 1
            else:
                run[i] = 1

        stack = []

        for i in range(n + 1):
            current = run[i] if i < n else 0

            while stack and run[stack[-1]] >= current:
                p = stack.pop()

                left = stack[-1] + 1 if stack else 0
                height = i - left
                side = min(run[p], height)
                answer = max(answer, side * side)

            stack.append(i)

    print(answer)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        solve()
        return sys.stdout.getvalue().strip()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

# Provided sample 1
assert run("""2 2
GG
GG
""") == "4", "sample 1"

# Provided sample 2
assert run("""5 5
GGGGG
GBBBG
GBBBG
GBBBG
GGGGG
""") == "9", "sample 2"

# Minimum-size input, including a bad cell that can be flipped.
assert run("""1 1
B
""") == "1", "minimum size"

# Every row is constant, so every row can independently be flipped if needed.
assert run("""3 3
GGG
BBB
GGG
""") == "9", "independent row flips"

# A change inside the candidate width prevents a 2x2 square.
assert run("""3 4
GGGG
GBBG
GGGG
""") == "1", "horizontal run boundary"

# Maximum-size all-equal grid.
large = "1000 1000\n" + ("G" * 1000 + "\n") * 1000
assert run(large) == "1000000", "maximum size"

print("all tests passed")

 単細胞の場合`1 1 / B`最初の列がヒストグラムを作成するときに処理されます`[1]`。 センチネルはそのバーをすぐに処理し、垂直方向の高さを 1、水平方向の幅を 1 に設定します。 The candidate side is one, so the output is`1`。 MDT は、セルにアクセスする前にセルを反転できます。

GGG
BBB
GGG
