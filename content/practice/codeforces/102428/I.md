 ## 問題の理解

 すべてのメーリング リストを有向グラフの頂点として考えてください。 メーリングリストを配信する場合`i`メーリングリストが含まれています`j`からエッジを描きます`i`に`j`。 クライアントの電子メールは末端の頂点です。 メーリング リストにメッセージを送信するということは、すべての送信選択に従うことを意味するため、多くの異なるパスを介して同じクライアントに到達する可能性があります。 

作成ルールにより、このグラフに重要なプロパティが与えられます。つまり、メーリング リストが DAG を形成します。 リストは既存のリストにのみ挿入でき、リストは一度に 1 つずつ作成されるため、リスト間のエッジをたどると、既存のリストに戻ることなく、作成時に常に前後に移動します。 リストの数値アドレスはその作成時間を表すものではないため、エッジが小さいインデックスから大きいインデックスに移行すると仮定することはできません。 

最初の答えは、`B`、配信ごとに個別にカウントされます。 3 つの異なるパスを通じてクライアントに到達できる場合、そのクライアントは 3 つのパスを提供することになります。`B`。 2番目の答えは、`A`、到達可能な各クライアントを 1 回だけカウントします。 したがって`A`メーリング リストから到達可能な個別のクライアント アドレスの数です。`1`。 

多くてもあります`1000`メーリングリストと`2000`合計アドレス。 リストにはほぼすべてのアドレスを含めることができるため、メンバーシップ エントリの総数は 1 つに近づく可能性があります。`L(N-1)`, これは200万弱です。 これにより、同じサブリストを繰り返し展開したり、可能なパスをすべて列挙したりするアルゴリズムが排除されます。 線形または線形に近いグラフ アルゴリズムは、これらの境界に適しています。

## アプローチ

 直接的なブルート フォース シミュレーションは、実際のシステムとまったく同じように、メーリング リストの階層に従います。 クライアントに遭遇すると配信数が増加し、別のメーリング リストに遭遇するとそのリストが再帰的に処理されます。 これは正しいです。なぜなら、メーリング リストが出現するたびに、元のシステムとまったく同じように、別の独立したトラバースが表されるからです。 

問題は、同じサブグラフが何度も展開される可能性があることです。 メーリング リストを完全な DAG として構成し、リストを含めることを検討してください。`1`後のすべてのリスト、リストを指す`2`以降のすべてのリストを指します。 クライアントの電子メールを 1 つ最終リストに追加します。 中間リストのすべてのサブセットには、リストからの異なるパスが与えられます。`1`最後のメールに。 と`L`リスト、これにより作成されます`2^(L-2)`同じクライアントへの配達。 で`L = 1000`、つまり`2^998`再帰的なリーフ訪問は、実行可能なものをはるかに超えています。 

これを修正する観察結果は、グラフが DAG であるため、すべてのメーリング リストの効果を一度計算して再利用できるということです。 定義する`ways[i]`メーリングリストの作成時に生成されるクライアント配信の数として`i`処理されます。 リスト内の直接のクライアントの場合は、1 つ追加します。 別のメーリングリストの場合`j`、追加します`ways[j]`。 すべての子の計算が完了したら、`ways[i]`最終的に到達するさまざまなパスの数に関係なく、既知である`i`。 

重複のない答えはさらに簡単です。 すべてのリストに対して到達可能なクライアントのセットを構築する必要はありません。 リストから始める`1`、グラフの走査を実行し、アドレスが見つかったらすぐにすべてのアドレスをマークします。 メーリング リストは最初に到達したときのみ処理され、クライアントは最初に到達したときにのみカウントされます。 これは改善された動作を直接モデル化します。 

DP の前に必要な構造の詳細は、メーリング リスト グラフのトポロジカルな順序付けだけです。 カーンのアルゴリズムは、親から子に対して命令を与えます。 この順序を逆にすると、参照されるすべてのリストが`i`計算時にすでに評価されています`ways[i]`。

## アルゴリズムのチュートリアル

 1. すべてのメーリング リストを読み取り、そのメンバーを保存します。 別のメーリング リストであるすべてのメンバーについて、現在のリストからそのメンバーに有向辺を追加し、メンバーの次数を増やします。 完全なメンバーシップ リストを保持しておくと、同じ表現が後で DP と重複のないトラバーサルの両方で使用されるため便利です。 
2. メーリング リスト グラフでカーンのトポロジカル ソートを実行します。 入次数が 0 のすべてのリストから開始し、そのようなリストを 1 つ繰り返し削除し、その子の入次数を減らします。 作成ルールにより、グラフが非周期的であることが保証されるため、最終的にはすべてのメーリング リストが順序付けに表示されます。 
3. トポロジーの順序を逆にします。 もし`i -> j`そのリストを意味します`i`リストが含まれています`j`、 それから`j`前に評価する必要があります`i`。 順序を逆にすると、依存関係の方向が正確に決まります。 
4. メーリングリストを逆の順序で処理し、計算する`ways[i]`。 リスト内のすべての直接クライアントに対して`i`、 追加`1`。 すべてのメーリングリストに対して`j`リスト内`i`、 追加`ways[j]`。 結果を剰余として取得します`10^9 + 7`。 すべての参照リストはすでに処理されているため、再帰的展開は必要ありません。 
5. メーリングリストから始める`1`、すべてのアドレスに対して DFS または BFS を実行します。 1 つを維持する`seen`メーリング リストとクライアント アドレスの両方をカバーする配列。 以前に表示されていないクライアントに到達すると、そのクライアントにマークを付けて増加します`A`。 以前に表示されていないメーリング リストに到達したら、そのメーリング リストにマークを付けて、トラバーサル キューに入れます。 
6. 出力`ways[1]`およびトラバーサルによって到達した個別のクライアントの数。 最初の値は各パスを個別にカウントしますが、2 番目の値は各アドレスを最大 1 回カウントします。 

### なぜ効果があるのか

 最初の答えについては、不変条件はリストを処理した後のものです。`i`、`ways[i]`から始まるクライアント配信パスの数と正確に等しくなります。`i`。 すべての直接クライアントは 1 つのパスを提供し、含まれるすべてのメーリング リストはその子リストから始まるすべてのパスを提供します。 逆のトポロジー順序ではすべての子が最初に処理されるため、再帰によりすべての可能な配信が 1 回だけ計算されます。 

2 番目の答えについては、アドレスが最大 1 回処理されることが不変です。 リストから到達可能なすべてのクライアント`1`最終的にはトラバーサルで遭遇するため、到達可能なすべてのクライアントは 1 つだけを貢献します。`A`。 複数のパスが同じクライアントに到達する場合、その`seen`このエントリは、後のパスで検出された時点ですでに設定されているため、重複はカウントされません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 1_000_000_007

def solve():
    input = sys.stdin.readline

    n, l = map(int, input().split())

    members = [[] for _ in range(l)]
    graph = [[] for _ in range(l)]
    indegree = [0] * l

    for i in range(l):
        data = list(map(int, input().split()))
        k = data[0]
        cur = [x - 1 for x in data[1:k + 1]]
        members[i] = cur

        for x in cur:
            if x < l:
                graph[i].append(x)
                indegree[x] += 1

    # Topological order of the mailing-list DAG.
    queue = []
    head = 0

    for i in range(l):
        if indegree[i] == 0:
            queue.append(i)

    topo = []

    while head < len(queue):
        u = queue[head]
        head += 1
        topo.append(u)

        for v in graph[u]:
            indegree[v] -= 1
            if indegree[v] == 0:
                queue.append(v)

    # Children must be evaluated before parents.
    ways = [0] * l

    for u in reversed(topo):
        total = 0

        for x in members[u]:
            if x < l:
                total += ways[x]
            else:
                total += 1

        ways[u] = total % MOD

    # Count distinct client emails reachable from list 1.
    seen = [False] * n
    seen[0] = True

    queue = [0]
    head = 0
    distinct_clients = 0

    while head < len(queue):
        u = queue[head]
        head += 1

        for x in members[u]:
            if seen[x]:
                continue

            seen[x] = True

            if x < l:
                queue.append(x)
            else:
                distinct_clients += 1

    return f"{ways[0]} {distinct_clients}"

if __name__ == "__main__":
    print(solve())

DP は反復されます`reversed(topo)`。 この方向は間違いやすいです。 If リスト`u`リストが含まれています`v`、グラフには次のものが含まれます`u -> v`、したがって、通常の位相順序は次のようになります。`u`前に`v`。 DP には逆の順序が必要です。`v`前に`u`。 

Python の整数はオーバーフローしませんが、必要な答えはモジュロであるため、モジュロ演算は依然として必要です。`10^9 + 7`。 モジュロは各リストの計算後に 1 回実行されます。中間合計はメンバー数の倍によって制限されるため、これで十分です。`MOD`。

 ### サンプル 1

| リスト | メンバー |`ways`処理後 | 到達可能なクライアント |

 ## 特殊なケース

 最初のエッジ ケースは、異なるブランチを介した重複した到達可能性です。 のために```
4 3
2 2 3
1 4
1 4
```トポロジカル DP が計算します`ways[2] = 1`そして`ways[3] = 1`、 それで`ways[1] = 2`。 到達可能性のトラバーサル中に、リスト`2`クライアントを発見する`4`初め。 いつリスト`3`加工されて、`seen[4]`はすでに true であるため、クライアントは再度カウントされません。 出力は`2 1`。 

2 番目のエッジ ケースは、直接メンバーシップとネストされたメンバーシップによって発生する重複です。 のために```
4 2
2 2 3
1 3
```リスト`2`クライアントに 1 つの配信を生成します`3`。 リスト`1`クライアントも含まれます`3`直接的に、だから`ways[1] = 2`。 横断は到達します`3`リストから直接`1`そしてリストを通じて再びそれに遭遇します`2`ただし、2 番目の出現は無視されます。 出力は`2 1`。 

3 番目のエッジ ケースは、数値アドレスの順序と依存関係の順序の不一致です。```
3 2
1 2
1 3
```グラフには次の内容が含まれます`1 -> 2`、およびリスト`2`クライアントが含まれています`3`。 カーンのアルゴリズムの場所リスト`1`リストの前`2`、その後、逆の順序でリストが評価されます`2`初め。 したがって`ways[2] = 1`、 に続く`ways[1] = 1`。 リストからの走査`1`クライアントにも届きます`3`、与える`1 1`。 数値インデックス DP は、次の値を使用しようとするため失敗します。`ways[2]`計算する前に。 

最後の構造的なエッジ ケースは、同じクライアントへのパスが指数関数的に多くなるグラフです。```
8 4
4 2 3 4 8
3 3 4 8
2 4 8
1 8
```リストには 8 つの異なるパスがあります`1`クライアントへ`8`、 それで`B = 8`。 改善されたトラバーサルによりクライアントが表示される`8`一度与えます`A = 1`。 DP は、これら 8 つのパスを明示的に走査するのではなく、各リストを 1 回計算することによって 8 つのパスすべてを処理します。 これは、アルゴリズムをより大きな最大ケースに合わせて拡張するプロパティです。
