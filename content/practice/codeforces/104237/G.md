 ## 解決策
 ## 問題の理解

 私たちにはコースのコレクションが与えられます。 各コースには、スコアと単位数という 2 つの値が関連付けられています。 正確に K 個のコースを選択する必要があります。 選択が完了すると、選択したコースの合計スコアをそれらの同じコースの合計単位数で割ったものとして最終成績が計算されます。 

目標は、この比率を最大化するサイズ K のサブセットを選択することです。 分母は選択したセットに依存するため、セットの値は単純な方法では加算されないため、これは単純な「最大のスコアを選択する」または「最適な比率を個別に選択する」問題ではありません。 

制約は N = 100000 までなので、サイズ K のすべてのサブセットを試行するアプローチは不可能です。 単一のサブセットをチェックするだけでも O(K) であり、組み合わせを列挙すると組み合わせ論的に爆発してしまいます。 これにより、明示的にサブセットを構築せずに回答候補を評価できるアプローチが推進されます。 

素朴な直感を打ち破るような特殊なケースがいくつかあります。 

K = 1 の場合、答えは単純に v_i / u_i の最大値になります。 アイテム間の相互作用を前提としたアルゴリズムはこのケースを複雑にしすぎますが、それでも自然に解決されるはずです。 

K = N の場合、すべての項目を選択する必要があるため、答えは固定され、結果は sum(v_i) / sum(u_i) になります。 依然として最適化を試みる選択ロジックは冗長であり、正しく実装されていない場合は数値の不安定性が生じる可能性があります。 

貪欲な戦略を使用すると、さらに微妙な問題が発生します。 たとえば、v_i / u_i で並べ替えて上位 K を取ると、項目を結合すると分母の構造が変わるため失敗します。 単位が巨大な比率の高いアイテムは、局所的には最適に見えても、合計を引き下げる可能性があります。 

## アプローチ

 ブルートフォース手法では、ちょうど K 個のコースのすべてのサブセットを試し、結果の比率を計算し、最良のものを追跡します。 これは目的を直接評価するため、定義上正しいです。 ただし、サブセットの数は$\binom{N}{K}$これは、中程度の N の場合でも天文学的に大きくなります。これは、100000 までの N ではまったく実行不可能です。 

より構造化された視点は、問題を書き直すことで得られます。 合計の比率を最大化しようとしています。これは、サブセットを直接構築するのではなく、候補の回答を比較することを示唆しています。 最適な値がある数値 x であると推測するとします。 次のようなサイズ K のサブセットが存在するかどうかを確認できた場合:

 合計(v) / 合計(u) ≥ x

 x の実現可能性を検証できました。 この不等式を整理すると次のようになります。 

合計(v) − x * 合計(u) ≥ 0

 これで、式は要素に対して加算されるようになります。 各コース i に対して、変換された値を定義します。 

スコア_i(x) = v_i − x * u_i

 K 個のコースを選択すると、合計は sum(score_i(x)) になります。 固定 x の場合、サイズ K の可能な最良のサブセットは、単純に最大のスコア i(x) を持つ K 項目です。 これは、合計を最大化する必要があり、貢献度が項目ごとに独立しているためです。 

したがって、問題は次のようになります。候補 x について、K 個の最大変換値の合計が負でないかどうかを確認します。 このチェックは x において単調です。 x が大きすぎると、最良の K 個のアイテムでも 0 に達することができません。 x が十分に小さい場合、それは実現可能になります。 この単調性により、x の二分探索が可能になります。 

これにより、問題は組み合わせ選択から固定式に基づいて変換された値を繰り返し並べ替える問題に変換され、N = 100000 の場合には十分効率的になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O( C(N, K) · K ) | O(K) | 遅すぎる |
 | 最適 (二分探索 + 貪欲チェック) | O(N log N log R) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### 1. ターゲット値をパラメータ x として解釈します。 

最終成績を表す候補解答 x を仮定します。 最適な比率を直接計算する代わりに、x が達成可能かどうかをテストします。 

### 2. 各コースを直線的な貢献に変える

 各コース i について、score_i = v_i − x * u_i を計算します。 これにより、比率制約が合計制約に変換されます。 

### 3. 変換された値を並べ替える

 すべてのscore_iを降順に並べ替えて、最も優れた貢献者が先頭になるようにします。 

これが機能する理由は、固定 x の場合、すべての項目が独立して寄与するため、最適な K 個の寄与を選択すると合計が最大化されるためです。 

### 4. 最良の K 項目を取得し、その合計を計算します

 S = ソートされた変換配列の最初の K 要素の合計を計算します。 これは、正確に K 個の項目を選択するという制約の下での sum(v − x u) の可能な最良の値を表します。 

### 5. x の実現可能性を確認する

 S ≥ 0 の場合、平均が少なくとも x である K 項目の有効な選択が存在します。 そうしないと、x が大きすぎます。 

### 6. 実現可能な最大の x を二分探索します。 

実際の値を検索します。 下限は 0 から開始でき、上限は max(v_i / u_i) または 1e6 などの十分に大きな数値として設定できます。 

精度が必要な 1e-6 に達するまで、反復ごとに推定値が改良されます。 

### なぜ効果があるのか

 核となる不変条件は、x の実現可能性が単調であるということです。 値 x が達成可能であれば、より小さい x * u_i を減算するとすべての変換スコアが増加するため、より小さい値も達成可能です。 これにより、バイナリ検索空間の順序付けが保証され、上位 K 個の変換値の貪欲な選択により、固定 x ごとに最適なサブセットが正しく表現されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def check(n, k, u, v, x):
    arr = [v[i] - x * u[i] for i in range(n)]
    arr.sort(reverse=True)
    s = sum(arr[:k])
    return s >= 0

def solve():
    n, k = map(int, input().split())
    u = []
    v = []
    for _ in range(n):
        ui, vi = map(int, input().split())
        u.append(ui)
        v.append(vi)

    lo, hi = 0.0, 1e6
    for _ in range(60):
        mid = (lo + hi) / 2
        if check(n, k, u, v, mid):
            lo = mid
        else:
            hi = mid

    print(f"{lo:.6f}")

if __name__ == "__main__":
    solve()
```関数チェックは、候補平均 x の変換された値を構築し、有効なサブセットが存在するかどうかを評価します。 固定 x の最適なサブセットは常に K 個の最大の変換された寄与であるため、ソートが必要です。 

二分探索は、1e-6 を超える精度を保証するために、固定回数の反復で実行されます。 比較は正確な大きさではなく符号のみに依存するため、浮動小数点の安定性は十分です。

 ## 特殊なケース

 K が 1 の場合でも、上位 K 個の変換値が単一の最大要素に減り、二分探索が最適な個別比率に収束するため、アルゴリズムは引き続き機能します。 たとえば、あるコースが他のコースを圧倒する場合、その変換された値は正しい x 範囲で最高のままであり、実現可能性はその比率に応じて反転します。 

K が N に等しい場合、すべての要素が取得されるため、ソートされた選択ステップは無関係になります。 実現可能性チェックは sum(v) − x sum(u) ≥ 0 に帰着し、直接 x = sum(v) / sum(u) が得られます。 サブセットの競合が存在しないため、アルゴリズムは引き続き正しく収束します。 

1 つのコースに非常に大きな u と v があるなど、値が極端に偏っている場合、変換 v − x u は x に応じて正しくペナルティを与えるか、または報酬を与えます。 v/u が高い場合でも、u を大きくすると x に対する感度が保証され、検索範囲全体で誤った優位性が回避されます。
