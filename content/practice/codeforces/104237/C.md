 ## 解決策
 ## 問題の理解

 私たちは、道に沿って一定の順序で配置された一連のゴミの山を与えられます。 各山には重みがあり、ボブはスキップしたり並べ替えたりすることなく、左から右に山を拾う必要があります。 彼は繰り返しゴミ箱へ行きます。そのたびに、その移動の総重量が一定の制限を超えない限り、最後に止まった場所から連続して積み上げられたブロックを運ぶことができます。$K$。 

タスクは、順序制約と容量制約を考慮しながら、シーケンス全体を処理するために必要なそのようなトリップの最小数を計算することです。 

重要な制約は、$N \le 10^5$これにより、すべてのパーティションを試行したり、すべてのサブ配列を明示的にチェックしたりするソリューションは即座に除外されます。 二次関数またはそれより悪いアプローチでは、最大で次のようなパフォーマンスが得られます。$10^{10}$最悪の場合の操作は可能ですが、1 秒の制限では実行できません。 これにより、単一のリニア スキャン戦略が推進されます。 

単一の杭の重さが次の値に等しい場合、微妙なエッジケースが発生します。$K$。 その場合、たとえ小さな山が連続して現れたとしても、それは独自のトリップを形成する必要があります。 もう 1 つの特殊なケースは、すべての山が 1 つのトリップに収まる場合で、答えは 1 になるはずです。誤ってリセットしたり、新しいトリップを開始するのが早すぎる単純なアプローチでは、このようなシナリオでは過大なカウントが発生します。 

## アプローチ

 ブルートフォース戦略では、シーケンスを有効なトリップに分割する可能なすべての方法をシミュレートします。 各旅行は連続したセグメントであるため、その合計は最大で$K$場合は、すべてのブレークポイントを試して、セグメントの最小数を再帰的に計算できます。 これにより、当然、配列のすべてのパーティションが試行されることになります。 

ただし、パーティションの数は、$N$-要素配列は指数関数的に増加します。 有効な分割に限定したとしても、すべての要素が小さい最悪のケースでは、ほぼどこでも分割できるため、大まかに$2^{N-1}$可能性。 これは実行可能な計算をはるかに超えています。 

貪欲なパッキングプロセスとして解釈すると、問題の構造は大幅に単純化されます。 ボブはアイテムを順番に処理する必要があり、並べ替えたりスキップしたりすることはできないため、各トリップは単に現在の位置から始まる最大のプレフィックスであり、その合計は次を超えません。$K$。 厳格な順序制約により、新しい旅行を早く開始しても将来の要素をより効率的に組み合わせることができないため、旅行をさらに延長すると常に旅行の数が削減または維持されます。 

これにより、最適な戦略が簡単になります。左から右にスキャンし、重みを蓄積し続け、次のパイルを追加するたびに重みを追加します。$K$、現在の旅行をコミットし、新しい旅行を開始します。

 ## アルゴリズムのチュートリアル

 1. 現在のトリップ負荷を表す累計とトリップ数のカウンタから始めます。 どちらもゼロから始まります。 
2. 杭を左から右に順番に移動します。 
3. 各杭について、その重量を現在のトリップに追加すると超過するかどうかを確認します。$K$。 
4.を超えない場合$K$、実行合計を増やすことで、現在の旅行に山を含めます。 
5.超過した場合$K$、トリップ カウンタをインクリメントして現在のトリップを終了し、実行中の合計を現在のパイルの重みにリセットして、このパイルから新しいトリップを開始します。 
6. すべてのパイルを処理した後、未完了のトリップ (累計がゼロでない) がある場合、それを 1 つの最後のトリップとしてカウントします。 

ステップ 5 の背後にある理由は、一度制約に違反すると、以前の決定を再配置することはできないということです。 順序は固定されているため、唯一の有効な修復は、違反要素の直前でトリップ境界をカットすることです。 

### なぜ効果があるのか

 スキャンのどの時点でも、アルゴリズムは現在の旅行を表す山の連続セグメントを維持し、このセグメントは、その合計が最大であるという制約の下で常に最大になります。$K$。 必要よりも早くトリップを終了した場合、将来の要素をより早く移動したり交換したりすることはできないため、将来の要素をマージする機能が得られずにトリップの数が増加することになります。 したがって、カットするたびに、選択ではなく実現可能性によって強制され、最小限性が確保されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    
    trips = 0
    current = 0
    
    for x in a:
        if current + x <= k:
            current += x
        else:
            trips += 1
            current = x
    
    if current > 0:
        trips += 1
    
    print(trips)

if __name__ == "__main__":
    solve()
```実装は貪欲スキャンに正確に従います。 変数`current`進行中の走行重量を追跡します。 新しい山が適合しない場合は、すぐに前の旅行を終了し、その山だけで新しい旅行を開始します。 

最終チェックでは、部分的に満たされた最後の旅行がカウントされていることを確認します。 これがないと、最後にオーバーフローが発生しない場合、最後のセグメントが欠落してしまいます。

 ## 特殊なケース

 次のような最小限の入力`1 5 / 3`ループは分割をトリガーせず、最後の非ゼロであるため、正しく処理されます。`current`ちょうど 1 回の旅行に貢献します。 

フルキャパシティの単一パイルのような`1 5 / 5`オーバーフロー チェックはトリガーされず、最終的な累積がカウントされるため、すぐに 1 つの完了したトリップが作成されます。 

すべての山が等しいシーケンス$K$、 のような`4 3 / 3 3 3 3`、すべての要素で新しいトリップを強制します。 毎回`current + x`を超える$K$、アルゴリズムがリセットされ、間違って結合された山がないことが保証されます。 

のようなぎっしり詰まったシーケンス`6 5 / 2 3 2 3 2 3`は、グリーディ パッキングが常に切断前に各トリップを可能な限り充填し、実現可能性を向上させる切断を遅らせることがないことを示しています。
