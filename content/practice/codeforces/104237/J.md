 ## 解決策
 ## 問題の理解

 グラフの頂点として配置された一連の納屋が与えられます。 各納屋では、ジョーがそこに到着するたびに一定の利益が得られます。 納屋の間には指示された道路があり、それぞれに関連したコストがかかります。 これらの道路に加えて、ジョーはいつでもどの納屋から他の納屋にもテレポートでき、インデックスの絶対差に比例した距離ベースのコストを支払います。 何らかの方法で納屋に到着すると、ジョーはすぐにその納屋の報酬を受け取ります。 

問題は、単一の最適なパスを見つけることではありません。 代わりに、サイクル全体の合計ゲインが厳密に正になるような、以前に訪れた状態に移動して戻る方法が存在するかどうかが問われます。 このようなサイクルが存在する場合、ジョーはそれを無限に繰り返し、際限のない利益を蓄積することができます。 

制約は、納屋の数が最大 500 であるのに対し、道路の数は最大 5000 であることを示しています。長い一連の動きを明示的にシミュレートしたり、すべてのパスを探索したりする完全に単純なアプローチは不可能です。これは、状態を越える 3 次または 4 次の探索でさえすでに大きすぎるためです。 しかし、$N^2$スケール構造は受け入れられます。これは、各反復が$O(N^2)$またはそれ以上です。 

テレポーテーションからは微妙なエッジケースが発生します。 テレポート エッジはすべての納屋のペアの間に存在するため、すべてのテレポート エッジを明示的に構築する不用意な実装はすでに行われています。$O(N^2)$これは問題ありませんが、すべてのエッジに対して一般的な最短パス アルゴリズムを繰り返し実行すると、最適化せずにベルマン フォード スタイルで単純に実行すると、非常に遅くなります。 

もう 1 つの重要な詳細は、テレポート後も含め、納屋に入るたびに報酬が収集されることです。 これは、ノードの重みがソースではなくエッジの宛先に属することを意味します。 この詳細が欠けていると、不正確な標識モデリングにつながります。 

最後に、目標は、特定のノードへのパスを計算することではなく、正のサイクルを検出することです。 これにより、この問題は標準的な最短経路タスクとは区別されます。 

## アプローチ

 直接モデリングのアプローチは、各納屋をノードとして解釈し、各動きをその動きの正味ゲインに等しい重みを持つ有向エッジとして解釈することです。 ジョーが納屋から引っ越したら$i$納屋へ$j$、彼は移動コストを支払い、すぐに受け取ります$c_j$したがって、エッジの重みは次のようになります。$$w(i \to j) = c_j - \text{cost}(i, j)$$道路については、費用が表示されます。 テレポーテーションの場合、コストは次のとおりです。$K \cdot |i - j|$。 

グラフがこのように定義されると、問題は、合計の重みが正のサイクルが存在するかどうかを検出することになります。 

強引なアイデアは、最長パスの緩和を最大で実行することです。$N$すべてのエッジを使用して反復します。 何らかの値が改善された場合は、$N$- 回目の反復では、正のサイクルが存在します。 これは古典的なベルマン・フォードサイクル検出のアイデアですが、最大化形式です。 

ただし、グラフにはノードの各ペア間にテレポート エッジが含まれています。$O(N^2)$。 ナイーブなベルマン・フォードはコストがかかるだろう$O(N^3)$、 その周り$500^3 = 125$100 万回のリラクゼーションは、オーバーヘッドを考慮すると Python の境界線です。 

重要な観察は、テレポート エッジが非常に構造化されたウェイト形式を持っていることです。$$c_j - K|i - j|$$これにより、二次時間ではなく反復ごとに線形時間ですべてのテレポート緩和を計算できるようになります。 絶対値を 2 つのケースに分けることで、次のように書き換えます。$$c_j - K|i - j| = 
\begin{cases}
(c_j + Ki) - Kj & i \le j \\
(c_j - Ki) + Kj & i \ge j
\end{cases}$$この構造により、最適な候補を維持しながら、左から右、右から左へのスイープが可能になります。 

したがって、各 Bellman-Ford 反復は次のように削減できます。$O(N + M)$、完全なソリューションが実現可能になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ベルマン・フォードをあらゆるエッジで力づくで攻撃 |$O(N^3)$|$O(N^2)$| 遅すぎる |
 | テレポート スイープを備えた最適化された Bellman-Ford |$O(N(N + M))$|$O(N + M)$| 承認済み |

 ## アルゴリズムのチュートリアル

 この問題を最大重量サイクル検出タスクに変換します。 

1. 各状態が納屋に到着したばかりであることを表す納屋上の有向グラフを構築します。 値配列を初期化する`dist[i] = c_i`、納屋で終わる最高の利益を表します$i$動きゼロで。 これは、納屋から始めるとすぐに報酬が得られることを反映しています。 
2. すべての道路遷移を追加します。 からの道の場合$a$に$b$費用がかかる$w$、緩和ルールを定義します。$$dist[b] = \max(dist[b], dist[a] + c_b - w)$$これは、目的地での報酬の獲得と、移動コストの支払いをキャプチャします。 
3. テレポーテーションは完全なグラフ構造であるため、個別に処理します。 目的地ごとに$j$、私たちが望むのは：$$\max_i (dist[i] + c_j - K|i - j|)$$これは 2 つのスイープに分割されます。 

左から右へのスイープでは、次の最良の値を維持します。$dist[i] + Ki$、

 右から左へのスイープでは、次の最良の値を維持します。$dist[i] - Ki$。 
4. リラックスプロセスを実行します。$N$繰り返し。 各反復では、最初に道路緩和を適用し、次に 2 つのスイープ方法を使用してテレポート緩和を適用します。 
5.完了後$N$完全な反復を行った後、追加の反復を 1 回実行します。 いずれかの値が向上すると、正のサイクルが存在し、答えは次のようになります。`YES`。 
6. 追加の反復で改善が見られない場合、出力`NO`。 

### なぜ効果があるのか

 このプロセスは、ベルマン・フォードの最長パスに類似したものです。 後$k$反復、`dist[i]`最大で使用して達成可能な最大の利益を表します$k$動きます。 利益を増加させるサイクルは無期限に使用できる必要があり、最終的にはいくらか増加することになります。`dist[i]`すべての単純なパスが使い果たされた後でも。 その後も改善が見込めない場合は、$N$どのサイクルもノードを再訪問せずに通過できるため、正のサイクルは存在しません。$N$サイズのグラフの倍数$N$。 テレポートの最適化は、明示的な列挙とまったく同じ緩和を計算するため、正確性は変わりません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    N, M, K = map(int, input().split())
    c = [0] + [int(input()) for _ in range(N)]

    edges = []
    for _ in range(M):
        a, b, w = map(int, input().split())
        edges.append((a, b, w))

    dist = c[:]  # starting reward at each node

    def relax_once():
        nonlocal dist
        updated = False

        new = dist[:]

        # road edges
        for a, b, w in edges:
            val = dist[a] + c[b] - w
            if val > new[b]:
                new[b] = val
                updated = True

        # teleport: left to right
        best = -10**30
        for i in range(1, N + 1):
            best = max(best, dist[i] + K * i)
            val = best + c[i] - K * i
            if val > new[i]:
                new[i] = val
                updated = True

        # teleport: right to left
        best = -10**30
        for i in range(N, 0, -1):
            best = max(best, dist[i] - K * i)
            val = best + c[i] + K * i
            if val > new[i]:
                new[i] = val
                updated = True

        dist = new
        return updated

    for _ in range(N):
        relax_once()

    if relax_once():
        print("YES")
    else:
        print("NO")

if __name__ == "__main__":
    solve()
```この実装により、納屋ごとに世界最高の利益が維持されます。 各反復で新しい値が計算されます。`new`配列を使用して、同じラウンド内で更新が混在するのを避けることができます。これは、ベルマン・フォード スタイルの推論を正確にするために不可欠です。 道路緩和は端的なアップデートです。 

テレポート緩和は 2 つのリニア スキャンを使用して計算されます。 順方向スキャンでは、左側のインデックスの最適な候補が維持され、次のように調整されます。$+Ki$、これは次の場合に絶対距離を正確に考慮します。$i \le j$。 逆方向スキャンは、同じ考え方を反対方向にも反映します。 これにより、すべてのペアを明示的に反復することがなくなります。 

最後の追加の緩和ステップはサイクル検出トリガーです。その後も改善できる点があれば、$N$完全な反復では、正のサイクルが存在する必要があります。

 ## 特殊なケース

 重要なエッジケースは、テレポーテーションだけで唯一収益性の高い構造を作成できる場合です。 すべての道路が存在しない場合、テレポート エッジを完全に無視する単純なアプローチでは、サイクルが存在しないと誤って結論付けられてしまいます。 実際には、高報酬の納屋間のテレポート自体が、繰り返しの正のループを形成する可能性があります。 

ベルマン-フォードプロセスの後半で改善が行われる場合、別のエッジケースが発生します。 実装がサイクルをチェックするのが早すぎると、有益になるまでにいくつかの遷移が必要なサイクルを見逃す可能性があります。 最後の追加の反復により、この遅延伝播が正しく検出されることが保証されます。 

3 番目のエッジケースは次のような場合です。$K$十分に大きいため、テレポーテーションは常にマイナスになります。 その場合、すべてのテレポート緩和が道路ベースの構造をオーバーライドしてはならず、スイープ緩和が単に改善されないため、アルゴリズムは依然として正しく動作します。`dist`。
