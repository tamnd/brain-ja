 ## 解決策
 ## 問題の理解

 ブロックの列が与えられ、各ブロックには特定の数のツリーが含まれます。 一連のウォークも指定されており、各ウォークは 1 つのエンドポイントから別のエンドポイントまでのブロックの連続セグメントをカバーします。 クレアは、すべての歩行で、その間隔内のすべてのブロックにあるすべての木を通過します。タスクは、すべての歩行を組み合わせて通過した木の総数を計算することです。 

問題を直接読むと、固定配列の多くの部分配列の値の合計を繰り返し計算する必要があることがわかります。 配列の長さは最大 200 ですが、クエリの数は 10,000 に達する可能性があります。 それぞれの値は小さいですが、多くの範囲にわたる累積が重要です。 

この制約は、各セグメントの合計を最初から再計算することは境界線にあるものの、潜在的には許容できることを直ちに示唆しています。 ただし、最大 200 個の要素をスキャンするたびに 10,000 回のクエリを実行すると、約 200 万回の操作が発生します。これは、Python で 1 秒の制限内で快適に実行できる上限にすでに近づいています。 追加のオーバーヘッドや複数のテスト ケースがあると、これは危険になります。 よりクリーンなソリューションでは、反復的なトラバースを回避する必要があります。 

微妙な点は、各ウォーク エンドポイントを任意の順序で指定できることです。 ブロック 5 からブロック 2 へのウォークは、2 から 5 へのウォークと同じです。A_i が常に B_i 以下であると仮定するソリューションは失敗します。 

もう 1 つのよくある間違いは、包括性を忘れることです。 両方のエンドポイントが含まれるため、1 対 1 のようなセグメントは、ゼロではなく、その単一ブロックの値に寄与します。 

エッジ ケースは、歩行範囲が 1 つのブロックに崩壊する場合、またはすべての木が 1 つの位置に集中している場合に発生します。 たとえば、N = 1、T = [7]、および 1 つのクエリ (1, 1) がある場合、正しい答えは 7 です。半開間隔または不適切なスライスを使用した不用意な実装では、0 が生成されます。 

## アプローチ

 最も直接的なアプローチは、範囲内のすべてのブロックを反復処理し、ツリーを合計することによって、各ウォークを独立して処理することです。 これは簡単です。クエリごとにエンドポイントを正規化し、常に小さいインデックスから大きいインデックスまで反復し、その間隔で値を累積します。 

このアプローチは、変換せずに問題の定義に直接従うため、正しいです。 ただし、そのコストは各クエリ間隔のサイズに比例して増加します。 最悪の場合、各クエリはほぼ配列全体に及ぶため、およそ M × N 回の操作が発生します。これは、最悪のケースでは約 2 × 10^6 回の操作になります。 これはまだかろうじて実現可能ですが、不必要にきつく、繰り返しの作業が必要になります。 

重要な点は、基になる配列が静的であるということです。 すべてのクエリは固定配列の範囲にわたる合計を要求し、そのようなクエリは多数あります。 この構造は、まさにプレフィックス合計が設計されているものです。 累積合計を 1 回事前計算することにより、2 つのプレフィックス値を減算することで、各クエリに一定時間内に応答できます。 範囲合計の繰り返しにかかるコスト全体が、単一の前処理ステップに集約されます。 

データが小さいため総当り方式は機能しますが、効率マージンとスケーラビリティの点で失敗します。 プレフィックス合計変換は、反復的な走査を、以前に計算された部分的な結果の再利用に置き換えます。

 ## アルゴリズムのチュートリアル

 配列を定数時間の範囲クエリを可能にする構造に変換します。

1. ツリーの配列を読み取り、先頭からそのインデックスまでのツリーの合計数を各位置に格納するプレフィックス合計配列を構築します。 これにより、プレフィックス セグメントの合計を再計算することなく即座に取得できるようになります。 
2. クエリごとに、エンドポイント A と B を読み取ります。ウォークの方向は重要ではないため、小さいインデックスが最初に来るように並べ替えます。 これにより、常に有効な増加間隔で作業することが保証されます。 
3. プレフィックス配列を使用して、その間隔内のツリーの合計を計算します。 L から R までの合計は、R のプレフィックス値から L 前のプレフィックス値を引くことによって取得されます。これが機能するのは、プレフィックスの合計がある点までのすべての寄与が累積され、減算によって間隔より前のすべてが削除されるためです。 
4. この問題では、クエリごとの出力ではなく、すべての歩行を組み合わせた合計の合計が求められるため、計算された値を現在の合計に加算します。 
5. すべてのクエリを処理した後、累計を出力します。 

### なぜ効果があるのか

 プレフィックス合計配列は、各位置がその前にあるすべての要素の合計寄与度を格納するという不変式をエンコードします。 範囲の合計は、厳密に区間内にあるものを除き、重複するすべての寄与が相殺されるため、このような 2 つの累積値の差として表すことができます。 各クエリは事前計算された値に対する定数時間の算術演算に削減されるため、再計算や重複のあいまいさは発生せず、すべてのブロックは、それを含むクエリごとに 1 回だけ寄与します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    t = list(map(int, input().split()))
    
    prefix = [0] * (n + 1)
    for i in range(1, n + 1):
        prefix[i] = prefix[i - 1] + t[i - 1]
    
    total = 0
    for _ in range(m):
        a, b = map(int, input().split())
        if a > b:
            a, b = b, a
        total += prefix[b] - prefix[a - 1]
    
    print(total)

if __name__ == "__main__":
    solve()
```このソリューションでは、まずプレフィックス合計配列を構築します。ここで、インデックス i はブロック 1 からブロック i までのツリーの総数を表します。 これは、入力配列に対する単一の線形パスで行われます。 

各クエリは独立して処理されます。 唯一の微妙な実装の詳細は、左の境界が右の境界より大きくならないようにするエンドポイントの正規化です。 引き算`prefix[b] - prefix[a - 1]`ループやスライスを必要とせずに、包含区間の合計を正確に取得します。 

よくある落とし穴は、prefix[0] が空の合計を表すため、プレフィックスのインデックス付けにはオフセットが必要であることを忘れることです。 これが私たちがアクセスする理由です`a - 1`prefix[0] は 0 として定義されているため、a が 1 の場合でも安全です。

 ## 特殊なケース

 単一ブロック入力は、実装がゼロでのプレフィックス インデックス付けを正しく処理するかどうかをテストします。 入力あり`1 1 / 7 / 1 1`、プレフィックス配列は次のようになります`[0, 7]`、クエリは次のように評価されます。`prefix[1] - prefix[0]`、7が得られます。 

次のような逆引きクエリ`3 1`正規化が適用されていることを確認します。 スワップを行わないと、単純なループまたはスライスは範囲を誤って処理するか、空のセグメントを生成します。 スワップ後、間隔が有効になり、プレフィックスの減算により合計が計算されます。 

均一な配列では、繰り返しの蓄積の一貫性が重視されます。 すべてのブロックは同じ値を持つため、すべての範囲の合計はその長さに比例し、プレフィックスの減算によりこれが複数のクエリにわたって正確に保持されます。
