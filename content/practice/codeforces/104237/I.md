 ## 解決策
 ## 問題の理解

 私たちは、農家が最大 K 個の「間違い」を犯しながら、1 から N までの数字の順列を何回作ることができるかを数えるよう求められます。 位置 i に置かれた値が i そのものではない場合、位置 i でエラーが発生します。 言い換えれば、順列を恒等順序と比較すると、固定点ではないすべての位置が 1 つの間違いに寄与します。 

したがって、タスクは純粋に組み合わせになります。N 個の要素のすべての順列のうち、最大でも K 個の位置で単位順列と異なるものを数えます。 同様に、少なくとも N − K 個の位置は固定点のままでなければなりません。 

制約は非常に特殊な点で小さいです。 N は最大でも 100 ですが、K は最大でも 10 です。この不均衡が構造上の重要なヒントです。 N は順列の階乗ベースの列挙には大きすぎますが、許可される「非固定」位置の数はごくわずかです。 したがって、実行可能なソリューションでは、移動する位置の数によってパラメータ化し、その数を真の複雑さの要因として扱う必要があります。 

素朴なアイデアは、N 個の要素のすべての順列を列挙し、固定小数点をカウントすることです。 N = 20 の場合でも、順列の数はすでに天文学的に大きいため、これはすぐに失敗します。 もう 1 つのよくある間違いは、移動する K 個の位置を選択し、それらを任意に配置できると想定することです。 一部の配置では、選択したサブセット内に意図しない固定点が導入されるため、これは非常に重要です。 

K = 0 の場合、微妙なエッジ ケースが発生します。この場合、単一の不一致でもすでに制限を超えているため、恒等順列のみが有効です。 もう 1 つの特殊なケースは、K が N に比べて大きい場合です。その場合、「最大 K 個の間違い」という条件は空になり、答えは N! に崩れるはずです。これは、派生した数式の健全性チェックとして役立ちます。 

## アプローチ

 ブルートフォース手法では、1 から N までのすべての順列を構築し、それらのインデックスと異なる位置の数をチェックします。 これは定義上正しいですが、そのコストは N 階乗に応じて増加します。 N = 100 の場合、これは完全に不可能であり、Python では N = 12 でさえ境界線になります。 

制約の構造は、別の観点を示唆しています。 完全な順列について考えるのではなく、間違った位置の数によってそれらを分類します。 正確に m 個の位置が間違いであると仮定します。 まず、どの m 個の位置が間違っているかを選択できます。 これらの位置が固定されると、残りの位置はすべて正しい固定点になる必要があります。 

ここで、問題は、選択された m 個の位置のいずれも元の位置に留まらないような置換をカウントすることに帰着します。 まさにmサイズの狂いです。 

これにより、クリーンな分解が作成されます。C(N, m) 通りに m 個の不良位置のセットを選択し、固定点を使用せずにそれらを D[m] 通りに並べ替えます。 これを 0 から K までのすべての m について合計します。 

唯一欠けている要素は、混乱を効率的に計算することです。 m は最大 10 であるため、標準漸化式 D[m] = (m − 1) × (D[m − 1] + D[m − 2]) を使用して D[m] を事前計算できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | お(ん!) | O(N) | 遅すぎる |
 | 組み合わせ論 + 錯乱 | O(NK + K) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

1. N までの階乗とモジュロ 1009 での組み合わせのモジュラー逆数を事前計算します。これにより、すべての m ≤ K について二項係数 C(N, m) を高速に計算できます。 
2. 漸化式 D[m] = (m − 1) × (D[m − 1] + D[m − 2]) を使用して、狂い D[0..K] を事前計算します。 再発は、混乱の要素 1 がどこに送信されるか、スワップを形成するか、より長いサイクルの一部になるかを検討することから生まれます。 
3. 答えをゼロとして初期化します。 
4. 0 から K までの各 m について、m を順列が同一性と異なる位置の数として解釈します。 
5. 各 m について、C(N, m) を使用して、どの位置が間違っているかを選択する方法の数を計算します。 
6. これに D[m] を掛けます。これは、追加の固定点を導入せずに、選択した位置を並べ替える有効な方法をカウントします。 
7. 結果を答えのモジュロ 1009 に追加します。 
8. 最終的な累積合計を出力します。 

### なぜ効果があるのか

 すべての有効な順列は、その固定点のセットによって一意に分類できます。 順列に正確に N − m 個の固定点がある場合、残りの m 個の位置はすべて移動する必要があり、その制限により混乱が形成されます。 この分類は、異なる m 値間で互いに素であるため、順列が 2 回カウントされることはありません。 逆に、m 個の位置のすべての選択とそれらのすべての乱れは、正確に m 個の間違いを含む有効な順列を生成するため、マッピングは完了します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 1009

def solve():
    K, N = map(int, input().split())

    maxn = N

    fact = [1] * (maxn + 1)
    for i in range(1, maxn + 1):
        fact[i] = fact[i - 1] * i % MOD

    invfact = [1] * (maxn + 1)
    invfact[maxn] = pow(fact[maxn], MOD - 2, MOD)
    for i in range(maxn, 0, -1):
        invfact[i - 1] = invfact[i] * i % MOD

    def nCk(n, k):
        if k < 0 or k > n:
            return 0
        return fact[n] * invfact[k] % MOD * invfact[n - k] % MOD

    D = [0] * (K + 1)
    D[0] = 1
    if K >= 1:
        D[1] = 0
    for i in range(2, K + 1):
        D[i] = (i - 1) * (D[i - 1] + D[i - 2]) % MOD

    ans = 0
    for m in range(0, K + 1):
        ans = (ans + nCk(N, m) * D[m]) % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```実装は、クエリごとに一定時間での二項係数計算をサポートする階乗および逆階乗を構築することから始まります。 より大きな値は合計に無関係であるため、乱れた配列は K までのみ計算されます。 メインループは、考えられる間違いの数ごとに寄与を集計します。 

よくある実装上の落とし穴は、「m 個の選択された位置」と「m 個の任意の置換」を混同することです。これにより、m が誤って使用されてしまいます。 錯乱の代わりに。 もう 1 つは、選択されたセットの外側にある固定点がセット内に厳しい制限を強制することを忘れていることです。これはまさに、内部のカウントを制限のない順列ではなく混乱に変えるものです。

 ## 特殊なケース

 K = 0 の場合、ループは m = 0 のみを考慮します。二項係数 C(N, 0) は 1、D[0] は 1 であるため、結果は正確に 1 となり、恒等順列に対応します。 誤って m = 1 を含む実装では、乱れの処理方法に応じて、誤ってゼロまたはゼロ以外の寄与が追加されるため、ループを慎重に制限することが不可欠です。 

K ≥ N の場合、あらゆる可能な数の不一致が許可されます。 合計は、乱数によって重み付けされたすべてのサブセットに拡張され、順列の完全なセットが再構築されます。 たとえば、N = 3、K = 3 の場合、計算では 6 が得られ、3! と一致します。 このケースでは、分解によって順列が失われたり、異なる m 値にわたって順列が二重にカウントされたりしないことが検証されます。
