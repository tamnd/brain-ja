 ## 解決策
 ## 問題の理解

 合計がちょうどゼロになる実数の配列が与えられます。 各数値には固定の小数精度があるため、すべての値は既知の小数部を持つ有理数と考えることができます。 

タスクは各実数を整数に変換することですが、制限があります。各値は個別に切り捨てまたは切り上げのみ可能です。 すべてのインデックスについて、選択した整数は元の数値の下限または上限のいずれかである必要があります。 各要素に対してこれら 2 つのオプションのいずれかを選択した後でも、結果として得られる整数の合計は正確に 0 でなければなりません。 

これにより、独立した丸め決定間の結合が作成されます。 すべてを切り捨てると合計が小さくなりすぎます。 すべてを四捨五入すると合計が大きくなりすぎます。 ソリューションでは、グローバル合計制約が満たされるように、これらのローカル丸め選択のバランスを取る必要があります。 

この制約により、最大 100,000 個の番号が許可されます。 各要素には 2 つのオプションがあり、検索空間は指数関数的であるため、これにより、丸めの選択肢のすべての組み合わせを探索するアプローチは即座に除外されます。 有効な解はすべて線形または線形に近いものでなければなりません。 

多くの数値が整数である場合、微妙なエッジケースが発生します。 これらの値の場合、床と天井は同一であるため、バランス プロセスの柔軟性には寄与しません。 別のエッジ ケースは、小数部が極端に小さいか 1 に極端に近い場合に発生します。これは、慎重に処理しないと浮動小数点の解釈が異なる丸め動作を示唆する可能性があるためです。 

## アプローチ

 ブルートフォース戦略では、各要素に下限または上限のいずれかを割り当て、結果の合計がゼロに等しいかどうかをチェックします。 要素ごとに 2 つの選択肢があるため、これは次のようになります。$2^n$可能性。 たとえ$n = 30$、これはすでに実行不可能になり、$n = 10^5$それはまったく不可能です。 

重要な構造は、各数値がその下限値と範囲内の小数部分だけ異なることです。$[0, 1)$。 定義すると$x_i = \lfloor a_i \rfloor$、その後、代わりに上限を選択すると、数値がまだ整数でない場合は常に、値がちょうど 1 ずつ増加します。 これにより、問題は、すべてをフロアリングすることによって生じた不足分が総和補正によって補償されるように、「1 を追加」するインデックスのサブセットを選択することに変換されます。 

すべてのフロアを合計すると、ベースライン値が得られます。 元の合計はゼロであるため、ゼロとこのベースラインの差は整数値となり、切り上げる要素を選択して正確に修正する必要があります。 各切り上げは合計に正確に +1 を与えるため、タスクは小数部を含めて必要な数のインデックスを正確に選択することになります。 

必要な上向きラウンド数は完全に決まっており、小数部分のあるものを貪欲に選択できます。

 | ブルートフォース |$O(2^n)$|$O(n)$| 遅すぎる |
 | 最適 |$O(n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 各数値を下限値に変換し、どの数値が非整数であるかを追跡します。 

1. すべての数値の下限を計算し、それをすべての位置の基本整数の選択肢として保存します。 これにより、切り捨てによって目標合計を超えることのない有効な開始点が得られます。 
2. これらの下限値の合計を計算します。 床材が値を増加させることはないため、この合計は 0 以下になります。 
3. ゼロとこの合計の差は、切り上げが必要な要素の数です。 上向きに四捨五入するたびに合計がちょうど 1 増えるため、この差により、必要な調整の数が直接わかります。 
4. 数値がまだ整数ではないすべてのインデックスを特定します。 これらは切り上げが可能な唯一のポジションです。 
5. これらのインデックスの必要な数を正確に選択し、その値を床から天井まで増加させます。 それぞれが合計調整に同様に寄与するため、どの選択も機能します。 
6. 最終値を出力します。 

### なぜ効果があるのか

 このアルゴリズムは保存された量に依存しています。つまり、+1 増分のみを使用して、合計を下限の合計からゼロに調整する必要があります。 各非整数要素は、可能な +1 調整を 1 つだけ提供し、整数要素はまったく提供しないため、実現可能性は、必要な調整数と利用可能な小数位置の一致にのみ依存します。 元の合計は正確にゼロであるため、必要な調整は整数であり、使用可能な小数要素の数内であることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = []
floors = []
fractional = []

sum_floor = 0

for i in range(n):
    x = float(input())
    f = int(x // 1)
    a.append(x)
    floors.append(f)
    sum_floor += f
    
    if abs(x - f) > 1e-12:
        fractional.append(i)

need = -sum_floor  # how many we must round up

b = floors[:]

for i in fractional[:need]:
    b[i] += 1

print("\n".join(map(str, b)))
```コードは、すべての値を読み取り、切り捨てを使用してその整数の下限を計算することから始まります。`// 1`。 これは、Python では正の数と負の数の両方に対して正しく機能します。`//`フロア分割セマンティクスを実行します。 

すべてのフロアの合計を合計します。 最終的な答えの合計はゼロになる必要があるため、必要な上方調整の数は次のようになります。`-sum_floor`。 

上方四捨五入の対象となるインデックスを収集します。つまり、インデックスはまだ整数ではありません。 +1 の調整に貢献できるのはこれらのポジションだけです。 

最後に、正確に取得します`need`このようなインデックスを作成し、その下限値をインクリメントします。 各増分は合計の 1 単位に寄与するため、これにより最終的な合計がゼロになることが保証されます。 

微妙な点は、浮動小数点表現にもかかわらず、小数値を正しく検出できるようにすることです。 許容差チェックにより、次のような値の誤分類が回避されます。`3.00000000001`精密ノイズのため。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import math

    n = int(input())
    a = []
    floors = []
    frac = []
    s = 0

    for i in range(n):
        x = float(input())
        f = math.floor(x)
        floors.append(f)
        s += f
        if abs(x - f) > 1e-12:
            frac.append(i)

    need = -s
    b = floors[:]
    for i in frac[:need]:
        b[i] += 1

    return "\n".join(map(str, b))

# provided sample

-3.70387
""").split() == run("""4

-3.70387
""").split()

""").split() == ["1","-1","0"]

 ## 特殊なケース

 すべての数値がすでに整数である場合、分数リストは空になり、`need`ゼロになります。 アルゴリズムはすべての値を変更しないままにし、必要な合計を自動的に保持します。 

すべての数値が負の端数であり、丸め効果後にのみ合計が 0 になる場合、下限合計は負になり、利用可能な小数点の位置によって正確に補正されます。 選択メカニズムにより、存在しない調整能力を決して使用しようとしないことが保証されます。 

値が整数に非常に近い場合、浮動小数点許容値により、分数と整数のカテゴリに正しく分類されます。 アルゴリズムの正しさは、正確なバイナリ表現ではなく、一貫した識別に依存します。
