 ## 問題の理解

 長いバイナリ文字列が与えられました`a`およびそれより短い、または同じ長さのバイナリ文字列`b`。 スライドします`b`あらゆる可能な窓にわたって`a`同じ長さの 2 つの文字列を位置ごとに 1 文字ずつ比較します。 

各位置合わせについて、ウィンドウ間で異なる位置の数を数えます。`a`そして`b`。 タスクは、偶数の不一致を生成するアライメントの数を数えることです。 

これについて直接的に考える方法は、次の間のハミング距離を測定しているということです。`b`そしてそれぞれの部分文字列`a`、そしてそれらの距離のうちのいくつが均等であるかを数えたいと思います。 

長さ`a`は 1e6 までであるため、二次比較は不可能です。 各ウィンドウを単純に比較するソリューションでは、最悪の場合、約 1e6 × 1e6 の操作が実行されますが、これは 1 秒の許容範囲をはるかに超えています。 

主なエッジケースは次のような場合に現れます。`b`長さが 1 の場合、または両方の文字列が大きく、繰り返しが多い場合。 このような場合、単純なスライディング ウィンドウの比較は依然として単純に見えますが、静かに制限を超えています。 

## アプローチ

 ブルートフォースメソッドは、次のすべての部分文字列をチェックします。`a`長さの`|b|`、それぞれについて、不一致をカウントします。`b`。 これは問題の定義を直接実装しているため、これは正しいです。 ただし、それぞれのおおよその`n`位置、パフォーマンス`m`比較すると、合計が得られます`O(nm)`操作。 両方とも`n`そして`m`10^6 に近い場合、これは実行不可能です。 

これを改善するために、実際に重要なこと、つまり正確な数ではなく、不一致数の同等性に焦点を当てます。 これは、モジュロ 2 を使用して、不一致パリティをより単純な形式で表現しようとすることを示唆しています。 

文字をビットとしてエンコードしましょう。 位置の不一致`i`いつ起こるか`a[i] != b[j]`。 2 進算術では、不等号は XOR が 1 であることに対応します。したがって、ウィンドウの不一致数は次から始まります。`i`以上の合計になります`j`の：`a[i+j] XOR b[j]`この合計のモジュロ 2 のみを考慮します。GF(2) に関して、XOR は線形に動作します。 

sum (a XOR b) mod 2 = sum(a) XOR sum(b)

 これが重要な単純化です。 不一致の等価性は次のとおりです。 

(a のウィンドウの合計) XOR (b の合計)

したがって、問題はスライディング ウィンドウのパリティ カウントに帰着します。

 ## アルゴリズムのチュートリアル

 1. の 1 の数を計算します。`b`この値は、次のことを表します。`b`偶数または奇数のパリティを持ちます。 単純化後の不一致パリティに影響を与えるのはパリティのみであるため、これは重要です。 
2. プレフィックス合計配列を構築します。`a`、各エントリには、そのインデックスまでの 1 の数が格納されます。 これにより、任意の部分文字列に対する定数時間クエリが可能になります。 
3. すべての部分文字列を反復処理します。`a`長さのある`|b|`。 開始インデックスごとに`i`、内の 1 の数を計算します。`a[i : i+|b|]`プレフィックス配列を使用します。 
4. このウィンドウ合計を法 2 で減算し、現在の部分文字列内の 1 のパリティを取得します。 
5. このパリティを次のパリティと比較します。`b`。 それらが等しい場合、そのウィンドウの不一致数は偶数であるため、答えを増加させます。 

### なぜ効果があるのか

 バイナリ値の場合、位置の不一致は XOR と同等です。 不一致の合計数は、XOR 値の合計です。 2 を法として換算すると、XOR 合計が加算に分散され、式が 1 の合計数の XOR に折りたたまれます。 これにより不変条件が作成されます。つまり、すべてのウィンドウで、不一致のパリティはウィンドウ内の不一致のパリティのみに依存します。`a`そしてで`b`、その詳細な構造についてではありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    a = input().strip()
    b = input().strip()

    n, m = len(a), len(b)

    pb = sum(1 for ch in b) % 2

    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + (a[i] == '1')

    ans = 0
    for i in range(n - m + 1):
        ones = pref[i + m] - pref[i]
        if ones % 2 == pb:
            ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```解決策は、次の値のパリティを計算することから始まります。`b`。 これが唯一のプロパティです`b`それはパリティに換算した後の最終的な答えに影響します。 

次に、プレフィックス合計配列が構築されます。`a`、各部分文字列の合計を一定時間で計算できるようになります。 これにより、ウィンドウごとの再計算が回避されます。 

最後に、各ウィンドウは、そのウィンドウ内のパリティとそのパリティを比較することによってチェックされます。`b`。 等価条件は偶数不一致数に直接対応します。 

微妙な点は、不一致を明示的に計算しないことです。 変換全体は、不一致パリティ式をカウントのパリティ比較に変換することに依存します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    a = input().strip()
    b = input().strip()

    n, m = len(a), len(b)
    pb = sum(ch == '1' for ch in b) % 2

    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + (a[i] == '1')

    ans = 0
    for i in range(n - m + 1):
        if (pref[i + m] - pref[i]) % 2 == pb:
            ans += 1

    return str(ans)

 ## 特殊なケース

 いつ`b`長さは 1 で、各ウィンドウは 1 文字です。 アルゴリズムは、次のことを比較することに帰着します。`a[i]`のパリティと一致します`b`。 各ウィンドウの合計が 0 または 1 であるため、プレフィックスの合計は引き続き正しく機能し、パリティ比較は正確になります。 

いつ`a`は完全に 0 で構成され、すべてのウィンドウには 0 の値が含まれるため、すべてのウィンドウ パリティは 0 になります。 もし`b`偶数パリティもあり、すべてのウィンドウが一致し、答えは次のようになります。`|a| - |b| + 1`。 このアルゴリズムは、プレフィックスの違いから直接これを計算します。 

いつ`a`そして`b`同一の繰り返しパターンであるため、すべてのウィンドウは同一のパリティ構造を持ちます。 このアルゴリズムは構造の類似性に依存せず、カウントのみに依存するため、繰り返しても正しいままです。
