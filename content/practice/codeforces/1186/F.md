 ## 解決策
 ## 問題の理解

 無向の単純なグラフが与えられます。 すべての頂点には初期次数があり、エッジを削除することができます。 削除後も、各頂点は元の入射エッジの少なくとも半分を切り上げて保持する必要があります。 同時に、残りのエッジの総数がグローバル境界 (頂点とエッジの合計の約半分) を超えてはなりません。 

タスクは、グローバル エッジ制限も尊重しながら、すべての頂点制約を同時に満たすエッジのサブセットを選択することです。 

制約が十分に大きいため、削除を繰り返しシミュレートしたり、二次的な方法で次数を再計算したりするアプローチは失敗します。 頂点とエッジの数は両方とも 100 万に達する可能性があるため、隣接処理や次数の追跡による定数係数のオーバーヘッドはおそらく小さいですが、ソリューションは本質的にエッジの数が線形である必要があります。 

微妙な困難は、ローカル制約とグローバル制約の間の相互作用から生じます。 局所的には、各頂点はエッジの少なくとも半分が存続することを要求します。 世界的には、保持できるエッジの数には制限があります。 任意のエッジを貪欲に削除する単純な戦略は、特に密なグラフや不規則なグラフにおいて、一部の頂点で 0.5 度の要件を破る危険性があります。 

単純な削除による具体的な失敗例は、星型グラフです。 最初に中心からエッジを恣意的に削除すると、たとえ注意深い順序付けによって有効な解決策が存在したとしても、葉の制約を満たす前にその次数が半分以下に減ってしまう可能性があります。 もう 1 つの失敗例は、削除を調整しない場合にエッジを均一に削除すると、誤って頂点を早期に分離してしまう可能性があるサイクルです。 

主な課題は、頂点が許容最小値を下回らないようにエッジを削除する構造化された方法を見つけることです。 

## アプローチ

 強引なアイデアは、エッジを繰り返し選択し、その後も両方のエンドポイントが 0.5 度の制約を満たしている場合に削除を試みることです。 これには、次数を動的に再計算または追跡し、すべての候補削除の実現可能性をチェックする必要があります。 最悪の場合、すべてのエッジを何度もスキャンすることになり、およそ O(m^2) の動作が発生しますが、これは m が 10^6 までの場合は不可能です。 

重要な観察は、各頂点が最終次数の下限のみを強制することです。 局所的に何かを最大化または最小化する必要はなく、頂点が過度に多くのエッジを失わないようにするだけです。 これは、制御された方法で頂点から安全に「責任を取り除く」という観点から考える必要があることを示唆しています。 

有用な再定式化は、削除を「許可する」エンドポイントにエッジを向けることを考えることです。 各頂点がその入射エッジの最大半分を担当することが保証できれば、すべての頂点は残りの半分を安全に破棄できます。 これは、各頂点が出力される選択肢の最大半分に寄与するように、DFS のようなトラバーサルでエッジの方向を設定するというアイデアにつながります。 

DFS 構造を使用してグラフを処理し、頂点ごとに、損失が許容される入射エッジの数を維持します。 最初は、各頂点は最大で Floor(d_i / 2) エッジを失う可能性があります。 トラバース中に未使用のエッジに遭遇した場合、残りの許容値に基づいて、それを最終的な答えに保持するか、取り外し可能なエッジとして事実上「消費」するかを決定します。 DFS により、エッジに 1 回だけアクセスすることが保証され、許容量によりローカル制約を決して超えないことが保証されます。 

これにより、問題は単一の線形トラバースに変換され、頂点ごとのバジェットを維持しながら、各エッジが 1 回考慮され、保持または破棄のいずれかが割り当てられます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(m^2) | O(m) | 遅すぎる |
 | 予算追跡機能を備えた DFS | O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

1. グラフの隣接リストを作成します。 各エッジは識別子とともに保存されるため、エッジが 1 回だけ処理されることが保証されます。 これが必要なのは、トラバース方向ごとではなく、エッジごとにグローバルな決定が必要なためです。 
2. 各頂点の初期次数を計算します。 これから、各頂点が破棄できるエッジの数 (floor(d_i / 2)) を計算します。 この値は、その頂点の削除の予算として機能します。 
3. DFS 内で各エッジが最大 1 回処理されるように、エッジの訪問済みマーカーを初期化します。 
4. すべての未訪問の頂点から DFS を実行します。 これにより、グラフが接続されていることが保証されないため、切断されたコンポーネントを確実にカバーできます。 
5. DFS が頂点 u にある場合、すべての入射エッジ (u、v) に対して反復処理を行います。 エッジがすでに処理されている場合はスキップします。 
6. 未処理のエッジ (u、v) については、処理済みとしてマークします。 次に、それを最終回答に残すかどうかを決定します。 両方のエンドポイントにまだプラスの削除バジェットがある場合は、エッジを破棄して両方のバジェットを減らすことを好みます。 そうでない場合は、それを保持しなければなりません。 

頂点が削除予算を使い果たすと、残りのすべてのインシデント エッジは 0.5 度の制約を満たすために保持される必要があるため、この決定は安全です。 
7. エッジを保持することにした場合は、それを出力リストに追加します。 次に、隣接 v への DFS を続行します。 

すべての頂点を処理した後、収集されたエッジによって有効なサブグラフが形成されます。 

### なぜ効果があるのか

 中心となる不変条件は、常に頂点が Floor(d_i / 2) 以上のエッジを破棄しないことです。 各頂点は正確にそのバジェットで開始され、破棄されたエッジは両方のエンドポイントでバジェットを消費するため、構築によって頂点が制約に違反することはありません。 

終了時には、最大で半分の入射エッジが削除されているため、各頂点には少なくとも ceil(d_i / 2) 個の入射エッジが残ります。 DFS の順序付けでは、すべてのエッジが 1 回だけ考慮されることが保証されるため、保持されるエッジの総数は、予算に基づく削除によって消費されないエッジと正確に一致し、グローバル境界を満たすことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

n, m = map(int, input().split())
adj = [[] for _ in range(n + 1)]
edges = []

for i in range(m):
    u, v = map(int, input().split())
    adj[u].append((v, i))
    adj[v].append((u, i))
    edges.append((u, v))

deg = [0] * (n + 1)
for u, v in edges:
    deg[u] += 1
    deg[v] += 1

rem = [d // 2 for d in deg]
used = [False] * m
vis = [False] * (n + 1)

res = []

def dfs(u):
    vis[u] = True
    for v, idx in adj[u]:
        if used[idx]:
            continue
        used[idx] = True

        if rem[u] > 0 and rem[v] > 0:
            rem[u] -= 1
            rem[v] -= 1
        else:
            res.append(edges[idx])

        if not vis[v]:
            dfs(v)

for i in range(1, n + 1):
    if not vis[i]:
        dfs(i)

print(len(res))
for u, v in res:
    print(u, v)
```隣接リストにはエンドポイントとエッジ インデックスの両方が格納されるため、各エッジは 1 回だけ処理されます。 の`used`配列により、反対方向からのエッジの再訪問が防止されます。 の`rem`array は、頂点ごとの削除のバジェットであり、0.5 度の要件から直接導出されます。 

DFS は、エッジを失わずに接続性を探索できるようにすると同時に、エッジ保持を決定するための自然な順序を与えます。 重要な点は、後でではなく最初の遭遇時に削除を決定することです。これにより二重カウントが回避され、予算の一貫性が保たれます。 

よくある実装上の間違いは、決定を行う前にエッジを使用済みとしてマークするのを忘れることです。これにより、両方のエンドポイントから同じエッジが 2 回処理され、バジェットが破損する可能性があります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + m) | 各エッジは DFS トラバーサル中に 1 回処理されます。 
| スペース | O(n + m) | 隣接リストとブックキーピング配列 |

 線形複雑度は、n と m の両方が最大 10^6 である制約に一致します。 このアルゴリズムは、制限時間内に通過するために必要な、エッジごとの定時間作業のみを実行します。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, m = map(int, input().split())
    adj = [[] for _ in range(n + 1)]
    edges = []

    for i in range(m):
        u, v = map(int, input().split())
        adj[u].append((v, i))
        adj[v].append((u, i))
        edges.append((u, v))

    deg = [0] * (n + 1)
    for u, v in edges:
        deg[u] += 1
        deg[v] += 1

    rem = [d // 2 for d in deg]
    used = [False] * m
    vis = [False] * (n + 1)

    res = []

    def dfs(u):
        vis[u] = True
        for v, idx in adj[u]:
            if used[idx]:
                continue
            used[idx] = True
            if rem[u] > 0 and rem[v] > 0:
                rem[u] -= 1
                rem[v] -= 1
            else:
                res.append(edges[idx])
            if not vis[v]:
                dfs(v)

    for i in range(1, n + 1):
        if not vis[i]:
            dfs(i)

    return str(len(res)) + "\n" + "\n".join(f"{a} {b}" for a, b in res)

 ## 特殊なケース

 星型グラフは、アルゴリズムがセンターの予算を正しく尊重しているかどうかを明らかにします。 中心が 1、葉が 2 ～ 5 の星では、中心の次数は 4、バジェット 2 になります。このアルゴリズムでは、中心に付随する最大 2 つの削除が許可され、少なくとも 2 つのエッジが残ることが保証されます。 DFS がエッジを処理するとき、センターの予算が使い果たされると、残りのすべてのエッジが結果に強制的に取り込まれ、偶発的な過剰削除を防ぎます。 

パス グラフは、DFS を介した伝播が正確さを維持しているかどうかをチェックします。 エンドポイントには次数 1 とゼロ バジェットがあるため、インシデント エッジは常に維持され、許可された制限を超えて接続が切断されることはありません。 

サイクルはバランスをテストします。すべての頂点は等しい次数とバジェット 1 を持ちます。アルゴリズムは、制御された方法で頂点ごとに 1 つのエッジを正確に削除し、すべての制約を満たすスパニング構造を残します。
