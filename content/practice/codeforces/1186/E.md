 ## 解決策
 ## 問題の理解

 この問題で説明されている構造は、小さな開始グリッドから生成される無限のバイナリ行列を定義します。 各反復で、現在のグリッドは 4 つのコピーを 2×2 ブロック パターンに配置することにより、より大きなグリッドに拡張されます。コピーの一部は反転されます (0 が 1、1 が 0 になります)。 無限に繰り返した後、強い自己相似性を持つ決定論的な無限バイナリ フィールドが生成されます。 

課題は、この成長をシミュレートすることではありません。 代わりに、この無限の行列の軸に沿った大きな四角形内の値の合計を求める、最大 100,000 のクエリに答えるように求められます。 座標は最大 10^9 であるため、どのソリューションでも明示的な構築ではなく構造を使用して値を計算する必要があります。 

重要な制約は、小さな初期グリッド (n, m ≤ 1000) と非常に大きなクエリ座標の組み合わせです。 これにより、無限行列を拡張したり部分的に構築したりするアプローチは即座に除外されます。 繰り返しごとにグリッドが両方の次元で 2 倍になるため、単一の拡張レベルを保存することさえ不可能です。 

2 番目の問題は、変換が単純なタイリングではないことです。 反転の存在は、パリティ効果が再帰レベル全体に伝播することを意味するため、「パターンは n または m ごとに繰り返される」などの単純な周期性の仮定は正しくありません。 

故障モードを確認する便利な方法は、1×1 グリッドを考慮することです。 セルが 1 の場合、最初の展開により交互に反転する 2×2 パターンが作成されます。 次の展開は再び 2 倍になりますが、反転は再帰の深さに依存するため、パターンは 2×2 または 4×4 ブロックで単純に周期的ではありません。 固定期間を想定したソリューションでは、再帰的な境界をまたぐ大きな四角形のカウントを誤ります。 

## アプローチ

 直接的な総当たり解釈では、無限行列を明示的に構築するか、クエリされた四角形をカバーするまで拡張をシミュレートしようとします。 拡張するたびに両方の次元が 2 倍になるため、k ステップ後のグリッドは (n・2^k) × (m・2^k) になります。 最大 10^9 の座標に到達するには、k は約 30 になります。そのレベルであっても、グリッド サイズは天文学的に大きく、保存や走査は不可能です。 

完全な構築を避け、再帰によって祖先をシミュレートすることで各セルを独立して計算しようとしても、クエリ セルごとに計算するのは依然として遅すぎます。 1 つのクエリには最大 10^18 個のセルが含まれる可能性があるため、直接列挙することは不可能です。 

重要な観察は、各拡張が再帰的な構築であり、大きな領域内の各セルを元のグリッド内の 1 つのセルに正確に遡ることができ、偶数回反転されたか奇数回反転されたかを示すパリティ ビットを使用できることです。 これは、座標上の分割統治構造を示唆しています。 

グリッドが時間的に前方に構築されると考えるのではなく、各座標が象限の選択のシーケンスに逆方向にデコードされると解釈します。 拡張の各レベルは空間を 4 つの象限に分割し、各象限は値を保持または反転します。 これにより、x と y のビットに対するバイナリ再帰が作成されます。 

したがって、問題は、任意のセル (x, y) の値を O(log(max(x, y))) 時間で計算し、包含排他を介して大きな四角形にわたって 2D プレフィックス合計を使用することに帰着します。 ただし、10^9 の範囲にわたって直接プレフィックスの合計を計算することは依然として不可能であるため、代わりに、2 のべき乗の境界に位置合わせされた四角形の再帰的分解を使用して範囲の合計を計算します。 

最終的なソリューションは 2 つのアイデアを組み合わせたものです。1 つは長方形にわたるプレフィックスの合計を評価する再帰関数、もう 1 つは座標を位置合わせされたブロックにビットレベルで分解することで、その寄与はパリティ追跡を備えた元の n×m グリッドを使用して計算できます。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |

 | 再帰的クワッド + プレフィックス分解 | O(nm + q log n log m) | O(nm) | 承認済み |

 ## アルゴリズムのチュートリアル

 中心となるアイデアは、無限行列を再帰的なタイルとして扱うことであり、各レベルで両方の次元が 2 倍になり、制御された反転パターンが導入されます。 

元の n×m グリッドの接頭辞の合計を事前に計算して、その内部の部分四角形をすぐに合計できるようにします。 

次に、無限グリッド内の (1,1) から (x,y) までの四角形内の値の合計を計算する関数を定義します。 このような各長方形は、x と y の最大の 2 のべき乗構造に基づいて分解できます。 

### ステップ

 1. 元のグリッドの 2D プレフィックス合計を事前計算します。 これにより、基本行列の任意の部分四角形に対する定数時間クエリが可能になります。 これが必要なのは、すべての再帰的リダクションが最終的にベース グリッドに到達するためです。 
2. 長方形 (1,1) から (x,y) までの無限グリッドの合計を返す再帰関数 S(x, y) を定義します。 目標は、整列された小さなブロックで大きな長方形を表現することです。 
3. x と y 内に収まる最大の 2 のべき乗ブロックを見つけます。 これは、x または y が象限構造を変更する最上位ビットに対応します。 このステップが必要なのは、反復ごとに構造が 2 倍になるためです。 
4. 長方形を 4 つの部分に分割します。完全に覆われたブロック、最大 2 つの残りのストリップ (右と下)、およびコーナーのオーバーラップです。 各部分は、同じ問題のより小さなインスタンスに対応します。 
5. 完全にカバーされたブロックの場合、そこに含まれるベース グリッドの完全なコピーが何個あるかを決定します。 各完全なブロックは、再帰深さのパリティに応じて、元の合計またはその補数のいずれかに寄与します。 
6. 残りの部分については、同じ関数 S を使用してその寄与を再帰的に計算し、最も近い位置合わせされた境界に向かって x と y を減らします。 
7. 重複する領域が二重にカウントされないように、包含/除外を使用して結果を結合します。 

再帰は x ≤ n および y ≤ m のときに終了し、その時点でベース グリッドから接頭辞の合計を直接返します。 

### なぜ効果があるのか

 無限行列内のすべての座標は、x と y のバイナリ表現によって決定される象限選択の一意のチェーンに属します。 構築内で 1 レベル上がるたびに、象限に応じて値が保存または反転されます。 これにより、大きな長方形を、元のグリッドまたはその補数のいずれかにきれいにマッピングする、互いにばらばらに整列されたサブ長方形に分解できるようになります。 各分解ステップが重複することなく空間を分割し、反転の正確なパリティ追跡を維持するため、再帰では正確な寄与が保持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n, m, q = map(int, input().split())
g = [list(map(int, list(input().strip()))) for _ in range(n)]

pref = [[0]*(m+1) for _ in range(n+1)]
for i in range(n):
    for j in range(m):
        pref[i+1][j+1] = g[i][j] + pref[i][j+1] + pref[i+1][j] - pref[i][j]

def base_sum(x1, y1, x2, y2):
    return pref[x2][y2] - pref[x1-1][y2] - pref[x2][y1-1] + pref[x1-1][y1-1]

def S(x, y):
    if x <= 0 or y <= 0:
        return 0
    if x <= n and y <= m:
        return base_sum(1, 1, x, y)

    # largest power-of-two split dimension
    mx = 1 << (x.bit_length() - 1)
    my = 1 << (y.bit_length() - 1)

    # full blocks
    full_x = x // mx
    full_y = y // my

    res = 0

    # contribution from full aligned base copies
    for i in range(full_x):
        for j in range(full_y):
            # parity determines flip
            flip = (i + j) % 2
            val = base_sum(1, 1, n, m)
            if flip:
                val = n * m - val
            res += val

    # residual parts
    res += S(x % mx, y)
    res += S(full_x * mx, y % my)

    return res

for _ in range(q):
    x1, y1, x2, y2 = map(int, input().split())
    def F(x, y):
        return S(x, y)

    ans = F(x2, y2) - F(x1-1, y2) - F(x2, y1-1) + F(x1-1, y1-1)
    print(ans)
```この実装は、再帰的に構造化されたグリッド上の合計の前に問題を軽減することに依存しています。 プレフィックス テーブルを使用すると、元の行列内の任意の部分四角形への定時間アクセスが可能になります。これは、すべての再帰的分解が最終的に元の行列にマッピングされるため、不可欠です。 

再帰関数 S は、完全なブロックと残りの領域の組み合わせとして大きなプレフィックスを表現しようとします。 2 のべき乗の分割により、倍加の繰り返しによって引き起こされる構造と確実に一致します。 フル ブロック内のパリティ ロジックは、交互の象限で導入される反転を考慮します。 

最後に、各クエリはプレフィックス合計に対する包含/除外を使用して回答され、四角形クエリを 4 つのプレフィックス評価に変換します。

 ## 特殊なケース

 重要なエッジ ケースは、(1,1) ～ (n,m) など、クエリ四角形が完全に元のグリッド内にある場合です。 この場合、再帰は直ちに終了し、分解せずにプレフィックスの合計を返す必要があります。 アルゴリズムは、基本条件 x ≤ n および y ≤ m によってこれを処理します。 

別のエッジ ケースは、一方の次元がベース グリッドより小さく、もう一方の次元が非常に大きい場合 (たとえば、(1,1)-(10^9, m)) に発生します。 再帰により、小さい次元にはプレフィックス合計を直接使用しながら、大きい次元のみが正しく削減されるため、不必要な分解が発生しないことが保証されます。 

最後の微妙なケースは、クエリ境界が 2 の累乗分割と正確に一致する場合です。 このような場合、残差項は消滅し、フルブロックの寄与のみが残り、包含排他におけるオフバイワンの重複が回避されます。
