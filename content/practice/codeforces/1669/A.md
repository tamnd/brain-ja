 ## 解決策
 ## 問題の理解

 各テスト ケースでは、Codeforces ユーザー評価を表す単一の整数が与えられます。タスクは、その評価を 4 つの固定間隔 (それぞれが分割番号に対応する) の 1 つに分類することです。 

マッピングは純粋にしきい値ベースです。 マイナス評価を含む非常に低い評価はディビジョン 4 に分類されます。評価が上昇すると、最高評価のディビジョン 1 に到達する前に 2 つの中間バンドを通過します。 出力は計算ではなく、整数行のこの順序付けされたパーティション内の数値が存在する場所から導出されるラベルです。 

テスト ケースの数という点では制約が大きく、最大 1 万件です。 各テスト ケースは独立しており、必要な作業量は一定であるため、実行可能なソリューションは各入力を O(1) 時間で処理するものだけです。 並べ替えや繰り返しのスキャンを伴うものは不要なオーバーヘッドになりますが、制約内であれば技術的には可能です。 ただし、概念的には不一致であり、必要以上に遅くなります。 

この問題の唯一の微妙な点は、境界処理にあります。 分割境界は包括的であるため、1400、1600、および 1900 に正確に等しい値は、上位の分割バンドに正しく配置される必要があります。 典型的な間違いは、厳密な不等式を一貫性なく使用することです。これにより、境界値が間違った除算に移動する可能性があります。 たとえば、1400 をディビジョン 4 として扱うと、`< 1400`代わりにチェックしてください`<= 1399`誤った分類につながります。 

## アプローチ

 強引な解釈では、各分割間隔を順番に明示的にチェックし、メンバーシップをテストします。 範囲が 4 つしかないため、単純なアプローチでもテスト ケースごとの時間は一定のままです。 範囲をペアとして保存し、それを反復処理して、評価が各間隔に該当するかどうかをチェックすることを想像できます。 これは、間隔の数が固定されており、小さいため、テスト ケースごとのワーストケースの作業量が一定であるため、正しく機能します。 

ただし、問題の構造は一般的な区間メンバーシップよりも単純です。 間隔は連続しており、数直線上に並べられているため、反復やデータ構造はまったく必要ありません。 最低しきい値から最高しきい値までの直接の比較チェーンで十分です。 正しいバンドを検出したら、対応する分割ラベルをすぐに返すことができます。 

重要な観察は、評価空間が 3 つのカットポイント (1400、1600、および 1900) によって定義される 4 つの単調領域に分割されていることです。これにより、問題は単純なしきい値分類問題に変わり、これらのカットオフを昇順に比較するだけで済みます。

 ## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取ります。 これにより、実行する独立した分類の数が決まります。 
2. 各評価について、上位部門を定義する最小しきい値と比較します。 レーティングが 1900 以上の場合、それ以上の境界は存在しないため、ディビジョン 1 に属する必要があります。 
3. レーティングが 1900 未満の場合は、少なくとも 1600 であるかどうかを確認します。1600 である場合は、ディビジョン 1 に到達しないことが保証されているため、2 番目に高い帯域に位置します。 
4. 評価が 1600 未満の場合は、少なくとも 1400 であるかどうかを確認します。これより高い可能性はすでに除外されているため、これにより 3 番目のバンドが特定されます。 
5. 上記の条件がいずれも満たされない場合、レーティングは最大 1399 でなければならず、ディビジョン 4 に配置されます。 

各条件によって数直線の接頭辞が削除されるため、チェックの順序が重要になります。 条件が成功すると、その後のチェックは無関係になるため、決定を無効にしてはなりません。 

### なぜ効果があるのか

 評価線は 4 つの互いに素な区間に分割されており、その和集合はすべての整数をカバーします。 各条件チェックは、上位のものを除外した後のこれらの間隔のいずれかのメンバーシップに対応します。 チェックは最高のしきい値から最低のしきい値に進むため、すべての評価は正確に 1 つの部門に割り当てられ、包括的な境界定義により重複やギャップは発生しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    r = int(input())
    
    if r >= 1900:
        print("Division 1")
    elif r >= 1600:
        print("Division 2")
    elif r >= 1400:
        print("Division 3")
    else:
        print("Division 4")
```このソリューションは、各評価を個別に読み取り、固定された比較シーケンスを適用します。 最初の条件は上部の範囲を処理し、後続の各分岐は、より高い範囲をすべて除外した後でのみ、次に低い範囲を処理します。 これにより、間隔のエンドポイントを明示的にエンコードする必要がなく、正確さが保証されます。 

よくある間違いは、チェックの順序を逆にしてしまうことです (テストなど)。`r >= 1400`初め。 これにより、注意深く保護しない限り、すべてのより高い評価が誤ってディビジョン 3 以下に分類されてしまいます。 降順にすることで、このような誤分類を防ぐことができます。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        r = int(input())
        if r >= 1900:
            out.append("Division 1")
        elif r >= 1600:
            out.append("Division 2")
        elif r >= 1400:
            out.append("Division 3")
        else:
            out.append("Division 4")
    return "\n".join(out) + "\n"

 ## 特殊なケース

 負の評価は、最低帯域がゼロを超えて無制限の負の範囲にまで広がっていることを示しています。 のような入力の場合`-1`、小切手`r >= 1900`、`r >= 1600`、 そして`r >= 1400`すべて失敗し、正しい分類として Division 4 が残ります。 最後の else ブランチは、より高いしきい値でカバーされないすべてのものをキャプチャするため、アルゴリズムはこれを自然に処理します。 

1400、1600、1900 などの境界値は、ちょうど除算の遷移に位置するため、重要です。 たとえば、1400 は次の条件に合格する必要があります。`r >= 1400`1399 はすべての上位チェックに失敗し、ディビジョン 4 に分類されます。条件の厳密な順序付けにより、明示的な間隔エンドポイントを必要とせずに正しい配置が保証されます。
