 ## 解決策
 ## 問題の理解

 直線上に配置された一連のキャンディーの重みが与えられます。 アリスとボブの 2 人は、厳しい制約の下でキャンディーを消費します。アリスは左端からのみプレフィックスを取得でき、ボブは右端からのみサフィックスを取得できます。 どちらもキャンディーをスキップすることはできませんし、同じキャンディーを取ることもできません。 

ひねりを加えると、彼らは最終的に総重量が等しいキャンディーを食べたいということです。 重複しない左側の接頭辞と右側の接尾辞を選択するこのような有効な方法の中で、合計で消費されるキャンディーの数を最大化したいと考えています。 

キー オブジェクトは、配列を 3 つの概念的な部分に分割したものです。左側のセグメントは完全にアリスによって取得され、右側のセグメントは完全にボブによって取得され、中央のセグメントは空である可能性がありますが無視されます。 

制約が非常に厳しいため、すべてのプレフィックスとサフィックスのペアに対する二次検索は実行できません。 合計入力サイズが最大 200,000 である場合、左右のエンドポイントをすべて個別に試行するアプローチでは、最悪の場合、制限をはるかに超えて 10^10 の操作に陥る危険があります。 

部分和が一致しても、有効なプレフィックス/サフィックス構造と一致していない場合、微妙な問題が発生します。 たとえば、再調整を考慮せずに両端の等しい合計を貪欲に一致させると、片側を内側にシフトする必要がある長いバランスのとれた構成を見逃す可能性があります。 

単純な貪欲マッチングの失敗の最小限の例:

 入力:```
1
5
1 2 3 2 1
```単純なアプローチでは、1 対 1 がすぐに一致し、早めに停止して 2 つのキャンディーが生成される可能性がありますが、最適な解決策は左側で 1+2+3、右側で 2+1+3 (位置合わせ推論後) を取得し、中央の処理方法に応じてより大きなバランスの取れた構造を生成します。 実際の要件は、初期の一致にコミットすることではなく、すべてのプレフィックスとサフィックスのペアにわたって可能な限り最高の平等を維持することです。 

## アプローチ

 ブルートフォース ソリューションでは、アリスのすべての可能なプレフィックスとボブの可能なすべてのサフィックスを試し、それらの合計を計算し、それらが一致するかどうかを確認します。 各ペアについて、選択したセグメントが重複しないようにします。 これにより、テスト ケースごとに O(n^2) 個の候補ペアが生成され、プレフィックスの合計が事前に計算されていない限り、単純に合計を計算すると、その値はさらに高くなります。 

プレフィックスの合計を使用した場合でも、最悪の場合は O(n^2) の比較に直面することになります。これは、n が全体的に 2 · 10^5 に達すると大きすぎます。 

重要な観察は、両側が反対側からの単調累積であるということです。 アリスのセグメントを拡張すると、彼女の合計は増加するだけです。 同様に、ボブのセグメントを内側に拡張すると、合計が増加します。 これにより、自然な 2 ポインター構造が作成されます。つまり、左から 1 つと右から 1 つ、合計 2 つの合計のバランスを取ろうとします。 

すべての分割を個別に探索する代わりに、2 つのポインターを維持し、それらが一致するか交差するまで、小さい方の合計で辺を増分します。 合計が一致した場合、使用したキャンディーの総数を記録します。 それらが交差する場合は、その構成を停止します。 

これが機能するのは、有効な解が 2 つの単調累積の合流点に対応するためです。また、合計は内側に拡張する場合にのみ増加するため、以前の状態を再検討する必要がありません。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. 2 つのポインター (配列の左端と右端に 1 つ) と、アリスとボブの 2 つの累計を初期化します。 

このアイデアは、両方の人が食事の範囲を内側に拡大することをシミュレートすることです。 
2. 左ポインタが右ポインタと交差していない間に、2 つの合計を比較します。 

合計が等しい場合、これは有効な構成であり、これまでに消費されたキャンディーの数で答えを更新します。 
3. アリスの合計が小さい場合は、左ポインタを右に 1 つ移動し、そのキャンディーの重さをアリスの合計に加えます。 

これが必要なのは、アリスがボブの現在の合計額と一致するように合計額を増やす必要があるためです。 
4. それ以外の場合は、ボブの合計の方が小さいため、右ポインタを 1 ステップ左に移動し、そのキャンディーの重さをボブの合計に追加します。 

これにより、常に 2 つの合計のバランスをとる方向に進むことが保証されます。 
5. ポインタが交差するまで続行します。その点を超えると、互いに素なプレフィックスとサフィックスのパーティションは存在しません。 

なぜ効果があるのか:

 どの時点でも、アリスのセグメントはプレフィックスであり、ボブのセグメントはサフィックスです。 合計を増やす唯一の方法は内側に拡張することです。拡張しても両方の合計が厳密に減少することはありません。 有効な解は、2 つのポインターが等しい和を持つ互いに素なセグメントを定義する何らかの状態に対応します。 ポインタを和の小さい方に移動するだけであるため、候補をスキップせずに任意の等和状態に到達する可能性が維持されます。スキップするには和を減らす必要がありますが、この構成では不可能です。 したがって、特定の拡張パターンで等しい和のペアが最初に見つかったときは、それを考慮しても安全であり、そのようなすべての遭遇にわたって最大値を追跡することで最適な答えが得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        l, r = 0, n - 1
        left_sum = 0
        right_sum = 0
        ans = 0
        
        while l <= r:
            if left_sum <= right_sum:
                left_sum += a[l]
                l += 1
            else:
                right_sum += a[r]
                r -= 1
            
            if left_sum == right_sum:
                ans = max(ans, l + (n - 1 - r))
        
        print(ans)

if __name__ == "__main__":
    solve()
```この実装は、2 ポインター シミュレーションを直接反映しています。 左のポインタ`l`アリスが取得した要素の数を追跡し、右ポインタ`r`ボブが右側から何回取ったかを追跡します。 

表現`l + (n - 1 - r)`消費された要素の合計を計算します。`l`要素は左から、`(n-1-r)`右から要素。 これにより、二重カウントが回避され、縮小する中間セグメントが自然に処理されます。 

一般的な実装の落とし穴は、すべてのバランス調整ステップの後ではなく、ポインターが移動したときにのみ応答を更新することです。 どちらかの側が拡張した直後に一致が発生する可能性があるため、各拡張後に等価性チェックを実行する必要があります。

 ## 特殊なケース

 アリスとボブの両方が等しい和を持つ空でない互いに素なセグメントを選択できないため、単一要素の配列は常に失敗します。 このアルゴリズムは両端でポインターを初期化し、すぐに不均衡を生み出し、等価性を見つけることができないため、正しくゼロを返します。 

すべての要素が同一である配列では、次のようになります。`[5, 5, 5, 5]`、対称展開後、ポインタはすぐにバランスがとれます。 各ステップでは等しい成長可能性が維持されるため、等価性が頻繁に実現され、両側が同じ数の要素を消費すると最大スパンが正しく更新されます。 

最適解を得るために大きな中間ブロックをスキップする必要がある場合。`[1, 100, 1, 100]`、どちらの側も平等に違反することなく高い不均衡に利益をもたらすことができないため、アルゴリズムは自然に中間を回避します。 唯一の有効なバランスは、両方の側が一致する高重みのエンドポイントを消費するとき、つまりポインタが対称的に収束するときに達成されます。
