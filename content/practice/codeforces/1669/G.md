 ## 解決策
 ## 問題の理解

 次のサイズの長方形グリッドが与えられます。$n \times m$空のセル、石、障害物で構成されます。 石は「*」、空のセルは「.」、障害物は「o」で表されます。 目標は、重力をシミュレートすることです。各石は、グリッドの底、すでに沈んでいる別の石、または障害物に当たるまで、可能な限り落下します。 すべての石が落ち着いたら、グリッドの最終構成を出力する必要があります。 

グリッド サイズは最大 50 行、50 列に制限されており、テスト ケースは最大 100 個まで存在できます。 セルの総数は最大でも$50 \times 50 = 2500$テスト ケースごとに、単純なセルごとのシミュレーションでも十分に高速になります。 ただし、不注意に実装すると、障害物の上に石が積み上げられたり、複数の石が同じ柱から落ちたりする場合など、特定の構成では誤った結果が生じる可能性があります。 トップダウンで繰り返して石をすぐに空のセルに移動すると、石を「上書き」したりスキップしたりして、不正確な最終レイアウトが生成される危険があります。 小さな具体例としては、コラムがあります。`.*.*o.`。 トップダウンで処理すると、最初の「*」は落ちますが、カウントを適切に処理しないと、2 番目の「*」が誤って最初の決済された石を通過してしまう可能性があります。 

エッジ ケースには、障害物のみがある柱、石だけがある柱、障害物の上に複数の石が積み上げられている場合、および 1 列のグリッドが含まれます。 これらのケースを正しく処理するには、同じ列内の他の石と競合する可能性のある方法で石を個別に移動することなく、石が着地する場所を計算する必要があります。 

## アプローチ

 強引なアプローチは、グリッド内の各セルを繰り返し反復処理し、石が移動できなくなるまで石を 1 段階ずつ下に移動することです。 この方法は、各石が有限のステップ数しか落下できないため正しいですが、高さの柱の場合、非効率的です。$n$、石は最大まで移動する可能性があります$n$ステップと$n \times m$細胞、これは与えます$O(n^2 m)$テストケースごとの操作。 と$n = m = 50$、最悪のケースはテスト ケースあたり約 125,000 の操作であり、これはまだ実現可能ですが、より直接的なアプローチが存在する場合は不要です。 

重要な点は、各列を独立して処理できることです。 石を段階的に移動する代わりに、障害物間の石の数を数えて、利用可能な最も低い位置に石を「落とす」ことができます。 障害物は自然な区切りとして機能し、各列をセグメントに分割します。 各セグメントについて、数えた石をセグメントの底に配置し、残りを空のセルで埋めます。 このアプローチにより、作業が列ごとに 1 回のパスに減り、シンプルな結果が得られます。$O(nm)$このアルゴリズムは実装が簡単で、単純なシミュレーションの落とし穴を回避します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (ステップバイステップ) | O(n^2m) | O(nm) | 許容できるが不要 |
 | 列ごとのカウント | O(nm) | O(nm) | 最適、受け入れ済み |

 ## アルゴリズムのチュートリアル

 1. 各列を左から右に独立して繰り返します。 各列をセルの垂直配列として扱います。 
2. 各列について、石のカウンターをゼロに初期化します。 このカウンターは、現在のセグメント (障害物の間、または下から障害物まで) 内の石の数を追跡します。 
3. 下の行から上の行まで繰り返します。 石に遭遇した場合は、カウンターをインクリメントし、セルを一時的に空の「.」に置き換えます。 障害物に遭遇した場合は、現在のセグメントを処理します。 
4. セグメントを処理するとき (障害物にぶつかったとき、または柱の頂上に到達したとき)、カウントした数の石をセグメントを下から埋めていきます。 セグメント内の可能な限り低い位置に石を配置し、その上の残りのマスを空のマスで埋めます。 石のカウンターをゼロにリセットします。 
5. 柱の上部まで上向きに作業を続け、最後のセグメント (最後の障害物または下部から上部まで) が同じ方法で処理されることを確認します。 
6. すべての列を処理した後、グリッドは重力が適用された後の最終状態を表します。 

この方法が機能するのは、列の処理中のどの時点でも、現在の行の下にあるすべての石がすでに最終位置に配置されているという不変条件を維持しているためです。 石を数え、各セグメントの利用可能な最も低い位置に石を配置することで、障害物と以前に設置された石の両方を尊重します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, m = map(int, input().split())
    grid = [list(input().strip()) for _ in range(n)]

    for col in range(m):
        stones = 0
        for row in range(n-1, -1, -1):
            if grid[row][col] == '*':
                stones += 1
                grid[row][col] = '.'
            elif grid[row][col] == 'o':
                for k in range(1, stones+1):
                    grid[row+k][col] = '*'
                stones = 0
        for k in range(stones):
            grid[k][col] = '*'

    for row in grid:
        print(''.join(row))
```外側のループは複数のテスト ケースを処理します。 グリッドをリストのリストに読み込むと、その場での変更が可能になります。 各列を下から上に繰り返すことで石が数えられ、障害物または列の上部に遭遇した後に配置されます。 最後のネストされたループは、更新されたグリッドを出力します。 インデックスを慎重に扱うことで、障害物を上書きすることなく石を正しく配置できます。 

## 実用的な例

 ### 例 1

 入力列セグメント:```
Row 5: .
Row 4: *
Row 3: *
Row 2: o
Row 1: .
Row 0: *
```ボトムアップ処理:

 - 行 5 '.'、石=0
 - 行 4 '*'、石=1、'.' としてマークします。 
- 行 3 '*'、石=2、'.' としてマークします。 
- 行 2 'o'、下に 2 つの石を配置します。行 3 と 4 は '*' になり、石 = 0 にリセットされます。 
- 行 1 '.'、石=0
 - 行 0 '*'、石=1、'.' としてマークします。 
- 一番上に到達したら、残りの石を行 0 に置きます

 結果の列:```
Row 5: *
Row 4: *
Row 3: o
Row 2: .
Row 1: .
Row 0: *
```これは、障害物がどのようにセグメントを分割し、石がセグメント内の最も低い位置に落ち着くかを示しています。 

### 例 2

 入力: 列`*.*.*`ボトムアップ処理では、障害物間の石 (ここでは何もありません) をカウントし、それらを一番下に配置します。 

- 初期石=0
 - 行 4 '*'、石=1、'.' としてマークします。 
- 行 3 '.'、石=1
 - 行 2 '*'、石=2、'.' としてマークします。 
- 行 1 '.'、石=2
 - 行 0 '*'、石=3、'.' としてマークします。 
- 一番上に到達したら、下の 3 列に 3 つの石を置きます

 最後のコラム:`..***`これは、障害物がない複数の石が正しく底に積み重なっていることを示しています。
