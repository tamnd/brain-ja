 ## 解決策
 ## 問題の理解

 整数の配列が与えられ、個々の要素のビットを「オン」にすることができます。 各操作では 1 つの要素が選択され、以前は 0 だった 1 つのビットが 1 に設定されます。 せいぜいこれくらいかな`k`アレイ全体で 1 回。 

これらのビット挿入を適用した後、すべての配列要素に対してビットごとの AND を計算します。 目標は、この最終的な AND 値を最大化することです。 

主な難点は、AND が非常に厳密であることです。ビットは、すべての要素にビットが含まれている場合にのみ最終的な答えに寄与します。 これは、1 つの要素でもビットが欠けている場合、そのビットは結果に完全に存在しないことを意味します。 したがって、ビットを追加する操作は、最終的にすべての要素に出現する場合にのみ役に立ちます。 

この制約により、私たちはビットレベルの貪欲戦略またはカウンティング戦略に向かうことになります。 合計`n`テストケース全体で最大`2·10^5`したがって、各要素をビットごとに固定回数検査するソリューションであればどれでも受け入れられます。 ただし、ビットまたは要素のサブセットを試行したり、操作を直接シミュレートしたりするものはすべて、すぐに失敗します。`k`と同じ大きさにすることができます`10^9`。 

単純な解釈では、要素ごとにビットを貪欲に割り当てようとすることになりますが、これでは AND によって作成されるグローバル結合が無視されます。 実際の構造は、各ビットが独立しており、個別に分析できます。 

要素ごとの設定ビット数を常に最大化する必要があるとソリューションが想定している場合、微妙な失敗例が発生します。 

たとえば、次のことを考えてみましょう。```
n = 3, k = 1
a = [1, 0, 1]
```単純な考えとしては、中央の要素に対する演算を使用して他の要素から有用なビットをコピーするというものかもしれませんが、実際には、少なくとも 2 つの要素にすでにビットが存在しない限り、1 つの演算で 3 つの要素すべてにビットを出現させることはできません。 したがって、最良の答えは残ります`0`または完全な位置合わせが可能かどうかによって異なります。 これは、要素ごとではなく、ビットごとにグローバルに推論する必要があることを強調しています。 

## アプローチ

 強引な観点としては、最大の適用方法をすべてシミュレートすることです。`k`ビット挿入。 各操作はインデックスとビット位置を選択できるため、大まかに次のとおりです。`n * 31`操作ごとの選択肢。 小さいものに限定しても`k`、分岐係数により、これが指数関数的になります。 

この問題は、「ビットをどのように割り当てるか」から「AND を存続させるために各ビットに何が必要か」に視点を変えると、対処できるようになります。 

少し修正してください`j`。 初期配列では、`cnt[j]`このビットがすでに設定されている要素の数です。 ビットを作るには`j`最後の AND に出現する場合、すべての要素がこれで終わる必要があります。 つまり、正確に修正する必要があるということです`n - cnt[j]`このビットの位置がありません。 それぞれの操作で 1 つの要素内の 1 つのビットの 1 つの欠落位置を修正できるため、ビットを作成するコストは`j`完全に存在するはまさに`n - cnt[j]`。 

これで構造がわかりました。各ビットはその値に等しい「利益」を持つ項目です。`2^j`そして、それをグローバルにアクティブ化するために必要な操作の数に等しい「コスト」。 総コスト ≤ を条件として、合計値を最大化するビットのサブセットを選択したいと考えています。`k`。 

これは、ビットごとの有意性を貪欲にする典型的な状況です。 値において上位ビットが下位ビットを支配するため、30 から 0 までのビットを処理し、余裕があれば貪欲にビットを含めます。

 ## アルゴリズムのチュートリアル

 1. 各ビットのカウント`j`、すでにそのビットが設定されている配列要素の数。 これにより、ビットが「ほぼすでにグローバル」であるベースライン構造が得られます。 
2. 各ビットについて`j`、そのビットが欠落している要素の数を計算します。`cost[j] = n - cnt[j]`。 これは、このビットをすべての要素に存在させるために必要な操作の数です。 
3. 変数を初期化する`remaining_k = k`、まだ費やすことができる操作の数を追跡します。 
4. 答えを初期化する`ans = 0`。 
5. ビットを 30 から 0 まで繰り返します。各ビットについて`j`、どうかを確認してください`cost[j] <= remaining_k`。 そうであれば、このビットをグローバルに強制する余裕があります。 
6. ビットを含めると`j`、 追加`2^j`答えと引き算`cost[j]`から`remaining_k`。 
7. 少し余裕がない場合はスキップしてください。 下位ビットはまだ手頃な価格であり、組み合わせることで価値がある可能性があります。 

### なぜ効果があるのか

 ビットを設定するため、各ビットの動作は独立しています。`j`要素内の他のビットには影響しません。 ビットを完全に存在させるためのコストは、他のビットの選択ではなく、現在そのビットが欠落している要素の数によってのみ決まります。 

ビットの重要度による貪欲な順序付けは正しいものです。コストは固定されており独立していますが、値は厳密な 2 値の優位性に従います。 下位ビットを含む構成では、上位ビットの損失を補うことはできないため、上位ビットから下位ビットへの処理により、下位ビットの組み合わせが悪いために達成可能な上位ビット構成が犠牲になることがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))

        cnt = [0] * 31

        for x in a:
            for j in range(31):
                if x & (1 << j):
                    cnt[j] += 1

        remaining = k
        ans = 0

        for j in range(30, -1, -1):
            cost = n - cnt[j]
            if cost <= remaining:
                remaining -= cost
                ans |= (1 << j)

        print(ans)

if __name__ == "__main__":
    solve()
```このソリューションでは、まず配列全体でビット周波数を構築します。これは、各ビットが普遍性からどれだけ離れているかを知るために必要です。 次に、貪欲ループは、重要度の降順でビットの選択をシミュレートします。 

よくある間違いは、各演算が 1 ビットに対して 1 つの要素のみを修正することを認識せずに、ゼロをグローバルに数えることによってコストを誤って計算することです。 もう 1 つは、ビット間で演算を再利用しようとすることです。 各 OR 演算は 1 つの要素内の 1 ビットだけを対象とするため、これは無効です。

これは、高価でも予算内であれば、単一の上位ビットでも結果を支配する可能性があることを示しています。

 - ビット 1 はすでにすべての要素にあります

 ## 特殊なケース

 重要なエッジケースは、すべての要素にすでにビットが含まれている場合です。 その場合、`cnt[j] = n`、 それで`cost[j] = 0`、アルゴリズムは常にそのビットをすぐに受け取ります。 これにより、操作を消費することなく既存の構造が確実に保持されます。 

もう 1 つのエッジケースは次のような場合です`k = 0`。 このアルゴリズムには、すでにグローバルではないビットが含まれることはありません。`cost[j] > 0`完全に存在しない限り。 結果は元の配列の AND になります。 

最後に、いつ`k`が非常に大きい場合、アルゴリズムは単純にすべてのビットを含めようとしますが、それでも各ビットには実現可能性が必要です。 コストは独立しているため、最終的には、完全なカバレッジが可能な場合にのみ、すべての要素のビット単位の OR を再構築することになり、これは意図した最適化動作と一致します。
