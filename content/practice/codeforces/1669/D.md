 ## 解決策
 ## 問題の理解

 完全に空から始まるセルの行が与えられ、常に 2 つの隣接する位置に作用する特別な演算を適用することができます。 各アプリケーションは、これら 2 つのセルを、いずれかの順序で異なる色 (1 つは赤、もう 1 つは青) に再色付けします。 

最終的な構成は、白セル、赤セル、青セルからなる文字列として事前に固定されています。 白は「決して着色されない」ことを意味し、赤と青は永久的な色です。 このタスクは、最初はすべて白だった行をターゲット文字列に変換する、隣接する 2 つのセルのスタンプ操作のシーケンスが存在するかどうかを判断することです。 

各スタンプは常に 2 つの隣接するスタンプに影響を与えるため、ローカル制約が導入されます。色はセルごとに独立して割り当てられることはなく、常にペアで割り当てられます。 スタンプは重複して再適用できるため、以前の選択が上書きされる可能性があるため、問題は構築シーケンスを明示的に追跡することではなく、一貫したシーケンスが存在するかどうかを確認することです。 

制約は十分に大きいため、どのソリューションもテスト ケースごとに線形時間で実行する必要があります。 すべてのテスト ケースの合計の長さは最大 100,000 であるため、テスト ケースごとに O(n) または O(n log n) の解であっても許容されますが、ケースごとに 2 次関数を使用すると遅すぎます。 スタンプを適用する方法の数は位置の数に応じて指数関数的に増加するため、これにより、すべてのスタンプ シーケンスのブルート フォース シミュレーションが即座に除外されます。 

局所的に推論すると、いくつかの特殊なケースが見落とされがちです。 「B」や「R」のような単色のセルは不可能です。スタンプごとに 2 つのセルが色付けされるため、孤立した単色の要件を作成することはできません。 もう 1 つの微妙なケースは、色付きのセルが白で囲まれる「WBW」または「WRW」のようなパターンです。 色付きの各セルは個別に問題なく見えますが、隣接するセルに影響を与えずにセルを作成する方法はないため、このような構成は失敗します。 3 番目の重要なケースは、「BRBR」のような交互パターンです。このパターンでは、隣接するすべてのペアが「有効に見える」ものですが、各スタンプが色付き領域全体をタイリングする必要があるペアリング構造を強制するため、グローバルな一貫性が依然として重要です。 

## アプローチ

 ブルートフォースアプローチでは、このプロセスをシミュレートしようとします。つまり、すべての白から開始して、隣接するペアを繰り返し選択して BR または RB として割り当て、ターゲット文字列に到達するか可能性を使い果たすまで、考えられるすべてのシーケンスを探索します。 これは構築規則を正確に反映しているため、原理的には正しいです。 

ただし、各位置は多くのスタンプの選択肢の一部となる可能性があり、各スタンプの配置は将来の複数の状態に分岐します。 最悪の場合、およそ n 個の位置のそれぞれが複数の方法でペアになる可能性があるため、可能なシーケンスの数は n に応じて指数関数的に増加します。 n が 50 程度の場合でも、これは不可能になります。 

重要な点は、実際にはシーケンスを構築する必要がないということです。 各スタンプは常に、1 つの R と 1 つの B で構成される隣接する非白セルの有効なペアを生成します。したがって、有効な最終構成では、非白セルのすべての最大連続ブロックが、すべての非白セルをカバーできる隣接ペアに内部的に「解決可能」でなければなりません。 白いセルは、問題を独立したセグメントに分割する区切り文字として機能します。 

白いセルのないセグメント内では、基本的に、すべての隣接関係がいくつかの重複する BR/RB ペアによって説明できるように、各位置に色を割り当てることができるかどうかを尋ねています。 重要な単純化は、セグメントが交互配置のチェーンの有効な開始点を少なくとも 1 つ含む場合にのみ有効であり、単一の孤立した色付きセルを強制するセグメントはないということです。

これにより、問題は貪欲なローカル チェックに集約されます。文字列をスキャンし、白で分割し、白以外のセルの連続するブロックごとに、隣接する同色の端点のペアが少なくとも 1 つあること、または伝播を許可する隣接する有効な相互作用が少なくとも 1 つあることを確認します。 実際には、既知の単純化はさらに強力になります。長さが 1 のブロックは無効であり、長さが 2 以上のブロックは常に構築可能です。 

これは、少なくとも 2 の長さのセグメント内では、常に隣接するペアのスタンプを開始して、すべてのスタンプがローカルな隣接制約のみを強制することを考慮しながら、カバレッジを外側に拡張できるためです。 オーバーラップにより、マルチセル セグメントを実現するのに十分な柔軟性がありますが、単一セルには開始元のパートナーがありません。 

したがって、最終的な条件は、非白セルのすべての最大の連続セグメントの長さが少なくとも 2 であるかどうかをチェックすることになります。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. 現在の連続する非白セルのブロックの長さを追跡しながら、文字列を左から右にスキャンします。 「R」または「B」が表示されるたびに長さを増やし、「W」が表示されると長さをリセットします。 これは、白いセルがスタンピングの相互作用を妨げるために必要です。 
2. 白いセルに遭遇するか、文字列の終わりに到達するたびに、終了したばかりのセグメントが評価されます。 長さがちょうど 1 の場合、どのスタンプ操作でも単一のセルを生成できないため、構成が不可能であることがすぐにわかります。 
3. 文字列の残りの部分のスキャンを続け、セグメントごとに同じロジックを繰り返します。 
4. スキャン終了後、長さ 1 の無効なセグメントが見つからなかった場合、設定は可能です。 

重要な決定点は、セグメントを閉じる瞬間です。 その境界では、中断することなく構築する必要がある最大領域に関する完全な情報が得られるため、ローカルで安全に検証できます。 

### なぜ効果があるのか

 各スタンプは常に、隣接する色の付いたセルのペアを生成します。 これは、すべての色の付いたセルが、白以外のセルの接続領域内の何らかの隣接するペアに属している必要があることを意味します。 セグメントの長さが 1 の場合、利用可能な隣接パートナーは存在しないため、一連のスタンプによってセグメントが生成されることはありません。 逆に、重なり合うスタンプにより隣接の実現可能性を損なうことなく色を変更できるため、少なくとも 2 の長さのセグメントは 1 つのペアから開始して外側に拡張することで構築できます。 これにより、セグメントの長さが唯一の必要十分条件になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    s = input().strip()

    ok = True
    i = 0

    while i < n:
        if s[i] == 'W':
            i += 1
            continue

        j = i
        while j < n and s[j] != 'W':
            j += 1

        if j - i == 1:
            ok = False
            break

        i = j

    print("YES" if ok else "NO")
```この解決策は、連続する白以外のブロックを明示的に識別し、サイズ 1 のブロックを拒否することで機能します。 スキャンは線形であり、各位置は最大 1 回処理されます。 

微妙な実装の詳細により、ポインタが確実に動作します。`i`に直接ジャンプします`j`ブロックを処理した後。 これにより、文字の二重カウントが回避され、O(n) の動作が保証されます。 もう 1 つの重要な点は、セグメントが白いセルまたは文字列の末尾で完全に閉じられている場合にのみセグメントを評価し、境界での正確性を保証することです。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        s = input().strip()

        ok = True
        i = 0
        while i < n:
            if s[i] == 'W':
                i += 1
                continue
            j = i
            while j < n and s[j] != 'W':
                j += 1
            if j - i == 1:
                ok = False
                break
            i = j

        out.append("YES" if ok else "NO")
    return "\n".join(out)

# provided samples (partial inclusion due to length)

5
BRBBW
""") == "YES"

1
B
""") == "NO"

# custom cases

3
WBW
""") == "NO"

assert run("""1
2
BR
""") == "YES"

assert run("""1
4
WWWW
""") == "YES"

assert run("""1
5
RBBRW
""") == "YES"

 ## 特殊なケース

 入力「B」などの単一の色のセルは、スキャンによって長さ 1 のセグメントが生成されるため、即座に失敗を引き起こします。 アルゴリズムは、セグメントが文字列の最後で閉じるときにこれを識別し、正しく無効とマークします。 

「WBW」のようなパターンは、長さ 1 の 2 つのセグメントに分割されますが、1 つでもケースを拒否するには十分です。 スキャンは各白いセルでリセットされるため、両方のセグメントが独立してチェックされます。 

完全に白い文字列ではセグメントがまったく生成されないため、無効な条件がトリガーされることはなく、答えは YES のままで、単に何もできないという事実と一致します。
