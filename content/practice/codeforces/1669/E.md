 ## 解決策
 ## 問題の理解

 短い文字列のコレクションが与えられます。各文字列は、小さなアルファベットの小文字 2 文字だけで構成されます。 このタスクは、ちょうど 1 つの位置が異なるという意味で「ほぼ同一」の文字列に対応する、順序付けされていないインデックスのペアがいくつあるかを数えるというものです。 

2 つの文字列のうち 1 つが一致し、もう 1 つの位置が異なる場合、2 つの文字列は答えに寄与します。 例えば、`"ab"`そして`"ac"`2 番目の位置のみが異なるため、有効です。 しかし`"ab"`そして`"cd"`両方の立場が異なるので、違います。 同様に、次のような同一の文字列`"aa"`そして`"aa"`も、ゼロの位置が異なるため無効です。 

入力サイズは大きくなる可能性があり、テスト ケース全体で合計最大 100,000 文字列になります。 すべてのペアを比較するには、最悪の場合でも 10¹⁰ のオーダーの演算が必要となるため、これにより、二次的なペアごとの比較アプローチが即座に除外されます。 解決策は代わりに、頻度カウントまたはハッシュを使用して問題をテスト ケースごとの線形時間に短縮する、構造による集計に依存する必要があります。 

単純な推論による微妙な失敗例は、二重カウントまたは対称性の欠如です。 たとえば、1 文字を変更し、位置ごとに一致を個別にカウントして文字列を一致させようとすると、誤って各エンドポイントから 1 回ずつ、ペアを 2 回カウントしてしまう可能性があります。 慎重に分離せずに「一方の位置を固定し、もう一方でグループ化」しようとすると、別の問題が発生し、両方の位置が異なるケースが混在することになります。 

## アプローチ

 ブルート フォース ソリューションでは、文字列のすべてのペアがチェックされ、文字ごとに比較されます。 各文字列の長さは 2 であるため、各比較は定数時間であり、正確に 1 つの位置が異なるかどうかを直接テストします。 これは、条件を明示的に強制するため、正しいです。 ただし、テスト ケースごとに n が最大 100,000 になると、およそ n²/2 の比較が行われることになり、これは実現可能な限界をはるかに超えています。 

重要な点は、2 つの文字列が正確に 1 つの位置で異なるためには、一方の位置で一致し、もう一方の位置で異なる必要があるということです。 これは、状態を 2 つの独立したパターンに分割することを示唆しています。 最初の文字が一致して 2 番目の文字が異なるか、2 番目の文字が一致して最初の文字が異なるかのいずれかです。 

この構造により、頻度マップを使用して有効なペアをカウントできるようになります。 最初の文字を固定する場合、その最初の文字を共有するすべての文字列のうち、異なる 2 番目の文字を持つものがいくつあるかを数えるだけで済みます。 2番目の文字を固定する場合も同様です。 難しいのは、二重カウントを避けることです。同一のペアを注意深く減算すると、すべての有効なペアは 2 つのビューのいずれかで 1 回だけカウントされます。 

文字列をグループ化し、完全な文字列 ID と部分射影の頻度カウントを使用することで、これをきれいに処理します。

 | ブルートフォース | O(n²) | お(1) | 遅すぎる |

 ## アルゴリズムのチュートリアル

 各文字列を文字のペアとして扱います`(a, b)`そして、これらのペアに対して度数表を作成します。 

1. 各テスト ケースについて、すべての文字列を読み取り、それぞれの正確な文字列が何回出現するかを数えます。 これにより、同一のペアがいくつ存在するかに直接アクセスできるようになります。 
2. 各文字で始まる文字列の数を数え、最初の文字のみをキーとする頻度表を作成します。 これにより、最初の位置を共有するペアについての推論が可能になります。 
3. 同様に、2 番目の文字をキーとする頻度テーブルを作成し、各文字で終わる文字列の数を数えます。 
4. 同じ最初の文字を共有する文字列グループごとに、2 番目の文字の頻度の組み合わせを通じて間接的に、異なる 2 番目の文字を持つクロスペアがいくつ存在するかを計算します。 
5. 同じ 2 番目の文字を共有するグループに対して対称計算を実行します。 
6. 同一の文字列に対応する寄与を減算して、ゼロ位置が異なるペアが除外され、両方の位置が異なるペアが誤って含まれないようにします。 
7. すべてのグループにわたって結果を累積します。 

最終的な答えは、「同じ最初の文字、異なる 2 番目の文字」の寄与と「同じ 2 番目の文字、異なる最初の文字」の寄与を、同一の文字列との重複を避ける方法で組み合わせることで得られます。 

### なぜ効果があるのか

 文字列の有効なペアはすべて、正確に 1 つの座標で一致する必要があります。 つまり、すべての有効なペアは、最初の文字を共有するペアまたは 2 番目の文字を共有するペアですが、両方ではなく 2 つの素のカテゴリのいずれかに一意に分類されます。 頻度ベースのカウントでは、グループ化されたカウントに対する組み合わせ論を使用して各カテゴリ内のすべてのペアを列挙し、同一の文字列を除外することで無効なペアが導入されないようにします。 有効な各ペアには一致する座標が 1 つだけあるため、1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        freq = {}
        f1 = {}
        f2 = {}

        arr = []
        for _ in range(n):
            s = input().strip()
            arr.append(s)
            freq[s] = freq.get(s, 0) + 1
            f1[s[0]] = f1.get(s[0], 0) + 1
            f2[s[1]] = f2.get(s[1], 0) + 1

        ans = 0

        for s, c in freq.items():
            a, b = s
            # pairs with same first char but different second
            ans += c * (f1[a] - c)
            # pairs with same second char but different first
            ans += c * (f2[b] - c)

        print(ans // 2)

if __name__ == "__main__":
    solve()
```このソリューションは 3 つの周波数マップを維持します。 1 つは完全な文字列カウントを追跡し、他の 2 つは各文字位置への射影を追跡します。 個別の文字列ごとに、最初の文字を共有するが 2 番目の文字が異なる文字列とのペアが何組形成されるかを計算し、2 番目の文字についても同様に計算します。 各ペアは各エンドポイントから 1 回ずつ、計 2 回カウントされるため、最終結果は 2 で除算されます。 

重要な実装の詳細は減算を使用することです`f1[a] - c`そして`f2[b] - c`これにより、同一の文字列が考慮から削除され、異なる対応する文字列のみが寄与するようになります。

 ## 特殊なケース

 重要なエッジケースは、すべての文字列が同一である場合です。 この状況では、両方の位置周波数カウントが完全な周波数と一致するため、すべての減算ですべてがキャンセルされ、結果はゼロになり、同一のペアのカウントが正しく回避されます。 

もう 1 つの重要なケースは、文字列が 2 文字のすべての組み合わせにわたって完全にバランスが取れている場合です。`"ab", "ac", "db", "dc"`。 ここで、すべてのペアは正確に 1 つの位置で異なり、式では当然、半分になる前にエンドポイントごとにすべてのクロスの組み合わせが 1 回カウントされます。 

最後に、n が 1 の場合、すべての周波数差は直ちにゼロに崩壊し、すべての式が次の形式であるため、無効なアクセスや偶発的な負の寄与は発生​​しません。`c * (f - c)`それはゼロになります。
