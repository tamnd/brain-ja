 ## 解決策
 ## 問題の理解

 当社には 3 段階の生産パイプラインがあります。 

すべての洗濯物は最初に洗濯し、洗濯が終わったらすぐに乾燥機に移し、乾燥が終わったらすぐに折り畳み機に移す必要があります。 同じステージ内のマシンは同一であり、各マシンは一度に 1 つのアイテムのみを処理できます。 

「すぐに」という言葉が重要な難点です。 その瞬間に乾燥機が利用できない限り、アイテムの洗濯を完了することはできません。 同様に、その瞬間に折り機が利用できない限り、アイテムの乾燥を完了することはできません。 これらの条件が維持されるように、洗濯の開始を遅らせることは自由です。 

入力により、洗濯物の数、各段階の機械の数、および各段階の処理時間が得られます。 すべての項目が 3 つの段階すべてを完了する最も早い時間を計算する必要があります。 

制約は驚くほど小さいです。 多くてもあります$10^4$アイテムと最大でも$1000$ステージごとのマシン数。 各項目を個別に処理するシミュレーションは完全に実行可能です。 たとえ$O(k \log k)$または$O(k)$ソリューションは簡単に十分に高速です。 処理時間が長くなる可能性があるため、時間を分単位でモデル化するアプローチは除外されます。$1000$完了にかかる時間は数百万に及ぶ可能性があります。 

よくある間違いは、各段階を独立して扱うことです。 

考慮する：```
1 1 1 1 5 5 5
```答えは 15 です。1 つのアイテムにつき、洗濯 5 分、乾燥 5 分、たたみ 5 分かかります。 

より微妙な例は次のとおりです。```
2 1 1 1 1 100 1
```不注意な解決策を選択すると、洗濯機が空になるため、時刻 1 で 2 回目の洗濯が開始される可能性があります。 それは違法です。 最初のアイテムは時間 101 まで乾燥機を占有しているため、2 番目のアイテムは時間 101 より前に洗濯を完了できません。洗濯完了時に乾燥機を利用できるようにするには、その洗濯を遅らせる必要があります。 

折りたたみステージがボトルネックである場合、別のトラップが発生します。```
3 3 3 1 1 1 100
```3台の洗濯機と乾燥機はすべてすぐに利用できますが、折りたたみ機は1台のみです。 完了した乾燥操作ごとに即座に使用可能なフォルダーが必要となるため、複数の乾燥操作をほぼ同時に終了することは不可能です。 スケジュールはもっと早い段階、つまり洗浄段階で調整する必要があります。 

主な課題は、可用性の制約がパイプラインを通じて逆方向に伝播することです。 

## アプローチ

 強引な視点は、タイムライン上でイベントをスケジュールするという観点から考えることです。 すべての洗濯物について、可能な限り早い洗濯開始時間を検索することができ、最終的には乾燥とたたみへの即時移行が可能になります。 マシンの占有率が判明するとシステムは決定的になるため、これは正しいです。 

問題は、検索時間が明らかにコスト高になることです。 完了時間が非常に長くなる可能性があり、有効な瞬間を見つけるために繰り返し前方にスキャンすると、不必要な作業が発生する可能性があります。 

重要な観察は、時間をかけて検索する必要がまったくないということです。 重要なのは、各ステージのマシンが使用可能になる次の瞬間です。 

すでにいくつかの項目をスケジュールしたとします。 新品の場合は、最も早く入手可能なワッシャーを選択します。 利用可能な時間を$w$。 

洗濯を始める場合$w$、アイテムは次の時点で洗濯を終了します$w+t_1$。 そんな時は乾燥機が必要です。 すべての乾燥機の中で、最も早く利用可能な乾燥機によって、いつ転送が行われるかが決まります。 

同様に、乾燥が終わったら、すぐにフォルダーが必要になります。 

ステージを先へ進めるようにスケジュールするのではなく、折りたたみステージから逆算して考えることができます。 ある時点でフォルダーが使用可能になった場合$f$、その後、それに供給する乾燥操作は、次の時間までに終了する必要があります。$f$。 この乾燥操作によって、洗濯がいつ終了するかが決まります。 

コンテストで使用されたエレガントなソリューションにより、各ステージで次回すべてのマシンが利用可能になる時間が維持されます。 それぞれの洗濯物について、最も早い時期に利用可能な洗濯機、乾燥機、フォルダーを使用します。 これら 3 つの利用可能時間によって、このアイテムの最も早い実行可能な開始時間が決まります。 スケジュールを設定した後、マシンの可用性を更新します。 

プロセス全体がマシンのリリース時間の直接的なシミュレーションになります。

 ## アルゴリズムのチュートリアル

 しましょう`wash[i]`次回は洗濯機になります`i`利用可能です。 

させて`dry[i]`次回はドライヤーをしてください`i`利用可能です。 

させて`fold[i]`次回のフォルダーになります`i`利用可能です。 

最初はすべての値がゼロです。 

各洗濯アイテムについて:

 1. 利用可能時間が最も短い洗濯機を見つけます。 
2. 利用可能時間が最も短い乾燥機を見つけます。 
3. 利用可能時間が最小のフォルダーを見つけます。 
4. このような時はそのままにしましょう`w`、`d`、 そして`f`。 
5. 残りの段階への即時移行を可能にする最も早い洗浄開始時間を計算します。 

洗濯終了時間`start + t1`。 

その場合、乾燥機が利用できる必要があるため、次のようになります。```
start + t1 >= d
```乾燥終了時間`start + t1 + t2`。 

その場合、フォルダーが使用可能である必要があるため、次のようになります。```
start + t1 + t2 >= f
```洗濯機自体が時間前に起動できません`w`。 

すべての制約を組み合わせると、次のようになります。```
start = max(
    w,
    d - t1,
    f - t1 - t2
)
```6. この開始時刻を使用して項目をスケジュールします。 
7. 選択した洗濯機の次回の利用可能状況を次のように更新します。```
start + t1
```8. 選択した乾燥機の次回の空き状況を次のように更新します。```
start + t1 + t2
```9. 選択したフォルダーの次回の利用可能状況を次のように更新します。```
start + t1 + t2 + t3
```10. この項目の完了時間を記録します。 答えは、最後にスケジュールされた項目の完了時間です。 

### なぜ効果があるのか

 すべてのアイテムについて、各ステージで最も早く利用可能なマシンを選択します。 計算された開始時間は、3 つのリソース制約をすべて同時に満たす最小時間です。 

洗濯機はすでに空いている必要があります。 乾燥機は洗濯が終了した時点で空になっている必要があります。 乾燥が終了した時点でフォルダーは解放されている必要があります。 開始時間がこれより短いと、これらの条件の少なくとも 1 つに違反します。 

項目をスケジュールした後、選択した 3 台のマシンは、対応するステージが完了する瞬間まで占有されます。 可用性配列は常に、各マシンが別のアイテムを受け入れることができる将来の最も早い時間を表します。 すべての品目は、それらの在庫状況に合わせて可能な限り最も早い時点でスケジュールされるため、シミュレーションでは世界的に最も早いスケジュールが構築されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    k, n1, n2, n3, t1, t2, t3 = map(int, input().split())

    wash = [0] * n1
    dry = [0] * n2
    fold = [0] * n3

    answer = 0

    for _ in range(k):
        iw = min(range(n1), key=wash.__getitem__)
        idr = min(range(n2), key=dry.__getitem__)
        ifo = min(range(n3), key=fold.__getitem__)

        w = wash[iw]
        d = dry[idr]
        f = fold[ifo]

        start = max(
            w,
            d - t1,
            f - t1 - t2
        )

        wash[iw] = start + t1
        dry[idr] = start + t1 + t2
        fold[ifo] = start + t1 + t2 + t3

        answer = fold[ifo]

    print(answer)

if __name__ == "__main__":
    solve()
```3 つの配列にはマシンのリリース時間が保存されます。 リリース時刻とは、「このマシンはこの瞬間から新しいアイテムを受け入れることができる」という意味です。 

各アイテムについて、すべてのステージでリリース時間が最小のマシンを選択します。 マシンの数は最大 1000 台であるため、リニア スキャンで完全に十分です。 

最もデリケートな部分はコンピューティングです`start`。 

ワッシャーの利用可能性により、`start >= w`。 

洗濯が終わったら乾燥機を利用できるようにする必要があります。`start >= d - t1`。 

乾燥が完了したときにフォルダーが使用可能になる必要があります。`start >= f - t1 - t2`。 

これら 3 つの値の最大値を取ると、すべての制約が同時に満たされます。 

アップデートは間違いやすいものです。 ワッシャーは、パイプライン全体が終了した後ではなく、洗浄が完了した後に解放されます。 同様に、乾燥機は乾燥が完了するとフリーになります。 最終完了時刻まで、フォルダーのみが占有されたままになります。 

すべての算術演算は Python の整数に快適に適合します。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    k, n1, n2, n3, t1, t2, t3 = map(int, input().split())

    wash = [0] * n1
    dry = [0] * n2
    fold = [0] * n3

    ans = 0

    for _ in range(k):
        iw = min(range(n1), key=wash.__getitem__)
        idr = min(range(n2), key=dry.__getitem__)
        ifo = min(range(n3), key=fold.__getitem__)

        start = max(
            wash[iw],
            dry[idr] - t1,
            fold[ifo] - t1 - t2
        )

        wash[iw] = start + t1
        dry[idr] = start + t1 + t2
        fold[ifo] = start + t1 + t2 + t3

        ans = fold[ifo]

    return str(ans)

# provided sample
assert run("1 1 1 1 5 5 5\n") == "15"

# minimum size
assert run("1 1 1 1 1 1 1\n") == "3"

# many washers, one dryer
assert run("2 2 1 1 1 100 1\n") == "102"

# all equal
assert run("3 3 3 3 5 5 5\n") == "15"

# pipeline bottleneck
assert run("3 3 3 1 1 1 100\n") == "302"

 ## 特殊なケース

 次のことを考慮してください。```
2 2 1 1 1 100 1
```乾燥機がネックです。 最初の項目をスケジュールした後、乾燥機は時間 101 まで占有されます。2 番目の項目については、次のようになります。```
w = 0
d = 101
f = 102
```式は次のようになります。```
start = max(0, 100, 1) = 100
```2 回目の洗濯は意図的に遅らせて、乾燥機が使用可能になったときにちょうど洗濯が終了するようにします。 アルゴリズムは 102 を出力します。これは最適です。 

ここで次のことを考えてみましょう。```
3 3 3 1 1 1 100
```最初の項目の後、フォルダーは時間 102 まで占有されます。2 番目の項目は次を取得します。```
start = max(0, 0, 100)
```したがって、洗浄は時間 100 でのみ開始されます。3 番目のアイテムは時間 200 で開始されます。完了時間は 102、202、および 302 になります。 

洗濯機と乾燥機の可用性のみを追跡するソリューションでは、折り畳み機が使用可能になる前に複数のアイテムを誤って乾燥させようとします。 後方制約`f - t1 - t2`その間違いを防ぎます。 

最後に、次のことを考慮してください。```
4 1 1 1 10 1 1
```ワッシャーがネックです。 すべての新しいアイテムは、当然のことながら、洗濯機が空いたときに始まります。 乾燥機とフォルダーは常に時間内に利用できるため、この公式は洗濯機の制約に帰着します。 このアルゴリズムは、単純な単一マシンのパイプラインとまったく同じように動作し、正しいスケジュールを生成します。
