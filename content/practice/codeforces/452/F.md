 ## 解決策
 ## 問題の理解

 数字の順列が与えられます`1...n`。 2 つの異なる値の場合`a`そして`b`、彼らの平均は`(a+b)/2`。 順列にはすべての整数が 1 回だけ含まれるため、この平均も常に存在します。`a+b`は均等です。 

問題はペアが存在するかどうかです`a, b`そのため、それらの平均は順列順序でそれらの間のどこかに表示されます。 

より有用な再定式化は、値空間での算術数列を調べることです。 させて$$a = x-k,\qquad b = x+k.$$それから`x`まさにその平均です`a`そして`b`。 タスクは次のようになります。 

価値は存在するのか`x`そして距離`k > 0`の位置が`x`順列では、厳密に次の位置の間にあります。`x-k`そして`x+k`?

 順列のサイズは以下に達します`300000`。 すべてのペアまたはすべての等差数列を明示的にチェックするアルゴリズムは直ちに除外されます。 たとえ`O(n^2)`解決策には大まかに必要になります`9·10^{10}`限界をはるかに超えた最悪の場合の動作。 

難しいのは、条件に 2 つの異なる順序が混在していることです。 値は等差数列の順序で比較されますが、「間」とは順列内の位置を指します。 

順列を考慮してください```
1 5 2 4 3
```値`2`間にあります`1`そして`3`、したがって、答えは次のとおりです`YES`。 

ここで考えてみましょう```
1 3 4 2
```唯一可能な進歩のために`(1,2,3)`、値`2`の間にはない`1`そして`3`。 答えは`NO`。 

よくある間違いは、隣接する値のみ、または順列順序で長さ 3 の数列のみを検査することです。 等差数列は、隣接する位置ではなく、値自体に基づいて定義されます。 

## アプローチ

 ブルートフォースのアイデアは単純です。 考えられるすべての中心値に対して`x`、あらゆる距離を試してください`k`そのような`x-k`そして`x+k`中に残る`1...n`。 保存されているすべての値の位置を使用して、次の位置が正しいかどうかを確認できます。`x`2 つのエンドポイントの位置の間にあります。 

すべての有効な回答が 1 つの中心に正確に対応するため、これは正解です。`x`そして一つの距離`k`。 問題は走行時間です。 がある`Θ(n^2)`可能なペア`(x,k)`、これは大きすぎます`n = 300000`。 

重要な観察結果は、左から右への順列を処理すると現れます。 

現在 value にアクセスしているとします。`x`。 

すでに表示されているすべての値は左側にあります`x`順列の中で。 まだ見ていないすべての値は右側にあります`x`。 

値軸上のバイナリ配列を定義します。```
0 = already processed
1 = not processed yet
```到着したら`x`、価値の状態を変更します`x`から`1`に`0`。 

ここで、対称的な値のペアを見てみましょう。```
x-k , x+k
```それらの状態が異なる場合、一方はすでに処理されており、もう一方はまだ処理されていません。 つまり、1 つのエンドポイントが左側にあります。`x`そしてもう一つはその右側にあります`x`。 したがって、`x`は順列においてそれらの間にあり、有効な等差数列が見つかりました。 

So for every processed value`x`、バイナリシーケンスの周りにあるかどうかを知る必要があるだけです。`x`

```
[x-t ... x+t]
```と```
t = min(x-1, n-x)
```中心に対して対称です。 

シーケンスが完全に対称であれば、すべてのペアは`(x-k, x+k)`等しい状態を持っています。 

シーケンスが対称でない場合、一部のペアが異なる状態を持ち、有効な答えがすぐに得られます。 

範囲の対称性をチェックすることは、古典的なローリング ハッシュ タスクです。 フォワード ハッシュとリバース ハッシュの両方を格納するセグメント ツリーにバイナリ配列を維持します。 1 つの位置を更新した後、その位置の周囲の最大対称間隔をクエリします。`x`そして、その順方向ハッシュがその逆方向ハッシュと等しいかどうかをテストします。 

最初の非回文区間は、答えが次であることを証明します。`YES`。 すべての間隔が回文のままである場合、答えは次のようになります。`NO`。 これが意図したものです`O(n log n)`解決。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 最適 (セグメント ツリー + ハッシュ) | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 値に対するバイナリ配列を作成します`1...n`。 

最初はすべてのエントリが`1`、値がまだ順列に現れていないことを意味します。 
2. この配列にセグメント ツリーを構築します。 

各ノードは、セグメントの長さ、フォワード ローリング ハッシュ、およびリバース ローリング ハッシュを保存します。 
3. 左から右へ順列を処理します。 

値がいつ`x`訪問済み、位置を更新`x`からのセグメントツリー内`1`に`0`。 
4. しましょう$$t=\min(x-1,n-x).$$これは、両方が到達する最大距離です。`x-t`そして`x+t`存在する。 
5. 間隔を問い合わせる$$[x-t,\;x+t].$$順方向ハッシュと逆方向ハッシュを取得します。 
6. ハッシュが異なる場合、間隔は回文ではありません。 

すると、ある程度の距離が存在する`k`の状態が`x-k`そして`x+k`は異なります。 
7. 状態が異なるということは、一方のエンドポイントはすでに処理されており、もう一方はまだ処理されていないことを意味します。 

1 つのエンドポイントは左側にあります`x`順列内にあり、もう一方は右側にあります。 
8. 価値`x`は 2 つのエンドポイントの間にあるため、有効なペアが存在します。 

印刷する`"YES"`そしてやめてください。 
9. そのような間隔が見つからずにすべての値が処理された場合は、次のように出力します。`"NO"`。 

### なぜ効果があるのか

 現時点での価値`x`すべての値がマークされて処理されます`0`前に現れます`x`順列およびマークされたすべての値`1`後に表示されます`x`。 

あらゆる距離に対応`k`、ペア`(x-k, x+k)`状態が異なる場合に正確に有効な等差数列を提供します。 1 つのエンドポイントが前にあります`x`そしてもう一つはその後`x`、配置`x`彼らの間で。 

周囲の対称区間`x`すべての対称ペアが等しい状態を持つ場合に限り、 は回文になります。 非回文区間は、異なる状態を持つペアの存在と等価であり、これは、 を中心とする有効な等差数列の存在と等価です。`x`。 

アルゴリズムは、考えられるすべての中心値についてこの条件をチェックするため、答えが存在する場合は常に答えを見つけ、誤検知を報告することはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MASK = (1 << 64) - 1
BASE = 911382323

def solve():
    n = int(input())
    p = list(map(int, input().split()))

    powb = [1] * (n + 1)
    for i in range(1, n + 1):
        powb[i] = (powb[i - 1] * BASE) & MASK

    size = 1
    while size < n:
        size <<= 1

    seg_len = [0] * (2 * size)
    seg_f = [0] * (2 * size)
    seg_r = [0] * (2 * size)

    for i in range(size):
        idx = size + i
        seg_len[idx] = 1
        if i < n:
            seg_f[idx] = 1
            seg_r[idx] = 1

    for v in range(size - 1, 0, -1):
        l = v * 2
        r = l + 1

        len_l = seg_len[l]
        len_r = seg_len[r]

        seg_len[v] = len_l + len_r

        seg_f[v] = (
            seg_f[l] + (seg_f[r] * powb[len_l])
        ) & MASK

        seg_r[v] = (
            seg_r[r] + (seg_r[l] * powb[len_r])
        ) & MASK

    def update(pos):
        v = size + pos - 1
        seg_f[v] = 0
        seg_r[v] = 0

        v //= 2
        while v:
            l = v * 2
            r = l + 1

            len_l = seg_len[l]
            len_r = seg_len[r]

            seg_f[v] = (
                seg_f[l] + (seg_f[r] * powb[len_l])
            ) & MASK

            seg_r[v] = (
                seg_r[r] + (seg_r[l] * powb[len_r])
            ) & MASK

            v //= 2

    def combine(a, b):
        len_a, f_a, r_a = a
        len_b, f_b, r_b = b

        return (
            len_a + len_b,
            (f_a + f_b * powb[len_a]) & MASK,
            (r_b + r_a * powb[len_b]) & MASK,
        )

    def query(l, r):
        l = l + size - 1
        r = r + size - 1

        left = (0, 0, 0)
        right = (0, 0, 0)

        while l <= r:
            if l & 1:
                left = combine(left, (seg_len[l], seg_f[l], seg_r[l]))
                l += 1

            if not (r & 1):
                right = combine((seg_len[r], seg_f[r], seg_r[r]), right)
                r -= 1

            l //= 2
            r //= 2

        return combine(left, right)

    for x in p:
        update(x)

        t = min(x - 1, n - x)
        if t == 0:
            continue

        length, fh, rh = query(x - t, x + t)

        if fh != rh:
            print("YES")
            return

    print("NO")

solve()
```セグメント ツリーには、両方向の間隔ごとにローリング ハッシュが格納されます。 範囲クエリは、要求された間隔の順方向ハッシュと逆方向ハッシュを返します。 等しいということは、間隔が回文であることを意味します。 

更新操作では、単一の値が次から変更されます。`1`に`0`。 これは、値を「未確認」セットから「処理済み」セットに移動することに正確に対応します。 

周囲の最大対称区間`x`可能なすべてのペアがあるため使用されます`(x-k, x+k)`検査する必要があります。 その間隔内のどこかに不一致があると、必要な等差数列が生成されます。 

微妙な点は、操作の順序です。 更新しなければなりません`x`間隔を確認する前に。 チェックの瞬間、`x`それ自体は処理される側に属し、すべての`0`は、現在位置以降に出現する値に対応します。 

64 ビット ハッシュを使用すると、実装がコンパクトかつ高速に保たれます。 理論的には衝突が発生する可能性がありますが、競技プログラミングでは実際には衝突は無視できます。

import io

def run(inp: str) -> str:

    BASE = 911382323

    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n = int(input())
    p = list(map(int, input().split()))

    powb = [1] * (n + 1)
    for i in range(1, n + 1):
        powb[i] = (powb[i - 1] * BASE) & MASK

    size = 1
    while size < n:
        size <<= 1

    seg_len = [0] * (2 * size)
    seg_f = [0] * (2 * size)
    seg_r = [0] * (2 * size)

    for i in range(size):
        idx = size + i
        seg_len[idx] = 1
        if i < n:
            seg_f[idx] = 1
            seg_r[idx] = 1

    for v in range(size - 1, 0, -1):
        l = v * 2
        r = l + 1
        seg_len[v] = seg_len[l] + seg_len[r]
        seg_f[v] = (seg_f[l] + seg_f[r] * powb[seg_len[l]]) & MASK
        seg_r[v] = (seg_r[r] + seg_r[l] * powb[seg_len[r]]) & MASK

    def update(pos):
        v = size + pos - 1
        seg_f[v] = seg_r[v] = 0
        v //= 2
        while v:
            l = v * 2
            r = l + 1
            seg_f[v] = (seg_f[l] + seg_f[r] * powb[seg_len[l]]) & MASK
            seg_r[v] = (seg_r[r] + seg_r[l] * powb[seg_len[r]]) & MASK
            v //= 2

    def combine(a, b):
        la, fa, ra = a
        lb, fb, rb = b
        return (
            la + lb,
            (fa + fb * powb[la]) & MASK,
            (rb + ra * powb[lb]) & MASK,

        r = r + size - 1
        left = (0, 0, 0)
        right = (0, 0, 0)

        if t:

            if fh != rh:

 ## 特殊なケース

 可能な最小の入力を考えてみましょう。```
1
1
```異なる値のペアは存在しません。 アルゴリズムは 1 回の更新を実行し、`t = 0`、範囲をクエリすることはなく、正しく出力されます。`NO`。 

考慮する```
3
1 3 2
```値の唯一の等差数列は次のとおりです。`(1,2,3)`。 加工後`2`、 両方`1`そして`3`はすでに見られているので、それらの状態は等しいです。 間隔`[1,3]`は回文であり、アルゴリズムの出力`NO`。 

考慮する```
3
1 2 3
```いつ`2`処理される、値`1`状態があります`0`そして価値観`3`状態があります`1`。 間隔`[1,3]`非回文になります。 アルゴリズムは即座にレポートします`YES`、という事実と一致します`2`間にあります`1`そして`3`。 

最後に、値などの境界近くの中心を考慮します。`1`または値`n`。 それから`t = 0`, したがって、有効な対称ペアは存在しません。 このアルゴリズムはクエリを完全にスキップし、off-by-one エラーを回避し、値範囲の端を正しく処理します。
