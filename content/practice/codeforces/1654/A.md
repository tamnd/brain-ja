 ## 解決策
 ## 問題の理解

 私たちに与えられた一行は、$n$それぞれに重みのあるケーキ$a_i$。 ケーキのおいしさは、隣接する 2 つのケーキの合計として定義されます。 ケーキの **連続する 1 つのサブセグメント**を最大 1 回反転して、美味しさを測定することができます。 この作業後の美味しさを最大限に引き出すことが私たちの目標です。 

入力は複数のテスト ケースで構成されます。 テスト ケースごとに、ピースの数と重量が与えられます。 出力は、最大 1 回の反転後に達成できる最大の美味しさです。 

制約は中程度です。$n$まで行くことができます$1000$、最大で$50$テストケース。 これにより、おおよそのアルゴリズムが可能になります。$O(n^2)$テストケースごと、でも何でも$O(n^3)$遅すぎるでしょう。 注意すべきエッジ ケースには、サイズ 2 の非常に小さい配列、すべての要素が等しい配列、またはすでに厳密に降順または昇順になっている配列が含まれます。 たとえば、次の場合$a = [1, 100, 1]$、大きな塊を反転することのみを考慮した単純なアプローチでは、中間の 2 つの要素を反転することでおいしさが最大化されるということを見逃してしまう可能性があります。$100 + 1 = 101$。 

## アプローチ

 ブルートフォースアプローチはシンプルです: 可能なすべてのサブセグメントを試します$[l, r]$、それを逆にして、最大隣接合計を計算します。 これが機能するのは、配列の長さが十分に小さいことがわかっているためです。$O(n^3)$理論的には正しいですが、実際には次のことが含まれます。$n^3/2$操作の上限付近でタイムアウトになる可能性があります。$n = 1000$。 

重要な洞察は、逆転によって実際に何が変わるかを分析することから得られます。 **反転されたセグメントのエッジ**を含む合計、または配列の境界での合計のみが変更されます。 より具体的には、配列の中央を反転しても、反転されたサブセグメントの最初と最後の要素を除き、配列の外側のペアには影響しません。 これにより、問題が大幅に軽減されます。プレフィックス、サフィックスを反転するか、隣接するペアを交換することのみを考慮する必要があります。これより複雑な反転では、最大値と 2 番目に大きい隣接する数値を交換する以上に最大値を増やすことはできないためです。 

したがって、最適なアプローチは、元の配列の最大隣接合計を計算し、改善のための 3 つの候補を考慮することです。 

1. 最初の要素を他の要素と交換します (接頭辞を逆にします)。 
2. 最後の要素を他の要素と交換します (サフィックスを逆にします)。 
3. 最初の 2 つまたは最後の 2 つの要素を交換します (エッジ反転)。 

これらの可能性を確認することは直線的であり、$O(n)$配列のエンドポイントまたはペアに関係する合計のみを計算するため、テスト ケースごとに異なります。 この洞察により、$O(n^2)$サブセグメント全体の反転。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^3) | O(n) | n = 1000 では遅すぎます |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る$t$。 テスト ケースごとに、次の内容を読んでください。$n$そして配列$a$。 
2.初期化`max_tastiness`ゼロに。 配列を反復処理して、現在の最大隣接合計を計算します。$i$から$0$に$n-2$、 アップデート`max_tastiness = max(max_tastiness, a[i] + a[i+1])`。 
3. **プレフィックス**を逆転することを検討してください: それぞれ$i$から$1$に$n-1$、計算する`a[0] + a[i]`そして更新します`max_tastiness`。 これは逆転をシミュレートします$[0, i]`, bringing $a[i]$ next to $a[0]`。 
4. **サフィックス**を逆転することを検討してください: それぞれ$i$から$0$に$n-2$、計算する`a[n-1] + a[i]`そして更新します`max_tastiness`。 これは $[i, n-1]` の反転をシミュレートします。 
5. 印刷`max_tastiness`現在のテストケースの場合。 

ステップ 3 と 4 で十分である理由は、最初と最後の要素だけが以前は隣接していなかった大きな数値と「出会う」ことができるため、中央でこれ以上反転しても、最大の数値をエッジに移動することによって達成できる値よりも大きな新しい最大合計が作成されないためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    
    max_tastiness = 0
    # original adjacent sums
    for i in range(n - 1):
        max_tastiness = max(max_tastiness, a[i] + a[i+1])
    
    # consider prefix reversals (first element + any other)
    for i in range(1, n):
        max_tastiness = max(max_tastiness, a[0] + a[i])
    
    # consider suffix reversals (last element + any other)
    for i in range(n - 1):
        max_tastiness = max(max_tastiness, a[-1] + a[i])
    
    print(max_tastiness)
```コードはまず、既存の隣接する合計の最大値を計算します。 次に、最初または最後の要素を他のすべての可能な位置に移動することを評価し、影響を与える可能性のあるすべての逆転をシミュレートします。 サフィックスとプレフィックスの合計を計算するときに、最初と最後の要素が二重にカウントされないよう注意が必要です。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        max_tastiness = 0
        for i in range(n - 1):
            max_tastiness = max(max_tastiness, a[i] + a[i+1])
        for i in range(1, n):
            max_tastiness = max(max_tastiness, a[0] + a[i])
        for i in range(n - 1):
            max_tastiness = max(max_tastiness, a[-1] + a[i])
        print(max_tastiness)
    return out.getvalue().strip()
