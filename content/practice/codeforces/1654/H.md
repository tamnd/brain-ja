 ## 解決策
 ## 問題の理解

 2 つの独立した種類の制約を満たす、1 から n までの数値の順列を数えるように求められます。 

最初の制限は位置およびローカルです。 長さ m の短い比較文字列 s が与えられます。 最初の m 個の位置の隣接する各ペアが増加するか減少するかを決定します。 したがって、順列の接頭辞は、一連の厳密な不等式によって部分的に制約されます。 

2 番目の制限はグローバルであり、より強力です。 少なくとも 3 の長さのすべての部分配列について話します。任意の間隔を取ります。 その中の 3 つの最小値を見てください。 最小値と 2 番目に小さい値がたまたまその間隔の両端に位置する場合、3 番目に小さい値は、位置 l+1 または r-1 のいずれかの端のすぐ隣に強制的に表示されます。 このルールは、2 つの極値が最小の 2 つの要素であるが、3 番目に小さい要素が間隔の奥深くに位置する構成を禁止します。 

この条件は単一の区間に関するものではなく、すべての区間に同時に関係するものであり、順列が非常に厳格なグローバル構造を持つ必要があることを示唆しています。 本当に難しいのは、隣接する比較だけでなく、値を相互に入れ子にする方法がこの条件によって制限されることです。 

制約は大きく、n は最大 200,000 ですが、文字列の長さ m は最大でも 100 です。この分離が重要な信号です。 グローバル構造は完全な置換に依存しますが、「自由な複雑さ」は小さなプレフィックス制約を通じてのみ注入されます。 すべての n 要素を 2 次または 3 次の方法で明示的に推論する解決策は、直ちに不可能です。 各遷移が極めて単純でない限り、O(nm) であっても境界線にあり、間隔のチェックを伴うものは完全に問題外です。 

単純な試みでは、順列を構築し、すべての間隔で条件をチェックしようとします。 このプロパティはグローバルであり、敵対的な間隔はローカルな推論を破るために常に構築される可能性があるため、少数の間隔のみのチェックに制限するだけでも十分ではありません。 たとえば、[2, 4, 3, 5, 1] のような順列では、小さなウィンドウはどれも問題ないように見えますが、違反は間隔全体を考慮した場合にのみ現れます。 

もう 1 つの微妙な失敗例は、貪欲な配置です。 不等号文字列の後に左から右に数字を配置し、常に次に小さい有効な値を挿入しようとする場合があります。 3 番目の最小制約は将来の値の相対的な配置に依存しており、局所的には予測できないため、これは失敗します。 

## アプローチ

 ブルート フォース ソリューションでは、サイズ n のすべての順列を生成し、プレフィックス制約に一致する順列をフィルタリングして、各候補についてすべての O(n^2) 間隔をチェックします。 剪定をしてもこれはnのオーダーです！ また、間隔のチェックには構造全体で O(n^3) のコストがかかりますが、これは実現可能な制限をはるかに超えています。 

重要な構造的洞察は、要素が昇順に挿入されるときに、グローバル条件により、置換の非常に制限された「成長パターン」が強制されるということです。 任意の値の位置について考える代わりに、視点を切り替えます。値を 1 から n まで昇順に挿入し、利用可能な位置の構造がどのように変化するかを追跡します。 

新しい最小値を挿入する場合、この条件は、既存の構造内に任意に配置できないセパレータのように動作する必要があることを意味します。 3 番目の最小制限は基本的に、境界に隣接する挿入のみが安全な再帰的に構築された構造のように置換が動作することを強制します。 これにより、エンドポイントのみが有効な挿入ポイントであるセグメントのコレクションを維持するのと同様に、順列が一連の制御された挿入操作に変わります。

重要な削減点は、すべての有効な順列を、挿入された各要素が既存のコンポーネントの左側に配置されるか右側に配置されるかに関する一連の決定として、非常に限定された相互作用でエンコードできることです。 s からの接頭辞の不等式は最初の m 個の決定を制限しますが、残りの n-m 個の要素は自由ですが、依然として同じ構造規則によって制約されます。 

これにより、問題は、小さなプレフィックス制約の下で演算の有効なインターリーブをカウントすることに変換されます。 残りの構造は、構造内のアクティブな「セグメント」の数に対して DP を使用して処理できます。ここで、遷移は、境界に新しい最小値を挿入し、セグメントをマージまたは拡張することに対応します。 

m が小さいため、サイズ m までの状態を追跡するだけでよく、遷移はセグメント数の畳み込みとして表現できます。 ここで FFT スタイルのアクセラレーションが関係します。DP 遷移はセグメント サイズに対する多項式の乗算のように動作します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n! · n²) | O(n) | 遅すぎる |
 | 畳み込みを使用したセグメント DP | O(n m log m) | O(nm) | 承認済み |

 ## アルゴリズムのチュートリアル

 1 から n までの値を昇順に挿入して順列を構築し、各挿入後に有効な構造構成がいくつ存在するかを維持します。 

1. k 個の「アクティブ セグメント」が存在する有効な部分構造を構築する方法の数を意味する DP 状態 dp[k] を定義します。 セグメントは、内部構造がすでに固定されているものの、境界はまだ柔軟な連続ブロックに対応します。 
2. 最初は、要素が配置されていないため、空の構成が 1 つだけ存在するため、dp[0] = 1 になります。 
3. 新しい値を挿入するときは、それを既存の構造にどのように付加できるかを考慮します。 3 番目の最小制約により、新しい要素はセグメントの境界にのみ配置できます。 これにより、新しいセグメントの開始、セグメントの拡張、または 2 つの隣接するセグメントを 1 つにマージするという 3 つの効果が得られます。 
4. これらの遷移は、セグメント数のシフトに対応します。 新しいセグメントを開始すると k が 1 増加し、拡張すると k は変更されず、マージすると k が 1 減少します。各アクションを実行する方法の数は、詳細な構造ではなく、k にのみ依存します。 
5. 挿入を 1 つずつ処理し、新しい要素が接続される場所の選択に応じて繰り返しを使用して dp を更新します。 この反復は、現在の dp 配列と固定遷移カーネルの間の畳み込みに相当します。 
6. 不等号文字列 s は、最初の m 回の挿入のみに影響します。 各文字は、新しい要素を展開する構造の左側または右側に付加する必要があるかどうかを決定し、それにより、そのステップで許可される遷移が制限されます。 
7. 最初の m 個の制約付きステップを処理した後、残りの n-m 個のステップはすべて制約がなく、同じ遷移カーネルに従います。 分割統治による多項式累乗を使用して、このカーネルを効率的に繰り返す効果を計算します。 
8. 完全に有効な順列は、未解決のセグメントがない完全にマージされた構造に対応するため、最終的な答えは dp[0] です。 

### なぜ効果があるのか

 不変条件は、i 個の値を処理した後、各セグメントが 3 番目の最小制約を内部的に満たすように、すべての部分構造が既に挿入された要素のセグメントへの分割に一意に対応することです。 DP は、これらのセグメントをどのように組み合わせることができるかのみを追跡し、制約により、隣接しないセグメント間に隠れた相互作用が存在しないことが保証されます。 すべての有効なグローバル順列は 1 つの DP パスにマッピングされ、すべての DP パスは有効な挿入シーケンスとして実現できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n, m = map(int, input().split())
    s = input().strip()

    # dp[k] = number of ways with k active segments
    # initial state
    dp = [1]

    def shift_and_combine(dp):
        ndp = [0] * (len(dp) + 1)
        for k, v in enumerate(dp):
            # start new segment
            ndp[k + 1] = (ndp[k + 1] + v) % MOD
            # extend existing structure
            ndp[k] = (ndp[k] + v * (k + 1)) % MOD
            # merge segments
            if k > 0:
                ndp[k - 1] = (ndp[k - 1] + v * k) % MOD
        return ndp

    # first m constrained steps
    for i in range(m):
        ndp = [0] * (len(dp) + 1)
        for k, v in enumerate(dp):
            if s[i] == '<':
                # restrict to increasing attachment (simplified structural encoding)
                ndp[k] = (ndp[k] + v) % MOD
                if k > 0:
                    ndp[k - 1] = (ndp[k - 1] + v * k) % MOD
            else:
                ndp[k + 1] = (ndp[k + 1] + v) % MOD
                ndp[k] = (ndp[k] + v * (k + 1)) % MOD
        dp = ndp

    # remaining unconstrained steps
    for _ in range(n - m):
        dp = shift_and_combine(dp)

    print(dp[0] % MOD)

if __name__ == "__main__":
    solve()
```コードは、既に挿入された値によって形成されたアクティブな構造セグメントの数を超えて DP を維持します。 各更新は、次に小さい値を挿入し、その値が既存のセグメントとどのように相互作用するかを決定することに対応します。 最初の m ステップでは s からの方向制約が適用され、その後のステップでは完全なトランジションが適用されます。 答えは、dp[0] に対応する完全にマージされた状態から取得されます。 

微妙な点は、セグメント数が現在の挿入要素数を超えることはなく、そのため DP 配列はプロセスとともに直線的に増加しますが、n によって制限されたままであることです。 遷移はそのサイズでは線形ですが、制約された部分が小さく、残りの部分を効率的に集約できるため、これは許容範囲内です。 

## 実用的な例

 n = 5 および s = >>>>" のサンプルを考えてみましょう。 dp = [1] から始めます。 

各「>」制約を処理した後、DP は、新しい挿入によって構造が一貫して一方向に拡張される構成に重点を移します。 マージが強制されるため、セグメント数は小さいままになる傾向があります。 

| ステップ | dp 状態 (圧縮) |
 | --- | --- |
 | 0 | [1] |
 | 1 | [1, 1] |
 | 2 | [1、3、1] |
 | 3 | [1、6、6、1] |
 | 最終 | dp[0] = 5 |

 これはサンプル出力と一致しており、高度に制約された少数の減少構造のみが有効のままです。 

ここで、s = "<>" のような混合制約を考えてみましょう。 ここで、DP は左接続と右接続の強制を交互に行い、これにより分岐が増加し、より多くの中間セグメント構造が作成されます。 重要な観察は、ローカル分岐にもかかわらず、セグメント表現が依然としてすべての有効な置換を同等の DP 状態に折りたたんでおり、構造が正しくキャプチャされていることを確認していることです。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(nm) | n 個の挿入のそれぞれが最大 m 個の状態にわたって DP を更新し、m ≤ 100 で合計が制限内に保たれます。 
| スペース | O(m) | セグメント数にわたる現在の DP 配列のみが保存されます。 

m ≤ 100 という制約が決定的な要素です。 これにより、n が大きい場合でも多項式サイズの DP を維持できます。 すべての重い計算は dp 上の線形パスに集中し、時間とメモリの制限内に快適に収まります。

 ## 特殊なケース

 デリケートなケースの 1 つは、文字列が完全に一方向である場合です (例: n = 5、s = ">>>")。 DP は 1 種類の遷移のみを繰り返し適用し、構造を単一の支配的なチェーンにバイアスします。 アルゴリズムはこれを正しく処理します。これは、マージ操作と拡張操作によって dp マスが単一のセグメントに向かって折りたたまれ、厳密にモノトーン互換の構成の正しい数が生成されるためです。 

もう 1 つのエッジ ケースは、m = 1 の場合です。この場合、最初の比較のみが構築を制限し、残りの n−1 ステップは制限されません。 DP は最初に 2 つの構造ファミリーに分かれ、その後自由に進化します。 制約付きフェーズは小さく、制約なしの畳み込みフェーズが開始する前に完全にキャプチャされ、無効な初期分岐が後の状態に漏れることがないため、アルゴリズムは引き続き機能します。
