 ## 解決策
 ## 問題の理解

 最終的な重みが与えられます。`n`ケーキのかけら。 これらのピースは、重さのピースを繰り返し選択することによって、単一の初期ケーキから製造されました。`w`そしてそれを 2 つの部分に分割します。 

-`floor(w / 2)`-`ceil(w / 2)`その通り`n - 1`このようなカットが実行された結果、`n`最後の部分。 最後のピースの順序は関係ありません。 

タスクは、指定された配列が一連の有効な分割の結果であるかどうかを判断することです。 

有益な観察は、ケーキの初期重量が明示的に与えられていないが、強制されているということです。 すべての分割では合計重量が保持されるため、開始重量は最終的なすべての部分の合計と等しくなければなりません。 

制約は大きいです。 すべてのテスト ケースにわたって、ピースの合計数は最大で`2 · 10^5`。 考えられるすべてのカット注文をシミュレートしようとするアルゴリズムは指数関数的に爆発的に増加します。 たとえ`O(n²)`このアプローチは、最悪の場合、費用がかかりすぎる可能性があります。 に近いものが必要です`O(n log n)`。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

考慮する：```
1
3
2 3 3
```合計金額は`8`。 から始まる`8`、最初に可能な分割は次のとおりです。`4 + 4`。 プロセスを継続しても正確な結果が得られることはありません`{2,3,3}`。 正しい答えは、`NO`。 

もう 1 つの重要なケースは次のとおりです。```
1
6
1 1 1 1 1 1
```答えは`YES`。 すべての最終ピースは`1`, 6 つの部分が表示されるまで、より大きな部分を繰り返し分割できます。 多数の同一の値が検出されるたびに停止するソリューションは、このケースを誤って拒否する可能性があります。 

3 番目の微妙な例は次のとおりです。```
1
2
869 541
```合計金額は`1410`。 最初の分割は次のようにする必要があります`705 + 705`。 どちらの側も等しくありません`869`または`541`、さらに分割すると断片が小さくなるだけです。 正しい答えは、`NO`。 

重要な課題は、一連の合法的な分割によってターゲットの重みの複数セットを正確に生成できるかどうかを判断することです。 

## アプローチ

 ブルート フォース アプローチでは、総和から開始し、考えられるすべての分割シーケンスを再帰的に試行し、結果として得られるリーフ セットの 1 つがターゲット マルチセットと等しいかどうかを確認します。 

これは、文字通りすべての有効な構造を調査するため、正しいです。 残念なことに、可能な分割ツリーの数は指数関数的に増加します。 数十個のピース​​であっても検索は不可能になりますが、この問題により、最大で`2 · 10^5`個。 

操作の構造は、プロセスを逆に見ることを示唆しています。 

初期ケーキから目標のピースを製造できるかどうかを尋ねる代わりに、すべての目標値の単純な合計である初期ケーキの重量から始めるとします。 ピースが目的の値のいずれかに一致するたびに、それを「消費」し、そのブランチの分割を停止できます。 

ピースが残りのターゲット値と一致しない場合、フォワード プロセスで発生する可能性がある唯一のことは、このピースがさらに分割されることです。 分割は完全に決定されているため、続行方法が正確にわかります。```
w -> floor(w/2), ceil(w/2)
```これは貪欲な戦略につながります。 常に現在利用可能な最大の部分を選択してください。 必要な値と一致する場合は、その要件を削除します。 それ以外の場合は、それを 2 つの子に分割します。 

なぜ最大の部分を取ることに意味があるのでしょうか? 分割は重みを減らすだけであるため、現在利用可能な最大部分よりも大きなターゲット値を後で生成することはできません。 できるだけ早く大きな値を一致させると、不必要な分割による無駄が回避されます。 

両方のマルチセットを降順で保存できます。 1 つのマルチセットにはターゲット値が含まれます。 もう 1 つは、プロセスを逆に行っている間に現在利用可能なピースが含まれています。 

利用可能な最大の部分が必要な最大の値と等しい場合は常に、それらが一致します。 それ以外の場合は、利用可能な部分を分割します。 

有用な剪定ルールが自然に現れます。 利用可能な最大の部分が必要な最大のターゲットよりも小さくなった場合、将来の分割では値がさらに減少するだけであるため、成功は不可能です。

 ## アルゴリズムのチュートリアル

 1. ターゲット配列の合計を計算します。 これが唯一可能な初期ケーキ重量です。 
2. すべてのターゲット値を max-struct に保存します。 Python では、負の値を使用して最大ヒープをシミュレートできます。 
3. 合計のみを含む別の最大ヒープを作成します。 
4. 両方のヒープが空でない間に、この手順を繰り返します。 
5. しましょう`x`現在入手可能な最大の作品であること、および`y`一致しない最大のターゲット値になります。 
6. もし`x == y`、両方を削除します。 これは、ターゲット マルチセットの最後の部分を 1 つ特定することに成功したことを意味します。 
7. もし`x < y`、すぐに戻ります`NO`。 利用可能な最大のピースはすでに小さすぎるため、将来の分割ではピースをさらに小さくすることしかできません。 
8. もし`x > y`、 スプリット`x`の中へ：```
floor(x/2)
ceil(x/2)
```そして、両方のピースを利用可能なピースのヒープに挿入して戻します。 
9. もし`x == 1`そして`x > y`、 戻る`NO`。 重さの一部`1`それ以上分割することはできません。 
10. プロセスが完了したら、戻ります`YES`すべてのターゲット値が一致した場合、それ以外の場合は戻ります`NO`。 

### なぜ効果があるのか

 不変条件は、利用可能なピースのヒープが常に、合計から始まる有効な切断プロセスの中間段階に存在する可能性のあるピースのセットを表すということです。 

利用可能な最大のピースが残りの最大のターゲット値と等しい場合、そのピースは、成功した構築において最終的には変更されていないように見える必要があります。 それを維持し、そのブランチでのさらなる分割を停止しても、有効なソリューションに悪影響を与えることはできません。 

利用可能な最大の部分が必要な最大値よりも大きい場合、その部分は残りのターゲット値に直接対応できないため、有効な構成ごとに分割する必要があります。 分割は一意に決定され、代替の選択肢はありません。 

利用可能な最大のピースが必要な最大のターゲットよりも小さくなると、今後の操作でその重みを増やすことはできません。 必要な値に達することは不可能なので、拒否が正しいです。 

これらの観察により、貪欲なプロセスのすべてのステップが強制されます。これは、アルゴリズムが、合法的なカットによって生成されるマルチセットを正確に受け入れることを意味します。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    t = int(input())

    answers = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        need = [-x for x in a]
        heapq.heapify(need)

        pieces = [-sum(a)]

        possible = True

        while need:
            if not pieces:
                possible = False
                break

            x = -heapq.heappop(pieces)
            y = -need[0]

            if x == y:
                heapq.heappop(need)
                continue

            if x < y:
                possible = False
                break

            if x == 1:
                possible = False
                break

            left = x // 2
            right = x - left

            heapq.heappush(pieces, -left)
            heapq.heappush(pieces, -right)

            if len(pieces) > len(need):
                possible = False
                break

        answers.append("YES" if possible else "NO")

    sys.stdout.write("\n".join(answers))

if __name__ == "__main__":
    solve()
```最初のヒープには、一致させる必要があるすべてのターゲット値が格納されます。 2 番目のヒープには、構築プロセスを逆にしながら、現在利用可能なピースが格納されます。 

このアルゴリズムは、各ヒープの最大要素を繰り返し比較します。 それらが等しい場合、最後のピースが 1 つ見つかったことになり、それを検討から削除します。 

利用可能な部分が大きい場合は、唯一の正当な逆アクションを実行し、順方向プロセスで生成された可能性のある 2 つの部分に分割します。 

条件`x == 1`重要です。 重さ`1`それ以上分割することはできないため、それでも必要な値と一致しない場合、インスタンスは不可能です。 

小切手```
if len(pieces) > len(need):
```多くの受け入れられているソリューションで使用されている便利な最適化です。 残りのターゲット ピースよりも利用可能なピースが多くなると、完全に一致してもピースを結合し直すことができないため、成功は不可能になります。 

Python の整数は、合計の最大重みが最大でも次のとおりであるため、すべての合計を簡単に処理できます。```
2 · 10^5 × 10^9 = 2 · 10^14
```これは、Python の任意精度の整数に快適に適合します。
