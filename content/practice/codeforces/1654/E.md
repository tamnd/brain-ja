 ## 解決策
 ## 問題の理解

 最終的な配列が等差数列になるように、変更する配列要素をできるだけ少なくしたいと考えています。 

等差数列は、最初の値と共通の差という 2 つのパラメータによって完全に決定されます。 進行状況を次のように書くと$$a_i = b + d \cdot i$$この場合、すでにこの式を満たしているすべての位置は変更しないで済みますが、この式を満たしていないすべての位置は変更する必要があります。 

これにより、問題は最大化問題に変わります。 変更の数を直接最小化する代わりに、最大数の位置に既に一致する等差数列を探します。 その進行が一致する場合$k$ポジション、次に残り$n-k$位置を変更する必要があります。 

配列の長さは次のとおりです$10^5$、これに近いものは直ちに除外されます。$O(n^2)$。 二次アルゴリズムはおおよそのパフォーマンスを発揮します$10^{10}$限界をはるかに超えた操作。 周りに何かが必要です$O(n\sqrt n)$または$O(n \log n)$。 

いくつかの特殊なケースでは、素朴な推論が危険になります。 

考慮する```
3
5 5 5
```配列はすでに共通の違いを持つ等差数列です$0$。 答えは$0$。 ゼロ以外の差を調べるだけの解決策はここで失敗します。 

考慮する```
4
1 100000 1 100000
```最適な進行には、非常に大きな正または負の共通差が含まれる場合があります。 検索を小さな差異に限定すると、有効な答えが見つかりません。 

考慮する```
1
42
```単一の要素は常に等差数列になります。 答えは次のとおりです。$0$。 

最も微妙な問題は値の境界に起因します。 すべての元の値は次の間にあります。$1$そして$100000$ただし、ターゲットの進行には負の数値または より大きい値が含まれる場合があります。$100000$。 ソリューションでは、最終的な進行の範囲ではなく、どの既存の点が進行上に既に存在するかについてのみ推論する必要があります。 

## アプローチ

 便利な幾何学的ビューは、すべての配列要素を点として扱うことです。$(i,a_i)$。 

等差数列の形式は次のとおりです。$$a_i=b+d\,i$$これはまさに直線の方程式です。 問題は次のようになります。 

最大数の点を通過する線を見つけます$(i,a_i)$。 

行に次の内容が含まれている場合$k$ポイント、それら$k$位置は、その線で表される進行とすでに一致しています。 

ブルートフォースのアイデアは単純です。 すべての点のペアを選択し、それらを通る一意の線を決定し、その線上にある点の数を数えます。 最良の行が答えを示します。 

すべての等差数列は 1 つの直線に対応し、すべての直線は 2 つの点によって決定されるため、これは正しいです。 

問題はコストです。 がある$O(n^2)$ペアになり、それらを保存したり数えたりすることさえ不可能になります。$n=10^5$。 

重要な観察は境界から得られます$a_i \le 100000$。 

させて$B \approx \sqrt{100000}$、 について$320$。 

共通の違いを分割します$d$2つのカテゴリーに分けられます。 

小さな坂道の場合は、$|d| \le B$、くらいしかありません。$2B+1$可能な値。 固定の場合$d$、$$a_i = b + d i$$暗示する$$b = a_i - d i.$$すべてのポイントは同じ進行上にありますが、違いがあります$d$同じ値を持っています$a_i-di$。 の頻度を数えることができます$a_i-di$あらゆる小さなことに対して$d$。 

大きな斜面の場合は、$|d| > B$、何か特別なことが起こります。 元の値はすべてそこにあるため、$[1,100000]$、$$|a_j-a_i| \le 100000.$$2 つの点が次の数列に属している場合$|d|>B$、 それから$$|j-i| \le \frac{100000}{|d|} < \frac{100000}{B}.$$選択する$B \approx \sqrt{100000}$この距離は最大でも約$320$。 

したがって、大きな勾配の数列に属するすべての点のペアは、インデックスが近くなければなりません。 長さの短いウィンドウを検査するだけで済みます$B$各ポジションの前にあります。 

これにより、問題は次のように変換されます。$O(nB)$十分に高速なソリューションです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^2)$それより悪い |$O(n^2)$| 遅すぎる |
 | 最適 |$O(n\sqrt A)$、 どこ$A=100000$|$O(\sqrt A)$平均ハッシュ使用量 | 承認済み |

 ## アルゴリズムのチュートリアル

 1. しましょう$B=\lfloor\sqrt{100000}\rfloor+1$。 
2. メンテナンス`best`、共通の等差数列上に既に存在する位置の最大数。 
3. 小さな違いをすべて処理する$|d|\le B$。 

各整数について$d$その範囲で計算します$$a_i-di$$あらゆるポジションに対して$i$。 

共通の違いがある同じ進行に属するポジション$d$同じ値を生成します。 ハッシュマップで頻度をカウントし更新する`best`。 
4. 大きな差異をすべて処理する$|d|>B$。 

開始インデックスごとに$i$、位置のみを調べます$$j=i+1,\dots,\min(n-1,i+B).$$両方を含む有効な大きな勾配進行$i$そして$j$満たさなければなりません$$a_j-a_i=d(j-i).$$もし$(a_j-a_i)$で割り切れます$(j-i)$、整数の傾きを計算します$$d=\frac{a_j-a_i}{j-i}.$$5. 傾斜を無視する$|d|\le B$、すでに処理されているためです。 
6. 残りの斜面について、同じものを生成する近くの点がいくつあるかを数えます。$d$固定開始インデックスを使用した場合$i$。 

坂道が出てきたら$c$回の場合、対応する行には以下が含まれます$c+1$ポイントを含む$i$。 

アップデート`best`。 
7. 答えは次のとおりです。$$n-\text{best}.$$### なぜ効果があるのか

 すべての等差数列は直線に対応します$a_i=b+di$。 

小さな傾斜フェーズでは、考えられるすべての傾斜を明示的にチェックします。$|d|\le B$。 固定勾配の場合、点が同じ切片値を共有する場合、点は正確に同じ累進線上にあります。$a_i-di$したがって、頻度カウントにより、一致する位置の正確な数が得られます。 

大きな傾斜の場合、値の境界により、一致する 2 つの点がインデックス内で近くなるように強制されます。 可能な最大インデックス ギャップは次の値より小さいです$100000/B$、最大でも$B$。 したがって、大きな勾配の進行に属する点のすべてのペアがローカル ウィンドウ内で検出されます。 その数列上の最小のインデックスを処理するとき、数列上の他のすべての点は同じ傾きに寄与します。$d$、カウントは進行の正確なサイズを回復します。 

考えられるすべての進行は傾きが小さいか傾きが大きいカテゴリに分類されるため、アルゴリズムは変化しない位置の最大数を見つけます。 変更の最小数は、その最大数の補数になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    if n <= 2:
        print(0)
        return

    MAX_A = 100000
    B = int(MAX_A ** 0.5) + 1

    best = 1

    # Small slopes: |d| <= B
    for d in range(-B, B + 1):
        freq = {}
        cur_best = 0

        for i, x in enumerate(a):
            key = x - d * i
            val = freq.get(key, 0) + 1
            freq[key] = val
            if val > cur_best:
                cur_best = val

        if cur_best > best:
            best = cur_best

    # Large slopes: |d| > B
    for i in range(n):
        cnt = {}

        limit = min(n, i + B + 1)

        for j in range(i + 1, limit):
            diff = a[j] - a[i]
            dist = j - i

            if diff % dist != 0:
                continue

            d = diff // dist

            if -B <= d <= B:
                continue

            cnt[d] = cnt.get(d, 0) + 1

        for c in cnt.values():
            if c + 1 > best:
                best = c + 1

    print(n - best)

if __name__ == "__main__":
    solve()
```最初のフェーズでは、小さな共通の違いをすべて列挙します。 それぞれの数量は、`a[i] - d * i`線の切片として機能します。 切片が等しいということは、対応する点がすでに同じ等差数列上にあることを意味します。 

第 2 フェーズでは、値の限界が活用されます。 固定位置の場合`i`、次だけ`B`インデックスを検査する必要があります。 元の値は幅の範囲に制限されているため、より大きな勾配を持つ進行はそれ以上伸びることができません。`100000`。 

よくある実装上の間違いは、Python では 0 ベースのインデックスが使用されるのに対し、数学的導出のインデックスは 1 ベースであることを忘れることです。 表現`a[i] - d * i`すべてのインデックスを定数で変更することは切片をシフトするだけであり、等価性には影響しないため、0 ベースのインデックス付けでは完全に機能します。 

もう 1 つの簡単な間違いは、大きな傾斜をグローバルに数えることです。 ハッシュ マップは開始インデックスごとに再構築する必要があります`i`。 そうしないと、同じ傾きを持つ無関係な線が混在してしまいます。
