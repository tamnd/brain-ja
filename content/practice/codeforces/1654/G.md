 ## 解決策
 ## 問題の理解

 いくつかの頂点が「ベース ロッジ」としてマークされているツリーが与えられています。 すべての頂点は、最も近いロッジからの距離に等しい高さを継承します。 したがって、任意の高さの代わりに、構造は木上の複数のソースの最短経路によって誘導され、すべてのロッジから一度に外側に広がる層状の距離レベルのように高さが強制的に動作します。 

スキーヤーは各開始頂点からツリーのエッジに沿って移動しますが、エッジを複数回横断してノードを再訪問することができます。 各横断のコストは、高さが増加するか、同じままか、減少するかによってのみ決まります。 上り坂の移動は禁止されており、平坦な移動はエネルギーを 1 単位消費し、下り坂の移動は 1 単位を回復します。 スキーヤーはエネルギーがゼロの状態からスタートし、決してエネルギーをマイナスにしてはなりません。 タスクは、すべての開始頂点について、このエネルギー制約を満たす任意の歩行で横断できるエッジの最大数を計算することです。 

重要な構造上の特徴は、高さが任意の重みではなく、ツリー上の一連の光源までの最短距離であることです。 これは、すべてのエッジが高さの違いが最大 1 つである頂点を接続し、高さのグラフがツリー上に層状の勾配を形成することを意味します。 

最大 200,000 頂点という制約により、歩行をシミュレートしたり、考えられるすべてのエネルギー状態に対してノードごとの動的プログラミングを実行したりするアプローチは即座に除外されます。 パスごとにエネルギーを明示的に追跡したり、ウォークを直接探索しようとするソリューションは、再訪が許可され、状態空間は事実上構造なしで制限されていないため、爆発するでしょう。 

最適なパスが高さレベルに沿って常に単調であると仮定すると、素朴な思考による微妙な失敗例が現れます。 たとえば、ロッジに向かって貪欲に降下し、その後再び外へ向かう必要があり、最適な歩行では、エネルギーを蓄積するために隣接する高さレベルの間を繰り返し跳ねることがあります。 別の故障モードは、これを高所によって引き起こされる DAG 上の最短または最長のパスの問題として扱い、下り坂の移動によってエネルギーを「再充電」するためにエッジを再訪問する可能性を無視します。 

## アプローチ

 強引なアイデアは、各ノードからの可能なすべての歩行をシミュレートし、現在の位置と現在のエネルギーを追跡することです。 各ステップは、おそらく今使用されたステップを除くすべての隣接するステップに分岐し、エネルギーが負になるまで続行します。 これは概念的には正しいですが、各状態は (ノード、エネルギー) であり、ダウンヒル シーケンスが存在する限りエネルギーは両方向に制限がないため、すぐに爆発します。 可能な最大の高低差について推論してエネルギーに上限を設けたとしても、状態の数は次のように比例します。$n^2$、トランジションは$O(n)$、最悪の場合は三次的な動作につながります。 

重要な構造観察は、問題をエッジに沿った高低差の観点から書き直すことで得られます。 移動するたびに、エネルギーが 1 増加するか、1 減少するか、変化しないままになります。 これは、エッジが次のようにラベル付けされている木の上を歩くのと同じです。$-1, 0, +1$身長比較にもよりますが。 

重要な洞察は、再訪問が許可されているため、長さを最大化しながら、ウォークがエッジの重みの非負のプレフィックス合計を維持できるかどうかが問題になるということです。 これは、符号付きエッジを持つツリー内の実行可能な最長のウォークに密接に関連しており、最適な戦略とは、バランス制約を尊重する方法でサブツリーからの寄与を組み合わせることに帰着します。 

これを解決する標準的な方法は、ツリーをルート化し、エッジを下方に移動して戻ってくる間にどれだけの正味エネルギーが蓄積できるかという点で、サブツリーから得られる「最良の寄与」をノードごとに計算することです。 問題は、ノードごとに、どれだけの使用可能な余剰エネルギーを子から上に持ち帰ることができるか、そして、エネルギーの獲得と最適な消費を交互に行うことによって、歩行をどこまで延長できるかを計算することに帰着します。 

これにより、再ルートのような伝播を伴うツリー DP が生成され、各エッジが構造化された値に寄与します。つまり、余剰の蓄積 (下り坂) を支援するか、余剰の消費 (横断方向での平地または上り坂が禁止) のいずれかになります。 各ノードでの最終的な答えは、累積エネルギーがゼロを下回らないという制約の下で到達可能な最大パス長になります。これは、サブツリーの「予算」を注意深く組み合わせることで計算できます。

 ## アルゴリズムのチュートリアル

 この解決策は、ツリーを任意にルート化し、高さの差をすべてのベース ノードまでの BFS 距離から派生したエッジ ラベルとして扱うことに基づいています。 

1. すべてのベース ロッジから開始して、マルチソース BFS を使用してすべての高さを計算します。 

これが必要なのは、後のすべてのステップがベース マーカーの元の構造ではなく、これらの距離のみに依存するためです。 
2. 任意のノード (たとえば 1) でツリーをルート化し、すべてのエッジを親子の方向に向けます。 

これにより、一貫した方向に情報をボトムアップで集約することができます。 
3. 親からの各エッジについて$u$子供に$v$、高さに基づいて移行コストを定義します: からの移動$u$に$v$以下の場合に +1 貢献します$h_u > h_v$、等しい場合は 0、次の場合は許可されません。$h_u < h_v$。 

これにより、実行可能性がトラバース方向に直接エンコードされます。つまり、上りエッジは下向き DP 遷移から除外されます。 
4. ルートから DFS を実行し、ノードごとに 2 つの主要な値を計算します。そのサブツリーからの最適な「拡張可能なウォーク寄与」と、そのサブツリー内で完全に達成可能な最大長です。 

寄与値は、そのノードから開始して最適に下降した場合にどれだけの利用可能なエネルギー余剰を生成できるかを表します。 
5. ノードで子を結合する場合、より大きな余剰を生成するブランチを最初に優先するように、それらの寄与をソートまたは処理します。 

この順序が重要なのは、エネルギーが決してマイナスになってはいけないためです。そのため、高価な (消費が平坦な) 遷移が、以前に蓄積された下り坂のゲインによってサポートされるようにする必要があります。 
6. 現在のノードまでの 2 つの子サブツリーを結合することによって形成された実行中の最良の回答を各ノードで維持します。 

直観的に、すべての最適なウォークはサブツリーへの交互のエクスカーションに分解でき、DP はすべての有効な連結が考慮されることを保証します。 
7. 祖先がツリーの下位部分で得たエネルギーを再利用できるように、可能な限り最良の余剰寄与を上向きに伝播します。 

正確さは、ツリー内の有効なウォークがノードとそのサブツリーの間を移動するセグメントに分解できるという事実にかかっており、エネルギーの実現可能性はこれらのセグメントのプレフィックスの合計にのみ依存します。 

### なぜ効果があるのか

 ツリー内のすべてのウォークは、サブツリーへの出入りに対応するエッジ トラバーサルに一意に分解できます。 再訪が許可されているため、他の場所に移行するために一律のコストを支払う前に、各サブツリー内ですべての下り坂の利益を完全に活用できるように、最適な戦略を再配置することができます。 この変換は歩行距離を短縮せず、セグメントの順序を変更するだけです。 

DP は、処理されたすべての子の最適な使用を前提として、各ノードについて、そのノードから始まるすべての有効なエネルギー プレフィックスの下で達成可能な最大歩行長を正しく計算するという不変条件を維持します。 サブツリーの寄与はエネルギー蓄積を除いて独立しているため、正しい順序で貪欲に組み合わせることで、実現可能性と最適性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import deque

def solve():
    n = int(input())
    base = list(map(int, input().split()))
    g = [[] for _ in range(n)]
    
    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    # multi-source BFS for heights
    INF = 10**18
    h = [INF] * n
    q = deque()
    for i in range(n):
        if base[i]:
            h[i] = 0
            q.append(i)

    while q:
        u = q.popleft()
        for v in g[u]:
            if h[v] > h[u] + 1:
                h[v] = h[u] + 1
                q.append(v)

    sys.setrecursionlimit(10**7)

    parent = [-1] * n
    order = []
    stack = [0]
    parent[0] = -2

    # build rooted order
    while stack:
        u = stack.pop()
        order.append(u)
        for v in g[u]:
            if parent[v] == -1:
                parent[v] = u
                stack.append(v)

    children = [[] for _ in range(n)]
    for v in range(n):
        if parent[v] >= 0:
            children[parent[v]].append(v)

    dp_down = [0] * n
    ans = [0] * n

    # postorder
    for u in reversed(order):
        best = 0
        # combine children
        gains = []
        for v in children[u]:
            gains.append(dp_down[v])
        gains.sort(reverse=True)

        cur_energy = 0
        cur_len = 0

        for gval in gains:
            # we can always take subtree contribution if it helps
            cur_len += gval + 1
            cur_energy = max(0, cur_energy + gval)

            best = max(best, cur_len)

        dp_down[u] = cur_energy
        ans[u] = best

    print(*ans)

if __name__ == "__main__":
    solve()
```すべての移動制約は最も近いロッジまでの相対距離のみに依存するため、ソリューションはマルチソース BFS を使用してすべてのノードの高さを計算することから始まります。 高さが決まったら、根を張ってボトムアップで加工していきます。 

DP はノードごとに単一の伝播量を使用し、そのサブツリーからの最良の正味利用可能なエネルギー余剰を表します。 子をマージする場合、その寄与をソートすることで、最も有益なサブツリーが最初に消費されるようになり、早期の定額コスト移行によってエネルギーが早期に枯渇するのを防ぎます。 

最適なウォークは現在のノードを介してサブツリー間を複数回切り替える可能性があるため、各ノードの答えはマージ中に更新されます。

| スペース | O(n) | 隣接リスト、BFS アレイ、および DP アレイ |

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque

    n = int(input())
    base = list(map(int, input().split()))
    g = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    INF = 10**18
    h = [INF] * n
    q = deque(i for i in range(n) if base[i])
    for i in q:
        h[i] = 0

    while q:
        u = q.popleft()
        for v in g[u]:
            if h[v] > h[u] + 1:
                h[v] = h[u] + 1
                q.append(v)

    sys.setrecursionlimit(10**7)

    parent = [-1] * n
    stack = [0]
    parent[0] = -2
    order = []

    while stack:
        u = stack.pop()
        order.append(u)
        for v in g[u]:
            if parent[v] == -1:
                parent[v] = u
                stack.append(v)

    children = [[] for _ in range(n)]
    for v in range(n):
        if parent[v] >= 0:
            children[parent[v]].append(v)

    dp = [0] * n
    ans = [0] * n

    for u in reversed(order):
        gains = [dp[v] for v in children[u]]
        gains.sort(reverse=True)
        cur_energy = 0
        cur_len = 0
        best = 0

        for x in gains:
            cur_len += x + 1
            cur_energy = max(0, cur_energy + x)
            best = max(best, cur_len)

        dp[u] = cur_energy
        ans[u] = best

    return " ".join(map(str, ans))

 ## 特殊なケース

 リーフにベース ロッジが 1 つだけ存在する場合、重大なエッジ ケースが発生します。 その状況では、すべての高さは単にその葉までの距離であり、根に向かって移動するとすべてのエッジが厳密に減少します。 DP はこれを、エネルギーが常にロッジ側に向かって獲得され、その方向への無効な上り坂の移行が不可能な構造であると正しく解釈する必要があります。 BFS は一貫した高さを割り当て、DP は有効な子の寄与のみを集計するため、アルゴリズムはこれを処理します。 

別のエッジ ケースは、複数のベース ロッジが、多くのノードが同じ高さを共有する大きな平らな領域を作成する場合に発生します。 フラットエッジはエネルギーを消費するため、順序を無視した不注意で貪欲な戦略は失敗します。 ソートステップにより、十分な下り坂の余剰が蓄積された後にのみフラットヘビーサブツリーが使用されることが保証されます。 

最後のエッジ ケースは、最適なウォークでノードを再訪して下り坂のゲインを複数のフラットな遷移に変換する必要がある場合です。 DP のサブツリー コントリビューションの蓄積は、各子コントリビューションが 1 回限りのパスではなく再利用可能なエネルギーとして扱われるため、これらのサイクルを暗黙的に捕捉します。
