 ## 解決策
 ## 問題の理解

 グループのリストが与えられ、各グループには固定人数が含まれています。 各グループは、ある順序で提供する必要があり、グループに提供するには、サイズ P のチョコレート パック全体が消費されます。パックは必要に応じて開封されますが、厳しい制約があります。パックが開封されて残りが生じた場合、新しいパックを開ける前に、それらの残りは後のグループで完全に消費されなければなりません。 

各グループは、新しいパックの境界で開始するか、すでに待機している残りのピースがあるときに到着します。 グループは、開封したてのパックをすべて使用して提供される場合、つまり残りのチョコレートをまったく消費しない場合に「良好」とみなされます。 私たちの仕事は、グループを並べ替えて、適切なグループの数を最大化することです。 

主な問題点は、各グループ サイズが P を法とする剰余を決定し、これらの剰余が、順序付け全体で展開するグローバルな残りの状態を通じて相互作用することです。 N は最大 100、P は最大 4 であるため、構造は状態を直接推論できるほど十分に小さいですが、それでも単純な置換チェックが実行不可能であるほど十分に大きいです。 

素朴なアプローチでは、グループのすべての順列を試し、残ったプロセスをシミュレートします。 それがNさんです！ 各シミュレーションのコストは O(N) ですが、これは N = 20 の場合でも完全に実行不可能です。 

より微妙な障害モードは、貪欲な順序付けによって発生します。 たとえば、すべてのグループを最初に剰余 0 で配置するのは安全に思えますが、実際には、後のグループもパックの境界に正確に配置されるように残りを整列させる機会を無駄にする可能性があります。 

## アプローチ

 重要な観察は、残りのダイナミクスにとって重要なのはグループ サイズの法 P だけであるということです。 サイズ g のグループが到着すると、現在の残りのバッファから g 個の部分が消費されます。 その後、バッファーがちょうど 0 に達した場合、そのグループは「新鮮」です。 それ以外の場合は、新しい残りの剰余状態が作成されます。 

したがって、このプロセスは P を法として剰余を探索し、各グループがそのサイズを P を法として減算することによって状態を遷移させます。絶対的なサイズは重要ではなく、g % P のみが重要です。 

P ≤ 4 であるため、残り物の状態空間は非常に小さくなります。 使用した各残基クラスのグループの数と、現在の残存状態が何であるかを動的計画法で定義できます。 目標は、グループにサービスを提供するときに状態 0 に正確に遷移する回数を最大化することです。 

ブルート フォース ビューでは、これを剰余クラスのカウントに対する順列 DP として扱います。 これは生の形式ではまだ大きいですが、状態は (r0、r1、r2、r3) カウントに現在の残りを加えたもののみであり、遷移は次のグループ タイプの選択のみに依存するため、崩壊します。 

重要な削減点は、完全な順序付けが必要なく、残りのサイクルの各フェーズで各剰余クラスの数が消費されるだけであるということです。 これにより、問題は O(N * P * N^P) 状態の小さな DP オーバー カウントに変わりますが、P ≤ 4 および N ≤ 100 であるため、これは許容可能です。

 | --- | --- | --- | --- |
 | 置換総当たり | お(ん!) | O(N) | 遅すぎる |
 | 残余カウントと残余状態に対する DP | O(N^3) | O(N^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 それのみが残り物に影響するため、各グループ サイズをその剰余 P に圧縮します。

1. 0 から P-1 までの各剰余クラス r に分類されるグループの数を数えます。 これにより、問題はアイデンティティではなく周波数に帰着します。 
2. これまでに使用された各残基クラスのグループの数と現在の残りの状態を追跡する DP 状態を定義します。 残りの状態は、現在引き継がれているチョコレートの数であり、常に 0 から P-1 の間になります。 
3. DP 遷移では、まだグループが残っている残基クラスから次のグループを選択することが考慮されます。 現在の残りとグループ サイズが P の倍数である場合、このグループは新しいグループとしてカウントされ、残りは 0 になります。 それ以外の場合は、残りを (current + r) mod P に更新します。 
4. すべての有効な DP 状態を反復処理し、一度に 1 つのグループを消費して遷移を更新します。 DP 値には、これまでに達成された新しいグループの最大数が格納されます。 
5. 答えは、すべてのグループが使用されるすべての状態にわたる最大 DP 値です。 

### なぜ効果があるのか

 残った状態は、連続するグループ間の唯一の依存関係を完全にキャプチャします。 パックの使用量は実行中の剰余モジュロ P にのみ依存するため、同じ剰余で終了する 2 つの履歴は交換可能です。 DP は、この十分な状態情報を保存しながら、残基クラスの可能な順序付けをすべて探索するため、有効なシーケンスが失われることはなく、無効なシーケンスが有効としてカウントされることもありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import defaultdict

def solve():
    T = int(input())
    for tc in range(1, T + 1):
        N, P = map(int, input().split())
        arr = list(map(int, input().split()))

        cnt = [0] * P
        for x in arr:
            cnt[x % P] += 1

        # DP state: (c0, c1, ..., cP-1, rem)
        from functools import lru_cache

        @lru_cache(None)
        def dp(c, rem):
            if sum(c) == 0:
                return 0

            best = 0
            for r in range(P):
                if c[r] == 0:
                    continue
                nc = list(c)
                nc[r] -= 1
                new_rem = (rem + r) % P

                gain = 1 if new_rem == 0 else 0
                best = max(best, gain + dp(tuple(nc), new_rem))

            return best

        start = tuple(cnt)
        print(f"Case #{tc}: {dp(start, 0)}")

if __name__ == "__main__":
    solve()
```このソリューションでは、各グループをそのモジュロ クラスに圧縮します。 再帰的 DP は、残った剰余を維持しながら、これらのクラスの有効な順序付けをすべて調査します。 メモ化により、繰り返し状態が 1 回計算されることが保証されます。 

微妙な点は、状態には残りのカウントの完全なベクトルが含まれていることです。これが必要なのは、現在の残りが同一であっても、残りのグループの分布が異なると将来の可能性が異なるためです。 

## 実用的な例

 グループを考慮する`[4, 5, 6, 4]`P = 3 です。それらの剰余は次のとおりです。`[1, 2, 0, 1]`。 

カウントから始めます`(r0=1, r1=2, r2=1)`そして余りは0。 

| ステップ | 状態 (r0,r1,r2) | レム | 選ばれたr | 新しいレム | 新鮮 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | (1,2,1) | 0 | 0 | 0 | はい |
 | 2 | (0,2,1) | 0 | 1 | 1 | いいえ |
 | 3 | (0,1,1) | 1 | 2 | 0 | はい |
 | 4 | (0,1,0) | 0 | 1 | 1 | いいえ |

 これは、順序が剰余 0 に達する頻度にどのような影響を与えるかを示しています。 

ここで考えてみましょう`[1,1,1]`P = 3、すべての剰余が 1 の場合。 

| ステップ | 状態 | レム | 選ばれたr | 新しいレム | 新鮮 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | (3) | 0 | 1 | 1 | いいえ |
 | 2 | (2) | 1 | 1 | 2 | いいえ |
 | 3 | (1) | 2 | 1 | 0 | はい |

 順序に関係なく 1 つのグループのみが新鮮であり、DP が固有の制限を捉えていることが確認されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N * 状態) ≈ O(N^4) ワーストケースの小さい | DP のオーバーカウントとメモ化による余り |
 | スペース | O(状態) | それぞれの一意の (カウント ベクトル、剰余) は 1 回保存されます。 

N ≤ 100 および P ≤ 4 であるため、メモ化による大幅な枝刈りにより、状態空間は実際には管理可能なままになります。

 ## 特殊なケース

 すべてのグループのサイズが P で割り切れる場合、順序付けするたびに新しいグループが生成されます。 DP はステップごとに rem を 0 から 0 に即座に遷移させるため、すべてのグループがカウントされます。 

すべてのグループの剰余が同じ場合、P ステップごとに剰余 0 に戻る全サイクルを完了できるのは 1 つのグループだけであり、DP は状態を循環させることで自然にその制約を強制します。 

残基が混在している場合は順序が重要になりますが、DP では考えられるすべての配列が考慮されるため、局所的な貪欲な決定によって全体的に最適な配置が排除されることはありません。
