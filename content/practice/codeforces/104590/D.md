 ## 解決策
 ## 問題の理解

 グリッドは、歩行可能な道路とブロックされた建物に分割された都市を表します。 街路には兵士と砲塔という 2 種類のエンティティがあります。 建物は通行できず、視界や移動も妨げます。 兵士は一定の単位ステップ数まで 4 方向に移動でき、それぞれに 1 発の射撃しかありません。 

重要な相互作用は、行と列に沿った可視性です。 どの街頭セルからも、兵士は水平方向と垂直方向を見ることができます。 砲弾はすべてを通過するため、その列にある砲塔は、間に他の兵士や砲塔があったとしても標的にすることができます。 ただし、移動と砲塔の相互作用は異なります。砲塔がアクティブな間は砲塔のセルに足を踏み入れることは禁止されており、元のストーリーでは砲塔の視線の下にあるセルから出るのは危険ですが、兵士は死ぬことはなく待つことができるため、唯一の本当の制約は、一度破壊されたブロッカーとしての砲塔を無視して、グリッド上の M 移動以内に到達できることです。 

タスクは、破壊できる砲塔の数を最大化し、さらにどの兵士がどの砲塔を破壊したかを出力することです。 

制約はソリューションを形作るものです。 グリッドは 100 × 100 まで大きくできますが、兵士と砲塔の数はそれぞれ最大 100 です。 各兵士には制限された移動予算 M がありますが、M 自体はグリッド サイズ全体と同じくらい大きくなる可能性があるため、到達可能性は自明に局所的ではなく、依然として道路の単一の接続されたコンポーネントに限定されます。 これは、組み合わせ爆発がグリッド サイズからではなく、到達可能性の制約の下で最大 100 個のソースと 100 個のターゲットの間のマッチングから発生することを直ちに示唆しています。 

単純な考えでは、各兵士の移動経路をシミュレーションし、各砲塔の射撃位置に到達できるかどうかをテストすることになります。 しかし、グリッド構造はこれを誤解を招きます。兵士は最初から直線の同じ行または列に立つ必要はありません。 M ステップ以内の任意のセルに到達し、そこから遮るもののないラインに沿って発射します。 

砲塔が最初は開いた見通し内に直接位置合わせされておらず、移動後にのみ到達可能になる場合、微妙なエッジ ケースが発生します。 もう 1 つの問題は、複数の兵士が同じ射撃位置に到達する可能性があることですが、各兵士には弾丸が 1 つしかないため、割り当てが重要になります。 また、たとえ到達可能であっても、兵士に複数の砲塔を割り当てることはできません。 

2 番目の微妙なケースは、砲塔が建物の廊下にあり、「良好な射撃セル」に到達するには狭い道を通らなければならない場合です。 マンハッタンの距離のみを考慮する単純なアプローチでは、到達可能性を誤って仮定することになりますが、実際の到達可能性は障害物に依存します。 

## アプローチ

 ブルートフォース解釈では、各兵士が M 移動までの可能なすべてのパスを個別に試し、到達可能な各セルからどの砲塔が射撃可能になるかを確認しているものとして扱われます。 到達可能な各セルから行と列全体をスキャンして、どの砲塔が攻撃できるかを確認します。 これにより、すでに巨大な分岐構造が作成されています。各兵士には潜在的に O(RC) の到達可能な状態があり、各状態からのスキャン可視性は O(R + C) であり、兵士ごとの複雑さは O(RC(R + C)) になります。 最大 100 人の兵士と 100 × 100 のグリッドでは、これはすぐに実行不可能になります。特に、単純に実行すると移動探索自体が指数関数的に増加するためです。 

重要な観察は、動きと射撃がきれいに分離されていることです。 兵士はセルにどのように到達するかは気にせず、セルが M 歩以内に到達できるかどうかだけを気にします。 独房に入ると、射撃は静的な視線構造のみに依存します。 そこで問題は、各兵士について、少なくとも 1 つの有効な立ち位置を介して間接的に到達できる砲塔のセットを計算することです。

これは 2 部グラフの問題に変換されます。 左側には兵士、右側には砲塔があります。 兵士 i が砲塔 j が見えるセルに到達できればエッジを描きます。 次に、最大限のマッチングが必要になります。 全体的な困難は、これらの到達可能性と可視​​性の関係を効率的に計算することに帰着します。 

エッジを計算するために、各兵士から深さ M まで BFS を実行し、到達可能なセルをマークします。 訪問した各セルについて、その行と列をチェックして、その位置から見えるすべてのタレットを収集します。 すべての行と列を繰り返しスキャンするのはコストがかかるため、建物で区切られた砲塔の行方向および列方向のリストを前処理することによって、セルごとに 4 方向で最も近い砲塔候補を事前計算します。 これにより、任意のセルから可視タレットを O(1) または O(log n) で識別できます。 

2 部グラフを構築した後、グラフ サイズが最大 100 x 100 であるため、標準の DFS 拡張パス アルゴリズムを使用して最大 2 部マッチングを解決します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースパス列挙 | M とグリッド サイズの指数 | O(RC) | 遅すぎる |
 | 兵士ごとの BFS + 二者マッチング | O(S * RC + E * sqrt(V)) | O(RC + E) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、可視性クエリを効率的に行うためにグリッドを前処理します。 各行を左から右にスキャンし、建物で区切られたセグメントに分割します。 各セグメント内で、砲塔とその位置を記録します。 列についても同じことを行います。 これにより、任意の空きセルが与えられた場合、グリッド全体をスキャンすることなく、その行セグメントと列セグメント内のすべてのタレットを見つけることができます。 

次に、各兵士に対して、その位置から開始して M ステップまで拡張する幅優先検索を実行します。 私たちは通りのセルを通過するだけであり、砲塔は一度計画で考慮されると永久に動きを妨げるとは述べられていないため、動きの妨げとなるものとしては無視します。 重要な制約はステップ制限です。 

第三に、BFS がセルを訪問するたびに、その行セグメントと列セグメントをクエリし、その位置から見えるすべてのタレットを収集します。 このような砲塔ごとに、兵士がそれを射撃できることをマークし、2 部グラフにエッジを作成します。 

4 番目に、グラフを構築した後、兵士から砲塔までの最大 2 部マッチングを実行します。 各兵士は最大 1 つの砲塔に対応できるため、兵士を左側として扱います。 

5 番目に、一致するペアを再構築し、任意の順序で出力します。 

### なぜ効果があるのか

 BFS により、兵士が M 歩以内で物理的に到達できるすべてのセルを正確に探索できるようになります。 セグメンテーションの前処理により、到達可能なセルから、遮るもののない直線の視界内にある砲塔を正確に列挙できるようになります。 射撃では中間オブジェクトが無視されるため、兵士がそのセルに到達すると、目に見えるすべての砲塔が有効な即時射撃に対応します。 次に、2 部マッチングにより、各兵士が最大 1 回の破壊に寄与し、各砲塔が最大 1 回破壊されるという制約が適用されるため、結果のマッチングは有効なアクションの割り当てに直接対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque, defaultdict

def solve():
    C, R, M = map(int, input().split())
    grid = [list(input().strip()) for _ in range(R)]

    soldiers = []
    turrets = []

    for i in range(R):
        for j in range(C):
            if grid[i][j] == 'S':
                soldiers.append((i, j))
            elif grid[i][j] == 'T':
                turrets.append((i, j))

    S = len(soldiers)
    T = len(turrets)

    turret_id = {}
    for idx, (x, y) in enumerate(turrets):
        turret_id[(x, y)] = idx

    row_blocks = [[[] for _ in range(C)] for _ in range(R)]
    col_blocks = [[[] for _ in range(C)] for _ in range(R)]

    # preprocess row segments
    for i in range(R):
        j = 0
        while j < C:
            if grid[i][j] == '#':
                j += 1
                continue
            start = j
            cells = []
            while j < C and grid[i][j] != '#':
                cells.append(j)
                j += 1
            for jj in cells:
                row_blocks[i][jj] = [(i, y) for y in cells]

    # preprocess col segments
    for j in range(C):
        i = 0
        while i < R:
            if grid[i][j] == '#':
                i += 1
                continue
            start = i
            cells = []
            while i < R and grid[i][j] != '#':
                cells.append(i)
                i += 1
            for ii in cells:
                col_blocks[ii][j] = [(x, j) for x in cells]

    adj = [[] for _ in range(S)]

    # BFS per soldier
    for si, (sx, sy) in enumerate(soldiers):
        dist = [[-1] * C for _ in range(R)]
        q = deque()
        q.append((sx, sy))
        dist[sx][sy] = 0

        while q:
            x, y = q.popleft()
            if dist[x][y] > M:
                continue

            # collect visible turrets
            for (vx, vy) in row_blocks[x][y]:
                if grid[vx][vy] == 'T':
                    adj[si].append(turret_id[(vx, vy)])
            for (vx, vy) in col_blocks[x][y]:
                if grid[vx][vy] == 'T':
                    adj[si].append(turret_id[(vx, vy)])

            for dx, dy in [(1,0),(-1,0),(0,1),(0,-1)]:
                nx, ny = x + dx, y + dy
                if 0 <= nx < R and 0 <= ny < C and grid[nx][ny] != '#':
                    if dist[nx][ny] == -1:
                        dist[nx][ny] = dist[x][y] + 1
                        if dist[nx][ny] <= M:
                            q.append((nx, ny))

    # bipartite matching
    match_to = [-1] * T

    def dfs(u, vis):
        for v in adj[u]:
            if vis[v]:
                continue
            vis[v] = True
            if match_to[v] == -1 or dfs(match_to[v], vis):
                match_to[v] = u
                return True
        return False

    for u in range(S):
        vis = [False] * T
        dfs(u, vis)

    res = []
    for v in range(T):
        if match_to[v] != -1:
            res.append((match_to[v] + 1, v + 1))

    print(len(res))
    for s, t in res:
        print(s, t)

def main():
    t = int(input())
    for i in range(1, t + 1):
        print(f"Case #{i}:")
        solve()

if __name__ == "__main__":
    main()
```BFS は兵士あたり M によって制限されるため、各セルには兵士あたり最大 1 回アクセスされます。 可視性のステップは、事前に計算された行セグメントと列セグメントに依存して、グリッド全体のスキャンを回避します。 マッチングは、最大 100 × 100 のサイズのグラフに対する標準の DFS ベースの拡張です。 

微妙な点の 1 つは、複数のセルからの砲塔エッジの重複を避けることです。 この実装では重複が許可されており、DFS マッチングは引き続き機能するため許容されますが、より厳密な実装では、兵士ごとにセットすることで冗長なエッジが削減されます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、砲塔が配置された列や列につながる狭い廊下を除いて、兵士が建物に囲まれている場合です。 BFS は引き続き廊下を探索しますが、目に見える砲塔セグメントには遭遇しないため、エッジは作成されず、兵士は一致しないままとなり、その兵士の出力はゼロになります。 

もう 1 つのケースは、BFS フロンティア内の複数のセルが同じ見通し線砲塔を共有する場合です。 実装では重複エッジが追加される可能性がありますが、重複によってマッチング サイズが増加するわけではなく、冗長な DFS ブランチが追加されるだけであるため、マッチングの正確さには影響しません。 

最後のケースは、M が街路の接続されたコンポーネント全体に到達するのに十分な大きさである場合です。 そのシナリオでは、すべての兵士の BFS が事実上そのコンポーネントのフラッド フィルとなり、ソリューションは完全にグローバルな可視性ベースのマッチングに還元され、これは 2 部グラフ構築によって正しくキャプチャされます。
