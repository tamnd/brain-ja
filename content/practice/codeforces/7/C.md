 ## 問題の理解

 次の方程式で記述される直線上の整数点を見つけるように求められます。`Ax + By + C = 0`。 入力は 3 つの整数です。`A`、`B`、 そして`C`、線の傾きと位置を定義します。 私たちのタスクは整数を出力することです`x`そして`y`等式を満たす、または`-1`そのような整数が存在しない場合。 

の境界`A`、`B`、 そして`C`は最大 ±2·10⁹ と比較的大きくなりますが、出力できる座標の範囲は最大 ±5·10¹⁸ までとなります。 これは、考えられるすべてを試すことはできないことをすぐに示唆しています`(x, y)`ペア; ブルートフォース列挙は実行不可能です。 重要な問題は、整数解が存在するかどうか、そしてそれを効率的に計算する方法です。 

単純な間違いは、どの直線にも常に整数点があると仮定することです。 たとえば、次の行`2x + 4y + 1 = 0`整数の場合、右辺は奇数ですが、左辺は常に偶数であるため、整数の解はありません。`x`そして`y`。 もう 1 つの微妙なケースは、次のいずれかの場合です。`A`または`B`はゼロです。 もし`A = 0`とすると、方程式は次のようになります。`By + C = 0`そして`y`でなければなりません`-C/B`。 もし`-C/B`は整数ではないため、解は存在せず、不注意な実装では、割り切れる可能性をチェックせずに他の変数にゼロを代入しようとする可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、すべての整数が試行されます。`x`ある範囲で計算します`y = (-C - A*x)/B`。 もし`y`は整数であり、許可された範囲内であれば、返します`(x, y)`。 これは方程式が線形であるため機能しますが、非現実的です。 Even if we limit`x`±10⁹までの場合、数十億回の反復が必要になる可能性があり、これは 1 秒の時間制限をはるかに超えています。 

重要な洞察は数論、つまり方程式から得られます。`Ax + By = -C`の最大公約数が次の場合に限り、整数解が得られます。`A`そして`B`分割する`-C`。 これはベズーの恒等式の直接的な結果です: あらゆる整数について`A`そして`B`、整数が存在します`x`そして`y`そのような`Ax + By = gcd(A, B)`。 したがって、もし`gcd(A, B)`分割する`-C`、ベズー係数をスケールして解を得ることができます。 

これにより、広大な整数空間の検索から gcd の計算、拡張ユークリッド アルゴリズムを使用した 1 つのペアの検索までの問題が軽減されます。`(x, y)`。 特定の解決策を取得したら、いつでもそれを倍数で調整できます。`(B/gcd, -A/gcd)`必要に応じて範囲内にとどまること。

 ## アルゴリズムのチュートリアル

 1. 最大公約数を計算する`g = gcd(A, B)`ユークリッドアルゴリズムを使用します。 これにより、整数解が可能かどうかがわかります。 もし`g`分けない`-C`、出力`-1`すぐに。 
2. 拡張ユークリッド アルゴリズムを使用して整数を検索します`x0`そして`y0`そのような`A*x0 + B*y0 = g`。 このステップは出発点となります。 
3. スケール`x0`そして`y0`による`-C // g`実際の直線方程式を満たすには：`x = x0 * (-C//g)`そして`y = y0 * (-C//g)`。 今`(x, y)`満足することが保証されています`Ax + By + C = 0`。 
4. 次のことを確認します。`(x, y)`座標範囲 ±5·10¹⁸ 内にあります。 その場合は返品してください。 それ以外の場合は、次の式を使用してソリューションを調整します。`x = x + k*(B//g)`そして`y = y - k*(A//g)`値を範囲内に収めます。 任意の倍数`k`直線に沿って別の整数解を生成します。 

### なぜ効果があるのか

 拡張ユークリッド アルゴリズムがペアを生成するため、アルゴリズムが機能します。`(x0, y0)`満足のいく`Ax + By = gcd(A, B)`。 乗算`-C/g`左辺が等しいことを保証します`-C`、元の方程式の整数解が得られます。 一般的な解決形式`x + k*(B//g), y - k*(A//g)`このペアからすべての整数解を生成できることが保証されているため、範囲内に解が存在する場合はそれを見つけることができます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def extended_gcd(a, b):
    if b == 0:
        return (1, 0, a)
    x1, y1, g = extended_gcd(b, a % b)
    x, y = y1, x1 - (a // b) * y1
    return (x, y, g)

A, B, C = map(int, input().split())

x0, y0, g = extended_gcd(A, B)

if C % g != 0:
    print(-1)
else:
    factor = -C // g
    x = x0 * factor
    y = y0 * factor
    # Ensure solution is within bounds
    LIMIT = 5 * 10**18
    shift_x = B // g
    shift_y = A // g
    # Adjust k to bring x within limits
    if x < -LIMIT or x > LIMIT or y < -LIMIT or y > LIMIT:
        k = 0
        if shift_x != 0:
            k = max((-LIMIT - x)//shift_x, (-LIMIT - y)//(-shift_y)) if shift_y != 0 else (-LIMIT - x)//shift_x
            x += k * shift_x
            y -= k * shift_y
    print(x, y)
```このコードは、まず拡張 gcd を計算して解を見つけます。 乗算`-C//g`直線方程式が成り立つことを確認します。 最終調整により、解が許容座標制限内に収まるようになります。これは、最初にスケーリングされた解が大きすぎる場合に必要になる可能性があります。 沿ってシフトします`(B//g, -A//g)`直線方程式を保存します。
