 ## 解決策
 ## 問題の理解

 サイズ _m_ の線形メモリ配列用の単純なメモリ マネージャーを実装するように求められます。 各メモリ セルは、ブロックによって解放されることも占有されることもできます。 一連の操作を処理します。`alloc n`、`erase x`、 そして`defragment`。 アン`alloc n`リクエストは、_n_ バイトの連続セグメントを割り当てようとします。 複数の連続した空きセグメントが存在する場合は、メモリの先頭に最も近い空きセグメントが選択されます。 割り当てが成功すると、1 から始まる一意の識別子が与えられます。割り当てが失敗した場合は、次の値を返す必要があります。`NULL`。 

アン`erase x`リクエストは識別子 _x_ に関連付けられたメモリを解放します。 _x_ が割り当てられていないか、すでに消去されている場合は、次のように出力します。`ILLEGAL_ERASE_ARGUMENT`。 ついに、`defragment`割り当てられたすべてのブロックを順序を維持しながらメモリの先頭に移動し、それらの間のギャップを排除します。 

制約は厳しいですが、管理可能です。 操作の合計数は最大 100 で、メモリは最大 100 バイトです。 これにより、単純な O(t*m) アルゴリズムでも最大 10,000 ステップ実行され、1 秒の制限内に十分収まるため、メモリを明示的にシミュレートするソリューションが可能になります。 

エッジ ケースには、十分な大きさの連続した空きセグメントが存在しない場合のブロックの割り当て、割り当てられなかったブロックの消去の試行、ブロックを移動するがサイズは変更しない最適化後の割り当てなどが含まれます。 たとえば、メモリが`[alloc 3, alloc 4, erase 1]`、その後の`alloc 5`デフラグなしでは空き領域が分割されるため失敗しますが、デフラグありでは成功するはずです。 

## アプローチ

 ブルートフォース手法では、メモリを長さ _m_ のリストとしてシミュレートし、次のいずれかを保存します。`0`空きバイトの場合は割り当て ID、占有バイトの場合は割り当て ID。 のために`alloc n`、少なくとも _n_ 個のゼロの最初の連続シーケンスのリストをスキャンし、それを新しい ID に置き換えて、割り当てカウンターをインクリメントします。 のために`erase x`、メモリをスキャンし、出現するすべての ID を置き換えます`x`ゼロで。`defragment`これは、ゼロ以外のすべての ID を前方にフィルタリングし、残りをゼロでパディングすることによって実装されます。 すべての操作で必要なのは連続シーケンスのチェックと割り当て ID の維持だけであるため、これは正しいことですが、制約が大きい場合、大きな _m_ を求めてメモリを繰り返しスキャンすると速度が遅くなります。 

最適化の重要な観察点は、問題のサイズが直接シミュレーションを可能にするということです。 より大きなメモリの場合は、空きセグメントのリストを間隔として保持し、間隔の割り当てとマージを行い、割り当てられたセグメントを別のリストとして移動することができます。 この問題の構造により、リニア スキャンで十分になります。`t`そして`m`≤100である。

 | ブルートフォース | O(t*m) | O(m) | 承認済み |
 | 間隔の最適化 | O(t*ブロック数) | O(ブロック数) | 制約には必要ありません |

 ## アルゴリズムのチュートリアル

 1. メモリを長さ _m_ のゼロのリストとして初期化します。 迅速な消去チェックのために、1 から始まる割り当てカウンターと、メモリ範囲に ID をマッピングする辞書を維持します。 
2.`alloc n`操作では、メモリを最初から最後まで反復して、少なくとも _n_ 個以上の連続するゼロの最初のシーケンスを見つけます。 見つかった場合は、これらのゼロを現在の割り当て ID に置き換え、ID から範囲へのマッピングを記録し、カウンターをインクリメントして、ID を出力します。 見つからない場合は印刷します`NULL`。 
3.`erase x`操作では、まず ID かどうかを確認します。`x`マッピングに存在します。 そうでない場合は、印刷してください`ILLEGAL_ERASE_ARGUMENT`。 それ以外の場合は、ブロックの開始インデックスと終了インデックスを取得し、対応するすべてのメモリ セルをゼロに戻し、マッピングから ID を削除します。 
4.`defragment`操作を実行し、メモリを反復処理して、ゼロ以外のすべての ID を順番に収集します。 メモリを、長さ _m_ になるまでゼロが続くこの順序付きリストに置き換えます。 新しい範囲を反映するように各 ID のマッピングを更新します。 
5. 入力のすべての操作に対してステップ 2 ～ 4 を繰り返し、出力がすぐに印刷されるようにします。`alloc`そして失敗した`erase`操作。 

機能する理由: すべてのステップで、メモリは割り当ての状態を正確に反映します。 割り当てスキャンにより、最初に適合するポリシーが保証されます。 マッピングに対する消去チェックでは、有効な ID のみが削除されることが保証されます。 デフラグでは、割り当ての相対的な順序が維持されます。 メモリの一貫性と正しい ID 割り当ての不変条件が全体にわたって維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t, m = map(int, input().split())
memory = [0] * m
alloc_counter = 1
id_map = {}  # ID -> (start, end)

for _ in range(t):
    parts = input().split()
    cmd = parts[0]

    if cmd == 'alloc':
        n = int(parts[1])
        found = False
        i = 0
        while i <= m - n:
            if all(memory[i+j] == 0 for j in range(n)):
                for j in range(n):
                    memory[i+j] = alloc_counter
                id_map[alloc_counter] = (i, i+n)
                print(alloc_counter)
                alloc_counter += 1
                found = True
                break
            i += 1
        if not found:
            print("NULL")

    elif cmd == 'erase':
        x = int(parts[1])
        if x not in id_map:
            print("ILLEGAL_ERASE_ARGUMENT")
        else:
            start, end = id_map[x]
            for i in range(start, end):
                memory[i] = 0
            del id_map[x]

    elif cmd == 'defragment':
        new_memory = [val for val in memory if val != 0]
        memory = new_memory + [0]*(m - len(new_memory))
        idx = 0
        for val in new_memory:
            start = idx
            while idx < m and memory[idx] == val:
                idx += 1
            id_map[val] = (start, idx)
```コードはアルゴリズムを反映しています。メモリは明示的に表され、割り当ては空き領域をスキャンし、ID マップは有効な消去を保証します。 デフラグではメモリを所定の位置に再構築し、すべての範囲を更新します。 微妙な点は、最適化中に ID マップを正しく維持することです。 移動されたすべてのブロックの範囲を再計算します。 もう 1 つの微妙な点は、メモリを効率的にスキャンすることです。 失敗が確認されるまで、潜在的な割り当て内のインデックスをスキップせず、off-by-one エラーを防ぎます。
