 ## 解決策
 ## 問題の理解

 文字と数字で構成される文字列が与えられ、_回文度_ と呼ばれるすべての接頭辞の特別な尺度を計算するように求められます。 文字列が回文であり、その長さの前半と後半の場合、その文字列は回文次数 _k_ を持ちます。`len(s) // 2`それぞれの度数は _k-1_ です。 定義により、文字列が空であるとみなした場合、その文字列は次数 0 になります。 私たちの目標は、入力文字列のすべての接頭辞の回文次数を合計することです。 

文字列は最大 5·10⁶ 文字であるため、各プレフィックスを個別にチェックし、その半分を再帰的に調べる単純なアプローチでは、あまりにも時間がかかりすぎます。 5・10⁶の2乗は25・10¹²の演算となり、制限時間をはるかに超えているため、O(n²)時間で実行されるアルゴリズムは実行不可能です。 したがって、線形時間に近い、理想的には O(n) で実行されるアルゴリズムが必要です。 

文字列に繰り返しパターンがある場合、または文字列が非常に短い場合には、明らかではないエッジ ケースが発生します。 たとえば、1 文字の文字列「a」の次数は 1 ですが、「aa」のような 2 文字の文字列の次数は 2 です。これは、長さ 1 の接頭辞と接尾辞の次数が 1 であるためです。小さい回文から次数を正しく伝播できない場合、過小評価される可能性があります。 

別の微妙なケースは、「abba」のように、接頭辞が回文であるが、その半分が回文ではない場合に発生します。 完全な文字列は回文ですが、接頭辞「ab」と接尾辞「ba」は次数 1 の回文ではないため、「abba」の次数は 2 ではなく 1 になります。 

## アプローチ

 ブルートフォースソリューションでは、文字列のすべてのプレフィックスを反復処理し、それが回文であるかどうかをチェックし、その左半分と右半分をチェックして次数を再帰的に計算します。 これは原理的には機能しますが、大きな文字列の場合は非現実的になります。 長さ n の文字列の場合、総当たりアプローチではプレフィックスごとにおよそ n²/2 回の比較が必要になる可能性があり、次数の伝播を含めると合計操作数は O(n³) になります。 これは、n = 5・10⁶ にとっては明らかに遅すぎます。 

重要な洞察は、回文度数が度数の接頭辞配列_を使用して段階的に計算できることを認識することです。 どのプレフィックスが回文であるかを効率的に事前計算すると、1 回のパスで次数配列を構築できます。 このために、Z アルゴリズムまたはローリング ハッシュ技術を使用しますが、より単純なアプローチでは、文字列の回文プロパティが本質的に再帰的であるという事実を利用します。つまり、文字列の次数はその半分の次数に直接依存します。 具体的には、長さ L の接頭辞が回文の場合、その前半 (長さ L//2) の次数をチェックして 1 ずつインクリメントできます。`deg[i]`インデックス i で終わる接頭辞の回文次数については、次のように計算できます。`deg[i]`として`deg[i//2] + 1`プレフィックスが回文の場合は 0、それ以外の場合は 0。 

プレフィックスが回文であるかどうかを効率的にチェックするには、ハッシュを使用できます。 左から右へのローリング ハッシュと、右から左への逆ローリング ハッシュを計算します。 これら 2 つのハッシュが特定のプレフィックスと一致する場合、それは回文です。 これにより、適切な事前計算により、プレフィックスごとに O(n) 個の回文チェックが行われ、すべてのプレフィックスに対して合計 O(n) 回の回文チェックが行われます。

 ## アルゴリズムのチュートリアル

 1. 文字列のフォワード ローリング ハッシュ配列を計算します。 各プレフィックスのハッシュにより、事前に計算されたべき乗配列を使用して、任意の部分文字列ハッシュを定数時間で取得できます。 これにより、プレフィックスとそのミラーリングされたサフィックスを迅速に比較できるようになります。 
2. 逆ローリングハッシュ配列も同様に計算します。 これにより文字列がミラーリングされ、部分文字列を物理的に反転することなく、プレフィックスと対応するサフィックスを比較できるようになります。 
3. 配列を初期化する`deg`各プレフィックスの回文次数を格納する長さ n の。 
4. 位置 i で終わる各プレフィックスを繰り返します。 ハッシュ配列を使用して、部分文字列かどうかを確認します。`s[0..i]`回文です。 そうでない場合は設定してください`deg[i] = 0`。 
5. 接頭辞が回文の場合、次を使用して次数を計算します。`deg[i] = deg[i//2] + 1`。 ここ、`i//2`次のレベルを決定する次数の最大の接頭辞に対応します。 1 ずつ増加すると、回文次数の再帰的定義が伝播されます。 
6. すべてを合計する`deg[i]`最終的な答えを得るために値を設定します。 

機能する理由: 順方向ハッシュと逆方向ハッシュにより、すべてのプレフィックスに対する正しい回文検出が保証されます。 からの再帰的伝播`deg[i//2]`各プレフィックスの次数がその半分の次数を正しく考慮していることを保証します。 これにより、次の不変条件が維持されます。`deg[i]`は、i で終わる接頭辞が k 回文となるような、まさに最大の k です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7
BASE = 31

s = input().strip()
n = len(s)

pow_base = [1] * (n + 1)
for i in range(1, n + 1):
    pow_base[i] = (pow_base[i-1] * BASE) % MOD

hash_forward = [0] * (n + 1)
hash_reverse = [0] * (n + 1)

for i in range(n):
    hash_forward[i+1] = (hash_forward[i] * BASE + ord(s[i])) % MOD
    hash_reverse[i+1] = (hash_reverse[i] * BASE + ord(s[n-1-i])) % MOD

def get_hash(h, l, r):
    return (h[r+1] - h[l] * pow_base[r-l+1]) % MOD

deg = [0] * n
ans = 0

for i in range(n):
    if get_hash(hash_forward, 0, i) == get_hash(hash_reverse, n-i-1, n-1):
        deg[i] = (deg[i//2] + 1) if i > 0 else 1
    else:
        deg[i] = 0
    ans += deg[i]

print(ans)
```コードは、大きな素数を法とするハッシュ ベースの累乗を事前計算することから始まります。 順方向ハッシュと逆方向ハッシュは、定数回文チェックを可能にするために保存されます。 メイン ループは各プレフィックスを反復処理し、ハッシュ比較を使用して回文プロパティをチェックし、次に次数を再帰的に計算します。`deg[i//2]`。 すべての次数を合計すると答えが得られます。 Off-by-one エラーは、部分文字列ハッシュに対して 0 から始まるインデックスを一貫して使用することで慎重に回避されます。
