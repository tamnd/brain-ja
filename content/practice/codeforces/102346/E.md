 ## 解決策
 ## 問題の理解

 私たちは (N) 台の戦車を持っています。 水槽 (i) には、(M_i) の雄のカクレクマノミと (F_i) の雌のカクレクマノミがいます。 条件 (M_i=0) または (F_i>0) は、現在オスがいるすべての水槽に少なくとも 1 頭のメスもいることを意味します。 

一晩の間に、ちょうど 1 匹の魚をある水槽から別の水槽に移すことができます。 その夜の終わりに、すべての水槽に少なくとも 1 頭のオスがいて、メスがいないと、その水槽のちょうど 1 頭のオスが翌日にはメスになります。 目標は、できるだけ少ない動きですべてのオスの魚をメスにすることです。 答えは、必要な最小限の魚の動きです。 

水槽の数は最大 3000 個ですが、魚の数はそれぞれ (10^5) に達する可能性があります。 したがって、魚の総数は (3\cdot10^8) 程度になる可能性があるため、アルゴリズムは個々の魚を反復処理できません。 関連する作業は、魚の総数ではなく、水槽の数に依存する必要があります。 (N=3000) の場合、(O(N^2)) はすでに約 900 万回の操作であり、妥当ですが、タンクのサブセットの指数関数的な列挙は完全に不可能です。 

誤って対処しやすい特殊なケースがいくつかあります。 男性がまったくいない場合、答えはゼロです。 例えば、```
2
0 3
0 5
```水槽に魚が入っている場合でも、移動する必要はありません。 

タンクが完全に空の場合があります。 例えば、```
2
1 1
0 0
```一つの動きが必要です。 メスを最初の水槽から空の水槽に移します。 最初の水槽はオス専用になり、翌日にはオスがメスになります。 空のタンクを通常の女性専用タンクとして扱うと、この可能性が失われます。 

雄を含む水槽は、必ずしもそれらの雄が変換される水槽のままである必要はありません。 例えば、```
2
2 5
1 3
```3人の男性がいます。 2 つのタンクを個別に処理するには、最初のタンクでは (5+2-1=6) の移動、2 番目のタンクでは (3+1-1=3) の 9 つの移動がかかります。 より良い解決策は、1 匹のオスを 2 番目の水槽から 1 番目の水槽に移動し、そこで 3 匹のオス全員を処理することで、7 回の動作が必要になります。 公式のサンプル出力は 7 です。 

3つ目のサンプルは、```
4
2 3
0 0
3 1
0 0
```オスが5匹いて、空の水槽が2つあります。 答えは 5 です。空の水槽は、それ自体が雄を変換する水槽になる可能性があるため便利です。 

## アプローチ

 直接的な強引なアプローチは、どの水槽を最終的に雄魚を変換する水槽として使用するかを決定することです。 水槽のサブセットごとに、選択した水槽にすべての雄を割り当てるコストを計算し、最良の結果を維持できます。 これは正しいです。変換がトリガーされると、すべてのオスは最終的にメスがいない水槽に所属する必要があるからです。 

問題はサブセットの数です。 (2^N) 個の可能な選択肢があり、すべての (N) 個のタンクをスキャンしてサブセットを評価すると、(\Theta(N2^N)) の演算が得られます。 (N=3000) では、(2^{3000}) ですら実際の計算をはるかに超えています。 

重要な観察は、戦車の選択の寄与が、選択された他の戦車とは独立して表現できるということです。 すべての男性が 2 回の移動を必要とする単純な参照戦略から始めます。 1 つの動作では、雄を処理する水槽に入れ、別の動作では、その水槽が別の雄のために再利用されるときに作成された雌を除去します。 これにより、参照コストは次のようになります。 

[
 2\sum_i M_i.
 】

 ここで、実際に雄を処理するタンクの 1 つとしてタンク (i) を選択することを考えてみましょう。 元の (M_i) オスがそこに留まる場合、それぞれに 2 回の移動を支払う必要はありません。 代わりに、すべての (M_i) 人の男性を (F_i+M_i-1) の動きで処理できます。 基準コスト(2M_i)との差は、

 F_i-M_i-1。 
】

 したがって、タンク (i) を処理タンクとして割り当てると、答えは正確に変わります。 

[
 c_i=F_i-M_i-1。 
】

 同じ式で、空のタンクや女性専用タンクも処理されます。 (M_i=0) の場合、そのような水槽は他の水槽から雄を受け入れることができます。 その値は (F_i-1) のままです。 特に、空のタンクには (c_i=-1) があり、処理タンクとして使用することで得られる 1 回の動作の節約を正確に表しています。 

選択したすべての処理タンクには少なくとも 1 つのオスを受け入れる必要があるため、最大 (M=\sum_i M_i) 個のタンクを選択できます。 負の値 (c_i) は常に答えを改善するため、最も多くても (M) 個の負の値が必要です。 負の値がない場合でも、雄が存在するため処理タンクが 1 つ必要になるため、最小の (c_i) を選択します。 

これにより、指数サブセット検索がソート (N) 値になり、有用な負の値が取得されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (\シータ(N2^N)) | (O(N)) | 遅すぎる |
 | 最適 | (O(N\log N)) | (O(N)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての水槽を読み取り、雄の総数 (M) を計算します。 (M=0) の場合、魚は性別を変える必要がないため、答えはすぐにゼロになります。 
2. すべてのタンクについて、その値を計算します
 [
 c_i=F_i-M_i-1。 
】
 これは、元の雄 1 人あたり 2 回の移動の基準コストを使用する代わりに、そのタンクが処理タンクとして選択された場合のコストの変化です。 
3. すべて (c_i) を昇順に並べ替えます。 最も負の値が最大の節約を表すため、最初に考慮する必要があります。 
4. から始める`answer = 2 * M`。 これは処理タンクを選択する前の参考コストです。 
5. ソートされた配列から最大 (M) 個の負の値を取得し、それらを追加します。`answer`。 選択された各値は、少なくとも 1 頭の雄を受け入れ、(-c_i) 移動を保存する 1 つの戦車に対応します。 
6. 負の値がなく (M>0) の場合は、代わりに最小値を追加します。 処理タンクが必要であり、考えられるすべての選択肢のコスト変化がマイナスでない場合、最も安価なものが最適です。 
7. 結果の値を出力します。 

### なぜ効果があるのか

 最終的な戦略を検討し、少なくとも 1 人の雄が最終的にそこで変換される場合、そのタンクを処理タンクと呼びます。 すべての雄はまさに 1 つのそのような水槽に属します。 タンクが処理タンクでない場合は、元の雄をすべて別の場所に移動する必要があります。 タンクが処理タンクの場合、元のオスをそこに保持すると、オスあたり 2 回の移動の基準コストが (F_i+M_i-1) に置き換えられ、独立した調整 (F_i-M_i-1) が得られます。 唯一のグローバル制限は、各処理タンクに少なくとも 1 つの雄型タンクが必要であるため、最大 (M) 個の処理タンクが存在できることです。 その結果、考えられるすべての戦略の中で、最大 (M) 戦車までの最も有益なマイナス調整が最適なものとして選択されます。 どれも有益でない場合は、少なくとも 1 つの処理タンクが存在する必要があるため、最小の調整を選択する必要があります。 アルゴリズムはこれらの選択を正確に考慮するため、可能な限り最小限の動きを取得します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    total_males = 0
    costs = []

    for _ in range(n):
        m, f = map(int, input().split())
        total_males += m
        costs.append(f - m - 1)

    if total_males == 0:
        print(0)
        return

    costs.sort()

    answer = 2 * total_males
    used = 0

    for c in costs:
        if c >= 0 or used == total_males:
            break
        answer += c
        used += 1

    if used == 0:
        answer += costs[0]

    print(answer)

if __name__ == "__main__":
    solve()
```最初のループでは、雄の総数と各水槽の値 (F_i-M_i-1) のみが必要です。 その後、元の (M_i,F_i) ペアを保存する必要はありません。 

参照コストは次の場所に保存されます。`answer`として`2 * total_males`。 Python の整数には任意の精度があるため、フィッシュの合計数が最大値であってもオーバーフローの問題は発生しません。 

ソート後、負の値は最小値から最大値の順に処理されます。 選択後停止`total_males`なぜなら、選択されたすべての処理タンクには少なくとも 1 つの雄が含まれている必要があるためです。 実際には (N\le3000)、この制限はパフォーマンスよりも式の正確さに主に関係します。 

条件`used == 0`すべての (c_i) が非負である場合を処理します。 少なくとも 1 つの雄がいる場合は常に 1 つの処理タンクを選択する必要があるため、最小の値が追加されます。 

空のタンクでは自然に (c_i=-1) が生成されます。 これには特別なケースは必要ありません。これは、この式の便利な機能の 1 つです。

 | スペース | (O(N)) | タンク値のリストには (N) 個の整数が含まれています。 |

 ## 特殊なケース

 男性が存在しない場合、アルゴリズムは並べ替え前にゼロを返します。 のために```
2
0 0
0 100000
```男性の総数はゼロなので、移動する必要はありません。 

タンクが空の場合、その値は (-1) です。 のために```
2
1 1
0 0
```値は (-1,-1) で、男性が 1 人いるため、アルゴリズムはそのうちの 1 人を選択します。 初期の参照コストは 2 で、選択した戦車が寄与 (-1) するため、答えは 1 になります。 

タンクにメスはいるがオスがいない場合でも、別のタンクからオスを移動させることができるため、処理タンクとして有用です。 例えば、```
2
2 1
0 5
```値は (-2) と (4) です。 最初の水槽の方がターゲットとして適しているため、2 番目の水槽のメスはその場に留まり、オスは必要に応じて別の場所で処理されます。 この式では、元の雄を収容する必要があるという誤った要求はせずに、2 番目の戦車をターゲットの可能性があるとみなします。 

オスよりも有利なターゲット タンクが存在する場合、選択されたすべてのタンクには少なくとも 1 匹のオスが必要であるため、すべてを選択することはできません。 雄が 1 匹いて、空の水槽がたくさんあるとします。 実際にその男性を受け入れることができるターゲットは 1 人だけです。 したがって、アルゴリズムには最大でも`total_males`負の値。 

すべてのタンクが負でない値 (F_i-M_i-1) を持つ場合、処理タンクを選択しても基準コストが改善されることはありません。 少なくとも 1 人の男性がいる場合にはターゲットが必要であるため、アルゴリズムは最小値を選択します。 これはまさにサンプル 2 の状況です。値は 2 と 1 で、答えは (2\cdot3+1=7) になります。 

いくつかの水槽が負の値を持つ場合、それらを占有するのに十分な雄がいる限り、有用な水槽をすべて選択する必要があります。 サンプル 3 では、値は (0,-1,-3,-1) で、男性が 5 人いるため、3 つの負の値をすべて選択できます。 (2\cdot5=10) から開始すると、調整によって答えは (10-3-1-1=5) に減ります。
