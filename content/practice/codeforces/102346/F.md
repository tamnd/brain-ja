 ## 解決策
 ## 問題の理解

 すべての保存領域の結合が少なくとも (P%) の長方形領域をカバーするように、すべての川の周囲の整数距離 (r) を選択する必要があります。 

各川は軸に沿った線分です。 固定 (r) の場合、その保存領域は、セグメントをあらゆる方向に (r) 単位で拡張することによって得られる長方形になります。 川が ((x_1,y)) から ((x_2,y)) まで水平である場合、クリッピング前の長方形は次のようになります。 

[
 [x_1-r,x_2+r]\times[y-r,y+r]。 
】

 垂直な川の場合、類似の長方形は次のようになります。 

[
 [x-r,x+r]\times[y_1-r,y_2+r]。 
】

 テリトリー自体は長方形であるため、保存されているすべての長方形をテリトリーにクリップする必要があります。 必要な数量は、個々の面積の合計ではなく、これらすべての切り取られた長方形を合わせた面積です。これは、川が保存領域が重なるほど十分に近い場合があるためです。 

入力には最大でも (10^4) 個の河川が含まれますが、すべての座標は最大でも (10^5) 個です。 したがって、テリトリーは (10^{10}) ほどの面積を持つことができます。 これにより、平面を単位グリッドとして扱い、すべてのセルをチェックすることが直ちに除外されます。 このようなグリッドが 1 つでも (10^{10}) 個のセルを含む可能性があります。 個々の点やセルではなく、長方形の境界を操作する必要があります。 

答えにも限界があります。 領域に幅 (W) と高さ (H) があるものとします。 (r\ge\max(W,H)) の場合、すべての河川はすでに領域内にあり、拡張は可能なすべての水平および垂直座標に達するため、拡張されたすべての河川の長方形は領域全体をカバーします。 したがって、答えは (0) と (\max(W,H)) の間にあり、座標は最大でも (10^5) であるため、二分探索反復は約 (17) 回だけで済みます。 

不注意な実装を黙って破壊してしまう可能性のあるエッジケースがいくつかあります。 1つ目はオーバーラップです。 例えば、```
2
0 0 4 0
0 0 4 0
50
0 0 4 4
```両方の川は同じです。 (r=1) では、それらの保存領域は同じ (4\times2) の長方形であるため、保存領域は (8)、つまり (4\times4) 領域のちょうど (50%) になります。 答えは (0) ではなく (1) であり、2 つの長方形領域を加算した値でもありません。 単純に長方形の面積を合計するソリューションでは、同じ領域が 2 回カウントされます。 

領域に対するクリッピングもエラーのよくある原因です。 考慮する```
1
0 0 0 4
25
0 0 4 4
```(r=1) では、拡張された長方形は ([-1,1]\times[-1,5]) ですが、領域内には ([0,1]\times[0,4]) のみが存在します。 その面積は(4)、ちょうど(25%)なので、答えは(1)です。 クリッピングを忘れると、領域 (12) が誤って使用されてしまいます。 

場合 (r=0) も重要です。 線分の場合、保存された長方形の幅または高さはゼロになり、したがって面積もゼロになります。 (P\ge1) なので、(r=0) が答えになることはあり得ません。 下位エンドポイントがすでに実行可能であると仮定する二分探索では、無効な不変式が存在します。 

最後に、2 つの長方形は、正の交差領域を持たずにエッジに沿って接触することができます。 例えば、```
2
0 0 2 0
2 0 2 2
50
0 0 4 4
```(r=1) では、拡張された長方形は正の領域と重なりますが、より小さい距離では境界は単に接触するだけです。 長方形結合では概念的に半開スイープ間隔を使用する必要があるため、境界に人工的な領域が割り当てられることなく、間隔 ([y_1,y_2]) が幾何学的な長さ (y_2-y_1) に寄与します。 

## アプローチ

 直接的なアプローチは、考えられるすべての整数 (r) を試し、すべて (N) の拡張された四角形を構築し、それらの結合領域を計算することです。 標準的な長方形和集合スイープには (O(N\log N)) かかるため、すべての (O(10^5)) 個の可能な距離を試行すると (O(10^5N\log N)) のコストがかかります。 (N=10^4) の場合、これは (10^{10}) 個の対数スケール演算のオーダーであり、制限をはるかに超えています。 

ブルート フォース アプローチは、各候補 (r) について、問題によって定義された領域を正確に計算するため、正しいです。 その弱点は、答えが大きな順序付けられた範囲から選択された整数であり、本質的に同じ幾何学的問題を繰り返し解くことです。 

重要な観察は、(r) では保存領域が単調であることです。 (r) を大きくすると、保存されているすべての長方形のみが拡大されます。 したがって、ある距離 (r) が十分な領域を維持する場合、距離が大きくなるたびに十分な領域も維持されます。 したがって、最小の有効な (r) の検索は二分探索です。 

残る 1 つの幾何学的なサブ問題は、最大 (N) 個の軸に整列した長方形が与えられ、それらの和集合が十分な領域をカバーするかどうかを計算することです。 垂直スイープ ラインはこれを効率的に解決します。 各長方形の左側に開始イベントが作成され、右側に終了イベントが作成されます。 2 つの連続するイベント (x) 座標間では、アクティブな四角形のセットは変化しないため、結合のカバー高さは一定になります。 その高さが (L) で、スイープが (\Delta x) だけ移動すると、得られる面積は (L\Delta x) になります。 

覆われた高さを動的に維持するために、すべての長方形 (y) 座標を圧縮し、セグメント ツリーを使用します。 各ノードは、その間隔を完全にカバーするアクティブな四角形の数と、少なくとも 1 つの四角形によってカバーされる実際の長さを保存します。 正のカバー数は、ノード間隔全体がカバーされていることを意味します。 それ以外の場合、カバーされる長さは 2 つの子の合計になります。 

このように、総当たりの解決策は、長方形の結合によって正確な面積が得られるため機能しますが、考えられるすべての (r) に対して同じ計算を繰り返すと失敗します。 単調性により検索は (O(\log 10^5)) 個の候補に減りますが、スイープ ラインとセグメント ツリーでは各候補が (O(N\log N)) チェックされます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(10^5N\log N)) | (O(N)) | 遅すぎる |
 | 最適 | (O(N\log N\log 10^5)) | (O(N)) | 承認済み |

 公式問題ページでは、制限時間は 3 秒、メモリ制限は 256 MB と記載されています。 オリジナルのコンテスト PDF では、出力 (5) と (2) を含む 2 つのサンプル ケースが確認されています。 

## アルゴリズムのチュートリアル

 1. すべての河川を読み取り、座標が順序付けられるように各セグメントを正規化します。 テリトリーの境界を保存し、その総面積を計算します。 
2. 候補 (r) を受け取り、保存された結合が必要なパーセンテージに達したかどうかを返す関数を定義します。 必要な面積は、次のように整数演算で計算されます。 

[
 \left\lceil\frac{P\cdot A}{100}\right\rceil,
 】

 ここで、(A) はテリトリーの面積です。 上限を使用すると、浮動小数点計算が完全に回避されます。

1. すべての川について、その境界四角形を両座標方向に (r) だけ拡張します。 その長方形を領域と交差させます。 交差点の幅または高さがゼロの場合、面積には寄与しないため無視できます。 
2. 残りのすべての長方形を 2 つのスイープ イベントに変換します。 左側の境界はその (y) 間隔をアクティブ セットに追加し、右側の境界はそれを削除します。 セグメント ツリーでは基本的な間隔の境界として両方の (y) 座標が必要であるため、両方の (y) 座標を収集します。 
3. イベントを (x) で並べ替え、収集されたすべての (y) 座標を圧縮します。 2 つの連続するイベント位置の間では、アクティブ セットは変化しません。 したがって、セグメント ツリーは、水平ストリップ全体にわたってどのくらいの垂直長さがカバーされているかを正確に示します。 
4. イベントを左から右にスイープします。 現在 (x) でイベントを処理する前に、

 [
 (\text{現在 }x-\text{前 }x)\times\text{カバーされた高さ}
 】

 地域へ。 次に、現在 (x) で発生するすべての追加と削除を適用します。 等しい (x) 座標を 1 つのグループとして処理すると、同じ位置で発生するイベント間に人為的な水平幅が導入されることが回避されます。 

1. 蓄積面積が必要な面積に達したら直ちに停止します。 これは安全です。結合領域はスイープが進行するにつれてしか増加しないため、その後のイベントによってすでに成功したチェックが失敗することはありません。 
2. 実行可能な最小の (r) を二分探索します。 下限を (0) に設定します。これは、すべての河川の (r=0) に面積ゼロの保存領域があるため不可能です。また、上限を (\max(W,H)) に設定します。これは常に領域全体をカバーします。 中間点が実現可能な場合は、それを可能な答えとして保持し、より小さい値を検索します。 それ以外の場合は、より大きな値を検索します。 

二分探索の背後にある不変条件は、現在の答えを下回るすべての値は実行不可能であることがわかっており、現在の上限は実行可能であるということです。 セグメント ツリーの不変条件は、すべてのノードの格納された長さが、少なくとも 1 つのアクティブな四角形によってカバーされる (y) 間隔の部分に正確に一致するということです。 これら 2 つの不変条件を組み合わせることで、すべての実現可能性の決定が正確であること、および二分探索が有効な最小の整数距離を返すことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    rivers = []

    for _ in range(n):
        x1, y1, x2, y2 = map(int, input().split())
        if x1 > x2:
            x1, x2 = x2, x1
        if y1 > y2:
            y1, y2 = y2, y1
        rivers.append((x1, y1, x2, y2))

    p = int(input())
    tx1, ty1, tx2, ty2 = map(int, input().split())

    if tx1 > tx2:
        tx1, tx2 = tx2, tx1
    if ty1 > ty2:
        ty1, ty2 = ty2, ty1

    width = tx2 - tx1
    height = ty2 - ty1
    total_area = width * height
    need = (total_area * p + 99) // 100

    def enough(r):
        events = []
        ys = []

        for x1, y1, x2, y2 in rivers:
            lx = max(tx1, x1 - r)
            rx = min(tx2, x2 + r)
            ly = max(ty1, y1 - r)
            ry = min(ty2, y2 + r)

            if lx >= rx or ly >= ry:
                continue

            events.append((lx, 1, ly, ry))
            events.append((rx, -1, ly, ry))
            ys.append(ly)
            ys.append(ry)

        if not events:
            return False

        ys = sorted(set(ys))
        index = {y: i for i, y in enumerate(ys)}

        m = len(ys) - 1
        if m <= 0:
            return False

        cover = [0] * (4 * m)
        length = [0] * (4 * m)

        def update(node, left, right, ql, qr, delta):
            if ql <= left and right <= qr:
                cover[node] += delta
            else:
                mid = (left + right) // 2
                if ql <= mid:
                    update(node * 2, left, mid, ql, qr, delta)
                if qr > mid:
                    update(node * 2 + 1, mid + 1, right, ql, qr, delta)

            if cover[node] > 0:
                length[node] = ys[right + 1] - ys[left]
            elif left == right:
                length[node] = 0
            else:
                length[node] = (
                    length[node * 2] +
                    length[node * 2 + 1]
                )

        events.sort(key=lambda e: e[0])

        area = 0
        prev_x = events[0][0]
        i = 0

        while i < len(events):
            x = events[i][0]

            area += length[1] * (x - prev_x)
            if area >= need:
                return True

            while i < len(events) and events[i][0] == x:
                _, delta, y1, y2 = events[i]
                l = index[y1]
                rr = index[y2] - 1
                if l <= rr:
                    update(1, 0, m - 1, l, rr, delta)
                i += 1

            prev_x = x

        return area >= need

    lo = 0
    hi = max(width, height)

    while lo < hi:
        mid = (lo + hi) // 2
        if enough(mid):
            hi = mid
        else:
            lo = mid + 1

    print(lo)

if __name__ == "__main__":
    solve()
```入力が一度読み取られると、川はすぐに正規化されるため、その後の実行可能性チェックでは座標を均一に扱うことができます。 テリトリーも正規化されていますが、有効な入力ではすでに左下隅と右上隅が意図した順序で表示されています。 

内部`enough`、すべての川は切り取られた長方形になります。 の使用`max`そして`min`領土の境界に近い、または領土の境界に直接ある河川を処理するものです。 切り取られた幅または高さがゼロの長方形は、領域がないためスキップされます。 

セグメント ツリーは、連続する圧縮座標間の基本 (y) 間隔を表します。 圧縮された座標が (y_0,y_1,\ldots,y_k) の場合、葉 (i) は幾何学的間隔 ([y_i,y_{i+1}]) を表し、その長さは (y_{i+1}-y_i) になります。 これが、更新範囲が次で終了する理由です。`index[y2] - 1`ではなく、`index[y2]`。 後者を更新すると、長方形に属さない (y_2) 上の区間がカバーされます。 

の`cover`value は、セグメント ツリー ノードを完全にカバーするアクティブな四角形の数を記録します。 正の値の場合、子に関係なくノード間隔全体がカバーされます。 ゼロの場合、カバーされる長さは子から取得されます。 これは、標準の結合領域セグメントツリーの不変条件です。 

すべての面積計算では整数が使用されます。 座標は最大 (10^5) であるため、最大領域領域は (10^{10}) となり、Python 整数はすべての中間値を簡単に処理できます。 さらに重要なことは、パーセンテージの比較では浮動小数点が使用されないため、小さな領域の値 (33%) などに丸め誤差が生じることがありません。 

二分探索では、`lo < hi`そして割り当てます`hi = mid`候補が実行可能な場合。 これは二分探索の下限形式であるため、ループが終了すると、`lo`は正確に最初の実行可能な整数です。

            events.append((lx, 1, ly, ry))
            events.append((rx, -1, ly, ry))
            ys.append(ly)
            ys.append(ry)

        if not events:
            return False

        ys = sorted(set(ys))
        pos = {y: i for i, y in enumerate(ys)}

        m = len(ys) - 1
        if m <= 0:
            return False

        cover = [0] * (4 * m)
        length = [0] * (4 * m)

        def update(node, left, right, ql, qr, delta):
            if ql <= left and right <= qr:
                cover[node] += delta
            else:
                mid = (left + right) // 2

                if ql <= mid:
                    update(node * 2, left, mid, ql, qr, delta)

                if qr > mid:
                    update(node * 2 + 1, mid + 1, right, ql, qr, delta)

            if cover[node]:
                length[node] = ys[right + 1] - ys[left]
            elif left == right:
                length[node] = 0
            else:
                length[node] = length[node * 2] + length[node * 2 + 1]

        events.sort()
        area = 0
        prev_x = events[0][0]
        i = 0

        while i < len(events):
            x = events[i][0]
            area += length[1] * (x - prev_x)

            if area >= need:
                return True

            while i < len(events) and events[i][0] == x:
                _, delta, y1, y2 = events[i]
                l = pos[y1]
                r = pos[y2] - 1

                if l <= r:
                    update(1, 0, m - 1, l, r, delta)

                i += 1

            prev_x = x

        return area >= need

    lo = 0
    hi = max(width, height)

    while lo < hi:
        mid = (lo + hi) // 2

        if enough(mid):
            hi = mid
        else:
            lo = mid + 1

    return str(lo)

 ## 特殊なケース

 重複する保護地域については、3 つの同一の河川を考慮します。```
3
0 0 10 0
0 0 10 0
0 0 10 0
20
0 0 10 10
```(r=1) では、すべての川が面積 (10) のまったく同じ長方形 ([0,10]\times[0,1]) を生成します。 目標は(20)なので、(r=1)では足りず、答えは(2)となります。 スイープ ラインは、同じ (y) 間隔にわたってカバー カウントを 3 に保ちますが、保存されたカバーされた長さは (3) ではなく (1) のままです。 したがって、結果として得られる面積は (r=1) で (10) になります。これは、カバー数とカバー長が別個の状態でなければならない理由を示しています。 

クリッピングには、次を使用します```
1
0 0 0 4
25
0 0 4 4
```(r=1) では、境界のない拡張された四角形は ([-1,1]\times[-1,5]) になります。 クリッピングすると ([0,1]\times[0,4]) に変更され、その面積は (4) になります。 テリトリー面積は (16) なので、正確に (25%) となり、二分探索では (1) が返されます。 イベント構築はクリップされた四角形のみを受け取るため、領域外のエリアはスイープに入ることができません。 

(r=0) の場合、次のように考えます。```
1
0 0 10 0
1
0 0 10 10
```展開された長方形は ([0,10]\times[0,0]) で、高さはゼロです。 実現可能性チェックでは、次の理由により破棄されます。`ly >= ry`。 したがって、面積はゼロであり、二分探索はゼロより上に移動します。 (r=1) では、長方形は ([0,10]\times[0,1]) となり、面積は (10) となり、すでに必要な (1%) に達しています。 答えは(1)です。 

長さゼロの川の場合、次のように考えます。```
1
5 5 5 5
1
0 0 10 10
```セグメントには長さはありませんが、それでも有効な点です。 (r=1) では、保存される長方形は ([4,6]\times[4,6]) で、面積は (4) で、(100) 単位の領域の (1%) を保存するのに十分です。 アルゴリズムは、(x) 座標が等しいため、セグメントを垂直セグメントとして扱い、正しい (2r\times2r) 正方形を生成します。 

単に接触しているだけの長方形の場合、セグメント ツリーは別個の (y) 座標間の基本的な間隔で機能し、すべての寄与で次のような座標の差が使用されます。`ys[right + 1] - ys[left]`。 共有境界の幾何学的長さはゼロであるため、それ自体は領域に寄与しません。 これにより、2 つの整数座標が隣接しているというだけの理由で 1 単位を追加するというよくある間違いを回避できます。 

最後に、最大入力サイズの場合、(10^4) 個の同一の河川は、(10^4) 個の個別の幾何学的グリッドではなく、実行可能性チェックごとに (2\cdot10^4) 個のスイープ イベントを生成します。 セグメント ツリーは依然として結合を 1 回だけ表します。 アルゴリズムの実行時間は、領域内の潜在的な (10^{10}) 個のセルではなく、河川の数とそのイベントの境界によって決まります。
