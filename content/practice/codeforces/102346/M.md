 ## 解決策
 ## 問題の理解

 を取り揃えております。`N`ポップコーンバッグ、どこに`P[i]`袋の中のポップコーンの量です`i`。 がある`C`競合他社、そして各競合他社が最大で食べることができるのは、`T`1秒あたりのポップコーン。 

バッグは連続したセグメントに分割する必要があります。 競合他社は 1 つのセグメントを受け取りますが、競合他社は空のセグメントを受け取る可能性があるため、使用するセグメントの数は 1 つよりも少なくなります。`C`空でないセグメントは許可されます。 袋を参加者間で分割することはできないため、各セグメントのポップコーンの合計を 1 人の参加者が食べなければなりません。 すべての競技者が同時に作業するため、合計競技時間は最も遅い競技者によって決まります。 

を含むセグメントの場合`S`ポップコーン、食べる時間は`ceil(S / T)`。 このような最大時間を最小化する連続パーティションを選択し、その最小秒数を出力する必要があります。 

配列には最大で次のものを含めることができます`10^5`バッグ。 各バッグには最大でも次のものが含まれます`10^4`ポップコーン、合計金額が達することができます`10^9`。 二次アルゴリズムはすでに次のように実行されます。`10^10`合理的な範囲をはるかに超えた最悪の場合の運用。 線形に近いものが必要です。`O(N log N)`。 競争相手の数も次のように大きくなる可能性があります`10^5`したがって、二次関数に依存するアプローチは、`C`は不適切です。 

不正な実装が露呈する可能性のある境界ケースがいくつかあります。 バッグが1つしかない場合、たとえば```
1 3 4
5
```答えは`2`、競合他社の 1 人が必要とするため、`ceil(5 / 4) = 2`秒。 不注意なパーティションベースのソリューションは、単一のバッグを複数の競合他社に誤って分配しようとする可能性がありますが、バッグは完全に 1 人の競合他社に属さなければならないため、これは禁止されています。 

もう 1 つのケースは、バッグよりも競合相手が多い場合です。```
2 5 3
4 7
```答えは`3`。 2 つのバッグを 2 人の競技者に割り当てることができ、他の 3 人の競技者は何もしません。 競合他社の数を、必要な空ではないグループの数とまったく同じように扱うと、この有効な取り決めが拒否されます。 

3 番目のエッジ ケースは、1 つのバッグが他の考えられるすべてのグループよりも大きい場合に発生します。```
3 2 1
1 1 5
```答えは`5`。 入っている袋は`5`他の袋がどのように分配されるかに関係なく、ポップコーンにはすでに 5 秒かかります。 個々のバッグのサイズを考慮せず、合計金額のみをバランスさせるアルゴリズムでは、より小さい答えを誤って予測する可能性があります。 

最後に、競合他社の合計を計算した後に四捨五入を行う必要があります。 のために```
2 2 4
5 5
```各競合他社が必要とする`ceil(5 / 4) = 2`秒なので、答えは`2`、 ない`ceil(10 / (2 * 4)) = 2`偶然です。 他のケースでは区別が重要であるため、ソリューションでは競合他社のポップコーンを平均するのではなく、整数の時間制限を直接推論する必要があります。 

## アプローチ

 直接的な総当りのソリューションでは、連続するバッグ間に境界を設定するあらゆる可能な方法が考慮されます。 がある`N - 1`可能な境界があり、それぞれを選択することも選択しないこともできます。`2^(N-1)`異なるパーティション。 各パーティションについて、すべての競技者に割り当てられたポップコーンの合計を計算し、必要な最大の食事時間を維持することができます。 すべての合法的な連続割り当ては、そのような境界セットの 1 つに正確に対応するため、すべてのパーティションにわたって最小値を取ることは正しいことです。 

問題はパーティションの数です。 いつ`N = 10^5`、可能性の数は`2^99999`、それは天文学的な大きさです。 たとえ各パーティションの評価に一定の時間しかかからなかったとしても、検索はすでに不可能になります。 素直な気持ちで`O(N)`パーティションごとの評価、最悪の場合の作業は`O(N * 2^N)`。 このアプローチは小さな配列にのみ有用であり、実用的なアルゴリズムではなく、最適なアルゴリズムの定義を提供します。 

有益な観察は、実際には最適なパーティションをすぐに構築する必要はないということです。 代わりに、競争全体が 1 時間以内に終了する必要があると推測するとします。`X`秒。 その場合、各競技者は最大でも食べることができます`X * T`ポップコーン。 質問ははるかに単純になります。配列は最大で次のように分割できますか?`C`連続したグループ。各グループの合計は最大です`X * T`?

 固定容量については、その質問に答える貪欲な方法があります。 配列を左から右にスキャンし、容量を超えない限り、現在の競合他社にバッグを追加し続けます。 次のバッグの金額が大きくなりすぎる場合は、新しいバッグを開始します。 すべてのポップコーンの量はプラスであるため、現在のセグメントにさらに多くのバッグを投入しても、後で必要となる競合他社の量を減らすことはできません。 したがって、貪欲パーティションは、その容量に対して可能な最小数のセグメントを使用します。 

実現可能性も単調です。 もし`X`すべての競合他社がより大きな容量を獲得できるため、秒数で十分ですが、さらに大きな秒数でも十分です。 もし`X`秒は不可能であり、それより小さな値も不可能です。 この単調な性質により、答えに対する二分探索が可能になります。 

の間で二分探索ができます`1`2番目と`ceil(sum(P) / T)`秒。 候補時間ごとに次の値を掛けます。`T`競合他社が処理できる最大のポップコーンを取得するために、貪欲な実現可能性チェックを実行します。 結果として生じる複雑さは、`O(N log(sum(P) / T))`、これは十分に高速です`N = 10^5`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |`O(N * 2^N)`|`O(N)`| 遅すぎる |
 | 二分探索 + 貪欲 |`O(N log(sum(P) / T))`|`O(N)`| 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む`N`、`C`、`T`そしてポップコーンの量の配列。 答えの上限が得られるため、ポップコーンの合計も計算します。 
2. 二分探索の下限を次のように設定します。`1`2 番目と上限`ceil(sum(P) / T)`秒。 上限は、すべてのバッグを 1 人の競技者に渡すことに相当します。 あるかもしれないけれども`C`競合他社の場合、空でない競合他社は 1 つだけ許可されます。 
3. 候補時間について`mid`、1 人の競合他社の能力を次のように計算します。`mid * T`。 ここで、すべてのバッグを最大で割り当てられるかどうかを尋ねます。`C`合計がこの容量を超えない連続したグループ。 
4. アレイを左から右にスキャンします。 現在の競合他社に割り当てられたポップコーンの量を維持します。 次のバッグを追加しても容量内に収まる場合は、現在のセグメントに保持します。 容量を超えた場合は、そのバッグで新しいセグメントを開始し、使用する競合他社の数を増やします。 
5. 個別のバッグが容量を超える場合、候補時間は直ちに不可能になります。 それ以外の場合、配列全体をスキャンした後、必要な空でないセグメントの数が最大でも次の場合に候補が実行可能になります。`C`。 
6. 候補が実行可能な場合は、答えが小さくなる可能性があるため、下半分を検索します。 時間がかかるので無理な場合は上半分を探してください。 
7. 二分探索間隔に値が 1 つ含まれるまで続行します。 この値は、有効なパーティションが存在する最小秒数です。 

### なぜ効果があるのか

 固定容量の場合、貪欲スキャンは、次のセグメントを開始する前に、できるだけ大きなセグメントを作成します。 有効なパーティションの最初のセグメントを考えてみましょう。 すべてのバッグの量は正であるため、容量内に留まりながらその最初のセグメントを別のバッグで拡張することは、そのバッグを次の競合他社に残すよりも残りのサフィックスを分割するのを難しくすることはできません。 この引数を繰り返すことは、貪欲な方法により、配列全体に必要なセグメントの数が最小限に抑えられることを意味します。 

したがって、実現可能性チェックは正しいです。 述語は「以内に終了できる」`X`秒」は増加するため単調です`X`すべての競合他社の能力を高めるだけです。 したがって、二分探索では実行可能な最小値が見つかります。`X`、まさに最適な競技時間です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, c, t = map(int, input().split())
    p = list(map(int, input().split()))

    total = sum(p)

    def feasible(seconds):
        capacity = seconds * t
        competitors = 1
        current = 0

        for x in p:
            if x > capacity:
                return False

            if current + x <= capacity:
                current += x
            else:
                competitors += 1
                current = x

                if competitors > c:
                    return False

        return True

    lo = 1
    hi = (total + t - 1) // t

    while lo < hi:
        mid = (lo + hi) // 2

        if feasible(mid):
            hi = mid
        else:
            lo = mid + 1

    print(lo)

if __name__ == "__main__":
    solve()
```の`feasible`関数は、アルゴリズムから貪欲なパーティションを実装します。`capacity`候補秒数の間に 1 人の競技者が食べることができる最大量です。 変数`current`現在の競合他社に割り当てられたポップコーンを保管します。`competitors`空ではないセグメントが作成された数をカウントします。 

テスト`x > capacity`仕切りがないとバッグを分割できないため、必須です。 たとえ未使用の競合他社が多数いたとしても、候補者の容量を超える単一のバッグを割り当てることは法的にできません。 

いつ`current + x`容量を超えると、現在のセグメントが閉じられ、新しいセグメントが始まります。`x`。 以前のバッグを新しい競合他社に移動する理由はありません。そうしても最初のセグメントが小さくなるだけで、残りのサフィックスに必要なセグメントの数を減らすことができないからです。 

上限は整数の上限除算を使用します。`(total + t - 1) // t`。 この値は、1 人の競技者がポップコーンをすべて食べた場合に必要な時間を表します。 未使用の競合他社が許可されるため、これは常に有効な上限です。 

二分探索では、`lo < hi`したがって、ループが終了すると、両方の境界は同じ最小実行時間を表します。 Python の整数には任意の精度があるため、次のような乗算が可能です。`seconds * t`オーバーフローすることはできません。

def solve():

    n, c, t = map(int, input().split())
    p = list(map(int, input().split()))

    def feasible(seconds):

        competitors = 1
        current = 0

        for x in p:
            if x > capacity:
                return False

            if current + x <= capacity:
                current += x
            else:
                competitors += 1
                current = x

    while lo < hi:
        mid = (lo + hi) // 2
        if feasible(mid):
            hi = mid
        else:
            lo = mid + 1

    print(lo)

    old_stdout = sys.stdout

    try:
        sys.stdin = io.StringIO(inp)
        sys.stdout = io.StringIO()
        solve()
        return sys.stdout.getvalue().strip()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout
