 ## 解決策
 ## 問題の理解

 マフィアの階層は、メンバー 1 をルートとするルート付きツリーを形成します。 他のすべてのメンバーには直属の上司が 1 人だけ存在するため、すべてのメンバーが上司に至る独自のパスを持っています。 

予言者がメンバーを特定すると、警察はそのメンバーを逮捕し、逮捕されたメンバーを繰り返し尋問して上司に関する情報を入手することができます。 その結果、1 つのメンバーを選択すると、そのメンバーからルートまでのパス上のすべての頂点が効果的に停止されます。 

警察は予言者にせいぜいK人のメンバーについて尋ねることができる。 タスクは、ルート パスの結合にできるだけ多くの個別の頂点が含まれるように、これらのメンバーを選択することです。 

入力は、N と K までのルート ツリーを記述し、その後 2 から N までのすべての頂点の親を記述します。出力は、逮捕できる個別のマフィア メンバーの最大数です。 

N が 100000 までの場合、すべてのペア、すべてのサブセット、または 2 次動的プログラムを含むアルゴリズムはコストが高すぎます。 O(N log N) 付近の解決策は快適に適切ですが、K が大きい場合は O(NK) でも 10^10 の演算に達する可能性があります。 

不注意な実装が失敗する可能性があるエッジケースがいくつかあります。 K が 1 の場合、答えは N ではなく、単純に最も深いルートから頂点までのパスの長さになります。たとえば、次のようになります。`N = 3`、`K = 1`、そして両親`1 1`, どちらかの子供を選ぶと上司とその子供が逮捕されるので、答えは2です。 

いくつかのブランチの深さが等しい場合、別の微妙なケースが発生します。 と`N = 5`、`K = 2`、そして両親`1 1 2 2`、ツリーにはルート 1、子 2 と 3、そして 2 の下に子 4 と 5 があります。4 つの逮捕を選択します。`1,2,4`3 を選択すると、頂点 3 のみが追加され、4 が得られます。代わりに 4 と 5 の両方を選択すると、頂点 3 が追加されます。`1,2,4,5`また、4. 深さが同点の場合、解決策はどの子が最長の分岐として選択されるかに依存してはなりません。 

3 番目のケースはスターです。 と`N = 5`、`K = 4`、そして両親`1 1 1 1`、選択されたすべてのリーフは、最初の選択後に 1 つの新しい頂点を提供します。 答えは 5 です。完全なルートからリーフへのパスを一度だけ考慮する実装では、これらの独立した分岐を見逃す可能性があります。 

## アプローチ

 直接的な解決策は、最大 K 個の選択されたメンバーの可能なすべてのコレクションを試行し、選択された各メンバーからルートまでの親ポインターをたどり、結果として得られる結合内の個別の頂点をカウントします。 これは正しいです。なぜなら、逮捕されたセットはまさにこれらのルート パスの結合であるからです。 ただし、`C(N,K)`正確に K 個のメンバーが選択された場合に考えられる選択肢があり、各選択肢の処理自体に O(N) 回の作業が必要になる可能性があります。 最悪の場合、これは Θ(N · C(N,K)) となり、K が N/2 付近の場合は指数関数的になります。 考えられるすべての選択されたリーフを試す、それほど単純ではない実装であっても、制限をはるかに超えています。 

有用な観察は、いくつかのルート パスが選択されると、すでに拘束されている頂点が接続されたルート付きサブツリーを形成するということです。 残りの考えられるすべての寄与は、1 つのエッジによってその停止領域に接続された別個のサブツリー内にあります。 

現在停止している領域が頂点 v に到達し、子 c が v の下の選択された継続の一部ではないとします。c のサブツリー全体はまだ変更されていません。 そのサブツリー内で追加の Seer 使用を 1 回費やした場合、取得できる新しい頂点の最大数は、c から始まる最も深い下向きのパスの長さになります。 

これにより、自然な貪欲なプロセスが実現します。 ツリー全体のルートから頂点までの最長のパスから始めます。 そのパスを選択した後は、パスに沿ってスキップされたすべての子ブランチが独立した候補になります。 現在利用可能なすべての候補ブランチの中で、最大の深さを持つブランチを選択します。 そのブランチが選択されたら、それ自体の最も深いパスに沿って歩き、スキップされたすべての子ブランチを候補セットに追加します。 

重要な特性は、各候補が完全に手付かずのサブツリーを表すということです。 その深さは、正確に、1 つの選択がそのサブツリーから寄与できる新しい頂点の最大数です。 利用可能な短い枝を選択すると、最も長い枝を選択する場合よりもすぐに新しい頂点を得ることができませんが、最も長い枝を選択すると、残りの側枝がすべて公開されて将来の選択にさらされます。 これにより、貪欲な選択に最適な構造が与えられます。 

利用可能なブランチを最大ヒープ内に維持できます。 前処理 DFS が計算します`depth[v]`、v から始まる最長の下向きパス上の頂点の数と、`best[v]`、そんな道を歩み始める子。 ブランチが選択されるたびに、次のようになります。`best`ポインターを作成し、他のすべての子をヒープにプッシュします。 

ブルートフォースアプローチと最適アプローチは次のように要約できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | Θ(N・C(N,K)) | O(N) | 遅すぎる |
 | 最適 | O(N log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 親配列からルート付きツリーを構築します。 頂点 1 はルートであり、すべての頂点です`v > 1`は、指定された親の子リストに追加されます。 
2. コンピューティング`depth[v]`、 どこ`depth[v]`は、v から始まる最長の下向きパス上の頂点の数を意味します。同時に、`best[v]`、そんな最長の道を歩み始める子。 葉には`depth[v] = 1`そして最高の子もいない。 
3.置く`(depth[1], 1)`最大ヒープに入れます。 これは、ルートの下のどこからでも開始できる最初の利用可能なパスを表し、可能な限り最長の最初の寄与は、ルートからの最も深いパスになります。 
4. K 回繰り返します。 最大の深さを持つ候補をヒープから削除し、その深さを回答に追加します。 候補ルートは未処理のサブツリーに属しているため、その選択された下向きのパス上のすべての頂点が新たに捕捉されます。 
5. 選択した候補ルートから始めて、次のようにします。`best[v]`葉っぱに届くまで。 訪問したすべての頂点 v で、次のすべての子を検査します。`best[v]`。 このような各子は、選択されたパスによってスキップされたサブツリーを開始するため、プッシュ`(depth[child], child)`山の中へ。 
6. K 回選択した後の累積合計は、個別に停止された頂点の数になります。 すべてのヒープ候補はそのサブツリーがすでに選択されているパスから分離された場合にのみ作成されるため、選択されたパスは新しく追加された同じ頂点としてカウントされません。 

不変条件は、すべてのヒープ エントリがすでに逮捕された領域に接続された 1 つの完全に未処理のサブツリーを表し、その格納深度が 1 つのシーア クエリを使用してそのサブツリーから取得できる最大の寄与であるということです。 選択されたパスは常に、利用可能な最大の寄与を取得します。 一度選択されると、その側枝はまさに新しい独立した選択肢になります。 したがって、ヒープには常に考えられる次の寄与がすべて記述されており、その最大値を取ることがあらゆる段階で最適な貪欲な選択となります。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve(data=None):
    if data is None:
        data = sys.stdin.buffer.read().split()

    it = iter(data)
    n = int(next(it))
    k = int(next(it))

    children = [[] for _ in range(n)]

    for v in range(1, n):
        p = int(next(it)) - 1
        children[p].append(v)

    # Iterative DFS order, avoiding recursion depth problems on a chain.
    order = []
    stack = [0]

    while stack:
        v = stack.pop()
        order.append(v)
        for c in children[v]:
            stack.append(c)

    # depth[v] = number of vertices in the longest downward path from v.
    # best[v] = child starting that path.
    depth = [1] * n
    best = [-1] * n

    for v in reversed(order):
        best_depth = 0
        best_child = -1

        for c in children[v]:
            if depth[c] > best_depth:
                best_depth = depth[c]
                best_child = c

        if best_child != -1:
            depth[v] = best_depth + 1
            best[v] = best_child

    # Python has a min-heap, so store negative depths.
    heap = [(-depth[0], 0)]
    answer = 0

    for _ in range(k):
        neg_len, root = heapq.heappop(heap)
        answer += -neg_len

        v = root

        # Select the longest path from this candidate subtree.
        while v != -1:
            chosen = best[v]

            # Every other child starts a new available subtree.
            for c in children[v]:
                if c != chosen:
                    heapq.heappush(heap, (-depth[c], c))

            v = chosen

    return str(answer)

if __name__ == "__main__":
    print(solve())
```実装の最初の部分では、隣接リストを構築します。 入力は 1 から始まる番号付けを使用して 2 から N までの各頂点を識別しますが、コードはすべてを 0 から始まるインデックスに即座に変換します。 したがって、頂点 1 はインデックス 0 になります。 

反復 DFS では、親から子の順序が作成されます。 この順序を逆にすると、親の前に子が配置されます。これはまさに計算に必要な順序です。`depth[v]`すでに計算された子の値から。 ツリーは長さ 100,000 のチェーンになる可能性があり、Python のデフォルトの再帰呼び出しスタックを超える可能性があるため、反復トラバーサルが使用されます。 

の`depth`計算により最大値を持つ子が選択されます`depth`。 現在の頂点自体が 1 つの頂点に寄与するため、その値は 1 に最良の子の値を加えたものになります。 の`best`配列は、どの子がその最大値を生成したかを記憶します。 

ヒープには、使用可能なサブツリーが格納されます。 パイソンの`heapq`は最小ヒープであるため、コードは負の深さを格納して、最大の深さが最初に表示されるようにします。 

候補が削除されると、その候補に保存されている深さが回答に直接追加されます。 次に、コードは選択された最長のパスをたどります。 そのパス上の各頂点について、選択された継続を除くすべての子が新しいヒープ エントリになります。 これらの子は、選択したばかりのパスと重複することができないため、最も深いパス全体は今後のコントリビューションとして引き続き使用できます。 

Python では整数オーバーフローの懸念はなく、最大の答えは N だけです。ヒープには O(N) 個のエントリが含まれる可能性がありますが、すべてのツリー頂点は最大 1 つの選択されたパスで処理されるか、側枝として検査され、ヒープのメンテナンスとは別に必要な線形数の構造操作が提供されます。

 | --- | --- | --- |
 | 時間 | O(N log N) | すべての頂点は一定の回数処理され、ヒープの挿入または削除には O(log N) のコストがかかります。 |
 | スペース | O(N) | ツリー、DFS 順序、深さ配列、およびヒープはすべてリニア メモリを必要とします。 |

import sys
import heapq

def solve(inp: str) -> str:
    data = inp.split()
    it = iter(data)

    n = int(next(it))
    k = int(next(it))

    children = [[] for _ in range(n)]

    for v in range(1, n):
        p = int(next(it)) - 1
        children[p].append(v)

    order = []
    stack = [0]

    while stack:
        v = stack.pop()
        order.append(v)
        for c in children[v]:
            stack.append(c)

    depth = [1] * n
    best = [-1] * n

    for v in reversed(order):
        best_depth = 0
        best_child = -1

        for c in children[v]:
            if depth[c] > best_depth:
                best_depth = depth[c]
                best_child = c

        if best_child != -1:
            depth[v] = best_depth + 1
            best[v] = best_child

    heap = [(-depth[0], 0)]
    answer = 0

    for _ in range(k):
        neg_len, root = heapq.heappop(heap)
        answer += -neg_len

        v = root
        while v != -1:
            chosen = best[v]

            for c in children[v]:
                if c != chosen:
                    heapq.heappush(heap, (-depth[c], c))

            v = chosen

    return str(answer)

 ## 特殊なケース

 K = 1 の場合については、次のように考えます。`3 1`両親と一緒に`1 1`。 前処理により得られるのは、`depth[1] = 2`最も深いパスにはルートと 1 つの子が含まれているためです。 ヒープには最初にのみ含まれます`(2,1)`, したがって、1 回の反復は 2 を加えて停止します。 出力は 2 です。すべての分岐を独立してカウントできると仮定したソリューションでは、誤って 3 が返されます。 

深さが等しい分岐については、次のことを考慮してください。`5 2`両親と一緒に`1 1 2 2`。 ルートには 2 つの子があり、頂点 2 には 2 つの子があります。 最も深いパスの長さは 3 から頂点 4 または 5 までです。アルゴリズムが以下を選択するとします。`1-2-4`初め。 そのパスの処理中、頂点 5 は深さ 1 の候補となり、頂点 3 は深さ 2 の候補になります。2 番目の選択には次のものがかかります。`1-3`1 の新しい貢献として? ルートはすでにカバーされているため、ルート 3 の候補は頂点 3 のみに寄与し、ルート 5 の候補は頂点 5 のみに寄与します。したがって、合計は 4 になります。頂点 5 が最初に選択された場合、同じ結果が得られます。 内部でのタイブレーク`best[v]`選択したパスは変更されますが、その長さや最終的な最適値は変更されません。 

スターの場合、次のことを考慮します。`5 4`両親と一緒に`1 1 1 1`。 最初の選択には次の時間がかかります`1-2`パスの処理により、深さ 1 の独立した候補として頂点 3、4、および 5 が公開されます。次の 3 つの選択は、それぞれ 1 つの新しい頂点を提供し、次の頂点が生成されます。`2 + 1 + 1 + 1 = 5`。 これはまさに頂点の合計数であり、スキップされた子をヒープに挿入する必要がある理由を示しています。 

チェーンの場合は、次のように考えます。`7 3`両親と一緒に`1 2 3 4 5 6`。 最初の候補は深さ 7 を持ち、ツリー全体を選択します。 そのパス上のすべての頂点には、その唯一の子と等しい選択された子があるため、側枝は挿入されません。 最初の選択の後、ヒープは空になります。 すでに逮捕されている頂点を選択しても答えを増やすことはできないため、残りの予見者を使用しても効果はなく、答えは 7 のままです。 

100000 個の頂点を持つ最大サイズのスターの場合、最初に選択されたパスは 2 に寄与しますが、残りの 99998 個の頂点は深さ 1 のヒープ候補になります。 次の 99998 個の選択はそれぞれ 1 つの頂点に寄与するため、最終的な答えは 100000 になります。アルゴリズムは選択のペアに対して二次スキャンを実行することはなく、ヒープ作業の合計は O(N log N) のままです。
