 ## 解決策
 ## 問題の理解

 (N \times N) 行列があります。 行 (i) は装飾品 (i) を表し、列 (j) は棚の位置 (j) を表します。 値 (a_{i,j}) は、フラノが装飾 (i) が最初に占めていた位置 (j) をどの程度確信しているかを測定します。 

すべての装飾を正確に 1 つの位置に配置する必要があるため、すべての行とすべての列が 1 回だけ使用されます。 オーナメント (i) が位置 (p_i) に割り当てられている場合、完全なアレンジメントのスコアは次のようになります。 

[
 \prod_{i=1}^{N} a_{i,p_i}。 
】

 タスクは、有効な最大積を達成する配置で、各位置を占める装飾を出力することです。 

これは、割り当て問題の最大積バージョンです。 公式の問題アーカイブでは (N \le 100) が与えられており、時間制限は 1 秒、メモリ制限は 256 MB です。 

境界 (N \le 100) は、列挙順列を即座に除外します。 可能な配置は (N!) あり、1 つの配置を評価するだけでも (O(N)) コストがかかり、(O(N \cdot N!)) 時間がかかります。 (N=100) では、これはおよそ (100 \cdot 100! \およそ 9.3 \times 10^{159}) の基本演算になります。 多項式アルゴリズムが必要です。 

最初のエッジ ケースは (N=1) です。 例えば、```
1
100
```考えられる答えは 1 つだけです、`1`。 少なくとも 2 つの行または列があることを前提とした実装では、一致する配列を構築するときに失敗する可能性があります。 

もう 1 つのよくある間違いは、2 つの装飾品が同じ位置を使用することを許可することです。 考慮する```
2
10 9
10 1
```最も有効な取り決めは、`2 1`, (9 \cdot 10 = 90) を与えます。 各行の最大値を独立して取得する貪欲なプロシージャは、両方の装飾の位置 1 を選択しますが、これは有効な順列ではありません。 割り当て制約はグローバルに処理する必要があります。 

絆も自然に生まれます。 のために```
2
5 5
5 5
```すべての順列には積 (25) があるため、両方とも`1 2`そして`2 1`は正しいです。 コードは、最適値が一意であると想定してはなりません。 

値は 100 まで大きくすることもできます。(N=100) の場合、積は (100^{100}) まで大きくなり、C++ などの言語の固定幅整数型をはるかに超えます。 この積を直接計算することはありません。 ソリューションで使用される変換により、オーバーフローが完全に回避されます。 

## アプローチ

 直接的なアプローチは、(N) 個の装飾のすべての順列を列挙することです。 順列ごとに、選択した (N) 個の行列エントリを乗算し、最適な配置を維持します。 これは正しいです。考えられる有効な配置はすべて 1 つの順列によって表現され、最終的には最適な配置が検査されるからです。 そのコストは (O(N \cdot N!)) で、(N=100) よりずっと前に使用できなくなります。 

問題の構造から、より良い解決策が得られます。 すべての有効な配置では、すべての行とすべての列から 1 つのセルが正確に選択されます。これは、完全な 2 部グラフで正確に完全に一致します。 唯一の珍しい部分は、一致する重みが合計ではなく積であることです。 

対数はその差を取り除きます。 すべての行列値は正であるため、

 \sum_i \log(a_{i,p_i})。 
】

 対数は厳密に増加するため、積が最大になる配置は、まさに対数の和が最大になる配置となります。 この問題を標準の最大重み割り当て問題に変換しました。 

同等のコストを最小限に抑えることができます

 [
 c_{i,j}=-\log(a_{i,j})。 
】

 ハンガリーのアルゴリズムは、この割り当て問題を (O(N^3)) 時間で解決します。 そのポテンシャルベースの実装は、部分的な一致を維持し、次の行の拡張パスを繰り返し見つけます。 標準実装では配列を使用します`u`、`v`、`p`、`way`、 そして`minv`二重の可能性を維持し、それぞれの増強経路を再構築します。 

すべての入力値は 1 ～ 100 であるため、対数は小さな有限数になります。 意図された競合プログラミングの実装では、この問題に対する既知の解決策と同様に、浮動小数点対数が使用されます。 

したがって、比較は次のようになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(N \cdot N!)) | (O(N)) | 遅すぎる |
 | 最適 | (O(N^3)) | (O(N^2)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 信頼行列を読み取り、すべての値 (a_{i,j}) をコスト (-\log(a_{i,j})) に置き換えます。 以下のハンガリー語の実装は最小コストの割り当て用に書かれているのに対し、対数スコアを最大化する必要があるため、負の符号を使用します。 

以来

 \arg\min \sum_i -\log(a_{i,p_i}),
 】

 最適な順列は変わりません。 
2. メンテナンス`p[j]`、 どこ`p[j]`は現在列 (j) に割り当てられている行です。 列 0 は、すべての拡張の開始点として使用される仮想列です。 
3. 行を一度に 1 つずつ処理します。 行 (i) が導入されると、それを仮想列に一時的に接続し、未使用の実際の列につながる拡張パスを検索します。 

既存のマッチングは、以前に処理されたすべての行に対してすでに最適になっています。 新しい拡張パスは、行 (i) をマッチングに入れながら、以前に割り当てられた一部の行を別の列に移動できるメカニズムです。 
4. 検索中に、次のことを維持します。`minv[j]`、列 (j) に到達するために現在知られている最小の削減コスト、および`way[j]`、そのパスの前の列。 

削減されたコストは、

 [
 c_{i,j}-u_i-v_j。 
】

 可能性`u`そして`v`維持されたデュアル ソリューションにおいてコスト削減がマイナスにならず、最短の増強パスを効率的に拡張できるようになります。 
5. 最小の未使用列を選択します。`minv`価値。 その値を`delta`。 交互ツリーの現在到達可能な部分のポテンシャルを更新し、減算します。`delta`残ったものから`minv`価値観。 

これにより、二重の可能性の実現可能性が維持され、同時に少なくとも 1 つの新しいカラムをゼロのコスト削減で到達可能になります。 
6. 未使用の列に達するまで続行します。 そのときはフォローしてください`way`その列から後方へ。 結果として生じる交互パスに沿って割り当てを逆にします。 

新しい一致には以前よりも 1 行多い行が含まれていますが、処理されたすべての行には引き続き 1 つの列があり、すべての使用された列には引き続き 1 つの行があります。 
7. すべて (N) 行が処理されると、すべての列に 1 つの行が割り当てられます。 配列`p[1], p[2], ..., p[N]`は出力に必要な形式になっています: 各棚位置 (j) について、`p[j]`そこに置かれている飾りです。 

### なぜ効果があるのか

 対数変換では、考えられるすべての積の順序が保存されるため、変換された加法代入問題を解くことは、元の問題を解くことと同じです。 ハンガリーのアルゴリズムは、処理された行の有効なマッチングと、コストの削減がそのマッチングと互換性のあるデュアル ポテンシャルを維持します。 各拡張では、割り当ての制約を破ることなく新しい行が 1 つだけ追加され、最短の拡張パスにより追加の変換コストが最小限に抑えられます。 帰納法により、行 (i) を処理した後、最初の (i) 行の個別の列へのすべての割り当て間でマッチングが最適になります。 (N) 回目の拡張の後、すべての行と列が含まれるため、結果として得られる完全な一致は全体的に最適になります。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

def solve(data):
    it = iter(data.split())
    n = int(next(it))

    # cost[i][j] = -log(confidence)
    cost = [[0.0] * n for _ in range(n)]
    for i in range(n):
        for j in range(n):
            x = int(next(it))
            cost[i][j] = -math.log(x)

    # Hungarian algorithm for minimum-cost assignment.
    #
    # p[j] = row currently assigned to column j.
    # way[j] = previous column in the augmenting path.
    u = [0.0] * (n + 1)
    v = [0.0] * (n + 1)
    p = [0] * (n + 1)
    way = [0] * (n + 1)

    for i in range(1, n + 1):
        p[0] = i
        j0 = 0

        minv = [float("inf")] * (n + 1)
        used = [False] * (n + 1)

        while True:
            used[j0] = True
            i0 = p[j0]

            delta = float("inf")
            j1 = 0

            for j in range(1, n + 1):
                if used[j]:
                    continue

                cur = cost[i0 - 1][j - 1] - u[i0] - v[j]

                if cur < minv[j]:
                    minv[j] = cur
                    way[j] = j0

                if minv[j] < delta:
                    delta = minv[j]
                    j1 = j

            for j in range(n + 1):
                if used[j]:
                    u[p[j]] += delta
                    v[j] -= delta
                else:
                    minv[j] -= delta

            j0 = j1

            if p[j0] == 0:
                break

        while j0 != 0:
            j1 = way[j0]
            p[j0] = p[j1]
            j0 = j1

    return " ".join(map(str, p[1:]))

def main():
    data = sys.stdin.buffer.read()
    if data:
        print(solve(data))

if __name__ == "__main__":
    main()
```入力は 1 バイト文字列として読み取られ、一度分割されます。 これにより、解析のオーバーヘッドが小さく保たれますが、行列には​​最大 10,000 個の値が含まれるため、これは重要です。 

行列はすぐに負の対数コストに変換されます。 の`-1`インデックス調整`cost[i0 - 1][j - 1]`ハンガリー語の配列は 1 から始まるインデックスを使用するのに対し、Python リストは 0 から始まるインデックスを使用するため、これが必要です。 

配列`u`そして`v`は行と列の電位です。`p`現在の一致を保存します。`way`パス全体を明示的に保存しなくても、拡張パスを再構築するのに十分な先行情報を保存します。 これは、ハンガリー語の標準 (O(N^3)) 潜在的定式化です。 

仮想列`0`は実際の棚の位置ではありません。 設定`p[0] = i`現在処理されている装飾から拡張を開始します。 最終的な答えには決して出現してはなりません。そのため、結果では次のようになります。`p[1:]`。 

アップデート```
u[p[j]] += delta
v[j] -= delta
```とペアになっています```
minv[j] -= delta
```未使用の列の場合。 いずれかの部分を省略すると、コスト削減の不変条件が崩れ、無効なマッチングまたは非最適なマッチングが生成される可能性があります。 

コードが元の積を形成することはないため、整数オーバーフローは発生しません。 渡される最大値`math.log`はわずか 100 であり、ハンガリー ポテンシャルは大きさが小さい対数の和で動作します。

```すべての値が正であるため、対数コストは有限です。 対角線の割り当てには積 (10000) があり、もう一方の割り当てには積 (1) があります。 変換されたコストではこの順序が維持されるため、アルゴリズムは次の値を返します。`1 2`。 

(N=100) の場合、選択された値の積は (100^{100}) になる可能性がありますが、実装ではその数値は保存されません。 各行列エントリは次のようになります。`-math.log(100)`または別の小さな浮動小数点値であり、ハンガリーのアルゴリズムはこれらの対数コストを加算および減算するだけです。 割り当て配列は (N) で線形のままですが、行列は (O(N^2)) 個のメモリを占有します。 これは、まさに (O(N^3)) 割り当てアルゴリズムが適切なスケールです。
