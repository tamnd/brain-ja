 ## 解決策
 ## 問題の理解

 私たちのサークルには最大 13 人の出場者がいます。 使用されている各カード値のコピーが 4 つと、ワイルドカードが 1 つあります。 各出場者は 4 枚の通常カードを持ってスタートしますが、開始出場者はワイルドカードも受け取るため、最初は 5 枚のカードを持っています。 

重要なのは、ゲームが完全に決定的であるということです。 次の出場者は常に現在の出場者の右隣の人となり、パスするカードはルールによって一意に決定されます。 現在の出場者がワイルドカードを持っていて、それを受け取ったばかりではない場合、ワイルドカードをパスする必要があります。 それ以外の場合、出場者は手札の頻度が最小である通常のカードをパスし、固定されたカードの順序で同点を解消します。`A23456789DQJK`。 

出場者は、すべて同じ値の 4 枚のカードを持っている場合に勝ちとなります。 ワイルドカードは、不足しているカードの代わりにはなりません。 少なくとも 1 人の出場者がその状態に達するとすぐにゲームは停止し、すべての勝利した出場者の中で最も小さい出場者番号を持つ出場者が出力されます。 

入力により得られるのは、`N`そして`K`、続いて出場者ごとに 4 枚の通常カードが続きます。 ワイルドカードは入力に書き込まれません。 出場者に掲載`K`最初のターンをシミュレーションする前に。 

上限`N <= 13`これが直接シミュレーションが適切な理由です。 通常のカードの値は 13 個しかないため、最大 13 個のカウンターをスキャンすることであらゆる決定を下すことができます。 このステートメントではターン数に個別の上限を指定していないため、自然な複雑さのパラメーターは次の数値になります。`T`誰かが勝つ前に実際にシミュレーションされたターン数。 ルールではプログラムが探索する選択肢がないため、検索ツリーはありません。 

シミュレーションを静かに中断する可能性のあるエッジケースがいくつかあります。 

まず、スタート出場者はすぐにワイルドカードをパスすることはできません。 例えば、```
2 1
ABBB
AAAB
```出場者 1 が保持しています`ABBB`加えてワイルドカード。 ワイルドカードを受け取ったばかりなので、出場者 1 は通常のカードを渡す必要があります。`A`一度発生し、`B`が 3 回発生するため、`A`は出場者 2 に渡されます。出場者 2 は、`AAAA`そして勝つので、出力は次のようになります`2`。 ワイルドカードをすぐに渡す不注意な実装では、別のゲームが生成されてしまいます。 

第二に、ゲームは最初のターンより前にすでに終了している可能性があります。 例えば、```
2 2
AAAA
2222
```出場者 2 にワイルドカードが与えられるため、出場者 2 は 5 枚のカードを持っていますが、出場者 1 はすでに 4 枚のカードを持っています`A`カード。 正しい出力は次のとおりです`1`。 初手の後にのみ勝者を確認するのは間違いです。 

第三に、通常のカードを受け取った参加者は一時的に 5 枚のカードを持っているため、ある値が 4 回出現するかどうかをチェックするだけでは十分ではありません。 で```
3 3
AAA2
2233
A223
```出場者 3 はワイルドカードからスタートします。 彼らは合格しなければなりません`A`、 なぜなら`A`そして`3`どちらも 1 回発生し、`A`より低い値です。 円が回り込むため、カードは出場者 3 から出場者 1 に移ります。 出場者 1 は一時的に`AAAA2`、これは 5 枚のカードですが、まだ勝っていません。 次のターンで、競技者 1 はその唯一のパスをパスします。`2`、出発`AAAA`したがって、出場者 1 が勝ち、出力は次のようになります。`1`。 

最後に、タイブレーク順序は、アルファベット順ではなく、ステートメントからのカードの順序です。 以来`A`は最小値であり、`A`そして`2`選択しなければなりません`A`。 通常のカードを選択する必要がある場合は、常に同じ固定順序が使用されます。 

## アプローチ

 最も直接的なアプローチは、説明どおりにゲームをシミュレートすることです。 すべての出場者と 13 枚の通常カードの値ごとに、現在手札にあるカードの枚数を保存します。 ワイルドカードは特殊な動作をし、最小頻度の計算に決して参加してはいけないため、ワイルドカードを個別に保存します。 

単純なシミュレーションでは、すべての動きの後にすべての出場者をスキャンして、誰かが勝ったかどうかを確認できます。 出場者ごとに 13 個のカード カウンターをすべて検査するため、1 ターンのコストがかかります`O(13N)`、または最大 169 のカウンター検査`N = 13`。 ゲームが続けば`T`ターン、これは与えます`O(13NT)`、同等に`O(NT)`13は決まっているので。 これらの検査の正確な上限は次のとおりです。`169T`最大限に`N`。 

このアプローチは、指定された制約に対してすでに十分に高速ですが、単純な構造上の改善があります。 初期位置をチェックし、現在誰も勝っていないことを確認した後、手によって送信者と受信者の 2 人の参加者だけが手を変更します。 他の手は変化しません。 したがって、何も手を加えていない出場者が突然勝者になることはできません。 それぞれの動きの後に、これら 2 人の出場者をテストするだけで済みます。 

渡されたカードがワイルドカードであるか通常のカードであるかに関係なく、同じ観察が当てはまります。 内容が変更されたのは送信者と受信者の 2 つの手だけです。 各勝利状態チェックでは最大 13 個のカウンターがスキャンされるため、最適なシミュレーションには次の時間がかかります。`O(13)`カードの選択に取り組み、`O(13)`影響を受ける手をそれぞれ確認する作業を行います。 カードユニバースのサイズは 13 に固定されているため、これは事実上`O(T)`。 

ブルートフォース シミュレーションが機能するのは、初期状態が判明するとゲームにはプレイヤーの決定が残らないためですが、ハンドが変更される可能性のないプレイヤーを繰り返し検査するためです。 送信者と受信者のみが変更できるという観察により、シミュレートされたシーケンスをまったく変更せずに、不要なスキャンを削除できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 毎ターン後のフルスキャン |`O(13NT)`|`O(13N)`| 受け入れられましたが、不必要なスキャンが実行されます。 
| 影響を受ける出場者のみをチェック |`O(13T)`|`O(13N)`| 承認済み |

 ## アルゴリズムのチュートリアル

 1. カードの値を正確な順序でエンコードする`A23456789DQJK`。 すべてのカード値に 0 ～ 12 のインデックスを付けます。これにより、単一の整数インデックスがカードとそのタイブレーク優先度の両方を表すようになります。 
2. を構築します。`N x 13`入力からの周波数配列。 出場者向け`K`、ワイルドカードを保持していることを個別にマークします。 ワイルドカードを通常のカウントの外に置くと、最も頻度の低い通常のカードを選択するときに考慮されなくなります。 
3. 行動を起こす前に、すべての出場者をスキャンし、すでに勝利状態にあるかどうかを確認します。 勝ちハンドにはワイルドカードがなく、合計で 4 枚の通常カードが必要であり、4 枚すべてが同じ値でなければなりません。 複数の出場者がすでに勝っている場合は、最も小さい出場者番号をすぐに返します。 
4. 現在の出場者を次のように設定します。`K`ワイルドカードを新しく受信したものとしてマークします。 この特別なフラグは、現在ワイルドカードを保持している出場者にのみ必要です。 スタート出場者は、まさにそれを受け取ったばかりの人と同じように扱われます。 
5. から折り返して、次の出場者をすぐ右の人物として計算します。`N`に戻る`1`。 ゼロベースの Python インデックス付けでは、これは次のようになります。`(current + 1) % N`。 
6. 現在の出場者がワイルドカードを持っていて、それが新しく受け取られたものではない場合は、ワイルドカードを次の出場者に渡します。 現在の出場者からそれを削除し、次の出場者に渡し、そこで新しく受け取ったものとしてワイルドカードをマークします。 
7. それ以外の場合は、パスする通常のカードを選択します。 ゼロカウントとワイルドカードを無視して、13 のカード周波数をスキャンします。 最小の正の頻度を選択し、2 つの値がその頻度を持つ場合は、小さい方のカード インデックスを維持します。 これにより、必要なタイブレーク ルールの両方のレベルが直接実装されます。 
8. 選択した通常カードを現在の出場者から次の出場者に移動します。 この場合、ワイルドカードは現在の所有者に残るため、ワイルドカードの状態は変わりません。 現在の出場者がワイルドカードを受け取ったばかりの場合、特別な制限が消費されるため、次のターンでワイルドカードを通過する可能性があります。 
9. 移動後は、現在の出場者と次の出場者のみをチェックします。 変わったのはそれらの手だけです。 どちらかが優勝した場合は、優勝候補の中から出場者番号の小さい方を選んで返却します。 
10. 次の出場者を現在の出場者にして、勝者が見つかるまでシミュレーションを繰り返します。 

### なぜ効果があるのか

 中心的な不変条件は、保存されたカードの数が、シミュレートされた各ターンの直前の実際のゲーム状態を正確に表すということです。 ワイルドカード フラグは、現在の所有者がそのフラグを渡すことが禁止されているかどうかを記録します。 各ターンで、アルゴリズムはルールの 2 つの正当なケースのうちの 1 つに従います。許可されている場合はワイルドカードを渡すか、規定の値の順序を使用して最小頻度の通常のカードを選択します。 したがって、結果として得られる状態は、そのターン後の実際のゲームの状態とまったく同じになります。 

最初の勝者チェックでは、手を動かす前に終了するゲームが処理されます。 このチェックの後、新しい勝利状態は、手を変更した参加者、つまり送信者または受信者にのみ表示されます。 したがって、すべての動きの後に 2 人の出場者をチェックするだけで十分です。 勝利状態が見つかった場合、最小の出場者インデックスを選択すると、必要な勝者ルールと一致するため、返される出場者はゲームによって宣言されたものとまったく同じになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

VALUES = "A23456789DQJK"
V = len(VALUES)
POS = {ch: i for i, ch in enumerate(VALUES)}

def is_winner(cards, has_wild):
    if has_wild:
        return False

    total = 0
    has_four = False

    for x in cards:
        total += x
        if x == 4:
            has_four = True

    return total == 4 and has_four

def solve():
    n, k = map(int, input().split())
    k -= 1

    cards = [[0] * V for _ in range(n)]
    has_wild = [False] * n

    for i in range(n):
        s = input().strip()
        for ch in s:
            cards[i][POS[ch]] += 1

    has_wild[k] = True

    # The game may already be over before the first turn.
    for i in range(n):
        if is_winner(cards[i], has_wild[i]):
            return i + 1

    current = k
    wild_new = True

    while True:
        nxt = (current + 1) % n

        # The wildcard can be passed only if it was not
        # received immediately before this turn.
        if has_wild[current] and not wild_new:
            has_wild[current] = False
            has_wild[nxt] = True
            wild_new = True

        else:
            # Pass the least frequent ordinary card.
            # Ties are resolved by VALUES order, which is exactly
            # the index order 0..12.
            chosen = -1
            best_count = 10

            for value in range(V):
                cnt = cards[current][value]
                if cnt == 0:
                    continue

                if cnt < best_count:
                    best_count = cnt
                    chosen = value

            cards[current][chosen] -= 1
            cards[nxt][chosen] += 1

            # If the current player was holding a newly received
            # wildcard, it has now been held for one turn.
            if has_wild[current]:
                wild_new = False

        # Only these two contestants changed.
        winner = -1

        if is_winner(cards[current], has_wild[current]):
            winner = current

        if is_winner(cards[nxt], has_wild[nxt]):
            if winner == -1 or nxt < winner:
                winner = nxt

        if winner != -1:
            return winner

        current = nxt

if __name__ == "__main__":
    print(solve())
```の`VALUES`string には 2 つの目的があります。 これにより、すべてのカードに安定した整数インデックスが与えられ、そのインデックスは必要な同点順位をすでに表しています。 別の比較関数は必要ありません。 

通常のカードは、個々のカード オブジェクトとしてではなく、カウントとして保存されます。 ルールでは各値が何回出現するかを尋ねるだけなので、これで十分です。 また、最小周波数の選択が固定の 13 要素スキャンになります。 

ワイルドカードは次の場所に保存されます`has_wild`。 この分離は、勝利状態のテストに特に役立ちます。 ワイルドカードを持っている出場者は、4 枚の通常のカードがすべて同じであっても、ちょうど 4 枚のカードを持つことはできません。`is_winner`すべてのワイルドカード保持者を拒否します。 

勝利状態になるとすぐにゲームが終了するため、最初のスキャンは最初のターンの前に行われます。 ワイルドカードにより、開始出場者は 5 枚のカードを持っている可能性があるため、ワイルドカード所有者が最初の勝者として誤って受け入れられることはありません。 

表現`(current + 1) % n`特別な場合を除いて循環注文を処理します。 現在の出場者が`n - 1`、次の出場者はゼロになり、出場者 1 に対応します。 

の`wild_new`フラグは次のように初期化されます`True`なぜなら出場者`K`最初のターンの直前にワイルドカードを受け取りました。 所有者がワイルドカードを持っているときに通常のカードが渡されると、フラグは`False`、つまり、ワイルドカードはその出場者の次のターンに渡される可能性があります。 ワイルドカード自体が通過すると、受信側の出場者は`wild_new = True`。 

移動後の勝者チェックのみを調べます`current`そして`nxt`。 その手によって変更されたのは彼らの手だけですが、最初のスキャンでは、他の場所にすでに優勝者が存在していないことが保証されます。 影響を受ける両方の出場者が勝っている場合、小さい方の出場者番号に対応する、小さいゼロから始まるインデックスが選択されます。

## 複雑さの分析

 しましょう`T`ゲームが終了するまでにシミュレートされるターン数になります。 通常のカードの値はちょうど 13 個あります。 

| 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |`O(13T) = O(T)`| 各ターンはカード選択のために 13 の値をスキャンし、最大 2 つの 13 値の勝者チェックを行います。 
| スペース |`O(13N) = O(N)`| 周波数配列には、出場者ごとに 13 個のカウンターが保存されます。 

と`N <= 13`、状態の表現は小さいです。 カード値に対するすべての操作は 13 要素の固定ループであるため、Python の 1 ターンあたりのオーバーヘッドはほとんどありません。 このソリューションは、分岐検索を実行したり、考えられるカード配布の膨大なセットを構築したりしません。 

## テストケース```python
import sys
import io

VALUES = "A23456789DQJK"
POS = {ch: i for i, ch in enumerate(VALUES)}
V = 13

def game(data: str) -> str:
    inp = io.StringIO(data)

    n, k = map(int, inp.readline().split())
    k -= 1

    cards = [[0] * V for _ in range(n)]
    has_wild = [False] * n

    for i in range(n):
        s = inp.readline().strip()
        for ch in s:
            cards[i][POS[ch]] += 1

    has_wild[k] = True

    def winner(i):
        if has_wild[i]:
            return False
        return sum(cards[i]) == 4 and 4 in cards[i]

    for i in range(n):
        if winner(i):
            return str(i + 1)

    current = k
    wild_new = True

    while True:
        nxt = (current + 1) % n

        if has_wild[current] and not wild_new:
            has_wild[current] = False
            has_wild[nxt] = True
            wild_new = True
        else:
            chosen = -1
            best = 10

            for value in range(V):
                cnt = cards[current][value]
                if cnt and cnt < best:
                    best = cnt
                    chosen = value

            cards[current][chosen] -= 1
            cards[nxt][chosen] += 1

            if has_wild[current]:
                wild_new = False

        candidates = []
        if winner(current):
            candidates.append(current)
        if winner(nxt):
            candidates.append(nxt)

        if candidates:
            return str(min(candidates) + 1)

        current = nxt

 ## 特殊なケース

 最初のエッジケースは、新たに受け取ったワイルドカードを保持しているスタート出場者です。 のために```
2 1
ABBB
AAAB
```状態は競技者 1 が保持している状態から始まります`ABBB + W`。 の`W`1 ターン目ではパスできないため、アルゴリズムは通常のカードの分岐に入ります。 周波数は次のとおりです。`A = 1`そして`B = 3`、作る`A`選択したカード。 出場者2が獲得`A`そしてからの変化`AAAB`に`AAAA`、したがって、影響を受けるプレイヤーの勝者チェックはすぐに返されます`2`。 2 番目のターンはシミュレートされません。 

2 番目のエッジ ケースは、ゲームが開始される前にすでに勝者となっています。 で```
2 2
AAAA
2222
```出場者2が所有`2222 + W`、一方、出場者 1 は正確に所有しています`AAAA`。 最初のスキャンでは、転送が行われて返される前に、出場者 1 が勝者であると見なされます。`1`。 シミュレーション ループには決して入りません。 これは、ワイルドカードを勝利条件から除外する必要がある理由も示しています。 

3 番目のエッジ ケースは、4 枚の等しい普通のカードを持っているワイルドカード ホルダーです。 そのようなプレイヤーは合計 5 枚のカードを持っていますが、勝っていません。 たとえば、出場者が次のことを保持している場合、`AAAA + W`、通常の周波数配列には 4 つが含まれます。`A`カードですが、`has_wild`それは本当なので、`is_winner`falseを返します。 ワイルドカードが去った後にのみ、これら 4 つは`A`カードが勝ち手になります。 

4 番目のエッジ ケースは、循環インデックスです。 で```
3 3
AAA2
2233
A223
```現在の最初の出場者は出場者 3 です。その右隣は出場者 1 で、次のように表されます。`(2 + 1) % 3 = 0`ゼロベースのインデックス付けで。 出場者 3 は、`A = 1`、`2 = 2`、 そして`3 = 1`したがって、最小頻度は 1 であり、同点は次のとおりです。`A`そして`3`。 以来`A`値インデックスが小さい場合、それは出場者 1 に渡されます。出場者 1 は後で到達します。`AAAA`そして勝ちます。 これにより、ラップアラウンド境界と最小値タイブレークの両方が捕捉されます。 

5 番目のエッジケースは、複数の優勝者間の同点です。 初期状態が次の場合```
3 3
AAAA
2222
3333
```出場者 1 と 2 は両方ともすでに優勝していますが、出場者 3 はワイルドカードを持っています。 最初のスキャンは出場者番号順に進行し、出場者 1 を返します。勝者のルールは、カードの値ではなく、出場者の番号に基づいているため、アルゴリズムは、単に 4 枚の同じカードの値が小さいという理由だけで、後の出場者を選択することはできません。
