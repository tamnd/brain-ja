 ## 解決策
 ## 問題の理解

 ゼロから始まる現在の値を維持しながら、一連の数値を処理しています。 各位置で、現在の数値を直接加算するか、加算して結果の絶対値を取得するかの 2 つのアクションのどちらかを決定する必要があります。 2 番目の操作は、現在の合計が負になるのを防ぐ「リセットサイン」操作と見なすことができますが、後で有益になる可能性がある有用な負の累積を破壊する可能性もあります。 

目標は、配列全体でこれらの演算を選択して、すべての要素を処理した後の累計の最終値を最大化することです。 

主な問題点は、絶対値演算がローカルではないことです。 絶対的に早期に取得すると、累積合計全体の符号が反転する可能性があり、将来の加算の動作が変わります。 これにより、連続状態空間に対する動的プログラミングのように見える、決定間の依存関係が作成されます。 

制約は大きく、テスト ケース全体のすべての配列の長さの合計は最大 300,000 です。 これにより、すべてのプレフィックスと状態にわたる二次 DP が直ちに除外されます。 テスト ケースごとに O(n log n) のソリューションであっても、重い構造で実装されている場合は境界線になるため、意図したソリューションはテスト ケースごとに線形である必要があります。 

いくつかの大きな負の値の後で累計が負になる場合、微妙なエッジ ケースが発生します。 たとえば、[-5, -4] のような初期の接頭辞がある場合、絶対値をあまり早く適用することは避けたいと思うかもしれません。これは、適切なタイミングで符号を反転すると、後の正の数値が恩恵を受ける可能性があるためです。 逆に、絶対値を適用するのが遅すぎると、将来のすべての追加に影響を与える負の接頭辞が「固定」される可能性があります。 

もう 1 つの重要なエッジ ケースは、すべての数値が非負であるか、すべてが非正である場合です。 すべてが負でない場合、絶対演算は役に立たず、答えは単に合計になります。 すべてが正でない場合、絶対値を繰り返し取得することで、プロセスが効果的に大きさを累積するようになりますが、それでもタイミングが重要です。 

## アプローチ

 ブルートフォース戦略では、各インデックスに絶対値を適用するか適用しないという可能な選択肢をすべて試します。 各位置には 2 つの選択肢があるため、テスト ケースごとに 2^n 通りの可能性が生じます。 n が 2⋅10^5 までの場合、これは完全に不可能です。 n=40でもボーダーラインになります。 

ブルートフォースを超えるために、絶対操作が実際に何を行うのかを調べます。 あるステップで現在の値 c があり、a_i を追加するとします。 絶対値を使用しないと、c + a_i になります。 絶対値を使用すると、 |c + a_i| が得られます。これは、負でない場合は変更しないままにするか、負の場合は符号を反転するのと同じです。 

これは、プレフィックスの合計が負になった場合にのみ操作が重要になることを意味します。 絶対値を使用して負の接頭辞を「修正」することにした場合、事実上、その時点までの符号履歴を破棄し、結果を今後は非負として扱うことになります。 

重要な観察は、最適な戦略は、複雑なパターンで絶対値を複数回適用しても決してメリットがないということです。 重要なのは、累計がマイナスになることを許容するかどうか、そしてそれを「回復」する前にどれだけマイナスになるかということです。 回復することを決定したら、可能な限り最善の回復は、これまでに確認された最小プレフィックス合計の絶対値を取得することです。 

これは単純化につながります。答えはプレフィックス合計の最大可能絶対偏差に依存します。 直感的には、最終値を最大化したいと考えますが、絶対値が役に立つのは、負のプレフィックスを正のプレフィックスに変換し、大きな負の累積を大きな正のゲインに事実上変換するときだけです。 

そこで、プレフィックスの合計とその最小値を追跡します。 最良の戦略は、合計を計算するか、十分に負のプレフィックスを反転して、その大きさがプラスに寄与するようにすることです。

より正確には、最適な答えは、考えられるすべての最終状態の最大値であり、i までのすべてが負になるようにブレークポイント i を選択し、有益であればそのプレフィックスの符号を反転します。 これは、プレフィックスの合計を追跡し、可能な限り最善の改善を選択することになります。 

現在のプレフィックス合計と最小プレフィックス合計を維持できます。 答えは、最終合計の最大値と最終合計から最小プレフィックス合計の 2 倍を引いたもので、これは最悪のプレフィックス セグメントを反転することに相当します。

 ## アルゴリズムのチュートリアル

 現在のプレフィックス合計とこれまでに観察された最小プレフィックス合計という 2 つの値を維持しながら配列を処理します。 

1. 現在の合計を 0 に、最小プレフィックス合計を 0 に初期化します。 

これは、要素を処理する前の空のプレフィックスを表します。 
2. 配列を左から右に繰り返し、各要素を累計に加算します。 

各要素を処理した後の累計には、加算演算を選択した効果が一貫して反映されます。 
3. 現在の合計を更新した後、これまでに確認された最小値で最小プレフィックス合計を更新します。 

これは、任意のプレフィックスで到達したゼロ未満の最も深い落ち込みを追跡します。 
4. トラバーサルの終了後、2 つの候補を計算します。最終合計と、最悪のプレフィックスを「反転」することで得られる値 (final_sum - 2 * min_prefix_sum) です。 

減算は、マイナスの寄与をプラスの寄与に変換することに対応します。 
5. これら 2 つの値の最大値を出力します。 

最小プレフィックスのみを考慮する背後のロジックは、絶対演算の最適な使用は、プレフィックス構造内の 1 つの連続する負の偏差セグメントを正確に修正すると解釈できるということです。 最悪のディップによって、そのような補正から得られる最大のゲインが決まります。 

### なぜ効果があるのか

 累計は、絶対値をまったく使用していないかのように、すべての決定をエンコードします。 絶対値を適用すると、一部のプレフィックス合計の符号が負から正に変更されるだけです。 重要な唯一のプレフィックスは最も負のプレフィックスです。負でないプレフィックスを反転しても、最小値を反転する以上に結果を改善することはできないからです。 したがって、単純な合計を超える達成可能な最良の改善は、最小プレフィックス合計によって完全に決定され、ソリューションが完成します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        cur = 0
        min_pref = 0
        
        for x in a:
            cur += x
            if cur < min_pref:
                min_pref = cur
        
        ans = max(cur, cur - 2 * min_pref)
        out.append(str(ans))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このソリューションは、単一パスでプレフィックスの合計を計算します。 変数`cur`絶対値を適用しなかった場合の累計です。 変数`min_pref`は、この軌跡が到達する最低点を記録します。これは、負のセグメントによって蓄積された最大の「ダメージ」を表します。 最後の式は、未変更の結果と、ゼロ付近の最悪のプレフィックスを反映することによって得られる最良の修正とを比較します。 

表現`cur - 2 * min_pref`重要: いつ`min_pref`が負の場合、結果が増加し、事実上、負のディップが正のゲインに変わります。 

## 実用的な例

 ### 例 1

 入力:`[-1, -2, -3]`プレフィックスの合計を追跡します。

 最終的な合計は -6、最小プレフィックスは -6 です。 

次のように計算します。 

- 生 = -6
 - 反転 = -6 - 2(-6) = 6

 これは、負の累積全体を完全に反転すると最適な値が得られることを示しています。

 ## 特殊なケース

 次のような完全に正の配列`[2, 3, 1]`絶対操作の恩恵を受けることはありません。 現在の合計がゼロを下回ることはありません。そのため、最小プレフィックスはゼロのままで、アルゴリズムは単純な合計を返します。 これは、ネガティブ構造が存在しない場合、「フリップ補正」用語が結果を人為的に膨張させないことを裏付けています。 

次のような完全な負の配列`[-1, -2, -3]`着実に減少するプレフィックス合計を生成します。 最小プレフィックスは最終合計に等しく、数式は累積全体を反転して、合計の絶対値に等しい正の合計に変換します。 

次のような混合シーケンス`[3, -10, 4]`部分的な修正を示します。 2 番目の要素の後でプレフィックスは -7 に下がり、これがゲインを決定するキー値になります。 このディップを反転すると、失われた大きさが回復し、未補正の累積よりも高い最終結果が得られます。
