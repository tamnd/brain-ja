 ## 解決策
 ## 問題の理解

 私たちには番号が与えられています$x$, そして、それが非常に特殊な桁制限を満たす 2 つの正の整数の合計として表現できるかどうかを判断したいと考えています。 2 つの加数はそれぞれ、すべての桁が 5 ～ 9 の範囲内にある必要があり、両方の数値の桁数が同じである必要があります。 

この制限は強力です。両方の数字のすべての桁が少なくとも 5 であるため、0 ～ 4 のような小さな数字がどこにも出現する可能性はありません。 これは、各数値が「桁数が多い」ことを直ちに意味し、そのような数値を 2 つ追加すると、すべての列はキャリーも制限された制約された方法で動作します。 

入力サイズは最大です$10^4$テストケースと値$x$まで$10^{18}$。 これにより、テストごとに候補番号を強引に構築することが排除されます。 指定された長さの有効な数値をすべて生成することすら不可能です。$d$、 がある$5^d$有効な数値は非常に急速に増加します。 ペアを直接検索すると、天文学的な規模になります。 

重要な問題は、単に分解をチェックしているだけではないということです。$x$ただし、両方の加数に対する構造制約と位置合わせ制約 (同じ桁長) を伴う分解です。 

加数の桁数があいまいな場合、微妙な特殊なケースが発生します。 例えば、$x = 200$十分に小さいように見えても、有効な 2 桁または 3 桁の構成では、一部の列で大きすぎる最小合計がすぐに生成されるため、形成することはできません。 キャリー伝播や長さの一貫性を考慮せずに、桁ごとの実現可能性をチェックするだけの単純なアプローチは、このような場合には失敗します。 

もう 1 つのエッジケースは次のような場合です$x$キャリーの逆推論後の 0 より小さい数字または 9 より大きい数字が含まれています。 事実上、各桁を 2 桁に分割しようとしているため、$[5,9]$キャリー効果に加えて、キャリー制約を考慮しないローカル推論は、誤った実現可能性の結論につながります。 

## アプローチ

 ブルートフォース手法では、固定長の有効な数値をすべて列挙しようとします。$d$、すべてのペアをチェックします$(a, b)$そのような$a + b = x$。 それぞれについて$d$、検索空間は$5^d$数字とペアをチェックすると、$5^{2d}$、さえ不可能になります。$d = 5$。 和が次のペアに限定しても、$x$まだ候補を生成する必要があるため、役に立ちません。 

重要な観察は、桁構造により問題が列ごとに局所的になり、列間の相互作用が桁上げ伝播のみであるということです。 有効な数値の各桁は 5 ～ 9 であるため、2 桁を加算する場合、列ごとの最小合計は 10 で、最大合計は 18 になります。これは、すべての列の合計が 10 ～ 18 のいずれかに、受信される可能性のあるキャリーを加えたものでなければならないことを直ちに意味します。 

したがって、数値を構築する代わりに、逆算して、次の式から列ごとに 2 桁を割り当てられるかどうかをシミュレートしようとします。$[5,9]$それらの合計と桁上げが次の桁と一致するようにします。$x$。 これはキャリー状態を持つ有界数字 DP になりますが、キャリーは常に 0 または 1 であるため (最大合計は 18 であるため)、状態空間は小さいです。 

最下位から最上位まで数字を処理し、次を満たす各列の有効な数字のペアをすべて試します。$$a_i + b_i + c = x_i + 10 \cdot c'$$どこ$a_i, b_i \in [5,9]$、 そして$c, c' \in \{0,1\}$。 

桁が小さく固定されているため、2 つの有効な桁のすべての可能な合計を事前に計算し、それらを再利用できます。 

桁に対するブルート フォースは位置ごとに一定であるため、ソリューション全体は桁数が線形になります。

 ## アルゴリズムのチュートリアル

 書き換えます$x$数値配列として使用し、右から左への加算をシミュレートします。 

1. の数字を抽出します。$x$最も重要でないものから最も重要なものまで。 キャリーの伝播が自然な加算と一致するように、逆の順序で作業します。 
2. 前の列からのキャリーを表すキャリー値 (最初は 0) を維持します。 
3. 各ポジションについて、すべてのペアを試してください$(a, b)$どこ$a, b \in [5,9]$。 受信したキャリーを使用してそれらの合計を計算します。 
4. この合計から現在の桁が得られるかどうかを確認します。$x$、数字が存在することを意味します$d$次のような:$$a + b + carry \equiv d \pmod{10}$$結果として得られる新しいキャリーは、$\lfloor (a+b+carry)/10 \rfloor$。 
5. 少なくとも 1 つのペアが機能する場合は、次の桁に進みます。 そうしないと建設が不可能になります。 
6. すべての桁を処理した後、最後の桁上げが 0 であることを確認する必要があります。両方の数値が同じ長さを持ち、有効な拡張子が生成されない限り、最上位位置を超える余分な桁は許可されないためです。 

各ステップでの決定はローカルですが、キャリーによって制限されるため、桁ごとのブルートフォースが引き続き管理可能です。 

### なぜ効果があるのか

 正しさは、10 進数の加算がキャリーを除いて列ごとに独立しているという事実に基づいています。 すべての有効な分解は、各列の一連の数字ペアの選択に対応し、列間の唯一の結合は桁上げ状態です。 どちらの数値も固定桁範囲に制限されているため、キャリーが 1 を超えることはなく、この状態を超える隠されたグローバル構造は存在しません。 したがって、ローカルに有効なすべての遷移を列挙すると、グローバルに有効なすべての分解が完全に特徴付けられます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ok(x: str) -> bool:
    digits = list(map(int, x[::-1]))
    
    # try both possibilities: same length or with implicit leading carry structure
    # but we only need standard carry simulation
    
    carry = 0
    
    for d in digits:
        found = False
        
        for a in range(5, 10):
            for b in range(5, 10):
                s = a + b + carry
                if s % 10 == d:
                    found = True
        
        if not found:
            return False
        
        # update carry in a consistent way: we must pick a valid transition
        # recompute carry deterministically by checking any valid pair
        new_carry = None
        for a in range(5, 10):
            for b in range(5, 10):
                s = a + b + carry
                if s % 10 == d:
                    new_carry = s // 10
                    break
            if new_carry is not None:
                break
        
        carry = new_carry
    
    # final carry must be 0
    return carry == 0

t = int(input())
for _ in range(t):
    x = input().strip()
    print("YES" if ok(x) else "NO")
```実装は列方向のシミュレーションに直接続きます。 数字のペアに対するネストされたループは一定の作業 (25 の組み合わせ) であるため、$10^4$テストケースでは高速のままです。 状態空間が小さいため、キャリーを決定するためのわずかに冗長な 2 番目のパスは許容されます。 より厳密な実装では、実現可能性をチェックしながら有効な遷移を保存できます。 

最もデリケートな部分は、キャリーの一貫性を尊重せずに誤って数字の一致を受け入れないようにすることです。 そのため、キャリーは大まかに推測されるのではなく、実際の有効なペアから再計算されます。

## テストケース```python
import sys, io

def solve():
    import sys
    input = sys.stdin.readline

    def ok(x: str) -> bool:
        digits = list(map(int, x[::-1]))
        carry = 0

        for d in digits:
            found = False
            new_carry = None

            for a in range(5, 10):
                for b in range(5, 10):
                    s = a + b + carry
                    if s % 10 == d:
                        found = True
                        if new_carry is None:
                            new_carry = s // 10

            if not found:
                return False
            carry = new_carry

        return carry == 0

    t = int(input())
    for _ in range(t):
        print("YES" if ok(input().strip()) else "NO")

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from contextlib import redirect_stdout
    import io as _io
    out = _io.StringIO()
    with redirect_stdout(out):
        solve()
    return out.getvalue().strip()

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、逆処理で数値の先頭に暗黙的にゼロが含まれる場合です。 例えば、`10`最下位桁がキャリー生成ペアを介して達成可能であることが必要です。 アルゴリズムは常に両方向のキャリーを考慮するため、これを処理します。`5+5=10`キャリー 1 を含む数字 0 が正しく生成されます。 

もう 1 つの微妙なケースは、数字の一致が存在するが、特定のキャリー遷移に対してのみ存在する場合です。 たとえば、列ではキャリーイン 0 では桁の一貫性が許可されますが、キャリーイン 1 では許可されない場合があります。アルゴリズムは現在のキャリー状態を持つすべての桁のペアを列挙するため、有効な完全な遷移のない列は決して受け入れられません。 

最後に、次のようなケース`200`最初の列が許容される桁の合計と一致しない限り、局所的な実現可能性では十分ではないことを示しています。 ペアが存在しないため、アルゴリズムは正しく即座に拒否します。$[5,9]$上流で互換性のないキャリー構造を生成することなく、単位桁 0 を生成できます。
