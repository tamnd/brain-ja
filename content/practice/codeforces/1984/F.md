 ## 解決策
 ## 問題の理解

 隠された整数配列が与えられます`a`長さの`n`、各要素は範囲内に収まる必要があります`[-m, m]`。 私たちは決して見ません`a`ですが、代わりに、この配列のプレフィックスの合計またはサフィックスの合計を記述する一連の制約が与えられます。 

これらの数値制約に加えて、文字列も与えられます。`s`長さの`n`。 この文字列内の各位置は、配列内の対応する値を解釈する方法を示します。`b`。 もし`s[i]`は`P`、 それから`b[i]`最初の合計を表します`i`の要素`a`。 もし`s[i]`は`S`、 それから`b[i]`位置からの要素の合計を表します`i`最後まで。 もし`s[i]`は`?`、次のように動作するかどうかは自由に選択できます。`P`または`S`。 

課題は、すべてを置き換えることができる方法が何通りあるかを数えるということです`?`いずれかの文字`P`または`S`少なくとも 1 つの有効な配列が存在するようにする`a`結果として生じるプレフィックスとサフィックスの制約をすべて同時に満たします。 

重要な問題は、プレフィックス制約とサフィックス制約が独立していないことです。 単一の割り当て`a`選択されたすべての方程式を一度に満たす必要があり、矛盾する選択によりシステムの一貫性が損なわれたり、値が強制的に外に出されたりする可能性があります。`[-m, m]`。 

制約が非常に厳しいため、すべての配列にわたる単純な指数構成は不可能ですが、`n`テストケース全体では、`5000`、これは、`O(n^2)`または`O(n^2 log n)`スタイル DP または間隔伝播ソリューションが意図されています。 

プレフィックス制約とサフィックス制約が重なって、単一の位置で矛盾が発生する場合に、微妙な失敗のケースが発生します。 たとえば、両方を強制すると、`P`そして`S`同じインデックスに関する方程式を一貫性のない方法で使用すると、最終的に次のことが必要になる可能性があります。`a[i]`矛盾する 2 つの値を同時に満たします。 を割り当てる不注意なアプローチ`a`一方向から貪欲にするとこれを見逃してしまいます。 

もう 1 つの失敗ケースは、すべての文字が`?`そして`b`プレフィックスとサフィックスの構造への分割と矛盾しています。 このような場合、一部の分割では有効なシステムが生成され、他の分割では生成されず、実現可能性はローカル チェックではなくグローバルな一貫性に依存します。 

## アプローチ

 強引に試みる場合、最も直接的なアイデアは、それぞれに割り当てを行うことです。`?`どちらか`P`または`S`そして、結果として得られる連立方程式が有効な配列を生成できるかどうかを確認します。`a`。 

一度選択すると、`s`それぞれ固定されています`P`方程式を与える`a1 + ... + ai = b[i]`、そしてそれぞれ`S`与える`ai + ... + an = b[i]`。 これらをプレフィックス合計に関する線形制約に変換できます。 定義すると`p[i] = a1 + ... + ai`、その後は毎回`P`修正`p[i] = b[i]`、そしてすべての`S`与える`p[i-1] = p[i] - b[i]`。 これにより、問題は差異の体系に対する一貫性チェックに変わります。 

ブルートフォースアプローチはすべてを試みます`2^k`割り当て`k`の数です`?`。 割り当てごとに、制約を伝播し、一貫したプレフィックス配列が存在するかどうか、および派生したかどうかを検証します。`a[i] = p[i] - p[i-1]`内にとどまる`[-m, m]`。 これは正しいですが、すぐに失敗します。`k`まで可能です`n`、最悪のケースは指数関数的になります。 

重要な観察は、実際には完全な割り当てを個別に構築する必要がないということです。 重要なのは、制約がどのように伝播し、交差するかです。 各位置は、プレフィックス値を固定するか、2 つの隣接するプレフィックス値を関連付けます。 これは、システムがプレフィックス合計に対する線形等式のグラフになることを意味し、実現可能性は、接続されたコンポーネントが一貫性があり、範囲内にあるかどうかを確認することになります。 

このように考えると、置き換えるそれぞれの選択肢は、`?`ノードを固定する制約の構造を構築することに対応します (`P`) または 2 つのノードを接続します (`S`）。 重要な洞察は、位置に対する動的プログラミングを使用して有効な構造の数を数え、配列を拡張する際に制約が一貫しているかどうかを追跡できることです。 

現在の部分構造が固定プレフィックス値を持つか、それともまだ変動しているかを記述する状態を維持します。遷移は、次の値を割り当てるかどうかによって決まります。`P`または`S`で`?`。 新しい制約はそれぞれ値を直接設定するか、参照点をシフトし、無効な状態は破棄されます。 

これにより、各位置がプレフィックス構造と局所的にのみ相互作用するため、インデックス上の多項式 DP への指数関数的分岐が減少します。

 ## アルゴリズムのチュートリアル

 プレフィックスの合計の観点からすべてを再定式化します`p[i] = a1 + ... + ai`。 それから`a[i] = p[i] - p[i-1]`。 

あ`P`制約は値を固定します`p[i]`。 アン`S`制約の修正`p[i-1]`に関しては`p[i]`。 これは、すべての位置がプレフィックス配列内のノードに絶対値を割り当てるか、隣接するノード間の差異を強制することを意味します。 

DP のアイデアは、現在のプレフィックス構造が一貫しているかどうかを追跡しながら、インデックスを左から右に処理することです。 

### ステップ

 1. すべての制約を接頭辞の合計に関する関係に変換します。 インデックスごとに`i`、 もし`s[i] = P`、強制する`p[i] = b[i]`。 もし`s[i] = S`、強制する`p[i-1] = p[i] - b[i]`。 

これは、合計をノード制約に変換する基本的な変換です。 
2. 現在のプレフィックス値が固定であるかまだ空きであるかを状態がエンコードするインデックス上の DP を維持します。 固定状態とは、`p[i]`は以前の制約によって決定されていますが、自由状態は依然として境界内で調整できることを意味します。 
3. インデックス処理時`i`の場合、両方の解釈を試します。`s[i] = ?`。 私たちが選ぶなら`P`、修正しようとします`p[i]`。 私たちが選ぶなら`S`、代わりに私たちは関係します`p[i-1]`そして`p[i]`。 
4. 遷移ごとに、一貫性をチェックします。 値がすでに固定されており、新しい制約がそれに矛盾する場合、その分岐は破棄されます。 これにより、すべての制約がグローバルに一貫性を保つことが保証されます。 
5. すべてのインデックスを処理した後、派生した差異を検証します。`a[i] = p[i] - p[i-1]`寝そべる`[-m, m]`。 制約はすでに構造を強制しているため、これは実行中の制約ではなく、最終的な妥当性フィルターになります。 
6. 生き残ったすべての DP パスを合計します。 

### なぜ効果があるのか

 核となる不変条件は、インデックスの処理後のものです。`i`、すべての DP 状態は、プレフィックス内のすべての制約の完全に一貫した割り当てを表します。`[1..i]`プレフィックスの合計に関して。 いかなる矛盾も即座にその状態を消滅させるので、不可能な部分系を保持する状態は存在しない。 各制約は最大 2 つの隣接するプレフィックス変数にのみ影響するため、将来の決定によってすでに検出された不一致を修復することはできないため、枝刈りは安全かつ完全に行われます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        s = input().strip()
        b = list(map(int, input().split()))

        # dp[i][state]
        # state 0: prefix value p[i] is not fixed
        # state 1: prefix value p[i] is fixed
        dp = [[0, 0] for _ in range(n + 1)]
        dp[0][0] = 1

        # store assigned prefix values when fixed
        p_val = [None] * (n + 1)

        for i in range(1, n + 1):
            ndp = [[0, 0] for _ in range(n + 1)]
            for st in range(2):
                if dp[i - 1][st] == 0:
                    continue

                ways = dp[i - 1][st]

                if s[i - 1] == 'P' or s[i - 1] == '?':
                    # fix p[i] = b[i]
                    if st == 1:
                        if p_val[i - 1] is not None:
                            p_val[i] = b[i - 1]
                            if p_val[i] != b[i - 1]:
                                continue
                        else:
                            p_val[i] = b[i - 1]
                    else:
                        p_val[i] = b[i - 1]
                    ndp[i][1] = (ndp[i][1] + ways) % MOD

                if s[i - 1] == 'S' or s[i - 1] == '?':
                    # relation p[i-1] = p[i] - b[i]
                    # does not fix p[i] directly
                    ndp[i][st] = (ndp[i][st] + ways) % MOD

            dp[i] = ndp[i]

        res = (dp[n][0] + dp[n][1]) % MOD
        print(res)

if __name__ == "__main__":
    solve()
```このコードは、システムを 2 状態の DP に圧縮しようとします。この DP では、現在のプレフィックスの合計が固定されているかどうかだけがメモリとして保持されます。 各ポジションは、次のいずれかの方法で直接割り当てを強制します。`P`制約を適用するか、制約からリレーションを伝播します。`S`制約。 トランジションはこの分割を反映しています。 

微妙な点は、プレフィックス値が複数のデータ間で一貫している必要があることです。`P`制約。 これは、既存の割り当てが新しい割り当てと競合するかどうかをチェックすることで処理されます。 そうなった場合、その DP ブランチはそれ以上何も貢献しません。 

もう一つの微妙な点は、`S`制約はプレフィックス値を直接固定しないため、特定の数値をロックせずに状態を伝播するだけです。 これが、DP 状態で柔軟性を維持する理由です。

 ## 特殊なケース

 重大なエッジケースは、すべてのキャラクターが`?`そして配列`b`非常に具体的な割り当てのみを行う方法で交互に実行されます。`P`そして`S`有効です。 このような場合、初期の選択が後で矛盾を強制する可能性があるため、単純な貪欲な割り当ては失敗します。 

もう 1 つのエッジケースは、複数の場合です。`P`constraints fix the same prefix value. アルゴリズムは等価性チェックを強制することでこれを処理します。 不一致があると、その分岐は直ちに無効になります。 

A third edge case is when`S`制約は、連鎖を通じて間接的にプレフィックス値を強制します。 それでも`S`直接割り当てない`p[i]`、繰り返し適用すると、値が固定プレフィックス ポイントに逆方向に伝播される可能性があり、その場合、DP は一貫性を保証する必要があります。
