 ## 解決策
 ## 問題の理解

 値を維持しながら配列を左から右に処理します`c`、最初は`0`。 

あらゆる要素について`a[i]`、選択肢は 2 つあります。 交換させていただく場合がございます`c`と`c + a[i]`、または次のように置き換えます`|c + a[i]|`。 すべての要素が処理された後、異なる選択順序により、異なる最終値が生成される場合があります。`c`。 

考えられるすべての手順の中で、`k`は、達成可能な最終的な最大値になります。 仕事は計算することではない`k`一人で。 この最大値を正確に達成する個別のプロシージャの数を数えなければなりません。 2 つのプロシージャは、結果として得られる中間値がたまたま同じであっても、任意の位置で異なる選択を行う場合、異なるものとみなされます。 

配列の長さは次のとおりです`2·10^5`、すべてのテスト ケースの長さの合計は次のようになります。`3·10^5`。 どのポジションにも 2 つの選択肢があるため、すべての手順を総当たりで実行するには検証が必要になります。`2^n`州は、たとえ`n = 60`、ましてや`200000`。 受け入れられた解決策は、基本的に配列サイズが線形である必要があります。 

難しいのは、異なるプロシージャが同じ値にマージされる可能性があることです。`c`。 到達可能なすべての値を追跡する単純なカウント DP は、値が次のような大きさになる可能性があるため、すぐに爆発します。`10^9 · n`。 

両方の操作が同じ結果を生成する場合、微妙なエッジ ケースが 1 つ発生します。 考慮する：```
a = [5]
```たった一つのステップで、`c + a[i] = 5`したがって、どちらの選択肢を選んでも次の結果が得られます。`5`。 最大値は`5`、有効な手順は 1 つではなく 2 つあります。 プロシージャではなく状態をカウントするソリューションでは、アンダーカウントされます。 

もう 1 つの重要なケースは、1 つの位置で絶対値を取得すると、後でより大きな結果が得られる場合です。```
a = [-1, -2]
```絶対値を使用しない場合、最終結果は次のようになります。`-3`。 2 番目の位置に演算を適用すると、次のようになります。`3`、これが最適です。 「直接的に有益な場合にのみ絶対的な価値を取る」などの貪欲なルールでは十分ではありません。 

3 番目のエッジ ケースは、複数の最適な履歴が同じ中間値に達する場合です。 例えば：```
a = [1, 1]
```すべての演算では値が負でないままになるため、両方の選択肢は常に同等です。 答えは`2^2 = 4`。 個別の値のみをカウントすると、誤って返される`1`。 

## アプローチ

 最も直接的な解決策はブルートフォースです。 At every position we branch into two possibilities, generating all`2^n`手順。 プロシージャごとに最終値を計算し、最大値を決定し、それを達成するプロシージャの数を数えます。 

これはプロセスの定義に正確に従っているため機能します。 残念ながら、`n = 200000`、手順の数はおおよそ次のとおりです。`10^60205`、それは完全に不可能です。 

重要な点は、プレフィックスを処理した後は、到達可能なすべての値を知る必要がないということです。 

いくつかのプレフィックスを処理したとします。 させて：`mn = minimum reachable value`

`mx = maximum reachable value`到達可能な値に対して`x`、次の遷移は以下にのみ依存します。`x + a[i]`そして`|x + a[i]|`。 

機能`f(y) = y`そして機能`g(y) = |y|`範囲の端点に関しては両方とも単調です。 別のステップの後に到達可能なすべての値を検査する場合、将来の最適性にとって重要となる値は、到達可能な最小値と最大値のみです。 

これは、ハード バージョンの標準ソリューションにつながります。 まず、追跡のみを行う DP を使用して、達成可能な最大値を計算します。`minimum reachable value`

`maximum reachable value`すべてのプレフィックスに対して。 

最大値になったら`k`がわかっている場合は、最適な極限状態に到達するプロシージャの数をカウントする別の DP を実行します。 

重要な事実は、最適性に関連する一連の状態が、位置ごとに 2 つの値 (現在の到達可能な最小値と最大値) を決して超えないということです。 これにより、複雑さが線形に保たれます。

 ## アルゴリズムのチュートリアル

 ### 最大値の計算

 1. 単一の到達可能な値から開始します`0`。 したがって`mn = mx = 0`。 
2. 各要素について`a[i]`、現在の極値から取得できるすべての値を計算します。`mn + a[i]`

`mx + a[i]`

`|mn + a[i]|`

`|mx + a[i]|`3. 新しい到達可能な最小値は、これら 4 つの数値の最小値です。 
4. 新しい到達可能な最大値は、これら 4 つの数値の最大値です。 
5. 配列全体を処理した後、達成可能な最終的な最大値は次のようになります。`mx`。 

明らかではない部分は、なぜ 4 つのエンドポイント遷移で十分なのかということです。 各ステップ後の到達可能なセットは、達成可能な極値に関して間隔を形成し、両方の遷移操作は間隔のエンドポイントで極値に達します。 

### 最適な手順を数える

 1. すべてのプレフィックスの極値 DP 配列を再計算します。 
2. しましょう`mn[i]`そして`mx[i]`最初の処理後に到達可能な最小値と最大値を示します。`i`要素。 
3. これらの極値に達したプロシージャの数を維持します。 
4. 各位置について、前の極限状態からのすべての遷移を試します。 

両方の操作を使用して以前の最小値から、

 両方の操作を使用して以前の最大値から増加します。 
5. 遷移によって新しい最小値が生成されるたびに、そのカウントを最小カウンタに追加します。 
6. 遷移によって新しい最大値が生成されるたびに、そのカウントを最大カウンタに追加します。 
7. 最小値と最大値が一致する場合は、同じ状態が二重にカウントされないように、慎重にカウントをマージします。 
8. すべての位置を処理した後、最終的な最大値に関連付けられたカウントを出力します。 

すべてのカウントはモジュロで実行されます`998244353`。 

### なぜ効果があるのか

 すべてのプレフィックスについて、到達可能な値はすべて、プレフィックスの最小値とプレフィックスの最大値の間にあります。 いずれかの操作をその間隔内の値に適用しても、間隔のエンドポイントの 1 つから取得されない新しい最小値または最大値を作成することはできません。 

したがって、将来の最適な動作は 2 つの極値状態にのみ依存します。 最初の DP は、すべてのプレフィックスの後に到達可能な極値を正しく計算します。 2 番目の DP は、これらの極値を達成するプロシージャの数を伝播します。 すべての最適な最終プロシージャはグローバルな到達可能な最大値で終了する必要があるため、各ステップで極値状態に到達する方法を数えることは、最終的な最適値を達成するプロシージャを正確にカウントします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    t = int(input())

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        mn = [0] * (n + 1)
        mx = [0] * (n + 1)

        for i in range(1, n + 1):
            x = a[i - 1]

            vals = (
                mn[i - 1] + x,
                mx[i - 1] + x,
                abs(mn[i - 1] + x),
                abs(mx[i - 1] + x),
            )

            mn[i] = min(vals)
            mx[i] = max(vals)

        if mn[0] == mx[0]:
            cnt_mn = 1
            cnt_mx = 1
        else:
            cnt_mn = 1
            cnt_mx = 1

        cur_mn = 0
        cur_mx = 0

        for i in range(1, n + 1):
            x = a[i - 1]

            nmn = mn[i]
            nmx = mx[i]

            next_cnt_mn = 0
            next_cnt_mx = 0

            states = []

            if cur_mn == cur_mx:
                states.append((cur_mn, cnt_mx))
            else:
                states.append((cur_mn, cnt_mn))
                states.append((cur_mx, cnt_mx))

            for value, ways in states:
                y1 = value + x
                y2 = abs(y1)

                if y1 == nmn:
                    next_cnt_mn = (next_cnt_mn + ways) % MOD
                if y1 == nmx:
                    next_cnt_mx = (next_cnt_mx + ways) % MOD

                if y2 == nmn:
                    next_cnt_mn = (next_cnt_mn + ways) % MOD
                if y2 == nmx:
                    next_cnt_mx = (next_cnt_mx + ways) % MOD

            cur_mn = nmn
            cur_mx = nmx
            cnt_mn = next_cnt_mn
            cnt_mx = next_cnt_mx

        print(cnt_mx % MOD)

if __name__ == "__main__":
    solve()
```最初のループは、すべてのプレフィックスの後に到達可能な最小値と最大値を計算します。 遷移後のすべての極値は前の極値に由来する必要があるため、必要な候補値は 4 つだけです。 

2 番目のループではカウントが実行されます。 それぞれの極限状態に対して、両方の合法的な操作を試みます。 遷移が次のプレフィックスの最小値または最大値に達するたびに、対応する数のプロシージャが追加されます。 

ときの特別な取り扱い`cur_mn == cur_mx`が不可欠です。 その状況では、両方の極値を同時に表しているとしても、実際の状態は 1 つだけです。 これを 2 回処理すると、プロシージャのカウントが 2 倍になります。 

すべての算術はモジュロを使用します`998244353`、必要に応じて。

                cnt_mn, cnt_mx = a1, a2
