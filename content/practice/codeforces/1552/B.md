 ## 解決策
 ## 問題の理解

 各アスリートは、過去のマラソンごとに 1 つのランキングを含む 5 つのランキングで説明されます。 ランク 1 は 1 位を意味するため、値が小さいほど優れています。 

2人のアスリートの場合`x`そして`y`、私たちはそう言います`x`より優れています`y`もし`x`5 つのマラソンのうち少なくとも 3 つでより良い順位を獲得している。 正確に 5 つの比較が行われるため、大部分の項目で優れている場合、1 人のアスリートが直接比較で勝利します。 

私たちの課題は、このペアごとの比較で他のすべてのアスリートを破るアスリートを見つけることです。 そのような選手が存在する場合、その選手の指数を出力します。 それ以外の場合は出力`-1`。 

まず注目すべきことは、優越関係は推移的ではないということです。 アスリート A が B に勝ち、B が C に勝つ場合、A が C に勝つとは限りません。これにより、多くの標準的な並べ替えベースのアイデアが即座に除外されます。 実際、サイクルが存在する可能性があります。 

制約が本当の手がかりです。 すべてのテストケースにわたるアスリートの総数は最大 50,000 人です。 二次アルゴリズムはおおよそのパフォーマンスを発揮します$$50{,}000^2 = 2.5 \times 10^9$$最悪の場合のペア比較。これは 1 秒に収まる量をはるかに超えています。 直線に近いものが必要です`n`。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

循環関係を考えてみましょう。```
3
10 10 20 30 30
20 20 30 10 10
30 30 10 20 20
```アスリート 1 は 2 に勝ち、アスリート 2 は 3 に勝ち、アスリート 3 は 1 に勝ちます。他のアスリートに勝つアスリートはいないので、答えは次のようになります。`-1`。 「最高の平均ランク」を持つアスリートを選択しようとするアプローチは、誤って誰かを返すことになります。 

もう 1 つの微妙なケースは、候補者が全員ではなく多くのアスリートに勝つ場合です。```
3
1 1 1 100 100
2 2 2 1 1
3 3 3 2 2
```アスリート 1 はアスリート 2 に勝ちますが、アスリート 2 はアスリート 3 に勝ちます。最終候補がすべてのアスリートに勝つことを明示的に検証する必要があります。 敵を排除するだけでは十分ではありません。 

可能な限り最小のテスト ケースもチェックする価値があります。```
1
50000 1 50000 50000 50000
```アスリートが 1 人だけの場合、そのアスリートは要件を自明に満たします。 

## アプローチ

 ブルートフォースのアイデアは単純です。 すべてのアスリートにとって`i`、他のすべてのアスリートと比較してください`j`。 もし`i`他のすべてを打ち負かして、戻ってください`i`。 

ランキングは 5 つしかないため、2 人のアスリートの比較には一定の時間がかかります。 問題は比較の回数です。 出演します`O(n²)`ペアチェック。 と`n = 50,000`とすると、およそ 25 億件の比較が行われることになりますが、これでは遅すぎます。 

何かをより速く取得するには、次元が 5 つしかないという事実を利用する必要があります。 

有効なチャンピオンが存在すると仮定します。 あの選手をそうさせよう`C`。 

現在の候補者を維持しながら、アスリートを左から右にスキャンすることを想像してください。 別のアスリートが現在の候補者に勝つたびに、その候補者を交代します。 

なぜこれが興味深いのでしょうか? 現在の候補者が誰かに負けた場合、現在の候補者は世界チャンピオンになることはできません。 チャンピオンは全員を倒さなければなりません。 一度でも負けると即失格となります。 

これは、支配的な要素やトーナメントの勝者を見つける際に使用されるエリミネーションのアイデアとまったく同じです。 比較するたびに、1 人のアスリートが検討対象から除外されます。 

1 回の直線パスの後、生き残る候補者は 1 人だけです。 

残る問題は、その生存者が本当に正当であるかどうかである。 優越関係は推移的ではないため、生存者は潜在的なチャンピオンにすぎません。 すべてのアスリートに対して検証する必要があります。 

重要な所見は次のとおりです。 

チャンピオンが存在する場合、エリミネーションパスではそれを除去することはできません。 チャンピオンと対戦したアスリートは負けるので、最終的にはチャンピオンが候補者になるか、候補者のままになります。 したがって、敗退フェーズは常に真のチャンピオンが存在する場合に終了します。 

候補を取得した後、2 回目のリニア スキャンですべてのアスリートに勝つかどうかを確認します。 いずれかのアスリートが候補者を破った場合、チャンピオンは存在しません。

 | ブルートフォース | O(n²) | お(1) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのアスリートを読み取り、5 つのランキングを保存します。 
2. 比較関数を定義する`better(a, b)`アスリートの場合は true を返します`a`アスリートよりもランクが低い`b`5回のマラソンのうち少なくとも3回で出場。 
3. アスリートから始める`0`現在の候補としては。 
4. アスリートを左から右にスキャンします。 
5. アスリートごとに`i`、 比較する`i`今の候補者と一緒に。 
6. アスリートの場合`i`現在の候補者に勝つ場合は、候補者を次の候補者に置き換えます`i`。 

古い候補者は現在、直接比較で負けているため、誰よりも優れているとは考えられません。 
7. スキャンが終了すると、生き残った候補者は 1 人になります。 
8. 候補者をすべてのアスリートと比較して検証します。 
9. 候補者に勝った選手がいる場合は出力`-1`。 
10. それ以外の場合は、候補の 1 から始まるインデックスを出力します。 

### なぜ効果があるのか

 エリミネーションパスでは、交代ごとに世界チャンピオンになれないアスリートが 1 人除外されます。 スポーツ選手なら`A`スポーツ選手に負ける`B`、 それから`A`確かにすべてのアスリートより優れているわけではありません。 

有効なチャンピオンを仮定する`C`存在します。 いつでも`C`他のアスリートと比較されると、`C`勝ちます。 そこで一度`C`候補となるため、削除することはできません。 それが起こる前でさえ、他のアスリートを排除するすべてのアスリートは、単に非チャンピオンを排除しているだけです。 最終的にスキャンは次のように終了します。`C`候補としては。 

チャンピオンが存在しない場合でも、エリミネーション パスによって生存者が生成されます。 検証パスは、サバイバーを倒すアスリートを見つけることでこれを検出します。 したがって、アルゴリズムは、有効なアスリートが存在する場合、正確にそれを返します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def better(a, b):
    cnt = 0
    for k in range(5):
        if a[k] < b[k]:
            cnt += 1
    return cnt >= 3

t = int(input())

for _ in range(t):
    n = int(input())
    athletes = [list(map(int, input().split())) for _ in range(n)]

    cand = 0

    for i in range(1, n):
        if better(athletes[i], athletes[cand]):
            cand = i

    ok = True
    for i in range(n):
        if i != cand and not better(athletes[cand], athletes[i]):
            ok = False
            break

    print(cand + 1 if ok else -1)
```の`better`関数は問題の定義を直接実装します。 5 人のマラソン選手のうち何人が出場したかを数えます`a`アスリートよりも優れたパフォーマンスを発揮した`b`。 少なくとも 3 つの次元で勝利するということは、過半数の比較で勝利することを意味します。 

最初のループは削除フェーズを実行します。 別のアスリートが現在の候補者に勝つたびに、現在の候補者は永久に破棄されます。 

2 番目のループは重要な検証フェーズです。 優劣関係は推移的ではないため、最初のパスの生き残りが自動的に有効になるわけではありません。 それがすべてのアスリートに勝つことを明確に確認する必要があります。 

Python リストではゼロベースのインデックスが使用されるため、インデックスはゼロベースの値として内部的に保存されます。 この問題では 1 から始まるアスリートの番号付けが使用されているため、最終的な答えは出力する前に 1 を追加します。 

特別な処理は必要ありません`n = 1`。 エリミネーション ループは何も行わず、検証ループは成功し、アスリート 1 が出力されます。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    def better(a, b):
        cnt = 0
        for k in range(5):
            if a[k] < b[k]:
                cnt += 1
        return cnt >= 3

    t = int(input())
    ans = []

    for _ in range(t):
        n = int(input())
        athletes = [list(map(int, input().split())) for _ in range(n)]

        cand = 0

        for i in range(1, n):
            if better(athletes[i], athletes[cand]):
                cand = i

        ok = True
        for i in range(n):
            if i != cand and not better(athletes[cand], athletes[i]):
                ok = False
                break

        ans.append(str(cand + 1 if ok else -1))

    print("\n".join(ans))

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out

    solve()

    sys.stdin = old_stdin
    sys.stdout = old_stdout

    return out.getvalue()

 ## 特殊なケース

 循環的な例を考えてみましょう。```
3

30 30 10 20 20
```エリミネーション パスはアスリート 3 で終了します。不注意な解決法では、すぐに 3 が出力される可能性があります。検証中に、アスリート 2 がアスリート 3 に勝つため、アルゴリズムは正しく返されます。`-1`。 

一人のアスリートの場合を考えてみましょう。```

```候補者はアスリート 1 として開始します。除外比較は行われません。 検証では、対戦相手がいないため、意味のあるチェックも実行されません。 アルゴリズムの出力`1`、定義と一致します。

3

3 3 3 3 3
