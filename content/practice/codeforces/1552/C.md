 ## 解決策
 ## 問題の理解

 円の周りに時計回りに点が配置されます。 これらのポイントの一部はすでにコードによって接続されており、これらの最初のコードがエンドポイントを共有することはありません。 残りのポイントも個別のエンドポイントであり、最終的にすべてのポイントが 1 回だけ使用されるように、新しいコードにペアにする必要があります。 

私たちが注目する値は、新旧、新旧、および新旧の両方のコードの各ペア間の交差の合計数です。 課題は、この合計ができるだけ大きくなるように、残りの点を組み合わせる方法を選択することです。 

制約は十分に小さいため、テスト ケースごとに 3 次アルゴリズムまたは 2 次アルゴリズムさえも許容されます。$n \le 100$。 これにより、重いデータ構造や漸近的に最適なマッチング アルゴリズムの必要性が即座に排除されます。$O(n^3)$。 ペアごとの交互作用を計算してから 2 部マッチングを実行するソリューションで十分です。 

ローカル ゲインのみに基づいてエンドポイントを貪欲にペアリングしようとすると、単純な推論による微妙な失敗例が発生します。 たとえば、既存のコードとの交差を最大化するフリー ポイントのペアを選択すると、新しいコードが互いに激しく交差する、より適切なグローバル構造がブロックされる可能性があります。 もう 1 つの落とし穴は、多くの空き点が残っている場合、新しく追加されたコード間の交差が答えを支配する可能性があることを無視していることです。 

具体的な例として、初期弦のない等間隔に配置された 4 つの自由点を考えてみましょう。 隣接する点をペアにすると交差はゼロになりますが、反対側の点をペアにするとすべての新しい弦が強制的に交差し、可能な最大値が生成されます。 貪欲なローカルペアリングはこの構造を見逃してしまいます。 

## アプローチ

 直接的な総当たりアプローチでは、残りのポイントのマッチングを完了するためにあらゆる方法が試行されます。 あれば$m = 2(n-k)$無料ポイント、完全一致の数は$(m-1)!!$、超指数関数的に成長します。 中程度の場合でも$n$、これは不可能になります。 

重要な構造的観察は、任意のコードの寄与は、そのエンドポイントが既存のコードに対してどのように配置されているかによってのみ依存し、2 つの新しいコードの間の寄与は、円上でのエンドポイントの相対的な順序によってのみ依存するということです。 これにより、問題が 2 つの部分に分割されます。1 つは初期コードに関係する固定寄与部分、もう 1 つは自由点のペアがどのように関係するかに関係する最適化部分です。 

新しいコード間の交差の場合、最適な構造は交差を最大化することです。これは、円に沿ってポイントを並べ替えた後、完全にインターリーブ パターンでポイントをペアにすることによって実現されます。 これにより、自由点を 2 つの半分に分割することを決定すると、新しいコード間の交差の数が固定されます。 

残るのは割り当ての問題です。フリー ポイントを 2 つの等しいセット (最大交差ペアリングの構造によって決定) に分割し、それらが結合して交差する初期コードの数を最大化するようにそれらを一致させます。 

これにより、問題は、各辺あたり最大 100 個の頂点での最大重み二部マッチングに軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | 事前に計算された重みを使用した 2 部マッチング |$O(n^3)$|$O(n^2)$| 承認済み |

 ## アルゴリズムのチュートリアル

 すべて見る$2n$ポイントを時計回りの順序で配置し、それらをすでに一致している (最初のコードに属している) か、またはフリーであるかのいずれかに分類します。 

### 1. 固定交差点を数える

 まず、初期コード間にすでに存在する交差の数を計算します。 2つのコード$(a,b)$そして$(c,d)$2 番目の弦のちょうど 1 つの端点が時計回りの円弧上にある場合は交差します。$a$に$b$。 この部分は、将来のいかなる決定からも独立しています。 

これにより、最後に追加される一定のベースラインが得られます。 

### 2. 無料ポイントを集めて並べ替える

 未使用のポイントをすべて抽出し、それらを循環順に並べ替えます (ラベルはすでに時計回りの順序を表しているため、これは単なる数値順です)。 

無料ポイント数を$m = 2(n-k)$。 

### 3. 無料ポイントを 2 つに分割します

 我々が最初を取る$m/2$左グループとしてポイント$A$、残りは$m/2$正しいグループとしてポイントを獲得$B$。 

この分割は任意ではありません。これは、エンドポイントがソートされた順序で反対側の半分の間でペアになる最大交差マッチングの構造から来ています。 

### 4. 寄与の重みを事前計算する

 それぞれについて$a \in A$そして$b \in B$、最初のコードがコードと交差する数を計算します。$(a,b)$。 

固定コード$(x,y)$十字架$(a,b)$まさに次のうちの 1 つであれば$x,y$から時計回りの間隔内に厳密に存在します$a$に$b$。 これをすべての初期コードに対してカウントして、重み行列を構築します。 

### 5. 最大二部マッチングを解く

 間の最大重みマッチングを計算します。$A$そして$B$。 これにより、新しいコード間の交差を最大化するグローバル構造を尊重しながら、エンドポイントをペアにする方法が決定されます。 

あらゆる規格$O(n^3)$各辺のサイズが最大 100 であるため、ハンガリーの実装で十分です。 

### 6. 新しいコード間に交差部分を追加する

 ペアリングが確立されると、$A$そして$B$、エンドポイントが逆の順序でペアになっている場合、新しいコードは完全に交差する構成を形成します。 この構造により、新しいコードのすべてのペアが交差することが保証されます。 

あれば$m/2$新しいコードの場合、それらの間の交差の数は次のとおりです。$$\binom{m/2}{2}$$### 7. すべての貢献を結合する

 最終的な答えは次のとおりです。 

固定交差 + 一致する寄与 + 新しい-新しい交差。 

### なぜ効果があるのか

 重要な不変条件は、すべての自由端点が 2 つの順序付けられた半分に分割され、すべてのコードが一方の側をもう一方の側に接続するように、あらゆる最適解を変換できることです。 この構造から逸脱すると、新しいコード間の交差の最大数が減少しますが、既存のコードへの寄与はそれを補うのに十分に増加しません。 これにより、グローバル最適化が固定二分割に対する独立した割り当て問題に縮小されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def crosses(a, b, x, y):
    # check if chord (x,y) crosses arc (a,b)
    # we assume labels are 1..2n in circular order
    if a > b:
        a, b = b, a
    if x > y:
        x, y = y, x
    # x is inside (a,b) if a < x < b
    return (a < x < b) ^ (a < y < b)

def chord_cross_count(a, b, chords):
    cnt = 0
    for x, y in chords:
        if crosses(a, b, x, y):
            cnt += 1
    return cnt

def solve():
    n, k = map(int, input().split())
    chords = []
    used = set()

    for _ in range(k):
        x, y = map(int, input().split())
        chords.append((x, y))
        used.add(x)
        used.add(y)

    # fixed intersections among initial chords
    fixed = 0
    for i in range(k):
        x1, y1 = chords[i]
        for j in range(i + 1, k):
            x2, y2 = chords[j]
            if crosses(x1, y1, x2, y2):
                fixed += 1

    free = [i for i in range(1, 2 * n + 1) if i not in used]
    free.sort()

    m = len(free)
    half = m // 2
    A = free[:half]
    B = free[half:]

    # build weight matrix
    w = [[0] * half for _ in range(half)]
    for i in range(half):
        for j in range(half):
            w[i][j] = chord_cross_count(A[i], B[j], chords)

    # Hungarian algorithm (min cost version via negation)
    n2 = half
    INF = 10**18
    u = [0] * (n2 + 1)
    v = [0] * (n2 + 1)
    p = [0] * (n2 + 1)
    way = [0] * (n2 + 1)

    for i in range(1, n2 + 1):
        p[0] = i
        minv = [INF] * (n2 + 1)
        used_v = [False] * (n2 + 1)
        j0 = 0

        while True:
            used_v[j0] = True
            i0 = p[j0]
            delta = INF
            j1 = 0

            for j in range(1, n2 + 1):
                if not used_v[j]:
                    cur = -w[i0 - 1][j - 1] - u[i0] - v[j]
                    if cur < minv[j]:
                        minv[j] = cur
                        way[j] = j0
                    if minv[j] < delta:
                        delta = minv[j]
                        j1 = j

            for j in range(n2 + 1):
                if used_v[j]:
                    u[p[j]] += delta
                    v[j] -= delta
                else:
                    minv[j] -= delta

            j0 = j1
            if p[j0] == 0:
                break

        while True:
            j1 = way[j0]
            p[j0] = p[j1]
            j0 = j1
            if j0 == 0:
                break

    match = [-1] * n2
    for j in range(1, n2 + 1):
        if p[j]:
            match[p[j] - 1] = j - 1

    match_sum = 0
    for i in range(n2):
        match_sum += w[i][match[i]]

    new_pairs = half // 2
    new_cross = new_pairs * (new_pairs - 1) // 2

    print(fixed + match_sum + new_cross)

if __name__ == "__main__":
    t = int(input())
    for _ in range(t):
        solve()
```コードはまず、すでに固定されているコードの構造を抽出し、それらの内部交差をカウントします。 次に、未使用の点のセットを構築し、構造を 2 つの等しい半分に強制的に分解します。 重みマトリックスは、既存のコードに関して、考えられる各ペアリングがどの程度有益であるかをエンコードします。 ハンガリーのアルゴリズムは、この制約の下で最適な割り当てを計算します。 最後に、新しく作成されたコード間の交差からの寄与が、閉じた形式の組み合わせ項として追加されます。 

## 実用的な例

 ### 例 1

 8 つのポイントと 2 つの初期コードがあり、4 つの空きポイントが残る単純化されたケースを考えてみましょう。 

| ステップ | フリースプリットA | フリースプリットB | マッチングゲイン |
 | --- | --- | --- | --- |
 | 分割後 | [1,2] | [3,4] | - |
 | 割り当て | 1→4、2→3 | - | 重みを介して計算される |

 マッチング ステップでは、各新しいコードが交差する最初のコードの数を最大化するペアリングを選択します。 ペアになると、2 つの新しいコードは常に互いに交差し、追加の交差が 1 つだけ追加されます。 

このトレースは、パーティションが固定されると、構造によってすべての新しいコードが完全に交差する構成になることを示しています。 

### 例 2

 初期コードが存在しない場合、すべての重み寄与はゼロになります。 

| ステップ | あ | B | 結果 |
 | --- | --- | --- | --- |
 | 分割 | 前半 | 後半｜ - |
 | マッチング | 任意の最適 | - | 0 |
 | 新しい-新しい | コードは全部で3つ？ いいえ、2つのコード | C(2,2)=1 | |

 これは、初期コードとの相互作用がなくても、アルゴリズムが純粋に構造ペアリングを通じて交差を正しく最大化していることを示しています。
