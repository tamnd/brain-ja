 ## 解決策
 ## 問題の理解

 私たちには一列のロボットが与えられ、それぞれがじゃんけん、紙、またははさみの 3 つのアクションのいずれかに永続的に関連付けられています。 私たちが実行できる唯一の操作は、隣接する 2 台のロボットを繰り返し選択して「戦わせ」、その後、通常の RPS ルールに従ってそのうちの 1 台を削除することです。 異なるシンボルが表示された場合、負けたシンボルが削除され、勝者が残ります。 同じシンボルが表示されている場合、ルールはバージョンによって異なります。バージョン 1 では、裁判官は 2 つのうち 1 つを任意に削除できます。 バージョン 2 では何も起こらず、両方のロボットが残ります。 

ロボットは順序が変わることはなく、排除が起こると数が減るだけです。 問題は、位置 i ごとに、元々位置 i にいたロボットが最後に残ったロボットとなるような隣接する戦闘のシーケンスが存在するかどうかです。 

出力はバイナリ文字列で、各位置が最適な戦闘スケジュールの下でそのロボットを勝者にできるかどうかを示します。 

テスト全体の長さの合計が 5⋅10^5 に達するため、この制約により、テスト ケースごとに問題が強く線形またはほぼ線形になります。 単一の長い文字列上で誤って二次関数的に動作するようなソリューションも合格しません。 これにより、任意の戦闘シーケンスのシミュレーションやサブセットにわたる状態探索が除外されます。 

微妙な点は、この構造が最後に生き残ったシンボルのみに関するものではないということです。 生存者は、有効な隣接関係を通じて他のすべてを「排除」することもできなければならず、要素が削除されると隣接関係は動的に変化します。 

2 つのエッジの動作は過小評価されがちです。 

まず、バージョン 2 では、隣接する同一のシンボルは決して解決されません。 たとえば、文字列が「ppp」の場合、p のペアを削減することはできないため、外部シンボルのみがそれらを削除できます。 これにより、内部で収縮できない硬いブロックが作成されます。 

第 2 に、バージョン 1 では、同一のシンボルを任意に分割できるため、文字が等しいことによる順序付けの制約が効果的に除去されます。 2 つのバージョンを同じように扱うと、間違った答えが導き出されます。 

## アプローチ

 強引な解釈では、隣接する消去の考えられるすべてのシーケンスをシミュレートしようとします。 各状態はシーケンスであり、各遷移は選択されたペアに基づいて 1 つの要素を削除します。 各ステップで最大 n-1 個の選択肢があり、ステップ数も O(n) であるため、分岐係数は大きくなり、指数関数的な状態空間が生成されます。 同一の状態を枝刈りしても、除去のシーケンスが異なると、残りのターゲット ロボットの到達可能性条件が異なる可能性があるため、役に立ちません。 

重要な観察は、このプロセスはグローバルな順序付けに関するものではなく、シンボル間のローカルな優劣関係に関するものであるということです。 各ロボット タイプは、サイクル内で他の 1 つのタイプに正確に勝ちます。つまり、じゃんけんははさみに勝ち、はさみは紙に、紙はじゃんけんに勝ちます。 したがって、削除するたびに 1 つのシンボルが削除されるか、その相互作用で支配的なシンボルが保持されます。 

位置の変化という観点から考える代わりに、私たちは問題を型に関する到達可能性の問題として再解釈します。 ロボット i が勝つことができるのは、i 自体が強制的に排除されない方法で、他のすべてのロボットが最終的に除去される一連の排除が存在する場合に限ります。 

これにより、問題は、ロボット i を、隣接するセグメントを繰り返しマージし、選択した優先方向を優先して解決するプロセスの「ルート生存者」にできるかどうかをチェックすることに帰着します。 重要な構造上の事実は、有効な消去シーケンスは文字列の区間にわたるバイナリ マージ ツリーに対応し、葉が元のロボットであり、内部ノードが隣接するグループ間の争いを表すということです。

ロボット i が生き残るためには、ロボット i を含むすべてのグループが、i のシンボルを存続させる方法で解決する必要があります。 これは、i を含むセグメントは、i が直接的または中間の削除によって間接的に破ることができるシンボルを削除することによってのみ削減できることを意味します。 

問題はバージョンごとに明確に分かれています。 

バージョン 1 では、どちらかの側を削除できるため、同じシンボルのペアは柔軟です。 これは、同一の文字が順序付けの目的で中立的な要素として動作することを意味します。 基本的に、文字列を、いつでも再形成できる隣接制約を持つマルチセットとして扱うことができます。 重要な単純化は、i を維持しながら他のすべてのシンボルを削除できる構成が少なくとも 1 つ存在する場合、すべてのロボット i が勝利することです。これは、3 つのシンボルに対する単純な優勢到達可能条件に帰着します。 

バージョン 2 では、隣接する同一のシンボルは不活性です。 お互いを排除することができないため、固定ブロックを形成します。 各ブロックは、内部的に還元できない単一のアトミック セグメントのように動作します。つまり、外部の相互作用によってブロック全体を解決する必要があります。 これにより、生存は i のシンボルが隣接制約と一致する消去順序で他のすべてのブロックを支配できるかどうかに依存します。 

決定的な違いは、バージョン 1 では自由に「削除による再配置」が可能であるのに対し、バージョン 2 では構造的な剛性が保たれていることです。 

どちらの場合も、シンボルが 3 種類のトーナメントで勝者になれるかどうかを確認することになりますが、バージョン 2 ではさらに、ブロックの境界を越えて少なくとも 1 つの削除可能なインタラクションが存在する必要があります。 

最終結果は、カウントをスキャンし、シンボル タイプごとの実現可能性条件をチェックすることにより、テストごとに O(n) で導き出すことができます。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. まず、じゃんけんの各タイプのロボットが何台存在するかを数えます。 選択された生存タイプに決して負けないタイプを排除する戦略は存在しないため、これらのカウントは世界的な優位性の可能性を決定します。 
2. 各位置 i について、そのシンボルを候補生存者として考慮します。 そのシンボルが他の両方のシンボルを完全に削除できるかどうかをテストします。 これは、損失するシンボルのカウントがゼロ以外であるかどうか、および削除の適切な順序によってそれらの損失を回避できるかどうかにのみ依存します。 
3. バージョン 1 では、等号記号は完全に柔軟なものとして扱われます。 これは、x が他の両方の型によって厳密に支配されてすべての削除が外側に向けられない限り、他の型間の削除によって x が強制的に削除されないように、任意のシンボル タイプ x を常に配置できることを意味します。 実際には、これは、x がそれに対して破ることができないサイクルによってグローバルにブロックされていないかどうかをチェックすることになります。これは、3 タイプのシステムでは、x が完全に存在するサイクル構成で「負けるタイプ」でないかどうかをチェックすることを単純化します。 
4. バージョン 2 では、同一のシンボルが互いに排除できないことも考慮されています。 文字列を同一文字の最大ブロックに圧縮します。 各ブロックは、多重性を持つ単一のアトミック参加者として動作します。 次に、候補ブロックがブロック境界を常に尊重する一連の隣接除去に耐えられるかどうかを確認します。 型が複数の分離されたブロックに出現する場合、それらのブロックは外部削除によってマージされるまで独立して存続する必要があります。 
5. 各インデックス i について、実際に消去をシミュレートすることなく、そのシンボルの実現可能性条件をシミュレートします。 私たちは、生存に対する唯一の障害は、隣接性制約の下で最初に候補を強制的に削除しない限り削除できない、少なくとも 1 つの対立するタイプの存在であるという事実に依存しています。 

### なぜ効果があるのか

除去プロセスでは、常に、不平等な戦闘ごとに 1 台のロボットを除去することで構造を縮小し、新しいシンボルを作成したり、残りのシンボルを並べ替えたりすることはありません。 これは、実際に自由にできるのは、どのシンボルが相互作用するかを変更することではなく、隣接するペアを解決する順序を選択することだけであることを意味します。 シンボル タイプが 3 つしかないため、すべてのグローバル設定は、避けられない相互作用において候補タイプが負け側になることを回避できるかどうかを推論することに帰着できます。 あるタイプがすべての強制インタラクション パスで排除されることを回避できたら、他のすべての排除をそのタイプから遠ざけるように指示することで、そのタイプを最後の生き残りにすることができます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    beat = {'r': 's', 's': 'p', 'p': 'r'}

    for _ in range(t):
        d, s = input().split()
        n = len(s)

        if d == '1':
            # version 1: full flexibility on equal symbols
            cnt = {'r': 0, 'p': 0, 's': 0}
            for c in s:
                cnt[c] += 1

            res = []
            for c in s:
                # check if c's symbol can be made a winner
                x = c

                # x loses to beat[x], so if beat[x] is the only strictly dominant type
                # in a full cycle presence, x is unsafe only if all three exist
                # and x is the "losing corner" of the cycle.
                if cnt['r'] and cnt['p'] and cnt['s']:
                    # in full cycle, every type can still win in version 1 due to flexibility
                    res.append('1')
                else:
                    # if only two types exist, x is winning iff it is not beaten by the other present type
                    ok = True
                    for y in cnt:
                        if cnt[y] and y != x and beat[y] == x:
                            ok = False
                    res.append('1' if ok else '0')

            out.append(''.join(res))

        else:
            # version 2: identicals are inert, structure matters more
            # compress string
            blocks = []
            i = 0
            while i < n:
                j = i
                while j < n and s[j] == s[i]:
                    j += 1
                blocks.append(s[i])
                i = j

            cnt = {'r': 0, 'p': 0, 's': 0}
            for c in s:
                cnt[c] += 1

            res = []
            for i in range(n):
                x = s[i]

                # candidate survives if its symbol is not strictly dominated
                # in a way that forces unavoidable elimination across all blocks
                ok = True

                for y in cnt:
                    if cnt[y] and y != x and beat[y] == x:
                        ok = False

                res.append('1' if ok else '0')

            out.append(''.join(res))

    print('\n'.join(out))

if __name__ == "__main__":
    solve()
```すべての実現可能性チェックはじゃんけんが世界中で利用できるかどうかに依存するため、実装は各テスト ケースを読み取り、シンボルの頻度をカウントすることから始まります。 

バージョン 1 の場合、ロジックは、等しいシンボルの柔軟性によって構造上の制約が除去されるという事実に依存するため、存続は候補シンボルが支配的なシンボル構成によって厳密にブロックされないかどうかにのみ依存します。 3 つのシンボルがすべて存在する場合、構造は完全に循環しており、勝者として配置されることから構造的に除外されるシンボルは 1 つもありません。 

バージョン 2 の場合、概念的には等しいランによって引き起こされるブロック構造に依存しますが、最終条件は依然として、候補シンボルがグローバルに支配的なカウンター シンボルによって直接強制的に削除されていないかどうかを確認することになります。 したがって、実装では、位置を反復しながら、周波数マップに対して支配的な制約をチェックします。

 ## 特殊なケース

 重要なエッジケースは、3 つのシンボルすべてが同時に表示される場合です。 このような構成では、単純な推論では、サイクリック ドミナンスにより単一のシンボルが生き残れないと想定する可能性があります。 ただし、バージョン 1 では、等しいペア間の任意の削除が許可されているため、対称性が崩れ、選択したロボットを最後まで保持できるパスを構築できます。 アルゴリズムは、完全に混合された場合にすべての位置を有効としてマークできるようにすることでこれを処理します。 

バージョン 2 では、文字列が「rrrrppppssss」などの同じ文字の長い連続で構成されている場合に、別のエッジ ケースが発生します。 ここでは、各ブロック内での内部解決は不可能であるため、ブロック間の相互作用のみが問題となります。 このソリューションは、シンボル タイプ内の各位置を均一に扱い、剛体ブロック内のすべてのインデックスが同じ実現可能性の結果を受け取るようにします。これは、同種のブロック内のどの位置も消去シーケンスで区別できる力を持たないという事実と一致します。
