 ## 解決策
 ## 問題の理解

 私たちは特別な構造を持つグラフを扱っています。 0 というラベルが付けられた識別されたノードがあり、1 から n までの他のすべてのノードは、最初に重みが与えられるエッジによって直接接続されています。 これらの「スター エッジ」に加えて、1 ～ n のノード間に固定重みを持つ m 個の通常のエッジもあります。 

タスクは動的です。 一連の更新情報を受け取ります。 各更新により、ノード 0 を頂点 i に接続する 1 つのエッジの重みが永続的に変更されます。 更新のたびに、グラフ全体の最小スパニング ツリーの重みを出力する必要があります。 

重要な点は、ノード 0 に属するエッジのみが時間の経過とともに変化するということです。 1 から n までの内部エッジは固定されたままであるため、MST のすべての変更は、どの頂点が 0 に直接接続することを好むか、内部グラフを介して接続するかを交換することによって発生します。 

制約は最大 300,000 個の頂点、エッジ、クエリに達します。 これにより、クエリごとに MST を最初から再計算する必要がなくなり、毎回およそ O((n + m) log n) がかかり、非常に遅すぎます。 

MST を維持し、重みが変更されるたびに段階的に更新するという単純な考えがあります。 単一のスター エッジを変更すると MST がグローバルに再構築され、多くのエッジに複雑な影響を与える可能性があるため、このアプローチは機能しません。 

失敗例の小さな例は三角形です。ノード 0、1、2 にエッジ (0,1)=a1、(0,2)=a2、および (1,2)=w があります。 a1 を下げると、ノード 1 はエッジ (1,2) の使用から 0 への直接接続に切り替わり、ノード 2 が (1,2) を使用するか 0 に接続するかが変わります。ローカル更新ルールはこの伝播をキャプチャできません。 

したがって、「ルートへの接続コスト」の変化に効率的に対応するグローバル構造が必要です。 

## アプローチ

 動的更新を無視する場合、MST を計算するのが標準です。 クラスカルは、すべてのエッジをソートして n 個のエッジを選択し、O((n + m) log (n + m)) を与えます。 ただし、更新のたびにこれを繰り返すと、コストが約 30 万倍かかり、現実的ではありません。 

実際の構造は、ノード 0 を「仮想ルート」として見ることで得られます。 すべての頂点 i には、コスト a[i] を持つルートへの直接エッジがあり、さらに、内部グラフ内の何らかのパスを介して間接的にルートに到達できます。 任意の頂点 i について、MST はそれを 0 に直接接続するか、内部グラフ内のパスを介して、最終的にすでに 0 に接続されている頂点に到達します。 

これは、「各頂点を 0 を含む既に構築されたコンポーネントにどれだけ安価に接続できるか」という観点から考えることを示唆しています。 内部エッジは、高価なスター エッジを安価な間接接続に「置き換える」最短の方法を定義します。 

重要な再定式化は、ノード 0 が最初に分離されているグラフ上に MST を構築することを考えることです。頂点 i をその直接エッジを介して接続するのが最適かどうか、それとも内部エッジを介してすでに接続されている他の頂点 j を介して接続する方が安価かどうかを繰り返し検討します。 

これにより、標準的な変換が行われます。ノード 0 を無視してベースライン MST を計算し、0 への接続をその構造と競合する潜在的なエッジとして扱うことができます。 より正確には、内部エッジのみを使用して Kruskal によって構築された頂点 1..n 上のフォレストから開始することを想像できます。 次に、ノード 0 は、そのコンポーネント内で利用可能な最も安価な a[i] によって各コンポーネントに接続されますが、これらの値は動的に変化します。 

重要な観察は、内部グラフの各接続コンポーネント内では、そのコンポーネントを 0 に接続するために最小値 a[i] のみが重要であるということです。同じコンポーネント内の他の頂点は、最小値によって支配されるため、接続点として選択されることはありません。 

したがって、問題は動的配列 a[i] を維持することになりますが、固定グラフの DSU コンポーネントにわたって集約され、各コンポーネントの最小 a[i] のコンポーネントの合計と内部グラフの固定 MST 重みを加えたものはいくらになるかという答えになります。

内部グラフは固定されているため、その接続コンポーネントを事前計算し、そのグラフ上の最小範囲のフォレストを計算することもできます。 その後、各クエリは単一の a[i] のみを更新し、その最小値を追跡するためにコンポーネントごとにマルチセットを維持します。 

ただし、コンポーネントは MST の意味では静的ではありません。 これらは内部グラフのコンポーネントであり、最終的な MST ではありません。 これは、1..n 内の MST 構造がスターの重みから独立しているため有効です。内部エッジは、サイクルを作成するスター接続よりも安価な場合、常に最初に選択されます。 

したがって、内部エッジにわたって DSU を事前計算し、内部グラフの MST 重みを計算し、各コンポーネントについて現在の最小値 a[i] を維持できます。 各更新は 1 つのコンポーネントのマルチセットにのみ影響するため、対数時間で最小値のグローバル合計を更新できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとに MST を再計算する | O(q (n + m) log n) | O(n + m) | 遅すぎる |
 | DSU コンポーネント + マルチセットの最小値 | O((n + m) log n + q log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、グラフを 2 つの層に分割します。頂点 1 ～ n の固定内部グラフと、0 から各頂点までの動的スター エッジです。 

1. DSU または BFS/DFS を使用して内部グラフの連結成分を計算します。 これは、同じコンポーネント内の頂点がノード 0 を介さずに接続できるためです。 
2. 各コンポーネントについて、それに属するすべての頂点を収集し、初期の最小値 a[i] を計算します。 これは、コンポーネント全体をノード 0 にアタッチする最も安価な方法を表します。 
3. すべてのコンポーネントにわたるこれらの最小値の合計を計算します。 この値は、スター エッジを最適に使用してノード 0 をすべてのコンポーネントに接続するための総コストを表します。 
4. a[i] を更新する各クエリを処理します。 頂点 i について、そのコンポーネント c を特定します。 
5. コンポーネント c の保存された最小値を更新します。 a[i] が最小値の場合、それを削除または増加すると、そのコンポーネントで次に小さい値を選択する必要が生じる可能性があります。 小さくなった場合は、以前の最小値に置き換わる可能性があります。 
6. 値を更新し、最小値 (通常はマルチセット) を迅速に取得できるように、コンポーネントごとにデータ構造を維持します。 
7. 各更新の後、古いコンポーネントの最小値を減算し、新しいコンポーネントを追加することによって全体の合計を調整します。 

これが機能する理由は、内部接続により、コンポーネント内で 1 つの頂点のみがノード 0 への MST 接続に効果的に寄与することが保証されるためです。2 つ追加するとサイクルが作成され、より高価な方を削除することで短縮できるため、MST はコンポーネントごとに複数のスター エッジを使用することはありません。 

### なぜ効果があるのか

 内部グラフの接続された各コンポーネント内では、すべての頂点はノード 0 に触れることなく相互に到達可能です。グラフ全体を接続するスパニング ツリーは、そのような各コンポーネントを少なくとも 1 回はノード 0 に接続する必要があります。 コンポーネント内の 1 つの頂点が 0 に接続されると、他のすべての頂点は内部エッジを通じて 0 に到達できるため、同じコンポーネント内の追加のスター エッジはサイクルを作成するだけです。 したがって、各コンポーネントの MST コスト寄与は、そのコンポーネントの最小 a[i] に固定の内部 MST コストを加算したものになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

class DSU:
    def __init__(self, n):
        self.p = list(range(n))
        self.sz = [1] * n

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return
        if self.sz[a] < self.sz[b]:
            a, b = b, a
        self.p[b] = a
        self.sz[a] += self.sz[b]

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))

    dsu = DSU(n)

    edges = []
    for _ in range(m):
        u, v, w = map(int, input().split())
        u -= 1
        v -= 1
        dsu.union(u, v)
        edges.append((w, u, v))

    # find components
    comp = [dsu.find(i) for i in range(n)]

    # compress component ids
    comp_id = {}
    cid = 0
    for i in range(n):
        r = comp[i]
        if r not in comp_id:
            comp_id[r] = cid
            cid += 1
        comp[i] = comp_id[r]

    k = cid

    import heapq
    heaps = [list() for _ in range(k)]
    for i in range(n):
        heapq.heappush(heaps[comp[i]], a[i])

    def get_min(h):
        return h[0] if h else 10**30

    comp_min = [get_min(h) for h in heaps]
    total = sum(comp_min)

    q = int(input())

    # store current values
    cur = a[:]

    for _ in range(q):
        i, w = map(int, input().split())
        i -= 1
        c = comp[i]

        old_min = comp_min[c]

        cur[i] = w
        heapq.heappush(heaps[c], w)

        # lazy cleanup not strictly needed for correctness explanation simplicity,
        # but we recompute min by cleaning outdated entries
        while heaps[c] and cur[i] != heaps[c][0]:
            heapq.heappop(heaps[c])

        new_min = heaps[c][0]
        comp_min[c] = new_min

        total = total - old_min + new_min
        print(total)

if __name__ == "__main__":
    solve()
```この実装では、まず、固定内部エッジ上で DSU を使用して接続コンポーネントを構築します。 このステップは、1 つのスター エッジのみが関連するグループを定義するため、重要です。 

各コンポーネントは、頂点の現在のスター ウェイトのヒープを維持します。 更新のたびに、対応するヒープを更新し、最小値を再計算します。 グローバルな答えはコンポーネントの最小値の合計として維持されるため、各クエリはこの合計内の 1 つの項を調整するだけで済みます。 

唯一の微妙な点は、ヒープの最小値が更新された値を反映していることを確認することです。 現在の値を配列に保持し、必要に応じて古いヒープトップを破棄することでこれに対処します。 

## 実用的な例

 2 つの内部コンポーネントを持つ小さなグラフを考えてみましょう。 

初期状態にはコンポーネント {1,2} と {3} があり、a 値は [5,2,4] です。 成分の最小値は 2 と 4 なので、答えは 6 になります。 

コンポーネント {1,2} の頂点を更新した後、最小値は 5 と 2 の間でシフトする可能性があり、そのコンポーネントの寄与のみに影響します。 

| クエリ | 成分最小値 | 合計 |
 | --- | --- | --- |
 | イニシャル | (2, 4) | 6 |
 | 更新により 1 が 5 から 1 に変更されます | (1, 4) | 5 |
 | アップデートの変更点 2 が 2 から 10 | (5, 4) | 9 |

 各ステップでは、影響を受けるコンポーネントのみが重要であり、他のすべてのコンポーネントは安定したままであることが示され、分解特性が確認されます。 

このトレースは、内部構造が更新の影響を分離しているため、MST の再計算が不要であることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n + m) α(n) + q log n) | DSU はコンポーネントを 1 回ビルドし、更新ごとに 1 つのヒープと 1 つの最小値を調整します。 
| スペース | O(n + m) | DSU 配列、コンポーネント マッピング、およびヒープ |

 前処理は、逆アッカーマン係数を使用したエッジで線形であり、各クエリはヒープの更新により対数的になります。 これは、300,000 回の操作の制限内に問題なく収まります。

 ## 特殊なケース

 コンポーネントの最小要素が上方に更新される場合、クリティカルなエッジケースが発生します。 コンポーネントの値が [1、5、7] で、値 1 の頂点が 10 に更新されるとします。単純なヒープベースのアプローチでは、古いエントリが削除されない限り、依然として 1 が最小値として報告される可能性があります。 正しい動作は、1 が有効でなくなったことを検出し、それを 5 に置き換えることです。 

このアルゴリズムは、ヒープが有効な現在の最小値を反映するまで、現在の値の配列を保持し、古いヒープの先頭を破棄することでこれを処理します。 処理後、そのコンポーネントのヒープは正しく [5, 10, 7] になり、最小値は 5 になり、それに応じてグローバル応答が更新されます。 

もう 1 つのエッジ ケースは、コンポーネント内のすべての頂点が更新され、複数のクエリによって最小値が連続して前後にシフトされる場合です。 各更新は 1 つのコンポーネント ヒープのみに影響するため、コンポーネント間の干渉は発生せず、各調整後の合計は一貫したままになります。
