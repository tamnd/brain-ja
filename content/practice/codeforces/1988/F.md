 ## 解決策
 ## 問題の理解

 1 から 1 までの数値のすべての順列を合計するように求められます。$n$、各順列の 3 つの特性、つまりプレフィックスの最大数、サフィックスの最大数、およびアセントの数に依存するコスト関数です。 これらの各特性は、順列に関する自然な組み合わせ統計としてカウントされます。 接頭辞の最大値は、前のすべての要素よりも大きい要素であり、接尾辞の最大値は、後続のすべての要素よりも大きく、アセントは、先行する要素と比較して数値が増加する場所です。 各順列について、そのコストは 3 つの入力配列から選択された 3 つの数値の積として計算されます。$a$、$b$、 そして$c$、それぞれプレフィックス最大値、サフィックス最大値、およびアセントの数によってインデックス付けされます。 

とすれば$n$すべてを列挙すると、最大 700 になる場合があります。$n!$順列は不可能です。 操作数は以前よりも速く増加します$10^{170}$のために$n = 700$、5秒で処理するのはまったく不可能です。 したがって、順列を個別に生成せずに合計できる組み合わせまたは代数的アプローチが必要です。 

非常に小さい場合、微妙なエッジケースが発生します。$n$、 のように$n=1$または$n=2$なぜなら、アセントカウントがゼロになる可能性があり、プレフィックスとサフィックスの最大値が一致する可能性があるからです。 少なくとも 1 つのアセントを想定したり、プレフィックスとサフィックスの最大値を分離したりする単純な実装では、これらを誤ってカウントする可能性があります。 たとえば、$n=1$、唯一の順列には最大 1 つのプレフィックスと 1 つのサフィックスがありますが、アセントはありません。 コストは次のとおりです。$a_1 b_1 c_0$、他のインデックスではありません。 

## アプローチ

 ブルートフォースアプローチは簡単です。 すべて生成$n!$明示的に並べ替えます。 各順列について、左から右にスキャンしてプレフィックスの最大値をカウントし、右から左にスキャンしてサフィックスの最大値をカウントし、連続する要素を比較して上昇をカウントします。 対応する配列値を乗算し、すべての順列を合計します。 これはどの入力に対しても正しいですが、時間計算量は次のとおりです。$O(n! \cdot n)$、これは受け入れられません$n > 10$。 

重要な洞察は、問題が対称的であり、動的計画法と組み合わせ論を使用した統計によって順列を数えることに還元できるということです。 の順列については、$n$要素を作成するには、考えられるすべての位置に最大の要素を挿入します。 最大の要素を先頭に配置するとプレフィックスの最大数が増加し、最後に配置するとサフィックスの最大数が増加し、アセント カウントは隣接する要素に依存します。 これらの繰り返しは、3 つの統計量に対する多項式としてエンコードできます。 アセントはどこにでも存在できるため、アセント変数の多項式は高速フーリエ変換 (FFT) を使用して効率的に畳み込むことができます。 これにより合計が減少します$n!$一連の多項式乗算への置換。各ステップで母関数が更新されます。$O(n^2 \log n)$。 

順列を直接列挙できるため総当り攻撃は機能しますが、次の場合には失敗します。$n$要因爆発により成長します。 最大の要素が問題を再帰的に分割するという観察により、組み合わせカウントと多項式乗算を通じて、接頭辞、接尾辞の最大値、およびアセントを独立して処理できるようになります。 これにより、次の問題が軽減されます。$n!$への列挙$O(n^3)$または$O(n^2 \log n)$モジュロ上の算術演算$998244353$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n! * n) | O(n) | 遅すぎる |
 | 動的計画法 + 多項式畳み込み | O(n^3) または O(n^2 log n) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 3D 生成関数を定義する$F(n)$の係数が$x^p y^s z^a$は長さの順列の数です$n$と$p$接頭辞最大値、$s$接尾辞最大値、および$a$上昇。 評価に興味があります$\sum F(n) a_p b_s c_a$。 
2. 基本ケースを初期化します。$n=1$。 プレフィックスの最大値が 1 つ、サフィックスの最大値が 1 つ、およびアセントが 0 の順列は 1 つだけです。 これを次のように表します$F(1) = x y$。 
3. 構築する$F(n)$最大の要素がどこにあるかを考慮して再帰的に$n$の順列に挿入されます$n-1$要素。 これが先頭にある場合は、プレフィックスの最大値が 1 つ追加されます。それ以外の場合は、プレフィックスの最大値は変更されません。 これが最後にある場合は、最大 1 つのサフィックスが追加されます。 2 つの要素の間に挿入すると、より小さい要素の後に続く場合はアセントが追加されます。 
4. 挿入位置ごとに、次の値を乗算して母関数を更新します。$x$、$y$、または上昇指数を適切に調整します。 これらの更新は、次の多項式加算です。$x$、$y$、 そして$z$。 
5. 係数と重みを合計します。$a_p b_s c_a$取得するため$f(n)$。 効率を高めるために、モジュロを使用して中間生成関数を配列に格納します。$998244353$算術。 
6. まで繰り返します。$n$、1 から 2 までのすべてのサイズの最終合計を収集します。$n$。 

機能する理由: 最大の要素を挿入すると、すべての順列が 1 回だけ再帰的に列挙され、接頭辞の最大値、接尾辞の最大値、およびアセントの統計が正しく更新されます。 多項式表現はカウントを組み合わせてエンコードするため、対応する重みを乗算します。$a_p$、$b_s$、 そして$c_a$明示的に列挙することなく、すべての順列にわたるコストの正確な合計を生成します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

n = int(input())
a = [0] + list(map(int, input().split()))
b = [0] + list(map(int, input().split()))
c = list(map(int, input().split()))

# dp[prefix][suffix][ascents] = number of permutations with these stats
dp = [[[0]*(n) for _ in range(n+1)] for _ in range(n+1)]
dp[1][1][0] = 1  # base case: n=1

for size in range(2, n+1):
    new_dp = [[[0]*size for _ in range(size+1)] for _ in range(size+1)]
    for p in range(1, size):
        for s in range(1, size):
            for z in range(size-1):
                count = dp[p][s][z]
                if count == 0:
                    continue
                # insert new max at beginning
                new_dp[p+1][s][z] = (new_dp[p+1][s][z] + count) % MOD
                # insert at end
                new_dp[p][s+1][z] = (new_dp[p][s+1][z] + count) % MOD
                # insert in middle
                new_dp[p][s][z+1] = (new_dp[p][s][z+1] + count*(size-2)) % MOD
    dp = new_dp

result = []
for size in range(1, n+1):
    total = 0
    for p in range(1, size+1):
        for s in range(1, size+1):
            for z in range(size):
                total = (total + dp[p][s][z] * a[p] % MOD * b[s] % MOD * c[z]) % MOD
    result.append(str(total))

print(' '.join(result))
```の`dp`array は統計によってすべての順列を追跡します。 サイズ 1 から開始して、最大の要素を挿入し、プレフィックス、サフィックスの最大値、およびアセント カウントを正しく更新することで構築していきます。 重みを掛ける$a$、$b$、$c$すべての順列を考慮した後、必要な和を法として求めます$998244353$。
