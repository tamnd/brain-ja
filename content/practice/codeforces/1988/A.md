 ## 問題の理解

 単一の数値を含むマルチセットから始めます`n`。 このマルチセットを変更する唯一の方法は、既存の番号を 1 つ繰り返し選択することです`u`、それを削除し、最大で次のものに置き換えます`k`合計が正確に一致する正の整数`u`。 目標は、最終的に 1 だけで構成されるようにマルチセットを変換することであり、そのような置換操作の使用数を最小限に抑えたいと考えています。 

重要な視点は、セットの観点から考えるのをやめ、代わりに単一の数量、つまりマルチセット内の要素の総数を追跡することです。 すべての操作で 1 つの数値がいくつかのより小さい数値に置き換えられ、合計の合計を維持しながら要素の数が増加します。 最終状態は次のようにする必要があるため、`n`1、最終的な要素数は正確に`n`、合計も`n`。 

制約は十分に小さいため、直接的な貪欲またはシミュレーションのアプローチは問題ありません。 各操作では 1 つの値が最大で 1 つの値に減ります。`k`したがって、成長プロセスは本質的に対数的です。 と`n ≤ 1000`操作をシミュレートしたり、テスト ケースごとに数式を計算したりする場合でも、十分に高速です。 

微妙なエッジケースが現れるのは、`n = 1`。 この場合、マルチセットには既に 1 だけが含まれているため、操作は必要ありません。 もう 1 つのエッジケースは次のような場合です`k`は十分な大きさなので、任意の数値を 1 ステップですべて 1 に分割できますが、それでも最大でも次の規則を尊重する必要があります。`k`部品。 常に正確に分割されるという素朴な仮定`k`部品が故障するのは`u < k`。 

## アプローチ

 ブルートフォースの観点は、プロセスをシミュレートすることです。つまり、最大の要素を繰り返し選択し、それをいくつかの部分に分割し、すべてが 1 つになるまで継続します。 これは正しいですが、分割の選択肢が異なると中間状態も異なるため、厄介です。 各数値はさまざまな方法で最大 2 つに分割できるため、分岐係数は大きくなります。`k`部品。 小さいものでも`n`、これにより、可能なシーケンスの指数関数的な数が作成されます。 

重要な点は、操作の順序は重要ではないということです。 重要なのは、値が 1 になるまでに何回「拡張」する必要があるかということです。各操作は 1 つの数値を置き換えます。`u`せいぜい`k`したがって、最善の戦略は常に、できるだけ均等に正確に分割することです。`k`いつでも部品`u > 1`。 これにより、目標に向けての進歩が最大化されます。 

したがって、プロセスは決定論的になります。数値を繰り返し置き換えます。`u`と`k`すべてが 1 になるまで、ほぼ等しい部分を作成します。必要な操作の数は、単に分割する必要がある回数です。`n`すべてのピースが 1 になるまでダウンします。これは、ノードを繰り返し最大で置き換えることと同じです。`k`サイズ 1 の葉に到達するまで、子供たちは木の中にいます。 

これは単純な成長モデルに帰着します。操作ごとにピースの数が増加し、1 つのピースから`n`各操作で最大でピースの数が増加します。`k - 1`。

 ## アルゴリズムのチュートリアル

 重要なアイデアは、現在持っているピースの数と、少なくともそれに到達するために必要な操作の数を追跡することです。`n`1 つの値から始まるもの。 

1. 価値の 1 つの要素から始める`n`。 概念的には、これを 1 つのアクティブな「チャンク」として扱います。 
2. 各操作は 1 つのチャンクを受け取り、それを最大で 1 つのチャンクに置き換えます。`k`より小さな塊。 常に最適に分割する場合、これを 1 つのチャンクを正確に置き換えるものとして扱います。`k`可能な限りチャンク。 これにより、操作ごとに取得されるチャンクの数が最大化されます。 
3. 最初に、`1`かたまり。 各操作の後、チャンクの数は最大で 1 ずつ増加します。`k - 1`、1 つのチャンクが削除されるため、最大`k`が追加されます。 
4. 正確に到達したい`n`チャンク。最後の各チャンクは`1`。 
5. そこで、次のステップに進むのに必要なステップ数を計算します。`1`に`n`の増分を使用して`k - 1`。 これは単純な算術成長プロセスです。 
6. もし`k = 1`、そうでない限り分割はできません。`n = 1`。 したがって、それを個別に処理します。 

### なぜ効果があるのか

 不変条件は、各操作の後、合計は一定のままですが、分割したときに部分の数が可能な最大量だけ増加するということです。`k`部品。 すべての最終構成は単なるものであるため、`n`つまり、目標を達成することは達成することと同じです`n`個。 最大分割からの逸脱は進行を遅らせるだけであるため、最適な戦略は常に操作ごとの新しい部分の数を最大化することです。 これにより、問題はステップごとのゲインが固定された決定論的な成長プロセスに帰着します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())

        if n == 1:
            print(0)
            continue

        if k == 1:
            # cannot split anything larger than 1
            print(-1)
            continue

        # each operation increases number of pieces by at most (k-1)
        # start with 1 piece, need to reach n pieces
        need = n - 1
        step_gain = k - 1

        ans = (need + step_gain - 1) // step_gain
        print(ans)

if __name__ == "__main__":
    solve()

 ## 特殊なケース

 いつ`n = 1`の場合、マルチセットにはすでに 1 つだけが含まれているため、すでに目標を満たしているため、操作は必要ありません。 アルゴリズムは正しく 0 を即座に返します。 

いつ`k = 1`そして`n > 1`、要素を複数の部分に分割することはできないため、要素の数を増やすことはできません。 1 つの要素から始めて必要があるため、`n > 1`、答えは不可能であり、アルゴリズムは戻ります`-1`。 

いつ`k >= n`、単一の分割で生成できるのは最大でも`n`1 回の操作で 1 つ、ただし最大でも 1 つのルールで許可されている場合のみ`k`部品。 式は可能な限り自然に 1 回の操作に減り、最適な動作に一致します。
