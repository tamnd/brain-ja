 ## 解決策
 ## 問題の理解

 私たちには、時間の経過とともに形を変えることができるバイナリ シーケンスが与えられています。 唯一許可される方法は、任意の連続セグメントを取得し、それをそのセグメントの大部分に等しい単一の値に圧縮することです。この場合、タイはゼロを優先して解決されます。 演算ごとにシーケンスの長さが短縮されるため、最終的には 1 つの数値になります。 

タスクは、シーケンス全体を 1 に等しい単一の要素に削減できるかどうかを判断することです。 

主な難点は、この操作が元に戻せないことと、値の長さと分布の両方が変化することです。 ローカルでは有利に見えるセグメントでも、誤って使用するとグローバル構造が破壊される可能性があります。 この決定は純粋に存続に関するものであり、構築に関するものではありません。 

この制約により、テスト ケース全体で合計 2 · 10^5 までの要素が許可されます。 操作をシミュレートしたり、セグメントの検索を試みたりするソリューションは、各操作自体が O(n) であり、収束するまでに多数の操作が存在する可能性があるため、非常に遅くなります。 テスト ケースごとの 2 次アプローチでも大きすぎます。 

いくつかの微妙な特殊なケースについては注意する価値があります。 

入力などの単一のゼロ`0`に変えるのは明らかに不可能です`1`紹介する方法がないからです。 

のような文字列`10`これも不可能です。唯一のセグメント操作はシングルトンまたは配列全体のいずれかです。 配列全体には 0 が 1 つと 1 が 1 つあるため、大部分が 0 となり、すべてが折りたたまれます。`0`。 

もっと興味深いケースは次のようなものです`10001`。 1 は存在しますが、それらはまばらであり、ゼロが多すぎる操作はすぐにゼロに切り替わり、回復が不可能になります。 

これらの例は、答えがセグメントの構造によってではなく、全体的なバランス条件によって支配されることを示唆しています。 

## アプローチ

 ブルート フォース ビューでは、考えられるすべての操作をシミュレートしようとします。 各ステップで、任意の部分配列を選択し、その過半数を計算し、結果のシーケンスを再帰的に続行できます。 これにより、各状態が O(n^2) の可能性に分岐し、深さも O(n) になる巨大な検索ツリーが形成されます。 メモ化を行ったとしても、異なる圧縮シーケンスによって異なる中間配列が生成されるため、個別の状態の数は指数関数的に増加します。 このアプローチはすぐに実行不可能になります。 

重要な観察は、この操作が強力な単調な動作をするということです。つまり、配列を縮小し、ローカル構造をローカル多数を反映する単一ビットに置き換えるだけです。 重要なのは、ある地域で十分に優勢である場合にのみ保存されるということです。 ローカル同点または過半数がゼロの場合、ゼロはデフォルトの結果として機能します。 

シングルで終わりたい`1`これは、ある時点で、圧縮を繰り返してもすべての 1 が除去されないセグメントが存在する必要があることを意味します。 いずれかの段階で、ゼロが大半を占めるセグメントを作成すると、そのセグメントはゼロに崩壊し、最終的なセグメントに寄与できなくなります。 

これは重要な簡素化につながります。つまり、単一のコードで終了する唯一の方法です。`1`1 の合計数が厳密に 0 より大きい場合です。 ゼロが等しいかそれ以上の場合、全配列の操作は即座にゼロに崩壊し、プロセスは圧縮するだけでゼロを作成しないため、後でゼロを「回復」するメカニズムはありません。 

1 が厳密にそれ以上の場合、大部分の 1 を保持しながらゼロを徐々に削除する一連の圧縮を常に見つけることができます。 直感的に、グローバルな優位性が反転して最終的に配列が 1 つに折りたたまれることを回避するセグメントをいつでも選択できます。 

したがって、答えは count(1) > count(0) かどうかを確認することになります。

 ## アルゴリズムのチュートリアル

 1. 入力文字列内の 1 と 0 の数を数えます。 これにより、操作をシミュレートする必要がなく、配列の全体的な概要が得られます。 
2. カウントを比較します。 1 の数がゼロの数よりも厳密に大きい場合は、YES を出力します。 それ以外の場合は NO を出力します。 

### なぜ効果があるのか

 すべての操作はセグメントをその過半数に置き換えます。セグメントがすでに局所的に優勢でない限り、セグメントの数は決して増加しません。 少なくとも 1 と同じ数の 0 を持つセグメントはすべて 0 に崩壊し、システム内の 1 の存在が永久に減少します。 グローバルに 0 が 1 よりも厳密に小さくない場合、配列全体をマージしようとすると最終的には 0 が生成され、操作は構造を縮小するだけであるため、失われた 0 を再導入する方法はありません。 逆に、1 が厳密に大きい場合は、慎重に選択したセグメントをマージし、配列が 1 つの要素に縮小するまで 1 が支配的な構成を維持することで、構造全体が 0 に崩壊することを常に回避できます。 

これにより、カウント間のグローバルな不平等が必要かつ十分になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    s = input().strip()
    
    ones = s.count('1')
    zeros = n - ones
    
    if ones > zeros:
        print("YES")
    else:
        print("NO")
```このソリューションは、各テスト ケースを個別に読み取り、直線時間でカウントを計算します。 中心となるロジックは 1 と 0 の比較です。 シミュレーションや構造追跡は必要ありません。 

唯一の注意点は、文字列が正しく削除されることを確認することです。そうしないと、末尾の改行がカウントに影響を与えるからです。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        s = input().strip()
        ones = s.count('1')
        zeros = n - ones
        out.append("YES" if ones > zeros else "NO")
    return "\n".join(out)

 ## 特殊なケース

 単一要素の配列は、基本的な動作を強調表示します。 入力用`1`、配列はすでに次と等しいため、答えは自明にYESです。`[1]`。 アルゴリズムは、1 = 1、0 = 0 を正しく計算し、YES を返します。 

入力用`0`、1 = 0、0 = 1 であるため、出力は NO になります。 これは、いかなる操作による導入も不可能であることと一致します。 

みたいなバランスのとれた構造`01`または`10`のカウントは常に等しいため、NO となります。 このアルゴリズムは配置に依存しません。これは、バランスの取れたセグメントの完全なマージがタイブレークによってゼロに崩壊するという事実と一致します。
