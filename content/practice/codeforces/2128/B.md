 ## 解決策
 ## 問題の理解

 数値の順列が与えられ、残っている左端または右端の要素を繰り返し削除して新しいシーケンスを構築します。 これにより長さ n のシーケンスが生成されますが、各ステップで左から取得するか右から取得するかを自由に決定できます。 

生成されたシーケンスの唯一の要件は構造的です。厳密に増加または厳密に減少している 5 つの連続する要素のブロックが含まれていてはなりません。 言い換えれば、結果として得られるシーケンスのどこかに長さ 5 の単調なランを作成しないようにする必要があります。 

難しいのは、順列自体について何かを計算することではなく、シーケンスをオンラインで構築する方法を制御することです。 要素が端から取り出されると、後で使用できなくなり、残りのセグメントが縮小するため、各決定は将来の自由に影響します。 

この制約により、テストあたり最大 100,000 個の要素、合計 200,000 個の要素が許可されます。 これにより、考えられるすべてのシーケンスをシミュレートまたは評価するアプローチは即座に除外されます。 先読みを使用して貪欲な選択肢をすべてチェックしても、最悪の場合は 2 次式になります。 

重要な点は、制約がローカルでありながらメモリを持っていることです。違反は、最後の 1 つまたは 2 つだけではなく、最後に選択された 5 つの要素に依存します。 最後の比較方向のみを追跡する単純な貪欲は失敗します。 

典型的な失敗例は、常に小さいエンドポイントまたは大きいエンドポイントを選択することに起因します。 

入力:```
5
1 2 3 4 5
```常に左を選択すると、完全に増加するシーケンスが生成され、5 番目のステップで直ちにルールに違反します。 同様に、常に大きいエンドポイントを選択すると、実行が減少する可能性があります。 

したがって、アルゴリズムは、エンドポイントを消費しながら、長い単調な実行を積極的に防止する必要があります。 

## アプローチ

 ブルート フォース ソリューションでは、すべてのステップで両方の選択肢を試し、L と R の決定の考えられるすべてのシーケンスを構築し、結果のシーケンスが有効であるかどうかを確認します。 これにより、深さ n のバイナリ ツリーが形成され、2^n の可能性が得られます。また、違反は最大 5 つの要素が蓄積された後にのみ現れるため、早期に枝刈りしても依然として指数関数的な爆発につながります。 

重要な観察は、シーケンスの完全な履歴について推論する必要がないということです。 唯一の危険な状況は、最後の 4 つの要素と次の選択肢が完全に単調な連鎖を形成する場合です。 つまり、いつでも、構築されたシーケンスの最後の 4 つの要素を追跡し、5 番目の要素が単調な実行を延長しないことを確認するだけで済みます。 

これにより、この問題は、デキュー構築プロセスにおけるローカル制約の維持の問題に帰着します。 常に 2 つの候補 (左と右) があるため、禁止された長さ 5 の単調セグメントをすぐに作成しない側を貪欲に選択できます。 双方が安全であれば、どちらでも機能します。 

これが機能する深い理由は、禁止されたパターンが短く連続しているためです。 ローカルでの作成を回避すると、将来の拡張機能は最後の 4 つの要素にのみ依存するため、後で「再表示」することはできません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (すべてのシーケンス) | O(2^n) | O(n) | 遅すぎる |
 | ローカル制約のある貪欲な | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 最後に選択された最大 4 つの値のウィンドウを維持しながら、結果シーケンスを段階的に構築します。 

1. 2 つのポインタを初期化します。1 つは順列の左端、もう 1 つは右端にあります。 空のリストも維持する`q`結果のために。 
2. 各ステップで、左端の値と右端の値の 2 つの候補を検討します。 
3. 候補ごとに、追加するかどうかを一時的に確認します。`q`長さ 5 の厳密に増加または厳密に減少するランを作成します。 

このチェックには、次の最後の 4 つの要素のみが含まれます。`q`加えて候補者。 
4. 2 つの選択肢のうち 1 つが安全な場合は、すぐにそれを選択してください。 
5. 両方が安全な場合は、一貫してどちらかの側を選択します (たとえば、常に左を取る)。 この制約はローカルな単調性のみを制限し、グローバルな構造を制限するものではないため、これによって正確性が損なわれることはありません。 
6. 選択した値を`q`、対応するポインターを更新し、すべての要素が使用されるまで繰り返します。 

実装の重要な詳細は、最後の 4 つの要素以上を決してスキャンしないことです。 これにより、ステップごとに O(1) の作業が保証されます。 

### なぜ効果があるのか

 どの時点でも、条件に違反する唯一の方法は、現在の要素で終わる長さ 5 の単調セグメントを完了することです。 そのセグメントは、最後の 4 つの要素と候補の選択によって完全に決定されます。 

このような完了を決して許可しないことを保証することで、最終シーケンスに不良セグメントが出現しないことを保証します。 将来のすべてのチェックは最後の 4 つの要素のみに依存するため、そのウィンドウを超えた以前の構造は将来の有効性に影響を与えることができないため、貪欲な人は避けられない失敗に「自分自身をロック」することはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def is_bad(last, x):
    if len(last) < 4:
        return False
    a, b, c, d = last[-4], last[-3], last[-2], last[-1]
    if a < b < c < d < x:
        return True
    if a > b > c > d > x:
        return True
    return False

def solve():
    n = int(input())
    p = list(map(int, input().split()))
    
    l, r = 0, n - 1
    last = []
    ans = []

    for _ in range(n):
        left_val = p[l]
        right_val = p[r]

        can_left = not is_bad(last, left_val)
        can_right = not is_bad(last, right_val)

        if can_left:
            ans.append('L')
            last.append(left_val)
            l += 1
        else:
            ans.append('R')
            last.append(right_val)
            r -= 1

        if len(last) > 4:
            last.pop(0)

    print("".join(ans))

if __name__ == "__main__":
    solve()
```この実装では、最後の 4 つの要素のスライディング ウィンドウが保持されます。`last`。 長さ 5 の単調なランのみが重要であり、そのようなランは現在の位置で終了する必要があるため、これで十分です。 

決定ロジックは両端をチェックし、禁止パターンを直ちに作成するような動きを回避します。 片側のみが有効な場合は、それを選択する必要があります。 両方が有効な場合は、どちらかを選択しても安全であり、実装ではデフォルトで左側が使用されます。 

スライディング ウィンドウは、サイズ 4 を超えると前面から飛び出すことによって維持され、一定のメモリと一定時間のチェックが保証されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    def is_bad(last, x):
        if len(last) < 4:
            return False
        a, b, c, d = last[-4], last[-3], last[-2], last[-1]
        return (a < b < c < d < x) or (a > b > c > d > x)

    def solve():
        n = int(input())
        p = list(map(int, input().split()))
        l, r = 0, n - 1
        last = []
        ans = []
        for _ in range(n):
            lv, rv = p[l], p[r]
            can_l = not is_bad(last, lv)
            can_r = not is_bad(last, rv)
            if can_l:
                ans.append('L')
                last.append(lv)
                l += 1
            else:
                ans.append('R')
                last.append(rv)
                r -= 1
            if len(last) > 4:
                last.pop(0)
        return "".join(ans)

    return solve()

assert len(run("5\n5 4 3 2 1\n")) == 5

# custom cases
assert set(run("5\n1 2 3 4 5\n")) <= {"L","R"} * 5, "monotone increasing"
assert set(run("6\n6 5 4 3 2 1\n")) <= {"L","R"} * 6, "monotone decreasing"
assert len(run("5\n1 3 5 2 4\n")) == 5, "mixed permutation"

 ## 特殊なケース

 微妙なケースは、初期段階では両端が安全であるにもかかわらず、1 つの選択肢だけが将来の柔軟性を維持する場合です。 このアルゴリズムはこの問題を回避します。安全でない継続は直ちに長さ 5 の単調チェーンを形成し、そのようなチェーンは連続している必要があるため、後で非表示にしたりトリガーしたりすることはできません。 

もう 1 つのエッジ ケースは、n が小さく、特に n = 5 です。この場合、アルゴリズムは、最終的に選択された次数が単調であるかどうかを効果的にチェックします。 禁止された実行を即座に作成しない場合にのみ移動を許可するため、当然のことながら、一方向に完全にソートされたシーケンスを構築することは回避されます。 

最後に、すでに両方向でほぼソートされている順列は引き続き機能します。これは、一方の側が単調なチェーンを完成させるときに、貪欲な側がちょうど端を切り替えるためです。 ローカルチェックにより、決定境界がステップレベルで常に検出可能であることが保証され、行き止まりが防止されます。
