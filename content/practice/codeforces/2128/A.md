 ## 解決策
 ## 問題の理解

 いくつかの独立したシナリオが与えられています。 各シナリオにはバッグのコレクションがあり、それぞれに初期重量が設定されています。 時間は不連続な秒単位で進みます。 私たちは毎秒、残りの袋をちょうど 1 つ取り出さなければなりません。 バッグの取り出しは、現在の重量がしきい値を超えているかどうかに応じて、無料の場合もあれば、コインがかかる場合もあります。 取り出した後、残ったすべてのバッグの重量は 2 倍になります。 

重要な問題は、時間の経過とともに重量が増加するため、初期に取り出すのに安価なバッグが後で高価になる可能性があることです。 私たちはバッグを取り出すかどうかを選択しているのではなく、各バッグを取り出すタイミングを選択しているだけであり、そのタイミングによって料金を支払うかどうかが決まります。 

入力サイズは小さく、テスト ケースあたり最大 30 袋、最大 1000 のテスト ケースです。 これにより、順列に対する指数関数的なスケジューリングが即座に排除されます。 ソリューションでは、ソート、貪欲な決定、テスト ケースごとの O(n²) シミュレーションなどは可能ですが、時間の経過に伴うサブセットにわたる階乗または状態 DP は可能ではありません。 

すべての値がすでにしきい値を超えている場合、微妙なエッジ ケースが発生します。 この場合、順序に関係なくすべての除去のコストは 1 となるため、答えは単純に n になります。 反対の極端な場合は、すべての値が長期間にわたってしきい値を下回る場合であり、順序が非常に重要になります。 たとえば、小さなバッグは遅れると大きくなる可能性があるため、時間を考慮せずに単純に「大きいものを最初に取り出す」または「小さいものを最初に取り出す」とすると、どちらも失敗する可能性があります。 

## アプローチ

 強引なアプローチでは、バッグを取り除くというあらゆる可能な命令が試行されることになります。 んがあるから！ 各除去シーケンスでは最大 n ステップにわたる重み更新のシミュレーションが必要ですが、これは n = 30 の場合でも完全に不可能になります。最悪の場合、合計操作は 103² を超えることになります。 

重要な観察点は、各バッグの最終コストは、バッグが取り出される時間ステップのみに依存するということです。 時刻 t (0 から開始) でバッグが取り出された場合、その重量は初期値に 2^t を乗算した値になります。 したがって、できる限り多くのバッグが条件 a_i * 2^t ≤ c を満たすように、各バッグに一意のタイムスロットを割り当てることができるかどうかを知る必要があるだけです。 

この条件を書き直すと、時間の制約が得られます。各バッグには、無料で取り出せる最新の時間が設定されています。 a_i * 2^t ≤ c となるような最大の t として期限 d_i を定義すると、各バッグは 0 から n-1 までの個別のタイムスロットでスケジュールする必要があるジョブになります。 期限を超える時間が割り当てられたバッグにはコスト 1 が発生します。 

これは古典的なスケジュールの問題です。期限までに完了するジョブの数を最大化する必要があります。 最適な戦略は貪欲です。 期限を分類し、各バッグに可能な限り早い空き枠を割り当てます。 有効なスロットに入れることができない手荷物については、料金を支払う必要があります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (順列) | O(n! · n) | O(n) | 遅すぎる |
 | 貪欲な最適なスケジューリング | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各バッグについて、無料で取り出せるほど大きくなる前に、どのくらいの時間保管できるかを計算します。 

これは、≤ c を維持している間に許可される倍加の最大数です。 cを超えるまでに何回2を掛けることができるかを数えることによって、概念的に2倍を繰り返します。 これにより、各バッグの期限値が定義されます。 
2. 各バッグを期限 t_i に変換します。つまり、時間 ≤ t_i にスケジュールされた場合にのみ無料で取り出すことができます。 
3. すべての期限を昇順に並べ替えます。 

分類することで、安全に取り出せる範囲が最も狭いバッグから最も制限の厳しいバッグを優先することが保証されます。 
4. 現在のタイムスロットへのポインタを維持しながら、ソートされた期限を通過します。

開始時間は0時。 
5. 各期限について、現在時刻 ≤ 期限の場合、バッグをこの時間に割り当て、時間を増分します。 そうしないと、空きスロットに入れることができないため、後でコスト 1 で削除する必要があります。 
6. 未割り当てのバッグの数が答えです。 

### なぜ効果があるのか

 各バッグは、コストゼロでの最大許容取り出し時間を個別に定義します。 項目を整数のタイムスロットに効果的に照合しています。 コストを最小限に抑える割り当ては、許容間隔内に収まる手荷物の数を最大にすることと同じです。 最も早い締め切り順に並べ替えることで、後で配置される可能性のあるバッグの狭いスロットを無駄にすることがなくなり、より厳しい制約に対する実現可能性が維持されます。 この貪欲な選択により、すべての割り当てを有効に保ちながら、すべてのステップで可能な最小限のタイムスロット数を使用するという不変条件が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, c = map(int, input().split())
        a = list(map(int, input().split()))

        deadlines = []

        for x in a:
            if x > c:
                deadlines.append(-1)
                continue

            tlim = 0
            val = x
            while val <= c:
                val *= 2
                tlim += 1

            deadlines.append(tlim - 1)

        free_slots = sorted(deadlines)
        time = 0
        paid = 0

        for d in free_slots:
            if d >= time:
                time += 1
            else:
                paid += 1

        print(paid)

if __name__ == "__main__":
    solve()
```実装の中核は、各重みを期限に変換することです。 c を超えるまで 2 倍化を明示的にシミュレートします。これは、値が指数関数的に増加し、n が小さいため安全です。そのため、このループは約 30 回の反復で制限されます。 

c より大きい初期値は期限 -1 を持つものとして扱います。これは、無料では削除できないことを意味します。 これらは、非常に早期に一致しない限り、自動的に支払い済みとしてカウントされますが、これは貪欲ループによって自然に処理されます。 

最後に、タイムスロットを並べ替えて貪欲に割り当てることで、無料の削除を最大化します。

 ## 特殊なケース

 すべての要素がすでにしきい値を超えている場合、すべての期限は -1 になります。 すべての要素が即座に有料バケットに強制的に入れられるため、このアルゴリズムは引き続き機能し、有効な割り当てが発生した場合にのみ時間が増加するため、偽の順序付けの利点は生まれません。 

すべての要素が小さい場合、期限は長くなり、期限も長くなります。 ソートにより、すべてが競合することなく順番に割り当てられるため、コインは支払われません。 

値がしきい値の周囲に密集している場合、一部のバッグは 1 回か 2 回の倍増だけで無効になります。 期限ごとに分類することで、脆弱なケースが最初に処理されるようになり、後で誤って支払いが行われる可能性があるケースを防ぐことができます。
