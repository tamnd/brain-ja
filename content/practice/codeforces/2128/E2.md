 ## 解決策
 ## 問題の理解

 配列内のサブメディアンを識別するように求められます。 より具体的には、配列範囲内の各整数に対して$1$に$n$、少なくとも次の長さの連続した部分配列が存在するかどうかを判断したいとします。$k$整数がその部分配列の中央値になるようにします。 中央値は、配列を半分に分割する要素です。少なくとも半分の要素はそれより大きくなく、少なくとも半分はそれより小さくありません。 偶数長の配列の場合、複数の整数がこの条件を満たすことができます。 また、整数が中央値であるサブ配列を 1 つ提供する必要もあります。 

入力は複数のテスト ケースで構成されます。 各ケースには最大 300,000 個の要素の配列があり、すべての要素の合計$n$すべてのテスト ケースも最大 300,000 件に達します。 制限時間3秒なら大体余裕です$O(n)$テストケースごと、または$O(n \log n)$対数係数が重すぎない場合。 二次方程式のアプローチはすぐには実用的ではありません。$n^2$到達できた$9 \times 10^{10}$。 

単純な総当たりアプローチでは、少なくとも次の長さのすべての部分配列が考慮されます。$k$そしてその中央値を計算します。 これは原理的には正しいですが、次のことが必要になります。$\Omega(n^2)$単一の配列に対する操作では、非常に遅すぎます。 偶数長の部分配列を正しく処理しない不注意な実装は、複数の中央値を誤って識別する可能性があります。 たとえば、配列では$[1,2,3,2,1]$と$k=3$、サブ配列$[2,3,2]$中央値がある$2$ただし、中央の要素のみを調べる単純なチェックでは、誤って主張する可能性があります。$3$。 

## アプローチ

 ブルート フォース メソッドは、少なくとも長さのすべてのサブ配列を列挙します。$k$、各部分配列をソートし、すべての中央値を計算します。 長さの部分配列のソート$m$費用$O(m \log m)$したがって、このアプローチは$O(n^3 \log n)$最悪の場合、遅すぎます。 

重要な洞察は、中央値のプロパティ (整数) から得られます。$v$配列を要素の +1 に変換する場合、部分配列の中央値が ≥$v$要素の場合は -1 <$v$、長さ ≥ の連続したセグメントが存在します。$k$その合計は負ではありません。 この合計は次のことを反映しています$v$少なくとももう一方の側に同じ数の要素があります。 この変換により、問題は長さ ≥ の部分配列を見つけることになります。$k$これは、プレフィックス合計と実行最小値を使用して線形時間で実行できます。 

すべての潜在的な中央値をチェックするのではなく、$O(n)$時間を別にして、1 から 2 までの値を繰り返します。$n$、それぞれに対して、接頭辞合計トリックを使用します。 有効な部分配列が見つかったら検索を停止し、各部分中央値が 1 回だけ報告されることを保証することもできます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n3 log n) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各候補整数について$v$1から$n$、次の場合、各要素が +1 になる変換された配列を作成します。$a[i] ≥ v$それ以外の場合は -1。 この変換は次のことをエンコードします。$v$サブ配列を支配することになります。 
2. この変換された配列のプレフィックス合計配列を計算します。 させて$pref[i]$最初の合計になる$i$要素。 
3. 位置までの最小プレフィックス合計を維持します。$i - k$。 インデックスごとに$i ≥ k$、どうかを確認してください$pref[i] - min\_prefix ≥ 0$。 これは、で終わるサブ配列が存在することを示します。$i$少なくとも長さの$k$どこ$v$は中央値です。 
4. そのようなインデックスが見つかった場合は、記録します。$v$部分中央値として部分配列のインデックスを保存します$[l,r]$最小プレフィックス合計の位置を使用します。 
5. 次の候補整数に進みます。 各整数は独立して処理されるため、それぞれの最初の有効な部分配列のみが必要です。 

なぜ機能するのか: 変換された配列は、$v$+1/-1付き。 部分配列の合計 ≥ 0 により、次のことが保証されます。$v$は、少なくとも小さい要素と同じ頻度であり、これがまさに中央値であるための条件です。 実行最小値を使用したプレフィックス合計トリックにより、長さ ≥ のすべての部分配列を効率的にチェックできます。$k$線形時間で。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        result = []

        for v in range(1, n+1):
            transformed = [1 if x >= v else -1 for x in a]
            pref = [0]*(n+1)
            for i in range(n):
                pref[i+1] = pref[i] + transformed[i]

            min_pref = 0
            left_index = 0
            found = False
            for r in range(k, n+1):
                min_pref = min(min_pref, pref[r - k])
                if pref[r] - min_pref >= 0:
                    # find l corresponding to min_pref
                    for l_candidate in range(r - k + 1):
                        if pref[l_candidate] == min_pref:
                            result.append((v, l_candidate + 1, r))
                            found = True
                            break
                    if found:
                        break

        print(len(result))
        for v, l, r in result:
            print(v, l, r)

if __name__ == "__main__":
    solve()
```コードはまず複数のテスト ケースを読み取ります。 各候補整数について$v$、配列を変換し、プレフィックスの合計を計算します。 位置までの最小プレフィックス合計$i-k$サブ配列の検出に役立ちます。$v$は中央値です。 有効なサブ配列が見つかると、それが記録され、次の整数候補が処理されます。 

境界条件は慎重に処理されます。プレフィックス合計配列には長さがあります。$n+1$and indexing is consistent with 1-based output. の検索$l$は線形ですが、最初の有効なサブ配列が見つかるまでに限られるため、全体的な複雑さは効率的なままです。 

## 実用的な例

 配列を考慮してください`[4, 1, 2, 4]`と`k=3`。 のために変身する`v=2`与える`[1, -1, 1, 1]`、プレフィックスの合計`[0,1,0,1,2]`。 インデックスの最小プレフィックス`3`は`0`。 以来`pref[3] - min_pref = 1 >= 0`、部分配列`[1,3]`動作します。 のために`v=4`、変換された配列は次のようになります。`[1, -1, -1, 1]`、プレフィックスの合計`[0,1,0,-1,0]`。 索引`4`与える`pref[4]-min_pref = 0 - (-1) = 1 >= 0`、つまり部分配列`[2,4]`動作します。 

| r | 優先[r] | 最小プレフ | pref[r]-min_pref | サブアレイが見つかりましたか? |
 | --- | --- | --- | --- | --- |
 | 3 | 1 | 0 | 1 | はい [1,3] |
 | 4 | 2 | 0 | 2 | はい [1,4] |

 これは、アルゴリズムがサブ配列を正しく識別していることを示しています。`v`中央値 (複数の中央値の処理を含む) です。
