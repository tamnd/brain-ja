 ## 問題の理解

 配列と長さの制約が与えられます$k$。 この配列から、少なくとも次の長さの連続したセグメントを選択したいとします。$k$。 選択したセグメント内で、一般化された意味での中央値、つまり値を調べます。$v$要素の少なくとも半分が次の場合に中央値とみなされます。$\ge v$そして少なくとも半数は$\le v$。 この定義により、偶数長のセグメントに対して複数の有効な中央値が許可されます。 

値$v$有効なセグメント (少なくとも長さ) が存在する場合、サブメディアンと呼ばれます。$k$） どこ$v$中央値の 1 つです。 そのようなすべての価値の中で、私たちは可能な限り最大のものを求めます。$v$また、それを有効にするセグメントを出力する必要もあります。 

主な困難は、固定セグメントの中央値を計算することではなく、特定の値が中央値として機能するセグメントが存在するかどうかを判断することです。 その値を最大化する必要があるため、構造は値に対する単調な実現可能性条件を示唆します。 

制約は大きく、すべてのテスト ケースにわたる配列の合計長は最大 300,000 です。 これにより、二次関数や偶数関数が即座に除外されます。$O(n \sqrt{n})$アプローチ。 すべての解は、テスト ケースごとに線形または対数に近くなければなりません。 

すべての値が同一の場合、微妙なエッジケースが発生します。 その場合、すべてのセグメントが機能し、答えは当然のことながら配列内の最大値になります。 別の重要なケースが発生するのは、$k = 1$ここで、すべての単一要素が有効なセグメントを形成し、答えは単純に最大の配列要素になります。ただし、ロジックは依然としてセグメントを正しく生成し、中央値処理の仮定によって失敗しない必要があります。 

さらに危険な落とし穴は、不等式の定義の両側のバランスを慎重にとらずに、「中央値 ≥ v」が「少なくとも半分の要素が ≥ v」と同じ意味であると仮定することです。 均等な長さのセグメントでは中央値条件での結合が許可されるため、対称性が重要になります。 

## アプローチ

 直接的なアプローチでは、少なくとも可能な長さのすべてのセグメントを試します。$k$、中央値セットを計算し、中央値として表示されるすべての値をチェックします。 これは概念的には正しいですが、実行不可能です。$O(n^2)$セグメント、および中央値条件を計算することもできます。$O(1)$または$O(\log n)$セグメントごとに実行すると、依然として操作が多すぎます。 

重要な洞察は、候補値を修正することです$v$そして配列をバイナリシーケンスに変換します。要素を次のようにマークします。$+1$もし$a_i \ge v$、 そして$-1$さもないと。 次に、セグメントについて考えてみましょう。 という条件が$v$中央値は、この変換の下で負ではない「バランス」を持つセグメントに相当します。つまり、少なくとも同じ数の要素があることを意味します。$v$要素として <$v$中央値のしきい値にスケールした場合。 中央値の定義を少し調整すると、少なくとも次の長さの部分配列を見つけることができます。$k$その合計は負ではありません。 

これにより、問題は古典的な実現可能性チェックに変わります。$v$、少なくとも次の長さの部分配列が存在するかどうかを知りたいのです。$k$変換された配列の合計が 0 より大きい場合。 これは、プレフィックスの合計と有効な開始位置にわたるスライド最小プレフィックスを使用して線形時間で解決できます。 

実現可能性が単調なので、$v$、値の場合$v$動作する場合、より小さな値もすべて動作します。 これにより、バイナリ検索が可能になります$v$で$[1, n]$。 それぞれのチェックは、$O(n)$したがって、全体の複雑さは次のようになります。$O(n \log n)$、それで十分です。

 ## アルゴリズムのチュートリアル

 最大値を二分探索することで問題を解決します$v$有効なセグメントが存在するようにします。 

1. 候補値を確定する$v$そして、配列を、各位置が +1 に寄与するゲイン配列に変換します。$a_i \ge v$、それ以外の場合は -1。 これは次のことをエンコードします。$v$それぞれの立場で「支えられる」。 
2. プレフィックス合計を構築する$p[i]$、 どこ$p[i]$開始からインデックスまでの合計ゲインです$i$。 次に、サブ配列の合計がプレフィックスの合計の差として計算されます。 
3. For every right endpoint$r \ge k$、左側のエンドポイントが必要です$l \le r-k+1$部分配列の合計が$p[r] - p[l-1]$は非負です。 これは、有効な開始位置のスライディング ウィンドウにわたってプレフィックスの最小値を見つけることと同じです。 
4. インデックス間の最小プレフィックス値を維持する$0 \dots r-k$。 それぞれについて$r$かどうかを確認します。$p[r] \ge \min p[l-1]$。 「はい」の場合、有効なセグメントが見つかりました。 
5. セグメントが存在する場合、そのエンドポイントを記録し、その実現可能性を報告します。$v$。 
6. 最大二分探索$v$それは実現可能であり、両方を出力します$v$そして録画されたセグメント。 

これが機能する理由は、変換によって中央値条件が、相対的なカウントのバランス条件にエンコードされるためです。$v$。 有効なセグメントには十分な要素が必要です ≥$v$以下の要素を「補う」$v$、これはまさに非負の部分配列合計がキャプチャするものです。 スライディング最小値により、合計を再計算せずにすべての有効なセグメントの開始をテストできます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def check(a, k, v):
    n = len(a)
    pref = [0] * (n + 1)
    
    for i in range(1, n + 1):
        pref[i] = pref[i - 1] + (1 if a[i - 1] >= v else -1)

    min_pref = 0
    min_pos = 0

    for r in range(k, n + 1):
        if pref[r - k] < min_pref:
            min_pref = pref[r - k]
            min_pos = r - k

        if pref[r] - min_pref >= 0:
            l = min_pos + 1
            return True, l, r

    return False, -1, -1

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    lo, hi = 1, n
    ans_l, ans_r = 1, k

    while lo <= hi:
        mid = (lo + hi) // 2
        ok, l, r = check(a, k, mid)
        if ok:
            ans_l, ans_r = l, r
            lo = mid + 1
        else:
            hi = mid - 1

    print(hi, ans_l, ans_r)

t = int(input())
for _ in range(t):
    solve()
```このコードは、実現可能性のチェックを二分探索から分離します。 の`check`関数は、変換された配列に対して線形スキャンを実行し、プレフィックスの合計を構築し、有効な開始位置の中で最小のプレフィックスを維持します。 変数`min_pref`これまでのところ最良の出発点を追跡しますが、`min_pos`セグメントを再構築できるように、発生した場所を保存します。 

よくある実装の落とし穴は、有効な左エンドポイントが依存していることを忘れていることです。$k$、つまり、次までの起動のみを許可します$r-k$。 もう 1 つの微妙な問題は、実現可能性が見つかったらすぐにセグメントを返すことです。 二分探索ではセグメントの最適性ではなく存在のみが必要なので、これは問題ありません。
