 ## 解決策
 ## 問題の理解

 長さの配列から始めます`n`、ゼロで埋められます。 演算では正の整数が選択されます`x`これは、配列内の現在の最小値よりも厳密に大きい値です。 

この操作では、どの位置で増分を受け取るかを選択することはできません。 代わりに、値がまだ下にある左端のインデックスを自動的に検索します。`x`。 そのポジションが受け取るのは`+x`。 

問題は、指定されたターゲット配列が`b`このような操作を任意の回数実行した後、すべてゼロの配列から生成できます。 

入力には多くのテスト ケースが含まれています。 すべてのテスト ケースにわたって、配列要素の合計数は最大 200,000 です。 テスト ケースごとに線形またはほぼ線形よりも遅いソリューションは危険になります。 二次アルゴリズムでは、大まかに次のものが必要になります。$4 \cdot 10^{10}$最悪の場合の操作は完全に不可能です。 ターゲットは$O(n)$または$O(n \log n)$解決。 

いくつかの状況は判断を誤りやすいものです。 

考慮する：```
3
3 1 2
```正しい答えは、`NO`。 

よくある間違いは、すべての要素が正の増分の合計として表現できるかどうかだけを見てしまうことです。 それは常に真実です。 困難は、強い順序制約を課す左端ルールに起因します。 

もう 1 つの注意が必要なケースは次のとおりです。```
2
1 1
```答えは`YES`。 

不注意な議論により、すべての増分は現在の最小値よりも大きくなければならず、最初の要素が正になるため 2 番目の位置に到達することは不可能であると主張される可能性があります。 実際には、最初の要素を次と等しくした後、`1`、配列の最小値は依然として`0`、だから選ぶかもしれない`x = 1`もう一度、2 番目の要素を更新します。 

もう 1 つの有用な例は次のとおりです。```
3
40 60 90
```答えは`NO`。 

どの値も大きいですが、3 番目の位置は十分な値を蓄積できません。 初期の位置により、後の位置に到達する増分のサイズに上限が課されます。 

その限界を理解することが重要な観察です。 

## アプローチ

 ブルート フォース ビューでは、考えられるすべての操作シーケンスをシミュレートしようとします。 各ステップで、多くの異なる値を選択できます。`x`となり、到達可能な状態の数は爆発的に増加します。 配列が非常に小さい場合でも、検索ツリーは巨大になります。 すべての可能性を列挙する現実的な方法はありません。 

構造を見つけるには、単一の位置に焦点を当てます`i`。 

構築しようとしているとします`b[i]`。 位置に達する増分`i`2つの条件を満たさなければなりません。 

まず、以前のすべての要素よりも大きくてはなりません。 それ以外の場合は位置`i`以下の左端の値ではありません`x`。 サイズ増加の場合`x`位置に到達`i`、その後、その前のすべての位置`i`すでに少なくとも`x`。 

第二に、位置が`i`最初の増分を受け取ると、その現在の値は`0`。 増分自体は`x`、最初の増分が最終目標を超えることはできません。`b[i]`。 

これらの事実を組み合わせると、すべての増分が位置に適用されます。`i`最大でもサイズがあります$$\min(b_1,b_2,\ldots,b_{i-1}).$$させて$$m_i=\min(b_1,\ldots,b_{i-1}).$$もし`b[i] > m_i`、その後、到達する唯一の方法は`b[i]`位置の最初の増分です`i`まさにそうなる`b[i]`。 より小さな増分の合計は最大でも合計になります。`m_i`。 

つまり、サイズの増分を適用できる必要があります`b[i]`位置に直接`i`。 それが起こるためには、以前のすべてのポジションがすでに少なくとも次の位置にある必要があります`b[i]`。 最終的な値は正確であるため、`b[1],...,b[i-1]`、これには必要です$$b[i] \le m_i.$$もし`b[i] > m_i`、到達`b[i]`不可能です。 

逆に、もし$$b[i] \le m_i$$最初以降のすべての位置で成立する場合、常に構築が可能です。 単純に位置を与えることができます`i`サイズを 1 つずつ増やす`b[i]`以前のすべてのポジションが最終値に達したら。 

問題全体は、すべての要素が以前のすべての要素の最小値以下であるかどうかをチェックすることに帰着します。

 ## アルゴリズムのチュートリアル

 1. ターゲット配列を読み取ります`b`。 
2.初期化`pref_min = b[0]`。 

これには、これまでに確認されたすべての要素の最小値が格納されます。 
3. インデックスから開始して左から右に位置を処理します。`1`。 
4. 現在値について`b[i]`、どうかを確認してください$$b[i] \le pref\_min.$$この位置に到達する増分は、以前の位置の最終最小値を超えることはできません。 
5. もし`b[i] > pref_min`、すぐに答えます`NO`。 

位置`i`以前のポジションがサポートできるものよりも大きな増分が必要になります。 
6. それ以外の場合は更新します$$pref\_min = \min(pref\_min, b[i]).$$これにより、処理されるすべての要素の最小値が維持されます。 
7. すべてのポジションがチェックに合格した場合、回答します。`YES`。 

### なぜ効果があるのか

 どのポジションでも`i > 1`、それに到達するすべての増分は、それ以前のすべての位置の最終値を超えてはなりません。 したがって、そのようなすべての増分は最大でも$$m_i=\min(b_1,\ldots,b_{i-1}).$$もし`b[i] > m_i`、許可された一連の増分によって生成されるものはありません。`b[i]`、最初の増分はすでに超えることができないため、`m_i`。 

もし`b[i] \le m_i`、ポジションが決まるまで待つ場合があります`1..i-1`ターゲットに達した場合は、サイズを 1 回増分して適用します`b[i]`位置を決める`i`。 以前のすべてのポジションは少なくとも`b[i]`の場合、操作は有効であり、その位置をすぐに終了します。 

したがって、最初の要素以降のすべての要素が、それ以前のすべての要素の最小値を超えない場合に、ターゲット配列に正確に到達できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    ans = []

    for _ in range(t):
        n = int(input())
        b = list(map(int, input().split()))

        pref_min = b[0]
        ok = True

        for i in range(1, n):
            if b[i] > pref_min:
                ok = False
                break
            pref_min = min(pref_min, b[i])

        ans.append("YES" if ok else "NO")

    sys.stdout.write("\n".join(ans))

solve()
```この解では、現在位置の左側にあるすべての要素の最小値が維持されます。 

加工時`b[i]`、変数`pref_min`まさに$$\min(b_1,\ldots,b_{i-1}).$$到達可能条件は単純に`b[i] <= pref_min`。 一度条件が失敗すると、その後の処理では修復できないため、そのテスト ケースをすぐに停止する場合があります。 

すべての値は 32 ビット整数に快適に収まりますが、Python 整数はそれらを自動的に処理します。 このアルゴリズムは、条件に関係なく、少数の変数のみを使用します。`n`なのでメモリ使用量は一定です。

 ## 特殊なケース

 次のことを考慮してください。```
1
3
3 1 2
```アルゴリズムは以下を処理します。 

| ポジション | 値 | プレフィックスの最小値 |
 | --- | --- | --- |
 | 1 | 3 | - |
 | 2 | 1 | 3 |
 | 3 | 2 | 1 |

 位置 3 には、`2 > 1`、したがって、答えは次のとおりです`NO`。 

位置 2 はのみで終了します`1`、より大きな増分はないことを意味します`1`位置 3 に到達することはできます。目標値`2`達成不可能です。 

考慮する：```
1
2
1 1
```スキャンで分かるのは`1 <= 1`、したがって、答えは次のとおりです`YES`。 

厳密な不等式を記述すると、等号の場合は誤って処理されやすくなります。 条件は`<=`、 ない`<`。 

考慮する：```
1
3
40 60 90
```アルゴリズムは位置 2 ですぐに停止します。`60 > 40`。 

値が大きくても、サイズだけでは意味がありません。 重要なのは、各要素が以前の最小値を超えているかどうかです。 ポジションがその最小値より大きくなると、操作ルールによりそのポジションは作成されなくなります。
