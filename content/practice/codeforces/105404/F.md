 ## 解決策
 ## 問題の理解

 サイズの空のグリッドから始めます$n \times m$ここで、すべてのセルは最初は白です。 グリッドを変更する唯一の方法は、行全体または列全体を選択し、完全に黒でペイントすることです。 行がペイントされると、その行のすべてのセルが黒になります。 同じことが列にも当てはまります。 

このような操作を任意の数実行した後、残っている白セルの数が正確に一致するようにしたいと考えます。$k$。 それぞれのテストケースで得られるものは、$n$、$m$、そしてこの目標値$k$、そしてそれが達成可能かどうかを判断する必要があります。 

操作の構造に関する重要な観察点は、最終的な構成は、操作の順序ではなく、どの行とどの列が描画されるかのみに依存するということです。 一連の行をペイントすると$R$と列のセット$C$、次に、内のすべてのセル$R$または$C$黒くなります。 残りの白いセルは両方のセットの外側にあるものであり、同じサイズのきれいな長方形のブロックを形成します。$(n - |R|) \times (m - |C|)$。 

これは、最終的な白血球の数が常に次の形式になることを意味します。$$(n - r)(m - c)$$いくつかの整数の場合$0 \le r \le n$、$0 \le c \le m$。 

したがって、問題はもはや操作ではなく、表現できるかどうかです。$k$グリッドの寸法に合わせて整列されたサブ長方形の領域として。 

制約から、$t$最大 30000 に達する可能性があるため、各テストは理想的には非常に高速である必要があります$O(1)$または$O(\sqrt{k})$最悪の場合。 以来$n$、$m$、 そして$k$サイズが大きくなる可能性があるため、グリッド上のシミュレーションや操作の列挙を伴うものは不可能です。 

よくある失敗例は、最終的なジオメトリではなく「ペイント シーケンス」という観点から推論することに起因します。 たとえば、行と列の操作が重なるとカウントが複雑に変化すると誤って考えられる可能性があります。 実際には、重なりは問題ではありません。行または列のいずれかが選択されている場合、セルは黒になるため、結果は純粋に乗算になります。 

もう一つの微妙な間違いは治療です$k$グリッド内の長方形の領域に等しくなければならないことを忘れていますが、任意です。 たとえば、次の場合$n = 3$、$m = 3$、 そして$k = 5$を形成する方法はありません。$3 \times 3$部分的なペイントの直感では 5 つが「到達可能」に見えるかもしれませんが、残りの白いセルがちょうど 5 つあるグリッド領域です。 

## アプローチ

 ブルートフォースパースペクティブでは、ペイントされた行と列のすべての選択肢がシミュレートされます。 行と列のサブセットごとに、結果として得られる白セルの数を計算します。 これはすぐに指数関数的になります$n + m$、あるので$2^n \cdot 2^m$可能な状態。 小さなグリッドでもこれは爆発してしまい、使用できなくなります。 

重要な簡素化は、すべての有効な最終状態が、完全に削除された行と列の数によってのみ決定されることを認識することから生まれます。 取り除いたら$r$行と$c$列の残りの白い領域は完全なサイズの長方形です$(n-r) \times (m-c)$。 これは問題を純粋な因数分解チェックに変換します。つまり、整数が存在するかどうかを尋ねています。$x \le n$そして$y \le m$そのような$x \cdot y = k$。 

したがって、タスクは、次のことを確認することになります。$k$約数がある$x$内に収まるもの$n$、対応する商$y = k/x$内に収まる$m$。 

演算についてはまったく考える必要がなくなり、約数について考えるだけで済みます。$k$。

 ## アルゴリズムのチュートリアル

 1. ペイントする行と列を選択した後、残りの白いセルが次のサイズの長方形を形成することを観察します。$(n-r) \times (m-c)$。 これにより、2 つの辺の長さを選択するという問題が軽減されます。 
2. タスクを整数の検索として再定式化する$x, y$そのような$x \cdot y = k$、 と$x \le n$そして$y \le m$。 ここ$x$残りの未塗装の行を表し、$y$残った未塗装の柱。 
3. 考えられるすべての約数を反復処理します。$x$の$k$。 それぞれについて$x$、分割されるかどうかを確認します$k$きれいに。 これにより、有効な長方形の寸法のみが考慮されるようになります。 
4. 有効な約数ごとに$x$、計算する$y = k / x$、次に、次のことを確認します。$x \le n$そして$y \le m$。 
5. そのようなペアが機能しない場合は、次のように結論付けます。$k$グリッド内の有効な長方形領域として形成できません。 

### なぜ効果があるのか

 すべての有効な操作シーケンスは、削除する行と列のセットの選択に正確に対応しており、その選択により常に長方形の残りの白い領域が生成されます。 逆に、すべてのサイズの長方形$x \times y$グリッド内は放置することで取得できます$x$行と$y$柱は未塗装で残りは塗装します。 これにより、実現可能な構成と要素のペアの間に 1 対 1 の対応関係が作成されます。$k$グリッドの寸法によって制約されるため、すべての約数をチェックすることが必要かつ十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def possible(n, m, k):
    x = 1
    while x * x <= k:
        if k % x == 0:
            y = k // x
            if x <= n and y <= m:
                return True
            if y <= n and x <= m:
                return True
        x += 1
    return False

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n, m, k = map(int, input().split())
        out.append("SI" if possible(n, m, k) else "NO")
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```機能`possible`までの除数スキャンを実行します$\sqrt{k}$。 各約数について$x$、長方形の両方の方向をチェックします。$x$残りの行または残りの列を表すことができます。 

対称性チェックが必要なのは、$x$に対応する必要があります$n$-次元または$m$-寸法。 この交換を怠ると、誤った答えが生じる一般的な原因になります。

 ## 特殊なケース

 まれなケースは次のような場合です$k = 1$。 問題に次のように書かれているにもかかわらず、$k \ge 2$、それについて推論することで正しさが明らかになります。$1 \times 1$長方形は有効です。つまり、グリッドでは少なくとも 1 つの未処理の行と列を許可する必要があります。 

もう一つの微妙なケースは次のような場合です。$k$プライムです。 例えば、$k = 13$と$n = 3$、$m = 10$。 唯一の因数分解は、$1 \times 13$1 つの次元が 13 を収容できない場合、これは失敗します。1 以外の約数が存在しないため、アルゴリズムは他のすべての値を正しく拒否します。 

さらに興味深いケースは、両方の因数分解が存在するが、一方のみが適合する場合です。 のために$n = 5$、$m = 20$、$k = 50$、ペアがあります$(1,50)$、$(2,25)$、$(5,10)$、$(10,5)$。 のみ$(5,10)$そして$(10,5)$関連性があり、少なくとも 1 つが制約を満たすため、アルゴリズムは制約に遭遇するとすぐに受け入れます。
