 ## 解決策
 ## 問題の理解

 いくつかの独立したテスト ケースが与えられています。 各テスト ケースでは、正の整数のリストが提供されます。 このタスクは、同じリスト内のすべての要素 (それ自体を含む) を簡単な方法で分割できる要素がリスト内に少なくとも 1 つ存在するかどうかを判断することです。 

より具体的には、配列ごとにインデックスを検索します。$i$あらゆる人にとって$j$、値$a_i$分割する$a_j$残りなしで。 そのような要素が存在する場合は「SI」と回答し、存在しない場合は「NO」と回答します。 

入力サイズにより、テストケースごとの効率について慎重に考える必要があります。 テスト ケースは最大 100 個まで存在でき、各テスト ケースには最大 10,000 個の数値を含めることができます。 各候補要素の割り算ペアを他のすべての要素と比較してチェックする単純なアプローチでは、以下のチェックが必要になります。$n^2$テスト ケースごとの関係。最悪の場合、$10^8$可分性チェック。 これはまだ境界線にありますが、慎重に実装された場合にのみ、最適化された Python で合格できます (不要ですが)。 

より微妙な制約は値の範囲にあります。各数値は最大です。$10^9$。 これにより、周波数配列や直接インデックス付けのアプローチが除外されます。 この構造は純粋に算術演算です。 

素朴な推論を打ち破る特殊なケースの 1 つは、値が繰り返されることです。 たとえば、次のような配列では、`[4, 2, 4, 6, 8, 4]`の場合、値 4 は複数回出現し、有効な候補ですが、すべての要素を注意深くチェックしない限り、すべての位置で 2 または 6 を分割することはできません。 もう 1 つの特殊なケースは、最小の数値が答えではない場合です。 例えば`[2, 3, 6]`候補として 2 がありますが、3 は 2 で割り切れないため失敗します。 

2 番目の微妙な障害モードは、最小限の要素が常に機能すると仮定することです。 のために`[2, 3, 4]`、最小値は 2 ですが、2 は 3 を割らないため、正解は「NO」です。 

最後に、等しい要素が多数ある配列は扱いが難しくなります。 すべての数値が同じ場合、任意の要素が他のすべての要素を割るため、答えは常に「SI」になります。 

## アプローチ

 ブルートフォースアプローチは簡単です。 配列内の各要素について、それを除数の候補として扱い、要素が 1 つおきに分割されているかどうかを確認します。 これには 2 つの入れ子になったループが必要です。1 つは候補を選択するため、もう 1 つは配列全体の割り算を検証するためです。 各チェックは定数時間であるため、テスト ケースごとの複雑さは次のようになります。$O(n^2)$。 と$n = 10^4$、これは次のことにつながります$10^8$テスト ケースごとの操作が複数のテスト ケースにまたがると遅くなりすぎます。 

重要な観察は、有効な候補は最大要素を含むすべての要素を分割する必要があるということです。 これは、候補が分割されるすべての要素以下である必要があることを直ちに意味するため、候補は配列内の最小値でなければなりません。 ただし、明示的に可分性をテストしない限り、一般的な推論では最小値だけでは十分ではありません。 

これにより、検索スペースが大幅に減少します。 すべての要素をテストするのではなく、配列内の最小値のみをテストする必要があります。 この値がすべての要素を分割する場合、それは有効な答えです。 そうしないと、より大きな候補は最小値自体を除算できないため、他の要素は機能しません。 

これにより、問題は最小値を見つけるための 1 回のスキャンに変換され、その後、割り切れる可能性を検証するために 2 回目のスキャンが行われます。

 | ブルートフォース | O(n²) | お(1) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースごとに、整数の配列を読み取ります。 これにより、独立したシナリオが分離され、シナリオ間で状態が引き継がれることはありません。 
2. 配列を 1 回スキャンして、最小の要素を見つけます。 有効な約数はすべての要素を分割できるほど十分に小さい必要があるため、この候補が選択されます。 
3. 配列を再度スキャンし、すべての要素がこの候補で割り切れるかどうかを確認します。 
4. いずれかの要素が可分性チェックに失敗した場合は、このテスト ケースに有効な要素が存在しないと直ちに結論付けます。 
5. すべての要素がチェックに合格した場合は「SI」を出力し、そうでない場合は「NO」を出力します。 

### なぜ効果があるのか

 数値が配列内のすべての要素を分割する場合、特に最小要素を分割する必要があります。 最小値より小さい数値は配列内に存在しないため、すべての制約を無視できる唯一の候補は最小値そのものです。 これより大きい数値は最小値を割り切れないため、有効ではありません。 これにより、厳密な一意性のプロパティが作成されます。チェックする必要がある候補は最大 1 つであり、その妥当性によって答えが完全に決まります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        arr = list(map(int, input().split()))

        m = min(arr)

        ok = True
        for x in arr:
            if x % m != 0:
                ok = False
                break

        out.append("SI" if ok else "NO")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このソリューションは、すべてのテスト ケースを読み取り、それらを個別に処理することから始まります。 それぞれの場合において、単一パスを使用して最小値が計算されます。 

2 番目のループでは、すべての要素がこの最小値で割り切れるかどうかをチェックします。 早期に中断することは、反例が見つかった場合に不要な作業を回避し、早期に障害が発生する最悪の場合の入力でのパフォーマンスを向上させるため重要です。 

微妙な点は、最小値自体が割り算されるかどうかをテストする必要がないことです。`x % m`の場合は常にゼロです`x == m`。 これにより、冗長なロジックが回避され、すべての要素にわたってチェックが均一に保たれます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべての要素が同一である場合です。 のような入力の場合`[7, 7, 7, 7]`、最小値は 7 で、すべての要素は 7 で割り切れます。アルゴリズムは 1 回スキャンし、すべての要素の割り切れ性を確認し、「SI」を出力します。 これにより、繰り返される値に特別な処理が必要ないことが検証されます。 

もう 1 つのケースは、最小値が 1 回しか現れず、それでも除数として失敗する場合です。`[2, 3, 4, 6]`。 アルゴリズムは 2 を候補として選択しますが、3 ではすぐに失敗します。`3 % 2 != 0`。 早期終了により、不必要なチェックが防止されます。 

3 番目のケースは、より大きな数がもっともらしいように見えますが、最小値を割り切れないため正しくない場合です。 のために`[4, 2, 4, 6, 8, 4]`, 2か4以外の候補は無理です。 アルゴリズムは正しく 2 に落ち着き、配列全体に対してそれを検証し、「SI」を生成します。
