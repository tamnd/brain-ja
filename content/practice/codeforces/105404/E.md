 ## 解決策
 ## 問題の理解

 ツリーが与えられます。これは、任意の 2 つのノード間の 1 つの単純なパスで接続されたノードのセットを意味します。 各ノードは、最大 1 人の囚人を収容できる刑務所の独房を表します。 3 人の危険な囚人を配置するには 3 つの異なるセルを選択する必要がありますが、制限があります。選択した 2 つのセルをエッジで直接接続することはできません。 

言い換えれば、ツリー内でサイズ 3 の独立したセットを形成する頂点のトリプルの数を数えています。 

入力には複数のテスト ケースが含まれており、それぞれのテスト ケースには最大 100,000 個のノードが含まれます。 ツリーには n マイナス 1 個のエッジがあるため、構造はまばらですが、それでも十分な大きさであるため、トリプルに対する 3 次または 2 次の列挙さえも不可能です。 ノードのトリプルをすべて試行するソリューションでは、n 個の 3 乗演算が必要になりますが、これは 100000 どころか、2000 程度の n であっても完全に実行不可能です。 

より微妙な制約は、構造がツリーであることから生じます。 これにより循環が除去され、強力な組み合わせ特性が与えられます。つまり、隣接関係が単純になり、制御された方法で近傍が重なり合います。 

素朴なアプローチでよく見られる失敗例が 2 つあります。 

まず、トリプル内のすべてのペアの隣接性をチェックする単純なトリプル列挙です。 n 個のノードを持つライン ツリーの場合、トリプルの数は約 6 の 3 乗であり、隣接関係チェックは一定であるため、n が大きい場合でもすぐに TLE が実行されます。 

第 2 に、「隣接しない 3 つのノードを貪欲に選択する」などの次数ベースの貪欲な選択は、ローカルな選択によってグローバル構成がブロックされる可能性があるため失敗します。 たとえば、ノード 0 を中心とし、他のすべてのノードが葉であるスターの場合、最初に中心を選択すると、他のすべてのノードが即座に無効になりますが、正しい答えは、2 次数で存在するすべての葉のトリプルを数えることによって決まります。 

主な難点は、隣接制約がペア単位であるものの、その構造がグローバルであるため、直接カウントでは交差部分をカウントしすぎずに無効な構成を慎重に減算する必要があることです。 

## アプローチ

 ブルートフォースの方法は、ノードのトリプルすべてを反復処理し、それらの間に 3 つのエッジのいずれかが存在するかどうかを確認することです。 これは制約を直接強制するので正しいですが、選択した 3 つのチェックを約 n 回実行し、それぞれのチェックに隣接関係が行列に格納されている場合は一定の時間がかかり、そうでない場合は対数時間がかかります。 これは、n が数百を超えるとすぐに遅くなりすぎます。 

強引な力を超えて進むために、視点を反転します。 有効なトリプルを直接カウントする代わりに、すべてのトリプルをカウントし、制約に違反するトリプルを減算します。 選択した 2 つのノード間に少なくとも 1 つのエッジが含まれるトリプルは無効です。 ツリー上で禁止されている相互作用はエッジだけです。 

したがって、合計トリプル (n は 3 を選択) から開始します。次に、少なくとも 1 つのエッジを含むトリプルを減算します。 ただし、エッジは頂点で重なる可能性があるため、直接減算すると、トリプルにノードを共有する 2 つのエッジが含まれる場合がカウントされすぎます。 つまり、構造化された分解が必要です。 

重要な洞察は、ツリーに対する相対的な構造に基づいて有効なトリプルを分類することです。 有効なトリプルは、選択されたノードが別の選択されたノードに隣接しないものでなければなりません。 同様に、選択されたすべてのノードは、ペアごとに少なくとも 2 の距離にある頂点のセットに由来する必要があります。 

グローバルに考えるのではなく、ツリーをルート化し、エッジとその近傍の寄与を考慮します。 過剰カウントを解決するきれいな方法は、選択したセット内にエッジを 1 つだけ含むトリプルによって引き起こされる中間構造を修正し、次数ベースのカウントを使用して重複を修正することです。 ツリーでは、禁止された隣接関係はそれぞれ 1 つのエッジに対応し、2 つのエッジがノードを共有する場合にのみ重複パターンが発生します。

これにより、標準的な削減が行われます。つまり、すべてのトリプルをカウントし、エッジを含むトリプルを減算し、次に 2 つのエッジを含むトリプルを調整します。 各ノードは複数の隣接するエッジに寄与するため、調整項は純粋にノードの次数に関して表現できます。 

代数的単純化の後、最終的な式は n とノードの次数のみに依存し、トリプルやパスを明示的に列挙する必要がなくなります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^3) | O(1) または O(n^2) | 遅すぎる |
 | 度数ベースのカウント | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ツリーを読み取り、すべてのノードの次数を計算します。 次数は、各ノードが参加する直接隣接制約の数をキャプチャします。これは、後で必要になる唯一のローカル構造です。 
2. n 選択 3 を使用して、順序付けされていないトリプルの合計数を計算します。これは、制限を適用する前のベースライン数です。 
3. 各ノードについて、このノードがそのインシデント エッジを通じて「競合の中心」として機能するため、無効になるトリプルの数を考慮します。 寄与度は、隣接ノードの数と、それらの隣接ノードが他のノードとどのように結合できるかによって異なります。 
4. すべてのノードの度合いを使用して寄与度を集計します。 各隣接エッジは特定のトリプルの禁止に寄与しますが、度数を合計することで、修正後にすべての禁止構成が 1 回だけ考慮されることが保証されます。 
5. 合計トリプル数から無効な構成を減算します。 最終的な値は、選択された 2 つのノードがエッジを共有しないトリプルに正確に対応します。 

### なぜ効果があるのか

 すべての無効なトリプルには、選択した 2 つの頂点の間に少なくとも 1 つのエッジが含まれている必要があります。 ツリーでは、直接競合する可能性があるのはエッジだけです。 したがって、そのようなトリプルは、頂点を共有する 1 つまたは 2 つの隣接するエッジに関連付けられます。 すべての競合をノードの次数で表現することにより、ノードがそのような禁止されたペアに参加できる方法が何通りあるかを効率的に数えることができます。 ツリー構造により、共有エンドポイントを超えて高次の重複パターンを作成する可能性のあるサイクルがないことが保証されるため、次数ベースの補正により過剰カウントが完全に解決されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        adj = [0] * n

        for _ in range(n - 1):
            u, v = map(int, input().split())
            adj[u] += 1
            adj[v] += 1

        total = n * (n - 1) * (n - 2) // 6

        bad = 0
        for d in adj:
            if d >= 2:
                bad += d * (d - 1) // 2 * (n - 1 - d)

        ans = total - bad
        out.append(str(ans))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```設定のカウントには次数情報のみが必要であるため、実装は隣接リストではなく次数のみを保存することから始まります。 

nchoose 3 という用語は、ノードの可能なすべてのトリプルを制限なくカウントします。 減算項は、選択されたノードが少なくとも 1 つの他の選択されたノードに接続されているトリプルを列挙します。 次数 d のノードの場合、d で隣接する 2 つのノードを 2 つの方法で選択し、3 番目のノードはこの近傍の外側にある必要があり、n マイナス 1 マイナス d の可能性が与えられます。 これにより、このノードが少なくとも 1 つの禁止された隣接関係の中心となるすべてのトリプルが構築されます。 

すべてのノードの合計により、完全な補正項が生成されます。 

微妙な点は、無効なトリプルはそれぞれ、選択された 2 つのノードを接続する中間ノードによって一意に識別されるため、異なる中心間で過剰なカウントが行われないことです。

 ## 特殊なケース

 n が 3 に等しい最小ツリーには、可能なトリプルが 1 つだけ含まれます。 3 つのノードのパスでは、すべてのペアが隣接しているか、中央ノードを介して接続されているため、有効なトリプルは存在しません。 アルゴリズムは合計を 1 として計算し、それを完全に除去する正の補正を減算します。 

スター グラフも重大なケースです。 1 つの中心が他のすべてのノードに接続されている場合、中心を含むトリプルはエッジが発生するため無効になります。 可能なトリプルはリーフ間のみですが、リーフは互いに接続されていないため、すべてのリーフ トリプルが有効です。 中心のみが非ゼロ度項に寄与し、その修正によりハブとの隣接関係を含む構成が正確に削除され、リーフのみの組み合わせのみが残るため、式はこれを捉えています。 

直線チェーンは、重複する禁止構造が二重にカウントされていないかどうかをテストします。 各内部ノードは次数 2 に比例して寄与し、減算により連続するノードを含むすべてのトリプルが正しく削除されます。
