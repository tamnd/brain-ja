 ## 解決策
 ## 問題の理解

 平面上の一連の点とターゲット領域が与えられます。 タスクは、それらが形成する三角形が要求された領域と正確に一致するように 3 つの点を選択するか、そのような三角形が存在しないことを報告することです。 整数座標の場合、2 倍の面積は常に整数であるため、面積は 2 倍の面積を使用して比較されます。 元の問題は最大 2000 点、ターゲット領域は最大 2000 点です。$2 \cdot 10^{18}$。 

境界により、すべてのトリプルのチェックが直ちに除外されます。 がある$O(n^3)$可能な三角形、つまり周囲を意味します$8 \cdot 10^9$最大の入力サイズでチェックします。 たとえ非常に小さな定数係数を使用したとしても、これは多すぎます。 検索をおよそ 2 次作業に減らす必要があります。$2000^2$操作は管理可能です。 

三角形について考えるときに便利な方法は、1 つの辺を底辺として固定することです。 ベースの 2 つの端点がわかれば、必要な高さもわかります。 残りのタスクは、このベースラインからの垂直距離が正確に必要な値を持つ点を見つけることです。 

浮動小数点ジオメトリを使用する場合、不注意な実装は失敗する可能性があります。 たとえば、対象となる2倍の領域が`1`また、三角形の高さが非常に小さいため、浮動小数点の丸めにより、面積が正確でないと誤って判断される可能性があります。 入力座標は次のように大きくできます。$10^9$、したがって、外積は約に達します$10^{18}$、整数演算を使用する必要があります。 

もう 1 つのよくある間違いは、三角形が選択した底辺のどちら側にでも配置できることを忘れていることです。 入力用```
3 5
0 0
10 0
5 1
```2倍の面積は`10`, したがって、この特定のターゲットは不可能です。 基底より上の点のみを検索する方法では、点が基底より下にある場合も、符号付き外積が負になるため、有効な解が見つかりません。 

## アプローチ

 ブルートフォースアプローチは、ポイントの 3 倍ごとを選択し、外積を使用して 2 倍の面積を計算し、それをターゲットと比較することです。 考えられるすべての三角形が明示的にチェックされるため、これは正しいです。 問題はトリプルの数です。$n^3/6$。 のために$n=2000$、つまり数十億回の操作です。 

重要な観察は、拠点を選択した後、エリア条件が一次元の検索になることです。 基底ベクトルが$v$、2 倍の面積は、次の間の外積の絶対値です。$v$そして 3 番目の点へのベクトル。 ベースラインから特定の符号付き距離を持つ点が必要です。 

難しいのは、現在の基地までの距離によって順序付けされたポイントを維持することです。 すべてのペアに対してこの順序を再計算すると、やはり時間がかかりすぎます。 代わりに、可能なすべてのセグメントを通してベースを回転させます。 底辺の方向が連続的に変化する場合、回転する直線がその 2 点を結ぶ線分と平行になった場合にのみ、2 点の相対的な順序が変化します。 すべての点のペアを角度順に処理するため、すべての変更は、維持された順序内の 2 つの隣接する点を交換するだけです。 これにより、$O(n^2 \log n)$解決。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n3) | お(1) | 遅すぎる |
 | 最適 | O(n² log n) | O(n²) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての有向点のペアを作成し、ペアを接続する線分の角度によって並べ替えます。 スイープは水平方向から始まります。ラインまでの距離による並べ替えは、y 座標による並べ替えと同じです。 
2. 現在のスイープ ラインからの符号付き距離順に並べられた点の配列を維持します。 また、スワップが定数時間になるように、この配列内のすべてのポイントの位置を保存します。 
3. 角度順序のすべてのセグメントについて、現在の順序を使用して 3 番目の点を検索します。 ベースの場合`a`に`b`、2倍の領域の条件は次のとおりです。$$cross(b-a, c-a)=2S$$または、同じ値を反対の符号で表します。 点はこの値によって並べ替えられるため、二分探索で一致する点を見つけることができます。 

1. セグメントを処理した後、維持された順序内でそのセグメントの 2 つのエンドポイントを交換します。 これにより、次のスイープ位置の順序が更新されます。 

交換で十分な理由は、回転する線に対して 2 つの点の順序が入れ替わるのは、その線がそれらを結ぶ線分と平行になるときだけであるためです。 私たちはそれらのイベントを正確に処理します。 

機能する理由: 維持される順序は常に、現在のベースラインからの符号付き距離によるポイントの順序です。 二分探索は、固定基底ベクトルとの外積が線形変換であるため有効であり、距離の順序が保持されます。 スイープでは、2 つの距離が等しくなり、3 つの点が同一線上にない正確な瞬間に順序付けが更新されるため、すべてのイベントは明確になります。 必要な外積を持つ点が見つかると、三角形の面積条件が構築によって満たされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, S = map(int, input().split())
    pts = [tuple(map(int, input().split())) for _ in range(n)]
    target = 2 * S

    def cross(a, b, c):
        return (b[0] - a[0]) * (c[1] - a[1]) - (b[1] - a[1]) * (c[0] - a[0])

    events = []
    for i in range(n):
        for j in range(i + 1, n):
            dx = pts[j][0] - pts[i][0]
            dy = pts[j][1] - pts[i][1]
            events.append((dy, dx, i, j))

    events.sort(key=lambda e: __import__("math").atan2(e[0], e[1]))

    order = sorted(range(n), key=lambda i: pts[i][1])
    pos = [0] * n
    for i, x in enumerate(order):
        pos[x] = i

    for _, _, a, b in events:
        lo, hi = 0, n
        while lo < hi:
            mid = (lo + hi) // 2
            c = order[mid]
            val = cross(a, b, c)
            if val < target:
                lo = mid + 1
            else:
                hi = mid

        if lo < n and cross(a, b, order[lo]) == target:
            c = order[lo]
            print("YES")
            print(*pts[a])
            print(*pts[b])
            print(*pts[c])
            return

        lo, hi = 0, n
        while lo < hi:
            mid = (lo + hi) // 2
            c = order[mid]
            val = cross(a, b, c)
            if val < -target:
                lo = mid + 1
            else:
                hi = mid

        if lo < n and cross(a, b, order[lo]) == -target:
            c = order[lo]
            print("YES")
            print(*pts[a])
            print(*pts[b])
            print(*pts[c])
            return

        pa, pb = pos[a], pos[b]
        order[pa], order[pb] = order[pb], order[pa]
        pos[a], pos[b] = pb, pa

    print("NO")

if __name__ == "__main__":
    solve()
```の`cross`関数はコアのジオメトリ操作です。 符号付き領域の 2 倍を返し、すべての浮動小数点計算を回避します。 

スイープアレイ`order`アルゴリズムで記述された動的構造です。 の`pos`array は、現在のベースの 2 つのエンドポイントを交換する必要がある場合に、コストのかかる検索を防止します。 

二分探索では、三角形の可能な両方の方向が検索されます。 1 つの標識だけを検索すると、底辺の反対側にある三角形を見逃してしまいます。 すべての算術演算は Python 整数のままであるため、大きな座標積がオーバーフローすることはありません。

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |

| スペース | O(n²) | すべての点ペアのリストがメモリの大部分を占めます。

 ## 特殊なケース

 不可能なサンプルの場合:```
3 7
0 0
3 0
0 4
```アルゴリズムはすべての可能な塩基をチェックします。 ベース`(0,0)`に`(3,0)`外積 14 の点が必要ですが、3 番目の点では 12 が得られます。他の 2 つの塩基も同様に失敗するため、答えは残ります。`NO`。 

最小の有効な三角形の場合:```
3 1
0 0
1 0
0 1
```目標の 2 倍の面積は 2 です。最初の 2 点を基準として、3 番目の点の外積は 1 になりますか? ベースを正しい向きにすると、`(0,0)`に`(0,1)`外積 2 が得られるため、二分探索でそれが見つかり、返されます。`YES`。 

すべての塩基が両方の方向でテストされるため、アルゴリズムは両方の方向を処理します。`target`そして`-target`したがって、選択したベースラインの下の三角形は、その上の三角形とまったく同様に扱われます。
