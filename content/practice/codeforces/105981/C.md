 ## 解決策
 ## 問題の理解

 整数の配列が与えられ、その順序について非常に具体的な質問がされました。それは、2 つの要素の最大 1 回の交換を使用して非減少シーケンスに変換できるかどうかです。 隣接している必要はなくても、任意の 2 つの位置間での交換が許可されており、配列がすでにソートされている場合は、まったく交換しないことを選択することもできます。 

入力は単一のシーケンスを表し、出力は二分決定です。 配列を 0 または 1 つのスワップでソートできることを確認するか、拒否します。 

制約 n ≤ 1000 は十分小さいため、O(n²) 推論でも問題なく通過できます。 このことは、複雑な変換のシミュレーションや多層最適化の実行が期待されていないことをすでに示唆しています。 タスクの構造は、増分処理ではなく、グローバルな整合性チェックです。 

重複が存在する場合、微妙なケースが発生します。 たとえば、次のような配列では、`[1, 3, 2, 2, 3]`、複数の正しいスワップが存在する可能性がありますが、重要なのは特定の 1 つのスワップだけです。 「反転の数」だけをチェックする不注意なアプローチは失敗します。反転は、単一のスワップでグローバルな順序を修正できるかどうかを直接エンコードしないからです。 正しい基準は、ソートされたバージョンとの正確な位置の不一致によって決まります。 

もう 1 つの失敗例は、反転がほとんどない場合、スワップによって常に反転が修正されると仮定することです。 例えば、`[3, 1, 2]`には複数の反転がありますが、単一のスワップによってソートされることはありません。 

本当の難しさは計算の問題ではなく、「ソートから 1 回のスワップ」が順列にどのような構造を課すかを特定することです。 

## アプローチ

 ブルートフォース手法では、考えられるすべてのインデックス i と j のペアを試し、それらを交換し、結果の配列がソートされているかどうかを確認します。 これは問題文の直後にあるため、正解です。 ただし、各チェックのコストは O(n) で、スワップは O(n²) 回あり、合計時間は O(n³) になります。 n = 1000 の場合、これは約 10⁹ 操作に達します。これは境界線ですが、それでも Python では遅すぎます。 

繰り返しのシミュレーションを避けることでこれを改善します。 重要な観察は、ソートされた配列は、ソートされた順序に対して要素が誤って配置されている位置のみが元の配列と異なるということです。 配列をソートし、元の配列と位置ごとに比較すると、正しい位置はすべて一致し、間違った位置は構造が壊れた場所を正確にマークします。 

3 つ以上の位置が異なる場合、1 回のスワップでは正確に 2 つの位置しか修正できないため、1 回のスワップですべての不一致を修正することはできません。 正確に 2 つの位置が異なる場合は、元の配列内の 2 つの要素を交換することでソートされた配列が生成されるかどうかをテストできます。 

これにより、問題はソートされたバージョンとの 1 つの比較に減ります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォーススワップシミュレーション | O(n3) | お(1) | 遅すぎる |
 | ソートされた配列と比較する | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 元の配列をソートされた形式と比較し、構造の不一致について推論することで、問題を軽減します。 

1. 配列のソートされたコピーを作成します。 これは、到達したいターゲット構成を表します。 ソートのコストは O(n log n) ですが、これは十分に高速です。 
2. 元の配列とソートされた配列のインデックスをインデックスごとに比較し、異なるインデックスをすべて収集します。 これらの位置は、現在の順序が有効な並べ替え順序と一致しない場所を正確に表します。 
3. 不一致の位置がゼロの場合、配列はすでにソートされているため、スワップは必要ありません。 
4. 3 つ以上の不一致位置がある場合、1 回のスワップで影響するのは順列内の最大 2 つの位置であるため、1 回のスワップで配列を修正することは不可能です。 
5. 不一致の位置 i と j がちょうど 2 つある場合は、元の配列で a[i] と a[j] を交換して、配列がソートされた配列と等しくなるかどうかを確認します。 そうであれば、答えは肯定的ですが、そうでない場合は、1 回の交換では修正できません。 

機能する理由: ソートされた配列は、固定されたターゲットの順列です。 単一のスワップでは、値が変更される形で正確に 2 つの位置が変更されます。 したがって、不一致のセットは空であるか、またはこれら 2 つの要素を交換することで同時に修正できる正確に 2 つの位置で構成されている必要があります。 1 回のスワップでは 3 つ以上の間違った位置を同時に修復できないため、大きな不一致セットは 1 回の転置では解決できません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    a = list(map(int, input().split()))
    
    b = sorted(a)
    
    diff = []
    for i in range(n):
        if a[i] != b[i]:
            diff.append(i)
    
    if len(diff) == 0:
        print("Sorted")
        return
    
    if len(diff) != 2:
        print("Failed")
        return
    
    i, j = diff
    a[i], a[j] = a[j], a[i]
    
    if a == b:
        print("Sorted")
    else:
        print("Failed")

if __name__ == "__main__":
    solve()
```このソリューションは、並べ替えられたターゲットを構築し、それを構造比較の参照として使用します。 diff リストは、順列が逸脱している場所を正確に特定します。 最後の交換テストが必要なのは、値が正しく一致しない限り、不一致が 2 つだけ存在しても、それらを交換しても順序が修正されるとは限らないためです。 

## 実用的な例

 インプットを考慮する`[1, 3, 2]`。 ソートされた配列は`[1, 2, 3]`。 位置 1 と 2 で不一致が発生します。これらを交換すると、次のようになります。`[1, 2, 3]`なので、出力は有効です。 

| ステップ | 配列 | 並べ替え済み | 差分位置 |
 | --- | --- | --- | --- |
 | イニシャル | 1 3 2 | 1 2 3 | [1、2] |
 | 交換後 | 1 2 3 | 1 2 3 | [] |

 これは、単一のスワップで順列が修正されるケースを裏付けています。 

ここで考えてみましょう`[3, 1, 2]`。 ソートされた配列は`[1, 2, 3]`。 全てのポジションが違うのでデフサイズが3となり、すぐに無理になります。 

| ステップ | 配列 | 並べ替え済み | 差分位置 |
 | --- | --- | --- | --- |
 | イニシャル | 3 1 2 | 1 2 3 | [0、1、2] |

 アルゴリズムはスワップを試行せずに拒否しますが、これは単一の転置の構造的制限と一致します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | 並べ替えが優先されます。 比較は線形です |
 | スペース | O(n) | ソートされたコピーと差分リストのストレージ |

 n ≤ 1000 という制約により、制限内でこれを実行するのが簡単になります。 テスト ケース間で並べ替えを繰り返しても、効率は維持されます。

 ## 特殊なケース

 主なエッジケースは、配列がすでにソートされている場合です。 入力用`[1, 2, 3]`の場合、差分リストは空であり、アルゴリズムはスワップを試行せずにすぐに受け入れます。これにより、不必要な変更が回避され、正確さが保証されます。 

もう 1 つの重要なケースは、正確に 2 つの不一致が存在するが、値の不一致によりそれらを交換しても順序が修正されない場合です。 例えば`[1, 4, 3, 2]`ソートされる`[1, 2, 3, 4]`。 diff インデックスは 3 つの位置であるため、誤解を招く部分的な修正の試行を避けて、すぐに拒否されます。 

比較はインデックスベースではなく値ベースであるため、重複によってロジックが破壊されることはありません。 複数の有効なソートされた順列が存在する場合でも、ソートされた配列は正規のターゲットを提供し、不一致の検出は安定したままになります。
