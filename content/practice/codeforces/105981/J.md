 ## 解決策
 ## 問題の理解

 単一の整数を繰り返し縮小するプロセスが与えられています。 値から始める`m = n`、1 回の操作で範囲内の均一にランダムな整数に置き換えられます。`[0, m-1]`。 値が次になるとプロセスは停止します。`0`。 タスクは、さまざまな開始値に対して、終了までに必要な操作の予想数を計算することです。`n`。 

各テスト ケースには 1 つの開始番号が与えられ、プロセスがゼロに達するまでランダムな削減の予想される数を出力する必要があります。 

制約は大きく、最大で`10^5`テストケースとそれぞれの`n`と同じ大きさにすることができます`10^5`。 これにより、線形時間または二次時間でクエリごとに期待値をゼロから再計算するアプローチが除外されます。 平`O(n^2)`前処理はすでに厳しいものになりますが、`O(n log n)`または`O(n)`による前処理`O(1)`クエリは明らかに受け入れられます。 

主な微妙な点は、プロセスが確率的であるにもかかわらず、高度に構造化されていることです。 各州`m`より小さな国家にのみ依存する`0..m-1`、これは動的計画法による定式化を強く示唆しています。 

一般的な失敗例は、遷移を独立したものとして扱ったり、プロセスをシミュレートしようとしたりするときに発生します。 

たとえば、次の場合`n = 2`、プロセスは 2 から始まり、次にランダムな値に進みます。`{0, 1}`。 そうなったら`1`、平均してさらにもう 1 つのステップが必要ですが、それが進むと`0`、すぐに停止します。 いくつかのランダムな実行を平均する単純なシミュレーションでは、分布が早期終了に大きく偏っているため、収束が遅くなるか誤解を招く可能性があります。 

もう一つのエッジケースは、`n = 0`。 プロセスはすでに終了しているので、答えは正確です`0`。 再発する場合は、この基本ケースを明示的に固定する必要があります。そうしないと、未定義の期待が誤って伝播されます。 

## アプローチ

 期待について考える強引な方法は、次のように定義することです。`E(m)`値から始まる予想される操作の数として`m`。 州から`m`、常に 1 つの操作が実行され、その後、いずれかの状態に均一に遷移します。`0`を通して`m-1`。 これにより直接再帰が得られます```
E(m) = 1 + (1/m) * sum_{k=0}^{m-1} E(k)
```この定式化は正しいですが、直接評価すると高価になります。 それぞれについて`m`、以前のすべての状態のコストの合計を計算します`O(m)`、につながる`O(n^2)`前処理中。 

重要な単純化は、反復が次のプレフィックスの合計のみに依存することに気づくことから来ます。`E`。 維持すれば`S(m) = sum_{k=0}^m E(k)`、その後、再発は次のようになります```
E(m) = 1 + (1/m) * S(m-1)
```そしてその結果として```
S(m) = S(m-1) + E(m)
```これにより、問題は単一の線形パスに変換されます。 

より深い構造は、それぞれ`E(m)`個々の値ではなく、より小規模な州に関する集約された情報のみに依存します。 これにより、合計を繰り返し再計算する必要がなくなります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 再計算による直接再帰 | O(n^2) | O(n) | 遅すぎる |
 | プレフィックスサム DP の最適化 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### 最適な DP の計算

 1.初期化`E(0) = 0`そして`S(0) = 0`。 これは、値がすでにゼロの場合には操作は必要ないという定義と一致します。 
2. 反復する`m`から`1`最大限に`n`すべてのテストケースにわたって。 
3. コンピューティング`E(m)`保存されているプレフィックスの合計を使用して、次のようにします。```
E(m) = 1 + S(m-1) / m
```これは、すべての遷移が次から始まるため機能します。`m`より小さな州に一律に行き、彼らの期待はすでに集約されています。`S(m-1)`。 
4. プレフィックスの合計を更新します。```
S(m) = S(m-1) + E(m)
```5. 前処理後、各クエリ`n`は次のように直接答えられます`E(n)`。 

この順序が重要である理由は次のとおりです。`E(m)`完全なプレフィックスに依存するため、小さい値がすべて確定した後に常に計算する必要があります。 

### なぜ効果があるのか

 不変条件は、反復の開始時です。`m`、`S(m-1)`すべての状態の正しい期待値の正確な合計は、厳密に次の値よりも小さいです`m`。 再発が表現する`E(m)`純粋に、これらのすでに正しい値の線形結合として。 将来の状態が以前の状態に影響を与えることはないため、DP は計算後に値を修正することはなく、各期待値は完全に決定された情報からのみ構築されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXN = 100000

E = [0.0] * (MAXN + 1)

S = [0.0] * (MAXN + 1)

for m in range(1, MAXN + 1):
    E[m] = 1.0 + S[m - 1] / m
    S[m] = S[m - 1] + E[m]

t = int(input())
out = []
for _ in range(t):
    n = int(input())
    out.append(str(E[n]))

print("\n".join(out))
```コードは期待値を可能な限り最大まで事前計算します。`n`。 配列`E`各状態の最終的な答えを保存します。`S`定数時間の反復評価を可能にするためにプレフィックスの合計を維持します。 各更新では以前に計算された値のみが使用されるため、ループは厳密に順方向のみであり、必要な精度に関して数値的に安定しています。 

微妙な点の 1 つは、すべてが浮動小数点で格納されることです。 要求される精度は次のとおりですので、`1e-4`、倍精度で十分であり、正確な有理演算は必要ありません。 

## 実用的な例

 ### 例 1: n = 2

 段階的に計算していきます。 

| メートル | S(m-1) | E(m) | S(m) |
 | --- | --- | --- | --- |
 | 0 | 0 | 0 | 0 |
 | 1 | 0 | 1 | 1 |
 | 2 | 1 | 1 + 1/2 = 1.5 | 2.5 |

 のために`n = 2`、結果は`1.5`。 

このトレースは状態を示しています`2`両方の結果を集計します`{0,1}`均一に。 

### 例 2: n = 4

 | メートル | S(m-1) | E(m) | S(m) |
 | --- | --- | --- | --- |
 | 1 | 0 | 1 | 1 |
 | 2 | 1 | 1.5 | 2.5 |
 | 3 | 2.5 | 1 + 2.5/3 ≈ 1.8333 | 4.3333 |
 | 4 | 4.3333 | 1 + 4.3333/4 ≈ 2.0833 | 6.4166 |

 それで`E(4) ≈ 2.0833`。 

これは、各層が個々の遷移ではなく、蓄積された期待にのみ依存していることを示しています。

 ## 特殊なケース

 のために`n = 0`、DP は返さなければなりません`0`負のインデックスのプレフィックス合計にアクセスしようとせずに。 初期化`E(0) = 0`この場合、再発を調整する必要がないことが保証されます。 

のために`n = 1`、トランジションは常に次のようになります。`0`したがって、必要な操作は 1 つだけです。 DP では、これは次のように計算されます。`E(1) = 1 + S(0)/1 = 1`、正しさを確認します。 

値が大きい場合、安定性は正しい順序付けに依存します。`E(m)`前に計算されます`S(m-1)`が完全に構築されると、後の状態が以前の計算を汚染してしまいます。 順方向のみの構築ではこれを完全に回避し、各期待値が正確に 1 回確定されるようにします。
