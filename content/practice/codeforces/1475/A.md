 ## 解決策
 ## 問題の理解

 指定された整数かどうかを判断するように求められます。$n$1 より大きい奇数の約数を持ちます。 言い換えれば、奇数が存在するかどうかを知りたいのです。$x > 1$それは分ける$n$均等に。 もし$n$がそのような数で割り切れる場合、答えは「YES」です。 それ以外の場合は「いいえ」です。 

入力は複数のテスト ケースで構成され、それぞれが 1 つの整数を持ちます。$n$。 可能な限り最大の$n$到達できる$10^{14}$これは、以下のすべての数値を試す単純なアプローチの限界をはるかに超えています。$n$潜在的な約数として。 までの可能性があることを考えると、$10^4$テスト ケース、線形なアプローチ$n$が遅すぎるでしょう。 クエリごとに対数時間または定数時間で動作するものが必要です。 

エッジケースには、小さな数や 2 のべき乗が含まれます。 たとえば、次の場合$n = 2$、1 より大きい奇数の約数はないため、答えは「NO」でなければなりません。 もし$n = 3$、それ自体は 1 より大きい奇数であるため、答えは「YES」です。 2 のべき乗の場合、次のようになります。$n = 16$、すべての約数も 2 のべき乗であるため、偶数になります。 これらは「NO」を返すはずです。 2 のべき乗を奇数の約数を持つものと誤認することは、単純な実装ではよくある間違いです。 

## アプローチ

 ブルートフォースアプローチは、3 から 3 までの各整数をチェックすることです。$n$(偶数をスキップして) 割れるかどうかを確認します$n$。 これは、数値が除算される場合に機能するため、$n$、奇数の約数です。 ただし、最悪のケースが発生します$n = 10^{14}$、大まかに必要$5 \cdot 10^{13}$分割チェックは完全に不可能です。 これは明らかに制限時間を超えています。 

重要な観察は、整数が$n$2 の累乗である場合に限り、1 を超える奇数の約数はありません。 2 の累乗は次の形式の数値です。$2^k$、それらの約数はすべて 2 のべき乗であり、1 を除いてすべて偶数であることを意味します。その他の数$n$それ自体が奇数の因数を持つか、または 2 のべき乗を乗じた奇数に因数分解することができます。 この洞察により、問題は以下のことを確認することになります。$n$は 2 の累乗です。 

数値が 2 の累乗であるかどうかを確認することは、ビットごとのトリックを使用して効率的に行うことができます。 正の整数の場合$n$、 もし$n \& (n-1) == 0$、 それから$n$は 2 の累乗です。 これが機能するのは、2 のべき乗には 2 進数で 1 つのビットが設定されているためです。 それ以外の場合、数値に 1 より大きい奇数の因数があるため、「YES」を返します。

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る$t$。 これは、連続して処理する必要がある数値の数を定義します。 
2. 各テスト ケースについて、整数を読み取ります。$n$。 かどうかを検討します。$n$1 より大きい奇数の約数を持ちます。 
3. ビット単位の 2 のべき乗テストを適用します。$n \& (n-1)$。 これがゼロに等しい場合、$n$は 2 の累乗であり、1 より大きい奇数の約数がないため、「NO」を出力します。 
4. もし$n \& (n-1)$がゼロでない場合は、「YES」を出力します。 これは次のことを示しています$n$は純粋な 2 の累乗ではありません。これは、1 より大きい奇数の約数があることを意味します。 

これが機能する理由: 自明でないすべての約数が偶数となる整数は 2 の累乗だけです。 バイナリ表現をチェックすることにより、ビット単位のトリックによりこのプロパティが直接識別されます。 チェックに失敗した数値には奇数の因数が含まれている必要があり、これにより 1 より大きい奇数の約数が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    t = int(input())
    for _ in range(t):
        n = int(input())
        if n & (n - 1) == 0:
            print("NO")
        else:
            print("YES")

if __name__ == "__main__":
    main()
```コードは、次を使用してすべての入力を効率的に読み取ることから始まります。`sys.stdin.readline`。 各テスト ケースをループし、ビットごとのチェックを適用します。 使用する`n & (n-1)`重要です。 次のような素朴なモジュロアプローチ`n % 2`または、除数を反復すると時間制約を満たせなくなります。 Python の整数は任意精度であるため、コードは非常に大きな数値を正しく処理します。

 ## 特殊なケース

 このアルゴリズムは、可能な限り最小の数値を正しく処理します。 のために$n = 2$、ビット単位のテストではゼロが返され、「NO」が生成されます。 奇数の場合は次のようになります$n = 3$または$n = 9$の場合、テストは失敗し、1 より大きい奇数の約数が存在することが正しく識別されます。 2 のべき乗の場合、次のような非常に大きなものでも、$n = 2^{40}$、チェックはループや再帰を行わずにスケーリングされ、速度と正確性の両方が保証されます。 ビットごとの演算では 2 の累乗の 1 ビット パターンが正確に検出されるため、off-by-1 エラーは存在しません。
