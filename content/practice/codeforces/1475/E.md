 ## 解決策
 ## 問題の理解

 マーシャはブロガーのリストを持っており、それぞれに一定数のフォロワーがおり、正確に雇用したいと考えています。`k`視聴者数の合計を最大化するために、 入力により得られるのは、`n`、ブロガーの合計、`k`、雇用できる数、および配列`a`長さの`n`各ブロガーのフォロワー数。 各テスト ケースの出力は、選択する方法の数です。`k`ブロガーは、フォロワーの合計が可能な限り多くなるようにします。 少なくとも 1 人のブロガーによって異なる場合、2 つの選択は異なるものとみなされます。 

制約を考慮すると、`n`1000までとすべての合計`n`テスト ケース全体の境界も 1000 であるため、時間計算量が約 1000 を超えるソリューションであることがわかります。`O(n log n)`テストケースごとに簡単に適合します。 組み合わせカウントにも注意する必要があります。`k`と同じ大きさにすることができます`n`また、カウントは繰り返される可能性があるため、単純なカウントでは 1 つずつ違う間違いが発生しやすくなります。 

複数のブロガーのフォロワー数が同じ場合、微妙なエッジケースが発生します。 たとえば、すべてのブロガーに同じフォロワーがいて、`k=2`、すべてのペアが有効です。 ただ単に取るだけの素朴なアプローチ`k`頻度を考慮せずに最大数を指定すると、可能性が過小評価されてしまいます。 

## アプローチ

 ブルートフォースアプローチでは、すべてが列挙されます。`n choose k`サブセットを作成し、そのフォロワーを合計し、最大合計に達するものをカウントします。 これは、すべてのサブセットをチェックすることで正確さが保証されるため機能しますが、たとえ`n=30`サブセットの数が指数関数的に増加するためです。 と`n`1000までは無理です。 

重要な観察は、単純にフォロワーの総数が最大化されるということです。`k`フォロワー数が最も多いブロガー。 配列を降順に並べ替えると、最大合計がすぐに特定されます。 複雑さの軽減は、かつては最大規模だった`k`フォロワーは既知ですが、それらを選択する方法の数は、これらの上位の値の最小値の頻度のみに依存します。`k`配列全体のフォロワー。 具体的には、`k`- 番目に多いフォロワー数が表示されます`c`配列全体の回数と`m`トップ以内の回数`k`、次にトップを選択する方法の数`k`ブロガーは`C(c, m)`、二項係数。 

ソートは`O(n log n)`とコンピューティング`C(c, m)`で行うことができます`O(k)`事前に計算された階乗モジュロを使用`10^9+7`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n は k * k を選択します) | O(k) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る`t`。 
2. 各テスト ケースについて、次の内容を読んでください。`n`そして`k`、次にフォロワー配列を読み取ります`a`。 
3. 並べ替え`a`降順で。 最初`k`要素は可能な最大の合計を与えるようになりました。 
4. 特定する`x`, 上位の中でフォロワー数が最も少ない`k`ブロガー。 
5. カウント`m`、の出現数`x`上部内で`k`。 
6. カウント`c`、の出現の合計数`x`配列全体で。 
7. 二項係数を計算する`C(c, m)`モジュロ`10^9+7`有効な選択の数を取得します。 
8. 各テスト ケースの結果を出力します。 

このアルゴリズムが機能するのは、最適なセットには より大きい要素がすべて含まれなければならないという不変条件があるためです。`x`そしてまさに`m`に等しい要素のうち`x`。 これにより、合計が最大となり、すべての異なる組み合わせが正しくカウントされることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
MOD = 10**9 + 7

# precompute factorials and inverse factorials
N = 1000
fact = [1] * (N+1)
invfact = [1] * (N+1)

for i in range(2, N+1):
    fact[i] = fact[i-1] * i % MOD

def modinv(x):
    return pow(x, MOD-2, MOD)

for i in range(2, N+1):
    invfact[i] = modinv(fact[i])

def comb(n, k):
    if k < 0 or k > n:
        return 0
    return fact[n] * invfact[k] % MOD * invfact[n-k] % MOD

t = int(input())
for _ in range(t):
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    a.sort(reverse=True)
    x = a[k-1]
    m = a[:k].count(x)
    c = a.count(x)
    print(comb(c, m))
```階乗と逆モジュラーの事前計算により、任意の二項係数を効率的に計算できます。 並べ替えにより、最大の要素が確実に選択されます。 一番上の最小要素の出現を数える`k`合計は正しい組み合わせ計算を保証します。 A common mistake is miscounting`m`または`c`、またはモジュロ演算を忘れています。 

## 実用的な例

 サンプル 1:```
n=4, k=3, a=[1,3,1,2]
```| ステップ | 配列 a | トップk | × | メートル | c | 櫛(c,m) |
 | --- | --- | --- | --- | --- | --- | --- |
 | 1 | [1,3,1,2] | [3,2,1] | 1 | 1 | 2 | 2 |

 これは、上位 3 つの要素の最小値が 1 であることを示しています。これは上位 3 つに 1 回、全体で 2 回発生します。 選択するには2つの方法があります`1`利用可能な 2 つのうちの 1 つで、期待される出力と一致します。 

サンプル 2:```
n=4, k=2, a=[1,1,1,1]
```| ステップ | 配列 a | トップk | × | メートル | c | 櫛(c,m) |
 | --- | --- | --- | --- | --- | --- | --- |
 | 1 | [1,1,1,1] | [1,1] | 1 | 2 | 4 | 6 |

 すべての値は同じです。 上位 2 つを選択するには 4 つの 2 つの方法があり、結果は 6 つになります。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | テスト ケースごとに O(n log n) | ソートが優先され、出現回数のカウントは O(n) |
 | スペース | O(n) | 配列と階乗を 1000 まで保存 |

## テストケース```python
import sys, io

def run(inp):
    sys.stdin = io.StringIO(inp)
    MOD = 10**9 + 7
    N = 1000
    fact = [1]*(N+1)
    invfact = [1]*(N+1)
    for i in range(2,N+1):
        fact[i] = fact[i-1]*i % MOD
    def modinv(x):
        return pow(x,MOD-2,MOD)
    for i in range(2,N+1):
        invfact[i] = modinv(fact[i])
    def comb(n,k):
        if k<0 or k>n: return 0
        return fact[n]*invfact[k]%MOD*invfact[n-k]%MOD
    t=int(input())
    res=[]
    for _ in range(t):
        n,k=map(int,input().split())
        a=list(map(int,input().split()))
        a.sort(reverse=True)
        x=a[k-1]
        m=a[:k].count(x)
        c=a.count(x)
        res.append(str(comb(c,m)))
    return "\n".join(res)

# Provided samples
assert run("3\n4 3\n1 3 1 2\n4 2\n1 1 1 1\n2 1\n1 2\n") == "2\n6\n1", "sample 1"

# Custom cases
assert run("1\n5 3\n5 5 5 5 5\n") == "10", "all equal"
assert run("1\n3 2\n1 2 3\n") == "1", "simple increasing"
assert run("1\n6 3\n1 2 2 3 3 3\n") == "1", "multiple repeats, largest freq"
assert run("1\n6 3\n3 3 2 2 1 1\n") == "1", "sorted descending with ties"

 | 3 2 1 2 3 | 1 | 単純な増加、一意の最大要素 |

| 6 3 3 3 2 2 1 1 | 1 | 降順で並べ替えられ、タイは正しく処理されました。
