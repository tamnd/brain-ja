 ## 解決策
 ## 問題の理解

 方程式は数値を結び付けます`a`変数付き`x`減算とビットごとの XOR という 2 つの演算を使用します。 与えられた各値に対して、`a`、負ではない整数をいくつ数えるように求められます。`x`アイデンティティを満たす`a - (a XOR x) - x = 0`。 

入力は、次のいくつかの独立した値で構成されます。`a`。 それぞれについて、選択肢がいくつあるかを決定する必要があります。`x`式を正確にゼロに評価させます。 

重要な制約は、`a`直下まで大きくすることができます`2^30`これは、すべての数値が 30 バイナリ ビット以内に収まることを意味します。 これは、考えられるすべてのソリューションを反復するソリューションは、`x`まで`a`最悪のシナリオでは、テスト ケースごとに最大 10 億回の操作が必要となるため、これは実行不可能です。 テスト ケースごとに 30 ビットの数値すべてを反復処理する場合でも、ビットごとのシミュレーションを大量に実行すると、時間がかかりすぎます。 

素朴なアプローチではあらゆる可能性を試すことになる`x`そして式を直接評価します。 これは論理的には正しいですが、検索スペースのビット数が指数関数的であるため、計算的には失敗します。 

エッジケースは次の場合に発生します。`a`設定ビットがほとんどないか、バイナリのビットで完全に埋められている場合。 たとえば、次のようなとき`a = 0`、唯一の有効な選択肢は`x = 0`。 いつ`a = 2`、バイナリ`10`、有効な選択肢は 2 つあります。`x = 0`そして`x = 2`。 いつ`a = 2^30 - 1`、すべてのビットは 1 であり、有効なビットの数は`x`非常に大きくなり、具体的にはすべて`2^30`サブマスク。 正しいソリューションは、候補を列挙することなく、これらの極端な問題に対処する必要があります。 

## アプローチ

 ブルートフォース戦略は、定義から直接問題を扱います。 それぞれについて`a`、私たちは可能な限りのことを試みます`x`から`0`上限が大きいかどうかを確認します。`a - (a XOR x) - x`ゼロに等しい。 これが機能するのは、ステートメントに正確に従っており、XOR の計算が簡単であるためです。 ただし、以来、`a`最大 30 ビットを含めることができ、可能なスペースは`x`値は最大です`2^30`。 枝刈りを行ったとしても、これは依然として実行可能な限界をはるかに超えています。 

重要な観察は、標準の XOR ID を使用して式を書き換えることから得られます。`a + x = (a XOR x) + 2 * (a AND x)`。 

元の式を再整理することで、XOR を完全に削除し、条件をビットの重複という観点から表現できます。`a`そして`x`。 単純化すると、次の場合にのみ方程式が成り立つことがわかります。`x`にはビットが含まれていません`a`ゼロビットがあります。 言い換えれば、設定されたすべてのビットは、`x`にも設定する必要があります`a`。 

これはつまり`x`は単に次のサブマスクです`a`。 設定されている各ビット`a`独立して選択することも、選択しないこともできます`x`、すべてのゼロビットが`a`力`x`その位置にもゼロが入ります。 もし`a`もっている`k`ビットを設定すると、正確に`2^k`～に対する有効な選択肢`x`。 

これにより、問題は、算術式に対する制約のチェックから、ビット サブセットに対する単純な組み合わせカウントの問題に変換されます。

 | ブルートフォース | テストごとに O(2^30) | お(1) | 遅すぎる |
 | 最適 | テストごとの O(log a) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. の各値を読み取ります。`a`独立して。 各テスト ケースは分離されているため、状態は共有されません。 
2. のバイナリ表現に設定されているビット数を数えます。`a`。 この値は、形成時に独立した選択が可能な位置の数を表します。`x`。 
3. 有効な数を計算します。`x`として`2^(popcount(a))`。 設定された各ビットは二項決定に寄与します。`x`か否か。 
4. 各テストケースの計算値を出力します。 

### なぜ効果があるのか

 この方程式は、次のすべてのビットを強制します。`x`の設定ビット内に含まれるようにする`a`。 単純化後はキャリー相互作用やクロスビット依存関係は残りません。 設定された各ビット`a`XOR と減算の相互作用は、ビット単位の ID を使用して書き換えられると正確にキャンセルされるため、独立して動作します。 この独立性により、設定ビットのすべてのサブセットが`a`正確に 1 つの有効な値に対応します`x`であり、無効な構成は方程式を満たすことができません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        a = int(input())
        # number of valid x is 2^(number of set bits in a)
        print(1 << a.bit_count())

if __name__ == "__main__":
    solve()
```実装は Python の組み込みに依存します`bit_count()`これにより、設定されたビット数が効率的に直接計算されます。 最終的な答えは、定数時間で 2 のべき乗を計算する左シフトを使用して取得されます。 

よくある落とし穴は、方程式を直接シミュレートしようとすることです。 このアプローチでは、不必要な算術演算が複雑になり、ビット表現に隠された単純なサブセット構造がわかりにくくなります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        a = int(input())
        out.append(str(1 << a.bit_count()))

 ## 特殊なケース

 いつ`a = 0`、バイナリ表現にはビットが設定されていません。 アルゴリズムは計算します`popcount(a) = 0`、結果は次のようになります`2^0 = 1`。 これは、次の事実と一致します。`x = 0`無効なビットの導入を回避できます。 

いつ`a`は次のような 2 のべき乗です`8`、1 つのビットだけが設定されます。 アルゴリズムの結果は、`2^1 = 2`、空のサブセットまたはその単一ビットのいずれかを選択することに正確に対応します。 

いつ`a = 2^30 - 1`、すべてのビットが設定されます。 アルゴリズムは計算します`2^30`、有効なサブマスクの最大可能数と一致します。 Python の整数は 2 の大きな累乗を自然に処理するため、オーバーフローの問題は発生しません。
