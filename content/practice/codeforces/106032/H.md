 ## 解決策
 ## 問題の理解

 私たちは、非常に構造化された有向グラフ上でプレイされるゲームを与えられています。 任意のグラフの代わりに、頂点がレイヤーに配置されます。 各レイヤーはノードの列であり、レイヤー内では左から右へのみ移動できます。 レイヤー内の任意のノードから、次のレイヤーの最初のノードにジャンプすることもできます。 

ゲームは最初のレイヤーの最初のノードから始まり、2 人のプレイヤーが交互に動きます。 移動とは、単に現在のノードから発信エッジを選択し、それに沿ってトークンを移動することです。 トークンを最後のレイヤーの最後のノードに移動したプレーヤーが即座に勝ちます。 

したがって、ゲーム全体は、完璧な情報を備えた DAG 上の決定的な 2 人用ゲームです。 重要な状態は現在のノードだけであり、各ノードからの一連の動きはレイヤーの構造によって固定されます。 

入力サイズは大きく、最大 10^5 レイヤーであり、各レイヤーのサイズは 10^18 まで大きくなる可能性があります。 これにより、グラフの構築やノードのシミュレーションが即座に除外されます。 ノードの総数は天文学的に大きくなる可能性があるため、すべてのノードを反復処理することさえ不可能です。 解決策は、個々のノードではなく、レイヤー サイズの構造のみに依存する必要があります。 

ゲームがノードの総数に依存すると仮定すると、単純な推論による微妙な失敗例が現れます。 たとえば、最後のレイヤーを除くすべてのレイヤーのサイズが 1 である場合、単純なアプローチでは、答えはチェーンに沿った動きのパリティのみに依存すると結論付ける可能性があります。 ただし、単一レイヤーをサイズ 1 からサイズ 2 に変更すると、ノード数はわずかしか変化しませんが、分岐オプションが完全に変わります。 たとえば:

 入力

 n = 3

 a = [1, 1000000000000000000, 1]

 単純な「手数を数える」という考えでは、パスは依然として本質的に直線的であると思われるかもしれませんが、実際には、第 2 層は、最適なプレイの結果を変える巨大な水平方向の逃げ場を与えます。 

もう 1 つの隠れたエッジ ケースは、レイヤーのサイズが 1 の場合です。これらのレイヤーは強制トランジションのように動作しますが、大きなレイヤーと混合すると、強制セグメントと自由選択セグメントが交互に生成されます。 すべてのレイヤーを均一に扱うソリューションは、ここでは失敗します。 

## アプローチ

 このゲームについて考える強引な方法は、グラフを明示的に構築し、標準の勝敗状態 DP を実行することです。 各ノードから、相手を負け状態に追い込む手が存在するかどうかを確認します。 これが機能するのは、グラフが非循環であるため、勝ち/負けの状態を最後から逆方向に計算できるためです。 

問題は、グラフのサイズが使用できないことです。 遷移のみを考慮した場合でも、各レイヤーには最大 10^18 のノードが含まれます。 ブルートフォース手法では O(合計ノード + エッジ) が必要になりますが、これを表現することさえ不可能です。 

重要な観察は、レイヤー内では動きが完全に決定的であるということです。どのノードからでもそのレイヤーの終わりまで直接歩くことができます。 つまり、レイヤー内のすべてのノードは、インデックスを除いて同一の出力構造を持つ単一のチェーンに沿った位置のように動作します。 唯一意味のある「選択ポイント」は、プレイヤーがレイヤーの横断を早めに中止するか、それとも飛び降りる前に最後まで継続するかです。 

これにより、各レイヤーが、レイヤーの最初のノードにいるのか、レイヤー内のどこかにいるのかによって特徴づけられる単一のゲーム状態に折りたたまれます。 ただし、すべてのノードは次のレイヤーの最初のノードに接続するため、レイヤー内のどの位置でも、すでに消費された移動数を除いて、そのレイヤーの終わりと同じ将来のオプションが事実上与えられます。 

これにより、ゲーム全体がレイヤー上のパリティ スタイルの決定に集約されます。重要なのは、プレイヤーが直ちに垂直方向のトランジションを取ることを強制されるか、それともターン パリティを反転するためにレイヤー内で余分な動きを「消費」できるかということです。 構造を単純化した後、各レイヤーは単一の値に寄与します。その長さが奇数であるか偶数であるかによって、そのレイヤーに入ると現在のプレイヤーのアドバンテージが維持されるか反転されるかが決まります。

したがって、ゲームは、層パリティに対する単純な XOR のような累積を計算することになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース グラフ DP | O(総ノード数) | O(総ノード数) | 遅すぎる |
 | レイヤパリティ削減 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各レイヤーを強制的な水平移動のセグメントとして扱い、その後に次のレイヤーへの強制的なジャンプを行います。 プレイヤーは構造をスキップできないため、最終的にはすべての決定は、コントロールを渡す前に消費される移動数に基づいて行われます。 
2. レイヤー内で、プレーヤーが単一の有向チェーンに沿って交互に移動することを観察します。 レイヤーの長さが偶数の場合、レイヤーに入ると、退出するときに誰の順番になるかが保持されます。 奇数の長さの場合、終了後にターンが反転します。 
3. 各層をパリティトランスとしてモデル化します。 最初のプレイヤーがレイヤー 1 で移動することから始めます。 
4. 1 から n までのレイヤーを反復処理し、現在のレイヤーに入るときにまだ最初のプレイヤーのターンであるかどうかを表すブール値を維持します。 現在のレイヤーの長さが奇数の場合、このブール値を反転します。 
5. すべての層を処理した後、最終層の最後のノードに到着したプレーヤーが開始したプレーヤーと同じであるかどうかを判断します。 パリティが最初のプレイヤーが最終的な動きをしたことを示している場合、そのプレイヤーが勝ちます。 それ以外の場合は、2 番目のプレーヤーが勝ちます。 

### なぜ効果があるのか

 不変なのは、いずれかのレイヤーを終了した後、ゲームの残りの部分で重要となる唯一の情報は、どのプレイヤーのターンであるかということです。 層内のすべてのノードが同じ次層エントリにつながるため、層内の内部位置は将来の分岐には影響しません。 レイヤーの唯一の影響は、次の決定境界に到達するまでに消費される手数です。これはまさにそのパリティです。 ゲームはレイヤー間の決定論的な移行を伴う単一パス上の純粋な交互の動きであるため、各レイヤーをパリティ フリップに縮小することで完全なゲーム状態が保存されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        # True means first player's turn at current layer entry
        first_turn = True

        for x in a:
            if x % 2 == 1:
                first_turn = not first_turn

        out.append("First" if first_turn else "Second")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装では、各層が 1 つのパリティ チェックに圧縮されます。 追跡される唯一の状態は、レイヤーを通過した後にターンが反転するかどうかです。 ノードやエッジをモデル化する必要はありません。 

ここでよくある間違いは、レイヤー内の動きを段階的にシミュレートしようとすることですが、単一レイヤーのサイズが最大 10^18 であることを考えると、これは不可能です。 もう 1 つの間違いは、層間の移行は常に強制されるため、唯一制御可能な要素はパスの選択ではなくパリティであることを忘れていることです。 

## 実用的な例

 ### 例 1

 入力:

 n = 3

 a = [4, 3, 2]

 各レイヤーの後に現在のプレーヤーが変更されるかどうかを追跡します。 

| レイヤー | サイズ | パリティ | レイヤ後の現在のターン |
 | --- | --- | --- | --- |
 | 1 | 4 | 偶数 | 最初 |
 | 2 | 3 | 奇数 | 2番目 |
 | 3 | 2 | 偶数 | 2番目 |

 最後の動きは 2 番目のプレイヤーのターンでレイヤー 3 に着地するため、2 番目のプレイヤーが勝ちます。 

このトレースは、パリティのみが重要であり、中間ノード構造は無関係であることを示しています。 

### 例 2

 入力:

 n = 2

 a = [1, 1]

 | レイヤー | サイズ | パリティ | レイヤ後の現在のターン |
 | --- | --- | --- | --- |
 | 1 | 1 | 奇数 | 2番目 |
 | 2 | 1 | 奇数 | 最初 |

 最終状態ではコントロールが First プレイヤーに返されるため、First が勝ちます。 

この例では、複数の奇数レイヤーが互いのターン フリップをキャンセルできることを強調しています。

 ## 特殊なケース

 単一レイヤーのゲームが最も直接的なケースです。レイヤーのサイズが奇数の場合、最初のプレーヤーは唯一の動きの後すぐにコントロールを失うため、結果は純粋にパリティ ロジックに依存します。 アルゴリズムは、奇数の値に遭遇したときに 1 回の反転を適用するため、これを処理します。 

すべてのレイヤーのサイズが 1 の場合、すべてのレイヤーがターンを反転します。 n 層後の勝者は、n が偶数か奇数かによって決まります。 ループは、特別なケースを使用せずに、これらのフリップを正しく蓄積します。 

すべてのレイヤーが均等な場合、反転は発生せず、最初のプレーヤーがチェーン全体を通じてコン​​トロールを保持します。 ブール値は決して変更されないため、アルゴリズムは「First」を正しく出力します。
