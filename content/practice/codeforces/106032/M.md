 ## 解決策
 ## 問題の理解

 アリスとボブという 2 人のプレイヤーが与えられ、それぞれが時間をかけて文字列を構築します。 どちらも単一の文字で構成される同じ単純な文字列から始まります`"a"`。 

次に、一連の操作を受け取ります。 各操作はアリスまたはボブのいずれかをターゲットにし、指定された文字列の複数のコピーを現在の文字列に追加します。 各操作の後、各プレイヤーは、現在持っている文字の辞書編集上可能な限り最小の配置を作成することを目的として、文字列全体の文字を好きな方法で自由に並べ替えることができます。 

並べ替えには制限がなく、文字数だけが問題となるため、文字列の実際の構造は無関係になります。 各操作の後に重要なのは、各プレイヤーが各キャラクターをどれだけ蓄積したかです。 

両方のプレイヤーが順序を個別に最適化した後、結果の文字列を辞書編集的に比較し、どちらが小さいか、または等しいかどうかを出力します。 

重要な意味は、すべての文字列が常にプレーヤーが所有するソートされた文字のマルチセットであるということです。 したがって、問題は、アリスとボブの手紙の頻度カウントを維持し、各更新後に 2 つのマルチセットを比較することに帰着します。 

入力サイズを考慮すると、この削減は不可欠です。 各操作は、最大 200,000 回繰り返される最大 400,000 の長さの文字列を追加できますが、グローバルでは、すべての操作にわたる長さの合計は、テスト ケースごとに 400,000 に制限されます。 この制約は重要な観察です。k は大きくても構いませんが、必要なのはカウントを乗算するだけであり、処理される個別の文字の合計は入力サイズにおいて線形です。 

繰り返される文字列を明示的に構築する単純な解釈は、単一の操作でも膨大な長さに拡張される可能性があるため、すぐに失敗します。 

単純なソリューションを壊すことが多いエッジ ケースは、同じ操作で大きな文字列を何度も繰り返し追加する場合です。 たとえば、`"zz"`100,000 回繰り返しても、200,000 文字の文字列を明示的に構築することはできません。 そうすると、タイムアウトになったり、メモリが使い果たされたりする可能性があります。 

もう 1 つの微妙なケースは、アリスとボブが同一の一連の操作を受け取る場合です。 正しい出力は常に次のようになります。`"Tie"`あらゆる段階で。 文字数ではなく生の文字列を誤って比較するソリューションでは、両方が常に最後にソートされているにもかかわらず、異なる内部順序を誤って区別する可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、文字通り問題をシミュレートしようとします。 操作ごとに、を繰り返して文字列を展開します。`x`その通り`k`を回して、ターゲットプレイヤーの文字列に追加します。 更新のたびに、文字列全体をソートし、アリスとボブを辞書順に比較します。 

これは、文字列を構築し、最適に並べ替えて、比較するというルールに正確に従っているため、原則的には正しいです。 ただし、ソートのコストは文字列の合計の長さに応じて増加します。 多くの操作を行うと、文字列は追加されたすべての文字の合計に比例するサイズに増加する可能性があります。 最大 400,000 文字でソートが繰り返される場合、最悪の場合、総コストは操作全体でおよそ O(n² log n) となり、制限をはるかに超えています。 

重要な洞察は、各操作後のソートが不要であるということです。 常に任意に並べ替えることができるため、各プレーヤーの文字列はサイズ 26 の周波数配列によって完全に決定されます。`x`繰り返された`k`単に足すだけです`k * count_of_each_character_in_x`プレーヤーの周波数ベクトルに変換します。 アリスとボブの比較は、文字列をソートしたかのように、2 つの長さ 26 のベクトルを辞書編集的に比較することになります。 

これにより、各操作が文字数を数える作業に減ります。`x`1 回とスケーリング`k`、次に固定サイズの配列を更新します。 辞書編集的な比較も 26 文字にわたる定数時間です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (ビルド + 文字列のソート) | O(クエリごとのログの合計長) | O(全長) | 遅すぎる |
 | 操作ごとの頻度カウント | テスト ケースあたり O(26 · q) | お(26) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 2 つの配列を初期化する`A[26]`そして`B[26]`アリスとボブの各文字の数を表します。 どちらも次から始まります`A['a']=1`そして`B['a']=1`、その他はすべてゼロ。 これにより、初期文字列が明示的に保存されずにエンコードされます。 
2. 各操作について、次の内容を読み取ります。`(op, x, k)`。 
3. ローカル周波数配列を計算する`cnt[26]`文字列用`x`。 これには 1 回のスキャンが必要です`x`、各文字の出現を数えます。 
4. 乗算間隔`cnt[c]`による`k`。 これは文字列の繰り返しを表します`k`構築せずに何度も。 
5. 操作がアリスをターゲットとする場合は、次を追加します`cnt`の中へ`A`。 それ以外の場合は追加します`B`。 各更新は文字数の直接の蓄積です。 
6. この操作後の出力を決定するには、以下を比較します。`A`そして`B`辞書順に`'a'`に`'z'`。 最初に異なるインデックスが勝者を決定します。カウントが小さいほど、プレイヤーがソートした文字列が辞書編集的に小さいことを意味します。 
7. すべてのカウントが一致した場合、出力します。`"Tie"`。 

これが機能する理由は、各操作の後、各プレイヤーの文字列が常に文字の非降順でソートされるという不変条件に依存します。 並べ替えには制限がないため、どのような並べ替えも同じ正規の並べ替えられたマルチセットになります。 したがって、プレーヤー間の辞書編集的な比較は、プレーヤーの周波数ベクトルをアルファベット順に比較することに相当します。 文字列の隠された構造は重要ではありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def cmp(a, b):
    for i in range(26):
        if a[i] != b[i]:
            return "Alice" if a[i] < b[i] else "Bob"
    return "Tie"

def main():
    T = int(input())
    for _ in range(T):
        q = int(input())
        A = [0] * 26
        B = [0] * 26

        A[0] = 1
        B[0] = 1

        for _ in range(q):
            parts = input().split()
            op = int(parts[0])
            x = parts[1]
            k = int(parts[2])

            cnt = [0] * 26
            for ch in x:
                cnt[ord(ch) - 97] += 1

            for i in range(26):
                cnt[i] *= k

            if op == 1:
                for i in range(26):
                    A[i] += cnt[i]
            else:
                for i in range(26):
                    B[i] += cnt[i]

            print(cmp(A, B))

if __name__ == "__main__":
    main()
```実装上の重要な選択は、展開された文字列の構築を避けることです。 乗算ステップは、そうでなければ k 個の連結となるものを置き換えます。 もう 1 つの微妙な点は、周波数配列をサイズ 26 に固定することです。これにより、文字列の合計の増加に関係なく定数時間の比較が保証されます。 

## 実用的な例

 単純化したシナリオを考えてみましょう。 

入力:```
1
3
1 aa 2
2 ab 1
2 a 3
```アリスから始めます =`{a:1}`、ボブ =`{a:1}`。 

最初の手術の後、アリスはこう付け加えます。`"aa"`2回、貢献`{a:4}`これまでの合計`{a:5}`。 

2回目の手術の後、ボブはこう付け加えた。`"ab"`1 回なので、ボブは次のようになります`{a:2, b:1}`。 

3回目の手術の後、ボブはこう付け加えた。`"a"`3 回なので、ボブは次のようになります。`{a:5, b:1}`。 

各ステップで辞書順に比較します。 

| ステップ | アリスA | ボブB | 結果 |
 | --- | --- | --- | --- |
 | 初期化 | :1 | :1 | ネクタイ |
 | 1 | :5 | :1 | ボブ |
 | 2 | :5 | a:2、b:1 | アリス |
 | 3 | :5 | a:5、b:1 | アリス |

 このトレースは、辞書編集上の比較が最初の異なる文字に依存していることを示しています。`'a'`それから`'b'`、元の文字列の順序には関係ありません。 

次に、構造を強調した 2 番目の例を考えてみましょう。 

入力:```
1
2
1 cba 1
2 abc 1
```両方の操作の後:

 アリス:`{a:1, b:1, c:1}`ボブ：`{a:1, b:1, c:1}`入力が異なっていても、並べ替えによって構造が完全に削除されるため、結果は常に同点になります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    T = int(input())
    out = []

    for _ in range(T):
        q = int(input())
        A = [0]*26
        B = [0]*26
        A[0] = B[0] = 1

        def cmp(a,b):
            for i in range(26):
                if a[i]!=b[i]:
                    return "Alice" if a[i] < b[i] else "Bob"
            return "Tie"

        for _ in range(q):
            op,x,k = input().split()
            op = int(op); k = int(k)
            cnt = [0]*26
            for ch in x:
                cnt[ord(ch)-97]+=1
            for i in range(26):
                cnt[i]*=k
            if op==1:
                for i in range(26): A[i]+=cnt[i]
            else:
                for i in range(26): B[i]+=cnt[i]
            out.append(cmp(A,B))

    return "\n".join(out)

# custom cases
assert run("1\n1\n1 a 1\n") == "Tie", "single update"
assert run("1\n2\n1 z 1\n2 a 1\n") == "Bob\nBob", "lexicographic dominance"
assert run("1\n2\n1 abc 2\n2 acb 2\n") == "Tie\nTie", "reordering symmetry"
assert run("1\n1\n1 zzz 100\n") == "Bob", "large repetition handled"

 | --- | --- | --- |

 | z 対 a | ボブ | 辞書編集上の順序 |
 | 並べ替えられた文字列 | ネクタイ | 無関係性を並べ替える |

 ## 特殊なケース

 最初のエッジケースは、両方のプレーヤーがすべての操作を通じて同一のままである場合です。 アルゴリズムは同一の周波数配列を維持するため、比較ループは常に差異を検出することなく終了し、正しく出力されます。`"Tie"`毎回。 

もう 1 つのケースは、大量の繰り返しです。たとえば、400,000 文字の文字列に大きな乗数を追加する場合です。 実装では展開された文字列が構築されることはないため、メモリ使用量は一定のままです。 乗算ステップでは、Python ではオーバーフローを考慮することなく、カウントが正しくスケーリングされます。 

最後のケースは、後期のアルファベット文字のみで違いが発生する場合です。 からの比較スキャンなので、`'a'`に`'z'`、以前の等しい接頭辞は安全にスキップされ、辞書編集順の要求どおりに最初の異なる文字によって結果が決まります。
