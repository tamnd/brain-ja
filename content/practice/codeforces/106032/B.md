 ## 解決策
 ## 問題の理解

 私たちには、ツリー構造で接続されたコンピューターのシステムが与えられています。 各コンピュータには、オンまたはオフの初期状態があります。 実行できる操作は 1 つだけです。コンピュータを 1 台選択し、その状態を反転し、それに直接接続されているすべてのコンピュータの状態も反転します。 

反転とは、0 を 1 に、1 を 0 に変更することを意味します。問題は、この操作を何回か適用して、すべてのコンピューターが同時に「オン」状態になるかどうかです。 

入力は複数の独立したテスト ケースで構成されます。 テスト ケースごとに、コンピューターの数、コンピューターの初期バイナリ状態、およびコンピューター間の接続を表すツリーのエッジが与えられます。 出力は、ターゲット構成が達成可能かどうかを示す単純な「はい」または「いいえ」です。 

重要な制約は、すべてのテスト ケースにわたるノードの総数が最大 200,000 程度まで大きくなる可能性があることです。 これにより、すべての一連の操作を試したり、システムの状態を完全に検索したりするなど、テスト ケースごとにコストのかかる再計算を行うアプローチは直ちに除外されます。 ここでの状態空間のサイズは 2^N であり、小さな N であっても完全に実行不可能です。 

微妙な障害モードは、これが一度に 1 つのノードを繰り返し修正するローカルの貪欲なプロセスであると想定することで発生します。 たとえば、状態 0 1 0 を持つ 3 つのノードのラインを考えてみましょう。単純な戦略では、ノード 2 を反転して最初に中央を修正しようとする可能性がありますが、それは同時に隣接ノードに影響を与え、以前のエラーが再導入される可能性があります。 この相互依存性が主な問題点です。1 つの操作が常に構造化された方法で複数のノードに影響を与えます。 

もう 1 つの重要なエッジ ケースは、すべてのノードがすでに 1 である場合です。正解は自明のことながら「はい」ですが、盲目的に操作を適用して「強制的に改善」しようとするアルゴリズムは、システムがすでに有効であることを認識しない場合、誤ってソリューションから遠ざかってしまう可能性があります。 

## アプローチ

 ブルート フォース アプローチでは、各ノード構成を状態として扱い、許可された各操作を遷移として扱います。 初期構成から始めて、すべて 1 の構成に到達するか、可能性を使い果たすまで、すべての可能な状態に対して幅優先検索を実行できます。 

すべての操作は可逆的であり、シーケンスが存在する場合は BFS がシーケンスを検索するため、これは原理的には正しいです。 問題は規模だ。 各ノードは操作用に選択できるため、すべての状態には N 個の出力遷移があり、2^N 個の状態が存在します。 N = 20 の場合でもこれは境界線になりますが、N が数千の場合は完全に不可能です。 

重要な観察は、操作が GF(2) に対して線形であることです。つまり、ノードを反転すると、ノードの固定セット、つまりそれ自体とその隣接ノードが切り替わります。 つまり、最終的な状態は、順序ではなく、各操作を偶数回適用するか奇数回適用するかによって決まります。 これにより、問題が 2 値フィールド上の線形方程式系に変換されます。 

各ノードは 1 つの方程式を提供します。すべての操作の後、その最終値は 1 でなければなりません。ノード u での各操作は、u とその隣接するすべてのノードへのトグルに貢献します。 つまり、N XOR 方程式系に解があるかどうかを解決していることになります。 

ツリー上では、このシステムは削減できる構造になっています。 ツリーをルート化すると、ノードでの演算の適用を選択するかどうかを変数として表現できます。 したがって、各ノードの最終的なパリティは、それ自体とその親および子の選択のみに依存します。 これは、ボトムアップまたはトップダウンで値を決定する 1 回の走査で解決可能になります。 

アプローチを比較します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース状態検索 | O(2^N・N) | O(2^N) | 遅すぎる |
 | ツリー DP / リニア XOR システム | テスト ケースあたり O(N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 任意のノード (通常はノード 1) でツリーをルートにするため、ルートを除くすべてのノードに親があります。 これにより、決定を一貫して伝達するために必要な方向性のある構造が得られます。 
2. 各ノードに対して反転操作を実行するかどうかを示すバイナリ変数を定義します。 ノードの選択の効果は決定的です。ノード自体とその隣接ノードすべてが反転されます。 
3. DFS 順序でツリーを走査します。 重要なアイデアは、親の前に子を処理することで、ノードで決定するまでに、そのサブツリーが現在の決定の下でどのように動作するかをすでに知っているようにすることです。 
4. 各ノードについて、ツリーのすでに処理された部分からノードに影響を与えるフリップの現在のパリティを維持します。 このパリティは、これまでに行われた決定に基づいて、ノードが現在オンであるかオフであるかを表します。 
5. リーフでは、ターゲット状態と一致させるためにそのノードで操作を適用する必要があるかどうかを直接決定します。 リーフには子がないため、その決定はローカルに制約されます。 
6. 子から親に戻るとき、制約を集約します。各子は、子がすでに修正できるか、まだ親の決定に依存しているかどうかに応じて、親に要件を課します。 
7. この伝播を上方向に続けて、すべてのノードの制約が満たされていることを確認します。 同じノードに対して反転と非反転の両方を必要とするなど、どこかの時点で矛盾が発生した場合は、不可能であると結論付けます。 
8. ツリー全体を処理した後、ルートもその制約を満たしていることを確認します。 すべての制約が一貫している場合、有効な一連の操作が存在します。 

### なぜ効果があるのか

 各操作は、ツリー エッジ上の固定 XOR パターンに影響します。 XOR は結合的かつ可換であるため、最終状態は各ノードでの演算のパリティのみに依存します。 DFS の定式化では、親が処理される前にすべてのサブツリーの寄与が完全に考慮されるため、後の決定によって以前に固定された制約が無効になることはありません。 これにより、システムが解決可能な場合に限り、すべてのノード方程式を同時に満たすバイナリ変数の一貫した割り当てが作成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        g = [[] for _ in range(n)]
        for _ in range(n - 1):
            u, v = map(int, input().split())
            u -= 1
            v -= 1
            g[u].append(v)
            g[v].append(u)

        sys.setrecursionlimit(10**7)

        parent = [-1] * n
        order = []
        
        stack = [0]
        parent[0] = -2

        while stack:
            u = stack.pop()
            order.append(u)
            for v in g[u]:
                if v == parent[u]:
                    continue
                if parent[v] != -1:
                    continue
                parent[v] = u
                stack.append(v)

        dp = [0] * n

        for u in reversed(order):
            cur = a[u] ^ dp[u]
            if cur == 0:
                if parent[u] != -2:
                    dp[parent[u]] ^= 1

        print("YES")

if __name__ == "__main__":
    solve()
```この実装では、反復 DFS を使用して、大きなツリーでの再帰の問題を回避します。 重要な考え方は、各ノードが単一のパリティ要件をその親に伝播するということです。 の`dp`配列は、ノードがサブツリーによって追加の反転を適用するよう効果的に「強制」されているかどうかを追跡します。 サブツリー効果を考慮した結果、ノードが望ましくない状態になった場合、親の寄与を切り替えることで制約を上方に渡します。 

最終的な実現可能性は、ルートが累積パリティ要件を満たすことができるかどうかにかかっています。

 ## 特殊なケース

 単一ノードの場合、アルゴリズムはその状態をすぐに評価し、伝播する制約が見つからないため、すでに 1 であれば YES を返します。すべてのノードがすでに 1 であるツリーの場合、トラバース中に制約を上方に押し上げるノードはないため、ルートは矛盾を認識せず、答えは YES のままになります。 完全にオフツリーの場合、すべてのリーフが要件を上方に押し上げますが、各制約は親レベルでの単なる XOR の累積であるため、これらは競合するのではなく一貫して累積され、ルートは曖昧さなく最終的な実現可能性を明確に決定します。
