 ## 解決策
 ## 問題の理解

 各ショップには、販売価格に応じた線形需要モデルがあります。 価格を設定する場合$p$、 店$i$需要に貢献する$a_i - b_i p$販売されたユニットごとに利益が得られます$p - c_i$。 その店からの利益の合計は、これら 2 つの式の積です。 さまざまなショップの合計利益は、これらのショップごとの貢献の合計にすぎません。 

クエリにより、店舗の連続したセグメントが得られます。 そのセグメントでは、単一のグローバル価格を選択できます。$p$これはセグメント内のすべての店舗に適用され、総利益を最大化したいと考えています。 

したがって、入力は配列で構成されます$a_i$、$b_i$、$c_i$、および複数のクエリ。最適な価格を選択するときに、それぞれがサブ配列に対して達成可能な最高の利益を求めます。 

この制約は、クエリが多数ある場合にクエリごとのリニア スキャンが遅すぎるように設計されています。 もし$n, q$大きい、$O(nq)$解決策には以下が含まれます$10^{10}$2 秒以内に実行可能な限界をはるかに超える操作が行われます。 これにより、前処理後に各クエリが一定時間または対数時間で応答されるソリューションがすぐに得られます。 

微妙な問題が 2 つの状況で現れます。 まず、次の場合、需要はゼロまたはマイナスになります。$p$は大きいため、制約のない数学的最適値は有効な価格設定範囲の外にある可能性があります。 第二に、もしすべてが$b_i = 0$セグメントでは、利益は直線的になります。$p$, したがって、「放物線の頂点」の議論は破綻します。 

小さな具体的な失敗例: もしすべてが失敗した場合$b_i = 0$、すると利益は$\sum a_i (p - c_i)$、無制限に増加します$p$が増加するため、単純な頂点式はゼロで除算するか、無意味な結果を生成します。 別のエッジケースは、最適価格が最大許容価格を超えている場合に発生します。$m$ここで、答えは制約のない最適値ではなく境界で評価される必要があります。 

## アプローチ

 クエリセグメントを修正する$[l, r]$。 単一のショップの場合、利益式を拡張すると次のようになります。$$(a_i - b_i p)(p - c_i) = -b_i p^2 + (a_i + b_i c_i)p - a_i c_i.$$セグメントを合計すると、二次構造が維持されます。 合計利益は次のようになります。$$-Ap^2 + Bp - C,$$どこ：$$A = \sum_{i=l}^r b_i,\quad B = \sum_{i=l}^r (a_i + b_i c_i),\quad C = \sum_{i=l}^r a_i c_i.$$これは凹放物線です$p$、したがって最大値はその頂点で発生します$p = \frac{B}{2A}$、 提供された$A > 0$。 

ブルートフォースソリューションでは再計算が行われます。$A$、$B$、 そして$C$すべてのクエリに対してセグメントをスキャンし、最適価格の候補で放物線を評価します。 それには費用がかかります$O(n)$各クエリは範囲にわたる合計を必要とするため、クエリごとに実行されます。 

重要な観察は、セグメントが 3 つの線形統計のみを集計していることです。 プレフィックスの合計を事前計算したら、$b_i$、$a_i + b_i c_i$、 そして$a_i c_i$、取得できます$A$、$B$、 そして$C$クエリごとに一定時間で。 これにより、問題は、一定数の候補点 (頂点とその近くの整数、および境界制約) での 2 次関数の評価に集約されます。 

最大許容価格がある場合$m$場合、最適値が切り取られる可能性があります。 その場合、内部最適値とエンドポイントを比較します。$0$そして$m$なぜなら、凹関数は拘束されたときに頂点または境界のいずれかで最大値に達するからです。 

特別な場合$A = 0$二次項を完全に削除し、一次関数を残します。$p$したがって、最良の選択は常に境界にあります$m$。

 ## アルゴリズムのチュートリアル

 1. 3 つのシーケンスのプレフィックス合計を事前計算します。$b_i$、$a_i + b_i c_i$、 そして$a_i c_i$。 これにより、減算によってセグメントの合計を一定時間内に計算できます。 これが機能する理由は、必要な式がすべてインデックスに対して加算されるためです。 
2. クエリごとに$[l, r]$、次を計算します。$A = \sum b_i$、$B = \sum (a_i + b_i c_i)$、 そして$C = \sum a_i c_i$。 これにより、反復処理を行わずに、そのセグメントの二次利益関数が再構築されます。 
3. もし$A = 0$、利益を線形として扱います。$p$。 その場合の関数は、$Bp - C$、最大許容価格で最大化されます。$m$。 
4. それ以外の場合は、制約のない最適価格を計算します。$p_0 = \frac{B}{2A}$。 これは放物線の頂点であり、導関数をゼロに設定することで得られます。 
5.以来$p$実際には整数でなければなりません。利益は次のように評価されます。$\lfloor p_0 \rfloor$そして$\lceil p_0 \rceil$なぜなら、凹二次関数はこれらの最も近い整数の 1 つで最大値に達するからです。 
6. 上限価格がある場合$m$、でも評価します$p = m$。 正解は、有効な候補すべての中での最大値です。 
7. 最も評価された利益を返します。 

ステップ 5 の背後にある理由は、連続最適値は整数ではない可能性があるが、凹面により、離散最適値が頂点の周囲の最も近い整数点に存在することが保証されるということです。 

### なぜ効果があるのか

 すべてのクエリ セグメントについて、価格の関数としての利益は凹二次関数になります。 凹二次方程式は実領域で単一のグローバル最大値を持ち、その値は頂点から離れるにつれて厳密に減少します。 整数に制限されている場合、最大値は頂点を囲む 2 つの整数のいずれか、または制約によってドメインが制限されている場合は境界で発生する必要があります。 プレフィックス合計はこの 2 次式の係数を正確に再構築するため、すべてのクエリは固定された小さな候補セットを評価することになり、正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, q, m = map(int, input().split())
    a = [0] + list(map(int, input().split()))
    b = [0] + list(map(int, input().split()))
    c = [0] + list(map(int, input().split()))

    pa = [0] * (n + 1)
    pb = [0] * (n + 1)
    pc = [0] * (n + 1)

    for i in range(1, n + 1):
        pa[i] = pa[i - 1] + b[i]
        pb[i] = pb[i - 1] + (a[i] + b[i] * c[i])
        pc[i] = pc[i - 1] + a[i] * c[i]

    def range_sum(pref, l, r):
        return pref[r] - pref[l - 1]

    for _ in range(q):
        l, r = map(int, input().split())

        A = range_sum(pa, l, r)
        B = range_sum(pb, l, r)
        C = range_sum(pc, l, r)

        def profit(p):
            return -A * p * p + B * p - C

        best = -10**30

        if A == 0:
            best = profit(m)
        else:
            p0 = B / (2 * A)

            for p in (int(p0), int(p0) + 1):
                if 0 <= p <= m:
                    best = max(best, profit(p))
            best = max(best, profit(0), profit(m))

        print(best)

if __name__ == "__main__":
    solve()
```この実装は代数を直接反映しています。 プレフィックス配列には、各セグメントの二次方程式を再構築するために必要な係数が正確に保存されます。 利益関数は、導出された式の直接変換として評価されます。 

唯一のデリケートな点は、浮動小数点頂点計算の処理です。 コードは周囲の近くの整数のみを評価します。$p_0$これにより、凹面によって保証される個別の最適値を取得しながら、精度の問題を回避できます。 

境界チェックでは、$0$そして$m$頂点が有効な範囲外にある場合に正確さを保証します。

 ## 特殊なケース

 重要なエッジケースは、次のような場合です。$b_i = 0$。 この状況では、二次項が消え、頂点の式がゼロで除算されます。 アルゴリズムはこのケースを明示的にチェックし、境界価格の評価に切り替えます。$m$、これは関数の単調構造と一致します。 

最適な価格が以下から計算される場合、別のエッジケースが発生します。$p_0 = \frac{B}{2A}$外にある$[0, m]$。 その場合、放物線は有効範囲内で減少し、のみを評価します。$0$そして$m$定常点が実行不可能な場合、閉じた区間にわたる凹関数は端点で極値に達するため、最大値が正確に取得されます。 

最後に、浮動小数点の丸め処理$p_0$不注意に扱うと、正確な頂点を誤って分類する可能性があります。 評価を制限する$\lfloor p_0 \rfloor$そして$\lceil p_0 \rceil$凹面により最適値が実数値の頂点に隣接していることが保証されるため、丸め誤差によって真の最良の整数点がスキップされることはありません。
