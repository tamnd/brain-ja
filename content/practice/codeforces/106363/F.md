 ## 解決策
 ## 問題の理解

 1 から n までの数値の順列が与えられます。 この順列から、すべての連続セグメントを考慮し、そのセグメント内に現れない最小の正の整数を意味する MEX を計算します。 タスクは、順列のすべての可能なセグメントにわたってこの MEX 値を合計することです。 

重要な構造は、任意の配列を操作しないということです。 1 から n までのすべての値は 1 回だけ出現します。値 1 から k のそれぞれが配列内の 1 つの位置に対応するため、値 1 から k の存在条件を追跡するのがはるかに簡単になります。 

n が 200,000 以上のオーダーで大きい場合、すべてのサブ配列を列挙してサブ配列ごとの MEX を計算することは直ちに不可能になります。 サブアレイの数は O(n^2) で、サブアレイごとの線形スキャンでもこれは O(n^3) に達しますが、これは一般的な制限をはるかに超えています。 このため、直接列挙するのではなく、値の寄与という観点から問題を再定式化する必要があります。 

配列が小さい場合、または初期の値がクラスター化されている場合、微妙なエッジ ケースが発生します。 たとえば、順列が [1, 2, 3] の場合、すべてのサブ配列は初期セグメントが空の場合にのみ大きな MEX を持ち、ローカル ギャップに関する単純な推論ではグローバル カバレッジを簡単に見逃す可能性があります。 もう 1 つの特殊なケースは、[n, n−1, ..., 1] などの逆順列で、小さな数値の位置が遠く離れており、プレフィックスを含めるのに必要な範囲が最大化されます。 

単純なアプローチでは、すべてのサブ配列に対して個別に MEX を繰り返し再計算することになりますが、論理的には正しい場合でも、時間の計算量が原因で暗黙的に失敗します。 

## アプローチ

 ブルートフォース戦略は単純です。 すべての部分配列について、その要素をスキャンし、出現する値をマークし、欠落している最小の整数を計算します。 これが機能するのは、MEX がサブ配列ごとにローカルに定義されており、概念的にはそれ以上何も必要ないためです。 問題は、各サブ配列の処理コストが O(n) であり、サブ配列が O(n^2) あるため、合計で O(n^3) の演算が必要になり、大きな入力に対しては遅すぎることです。 

これを改善するために、視点を反転します。 「このサブ配列の MEX は何か」を尋ねる代わりに、「どのサブ配列の MEX が少なくとも k + 1 であるか」を尋ねます。 部分配列に 1 から k までのすべての数値が含まれている場合にのみ、部分配列の MEX は k より大きくなります。 順列を扱っているため、各数値は 1 回だけ出現するため、「1..k のすべてが含まれる」という条件は単純な区間条件になります。 

各 k について、1 から k までの数字の位置を特定します。 L_k をこれらの位置の最小値、R_k を最大値とする。 1..k のすべてを含むサブ配列は、この間隔 [L_k, R_k] を完全にカバーする必要があります。 このようなサブ配列の数は、左のエンドポイントでは L_k 個、右のエンドポイントでは (n − R_k + 1) 個の選択肢です。 

これにより、問題は、k が増加するにつれて 1..k の位置によって形成される拡大間隔を維持することに変換されます。 各ステップでは間隔のエンドポイントのみが更新され、寄与率は k ごとに一定時間で計算されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^3) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. pos[x] が順列内の値 x のインデックスとなるように、配列 pos を構築します。 これにより、各数字が表示される場所への一定時間のアクセスが可能になります。 
2. k が増加するにつれて、値 1 から k までの最小位置と最大位置を表す 2 つの変数 L と R を維持します。 値 1 のみが含まれるため、最初は L = R = pos[1] となります。 
3. 1 から n までの各 k について、L = min(L, pos[k]) および R = max(R, pos[k]) を更新して間隔を拡張します。 これにより、L と R が常にすべての値 1..k をカバーする最小セグメントを記述することが保証されます。 
4. 各 k について、区間 [L, R] 全体を含む部分配列の数を計算します。 左端点は L 以降で開始する必要があるため、L 通りに選択できます。右端点は R 以降に終了する必要があるため、(n − R + 1) 通りに選択できます。これらを乗算して count_k を取得します。 
5. 答え += count_k を累積します。 この値は、MEX が厳密に k より大きいサブ配列の数を表します。 
6. すべての k を処理した後、最終的な累積値を返します。 これが機能するのは、各部分配列がその MEX より小さい k ごとに正確に 1 を提供するためです。 

### なぜ効果があるのか

 各部分配列は、1..k がその中に完全に含まれるように、整数 k ごとに 1 回ずつ最終合計に寄与します。 この条件は、1..k の位置によって定義される区間をカバーする部分配列と同等です。 置換構造では、値のプレフィックスごとに単一の間隔が保証されるため、この間隔をカバーするサブ配列をカウントすると、k より大きい MEX を持つすべてのサブ配列が正確にカウントされます。 k を合計すると、重複や省略のない合計 MEX 合計が再構築されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    pos = [0] * (n + 1)
    for i, v in enumerate(a):
        pos[v] = i

    L = pos[1]
    R = pos[1]
    ans = 0

    for k in range(1, n + 1):
        L = min(L, pos[k])
        R = max(R, pos[k])
        ans += (L + 1) * (n - R)

    print(ans)

if __name__ == "__main__":
    solve()
```コアの実装は、間隔の更新が一定時間になるように、位置の事前計算に依存しています。 表現`(L + 1) * (n - R)`0 から始まるインデックス付けを想定しています。`L + 1`有効な左端点をカウントし、`n - R`有効な右エンドポイントを厳密に R の右側にカウントします。ここでの間違いの主な原因は、1 つずつのインデックス付けです。エンドポイントを包含または排他として扱うと、式が完全に変わってしまいます。 

ループは間隔を段階的に拡大し、位置配列を超える追加のデータ構造は必要ありません。

 ## 特殊なケース

 ### 単一要素

 入力:```
1
1
```ここで、L = R = 0 です。唯一の部分配列は配列全体であり、すべてのプレフィックス条件が即座に当てはまります。 この式では (L+1)(n−R) = 1 が得られ、これは唯一の MEX 値と一致します。 

### 完全に逆の順列

 入力:```
4
4 3 2 1
```L と R は段階的に内側に拡張し、アレイ全体をカバーします。 初期の k 値は大きな間隔を生成し、サブ配列の数が急速に減少します。 アルゴリズムは隣接関係ではなく常にグローバルな最小位置と最大位置を使用するため、これを正しく追跡します。 

### ランダム シャッフル エッジ動作

 小さな値が散在する入力では、L と R が大きく変動します。 各更新は極値のみに依存し、中間構造は区間範囲には無関係であるため、アルゴリズムは依然として正しいままです。
