 ## 解決策
 ## 問題の理解

 タスクは次の数字を並べることです。`1`に`n`順列に。 順列の品質は、各位置を調べ、その値をその隣の値と比較することによって測定されます。 すべての要素について、隣接する要素との間にできる最大の絶対差を考慮します。 順列の美しさは、すべての位置におけるこれらの値の最小値です。 目標は、最大限の美しさを備えた順列を構築することです。 

入力には順列のサイズのみが含まれます。 出力は、次のすべての数値を 1 つの順序で並べたものである必要があります。`1`に`n`最高の美しさを実現します。 

の制約`n`アルゴリズムが線形に近い必要があることを意味します。 たとえ`n`サイズが大きいので、印刷するだけで済みます`n`したがって、要素ごとに少量の一定量以上の作業を行うソリューションは、遅すぎる危険性があります。 答えは直接的な構造になっているため、並べ替え、検索、または多くの候補順列の試行は不要です。 

難しいケースは、パフォーマンスに関するものではなく、すべての要素に必要な最小限の差を維持することに関するものです。 

のために`n = 1`、すべての要素に 2 つの隣接要素があると仮定する解決策は失敗します。 正しい出力は次のとおりです。```
Input:
1

Output:
1
```可能な順列は 1 つだけであり、それが答えです。 

のために`n = 2`不注意な実装では、最大の要素を構築の途中に配置しようとする可能性があります。 中間の位置はないため、構築では引き続き両方の数値を生成する必要があります。```
Input:
2

Output:
2 1
```次のような奇数の値の場合`n = 5`、調整せずに均等な構築式を使用すると、値が重複または欠落します。 正しい順列は次のとおりです。```
Input:
5

Output:
3 1 4 2 5
```配置の片側にもう 1 つの要素があるため、中央の値は個別に処理する必要があります。 

## アプローチ

 直接的な総当りのアプローチでは、あらゆる可能な順列が生成され、その美しさが計算されます。 各要素は隣接する要素に対してチェックするだけでよいため、1 つの順列の計算は線形です。 ただし、`n!`可能な順列なので、総仕事量は次のようになります。`O(n * n!)`。 たとえ小さな値であっても、`n`、これは成長が早すぎます。 

重要な点は、配置を検索する必要がないということです。 美しさは、すべての要素に少なくとも 1 つの隣接要素が遠く離れたところに存在するようにするかどうかによって決まります。 大きな値は小さな値の隣に配置する必要があります。これは、それらの差がリソースを最大化するためです。 

可能な限り最大の美しさは半分を超えることはできません`n`偶数の場合。 中間の値を検討してください`n / 2`。 組み合わせることができる最大の値は次のとおりです。`n`、正確に の差が得られます`n / 2`。 可能な限り近い配置でもこの中間要素が制限要素として残るため、どの要素もより大きな保証差を達成することはできません。 

この境界は、構築では数値の前半と後半をペアにする必要があることを示唆しています。 この配置では、未使用の大きな値と未使用の小さな値が交互に配置され、あらゆる場所で大きな差が生じます。 

偶数の場合`n`、シーケンスは次のとおりです。```
n/2 + 1, 1, n/2 + 2, 2, ..., n, n/2
```奇数の場合`n`、中央の値はわずかに異なるため、構造は次のようになります。```
(n+1)/2, 1, (n+1)/2 + 1, 2, ..., n
```ブルートフォース手法は、考えられるすべての配置を探索するため機能します。 この構築が機能するのは、目標の構造がどの値が隣接するべきかを正確に示すためです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * n!) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(1) 出力ストレージ以外の | 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む`n`、必要な順列のサイズ。 
2.ハンドル`n = 1`別途出力することで`1`。 一般的な構造は、単一の要素には存在しない、小さい値と大きい値のペアを持つことに依存しています。 
3. もし`n`は偶数です、から開始します`n/2 + 1`そして`1`。 大きな数値を加算し、次に対応する小さな数値を加算し、ペアごとに両側を増やします。 これにより、絶対差が大きいペアが作成されます。 
4. もし`n`奇数です、から始めてください`(n+1)/2`そして`1`。 すべての数値が使用されるまで、大きな値を 1 つ追加し、その後に小さな値を 1 つ追加し続けます。 追加の中間値は当然先頭に配置されます。 
5. 構築された順列を出力します。 

構築が半分の間で交互に行われる理由は、すべての番号が反対側の半分から隣接する番号にアクセスできるためです。 下半分の値は上半分の値と大きく異なり、最小隣接差分が可能な限り大きく保たれます。 

なぜ効果があるのか:

 この構造により、エンドポイントを除くすべての要素が、数値範囲の残りの半分に隣接する値を持つことが保証されます。 エンドポイントには、配置によって作成される最大限の分離を備えた隣接ノードもあります。 範囲の中央の要素は考えられる答えを制限するため、その値に到達すると構築が最適であることが証明されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    if n == 1:
        print(1)
        return

    ans = []

    if n % 2 == 0:
        low = 1
        high = n // 2 + 1

        while high <= n:
            ans.append(high)
            ans.append(low)
            high += 1
            low += 1
    else:
        low = 1
        high = (n + 1) // 2

        while high <= n:
            ans.append(high)
            if low < high:
                ans.append(low)
            high += 1
            low += 1

    print(*ans)

if __name__ == "__main__":
    solve()
```コードは、置換の未使用部分を表す 2 つのポインターを保持します。`low`小さい半分を通り抜けて、`high`大きい半分を歩きます。 それらを交互に追加すると、必要な大きなギャップが作成されます。 

偶数の場合は、両方の半分のサイズが同じであるため、より単純です。 奇妙なケースには、余分な大きい側の要素が 1 つあるため、ループは小さい側の値を追加する前に、小さい側の値がまだ存在するかどうかをチェックします。 

境界条件`n == 1`ループ ロジックが無効な空のペアを作成するのを防ぎます。 値は範囲から直接生成されるため、重複する値や欠落した数値はありません。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | からの各番号`1`に`n`は 1 回だけ生成されます。 |
 | スペース | O(n) | 出力リストには、印刷前に順列が保存されます。 |

 このアルゴリズムは要素ごとに数回の操作のみを実行するため、制約に簡単に適合します。 検索構造やグラフ表現が必要ないため、メモリ使用量も最小限に抑えられます。 

## テストケース```python
import sys
import io

def solution(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n = int(input())

    if n == 1:
        return "1\n"

    ans = []

    if n % 2 == 0:
        low = 1
        high = n // 2 + 1
        while high <= n:
            ans.append(high)
            ans.append(low)
            high += 1
            low += 1
    else:
        low = 1
        high = (n + 1) // 2
        while high <= n:
            ans.append(high)
            if low < high:
                ans.append(low)
            high += 1
            low += 1

    return " ".join(map(str, ans)) + "\n"

assert solution("1\n") == "1\n", "minimum size"
assert solution("2\n") == "2 1\n", "two elements"
assert solution("5\n") == "3 1 4 2 5\n", "odd size"
assert solution("6\n") == "4 1 5 2 6 3\n", "even size"
assert solution("8\n") == "5 1 6 2 7 3 8 4\n", "larger even size"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1`|`1`| 単一要素境界の場合 |
 |`2`|`2 1`| 最小の自明でない順列 |
 |`5`|`3 1 4 2 5`| 奇妙な構造 |
 |`6`|`4 1 5 2 6 3`| 偶数建設 |
 |`8`|`5 1 6 2 7 3 8 4`| より大きな生成されたシーケンス |

 ## 特殊なケース

 のために`n = 1`、アルゴリズムはすぐに戻ります`1`。 ペアの作成は試行されないため、存在しない隣接要素へのアクセスが回避されます。 

のために`n = 2`、均等な建設は次から始まります。`n/2 + 1 = 2`、大きい値が最初になる唯一の可能な順序が生成されます。```
2 1
```2 つの要素の差が可能な最大値です。 

のために`n = 5`、アルゴリズムは奇妙な数式を使用します。```
3 1 4 2 5
```値`3`は範囲の中間であるため、どちらの半分からも通常の要素のように扱うことはできません。 これを最初に配置し、残りの数字を交互に配置すると、隣接する最小の差が最適に保たれます。 

のために`n = 8`、生成されるシーケンスは次のとおりです。```
5 1 6 2 7 3 8 4
```このアルゴリズムでは、並べ替え、交換、検索は行われません。 下半分と上半分を並行して消費するだけなので、すべての値は 1 回だけ表示され、隣接する関係はすべて意図したパターンに従います。
