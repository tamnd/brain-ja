 ## 解決策
 ## 問題の理解

 単一の整数が与えられます$n$そして、数値の順列を構築する必要があります。$1$を通して$n$。 この順列を構築した後、その「美しさ」を評価します。これは、順列内の隣接する要素のすべてのペア間の絶対差の合計として定義されます。 

言い換えると、順列が$p_1, p_2, \dots, p_n$、私たちが気にする値は$$|p_1 - p_2| + |p_2 - p_3| + \cdots + |p_{n-1} - p_n|.$$タスクは、値自体ではなく、この値を最大化する順列を出力することです。 

制約構造は、私たちが何もする余裕がないことを意味します。$O(n^2)$テストケースごとの構築または評価。 有効なソリューションでは、出力の生成自体にすでにコストがかかるため、線形時間で順列を構築する必要があります。$O(n)$。 それを超える並べ替えや貪欲な再計算はまだ許容されますが、二次関数はすぐに遅すぎます。 

微妙なエッジケースは次のような場合です$n = 1$または$n = 2$。 のために$n = 1$、隣接するペアがないため、美しさは常にゼロであり、あらゆる順列が有効です。 のために$n = 2$、どちらの順列も同じ絶対差を生成するため、どの順序でも最適です。 全てペアリング構造を想定した素朴な構造$n$これらのケースを処理しないと、不正なインデックス付けや不完全な出力が生成される可能性があります。 

## アプローチ

 ブルートフォースソリューションでは、次のすべての順列を列挙します。$1$に$n$、それぞれの隣接関係の合計を計算し、最良のものを維持します。 これは、すべての候補の目的関数を直接評価するため、正しいです。 ただし、これには次のことが必要です$n!$順列、および各評価には次の値がかかります。$O(n)$、階乗増加につながり、$n = 10$。 

重要な構造的洞察は、目的は隣接する差異のみに依存し、大きな差異は常に有益であるということです。 合計を最大化するには、大きな値ができるだけ小さな値に隣接するように数値を配置します。 これは、インターリーブの極端な例、つまり、残っている未使用の最大の番号と残っている未使用の最小の番号を繰り返しペアにすることを示唆しています。 

偶数の場合$n$、ペアリングできます$(1, n), (2, n-1), (3, n-2), \dots$、これらのペアが順列で連続して現れるように配置します。 これにより、各ステップで大きな絶対差が保証され、ペア構造の制約によって制限される最大可能合計が達成されることがわかります。 

奇数の場合$n$、中央で 1 つの要素がペアになっていないままになります。 最適な構造は依然として同じ考え方に従いますが、中心要素が構造をわずかにシフトし、最適に近い極端なペアリングを維持する既知の最適な配置につながります。 

ブルートフォースはすべての順序を調査するため機能しますが、指数関数的な増加により失敗します。 最適性は局所的な極端なギャップを最大化することから得られるという観察により、問題は線形時間での決定論的な構造に帰着します。

 | ブルートフォース |$O(n!)$|$O(n)$| 遅すぎる |
 | 最適 |$O(n)$|$O(1)$番外編 | 承認済み |

 ## アルゴリズムのチュートリアル

 極値をペアにすることで直接順列を構築します。 

1. 2 つのポインターを初期化します。1 つは範囲の先頭 (1)、もう 1 つは範囲の末尾 (n) です。 これらは、未使用の最小値と最大値を表します。 
2. 上位から 1 つと下位から 1 つの数値を繰り返し取得し、それらを交互に追加します。 
3. すべての番号が使用されるまでこのプロセスを続けます。 もし$n$が奇数の場合、中間要素が 1 つ残り、シーケンスの最後に配置されます。 

交互のエンドポイントが正しい理由は、高い値と低い値の間で遷移が発生するたびに、各ステップで連続する要素間に大きな絶対差が強制されるためです。 これがまさに合計に最も貢献するものです。 

### なぜ効果があるのか

 すべてのステップで、可能な限り、隣接する要素が残りの値の範囲の反対側の端から来るようにします。 この戦略から逸脱すると、内部値は常に極値よりも近い値になるため、大きな差は小さな差に置き換えられます。 各要素は最大 2 つの隣接する差異に関与するため、この構築では、合計を改善できる方法で将来の選択に影響を与えることなく、各隣接の寄与を貪欲に最大化します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    
    l, r = 1, n
    res = []
    
    while l <= r:
        if l == r:
            res.append(l)
        else:
            res.append(r)
            res.append(l)
        l += 1
        r -= 1
    
    print(*res)

if __name__ == "__main__":
    solve()
```この実装では、中心に向かって縮小する 2 つのポインターが維持されます。 各反復では、現在の範囲の両端が消費され、それらが交互の順序で追加されます。 ポインタが交わると、最後の中間要素が 1 回追加されます。 

各ペア内の順序が重要です。大きい値を小さい値の前に配置すると、次の遷移で絶対的な差が早期に弱まるのではなく、再び大きな絶対差が生成されます。 

終了条件`l <= r`偶数と奇数の両方のケースが個別の論理分岐なしで均一に処理されるようにします。 

## 実用的な例

 ### 例 1: n = 6

 建設を段階的に追跡します。 

| l | r | 追加 | 結果 |
 | --- | --- | --- | --- |
 | 1 | 6 | 6、1 | [6, 1] |
 | 2 | 5 | 5、2 | [6、1、5、2] |
 | 3 | 4 | 4、3 | [6、1、5、2、4、3] |

 最後の置換は、$[6, 1, 5, 2, 4, 3]$。 これにより、高い値と低い値が一貫して交互になり、隣接する差が最大化されます。 

### 例 2: n = 7

 | l | r | 追加 | 結果 |
 | --- | --- | --- | --- |
 | 1 | 7 | 7、1 | [7、1] |
 | 2 | 6 | 6、2 | [7、1、6、2] |
 | 3 | 5 | 5、3 | [7、1、6、2、5、3] |
 | 4 | 4 | 4 | [7、1、6、2、5、3、4] |

 最後の要素 4 は中間の値です。 対応するものが残っていないため、構造は破壊されず、避けられない隣接する 2 つの差異のみが寄与します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from sys import stdout
    stdout.write = lambda s: output.append(s)
    global output
    output = []
    
    solve()
    return "".join(output).strip()

def solve():
    n = int(input().strip())
    l, r = 1, n
    res = []
    while l <= r:
        if l == r:
            res.append(l)
        else:
            res.append(r)
            res.append(l)
        l += 1
        r -= 1
    print(*res)

# minimum size
assert run("1\n") == "1"
assert run("2\n") in ["1 2", "2 1"]

# small even
assert run("4\n") == "4 1 3 2"

# small odd
assert run("5\n") in ["5 1 4 2 3", "5 1 4 2 3"]

# larger case
out = run("7\n")
assert sorted(out.split()) == ["1","2","3","4","5","6","7"]
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 | 1 | 最小境界 |
 | 2 | 1 2 または 2 1 | 対称性 |
 | 4 | 4 1 3 2 | 偶数構造の正確さ |

 ## 特殊なケース

 のために$n = 1$、ループは次のようにして 1 回実行されます。$l = r = 1$、単一の値が追加されます。 隣接関係が存在しないため、出力は明らかに正しいです。 

のために$n = 2$の場合、アルゴリズムは 2、次に 1 を追加し、差分 1 を生成します。これを超える置換はできないため、これが最適です。 

奇数の場合$n$、中央の要素に到達するとき$l = r$。 その時点で、それは正確に 1 回追加され、重複がないことが保証され、置換の有効性が維持されます。
