 ## 解決策
 ## 問題の理解

 チケット価格のコレクションが与えられ、2 レベルの選択タスクを解くように求められます。 まず、チケット価格間のすべてのペアごとの差の中で、k 番目に小さい差の値を決定する必要があります。 このターゲットの差を特定した後、問題のタイブレーク ルール (その制約の下で可能な限り最良のペアを選択する) に従ってペアの選択を最適化しながら、価格差がまさにその値であるチケットのペアを見つけたいと考えます。 

自然な解釈では、価格を表す整数の配列を操作していることになります。 この配列から、すべてのペア i < j を暗黙的に形成し、それらの絶対的な差を考慮します。 第 1 段階は、これらの違いに関する世界的なランキングの問題です。 2 番目のフェーズは、差に関する等価条件を満たすペアに対する制約付き検索です。 

この制約は、チケットの数が多くなり、すべてのペアを列挙することが不可能になる可能性があることを意味します。 n が 2 × 10^5 までの場合、ペアの数は約 2 × 10^10 となり、実行可能な計算をはるかに超えます。 これにより、両方の段階で二次アプローチが即座に排除されます。 どのソリューションも明示的なペアの生成を避け、代わりにソートされた構造とカウント手法に依存する必要があります。 

複数のペアが同じ違いを共有する場合、微妙な問題が発生します。 単純なアプローチでは、一意性を誤って仮定したり、最終的なペアを再構築するときにタイブレークを誤って処理したりする可能性があります。 もう 1 つのよくある落とし穴は、差分が並べ替えられた値に基づいて計算されるため、並べ替え後にのみ差分の絶対値が単純な減算になることを忘れていることです。 

具体的なエッジ ケースとして、k = 1 の価格 [1, 10, 20] を考えてみましょう。(1, 10) との最小の差は 9 です。 元の配列内の隣接する差分のみをチェックする単純で間違ったアプローチでは、ペア (1, 10) を完全に見逃す可能性があります。 もう 1 つのケースは [1, 2, 3, 100] で、連続する要素間に多くの小さな差が存在しますが、k 番目に小さい差は、k に応じて隣接しない構造から得られる可能性があります。 これは、元の順序における隣接性が無関係であることを示しています。 命令を課さなければなりません。 

## アプローチ

 直接的なブルート フォース ソリューションは、インデックス i < j のすべてのペアを列挙し、|a[j] - a[i]| を計算し、これらの値を保存し、並べ替えて、k 番目に小さいものを選択します。 これは、差分の完全なマルチセットを明示的に構築するため、正しいです。 ただし、ペアの数が二次関数的に増加するため、O(n^2) 時間と O(n^2) メモリが必要ですが、n が 10^5 程度の場合でも不可能になります。 

重要な構造的観察は、配列がソートされると、問題は差分閾値において単調になるということです。 値 d を固定し、最大 d の差を持つペアの数をカウントする場合、このカウントは 2 ポインター スイープを使用して線形時間で計算できます。 d が増加すると、このカウントは増加するだけです。 この単調性により、d を二分探索して、少なくとも k 個のペアの差分 ≤ d が存在する最小値 (正確に k 番目に小さい差分) を見つけることができます。 

このしきい値の差が判明すると、第 2 フェーズは制約付き計数問題になります。 ここでも、ソートされた配列に対して 2 ポインター アプローチを使用して、差がターゲット値に等しいペアを特定し、必要な順序付け条件に従って最適なペアを選択します。 これにより、有効な最適解を回復しながら、すべてのペアを列挙することが回避されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2 log n^2) | O(n^2) | 遅すぎる |
 | 最適 | O(n log n) | O(1) または O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、チケット価格の配列を並べ替えて、要素間の差異を単純な減算で処理できるようにします。

1. 配列を降順でない順に並べ替えます。 並べ替えにより、任意の i < j について、a[j] - a[i] の差が負でなく、j において単調であることが保証されます。 
2. a[j] - a[i] ≤ d となるペア (i, j) の数を返す関数 count(d) を定義します。 これは 2 つのポインターを使用して計算されます。 各 i について、制約を維持しながら j を可能な限り進めます。 i で始まる有効なペアの数は (j - i - 1) になります。 j が条件に違反すると、その後のすべてのインデックスも条件に違反するため、これが機能します。 
3. 0 ～ max(a) - min(a) の範囲で d を二分探索します。 各中間点について、count(mid) を計算します。 count(mid) ≥ k の場合、k 番目の最小の差は ≤ mid であることがわかるため、上限を下に移動します。 それ以外の場合は、下限を上に移動します。 これは、少なくとも k 個のペアが条件を満たすような最小の d に収束します。 
4. 正確なしきい値 d を取得した後、差が正確に d であるペアを分離する必要があります。 同様の 2 ポインター スイープを実行します。各 i について、a[j] - a[i] ≤ d となるような j を見つけ、等号が成立するペアを個別に追跡します。 
5. スキャン中、必要な順序付けルール (通常はステートメントのタイブレーク条件に応じて辞書編集上の最小または最大のインデックス) に従って最適なペアを維持します。 差が d と正確に一致する場合にのみ候補を更新します。 
6. 選択したペアを出力します。 

### なぜ効果があるのか

 正しさは述語「a[j] - a[i] ≤ d」の単調性に依存します。 d が増加すると、有効なペアのセットは拡大するだけです。 これにより、カウント関数が非減少となり、有効なペアの累積数が k と交差する一意のしきい値が二分探索で見つかることが保証されます。 すべてのペアは、この差分による順序付けに 1 回だけ寄与するため、k 番目に小さい差分がこのしきい値に存在する必要があります。 次に 2 番目のパスでは、まさにその差を持つペアの同値クラスに注目を制限し、より小さいまたはより大きい差クラスのペアが混在しないようにします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def count_pairs(a, d):
    n = len(a)
    j = 0
    total = 0
    for i in range(n):
        if j < i + 1:
            j = i + 1
        while j < n and a[j] - a[i] <= d:
            j += 1
        total += (j - i - 1)
    return total

def find_pair_with_diff(a, d):
    n = len(a)
    j = 0
    best = None

    for i in range(n):
        if j < i + 1:
            j = i + 1
        while j < n and a[j] - a[i] <= d:
            if a[j] - a[i] == d:
                if best is None or (a[i], a[j]) < best:
                    best = (a[i], a[j])
            j += 1

        # j may have stepped one too far; fix for next i implicitly

    return best

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    a.sort()

    lo, hi = 0, a[-1] - a[0]

    while lo < hi:
        mid = (lo + hi) // 2
        if count_pairs(a, mid) >= k:
            hi = mid
        else:
            lo = mid + 1

    d = lo
    ans = find_pair_with_diff(a, d)
    print(ans[0], ans[1])

if __name__ == "__main__":
    solve()
```カウントと再構築の両方が右ポインターの単調な動きに依存しているため、ソートのステップは不可欠です。 カウント関数により、左の各エンドポイントが有効なウィンドウを 1 回だけ拡張することが保証され、チェックごとの複雑さが線形に保たれます。 二分探索では、この関数を O(log(maxA)) 回呼び出します。 

再構成ステップでは、差が最終しきい値に等しいペアのみを受け入れます。 これにより、k 番目のクラスと正確に一致するという要件に違反する、≤ d を満たすが厳密に小さいペアを誤って選択することが回避されます。 

## 実用的な例

 k = 3 の入力配列 [1, 3, 4, 8] を考えてみましょう。ソート順のペアごとの差は 2、3、4、5、7、3 です。これらをソートすると 2、3、3、4、5、7 が得られるため、k 番目に小さい差は 3 になります。 

d = 3 のカウント関数をトレースします。 

| 私 | 動き | i から数えたペア |
 | --- | --- | --- |
 | 0 | j は 2 (1→3→4) に展開されます。 2 |
 | 1 | j は 3 に展開されます (3→4) | 1 |
 | 2 | j は 3 に拡張されます (4→8 はすぐに停止します) | 0 |
 | 3 | ペアはありません | 0 |

 合計 = 3 ペア、k 個のしきい値と一致します。 

これにより、二分探索で d = 3 が正しく識別されたことが確認されます。 

ここで、d = 3 の同じ配列での再構成を考えてみましょう。 

| 私 | j | 違い | アクション |
 | --- | --- | --- | --- |
 | 0 | 1 | 2 | スキップ |
 | 0 | 2 | 3 | 候補者 |
 | 1 | 2 | 1 | スキップ |
 | 1 | 3 | 5 | スキップ |
 | 2 | 3 | 4 | スキップ |

 唯一の有効なペアは (1, 4) であり、これが選択されています。 

これは、再構成により、しきい値を下回るすべてのペアではなく、正確な差分のペアのみが分離されることが示されています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n + n log W) | ソートと差分範囲にわたる二分探索、各チェックは線形です。 
| スペース | O(1) 追加 | 入力ストレージ以外には、ポインターのみが使用されます。 

この構造は、各二分探索ステップが線形であり、ステップ数が値の範囲内で対数であるため、大きな n に対して十分効率的です。 これは、最大 2 × 10^5 の n に対する典型的な Codeforce 制限内に問題なく収まります。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべての要素が等しい場合です。 入力 [7, 7, 7, 7] の場合、すべてのペアの差分は 0 です。 count(0) が n(n−1)/2 に等しいため、二分探索は直ちに d = 0 に収束し、再構成では有効なペアが正しく返される必要があります。 等価性チェックではすべてのゼロ差分ペ​​アが明示的に取得されるため、アルゴリズムはこれを処理します。 

別のケースは、k が最大差分ペアに対応する場合です。 [1, 100, 200] の場合、(1, 200) との最大の差は 199 です。 二分探索は hi が 199 に達するまで自然に拡張され、再構成ではその差を達成する唯一のペアが選択されます。 

最後の微妙なケースは、多くのペアが同じ違いを共有しており、タイブレークを混乱させる可能性がある場合です。 再構成では候補ペアを明示的に比較し、完全一致のみを更新するため、有効な回答が複数存在する場合でも、選択は決定的なままになります。
