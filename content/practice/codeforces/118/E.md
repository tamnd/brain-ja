 ## 解決策
 ## 問題の理解

 バータウンの道路網を表す接続された無向グラフが与えられます。ジャンクションがノード、道路がエッジです。 現在、各道路では双方向の交通が許可されていますが、結果として得られる有向グラフが強いつながりを保つように、すべての道路に方向を割り当てるという使命があります。 強力な接続性とは、どのジャンクションからでも、一方通行の道路に沿って他のすべてのジャンクションに到達できることを意味します。 

入力サイズは重要です。最大 100,000 のジャンクションと 300,000 の道路が存在する可能性があります。 これは、n·m が 10^10 に達する可能性があり、5 秒の制限時間内に収まる値をはるかに超えているため、O(n + m) より悪い解は遅すぎる可能性が高いことを意味します。 したがって、道路方向のすべての順列をチェックする単純なアプローチは実行不可能です。 

明らかではないエッジケースは、サイクルとブリッジから発生します。 たとえば、無向グラフにブリッジ (削除するとグラフが切断されるエッジ) がある場合、強い接続性を維持するようにエッジの向きを変えることは不可能です。 簡単な例は、単一の橋で接続された三角形です。橋を任意の方向に向けると、反対方向への横断は不可能になります。 完全なグラフでは、別のエッジ ケースが発生します。つまり、すべてのエッジを周期的に方向付けることができ、強力な接続性が自然に維持されます。 

## アプローチ

 ブルートフォース手法では、考えられるすべてのエッジの向きを試し、結果として得られる有向グラフが強く接続されているかどうかを確認します。 これには 2^m 個の方向をチェックする必要があり、それぞれの DFS または BFS に O(n + m) 時間が必要です。 m が 3×10^5 までの場合、これは天文学的に遅くなります。 

重要な観察は、ブリッジが強力な接続を妨げているということです。 グラフにブリッジがある場合、ブリッジの向きが間違っていると、一方の端がもう一方の端に到達できなくなります。 したがって、最初のステップは、ブリッジが存在するかどうかを特定することです。 Tarjan のアルゴリズムは、DFS を実行し、検出時間と低リンク値を追跡することにより、O(n + m) 時間でブリッジを検出できます。 橋が見つかった場合、答えはすぐに 0 になります。 

ブリッジが存在しないことが分かると、無向グラフは 2 つのエッジで接続されます。 このシナリオでは、グラフが強く結びつくように方向を割り当てることが常に可能です。 シンプルな DFS ベースの構築が機能します。DFS 中に検出されたすべての木のエッジに対して、親から子への方向が設定されます。 バックエッジごとに、子から親への向きを設定します。 これにより、無向グラフ内のすべてのサイクルが有向サイクルになり、サイクルがコンポーネントをリンクするため、強力な接続が保証されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^m · (n + m)) | O(n + m) | 遅すぎる |
 | DFS + Tarjan ブリッジ | O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力エッジから無向グラフの隣接リストを構築します。 これは、DFS とブリッジ検出に使用する構造です。 
2. 検出時間を追跡するために配列を初期化します (`tin`)、到達可能な最短の検出時間 (`low`)、および各ノードの訪問済みフラグ。 
3. 任意のノード (ノード 1 など) から開始して DFS を実行し、ブリッジを検出します。 ノードごとに設定します`tin`そして`low`現在のタイマーに合わせて、未訪問の近隣を再帰的に訪問します。 アップデート`low`標準の Tarjan ブリッジ検出ルールに従った値。 何かエッジを見つけたら`low[neighbor] > tin[node]`、これはブリッジなので、すぐに 0 を返します。 
4. DFS 中に、エッジの方向を記録します。 ツリーのエッジは親から子の方向を向いています。 バック エッジは、現在のノードからその祖先の方向に向けられます。 入力順序を維持するために、エッジ インデックスをキーとする辞書に方向を格納します。 
5. DFS 後、ブリッジが見つからなかった場合は、保存されているエッジ方向を入力で指定された順序で出力します。 

機能する理由: ブリッジは、接続された無向グラフを強く接続された有向グラフに方向付ける唯一の障害です。 DFS を実行し、ツリーとバック エッジを記録することにより、すべてのエッジが一貫した方法でサイクルに沿って配置されます。 これにより、サイクルによって異なるパスを介した両方向のトラバースが可能になり、強力な接続が満たされるため、すべてのノードが他のすべてのノードに到達できることが保証されます。 

## Python ソリューション```python
import sys
sys.setrecursionlimit(10**6)
input = sys.stdin.readline

def main():
    n, m = map(int, input().split())
    adj = [[] for _ in range(n)]
    edges = []
    
    for i in range(m):
        a, b = map(int, input().split())
        a -= 1
        b -= 1
        adj[a].append((b, i))
        adj[b].append((a, i))
        edges.append((a, b))
    
    tin = [-1] * n
    low = [-1] * n
    timer = [0]
    visited = [False] * n
    res = [None] * m
    found_bridge = [False]
    
    def dfs(u, parent):
        visited[u] = True
        tin[u] = low[u] = timer[0]
        timer[0] += 1
        for v, idx in adj[u]:
            if v == parent:
                continue
            if visited[v]:
                low[u] = min(low[u], tin[v])
                if res[idx] is None:
                    res[idx] = (u + 1, v + 1)
            else:
                res[idx] = (u + 1, v + 1)
                dfs(v, u)
                low[u] = min(low[u], low[v])
                if low[v] > tin[u]:
                    found_bridge[0] = True
    
    dfs(0, -1)
    
    if found_bridge[0]:
        print(0)
    else:
        for p, q in res:
            print(p, q)

if __name__ == "__main__":
    main()
```隣接リストは各エッジをそのインデックスとともにキャプチャするため、後で入力順に出力できます。`tin`そして`low`配列は Tarjan のブリッジ検出を実装します。 DFS は、ツリーのエッジを親から子へ、バック エッジを現在のノードから祖先に向けます。 解決不可能な事件に対処するために橋を即座に検出します。 の`res`配列は方向マッピングを維持します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + m) | DFS は各ノードを 1 回訪問し、すべてのエッジをチェックします。 |
 | スペース | O(n + m) | DFS の隣接リスト、エッジ方向配列、および補助配列。 |

 この複雑さは制約内にうまく収まります。DFS を使用すると、105 個のノードと 3・105 個のエッジを 1 秒以内に効率的に処理できます。
