 ## 解決策
 ## 問題の理解

 私たちは、一定数の同じ種類の歩兵と騎兵で構成されるカエサルの兵士を並べる方法の数を数えるよう求められます。そうすれば、同じ種類の兵士が一定数以上連続しないようになります。 具体的には、それ以上の場合、`k1`従者が 1 列以上出現する`k2`騎手が連続して出現する場合、その並びは無効です。 同じタイプの各兵士は区別できないため、個々の ID ではなく、タイプの順序のみを考慮します。 目標は、有効なシーケンスの総数を 100,000,000 を法として計算することです。 

入力は 4 つの整数で構成されます。`n1`そして`n2`(歩兵と騎手の数)、および`k1`そして`k2`(連続して許可される歩兵と騎兵の最大数)。 出力は、すべての有効なラインナップの数を表す単一の整数です。 

制約は十分に小さいため、動的プログラミング ソリューションが可能になります。 と`n1`そして`n2`100 までは、3 次複雑度のアルゴリズムは潜在的に危険ですが、2 次複雑度は安全です。 以来`k1`そして`k2`が最大 10 であれば、状態空間を爆発させることなく連続したカウントを効率的に追跡できます。 

明らかではないエッジケースは、次のいずれかの場合に発生します。`n1`または`n2`対応するものより小さい`k`。 たとえば、次の場合`n1 = 1`、`n2 = 2`、`k1 = 10`、`k2 = 1`、常にシーケンスを最大まで拡張しようとする単純なロジック`k1`利用可能なフットマンの数を超えるシーケンスが生成される可能性があります。 もう 1 つのエッジケースは次のような場合です`k1 = k2 = 1`と兵士は厳密に交代します。 これが欠けていると、off-by-one エラーが発生します。 

## アプローチ

 ブルートフォースアプローチでは、長さのすべてのシーケンスが生成されます。`n1 + n2`まさに`n1`フットマンと`n2`次に、連続制限に違反するシーケンスを除外します。 これは正しいですが、実行不可能です。 系列の数は二項係数です`C(n1 + n2, n1)`非常に急速に成長します。 のために`n1 = n2 = 100`、これは天文学的に大きく、およそ 10 ^ 58 であり、あらゆる計算能力をはるかに超えています。 

重要な洞察は、この問題には明確な再帰構造を持つ重複する部分問題があるということです。 左から右へ有効なシーケンスを構築することを検討してください。 最後のグループが歩兵である場合、連続して何人の歩兵がすでに配置されているかがわかります。 次の兵士はこのグループを継続することができます (到達していない場合)`k1`）または騎手に切り替える。 これは当然、動的プログラミングに適しています。 私たちは定義します`dp[f][h][last]`有効なシーケンスの数として次を使用します。`f`フットマンと`h`騎手、長さの連続したグループで終わる`last`現在のタイプのもの。 拡張されるタイプの連続カウントを追跡する必要があるだけで、歩兵と騎兵を再帰的に切り替えます。 

これらのサブ問題をメモ化することで、指数関数的なブルート フォースの複雑さを管理可能な 3 次 DP まで削減します。`O(n1 * n2 * max(k1, k2))`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(C(n1+n2, n1)) | O(n1+n2) | 遅すぎる |
 | 最適 | O(n1 * n2 * max(k1, k2)) | O(n1 * n2 * 2) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 3D DP 配列を初期化する`dp[f][h][t]`、 どこ`f`残りのフットマンは、`h`残っている騎手たちは、`t`最後に追加された兵士が歩兵 (0) であるか騎兵 (1) であるかを示します。 各エントリには、その状態の有効なシーケンスの数が格納されます。 
2. 基本的なケースは、次のいずれかの場合です。`f = 0`または`h = 0`。 もし`f = 0`、最大でも長さの騎手シーケンスのみを追加できます。`k2`、同様に`h = 0`フットマンと一緒に。 兵士タイプごとに長さ 1 のシーケンスを初期化します。 
3. 各 DP 状態について`(f, h, t)`、連続制限を超えていない場合は、同じタイプでシーケンスを拡張することを検討するか、他のタイプに切り替えることを検討してください。 すべての有効な内線番号からのカウントを蓄積します。 
4. 連続する兵士の可能なすべてのカウントを最大まで繰り返します。`k1`フットマンと`k2`シーケンスを拡張するときに、異なる連続長で終了するシーケンスを考慮するための騎手用。 
5. DP を埋めた後、正確に対応するすべての状態を合計します。`n1`フットマンと`n2`騎兵、歩兵または騎兵で終わる。 
6. 100,000,000 を法とした結果を返します。 

これが機能する理由は、DP 状態が副問題、つまり残りの兵士と最後の連続グループの種類/長さを完全に把握しているためです。 すべての有効なシーケンスは、ルールに従ってフットマンまたはホースマンを追加することによって構築できます。 二重カウントや順序の省略はありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 100000000

def solve():
    n1, n2, k1, k2 = map(int, input().split())
    
    # dp[f][h][t] = number of sequences with f footmen, h horsemen, last type t
    dp = [[[0, 0] for _ in range(n2+1)] for _ in range(n1+1)]
    
    dp[1][0][0] = 1  # first soldier is footman
    dp[0][1][1] = 1  # first soldier is horseman
    
    for f in range(n1+1):
        for h in range(n2+1):
            # add footmen
            for l in range(1, k1+1):
                if f >= l:
                    dp[f][h][0] += dp[f-l][h][1]
                    dp[f][h][0] %= MOD
            # add horsemen
            for l in range(1, k2+1):
                if h >= l:
                    dp[f][h][1] += dp[f][h-l][0]
                    dp[f][h][1] %= MOD
    
    result = (dp[n1][n2][0] + dp[n1][n2][1]) % MOD
    print(result)

solve()
```この実装では、両方のタイプの最初の兵士ケースを事前に入力します。 ネストされたループは、制限までのすべての可能な連続長を処理します。`k1`そして`k2`。 各 DP エントリは、反対のタイプで終わるシーケンスからの寄与を結合し、連続した制約が確実に尊重されるようにします。 モジュロ演算によりオーバーフローが防止されます。 Off-by-one エラーは、慎重にインデックスを作成することで回避されます。`dp[f-l][h][1]`ゼロ以下の減算が決して行われないようにします。 

## 実用的な例

 **サンプル 1:**`2 1 1 10`| f | h | dp[f][h][0] | dp[f][h][1] |
 | --- | --- | --- | --- |
 | 1 | 0 | 1 | 0 |
 | 0 | 1 | 0 | 1 |
 | 2 | 0 | 0 | 0 |
 | 1 | 1 | 1 | 1 |
 | 2 | 1 | 1 | 0 |

 結果は 1 です。シーケンス 121 のみが有効です。 この表は、シーケンスが連続フットマン制限 1 に違反していないことを確認します。 

**サンプル 2:**`2 3 2 1`DP は、連続する最大 2 人の歩兵と 1 人の騎手に関するシーケンスを蓄積します。 有効なシーケンスは 12121、21212、12112、21211 で、交互の制限が正しく処理されていることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n1 * n2 * max(k1, k2)) | トリプルループ: それぞれ`f`、`h`、連続する長さまでループします。`k1`または`k2`|
 | スペース | O(n1 * n2 * 2) | 歩兵、騎兵、最後のタイプの 3D 配列 |

 このアルゴリズムは、2 秒の制限時間と 256 MB のメモリ内に快適に収まります。 のために`n1 = n2 = 100`そして`k1 = k2 = 10`、操作数は約 200,000 で、許容範囲です。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()
    solve()
    return sys.stdout.getvalue().strip()

# Provided samples
assert run("2 1 1 10\n") == "1", "sample 1"
