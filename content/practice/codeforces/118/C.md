 ## 解決策
 ## 問題の理解

 車の番号を表す数字の列が与えられます。 少なくとも次の場合、その数字は美しいとみなされます。`k`位置に同じ数字が含まれています。 任意の数字を別の数字に変更したり、数字を変更したりする場合があります`a`数字に変換する`b`費用`|a - b|`。 

このタスクには 2 つの目的があります。 まず、総改造コストを最小限に抑えます。 次に、すべての最小コストの答えの中で、辞書順に最小の結果文字列を返します。 

入力サイズが十分小さいため、ターゲットの数字をすべて試すことができます。`0`に`9`。 文字列の長さは最大でも`10^4`、したがって、周りの解決策`O(10 * n log n)`または`O(10 * n)`完全に安全です。 すべての位置に対する 2 次アプローチもここでは合格しますが、辞書編集上のタイブレークは微妙であるため、ロジックを慎重に設計する必要があります。 

難しいのは、最小コストを計算することではありません。 難しいのは、すべての最小コストのソリューションの中で辞書編集的に最小の答えを導き出すことです。 

次の例を考えてみましょう。```
4 3
9090
```3 桁を次と等しくすると決めた場合`0`1 つだけ変更する必要があります`9`の中へ`0`、 料金`9`。 選択肢は 2 つあります。```
0090
9000
```どちらもコストは同じですが、`0090`辞書編集的には小さいです。 常に左端の可能な数字を最初に変更するという不注意で貪欲な戦略は、他のターゲットでは失敗する可能性があります。 

もう 1 つの微妙なケースは、ターゲットより小さい桁とターゲットより大きい桁を変換するときに発生します。 

例：```
5 4
12345
```対象の数字が`3`。 

変化`2 -> 3`そして`4 -> 3`それぞれの費用`1`。 

変化`1 -> 3`そして`5 -> 3`それぞれの費用`2`。 

等コストのソリューションの中で辞書編集的に最小の結果を取得するには、次のことを行う必要があります。 

大きい桁を左から右に変更します。先に桁を減らすと文字列が小さくなります。 

ただし、前の桁を増やすと文字列が大きくなるため、小さい桁を右から左に変更します。 

多くの誤った解決策はこの非対称性を見逃しています。 

もう 1 つのエッジ ケースは、文字列に少なくとも次のものが既に含まれている場合です。`k`等しい数字。 

例：```
6 4
777712
```正解はコストです`0`そして元の文字列自体。 に達した後も数字を変更し続けるアルゴリズム`k`何かが起こると、誤って答えが悪化する可能性があります。 

## アプローチ

 強引なアイデアは簡単です。 対象桁ごとに`d`から`0`に`9`、変換する位置の可能なすべてのサブセットを試します。`d`、合計コストを計算し、最良の結果を維持します。 

最終的な美しい数字は少なくとも表示される数字を選択する必要があるため、これは概念的に機能します。`k`回。 その桁が固定されると、変更されたすべての位置が独立してコストに影響します。 

問題はサブセットの数です。 まだ等しくない立場だけを考えても`d`、まだおおよその可能性があります`2^n`可能性。 と`n = 10^4`、これは絶望的です。 

重要な観察は、コストは桁の距離のみに依存するということです。 ターゲットの数字が`d`、次に距離を使って数字を変換します`1`数字を距離で変換するよりも常に優れています`2`。 

つまり、各ターゲット桁について、コストの昇順で貪欲にポジションを取る必要があります。 

最初に距離のあるすべての数字`1`、

 それから距離`2`、

等々。 

これにより、総コストが即座に最小限に抑えられます。 

可能な最小コストを修正した後も、辞書編集上最小の文字列が必要になります。 これにより、貪欲の第 2 層が導入されます。 

より大きい桁を変換するとします。`d`。 大きな数字を小さな数字に置き換えると、文字が減ります。 これを文字列の前半で実行すると、辞書編集上の順序が改善されるため、これらの位置を左から右に処理する必要があります。 

より小さい桁の場合`d`, 置き換えるとキャラクターが増えます。 前の文字を増やすと辞書編集上の順序が損なわれるため、これらの位置を右から左に処理する必要があります。 

これにより、各ターゲット桁に対してクリーンな貪欲な構造が得られます。 

ターゲットとなる 10 桁すべてを試し、それぞれに対して可能な限り最適な文字列を構築し、次を選択します。 

まず最小コストから、

 次に辞書編集的に最小になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(10・2^n) | O(n) | 遅すぎる |
 | 最適 | O(10・n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 文字列内に各数字がすでに出現している回数を数えます。 

数字の場合`d`少なくともすでに登場している`k`このターゲットのコストはすぐに計算されます。`0`。 
2.対象桁ごとに`d`から`0`に`9`、追加で必要なコピーの数を計算します。 

させて：```
need = k - count[d]
```もし`need <= 0`、現在の文字列はすでにこの数字の条件を満たしています。 
3. 文字列の変更可能なコピーを作成します。 

徐々に数字を次のように変換していきます`d`。 
4. からの距離を処理する`1`に`9`。 

あらゆる距離に対して`dist`、有用なソース数字は最大 2 つです。`d - dist`そして`d + dist`。 

これらはまさにコンバージョンコストが等しい数字です`dist`。 
5. より大きい数字を最初に処理します。`d`。 

もし`d + dist <= 9`、文字列を左から右にスキャンします。 

数字を見るたびに`d + dist`さらに多くのコピーが必要です`d`に置き換えてください`d`。 

大きい数字を小さい数字に置き換えると、文字列が辞書編集的に早く小さくなるため、左から右への入力が最適です。 
6. 次に、以下の桁を処理します。`d`。 

もし`d - dist >= 0`、文字列を右から左にスキャンします。 

数字を見るたびに`d - dist`さらにコピーが必要な場合は、次のように置き換えます。`d`。 

ここでは桁を増やしています。 これらの増加をできるだけ右に遅らせると、文字列が辞書編集的に小さくなります。 
7. 置き換えるたびに追加される`dist`総コストと減少`need`1つずつ。 

一度止めてください`need`ゼロになります。 
8. 構築された候補を現在のグローバルベストと比較します。 

総コストは小さい方が良い。 

コストが同じである場合は、辞書編集的に小さい文字列を優先します。 

### なぜ効果があるのか

 固定対象桁の場合`d`、最小コスト戦略は常に、からの距離が大きい順にポジションを取る必要があります。`d`。 より短い距離が利用可能な場合に、より長い距離を使用するソリューションは、すぐに改善できます。 

すべての最小コストの選択肢の中で、辞書編集上の順序は、どの位置が変更されるかによってのみ決まります。 前の桁を減らすと辞書編集上の順序が向上しますが、前の桁を増やすと順序が損なわれます。 そのため、大きな数字は左から右に変更され、小さな数字は右から左に変更されます。 

考えられるすべてのターゲット桁に対して最適な答えを個別に計算するため、それらの候補の中の全体的な最小値が最適な最終的な答えになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    s = input().strip()

    best_cost = float('inf')
    best_string = ""

    for target in range(10):
        cnt = s.count(str(target))
        need = k - cnt

        cur = list(s)
        cost = 0

        if need > 0:
            for dist in range(1, 10):
                if need == 0:
                    break

                bigger = target + dist
                if bigger <= 9:
                    for i in range(n):
                        if need == 0:
                            break
                        if int(cur[i]) == bigger:
                            cur[i] = str(target)
                            cost += dist
                            need -= 1

                smaller = target - dist
                if smaller >= 0:
                    for i in range(n - 1, -1, -1):
                        if need == 0:
                            break
                        if int(cur[i]) == smaller:
                            cur[i] = str(target)
                            cost += dist
                            need -= 1

        candidate = ''.join(cur)

        if cost < best_cost:
            best_cost = cost
            best_string = candidate
        elif cost == best_cost and candidate < best_string:
            best_string = candidate

    print(best_cost)
    print(best_string)

solve()
```外側のループは、最後の反復桁として考えられるすべての桁を試行します。 10 桁しかないため、この部分は事実上定数です。 

変数`need`ターゲット数字のコピーがまだ必要な数を追跡します。 それがゼロになると、現在の候補が完了します。 

変更の順序は、実装の中で最もデリケートな部分です。 

大きな数字をターゲットに変換するときは、左から右にスキャンします。```
for i in range(n):
```前の桁を減らすと辞書編集上の順序が改善されるためです。 

小さい桁をターゲットに変換するときは、右から左にスキャンします。```
for i in range(n - 1, -1, -1):
```辞書編集的には、後の桁を増やす方が害が少ないからです。 

もう 1 つの微妙な詳細は、次のように変更します。`cur`、元の文字列ではありません`s`。 元の数は、最初に必要な置換の数を決定するためにのみ使用されます。 

比較ステップでは、最初にコストをチェックし、次に辞書順をチェックする必要があります。 Python の文字列比較では、辞書編集上の順序付けがすでに正しく実装されています。
