 ## 解決策
 ## 問題の理解

 列の柱が与えられ、それぞれの柱には最初はちょうど 1 つのディスクが保持されています。 各ディスクには個別の半径があるため、入力は位置 1 から n に配置された 1 から n までの値の並べ替えとして考えることができます。 

唯一許可される移動は非常に制限されています。 ディスクは、ピラーから隣接するピラーに移動できますが、現在のピラーにディスクが 1 つだけ存在する場合に限ります。 さらに、別の柱に配置する場合は、空の柱に着地するか、厳密に大きな円盤の上に着地する必要があります。 これにより、ディスクを半径の小さい順にのみ配置できるというスタッキング制約が作成されます。 

問題は、これらの隣接する単一ディスクの移動のみを使用して、最終的にすべてのディスクを単一の柱に集めることが可能かどうかです。 

n が 2 · 10^5 までの制約により、実際の動きのシミュレーションから遠ざけられます。 ディスクを段階的に明示的に移動させようとするアプローチは、ディスクが多くの位置を横断する可能性があり、それぞれの移動がローカルであるため、二次的な動作を行う危険性があります。 

微妙な難点は、「現在ディスクが 1 つだけある柱からのみディスクを移動できる」という移動制限により、任意の再配置が妨げられていることです。 これを自由なソートプロセスとして扱おうとすると、いつでも中間位置を介してディスクを往復できると誤って仮定することになります。 実際には、中間の構成が将来の動きを妨げる可能性があります。 

一般的な失敗例は、隣接関係の制約を無視して貪欲にスタッキングすることに起因します。 たとえば、一貫した外側への拡張で小さなディスクを剥がすことができるように大きなディスクが配置されていない場合、単純な貪欲な順序付けでは有効な減少シーケンスが生成されますが、必要な中間ピラーの一部に一時的に複数のディスクが含まれることが無視され、移動が不正になります。 

したがって、最も難しいのは、ディスクを順序付けることではなく、シングルトンとして移動できない構成内で隣接性制約によってディスクがトラップされないようにすることです。 

## アプローチ

 強引なアイデアは、構成上で BFS を使用してすべての有効な動きをシミュレートすることです。 各状態はスタックの完全な配置を表し、各遷移は有効なディスクを隣接ディスクに移動します。 これは、到達可能なすべての構成を調査するため、理論的には正しいですが、状態の数は天文学的に多くなります。 適度な n の場合でも、ピラー全体にディスクを積み重ねる方法の数は指数関数的に増加するため、このアプローチは完全に実行不可能になります。 

重要な洞察は、実際には一連の動きを構築する必要がないということです。 有効なシーケンスが存在するかどうかを判断することだけが必要です。 隣接制約は構造的特性を意味します。つまり、どの時点でも、まだ移動されていないディスクのセットが現在の構築プロセスの周囲に連続した領域を形成する必要があります。 さらに重要なのは、単一ディスクの柱からしか移行できないため、最終スタックを構築するプロセスは、アレイを両端から内側に剥がすように動作することです。 

これは簡素化につながります。 ターゲットの最終ピラーを暗黙的に選択し、すべてのディスクを単一の減少するスタックに「収集」できるかどうかをシミュレートしようとします。 ディスクは降順で終わる必要があるため、最大のディスクが最終構造の最初の固定要素でなければなりません。 それをベースとして配置した後、残りのすべてのディスクを降順で接続する必要があり、各ステップで、残りのセグメントの現在の端の 1 つから次のディスクを取得することのみが許可されます。 これは、「シングルトン ソース ピラー」制約に違反せずに到達可能なのはエンドポイントのみであるためです。 

したがって、問題は、最大要素の位置から開始して外側に拡張できるかどうかを確認し、最後に選択したディスクよりも小さい隣接する未処理の要素を常に選択できるかどうかを確認することに帰着します。

 ## アルゴリズムのチュートリアル

 まず、最大半径ディスクの位置を特定します。 このディスクより上に位置するより大きなディスクが存在しないため、このディスクが最終スタックの開始点になる必要があります。 

次に、2 つのポインターを維持します。1 つはこの位置から左に拡張し、もう 1 つは右に拡張します。 また、最終的な順序で最後に選択されたディスクを追跡する変数も維持します。最初は最大ディスクに設定されます。 

各ステップで、現在の境界にある 2 つの候補を検討します。 最終的なスタックは厳密に減少する必要があるため、候補の半径が最後に選択した値よりも厳密に小さい場合にのみ候補を選択できます。 有効な候補の中から、大きい方を選択します。 この選択は重要です。なぜなら、より小さい値を選択するのが早すぎると、後でより大きな有効な候補へのアクセスがブロックされる可能性がある一方で、貪欲な選択により柔軟性が保たれるからです。 

すべての要素が消費されるまで、またはどちらの境界候補も有効でなくなるまで、拡張を続けます。 

終了後、すべてのディスクが正常に含まれていれば答えは「YES」、それ以外の場合は「NO」になります。 

正確さは、すでに選択されたシーケンスが常に厳密に減少しており、最大要素を中心とする元の配列内の連続セグメントに対応するという不変式に依存します。 残りのすべての候補はこのセグメントに隣接しているため、有効な完全な構成が存在する場合は、各ステップで降順に違反しない有効な境界の選択が常に存在します。 貪欲な選択により、必要なより大きな要素が時期尚早に破棄されることがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    mx = max(range(n), key=lambda i: a[i])
    last = a[mx]

    l = mx - 1
    r = mx + 1

    used = 1

    while used < n:
        left_val = a[l] if l >= 0 else -1
        right_val = a[r] if r < n else -1

        valid_left = l >= 0 and left_val < last
        valid_right = r < n and right_val < last

        if not valid_left and not valid_right:
            print("NO")
            return

        if valid_left and valid_right:
            if left_val > right_val:
                last = left_val
                l -= 1
            else:
                last = right_val
                r += 1
        elif valid_left:
            last = left_val
            l -= 1
        else:
            last = right_val
            r += 1

        used += 1

    print("YES")

if __name__ == "__main__":
    solve()
```コードは最初に最大要素インデックスを特定し、その周囲の拡張境界を初期化します。 ループは、厳密に減少する条件を維持しながら、選択したセグメントを外側に拡張します。 

重要な実装の詳細は、慎重な境界処理です。一方の側が使い果たされた場合、それを候補として考慮してはなりません。 もう 1 つの微妙な点は、比較で厳密な不等式を使用することです。`last`、問題ステートメントによって等しい値は不可能ですが、条件は依然として構造的に正しさを強制するためです。 

左と右の間の貪欲な選択は、それらの値を直接比較することによって実装され、常により大きな実現可能な境界値に向かって拡張されます。 

## 実用的な例

 次のサンプル入力を考えてみましょう。```
4
1 3 4 2
```まず、インデックス 2 で最大の要素 4 を見つけます。 

| ステップ | 左ポインタ | 右ポインタ | 最後に選択した | アクション |
 | --- | --- | --- | --- | --- |
 | 初期化 | 1 | 3 | 4 | 最大値から開始 |
 | 1 | 1 | 3 | 4→3 | 右折 (3) |
 | 2 | 1 | 4 | 3→2 | 右折 (2) |
 | 3 | 1 | 4 | 2→1 | 左に進みます (1) |

 すべての要素が正常に消費され、実現可能性が確認されました。 

次に、失敗するスタイルの配置を考えてみましょう。```
4
4 1 3 2
```インデックス 0 の 4 から開始します。 

| ステップ | 左ポインタ | 右ポインタ | 最後に選択した | アクション |
 | --- | --- | --- | --- | --- |
 | 初期化 | -1 | 1 | 4 | 開始 |
 | 1 | -1 | 1 | 4→1 | 右を取らなければなりません |
 | 2 | -1 | 2 | 1 → 3 無効 | 立ち往生 |

 ステップ 2 では、最後に選択した値 1 より大きい 3 を選択することはできず、有効な左移動がありません。 プロセスは早期に停止するため、答えは「NO」です。 

これらのトレースは、実現可能性は、外側への貪欲な拡張が常に減少する境界拡張を見つけられるかどうかに依存することを示しています。

 ## 特殊なケース

 主なエッジケースは、最大要素が極端な位置にある場合です。 その状況では、展開は即座に一方的なものになり、アルゴリズムは、欠落している側にアクセスしようとせずに、欠落している側を無効として正しく処理する必要があります。 

もう 1 つの微妙なケースは、両方の側が有効であるにもかかわらず、早い段階で間違った側を選択しても局所的には正しいように見える場合です。 利用可能なより大きな近傍を常に選択するという貪欲なルールにより、拡張の実行可能性を維持するために後で必要になる可能性のある小さな値を時期尚早に消費することがなくなります。 

最後の重要なケースは、有効な動きがいくつかのステップにわたって存在するが、最終的には行き止まりにつながる構成です。 ステップバイステップの境界シミュレーションにより、実際のプロセスで正当なディスク移動が不可能になる瞬間を反映して、両側が減少制約を満たさなかったときにアルゴリズムが正確にこれを検出することが保証されます。
