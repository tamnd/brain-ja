 ## 解決策
 ## 問題の理解

 一連の数値が与えられ、特定のスコア関数を最大化するために、連続するセグメントを 1 つ選択するか、何も選択しないように求められます。 選択されたセグメントのスコアは、その単純な合計から、その長さだけに依存するペナルティを引いたものになります。 ペナルティはサイズのブロック数に比例します`m`セグメントをカバーするには必要であり、各ブロックにはコストがかかります`k`。 

したがって、単純な最大部分配列合計の代わりに、追加されるすべての`m`要素は効果的に別の演繹を引き起こします`k`。 これにより、問題は標準的な Kadane スタイルの最適化のように動作しますが、長さが の倍数を横切る場合にのみ段階的にコストが変化します。`m`。 

出力は単一の整数です。これは、何も選択しないオプション (結果が 0) を含む、すべての可能なサブ配列に対して達成可能な最高のスコアです。 

この制約により、二次解またはそれより悪い解は即座に除外されます。 と`n`最大 300,000 の場合、すべてのサブ配列を試したり、サブ配列ごとの合計を再計算したりするアプローチは、制限時間を数桁超えてしまいます。 私たちは、何らかの形式の動的プログラミングを使用して、線形または線形に近いスキャンを行うことを余儀なくされています。 

微妙な問題は、ペナルティの長さが直線的ではないことです。 セグメントの長さが の倍数を横切る場合にのみ変化します。`m`。 これにより、標準的なカダンの定式化が崩れる不連続性が生じます。 

いくつかのエッジな状況が問題を明確に示しています。 

すべての数値が負の場合、単純な最大部分配列合計は最小の負のセグメントを返しますが、ここでは空の部分配列が許可され、ゼロが得られるため、答えがゼロを下回ることはありません。 

もし`m = 1`の場合、すべての要素の値からマイナスの値が寄与します。`k`、問題を変換された値の標準的な最大部分配列合計に変換します。`a[i] - k`。 この縮退を認識できないソリューションはまだ機能する可能性がありますが、有用な健全性チェックを提供します。 

ペナルティが要素間で均等に分散できると仮定すると、別の障害モードが発生します。 たとえば、減算しようとすると、`k/m`天井により境界でジャンプが作成されるため、要素ごとの値は正しくありません。 

## アプローチ

 ブルートフォースのアイデアは単純です。すべての部分配列を列挙し、その合計を計算し、その長さを計算し、上限式を使用してペナルティを評価し、最大値を追跡します。 これは定義に直接従うため、正しいです。 ただし、大まかには、`O(n^2)`サブ配列、および O(1) の範囲合計を計算するためのプレフィックス合計を使用した場合でも、候補の評価に二次関数の時間を費やします。 と`n = 3e5`、これはまったく不可能です。 

重要な観察は、ペナルティが部分配列の長さにのみ依存し、固定された右端点を拡張するにつれて長さが単調に増加するということです。 これは、各位置で終わるサブ配列の最良のスコアを維持する、プレフィックスに対する動的プログラミングの定式化を示唆しています。 

位置で終了する最適なサブ配列を表す実行中の DP 状態を定義します。`i`。 部分配列を要素 1 つ拡張すると、合計は次のように増加します。`a[i]`, ただし、次の倍数を超えるかどうかに応じて、ペナルティが増加する場合と増加しない場合があります。`m`。 ここが重要なポイントです。各ブロックのサイズ内で`m`、ブロックがいっぱいになるまで、要素を追加しても追加のペナルティはありません。 

この構造は、モジュロで取得された要素の数によって答えを個別に追跡することを示唆しています。`m`。 それぞれのポジションごとに、`m`現在のサブ配列長のモジュロに対応する DP 状態`m`。 1 つの要素によって拡張する場合、これらの状態の間で遷移します。これは、要素からラップする場合にのみ行われます。`m-1`に戻る`0`追加料金がかかりますか`k`。 

これにより、問題はアレイ全体にわたる小規模な状態の DP に縮小され、線形の解決策が得られます。

 ## アルゴリズムのチュートリアル

 DP 状態を維持します`dp[r]`、 どこ`r`現在選択されている部分配列の長さを法で表します`m`。 各状態は、現在のインデックスで終わる部分配列とその残りの最大の合計の差を保存します。 

また、空のサブ配列が有効であり、前のセグメントを拡張する必要がないため、任意の位置から再開することもできます。 

### ステップ

 1. すべての DP 状態を非常に負の値に初期化し、グローバル応答をゼロに設定します。 これは、サブ配列をまったく選択しないというオプションの説明になります。 
2. 配列を左から右に繰り返し、各位置をサブ配列の潜在的なエンドポイントとして扱います。 
3. 各要素で`a[i]`、この要素のみからなる新しい部分配列を開始することを検討します。 この新しい部分配列には長さがあります`1`、貢献します`a[i]`まだペナルティはありません。 
4. 以下を追加することで、以前のすべての DP 状態を拡張することも検討します。`a[i]`。 状態を剰余で拡張すると`r`、新しい余りは次のようになります`(r + 1) % m`。 
5. 新しい余りが得られたとき`0`、サイズのブロックが完成したことを意味します`m`, したがって、減算します`k`累積値から。 これは、段階的な上限ペナルティをエンコードします。 
6. 遷移を更新した後、どの終了部分配列も最適である可能性があるため、すべての DP 状態で答えを更新します。 
7. 配列の最後まで続けます。 

### なぜ効果があるのか

 DP 状態は、現在のインデックスで終わるすべてのサブ配列を暗黙的に追跡し、次の倍数を超える要素の数によってグループ化します。`m`現在はそうなっています。 サブ配列が倍数を超えて増大するたびに、`m`、ちょうど 1 つの追加ペナルティ`k`が適用され、天井の定義と一致します。 すべてのサブ配列は新たに開始されるか、以前の有効なサブ配列から拡張されるため、すべての可能性がカバーされます。 コストは正確な境界交差でのみトリガーされ、剰余がゼロにリセットされる遷移に正確に対応するため、遷移ではペナルティが二重にカウントされることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    a = list(map(int, input().split()))
    
    NEG = -10**30
    
    dp = [NEG] * m
    ans = 0
    
    for x in a:
        new_dp = [NEG] * m
        
        # start new subarray
        new_dp[1 % m] = max(new_dp[1 % m], x)
        
        # extend previous subarrays
        for r in range(m):
            if dp[r] == NEG:
                continue
            nr = (r + 1) % m
            val = dp[r] + x
            if nr == 0:
                val -= k
            new_dp[nr] = max(new_dp[nr], val)
        
        for r in range(m):
            dp[r] = max(dp[r], new_dp[r])
            ans = max(ans, dp[r])
    
    return ans

if __name__ == "__main__":
    print(solve())
```DP アレイ`dp[r]`現在の位置で終わるサブ配列の最良の値を、以下に一致する長さで格納します。`r mod m`。 トランジションは、新しいセグメントの開始と古いセグメントの延長の両方を明示的に処理します。 の引き算`k`まさにいつ`nr == 0`天井関数の動作をエンコードします。 

の使用`NEG`無効な状態が遷移を妨げないようにします。 継続的に合併していきます`new_dp`の中へ`dp`これにより、すべてのサブ配列を後の位置で拡張できるようになります。 

## 実用的な例

 次のサンプル入力を考えてみましょう。```
n = 7, m = 3, k = 10
a = [2, -4, 15, -3, 4, 8, 3]
```最も関連性の高い州のみを追跡します。 

| 私 | a[i] | 前の dp | キートランジション | |後の dp 答え |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 2 | すべてNEG | 開始 [2] | r=1:2 | 2 |
 | 2 | -4 | r=1:2 | 延長 → -2 | r=2:-2 | 2 |
 | 3 | 15 | r=2:-2 | 延長 +15 → 13 (ペナルティなし) | r=0:13-10=3、15 から開始 | 15 |
 | 4 | -3 | ... | 最良の拡張 r=0 → 0 | r=1:0 | 15 |
 | 5 | 4 | ... | r=1 → 4 を拡張 | r=2:4 | 15 |
 | 6 | 8 | ... | r=2 → 12-10=2 を拡張 | r=0:2 | 15 |
 | 7 | 3 | ... | r=0 → 5 を拡張 | r=1:5 | 15 |

 トレースは、一定のサイズのブロックを完了した場合にのみペナルティがどのようにアクティブになるかを示しています`m`、そして優れたセグメントがコストを支払う前に複数の要素を蓄積できる方法。 

2 番目の簡単な例:```
a = [5, -1, -1], m = 2, k = 3
```ここで最高のセグメントは`[5, -1]`費用がかかる`4 - 3 = 1`、長さが 2 に達したとき、DP はペナルティを正確にキャプチャします。

 ## 特殊なケース

 配列が完全に負の場合、各 DP 状態は引き続き負の値を蓄積する可能性がありますが、アルゴリズムは常にゼロと比較し、空のサブ配列が最適なままであることを保証します。 たとえば、`[-5, -2]`、拡張ごとにスコアが減少し、DP 状態がゼロを超えることはないため、答えは正しく残ります。`0`。 

いつ`m = 1`、すべての新しい要素はすぐにブロックを完成させます。 DP トランジションの減算`k`すべてのステップで、式に一致します`a[i] - k`。 したがって、このアルゴリズムは、変換された値に対して Kadane のアルゴリズムとまったく同じように動作し、状態圧縮によってこの特殊なケースが崩れることはありません。 

最適なセグメント長が倍数でない場合`m`、DP はまだ部分的な残りを追跡します。 減算は剰余がゼロに戻った場合にのみ行われるため、最後の不完全なブロックには追加のペナルティがかかりません。 これにより、セグメントが適切な長さになることが保証されます。`m + 1`上限の定義と正確に一致して、2 回ではなく 1 回だけ請求されます。
