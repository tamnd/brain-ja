 ## 解決策
 ## 問題の理解

 非減少配列が与えられ、それを正確に分割するように求められます。$k$連続した部分。 各部分のコストは、その最大の要素と最小の要素の差に等しいコストに寄与します。配列はソートされているため、これは単にそのセグメント内の最後の要素と最初の要素の差になります。 

課題は選択することです$k-1$これらのセグメント範囲の合計が最小になるように位置をカットします。 

制約は次のとおりです$n = 3 \cdot 10^5$これにより、カットを配置するあらゆる方法を試したり、二次動的計画法を使用したりするアプローチは即座に除外されます。 それを超えたもの$O(n \log n)$実際にはタイムアウトになるリスクがあり、$O(n^2)$セグメント境界を越える DP は遅すぎます。 

この問題の微妙な側面は、「セグメントに分割」しているにもかかわらず、コストが内部構造ではなくセグメントのエンドポイントのみに依存することです。 これは、カットをどこに配置するかによって全体の最適化が左右されることを意味します。 

素朴な直観が失敗するケースの 1 つは、隣接する差分が全体的に最も大きい場所をカットする必要があると仮定することです。 たとえば、最大のものを取ると、$k-1$これらのギャップがセグメント形成とどのように相互作用するかを考慮しない場合、ギャップは常に機能するとは限りません。各カットは、独立してコストを追加するのではなく、セグメント範囲への内部寄与を除去するためです。 

もう 1 つの落とし穴は、ローカルな決定を使用した左から右への貪欲なセグメンテーションが最適であると考えていることです。 ローカル最小範囲セグメントは、より適切なグローバル パーティションをブロックする可能性があります。 

## アプローチ

 ブルートフォースソリューションでは、あらゆる方法で配置を試みます。$k-1$間のカット$n-1$可能性のあるギャップ。 各構成はパーティションを定義し、そのコストを計算します。$O(n)$、につながる$O(\binom{n}{k} \cdot n)$、たとえ小規模であっても完全に実行不可能です。$n$。 

より構造化された DP アプローチでは次のように定義されます。$dp[i][j]$プレフィックスを分割するための最小コストとして$1 \dots i$の中へ$j$セグメント。 移行するには、以前のすべてのカットポイントを試す必要があります。$O(n^2 k)$単純な形での時間ですが、それでも限界を超えています。 

重要な観察は、配列がソートされているため、2 つの隣接するセグメントをマージすると、常に予測可能な方法でコストが変化するということです。 配列全体を 1 つのセグメントとすると、コストは次のようになります。$a_n - a_1$。 私たちが間を分けるたびに$i$そして$i+1$、接続の寄与を効果的に「除去」します。$a_i$に$a_{i+1}$、これら 2 つの要素は同じセグメントに属さなくなったためです。 

アレイが 1 セグメントの場合、コストにはスパン全体が含まれます。 各カットの位置$i$ギャップ寄与を除去します$(a_{i+1} - a_i)$。 したがって、セグメントの構築について考える代わりに、フルスパンから開始して、削減によって得られる節約を差し引くことを考えることができます。 

コストを最小限に抑えるために、削除される寄与の合計を最大化したいと考えています。これは、$k-1$最大の隣接差。 

これにより、問題は単純な並べ替え選択問題に変換されます。$n-1$価値観。

 ## アルゴリズムのチュートリアル

 1. 隣接するすべての差分を計算する$d_i = a_{i+1} - a_i$のために$1 \le i < n$。 

これらは、間にカットを配置した場合の潜在的な節約を表しています。$i$そして$i+1$。 
2. 総コストを次のように計算します。$a_n - a_1$。 

これは、まったく分割しない場合のコストに相当します。 
3. 相違点のリストを降順に並べ替えます。 

これにより、最も有益なカット位置を最初に選択できるようになります。 
4. 最大値の合計を取る$k-1$違い。 

選択されたそれぞれの差異は、総コストを削減する削減に対応します。 
5. 初期総コストからこの合計を減算し、結果を出力します。 

### なぜ効果があるのか

 このアルゴリズムは、セグメンテーション コストが全範囲からカットによって除去された差異の合計を差し引いたものとして表現できるという不変式に依存しています。 各カットはグローバル スパンからちょうど 1 つの隣接関係の寄与を削除し、これらの寄与は独立しているため、カットの選択は位置間で干渉しません。 したがって、除去された寄与を最大化することは、隣接する最大のギャップを選択することと同等であり、最適性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    if k == 1:
        print(a[-1] - a[0])
        return

    diffs = []
    for i in range(n - 1):
        diffs.append(a[i + 1] - a[i])

    diffs.sort(reverse=True)

    saved = sum(diffs[:k - 1])
    print((a[-1] - a[0]) - saved)

if __name__ == "__main__":
    solve()
```解決策は、カットが行われない些細なケースを処理することから始まります。 メインの計算では、隣接する差異のリストを作成し、それらを並べ替えて大きなギャップに優先順位を付けてから、最適なものを選択します。$k-1$彼らのうち。 最後の減算により、「最大節約」の解釈が元のコストの公式に戻されます。 

よくある間違いは、次のことを忘れることです。$k-1$ギャップが選択されたり、最大のものを選択する代わりにすべての差分を誤って合計したりする可能性があります。

| 私 | a[i] | a[i+1] | 差分 |
 | --- | --- | --- | --- |
 | 1 | 4 | 8 | 4 |

 | 3 | 15 | 16 | 1 |

 | 5 | 23 | 42 | 19 |

 差分を並べ替えます。$[19, 7, 7, 4, 1]$。 

私たちは取る$k-1 = 2$最大：$19 + 7 = 26$。 

初期費用は$42 - 4 = 38$。 

最終的な答えは、$38 - 26 = 12$。 

これにより、最適なカットが最大のギャップに正確に対応していることが確認されます。

 ## 特殊なケース

 主なエッジケースは次のような場合です$k = 1$。 アルゴリズムは相違点の選択を回避し、直接返す必要があります。$a_n - a_1$。 この場合、diff 配列は無関係であり、誤って減算すると結果が誤って減少します。 

もう 1 つの特殊なケースは、すべての要素が等しい場合です。 隣接するすべての差はゼロであるため、サブセットを並べ替えて選択しても、節約はゼロでなければなりません。 最終結果は、次の条件に関係なくゼロのままです。$k$、アルゴリズムがカットを過剰にカウントしないことを確認します。 

いつ$k = n$、すべての要素が独自のセグメントになります。 各セグメントの最小値と最大値は等しいため、コストはゼロでなければなりません。 アルゴリズムは最大値を合計するため、これを正しく処理します。$n-1$ギャップ、全範囲に等しい$a_n - a_1$、最終的な答えはゼロになります。
