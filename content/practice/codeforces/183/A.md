 ## 問題の理解

 車は無限の 2D グリッド上のどこかから出発し、最終的には次のアイスクリーム屋台に到着しました。`(0, 0)`。 移動の数と GPS 記録の順序はわかっていますが、各記録はそのステップで考えられる方向のセットを示しているだけです。 

例えば、`"UR"`動きは上または右のいずれかであったことを意味します。`"ULDR"`つまり、移動は 4 つの方向のいずれかであった可能性があります。 

開始位置がどれだけ多くなる可能性があるかを数える必要があります。`(0, 0)`すべての動きを処理した後。 

問題を考える直接的な方法は、プロセスを逆に考えることです。 車がどこからスタートしたのかを尋ねるのではなく、もし次の地点からスタートした場合、各ステップの後にどこにあるのかを尋ねます。`(0, 0)`そして、動きの説明を逆方向に進みます。 この逆のプロセスにおけるすべての有効な終了位置は、考えられる 1 つの本部の場所に対応します。 

移動回数は最大です`2 * 10^5`したがって、到達可能なすべてのポイントを明示的に保存するアルゴリズムは不可能です。 たとえ各ステップで州の数が 2 倍になったとしても、すぐに天文学的な規模に達するでしょう。 ここでも二次解は遅すぎます。 2 秒の制限があるため、直線的な時間に近い値が期待できます。 

重要な課題は、到達可能な位置のセットが見た目は幾何学的に増加しますが、実際には非常に厳格な構造を持っていることです。 この構造が欠けていると、不必要な状態爆発が発生します。 

簡単な間違いの 1 つは、パリティ制約をチェックせずに、x 座標と y 座標を独立して扱うことです。 

考慮する：```
1
UR
```車は右か上に動いた可能性があります。 それを逆にすると、本社は次の場所にある可能性があります。`(-1,0)`または`(0,-1)`。 あるのは`2`可能性がありますが、長方形内のすべての点が含まれるわけではありません。 

もう 1 つの微妙なケースは、無制限の移動が繰り返されることです。```
2
ULDR
ULDR
```任意の 2 つの移動の後、到達可能な位置は、すべてのポイントではありません。`5 x 5`四角。 マンハッタンの距離の同等性が重要です。 有効な本社の位置は、原点からの距離が最大で次の点です。`2`と同じパリティを持ちます`2`。 

ここで不用意に四角形をカウントするソリューションを使用すると、過剰にカウントされてしまいます。 

すべての動きが同じ軸方向に強制される、退化したケースもあります。```
3
UR
UR
UR
```各移動は x を次のように変更します`+1`またはyによって`+1`。 これを逆にすると、すべての本部の役職は次の条件を満たします。```
x <= 0
y <= 0
x + y = -3
```答えはただ`4`、面積規模の数量ではありません。 

到達可能なセットの構造が問題全体です。 

## アプローチ

 ブルートフォースのアイデアは単純です。 各移動の後、可能なすべてのポジションのセットを維持します。 から開始`(0,0)`。 現在のすべてのポイントに対して、現在の GPS レコードから許可されているすべての方向を適用し、結果のポイントを新しいセットに挿入します。 

これは、すべての有効なパスを明示的にシミュレートするため、正しいです。 問題は成長です。 と`n = 2 * 10^5`、到達可能なポイントの数は次のようになります。`n^2`。 すべてを明示的に保存して更新するには、次のものが必要になります`10^10`最悪の場合の運用。 

これらの状態が実際に幾何学的にどのように見えるかを理解する必要があります。 

それぞれの移動により、正確に 1 つの座標が変更されます。`±1`。 後`n`移動すると、到達可能なすべてのポイントのマンハッタン距離パリティは次のようになります。`n`。 

次に、考えられる 5 つのレコード タイプを見てみましょう。`"UR"`常に x または y のいずれかを増加させます`1`。`"DL"`常に x または y のいずれかを減少させます`1`。`"UL"`y を増やすか、x を減らします。`"DR"`y を減らすか、x を増やします。`"ULDR"`あらゆる方向を許可します。 

すべての点を追跡する代わりに、2 つの変換された座標上の制約を追跡できます。```
s = x + y
d = x - y
```それぞれの動きは、これらの値のいずれか 1 つにのみ影響します。`±1`。 

たとえば:

 | 移動 | s の変化 | d | の変化
 | --- | --- | --- |
 | う | +1 | -1 |
 | D | -1 | +1 |
 | Ｌ | -1 | -1 |
 | R | +1 | +1 |

 次に、各レコード タイプを調べます。`"UR"`常に増加します`s`による`1`。`"DL"`常に減少します`s`による`1`。`"UL"`常に減少します`d`による`1`。`"DR"`常に増加します`d`による`1`。`"ULDR"`変換された両方の軸でどちらの方向でも許可されます。 

これにより問題が完全に分離されます。 

仮定する：```
a = count("UR")
b = count("DL")
c = count("DR")
d = count("UL")
e = count("ULDR")
```それから：```
s = a - b + variable
d = c - d + variable
```ここで、各変数は無制限の動きとステップごとの変化から来ています。`2`。 

より正確には:```
s ∈ [a - b - e, a - b + e]
d ∈ [c - d - e, c - d + e]
```そして両方の値はその中心と同じパリティを持ちます。 

すべての有効なペア`(s,d)`正確に 1 つの格子点を決定します。```
x = (s + d) / 2
y = (s - d) / 2
```パリティ条件により完全性が自動的に保証されます。 

したがって、答えは次のようになります。```
(number of possible s values) *
(number of possible d values)
```各インターバルは次のステップで進行します。`2`、したがって、それぞれは正確に`e + 1`可能性。 

最終的な答え:```
(e + 1)^2
```これは、状態空間の見かけの複雑さと比較すると、驚くほど小さいです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | ブルートフォース | O(n²) から O(n³) は実装に応じて異なります。 O(n²) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての移動記録を読み取ります。 

各タイプが何回出現するかだけを考慮します。 変換された座標に移動すると、それらの正確な順序は問題になりません。 
2. レコードの数を数えます`"ULDR"`。 

このカウントを次のようにします`e`。 
3. 他の移動タイプの強制動作を観察します。`"UR"`常に増加します`s = x + y`。`"DL"`常に減少します`s`。`"DR"`常に増加します`d = x - y`。`"UL"`常に減少します`d`。 

これらの移動は固定オフセットに寄与し、分岐を作成することはありません。 
4. の動作を観察します。`"ULDR"`。 

無制限の動きはそれぞれ独立して変更可能`s`どちらかで`+1`または`-1`、同様に`d`。 

後`e`このような動きでは、変換された各座標は正確に`e + 1`値はステップごとに異なるため、到達可能な値`2`。 
5. 可能性を倍増します。 

の選択肢`s`そして`d`独立しています。 すべての有効なペアは、正確に 1 つの整数グリッド ポイントに対応します。 

本社のポジションの数は次のとおりです。```
(e + 1)²
```### なぜ効果があるのか

 変革:```
s = x + y
d = x - y
```動きの制約を切り離します。 

すべての非`"ULDR"`レコードは、変換された座標変更を 1 つだけ修正し、分岐を残しません。 のみ`"ULDR"`選択肢が作成され、そのような動きのそれぞれが独立して 1 つの二者決定に寄与します。`s`そして 1 つの二者択一の決定により、`d`。 

後`e`無制限の動き、変換された両方の座標は正確に取ることができます`e + 1`到達可能な値は差のある等差数列を形成するため、個別の値`2`。 

間のマッピング`(s,d)`そして`(x,y)`はパリティ値の一致に対して全単射であるため、変換された座標のペアをカウントすることは、グリッド点をカウントすることとまったく同じです。

input = sys.stdin.readline

n = int(input())

free_moves = 0

for _ in range(n):
    s = input().strip()
    if s == "ULDR":
        free_moves += 1

print((free_moves + 1) ** 2)
```数学的削減によりすべてのジオメトリが削除されるため、実装は非常に小さくなります。 

可能な本部ポジションの数に影響を与える唯一の情報は、完全に制限されていない動きがどれだけ存在するかということです。 制約されたすべての移動は、サイズを変更せずに最終的な到達可能な領域を移動するだけです。 

この式では整数演算のみが使用されるため、精度の問題はありません。 最大の制約でも:```
(200000 + 1)^2
```Python 整数内に快適に収まります。 

よくある実装上の間違いは、座標をシミュレートしたり、到達可能なセットを維持しようとしたりすることです。 このアプローチでは、パリティ制約を正しく管理することが難しくなるため、時間がかかり、エラーが発生しやすくなります。

import sys
import io

def solve():
    input = sys.stdin.readline

    n = int(input())

    cs = 0
    cd = 0

    for _ in range(n):
        s = input().strip()

        if s == "UR":
            cd += 1
        elif s == "DL":
            cd += 1
        elif s == "UL":
            cs += 1
        elif s == "DR":
            cs += 1
        else:
            cs += 1
            cd += 1

    print((cs + 1) * (cd + 1))

def run(inp: str) -> str:

    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out
