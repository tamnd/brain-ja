 ## 解決策
 ## 問題の理解

 すべてのエッジがその端点の色間の厳密な関係を強制する有向グラフがあります。 頂点に色がある場合`c`の場合、すべての発信近隣には色が必要です`c + 1`、モジュロをラップアラウンド`k`。 

条件を記述する別の方法は次のとおりです。$color(v) \equiv color(u)+1 \pmod{k}$有向エッジごとに、循環番号付けシステムでちょうど 1 ステップずつ色が増加します。 

タスクは可能な限り最大のものを見つけることです`k`そのような割り当てが存在します。 

グラフには自己ループと複数のエッジが含まれる場合があります。 自己ループは、頂点からそれ自体へのエッジが以下を必要とするため、特に制限が厳しくなります。$color(u) \equiv color(u)+1 \pmod{k}$つまり`k = 1`。 

制約が十分に大きいため、ほぼ線形の解決策が必要です。 まで`10^5`頂点とエッジ、すべてを試すアルゴリズム`k`値を設定し、それらを個別に検証すると、速度が非常に遅くなります。 二次グラフの走査は直ちに除外されます。 周囲に何かを期待する必要があります`O(n + m)`または`O((n + m) log n)`。 

難しいのは、カラーリングの制約が実際にグローバルに何を意味するのかを理解することです。 

ある長さの方向のある経路に沿って歩くと仮定します。`d`。 すべてのエッジで色が 1 ずつ進むため、パスを通過した後、端点間の色の違いは強制的に次のようになります。`d mod k`。 

ここで長さの有向サイクルを考えてみましょう`L`。 頂点から開始して頂点に戻ることは、次のことを意味します。$L \equiv 0 \pmod{k}$したがって、すべての有向サイクル長は次で割り切れる必要があります。`k`。 

この観察によって問題は完全に変わります。 色について直接考える代わりに、周期の長さを理解することだけが必要です。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

自己ループを考えてみましょう。```
1 1
1 1
```唯一の有効な答えは次のとおりです。```
1
```通常のサイクルのみを考慮する不注意な実装では、長さのサイクルを見逃す可能性があります。`1`力`k = 1`。 

もう 1 つの危険なケースは、グラフが切断されていることです。```
4 2
1 2
3 4
```有向サイクルはまったくありません。 DAG では、任意の大きさを使用できます。`k`なぜなら、矛盾は決して現れないからです。 問題が必要なので、`k ≤ n`、正解は`n = 4`。 

既存のサイクルで gcd のみを計算する実装では、誤って次の結果が返される可能性があります。`0`。 

より微妙な例は次のとおりです。```
3 3
1 2
2 3
3 1
```このグラフには長さの周期があります`3`、したがって、答えは次のとおりです`3`。 

しかし、別のエッジを追加すると:```
3 4
1 2
2 3
3 1
1 3
```長さのサイクルを作成します`2`同じように：`1 -> 3 -> 1`今では両方とも`2`そして`3`で割り切れる必要があります`k`、したがって、次のみ:```
1
```動作します。 

一度に 1 つの DFS サイクルのみを検査するソリューションでは、誤った結果が返される可能性があります。`3`。 

## アプローチ

 ブルートフォースのアイデアは単純です。 あらゆる可能性を試してみる`k`から`n`まで`1`を選択し、有効なカラーリングが存在するかどうかを確認します。 

固定の場合`k`、DFS または BFS を使用して色を割り当てることができます。 すべてのエッジで次のことが強制されます。```
color[v] = (color[u] + 1) mod k
```同じ頂点に対して 2 つの異なる色を導出した場合、`k`は無効です。 

この検証には次の時間がかかります`O(n + m)`時間。 あらゆる人のためにそれを行う`k`与える:```
O(n(n + m))
```と`n = 10^5`、これはあまりにも大きくなりすぎます。 

重要な観察は、エッジ制約がパスに沿って蓄積されるということです。 長さのあるパス`d`の色の違いを強制します`d mod k`。 2 つの異なるパスが同じ頂点のペアを接続する場合、それらの長さはモジュロで一致する必要があります。`k`。 

DFS が各頂点に深さを割り当てるとします。 あらゆるエッジに`u -> v`、私たちは次のことを知っています:```
depth[v] = depth[u] + 1
```木の端に沿って。 

非ツリー エッジに遭遇した場合は、次のようになります。```
depth[u] + 1 - depth[v]
```到達する 2 つの方法の長さの違いを表します`v`。 

その差は次で割り切れるはずです`k`。 

グラフ全体にわたってこれらの制約を収集すると、次のようになります。$k \mid (depth[u]+1-depth[v])$あらゆるエッジに。 

したがって、有効な最大値は`k`は、単にそのようなすべての値の gcd です。 

なぜこれが機能するのでしょうか?

 すべての有向サイクルはこれらの違いの 1 つに寄与し、gcd はすべてのサイクル長で共有される公約数を正確に捕捉します。 

グラフに有向サイクルがない場合、すべての差はゼロとなり、制限がまったくないことを意味します。 その場合の答えは、`n`。 

最後のアルゴリズムは、グラフに対して 1 回の DFS を実行し、gcd を増分的に計算します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n(n + m)) | O(n) | 遅すぎる |
 | 最適 | O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 有向グラフの隣接リストを作成します。 
2. に初期化された深さ配列を維持します。`-1`。 の値`-1`頂点がまだ訪問されていないことを意味します。 
3. すべての未訪問の頂点から DFS を開始します。 開始深度を次のように設定します`0`。 
4. DFS中、すべてのエッジに対して`u -> v`：

もし`v`未訪問の場合は、次のように割り当てます。```
depth[v] = depth[u] + 1
```DFS を続行します。 
5. もし`v`すでに訪問されている場合、次を計算します。```
diff = depth[u] + 1 - depth[v]
```この値はサイクル制約を表します。 任意の有効な`k`この数値を除算する必要があります。 
6. ゼロ以外のすべての gcd を維持する`diff`DFS 中に検出された値。 
7. グラフ全体を処理した後:

 gcd が`0`、グラフにはサイクル制約が含まれていないため、`k`動作します。 許可される最大の答えは次のとおりです`n`。 
8. それ以外の場合は、gcd の絶対値を出力します。 

### なぜ効果があるのか

 DFS の深さは、DFS ルートからのパスの長さをエンコードします。 

あらゆるエッジに`u -> v`、式:```
depth[u] + 1 - depth[v]
```に至る 2 つの経路の長さの差を測定します。`v`。 

有効なカラーリングでは、同じ頂点間のすべてのパス長がモジュロに一致する必要があります。`k`。 つまり、そのような差はすべて次の式で割り切れる必要があります。`k`。 

すべての差の gcd は、すべてのサイクル長制約を同時に除算した最大の数値です。 数値が大きい場合は、少なくとも 1 つのサイクルに違反します。 

すべての差がゼロの場合、グラフはこれらの制約に関して DAG のように動作し、制限はありません。`k`存在します。 

## Python ソリューション```python
import sys
from math import gcd

input = sys.stdin.readline

def solve():
    sys.setrecursionlimit(1 << 25)

    n, m = map(int, input().split())

    graph = [[] for _ in range(n)]

    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        graph[u].append(v)

    depth = [-1] * n
    g = 0

    def dfs(u):
        nonlocal g

        for v in graph[u]:
            if depth[v] == -1:
                depth[v] = depth[u] + 1
                dfs(v)
            else:
                diff = depth[u] + 1 - depth[v]
                g = gcd(g, abs(diff))

    for i in range(n):
        if depth[i] == -1:
            depth[i] = 0
            dfs(i)

    if g == 0:
        print(n)
    else:
        print(g)

solve()
```隣接リストには、すべての発信エッジが保存されます。 複数のエッジと自己ループは、特別な処理を行わなくても自然に機能します。 

の`depth`配列には 2 つの目的があります。 訪問した頂点をマークし、サイクル制約を導出するために必要な DFS 深度を記録します。 

DFS がツリーのエッジに従う場合、子の深さは親の深さよりも 1 大きくなります。 これは、すべての有向エッジが色を 1 つ進めるという事実と一致します。 

すでに訪問した頂点の場合、計算された`diff`2 つのパス間の不一致をキャプチャします。 gcd は結合的であるため、gcd を段階的に取得するだけで十分です。```
gcd(a, b, c) = gcd(gcd(a, b), c)
```絶対値が重要です。 走査順序に応じて、`diff`は負になる可能性がありますが、割り算の制約は大きさのみに依存します。 

特別な場合`g == 0`すべての差がゼロの場合に発生します。 これは、自明でないサイクル制約が発見されなかったことを意味します。 この状況では、グラフではあらゆることが許可されます。`k`したがって、許可される最大値は次のようになります。`n`。

 ## 特殊なケース

 自己ループにより、即座に答えが強制されます。`1`。 

入力：```
1 1
1 1
```DFS は頂点から開始します`1`深みのある`0`。 

エッジ用`1 -> 1`:```
diff = 0 + 1 - 0 = 1
```gcd は次のようになります`1`したがって、最終的な答えは次のとおりです。`1`。 

これが機能するのは、自己ループでは色がそれ自体の次の色と等しくなる必要があるためです。 

次に、サイクルのないグラフを考えてみましょう。```
4 2
1 2
3 4
```DFS は増加する深さを割り当てますが、すべてのエッジは未訪問のノードに送られます。 非ツリー エッジは表示されないため、gcd は残ります。`0`。 

アルゴリズムの出力`n = 4`。 

これは、非巡回グラフがモジュールの制限を課さないことを正しく反映しています。 

最後に、競合するサイクル長を考慮します。```
3 4
1 2
2 3
3 1
1 3
```グラフには 3 サイクルと 2 サイクルの両方が含まれています。 

DFS は gcd を使用して制約を生成します。```
gcd(3, 2) = 1
```だからそれだけ`k = 1`動作します。 

このアルゴリズムは、検出された単一のサイクルに依存するのではなく、すべてのサイクル情報を正しく組み合わせます。
