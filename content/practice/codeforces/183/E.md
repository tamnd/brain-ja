 ## 問題の理解

 あります`n`子どもたちは一定の周期的な順序で座っています。 購入プロセス中、選択したパッケージ サイズは、すべてのターンにわたってグローバルに厳密に増加するシーケンスを形成する必要があります。 子供の後`n`、次のターンはキッドに戻ります`1`。 

どの子供も複数のパッケージを購入する可能性がありますが、最終的な状態では、すべての子供が同じ数のパッケージを購入する必要があります。 子供`i`小遣い以上は使えない`a[i]`。 当店では以下のパッケージサイズを販売しております。`1`に`m`。 

販売されるキャンディーの総数をできるだけ多くしたいと考えています。 

重要な制限は、グローバルな昇順です。 購入したすべてのパッケージのサイズを時系列順に記述すると、それらは単に次から選択された厳密に増加する順序になります。`1...m`。 ターンによって、どの子供がそのシーケンス内でどのポジションを獲得するかが決まります。 

それぞれの子供が正確に購入すると仮定します`k`パッケージ。 購入したパッケージの総数は次のようになります。`n * k`。 パッケージのサイズは厳密に増加しており、それを超えることはできないため、`m`、シーケンスには正確に含まれている必要があります`n * k`～からの異なる整数`1...m`。 

お子様の総費用の最小額`i`グローバル シーケンスが可能な限り小さい場合、つまり次の場合に発生します。```
1, 2, 3, ..., n*k
```子供`i`ポジションを受け取ります:```
i, i+n, i+2n, ...
```したがって、最小限の支出は次のようになります。```
i + (i+n) + (i+2n) + ... + (i+(k-1)n)
= k*i + n*k*(k-1)/2
```この最小値でも許容範囲を超える場合は、購入`k`それぞれのパッケージは不可能です。 

制約は二次または偶数であるほど十分に大きいです。`O(n * sqrt(m))`スタイルシミュレーションは危険です。 ここ`n`到達する`2 * 10^5`そして`m`到達する`5 * 10^6`したがって、線形または対数に近いものが必要です。 

可能な限り最小のパッケージを買う余裕さえない子供がいる場合、微妙なエッジケースが現れます。 

例：```
2 5
1
100
```子供 2 は大きな荷物を購入できますが、子供 1 は少なくとも荷物を受け取る必要があります`1`最初のサイクルとパッケージで`3`2番目のサイクルで。 答えはただ`1`すべての子供が同じ数のパッケージで終了する必要があるため、子供 2 を単独で続行させることで得られる大きなものではありません。 

もう 1 つの簡単な間違いは、上限を忘れることです`m`。 

例：```
2 3
100
100
```お金は十分にあるので、子供たちは両方ともたくさんのパッケージを買うことができると思うかもしれません。 しかし、内部で最も長い厳密に増加するシーケンス`1...3`長さがある`3`。 購入総数は次の値で割り切れる必要があるため、`n = 2`、最大値は`2`。 

さらに微妙な落とし穴は、最適なシーケンスには連続した番号を使用する必要があると想定していることです。 そうではありません。 

例：```
2 5
5
10
```最適な順序は次のとおりです。```
1, 3, 4, 5
```ない：```
1, 2, 3, 4
```最初のシーケンスは合計を示します`13`よりも大きい`10`。 

コツは、実現可能性が決定されたら、選択した数値を押し上げて合計を最大化する必要があることです。 

## アプローチ

 強引なアイデアは、考えられるすべての数字を試すことです`k`子供一人あたりのパッケージ数。 それぞれについて`k`、長さが増加するシーケンスを検索できます。`n*k`すべての子供が予算内に収まっているかどうかを確認します。 

最小支出パターンが明確であるため、実現可能性の条件自体は管理可能です。```
cost(i, k) = k*i + n*k*(k-1)/2
```それですべてをテストできる`k`から`1`に`m/n`。 

本当の難しさは、実現可能性を判断した後に販売されるキャンディーの総数を最大化することです。 実際のシーケンスの列挙は組み合わせになります。 すべてに対して貪欲に最適なシーケンスを生成することも可能`k`が遅すぎるときは`m`数百万です。 

重要な観察は、実現可能性は最小割り当てのみに依存するということです。 一度値が`k`実現可能であれば、余分なお金をより大きなパッケージ サイズに変換できます。 

すでに修正済みだとします`L = n*k`、購入したパッケージの合計数。 厳密に長さが増加するすべてのシーケンスの中で`L`内部`1...m`、考えられる最大の合計額は明らかに次のとおりです。```
m-L+1, m-L+2, ..., m
```その合計は次と等しくなります。```
L * (2m-L+1) / 2
```問題は、子供たちがそのような最大化されたシーケンスを許容できるかどうかです。 

ここで重要な不変条件が現れます。 最小シーケンスから始めます。```
1, 2, ..., L
```厳密な増加を維持しながら要素を増やすことができます。 利用可能な増加の合計額は正確に次のとおりです。```
L * (m-L)
```それぞれの位置が上に移動する可能性があるためです。 

子供`i`最初に支出するのは:```
base_i = k*i + n*k*(k-1)/2
```予算が残っています:```
extra_i = a[i] - base_i
```すべての子供の追加予算の合計は、最小シーケンスを最大シーケンスに変換するために必要な上方シフトの合計以上でなければなりません。 

必要な増加量は次のとおりです。```
L * (m-L)
```なぜなら：```
sum(maximal) - sum(minimal)
```まさにその量です。 

この条件でも十分です。 すべての上向きシフトは、昇順を維持しながら独立して分散できます。 

したがって、問題全体は、実現可能な最大のものを見つけることに帰着します。`L = n*k`満足のいく：```
1. base_i <= a[i] for all i
2. sum(extra_i) >= L*(m-L)
```あとは可能なものを反復処理するだけです`k`、最大でも`m/n ≤ 2.5 * 10^6`。 慎重に計算すれば、これは時間内に快適に機能します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(m²)以上 | O(m) | 遅すぎる |
 | 最適 | O(m / n + n) | O(1) おまけ | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての許容値を配列に読み取ります`a`。 
2. 合計許容量を計算します。```
S = sum(a)
```なぜなら、世界の予算状況は残りのお金の総額に依存するからです。 

1. 子供ごとに考えられる荷物の数を繰り返します。`k = 1, 2, ...`。 

合計購入数は次のとおりです。```
L = n*k
```もし`L > m`、より長く厳密に増加するシーケンスを形成することはできないため、すぐに停止します。`m`。 

1. 子供に必要な最低支出を計算します`i`:```
base_i = k*(i+1) + n*k*(k-1)/2
```ここでのインデックスはコード内でゼロベースなので、`i`ラベルに対応する`i+1`。 

1. ある程度の場合`base_i > a[i]`、それからこれ`k`不可能です。 より大きな`k`必要な最小限のコストのみを増加させるので、ループを完全に停止できます。 

この単調さが重要です。 値が 1 つになると、`k`失敗すると、より大きな値もすべて失敗します。 

1. 選択したすべてのパッケージ サイズの最小合計を計算します。```
min_sum = L*(L+1)/2
```そして最大合計額は次のようになります。```
max_sum = L*(2*m-L+1)/2
```それらの違いは、追加の上方シフトが必要であることです。 

1. 合計許容量が最大シーケンスを支払うことができるかどうかを確認します。```
S >= max_sum
```予算はグローバルではなく子供ごとに設定されるため、これだけでは十分ではありません。 

1. 子供全体の最小支出の合計を計算します。```
base_total = min_sum
```最小シーケンスであるため、これらは実際には等しいです。`1...L`それらのコストを正確に割り当てます。 

1. 利用可能な追加予算の合計は次のとおりです。```
S - base_total
```必要な追加の増加は次のとおりです。```
max_sum - min_sum
```これは次のように単純化されます。```
L*(m-L)
```利用可能な追加予算が少なくともこの量であれば、最大シーケンスが達成可能です。 

1. 最良の回答を保持します。```
answer = max_sum
```固定のため`L`、最大数列は常に販売されたキャンディーの合計が最大になります。 

### なぜ効果があるのか

 一定ラウンド数の場合`k`、すべての有効な購入プロセスは、厳密に増加する長さのシーケンスに対応します。`L = n*k`。 

実行可能な最小シーケンスは次のとおりです。```
1, 2, ..., L
```そしてこれにより、すべての子供が同時に可能な限り最小限の支出を行うことになります。 

他の有効なシーケンスは、厳密な順序を維持しながらいくつかの要素を増やすことによって取得できます。 最小シーケンスから最大シーケンスまでの可能な増加の合計は次のようになります。```
L*(m-L)
```個別の予算制約は最小シーケンスですでに満たされています。 残りの許容量は、これらの増加に対する容量と見なすことができます。 

厳密な増加を維持しながら、増加をポジション間で独立して配分できるため、唯一の追加要件は、残りの予算の合計が十分に大きいことです。 したがって、実現可能条件は必要かつ十分である。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = [int(input()) for _ in range(n)]

    total = sum(a)
    ans = 0

    k = 1

    while n * k <= m:
        l = n * k

        add = n * k * (k - 1) // 2

        ok = True

        for i in range(n):
            need = k * (i + 1) + add
            if need > a[i]:
                ok = False
                break

        if not ok:
            break

        max_sum = l * (2 * m - l + 1) // 2

        if total >= max_sum:
            ans = max_sum

        k += 1

    print(ans)

if __name__ == "__main__":
    solve()
```ループは、シーケンスの長さを直接繰り返すのではなく、子供ごとのパッケージの数を繰り返します。 これにより、すべての子供が同じ数のパッケージを購入するという条件が自動的に維持されます。 

表現```
add = n * k * (k - 1) // 2
```すべての子供に共有される等差数列の貢献です。 残りの任期`k * (i + 1)`子供のオフセットを考慮します`i`各サイクル内で。 

微妙な点は、子供が最低コストのテストに失敗した場合に早期終了されることです。 最小必要支出は次のように単調増加します。`k`、したがって、特定の 1 回`k`は不可能です。これより大きな値もすべて不可能です。 

もう 1 つの重要な点は、64 ビット演算の使用です。 値はおおよそに達する可能性があります`m²`、それは周りにあります`2.5 * 10^13`。 Python の整数はこれを自動的に処理します。 

条件```
total >= max_sum
```個々の最小限のチェックに合格した後は十分です。 最小の取り決めは子供ごとのすべての制約をすでに満たしており、残りの合計許容量はいつでも上方シフトを通じて再分配できます。
