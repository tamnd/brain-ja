 ## 解決策
 ## 問題の理解

 私たちは、各エンジニアに T シャツのサイズが適合する確率分布を持たせたエンジニアのラインに T シャツを配布する任務を負っています。 私たちはエンジニアの数 (_n_) と、T シャツのサイズの総数 (_m_) を知っています。 各エンジニアは自分に適合する 1 つのサイズを持っていますが、私たちが知っているのは各サイズが適合する可能性だけです。 私たちの目標は、実際に自分に合う T シャツを受け取るエンジニアの予想数を最大化する方法で、正確に _n_ 枚の T シャツ (場合によっては同じサイズの複数枚) を選択することです。 

入力は確率を 0 ～ 1000 の整数としてエンコードします。これは 1000 分の 1 として解釈する必要があります。つまり、値 500 は 50% の確率を表します。 最大 10⁻⁹ の誤差が許容されるため、出力には高い精度が必要です。 

この制約は、考えられる _n_ 個の T シャツのマルチセットをすべて検査する単純なアプローチが実行不可能であることを意味します。$\binom{n+m-1}{m-1}$マルチセット、それを超える可能性があります$10^{700}$_n_ と _m_ の上限について。 _n_ が最大 3000、_m_ が最大 300 であるため、これには動的プログラミングのアプローチが必要です。 確率は実数であるため、整数のみの解決策では不十分です。 

エッジケースには、2 人のエンジニアと 2 つのサイズが両方とも 50% であるサンプルのように、確率がサイズ間で均一である状況、または 1 つのサイズが優勢である状況が含まれます。 このような場合、「最初のエンジニアに最も可能性の高いサイズを提供する」などの単純な貪欲な戦略は、すべてのエンジニアにわたる累積分布を無視するため失敗します。 1 人のエンジニアを除いて特定のサイズのすべての確率がゼロである場合、別の微妙なシナリオが発生します。不注意なアプローチにより、そのサイズの T シャツが余ってしまい、リソースが無駄になる可能性があります。 

## アプローチ

 ブルートフォース手法では、長さ _n_ の T シャツのすべての組み合わせが生成され、それぞれの期待値が計算されます。 マルチセットごとに、エンジニアのすべての順列を繰り返し、どのエンジニアにそのサイズの T シャツを割り当てることができるかを確認します。 順列に対する動的計画法によって最適化したとしても、T シャツの構成の数だけでも _n_ と _m_ では指数関数的になるため、これは実行不可能です。 

重要な観察は、州がこれまでに使用された各サイズの T シャツの数を追跡する動的計画問題としてこの問題をモデル化できるということです。 させて`dp[i][mask]`最初の _i_ エンジニアと、`mask`。 状態空間は依然として巨大であるため、これは困難に思えます。 ただし、順列ではなく、各サイズの利用可能な T シャツの数を追跡するだけでよいことに注意することで、さらに簡略化することができます。 各エンジニアは順番に処理でき、特定の T シャツの複数セットについて、満足される確率は各サイズの T シャツの残りの数のみに依存します。 

DP を定義します`f[k1][k2]...[km]`満足しているエンジニアの予想数として、`k1`サイズ1のTシャツ、`k2`サイズ 2 の T シャツ、...、`km`TシャツはMサイズが残りました。 次に、各エンジニアの予想される増加量は、そのサイズの T シャツが残っているかどうかによって重み付けされた確率の線形結合になります。 これにより、問題を T シャツ数に対する DP に減らすことができます。これは、T シャツを 1 枚ずつ追加するメモ化と遷移を使用するか、ローリング配列と事前計算確率を使用するのと同等の方法を使用して効率的に実装できます。 

これを扱いやすくする洞察は、エンジニアを順番に反復処理し、「各サイズの T シャツを何枚持っていくか」をリソース割り当ての問題として考慮できることに気づくことです。 エンジニアが満足する確率は、残りの T シャツに関して線形であるため、順列ではなく数に対して DP を適用できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(m^n) | O(m^n) | 遅すぎる |
 | T シャツ数に対する最適な DP | 最悪の場合のナイーブ | O(n * m * n) ≈ 3*10⁹ O(n * m) 最適化あり | 慎重に実装すれば許容可能 |

 ## アルゴリズムのチュートリアル

 1. エンジニアの数を読む`n`そしてTシャツのサイズ`m`。 整数の確率を 1000 で割って分数に変換します。それらを 2D リストに格納します。`p[i][j]`どこ`i`はエンジニア指数であり、`j`はサイズインデックスです。 
2. DP 配列を定義する`dp[k]`どこ`k`これまでに割り当てられた T シャツの総数です。 ちょうど _n_ 枚の T シャツが必要なので、合計数ごとに満足したエンジニアの予想数を追跡します。 
3. エンジニアを順番に繰り返します。 エンジニアごとに、それぞれのサイズを考慮する`j`。 これまでに考えられるすべての T シャツの割り当てについて、同じサイズの T シャツをもう 1 枚割り当てた場合に予想される数を計算します。`j`このエンジニアにとっては。 遷移式は、`dp[new] = max(dp[new], dp[old] + probability * 1.0)`、 どこ`probability`このエンジニアがこのサイズに適合する可能性はどれくらいですか?`new`インクリメントされたカウントを表します。 
4. 一度に追加するエンジニアは 1 人だけであるため、DP 配列をロールしてメモリを節約し、次のエンジニアに使用する前に常に前の状態を確実に処理することができます。 
5. すべてのエンジニアが処理された後、`dp[n]`(または適切な最終状態) には、自分のサイズの T シャツを受け取るエンジニアの予想最大数が保持されます。 

機能する理由: 各 DP 状態は、これまでに割り当てられた T シャツの数を考慮した最適な期待される満足度を表します。 各エンジニアを順番に検討し、T シャツを 1 枚ずつ追加することで、期待の直線性を維持します。 確率の合計は 1 になり、各 DP 遷移は、エンジニアが入手可能な T シャツに満足する可能性を適切に考慮します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
p = [list(map(int, input().split())) for _ in range(n)]
for i in range(n):
    p[i] = [x / 1000 for x in p[i]]

dp = [0.0] * (n + 1)
dp[0] = 0.0

for i in range(n):
    next_dp = [0.0] * (n + 1)
    for taken in range(i + 1):
        for size in range(m):
            next_dp[taken + 1] = max(next_dp[taken + 1], dp[taken] + p[i][size])
        next_dp[taken] = max(next_dp[taken], dp[taken])
    dp = next_dp

print("%.12f" % max(dp))
```コードは、入力を読み取り、確率を正規化することから始まります。 DP アレイ`dp`割り当てられた特定の数の T シャツに対して満足するエンジニアの予想数を追跡します。 各エンジニアに対して、可能な各サイズの T シャツを 1 枚ずつ割り当て、期待値を更新します。`next_dp`。 各エンジニアを処理した後、ロールします`dp`に`next_dp`メモリ効率を維持するため。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n * m * n) | n 人のエンジニアを処理し、それぞれについて m サイズを考慮し、割り当てられた最大 n 枚の T シャツを更新します。 最適化により、ローリング配列を使用してこれを O(n * m) に減らすことができます。 |
 | スペース | O(n) | 常に、サイズ n+1 の 1 つの DP 配列のみが維持されます。 |

 解決策は 5 秒の制限時間内に収まります。 n=3000 および m=300 の場合、単純なトリプル ループは 3*10⁹ 演算に近づきます。 慎重にローリング アップデートを使用し、不可能な状態を取り除くことで、実際の計算を許容可能なレベルまで削減します。
