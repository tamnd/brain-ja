 ## 解決策
 ## 問題の理解

 タスクは、入力された単語が正しいかどうかを確認することです。`t`単語のキーを押した結果として生じる可能性があります`s`時折文字を繰り返すキーボード。 それぞれの文字は`s`に順番に現れる必要があります`t`, ただし、1回以上連続して出現する場合があります。 たとえば、次の場合`s`が "hello" の場合、"helloo" または "hheelloo" は有効な出力ですが、"helo" または "hlllloo" は、文字が欠落しているか順序に違反しているため、有効ではありません。 

入力は最大 100,000 個の複数の単語ペアで構成され、各単語には最大 1,000,000 文字が含まれます。 ただし、全体の長さは、`s`結合した単語は 1,000,000 を超えず、すべての単語についても同様です`t`言葉。 これは、私たちのソリューションでは、長さを繰り返すネストされたループを含めることができないことを意味します。`s`そして`t`最悪の場合、最大 10^12 の演算が行われる可能性があります。 各単語ペアの線形スキャンは、処理される文字の総数が最大 2 * 10^6 であるため、許容されます。これは制限時間内で実行可能です。 

明らかではないエッジケースには、次のような状況が含まれます。`t`の連続した繰り返しに対応しない追加の文字が含まれています。`s`。 例えば、`s = "abc"`そして`t = "aabbccx"`余分な「x」は生成できないため、NO を返す必要があります。`s`。 もう一つの微妙なケースは次のような場合です。`t`たとえば、文字が完全に欠落しています`s = "aaa"`そして`t = "aa"`。 ここでも、出力は NO になるはずです。`s`順番に少なくとも 1 回は出現する必要があります。 

## アプローチ

 素朴なアプローチでは、すべての文字を一致させようとします。`s`のすべてのキャラクターに`t`ネストされたループを使用します。 の各キャラクターごとに、`s`、前方にスキャンします`t`一致する文字が見つかるまで、次の文字に対して繰り返します。 This is correct logically, but if`s`長さは m で、`t`長さが n の場合、最悪の場合の複雑さは O(m * n) です。 最大語長では、これは 10^12 演算程度になる可能性があり、これでは遅すぎます。 

最適なアプローチのための重要な洞察は、次のことを理解することです。`s`そして`t`2 つのポインターで同時にスキャンできます。 ポインタを保持します`i`で`s`そしてポインタ`j`で`t`。 いつ`s[i] == t[j]`、私たちは移動します`i`そして`j`フォワード。 もし`t[j]`等しい`t[j-1]`、私たちは動くだけです`j`キーを繰り返し押す可能性があるため、前に進みます。 このパターンからの逸脱は、`t`から生じることはできません`s`。 これにより、問題は線形スキャンに帰着します。`t`そして`s`、複雑さはそれらの長さの合計に比例します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(m*n) | お(1) | 遅すぎる |
 | 2 点スキャン | O(m+n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 2 つのポインタを初期化する`i`そして`j`ゼロに。`i`横断します`s`そして`j`横断します`t`。 
2. その間`j`の終わりに達していない`t`:

 ａ． もし`i`の終わりに達しました`s`の残りの文字があるかどうかを確認します。`t`すべて等しい`t[j-1]`。 そうでない場合は、NO を返します。 

b. もし`s[i] == t[j]`、両方を移動します`i`そして`j`フォワード。 

c. それ以外の場合`j > 0`そして`t[j] == t[j-1]`、 動く`j`フォワード。 これは、壊れたキーボードによって引き起こされる文字の繰り返しの原因となります。 

d. それ以外の場合は、NO を返します。`t[j]`の現在の文字と一致しません`s`または有効な繰り返し。 
3. ループの後、次のことを確認します。`i`の終わりに達しました`s`。 そうでない場合は、NO を返します。`s`は使用されませんでした。 
4. すべてのチェックに合格した場合は、YES を返します。 

なぜ効果があるのか​​: 各ステップで、`i`そして`j`前のすべての文字という不変条件を維持します。`i`で`s`以前の文字と順番に一致しました`j`で`t`、繰り返しが可能になります。 のいずれかの文字があれば、`t`このパターンに違反すると、アルゴリズムは直ちに NO を返します。 スキャンでは、各文字が`s`少なくとも 1 回、順番に一致し、かつ`t`さらに繰り返される文字が含まれる場合があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can_be_typed(s: str, t: str) -> str:
    i, j = 0, 0
    while j < len(t):
        if i < len(s) and s[i] == t[j]:
            i += 1
            j += 1
        elif j > 0 and t[j] == t[j-1]:
            j += 1
        else:
            return "NO"
    return "YES" if i == len(s) else "NO"

n = int(input())
results = []
for _ in range(n):
    s = input().strip()
    t = input().strip()
    results.append(can_be_typed(s, t))

print("\n".join(results))
```機能`can_be_typed`上で説明した 2 ポインター スキャンを実装します。 境界を慎重に処理します。`i`の終わりに達するかもしれない`s`その間`j`まだ入っています`t`、および末尾に繰り返される文字`t`許可されています。 メインループはポインタが範囲外にならないことを保証し、最終チェックですべての値が確認されます。`s`消費されました。

 ## 特殊なケース

 入力用`s = "aaa"`、`t = "aa"`、アルゴリズムは次から始まります`i = 0, j = 0`。 最初の「a」と一致し、両方のポインターをインクリメントしてから、2 番目の「a」と一致し、両方をインクリメントして、`j`終わりに`t`その間`i`はまだ 2 です。`i != len(s)`の場合、NO が返され、それが正しく識別されます。`t`すべてをカバーしているわけではありません`s`。
