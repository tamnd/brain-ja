 ## 解決策
 ## 問題の理解

 私たちには小さな歌のコレクションが与えられました。 各曲には長さとジャンルがあり、これらの曲のいくつかを繰り返しなく選択して、順序付けられたプレイリストを形成したいと考えています。 プレイリストは 3 つの制約を同時に満たさなければなりません。 合計リスニング時間は正確に固定値でなければなりません$T$。 どの曲インデックスも複数回使用することはできません。 また、プレイリスト内の隣接する曲は異なるジャンルでなければなりません。 

出力は、有効な順序付けされたプレイリストの数を法的に表したものです。$10^9+7$。 順序は重要であるため、ジャンルのルールが尊重されている限り、同じ曲のセットを異なる順列で選択しても、異なる回答としてカウントされます。 

制約は、曲のサブセットにわたる状態空間を即座に示唆します。$n \le 15$。 メモ化せずにすべてのシーケンスを列挙しようとするソリューションでは、最大で以下を探索する危険があります。$15!$順列は実現不可能です。 時間制限があるため、各サブセットを 1 回ずつ検討するビットマスク動的プログラミング アプローチを余儀なくされます。 

時間の次元$T \le 225$も小さいため、これを DP 状態の一部として安全に含めることができることを示唆しています。 

単純な間違いは、これを部分集合の合計に対する単純な順列カウント問題として扱うことです。$T$、隣接関係の制約は無視されます。 これにより、同じジャンルの 2 つの曲を連続して配置するなど、無効なトランジションが過大にカウントされてしまいます。 もう 1 つの微妙な失敗例は、曲のセットを修正すれば十分であると仮定している場合ですが、ジャンルの制約は選択だけではなく順序に依存するため、順序が依然として重要です。 

## アプローチ

 ブルートフォースアプローチでは、曲のすべてのサブセットの可能な順序をすべて試します。 サブセットごとに、すべての順列を生成し、合計期間と隣接制約の両方をチェックします。 これはすでに次のことを意味します$15!$制約はグローバルであり、プレフィックス削減可能ではないため、最悪の場合は順列が発生し、期間による枝刈りさえもあまり役に立ちません。 繰り返し制約は、中間結果を再利用するための構造を持たずに分岐係数を乗算します。 

重要な観察は、プレイリストを構築するプロセスが段階的に行われるということです。 いつでも、有効な部分プレイリストを拡張するために必要な情報は、すでに使用されている曲、現在の合計時間、最後に選択した曲のジャンルだけです。 これは、トランジションが 1 つの新しい曲の追加に対応するサブセット上の DP を示唆しています。 

なぜなら$n$が小さい場合、ビットマスクはどの曲がすでに使用されているかを表します。 現在の時間と最後のジャンルも追跡します。 これにより、グローバルな順序付けの問題が、状態の DAG 上のローカルな遷移に変換されます。 

同じ部分的な構成を何度も再計算するため、ブルート フォースは失敗します。 DP が機能するのは、各状態がシーケンスを正しく拡張するために必要なすべてを一意に取得するためであり、部分問題が大きく重複します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n! \cdot n)$|$O(n)$| 遅すぎる |
 | 最適な DP (ビットマスク) |$O(2^n \cdot n \cdot T)$|$O(2^n \cdot T \cdot 3)$| 承認済み |

 ## アルゴリズムのチュートリアル

 特定の構成で終わる有効なプレフィックスを構築できる方法が何通りあるかを表す DP 状態を定義します。 

1. 定義します`dp[mask][time][last_genre]`の曲を正確に使用してシーケンスを形成する方法の数として`mask`、正確に消費する`time`数分、そしてジャンルの曲で終わる`last_genre`。 最後のジャンルは、次の曲を追加できるかどうかを決定するため、必須です。 
2. 単一の曲が選択されているすべての状態を初期化します。 曲ごとに$i$、設定しました`dp[1<<i][t_i][g_i] = 1`。 これは、プレイリストが任意の単一の有効な曲から開始できることを反映しています。 
3. すべてのマスクを小さいものから大きいものまで繰り返します。 各マスクについて、ゼロ以外のカウントを持つすべての可能な時間と最後のジャンル状態を考慮します。 これにより、到達可能な構成のみを拡張することが保証されます。 
4. 各状態から新しい曲を追加してみます$j$それはマスクの中にはありません。 この移行は次の場合にのみ許可されます$g_j \ne last\_genre$。 これにより、すべてのステップで隣接関係の制約がローカルに適用されます。 
5. 曲を追加する場合$j$新しい合計時間を生成します$time + t_j \le T$、次の状態を更新します。`dp[new_mask][new_time][g_j] += dp[mask][time][last_genre]`。 
6. すべての状態を処理した後の答えは、すべての状態の合計になります。`dp[mask][T][last_genre]`あらゆるマスクとジャンルにわたって。 

これが機能する理由は、すべての有効なプレイリストがこの DP 内の 1 つのトランジション シーケンスに正確に対応しているためです。 各プレフィックスは、使用されたセット、累積時間、および最後のジャンルによって一意に表されるため、有効な構造が失われたり、個別の順序付けパスを超えて二重にカウントされたりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def main():
    n, T = map(int, input().split())
    songs = [tuple(map(int, input().split())) for _ in range(n)]

    dp = [[[0] * 4 for _ in range(T + 1)] for _ in range(1 << n)]

    for i, (t, g) in enumerate(songs):
        if t <= T:
            dp[1 << i][t][g] = 1

    for mask in range(1 << n):
        for time in range(T + 1):
            for last in range(1, 4):
                cur = dp[mask][time][last]
                if not cur:
                    continue

                for j in range(n):
                    if mask & (1 << j):
                        continue
                    t, g = songs[j]
                    if g == last:
                        continue
                    nt = time + t
                    if nt > T:
                        continue
                    nmask = mask | (1 << j)
                    dp[nmask][nt][g] = (dp[nmask][nt][g] + cur) % MOD

    ans = 0
    for mask in range(1 << n):
        for last in range(1, 4):
            ans = (ans + dp[mask][T][last]) % MOD

    print(ans)

if __name__ == "__main__":
    main()
```DP テーブルは、サブセット、時間、最後のジャンルの 3 次元です。 最初のレイヤーは単一曲のプレイリストをシードします。 トランジション ループは、ビットマスク チェックによって曲の再利用を慎重に回避し、状態を更新する前にジャンルの制約を強制します。 オーバーフローを防ぐために、加算のたびにモジュロが適用されます。 

よくある落とし穴は、最後のジャンルの状態には曲ごとの初期値が含まれている必要があることを忘れていることです。そうでないと、最初のステップからの遷移が無効になります。 もう 1 つは、インデックス作成までの時間を制限しないことです。これにより、低レベル言語では暗黙的にメモリが破損したり、Python でロジック エラーが発生したりする可能性があります。 

## 実用的な例

 ### 例 1

 入力:```

1 2
1 3
```単一曲の状態から始めます。 

| マスク | 時間 | 最後 | 値 |

 | 001 | 1 | 1 | 1 |
 | 010 | 1 | 2 | 1 |
 | 100 | 1 | 3 | 1 |

 各状態から、異なるジャンルの曲を追加することができ、最終的には長さ 3 のすべての順列に到達します。 

時間 3 の最終状態:

 | マスク | 最後 | カウント |
 | --- | --- | --- |
 | 111 | 1 | 2 |
 | 111 | 2 | 2 |
 | 111 | 3 | 2 |

 合計すると6になります。 

これにより、すべてのジャンルが異なる場合に、DP がすべての順列を正しく列挙することが確認されます。 

### 例 2 (構築済み)```
3 3
1 1
2 2
1 1
```有効な構造では、連続したジャンル 1 を避ける必要があります。DP は各曲から始まり、ジャンル 1 と 2 の間の遷移のみを許可します。 

有効なパスは次のとおりです。 

(2、ジャンル 2) から開始し、残り時間に応じてジャンル 1 の曲に移動したり、その逆も可能です。 

DP は、ジャンル 1 の 2 つの曲の間のトランジションを自然にブロックします。 

このトレースは、繰り返しジャンルの隣接関係が遷移ごとにローカルに適用されていることを確認します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(2^n \cdot n \cdot T)$| 各州は可能なすべての次の曲を試します。 
| スペース |$O(2^n \cdot T \cdot 3)$| サブセット、時間、最後のジャンルにわたる DP |

 と$n \le 15$、$2^n = 32768$、 そして$T \le 225$、状態空間の合計は約数百万エントリであり、慎重にループすれば Python の制限内に十分収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, T = map(int, input().split())
    songs = [tuple(map(int, input().split())) for _ in range(n)]

    MOD = 10**9 + 7
    dp = [[[0] * 4 for _ in range(T + 1)] for _ in range(1 << n)]

    for i, (t, g) in enumerate(songs):
        if t <= T:
            dp[1 << i][t][g] = 1

    for mask in range(1 << n):
        for time in range(T + 1):
            for last in range(1, 4):
                cur = dp[mask][time][last]
                if not cur:
                    continue
                for j in range(n):
                    if mask & (1 << j):
                        continue
                    t, g = songs[j]
                    if g == last:
                        continue
                    nt = time + t
                    if nt <= T:
                        dp[mask | (1 << j)][nt][g] = (dp[mask | (1 << j)][nt][g] + cur) % MOD

    return str(sum(dp[mask][T][last] for mask in range(1 << n) for last in range(1, 4)) % MOD)

 ## 特殊なケース

 エッジ ケースの 1 つは、複数の曲が同じジャンルと長さを共有する場合です。これにより、多くの順列が作成されるだけでなく、無効なトランジションも多く作成される可能性があります。 DP は、各曲が個別のインデックスとして扱われ、トランジションがアイデンティティではなく純粋にジャンルによってフィルターされるため、これを処理します。 

別のエッジケースが発生するのは次の場合です。$T$曲の長さに比べて短いです。 例えば：```
n=2, T=1
t=[2,3], g=[1,2]
```すべての曲が次の値を超えているため、初期状態は有効ではありません。$T$したがって、DP は全体を通してゼロのままであり、正しく 0 を返します。 

最後の微妙なケースは、1 つの曲だけが完全に適合する場合です。$T$。 DP はその単一の状態を初期化し、拡張することはなく、有効なプレイリストを 1 つだけ生成します。これは、繰り返しは許可されないが単一要素シーケンスは有効であるという要件と一致します。
