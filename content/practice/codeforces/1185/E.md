 ## 解決策
 ## 問題の理解

 各セルが空か、小文字のラテン文字が含まれるグリッドが与えられます。 最終的なグリッドは、「蛇」を繰り返し描くことによって形成されたと主張されており、各蛇は水平または垂直に配置された同一の文字の直線部分です。 各ヘビには、次の順序で文字が割り当てられます。`'a'`以降のスネークは以前のスネークを上書きできます。 

主要な運用モデルは、最終的なグリッドが空のグリッドを取得し、それぞれに個別の文字でラベル付けされた最大 26 個の直線セグメントをオーバーレイした結果であるということです。各セグメントは 1 本の連続した水平線または垂直線でなければなりません。 上書きとは、2 つのヘビが同じセルをカバーしている場合、後のほうのヘビが最終的な文字を決定することを意味します。 

タスクは、指定されたグリッドにそのような構造が存在するかどうかを判断し、存在する場合は最大 26 個のヘビの有効なシーケンスを再構築することです。 

この制約により、考えられるすべてのスネーク分解に対する総当りの再構築は不可能になります。 すべてのテスト ケースにわたる合計グリッド サイズは最大 4x10^6 であるため、どのソリューションも基本的にセル数が線形である必要があります。 

単純な試みでは、各文字のセルを任意にセグメントにグループ化しようとしますが、重なり合う方向が重要であるため、これは失敗します。 もう 1 つの素朴なアイデアは、各文字を独立して扱い、そのすべてのセルをパスに接続することです。ただし、これでは上書きが無視されます。文字は後の文字によって部分的に隠される可能性があり、そのため、表示されているセルは完全に接続された形状を形成しません。 

いくつかの微妙な失敗例がその難しさを示しています。 L 字型に表示される文字を考えてみましょう。```
a a .
. a a
```直線でなければならないため、1 匹のヘビではこれをカバーできません。 単純なグループ化は、明示的に直線性を強制しない限り、これを誤って受け入れてしまいます。 

上書きすると別の障害が発生します。```
a a a
b b b
a a a
```ここ、`'b'`後に描かなければなりません`'a'`上書きもできるので、`'a'`部分的に消去された 2 つの別個の水平セグメントとして存在する必要があります。 最終的な形状が実際の構築順序を反映していないため、文字ごとの単純な接続性チェックは失敗します。 

最大の難点は、文字が独立したオブジェクトではないことです。 それらは、重複によって引き起こされる順序制約を通じて相互作用します。 

## アプローチ

 ブルートフォースパースペクティブでは、表示されているセルを正確にカバーする水平または垂直セグメントを各文字に割り当て、考えられるすべての順列 (最大 26!) で文字を並べようとします。 発注ごとに図面をシミュレーションし、グリッドを再構築できるかどうかを確認します。 単一のシミュレーションでも O(nm) であり、順列は天文学的に大きいため、これは完全に実行不可能です。 

重要な構造的洞察は、プロセスを逆転させることです。 空のグリッドから構築する代わりに、最終的なグリッドを分析し、有効な構築においてどの文字が最後に描画される必要があるかを判断します。 

文字がグリッドに表示される場合は、その外接する四角形を考慮してください。 その文字が蛇として有効である場合、蛇はまっすぐであるため、その文字がすべて単一の行または単一の列に存在する必要があります。 これにより、必要な条件がすぐに得られます。すべての文字が 1 つの行または 1 つの列セグメントを占有する必要があります (上書きのため、最終グリッドでは必ずしも連続しているとは限りませんが、独自のレイヤーでは直線である必要があります)。 

次に依存関係について考えてみましょう。 文字の境界行または列に、その範囲内に異なる他の文字が含まれている場合、それらの文字はその後に描画されている必要があります。 これにより、自然な部分的な順序が与えられます。文字は、必要な直線セグメントを「通過」するすべての文字の後にのみ描画できます。 

これは、文字を逆に構築することを示唆しています。つまり、現在「クリーン」な文字、つまり必要なセグメントが現在のグリッドと一致している文字を繰り返し選択し、それを次のスネークとして出力し、グリッドから消去します。 この貪欲な削除が機能するのは、有効な構造には、各段階でセグメント内に他の文字をブロックしない文字が少なくとも 1 つ含まれている必要があるためです。 

各文字の最小外接長方形を維持し、それが有効な直線セグメントを形成しているかどうかを検証します。 有効な場合は、削除して続行します。 文字数は最大 26 文字であるため、このプロセスには制限があります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース順列 | O(26! · nm) | O(nm) | 遅すぎる |
 | 貪欲な逆除去 | O(26・nm) | O(nm) | 承認済み |

 ## アルゴリズムのチュートリアル

 各テスト ケースを個別に処理し、表示される文字のみを処理します。 

1. グリッドをスキャンしてすべての文字を収集し、その位置を保存します。 文字が表示された場合は、その境界四角形 (行と列の最小値と最大値) を計算します。 
2. 各文字について、それが有効なヘビ セグメントを表すことができるかどうかを確認します。 これは、すべてのセルが厳密に 1 行または 1 列に存在する必要があることを意味します。 どちらも当てはまらない場合、再建は不可能であることがすでにわかっています。 
3. 取り外し可能な文字を選択することを繰り返し試みます。 文字を削除できるのは、その境界四角形が行セグメント全体または列セグメント全体であり、そのセグメント内のすべてのセルに現在その文字が正確に含まれている場合です。 これにより、有効な順序で最後に描画されたヘビに対応することが保証されます。 
4. そのような文字を見つけたら、その端点をヘビとして記録し、そのセルをドットに置き換えることによってグリッドからそれを消去します。 
5. 文字がなくなるまで繰り返します。 いずれかの時点で文字が残っているが削除できない場合は、構成は不可能であると判断します。 
6. 削除は逆の描画順序に対応するため、記録されたスネークを削除の逆順序で出力します。

この貪欲な戦略が機能する主な理由は、有効な構造には常に少なくとも 1 つの「最も外側」のスネークがあり、そのセグメントが以前の構造によって部分的にブロックされていないためです。 後のヘビが以前のヘビを上書きするため、そのヘビの最後に表示されるセグメントは、それを識別した時点ではまだ無傷で、グリッド内にまっすぐに残っている必要があります。 

### なぜ効果があるのか

 反転のどの段階でも、元の有効な構造を考慮してください。 その構造で描かれた最後のヘビは、現在のグリッド状態でもセグメント全体が依然として表示され、中断されない文字に対応します。 その文字は、その直線性を損なうような方法で、他の残りの文字と部分的に重なることはできません。そうでなければ、元々は単一の直線セグメントとして描画できなかったはずです。 これにより、すべての文字が処理されるまで少なくとも 1 つの削除可能な文字が存在することが保証され、貪欲な削除の正確さが維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        grid = [list(input().strip()) for _ in range(n)]

        pos = {}
        for i in range(n):
            for j in range(m):
                c = grid[i][j]
                if c == '.':
                    continue
                if c not in pos:
                    pos[c] = []
                pos[c].append((i, j))

        letters = sorted(pos.keys())
        used = set()

        res = []

        def valid_and_remove(ch):
            cells = pos[ch]
            if not cells:
                return False

            rs = [x for x, _ in cells]
            cs = [y for _, y in cells]
            r1, r2 = min(rs), max(rs)
            c1, c2 = min(cs), max(cs)

            # must be straight line
            if r1 != r2 and c1 != c2:
                return False

            if r1 == r2:
                r = r1
                for j in range(c1, c2 + 1):
                    if grid[r][j] != ch:
                        return False
                res.append((r + 1, c1 + 1, r + 1, c2 + 1))
                for j in range(c1, c2 + 1):
                    grid[r][j] = '.'
                pos[ch] = []
                return True

            else:
                c = c1
                for i in range(r1, r2 + 1):
                    if grid[i][c] != ch:
                        return False
                res.append((r1 + 1, c + 1, r2 + 1, c + 1))
                for i in range(r1, r2 + 1):
                    grid[i][c] = '.'
                pos[ch] = []
                return True

        remaining = set(pos.keys())

        changed = True
        while remaining and changed:
            changed = False
            for ch in list(remaining):
                if valid_and_remove(ch):
                    remaining.remove(ch)
                    changed = True

        if remaining:
            print("NO")
            continue

        print("YES")
        print(len(res))
        for r1, c1, r2, c2 in reversed(res):
            print(r1, c1, r2, c2)

if __name__ == "__main__":
    solve()
```コードはまず各文字の出現をすべて記録し、次に、現在表示されている形状が有効な直線セグメントを形成する文字を繰り返し識別しようとします。 そのような文字が見つかると、その文字はグリッドから削除され、構築プロセスを逆に行うことをシミュレートします。 反転順序は、最終出力が順方向描画順序に対応するように保存されます。 

微妙な点は、有効性が初期のグリッド状態ではなく、現在のグリッド状態に対してチェックされることです。 以前に削除すると、以前に上書きされた隠された構造が露出する可能性があるため、これは不可欠です。 

もう 1 つの重要な詳細は、最後に結果リストを反転することです。 最後に描画されたスネークの削除を最初にシミュレートするため、記録されたシーケンスは、必要な出力順序に対して逆になります。

 ## 特殊なケース

 重大なエッジ ケースは、文字が正しい直線セグメントを形成しているにもかかわらず、最終的なグリッド表現では部分的に上書きされる場合に発生します。 たとえば、有効なヘビが別の文字のセグメントの下に存在する可能性があるため、その可視セルは断片化されています。 

削除では正確な境界線のみについて現在のグリッド状態と照合してチェックされるため、アルゴリズムはこれを処理します。 必要なセルが別の文字で上書きされている場合は、その文字を事前に削除する必要があります。 これにより、正しい順序が強制されます。 

もう 1 つの特殊なケースは、複数の文字が相互に依存するブロックのサイクルを形成する場合です。 このような場合、どの段階でも「クリーン セグメント」条件を満たす文字はなく、アルゴリズムは正しく NO を出力します。 

最後に、単一文字のグリッドまたは文字がまったく含まれていないグリッドは自然に処理されます。アルゴリズムは、単一の有効なセグメントを削除するか、スネークがゼロで直ちに YES を返します。
