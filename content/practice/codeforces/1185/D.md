 ## 解決策
 ## 問題の理解

 順序付けされていない整数のシーケンスが与えられ、その要素を削除すると残りの数値が等差数列を形成できる単一の要素を特定するように求められます。 等差数列は、連続する項間の差が一定である数列です。 入力サイズは 200,000 要素に達する可能性があり、値の範囲は負から正の 10^9 までであるため、すべての可能な部分配列を反復したり、すべての順列を試行したりするソリューションは非常に遅くなります。 ほぼ線形または線形演算時間、理想的には O(n log n) で動作するアルゴリズムが必要です。 

この微妙な点は、いくつかの明らかではないケースから来ています。 まず、シーケンスがすでに等差数列になっている可能性があり、その場合は最初または最後の要素を削除することが有効です。 第 2 に、外れ値は先頭、末尾、または中間のどこかに現れる可能性があるため、最初のいくつかの違いだけを調べる単純なチェックでは、外れ値を見逃す可能性があります。 第三に、すべての要素が等しい可能性があります。これは有効な進行です。 要素を削除すると、要素が保持されます。 最後に、シーケンスに負の数値または大きな数値が含まれている場合は、整数のオーバーフローを回避し、正確な差に依存する必要があります。 

不注意なアプローチでは、単純に並べ替えられた要素間の差異をチェックし、見つかった最初の不一致を削除する可能性がありますが、外れ値が通常の進行の途中にある場合は失敗します。 たとえば、`[2, 4, 6, 9, 8]`、削除`9`与える`[2, 4, 6, 8]`ただし、最初の不一致を削除します`6`間違って実行すると失敗します。 

## アプローチ

 強引な方法は、各要素を削除して、残りのシーケンスが等差数列を形成できるかどうかを確認することです。 削除するたびに、残りの配列をソートして連続する差分をチェックするのに O(n log n) かかり、これを n 回実行すると、複雑さは O(n^2 log n) になります。 n が 2・10^5 までの場合、これは遅すぎます。 

重要な洞察は、有効な等差数列は最初の 2 つの要素によって完全に決定されるということです。 したがって、シーケンスが等差数列にならないのは、余分な要素が 1 つだけである場合のみです。 これは、ソートされた配列の最初の 2 つの要素のうちの 1 つ、または最後の要素を削除することのみを考慮すればよいことを示唆しています。 配列を一度ソートして差異を確認することで、外れ値が先頭、末尾、あるいは中間のどこかにあるかを特定できます。 潜在的な外れ値が特定されたら、プロセス全体を O(n log n) に保ちながら、1 つのパスで差異をスキャンすることで検証できます。 

これにより、問題は、すべての除去の非構造化チェックから、等差数列の構造に基づいた少数の候補除去のセットに変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2 log n) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. シーケンスを読み取り、各要素を元のインデックスとともに保存します。 これにより、後で元の位置を報告することができます。 
2. 配列を値でソートします。 並べ替えは、連続した差分を簡単に計算し、潜在的な外れ値を特定するために必要です。 
3. ソートされた連続する要素間の差異を計算します。 外れ値が存在しない場合、有効な共通差異はシーケンス全体で一貫している必要があります。 
4. 最初の要素、2 番目の要素、最後の要素の 3 つの削除候補を検討します。 これらのいずれかを削除すると、多くの場合、単一の不一致が解決されます。これは、単一の外れ値が開始点付近、終了点付近、または通常の差からの最初の偏差として表示される必要があるためです。 
5. 削除候補ごとに、残りの差分がすべて等しいかどうかを確認します。 存在する場合は、削除された要素の元のインデックスを返します。 
6. 削除候補がどれも機能しない場合、外れ値は中央にあるはずです。 ソートされた配列をスキャンし、予想される共通の差異から逸脱する最初の差異を見つけます。 不一致の原因となっている要素を削除し、残りの要素が有効な進行を生成することを確認すると、答えが得られます。 
7. 単一の削除によって有効な等差数列が生成されない場合は、-1 を返します。 

このアルゴリズムが機能するのは、等差数列が最初の 2 つの要素と共通の差分によって完全に決定されるためです。 シーケンス内に追加要素が 1 つだけあると、最大で 1 つの違いが逸脱します。 最初の相違点と端の候補をチェックすることで、すべてのケースがカバーされていることを確認します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
arr = list(map(int, input().split()))
indexed_arr = [(val, i + 1) for i, val in enumerate(arr)]
indexed_arr.sort()

def check_remove(candidate):
    temp = [x for x in indexed_arr if x != candidate]
    if len(temp) <= 1:
        return True
    diff = temp[1][0] - temp[0][0]
    for i in range(1, len(temp)):
        if temp[i][0] - temp[i-1][0] != diff:
            return False
    return True

# Candidates: first, second, last
for candidate in [indexed_arr[0], indexed_arr[1], indexed_arr[-1]]:
    if check_remove(candidate):
        print(candidate[1])
        sys.exit(0)

# Check internal outlier
diff = indexed_arr[1][0] - indexed_arr[0][0]
for i in range(1, n):
    if indexed_arr[i][0] - indexed_arr[i-1][0] != diff:
        print(indexed_arr[i][1])
        sys.exit(0)

print(-1)
```削除された要素の 1 から始まる位置を返すことができるように、各値を元のインデックスで保存します。 Sorting allows easy computation of differences.`check_remove`連続した差分をスキャンすることで候補を検証します。 エッジ候補は単純な外れ値のケースを解決することが多いため、最初にチェックされます。 最後のループでは、中央で外れ値を確実にキャッチします。 インデックスを保持するために配列をその場で変更することは避けます。
