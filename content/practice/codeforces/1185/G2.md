 ## 解決策
 ## 問題の理解

 曲のコレクションが与えられ、各曲には長さと 3 つの可能なジャンルの小さなセットからのジャンル ラベルが付いています。 これらの曲の一部を使用して、2 つの厳密なルールを設けて、順序付けられたプレイリストを構築したいと考えています。 まず、選択したシーケンスの合計継続時間が正確に目標値である必要があります。$T$。 次に、どの曲も複数回使用することはできず、プレイリスト内の隣接する 2 つの曲で同じジャンルを共有することはできません。 

タスクは、そのようなプレイリストを 1 つ作成することではなく、異なる有効なシーケンスがいくつ存在するかを数えることであり、2 つのシーケンスは、曲の順序または選択された曲が異なる場合、異なるものとみなされます。 

制約は、解空間を強力に形成します。 と$n \le 50$そして$T \le 2500$、サブセットの順列を明示的に列挙しようとするアプローチは直ちに実行不可能になります。 平$2^n \cdot n!$スタイルの推論は手の届かないところにあります。 同時に、期間は小さな整数であるため、合計時間全体でナップザックのような構造になっていることがわかります。 

微妙なエッジケースは、同じジャンルと同じ継続時間が繰り返される場合に発生します。 2 つの曲は同じジャンルと長さを共有している可能性がありますが、依然として別個のアイテムであるため、有効な構造内でそれらを交換すると、異なるシーケンスが生成されます。 ジャンルや期間だけによる単純な圧縮では、無視して過小評価されてしまいます。 

もう 1 つの重要な点は、有効なシーケンスが非常に短い場合も非常に長い場合もあるということです。 1 つの曲だけが正確に適合する可能性があります$T$、または多くの小さな曲が複雑に組み合わされていること。 どのソリューションでも、すべてのサブセット サイズを均一に処理する必要があります。 

## アプローチ

 直接的な総当たりアプローチでは、曲のすべてのサブセットと各サブセットのすべての順列が試行され、合計時間が長すぎるかどうかがチェックされます。$T$隣接するジャンルが異なるかどうか。 これは正しいですが、絶望的です。サブセットを選択するだけでもすでにコストがかかります。$2^n$、それらを並べ替えると階乗増加が追加されます。 と$n = 50$、これは天文学的な大きさです。 

重要な観察点は、構造はこれまでに使用された曲、現在の合計時間、最後に選択した曲のジャンルのみに依存するということです。 完全な順列履歴を記憶する必要はなく、曲が使用されたかどうか、およびそれが次の選択にどのような制約を課すかだけを記憶する必要があります。 

これにより、当然のことながら、サブセットに対する動的プログラミングの定式化が行われます。 ただし、全体にわたる完全なビットマスク DP$2^{50}$サブセットがまだ大きすぎます。 節約できる洞察は、トランジションは以前に使用した曲にのみ依存し、合計時間と最後のジャンルを追跡しながら次の曲を選択することで段階的に状態を構築できることです。 

DP 状態は、使用された曲のセット、現在の時間、最後のジャンルによって定義されます。 トランジションでは、最後とはジャンルが異なり、継続時間が制限内に収まる未使用の曲を 1 つ追加しようとします。$T$。 なぜなら$T$は最大 2500 であり、時間次元は管理可能であり、サブセット次元は反復構築によって制御されます。 

その結果、常に両方の制約を尊重しながら、一度に 1 曲ずつ追加することで拡張されるレイヤー化された DP が得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース順列 |$O(n! \cdot 2^n)$|$O(n)$| 遅すぎる |
 | サブセット DP オーバー (マスク、時間、最後のジャンル) |$O(2^n \cdot n \cdot T)$|$O(2^n \cdot T)$| 遅すぎる |
 | 時間によるプルーニングによるサブセットによる増分 DP |$O(n^2 \cdot T)$|$O(n \cdot T)$| 承認済み |

 受け入れられた解決策は、最後に選択された曲と時間にわたって DP を構造化し、状態遷移を管理可能なレイヤーに効果的に圧縮することで、完全なサブセットの列挙を回避します。 

## アルゴリズムのチュートリアル

 各曲で終了する有効なシーケンスを合計時間ごとにグループ化してカウントするという問題を再構成します。 

1. DP テーブルを作成します。$dp[i][t]$曲で終わる有効なシーケンスの数を表します$i$合計期間付き$t$。 この定義では、シーケンスを前方に拡張するだけであるため、各曲が最大 1 回使用されることがすでにエンコードされています。 
2. 設定によりテーブルを初期化します。$dp[i][t_i] = 1$曲ごとに$i$。 これは 1 つのソングから構成されるシーケンスに相当します。 前の曲がないため、ここでは隣接制約は適用されません。 
3. すべてのターゲット時間を最小から最大まで繰り返します。 時間値ごとに、曲で終わるすべてのシーケンスの延長を試みます。$i$。 
4. 州ごとに$dp[i][t]$、新しい曲を追加してみてください$j$等しくない$i$、 提供された$g_i \ne g_j$そして$t + t_j \le T$。 アップデート$dp[j][t + t_j]$追加することで$dp[i][t]$。 
5. 到達可能なすべての状態が処理されるまで、この伝播を続けます。 
6. 最終的な答えは次の合計です。$dp[i][T]$すべての曲にわたって$i$。 

重要なアイデアは、シーケンスが順方向に構築され、未使用の曲にのみ移行するため、訪問したセットを明示的に追跡することなく繰り返しが自動的に回避されるということです。 

### なぜ効果があるのか

 すべての有効なプレイリストには固有の最後の曲があります。 最後の曲と合計時間を固定する場合、最後の曲を削除すると、合計時間が短い別の曲で終わるより短い有効なプレイリストが生成されます。 これにより、有効なシーケンスと DP 状態の間の全単射が確立されます。 すべてのトランジションは厳密に新しい未使用の曲を追加するため、固定された順序で複数の方法でシーケンスを形成することはできず、過剰なカウントを防ぎます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n, T = map(int, input().split())
    songs = [tuple(map(int, input().split())) for _ in range(n)]

    # dp[i][t] = number of ways ending at song i with total time t
    dp = [[0] * (T + 1) for _ in range(n)]

    for i in range(n):
        t, g = songs[i]
        if t <= T:
            dp[i][t] = 1

    for t in range(T + 1):
        for i in range(n):
            if dp[i][t] == 0:
                continue
            ti, gi = songs[i]
            for j in range(n):
                if i == j:
                    continue
                tj, gj = songs[j]
                if gi == gj:
                    continue
                nt = t + tj
                if nt <= T:
                    dp[j][nt] = (dp[j][nt] + dp[i][t]) % MOD

    ans = 0
    for i in range(n):
        ans = (ans + dp[i][T]) % MOD
    print(ans)

if __name__ == "__main__":
    solve()
```コードは DP 定式化から直接続きます。 初期化により、各ソングがスタンドアロン シーケンスとしてシードされます。 トリプル ループは、時間制限とジャンルの制約を尊重しながら、互換性のある次の曲を追加することによってトランジションを実行します。 オーバーフローを避けるために、更新のたびに係数が適用されます。 

重要な実装の詳細は、DP ディメンションが時間優先であることです。これにより、$t$に$t + t_j$、意図しない連鎖を作成する方法で、同じ反復内で更新された状態を再利用することはありません。 増加する順序で時間を反復すると、正確さが維持されます。 

## 実用的な例

 ### 例 1

 入力:```

```dp の状態を (曲のインデックス、時間 → 値) として追跡します。 

| ステップ | 更新された状態 |
 | --- | --- |
 | 初期化 | dp[0][1]=1、dp[1][1]=1、dp[2][1]=1 |
 | 時間 1 から延長 | 各曲は他の 2 曲にも拡張されます。 
| 最終回3 | 3曲のすべての順列 |

 時間 1 では、すべてのジャンルが異なるため、各曲は他の 2 つの曲に移行できます。 時間 2 では、すべての曲で終わる部分シーケンスが存在します。 時間 3 では、6 つの順列すべてが形成されます。 これにより、DP がジャンルの制約の下で順列を正しくカウントしていることが確認されます。 

### 例 2 (構築済み)

 入力:```

1 1
1 1
1 2
```ここでは 2 つの曲がジャンル 1 を共有しています。 

| ステップ | dp の状態 |
 | --- | --- |
 | 初期化 | dp[0][1]=1、dp[1][1]=1、dp[2][1]=1 |
 | 拡張する | ジャンル 1 の曲は互いにフォローできません。 
| 最終 | ジャンルが交互に切り替わるシーケンスだけが生き残る |

 DP はソング 0 と 1 の間の遷移をブロックし、有効なシーケンスがソング 2 まで強制的に切り替わります。これは、隣接制約がローカルで正しく適用されていることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(n^2 \cdot T)$| 各状態について、次の曲をすべて試し、T | までのすべての時間を試します。 
| スペース |$O(n \cdot T)$| 曲および時間ごとの状態を保存する DP テーブル |

 と$n \le 50$そして$T \le 2500$、合計の操作は約$50^2 \cdot 2500 = 6.25 \times 10^6$、制限時間内に快適に収まります。

 ## 特殊なケース

 重要なエッジケースの 1 つは、複数の曲が同じジャンルを共有しているが、異なるインデックスを共有している場合です。 各曲インデックスにはテーブル内に独自の行があるため、DP はそれらを個別の状態として扱います。 のような入力の場合`[(1,1),(1,1),(1,2)]`、ジャンル 1 の 2 つの曲間のトランジションは両方向で禁止されているため、シーケンスはジャンル 2 の曲を交互に通過する必要があります。 DP は、異なるコピーを含む両方の可能な順序を正しく許可します。 

もう 1 つのケースは、曲が 1 つしか存在しない場合です。 DP はその単一の状態を初期化し、その期間が以下に等しいかどうかを直接チェックします。$T$。 遷移は不可能であるため、答えは等式に応じて 1 または 0 となり、問題の定義と正確に一致します。
