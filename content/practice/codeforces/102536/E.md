 ## 解決策
 ## 問題の理解

 グリッドで表された長方形の床があります。 一部のセルは通常の歩行可能なスペースであり、一部は壁、一部はドアです。 エージェントはマークされたセルから開始します。`A`マークされたセルに到達する必要があります`B`。 

隣接する歩行可能セルへの移動には 1 秒かかります。 ドアセルは閉じている間は歩くことができません。 隣のドアを開けるには 1 秒かかり、一度開けるとエージェントはそこを通過できます。 いつでも、それ以上ではありません`k`ドアが開いたままになる場合があります。 任務は、爆弾に到達するまでの可能な最小限の時間を見つけるか、到達できないことを報告することです。 

制約はグラフ アルゴリズムには十分小さいですが、グリッドの大部分を繰り返し探索するアルゴリズムには十分ではありません。 1 つのグリッドには最大 5000 個のセルが含まれますが、すべてのテスト ケースには最大 300000 個のセルが含まれます。 これは、セルごとにほぼ線形または線形演算の解が必要であることを意味します。 ドアのサブセットの数が指数関数的に増加するため、開いているドアのあらゆる組み合わせを試したソリューションは不可能です。 さまざまなドア構成に対して完全な検索を実行しても、すぐに制限時間を超えてしまいます。 

重要な問題は、エージェントの立場だけではなく、開かれたドアの数が重要であるということです。 ドアの制限を無視した最短パスでは、開いたドアが多すぎる可能性があるため、答えが過小評価される可能性があります。 

小さなケースを考えてみましょう。```
1
1 3 1
ABD
```出力は次のとおりです。```
HAHAHUHU
```エージェントは実際に爆弾の背後にあるためドアに入ることができませんか? この例は無効です。`B`は空のセルである必要があるため、壁以外のすべてのセルを交換可能として扱う不注意な実装は、不正な仮定によりすでに失敗する可能性があります。 有効な小さな例は次のとおりです。```
1
1 4 1
AD.B
```出力は次のとおりです。```
HAHAHUHU
```ドアが唯一のルートを遮断しており、それを回避する方法はありません。 ドアをオープンセルとして扱う通常の BFS は、パスを誤って報告します。 

もう 1 つの重要なケースは、ルートでより多くのドアが使用される場合です。`k`。```
1
1 5 1
ADDB.
```エージェントは 2 つのドアを渡らなければなりませんが、開いたままにできるのは 1 つのドアだけです。 最初のドアは開いたままにすることができますが、通過後は 2 番目のドアを閉める必要があります。 開いたドアの数だけをカウントし、閉めるコストを忘れたソリューションでは、答えが過小評価されてしまいます。 

## アプローチ

 直接的な総当たりアプローチでは、フロアの完全な状態、つまり現在の位置とどのドアが開いているかが正確に保持されます。 未来は両方の情報に依存するため、これは正しいです。 ただし、ある場合は、`m`ドア、これにより、`r*c*2^m`州。 数十のドアがあるグリッドでもこれは不可能です。 

有益な観察は、開いているドアの正体を知る必要がないということです。 選択したルートでは、エージェントが通過するすべてのドアを 1 回開く必要があります。 唯一の決定は、最後にどのドアが開いたままになるかです。 せいぜい`k`そのうち、クロージングコストを回避できます。 

道が交差しているとします`d`ドアセルとその内容`s`細胞間の移動。 移動自体にコストがかかる`s`。 すべてのドアを開けるとコストがかかる`d`。 そのドアの中ではせいぜい`k`閉店を避けてください。 残りのドアごとに、閉じるまでに 1 秒追加されます。 総費用は次のとおりです。`s + d + max(0, d - k)`これは、制限されたドアの数を知る必要があるだけであることを意味します。`k`。 もう越えてしまったら`k`追加のドアはすべて同じように動作します。追加の開閉コストが追加されます。 

グラフを展開できるようになりました。 状態とは、`(cell, x)`、 どこ`x`交差ドアの上限数です`k`。 空のセルに移動すると、`x`変更せず、コストは 1 です。 ドアを通る移動が増える`x`以下であれば`k`; 最初のコストは 2 秒です`k`ドアを開けて3秒後。 

すべてのエッジの重みは小さな正の値であるため、ダイクストラのアルゴリズムは最小距離を見つけることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 開いたドアセットに対するブルートフォース | O(rc * 2^m) | O(rc * 2^m) | 遅すぎる |
 | ドア数の拡大グラフ | O(rc * k log(rc*k)) | O(rc * k) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 開始セルを見つける`A`そして宛先セル`B`。 すべてのグリッド セルが次のような最短パス状態グラフを作成します。`k + 1`可能な状態。 州`x`まさにそれを意味します`x`ドアが渡され、そこで`x = k`また、以下のすべての値を表します`k`。 
2. からダイクストラのアルゴリズムを開始します。`(A, 0)`。 エージェントは最初はドアを渡っていないため、初期ドア数はゼロです。 
3. 状態を拡張するときは、隣接する 4 つのセルのそれぞれに移動してみてください。 壁は決して入ることができないので無視されます。 
4. 隣接セルが空のセルまたは爆弾セルの場合、新しい状態は同じドア数を維持し、1 秒の追加コストを受け取ります。 これはごく普通の動きです。 
5. 隣接ドアがドアの場合、ドア数の状態がまだ下回っている場合は増加させます。`k`。 最初のいずれかを入力すると、`k`ドアの所要時間は 2 秒です。ドアを開けるのに 1 秒、ドアを通過するのに 1 秒です。 その後ドアに入る`k`すでにドアを通過している場合は、そのドアは最終的に閉める必要があるため、3 秒かかります。 
6. 答えは、爆弾室で終わるすべての州間の最小距離です。 ドアの数が異なると、爆弾に到達するコストも異なります。 

なぜ効果があるのか:

 どのルートでも、ドアの追加コストに影響する唯一の情報は、各ドアに入る前に通過したドアの数です。 エージェントは任意のドアを選択できるため、ドアの正確な ID は重要ではありません。`k`ドアは開いたままにしておきます。 状態は、隣のドアに 2 秒かかるか 3 秒かかるかを判断するために必要な情報を正確に保存します。 ダイクストラは合計時間を増加させながら状態を探索し、考えられるすべての有効なルートがこの拡張グラフ内のパスに対応するため、見つかった最小距離が真の最小到着時間となります。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        r, c, k = map(int, input().split())
        grid = []
        start = -1
        target = -1

        for i in range(r):
            row = list(input().strip())
            for j, ch in enumerate(row):
                if ch == 'A':
                    start = i * c + j
                elif ch == 'B':
                    target = i * c + j
            grid.extend(row)

        n = r * c
        states = k + 1
        total = n * states
        INF = 10**18

        dist = [INF] * total
        dist[start * states] = 0

        heap = [(0, start, 0)]

        while heap:
            d, pos, used = heapq.heappop(heap)
            idx = pos * states + used
            if d != dist[idx]:
                continue

            if pos == target:
                ans.append(str(d))
                break

            x = pos // c
            y = pos % c

            for nx, ny in ((x - 1, y), (x + 1, y), (x, y - 1), (x, y + 1)):
                if nx < 0 or nx >= r or ny < 0 or ny >= c:
                    continue

                npos = nx * c + ny
                cell = grid[npos]

                if cell == '#':
                    continue

                if cell == 'D':
                    if used < k:
                        nused = used + 1
                        cost = 2
                    else:
                        nused = k
                        cost = 3
                else:
                    nused = used
                    cost = 1

                nd = d + cost
                nidx = npos * states + nused

                if nd < dist[nidx]:
                    dist[nidx] = nd
                    heapq.heappush(heap, (nd, npos, nused))
        else:
            ans.append("HAHAHUHU")

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```距離配列には、展開されたグラフ状態ごとに 1 つの値が格納されます。 インデックス`cell * (k + 1) + used`すでに通過したドアの数とともにグリッドの位置を一意に識別します。 

ヒープには以下が含まれます`(current distance, cell, used doors)`エントリ。 古いエントリは、その距離が保存されている最短距離と一致しなくなった場合には無視されます。これは、ダイクストラの標準的な遅延削除手法です。 

ドアの移行コストは、実装の詳細の中心となります。 到達する前に`k`ドアを越えて別のドアに入るには 2 秒かかります。 その時点を過ぎると、後ですべての新しいドアを閉じる必要があるため、コストは 3 秒になります。 ドアの数には上限があります`k`、これにより状態の数が管理可能に保たれます。 

ドアを閉じることを明示的にシミュレートする必要はありません。 移行の背後にある公式は、どのドアが開いたままになるかの最適な選択をすでに説明しています。

 ## 特殊なケース

 ドアのないルートは国が処理する`(cell, 0)`のみ。 すべての移動に正確に 1 秒かかるため、アルゴリズムは空のセル上の通常の最短パスに短縮されます。 

最適ルート上のドア数を超えた場合`k`、アルゴリズムは保存するだけで情報を失いません。`k`。 一度`k`ドアはすでに開いたままにすることができ、それ以降のドアには同じ追加料金がかかります。 たとえば、`ADDB.`と`k = 1`、最初のドアは空きスロットを使用し、2 番目のドアは閉鎖ペナルティを追加します。 

ドアが通常のセルと同様に扱われる場合に可能であると思われるルートは拒否されます。これは、ドア セルはドアの遷移を介してのみ入力されるためです。 遷移ロジックはドアを通過できる唯一の場所であるため、壁や閉じたドアが誤って通常の移動セルになることはありません。
