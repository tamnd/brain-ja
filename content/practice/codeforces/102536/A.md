 ## 解決策
 ## 問題の理解

 2 つのパスワードを比較し、編集距離を決定する必要があります。 最初の文字列はユーザ​​ーが入力した文字列で、2 番目の文字列は実際のパスワードです。 編集とは、1 文字の変更、1 文字の挿入、または 1 文字の削除です。 出力は、必要な編集の最小数が 0、1、2、3、またはそれ以上であるかどうかによってのみ異なります。 

入力には最大 10,000 のパスワード ペアを含めることができ、すべてのパスワードを組み合わせた長さは 2,000,000 文字に達することがあります。 通常の動的プログラミング編集距離ソリューションでは、`O(nm)`一定の長さの文字列の時間`n`そして`m`、両方の文字列の長さが約 100,000 である場合、これは非常に高価になります。 長さ 100,000 の 1 つのペアでも、約 100 億回の状態遷移が必要になります。 この解決策では、最大 3 までの距離のみを考慮するという事実を利用する必要があります。 

単純な比較では誤った結果が得られる可能性があるため、特別な注意が必要な場合があります。 1 つ目は、文字列の長さが異なる場合です。 例えば：```
Input:
1
abc
abcd
```正しい出力は次のとおりです。```
You almost got it. You're wrong in just one spot.
```異なる位置のみをカウントする比較では、最初の 3 文字で不一致の位置が検出されず、文字列が一致していると誤って主張されてしまいます。 欠落文字は削除または挿入であるため、カウントする必要があります。 

もう 1 つのケースは、挿入によって後のすべての文字がシフトされる場合です。 例えば：```
Input:
1
abcde
abXcde
```正しい出力は次のとおりです。```
You almost got it. You're wrong in just one spot.
```位置ごとの不一致カウンターでは、挿入したとしても、いくつかの間違った位置が検出されます。`X`1 回の操作ですべてを修正します。 

最後のエッジケースは、長さの変更によって生じる置換編集と複数編集の違いです。 例えば：```
Input:
1
abc
xyz
```正しい出力は次のとおりです。```
You almost got it, but you're wrong in two spots.
```実際には、3 文字すべてを置換する必要があるため、ここでは編集距離は 3 です。 並べ替えたり位置を無視した後で異なる文字の数だけを比較する方法では、誤って分類される可能性があります。 

## アプローチ

 直接的なアプローチは、動的計画法を使用して古典的なレーベンシュタイン距離を計算することです。 2 つの文字列について、一方の文字列のプレフィックスをもう一方の文字列のプレフィックスに変換するために必要な最小編集数を各セルが表す表を作成します。 トランジションでは、文字の削除、文字の挿入、または不一致の文字の置換が考慮されます。 これは正しいです。最適な変換はすべて、これら 3 つの操作のいずれかで終了する必要があるからです。 

問題はテーブルの大きさです。 両方のパスワードの長さが 100,000 の場合、テーブルには約 100 億のセルがあります。 答えの上限は 3 ですが、通常のアルゴリズムは、最終的な決定に影響を及ぼさない状態の計算に依然として時間を費やします。 

重要な観察は、距離が 3 より大きくなると、正確な距離は必要なくなるということです。 距離が最大 3 であるかどうかだけを知る必要があります。 2 つの文字列の長さの差がすでに 3 よりも大きい場合、少なくともその回数の挿入または削除が必要となるため、答えはすぐに大きすぎます。 

長さが近い場合は、少数の編集のみが許可されるという事実を利用して文字列を揃えることができます。 文字列の違いが最大 3 回の操作の場合、一致する部分はほぼ位置合わせされたままでなければなりません。 両端から一致する文字を再帰的にスキップして、残っている小さな不一致領域を処理できます。 それぞれの不一致は、考えられる編集操作を試行し、編集数が 3 を超えたらすぐに停止することで解決できます。 

ブルートフォース ソリューションは、考えられるすべての編集シーケンスが考慮されるため機能しますが、考えられるシーケンスの数が急速に増加するため失敗します。 許容される距離が小さな定数であるという観察により、完全な動的プログラミング テーブルを構築する代わりに、現在の不一致の周囲の小さなスペースのみを検索できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 編集数の指数関数的増加 | O(深さ) | 遅すぎる |
 | 完全な動的プログラミング | O(nm) | O(nm) または O(min(n,m)) | 最大入力に対して遅すぎる |
 | 最適な境界検索 | O(k * L)、ここで k = 3、L は結合された文字列の長さ | O(k) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 2 つのパスワードを読み取ります。 それらが同一の場合、編集距離はゼロとなり、すぐにログイン成功メッセージを返すことができます。 最初に等価性をチェックすると、最も一般的な単純なケースでの不必要な再帰作業も回避されます。 
2. 2 つのパスワードの長さを比較します。 それらの差が 3 より大きい場合は、3 より大きい距離のメッセージを返します。 長さの違いが 4 である場合、既存のすべての文字が一致する場合でも、すでに 4 回の挿入または削除が必要になります。 
3. 2 つの現在位置と既に使用された編集の数を受け取る再帰関数を使用します。 さらに作業を行う前に、現在の位置から一致する文字をすべてスキップします。 一致する文字が最適な編集シーケンスに参加する必要はありません。 
4. 1 つの文字列が最後に到達した場合、もう 1 つの文字列の残りの文字をすべて挿入または削除する必要があります。 残りの長さを現在の編集数に追加します。 
5. 現在の編集数がすでに 3 を超えている場合は、このパスの探索を停止します。 距離が長くても最終カテゴリには影響しません。 
6. 両方の文字列にまだ文字が残っており、それらが異なる場合は、可能な 3 つの編集操作を試してください。 両方の文字を置き換えて次に進むか、最初の文字列から文字を削除するか、2 番目の文字列から文字を削除します。 見つかった編集の最小数を返します。 
7. 最終距離を必要な出力メッセージに変換します。 3 を超える距離は同じ出力を共有します。

機能する理由: 等しいプレフィックスをすべて削除した後、最初に残った文字は異なります。 最適な編集シーケンスでは、これらの文字の 1 つを置換するか、それらの 1 つを削除するか、またはそれらの文字の 1 つの前に文字を挿入する必要があります。 これらはまさに、アルゴリズムによって探索される 3 つの遷移です。 再帰は、3 つ以上の編集が必要であることが証明された後にのみ停止します。これは、すべての大きな距離で必要な出力が同じであるため、これで十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

LIMIT = 3

def limited_distance(a, b):
    from functools import lru_cache

    @lru_cache(maxsize=None)
    def solve(i, j, used):
        while i < len(a) and j < len(b) and a[i] == b[j]:
            i += 1
            j += 1

        if i == len(a):
            return used + (len(b) - j)
        if j == len(b):
            return used + (len(a) - i)

        if used > LIMIT:
            return LIMIT + 1

        best = LIMIT + 1

        best = min(best, solve(i + 1, j + 1, used + 1))
        best = min(best, solve(i + 1, j, used + 1))
        best = min(best, solve(i, j + 1, used + 1))

        return best

    return solve(0, 0, 0)

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        a = input().rstrip("\n")
        b = input().rstrip("\n")

        d = limited_distance(a, b)

        if d == 0:
            ans.append("You're logged in!")
        elif d == 1:
            ans.append("You almost got it. You're wrong in just one spot.")
        elif d == 2:
            ans.append("You almost got it, but you're wrong in two spots.")
        elif d == 3:
            ans.append("You're wrong in three spots.")
        else:
            ans.append("What you entered is too different from the real password.")

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```の`limited_distance`関数は、アルゴリズムで説明されている限定された検索です。 キャッシュには、2 つの現在位置と既に使用された編集の数から構成される状態が保存されます。 編集数が含まれるのは、異なる数の編集を使用した後に同じ位置のペアに到達すると、枝刈りの決定が異なる可能性があるためです。 

等しい文字をスキップするループが主な最適化です。 パスワードの長い同一セクションは、再帰状態を作成せずに無視されます。 編集は 3 つだけ許可されるため、再帰的分岐は文字列が異なるいくつかの場所の周囲でのみ発生します。 

基本ケースは、1 つのパスワードが最初に終わる状況を処理します。 他のパスワードの残りのサフィックスは他の方法で一致させることができないため、残りのすべての文字を挿入または削除する必要があります。 

この関数は、4 つ以上の距離を区別する必要はありません。 戻る`LIMIT + 1`これらすべてのケースで同じ出力が生成されるため、これで十分です。 ここでは Python 整数はオーバーフローせず、不一致領域に近い状態のみが調査されるため、キャッシュ サイズは小さいままです。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(3L) は O(L) | 探索された各状態は小さな編集距離境界内にあり、一致する実行はスキップされます。 |

 ## 特殊なケース

 3 を超える長さの違いは、再帰によって時間が無駄になる前に処理されます。 例えば：```
Input:
1
a
abcde
```2 番目のパスワードには 4 つの余分な文字が含まれています。 たとえ既存の`a`完全に一致する場合、4 つの挿入が必要です。 アルゴリズムは 3 より大きい距離を返し、次のように出力します。```
What you entered is too different from the real password.
```位置ベースの不一致カウンターは、誤って共有文字のみに焦点を当て、必要な挿入を見逃してしまいます。 

アルゴリズムは置換だけでなく削除と挿入も試行するため、パスワードの途中に 1 回挿入しても処理されます。 のために：```
Input:
1
abcde
abXcde
```再帰的な処理がスキップされる`ab`、不一致に達し、削除を試みます`X`2番目の文字列から。 残りの文字は一致し、距離は 1 になります。 

比較では実際の文字が使用されるため、同じ文字を含むが大文字小文字が異なるパスワードは異なるものとして扱われます。 のために：```
Input:
1
Password
password
```最初の文字が異なるため、アルゴリズムは置換をカウントします。 出力は次のとおりです。```
You almost got it. You're wrong in just one spot.
```これにより、誤ってパスワードを大文字と小文字を区別しないものとして扱ってしまい、比較の意味が変わってしまうことを回避できます。
