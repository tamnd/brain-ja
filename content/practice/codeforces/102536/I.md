 ## 解決策
 ## 問題の理解

 会社の階層は根を張ったツリーです。 従業員`i`は調査対象地域のルートであり、有効なレポートは、次の内容が含まれる接続された従業員のセットです。`i`。 構造はツリーであるため、子孫を含めるたびに、パス上のすべての従業員が`i`も含める必要があります。 

各従業員は 2 つのタイプのいずれかを持っています。 クエリは、サブツリー内に有効な接続セットがあるかどうかを尋ねます。`i`正確に含まれています`c`タイプの従業員`C`そしてまさに`s`タイプの従業員`S`。 

入力順序には便利な特性があります。すべての親がその子の前に表示されます。 これにより、動的プログラミングを逆インデックス順序で実行できるようになります。 制限は非対称です。`10000`従業員、ただし最大`200000`クエリ。 すべてのクエリに対してツリーを探索するソリューションには、次のようなものが必要になります。`2 * 10^9`最悪の場合、制限時間を大幅に超えてノードが訪問することになります。 前処理フェーズでは、ほぼすべての作業を実行する必要があり、各クエリはほぼ一定時間になります。 

よくある間違いは、可能なサブツリー サイズのみを保存することです。 同じサイズの 2 つの接続されたセットには異なる数のデータが含まれる可能性があるため、情報が失われます。`C`従業員。 

たとえば、次のことを考えてみましょう。```
2 1
0 1
CS
1 1 1
```答えは`COMPROMISED`両方の従業員を選択すると 1 つが得られるため、`C`そして1つ`S`。 可能なサイズのみを保存するソリューションでは、そのサイズがわかります。`2`可能ですが、分布はわかりません。 

もう 1 つのエッジ ケースは、サブツリー サイズよりも大きなカウントを要求するクエリです。```
1 2
0
C
1 0 1
1 2 0
```最初のクエリは`COMPROMISED`なぜなら、単一ノードは社会主義者のカウントが 0、資本主義者のカウントが 1 であるからです。 2 番目のクエリは、`NOT COMPROMISED`、従業員が足りないからです。 配列境界のチェックを忘れた実装では、無効な状態に誤ってアクセスする可能性があります。 

## アプローチ

 直接的な解決策は、クエリごとに接続されているすべてのルート サブツリーを列挙することです。 考えられるすべての答えがチェックされるため、これは正しいですが、接続されたサブツリーの数は指数関数的に増加する可能性があります。 どんなに長い道でも`10000`すでに 2 次数のルート接続された選択肢があり、これを行うと、`200000`クエリは不可能です。 

最初の改善点は、すべてのノードを前処理することです。 ノードの場合`v`、接続されている可能性のあるすべてのサブツリーを保存するのではなく、可能性のあるすべてのサイズの情報を保存します。`t`。 接続されたすべてのサイズのセットの中で`t`に根ざした`v`、可能な最小数と最大数のみが必要です。`C`従業員。 重要な観察は、これら 2 つの極端な値の間にあるすべての値も可能であるということです。 

最小数であれば、`C`従業員は`a`そして最大値は`b`、選択したノードを一度に 1 つずつ置き換えることによって、最小構成を最大構成に変換すると、カウントは毎回最大 1 つずつ変化します。 シーケンスは、次のすべての値を通過する必要があります。`a`に`b`。 

したがって、動的プログラミングの状態は次のようになります。`minC[v][t]`= の最小数`C`有効な接続セット内の従業員`t`をルートとするノード`v`。`maxC[v][t]`も同様に定義されます。 

子を結合するときは、木のナップザックのように、考えられる貢献を結合します。 ノードのペアは、最も低い共通の祖先が処理される場合にのみ結合されるため、合計のマージ作業は 3 次ではなく 2 次になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | クエリごとの指数 | O(n) | 遅すぎる |
 | 最適なDP | O(n²) 前処理、O(1) クエリ | O(n²) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. からのプロセスノード`n`まで`1`。 親のインデックスは常に子よりも小さいため、すべての子はすでに処理されています。 
2. ノード自体を使用してノードの動的プログラミング状態を初期化します。 ノードが`C`、サイズ 1 の接続されたセットには 1 人の資本家がいます。 もしそうなら`S`、値はゼロです。 
3. すべての子を現在のノードにマージします。 すでに取得されているノードのすべての可能な数と、子サブツリーから取得されるすべての可能な数について、最小および最大のキャピタリスト カウントを更新します。 
4. ノードごとに結果の配列を保存します。 クエリ`(i, c, s)`接続されたサイズのセットについて尋ねます`c+s`。 もし`c`間にあります`minC[i][c+s]`そして`maxC[i][c+s]`、答えは`COMPROMISED`。 

それが機能する理由: DP は、あらゆる規模の可能な極端な数の資本家を保存します。 間隔プロパティは、これらの極値の間に欠落している値がないことを証明します。 クエリ条件は、要求された資本家の数がその範囲に属するかどうかを正確にチェックし、合計サイズによって社会主義者の数が自動的に決定されます。 

## Python ソリューション```python
import sys
from array import array

input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    parent = list(map(int, input().split()))
    s = input().strip()

    children = [[] for _ in range(n)]
    for i in range(1, n):
        children[parent[i] - 1].append(i)

    INF = 30000
    mins = [None] * n
    maxs = [None] * n

    for v in range(n - 1, -1, -1):
        val = 1 if s[v] == 'C' else 0

        if len(children[v]) == 0:
            mins[v] = array('h', [INF, val])
            maxs[v] = array('h', [-INF, val])
            continue

        if len(children[v]) == 1:
            ch = children[v][0]
            cm = mins[ch]
            cx = maxs[ch]
            mn = array('h', [INF] * (len(cm) + 1))
            mx = array('h', [-INF] * (len(cx) + 1))
            mn[1] = val
            mx[1] = val
            for t in range(1, len(cm)):
                mn[t + 1] = cm[t] + val
                mx[t + 1] = cx[t] + val
            mins[v] = mn
            maxs[v] = mx
            continue

        cur_min = array('h', [INF, val])
        cur_max = array('h', [-INF, val])

        for ch in children[v]:
            cm = mins[ch]
            cx = maxs[ch]
            a = len(cur_min) - 1
            b = len(cm) - 1
            nm = array('h', [INF] * (a + b + 1))
            nx = array('h', [-INF] * (a + b + 1))

            for i in range(1, a + 1):
                if cur_min[i] < nm[i]:
                    nm[i] = cur_min[i]
                if cur_max[i] > nx[i]:
                    nx[i] = cur_max[i]

            for i in range(1, a + 1):
                if cur_min[i] == INF:
                    continue
                for j in range(1, b + 1):
                    if cm[j] != INF:
                        x = cur_min[i] + cm[j]
                        if x < nm[i + j]:
                            nm[i + j] = x
                    if cx[j] != -INF:
                        x = cur_max[i] + cx[j]
                        if x > nx[i + j]:
                            nx[i + j] = x

            cur_min, cur_max = nm, nx

        for i in range(1, len(cur_min)):
            cur_min[i] += val
            cur_max[i] += val

        mins[v] = cur_min
        maxs[v] = cur_max

    out = []
    for _ in range(q):
        i, c, st = map(int, input().split())
        i -= 1
        size = c + st
        if size < len(mins[i]) and mins[i][size] <= c <= maxs[i][size]:
            out.append("COMPROMISED")
        else:
            out.append("NOT COMPROMISED")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```逆反復では、入力順序によって有効なボトムアップ順序がすでに与えられているため、再帰の深さの問題が回避されます。 格納された各配列には、可能な接続セット サイズごとに 1 つのエントリがあります。 の`array('h')`格納されているすべての値が最大で 1 つであるため、コンテナーはメモリ使用量を低く抑えます。`10000`。 

単一子の最適化が必要です。 これがないと、パス状のツリーが大きな子ステートを繰り返しマージし、立体的な作業に劣化してしまいます。 最適化により、高価なナップザック マージは分岐ノードでのみ発生し、ツリー全体にわたるペアごとの相互作用の総量は 2 次のままになります。 

クエリで使用されるのは、`size = c + s`なぜなら、選ばれた従業員は皆、次のいずれかであるからです。`C`または`S`。 規模と資本家の数が決まれば、社会主義者の数も決まります。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n² + q) | ツリー ナップザックの前処理と定数時間クエリ |
 | スペース | O(n²) | すべての DP 間隔はノードごとに保存されます。 

サブツリー サイズの最大合計は約`n²/2`これは、チェーンあたり約 5,000 万の州になります。 コンパクトな整数配列により、これが十分なメモリ制限内に収まります。

 ## 特殊なケース

 単一の従業員ツリーは、サイズ 1 の状態のみを初期化することによって処理されます。 子のマージは行われないため、答えは従業員自身のタイプのみに依存します。 

長いチェーンの場合、単一子の遷移はサイズを変更して子の状態をコピーします。 これにより、高価なネストされたマージが回避され、実行時間が二次関数に保たれます。 

分岐ツリーの場合、マージ ステップでは両極端が維持されます。 間隔プロパティは 2 つの極端な値の間で考えられるすべての資本主義カウントをカバーするため、中間値を要求するクエリは受け入れられます。
