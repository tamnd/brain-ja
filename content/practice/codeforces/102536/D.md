 ## 解決策
 ## 問題の理解

 このタスクは、ユーザーの年齢とコンテンツの評価カテゴリという 2 つの情報に基づいて、ユーザーがコンテンツにアクセスできるかどうかを決定することです。 タイトル自体は決定に影響を与えず、入力フォーマットの一部にすぎません。 責任ある大人が同伴する場合に若い人でも入場できる特別な PG ケースを除き、レーティングによって最低年齢要件が決まります。 

入力には、1 行目に 1 つの年齢値と 1 つの評価文字列が含まれ、その後 2 行目にコンテンツ タイトルが続きます。 出力はアクセス決定を説明します。 通常の承認、大人の同伴を必要とする条件付き承認、または拒否の場合があります。 

年齢は 10^9 まで大きくすることができますが、決定はその年齢をいくつかの固定しきい値と比較することによってのみ決まります。 タイトルの長さは最大 100 文字なので、読み取りや保存は簡単です。 タイトルをスキャンしたり、年齢に比例する計算を実行したりするソリューションは不要です。 目的のアルゴリズムでは、入力を解析した後に定数時間を使用する必要があります。 

不注意な実装によって問題が発生する主なケースは、正確な境界年齢です。 たとえば、ちょうど 13 歳の人は R-13 コンテンツへの参加を許可されるべきです。```
13 R-13
Example
```正しい出力は次のとおりです。```
OK
```を使用した解決策`age > 13`の代わりに`age >= 13`このケースは誤って拒否されてしまいます。 

もう 1 つの重要なケースは、若者を対象とした PG コンテンツです。 PG では同伴であればアクセスが許可されているため、1 歳児がすぐに拒否されることはありません。```
1 PG
Example
```正しい出力は次のとおりです。```
OK IF ACCOMPANIED
```13 歳未満のすべての年齢を禁止されているものとして扱う解決策は、間違った結果を生み出すでしょう。 

G レーティングには年齢制限がないため、これも特別なケースです。```
0 G
Example
```正しい出力は次のとおりです。```
OK
```すべてのレーティングに最低年齢チェックを適用する実装はここで失敗します。 

## アプローチ

 直接的なアプローチは、すべての評価に対して一連の条件を作成し、それを 1 つずつチェックすることです。 可能な評価値が 5 つしかないため、これはすでに自然な強引な方法です。 その作業は一定です。入力を読み取り、必要に応じて年齢としきい値を比較し、対応する結果を出力します。 

タイトルは決定に何の役割も持たないため、タイトルに関係する意味のあるスローブルートフォースは存在しません。 考えられるすべての年齢値を繰り返し検査する仮説的なアプローチでは、最大のケースで最大 10^9 のチェックが実行されますが、これは利用可能な時間をはるかに超えています。 問題の構造から、年齢と固定カットオフの関係のみが重要であることがわかります。 

重要な観察は、すべての評価が単純なルールで表現できるということです。 G は常に成功します。 PG には、13 歳未満の年齢に対する条件付き結果が 1 つあります。R-13、R-16、および R-18 はすべて最低年齢要件です。 これらのルールを明示的に記述すると、問題全体が一定数の比較になります。 

可能なカテゴリの数が少ないため、総当り攻撃が機能しますが、入力サイズが一般的な検索やシミュレーションを必要としないことがわかると、有益な洞察が得られます。 評価システムが固定の決定テーブルであるという観察により、解決策をいくつかの条件付きチェックに減らすことができます。

 ## アルゴリズムのチュートリアル

 1. その人の年齢と要求された評価を読み取ります。 タイトルは入力からも消費できますが、結果には影響しません。 
2. 評価が G の場合、このカテゴリには年齢制限がないため、すぐに OK を返します。 
3. レーティングが PG の場合は、年齢を 13 歳と比較します。通常は 13 歳以上が承認されますが、それより若い年齢の場合は承認メッセージが表示されます。 
4. レイティングが R-13、R-16、または R-18 の場合、レイティング番号から必要な最低年齢を決定し、それを人物の年齢と比較します。 年齢が必要な値以上である場合にのみ受け入れられます。 
5. 結果と一致する決定文字列を出力します。 

これが機能する理由は、評価ルールがすべての可能な入力の完全な分割を形成しているためです。 各評価にはルールが 1 つだけあり、各ルールは評価システムによって記述された条件と直接一致します。 

なぜ効果があるのか:

 任意の入力に対して、アルゴリズムは指定された評価に対応するルールを選択します。 G の場合、ルールは全員を受け入れます。これは無制限のカテゴリに一致します。 PG の場合、アルゴリズムは人々を通常の年齢要件を満たす人と同伴が必要な人に分類します。 制限された評価の場合、アルゴリズムは最低年齢条件を満たす年齢を正確に受け入れます。 考えられるすべての評価が正しいルールによって処理されるため、生成される出力は常に必要なアクセス決定と一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

age, rating = input().split()
age = int(age)

if rating == "G":
    print("OK")
elif rating == "PG":
    if age >= 13:
        print("OK")
    else:
        print("OK IF ACCOMPANIED")
else:
    limit = int(rating[2:])
    if age >= limit:
        print("OK")
    else:
        print("ACCESS DENIED")
```コードはまず年齢を評価から分離し、数値比較を実行できるように年齢を整数に変換します。 タイトル行には、決定プロセスで使用される情報が含まれていないため、解析後には必要ありません。 

G ブランチが最初に来るのは、年齢を完全に無視しているためです。 PG ブランチには 2 つの可能な結果があります。`age >= 13`したがって、ちょうど 13 の境界ケースは正しく処理されます。 

残りの評価はすべて同じ形式です。R の後にハイフンと数字が続きます。 最初の 2 文字の後の部分文字列を抽出すると、必要な最小年齢が得られます。 Python の整数は、オーバーフローを心配することなく最大経過時間の値を処理できます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | お(1) | このアルゴリズムは、固定数の文字列操作と比較を実行します。 |
 | スペース | お(1) | 少数の変数のみが保存されます。 |

 固定定数と比較するだけなので、可能な最大年齢を設定しても仕事量は増加しません。 タイトルの長さは短く、計算に影響を与えないため、ソリューションは時間とメモリの制限内に簡単に収まります。 

## テストケース```python
import sys
import io

def solve():
    input = sys.stdin.readline
    age, rating = input().split()
    age = int(age)

    if rating == "G":
        return "OK"
    elif rating == "PG":
        if age >= 13:
            return "OK"
        return "OK IF ACCOMPANIED"
    else:
        limit = int(rating[2:])
        if age >= limit:
            return "OK"
        return "ACCESS DENIED"

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    return solve()

assert run("18 R-18\nFrozen 3\n") == "OK", "sample 1"
assert run("1 R-13\nStar Wars: The Fall of Skywalker\n") == "ACCESS DENIED", "sample 2"
assert run("13 PG\nAgent Cody Banks\n") == "OK", "sample 3"

assert run("0 G\nAnything\n") == "OK", "minimum age with unrestricted rating"
assert run("12 PG\nMovie\n") == "OK IF ACCOMPANIED", "PG boundary below 13"
assert run("16 R-16\nMovie\n") == "OK", "exact restricted boundary"
assert run("1000000000 R-18\nMovie\n") == "OK", "maximum age value"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`0 G`|`OK`| 年齢要件なしで評価を処理します。 |
 |`12 PG`|`OK IF ACCOMPANIED`| しきい値を下回る特殊な PG の動作をチェックします。 |
 |`16 R-16`|`OK`| 制限された評価境界での同等性をチェックします。 |
 |`1000000000 R-18`|`OK`| 大きな年齢値が正しく処理されることを確認します。 |

 ## 特殊なケース

 正確に最低年齢にある人の場合、アルゴリズムは以上の比較を使用します。```
13 R-13
Movie
```評価は G または PG ではないため、コードは制限を 13 として抽出し、`13 >= 13`。 条件は成功し、答えは次のようになります。`OK`。 

13 歳未満の子供がいる PG 評価の場合、アルゴリズムはすぐには拒否しません。```
5 PG
Movie
```コードはPGブランチに入り、チェックします`5 >= 13`、そしてそれが間違っていることがわかります。 PGは伴奏可なので正解は`OK IF ACCOMPANIED`。 

非常に若い人が含まれる G 評価の場合、アルゴリズムは年齢の比較を実行しません。```
0 G
Movie
```最初の条件が一致すると、答えは次のようになります。`OK`。 これにより、他のカテゴリに属する​​制限が誤って適用されることが回避されます。
