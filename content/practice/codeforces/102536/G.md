 ## 解決策
 ## 問題の理解

 一連のキャストを構築する必要があります。 キャストはまさに次のセットです`g`出演者の中から選ばれた俳優`a`俳優たち。 最初のキャストは固定です。 次のすべてのムービーは、俳優を 1 人だけ削除し、別の俳優を 1 人だけ追加することによって取得する必要があります。 また、どのキャストセットも重複して登場することはありません。 

タスクは特定のシーケンスを見つけることではなく、有効な長さのシーケンスだけを見つけることです。`n`指定されたキャストから開始します。 

重要な制約は、`a`せいぜい`1000`、 その間`n`せいぜい`10000`。 可能なキャストの数は膨大になる可能性があるため、すべてのキャストを生成することは不可能です。 必要なのは、有効な順序の小さなプレフィックスだけです。 状態空間の探索に指数関数的な時間を費やすソリューションは失敗します。 

よくある間違いは、同じ俳優を新しい俳優に繰り返し置き換えることです。 たとえば、`g = 2`そして俳優たち`{a,b,c,d}`、シーケンス`{a,b}`、`{a,c}`、`{a,d}`未使用のキャストがたくさん残っているにもかかわらず、すぐにスタックしてしまいます。 変化する位置も最終的には移動する必要があります。 

もう一つの間違いは、キャストがセットであることを忘れていることです。 同じアクターを削除および追加しても変化は生じず、そのような遷移を出力することはルールに違反します。 

## アプローチ

 ブルート フォース ソリューションでは、考えられるすべてのキャストがグラフ内のノードとして扱われます。 2 つのノードのキャストが 1 つのアクターだけ異なる場合、2 つのノードは接続されています。 指定されたキャストから開始して、DFS を実行して、次の長さのパスを検索できます。`n`。 すべてのエッジが合法的なムービー トランジションを表すため、これは正しいです。 

問題はこのグラフの大きさです。 含まれています`C(a,g)`州は大きすぎます。 すべての隣接する州を繰り返しチェックすることさえ不可能です。`a`到達する`1000`。 

有益な観察は、キャストが固定サイズのサブセットであるということです。 固定サイズのサブセットにはグレイ コードの順序があり、1 つの要素のみを交換することで連続するサブセットが異なります。 このような順序を列挙し、その最初のサブセットを指定されたキャストと等しくすることができれば、連続するすべてのペアが自動的に合法的な映画トランジションになります。 

これを行うには、アクターを並べ替えます。 サイズの組み合わせを生成する場合`k`最初から始める`k`アクターの場合、最初に選択したアクターを並べ替えたリストの最初に配置できます。 いつ`g`is large, it is easier to generate the missing actors instead, because replacing one member of the cast is equivalent to replacing one member of its complement.

 ## アルゴリズムのチュートリアル

 1.キャストサイズの場合`g`がキャスト外の俳優の数以下である場合は、キャスト内の俳優の組み合わせを生成します。 それ以外の場合は、キャストの外にある俳優の組み合わせを生成します。 補数表現により、生成されるサブセットは小さく保たれます。 
2. 現在のサブセットが最初に表示されるようにアクターを並べ替えます。`k`俳優たち。 グレーコードオーバー`k`選ばれた俳優は常に最初から始まります`k`ポジション。 
3. 固定サイズのグレイ コードを再帰的に生成します。 前半は最後の俳優を不在のままにし、後半は方向を反転しながら存在を維持します。 この反映により、2 つの半分の間の境界は 1 人の俳優だけが変更されます。 
4. 最初に生成されたサブセットは最初のムービーであるため無視します。 後続のすべてのサブセットについて、前のサブセットと比較します。 消えた要素はアクターが去ることであり、新しい要素はアクターが参加することです。 
5. 生産後停止`n - 1`トランジション。 

これが機能する理由: 生成された順序には、連続するすべてのサブセットが選択された 1 つの要素内で異なるという不変条件が含まれます。 選択された要素はキャスト内の俳優またはキャスト外の俳優のいずれかを表すため、これは常に 1 人の俳優の削除と 1 人の俳優の追加に対応します。 最初の並べ替えにより、最初に生成されたサブセットが必要な最初のムービーと同じになるため、シーケンス全体が正しく開始されます。 グレイ コードの生成ではサブセットが繰り返されることはないため、映画のキャストはすべて一意です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def gray_combinations(n, k, rev=False, start=0):
    if k == 0:
        yield ()
        return
    if k == n:
        yield tuple(range(start, start + n))
        return

    if not rev:
        yield from gray_combinations(n - 1, k, False, start)
        for x in gray_combinations(n - 1, k - 1, True, start):
            yield x + (start + n - 1,)
    else:
        for x in gray_combinations(n - 1, k - 1, False, start):
            yield x + (start + n - 1,)
        yield from gray_combinations(n - 1, k, True, start)

def solve():
    t = int(input())
    ans_all = []

    for case in range(t):
        g, n, a = map(int, input().split())
        actors = input().split()
        initial = input().split()

        initial_set = set(initial)

        if g <= a - g:
            small = initial[:]
            rest = [x for x in actors if x not in initial_set]
            order = small + rest
            k = g
            complement = False
        else:
            small = [x for x in actors if x not in initial_set]
            rest = initial[:]
            order = small + rest
            k = a - g
            complement = True

        previous = set(range(k))
        result = []
        count = 0

        for comb in gray_combinations(a, k):
            if count == 0:
                count += 1
                continue

            if count >= n:
                break

            current = set(comb)

            if complement:
                old = set(range(a)) - previous
                new = set(range(a)) - current
            else:
                old = previous
                new = current

            out_idx = next(iter(old - new))
            in_idx = next(iter(new - old))

            result.append(order[out_idx] + " " + order[in_idx])

            previous = current
            count += 1

        ans_all.append("\n".join(result))

    print("\n\n".join(ans_all))

solve()
```再帰ジェネレータはソリューションの中核です。 非反転方向では、最初に最新のアクターを含まないサブセットが生成され、次にそれを含むサブセットが逆の順序で生成されます。 逆方向では、これら 2 つの部分が交換されます。 前半の最後のサブセットと後半の最初のサブセットは、最も新しい俳優だけが異なる必要があるため、この反転が必要です。 

補数の処理は微妙な部分です。 内部アクターの代わりに外部アクターを生成すると、生成されたサブセットはキャストから欠落しているアクターを記述します。 欠落しているセットの要素が 1 つ変更されても、実際のキャストに 1 人の俳優が出入りするだけです。 

遷移抽出は集合差分を利用する。 グレイ コードでは変更された要素が 1 つだけ保証されるため、両方の違いにはアクターが 1 つだけ含まれるため、検索や追加の検証は必要ありません。

## 特殊なケース

 いつ`g = 1`1 要素の組み合わせのグレイ コードがアクターを 1 つずつ処理するだけなので、アルゴリズムは依然として機能します。 この移行は、前の単一のアクターを置き換えるだけです。 

いつ`g = a - 1`代わりに、欠落しているアクターを生成することで、セットのほぼ全体を生成するという困難なケースを回避できます。 たとえば、俳優が 5 人、キャスト メンバーが 4 人の場合、キャストが変わると正確に欠けている俳優も変わります。 

初期キャストにソート順ではないアクターが含まれている場合、解決策は入力順序に依存しません。 最初`k`並べ替えられたリストの俳優は、最初に生成された組み合わせが指定されたキャストになるように特別に選択されます。
