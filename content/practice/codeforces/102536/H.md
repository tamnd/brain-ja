 ## 解決策
 ## 問題の理解

 グリッドは、有効なセルが対角線の廊下を形成する長方形です。 廊下には幅がある`l - w + 1`、各行がコリドーを 1 つ右に移動します。 パスは右または下にのみ移動するため、問題は、この斜めのストリップから決して出ない単調なパスを数えることです。 

直接動的プログラミング ソリューションでは、すべてのセルに到達する方法の数が保存されます。 それには約の処理が必要になります`l * w`セルは大きすぎるため、`l`到達できる`5 * 10^6`そして`w`到達できる`5 * 10^5`。 

有用な観察は、コリドー条件を 1 次元の歩行に変換できることです。 現在の値を次のようにします。```
column - row
```右に動かすとこの値が 1 ずつ増加し、下に動かすと 1 ずつ減少します。 開始値は`0`、最終的な値は`l - w`、この値が の間にあるとき、パスは正確に有効です。`0`そして`l - w`。 

これにより、問題は、境界のあるストリップ内の歩行をカウントすることに変わります。 

## アプローチ

 ブルート フォース ソリューションでは、グリッド上で動的プログラミングを使用します。 開いたセルごとに、上のセルと左側のセルからウェイの数が加算されます。 これは正しいです。すべての有効なパスは、これら 2 つの方向のいずれかから正確にセルに到達します。 ただし、セルの数は約`2.5 * 10^12`, したがって、このアプローチは不可能です。 

重要な観察は、1 次元の歩行には 2 つの禁止された境界があるということです。 反射原理により、境界を横切るすべてのパスを反射することで無効な歩行をカウントできます。 結果は、通常の二項係数の交互の合計になります。 

させて：```
n = l + w - 2
d = l - w
```答えは次のようになります。```
sum over k:
C(n, l - 1 + k(d + 2)) - C(n, l + k(d + 2))
```間のインデックスのみ`0`そして`n`重要なので、和には少数の項が含まれます。`d`大きいとき`d`ステップサイズは小さいですが、項の数はまだ管理可能です。 

弾性率`104857601`は素数であるため、階乗と逆階乗を使用すると、すべての二項係数を定数時間で計算できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース DP | O(lw) | O(lw) | 遅すぎる |
 | 反射 + 二項 | O(l + w) | O(l + w) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. コンピューティング`n = l + w - 2`そして`step = l - w + 2`。 値`step`は、パスの連続した反射コピー間の距離です。 
2. 階乗および逆階乗を最大で事前計算します。`n`。 係数は素数であるため、すべての二項係数は次のように取得できます。```
C(n, k) = fact[n] * invfact[k] * invfact[n-k]
```1. フォームのすべての用語を追加します`C(n, l - 1 + k * step)`範囲内にあるもの`[0, n]`。 
2. フォームのすべての項を減算します。`C(n, l + k * step)`範囲内にあるもの`[0, n]`。 
3. 結果のモジュロを正規化します。`104857601`。 

これが機能する理由: すべての無効なパスは、正確に 1 つの反映されたパスとペアになります。 二項係数の最初のファミリーは制限されていないパスをカウントし、2 番目のファミリーは上限または下限の禁止境界を越えるパスを削除します。 交互に合計すると、完全に廊下の内側に留まるパスのみが残ります。 

## Python ソリューション```python
import sys
from array import array

input = sys.stdin.readline

MOD = 104857601

def solve():
    l, w = map(int, input().split())

    n = l + w - 2
    step = l - w + 2

    fact = array('I', [1]) * (n + 1)
    for i in range(1, n + 1):
        fact[i] = (fact[i - 1] * i) % MOD

    invfact = array('I', [1]) * (n + 1)
    invfact[n] = pow(fact[n], MOD - 2, MOD)
    for i in range(n, 0, -1):
        invfact[i - 1] = (invfact[i] * i) % MOD

    def comb(k):
        if k < 0 or k > n:
            return 0
        return fact[n] * invfact[k] % MOD * invfact[n - k] % MOD

    ans = 0

    x = l - 1
    while x >= 0:
        ans += comb(x)
        x -= step

    x = l - 1 + step
    while x <= n:
        ans += comb(x)
        x += step

    x = l
    while x >= 0:
        ans -= comb(x)
        x -= step

    x = l + step
    while x <= n:
        ans -= comb(x)
        x += step

    print(ans % MOD)

if __name__ == "__main__":
    solve()
```階乗配列は以下を使用します`array('I')`通常の Python リストの代わりに、最大値が`n`に近いです`5.5 * 10^6`、Python 整数オブジェクトはより多くのメモリを消費します。 

4 つのループは、正と負の反射項を個別に生成します。 反射されたパスは負の値に対応する可能性があるため、両方向から開始する必要があります。`k`ポジティブなものだけでなく。 

逆モジュラーはフェルマーの小定理を使用します。これは有効です。`104857601`プライムです。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(l + w) | 階乗準備が優勢であり、反射和に含まれる項ははるかに少なくなります。 
| スペース | O(l + w) | 2 つの配列には階乗値と逆階乗値が格納されます。 

最大階乗サイズは約`5.5 million`, そのため、メモリ使用量は制限を大幅に下回ったままになります。 このソリューションにより、元のグリッド内のセルの数への依存が回避されます。
