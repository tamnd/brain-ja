 ## 解決策
 ## 問題の理解

 先輩はいくつかの性質を使って人を判断します。 各品質には重みがあるため、一部の品質を向上させることは、他の品質を向上させることよりも重要です。 先輩自身の要求品質レベルは時間とともに直線的に変化します。 すべての品質について、要件には開始値と変化率があります。 

後輩はすべての個人の資質がゼロから始まります。 唯一の制限は改善の速度です。どの瞬間においても、すべての品質の成長率のベクトルは最大でも長さでなければなりません。`g`。 課題は、後輩が重み付けされた個人スコアを少なくとも先輩の現在の標準以上にする最適な改善戦略を選択できる最も早い時間を見つけることです。 

入力により、品質の数、最大成長速度、すべての品質の重み、および先輩の変化する基準を表す一次関数が得られます。 出力は、成功が可能になる最小時間です。 

この制約により、すべてのテスト ケースにわたる品質の数はわずかであることがわかります。`10^4`、したがって、品質を直線的に通過することが期待されます。 時間をかけてシミュレーションしたり、品質を重視した動的プログラミングを行ったり、高価なチェックを繰り返し実行する検索を行うと、不必要な作業が追加されます。 答えは実数であるため、主な課題は、複雑な計算を通じて数値精度を処理することではなく、式を導き出すことです。 

厄介なケースは、体重、成長率、開始要件がすべてマイナスになる可能性があるという事実から生じます。 すべての値が正であると仮定するソリューションは、何も通知せずに失敗する可能性があります。 

後輩がすでに要件を超えている 1 つの品質を考えてみましょう。```
1
1 10
1
0 -5
```正しい出力は次のとおりです`0`。 初期要件は次のとおりですので、`-5`そして後輩の初期スコアは`0`、改善の必要はありません。 現状を確認せずにすぐに割り算をする不用意な計算式は、マイナスのタイムを生む可能性があります。 

もう 1 つのケースは、負の重みによって品質の向上が有害になる場合です。```
1
1 10
-2
0 5
```重みが負であるため、品質を向上させる必要はありません。 正しい推論では重みベクトルの全長を使用し、後輩が重み付きスコアを最大化する方向に移動できるようにします。 重みを合計するだけでその符号を無視するソリューションでは、誤った成長の可能性が計算されてしまいます。 

## アプローチ

 直接的なアプローチでは、考えられる改善戦略をシミュレートしようとします。 選ばれた時間のために`t`、すべての品質にどれだけの成長予算を投入するかを決定し、加重スコアが Senpai の要件に達しているかどうかを確認することができます。 条件は最終的な品質値にのみ依存するため、これは正しいですが、可能な継続的な改善機能の余地は膨大です。 可能な回数だけチェックするように減らしても、最適化問題を繰り返し解く必要があります。 と`q = 1000`、多くの候補割り当てを試したり、詳細な時間シミュレーションを使用したりすることは、すぐに実行不可能になります。 

重要な観察は、後輩の品質ベクトルの最終的な位置のみが重要であるということです。 ゼロから開始する有効な成長パスは、品質ベクトルを最大距離だけ移動できます。`g * t`時間が経ってから`t`。 重み付きスコアは、最終的な品質ベクトルと重みベクトルの間のドット積です。 制限された長さのベクトルとの可能な最大の内積は、重みの方向に正確に移動することによって取得されます。 

時間経過後の加重スコアの最大値`t`したがって、次のようになります。 

g⋅t⋅∣∣W∣∣

 ここで:

 ∣∣W∣∣= i ∑ W i 2

 Senpai の合計要件も線形です。 

i∑ S i (t)=t i ∑ F i + i ∑ C i

 両辺は時間の単純な一次関数になります。 答えは不等式を 1 つ解くことで直接見つかります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(戦略を無限に探索) | O(q) | 遅すぎる |

 ## アルゴリズムのチュートリアル

 1. 品質の重みを読み取り、重みベクトルの 2 乗の長さを計算します。 重みベクトルの方向によって後輩の成長速度を最適に費やす方法が決まるため、必要なのはその大きさだけです。 
2. Senpai の成長因子をすべて追加します。`sum_f`そしてすべての初期要件を`sum_c`。 これら 2 つの値は、先輩の合計標準を単一の線形関数として表します。 
3. 後輩の単位時間当たりの最大スコア増加量を次のように計算します。 

g i ∑ wi 2

 改善の方向は自由に選択できるため、これは加重品質合計の可能な最大増加率です。 

1. 2 つの一次関数を比較します。 もし`sum_c <= 0`, 後輩は時間ゼロの時点ですでに要件を満たしているので、答えはゼロです。 
2. それ以外の場合は、次のように解決します。 

(g∣∣W∣∣− i ∑ F i )t≥ i ∑ C i

 この問題では答えが存在することが保証されているため、分母は正の値でなければなりません。 残りの要件をこの値で割って、最小時間を取得します。 

なぜ効果があるのか​​: 時間が経つと`t`、考えられるすべての改善戦略では、ユークリッド長が最大で次の品質のベクトルが生成されます。`gt`。 コーシー-シュワルツの不等式により、加重スコアは最大でも 2 つのベクトルの長さの積になります。`gt||W||`。 この上限は、重みベクトルと平行な改善方向を選択することで達成できます。 アルゴリズムは、この可能な最大スコアを正確に使用し、先輩の要件に達する最初の時間を見つけます。そのため、それより早い時間は機能せず、返された時間は達成可能です。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

def solve():
    c = int(input())
    ans = []

    for _ in range(c):
        q, g = map(int, input().split())

        w = list(map(int, input().split()))

        sum_f = 0
        sum_c = 0
        for _ in range(q):
            f, cc = map(int, input().split())
            sum_f += f
            sum_c += cc

        w_len = math.sqrt(sum(x * x for x in w))
        growth = g * w_len

        if sum_c <= 0:
            ans.append("0.00000000000")
        else:
            t = sum_c / (growth - sum_f)
            ans.append("{:.12f}".format(t))

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```コードはまず、すべての品質情報を 3 つの値に分解します。重みベクトルの大きさ、先輩の標準が変化する合計速度、および初期合計標準です。 個々の品質は、その貢献が蓄積された後に保存する必要がなくなりました。 

平方根はテスト ケースごとに 1 回だけ計算されます。 必要な誤差は次のとおりであるため、浮動小数点精度で十分です。`1e-10`、関係する値は小さいです。 この式では、ゼロ時間の場合をチェックした後でのみ除算を使用し、誤った否定的な答えを回避します。 

Python では整数オーバーフローの懸念はありませんが、実装では最終的な式を浮動小数点に変換する前に元の制約の合計を使用することで計算を単純に保ちます。

## テストケース```python
import sys
import io
import math

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)

    def solve():
        import math
        input = sys.stdin.readline
        c = int(input())
        res = []
        for _ in range(c):
            q, g = map(int, input().split())
            w = list(map(int, input().split()))
            sf = sc = 0
            for _ in range(q):
                f, x = map(int, input().split())
                sf += f
                sc += x
            rate = g * math.sqrt(sum(x * x for x in w))
            if sc <= 0:
                res.append("0.00000000000")
            else:
                res.append("{:.12f}".format(sc / (rate - sf)))
        return "\n".join(res)

    out = solve()
    sys.stdin = old_stdin
    return out

4 4
1 1 1 1
1 3
2 3
2 3
1 3
""") == "6.000000000000", "sample 1"

assert run("""1

""") == "0.00000000000", "already satisfied"

assert run("""1

3

""") == "0.00000000000", "negative initial requirement"

assert run("""1

""") == "7.071067811865", "opposite weight directions"

 ## 特殊なケース

 初期要件がすでに満たされている場合、アルゴリズムは線形方程式を使用する前にゼロを返します。 のために：```
1
1 10
1
0 -5
```

`sum_c = -5`なので、改善の必要はありません。 このチェックを行わない除算ベースの実装では、無効な負の時刻が返される可能性があります。 

重みに負の値が含まれる場合、最善の戦略は、すべての品質を向上させないことです。 最適な移動方向は重みベクトルに従います。これは当然、負の重みを持つ品質が低下することを意味します。 例えば：```
1
2 1
1 -1
0 5
0 5
```ウェイトの長さは次のとおりです。 

1 2 +(−1) 2 = 2

 後輩の最大向上率は`sqrt(2)`。 要件は一定です`10`、したがって、答えは次のようになります。 

10/2 =7.071067811865

 アルゴリズムは、重みの合計ではなく二乗重みを使用するため、これを処理します。 

先輩の基準が急激に上がると、最終的な式の分母が小さくなってしまいます。 このソリューションは答えの周りを検索しないため、狭い範囲のバイナリ検索によって引き起こされる精度の低下を回避します。 正確な直線交点を直接計算します。
