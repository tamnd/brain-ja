 ## 解決策
 ## 問題の理解

 タイルの長方形グリッドがあります。 タイル上の文字は、人がその上に立ったときにどのように方向を変えるかを決定します。白は現在の方向を維持し、赤は左に、青は右に曲がります。 開始タイルは でマークされます。`S`、初期方向は自由に選択できます。 

タスクは 1 つの道を見つけることではなく、歩き始める前に最大 1 つの白いタイルを赤または青のタイルに変更できる場合に到達できるすべての壁セグメントを見つけることです。 移動がタイルの片側を通ってグリッドを離れると、壁セグメントに到達します。 

グリッド領域は、すべてのテスト ケースにわたって最大 400,000 です。 これにより、変更された可能性のあるすべてのタイルを試したり、最初からシミュレーションしたりすることが排除されます。 数十万のタイルと 4 つの開始方向が存在する可能性があるため、単一の大きなグリッドでは強引なアプローチはすでに遅すぎます。 タイル数が線形に近い解決策が必要です。 

主な罠は、変更されたタイルが開始タイルになる可能性があること、移動がサイクルに入り壁に到達しない可能性があること、同じタイル上の異なる方向が異なる状態であることです。 

たとえば、1 セルのグリッドの場合は次のようになります。```
1 1
S
```には 4 つの可能な開始方向があり、4 つの壁セグメントすべてに到達可能です。 開始タイルを離れた後の動きだけをチェックするソリューションでは、すべての答えが見逃されてしまいます。 

別のケース:```
1 2
SB
```右を向き始めると、青いタイルが下を向くので、右側から出られなくなります。 青いタイルを現在の動きではなく前の方向に影響を与えるものとして扱うソリューションでは、間違った終了が発生します。 

サイクルも可能です:```
3 3
BBB
BSB
BBB
```通常の動作では、状態によっては境界に到達することはありません。 このような状態は、単一の変更によって脱出するパスが作成されない限り、到達可能な壁がないものとして扱われなければなりません。 

## アプローチ

 直接的なアプローチは、あらゆる可能性をシミュレートすることです。 すべての白いタイルを赤と青に変更してみて、4 つの開始方向をシミュレートします。 選択できるのは 1 つの変更されたタイルだけであるため、これは正解です。 ただし、O(hw) 個の可能なタイルが存在する可能性があり、すべてのシミュレーションは O(hw) 状態を通過できます。 最悪の場合は O((hw)^2) となり、制限をはるかに超えます。 

有益な観察は、運動システムが関数グラフであるということです。 状態はタイルと方向のペアです。 すべての状態には、通常の次の状態が 1 つだけ存在するか、グリッドから抜け出します。 ある状態に到達すると、その最終的な壁セグメントが固定されます。 この結果はメモ化で計算できます。 

許可された 1 つの変更の唯一の効果は、最初から通常のパスをたどっている間に、1 つの白いタイルの 1 つのトランジションを、そのタイルが赤または青の場合に発生するトランジションに置き換えることができることです。 この 1 つの代替遷移を実行した後、パスの残りの部分は再び正常になります。 これにより、問題は、限られた状態セットの正常な結果を収集することになります。 

あらゆる可能な変更が考慮されるため、総当り攻撃は機能しますが、選択肢の数が増えると失敗します。 すべての変更されていないパスが 1 つの関数グラフに属しているという観察により、必要なすべてのパスをまとめて解決できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O((hw)^2) | O(hw) | 遅すぎる |
 | 最適 | O(hw) | O(hw) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 暗黙的な関数グラフを構築します。 状態はタイルと 4 つの方向の 1 つです。 次の状態はグリッドから一定時間で計算できるため、すべてのエッジを明示的に保存しません。 
2. 開始タイルから 4 つのウォークを開始します (可能な初期方向ごとに 1 つずつ)。 普通に歩きながら、訪問したすべての州を収集します。 これらはまさに、1 つの変更を適用できる状態です。 
3. 白いタイルの上にあるすべての収集された状態について、そのタイルを赤と青に変更してみます。 これら 2 つの選択肢の目的地の状態を計算し、各目的地から通常の最終壁セグメントを求めます。 
4. 4 つの元の開始状態の通常の結果も計算します。 成功したすべての壁セグメントをセットに挿入します。 
5. 正常な結果のクエリに答えるには、反復メモ化を使用して関数グラフに従います。 パスが既知の状態に達した場合は、その答えを再利用します。 サイクルが検出された場合、そのサイクル内のすべての状態には壁セグメントがありません。 

なぜ効果があるのか:

 すべての有効なソリューション パスは、通常のプレフィックス、最大 1 つの変更された白いタイル、および通常のサフィックスで構成されます。 通常のプレフィックスは 4 つの元のウォークの 1 つである必要があるため、考えられるすべての変更ポイントが収集されます。 アルゴリズムはそのような点ごとに両方の可能な変更を試み、メモ化された関数グラフは残りのサフィックスの正確な結果を返します。 考えられるすべての有効なパスが表現されるため、到達可能な壁セグメントが見逃されることはありません。 

## Python ソリューション```python
import sys
from array import array

input = sys.stdin.readline

def solve_case():
    h, w = map(int, input().split())
    grid = [input().strip() for _ in range(h)]

    n = h * w
    start = 0
    for i in range(h):
        j = grid[i].find('S')
        if j != -1:
            start = i * w + j
            break

    # directions: 0 up, 1 right, 2 down, 3 left
    dr = (-1, 0, 1, 0)
    dc = (0, 1, 0, -1)

    def next_state(s, turn=None):
        pos, d = divmod(s, 4)
        r, c = divmod(pos, w)
        ch = grid[r][c]
        if ch == 'R' or turn == 'R':
            d = (d + 3) & 3
        elif ch == 'B' or turn == 'B':
            d = (d + 1) & 3
        nr, nc = r + dr[d], c + dc[d]
        if nr < 0:
            return -(1 + w + h + w + c)
        if nr >= h:
            return -(1 + w + h + w + w + c)
        if nc < 0:
            return -(1 + c + 2 * w + h)
        if nc >= w:
            return -(1 + c + 2 * w + h + w)
        return (nr * w + nc) * 4 + d

    # Negative values are exits. Use positive shifted values for memoized exits.
    memo = array('i', [-2]) * (4 * n)
    mark = array('i', [0]) * (4 * n)
    token = 0

    def get_exit(s):
        nonlocal token
        if memo[s] != -2:
            return memo[s]
        token += 1
        cur = s
        path = []
        while True:
            if cur < 0:
                ans = cur
                break
            if memo[cur] != -2:
                ans = memo[cur]
                break
            if mark[cur] == token:
                ans = -1
                break
            mark[cur] = token
            path.append(cur)
            cur = next_state(cur)

        for x in reversed(path):
            memo[x] = ans
        return ans

    visited = array('i', [0]) * (4 * n)
    states = []
    walk_id = 1
    for d in range(4):
        cur = start * 4 + d
        while cur >= 0 and visited[cur] != walk_id:
            visited[cur] = walk_id
            states.append(cur)
            cur = next_state(cur)
        walk_id += 1

    ans = set()

    for d in range(4):
        e = get_exit(start * 4 + d)
        if e < 0:
            ans.add(-e - 1)

    for s in states:
        pos = s // 4
        r, c = divmod(pos, w)
        if grid[r][c] == 'W' or grid[r][c] == 'S':
            for t in ('R', 'B'):
                e = next_state(s, t)
                if e < 0:
                    ans.add(-e - 1)
                else:
                    e = get_exit(e)
                    if e < 0:
                        ans.add(-e - 1)

    out = []
    conv = []
    for x in ans:
        # encode sides in increasing ASCII order: B, L, R, T
        if x < w:
            conv.append(('T', x + 1))
        elif x < 2 * w:
            conv.append(('B', x - w + 1))
        elif x < 2 * w + h:
            conv.append(('L', x - 2 * w + 1))
        else:
            conv.append(('R', x - 2 * w - h + 1))

    conv.sort()
    out.append(str(len(conv)))
    for a, b in conv:
        out.append(f"{a} {b}")
    return "\n".join(out)

def main():
    t = int(input())
    ans = []
    for _ in range(t):
        ans.append(solve_case())
    print("\n".join(ans))

main()
```実装ではグラフが暗黙的に保持されます。 機能`next_state`通常の動きと 2 つの可能な変更の両方を処理します。 負の戻り値は、壁セグメントを通ってグリッドから離れることを表します。 

メモ配列には、通常のパスの最終的な壁の結果が格納されます。 反復トラバーサルは、Python の再帰制限を回避し、訪問された大規模な配列を繰り返しクリアする代わりに、タイムスタンプ配列を使用してサイクルを検出します。 

リスト`states`オプションの変更の前に現れる可能性のあるすべての状態が含まれます。 変更は元のウォーク中に行われる必要があるため、これらの状態のみが重要です。 修正後は、`get_exit`残りの通常の動きを処理します。 

最後の変換は出力フォーマットのみを目的としています。 内部的には、出口は整数として保存され、その後、上、下、左、右のセグメントに変換されます。

 ## 特殊なケース

 開始状態自体が収集された状態に含まれるため、単一セルの場合が処理されます。 変化`S`も考慮されます。`S`白いタイルとして動作します。 

サイクルはタイムスタンプベースのトラバーサルによって処理されます。 同じ検索中に状態が繰り返される場合、そのループ内のすべての状態は、到達可能な壁がないことを意味する値を受け取ります。 変更された遷移は個別にクエリされるため、その後の変更でもエスケープできます。 

境界にあるタイルは、次の移動がグリッドから離れると、直接壁セグメントに変換されます。 離れる方向によって答えが上下左右のいずれに属するかが決まり、一過性の間違いを防ぎます。 

要求されたすべてのセクションを完全に展開したコンテスト編集スタイルのバージョンが必要な場合は、より完全な証明、より詳細なトレース、またはより厳密なアサートベースのローカル テスターを使用して編集を拡張できます。
