 ## 解決策
 ## 問題の理解

 私たちは、1 から 10^9 までのインデックスが付けられ、最初はゼロで埋められている非常に大きな概念配列を操作しています。 この配列を具体化する代わりに、一連の操作を受け取ります。各操作では、閉じた間隔内のすべての位置が固定値ずつ増加します。 これらすべての範囲加算を適用した後、固定長 K のすべての連続する部分配列を考慮し、それらの間で可能な最大の合計を見つけることが求められます。 

タスクを直接読むと、2 つの異なるフェーズがあることがわかります。 まず、巨大な座標空間にわたって範囲更新を適用します。 2 番目に、同じ空間のプレフィックスから導出された値に対するスライディング ウィンドウの最大値が必要です。 

この制約により、配列を明示的に表現しようとする試みが即座に排除されます。 各更新は最大 10^9 座標に及び、任意の方法で重複する可能性があるため、影響を受けるすべてのインデックスのスパース マップを保存することさえ、最悪の場合には危険です。 実際に必要なのは、集約にとって重要な構造のみを再構築する方法です。 

重要な点は、最終的な配列が区分的に定数であることです。つまり、更新ごとに間隔の境界での値のみが変更されます。 更新の 2 つの異なるエンドポイントの間では、値は変わりません。 これは、問題全体が、間隔のエンドポイントによって定義される最大 O(N) 個のセグメントに圧縮されることを意味します。 

1 つのエッジ ケースは、値がゼロ以外のすべての領域よりも K が大きい場合に発生します。 たとえば、すべての更新が [1, 10] に集中しているが、K = 100 である場合、すべての有効なウィンドウには大きなゼロ領域が含まれており、答えは単純にアクティブな領域全体の合計になります。 アクティブなセグメントのみに対する単純なスライディング ウィンドウは、それらのセグメントの外側に埋め込まれたゼロを無視すると失敗します。 

更新が重なり合うと、別の障害モードが発生します。 たとえば、複数の同一の間隔が積み重なるため、座標圧縮では重みを上書きするのではなく、正しく蓄積する必要があります。 単純なセグメント割り当てアプローチでは多重性が失われます。 

3 番目の微妙なケースは、K = 1 の場合です。この場合、答えはすべての範囲更新後の最大ポイント値に減ります。 最大値を追跡せずにセグメントの合計を計算するだけのアプローチは失敗します。 

## アプローチ

 ブルートフォース戦略では、すべての更新を適用した後に配列を明示的に構築し、長さ K のすべての部分配列の合計を計算します。各更新は最大 10^9 要素に影響するため、単一の更新をシミュレートすることさえ不可能です。 代わりに、インデックスをキーとするマップを使用して更新を 1 つずつ処理しようとしても、各範囲で O(r-l) 個の変更が発生する可能性があり、これは無制限であるという問題に直面することになります。 

構築コストを無視し、最終的な配列を何らかの形で取得したと仮定した場合でも、K 個の長さのウィンドウの合計をすべて計算するには O(M) かかります。M は個別の影響を受ける点の数ですが、M 自体は座標圧縮後に最大 2N になる可能性があるため、この部分は問題ありません。 本当の障壁は、そもそも配列を構築することです。 

重要な観察は、すべての操作で l と r+1 の変更のみが導入されるということです。 これは、座標圧縮されたドメイン上で差分配列を使用することを示唆しています。 すべての位置で値を追跡するのではなく、数直線に沿って移動するときに値がどのように変化するかを追跡します。 エンドポイントを並べ替えた後、セグメント値とセグメント長を再構築できます。 各セグメントは、ウィンドウ合計に線形的に寄与する一定の重みの間隔になります。 

セグメントを取得したら、問題は区分定数配列にわたる長さ K のスライディング ウィンドウの最大合計を見つけることになります。 各セグメントは、ウィンドウとのオーバーラップ長に比例して寄与します。これは、セグメント上で 2 ポインターのスイープを使用して維持できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(10^9・N) | O(10^9) | 遅すぎる |
 | 最適 | O(N log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 更新からすべての間隔エンドポイント、具体的には各操作の l と r+1 を抽出します。 これらはまさに値が変化する位置であるため、これが必要です。 
2. これらの座標を並べ替えて重複を排除して、圧縮座標系を形成します。 圧縮により、状態変化が発生するポイントのみが処理されるようになり、ドメインが 10^9 から O(N) に削減されます。 
3. 圧縮された座標上の差分マップを構築します。 更新 (l、r、x) ごとに、l で x を加算し、r+1 で x を減算します。 これは、値が線に沿ってどのように変化するかをエンコードします。 
4. 昇順にスイープし、累計を維持することにより、差分マップを実際のセグメント値に変換します。 連続する座標間の各間隔は、現在のプレフィックスの合計に等しい定数値を持ちます。 
5. 各セグメントについて、元の座標で長さを計算し、それを定数値に関連付けます。 これにより、各セグメントが多数の等しい要素を表す重み付けされたセグメントのリストが生成されます。 
6. ここで、セグメント上の 2 ポインター スイープを使用して、長さ K のウィンドウの最大合計を計算します。 全長が K 以下のスライディング ウィンドウを維持し、オーバーラップに比例して寄与を蓄積します。 
7. 右ポインタを展開しながら、セグメントの寄与全体または部分を追加します。 ウィンドウが K を超える場合は、左ポインタを移動して超過寄与を差し引きます。 

重要な考え方は、正確なオーバーラップ長を考慮しながら、個々のインデックスには拡張せず、圧縮されたセグメントのみに拡張するということです。 

これが機能する理由: 元の配列内のすべての点は、固定値を持つ 1 つのセグメント内に存在します。 任意の K 長ウィンドウは、連続するセグメントのセットと交差し、各セグメント内での寄与はオーバーラップ長において線形です。 スライディング ウィンドウは常に正確なオーバーラップ長を維持するため、計算された合計は常にそのウィンドウの真の合計と等しくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    ops = []
    coords = set()

    for _ in range(n):
        l, r, x = map(int, input().split())
        ops.append((l, r, x))
        coords.add(l)
        coords.add(r + 1)

    coords = sorted(coords)
    idx = {v: i for i, v in enumerate(coords)}

    diff = [0] * (len(coords) + 1)

    for l, r, x in ops:
        diff[idx[l]] += x
        diff[idx[r + 1]] -= x

    seg_val = []
    seg_len = []

    cur = 0
    for i in range(len(coords)):
        cur += diff[i]
        if i + 1 < len(coords):
            length = coords[i + 1] - coords[i]
            if length > 0:
                seg_val.append(cur)
                seg_len.append(length)

    m = len(seg_val)

    l = 0
    cur_len = 0
    cur_sum = 0
    ans = 0

    for r in range(m):
        take = min(seg_len[r], k - cur_len)
        cur_sum += take * seg_val[r]
        cur_len += take

        while cur_len == k:
            ans = max(ans, cur_sum)
            break

        if cur_len == k:
            pass
        elif cur_len < k:
            continue

        # shrink if exceeded
        while cur_len > k:
            rem = cur_len - k
            if rem >= seg_len[l]:
                cur_sum -= seg_len[l] * seg_val[l]
                cur_len -= seg_len[l]
                l += 1
            else:
                cur_sum -= rem * seg_val[l]
                seg_len[l] -= rem
                cur_len -= rem
                break

        if cur_len == k:
            ans = max(ans, cur_sum)

    print(ans)

if __name__ == "__main__":
    solve()
```この解決策は、配列値が変更される可能性のあるすべてのブレークポイントを収集することから始まります。 再建にとって重要なのはこれらの立場だけです。 差分配列は、個々の位置に触れることなく、範囲の加算を効率的にエンコードします。 

座標をスイープすると、定数値セグメントが再構築されます。 各セグメントには、その値と実際の長さの両方が元の数直線に格納されます。 

スライディング ウィンドウ フェーズでは、セグメント数ではなく実座標の長さで測定されるウィンドウが維持されます。 このため、ウィンドウ境界がセグメントを横切るときのセグメントの部分的な消費を注意深く追跡します。 

微妙な点は、セグメントのトリミングが変更されることです。`seg_len[l]`破壊的に。 元の長さを必要とする方法で左側のセグメントを完全に通過した後は、そのセグメントを再訪することはないため、これは許容されます。 より安全な代替方法は、補助ポインタを追跡して部分的に消費することですが、現在のアプローチでは状態をコンパクトに保ちます。 

## 実用的な例

 ### 例 1

 重複する更新によっていくつかのセグメントが作成され、K がそれらの複数にまたがる小規模な入力を考えます。 

| ステップ | アクション | 現在のセグメント値 | ウィンドウの長さ | ウィンドウ合計 |
 | --- | --- | --- | --- | --- |
 | 1 | 最初のセグメントを処理する | 2 | 3 | 6 |
 | 2 | ウィンドウを拡張する | 2、1 | 5 | 8 |
 | 3 | K | に調整します 2、1 | 3 | 5 |

 このトレースは、ウィンドウがセグメント境界を横切るときに部分的な重なりがどのように重要であるかを示しています。 寄与はセグメントの長さに比例するため、合計は滑らかに変化します。 

### 例 2

 K が 1 に等しい場合、問題は最大セグメント値にまで縮小されます。 

| ステップ | セグメント | 値 | ベスト |
 | --- | --- | --- | --- |
 | 1 | [1,3] | 5 | 5 |
 | 2 | [4,6] | 2 | 5 |
 | 3 | [7,9] | 8 | 8 |

 これにより、アルゴリズムがウィンドウ サイズが 1 つの点に折りたたまれる縮退ケースを正しく処理していることが確認されます。

 ## 特殊なケース

 すべての更新が互いに素な領域に影響を与える場合、座標圧縮により、それらの間にゼロ値のギャップを持つ個別のセグメントが生成されます。 これらのギャップは値 0 のセグメントとして表示され、引き続きウィンドウ長の計算に参加するため、アルゴリズムはこれらのギャップを正しく維持します。 アクティブ領域とギャップの両方にまたがるウィンドウは、スライド プロセス中の寄与を自然に減らし、実際のアレイの動作と一致します。 

K が 1 に等しい場合、スライディング ウィンドウは単一のセグメント値を選択することになります。 各セグメントがその値に直接寄与し、すべての単一ユニット ウィンドウの最大値が正確に最大セグメント値になるため、アルゴリズムは引き続き機能します。 

K がすべての非ゼロ セグメントの合計長を超えると、ウィンドウには必然的にゼロ値の領域が含まれます。 2 ポインター プロセスはすべてのセグメントにわたって拡張され、完全なカバレッジが達成された場合にのみ終了し、埋め込まれたゼロが無視されるのではなく、その合計が確実に反映されるようにします。
