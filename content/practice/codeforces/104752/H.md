 ## 解決策
 ## 問題の理解

 いくつかの独立したシナリオでプレイされるターンベースのゲームが与えられます。 各シナリオはバルーン バンドルのコレクションで構成されており、各バンドルにはいくつかのバルーンが含まれています。 プレイヤーのターンでは、バンドルを 1 つだけ選択し、いずれかを削除します$A$、$B$、 または$C$選択した量がそのバンドルのサイズを超えない限り、そこからバルーンを作成します。 バンドルの移動サイズが 3 つすべてよりも小さい場合は、バンドルからの実行可能な削除のみが許可されます。 自分のターンに有効な動きを行えなかったプレイヤーは負けます。 

同じ移動ルールを共有する以外のバンドル間の相互作用はないため、各バンドルは移動セットを備えた減算ゲームの独立した山のように動作します。$\{A, B, C\}$。 ターンは、1 つの山を選択し、1 つの有効な減算を適用することで構成されます。 

各クエリは、そのゲーム ポジションの最初のプレーヤーが勝利戦略を持っているかどうかを尋ね、両側からの最適なプレイを仮定して、どの指名プレーヤーが最終的に勝つかを出力する必要があります。 

制約により、事前計算が強く推進されます。 まであります$10^5$各クエリには最大で 6 つのクエリを含めることができます。$10^3$バンドル、最大バンドル サイズ$10^6$。 クエリごとにゲームツリーを直接検索することは不可能です。なぜなら、単一の山であってもサイズがあるからです。$10^6$最大 3 の分岐係数は指数関数的な状態空間を生成します。 クエリごとに再計算されるバンドルごとの動的プログラミングでさえ、最悪の場合には遅すぎます。 

微妙なエッジ ケースは、「バンドルを選択して A/B/C バルーンを削除する」を正しく解釈することから生じます。 この手は「合計値から A/B/C を選択する」というものではなく、ちょうど 1 つの山に対して独立して適用されます。 これをグローバルな減算ゲームと誤解すると、パイル サイズの誤った集計につながります。 

もう 1 つの重要なエッジ ケースは、同一のバンドルは特別なものではないということです。 2 つの異なるクエリが同じパイル値を共有する場合がありますが、移動セット自体の構造を利用しない限り、クエリ間で再利用することはできません。 

## アプローチ

 ブルートフォースアプローチは、各クエリを完全に公平なゲーム状態として扱います。$K$をヒープし、位置のグランディ値の計算を試みます。 単一の状態からの移動は、1 つのヒープを選択し、それを次のように削減することで構成されます。$A$、$B$、 または$C$したがって、状態グラフは最大で接続されます。$3K$新しい状態は、それぞれ 1 つの座標で異なります。 これにより、中程度の場合でも状態空間が巨大になります。$K$、各ヒープの範囲が最大であるため、$10^6$、個別の構成の数は指数関数的になります。$K$。 

各ヒープの DP をその値まで個別に単純化して計算したとしても、クエリごとにそれを行うには、$O(K \cdot 10^6)$最悪の場合、限界をはるかに超えたテストごとに。 

重要な観察は、ゲームが同一の減算ゲームの選言的合計であるということです。 各バンドルは Nim のような構造のヒープです。 Sprague-Grundy の定理は、位置全体が独立したヒープの Grundy 値の XOR になることを示しています。 したがって、タスクはコンピューティングになります$g(x)$、サイズの単一ヒープのグランディ値$x$、ここで移動は減算されます$A$、$B$、 または$C$。 

以来$A, B, C \le 100$、それぞれの遷移$x$最大 3 つの小さな州にのみ依存します。 これにより、次のような単純な DP が実現可能になります。$10^6$1 回だけ、すべてのクエリで共有されます。 

クエリごとの最終的な答えは、次の単なる XOR です。$g(K_i)$すべてのバンドルにわたって。 XOR がゼロ以外の場合、開始プレイヤーが勝ちます。 そうでなければ彼らは負けます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース ゲーム ツリー | 指数 | 指数 | 遅すぎる |
 | DP + スプレイグ グランディ |$O(M + \sum K)$事前計算後 |$O(M)$| 承認済み |

 ここ$M = 10^6$、最大ヒープ サイズ。 

## アルゴリズムのチュートリアル

 1. DP 配列を事前計算する`grundy[x]`みんなのために$x$0 からクエリで見られる最大のパイル サイズまで。 これは、すべてのパイル状態がより小さい値にのみ依存するため必要です。 
2.セット`grundy[0] = 0`, 風船のないパイルには正当な動きがなく、定義上負けとなるためです。 
3. 各値について$x$、減算して到達可能な状態のセットを計算します。$A$、$B$、 または$C$、結果が負でない限り。 
4. 到達可能なすべての状態の Grundy 値を 1 つのセットに収集します。 
5. コンピューティング`grundy[x]`mex として、到達可能なセットにない最小の非負の整数。 これは、公平なゲームにおけるグランディ数の定義を捉えています。 
6. クエリごとに、アキュムレータを初期化します。`xor_sum = 0`。 
7. バンドルサイズごとに$k_i$、XOR`xor_sum`と`grundy[k_i]`。 これにより、独立したサブゲームが 1 つのポジションに集約されます。 
8. もし`xor_sum`がゼロ以外の場合、開始プレイヤーが勝ち手を持っています。それ以外の場合、ポジションは負けです。 

これが機能する理由は、それぞれの動きが 1 つのヒープにのみ影響するため、ゲームは値が XOR で結合される独立したサブゲームに分解されるためです。 DP は各ヒープ値がそのヒープ内のみで最適なプレイをエンコードすることを保証し、XOR は最適な戦略選択の下でヒープ間の相互作用をキャプチャします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    first = input().strip()
    A, B, C, Q = map(int, input().split())

    moves = (A, B, C)
    max_val = 10**6

    grundy = [0] * (max_val + 1)

    for x in range(1, max_val + 1):
        reachable = set()
        for m in moves:
            if x >= m:
                reachable.add(grundy[x - m])
        g = 0
        while g in reachable:
            g += 1
        grundy[x] = g

    def winner(xor_sum):
        if xor_sum != 0:
            return "Happy Bruce" if first == "Bruce" else "Sad Arthur"
        else:
            return "Sad Arthur" if first == "Bruce" else "Happy Bruce"

    out = []
    for _ in range(Q):
        K = int(input())
        arr = list(map(int, input().split()))
        x = 0
        for v in arr:
            x ^= grundy[v]
        out.append(winner(x))

    print("\n".join(out))

if __name__ == "__main__":
    main()
```DP テーブルは、各状態が最大 3 つの以前のエントリのみに依存するボトムアップ反復を使用して一度構築され、値ごとに遷移を一定時間に保ちます。 ここでは、到達可能なセットのサイズが最大 3 であるため、mex の計算は簡単です。そのため、少数の候補のみをテストします。 

その後、各クエリは事前計算された値に対する XOR 累算に還元され、クエリ処理がバンドルの数において線形になります。 

勝利する XOR ポジションの意味は観点によって異なるため、最終的なプレイヤー名のロジックは誰がゲームを開始するかを説明します。 ゼロ以外の XOR は、ゲーム開始時の現在のプレーヤーが勝利戦略を持っていることを意味します。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべての移動サイズがパイル サイズを超える場合です。 たとえば、次の場合$A=7, B=8, C=9$パイルにはサイズがあります$5$の場合、移動は不可能であり、Grundy 値は 0 になります。到達可能なセットが空で mex が 0 であるため、DP は 0 を正しく割り当てます。 

もう 1 つのケースは、複数の移動が同じ結果の状態につながる場合です。 もし$A=2, B=4, C=6$そして$x=6$、 両方$6-2=4$そして$6-4=2$は有効ですが、$6-6=0$。 到達可能なセットは次のようになります。$\{g(4), g(2), g(0)\}$、mex はこの重複排除されたセットに対して計算されるため、値を繰り返しても結果が歪むことはありません。 

3 番目のケースは、XOR がパイル全体でキャンセルされる場合です。 たとえば、2 つの山が同一のグランディ値を持つ場合、それらの XOR はゼロとなり、負けのペアを形成することを意味します。 XOR は特別なケースなしですべてのパイルに均一に適用されるため、アルゴリズムはこれを自然に処理します。
