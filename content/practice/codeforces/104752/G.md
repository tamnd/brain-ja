 ## 解決策
 ## 問題の理解

 一連のコイン スタックが与えられ、各スタックには初期のコイン数が含まれます。 2 人のプレイヤーが交互にターンを行い、各ターンでプレイヤーは任意のスタックを選択し、そのスタックに現在あるものを超えない正の数のコインを取り除くことができます。 これは最適なプレイの下では無限に続き、最終的にゲームは最終構成に達します。 

結果にとって重要なのは、スタックの最終構成だけです。 最終的な配列が降順以外でソートされれば、Ana が勝ちます。 昇順でない順に並べ替えると、Ernesto が勝ちます。 両方のプロパティが同時に成立した場合、両方のプレイヤーが勝者と宣言されます。 

この問題は 2 人プレイの最適なゲームとして構成されていますが、出力は中間スコアや手数ではなく、最終的な到達可能な状態にのみ依存します。 これは、ゲームのダイナミクスが実際にどの最終的な配置が達成されるかに影響を与えないことを示す強力なヒントです。 

制約$N \le 10^6$これは、配列の 1 回の線形スキャンしかできないことを意味します。 ゲームをシミュレートしたり、動きごとの最適なプレイについて推論したりするソリューションは、直ちに実行不可能になります。 平$O(N \log N)$境界線にありますが、ここでは不要です。$A_i \le 100$簡単なチェックのみが可能です。 

最も危険なエッジケースは、「ゲーム」が何を変えるのかを誤解することです。 単純な解釈では、リダクションをシミュレートしたり、最適なプレイをモデル化しようとすることになりますが、重要な問題は、許可された操作では、関心のある最終条件に対して有意義な方法でスタック間の相対的な順序付け制約が変更されることは決してないということです。 

以下の代表的なケースを考えてみましょう。 

入力が次の場合:```
5
1 2 10 4 5
```配列は非減少でも非増加でもないため、答えは「両方」ではありません。 正しい出力は「Ana」です。 

入力が次の場合:```
5
5 4 3 2 1
```すでに増加していないため、エルネストが勝ちます。 

入力が次の場合:```
5
5 5 5 5 5
```両方の単調性を同時に満たすので、両方が勝ちます。 

単純なアプローチでは、コインの除去と交互のターンをシミュレートしようとする可能性がありますが、すべてのスタックはいつでも独立して、最終的には 0 とその初期値の間の任意の値に減らすことができるため、ゲーム構造には、初期シーケンスが単調であるかどうかに影響を与える制約が導入されません。 

## アプローチ

 強引な解釈では、ゲームをシミュレートしようとします。 各状態をスタックの現在のベクトルとしてモデル化し、すべての可能な動きを再帰的に探索します。つまり、スタックを選択し、そこから任意の値を減算します。 各スタックはさまざまな方法で削減でき、分岐係数が膨大になるため、これはすぐに実行不可能になります。 単一ユニットの除去に制限したとしても、せいぜい$\sum A_i$動きますが、それはまだ先です$10^8$最悪の場合の操作が可能になり、状態空間はスタックの数で指数関数的に増加します。 

ただし、このシミュレーション全体は不要です。 重要な観察は、評価する唯一のプロパティは、最終構成がソートされているかどうかであるということです。 すべてのスタックは独立して次の値に減らすことができるため、$0$初期値に対する唯一の一貫した解釈は、最終的な結果はターン順序には依存せず、初期シーケンスが任意の独立した削減を生き残る単調性制約をすでに満たしているかどうかにのみ依存するということです。 

スタック間でコインを転送できる操作はないため、最終的な配列の相対的な順序制約は初期構成によってすでに完全に決定されています。 ゲームでは、制御された方法で新しい反転を導入したり、既存の反転を修正したりすることはできません。 位置間の結合は行わずに大きさを減少させるだけです。 

したがって、問題全体は、初期配列が減少していないか、増加していないか、あるいはその両方であるかをチェックすることに集約されます。

 ## アルゴリズムのチュートリアル

 ### 最適な戦略

 1. スタック サイズの配列を読み取ります。 
2. 左から右にスキャンし、各要素が少なくとも前の要素であることを確認して、シーケンスが非減少であるかどうかを確認します。 
3. 左から右にスキャンし、各要素が最大でも前の要素であることを確認して、シーケンスが非増加であるかどうかを確認します。 
4. 両方の条件が真の場合、「両方」を出力します。 
5. 非減少のみが成立する場合は、「Ana」を出力します。 
6. それ以外の場合は、「Ernesto」を出力します。 

2 つの単調性条件は独立しており、追跡比較を行わないと 1 回のパスでは両方を確実に決定できないため、各スキャンが必要になります。 

### なぜ効果があるのか

 最終的な結果は、最初の順序がすでに単調であるかどうかによってのみ決まります。 どの手もポジション間の相対的な順序の制約を変更することはできないため、すでに非減少または非増加となっているシーケンスは、ゲームで許可されている減少の下では引き続き有効です。 逆に、初期配列が両方の単調性に違反する場合、独立した減少のシーケンスは、分類結果を変更する方法でいずれかのグローバル順序条件を同時に強制することはできません。 したがって、分類は完全に初期配列のチェックに帰着します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    nondec = True
    noninc = True

    for i in range(1, n):
        if a[i] < a[i - 1]:
            nondec = False
        if a[i] > a[i - 1]:
            noninc = False

    if nondec and noninc:
        print("Both")
    elif nondec:
        print("Ana")
    else:
        print("Ernesto")

if __name__ == "__main__":
    solve()
```この実装は 2 つのブール フラグを維持する単一のリニア スキャンに依存しています。 最初のフラグは、非減少順序に違反する降下が発生するかどうかを追跡します。 2 つ目は、上昇が発生したかどうかを追跡しますが、これは非増加順序に違反します。 最終的な決定は 1 回のパス後に行われ、最適なパフォーマンスが保証されます。$N$100万まで。 

よくある落とし穴は、完全なソートを使用してソートを再計算することです。これにより、不必要なソートが発生します。$O(N \log N)$オーバーヘッド。 もう 1 つは、ゲームの動きをシミュレートしようとするものですが、これは最終的な分類とは無関係です。

## 特殊なケース

 単一要素配列の場合、隣接する違反がないため、シーケンスは非減少かつ非増加になります。 アルゴリズムは両方のフラグを正しく true に保ち、「両方」を出力します。 

次のような定数配列の場合`5 5 5 5 5`、すべての比較は等しいため、違反の増加も減少も発生しません。 両方のフラグが全体を通して true のままとなり、「両方」が生成されます。 

厳密に単調な配列の場合、フラグの 1 つだけが残ります。 スキャンは純粋に隣接する比較に基づいて方向性を正確に識別し、絶対値やゲームの解釈に依存しないことを保証します。
