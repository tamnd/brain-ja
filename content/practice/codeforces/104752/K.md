 ## 解決策
 ## 問題の理解

 グラフのようなレイアウトが与えられ、位置間の接続に沿って移動が許可されますが、一部の位置はブロックされているとマークされます。 通常の位置を通過する移動は常に許可されますが、ブロックされた位置に足を踏み入れると、限られた予算の 1 ユニットが消費されます。$K$。 タスクは、パスに沿って使用されるブロックされた位置の許容数を決して超えないようにしながら、指定された開始ノードからターゲット ノードまで移動するために必要な最小移動数を見つけることです。 

モデリングの観点から見ると、各状態はグラフ内の単なる位置ではなく、すでに通過したブロックされたノードの数でもあります。 これにより、問題は直ちに拡張された状態空間上の最短経路探索に変わります。 

制約 (通常は最大$10^5$このタイプの問題におけるノードとエッジ) は、ブロックされたステップの考えられる使用法ごとに最短パスを個別に再計算するアプローチを除外します。 近いものは何でも$O(K \cdot (n + m))$単純に繰り返すと、両方の場合に TLE になります$K$そしてグラフサイズも大きいです。 これにより、予算を州自体に統合する単一の横断方向に私たちは推進されます。 

実際には、いくつかの特殊なケースが重要になります。 

最初の微妙なケースは、開始ノード自体がブロックされている場合です。 たとえば、スタートがブロックされている場合、$K = 0$の場合、たとえ構造的にパスが存在しても、移動は不可能です。 開始位置でブロックされたコストを無視する単純な BFS は、到達可能なターゲットを誤って報告します。 

2 番目のケースは、複数のパスが異なる残りバジェットで同じノードに到達する場合です。 たとえば、1 つのパスがノードに到達する可能性があります。$v$手順は少ないですが、すでにブロックされているノードが多く使用されているものと、時間は長くなりますが、より多くの予算が確保されているものがあります。 ノードのみに対する単純な訪問配列では、有効な最適な状態が破棄されます。 

3 番目のケースは、グラフ内にサイクルが存在する場合です。 予算の次元を追跡しないと、BFS はノードを無期限に再検討したり、有効な改善を切り捨てたりする可能性があります。 

## アプローチ

 簡単な試みは、すべてのノードを平等に扱いながら開始ノードから BFS を実行し、ターゲットに到達するまで単純にステップ数をカウントすることです。 BFS は重み付けされていないグラフ内の最短パスを保証するため、これはブロックされたノードがない場合にのみ機能します。 ブロックされたノードによって制約が課されると、この方法は正しくなくなります。たとえステップが短くても、一部のパスが無効であるという事実が無視されます。 

もう少し慎重な総当たりアプローチは、各パスに沿って使用されているブロックされたノードの数を追跡することです。 これは、完全なパス状態を BFS または DFS に保存し、次の値を超えるパスを拒否することで実現できます。$K$。 それは正しいのですが、これは州の爆発につながります。 各ノードには最大でアクセスできます。$K+1$「使用される予算」が異なるため、検索スペースは次のようになります。$O(nK)$。 密なグラフや大きなグリッドでは、各状態がすべての隣接状態を探索するため、これは遅くなりすぎます。 

重要な観察は、これは依然として最短経路の問題であり、単に高次元の状態空間内でのみ行われるということです。 「ノードにいる」と考えるのではなく、$v$」、私たちは「ノードにいる」ことを考えます$v$使用した後$c$ブロックされたステップ。」 各遷移は次のいずれかを維持します$c$変更されないか、1 ずつ増加します。 これにより、問題が次の拡張グラフ上の標準的な最短経路に変換されます。$n \cdot (K+1)$州。 すべてのエッジのステップのコストは等しいため、この拡張された状態空間上の BFS が最適です。 

これにより、再計算やバックトラッキングの必要がなくなります。各状態は、正しい BFS 順序で最大 1 回訪問されます。

 ## アルゴリズムのチュートリアル

 拡張状態に対して BFS を使用して問題を解決します。 

1. 各状態をペアとして表します$(v, c)$、 どこ$v$は現在のノードであり、$c$これまでに使用されたブロックされたノードの数です。 これは、異なるノードで同じノードに到達するために必要です。$c$価値観はさまざまな将来の可能性につながる可能性があります。 
2. 距離構造を初期化します`dist[v][c]`無限大とセット付き`dist[start][initial_cost] = 0`、 どこ`initial_cost`開始ノードがブロックされている場合は 1、そうでない場合は 0 です。これにより、トラバーサルが開始される前に開始条件が正しく考慮されることが保証されます。 
3. 初期状態をキューにプッシュします。 
4. ステートを繰り返しポップします$(v, c)$行列から。 
5. 隣人ごとに$u$の$v$、新しいブロックされた使用量を計算します。 

- もし$u$ブロックされている場合`nc = c + 1`- さもないと、`nc = c`6. もし`nc > K`、制約に違反するため、この遷移を破棄します。 
7. 到達した場合$(u, nc)$以前に記録された距離よりも短い距離が得られる場合、それを更新してキューにプッシュします。 
8. BFS が終了したら、すべての状態間の最小距離として答えを計算します。$(target, c)$のために$c \in [0, K]$。 

これが機能する理由は、BFS が重み付けされていないグラフ内の最短パスを保証し、展開された状態グラフがすべての制約を正しくエンコードしているためです。 元のグラフ内の有効なパスは、展開されたグラフ内の 1 つのパスに正確に対応し、その逆も同様です。 より悪いコストまたは同等のコストを持つ状態を再検討することは決してないため、各状態は最適な順序で処理されます。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    blocked = list(map(int, input().split()))  # 0/1 per node

    g = [[] for _ in range(n)]
    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    start, target = map(int, input().split())
    start -= 1
    target -= 1

    INF = 10**18
    dist = [[INF] * (k + 1) for _ in range(n)]
    q = deque()

    init = blocked[start]
    if init <= k:
        dist[start][init] = 0
        q.append((start, init))

    while q:
        v, c = q.popleft()
        d = dist[v][c]

        for u in g[v]:
            nc = c + blocked[u]
            if nc > k:
                continue
            if dist[u][nc] > d + 1:
                dist[u][nc] = d + 1
                q.append((u, nc))

    ans = min(dist[target])
    print(-1 if ans == INF else ans)

if __name__ == "__main__":
    solve()
```このソリューションは、ノードとブロックされた予算の使用量によってインデックス付けされた 2D 距離テーブルを維持します。 初期化には、開始ノードがすでにバジェットの 1 単位を消費しているかどうかが慎重に含まれます。 BFS 中に、すべてのエッジの距離が 1 ステップずつ増加しますが、次のノードがブロックされているかどうかに応じてバジェット ディメンションのみが変化します。 

実装の微妙な詳細は、最後の集計ステップです。 正確に目標を達成するとは想定していません$K$使用法は最適です。 代わりに、すべての有効な使用状態の最小値を取得します。 これにより、ブロックされた許容量の消費が少なくなり、パスが短くなるというケースの見逃しが回避されます。 

## 実用的な例

 ノード 1 が 2 と 3 に接続し、ノード 2 が 4 に接続し、ノード 3 が 4 に接続する小さなグラフを考えてみましょう。ノード 3 がブロックされていると仮定します。$K = 1$。 スタートは 1、ターゲットは 4 です。 

状態を追跡します。 

| ステップ | ノード | 使用済みブロック | 距離 |
 | --- | --- | --- | --- |
 | 初期化 | 1 | 0 | 0 |
 | 1から | 2 | 0 | 1 |
 | 1から | 3 | 1 | 1 |
 | 2から | 4 | 0 | 2 |
 | 3から | 4 | 1 | 2 |

 BFS は両方のルートを探索しますが、ブロックされたノードを使用するパスは 1 つだけです。 両方とも同じ長さでターゲットに到達し、最小値が選択されます。 

これにより、正確性を維持するには、同じノードでの複数のバジェット状態が不可欠であることが確認されます。 

ここで、開始ノードがブロックされている場合を考えてみましょう。$K = 0$。 start が 1 でブロックされている場合、初期化では有効な開始状態が生成されないため、キューは空になり、応答はすぐに返されます。$-1$。 これは、実現可能性が接続性だけではなく、初期予算の消費に依存することを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O((n + m) \cdot (K+1))$| 各州$(node, used)$は一度処理され、すべてのエッジを探索します。 
| スペース |$O(n \cdot (K+1))$| 距離テーブルには、状態ごとに最もよく知られている値が格納されます。 

複雑さは次の場合には許容されます$K$～に比べて中程度である$n$これは、制約付き最短経路問題では一般的です。 BFS 構造により、展開された状態グラフ全体にわたって線形スケーリングが保証されます。

 ## 特殊なケース

 重要なエッジ ケースは、開始ノードがブロックされ、バジェット全体をすぐに消費してしまう場合です。 その状況では、次の状態のみが表示されます。$c = 1$最初は有効であり、$K = 0$、BFS は起動しません。 アルゴリズムは正しく返します$-1$キューが空のままだからです。 

もう 1 つのケースは、予算が利用可能であるにもかかわらず、最適なパスが意図的にブロックされたノードを回避する場合です。 BFS は常に次の遷移を考慮するため、これを自然に処理します。`nc = c`ブロックされていないノードを通過するときに、そのようなパスが距離比較において競争力を維持できるようにします。 

最後のケースは、ターゲット ノード自体がブロックされている場合です。 予算制約に違反しない限り、アルゴリズムに到達することが許可されるため、このアルゴリズムは引き続き機能します。 決勝戦`min(dist[target])`目標を達成するためのあらゆる方法の中から、実現可能な最適な予算の使用状況を正確に把握します。
