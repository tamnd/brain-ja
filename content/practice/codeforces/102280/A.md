 ## 解決策
 ## 問題の理解

 私たちは持っています`n`ドライバーは、最初はログ内で占める位置によって順序付けされます。 ログは次の単一の文字列です。`R`、`S`、 そして`P`, しかし、ゲームラウンド間の境界は消去されました。 

ラウンドは、現在関連グループに残っているすべてのドライバーによってプレイされます。そのため、現在のグループに`k`ドライバー、まさに`k`連続した文字がそのラウンドに属します。 3 つの兆候がすべて発生するか、すべての兆候が同一の場合、誰も脱落せず、同じグループが再度プレイします。 ちょうど 2 つのサインが発生した場合、通常のジャンケンのルールに従って、1 つのサインが負けます。 負けの兆候を示したすべてのドライバーが候補となり、それらの候補のみが現在の除外プロセスを続行します。 そのプロセスでドライバーが 1 人だけ残ると、そのドライバーはルートから離れ、前のグループはドライバーなしで再開されます。 

タスクは、ログからこのプロセスを再構築し、最後に残ったドライバーの番号を出力することです。 ログがゲームの完全な合法的なシーケンスを説明できない場合、答えは次のとおりです。`FAIL`。 

主な問題点は、ラウンドがどこで終了するかがログに明示的に示されていないことです。 幸いなことに、ラウンドの長さは不明ではありません。 これはまさに現在のグループのドライバーの数です。 決定的なラウンドに遭遇すると、負けの兆候によって次のグループが決定されるため、その規模もわかります。 

ドライバーの数は最大で`100`、そのため、現在のゲームを説明する状態は非常に小さいです。 ただし、ログには最大 100 万文字を含めることができます。 これにより、ログの長さが指数関数的に増加することが排除され、ログの線形スキャンが自然なターゲットになります。 の小さな値`n`また、ドライバーのグループのコピーやフィルター処理が低コストであることも意味します。 

いくつかの特殊なケースでは、不注意な実装が無効になる可能性があります。 例えば、```
2
RRRR
```生産しなければならない`FAIL`。 すべてのラウンドには 2 つの等号が含まれるため、すべてのラウンドは引き分けとなり、誰も退場することはありません。 文字列が終了するまで利用可能な文字を単純に処理するソリューションでは、残りのドライバーが誤って報告される可能性があります。 

もう 1 つのケースは、次の 3 つのサインすべてを含むラウンドです。```
3
RSP
```これは敗退ではなく引き分けです。 ログは直後に終了するので、正解は`FAIL`。 2 つの異なる兆候の存在を、誰かを排除するのに十分なものとして扱うのは、ここでは間違っています。 

それほど明白ではないケースは、負けのサインが 1 回だけ現れる決定的なラウンドです。```
2
RP
```

`R`に負ける`P`、それでドライバー`1`葉っぱとドライバー`2`最後の生き残りです。 正しい出力は次のとおりです`2`。 決定ラウンドで常に少なくとも 2 人の候補者が残ると仮定した解決策は、このケースでは失敗します。 

最後に、完全なゲームには未使用のログ文字を含めることはできません。```
2
RPRP
```最初のラウンドですでに勝負は決まっているので、`R`に負ける`P`。 ドライバ`1`葉っぱとドライバー`2`勝ったので追加`RP`ログを無効にします。 答えは`FAIL`。 

## アプローチ

 ブルート フォース ソリューションでは、欠落しているラウンド境界を不明なものとして扱い、ログの考えられるすべてのパーティションをラウンドに試行し、各候補パーティションをシミュレートします。 長さの文字列`L`もっている`2^(L-1)`隣接する文字間に境界を配置する可能な方法。 1 つのパーティションをシミュレートするには次の時間がかかります`O(L)`したがって、このアプローチでは`O(L * 2^L)`最悪の場合は動作します。 のために`L = 1,000,000`、可能なパーティションの数だけでも、実行可能な操作数よりも天文学的に大きくなります。 

この強引な力が必要ない理由は、ゲーム自体がすべての境界を決定するためです。 いつでも現在のグループのサイズは既知です`k`したがって、次のラウンドは正確に次のラウンドを占有する必要があります。`k`文字。 私たちはそのラウンドをすぐに検査することができます。 引き分けで退場`k`変わらない。 決定的なラウンドでは負けのサインが得られるため、そのサインで現在のグループをフィルターすると、敗退を継続する必要がある正確なグループが得られます。 

単純な反復シミュレーションで保持する必要がある状態が 1 つあります。 小規模な敗者グループが解決されている場合、一時的にその親グループから離れます。 小さなグループが 1 つの削除されたドライバーを生成すると、親グループはそのドライバーを削除して再開する必要があります。 これは当然、親グループのスタックによって表されます。 

結果として得られるアルゴリズムは、すべてのログ文字を 1 回だけ消費します。 ドライバーグループに関係する操作は、のみを取得します`O(n)`除去レベルごとに、最大でも`n-1`消去法。 以来`n <= 100`、この余分な作業は無視できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |`O(L · 2^L)`|`O(L)`| 遅すぎる |
 | 最適 |`O(L + n^2)`|`O(n^2)`| 承認済み |

 ここ`L`はログの長さであり、`n`ドライバーの数です。 

## アルゴリズムのチュートリアル

 1. ドライバーを含む現在のグループから開始します。`1, 2, ..., n`。 ポインタを維持する`pos`ログの次の未読文字に移動します。 現在のグループは常に、ドライバーがサインを書いた順序で保存されます。 
2. 正確に摂取する`len(current)`ログからの文字。 残っている文字数が少ない場合、ログはラウンドの途中で終了するため、ログは無効となり、答えは次のようになります。`FAIL`。 
3. このラウンドでどのような兆候が発生するかを判断します。 明確な兆候が 1 つだけの場合、ラウンドは引き分けとなり、現在のグループは変わりません。 前進`pos`グループのサイズによって判断し、別のラウンドを処理します。 
4. 3 つの兆候がすべて発生した場合も、そのラウンドは引き分けとなります。 またまた前進`pos`現在のグループを変更せずに、グループのサイズによって異なります。 
5. ちょうど 2 つのサインが発生した場合、どちらのサインが負けるかを判断します。 ペアの場合`R,S`、`S,P`、 そして`P,R`、負けサインはそれぞれ`S`、`P`、 そして`R`。 
6. 現在のグループをフィルタリングして、符号が負けの符号と等しいドライバーを正確に保持します。 これらは排除を続ける候補者です。 この削除が完了した後に再開する必要があるため、現在のグループを置き換える前に、古いグループをスタックにプッシュします。 
7. 新しいグループに少なくとも 2 つのドライバーが含まれている場合は、まったく同じ方法で処理を続けます。 決定的なラウンドごとにグループのサイズが厳密に縮小されるため、このネストされたプロセスを無期限に継続することはできません。 
8. 新しいグループに 1 人のドライバーが含まれている場合、そのドライバーは現在の排除に負けてガレージを離れるドライバーとして識別されます。 スタックから親グループをポップし、そこからこのドライバーを削除します。 その後、親グループが再び現在のグループになります。 
9. 現在のグループにドライバーが 1 人だけ含まれており、親グループが残っていない場合、そのドライバーが最終的な勝者となります。 ログは次の場合にのみ有効です。`pos`まさに`len(log)`。 文字が残っている場合は、記録されたゲームに追加のイベントが含まれていることを意味するため、答えは次のようになります。`FAIL`。 

なぜ機能するのか: 反復ごとに、`current`は、正確に次のラウンドが正しい記録順序でプレイされているドライバーのグループです。 そのサイズによって、可能な唯一の次のラウンド境界が決まります。 引き分けの場合はこのグループは変更されませんが、決定ラウンドでは負けのサインが一意に識別されるため、そのサインでフィルタリングすると、ルールで規定されている候補者が正確に得られます。 その候補グループが 1 つのドライバーに達したら、保存された親グループからそのドライバーを削除すると、再帰的排除が開始される前のゲームの状態が正確に再構築されます。 したがって、不変式はすべての遷移で存続し、ルートレベルのドライバーが 1 つだけ残っている場合、そのドライバーが必然的に最終的な勝者となります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    log = input().strip()

    pos = 0
    current = list(range(1, n + 1))
    stack = []

    while True:
        k = len(current)

        if k == 1:
            winner = current[0]

            if stack:
                parent = stack.pop()
                parent.remove(winner)
                current = parent
                continue

            if pos == len(log):
                return str(winner)

            return "FAIL"

        if pos + k > len(log):
            return "FAIL"

        round_ = log[pos:pos + k]
        pos += k

        signs = set(round_)

        if len(signs) == 1 or len(signs) == 3:
            continue

        if signs == {"R", "S"}:
            loser = "S"
        elif signs == {"S", "P"}:
            loser = "P"
        else:
            loser = "R"

        next_group = [
            player
            for player, sign in zip(current, round_)
            if sign == loser
        ]

        stack.append(current)
        current = next_group

print(solve())
```の`current`list には、ドライバーの数だけではなく、実際のドライバーの番号が保存されます。 最終的な答えは、単に残りのグループのサイズだけではなく、アイデンティティに依存するため、これが必要です。 

の`pos`変数は常に、まだラウンドに割り当てられていない最初の文字を指します。 表現`log[pos:pos + k]`これは、各ラウンドに現在のグループのすべてのドライバーからの 1 つのサインが含まれているため、まさに有効です。 

一連の記号は、可能な 3 つのラウンド タイプを区別します。 1 つの異なる記号は全会一致の引き分けを意味し、3 つの異なる記号は 3 者による引き分けを意味し、2 つの異なる記号は敗退を意味します。 

決定的なラウンドに向けて、`zip(current, round_)`記録された各標識を対応するドライバーに関連付けます。 フィルタリングオン`loser`再帰的排除のための正確な候補グループを構築します。 ドライバーの順序は保持されますが、ログの番号付けは記録順序に基づいているため、これは重要です。 

スタックには親グループが格納されます。 親は、決定的なラウンドでより小さなグループが作成された場合にのみプッシュされます。 その小さなグループが 1 人のドライバーに到達すると、そのドライバーは親から削除され、親が再開します。 ネストの最大深さは`n-1`、スタックは安全に次のように制限されます。`99`要素。 

Python には整数オーバーフローの問題はなく、すべてのインデックス作成は次のように保護されています。`pos + k > len(log)`。 最終的な平等`pos == len(log)`勝者を見つけることに成功しても、非常に長いログが有効になるわけではないため、これも必要です。

```最初のグループはドライバーです`1`そして`2`。 最初の 2 文字は引き分けを形成し、次の 2 文字も同様です。 最後のペアは、`SP`、紙がハサミに勝つ場所、つまりドライバー`2`負けてドライバー`1`残っています。

## 特殊なケース

 すべて等しい場合、```
2
RRRR
```アルゴリズムが消費する`RR`、1 つの異なる記号を認識し、`[1, 2]`。 その後、別のものを消費します`RR`2 人のドライバーが残ったまま最後まで到達します。 親グループも単一の勝者も存在しないため、アルゴリズムは次の結果を返します。`FAIL`。 

三者凡退の場合は、```
3
RSP
```現在のグループは`[1, 2, 3]`、そして唯一のラウンドは`RSP`。 その記号セットのサイズは 3 であるため、アルゴリズムはグループを変更しないままにします。 ログは 3 つのドライバーが残っている間に終了します。これにより、正しく生成されます。`FAIL`。 

シングルトン負けグループの場合、```
2
RP
```ラウンドには以下が含まれます`R`そして`P`。 ロックが負けたので、次のグループにはドライバーが含まれます`1`。 現在のグループはサイズ 1 に達しているため、ドライバー`1`親から削除されます`[1, 2]`。 親は、`[2]`、ログが完全に消費されているため、ドライバー`2`が勝者として返されます。 

追加の文字については、```
2
