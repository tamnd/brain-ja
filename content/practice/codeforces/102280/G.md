 ## 解決策
 ## 問題の理解

 道路上に出発点があり、その道路から離れた場所に目的地があります。 出発地と目的地の間の直線距離は、`s`、目的地から道路までの垂直距離は`h`。 車は道路に沿って高速で走行できる`v`そして地形を猛スピードで駆け抜ける`u`。 

意図したルートは 2 つの部分で構成されます。 まず、車はある程度の距離を移動します`x`道路沿いにあります。 その後、道路を離れて目的地まで直行します。 の値を見つける必要があります`x`総移動時間を最小限に抑えます。 

入力には 4 つの整数が含まれています`s`、`h`、`u`、 そして`v`。 ここ`s`出発地から目的地までの直線距離です。`h`目的地の道路からの垂直距離です。`u`は地形速度、そして`v`道路速度です。 出力は最適な距離です`x`道路に沿って移動しました。 

すべての値は次のように大きくできます。`10^9`。 これにより、最大 10 億の候補が存在する可能性があるため、可能なすべての整数距離にわたる反復に依存するアルゴリズムが即座に除外されます。 制限時間はわずか 0.5 秒なので、数億回の単純な操作でも妥当な範囲をはるかに超えています。 定数時間または対数時間の数学的解決策が必要です。 

不注意な実装を簡単に破ってしまう境界例がいくつかあります。 道路が地形より速くない場合、車は直ちに出発する必要があります。 たとえば、`1 1 10 10`、道路への目的地の投影は開始点にあるため、正解は`0.0`。 盲目的に除算する式`sqrt(v^2-u^2)`ゼロで割ることになります。 

別の境界ケースは、道路の速度は速いものの、垂直投影に到達するのに十分な速度ではない場合に発生します。 例えば、`5000 3000 20 25`正しい答えを出します`0.0`。 ここで、道路速度はちょうど最適な転換点が開始点となるしきい値にあります。 位置を確認せずに内部最適を仮定する式では、負の距離が生成される可能性があります。 

逆の状況は、実際のインテリア最適化です。 のために`5000 3000 15 25`、直接投影は`4000`スタート地点から数メートル。 最適な転換点は、`1750`道路沿いに数メートルあるので、答えは`1750.0`。 このケースは、すぐに出発することも、投影場所までずっと運転することも常に最適ではないことを確認するので便利です。 

## アプローチ

 簡単なアプローチは、考えられるすべての整数距離を考慮することです。`x`から`0`投影点までの移動時間を計算します。 投影がほぼ近い場合`10^9`メートル離れた、これはおおよその意味です`10^9`平方根といくつかの算術演算の評価。 0.5 秒の制限には遅すぎるだけでなく、整数値のみをチェックしても必要な条件を満たせません。`10^-9`真の最適値が非整数である場合の精度。 

すべての候補のターニングポイントを独立して評価できるため、総当りアプローチが機能します。 問題は候補者が多すぎることだ。 重要な観察は、幾何学によって非常に単純な 1 変数関数が得られ、その最小値は解析的に見つけることができるということです。 

させて`a`出発地から目的地の垂直投影までの道路に沿った距離です。 直線距離なので、`s`そして垂直距離は`h`、直角三角形は次のようになります。`a = sqrt(s^2 - h^2)`。 

車が走れば`x`道路上でメートル、残りの地形距離は`sqrt((a - x)^2 + h^2)`。 

したがって、総移動時間は、`T(x) = x / v + sqrt((a - x)^2 + h^2) / u`。 

この関数は関連する区間で凸であるため、内部最小値は最大 1 つ存在します。 差別化すると得られるもの`T'(x) = 1/v - (a - x) / (u * sqrt((a - x)^2 + h^2))`。 

内部最適値の場合、導関数はゼロでなければなりません。 この方程式を解くと、正確な転換点が得られます。 結果の式は境界に対してチェックできます。`x = 0`。 計算された点が開始点より前にある場合、実際の最適値は単純に次のようになります。`0`。 

このブルート フォースは、数学的に最適化したものと同じ移動時間関数を評価するため機能しますが、候補となる距離の数が膨大になると失敗します。 導関数が閉じた形式のゼロを持つという観察により、問題全体が一定数の算術演算に還元されます。

 ## アルゴリズムのチュートリアル

 1. 距離を計算する`a`を使用して、出発地から目的地の道路への垂直投影までを計算します。`a = sqrt(s^2 - h^2)`。 これにより、元のジオメトリが直角三角形に変換され、投影の 1 次元座標が得られます。 

2. もし`v <= u`、出力`0`。 道路上の移動は地形内を移動するより速くないため、道路に沿って開始点から離れてもルートを改善することはできません。 

3. のために`v > u`、距離の微分方程式を解きます。`y = a - x`転換点から投影まで。 導関数をゼロに設定すると、次のようになります。`y / sqrt(y^2 + h^2) = u / v`。 

収量の二乗と並べ替え`y = h * u / sqrt(v^2 - u^2)`。 

このブランチには次の特徴があるため、式は肯定的です。`v > u`。 

4.変換`y`を使用して希望の道路距離に戻ります`x = a - y`。 

5. もし`x < 0`、出力`0`その代わり。 これは、制約のない最小値が開始点の前にあるため、制約のある最小値が境界で発生することを意味します。`x = 0`。 

6. それ以外の場合は出力`x`十分な精度で。 パイソンの`float`必要なものには十分です`10^-9`ここでは絶対誤差または相対誤差があり、小数点以下 15 桁を印刷すると十分な出力精度が得られます。 

これが機能する理由: 合計移動時間は、旋回位置の凸関数です。 その導関数は単調であるため、導関数がゼロになる内点は固有の内部最小値になります。 その点が許可された間隔の外側にある場合、凸性は最も近い境界が最適であることを意味します。 この問題では、最適化できる唯一の関連境界は次のとおりです。`x = 0`、一方、もう一方の境界は`x = a`から少し移動するので、これ以上良いことはありません`a`出発点に向かうときはいつでも、低速の地形移動をより高速な道路移動に置き換えることができます。`v > u`。 したがって、アルゴリズムは一意の静止点または正しい境界点を返します。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

def solve():
    s, h, u, v = map(int, input().split())

    # Distance from the starting point to the perpendicular
    # projection of the destination onto the road.
    a = math.sqrt(float(s) * s - float(h) * h)

    # If the road is not faster than the terrain, leaving immediately
    # is optimal.
    if v <= u:
        print("0.0")
        return

    # y is the distance from the turning point to the projection.
    y = h * u / math.sqrt(float(v) * v - float(u) * u)

    x = a - y

    # The unconstrained minimum can lie before the starting point.
    if x < 0.0:
        x = 0.0

    print("{:.15f}".format(x))

if __name__ == "__main__":
    solve()
```最初の計算では、直角三角形の水平脚を取得します。 として書くと`float(s) * s - float(h) * h`潜在的に大きな二乗値を浮動小数点に変換する前に、整数演算に依存することを回避します。 

の`v <= u`分岐は、関係する式の前に処理されます。`sqrt(v^2 - u^2)`。 これは単なる最適化ではありません。 いつ`v == u`、平方根はゼロであり、静止点の公式は定義されていませんが、答えはゼロであることが直接わかっています。 

のために`v > u`、コードは計算します`y`よりも導出が簡単です。`x`自体。 幾何学的には、`y`転換点が目的地の投影からどのくらい離れているかを測定します。 それを引くと`a`道路上を実際に移動した距離を示します。 

の`x < 0`check は、数学的静止点が実行可能な区間の外にある場合を処理します。 明示的なものは必要ありません`x > a`式が与えられるので確認してください`y > 0`、 それで`x = a - y`は常に厳密に以下です`a`。 

最大の中間整数平方は次のとおりです。`10^18`。 Python の整数自体はオーバーフローせず、乗算の前にオペランドを浮動小数点に変換すると、計算が通常の倍精度範囲内に保たれます。 必要な応答許容誤差は、これらの入力の大きさの倍精度と互換性があります。

## テストケース```python
import sys
import io
import math

def solve_data(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)

    try:
        s, h, u, v = map(int, sys.stdin.readline().split())

        a = math.sqrt(float(s) * s - float(h) * h)

        if v <= u:
            x = 0.0
        else:
            y = h * u / math.sqrt(float(v) * v - float(u) * u)
            x = max(0.0, a - y)

        return "{:.15f}\n".format(x)
    finally:
        sys.stdin = old_stdin

def run(inp: str) -> str:
    return solve_data(inp)

def check(inp: str, expected: float, message: str):
    actual = float(run(inp))
    assert math.isclose(actual, expected, rel_tol=1e-12, abs_tol=1e-9), (
        f"{message}: expected {expected}, got {actual}"
    )

# Provided samples
check("5000 3000 15 25\n", 1750.0, "sample 1")
check("5000 3000 20 25\n", 0.0, "sample 2")

# Minimum-size input.
check("1 1 1 1\n", 0.0, "minimum values")

# All values equal, so the road provides no speed advantage.
check("100 100 50 50\n", 0.0, "equal speeds")

# Road is faster, but not enough to justify moving along it.
check("5 4 4 5\n", 0.0, "boundary optimum at zero")

# Large values, with a valid interior optimum.
s = 10**9
h = 6 * 10**8
u = 10**8
v = 2 * 10**8
a = math.sqrt(float(s) * s - float(h) * h)
y = h * u / math.sqrt(float(v) * v - float(u) * u)
expected = max(0.0, a - y)
check(f"{s} {h} {u} {v}\n", expected, "maximum-size input")

 ## 特殊なケース

 いつ`h = s`、垂直投影は正確に開始点に位置します。`sqrt(s^2 - h^2) = 0`。 例えば、`1 1 1 1`すぐにそれを取る`v <= u`分岐と返却`0.0`。 たとえ道路の速度が速かったとしても、投影に到達するまでに利用可能な正の距離はないため、可能な最適な道路距離はゼロだけです。 

いつ`v = u`、道路と地形の速度は同じです。 例えば、`100 80 50 50`に入ります`v <= u`分岐と返却`0.0`。 を評価する不注意な実装`sqrt(v^2 - u^2)`最適な答えは簡単ですが、最初は分母が 0 になります。 

いつ`v > u`しかし、道路の利点が不十分であるため、静止点は実行可能な区間の外側にあります。 考慮する`5 4 4 5`。 ここ`a = 3`、 そして`y = 4 * 4 / sqrt(5^2 - 4^2) = 16 / 3`。 

したがって`x = 3 - 16/3 < 0`したがって、アルゴリズムはそれをゼロにクランプします。 制限のない関数の数学的最適値は開始点の手前にあります。これは、実行可能な最良の選択は直ちに道路から離れることを意味します。 

ゼロと正の応答の間のしきい値では、静止点は正確に次の位置にあります。`x = 0`。 サンプル 2 では、`5000 3000 20 25`与える`a = 4000`そして`y = 4000`、正確に生産`x = 0`。 通常の式ではすでにゼロが得られるため、このアルゴリズムでは特別な等価比較は必要ありません。 

最後に、次のような非常に大きな値`s = 10^9`周囲の二乗距離を生成する`10^18`。 Python の整数表現はこれらの値を安全に処理しますが、最終的な計算では倍精度が使用されます。 出力自体は実数であるため、`10^-9`許容誤差がある場合、必要な精度には標準の浮動小数点演算を使用するだけで十分です。
