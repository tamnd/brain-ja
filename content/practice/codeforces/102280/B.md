 ## 解決策
 ## 問題の理解

 独立したミニバスが2台あります。 08:00 から 09:00 までの 1 時間の間に、各ミニバスはちょうど 1 回交差点に到着し、その到着時間は 1 時間のうち 3600 秒に均等に配分されます。 

信号機は時間 0 で青で始まり、緑が続きます。`g`秒、赤が続く`r`秒間、このパターンが繰り返されます。 危険なレースは、信号が赤の間に両方のミニバスが到着し、より具体的には、両方が同じ赤の段階で待機しているときに正確に始まります。 異なる赤色フェーズ中にそれらが到着した場合、それらは一致せず、レースは発生しません。 

入力には以下が含まれます`g`そして`r`、両方とも 1 ～ 3600 の範囲です。出力は、2 つの到着時間が同じ赤色の間隔に属する確率です。 

上限の 3600 は十分に小さいため、数千の操作さえも簡単です。 ただし、最も有用なソリューションは、毎秒またはすべての到着時間のペアをシミュレートする必要はありません。 周期構造により、確率計算全体を一定数の算術演算に減らすことができます。 必要なエラーは`10^-6`、通常の倍精度浮動小数点で十分です。 

主なエッジ ケースは、1 時間の観測間隔が信号サイクルの終わりに必ずしも終了するとは限らないという事実から来ています。 たとえば、`g = 3600`そして`r = 1`、1 時間全体が緑色なので、答えは正確に`0`。 1 時間内に少なくとも 1 つの完全な赤色段階があると仮定する不注意な計算式では、誤って赤色の間隔が追加されてしまいます。 

もう一つの境界ケースは、`g = 3000`、`r = 1000`。 最初のサイクルは 4000 秒続きます。 3600 秒の観察ウィンドウ中、ライトは最初の 3000 秒間は緑色で、最後の 600 秒間だけ赤色になります。 正しい確率は`600^2 / 3600^2 = 1 / 36 ≈ 0.0277777778`。 

常に完全な赤色の長さの区間を追加するソリューション`r`最終サイクルでは使用します`1000^2`の代わりに`600^2`そして間違った答えを導き出します。 

可能な最小の入力は次のとおりです。`g = 1`、`r = 1`。 1 時間に 1800 の完全なサイクルがあり、すべての赤い間隔の長さは 1 です。確率は次のとおりです。`1800 / 3600^2 = 1 / 7200 ≈ 0.000138888889`。 

このケースは、サイクル数と、答えが非常に小さい可能性があるという事実の両方をチェックするため便利です。 

## アプローチ

 直接的なアプローチでは、1 時間を 3600 の 1 秒間隔に分割し、順序付けされた到着秒のペアごとに検査できます。 がある`3600 * 3600 = 12,960,000`最悪の場合はペアになります。 各ペアについて、2 秒が同じ赤色フェーズに属しているかどうかを判断できます。 これは概念的には正しいです。なぜなら、信号機の状態は 1 秒間隔ごとに一定であり、連続的に分布する到着時間では正確な境界の確率が 0 になるからです。 ただし、1,300 万近くのペア チェックは不要であり、元の 0.5 秒の制限には適合しません。 

最終的には到着可能時間の 2 乗で面積を測定しているため、強引なアイデアが機能します。 最初の到着者とします`x`そして2番目は`y`。 どちらも 3600 秒にわたって均一であるため、すべてのポイント`(x, y)`広場で`[0, 3600] × [0, 3600]`確率密度は均一です。 レースが起こるのは、`x`そして`y`同じ赤い間隔内にあります。 

この観察により、重要な点が単純化されます。 1 つの赤い間隔に長さがあると仮定します。`L`。 両方の到着時間は独立してその間隔内に収まる必要があるため、`(x, y)`平面は辺のある正方形です`L`とエリア`L²`。 赤い間隔が異なると、互いに素な正方形が生成されます。 したがって、1 時間内の赤い間隔に長さがある場合、`L1, L2, ...`、合計の有利な領域は`L1² + L2² + ...`。 

可能なすべてのペアの合計面積は次のとおりです。`3600²`、したがって、答えは次のとおりです`(L1² + L2² + ...) / 3600²`。 

すべての完全な信号サイクルには、長さの赤の間隔が 1 つだけ含まれます。`r`。 時間に次の内容が含まれる場合`q`サイクルを完了すると貢献します`q * r²`。 最後に不完全なサイクルが 1 つ存在することもあります。 させて`rem`サイクルが完了した後の残りの秒数になります。 最初`g`残りの秒は緑色です。 のみ`max(0, rem - g)`秒は赤に属する可能性があるため、不完全なサイクルはその長さの 2 乗に寄与します。 

したがって、計算全体は定数時間になります。

 ## アルゴリズムのチュートリアル

 1. 観測長を次のように設定します。`T = 3600`秒と信号サイクルの長さ`cycle = g + r`。 分割する`T`による`cycle`番号を与える`q`1 時間内に完全に含まれる完全なサイクル。 
2. コンピューティング`rem = T % cycle`。 これは、時間の終わりにおける不完全なサイクルの長さです。 もし`rem <= g`、残り全体が緑色であるため、レースの確率には何も寄与しません。 
3. もし`rem > g`、最初の後の部分`g`不完全なサイクルの秒数は赤になります。 その長さは`rem - g`。 この赤いセグメントが貢献します`(rem - g)²`有利なエリアへ。 
4.それぞれの`q`完全なサイクルには、長さの赤い間隔が含まれます`r`。 彼らは共に貢献します`q * r²`。 
5. 完全な寄与分と部分的な寄与分を加算し、次の値で割ります。`T²`。 分子は競合を引き起こすすべての到着時間ペアの面積であり、分母は考えられるすべての到着時間ペアの面積です。 
6. 結果として得られる浮動小数点値を、必要な桁数を満たすのに十分な桁数で出力します。`10^-6`エラー許容度。 

### なぜ効果があるのか

 赤色の長さの間隔ごとに`L`、両方の独立した到着時間が同じ間隔内に収まる場合に、競合が発生します。 到着時間ペアの 2 次元空間では、それらの可能性は面積の正方形を形成します。`L²`。 異なる赤色の間隔に属する正方形は互いに素であるため、その面積を加算することができます。 このアルゴリズムは、切り捨てられた可能性のある最終間隔も含め、1 時間のウィンドウと交差するすべての赤い間隔の長さを正確に計算します。 正方形の長さを合計面積で割ります。`3600²`したがって、正確に望ましい確率が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

T = 3600

def solve():
    g, r = map(int, input().split())

    cycle = g + r
    full_cycles = T // cycle
    rem = T % cycle

    favorable = full_cycles * r * r

    partial_red = max(0, rem - g)
    favorable += partial_red * partial_red

    answer = favorable / (T * T)
    print(f"{answer:.12f}")

if __name__ == "__main__":
    solve()
```最初の 3 つの整数計算によって、1 時間が完全な信号サイクルと不完全な信号サイクルにどのように分割されるかが決まります。 以来`g`そして`r`は整数で最大 3600 であるため、Python では整数オーバーフローの危険はなく、同じ算術演算は標準の 64 ビット整数実装でも安全です。 

表現`max(0, rem - g)`最後の部分サイクルを処理します。 緑の間に残りが終了した場合、`rem - g`は負ですが、カウントする赤い間隔がありません。 ゼロにクランプすると、正の平方を誤って追加することがなくなります。 

の乗算`r * r`浮動小数点に変換する前に発生します。 これにより、最終的な分割まで幾何学的計算が正確に保たれます。 最終的な答えは小数点以下 12 桁で出力され、必要な精度よりもかなり高い精度が得られます。`10^-6`。 

信号機の境界自体は特別な処理を必要としません。 緑が赤に変わる瞬間など、単一の正確な時間は、連続一様分布の下では確率がゼロであるため、そのエンドポイントがどちらかのフェーズに割り当てられているかどうかによって答えが変わることはありません。

import sys
import io

T = 3600

def solve():
    g, r = map(int, input().split())

    cycle = g + r
    full_cycles = T // cycle
    rem = T % cycle

    favorable = full_cycles * r * r

    partial_red = max(0, rem - g)
    favorable += partial_red * partial_red

    answer = favorable / (T * T)
    print(f"{answer:.12f}")

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        solve()
        return sys.stdout.getvalue().strip()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

def assert_close(inp: str, expected: float, message: str):
    actual = float(run(inp))
    assert abs(actual - expected) <= 1e-12, message

# Provided samples
assert_close("1800 1800\n", 0.25, "sample 1")
assert_close("2700 3600\n", 0.0625, "sample 2")

# Minimum-size input
assert_close("1 1\n", 1 / 7200, "minimum values")

# Maximum-size input
assert_close("3600 3600\n", 0.0, "maximum values")

# Final partial cycle ends exactly at the green/red boundary
assert_close("3600 1\n", 0.0, "no red time inside the hour")

# Only 600 seconds of the final red interval are visible
assert_close("3000 1000\n", 600 * 600 / (3600 * 3600), "partial red interval")

# Many complete cycles, with no partial red interval
assert_close("1000 2000\n", 2000 * 2000 / (3600 * 3600), "complete red interval")

## 特殊なケース

 のために`1 1`、サイクルの長さは 2 なので、`3600 // 2 = 1800`完全なサイクルと`rem = 0`。 すべての赤い間隔の長さは 1 であり、好ましい領域が得られます。`1800 * 1² = 1800`。 結果は`1800 / 12,960,000 = 0.000138888889`。 アルゴリズムは 1800 サイクルにわたって反復する必要はありません。 

のために`3600 3600`、サイクルの長さは 7200 であるため、完全なサイクルはゼロであり、`rem = 3600`。 残りはちょうど緑の持続時間なので、`partial_red = max(0, 3600 - 3600) = 0`。 答えはゼロです。 これにより、緑の終点を正の長さの赤の区間として誤って扱う実装が捕捉されます。 

のために`3600 1`、サイクル長は 3601 です。ここでも完全なサイクルはゼロで、3600 秒の観測は最初の赤色段階が始まるちょうど 1 秒前に終了します。 赤い部分の長さは`max(0, 3600 - 3600) = 0`, したがって、答えはゼロです。 

のために`3000 1000`、サイクルの長さは 4000 です。1 時間には、最初の 3000 秒の緑と、その後の 600 秒の赤が含まれます。 したがって`full_cycles = 0`、`rem = 3600`、 そして`partial_red = 600`。 有利なエリアは、`600² = 360,000`、生産`360,000 / 12,960,000 = 0.027777777778`。 これは、表示される赤色の間隔が設定された赤色の期間よりも短いため、オフバイワン スタイルの主なケースです。 

のために`1000 2000`、サイクルの長さは 3000 です。1 時間には 1 つの完全なサイクルと 600 秒の残りが含まれます。 残りはまだ次の緑段階内にあるため、何も寄与しません。 唯一の好ましい領域は、長さ 2000 の完全な赤色の区間から得られます。`2000² / 3600² = 0.308641975309`。 これは、残りが存在するという理由だけで残りをカウントすべきではなく、グリーンフェーズ後の部分のみが重要であることを証明します。
