 ## 解決策
 ## 問題の理解

 (n) 台のドライバーと (n) 台のガゼル車があります。 各ドライバーは 1 台の車両を受け取り、すべての車両が 1 人のドライバーに割り当てられるため、割り当ては車両の順列になります。 

自分の車を受け取る場合、ドライバーは固定と呼ばれます。 その条件は、選ばれた (k 人の) ドライバーのうち、少なくとも 1 人は他人の車を運転していなければならないというものです。 同様に、全員が自分の車を受け取る (k) 人のドライバーを見つけることも不可能に違いありません。 

これにより、はるかに単純な定式化が得られます。順列には最大で (k-1) 個の固定点が含まれる可能性があります。 最大で (k-1) 個の固定点を持つ (10^9+7) を法とする (n) 個の要素のすべての順列をカウントする必要があります。 

元のステートメントには、提供されたテキストの書式設定の問題があります。例は 1 つにマージされています。 公式コンテスト ページでは、サンプルが (4\ 2 \to 17) および (30\ 1 \to 568643488) として提供されています。 

この制約により、(n) は 1000 に達することが許可されます。(1000!) は実行可能な演算数を大幅に超えているため、すべての順列を含むものは即座に除外されます。 (O(n^2)) の解であっても基本的な反復は約 100 万回しか実行されませんが、(O(n!)) は数十程度の小さな (n) ではすでに不可能です。 また、0.5 秒という制限により、Python では単純な (O(n^2)) 動的プログラムの魅力が薄れるため、(O(n)) のソリューションが推奨されます。 

誤って処理されやすい境界ケースがいくつかあります。 (n=1,k=1) の場合、唯一の割り当てはドライバーに自分の車を与えるため、条件は失敗し、答えは (0) になります。 (k=n) に対して単純に (n!) を返す不用意な実装も間違っています。 たとえば、(n=2,k=2) の場合、両方のドライバーが自分の車を同時に受け取ることはできないため、交換のみが有効で、答えは (2) ではなく (1) になります。 より一般的には、(k=n) の場合、恒等式を除くすべての順列が有効であり、(n!-1) が得られます。 逆の極端な場合、(k=1) は、ドライバーが 1 人でも自分の車を所有することを許可されないことを意味するため、有効な割り当てはすべて錯誤でなければなりません。 たとえば、(n=3,k=1) には有効な順列が 2 つだけあります。 

## アプローチ

 直接的な総当たりアプローチは、(n) 台の車両のすべての順列を生成し、固定されている位置の数を数え、その数が (k) より小さい場合は順列を維持することです。 これは正しいです。なぜなら、考えられるすべての車の分布は (n!) 個の順列の中で 1 回だけ出現し、条件は固定位置の数にのみ依存するからです。 最悪の場合、すべての順列のすべて (n) 個の位置を明示的に検査すると、作業は (n\cdot n!) になります。 (n=1000) の場合、つまり (1000\cdot1000!) の位置チェックですが、これは完全に実行不可能です。 

有益な観察は、所定の数の固定点を持つ順列が標準的な組み合わせ構造を持つということです。 正確に (i) ドライバーが自分の車を受け取ると仮定します。 これらの (i) ドライバーを (\binom ni) の方法で選択できます。 それらを修正した後、残りの (n-i) 人のドライバーはすべて、別のドライバーの車を受け取る必要があります。そうしないと、別の固定点が存在してしまうからです。 したがって、残りの割り当ては (n-i) 個の要素の乱れになります。 

(D_m) を (m) 個の要素の乱れの数を表すものとします。 正確に (i) 固定小数点を持つ順列の数は次のとおりです。 

[
 \binom に D_{n-i}。 
]

 最大 (k-1) 個の固定点が許可されるため、答えは次のようになります。 

[
 \sum_{i=0}^{k-1}\binom に D_{n-i}。 
]

 残りのタスクは、この合計を効率的に評価することです。 混乱は再発を満足させる

 [
 D_m=(m-1)(D_{m-1}+D_{m-2})、
 ]

 (D_0=1) および (D_1=0) です。 したがって、(n) までのすべての乱れの値は (O(n)) で計算できます。 

(0\le i<k) のすべての二項係数 (\binom ni) も必要です。 (n\le1000) なので、モジュラー逆関数を事前計算し、次を使用して現在の二項係数を更新できます。 

\binom n{i-1}\frac{n-i+1}{i}。 
]

すべての (i\le1000) は素数法 (10^9+7) より小さいため、(i) の逆剰余が存在します。 これにより、別の (O(n)) 回の計算が行われます。 

ブルートフォース手法は定義を直接チェックするため機能しますが、順列の数が階乗的に増加するため失敗します。 固定点の数のみが重要であるという観察により、指数関数的に多くの順列を (n) 個の組み合わせクラスにグループ化することができ、また、狂乱の反復により、それらのクラスを線形時間で評価することができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(n\cdot n!)) | (O(n)) | 遅すぎる |
 | 最適 | (O(n)) | (O(n)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. (n) と (k) を読み取ります。 望ましい順列は、まさに (k) 個未満の固定点を持つ順列です。 
2. 錯乱配列 (D) を計算します。 (D_0=1)と(D_1=0)を設定します。 すべての (m\ge2) に対して、(D_m=(m-1)(D_{m-1}+D_{m-2})) モジュロ (10^9+7) を使用します。 この繰り返しでは、誰も元の車を維持していない順列がカウントされます。 
3. (1) から (n) までのモジュラー逆行列を事前計算します。 法は素数であり、(n<10^9+7) であるため、この範囲内のすべての数値は法を逆法とします。 
4. (\binom n0=1) から始めます。 (0) から (k-1) までの各 (i) に対して、
 [
 \binom niD_{n-i}
 ]
 答えに。 この用語では、まず、どのドライバーが自分の車を保持するかを正確に選択し、次に残りのすべてのドライバーの狂気を回避して、誤って修復されるドライバーがいないようにします。 
5. (i) の現在値を処理した後、次の反復の二項係数を次を使用して更新します。 
[
 \binom n{i+1}
 =
 \binom ni\frac{n-i}{i+1}。 
]
 すべての乗算と除算は、事前に計算された逆モジュラーを使用して、モジュロ (10^9+7) で実行されます。 

### なぜ効果があるのか

 有効な置換を考慮し、それが正確に (i) 固定点を持つようにします。 これらの固定点は、正確に (\binom ni) の方法で選択できます。 ドライバーが選択されると、残りの (n-i) 人のドライバーは自分の車を持つことができなくなります。そうしないと、順列が (i) 個を超える固定点を持つことになります。 したがって、彼らの車は錯乱を形成し、正確に (D_{n-i}) 個の可能性を与えます。 したがって、(\binom niD_{n-i}) は、正確に (i) 個の固定点を持つすべての順列を 1 回だけカウントします。 (i=0,\ldots,k-1) についてこの数量を合計すると、元の条件で許可される順列が正確にカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 1_000_000_007

def solve():
    n, k = map(int, input().split())

    # D[i] = number of derangements of i elements.
    der = [0] * (n + 1)
    der[0] = 1

    if n >= 1:
        der[1] = 0

    for i in range(2, n + 1):
        der[i] = (i - 1) * (der[i - 1] + der[i - 2]) % MOD

    # Modular inverses of 1..n.
    inv = [0] * (n + 1)
    if n >= 1:
        inv[1] = 1

    for i in range(2, n + 1):
        inv[i] = MOD - (MOD // i) * inv[MOD % i] % MOD

    # C(n, 0) = 1.
    comb = 1
    ans = 0

    for i in range(k):
        ans = (ans + comb * der[n - i]) % MOD

        if i + 1 < k:
            comb = comb * (n - i) % MOD
            comb = comb * inv[i + 1] % MOD

    print(ans)

if __name__ == "__main__":
    solve()

逆配列は標準の素数係数再帰を使用します。 

MOD-\left\lfloor\frac{MOD}{i}\right\rfloor
 \operatorname{inv}(MOD\bmod i)\pmod{MOD}。 
]

 現在の値`comb`ループの先頭では常に (\binom ni) になります。 答えは次の係数を計算する前に更新されるため、ループには正確に (i=0,\ldots,k-1) が含まれます。 この境界が、この問題の主要なオフバイ 1 の詳細です。 

Python の整数はオーバーフローしませんが、すべての値は乗算後に剰余 (10^9+7) で減算されます。 リダクションにより中間値が小さく保たれ、問題で必要な演算が反映されます。 

アップデート```
comb = comb * (n - i) % MOD
comb = comb * inv[i + 1] % MOD
```と同等です

 \binom ni\frac{n-i}{i+1}。 
]

 値を剰余した後に通常の整数除算を使用する`MOD`それは不正確でしょう。 モジュラー除算は通常の整数除算ではないため、モジュラー逆算が必要です。 

## 実用的な例

 最初のサンプルの場合、(n=4、k=2)。 固定点は 0 個または 1 個の場合があります。 

| (i) | (\binom{4}{i}) | (D_{4-i}) | 貢献 | 実行中の答え |
 | --- | --- | --- | --- | --- |
 | 0 | 1 | 9 | 9 | 9 |
 | 1 | 4 | 2 | 8 | 17 |

 値 (D_4=9) は、誰も自分の車を持たない割り当てをカウントします。 正確に 1 つの固定点に対して、そのドライバーを (4) 通りに選択し、残りの 3 つのドライバーを (D_3=2) 通りに配置します。 合計は(9+8=17)となり、公式サンプルと一致します。 

2 番目のサンプルの場合、(n=30、k=1)。 ループには (i=0) のみが含まれるため、ドライバーは自分の車を受け取ることはできません。 

| (i) | (\binom{30}{i}) | (D_{30-i}) | 貢献 | 実行中の答え |
 | --- | --- | --- | --- | --- |
 | 0 | 1 | (D_{30}) | (D_{30}) | 568643488 |

 問題は、混乱の数 (D_{30}) に直接減少しました。 漸化法 (10^9+7) を計算すると、公式の 2 番目のサンプル出力 (568643488) が得られます。

 ## 特殊なケース

 (n=1,k=1) の場合、唯一の置換は次のとおりです。`[1]`。 固定点は 1 つありますが、最大許容数は (k-1=0) です。 アルゴリズムは (D_1=0) を計算し、(i=0) についてのみループに入り、(D_1) を加算して、`0`。 入力は`1 1`。 

(k=1) の場合、(i=0) の直後に加算が停止します。 ゼロの固定点は許可されますが、1 つの固定点はすでに禁止されているため、答えは正確に (D_n) です。 のために`3 1`、2 つの有効な順列は、次のように表される巡回代入です。`2 3 1`そして`3 1 2`したがって、アルゴリズムは (D_3=2) を返します。 

(k=n) の場合、許容される固定点の数は (n-1) です。 恒等式を除くすべての順列には最大 (n-1) 個の固定点があるため、答えは (n!-1) でなければなりません。 のために`2 2`、2 つの順列は恒等と交換であり、有効な割り当てが 1 つだけ残ります。 合計では (D_2+\binom21D_1=1+0=1) が計算され、これはこの解釈と一致します。 

正確に (k-1) 個の固定点が許可される場合も、オフバイワン トラップです。 のために`5 3`、0、1、2、または 3 ではなく、0、1、または 2 つの固定点が必要です。 寄与度は (D_5=44)、(5D_4=45)、および (\binom52D_3=20\cdot2=40) であり、次のようになります。`129`最初の 3 つの貢献のみが使用される場合。 実際の正しい合計は (44+45+40=129) であるため、このケースは、組み合わせ項が正しく形成されているかどうかを確認するのに役立ちます。 条件を「最大 (k) 個の固定点」として解釈する不注意な実装では、さらに (\binom53D_2=10) が含まれ、誤った結果が生成されます。`139`。 

最大の場合`1000 1000`、アルゴリズムは順列を構築することはなく、階乗サイズのオブジェクトを使用することはありません。 (D_{1000}) までの乱れを計算し、二項係数を一度に 1 つずつ生成し、1000 の合計ステップを実行します。 (k=n) であるため、数学的答えは (1000!-1) モジュロ (10^9+7) になります。`641419707`。 これにより、許可される最大の入力と固定小数点条件の正確な上限の両方が実行されます。
