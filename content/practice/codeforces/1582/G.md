 ## 解決策
 ## 問題の理解

 一連の数値と、それらの間に配置される一連の演算が与えられます。 各セグメントを値 1 で開始し、左から右に演算を適用します。 各位置は、現在の値に指定された数値を乗算するか、その数値で除算します。 作業を進めると、各操作の後に中間値が記録されます。 これらの中間値のすべてが整数である場合、セグメントは有効であると呼ばれます。 

タスクは、このプロセス全体で整数のみを生成する連続セグメントの数をカウントすることです。 

重要な問題は、除算がグローバルな制約を導入することです。数値で除算したら、その時点までの累積積に必要な素因数がすべて含まれていることを確認する必要があります。そうでない場合、値は整数でなくなります。 セグメントはどこからでも開始できるため、末尾だけでなく、セグメント内のすべてのプレフィックスに対して条件が適用される必要があります。 

この制約により、総当たり攻撃は実行不可能になります。 最大 100 万個の要素を使用すると、すべてのセグメントのチェックでさえすでに 2 次的であり、因数分解を再計算したり、各セグメント内の割り算を追跡すると、演算ごとに別の対数係数またはさらに悪い係数が導入されます。 素因数分解を繰り返し再計算したり、セグメントを個別にシミュレートしたりするソリューションは失敗します。 

除算を補う乗算の前に除算が現れる場合、微妙なエッジケースが発生します。 たとえば、シーケンスが分割で始まる場合、そこから始まるすべてのセグメントは直ちに無効になりますが、後で始まるセグメントは再び有効になる可能性があります。 もう 1 つの注意が必要な状況は、グローバルな履歴ではなくローカル セグメントのみが重要となるため、素因数の不足が生じ、後で修復される場合です。 

## アプローチ

 ブルートフォース手法では、すべてのセグメントを反復処理し、各セグメントのプロセスをシミュレートします。 固定セグメントの場合は、現在の値を維持し、値が整数のままであるかどうかを確認しながら乗算または除算を繰り返します。 このアプローチは定義に直接従うため、正しいです。 ただし、最悪の場合、各セグメントには直線的な時間がかかり、全体的に三次的な動作が発生します。 

主な障害は、割り算が素因数のバランスに依存することです。 数値を乗算すると素因数が加算され、除算すると素因数が削除されます。 セグメントのプレフィックスで素指数が負にならない限り、値は整数のままです。 

これにより、問題は、すべての素数について、その指数がすべての接頭辞にわたって非負のままであるかどうかの追跡に変換されます。 各セグメントを最初から再計算する代わりに、配列を左から右に処理し、各位置で終了するセグメントの最適な開始点を維持します。 

重要な観察は、各素数について、現在の残高がゼロを下回るかどうかだけを知る必要があるということです。 そうなった場合、その時点より前に開始するセグメントは有効なままではなくなるため、開始位置を前に進める必要があります。 各素数は、セグメントをどこまで左から開始できるかについて独立して制約を適用します。 最終的な有効な開始は、最も制限的なプライム制約によって決定されます。

 ## アルゴリズムのチュートリアル

 素因数によって課される制約を維持しながら、配列を左から右に処理します。 

1. 各数値を素因数分解します。 乗算は素数の加算として扱い、除算は素数の減算として扱います。 これにより、問題は複数の独立したバランス カウンター (素数ごとに 1 つ) の追跡に変換されます。 
2. 辞書を管理する`cur[p]`現在のプライムの余剰を表す`p`位置で終了するアクティブなセグメント内`i`。 正の値は、将来の除算に使用できる素数の追加のコピーがあることを意味します。 
3. 別の辞書を維持する`bad[p]`これはプライムのセグメントを再開することを強制する最も古い位置を記録します。`p`。 最初はすべての値がゼロです。 
4. 位置で乗算を処理する場合`i`、増やします`cur[p]`のすべての素因数に対して`a[i]`。 乗算だけではリソースが追加されるだけなので、制約違反は発生しません。 
5. 除算処理を行う場合`a[i]`からその素因数を引きます。`cur`。 プライムの場合`p`、値は負になります。これは、現在のセグメントにこのプレフィックスを含めることができないことを意味します。 次にリセットします`cur[p]`ゼロにして設定する`bad[p] = i`、つまり、ここで終わる有効なセグメントはこの時点の後に開始する必要があります。 
6. 各ポジションについて`i`、最も早い有効な開始は、最も制限的なプライム制約によって決定されます。 私たちは計算します`L = max(bad[p])`現在関連するすべての素数にわたって。 で終わる有効なセグメントの数`i`それなら`i - L + 1`。 
7. 私たちはこの貢献をポジションごとに蓄積します。 

これが機能する理由は、各主制約が独立しており、セグメントの開始位置に単調な制限を強制するためです。 プライムがその位置で強制的に再起動すると`i`、それより早く開始すると、で終わるセグメント内の素数の整数の有効性に永久に違反します。`i`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXV = 10**6 + 1

spf = list(range(MAXV))
for i in range(2, int(MAXV ** 0.5) + 1):
    if spf[i] == i:
        for j in range(i * i, MAXV, i):
            if spf[j] == j:
                spf[j] = i

def factor(x):
    res = {}
    while x > 1:
        p = spf[x]
        cnt = 0
        while x % p == 0:
            x //= p
            cnt += 1
        res[p] = cnt
    return res

n = int(input())
a = list(map(int, input().split()))
b = input().strip()

cur = {}
bad = {}
L = 0
ans = 0

for i in range(n):
    if b[i] == '*':
        f = factor(a[i])
        for p, c in f.items():
            cur[p] = cur.get(p, 0) + c
    else:
        f = factor(a[i])
        for p, c in f.items():
            cur[p] = cur.get(p, 0) - c
            if cur[p] < 0:
                bad[p] = i + 1
                cur[p] = 0

    for p, v in bad.items():
        if v > L:
            L = v

    ans += (i + 1 - L)

print(ans)
```この実装は、最小の素因数ふるいを使用した高速因数分解と組み合わせた線形スキャンに依存しています。 各数値は 1 回因数分解され、各素数は数回の更新のみに寄与します。 

変数`cur`実行中のセグメントで現在利用可能な各プライムの追加コピーが何個あるかを追跡します。 除算によって不足が強制されると、対応する素数はその位置で無効としてマークされ、そのカウンターがリセットされます。これは、この違反を超えて拡張する必要があるセグメントには以前の余剰を再利用できないためです。 

変数`L`すべての素数固有の制約を、各位置で終わる有効なセグメントの単一のグローバル左境界に集約します。 

## 実用的な例

 乗算と除算が相互作用する小さなシーケンスを考えてみましょう。 

入力:```
5

```素数 2 と 3 を追跡します。 

各ステップで次のことを維持します。`cur`そして`L`。 

| 私 | オプ | a[i] | 現在の変更点 | 悪いアップデート | Ｌ | 貢献 |

 | 1 | * | 2 | 2: +1 | なし | 0 | 1 |
 | 2 | / | 6 | 2:-1,3:-1 → 両方リセット | 悪い[2]=2、悪い[3]=2 | 2 | 0 |

 | 4 | / | 2 | 2:-1 | 悪い[2]=4 | 4 | 0 |
 | 5 | * | 3 | 3:+1 | なし | 4 | 1 |

2 番目の例:

*/**

    import sys
    input = sys.stdin.readline

    spf = list(range(MAXV))

            cnt = 0
            while x % p == 0:

                cnt += 1
            res[p] = cnt
        return res

    bad = {}
    L = 0
    ans = 0

    for i in range(n):

            for p, c in f.items():

 ## 特殊なケース

 最初のエッジ ケースは、配列に 1 だけが含まれる場合です。 素因数がないので、掛け算も割り算もバランスを変えません。 アルゴリズムが更新されない`bad`、 それで`L`はゼロのままで、すべてのセグメントがカウントされます。 これは、すべてのセグメントが自明に有効であるという事実と一致します。 

もう 1 つのエッジ ケースは、最初の演算が除算である場合です。 因数分解するとすぐにマイナスの残高が生じ、強制的に`bad[p]`1に等しいと移動します`L`違反の前に開始するセグメントがカウントされないように、前方に移動します。 これにより、後で回復できるようにしながら、無効なプレフィックスが正しく削除されます。 

最後のケースは、同じ数の乗算と除算の間で振動が繰り返される場合です。 このアルゴリズムは、赤字が発生するたびにカウンターをリセットすることでこれを処理し、現在実行可能なプライム残高のみがアクティブなセグメント境界に影響を及ぼし、過去の黒字が古くならないようにします。
