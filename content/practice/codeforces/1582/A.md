 ## 解決策
 ## 問題の理解

 3 つのタイプに分割された曲のコレクションが提供されます。1 分間のもの、2 分間のもの、3 分間のものがあります。 各テスト ケースでは、すべての曲を 2 つのコンサートのいずれかに割り当てる必要があります。 各曲は 1 回だけ使用する必要があり、各コンサートの継続時間は、割り当てられた曲の継続時間の合計となります。 

目標は、2 つのコンサートの合計時間の絶対的な差ができるだけ小さくなるように曲を分割することです。 

構造の観点から考えると、問題は実際には、多くの 1、2、3 で構成される数値の集合を平衡和を持つ 2 つのグループに分割することです。 

制約は大きく、a、b、c はそれぞれ最大 10^9 で、テスト ケースは最大 1000 個です。 これにより、個々の曲の割り当てを明示的に構築またはシミュレートしようとするアプローチは即座に排除されます。 どのメソッドもテスト ケースごとに一定時間で機能する必要があります。 

一般的な微妙なエッジ ケースは、合計が非常に小さい場合、または 1 つのタイプが優勢な場合に発生します。 たとえば、a = 1、b = 0、c = 0 のような 1 つの曲タイプしかない場合、私たちができる最善の方法は、それを 1 つのコンサートにすべて入れて、差を 1 にすることです。貪欲な「ペアリング」アイデアは、完璧なペアリングが不可能な場合でも、残りを正しく処理する必要があります。 

もう 1 つの重要なエッジ ケースは、異なる長さの曲を混合することで正確なバランスをとることができる場合です。 たとえば、3 分の 1 つの曲は 1 分と 2 分の曲のバランスを正確に取ることができるため、ローカルでの貪欲なマッチングが重要になります。 

## アプローチ

 素朴なアプローチでは、各曲を 2 つのコンサートのうち明るい方に 1 つずつ割り当てようとします。 この貪欲なシミュレーションでは、すべての a + b + c 曲を反復処理する必要があり、最悪の場合、そのサイズは 3 × 10^9 に達する可能性があります。 これはまったく実現不可能です。 

もう 1 つの強引な解釈は、これをパーティションの問題として扱い、曲のすべてのサブセットを試すことです。 それは曲数が指数関数的に増加しており、すぐには不可能です。 

重要な点は、個々の曲ではなく、各タイプのカウントのみが重要であるということです。 私たちは事実上、最初のコンサートに 1、2、3 をいくつ入れるかを選択していることになります。 残りは2番目に進みます。 これにより、問題は 3 つの変数の 2 つの線形結合のバランスをとることになります。 

合計金額は決まっています。 それを S で表す場合、2 つのサブセット間の絶対差を最小化することは、合計が S/2 にできるだけ近いサブセットを見つけることと同じです。 

重要な構造は、任意のサブセット合計を自由に選択できないということです。 多重度が大きく、価値 1、2、および 3 の限られたコインを使用して合計を形成することしかできません。 これにより、到達可能な合計が十分に密になり、最適なソリューションを単純な貪欲なバランシング ルールで特徴付けることができます。 

総額の半分を目指して貪欲に一つのコンサートを構築していきます。 最初にできるだけ大きな曲（3分）を使用し、次に2分曲で調整し、最後に残りのギャップを1分曲で修正します。 値が小さく構造化されているため、この貪欲な構築により常に達成可能な最良のバランスが得られます。

 ## アルゴリズムのチュートリアル

 合計持続時間 S = a + 2b + 3c を計算し、S/2 にできるだけ近い最初のコンサートの合計を構築することを目指します。

1. S = a + 2b + 3c を計算します。 これはすべての曲を合わせた合計時間であり、有効なパーティションではこの合計を 2 つの部分に分割する必要があります。 
2. 目標 T = S を設定します // 2. 実現可能性の制約を超えることなく、1 つのサブセットをこの目標にできるだけ近づけたいと考えています。 
3. 最初のコンサートではできるだけ多くの 3 分間の曲を使用するようにします。ただし、C を超えず、T // 3 を超えないようにしてください。これは最適です。3 分間の曲が項目ごとに最も多く寄与し、差が最も早く縮まるためです。 
4. 選択した 3 分間の曲の貢献度を残りのターゲットから減算します。 次に 2 分の曲に移行し、更新された目標を超えない範囲でできるだけ多くの曲を取得します。 理由は同じです。利用可能な最大のユニットを使用して残りのギャップを貪欲に埋めています。 
5. 最後に、a で制限された 1 分の曲を使用して残りのギャップを埋めます。 この時点で、残りのすべてのユニットは 1 分の曲である必要があるため、単純に min(a, 残りのギャップ) を取得します。 
6. X を最初のコンサートの構築された合計とする。 2 回目のコンサートは S − X なので、答えは |S − 2X| となります。 

これが機能する理由は、到達可能な合計の構造が十分に連続しているため、各ステップでの局所的に最適な選択がより適切な全体的な配置を妨げないためです。 私たちは常に目標を超過することなく可能な限り最大の貢献を選択するため、より小さなアイテムで埋められる小さなギャップに高額のアイテムを無駄にすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        a, b, c = map(int, input().split())
        
        S = a + 2*b + 3*c
        target = S // 2
        
        take3 = min(c, target // 3)
        target -= 3 * take3
        
        take2 = min(b, target // 2)
        target -= 2 * take2
        
        take1 = min(a, target)
        target -= take1
        
        X = 3 * take3 + 2 * take2 + take1
        print(abs(S - 2 * X))

if __name__ == "__main__":
    solve()
```コードは合計を計算し、その半分に最も近い達成可能なサブセット合計を貪欲に構築します。 減算ステップにより、目標を決して超えることがないことが保証されます。 最後の式は、構築されたサブセットを 2 つのパーティション間の絶対差に変換します。 

唯一の微妙な点は、2 番目のコンサートを明示的に追跡する必要がないことです。 一方がわかれば、もう一方も決まります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        a, b, c = map(int, input().split())
        S = a + 2*b + 3*c
        target = S // 2

        take3 = min(c, target // 3)
        target -= 3 * take3

        take2 = min(b, target // 2)
        target -= 2 * take2

        take1 = min(a, target)
        target -= take1

        X = 3 * take3 + 2 * take2 + take1
        out.append(str(abs(S - 2 * X)))

    return "\n".join(out)

assert run("4\n1 1 1\n2 1 3\n5 5 5\n1 1 2\n") == "0\n1\n0\n1"
assert run("1\n1 0 0\n") == "1"
assert run("1\n0 0 1\n") == "1"
assert run("1\n10 10 10\n") in {"0", "1"}
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 0 0 | 1 | 単一の最小のゼロ以外の不均衡 |
 | 0 0 1 | 1 | 1 曲 3 分分割ケース |
 | 10 10 10 | 0 または 1 | バランスのとれた大型の対称ケース |

 ## 特殊なケース

 1 分間の曲だけなど、1 種類の曲しか存在しない場合、貪欲な構築では単純に min(a, target) ステップを介してそれらの半分が暗黙的に取得されます。 たとえば、a = 5、b = 0、c = 0 の場合、合計は 5、ターゲットは 2 です。アルゴリズムは 2 つの 1 を取得し、3 つは他のコンサートに残し、差分 1 を正しく返します。 

c が大きく a = b = 0 であるなど、1 つの大きな曲が支配的である場合、アルゴリズムはそのうちのフロア(c/2) を片側に取り込み、S/2 に向かって埋めます。 たとえば、c = 3 の場合、合計は 9、ターゲットは 4 になります。このアルゴリズムでは 3 分の曲が 1 つかかり、ターゲット 1 が残りますが、これを埋めることはできず、最終的な差は 3 となり、避けられない不均衡と一致します。 

(1, 1, 1) などの完全なキャンセルが存在する場合、貪欲なマッチングにより 1 + 2 が 3 でキャンセルされることが保証されます。これは、最初に 3 分間の曲がターゲットを固定するために使用され、小さな曲がオーバーシュートすることなく残りのギャップを埋め、正確な同等性が得られるためです。
