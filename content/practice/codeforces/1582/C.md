 ## 解決策
 ## 問題の理解

 小文字で構成される文字列が与えられます。 アルファベットの 1 文字だけを選択し、文字列からその選択した文字が出現する箇所を削除することができます。場合によっては、その文字をまったく削除しないか、すべて削除することもできます。 これらの削除の後、結果として得られる文字列を回文にし、削除する文字数を最小限に抑えたいと考えています。 単一の文字を選択しても文字列を回文にできない場合は、それは不可能であると報告しなければなりません。 

重要な制約は、削除が非常に制限されていることです。 不一致の文字を自由に削除することはできません。 削除できるのは 1 つの固定文字のみです。 この制限により、問題は、1 つの文字タイプを「フィルタリングして除去」することによって文字列を回文に変換できるかどうかを確認することに変わります。 

入力サイズは、テスト ケースごとに最大 100,000 文字、合計で最大 200,000 文字に達します。 これにより、すべての文字およびすべての削除の組み合わせに対して、削除の選択肢と回文チェックを個別にシミュレートしようとするソリューションは即座に排除されます。 文字列を繰り返し再構築する単純なアプローチでは O(n * 26 * n) に達する可能性があり、これは許容限界をはるかに超えています。 

文字列がすでに回文である場合、微妙なエッジ ケースが発生します。 その場合、どの文字を選んでも答えはゼロになります。 もう 1 つの厄介な状況は、対称位置に不一致が存在するが、単一の文字タイプを削除するだけではすべてを解決できない場合に発生します。 たとえば、不一致のペアが 2 つの異なる文字を削除する必要がある場合、文字列が「ほぼ」対称に見えても、有効な解決策は存在しません。 

## アプローチ

 ブルートフォースのアイデアは簡単です。選択された削除文字として 26 個の可能な文字をそれぞれ試してみます。 選択肢ごとに、その文字をスキップして結果の文字列を構築し、残りの文字列が回文であるかどうかを確認します。 存在する場合は、実行された削除の数を数え、最小値を維持します。 

これは、許可された操作を直接シミュレートするため機能します。 ただし、各回文チェックは O(n) で、フィルター処理された文字列の構築も O(n) です。 これを 26 文字分繰り返すため、文字列構築を繰り返して不用意に実装すると複雑さは O(26 · n²) になり、最悪の実装パターンではチェックごとに O(26 · n²) になり、すべてのチェックで O(26 · n²) になります。 n が 10⁵ までの場合、これは不可能です。 

重要な点は、実際には候補文字ごとに文字列を再構築する必要がないということです。 代わりに、問題を制約付きの 2 点の回文チェックとして扱うことができます。不一致が見つかった場合、関係する 2 つの文字のうち 1 つを削除することでそれを「修正」する必要があり、その削除の選択はすべての不一致にわたって一貫していなければなりません。 これは、意味のある唯一の候補が、外側から最初の不一致に現れる 2 文字であることを意味します。 有効な解決策では、競合するペアからこれらの文字の 1 つを完全に削除する必要があります。そうしないと、対称性を回復できません。 

そこで、最初の不一致から得られる最大 2 つの候補文字をチェックするように問題を縮小し、その文字の出現をスキップする制約付き回文チェックをシミュレートします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(26 · n²) | O(n) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 文字列の両端からの 2 ポインター スキャンを使用します。

1. 2 つのポインタを左が 0、右が n − 1 に初期化します。文字が一致する限りそれらを内側に移動します。 これにより、すでに保持されているプレフィックスとサフィックスの対称性が検証されます。 
2. ポインタが交差する場合、その文字列はすでに回文であるため、削除する必要はありません。 
3. 左と右の位置で最初の不一致が見つかった場合、s[left] と s[right] の 2 つの文字の候補が得られます。 有効な解決策では、この不一致を解決するために、これら 2 つの文字のいずれかの出現をすべて削除する必要があります。 
4. 候補文字ごとに、その文字の出現をすべて無視する回文チェックをシミュレートします。 ここでも 2 つのポインターを使用し、選択した文字と同じ文字をスキップします。 
5. 1 文字スキップした後に文字列が回文になった場合は、元の文字列内のその文字の合計数から有効な回文形式に残っている出現数を引いたものとして、削除された文字の数を計算します。 
6. 2 つの候補から最小の結果を取得します。 どちらの候補も有効な回文を生成しない場合は、-1 を返します。 

候補を不一致ペアに制限する背後にある理由は、対称性が失われる最初の位置で、有効な解法において不一致の片側が完全に削除されることをすでに強制しているためです。 

### なぜ効果があるのか

 このアルゴリズムは、位置 l と r での回文の不一致は、無関係な文字を削除しても修正できないという事実に基づいています。 グローバルに削除できるのは 1 文字だけであるため、s[l] または s[r] の少なくとも 1 つをすべての関連する位置から削除する必要があります。 その文字が削除されると、文字列の残りの部分は 2 ポインター ペアの下ですでに構造的に一貫している必要があります。 これにより、成功した構成は 2 つの削除候補のいずれかに対応することが保証されるため、それらのみを確認するだけで十分であり、完全です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def check(s, ch):
    l, r = 0, len(s) - 1
    removed = 0
    while l < r:
        while l < r and s[l] == ch:
            l += 1
            removed += 1
        while l < r and s[r] == ch:
            r -= 1
            removed += 1
        if l >= r:
            break
        if s[l] != s[r]:
            return float('inf')
        l += 1
        r -= 1
    return removed

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()

        l, r = 0, n - 1
        while l < r and s[l] == s[r]:
            l += 1
            r -= 1

        if l >= r:
            print(0)
            continue

        c1, c2 = s[l], s[r]

        ans = min(check(s, c1), check(s, c2))
        print(-1 if ans == float('inf') else ans)

if __name__ == "__main__":
    solve()
```解決策は、最初の不一致を見つけることから始まり、これにより、考慮に値する 2 つの関連文字のみが特定されます。 ヘルパー関数`check`2 つのポインターを使用して回文チェックを維持しながら、選択した文字のすべての出現を削除することをシミュレートします。 の`removed`カウンタは必要な削除の数を追跡し、無効な構成はすぐに無限大を返します。 

主なロジックは、2 つの不一致文字のうち 1 つを削除すると、文字列の残りの部分は回文制約の下ですでに一貫している必要があるという事実に基づいています。 

## 実用的な例

 文字列を考えてみましょう`abcaacab`。 

まず、不一致が見つかるまで両端から比較します。 

| 左 | 右 | s[左] | s[右] | アクション |
 | --- | --- | --- | --- | --- |
 | 0 | 7 | | b | 不一致が止まる |

 候補者は、`a`そして`b`。 

のために`a`、すべてを削除します`a`文字の収量`bcaacb`、これは回文です。 削除数は4です。 

のために`b`、すべてを削除します`b`文字の収量`acaaca`、これも回文です。 必要な削除は 2 つです。 

最小値は 2 です。 

ここで考えてみましょう`khyyhhyhky`。 

不一致は最も外側の不一致で発生し、候補者を強制します`k`そして`y`。 

チェック中`k`すべてをスキップした後、削除すると一貫した回文が得られます。`k`文字を削除しながら`y`より多くの削除が必要ですが、それでも有効な回文構造が得られます。 アルゴリズムにより、実行可能な最小の削除数が選択されます。 

これらのトレースは、アルゴリズムが不必要な文字を決して探索せず、最初の構造的矛盾を直接解決する文字のみを探索していることを示しています。

 ## 特殊なケース

 文字列がすでに対称である場合、2 ポインター スキャンは不一致が発生することなく終了します。 アルゴリズムはすぐに 0 を返します。これは正しいことです。削除する必要がなく、どの文字を選択してもコストが増加するだけだからです。 

文字列の最後で不一致が発生した場合、次のようになります。`ab`、候補文字は次のとおりです。`a`そして`b`。 削除を試みるたびに単一文字の文字列が生成されますが、これは自明のことながら回文です。 アルゴリズムは、小さい方の削除コスト (どちらの場合も 1) を正確に返します。 

複数の不一致が文字列の深部に存在する場合でも、最初の不一致によって唯一の実行可能な削除候補が決定されます。 後の不一致に他の文字が関係している場合でも、有効な解決策は最初の競合をすでに解決している必要があるため、これら 2 つの文字に注意を限定するだけで十分であり、アルゴリズムは不可能なケースを正しく拒否します。
