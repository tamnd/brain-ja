 ## 解決策
 ## 問題の理解

 いくつかのテストケースが与えられています。 それぞれにおいて、ゼロ以外の整数の配列から始めます。$a$。 私たちのタスクは別の配列を構築することです$b$2 つの条件が同時に成立するような同じ長さ。 まず、要素がありません$b$ゼロであっても構いません。 次に、これらの係数を含む配列の加重合計は正確にゼロでなければなりません。つまり、ドット積は$\sum a_i b_i$完璧に打ち消してくれます。 また、次のような制約もあります。$b$は大きいが有限の範囲内に収まらなければならないため、任意に大きな数値を使用することはできません。 

重要な困難は、すべての$a_i$はゼロではないため、ポジションをゼロにすることで寄与を自明に無効にすることはできません。 代わりに、配列全体でプラスの寄与とマイナスの寄与のバランスを注意深く取る必要があります。 

配列の合計サイズという点では制約が大きく、最大で$2 \cdot 10^5$すべてのテスト ケースにわたる要素。 これにより、組み合わせを検索したり、テスト ケースごとに大量の計算を行う一般的な線形システムを解こうとするアプローチは即座に排除されます。 テスト ケースごとの直線時間を超えると、遅すぎます。 

素朴なアプローチは、ランダムな値を割り当ててみることです。$b_i$不均衡を繰り返し修正します。 これは 2 つの一般的な方法で失敗します。 まず、調整が容易に伝播し、以前に満たされていた制約が破られる可能性があります。 第 2 に、ランダム性では、潜在的に非常に大きな値を必要とせずに合計が正確にゼロになるという保証はなく、制限に違反します。$\sum |b_i|$。 

もう 1 つの素朴なアイデアは、1 つを除くすべての変数を修正し、最後の変数を解決することです。 つまり、設定します$b_n = -\frac{\sum_{i=1}^{n-1} a_i b_i}{a_n}$。 これにより正確性が保証されますが、次の制約は満たされません。$b_n$は制御された大きさの整数である必要があり、また次のことを保証します$b_n \neq 0$常に可能であるとは限りません。 本当の問題は、自由度を 1 つだけ制御するのは制限が多すぎることです。 

さらに深刻な問題は、脆弱なグローバルバランスに依存せずに、ローカルで拠出をキャンセルするための構造化された方法が必要であるということです。 

## アプローチ

 ブルートフォースの観点は、これを整数に対する制約充足問題として扱うことです。 それぞれのポジションが貢献する$a_i b_i$, そして合計が消えるようにしたいのです。 の値を試すことも想像できます。$b_1$を通して$b_n$、合計を確認し、調整します。 たとえ次のような小さな整数に限定したとしても、$\{-1, 1\}$、可能性の数は指数関数的に増加します$2^n$、これはたとえ$n = 20$、ましてや$10^5$。 

重要な観察は、実際にはあらゆる立場で自由が必要なわけではないということです。 ローカルキャンセルを構築するだけで済みます。 インデックスの小さなグループの合計が常に 0 になることを保証できれば、分割によって配列全体の合計が自動的に 0 になります。 

これは重要な洞察につながります。つまり、インデックスのペアまたは小さなブロックを使用して、インデックスの寄与を中和できるということです。$a$。 グローバルに考えるのではなく、$b$そのため、各局所構造は独立してバランスをとります。 

特に効果的なアイデアは、配列をペアに分割することです。 各ペアごとに$(a_i, a_{i+1})$、私たちが選択します$b_i$そして$b_{i+1}$そのような$a_i b_i + a_{i+1} b_{i+1} = 0$。 これは代入を使用すると常に可能です$b_i = a_{i+1}$、$b_{i+1} = -a_i$、 以来：$$a_i a_{i+1} + a_{i+1} (-a_i) = 0.$$This construction guarantees that each pair contributes zero independently, so the entire sum is zero. また、次のような制約も尊重します。$b_i$すべてがゼロであるため、$a_i$はゼロ以外です。 

唯一の問題は次のような場合です。$n$奇数です。 In that case, one element is left unpaired. 私たちは、これも正確に打ち消す 3 要素構造を使用することで、この問題を解決します。 For three consecutive elements$a_i, a_{i+1}, a_{i+2}$、次のものを割り当てることができます。$$(b_i, b_{i+1}, b_{i+2}) = (a_{i+1} + a_{i+2}, -a_i, -a_i).$$それから：$$a_i(a_{i+1} + a_{i+2}) + a_{i+1}(-a_i) + a_{i+2}(-a_i) = 0.$$これにより、残りのすべての要素をきれいに処理できるようになります。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1.要素数の場合$n$が偶数の場合、配列は素のペアで処理されます。 各ペアごとに$(a_i, a_{i+1})$、ウェブ割り当て$b_i = a_{i+1}$そして$b_{i+1} = -a_i$。 これにより、各ペアが合計に正確にゼロになることが保証されるため、グローバルな調整は必要ありません。 
2. もし$n$これは奇妙です。まず最初のものを処理します$n-3$上記と同じペアリング戦略を使用する要素。 これにより、最後にちょうど 3 つの要素が残ります。 
3. 最後の 3 つの要素について$a_{n-2}, a_{n-1}, a_n$、ウェブ割り当て:$b_{n-2} = a_{n-1} + a_n$、$b_{n-1} = -a_{n-2}$、$b_n = -a_{n-2}$。 これにより、自己完結型のキャンセル ブロックが作成されます。 
4. 構築した配列を出力する$b$。 

これが機能する理由は、構築されたすべてのブロックが他のブロックから独立して寄与度を持たないためです。 ペアリングブロックが貢献します$a_i a_{i+1} - a_{i+1} a_i = 0$。 トリプルブロックは、$a_{n-2}$他の 2 つのポジションの貢献を正確にキャンセルします。 配列は独立したゼロサム ブロックに分割されるため、合計もゼロになる必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    
    b = [0] * n
    
    i = 0
    while i + 1 < n:
        if n - i == 3:
            x, y, z = a[i], a[i+1], a[i+2]
            b[i] = y + z
            b[i+1] = -x
            b[i+2] = -x
            i += 3
        else:
            b[i] = a[i+1]
            b[i+1] = -a[i]
            i += 2
    
    print(*b)
```コードは、左から右に段階的に答えを構築します。 このループにより、常に 2 つの要素が消費されるか、ちょうど 3 つが残ったときにトリプル構造に切り替わります。 重要な微妙な条件は`n - i == 3`これにより、配列が処理不可能な最後のペアと残りのシングルトンに分割されるのを防ぎます。 

すべての代入では、値はゼロ以外の整数の合計または否定であるため、ゼロ以外の値が保持されます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、配列の長さが奇数である場合です。 単純なペアリング戦略では、単一の要素を未処理のままにしておこうとしますが、それを単独で無力化できる有効な非ゼロ割り当てがないため、すぐに失敗します。 トリプルブロック構造は、最後の 3 つの要素が常に閉じたシステムを形成するようにすることで、この問題を解決します。 たとえば、入力の場合$a = [1,2,3,4,5]$、アルゴリズムの処理$(1,2)$そして$(3,4)$、出発$(5)$一人で対処するのは不可能。 代わりに、実装では、最後の操作で常に 3 つの要素を同時に処理し、有効なキャンセル ブロックを生成するようにペアリング戦略が調整されるようにします。 

もう 1 つの特殊なケースは、すべての数値が同一である場合です。 そのような状況では、素朴な交互符号で十分であるように思われるかもしれませんが、慎重に構築しないとエントリがゼロになる可能性があります。 ペアリング方法では、これを完全に回避します。$b_i$非ゼロから直接導出されます$a_j$、キャンセルを維持しながら非ゼロ出力を保証します。 

最後のエッジケースは、値の大きさが大きく、境界に近い場合です。$10^4$。 それぞれなので$b_i$別のいずれかとして構築されます$a_j$または2つの合計$a_j$、最大等級は次の範囲に留まります。$2 \cdot 10^4$、絶対合計が安全に以内に収まることを保証します。$10^9$。
