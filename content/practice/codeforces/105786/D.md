 ## 解決策
 # 問題の理解

 このタスクは、ソートされたシーケンスに正確に挿入するのに十分な空の整数位置があるかどうかを維持することです。`k`新しい価値観。 元の配列は厳密に増加するはずですが、更新のたびに 1 つの要素が変更される可能性があるため、配列が一時的に無効になる可能性があります。 更新のたびに、挿入がまだ可能かどうかを判断する必要があります。 

2 つの隣接する値を考慮します`a[i]`そして`a[i+1]`。 それらの間に挿入される値は、厳密に より大きい整数である必要があります。`a[i]`そして厳密にそれよりも小さい`a[i+1]`。 このギャップで利用可能なポジションの数は次のとおりです。`a[i+1] - a[i] - 1`たとえば、`5`そして`10`、挿入可能な値は次のとおりです。`6, 7, 8, 9`、したがって、このギャップが寄与します`4`ポジション。 

挿入できる値の総数は、すべてのギャップ サイズの合計です。 答えは`YES`すべての隣接するペアが増加し、この合計容量が少なくとも`k`。 

この制約により、更新のたびにアレイ全体を再構築する必要がなくなります。 配列の長さと更新回数はそれぞれ次の値に達します。`2 * 10^5`。 数秒経つと、`O(nq)`ソリューションは次のように実行されます`4 * 10^10`可能なことをはるかに超えた操作。 各更新が一定数の値のみに影響を与えるようにする必要があります。 

単純な解決策を簡単に破ってしまうケースがいくつかあります。 

更新によって 2 つの隣接する値が等しくなった場合、配列は厳密には増加しなくなり、挿入によって元の順序を修復することはできなくなります。 

入力の場合:```
n = 3, k = 1
a = [1, 3, 5]
update: a[2] = 1
```配列は次のようになります`[1, 1, 5]`。 正しい出力は次のとおりです。```
NO
```空きポジションの数のみをチェックするソリューションでは、空きポジション間のギャップが誤ってカウントされてしまいます。`1`そして`5`そして答えるかもしれない`YES`。 

もう 1 つのエッジ ケースは、配列自体は有効なままであるにもかかわらず、すべてのギャップが小さすぎる場合です。 

入力の場合:```
n = 4, k = 5
a = [1, 2, 3, 4]
```すべてのギャップのサイズはゼロであるため、正しい出力は次のようになります。```
NO
```配列はすでに厳密に増加していますが、挿入できる整数がありません。 

最後の重要なケースは、`k = 0`。 追加の数値は必要ないため、厳密に増加する配列は許容されます。 

入力の場合:```
n = 3, k = 0
a = [10, 20, 30]
```正しい出力は次のとおりです。```
YES
```アルゴリズムは、少なくとも 1 つの利用可能なギャップを誤って要求してはなりません。 

# アプローチ

 直接的なアプローチでは、挿入プロセスをシミュレートします。 考えられるすべてのギャップを調べ、そこに収まる整数の数を数え、更新のたびにそれらの数を加算することができます。 これは正しいです。重要なのは、隣接する要素間の未使用の整数位置の合計数だけであるためです。 ただし、1 回の更新の後、すべてをスキャンすると、`n - 1`ギャップコスト`O(n)`。 と`q`更新すると、最悪のケースが発生します`O(nq)`が遅すぎます。 のために`n = q = 2 * 10^5`、これは約400億のギャップチェックです。 

重要な点は、ポイントの更新では、変更された位置に接するギャップのみが変更されるということです。 もし`a[i]`変更はペアのみ`(i-1, i)`そして`(i, i+1)`異なるギャップ サイズを持つことができます。 他のすべてのペアはまったく同じままです。 これにより、問題は 2 つの情報、つまりすべての隣接ペアが有効かどうか、およびすべてのギャップ容量の合計を維持することに変わります。 

無効な隣接ペアの数を保存できます。 総容量を次の合計として保存することもできます。`a[i+1] - a[i] - 1`有効に見えるすべての隣接ペアにわたって。 値が変更されると、影響を受けるギャップの古い寄与分が削除され、新しい寄与分が追加されます。 範囲クエリではなくグローバル合計のみが必要なため、フェンウィック ツリーやセグメント ツリーは不要です。 単純な累計で十分です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nq) | お(1) | 遅すぎる |
 | 最適 | O(n) 前処理後の O(q) | O(n) | 承認済み |

 # アルゴリズムのチュートリアル

 1. 初期配列を読み取り、すべての隣接するペアの寄与を計算します。 各ペアについて、左側の値が右側の値より小さいかどうかを確認します。 そうでない場合は、無効なペアの数を増やします。 それ以外の場合は、使用可能なギャップ サイズを合計容量に追加します。 
2. インデックスでの更新を処理する前`i`、影響を受ける可能性のある 2 つのギャップから古い情報を削除します。`i`そしてその後のギャップ`i`。 これは、古い値が答えに関与する唯一の場所です。 
3. 交換する`a[i]`新しい価値観で。 
4. 影響を受ける同じ 2 つのギャップに関する新しい情報を追加します。 新しい隣接ペアが無効な場合は、無効なカウンターを増やします。 それ以外の場合は、利用可能なポジションの新しい数を追加します。 
5. アップデート後、印刷します。`YES`無効な隣接ペアがなく、合計容量が少なくとも`k`。 それ以外の場合は印刷します`NO`。 

これが機能する理由: 値を挿入した後の最終配列は、元の値をソートされた順序で保持する必要があります。 隣接する元の値が増加していない場合、挿入された値はその矛盾を修正できません。 すべての隣接するペアが有効な場合、使用可能なすべての整数位置は 1 つのギャップにのみ属するため、ギャップ サイズの合計が挿入できる値の最大数となります。 条件`capacity >= k`必要かつ十分です。 

# Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n, k, q = map(int, input().split())
        a = list(map(int, input().split()))

        bad = 0
        space = 0

        def add_gap(i, sign):
            nonlocal bad, space
            if i < 0 or i + 1 >= n:
                return
            if a[i] >= a[i + 1]:
                bad += sign
            else:
                space += sign * (a[i + 1] - a[i] - 1)

        for i in range(n - 1):
            add_gap(i, 1)

        for _ in range(q):
            i, x = map(int, input().split())
            i -= 1

            add_gap(i - 1, -1)
            add_gap(i, -1)

            a[i] = x

            add_gap(i - 1, 1)
            add_gap(i, 1)

            if bad == 0 and space >= k:
                ans.append("YES")
            else:
                ans.append("NO")

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```ヘルパー関数`add_gap`1 つの隣接ペアの寄与を維持します。 の`sign`引数は、現在のコントリビューションを追加するか、更新前に古いコントリビューションを削除するかを決定します。 

初期化ループはすべてのギャップを 1 回処理します。 更新中、コードはインデックスのみに触れます。`i - 1`そして`i`変更された要素を含むギャップはこれらだけであるためです。 内部の境界確認`add_gap`無効な配列アクセスを作成せずに、最初または最後の要素への更新を処理します。 

カウンタは、おおよその値に達する整数として保存されます。`10^14`、配列値は次のような大きさになる可能性があるため、`10^9`そして多くのギャップが存在する可能性があります。 Python の整数はこれを自動的に処理しますが、固定サイズの整数を使用する言語では 64 ビット型が必要です。

 # エッジケース

 無効な注文の場合:```
3 1 1
1 3 5
2 1
```更新後の配列は次のようになります。`[1,1,5]`。 アルゴリズムはインデックスの周りの古いギャップを削除します`1`、新しいギャップを挿入し、最初のペアが無効であることを確認します。 無効なカウンタは次のようになります。`1`、結果は次のようになります`NO`。 

使用可能な挿入スロットがない場合:```
4 5 0
1 2 3 4
```配列は厳密に増加していますが、すべての違いは 1 つだけです。 それぞれのギャップが寄与する`0`なので、総容量は`0`。 以来`0 < 5`、アルゴリズムは戻ります`NO`。 

必要な挿入がゼロの場合:```
3 0 1
10 20 30
```総容量は関係ないので、`k`はゼロです。 唯一の要件は、無効なペアがないことです。 配列は厳密に増加しているため、アルゴリズムは次の値を返します。`YES`。
