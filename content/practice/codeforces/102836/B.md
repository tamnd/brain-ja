 ## 解決策
 ## 問題の理解

 固定容量のタンクが 3 つあります。 現在、各タンクにはある程度の量の液体が含まれており、3 つの量が必要な値と一致する最終的な状況に到達したいと考えていますが、タンクの順序は重要ではないため、必要な値は別のタンクに属している可能性があります。 

移動は、移動元のタンクと移動先のタンクを選択することで構成されます。 液体は、ソースが空になるか、デスティネーションが完全に満杯になるという 2 つのイベントのいずれかが起こるまで、ソースからデスティネーションに注がれます。 タスクは、必要なそのような注入の最小数を見つけること、または目標構成に到達できないことを報告することです。 

容量と量は次のように大きくできます。$10^6$, そのため、考えられるすべての金額の組み合わせをシミュレートすることは不可能です。 すべてのトリプルを直接検索するには、最大で次の時間がかかります。$(n_1+1)(n_2+1)(n_3+1)$州。 最大に近い容量では、これは約$10^{18}$これは、合理的な記憶や時間制限をはるかに超えています。 

主な制限は、タンクが 3 つしかないことです。 理論上の状態空間は巨大ですが、到達可能な状態の構造ははるかに小さくなります。 注ぐと、関係する 2 つのタンクのうち少なくとも 1 つが空になるか、満杯になります。 これは、最初の移動後、到達可能なすべての状態が、1 つの座標が 0 またはその容量のいずれかに固定される 6 つの「境界」面の 1 つに位置することを意味します。 液体の総量は一定であるため、これらの各表面には線形数の有用な状態のみが含まれます。 

不注意に実装すると、場合によっては失敗する可能性があります。 初期状態がすでに答えである場合、結果はゼロ手でなければなりません。```
Input:
5 7 9
1 3 4
4 1 3
```出力は次のとおりです。```
0
```移動の実行後に新しく生成された状態のみをチェックする BFS では、これが見逃されます。 

もう 1 つの罠は、ターゲットとなる戦車の順序が無関係であるという事実です。 例えば：```
Input:
10 5 3
7 1 2
1 3 6
```合計量は 10 なので、要求量の合計が 10 になるため目標自体は不可能ですが、1 つの要求タンク量がすべての一致を超えていますか? 正しい実装では、チェックだけを行うのではなく、ターゲット値のすべての順列と比較する必要があります。`(b1, b2, b3)`元の順序で。 

3 番目のエッジ ケースは、宛先がすでにいっぱいであるか、ソースがすでに空であるために、Pour によって何も変更されない場合です。```
Input:
5 5 5
5 0 0
5 0 0
```答えは次のとおりです。```
0
```これらの遷移を誤って生成すると、偽の状態が追加されたり、永久にループしたりする可能性があります。 

## アプローチ

 自然な最初の試みは、考えられるすべてのタンク充填物を対象に広範囲を優先して検索することです。 状態はトリプルです`(x, y, z)`各タンク内の現在の量を説明します。 状態から6方向の注ぎ方を試してみます。 BFS は正しいです。各遷移には 1 回の移動が必要となるため、最初に州を訪問したときに、その州に到達する最も短い一連の注ぎが見つかりました。 

問題は州の数です。 100万リットルの容量では、すべてのトリプルを保管することは不可能です。 ブルートフォース検索では、多くの不可能または不必要な状態が同様に重要なものとして扱われます。 

有益な観察は、注入の仕組みから得られます。 タンク A からタンク B に注ぐとします。A がゼロになるか、B が容量に達したときにのみ運転が停止します。 したがって、移動後のすべての状態には、境界値に少なくとも 1 つのタンクがあります。 検索空間は完全な 3 次元ボックスではありません。 これはいくつかの 2 次元表面の結合であり、液体の総量は決して変化しないため、各表面には線形数の状態のみが含まれます。 

ブルートフォース手法は、プロセスを正確にモデル化するため機能しますが、注入ルールによって作成された構造を無視するため失敗します。 BFS を境界プロパティとともに使用することにより、到達可能な州のみを訪問し、訪問される州の数は十分に少ないままになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n1 · n2 · n3) | O(n1 · n2 · n3) | 遅すぎる |
 | 到達可能な境界状態での最適な BFS | O(n1 + n2 + n3) | O(n1 + n2 + n3) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 容量、初期量、目標量を読み取ります。 ターゲットの順序は重要ではないため、後で順列をチェックすることによって、3 つの可能なターゲットの配置を暗黙的に保存します。 
2. BFS を開始する前に、初期状態がターゲットの順列の 1 つとすでに一致しているかどうかを確認します。 存在する場合、注ぐ必要がないため、答えはゼロです。 
3. BFSを初期状態から起動します。 訪問した各州を金額の 3 倍として保存します。 キューには常に、状態に到達するために必要な移動数の降順以外の順序で状態が含まれます。 
4. すべての状態について、各タンクから他の 2 つのタンクのそれぞれに注いでみてください。 タンクから注ぐ場合`i`タンクへ`j`、移動量を、利用可能な液体の小さい方として計算します。`i`そしてその中の空きスペース`j`。 
5. 結果として得られるすべての新しい状態を BFS キューに挿入します。 プロセスは履歴ではなく現在の量のみに依存するため、結果として得られる状態は将来を説明するのに十分です。 
6. 状態がターゲット量の順列に一致する場合、その BFS 距離を返します。 キューが空になると、一連の注入はターゲットに到達できないため、リターンします。`-1`。 

この検索が効率的である理由は、遷移ルール​​によって作成された不変条件です。 最初の状態を除くすべての状態には、少なくとも 1 つの空のタンクまたは満杯のタンクがあります。 有効な移動によって境界を作成できないため、BFS はこの到達可能な境界の外側の状態を探索する必要はありません。 

## なぜ機能するのか

 考えられるすべての注入シーケンスは、状態グラフ内のパスに対応します。 BFS はこのグラフをパスの長さの順に探索するため、初めてターゲット状態に到達するときの移動数は最小限になります。 

唯一の懸念は、縮小された状態空間で有効な答えが失われるかどうかです。 アルゴリズムは人為的に遷移を削除しないため、そうではありません。 検出されたすべての州からすべての合法的な注ぎを生成します。 境界プロパティは、検出された状態の数が管理可能なままである理由のみを説明します。 考えられるすべてのパスが依然として BFS グラフに表現されているため、答えは正しいままです。 

## Python ソリューション```python
import sys
from collections import deque
from itertools import permutations

input = sys.stdin.readline

def solve():
    n = list(map(int, input().split()))
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    targets = set(permutations(b))

    start = tuple(a)
    if start in targets:
        print(0)
        return

    q = deque([start])
    dist = {start: 0}

    while q:
        state = q.popleft()
        d = dist[state]

        for i in range(3):
            if state[i] == 0:
                continue
            for j in range(3):
                if i == j or state[j] == n[j]:
                    continue

                nxt = list(state)
                amount = min(nxt[i], n[j] - nxt[j])
                nxt[i] -= amount
                nxt[j] += amount
                nxt = tuple(nxt)

                if nxt in dist:
                    continue

                if nxt in targets:
                    print(d + 1)
                    return

                dist[nxt] = d + 1
                q.append(nxt)

    print(-1)

if __name__ == "__main__":
    solve()
```このソリューションでは、最初にすべての有効なターゲット状態のセットを構築します。 これは、物理的な戦車の順序が重要ではないという事実に対処します。 可能な順列の数は 6 つだけなので、このチェックは定数時間です。 

状態が疎であるため、BFS は個別の距離配列の代わりに辞書を使用します。 ディクショナリには、ある状態が訪問されたかどうかと、その状態に到達するまでに必要な手数の両方が保存されます。 

遷移計算は最も重要な実装の詳細です。 移動量は、移動元で利用可能な液体と移動先の残りの容量という 2 つの値によって制限されます。 これら 2 つの値の最小値を使用すると、問題の停止ルールが正確にモデル化されます。 

このコードは、新しい状態を生成した直後にターゲットをチェックします。 初期状態は遷移ループに入らないため、個別にチェックされます。 

## 実用的な例

## テストケース```python
import sys
import io
from collections import deque
from itertools import permutations

def solve(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)

    def input():
        return sys.stdin.readline

    read = input()
    n = list(map(int, read().split()))
    a = list(map(int, input()().split()))
    b = list(map(int, input()().split()))

    targets = set(permutations(b))

    start = tuple(a)
    if start in targets:
        ans = "0"
    else:
        q = deque([start])
        dist = {start: 0}
        ans = "-1"

        while q:
            state = q.popleft()
            d = dist[state]

            for i in range(3):
                for j in range(3):
                    if i == j:
                        continue
                    if state[i] == 0 or state[j] == n[j]:
                        continue

                    nxt = list(state)
                    move = min(nxt[i], n[j] - nxt[j])
                    nxt[i] -= move
                    nxt[j] += move
                    nxt = tuple(nxt)

                    if nxt in dist:
                        continue
                    if nxt in targets:
                        ans = str(d + 1)
                        q.clear()
                        break

                    dist[nxt] = d + 1
                    q.append(nxt)

    sys.stdin = old_stdin
    return ans

7 1 2
3 3 4
""") == "2"

assert solve("""10 5 3
0 5 3
0 5 3
""") == "0"

assert solve("""5 5 5
5 0 0
5 0 0
""") == "0"

assert solve("""1 1 1
1 0 0
0 1 0
""") == "1"

assert solve("""2 4 6
2 0 0
1 1 4
""") == "-1"

 | すでに解決された構成 | 0 | 初期状態検出 |

 ## 特殊なケース

 初期状態がすでに目標と一致している場合、BFS は移動する前に停止する必要があります。 例えば：```
5 5 5
5 0 0
5 0 0
```開始タプルはすでにターゲット順列の 1 つであるため、アルゴリズムはすぐに 0 を返します。 

ターゲット値を異なるタンクに配置できる場合、元の順序だけをチェックすると間違った答えが得られます。 例えば：```
10 5 3
7 1 2
4 3 3
```目標は次のように表すことができます。`(3, 3, 4)`したがって、アルゴリズムは、これら 3 つの値が任意の位置にある状態を受け入れます。 

タンクがすでに空または満杯の場合、一部の注入は無効になります。 例えば：```
5 5 5
5 0 0
0 5 0
```空の 2 番目のタンクから、またはすでに満杯の 1 番目のタンクに注ごうとすると、偽の動きが発生します。 遷移コードは、次の状態を計算する前にこれらのケースを拒否します。 

BFS は、状態をシステムの完全な記述として扱い、物理的に有効な注入のみを生成し、考えられるすべての最終調整をチェックするため、これらすべてのケースを処理します。
