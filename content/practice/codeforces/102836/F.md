 ## 解決策
 # 問題の理解

 このタスクは、英小文字で構成される文字列に関するものです。 文字を消去することはできますが、消去できる位置の数は指定された制限を超えることはできません。 目標は、文字列を短くすることではなく、表示される異なる文字の数をできるだけ少なくすることです。 残りの最小数の文字と、まさにその数の異なる文字を含む 1 つの可能なサブシーケンスを出力する必要があります。 

入力には、元の文字列と許可される削除の最大数が含まれます。 出力は、生き残ることができる個別の文字の最小数と、元の順序から文字を削除した結果の文字列が続きます。 

重要な制約は、文字列自体は大きくなる可能性があるにもかかわらず、アルファベットには 26 文字しか使用できないということです。 文字列の長さが約 100,000 の場合、考えられる多くの削除の組み合わせを試したり、すべての選択肢に対して答えを再構築したりする必要がなくなります。 線形時間で文字列を処理するアプローチが必要です。O(n) または O(n + アルファベットのサイズ) 程度のアルゴリズムは簡単に安全ですが、文字のサブセットや反復的なシミュレーションを伴うアプローチは急速に成長してしまうからです。 

いくつかの特殊なケースでは、不注意な実装が失敗する可能性があります。 すべての文字を削除できる場合、回答には個別の文字が含まれていない必要があります。 例えば：```
Input:
abc
5

Output:
0
```常に少なくとも 1 文字を保持するソリューションは、削除制限が文字列の長さよりも大きいため、ここでは失敗します。 

もう 1 つのケースは、文字が何度も表示され、完全に削除できない場合です。 例えば：```
Input:
aaaaa
4

Output:
1
aaaaa
```手紙`a`完全に削除するには 5 回の削除が必要となるため、そのままにしておく必要があります。 4 つの出現箇所を削除しても、個別の文字の数を減らすことはできません。 

最後によくある間違いは、最も安価な文字ではなく、任意の文字を削除することです。```
Input:
aabbbc
2

Output:
2
aabbb
```削除中`c`1 つの削除と削除を使用します`a`2 つの削除を使用します。 最良の選択は削除することです`c`第一に、最小のコストで個別の文字の数を減らすことができるからです。 1 つ削除する`b`代わりに、回答を減らすことなく削除を費やします。 

## アプローチ

 直接的な総当たりアプローチでは、どの文字が残っているかが考慮されます。 可能な文字は 26 個あるため、文字のすべてのサブセットを試して、許可された制限内で他のすべての文字を削除できるかどうかを確認することも考えられます。 これは正しいと考えられます。なぜなら、個別の文字の考えられるすべての最終セットが検査されるからです。 ただし、サブセットの数は 2^26 であり、文字列をチェックする前でも約 6,700 万通りの可能性があります。 これは、文字列処理と組み合わせると、妥当な範囲をはるかに超えています。 

重要なのはどの完全な文字グループが消えるかだけであるため、強引なアイデアは機能します。 探索できるグループが多すぎるため、失敗します。 重要な観察は、すべての文字が独立して寄与しているということです。 最終的な文字列から文字を削除するには、その文字の削除頻度を正確に費やす必要があります。 目標はできるだけ多くの異なる文字を削除することなので、最初に頻度が最も少ない文字に削除を費やす必要があります。 

26 文字の頻度を並べ替えた後、残りの削除予算が許す限り、文字全体を繰り返し削除できます。 削除できない文字は回答に残ります。 文字列を再度スキャンし、残った文字のみを保持することにより、元の文字の順序が保存されます。

 | --- | --- | --- | --- |
 | ブルートフォース | O(2^26 * n) | お(26) | 遅すぎる |
 | 最適 | O(n + 26 log 26) | お(26) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 文字列内に各小文字が何回出現するかを数えます。 頻度によって、その文字を完全に削除するために必要な正確な削除コストがわかります。 
2. 削除制限が文字列長以上の場合は、すべての文字を削除します。 最後の文字列は空で、個別の文字の数はゼロです。 
3. 文字を頻度の小さいものから大きいものの順に並べ替えます。 頻度が小さいほど、1 つの異なる文字全体をより安価に削除できることを意味します。 
4. この順序で文字にアクセスします。 現在のレターの頻度を残りの削除を使用して支払うことができる場合は、その頻度を予算から差し引いて削除します。 それ以外の場合は、最終セットに残します。 この貪欲な選択は正しいです。削除される文字ごとに個別の文字の数がちょうど 1 つ減るため、常に安価な削除を最初に行う必要があります。 
5. 元の文字列をスキャンし、文字が削除されていない文字のみを保持して、結果の文字列を構築します。 これにより、必要なサブシーケンス プロパティが保持されます。 

これが機能する理由: 回答から消えるすべての文字は、その出現箇所をすべて削除する必要があります。 文字を削除するコストは他のすべての文字から独立しており、その頻度に等しくなります。 貪欲なプロセスでは、最初に最も安価な削除可能な文字が選択されるため、プロセスが停止した後は、利用可能な以上の削除を費やすことなく残りの文字を削除することはできません。 より高価な文字を削除し、安価な取り外し可能な文字を残すという他の戦略は、これらの選択肢を交換することで改善できるため、貪欲な結果では個別の文字の数が可能な限り最小限になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    k = int(input())

    if k >= len(s):
        print(0)
        print()
        return

    freq = [0] * 26
    for c in s:
        freq[ord(c) - ord('a')] += 1

    removed = [False] * 26

    letters = sorted(range(26), key=lambda x: freq[x])

    for x in letters:
        if freq[x] <= k:
            k -= freq[x]
            removed[x] = True
        else:
            break

    ans = []
    for c in s:
        if not removed[ord(c) - ord('a')]:
            ans.append(c)

    print(len(set(ans)))
    print(''.join(ans))

if __name__ == "__main__":
    solve()
```最初の部分では、すべての文字が消える可能性がある特殊なケースを扱います。 これにより、削除予算が十分に大きい場合に、結果に不要な文字が残ることが回避されます。 

頻度配列にはアルファベットごとに 1 つの位置があるため、カウントには文字列を 1 回通過する必要があります。 26 個の要素だけを並べ替えると、実質的には一定時間になります。 

貪欲なループは、完全に削除できる文字をマークします。 の`removed`2 番目のスキャンではどの文字を保持するかを知る必要があるため、配列はこの決定を頻度とは別に保存します。 

最終スキャンでは、元の順序で回答が再構築されます。 部分的な削除では個別の文字の数は変更されず、問題では個別の文字の最小数のみが求められるため、残りの文字の個々の出現は削除されません。

 ## 特殊なケース

 削除制限が文字列より大きい場合:```
abc
5
```アルゴリズムチェック`k >= len(s)`すぐにゼロを返します。 このチェックを行わないと、後の貪欲なステップで文字が残る可能性があります。これは、頻度を反復する際にグループ全体の削除のみが考慮されるためです。 

単一の文字が繰り返される場合:```
aaaaa
4
```周波数配列には以下が含まれます`a = 5`。 貪欲ループは削除のコストを比較します。`a`利用可能な予算を考慮して削除を拒否します。 結果の文字列は変更されず、1 つの異なる文字を持ちます。 

競合する除去の選択肢については、次のとおりです。```
aabbbc
2
```周波数は次のとおりです。`a = 2`、`b = 3`、 そして`c = 1`。 アルゴリズムは以下を削除します`c`まず、1 つの削除を残します。 削除できません`a`残りの予算が少なすぎるため、最終的な個別の文字は`a`そして`b`。 利用可能な削除が最も安価な完全な削除に費やされたため、回答には可能な限り最小限の数の異なる文字が含まれています。
