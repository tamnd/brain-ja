 ## 解決策
 ## 問題の理解

 この問題は、次の目的で運営されている郵便局について説明しています。`n`分。 分の初めに`i`、`a[i]`クローンがキューに入ります。 その分の間、郵便局はせいぜいサービスを提供します`b`キューの先頭からクローンを追加します。 提供されたクローンは同じ分が終了すると退出します。 最後の 1 分を過ぎてもまだ待機しているクローンは、終了する前にさらに 1 分間滞在します。 課題は、すべてのクローンが郵便局内で費やした時間の合計を見つけることです。 

入力により、稼働時間 (分)、1 分あたりのサービス容量、および 1 分ごとに到着するクローンの数が得られます。 出力は、すべてのクローンを組み合わせた合計待機時間とサービス時間を表す 1 つの整数です。 分の先頭に入るクローン`i`そして残り1分で出発`i`1分貢献します。 

制限により、最大で許可されます`100000`分と到着カウントアップ`10^8`。 クローンの総数は次の数に達する可能性があるため、すべてのクローンを個別に処理するシミュレーションは不可能です。`10^13`。 すべてのクローンを保存したり、各クローンの残り時間を更新したりしても、実用的な制限を超えてしまいます。 このアルゴリズムは、現在キュー内にあるクローンの数のみを追跡することによって機能する必要があり、これにより線形の解決策が得られます。 

いくつかの詳細が誤った答えを引き起こす可能性があります。 よくある間違いは、稼働時間の最後の 1 分間に到着したクローンが、たとえ提供されなかったとしても、そこで時間を過ごしていることを忘れることです。 例えば：```
Input
1 10
5

Output
5
```5 つのクローンすべてがわずか 1 分間に入力され、すぐに提供されるため、それぞれに 1 分間かかります。 

もう 1 つの間違いは、閉店後の追加分を無視することです。 考慮する：```
Input
1 1
3

Output
5
```1 つのクローンが稼働時間中に提供され、1 分間かかります。 残りの 2 つのクローンは、稼働中に 1 分間屋内で過ごし、閉店後にさらに 1 分間滞在します。`1 + 2 + 2 = 5`。 

3 番目のエラーは、サービス後のキューのみをカウントすることです。 例えば：```
Input
2 100
3 4

Output
7
```1 分間に入るすべてのクローンは、たとえすぐに出て行ったとしても、その分に貢献します。 正しい合計は`3`最初の瞬間からそして`4`2分から。 

## アプローチ

 直接的なアプローチは、すべてのクローンをシミュレートすることです。 クローンが到着したら、それをキューに入れて分単位で移動し、最大で`b`クローンは毎分生成されます。 答えを計算するには、郵便局内に残っているすべてのクローンに 1 を追加します。 これは論理的には正しいです。各クローンは残り 1 分ごとにちょうど 1 分を提供するからです。 ただし、クローンの数は次のように大きくなる可能性があります。`10^13`したがって、すべてのクローンを 1 回通過するだけでも遅すぎます。 

重要な観察点は、キュー内で同じ位置にあるクローンは同じように動作するということです。 個々の身元を知る必要はなく、現在待機しているクローンの数だけを知る必要があります。 サービスの開始時に存在するクローンの数が 1 分ごとにあれば、その分にどれだけの時間が費やされたかを知るのに十分です。 この量を答えに追加した後、提供されるクローンの数だけキューを減らします。 

ブルート フォースはすべての寄与を個別に追跡するため機能しますが、オブジェクトの数が膨大であるため失敗します。 同じキュー状態にあるすべてのクローンが交換可能であるという観察により、現在のキュー サイズを表す 1 つの整数を維持するという問題が軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(クローン総数) | O(クローン総数) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 変数を保持する`queue`前の 1 分後に待機しているクローンの数を表し、保持します`answer`費やした時間の累計として。 
2. 1 分ごとに、到着したクローンをキューに追加します。 現在のキュー サイズは、ポスト オフィス内でこの 1 分を費やすすべてのクローンを表すため、これを`answer`。 
3. この 1 分間に提供されたクローンを削除します。 削除される数値は、現在のキュー サイズとサービス制限の小さい方です。`b`。 
4. すべての作業時間が処理された後、残りのキュー サイズをもう一度追加します。 これらのクローンは、閉じた後もさらに 1 分間保持されます。 

機能する理由: 稼働時間ごとに、現在内部にあるすべてのクローンがちょうど 1 分間貢献します。 アルゴリズムは、クローンが最後に離れるか待機し続けるかに関係なく、その分間に存在するクローンの数を正確に追加します。 最後の追加は、作業スケジュール外の唯一の時間間隔を処理します。 すべてのクローンの滞在全体がこれらのカウントされた間隔でカバーされるため、最終的な合計は正確になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, b = map(int, input().split())
    a = list(map(int, input().split()))

    queue = 0
    answer = 0

    for x in a:
        queue += x
        answer += queue
        queue -= min(queue, b)

    answer += queue
    print(answer)

if __name__ == "__main__":
    solve()
```変数`queue`クローンの総数への依存を回避し、未完成のクローンの数のみを保存します。 各反復の開始時に、サービスが開始される前に到着する到着客が追加されます。 

への追加`answer`提供されたクローンを削除する前に発生します。 すぐに提供されるクローンは依然として郵便局内で 1 分を費やすため、この順序は重要です。 削除後に追加を移動すると、そのようなクローンがすべて失われます。 

サービスステップで使用されるのは、`min(queue, b)`なぜなら、郵便局は現在待機している以上のクローンを提供できないからです。 Python の整数は、考えられる大きな答えを自動的に処理します。これは、合計時間が 32 ビット整数の制限よりはるかに大きくなる可能性があるため、必要です。

 ## 特殊なケース

 郵便局がクローンを残して閉店した場合:```
Input
1 1
3
```アルゴリズムは空のキューから始まります。 到着者 3 人を追加すると、キューが 3 人になり、解答に 3 分が追加されます。 1 つのクローンが提供され、2 つが残ります。 すべての作業時間が経過すると、アルゴリズムによって残りの 2 分が追加されます。 結果は`5`、必要な動作と一致します。 

すべてのクローンがすぐに提供される場合:```
Input
3 100
5 5 5
```前のキューは空であるため、各分は新しい到着者のみから始まります。 アルゴリズムは追加します`5`3 回実行し、毎回すべてのクローンを削除します。 誰も残っていないため、最後の延長戦は追加されません。 

到着がない場合：```
Input
2 10
0 0
```シミュレーション中、キューはゼロのままです。 時間をカウントする必要があるクローンがないため、答えはゼロのままです。 

サービス制限が到着よりも小さい場合:```
Input
3 2
5 0 0
```最初の 1 分が経過すると、3 つのクローンが残ります。 2 分目と 3 分目はそれぞれ、サービス前の既存のキューをカウントします。 終了後、1 つのクローンが残り、最後の瞬間に貢献します。 アルゴリズムはサービスを適用する前に常に現在のキューをカウントするため、これを自然に処理します。
