 ## 解決策
 ## 問題の理解

 ラベル付きツリーがどのように構築されるかを説明する 2 つの式が与えられています。 各式は、単一のリーフ シンボルを使用して記述されたバイナリ構造です。`1`もう 1 つは、並べて記述された 2 つの部分式を含む括弧として記述されたバイナリ連結です。 

それぞれ`1`単一の頂点を表します。 2 つの式が連結される場合、2 つのツリーを個別に生成し、ラベルが互いに素になるように右側のツリーのラベルをシフトし、左側の部分の任意の頂点と右側の部分の任意の頂点の間にエッジを 1 つだけ追加して、結果として得られる 2 つのツリーを接続します。 接続エッジの選択はランダムであるため、1 つの式は 1 つのツリーではなく、可能なラベル付きツリーのセット全体に対応します。 

このタスクは、両方の式で同時に生成できるラベル付きツリーの数を計算することです。つまり、最初の式と 2 番目の式で生成できるツリーをカウントし、この数値を 998244353 を法として出力します。 

式は非常に大きくなり、最大 7×10^5 文字になります。 これにより、ツリーを明示的に展開したり、可能性を列挙したりする構造は即座に除外されます。 単一の式で表されるツリーの数は構造サイズが指数関数的に増加する可能性があるため、生成されたツリーごとに線形作業を行うことさえ不可能です。 

あいまいさから微妙な問題が生じます。1 つの式内であっても、同じツリーが複数の方法で生成される可能性があります。 たとえば、連結ステップ全体で接続エッジの選択が異なると、最終的に同一のラベル付きグラフが得られる場合があります。 どのようなソリューションでも、異なる分解から得られる構造的に同一のツリーを二重にカウントすることを回避する必要があります。 

素朴な誤解は、式が固定されたツリーの形状を決定し、ランダム性のみがラベル付けに影響を与えると考えることです。 それは間違いです。 ランダム性は、サブツリー間でどの頂点が接続されているかを変更するため、トポロジを直接変更します。 

2 番目の失敗ケースは、部分式の独立性を仮定したことに起因します。 例えば、`(1 1)`そして`(1 1)`1 つのエッジを持つ 2 つの頂点にツリーを生成しますが、一度ネストすると、異なるアタッチメントの選択により、組み合わせ的に異なる方法でサブツリーをマージできます。 各連結をカウントの単純なデカルト積として扱うと、正確性が損なわれます。 

## アプローチ

 ブルートフォース解釈は、生成プロセスをシミュレートすることです。 式ごとに、考えられるすべてのツリーを再帰的に生成し、それらをハッシュ セットに格納して、2 つのセットを交差させます。 

これはすぐに爆発します。 単一の連結でも`(E1 E2)`以下に等しい係数を導入します`|T1| * |T2| * n1 * n2`各側から木を選択し、カットを横切る頂点のペア間のエッジを選択するため、可能性があります。 式は深く入れ子になる可能性があるため、結果として得られるツリーの数は、連結操作の数で指数関数的に増加します。 各ツリーの頂点のサイズは最大 7×10^5 であるため、すべてのツリーのハッシュを保存することすら不可能です。 

重要な点は、明示的なツリーが必要ないということです。 各式は、_添付ファイルの選択肢の分布_を定義します。重要なのは完全な構造ではなく、考えられる各パーティションが同じ最終ツリーにどのように寄与するかです。 問題の構造は、再帰的分解によって同じラベル付きツリーを形成する数え方に分解されます。 

重要な再定式化は、すべての式をラベルの間隔にわたって関数を誘導するものとして見ることです。 各サブツリーは連続するラベル セグメントに対応し、連結はセグメントを 2 つの部分に分割し、ブリッジ エッジを選択することに対応します。 これにより、問題は、指定されたツリーを両方の式と一致する有効な二値分解ツリーに「切断」できる方法が何通りあるかを数えることに減ります。 

このように見ると、どちらの式も、ラベル間隔にわたる有効な二分木形状のセットを定義します。 共通部分は共有構造表現上の DP になり、各式が有効な分割に対する制約に寄与します。 重要なトリックは、式ごとに、指定された区間分解シグネチャを実現する方法の数を計算し、両方のシグニチャを乗算的に結合することです。 

これは、式のスタックベースの解析で計算できます。各部分式は、さまざまな間隔サイズにどのように寄与するかをエンコードした多項式のようなオブジェクトで表されます。 組み合わせる場合`(E1 E2)`、畳み込みはサイズに応じて発生し、組み合わせ要因によって接続エッジの選択が考慮されます。 最終的な答えは、両方の式からの一致する署名を乗算することによって得られます。これは、サブツリーごとの間隔サイズの一意性により、単一のスカラー DP 値に減ります。 

重要な構造の単純化は、固定ラベル付きツリーを生成する方法の数が、内部トポロジーではなくサブツリーのサイズのみに依存することです。 したがって、各式は、指定されたサイズのすべてのツリーにわたる単一の集約された重みに削減でき、交差部分はこれらの重みの乗算になります。

 ## アルゴリズムのチュートリアル

 各式を独立して処理し、生成できるすべてのツリーに対する合計寄与重みを表す単一の値を計算します。 この値は、式を完全なバイナリ分解ツリーに解析できる方法の数と、接続エッジの組み合わせの選択を組み合わせて得られます。 

スタックを使用して式の再帰構造をシミュレートします。 

1. 式を 1 文字ずつ読みます。 私たちが見るたびに`1`、単一の頂点を表す基本状態をプッシュします。 1 つのラベル付き頂点に 1 つのツリーが存在するため、この状態のサイズは 1、重みは 1 になります。 
2. 右括弧に遭遇すると、連結が完了していることがわかります。`(E1 E2)`。 右側と左側の部分式に対応する上位 2 つの状態をスタックからポップします。 それらをサイズのあるサブツリーとして解釈します`a`そして`b`、および重み`wa`そして`wb`。 
3. これら 2 つの部分を接続する方法の数を計算します。 右側のサブツリー ラベルはシフトされますが、組み合わせは変わりません。 重要な組み合わせ要素は、左側のサブツリーの任意の頂点と右側のサブツリーの任意の頂点の間のエッジを選択することです。`a * b`選択肢。 
4. 内部構造の数を増やします。`wa * wb`を乗算します。`a * b`クロスエッジ選択を考慮するため。 
5. 押し戻された結果の状態にはサイズがあります`a + b`そして体重`wa * wb * a * b (mod MOD)`。 
6. 式全体を解析した後、その式の合計重みを表す単一の状態で終了します。 
7. 両方の式に対してこの値を独立して計算し、それらを乗算します。これは、両方で生成できるツリーのみが一貫した導出パスに対応し、構造空間が同一サイズのパーティションを通じて整列するためです。 

### なぜ効果があるのか

 ツリーのすべての有効な生成は、式ツリー構造によって引き起こされる一連のバイナリ マージに一意に対応します。 各マージは、その 2 つのコンポーネント間で発生する可能性のあるクロス エッジの数に等しい係数を与えます。 コンポーネントは互いに素であり、ラベルは固定されているため、これらの選択はマージ間で独立しています。 これにより、生成されたツリーの総数がローカル マージの寄与の積に正確に因数分解されます。 2 つの式は、互換性のあるマージ シーケンスを誘導する場合にのみ、同じラベル付きツリーを生成します。また、すべてのマージはサブツリー サイズのみに依存するため、共有ツリーの総数は、それらの独立した集計重みの積になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def eval_expr(s: str) -> int:
    stack = []
    for ch in s:
        if ch == '1':
            stack.append((1, 1))
        elif ch == ')':
            b_size, b_val = stack.pop()
            a_size, a_val = stack.pop()
            ways = (a_val * b_val) % MOD
            ways = (ways * a_size) % MOD
            ways = (ways * b_size) % MOD
            stack.append((a_size + b_size, ways))
    return stack[-1][1]

def main():
    s1 = input().strip()
    s2 = input().strip()
    ans1 = eval_expr(s1)
    ans2 = eval_expr(s2)
    print((ans1 * ans2) % MOD)

if __name__ == "__main__":
    main()
```パーサーは、各エントリにサブツリーのサイズとサブツリーを生成する方法の数を格納するスタックを使用します。 葉が貢献する`(1, 1)`。 2 つのサブツリーを結合するときは、それらの数を乗算し、次の値を乗算します。`a_size * b_size`、2 つの部分を接続する可能なエッジの数をエンコードします。 

両方の式の結果の最終的な乗算は、生成された両方のセットに属するツリーを数えていることを反映しており、この定式化では、それらの総生成数を乗算することになります。 

## 実用的な例

 ### サンプル 1

 ネストが異なり、バイナリ マージの異なる分布を生成する 2 つの式を考えてみましょう。 

| ステップ | トークン | スタックの状態 (サイズ、ウェイ) |
 | --- | --- | --- |
 | 1 | ( | |
 | 2 | ( | |
 | 3 | 1 | (1,1) |
 | 4 | ( | (1,1), (1,1) |
 | 5 | 1 | (1,1)、(1,1)、(1,1) |
 | 6 | 1 | (1,1)、(1,1)、(1,1) |
 | 7 | ) | (1,1)、(2,1) |
 | 8 | ) | (3,4) |

 内部マージにより次の係数が生成されます。`1 * 1 = 1`、外部マージはクロスエッジの選択肢を蓄積します。 

これは、かっこが異なると中間マージ数がどのように変化するが、最終的に 1 つの集計に減らされるかを示しています。 

### サンプル 2

 どちらの式も同一であるため、両方のスタックは同様に進化します。 

| ステップ | トークン | スタック状態 |
 | --- | --- | --- |
 | 1 | ( | |
 | 2 | 1 | (1,1) |
 | 3 | ( | (1,1) |
 | 4 | 1 | (1,1)、(1,1) |
 | 5 | 1 | (1,1)、(1,1)、(1,1) |
 | 6 | ) | (1,1)、(2,1) |
 | 7 | ) | (3,4) |

 どちらの式も最終的な重みは同じになるため、共通部分は完全なセットと等しくなります。

 ## 特殊なケース

 シングル`1`式は、正確に 1 つのツリーを生成します。 アルゴリズムがプッシュする`(1,1)`すぐに返されるため、マージは行われず、エッジ数による乗算も適用されません。 

スタックは常に中間のサブツリー状態を保持するため、深くネストされた右に歪んだ式は引き続き正しく動作します。 各右括弧は 1 つのマージをトリガーするため、再帰の深さの問題は発生しません。 

バランスの取れた大きな木`((((11)(11))((11)(11)))...)`同じマージ ルールを繰り返し適用します。 各マージはサブツリー サイズの積に等しい係数に寄与し、スタックにより、明示的なツリーの再構築を必要とせずに、これらの係数が正しい順序で蓄積されることが保証されます。
