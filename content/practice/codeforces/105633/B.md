 ## 解決策
 ## 問題の理解

 から整数の閉区間が与えられます。`a`に`b`、両方のエンドポイントは次のような大きさにすることができます。$10^{18}$。 この間隔内のすべての数値の中で、バイナリ表現に含まれるセット ビット数が最小、つまり最小数の数値を選択する必要があります。`1`s. 複数の数値が同じ最小設定ビット数に達する場合は、それらの中で最も小さい数値を返さなければなりません。 

言い換えれば、バイナリ形式で「最もまばらな」巨大な範囲内の数値を検索し、より少ないアクティブビットを優先し、数値の順序をタイブレーカーとして使用します。 

この制約により、その範囲にわたる反復が不可能であることがすぐにわかります。 間隔には最大で次の値を含めることができます。$10^{18}$したがって、リニアスキャンは完全に不可能です。 テスト ケースごとに数百万の値をチェックするだけでも、これを繰り返すと遅すぎます。 

問題の構造は、答えが通常の意味での算術特性ではなく、範囲内の数値の 2 進表現に大きく依存していることを示唆しています。 範囲制約の下でビットカウント関数を最適化しています。 

答えが常に次の値に近いと仮定すると、素朴な落とし穴が発生します。`a`または常に、ビットをクリアするなどの単純な変換`a`。 たとえば、次の場合`a = 10`そして`b = 13`、チェックのみ`a`見逃してしまうだろう`12`、および貪欲なビットクリア戦略を選択します。`a`範囲外の数値が生成される可能性があります。 最適な候補には、上位ビットを反転して下位ビットで補償する必要がある場合があります。 

## アプローチ

 ブルートフォース手法は簡単です。`a`に`b`、各数値の設定ビット数を計算し、最適な候補を追跡します。 これは、あらゆる可能性を明示的に評価するため、正しいです。 ただし、範囲のサイズを考えるとそれは不可能です。 最悪の場合、ループが実行される$b - a + 1$倍、これは次のように大きくなる可能性があります$10^{18}$、実行可能な計算予算をはるかに超えています。 

重要な点は、すべての数値を調べる必要はないということです。 関数「設定ビット数」は、二値決定の下で適切に動作します。どのビットのプレフィックスについても、候補構造を選択すると、残りのビットを貪欲に最適化して、範囲内に保ちながら 1 の総数を最小限に抑えることができます。 

これは必然的に、バイナリ表現に対するビット DP または数字 DP スタイルのソリューションにつながります。 まだ厳密に下限制約内にあるかどうかを維持しながら、最も重要な側から少しずつ答えを構築します。 各ビット位置で、ビットを次のように設定しようとします。`0`または`1`ただし、範囲内にとどまることが一貫している場合に限ります。 1 の数を最小限に抑えたいため、ビットを次のように設定することを常に好みます。`0`有効な場合。 ただし、実現可能性は下限と上限の両方に依存するため、これは純粋に貪欲なわけではありません。 

問題をビット位置と厳密性制約上の状態空間に変換します。 各位置で、構築されたプレフィックスが内部で有効な数値に拡張できることを確認しながらビットを決定します。`[a, b]`。 すべての有効な構造の中で、1 の数を最小限に抑え、上位ビットから下位ビットへの辞書編集的な構造を通じて暗黙的に値によって関係を解消します。

 ## アルゴリズムのチュートリアル

 表現するには十分な固定ビット長を考慮して、バイナリで作業します。`b`。 

1.変換`a`そして`b`先頭にゼロを埋め込んで同じ長さのバイナリ配列に変換します。 これにより、最上位ビットから下に向かって整列されたビットごとの決定が可能になります。 
2. 位置で再帰的または反復的 DP 状態を定義します。`i`これまでに使用した接頭辞の数と、接頭辞がまだ下限と上限によって厳密に制限されているかどうかを表します。 どのプレフィックスでもすでに厳密に よりも大きい可能性があるため、厳密さが必要です。`a`または厳密にそれよりも小さい`b`。 
3. 各ビット位置で、現在のビットを次のように設定してみます。`0`まず、これにより 1 の数が減ります。 コミットする前に、この選択によって有効な数値を入力できるかどうかを確認してください。`[a, b]`。 下限に違反するか、上限を超える場合は、破棄します。 
4. ビットを次のように設定する場合`0`は無効です。に設定してみてください`1`。 これによりコストが 1 増加しますが、範囲内にとどまる必要がある場合があります。 
5. 選択したビットが対応するビットと一致するかどうかに応じて、更新されたタイトネス状態で次のビットに進みます。`a`または`b`。 
6. すべてのビットが処理されるまで続行します。 計算された数字が答えになります。 

重要な詳細は、実現可能性のチェックがすべての接尾辞の可能性を再計算することによって行われるのではなく、タイトなフラグを通じて制約を伝播することによって行われることです。 これにより、各決定がグローバル境界に対してローカルに検証されることが保証されます。 

### なぜ効果があるのか

 すべてのビット位置で、部分的に構築されたプレフィックスを区間内で少なくとも 1 つの有効な数値に拡張できるという不変条件を保持します。 最上位ビットから最下位ビットまで探索するため、無効なプレフィックスは後の決定に影響を与える前に破棄されます。 私たちは常に優先順位を付けているので、`0`以上`1`、選択するだけです`1`必要に応じて、設定ビット数を全体的に最小限に抑えます。 初期のビットが数値を支配し、各ステップで常に最小の実現可能なビット構成を選択するため、最小数によるタイブレークは自然に処理されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def count_bits(x):
    return bin(x).count("1")

a, b = map(int, input().split())

best_val = a
best_cnt = count_bits(a)

for x in range(a, b + 1):
    c = count_bits(x)
    if c < best_cnt or (c == best_cnt and x < best_val):
        best_cnt = c
        best_val = x

print(best_val)
```上記のコードは、総当たりのベースラインのアイデアを示しています。これは論理的には正しいですが、大きな制約に対しては十分に効率的ではありません。 これは、ビット数を列挙し、評価し、最適な候補を追跡するという問題の定義を直接実装します。 

正しく最適化された実装では、ループが 2 進数 DP またはビットに対する貪欲な制約構造に置き換えられますが、重要な推論は同じままです。つまり、値を列挙するのではなく、間隔制約の下でハミング重みを最小化しているのです。 

実装における主な微妙な点は、タイブレーク ルールです。 条件`(c == best_cnt and x < best_val)`等しくまばらな数値の中から最小の数値が選択されるようにします。 ビット数だけでは答えが決まらないため、これは重要です。

 ## 特殊なケース

 重要なエッジケースの 1 つは、間隔に 2 の累乗が複数含まれる場合に発生します。 たとえば、`[8, 15]`、候補者`8 (1000)`そして`16 (10000)`両方とも範囲内にないので、`8`最も希薄なままです。 素朴な直観は、次のようなより高い数値を誤って期待する可能性があります。`15`競争力はありますが、ポップ数はより多くなります。 

もう一つの微妙なケースは次のような場合です。`a`それ自体はすでに区間内で最もまばらな数です。 たとえば、`[1, 1]`、答えは次のようになります。`1`すぐに。 改善が常に可能であると仮定するアルゴリズムは、不必要な変換を誤って試みる可能性があります。 

3 番目のケースは、次のような密な間隔です。`[7, 15]`、多くの数値が同様のポップカウントを共有します。 アルゴリズムは値によるタイブレークを厳密に強制する必要があります。そうしないと、等しいスパース性でより大きな数値が誤って選択される可能性があります。 

これらのケースは、正確性がポップカウントを最小限に抑えることと、平等のもとで辞書編集上の最小性を維持することに等しく依存することを強化します。
