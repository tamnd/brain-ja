 ## アルゴリズムのチュートリアル

3.セット$dp[n+1] = 0$、最後の要素を超えると処理するものが何もないためです。

5. 次に、考えられるすべてのセグメントを検討します$[i, j]$から始まる$i$。 プレフィックス合計を使用して合計を計算します。 もし$(\text{sum} - r) \ge 0$で割り切れる$d$、有効な乗数を取得します。$k$。 その場合、このセグメントを獲得して収益を得ることができます。$k$、から続く$j+1$、貢献$k + dp[j+1]$。

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, d, r = map(int, input().split())
    a = list(map(int, input().split()))

    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + a[i]

    def get_sum(l, r_):
        return pref[r_ + 1] - pref[l]

    dp = [0] * (n + 2)

    for i in range(n, 0, -1):
        best = dp[i + 1]

        for j in range(i, n + 1):
            s = get_sum(i - 1, j - 1)
            if s >= r and (s - r) % d == 0:
                k = (s - r) // d
                best = max(best, k + dp[j + 1])

        dp[i] = best

    print(dp[1])

if __name__ == "__main__":
    solve()
```この実装は DP 定義を直接翻訳したものです。 プレフィックス合計配列を使用すると、定数時間のサブ配列合計計算が可能になります。これは、二重ループの実行可能性を維持するために重要です。 内側のループは、各位置から始まるセグメントの可能なすべてのエンドポイントを列挙します。 

微妙な点は、スキップトランジションが含まれていることです。`dp[i + 1]`これにより、その位置でセグメントを開始しないオプションを正しくモデル化できます。$i$。 これがないと、すべての位置が誤って何らかのセグメントに属することを強制されてしまいます。 

## 実用的な例

 次のサンプルを考えてみましょう。$n = 5$、$d = 5$、$r = 1$、配列は$[2, 2, 2, 4, 4]$。 

サフィックス DP 値を右から左に計算します。 各位置で、有効なセグメントをスキップするか取得するかを決定します。 

| 私 | 選択されたセグメント [i, j] | 合計 | k | dp[j+1] | 最高の dp[i] |
 | --- | --- | --- | --- | --- | --- |
 | 5 | [5,5] | 4 | 無効 | - | 0 |
 | 4 | [4,4] | 4 | 無効 | - | 0 |
 | 3 | [3,4] | 6 | 1 | dp[5]=0 | 1 |

 このトレースは、$[1,3]$そしてその後$[3,4]$構造は複数の寄与をもたらしますが、時期尚早な選択は将来のセグメントを妨げることになります。 

ここで、初期セグメントが大きいとさらなる利益が得られない可能性がある 2 番目のサンプルのアイデアを考えてみましょう。 配列の大部分を消費するセグメントを取得した場合、追加の有効なセグメントを抽出するためのサフィックスが残っていないため、将来の dp 寄与は消滅します。 

これは、高い即時性とのトレードオフを示しています。$k$そして将来の構造を保存します。

 ## 特殊なケース

 重要なエッジ ケースは、必要なモジュラー形式を満たすサブアレイがない場合に発生します。 その状況では、すべての DP 状態はすぐにスキップに戻り、サフィックス全体にゼロを伝播する必要があります。 遷移の更新がないため、アルゴリズムはこれを自然に処理します。`best`超えて`dp[i+1]`。

3 番目の微妙なケースは、有効なセグメントが重なり合う場合です。 各状態は現在のインデックスから始まるセグメントのみを考慮し、重複する選択肢は将来の状態遷移によって暗黙的に解決され、削除されたインデックスの無効な再利用が保証されないため、DP はこれを正しく処理します。
