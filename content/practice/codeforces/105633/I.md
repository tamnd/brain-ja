 ## 解決策
 ## 問題の理解

 正の整数の配列と複数のクエリが与えられ、各クエリはその配列の連続セグメントを指定します。 各セグメントについて、概念的にはその中の個別のインデックスのすべてのペアを考慮し、2 つの対応する値の gcd を計算します。 これらすべてのペアごとの gcd 値の中で、可能な最大値が必要です。 

タスクを読み取るもう 1 つの方法は、サブ配列の場合、そのサブ配列から選択された 2 つの異なる要素の gcd として表示できる最大の整数が必要であるということです。 どのペアがそれを達成するかを出力するように求められるのではなく、値のみを出力するように求められます。 

この制約により、各クエリ内のペアを検査するアプローチから遠ざけられます。 n が 100000 まで、q が 100000 までの場合、単一の最悪の場合の間隔でもすでに約 5e9 ペアが含まれるため、クエリごとに直接 O(length²) スキャンを行うことは実現不可能です。 クエリあたり O(n) であっても境界線に達するため、ソリューションではクエリ全体で構造を再利用するか、グローバルな関係を事前計算する必要があります。 

微妙なエッジ ケースは、セグメント内のすべての要素が等しい場合です。 その場合、すべてのペアの gcd はその値に等しいため、答えはその値になります。 もう 1 つのコーナーは、すべての値が個別の素数である場合です。 すると、すべてのペアの gcd が 1 になるため、答えは 1 になります。ペアは間隔内で任意であるため、gcd 構造が隣接性または順序に依存すると仮定するアプローチはここでは失敗します。 

## アプローチ

 ブルート フォース ビューは定義から始まります。クエリ間隔ごとに、すべてのペア (i, j) を列挙し、gcd(a[i], a[j]) を計算し、最大値を取得します。 これは問題の定義に直接従うため、正しいです。 問題はペアの数であり、間隔サイズでは二次関数になります。 サイズ 100000 の最悪の場合の間隔では、これは 5e9 gcd の計算になり、それぞれの計算自体は自明ではなく、時間制限をはるかに超えます。 

改善するには、視点を逆転させることが重要です。 最適なペアを求める代わりに、間隔内のペアの gcd としてどのような値が表示されるかを尋ねます。 数値 x は、区間内に x で割り切れる要素が少なくとも 2 つ存在する場合に限り、2 つの値の gcd になります。 そのようなすべての x の中で、最大のものを求めます。 

これにより、問題は割り算に関する頻度の問題に変換されます。各候補値 x について、指定された範囲内の要素の数が x で割り切れるかを知る必要があります。 少なくとも 2 つあれば、x が可能です。 次に、クエリごとに実現可能な最大の x が必要になります。 

値の制約 (ai ≤ 100000) は重要です。 これらを使用すると、maxA までのすべての x について、x の倍数の位置を間接的に事前計算したり、前処理された構造を使用して倍数にわたるカウントを維持したりすることが可能になります。 次に、各クエリは候補 x を降順でチェックすることになりますが、クエリごとに単純に実行すると、やはり時間がかかりすぎます。 

標準的な最適化では、x ごとに、x で割り切れる要素が出現する位置のソート済みリストを事前計算し、二分探索によって範囲頻度クエリに応答します。 ただし、クエリごとにすべての x を反復処理すると、最悪の場合でも依然として大きすぎます。 

より効率的な構造は、クエリをオフラインで処理し、各 x について、それが回答候補となり得るすべての区間を計算することですが、より単純な競技プログラミング ソリューションは、実際の出現ごとに値をグループ化し、ふるいのような累積を使用してカウントを約数に伝播し、範囲カウントのデータ構造を維持できるという事実に依存しています。 

実際的なアプローチは、a[i] が x で割り切れるすべてのインデックス i を格納する配列 pos[x] を構築することです。 次に、クエリ [l, r] の場合、pos[x] で少なくとも 2 つのインデックスが [l, r] に存在するような最大の x を見つける必要があります。 これは、pos[x] の二分探索によって確認できます。

次に、x を maxA から下方向に反復し、各 x についてクエリの実行可能性をチェックしますが、代わりに役割を逆転させます。つまり、各 x に候補クエリのリストを割り当ててそれらを処理するか、Mo のようなチェックまたはバケット化されたチェックを使用します。 制約が与えられた場合、目的の解決策は通常、すべての倍数の出現を事前計算し、事前計算された次の出現構造または除数に対するセグメント ツリーを介してクエリの回答を得る方法ですが、最もクリーンな概念的な解決策は、位置リストの二分探索を使用して x をオフラインでチェックすることです。 

中心的な考え方は、可分性構造がペアの列挙を置き換え、範囲周波数がペアごとの gcd 計算を置き換えるということです。

 | 約数の位置リスト + 二分探索 | O((n + q) · sqrt(A) · log n) | O(n · sqrt(A)) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、配列の最大値までのすべての値 x について、x で割り切れる要素が出現するインデックスのリストを事前計算します。 これは、配列の位置を反復して値ごとにその除数を生成することによって、または x を反復してふるいスタイルのループを通じて倍数をマークすることによって行われます。 

これらのリストが存在すると、gcd が x 以上であるペアは両方の要素が x で割り切れなければならないため、各リストは x が gcd ペアに寄与する可能性があるすべての位置を表します。 

各クエリ [l, r] について、最大の x から最小の x まで候補の回答をテストします。 指定された x について、pos[x] の少なくとも 2 つの要素が [l, r] 内にあるかどうかを確認する必要があります。 これは二分探索を使用して行われます。最初の位置 ≥ l および最初の位置 > r を見つけ、その中にいくつあるかを測定します。 

条件を満たす最初の x を (降順で) 返します。 

### なぜ効果があるのか

 x が何らかのペア (i, j) の gcd である場合、a[i] と a[j] は両方とも x で割り切れます。これは、両方のインデックスが pos[x] に出現する必要があることを意味します。 逆に、pos[x] にクエリ区間内に少なくとも 2 つの要素が含まれている場合、その区間には x で割り切れる 2 つの値が存在し、それらの gcd は少なくとも x であり、x が候補の答えとして実現可能であることを意味します。 降順で検索するため、最初の有効な x がすべてのペアの中で可能な最大の gcd であることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXA = 100000

def build_positions(a):
    n = len(a)
    pos = [[] for _ in range(MAXA + 1)]
    for i, v in enumerate(a, start=1):
        # enumerate divisors of v
        d = 1
        while d * d <= v:
            if v % d == 0:
                pos[d].append(i)
                if d * d != v:
                    pos[v // d].append(i)
            d += 1
    return pos

def count_in_range(lst, l, r):
    # first index >= l
    lo, hi = 0, len(lst)
    while lo < hi:
        mid = (lo + hi) // 2
        if lst[mid] < l:
            lo = mid + 1
        else:
            hi = mid
    left = lo

    lo, hi = 0, len(lst)
    while lo < hi:
        mid = (lo + hi) // 2
        if lst[mid] <= r:
            lo = mid + 1
        else:
            hi = mid
    right = lo

    return right - left

def main():
    n = int(input())
    a = list(map(int, input().split()))
    q = int(input())

    pos = build_positions(a)

    queries = [tuple(map(int, input().split())) for _ in range(q)]

    # answer queries
    res = []
    for l, r in queries:
        ans = 1
        # try all possible gcd values descending
        for x in range(MAXA, 0, -1):
            lst = pos[x]
            if len(lst) < 2:
                continue
            if count_in_range(lst, l, r) >= 2:
                ans = x
                break
        res.append(str(ans))

    print("\n".join(res))

if __name__ == "__main__":
    main()
```コードは、各除数値の位置のリストを作成することから始まります。 各配列要素はその値のすべての約数に寄与し、すべての潜在的な gcd 候補が互換性のある形式で出現する場所の記録を保持するようにします。 

の`count_in_range`この関数は、並べ替えられたリストに対して 2 つのバイナリ検索を実行して、クエリ間隔内に含まれる有効な位置の数を計算します。 これは、ソートされた位置リストを範囲頻度クエリに変換する標準的な方法です。 

メイン ループは各クエリを独立して評価し、候補となる gcd 値を最大から最小までスキャンします。 間隔内に少なくとも 2 回出現する最初の値がすぐに返されます。 

微妙な点は、gcd 候補は両方の要素を除算する必要があるため、生の値を保存するのではなく、除数の位置を保存することです。 これにより、gcd がいずれかの要素よりも小さい場合の欠落が回避されます。 

## 実用的な例

 配列 (10、20、30、40、50、60) と完全な間隔 [1、6] を考えてみましょう。 

大きな約数が少なくとも 2 回出現するかどうかに焦点を当てます。 

| × | pos[x] 内の位置 | [1,6] でカウント | 有効 |
 | --- | --- | --- | --- |
 | 60 | [6] | 1 | いいえ |
 | 30 | [3、6] | 2 | はい |
 | 20 | [2、4] | 2 | はい |
 | 10 | [1、2、3、4、5、6] | 6 | はい |

 スキャンでは最初に 30 が検出されるため、答えは 30 になります。これは、gcd(30, 60) が達成可能な最大のペア gcd であるという考えと一致します。 

次に、配列 (13、2、35、4、13、2、5、1、7、4) とクエリ [1, 4] を考えてみましょう。 

約数の候補を確認します。 

| × | 間隔内の位置 | カウント | 結果 |
 | --- | --- | --- | --- |
 | 35 | [3] | 1 | いいえ |
 | 13 | [1] | 1 | いいえ |
 | 7 | [3] | 1 | いいえ |
 | 5 | [3] | 1 | いいえ |
 | 4 | [2、4] | 2 | はい |

 最初に見つかった有効な値は 4 なので、答えは 4 です。これは、大きな公約数が存在しない場合、アルゴリズムが自然に小さな gcd にフォールバックすることを示しています。

 ## 特殊なケース

 重大なエッジ ケースは、最大値が間隔内で 1 回だけ発生する場合です。 たとえば、最大の数値が 100000 であるが 1 回しか出現しない間隔では、アルゴリズムはその数値を正しく拒否します。`pos[100000]`サイズは 1 です。その後、少なくとも 2 回出現する値が見つかるまで下方向に進みます。 

もう 1 つのケースは、最適な gcd が値 [6、10、15] などの個々の要素よりもはるかに小さい場合です。 配列に 5 が現れていなくても、最適なペア gcd は (10, 15) からの 5 です。 前処理中に 10 と 15 の両方が寄与するため、除数ベースの位置リストは 5 を正しく捕捉します。そのため、アルゴリズムは依然として間隔内の 2 つの出現を識別します。
