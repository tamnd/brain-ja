 ## 解決策
 ## 問題の理解

 候補となる方向指示のない道路で接続された一連の都市が与えられています。 各都市には、その重要性を表す重みがあります。 これらの都市のうち、都市 1 は首都の横浜です。 すべての都市にわたって接続された構造を形成する道路のサブセットを選択する必要があります。この構造はツリーでなければなりません。これは、任意の 2 つの都市間には 1 つの単純な経路が存在することを意味します。 

各道路には脆弱性の値があります。 選択した木の道路が破壊されると、その木は 2 つのコンポーネントに分割されます。 一部の都市は首都から切り離されます。 そのイベントの被害は、都市 1 への接続を失ったすべての都市の重要度の値の合計です。各道路のリスク寄与は、この被害にその脆弱性を乗算したもので、合計リスクは、選択されたすべての木の端の合計になります。 

タスクは、この全体的なリスクを最小限に抑えるスパニング ツリーを構築することです。 

n は最大 100,000、m は最大 300,000 であるため、この制約により、候補エッジの数はほぼ線形または n log n の解に近づきます。エッジごとの削除をシミュレートしたり、接続性を繰り返し再計算しようとするアプローチは、最悪の場合少なくとも O(nm) の動作につながるため、遅すぎます。 

微妙な点は、エッジの「ダメージ」は、最終ツリーのエッジのどちら側に首都が含まれるかによって決まることです。 これにより、エッジのコストがローカルの重みだけでなくグローバル構造に依存するようになります。 

単純な間違いは、qj または p ベースのヒューリスティックに等しい重みを持つ最小スパニング ツリーを選択できると考えることです。 これは失敗します。コストは頂点ごとまたはエッジごとに個別に加算されないためです。 それはルートに対するサブツリーの合計に依存します。 

たとえば、p = [1, 100, 100] の単純なチェーン 1 - 2 - 3 を考えてみましょう。 エッジ (2,3) が切断された場合、ノード 3 のみが失われますが、構造が異なっていれば、同じエッジからより大きな合計が分離される可能性があります。 この依存関係を無視する単純な MST は、ルートベースのパーティショニングに関係なく同じ構造を選択しますが、これは正しくありません。 

もう 1 つの落とし穴は、早期に比重の高い都市を貪欲に接続できると想定していることです。 ノードのコスト寄与は、ノードが各エッジ カットの首都側にあるかどうかによって決まり、これは完全なツリーが構築された後にのみ決定されます。 

## アプローチ

 主な問題点は、各エッジがそのエッジの片側、具体的にはエッジが削除されたときに資本から切断される側のノードの重みの合計に比例するコストに寄与することです。 

ツリーを修正すると、エッジごとにツリーが 2 つのコンポーネントに分割されます。 エッジ e について、ノード 1 を含まないコンポーネントの p 値の総和を S とします。エッジは S * q_e に寄与します。 

ブルート フォース アプローチでは、すべてのスパニング ツリーを列挙し、それぞれのサブツリーの合計を計算し、総コストを評価します。 スパニング ツリーの数は指数関数的であり、1 つのツリーを評価するだけでも O(n) となるため、これは実行不可能です。 

重要な観察は、ノードの寄与を分離する方法でコストを再解釈することです。 各エッジがサブツリーを削除することを考える代わりに、視点を逆にします。ルート以外の各ノードは、ツリー内のちょうど 1 つのエッジによってルートから分離されます。 そのエッジはまさにノードをルートから「保護」するものです。 そのエッジが削除されると、ノードは切断されるため、そのエッジがそのノードの重みを負担します。 

これは、二重の観点を示唆しています。各ノードの重みは、ノードからルートまでのパスに沿って課金されますが、選択したツリー内のそのパス上の最大の脆弱性エッジを介してのみ課金されます。これは、そのエッジが障害シナリオで実際に最初にノードを切断するためです。 

形式的には、ノード v の場合、その寄与は、選択されたツリー内の 1 から v までの一意のパス上の最大エッジ脆弱性の p[v] 倍になります。 これにより、問題は、p[v] にパス最大制約を掛けたノードの合計を最小化するという問題に変換されます。

この構造は、逆クラスカル プロセスの古典的なものです。パス上の脆弱性の高いエッジによって重みが増大するため、重みの高いノードができるだけ早く脆弱性の低いエッジを介して接続されるようにノードを接続したいと考えています。 

qの昇順にエッジを処理します。 当社は DSU を保守しています。 エッジが 2 つのコンポーネントを接続する場合、1 つのコンポーネント内のすべてのノードが最大 q の脆弱性エッジを通ってルートに到達すると事実上判断することになります。 増分コストは、ルートを含むコンポーネントに新たに接続されるノードの p 値の合計の q 倍です。 

すべてを暗黙的にノード 1 にルートすることで正確性を保証します。ノードが最初にノード 1 のコンポーネントに接続される時期だけを考慮します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべてのツリーを列挙する | 指数 | O(n) | 遅すぎる |
 | DSU + ルート コンポーネント トラッキングを備えた Kruskal | O(m log m α(n)) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのエッジを脆弱性の順に並べ替えます。q. これにより、コンポーネントを接続する最も安価な方法を常に最初に検討することができます。 
2. 各都市が独自のコンポーネントである DSU を初期化します。 各コンポーネントが首都 (ノード 1) に接続されているかどうかを示すフラグを維持します。 
3. 各 DSU セット内の p 値の合計であるコンポーネントの重みの合計も維持します。 
4. 最初は、ノード 1 を含むコンポーネントのみが首都に接続されているとしてマークされます。 
5. ソートされた順序でエッジを処理します。 各エッジ (u、v、q) について、その DSU 代表を見つけます。 
6. u と v がすでに同じコンポーネント内にある場合は、接続性やコストに影響を与えないため、スキップします。 
7. 2 つのコンポーネントのうちの 1 つが首都に接続されている場合、それらをマージすると、以前は到達できなかった 1 つのコンポーネントが到達可能になります。 コストは、資本にまだ接続されていないコンポーネントの合計 p-sum を乗算した q だけ増加します。 
8. 2 つの DSU コンポーネントをマージし、それらの p 値の合計を更新し、どちらかの側が接続されている場合は、結果のコンポーネントを資本に接続されているとしてマークします。 
9. すべてのエッジが処理されるまで続行します。 累積コストが答えです。 

ステップ 7 の背後にある理由は、新しいコンポーネントが脆弱性 q のエッジを介してルートに接続されると、接続の時点でそのエッジがノード 1 からそのコンポーネント内のすべてのノードへのパス上で最も高い脆弱性になるということです。 したがって、そのコンポーネント内の各ノードは、正確に q * p[v] を 1 回だけ支払います。 

### なぜ効果があるのか

 各ノードは、q 増加プロセスでノード 1 を含むコンポーネントに最初に接続された瞬間に 1 回だけ貢献します。 その時点で、接続を可能にしたエッジは、この構造と一致する有効なツリー内のルートへの最終的なパス上で最大の脆弱性エッジになります。 エッジは非降順で処理されるため、すでに接続されているノードのこのボトルネックを後続のエッジで置き換えることはできません。 これにより、増加する接続時間へのノードの分割が作成され、各ノードの重みは正しい制限エッジ値で 1 回だけチャージされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def find(parent, x):
    while parent[x] != x:
        parent[x] = parent[parent[x]]
        x = parent[x]
    return x

def union(parent, size, comp_sum, connected, a, b):
    ra = find(parent, a)
    rb = find(parent, b)
    if ra == rb:
        return ra

    if size[ra] < size[rb]:
        ra, rb = rb, ra

    parent[rb] = ra
    size[ra] += size[rb]
    comp_sum[ra] += comp_sum[rb]
    connected[ra] = connected[ra] or connected[rb]
    return ra

def solve():
    n, m = map(int, input().split())
    p = list(map(int, input().split()))

    edges = []
    for _ in range(m):
        u, v, q = map(int, input().split())
        edges.append((q, u - 1, v - 1))

    edges.sort()

    parent = list(range(n))
    size = [1] * n
    comp_sum = p[:]
    connected = [False] * n
    connected[0] = True

    ans = 0

    for q, u, v in edges:
        ru = find(parent, u)
        rv = find(parent, v)
        if ru == rv:
            continue

        if connected[ru] and not connected[rv]:
            ans += q * comp_sum[rv]
        elif connected[rv] and not connected[ru]:
            ans += q * comp_sum[ru]

        union(parent, size, comp_sum, connected, ru, rv)

    print(ans)

if __name__ == "__main__":
    solve()
```この実装は、コンポーネントごとに 3 つの情報 (ランク別結合のサイズ、重要度値の合計、資本コンポーネントに既に接続されているかどうか) を追跡する DSU に依存しています。 重要な決定は、コンポーネントをマージする前に行われます。正確に一方の側が首都に接続されている場合、反対側全体が新たに到達可能になり、その合計の重みに現在のエッジの脆弱性を乗じた金額が請求されます。 

実装の微妙な詳細は、結合演算の前に代表ルートを計算する必要があることです。そうしないと、「すでに接続されている」コンポーネントと「まだ接続されていない」コンポーネントの区別が失われます。

 ### サンプル 1

 入力:```
3 3
1 2 3
1 2 2
2 3 3
1 3 4
```エッジを q: (1,2,2)、(2,3,3)、(1,3,4) でソートします。 

DSU の状態を追跡します。 

| ステップ | エッジ | コンポーネント (ルート セット) | 接続されたセット | アクション | 追加コスト |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 1-2,2 | {1}、{2}、{3} | {1} | 1 と 2 をマージすると、新しいコンポーネントが接続されます。 2 * 2 = 4 |
 | 2 | 2-3,3 | {1,2}、{3} | {1,2} | 3 とマージすると、3 が接続されます | 3 * 3 = 9 |
 | 3 | 1-3,4 | すべて接続されています | すべて接続されています | 無視 | 0 |

 合計は13です。 

このトレースは、各ノードが最初に首都から到達可能になったときに 1 回だけ寄与し、その時点のエッジの重みが制限要因であることを示しています。

 ## 特殊なケース

 エッジ ケースの 1 つは、コンポーネントが完全に形成されているものの、かなり後のエッジまで首都に直接接続されない場合です。 この状況では、コンポーネントがノード 1 の到達可能なセットにまだ含まれていないため、すべての内部マージはコストを生成しません。アルゴリズムは、ルート コンポーネントへの最初のブリッジが表示されるまで課金を正しく遅延させ、その時点で累積合計全体が 1 回課金されます。 

複数のコンポーネントが同じ脆弱性レベルで資本に接続する場合、別のエッジ ケースが発生します。 エッジは減少しない順序で処理されるため、各マージは新しくアタッチされたコンポーネントのコストを独立してトリガーします。また、各ノードは最初のアタッチ時に 1 回だけ課金されるため、等しい q エッジ間の順序は重要ではありません。 

最後のケースは、グラフがほぼ完成しているにもかかわらず、エッジが 1 つだけ欠けているだけで初期の接続が妨げられる場合です。 DSU は、冗長エッジが異なるコンポーネントをマージすることがないため、中間サイクルがコストに影響を与えないことを保証し、二重カウントを防ぎます。
