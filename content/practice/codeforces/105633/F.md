 ## 解決策
 ## 問題の理解

 私たちは長方形の箱の隅に立っていて、その表面に沿ってのみ移動することができ、内部を通ることはできません。 その開始コーナーから、最短のサーフェス距離という点で可能な限り遠いサーフェス上のポイントが必要です。 

主な問題は、2 つの表面点間の最短経路が 3D 空間では必ずしも直線ではないことです。 代わりに、サーフェスの一部を平面に展開した後にのみ、直線のように動作します。 ボックスを「開く」さまざまな方法により、さまざまな平面レイアウトが作成され、レイアウトごとに、到達可能な最も遠い点の異なる候補が生成される場合があります。 

入力により、ボックスの 3 つの辺の長さが得られます。 出力は単一の実数、つまり開始頂点からサーフェス上の任意の点までのサーフェスに沿った可能な最大測地線距離です。 

制約は小さく、各次元は最大 100 であるため、任意の一定数の幾何学的構成を直接テストできます。 これは、解決策が最適化トリックに関するものではなく、展開候補の有限セットを特定し、それらを浮動小数点で注意深く評価することであることをすぐに示唆しています。 

素朴な推論でよくある失敗例は、最も遠い点が常にボックスの反対側の頂点 (内対角に対応する) であると仮定することです。 もう 1 つの誤った仮定は、展開される 1 つの面だけが重要であるということです。 どちらも、最短経路が最も遠い点に到達する前に 2 つ以上の面を迂回する構成をミスします。 

誤解を招く具体的な例としては、$1 \times 1 \times 2$箱。 反対側の頂点に対する直線空間の対角線は次のようになります。$\sqrt{6}$ただし、実際の最も遠い表面点には距離があります$\sqrt{65/8}$、それよりも大きいです。 これは、最適なパスが立方体の内部ジオメトリの端点に制約されないことを示しています。 

## アプローチ

 強引なアイデアは、サーフェス上のターゲット ポイントを選択し、最初からサーフェスに沿った最短パスを計算し、それを最大化することを想像することです。 原則として、表面上のすべての点は面ごとにパラメータ化でき、関連する面を平面に展開することで測地線距離を計算できます。 

各面には連続した 2D 領域が導入され、各領域ではパスがどのエッジと交差するかに応じて複数の展開トポロジを考慮する必要があるため、これはすぐに実行不可能になります。 「興味深い」点の有限セットに制限することさえ、構造がなければ自明ではありません。 

重要な観察は、多面体表面の平面への有効な展開では、多面体表面上の最短経路は常に直線であるということです。 直方体の角からは、少数の展開トポロジーのみが問題になります。これは、最短経路が目的地に到達するまでに通過できる面はせいぜい数個であるためです。 ボックスの場合、関連する展開は、2 つの隣接する面が平らに置かれて長方形を形成し、パスがその長方形を横切る直線になる構成になります。 

このような展開ごとに最遠点の候補が生成され、その展開における最遠点は、結果として得られる平面形状の原点から最も遠い角にすぎません。 

この解決策は、直方体のエッジのペアから導出される一定数の幾何学的表現を評価することに帰着します。

 ## アルゴリズムのチュートリアル

 1. 開始頂点をサーフェス上の動きの原点として扱い、サーフェスを平面に展開するという観点から考えます。 それぞれの有効な展開は、最短のサーフェス パスが直線セグメントになるように特定のエッジに沿って切断することに対応します。 
2. 隣接する 2 つの面を一度に展開することを検討します。 このような各選択により、サーフェスが平らになって長方形になり、1 つの次元は 2 つのエッジの合計であり、もう 1 つの次元は残りのエッジになります。 これにより、次の形式の候補二乗距離が生成されます。$(x+y)^2 + z^2$。 
3. どの 2 つの面が一緒に展開されるかに応じて、任意のエッジのペアを組み合わせることができるため、3 次元のすべての順列に対してこれを繰り返します。 
4. 3 つの二乗距離の候補を計算します。$(a+b)^2 + c^2$、$(a+c)^2 + b^2$、$(b+c)^2 + a^2$。 
5. これらの値の最大値を取得します。それぞれが有効な展開、つまり有効な最短パス ジオメトリに対応するためです。 
6. 最大値の平方根を出力します。 

これが機能する理由は、開始頂点から表面点までの最短パスが、歪みなく平面に平坦化できる一連の面上に存在する必要があるためです。 直方体の場合、原点からの距離を最大化するシーケンスは、3 次元を直交に保ちながら 2 つのエッジ方向を 1 つの直線平面軸に結合することによって取得されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    a, b, c = map(float, input().split())

    ans2 = 0.0
    ans2 = max(ans2, (a + b) ** 2 + c ** 2)
    ans2 = max(ans2, (a + c) ** 2 + b ** 2)
    ans2 = max(ans2, (b + c) ** 2 + a ** 2)

    print(ans2 ** 0.5)

if __name__ == "__main__":
    solve()
```コードは展開推論を直接実装します。 各式は、展開平面内の同じ直線方向に沿って配置される 2 つのボックスの寸法のうち、3 番目のボックスの寸法が垂直のままであることを選択することに対応します。 

すべての演算は大きさが多項式 (入力は最大 100) であり、必要な精度は十分に倍精度の範囲内であるため、浮動小数点演算の使用は安全です。 

## 実用的な例

 ### 例 1:$1 \times 1 \times 2$私たちはすべての候補者を評価します。 

| 展開の選択 | 計算 | 値 |
 | --- | --- | --- |
 | (a+b、c) | (1+1)^2 + 2^2 | 8 |
 | (a+c, b) | (1+2)^2 + 1^2 | 10 |
 | (b+c, a) | (1+2)^2 + 1^2 | 10 |

 最大二乗値は 10 なので、結果は次のようになります。$\sqrt{10}$。 

これは、長さ 2 のエッジをユニット エッジの 1 つと一緒に展開することに対応し、平らな構成で最長の直線リーチが生成されます。 

### 例 2:$10 \times 10 \times 10$| 展開の選択 | 計算 | 値 |
 | --- | --- | --- |
 | (a+b、c) | 20^2 + 10^2 | 500 |
 | (a+c, b) | 20^2 + 10^2 | 500 |
 | (b+c, a) | 20^2 + 10^2 | 500 |

 すべての構成は対称であるため、結果は次のようになります。$\sqrt{500} = 10\sqrt{5}$。 

これは、すべての次元が等しい場合、すべての展開が同じように動作することを示しています。

import sys, io

def run(inp: str) -> str:

               (a + c) ** 2 + b ** 2,

 ## 特殊なケース

 最も微妙なエッジ ケースは、2 つの次元が等しく、3 番目の次元が小さい場合です。 このような場合、複数の展開によって同様の値が生成されるため、浮動小数点のタイブレークが正確さに影響を及ぼしてはなりません。 

入力用`1 1 2`、3 つの式は次のとおりです。$$(1+1)^2 + 2^2 = 8,\quad (1+2)^2 + 1^2 = 10,\quad (1+2)^2 + 1^2 = 10$$アルゴリズムは 10 を選択し、$\sqrt{10}$。 すべての候補が同じ数値スケール内にあるため、計算は安定したままになります。 

もう 1 つのエッジケースは、1 つの次元が大幅に大きい場合です。`100 2 3`。 支配的な項は最大のエッジを含む合計となり、正しい展開により最長寸法が自然に平面軸の 1 つと整列し、特別な処理を必要とせずに二乗距離が最大化されます。
