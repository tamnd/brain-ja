 ## 解決策
 ## 問題の理解

 溶液の入った容器がいくつか与えられます。 各容器には一定量の液体が入っていますが、液体の各単位内の溶解物質の量は正確にはわかりません。 代わりに、コンテナ i の場合、液体の単位あたりの濃度は 2 つの境界の間のどこかにあり、真の値がその範囲内に収まることが保証されます。 

液体の総量の合計が固定値 s に達する限り、これらの容器から任意の割合で注ぐことができます。 不確実性は広がります。混合後の溶解物質の総量は単一の数値ではなく、各容器の隠れた濃度が許容範囲内でどのように判明するかに応じて一定の範囲になります。 

達成したい溶解物質の目標量もあります。 不確実性があるため、正確にヒットすることを保証することはできません。 代わりに、各容器から採取する量を決定すると、実際に取得する物質の量は一定の間隔内にあり、その間隔と目標値の間の最悪の絶対差として誤差を測定します。 

タスクは、この最悪の場合の偏差が可能な限り小さくなるように各コンテナから取り出す液体の量を選択し、その最小の偏差を縮小分数として出力することです。 

この制約は、 を n 個のコンテナ間で分割するすべての方法を単純に列挙することは不可能であることを示唆しています。 部分割り当てのスペースは連続しており、n は最大 1000 になる可能性があるため、完全な分布を保存しても、直接検索するには大きすぎます。 

さらに微妙な点は、不確実性は確率的な動作ではなく、固定された範囲内での敵対的な選択に依存するということです。 これにより、問題は確率論的な問題ではなく、線形関数に関する最適化問題に変わります。 

一般的な失敗例は、各コンテナが個別に最悪のエラーの原因となっていると想定した場合に発生します。 たとえば、単一の容器からすべての液体を取り出し、その偏差を可能な限り最大にすることは、混合により範囲の平均化によって不確実性が低減されるため、最適ではありません。 

もう 1 つの間違いは、上限と下限が同じ混合物から得られるものであることを強制せずに、別々に扱うことです。 「最良のケース」と「最悪のケース」が結びついていることが、問題を自明ではないものにしています。 

## アプローチ

 直接的なブルートフォース解釈では、摂取する液体の量を表す実数値 xi を各コンテナに割り当てようとします (合計 xi = s)。 割り当てごとに、線形結合を通じて間隔の不確実性を伝播することにより、考えられる最悪の偏差を計算します。 xi を離散化したとしても、状態の数は、離散化の粒度に応じて、n とともに指数関数的に増加するか、非常に大きな指数で多項式的に増加します。 これは 2 秒で実行できる速度をはるかに超えています。 

重要な構造的観察は、液体の量と物質の量の両方が、選択された変数において線形であるということです。 xi がコンテナ i から採取された量である場合、物質の合計は、区間にある係数を持つ xi の線形結合です。 これにより、結果として得られる可能性のある物質の量が、端点が xi の一次関数となる区間に変わります。 

したがって、xi を固定して選択した場合、結果は常に区間 [L(x), R(x)] となり、誤差はこの区間がターゲットからどれだけ離れているかによってのみ決まります。 これにより、問題は、その点の線形変換が固定値にできるだけ近くなるように、高次元シンプレックス内の点を選択することに変換されます。 

2 番目の縮小により、ジオメトリが簡素化されます。 ペア (L(x), R(x)) は、ペア (li, ri) の凸組み合わせのみに依存します。 総質量で正規化した後、すべての解はこれらのペアの凸包内の点に対応します。 実現可能条件は、その凸包にわたる線形不等式になります。

その時点で、問題は、ターゲット ラインの周りの対称偏差を最小限に抑えるという追加の目的を伴う 2 次元の凸の実現可能性問題になります。 シンプレックス上の線形プログラムの最適解は極端な構造で発生するため、最大 2 つのコンテナーの組み合わせについて推論するだけで十分です。 これにより、連続的な高次元検索が平面内の線分のチェックに軽減されます。 

次に、許容誤差をターゲットの周囲の許容帯域としてパラメータ化し、点 (li、ri) の凸状の組み合わせが帯域制約内に収まるかどうかを確認します。 これは単調な実現可能性チェックとなり、答えに対する二分探索が可能になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべての割り当てを列挙する | 指数 | O(n) | 遅すぎる |
 | 凸縮小 + セグメントチェック + 二分探索 | O(n² log V) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各コンテナ i を点 (li, ri) として書き換え、液体の単位当たりの最小および最大の寄与を表します。 有効な混合は、液体の総量によってスケールされた、これらの点の凸状の組み合わせを形成する重みを選択することに対応します。 

次に、次のように進めます。 

1. 各コンテナを 2D 点 (li、ri) に変換します。 任意の混合は、これらの点の凸状の組み合わせに s を掛けた点 (L, R) に対応します。 これにより、問題は 2 次元の凸包上の幾何学に変わります。 
2. 目標金額を同じスケール上の点として表現します。 目標は、許容される対称許容値を使用して、結果として得られる点の両方の座標をこのターゲットの近くに配置することです。 
3. 許容値 t を導入し、それを凸の組み合わせの制約に変換します。 実行可能領域は、平面内で長方形状の帯になります。下側の座標がターゲットを大きく下回ってはならず、上側の座標がターゲットを大きく超えてはいけません。 
4. 固定許容差の場合、(li, ri) の凸包内の点がこの実行可能領域内にあるかどうかを確認します。 凸包メンバーシップは線形結合によって定義されるため、実現可能な点は最大 2 つの頂点を使用して表現できます。 
したがって、コンテナ i と j の各ペアについて、それらの点のすべての凸の組み合わせを考慮します。 各ペアについて、(li, ri) と (lj, rj) の間のセグメントが許容差で定義された実行可能領域と交差するかどうかを確認します。 
6. いずれかのペアが有効な交差を生成する場合、許容差は十分です。 それ以外の場合はそうではありません。 
7. t に対して二分探索を使用します。 許容値を増加しても許容領域が拡大するだけであるため、実現可能条件は単調です。 
8. 最小 t を見つけたら、比較で使用される正確な算術を追跡することによって、それを必要な有理形式に変換し直します。 

これが機能する理由は、すべての実行可能な解が 2 次元の凸多面体の点に対応しているためです。 最大偏差を最小限に抑えることは、最初にこのポリトープに接触するまで、ターゲットの周囲の対称バンドを縮小することに対応します。 最初の接触点はポリトープの極端な構造で発生する必要があり、2 次元では常に最大 2 つの元の点を使用して表現できます。 これにより、すべてのペアをチェックするだけで十分であり、より複雑な混合は必要ないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from fractions import Fraction

def feasible(points, s, c, M, alpha):
    L = c - alpha
    U = c + alpha

    # We need a convex combination of points (li, ri)
    # but scaled by s is irrelevant for feasibility in normalized form.
    # Check existence of segment intersection.
    n = len(points)

    for i in range(n):
        x1, y1 = points[i]
        for j in range(i, n):
            x2, y2 = points[j]

            # We check if segment between i and j can enter region:
            # x >= L and y <= U

            dx = x2 - x1
            dy = y2 - y1

            # We want t in [0,1] such that:
            # x1 + t dx >= L  -> t >= (L - x1)/dx if dx>0 else <=
            # y1 + t dy <= U  -> t <= (U - y1)/dy if dy>0 else >=

            lo, hi = 0.0, 1.0

            if dx != 0:
                t1 = (L - x1) / dx
                t2 = (U - x1) / dx
                if dx > 0:
                    lo = max(lo, t1)
                    hi = min(hi, 1.0)
                else:
                    lo = max(lo, 0.0)
                    hi = min(hi, t1)

            # y constraint
            if dy != 0:
                t1 = (U - y1) / dy
                t2 = (L - y1) / dy

                if dy > 0:
                    hi = min(hi, t1)
                else:
                    lo = max(lo, t1)

            if lo <= hi:
                return True

    return False

def solve():
    n, s, c = map(int, input().split())
    M = 10000

    pts = []
    for _ in range(n):
        a, l, r = map(int, input().split())
        pts.append((l, r))

    # binary search on alpha in [0, M]
    lo = 0
    hi = M

    for _ in range(60):
        mid = (lo + hi) / 2
        if feasible(pts, s, c, M, mid):
            hi = mid
        else:
            lo = mid

    # hi is answer in scaled form alpha = (M/s)*t
    alpha = hi

    # convert back to t = alpha * s / M
    t = Fraction(alpha).limit_denominator() * Fraction(s, M)

    print(t.numerator, t.denominator)

if __name__ == "__main__":
    solve()
```コードはまず、各コンテナを幾何学的な点に変換します。 次に、2 点間のセグメントが許容領域に入ることができるかどうかを確認することにより、固定許容値の実現可能性テストを実行します。 これにより、完全な凸包を明示的に構築することが回避されます。これは、包内の実行可能な点が 2 次元の極端な点の間のセグメント上に存在するためです。 

許容値を拡大すると制約が緩和されるだけで、以前に有効だった構成が無効になることはないため、二分探索が使用されます。 最後のステップでは、正規化と合計混合サイズの関係を使用して、スケーリングされた許容誤差を実際の誤差に変換します。 

微妙な点は、浮動小数点演算は検索のみに使用され、最終出力は有理数に変換されることです。 より厳密な実装では、検索が正確な分数演算に置き換えられますが、実現可能性チェックの構造は変更されません。

| ステップ | アルファ | 実行可能なペアが見つかりました | 決定 |

 ここでは、2 つのコンテナがすでに重複する不確実性範囲を提供しています。 

| ステップ | アルファ | 実行可能なペアが見つかりました | 決定 |
 | --- | --- | --- | --- |

 このケースは、2 つの点の凸状の組み合わせがすでに境界条件に達しているため、最適な混合では 2 つのソースのみを使用することが多いことを示しています。

 ## 特殊なケース

 すべてのコンテナの不確実性間隔が同じである場合、重大なエッジ ケースが発生します。 その状況では、すべての凸の組み合わせは同じ点に崩壊し、アルゴリズムは複数のソースを混合する必要なく、達成可能なエラーがゼロであることを正確に識別します。 

別のケースは、1 つのコンテナーが非常に幅広い不確実性で支配的である一方で、他のコンテナーが正確である場合に発生します。 最適解ではノイズの多いコンテナが完全に除外されることが多く、その点を含むセグメントはターゲット領域との交差を改善しないため、凸の実現可能性チェックは自然にこれを反映します。 

最後の微妙なケースは、最適解が実行可能領域の境界上に正確に存在する場合です。 セグメント交差ロジックは依然として等価条件を受け入れ、許容範囲にちょうど触れる解が有効なものとして扱われることを保証します。これは、連続空間での off-by-one スタイル エラーを回避するために必要です。
