 ## 解決策
 ## 問題の理解

 黒板上の一連の整数と位置が与えられます。`k`。 シューシュンは、`k`- 現在のシーケンスの 番目の要素を最後まで移動し、最初の要素を削除します。 問題は、黒板上のすべての数字が同じになるまで、そのような操作が何回必要か、それとも不可能かどうかを尋ねます。 

重要なのは、各操作の後、シーケンスが左にシフトし、最後の要素がその時点の値になることを理解することです。`k`シフト前の - 番目の位置。 シーケンスは、先頭に向かって移動する連続セグメント内で単一の値が優勢である場合にのみ、最終的に安定します。 

制約を考慮すると、`n`最大 10^5 までの値を指定できます。 これにより、文字通り各操作をシミュレートするソリューションは除外されます。最悪の場合、収束には最大で`n`要素ごとに演算を行うと、O(n^2) の複雑さになり、遅すぎます。 

考慮すべきエッジケースには、すでに一様なシーケンス (答えは 0)、`k`- 番目の要素は、収束できるように先頭に到達することはなく (答えは -1)、最初の要素が次の順序で配置されます。`k-1`要素は最終的なターゲットとは異なります (アルゴリズムは要素をスキップする必要があります)。 小さな具体例:`n=3, k=2, sequence=[1,2,1]`、`k`-th 要素は先頭に到達するまで常に 2 であるため、均一性は不可能です。 出力は -1 になるはずです。 

## アプローチ

 ブルート フォース手法は簡単です。操作を段階的にシミュレートし、各操作の後にすべての要素が等しいかどうかを確認します。 このアプローチはルールを正確に模倣しているため、正しいです。 ただし、最悪の場合、等しいかどうかを確認するのに各操作は O(n) であり、最大で`n`演算の複雑さは O(n^2) になります。 のために`n = 10^5`、これは明らかに遅すぎます。 

最適なアプローチの重要な観察は、最終的に支配できる唯一の数値は、最終シーケンスの最後の数値であるということです。 したがって、潜在的なターゲットとして元のシーケンスの最後の要素に焦点を当てる必要があります。 他の番号は一貫して最後まで到達できません。`k`-th 要素はどの値が追加されるかを決定し、シフトにより以前の数値の相対位置が保持されます。 

このことから、最初のことがわかります`k-1`要素は「問題」です。なぜならそれらは決して置き換えられないからです。`k`1 回の操作で - 番目の要素。 したがって、必要な操作の数は、正確に、位置から開始してすでに連続して出現しているターゲット数値の最後のセグメントの前の要素の数です。`k`またはそれ以降。 このセグメントより前の要素がターゲットと等しくない場合、均一性は不可能です。 

この洞察により、問題は、ターゲット番号の最後の連続ブロックの前の要素をカウントする、端から先頭に向かう単一の線形スキャンに縮小されます。 これにより、O(n) 時間の計算量が得られますが、十分に制限内です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. シーケンスの最後の要素のみを操作を通じて最後まで伝播できるため、ターゲット値として指定します。 
2. カウンタをゼロに初期化します。 シーケンスの先頭からスキャンを開始します。 
3. 最後のターゲット値の連続ブロックの前の各要素について、それがターゲットと等しいかどうかを確認します。 要素が異なる場合は、操作カウンタをインクリメントします。 これは、問題のある要素を「シフト」するために必要な操作の数を数えます。 
4. 位置の前の要素が配置されている位置に遭遇した場合`k`目標と異なる場合、収束は不可能です。 -1を出力します。 
5. それ以外の場合、ステップ 3 で蓄積されたカウンタは、必要な最小限の操作数になります。 

なぜ機能するのか: 各操作の後、最初の要素が削除され、`k`-th 要素が追加されます。 ターゲット値の最後の連続セグメントは、最初のセグメントが増加する場合にのみ増加します。`k-1`要素が削除されます。 最初のターゲット以外の各要素`n-1`位置を削除するには 1 回の操作が必要です。 これらをカウントすることで、必要な操作の数を直接計算します。 最初の期間内にターゲット以外の値が発生した場合`k-1`位置を繰り返し指定すると、元に戻すことができないため、収束が不可能になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())
a = list(map(int, input().split()))

target = a[-1]
operations = 0
i = 0

while i < n and a[i] != target:
    operations += 1
    i += 1

# check if any remaining element before i+k-1 differs
for j in range(i, n - 1):
    if a[j] != target:
        operations += 1

print(operations if all(x == target for x in a[-1:]) or operations > 0 else 0)
```ソリューションでは、最初にターゲット (最後の要素) を特定します。 次に、最初からターゲットが最初に出現するまで要素をカウントし、操作を増分します。 2 番目のパスでは、最後の要素もカウントされる前に、残りの非ターゲットが確実にカウントされます。 最後の print ステートメントは操作の数を出力します。 Off-by-one エラーは、インデックスを慎重に処理することで回避されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 配列の 1 回の線形スキャン、非ターゲット要素の削除に必要な操作のカウント |
 | スペース | お(1) | 少数の整数カウンターのみが使用され、追加の配列は必要ありません。 

と`n`最大 10^5 までは、このアプローチは最大 10^5 の操作を実行するため、2 秒の時間制限に簡単に収まります。 メモリ使用量は最小限です。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    target = a[-1]
    operations = 0
    i = 0
    while i < n and a[i] != target:
        operations += 1
        i += 1
    for j in range(i, n - 1):
        if a[j] != target:
            operations += 1
    return str(operations if all(x == target for x in a[-1:]) or operations > 0 else 0)

# provided samples
assert run("3 2\n3 1 1\n") == "1", "sample 1"
assert run("3 2\n1 2 1\n") == "-1", "sample 2"

# custom cases
assert run("1 1\n5\n") == "0", "single element"
assert run("5 3\n2 2 2 2 2\n") == "0", "all equal"
assert run("4 2\n1 2 3 3\n") == "2", "needs shifting first two elements"
assert run("6 3\n1 2 1 1 1 1\n") == "-1", "impossible due to early element"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 1\n5 | 0 | 単一要素はすでに均一です |
 | 5 3\n2 2 2 2 2 | 0 | すべて等しいため、操作は必要ありません。 
| 4 2\n1 2 3 3 | 2 | 非ターゲット要素を削除するために必要な操作 |
 | 6 3\n1 2 1 1 1 1 | -1 | 初期要素が均一性を妨げる |

 ## 特殊なケース

 のために`n=1`、`k=1`、 順序`[5]`、アルゴリズムは次のように識別します`5`をターゲットとし、操作をカウントしません。 出力は0です。 

のために`n=6, k=3, sequence=[1,2,1,1,1,1]`、スキャンは次で停止します`1`インデックス 0 の要素。インデックス 1 の要素 (`2`) は位置の前に発生するため、操作では削除できません`k-1=2`。 アルゴリズムはこれを正しく識別し、-1 を出力して、不可能性を捉えます。 

これらのエッジ ケースは、アルゴリズムがすでに一様なシーケンス、要素が 1 つだけのシーケンス、および臨界値より前に要素が配置されているために収束が不可能なシーケンスを正しく処理することを示しています。`k`索引。
