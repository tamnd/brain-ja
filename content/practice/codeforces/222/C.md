 ## 解決策
 ## 問題の理解

 分数は単一の分子と分母として与えられるわけではありません。 代わりに、2 つの配列を受け取ります。 

最初の配列内のすべての数値の積が分子で、2 番目の配列内のすべての数値の積が分母です。 

私たちのタスクは、完全な縮小後に同じ分数を表す 2 つの新しい配列を出力することです。 言い換えれば、もし$$N=\prod a_i,\qquad D=\prod b_i$$その場合は両方を分割する必要があります$N$そして$D$最大公約数で計算し、結果の分子と分母を再び以下の整数の配列として表します。$10^7$。 

最初の課題は、製品自体が巨大であることです。 たとえ数十の値がそれに近いものであっても、$10^7$すでに通常の整数の範囲を超えており、ここでは最大で$10^5$数字。 建設中$N$そして$D$直接は無理です。 

この制約は、素因数アプローチを強く示唆しています。 個々の値は最大でも$10^7$、最小素因数ふるいを使用して効率的に因数分解できます。 まであるので、$2 \cdot 10^5$合計の数値が大きい場合、すべての分子要素と分母要素間のペアごとの gcd 計算を含むアルゴリズムは、コストが高すぎます。 

微妙な点は、出力は依然として以下の整数の配列として表現する必要があることです。$10^7$。 リダクション後、残りの素因数はその限界を満たす数値に再分配されなければなりません。 

次の例を考えてみましょう。```
1 1
12
18
```分数は$12/18$。 gcd は$6$、したがって、換算された分数は次のようになります。$2/3$。 

配列要素間で因子を貪欲にキャンセルするが、すべての共通の素因数を完全に削除しない不注意な解決策は、誤って配列を残す可能性があります。$4/6$、減りません。 

もう 1 つの重要なケースは、すべてがキャンセルされる場合です。```
1 1
100
100
```換算された分数は$1/1$。 

出力配列を空にすることはできません。 すべての要素を削除してゼロの数値を出力するソリューションは形式に違反します。 少なくとも 1 つの値を出力する必要があります。`1`。 

もう 1 つのトリッキーな例:```
2 1
8 9
6
```分子は等しい$72$、分母が等しい$6$、したがって、換算された分数は次のようになります。$12/1$。 

主な要因$2$分母からの関数は、分子の因数分解の一部のみをキャンセルします。 素数の指数ではなく整数のみを比較するアプローチでは、このような部分的なキャンセルを簡単に見逃す可能性があります。 

## アプローチ

 最も直接的なアイデアは、分子と分母の積を再構築し、その gcd を計算し、両方をそれで割ってから、何らかの方法で配列を再構築することです。 

これは数学的には正しいですが、まったく実行不可能です。 製品には以下が含まれます$10^5$因子、それぞれの大きさは$10^7$。 結果として得られる整数は数十万桁になります。 

もう少し洗練された総当たりのアイデアは、分子要素と分母要素の間で gcd を繰り返し計算することです。 すべてのペアについて$(a_i,b_j)$、それらの共通因数を分割します。 

すべての共通素因数は何らかのペア内に出現する必要があるため、最終的には換算された分数が生成されます。 残念ながら、それまであります$10^5$それぞれの側に数字があり、$10^{10}$最悪の場合はペアになります。 

重要な観察は、リダクションは素数指数のみに依存するということです。 

プライムなら$p$表示されます$x$分子に回があり、$y$分母に倍を掛け、リダクション後:$$p^{x-\min(x,y)}$$分子に残り、$$p^{y-\min(x,y)}$$分母に残ります。 

したがって、個々の数値間の因数をキャンセルする代わりに、すべての入力値を因数分解し、両側の各素数の合計指数を数えることができます。 

すべてのカウントがわかったら、各素数の共通量を減算します。 残るのは、まさに縮小された分子と分母の素因数分解です。 

最後のステップは配列を再構築することです。 残りの素因数を収集し、それらを貪欲に乗算し、次の乗算が次の乗算値を超えるたびに新しい出力数値を開始します。$10^7$。 すべての素因数自体は最大でも$10^7$、これは常に成功します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースペアワイズキャンセル | O(nm log A) | お(1) | 遅すぎる |
 | 最適な素因数カウント | O(A ログ log A + K) | O(A) | 承認済み |

 ここ$A=10^7$、 そして$K$すべての入力数値にわたる素因数の合計数です。 

## アルゴリズムのチュートリアル

 1. 以下のすべての数値に対して最小の素因数ふるいを構築します。$10^7$。 
2. ふるいを使用してすべての分子値を因数分解し、マップ内の素数指数を累積します。`cntA`。 
3. ふるいを使用してすべての分母の値を因数分解し、マップ内の素数指数を累積します。`cntB`。 
4. いずれかのマップに出現するすべての素数について、次の計算を行います。$$c=\min(cntA[p],cntB[p]).$$減算`c`両方のカウントから。 

これにより、gcd に寄与した指数が正確に削除されます。 
5. 削減された分子を再構築します。 

すべての素数について$p$、追加$p$その通り`cntA[p]`残りの素因数の流れに繰り返します。 

乗算係数を現在の出力数値を超えない範囲で乗算します。$10^7$。 それ以外の場合は、現在の番号を終了し、新しい番号を開始します。 
6. 同じ手順と残りの指数を使用して削減された分母を再構築します。`cntB`。 
7. 再構築された配列のいずれかが空の場合は、次の配列に置き換えます。`[1]`。 
8. 両方の配列のサイズを出力し、その後に配列自体を出力します。 

### なぜ効果があるのか

 整数の因数分解は独特です。 すべての素数は分子と分母に独立して寄与します。 

素数ごとに$p$、gcd は正確に削除します$$p^{\min(cntA[p],cntB[p])}.$$これらの指数を差し引いた後の残りの指数は、正確に換算された分数の指数になります。 少なくとも 1 つの辺がすべての素数の指数 0 を持つため、共通の素因数は残りません。 

再構成フェーズでは、残りの素因数を以下の数にグループ化するだけです。$10^7$。 素因数の複数セットは変更されないため、表現された分子と分母は換算された分数と同じままになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXV = 10 ** 7

def build_spf(n):
    spf = list(range(n + 1))
    spf[0] = spf[1] = 0

    limit = int(n ** 0.5)
    for i in range(2, limit + 1):
        if spf[i] == i:
            step = i
            start = i * i
            for j in range(start, n + 1, step):
                if spf[j] == j:
                    spf[j] = i
    return spf

def factorize(x, spf, cnt):
    while x > 1:
        p = spf[x]
        c = 0
        while x % p == 0:
            x //= p
            c += 1
        cnt[p] = cnt.get(p, 0) + c

def rebuild(cnt):
    res = []
    cur = 1

    for p in sorted(cnt):
        e = cnt[p]
        for _ in range(e):
            if cur * p <= MAXV:
                cur *= p
            else:
                res.append(cur)
                cur = p

    if cur > 1:
        res.append(cur)

    if not res:
        res = [1]

    return res

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    mx = max(max(a), max(b))
    spf = build_spf(mx)

    cntA = {}
    cntB = {}

    for x in a:
        factorize(x, spf, cntA)

    for x in b:
        factorize(x, spf, cntB)

    primes = set(cntA) | set(cntB)

    for p in primes:
        common = min(cntA.get(p, 0), cntB.get(p, 0))
        if common:
            cntA[p] = cntA.get(p, 0) - common
            cntB[p] = cntB.get(p, 0) - common

    num = rebuild(cntA)
    den = rebuild(cntB)

    print(len(num), len(den))
    print(*num)
    print(*den)

if __name__ == "__main__":
    solve()
```ふるいには、すべての整数の最小の素因数が格納されます。 各除算で少なくとも 1 つの素因数が削除されるため、因数分解が非常に高速になります。 

地図`cntA`そして`cntB`数値ごとの情報ではなく、合計の指数を保存します。 それはまさに分数削減が必要なことです。 

再構築中、残りのすべての素因数が保存されます。 各素因数は最大でも次の値であるため、貪欲なパッキングは安全です。$10^7$。 乗算が制限を超える場合は、単純に新しい出力数値を開始します。 

すべての要素がキャンセルされる場合、空の配列に対する特別な処理が必要になります。 出力形式では、両側に少なくとも 1 つの数字が必要です。

 ## 特殊なケース

 次のことを考慮してください。```
1 1
100
100
```因子数は両側で同一です。$$2^2 \cdot 5^2$$すべての指数が相殺され、素因数が残りません。 再構築手順では空のリストが生成され、それらは次のように置き換えられます。`[1]`。 出力は次のようになります。```
1 1
1
1
```これは換算された分数を正しく表しています。 

次に、次のことを考えてみましょう。```
2 1
8 9
6
```分子には以下が含まれます$2^3 \cdot 3^2$、分母には次のものが含まれます。$2 \cdot 3$。 共通指数を差し引いた後の残りの因数分解は次のようになります。$2^2 \cdot 3$。 アルゴリズムは再構築します`12`、生産`12/1`。 

ついに：```
1 1
9999991
9999991
```値は大きな素数です。 因数分解マップには、両側にその素数が 1 回出現することが含まれます。 キャンセルすると完全に削除され、残ります`1/1`。 これは、すべてが素指数を通じて処理されるため、アルゴリズムが合成数と同じくらい簡単に大きな素数を処理することを裏付けます。
