 ## 解決策
 ## 問題の理解

 スコアの 2 つのマルチセットが与えられます。 

配列`a`最初のツアーで取得したスコアと配列が含まれます`b`2 回目のツアーで取得したスコアが含まれます。 2 つの配列間の対応関係が失われているため、最初のツアーのどのスコアがどの 2 番目のツアーのスコアに属するかはわかりません。 

すべての参加者は各配列に 1 回だけ出現するため、実際の最終順位は、参加者間の完全な一致によって決まります。`a`そして`b`。 参加者の最終スコアは、一致した 2 つの値の合計です。 

Vasya に関する唯一の情報は、彼の最終スコアが少なくとも`x`。 

データと一致するすべてのマッチングの中で、Vasya が取得できた可能性のある最良の場所と最悪の場所を決定する必要があります。 

制約`n ≤ 100000`明示的にマッチングを試みるアプローチは直ちに除外されます。 がある`n!`可能なペアリング、さらにはすべてのペアリングを調べる`n²`候補ペアを繰り返し実行するとコストがかかりすぎます。 受け入れられた解決策は次のようなものでなければなりません`O(n log n)`。 

この問題の最も欺瞞的な部分は、Vasya の正確なスコアが求められていないことです。 私たちが知っているのは、彼のスコアが少なくとも`x`。 順位を再構築しようとする素朴な試みは不必要であり、間違った方向に進みます。 

小さな例を考えてみましょう。```
n = 3, x = 10
a = [10, 0, 0]
b = [10, 0, 0]
```1人の参加者が得点できる`20`、他の2人が得点する間、`0`。 Vasya は参加者になる可能性があります`20`、場所を与える`1`。 

次に、次のことを考えてみましょう。```
n = 3, x = 5
a = [3, 3, 3]
b = [3, 3, 3]
```すべての参加者が得点します`6`。 Vasya はタイブレークに応じて 1 位または 3 位に配置されます。 厳密に大きなスコアのみをカウントするソリューションでは、これが見逃されます。 

重要な観察点は、合計スコアが以下の参加者は、`x`Vasya のスコアは少なくとも`x`。 

## アプローチ

 ブルート フォース ビューは、適切な抽象化を発見するのに役立ちます。 

間の可能なすべてのマッチングを試みるとします。`a`そして`b`。 マッチングごとにすべての最終スコアを計算し、少なくともスコアを持つ参加者を特定します`x`Vasya として評価し、彼の最高ランクと最低ランクを評価します。 

これは正しいですが、絶望的に遅いです。 がある`n!`マッチングも不可能になる`n = 20`、ましてや`100000`。 

重要な観察点は、上記の正確なスコアは`x`関係ありません。 

Vasyaは少なくともスコアを持っているので、`x`、以下のスコアを持つすべての参加者`x`彼の後ろにいることが保証されている。 Vasya の順位と競合できる唯一の参加者は、スコアも少なくとも`x`。 

これにより問題は完全に変わります。 

最高の場所として、Vasya は、スコアが少なくとも`x`。 同点の順序は任意であるため、常に最初に配置することができます。 可能な限り最高の場所は常に`1`。 

最悪の場合は、できるだけ多くの参加者に少なくともスコアを獲得してもらいたい`x`。 あれば`k`そのような参加者では、Vasya がその中で最も弱い可能性があり、タイブレークにより少なくともスコアで他のすべての参加者よりも劣る可能性があります。`x`。 彼の考えられる最悪の場所はまさに`k`。 

問題は次のように縮小されました。 

> ペアの最大数を求める`(a[i], b[j])`少なくとも合計で形成できる`x`。 

両方の配列をソートすると、これは古典的な貪欲マッチングの問題になります。 

残りの最大値を次から取得します。`a`。 より大きな値を保存するには`b`将来使用するために、次の最小値と一致させてください。`b`それでも合計額に達する`x`。 そのような値が存在しない場合、これは`a`成功したペアに参加することはできません。 

この貪欲な戦略により、成功するペアの数が最大化されます。

 | ブルートフォース | お(ん!) | O(n) | 遅すぎる |
 | 最適な貪欲 + ソート | O(n log n) | O(1) 追加 (並べ替え以外) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 並べ替え`a`減少しない順序で。 
2. 並べ替え`b`減少しない順序で。 
3. ポインタを設定する`j = 0`の最小の未使用要素を表します。`b`。 
4. 反復処理する`a`最大から最小まで。 
5. 現在値について`a[i]`、 前進`j`次のいずれかになるまで：

 -`a[i] + b[j] >= x`、または
 - のすべての要素`b`疲れ果てています。 
6. 適切なものがない場合`b[j]`存在します、やめてください。 以来`a`最大値から最小値の順に処理され、残りの値はすべて処理されます。`a`はさらに小さく、うまくペアを形成することもできません。 
7. それ以外の場合は、これを使用して正常なペアを作成します`b[j]`、数えて、移動してください`j`フォワード。 
8. 成功したペアの数を次のようにします。`k`。 
9. 出力:

 - 最高の場所 =`1`- 最悪の場所 =`k`### なぜ効果があるのか

 参加者のスコアが以下の場合`x`Vasya のスコアは少なくとも`x`。 

最悪のランクの場合、重要なのは何人の参加者が少なくとも 1 点以上のスコアを達成できるかどうかだけです。`x`。 あれば`k`そのような参加者は、Vasyaがその中で最後になるように手配して、場所を与えることができます`k`。 

貪欲なマッチングにより、成功するペアの数が最大化されます。 大きな値を処理する場合`a[i]`、最小のものを使用します`b[j]`それは常に最適な状態で機能します。 より大きな選択はより強力な力を無駄にするでしょう`b`後でより小さい値が必要になる可能性がある値`a`。 これは、貪欲なマッチングの背後にある標準的な交換引数です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, x = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    a.sort()
    b.sort()

    j = 0
    cnt = 0

    for i in range(n - 1, -1, -1):
        while j < n and a[i] + b[j] < x:
            j += 1

        if j == n:
            break

        cnt += 1
        j += 1

    print(1, cnt)

solve()
```並べ替えステップでは、貪欲なマッチングのために両方の配列を準備します。 

ポインタ`j`常に、未使用の最小値を参照します。`b`。 大きな値を処理する場合`a`、すべてスキップします`b[j]`それは閾値に達するには小さすぎます。 成功した最初の値が、将来の一致のためにすべてのより大きな値を保持するため、最良の選択となります。 

早めの休憩が安心です。 現在の最大残高がなくなると、`a`一致するものが見つかりません`b`の小さい値ごとに、`a`も失敗します。 

最終的な数は、合計スコアが少なくとも到達できる参加者の最大数です。`x`、これはヴァシャの最悪の場所に相当します。
