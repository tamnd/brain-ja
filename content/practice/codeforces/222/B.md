 ## 解決策
 ## 問題の理解

 整数の行列と、それに繰り返し適用される 3 種類の演算があります。 

1 回の操作で 2 行が交換されます。 もう 1 つは 2 つの列を交換します。 3 番目は、特定の行と列に現在表示されている値を要求します。 

難しいのは、行列自体が 100 万セルにもなり、クエリ数が 50 万に達する可能性があることです。 毎回行または列全体を物理的に再配置するソリューションでは、データの移動に非常に多くの時間がかかります。 

入力では、まずテーブルの次元と操作の数が与えられます。 次に、初期行列が来ます。 その後、各クエリは次のいずれかになります。`r x y`行を入れ替える`x`列あり`y`。`c x y`列を交換する`x`コラム付き`y`。`g x y`現在行にある値を尋ねます`x`、 カラム`y`。 

あらゆる人にとって`g`クエリを実行すると、要求された番号が出力されます。 

制約はソリューションを強力に形作ります。 マトリックスのサイズは最大でも`1000 × 1000`、メモリ内で管理可能です。 本当のプレッシャーは、`500000`操作。 たとえ`O(n)`または`O(m)`ここでスワップあたりのコストが危険になります。 

行を物理的に交換するとします。 単一行の交換がタッチ`m`要素。 と`m = 1000`そして`500000`操作、それはおおよそになります`5 × 10^8`最悪の場合は割り当て。 Python は制限時間内に生き残ることはできません。 

各操作を一定時間で実行する必要があります。 

明らかではない部分は、スワップが開始された後、行インデックスと列インデックスが元の行列と一致しなくなることです。 不用意に実装すると、「現在の行の位置」と「メモリに格納されている元の行」が混同されることがよくあります。 

次の例を考えてみましょう。```
2 2 3
1 2
3 4
r 1 2
g 1 1
g 2 1
```行 1 と行 2 を交換すると、表示される行列は次のようになります。```
3 4
1 2
```正しい出力は次のとおりです。```
3
1
```行の再マッピングを忘れたバグのある実装でも、元の行列から読み取って出力します。`1`それから`3`。 

列の交換により、反対方向からも同じ問題が発生します。```
2 3 2
1 2 3
4 5 6
c 1 3
g 1 1
```表示される最初の行は次のようになります。```
3 2 1
```答えは`3`、 ない`1`。 

もう 1 つの微妙なケースは、同じ行または列の繰り返しの交換です。```
2 2 3
1 2
3 4
r 1 2
r 1 2
g 1 1
```2 つのスワップは互いにキャンセルされます。 答えは必ず戻ってくるはずです`1`。 データを不適切に変更するソリューションは、時間の経過とともに実際の状態から乖離する可能性があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 マトリックスを表示どおりに保存します。 行交換の場合は、2 つの行配列全体を交換します。 列の交換の場合は、すべての行を反復処理して 2 つの列の値を交換します。 クエリの場合は、要求されたセルを直接読み取ります。 

これが機能するのは、各操作がテーブルの状態を直接シミュレートするためです。 

問題はコストです。 行の交換には時間がかかります`O(m)`それらの行のすべてのエントリを移動するためです。 列の交換には時間がかかります`O(n)`。 最悪の場合、`500000`スワップとディメンションの近く`1000`、総作業量は数億の操作に達します。 

重要な観察は、スワップによって実際には値自体が変更されるわけではないということです。 これらは、特定の表示位置に現在表示されている元の行または列を変更するだけです。 

データを移動する代わりに、2 つのマッピング配列を保持できます。`row_pos[i]`元の行が現在表示されている行を占めているかを示します`i`。`col_pos[j]`元の列が現在表示されている列を占めているかを示します`j`。 

最初に:```
row_pos[i] = i
col_pos[j] = j
```行を交換するときは、内部のエントリのみを交換します。`row_pos`。 

列を交換するときは、内部のエントリのみを交換します。`col_pos`。 

お問い合わせの場合`(x, y)`、実際の値は次から得られます。```
matrix[row_pos[x]][col_pos[y]]
```これで、すべての操作が一定時間になります。 

ブルートフォースソリューションは、正確な可視マトリックスを直接維持するため機能します。 最適化されたソリューションが機能するのは、行列の内容が論理的に移動することはなく、インデックスの解釈のみが変更されるためです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(k × max(n, m)) | O(nm) | 遅すぎる |
 | 最適 | O(k + nm) | O(nm + n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. マトリックスをメモリに読み取ります。 

プログラム全体を通じて、元の行列を変更せずに維持します。 
2. 行マッピング配列を作成します。`rows[i]`現在表示されている行にどの元の行が表示されているかを格納します`i`。 

最初は、すべての行がそれ自体にマップされます。 
3. 列マッピング配列を作成します。`cols[j]`現在表示されている列にどの元の列が表示されているかを格納します`j`。 

最初は、すべての列がそれ自体にマップされます。 
4. 各クエリを 1 つずつ処理します。 

各クエリはマッピングを変更するか、値を要求します。 
5. 行交換クエリの場合`r x y`、交換`rows[x]`そして`rows[y]`。 

これにより、行列自体に触れることなく、表示される順序が即座に更新されます。 
6. 列交換クエリの場合`c x y`、交換`cols[x]`そして`cols[y]`。 

繰り返しますが、列の位置の解釈のみが変わります。 
7. 取得クエリの場合`g x y`、次を計算します。```
original_row = rows[x]
original_col = cols[y]
```次に出力します:```
matrix[original_row][original_col]
```8. すべてのクエリが処理されるまで続行します。 

### なぜ効果があるのか

 不変条件は次のとおりです。`rows[i]`現在表示されている行に表示されている元の行と常に等しい`i`、 そして`cols[j]`現在表示されている列に表示されている元の列と常に等しい`j`。 

最初は何も交換されていないため、これは当てはまります。 

行の交換では 2 つの表示位置が交換されるため、対応するエントリが交換されます。`rows`不変式を正確に保持します。 同じ議論が列の交換にも当てはまります。 

クエリは、現在表示されている値を要求します。`(x, y)`。 不変式により、実際に格納される値は元の行から取得されます。`rows[x]`そしてオリジナルコラム`cols[y]`。 Reading that cell from the unchanged matrix always returns the correct answer.

 ## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())

    table = [list(map(int, input().split())) for _ in range(n)]

    rows = list(range(n))
    cols = list(range(m))

    ans = []

    for _ in range(k):
        t, x, y = input().split()
        x = int(x) - 1
        y = int(y) - 1

        if t == 'r':
            rows[x], rows[y] = rows[y], rows[x]

        elif t == 'c':
            cols[x], cols[y] = cols[y], cols[x]

        else:
            ans.append(str(table[rows[x]][cols[y]]))

    sys.stdout.write("\n".join(ans))

solve()
```マトリックスは一度保存され、その後変更されることはありません。 これが実装の中心的なアイデアです。 すべての変化は、`rows`そして`cols`配列のマッピング。 

Python リストはゼロベースであるため、マッピングではゼロベースのインデックスが使用されます。 すべてのクエリは、入力インデックスから直ちに 1 を減算します。 この変換を忘れることは、この問題で最も一般的な 1 つ違いの間違いです。 

行交換の場合、コードは内部の 2 つの整数のみを交換します。`rows`。 同じことが列にも当てはまります。 行列要素は物理的に移動しません。 

クエリ操作は一見すると少し非対称に見えます。```
table[rows[x]][cols[y]]
```これが機能する理由は、`rows[x]`元の行が現在表示されている行を占めていることがすでにわかります`x`。 マトリックス自体は依然として元の座標を使用します。 

出力はリストに蓄積され、最後に一度出力されます。 Python では、行ごとに最大 50 万回印刷すると速度が遅くなる可能性があります。
