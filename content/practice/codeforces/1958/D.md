 ## 解決策
 ## 問題の理解

 階段の段が何列か与えられていますが、それぞれの段は修理が必要か、すでに大丈夫かのどちらかです。 ステップが正常であれば、入力ではゼロのように動作します。 壊れている場合は、修理の困難さを表す正のコスト値がかかります。 

修復プロセスには日数の制約があります。 私たちは毎日、たった 1 つの手術を実行することが許されています。 その操作は、単一の壊れたステップをその値と同じコストで修復するか、隣接する 2 つの壊れたステップをそれらの値の合計の 2 倍に等しいコストで一緒に修復するかのいずれかです。 目標は、最初に可能な限り最小の日数を使用してすべての修理を完了することであり、この最小日数を達成するすべての戦略の中で、最小の総コストが必要です。 

最初の重要な観察は、分割されたポジションを単一または隣接するペアにグループ化する方法によって日数が完全に決定されるということです。 すべての壊れた位置は 1 回だけカバーされる必要があり、各操作は 1 つまたは 2 つの隣接する壊れたインデックスをカバーします。 したがって、ペアリングにより操作の数が減るため、「最小日数」の要件により、可能な限り最大数の隣接するペアを使用する必要があります。 

これにより、問題は直ちに、分割されたステップの最大の連続セグメントごとに一致するスタイルの決定に変わります。 ゼロをまたいでペアにすることはできないため、ゼロは配列を独立したセグメントに分割します。 

制約から、すべてのテスト ケースの合計 n は最大 3·10^5 になります。 これにより、テスト ケースごとの配列全体に対する二次動的計画法が除外されます。 テスト ケースごとにリニア スキャンが必要です。 インターバル DP を試みたり、すべてのペアリングをグローバルに考慮したりするソリューションは、遅すぎます。 

すべての値が 0 の場合、答えが 0 でなければならない場合、微妙なエッジ ケースが発生します。 もう 1 つは、単一セグメント内のすべての値が正の場合です。貪欲なペアリングの決定では、隣接性の制約と、単一操作とペア操作の間のコストの非対称性を考慮する必要があります。 

## アプローチ

 ブルートフォース戦略では、あらゆる方法で正の値の連続セグメントをシングルトンと隣接するペアに分割しようとします。 長さ k のセグメントの場合、フィボナッチのような多くのマッチングがあり、k が線形であっても、構成の数は指数関数的に増加します。 各構成について、操作の数とコストを計算し、操作の数とコストが最小のものを選択します。 最悪の場合、k は最大 3・10^5 になる可能性があるため、これはすぐに実行不可能になります。 

最初の目的が日数を最小化することであることが理解されると、構造は単純化されます。これは、ペアになった隣接する操作の数を最大化するのと同じです。 これにより、問題はパス グラフ内で最大の一致を選択することになります。これは簡単です。常に、可能な限り多くの隣接する壊れた要素をペアにし、セグメントの長さが奇数の場合、ちょうど 1 つの要素が単一のままになります。 

2 番目の目的は、最大のペア間のコストを最小限に抑えることですが、これが唯一の本当の微妙な点です。 i と i+1 をペアにすると 2(a[i] + a[i+1]) のコストがかかりますが、それらを別々のままにしておくと、a[i] + a[i+1] のコストがかかります。 ペアリングは要素ごとに厳密に高価であるため、コスト削減のためにペアを選択しているのではなく、日数の最小化のためにペアを選択せざるを得ません。 ただし、要素が単一の場合、その寄与は a[i] であるため、ペアリングとペアリングなしの違いは局所的になります。 唯一の柔軟性は、セグメント内で奇数の残りが発生する場合です。どの位置をペアにしないままにするかを選択でき、その選択が総コストに影響します。

したがって、各セグメントについて、左から右へ貪欲にペアにする必要がありますが、セグメントの長さが奇数の場合は、残りの 1 つが最適に配置されるようにする必要もあります。 これは、セグメント内の 1 つの要素のすべての可能な削除をテストし、残りの偶数長リストのペアリング コストを計算することになります。 標準的なトリックでは、最適な選択は、各奇数セグメント内で最小コスト要素をペアにしないままにすることであることを示しています。これは、ペアにするとより積極的に二重カウントされるためです。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. 配列を、ゼロ以外の値の最大の連続セグメントに分割します。 ゼロをまたぐ操作はできないため、ゼロは区切り文字として機能します。 これにより、部分問題の独立性が保証されます。 
2. セグメントごとに、すべての値をリストに収集します。 このリストだけで問題を解決します。 
3. セグメントの長さが偶数の場合は、(0,1)、(2,3)、(4,5) などの順序で要素を貪欲にペアにします。 各ペアは 2 · (a[i] + a[i+1]) をコストに寄与します。 
4. セグメントの長さが奇数の場合は、1 つの要素だけをペアにしないでください。 暗黙的に最適な選択を試みます。ペアになっていないすべての要素は、2 倍のペアのコスト構造の一部ではなく 1 回だけ寄与するため、最小の要素をペアになっていない状態にしておくと、コストのインフレが最小限に抑えられます。 
5. すべてのペアのコストの合計とすべてのペアになっていない要素の合計として合計コストを計算します。 

貪欲な構造が機能するのは、ペアリングが可能な限り強制され、隣接制約によりセグメント内の異なるペアリング決定間の相互作用が防止されるためです。 

### なぜ効果があるのか

 各セグメントの内部では、問題はエッジ (ペア) と頂点 (シングルトン) でパスをカバーすることに帰着します。そこではエッジ数を最大化する必要があります。 エッジ数が固定されると、残りの選択は、奇数セグメント内でどの頂点が一致しないままになるかだけです。 ペアを再配置してもペアの数は変わりませんが、一致しない頂点が並べ替えられるだけです。 コストの差は線形であり、一致しない頂点に対して局所的であるため、一致しない頂点として最小値を選択すると、総コストが最小化されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        ans = 0
        i = 0
        
        while i < n:
            if a[i] == 0:
                i += 1
                continue
            
            seg = []
            while i < n and a[i] != 0:
                seg.append(a[i])
                i += 1
            
            m = len(seg)
            seg.sort()
            
            # We maximize pairing: floor(m/2) pairs
            # If odd, one element remains unpaired
            if m % 2 == 1:
                # leave smallest unpaired
                ans += seg[0]
                seg = seg[1:]
                m -= 1
            
            # remaining is even, fully paired in sorted form
            # pairing arbitrary order in optimal cost reduces to sum structure
            for j in range(0, m, 2):
                ans += 2 * (seg[j] + seg[j+1])
        
        print(ans)

if __name__ == "__main__":
    solve()
```この実装では配列をゼロで分割し、セグメント間の独立性を確保します。 各セグメントはソートされているため、必要なときにどの要素がペアになっていないかを最適に決定できます。 重要な点は、並べ替えが、ペアリングの隣接制約を変更するためではなく、不一致要素によるペナルティを最小限に抑えるためにのみ使用されることです。 隣接性はペアリングの存在のみを考慮しており、最大マッチング間のコスト最小化を考慮するものではありません。 

次に、ペアリング ループは一度に 2 つの要素を消費し、各ペアの強制コストを累積します。 

## 実用的な例

 ### 例 1

 入力セグメント:`[13, 15, 8]`セグメントがどのように処理されるかを追跡します。 

| ステップ | セグメント | アクション | ペアになっていない | 追加コスト | 合計 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | [13,15,8] | 並べ替え | [] | 0 | 0 |
 | 2 | [8,13,15] | 最小 (奇数の長さ) を削除 | 8 | 8 | 8 |
 | 3 | [13,15] | ペア | [] | 2・(13+15)=56 | 64 |

 最終的な答えは64です。 

このトレースは、最小の要素はペアリング コストによる増幅を避けるため、ペアリングしないままにするのが最適であることを示しています。 

### 例 2

 入力セグメント:`[1,2,3,4,5]`| ステップ | セグメント | アクション | ペアになっていない | 追加コスト | 合計 |

 | 1 | [1,2,3,4,5] | 並べ替え | [] | 0 | 0 |
 | 2 | [1,2,3,4,5] | 最小値を削除 | 1 | 1 | 1 |
 | 3 | [2,3,4,5] | ペア (2,3) | [] | 2・(2+3)=10 | 11 |

 ## 特殊なケース

 入力などの長さ 1 のセグメント`[7]`は、ソートし、すぐにペアになっていない要素としてカウントすることによって処理されます。 このアルゴリズムは 7 を直接加算し、ペアリングを実行しません。これは両方の制約と一致します。 

完全にゼロの配列ではセグメントがまったく生成されないため、計算ループに入らずに答えはゼロのままになります。 

のような長い交互パターン`1 0 2 0 3 0 4`独立したシングルトンに分割されます。 各シングルトンは直接寄与し、ロジックが適用される前にセグメンテーションによって境界が強制されるため、ゼロをまたがる偶発的なペアリングは発生しません。
