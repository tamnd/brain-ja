 ## 解決策
 ## 問題の理解

 クロックは通常の連続表示ではなく、3 つの状態を繰り返すサイクルのように動作します。 どのサイクルにも長さがある$3k$秒。 各サイクルの開始時に時計は水温を表示し、その後、$k$数秒後に気温に切り替わり、その後、$k$秒を経過すると、実際の時刻の表示に切り替わります。 3 番目のセグメントの後、同じパターンが再び再開されます。 

したがって、タイムラインは次のようにブロックに分割されます。$0$に$k-1$クロックは状態 0 にあります。$k$に$2k-1$状態 1 にあり、から$2k$に$3k-1$状態 2 にあり、時刻が表示されます。 このパターンは無限に繰り返されます。 

テストケースごとに時間が与えられます$m$、そして私たちはその秒に立って時計をチェックしています。 問題は、時計が「時間表示」セグメントにある次の瞬間、つまり次の整数の時間が必要になるまでどれくらい待つ必要があるかということです。$t \ge m$そのような$t \bmod 3k \in [2k, 3k)$、そして出力する必要があります$t - m$。 

制約が非常に大きいため、数秒にわたるシミュレーションは不可能です。 と$t$まで$10^4$そして$m$まで$10^9$、一度に 1 秒ずつチェックする場合でも、最大で$10^{13}$限界をはるかに超えた最悪の場合の操作。 解はテスト ケースごとに一定時間である必要があります。 

よくある間違いは、境界動作の誤解から生じます。 クロックは正確に次の倍数で状態を切り替えます。$k$、インターバル中ではありません。 たとえば、時間$2k$、すぐに時間が表示され始めるので、$2k$それ自体は有効です。 もう一つの微妙なケースは次のような場合です。$m$すでに時間間隔内にあります。 その場合、答えはセグメントの残りの長さではなく、ゼロになります。 

## アプローチ

 直接シミュレーションのアプローチでは、次から開始して時間を繰り返し増加させます。$m$インターバルの瞬間に至るまで$[2k, 3k)$モジュロ$3k$。 これは、クロック動作の正確な定義に従っているため、概念的には正しいです。 ただし、最悪の場合、$m$時間表示セグメントが終了した直後なので、ほぼスキャンする可能性があります$2k$次のステップに進む前のステップ。 以来$k$まで可能です$10^8$、これは完全に不可能になります。 

重要な観察は、システムが純粋に周期的であり、周期があることです。$3k$。 これは残りのみを意味します$m$モジュロ$3k$重要です。 サイクル内のどこにいるのかがわかれば、答えは区間内の次の点までの距離のみに依存します。$[2k, 3k)$。 すでにその間隔内に入っている場合は、作業は完了です。 それ以外の場合は、次に進みます$2k$位置に応じて、現在または次のサイクルで。 

これにより、時間の経過に伴うシミュレーションではなく、モジュラー位置に関する単純な計算に問題が軽減されます。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. サイクル長を次のように計算します。$3k$。 これは、クロック状態の完全な繰り返しパターンを表します。 この値を法として扱うと、無限のタイムラインが 1 つの制限された間隔に縮小されます。 
2. コンピューティング$r = m \bmod (3k)$これは、現在時間が繰り返しサイクル内のどこにあるかを示します。 このステップでは、関連情報を失うことなく、無限の時間軸を 1 つのサイクルに圧縮します。 
3. かどうかを確認します。$r$すでに時刻表示間隔内にあります$[2k, 3k)$。 もしそうなら、時計はすでに時刻を示しています$m$なので待ち時間はゼロです。 
4. もし$r < 2k$、私たちはまだ水中か空中の展示中です。 次回の表示は、値に対応する次のサイクルの時間セグメントの開始時に始まります。$2k$現在のサイクルで。 待ち時間は$2k - r$。 
5. もし$r \ge 2k$、時間表示セグメント内にいますが、正確な位置によっては解釈が間違っている可能性があります。 ただし、ステップ 3 で有効な間隔をすでにカバーしているため、この場合は時間セグメント内にいることを意味し、答えはゼロになります。 

この構造により、次のしきい値までの単純な距離のみを計算することが保証されます。 

### なぜ効果があるのか

 重要な不変条件は、クロック状態は次の条件のみに依存するということです。$t \bmod 3k$。 毎秒は固定長サイクル内の位置に一意にマッピングされ、「時間表示」状態はまさにその間隔です$[2k, 3k)$。 したがって、次の有効な瞬間を見つけることは、最小のものを見つけることになります。$t \ge m$その残差がその間隔内にあるようにします。 残基はサイクルごとに繰り返されるため、次のいずれかになります。$m$すでに有効であるか、次の有効な瞬間が最初の境界です$2k$現在または次のサイクルで。 他の構造では、これより近い有効時間を生成することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    k, m = map(int, input().split())
    
    cycle = 3 * k
    r = m % cycle
    
    if r >= 2 * k:
        print(0)
    else:
        print(2 * k - r)
```この解決策は、モジュロ演算を使用して時間を単一サイクルに圧縮します。 変数`r`は、繰り返しパターン内の正確な位置を表します。 もし`r`すでに時刻表示ウィンドウ内にあるため、待つ必要はありません。 それ以外の場合は、までの距離`2k`時計が再び時間を示し始める次の瞬間を表します。 

微妙な点は、境界を正確に正確に処理することです。`2k`。 開始時に間隔が含まれているため、`r == 2k`待機をゼロにする必要があり、これは自然に処理されます。`>=`状態。

## テストケース```python
import sys, io

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline
    
    t = int(input())
    out = []
    for _ in range(t):
        k, m = map(int, input().split())
        cycle = 3 * k
        r = m % cycle
        if r >= 2 * k:
            out.append("0")
        else:
            out.append(str(2 * k - r))
    return "\n".join(out)

 ## 特殊なケース

 エッジケースの 1 つは次のような場合です$m$はまさに次の倍数です$3k$。 この場合$r = 0$つまり、水温段階のサイクルのまさに開始点にいます。 アルゴリズムは距離を正確に計算します。$2k$、つまり$2k$、最初の時間表示の瞬間と一致します。 

もう 1 つのエッジケースは次のような場合です$m = 2k$。 ここ$r = 2k$、ということで条件は$r \ge 2k$がトリガーされ、出力はゼロになります。 これは、時計がその瞬間に正確に時間を表示し始めるという事実と一致します。 

3 番目のケースは次の場合です。$m$時間セグメントが終了する直前です。たとえば、$m = 3k - 1$。 モジュロは以下を与えます$r = 3k - 1$、まだ時間表示間隔内にあるため、答えはゼロです。 これにより、境界に近いかどうかに関係なく、間隔内のどこにでもあれば十分であることが確認されます。
