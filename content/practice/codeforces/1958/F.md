 ## 解決策
 ## 問題の理解

 私たちは、わずか 2 行と多数の列という、非常に制約されたグリッドに取り組んでいます。 スタートは左上のセル、ゴールは右下のセルです。 移動は右または下のみに制限されています。つまり、有効なパスは、上の行にしばらく留まり、一度だけ下の行に下がってから右に進むか、場合によってはグリッドの境界を尊重する同等の動作を行う必要があります。 

グリッドには 2 行しかないため、スタートからゴールまでのすべてのパスは非常に厳格な構造になります。 パスは、単一の下向き移動が発生する列によって完全に決定されます。 パスが下に移動しない場合、ターゲット セルに到達できないため、有効なパスはすべて、行を切り替える列を 1 つだけ選択する必要があります。 

このタスクでは障害が発生します。開始セルと終了セルを除いて、ブロックするセルを正確に k 個選択します。 セルをブロックすると、セルを通過するすべてのパスが削除されます。 可能な値 i ごとに、残りの有効なパスの数がちょうど i になるように、k 個のブロックされたセルを選択する方法が何通りあるかを数えなければなりません。 

制約は大きく、n は最大 200,000 です。 これにより、ブロックされた構成を列挙しようとしたり、構成ごとにパスを明示的にシミュレートしようとするソリューションは直ちに排除されます。 どのアプローチでも、問題を閉じた形式の組み合わせ計数構造、理想的には n において線形または線形に近い構造に還元する必要があります。 

k が十分に大きい場合、たとえ少数の列をブロックするだけでもグリッドの一部を完全に分離できる場合、微妙なエッジ ケースが発生します。 たとえば、k がエンドポイントを除く列内のすべてのセルをブロックする場合、その列は潜在的な「スイッチ ポイント」を完全に排除する可能性があります。 もう 1 つのエッジ ケースは、k が最小の場合です。k = 0 の場合、各列が可能な切り替えポイントを表すため、すべての列が使用可能なままとなり、パスの数は最大化され、n に等しくなります。 

単純なアプローチでは、k 個のブロックされたセルを選択し、切り替えポイントとして有効な列の数を再計算します。 これは、ブロックされたセルからパス数へのマッピングが非常に非線形であるため、失敗します。単一のセルをブロックすると、可能性のあるパスは 1 つだけに影響しますが、複数のセルが同じ列にある場合、組み合わせは強く相互作用します。 

## アプローチ

 重要な簡素化は、2 行グリッド内でパスがどのように動作するかを理解することで実現します。 それぞれの有効なパスは、パスが行 1 を右に進み、列 j まで進み、その後下に移動し、その後行 2 に右に進むように、列 j を選択することに対応します。したがって、可能な正規パスは、列ごとに 1 つずつ、正確に n 個あります。 

ただし、セル (1, j) または (2, j) のいずれかがブロックされると、列 j は使用できなくなります。 どちらかがブロックされると、その切り替えポイントは破壊されます。 したがって、パスの数は、両方のセルがブロックされていない列の数と正確に一致します。 

したがって、問題は、2n − 2 個の適格なセル (開始と終了を除く) の中から k 個のブロックされたセルを選択し、その結果の構成で正確に i 列が完全に無傷のままになる方法が何通りあるかを数えるということになります。 

2 つのセルがどちらもブロックされていない場合、列を「良好」と定義しましょう。 列が適切でない場合、パスは提供されません。 したがって、パスの数は正常な列の数と等しくなります。 

ここで問題は、正確に i 列が完全に変更されないように k 個のセルを選択することです。 

i 列が完全に変更されていない場合、それらの列では何もブロックされません。つまり、すべての 2i セルが選択されないままになります。 残りの n − i 列は「損傷した列」であり、少なくとも 1 つのセルがブロックされています。 

ここで問題を、どの列が完全にクリーンであるかを選択し、k 個のブロックが残りの列にどのように分散されるかを選択することに変換します。

n − i 個の損傷した列のそれぞれについて、上部セルのみをブロックする、下部セルのみをブロックする、または両方をブロックするという 3 つの可能性があります。 これにより、列ごとにローカルなカウント構造が作成されます。 ブロックされたセルの総数は k であり、これらの列全体にパーティション制約が強制されます。 

これは、母関数を持つ独立した列にわたる古典的な分布問題になります。 各列は多項式に寄与します。ここで、x はブロックされたセルの数をカウントします。 

損傷した各列は次の原因となります。 

1 + 2x + x^2。1 は何もブロックしないことに対応します (列が損傷していると想定される場合は許可されません)。そのため、実際に損傷した列が寄与する必要があります (2x + x^2)。 

クリーンなカラムは 1 に貢献します。 

したがって、固定 i の場合、次の x^k の係数が必要です。$$\binom{n}{i} (2x + x^2)^{n-i}$$次に展開します。$$(2x + x^2)^{n-i} = x^{n-i} (2 + x)^{n-i}$$したがって、x^k の係数は次のようになります。 

私たちに必要なのは：$$x^{n-i} \cdot x^{k-(n-i)}$$これは k ≥ n − i を意味し、(2 + x)^{n-i} の x^{k-(n-i)} の係数に換算します。 

これで、次のように簡単になります。$$(2 + x)^{n-i} = \sum_{j=0}^{n-i} \binom{n-i}{j} 2^{n-i-j} x^j$$したがって、最終的な答えは次のとおりです。$$\binom{n}{i} \binom{n-i}{k-(n-i)} 2^{(n-i)-(k-(n-i))} = \binom{n}{i} \binom{n-i}{k-n+i} 2^{2(n-i)-k}$$有効な i のみを合計します。

 ## アルゴリズムのチュートリアル

 1. 階乗および逆階乗を最大 2n まで事前計算して、二項係数の高速評価を可能にします。 これは、素数を法とする組み合わせを繰り返し計算するために必要です。 
2. i を完全にブロックされていない列の数として解釈して、0 から n までのすべての i の値を反復処理します。 i を選択するたびに、列がクリーンなグループと破損したグループに分割されます。 
3. i 列がクリーンな場合は、それらを選択します。$\binom{n}{i}$方法。 これにより、どの列がパスに寄与するかが修正されます。 
4. t = n − i を損傷した列の数とします。 これらはブロックを配置する唯一の列です。 
5. 損傷した各列は、1 つまたは両方のセルをブロックするかどうかに応じて、1 つまたは 2 つのブロックされたセルに寄与します。 ここで、各列が少なくとも 1 ブロックに寄与するように、k ブロックを t 列に分散する必要があるため、t を減算して割り当て削減問題を解決します。 
6. r = k − t を定義します。 これは、損傷した列ごとに 1 つのブロックを配置することを超える「追加ブロック」の数です。 r が負の場合、または t より大きい場合、この構成は不可能です。 
7. t 個の損傷した列の中から r 個の列を選択して、2 番目のブロックを受け取ります。 これは貢献します$\binom{t}{r}$。 
8. 各構成は次の要因に寄与します。$2^{t-r}$、列内の単一のブロックが一番上のセルに配置されるか、一番下のセルに配置されるかに対応します。 
9. すべての寄与を乗算します。$\binom{n}{i} \binom{t}{r} 2^{t-r}$。 

### なぜ効果があるのか

 重要な不変条件は、すべての有効なブロッキング構成がトリプルに一意に対応するということです。つまり、クリーンな列の選択、どの損傷列が 1 つまたは 2 つのブロックされたセルを受け取るかの選択、および 1 つのブロックを受け取るすべての列について、どの行をブロックするかの 2 進選択です。 クリーンな列と損傷した列への分割が修正されると、これらの選択は独立します。 これにより、列間のすべての相互作用が削除され、グローバル制約「ちょうど k ブロック」が、オフセット r を t 個の同一スロットに分散することによって処理される列ごとの追加制約に縮小されます。 どの構成も 2 回カウントされません。これは、各ブロックされたセル パターンによって、どの列がクリーンであるか、および各破損した列に含まれるブロックの数が一意に決定されるためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
MOD = 10**9 + 7

def modpow(a, e):
    res = 1
    while e:
        if e & 1:
            res = res * a % MOD
        a = a * a % MOD
        e >>= 1
    return res

def solve():
    n, k = map(int, input().split())

    maxv = 2 * n
    fact = [1] * (maxv + 1)
    invfact = [1] * (maxv + 1)

    for i in range(1, maxv + 1):
        fact[i] = fact[i - 1] * i % MOD

    invfact[maxv] = modpow(fact[maxv], MOD - 2)
    for i in range(maxv, 0, -1):
        invfact[i - 1] = invfact[i] * i % MOD

    def C(a, b):
        if b < 0 or b > a:
            return 0
        return fact[a] * invfact[b] % MOD * invfact[a - b] % MOD

    res = [0] * (n + 1)

    for i in range(n + 1):
        t = n - i
        r = k - t
        if r < 0 or r > t:
            continue
        ways = C(n, i) * C(t, r) % MOD
        ways = ways * modpow(2, t - r) % MOD
        res[i] = ways

    print(*res)

if __name__ == "__main__":
    solve()
```階乗事前計算により、定数時間の二項係数クエリが有効になります。これは、i に対するループがすべての列に対して実行されるために必要です。 べき乗は、「単一ブロック」の損傷列ごとに、いずれかの行に単一ブロックを配置するという二項選択を処理します。 r の境界チェックにより、ブロックの有効な分布のみがカウントされることが保証されます。 

よくある落とし穴は、損傷した列には少なくとも 1 つのブロックされたセルが含まれている必要があることを忘れていることです。そのため、r は k − (n − i) として定義されます。 もう 1 つのよくある間違いは、2 番目のブロックの選択が 2^r に対応するか 2^{t-r} に対応するかを混同することです。 正しい解釈は、ブロックが 1 つだけ含まれる列のみが係数 2 に寄与するということです。

import sys, io

MOD = 10**9 + 7

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, k = map(int, input().split())

    maxv = 2 * n
    fact = [1] * (maxv + 1)
    invfact = [1] * (maxv + 1)

    for i in range(1, maxv + 1):
        fact[i] = fact[i - 1] * i % MOD

    def modpow(a, e):
        res = 1
        while e:
            if e & 1:
                res = res * a % MOD
            a = a * a % MOD
            e >>= 1
        return res

    invfact[maxv] = modpow(fact[maxv], MOD - 2)
    for i in range(maxv, 0, -1):
        invfact[i - 1] = invfact[i] * i % MOD

    def C(a, b):
        if b < 0 or b > a:
            return 0
        return fact[a] * invfact[b] % MOD * invfact[a - b] % MOD

    res = [0] * (n + 1)

    for i in range(n + 1):
        t = n - i
        r = k - t
        if 0 <= r <= t:
            res[i] = C(n, i) * C(t, r) % MOD * pow(2, t - r, MOD) % MOD

    return " ".join(map(str, res)) + "\n"

 ## 特殊なケース

 k = 0 の場合、セルはブロックされないため、すべての列は有効なままになります。 アルゴリズムは t = n − i および r = −t を設定し、i = n を除くすべてのケースを即座に拒否します。 これにより、n 個のパスがすべて残っているという事実と一致する、単一の構成が生成されます。 

k が 2n − 2 に近い非常に大きい場合、ほとんどの列が損傷するはずです。 r = k − t という制約により、必要な数のブロックを分散できる構成のみをカウントすることが保証され、不可能な高密度ブロック パターンの過剰カウントが防止されます。 

i = n の場合、すべての列はクリーンであるため、t = 0、r = k となります。 これは、k = 0 を強制します。そうでない場合、構成は無効になります。これは、ブロックが存在する場合、少なくとも 1 つの列が破壊され、パスが減少するという直感と一致します。
