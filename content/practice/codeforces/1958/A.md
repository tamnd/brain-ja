 ## 解決策
 ## 問題の理解

 値が 1、3、および 5 のコインを使用して正確な合計を計算するように求められます。目標金額 n ごとに、任意の数の 3 および 5 コインを使用して正確に n を支払いたいと考えており、1 コインの使用を強制されるのは、それが避けられない場合のみです。 課題は、そのような分解で出現する 1 コインの数を最小限に抑えることです。 

言い換えれば、最初に 3 と 5 だけを使用して n を構築しようとすると想像してください。 それが不可能な場合は、1 を使用して残りを「修復」することができます。 使用される各 1 コインは、3 コインと 5 コインの組み合わせを選択した後にカバーされていない残りを残すことに対応します。 

制約は小さく、n は最大 100、テスト ケースの数は最大 100 です。 これは、二次または三次動的計画法のアプローチでも時間内に問題なく実行できることを意味します。 ただし、問題の構造は、すべての合計に対する DP よりもはるかに単純な何かが可能であることを示唆しています。 

貪欲な選択が失敗した場合、微妙なケースが発生します。 たとえば、n = 8 の場合、5 を 1 つ使用すると 3 が残り、1 がなくてもカバーできますが、3 を 2 つ使用すると 2 が残り、これには 2 つの 1 が必要になります。 常に最大のコインを最初に取る単純な貪欲な戦略では、剰余構造の点で 5 が 3 の組み合わせより常に優れているとは限らないため、残りの 1 を確実に最小化することはできません。 

n が小さい場合には、別のエッジ状況が現れます。 n = 1 または n = 2 の場合、3 と 5 の組み合わせはまったく役に立たないため、すべての支払いは 1 コインを使用して行う必要があります。 いつでも 3 または 5 から始められると仮定したアプローチは、ここではすぐに失敗します。 

## アプローチ

 ブルートフォースアプローチでは、3 枚と 5 枚のコインのすべての組み合わせが試行されます。 5 コインの各数と 3 コインの各数について、1 コインを使用して残りの値を形成できるかどうかを確認します。 固定 n の場合、5 コインの最大 n/5 の選択肢と 3 コインの n/3 の選択肢を試す可能性があるため、可能性の数は O(n^2) です。 各ペアについて、残りを計算し、それを 1 コインの数として数えます。 これは、有効な分解をすべて列挙しているため、正しいです。 

このアプローチは、n ≤ 100 に対してすでに十分小さいですが、それでも不必要です。 重要な観察は、1 コインを決定変数として明示的に考慮する必要がまったくないということです。 3 コインと 5 コインの使用枚数を決めてしまえば、1 コインの枚数は残りによって完全に決まります。 したがって、タスクは n から 3x + 5y を引いた後の剰余を最小化することになります。 

すべてのペアを試す代わりに、使用する 5 コインの数を繰り返すことができます。 それぞれの選択肢について、剰余は n から 5y を引いたものになります。 残りは、未使用ユニットが 1 コインになるため、できるだけ多くの 3 を使用して減らしたいと考えています。 唯一の微妙な点は、3 コインは残りを 3 ずつ減らすため、3 コインを使用した後の残りは単純に (n - 5y) mod 3 になることです。 

これにより、問題は 5 コインの可能な数にわたる 1 次元のスキャンに変換されます。

 | 最適 | テストあたり O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、n を目標合計として読み取ります。 
2. 0 から n // 5 までの 5 コインの可能な数をすべて試してください。 
3. 5 枚のコインの各選択肢 y について、残りの値 r = n - 5y を計算します。 
4.rからは3コインをできるだけ多く使います。 3 コインを使用した後の残りは r % 3 です。 
5. この残りを必要な 1 コインの数として解釈します。 
6. y のすべての選択肢の最小残りを追跡します。 

3 コインではなく 5 コインを繰り返す理由は、純粋に利便性のためです。 5 が大きいため、反復回数は少なくなり、剰余はモジュロ 3 で適切に動作します。 

### なぜ効果があるのか

5 コインの固定選択では、3 コインの最適な使用が強制されます。3 つの 1 コインを 1 つの 3 コインに置き換えても 1 コインの数は決して増加しないため、できるだけ多くの 3 を取ることで、常に残りのカバーされない量が最小限に抑えられます。 5 コインの数が固定されると、残りの異なるセグメント間の相互作用はなくなるため、残りの合計の最適な構造は貪欲かつ標準的になります。 したがって、大域的な最適化は、各 y に対するこれらの局所的に最適な選択肢の中から発生する必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    
    ans = n  # worst case: all 1-coins
    
    for y in range(n // 5 + 1):
        rem = n - 5 * y
        ans = min(ans, rem % 3)
    
    print(ans)
```コードは各テスト ケースを読み取り、すべてのユニットが 1 コインで支払われるという悲観的なケースで答えを初期化します。 次に、5 コインの可能なすべての数を列挙します。 選択ごとに剰余を計算し、3 コインを使用して貪欲に剰余を減らし、必要な 1 コインの数として 3 を法とする剰余のみを残します。 すべての選択肢の最小値が出力されます。 

ここでよくある間違いは、余りを 3 で割って、それを答えに加えようとすることです。 これにより、1 コインが最小化されるのではなく、誤って 3 コインがカウントされてしまいます。 正しい見方は、3 コインはサイズ 3 のチャンクを完全に除去し、残りだけを残すということです。 

## 実用的な例

 n = 7 と n = 11 の計算を追跡します。 

### 例 1: n = 7

 | 5コイン(y) | 剰余 r = n - 5y | r%3 | これまでのベストアンサー |
 | --- | --- | --- | --- |
 | 0 | 7 | 1 | 1 |
 | 1 | 2 | 2 | 1 |

 最良の結果は 1 で、5 コインを 0 枚と 3 コインを 2 枚使用し、残りが 1 になったときに達成されます。 

これは、5 コインを混合することで必ずしも剰余が改善されるわけではないことを裏付けています。なぜなら、5 は剰余構造を導入し、モジュロ 3 ではさらに悪くなる可能性があるからです。 

### 例 2: n = 11

 | 5コイン(y) | 剰余 r = n - 5y | r%3 | これまでのベストアンサー |
 | --- | --- | --- | --- |
 | 0 | 11 | 2 | 2 |
 | 1 | 6 | 0 | 0 |
 | 2 | 1 | 1 | 0 |

 最適な選択は y = 1 です。ここで、11 − 5 = 6 は 3 で完全に割り切れるため、1 コインはゼロになります。 

これは重要なトレードオフを示しています。5 コインを使用すると、残りを 3 の倍数に完全に揃えることができます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        ans = n
        for y in range(n // 5 + 1):
            rem = n - 5 * y
            ans = min(ans, rem % 3)
        out.append(str(ans))
    return "\n".join(out)

 ## 特殊なケース

 n = 1 の場合、有効な 3 または 5 コインは存在しないため、アルゴリズムは y = 0 のみを評価します。剰余は 1 で、r % 3 = 1 となり、正しく 1 コインが 1 つ生成されます。 

n = 2 の場合も同じ状況が発生します。y = 0 のみが有効で、残りは 2 となり、答えは 2 になります。 

n = 3 の場合、ループには y = 0 が含まれ、r % 3 = 0 で剰余 3 が得られ、答えは 0 になります。 y = 1 は不可能ですが、正しい解は y = 0 ですでに見つかります。 

n = 8 の場合、y = 0 と y = 1 の両方が評価されます。 このアルゴリズムは、余り 8 (2 が得られる) と余り 3 (0 が得られる) を比較し、5 + 3 を介してゼロの 1 コインを正しく選択します。
