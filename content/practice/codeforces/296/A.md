 ## 解決策
 ## 問題の理解

 ヤロスラフは一連の整数を持っており、連続する 2 つの要素が等しくないように整数を再配置したいと考えています。 唯一許可されている操作は 2 つの隣接する要素を交換することです。彼は、この条件を満たす構成に到達できるかどうかを知りたいと考えています。 入力は配列の長さで構成されます。`n`、 に続く`n`配列を表す整数。 有効な再配置が存在する場合、出力は「YES」、それ以外の場合は「NO」になります。 

重要な制約は次のとおりです。`n`は最大 100 まで可能で、配列要素の値の範囲は最大 1000 です。`n`小さく、時間計算量が最大のアルゴリズム`O(n^2)`実現可能ですが、指数関数的または階乗的なものは何でも`n`やりすぎだろう。 配列値自体は時間計算量とはあまり関係がありません。 それらは出現回数を数える場合にのみ重要です。 

明らかではないエッジ ケースは、1 つの要素が頻繁に発生する場合に発生します。 たとえば、次の場合`n = 5`そして配列は`[1, 1, 1, 2, 3]`、要素`1`3回登場します。 これらを連続した重複なしに配置するには、それらを分離するために少なくとも 4 つの「スロット」が必要になりますが、これは不可能です。`n - max_count = 2`。 この場合、正解は「NO」です。 不注意なアプローチでは、頻度をチェックせずに要素を貪欲に並べ替えようとするだけで失敗する可能性があります。 

特殊なケースは次のような場合です`n = 1`。 任意の単一要素配列は要件を自明に満たすため、答えは「YES」です。 

## アプローチ

 ブルートフォース手法では、配列の可能なすべての置換を試し、それらのいずれかが連続差分条件を満たすかどうかをチェックします。 がある`n!`順列。 たとえ`n = 10`、これにより 300 万を超える順列が生成され、各順列をチェックするコストは次のようになります。`O(n)`、これは実用的ではありません`n = 100`。 

最適化するための重要な観察事項は、有効な配置を妨げる唯一の制約は、ある数値が頻繁に出現する場合であるということです。 最も頻繁に発生する要素があると仮定します。`max_count`回。 連続した重複を避けるために、この要素のすべての出現を他の要素とインターリーブする必要があります。 これは、他の要素の数が少なくとも`max_count - 1`。 正式には、「YES」の条件は次のとおりです。```
max_count <= (n + 1) // 2
```これは、最も頻繁に使用される要素を位置 0、2、4、... に配置し、残りのスロットを他の要素で埋めることができるため機能します。 最頻値要素が次を超える場合`(n + 1) // 2`、最適な配置であっても、同一の要素の連続するペアが少なくとも 1 つ残ります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | お(ん!) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(1000) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む`n`そして配列`a`。 
2. 配列内の各要素の頻度を数えます。 これは、要素値でインデックス付けされた辞書または配列を使用して実行できます。 
3. 最大周波数を特定します。`max_count`。 
4. 比較する`max_count`に`(n + 1) // 2`。 もし`max_count`より大きい`(n + 1) // 2`、この要素のすべての出現を分離することは不可能であるため、「NO」を出力します。 
5. それ以外の場合は、要素を適切にインターリーブすることによって有効な配置が存在するため、「YES」を出力します。 

機能する理由: このアルゴリズムは、繰り返される要素を分離するために使用できるスロットの数が次のとおりであるという不変条件を維持します。`n - max_count + 1`。 最も頻繁に使用される要素が重複することなくこれらのスロットに収まる場合、残りの要素はギャップを埋めることができ、連続した重複がないことが保証されます。 これは必要かつ十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import Counter

n = int(input())
a = list(map(int, input().split()))

freq = Counter(a)
max_count = max(freq.values())

if max_count <= (n + 1) // 2:
    print("YES")
else:
    print("NO")
```このソリューションでは、まず入力を効率的に読み取ります。`sys.stdin.readline`。 使用回数のカウント`Counter`標準ライブラリから取得します。これはシンプルであり、値の範囲を事前定義せずにスパース配列を処理します。 計算中`(n + 1) // 2`奇数の正しい天井分割を保証します`n`。 比較により、不可能なケースのみが拒否されることが保証されます。 条件は純粋にカウントに依存するため、並べ替えや再配置は必要ありません。

## テストケース```python
import sys, io
from collections import Counter

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    a = list(map(int, input().split()))
    freq = Counter(a)
    max_count = max(freq.values())
    return "YES\n" if max_count <= (n + 1) // 2 else "NO\n"

# Provided samples
assert run("1\n1\n") == "YES\n", "sample 1"
assert run("5\n1 1 1 2 3\n") == "YES\n", "sample 2"
assert run("4\n1 1 1 2\n") == "NO\n", "sample 3"

# Custom cases
assert run("2\n1 1\n") == "YES\n", "2 elements same"
assert run("3\n2 2 2\n") == "NO\n", "3 identical elements"
assert run("6\n1 1 2 2 3 3\n") == "YES\n", "perfectly interleavable"
assert run("7\n1 1 1 1 2 3 4\n") == "NO\n", "most frequent exceeds (n+1)//2"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 2\n1 1 | はい | 要素が繰り返される最小サイズの入力 |
 | 3\n2 2 2 | いいえ | すべての要素が同一 |
 | 6\n1 1 2 2 3 3 | はい | 配列は完全にインターリーブ可能 |
 | 7\n1 1 1 1 2 3 4 | いいえ | 最も頻繁に使用される要素が許容数を超えています |

 ## 特殊なケース

 いつ`n = 1`、アルゴリズムはすぐに「YES」を返します。`(1 + 1)//2 = 1`単一要素の頻度は 1 です。次のように、すべての要素が同一である配列の場合、`[2, 2, 2]`、周波数は 3 ですが、`(n+1)//2 = 2`、「NO」をトリガーします。 最も頻繁に使用される要素が位置のちょうど半分または半分を下回る配列は、次の理由により正しく処理されます。`(n+1)//2`天井分割を実装します。
