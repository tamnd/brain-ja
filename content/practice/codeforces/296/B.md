 ## 解決策
 ## 問題の理解

 同じ長さの 2 つの数字列が与えられていますが、一部の位置には、次のように表される未知の文字が含まれている可能性があります。`?`。 それぞれ`?`以下の任意の数字に独立して置き換えることができます。`0`に`9`、異なる位置での選択は相互作用しません。 

すべての未知数を修正した後、次の長さの 2 つの具体的な数字列を取得します。`n`。 完成した文字列の各ペアについて、一方の文字列がどこでも他方の文字列よりも優勢である場合、つまり、厳密に大きくなることはなく、どこかで厳密に小さくなったり、その逆も起こらないことを意味します。 「比較不可能」であるための条件は、厳密な利点の両方の方向が位置をまたがるどこかに現れることです。つまり、最初の文字列が大きいインデックスと 2 番目の文字列が大きいインデックスが存在します。 

タスクは、両方のテンプレートの完了数が比較不可能なペア (モジュロ 1e9 + 7) を生成する回数をカウントすることです。 

重要な制約は、`n ≤ 10^5`これにより、位置ごとの桁の違いによって増大する二次空間または状態空間が除外されます。 どのソリューションでも、各位置を一定時間または一定数の状態で処理する必要があり、必然的に線形 DP または組み合わせプレフィックス集約が行われます。 

よくある微妙な失敗のケースは、「あるポジションでの局所的な優位性」と「グローバルな比較可能性」が混ざることから発生します。 たとえば、次のような 2 つの文字列`10`そして`01`一方がインデックス 1 で勝ち、もう一方がインデックス 2 で勝つため比較できませんが、ポジションごとの比較を貪欲に解釈すると、合計または最初の差のみが考慮される場合、誤って比較可能なものとしてラベル付けされる可能性があります。 

別の失敗例は、未知の要素が非対称的な柔軟性を生み出すときに発生します。 例えば、`?0`対`00`割り当てに応じて、比較可能な結果と比較できない結果の両方が生成される可能性があり、グローバルな方向制約を追跡せずに各位置を独立して処理すると、過大なカウントにつながります。 

## アプローチ

 ブルート フォース手法では、両方のテンプレートのすべての数字の割り当てが試行されます。 各ポジションには独立して最大 10 個の選択肢があるため、次のようになります。`10^(2n)`最悪の場合の可能性も。 たとえ`n = 10^5`、これは完全に不可能であり、`n = 10`それはすでに大きいです。 

重要な観察は、最終的な分類は、次の位置が少なくとも 1 つ存在するかどうかのみに依存するということです。`s > w`そして少なくとも 1 つは`s < w`。 これは、いずれかの方向で厳密な利点がすでに確認されているかどうかを維持しながら、位置ごとに比較を追跡することを示唆しています。 

文字に応じて、各位置で割り当てによって生成される数を数えることができます。`s[i] > w[i]`、何個生産しますか`s[i] < w[i]`、そしてどれだけの数が平等を生み出しますか。 文字列を構築する代わりに、3 状態 DP の遷移を集約します。これまでに違いが見られなかったか、見られたか`s > w`、見た`s < w`、またはその両方 (有効な状態を吸収)。 

これにより、問題は線形スキャンに縮小され、各位置が組み合わせカウントによって重み付けされた一定サイズのステート マシンを更新します。

 ## アルゴリズムのチュートリアル

 現在のプレフィックスまでに観察されたものを記述する 4 つの概念状態にわたる DP を維持します。 

状態を次のようにします。 

-`00`: 厳密な比較はまだ行われていません
 -`10`: 私たちは次のような位置を見てきました。`s > w`-`01`: 私たちは次のような位置を見てきました。`s < w`-`11`：両方向が見られている（有効な吸収状態）

 それぞれの立場について、それが平等にどのように寄与するかを計算します。`s > w`、 または`s < w`。 

### 1. ポジションごとの貢献度のカウント

 インデックスごとに`i`、キャラクターを調べます`a = s[i]`、`b = w[i]`。 

両方が数字の場合、結果は 1 つだけあり、等しいか大きいか小さいかのいずれかに影響します。 

どちらかまたは両方が該当する場合、`?`、桁のペアの数を数えます`(x, y)`それぞれの関係を生み出します。 これは純粋に数字の組み合わせです`0..9`。 

このステップが必要なのは、割り当てをグローバルに反復するのではなく、各位置のすべての割り当てをカウントに圧縮するためです。 

### 2. DP トランジションのセットアップ

 プレフィックスを処理した後、各状態になるウェイの数を最大で維持します。`i`。 

最初に:

 -`dp[00] = 1`- 他はゼロです

 これは、文字を処理する前に比較が観察されていないことを反映しています。 

### 3. 等価遷移による更新

 位置にある場合`i`同じ数字を割り当てても、グローバル状態は変わりません。 すべての DP 状態には、等価割り当ての数が乗算されます。 

これにより、新しい情報を導入することなく、比較に関する現在の知識が保存されます。 

### 4. 厳密な比較遷移による更新

 もし`s[i] > w[i]`、その後:

 - 状態`00`に移行します`10`- 州`01`に移行します`11`- 州`10`滞在します`10`- 州`11`滞在します`11`同様に、`s[i] < w[i]`、対称トランジションが適用されます。 

このステップは重要なロジックをエンコードします。つまり、両方向が出現すると、永久に有効なままになります。 

### 5. 最終的な回答の抽出

 すべての位置を処理した後、状態のみを表示します`11`非比較には少なくとも 1 つが必要であるため、答えに貢献します。`s > w`そして少なくとも1つ`s < w`。 

### なぜ効果があるのか

 このアルゴリズムは、両方の比較方向をすでに確認したかどうかという観点から、すべてのプレフィックス割り当ての完全な概要を維持します。 各位置は、等しい、大きい、または小さいという 3 つの結果のいずれかに正確に寄与するため、数字の割り当てはこれらの状態を通る 1 つのパスに正確に対応します。 遷移は方向が以前に見られたかどうかのみに依存するため、将来の決定によって以前に見られた比較を元に戻すことはできず、DP がすべての割り当ての正しい圧縮になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def count_rel(a, b):
    if a != '?' and b != '?':
        a = int(a)
        b = int(b)
        if a == b:
            return (1, 0, 0)
        elif a > b:
            return (0, 1, 0)
        else:
            return (0, 0, 1)

    res_eq = res_gt = res_lt = 0

    for x in range(10):
        for y in range(10):
            if a != '?' and x != int(a):
                continue
            if b != '?' and y != int(b):
                continue
            if x == y:
                res_eq += 1
            elif x > y:
                res_gt += 1
            else:
                res_lt += 1

    return res_eq, res_gt, res_lt

def solve():
    n = int(input())
    s = input().strip()
    w = input().strip()

    dp00 = 1
    dp10 = 0
    dp01 = 0
    dp11 = 0

    for i in range(n):
        eq, gt, lt = count_rel(s[i], w[i])

        ndp00 = ndp10 = ndp01 = ndp11 = 0

        ndp00 = dp00 * eq % MOD

        ndp10 = (dp00 * gt + dp10 * eq + dp10 * gt + dp01 * gt) % MOD
        ndp01 = (dp00 * lt + dp01 * eq + dp01 * lt + dp10 * lt) % MOD

        ndp11 = (dp11 * (eq + gt + lt) + dp10 * lt + dp01 * gt) % MOD

        dp00, dp10, dp01, dp11 = ndp00, ndp10, ndp01, ndp11

    print(dp11 % MOD)

if __name__ == "__main__":
    solve()
```コードは、位置ごとに、等しい、大なり、小なりの関係を生成する桁の割り当ての数を計算することから始まります。 これにより、後で個々の数字の選択について検討する必要がなくなります。 

次に、DP は 4 つの州を追跡します。`dp00`観察された差はありませんが、`dp10`そして`dp01`厳密な不等式を一方向のみで見たことを表し、`dp11`は両方向がすでに出現していることを表します。 各遷移では、以前の状態カウントと位置ごとの関係カウントが結合されます。 

微妙な点は、`dp10`そして`dp01`現在の方向の状態を保存する等式のケースを含める必要がありますが、反対の不等号が現れた場合には新しい遷移も許可します。 の`dp11`両方の方向が存在すると、位置を追加しても非比較性を無効にできないため、状態はすべての遷移を吸収します。

 ## 特殊なケース

 重要なエッジ ケースは、桁が固定されているため、一方の文字列が他方の文字列を決して超えることができない場合です。 例えば：```

もう 1 つのケースは、完全なワイルドカード入力です。```

```すべての位置は、等しいか、大きいか、小さい場合があります。 DP は多くの混合パスを蓄積し、少なくとも 1 つの位置が寄与するパスのみを蓄積します。`>`そしてもう一人が貢献する`<`到着`dp11`。 遷移構造により、等価のみのパスが誤って有効状態に入ることはありません。
