 ## 解決策
 ## 問題の理解

 ゲームは正の整数の列でプレイされます。 アリスが先に動きます。 ターンでは、プレイヤーは 1 より大きい公約数を持つ 2 つの隣接する数字を選択します。 選択したペアは、両方の数値を最大公約数で割ることによって単純化されます。 隣接するペアが約数を共有しない場合、現在のプレーヤーは正当な手を持たず、負けます。 

タスクは、最終的な配列自体を見つけることではなく、どのプレイヤーが負けた位置に到達するかだけです。 入力は行の長さとその行の初期値で構成されます。 出力は、最適なプレイで勝利したプレーヤーの名前です。 

数値は次のように大きくなります。$10^9$、しかし、それらは50個しかありません。 手の順序によって多くの可能な状態が作成されるため、ゲームを直接検索することはできません。 ただし、各演算では配列から厳密に素因数が削除されます。 せいぜい数字$10^9$多重度を持つ素因数が最大 29 個含まれるため、可能な削除の総数は少なくなります。 これは、すべてのゲーム状態を探索するのではなく、単調なプロセスを探すことを示唆しています。 

重要な観察は、移動するたびに配列内の素因数情報の総量が減少するということです。 より正確には、移動によって 2 つの数値が gcd で除算される場合、削除されたすべての素因数が両方の数値から消えます。 どの操作でも、隣接するものの間に新しい公約数を導入することはできません。 この単調な動作のため、ゲームには手数の同等性に対する戦略的分岐効果がありません。 一連の正当な手は、同じ回数の手の後に同じ最終状態に達します。 

よくある間違いは、別のペアを選択すると勝者が変わる可能性があると考えることです。 たとえば、次のようになります。```
3
2 6 3
```最初のペアを選択すると、`[1, 3, 3]`, すると、さらにもう一手が可能になります。 2 番目のペアを選択すると、`[2, 2, 1]`、そして再びもう1つの動きが可能になります。 どちらのパスも 2 つの移動が必要なので、ボブが勝ちます。 

もう 1 つのエッジ ケースは、すべての隣接するペアがすでに互いに素である場合です。```
2
5 7
```答えは、`Bob`, なぜならアリスは全く行動を起こせないからです。 少なくとも 1 つの操作が存在することを前提としたソリューションでは、移動が誤ってカウントされます。 

最後の微妙なケースは、1 つの操作で複数の素因数を一度に削除する場合です。```
2
60 30
```gcd は 30 なので、この移動により直接次のものが作成されます。`[2, 1]`。 完全な gcd ではなく、共通の素数を 1 つだけカウントすると、移動数が過大評価されてしまいます。 

## アプローチ

 ブルートフォースアプローチは、隣接する数字のあらゆる選択肢をゲームツリーの分岐として扱うことです。 状態ごとに、すべての正当な手を再帰的に試し、相手を強制的に負け状態にする手が存在するかどうかを判断します。 これは公平なゲームでは正しいですが、ここではまったく現実的ではありません。 小さな配列でも多くの移動オーダーが存在する可能性があり、状態の数は指数関数的に増加します。 

重要な構造は、ゲームが実際にはミニマックスを必要としないことです。 すべての動きは素因数を削除するだけであり、それらを別のものに変えることはありません。 プロセス全体をリダクションを繰り返し適用するものとして見ると、隣接するすべてのペアが互いに素になるまで、リダクションの順序は必要なリダクションの数に影響を与えません。 

ブルートフォースは、最適なプレイの定義に従うため機能しますが、同じリダクションの同等の次数を多数探索するため失敗します。 プロセスが合流しているという観察により、ゲーム検索を単純なシミュレーションに置き換えることができます。 利用可能な手を繰り返し適用し、発生した手の数をカウントするだけです。 カウントが奇数の場合は、アリスが最後の行動をとります。 互角であれば、ボブが最後の動きをしました。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | 指数 | 遅すぎる |
 | 最適 |$O(n \cdot F)$|$O(1)$| 承認済み |

 ここ$F$最大移動数です。 一手ごとに 2 つの数から少なくとも 1 つの素因数が削除され、素因数の総数は少ないため、$F$有界である。 

## アルゴリズムのチュートリアル

 1. 配列を保存し、gcd が 1 より大きい隣接ペアを繰り返し検索します。 このようなペアは、両方の数値を減らすことができるため、合法的な動きを表します。 
2. 正当なペアが見つかったら、両方の数値を gcd で割って、移動カウンタを増やします。 すべての有効な選択は同じ最終移動パリティをもたらすため、選択した正確なペアは重要ではありません。 
3. 隣接するペアの gcd が 1 より大きくなるまで続けます。 次のプレイヤーに正当な手がないため、この時点でゲームは終了します。 
4. 手数が奇数の場合は、次のように出力します。`Alice`。 それ以外の場合は印刷します`Bob`。 

なぜ効果があるのか:

 アルゴリズムの背後にある不変条件は、配列が素因数を失うだけであるということです。 移動によって新しい除数関係を作成することはできないため、すべての法的操作は同じ削減プロセスの一部となります。 終端位置とリダクション数のパリティは手の順序とは無関係であるため、有効なシーケンスをカウントすると正しい勝者が得られます。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    moves = 0

    while True:
        changed = False

        for i in range(n - 1):
            g = math.gcd(a[i], a[i + 1])
            if g > 1:
                a[i] //= g
                a[i + 1] //= g
                moves += 1
                changed = True
                break

        if not changed:
            break

    print("Alice" if moves % 2 else "Bob")

if __name__ == "__main__":
    solve()
```ループは、一度に 1 つの利用可能な手を検索します。 重要なのは次の状態だけであり、どの特定の合法的な手が選択されたかではないため、各パスで最初に縮小が成功した後で停止します。 

gcd 計算では、Python の組み込みユークリッド アルゴリズムを使用し、最大の値を簡単に処理します。$10^9$。 gcd は選択された両方の数値を常に正確に除算するため、整数除算は安全です。 

考えられる唯一の実装上の間違いは、gcd 1 が正当な動きではないことを忘れていることです。 1 で割ると状態が変化しないため、無限ループが作成されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(n \cdot F)$| 各反復で行をスキャンし、$F$削減数です。 |
 | スペース |$O(1)$| 入力配列とカウンターのみが保存されます。 |

 移動するたびに素因数が永久に削除されるため、削減の最大数は小さくなります。 と$n \le 50$最大でも値$10^9$、シミュレーションは簡単に制限に適合します。 

## テストケース```python
import sys
import io
import math

def run(inp: str) -> str:
    data = inp.strip().split()
    n = int(data[0])
    a = list(map(int, data[1:]))

    moves = 0
    while True:
        ok = False
        for i in range(n - 1):
            g = math.gcd(a[i], a[i + 1])
            if g > 1:
                a[i] //= g
                a[i + 1] //= g
                moves += 1
                ok = True
                break
        if not ok:
            break

    return ("Alice" if moves % 2 else "Bob") + "\n"

assert run("3\n2 4 2\n") == "Bob\n", "sample 1"
assert run("4\n3 9 6 18\n") == "Alice\n", "sample 2"

assert run("2\n5 7\n") == "Bob\n", "no moves"
assert run("2\n60 30\n") == "Alice\n", "large gcd removal"
assert run("5\n2 2 2 2 2\n") == "Bob\n", "repeated equal values"
```| テスト入力 | 期待される出力 | 検証内容 |

 |`5 7`| ボブ | 最初の負けポジションを確認します。 |

 ## 特殊なケース

 この場合の場合:```
2
5 7
```アルゴリズムは隣接するペアのみをスキャンし、1 に等しい gcd を検出し、移動は実行しません。 カウンタはゼロのままなので、ボブが勝ちます。 

この場合の場合:```
3
2 6 3
```アルゴリズムは、隣接するペアのいずれかを選択します。 選択する`[2,6]`作成します`[1,3,3]`、次のパスでは最後のペアの gcd が削除されます。 選択する`[6,3]`作成します`[2,2,1]`、続いてもう1つの削減が続きます。 どちらのパスも同じパリティを持っているため、結果は依然として Bob になります。 

この場合の場合:```
2
60 30
```gcd は 30 であり、素因数は 1 つだけではありません。 操作により生成されるのは、`[2,1]`すぐに。 アルゴリズムは 1 つの手をカウントし、正しくアリスを返します。
