 ## 解決策
 ## 問題の理解

 このタスクでは、都市の有向非循環グラフを再構築するように求められます。 市`m`すべての出荷元です。 あらゆる都市に`i`、私たちに与えられているのは`D[i]`、で始まるさまざまな有向パスの数`m`そしてで終わります`i`。 これらのパス数を正確に作成する有向道路のセットを出力する必要があります。 グラフは非周期的である必要があり、同じ都市のペア間の複数の道路を含めることはできません。 元のステートメントでは、これを、収集されたルート数から可能な出荷マップを構築すると説明しています。 

重要な観察は、都市のルートの数は、その都市に入る道路によって完全に決定されるということです。 都市から入ってくるすべての道路`u`すでに到達しているすべてのパスに貢献します`u`したがって、都市に近隣住民が入ってくるとします。`p1, p2, ...`、その値は次を満たす必要があります。`D[v] = D[p1] + D[p2] + ...`グラフは非巡回であるため、都市のすべての親のパス数は小さくなる必要があります。 値がゼロの都市にはソースから到達できず、進入道路がないはずです。 ソース都市自体にはそれ自体へのパスが 1 つだけあり、空のパスなので、その値は 1 でなければなりません。 

限界`n <= 60`は小さいですが、の値は`D`と同じ大きさにすることができます`2^62`, そのため、値の数値サイズに依存するアルゴリズムは不可能です。 カウントを拡張したり、パスを列挙したり、値に対して動的プログラミングを使用したりすることはできません。 この構築には、グラフの構造と都市が 60 しかないという事実を利用する必要があります。 

重要なエッジ ケースは、値が 0 の都市、値が 1 の都市、および値の繰り返しです。 値がゼロの都市が誤ってエッジを受け取ってはなりません。 例えば：```
n = 3, m = 1
D = [1, 0, 0]
```正しいグラフには道路がありません。 市内からの道路を追加する`1`街へ`2`すぐに 1 つのパスを作成し、`D[2]`正しくない。 

繰り返される値は慎重に扱う必要があります。 例えば：```
n = 4, m = 1
D = [1, 1, 1, 3]
```最後の都市には、直接のソース寄与の他に、ソースからの 2 つのパスが必要です。 両方のバリューワン都市をそれに接続すると、3 つのパスが得られます。 構築順序を考慮せずに等しい値を交換可能として扱うと、サイクルや無効な親の選択が作成される可能性があります。 

## アプローチ

 直接的なアプローチでは、各都市の進入道路を個別に決定しようとします。 価値ある街へ`x`、以前のすべての都市を検索し、パス数の合計が次のようなサブセットを見つけます。`x`。 ノードに入るパスの数は、その親のパス数の合計に正確に一致するため、これは正しいです。 ただし、すべてのサブセットを試すには指数関数的な時間が必要です。 60 の都市がある場合、最悪のケースでは以下の点を考慮する必要があります。`2^60`限界をはるかに超えた可能性。 

有益な観察は、一般的な部分集合和の問題を解く必要がないということです。 指定されたパス数は DAG から取得されます。これは、すべての値がすでに以前の都市の値に分解できることを意味します。 パス数の昇順に都市を処理すると、親となる可能性のあるすべての都市がすでに処理されています。 必要な合計に達するまで、利用可能な最大の小さい値を貪欲に取得できます。 

有効な入力の場合、この貪欲な分解は、利用可能な最大の小さい値で残りの量をカバーできない場合、それ以降の小さい値も役に立たないため、機能します。 ソートされた順序では、欠落しているすべての部分が現在の都市の前に出現する必要があるという特性が保持されます。

 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | 最適 | O(n^2) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ソース都市を確認し、パス数が正の都市をすべて収集します。 値が 0 の都市は、到達不可能なままでなければならないため、無視されます。 
2. 正の値の都市をパス数に基づいて並べ替えます。 それらを小さな値から大きな値まで処理すると、都市を構築するときに、考えられるすべての親がすでに利用可能であることが保証されます。 
3. ソースを除くすべての都市について、パス数の合計が必要な値に達する以前の都市を検索します。 これらの親都市からの有向エッジを現在の都市に追加します。 
4. 親を見つけるには、パス カウントの最大のものから前の都市をスキャンします。 都市の値が残高を超えない場合は、それを親として使用し、残高から差し引きます。 
5. 収集したすべての道路を出力します。 

不変条件は、ソートされた都市のプレフィックスを処理した後、処理されたすべての都市がソースからの必要な数のパスをすでに正確に持っているということです。 新しい都市が追加されると、その入ってくるエッジは選択された以前のパス数に正確に寄与するため、新しい都市の値も正確になります。 すべてのエッジは小さい値から大きい値に移行するため、サイクルは表示されません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    d = list(map(int, input().split()))

    src = m - 1
    nodes = [(d[i], i) for i in range(n) if d[i] > 0]
    nodes.sort()

    pos = {}
    for idx, (_, v) in enumerate(nodes):
        pos[v] = idx

    edges = []

    for idx, (val, v) in enumerate(nodes):
        if v == src:
            continue

        need = val
        for j in range(idx - 1, -1, -1):
            if nodes[j][0] <= need:
                edges.append((nodes[j][1] + 1, v + 1))
                need -= nodes[j][0]
            if need == 0:
                break

    print(len(edges))
    for a, b in edges:
        print(a, b)

if __name__ == "__main__":
    solve()
```このコードはまず、到達不能な都市を考慮から除外します。 これらはソースからのパスがないため、ルート数に寄与できません。 

ソートされたリストには、パス数と都市インデックスのペアが格納されます。 このリストのループは、アルゴリズムからの構築順序です​​。 必要な価値を持つ都市の場合`val`、変数`need`まだ作成する必要があるパスの数を追跡します。 選択されたすべての親はそのパス全体の数に寄与するため、その値を減算すると、パス数の式が正確に反映されます。 

ソース都市の値は空のパスによってすでに定義されているため、ソース都市はスキップされます。 エッジの方向は常に、先にソートされた都市から後の都市へ向かうため、循環が防止されます。 Python の整数は、`2^62`range を直接扱うため、オーバーフロー処理は必要ありません。

## 特殊なケース

 到達できない都市の場合、アルゴリズムはそれらの都市を並べ替えられたポジティブ リストに入れません。 のために：```
3 1
1 0 0
```ソース以外の都市は処理されないため、出力には道路が含まれず、パス数は正しいままになります。 

ソースの直接の子の複数の場合:```
4 1
1 1 1 3
```2 つの価値 1 都市はどちらも、価値 3 都市が建設される前に利用可能です。 アルゴリズムは、それらをソース寄与とともに使用して、必要な 3 つのルートを作成します。 

より大きな値が繰り返される場合:```
5 1
1 1 1 2 4
```価値 2 の都市は 2 つの価値 1 の都市から作成され、価値 4 の都市はより小規模に建設された都市を使用できます。 昇順に処理することで、必要になる前にすべての可能な親が利用可能になることが保証されます。
