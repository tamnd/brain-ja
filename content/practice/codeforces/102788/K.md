 ## 問題の理解

 この問題は、いくつかのチームが古典的な 3 ロッドのハノイの塔の解決策を実行している間の中間位置を示します。 各チームはまったく同じ再帰的手順に従い、すべてのチームを移動させました。`N`ロッドからのディスク`A`ロッドに`B`。 すべてのチームに、次の長さの文字列が与えられます。`N`、位置の文字`i`ディスクの現在のロッドを説明します`i`、ディスク付き`1`最小のものとディスク`N`最大であること。 タスクは、どのチームがプロセスで最も進んでいるかを判断することです。つまり、記録された構成が独自の最適なシーケンスで最も新しく見えるチームを意味します。 複数のチームが同じ構成である場合は、その中の最初のチームを選択する必要があります。 

到達できるディスクの数`1000`、チーム数も到達可能`1000`。 総移動数は、`2^N - 1`したがって、シーケンス全体を保存したりシミュレートしたりすることは、たとえ中程度の規模のものであっても不可能です。`N`。 直接シミュレーションはすでに役に立たなくなっています`N = 60`, 通常の制限時間内で処理できる手数を超えているためです。 ソリューションは大まかに機能する必要があります`O(NM)`入力自体に次のものが含まれるため、時間`NM`文字。 

最初の注意が必要なケースは、移動カウントが直接保存されず、標準の整数型に適合できないことです。 たとえば、`N = 1000`、答えには約 1,000 ビットが必要になる場合があります。 構成を通常の整数に変換するソリューションでは、オーバーフローが発生したり、膨大な演算に不必要な時間が費やされたりします。 

もう 1 つのエッジ ケースは、複数のチームが同じ状態にある場合です。 例えば：```
2 3
AA
BB
BB
```正しい出力は次のとおりです。```

```最後の 2 チームはどちらもパズルを完成させましたが、最初に出現したものを選択する必要があります。 回答を更新する不注意な実装`>=`だけではなく`>`誤ってチームを返してしまう`3`。 

2 番目のエッジ ケースは初期構成です。```

AAA
```正しい出力は次のとおりです。```
1
```最初の状態は移動に対応します`0`。 少なくとも 1 つのディスクが移動したことを前提とした実装では、この構成が誤って分類される可能性があります。 

## アプローチ

 簡単なアプローチは、ハノイ プロセスのすべての構成を生成し、生成された各状態をチームの状態と比較することです。 再帰的手順は、それぞれの動きが事前にわかっているため、シミュレーションが簡単です。 問題は、シーケンスが`2^N`州。 のために`N = 1000`、これは考えられる限界をはるかに超えています。 ナノ秒ごとに 1 つの動きを生成したとしても、このアプローチは実用的ではありません。 

重要な観察は、古典的なハノイシーケンスが再帰的な構造を持っているということです。 解くとき`N`からのディスク`A`に`B`、動きの前半は解決します`N-1`からのディスク`A`に`C`、次にディスク`N`から移動します`A`に`B`、残りは`N-1`ディスクの移動元`C`に`B`。 これは、最大のディスクの位置によって、シーケンスのどの半分に現在の状態が含まれているかがすぐにわかることを意味します。 

最大の円盤がまだソースロッド上にある場合、答えは前半のどこかにあります。 それが目的のロッド上にある場合、答えは後半にあり、ロッドの役割を交換して小さいディスク上で再帰的に続行するだけで済みます。 シーケンス全体を構築する代わりに、移動番号のバイナリ表現を再構築します。 各ディスクは、そのディスクが移動した瞬間がすでに起こったかどうかを示す 1 ビットに寄与します。 

ハノイ シーケンスが決定的であるため、ブルート フォース手法は機能しますが、シーケンスが指数関数的に増大するため失敗します。 再帰的な構造により、問題を各ディスクを 1 回調べるだけで済みます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |`O(2^N)`|`O(N)`| 遅すぎる |
 | 最適 |`O(NM)`|`O(N)`| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各チームの構成について、最大のディスクと元のハノイ パラメータから開始します: ロッドから移動`A`ロッドに`B`ロッドを使って`C`。 
2. 現在の最大のディスクの位置を確認します。 それがまだソースロッド上にある場合、移動番号は再帰シーケンスの前半に属しているため、現在のビットは次のようになります。`0`。 次の再帰的問題は、残りのディスクを同じソースから補助ロッドに移動することです。 
3. 最大のディスクが目的のロッド上にある場合、移動番号は後半に属します。 現在のビットは`1`、残りのディスクは、補助ロッドから目的のロッドに移動する 2 番目の再帰フェーズで考慮する必要があります。 
4. すべてのディスクの処理が完了するまで続行します。 ビットのシーケンスは移動番号を表します。 巨大な整数を構築する代わりに、これらのビット文字列を最上位側から比較します。 
5. チームを最大のバイナリ移動表現で維持します。 厳密に大きい値が見つかった場合にのみ現在の答えを置き換えます。これにより、同点の場合には最初のチームが自動的に保持されます。 

これが機能する理由は、最大のディスクが最適解全体の中でちょうど 1 回位置を変更するためです。 その移動の前に、すべての構成が最初の再帰ブロックに属している必要があります。 この移動の後、すべての構成は 2 番目の再帰ブロックに属します。 より小さいディスクに対してこの引数を繰り返すと、シーケンス内のすべての状態の位置が一意に決定されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def get_bits(state):
    n = len(state)
    src, dst, aux = 'A', 'B', 'C'
    bits = []

    for disk in range(n - 1, -1, -1):
        pos = state[disk]
        if pos == src:
            bits.append('0')
            src, dst, aux = src, aux, dst
        else:
            bits.append('1')
            src, dst, aux = aux, dst, src

    return ''.join(bits)

def solve():
    n, m = map(int, input().split())

    best_team = 1
    best = None

    for i in range(1, m + 1):
        state = input().strip()
        value = get_bits(state)

        if best is None or value > best:
            best = value
            best_team = i

    print(best_team)

if __name__ == "__main__":
    solve()
```機能`get_bits`再帰なしで再帰的推論を実行します。 ループは、移動番号の最上位ビットを決定するため、最大のディスクから開始されます。 最大のディスクから最小のディスクへの処理は、再帰呼び出しによって下降することと同じです。 

現在のディスクがソース ロッド上にあるときは、移動はまだ行われていないため、対応するビットは`0`。 The smaller disks are still in the first recursive phase, which changes the auxiliary rod into the temporary destination. When the disk is on the destination rod, the move has happened, so the bit is`1`、ロッドの役割が変化して第 2 フェーズが説明されます。 

すべての状態が正確に結果を生成するため、比較は文字列に対して行われます。`N`ビット。 Equal-length binary strings compare correctly lexicographically, with`1`より大きいこと`0`したがって、大きな整数の変換は必要ありません。
