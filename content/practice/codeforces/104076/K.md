 ## 解決策
 ## 問題の理解

 1 から n までの整数の順列が与えられます。 左から右に数字を読み、各数字を確認したら、すぐにそれを m 個のスタックの 1 つに配置する必要があります。 配置は永続的なため、要素がスタックにプッシュされると、そのスタック全体がポップされるまでそこに残ります。 

すべてのプッシュが完了したら、ポップを開始できます。 ルールは、スタックを選択し、空になるまでそこからポップし続け、空になったときのみ別のスタックに切り替えることができるというものです。 スタックがポップされている間、スタックは標準の後入れ先出し方式で動作します。 

目標は、グローバル出力シーケンスが正確に 1、2、3、最大 n になるように、要素をスタックに割り当てる方法とスタック ポップの順序を選択することです。 これを実現するには、スタックの数をできるだけ少なくしたいと考えています。 

テスト全体で n が 5×10^5 までという制約は、テストごとに O(n log n) または O(n) のアプローチが必要であることを意味します。 すべてのスタック割り当てをシミュレートしたり、パーティションを検索しようとしたソリューションは、O(n^2) でさえ実現可能な制限をはるかに超えているため、すぐに失敗します。 

微妙な問題は、ポップフェーズがスタック境界によって制限されていることです。 スタックを選択した場合は、切り替える前にスタックを完全に空にする必要があります。 これにより、単一スタック内の要素が値において相互にどのように関係しなければならないかについて、強力な順序制約が作成されます。 

制約を明らかにする小さな例は、順列 [3, 1, 2] です。 3 と 1 をプッシュ順序で同じスタックに入れようとすると、プッシュ シーケンス [3, 1] が得られ、これは [1, 3] としてポップされます。 これは、必要なグローバル順序 1、2、3 で現れることはできません。これは、3 が 2 の前に、他のスタックに対して間違った場所に現れるためです。 このタイプの逆転が最も難しい点です。 

## アプローチ

 この問題を考える強引な方法は、n 個の要素のそれぞれを m 個のスタックの 1 つに割り当て、ポップ フェーズをシミュレートして、並べ替えられた出力が得られるかどうかを確認することです。 固定割り当ての場合でも、正確さを検証するにはスタックの動作をシミュレートし、各ステップで次に必要な番号が空にすることを選択したスタックの先頭に表示されることを確認する必要があります。 割り当ての数は最悪の場合でも m^n であり、m を制限してもこれは実現できません。 

重要な簡素化は、単一のスタックがどのような構造を強制するかを検討することで実現します。 1 つのスタック内では、要素はプッシュ順序とは逆にポップされます。 最終出力は 1 から n に増加する必要があるため、各スタック内の逆プッシュ順序自体も増加する必要があります。 これは、スタック内のプッシュ順序を見ると、値が厳密に減少するシーケンスを形成する必要があることを意味します。 

したがって、各スタックには、到着時間に関して値が減少する順列のサブシーケンスを含めることが強制されます。 問題は分割タスクになります。つまり、順列を最小数の減少する部分列に分割します。 

これは古典的な双対性の結果です。 シーケンスを分割するために必要な減少するサブシーケンスの最小数は、最長の増加するサブシーケンスの長さに等しくなります。 直観的には、単一のスタックでは逆の場合に増加順序を保持できないため、増加するチェーンはすべて異なるスタックに配置する必要があると考えられます。 

したがって、スタックを明示的に構築する代わりに、指定された順列の LIS の長さを計算します。 その値がまさに答えです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース割り当てとシミュレーション | 指数 | O(n) | 遅すぎる |
 | 貪欲 + 二分探索による LIS | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 左から右へ順列を処理し、減少するサブシーケンスに対して可能な限り最良の「スタックトップ」を表す構造を維持します。 
2. それぞれの受信値 x について、スタックの順序が厳密に減少するようにスタックに配置したいと考えています。 これは、現在のトップが x より大きいスタックを見つけることと同じです。これは、x をより大きなトップの下に配置すると、プッシュ シーケンスの降順が保持されるためです。 
3. すべての有効なスタックの中で、x より大きい、可能な限り最小の最上位値を持つスタックを選択します。 この貪欲な選択により、将来のより大きな値に対してより大きな頂点を利用できるようになるため、将来の要素に対する柔軟性が維持されます。 
4. そのようなスタックが存在しない場合は、x で新しいスタックを開始します。 これは、減少する部分列の数を増やすことに対応します。 
5. スタックトップの配列をますますソートして維持します。 各更新では値が置き換えられるか、新しい値が追加されます。これは二分探索を使用して実装できます。 
6. すべての要素を処理した後、スタックの数はこの構造のサイズとまったく同じになります。 

この貪欲な選択が機能する理由は、各スタックが元の順序で減少するサブシーケンスを表すためです。 要素を常に最適な既存のスタックに配置することで、既存のスタックがその要素を収容できる場合でも、不必要な新しいスタックを作成することがなくなります。 

### なぜ効果があるのか

 どの時点でも、維持される構造は、処理されたプレフィックスから形成される減少するサブシーケンスの終了値の可能な最小限のセットを表します。 要素を配置するたびに、サブシーケンスを拡張するか、その終了値をより小さい値に置き換えて、将来の拡張のための余地を確保します。 これはまさに、逆順序解釈に適用される LIS 計算の忍耐ソート不変条件です。 したがって、必要なスタックの数は、強制分離の最長チェーンの長さとなり、これは順列の LIS 長に対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n = int(input())
        a = list(map(int, input().split()))

        piles = []

        for x in a:
            # we want first pile top > x, so we maintain increasing piles
            # use binary search on piles for first > x
            l, r = 0, len(piles)
            while l < r:
                mid = (l + r) // 2
                if piles[mid] > x:
                    r = mid
                else:
                    l = mid + 1

            if l == len(piles):
                piles.append(x)
            else:
                piles[l] = x

        print(len(piles))

if __name__ == "__main__":
    solve()
```実装は配列を維持します`piles`ここで、各エントリは、減少するサブシーケンスを終了するスタックの現在の最小の最上位値を表します。 二分探索により、頂点が現在の値より大きい最初の山が見つかります。これは、そのサブシーケンスを拡張するための正しい場所です。 

そのようなパイルが存在しない場合は、新しいスタックが作成されます。 答えが増えるのはこの場合だけです。 

## 実用的な例

 ### 例 1: 順列 [3, 2, 1]

 挿入するたびにパイルトップを追跡します。 

| ステップ | × | 前に山 | 選択された位置 | 後の山 |
 | --- | --- | --- | --- | --- |
 | 1 | 3 | [] | 新しい杭 | [3] |
 | 2 | 2 | [3] | 3 を置き換える | [2] |
 | 3 | 1 | [2] | 2を置き換える | [1] |

 最終的な山数は1です。 

これは、必要なプッシュ順序制約に直接一致するため、完全に減少する順列が 1 つのスタックに収まることを示しています。 

### 例 2: 順列 [1, 4, 2, 5, 3]

 | ステップ | × | 前に山 | 選択された位置 | 後の山 |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | [] | 新しい | [1] |
 | 2 | 4 | [1] | 新しい | [1、4] |
 | 3 | 2 | [1、4] | 4を置き換える | [1、2] |
 | 4 | 5 | [1、2] | 新しい | [1、2、5] |
 | 5 | 3 | [1、2、5] | 5を置き換える | [1、2、3] |

 最終的な答えは 3 です。 

これは、中間置換によって構造が維持され、不要な新しいスタックの作成がどのように防止されるかを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | 各要素はパイルトップで二分探索を使用します。 
| スペース | O(n) | 最悪の場合のパイルトップの保管 |

 すべてのテスト ケースにわたる n の合計は 5×10^5 であるため、O(n log n) 解は制限内に問題なく収まります。

 ## 特殊なケース

 [5、4、3、2、1] のような完全に減少する順列では、全体で 1 つの山が生成されます。 すべての新しい要素は以前の最上位を置き換えることができるため、追加のスタックが作成されることはありません。 

[1, 2, 3, 4] のような完全に増加する順列では、既存のスタック トップが現在の要素より大きくないため、アルゴリズムは各ステップで新しいパイルを作成するように強制されます。 同じ減少サブシーケンス内に 2 つの要素が共存できないため、これは n 個のスタックが必要になることに直接対応します。 

[2, 1, 4, 3] などの混合ケースは、置換によって不必要なスタックの作成がどのように回避されるかを示しています。 要素 1 が 2 を置き換え、その後 3 が 4 を置き換え、スタック数を最小限の 2 に保ちます。これはシーケンスの LIS 構造と一致します。
