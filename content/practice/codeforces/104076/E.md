 ## 解決策
 ## 問題の理解

 1 から n までの数値の順列と固定セグメント長 k が与えられます。 順列内の長さ k の連続ブロックごとに、その合計を計算します。 要件は、これらすべてのウィンドウの合計が同一のパリティを持つ必要があることです。これは、そのような合計が常に偶数か常に奇数であることを意味します。 

タスクは順列を構築することではなく、各テスト ケースに少なくとも 1 つの有効な順列が存在するかどうかを判断することだけです。 

制約は非常に大きく、n と k は最大 10^9、テスト ケースは最大 10^5 です。 順列をシミュレートしたり、ウィンドウを明示的に検査したりするソリューションは、直ちに不可能になります。 テスト ケースごとの線形スキャンでさえすでに遅すぎるため、答えは n と k の直接的な構造条件から得られる必要があります。 

k が 1 に等しい場合、微妙なエッジ ケースが発生します。各ウィンドウは 1 つの要素で構成されているため、条件により順列内のすべての値が同じパリティを共有するように強制されます。 n ≥ 2 の場合、1 から n への順列には常に奇数と偶数の両方が含まれるため、これは不可能です。 たとえば、n = 3 および k = 1 の場合、[1, 2, 3] のような順列はパリティを共有しないウィンドウ合計 1、2、3 を生成するため、正解は No になります。n = 1 および k = 1 の場合、ウィンドウは 1 つだけであるため、条件は自明に満たされ、答えは Yes になります。 

もう 1 つの潜在的な落とし穴は、k が大きいと常に条件が容易になると想定していることです。 たとえば、k = n の場合、ウィンドウは 1 つだけであるため、条件は順列に関係なく常に成立します。 

## アプローチ

 ブルートフォースの観点は、順列を選択し、長さ k のすべての部分配列をチェックすることから始まります。 各テスト ケースでは、n − k + 1 ウィンドウの合計を計算する必要があり、プレフィックスの合計が使用されない限り、それぞれに O(k) 時間がかかります。 プレフィックス合計を使用しても、各テストには依然として O(n) 時間がかかりますが、n が 10^9 に達する場合は不可能です。 

重要な簡素化は、隣接するウィンドウを比較することで実現します。 S_i を位置 i から始まる部分配列の合計とします。 連続するウィンドウ間の差は次のようになります。 

S_{i+1} − S_i = p[i+k] − p[i]。 

パリティのみを考慮するため、減算は 2 を法とする加算のように動作するため、すべての S_i が同じパリティを持つという条件が適用されます。 

p[i] ≡ p[i+k] (mod 2)。 

これは、ちょうど k 個の位置で区切られた要素が同じパリティを持つ必要があることを意味します。 したがって、配列は、k を法とするインデックスに基づいて k 個の独立したチェーンに分割され、各チェーンは完全に 1 つのパリティの番号で構成されなければなりません。 

そこで問題は次のとおりです。奇数スロットの総数が 1 ～ n の奇数整数の数と等しくなるように、これら k 個の位置グループのそれぞれにすべて奇数またはすべて偶数を割り当てることができるでしょうか。 

この時点で構造は単純になります。 k 個のグループのサイズの違いは最大 1 であり、どのグループが「奇数グループ」であるかを選択できます。 利用可能なグループ サイズは連続した構造 (floor(n/k) と ceil(n/k) のみ) を形成しているため、矛盾を強いられない限り、グループ サイズの目標合計はすべて達成できます。 

唯一の真の障害物は、k = 1 の場合に現れます。その場合、すべての位置を含む 1 つのグループが存在し、それは完全に奇数であるか、完全に偶数である必要があります。 そのためには、1 から n までのすべての数値が同じパリティを共有する必要がありますが、これは n = 1 でない限り不可能です。 

k ≥ 2 ごとに、どのグループが奇数を取るかを選択できる柔軟性は、必要な奇数整数の数と一致するのに十分です。

 ## アルゴリズムのチュートリアル

1. k が 1 に等しいかどうかを確認します。1 に等しい場合、条件により、置換内のすべての要素が同じパリティを持つことが強制されます。 これは、n が 1 に等しい場合にのみ可能です。これは、より大きな順列には奇数と偶数の両方が含まれるためです。 
2. k が 2 以上の場合、構築可能性は常に可能です。 パリティ制約は、インデックス クラス内の平等を法 k のみに強制し、これらのクラスには、必要なグローバル カウントに一致する方法で常に奇数および偶数の役割を割り当てることができます。 
3. k が 1 で n が 1 より大きい場合を除くすべての場合に「Yes」を出力します。 

### なぜ効果があるのか

 パリティ制約により、配列は独立したインデックス クラスに分割され、位置 i、i + k、i + 2k などにあるすべての要素がパリティを共有する必要があります。 これらのクラスは、有効性にとって重要な唯一の構造です。 クラスごとにパリティを自由に割り当てることができるため、問題は必要な奇数カウントを k 個の調整可能なグループに分割することになります。 この分割が不可能になるのは、グループが 1 つだけの場合であり、まさに k = 1 および n > 1 の場合に発生します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        if k == 1 and n > 1:
            print("No")
        else:
            print("Yes")

if __name__ == "__main__":
    solve()
```実装は構造的な結論を直接エンコードします。 唯一の条件付き分岐は、すべての要素が単一のパリティ クラスに存在する必要がある縮退ケースに対応します。 問題はモジュラーインデックスグラフに複数のコンポーネントがあるかどうかに完全に帰着するため、シミュレーションや構築は必要ありません。 

## 実用的な例

 ### 例 1

 入力: n = 4、k = 2

 インデックス (1,3) と (2,4) という 2 つのポジション クラスがあります。 各クラスは均一なパリティを持つ必要があります。 1 ～ 4 の奇数値の数は 2 であるため、1 つのクラスを奇数に割り当て、もう 1 つのクラスを偶数に割り当てることができます。 

| ステップ | 観察 |
 | --- | --- |
 | kチェック | k = 2 なので、複数のクラス |
 | パリティ要件 | 位置 i と i+2 はパリティを共有します。 
| 割り当て | 1 つのクラスは奇数、1 つは偶数 |
 | 結果 | 有効 |

 これは、クラス割り当ての柔軟性によりパリティ数のバランスがとれることを示しています。 

### 例 2

 入力: n = 3、k = 1

 すべてのポジションを含む 1 つのクラスがあります。 すべての要素はパリティを共有する必要がありますが、セット {1,2,3} には奇数と偶数の両方の値が含まれます。 

| ステップ | 観察 |
 | --- | --- |
 | kチェック | k = 1、単一クラス |
 | 制約 | すべての値は同じパリティを持つ必要があります。 
| 実現可能性 | n > 1 では不可能 |
 | 結果 | いいえ |

 これは、すべての構造が単一の強制パリティ グループに崩壊していることを示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = []
    t = int(sys.stdin.readline())
    for _ in range(t):
        n, k = map(int, sys.stdin.readline().split())
        if k == 1 and n > 1:
            output.append("No")
        else:
            output.append("Yes")
    return "\n".join(output)

# provided samples
assert run("3\n3 1\n4 2\n5 3\n") == "No\nYes\nYes"

# minimum edge case
assert run("1\n1 1\n") == "Yes"

# k = 1 impossible case
assert run("2\n2 1\n10 1\n") == "No\nNo"

# large k always yes
assert run("3\n10 10\n5 6\n7 100\n") == "Yes\nYes\nYes"

# mixed cases
assert run("4\n6 2\n6 3\n6 1\n1 5\n") == "Yes\nYes\nNo\nYes"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | n=1、k=1 | はい | 自明な基本ケース |
 | k=1,n>1 | いいえ | 単一パリティ クラス障害 |
 | k>=2 | はい | 一般的な実現可能性 |

 ## 特殊なケース

 最も重要なエッジ ケースは、k = 1 の場合です。この状況では、すべてのウィンドウが単一の要素であるため、順列内のすべての数値が同じパリティを共有する必要があります。 n > 1 の場合、順列には奇数と偶数の両方の値が含まれるため、これはすぐに失敗します。 アルゴリズムはこれを正しく識別し、「いいえ」を出力します。 

たとえば、入力 n = 2、k = 1 の場合、コードは特別な条件に入り、そのケースを拒否します。 ロジックをたどると、単一のクラスに両方の位置が含まれているため、両方の数値に同一のパリティが強制され、集合 {1, 2} の構造と矛盾します。 

k ≥ 2 の場合、k = n のような極端な値でも正しく動作します。 ウィンドウが 1 つしかないため、アルゴリズムはそれらを即座に受け入れ、パリティの競合は発生しません。
