 ## 解決策
 ## 問題の理解

 間隔のコレクションから始めます。 各間隔は、数直線上の連続した範囲を表します。 このプロセスでは、2 つの既存の間隔が 1 つの新しい間隔に繰り返しマージされます。 マージ中に、最初の間隔から 1 つと 2 番目の間隔から 1 つの実数を選択します。ただし、最初に選択した値が 2 番目の値より厳密に小さくなければならないという唯一の制限があります。 元の 2 つの間隔が削除され、これら 2 つの選択された値によって定義された新しい間隔が挿入され直されます。 

1 つの間隔だけが残るまでこれを繰り返した後、ペアと内部点の選択が異なると、最終的な間隔が異なる場合があります。 タスクは、個別の最終間隔をいくつ生成できるかを決定することです。 

したがって、問題はプロセスをシミュレートすることではなく、任意の数のそのようなマージの後に最終結果としてどのようなエンドポイントが表示されるかを理解することです。 

入力は複数のテスト ケースで構成されます。 各テスト ケースでは最大 100,000 の間隔が与えられ、それぞれの間隔には最大 10^9 の整数のエンドポイントが含まれます。 すべてのテスト ケースにわたって、間隔の合計数は最大 100,000 です。 

これにより、マージをシミュレートしたり、組み合わせを探索しようとするソリューションは即座に除外されます。 10^5 の 2 乗はすでに 10^10 の演算であるため、テスト ケースごとに n の二次関数であっても失敗します。 

微妙なエッジ ケースは、マージ操作によりエンドポイントだけでなく、間隔内の任意のポイントを選択できるという事実から生じます。 たとえば、間隔 [1, 100] と [2, 3] では、1 や 100 などのエンドポイントに制限されず、内部の実数値を選択できます。 エンドポイントのみを考慮する単純な解釈では、有効な構造を見逃してしまいます。 

もう 1 つの落とし穴は、プロセスが決定論的であるか、最終間隔が左の最小エンドポイントと右の最大エンドポイントによって一意に定義されると想定していることです。 これは誤りです。マージ順序が異なると、どの値を繰り越せるかが制限される可能性があるからです。 

## アプローチ

 強引なアイデアは、マージ プロセスをシミュレートすることです。 各ステップで 2 つの間隔を選択し、x と y の可能な選択肢をすべて列挙し、結果の間隔を追跡します。 これは、マージごとに選択肢の連続が導入され、エンドポイントへの離散化でさえ、間隔の結合方法の組み合わせ爆発につながるため、すぐに指数関数的になります。 n−1 個のマージの後、可能な状態の数は実現可能な限界をはるかに超えて増加します。 

重要な点は、マージ操作では、間隔内の値を選択できる以上に内部構造が保持されないということです。 2 つの間隔がマージされると、結果の間隔は、達成可能な最小値から達成可能な最大値までの連続した範囲のように動作し、将来の操作はこれらの極端な値にのみ依存します。 どの値が左のエンドポイントとして機能し、どの値が右のエンドポイントとして機能するかを除いて、各間隔内の履歴は無関係になります。 

これにより、問題は、どの値が最終間隔のグローバル左エンドポイントとして表示され、どの値がグローバル右エンドポイントとして表示されるかを推論することに帰着します。 最終的な間隔は、最小値として機能する 1 つの値と最大値として機能する 1 つの値を選択することによって決定されます。各マージでは個別のソースが結合されるため、これら 2 つの値は異なる元の間隔から取得する必要があります。 

これは単純化につながります。つまり、ある間隔の値を最終的な左端点として取り、別の間隔からの値を最終的な右端点として取り、左が右よりも厳密に小さい間隔のペアのみを考慮します。 間隔内の任意の値が使用できるため、各間隔は完全な連続範囲に寄与し、実現可能性の比較ではエンドポイントのみが重要になります。 

したがって、問題は、有効な不等式 li < rj を生成できる順序付き区間ペアの数を数えることになります。

 ## アルゴリズムのチュートリアル

 各区間 [li, ri] を 2 つの使用可能な値に寄与するものとして言い換えます。候補となる左端点は [li, ri] のどこかにあり、右端点についても同様です。 唯一のグローバル要件は、最終的な左の値が最終的な右の値よりも厳密に小さいことと、それらの値が異なる間隔から発生する必要があることです。 

計数タスクは次のようになります。x < y となるような、区間 i の x と区間 j の y を選択できる区間 (i, j) のペアがいくつあるか。 

x は [li, ri] の任意の値にできるため、最も強い制約は最悪の場合の選択から得られます。間隔 i は、マージ ツリーの方向に応じて、ri と同じくらい大きくても、li と同じくらい小さくも寄与します。 ただし、何らかの有効な構造の存在をカウントしているため、li < rj を満たす値のペアが存在するかどうかを確認するだけで十分です。これは、エンドポイントを比較するのと同じです。 

これは直接の組み合わせ削減につながります。 

1. すべての間隔の左端点を配列 L に収集し、右端点を配列 R に収集します。 
2. 両方の配列を個別にソートします。 
3. 各区間 i について、li < rj を満たす区間 j がいくつあるかを数えます。 
4. ソートされた R 上のポインターを使用して、考えられる右端点をスイープします。各 li について、厳密に li より大きい rj がいくつあるかを数えます。 
5. すべての i についてこれらのカウントを合計し、i と j が異なることを確認します。間隔の等価性は両方向の厳密な不等式を満たさないため、これは自動的に処理されます。 

### なぜ効果があるのか

 本質的な不変条件は、マージ プロセスが、間隔のエンドポイントを超えて上方に持ち越される値のセットを決して制限しないことです。 マージされた間隔のすべてのサブツリーは、現在の集約間隔内で常に任意の値を実現でき、集約によってホールや個別の制限が生じることはありません。 結果として、最終的なペアを構築できるかどうかは、マージ履歴や構造ではなく、間隔間のエンドポイントの順序のみに依存します。 これにより、問題は区間境界の純粋なペアごとの比較に分解されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        L = []
        R = []
        intervals = []
        
        for _ in range(n):
            l, r = map(int, input().split())
            L.append(l)
            R.append(r)
            intervals.append((l, r))
        
        L.sort()
        R.sort()
        
        j = 0
        ans = 0
        
        for l in L:
            while j < n and R[j] <= l:
                j += 1
            ans += (n - j)
        
        print(ans)

if __name__ == "__main__":
    solve()
```最終的に必要な条件は、選択された左の値と選択された右の値の間の純粋な不等価であるため、コードは左と右のエンドポイントを分離します。 両方の配列をソートすると、考えられる左端点ごとに厳密に大きい右端点の数をカウントする線形スイープが可能になります。 

R がソートされているため、ポインター j は前方にのみ移動し、各要素が 1 回処理されることが保証されます。 これにより、O(n^2) のネストされたループが回避されます。 

微妙な点は、厳密な不等号です。 ループはすべての rj ≤ l を超えて進み、有効な rj > l のみがカウントされるようにします。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

 | 時間 | O(n log n) | エンドポイントの並べ替えが優勢で、スイープは線形です。 
| スペース | O(n) | エンドポイント配列の保存 |

 この制約では最大 10^5 の間隔が許可されるため、O(n log n) 解は 2 秒以内に快適に適合します。 配列の並べ替えと 1 回のパスにより、最悪の場合の集約入力でも線形演算動作が保証されます。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys

    out = []
    for _ in range(t):
        n = int(input())
        L = []
        R = []
        intervals = []
        for _ in range(n):

            L.append(l)

        ans = 0
        for l in L:

                j += 1
            ans += (n - j)
        out.append(str(ans))

    return "\n".join(out)

 ## 特殊なケース

 [1,2] などの単一間隔のケースは、ペアを形成する 2 番目の間隔がなく、スイープによって自然に寄与が生成されないため、アルゴリズムが正しく 0 を返すことを示しています。 

[1,10]、[2,9]、[3,8] のような完全にネストされた構成では、すべての左エンドポイントが複数の右エンドポイントよりも小さいという事実が利用され、アルゴリズムはすべての有効なクロス ペアを二重にカウントすることなく正しくカウントします。 

[1,2]、[3,4]、[5,6] などの素な間隔の厳密なチェーンは、オーバーラップがなくても、前のすべての左端点がその後の右端点と互換性があり、不等式に基づくカウントですべての有効な構成が捕捉されることを示しています。
