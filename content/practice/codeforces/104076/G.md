 ## 解決策
 ## 問題の理解

 現在のセグメントの中央の要素を常にピボットとして選択し、Hoare スタイルのパーティション手順を使用する決定論的なクイックソートの実装が与えられています。 配列をソートするように求められるのではなく、完全な実行中に発生するスワップの数を決定するように求められます。`quicksort(A, 1, n)`入力配列が順列の場合。 

重要な詳細は、配列はスワップ以外では決して変更されず、パーティション ルーチンはピボットの間違った側に要素のペアが見つかった場合にのみスワップを実行するということです。 各スワップは、パーティション ステップ中のピボットに対する特定の反転の修正に対応します。 したがって、このタスクは再帰を直接シミュレートすることではなく、再帰ツリー全体でそのようなパーティション間の交換が何回発生するかをカウントすることです。 

この制約により、クイックソートの直接シミュレーションは実行できなくなります。 すべてのテスト ケースの合計の長さは最大 5×10^5 で、T は 10^5 まで大きくなる可能性があります。 パーティションを使用した単純な再帰シミュレーションでは、セグメントのスキャンと要素の交換が繰り返し行われ、敵対的な置換で二次的な動作が発生する可能性があります。 これは許容される時間予算をはるかに超えています。 

微妙なエッジケースは、ここで使用されている Hoare パーティションのバリアントを理解することにあります。 戻ってくるから`j`そして再帰的に`[lo, p]`そして`[p+1, hi]`、ピボットは必ずしも最終的に並べ替えられた位置に配置されるとは限りません。 これは、「各要素が最終位置に一度交換される」という標準的なクイックソートの直感が直接当てはまらないことを意味します。 したがって、各反転がちょうど 1 回交換されるという不注意な仮定は、誤ったカウントにつながる可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、文字通り、説明されているクイックソートを実行し、内部でスワップをカウントします。`partition`。 各パーティションは 2 つのポインターを使用して内側にスキャンし、ペアが見つかるたびにスワップを実行します。`(i, j)`そのような`A[i] ≥ pivot`そして`A[j] ≤ pivot`その間`i < j`。 再帰呼び出し全体で、各要素は多くのパーティションに参加でき、各パーティションはサブ配列をスキャンします。 すでにソートされている配列や逆ソートされた配列などの最悪の場合、再帰は非常に不均衡なパーティションに変質し、二次的な合計作業量が生成されます。 要素の合計が最大 5×10^5 であるため、これは実行不可能です。 

重要な洞察は、各スワップが実際に何を表しているのかを再解釈することです。 ピボット値を使用したパーティション中`x`、すべてのスワップは値を交換します`≥ x`左側に値が入っています`≤ x`右側にあります。 これは、各スワップが、その再帰レベルでピボットしきい値に対して誤って分離された要素のペアに対応することを意味します。 クイックソートをインデックス範囲ではなく値範囲にわたる再帰ツリーの構築と見なす場合、要素の各ペアは、要素を区切る最も低い共通祖先パーティションごとに 1 回だけ「ピボットと比較」されます。 

これは古典的な観点につながります。各スワップは、LCA ピボットが選択された時点でパーティションの反対側にある要素のペアに対応し、そのピボットはそれらの値の間にあります。 したがって、スワップをシミュレートする代わりに、再帰的なセグメント構造によって引き起こされる値の順序間でピボットが要素のペアを分割する回数を数えます。 これは、要素の位置に関する分割統治の計数問題に変換できます。各セグメントで中間位置のピボットを選択し、ピボットより大きい左側の要素の数と、ピボットより小さい右側の要素の数を数え、クロス ペアに寄与します。 

値から位置へのマッピングを維持し、セグメントを再帰的に処理し、フェンウィック ツリーや位置にわたる順序統計などの効率的なカウント構造を使用して、ピボット分割によって引き起こされる相互反転を蓄積できます。

 ## アルゴリズムのチュートリアル

 1. アレイを構築する`pos`どこ`pos[x]`値のインデックスを与える`x`順列の中で。 これにより、インデックスベースのパーティショニング動作を尊重しながら、問題は値空間での作業に変換されます。 
2. 値の間隔で動作する再帰関数を定義します。`[L, R]`。 各呼び出しで、この間隔を、インデックスの一部のセグメントでクイックソートによって現在ソートされている値のセットとして解釈します。 
3. この間隔の中間値としてピボット値を選択します。`mid = (L + R) // 2`。 これは、元のコードがインデックスによって中央の要素を選択するという事実を反映しており、順列にわたる再帰の下では、これは値空間再構築における現在のセグメントの中央値の選択に対応します。 
4. 間隔を左の値に分割します`[L, mid-1]`そして正しい価値観`[mid+1, R]`。 目標は、このピボットでのこれら 2 つのグループ間の相互作用によって引き起こされるスワップをカウントすることです。 
5. 現在のピボットについて、ピボットの位置の右側に表示される左側のグループの要素の数と、ピボットの位置の左側に表示される右側のグループの要素の数を数えます。 このような間違って配置された各ペアは、この分割段階で 1 つのスワップに寄与します。 
6. このクロス カウントを累積し、左右の値の間隔を独立して再帰します。 
7. 次の場合に再帰が停止します。`L ≥ R`単一要素間隔ではパーティションやスワップが発生しないためです。 

これが機能する理由は、クイックソートの各パーティション ステップが中央ピボットで現在の値の間隔を分離することに対応し、Hoare パーティションのすべてのスワップがその分割全体にわたる 1 つの反転の修正に対応するためです。 値の各ペアは 1 つの再帰レベルで正確に分離されるため、特にピボットがランク間にあるレベルで 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

class BIT:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

def solve_case(n, a):
    pos = [0] * (n + 1)
    for i, v in enumerate(a, 1):
        pos[v] = i

    bit = BIT(n)

    def dfs(L, R):
        if L >= R:
            return 0
        mid = (L + R) // 2

        left_vals = range(L, mid + 1)
        right_vals = range(mid + 1, R + 1)

        # We count contributions using positions:
        # Insert all left side positions, then query right side inversions
        for v in left_vals:
            bit.add(pos[v], 1)

        res = 0
        for v in right_vals:
            # count how many left elements are to the right of this position
            res += len(left_vals) - bit.sum(pos[v])

        for v in left_vals:
            bit.add(pos[v], -1)

        return res + dfs(L, mid) + dfs(mid + 1, R)

    return dfs(1, n)

def main():
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        out.append(str(solve_case(n, a)))
    print("\n".join(out))

if __name__ == "__main__":
    main()
```コードは最初に構築します`pos`、インデックスの観点からセグメント操作を推論できるように、値を位置に変換します。 フェンウィック ツリーは、位置境界の片側に 1 つのグループの要素がいくつあるかを数える一時的な構造として使用されます。 各再帰呼び出し中に、左グループの値が挿入され、次に右グループの値が、置換順でその後ろに左の要素がいくつあるかをクエリします。 この違いは、パーティショニング中のスワップ操作に直接対応します。 

再帰的な構造はクイックソート パーティション ツリーを反映しており、各値の間隔が 1 回だけ処理されることが保証されます。

 ## 特殊なケース

 重大なエッジ ケースは、ピボットが繰り返しセグメントの中心近くに到達するが、すでにソートされた入力など、配列が大きく歪んでいる場合です。 この場合、Hoare パーティションは引き続きスキャンを実行しますが、スワップはほとんどありません。 左側の値が既に右側の値の前に配置されている場合は常にグループ間のカウントがゼロになり、フェンウィック クエリによって分割全体で反転がないことが確認されるため、アルゴリズムはこれを正しく処理します。 

順列が逆になると、別の特殊なケースが発生します。 すべてのパーティションは、ほぼすべての左グループ要素が間違った側になるように値を分割します。 最初の再帰レベルはスワップの大部分に寄与し、より深いレベルはシングルトンに到達するまで寄与し続けます。 分割統治構造により、再帰境界を越えて二重にカウントされるのではなく、それぞれの配置ミスが正しいピボット レベルで 1 回だけ起因することが保証されます。
