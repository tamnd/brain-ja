 ## 解決策
 ## 問題の理解

 重み付き無向グラフと 2 つの特別な頂点 (開始点としての頂点 1、目的地としての頂点 n) が与えられます。 1 から x までの整数 i ごとに、非常に具体的な質問が行われます。1 で開始し、n で終了し、正確に i 個のエッジを使用するすべてのウォークの中で、そのようなウォークの最小可能な総重みはいくらですか。 特定の i にそのようなウォークが存在しない場合、その寄与はゼロになります。 最後に、すべての回答を個別に報告するのではなく、1 から x までの i にわたるこれらすべての値を合計し、結果のモジュロ 998244353 を出力します。 

重要な点は、単純な道を探しているわけではないということです。 エッジと頂点の再利用は任意に許可されているため、構造は最短パスではなく、長さが制限されたウォークに近くなります。 「正確に i 個のエッジ」という制約は、通常の最短経路の問題を超えた 2 番目の次元を導入するため、重要な問題です。 

この境界により、各 i について独立して答えを計算しようとするアプローチは即座に除外されます。 値 x は 10^9 まで大きくなり、i に対するクエリごとの動的プログラミングは不可能になります。 同時に、n は最大 2000、テスト全体の合計 m は最大 5000 です。これは、すべての i に対する反復を明示的に回避する場合にのみ、頂点にわたるステップごとのグラフ DP が実現可能であることを示唆しています。 

素朴だが自然なアイデアは、正確に i 個のエッジを使用して頂点 v に到達するための最小コストとして dp[i][v] を定義することです。 これは概念的には機能しますが、x が大きすぎるため、x まで反復することはできません。 x までのすべての i の dp を計算することすら不可能です。 

i を n や m のような値に「制限」しようとすると、より微妙な故障モードが表示されます。 たとえば、負のサイクルを持つグラフではこれが必要になる可能性がありますが、ここでは重みが正であるため、サイクルはコストを増加させるだけです。 ただし、重要な問題は、サイクルが高価であるにもかかわらず、x が大きい場合にパリティまたはエッジ数を調整するためにサイクルが使用される可能性があるため、長さを制限することが明らかに安全ではないということです。 

構造を示す小さな例:

 入力:

 n = 3、m = 2、x = 5

 エッジ: 1-2 (1)、2-3 (1)

 唯一の単純なパス 1 → 2 → 3 は、コスト 2 の 2 つのエッジを使用します。 

i = 2 の場合、答えは 2 ですが、i = 3 の場合、1 → 2 → 3 → 2 → 3 のような処理を行う必要があり、コストが増加します。 最適な構造は、もはや単純な最短パスではなく、エッジを再利用できる固定長の最短ウォークです。 

主な問題は、「正確に i 個のエッジ」により、最短経路が非常に多くの層数にわたる層状グラフの問題に変わることです。 

## アプローチ

 強引な解決策は、1 から x までのすべての i に対して dp[i][v] を明示的に計算することです。 各層はすべてのエッジ上で遷移するため、各 i について、m 個のエッジすべてを緩和し、n 個の状態を更新します。 これにより、テスト ケースあたりの時間は O(x · m) になりますが、x が 10^9 の場合はまったく不可能です。 

重要な観察は、すべての dp レイヤーを個別に必要とするわけではないということです。 代わりに、正確に i 個のエッジで n に到達するための最良のコストのみを考慮し、最終的に i の合計を計算します。 この構造は、遷移が線形で前の層にのみ依存するため、i にわたる線形回帰動作を強く示唆しています。 

この問題は、サイズ n のベクトルに対する min-plus 線形漸化式として書き直すことができます。 各エッジは遷移行列に寄与し、1 つのステップを適用することは、min-plus 隣接演算子を乗算することに対応します。 したがって、dp[i] は、同じ変換を i 回適用することによって取得されます。 

これは二乗による累乗が適用される古典的な設定ですが、min-plus セミリングで、1 から x までのすべての i に対する追加の集計が行われます。 すべてのべき乗を計算する代わりに、繰り返された二乗の効果と中間べき乗の累積寄与の両方を追跡する結合構造を計算できます。

標準的なトリックは、変換を行列 T (T[u][v] = エッジ u-v の重み) として扱い、min-plus 乗算を使用して T のべき乗を計算することです。 次に、T^k だけでなく、k までのべき乗の和も維持します。 これは、各状態が「k ステップ後の最良の値」と「k までのすべてのステップの合計」の両方を格納する、行列のべき乗における接頭辞の合計に似ています。 

n が小さいため (テスト全体で合計 2000 以下ですが、実質的にテストごとに管理可能)、エッジの疎性と慎重な min-plus 乗算に依存します。 10^9 までの指数 x は、バイナリ リフティングを使用して O(log x) 層で処理されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | i 上のブルート フォース DP | O(x・m) | O(n) | 遅すぎる |
 | プレフィックス集約を使用した Min-plus バイナリ リフティング | O(n^3 log x) または最適化されたスパース O(m n log x) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各ステップをエッジに沿って移動するものとしてモデル化するため、グラフ遷移の 1 つの適用により頂点間の距離のベクトルが変換されます。 これは、dp[0][1] のみがゼロであるベクトルから開始して、同じ演算子を x 回繰り返し適用していることを意味します。 
2. k ステップ後の遷移だけでなく、k までのすべてのステップ数に対する最良の結果を表す構造を定義します。 これにより、累乗しながら最終合計への寄与を蓄積することができます。 
3. エッジを 1 つだけ取得することに対応する基本遷移を初期化します。重み w を持つすべてのエッジ u-v について、コスト w で u と v の間を移動できます。 
4. このような 2 つの遷移構造間の乗算演算を定義します。 長さ a と b の 2 つのブロックを合成すると、長さ a+b のブロックが得られます。 合成ではすべての中間頂点を考慮し、最小コストのパスを選択する必要があります。 
5. 構成に加えて、ブロック内のすべての長さの累積最良コストを表す 2 番目の値も維持します。 これは、長さによって適切にシフトされた、左側のブロックと右側のブロックからのプレフィックスの寄与を組み合わせることによって更新されます。 
6. x の遷移構造に 2 進累乗を適用し、x を 2 の累乗に分解します。 二乗するたびに、構造を結合し、遷移と累積和の両方を更新します。 
7. x を処理した後、開始頂点 1 から終了頂点 n までの累積寄与を抽出します。これにより、すべての i にわたって必要な合計が得られます。 
8. 特定の長さのパスが存在しない場合、それらの寄与は事実上無限のままであり、min 演算では無視され、最終的な合計ではゼロになります。 

### なぜ効果があるのか

 このアルゴリズムは、「正確に i エッジ」がウォークの連結の下で半群を定義するという事実に依存しています。 長さ i のすべてのウォークは、より小さいウォークの連結に一意に分割でき、コスト関数はこの分割に対して加算され、最小化は min-plus 畳み込みを介して合成に分散されます。 プレフィックス合計の拡張では、すべての中間の長さに関する情報が保存されるため、べき乗によって長さごとの寄与が失われることはありません。 これにより、x を 2 の累乗に分解した後、x までの任意の長さのすべての有効な歩行が、その最適コストで正確に 1 回カウントされることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**30
MOD = 998244353

class Mat:
    def __init__(self, n):
        self.n = n
        self.a = [[INF] * n for _ in range(n)]
        self.sum = [[0] * n for _ in range(n)]

def merge(A, B):
    n = A.n
    C = Mat(n)

    for i in range(n):
        for k in range(n):
            if A.a[i][k] == INF:
                continue
            aik = A.a[i][k]

            for j in range(n):
                if B.a[k][j] == INF:
                    continue
                cand = aik + B.a[k][j]
                if cand < C.a[i][j]:
                    C.a[i][j] = cand

    for i in range(n):
        for j in range(n):
            C.sum[i][j] = (A.sum[i][j] + B.sum[i][j] + C.a[i][j]) % MOD

    return C

def power(base, exp):
    n = base.n
    res = Mat(n)

    for i in range(n):
        res.a[i][i] = 0

    while exp:
        if exp & 1:
            res = merge(res, base)
        base = merge(base, base)
        exp >>= 1

    return res

def solve():
    T = int(input())
    for _ in range(T):
        n, m, x = map(int, input().split())

        base = Mat(n)

        for i in range(n):
            base.a[i][i] = 0

        for _ in range(m):
            u, v, w = map(int, input().split())
            u -= 1
            v -= 1
            base.a[u][v] = min(base.a[u][v], w)
            base.a[v][u] = min(base.a[v][u], w)

        res = power(base, x)

        ans = res.sum[0][n - 1] % MOD
        print(ans)

if __name__ == "__main__":
    solve()
```実装の中核は、min-plus 行列構造です。 の`a`表は、ブロック内の正確に k ステップの最短距離を表します。`sum`すべてのプレフィックスの寄与を集計します。 の`merge`関数は、中間頂点に対して min-plus 畳み込みを実行します。これは、2 つのパス長ブロックを連結することに対応します。 

2進累乗`power`x ステップの効果を効率的に蓄積します。 各二乗により、遷移合計と累積合計の両方を維持しながら、歩行セグメントの長さが 2 倍になります。 

微妙な点は、単位行列の初期化です。これは、同じノードに留まるコストがゼロである長さゼロの遷移を表します。 これは、部分的なバイナリ寄与に対して累乗が正しく動作するために必要です。

 ## 特殊なケース

 エッジ ケースの 1 つは、エッジ数を無視しても 1 から n へのパスがない場合です。 その場合、すべての dp[i][n] は無限のままであるため、すべての寄与はゼロになります。 min-plus の乗算では INF 値が改善されないため、アルゴリズムはこれを自然に処理し、最終的な累積合計はゼロのままになります。 

もう 1 つのエッジ ケースは、自己ループを含むグラフです。 自己ループを使用すると、頂点を変更せずにエッジ数を増やすことができるため、より大きな i の実現可能性を人為的に向上させることができます。 min-plus 構造はこれを正しく処理します。自己ループは基本行列内で有効な遷移として表示され、べき乗は特別なケースを必要とせずにそれらを自然に長いウォークに組み込むためです。 

3 番目のエッジ ケースは、同じ頂点間に異なる重みを持つ複数のエッジが存在する場合です。 初期化ステップでは明示的に最小重みエッジを取得し、後続のすべての DP レイヤが最良のローカル遷移を尊重するようにします。
