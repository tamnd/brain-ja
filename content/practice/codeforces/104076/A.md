 ## 解決策
 ## 問題の理解

 タワーの高さのコレクションが与えられます。各タワーの高さは整数です。 何かを行う前に、完全に削除することができます。$m$塔。 残りのタワーには、高さを 1 つ増やす、高さを 1 つ下げる (ゼロにならない限り)、または床分割を使用して高さを半分に置き換えるという 3 種類の操作を繰り返し適用できます。 

目標は、残りのすべてのタワーが最終的に同じ高さになるようにすることであり、高さの変更と削除するタワーの選択の両方を含む、その状態を達成するために使用される操作の合計数を最小限に抑えたいと考えています。 

重要な問題は、事前に目標の高さを直接選択していないことです。 代わりに、任意の整数の高さが最終的な共通値になる可能性があり、追加の変更と繰り返しの半分化ステップの組み合わせを通じて、各初期タワーをそのターゲットに変換できます。 

制約$n \le 500$、$T \le 10$、 そして$a_i \le 10^9$を強く提案する$O(n^3)$あるいは$O(n^2 \log A)$アプローチは許容されますが、サブセットまたはターゲットを超える指数関数的なものは不可能です。 2 による除算の存在は、それぞれの値が唯一のものであることを示すヒントです。$O(\log A)$可能な変換を通じて逆方向に追跡すると、意味のある状態が得られます。 

いくつかの微妙なエッジの状況が重要です。 

すべてのタワーがすでに等しい場合、答えはゼロになります。$m = 0$、しかし、もし$m > 0$、いくつかのタワーを削除し、残りのタワーを均等化する必要があります。 単純なアプローチでは、削除は「せいぜい」という意味でオプションであると誤って仮定する可能性があります。$m$「まさに」ではなく$m$」により、実現可能性の決定が変わります。 

もう 1 つの罠は、2 で除算すると反転不可能な構造が作成されることを無視していることです。 たとえば、高さ 7 から半分にすると 3 になりますが、先行するものをきれいに列挙する対称的な逆演算はありません。 状態に対する単純な BFS は、半分にすると大きさが小さくなるにもかかわらず、各数値が無限に増加および減少して分岐するため、爆発してしまいます。 

最後に、ゼロを禁止する操作制約は、小さな値を自由にデクリメントできないことを意味するため、ゼロを通過するパスはすべて拒否されなければなりません。 

## アプローチ

 ブルートフォース戦略では、どちらかを選択しようとします。$m$タワーを取り外してから、可能な限りのターゲットの高さを試してください$H$。 固定されたサブセットとターゲットの場合、各タワーは、達成するために必要な最小限の操作を個別に計算します。$H$。 その部分問題自体は、次のように定義されたエッジを持つ状態のグラフを検索する必要があります。$\pm 1$そして2で割ります。 距離を事前に計算したとしても、サブセットの選択とターゲットのスキャンを組み合わせると爆発的な影響が生じます。サブセットの選択にはコストがかかります。$\binom{n}{n-m}$、そしてさらに$n=500$これは不可能です。 

重要な観察は、演算の構造により、すべての数値がのみを生成するということです。$O(\log a_i)$逆算すると、意味のあるターゲット候補が得られます。 目標の高さを固定し、その目標に到達する方法を尋ねるのではなく、考え方を逆転させます。各タワーについて、繰り返し 2 で割ることを使用して崩壊する可能性のあるすべての値を列挙し、それらの値に到達するためのコストを記録します。 それが完了すると、すべてのタワーが、関連コストとともに候補となる「着陸高さ」の小さなリストを提供します。 

これにより、問題は一般的な高さの選択に変わります$H$を選択してから、$n-m$到達できる塔$H$、総コストを最小限に抑えます。 それぞれについて$H$、これはコストをめぐるナップザックのような選択問題になります。最良のものを選択します。$n-m$到達可能なすべてのタワー間の貢献度$H$。 以来$n$が十分小さい場合、候補のコストを高さごとに分類することは可能です。 

最終的なソリューションでは、すべてのタワーの半分化チェーンから生じるすべての可能なターゲットの高さを集約し、それぞれを評価して、最適な高さを計算します。$n-m$課題。

 ## アルゴリズムのチュートリアル

 ### ステップ 1: タワーごとに到達可能なすべての圧縮状態を構築する

 各タワーの値について$a_i$、2 による除算を繰り返し適用し、各中間値を記録します。 それぞれの値とともに、その値に到達するまでのコストを以下から計算します。$a_i$各半分のステップの前に増分と減分を使用します。 これが機能する理由は、2 による除算を使用する一連の演算は、値のバイナリ ツリーの祖先で安定するまで繰り返し数値を減らすものとみなせるためです。 

### ステップ 2: 目標値ごとのコスト寄与を保存する

 すべてのタワーについて、到達可能な高さからのマッピングを維持します$H$そのタワーを$H$。 複数のパスが同じに到達する場合$H$、最小限のコストのみを維持します。 これにより、各タワーが潜在的な最終高さに最適に寄与することが保証されます。 

### ステップ 3: タワー全体で候補者を集約する

 すべてのペアを集めます$(H, cost)$すべての塔から高さを基準としたグローバル構造へ$H$。 各高さにはコストのリストがあり、タワーごとに 1 つ (または、到達できない場合はそれよりも少なくなります) が含まれます。 

### ステップ 4: 各候補の身長を評価する

 固定高さの場合$H$、まさに欲しいです$n-m$塔は残り、すべて変換されます$H$。 したがって、それに関連するすべての費用は当社が負担します$H$、それらを並べ替えて、最小のものを選択します$n-m$価値観。 未満の場合$n-m$塔は到達できる$H$、この高さを破棄します。 

ソートが機能する理由は、タワーが一度独立しているためです$H$固定されています。 グローバルな数の制約を超えて、どのタワーを選択するかの間に相互作用はありません。 

### ステップ 5: すべての高さの最小値を取得します

 有効な高さごとにコストを計算し、最小値を採用します。 これにより、チェーンを半分にすることによって引き起こされる、構造的に可能なあらゆる最終状態を確実に探索できます。 

### なぜ効果があるのか

 タワーを変換する有効な演算シーケンスはすべて、その半減チェーンに現れる何らかの値で終了します。これは、2 による除算を適用するときは常に、数値が厳密に 2 進数のリダクション パスに従うためです。 加算および減算演算は、半分にする前に固定レベル内でのみ調整します。 したがって、タワーの到達可能な最終高さはすべて列挙で表されます。 すべてのタワーを高さごとの候補コスト リストにまとめたら、$n-m$目標の高さが固定されると、運用はタワー間で独立するため、総コストが最小のタワーが最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import defaultdict

def build_costs(x):
    # returns dict: value -> min cost to convert x to value
    res = {}
    # current value starts at x, cost 0
    val = x
    cost = 0
    step = 0

    while val > 0:
        # we can reach val
        if val not in res:
            res[val] = cost
        else:
            res[val] = min(res[val], cost)

        # move to parent via /2
        # to go from val to val//2, we assume we first adjust val to 2*(val//2) or 2*(val//2)+1
        # but in this construction we accumulate via simulation of reverse chain
        val //= 2
        step += 1
        cost += 1

    return res

def solve():
    T = int(input())
    for _ in range(T):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        keep = n - m

        mp = defaultdict(list)

        for x in a:
            costs = build_costs(x)
            for v, c in costs.items():
                mp[v].append(c)

        ans = float('inf')

        for v, arr in mp.items():
            if len(arr) < keep:
                continue
            arr.sort()
            ans = min(ans, sum(arr[:keep]))

        print(ans)

if __name__ == "__main__":
    solve()
```この実装では、タワーごとに、半減を繰り返すことで得られる値のチェーンが構築されます。 各中間値について、実行された半減ステップの数に比例したコストが記録されます。 これらのタワーごとのマップは、ターゲットの高さをキーとするグローバル辞書にマージされます。 

最後のループでは、各候補の身長を個別に評価します。 最も安いものを選択する必要があるため、高さごとにコストリストを並べ替える必要があります。$n-m$あの高さに達する塔。 

主な微妙な点は、少なくとも実際に到達可能な高さのみを考慮することです。$n-m$塔。 そうしないと、実現可能性を誤って想定してしまうことになります。 

## 実用的な例

 ### 例 1

 入力:```
n = 5, m = 3
a = [1, 2, 3, 4, 5]
keep = 2
```到達可能なチェーンを計算します。 

| タワー | 到達可能な値 (簡略化) |
 | --- | --- |
 | 1 | 1 → 0 |
 | 2 | 2 → 1 → 0 |
 | 3 | 3 → 1 → 0 |
 | 4 | 4 → 2 → 1 → 0 |
 | 5 | 5 → 2 → 1 → 0 |

 次に、候補ターゲットを評価します。 

のために$H = 1$、コストは次のようになります。 

| タワー | コストは 1 |
 | --- | --- |
 | 1 | 0 |
 | 2 | 1 |
 | 3 | 1 |
 | 4 | 2 |
 | 5 | 2 |

 最良の 2 つを選択します: 0 と 1、合計 = 1。 

のために$H = 2$、一部の塔のみが到達できます。 

| タワー | コストは 2 |
 | --- | --- |
 | 2 | 0 |
 | 4 | 1 |
 | 5 | 1 |

 ベスト 2 のコストは 0 + 1 = 1 になります。 

すべてのターゲットの最小値は 1 です。 

これは、効率的に到達できるタワーの数に応じて、最終的な高さを小さくするか大きくするかのトレードオフを示しています。 

### 例 2

 入力:```
n = 3, m = 1
a = [10, 20, 25]
keep = 2
```候補チェーン:

 | タワー | 到達可能な値 |
 | --- | --- |
 | 10 | 10 → 5 → 2 → 1 |
 | 20 | 20 → 10 → 5 → 2 → 1 |
 | 25 | 25 → 12 → 6 → 3 → 1 |

 ターゲット$H = 5$:

 | タワー | コスト |
 | --- | --- |
 | 10 | 1 |
 | 20 | 1 |
 | 25 | 到達不能 |

 最小のコストを 2 つ選択します: 1 + 1 = 2。 

ターゲット$H = 1$:

 すべてのタワーが 1 に達します:

 | タワー | コスト |
 | --- | --- |
 | 10 | 3 |
 | 20 | 3 |
 | 25 | 3 |

 ベスト 2 は 3 + 3 = 6 となります。 

したがって、最適な値は 2 です。$H = 5$。 

この例では、中間の半分の値が 1 まで折りたたむよりもはるかに優れている理由を強調しています。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、多くのタワーが同一の半分のパスを共有する場合です。 たとえば、すべての値が 2 のべき乗である場合、すべてのタワーはきれいに 1 に崩壊しますが、8 や 4 などの中間値では、削除数に応じてより安価なアラインメントが得られる可能性があります。 中間の高さごとに複数のコスト エントリが蓄積され、並べ替えによって最適なサブセットが自然に選択されるため、アルゴリズムがこれを処理します。 

別のケースは、正確にのみの場合です。$n-m$塔は指定された高さに達することができます。 このアルゴリズムは、コストを選択する前にリストの長さによって実現可能性をチェックし、偶発的な過少選択を防ぐため、引き続き機能します。 

最後のケースは、最適なソリューションを実現するには、個別には安価に見えるが、より適切な共有ターゲットへのアクセスをブロックするタワーを削除する必要がある場合です。 削除は選択のみで暗黙的に処理されるため、$n-m$高さごとの塔の数に応じて、アルゴリズムは明示的にサブセットを列挙することなく、そのトレードオフを自然に探索します。
