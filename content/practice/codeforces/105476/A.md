 ## 解決策
 ## 問題の理解

 私たちは一連の文字列を扱っており、各用語は連続する数字の観点から記述することによって前の用語から構築されています。 単一の文字列からプロセスが開始されます`"1"`、次のすべての文字列は、前の文字列を左から右にスキャンし、同一の連続する文字をグループ化し、各グループをグループの長さとその後に数字自体が続くペアで置き換えることによって形成されます。 

タスクは、この変換プロセスによって生成される N 番目の項を計算することであり、インデックス付けは最初の文字列から始まります。 出力は算術的な意味での数値ではなく、N 回の変換後のシーケンスの状態を表す文字列です。 

N ≤ 53 という制約は十分に小さいため、シーケンスを直接シミュレートできます。 各変換では文字列の長さが不規則に増減しますが、この範囲内では管理可能なままです。 シーケンスは本質的に閉じた形式ではなく反復書き換えによって定義されるため、対数または定数時間の式は期待されません。 

インデックス作成では、微妙な特殊なケースが発生します。 シーケンス定義では基本値 a₀ = 1 を使用しますが、サンプル入力は最初の出力が最初に適用された変換に対応するかのように動作します。`"1"`、初期状態そのものではありません。 これは、インデックスを正しく調整するには細心の注意が必要であることを意味します。そうしないと、1 つずつずれたエラーによってすべての結果がシフトされてしまいます。 

もう 1 つの潜在的な落とし穴は、シーケンス要素を整数として扱うことです。 出力は標準の整数サイズを超えて大きくなり、繰り返しの数字が含まれる可能性があるため、すべてを文字列として処理する必要があります。 例えば、`"111221"`先頭の繰り返しと数字のグループ化が不可欠であるため、構造を失わずに数値的に解釈することはできません。 

## アプローチ

 ブルートフォースアプローチは定義に直接従います。 から始めます`"1"`そして、「リードオフ」変換を N 回繰り返し適用します。 各変換は現在の文字列をスキャンし、連続する等しい文字をカウントし、count の後に文字を追加して次の文字列を構築します。 

問題定義は明示的に再帰的であるため、これは正しいです。 1 回の変換のコストは、現在の文字列の長さに比例します。 ただし、シーケンスが進行するにつれて文字列は長くなり、N は小さいものの、長さの増加は単純な多項式によって厳密に制限されません。 経験的には、約 40 ～ 50 のステップを経ると、文字列は大きくなりますが、それでも Python の制限時間内で管理できるようになります。 

重要な洞察は、単純なシミュレーション以外の最適化は必要ないということです。 各項は前の項の正確なランレングス エンコーディングに依存するため、シーケンスの構造では N 番目の項への直接のスキップやジャンプはサポートされていません。 唯一の簡素化は、効率的な線形スキャンとリスト バッファを使用した文字列構築であり、二次連結のオーバーヘッドを回避します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(Σ | a_i | ) |
 | 最適 | O(Σ | a_i | ) |

 実際には、どちらのアプローチも同じです。 違いは実装効率のみです。 

## アルゴリズムのチュートリアル

 ## アルゴリズムのチュートリアル

 1. 最初の文字列から始める`"1"`シーケンスの最初の要素として。 これは、ランレングス エンコーディングが適用される前の基本構成を表します。 
2. 変換を正確に N 回繰り返します。 繰り返しのたびに、現在の文字列から次の文字列が構築されます。 
3. 次の文字列を構築するには、同じ文字の現在の実行の開始を追跡するポインタを維持しながら、現在の文字列を左から右にスキャンします。 これにより、常に最大の連続セグメントがグループ化されます。 
4. 実行ごとに、同じ文字が連続して何回繰り返されるかを数えます。 実行が終了したら、カウントに続いて文字自体を一時バッファーに追加します。 
5. ポインタを次の実行の先頭に移動し、文字列全体が処理されるまで続行します。 これにより、すべての文字が 1 つのグループに 1 回だけ含まれることが保証されます。 
6. 現在の文字列を新しく構築されたバッファーに置き換えて、次の反復に進みます。 

このプロセスの正しさは、各反復後の文字列が前の文字列のランレングス エンコード記述とまったく同じであるという不変条件から得られます。 ランレングス エンコーディングは特定の文字列に対して一意に決定されるため、それを繰り返し適用すると、曖昧さや分岐のない決定的なシーケンスが得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def next_term(s: str) -> str:
    res = []
    i = 0
    n = len(s)

    while i < n:
        j = i
        while j < n and s[j] == s[i]:
            j += 1
        cnt = j - i
        res.append(str(cnt))
        res.append(s[i])
        i = j

    return "".join(res)

def solve():
    n = int(input().strip())
    s = "1"

    for _ in range(n):
        s = next_term(s)

    print(s)

if __name__ == "__main__":
    solve()
```コア機能`next_term`単一のランレングス エンコーディング パスを実装します。 リスト内のフラグメントを収集し、最後に 1 回結合することで、文字列の繰り返しの連結を回避します。これは、実行時間を文字列の長さで線形に保つために不可欠です。 2 ポインター手法により、反復ごとに各文字が正確に 1 回訪問されることが保証されます。 

メインループは、この変換を次から N 回適用します。`"1"`、シーケンスの再帰的定義と一致します。 入力定義は N 個の変換を直接実行することに対応しているため、インデックス付けに特別な処理は必要ありません。 

## 実用的な例

 ### 例 1: N = 1

 初期状態:

 | ステップ | 現在の文字列 | 処理された実行 | 次の文字列 |
 | --- | --- | --- | --- |
 | 1 | 1 | (1 × "1") | 11 |

 単一の文字`"1"`長さ 1 のランを形成し、`"11"`出力として。 これにより、1 つの変換が初期状態を正しくエンコードしていることが確認されます。 

### 例 2: N = 2

 | ステップ | 現在の文字列 | 処理された実行 | 次の文字列 |
 | --- | --- | --- | --- |
 | 1 | 1 | (1 × "1") | 11 |
 | 2 | 11 | (2 × "1") | 21 |

 最初の変換後、次のようになります。`"11"`。 2 番目の変換では、2 つの実行があります。`"1"`キャラクター、プロデュース`"21"`。 

このトレースは、グループ化がどのように進化するかを示しています。繰り返された数字はカウントと数字のペアに圧縮され、それが次の反復の入力構造になります。

 ## 特殊なケース

 1 つのエッジ ケースは、可能な最小の入力です。 N がゼロ変換に対応する場合、出力はそのままになるはずです。`"1"`。 実装では、ループが正確に N 回実行され、N がゼロの場合は完全にスキップされるため、これは自然に処理されます。 

もう 1 つのエッジ ケースは、後の反復で実行が大幅に拡大するシーケンスです。 たとえば、から始めて、`"1"`、変換を繰り返すと、最終的に次のような混合数字パターンが作成されます。`"1113213211"`。 このアルゴリズムは、数字の値を決して仮定せず、文字の同一性のみを仮定するため、これを正しく処理します。 各実行は純粋に隣接性によって決定されます。 

最後のエッジケースは、次のような長い同種文字列です。`"111111"`。 アルゴリズムはこれを次のように圧縮します。`"61"`ワンパスで。 2 ポインター スキャンにより、非常に長い実行であっても、中間の断片化が発生することなく正しく削減されます。
