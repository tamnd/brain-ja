 ## 解決策
 ## 問題の理解

 各テスト ケースに数字の文字列が与えられ、その連続する部分文字列のうち、11 で割り切れる整数を表す文字列がいくつあるかを数えるように求められます。各部分文字列は 10 進数として解釈されますが、部分文字列はゼロで始まる場合があるため、先頭のゼロは割り算に影響しません。 

直接的な解釈は、インデックスのすべてのペアを考慮することになります。$(l, r)$、部分文字列を抽出し、それを数値に変換し、11 で割り切れるかどうかをテストします。入力サイズが次の値に達します。$10^5$テストごとに$O(n^2)$部分文字列の列挙は、生の数の点ではすでに許容範囲ギリギリですが、各部分文字列を整数に変換すると、$O(n^3)$最悪の場合、それは直ちに実行不可能になります。 

本当の制約圧力は、次の処理まで処理しなければならないという事実から生じます。$10^5$つまり、テストごとに線形またはほぼ線形以上の作業を行うソリューションは失敗します。 

微妙なエッジ ケースは、ゼロで始まる部分文字列です。 たとえば、`1000`、のような部分文字列`00`または`000`は有効な数値であり、11 で割り切れるゼロとして扱う必要があります。先頭のゼロをスキップしたり、部分文字列を無効なものとして扱う単純なアプローチでは、大幅に過小評価されてしまいます。 もう 1 つのエッジ ケースは、11 で割り切れるかどうかが交互の桁の合計に依存するため、パリティ構造を無視すると不正確なカウントにつながる可能性があることです。 

## アプローチ

 ブルートフォースのアイデアは単純です。すべての左端点を反復し、右端点を拡張し、現在の数値を維持し、各ステップで 11 で割り切れるかどうかをテストします。 値を段階的に維持しても、引き続き処理が行われます。$O(n^2)$テストケースごとの部分文字列。 と$n = 10^5$、これにより約$5 \cdot 10^9$部分文字列、これは時間制限をはるかに超えています。 

重要な観察は、11 で割り切れる可能性は、接頭語の交互の和で表現すると単純な構造になるということです。 数字を含む数字の場合$d_0 d_1 \dots d_{n-1}$、プレフィックス値を定義します$p[i]$位置までの交互の合計として$i$。 部分文字列$s[l:r]$セグメントの交互の合計が 11 を法として 0 である場合、正確に 11 で割り切れます。これにより、符号の交互は開始インデックスに依存するため、パリティ調整を使用して、問題を等しいプレフィックス状態のペアをカウントすることに変換します。 

各プレフィックスを 2 つの状態 (偶数インデックスの場合と奇数インデックスの場合) で表現すると、問題は周波数マップで等しい値を数えることになります。 これにより、問題は二次列挙から線形計数に軽減されます。

 ## アルゴリズムのチュートリアル

 部分文字列チェックが等価性チェックになるように、各プレフィックスを正規化された交互合計に書き換えます。 

1. 文字列を左から右にスキャンしながら、プレフィックスの交互の合計を作成します。 インデックス時$i$、パリティに応じて数字を加算または減算します。 これは、11 で割り切れる構造をエンコードします。 
2. 確認されたプレフィックス状態の周波数マップを維持します。 各状態は、現在の交流合計値によって定義されます。 これにより、現在のプレフィックスと一致する以前のプレフィックスの数を数えることができます。 
3. 処理が開始される前に、状態 0 が一度発生するようにマップを初期化します。 これにより、インデックス 0 から始まる部分文字列を正しくカウントできるようになります。 
4. 各位置について、プレフィックス状態を更新し、この状態が以前に見られた回数を答えに追加します。 次に、その周波数を増加させます。 

インクリメントする前に追加する理由は、以前に同じプレフィックス状態が出現するたびに、現在の位置で終わる有効な部分文字列が定義されるためです。 

### なぜ効果があるのか

 部分文字列$s[l:r]$は、2 つのプレフィックスの交互の合計の差に相当します。 交互の符号は位置に基づいて反転するため、パリティが状態定義に組み込まれている場合、一致する部分文字列は等しいプレフィックス状態に正確に対応します。 したがって、同一の状態のすべてのペアは 11 で割り切れる部分文字列を定義し、他の部分文字列はカウントされません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    
    for _ in range(t):
        n = int(input())
        s = input().strip()
        
        # map: (alternating prefix sum) -> frequency
        freq = {0: 1}
        
        pref = 0
        ans = 0
        
        for i, ch in enumerate(s):
            d = ord(ch) - 48
            
            # alternating sum: + - + - ...
            if i % 2 == 0:
                pref += d
            else:
                pref -= d
            
            ans += freq.get(pref, 0)
            freq[pref] = freq.get(pref, 0) + 1
        
        out.append(str(ans))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装では、実行中の交互合計が維持されます。`pref`。 パリティはインデックスに関連付けられているため、各位置は正しい符号を持ちます。 辞書`freq`各プレフィックス値が出現した回数を格納します。 

主要な実装の詳細は初期化です`freq`と`{0: 1}`。 これにより、プレフィックス自体がゼロになったときに、インデックス 0 から始まる部分文字列が確実にカウントされます。 もう 1 つの微妙な点は、頻度を増やす前に答えを更新することです。これにより、各部分文字列が正確に 1 回カウントされることが保証されます。

 ## 特殊なケース

 のような文字列の場合`0000`、各桁がゼロに寄与するため、すべてのプレフィックスの状態は同一のままです。 周波数マップは次のように進化します。`1, 2, 3, 4, 5`、そして答えは蓄積されます$0 + 1 + 2 + 3 = 6$、すべての可能な部分文字列と一致します。 ゼロは交互の合計に影響を与えないため、アルゴリズムはこれを自然に処理します。 

次のような単一文字入力の場合`7`、プレフィックスの状態はゼロ以外で一意であるため、以前の一致は存在しません。 数字自体が有効な 11 で割り切れる条件を提供しない限り、答えは 0 のままです。この条件は、接頭辞比較ロジックによって正しく捕捉されます。
