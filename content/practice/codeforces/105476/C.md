 ## 解決策
 ## 問題の理解

 通りに沿ったいくつかの独立したシナリオが与えられます。 各シナリオには、人々が立つ固定位置と一連の街灯があり、それぞれが何らかの座標に配置され、その半径によって決まる周囲の対称範囲を照らすことができます。 位置にある街灯$y$半径あり$r$閉区間内のすべての点をカバーします$[y - r, y + r]$。 人の位置が少なくとも 1 つのそのような照明間隔内にある場合、その人は安全であると考えられます。 

シナリオごとに、点灯する街路灯のサブセットを選択し、アクティブにする街路灯の数を最小限に抑えながら、すべての人の位置が少なくとも 1 つの選択された間隔でカバーされるようにする必要があります。 どのライトを選択してもすべての人をカバーできない場合、それは不可能であると出力されます。 

中心となる抽象化は、ポイントの間隔カバレッジであり、各街灯が固定間隔を生成し、必要なすべてのポイントをカバーする間隔の最小サブセットが必要です。 

制約により効率化が図られます。 合計サイズは次のように大きくなります。$10^5$人々と$10^5$テスト ケースごとに街路灯、最大 100 のテスト ケース。 すべての人をすべての光と比較するソリューションは、次のような結果に直接つながります。$O(nm)$、それは$10^{10}$最悪の場合は操作が停止され、3 秒の制限の下では実行不可能になります。 したがって、次のような解決策が必要です。$O((n+m)\log n)$または$O(n \log n + m)$。 

微妙な失敗例は、わずかに異なる光が適用範囲をさらに拡大する可能性があることを考慮せずに、貪欲な方法で人を覆う最初の光を誤って選択した場合に発生します。 たとえば、人が位置 1、2、3 にいて、2 つのライトが存在するとします。1 つは [1,2] のみをカバーし、もう 1 つは [1,3] をカバーします。 最初の重なりに基づいて貪欲に選択すると、1 つで十分なライトを 2 つ選択することになる可能性があります。 

一部の人々がすべての間隔から完全に外れている場合、別の特殊なケースが発生します。 たとえば、位置 10 にいる人がすべてのライトで [0,5] のみをカバーしている場合、すぐに不可能になりますが、カバレッジが存在することを前提とした単純な実装は、後で静かに失敗します。 

最後に、複数のライトが同じ領域をカバーする可能性があり、最適な選択はローカルな選択ではなくグローバルな構造に依存するため、重複する間隔は慎重に処理する必要があります。 

## アプローチ

 強引なアプローチは簡単です。街路灯のすべてのサブセットについて、その間隔の結合がすべての人々をカバーしているかどうかを確認します。 わずかに改善されたとしても、ライトごとにそれが必要かどうかを判断しようとし、指数関数的または組み合わせ検索につながる可能性があります。 さらにシンプルなベースライン アプローチは、各人が自分をカバーするすべてのライトを試し、構造を持たずに貪欲または DP の選択を構築することです。 主なコストはスキャンの繰り返しから発生します。すべての照明コストに対して各人の適用範囲を確認します。$O(nm)$、サブセットの列挙を試みると、指数関数的になります。$m$、すぐに使用できなくなります。 

重要な観察は、私たちは実際には、組み合わせの意味で個々の人々を独立して気にしていないということです。 ここでは、間隔を使用して線上の点をカバーすることのみを考慮します。これは、古典的な最小間隔カバーの問題です。 ひとたび間隔がわかると、人々の実際のアイデンティティは失われます。 ソートされたリスト内のすべての点が、少なくとも 1 つの選択された間隔に含まれていることを確認するだけで済みます。 

これにより、問題は次のように簡略化されます。一連の間隔が与えられた場合、和集合がすべての必要な点をカバーする最小数を選択します。 最適な構造は、人を選別し、各ステップで可能な限りカバー範囲を貪欲に拡大することによって生まれます。 現在カバーされていないポジションについては、それをカバーするのに十分早く始まるすべての間隔を考慮し、最も右に延びる間隔を選択します。 これは、ポイントの間隔をカバーするための標準的なグリーディです。 

欠けている難しさは、適用可能な間隔を効率的に選択することです。 人物と間隔を並べ替えて、左から右にスイープし、現在の位置をカバーできる間隔にポインタを維持できます。

 ## アルゴリズムのチュートリアル

 1. 各街路灯をそのカバー範囲に変換します。$[y - r, y + r]$。 これにより、問題は点にわたる区間範囲に変換されます。 
2. すべての人の役職を昇順に並べ替えます。 カバーされていないポイントを左から右に処理する必要があるため、並べ替えは不可欠です。 
3. すべての間隔を開始座標で並べ替えます。 これにより、現在の位置をカバーできる間隔のみを段階的に考慮することができます。 
4. 一定の間隔でポインタを初期化し、選択したライトの数のカウンタを設定します。 
5. 現在の左端の覆われていない人物の位置については、開始位置がその位置以下であるすべての間隔をスキャンします。 これらのうち、最大の右端点を追跡します。 
6. 現在の位置をカバーできる間隔がない場合 (つまり、右の最大端点がまだ位置より下にある場合)、出力は不可能です。 
7. それ以外の場合は、最も右に達する間隔を選択し、回答を増分し、現在の位置をそのカバー範囲を超えた最初の人物に移動します。 
8. すべての人が覆われるまで繰り返します。 

### なぜ効果があるのか

 あらゆる段階で、私たちは一番左のカバーされていない人をカバーする必要があります。 有効な解は、その位置をカバーする間隔を選択する必要があります。 このようなすべての間隔の中で、最も右に延びる間隔を選択しても、残りのカバーされていないプレフィックスの縮小が最大化されるため、将来の可能性が減少することはありません。 代替間隔が早く終了しても、未カバーのポイントがさらに多く残るだけであり、将来のカバレッジを向上させることはできません。 この貪欲な交換引数により、選択された間隔の数を増やすことなく、各選択肢を最適なソリューションに変換できることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        xs = list(map(int, input().split()))

        intervals = []
        for _ in range(m):
            y, r = map(int, input().split())
            intervals.append((y - r, y + r))

        xs.sort()
        intervals.sort()

        i = 0
        ans = 0
        idx = 0

        nxs = len(xs)

        while i < nxs:
            target = xs[i]

            best = -1
            while idx < m and intervals[idx][0] <= target:
                if intervals[idx][1] >= target:
                    best = max(best, intervals[idx][1])
                idx += 1

            if best < target:
                print("imposible")
                break

            ans += 1

            # move i to first uncovered person
            cover_limit = best
            while i < nxs and xs[i] <= cover_limit:
                i += 1

        else:
            print(ans)

if __name__ == "__main__":
    solve()
```コードは、各街路灯をそのカバレッジ間隔に変換することから始まります。 人物と間隔の両方を並べ替えることで、直線的なスイープが可能になります。 

ポインタ`i`最初に発見された人物を追跡しますが、`idx`これまでに考慮された間隔の数を追跡します。 暴露された各人のために、私たちは前進します`idx`開始点がその人の位置を超えないすべての間隔にわたって、その中で最も遠くに到達可能なエンドポイントを計算します。 

現在の人をカバーできない間隔がある場合は、すぐに印刷されます`"imposible"`。 それ以外の場合は、1 つのライトを選択して先に進みます。`i`その間隔でカバーされる過去のすべての人々。 

微妙な詳細は、`idx`リセットされることはありません。 これは正しいことです。間隔はソートされた順序で処理され、間隔が現在の位置の後に開始されると、その後のスイープでのみ関連するようになります。 

## 実用的な例

 次のサンプルを考えてみましょう。 

入力:```
1
5 3
7 10 3 4 4
3 3
7 1
8 2
```並べ替えられた人物: [3、4、4、7、10]

 間隔: [0,6]、[6,8]、[6,10]

 | ステップ | 現在の位置 | 利用可能な間隔 | 選択された間隔 | 取材範囲 | 次のインデックス |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 3 | [0,6] | [0,6] | 0-6 | 3 |
 | 2 | 7 | [6,8]、[6,10] | [6,10] | 6-10 | 終わり |

 まず、間隔 [0,6] を使用して位置 3 をカバーし、これは両方の 4 もカバーします。 次にカバーされていないポイントは 7 で、それをカバーする最良の間隔は [6,10] で、これでカバーが完了します。 

このトレースは、アルゴリズムがローカル カバレッジを最大のセグメントに自然にマージする方法を示しています。

 ## 特殊なケース

 主なエッジケースは、複数の間隔が重なり合っているものの、到達範囲がわずかに異なる場合です。 人々が [1,2,3] にいて、間隔が [1,2] と [1,3] であるとします。 アルゴリズムは [1,3] を選択し、すべてを 1 ステップでカバーします。 1 をカバーする最初の有効な区間にコミットする素朴なアプローチでは、[1,2] を選択し、その後別の選択が必要となり、次善の答えが生成されます。 

もう一つのケースは完全に不可能です。 人が 100 で存在し、すべての間隔が 50 で終了する場合、スイープはその人に次のように到達します。`best = -1`、すぐに失敗を引き起こします。 これにより、遅れて誤ったカウントが行われることを防ぎます。 

3 番目のケースには、開始が同じである密な間隔が含まれます。 ソートにより、同じ開始点の中で、ポインターを進める前に最も遠くに到達したものが正しく評価され、時期尚早なポインターの移動によって引き起こされる過少選択が防止されます。
