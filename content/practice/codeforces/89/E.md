 ## 解決策
 ## 問題の理解

 ソロモンは要塞の壁に所定の位置に立っています`0`。 彼の右側には、位置を占める一連の氷ブロックが存在する可能性があります`1, 2, ...`。 最初はブロックがまったくありません。 

戦場は長い線である`n`。 戦場の位置で`i`、強さを持った悪魔がいるかもしれない`a[i]`。 落下する氷塊が所定の位置に着地する`i`減少する`a[i]`1つずつ。 力がゼロになると悪魔は消滅します。 

ソロモンは既存の氷ブロックに沿って左右に移動でき、ブロックの存在をすぐ右側に切り替えることができます。 彼がブロックを破壊すると、右にあるすべてのブロックがサポートを失い、戦場に垂直に落ちます。 落下するブロックごとに、その真下のデーモンに 1 回ずつダメージを与えます。 

タスクは、すべての悪魔を破壊する可能な限り最短の操作シーケンスを出力することです。 

制約は驚くほど小さく、`n ≤ 1000`そしてそれぞれの強さは最大でも`100`。 難しいのは計算の複雑さではなく、最適な戦略を発見し、最小性を証明することです。 回答の長さ自体が約 100 メートルに達する可能性があるため、明示的に回答を構築するアルゴリズムは十分に高速です。`2 * sum(a[i]) + O(n)`、これはせいぜい約`200000`。 

危険なのは仕組みを正しく理解することです。 操作の素朴な解釈`A`多くの場合、誤った構築につながります。 

次の例を考えてみましょう。```
n = 3
1 0 1
```ソロモンがその位置に立った場合`0`そして実行します`A`、彼はブロックを作成します`1`。 まだ何も落ちていません。 彼が出演したら`A`またすぐにブロックします`1`破壊され、戦場の独房に落ちます`1`、そこにいる悪魔にダメージを与えます。 

よくある間違いは、1 つのブロックを破壊するとすべてのブロックが落ちると想定することです。 それは誤りです。 右側のサポートされていないブロックのみが一緒に落下します。 

もう 1 つの簡単な間違いは、ギャップがある場合に発生します。```
n = 5
1 0 0 0 1
```上位のブロックチェーンを左から破壊すると、空のセルに多くのブロックが無駄になります。 最適な戦略では、チェーンの開始位置と終了位置を慎重に決定する必要があります。 

最も困難なエッジケースは、単一の悪魔です。```
n = 1
5
```唯一可能な戦略は、最初のブロックの作成と破壊を繰り返すことです。 より深い構造を構築しようとする試みは、不必要な動きを追加するだけです。 

## アプローチ

 強引なアイデアは、氷の構造全体の状態をモデル化し、BFS を使用して最短の操作シーケンスを探索することです。 状態には、ソロモンの位置と既存のブロックのセットが含まれます。 私たちは各州からあらゆる法的操作を試みます。 

すべての操作には単位コストがあるため、これは概念的に機能し、BFS は最短のシーケンスを自動的に見つけます。 

問題は状態空間です。 がある`2^n`可能な氷の構成と`n+1`可能な位置。 たとえ`n = 30`、これは完全に不可能になります。 

本当の進歩は、ブロックが落ちたときに実際に何が重要なのかを観察することから生まれます。 

ブロックが現在位置を占めていると仮定します。`1...k`。 ソロモンがブロックを破壊した場合`x+1`、その後ブロックします`x+1...k`同時に落ちます。 そのサフィックス内のすべての戦場のセルにちょうど 1 つのダメージが与えられます。 

つまり、各破壊操作は連続するサフィックスにダメージを与えます。 

今度は逆に考えてみましょう。 ブロックをシミュレートする代わりに、各位置が破壊されたサフィックスに何回属する必要があるかを尋ねます。 

位置の場合`i`力がある`a[i]`、その場合は正確にヒットする必要があります`a[i]`回。 

いくつかの接尾辞を繰り返し選択するとします`[l, n]`そして一度落とします。 位置`i`選択されたサフィックスごとに 1 回ヒットします`l ≤ i`。 

これにより、問題は差分配列分解に変換されます。 

定義する：```
b[i] = a[i] - a[i+1]
```と`a[n+1] = 0`。 

いつでも`b[i] > 0`、正確に開始する必要があります`b[i]`位置での新しい接尾語攻撃`i`。 

これにより、最適な破壊イベント数がすぐに得られます。```
total_attacks = a[1]
```伸縮後。 

次に、この数学的構造を物理演算に変換して戻します。 

その位置から開始して 1 回の攻撃を実行するには`i`、ソロモンが歩いてブロックする`i-1`、希望の高さまでブロックを構築し、その後ブロックを破壊します`i`。 

最適な戦略は、現在のチェーンを維持しながら攻撃を左から右に処理することです。 これにより、移動が最小限に抑えられ、不要なブロックの再構築が回避されます。 

最終的な構造は理論上の最小値を達成します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n · n) | O(2^n · n) | 遅すぎる |
 | 最適 | O(回答の合計の長さ) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列に追加のゼロを追加して、`a[n+1] = 0`。 
2. ポジションごとに`i`、ここで開始する必要がある新しい攻撃の数を計算します。```
need = a[i] - a[i+1]
```正の値のみが重要です。 

1.ソロモンの現状維持`pos`現在の右端の既存の氷ブロック`mx`。 

最初は両方とも`0`。 

1. 位置を右から左に処理します。 

右から左への処理が重要な簡素化です。 ポジション攻撃を決めるとき`i`、すべての深い位置には、将来のヒットの正確な必要数がすでに含まれています。 

1. その間`a[i] > a[i+1]`、から始まる新しい攻撃を 1 回実行します。`i`。 
2. ソロモンを右の位置に到達するまで移動します`i-1`。 

この時点でブロックは`1...i-1`すでに存在します。 

1. からブロックを作成します`mx+1`現在必要な深さまで。 

すべての創造は操作である`A`に続く`R`さらに動きが必要な場合。 

1. 最も深いブロックから左に戻り、所定の位置に戻ります`i-1`。 
2.ブロックを破壊する`i`操作付き`A`。 

これによりサフィックスが削除されます`[i, mx]`、その範囲内のすべての戦場のセルに1ダメージを与えます。 

1. ポジションに必要な攻撃がすべて行われるまで繰り返します`i`完成しました。 
2. すべての位置が処理された後、構築された操作文字列を出力します。 

### なぜ効果があるのか

 不変条件は、位置を処理する前の条件です。`i`、より大きいすべての位置`i`すでに必要な合計ダメージを正確に受けています。 

ブロックを破壊すると`i`、あらゆるポジション`j ≥ i`追加のヒットが 1 つ追加されます。 正確に実行しますので、`a[i] - a[i+1]`そのような攻撃、位置`i`正確に蓄積します:```
(a[i] - a[i+1]) + (a[i+1] - a[i+2]) + ...
= a[i]
```全体的にヒット。 

すべての攻撃により、少なくとも 1 つのまだ満たされていない位置のヒット数が増加するため、不必要な攻撃は実行されません。 また、既存のチェーン構造を再利用することで動きを最小限に抑えた構造となっています。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    a.append(0)

    ans = []

    current_len = 0
    pos = 0

    for i in range(n - 1, -1, -1):
        cnt = a[i] - a[i + 1]

        for _ in range(cnt):
            while pos < i:
                ans.append('R')
                pos += 1

            while current_len < a[i]:
                ans.append('A')
                current_len += 1

                if current_len < a[i]:
                    ans.append('R')
                    pos += 1

            while pos > i:
                ans.append('L')
                pos -= 1

            ans.append('A')

    print(''.join(ans))

if __name__ == "__main__":
    solve()
```この解決策は、落下するブロックの接尾辞の解釈に依存します。`current_len`現在存在する連続ブロックの数を追跡します。 ソロモンの位置は次のように保存されます。`pos`。 

それぞれの位置が破壊されるため、処理は右から左に行われます。`i`すべてのポジションに影響を与える`≥ i`。 最初に大きなインデックスを修正することで、後で小さなインデックスに誤って過剰なダメージを与えることがなくなります。 

微妙な部分の意味は、`a[i] - a[i+1]`。 

仮定する：```
a = [5, 3, 3, 1]
```位置`1`5 安打が必要、位置`2`3ヒットが必要です。 つまり、正確に 2 回の攻撃がその位置で開始されなければならないことを意味します`1`、これらはポジションごとに受け取ったヒットであるため、`1`でも立場によるものではない`2`。 

コードはこれらの攻撃を物理的に実現します。 

もう一つ間違いやすいのは、チェーンを伸ばした後の動きです。 新しいブロックを構築するとき、ソロモンは拡張とともに右に移動します。 目的のブロックを破壊する前に、左の正しい位置に戻らなければなりません。 

この実装では、操作をリストに直接保存し、最後に一度結合します。 繰り返しの文字列連結はここでも通過しますが、リストはよりクリーンで安全です。

import io

                    ans.append('R')
                    pos += 1

            while pos > i:
                ans.append('L')
                pos -= 1

            ans.append('A')

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    backup = sys.stdout
    sys.stdout = out

    solve()

    sys.stdout = backup

 ## 特殊なケース

 単一位置の場合を考えてみましょう。```
1
5
```アルゴリズムは以下を計算します。```
a[1] - a[2] = 5
```つまり、ちょうど 5 回の攻撃がその位置で始まります`1`。 

各攻撃は単にブロックを作成するだけです`1`そしてすぐに破壊します。 動きは起こりません。 すべてのヒットには少なくとも 1 つの破壊が必要であるため、生成されるシーケンスは最適です。 

次に、次のことを考えてみましょう。```
5
1 0 0 0 1
```アルゴリズムはその位置で 1 回の攻撃を開始します`5`そしてその位置で1回の攻撃`1`。 

ポジションでの攻撃`1`すべての細胞にダメージを与えるが、細胞のみにダメージを与える`1`そして`5`案件。 空のセルは無駄なヒットを安全に吸収します。 

空のセルに当たらないようにしようとする不用意な戦略は、チェーンを不必要に再構築する動きを無駄にすることになります。 

最後に、強度を厳密に減少させることを検討します。```
4
4 3 2 1
```違いは次のとおりです。```
1 1 1 1
```すべての位置で 1 つの新しいサフィックス攻撃が開始されます。 

このアルゴリズムは、ネストされたサフィックスを自然に作成します。```
[4]
[3,4]
[2,3,4]
[1,2,3,4]
```位置`1`4回ヒット、位置`2`3回など。 これは、証明の背後にある伸縮式不変条件を裏付けています。
