 ## 解決策
 ## 問題の理解

 この銀行はダイヤモンドを一連のセルに保管しています。 1 分ごとに、セキュリティ システムはすべての隣接するペアの合計をチェックします。$$a_1 + a_2,\ a_2 + a_3,\ \dots,\ a_{n-1} + a_n$$前回のチェックと比較してこれらの合計のいずれかが変化すると、アラームがトリガーされます。 

ジョーはチェック間でダイヤモンドを移動することができます。 1 回の移動で、1 つのダイヤモンドをあるセルから別のセルに、あるセルからポケットに、またはポケットからセルに戻すことができます。 彼が持っているのはせいぜい`m`毎分正確に動きます`k`出発の数分前。 最後にポケットに残ったものは盗まれます。 

課題は、隣接するすべての合計を毎分変化させずに、削除されるダイヤモンドの数を最大化することです。 

この制約により、個々のダイヤモンドに対するシミュレーションは即座に除外されます。 セルの数はたったの$10^4$、しかし両方とも`m`そして`k`到達できる$10^9$。 利用可能な操作の合計数は次のようになります。$10^{18}$、そのため、分刻みの動きをシミュレートするアプローチは不可能です。 ソリューションでは、セキュリティ システムによって課された不変条件から数学的構造を抽出する必要があります。 

主な困難は、どの構成が隣接するすべての合計を保持するかを理解することです。 不注意なアプローチでは、配列は変更されないままでなければならないと想定する可能性がありますが、これは誤りです。 

考慮する：```
3 2 1
4 1 3
```隣接する合計は次のとおりです。```
5 4
```Joe は配列を次のように変換できます。```
3 2 2
```合計は次のようになります。```
5 4
```そして彼はダイヤモンドを1つ盗みます。 

別の微妙なケースが現れるのは、`n = 2`。```
2 3 10
2 3
```唯一の隣接和は`a1 + a2`。 その合計は一定でなければならないため、ダイヤモンドを削除するとすぐに変更されます。 答えは`0`。 単純な交互戦略は、補償する 3 番目のセルがないため失敗します。 

パリティも重要です。 偶数の場合`n`、1 つの要素が固定されると、システムはすべての値を完全に決定します。 奇数の場合`n`、自由度が 1 つあり、それがまさに盗みを許可するものです。 

例えば：```
5 100 100
10 1 10 1 10
```交互の合計は次のとおりです。$$10 - 1 + 10 - 1 + 10 = 28$$ジョーがどれだけ多くの手を持っていても、非負の値によって強制される最小可能な交互合計を超える量を盗むことはできません。 

ローカル転送のみを考慮する貪欲な実装では、このグローバルな不変条件が見逃される可能性があります。 

## アプローチ

 ブルートフォースの観点は、各分を状態遷移の問題として扱うことから始まります。 最大でも、到達可能なすべての配列を列挙しようと試みることができます。`m`隣接するすべての合計を維持しながら移動します。 1 つの有効な構成から、可能なすべての転送を試し、結果として得られる隣接する合計が同一のままかどうかを確認します。 

条件を確認しやすいため、これは小さな入力に対して機能します。 移動するたびに、隣接する合計のみが変化します。 残念ながら、州の数はすぐに爆発的に増加します。 すべてのセルにダイヤモンドが数個しか含まれていない場合でも、分布の数はダイヤモンドの総数に応じて指数関数的に増加します。 まで$10^4$までのセルと値$10^5$、力技は絶望的です。 

転換点は、セキュリティ システムによって課される方程式を研究することで起こります。 

現在の配列が次のようになっているとします。$$b_1, b_2, \dots, b_n$$そして、元の隣接する合計を保持する必要があります。$$b_i + b_{i+1} = a_i + a_{i+1}$$あらゆる人にとって$i$。 

隣接する方程式を減算すると、次のようになります。$$b_{i+1} - a_{i+1} = -(b_i - a_i)$$変更では符号を交互にする必要があります。 次のように定義すると、$$x = b_1 - a_1$$それから：$$b_i = a_i + (-1)^{i-1}x$$すべての有効な構成は単一のパラメータによって決定されます`x`。 

問題ははるかに単純になります。 ジョーは配列の合計を減らすことでダイヤモンドを盗みます。 最終的な合計は次のようになります。$$\sum b_i$$盗まれた金額は次のとおりです。$$\sum a_i - \sum b_i$$偶数の場合`n`、交互に加算と減算が相殺されるため、合計は決して変わりません。 盗むことは不可能です。 

奇数の場合`n`、合計は正確に変化します`x`。 具体的には：$$\sum b_i = \sum a_i + x$$盗まれたダイヤモンドを最大化するには、可能な限り最小のダイヤモンドが必要です`x`。 

すべてのセルが非負でなければならないため、次のようになります。 

奇数の位置の場合:$$a_i + x \ge 0$$偶数の位置の場合:$$a_i - x \ge 0$$したがって：$$-\min(\text{odd positions}) \le x \le \min(\text{even positions})$$最低限実現可能なもの`x`は：$$-\min(\text{odd positions})$$盗める最大量は次のようになります。$$-x = \min(\text{odd positions})$$もし`n`奇数です。 

操作数という制約がまだ 1 つ残っています。 

ダイヤを 1 つずつセルを変更するには、そのセルに出入りする 1 回の移動が必要です。 移動されたダイヤモンドの合計数は次のようになります。$$|x| \times n$$すべてのセルが正確に変化するため、`|x|`。 

ジョーが持っているのは`m * k`操作の合計。 したがって、実際の答えは次のように制限されます。$$\left\lfloor \frac{m \cdot k}{n} \right\rfloor$$両方の制限を組み合わせると、最終的な答えが得られます。

 ## アルゴリズムのチュートリアル

 1. 配列を読み取り、使用可能な操作の合計数を計算します。$$\text{ops} = m \cdot k$$1. もし`n`偶数です、印刷します`0`。 

偶数長の配列の場合、隣接する合計をすべて保存すると、合計も保存されます。 ダイヤモンドは星系から出ることはできません。 

1. それ以外の場合は、1 ベースのインデックス付けで奇数のインデックス付き位置の最小値を見つけます。 

これらはポジションです`1, 3, 5, ...`。 

1. この最小値を次のようにします`mn`。 

数学的特徴付けは、ジョーが最大で盗むことができることを示しています`mn`すべてのセルを非負に保ちながらダイヤモンドを作成します。 

1. 盗まれたダイヤモンドはすべて変更する必要があります`n`セルを 1 単位ずつ交互に動かします。 

とても盗みます`t`ダイヤモンドの正確な価格は次のとおりです。$$t \cdot n$$操作。 

1. 運用予算では、最大でも次のことが許可されます。$$\left\lfloor \frac{m \cdot k}{n} \right\rfloor$$盗まれるダイヤモンド。 

1. 答えは次のとおりです。$$\min\left(mn,\ \left\lfloor \frac{m \cdot k}{n} \right\rfloor\right)$$### なぜ効果があるのか

 有効な最終構成はすべて次の条件を満たす必要があります。$$b_i = a_i + (-1)^{i-1}x$$ある整数に対して`x`。 これは、隣接和方程式によって一意に強制されます。 

いつ`n`が偶数であれば、交互の変化は合計でキャンセルされるため、盗むことは不可能です。 

いつ`n`奇数、減少しています`x`銀行内のダイヤモンドの総量が減ります。 実現可能な最小値は、奇数インデックスのセルの非負性によって制限され、次のようになります。$$x \ge -\min(\text{odd positions})$$したがって、盗まれる可能性のある最大の金額は、その最小の奇数位置の値に等しくなります。 

変化`x`by one はすべてのセルを 1 つのひし形で変更するため、正確には`n`盗まれたダイヤモンドごとに操作が必要です。 操作バジェットによって 2 番目の上限が作成されます。 両方の限界は同時に達成可能であるため、それらの最小値を取ることで最適な答えが得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    a = list(map(int, input().split()))

    if n % 2 == 0:
        print(0)
        return

    mn = min(a[::2])

    ops = m * k

    print(min(mn, ops // n))

solve()
```コードに実装される最初の観察はパリティ チェックです。 偶数長の配列では、隣接する合計を保持しながら合計を変更することはできないため、答えはすぐにゼロになります。 

奇数長の配列の場合、解には奇数のインデックスが付いたセルの最小値のみが必要です。 Python はゼロベースのインデックスを使用するため、位置`1, 3, 5, ...`ステートメント内のインデックスに対応します`0, 2, 4, ...`、まさにその通りです`a[::2]`。 

操作制限は次のように計算されます。`m * k`。 Python の整数は任意精度であるため、両方の値がこの値に達した場合でもオーバーフローの問題は発生しません。$10^9$。 

表現`ops // n`移動予算を考慮して盗めるダイヤモンドの最大数を計算します。 盗まれたダイヤモンドはすべて正確な価格がかかります`n`動く。 

最終的な答えは、構造上の限界と動作上の限界の小さい方です。 

よくある間違いは、次の値で割ることです。`2`または、各ダイヤモンドに必要な操作は 1 つだけであると仮定します。 不変条件により、すべてのセルが交互の方向に同時に変更されるため、盗まれた 1 つのダイヤモンドの価格は常に正確になります。`n`操作。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    n, m, k = map(int, input().split())
    a = list(map(int, input().split()))

    if n % 2 == 0:
        print(0)
        return

    mn = min(a[::2])
    print(min(mn, (m * k) // n))

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    backup = sys.stdout
    sys.stdout = out

    solve()

    sys.stdout = backup
    return out.getvalue().strip()

# provided sample
assert run(
"""2 3 1
2 3
"""
) == "0", "sample 1"

# odd length, enough operations
assert run(
"""3 100 100
4 1 3
"""
) == "3", "full structural limit"

# odd length, operation budget binds
assert run(
"""3 1 1
4 1 3
"""
) == "0", "not enough operations"

# minimum size
assert run(
"""1 5 2
7
"""
) == "7", "single cell"

# even length always impossible
assert run(
"""4 100 100
1 2 3 4
"""
) == "0", "even length invariant"

# all equal values
assert run(
"""5 10 10
5 5 5 5 5
"""
) == "4", "operation limit smaller"

# zero among odd positions
assert run(
"""5 100 100
0 9 8 9 7
"""
) == "0", "nonnegative constraint"

```隣接する合計がまったくないため、セキュリティ システムは制限を課しません。 ジョーは 7 つのダイヤモンドをすべて取り除くことができます。 アルゴリズムは以下を計算します。 

| 数量 | 値 |
 | --- | --- |
 | 奇数桁の最小値 | 7 |

 | 予算制限 | 10 |
