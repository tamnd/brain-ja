 ## 解決策
 ## 問題の理解

 チップが入ったグリッドがあります。 すべてのチップは、左、右、上、下の 1 つの方向を保存します。 

あるチップから移動を開始すると、プロセスは次のように動作します。 

現在のチップは矢印の方向を向いています。 その行または列にあるすべての残りのチップの中から、その方向に最も近いチップを選択します。 現在のチップは消滅し、見つかったチップが新しい現在のチップになります。 必要な方向にチップがなくなるまでこれを繰り返します。 その後、最後のチップも消えて移動が終了します。 

移動のスコアは、削除されたチップの数に等しくなります。 

タスクは 2 つの値を計算することです。 

まず、単一の開始チップから取得できる最大スコアです。 

第二に、その最大値に達する開始チップの数。 

グリッド サイズは合計で最大 5000 セルです。 それは問題の性質を完全に変えます。 私たちは、線形スキャンのみが重要な巨大なまばらな構造を扱っているのではありません。 アン$O((nm)^2)$アプローチはまだ境界線にあるかもしれませんが、立体的なものは完全に不可能です。 

危険なのは、途中で基板が変わってしまうということです。 チップが消えると、その後のジャンプはチップを飛び越えて、より遠くに着地する可能性があります。 行と列を繰り返しスキャンする単純なシミュレーションでは、誤って過剰な作業が再計算される可能性があります。 

誤った実装を簡単に破壊してしまういくつかのエッジケースがあります。 

取り除かれたチップがすぐに消えることを忘れた場合に永遠にループするチェーンを考えてみましょう。```
1 2
RL
```左側のチップから始めます。 

左側のチップは右を指しているので、右側のチップに移動して左側のチップを削除します。 

これで右のチップだけが残りました。 左を指しますが、チップがなくなったので消えて終了します。 

正解は 2 であり、無限サイクルではありません。 

もう 1 つの微妙なケースは、複数のチップが同じ方向に存在するが、最も近いものだけが問題となる場合です。```
1 4
R.RL
```最初のチップから開始して、4 番目のセルではなく 3 番目のセルにジャンプします。 到達可能なチップを不用意に実装すると、間違ったパスが生成されます。 

もう 1 つのよくある間違いは、プロセスが最初のボードから構築されたグラフ エッジのみに依存すると仮定することです。 そうではありません。 

例：```
1 3
RRL
```Initially:

 Cell 1 points to cell 2.

 Cell 2 points to cell 3.

 Cell 3 points to cell 2.

 セル 1 から開始すると、セル 1 が消えます。 セル 2 から見て、右側に最も近いチップはセル 3 になります。セル 2 が消えると、セル 3 の左側には誰もいなくなります。 The move length is 3.

 静的なグラフでは、こうした動的な変化が見逃されます。 

## アプローチ

 最も直接的なアプローチは、開始チップごとに独立してゲームをシミュレートすることです。 

現在の生きているチップのセットを維持します。 各ステップで、現在の位置から、最も近い生きているチップが見つかるまで、必要な方向に外側にスキャンします。 次に、現在のチップを削除して続行します。 

これはルールに正確に従っているため、これは正しいです。 

The problem is speed. ボードに次のものが含まれているとします。$K$チップス。 1 つのシミュレーションですべてが削除される可能性があります$K$各ステップは行全体または列全体をスキャンできます。 最悪の場合こうなります$O(K^2)$1回のスタートで、そして$O(K^3)$全体。 と$K \le 5000$、これは絶望的です。 

重要な点は、削除は行と列内のローカルの隣接要素にのみ影響するということです。 

チップがその位置にあると仮定します$(r,c)$消えます。 この場合、4 つの関係のみが変化します。 

左側に最も近いチップは、右側に最も近いチップに接続できるようになります。 

上の最も近いチップは、下の最も近いチップに接続できるようになります。 

他には何も変わりません。 

これは、二重リンク リストからノードを削除するのとまったく同じ考え方です。 

チップごとに 4 つのポインターを保存します。 

同じ列に残っている最も近いチップ。 

同じ列にある最も近いチップ。 

同じ列の最も近いチップアップ。 

同じ列内の最も近いチップ。 

ここでチップを削除すると、$O(1)$。 隣接するものを再接続するだけです。 

残りの課題は、シミュレーションごとに構造が変更されるため、構造を永久に破壊することができないことです。 標準的なトリックはロールバックです。 

シミュレーション中、すべてのポインターの更新はスタックに記録されます。 シミュレーションが終了したら、すべての変更を元に戻し、元の構造を復元します。 

それぞれの削除では、定数のポインタ変更のみが発生します。 各チップは 1 回のシミュレーション中に最大 1 回削除されるため、シミュレーションごとの合計作業量は削除されるチップの数に比例します。 

すべての開始チップ全体では、複雑さは次のようになります。$O(K^2)$に快適にフィットします。$K \le 5000$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(K^3)$|$O(K)$| 遅すぎる |
 | 最適 |$O(K^2)$|$O(K)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. グリッドを読み取り、すべてのチップに整数 ID を割り当てます。 

空のセルはゲームに参加しないため、完全に無視されます。 
2. 行ごとに、左右のポインタを使用して連続するチップを接続します。 

チップ A が同じ行のチップ B の直前にある場合、次のようになります。`right[A] = B`そして`left[B] = A`。 
3. 列ごとに、アップポインタとダウンポインタを使用して連続するチップを接続します。 

これにより、すべてのチップの周囲に 4 つの二重リンク リストが構築されます。 
4. 開始位置としてのすべてのチップについて、移動をシミュレートします。 

私たちは以下を維持します:

 - 現在のチップ
 - 削除されたチップの数
 - すべてのポインター変更を保存するロールバック スタック
 5. チップから続行するには、チップに書かれている指示に従ってください。 

方向が次の場合:

 -`L`に移動します`left[cur]`-`R`に移動します`right[cur]`-`U`に移動します`up[cur]`-`D`に移動します`down[cur]`リンクされたリストは常に削除されたチップをスキップするため、その方向で最も近い生きているチップが自動的に与えられます。 
6. 現在のチップを削除する前に、隣接するチップを再接続します。 

水平隣接の例:

 もし`left[cur] = a`そして`right[cur] = b`、削除後:

 -`right[a] = b`-`left[b] = a`垂直方向にも同じことが行われます。 
7. 変更されたすべてのポインターは、次のようにロールバック スタックにプッシュされます。`(array_name, index, old_value)`これにより、後で正確に前の状態を復元できます。 
8. 次のチップがなくなるまで続けます。 

現在のチップは停止する前に削除され、ゲームのルールに正確に一致します。 
9. 1 つのシミュレーションが終了したら、取得したスコアをグローバル最大値と比較します。 
10. 保存されたスタックを使用して、すべてのポインターの変更をロールバックします。 

これにより、次の開始チップ用に元のボードが復元されます。 

### なぜ効果があるのか

 リンクされたリストは常に、各行と列の現在有効なチップを正確に表します。 

チップを削除すると、すぐ隣のチップが再接続されるため、今後の走査では、削除されたチップが自動的にスキップされ、最も近い残りのチップに到達します。 ゲーム内のすべての動きは、生きている最近傍にのみ依存するため、シミュレーションはルールに正確に一致します。 

ロールバックでは、変更されたすべてのポインターが以前の値に復元されるため、各開始シミュレーションは変更されていない元のボードから始まります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
grid = [input().strip() for _ in range(n)]

ids = [[-1] * m for _ in range(n)]
pos = []
dirs = []

k = 0

for i in range(n):
    for j in range(m):
        if grid[i][j] != '.':
            ids[i][j] = k
            pos.append((i, j))
            dirs.append(grid[i][j])
            k += 1

LEFT = [-1] * k
RIGHT = [-1] * k
UP = [-1] * k
DOWN = [-1] * k

# build row links
for i in range(n):
    prev = -1
    for j in range(m):
        v = ids[i][j]
        if v != -1:
            if prev != -1:
                RIGHT[prev] = v
                LEFT[v] = prev
            prev = v

# build column links
for j in range(m):
    prev = -1
    for i in range(n):
        v = ids[i][j]
        if v != -1:
            if prev != -1:
                DOWN[prev] = v
                UP[v] = prev
            prev = v

arrays = {
    'L': LEFT,
    'R': RIGHT,
    'U': UP,
    'D': DOWN
}

best = 0
count = 0

for start in range(k):
    history = []

    def set_value(arr, idx, val):
        history.append((arr, idx, arr[idx]))
        arr[idx] = val

    cur = start
    score = 0

    while cur != -1:
        score += 1

        d = dirs[cur]

        if d == 'L':
            nxt = LEFT[cur]
        elif d == 'R':
            nxt = RIGHT[cur]
        elif d == 'U':
            nxt = UP[cur]
        else:
            nxt = DOWN[cur]

        l = LEFT[cur]
        r = RIGHT[cur]
        u = UP[cur]
        dwn = DOWN[cur]

        if l != -1:
            set_value(RIGHT, l, r)

        if r != -1:
            set_value(LEFT, r, l)

        if u != -1:
            set_value(DOWN, u, dwn)

        if dwn != -1:
            set_value(UP, dwn, u)

        cur = nxt

    if score > best:
        best = score
        count = 1
    elif score == best:
        count += 1

    while history:
        arr, idx, old = history.pop()
        arr[idx] = old

print(best, count)
```最初の段階では、グリッドをコンパクトなチップ ID に変換します。 これは、空のセルがゲームに参加することがなく、チップのみを使用してすべての配列を小さく保つため、重要です。 

4 つの隣接する配列は、行と列にわたって二重にリンクされたリストを形成します。 例えば、`RIGHT[x]`常にチップの右側にある最も近い生存チップを意味します`x`。 

シミュレーション ループはゲームの定義に正確に従います。 現在のチップを削除する前に、現在のポインターを使用して次のチップを計算します。 削除後、ポインタが再配線されるため、今後の検索では削除されたチップがスキップされます。 

ロールバック スタックは最もデリケートな部分です。 ポインターを変更するたびに、前の値を上書きする前にそれを保存する必要があります。 更新が 1 つでも欠けていると、後のシミュレーションが破損します。 

もう 1 つの微妙な点は、次のチップが存在しない場合でも、最後のチップもカウントして削除する必要があることです。 それが理由です`score`確認する前に増加します`nxt`。
