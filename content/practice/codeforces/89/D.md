 ## 解決策
 ## 問題の理解

 デス・スターは半径の球体です`R`。 その中心は点から始まります`A`等速ベクトルで永久に直線運動します`v`。 すべての鉱山は 2 種類のジオメトリで構成されます。 

最初の部分は、次の点を中心とする球です。`O`半径あり`r`。 

2番目の部分はスパイクのセットです。 それぞれのスパイクは、次のセグメントの一部にすぎません。`O`に`O + p`。 

デス・スターのどこかの点が地雷本体またはそのスパイクのいずれかに触れた瞬間、地雷は爆発します。 すべての地雷の中で最も早い衝突時間を計算するか、デス・スターが何も触れずに永久に飛行できることを報告する必要があります。 

オブジェクト数の点では制約は少ないです。 多くてもあります`100`鉱山があり、各鉱山には最大でも`10`スパイク。 つまり、幾何学的プリミティブの総数はわずかで、およそ 1,000 個です。 これは、意図された困難が最適化トリックではなく幾何学的推論であることを強く示唆しています。 

座標は次のように大きくできます。`10000`、そして動きは時間的に連続的です。 これにより、小さなタイムステップでのシミュレーションが除外されます。 シミュレーション時間を 1 秒あたり 100 万ステップ使用したとしても、サンプル間で発生する衝突を見逃す可能性があります。 ソリューションは、正確な幾何学的公式を使用して分析的に機能する必要があります。 

最も危険な実装上の間違いは、スパイクを不適切に処理することに起因します。 

デス・スターのパスがスパイクの無限線の近くを通過するが、最も近い点がセグメント自体の外側にあると仮定します。```
Spike: from (0,0,0) to (2,0,0)
Star center path: x = 5, y = t
R = 1
```無限直線距離が近くなる`(5,0)`, しかし、その点はセグメント上にありません。 不用意なライン距離の式を使用すると、誤った衝突が報告されてしまいます。 投影をセグメントの端点にクランプする必要があります。 

もう一つの簡単な間違いは、デス・スター自体に半径があることを忘れていることです`R`。 動く物体は点ではありません。 地雷本体への接触は、中心間の距離が正確になったときに起こります。`R + r`、だけではありません`r`。 

例えば：```
Star center starts at (0,0,0)
Velocity (1,0,0)
R = 5

Mine center at (20,0,0)
Mine radius = 2
```中心距離が以下になると衝突が発生します`7`、したがって、答えは次のとおりです`13`、 ない`18`。 

スパイク上の最も近い点が 1 つのエンドポイントにある場合、より微妙なエッジ ケースが現れます。 セグメントへの投影は、数値的にはわずかに下回る可能性があります。`0`以上`1`浮動小数点精度のため。 慎重にクランプしないと、マイナスの衝突時間が発生したり、接線方向のタッチを見逃したりする可能性があります。 

もう 1 つの重要なケースは接線です。 この問題では、接触は破壊としてカウントされると明示的に述べられています。 二次式の判別式がちょうどゼロになった場合でも、有効な衝突が存在します。 

例：```
Star center path: y = 5
Mine body center: origin
R + r = 5
```軌跡は展開された球に接しており、正解は接線時間です。 

## アプローチ

 この強引なアイデアは、時間をシミュレーションし、デス・スターが地雷オブジェクトと交差するかどうかを繰り返しテストすることです。 サンプリング時間ごとに`t`、星の中心を計算できます`A + vt`次に、すべての球とすべてのセグメントに対する距離を確認します。 

このアプローチは、衝突テスト自体が簡単であるため、概念的に単純です。 球の衝突は中心の距離に短縮され、スパイクの衝突は点とセグメントの距離に短縮されます。 

問題は連続動作です。 安全なステップ サイズはありません。 特にデス・スターが高速で移動する場合、またはスパイクにほとんど触れない場合には、2 つのサンプリング時間の間で衝突が発生する可能性があります。 信頼性を確保するためにステップ サイズを十分に小さくすることは不可能になります。 

重要な観察は、あらゆる衝突条件が分析的に表現できるということです。 

地雷体の場合、デス・スターは移動中心が距離に達したときに正確に衝突します。`R + r`鉱山中心部から。 星の中心は直線的に移動するので、これが光線と球の交点になります。 

スパイクについては、別の考え方もできます。 半径の球を移動する代わりに`R`、星の中心を移動点として保持し、距離によってスパイク セグメントを拡大します。`R`。 移動点が距離に達したときに衝突が発生します`R`セグメントから。 

軌道は 3D における光線です。 光線上の移動点と固定セグメント間の最短距離は、時間の二次関数です。 巨大な式を直接導き出すのではなく、よりクリーンな幾何学的トリックを使用します。 

時間に`t`、星の中心は次のとおりです。$$P(t) = A + vt$$一番早いものが必要です`t >= 0`次のような:$$\text{dist}(P(t), \text{segment}) \le R$$これは、ラインとセグメント間の標準的な最近接問題になります。 両方のパラメータの最小化子は、ドット積を使用して導出できます。 セグメントの数が少ないため、セグメントごとに小さな二次系を解くことさえ簡単です。 

最終的なソリューションでは、すべての地雷本体とすべてのスパイクを個別にチェックし、最も早い有効な衝突時間を計算し、最小値を取得します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 無制限 / 精度に依存 | お(1) | 遅すぎて信頼性が低い |
 | 最適 | O(nm) | お(1) | 承認済み |

 ここ`m`最大でも地雷ごとのスパイクの数です`10`。 

## アルゴリズムのチュートリアル

 1. すべての点とベクトルを、基本的な演算 (加算、減算、スカラー倍算、ドット積、二乗ノルム) を使用して 3D ベクトルとして表現します。 
2. 各地雷体について、光線と球の交差を解決します。 

デス・スターの中心は次のように動きます。$$P(t)=A+vt$$地雷球との衝突は、次の場合に発生します。$$|P(t)-O|=R+r$$両辺を二乗すると、次の二次方程式が生成されます。`t`。 
3. 二次方程式を展開します。$$|A+vt-O|^2=(R+r)^2$$させて：$$d=A-O$$それから：$$(v \cdot v)t^2 + 2(d \cdot v)t + (d \cdot d-(R+r)^2)=0$$4. 判別式を計算します。 

負の値の場合、軌道は拡張された球に到達しません。 

それ以外の場合は、両方の根を計算し、最小の非負の根を保持します。 
5. すべてのスパイクセグメントに対して、`O`に`Q=O+p`、移動点が移動する最も早い時間を計算します。`P(t)`距離に達する`R`セグメントから。 
6. セグメントを次のようにパラメータ化します。$$S(u)=O+u(Q-O), \quad 0 \le u \le 1$$7. 衝突時、最も近い点が端点でない限り、移動点とセグメント点の間のベクトルはセグメント方向に対して垂直でなければなりません。 

これにより、以下が最小限に抑えられます。$$|A+vt-(O+us)|^2$$どこ：$$s=Q-O$$8. ドット積を使用して、光線とセグメントの間の最も近いペアを求めます。 

制約のないミニマイザーは次の線形システムを満たします。`t`そして`u`。 
9. クランプ`u`の中へ`[0,1]`。 

最適値がセグメントの外側にある場合、最も近い点は実際には 1 つの端点になります。 次に、問題は半径を伴う光線と球の交差に帰着します。`R`そのエンドポイントを中心にします。 
10. 内装ケースは最適なものを代用してください。`u(t)`距離方程式に戻り、結果として得られる距離の二次方程式を正確に解きます。`R`。 
11. 球とスパイクからのすべての有効な衝突時間のうち、最小値を出力します。 衝突が存在しない場合は、印刷します`-1`。 

### なぜ効果があるのか

 アルゴリズムは、デス・スターを破壊する可能性のあるすべての幾何学的オブジェクトをチェックします。 地雷体との衝突は、移動中心が拡張された半径の球体に入るのと同等です。`R + r`。 スパイク衝突は移動中心到達距離に相当`R`スパイクセグメントから。 

各オブジェクトの最も早い衝突時間は、数値的に近似するのではなく、ジオメトリから正確に計算されます。 二次方程式はユークリッド距離公式から直接得られるため、接線を含むすべての有効なタッチが検出されます。 答えは単にすべての独立したオブジェクトにわたる最小衝突時間であるため、全体的な最も早い爆発は正しく計算されます。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

EPS = 1e-10
INF = 1e100

class Vec:
    def __init__(self, x, y, z):
        self.x = float(x)
        self.y = float(y)
        self.z = float(z)

    def __add__(self, other):
        return Vec(self.x + other.x,
                   self.y + other.y,
                   self.z + other.z)

    def __sub__(self, other):
        return Vec(self.x - other.x,
                   self.y - other.y,
                   self.z - other.z)

    def __mul__(self, k):
        return Vec(self.x * k,
                   self.y * k,
                   self.z * k)

    def dot(self, other):
        return self.x * other.x + self.y * other.y + self.z * other.z

    def norm2(self):
        return self.dot(self)

def ray_sphere(A, v, C, rad):
    d = A - C

    a = v.dot(v)
    b = 2.0 * d.dot(v)
    c = d.dot(d) - rad * rad

    disc = b * b - 4.0 * a * c

    if disc < -EPS:
        return INF

    disc = max(disc, 0.0)
    sq = math.sqrt(disc)

    t1 = (-b - sq) / (2.0 * a)
    t2 = (-b + sq) / (2.0 * a)

    ans = INF

    if t1 >= -EPS:
        ans = min(ans, max(0.0, t1))

    if t2 >= -EPS:
        ans = min(ans, max(0.0, t2))

    return ans

def segment_collision(A, v, P0, P1, R):
    s = P1 - P0
    ss = s.dot(s)

    # endpoint collisions
    ans = min(
        ray_sphere(A, v, P0, R),
        ray_sphere(A, v, P1, R)
    )

    vv = v.dot(v)
    vs = v.dot(s)

    w0 = A - P0
    ws = w0.dot(s)
    wv = w0.dot(v)

    denom = vv * ss - vs * vs

    if abs(denom) < EPS:
        return ans

    # u(t) from minimizing distance
    # substitute into distance formula
    # gives quadratic At^2 + Bt + C = R^2

    Acoef = vv - (vs * vs) / ss
    Bcoef = 2.0 * (wv - (vs * ws) / ss)
    Ccoef = w0.dot(w0) - (ws * ws) / ss - R * R

    disc = Bcoef * Bcoef - 4.0 * Acoef * Ccoef

    if disc < -EPS:
        return ans

    disc = max(disc, 0.0)
    sq = math.sqrt(disc)

    roots = [
        (-Bcoef - sq) / (2.0 * Acoef),
        (-Bcoef + sq) / (2.0 * Acoef)
    ]

    for t in roots:
        if t < -EPS:
            continue

        t = max(0.0, t)

        u = (vs * t - ws) / ss

        if -EPS <= u <= 1.0 + EPS:
            ans = min(ans, t)

    return ans

def solve():
    Ax, Ay, Az, vx, vy, vz, R = map(int, input().split())

    A = Vec(Ax, Ay, Az)
    v = Vec(vx, vy, vz)

    n = int(input())

    best = INF

    for _ in range(n):
        ox, oy, oz, r, m = map(int, input().split())

        O = Vec(ox, oy, oz)

        best = min(best, ray_sphere(A, v, O, R + r))

        for _ in range(m):
            px, py, pz = map(int, input().split())

            P1 = O + Vec(px, py, pz)

            best = min(best, segment_collision(A, v, O, P1, R))

    if best >= INF / 2:
        print(-1)
    else:
        print("{:.10f}".format(best))

solve()
```の`ray_sphere`関数は、地雷の本体とスパイクのエンドポイントとの衝突を処理します。 この導出は、パラメトリック光線方程式を球方程式に代入することで直接得られます。 

微妙な部分は、`segment_collision`。 点からセグメントまでの最短距離は、セグメント内で常に実現されるわけではありません。 そのため、エンドポイントの衝突は最初に個別にチェックされます。 

内部の場合、最も近いセグメントのパラメータ`u`は分析的に導出されます。 二次方程式を解いた後、対応する`u`実は中にあります`[0,1]`。 そうでない場合、想定される衝突はセグメント自体ではなく、無限のライン延長部に属します。 

接線付近では浮動小数点の許容値が重要です。 コードはわずかに負の判別式をゼロにクランプし、範囲内の値を受け入れます。`EPS`有効なパラメータ範囲。
