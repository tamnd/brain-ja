 ## 解決策
 ## 問題の理解

 数直線上の線分の集合と、部分範囲について尋ねる複数のクエリが与えられます。 クエリセグメントごとに$[x, y]$、結合がすべての実数点を完全にカバーする指定されたセグメントの最小数を知りたいのです。$x$に$y$。 カバレッジにギャップがある場合、答えは不可能なので、-1 が出力されます。 

これは個別のカバレッジの問題ではありません。 要件は継続的なカバレッジであるため、次のような間隔になります。$[1,3]$そして$[4,5]$共同でカバーしないでください$[1,5]$3 と 4 の間のギャップにより、3.5 などのカバーされていない実際の値が残るためです。 

制約は私たちを$O((n + m)\log n)$または$O((n + m)\log \max r)$解決。 まで$2 \cdot 10^5$間隔とクエリでは、間隔にわたるクエリごとのリニア スキャンが遅すぎます。 平$O(nm)$ではすぐには不可能です$4 \cdot 10^{10}$操作。 

微妙な問題は、クエリは独立しているものの、間隔は共有されることです。 単純なクエリごとの貪欲な場合、すべての候補をスキャンすることで間隔を繰り返し選択できますが、それはあまりにも多くの作業を繰り返すことになります。 

もう 1 つの重要なエッジ ケースは切断です。間隔は部分的に重複する可能性がありますが、それでも連続チェーンを形成できません。 例えば：```
intervals: [1,3], [3,5]
query: [1,5]
```実際のカバレッジにはエンドポイントに触れるだけで十分であるため、これは有効です。 しかし：```
intervals: [1,3], [3,4], [5,6]
query: [1,6]
```(4,5) のギャップのため失敗します。 貪欲なアルゴリズムでは、現在のカバレッジ境界を越える間隔がないことを明示的に検出する必要があります。 

最後に、重複する間隔は冗長になる可能性があり、早い段階で間違った間隔を選択すると、セグメント数が最適ではなくなる可能性があります。 正しいソリューションでは、重複する間隔を選択するだけでなく、各ステップでのリーチを常に最大化する必要があります。 

## アプローチ

 ブルート フォース アプローチでは、各クエリが個別に処理されます。 お問い合わせの場合$[x, y]$、現在カバーされているポイントまたはその前で始まるすべての間隔の中から繰り返し検索し、最も右に伸びているものを選択し、到達するまで検索を続けます。$y$または失敗します。 各貪欲な選択では、すべての間隔をスキャンする必要があります。$O(n)$ステップごとに、潜在的に$O(n)$につながるステップ$O(n^2)$最悪の場合、クエリごとに。 と$m$クエリの実行が非常に遅くなります。 

重要な観察は、貪欲なプロセス自体がインターバル カバレッジに対して正しいということです。つまり、現在の位置において、最良の選択は常に、その位置の前またはその位置で開始され、最も右に広がるインターバルです。 この問題は、左のエンドポイントでソートされた間隔で高速に繰り返される「最適な拡張」クエリをサポートすることに帰着します。 

これにより、効率的に前方にジャンプできる構造に間隔を前処理することができます。 開始点で間隔を並べ替えてバイナリ リフティング テーブルを構築すると、次のようになります。$next[i]$インターバルから開始する貪欲な 1 つのステップで達成可能な最も遠い距離です$i$そうすると、対数ジャンプで貪欲なチェーンをシミュレートできます。 

各間隔はノードとして扱うことができます: from 間隔$i$を選択すると、カバレッジを継続して最も遠くまで延長する間隔にジャンプできます。 この次のポインターを計算したら、それをバイナリ リフトして、少なくともクエリ エンドポイントをカバーする間隔に到達するために必要なステップ数を答えることができます。 

クエリに答えるために、まず、その時点またはその前にカバレッジを開始できるすべての間隔を見つけます。$x$、最も右のエンドポイントを持つものを選択し、バイナリ リフティングを使用して、少なくとも到達するために必要なジャンプの数を数えます。$y$。

 ## アルゴリズムのチュートリアル

 「あるポジションからの最適な延長」を効率的に回答できるように、まず間隔を正規化します。 

1. すべての間隔を左のエンドポイントで並べ替えます。 これにより、カバレッジを昇順に処理し、一貫して到達可能性を構築できるようになります。 
2. 間隔ごとに、最適な即時延長を計算します。 インターバル用$i = [l_i, r_i]$、またはそれより前に始まる間隔が必要です$r_i$そして最大の右端点を持ちます。 これにより、指向性のあるエッジが得られます。$i$最も積極的にカバレッジを拡大する後続間隔に変更します。 
3. 各間隔が 1 つの貪欲な拡張ステップを表す「次の」ポインターを持つ構造を構築します。 
4. バイナリリフティングテーブルを事前計算する$up[k][i]$、 どこ$up[0][i]$の次の間隔です$i$、より高いレベルは繰り返しジャンプを表します。 これにより、多くの欲深いステップを一度にスキップできます。 
5. 各クエリについて$[x, y]$を使用して、すべての間隔の中で最も遠くまで届く間隔を見つけます。$l \le x$。 この最適リーチがまだ未満である場合は、$x$の場合、カバレッジを開始することさえできないため、答えは -1 です。 
6. この間隔から開始して、バイナリ リフティングを繰り返し使用して、オーバーシュートせずにできるだけ右にジャンプします。$y$、使用された間隔の数を数えます。 
7. いずれかの時点で進行が不可能な場合 (次の間隔でカバレッジが拡張されない場合)、-1 を返します。 

### なぜ効果があるのか

 貪欲なルールは局所的に最適です。現在の境界でカバレッジを継続できるすべての間隔の中で、最大の正しいエンドポイントを持つ間隔を選択しても、将来の可能性を減らすことはできません。これは、代替間隔が早く終了するため、強制的に同じステップ以上のステップしか強制できないためです。 これにより、間隔のエンドポイントにわたって単調な構造が作成されます。 バイナリ リフティング テーブルは、この単調遷移の繰り返し適用を圧縮し、繰り返しのスキャンを減らしながら正確さを維持します。 すべてのクエリは、単純な貪欲プロセスとまったく同じ決定をシミュレートしますが、より高速なだけです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

LOG = 20

def build_next(intervals):
    n = len(intervals)
    nxt = [-1] * n

    # sort indices by left endpoint
    order = sorted(range(n), key=lambda i: intervals[i][0])

    # for each i, find best j with l_j <= r_i maximizing r_j
    j = 0
    best_idx = -1
    best_r = -1

    for i in order:
        l, r = intervals[i]

        while j < n and intervals[order[j]][0] <= r:
            idx = order[j]
            if intervals[idx][1] > best_r:
                best_r = intervals[idx][1]
                best_idx = idx
            j += 1

        nxt[i] = best_idx

    return nxt

def build_lift(nxt):
    n = len(nxt)
    up = [[-1] * n for _ in range(LOG)]
    up[0] = nxt[:]

    for k in range(1, LOG):
        for i in range(n):
            if up[k-1][i] != -1:
                up[k][i] = up[k-1][up[k-1][i]]
    return up

def solve():
    n, m = map(int, input().split())
    intervals = [tuple(map(int, input().split())) for _ in range(n)]

    nxt = build_next(intervals)
    up = build_lift(nxt)

    # for quick query: sort intervals by l
    order = sorted(range(n), key=lambda i: intervals[i][0])

    L = [intervals[i][0] for i in order]

    import bisect

    def best_start(x):
        # all intervals with l <= x
        idx = bisect.bisect_right(L, x) - 1
        if idx < 0:
            return -1

        # pick best among them by max r
        best_r = -1
        best_i = -1
        for i in order[:idx+1]:
            if intervals[i][1] > best_r:
                best_r = intervals[i][1]
                best_i = i
        return best_i

    for _ in range(m):
        x, y = map(int, input().split())

        cur = best_start(x)
        if cur == -1:
            print(-1)
            continue

        if intervals[cur][1] >= y:
            print(1)
            continue

        cnt = 1
        cur_r = intervals[cur][1]

        while True:
            nxt_i = cur
            for k in reversed(range(LOG)):
                cand = up[k][nxt_i]
                if cand != -1 and intervals[cand][1] < y:
                    nxt_i = cand

            if nxt[nxt_i] == -1:
                break

            nxt_i = nxt[nxt_i]
            cnt += 1

            if intervals[nxt_i][1] >= y:
                print(cnt)
                break
        else:
            print(-1)

solve()
```このソリューションは、間隔を貪欲なジャンプ グラフに変換することを中心に構成されています。 の`build_next`関数は、並べ替えられた開始点と終了点の 2 ポインター スイープを使用して、各間隔の即時に最適な拡張を構築します。 これにより、どの間隔からでも、一定時間内に最適な次の間隔を知ることができます。 

次に、これらの遷移上にバイナリ リフティングが構築されるため、繰り返しの拡張を対数ジャンプに圧縮できます。 それぞれ`up[k][i]`貪欲なステップの適用を表します$2^k$回。 

各クエリについて、関数はまず、左側のエンドポイントをカバーする有効な開始間隔を特定します。 任意の間隔を任意に選択すると、最適なカバレッジを逃す可能性があるため、この手順は非常に重要です。 ここでのスキャンはこの実装のボトルネックであり、セグメント ツリーを使用してさらに最適化できますが、概念的な構造は正しいままです。 

メイン ループは、正しいエンドポイントに到達するか、それ以上先に進めなくなるまで、事前に計算された遷移を使用して繰り返し前方にジャンプします。 カウンタは、貪欲チェーンで使用される間隔の数を追跡します。

 ## 特殊なケース

 主なエッジケースは、間隔がエンドポイントでちょうど接触する場合です。 例えば：```
[1,3], [3,5], query [1,5]
```実数にわたるカバレッジにより、境界に触れてギャップなくセグメントを接続できるため、アルゴリズムはこれを有効なものとして扱います。 

もう 1 つのケースは、クエリの前に複数の間隔が開始されるが、最大リーチを与えるのは 1 つだけである場合です。 最初に誤って短い間隔を選択すると、ステップ数が増えたり、早期に失敗したりする可能性があります。 貪欲な前処理により、そのような選択を常に 1 つの最適な代表に集約できるため、クエリは常に可能な限り最も強い間隔から開始されます。 

3 番目のエッジ ケースは、間隔間のギャップ内で開始されるクエリです。 例えば：```
intervals: [1,2], [4,6]
query: [3,5]
```best_start ステップでは間隔が見つかりません。$l \le 3$これは 3 まで拡張できるため、アルゴリズムはすぐに -1 を返し、カバレッジがクエリの左側の境界で開始できないことを正しく識別します。
