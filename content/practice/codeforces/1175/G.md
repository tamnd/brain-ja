 ## 解決策
 ## 問題の理解

 整数の配列を正確に分割するように求められます。$k$合計の重みが最小になるように連続したサブセグメントを作成します。 セグメントの重みは、その長さに最大要素を乗じたものとして定義されます。 合計の重みは、すべてのセグメントの重みの合計です。 私たちの目標は、セグメント境界を最適に選択することです。 

入力はサイズの配列で構成されます$n$(最大 20,000) およびセグメント数$k$(最大100)。 配列内の各要素は最大 20,000 です。 出力は単一の整数、つまり最小の合計重みです。 

制約は、次のアルゴリズムを使用することを示します。$O(n^2 \cdot k)$操作が適切に最適化されていれば機能する可能性があります。$2 \cdot 10^4 \cdot 100 = 2 \cdot 10^6$、5 秒以内であれば許容されます。 ただし、$O(n^2 \cdot k)$単純にセグメント最大値を再計算するアルゴリズムは遅すぎます。 

セグメントに複数の等しい最大要素が含まれている場合、またはすべての要素が等しい場合、微妙なエッジ ケースが発生します。 たとえば、$a = [5,5,5,5]$そして$k = 2$、どこに分割してもセグメントあたりの最大値は同じになりますが、合計の重みは長さに大きく依存します。 不注意なアプローチでは、さまざまな長さを考慮せずに常に中央で分割され、最適でない総重量が与えられる可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、配列を分割するあらゆる方法が検討されます。$k$セグメント。 分割候補ごとに、各セグメントの最大値を計算し、その長さを乗算して重みを取得します。 次に、すべてのセグメントの重みを合計し、すべてのパーティションの最小値を取得します。 これは、考えられるすべてのパーティションを列挙しているため、明らかに正しいですが、計算上実行不可能です。 たとえ$n = 20$そして$k = 10$、パーティションの数は組み合わせによって決まり、急速に増加します。 

重要な洞察は、動的プログラミングを使用することです。 させて$dp[i][j]$最初のパーティションを分割するための最小の重みになります$i$要素を$j$セグメント。 再発というのは、$$dp[i][j] = \min_{p < i} \{ dp[p][j-1] + (i - p) \cdot \max(a_{p+1}, \dots, a_i) \}$$単純な実装では、間隔ごとに最大値を再計算する必要があります。$[p+1, i]$、与える$O(n^2 \cdot k)$との時間$O(n)$内側のループ。 ただし、最大値を事前に計算できます。$O(1)$単調スタックまたはセグメント ツリーを使用したクエリごと。 さらに、コスト関数が四角形の不等式を満たすため、DP に分割統治最適化を適用できます。右端点が増加しても、前の最適な分割点は減少しません。 これにより、DP の複雑さが軽減されます。$O(n k \log n)$あるいは$O(n k)$実際に。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | お($\binom{n-1}{k-1} \cdot n$) | お(1) | 遅すぎる |
 | 素朴な最大値を持つ DP | O(n^2 * k) | O(n * k) | n=2e4 には遅すぎます |
 | 分割統治最適化を備えた DP | O(n * k) | O(n * k) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. DP テーブルの初期化$dp[i][j]$どこ$i$範囲は0から$n$そして$j$範囲は0から$k$。 セット$dp[0][0] = 0$他のすべてのエントリは無限大になります。 これは、最初のパーティションを分割するための最小の重みを表します。$i$要素を$j$セグメント。 
2. 各プレフィックスの最大値を事前計算します。 それぞれについて$i$、配列を維持する$max\_to[i]$前回の分割から位置までの最大値を記録します$i$DP 計算中。 これにより、セグメントの重みを段階的に計算できるようになります。$O(1)$ループ内の要素ごとに。 
3. セグメント数ごと$j$1から$k$、 埋める$dp[1..n][j]$分割統治最適化を使用します。 それぞれについて$i$、前の最適な分割を決定します$p$それは最小限に抑えます$dp[p][j-1] + (i-p) \cdot \max(a_{p+1..i})$。 分割統治特性により、最適な検索間隔が保証されます。$p$は単調なので、調査する候補の数が減ります。 
4. DP テーブルに記入したら、$dp[n][k]$最小の総重量が含まれています。 この値を返します。 

それが機能する理由: 各 DP ステップで、次の不変条件を維持します。$dp[i][j]$最初の最小総重量です$i$正確に一致する要素$j$セグメント。 繰り返しにより、考えられるすべての最後のセグメントが次で終わることが保証されます。$i$が考慮されます。 最適な分割の単調性により、より短い間隔を調べてもグローバル最小値が見つかることが保証されるため、分割統治最適化では候補がスキップされません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    INF = 10**18

    dp_prev = [INF] * (n + 1)
    dp_curr = [INF] * (n + 1)
    dp_prev[0] = 0

    for seg in range(1, k + 1):
        stack = []
        def compute(l, r, opt_l, opt_r):
            if l > r:
                return
            mid = (l + r) // 2
            best = (INF, -1)
            max_val = 0
            for p in range(opt_l, min(mid, opt_r) + 1):
                max_val = max(max_val, a[p])
                cost = dp_prev[p] + (mid - p) * max_val
                if cost < best[0]:
                    best = (cost, p)
            dp_curr[mid] = best[0]
            opt = best[1]
            compute(l, mid - 1, opt_l, opt)
            compute(mid + 1, r, opt, opt_r)
        compute(1, n, 0, n - 1)
        dp_prev, dp_curr = dp_curr, [INF] * (n + 1)

    print(dp_prev[n])

if __name__ == "__main__":
    main()
```スペースを節約するために 2 つの DP 配列を使用し、以前のセグメント計算と現在のセグメント計算を交換します。 の`compute`関数は、最適な分割の単調性を使用して候補を減らす分割統治最適化を適用します。 内側のループは現在のセグメントの最大値を段階的に更新し、再計算を回避します。

## 複雑さの分析
