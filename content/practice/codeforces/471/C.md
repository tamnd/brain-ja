 ## 問題の理解

 砂上の楼閣は床から作られます。 フロアに次のものがある場合`k`部屋の場合、各部屋は 2 枚の傾斜カードを使用するため、部屋自体が消費します`2k`カード。 隣接する部屋の間と、最も外側の部屋の上には、水平のカードで作られた天井があります。 の列`k`部屋のニーズ`k - 1`隣接する部屋間で天井カードを共有し、各部屋の位置の上にもう 1 枚の天井カードを追加すると、合計が得られます。`k - 1 + 1 = k`横向きのカード。 

したがって、床には`k`部屋は以下を使用します:$$2k + (k-1)=3k-1$$カード。 

家の中を上に進むにつれて、部屋の数は厳密に減らさなければなりません。 床に次のものがある場合$$a_1 > a_2 > \dots > a_h \ge 1$$部屋の場合、カードの総数は次のようになります。$$\sum_{i=1}^{h}(3a_i-1) = 3\sum a_i - h.$$私たちは正確に与えられています`n`カードを使用し、異なる高さの数を数えなければなりません`h`可能です。 高さは、合計カード消費量が正確に一致する厳密に減少する正の順序の部屋数が存在する場合に有効です。`n`。 

制約が興味深い部分です。`n`と同じ大きさにすることができます`10^12`。 パーティションを列挙したり、フロア サイズの組み合わせを調査したりするアプローチは絶望的です。 平`O(n)`は大きすぎます。 対数または平方根の複雑さに近いものが必要です。 

有効な家がまったくない場合、微妙なケースが発生します。 例えば：```
6
```最小の平屋住宅が使用するのは、`2`最小の 2 階建ての家が使用するカード`7`カードを正確に消費する有効な構成がない`6`。 答えは`0`。 

もう 1 つの簡単な間違いは、厳密な減少条件を忘れることです。 考慮する：```
13
```部屋数の使用`(2,2)`消費するだろう`10`カードはありますが、厳密には階数が減っていないため違法です。 厳密に減少するシーケンスのみが許可されます。 

バグの 3 番目の原因は、異なる部屋の分布を個別にカウントすることです。 この問題では、家の数ではなく、可能な高さの数が求められます。 複数の異なるフロア構成が同じ高さである場合、それらは 1 回だけ寄与します。 

## アプローチ

 直接的なブルートフォース解釈は、厳密に減少する正の整数のシーケンスをすべて生成し、それらのカード使用量を計算し、それが等しいかどうかをチェックすることです。`n`。 これは正しいです。なぜなら、すべての法律上のハウスは、そのようなシーケンスの 1 つに正確に対応するからです。 残念ながら、減少するシーケンスの数は爆発的に増加します。 中程度の値であっても、`n`、検索スペースは整数パーティションの数に似ており、これは、次の場合に探索できる範囲をはるかに超えています。`n`到達する`10^12`。 

重要な観察は、カードの公式を書き換えることから得られます。$$n = 3\sum a_i - h.$$並べ替えると$$\sum a_i = \frac{n+h}{3}.$$固定高さの場合`h`、問題は次のようになります。 

書いてもいいですか$$S=\frac{n+h}{3}$$合計として`h`明確な正の整数?

 これは古典的な数論の問題です。 

可能な最小の合計`h`異なる正の整数は次から取得されます。$$1+2+\cdots+h = \frac{h(h+1)}2.$$このようなセットが得られたら、最大の要素を負以外の量だけ増加させると、区別性が維持されます。 したがって、少なくともすべての整数の合計は、$$\frac{h(h+1)}2$$達成可能です。 

それで高さ`h`は、次の 2 つの条件が当てはまる場合にのみ有効です。$$n+h \equiv 0 \pmod 3$$そして$$\frac{n+h}{3}\ge \frac{h(h+1)}2.$$2 番目の不等式は次のようになります。$$h^2+h \le \frac{2(n+h)}3.$$簡略化後:$$3h^2+h-2n \le 0.$$これにより、すぐにおよその上限が得られます。$$h \le \sqrt{\frac{2n}{3}},$$たとえ100万未満であっても`n = 10^{12}`。 その境界までの可能なすべての高さを単純にテストできます。

 ## アルゴリズムのチュートリアル

 1. 可能なすべての高さに対して反復します。`h`から始まる`1`。 
2.次の場合に停止します`3h² + h > 2n`。 高さを超えると、カードの最小必要数がすでに超えています`n`したがって、それ以上の高さは有効ではありません。 
3. かどうかを確認します。`n + h`で割り切れます`3`。 そうでない場合は、`S = (n+h)/3`は整数ではなく、高さの家もありません`h`存在します。 
4. 割り切れる場合は、最小和条件を検証します。$$\frac{n+h}{3} \ge \frac{h(h+1)}2.$$これは上記の導出と同等です。 
5. 条件が満たされる場合、答えをインクリメントします。 
6. 実現可能な高さをすべてテストした後、カウントを出力します。 

### なぜ効果があるのか

 あらゆる身長に対応`h`、すべての法的ハウスは厳密に減少するシーケンスに対応します。`h`プラスの部屋数。 合計カードの式は、問題を次のような問いに変換します。`(n+h)/3`の合計として表すことができます`h`異なる正の整数。 

合計`h`明確な正の整数は、少なくとも次の場合に正確に存在します。`1+2+\cdots+h`。 より大きな値はすべて、区別性を維持しながら最大の要素を増やすことによって取得できます。 したがって、割り算条件と最小和条件は両方とも必要十分条件です。 アルゴリズムは、実行可能なすべての高さについてこれらの条件を正確にチェックするため、有効な高さはすべて 1 回カウントされ、無効な高さはすべて拒否されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    ans = 0
    h = 1

    while 3 * h * h + h <= 2 * n:
        if (n + h) % 3 == 0:
            s = (n + h) // 3
            if s >= h * (h + 1) // 2:
                ans += 1
        h += 1

    print(ans)

solve()
```変数`h`は現在テストされている高さを表します。 

ループ条件は不等式から直接得られます。$$3h^2+h-2n \le 0.$$失敗すると、その高さの可能な最小限の家であっても、利用可能な以上のカードが必要になるため、それ以上の高さも機能できなくなります。 

割り算チェックは計算前に実行されます。`s`。 これがなければ、整数の除算は不可能なケースを黙って受け入れることになります。 

との比較`h(h+1)/2`表現の存在を次の合計としてエンコードします。`h`異なる正の整数。 Python の整数には任意の精度があるため、次のような場合でもオーバーフローのリスクはありません。`n = 10^{12}`。
