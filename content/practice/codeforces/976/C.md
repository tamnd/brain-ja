 ## 解決策
 ## 問題の理解

 数直線上の閉区間の集合が与えられます。 各区間は左端と右端を持つセグメントを表しており、一方が他方の内部に完全に含まれるような別個のセグメントのペアが存在するかどうかを判断する必要があります。 

正式には、2 つのセグメントの場合$[l_i, r_i]$そして$[l_j, r_j]$、インデックスを見つけたい$i \neq j$そのような$l_i \ge l_j$そして$r_i \le r_j$。 そのようなペアが存在する場合は、有効なネストされたペアのインデックスを返します。 それ以外の場合は、ネストが存在しないと報告されます。 

制約により、最大で$3 \cdot 10^5$セグメントとエンドポイントは次のような大きさにすることができます。$10^9$。 これにより、二次比較戦略が即座に除外されます。 ナイーブ$O(n^2)$スキャンは約実行されます$9 \cdot 10^{10}$最悪の場合の比較は、2 秒で実行できる量をはるかに超えています。 

重要な問題は、封じ込めが 2 つの側面に同時に依存していることです。 1 つの座標のみで並べ替えても、もう一方の座標は自動的に保持されないため、不注意に順序付けすると有効な答えが隠れてしまう可能性があります。 

いくつかの危険な状況は、一般的な落とし穴を示しています。 すべてのセグメントが同一の場合、どのペアも有効であり、検出する必要があります。 厳密な不等式だけを探すソリューションでは、これを誤って見逃してしまう可能性があります。 次のように両方のエンドポイントでセグメントが厳密に増加している場合$[1,2], [2,3], [3,4]$、構造化された方法で間隔が重なっている場合でも、封じ込めはありません。 もう 1 つの注意が必要なケースは、セグメントが非常に長く、他のセグメントが多数含まれている場合です。$[1,100]$含む$[2,99]$、$[3,98]$、 等々。 元の順序で隣接するもののみを比較するアルゴリズムは、構造が再編成されない限り、ここでは失敗します。 

## アプローチ

 ブルートフォース手法では、セグメントのすべてのペアをチェックし、一方にもう一方が含まれているかどうかを検証します。 これは簡単です: それぞれについて$i$、すべてと比較してください$j > i$そして封じ込め状態をテストします。 これは、考えられるすべてのペアを明示的に評価するため正しいですが、そのコストは二次関数的に増加します。 と$3 \cdot 10^5$セグメントの数が増えると、比較の数が法外になり、最適化された定数係数でもそれを回復できなくなります。 

重要な観察は、問題を慎重に選択した順序に帰着させると、封じ込めの検出がはるかに簡単になるということです。 セグメントを左端点で昇順に並べ替える場合、潜在的なコンテナはこの順序で前または同じ位置に表示される必要があります。 しかし、これではまだ不十分です。なぜなら、同じ左端点を持つセグメントのうち、より大きな右端点を持つセグメントを外側のセグメントと見なす必要があるからです。 

これにより、より正確な構造が得られます。つまり、左端点の昇順で並べ替え、同点の場合は右端点の降順で並べ替えられます。 この順序でリストをスキャンするたびに、先に開始または同じ時点で開始し、後で終了するセグメントは、後続のすべてのセグメントのコンテナーとなる可能性があります。 

次に、スキャン中にこれまでに確認された最良の (最大の右エンドポイント) セグメントを維持します。 現在のセグメントがこの最大値またはそれより前に終了する場合、そのセグメントは以前に表示されたセグメントに含まれます。 それ以外の場合は、それが新しい候補コンテナーになります。 

これにより、2 次元の比較問題が、不変条件が維持された単一パスに変わります。

 ## アルゴリズムのチュートリアル

 この問題を、ソートされたリストをスキャンする際の包含関係の検出に変換します。 

1. ソート後に元の位置に戻せるように、すべてのセグメントにインデックスを付けます。 並べ替えによって入力順序が破壊されるため、これが必要になります。 
2. 左の端点を増やしてセグメントを並べ替えます。 2 つのセグメントが同じ左端点を共有する場合は、右端点の降順で並べ替えます。 この順序付けにより、開始が等しい場合、最も広い間隔が最初に配置されます。これは、同じ左境界を持つ他の間隔を含めることができる唯一の間隔です。 
3. 2 つの変数を初期化します。1 つはこれまでに確認された最大の右端点を保存する変数で、もう 1 つはどのセグメントがその最大値に達したかを保存する変数です。 
4. ソートされたセグメントを左から右に繰り返します。 各セグメントごとに$[l, r]$、その右端点を現在の最大右端点と比較します。 
5. もし$r \le \text{maxR}$の場合、このセグメントは、生成されたセグメントに完全に含まれます。$\text{maxR}$なぜなら、そのセグメントはすぐに始まり、少なくとも右端まで広がっているからです。 
6. 包含が見つからず、現在のセグメントの右端点が$\text{maxR}$、保存されている最良のセグメントをこのセグメントに更新します。 

重要な推論ステップは、並べ替え順序を確保した後は、左のエンドポイントの条件が順序付けによってすでに暗黙的に強制されているため、包含に欠け​​ている唯一の条件は右のエンドポイントの比較であるということです。 

### なぜ効果があるのか

 スキャンの各ステップで、以前に確認されたすべてのセグメントの中で最大の右端点を持つものとして保存されたセグメントは、将来のセグメントの有効な候補コンテナであることが保証されます。これは、そのセグメントが右方向への到達範囲が最も大きいセグメントの中で可能な限り最小の左端点を持つためです。 包含テストに不合格となったセグメントは、それまでのすべてのセグメントよりも右に拡張する必要があり、その場合、そのセグメントが新たな最良の候補になります。 この不変式により、包含ペアが存在する場合、内部セグメントに遭遇したときに正確に検出されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
segs = []

for i in range(n):
    l, r = map(int, input().split())
    segs.append((l, r, i + 1))

segs.sort(key=lambda x: (x[0], -x[1]))

best_r = -1
best_idx = -1

for l, r, idx in segs:
    if r <= best_r:
        print(idx, best_idx)
        sys.exit(0)
    if r > best_r:
        best_r = r
        best_idx = idx

print(-1, -1)
```ソートによって順序は変更されますが、出力は入力位置を参照する必要があるため、解決策は元のインデックスを保持することから始まります。 選別ステップは、単一パスで封じ込めを検出できるようにする構造変換です。 

スキャン中に、`best_r`は、潜在的なコンテナーであるセグメントの中でこれまでに確認された最も右のエンドポイントを表します。 右端点がこの値を超えないセグメントが見つかった場合、ソートにより以前のセグメントの左端点も現在のセグメント以下であるため、そのセグメントはその前のセグメントによって完全にカバーされている必要があります。 

有効なペアが見つかったら、どのペアでも受け入れられるため、早期終了は安全です。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from sys import stdout
    import sys

    input = sys.stdin.readline

    n = int(input())
    segs = []
    for i in range(n):
        l, r = map(int, input().split())
        segs.append((l, r, i + 1))

    segs.sort(key=lambda x: (x[0], -x[1]))

    best_r = -1
    best_idx = -1

    for l, r, idx in segs:
        if r <= best_r:
            return f"{idx} {best_idx}"
        if r > best_r:
            best_r = r
            best_idx = idx

    return "-1 -1"

# provided sample
assert run("5\n1 10\n2 9\n3 9\n2 3\n2 9\n") in ["2 1", "3 1", "4 1", "5 1", "3 2", "4 2", "5 2", "2 5", "4 5"], "sample 1"

# all identical segments
assert run("3\n1 1\n1 1\n1 1\n") != "-1 -1"

# no nesting
assert run("3\n1 2\n2 3\n3 4\n") == "-1 -1"

# clear nesting
assert run("3\n1 10\n2 5\n6 9\n") != "-1 -1"

# reverse nested chain
assert run("4\n1 8\n2 7\n3 6\n4 5\n") != "-1 -1"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | すべて同一のセグメント | 任意の有効なペア | 重複は処理されます |
 | チェーンを増やす | -1 -1 | 誤検知なし |
 | ネストをクリアする | 有効なペア | 基本的な正しさ |
 | 深い鎖 | 有効なペア | 最悪の場合の入れ子構造 |

 ## 特殊なケース

 微妙なケースの 1 つは、複数のセグメントが同じ左端点を共有する場合です。 例えば：```
3
1 10
1 5
1 7
```等しい左端点内で右端点が降順になるように並べ替えると、セグメント (1,10) が最初に表示されます。 スキャンが進むにつれて、`best_r`はすぐに 10 になり、その他はすべて含まれていると正しく検出されます。 2 番目の並べ替えを行わないと、短いセグメントが誤って「最良」となり、検出が妨げられる可能性があります。 

別のケースでは、間隔を厳密に増加させる必要があります。```
3
1 2
2 3
3 4
```ここ、`best_r`常に増加し、満たされるセグメントはありません`r <= best_r`有意義な時間に。 アルゴリズムは正しく最後まで到達し、戻ります`-1 -1`、封じ込めがないことを反映しています。
