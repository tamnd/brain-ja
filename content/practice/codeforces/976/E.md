 ## 解決策
 ## 問題の理解

 各クリーチャーは固定の体力値と固定のダメージ値で始まります。 私たちは 2 つの世界規模の作戦を使用して軍隊を強化することができます。 1 つの操作はクリーチャーの体力を 2 倍にして増加させ、もう 1 つの操作はクリーチャーのダメージを現在の体力で上書きします。 小さな体力値をダメージにコピーすることはほとんど役に立たないため、2 番目の操作は最初の操作が十分な回数適用された後にのみ価値があります。 

目標は最大でも配布することです`a`倍増、最大でも`b`最終的なダメージ値の合計が最大になるように、すべてのクリーチャーにわたって操作を任意の順序でコピーします。場合によってはクリーチャーごとに複数の操作を実行します。 

制約`n ≤ 2 · 10^5`クリーチャーの数の二次関数を除外します。 小さな限界`a ≤ 20`これが重要な構造上のヒントです。2 倍になる回数はごくわずかなので、各クリーチャーの健康状態は最大でも約 2^20 の異なる有効な状態しか取りえません。 これは、各クリーチャーが何倍になるかを列挙し、コピー操作をグローバルに適用する方法を決定できることを示唆しています。 

単純な戦略では、すべての操作シーケンスをシミュレートしようとします。 分散操作だけを考えても、それぞれ`a`ダブリングは任意のクリーチャーに割り当てることができ、それをインターリーブすることができます。`b`これは組み合わせ的に爆発的に増加し、実行可能な限界をはるかに超えています。 

2 番目の単純なアイデアは、クリーチャーごとに、それを何倍にするか、その体力をダメージにコピーするかどうかを個別に決定することです。 これは、コピー操作がグローバルであるため失敗します。1 つのクリーチャーでコピーを使用すると、他の場所で使用できなくなるため、選択肢が結合されます。 

あるクリーチャーの初期ダメージが高く、別のクリーチャーのダメージは低いが倍増後の体力が非常に高い場合、微妙な失敗のケースが発生します。 「常に最大の現在の体力をコピーする」などの貪欲なローカル決定は、別のクリーチャーの後で倍増することで、同じコピー予算ではるかに優れたターゲットが生成される可能性があることを無視しているため、失敗します。 

## アプローチ

 最大の難点は、各クリーチャーには倍増回数に応じて複数の可能な状態があり、コピー操作を適用することにした場合、そのような各状態には「値」があることです。 以来`a ≤ 20`、各クリーチャーには最大 21 の意味のあるバージョンがあります。つまり、2 倍になります。`k`時代は健康を与えます`hp · 2^k`, そしてコピーすると、その貢献度は元のダメージではなくその値になります。 

固定生物の場合は、次のいずれかを選択することが考えられます。`k + 1`オプション: コピーを使用せずに初期の損傷を維持するか、コピーを後で適用するかのどちらかです。`k`倍増、貢献`hp · 2^k`。 を選ぶのにかかる費用は、`k`-番目のオプションは`k`倍増予算の単位。 

これにより、各クリーチャーが小さなナップサックのようなアイテムのセットに変わります。各アイテムにはコストがかかります。`k`値ゲインは次と等しい`max(0, hp·2^k − dmg)`なぜなら、私たちはベースラインのダメージを改善することだけを気にしているからです。 

ただし、コピー操作もグローバルに制限されます。`b`、そしてコピーされたクリーチャーが1ユニットの`b`。 したがって、選択したアップグレードされた状態ごとに、以下を超えないことも確認する必要があります。`b`そういった選択。 

重要なアイデアは、問題を 2 つの層に分離することです。 まず、各クリーチャーが受け取る倍増の数を決定します。 第二に、結果として得られる状態の中から、最大でも次の状態を選択します。`b`すべてのクリーチャーの合計が最大で 2 倍になることを尊重しながら、クリーチャーはコピー操作を適用できます。`a`。 

それぞれの生き物について可能な限りの計算が可能です`(cost_k, gain_k)`ペア。 次に、すべての候補をグローバル リストにマージします。 制約`a ≤ 20`これにより、割り当ての 2 倍を制限された予算として扱うことができ、合計 2 倍に対して動的プログラミング アプローチを使用し、予算ごとに形成可能な最適な候補のセットを維持します。 

倍増予算ごとに達成可能な最適なアップグレード状態のマルチセットがわかったら、上位を選択します。`b`そのプールから利益が得られます。 

より直接的で標準的な最適化は、視点を反転することです。つまり、各クリーチャーとそれぞれについてです。`k`にアップグレードすることによる増分メリットを計算します。`k`2 倍にして、各オプションを重み付きの単一項目として扱います。`k`そして利益`gain_k`。 ナップザックを走らせます`a`ただし、任意のサブセットを選択する代わりに、状態を選択すると、すでに 1 つのコピー操作の使用がコミットされていることがわかります。そのため、選択するのは最大でも 1 つであることを確認する必要があります。`b`世界中のアイテム。 これは、倍増割り当てを修正した後、候補ゲインをソートすることで処理されます。 

最終的な構造は次のようになります。`(hp_i · 2^k − dmg_i)`みんなのために`i, k`、コスト別にグループ化します`k`、予算を 2 倍にして DP を実行し、達成可能な最良の利益セットを計算し、貪欲にトップを獲得します`b`。

 ## アルゴリズムのチュートリアル

 1. 各クリーチャーについて、次のすべての可能な健康値を計算します。`k`倍増`k`0から`a`。 これにより、クリーチャーごとに最大 21 の状態が生成されます。 
2. 状態ごとに、その状態でのコピーの選択によるゲインを計算します。次のように定義されます。`(hp_i * 2^k - dmg_i)`。 コピーしても役に立たないため、この値が正でない状態は無視してください。 
3. 有効な各状態をコスト付きの候補項目として保存します`k`そして価値観`gain_k`。 
4. 0 から 2 倍の総予算にわたってナップザック スタイルの動的プログラミングを実行します。`a`、 どこ`dp[j]`達成可能なすべてのゲインを正確に使用して保存します`j`倍加は選択された候補者全体に分配されます。 
5. DPを満たした後、予算内で到達可能なすべての州からすべての利益を収集します`a`。 
6. これらのゲインを降順に並べ替えます。 
7. 頂上に立つ`b`利益を獲得し、元のすべての損害のベースライン合計に加算します。 

重要な決定点は、DP 中にコピー操作を直接割り当てないことです。 代わりに、倍加制約の下でどのアップグレードされた状態に到達できるかがわかるまで、その決定を遅らせます。 この分離により、2 つのリソース制約間の干渉が防止されます。 

### なぜ効果があるのか

 すべての操作後の各クリーチャーの貢献は、元のダメージ、または一定回数の倍増とそれに続く最大 1 回のコピー操作の後に得られる単一のアップグレード値のいずれかです。 同じクリーチャーの複数のコピーは決して役に立たず、最良の状態を超えて追加のコピーが価値を増加させることはないため、最適な解決策はすべてこの形式に変換できます。 これにより、各クリーチャーの決定空間が小さな有限セットに縮小され、全体的な問題は最大でも選択することになります。`b`総コスト制約の下で構造化されたプールから項目を抽出する`a`、これはまさにDPが捉えているものです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, a, b = map(int, input().split())
    creatures = [tuple(map(int, input().split())) for _ in range(n)]

    base = 0
    gains_by_cost = [[] for _ in range(a + 1)]

    for hp, dmg in creatures:
        base += dmg
        cur = hp
        for k in range(a + 1):
            gain = cur - dmg
            if gain > 0:
                gains_by_cost[k].append(gain)
            cur *= 2

    # dp[j] = list of gains achievable with total doubling cost j
    dp = [set() for _ in range(a + 1)]
    dp[0].add(0)

    for cost in range(a + 1):
        for gain in gains_by_cost[cost]:
            for j in range(a, cost - 1, -1):
                for prev in list(dp[j - cost]):
                    dp[j].add(prev + gain)

    all_gains = set()
    for j in range(a + 1):
        all_gains |= dp[j]

    all_gains = sorted(all_gains, reverse=True)
    ans = base + sum(all_gains[:b])

    print(ans)

if __name__ == "__main__":
    solve()
```コードは、コピー操作をまったく使用しない場合、すべてのクリーチャーが少なくともその程度のダメージを与えるため、ベースラインの答えをすべての初期ダメージの合計として保存することから始まります。 

それぞれの生き物について、最大で次のことをシミュレートします。`a`倍増、現在の健全性を明示的に維持します。 各状態は、ベースラインのダメージを上回る潜在的な改善をもたらし、それは倍増コストによってグループ化されて記録されます。 

動的プログラミングの構造`dp[j]`正確に使用して、達成可能なすべての合計ゲイン合計を追跡します。`j`選択したアップグレード状態全体に分散される合計 2 倍。 各移行には候補者が含まれるか、候補者がスキップされるため、限られた倍増予算が確実に尊重されます。 

最後に、到達可能なゲインの合計がすべて収集され、並べ替えられ、最適なゲインが得られます。`b`が追加されます。 これは、アップグレードされた状態のセットが修正された後のコピー操作の独立した性質を反映しています。

 ## 特殊なケース

 重大なエッジ ケースは、倍増によって生成される値がいくつかのステップを経て初めて価値があるが、コピー バジェットが小さすぎてそのような改善をすべて使用できない場合に発生します。 アルゴリズムはこれを処理します。`(k, gain)`独立して考慮され、世界的に最高のもののみが考慮されます`b`ゲインは 2 倍化制約を尊重した後に選択されます。 

もう一つのケースは次のような場合です。`a = 0`。 そうすれば、すべてのクリーチャーは元のダメージを与えるか、ゼロダブリングで最大でも 1 枚のコピーのみを貢献できるため、問題はトップを選ぶことだけになります。`b`改善`max(0, hp - dmg)`。 DP は自然に 1 つのバケットに折りたたまれます`k = 0`したがって、直接的な利益のみが考慮されます。 

最後のコーナーケースは、すべてのゲインが負の場合です。 アルゴリズムはこれらを早期に除外するため、コピー操作は使用されず、答えは正確にベースラインの損害額の合計のままになります。
