 ## 解決策
 ## 問題の理解

 すでに有効な正規形式になっているバイナリ文字列が与えられています。これは、不必要な先行ゼロのないバイナリ形式の非負の整数を表していることを意味します。 タスクは、隣接する文字を自由に交換する操作と、「11」を単一の「1」に置き換えることによって連続する文字の出現を減らすという 2 つの許可された操作を使用して、この文字列をバイナリ比較ルールに基づいて可能な最小値に変換することです。 

最初の操作では、隣接する入れ替えを繰り返すことで任意の並べ替えを実現できるため、文字を完全に自由に再配置できます。 2 番目の操作では、1 のペアを圧縮して文字列の構造を変更し、文字列内の 1 の数を効果的に減らします。 

出力は、単なる並べ替えられた文字列ではなく、これらの変換で取得できる辞書編集上最小のバイナリ文字列であり、先頭のゼロのない有効な表現のままです。 

n ≤ 100 という制約は、二次推論や小規模なシミュレーションでも実行可能であることを意味しますが、演算の構造は、やみくもにシミュレーションすべきではないことを示唆しています。 代わりに、不変量、特に効果的に削減および再配置できるゼロと 1 の数を特定する必要があります。 

単純なアプローチでは、すべての順列と縮小を試行しますが、n = 100 の場合でも、これは天文学的に大きくなります。 構造的不変条件を持たない操作を繰り返し適用する貪欲なシミュレーションでも、失敗する可能性があります。 

文字列に 1 のみが含まれる場合、微妙なエッジケースが発生します。 たとえば、入力「111」は繰り返し「1」に折りたたまれる可能性があり、リダクションを単一パスとして扱うアプローチは誤って「11」で停止します。 もう 1 つのケースは、「10101」のように、ゼロが 1 と 1 を区切る場合で、再配置が非ローカルな方法で圧縮と相互作用します。 単純な貪欲なスワップ戦略では、最初に 1 つをまとめることによって圧縮が最大化されることに気づかない可能性があります。 

## アプローチ

 ブルートフォースの考え方は、2 つの操作をあらゆる方法で繰り返し適用し、到達可能なすべての文字列を追跡し、最小値を選択することです。 これが機能するのは、状態空間が有限であり、すべての遷移が有効であるためです。 ただし、スワップごとに分岐係数が大幅に拡張され、n が小さい場合でも、スワップと圧縮のインターリーブを通じて到達可能な個別のバイナリ文字列の数は指数関数的に増加します。 ボトルネックは、スワップではすべての順列が生成されるのに対し、圧縮では文字列の長さが動的に変更されるため、状態を超えた BFS または DFS が実行不可能になることです。 

重要な観察は、スワップにより任意の並べ替えが可能になるため、最終結果は元の位置ではなく、0 と 1 のカウントのみに依存するということです。 圧縮ルール「11 → 1」は、複数の 1 が 1 つの 1 に集約されることを意味するため、正の数の 1 は最終的には 1 つのように動作します。 したがって、意味のある唯一の区別は、「1」が少なくとも 1 つあるのか、まったく存在しないのか、そして最後の 1 つの 1 に対してゼロがどのように配置されているかということです。 

「1」がない場合、答えは単純に「0」になります。 少なくとも 1 つの「1」がある場合、すべての 1 を 1 つの「1」にマージでき、その後はゼロを最適に配置するだけで済みます。 先行ゼロは許可されないため、最小の配置は、単一の「1」を可能な限り左に配置し、その後にゼロを残し、「1」の後にすべてゼロが続く形式の文字列を生成することです。 

したがって、問題は「1」が存在するかどうかを数えることと、ゼロを数えることに帰着します。

 ## アルゴリズムのチュートリアル

1. 文字列をスキャンして、ゼロの数と「1」が少なくとも 1 つ存在するかどうかを数えます。 これにより、任意のスワップ後に関連するすべての情報が取得されます。 
2. 「1」が存在しない場合は、「0」を返します。すべてゼロの文字列はゼロを表し、これ以上減らすことができないためです。 
3. 少なくとも 1 つの「1」が存在する場合は、「11 → 1」演算を繰り返し適用して、すべての 1 を 1 つの「1」にまとめます。 
4. 単一の「1」の後にすべてのゼロを配置して出力を構築します。 これにより、先行ゼロが表示されず、バイナリ比較で値が最小化されることが保証されます。 

重要な推論ステップは、一度交換が自由に許可されると位置構造は無意味になり、圧縮が存在すると複数の構造が単一の代表に崩壊するということです。 唯一の還元不可能な情報は、数値がゼロか正か、およびゼロがいくつ残っているかということです。 

### なぜ効果があるのか

 不変条件は、複数の文字セットがすべてゼロになるか、正確に 1 つの「1」とゼロになるかのどちらかになるということです。 スワッピングによりカウントが保持され、圧縮ルールにより、値を増やすことなく 1 の数が厳密に削減されます。 したがって、到達可能なすべての状態は、最大 1 つの「1」を持つ構成と同等であり、それらの構成の中で、すべてのゼロの前に 1 つの「1」を置くと、最小のバイナリ値が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

s = input().strip()

if '1' not in s:
    print("0")
else:
    zeros = s.count('0')
    print("1" + "0" * zeros)
```実装では、アルゴリズムで説明されているリダクションを直接エンコードします。 「1」が存在しないことをチェックすると、縮退ゼロのケースが処理されます。 すべての 1 が 1 つの代表にまとめられるため、0 を数えるだけで十分です。 最終的な構成では、最上位の位置に「1」のみを配置することで、可能な限り最小のバイナリ値が保証されます。 

よくある落とし穴は、スワップ後に相対的な順序を維持しようとしますが、スワップによって位置制約が無効になってしまうことです。 もう 1 つの微妙な問題は、複数のものは最終的な縮小形では複数のままではないということを忘れていることです。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    s = sys.stdin.readline().strip()
    if '1' not in s:
        return "0"
    return "1" + "0" * s.count('0')

# provided sample
assert run("4\n1001\n") == "100"

# all zeros (edge)
assert run("3\n000\n") == "0"

# single one
assert run("1\n1\n") == "1"

# all ones
assert run("5\n11111\n") == "1"

# mixed
assert run("5\n10101\n") == "1000"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 000 | 0 | オールゼロ崩壊 |
 | 1 | 1 | 単一要素の場合 |
 | 11111 | 1 | 完全圧縮 |
 | 10101 | 1000 | 混合構造の正規化 |

 ## 特殊なケース

 重要なエッジケースは、文字列にゼロのみが含まれる場合です。 この状況では、スワップや圧縮を行っても何も変更できず、正しい出力は「0」のままです。 アルゴリズムは、「1」が存在しないことをチェックすることでこれを明示的に処理します。 

もう 1 つのエッジ ケースは、完全に 1 で構成される文字列です。 圧縮ルールを繰り返し適用すると、連続した長さが単一の「1」に短縮され、交換は無関係になります。 この実装では当然「1」が生成されます。 

「10101」などの混合配置は、位置の最適化が必要であることを示唆している可能性がありますが、スワップでは任意の順列が許可されるため、最終状態は元の順序を無視します。 アルゴリズムはそれを単一の値とそれに続くゼロに正確に還元し、構造が配置ではなくカウントによって完全に決定されることを確認します。
