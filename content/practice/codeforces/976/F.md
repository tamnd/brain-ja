 ## 解決策

 ## 問題の理解

 ここでは、エッジが左側の頂点を右側の頂点に接続する 2 部グラフを使用しており、同じペア間の複数のエッジが許可されています。 このグラフから、エッジのサブセットを選択することができます。 

固定整数 k の場合、元のグラフのすべての頂点がその選択されたサブセットからの少なくとも k 個のエッジに属する場合、選択されたエッジのセットを有効と呼びます。 言い換えれば、選択したエッジのみを保持した後でも、すべての頂点は少なくとも k 以上の次数を持たなければなりません。 その k のすべての有効なサブセットの中で、エッジの数が最も少ないサブセットが必要です。 

元のグラフの 0 から最小次数までのすべての k に対して、このような最適なサブセットを出力する必要があります。 k が大きいと実現可能性が制限され、k が小さいと答えがより疎な構造になる傾向があるため、パラメーターの範囲が重要になります。 

二部グラフの両方の部分に最大 2000 個の頂点があり、エッジの数も最大 2000 個であるという意味で、制約は厳しいです。これは、どのソリューションも、再利用せずに k ごとに 3 次または反復 2 次作業を回避する必要があることを直ちに示唆しています。 ただし、同じグラフがすべての k で再利用されます。これは、各再計算自体が m でほぼ線形でない限り、単純な方法ですべてを独立して最初から再計算すべきではないことを強く示唆しています。 

頂点の次数がターゲット k と正確に等しい場合、微妙なエッジ ケースが発生します。 どのような最適解でも、そのような頂点はその入射エッジを失うことができないため、非常に厳格なグローバル構造が強制されます。 もう 1 つのエッジ ケースは k = 0 です。この場合、正解はグラフに関係なく空集合になります。 グラフが非常に不均等である場合、さらに明白ではない状況が発生します。一方の側の次数が他方の側よりもはるかに大きい場合があり、特定の頂点に k を超える余分なエッジが必要になる可能性があります。これらのエッジは反対側の制約を満たすために必要であるためです。 

## アプローチ

 この問題を直接考える方法は、「各頂点には少なくとも k 個の選択されたエッジがなければならない」という制約に焦点を当てることです。 貪欲に答えを構築しようとすると、現在の次数が最小の頂点を助けるエッジを繰り返し選択することになる可能性があります。 すべてのエッジが 2 つの頂点に同時に影響し、ローカルな決定が後で実現可能性を妨げる可能性があるため、これはすぐに問題に陥ります。 二分割の両側間の相互作用により、単純な貪欲な構築は信頼できなくなります。 

より構造化された視点は、問題を裏返すことです。 維持するエッジについて考える代わりに、元のグラフから削除するエッジについて考えます。 元のグラフで頂点の次数 deg(v) があり、いくつかのエッジを削除した場合、最終グラフでは少なくとも k 個の入射エッジを維持する必要があります。 これは、各頂点から最大 deg(v) − k 個のエッジを削除できることを意味します。 

したがって、削除されたエッジが各頂点に触れることができる数の頂点ごとの上限を尊重しながら、できるだけ多くのエッジを削除したいと考えています。 これは、元のグラフ上の最大 b マッチング問題になります。ここで、各頂点 v の容量は cap(v) = deg(v) − k であり、選択された各エッジは両方の端点に 1 を与えます。 取り外し可能なエッジを最大化すると、残りのエッジが最適な K-cover を形成します。 

二部 b マッチングは標準的なフロー問題であるため、この変換は役立ちます。 ただし、k ごとに完全なフローを再計算するには依然としてコストがかかります。 重要な観察は、容量が非常に規則的に変化するということです。k が 1 増加すると、すべての頂点の容量がちょうど 1 ずつ減少します。この均一なシフトにより、解を増分的に再計算できますが、この問題では制約が十分小さいため、k ごとのクリーンなフロー解がすでに十分です。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 貪欲なエッジ構造 | O(m²) 最悪 | O(m) | 不正解 |
 | 各 k | のフローによる最大 b マッチング O(minK・フロー) | O(m + n) | 承認済み |

 ## アルゴリズムのチュートリアル

 値 k を固定し、補数問題に関するフロー定式化を使用して最適な k-cover を構築します。 

1. 元のグラフのすべての頂点の次数 deg(v) を計算します。 これにより、k 個の入射エッジを維持しながら、各頂点が潜在的に「損失に耐えられる」エッジの数が決定されます。 
2. 問題を除去問題に変換します。 各頂点 v に対して、容量 cap(v) = deg(v) − k を定義します。 これは、v で削除できる入射エッジの最大数です。 
3. 二部 b マッチングのためのフロー ネットワークを構築します。 左のすべての頂点に接続されたソースを作成し、左と右の頂点の間のすべてのエッジの容量は 1 で、右のすべての頂点はシンクに接続します。 各頂点 v は、その入射エッジの最大 cap(v) が除去対象として選択されるように制約されます。 
4. 最大フローを実行して、これらの制約の下で可能な最大の取り外し可能なエッジ セット R_k を計算します。 フローの各単位は、1 つの元のエッジを削除することに対応します。 
5. R_k で使用されていないすべてのエッジを取得して、応答セット E_k を構築します。 これらは、k-covering ソリューションで保持するエッジです。 
6. 0 から最小度までの k ごとにこのプロセスを繰り返し、結果として得られる保持エッジ セットを出力します。 

なぜそれが機能するのかというと、単純な優位性の議論に帰着します。 有効な k-cover はすべての頂点に付随する少なくとも k エッジを保持する必要があります。これは、各頂点で最大 deg(v) − k エッジを削除することと同等です。 フローは、これらの頂点ごとの制約に基づいて削除の最大数を計算するため、保持されるエッジの数は可能な限り最小限になります。 エッジが削除されるたびに、保持されるセットの合計サイズが減少するため、削除を最大化することは、最終的な k-cover サイズを最小化することと同じです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import deque

class Dinic:
    def __init__(self, n):
        self.n = n
        self.adj = [[] for _ in range(n)]

    def add_edge(self, a, b, c):
        self.adj[a].append([b, c, len(self.adj[b])])
        self.adj[b].append([a, 0, len(self.adj[a]) - 1])

    def bfs(self, s, t):
        self.level = [-1] * self.n
        q = deque([s])
        self.level[s] = 0
        while q:
            v = q.popleft()
            for to, cap, rev in self.adj[v]:
                if cap > 0 and self.level[to] == -1:
                    self.level[to] = self.level[v] + 1
                    q.append(to)
        return self.level[t] != -1

    def dfs(self, v, t, f):
        if v == t:
            return f
        for i in range(self.it[v], len(self.adj[v])):
            self.it[v] = i
            to, cap, rev = self.adj[v][i]
            if cap > 0 and self.level[to] == self.level[v] + 1:
                pushed = self.dfs(to, t, min(f, cap))
                if pushed:
                    self.adj[v][i][1] -= pushed
                    self.adj[to][rev][1] += pushed
                    return pushed
        return 0

    def max_flow(self, s, t):
        flow = 0
        INF = 10**18
        while self.bfs(s, t):
            self.it = [0] * self.n
            while True:
                pushed = self.dfs(s, t, INF)
                if not pushed:
                    break
                flow += pushed
        return flow

def solve_k(n1, n2, edges, k):
    n = n1 + n2 + 2
    s = n1 + n2
    t = n1 + n2 + 1

    deg = [0] * (n1 + n2)
    for i, (u, v) in enumerate(edges):
        u -= 1
        v = n1 + v - 1
        deg[u] += 1
        deg[v] += 1

    cap = [max(0, deg[i] - k) for i in range(n1 + n2)]

    dinic = Dinic(n)

    for i in range(n1):
        dinic.add_edge(s, i, cap[i])

    for i in range(n2):
        dinic.add_edge(n1 + i, t, cap[n1 + i])

    for i, (u, v) in enumerate(edges):
        u -= 1
        v = n1 + v - 1
        dinic.add_edge(u, v, 1)

    flow = dinic.max_flow(s, t)

    # recover which edges are used: if edge is NOT saturated in removal flow, it is kept
    used = set()
    idx = 0
    for u, v in edges:
        uu = u - 1
        vv = n1 + v - 1
        # check if edge was used in flow by looking for reverse saturation trick
        for to, cap, rev in dinic.adj[uu]:
            if to == vv and cap == 0:
                used.add(idx)
                break
        idx += 1

    # kept edges are those not removed
    kept = [i + 1 for i in range(len(edges)) if i not in used]
    return kept

def main():
    n1, n2, m = map(int, input().split())
    edges = [tuple(map(int, input().split())) for _ in range(m)]

    deg_min = 10**9
    deg = [0] * (n1 + n2)
    for u, v in edges:
        u -= 1
        v = n1 + v - 1
        deg[u] += 1
        deg[v] += 1
    deg_min = min(deg)

    for k in range(deg_min + 1):
        ans = solve_k(n1, n2, edges, k)
        print(len(ans), *ans)

if __name__ == "__main__":
    main()
```実装では、k ごとにフロー ネットワークを構築します。 左側の頂点は、削除できる入射エッジの数に等しい容量でソースから接続されます。 シンクの右側の頂点についても同じことが行われます。 元の各エッジは中央の単位容量エッジになり、潜在的な削除を表します。 

最大流量を計算した後、飽和した中間エッジを削除されたエッジとして解釈します。 他のすべては保持され、K カバーが形成されます。 

微妙な点は、再構築ステップがフロー内でどの中間エッジが完全に使用されたかを検出することに依存していることです。 各エッジの容量は 1 であるため、順方向の残り容量がゼロのエッジは選択された削除に対応します。 

## 実用的な例

 ### 例 1

 k を徐々に増加させると、より多くのエッジが残る小さな二部グラフを考えてみましょう。 

| k | キャップ(U/V)アイデア | 削除されたエッジ | エッジを維持 |
 | --- | --- | --- | --- |
 | 0 | 完全な度 | すべてのエッジ | 空 |
 | 1 | 各頂点は最大で 1 つを失います | 一部のエッジが削除されました | 構造化されたカバー |
 | 2 | 制限を厳しくする | 許可される削除が少なくなります | 高密度コア |

 このトレースは、k が増加するにつれてフローがより制約され、破棄できるエッジが少なくなることを示しています。 保持されたセットは単調増加します。 

### 例 2

 左側の 1 つの頂点が右側の多くの頂点に接続している、星型の構造を考えてみましょう。 

k = 0 の場合、すべてを削除できます。 k = 1 の場合、右側のすべてのリーフは少なくとも 1 つの入射エッジを保持する必要があり、これにより中央の頂点は複数のエッジを保持する必要があります。 これは、コンストレイントが頂点ごとに独立して動作するのではなく、共有エンドポイントを通じて伝播することを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(minD・F) | 最大フローは k ごとに実行されます。ここで、F は m ≤ 2000 エッジ上の Dinic のコストです。 
| スペース | O(n + m) | フロー グラフは、頂点ごとに 1 つのノードとエッジ リストを格納します。 

このグラフは、n と m の両方が最大 2000 であり、k レベルの合計数が最小次数によって制限されているため、繰り返しのフロー計算が制限内に収まるほど十分に小さいです。

 ## 特殊なケース

 k が 0 の場合、まれなケースが発生します。 この状況では、エッジを選択しなくてもすべての頂点がすでに要件を満たしているため、正しい出力は空のセットになります。 すべての容量が元の度数と等しくなり、完全な削除が可能になり、保持されたセットにエッジが残らないため、流れの定式化にもこれが反映されます。 

もう 1 つのケースは、頂点の次数が正確に k である場合です。 その状況では、その除去能力はゼロになり、フローはそれに付随するエッジの除去を回避することになります。 その頂点を介してフローを送信しようとすると容量制約に違反するため、アルゴリズムは当然これを尊重します。 

最後に、非常に不均衡な二部構造では、局所的には不必要に見える場合でも、一方の側がもう一方の側にエッジを保持するよう強制する場合があります。 これは、すべてのエッジが両方のエンドポイントで同時に制約され、フローによって頂点ごとの貪欲な選択ではなくグローバルな一貫性が強制されるため、正しく処理されます。
