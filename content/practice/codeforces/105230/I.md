 ## 解決策
 ## 問題の理解

 私たちには一連の材料が与えられており、いくつかの材料の組み合わせは同じ味であることが知られています。 この関係は単なるペア関係ではなく、推移的に拡張されるため、材料 A が B と一致し、B が C と一致する場合、A、B、および C はすべて同じフレーバー グループに属します。 

ピザを作るプロセスは、すべての材料をランダムに並べて左から右にスキャンすることとして説明されています。 材料を見つけると、それを追加しようとします。 同等性情報に基づいて、すでに選択されている材料の中でこれまでに登場したことのないフレーバーを導入する場合にのみ追加されます。 それ以外の場合は無視されます。 

最終的な出力は 1 回の実行に関するものではありません。 このプロセスにより、考えられるすべての成分の組み合わせにおいて、どれだけの異なる成分セットが生成できるかが問われます。 注文だけでなく、選択した食材の実際のセットが異なる場合、2 つのピザは異なります。 

n が 100000 まで、m が 100000 までという制約は、本質的に線形または線形に近い処理が必要であることを意味します。 n階乗が大きすぎるため、順列を列挙したり順序付けをシミュレートしようとするアプローチは不可能であり、エッジ上の二次関数でさえタイムアウトの危険があるためです。 

微妙な問題は、同値関係が推移的であるにもかかわらずエッジとしてのみ与えられることです。 直接ペアのみを考慮する単純なアプローチでは、フレーバー グループを誤って分類する可能性があります。 

もう 1 つの注意が必要な点は、ランダム性の解釈です。 問題は、順列に対する確率や期待値を求めることではありません。 任意の順列に対して現れる可能性のある個別の結果セットの数を求めています。 

## アプローチ

 強引な解釈では、n 個の成分のすべての順列を生成し、スキャン プロセスをシミュレートし、結果として得られる選択セットを保存します。 シミュレーション自体は n で線形であるため、これには O(n · n!) 時間かかりますが、これは非常に小さい n の場合でも直ちに実行不可能です。 ボトルネックはシミュレーションではなく、可能な注文の急増です。 

重要な観察は、等フレーバー関係のグラフで重要なのは、その連結成分だけであるということです。 接続されたコンポーネント内で、そのコンポーネントのいずれかの成分が選択されると、そのコンポーネント内の他のすべての成分はすでに表示されているフレーバーを持つとみなされ、後で検出されたときに拒否されます。 

ここで、固定順列の最終セットを決定するものを考えてみましょう。 各連結コンポーネントでは、そのコンポーネント間の順列で最初に現れるのは 1 つの成分だけです。 そのコンポーネントが選択され、同じコンポーネント内の他のコンポーネントはすべてスキップされます。 これは、すべての順列により、各連結成分の代表を 1 つだけ含むセットが生成されることを意味します。 

重要な点は、異なる順列により同じコンポーネントから異なる代表が選択される可能性があり、これらの選択はコンポーネント間で独立しているということです。 サイズ s のコンポーネントでは、その s ノードのいずれかが、そのコンポーネントに対する順列で最初に現れるノードになる可能性があるため、選択された代表になります。 コンポーネントは互いに干渉しないため、可能なピザの総数はコンポーネントのサイズの積になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (すべての順列) | O(n・n!) | O(n) | 遅すぎる |
 | 接続されたコンポーネント + カウント | O(n + m) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、指定されたペアを無向グラフのエッジとして解釈します。 パスで接続されている 2 つの成分は同じフレーバー グループに属しているため、連結成分を計算する必要があります。 これは、素の集合共用体構造または DFS を使用して実行できます。

ノードをコンポーネントにグループ化した後、各コンポーネントのサイズを計算します。 順序付けプロセスでは、コンポーネントが選択した代表を解決する方法が混合されることはないため、各コンポーネントは最終的なカウントに独立して寄与します。 

最後に、サイズ s の各コンポーネントについて、答えに s を掛けます。これは、ランダムな並べ替えでそのコンポーネントの最初に出現するノードとなるノードの選択肢がちょうど s つあるためです。 

積を法 10^9 + 7 とします。 

これが機能する理由は、どのような順列においても、接続コンポーネントごとに 1 つの要素が選択されるという不変条件、具体的にはそのコンポーネントの順序付けの最初の要素が選択されることに基づいています。 順列から結果のピザへのマッピングは、各コンポーネントのこの最初の要素の選択によって完全に決定されます。 このような選択はすべて、選択した要素がそのコンポーネントの他のすべての要素の前に出現する順列を構築することによって実現でき、コンポーネントは互いに制約しないため、これらの選択肢は独立して増加します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return
        if self.size[ra] < self.size[rb]:
            ra, rb = rb, ra
        self.parent[rb] = ra
        self.size[ra] += self.size[rb]

def solve():
    n, m = map(int, input().split())
    dsu = DSU(n)

    for _ in range(m):
        a, b = map(int, input().split())
        dsu.union(a - 1, b - 1)

    comp_size = {}
    for i in range(n):
        r = dsu.find(i)
        comp_size[r] = comp_size.get(r, 0) + 1

    ans = 1
    for sz in comp_size.values():
        ans = (ans * sz) % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、素のセット共用体構造を使用して接続コンポーネントを構築します。 各結合は、フレーバーに相当する成分を単一の代表的なセットにマージします。 

すべてのエッジを処理した後、すべてのノードを 1 回反復して、各ルート コンポーネントのサイズをカウントします。 DSU は構造のみを維持し、明示的なコンポーネントのリストは維持しないため、この手順が必要です。 

最後のループでは、モジュロ演算ですべてのコンポーネントのサイズを乗算します。 結果は、各コンポーネントがその代表的な成分に寄与する方法の数に直接対応します。

 ## 特殊なケース

 エッジがない場合、すべての成分が独自のコンポーネントを形成します。 このアルゴリズムは各ノードを個別のルートとして扱い、積が繰り返し 1 になり、その結果 1 になります。これは、すべての順列がシングルトン コンポーネント全体で同じ決定論的な選択パターンを生成するという事実と一致します。 

すべての要素がチェーンを介して接続されている場合、DSU はすべてを 1 つのコンポーネントに圧縮します。 n 個のノードのいずれかがそのコンポーネント内で最初に検出される可能性があり、それによって結果として得られるピザ セットが完全に決定されるため、最終的な答えは n になります。 

1 つの大きなコンポーネントと多数の孤立したノードなど、コンポーネントのバランスが非常に悪い場合でも、孤立したノードが係数 1 に寄与し、変動性を決定するのに大きなコンポーネント サイズのみが残るため、乗算は引き続き正しく機能します。
