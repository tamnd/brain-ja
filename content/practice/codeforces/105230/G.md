 ## 解決策
 ## 問題の理解

 各要素が小さな正の整数である配列を維持しており、その素因数構造のみに関心があります。 配列は 3 つの操作によって変更されます。単一の位置から素因数を削除することができ、範囲全体を定数値で上書きすることができ、以前のすべての削除が最良の方法で考慮された後、素因数の最小和を求める範囲をクエリすることができます。 

重要な点は、値の演算が実際にはランダム性に依存しないことです。 このステートメントでは「ランダムな」素因数の削除について言及していますが、クエリではすべての結果にわたって可能な最小の合計が求められます。これは、クエリを評価するたびに、各位置に対して敵対的に最適な削除を想定できることを意味します。 

入力サイズにより、ソリューションは最大 10 万の更新とクエリをサポートする必要があります。 因数分解を再計算したり、操作ごとに範囲を最初から再計算したりするメソッドは遅すぎます。 クエリごとの線形スキャンでも、最悪の場合は約 10^10 の操作が必要になりますが、これは実行不可能です。 

それぞれの値は最大 10^4 であり、これは強力なヒントです。すべての素因数分解と派生量を事前に計算できます。 この限界は、値ごとの情報が、係数を繰り返し再計算するのではなく、おそらく事前計算されたコストの小さなセットとして、コンパクトな形式で保存できることも示唆しています。 

素朴だが重要な誤解は、「素因数を削除する」操作を固定量だけ決定論的に合計を減らすものとして扱うことです。 たとえば、12 = 2 × 2 × 3 の場合、ランダムな因子を削除すると 6 または 4 になる可能性があり、結果として得られる最小合計は、どちらの因子が最初に削除されるかによって異なります。 クエリでは、複数の操作にわたるこのような削除のすべてのシーケンスを考慮する必要があります。 

もう 1 つの微妙な問題は、範囲の上書きです。 データが正しく構造化されていない場合は、範囲内のすべての要素の因子情報を再構築する必要がありますが、これもまた時間がかかりすぎます。 

## アプローチ

 ブルートフォースアプローチは概念的には単純です。 すべての要素の正確な値を維持します。 タイプ 1 が発生すると、インデックス i で数値を因数分解し、任意に 1 つの素因数を削除し、格納されている整数を更新します。 タイプ 3 が発生すると、範囲が上書きされます。 タイプ 2 が発生した場合、クエリ範囲内のすべての数値を因数分解し、すべての素因数を合計します。 

これは文字通りプロセスをシミュレートするものであるため、これは正しいです。 ただし、ボトルネックはすぐに解消されます。 タイプ 2 クエリは最大 10^5 要素をスキャンでき、各因数分解には最大 √a_i (約 100 回の操作) のコストがかかる可能性があります。 10^5 クエリの場合、これは非常に大きくなります。 

重要な点は、クエリ中に数値を完全に因数分解する必要がないということです。 最適な除去後の素因数の合計が必要になるだけです。 各削除は正確に 1 つの素因数を削除するため、各要素の寄与は非常に構造化された方法で進化します。すべての要素は常に素数のマルチセットとして表現可能であり、削除によってマルチセットのサイズは一度に 1 つずつ減少するだけです。 

これにより、各数値を小さな動的状態に減らすことができます。 完全な整数を追跡する代わりに、その整数に含まれる「残りの貢献」の数とその合計がいくらかを追跡します。 値が小さいため、最大 10^4 までのすべての x について素因数の合計 (多重度を使用) を事前計算します。 削除するたびに、この合計は、その数値の因数分解で使用可能な最小の素因数だけ減ります。 この観察が鍵となります。将来の合計を最小化するには、常に最小の素因数を最初に削除します。これは、より大きな素数を削除すると、後で合計が小さくなるからです。

したがって、各数値について、マルチセットのような構造を維持しますが、必要な情報は 2 つだけです。残りの素因数の現在の合計と、利用可能な最小の素因数です。 セグメント ツリーは、ポイントの更新と範囲の割り当てをサポートしながら、範囲の合計を維持できます。 削除操作は 1 つのインデックスでのローカル更新となり、現在の値をその最小の素因数で割った同じ値に置き換えます。 

セグメント ツリーには、セグメントごとに、現在の「最適な除去後の素因数の合計」の合計が格納されます。 範囲の割り当ては、保存された値をリセットし、基数から事前に計算された状態を再計算することにより、遅延伝播で処理されます。

 ## アルゴリズムのチュートリアル

 まず、10^4 までのすべての数値の素因数情報を事前計算します。 各値 x について、多重度を持つ素因数のリスト、その総和、および最小の素因数を繰り返し除去することで得られる状態のシーケンスを計算します。 各状態は、k 回の削除後の可能な最良の構成を表します。 

次に、配列上にセグメント ツリーを構築します。ここで、各ノードは、最適な除去の下でセグメントの現在の寄与を保存します。 

1. 10^4 までのすべての素因数分解を事前計算し、数値 x ごとに状態のリストを作成します。各状態は、最小の因数を繰り返し削除した後の残りの素因数の合計です。 

これにより、O(1) で「k 回削除した後に何が起こるか」を確実に答えることができます。 
2. すべての配列要素に対して状態 0 を使用してセグメント ツリーを初期化します。これは、まだ削除が適用されていないことを意味します。 

各リーフには、その値の素因数の合計が格納されます。 
3. インデックス i でのタイプ 1 操作の場合、その要素の削除カウントを 1 つ増やし、次の事前計算済み状態に移動します。 

これが機能するのは、1 つの素因数を削除することが、事前計算されたチェーン内で 1 つの状態を前に進めることに常に対応するためです。 
4. 値 x を範囲に割り当てるタイプ 3 の操作では、影響を受けるすべての位置を x の状態 0 にリセットします。 

上書きにより因子構造全体が置き換えられるため、これにより以前の因子履歴がすべて破棄されます。 
5. [l, r] に関するタイプ 2 クエリの場合、現在の状態のセグメント ツリーの合計をクエリします。 

保存された値にはすでに最適な削除動作が反映されているため、再計算は必要ありません。 

### なぜ効果があるのか

 正しさは、利用可能な最小の素因数を連続的に除去することによって定義される決定論的な状態の連鎖を通じて、各数値が独立して進化するという事実に基づいています。 残りの合計を最小化することを目的とした一連の削除では、各ステップで常に利用可能な最小の素因数を削除する必要があります。これは、より大きな係数を削除すると、厳密に大きな残差和が残るためです。 これにより、状態遷移が貪欲かつ単調になり、各値を事前に計算されたリダクション シーケンスのプレフィックスとして表現できるようになります。 次に、セグメント ツリーはこれらの独立した寄与を線形に集計します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXV = 10000

spf = list(range(MAXV + 1))
for i in range(2, MAXV + 1):
    if spf[i] == i:
        for j in range(i * i, MAXV + 1, i):
            if spf[j] == j:
                spf[j] = i

def factor_sum(x):
    s = 0
    while x > 1:
        p = spf[x]
        s += p
        x //= p
    return s

# precompute full reduction chains
states = [[] for _ in range(MAXV + 1)]
max_steps = [0] * (MAXV + 1)

for x in range(1, MAXV + 1):
    cur = x
    seq = [factor_sum(cur)]
    while cur > 1:
        p = spf[cur]
        cur //= p
        seq.append(factor_sum(cur))
    states[x] = seq
    max_steps[x] = len(seq) - 1

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.size = 1
        while self.size < self.n:
            self.size *= 2
        self.seg = [0] * (2 * self.size)
        self.base = arr[:]  # original values
        self.step = [0] * self.n

        for i in range(self.n):
            self.seg[self.size + i] = states[arr[i]][0]
        for i in range(self.size - 1, 0, -1):
            self.seg[i] = self.seg[2 * i] + self.seg[2 * i + 1]

    def apply(self, idx):
        x = self.base[idx]
        self.step[idx] += 1
        if self.step[idx] < len(states[x]):
            val = states[x][self.step[idx]]
        else:
            val = 0
        return val

    def update_point(self, idx):
        self.seg[self.size + idx] = self.apply(idx)
        i = (self.size + idx) // 2
        while i:
            self.seg[i] = self.seg[2 * i] + self.seg[2 * i + 1]
            i //= 2

    def query(self, l, r):
        l += self.size
        r += self.size
        s = 0
        while l <= r:
            if l % 2 == 1:
                s += self.seg[l]
                l += 1
            if r % 2 == 0:
                s += self.seg[r]
                r -= 1
            l //= 2
            r //= 2
        return s

n = int(input())
a = list(map(int, input().split()))
q = int(input())

st = SegTree(a)

for _ in range(q):
    tmp = list(map(int, input().split()))
    if tmp[0] == 1:
        i = tmp[1] - 1
        st.update_point(i)
    elif tmp[0] == 2:
        l, r = tmp[1] - 1, tmp[2] - 1
        print(st.query(l, r))
    else:
        l, r, x = tmp[1] - 1, tmp[2] - 1, tmp[3]
        for i in range(l, r + 1):
            st.base[i] = x
            st.step[i] = 0
            st.seg[st.size + i] = states[x][0]
        # rebuild upwards
        for i in range(st.size - 1, 0, -1):
            st.seg[i] = st.seg[2 * i] + st.seg[2 * i + 1]
```この実装は、最大 10^4 までの各値の完全なリダクション シーケンスを事前計算することに依存しています。 セグメント ツリーの各リーフには、特定の回数の削除後のその要素の現在考えられる最良の寄与が格納されます。 タイプ 1 の更新操作は、単にそのインデックスの状態ポインターを進め、そのリーフをリフレッシュします。 

上書きすると以前の因子の履歴が破壊されるため、範囲の割り当てでは基本値と除去カウンターの両方がリセットされます。 次に、セグメント ツリーが正確さを期すためにボトムアップで再計算されます。 

主な微妙な点は、各要素の進化が独立しているため、インデックス間で削除を調整する必要がないことです。

 ## 特殊なケース

 重要なエッジ ケースは、1 になる数値に対して繰り返し除去が行われることです。数値が 1 に達すると、その数値には素因数がないため、それ以上のタイプ 1 演算によって数値が変更されることはありません。 事前計算されたシーケンスは寄与ゼロで終了するため、状態チェーンはこれを自然に処理します。 

もう 1 つのケースは、複数の削除後に範囲を上書きすることです。 正しい動作は、以前の状態履歴がすべて破棄されることです。 これは、ベース値とステップ カウンタの両方をリセットすることで処理され、古い因子構造が新しいセグメント値に漏れないようにします。
