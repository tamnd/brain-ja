 ## 問題の理解

 私たちに与えられた教室は、$n$学生には、それぞれ独立して 365 日にわたって一律に誕生日が割り当てられます。 非常に特殊な構成の確率を尋ねられます。 

構成は厳密です。正確に次のグループが存在する必要があります。$x$生徒全員が同じ誕生日を共有し、その誕生日をクラスの他の人と共有することはありません。 残りの生徒も全員、お互いに異なる誕生日を持ち、また、全員が共有する誕生日とも異なる誕生日を持っている必要があります。$x$-グループ。 言い換えれば、特別なグループの外では、誕生日を共有する生徒は 2 人もおらず、選択した共有日と衝突する生徒もいません。 

出力はこの確率をモジュロで表現したものです$10^9+7$、と書かれています$p \cdot q^{-1} \bmod M$、 どこ$p/q$確率の縮小された部分です。 

制約$n \le 10^{18}$生徒や数日間にわたって反復されるアプローチは直ちに除外されます。 多項式依存性も$n$は不可能であるため、解は少量の導出量のみに依存する必要があります。 誕生日は 365 個の値の固定された世界から得られるため、組み合わせ構造は一定サイズの計算に崩壊する必要があります。 

微妙な失敗例が現れるのは、$n-x$大きいです。 364 人を超える残りの生徒がいる場合は、選択した共有日を除いて個別の誕生日を割り当てる必要がありますが、残っているのは 364 日だけです。 たとえば、次の場合$n=1000$そして$x=10$の場合、残りの 990 人の生徒全員が 364 個のスロットで異なる誕生日を持つことはできないため、確率はまったくゼロになります。 この制約を無視する単純な式では、誤ってゼロ以外のモジュラー値が生成されます。 

もう一つの失敗例は治療から生じます$C(n,x)$階乗を直接使用します。 以来$n$できる$10^{18}$、階乗ベースの二項計算は、有効な組み合わせサイズが小さいという事実を利用しない限り不可能です。 

## アプローチ

 強引な解釈では、誕生日のすべての割り当てが列挙されます。$n$条件を満たす人を数えて、次で割ります。$365^n$。 これは概念的には正しいですが、完全に実行不可能です。 状態空間は$365^n$、そして単純化せずにそのスケールで組み合わせ論的に推論することさえ不可能です。 

重要な観察は、有効な割り当ての構造が非常に厳格であるということです。 共通の特別な誕生日を選択したら、$x$人々、残りのすべては残りの 364 日間に強制的に割り当てられます。 これにより、問題はグループの選択、曜日の選択、および残りの課題を繰り返しなく並べ替えることになります。 

重要な単純化は、次のことだけです。$k = n - x$残りの学生にとって重要であり、実現可能性が必要です$k \le 364$。 これが成立すると、残りの構造はすべて、小さな順列と、下位のインデックスが小さい二項項にのみ依存します。 これにより書き換えが可能になります$C(n,x)$として$C(n,k)$の製品になります。$k$たとえいつでも条件$n$巨大です。 

最終的な式は、特別な日の選択、グループを形成する生徒の選択、残りの個別の誕生日の割り当てという 3 つの独立した要素の積になります。

 ## アルゴリズムのチュートリアル

 有効な割り当てを数え、合計割り当てで割るという観点から問題を書き直します。 

### ステップ

 1. コンピューティング$k = n - x$。 これは、特別な誕生日グループに属していない生徒の数を表します。 残りの計算は、これらが次の条件を満たすかどうかに完全に依存します。$k$学生には、共有された誕生日以外の個別の誕生日を割り当てることができます。 
2. もし$k > 364$、すぐに 0 を返します。これは、$x$学生の皆さん、残りの個別の日は 364 日だけなので、364 人を超える人に一意の誕生日を割り当てることはできません。 
3. すべての組み合わせ項がこの範囲に制限されるため、365 までの階乗および逆階乗を事前計算します。 
4. 共有される誕生日を選択します。 日付の選択方法は 365 通りあります。$x$人が一致する。 
5. どちらかを選択してください$x$学生がグループを形成します。 以来$k = n-x$、計算が簡単です$C(n,k)$の代わりに$C(n,x)$、大規模な問題への対処を回避します。$x$。 これは積として計算されます。$$C(n,k) = \frac{n(n-1)\cdots(n-k+1)}{k!}$$6. 残りのメンバーに誕生日を割り当てます。$k$学生たち。 それらはすべて異なるものでなければならず、選択された日を避ける必要があるため、これは順列になります。$$P(364, k) = \frac{364!}{(364-k)!}$$7. すべての寄与を乗算します。$$\text{ways} = 365 \cdot C(n,k) \cdot P(364,k)$$8. 合計結果で割る$365^n$べき乗モジュラーと逆モジュラーを使用します。 

### なぜ効果があるのか

 すべての有効な構成は、共有された誕生日、ユーザーの ID という 3 つの独立した選択によって一意に決定されます。$x$生徒たちはそれを共有し、残りの生徒には個別の誕生日を全単射的に割り当てます。 これらの選択は、配置と重複したり二重にカウントされたりすることはありません。 制約$k \le 364$順列割り当てが常に有効であることを保証します。 これにより、カウントされた構造と有効な確率結果との間に 1 対 1 の対応関係が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

MAXD = 365

fact = [1] * (MAXD + 1)
invfact = [1] * (MAXD + 1)

for i in range(1, MAXD + 1):
    fact[i] = fact[i - 1] * i % MOD

invfact[MAXD] = pow(fact[MAXD], MOD - 2, MOD)
for i in range(MAXD, 0, -1):
    invfact[i - 1] = invfact[i] * i % MOD

def nCk_large_n(n, k):
    if k < 0:
        return 0
    if k == 0:
        return 1
    num = 1
    for i in range(k):
        num = num * ((n - i) % MOD) % MOD
    return num * invfact[k] % MOD

def perm_364(k):
    if k > 364:
        return 0
    return fact[364] * invfact[364 - k] % MOD

def solve():
    t = int(input())
    for _ in range(t):
        n, x = map(int, input().split())
        k = n - x

        if k < 0 or k > 364:
            print(0)
            continue

        ways_group = nCk_large_n(n, k)
        ways_perm = perm_364(k)

        ways = 365 * ways_group % MOD
        ways = ways * ways_perm % MOD

        denom = pow(365, n, MOD)
        ans = ways * pow(denom, MOD - 2, MOD) % MOD

        print(ans)

if __name__ == "__main__":
    solve()

順列項は、その領域が 365 によって厳密に制限されているため、階乗を介して事前に計算されます。$365^n$べき乗剰余演算を使用して処理されます。これは、非常に大規模な場合でも実行可能です。$n$べき乗は対数時間で実行されるためです。 

## 実用的な例

 小さな例を考えてみましょう$n=10, x=3$。 それから$k=7$, そのため、残りの 7 人の生徒には、共通の誕生日を除いた個別の誕生日を割り当てます。 

| ステップ | 値 |
 | --- | --- |
 | k | 7 |
 | C(n,k) |$C(10,7)$|

 この構造では、まず 7 人の非グループの生徒を選択し、次にそれらに固有の誕生日を割り当て、最後に共有日の選択肢の数を掛けます。 これは、有効な割り当ての構造と正確に一致します。

## テストケース```python
import sys, io

MOD = 10**9 + 7

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    MAXD = 365
    fact = [1] * (MAXD + 1)
    invfact = [1] * (MAXD + 1)

    for i in range(1, MAXD + 1):
        fact[i] = fact[i - 1] * i % MOD

    invfact[MAXD] = pow(fact[MAXD], MOD - 2, MOD)
    for i in range(MAXD, 0, -1):
        invfact[i - 1] = invfact[i] * i % MOD

    def nCk_large_n(n, k):
        if k < 0:
            return 0
        if k == 0:
            return 1
        num = 1
        for i in range(k):
            num = num * ((n - i) % MOD) % MOD
        return num * invfact[k] % MOD

    def perm_364(k):
        if k > 364:
            return 0
        return fact[364] * invfact[364 - k] % MOD

    def solve():
        t = int(input())
        out = []
        for _ in range(t):
            n, x = map(int, input().split())
            k = n - x
            if k < 0 or k > 364:
                out.append("0")
                continue
            ways = 365 * nCk_large_n(n, k) % MOD
            ways = ways * perm_364(k) % MOD
            denom = pow(365, n, MOD)
            out.append(str(ways * pow(denom, MOD - 2, MOD) % MOD))
        return "\n".join(out)

    return solve()

 ## 特殊なケース

 直接的なコーナーケースは次のような場合です$n=x$。 そうすれば、生徒全員が同じ誕生日グループに属します。 この方式は、残りの割り当てを行わずに共有する日を選択することになります。 アルゴリズムは正しく生成します$365 \cdot 1 \cdot 1 / 365^n$これは、1 日だけが重要であり、他のすべての制約がなくなるという事実と一致します。 

もう 1 つの例外的なケースは次のような場合です。$n-x=364$。 ここでは、残りの生徒は全員、残りの日数をすべて 1 回だけ占有する必要があります。 順列項は次のようになります。$364!$、アルゴリズムは動的推論を行わずに、事前に計算された階乗から直接計算します。 これは実現可能な最も厳密な構成であり、境界をチェックする際に 1 つずれたミスがあると、誤って拒否されてしまいます。
