 ## 解決策
 ## 問題の理解

 整数のリストが与えられ、それぞれに対して変換を繰り返し適用します。つまり、数値を適切な約数の合計に置き換えます。これは、すべての約数が数値自体よりも厳密に小さいことを意味します。 この変換は複数回適用できますが、ここでのタスクは長いチェーンをシミュレートすることではありません。 代わりに、数値ごとに、このプロセスの最初のステップである適切な約数の合計を 1 回確認するだけで済みます。 

その単一の計算値に基づいて、各数値は 4 つのカテゴリのいずれかに分類されます。 適切な約数の合計がその数に等しい場合、その数は完全と呼ばれます。 その合計に同じ演算を適用すると元の数値が返される場合、2 つの数値は友好的なペアを形成し、ここではロマンチックと呼ばれます。 合計が数値より大きければ、それは豊富です。 それ以外の場合は、複雑なものとして分類されます。 

入力サイズは最大 100,000 個の数値に達し、それぞれの値は最大 100,000 個になります。 これにより、すべてのクエリの試行除算による約数の再計算が即座に除外されます。 各クエリの平方根までのすべての数値をチェックする単純なアプローチでは、およそ O(n√a) のコストがかかり、最悪の場合は約 10^10 の演算となり、1 秒の制限をはるかに超えます。 

主要な構造上の制約は、すべてのクエリが独立しているが、同じ除数和の計算を共有することです。 つまり、100,000 までのすべての値の適切な約数の合計を 1 回事前計算し、一定時間内に各クエリに答えることができます。 

エッジケースはほとんどが少数から発生します。 n = 1 の場合、適切な約数の合計は 0 なので、明示的にチェックしない限り、完全でも豊富でもロマンチックなペアの一部でもありません。 単純な実装では、1 を正しく処理することを忘れて、誤って完全なものとして分類されたり、未分類のままになったりする可能性があります。 

もう 1 つの微妙なケースは、ロマンチックな数字です。 sum(sum(a)) が a に等しいかどうかを確認するだけでは十分ではありません。 sum(a) が a 自体と等しくないことを確認する必要があります。そうしないと、誤解された場合に完全数が誤ってロマンチックであるとみなされる可能性があります。 

## アプローチ

 直接的なアプローチでは、各数値の適切な約数の合計を個別に計算します。 数値 x の場合、1 から √x までを繰り返し、約数をペアで加算します。 これは正しいです。なぜなら、√x より大きい約数はすべて、√x より小さい約数とペアになるからです。 ただし、これを最大 100,000 のクエリに対して実行すると、最良の場合でも約 100,000 × 316 ≈ 3,000 万の除数チェックが行われ、特に係数と除算の演算が繰り返される場合、Python の定数は大幅に悪化します。 

非効率性は、同じ除数情報を繰り返し再計算することから発生します。 すべての数値が複数のクエリに寄与するため、構造は事前計算を示唆しています。 各数値を個別に因数分解する代わりに、視点を逆にすることができます。つまり、潜在的な約数 d ごとに、それを d のすべての倍数に加算します。 これは古典的なふるい式の蓄積です。 各 i について、j が i 自体に等しい場合を除き、i のすべての倍数 j は適切な除数の寄与として i を受け取ります。 

これにより、問題はエラトステネスの篩に似た一連の調和ループに変換され、前処理の合計操作数は約 N log N になります。 100,000 までのすべての数値の適切な約数の合計が得られると、分類はクエリごとに O(1) になります。

 ## アルゴリズムのチュートリアル

 テーブルを事前計算します`sigma[x]`x の適切な約数の合計を格納します。 

1. 配列を初期化する`sigma`サイズ N+1 でゼロが含まれます。 この配列は、各数値の除数の寄与を累積します。 
2. 1 から N までのすべての整数 i を繰り返します。各 i について、j = 2i、3i、4i など、N までのすべての倍数に i を加算します。i 自体を適切な約数として含めるべきではないため、2i から開始します。 
3. このループの後、`sigma[x]`x のすべての適切な約数の合計が含まれます。 
4. 各クエリ値 a について、b = sigma[a] を計算します。 
5. b == a の場合、その数を完全であるとラベル付けします。 
6. b != a かつ sigma[b] == a の場合、divisor-sum 関数の下で a と b は 2 つのサイクルを形成するため、この数はロマンチックになります。 
7. b > a で、まだ完璧またはロマンチックに分類されていない場合は、「豊か」というラベルを付けます。 
8. それ以外の場合は、複雑なものとして分類します。 
9. 番号とその分類ラベルを出力します。 

ロマンチックなチェックが機能する理由は、制限値までのすべての値に対してシグマがすでに事前計算されているためです。 したがって、sigma[b] のチェックは定数時間です。 

### なぜ効果があるのか

 ふるいは、すべての d を反復してその倍数に分配するため、x のすべての適切な約数 d が sigma[x] に 1 回だけ加算されることを保証します。 これにより、sigma[x] が x 自体を除く x を除算するすべての整数の正確な合計になることが保証されます。 

分類ロジックは、sigma[x]、x、および sigma[sigma[x]] 間の比較にのみ依存します。 シグマは範囲内のすべての値に対して正確であるため、ロマンティック条件は 2 要素サイクルを正しく検出し、それらを完全な数やより大きなサイクルと混同することはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAX = 100000

sigma = [0] * (MAX + 1)

for i in range(1, MAX + 1):
    for j in range(i * 2, MAX + 1, i):
        sigma[j] += i

def classify(x):
    s = sigma[x]
    if s == x:
        return "perfecto"
    if s <= MAX and sigma[s] == x and s != x:
        return "romantico"
    if s > x:
        return "abundante"
    return "complicado"

n = int(input())
out = []
for _ in range(n):
    a = int(input())
    out.append(f"{a} {classify(a)}")

print("\n".join(out))
```実装の中核は、ふるいのような構造です。`sigma`。 内側のループは次から始まります`2*i`数値はそれ自体の適切な約数とはみなされないためです。 これにより、誤って自己貢献を含めてしまうというよくある間違いを防ぐことができます。 

分類関数は条件を正しい順序で評価します。 完全数は最初にチェックする必要があります。相互の等価性を大まかにチェックするだけだとロマンチックなものと誤解されてしまうからです。 ロマンティックには厳密な 2 サイクル条件が必要であるため、`s != x`。 完全数は技術的に次の条件を満たすため、それらのケースを除外した後にのみ豊富さがチェックされます。`s >= x`しかし、豊富であるとレッテルを貼られてはなりません。

 シグマ値を使用します。 

シグマ[6] = 1 + 2 + 3 = 6

 シグマ[12] = 1 + 2 + 3 + 4 + 6 = 16

 | × | シグマ[x] | シグマ[シグマ[x]]をチェック | 分類 |
 | --- | --- | --- | --- |
 | 6 | 6 | 必要ありません | 完璧 |

 x = 6 の場合は、x とその約数の合計が等しいことが完全な分類を直接引き起こすことを確認します。 x = 12 の場合は、除数の合計が厳密に大きく、相互関係がないことを示しており、豊富であることが確認されます。 

### 例 2

 入力数値：220、284

 既知の値を使用します。 

シグマ[220] = 284

 シグマ[284] = 220

 | × | シグマ[x] | シグマ[シグマ[x]] | 分類 |
 | --- | --- | --- | --- |
 | 220 | 284 | シグマ[284] = 220 | ロマンティコ |
 | 284 | 220 | シグマ[220] = 284 | ロマンティコ |

 このトレースは、相互マッピングのプロパティを示します。 各数値はシグマの下で他の数値にマッピングされ、固定の 2 サイクルを形成します。 これは、対称チェックを使用してロマンチックな数字が検出される理由を裏付けています。

 ## 特殊なケース

 x = 1 の場合、sigma[1] には適切な約数がないため、0 になります。 分類関数は、x より小さい s = 0 を認識し、sigma[0] が無関係であることをチェックします。 最終的な結果は複雑です。 これにより、数値に約数がない縮退ケースがアルゴリズムで正しく処理されることが確認されます。 

6 のような完全な数の場合、sigma[6] は 2 + 3 + 1 = 6 として計算されます。条件 s == x はすぐにトリガーされるため、他のチェックの前にperfecto として分類されます。 これにより、豊かであるかロマンチックであるかの誤分類を防ぐことができます。 

220 と 284 のような友好的なペアの場合、両方の値が範囲内にあり、それらのシグマ値は相互に指します。 チェック sigma[sigma[x]] == x は両方に対して対称的に成功し、明示的なペアの追跡を必要とせずに両方がロマンティコにラベル付けされることが保証されます。 

12 のような豊富な数の場合、sigma[12] = 16、および sigma[16] = 15 となり、12 には戻りません。16 > 12 であるため、豊富として分類されます。 2つのサイクルがないため、ロマンチックなものとして誤ってラベル付けされるのを防ぎます。
