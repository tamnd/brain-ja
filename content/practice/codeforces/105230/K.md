 ## 解決策
 ## 問題の理解

 長方形のグリッドが与えられ、各セルが壁、空の通路、トラップ、開始位置、または数値の量の宝物を含むセルを表します。 開始セルからは 4 方向への移動が許可されます。 目標は、トラップによって課された非常に特殊な制限の下で迷路を移動しながら、どれだけの宝を収集できるかを決定することです。 

重要な点は、トラップが動きを直接ブロックしないことです。 代わりに、トラップに直接隣接するセルは危険な領域になります。 アイリンは、この意味で危険な位置を通過することを拒否します。 その結果、有効な通過可能エリアは壁だけで決まるのではなく、近くのセルを考慮から除外するトラップの「影響ゾーン」によっても決まります。 

各テスト ケースは独立した迷路であり、これらの安全制約を尊重しながら、最初から到達できるすべての桁の合計を計算する必要があります。 

グリッド サイズは 1000 x 1000 までの大きさにすることができます。フル スキャンではすでに最大 100 万個のセルが処理されているため、テスト ケースごとの直線時間よりも悪いものは直ちに排除されます。 セルを頻繁に再訪したり、プルーニングを行わずに単純な探索をシミュレートしたりするソリューションは、タイムアウトになります。 

いくつかの状況では、単純な解決策が崩れる傾向があります。 

失敗例の 1 つは、セルがジオメトリのみから到達可能であるにもかかわらず、トラップの隣にある場合に発生します。```
S1.
.T.
.1.
```トラップの影響を無視した単純な BFS では、一番下のセルに到達して宝物がカウントされますが、正しい答えは、そのセルがトラップに隣接しているかどうかに応じて 0 または 1 になります。 このレイアウトでは隣接しているため、走査から完全に除外する必要があります。 

もう 1 つの微妙なケースは、開始点自体がトラップに隣接している場合です。 単純なアプローチではまだ外側に拡大する可能性がありますが、ルールにより最初の動きさえ阻止されます。 

最後に、複数の切断された安全領域を持つグリッドは、走査前に安全でないセルを適切にマークしないフラッドフィル実装で誤解を招くことがよくあります。 BFS 中に事前計算ではなく安全性が遅延チェックされると、アルゴリズムが無効化されるべきセルを誤って「ウォークスルー」する可能性があります。 

## アプローチ

 ブルート フォース解釈では、ステートフル検索として探索をシミュレートします。各移動では、ローカル トラップの近接性に基づいて、隣接するセルへの侵入が許可されるかどうかが考慮されます。 各状態から 4 方向すべてを検査し、周囲のトラップを動的にチェックし、再帰的に分岐します。 

これは、すべての有効なパスが探索され、セルが訪問されるたびに宝物が蓄積されるため、概念的に機能します。 しかし、問題は繰り返し作業にあります。 最悪の場合、すべてのセルに複数の方向から侵入する可能性があり、侵入ごとに隣接セルを再スキャンして安全性を確認することがあります。 これにより、ローカル チェックが多くのパスにわたって繰り返されるため、異常な構成では複雑さが O(N²M²) に達します。 

重要な観察は、細胞の「危険な状態」は、私たちがどのようにそこに到着するかによって決まるわけではないということです。 セルが全体的に安全か安全でないかは、隣接するセルにトラップが含まれているかどうかによってのみ決まります。 これが事前に計算されると、グリッドはフィルタリングされたグラフ上の標準的な接続問題になります。 

次に、問題は、開始ノードを含む接続コンポーネントを見つけることになりますが、安全なセル上でのみ検索し、途中で数値を合計することになります。 

これにより、タスクは最大 N×M ノードにわたる単一の BFS または DFS に変換され、一定時間の遷移が行われます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O((NM)²) | O(NM) | 遅すぎる |
 | 安全性の事前計算 + BFS | O(NM) | O(NM) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. グリッド全体を 1 回スキャンし、すべてのトラップの位置を記録します。 これは、後で検索を繰り返さずにその影響を効率的にマークできるようにするために必要です。 
2. ブール値グリッドを作成する`bad`、最初はすべてのセルに対して false です。 これを使用して、安全にアクセスできないセルをマークします。 
3. すべてのトラップ セルについて、その 4 つの隣接セルがグリッド内にあり、壁ではない場合は不良としてマークします。 このステップでは、トラップによって引き起こされる「危険ゾーン」を構築します。 横断前にこれを行う理由は、経路の選択とは関係なく安全性を知る必要があるためです。 
4. また、すべてのトラップ セル自体に入ることができないため、それ自体を不良としてマークします。 
5. 開始セルを見つけます。 すでに不良とマークされている場合は、法的な動きを開始できないため、答えは即座にゼロになります。 
6. 開始セルからグリッド上で BFS を実行します。 壁ではなく、不良とマークされておらず、以前に訪問したことのないセルにのみ移動してください。 
7. BFS がセルを訪問するたびに、セルに数字が含まれている場合は、それを整数に変換し、累計に追加します。 
8. キューが空になるまで続行します。 積み上げた合計が答えになります。 

### なぜ効果があるのか

 正しさは、「悪い」ステータスが走査順序とは無関係であるという事実にかかっています。 セルは、それがトラップであるか、トラップに直接隣接している場合には使用できなくなりますが、この特性は移動方法によって変化しません。 安全でないセルがすべて削除されると、残りのすべての移動で安全が確保され、標準の無向グリッド グラフが形成されます。 したがって、BFS は最初から到達可能な安全なコンポーネントを正確に列挙し、各セルは 1 回訪問されるため、そのコンポーネント内の収集可能な宝物はすべて 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import deque

def solve():
    n, m = map(int, input().split())
    g = [list(input().strip()) for _ in range(n)]

    bad = [[False] * m for _ in range(n)]
    sx = sy = -1

    traps = []

    for i in range(n):
        for j in range(m):
            if g[i][j] == 'T':
                traps.append((i, j))
            if g[i][j] == 'S':
                sx, sy = i, j

    dirs = [(1,0), (-1,0), (0,1), (0,-1)]

    for x, y in traps:
        bad[x][y] = True
        for dx, dy in dirs:
            nx, ny = x + dx, y + dy
            if 0 <= nx < n and 0 <= ny < m:
                if g[nx][ny] != '#':
                    bad[nx][ny] = True

    if bad[sx][sy]:
        print(0)
        return

    q = deque()
    q.append((sx, sy))
    vis = [[False] * m for _ in range(n)]
    vis[sx][sy] = True

    ans = 0

    while q:
        x, y = q.popleft()

        if g[x][y].isdigit():
            ans += int(g[x][y])

        for dx, dy in dirs:
            nx, ny = x + dx, y + dy
            if 0 <= nx < n and 0 <= ny < m:
                if not vis[nx][ny] and not bad[nx][ny] and g[nx][ny] != '#':
                    vis[nx][ny] = True
                    q.append((nx, ny))

    print(ans)

if __name__ == "__main__":
    solve()
```まずグリッドが完全にスキャンされ、トラップと開始位置が特定されます。 これにより、後で作業を繰り返すことがなくなります。 の`bad`配列は、トラップに近いために禁止されているすべてのセルをエンコードします。 この事前計算は、動的安全条件を静的プロパティに変えるため、重要です。 

BFS は、壁と安全でないセルの両方をフィルタリングすることを除いて、標準的なフラッド フィルと同様に動作します。 訪問された配列により、各セルが 1 回処理されることが保証され、指数関数的な分岐が防止されます。 

よくある間違いは、事前計算ではなく、BFS 拡張中にトラップへの隣接性をチェックすることです。 これにより、走査順序に応じて一貫性のない決定が行われることになります。 Another subtle issue is forgetting to block trap cells themselves, which can incorrectly allow passage through them if they are not adjacent to another trap.

 ## 実用的な例

 次の入力について考えてみましょう。```
4 9
S......T.
#####.###
111.#.111
..T....T.
```前処理後、トラップに隣接するすべてのセルがブロックされます。 BFS の開始時刻`S`そして安全な通路だけを探索します。 

| ステップ | Queue | Current Cell | アクション | 合計 |
 | --- | --- | --- | --- | --- |
 | 1 | (S) | S | 開始 | 0 |
 | 2 | ... | 到達可能な安全なセルのみ | 安全な領域で数字を収集する | 2 |

 検索が開始される前にトラップ近くのグリッドの大部分が無効になるため、トラバースはすぐに制限されます。 

次に、2 番目のカスタム例を考えてみましょう。```
3 5
S1T..
..2..
..3..
```安全でないセルをマークした後、隣接するすべてのセルが`T`が削除されます。 下部領域のみが接続されたままであると仮定します。 

| ステップ | キュー | 現在のセル | アクション | 合計 |
 | --- | --- | --- | --- | --- |
 | 1 | S | S | 開始 | 0 |
 | 2 | (1) | 1 | 集める | 1 |
 | 3 | (2) | 2 | 集める | 3 |
 | 4 | (3) | 3 | 集める | 6 |

 このトレースは、BFS が事前に検証された安全な構造上でのみ動作し、宝の蓄積は純粋に到達可能性の関数であることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(NM) | 各セルは前処理中に 1 回処理され、BFS 中に 1 回処理されます。 
| スペース | O(NM) | グリッド状態、訪問追跡、および安全マーキングの配列 |

 この制約により、テスト ケースごとに最大 100 万セルが許可されるため、リニア スキャン ベースのソリューションは時間とメモリの制限内に快適に収まります。 このアルゴリズムは探索の繰り返しを回避し、高密度のグリッドでも予測可能なパフォーマンスを保証します。

 ## 特殊なケース

 エッジケースの 1 つは、スタート地点がトラップに囲まれている場合です。 このような構成では、前処理ステップで開始セルが不良としてマークされ、アルゴリズムは直ちに終了します。 例えば：```
3 3
T.T
.S.
T.T
```の`bad`マーキングは各トラップから中央のセルに伝播するため、BFS は開始されず、正しくゼロが生成されます。 

もう 1 つのケースは、隣接ルールにより後で無効になる領域を介してのみセルに到達できる場合です。 すべての無効化はトラバーサルの前に行われるため、BFS はこれらのセルをまったく考慮せず、一貫性のない部分的な探索を防ぎます。 

最後のケースは、トラップがまばらな大きなオープングリッドで発生します。 ほとんどのセルは幾何学的に到達可能ですが、トラップに隣接していないセルだけが BFS グラフに残ります。 このアルゴリズムは、可視性や方向性の推論をシミュレートする必要なく、探索を適切に制限します。
