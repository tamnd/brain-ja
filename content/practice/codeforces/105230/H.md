 ## 解決策
 ## 問題の理解

 次の文字列としてエンコードされた 1 次元のパスが与えられます。`+`そして`-`。 文字列を処理する前に、暗黙的な高さゼロから開始します。 各文字は現在の高さを 1 単位だけ移動します。`+`身長が一つ伸びて、`-`1つ減ります。 各文字を処理した後、パスに沿った一連の高さ (文字列内の位置ごとに 1 つの高さ) を取得します。 

タスクは、歩行全体で高さが最大値に達する文字列内の位置を見つけることです。 位置には 1 から始まるインデックスが付けられ、その高さにつながる文字列内の文字を参照します。 

したがって、問題は本質的に、±1 配列にわたってプレフィックス合計をシミュレートし、この最大値が一意であることを保証しながら、最大プレフィックス合計が発生する最も早い位置を報告することです。 

制約`|s| ≤ 10^5`これは、あらゆる解が線形または線形に近いものでなければならないことを意味します。 プレフィックス合計の再計算や各位置からのスキャンなどの O(n²) シミュレーションでは、最悪の場合で最大 10¹⁰ の操作が必要となるため、非常に遅すぎます。 

Python の 1 秒制限では 105 回の操作は簡単なので、O(n) の線形スキャンで十分です。 

すぐに最大高さに達する場合、微妙なエッジケースが発生します。 たとえば、入力`+----`位置 1 で高さ 1 に達し、再びそれを超えることはありません。したがって、答えは 1 になります。別のケースは、最後に最大値に達する場合です。`++++`、答えは 4 です。ピークが必ずしも歩行の終点にあるとは限らないため、最終的な高さを追跡するだけの単純なアプローチはここでは失敗します。 

## アプローチ

 簡単なアイデアは、歩行をシミュレートし、各ステップの後の高さを計算することです。 ゼロから始まる累計を維持し、文字に応じて +1 または -1 ずつ更新します。 その過程で、これまでに確認された最大値と、それが最初に発生した位置を追跡します。 

これが機能するのは、各位置の高さがその位置までの文字列のプレフィックスのみに依存するためです。 ただし、不用意に実装すると、各インデックスの高さを最初から再計算する可能性があり、各位置で以前のすべての文字を再度スキャンするため、O(n²) 時間がかかります。 

重要な観察は、プレフィックスの合計が増加しているということです。 新しい高さはそれぞれ、前の高さから一定時間で導出できます。 これにより、計算が文字列の 1 回のパスに減り、最適化されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (プレフィックスを毎回再計算) | O(n²) | お(1) | 遅すぎる |
 | 最適 (単一プレフィックス スキャン) | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 現在の高さ、これまでに見つかった最高の高さ、最高の高さが発生するインデックスの 3 つの値を維持しながら、文字列を 1 回スキャンします。 

1. 現在の高さを 0 に、最適な高さを 0 に、最適な位置を 0 に初期化します。最大値が初期の想定を超えて改善されないケースを処理するために、概念的に位置 0 を含めます。 
2. 1 から始まるインデックス i を使用して、文字列を左から右に繰り返します。 
3. 現在の身長を更新します。キャラクターが高ければ 1 ずつ増加します。`+`、それ以外の場合は 1 減ります。 
4. 現在の高さと最適な高さを比較します。 現在の高さが厳密に大きい場合は、最適な高さを更新し、位置 i を記録します。 
5. 文字列の終わりまで続けます。 
6. 保存したベストポジションを出力します。 

各ステップは高さが累積的に構築されるという事実に依存しているため、処理後に将来または過去のセグメントを再検討する必要はありません。 

### なぜ効果があるのか

 高さの順序はプレフィックスの合計によって完全に決定され、各プレフィックスの合計は前のプレフィックスの合計にのみ依存します。 各ステップ i で、アルゴリズムは i までのすべてのプレフィックスの合計の最大値を保存します。 すべてのプレフィックスの合計は 1 回だけ評価され、すぐに比較されるため、より大きな値が見逃されることはありません。 一意性が保証されているため、同点や複数の候補を処理する必要がないため、単純な厳密な比較で十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    
    cur = 0
    best = 0
    best_pos = 0
    
    for i, ch in enumerate(s, 1):
        if ch == '+':
            cur += 1
        else:
            cur -= 1
        
        if cur > best:
            best = cur
            best_pos = i
    
    print(best_pos)

if __name__ == "__main__":
    solve()
```このコードは、プレフィックス合計スキャンを直接実装します。 変数`cur`現在の高さを追跡し、文字ごとに一定時間で更新されます。 変数`best`これまでに確認された最高の高さを保存し、`best_pos`それが起こった場所を覚えています。 

ループは 1 から始まるインデックスを使用します。`enumerate(s, 1)`問題の位置の定義と一致するようにします。 厳密な比較`cur > best`これは、一意性の保証と一致する、最初に発生した最大高さのみを記録することを保証します。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、最初のステップですぐに最大高さに達する場合です。 入力用`+----`、プレフィックスの高さは次のとおりです。`[1, 0, -1, -2, -3]`したがって、答えは 1 でなければなりません。アルゴリズムはこれを処理します。`best`0 から始まり、i = 1 で更新されます。`cur = 1`。 

もう 1 つのエッジ ケースは、開始後に高さがゼロを超えない場合です。 入力用`-----`、最大プレフィックス高さは、位置 0 (移動前) では 0 です。 実装では当然 0 が返されます。`best_pos`0 に初期化され、更新されることはありません。 

3 番目のケースは、最大値が複数回発生するが、最初の発生値のみが返される必要がある場合です。 のために`++-++`、高さは`[1, 2, 1, 2, 3]`、最大値 3 は位置 5 に 1 回だけ表示されます。等しい最大値が複数ある場合、厳密な値は`>`比較により、最初に出現したものが確実に保持されます。
