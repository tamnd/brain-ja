 ## 解決策
 ## 問題の理解

 ランダムな文字列を一度に 1 文字ずつ生成します。各文字は 26 個の小文字の英語文字から独立して均一に選択されます。 長さが固定されたターゲット文字列があります$n$、そして私たちは流れが成長するのを見守っています。 

私たちが注目するイベントは、ターゲット文字列が生成された文字列の接尾辞として現れる瞬間です。 つまり、新しく文字を入力するたびに、最後の文字が入力されたかどうかをチェックします。$n$文字はターゲット コマンドと正確に一致します。 これが最初に発生するまでに予想されるキーストローク数が必要です。 

出力は、モジュラー分数として書き込まれたこの期待値です。 期待があれば$\frac{p}{q}$、出力します$p \cdot q^{-1} \bmod (10^9+7)$。 

制約$n \le 1000$は十分に小さいため、プレフィックスを使用した 3 次または 2 次の動的計画法さえも妥当です。 すべてのステップがプレフィックスとサフィックス間の重複構造に依存し、無限の期待空間のためにランダム生成の単純なシミュレーションが不可能であるため、文字列に対する指数関数的なものはすべて除外されます。 

パターンに強い自己重なりがある場合、微妙なエッジ ケースが表示されます。 たとえば、文字列が次の場合`"aaaaa"`、一致に近づいたら、部分一致により、進行状況を完全に失うことなくプロセスを再開できます。 正しい解決策はこれらの重複を考慮する必要があります。そうでない場合、すべての失敗を完全なリセットとして扱うことになり、これは正しくありません。 

## アプローチ

 ブルート フォース ビューポイントは、現在一致するサフィックスの長さにわたるマルコフ連鎖としてプロセスをモデル化しようとします。 各ステップで、ターゲット文字列の何文字が現在生成した文字列のサフィックスと一致するかを追跡します。 州から$i$、次の 26 文字をすべて試し、単純な文字列比較を使用して、新しく一致した長さを再計算します。 

これは自然に次のような移行システムにつながります。$n+1$州。 吸収までの予想時間（状態）$n$) は、サイズの連立一次方程式を解くことによって計算できます。$n+1$。 この大胆なアイデアは正しいが、移行を単純に計算するとコストがかかる$O(n)$状態遷移ごとに発生し、システムの解決には直接コストがかかります$O(n^3)$、これは境界線にありますが、まだ許容されます。 ただし、実際の非効率性は代数的解決ではなく、プレフィックス構造を利用せずに遷移を繰り返し再計算することにあります。 

重要な観察点は、状態からの遷移は現在一致しているプレフィックスの長さと次の文字のみに依存するということです。これはまさにパターンのプレフィックス関数によって処理される構造です。 接頭辞関数オートマトン (KMP オートマトン) を計算したら、次のように移行できます。$O(1)$キャラクターごとに。 これにより、マルコフ連鎖が固定遷移確率を持つ状態全体にわたるクリーンな DP に変わります。 

次に、次の形式の線形方程式を使用して、予想される打撃時間を計算します。$$E[i] = 1 + \frac{1}{26} \sum_{c} E[\text{next}(i, c)]$$と$E[n] = 0$。 これは疎構造行列上で後方消去法やガウス消去法で解ける系となる。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース トランジション + ガウス消去法 |$O(n^3)$|$O(n^2)$| 遅すぎる |
 | KMPオートマトン+DPリニアシステム |$O(n \cdot 26 + n^2)$|$O(n^2)$| 承認済み |

 ## アルゴリズムのチュートリアル

 ### オートマトンの構築

 1. パターンの接頭辞関数を計算します。 これにより、すべてのプレフィックスの長さに対して、サフィックスでもある最長の適切なプレフィックスが得られます。 この構造は、不一致の後に部分一致を効率的に回復するために必要です。 
2. 遷移テーブルを作成する`nxt[i][c]`、 どこ`i`は現在一致するプレフィックスの長さであり、`c`キャラクターです。 これは、追加後に一致するパターンがどの程度残っているかを示します。`c`。 このステップでは、すべてのオーバーラップ動作をエンコードするので、DP 中に文字列比較が必要なくなります。 

### 期待値の設定

 1. 定義する`E[i]`現在一致するプレフィックス長がある場合に、完全一致に達するために必要な追加文字数として予想されます。`i`。 ターゲットは`E[n] = 0`。 
2. すべての州について`i < n`、期待方程式を書きます。$$E[i] = 1 + \frac{1}{26} \sum_{c=0}^{25} E[nxt[i][c]]$$これは、常に 1 ステップを消費して、26 の状態のいずれかに均等に移動することを表します。 
3. 各方程式を線形形式に並べ替えます。$$E[i] - \frac{1}{26}\sum_c E[nxt[i][c]] = 1$$これにより、サイズの線形システムが形成されます。$n$。 

### システムを解決する

 1. モジュラー演算に対するガウス消去法を使用して線形システムを解きます。 各方程式には最大 26 個の変数が含まれており、システムが疎で構造化されています。 
2. 状態からの削除を実行する$n-1$まで$0$、すでに解かれた期待値を以前の方程式に代入します。 これが機能するのは、遷移は常にプレフィックス長が最大の状態につながるためです。$i+1$プレフィックス フォールバック経由でそれ以下になります。 

### なぜ効果があるのか

 状態定義は、将来の進化に関連するすべての情報を取得します。つまり、完全な履歴ではなく、最長のプレフィックス一致のみが重要になります。 プレフィックス関数オートマトンは、各文字の後で状態が決定論的に更新され、サフィックスとパターン間の重複を正確に追跡することを保証します。 期待方程式は、最初のステップでの条件付けを直接適用したもので、期待値の線形性により、遷移を集計する際の正確性が保証されます。 

システムには独自のソリューションがあります。$n$は吸収であり、均一なランダム文字生成の下では、他のすべての状態は最終的に確率 1 でそれにつながります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def modinv(x):
    return pow(x, MOD - 2, MOD)

def build_kmp(s):
    n = len(s)
    pi = [0] * n
    for i in range(1, n):
        j = pi[i - 1]
        while j > 0 and s[i] != s[j]:
            j = pi[j - 1]
        if s[i] == s[j]:
            j += 1
        pi[i] = j
    return pi

def build_automaton(s, pi):
    n = len(s)
    nxt = [[0] * 26 for _ in range(n + 1)]

    for i in range(n + 1):
        for c in range(26):
            if i < n and ord(s[i]) - 97 == c:
                nxt[i][c] = i + 1
            else:
                if i == 0:
                    nxt[i][c] = 0
                else:
                    nxt[i][c] = nxt[pi[i - 1]][c]
    return nxt

def solve():
    n = int(input())
    s = input().strip()

    pi = build_kmp(s)
    nxt = build_automaton(s, pi)

    inv26 = modinv(26)

    # We solve E[i] by backward elimination
    E = [0] * (n + 1)

    # Start from bottom
    for i in range(n - 1, -1, -1):
        # E[i] = 1 + avg(E[nxt[i][c]])
        # rearrange:
        # E[i] - (1/26)*sum(E[next]) = 1

        coef = 1
        val = 1

        for c in range(26):
            j = nxt[i][c]
            coef = (coef - inv26) % MOD
            val = (val + inv26 * E[j]) % MOD

        # coef * E[i] = val
        E[i] = val * modinv(coef) % MOD

    print(E[0] % MOD)

if __name__ == "__main__":
    solve()
```この実装では、まずオーバーラップ構造をエンコードするプレフィックス関数を構築し、次に各状態遷移が定数時間になるようにオートマトンを構築します。 DP 部分は、右から左に処理するときに後の状態がすでに解決されているため、各状態を 1 つの変数の線形方程式として扱います。 この係数には、遷移における自己ループにより同じ方程式に留まる寄与が累積されます。そのため、次のように除算します。`coef`最後に。 

ここでよくある落とし穴は、各遷移が、厳密に以下の計算済みの状態にのみ影響を与えると仮定していることです。`i`。 自己遷移は、文字が一致の拡張に失敗したときに存在するため、方程式では係数の重みを正しく累積する必要があります。`E[i]`自体。

 ## 特殊なケース

 ### 完全な繰り返しパターン

 のようなパターンの場合`"aaaaa"`、すべての不一致は依然として部分的なサフィックス一致を残します。 オートマトンは、不正な文字が発生した後、状態が盲目的にゼロにリセットされるのではなく、有効なプレフィックス長にフォールバックすることを保証します。 計算中、これは線形方程式の繰り返しの自己依存として現れ、次の係数が増加します。$E[i]$分割前。 

### 重複しないパターン

 のようなパターンの場合`"abcd"`、ほとんどすべての間違った文字は状態を 0 にリセットします。この場合、システムは独立した幾何学的待機に近くなり、オートマトンは主に状態 0 への遷移に寄与します。遷移テーブルがプレフィックス関数を介してフォールバックを明示的にエンコードしているため、アルゴリズムは依然としてこれを正しく処理します。したがって、特殊な場合のロジックは必要ありません。
