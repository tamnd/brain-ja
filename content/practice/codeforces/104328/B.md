 ## 解決策
 ## 問題の理解

 すべての頂点が 20 ビットの整数値を保持する有向非巡回グラフが与えられます。 タスクは、有向エッジに沿って移動するパスを選択することです。$k$頂点を計算し、パスに沿ったすべての値のビット単位の AND として定義されたスコアを計算します。 すべての有効な長さのパスの中で$k$、この AND の可能な最大の結果が必要です。 

したがって、問題は古典的な意味での最短または最長のパスを見つけることではなく、選択されたすべての頂点にわたって共通のセット ビットをできるだけ多く保持する、制約された長さのパスを選択することです。 

重要な問題は、構造とビット単位の演算の間の相互作用にあります。 グラフは遷移を制限しますが、AND 演算はどの頂点が一緒に表示されるかに大きく依存します。 選択した頂点に 1 つのゼロ ビットがあると、最終結果のそのビットは永久に破壊されます。 

制約は大きく、最大で$2 \cdot 10^5$頂点とエッジ、そして$k$と同じ大きさにすることもできます$n$。 パスを列挙したりパスごとの状態を維持しようとするソリューションは失敗します。すべての部分的なパスを保存するだけでも指数関数的に増加するためです。$k$、圧縮なしのすべてのパスの DP であっても、$O(nk)$これは境界線にありますが、それでも大きすぎます$m$同じように。 

DAG である構造は非常に重要です。 サイクルがないことが保証されるため、頂点をトポロジカルな順序で処理でき、どのパスも最大でも長さを持つことが保証されます。$n$。 

素朴なアプローチの微妙な失敗例は、貪欲さが局所的に機能すると仮定することです。 たとえば、局所的に最適な頂点によって将来の継続に必要なビットが削除される可能性があるため、各ステップで最大値を持つ近傍を選択することは機能しません。 

別の失敗例は、スカラー重みをもつ最長パス DP のように扱うことです。 ここで、「重み」は加算的または単調的ではないため、ノードごとに単一の最良値を使用して部分問題を結合するだけでは不十分です。 頂点ごとに 1 つの最高スコアだけではなく、より多くの情報を記憶する必要があります。 

## アプローチ

 強引なアイデアは、パス上の DP を定義することです。すべての頂点およびすべての長さについて、その頂点で終わるその長さのパスの可能な限り最良の AND 値を計算します。 遷移では、すべての入力エッジが考慮されます。 これはフォームの再発につながります$dp[v][t] = \max_{u \to v}(dp[u][t-1] \& a_v)$。 

これは正しいですが、遅すぎます。 状態空間は$O(nk)$、各遷移は入力エッジをスキャンし、$O(mk)$、最悪の場合、$2 \cdot 10^{10}$操作。 

重要な観察は、値空間が任意ではないということです。 各数値は最大 20 ビットなので、$2^{20}$可能なマスク、および AND 演算はビットのみを削除します。 これは、ビットレベルの構築を示唆しています。正確な DP 値を計算する代わりに、可能な限り高いマスクから下に向かって貪欲に答えを構築しようとします。 

視点を逆転させます。「各パスに最適な AND は何か」を尋ねる代わりに、「指定されたマスクを長さ k のパスの AND として実現できるか?」と尋ねます。 マスクが達成可能であれば、そのすべてのサブマスクも達成可能です。 この単調性により、バイナリ検索や貪欲なビット構築が可能になります。 

最も重要なものから最も重要でないものまで、少しずつ答えを構築します。 各ステップで、ビットを暫定的に 1 に強制し、次の長さのパスが存在するかどうかを確認します。$k$現在固定されているすべてのビットを値に含む頂点のみを使用します。 このチェックは、DAG 上の制限された到達可能性 DP に縮小され、許可された頂点のみを介して伝播します。 

なぜなら、それぞれの実現可能性チェックは$O(n + m)$、これを最大 20 ビットに対して行うと、全体の複雑さは次のようになります。$O(20(n + m))$、効率的です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | パス上のブルート フォース DP |$O(mk)$|$O(nk)$| 遅すぎる |
 | DAG を超えるビットマスクの貪欲な実現可能性 |$O(20(n + m))$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 この問題を、有効な長さ k のパスの AND として現れる最大ビットマスクを構築するものとして再解釈します。 

### ステップ

 1. DAG のトポロジー的順序付けを計算します。 

これにより、ノードを再度訪問することなく、単一の順方向パスでパス情報を伝播できることが保証されます。 
2. 応答マスクを 0 として初期化します。 

ビットを上位から下位に設定してみます。 
3. 19 から 0 までの各ビットについて、応答マスクに設定してみます。 

以前に固定されたすべてのビットとこの新しいビットを含む候補マスクを一時的に定義します。 
4. 候補マスクと互換性のある頂点をフィルターします。つまり、候補内のすべてのビットが頂点値に存在します。 

これに失敗した頂点は、このマスクの下の有効なパスに表示されません。 
5. DAG 上でトポロジ順に DP を実行し、有効な各ノードから開始して達成可能な最大パス長を計算します。 

各ノードについて、それが有効であれば、その最適なチェーン長は 1 に、同様に有効なすべての発信隣接ノードの最大値を加えたものになります。 
6. いずれかのノードが少なくともパス長を達成した場合$k$の場合、候補マスクは実行可能であるため、ビットを保持します。 それ以外の場合は破棄します。 
7. すべてのビットを処理した後、構築されたマスクを出力します。 

各実現可能性チェック内の DP は、重要な計算ステップです。 それは基本的に、許可された頂点によって誘導されたサブグラフ内に、少なくとも次の長さのパスが存在するかどうかを尋ねます。$k$? グラフは DAG であるため、これは有効なノードに限定された DAG における最長パスの問題に帰着します。 

### なぜ効果があるのか

 このアルゴリズムは、すべてのステップで、現在のマスクが少なくとも 1 つの有効な長さのパスによって達成可能な値を表すという不変条件を維持します。$k$。 各実現可能性チェックでは、新しいビットを追加してもこのプロパティが破壊されないことが保証されます。 AND はビットを削除するだけでビットを導入しないため、マスクを拡張しても頂点セットは小さくなるだけで、大きくなることはありません。 したがって、ビット除去に関して実現可能性は単調であり、上位ビットから下に向かう貪欲な構築が正当化されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can(mask, n, adj, topo, a, k):
    valid = [False] * n
    for i in range(n):
        if (a[i] & mask) == mask:
            valid[i] = True

    dp = [0] * n
    best = 0

    for u in topo:
        if not valid[u]:
            continue
        dp[u] = max(dp[u], 1)
        for v in adj[u]:
            if valid[v]:
                if dp[u] + 1 > dp[v]:
                    dp[v] = dp[u] + 1
        best = max(best, dp[u])

    return best >= k

def topo_sort(n, adj):
    indeg = [0] * n
    for u in range(n):
        for v in adj[u]:
            indeg[v] += 1

    stack = [i for i in range(n) if indeg[i] == 0]
    topo = []

    while stack:
        u = stack.pop()
        topo.append(u)
        for v in adj[u]:
            indeg[v] -= 1
            if indeg[v] == 0:
                stack.append(v)

    return topo

def solve():
    n, m, k = map(int, input().split())
    a = list(map(int, input().split()))

    adj = [[] for _ in range(n)]
    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        adj[u].append(v)

    topo = topo_sort(n, adj)

    ans = 0
    for b in range(19, -1, -1):
        cand = ans | (1 << b)
        if can(cand, n, adj, topo, a, k):
            ans = cand

    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションでは、最初に、すべての遷移が DAG の方向を尊重するようにトポロジカルな順序付けを構築します。 これが必要なのは、実現可能性 DP が状態を再検討せずに依存関係の順序でノードを処理することに依存しているためです。 

の`can`関数は頂点をフィルタリングすることによって現在のビットマスク制約を強制します。 必要なビットが欠けているノードは完全に除外されます。 次に、最長パスのような DP が DAG 上で実行されますが、有効なノード間でのみ実行されます。 いずれかのノードが少なくともチェーンの長さに達すると、$k$、マスク承ります。 

外側のループは、最上位ビットから最下位ビットまで貪欲に答えを構築し、辞書編集上の最大ビットマスクを保証します。 

微妙な点は、正確なパスを追跡する必要はなく、最長の有効なチェーンのみを追跡する必要があることです。 長さだけを気にするので、$k$パスが存在します、DP 値がそれを超えています$k$は無関係です。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    def topo_sort(n, adj):
        indeg = [0]*n
        for u in range(n):
            for v in adj[u]:
                indeg[v]+=1
        stack = [i for i in range(n) if indeg[i]==0]
        topo=[]
        while stack:
            u=stack.pop()
            topo.append(u)
            for v in adj[u]:
                indeg[v]-=1
                if indeg[v]==0:
                    stack.append(v)
        return topo

    def can(mask, n, adj, topo, a, k):
        valid=[False]*n
        for i in range(n):
            if (a[i]&mask)==mask:
                valid[i]=True
        dp=[0]*n
        best=0
        for u in topo:
            if not valid[u]: continue
            dp[u]=max(dp[u],1)
            best=max(best,dp[u])
            for v in adj[u]:
                if valid[v]:
                    dp[v]=max(dp[v], dp[u]+1)
        return best>=k

    n, m, k = map(int, input().split())
    a = list(map(int, input().split()))

    ans=0
    for b in range(19,-1,-1):
        if can(ans|(1<<b), n, adj, topo, a, k):
            ans|=(1<<b)
    return str(ans).strip()
