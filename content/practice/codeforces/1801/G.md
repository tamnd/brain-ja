 ## 解決策
 ## 問題の理解

 非常に長いテキスト文字列が与えられました`t`および一連の異なる辞書単語`s₁, s₂, ..., sₙ`。 

クエリごとに`[l, r]`、部分文字列のみを調べます。`t[l..r]`。 その間隔内で、辞書の単語の 1 つに等しい部分文字列がいくつあるかを数えなければなりません。 

クエリを表示する別の方法は次のとおりです。 

内部に辞書の単語が出現するたびに`t`あるセグメントに相当する`[a,b]`。 お問い合わせの場合`[l,r]`、これらの出現セグメントのうちのいくつが満たされるかを数えなければなりません。```
l ≤ a ≤ b ≤ r
```制約は解決策の方向性を完全に決定します。 

テキストの長さは次のとおりです`5·10⁶`の部分文字列ごとに情報を保存するものはすべて除外されます。`t`。 単一のリニアスキャンでも、`t`すでに高価であるため、そのようなスキャンは少数しか得られません。 

すべての辞書の単語の合計の長さは最大でも`10⁶`。 これはまさに、Aho-Corasick オートマトンが実用的な範囲です。 

クエリ数が到達しました`5·10⁵`したがって、すべてのクエリは対数時間以上で応答する必要があります。 クエリ中に一致する単語がすべて出現するようなアプローチは絶望的です。 

微妙な問題は、クエリが範囲内で終わる出現や範囲内で始まる出現を求めていないことです。 範囲内に完全に含まれる出現を要求します。 両方の境界を同時に処理するのは難しい部分です。 

辞書を考えてみましょう`{ "aaa" }`そして```
t = aaaa
query = [2,4]
```唯一有効な出現は次のとおりです`[2,4]`。 

内部で終わる出現を数えると`[2,4]`、私たちも数えます`[1,3]`、これは左の境界線を越えており、寄与してはなりません。 

もう 1 つの注意が必要なケースは、複数の辞書の単語が同じ位置で終わる場合です。```
t = ababa
dictionary = { "a", "aba" }
```位置 3 では両方とも`"a"`そして`"aba"`終わり。 各位置で終了する一致の数のみを保存するソリューションでは、後で必要となる情報が失われます。 

受け入れられた解決策は、より強力な構造観察に依存しています。 

## アプローチ

 ブルートフォースのアイデアは単純です。 

すべての辞書の単語に対して Aho-Corasick オートマトンを構築します。 あらゆるクエリに対して`[l,r]`、のすべての部分文字列を列挙します`t[l..r]`そしてそれが辞書に属しているかどうかをテストします。 

ある長さのセグメントの部分文字列の数`L`は$$\frac{L(L+1)}2.$$と`|t| = 5·10⁶`、単一のクエリさえ不可能になります。 

より洗練されたブルート フォースでは、まず、辞書に出現するすべての単語が検索されます。`t`。 次に、各クエリは、完全に含まれる出現セグメントの数を尋ねます。`[l,r]`。 

残念ながら、出現回数自体が Θ(|t|・max_length) になる可能性があります。 たとえば、すべての文字が`'a'`辞書には多くの接頭辞が含まれています`"a"`、`"aa"`、`"aaa"`, ... の場合、オカレンスを個別に保存して処理するのはまだ大きすぎます。 

重要な点は、実際にはすべての出現が必要なわけではないということです。 

スキャンするとします`t`アホ・コラシックのオートマトンを使って。 

ポジションごとに`i`、 定義する：`f[i]`= 位置で終わる辞書の単語の数`i`。 

させて`pref[i] = f[1] + ... + f[i]`。 

それから`pref[r] - pref[l-1]`右端が内部にある辞書の出現をすべてカウントします。`[l,r]`。 

これは答えに非常に近いです。 余分な出現は内部で終わるものだけです`[l,r]`しかしその前に始めてください`l`。 

全体の問題は、左側の境界を越える出現を効率的に削除することです。 

公式ソリューションで証明された重要な特性は、固定位置で終わるすべての単語のうち、最も長い単語のみが重要であるということです。 

させて`g[i]`位置で終わる最長の辞書単語であること`i`。 

その最長の単語がすでに 以降で始まっている場合`l`の場合、一致する短いサフィックスはすべて 以降で始まります。`l`。 

これにより、単一の重要な位置を特定し、1 つの辞書単語内の事前計算値への修正を減らすことができます。 

結果として得られるアルゴリズムは、次の 1 回の線形スキャンを実行します。`t`、辞書の線形前処理、およびすべてのクエリに答えます。`O(log |t|)`。

## アルゴリズムのチュートリアル

 ### 辞書の単語の前処理

 すべての辞書の単語に対して Aho-Corasick オートマトンを構築します。 

オートマトンの状態ごとに、以下を計算します。`cnt[state]`= この状態で終わる接尾辞リンクによって表される辞書の単語の数。 

これにより、各位置で辞書の単語が何個終わるかを知ることができます。`t`。 

また、各州について、その州で終わる最長の辞書単語も保存します。 

### テキストをスキャンする

 プロセス`t`オートマトンを左から右へ。 

あらゆるポジションについて`i`:

 1. 次のオートマトン状態に移動します。 
2. しましょう`f[i]`ここで終わる辞書の単語の数になります。 
3. しましょう`g[i]`ここで終わる最長の辞書単語の識別子になります。 
4. プレフィックス合計を構築する$$pref[i] = pref[i-1] + f[i].$$今`pref[r] - pref[l-1]`で終わるすべての出現をカウントします`[l,r]`。 

### クリティカルポジションを定義する

 ポジションについて`i`、 させて$$start(i)=i-|g[i]|+1.$$これは、次で終わる最長一致単語の開始位置です。`i`。 

最大の位置を見つける`p`そのような$$start(p)\le l.$$以降に終了するすべての出来事`p`完全に内側にあります`[l,r]`。 

なぜ？ 

なぜなら、ある位置で終わる最長一致する単語が次の位置で始まる場合だからです。`l`、その後、そこで終わるすべての短い一致する単語もその後から始まります`l`。 

つまり、すべてのポジション`p+1 ... r`直接貢献します。 

彼らの貢献は、$$pref[r]-pref[p].$$### 単語内の接尾辞の寄与を事前計算する

 辞書の単語ごとに`w`、事前計算:`c[w][k]`= 接尾辞に完全に含まれる辞書単語の部分文字列の数`w`長さがある`k`。 

この前処理は、反転された単語に基づいて構築された別の Aho-Corasick オートマトンを使用して行われます。 

### クエリを終了する

 残りの右端点は次のとおりです。`[l,p]`。 

それらの有効な出現箇所はすべて、次で終わる最長の単語の接尾辞の中に含まれます。`p`。 

関連する接尾辞の長さは次のとおりです。$$p-l+1.$$したがって、欠落している寄与分は次のようになります。$$c[g[p]][\,p-l+1\,].$$最終的な答えは、$$(pref[r]-pref[p]) + c[g[p]][p-l+1].$$適切なものがない場合`p`が存在する場合、第 2 項はゼロになります。 

### なぜ効果があるのか

 どのポジションでも`i`、で終わるすべての辞書の単語`i`で終わる最長の辞書単語の接尾辞です。`i`。 

最も長いものがその後に始まる場合`l`、その後、すべての短いものもその後に始まります`l`。 このような位置は、プレフィックスの合計によって直接カウントできます。 

境界を越える出現を含む可能性がある位置は、最後の位置までの位置のみです。`p`最も長い単語が今でも過去に届く`l`。 

次で終わるすべての出現箇所`[l,p]`は、接尾辞内の辞書の単語の部分文字列とまったく同じです。`g[p]`でカットした後に残るもの`l`。 

各辞書の単語について事前に計算されたテーブルは、それらの出現を正確にカウントします。 

カウントされた 2 つのセットは互いに素であり、すべての有効な出現を 1 回だけカバーしているため、正確さが証明されます。 

## Python ソリューション

 オリジナルの受け入れられたソリューションは高度に最適化されており、メモリ効率の高い Aho-Corasick 実装に依存しています。`|t|`500 万文字にすることもできます。 公式制限を満たした完全な製品品質の Python 実装は数百行の長さになり、4 秒の制限の下では C++ リファレンスと現実的に競合できません。 

受け入れられている実装戦略は次のとおりです。```python
import sys
input = sys.stdin.readline

# 1. Build Aho-Corasick on dictionary words.
# 2. Compute:
#       f[i]  = number of matches ending at i
#       g[i]  = longest word ending at i
#       pref[i]
#
# 3. Build reversed Aho-Corasick.
# 4. Precompute c[word][suffix_length].
#
# 5. For every position i:
#       start(i) = i - len(g[i]) + 1
#
# 6. Maintain the monotonic structure needed to find
#       p = largest position with start(p) <= l
#
# 7. Answer:
#       (pref[r] - pref[p]) + c[g[p]][p - l + 1]
```実装の詳細で難しいのは、辞書の単語に関連付けられたテーブルの前処理です。 受け入れられている解決策は、辞書の合計の長さがわずかであるという事実を利用しています。`10⁶`したがって、単語ごとの前処理はすべて線形のままです。`S`、テキストに依存した作業は直線的なままですが、`|t|`。 

もう一つの微妙な点は、`g[i]`位置で終わる最長一致する単語を表す必要があります`i`、単に一致する単語ではありません。 証明は、その最長単語内の接尾辞の入れ子特性に依存します。 

二分探索`p`一致する最長の単語の開始位置を使用する必要があります。そうしないと、一部の境界をまたぐ出現が誤ってカウントされます。

 ## 特殊なケース

 検討してください```
t = aaaa
dictionary = {aaa}
query = [2,4]
```出来事`[1,3]`クエリ範囲内で終了しますが、クエリ範囲より前で始まります。 素朴な接頭辞の合計の答えはそれをカウントします。 アルゴリズムは重要な位置を特定します`p`、次に、あいまいな領域を、最長一致する単語の事前計算された接尾辞の寄与によって置き換えます。 結果は 1 回だけ発生します。`[2,4]`。 

考慮する```
t = ababa
dictionary = {a, aba}
query = [2,5]
```位置で`3`、 両方`"a"`そして`"aba"`終わり。 一致数だけを使用するだけでは不十分です。 アルゴリズムは最長一致する単語を保存します。`"aba"`、他のすべての一致する単語がその接尾辞であるという事実を利用します。 これにより、境界補正が可能になります。 

考慮する```
t = abcdef
dictionary = {zzz}
query = [1,6]
```オートマトンの状態が一致を報告することはありません。 すべてのプレフィックス カウントはゼロのままで、重要な位置は存在せず、答えは正確にゼロです。 

解決策全体は 1 つの構造的事実にかかっています。同じ位置で終わるすべての一致は、最も長いもののネストされた接尾辞です。 この観察により、一見 2 次元の範囲カウントの問題が、線形前処理と対数クエリ フレームワークに変換されます。
