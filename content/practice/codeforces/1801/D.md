 ## 解決策
 ## 問題の理解

 私たちは都市の有向ネットワークを与えられており、各都市には 1 日あたりの収入があり、各フライトには固定コストがかかります。 ある程度の初期資金を持って都市 1 から開始し、目標は都市 n に到達することです。 制約は、飛行機に乗る前に、その費用を支払うのに十分なお金をすでに持っていなければならず、飛行機に乗るとその費用が差し引かれるということです。 

どの都市でもパフォーマンスに時間を費やすことができます。 各パフォーマンスにより、その都市の収入価値に応じて私たちのお金が増加します。 問題は、単に都市 n への到達が可能かどうかではなく、選択した経路に沿ったすべてのフライトの予算制約の下で都市 n への到達を可能にするために必要な最小限のパフォーマンス数は何かということです。 

核心的な問題は、お金が静的な状態ではないということです。 それは時間の経過とともに増加しますが、それは離散的な場所でのみであり、すべてのエッジは横断する前に最低限必要なバランスを課します。 これにより、問題は最短経路のように見えますが、「距離」はパフォーマンスの数であり、実現可能性はその経路に沿った累積収入に依存します。 

制約は、単純な検索が失敗する理由を示しています。 テストごとに最大 800 都市と 3,000 便、全体で最大 10,000 便が可能です。 お金の範囲は最大 10^9 であり、動的に増加するため、都市と現在のお金を追跡する国家空間は不可能です。 お金を明示的にシミュレートしようとするアプローチは実行不可能です。 

貪欲な最短経路の考え方が微妙に失敗するケースは、高価な航空券が少ない経路の方が、低所得都市に長く滞在することになるため、実際には悪くなる場合です。 

たとえば、都市 1 の収入は非常に低いが、都市 2 の収入は高く、都市 3 に到達するには 2 つの方法があるとします。1 つは 1 から 3 への高価なエッジを直接経由する方法、もう 1 つは最初のエッジは安いが 1 で待機する必要がある 2 を経由する方法です。単純なアプローチでは、単純に見えるため直接エッジを選択する可能性がありますが、都市 1 でより多くのパフォーマンスを強制するため、状況が悪化します。 

本当の課題は、「待機コスト」（パフォーマンス）とフライト要件のバランスをとることです。 

## アプローチ

 強引なアイデアは、これを各州が (都市、お金) のペアである州グラフとして扱うことです。 各州から、ショーを実行するか (w_i とコスト +1 でお金を増やします)、十分なお金があれば出発の飛行機に乗ることができます。 これにより、巨大な暗黙的なグラフ上で最短経路問題が生成されます。 

お金は最大 10^9 まであり、任意に増加する可能性があるため、実際には状態の数に制限はありません。 たとえ離散化されていても、各都市にはさまざまな通貨価値があり、都市間の遷移はしきい値に依存します。 これは指数関数的な爆発につながります。 

重要な観察は、正確な金額を知る必要はなく、一連の飛行を実行可能にするために所定の公演数が十分であるかどうかだけを知る必要があるということです。 パフォーマンスの候補数を固定すれば、実現可能性をチェックできます。すべてのエッジ要件が満たされるように、パスに沿って最大でその数のパフォーマンスを分散できるか?

 これは、答えに対する二分探索を示唆しています。 単調性は重要です。k 個のパフォーマンスで目的地に到達できるのであれば、任意の k' > k を使用しても可能です。 

ここで問題は、固定 k の実現可能性を確認することに移ります。 与えられた k に対して、すべての飛行費用を支払うのに十分なパフォーマンスからの資金をそのパスに沿って蓄積できるような 1 から n へのパスが存在するかどうかを知りたいと考えます。 

私たちは、最良優先伝播を使用して貪欲にシミュレーションします。各都市で、パスに沿って最適に分散された合計パフォーマンスを最大 k 回費やした後に持ち運べる最大の残りのお金を計算します。 正確なパフォーマンス分布を追跡する代わりに、都市ごとに達成可能な最良の「予算状態」を伝播し、余裕がある場合はエッジを緩和します。

これは、収集される総収入が k 個のパフォーマンスによって制限されるという制約の下で、各ノードの残りのお金を最大化しようとするグラフ緩和問題になります。 都市 n に到達できれば、k は実現可能です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | BFS の状態 (都市、お金) | 指数 | 指数 | 遅すぎる |
 | 二分探索 + グラフ上の実現可能性伝播 | O(m ログの答え) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 最小演奏回数 k を二分探索します。 パフォーマンスを追加してもどこでも利用可能なお金が増えるだけであり、到達可能性は決して低下しないため、単調性が維持されます。 
2. 固定 k について、都市 1 から開始して都市 n に到達できるかどうかを計算します。 
3. 配列を維持します`best[i]`、旅行全体で最大 k 個の合計パフォーマンスを使用しながら、都市 i に到着したときに得られる最大のお金を表します。 
4.初期化`best[1] = p + k * w_1`, なぜなら、最悪の場合、開始前にすべての公演を都市1で費やす可能性があるからです。 
5. 優先構造または繰り返しの緩和を使用して、潜在的な到達可能性の昇順に都市を処理し、常に可能な限り最高の残存資金を前進させるよう努めます。 これにより、常に最も有望な州を最初に拡張することが保証されます。 
6. コスト s の各直行便 i -> j について、次の場合`best[i] >= s`、それを横断することができます。 コストを支払った後、以下を更新します。`best[j] = max(best[j], best[i] - s + k * w_j)`。 

これは、j に到達した後も残りのパフォーマンスをどこにでも割り当てることができるが、合計キャップ k はすでにグローバルに考慮されているという考えに対応します。 
7. 改善が不可能になるまでリラクゼーションを繰り返します。 
8. もし`best[n] >= 0`の場合、k は実行可能です。 それ以外の場合はそうではありません。 

### なぜ効果があるのか

 重要な不変条件は次のとおりです`best[i]`は常に、合計で最大 k 個のパフォーマンスを使用する有効な戦略の下で、都市 i で可能な最大の残金を表します。 k 個のパフォーマンスを持つ有効なパスはすべて、この定義と一致する一連の緩和を引き起こします。また、残りの未使用のパフォーマンスはすべて、実現可能性に違反することなく常に現在のノードまたは以前のノードに割り当てることができるため、更新ルールは潜在的により良いパフォーマンスの分布を破棄することはありません。 これにより、実行可能な割り当てが存在する場合、伝播によって最終的にそれを支配する状態が再構築されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def can(n, g, w, p, k):
    best = [-1] * (n + 1)
    best[1] = p + k * w[0]

    dq = deque([1])
    inq = [False] * (n + 1)
    inq[1] = True

    while dq:
        v = dq.popleft()
        inq[v] = False

        for to, cost in g[v]:
            if best[v] < cost:
                continue
            val = best[v] - cost + k * w[to - 1]
            if val > best[to]:
                best[to] = val
                if not inq[to]:
                    dq.append(to)
                    inq[to] = True

    return best[n] >= 0

def solve():
    t = int(input())
    for _ in range(t):
        n, m, p = map(int, input().split())
        w = list(map(int, input().split()))

        g = [[] for _ in range(n + 1)]
        for _ in range(m):
            a, b, s = map(int, input().split())
            g[a].append((b, s))

        lo, hi = 0, 10**9
        ans = -1

        while lo <= hi:
            mid = (lo + hi) // 2
            if can(n, g, w, p, mid):
                ans = mid
                hi = mid - 1
            else:
                lo = mid + 1

        print(ans)

if __name__ == "__main__":
    solve()
```このソリューションでは、最初にグラフを構築し、次にパフォーマンスの数に対して二分探索を使用します。 各候補値について、`can`関数は最適なお金の伝播をシミュレートします。 重要な実装の詳細は、残りのすべてのパフォーマンスが目的地の都市で引き続き使用できるかのように各リラクゼーションを扱うことで、パス全体にパフォーマンスを明示的に分散することを回避します。 

キューベースの緩和により、SPFA の動作と同様に、ノードの最適値が向上した場合にのみノードを再訪することが保証されます。 ブール値`inq`冗長なキューの挿入を防ぎます。 

都市 1 の初期値には、k 個のパフォーマンスから得られるすべての収益がすでに含まれており、グローバル予算がノードごとに 1 つのスカラーにエンコードされます。 

## 実用的な例

 ### トレース例 (小規模な構築ケース)

 3 つの都市を考えます: 1 → 2 → 3、p = 0、w = [2, 3, 5]、エッジ 1→2 コスト 3、2→3 コスト 4、および k = 2。 

| ステップ | 都市 | ベスト[1] | ベスト[2] | ベスト[3] | アクション |
 | --- | --- | --- | --- | --- | --- |
 | 初期化 | 1 | 4 | - | - | シティ1にて2公演 |
 | リラックス1→2 | 2 | 4 | 3 | - | 4 - 3 + 2*3 = 7 |
 | リラックス2→3 | 3 | 4 | 7 | 7 | 7 - 4 + 2*5 = 13 |

 都市 3 に到達するため、k = 2 が可能です。 

このトレースは、アルゴリズムが常に残りの潜在的な収入を可能な限り最適な場所で適用できると想定して、各ステップでパフォーマンスがどのように効果的に「再割り当て」されるかを示しています。

 ## 特殊なケース

 微妙なエッジ ケースの 1 つは、パフォーマンスを行わずに目的地に到達できる場合です。 その場合、二分探索では少なくとも 1 つを強制するのではなく、正しく 0 を返す必要があります。 初期化`lo = 0`これがテストされることを保証し、k = 0 での実現可能性チェックにより、初期資金のみが正しく伝播されます。 

もう 1 つのエッジ ケースは、すべてのフライトで最大限のパフォーマンスを発揮しても獲得できる金額を超える金額が必要になる場合です。 このような場合、すべての二分探索値は失敗し、答えは -1 のままになります。 伝播関数は自然に遷移をブロックします。`best[v] < cost`横断を防ぎます。 

3 番目のエッジ ケースは、最適な戦略がすべてのショーを分散するのではなく 1 つの都市で実行する必要がある場合に発生します。 各緩和では、残りの予算のすべてが現在のノードで再割り当てできると想定されているため、収入の集中が常に暗黙的に許可されるため、定式化はこれを処理します。
