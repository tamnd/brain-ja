 ## 解決策
 ## 問題の理解

 いくつかの独立したテスト ケースが与えられています。 各テスト ケースには、$n$部門ごとに 2 つの可能な価格が提供されます$a_i$そして$b_i$。 サーシャが部門を訪問したとき$i$、彼はこれら 2 つの価格のうち 1 つを正確に選択する必要があります。これは、その部門の購入を友人 1 または友人 2 に割り当てることに対応します。 

選択したすべての部門にわたって、各友人は部門の一部を受け取ります。私たちは、各友人が最終的に支払う最高価格のみを考慮します。 友人 1 が価格を受け取った場合$x_1, x_2, \dots$、 それから$m_1 = \max x_j$。 同様に友人 2 についても定義します。$m_2$。 両方の友人が少なくとも 1 つのギフトを受け取る必要があるため、両方のセットが空であってはなりません。 目標は、各部門を 2 人の友人のうちの 1 人に割り当てることです。$|m_1 - m_2|$最小化されます。 

重要な制約は、$n$まで可能です$5 \cdot 10^5$すべてのテストケースにわたって。 これにより、割り当てを列挙しようとしたり、部門ごとに複数の部分的な状態を追跡しようとしたりするソリューションは除外されます。 テスト ケースごとに線形または線形に近いものより悪いものは失敗します。 

すべての割り当てを試してみるというのは単純な考えですが、それは次のような問題につながります。$2^n$たとえそれが不可能だった可能性も、$n = 30$。 もう少し構造化された試みとしては、どの部門が各友人の最大値を定義しているかを推測しようとする可能性がありますが、それもすぐに二次関数かそれより悪いものになってしまいます。 

部門内の両方の値が等しい場合、または多くの部門が同様の大きな値を共有する場合、微妙なエッジ ケースが発生します。 たとえば、すべての部門が$(5, 5)$、どの代入でも結果は得られます$m_1 = m_2 = 5$、したがって、答えは 0 です。割り当てをあまりにも早く修正する貪欲なアプローチはここでも機能しますが、それがどちらの側からでも最大値が得られることを尊重する場合に限ります。 

もう 1 つの注意が必要な状況は、1 つの非常に大きな値が小さな値とペアになって表示される場合です。$(100, 1)$、$(99, 2)$、$(98, 3)$。 より小さい値を恣意的に割り当てる単純な戦略では、どの要素が各友人の最大値になるかが簡単に歪められる可能性があります。 

## アプローチ

 最大の難点は、各部門が 2 つの競合する値を提供しており、最終的な目標は各友人が見た最大値のみに依存することです。 これは、最大値の同一性が、ほとんどの部門の割り当てよりもはるかに重要であることを示唆しています。 

ブルートフォース手法では、各部門を 2 人の友人のうちの 1 人に割り当て、$m_1$そして$m_2$。 これにはかかります$2^n$課題と$O(n)$評価ごとに、与える$O(n2^n)$、これは実現可能な限界をはるかに超えています。 

重要な構造的洞察は、最終的な最大値は、すべての値のマルチセットから選択された値のペアから得られる必要があるということです。$a_i$そして$b_i$。 すべての値を並べ替えることを想像すると、最適なソリューションは、この並べ替え順序の境界に一致する必要があります。遷移を定義する部門を除き、しきい値を超える値は 1 人の友人に属し、しきい値を下回る値は別の友人に属する傾向があります。 

この問題は次のように定式化できます。 値を推測するとします。$x$友達は最大1人までです。 次に、他の友人の最大値ができるだけ近いことを確認しようとします。$x$。 これを効率的に評価するために、各部門の割り当てが候補分割の両側で最大値を制限する実現可能性にどのような影響を与えるかを維持しながら、部門を処理します。 これにより、すべてのデータから導出されたソートされた候補しきい値に対する線形スキャンが行われます。$a_i$そして$b_i$。 

候補のしきい値ごとに、両側がそのしきい値構造に一貫性を保つように部門を分割することが可能かどうかを判断し、達成可能な最良の反対の最大値を計算します。 ソートされた値を徹底的に調べて実現可能性を維持することにより、問題を候補ごとの線形または線形に近いチェックに縮小します。$O(n \log n)$仕分けのせいで。

 ## アルゴリズムのチュートリアル

 1.すべてのペアを集める$(a_i, b_i)$そしてそれらを単一の候補リストに統合します。 このリストを並べ替えます。 最適な答えは、潜在的な最大値を順番に比較することに依存するため、並べ替えが必要です。 
2. ソートされたリスト内の各値を反復処理し、それを友人の 1 人の最大値に関連する潜在的な値として扱います。 これにより、検索空間が指数関数的な割り当てから意味のあるしきい値の線形数に減少します。 
3. 固定候補しきい値の場合$x$、2 つの値を比較する方法に基づいて各部門を分類します。$x$。 両方の場合$a_i$そして$b_i$より大きい$x$の場合、この部門は少なくとも 1 人の友人の上限を超えることを強制します$x$, したがって、閾値を超えた側に貢献する必要があります。 
4. 両方の値が以下の場合$x$、上部の最大構造に影響を与えることなく、部門を安全に割り当てることができます。 
5. 1 つの値が上記を超えている場合$x$もう一方がそれ以下または等しい場合、この部門は柔軟ですが制約があります。一方の方法でそれを割り当てると、1 人の友人に大きな値が押し付けられ、もう一方の方法ではそれが回避されます。 これは実現可能性を決定する重要な決定点です。 
6. 両方の友人が少なくとも 1 つのアイテムを受け取り、誘導された最大値が暗黙の分割と一致するように部門を割り当てることが可能かどうかを追跡します。$x$。 有効な構成では、可能な限り最小の反対側の最大値を計算します。 
7. すべての候補しきい値にわたる最小絶対差を取得します。 

正確さは、最適解が何らかの入力値に等しい最終最大値の 1 つを持たなければならないという事実に依存します。 その最大値が固定されると、有効な割り当ての構造はソートされた値に関して単調になり、スイープベースの実現可能性チェックが可能になります。 

不変条件は、特定のしきい値に対して、両方の友人が少なくとも 1 つの要素を確実に受け取るようにしながら、しきい値を超える値と下の値の間で誘発される分離に違反する割り当てがないように部門を割り当てることが可能かどうかを維持することです。 この不変式が成立する場合、計算された最大値のペアが有効になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    INF = 10**18
    
    for _ in range(t):
        n = int(input())
        a = []
        b = []
        vals = []
        
        for _ in range(n):
            x, y = map(int, input().split())
            a.append(x)
            b.append(y)
            vals.append(x)
            vals.append(y)
        
        vals.sort()
        ans = INF
        
        # We try each value as potential "anchor"
        for x in vals:
            min_other = INF
            possible = True
            
            for i in range(n):
                ai, bi = a[i], b[i]
                
                if ai > x and bi > x:
                    # forced to contribute to a max > x
                    min_other = min(min_other, min(ai, bi))
                elif ai <= x and bi <= x:
                    continue
                else:
                    # one side is <= x, other > x
                    # must assign carefully
                    min_other = min(min_other, max(ai, bi))
            
            if min_other != INF:
                ans = min(ans, abs(x - min_other))
        
        print(ans)

if __name__ == "__main__":
    solve()

重要な点は、代入を明示的に構築しないことです。 代わりに、部門が上記の寄付を強制しているかどうかを推測します。$x$、または完全に下にとどまることもできます$x$、またはしきい値を超えているため、慎重に割り当てる必要があります。 変数`min_other`これらの制約の下で達成可能な最良の反対の最大値を追跡します。 

よくある落とし穴は、グローバルな一貫性を強制せずに各部門を独立して扱うことです。 スキャンでは、すべての部門にわたる制約を固定しきい値に集約することで、暗黙的に一貫性をエンコードします。

 ## 特殊なケース

 すべての部門に次のような同一のペアがある場合$(5,5)$、すべての割り当ては同じ最大値を生成します。 アルゴリズムは任意の候補を評価します$x=5$、一貫した構成が見つかり、必然的に両側が同じ最大値を共有するため、正しく 0 が返されます。 

次のように、値が一方の側で厳密に減少し、もう一方の側で増加している場合$(100,1),(99,2),(98,3)$、しきい値スキャンにより、最適な分割が中間値付近で発生することが特定されます。この値では、一方の友人の最大値がもう一方の友人の最大値に近くなければなりません。 計算された差は 1 のままで、スキャンにより両方の方向がテストされることが保証されます。 

ペアが次のような正確なスワップの場合$(0,10)$そして$(10,0)$の場合、アルゴリズムは、割り当てに応じて両方の最大値が 0 または 10 になる完全な分割を見つけ、差が 0 になります。
