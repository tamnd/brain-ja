 ## 問題の理解

単純な試みとしては、貪欲に一意の値を割り当ててから、XOR 制約の違反を修正しようとする可能性があります。 各セルが多くの重複に参加しているため、これは失敗します。$4 \times 4$そのため、ローカルな修正が伝播し、すぐに矛盾が生じます。

本当の課題は、制約が単純な方法ではローカルではなく、グリッド全体に構造化された線形依存関係を課すことを認識することです。 

## アプローチ

 ブルートフォースの観点は、各セルを変数として扱い、それぞれのセルを変数として扱うことです。$4 \times 4$XOR 方程式系としてのサブグリッド条件。 各ウィンドウに対して 2 つの XOR 等式を適用し、おおよそ次のようになります。$O(nm)$制約。 これを直接解決するには、ガウス消去法が必要になります。$GF(2)$最大 40,000 個の変数を持つシステムでは、非常に遅すぎます。 

重要な観察は、この形式の XOR 制約が分離可能な構造を強制することです。つまり、グリッドは行と列からの独立した寄与に分解でき、より具体的には、座標の最後の 2 ビットによって完全に決定されるパターンに分解できます。 

この条件は基本的に、シフトするときのことを示しています。$2 \times 2$グリッド全体でブロックを分割する場合、XOR の差は一貫性を保つ必要があります。 これにより、グリッドは値の差が座標の小さな近傍のみに依存する関数のように動作するようになり、行インデックスと列インデックスのビット単位のエンコードを使用して値を構築することが推奨されます。

 ## アルゴリズムのチュートリアル

 1. 各セルの割り当て$(i, j)$ビット シフトと XOR を使用して行インデックスと列インデックスを組み合わせて形成される値。 行ビットと列ビットが干渉しないように分離するのが便利な選択です。 
2. 各行インデックスについて$i$、それを上位ビットにシフトして、行の ID が列から独立した範囲を占めるようにします。 これにより、異なる次元間での XOR キャンセルが防止されます。 
3. 各列インデックスについて$j$、列の変化が各行ブロック内で完全に区別できるように、下位ビットに保持します。 
4. 次を使用してグリッドを塗りつぶします。$B[i][j] = (i \ll 7) \oplus j$。 定数シフトは、列ビットとの重複を避けるのに十分な大きさだけが必要です (固定の安全なオフセットは機能します。$m \le 200 < 2^8$）。 
5. マトリックス全体を出力します。 すべての値は一意であるため、個別の値の数は正確に$n \cdot m$、これは可能な最大値です。 

### なぜ効果があるのか

 XOR 制約は次の範囲で線形です。$GF(2)$, そのため、行依存部分と列依存部分を別々に分析できます。 行情報を上位ビットにエンコードし、列情報を下位ビットにエンコードすることにより、すべての XOR がすべてのビットに対して行われます。$2 \times 2$または$4 \times 4$ブロックは独立した行と列の寄与に分割されます。 必要な等式の各辺には、行インデックスの同じマルチセットと列インデックスの同じマルチセットが含まれるため、それらの XOR は正確に一致します。 これにより、期間間の干渉が防止され、すべての制約が同時に保持されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        
        shift = 10  # enough since m <= 200
        
        cnt = n * m
        print(cnt)
        
        for i in range(n):
            row = []
            base = i << shift
            for j in range(m):
                row.append(str(base ^ j))
            print(" ".join(row))

if __name__ == "__main__":
    solve()
```このソリューションでは、各行を独立して直接構築します。 重要な実装の詳細は、行と列の寄与が重複しないことを保証する固定ビット シフトです。 10 のシフトで十分です。$2^{10} = 1024$これは可能な最大列インデックスを超えているため、XOR によって行部分と列部分の間で意図しない衝突が発生することはありません。 

出力数は常に$n \cdot m$、すべてのエントリが個別であるため、これが最適です。

import sys, io

def run(inp: str) -> str:

 ## 特殊なケース

 最小有効グリッド サイズ$4 \times 4$制約が最も厳しいケースです。 この構造では次のような値が割り当てられます。$0,1,2,\dots$行ブロックごとにシフトされます。 この最小のシナリオでも、各行が固定の高ビット署名に寄与するため、すべてのセルは一意のままであり、XOR 制約が保持されます。 

のために$4 \times 6$グリッドでは、同じ行をシフトすることで、列を拡張しても衝突が発生しません。 各行は上位ビットで独立したままであるため、重複する内部の異なる行間で干渉は発生しません。$4 \times 4$窓。 

複数のテスト ケースの場合、各グリッドは独立して生成されます。 グローバル状態が使用されないため、キャリーオーバー効果はなく、各出力ブロックは独立して有効なままになります。
