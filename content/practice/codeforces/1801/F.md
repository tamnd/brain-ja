 ## 解決策
 ## 問題の理解

 私たちは n 次元のチョコレートバーを与えられています。 各次元に沿って、バーはすでに個別の単位に分割されています。次元 i については、`a_i`単位。 Vasya さんは、これらの既存の分割に沿ってチョコレートをさらにカットして、少なくとも生産できるようにしたいと考えています。`k`個。 セグメントの数を選択できます`b_i`各寸法に沿って切断するには、`1 <= b_i <= a_i`。 切断後、結果として得られる各ピースには、床の分割の積によって与えられる多数の元のスライスが含まれます。`floor(a_1 / b_1) * ... * floor(a_n / b_n)`。 一枚一枚にボリュームがある`1 / (a_1 * ... * a_n)`, したがって、1 片の体積は、この製品をスライスの合計数で割ったものになります。 Vasya は、最小部分の体積を次の値に乗じて最大化したいと考えています。`k`。 

入力により寸法が得られます`n`(最大100個)、必要最小限の個数`k`(最大 10^7)、および配列`a`サイズの`n`(それぞれ最大 10^7)。 出力は浮動小数点数、つまり最小のピース時間で可能な最大ボリュームです。`k`。 

制約は次のことを教えてくれます`n`中程度ですが、`a_i`そして`k`非常に大きくなる可能性があります。 これにより、考えられるあらゆる組み合わせを試みる単純な総当りアプローチが排除されます。`b_i`、組み合わせの合計数は`a_1 * a_2 * ... * a_n`、それは天文学的に大きくなる可能性があります。 また、整数のオーバーフローも慎重に処理する必要があります。`a_i`10^18 を超える場合があります。 

エッジケースには、取得が不可能な状況が含まれます。`k`ピース、例:`n=1, a=[5], k=6`。 ここで、どの選択肢を選んでも、`b_1`生成されるピースは最大で 5 つであるため、正しい答えは 0 です。もう 1 つの微妙な点は、床の分割の価値が失われるため、ボリュームを最大化すると、一部の寸法に沿ってカット数が少なくなることが望ましい場合があることです。 たとえば、`a=[4,7]`そして`k=7`、カットを均等に分散すると、より大きな寸法に沿ってカットを集中させる場合とは異なる最小体積が得られます。 

## アプローチ

 ブルートフォースアプローチは概念的には単純です。すべての組み合わせを試してください。`b_1`を通して`b_n`満足するもの`1 <= b_i <= a_i`、計算する`floor(a_1 / b_1) * ... * floor(a_n / b_n)`を選択し、少なくとも次の結果が得られる組み合わせを選択します。`k`分割して最大化する`k * volume`。 これは非常に小さい場合に機能します`a_i`そして`n`、しかし、`n=100`そして`a_i=10^7`、組み合わせの数は信じられないほど多くなります。 すべて生成しても`b_i`10^7 ほどの大きさの単一次元の場合、コストが高すぎます。 

重要な観察は、実際には可能な限り最大の値を探しているということです。`x`少なくとも 1 つの部分の最小スライス数が 1 つ以上になるように、チョコレートを細かく切ることができます。`x`。 この問題は、候補者の検索として再構成できます。`x`、整数を見つけることができますか`b_i`そのような`floor(a_1 / b_1) * ... * floor(a_n / b_n) >= x`そして`b_1 * ... * b_n >= k`? ボリュームは次のように変化するため、`floor(a_i / b_i)`、二分探索を使用できます`x`。 

それぞれについて`x`、最大値を計算します`b_i`それは保証します`floor(a_i / b_i) >= t`は簡単です:`b_i <= a_i // t`。 次に、これらの積が正しいかどうかを確認する必要があります。`b_i`少なくとも到達できる限界`k`。 これにより、問題は「中間者会議」つまり貪欲なアプローチ、すなわち実現可能な最大値を乗算するアプローチに縮小されます。`b_i`それぞれの次元について、どちらかに到達するまで`k`または排気オプション。 

洞察としては、問題は次元に沿って分離され、整数の除算を使用して床関数を逆にできるということです。 最小ピースサイズの候補を設定したら`x`、各次元はセグメントの最大数に独立して寄与します。`b_i`。 次に、自社の製品が適合するかどうかを確認します。`k`。 二分探索により、可能な最大値に収束することができます`x`効率的に。

 ## アルゴリズムのチュートリアル

 1. スライスの総数を計算します。`total = a_1 * ... * a_n`。 もし`total < k`、を持つことは不可能なので、すぐに0を出力します。`k`個。 
2. 最小スライス数の二分探索範囲を設定します。`x`。 下限は 0、上限は`max(a_i)`最小ピースには、次元に沿ってこれより多くのスライスを含めることはできないため、`a_i`。 
3. 二分探索範囲が空ではない間に、`mid = (low + high + 1) // 2`。 これ`mid`は、最小のピースの候補最小スライス数を表します。 
4. 各次元について`i`、計算する`max_bi = a_i // mid`。 これは、寸法に沿って行うことができるカットの最大数です。`i`候補の最小個数に違反することなく。 もし`max_bi == 0`、候補者`mid`大きすぎます。 この次元に沿ってスライスを 1 つも取得することはできません。 
5.積を計算する`prod_b`の`max_bi`あらゆる次元にわたって。 いずれかの時点で製品が超過した場合`k`、到達できるかどうかだけを気にしているので、早めに停止できます。`k`。 
6. もし`prod_b >= k`、候補者`mid`実現可能なので、設定します`low = mid`。 それ以外の場合は、設定します`high = mid - 1`。 
7. 二分探索が完了したら、`low`ピースあたりの最大達成可能な最小スライス数が含まれます。 最終的な体積を次のように計算します。`volume = (low / a_1) * ... * (low / a_n) * k`、これを単純化すると、`volume = low * k / total_slices`。 
8. 十分な精度でボリュームを出力します。 

なぜ機能するのか: 二分探索は、どのような結果であっても不変条件を維持します。`x <= low`達成可能であり、何でも`x > high`そうではありません。 独立機関による実現可能性の確認`b_i`境界は正しいです。フロア分割により、次のことが保証されます。`b_i <= a_i // x`、どのピースもこれより少ないことはありません`x`その次元に沿ってスライスします。 境界を乗算すると、少なくとも次の値に到達することが保証されます。`k`個。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    
    total_slices = 1
    for ai in a:
        total_slices *= ai
        if total_slices >= 1e18:  # cap to prevent overflow
            break
    if total_slices < k:
        print(0)
        return

    low, high = 0, max(a)
    while low < high:
        mid = (low + high + 1) // 2
        prod = 1
        for ai in a:
            prod *= ai // mid
            if prod >= k:
                break
        if prod >= k:
            low = mid
        else:
            high = mid - 1

    minimal_slices = low
    volume = minimal_slices * k / total_slices
    print(f"{volume:.12f}")

if __name__ == "__main__":
    main()
```ソリューションはまず次のことを確認します。`k`スライスの総数でも可能です。 二分探索により、最小部分が確実に最大化されます。 乗算する`ai // mid`各次元でフロア分割制約が満たされることが保証され、早期停止によりオーバーフローが防止されます。 最後にコンピューティング`minimal_slices * k / total_slices`スケールされたボリュームを与える`k`。
