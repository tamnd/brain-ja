 ## 解決策
 ## 問題の理解

 単一の整数が与えられます$n$、そしてそれを 3 つの正の整数の合計として表す必要があります。$a, b, c$。 追加の制限は、これら 3 つの数値はいずれも 3 で割り切れないことです。有効な 3 倍はどれも受け入れられるため、制約を満たす以外の最適化基準はありません。 

構造的な観点から見ると、これは建設的な分解の問題です。 最小値や最大値を検索しているのではなく、モジュラー制約の下で 1 つの実現可能なパーティションだけを検索しています。 これは、ソリューションが検索ではなくモジュラー演算に依存する必要があることをすぐに示唆しています。 

入力制約$3 \le n \le 10^9$トリプルの強引な列挙を排除します。 2 つの変数を固定して 3 番目の変数を導出しようとしても、検索空間は 2 次になります。$n$、これは大きすぎます。 したがって、問題は定数時間の構築に帰着する必要があります。 

次の場合、微妙なエッジケースが発生します。$n$小さいです。 例えば、$n = 3$可能な唯一のパーティションを強制します$1,1,1$3 で割り切れるものがないため、これは機能します。もう 1 つの興味深い状況は次のような場合です。$n \equiv 0 \pmod{3}$、均等に分割するような素朴な試みなので、$n/3, n/3, n/3$各部分は 3 で割り切れるため、すぐに失敗します。 

## アプローチ

 ブルートフォース戦略では、すべてのペアが列挙されます。$(a, b)$そのような$a \ge 1, b \ge 1$、計算する$c = n - a - b$を実行し、3 つすべてが正で 3 で割り切れないかどうかを確認します。これは問題の定義を直接テストするため論理的に機能しますが、次のことが必要です。$O(n^2)$最悪の場合にチェックしますが、それは不可能です$n$まで$10^9$。 

重要な観察は、制約が 3 で割り切れるかどうかのみに依存しており、これは完全に周期的な 3 を法とするということです。有効な値を検索する代わりに、剰余 0 mod 3 を回避する固定パターンを使用して値を構築できます。 

3 で割り切れない整数は、1 または 2 のモジュロ 3 に完全に合同な整数です。したがって、それぞれの整数を確認するだけで済みます。$a, b, c$これら 2 つの剰余クラスに分類されますが、合計すると$n$。 値の選択には完全な自由があるため、そのうち 2 つを修正して 3 つ目を導き出し、残りが制約に違反する場合はわずかに調整できます。 

標準的な構成では、1 と 2 など、3 の倍数ではない 2 つの小さな値を選択し、それに応じて 3 番目の値を調整します。 設定すると$a = 1$、$b = 1$、 それから$c = n - 2$。 さて、唯一の問題は、$c$3 で割り切れる場合は、3 の倍数にならないように、前の選択肢の 1 つをわずかにシフトします。3 を法とする剰余クラスは小さく、加算で閉じられるため、一定数の調整で常に十分です。 

これにより、問題は無制限の検索から一定数の算術ケースに減ります。

 ## アルゴリズムのチュートリアル

 モジュラー推論を使用して直接答えを構築します。 

1.修正から始めます$a = 1$。 これにより保証されます$a$は正であり、3 で割り切れません。 
2.修正$b = 1$同じ理由で。 この時点で合計2台使用しました。 
3. コンピューティング$c = n - 2$。 これにより合計条件が保証されます$a + b + c = n$まさに当てはまります。 
4. かどうかを確認します。$c$は 3 で割り切れます。そうでない場合は、$(1, 1, c)$はすでに有効です。 
5. もし$c$は 3 で割り切れます。置き換えて構造を調整します。$b = 2$そして$a = 1$、与える$c = n - 3$。 このシフトにより、剰余クラスを変更しながら合計が保存されます。$c$、有効な場合は 3 で割り切れないことを確認します。$n$。 

これらの小さな調整で十分な理由は、1 または 2 のシフトによって剰余クラス モジュロ 3 が制御された方法で変更され、剰余 0 を回避するだけで済むためです。 

### なぜ効果があるのか

 すべての整数は、3 を法とする 3 つの剰余クラスのいずれかに正確に分類されます。$a$そして$b$、そして私たちは保証します$c$から派生した$n$小さな定数を減算することによって。 異なる剰余を介して 2 または 3 サイクルを減算するため、これらの定数オフセットの少なくとも 1 つにより有効な$c$これは、解が存在し、私たちの構築が常に解を見つけることを保証します。

唯一の微妙な点は、ポジティブさを確保することです。 のために$n \ge 3$、 両方$n - 2$そして$n - 3$少なくとも 1 のままであるため、両方のブランチは安全です。 条件付きチェックにより、正の制約​​を破ることなく、唯一の問題のある残基ケースを回避することが保証されます。

 ## 特殊なケース

 のために$n = 3$、アルゴリズムが生成する$a = 1, b = 1, c = 1$。 これらはいずれも 3 で割り切れないため、調整分岐に入らなくても、結果はすぐに正しいものになります。
