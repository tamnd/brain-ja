 ## 解決策
 ## 問題の理解

 この問題は本質的に循環モジュラー算術演算とサブセット和に関するものです。 _n_ 個のステーションの円軌道があり、各ステーションは _m_ マイル離れています。 キャプテン・ビトニクスは、それぞれ一定の容量を持つ一連の燃料タンクを持っています。 戦車を使用すると、時計回りまたは反時計回りに正確にその数マイル移動します。 ミッションは、燃料タンクのサブセットがどれだけ破壊された場合、一連の燃料タンク使用後にステーションに正確に着陸するのを妨げるかを判断することです。 

言い換えると、目標は、どちらの方向に移動しても残りのタンクを組み合わせても総距離がステーション間の距離と整数のステップ数 (つまり、_n × m_ の倍数) の倍数にならないようにタンクのサブセットをカウントすることです。 これはモジュラー演算を使用して簡略化できます。使用済みタンク容量の合計がモジュロである場合、パトロールは有効です。`n * m`すべての距離は _m_ の倍数であるため、 は _m_ で割り切れるか、モジュロ _n_ で割り切れます。 したがって、各タンクの体積を法 _n_ で減らし、このモジュール空間で問題を解決できます。 

制約により、_n_ は最大 1000、戦車は最大 10,000 個存在できることがわかります。 サブセットは 2^10000 あるため、すべてのサブセットを直接試すことは不可能です。 これは、すべてのサブセットに対するブルート フォースは実行不可能であることを意味します。 エッジ ケースには、すべてのタンクが _n_ の倍数であるか、モジュラーの剰余が空間全体をカバーする状況が含まれます。 モジュラーリダクションを使用しない不注意な合計は失敗します。 

たとえば、`n = 3`、`m = 60`、タンク`[3, 6, 9]`、モジュロ 3 のすべての組み合わせは 0 であるため、いつでも開始ステーションに戻ることができます。 モジュロ _n_ を減らさずに素朴に距離を合計すると、サブセットがパトロールの完了を妨げていると誤って結論付ける可能性があります。 

## アプローチ

 ブルートフォースアプローチは、戦車の 2^t 個のサブセットをすべて考慮し、サブセットごとに、残りの戦車の組み合わせが有効な哨戒を可能にするかどうかを確認することです。 これはすべての可能性をチェックするので原理的には正しいですが、明らかに遅すぎます。t が 10,000 までの場合、2^10000 の演算は天文学的に大きくなります。 

重要な洞察は、問題は、ゼロ モジュロ _n_ を生成できないサブセットの数を数えることに帰着するということです。 各タンクはどちらの方向でも使用できるため、タンクを追加することは、その体積を法 _n_ で加算または減算することと同じです。 これはまさに、± 符号を使用して、合計が _n_ で割り切れるサブセットの数を数えるという古典的な問題です。 これは、モジュール和に関する動的計画法を使用して効率的に解決できます。 

DP 配列を定義します`dp[r]`± 方向のタンクのサブセットを使用して、剰余 _r_ modulo _n_ を達成する方法の数を表します。 各戦車は加算と減算の両方を考慮して DP を更新します。 最後に、`dp[0]`有効なパトロールを完了できるサブセットの数を示します。 部分集合の総数は 2^t であるため、答えは次のようになります。`2^t - dp[0]`、モジュロ 10^9 + 7。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^t × t × n) | O(n) | 遅すぎる |
 | モジュロ和の DP | O(t × n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 局数の読み取り`n`、駅間距離`m`、タンクの数`t`、タンク容量が続きます。 
2. 各タンクのモジュロを削減します。`n`。 _n_ を法とする合計のみがステーションの位置合わせを決定するため、これで十分です。 
3. DP 配列を初期化する`dp`サイズの`n`すべてゼロで設定します`dp[0] = 1`空集合の合計を表します。 
4. 各タンクを繰り返し処理します。 現在の剰余ごとに`r`で`dp`、タンクを両方向に追加します。`(r + tank) % n`そして`(r - tank) % n`。 上書きを避けるため、更新用に新しい配列を保持します。 
5.すべてのタンクを処理した後、`dp[0]`n を法として合計が 0 になるサブセット (空を含む)、つまりパトロールを許可するサブセットの数をカウントします。 
6. コンピューティング`2^t - dp[0]`モジュロ 10^9 + 7。これは、パトロールを妨げるサブセットの数です。 
7. 結果を出力します。 

機能する理由: 各タンクは、すべての有効な組み合わせをカバーし、総和法 n にプラスまたはマイナスの影響を与えることができます。 DP は、達成可能なすべての剰余を段階的に正確にカウントします。 不変条件は、i 個のタンクを処理した後、`dp[r]`最初の i タンクの組み合わせの数が n を法とする剰余を生成するかどうかを正確にカウントします。 モジュロを使用すると、数値が小さく保たれ、演算が実行可能になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n, m, t = map(int, input().split())
    tanks = list(map(int, input().split()))
    
    tanks = [x % n for x in tanks]
    
    dp = [0] * n
    dp[0] = 1  # empty set
    
    for tank in tanks:
        ndp = dp[:]
        for r in range(n):
            ndp[(r + tank) % n] = (ndp[(r + tank) % n] + dp[r]) % MOD
            ndp[(r - tank) % n] = (ndp[(r - tank) % n] + dp[r]) % MOD
        dp = ndp
    
    total_subsets = pow(2, t, MOD)
    answer = (total_subsets - dp[0]) % MOD
    print(answer)

if __name__ == "__main__":
    solve()
```この解決策は、まずタンクを法 n で減らし、剰余カウントの DP を初期化し、加算と減算の両方でそれを繰り返し更新します。 別のものを使用する`ndp`配列は、単一の反復内での二重カウントを防ぎます。 最終計算では、制限内に収まるように、合計からパトロールを有効にするサブセットの数を 10^9 + 7 を法として減算します。 

## 実用的な例

 サンプル 1:

 入力:```
7 6 5
5 4 12 6 5
```| ステップ | タンク | DP 更新 (残りカウント) |
 | --- | --- | --- |
 | 初期化 | - | dp[0]=1 |
 | 5 | +5、-5 | dp[5]=1、dp[2]=1、dp[0]=1 |
 | 4 | +4、-4 | dp[0]、dp[1]、dp[2]などを更新します。 
| 12->12%7=5 | +5、-5 | ... |
 | 6->6%7=6 | +6、-6 | ... |
 | 5 | +5、-5 | ... |

 すべてのタンクの後、dp[0]=26。 サブセットの合計 = 2^5 = 32。答え = 32 - 26 = 6。 

これは、DP が n を法とする達成可能な合計を正しくカウントし、サブセット全体から減算すると破壊的なサブセットの数が得られることを示しています。 

カスタム入力:```
3 1 3
1 2 3
```ここで、タンクのモジュロ 3 は [1,2,0] です。 DP は、3 を法として 0 に達する合計をカウントします。減算すると、パトロールを妨げるサブセットの数が得られます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(t × n) | 各タンクは、両方向を考慮して n 個の DP エントリを更新します。 |
 | スペース | O(n) | DP 更新用にサイズ n の 2 つの配列を維持します。 |

 n ≤ 1000 および t ≤ 10,000 の場合、t × n ≤ 10^7 の演算は 2 秒以内で快適に実行されます。
