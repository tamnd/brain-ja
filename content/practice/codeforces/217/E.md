 ## 解決策
 ## 問題の理解

 DNA 文字列から始めます。 各突然変異は、連続したセグメントを選択し、そのセグメントを所定の位置に保持し、その直後に変換されたコピーを挿入します。 

選択したセグメントが`x1 x2 x3 x4 x5 x6`挿入されたコピーは`x2 x4 x6 x1 x3 x5`突然変異は次々に適用されます。 最終的な DNA は天文学的に大きくなる可能性がありますが、必要なのは最初の DNA だけです`k`文字。 

制約は、問題について私たちが考えなければならない方法を完全に変えます。 元の DNA の長さと`k`どちらも最大です`3 · 10^6`したがって、出力だけで 300 万文字が含まれる可能性があります。 一方、変異の数はわずか`5000`。 

直接シミュレーションすることは不可能です。 単一の突然変異によって、すでに長さが巨大なセグメントが複製される可能性があり、何千もの突然変異が発生すると、DNA の長さは明示的に保存できる長さを超える可能性があります。 

重要な観察は、最終的な DNA 全体が必要になることは決してないということです。 最初のそれぞれについて決定する必要があるだけです。`k`元のキャラクターが最終的にその位置を占めることになります。 

見逃しやすい状況がいくつかあります。 

コピーされたブロックが最初のブロックを完全に超えていると仮定します。`k`ポジション。 そうすれば、たとえそれが何百万もの文字を複製したとしても、その突然変異は答えにまったく影響を与えることはできません。 

奇数の長さのセグメントに突然変異が作用すると仮定します。 変換されたコピーには、最初に偶数インデックスの要素がすべて含まれ、次に奇数インデックスの要素がすべて含まれます。 コピーされた位置をソースにマッピングする不用意な式は、2 つのグループのサイズが異なるため、奇数の長さで失敗することがよくあります。 

後の多くの突然変異が、それ自体が以前の突然変異によって作成された文字を複製すると仮定します。 位置の正しいソースは、元の文字ではなく、別の生成された位置である可能性があります。 ソースをすぐに解決しようとするソリューションでは、誤った答えが生成されます。 

## アプローチ

 強引なアイデアは単純明快です。 DNA 配列全体を保持し、文字通りすべての突然変異を実行し、最後に最初の配列を出力します。`k`文字。 

突然変異自体は、その長さが現在の DNA サイズに比例するセグメントをコピーする可能性があります。 DNA の長さは操作のたびに増加するため、総作業量はすぐに膨大になります。 結果の文字列を保存することさえ不可能です。 

解決策は、プロセスを逆にすることです。 

に作用する 1 つの突然変異を考えてみましょう`[l, r]`。 In the sequence *after* the mutation, the newly inserted block occupies positions`[r + 1, r + (r - l + 1)]`。 

過去に遡ると、それらの位置はまさに消滅する位置です。 

挿入されたブロック内の位置は失われません。 元のセグメントのどの位置でそれが生成されたのかが正確にわかります。 したがって、逆のプロセス中に、コピーされた位置からそのソース位置までの親ポインターを記録できます。 

ここで、ミューテーションを最後から最初に処理することを想像してください。 

常に、処理済みの突然変異の挿入ブロックを削除した後にまだ存在する位置のみを考慮します。 これらの生き残ったポジションは、`1`に`current_length`。 

突然変異の場合`[l, r]`、挿入されたブロックはランクから始まります`r + 1`現在生き残っているポジションの中には。 繰り返し削除していきます`(r + 1)`-th 番目の生存ポジションを内部の適切なソース ランクに接続します`[l, r]`。 

セグメント ツリーには、各範囲にどれだけの生き残ったポジションが残っているかが保存されます。 これにより、生存者の中で特定のランクを持つポジションを見つけることができます。`O(log k)`時間。 

最初のそれぞれの`k`ポジションは最大 1 回削除されるため、削除の合計数は最大で`k`。 これが、このソリューションが適合する決定的な理由です。 

逆処理のアイデアとランクベースの削除戦略は、受け入れられているソリューションの背後にある中心的な観察です。 citeturn2view0

 | 最適 | O(k log k) | O(k) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. レットポジション`1 ... k`最初のものを表す`k`最終的な DNA の位置。 

2. すべての位置が最初から有効なセグメント ツリーを構築します。 各葉には格納されます`1`。 

3. 変異を最後から最初に処理します。 

4. しましょう`len = r - l + 1`。 

5. もし`r >= current_alive_count`、この突然変異は最初の位置の間のどの位置にも影響を与えることはできません。`k`今でも重要なポジション。 スキップしてください。 

6. それ以外の場合、挿入されたブロックはランクから始まります`r + 1`生きている立場の中で。 

7. コピーされた文字を、突然変異によって生成された順序どおりにスキャンします。 

まず偶数の位置`[l, r]`、

 次に、の奇数の位置`[l, r]`。 

8. コピーされた各文字について:

 ランクのある生きているポジションを見つけて削除します`r + 1`。 挿入されたブロックに属する 1 つの位置です。 

内部の適切なソースランクに対応する生存位置を見つけます`[l, r]`。 

親ポインタを削除された位置からソース位置まで保存します。 

9. すべての突然変異が処理された後、すべての位置が親ポインターを持つか、元の文字に直接対応します。 

10. から位置をスキャンします`1`に`k`。 

位置に親がない場合は、元の DNA から次の文字を割り当てます。 

それ以外の場合は、その親のすでに計算された文字をコピーします。 

11. 結果の文字列を出力します。 

### なぜ効果があるのか

 ミューテーションを逆方向に処理する場合、生成されたすべての位置は、それを作成したミューテーションが反転されたときに正確に削除されます。 

削除された位置は、そのキャラクターの出身ランクに関連付けられます。 後の突然変異が最初に処理されるため、そのソース ランクはすでに初期の DNA 状態の正しい位置を参照しています。 

すべての逆転の後、生き残った位置は正確に元のキャラクターの順序になります。 削除されたすべての位置は、直接的または間接的に、これらのオリジナルのいずれかを指します。 

したがって、すべての最終位置は、順方向突然変異プロセスでそれを生成した文字を正確に受け取ります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    k = int(input())
    n = int(input())

    L = [0] * n
    R = [0] * n

    for i in range(n):
        l, r = map(int, input().split())
        L[i] = l
        R[i] = r

    size = 1
    while size < k:
        size <<= 1

    seg = [0] * (2 * size)

    for i in range(k):
        seg[size + i] = 1

    for i in range(size - 1, 0, -1):
        seg[i] = seg[i << 1] + seg[i << 1 | 1]

    def kth(pos_rank, erase):
        p = 1
        l = 1
        r = size

        while l != r:
            if erase:
                seg[p] -= 1

            mid = (l + r) >> 1

            if seg[p << 1] >= pos_rank:
                p <<= 1
                r = mid
            else:
                pos_rank -= seg[p << 1]
                p = p << 1 | 1
                l = mid + 1

        if erase:
            seg[p] -= 1

        return l

    parent = [0] * (k + 1)

    for idx in range(n - 1, -1, -1):
        l = L[idx]
        r = R[idx]

        if r >= seg[1]:
            continue

        parity = ((l & 1) ^ 1)
        cur = l + parity

        if cur > r:
            cur = l + (parity ^ 1)

        length = r - l + 1

        for _ in range(length):
            if r >= seg[1]:
                break

            copied_pos = kth(r + 1, True)
            source_pos = kth(cur, False)

            parent[copied_pos] = source_pos

            cur += 2
            if cur > r:
                cur = l + (parity ^ 1)

    ans = [''] * (k + 1)

    ptr = 0
    for i in range(1, k + 1):
        if parent[i]:
            ans[i] = ans[parent[i]]
        else:
            ans[i] = s[ptr]
            ptr += 1

    sys.stdout.write(''.join(ans[1:]) + '\n')

if __name__ == "__main__":
    solve()
```セグメント ツリーには、各間隔に残っている生存位置の数が保存されます。 の`kth(rank, erase)`ルーチンは、現在の生存ランクが等しいポジションを見つけます。`rank`。 

いつ`erase=True`、ツリーを下降するときに、その位置がアライブセットから削除されます。 いつ`erase=False`、構造は変更されません。 

微妙な部分は、コピーされたブロック内のソース ランクの順序です。 この突然変異では、最初に偶数のインデックスが付けられたすべての要素が出力され、その後に奇数のインデックスが付けられたすべての要素が出力されます。 変数`cur`これらのソース ランクをまさにその順序で調べます。 

再構築フェーズは有用なプロパティに依存します。 親インデックスは常に、それを参照する位置よりも早く解決されます。 これにより、左から右への 1 回のパスで答えを埋めることができます。

 ## 特殊なケース

 次のことを考慮してください。```text

1
