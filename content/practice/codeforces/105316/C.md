 ## 解決策
 ## 問題の理解

 馬が位置 0 から開始し、ラインに沿って正の方向にのみ移動する、いくつかの独立したシナリオが与えられています。 このラインに沿って、明確な位置に食べ物の皿が配置されています。 各料理は、馬が到着してから食べるまでに一定の時間がかかります。 前に進むには、移動距離に比例して時間もかかります。馬が位置 x から位置 y に移動すると、移動に y − x 分かかります。 

各テスト ケースについて、馬が最適な料理のサブセットと順序を選択できるが、後戻りすることはできないと仮定して、総制限時間 D 内に馬が食べることができる料理の数を決定する必要があります。 

重要な相互作用は、移動時間と食事時間の間にあります。 遠くにある料理は、行くのにお金がかかりますし、食べるのにも時間がかかります。 これにより、単調な動きと累積コストを伴うラインでスケジュールの問題が発生します。 

制約が十分に大きいため、テスト ケースごとに二次的な動作を行うソリューションは失敗します。 すべてのテスト ケースの n の合計は最大でも 10^5 であるため、O(n^2) メソッドはすでに境界線に達しているか、遅すぎることになりますが、これより悪いことは明らかに不可能です。 これにより、テスト ケースごとに O(n log n) または O(n) となる、ソート ベースの貪欲またはプレフィックス最適化手法が推進されます。 

微妙なエッジケースは、距離のみ、または食事時間のみに基づいた貪欲な選択が失敗した場合に発生します。 

料理について考えてみましょう。```
D = 5
positions: 1 2 5
times:      1 1 1
```いつもできるだけ遠いところから選ぶとすると、5 に行くと移動に 5 分、食事に 1 分かかり、すでに D を超えています。しかし、最初に近い料理を選ぶことで、より多くの料理の合計が可能になります。 地位だけに基づいた単純な貪欲は失敗します。 

もう 1 つの失敗モードは、累積時間を無視することによって発生します。それぞれの料理が個別に実行可能であっても、それらの合計移動量の累積により、以前は有効だった選択が無効になる可能性があります。 

## アプローチ

 強引な解釈では、料理のすべてのサブセットを試し、各サブセットを位置で並べ替え、0 から合計移動時間を計算し、食事時間の合計を計算し、それが D 内に収まるかどうかを確認します。これは、単調な移動の制約を尊重しているため正しいですが、組み合わせ的に爆発します。 テスト ケースごとに 2^n のサブセットがあり、サブセットごとに実行可能性の計算に O(n) を費やすことになり、指数関数的な時間がかかります。 

部分集合の観点から考えるのをやめ、代わりに料理を位置別に分類すると、問題の構造は管理可能になります。 馬は決して後退しないので、有効な計画は、昇順の位置を選択し、その順序でそれらを訪問することに対応します。 ソートが完了すると、選択されたプレフィックスのようなサブセットの移動時間は、選択された最大の位置と、スキップされたギャップによる調整のみに依存します。 

重要な簡素化は、グローバルな動きと段階的な決定を分離する方法で、選択したセットのコストを書き換えることです。 セットを固定して位置で並べ替えると、移動コストの合計は、0 から始まる連続した選択されたポイント間の距離の合計にすぎません。これは、段階的に考えることができることを示唆しています。つまり、パスを左から右に延長し、各ポイントで次の料理を含めるかどうかを決定します。 

サブセットを明示的に列挙する代わりに、指定された数の料理の総食事時間を最小限に抑えて、選択した料理のセットを維持する貪欲な戦略を使用します。 カウントを最大化するには、できるだけ多くの初期の料理を許可しながら、総コストを低く抑えたいと考えています。 これは当然、最小ヒープ アプローチにつながります。料理を位置の昇順で繰り返し、実行時間コストを維持し、D を超えた場合は、これまでに選択した料理の中で最も高価な食事時間の料理を破棄します。 これが機能する理由は、旅行コストが注文によって固定されるため、調整できるのは食事時間だけであり、食事時間の最も悪い項目を削除することで、実行可能性を維持する最大のチャンスが得られるためです。 

これにより、問題は累積制約の下で項目の最大数を選択することに変換され、項目はソートされた順序で処理され、実現可能性が貪欲に維持されます。

 ## アルゴリズムのチュートリアル

 まず、すべての料理を位置ごとに分類します。 これが必要なのは、移動が厳密に前方に行われるためであり、最適なルートは位置の昇順を尊重する必要があります。 

次に、選択した料理の実行構造を維持しながら、左から右に料理を繰り返します。 各料理では、以前に選択した位置からその料理に到達するまでに必要な追加時間と、その食事の時間を計算します。 トータルコストを維持し、必要に応じて以前に選択した食事時間を削除できる構造を維持します。 

選択した料理の最大山盛りの食事時間を使用します。 これにより、合計が D を超えるたびに、最も時間の無駄な料理を効率的に廃棄することができます。最大の食事時間を削除することが最もコストの削減につながるためです。 

各ステップで、現在の料理を挿入し、移動の寄与と食事時間を追加し、合計時間が再び D 以内になるまで、最悪の候補を削除することで違反を繰り返し修正します。 

最後に、答えは、任意の時点で選択範囲に残る料理の最大数です。 

### なぜ効果があるのか

現時点では、ソート順に料理の接頭語を検討しています。 この接頭辞から k 個の料理を選択するすべての方法の中で、移動コストは選択された右端の位置によって決まり、順序も固定されるため、最適な方法は総食事時間を最小限に抑えます。 貪欲な戦略はまさにその特性を維持します。つまり、固定サイズの場合、実現可能性と一致する方法で、到達可能な候補者間で k 個の最小の食事時間を常に維持します。 選択した料理をより長い食事時間に置き換えるソリューションは、アクセス可能性を向上させることなく総コストを増加させるだけであるため、ヒープベースの置き換えにより最適性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import heapq

def solve():
    t = int(input())
    for _ in range(t):
        n, D = map(int, input().split())
        p = list(map(int, input().split()))
        t_eat = list(map(int, input().split()))
        
        dishes = sorted(zip(p, t_eat))
        
        heap = []
        total_time = 0
        prev_pos = 0
        best = 0
        
        for pos, eat in dishes:
            travel = pos - prev_pos
            total_time += travel + eat
            prev_pos = pos
            
            heapq.heappush(heap, -eat)
            
            while heap and total_time > D:
                removed = -heapq.heappop(heap)
                total_time -= removed
            
            best = max(best, len(heap))
        
        print(best)

if __name__ == "__main__":
    solve()
```このソリューションは、連続して選択された位置間の違いを使用して移動が段階的に処理されるように料理を並べ替えます。 変数`total_time`移動時間と食事時間の両方を蓄積します。 

ヒープは、Python のデフォルトの最小ヒープを使用して最大ヒープをシミュレートするために、食事時間を負の値として保存します。 合計時間が制限を超えると、違反に最も大きく寄与するため、食事時間が最も長い料理が削除されます。 

変数`best`任意のプレフィックス ステップで実行可能に維持できるディッシュの最大数を追跡します。 

微妙な点は、常に更新されるということです`prev_pos`たとえ後で皿を取り除いたとしても。 ヒープの削除は食事時間にのみ影響するため、これは安全です。 動きの構造は、ソートされた位置の反復順序によって固定されます。 これにより、旅行の累計と選択の間の一貫性が確保されます。

 ## 特殊なケース

 原点から遠く離れた、食事時間が長い単一の料理は、自明の動作をします。アルゴリズムは、それを一度追加し、D が十分であれば決して削除しません。 他の料理との競合がないため、ヒープが除去をトリガーすることはなく、答えは 1 のままです。 

D が最初の移動費と食費を足したものよりも小さい場合、ヒープはすぐにオーバーフローし、唯一の要素が削除され、空の選択が残ります。 アルゴリズムは正しくゼロを報告します。 

後の大きな外れ値を持つ小さな位置の皿の密集したクラスターは、剪定の意図された動作を示しています。初期の皿はゆっくりと蓄積しますが、遠い皿は大きな移動ジャンプを引き起こし、高い食事時間の削除を強制します。 ヒープにより、最適な選択戦略に一致する、低コストの組み合わせのみが確実に生き残ります。
