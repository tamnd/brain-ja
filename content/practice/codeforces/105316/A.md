 ## 解決策
 ## 問題の理解

 正の整数の配列が与えられます。 タスクは、それをいくつかの連続した空ではないセグメントに分割することです。 各要素は正確に 1 つのセグメントに属している必要があるため、すべての有効な解は配列の連続したブロックへの完全な分割に対応します。 

すべてのセグメントについて、その合計を計算し、これらの合計がポリゴンのエッジの長さになります。 問題は、これらの辺の長さが凸多角形を形成できるように配列を分割できる方法が何通りあるかを数えることです。 

幾何拘束は重要な隠れた部分です。 正の長さのセットは、どの辺も大きすぎない場合に限り、凸多角形を形成できます。より正確には、最大の辺が他のすべての辺の合計より厳密に小さくなければなりません。 すべての要素の合計が S で、セグメントの合計が s1、s2、...、sk の場合、条件は max(si) < S - max(si) であり、これは 2 * max(si) < S と同等です。 

これにより、問題はジオメトリからパーティションの制約に変換されます。セグメントの最大合計が配列の合計の半分より厳密に小さくなるように、配列を分割するすべての方法をカウントする必要があります。 

N は最大 10^6 であるため、すべてのパーティションを明示的に試行する解決策は不可能です。 O(N^2) のアプローチでも、最悪の場合は約 10^12 の演算が必要となり、これは制限をはるかに超えています。 これは、スライディング ウィンドウ構造を使用した線形または線形に近い動的プログラミング アプローチが必要であることを直ちに示唆しています。 

単一の要素がすでに大きすぎる場合、微妙なエッジ ケースが発生します。 たとえば、合計が 10 で 1 つの要素が 6 の場合、有効なセグメント内にその要素を含むパーティションは条件を満たすことができません。これは、そのセグメントだけが多角形不等式に違反するためです。 このような場合、たとえ多くの分割が組み合わせ的に存在しても、答えはゼロになります。 

もう 1 つのエッジケースは、最適なパーティション構造が貸借一致セグメントの合計に依存する場合です。 たとえば、すべての要素が合計に比べて大きい場合、セグメント合計の有効ウィンドウが非常に小さくなり、場合によっては長さ 1 のセグメントが強制されたり、答えが完全に消えてしまったりします。 

## アプローチ

 ブルートフォースソリューションでは、要素間にカット位置を配置するためのあらゆる可能な方法を列挙します。 長さ N の配列の場合、N−1 個の可能なカット位置があるため、2^(N−1) 個の可能な分割が存在します。 パーティションごとにセグメントの合計を計算し、ポリゴン条件が当てはまるかどうかを確認します。 これは正しいですが、N = 40 でもすでに 1 兆を超えるパーティションが生成されるため、完全に実行不可能です。 

重要な観察は、幾何学的条件が最大セグメント合計のみに依存するということです。 しきい値 X を Floor((S−1)/2) に固定すると、すべての有効なパーティションは、すべてのセグメントの合計が最大でも X になるパーティションになります。条件「最大セグメントの合計 < S/2」は、「すべてのセグメントの合計 ≤ X」になります。 これにより、ローカル合計制約を超えたセグメント間の依存関係が削除されます。 

ここで、問題は古典的な計数問題になります。各セグメントの合計が X を超えないように、配列を連続セグメントに分割する方法の数を数えます。これは動的プログラミングで解決できます。 各位置 i について、部分配列 (j+1 ～ i) が合計 ≤ X になるように、以前のすべてのカット位置 j を考慮し、dp[j] を累積します。 

単純な DP は依然として O(N^2) 遷移を試行します。 ただし、値はすべて正であるため、2 つのポインターを使用して有効な開始点のスライディング ウィンドウを維持できます。 i が増加すると、有効な左境界は前方にのみ移動します。 これにより、dp 値に対するプレフィックスの合計を使用して、償却 O(1) 時間で各 dp[i] を計算できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^N・N) | O(N) | 遅すぎる |
 | 2 つのポインターを使用した最適な DP | O(N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

まず配列の総和 S を計算し、しきい値 X = (S−1)//2 を導出します。 この値は、許容されるセグメント合計の最大値を表します。 

次に、動的プログラミングを使用します。ここで、 dp[i] は、プレフィックス a[1..i] を分割する有効な方法の数を表します。 また、高速な範囲合計クエリを可能にするために、dp 上のプレフィックス合計配列も維持します。 

1. dp[0] = 1 を初期化します。これは、空のプレフィックスを分割する 1 つの方法を表します。 また、prefix_dp[0] = 1 を維持します。 
2. i で終了するウィンドウのスライディング ウィンドウの左ポインター l = 1 と実行セグメントの合計 current_sum = 0 を維持します。 
3. 1 から N までの各 i について、 a[i] を current_sum に追加してウィンドウを拡張します。 
4. current_sum が X を超える場合、l をインクリメントし、current_sum から a[l] を減算することにより、ウィンドウが再び有効になるまでウィンドウを左から縮小します。 これにより、[l..i] 内の任意の j から始まり i で終わるすべてのセグメントの合計が X になることが保証されます。 
5. 開始位置の有効な範囲が決定されたら、[l..i] 内のすべての j の dp[j−1] の合計として dp[i] を計算します。 これは、プレフィックスの合計 dp[i] = prefix_dp[i−1] − prefix_dp[l−2] を使用して効率的に計算されます。 
6. 1e9+7 を法として、prefix_dp[i] = prefix_dp[i−1] + dp[i] を更新します。 

この正確性は、i で終わるすべての有効な最後のセグメントが開始インデックスの連続範囲に正確に対応し、配列要素が正であることにより、i が増加するにつれてこの範囲が単調に移動することが保証されるという事実から得られます。 

### なぜ効果があるのか

 重要な不変条件は、各位置 i で、スライディング ウィンドウ [l, i] が、i で終了するセグメントの合計が最大で X である開始点のセットを正確に表していることです。すべての要素が正であるため、左側の境界を拡張してもセグメントの合計は減少するだけであり、右に移動するとセグメントの合計は増加するだけであるため、有効なセットは常にプレフィックス間隔になります。 この構造により、dp 遷移を拡張するときにすべての有効なパーティションが 1 回だけカウントされることが保証され、X を超えるセグメントはウィンドウから除外されるため、無効なパーティションが寄与することはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    total = sum(a)
    X = (total - 1) // 2

    # If even a single element exceeds X, no valid segment can contain it
    # since segments are contiguous and must satisfy sum <= X.
    for v in a:
        if v > X:
            print(0)
            return

    dp = [0] * (n + 1)
    prefix = [0] * (n + 1)

    dp[0] = 1
    prefix[0] = 1

    l = 1
    current_sum = 0

    for i in range(1, n + 1):
        current_sum += a[i - 1]

        while current_sum > X:
            current_sum -= a[l - 1]
            l += 1

        left = l - 1
        # dp[i] = sum(dp[j]) for j in [left .. i-1]
        dp[i] = (prefix[i - 1] - (prefix[left - 1] if left > 0 else 0)) % MOD
        prefix[i] = (prefix[i - 1] + dp[i]) % MOD

    print(dp[n] % MOD)

if __name__ == "__main__":
    solve()
```実装は DP 定義に直接準拠します。 唯一重要な部分は、遷移をプレフィックス合計クエリに変換することです。これにより、すべての有効な以前のカット位置の反復が回避されます。 スライディング ウィンドウにより、合計を最初から再計算することなく、セグメント合計に対する制約が段階的に適用されます。 

dp[i] は dp[j] に依存するため、プレフィックス配列のインデックスには注意が必要です。j は配列のインデックスではなくカット位置に対応します。 セグメント開始位置と dp インデックスの間の変換は、l ポインタと 1 ずつシフトすることによって処理されます。 

## 実用的な例

 ### 例 1

 すべてのパーティションを明示的に追跡できるほど配列が小さい入力を考えてみましょう。 

有効な dp 遷移が次の動作を生成すると仮定します。 

| 私 | a[i] | l | 現在の合計 | dp[i] | 接頭辞[i] |
 | --- | --- | --- | --- | --- | --- |
 | 1 | × | 1 | × | 1 | 1 |
 | 2 | y | 1 | x+y | 1 | 2 |
 | 3 | z | 2 | y+z | 2 | 4 |

 このトレースは、l をシフトすることで無効なセグメント開始がどのように削除されるか、および dp がすべての有効な以前のカット位置からの寄与をどのように蓄積するかを示します。 

ここで確認された重要な特性は、プレフィックスが有効になると、そのインデックスで終わるすべてのパーティションが、以前の有効なカット ポイントを選択することによって形成されるということです。 

### 例 2

 1 つの大きな要素が早期のウィンドウ縮小を強制する場合を考えてみましょう。 

| 私 | a[i] | l | 現在の合計 | dp[i] |
 | --- | --- | --- | --- | --- |
 | 1 | 大 | 1 | 大 | 1 |
 | 2 | 小さい | 2 | 小さい | 1 |
 | 3 | 小さい | 2 | 小さい+小さい | 2 |

 これは、大きなプレフィックスによってアルゴリズムが以前の開始位置を強制的に破棄する方法と、有効なセグメントの開始のみをカウントすることで dp の一貫性を維持する方法を示しています。

 ## 特殊なケース

 単一の要素がすでにしきい値 X を超えている場合、その要素をセグメントとして含むすべてのパーティションは無効になります。 この状況では、その要素をカバーするインデックスのスライディング ウィンドウが安定することはなく、そのインデックスを含むセグメントに有効な開始位置が存在しないため、DP は正しくゼロを提供します。 

すべての要素が小さい場合、スライディング ウィンドウは長い範囲をカバーするように拡張されます。つまり、すべてのカット位置が多くのエンドポイントに対して有効になります。 その後、DP は多数のウェイを蓄積し、各有効なカットはエンドポイントごとに 1 回だけ寄与するため、正確性は二重カウントを回避するプレフィックス合計構造に完全に依存します。 

要素のバランスが著しく崩れている場合、初期の大きなプレフィックス合計によりウィンドウが頻繁に縮小します。 各短縮は以前のインデックスに対して永続的であり、ポインタの単調な動きにより無効なセグメントが再検討されることはないため、アルゴリズムはこれをきれいに処理します。
