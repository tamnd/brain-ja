 ## 解決策
 ## 問題の理解

 2D 整数グリッド上にいくつかの円が与えられ、それぞれが中心点と半径によって定義されます。 すべての円を読み取った後、一連のクエリ ポイントを受け取ります。 クエリ ポイントごとに、指定された円のうちのいくつがそのポイントを含むか、そのポイントに触れているかをカウントする必要があります。 

点と円の中心の間のユークリッド距離が半径以下の場合、円は点を「カバー」します。 すべての座標は整数であり、半径が小さい (最大 10) ため、基本的には境界のある幾何学的条件を繰り返しチェックすることになります。 

入力サイズは、すべてのケースで合計最大 100,000 個のサークルと 100,000 個のクエリを含む複数のテスト ケースを示唆しています。 これにより、すべてのクエリに対してすべての円をチェックするソリューションは即座に除外されます。 単純なアプローチでは、最悪の場合、最大 10¹⁰ の距離チェックが実行されますが、これは制限時間をはるかに超えています。 

微妙だが重要な制約は、半径が非常に小さく、最大でも 10 であることです。これは、各円が平面の小さな局所領域にのみ影響を与えること、そして円をグローバルな幾何学的オブジェクトとして扱うのではなく、この局所性を活用できることを強く示唆しています。 

単純な間違いが明らかになる特殊なケースの 1 つは、多くの円が 1 つの点で重なり合う場合です。 たとえば、すべての円の中心が (1, 1) で半径 10 の場合、その点に近いすべてのクエリですべての円がカウントされる必要があります。 素朴な解決策でも論理的には機能しますが、遅すぎます。 本当のリスクは、正確な距離検証を行わずに境界ボックスに基づいてチェックを誤ってスキップしようとする最適化にあり、x² + y² が r² に正確に等しい境界でオフバイ 1 エラーが発生する可能性があります。 

## アプローチ

 ブルート フォース手法は簡単です。クエリ ポイントごとに、すべての円を反復処理し、二乗距離を使用してポイントが円内にあるかどうかを計算します。 この定義は直接的であり、円ごとに独立しているため、これは正しいです。 ただし、テスト ケースごとに n × q 回の距離チェックが実行されます。 n と q の合計制約が 10⁵ に達すると、これは約 10¹⁰ の操作になり、これは実現不可能です。 

重要な観察は半径の境界から得られます。 各円は (2r + 1) × (2r + 1) 正方形内の点にのみ影響します。r ≤ 10 であるため、この領域は最大 21 × 21 = 441 グリッド点になります。 これは視点の逆転を示唆しています。各点をどの円に含むかを尋ねる代わりに、各円の寄与をその円がカバーするすべての整数点に分配できます。 

グリッド点上の周波数マップを事前計算できます。 すべての円について、dx² + dy² ≤ r² となるようにすべての整数オフセット (dx, dy) を反復し、対応する点 (x + dx, y + dy) のカウンターをインクリメントします。 すべての円を処理した後、各クエリは直接辞書検索になります。 

これが機能するのは、円ごとの格子点の総数が定数 (~300 ～ 400) で制限されているためです。そのため、前処理は小さな定数係数を使用して n で線形になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nq) | お(1) | 遅すぎる |
 | カバレッジ マップを事前計算する | O(n · r² + q) | O(n · r²) | 承認済み |

 ## アルゴリズムのチュートリアル

 各円をそれがカバーする整数グリッド点のセットに変換し、寄与を蓄積します。

1. 整数点ごとに、それをカバーする円の数を格納するハッシュ マップ (または辞書) を作成します。 このマップは、すべての可能なクエリ ポイントに対して事前に計算された回答を表します。 
2. 中心 (cx, cy) と半径 r の円ごとに、-r から r までのすべての整数オフセット dx を繰り返します。 各 dx について、dy を −r から r まで繰り返し、dx² + dy² ≤ r² かどうかを確認します。 この条件により、円の境界内または境界上の点のみが含まれることが保証されます。 
3. 有効な値 (dx、dy) ごとに、キー (cx + dx、cy + dy) のカウンターをインクリメントします。 これにより、円がグリッド上に効果的に「ペイント」され、影響を受けるすべての整数点のカバレッジ カウントが増加します。 
4. すべての円を処理した後、各クエリ ポイント (qx、qy) は、マップに格納されている値を読み取ることによって応答されます。 ポイントが存在しない場合、その値はゼロになります。 

重要な考え方は、計算をクエリ時間から前処理時間に移すということです。 各サークルは小さな固定された近傍にのみ貢献するため、全体の作業は管理しやすくなります。 

### なぜ効果があるのか

 正確さは、各円が各格子点に独立して寄与するという事実に依存します。 前処理ステップでは、各円の円不等式を満たす整数点を正確に列挙します。 このような点はすべて、円ごとに 1 回だけ訪問されるため、任意の座標に保存されている値は、幾何学的条件にその点が含まれる円の数に等しくなります。 クエリはこの事前計算された集計を取得するだけなので、情報が失われたり、誤って二重にカウントされたりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n, q = map(int, input().split())

        mp = {}

        circles = []
        for _ in range(n):
            x, y, r = map(int, input().split())
            circles.append((x, y, r))

        # precompute offsets for each possible radius (small bound r <= 10)
        for x, y, r in circles:
            rr = r * r
            for dx in range(-r, r + 1):
                dy_limit = int((rr - dx * dx) ** 0.5)
                for dy in range(-dy_limit, dy_limit + 1):
                    px = x + dx
                    py = y + dy
                    key = (px, py)
                    mp[key] = mp.get(key, 0) + 1

        for _ in range(q):
            x, y = map(int, input().split())
            out.append(str(mp.get((x, y), 0)))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このソリューションでは、まず、円の影響を受けるすべての整数点のカバレッジ カウントを格納する辞書を構築します。 各円について、方程式 dx² + dy² ≤ r² を使用して、円内の有効な整数オフセットのみを列挙します。 内側のループは半径制約によって厳密に境界付けられるため、効率性が維持されます。 

微妙な実装の詳細は、ユークリッド距離の代わりに二乗距離を使用して、浮動小数点精度の問題を回避することです。 もう 1 つの詳細は、タプルをキーとする辞書を使用することです。これは、生成されるポイントの合計数が制限されているため、十分に効率的です。

 ## 特殊なケース

 重要なエッジ ケースは、クエリが円の境界上に正確に存在する場合です。 (0, 0) を中心とし半径 2 の円の場合、2² = 4 が r² に等しいため、点 (2, 0) をカウントする必要があります。 dx² + dy² ≤ r² という条件で明示的に等価性が認められ、dx = 2、dy = 0 の場合には整数の列挙により (2, 0) が生成されることが保証されるため、アルゴリズムにはこの点が含まれています。 

もう 1 つのケースは、複数の円が同一の座標で重なっている場合です。 10 個の円がすべて半径 1 の中心 (5, 5) を共有する場合、(5, 5) のマップ エントリは前処理中に 10 回増分されます。 (5, 5) のクエリは、その累積値を単純に読み取り、円間の干渉のない線形累積動作を確認します。
