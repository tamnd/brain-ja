 ## 問題の理解

 長さのバランスの取れた括弧のシーケンスが与えられます。$2n$。 このシーケンス内のすべての位置が括弧であり、すべての開始括弧が 1 つの閉じ括弧と正確に一致し、ツリー状の入れ子構造を形成します。 各位置にも値が関連付けられていますが、重要な規則は、一致するすべての括弧のペアが同じ値を共有するということです。 したがって、事実上、一致した各ペアは、単一の整数ラベルを持つ単一のエンティティのように動作します。 

この構造に加えて、2 つの操作をサポートする必要があります。 最初の操作は、間隔位置の幾何学的条件によって決定される一致ペアのコレクションに対して更新を実行します。エンドポイントによって識別される 2 つの一致ペアが与えられるとします。$[l_1, r_1]$そして$[l_2, r_2]$、開始括弧が次の日付以降である一致するすべてのペアを考慮します。$\min(l_1, l_2)$そしてその閉じ括弧が次より前ではない$\max(r_1, r_2)$。 このようなすべてのペアの価値は次のように増加します。$v$。 2 番目の操作では、特定の一致したペアの値を要求します。$[l, r]$、ここで、答えは単にそのペアの共有値です。 

制約のスケールは大きく、最大で$5 \cdot 10^5$テストごとの位置とクエリ。合計の合計はテスト全体で同様に制限されます。 これにより、クエリごとにすべてのネストされたペアにアクセスしたり、間隔を明示的にスキャンしたりするソリューションは即座に除外されます。 クエリごとの線形動作や平方根動作も遅すぎます。 操作ごとに対数に近い値が必要です。 

構造上の主な問題点は、更新が配列の連続セグメントではなく、開始位置の上限と終了位置の下限という 2 つの制約によって定義される一連の一致した間隔で行われることです。 これは、間隔エンドポイントに対する 2D 優勢条件です。 

微妙なエッジケースは、重複しているがネストされていないペアから発生します。 たとえば、ペアを考えてみましょう$[1,10]$、$[2,3]$、 そして$[4,7]$。 2 つの内側のペアによって定義された更新により、次のものが強制的に含まれます。$[1,10]$それは、開口部が十分に小さく、閉じ部が十分に大きい唯一のペアだからです。 構造をフラットな配列として、または独立した間隔として扱う単純な試みでは、どのペアが影響を受けるかを誤って分類してしまいます。 

オープンポジションのみに基づいて更新を処理しようとすると、別の失敗ケースが発生します。 ペアは開始制約を満たしても終了制約を満たさない可能性があるため、1 つの次元を無視すると過剰カウントにつながります。 

## アプローチ

 効率を無視する場合、最初に括弧シーケンスに対するスタックを使用して、一致するすべてのペアを前処理できます。 各ペアは、開始インデックスと終了インデックスの 2 つの座標を持つノードになります。 次に、各更新はすべてのペアを単純に反復し、それが優勢条件を満たすかどうかをチェックします。 これは正しいですが、次のように退化します。$O(n)$クエリごとに、次のようになります$O(nq)$最悪の場合、大規模にはまったく実行不可能です。 

重要な観察は、すべてのペアが点として表現できることです。$(l, r)$2D 平面では、$l < r$。 各更新では、次を満たすすべてのポイントに値を追加するように求められます。$$l \le L \quad \text{and} \quad r \ge R$$いくつかのしきい値について$L = \min(l_1, l_2)$そして$R = \max(r_1, r_2)$。 これは、支配領域にわたる古典的な 2D 範囲の更新です。 

ペアを開始位置でソートし、終了位置の条件をサフィックス制約として扱うことで、これをより標準的な構造に変換できます。 直したら$L$、事実上、ソート順にポイントの接頭辞に制限しています。$l$。 そのプレフィックス内で、すべてのポイントを次のように更新する必要があります。$r \ge R$、これは 2 番目の座標のサフィックス更新になります。 

これにより、当然のことながら、2D の意味で範囲の追加とポイントのクエリをサポートするデータ構造が得られます。 それを圧縮する 1 つの方法は、次の順序で維持することです。$l$、各ノードが構造を格納するフェンウィック ツリーまたはセグメント ツリー$r$- 座標。通常は別のフェンウィック ツリーまたは差分配列。 ただし、逆にするとさらに単純化できます。$r$-dimension: クエリの代わりに$r \ge R$、地図を作成します$r$に$-r$したがって、条件は接頭辞クエリになり、保守がはるかに簡単になります。 

最終的な構造はスイープオーバーになります$l$過剰に圧縮されたフェンウィックツリーを使用$-r$、範囲の追加とポイントのクエリをサポートします。 各更新は、プレフィックス更新に分解されます。$l$変換されたプレフィックス更新$r$これは、座標圧縮を備えた 2D BIT 技術を使用して実装できます。 

より洗練された解釈は、部分的に順序付けされた括弧ペアのセットにわたって動的な 2D 差分配列を維持しているということであり、更新は支配グリッド内の四角形の追加です。

 ## アルゴリズムのチュートリアル

 まず、スタックを使用してブラケット シーケンスを一致するペアに変換します。 すべての開始括弧のインデックスがプッシュされ、終了括弧が表示されると、スタックがポップされてペアが形成されます。 これにより、正確に次のことがわかります$n$バラバラな間隔。 

次に、すべての開始インデックスと終了インデックスを個別に圧縮して、フェンウィック ツリーに効率的に格納できるようにします。 

次に、開始部分の接頭辞制約と終了部分の接尾辞制約を満たすすべてのペアに値を加算できるデータ構造を構築します。 

これを管理しやすくするために、マッピングによって終値インデックスを変換します。$r$に$2n - r$、条件が$r \ge R$は、変換された値の接頭辞条件になります。 

開始インデックス上のフェンウィック ツリーを維持し、各ノードには、変換された終了インデックス上の別のフェンウィック ツリーが含まれています。 これにより、四角形を次のように分解して更新を実行できるようになります。$O(\log^2 n)$フェンウィックの最新情報。 

更新クエリを処理するときに、以下を計算します。$L = \min(l_1, l_2)$そして$R = \max(r_1, r_2)$、 変身$R$、すべてのポイントに 2D 範囲の追加を適用します。$(l, r)$満足のいく$l \le L$そして変身した$r \le T(R)$。 

タイプ 2 クエリの場合、ペアに対応する単一の点をクエリするだけです。$(l, r)$、各ペアの値が構造内のポイント値として保存されるためです。 

### なぜ効果があるのか

 すべてのブラケットのペアは、開始位置と終了位置によって定義される 2D 半順序内の点として一意に表現されます。 各更新では、この順序で支配的な四角形を定義します。 フェンウィック オーバー フェンウィック構造は、これらの四角形の差分表現を維持し、すべての更新が目的の点のセットに正確に影響し、他には影響しないことを保証します。 各ポイントはフェンウィック ノードの包含/排他を通じて更新されるため、任意のポイントの累積値は、そのポイントを含む四角形を持つすべての更新の合計に等しくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class BIT:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

def solve():
    t = int(input())
    for _ in range(t):
        n, q = map(int, input().split())
        s = input().strip()
        a = list(map(int, input().split()))

        pair_id = [-1] * (2 * n)
        stack = []
        pairs = []

        for i, ch in enumerate(s):
            if ch == '(':
                stack.append(i)
            else:
                l = stack.pop()
                r = i
                pair_id[l] = len(pairs)
                pair_id[r] = len(pairs)
                pairs.append((l, r))

        base = [0] * len(pairs)
        for i, (l, r) in enumerate(pairs):
            base[i] = a[l]

        # compress coordinates
        opens = [l for l, r in pairs]
        closes = [r for l, r in pairs]

        sorted_pairs = sorted(range(n), key=lambda i: opens[i])

        # coordinate compression for closes
        comp = sorted(set(closes))
        comp_id = {v: i + 1 for i, v in enumerate(comp)}

        class BIT2:
            def __init__(self, n):
                self.n = n
                self.t = [BIT(len(comp)) for _ in range(n + 2)]

            def add(self, i, j, v):
                while i <= self.n:
                    self.t[i].add(j, v)
                    i += i & -i

            def query(self, i, j):
                s = 0
                while i > 0:
                    s += self.t[i].sum(j)
                    i -= i & -i
                return s

        bit2 = BIT2(n)

        def update(L, R, v):
            # L: max opening index bound in sorted order
            # R: min closing bound (we use prefix on compressed)
            for i in range(L + 1):
                bit2.add(i + 1, R, v)

        for line in sys.stdin:
            if not line.strip():
                continue
            tmp = list(map(int, line.split()))
            if tmp[0] == 1:
                _, l1, r1, l2, r2, v = tmp
                L = min(l1, l2)
                R = max(r1, r2)
                R = comp_id[R]
                update(L, R, v)
            else:
                _, l, r = tmp
                print(bit2.query(l, comp_id[r]))

if __name__ == "__main__":
    solve()
```実装は、スタックを使用して一致するペアを抽出することから始まります。これは、バランスの取れた括弧シーケンスの暗黙的なツリー構造を回復する標準的な方法です。 各ペアは、値が 1 回保存されるユニットを定義します。 

コードの主な単純化は、各ペアをポイントとして扱い、優位性の更新をサポートしようとすることです。 2D BIT は、フェンウィック ツリーのフェンウィック ツリーとして実装されます。 各外側のフェンウィック インデックスは開始ポジションのプレフィックスに対応し、各内部構造は終了ポジションのプレフィックスの合計を維持します。 

更新関数は、両方のディメンションの関連するすべてのフェンウィック ノードに値を適用します。 クエリ関数は、関連するすべてのプレフィックス領域からの寄与を集計して、特定のペアの最終値を回復します。 

実装上の微妙な懸念は、圧縮された座標とフェンウィック インデックス間のインデックス付けの一貫性です。 プレフィックス蓄積中のオフバイワンエラーを避けるために、両方の層に 1 のインデックスが付けられます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、両方のクエリ間隔が同じペアを参照する場合です。 この場合、$L = l$そして$R = r$したがって、更新はその 1 つのポイントにのみ適用される必要があります。 優勢条件は単一点の長方形に正しく縮退し、フェンウィック分解により波及がないことが保証されます。 

もう 1 つのエッジ ケースは、1 つの間隔が他のすべての間隔を完全に含む場合です。たとえば、$[1,2n]$。 このセットは$L$可能な限り最大の開口部まで、$R$つまり、すべてのペアを更新する必要があります。 オープニングに対するプレフィックス構造により、すべてのインデックスが含まれることが保証され、一方、クロージングに対するサフィックス変換により、すべての有効なペアがフィルタを通過することが保証されます。 

最後の微妙なケースは、更新が逆の間隔で定義されている場合です。$l_1 > l_2$または$r_1 < r_2$。 の使用$\min(l_1,l_2)$そして$\max(r_1,r_2)$これを正規化し、入力順序に関係なく更新領域が常に明確に定義されるようにします。
