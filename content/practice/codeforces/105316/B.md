 ## 解決策
 ## 問題の理解

 ちょうど 3 枚の一桁のカードから始まる決定論的なプロセスが与えられています。 各カードは 1 から 9 までの値を保持します。このプロセスでは、コレクション全体が繰り返し変換されます。つまり、すべてのカードの値が 3 倍され、結果が 10 進数に分割されます。 各数字が新しいカードになり、これが正確に繰り返されます$n$回。 

この変換を実行した後、$n$何度も、結果として得られる複数の数字セットが表示されますが、Omar が隠しているために 1 つの数字が欠落しています。 私たちの仕事は、その隠された数字を取り戻すことです。 

重要なのは、歴史全体や最初の 3 枚のカードを直接再構築することは求められていないということです。 最終的なマルチセットに再挿入された場合、どの 1 桁が、以下の 3 桁の開始桁からの有効な進化と一致するかを特定するだけで済みます。$n$作戦のラウンド。 

制約はすでにソリューションを強力に形成しています。 テスト ケースの数は次のように大きくなります。$10^4$、すべてのテストで観察された合計桁数は次のとおりです。$10^6$。 変容の深さ$n$これは、テスト ケースごとに完全なプロセスを最初からシミュレートすることは、単純な方法でカードごと、ステップごとに実行すると、両方の値が乗算されるため、遅すぎることがすぐにわかります。$n$そして拡大するシーケンスサイズ。 しかし、$n$は十分小さいので、単一の数字に変換を繰り返し適用する効果を事前計算できます。 

最初の3桁が不明なのが微妙な難点。 単純な試みでは、すべての 3 桁の数字を試してプロセスをシミュレートし、1 つの要素が欠落している最終的なマルチセットと比較します。 これは、時間の経過とともに各桁が複数の桁に拡張され、すべての桁に対してこれを行うため、爆発的に増加します。$9^3$テスト ケースごとの選択肢を掛け合わせると、すでに境界線に達します。$10^4$。 

2 番目の微妙な問題は、桁の順序は重要ではなく、多重度だけが重要であるということです。 これは、問題が基本的に決定論的展開プロセス後のマルチセットの等価性に関するものであることを意味します。 

最終的な構成からシーケンスを段階的に再構築しようとする単純なアプローチは、変換が可逆ではないため失敗します。1 のような数字は、初期の段階では 3、12、または 21 から得られる可能性があるため、逆方向に作業することは曖昧です。 

## アプローチ

 重要な観察は、変換が桁ごとに完全に独立していることです。 数字が別の数字と相互作用することはありません。 「3 を掛けて数字を分割する」を繰り返し適用することによって決定される固定シーケンスに展開されるだけです。 これは、各開始桁がその後の固定マルチセットに寄与することを意味します。$n$ステップ。 

したがって、システム全体をシミュレートする代わりに、各桁について事前計算します。$d \in [1,9]$その後どのようなマルチセットになるか$n$変化。 このベクトルをベクトルと呼びましょう$F_n(d)$, ここで、各エントリは各数字が何回出現するかをカウントします。 

これらのフィンガープリントが判明すると、3 枚のカードの最初の選択は、そのようなベクトルを 3 つ追加することに対応します。 したがって、最終的な完全なマルチセットは次と等しくなければなりません。$F_n(a) + F_n(b) + F_n(c)$いくつかの桁について$a, b, c$。 

完全な最終的なマルチセットは与えられていません。 1 つの要素が削除された状態で与えられます。 したがって、真の完全なマルチセットは、観測されたマルチセットにちょうど 1 桁の追加の数字を加えたものになります。$x$。 これは、各候補の数字を試すことができることを意味します$x$、完全なマルチセットを再構築し、それが 3 桁の指紋の合計として表現できるかどうかを確認します。 

総当たりのアイデアが明確になりました。つまり、3 つの指紋の考えられるすべての合計を事前に計算します。 あるのは$9^3 = 729$このようなトリプルなので、このセットは小さいです。 それぞれの合計はカウントの 9 次元ベクトルであり、タプルのようなハッシュ可能な形式で保存できます。 次に、テスト ケースごとに、観測された周波数ベクトルを 1 回計算し、欠落桁の候補ごとに、再構築された完全なベクトルが事前計算されたセットに存在するかどうかをテストします。 

残っている唯一の仕事はコンピューティングです$F_n(d)$。 数字は 1 ～ 9 のみなので、変換を繰り返し適用できます。$n$1 桁から開始して、ステップごとにその周波数ベクトルを更新します。 各ステップは、桁分割を通じてカウントを決定的に拡張します。$3d$、そしてそれ以来$n \le 33$、これは桁ごとの定数時間の作業です。

 ## アルゴリズムのチュートリアル

 1. 1 から 9 までの各数字について、次のように変換署名を構築します。$n$ラウンドします。 その数字を 1 回カウントすることから始めて、「3 を掛けて数字に分割する」というルールを繰り返し適用し、そのたびに長さ 9 の周波数配列を更新します。 これにより、各桁の動作が分離されるため、完全なマルチセットを再度シミュレートする必要がなくなります。 
2. 最初の 3 桁を選択した場合に考えられるすべての結果を含むグローバル ルックアップ構造を事前計算します。 注文されたトリプルごとに$(a, b, c)$1 ～ 9 の範囲でベクトルを計算します$F_n(a) + F_n(b) + F_n(c)$そしてそれをハッシュセットに保存します。 これは、カードが非表示になる前の、考えられるすべての完全な最終構成を表します。 
3. テスト ケースごとに、観測されたマルチセットを読み取り、サイズ 9 の周波数ベクトルに変換します。 
4. 考えられる数字をすべて試してください$x$隠しカードとして1から9まで。 一時的に次のオカレンスを 1 つ追加します$x$観測された周波数ベクトルに変換して、完全なマルチセット候補を再構築します。 
5. この再構築されたベクトルが、有効な完全な構成の事前計算されたセットに存在するかどうかを確認します。 最初に一致する数字が隠しカードです。 

### なぜ効果があるのか

 各数字は変換中に独立して進化するため、最終的なマルチセットは常に 3 つの独立した決定的な数字署名の合計になります。 これらのシグネチャの考えられるすべてのトリプルを事前計算するため、すべての有効な最終状態を正確に表現できます。 非表示の数字を追加し直すと、真の最終状態が復元され、正しい数字のみが、事前に計算された有効な構成の 1 つと一致するベクトルを生成します。 他の数字が誤ってこの制約を満たすことはできません。これは、最初の数字の異なる有効な 3 つの数字を意味し、一意性の保証に矛盾するためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

# precompute transformation of a single digit
def build_f(n):
    f = [[0]*10 for _ in range(10)]
    
    for d in range(1, 10):
        cur = [0]*10
        cur[d] = 1
        
        for _ in range(n):
            nxt = [0]*10
            for x in range(1, 10):
                if cur[x] == 0:
                    continue
                val = x * 3
                for ch in str(val):
                    nxt[int(ch)] += cur[x]
            cur = nxt
        
        f[d] = cur
    return f

def solve():
    t = int(input())
    ns = []
    tests = []
    
    max_n = 0
    for _ in range(t):
        n, m = map(int, input().split())
        arr = list(map(int, input().split()))
        tests.append((n, m, arr))
        max_n = max(max_n, n)
    
    # precompute up to max_n by recomputing per test n (simpler given small constraints)
    # but we actually cache per n
    cache = {}

    for n, m, arr in tests:
        if n not in cache:
            f = build_f(n)
            
            triples = set()
            for a in range(1, 10):
                for b in range(1, 10):
                    for c in range(1, 10):
                        vec = [0]*10
                        for i in range(1, 10):
                            vec[i] = f[a][i] + f[b][i] + f[c][i]
                        triples.add(tuple(vec[1:]))
            
            cache[n] = triples, f

        triples, f = cache[n]

        obs = [0]*10
        for x in arr:
            obs[x] += 1

        for cand in range(1, 10):
            vec = obs[:]
            vec[cand] += 1
            if tuple(vec[1:]) in triples:
                print(cand)
                break

solve()
```このソリューションでは、懸念事項を明確に分離します。`build_f(n)`繰り返される数字変換を数字ごとのフィンガープリントに圧縮し、トリプル列挙によって考えられるすべての初期状態をエンコードします。 最後のループは、テスト ケースごとに 9 つの候補に対する定数要素のチェックです。 

実装の微妙な詳細の 1 つは、周波数ベクトルを長さ 9 のタプルとして表すことです。これにより、ハッシュの安定性が確保され、事前計算されたセットでのメンバーシップ テストを高速に行うことができます。 もう 1 つは、個別のフィンガープリントを再計算することです。$n$安全なので$n \le 33$, そのため、最悪の場合でも最大 33 回再構築します。

 | --- | --- | --- | --- | --- |

 ## 特殊なケース

 観測されたすべての数字が同一である場合、解が偶然位置構造に依存しているかどうかが強調されます。 たとえば、観察されたマルチセットが次の場合、`2 2 2 2`、アルゴリズムは依然としてそれを純粋に周波数ベクトルとして扱い、順序付けとは関係なく、再構成によって候補を正しくテストします。 

いつ$n$33 のように大きい場合、繰り返し変換が不安定に見える可能性があります。 フィンガープリント構造は、同じ決定論的マッピングを繰り返し適用することでこれを処理します。 反転は試みられないため、深さがあいまいになりません。 

隠れた数字が観測されたマルチセット内で最も頻度の高い値または最も頻度の低い値である場合、アルゴリズムは常に 9 つの候補すべてを対称的にテストし、事前計算された有効空間内のセットのメンバーシップのみに依存するため、均一に動作します。
