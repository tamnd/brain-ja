 ## 解決策
 ## 問題の理解

 複数のスティックの長さのセットが与えられているので、それらすべてを原点から始まるポリラインに配置する必要があります。 各スティックはこのポリラインの 1 つのセグメントになり、すべてのセグメントは軸に揃えられている必要があります。つまり、水平または垂直のいずれかになります。 唯一の構造上の制約は、方向が交互になる必要があるため、連続する 2 つのスティックを両方とも水平にしたり、両方とも垂直にしたりすることはできません。 

この交互ルールに従って、スティックの順序を自由に変更したり、方向を選択したりできます。 ポリライン自体が幾何学的に重なり合う可能性がありますが、最適な構築によりそれが回避されます。 目標は、すべてのスティックを配置した後、原点から最終終点までのユークリッドの二乗距離を最大化することです。 

主要な出力は単一の整数、つまり (0, 0) からのエンドポイントの二乗距離です。 

n が 100000 までの制約により、どのような解もおよそ O(n log n) または O(n) 時間かかります。 順列を調べたり方向を単純に割り当てたりしようとすると、階乗または指数関数的な時間が必要になり、すぐに失敗します。 2^n が大きすぎるため、サブセットに対する動的計画法さえ不可能です。 

微妙なエッジケースは、n のパリティと長さの分布から生じます。 すべてのスティックが等しい場合、または 1 つの非常に大きなスティックがある場合、バランスを計画せずに方向を切り替える単純な貪欲な割り当てにより、最適でない投影が生成される可能性があります。 たとえば、常に最も長いスティックを最初に一方向に割り当てると、全長が固定されている場合でも、最終的な変位が減少するキャンセル効果が生じる可能性があります。 

## アプローチ

 直接的な総当たりアプローチでは、スティックのすべての並べ替えと、交互を考慮した水平および垂直方向のすべての割り当てが試行されます。 構成ごとにポリラインをシミュレートし、エンドポイントを計算します。 これは、すべての有効な構造を探索するので正しいですが、n! が必要です。 順列、および順列を無視した場合でも 2^n 方向の選択が可能ですが、n が 20 を超えると実行不可能になります。 

重要な観察は、最終的な位置が符号付き水平変位の合計と符号付き垂直変位の合計にのみ依存するということです。 交互制約は、正確に ⌈n/2⌉ のスティックが 1 つの軸に配置され、 ⌊n/2⌋ がもう 1 つの軸に配置されることを意味しますが、どのスティックをどの軸に配置するかは自由に選択できます。 

二乗距離 x^2 + y^2 を最大化するには、x と y の絶対値を独立して最大化する必要があります。 方向によって符号が反転する可能性があるため、重要なのはスティックを 2 つのグループに分割し、その合計の大きさができるだけ大きくなるようにすることです。 これは古典的なパーティショニングのアイデアになります。つまり、両方のグループが大きな合計を得るように、戦略的に最大のスティックを割り当てます。 

最適な構成は、スティックを降順にソートし、それらを x グループと y グループに交互に割り当てることです。 これにより、両方の合計ができるだけ大きく保たれます。これは、大と大のペアを使用すると、どちらの軸も寄与が枯渇することがないためです。

 ## アルゴリズムのチュートリアル

 1 つは水平方向の寄与、もう 1 つは垂直方向の寄与の 2 つの合計を構築することに焦点を当てます。 

1. すべてのスティックの長さを降順に並べ替えます。 これにより、軸間で分配するときに常に大きなスティックを最初に考慮することが保証されます。 
2. 2 つのアキュムレータを初期化します。1 つは水平合計用、もう 1 つは垂直合計用です。 
3. ソートされたリストを繰り返し処理します。 最初のスティックを水平、2 番目を垂直、3 番目を水平、というように交互に割り当てます。 これにより、両方のグループがバランスのとれた方法で大きな要素を受け取ることが保証されます。 
4. 分配後、二乗距離をhorizo​​ntal_sum^2 +vertical_sum^2として計算します。 
5. この値を出力します。

交互割り当てが機能する理由は、2 つの競合する合計のバランスを効果的にとっているためです。 すべての大きなスティックを 1 つの軸に割り当てると、もう 1 つの軸が小さくなりすぎます。また、目的は 2 次であるため、不均衡により総二乗和が減少します。 

### なぜ効果があるのか

 最終エンドポイントは、2 つの直交する軸に沿った独立した寄与によって決定されます。 方向記号を自由に選択できるため、割り当てられたサブセットに可能な限り最大の長さの合計が含まれる場合、各軸の寄与が最大になります。 ソートされたリストを交互に使用することは、両方のサブセットが同等の高価値の要素を確実に受け取ることを保証する貪欲な方法です。 大きな要素を 1 つの軸にクラスタリングする偏差は、関数が座標間の不均衡で凸であるため、x^2 + y^2 を厳密に減少させます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

a.sort(reverse=True)

x = 0
y = 0

for i, v in enumerate(a):
    if i % 2 == 0:
        x += v
    else:
        y += v

print(x * x + y * y)
```このソリューションでは、まずすべてのスティックの長さを読み取り、降順で並べ替えて、より大きな寄与が先に配置されるようにします。 次に、水平方向と垂直方向の合計を表す 2 つのアキュムレータに交互に代入します。 この交互配置は、ステップごとに方向を切り替える必要があるという制約の下で、最適な軸の割り当てをエンコードします。 最後に、標準の式 x^2 + y^2 を使用して二乗ユークリッド距離を計算します。 

よくある間違いは、グループ分けを決める前に標識や指示を割り当てようとすることです。 正しい抽象化は、最初に各軸に入る合計の長さを決定し、その後で符号を適用することです。そのため、貪欲なパーティションで十分です。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))
    a.sort(reverse=True)

    x = 0
    y = 0
    for i, v in enumerate(a):
        if i % 2 == 0:
            x += v
        else:

 ## 特殊なケース

 すべてのスティックが同じ値を持つ場合、ソートによってシーケンスは変更されませんが、交互にはほぼ均等な分割が保証されます。 たとえば、入力 4 4 4 4 では、x = 8 および y = 8 が生成され、128 が得られます。不均衡があると二乗和が減少します。 

支配的な大きなスティックが 1 つと小さなスティックが多数ある場合、大きなスティックを 1 つの軸に単独で配置するのが最適です。これは、その寄与の希薄化を防ぐためです。 貪欲な順序付けでは、最初に配置されるため、これが自然に保証され、その後の小さな値によってバランスが大きく歪むことはありません。 

n が奇数の場合、1 つの軸は必然的にもう 1 つのスティックを受け取ります。 ソートにより、この追加の割り当てが現在最大の部分和をすでに持っている軸に確実に割り当てられるため、二乗目標に対する不均衡の影響が最小限に抑えられます。
