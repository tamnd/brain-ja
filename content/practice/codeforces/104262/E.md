 ## 解決策
 ## 問題の理解

 完全な重み付きグラフが与えられます。$N$各頂点は岩を表します。 費用$C_{i,j}$石を直接接着する場合の価格です$i$岩の隣に$j$。 目標は、すべての岩がちょうど 2 つの隣接する岩になるように、すべての岩を円形の順序で配置することであり、サイクル内の各隣接のコストを支払います。 総コストは、最後の岩から最初の岩までのリングを閉じるエッジを含む、このサイクル内のすべての連続するペアのコストの合計です。 

したがって、タスクはすべての順列を選択することです$N$岩石をサイクルとして解釈し、そのサイクル内の隣接エッジ コストの合計を最小化します。 

制約は小さいですが、$N \le 12$これは、指数関数的な状態探索が可能であることを直ちに示します。 すべての順列に対する階乗解 (大まかに言うと)$12! \approx 4.8 \times 10^8$、すでに境界線に達していますが、単純に実行すると Python ではまだ大きすぎます。 どのソリューションでも、対称性を圧縮するか、サブセットに対して動的プログラミングを使用する必要があります。 

重要な構造観察は、サイクルが回転対称であることです。 同じ配置を循環的に回転させると同じコストが発生するため、総当りの順列カウントでは次の係数が無駄になります。$N$。 さらに重要なのは、単に順列が必要なだけではなく、閉じたサイクルを確保する必要があるということです。これにより、最初の要素と最後の要素の間に依存関係が導入され、単純な貪欲または増分構造が壊れます。 

すべてのコストが同一またはゼロである場合、微妙なエッジケースが発生します。 このような場合、どのサイクルも最適ですが、終了エッジの追加を忘れたり、エッジを二重にカウントしたりする単純なアルゴリズムでは、依然として不正確な結果が生成されます。 たとえば、次の場合$N=4$すべてのコストがゼロであれば、正解はゼロです。 サイクルを閉じずに連続するペアを合計するだけのバグのあるソリューションも、ここでゼロを出力してバグを隠してしまうため、経験的にチェックするのではなく、構造的に正確さを強制する必要があります。 

最適なサイクルが一意ではない場合、別のエッジ ケースが発生します。 たとえば、非対称なローカル選択でも、グローバルに最適なサイクルを生成できます。 局所的な最小エッジはグローバルに一貫したサイクルを保証しないため、最近傍を早期に修正する貪欲なアプローチは失敗します。 

## アプローチ

 最も直接的なアイデアは、岩石の可能な順序をすべて列挙し、対応するサイクルのコストを計算することです。 各順列について、合計します。$C_{p_i, p_{i+1}}$プラスラップアラウンドエッジ$C_{p_{N}, p_1}$。 これは、すべての有効なサイクルを明示的に評価するため、正しいです。 ただし、必要なのは$N!$順列と$O(N)$順列ごとに働くため、$O(N \cdot N!)$、これは$N=12$実現可能な限界をはるかに超えています。 

このアプローチの冗長性は、同じ部分的な順序が多くの置換で現れるという事実から来ています。 選択した頂点のプレフィックスが固定されると、残りの構造はどの頂点がまだ使用されていないのか、どの頂点が現在パスの終端にあるのかによってのみ決まります。 これは状態圧縮のアイデアを示唆しています。完全な順列を追跡する代わりに、サブセットを追跡します。 

これは当然、ビットマスク動的プログラミングの定式化につながります。 頂点のサブセットを選択し、現在特定の頂点で終了していることを表す状態を定義します。 状態に保存されるコストは、それらの頂点をある順序で正確に訪問し、その頂点で終了するパスを形成するための最小コストです。 トランジションは、未使用の頂点を 1 つ追加することでパスを拡張します。 

最終的な答えはサイクルを閉じることで得られます。すべての頂点が使用されたら、最後の終点から開始頂点に戻り、最後のエッジを追加します。 

これにより、階乗順列の問題が次のように軽減されます。$O(N^2 2^N)$状態、これは容易に実現可能です$N \le 12$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース順列 |$O(N \cdot N!)$|$O(N)$| 遅すぎる |
 | パス上のビットマスク DP |$O(N^2 2^N)$|$O(N 2^N)$| 承認済み |

 ## アルゴリズムのチュートリアル

 回転対称性を取り除くための開始点として 1 つの頂点を固定します。 一般性を失わずに、サイクルの開始点として頂点 0 を選択します。 すべての有効なサイクルは、0 から始まるように回転できます。 

DP テーブルを定義します。`dp[mask][i]`は 0 から開始し、正確に頂点を訪問するための最小コストを表します。`mask`、頂点で終了`i`。 

1. DP テーブルを無限大で初期化します。 セット`dp[1 << 0][0] = 0`コストなしで頂点 0 から開始するためです。 
2. 頂点 0 を含むすべてのマスクを反復処理します。各マスクと各エンドポイントに対して`i`マスク内でトランジションを試みます。 
3. 現在の状態ごとに`(mask, i)`、頂点を追加してパスを延長してみてください`j`入っていない`mask`。 新しい状態は次のようになります`(mask | (1 << j), j)`、コストは次のように増加します`C[i][j]`。 更新します`dp`可能な最小値で。 
4. すべての状態を処理した後、以下の状態のみを考慮します。`mask`すべての頂点が含まれます。 考えられる終了頂点ごとに`i`、コストを追加してサイクルを終了します`C[i][0]`。 
5. 答えは、そのようなすべてのフルマスク エンドポイントの最小値です。 

開始頂点の固定が機能する理由は、コストを変更せずに任意のサイクルを回転して 0 から開始できるためです。 これにより、異なるローテーションにおける同一サイクルの冗長なカウントが削除され、状態空間が 1 分の 1 に削減されます。$N$。 

## なぜ機能するのか

 すべての DP 状態で、次の不変条件が維持されます。`dp[mask][i]`の頂点を正確に訪れるすべてのパスの最小コストです。`mask`そしてで終わります`i`。 すべての遷移は、未使用の頂点を 1 つだけ追加することによって有効性を維持するため、無効な再訪問は発生しません。 

頂点 0 から始まるすべての順列は DP 遷移の 1 つのシーケンスに正確に対応するため、0 から始まるすべての可能なハミルトニアン パスが表現されます。 最後にサイクルを閉じると、欠落している最終エッジが正しく考慮されます。また、各サイクルには 0 から始まる代表値があるため、最適なサイクルが考慮されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    c = [list(map(int, input().split())) for _ in range(n)]
    
    INF = 10**18
    dp = [[INF] * n for _ in range(1 << n)]
    
    dp[1][0] = 0
    
    for mask in range(1 << n):
        if not (mask & 1):
            continue
        for i in range(n):
            if not (mask & (1 << i)):
                continue
            cur = dp[mask][i]
            if cur == INF:
                continue
            for j in range(n):
                if mask & (1 << j):
                    continue
                nmask = mask | (1 << j)
                val = cur + c[i][j]
                if val < dp[nmask][j]:
                    dp[nmask][j] = val
    
    full = (1 << n) - 1
    ans = INF
    for i in range(n):
        ans = min(ans, dp[full][i] + c[i][0])
    
    print(ans)

if __name__ == "__main__":
    solve()
```DP テーブルは、到達不能な状態が最小遷移を妨げないように、大きなセンチネル値で初期化されます。 開始状態はマスクを使用します`1`頂点 0 のみが含まれるためです。 

マスク、現在のエンドポイント、および次の頂点にわたる 3 つのループが、コアの遷移エンジンです。 部分パスの可能なすべての拡張を、繰り返しを行わずに系統的に試行します。 

最後のループは、開始頂点に戻ることによってサイクルを明示的に閉じ、循環構造が完全に考慮されていることを確認します。 

ここでよくある間違いは、パスが一貫して 0 から始まることを強制するのを忘れることです。 これがないと、同じサイクルの回転が複数回カウントされますが、冗長な計算はあるものの、最小値は正しいままになります。

 ## 特殊なケース

 重要なエッジケースの 1 つは次のような場合です。$N=2$。 DP はまだ機能しますが、可能なサイクルは 0 → 1 → 0 の 1 つだけです。状態遷移は決して分岐せず、最終的な答えは単純です。$C_{0,1} + C_{1,0}$。 DP テーブルには関連する状態が 2 つだけ含まれており、終了ステップで戻りエッジが明示的に追加されるため、アルゴリズムはこれを自然に処理します。 

もう 1 つのケースは、すべてのコストがゼロの場合です。 すべてのハミルトニアン サイクルのコストはゼロであり、DP はすべての状態にゼロを伝播します。 最終的な最小値は、パスの選択に関係なくゼロのままであり、アルゴリズムがタイブレークに依存していないことが確認されます。 

3 番目のケースは、1 つのエッジが他のエッジに比べて極端に大きい場合です。 DP は、考えられるすべての遷移を常に考慮し、完全なパス全体の最小値を保持するため、これを正しく回避します。 たとえローカルに安価なエッジがグローバルに高価な完了をもたらしたとしても、状態空間探索により、代替ルートが評価され、安価であれば選択されることが保証されます。
