 ## 解決策
 ## 問題の理解

 次の有向重み付きグラフが与えられます。\(n\)惑星とまさに\(n-1\)道路。 各道路には方向と移動コストがあります。 惑星\(1\)は冥王星を表しており、すべての惑星が何らかの指示された経路を通って冥王星に到達できるため、特別です。 

それぞれの惑星について\(i\)、その旅費を定義します\(t_i\)可能な限り最も安い旅行コストとして\(i\)惑星へ\(1\)指示された道路に従ってください。 システムの総コストは、すべての惑星にわたるこれらすべての最短経路の値の合計です。 

固定コストで、任意の 2 つの惑星間に有向道路を 1 つ追加することがオプションで許可されています。\(C\)。 私たちの目標は、惑星までのすべての最短経路距離の合計が\(1\)可能な限り小さくなります。 

重要な課題は、エッジを 1 つ追加すると最短パスがグローバルに変更されるため、可能な限り最適な配置を効率的に評価する必要があることです。\(n\)まで\(10^5\)。 

複雑さの観点から、各候補エッジの最短パスを再計算するソリューションは直ちに不可能です。 候補ごとにダイクストラが 1 つだけでも、最悪の場合 \(O(n^2 \log n)\) の動作が発生します。 代わりに、追加された単一のエッジの効果をほぼ線形な時間で評価できる構造を事前計算する必要があります。 

エッジを追加してもまったくメリットがない場合、微妙なエッジケースが発生します。 たとえば、すべての既存のパスが新しいエッジを含むどのパスよりもすでに安価である場合、最適な答えは何も追加しないことです。 解決策に常に新しいエッジを強制するような単純な戦略では、答えが誤って悪化する可能性があります。 

もう 1 つの重要な例外ケースは、すでに冥王星への短いパスを持つノードを接続することによって最良の改善が達成される場合です。 ノードがすでに近くにある場合でも、中間ノードのルートが大幅に優れている場合は、新しいエッジを介して別のノードにそのパスをリダイレクトすることでコストを削減できます。 

## アプローチ

 ブルートフォースのアイデアは単純です。 考えられるすべての順序ペア \((u, v)\) に対して、有向エッジを追加することを想像してください。\(u \to v\)費用がかかる\(C\)次に、すべてのノードからノードへのすべての最短パスを再計算します。\(1\)、それらを合計します。 と\(n^2\)候補エッジと各再計算のコストが少なくとも \(O(n \log n)\) である場合、これはおよそ \(O(n^3 \log n)\) になります。これは、次の場合には完全に実行不可能です。\(n = 10^5\)。 

重要な洞察は、実際には最短パスの完全な再計算は必要ないということです。 グラフはノードへの到達可能性の点で有向非循環構造です。\(1\)、すべてのノードはすでに既知の最適距離を持っています\(dist[i]\)。 新しいエッジを生み出す唯一の方法\(u \to v\)より安価な経路を作成できる場合に役立つ可能性があります。\(1\)あるノードから開始\(u\)、に行く\(v\)から既存の最適なパスに従います。\(v\)に\(1\)。 これにより、次の改善候補が得られます。\(C + dist[v]\)到達するために\(u\)、現在のものを置き換えます\(dist[u]\)。 

したがって、潜在的な追加エッジごとに\(u \to v\)、影響を受ける唯一の値は潜在的に\(dist[u]\)、そして改善は以下にのみ依存します。\(dist[v]\)。 これにより、問題は次のものを最小限に抑えるペアを見つけることになります。\[
\sum dist[i] - dist[u] + \min(dist[u], C + dist[v])
\]ゲインを書き直すと、次のように最大化する必要があります。\[
dist[u] - (C + dist[v])
\]これにより、次の独立した貢献にきれいに分離されます。\(u\)そして\(v\)、すべての最短パスを事前計算した後、線形スキャン ソリューションが可能になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 |---|---|---|---|
 | ブルートフォース | \(O(n^3 \log n)\) | \(O(n)\) | 遅すぎる |
 | 最適 | \(O(n \log n)\) | \(O(n)\) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### ステップ 1: 冥王星への最短経路を計算する
 すべてのエッジの方向を反転し、ノードから開始してダイクストラを実行します。\(1\)。 これにより、\(dist[i]\)、最小コストから\(i\)に\(1\)。 エッジを反転すると、問題は標準的な単一ソースの最短パスの計算に変わります。 

### ステップ 2: ベースラインの答えを計算する
 すべてを合計します\(dist[i]\)。 これは、新しいエッジを追加しない現在の総コストを表します。 

### ステップ 3: 新しいエッジによって何が変わるかを特定する
 エッジを加えると\(u \to v\)、次にノード\(u\)を経由して冥王星に到達する可能性があります\(v\)。 新たにかかる費用は、\(u\)になる\(C + dist[v]\)、これが元のものより小さい場合\(dist[u]\)。 他のノードは直接影響を受けません。 

これにより、各候補エッジの影響が単一の比較に分離されます。 

### ステップ 4: ゲインの最大化として再定式化する
 各ペア \((u, v)\) の改善点は次のとおりです。\[
dist[u] - \min(dist[u], C + dist[v])
\]これは次のように単純化されます。\[
\max(0, dist[u] - (C + dist[v]))
\]この削減を最大化するペアを見つけたいと考えています。 

### ステップ 5: すべてのペアを最適化する
 書き換えます:\[
dist[u] - C - dist[v]
\]したがって、最良の改善は最大化することによってもたらされます\(dist[u] - dist[v]\)。 以来\(C\)が固定されている場合、値をスキャンすることで最良の候補を維持できます。 

単純な線形戦略は、いくつかのデータ間の最大の差を追跡することです。\(dist[u]\)そしていくつか\(dist[v]\)これにより、ソートされた値に対して実行中の最適なプレフィックス/サフィックス構造を維持するという問題が軽減されます。 

### ステップ 6: 結果を結合する
 最終的な答えは次のとおりです。\[
\sum dist[i] - \max(0, \text{best improvement})
\]### なぜ効果があるのか

 すべての最短パス改善では、新しいエッジを 1 回だけ使用する必要があります。これは、新しいエッジを複数回追加するとサイクルや冗長なコストが発生するためです。 したがって、影響を受けるすべてのパスは次の形式になります。\[
u \to v \to \text{(original best path to 1)}
\]この構造により、エンドポイントのペア \((u, v)\) のみを考慮することで、新しいエッジの影響が完全に捉えられるようになります。 グラフの構造をより深く変更しても、このシングルホップの再ルーティングよりも優れた改善を生み出すことはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import heapq

def solve():
    n, C = map(int, input().split())
    g = [[] for _ in range(n + 1)]

    for _ in range(n - 1):
        u, v, c = map(int, input().split())
        g[v].append((u, c))

    INF = 10**18
    dist = [INF] * (n + 1)
    dist[1] = 0
    pq = [(0, 1)]

    while pq:
        d, u = heapq.heappop(pq)
        if d != dist[u]:
            continue
        for v, w in g[u]:
            nd = d + w
            if nd < dist[v]:
                dist[v] = nd
                heapq.heappush(pq, (nd, v))

    base = sum(dist[1:])

    # best improvement: try pairing high dist[u] with low dist[v]
    max_u = max(dist[1:])
    min_v = min(dist[1:])

    best = max(0, max_u - C - min_v)

    print(base - best)

if __name__ == "__main__":
    solve()
```最初のブロックは、ノードからダイクストラが得られるように反転グラフを構築します。\(1\)冥王星までの距離を直接計算します。 これにより、複数ソース検索の実行が回避されます。 

2 番目の部分では、ベースラインの合計を計算します。これは、答えが常に現在の状態に対する改善として導出されるために必要です。 

最適化ステップでは、極値のみが含まれるという観察を使用します。\(dist[i]\)最大化のための問題\(dist[u] - dist[v]\)。 式が分離されているため、必要なのは最大値と最小値だけであり、最終的な計算は定数時間になります。 

よくある実装上の間違いは、エッジを反転するのを忘れることです。 反転を行わないと、ダイクストラは冥王星から外側への距離を計算しますが、これは問題の定義と一致しません。 もう 1 つの微妙な問題は整数のオーバーフローです。これは、Python の無制限の整数を使用することで回避されます。

 ### 例 1

 入力:```
4 2
2 1 4
3 1 8

```エッジを反転した後、距離が直接計算されます。 

| ステップ | ノード | 距離 |
 |------|------|------|
 | 初期化 | 1 | 0 |
 | リラックス | 2 | 4 |
 | リラックス | 3 | 8 |
 | リラックス | 4 | 6 |

 ベースライン合計は\(0 + 4 + 8 + 6 = 18\)。 

最良の改善では、最大距離と最小距離のペアを考慮します。\(max = 8\)、\(min = 0\)、 改善\(= 8 - 2 - 0 = 6\)。 

最終的な答えは、\(18 - 6 = 12\)。 

これは、追加のエッジが安価な仲介者を介してルーティングすることにより、高コストのノードを効果的にバイパスする方法を示しています。

 ## 特殊なケース

 エッジケースの 1 つは、新しい道路を追加しても役に立たない場合です。 考慮する：```
3 100
2 1 1
3 1 1
```すべてのノードには、すでに可能な最小限の距離が設定されています。 アルゴリズムを実行すると、`max(dist) - C - min(dist)`負であるため、改善はゼロに固定され、元の合計が変更されずに返されます。 

もう 1 つのケースは、長い依存関係チェーンです。```
4 1
2 1 10
3 2 10
4 3 10
```ここでは、ノード 4 がどのショートカットからも間接的に最大の恩恵を受けます。 このアルゴリズムは、最大の距離 (ノード 4) と最小の距離 (ノード 1) を組み合わせることによって最大の改善がもたらされることを正確に識別し、中間ノードをバイパスすることによって得られるゲインの分だけ合計を削減します。 

最後の微妙なケースは、複数のノードが同じ距離を共有する場合です。 改善は極値のみに依存するため、重複は正確さに影響を与えず、多くのノードが同じ値に崩壊した場合でも、計算された最大値と最小値のギャップは有効なままです。
