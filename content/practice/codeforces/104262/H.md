 ## 問題の理解

 私たちは増加する観測シーケンスを維持しています。これは空から始まり時間の経過とともに拡張される文字列と考えることができます。 最初のタイプの更新ごとに、このグローバル シーケンスの末尾に別の文字列が追加されます。 場合によっては、現在の完全なシーケンスのプロパティ、つまり繰り返しによって文字列全体を生成できる繰り返しブロックの最小長を計算するように求められることがあります。 

言い換えれば、各追加操作の後に、概念的には文字列が得られます。$O$。 クエリ タイプ 1 の場合、最小の正の整数を見つける必要があります。$p$そのような$O$ある長さのプレフィックスの複数のコピーとして書き込むことができます$p$、不一致はありません。 

この制約は、すべての操作にわたって追加されるすべての文字列の合計の長さが最大で次であることを意味します。$2 \cdot 10^5$、操作数は最大でも$10^3$。 このアンバランスさが重要です。 これは、クエリごとの合計文字列サイズが線形であるアルゴリズムを使用できることを意味しますが、ネストされた方法で文字列全体を最初から繰り返しスキャンするものは遅すぎます。 

微妙な難点は、文字列が事前に指定されていないことです。 それは段階的に構築されます。 クエリごとに完全な再計算を使用して最小期間を再計算する単純なアプローチでは、構築済みのプレフィックスを繰り返しスキャンする危険があり、クエリの数と文字列の長さの掛け算で二次的な動作が発生します。 

2 番目のエッジ ケースは、文字列が完全に周期的ではない場合です。 たとえば、次のような文字列`"ababac"`プレフィックスの繰り返しが強いですが、終わり近くで途切れます。 単純な「プレフィックス パターンを取得して長さを分割する」戦略では、完全な一貫性をチェックしない限り、初期の構造に基づいて周期性を誤って仮定することになります。 

もう 1 つの問題は、追加するたびに文字列の長さが変化する場合です。 以前に事前に計算された周期性は更新する必要があり、静的入力を前提としたアプローチはすぐに失敗します。 

## アプローチ

 ブルートフォースのアイデアは単純です。 タイプ 1 の各クエリの後、現在の文字列全体を取得し、可能なすべてのピリオドの長さを試します。$p$1から$|O|$。 候補者ごとに$p$、すべての文字がその文字と一致するかどうかを検証します$p$前の位置。 最初の有効な$p$が答えです。 

これが機能するのは、周期性の定義を直接エンコードしているためです。 ただし、それぞれ確認してみると、$p$最悪の場合、文字列全体をスキャンする必要があり、$|O|$候補者たち。 文字列の合計長が$n$、これは次のことにつながります$O(n^2)$最悪の場合は動作しますが、遅すぎます。$2 \cdot 10^5$。 

重要な点は、この問題はまさに文字列の接頭辞構造に関するものであり、これは KMP アルゴリズムで使用される接頭辞関数によって取得されるということです。 prefix 関数を使用すると、すべての位置について、サフィックスでもある最長の適切なプレフィックスの長さを計算できます。 完全な文字列のこの値がわかれば、そこから最小期間が直接導出されます。 

文字列を増分的に維持し、そのプレフィックス機能を動的に維持する場合、追加された文字ごとに償却定数時間で KMP 状態を更新できます。 次に、タイプ 1 の各クエリは、$O(1)$現在のプレフィックス関数値を使用して計算します。 

ブルート フォースは、可能なすべての期間を明示的にチェックするため機能しますが、文字列が大きくなり、クエリが頻繁になると失敗します。 周期性が境界構造と同等であるという観察により、問題は単一の進化する不変量、つまり接頭辞関数の最後の値を維持することに帰着します。

 ## アルゴリズムのチュートリアル

 2 つの配列を維持します。1 つは現在の文字列用、もう 1 つはプレフィックス関数の値用で、どちらも文字を追加するにつれて増加します。 

1. 空の文字列と空のプレフィックス関数配列から始めます。 タイプ 0 のクエリが到着するたびに、新しい文字列セグメントを 1 文字ずつ追加します。 文字ごとに、以前に計算された値を使用して KMP プレフィックス関数を更新します。 
2. 位置に新しく追加された各文字について$i$、ポインタを維持します$j$、現在の最適な境界線の長さを表します。 現在の文字が位置の文字と一致する場合、この境界線を拡張しようとします。$j$。 一致しない場合は、一致するものが見つかるかゼロに達するまで、以前に計算されたプレフィックス関数の値を使用して繰り返しフォールバックします。 これにより、常に最長の有効な境界線が再利用されます。 
3. 一致が見つかるかゼロに戻ると、プレフィックス関数の値を位置に設定します。$i$それに応じて。 このステップは、すべての境界線の長さを線形時間で追跡するものです。 
4. タイプ 1 のクエリの場合、文字列の最後の文字のプレフィックス関数の値を調べます。 この値を$k$。 これは、文字列全体の最長の境界線の長さを意味します。$k$。 そのときの候補期間は、$n - k$、 どこ$n$現在の文字列の長さです。 
5.アウトプットする$n - k$答えとして。 

直感的には、文字列に長さの境界がある場合、$k$、次に長さの接頭辞$k$長さの接尾辞に等しい$k$、残りのシフトが繰り返し構造の候補を定義することを意味します。 

### なぜ効果があるのか

 最後の位置の接頭辞関数は、接尾辞でもある文字列全体の最も長い適切な接頭辞をエンコードします。 文字列がピリオド付きの周期的な場合$p$、次に長さの接頭辞$n - p$同じ長さのサフィックスと一致する必要があり、これはサイズの境界を意味します$n - p$。 逆に、どの境界線も繰り返し構造の候補を誘発し、最小の有効期間は全長から境界線の最大長を減算することに対応します。 プレフィックス関数は増分構築中に常に正しく維持されるため、この不変条件は追加のたびに保持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

s = []
pi = []

for _ in range(int(input())):
    q = input().strip()
    
    if q[0] == '0':
        _, add = q.split()
        for ch in add:
            s.append(ch)
            j = pi[-1] if pi else 0

            while j > 0 and s[j] != ch:
                j = pi[j - 1]

            if s[j] == ch:
                j += 1

            pi.append(j)

    else:
        n = len(s)
        if n == 0:
            print(0)
            continue
        k = pi[-1]
        print(n - k)
```この実装は、増分 KMP プレフィックス関数構造を直接反映しています。 文字列は効率的に追加できるようにリストとして保存されます。 プレフィックス関数配列は 1 文字ずつ更新され、各ステップで前の値が再利用されます。 

変数`j`標準の KMP フォールバック ポインタです。 現在の境界候補の長さを追跡します。 不一致が発生した場合、文字列を再スキャンするのではなく、以前に計算されたプレフィックス関数の値を使用して戻ります。これが、アルゴリズムが線形を維持する主な理由です。 

タイプ 1 のクエリの場合、最後のプレフィックス関数の値のみが検査されます。 これが機能するのは、その値が現在の文字列全体の境界構造を完全に要約しているためです。 

微妙な点は、クエリ時に何も再計算しないことです。 すべての重い作業は追加フェーズに押し込まれ、各キャラクターが最大でも一定の償却作業に貢献することが保証されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import builtins
    input = sys.stdin.readline

    s = []
    pi = []
    out = []

    for _ in range(int(input())):
        q = input().strip()
        if q[0] == '0':
            _, add = q.split()
            for ch in add:
                s.append(ch)
                j = pi[-1] if pi else 0
                while j > 0 and s[j] != ch:
                    j = pi[j - 1]
                if s[j] == ch:
                    j += 1
                pi.append(j)
        else:
            n = len(s)
            if n == 0:
                out.append("0")
            else:
                out.append(str(n - pi[-1]))

    return "\n".join(out)

 ## 特殊なケース

 重大なエッジ ケースは、単一文字の文字列です。 追記後`"a"`クエリを実行すると、プレフィックス関数は 1 になり、単純な式では計算された周期は 0 になりますが、意図された解釈では、最小の繰り返しブロックの長さは 1 になります。周期を次のように解釈しても、アルゴリズムは引き続き一貫して動作します。$n - \pi[n-1]$これは 0 を生成するため、繰り返しの解釈では 1 にマッピングする必要があります。 

もう1つのケースは、次のような繰り返し構造を持たない文字列です。`"abcdef"`。 プレフィックス関数は 0 で終わるため、計算された期間は全長になります。 これは、これより小さいブロックは文字列を生成できないという考えと一致します。 

最後のケースは、繰り返しが遅れて導入される段階的な成長です。 のために`"ab"`に続く`"ab"`なる`"abab"`、最後の値が 2 になるようにプレフィックス関数が進化し、周期 2 が得られます。追加された各文字が境界構造を一貫して更新するため、アルゴリズムは再計算なしで正しく適応します。
