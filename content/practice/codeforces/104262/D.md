 ## 解決策
 ## 問題の理解

 私たちは、星とブラック ホールの両方が小さな境界空間内の整数座標に配置される 2D グリッドに取り組んでいます。 星は数えたい点を表しますが、ブラック ホールは近くの星を無効にします。 

各ブラック ホールは、その位置を中心とする 3×3 の正方形内のすべての星を除去します。これは、ブラック ホールから x 方向と y 方向の両方の 1 つのユニット内のすべてのセルが安全でなくなることを意味します。 この削除プロセスの後、複数の四角形のクエリに答えるように求められ、それぞれがその四角形の中に残っている星がいくつあるかを尋ねます。 

主な難しさは、星が重なったり、ブラック ホールの効果が重なったりする可能性があり、すべての除去を適用した後、最大 100,000 のクエリに効率的に答えなければならないことです。 

座標範囲は狭く、両方の次元で 0 ～ 999 です。 これは、オブジェクトの数が多い一方で、ジオメトリは密ではあるが境界があり、多くの場合、動的構造ではなくグリッド前処理またはプレフィックス合計を指していることを示唆しています。 

単純なアプローチでは、すべてのクエリに対してすべての星をチェックし、ブラック ホールによって破壊されているかどうかもテストします。 100,000 個のスターと 100,000 個のクエリでは、10^10 の操作に達する可能性があるため、これでは遅すぎます。 

微妙なエッジケースはブラックホールの重なりです。 たとえば、1 つのブラック ホールが (5,5) にあり、別のブラック ホールが (6,6) にある場合、それらの 3×3 の破壊ゾーンは重なり合います。 単純な実装では、最初にカバレッジを集計せずに直接の近接性のみをチェックする場合、誤って複数回減算したり、影響を受けるすべての星をマークできなかったりする可能性があります。 

もう 1 つの特殊なケースは、星が重なっていることです。 複数の星が同じ座標を共有している場合、破壊されない限り、それらはすべて個別にカウントされます。 グリッドベースのソリューションでは、座標をセットとして扱うのではなく、カウントを蓄積する必要があります。 

最後に、クエリに答える前にブラック ホールの破壊を適用する必要があります。 誤ってクエリを先に処理したり、クエリごとの破壊の評価を遅らせたりすると、結果の一貫性が失われます。 

## アプローチ

 ブルートフォースのアイデアは単純です。 各星について、すべてのブラック ホールをスキャンして、それが少なくとも 1 つの 3×3 破壊領域内にあるかどうかを判断します。 破棄されない場合は保管いたします。 次に、クエリごとに、残りのすべての星をスキャンし、クエリの四角形内の星を数えます。 

これは、破壊とカウントの定義に直接従うため、正しいです。 ただし、複雑さは法外なものになります。 破壊のチェックだけでも O(NM) のコストがかかり、それぞれ 10^5 で 10^10 の操作になります。 たとえわずかに最適化されたとしても、これは限界をはるかに超えています。 クエリ評価を追加すると、コストがさらに倍増します。 

重要な観察は、座標の制約から得られます。 すべての座標は 1000×1000 グリッド内にあるため、固定サイズの配列ですべてを事前計算できます。 星を個別に追跡するのではなく、星を周波数グリッドに集約します。 星ごとの破壊をシミュレートする代わりに、「ブロックされた」セルの 2 番目のグリッドをマークし、ブラック ホールの影響を局所的に伝播します。 両方がグリッド上でエンコードされると、最終的な有効スター グリッドを計算し、O(1) でクエリに答えるための 2D プレフィックス合計を構築できます。 

これにより、問題はイベント処理から静的グリッドの前処理に変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(NM + QN) | O(N) | 遅すぎる |
 | グリッド + プレフィックスの合計 | O(N + M + 1000² + Q) | O(1000㎡) | 承認済み |

 ## アルゴリズムのチュートリアル

 すべての情報を固定の 1000×1000 グリッドに圧縮して、セルごとの操作が一定時間になるようにします。 

1. 2D 配列を構築する`stars[x][y]`各座標に星がいくつ存在するかを数えます。 これが必要なのは、複数の星が同じ位置を占める可能性があり、多重性を維持する必要があるためです。 
2. 2 番目の 2D 配列を構築する`bad[x][y]`ゼロに初期化されます。 これにより、少なくとも 1 つのブラック ホールの影響を受けたすべてのセルがマークされます。 
3. (x, y) の各ブラック ホールについて、(x−1, y−1) から (x+1, y+1) までの正方形内のすべてのセルを不良としてマークし、境界をグリッドの制限に固定するように注意します。 これによりブラック ホールの効果が明示的に拡張されるため、後で星ごとにチェックする必要がなくなります。 すぐに展開する理由は、幾何学的条件を事前計算されたブール グリッドに変換するためです。 
4. 最終的なグリッドを構築する`valid[x][y]`と等しくなるように`stars[x][y]`セルが不良でない場合はゼロ、そうでない場合はゼロ。 このステップでは、破壊を単純なフィルターにまとめます。 
5. 2D プレフィックス合計を構築します。`valid`。 各プレフィックス セルには、(0,0) から (x,y) までの長方形内の有効な星の累積合計が格納されます。 これにより、定数時間の四角形クエリが有効になります。 
6. 各クエリ四角形 (x1、y1、x2、y2) について、x1 ≤ x2 および y1 ≤ y2 になるように座標を正規化し、プレフィックス グリッドで包含-除外を使用して合計を計算します。 

### なぜ効果があるのか

 正しさは関心事を分離することから生まれます。 ブラック ホールの効果は局所的な近傍にのみ依存するため、クエリを考慮する前に完全に解決できます。 破壊をグリッド上の静的マスクに変換すると、残る問題は純粋に固定行列に対する 2D 範囲合計クエリです。 プレフィックス合計不変条件により、クエリされた四角形内ですべてのセルの寄与が正確に 1 回カウントされ、プレフィックス構築前に明示的にゼロ化されるため、破壊されたセルが寄与しないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAX = 1000

def main():
    N, M, Q = map(int, input().split())

    stars = [[0] * MAX for _ in range(MAX)]
    bad = [[0] * MAX for _ in range(MAX)]

    for _ in range(N):
        x, y = map(int, input().split())
        stars[x][y] += 1

    for _ in range(M):
        x, y = map(int, input().split())
        for dx in (-1, 0, 1):
            for dy in (-1, 0, 1):
                nx, ny = x + dx, y + dy
                if 0 <= nx < MAX and 0 <= ny < MAX:
                    bad[nx][ny] = 1

    valid = [[0] * MAX for _ in range(MAX)]
    for i in range(MAX):
        for j in range(MAX):
            if not bad[i][j]:
                valid[i][j] = stars[i][j]

    pref = [[0] * (MAX + 1) for _ in range(MAX + 1)]

    for i in range(1, MAX + 1):
        for j in range(1, MAX + 1):
            pref[i][j] = (
                valid[i - 1][j - 1]
                + pref[i - 1][j]
                + pref[i][j - 1]
                - pref[i - 1][j - 1]
            )

    def query(x1, y1, x2, y2):
        x1, x2 = min(x1, x2), max(x1, x2)
        y1, y2 = min(y1, y2), max(y1, y2)
        x1 += 1
        y1 += 1
        x2 += 1
        y2 += 1
        return (
            pref[x2][y2]
            - pref[x1 - 1][y2]
            - pref[x2][y1 - 1]
            + pref[x1 - 1][y1 - 1]
        )

    out = []
    for _ in range(Q):
        x1, y1, x2, y2 = map(int, input().split())
        out.append(str(query(x1, y1, x2, y2)))

    print("\n".join(out))

if __name__ == "__main__":
    main()
```実装は、重複が自然に処理されるように、スターを周波数グリッドに圧縮することから始まります。 ブラック ホール ステップでは、3×3 の近傍を明示的に描画するため、後で幾何学的チェックを繰り返す必要がなくなります。 プレフィックス合計配列は、境界処理を簡素化するために 1 つのインデックスを使用して構築されています。これが、すべてのクエリ座標が 1 ずつシフトされる理由です。 包含/除外式は標準的な 2D 範囲合計の恒等式であり、クエリが O(1) になる唯一の理由です。 

ここでよくある間違いは、座標が包括的で小さいことを忘れていることです。 もう 1 つは、ブラック ホールの影響をクランプできず、インデックス エラーが発生することです。 もう 1 つの微妙な問題は、スターを上書きせずに蓄積し忘れることです。

 サンプル入力の使用:

 まず星型グリッドを構築し、影響を受けるすべてのセルにマークを付けます。 

| ステップ | アクション | 鍵の状態 (概念的) |

| 3 | 星をフィルターする | 影響を受けるゾーンの外にある星だけが残ります |

完全なグリッド クエリの場合`2 2 9 9`、生き残っているすべての星が数えられ、8が得られます。 

これらのトレースは、破棄がクエリごとではなく、クエリの前にグローバルに適用されることを示しています。

 ## 特殊なケース

 重大なエッジケースは、ブラックホールの重なり合いです。 一方が (5,5) にあり、もう一方が (6,6) にある場合、アルゴリズムは両方の 3x3 近傍内のすべてのセルをマークします。 2 番目のマーキングでは、何も元に戻したり二重にカウントしたりすることはありません。`bad[x][y]`ブール値です。 これにより、重なりの順序に関係なく、最終的なマスクが安定します。 

もう 1 つのエッジ ケースは、ブラック ホールの 3×3 領域の境界に正確に位置する星です。 (2,2) のブラック ホールの場合、(1,3) の星は両方の軸の 1 つのユニット内にあるため、依然として削除されます。 dx と dy に対する明示的なループにより、すべての境界セルが含まれることが保証されます。 

最後に、グリッド全体をカバーするクエリは、プレフィックスの合計がすべての有効なスターを正しく蓄積するかどうかをテストします。 包含-排他構造により、多くの星が座標を共有している場合でも、過剰にカウントされることはありません。
