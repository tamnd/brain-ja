 ## 解決策
 ## 問題の理解

 可変文字列と一連のクエリが与えられます。 各クエリは、特定の位置の文字を変更するか、メイン文字列の特定の部分文字列内の部分文字列として小さい文字列が何回出現するかを尋ねます。 文字列とすべてのクエリには 1 から始まるインデックスが付けられ、部分文字列の出現は重複する可能性があります。 

入力サイズは大きく、メイン文字列は最大 100,000 文字、クエリは最大 100,000 個まで可能です。 各部分文字列クエリのクエリ文字列の合計長は、すべてのクエリの合計で最大 100,000 になります。 すべてのクエリの部分文字列をスキャンする素朴な解決策では、大まかに |substring| を検査します。 × |y| クエリごとの文字数。 最悪の場合、これは 10^5 × 10^5 = 10^10 の操作となり、6 秒の制限には大きすぎます。 

エッジケースは微妙です。 たとえば、重複する出現をカウントする必要があります。 もし`s = "aaaaa"`そして私たちはクエリします`y = "aa"`文字列全体では、「aa」が位置 1、2、3、および 4 から始まるため、正しいカウントは 4 です。`str.count`または`find`重複を注意深く処理しないと 2 が返されますが、これは間違っています。 もう 1 つのエッジ ケースは、文字が最近更新された位置を含む部分文字列クエリです。 後続の部分文字列カウントが現在の文字列状態を反映するように、更新が正しく伝播されることを確認する必要があります。 

## アプローチ

 ブルート フォースのアプローチは簡単です。タイプ 2 のクエリごとに部分文字列を抽出し、左から右にスキャンして、各位置でクエリ文字列が一致するかどうかを確認します。 長さの部分文字列の場合`m`および長さのクエリ文字列`k`、これには O(m × k) のコストがかかります。 10^5 クエリの場合、これは非常に遅くなります。 

重要な洞察は、すべてのクエリ文字列の長さの合計が 10^5 で制限されるという観察から得られます。 つまり、個別のクエリ文字列ごとに情報を事前計算すれば、複数の部分文字列クエリにまたがる作業を償却できるということです。 具体的には、メイン文字列内で各クエリ文字列が出現する位置を追跡できます。 タイプ 1 の更新が発生した場合、変更された文字が一致に影響を与える可能性がある位置のみを調整する必要があります。 これにより、クエリ文字列から開始位置の並べ替えられたリストへのマッピングを使用するソリューションが自然に得られ、これにより、二分検索で、指定された範囲内に一致する数を効率的にカウントできるようになります。 

次の観察を使用します: 文字列の一致`y`位置から開始`i`更新によりいずれかの変更が行われた場合にのみ無効になります。`len(y)`で始まる文字`i`。 逆に、更新された文字を含む位置から新しい一致が表示される場合もあります。 ソートされた出現リストで二分検索を使用すると、クエリ範囲内に一致する数を簡単にカウントできます。

 | ブルートフォース | O(q × n × k) | O(n) | 遅すぎる |
 | 最適 | O(q × log(n) × | y | _max) 償却 |

 ## アルゴリズムのチュートリアル

 1. 文字列とクエリを解析します。 O(1) 更新を許可するために、文字列を文字のリストとして維持します。 
2. すべての一意のクエリ文字列を特定する`y`タイプ 2 クエリ全体。 文字列ごとに`y`、初期文字列内のすべての開始位置を事前計算します。`y`が発生し、それらをソートされたリストに保存します。 
3. 各クエリについて:

 - 位置でのタイプ 1 更新の場合`i`文字をに変更する`c`、文字列を更新します。 次に、クエリ文字列ごとに`y`、からのポジションを検討します`i - len(y) + 1`に`i`潜在的に影響を受ける可能性があるため。 境界内のこれらの位置のそれぞれについて、次のことを確認します。`y`一致するようになりました。 変更前に一致が存在し、一致しなくなった場合は、リストから削除します。 新しい一致が見つかった場合は、並べ替え順序を維持したままリストに挿入します。 
- タイプ 2 クエリの場合は、クエリ文字列の開始位置の並べ替えられたリストに対して二分検索を使用します。`y`指定された部分文字列内に開始位置がいくつあるかをすばやくカウントするには`[l, r - len(y) + 1]`。 これにより、出現回数が効率的に得られます。 
4. すべてのタイプ 2 クエリのカウントを出力します。 

これが機能する理由: 不変条件は、並べ替えられたリストが各クエリ文字列の現在の文字列内のすべての開始位置を常に正確に反映することです。 二分探索により、指定された範囲内での正確なカウントが保証され、ローカライズされた更新により、影響を受ける位置のみがチェックされるため、更新の効率が維持されます。 

## Python ソリューション```python
import sys
import bisect
input = sys.stdin.readline

s = list(input().strip())
n = len(s)
q = int(input())
queries = []
query_strings = set()

for _ in range(q):
    parts = input().split()
    if parts[0] == '1':
        queries.append((1, int(parts[1])-1, parts[2]))
    else:
        l, r, y = int(parts[1])-1, int(parts[2])-1, parts[3]
        queries.append((2, l, r, y))
        query_strings.add(y)

occurrences = {}
for y in query_strings:
    occ = []
    m = len(y)
    for i in range(n - m + 1):
        if ''.join(s[i:i+m]) == y:
            occ.append(i)
    occurrences[y] = occ

for query in queries:
    if query[0] == 1:
        idx, c = query[1], query[2]
        s[idx] = c
        for y in query_strings:
            m = len(y)
            start = max(0, idx - m + 1)
            end = min(n - m, idx)
            occ_list = occurrences[y]
            for i in range(start, end + 1):
                slice_now = ''.join(s[i:i+m])
                pos = bisect.bisect_left(occ_list, i)
                exists = pos < len(occ_list) and occ_list[pos] == i
                if slice_now == y and not exists:
                    occ_list.insert(pos, i)
                elif slice_now != y and exists:
                    occ_list.pop(pos)
    else:
        l, r, y = query[1], query[2], query[3]
        occ_list = occurrences[y]
        m = len(y)
        left = bisect.bisect_left(occ_list, l)
        right = bisect.bisect_right(occ_list, r - m + 1)
        print(right - left)
```このソリューションでは、文字列をリストとして読み取り、O(1) 更新を許可します。 出現位置を事前計算すると、繰り返されるクエリ文字列の再スキャンが回避されます。 更新を処理する際には、変更の影響を受ける可能性のある位置のみがチェックされるため、無駄な作業が軽減されます。 ソートされたリストの二分検索により、範囲内の出現数のカウントが高速になります。 インデックス付けと包含/排他範囲の処理には細心の注意が必要です。
