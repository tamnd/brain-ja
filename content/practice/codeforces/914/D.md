 ## 解決策
 ## 問題の理解

 2 種類の操作をサポートする配列を維持します。 

最初の操作ではセグメントについて尋ねます。`[l, r]`そして値`x`。 セグメント全体の gcd が正確になるように、そのセグメント内の最大 1 つの要素を変更できるかどうかを知りたいのです。`x`。 

2 番目の操作は、1 つの配列位置を永続的に更新します。 

課題は、配列サイズとクエリ数の両方が非常に大きいことです。 配列には最大で次のものが含まれます`5 · 10^5`要素があり、最大で`4 · 10^5`操作。 すべてのクエリに対してセグメント全体をスキャンするソリューションは、直ちに不可能です。 最悪の場合のセグメント長は次のとおりです。`5 · 10^5`したがって、クエリごとのリニアスキャンには約`2 · 10^11`操作。 

重要な観察は、「変更は最大 1 つの要素」というフレーズの中に隠されています。 

セグメントの最終的な gcd を次のようにしたいとします。`x`。 変更されていないすべての要素は次の式で割り切れる必要があります。`x`これは、gcd がセグメントのすべての要素を分割するためです。 2 つの異なる位置が次の数で割り切れない場合`x`、1 つの変更で両方を修正することはできません。 これは、セグメントに次の要素で割り切れない要素が 1 つだけ含まれている場合にクエリが有効であることを意味します。`x`。 

いくつかの特殊なケースは見落とされがちです。 

考慮する：```
3
6 12 18
1
1 1 3 6
```すべての要素は次のように割り切れます。`6`、したがって、答えは次のとおりです`YES`。 何も変更する必要はありません。 「変更が 1 つまで」という表現には、変更がゼロのものも含まれます。 

次に、次のことを考えてみましょう。```
3
6 10 15
1
1 1 3 5
```のみ`6`で割り切れない`5`。 その単一の要素を次のように変更した後、`5`、セグメントは次のようになります。`[5,10,15]`、その gcd は`5`。 答えは`YES`。 

ついに：```
3
6 10 14
1
1 1 3 5
```両方`6`そして`14`で割り切れない`5`。 1 つの変更で両方を割り切れるようにすることはできません`5`、したがって、答えは次のとおりです`NO`。 

よくある間違いは、現在のセグメント gcd が何らかの方法で次のように変換できるかどうかを確認することです。`x`。 実際の条件は、次の要素で割り切れない要素の数によって異なります。`x`、現在の gcd だけではありません。 

## アプローチ

 ブルートフォースソリューションはクエリを処理します`(l, r, x)`セグメント内のすべての要素をスキャンし、次の要素で割り切れない要素がいくつあるかを数えます。`x`。 

論理は正しいです。 カウントが 1 までの場合は応答します`YES`; それ以外の場合は答えてください`NO`。 

問題はスピードです。 セグメントには以下が含まれる場合があります`5 · 10^5`要素が含まれる可能性があります`4 · 10^5`クエリ。 最悪の場合、これはおおよそ次のようになります`2 · 10^11`可分性チェック。 

「悪い」要素をもっと速くカウントする方法が必要です。 

重要な観察は、次のように割り切れることです。`x`gcd を通じて検出できます。 任意の範囲について、範囲 gcd が次の値で割り切れる場合`x`の場合、その範囲内のすべての要素は次の数で割り切れます。`x`。 

これは、範囲 gcd を格納するセグメント ツリーを示唆しています。 

セグメントを調べるとします。`[l, r]`。 

もし`gcd(l, r)`で割り切れます`x`の場合、セグメント内のすべての要素は次のように割り切れます。`x`、答えはすぐにわかります`YES`。 

それ以外の場合、セグメント内のどこかに、次の要素で割り切れない要素が存在します。`x`。 

すべての要素をチェックする代わりに、セグメント ツリーを下降します。 ノードの gcd が次の値で割り切れるときは常に`x`、その区間全体がクリーンであり、スキップできることがわかります。 gcd が次で割り切れないノードのみに進みます。`x`。 

問題となる要素を複数発見するとすぐに停止します。 

これにより、問題は次の要素の数が次の要素の数で割り切れるかどうかを調べることに変わります。`x`は最大でも 1 つです。 セグメント ツリーを使用すると、大きなクリーン インターバルはすぐに破棄されるため、これらの要素を効率的に見つけることができます。 

更新は、標準的なセグメント ツリー ポイントの更新です。

 ## アルゴリズムのチュートリアル

 1. すべてのノードがその間隔の gcd を保存するセグメント ツリーを構築します。 
2. 更新クエリの場合`(i, y)`、位置に対応するリーフを更新します`i`そして、ルートに戻るパス上の gcd 値を再計算します。 
3. 確認クエリの場合`(l, r, x)`、セグメントに次の要素で割り切れない要素が 1 つだけ含まれているかどうかを判断します。`x`。 
4. セグメント ツリーを再帰的に走査します。 
5. 現在のノード間隔が交差しない場合`[l, r]`、不良要素を返しません。 
6. 現在のノードが完全に含まれている場合`[l, r]`そして、その格納された gcd は次で割り切れます。`x`、不良要素を返しません。 

その区間内のすべての要素は次のように割り切れます。`x`, したがって、そこに不快な要素は存在できません。 
7. 現在のノードが単一の位置を表し、その gcd が次の値で割り切れない場合`x`、不良要素を 1 つ返します。 
8. それ以外の場合は、2 つの子に分割して検索を続けます。 
9. 不良要素の実行数を記録します。 カウントが 1 を超えた瞬間に探索を停止し、1 より大きい値を返します。 
10. トラバース後、応答します`YES`カウントが最大 1 の場合、それ以外の場合は応答します`NO`。 

### なぜ効果があるのか

 任意の間隔について、その gcd が次で割り切れる場合`x`の場合、その区間内のすべての要素は次の数で割り切れます。`x`。 このような間隔には不正な要素を含めることはできず、完全に無視できます。 

ノード gcd が次の値で割り切れないときは常に`x`、その区間内の少なくとも 1 つの要素が次の値で割り切れません。`x`、そのため、その子に降りる必要があります。 

再帰は最終的に、値が次の値で割り切れない葉に正確に到達します。`x`。 アルゴリズムはそれらをカウントし、複数のものが見つかると停止します。 

セグメントは gcd を持つように変換できます`x`最大 1 つの要素が次の要素で割り切れない場合にのみ、最大 1 つの変更を使用します。`x`。 このような要素が 2 つ以上ある場合は、それぞれを変更する必要がありますが、これは不可能です。 そのような要素が 0 つまたは 1 つある場合、その 1 つの要素を適切に変更すると、常にセグメント全体の gcd が次のようになります。`x`。 

## Python ソリューション```python
import sys
from math import gcd

input = sys.stdin.readline

class SegmentTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.seg = [0] * (4 * self.n)
        self._build(1, 0, self.n - 1, arr)

    def _build(self, node, left, right, arr):
        if left == right:
            self.seg[node] = arr[left]
            return

        mid = (left + right) // 2
        self._build(node * 2, left, mid, arr)
        self._build(node * 2 + 1, mid + 1, right, arr)
        self.seg[node] = gcd(
            self.seg[node * 2],
            self.seg[node * 2 + 1]
        )

    def update(self, node, left, right, idx, value):
        if left == right:
            self.seg[node] = value
            return

        mid = (left + right) // 2

        if idx <= mid:
            self.update(node * 2, left, mid, idx, value)
        else:
            self.update(node * 2 + 1, mid + 1, right, idx, value)

        self.seg[node] = gcd(
            self.seg[node * 2],
            self.seg[node * 2 + 1]
        )

    def count_bad(self, node, left, right, ql, qr, x):
        if left > qr or right < ql:
            return 0

        if self.seg[node] % x == 0:
            return 0

        if left == right:
            return 1

        mid = (left + right) // 2

        res = self.count_bad(
            node * 2,
            left,
            mid,
            ql,
            qr,
            x
        )

        if res > 1:
            return res

        res += self.count_bad(
            node * 2 + 1,
            mid + 1,
            right,
            ql,
            qr,
            x
        )

        return min(res, 2)

def solve():
    n = int(input())
    arr = list(map(int, input().split()))

    st = SegmentTree(arr)

    q = int(input())
    ans = []

    for _ in range(q):
        query = list(map(int, input().split()))

        if query[0] == 1:
            _, l, r, x = query
            bad = st.count_bad(1, 0, n - 1, l - 1, r - 1, x)
            ans.append("YES" if bad <= 1 else "NO")
        else:
            _, idx, value = query
            st.update(1, 0, n - 1, idx - 1, value)

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```セグメント ツリーには、間隔ごとに 1 つの値、つまり gcd が格納されます。 ツリーの構築には直線的な時間がかかります。 

更新操作は完全に標準です。 1 つのリーフを変更し、ルートに戻りながら gcd 値を再計算します。 

興味深い部分は、`count_bad`。 ノード gcd が次の値で割り切れるときはいつでも、`x`、区間全体がクリーンであることがわかっているため、再帰はすぐに停止します。 この枝刈りにより、ソリューションが迅速化されます。 

戻り値の上限は次のとおりです`2`。 クエリでは、問題のある要素の数が次のとおりであるかどうかのみが考慮されます。`0`、`1`、または少なくとも`2`。 それ以上を数える理由はありません。 

ツリー内のすべてのインデックスは 0 から始まりますが、入力は 1 から始まります。 変換`l - 1`、`r - 1`、 そして`idx - 1`は不可欠です。 

Python の整数は、次の値まで簡単に処理できます。`10^9`したがって、オーバーフローが心配されることはありません。

## テストケース```python
import sys
import io
from math import gcd

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    class SegmentTree:
        def __init__(self, arr):
            self.n = len(arr)
            self.seg = [0] * (4 * self.n)
            self.build(1, 0, self.n - 1, arr)

        def build(self, p, l, r, arr):
            if l == r:
                self.seg[p] = arr[l]
                return
            m = (l + r) // 2
            self.build(p * 2, l, m, arr)
            self.build(p * 2 + 1, m + 1, r, arr)
            self.seg[p] = gcd(self.seg[p * 2], self.seg[p * 2 + 1])

        def update(self, p, l, r, idx, val):
            if l == r:
                self.seg[p] = val
                return
            m = (l + r) // 2
            if idx <= m:
                self.update(p * 2, l, m, idx, val)
            else:
                self.update(p * 2 + 1, m + 1, r, idx, val)
            self.seg[p] = gcd(self.seg[p * 2], self.seg[p * 2 + 1])

        def query(self, p, l, r, ql, qr, x):
            if l > qr or r < ql:
                return 0
            if self.seg[p] % x == 0:
                return 0
            if l == r:
                return 1
            m = (l + r) // 2
            res = self.query(p * 2, l, m, ql, qr, x)
            if res > 1:
                return res
            res += self.query(p * 2 + 1, m + 1, r, ql, qr, x)
            return min(res, 2)

    n = int(input())
    arr = list(map(int, input().split()))
    st = SegmentTree(arr)

    q = int(input())
    out = []

    for _ in range(q):
        t = list(map(int, input().split()))
        if t[0] == 1:
            _, l, r, x = t
            out.append(
                "YES"
                if st.query(1, 0, n - 1, l - 1, r - 1, x) <= 1
                else "NO"
            )
        else:
            _, i, y = t
            st.update(1, 0, n - 1, i - 1, y)

    return "\n".join(out)
