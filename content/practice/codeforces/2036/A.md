 ## 解決策
 ## 問題の理解

 ここでのメロディーは、単なる整数ピッチの短いシーケンスです。 各ピッチは 0 ～ 127 の整数であり、重要なのは絶対値ではなく、隣接するノート間の差です。 

単純な構造特性をチェックするように求められます。シーケンス内のすべての隣接するペアについて、それらの値の絶対差は 5 または 7 でなければなりません。メロディーのすべてのトランジションがこのルールに従っている場合、メロディーは有効であるとみなされ、そうでない場合は拒否されます。 

各テスト ケースは独立しているため、タスクは複数の小さな配列のチェックを繰り返します。 各メロディーのサイズは小さく、最大 50 音符であり、テスト ケースは最大 1000 個あるため、単純なペアごとのチェックでも快適に高速です。 

隠された変換やグローバル制約はありません。 唯一の微妙な点は、条件が符号付きの差ではなく絶対差に基づいていることを覚えておくことです。 10 から 17 および 17 から 10 のような遷移は、どちらも結果の差が 7 であるため、両方とも有効です。 

単純な実装における典型的な間違いは、絶対値を忘れたり、差の一方向のみをチェックしたりすることです。 誰かが誤って連続した音符の差ではなく等しいことをチェックした場合、別の問題が発生します。 

エッジケースはほとんどが最小​​限の長さです。 メロディーにちょうど 2 つの音符がある場合、1 つの音程のみがチェックされます。 たとえば、入力`[1, 6]`差は 5 なので有効ですが、`[1, 7]`差が 6 であるため無効ですが、これは許可されていません。 

## アプローチ

 ブルートフォースアプローチは定義とほぼ同じです。 各メロディーについて、すべての隣接するペアを反復処理し、それぞれの違いが 5 または 7 であるかどうかを確認します。いずれかのペアが条件に違反する場合、そのメロディーは直ちに拒否されます。 

各メロディーには最大で 50 個の音符があるため、このアプローチではテスト ケースごとに最大 49 件の比較が実行され、最大で 1000 件のテスト ケースが実行され、最悪の場合約 50,000 回の操作が行われます。 これはすでに簡単なことなので、高度な最適化は必要ありません。 

ここには実際のアルゴリズムのトリックは隠されていません。 重要な観察は、単に条件がローカルであるということです。すべての制約には連続する 2 つの要素のみが含まれるため、問題全体は単一パスの検証に帰着します。 共有エンドポイントを越えた異なるペア間には依存関係がないため、動的プログラミングや前処理は必要ありません。

 ## アルゴリズムのチュートリアル

 各メロディーを個別に処理し、シングルパスで検証します。 

1. テスト ケースの数を読み取ります。 各テスト ケースは 1 つのメロディーを記述します。 
2. 各メロディーについて、音符の数と整数のリストを読み取ります。 
3. 2 番目の音符から最後の音符までを繰り返します。 
4. 各インデックス i について、a[i] と a[i−1] の差の絶対値を計算します。 これにより、方向に関係なく、連続するノート間の間隔がキャプチャされます。 
5. この差が正確に 5 であるか正確に 7 であるかを確認します。そうでない場合は、メロディーが無効であると直ちに結論付けます。 
6. 違反が見つからずにループが終了した場合、メロディーはすべての制約を満たしており、有効です。 

重要な設計上の選択は、障害時の早期終了です。 無効なインターバルが 1 つ見つかったら、メロディー全体を無効にするのに 1 つの違反で十分であるため、シーケンスの残りの部分をスキャンし続ける必要はありません。 

### なぜ効果があるのか

 問題内のすべての要件は独立しており、隣接するペアに対してローカルです。 メロディーは、すべてのローカル制約が満たされる場合にのみ有効です。 アルゴリズムは、各制約を 1 回だけ直接強制します。 どのステップもシーケンスを変更したり、将来の決定に依存したりしないため、有効なシーケンスが誤って拒否されたり、無効なシーケンスが受け入れられたりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))

    ok = True
    for i in range(1, n):
        diff = abs(a[i] - a[i - 1])
        if diff != 5 and diff != 7:
            ok = False
            break

    print("YES" if ok else "NO")
```このソリューションは、単純なストリーミング検証として構成されています。 各テスト ケースは独立して処理され、現在の配列を超えたものを保存することは避けられます。 

重要な実装の詳細は、`abs(a[i] - a[i - 1])`。 絶対値がないと、負の差が符号に応じて誤って合格または不合格となります。 もう 1 つの重要な詳細は、初期の`break`これにより、違反を検出したらすぐに停止することが保証されます。

## テストケース```python
import sys, io

def solve():
    import sys
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        ok = True
        for i in range(1, n):
            d = abs(a[i] - a[i - 1])
            if d != 5 and d != 7:
                ok = False
                break

        out.append("YES" if ok else "NO")

    print("\n".join(out))

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from contextlib import redirect_stdout
    import io as _io
    buf = _io.StringIO()
    with redirect_stdout(buf):
        solve()
    return buf.getvalue().strip()

 ## 特殊なケース

 1 つのエッジ ケースは、可能な限り最小のメロディーの長さ、n = 2 です。たとえば、次のように入力します。`0 5`間隔が 1 つだけ存在し、ルールに一致するため、YES を返す必要があります。 ループが 1 回実行され、その 1 つの違いが検証されるため、アルゴリズムはこれを正しく処理します。 

もう 1 つのケースは、方向を交互に切り替えながら有効なステップ サイズを維持するシーケンスです。`0 5 0 5`。 違いは 5、5、5 ですべて有効なので、メロディーは合格します。 アルゴリズムは単調な動きを想定していないため、当然これをサポートしています。 

失敗のケースは、単一の無効な遷移が途中で現れる場合です。 例えば`0 5 10 18`には差 5、5、および 8 があります。10 から 18 へのステップでは差は 8 であるため、すぐに拒否がトリガーされます。 早期に終了することで、誤って続行したり違反を見落としたりすることがなくなります。
