 ## 解決策
 ## 問題の理解

 入力は、数字のいくつかの長方形グリッドを記述します。 各グリッドは概念的に、外側の境界線から始まって内側に向かって、同心の「リング」またはレイヤーに分割されます。 その境界に沿って時計回りに歩くと、すべてのレイヤーが閉じたサイクルを形成します。 

このようなサイクルごとに、その正確な走査順序で数字を読み取ることを想像します。 グリッドのすべての層にわたって、これらの循環文字列に連続シーケンス「1543」が何回出現するかを数えるように求められます。 

重要な詳細は、各層が独立していることです。外側のリングが最初に読み取られ、次に削除され、次の内側の長方形が新しい外側のリングになります。 合計の答えは、すべてのレイヤーにわたる出現の合計です。 

制約により、テスト ケースごとに線形または線形に近い解決策が強制されます。 すべてのグリッドにわたるセルの合計数は最大でも 10^6 であるため、各セルを一定の回数だけ処理するアプローチはどれでも受け入れられます。 レイヤー文字列を繰り返し再計算したり、レイヤー境界ごとに繰り返しスキャンを実行したりするものは、最悪の場合、特に約 500 のレイヤーがある 1000 x 1000 のようなグリッドの場合、二次的な動作を引き起こす危険があります。 

単純なアプローチでは、各レイヤーを文字列に明示的に抽出し、「1543」の部分文字列検索を実行します。 これはすでに安全そうに見えますが、層ごとに中間リストを繰り返しスライスまたは再構築すると、抽出の実行方法に微妙な非効率が現れます。 Python では、レイヤー構築中に不注意に連結するとパフォーマンスが大幅に低下する可能性があります。 

2 番目の、より危険な落とし穴は、レイヤーが循環していることを忘れていることです。 パターン「1543」は、線形化されたレイヤー表現の境界を越えてラップすることができます。 たとえば、レイヤーが「1」で終わり、「543」で始まる場合、パターンは存在しますが、ラップアラウンドを明示的に処理しない限り、ラップされていないシーケンスのストレート部分文字列チェックではパターンが見逃されます。 

エッジケースの例:

 グリッド層の走査:`... 5 4 3 1`線形部分文字列の出現のみをチェックすると、シーケンスが実際には循環している場合に「1543」が表示されることを見逃してしまいます。 

正しく処理するには、各レイヤーを循環として扱うか、長さ 3 のプレフィックスを最後に連結してラップをシミュレートする必要があります。 

## アプローチ

 ブルートフォースのアイデアは簡単です。各層について、その完全な時計回りの走査を数字のリストに抽出し、それをスキャンして「1543」の出現を探します。 各レイヤーを独立して処理し、その文字列を明示的に構築すると、レイヤーごとの合計作業量は周囲の長さに比例します。 すべてのレイヤーを合計すると、すべてのセルは正確に 1 つのレイヤーに属するため、抽出だけでも全体で O(nm) になります。 

問題は、パターンをどのように検索するかという点にあります。 レイヤーごとの単純な文字列検索はレイヤー サイズが線形であるため、問題ありません。 実際の非効率性は、非効率的にレイヤーを繰り返し再構築したり、ループ内でスライス操作を繰り返したりした場合に現れます。 これにより、定数が劣化したり、隠れた二次関数の動作が発生したりする可能性があります。 

重要な観察は、レイヤーのトラバーサルではローカルな隣接関係を超えるものはまったく必要ないということです。 実行中にトラバースをシミュレートし、最後の 4 桁のローリング ウィンドウを維持できます。 これにより、完全な文字列を完全に構築する必要がなくなりました。 各セルは 1 回だけアクセスされ、各更新は O(1) です。 

また、各レイヤーをサイクルとして扱うことにより、循環性を自然に処理します。走査の終了後、最後の 3 桁を先頭に対してチェックする必要があります。 循環シーケンス上のローリング ハッシュ ウィンドウにより、これがきれいに解決されます。 

したがって、最適な解決策は、長さ 4 のスライディング ウィンドウを維持しながら、レイヤー境界ごとに 1 つのパスになります。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. マトリックスを外側から内側に剥がして層を特定します。 各レイヤーは、上の行、右の列、下の行、および左の列の境界によって定義されます。 
2. 各レイヤーについて、その境界を時計回りの順序で移動し、数字のストリームを生成します。 
3. この走査で見られる最後の 4 桁のローリング バッファを維持します。 
4. バッファーが長さ 4 に達するたびに、シーケンス「1543」と比較します。 一致する場合は、答えをインクリメントします。 
5. 走査は周期的であるため、レイヤーの終了後、そのレイヤーの最初の 3 桁を取得し、それらを論理的に継続してラップアラウンド チェックをシミュレートします。 
6. すべてのレイヤーが処理されるまで続行します。 

重要な考え方は、レイヤーの完全な文字列を明示的に構築しないということです。 境界に沿った動きのみをシミュレートし、局所的なパターンを確認します。 

### なぜ効果があるのか

 レイヤー内の「1543」の出現は、そのレイヤーの巡回トラバーサル内の 4 つの連続する位置に対応する必要があります。 走査順序にわたってスライディング ウィンドウを維持することにより、すべての可能な開始位置が 1 回だけチェックされます。 周期的な性質は概念的にトラバースを拡張することによって処理され、終了と開始の間の境界を横切るパターンもカウントされるようになります。 各レイヤーは独立していて完全にカバーされているため、出現が見逃されたり二重にカウントされたりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

TARGET = "1543"

def count_layer(mat, top, bottom, left, right):
    seq = []

    # top row
    for j in range(left, right + 1):
        seq.append(mat[top][j])

    # right column
    for i in range(top + 1, bottom + 1):
        seq.append(mat[i][right])

    # bottom row
    for j in range(right - 1, left - 1, -1):
        seq.append(mat[bottom][j])

    # left column
    for i in range(bottom - 1, top, -1):
        seq.append(mat[i][left])

    if len(seq) < 4:
        return 0

    # simulate cyclic behavior by extending first 3 chars
    ext = seq + seq[:3]

    count = 0
    window = []

    for ch in ext:
        window.append(ch)
        if len(window) > 4:
            window.pop(0)
        if len(window) == 4 and "".join(window) == TARGET:
            count += 1

    return count

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n, m = map(int, input().split())
        mat = [input().strip() for _ in range(n)]

        top, bottom = 0, n - 1
        left, right = 0, m - 1

        ans = 0

        while top <= bottom and left <= right:
            ans += count_layer(mat, top, bottom, left, right)
            top += 1
            bottom -= 1
            left += 1
            right -= 1

        out.append(str(ans))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このソリューションでは、各レイヤーの境界を時計回りの順序で抽出し、個別に処理します。 の`count_layer`関数は、単一のリングをフラット化し、最初の 3 文字を最後に追加することによるラップアラウンド処理を含む、ターゲット パターンの出現をチェックする役割を果たします。 

層状剥離`solve()`各セルが正確に 1 つのリングに属し、境界が内側に正しく縮小されることが保証されます。

 ## 特殊なケース

 小さいながらも重要なケースは、唯一のレイヤーが長さ 4 のサイクルを形成する最小の 2x2 グリッドです。アルゴリズムはそれをシーケンスに変換し、最初の 3 文字を追加して、ラップアラウンド検出が確実に機能するようにします。 この拡張がないと、トラバースの最後のセルで始まる「1543」のようなパターンが見逃されてしまいます。 

別のケースは、薄い長方形のリング、たとえば 2 x m です。 ここでは、トラバースは垂直方向の辺のない 2 つの行に退化します。 この構築では、右列と左列のループが空になり、アルゴリズムが自然に水平サイクルに戻るため、依然として有効な循環シーケンスが生成されます。
