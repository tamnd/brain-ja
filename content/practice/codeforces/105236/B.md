 ## 解決策
 ## 問題の理解

 整数グリッド上に 2 つの点が与えられ、それぞれが円形の影響の中心として機能します。 各中心の周囲で、特定のユークリッド半径内のすべての格子点の値は、-1 を乗算することで反転されます。 すべてのグリッド点には最初は何らかの正の数が含まれていますが、重要なのはそれが奇数回反転されるか偶数回反転されるかだけです。 両方の循環操作の後、セルが 2 つのディスクの一方の内側に正確に存在する場合、セルは負になります。 

したがって、タスクは幾何学的な質問になります。2 つの円のうちの 1 つの円の内側にある整数格子点を見つけるか、そのような点は存在しないと報告するかです。 答えの座標も絶対値が最大 3×10⁹ 以内になければなりません。 

制約は大きく、座標と半径は最大 10⁹ です。 これにより、円内のグリッド点を列挙したり、境界ボックス内のすべての整数点を反復したりするアプローチは除外されます。これは、単一の円でも約 r² の格子点をカバーできるため、これは実行可能な制限をはるかに超えています。 

微妙な故障モードは、円がほぼ同一であるか、一方の円がもう一方の円の中に完全に含まれている場合に現れます。 このような場合、変な報道をしても意味がないかもしれません。 

たとえば、両方の中心が一致し、半径が等しい場合、すべての点は 2 回または 0 回反転されるため、有効な点は存在せず、答えは −1 −1 でなければなりません。 オーバーラップ構造をチェックせずに常に境界近くの点を選択しようとする単純な戦略では、円の内側に何かが誤って出力されてしまいます。 

もう 1 つのエッジ ケースは、ほぼ完全な封じ込めです。一方の円が厳密に他方の円の内側にある場合、小さい円の影響を受けるすべての点は大きい円の影響も受けるため、やはり単独でカバーされる領域は存在しません。 

## アプローチ

 強引なアイデアは、両方の円を含む境界ボックス内のすべての整数点を反復処理し、各点が正確に 1 つの円内にあるかどうかを確認し、最初の有効な点を返すことです。 すべての有効な答えはその領域内に存在する必要があるため、これは原理的には正しいですが、境界ボックスの辺の長さは最大 2×10⁹ なので、約 10¹⁸ の候補点が得られます。 円に限定したとしても、半径 r の円内の整数点の数は Θ(r²) であり、直接チェックするには多すぎます。 

重要な観察は、特定の点は必要なく、2 つの円盤の対称差に点が存在するだけでよいということです。 2 つの凸領域の対称的な差分は空であるか、境界に隣接する構造を含んでいます。 エリア内を検索する代わりに、ジオメトリから導出された候補点の有限セットのみを検索できます。 

重要な点は、有効な点が存在する場合、少なくとも 1 つの円の境界上、またはその境界線のすぐ近くに点が存在する必要があるということです。 より正確には、カバレッジの変化は円の境界を横切るときにのみ発生するため、有効な答えは円の中心付近の点と整数方向のいくつかの極端なオフセットの間で見つかります。 

これは建設的なアプローチにつながります。つまり、中心から導出された候補点の小さなセットを試し、各候補について、それが正確に 1 つの円内にあるかどうかを検証します。 どれも機能しない場合は、対称差は空であると安全に結論付けることができます。これは、一方の円がもう一方の円に含まれている場合、またはそれらが同一である場合にのみ発生します。 

円間の包含は中心と半径の間の距離によってチェックできるため、空のケースを明示的に検出することができ、そうでない場合は、半径の差によって一方の中心から他方の中心に向かって移動することによって境界監視点を構築できます。

 ## アルゴリズムのチュートリアル

各円をユークリッド空間の中心および半径として扱います。 円を C1 と C2 とします。 

1. 中心間の二乗距離を計算します。 これにより、浮動小数点の精度の問題が回避され、すべてが整数に保たれます。 すべての比較は単調であるため、正方形の形式で十分です。 
2. 一方の円がもう一方の円に完全に含まれているかどうかを確認します。 距離(center1, center2) + r1 ≤ r2 の場合、円 C1 は C2 の内側にあります。 これがどちらの方向にも当てはまる場合、小さい方の円でカバーされるすべての点は大きい方の円でもカバーされるため、奇数のカバーを持つ点は存在しません。 
3. いずれかの方向で包含が成立し、円が同一であるか入れ子になっている場合は、-1 -1 を出力します。 これは、対称差分が空であるすべてのケースを処理します。 
4. それ以外の場合、円が入れ子になっていないことがわかり、その対称差は空ではありません。 次に、候補点を構築します。 center1 から center2 へのベクトルを取得し、概念的に正規化して、center1 から center2 に向かって距離 r1 + 1 または整数近似で r1 だけ移動します。 目標は、円 1 の外側に着地するが、それでも円 2 の外側に留まる可能性が高いほど十分に近い位置に着地すること、または非対称に応じてその逆の場合もあります。 

より単純な決定論的な構築は、マンハッタン方向の点や半径境界の軸に沿った方向など、各中心の周りのオフセットの固定された小さなセットを試し、それらを両方の円に対してテストすることです。 

1. 各候補点について、各中心までの二乗距離が ≤ r² であるかどうかを確認します。 ちょうど 1 つの円の内側にある場合は、すぐに返します。 
2. 機能する候補がない場合 (すでに除外されている縮退対称の場合にのみ発生します)、-1 −1 を出力します。 

### なぜ効果があるのか

 重要な不変条件は、カバレージが異なる点は 2 つのディスクの対称的な差の中に存在する必要があり、ディスクがネストされていない場合、この領域は空ではなく、境界に隣接する整数候補の一定サイズのセットと交差する必要があるということです。 円のメンバーシップは境界を横切る場合にのみ変化し、境界は凸状で連続しているため、離散グリッドには中心間の極値方向近くにウィットネスが含まれている必要があります。 包含チェックでは、完全な重複によりこの推論が失敗するすべてのケースが削除されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def inside(x, y, cx, cy, r2):
    dx = x - cx
    dy = y - cy
    return dx*dx + dy*dy <= r2

def solve():
    x1, y1, r1 = map(int, input().split())
    x2, y2, r2 = map(int, input().split())

    d1 = (x1 - x2) ** 2 + (y1 - y2) ** 2

    # containment checks
    if (x1 == x2 and y1 == y2 and r1 == r2):
        print(-1, -1)
        return

    if d1 <= (r1 - r2) ** 2 and r1 >= r2:
        print(-1, -1)
        return
    if d1 <= (r2 - r1) ** 2 and r2 >= r1:
        print(-1, -1)
        return

    candidates = [
        (x1 + r1, y1),
        (x1 - r1, y1),
        (x1, y1 + r1),
        (x1, y1 - r1),
        (x2 + r2, y2),
        (x2 - r2, y2),
        (x2, y2 + r2),
        (x2, y2 - r2),
    ]

    for x, y in candidates:
        c1 = inside(x, y, x1, y1, r1 * r1)
        c2 = inside(x, y, x2, y2, r2 * r2)
        if c1 ^ c2:
            print(x, y)
            return

    print(-1, -1)

if __name__ == "__main__":
    solve()
```このソリューションでは、浮動小数点エラーを回避するために、まず二乗距離を介してサークルのメンバーシップをエンコードします。 包含チェックでは、対称的な差異が存在しないケースを明示的に排除します。これは正確性にとって重要です。 

候補生成ステップでは、各円の周りの軸に合わせた境界点を使用します。 これが機能するのは、点が正確に 1 つのディスク内に存在する場合、中心からの少なくとも 1 つの境界方向が排他的領域につながる必要があり、これらの極値点がそれらの遷移を捕捉するためです。 

XOR 条件`c1 ^ c2`「ちょうど 1 つの円の内側」を直接エンコードします。

 ## 特殊なケース

 2 つの円が正確に一致する場合、すべての点は 2 回または 0 回反転されます。 アルゴリズムは中心と半径の等価性チェックによってこれを早期に検出し、候補検索が試行されないようにします。 

1 つの円が厳密に別の円の内側にある場合、距離の 2 乗と半径の差の比較により、包含が識別されます。 アルゴリズムはすぐに −1 −1 を出力し、両方の円の内側にある点を返してしまう不正確な境界推測を防ぎます。 

円が遠く離れている場合、封じ込めは失敗し、どちらかの中心の周りの候補点がすぐにもう一方の円の外側に位置し、内部領域を探索する必要なく有効な非対称点が生成されます。
