 ## 問題の理解

 3 つの整数が与えられます$R$、$x$、 そして$y$。 すべての整数セグメントを考慮します$[l, r]$両方のエンドポイントが 1 と 2 の間にあるようにします。$R$。 このようなセグメントごとに、その中の数値が次の数で割り切れる数がいくつあるかを調べます。$y$。 タスクは、正確に含まれるセグメントの数を数えることです。$x$の倍数$y$。 

入力サイズが大きく、すべてのパラメータが最大$10^9$。 これにより、すべてのセグメント、さらにはすべての位置を高密度で反復しようとするソリューションは即座に除外されます。 セグメントの数だけでは、$O(R^2)$、次の場合はまったく実行不可能です。$R$大きいです。 

重要な構造的観察は、次のように割り切れることです。$y$まばらな規則的なパターンを作成します: の倍数のみ$y$案件。 それらの間のすべては、割り切れる数のカウントへの寄与という点で均一に動作します。 

よくある間違いは、各位置を独立して扱い、すべての間隔にわたってカウントを維持しようとすることです。 たとえば、すべてを反復処理する$l$そして拡大する$r$割り切れる要素を数えるのは正しいですが、二次になります。 別の微妙な問題が発生する場合、$x = 0$、セグメントには次の倍数が含まれないため、$y$連続する倍数の間のギャップに存在し、範囲の開始または終了の境界寄与を見逃しがちです。 

## アプローチ

 ブルートフォース手法では、すべてのペアを列挙します。$(l, r)$、各セグメントについて、次の数で割り切れる数を数えます。$y$含まれています。 セグメント内の割り切れる数を数えるには、次のようにします。$O(1)$算術接頭語カウントを使用する:$\lfloor r/y \rfloor - \lfloor (l-1)/y \rfloor$。 これにより、ブルートフォースが行われます$O(R^2)$、それはもう不可能になります$R = 5000$約 2,500 万のセグメントがあるため、次の場合にはまったく使用できません。$10^9$。 

重要な観察は、述語「の倍数」が$y$「セグメント内」は、の倍数にのみ依存します。$y$2つの境界線の間にあります。 すべての整数位置に取り組む代わりに、問題を次の倍数のシーケンスに圧縮することができます。$y$。 各セグメントは、含まれる倍数の数と正確に含まれるセグメントによって決まります。$x$倍数は、正確に異なる開始点と終了点を選択することに対応します。$x$の倍数の出現$y$同時に、ギャップ内のエンドポイントの自由な選択も考慮します。 

の倍数$y$まで$R$位置にあります$y, 2y, 3y, \dots, ky$、 どこ$k = \lfloor R/y \rfloor$。 連続する倍数の間には、パディングのように動作する非倍数の部分があります。 正確に次のセグメント$x$倍数は、ギャップ内の開始点を選択し、含まれる最初の倍数を選択し、次にその倍数まで拡張することによって決定されます。$x$- 番目の次の倍数、そして最後に次のギャップ内のエンドポイントを選択します。 

これにより、一連の倍数と境界ギャップにわたるスライディング ウィンドウ スタイルの組み合わせカウントにカウントが削減されます。

 ## アルゴリズムのチュートリアル

 しましょう$k = \lfloor R/y \rfloor$、内の整数の数$[1, R]$で割り切れる$y$。 また、非倍数の合計数を次のように定義します。$R - k$。 

1. ラインを分割する$1 \dots R$の中へ$k+1$の倍数で区切られた非倍数のブロック$y$。 最初のブロックにはサイズがあります$y-1$、中間ブロックにもサイズがあります$y-1$、最後のブロックのサイズは$R - ky$。 すべてのセグメントは、これらのブロックに対する相対的な開始位置によって一意に決定されるため、この分解は非常に重要です。 
2. 正確に含まれるセグメントを考えます。$x$の倍数$y$。 このようなセグメントは、ブロック内のどこかで開始し、選択した開始複数を含めてから、次のセグメントを含める必要があります。$x-1$最後に含まれる複数の後のどこかで最終的に終了します。 
3. 最初に含まれる複数のインデックスを次のように修正します。$i$、 どこ$1 \le i \le k - x + 1$。 これにより、セグメントに次のものを含めることができます。$x$から始まる連続した倍数$i$。 
4. 固定の場合$i$、左端の選択肢の数$l$直前のギャップ内のポジションの数に等しい$i$- 番目の倍数に加えて、その倍数自体から正確に開始する可能性があります。 これは次の要因に寄与します$y$、あるので$y-1$各倍数の前の整数と倍数自体。 
5. 同様に、右のエンドポイントについても$r$、最後に含まれる倍数がその位置に固定されると、$i + x - 1$、選択肢の数は、その倍数からそのギャップの終わりまでのポジションの数であり、これも約に寄与します。$y$ただし、おそらく最後のブロックが短い境界部分は除きます。 
6. 有効なすべての合計$i$、左右の選択肢からの寄与を乗算し、有効なセグメントの合計数を累積します。 最後の部分ブロックの境界補正は、均一であると仮定するのではなく、正確なギャップ サイズを使用して処理されます。$y$。 

### なぜ効果があるのか

 すべてのセグメントを正確に$x$の倍数$y$長さの開始倍数と終了倍数のスパンの選択に一意に対応します$x$に加えて、セグメントが周囲の非多重ギャップにどの程度まで及ぶかについての独立した選択が可能です。 ギャップへの分解により、セグメントが二重にカウントされることがなくなります。最初と最後に含まれる倍数の同一性によってセグメントの「コア」が一意に決定され、隣接するギャップへの自由な拡張により、考えられるすべての整数エンドポイントが考慮されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    R, x, y = map(int, input().split())
    
    if x == 0:
        # segments with no multiples of y
        k = R // y
        # total segments minus those that include at least one multiple
        # easier: count gaps
        total = 0
        prev = 0
        for i in range(1, k + 1):
            cur = i * y
            gap = cur - prev - 1
            total += gap * (gap + 1) // 2
            prev = cur
        # tail gap
        gap = R - prev
        total += gap * (gap + 1) // 2
        print(total)
        return

    k = R // y
    if k < x:
        print(0)
        return

    # count valid choices of first multiple i
    ans = 0

    for i in range(1, k - x + 2):
        left_block_start = (i - 1) * y + 1
        left_block_end = i * y - 1
        left_choices = i * y - left_block_start + 1

        right_end_multiple = (i + x - 1) * y
        right_block_end = min(R, right_end_multiple + y - 1)
        right_choices = right_block_end - right_end_multiple + 1

        ans += left_choices * right_choices

    print(ans)

if __name__ == "__main__":
    solve()
```コードはケースを区切ります$x = 0$倍数のないセグメントは純粋なギャップ合計として処理されるのが最適であるためです。 連続する倍数間の各ギャップが寄与します$\frac{len \cdot (len+1)}{2}$、そのギャップ内に完全に含まれるすべてのサブセグメントを数えます。 

のために$x > 0$、開始可能な複数のインデックスを反復処理します。 開始位置ごとに、前のギャップに拡張できる有効な左端点の数と、最後に含まれる倍数の後の次のギャップに拡張できる右端点の数を計算します。 これらを乗算すると、最初と最後に含まれる倍数が固定されたすべてのセグメントが得られます。 

微妙な実装の詳細は、最後の倍数の後の最後の部分ブロックを正しく処理することであり、ギャップは$y-1$。 これが理由です`min(R, right_end_multiple + y - 1)`が必要です。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    from math import *

    R, x, y = map(int, sys.stdin.readline().split())

    if x == 0:
        k = R // y
        total = 0
        prev = 0
        for i in range(1, k + 1):
            cur = i * y
            gap = cur - prev - 1

            prev = cur
        gap = R - prev

    if k < x:
        return "0"

    return str(ans)

 ## 特殊なケース

 いつ$x = 0$、完全に倍数間のギャップ内にあるすべてのセグメントが寄与します。 たとえば、$R = 10$、$y = 3$、倍数は 3、6、9 です。ギャップは次のとおりです。$[1,2]$、$[4,5]$、$[7,8]$、 そして$[10,10]$。 各ギャップは独自の内部サブセグメントに独立して寄与し、アルゴリズムは合計します。$\frac{len(len+1)}{2}$ギャップごと。 実装ではこれらのギャップを明示的に反復し、境界セグメントが 1 回だけ含まれるようにします。 

いつ$x > 0$、最初に選択した複数には、右側に十分なスペースが必要です。$x$連続する倍数。 たとえば、次の場合$k = 5$そして$x = 3$、開始インデックス 1、2、および 3 のみが有効です。 ループ`range(1, k - x + 2)`これを正確に強制し、範囲外のアクセスや過剰カウントを防ぎます。
