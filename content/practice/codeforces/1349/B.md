 ## 問題の理解

 いくつかの独立したクエリが与えられます。 各クエリは一連の整数とターゲット値を提供します。$k$。 シーケンスの任意の連続セグメントを繰り返し選択し、そのセグメント内のすべての要素をそのセグメントの中央値で置き換えることができます。 中央値はセグメントを並べ替えた後の中央の要素として定義され、長さが偶数の場合は下側の中央が選択されます。 

問題は、このようなセグメント操作をいくつでも適用した後、配列全体を以下と等しくすることが可能かどうかです。$k$。 

主な問題点は、各操作が非常に非ローカルであることです。単一のセグメント操作は多くの位置を一度に上書きし、書き込まれる値は合計や極値ではなく、そのセグメントの順序統計に依存します。 このため、この問題では多くの可能な状態を追跡する必要があるように感じられますが、制約によりそれは除外されます。 合計あり$n \le 10^5$すべてのセグメントをチェックするだけでも既に 2 次であるため、操作をシミュレートしたりセグメントを明示的に探索したりするソリューションは失敗します。 

よくある微妙な失敗のケースは、中央値演算で新しい値を自由に「作成」できると想定していることから発生します。 たとえば、次の場合$k$最初は表示されませんが、より小さい値とより大きい値を組み合わせて構築することを望むかもしれません。 操作によって生成されるすべての値は、選択されたセグメント内の要素の 1 つである必要があるため、これは不正確です。 中央値は常にそのセグメントの既存の要素です。 

もう 1 つの誤解を招く状況は次のような場合です。$k$配列内に存在しますが、「トラップされている」ようです。 たとえば、たとえ$k$が存在する場合でも、値がその周りにどのように分散されているかによっては、それを配列全体に広げることが常に可能であるとは限りません。

 ## アルゴリズムのチュートリアル

 各クエリを個別に処理します。 

1. アレイをスキャンして、$k$存在します。 存在しない場合は、完全に以下から構成される配列を取得することは不可能であるとすぐに結論付けることができます。$k$。 これは、中央値が常に選択したセグメント内の既存の要素から描画されるという事実からわかります。 
2. より厳密に小さい要素が少なくとも 1 つ存在するかどうかを計算します。$k$。 
3. 厳密に次の値よりも大きい要素が少なくとも 1 つ存在するかどうかを計算します。$k$。 
4. すべての要素がすでに次と等しい場合$k$の場合、操作は必要ないため「YES」を返します。 
5. それ以外の場合、両方がより小さい場合にのみ「YES」を返します。$k$そしてそれより大きい$k$要素が存在します。 片方が欠けている場合は「NO」を返します。 

最後のステップの背後にある直感は、伝播するということです。$k$最初の出現を超えて、次のようなセグメントが必要です。$k$値を再調整した後、中央値として機能します。 このようなリバランスには、次の両側の値が必要です。$k$。 配列が完全に片側にある場合$k$、すると、すべての中央値が同じ側に留まり、$k$どこでも支配的になることはできません。 

### なぜ効果があるのか

 中央値演算では、選択したセグメントの外側に新しい値が導入されることはありません。$k$最初から存在する必要があります。 一度$k$存在する場合、その影響力を拡大する唯一の方法は、中央値が次のように評価されるセグメントを介することです。$k$、より小さい値と大きい値の両方の存在が必要です。$k$。 配列が一方的な場合$k$、すべてのセグメントの中央値も片側のままであり、一様な方向へのさらなる構造変化を防ぎます。$k$配列。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        
        has_k = False
        has_less = False
        has_greater = False
        
        for x in a:
            if x == k:
                has_k = True
            elif x < k:
                has_less = True
            else:
                has_greater = True
        
        if not has_k:
            print("NO")
        elif all(x == k for x in a):
            print("YES")
        else:
            if has_less and has_greater:
                print("YES")
            else:
                print("NO")

if __name__ == "__main__":
    solve()

最終的な決定ロジックは、構造的特徴付けから直接導き出されます。つまり、配列がすでに均一であるか、配列の両側に値が含まれている必要があります。$k$最初の発生を超えた伝播を許可します。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))

        has_k = False
        has_less = False
        has_greater = False

        for x in a:
            if x == k:
                has_k = True
            elif x < k:
                has_less = True
            else:
                has_greater = True

        if not has_k:
            out.append("NO")
        elif all(x == k for x in a):
            out.append("YES")
        else:
            out.append("YES" if (has_less and has_greater) else "NO")

    return "\n".join(out)
