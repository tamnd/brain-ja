 ## 解決策
 ## 問題の理解

 数字の文字列として書かれた数値が与えられます。 1 回の操作で、現在の文字列の任意の場所から 1 桁を削除することも、文字列の右端に 1 桁を追加することもできます。 これらの操作は任意の順序で繰り返すことができます。 

目標は、指定された数値を、先行ゼロなしの 10 進数で書かれた 2 のべき乗に変換することです。 必要な操作の数は最小限に抑え、削除または追加を 1 回の移動としてカウントします。 

この問題を解釈する便利な方法は、数字シーケンスを他の数字シーケンスに再形成できることですが、コストが非常に非対称であることです。数字を削除するとコストが 1 になり、数字を最後にのみ挿入するとコストも 1 になります。 この非対称性が核心的な難しさです。 

この制約では最大 10^4 のテスト ケースが許可され、各数値は最大 10^9 であるため、各入力文字列の桁数は最大 10 です。 これは十分に小さいため、関連するすべてのターゲットと比較することができます。 ボトルネックはテストごとの計算ではなく、候補ターゲットごとに何かを効率的に実行することです。 

素朴な解釈では、変換をシミュレートしたり、文字列に対して BFS を実行したりすることさえあります。 文字列が短い場合でも、状態空間は文字列の長さに応じて指数関数的に増大するため、これはすぐに実行不可能になります。 本当の課題は、中間の文字列が重要ではないことです。 最初の文字列と固定ターゲットの間の関係のみが重要です。 

微妙なエッジケースは、先行ゼロから発生します。 削除により先頭のゼロが作成され、それらが保持されるため、文字列を次のように扱う必要があります。`"01"`そして`"1"`最終的な答えでは先頭のゼロが禁止されている場合でも、さまざまな中間状態として扱われます。 これは、桁を揃えるときに削除をカウントする方法に影響します。 

## アプローチ

 ブルートフォースの考え方は、問題を文字列間の最短パスとして扱うことです。ここで、各ノードは文字列であり、エッジは挿入/削除操作です。 指定された数値から開始して、文字列の 2 のべき乗に到達するまで BFS を実行できます。 

これは正しいですが、まったく実行不可能です。 長さが最大 ​​10 であっても、削除ごとに多くの分岐が作成され、挿入によって可能性がさらに拡張され、巨大な状態グラフが生成されます。 到達可能な文字列の数は組み合わせによって増加し、検索できるほど厳密に制限されません。 

重要な点は、開始番号から外側に向かって検索する必要がないということです。 代わりに、視点を逆転させて、2 のべき乗の候補を固定し、指定された文字列をそれに変換するために必要な操作の数を尋ねます。 

固定ターゲット文字列の場合`T`、元の文字列から数字を削除し、一致する数字を追加できます。`T`。 最適な戦略は、`T`順番に。 そのサブシーケンスは変更せずに保持できます。 それ以外はすべて削除されます。 次に、欠落している接尾辞を追加します`T`。 

したがって、文字列の 2 のべき乗ごとに、`T`、コストは次のようになります。```
deletions = len(S) - LCS(S, T)
additions = len(T) - LCS(S, T)
total = len(S) + len(T) - 2 * LCS(S, T)
```以来`|S| ≤ 10`10^9 までの最大の 2 のべき乗は最大 30 桁なので、約 30 個の候補をテストするだけで済みます。 

10^18 までの 2 の累乗をすべて事前計算します (すべての文字列長を安全にカバーするため)。 つまり候補者は 60 人未満になります。 それぞれについて、単純な 2 ポインター サブシーケンス チェックを介して入力文字列を使用して LCS を計算します。

 ## アルゴリズムのチュートリアル

 1. 2 のすべてのべき乗を文字列として事前計算します。 

最大 10 桁の長さに合理的に一致できる累乗のみが必要ですが、最大 10^18 を維持するのが安全です。 
2. テスト ケースごとに、入力文字列を読み取ります。`S`。 

これを純粋に文字のシーケンスとして扱います。 
3. 答えを無限大として初期化します。 

2 の累乗ごとに改善を試みます。 
4. 2 のべき乗の文字列ごとに`T`、の最長部分列の長さを計算します。`S`に登場する`T`。 

これはスキャンによって行われます`S`左から右へ、貪欲に一致する文字`T`。 

これが機能する理由は、削除によって任意の数字を削除できるため、連続性ではなく順序の保持のみが必要になるためです。 
5. 以下を使用してコストを計算します。`len(S) + len(T) - 2 * matched`。 

これは、一致しない数字の削除を反映しています。`S`一致しない数字を追加します`T`。 
6. 2 の累乗の最小値を求めます。 
7. 結果を出力します。 

### なぜ効果があるのか

 あらゆる固定ターゲットに対して`T`、最良の変換では、次のシーケンスが保持されます。`S`に埋め込むことができます`T`順番に。 任意の数字`S`このサブシーケンスで使用されていない数字は削除する必要があり、その中の数字はすべて削除する必要があります。`T`カバーされていないものは追加する必要があります。 挿入は最後にのみ発生するため、次のように構築します。`T`一致したサブシーケンスの順序は常に達成可能です。 これにより、問題は保存されたサブシーケンスを最大化することになり、これがまさに貪欲マッチングの計算内容となります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

# precompute powers of two as strings
POW2 = []
x = 1
while x <= 10**18:
    POW2.append(str(x))
    x *= 2

def match_len(s, t):
    i = 0
    for ch in s:
        if i < len(t) and ch == t[i]:
            i += 1
    return i

def solve():
    t = int(input())
    for _ in range(t):
        s = input().strip()

        best = float('inf')

        for pw in POW2:
            m = match_len(s, pw)
            cost = len(s) + len(pw) - 2 * m
            best = min(best, cost)

        print(best)

if __name__ == "__main__":
    solve()
```コードは最初に 2 のすべてのべき乗を文字列として構築するため、比較は純粋に文字レベルで行われます。 テスト ケースごとに、入力数値内で指定された 2 の累乗の何桁が順番に一致できるかを計算します。 この一致数は、ターゲットに到達するために入力から何桁削除する必要があるか、また何桁追加する必要があるかを直接決定します。 

貪欲なサブシーケンス マッチャーは、数字を並べ替える必要がなく、最後に削除または追加するだけなので、正しいです。 サブシーケンスの選択後に常に完全なターゲット文字列を再構築するため、追加の制限は影響しません。 

## 実用的な例

 サンプルから 2 つのケースを追跡します。 

### 例 1:`1052`と比較します`1024`。 

| ステップ | Sインデックス | T インデックス | 一致しました |
 | --- | --- | --- | --- |
 | 1 | 1 | 1 | 1 |
 | 2 | 0 | 1 | 1 |
 | 3 | 5 | 1 | 1 |
 | 4 | 2 | 1→2 | 2 |

 このペアの一致したサブシーケンスの長さは 3 です (実際の完全な実行では 3 つの一致が生成されます。1、0、2、4 のアライメントでは 1024 のサブシーケンスの動作が得られます)。 

コストは次のとおりです。`4 + 4 - 2*3 = 2`。 

これは、連続的な配置を強制していないことを示しています。 5 などの桁をスキップするのが最適です。 

### 例 2:`8888`と比較します`8`。 

| ステップ | S 文字 | T 文字 | 一致しました |
 | --- | --- | --- | --- |
 | 1 | 8 | 8 | 1 |
 | 2 | 8 | - | 1 |
 | 3 | 8 | - | 1 |
 | 4 | 8 | - | 1 |

 一致 = 1、つまりコストは`4 + 1 - 2 = 3`。 

これは、アルゴリズムが複数回一致を試みるのではなく、余分な数字をすべて削除することを正しく選択していることを示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    POW2 = []
    x = 1
    while x <= 10**18:
        POW2.append(str(x))
        x *= 2

    def match_len(s, t):
        i = 0
        for ch in s:
            if i < len(t) and ch == t[i]:
                i += 1
        return i

    def solve():
        t = int(input())
        out = []
        for _ in range(t):
            s = input().strip()
            best = float('inf')
            for pw in POW2:
                m = match_len(s, pw)
                best = min(best, len(s) + len(pw) - 2 * m)
            out.append(str(best))
        return "\n".join(out)

    return solve()

 ## 特殊なケース

 エッジ ケースの 1 つは、入力がすでに 2 のべき乗である場合です。 たとえば、入力`128`ターゲットと一致する`128`サブシーケンス全体の長さがあるため、コストはゼロになります。 アルゴリズムはこれを自然に処理します。`len(S) + len(T) - 2*len(S)`ゼロになります。 

もう 1 つのケースは、有用な部分列の重複がない数値です。たとえば、`999999`。 ターゲット向け`8`、一致する桁がないため、コストは`6 + 1 - 0 = 7`、完全な削除と挿入を意味します。 順序どおりに整列する文字がないため、貪欲マッチャーは一致する長さがゼロであることを正確に返します。 

最後の微妙なケースは、2 のべき乗の文字列の一部のみを照合することが最善の戦略である場合です。 例えば`1052`に対して`1024`桁をスキップします`5`全体的に。 部分配列では任意の削除が可能であり、ターゲット内の連続性は決して必要ないため、部分配列の定式化ではこれを自然に捉えています。
