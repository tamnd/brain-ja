 ## 問題の理解

 Polycarp が「好む」正の整数のシーケンスを生成するように求められます。 数値は、3 で割り切れず、数字の 3 で終わらない場合に好まれます。整数が与えられた場合$k$、タスクは、を出力することです。$k$このシーケンスの - 番目の番号。 複数のテスト ケースが提供され、それぞれに個別のテスト ケースが用意されています。$k$。 

入力は次のもので構成されます$t$、テストケースの数、その後に続きます。$t$整数$k$。 それぞれ$k$最大 1000 までの値を指定でき、最大 100 のテスト ケースを含めることができます。 必要な最大数はそれほど多くない (数千台前半) ため、整数を順番に反復処理するなどの単純な方法を使用できます。 この制約により、数百万の数値を検索する必要があるソリューションは除外されますが、目的の数値に到達するまで数値をフィルタリングする線形アプローチは可能になります。$k$- 番目の有効なもの。 

3 で割り切れる数値、または 3 で終わる数値はスキップする必要があるため、明らかではない特殊なケースが発生します。 たとえば、3 つおきの数字が悪いと仮定する単純なアプローチは失敗します。13、23、16 のような数字は、割り算に加えて最後の桁も重要であるため、別の方法でスキップされます。 小さな例がこれを示しています。9 番目のいいね数は 13 や 15 ではなく、14 です。不注意にインデックスを作成すると、ここで簡単に数え間違える可能性があります。 

## アプローチ

 ブルートフォースアプローチは簡単です。 1 から開始して、3 で割り切れる整数をスキップするか、3 で終わる整数を繰り返します。見つかったいいね数の数を数え、次の数に達したら停止します。$k$- 番目。 すべての数値をチェックするため、これは動作することが保証されていますが、次の場合には遅くなる可能性があります。$k$潜在的に複数回の反復処理が必要となるため、非常に大きくなりました。$k$数字。 

重要な観察により、これが単純化されます。 3 で終わる数字、または 3 で割り切れる数字はスキップする必要があります。 にジャンプするための直接的な公式はありません。$k$- 番目の数字は、スキップが不規則であるためです。3 で終わる 10 番目の数字ごとに不良であり、3 で割り切れる 3 番目の数字ごとに不良であり、これらが重なる場合もあります。 ただし、$k \le 1000$、単に数値を順番に生成するだけでも十分高速であり、それ以上の最適化は不要です。 もし$k$はるかに大きい場合は、スキップされた数値のカウントに基づいて、事前に計算されたリストまたは数学的パターンを使用することもできますが、そのような式の複雑さは、単に反復するよりも高くなります。

 ## アルゴリズムのチュートリアル

 1. 見つかったいいね数の数のカウンターを初期化します。 ゼロから始めましょう。 
2. 現在の数値を 1 に初期化します。 
3. カウンタが以下の間$k$、現在の番号を確認します。 
4. 数値が 3 で割り切れる場合、または 3 で終わる場合は、スキップします。 それ以外の場合は、カウンターをインクリメントします。 
5. 現在の数値を増やし、ステップ 3 を繰り返します。 
6. カウンターが到達したら$k$、考慮される最後の数値は、$k$-番目の好きな番号。 返してください。 

不変条件は、カウンターが私たちが目にしたいいね数の数を正確に追跡することです。 有効な数値のカウンタのみをインクリメントします。つまり、カウンタが次の値に等しい場合、$k$に到達していることが保証されています。$k$-番目の好きな番号。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def kth_liked_number(k):
    count = 0
    num = 1
    while True:
        if num % 3 != 0 and num % 10 != 3:
            count += 1
            if count == k:
                return num
        num += 1

t = int(input())
for _ in range(t):
    k = int(input())
    print(kth_liked_number(k))
```機能`kth_liked_number`整数を順番に処理し、数値が気に入られた場合にのみカウンターをインクリメントします。 メインループは複数のテストケースを処理します。 状態には気をつけます`num % 10 != 3`文字列表現をチェックするよりも、わずかに高速です。 使用する`while True`すぐに終了できます$k$- 番目の番号が見つかりました。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

 | 時間 | テスト ケースごとの O(k) | k 番目のいいね数を見つけるには、k よりわずかに多くの数をチェックする必要があるかもしれませんが、およそ 1.5k を超えることはありません。 |

## 特殊なケース

 k = 1 の場合、最初にいいねされた数値は 1 です。アルゴリズムは 1 からカウントを開始し、数値がいいねされた場合にのみカウンターを正しくインクリメントします。 最初の番号の前にスキップされる番号は発生しません。 k = 1000 の場合、アルゴリズムは 1666 まで継続し、すべての 3 の倍数と 3 で終わる数値を正しくスキップします。 3、6、13、33 などの数値の周囲のエッジ ケースは、条件分岐によって処理されます。`num % 3 != 0 and num % 10 != 3`これにより、カウンタが有効な数値に対してのみ増加することが保証されます。
