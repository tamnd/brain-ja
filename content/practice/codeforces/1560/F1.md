 ## 解決策
 ## 問題の理解

 開始番号と、使用できる個別の桁数の制限が与えられます。 各クエリについて、指定された数値以上で、10 進表現で最大で次の値を使用する最小の整数を見つける必要があります。`k`桁が違う。 

出力は、入力数値をローカルに変換するものではなく、グローバルな桁制約を満たす最初の数値に到達するまで整数内を前方検索するものです。 これにより、問題は基本的に整数行での制約された後続検索になります。 

制約は非常に特殊な点で厳しいです。 の値`n`まで行くことができます$10^9$, したがって、数値は最大 10 桁です。 テスト ケースの数は次のように大きくなります。$10^4$、から 1 つずつ順方向にスキャンしようとするソリューションは除外されます。`n`最悪の場合。 クエリごとのリニア スキャンでは、数十億桁のチェックが行われる可能性があります。 

素朴な考えは、次のように増分することです。`n`上向きに移動し、各数値が最大で次の値を使用しているかどうかを確認します。`k`明確な数字。 数値が長く続くと、有効な制約に到達する前に制約に違反する可能性があるため、これは失敗します。 特に、`k = 1`100000000、100000001、100000002 などの数値は、111111111 に達するまではすべて無効です。この差は非常に大きいです。 

2 番目の微妙な失敗例が現れるのは、`n`すでに以上のものを含んでいます`k`明確な数字。 グローバルな伝播を考慮せずに、問題のある最初の数字だけを「修正」しようと貪欲に試みると、簡単に次の数字よりも小さな数字が生成される可能性があります。`n`あるいは、真の最小候補を見逃してしまいます。 

本当の課題は、数字の制約が位置構造と相互作用することです。 ローカルな小さな変更は、大きなサフィックスの変更に伝播します。 

## アプローチ

 ブルートフォースアプローチは簡単です。`n`、各数値をチェックし、その個別の桁を数え、条件が満たされたときに停止します。 各小切手にかかる費用$O(\log n)$、最悪の場合、有効な数値に到達する前に非常に広い範囲をスキャンしてしまう可能性があります。 答えが遠い場合、制限時間内では実行できなくなります。 

重要な観察は、有効な数値の構造が次の場合に非常に制限されるということです。`k ≤ 2`。 最大 2 桁を使用する数値は、全体が 1 桁の繰り返しか 2 桁の混合で構成されなければなりません。 これは、どの桁が許可されるかを決定すると、最適な候補は恣意的ではなく、桁の選択と位置によって辞書編集的に制約されることを意味します。 

やみくもに検索するのではなく、桁ごとに答えを構築することを検討します。 各位置について、次の接頭辞の一致を試みます。`n`、失敗した場合は、その位置を上方に調整し、最大でも次の値を使用して、サフィックスを可能な限り最小の有効な継続で埋めます。`k`数字。 

中心となるアイデアは、プレフィックスを使用した数値動的プログラミングですが、次の事実によって単純化されています。`k`は 1 または 2 のみです。可能な桁セット (サイズ 1 または 2) を列挙し、各セットに対して最小の数値を構築します ≥`n`これらの数字のみを使用して形成できます。 答えは、そのようなすべての構造における最小値です。 

最大でも 10 桁であり、1 桁または 2 桁のセットのみを選択するため、候補の数は総当たりで実行できるほど十分に少ないです。

 ## アルゴリズムのチュートリアル

 各テスト ケースを独立して処理し、最適な有効な数値を構築します。 

1. すべての候補数字セットを抽出します。 

サイズ 1 (10 の可能性) とサイズ 2 (45 の可能性) のすべてのセットを列挙します。 数字の範囲は 0 ～ 9 のみであるため、これは実現可能です。 
2. 候補数字セットごとに、次の値以上の最小の数値を構築しようとします。`n`。 

私たちは代表します`n`桁ごとの構築を処理する文字列として。 
3. 固定数字セットの場合、一致を試みます。`n`左から右へ。 

各位置に、プレフィックス制約に違反しない最小の許容数字を配置しようとします。 
4. 数字セット内に収まりながらプレフィックス全体を一致させることができる場合、この構造を答えの候補として受け入れます。 
5. If at some position we cannot match`n`正確には、次に大きい許可される数字を選択することでプレフィックスを「分割」し、残りの位置を許可される最小の数字で埋めます。 

このステップは非常に重要です。`n`ある位置では、残りの桁を貪欲に最小化する必要があります。 
6. 桁セットが同じ長さの数値を生成できない場合、≥`n`、長さの最小の有効な数値を試します`len(n) + 1`、これは単にその数字セットを使用した最小の非ゼロ先行構造です。 
7. すべての有効な構造の最小値を取得します。 

### なぜ効果があるのか

 正しさは、有効な答えが最大 2 のサイズの数字セットの選択に対応する必要があるという事実から得られます。数字セットが固定されると、制約を満たし ≥ となる最小の数になります。`n`貪欲な辞書編集構造によって決定されます。 貪欲な選択から逸脱すると、数値が以下よりも小さくなります。`n`または不必要に増加するため、最適化できません。 すべての桁セットを網羅することで、最適な構成を見逃さないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_with_set(s, digits):
    digits = sorted(digits)
    n = len(s)

    # try same length
    res = None

    for i in range(n):
        ok = False
        for d in digits:
            if i == 0 and d == 0:
                continue
            if d > s[i]:
                cand = []
                cand.extend(list(s[:i]))
                cand.append(str(d))
                cand.extend([str(digits[0])] * (n - i - 1))
                cand_str = ''.join(cand)
                if res is None or cand_str < res:
                    res = cand_str
                ok = True
                break
            elif d == s[i]:
                ok = True
                break

        if not ok:
            break
    else:
        # fully matched prefix
        if set(s).issubset(set(map(str, digits))):
            if res is None or s < res:
                res = s

    # try longer length
    if digits[0] != 0:
        cand = str(digits[0]) * (n + 1)
        if res is None or cand < res:
            res = cand

    return res

def solve():
    t = int(input())
    for _ in range(t):
        n, k = input().split()
        n = n.strip()

        best = None

        # generate digit sets
        for a in range(10):
            for b in range(a, 10):
                digits = {a}
                if k == 2:
                    digits.add(b)

                if len(digits) > k:
                    continue

                cand = build_with_set(n, digits)
                if cand is None:
                    continue
                if best is None or int(cand) < int(best):
                    best = cand

        print(best)

if __name__ == "__main__":
    solve()
```このソリューションでは、最大でもサイズの有効な数字セットをすべて列挙します。`k`。 各セットについて、以上の最小の数を構築します。`n`合わせようとすることで`n`左から右へ貪欲に、許容セット内に留まりながら桁を増やせる最初の位置でブレーク。 

微妙な点は、プレフィックスの等価性を正しく処理することです。 なんとかフォローできれば`n`完全に、使用されている数字が有効であることを確認する必要があります。 そうでない場合は、その候補者を拒否します。 より長い数値へのフォールバックにより、次のようなケースを見逃すことがなくなります。`999`桁セットあり`{1}`答えはどこになるべきか`1111`。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    def build_with_set(s, digits):
        digits = sorted(digits)
        n = len(s)
        res = None

        for i in range(n):
            ok = False
            for d in digits:
                if i == 0 and d == 0:
                    continue
                if d > s[i]:
                    cand = s[:i] + str(d) + digits[0]*(n-i-1)
                    res = cand if res is None else min(res, cand)
                    ok = True
                    break
                elif d == s[i]:
                    ok = True
                    break
            if not ok:
                break
        else:
            if all(c in set(map(str, digits)) for c in s):
                res = s if res is None else min(res, s)

        if digits[0] != 0:
            cand = str(digits[0]) * (len(s)+1)
            res = cand if res is None else min(res, cand)

        return res

    def solve():
        t = int(input())
        for _ in range(t):
            n, k = input().split()
            best = None
            for a in range(10):
                for b in range(a, 10):
                    digits = {a}
                    if k == 2:
                        digits.add(b)
                    if len(digits) > k:
                        continue
                    cand = build_with_set(n, digits)
                    if cand and (best is None or int(cand) < int(best)):
                        best = cand
            print(best)

    # samples
    assert run("4\n1 1\n221 2\n177890 2\n998244353 1\n") == "1\n221\n181111\n999999999\n"

    # custom cases
    assert run("1\n8 1\n") == "8", "single digit already valid"
    assert run("1\n9 1\n") == "9", "boundary single digit"
    assert run("1\n100 1\n") == "111", "carry expansion"
    assert run("1\n999 2\n") == "999", "already valid with k=2"

 ## 特殊なケース

 重要なエッジケースは次の場合に発生します。`n`すでに 1 桁しか使用されていませんが、`k = 2`。 例えば、`n = 111`と`k = 2`残るべきだ`111`。 アルゴリズムはこれを処理します。`{1}`常に考慮され、改善できない場合は同じ数値が再構築されます。 

もう 1 つのエッジ ケースは、数字を早めに増やすと、その増加を補う小さなサフィックスが生成される場合です。 たとえば、次のようなとき`n = 177890`、からの切り替え`7`に`8`特定の位置でサフィックスをすべてにすることができます`1`s に近い値を維持しようとする試みよりも、グローバルに小さい有効な数値が生成されます。`n`。 

最後に、次のようなケース`999`と`k = 1`アルゴリズムがより長い長さの数値に正しく移行することを確認します。 最小桁を繰り返す構造により、最小限の有効な拡張子を見逃さないことが保証されます。
