 ## 解決策
 ## 問題の理解

 全長のリボンをご用意しております`n`。 すべてのカットピースは、次の 3 つの許容される長さのいずれかでなければなりません。`a`、`b`、 または`c`。 目標は、リボンを正常に分割することだけではなく、取得できるピースの合計数を最大化することです。 

たとえば、リボンの長さが次の場合、`5`許容される長さは次のとおりです`5`、`3`、 そして`2`、それを1枚の長さにカットします`5`動作しますが、細かく切断します`3 + 2`2 つの部分が生成されますが、そのほうが優れています。 

制約`n ≤ 4000`動的プログラミングには十分小さいです。 おおよそのアルゴリズム`O(n)`または`O(n^2)`操作は制限内に簡単に収まります。 すべての可能なカット シーケンスを探索する真の総当り再帰は、これらの範囲で終了しますが、同じ部分問題を何度も繰り返すため、不必要にコストがかかります。 

難しいのは、すべての中間の長さに到達できるわけではないということです。 実装を不用意に行うと、誤って不可能な状態を有効なものとして扱い、そこから答えを構築する可能性があります。 

次の例を考えてみましょう。```
7 5 2 5
```正しい答えは、`2`、カットできるので`5 + 2`。 

DP 配列がゼロで初期化されていると仮定します。 その後、状態を述べます`dp[1]`値で到達可能であるように誤って表示される`0`、その後の移行では、そこから偽のソリューションを構築する可能性があります。 不可能な状態は、通常は次のように明確にマークする必要があります。`-1`または負の無限大。 

すべての長さが等しい場合には、別の微妙なケースが発生します。```
9 3 3 3
```正しい答えは、`3`。 一部の実装では、重複する長さを削除したり、遷移を複雑にする不必要な分岐ロジックを使用しようとします。 3 つの長さをすべて均一に扱うだけであれば、問題ははるかに単純になります。 

もう 1 つの特殊なケースは、最適な答えを得るために、より大きな有効なカットではなく、多くの小さなカットが必要な場合です。```
8 5 3 2
```有効な分解には次のものがあります。`5 + 3`2枚入りと`2 + 2 + 2 + 2`4個入り。 常に最大のピースを最初に取るという貪欲な戦略は、ここでは失敗します。 

## アプローチ

 直接的な総当たりアプローチでは、考えられるすべてのカット シーケンスが試行されます。 長めのリボンから`x`、再帰的に切断を試みます`a`、`b`、 そして`c`、残りの長さを解きます。 

すべての有効な切断シーケンスが探索されるため、再帰は当然正しいものになります。 問題は繰り返しです。 長さの最適な答えを計算すると`20`、後で別のパスから再度再計算する可能性があります。 最悪の場合、再帰呼び出しの数は指数関数的に増加します。 

のために`n = 4000`、指数関数的な複雑さが大きすぎます。 のようなものでも`3^30`すでに1秒以内に操作は不可能です。 

重要な観察は、この問題には重複する部分問題があるということです。 リボンの長さのベストアンサー`x`長さに関する最良の答えのみに依存します`x-a`、`x-b`、 そして`x-c`。 

そのため、これは古典的な動的計画法の問題になります。 

以下を定義します。```
dp[i] = maximum number of pieces that can form length i
```形成できない長さの場合は、不可能としてマークされます。 

手の届く長さから`i`、許可されている各カット サイズを使用して拡張してみます。 トランジションごとにピースが 1 つ追加されます。 

各状態はより短い長さにのみ依存するため、次から繰り返し答えを計算できます。`0`まで`n`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(3^n) | O(n) 再帰スタック | 遅すぎる |
 | 最適な動的プログラミング | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.次のサイズの DP 配列を作成します`n + 1`。 

各ポジション`dp[i]`全長を生成できる最大数のピースを格納します`i`。 
2. すべての状態を不可能として初期化します。 

私たちが使用するのは`-1`不可能な状態の場合、`0`長さについてのみ有効な答えです`0`。 
3.セット`dp[0] = 0`。 

長さのあるリボン`0`必要な個数はゼロなので、これが開始状態です。 
4. 以下のすべての長さを反復処理します。`0`に`n`。 

到達可能な長さごとに、もう 1 つ長さを追加してみてください`a`、`b`、 そして`c`。 
5. カット長ごとに`x`で`{a, b, c}`：

もし`i + x ≤ n`、 アップデート：```
dp[i + x] = max(dp[i + x], dp[i] + 1)
```追加のリボンを 1 つ使用するため、1 つ追加します。 
6. すべての状態を処理した後、印刷します。`dp[n]`。 

このステートメントは、少なくとも 1 つの有効なカットが存在することを保証するため、最終的な答えには常に到達できます。 

### なぜ効果があるのか

 DP の不変式は次のとおりです。```
dp[i] always stores the maximum number of pieces for total length i
```唯一確実に正しい状態から始めます。`dp[0] = 0`。 

到達可能な状態を 1 つの許可されたカットだけ拡張するたびに、別の有効なリボン分解が作成されます。 すべてのトランジションが正確に 1 つの部分を追加するため、最大値を取得すると、すべての長さに対して可能な限り最良の分解が維持されます。 

すべての有効な切断シーケンスは、DP 内の遷移のチェーンに対応します。 このようなすべての遷移が調査されるため、次の最適な答えが得られます。`n`見つかることが保証されています。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, a, b, c = map(int, input().split())

    dp = [-1] * (n + 1)
    dp[0] = 0

    cuts = [a, b, c]

    for i in range(n + 1):
        if dp[i] == -1:
            continue

        for x in cuts:
            if i + x <= n:
                dp[i + x] = max(dp[i + x], dp[i] + 1)

    print(dp[n])

solve()
```DP 配列は次のように初期化されます。`-1`したがって、到達不能な状態は有効な状態から明確に分離されます。 これにより、不可能な長さからトランジションを誤って作成することがなくなります。 

基本的なケース`dp[0] = 0`は、カットが行われる前の空のリボンを表します。 

外側のループは、到達可能なすべてのリボン長を処理します。 内側のループは、許可されている 3 つのカットすべてを試みます。 カットの追加が範囲内にとどまる場合は、これまでに確認された最良のピース数で宛先の状態を更新します。 

微妙な実装の詳細は、次の状態をスキップすることです。`dp[i] == -1`。 このチェックがないと、不可能な状態で誤って遷移が生成されてしまいます。 

別の詳細は使用しています`max`。 異なる分解が同じ全長に達する可能性があるため、最も多くの部分を生成する分解を維持する必要があります。

```トレースは、最大化が必要な理由を示しています。 長さ`5`最初は 1 つの部分で直接到達し、後で使用して改善します。`3 + 2`。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    n, a, b, c = map(int, input().split())

    dp = [-1] * (n + 1)
    dp[0] = 0

    for i in range(n + 1):
        if dp[i] == -1:
            continue

        for x in (a, b, c):
            if i + x <= n:
                dp[i + x] = max(dp[i + x], dp[i] + 1)

    print(dp[n])

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()

    backup_stdout = sys.stdout
    sys.stdout = out

    solve()

    sys.stdout = backup_stdout

    return out.getvalue().strip()

# provided sample
assert run("5 5 3 2\n") == "2", "sample 1"

# minimum-size valid input
assert run("1 1 1 1\n") == "1", "minimum case"

# all lengths equal
assert run("9 3 3 3\n") == "3", "all equal lengths"

# greedy would fail here
assert run("8 5 3 2\n") == "4", "many small cuts are optimal"

# boundary-style combination
assert run("7 5 2 5\n") == "2", "mixed reachable states"

# larger input
assert run("4000 1 2 3\n") == "4000", "maximum n with unit cuts"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1 1 1 1`|`1`| 有効な最小入力値 |
 |`9 3 3 3`|`3`| 重複したカット長さ |
 |`8 5 3 2`|`4`| 貪欲なアプローチは失敗します |
 |`7 5 2 5`|`2`| 不可能な中間状態が正しく処理される |
 |`4000 1 2 3`|`4000`| 最大境界サイズ |

 ## 特殊なケース

 次の入力を考えてみましょう。```
7 5 2 5
```DP は次のように始まります。```
dp[0] = 0
```長さから`0`、私たちは長さに到達することができます`5`そして`2`。```
dp[5] = 1
dp[2] = 1
```長さから`2`、さらに追加`5`到達する`7`:```
dp[7] = 2
```などのありえない状態`1`、`3`、 そして`4`残る`-1`したがって、それらから無効な遷移は生成されません。 

ここで、等しいカット サイズを考えてみましょう。```
9 3 3 3
```各遷移は独立して処理されるため、アルゴリズムは引き続き正常に動作します。 更新内容は次のようになります。```
dp[3] = 1
dp[6] = 2
dp[9] = 3
```重複する値には特別な処理は必要ありません。 

最後に、貪欲が失敗するケースを考えてみましょう。```
8 5 3 2
```貪欲な戦略の選択`5`最初は以下のみを生成します:```
5 + 3 = 8
```2個入り。 

DP は、反復を含む、到達可能なすべての分解を調査します。`2`カット:```
2 + 2 + 2 + 2 = 8
```これで正しくは 4 つの部分が得られます。
