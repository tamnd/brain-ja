 ## 解決策
 ## 問題の理解

 厳密に増加する整数列が与えられます。 このシーケンスからは、最大でも次のものを削除できます。`k`要素を削除し、残りのサブシーケンスを元の順序で残します。 結果として得られるシーケンスの値は、2 つの連続する残りの要素間の最小の差によってのみ決定されます。 残っている要素が 2 つ未満の場合、値は無限として扱われます。 

タスクは、残りのシーケンス内のこの最小隣接ギャップができるだけ大きくなるように、削除する要素を選択することです。 

最大の難点は、要素を削除するとギャップが間接的に増加することですが、実行できる削除の数には制限があることです。 それぞれの選択は将来のすべてのギャップに影響を与えるため、局所的な決定が全体的な最適値を簡単に破ってしまう可能性があります。 

制約により、最大で`2 × 10^5`すべてのテスト ケースにわたる要素の合計。 これにより、すべてのサブセット、さらにはすべての削除パターンを試行するソリューションは直ちに除外されます。これは、指数関数的に増加するためです。 テスト ケースごとに 2 次アプローチを使用しても、最悪の場合は時間がかかりすぎます。 

ターゲットのギャップなしで貪欲な削除を試みると、微妙な失敗のケースが発生します。 たとえば、最小のギャップを作成する局所的な「悪い」要素を常に削除すると、別の削除後により優れたグローバルな最小ギャップを可能にする構造が破壊される可能性があります。 

別のエッジ状況が発生するのは次の場合です。`k = 0`。 その場合、答えは元の配列によって強制されるため、どのアルゴリズムも削除が許可されない場合を正しく処理し、有効な削除セットを出力する必要があります。 

最後に、最適解が保持する要素が非常に少ない場合、誤って必要以上の要素を出力する可能性が高くなります。`k`構築が実現可能性と慎重に結び付けられていない限り、削除される可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、最大でも削除することによって取得されたすべてのサブセットが試行されます。`k`要素。 各サブセットについて、すべての隣接する差分を計算し、最小値を取得します。 厳密に考えただけでも`n - k`要素は保持されますが、それらを選択する方法の数は依然として組み合わせによるものです。`O(n choose k)`、これは実現不可能です。 

重要な点は、どの要素を削除するかを直接決定する必要がないということです。 代わりに、視点を反転して、答えの候補を修正するとします。`x`、つまり、最終シーケンス内のすべての隣接するペアが少なくとも異なるようにしたいことを意味します。`x`。 ここで、問題は、最大でも削除しながら、この制約を満たすサブシーケンスを選択できるかどうかを確認することになります。`k`要素。 

固定の場合`x`常に可能な限り早い要素を取得し、規則に違反するすべてをスキップすることで、最長の有効なサブシーケンスを貪欲に構築できます`x`ギャップ要件。 一度要素を選択すると、次の選択を遅らせても将来の選択肢が減るだけであるため、この貪欲な構築は最適です。 

これにより、問題が単調な実現可能性チェックに変換され、二分探索が可能になります。`x`。 隙間があれば`x`が達成可能であれば、制約が弱くなるため、より小さなギャップも達成可能になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | ブルートフォース | 指数 | O(n) | 遅すぎる |

## アルゴリズムのチュートリアル

 削除制限の下で、有効なサブシーケンス内の最大可能最小ギャップを見つけたいと考えています。 

1. 答えを二分探索します`x`、許容される最小隣接差。 検索範囲は次のとおりです`0`に`a[n-1] - a[0]`。 隣接する差分がフル スパンを超えることはできないため、この範囲は考えられるすべての意味のあるギャップをカバーします。 
2. 固定の場合`x`、サブシーケンスを貪欲に構築することで実現可能性をチェックします。 常に最初の要素を選択することから始めます。 
3. 配列を左から右にスキャンします。 現在の要素が少なくとも`last_selected + x`、私たちはそれを保持し、更新します`last_selected`。 それ以外の場合は、削除されたものとしてスキップします。 
4. スキャン後、保持された要素の数を計算します。 もし`kept >= n - k`、 それから`x`必要に応じて、削除予算の範囲内で保持されている余分な要素をいつでも削除できるため、これは実現可能です。 
5. 二分探索を使用して、実現可能な最大値を見つけます。`x`。 
6. この最適化を使用して貪欲なプロセスをもう一度実行します。`x`、どのインデックスが保持されているかを記録します。 
7. 他のすべてのインデックスは削除セットを形成します。 そのサイズとインデックスを出力します。 

### なぜ効果があるのか

 貪欲チェックでは、ギャップ制約を満たすサブシーケンスの可能な最大サイズが生成されます。`x`。 有効なサブシーケンスは同じ順序制約を尊重する必要があり、以前の有効な要素を選択しても、将来の実現可能性が低下することはありません。 これにより、貪欲なソリューションが固定用途に最適になります。`x`。 実行可能性は単調であるため、二分探索は有効です。`x`したがって、一度ギャップが不可能になると、それより大きなギャップもすべて不可能になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def feasible(a, k, x):
    n = len(a)
    cnt = 1
    last = a[0]
    for i in range(1, n):
        if a[i] - last >= x:
            cnt += 1
            last = a[i]
    return cnt >= n - k

def build(a, x):
    n = len(a)
    keep = [False] * n
    last = a[0]
    keep[0] = True
    for i in range(1, n):
        if a[i] - last >= x:
            keep[i] = True
            last = a[i]
    return keep

def solve():
    T = int(input())
    for _ in range(T):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))

        lo, hi = 0, a[-1] - a[0]

        while lo <= hi:
            mid = (lo + hi) // 2
            if feasible(a, k, mid):
                lo = mid + 1
            else:
                hi = mid - 1

        best = hi
        keep = build(a, best)

        delete_idx = []
        for i in range(n):
            if not keep[i]:
                delete_idx.append(i + 1)

        if len(delete_idx) > k:
            delete_idx = delete_idx[:k]

        print(len(delete_idx))
        if delete_idx:
            print(*delete_idx)
        else:
            print()

if __name__ == "__main__":
    solve()
```実現可能性関数は、最小ギャップを維持しながら保持できる要素の数を計算します。`x`。 構築機能は同じ貪欲なプロセスを繰り返しますが、決定を記録します。 二分探索により、許容される最小のギャップが最大化されることが保証され、最終的な削除リストは単に保持されたセットの補完になります。 

微妙な点は、greedy は可能な最大数の要素を保持するため、既にそれ以上の要素を保持している場合、`n - k`、削除できる数が少ないため、まだ安全です。`k`要素。

 ## 特殊なケース

 いつ`k = 0`、貪欲な構造は削除には決して使用されません。 二分探索では実現可能性が正しく評価されますが、最終的な削除リストは空でなければなりません。 すべての要素が保持としてマークされたままであるため、アルゴリズムはこれを自然に処理します。 

いつ`n - k = 1`の場合、単一の要素で十分であるため、実現可能条件は自明になります。 貪欲型は常に少なくとも 1 つの要素を返し、アルゴリズムは大規模な要素を正しく許可します。`x`ただし、隣接する差異が存在しないため、最終的な答えは無関係です。 

最適解がほぼすべての要素を保持している場合でも、貪欲解は必要なサイズの有効なスーパーセットを生成し、単純に最大で切り捨てます。`k`保持されたセットの補数を選択することによる削除。
