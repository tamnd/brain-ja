 ## 解決策
 ## 問題の理解

 私たちには、キャンディーの山を使ってプレイされるターンベースのゲームが与えられます。 2 人のプレーヤーが交互に動き、最初のプレーヤーが常に最初に動きます。 各移動で、現在のプレイヤーは山から正確に 1、3、または 4 個のキャンディーを取り除かなければなりません。 プレイヤーがターンを開始して正当な動きを行えなかった場合、つまり山が空であるか、残りのカウントに適合する許可された動きがない場合、そのプレイヤーはすぐに負けます。 

各テスト ケースではキャンディーの初期数が与えられ、最適なプレイでどのプレイヤーが勝つかを判断する必要があります。 出力は単純に勝者の名前です。先手は「オレンジ」、後手は「アイス」となります。 

この制約では、最大 100,000 のテスト ケースと、最大 1e9 の n の値が許可されます。 これにより、n までの全範囲にわたるテストごとの動的プログラミングが即座に除外されます。 1e9 までの線形 DP ですら不可能であり、1e9 までの事前計算ですら、時間とメモリの両方で実行不可能です。 ソリューションでは、小さな前処理フェーズの後に各クエリを定数時間に短縮するか、直接式を導き出す必要があります。 

素朴な推論を打ち破ることが多い、微妙なエッジ ケースが 2 つあります。 

まず、n = 0 とします。最初のプレイヤーは何も動かず、すぐに負けます。したがって、答えは「氷」でなければなりません。 開始位置が勝利であると想定する DP は、明示的に処理されない限り、これを誤って勝利としてマークします。 

第 2 に、n = 2 のような小さな値は、誤った貪欲な思考を露呈します。 2 つのキャンディーから 1 つを取るだけで、残り 1 つは相手に残り、その位置は次のプレイヤーの勝ちとなります。 つまり、2 は、対称的または「勝つのに十分小さい」ように見えるとしても、現在のプレーヤーにとっては負けです。 

3 番目の構造的なエッジ ケースは、許可される動きが {1,2} のように対称ではないことです。 3 と 4 の存在により、単純なパリティ パターンではなく周期構造が作成されます。 ゲームを「奇数勝ち、偶数負け」に減らそうとする試みはすぐに失敗します。たとえば、n = 3 はすべてのキャンディーを獲得できるため、直接勝ちです。 

## アプローチ

 このゲームを分析する最も直接的な方法は、標準的な公平なゲーム DP です。 現在のプレイヤーが n 個のキャンディーを残して勝利を強制できる場合に true となる状態 dp[n] を定義しましょう。 位置 n から、プレーヤーはすべての有効な動きを試みます: 1、3、または 4 個のキャンディーを削除し、それらの状態が存在する場合は dp[n-1]、dp[n-3]、および dp[n-4] に移行します。 少なくとも 1 つの手が相手の負けポジションにつながる場合、そのポジションは勝利したことになります。 

この漸化式は正しいですが、n = 1e9 まで計算することは不可能です。 1e7 のような中程度の制限までしか計算しない場合でも、テスト ケースの数とメモリ要件が大きくなりすぎます。 

重要な観察は、これが固定された動きを設定した減算ゲームであるということです。 このようなゲームは、状態が少数の以前の値にのみ依存するため、短いプレフィックスの後に周期的になることがよくあります。 ここで、dp[n] は dp[n-1]、dp[n-3]、および dp[n-4] にのみ依存するため、状態空間は制限され、シーケンスは最終的に繰り返されます。 

最初の数十個の値の dp を計算すると、繰り返しパターンが観察されます。 実際、損失ポジションは期間 7 で繰り返されます。このサイクルが特定されると、すべてのクエリは n モジュロ 7 を計算し、固定ルックアップ テーブルをチェックすることになります。 

これにより、O(1) 前処理後の問題はクエリごとの定数時間に変わります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート DP 最大 n | テストあたり O(n) または合計 O(max n) | O(n) | 遅すぎる |
 | 周期的 DP + モジュロ | テストごとに O(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、サイクルが明らかになるまで、n の小さな値について勝ちと負けの状態を計算します。 false は負けを意味し、true は勝ちを意味するブール配列を定義します。

キャンディーを持たないプレイヤーは移動できないため、dp[0] を負けとして初期化します。 そこから、インデックスが有効である限り、i − 1、i − 3、i − 4 からの許可された遷移を使用して dp[i] を繰り返し計算します。 

テーブルを拡張するときに、dp 値のパターンの繰り返しを探します。 シーケンスが長さ 7 の繰り返しサイクルに安定したことが確認できたら、前処理を停止し、周期を記録します。 

この時点で、n mod 7 が勝ちポジションまたは負けポジションに対応するかどうかをエンコードするサイズ 7 のルックアップ テーブルを構築します。 

各クエリ n について、r = n mod 7 を計算します。 dp_pattern[r] が勝利状態を示している場合は「オレンジ」を出力し、それ以外の場合は「アイス」を出力します。 

### なぜ効果があるのか

 このゲームは、制限された移動セットを備えた有限減算ゲームです。 各位置の状態は、一定数の前の状態にのみ依存するため、dp 値のシーケンスは有限のバイナリ アルファベットにわたって線形反復を形成します。 このようなシーケンスは最終的には周期的になるはずです。 周期領域に到達すると、dp[n] の値はサイクル長の n を法としてのみ依存するため、発見された周期の n を法として減少させることで、すべての大きな値の正確性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

# Precompute DP until we see a cycle
moves = [1, 3, 4]
N = 50  # enough to observe periodicity

dp = [False] * (N + 1)
dp[0] = False

for i in range(1, N + 1):
    win = False
    for m in moves:
        if i - m >= 0 and not dp[i - m]:
            win = True
    dp[i] = win

# Observed cycle for this problem: period 7 starting early
# We extract pattern for mod 7
pattern = [dp[i] for i in range(7)]

t = int(input())
out = []

for _ in range(t):
    n = int(input())
    if pattern[n % 7]:
        out.append("Orange")
    else:
        out.append("ice")

print("\n".join(out))
```コードはまず、ゲームの構造を明らかにするのに十分な小さな DP テーブルを構築します。 遷移では、有効な手が負け状態につながるかどうかがチェックされます。 そうであれば、現在の状態が勝利しています。 

十分な値を計算した後、dp[i] モジュロ 7 の動作を直接読み取ります。一定サイズのパターン配列には、各剰余クラスが勝っているかどうかが格納されます。 

その後、各クエリは単一のモジュロ演算とテーブル ルックアップに縮小されます。 これにより、n への依存が回避されます。 

微妙な点は、dp[0] を正しく処理することです。 現在のプレイヤーには有効な手がないため、負けとして初期化する必要があります。 それ以降のすべての状態は、この基本ケースに依存します。 

## 実用的な例

 n = 5、n = 6、および n = 7 を考えてみましょう。DP の決定を追跡します。

 n = 2 の場合、すべての手が相手の勝ち状態につながるため、負けています。 n = 4 の場合、すぐに 4 つを取ると勝ちとなり、勝ちとなります。 

次に、周期性を示すために、より大きな値を検討します。 

| n | n mod 7 | 結果 |

痕跡は、ゲームがパリティのみによって支配されていないことを示しています。 3 番目と 4 番目の動きが利用可能であるため、単純なパターンを破壊しながらも、制限されたサイクルを生成する勝利のジャンプが作成されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    moves = [1, 3, 4]
    N = 50

    dp = [False] * (N + 1)
    dp[0] = False

    for i in range(1, N + 1):
        win = False
        for m in moves:
            if i - m >= 0 and not dp[i - m]:
                win = True
        dp[i] = win

    pattern = [dp[i] for i in range(7)]

    t = int(input())
    res = []
    for _ in range(t):
        n = int(input())
        res.append("Orange" if pattern[n % 7] else "ice")

    return "\n".join(res)

 ## 特殊なケース

 n = 0 の場合、dp_pattern[0] が false であるため、アルゴリズムは直接 Ice を割り当てます。 これは、手が存在しないという事実と一致するため、最初のプレイヤーはすぐに負けます。 

n = 2 の場合、剰余クラスは損失状態につながります。 DP をトレースすると、考えられる両方の結果 (1 を取る) が対戦相手に勝利の位置を残すことが確認されるため、正しい出力は氷になります。 

n = 7 の場合、r = 0 を計算します。パターンはこれを負けとしてマークするため、ice が勝ちます。 7 では複数の手が許可されていますが、各オプションは最適に対抗できる状態につながります。 

n = 8、r = 1 の場合、勝ちです。 アルゴリズムはオレンジを出力します。これは、最初のプレイヤーが負けた残留クラスに移動することで強制的に勝利を収めることができるという事実と一致します。
