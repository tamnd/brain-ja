 ## 解決策
 ## 問題の理解

 いくつかの独立したテスト ケースが与えられています。 それぞれで、石のコレクションの「魔法の力」を表す整数のリストを受け取ります。 個別の石の順序のないペアごとに、それらの値のビットごとの AND を計算し、すべてのペアについてこれらの結果を合計します。 

したがって、タスクは純粋に組み合わせです。すべてのペアは、2 つの数値間の共有セット ビットによって決定される値に寄与します。 各テスト ケースの出力は、すべてのペアの合計です。 

重要な構造上の課題は、ペアの数が n とともに二次関数的に増加することです。 テストで n が 200,000 に達すると、ペアの数は 2×10^10 のオーダーになり、直接のペアの列挙は即座に除外されます。 複数のテスト ケースがある場合でも、合計 n は 400,000 に達する可能性があるため、どの解も線形または線形対数に近いものでなければなりません。 

素朴な推論が微妙に失敗するケースは、ペアごとの AND が算術平均のように動作する、またはビットの独立性を考慮せずに集計できると仮定することです。 たとえば、すべての数値が同じである場合、次のようにします。`[7, 7, 7]`、すべてのペアが貢献します`7 & 7 = 7`、したがって、答えは次のとおりです`3 * 7 = 21`。 誤ってペアごとではなく要素ごとに寄与をカウントする単純な試みは、順序付きペアと順序なしペアを混合することによって簡単に過大カウントまたは過少カウントする可能性があります。 

もう 1 つの落とし穴は、ビット単位の演算がビットごとにきれいに分解されるが、それは各ビットが独立して処理される場合に限られるということを忘れていることです。 ビットごとの推論を行わずに AND 値を再構築しようとするアプローチは、大きな制約の下では破綻する傾向があります。 

## アプローチ

 ブルートフォースソリューションでは、すべてのペアに対して反復処理が行われます。`(i, j)`と`i < j`そして計算する`(a[i] & a[j])`、結果を蓄積します。 これは問題の定義に直接従うため、正しいです。 ただし、そのコストはペアの数に比例し、最悪の場合は`n(n-1)/2`。 と`n = 2 × 10^5`、これは完全に不可能になります。 

ビットごとの AND の構造は分解を示唆しています。ペアごとに完全な値を計算する代わりに、各ビット位置を独立して調べることができます。 少しは貢献する`2^k`ペアの両方の数値にそのビットが設定されている場合に限り、ペアの最後の AND 和に変換します。 これにより、問題は値に関する推論からビット数に関する推論に変わります。 

固定ビットの場合`k`、 仮定する`cnt_k`番号にはこのビットが設定されています。 これらから形成されるペア`cnt_k`数字が貢献する`2^k`答えに。 そのようなペアの数は`cnt_k * (cnt_k - 1) / 2`。 これをすべてのビットで合計すると、最終結果が得られます。 

これが機能するのは、ビットごとの AND が独立したビット位置に対して加算的であり、ビット間にキャリーや相互作用が存在しないためです。

 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | 遅すぎる |
 | ビットカウント | O(n · 31) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 各テスト ケースを個別に処理し、ビットごとのカウントを使用して答えを計算します。 

1. 配列またはループ構造を初期化して、各ビットに含まれる数値の数をカウントします。 以来`a[i] ≤ 10^8`、30 までのビットだけが必要です。 
2. 配列内の各数値について、各ビット位置を検査します。 ビットが設定されている場合は、対応するカウンタをインクリメントします。 これにより、各ビットに含まれる数値の頻度表が作成されます。 
3. 各ビット位置について`k`、そのビットが設定されている数値から何組のペアを形成できるかを計算します。 もし`cnt_k`数字にはビットが含まれています`k`、有効なペアの数は`cnt_k * (cnt_k - 1) // 2`。 
4. このような各ペアは貢献します`2^k`最終的な金額まで。 この寄与を乗算して答えに加算します。 
5. テストケースの累積結果を出力します。 

頻度を数えた後にペアを数える理由は、ペアの形成は、順序や他のビットとの相互作用ではなく、ビットを含む数値セットのメンバーシップにのみ依存するためです。 

### なぜ効果があるのか

 各ペアは、両方の数値が 1 を共有するビットごとに独立して最終的な合計に寄与します。ビット位置を固定すると、すべてのペアの寄与は、そのビットが含まれる数値の数によって完全に決まります。 異なるビット位置が干渉することはないため、ビット間の寄与を合計すると、ペアとビットの組み合わせごとに 1 回だけ、すべてのペアにわたる完全な AND 合計が再構築されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        cnt = [0] * 31  # enough for values up to 1e9

        for x in a:
            b = 0
            while x:
                if x & 1:
                    cnt[b] += 1
                x >>= 1
                b += 1

        ans = 0
        for k in range(31):
            c = cnt[k]
            if c > 1:
                ans += (c * (c - 1) // 2) * (1 << k)

        print(ans)

if __name__ == "__main__":
    solve()
```このソリューションではビットごとの周波数配列を使用します。`cnt`。 各数値について、各ビット インデックスを繰り返しマスクするのではなく、ビット シフトを使用して分解します。これにより、実装がシンプルになり、余分なオーバーヘッドが回避されます。 

よくある実装上の間違いは、ビットを間違って反復したり、元の数値を不用意に破壊的にシフトしたりすることです。 ここでは、シフトするループを使用してビット位置を再構築します。`x`、したがって、各番号は他の番号に影響を与えることなく安全に消費されます。 

組み合わせ方程式は`c * (c - 1) // 2`64 ビット安全な算術演算で計算する必要があります。 Python は自然に大きな整数を処理するため、オーバーフローは問題になりません。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

 | 時間 | O(T・n・B) | 各数値は最大 B = 31 ビットにわたって処理されます。

 この制約により、すべてのテスト ケースにわたって合計 4×10^5 までの要素が許可されます。 要素あたり約 31 の演算があるため、合計作業量はおよそ 1.2×10^7 演算となり、Python の時間制限内に簡単に収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from sys import stdout

    data = inp.strip().split()
    it = iter(data)
    t = int(next(it))
    out = []

    for _ in range(t):
        n = int(next(it))
        arr = [int(next(it)) for _ in range(n)]

        cnt = [0] * 31
        for x in arr:
            b = 0
            while x:
                if x & 1:
                    cnt[b] += 1
                x >>= 1
                b += 1

        ans = 0
        for k in range(31):
            c = cnt[k]
            ans += (c * (c - 1) // 2) * (1 << k)

        out.append(str(ans))

    return "\n".join(out)

# provided sample
assert run("1\n3\n1 2 3") == "3"

# minimum size
assert run("1\n1\n7") == "0"

# all equal
assert run("1\n4\n5 5 5 5") == "30"

# no shared bits
assert run("1\n3\n1 2 4") == "0"

# mixed
assert run("2\n2\n1 3\n3\n7 7 7") == "1\n21"

 ## 特殊なケース

 次のような単一要素テスト`n = 1`実装が少なくとも 1 つのペアが存在すると誤って想定しているかどうかを明らかにします。 この場合、ビット数はゼロでない可能性がありますが、ペアの式は正しくゼロを返します。`cnt * (cnt - 1) / 2`はゼロです。 

のような入力の場合`3 1 2 4`、各数値には互いに素なビットがあるため、すべての AND は 0 になります。 ビット カウントのアプローチでは、各ビット カウントが正確に 1 に設定され、ビットあたりの寄与がゼロとなり、期待される結果と一致します。 

次のような一様な配列の場合`5 5 5 5`、各ビットは 4 回出現し、アルゴリズムはカウントします。`6`すべてのペアが 5 に等しい同一の AND を持つという事実を正しく再現します。
