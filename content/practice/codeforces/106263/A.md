 ## 解決策
 ## 問題の理解

 多くの独立したクエリが与えられます。 各クエリは 2 つの整数を提供します$a$そして$b$、そしてそれらの素因数分解を通じて定義された値を計算する必要があります。 

タスクは、いずれかの数値に出現するすべての素数を調べることです。 素数ごとに$p$、両方を分割するかどうかを確認します$a$そして$b$。 含まれる場合は、$p$製品内で 1 回だけ。 両方の数値を割る素数がない場合、答えはゼロとして定義されます。 それ以外の場合は、そのような共通の素数をすべて掛け合わせます。 

したがって、各クエリの出力は多重度に関するものではなく、素数が共有されているかどうかのみに関するものです。 次のような繰り返しの力$p^k$または$p^m$～の存在以外は問題ではない$p$どちらの因数分解でも。 

制約は厳しいです: まで$2 \cdot 10^5$クエリ。それぞれの数値は次のように大きくなります。$2 \cdot 10^6$。 これにより、平方根までの試行除算を使用して各数値を個別に因数分解することはすぐに除外されます。$2 \cdot 10^5 \cdot \sqrt{2 \cdot 10^6}$、これは大きすぎます。 

よく現れる単純なアイデアは、クエリごとに両方の数値の素因数分解を計算し、素数セットを交差させるというものです。 これは、最適化された試行分割を使用しても、200,000 のクエリにわたって因数分解を繰り返すと遅すぎるため、時間のプレッシャーで失敗します。 

もう 1 つの微妙な失敗例は、両方の数値の約数を再計算し、その場で素数性をチェックすることです。 たとえば、次のような入力では$a = 999983$そして$b = 999979$、両方の素数の場合、単純因数分解は数値ごとにほぼ一定の処理を行いますが、それでもクエリごとに厳しいチェックを繰り返します。 

重要な構造的問題は、私たちが境界のある範囲内の数値を繰り返し因数分解していることです。 これは、すべてのプライム情報を一度前処理することを強く示唆しています。 

## アプローチ

 ブルートフォースアプローチでは、次の素因数分解を計算します。$a$そして$b$試行分割を使用してクエリごとに。 各数値の素数のセットを抽出した後、それらの共通部分を計算し、それらの素数を乗算します。 

これは定義に直接従うため、正しいです。 ただし、各因数分解には最大で次のコストがかかります$O(\sqrt{n})$、そして$n \le 2 \cdot 10^6$、このあたりです$1400$数値ごとの操作。 クエリごとに 2 つの数値を使用し、最大で$2 \cdot 10^5$クエリについては、おおよその結果が得られます$5.6 \cdot 10^8$動作が遅すぎます。 

重要な点は、クエリごとに完全な因数分解を行う必要がないということです。 どの素数が数値を割るかを知る必要があるだけで、これは最大のすべての整数について事前に計算できます。$2 \cdot 10^6$改良されたふるいを使用します。 完全な因数分解を保存する代わりに、個別の素因数の二乗なし積のみを保存します。 次に、各クエリは、これらの変換された値の最大公約数を計算することになります。 

定義すると$f(x)$の異なる素因数の積として$x$、その場合、答えは正確になります$\gcd(f(a), f(b))$。 これが機能するのは、各素数が 1 回寄与し、gcd が多重性を無視して共通の素数を自然に選択するためです。 

これにより、各クエリが事前計算された値に対する単一の gcd 操作に変換されます。

 ## アルゴリズムのチュートリアル

 1. 配列を事前計算する`spf`または配列を直接構築する`val`どこ`val[x]`は次の異なる素因数の積です`x`。 これは、次の値までのすべての数値をふるいを使用して行われます。$2 \cdot 10^6$。 初めて素数に出会ったとき$p$、それをすべての倍数に乗算します。$p$、各数値が各素数を 1 回だけ収集するようにします。 
2. すべての整数について$x$、各素数が 1 回だけ寄与するようにします。 これは、複数の処理を繰り返すときを意味します。$p$、次のようなより高い累乗を得るために繰り返し乗算することはありません。$p^2$。 これは、素数を塩基素数ごとに 1 回だけ伝播する標準的なふるいによって処理できます。 
3. 前処理後の各数値$x$正方形のない表現に置き換えられます$val[x]$。 
4. 各クエリについて$(a, b)$、計算する$g = \gcd(val[a], val[b])$。 
5. もし$g = 1$、共通素因数がないため、0 が出力されます。 
6. それ以外の場合は出力$g$、すべての共有素数の積です。 

### なぜ効果があるのか

 各数値は素数と指数の積として一意に表現できますが、指数は破棄し、素数が出現するかどうかのみを保持します。 ふるいは、すべての素数が、それが分割するすべての倍数に 1 回だけ寄与することを保証します。 したがって、$val[x]$素数の集合を割った積です$x$。 

このような 2 つの積の gcd は、両方の因数分解で現れる素数を正確に保持します。これは、別個の素数の積の gcd が素数セットの共通部分に対応するためです。 これにより、クエリごとに数値を明示的に因数分解することなく正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXN = 2_000_000

val = [1] * (MAXN + 1)

# modified sieve: build square-free product of prime factors
for i in range(2, MAXN + 1):
    if val[i] == 1:  # i is prime (not yet marked)
        for j in range(i, MAXN + 1, i):
            val[j] *= i

T = int(input())
out = []

for _ in range(T):
    a, b = map(int, input().split())
    g = __import__("math").gcd(val[a], val[b])
    out.append(str(g if g > 1 else 0))

print("\n".join(out))
```前処理ループは、各整数の変換された表現を構築します。 条件`val[i] == 1`複合体にはすでに小さな素数が乗算されているため、素数を識別します。 次に、各素数はその倍数に 1 回だけ伝播し、各数値が異なる素因数のみを蓄積するようにします。 

その後、クエリ セクションは gcd 操作まで定数時間になります。 ゼロへの最終変換は、共通の素数が存在しない特殊なケースを処理します。 

ここでよくある落とし穴は、同じ素数の繰り返しの乗算は避けなければならないことを忘れていることです。 ふるいの構造により、各素数を 1 回だけ処理することで、これが自然に保証されます。

## テストケース```python
import sys, io
import math

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    MAXN = 2_000_000
    val = [1] * (MAXN + 1)

    for i in range(2, MAXN + 1):
        if val[i] == 1:
            for j in range(i, MAXN + 1, i):
                val[j] *= i

    T = int(input())
    out = []
    for _ in range(T):
        a, b = map(int, input().split())
        g = math.gcd(val[a], val[b])
        out.append(str(g if g > 1 else 0))
    return "\n".join(out)

def run(inp: str) -> str:
    return solve(inp)

# provided samples
assert run("1\n60 70\n") == "10"
assert run("1\n12 175\n") == "0"

# custom cases
assert run("1\n2 3\n") == "0"          # disjoint primes
assert run("1\n8 4\n") == "2"          # repeated powers should not matter
assert run("1\n30 105\n") == "15"      # multiple shared primes
assert run("3\n6 10\n12 18\n7 49\n") == "2\n6\n0"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 2 3 | 0 | 素数の素数 |
 | 8 4 | 2 | 指数を無視します |
 | 30 105 | 15 | 複数の共有素数 |
 | 混合バッチ | 2 / 6 / 0 | 複数のクエリの正確性 |

 ## 特殊なケース

 微妙なケースは、次のような 1 つの数値が純粋な累乗である場合です。$a = 64$そして$b = 8$。 どちらも 2 の累乗なので、正解は 2 です。ふるい表現では次のようになります。`val[64] = 2`そして`val[8] = 2`したがって、gcd は 2 となり、予想と一致します。 

もう 1 つのケースは、次のように、数値が素数をまったく共有しない場合です。$a = 999983$そして$b = 999979$、両方とも素数です。 表現はそれ自体になり、gcd は 1 になり、出力 0 が生成されます。 

最後のケースは、数値に素数の繰り返しが含まれる場合です。$a = 72 = 2^3 \cdot 3^2$。 これをふるいで圧縮すると、`val[72] = 6`。 正しい解法では、乗算を繰り返しても積が歪まないようにする必要があります。そうしないと、gcd が素数を誤ってカウントしすぎてしまいます。
