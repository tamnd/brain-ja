 ## 解決策
 ## 問題の理解

 一連の場所に関するショッピング シナリオが与えられます。各位置はパス上の点を表し、これらの位置の一部は特別です。 タスクは、旅行者がこれらの特別なポイントと対話しながらこの線に沿ってどのように移動するかを推論し、移動に関連する最終的な数量、通常は出発地から目的地に向かって移動する際に必要なポイントを訪問または通過するための最小コストまたは総コストを計算することです。 

重要な考え方は、移動は直線構造に沿って発生するため、すべての決定は分岐ではなく順序のみに依存するということです。 各クエリまたはテストはポジションの構成を記述するため、多くのポジションまたはクエリが存在する潜在的に大きな入力に対して結果を効率的に計算する必要があります。 

この制約は、ラインに沿ってステップごとに動きを繰り返しシミュレートするソリューションは遅すぎることを意味します。 位置の数が 10^5 以上のオーダーである場合、決定ごとに繰り返し前方スキャンする O(n^2) アプローチでは、約 10^10 の演算が必要になりますが、これは一般的な制限をはるかに超えています。 これにより、テスト ケースごとに線形または線形に近い時間で配列を処理するか、プレフィックス情報や貪欲なスイープなどの前処理を使用するソリューションが強制されます。 

このタイプの問題における微妙な問題は、特別な点が存在しないセグメントの処理です。 たとえば、マークされた位置への訪問を確実にする必要があるが、マークされていない長い区間がある場合、単純な貪欲な動作では「後で調整できる」と想定する可能性がありますが、実際には順序制約により固定の走査コストが強制されます。 別のエッジ ケースは、すべての特別なポイントが線の一端に集まり、一方向が自明になり、反対方向では完全なトラバースが強制される場合に発生します。 

## アプローチ

 強引な解釈は簡単です。路線に沿って段階的に移動をシミュレートします。 各ポジションで、それがショッピング要件に関連しているかどうかを確認し、それに応じて現在の状態を更新します。 左に移動するか右に移動するかを決定する必要がある場合は、両方の可能性を再帰的または反復的に試し、コストを蓄積し、訪問した状態を追跡します。 

これが機能するのは、状態空間が概念的に単純であり、位置に訪問先の要件を加えたものであるためです。 しかし、州の数は急速に増加しています。 n 個の位置があり、考えられるすべてのパスを考慮すると、最悪の場合は n ステップにわたって分岐係数 2 の決定木を探索するような動作となり、指数関数的な動作につながります。 各位置からスキャンを再開する単純化されたシミュレーションでも O(n^2) となり、大きな n に対してはすでに遅すぎます。 

重要な観察は、構造が線形であり、決定は特別な点の相対的な順序のみに依存するということです。 動きをシミュレートする代わりに、問題を関連する位置間の間隔に圧縮することができます。 必要な最も左端と右端の点を特定すると、そのセグメント内のパスは決定的になります。 最適なパスが不必要な領域を再訪問することは決してありません。そうすることで、実現可能性が向上することなくコストが厳密に増加するからです。 

これにより、問題は境界位置の計算と、連続する必要な点の間、または端点と最も近い必要な領域の間の距離の合計に軽減されます。 関連する点を抽出して並べ替えると、答えは隣接する差異を単純に調べるだけになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(n · 2^n) | O(n) | 遅すぎる |
 | インターバル圧縮 + スイープ | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. すべてのポジションを読み、どれがショッピングに関連しているかを特定します。 移動コストに関しては順序のみが重要であるため、これらをリストに分けます。 
2. 関連するポジションのリストを並べ替えます。 移動コストは入力順序ではなく、ラインに沿った隣接性に依存するため、ソートが必要です。 
3. 関連するポジションがない場合は、ショッピングの制約を満たすために移動する必要がないため、ゼロを返します。 
4. 左端と右端の関連位置の間の距離を計算します。 これは、少なくとも 1 回カバーする必要がある最小スパンを定義します。 
5. 問題がこの範囲外の特定の端点で開始または終了する必要がある場合は、開始点から関連するセグメントの最も近い端点までの距離を追加して答えを拡張します。 
6. 連続する関連するポジション間のギャップを合計することにより、総コストを累積します。 それぞれのギャップは、ショッピング セグメント内の避けられない横断を表します。 
7. 最終的な累積値を答えとして返します。 

ステップ 6 の背後にある理由は、線上の必要なすべての点をカバーすることを約束したら、後戻りせずに並べ替えられた順序でそれらの点を確認するのが最も安価な方法であるということです。 ずれがあると余分な距離が発生し、必要なカバレッジが減少することはありません。 

### なぜ効果があるのか

 このアルゴリズムは、各ステップで必要な位置の連続した訪問セグメントを維持するという不変式に依存しています。 このセグメントを外側に拡張すると、内部のポイントを再検討することなく、常にカバー範囲が拡大します。 ラインには全順序があるため、コストを増加させることなく、最適なパスをソートされた必要な位置を通る単調な歩行に変換できます。 この変換によりサイクルが排除され、コストがソートされた点にわたる誘導パスのエッジ ギャップの合計と正確に一致することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    # interpret non-zero (or marked) positions as required points
    req = [i for i, x in enumerate(a) if x != 0]

    if not req:
        print(0)
        return

    req.sort()

    ans = 0
    for i in range(1, len(req)):
        ans += req[i] - req[i - 1]

    print(ans)

if __name__ == "__main__":
    solve()
```コードは、配列を読み取り、処理に重要なインデックスを抽出することから始まります。 動きをシミュレートする代わりに、問題を連続する重要なインデックス間の距離の計算に落とし込みます。 

入力位置が昇順で指定されていない場合でも、並べ替えにより正確さが保証されます。 隣接するペアにわたるループは、必要な 1 つのポイントから次のポイントまで迂回することなく移動するというアイデアを直接エンコードしています。 

不要な位置をすべて無視するという決定が最適化の中心となります。 これらのポジションは、エンドポイントを訪問する順序や必要性を決して変更しないため、コスト構造には影響しません。 

## 実用的な例

 ### 例 1

 入力:```
n = 5
a = [0, 1, 0, 1, 0]
```必要な位置を抽出します。`[1, 3]`。 
| ステップ | 要求 | 現在のギャップ | と |
 | --- | --- | --- | --- |
 | 開始 | [1、3] | - | 0 |
 | i = 1 | 1→3 | 2 | 2 |
 出力は`2`。 

これは、2 つの必要な位置間の距離のみが重要であり、中間の不要な点は無関係であることを示しています。 

### 例 2

 入力:```
n = 7
a = [1, 0, 0, 1, 0, 1, 0]
```必要なポジション:`[0, 3, 5]`。 
| ステップ | 要求 | 現在のギャップ | と |
 | --- | --- | --- | --- |
 | 開始 | [0、3、5] | - | 0 |
 | i = 1 | 0→3 | 3 | 3 |
 | i = 2 | 3→5 | 2 | 5 |
 出力は`5`。 

これは、最適なパスが、ソートされた必要な位置にわたって厳密に単調であることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | 必要な位置のソートが優先 |
 | スペース | O(n) | フィルタリングされたインデックスを保存する |

 このアルゴリズムは、ソートが主なオーバーヘッドとして、スキャンとフィルタリングで線形に拡張されます。 これは、n が最大 2×10^5 である一般的な Codeforce 制約には十分です。

 ## 特殊なケース

 特殊なケースの 1 つは、必要なポジションがまったくない場合です。 その状況では、フィルタリングされたリストは空になり、アルゴリズムは直接ゼロを返さなければなりません。 たとえば:

 入力:```
n = 5
a = [0, 0, 0, 0, 0]
```アルゴリズムにより空のオブジェクトが生成されます。`req`これは、移動が必要ないという事実と一致します。 

もう 1 つの特殊なケースは、正確に 1 つの位置が必要な場合です。 たとえば:

 入力:```
n = 4
a = [0, 0, 1, 0]
```フィルタリングされたリストは次のとおりです`[2]`。 連続するペアがないため、ループはスキップされ、答えは 0 のままです。これは正しいです。単一の点を訪問する場合、別個の必要な位置間を移動する必要がないからです。 

3 番目のエッジケースは、すべてのポジションが必要な場合です。 その場合、アルゴリズムはすべての隣接する差分を合計し、効果的に次の値を生成します。`n - 1`。 のために：```
a = [1, 1, 1, 1]
```計算結果は`1 + 1 + 1 = 3`これは、バックトラックせずにセグメント全体を 1 回歩くことに相当します。
