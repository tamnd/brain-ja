 ## 解決策
 ## 問題の理解

 長さの円形カレンダーを備えた 1 年モデルが与えられています。`k`、毎日が繰り返される場所`k`ステップ。 がある`n`各ファラオには 2 つの段階からなる地域が割り当てられます。植栽には時間がかかります。`p[i]`時間単位と収穫にかかる時間`c[i]`時間単位。 両方のフェーズが完了すると、そのファラオのための 1 つの祭りがちょうど同じ時間に開催されます。`p[i] + c[i]`。 

時間には周期があるから`k`、スケジュール設定で重要なのは、絶対的な時間ではなく、年間の中での位置です。`(p[i] + c[i]) mod k`。 

各祭りは最初の日に行われなければならないと言われています`n`ある年の日数。つまり、その年の曜日が範囲内にある必要があります。`[0, n-1]`。 整数年ごとにシフトすると、次の倍数が加算されるだけなので、`k`、剰余モジュロは変更されません`k`したがって、各ファラオの祭りの日は完全に次のように決定されます。`t[i] = (p[i] + c[i]) mod k`。 

たとえ異なる年であっても、2 つのフェスティバルを同じ暦日に開催することはできません。 これにより、衝突は剰余クラスのモジュロのみに依存するため、年シフトを使用して衝突を分離する自由が失われます。`k`。 

したがって、タスクは、これらが`n`残基はすべて別個であり、それぞれが次の位置にあります。`[0, n-1]`。 

制約の観点から見ると、`n`まで上がります`10^6`したがって、どのような解も線形または線形に近いものでなければなりません。 ソートもハッシュも問題ありませんが、二次関数はすぐに不可能になります。 重要な点は、問題がモジュラー残基に正しく還元されると、組み合わせ検索は残らないということです。 

慎重に削減しないと、いくつかの微妙なエッジケースが発生します。 

二人のファラオが同じものを生産した場合`(p[i] + c[i]) % k`、たとえば、合計が大幅に異なる場合でも衝突します。`k = 5`、`t = [1, 6]`両方ともマップされます`1`、衝突を強制します。 

剰余が有効なモジュロである場合`k`しかし超えます`n-1`、 例えば`n = 3`、`k = 10`、剰余は次と等しい`7`の場合、その年の有効な日であっても、「最初の n 日間」の要件に違反します。 

最後に、衝突を避けるために誤って異なる年を割り当てようとすると、年のシフトによって日付が変更されないため、失敗します。 

## アプローチ

 強引な解釈では、各ファラオをある年の特定の日に割り当て、配置を明示的にシミュレートし、考えられるすべての年のシフトにわたってすべての衝突をチェックします。 それぞれの選択が他のすべての選択と相互作用し、配置に関して指数関数的、または少なくとも二次関数的な推論につながるため、これはすぐに実行不可能になります。 

重要な構造の単純化は、時間が固定係数で周期的であることです。`k`、したがって、各イベントは単一の不変の残基に折りたたまれます。`(p[i] + c[i]) mod k`。 これが観察されると、すべての自由が失われます。私たちは、これらの残基がセットへの単射写像を形成するかどうかをチェックするだけです。`{0, 1, ..., n-1}`。 

これにより、問題は単純な周波数チェックと範囲検証に軽減されます。

 ## アルゴリズムのチュートリアル

 ### 1. 実質的なフェスティバルの日を計算する

 ファラオごとに計算します`t[i] = (p[i] + c[i]) % k`。 丸年単位でシフトしてもこの値は変わらないため、これはフェスティバルが開催される可能性がある唯一の日付です。 

### 2. 日範囲制約を検証する

 それぞれかどうかを確認してください`t[i]`にある`[0, n-1]`。 いずれかの値が以上の場合`n`、そのフェスティバルは許可された最初の範囲内に配置できないため、構成は不可能です`n`日々。 

### 3. 一意性を確認する

 それぞれを挿入します`t[i]`ハッシュセットに入れます。 値がすでに存在する場合、2 つのフェスティバルが同じ暦日を共有することになり、スケジュールが無効になります。 

### 4. 結果を返す

 両方の条件がすべてのファラオに当てはまる場合、出力`"S"`、それ以外の場合は出力`"N"`。 

### なぜ効果があるのか

 各ファラオの祭りの時間はモジュロで固定されています`k`, そのため、数年にわたるスケジュールの自由度は、1 年以内の注文には影響しません。 重要な唯一の制約は、これらの固定残基を利用可能なオブジェクトに注入できるかどうかです。`n`衝突のないスロット。 このアルゴリズムは、許可されたドメインへの注入性を直接検証するため、失敗は禁止された重複または範囲外の割り当てに正確に対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    p = list(map(int, input().split()))
    c = list(map(int, input().split()))
    
    seen = set()
    
    for i in range(n):
        t = (p[i] + c[i]) % k
        if t >= n:
            print("N")
            return
        if t in seen:
            print("N")
            return
        seen.add(t)
    
    print("S")

if __name__ == "__main__":
    solve()
```コードはリダクションに正確に従っています。 計算`(p[i] + c[i]) % k`は標準的な時間の位置です。 の`t >= n`check は「最初の n 日間」の制限を強制します。 このセットでは、2 人のファラオが同じ日を共有しないように強制されます。 

よくある実装上の落とし穴は、両方の制約を個別にチェックする必要があることを忘れていることです。値が許容日範囲外にある場合、一意性だけでは十分ではありません。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべての値が別個のモジュロである場合です。`k`しかし、1 つは許容範囲を超えています。 たとえば、次の場合`n = 3`、`k = 10`、計算された剰余は`7`、最初の 3 日以内に配置できないため、まだ無効です。 アルゴリズムはこれを直ちに拒否します。`t >= n`一意性の推論が重要になる前の条件。 

もう 1 つのエッジ ケースは、モジュロ リダクション下の完全衝突です。 たとえば、複数のファラオの意見が異なる場合、`(p[i] + c[i])`ただし、同じ剰余モジュロを共有します`k`、年をまたいだスケジュールの解釈に関係なく、それらは必然的に矛盾します。 セットベースのチェックは、反復中にこれを直接捕捉します。 

最後の微妙なケースは次のような場合です。`k < n`制約があるため不可能です (`n ≤ k`)、ただし、それでもなお、剰余が衝突する可能性があります。これは、モジュロ削減により、より大きな整数空間がより小さな巡回領域に折りたたまれるためです。
