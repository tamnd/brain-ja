 ## 解決策
 ## 問題の理解

 私たちは非常に大きなサイズのグリッドに取り組んでいます$2n \times 2m$ただし、座標の合計が偶数である白いセルのみに注目します。 これらの白いセルの中には、一連の更新中に使用可能と使用不可が動的に切り替わるものもあります。 

更新のたびに、正確に選択できるかどうかを判断する必要があります。$n \cdot m$選択した 2 つのセルが対角線を含めて隣接しないような白いセル。 言い換えれば、選択された 2 つのセルがエッジやコーナーを共有することはできません。 

これはグラフ上のパッキング問題です。各白いセルは頂点であり、エッジはチェビシェフ距離 1 以内にあるセルのペアを接続します。サイズのセットを選択できるかどうかを尋ねられます。$n \cdot m$現在利用可能な頂点内に独立したセットを形成します。 

重要な制約は、ボードが巨大であり、アップデートが次の期間まで行われることです。$2 \cdot 10^5$したがって、切り替えのたびに最大の独立セットを再計算することは不可能です。 クエリごとにすべてのセルにアクセスするソリューションであっても、すぐに遅すぎます。 私たちは、各更新がほぼ対数時間または償却対数時間で処理される構造に強制されます。 

2 つのセルが斜めに隣接する小さな領域を除いて、使用可能なセルがほぼ完全に有効な構成を形成する場合、微妙なエッジ ケースが発生します。 斜めの隣接はエッジの隣接よりも弱いように感じられますが、ここでは同様に禁止されており、これはまさに単純な貪欲な構築が失敗する場所です。 たとえば、$2 \times 2$白セルのブロック (パリティ制約により交互) では、たとえローカルにカウントすることで実現可能性が示唆されたとしても、斜めに隣接する 2 つのセルが残っている場合、3 つのセルを選択することは不可能です。 

問題は、制約が純粋に局所的な次数に基づいていないことです。 これは、厳しい容量制限を持つグローバル パリティの 2 部構造をエンコードします。 

## アプローチ

 効率を無視する場合、切り替えのたびに実現可能性を最初から再計算するのが自然な考え方です。 利用可能な白セルのグラフを構築し、最大独立セットまたは同等の最小頂点カバーを計算し、それを必要なサイズと比較します。$n \cdot m$。 キングはキング グラフ内の独立したセットに対応するため、これは原理的には正しいです。 

ただし、グラフには、$O(nm)$頂点とエッジが大きすぎます。 クエリごとに 1 つの最大マッチングやフロー計算さえも不可能です。 

重要な観察は、チェス盤上のキング グラフを、問題を、特定の 2 部マッチングが固定ターゲットを飽和させるかどうかをチェックするという構造に分解できることです。 この変換は、基板を回転座標系で表示することによって行われます。正方形で作業する代わりに、隣接関係が方向性エッジの小さなセットに対応するグリッドに制約をマッピングし、実現可能性条件がカット キャパシティ条件になります。 

この問題の古典的な結果は、配置できるキングの最大数が、グリッドのサイズから派生二部グラフの最小頂点カバーのサイズを引いたものに等しいということです。 構造は平面的で局所的に一貫しているため、問題は特定の動的カット値がしきい値未満に留まるかどうかを維持することに帰着します。 

ハード バージョンではセルが切り替わるため、完全に動的な構造が必要です。 重要な洞察は、各セルが少数のローカル制約にのみ寄与しており、グローバル条件はスイープ構造を使用して行と列にわたる寄与の合計として表現できるということです。 これにより、エッジ アクティビティ間隔を保存するセグメント ツリーと組み合わせて、時間の経過に伴う分割統治が可能になります。各エッジ (競合ペア) は、両方のエンドポイントが利用可能なクエリ間隔中にのみアクティブになります。 

次に、時間軸に対して分割統治を実行し、ロールバックを使用して DSU を維持し、アクティブな競合によって引き起こされた制約グラフ内の接続されたコンポーネントを追跡します。 実現可能性は、2 部コンポーネント構造が固定限界に違反しているかどうかをチェックすることに帰着します。

 ## アルゴリズムのチュートリアル

 この問題を禁止されたペアの観点から再解釈します。 2 つの白セルは、チェビシェフ距離 1 以内にある場合、互いに攻撃します。これは、各セルが一定数の競合エッジに参加することを意味します。 

可用性を動的に追跡するため、各セルは複数の連続しない時間セグメントにわたってアクティブになります。 2 つの白いセル間の各競合エッジについて、それらのアクティブな間隔の交差点を決定します。 これらの間隔中、エッジは競合グラフ内で「アクティブ」になります。 

ここでは、クエリ インデックスに対してセグメント ツリーを使用して時間を処理します。 

1. 各セルのトグルをアクティブな間隔に変換します。 すべてのセルは非アクティブとアクティブを繰り返すため、その生きているセグメントを長期にわたって保存します。 エッジ アクティビティは両方のエンドポイントが同時にアクティブであることに依存するため、この手順が必要です。 
2. 隣接する白セル (対角隣接を含む) 間の競合エッジごとに、アクティブな間隔の交差を計算し、そのエッジをそれらの間隔をカバーするセグメント ツリー ノードに挿入します。 これにより、動的グラフが間隔が割り当てられたエッジの静的なコレクションに変換されます。 
3. DFS を使用してセグメント ツリーを走査します。 各ノードで、アクティブな競合グラフの接続されたコンポーネントを格納するロールバックを備えた DSU を維持します。 
4. ノードに入るとき、そのノードに保存されているすべてのエッジを結合します。 これは、その時間セグメント全体にわたって有効なすべての競合のアクティブ化をシミュレートします。 
5. クエリ時間に対応するリーフにいる場合、現在の構造が実現可能性に違反しているかどうかを計算します。 これは、キング パッキング限界によって暗示される 2 部バランス制約に違反するコンポーネントがあるかどうかをチェックすることになります。 
6. セグメント ツリー ノードの子を処理した後、このノードで実行されたすべての DSU 操作をロールバックします。 これにより、時間セグメント間の独立性が確保されます。 

重要な部分は、DSU が接続性を追跡するだけでなく、2 部パリティの一貫性も追跡していることです。 各共用体はパリティ状態をマージします。 矛盾が生じた場合、設定は無効になります。 

### なぜ効果があるのか

 競合グラフは、キングの禁止された隣接関係を正確にエンコードします。 有効な配置は、隣接制約によって引き起こされる各閉じた近傍領域から最大 1 つの頂点を選択することに対応します。 2 部構造により、実現可能性は接続されたコンポーネント内のパリティ制約の一貫性のみに依存します。 すべてのエッジは連続した時間間隔にわたってアクティブであるため、セグメント ツリー分解により、一貫性のない時間状態が混在しないことが保証されます。 DSU ロールバックは、関連するすべての制約を集計しながら、各間隔が個別に評価されることを保証することで正確さを維持します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n
        self.parity = [0] * n
        self.stack = []
        self.bad = 0

    def find(self, x):
        while self.parent[x] != x:
            x = self.parent[x]
        return x

    def unite(self, a, b):
        ra = self.find(a)
        rb = self.find(b)

        if ra == rb:
            if self.parity[a] == self.parity[b]:
                self.stack.append((-1, 0, 0, 0))
                self.bad += 1
            else:
                self.stack.append((-1, 0, 0, 0))
            return

        if self.size[ra] < self.size[rb]:
            ra, rb = rb, ra
            a, b = b, a

        self.stack.append((rb, self.parent[rb], self.size[ra], self.parity[rb]))

        self.parent[rb] = ra
        self.parity[rb] = self.parity[a] ^ self.parity[b] ^ 1
        self.size[ra] += self.size[rb]

    def snapshot(self):
        return len(self.stack), self.bad

    def rollback(self, snap):
        t, bad0 = snap
        while len(self.stack) > t:
            rb, prev_parent, prev_size, prev_parity = self.stack.pop()
            if rb == -1:
                continue
            ra = self.parent[rb]
            self.size[ra] -= self.size[rb]
            self.parent[rb] = prev_parent
            self.parity[rb] = prev_parity
        self.bad = bad0

 ## 特殊なケース

 重大なエッジ ケースは、少数のセルのみが残っているが、それらが斜めの隣接チェーンを形成している場合です。 使用可能なセルの数が必要なキングの数と等しい場合でも、構成は無効です。 同じコンポーネント内の 2 つのセルが同じパリティ割り当てを必要とする場合、DSU パリティ構造が不一致を検出するため、アルゴリズムはこれを検出します。 

もう 1 つのエッジ ケースは、同じセルの切り替えが繰り返されることで、複数の互いに素なアクティブな間隔が作成されます。 セグメント ツリーの分解がなければ、単純なアプローチではこれらが誤ってマージされ、制約が過剰にカウントされてしまいます。 間隔ベースの挿入により、各アクティブ化期間が独立して処理されるようになり、時間セグメント間のリークが防止されます。
