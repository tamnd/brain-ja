 ## 問題の理解

 この問題では、単純な整数エンコーディング スキームをリバース エンジニアリングすることが求められます。 Pasha は厳密に正の整数を暗号化します$n$3つの数字を使って$a$、$b$、 そして$c$、すべてが 2 つの指定された境界の間にあるように制約されます。$l$そして$r$。 暗号化式は次のとおりです$m = n \cdot a + b - c$。 私たちは与えられています$l$、$r$、および暗号化された値$m$有効なトリプルを見つけなければなりません$(a, b, c)$正の整数と一緒に$n$それは方程式を満たします。 

制約は、実現可能なアルゴリズムの複雑さに関するヒントを与えます。 テストケースの数が少ない（$t \leq 20$)、しかし限界は$l$そして$r$最大 500,000 まで可能で、$m$と同じ大きさにすることができます$10^{10}$。 これにより、考えられるすべての値を試行するソリューションは即座に除外されます。$n$素朴な意味で、なぜなら$n$巨大なものになる可能性があります。 

注意すべきエッジケースは次のような場合です。$m$よりも小さいです$l$、最初の倍数を意味します$a \cdot n$すでに超えているかもしれない$m$。 もう 1 つの注意が必要な状況は次のような場合です。$m$かろうじて大きいです$l$または$r$、小さな違いがあるため、$b$そして$c$に到達するには正確に補正する必要があります$m$。 ただ選ぶだけの無頓着なアプローチ$a = b = c = l$ここで失敗するかもしれません。 

## アプローチ

 ブルートフォース ソリューションでは、可能な限りすべてのことを繰り返すことになります。$a$範囲内で$[l, r]$、それぞれについて$a$解決しようとする$n \cdot a + b - c = m$可能なすべてをループすることによって$n$。 それでは各候補者ごとに$n$私たちは選択しようとします$b$そして$c$式が成り立つような許容範囲内です。 これは原理的には正しいですが、完全に実行不可能です。$r - l$500,000 ですが、数百万になる可能性があります$a$候補者と、$n$簡単にできる$10^{10} / l$、何兆もの小切手につながります。 

重要な洞察は、その違いに気づくことです$b - c$間の任意の整数を指定できます$-(r-l)$そして$r-l$に比べて小さいです。$m$。 これはつまり$n$正確に分ける必要はない$m$; 選ぶだけでいいのです$a$残りが$|m \bmod a|$として表せるほど十分小さい$b - c$。 基本的に、どんなものに対しても、$a$、最も近い倍数$a$に$m$は$n \cdot a$、残りは必要な値を与えます$b - c$。 全部試してみることで$a$で$[l, r]$そして調整する$b$そして$c$わずかな残りを吸収するために、解決策を保証します。 これにより、問題は線形時間に短縮されます。$r-l$何兆ものステップの代わりに。

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、次の内容を読んでください。$l$、$r$、 そして$m$。 最大許容差を計算します$d = r - l$。 これは調整できる範囲です$b - c$限界を超えずに。 
2. 各候補をループします$a$から$l$に$r$。 それぞれについて$a$、次の場合に剰余を計算します。$m$で割られる$a$:$rem = m \bmod a$。 この残りはどれくらいですか$m$最も近い下位の倍数からの値です$a$。 
3. 次のことを確認します。$rem \le d$。 その場合は設定してください$n = m // a$、$b = l + rem$、$c = l$。 それから$n \cdot a + b - c = n \cdot a + rem = m$。 
4. それ以外の場合、$a - rem \le d$、 それから$m$の高い倍数よりわずかに小さい$a$。 セット$n = m // a + 1$、$b = l$、$c = l + (a - rem)$。 それから$n \cdot a - (a - rem) = m$。 
5. 最初のトリプルを出力します$(a, b, c)$条件を満たすことが分かりました。 有効な解決策が見つかったら、ループを中断します。 

なぜ機能するのか: 不変条件は、どのような場合でも$a$、最も近い小さい倍数のいずれか$a$に$m$または、最も近いより大きな倍数は最大でも$r-l$離れて。 調整することで$b$そして$c$せいぜい$r-l$、いつでも一致するように補正できます$m$。 問題によって解決策が存在することが保証されるため、ループがオーバーします。$[l, r]$有効なトリプルが見つかります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    l, r, m = map(int, input().split())
    d = r - l
    for a in range(l, r + 1):
        rem = m % a
        if rem <= d:
            n = m // a
            b = l + rem
            c = l
            if n > 0:
                print(a, b, c)
                break
        elif a - rem <= d:
            n = m // a + 1
            b = l
            c = l + (a - rem)
            if n > 0:
                print(a, b, c)
                break
```最初のループでは、テスト ケースの数を読み取ります。 2 番目のループは、各テスト ケースを個別に処理します。 それぞれについて$a$候補者、残りを計算します$rem$最も近い倍数を次のように調整できるかどうかを判断します。$b - c$合わせる$m$。 の`if n > 0`状態は厳密にポジティブを維持することを保証します$n$、それ以外の場合はゼロになる可能性があります。$m$に比べて小さい$a$。
