 ## 解決策
 ## 問題の理解

 小文字と疑問符で構成される短い文字列が与えられます。 各疑問符は、後で任意の小文字に置き換えることができます。 置換後は、固定パターンを含む文字列が得られるようにしたいと考えています。`"abacaba"`部分文字列として 1 回だけ。 

タスクは、単に次のことを確認することではありません。`"abacaba"`現れることがあります。 可能であれば完全な有効な文字列を積極的に構築し、すべての置換後に最終的な文字列のどこかにパターンが 1 つだけ出現することを確認する必要があります。 

重要な制約は、文字列の長さが最大 ​​50 であり、テスト ケースの数が最大 5000 であることです。 これにより、考えられるすべての部分文字列をチェックし、試行ごとに線形検証を実行するソリューションが受け入れられることがすぐにわかります。 50 の 2 乗は自明であり、そのようなケースが 5000 個であっても問題なく制限内に収まるため、テスト ケースごとの 2 次アプローチは問題ありません。 

主な微妙な点は、疑問符がワイルドカードとして機能することです。 これらは何でもよいので、パターンを強制的に一致させるために使用できます。 しかし、それらは危険ももたらします。`"abacaba"`、残りの文字を埋めた後、他の偶然の出来事が他の場所に現れる可能性があります。 

単純な間違いは、最初の互換性のある位置にパターンを貪欲に配置し、それが機能すると仮定することです。 別の隠れた出来事が他の場所に残っている場合、これは失敗します。 もう 1 つの間違いは、疑問符を任意に入力した後、誤って追加の一致が作成される可能性があるという事実を無視することです。 

For example, consider a string like:```
?abacaba?
```置いたら`"abacaba"`位置 1 から開始しても、端を埋める方法によっては、別のオカレンスが重なってしまう可能性があります。 最終的な文字列を検証しない不注意なアプローチでは、不正確な答えが生成されます。 

もう 1 つの失敗モードは、疑問符を解決する前に発生回数をカウントすることです。 以来`'?'`何でも一致する可能性があるため、修正せずにカウントすると、意味のない結果が得られます。 

## アプローチ

 強引なアイデアは、疑問符を文字に置き換えるあらゆる方法を試してから、`"abacaba"`。 これは明らかに実行不可能です。最大 50 の位置にはそれぞれ 26 の可能性があるため、検索空間は天文学的に大きくなります。 

唯一の意味のある決定は、`"abacaba"`が始まります。 開始位置の候補は最大 44 個あります。 候補位置ごとに、互換性をチェックしてパターンを強制的に適用しようとします。すべての固定文字が一致する必要があり、疑問符は一致するように置き換えることができます。 

候補が機能する場合は、次のようにして完全な文字列を一時的に構築します。`"abacaba"`そこに、他のすべての疑問符を任意に埋めます。たとえば、`'z'`。 次に、次の出現を数えることによって最終的な文字列を検証します。`"abacaba"`。 1つであれば受け付けます。 

重要な洞察は、グローバルにすべての置換について推論する必要はないということです。 必要なのは、1 つの出現をアンカーし、文字列を確定的に完成させ、正確さを検証することだけです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | すべてのプレースメントを試して検証 | O(n^2) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは、どこがユニークなのかを判断しようとします。`"abacaba"`部分文字列を配置する必要があります。 

1. 可能なすべての開始インデックスを反復処理します。`i`ここで、長さ 7 のパターンは文字列内に収まります。 これにより、必要な部分文字列の可能なすべての場所を確実にカバーできます。 
2. ポジションごとに`i`、オーバーレイできるかどうかを確認します`"abacaba"`文字列の上に。 パターン内のすべての文字について、元の文字列に同じ文字があるか、または含まれている場合、位置は有効です。`'?'`。 これにより、パターンを法的に強制できることが保証されます。 
3. 位置が有効な場合は、文字列の作業コピーを作成し、次のように書き込みます。`"abacaba"`ポジションに`[i, i+7)`。 
4. 残りすべてを交換します`'?'`文字列の中に`'z'`。 この選択により、誤って新しいオカレンスが作成されることを回避できます。`"abacaba"`構造によって強制されない限り。 
5. 結果の文字列をスキャンして回数を数えます`"abacaba"`部分文字列として表示されます。 
6. カウントがちょうど 1 の場合は、この文字列を応答として直ちに返します。 
7. 有効な構築につながる位置がない場合は、出力`"No"`。 

### なぜ効果があるのか

 このアルゴリズムは、有効な最終文字列が存在する場合、少なくとも 1 つの配置が存在することを保証します。`"abacaba"`それはそのソリューション内の実際の出来事と一致します。 その配置を試みるときは、それを正確に保持し、他のすべてを決定論的に埋めることで曖昧さを排除します。 1 文字おきに固定されているため、最終的な出現数は信頼できます。 正しい解決策はテストされたアンカーの 1 つに対応している必要があるため、有効な答えを見逃すことはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

PAT = "abacaba"

def count_occ(s):
    cnt = 0
    for i in range(len(s) - 6):
        if s[i:i+7] == PAT:
            cnt += 1
    return cnt

def can_place(s, i):
    for j in range(7):
        if s[i+j] != '?' and s[i+j] != PAT[j]:
            return False
    return True

def solve_case(n, s):
    s = list(s)

    for i in range(n - 6):
        if not can_place(s, i):
            continue

        t = s[:]
        for j in range(7):
            t[i+j] = PAT[j]

        for k in range(n):
            if t[k] == '?':
                t[k] = 'z'

        cand = ''.join(t)
        if count_occ(cand) == 1:
            return "Yes\n" + cand

    return "No"

def main():
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        s = input().strip()
        out.append(solve_case(n, s))
    print("\n".join(out))

if __name__ == "__main__":
    main()
```実装の中核は、考えられるそれぞれの配置を試すことです。 ヘルパーさん`can_place`競合する固定文字を決して上書きしないようにします。 パターンを配置した後、残りの疑問符をすべて次のように変換することで非決定性を排除します。`'z'`、検証が簡素化されます。 

最終チェックが重要です。 完全な建設後に発生件数を再カウントしないと、二次的な事故が発生した場合を誤って受け入れる可能性があります。`"abacaba"`が表示されます。

 ## 特殊なケース

 重大なエッジケースは次のような場合です。`"abacaba"`は、最初の文字列にすでに疑問符付きで複数回出現しています。 入力後に一意性を明示的に強制しない場合、そのようなケースが誤って受け入れられる可能性があります。 

例えば：```
abacaba?abacaba
```最初の出現箇所にパターンを配置し、残りを埋めると`'?'`と`'z'`、2 番目の出現はまだそのまま残っている可能性があります。 最終的なカウントチェックでは、設定を拒否することでこの間違いを防ぎます。 

もう 1 つのエッジ ケースは、パターンを配置すると、存在する可能性のある 2 番目の出現が削除される場合です。 1 つの領域のみを上書きし、残りを決定的に埋めるため、生き残った出現は完全に制御され、正確さを保証するために明示的にカウントする必要があります。
