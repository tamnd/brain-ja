 ## 解決策
 ## 問題の理解

 テキスト文字列とパターン文字列が与えられます。 許可される操作は、テキスト内のパターンの出現箇所を選択し、その出現箇所全体をドットに置き換えることです。 これらのドットは依然として位置を占めていますが、その後のパターン マッチには参加しなくなりました。 

目標は、すべての出現を削除するだけではなく、そのような置換の数を最小限に抑えることです。 その最小数が固定されたら、その最小値を達成するための個別の方法がいくつ存在するかをカウントする必要もあります。ここで、異なる位置で始まる出現を削除する 2 つの方法は異なるものとみなされます。 

重要な点は、オカレンスが重複する可能性があり、1 つのオカレンスを削除すると他のオカレンスが破壊されたり、部分的に影響を与えたりする可能性があることです。 これにより、構造が動的になります。早い段階で出現箇所を選択すると、後に残るものが変更される可能性があります。 

制約の合計サイズは小さく、テスト ケースにわたるすべての文字列の長さの合計は最大でも 500 です。これはすぐに、$O(n^3)$あるいは慎重に設計された$O(n^2)$動的計画法による解決策は許容されますが、部分文字列に対する指数関数やすべての削除シーケンスの単純なシミュレーションは許容されません。 

素朴なアプローチでは、パターンの出現のすべてのサブセットを試し、削除をシミュレートします。 最初にすべての一致を列挙したとしても、$O(n^2)$、サブセットの数は、一致の数において指数関数的に増加する可能性があります。 のような文字列で`"aaaaaa"`模様付き`"aa"`、重複する出現が多数あり、サブセットの選択肢が組み合わせ的に爆発的に増加します。 

もう 1 つのよくある間違いは、貪欲な削除です。つまり、常に左端または右端の出現箇所を削除してしまいます。 これは、最適なソリューションでは、後でより適切にパッキングできるように、初期の有効な一致をスキップする必要がある場合があるため、失敗します。 たとえば、`"aaaaa"`と`"aaa"`最初の一致を選択すると、戦略に応じて異なる最適なカウントが生成される可能性がある、その後の 2 つの重複する一致がブロックされます。 

したがって、この構造は基本的に、パターンの間隔の出現のセットを選択し、それらを削除した後 (重複伝播を考慮して)、すべての出現が除去されると同時に、選択された間隔の数を最小限に抑え、最適なカバーをカウントすることになります。 

## アプローチ

 まず、文字列内のパターンの出現をすべて列挙します。 それぞれの出現は間隔です$[l, r]$。 出現箇所を選択すると、そのセグメントを「消去」しますが、消去すると文字がドットに変わるため、1 つの区間を削除すると他の区間が破壊または分割される可能性があるため、出現箇所が重複すると事態が複雑になります。 

ブルートフォースのアイデアは、各出現を決定点として扱い、それを採用するか否かを選択し、各サブセットの後で結果の文字列をシミュレートすることです。 サブセットごとに、すべての出現が破棄されたかどうかを確認し、使用された削除の数をカウントします。 これは正しいですが、出現回数が異なる可能性があるため、実行不可能です。$O(n^2)$密な文字列では、サブセットの列挙が指数関数的に行われます。 

重要な点は、削除後の文字列の完全な構造が実際には必要ないということです。 重要なのは、部分文字列が以前の削除によってすでに「カバー」されているかどうかだけです。 これは、ポジションに関する動的プログラミングの定式化につながります。 

文字列を左から右に処理します。 それぞれの位置で、パターンの発生がそこから始まるかどうかを検討します。 状態は、文字列をカバーしている範囲と、この状態に到達する有効な最適シーケンスの数をエンコードする必要があります。 

直接の DP は次のようになります。$dp[i]$位置から始まるすべての出現を除去するために必要な最小移動数を表します。$i$、 そして$ways[i]$から最適なシーケンスがいくつ存在するかを数えます$i$。 

位置から$i$、何もしなければ、$i$に移動します$i+1$。 から始まるパターンの発生がある場合$i$にジャンプして、削除することを選択できます。$i+|t|$。 ただし、重複したオカレンスは削除することを意味するため、これでは不十分です。$i$以前に開始されたオカレンスに影響を与える可能性があります$i$しかし後で終わります。 

重複を正しく処理するために、代わりに視点を変えます。プレフィックスよりも DP を考慮し、削除が文字列をどこまで「カバー」できるかを追跡します。 位置から始まる出現を選択すると$i$、それはカバーします$[i, i+|t|-1]$、重複するオカレンスはすでに破棄されているとみなされます。 

したがって、正しい定式化は、プレフィックス処理を伴う間隔 DP になります。各位置に対してできる限りの最善を維持し、発生を考慮するときは、それをカバレッジを拡大するアクションとして扱います。 

この遷移は、加重区間カバーに似ています。すべての「不良イベント」(パターンの出現) をカバーする最小数の区間を選択したいのですが、区間は他の区間を破壊するため、問題を、すべてのイベントが少なくとも 1 つの選択された区間と交差する必要があるラインをカバーするものとして再解釈します。 これはインターバルでの打撃セットに帰着しますが、インターバルは直線上にあり、弦の位置によって構造化されているため、貪欲な DP が機能します。 

開始インデックスによって出現をソートし、次にどの出現を選択するかを決定する DP を実行し、常に前方にジャンプし、等しい DP 状態にわたる組み合わせ論によって方法をカウントします。

 ## アルゴリズムのチュートリアル

 1. 出現するパターンをすべて検索します。$t$で$s$、開始インデックスを保存します。 それぞれの出現は長さの間隔に対応します$|t|$。 
2. 開始インデックスを並べ替えます。ただし、実際には、それらはすでに自然に順序付けされています。 
3. 位置ごとに計算する DP を定義します。$i$、以降で始まるすべての出現を削除するために必要な最小削除数。$i$。 これは、問題を、すべての出現がカバーされるように削除をどこに配置するかを決定することであると再構成します。 
4. 位置で$i$、そこで何も発生が開始されない場合は、次のステップに進みます。$i+1$コストなしで。 これは、位置をスキップしても、新たに必要な削除が発生しないためです。 
5. 発生が開始された場合$i$、決定があります: ある位置から始まる削除を使用してそれをカバーするかどうか$j \le i$それを超えるか、または次の場所で新しい削除を開始します。$i$。 最適な構造により、最も遠くまで届く範囲をできるだけ早くカバーできるよう常に考慮されます。 
6. オカレンスごとに、開始から終了までジャンプする遷移を計算し、削除カウントを 1 ずつ増やし、以前に計算された最適な状態に基づいて、カバレッジを破ることなくその位置に到達できる方法を蓄積します。 
7. 複数の遷移が同じ DP 値につながる場合、それらのカウントを法的に合計します。$10^9+7$。 

### なぜ効果があるのか

 それぞれの出現は、少なくとも 1 つの選択された削除によって「ヒット」する必要がある間隔です。 有効な解はどれも、和集合がすべての出現間隔と交差する間隔のセットを選択することに相当します。 間隔は直線上にあるため、最適解は、カウントを増やすことなく、終了位置の昇順で削除を選択する解に常に変換できます。 この貪欲な構造により、ポジションまたはインターバルのエンドポイントにわたる DP がすべての最適解を確実に捕捉し、等コスト状態間の遷移をカウントすることで、すべての最小カバレッジが正しく列挙されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def find_occurrences(s, t):
    n, m = len(s), len(t)
    occ = []
    for i in range(n - m + 1):
        if s[i:i+m] == t:
            occ.append(i)
    return occ

def solve_case(s, t):
    n, m = len(s), len(t)
    occ = find_occurrences(s, t)

    if not occ:
        return 0, 1

    # dp[i] = min moves to eliminate all occurrences starting from position i
    # ways[i] = number of optimal ways
    # We use suffix DP over positions
    dp = [10**9] * (n + 1)
    ways = [0] * (n + 1)

    dp[n] = 0
    ways[n] = 1

    occ_set = set(occ)

    for i in range(n - 1, -1, -1):
        # option 1: skip
        dp[i] = dp[i + 1]
        ways[i] = ways[i + 1]

        # option 2: if occurrence starts here, take it
        if i in occ_set:
            j = min(n, i + m)
            cand = dp[j] + 1

            if cand < dp[i]:
                dp[i] = cand
                ways[i] = ways[j]
            elif cand == dp[i]:
                ways[i] = (ways[i] + ways[j]) % MOD

    return dp[0], ways[0] % MOD

def main():
    q = int(input())
    for _ in range(q):
        s = input().strip()
        t = input().strip()
        ans = solve_case(s, t)
        print(ans[0], ans[1])

if __name__ == "__main__":
    main()
```このソリューションでは、パターンのすべての出現を構築し、文字列内の位置に対してサフィックス動的プログラムを実行します。 位置の状態$i$は、その接尾辞から開始して達成可能な最良の結果を表します。 

各位置で、それを無視して先に進むか、パターンがそこから始まる場合はそれを「取る」ことを検討し、パターンの長さだけ先に進み、手数を 1 つ増やします。 カウント ロジックは、同等の最適な遷移からウェイを蓄積します。 

微妙な点は、空の出現ケースの処理です。答えはゼロ手で正確に一方向です。 もう 1 つは、モジュロ演算がカウントにのみ適用され、DP 最小値には適用されないことを保証することです。
