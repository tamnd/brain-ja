 ## 解決策
 ## 問題の理解

 タイルの行を表す小文字の文字列が与えられます。 各位置は最初の文字から最後の文字までのパス内のノードですが、隣接する位置にのみ移動する必要はありません。 代わりに、任意のインデックスから他のインデックスにジャンプすることができます。ジャンプのコストは文字にのみ依存します。つまり、アルファベットの位置間の絶対的な違いです。 

タスクは、インデックス 1 から始まりインデックス n で終わる有効なパスを構築し、各インデックスを最大 1 回訪問することです。 可能な限り最小の総コストを達成するすべてのパスの中で、最大数のインデックスを使用するパスを選択する必要があります。これは、最適なコストを増加させることなく、できるだけ多くの中間ストップを挿入することを意味します。 

したがって、この問題には 2 つの層があります。最初に総コストを最小化し、次にすべての最小コストの解決策の中でパス内の頂点の数を最大化します。 

テスト ケース全体の文字列の合計長が最大 2e5 であるという制約は、テスト ケースごとに O(n) または O(n log n) の解を即座に示唆します。 1 つのテスト ケースが大きい場合、単一文字列内の二次関数はすべて失敗します。 

複数の文字がアルファベット順でエンドポイントの間にある場合、微妙なエッジケースが発生します。 たとえば、「az」のような文字列では、「m」のような中間文字には両方のエンドポイントからの距離に応じたコストがかかり、追加のノードを挿入すると、構造に応じてコストが維持または増加する可能性があります。 すべてのインデックスにわたる単純な最短パスでは、中間構造を不必要に再訪問することができますが、インデックスを再訪問することは禁止されているため、サイクルは許可されません。 

主な困難は、任意のエッジを持つグラフ内の最短経路を見つけるだけではないことです。 O(n^2) 遷移の考慮を避けるために、エッジの重みの構造を利用する必要があります。 

## アプローチ

 直接的なアプローチは、n 個のノードを持つ完全な有向グラフ上の最短パスとして問題をモデル化することです。この場合、インデックスのすべてのペアに重み付けされたエッジがあります。 ダイクストラを実行すると正しい最小コストが得られますが、n が 2e5 までの場合、O(n^2 log n) の動作は不可能です。 

遷移を賢く制限したとしても、単純なビューでは依然として O(n^2) 個のエッジが潜在的に考慮されます。 ボトルネックは、すべてのノードが位置ではなく文字のみに依存するコストで他のすべてのノードに接続できることです。 

重要な点は、文字の位置ではなく、アルファベット内の文字の相対的な順序のみが重要であるということです。 文字の観点から考えると、最適な移動は近くの文字値の間で移動することを優先します。これは、大きなアルファベットのギャップを飛び越えるのはコストが高く、それらの中間ステップが存在しない限り、より安価な中間ステップに分解できないためです。 

これは、インデックスをその文字に基づいて並べ替えることによって問題を圧縮することを示唆しています。 インデックスが文字ごとにグループ化されたら、ソートされた順序で隣接する文字間の遷移を考慮するだけで済みます。 同じレター内では、すべてのポジションのコストが等しいため、コストに影響を与えることなく、それらを自由にチェーンして訪問ノードの数を増やすことができます。 

したがって、最適な構造は、文字ごとにグループ化されたすべてのインデックスを訪問し、エンドポイントに応じて周波数境界の昇順または降順で文字を横断するように配置された、文字値を巡る単調なウォークになります。 

正しい構成は、s[1] と s[n] の間でアルファベットの方向を選択し、それらの間に文字が含まれるすべてのインデックスをソートされた文字順に訪問し、文字ごとに出現をグループ化することです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 完全なグラフ最短パス | O(n^2 log n) | O(n^2) | 遅すぎる |
 | 文字ごとに並べ替え/グループ化 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 各文字をアルファベットのインデックスに変換します。 開始を s[1]、終了を s[n] とします。 
2. start と end が同じ文字値を持つ場合、その間にあるその文字のすべての出現を訪問するパスは、コストを増加させることなく再配置できます。 同じ文字の移動を追加してもコストは増加しないため、最適なパスは、その文字を含むすべてのインデックスを訪問することです。 
3. それ以外の場合は、アルファベット空間でのトラバース方向を決定します。 開始値が終了値より小さい場合は上に移動します。 それ以外の場合は下に移動します。 この方向によって、どの中間文字グループを含めるかが決まります。 
4. 文字値ごとにグループ化されたすべてのインデックスを収集します。 文字ごとに、それが出現するすべての位置を保存します。 
5. 開始値から終了値に向かって選択した方向に文字を移動します。 厳密にそれらの間にある各文字に対して、そのすべてのインデックスを任意の順序で追加します。 すべて同じ文字値を持つため、文字グループ内の順序はコストに影響しません。 
6. 最終的なパスを次のように構築します。インデックス 1 を開始し、次に走査順序で収集されたすべての中間インデックス、最後にインデックス n を作成します。 
7. 構築されたパスに沿った連続する文字値間の絶対差を合計することによってコストを計算します。 

この順序が有効である理由は、アルファベットの単調な順序で移動することで、不必要なコストが発生する大きな文字のギャップを「後戻り」することがないことが保証されるためです。 

### なぜ効果があるのか

 コスト関数は文字の値のみに依存し、1 から 26 までの整数にわたってメトリックに似ています。迂回するたびに絶対差が増加するため、総コストを最小化する最適なパスは、離れた文字間で振動することから恩恵を受けることはできません。 したがって、最適なソリューションは、エンドポイント間のアルファベット空間で単調でなければなりません。 単調性が強制されると、連続してグループ化された場合、同じ文字値内で繰り返しアクセスしてもアルファベットの増分変更がゼロになるため、文字の中間オカレンスをすべて挿入してもコストは増加しません。 これにより、最小限のコストと訪問インデックスの最大数の両方が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        s = input().strip()
        n = len(s)

        pos = [[] for _ in range(26)]
        for i, ch in enumerate(s):
            pos[ord(ch) - 97].append(i + 1)

        start = ord(s[0]) - 97
        end = ord(s[-1]) - 97

        path = [1]

        if start <= end:
            for c in range(start, end + 1):
                for idx in pos[c]:
                    if idx != 1 and idx != n:
                        path.append(idx)
        else:
            for c in range(start, end - 1, -1):
                for idx in pos[c]:
                    if idx != 1 and idx != n:
                        path.append(idx)

        path.append(n)

        cost = 0
        for i in range(len(path) - 1):
            cost += abs((ord(s[path[i] - 1]) - 97) - (ord(s[path[i + 1] - 1]) - 97))

        print(cost, len(path))
        print(*path)

if __name__ == "__main__":
    solve()
```実装では、最初に文字ごとにインデックスをグループ化するため、位置間のペアごとの比較が回避されます。 トラバース方向はエンドポイント文字に基づいて選択され、アルファベット空間での単調なスイープが保証されます。 

エンドポイントは常に固定されているため、重複を避けるためにインデックス 1 と n を中間挿入から明示的に除外します。 

選択ロジックの複雑化を避けるために、コストの計算は構築後に行われます。 パスはすでに構造的に最適化されているため、その重みのみを検証します。

 コストは、可能な最小限の遷移に一致する、この単調降下に沿った文字値間の差として計算されます。 

これは、エンドポイント間の中間文字を使用して、最適なコストに違反することなくパスの長さを増加できることを示しています。 

### 例 2:`codeforces`スタートは`c`、最後は`s`, したがって、上に移動します。 

| ステップ | 現在の文字範囲 | 追加されたインデックス | パス |

 これは、多くの中間文字が存在する場合、単調なアルファベットの進行を維持しながら、ジャンプの数を最大化するためにすべての文字を完全に利用していることを示しています。

 ## 特殊なケース

 例外的なケースの 1 つは、すべての文字が同一である場合に発生します。 このアルゴリズムは、すべてのインデックスを 1 文字の下にグループ化し、1 から n までのすべての位置を出力します。 すべての文字の違いがゼロであるため、訪問するノードの数を最大化しながらコストはゼロのままです。 この構築には当然、すべてのインデックスが順番に含まれており、両方の目的が満たされます。 

もう 1 つの特殊なケースは、「cba」のような厳密に減少する文字列です。 アルゴリズムは下方向のトラバーサルを選択し、すべてのインデックスを正しい逆アルファベット順に含めます。 文字列内で位置が順序付けされていない場合でも、グループ化によりすべての出現が正確に 1 回含まれることが保証され、各ステップでアルファベット空間内で 1 単位のみが移動するため、コストは最小限に抑えられます。 

3 番目のケースには、「abac」のような混合文字が含まれます。 a から c への走査には、「a」グループと「b」グループの両方が含まれるため、有益な中間文字がスキップされることはありません。 パスには「a」と「b」のすべての出現が含まれており、コストを増加させる非単調な遷移を導入することなくジャンプを最大化します。
