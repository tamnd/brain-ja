 ## 解決策
 ## 問題の理解

 私たちは友人のコレクションを与えられ、各友人には 2 つの数字、つまりレストランでいくら使うつもりか、そして実際に持っているお金がいくらあるかが与えられました。 目標は、これらの友人の一部を別々のグループに分割し、各グループに少なくとも 2 人が所属するようにすることです。 各人は最大 1 回しか使用できず、一部の友達は完全に除外される場合があります。 

グループは、そのグループで利用可能な合計金額が少なくともそのグループの計画支出総額以上である場合にのみ有効です。 私たちは、そのような有効なグループをできるだけ多く形成できるようにしたいと考えています。 

この構造は、個別に予算を割り当てるのではなく、人々をペアにして、各グループ内の「余剰資金」が集合的に「不足額」をカバーするようにするものです。 これは、単純なマッチングの問題ではなく、バランスの問題を直ちに示唆します。 

制約があるため、私たちは効率的な解決策に向かうことになります。 すべてのテスト ケースにわたる友人の総数は最大 100,000 であるため、テスト ケースごとの n で二次関数となる解は遅すぎます。 テスト ケースごとに O(n log n) であっても許容されますが、O(n^2) よりも悪いものは許容されません。 

単純な考えは、考えられるすべてのパーティションを試したり、サブセットをチェックして貪欲にグループを構築したりすることです。 サブセットの数が指数関数的に増加するため、これはすぐに失敗します。 

さらに微妙な問題は、グループ化の決定が相互作用することです。 大きな余剰を持つ友人は、複数の潜在的なグループで役立つ可能性があり、初期のグループ分けの決定が間違っていると、最終的な答えが減る可能性があります。 たとえば、強いプラスサムの友人 1 名と弱いパートナー 1 名でグループを貪欲に形成すると、後でより大きなグループのバランスをとることができた強力な余剰を無駄にしてしまう可能性があります。 

主な問題点は、グループ化が個々の実行可能性ではなく、合計条件によって制約されることです。 

## アプローチ

 ブルートフォース ソリューションでは、各友人を何らかのグループに割り当て、すべてのパーティションを検証しようとします。 段階的にグループを構築することに限定したとしても、各ステップで残っている友達のサブセットを考慮する必要があります。 これにより、各友人は任意のグループに入れられるかグループから除外される可能性があるため、状態の数が指数関数的に増加します。 枝刈りを行っても、n が 100,000 までの場合、最悪のケースは依然として対処が困難です。 

ターニングポイントは、各友人が正味価値、つまり「予算からコストを差し引いたもの」に貢献していると再解釈することで起こります。$y_i - x_i$。 グループ内のこれらの値の合計が負でない場合、グループは有効です。 これにより、問題は、各グループに少なくとも 2 つの要素が含まれなければならないという制約付きで、正味合計値が少なくとも 0 になるグループを形成するという問題に変換されます。 

このように見ると、この問題は、ソートされた純寄与に基づいて要素をペアリングまたはグループ化することに似ています。 意味のある順序で友達を分類すると、どの要素がグループを固定し、どの要素がグループをサポートするかを貪欲に決定できます。 

最適な戦略は、友達を正味価値で分類することから生まれます$d_i = y_i - x_i$。 正の値は役に立ちますが、負の値は有害です。 グループの数を最大化するには、ポジティブな貢献を使用して、できるだけ多くのネガティブな貢献を「中和」したいと考えています。 貪欲な 2 点戦略が自然に生まれます。つまり、最も弱い (最もネガティブな) ものと最も強い (最もポジティブな) ものを一致させ、それらの合計が負でなくなるたびにグループを形成し、内側に進みます。 

これは、実現可能性を最大化するために極端な値を一致させる最適ペアリング問題と精神的に似ています。

 ## アルゴリズムのチュートリアル

 1. 各友人の正味価値を次のように計算します。$d_i = y_i - x_i$。 これにより、グループの条件が単一の配列の合計制約に変換されます。 グループは、選択したグループの合計が有効である場合に有効です。$d_i$は非負です。 
2. すべて並べ替える$d_i$降順ではない順に。 これにより、最も負の値が最初に配置され、最も正の値が最後に配置されるため、極端なペアの推論が容易になります。 
3. 2 つのポインタを初期化し、1 つは先頭（左）、もう 1 つは末尾（右）に設定します。また、グループ数のカウンタも初期化します。 
4. 左 < 右の場合、2 つの極値をペアにすることを検討します。 もし$d[left] + d[right] \ge 0$の場合、これら 2 つはサイズ 2 の有効なグループを形成できるため、グループを 1 つと数え、両方のポインターを内側に移動します。 これは、利用可能な最も強い値が利用可能な最も弱い値を補償するために使用され、残りの要素の構造を維持するため最適です。 
5. もし$d[left] + d[right] < 0$そうすると、利用可能な最も強い友人であっても、最も弱い友人を補うことはできません。 その場合、左前方に移動して最も弱い要素を破棄します。 最も弱い要素は、他の残りの要素とペアになっている有効なグループの一部になることができないため、これは安全です。 
6. ポインタが合うまで続けます。 成功したペアリングの数が答えです。 

### なぜ効果があるのか

 正しさは、最適解では、ソート後に極端な反対のものをペアにすることによってグループが効果的に形成されると仮定できるという事実に依存します。 非常にネガティブな要素を利用可能な最大のポジティブ要素と組み合わせることができない場合、他の要素はあまり役に立たないため、他の要素とも組み合わせることができません。 したがって、破棄しても安全です。 逆に、最大のプラスが最小のマイナスを補うことができる場合は常に、どちらかをより小さい大きさのパートナーに置き換えても実現可能性を向上させることはできないため、それらをペアにすることは常に安全です。 この貪欲な極端なペアリングにより、最も制限的なネガティブを排除しながら、強いポジティブの最大限の使用が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        x = list(map(int, input().split()))
        y = list(map(int, input().split()))
        
        d = [y[i] - x[i] for i in range(n)]
        d.sort()
        
        l, r = 0, n - 1
        ans = 0
        
        while l < r:
            if d[l] + d[r] >= 0:
                ans += 1
                l += 1
                r -= 1
            else:
                l += 1
        
        print(ans)

if __name__ == "__main__":
    solve()
```実装は、各友人を単一の純残高値に集約することから始まります。 グループ制約は合計のみに依存するため、これは非常に重要です。 

並べ替えることにより、残った「最悪の」候補と「最良の」候補を常に推論できるようになります。 2 つのポインターは、利用可能な最も強いものを使用して最も弱い参加者を救出する試みを繰り返しシミュレートします。 

条件`l < r`すべてのグループに少なくとも 2 人がいることを強制します。 これは問題の制約に直接一致します。 

ペアが有効な場合は、すぐにそのペアにコミットします。 そうでない場合は、現在の最強の候補よりも効果的にそれを救い出す将来のペアは存在しないため、最も弱い要素を破棄します。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべての正味値が負またはゼロの場合に発生します。 たとえば、すべての友人が自分の所持金よりも多く支出している場合、並べ替えられた配列は完全に非正になります。 最も強い要素との有効な組み合わせが負でない合計に達することができないため、アルゴリズムは最も弱い値を繰り返し破棄し、結果としてグループがゼロになります。これは、予算条件を満たす 2 人のグループがないため、現実と一致します。 

もう 1 つのケースは、強い正の値が 1 つだけあり、わずかに負の値が多数ある場合です。 このアルゴリズムにより、最も強力なポジティブな結果が不可能なペアリングに無駄にならないことが保証されます。 これは、実際に弱い要素のバランスをとることができる場合にのみ使用され、そうでない場合は、より弱いマイナス要素が最初に破棄されます。 

最後に、値がゼロの周りに密にクラスター化されている場合、すべてのペアリング試行は成功し、アルゴリズムは貪欲に Floor(n/2) グループを形成します。これは、すべてのペアが構造を残さずに有効なグループに寄与するため、最適です。
