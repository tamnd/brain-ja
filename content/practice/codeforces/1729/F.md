 ## 解決策
 ## 問題の理解

 数字列が与えられます。 すべてのクエリについて、元の文字列の 1 つの部分文字列を調べます。`s[l..r]`、その数値の剰余を計算します。`9`。 

個別に、固定長の 2 つの異なる部分文字列を選択することもできます。`w`。 彼らの開始位置を次のようにします`L1`そして`L2`。 クエリは満足のいくポジションを要求します$$v(L_1,L_1+w-1)\cdot v(l,r)+v(L_2,L_2+w-1)\equiv k \pmod 9$$すべての有効なペアのうち、最小化する必要があります。`L1`、その中で最小化します`L2`。 

まず注目すべき点は、実際の数値が非常に大きくなる可能性があるということです。 部分文字列には最大で次のものを含めることができます`2·10^5`数字なので、数値を直接構築することは不可能です。 幸いなことに、この条件では剰余モジュロのみが考慮されます。`9`。 

すべてのテスト ケースの合計の長さは最大でも`2·10^5`、クエリの合計数も最大です。`2·10^5`。 すべての長さのペアを検査するアルゴリズム`w`すべてのクエリの部分文字列を取得することは絶望的です。 単一のテスト ケースでも、大まかに次の内容を含めることができます。`2·10^5`候補部分文字列があるため、二次関数が有効になります。`4·10^{10}`操作。 

ソリューションはすべての長さを前処理する必要があります。`w`部分文字列を 1 回実行すると、ほぼ一定の時間で各クエリに応答します。 

微妙な点は、答えは単なる有効なペアではないということです。 辞書編集的な最小化が重要です。 剰余クラスが次のような状況を考えてみましょう。`3`開始位置を含む`[2,7,20]`および残差クラス`5`含まれています`[4,8]`。 両方の場合`(2,8)`そして`(7,4)`モジュラー方程式を満たす場合、正解は`(2,8)`なぜなら`L1`より小さいです。 最初の有効な残基の組み合わせで停止する不注意な実装は、間違ったペアを返す可能性があります。 

もう一つの簡単な間違いは、それを忘れることです`L1`そして`L2`異なる位置でなければなりません。 すべての長さを仮定すると、`w`部分文字列には同じ残基があり、その残基は 1 回だけ存在します。 そして、同じ位置を二度使用することは禁止されています。 

例えば：```
s = "111"
w = 2
```長さ 2 の部分文字列のみが次の位置で始まります`1`そして`2`。 単一の残基の再利用を許可するロジックでは、誤って生成される可能性があります。`(1,1)`。 

先頭のゼロも関係します。 部分文字列`"000"`数字を表します`0`、無効な値ではありません。 モジュロだけが必要なので、`9`、桁の合計はこれを自然に処理します。 

## アプローチ

 ブルーフォースのアイデアは単純明快です。 すべてのクエリについて、考えられるすべての長さを列挙します。`w`最初の選択肢としての部分文字列と可能なすべての長さ -`w`部分文字列を 2 番目の選択肢として選択します。 かどうかを確認してください$$(a\cdot x+b)\bmod 9=k$$どこ`a`クエリ部分文字列値の剰余です`9`、 そして`x`、`b`選択した長さの剰余です -`w`部分文字列。 

おおよそあります`n-w+1`候補者たち。 最悪の場合はこれくらいです`2·10^5`したがって、すべてのペアのコストを大まかにチェックすると、$$(2\cdot10^5)^2 = 4\cdot10^{10}$$クエリごとの操作。 それはまったく不可能です。 

重要な観察は、モジュロであるということです。`9`検索スペースが劇的に崩壊します。 

任意の 10 進数の場合、$$value \bmod 9 = (\text{sum of digits}) \bmod 9.$$あらゆる長さ-`w`部分文字列は 9 つだけの残基クラスの 1 つに属します。`0`を通して`8`。 

すべての部分文字列値を記憶するのではなく、その剰余モジュロのみを考慮します。`9`。 残基ごとに`r`、すべての長さの開始位置を保存します。`w`値がモジュロである部分文字列`9`等しい`r`。 

次にクエリを考えてみましょう。 させて$$a = v(l,r)\bmod 9.$$残留物が必要です`x`そして`y`そのような$$(a\cdot x+y)\bmod 9 = k.$$あるのは`9×9=81`チェックする残差ペア。 

各候補残基ペアについて、保存されているリストから辞書編集上最小の有効な位置を即座に決定できます。 81 は定数なので、各クエリは次のようになります。`O(81)`。 

残りのタスクは、部分文字列の残基を効率的に計算することです。 桁の接頭辞の合計を使用すると、任意の部分文字列の桁の合計を次の形式で取得できます。`O(1)`、したがってそのモジュロ`9`値は以下でも利用できます`O(1)`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(m・n²) | O(n) | 遅すぎる |
 | 最適 | O(n + 81m) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 数字の値のプレフィックス合計配列を構築します。 

させて`pref[i]`最初の合計になる`i`数字。 この場合、任意の部分文字列の桁の合計は次のようになります。$$pref[r]-pref[l-1].$$2. あらゆる長さを列挙します。`w`部分文字列。 

スタートポジションごとに`i`、次の桁の合計を計算します。`s[i..i+w-1]`プレフィックスの合計を使用して剰余を取得します`9`。 
3. 開始位置を残基ごとにグループ化します。 

9 つのリストを作成します。 長さの場合は、`w`部分文字列に残余があります`r`、開始位置をリストに追加します`pos[r]`。 

左から右にスキャンするため、各リスト内の位置は自動的に並べ替えられます。 
4. 各クエリを処理します。 

コンピューティング$$a=v(l,r)\bmod 9.$$繰り返しますが、桁の和でこれが得られます。`O(1)`。 
5. すべての残基ペアを列挙します`(x,y)`。 

かどうかを確認してください$$(a\cdot x+y)\bmod 9 = k.$$そのようなペアのみが答えに貢献できます。 
6. 有効な残基ペアについて、使用可能な最小の位置を決定します。 

もし`x != y`、最良の選択は、の最初の要素です。`pos[x]`そしての最初の要素`pos[y]`。 

もし`x == y`、2 つの異なる部分文字列が必要なので、残基クラスには少なくとも 2 つの位置が含まれている必要があります。 最良の選択は、リストの最初の 2 つの位置です。 
7. すべての候補の答えの中で、辞書編集的に最小のペアを保持します。 

まず比較してください`L1`、その後、`L2`。 
8. 保存されたペアを出力する、または`-1 -1`候補者が存在しない場合。 

### なぜ効果があるのか

 あらゆる長さ-`w`部分文字列はその剰余モジュロによってのみ表されます`9`。 クエリ条件は次の残基のみに依存します。$$(v_1\cdot a+v_2)\bmod 9 = ((v_1\bmod9)\cdot(a\bmod9)+(v_2\bmod9))\bmod9.$$したがって、各部分文字列をその剰余で置き換えても、情報は失われません。 

固定剰余ペアの場合`(x,y)`、辞書編集上最小の使用可能な位置は、対応するリストに格納されている最も古い出現位置から常に取得されます。 それ以降の発生は増加するだけです`L1`または`L2`。 

このアルゴリズムは、考えられるすべての残基ペアをチェックします。 すべての部分文字列は正確に 1 つの残基クラスに属するため、すべての有効な答えは検査されたペアの 1 つに対応します。 すべての実行可能な候補の中から、問題の要件に一致する、辞書編集的に最小の候補が選択されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        s = input().strip()
        n = len(s)

        w, m = map(int, input().split())

        pref = [0] * (n + 1)
        for i, ch in enumerate(s, 1):
            pref[i] = pref[i - 1] + int(ch)

        pos = [[] for _ in range(9)]

        for start in range(1, n - w + 2):
            end = start + w - 1
            rem = (pref[end] - pref[start - 1]) % 9
            pos[rem].append(start)

        for _ in range(m):
            l, r, k = map(int, input().split())

            a = (pref[r] - pref[l - 1]) % 9

            best = None

            for x in range(9):
                if not pos[x]:
                    continue

                for y in range(9):
                    if (a * x + y) % 9 != k:
                        continue

                    if x != y:
                        if not pos[y]:
                            continue
                        cand = (pos[x][0], pos[y][0])
                    else:
                        if len(pos[x]) < 2:
                            continue
                        cand = (pos[x][0], pos[x][1])

                    if best is None or cand < best:
                        best = cand

            if best is None:
                print(-1, -1)
            else:
                print(best[0], best[1])

solve()
```プレフィックス合計配列には、数値ではなく桁の合計が格納されます。 モジュロ`9`、桁の合計と数値は同等であるため、巨大な整数を扱う必要がなくなります。 

前処理フェーズでは、あらゆる長さの剰余を計算します。`w`部分文字列。 各開始位置は 9 つのバケットの 1 つに挿入されます。 位置は昇順に処理されるため、バケットの最初の要素が自動的にその剰余を含む最小の開始位置になります。 

クエリ処理中に、`s[l..r]`は同じプレフィックス合計から得られます。 ダブルループオーバー`x`そして`y`81 個の可能な残基の組み合わせをすべて調べます。 ペアがモジュラー方程式を満たすたびに、最も古い有効な位置が対応するバケットから抽出されます。 

特別な場合`x == y`注意が必要です。 2 つの異なる部分文字列が必要なので、位置が 1 つだけのバケットは使用できません。 最初の 2 つの位置は、辞書編集上の最小の有効なペアを提供します。 

Python のタプル比較は、必要な順序付けを簡単に実装します。`(a,b) < (c,d)`正確には小さいことを意味します`L1`、等しい場合は小さい`L2`。

 ## 特殊なケース

 次のことを考慮してください。```
1
0000
1 1
1 4 0
```長さ 1 のすべての部分文字列には剰余があります`0`。 バケットは次のとおりです。```
