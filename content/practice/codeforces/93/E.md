 ## 解決策
 ## 問題の理解

 ヒット インジケーターと呼ばれる、指定された整数セットの中で **割り切れない** 1 から _n_ までの数値がいくつあるかを計算するように求められます。 各インジケーターは他のインジケーターと互いに素であることが保証されており、_k_ 個あり、それぞれ最大 1000 です。概念的に、イゴールの英雄が強さで_n_ インジケーターにエンコードされた武器を振り回していると想像してください。 ダメージは、これらの指標のいずれかで割り切れる「生き残る」数を 1…_n_ で数えることに対応します。 

制約は、アルゴリズムの選択に関する即座の手がかりを与えてくれます。 _n_ は最大 10^13 まで可能で、各数値を個別にチェックするアルゴリズムは除外されます。 10^13 の演算が必要となるため、線形に反復することすら不可能です。 _k_ は比較的小さく、最大でも 100 であり、インジケーターも小さい (≤1000) ため、インジケーターのサブセットを使用する組み合わせ手法が実現可能です。 

_n_ がどの指標よりも小さい場合、明らかではないエッジ ケースが発生します。 たとえば、_n_ = 3 でインジケーターが 5、7、11 の場合、どの数値もどのインジケーターでも割り切れないため、答えは 3 になります。少なくとも 1 つの数値が常に各インジケーターで割り切れると仮定する単純なアプローチは、ここでは失敗します。 もう 1 つの潜在的な落とし穴は、サブセットの組み合わせでインジケーターの積を計算するときの整数のオーバーフローです。 製品によっては 10^13 を超える場合があるので注意が必要です。 

## アプローチ

 ブルートフォース手法は単純です。1 から _n_ までのすべての整数を反復処理し、すべての _k_ インジケーターに対してそれぞれをチェックし、それらのどれでも割り切れないものをカウントします。 これは正しく機能しますが、O(n * k) の演算が必要となり、最悪の場合は 10^15 に達する可能性があります。 これは許容範囲をはるかに超えています。 

重要な観察は、すべての指標がペアごとに互いに素であるということです。 これにより、**包含-除外原則**を使用できるようになります。 インジケーターのサブセットについては、その積で割り切れる数値の数を計算できます。 サブセットに奇数のインジケーターが含まれている場合は、その寄与分を追加します。 偶数であれば、それを差し引きます。 これを使用すると、2^k 個のサブセットのみを考慮する必要があります。これは、積が _n_ を超えるサブセットを取り除く場合、k ≤ 100 の場合に実現可能です。 共素性により、サブセットの最小公倍数がその要素の積に過ぎないことが保証され、計算が簡素化されます。 

ブルート フォースは、割り算を 1 つずつ正しくチェックするため機能しますが、_n_ が大きい場合は失敗します。 包含-排他アプローチが機能するのは、共主性により、製品ごとに倍数をカウントすることで、二重にカウントすることなく重複が正確に把握されることが保証されるためです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * k) | お(1) | 遅すぎる |
 | 包含-除外 | O(2^k) (積 ≤ n によって枝刈り) | O(k) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 整数 _n_ と _k_ を読み取り、次にインジケーターのリスト _a_ を読み取ります。 
2. 変数を初期化する`count_divisible`0まで; 少なくとも 1 つのインジケーターで割り切れる数値の合計数が保存されます。 
3. インジケーターの空ではないすべてのサブセットを繰り返します。 1 ～ 2^k - 1 のビットマスクでサブセットを表します。 
4. 各サブセットについて、その要素の積を計算します。 積が _n_ を超える場合はサブセットをスキップします。これは、数値 ≤ _n_ がそれで割り切れないためです。 
5. サブセットの寄与を決定する`count_divisible`。 サブセットのサイズが奇数の場合は、floor(n / product) を追加します。 偶数の場合は、floor(n / product) を減算します。 これが包含排除式です。 
6. すべてのサブセットを処理すると、答えは次のようになります。`n - count_divisible`、どの指標でも割り切れない数値を表します。 

正確さを保証する不変条件は、包含排他原則が少なくとも 1 つの要素で割り切れる数を正しくカウントし、サブセットの基数が奇数の場合は加算し、偶数の場合は減算することです。 共素性により、積が最小公倍数に正確に対応することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from itertools import combinations
from math import prod

def main():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    
    count_divisible = 0
    for mask in range(1, 1 << k):
        subset = []
        for i in range(k):
            if mask & (1 << i):
                subset.append(a[i])
        p = 1
        for x in subset:
            if p > n // x:
                p = n + 1
                break
            p *= x
        if p > n:
            continue
        if len(subset) % 2 == 1:
            count_divisible += n // p
        else:
            count_divisible -= n // p
    print(n - count_divisible)

if __name__ == "__main__":
    main()
```このソリューションは、整数オーバーフローをチェックすることによって慎重に処理します。`p > n // x`掛ける前に。 これにより、積が 10^13 を超えることがなくなります。 ビットマスクを使用すると、サブセットを効率的に生成でき、奇数/偶数チェックにより包含/除外記号が実装されます。 引き算`n - count_divisible`最後に、すべての指標から安全な数値を正確に示します。

## 特殊なケース

 _n_ がすべての指標より小さい場合、たとえば`n=3`とインジケーター`[5,7]`の場合、包含/除外アルゴリズムは、product > n のサブセットを正しくスキップします。 各部分集合積は n を超えるため、`count_divisible`は 0 のままで、答えは 3 になります。 これは、倍数が存在しない場合にアルゴリズムが誤って数値を減算しないことを示しています。 

インジケーターが 1 の場合、すべての数値は割り切れるため、アルゴリズムは 1 を含むすべてのサブセットが寄与していることを正確に識別します。`count_divisible`となり、残りの番号はゼロになります。 小切手`p > n // x`n=10^13 やインジケーター 1000 など、小さいインジケーターで大きな n を処理する場合のオーバーフローを防ぎます。
