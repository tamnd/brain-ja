 ## 解決策
 ## 問題の理解

 まずは 1 つのレジスタから始めます。`eax`、不明な値が含まれています`x`。 1 つおきのレジスタには次の内容が含まれます`0`。 目標は生産することです`n * x`任意のレジスタで可能な最小数を使用して`lea`説明書。 

命令セットは驚くほど限られていますが、驚くほど強力でもあります。 シングル`lea`形状の表現を形成できる```
y
y + z
k * y
y + k * z
```どこ`k`の 1 つです`1, 2, 4, 8`。 

すべてのレジスタには常に元の値の倍数が格納されるため、`x`、問題全体が係数の算術になります。 レジスターに現在次の内容が含まれている場合`a * x`、その後、1 回の操作で作成できます```
(a + b) * x
(a + k * b) * x
k * a * x
```のために`k ∈ {1,2,4,8}`。 

入力は単一の整数です`n`、 と`1 ≤ n ≤ 255`。 出力は、単に最小限の命令数ではなく、最適なプログラムでなければなりません。 つまり、最短距離の計算と演算の再構築の両方が必要になります。 

バウンド`n ≤ 255`問題の性質を完全に変えます。 私たちは、漸近的な公式や貪欲なパターンを探しているわけではありません。 到達可能な状態空間全体は小さいです。 考えられるすべてのレジスタ構成を明示的にモデル化したとしても、最適なプログラムは短く、係数が小さな範囲を超える必要がないため、探索空間は管理可能なままです。 

微妙な部分は、中間値が`n`まだ役立つかもしれません。 までの価値を構築するだけの貪欲な戦略`n`最適な答えを見逃す可能性があります。 たとえば、到達する`15`を通して```
5 -> 20 -> 15
```減算が存在しないため不可能ですが、一部のターゲットを効率的に達成するには、バイナリ表現からは明らかではない補助係数を構築する必要があることがよくあります。 

もう 1 つの簡単な間違いは、1 つの作業レジスタのみが重要であると想定することです。 のサンプル`41`すでにこれを反証しています:```
5*x in ebx
41*x in ecx using eax and ebx
```いくつかの中間係数を同時に有効に保つことが、ショート プログラムが存在する理由です。 

最小のエッジケースは次のとおりです。`n = 1`。 答えは指示ゼロです。`eax`すでに含まれています`1 * x`。 常に少なくとも 1 つの命令を発行する不注意な実装は、すぐに失敗します。 

もう 1 つの危険なエッジ ケースは、レジスタの再利用です。 指示```
lea eax, [eax + 8*eax]
```有効であり、計算されます`9 * eax_old`。 概念的には、代入が行われる前に古い値を読み取る必要があります。 シミュレーション中にレジスタの変更が早すぎる実装では、再構築が破損する可能性があります。 

## アプローチ

 最も直接的な総当り攻撃のアイデアは、考えられる長さのプログラムをすべて生成することです。`1`、その後、長さのすべてのプログラム`2`、など、結果が得られるまで続きます。`n * x`。 

各命令は、デスティネーション レジスタ、1 つまたは 2 つのソース レジスタ、およびオプションで乗算器を選択します。`{2,4,8}`。 レジスタが少数しかない場合でも、分岐要素は膨大になります。 深さ 6 の検索では、すでに何百万もの可能性が探求されています。 多くの異なる命令シーケンスが同じ係数構成につながるため、ほとんどの作業が重複します。 

ブルートフォースは、問題の実際の構造を明らかにするため、概念的には依然として有用です。 すべてのレジスタには常に元の値の整数倍が格納されます。 正確な実行時の値はまったく問題ではありません。 係数だけが重要です。 

この観察により、タスクは整数状態に関する最短経路問題に変わります。 

現在、すでに構成可能な係数がいくつかわかっていると仮定します。 どのペアからも`(a, b)`私たちは作成するかもしれません```
a + b
a + 2b
a + 4b
a + 8b
2a
4a
8a
```ワンステップで。 

これは加算連鎖の問題に似ていますが、小さい乗数が許可される点が異なります。 以来`n ≤ 255`、到達可能な係数に対して幅優先検索を実行できます。 

重要な洞察は、実際には 26 レジスタすべてをモデル化する必要はないということです。 最適なプログラムはどれも、計算された係数の DAG として表すことができます。 すべての命令は、古い係数から 1 つの新しい係数を作成します。 ここでは依存関係グラフのみに注目します。 

探索深度が小さいため、ある安全な制限までの係数にわたる BFS が機能します。 新たに発見された係数ごとに、それがどのように生成されたかを覚えています。 到着したら`n`、命令シーケンスを逆方向に再構築します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 網羅的なプログラムの列挙 | 指数 | 指数 | 遅すぎる |
 | 構成可能な係数の BFS | O(平方メートル) | お(お) | 承認済み |

 ここ`M`BFS 中に使用される最大係数限界です。 

## アルゴリズムのチュートリアル

 1. すべてのレジスタ値を、元の未知の数に乗算する係数として扱います。`x`。 

最初は係数のみ`1`なぜなら存在する`eax = x`。 
2. 係数から開始して幅優先検索を実行します。`1`。 

BFS は適切です。`lea`命令には 1 回の操作が必要です。 
3. 現在知られているすべての係数について`a`、すでに発見されているすべての係数と組み合わせます`b`。 

から`(a, b)`生成する：```
a + b
a + 2b
a + 4b
a + 8b
```また、自然に純粋なスケーリングも得られます。`a = 0`は乗算と同等ですが、明示的なゼロを格納する必要はありません。 
4. 新しい係数が追加されるたびに`c`初めて発見された場合は、次のように記録します。```
parent coefficients
multiplier used
BFS depth
```BFS は命令の数を増やしながら状態を探索するため、最初の検出が最適です。 
5. 係数まで継続`n`に達します。 
6. 依存関係グラフを逆方向に再構築します。`n`。 

各係数は、その係数を生成した以前の係数を記憶しています。 
7. トポロジ順に命令を発行します。 

構築されたすべての係数にレジスタを割り当てます。 最適な深さがあるため、`n ≤ 255`は非常に小さいため、同時に有効な係数の数は 26 個のレジスタ内に簡単に収まります。 

### なぜ効果があるのか

 すべての命令は、既存の係数から 1 つの新しい係数を正確に作成します。 BFS は、到達可能なすべての係数を調査します。`0`命令、次に到達可能なすべての係数`1`指導など。 ときの係数`n`が最初に発見されたとき、それより短い配列は存在できません。 

保存されている各遷移が 1 つの有効な遷移に正確に対応しているため、再構成は正確です。`lea`命令。 依存関係グラフを BFS 順序で再生すると、同じ数の操作を使用してターゲット係数が再現されます。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

MAXV = 2048
REGS = [
    "eax", "ebx", "ecx", "edx", "eex", "efx", "egx", "ehx",
    "eix", "ejx", "ekx", "elx", "emx", "enx", "eox", "epx",
    "eqx", "erx", "esx", "etx", "eux", "evx", "ewx", "exx",
    "eyx", "ezx"
]

def solve():
    n = int(input())

    if n == 1:
        print(0)
        return

    dist = [-1] * MAXV
    parent = [None] * MAXV

    q = deque([1])
    dist[1] = 0

    discovered = [1]

    while q:
        a = q.popleft()

        current = discovered[:]

        for b in current:
            for k in (1, 2, 4, 8):
                c = a + k * b

                if c >= MAXV:
                    continue

                if dist[c] != -1:
                    continue

                dist[c] = dist[a] + 1
                parent[c] = (a, b, k)

                discovered.append(c)
                q.append(c)

                if c == n:
                    q.clear()
                    break
            else:
                continue
            break

    need = set()

    def collect(v):
        if v == 1 or v in need:
            return
        need.add(v)
        a, b, k = parent[v]
        collect(a)
        collect(b)

    collect(n)

    order = []

    visited = set()

    def topo(v):
        if v == 1 or v in visited:
            return
        visited.add(v)

        a, b, k = parent[v]

        topo(a)
        topo(b)

        order.append(v)

    topo(n)

    reg_of = {1: "eax"}
    free_regs = deque(REGS[1:])

    instructions = []

    for v in order:
        a, b, k = parent[v]

        ra = reg_of[a]
        rb = reg_of[b]

        rv = free_regs.popleft()
        reg_of[v] = rv

        if a == b and k == 1:
            expr = f"[{ra} + {rb}]"
        elif k == 1:
            expr = f"[{ra} + {rb}]"
        else:
            expr = f"[{ra} + {k}*{rb}]"

        instructions.append(f"lea {rv}, {expr}")

    print(len(instructions))
    print("\n".join(instructions))

solve()
```BFS は、すべての係数を作成するために必要な命令の最小数を計算します。 配列`parent`最初に各値を生成した正確な操作を保存します。 

検索限界`2048`意図的により大きい`255`。 ターゲットを超える中間係数が最適な構成で出現する可能性があるため、検索を次のように制限します。`≤ n`安全ではありません。 

再構築フェーズには 2 つの DFS トラバーサルがあります。 最初の項目は、最終的な答えに必要なすべての係数をマークします。 2 番目の方法では、依存関係が常にそれを使用する値の前に計算されるように、トポロジー的な順序が生成されます。 

依存関係グラフが小さいため、レジスタの割り当ては簡単です。 構築された各係数に 1 つのレジスタを永続的に割り当てます。 必要な係数の数が、使用可能な 26 レジスタに近づくことはありません。 

微妙な点の 1 つは命令のフォーマットです。 このステートメントでは、特定の構文形式のみが許可されます。 私たちは常にどちらかを発します```
[y + z]
```または```
[y + k*z]
```どちらも有効です。

 ## 特殊なケース

 ### エッジケース 1:`n = 1`入力：```
1
```初期状態にはすでに係数が含まれているため、アルゴリズムは直ちにゼロ命令を返します。`1`。 

BFS の拡張は必要ありません。 これにより、次のような無駄な操作を生成するというよくある間違いを防ぐことができます。```
lea ebx, [eax]
```それは最適ではありません。 

### エッジケース 2: 同じレジスタの再利用

 入力:```
15
```工事：```
3 = 1 + 2*1
15 = 3 + 4*3
```発行された命令は次のようになります。```
lea ecx, [ebx + 4*ebx]
```両方の発生`ebx`代入前の古い値を参照します。 再構築では可変の実行時状態ではなく、シンボリック係数の依存関係が保存されるため、アルゴリズムはこれを自然に処理します。 

### エッジケース 3: 明らかなバイナリ チャンクより大きい中間係数

 入力:```
255
```単純な 2 値の 2 倍化戦略が常に最適であるとは限りません。 BFS は、異常な中間構造を含む、到達可能なすべての係数を均一に探索します。 検索空間にはそれを超える値が含まれるため、`255`、最適なパスが誤って切り詰められることはありません。
