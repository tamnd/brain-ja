 ## 解決策
 ## 問題の理解

 ある数値 n のちょうど 2 倍のサイズの整数のマルチセットが与えられます。 タスクは、並べ替えられた配列を長さ n の 2 つの連続する半分に分割した場合に、左半分の合計が右半分の合計と異なるように、これらの値を新しい順序に並べ替えることです。 そのような再配置が存在しない場合は、失敗を報告する必要があります。 

重要な点は、この不等条件を超えて最適化することは求められていないということです。 自由に並べ替えることができるため、解の構造は、順序付けを通じて 2 つの半和にどのような影響を与えることができるかに完全に依存します。 

制約 n ≤ 1000 は、配列サイズが最大 2000 であることを意味します。これは十分に小さいため、ソートや線形スキャンは簡単で、O(n²) 個の構築でも合格します。 重要な部分は、計算効率ではなく、合計の構造についての推論です。 

すべての要素が同一である場合、微妙なエッジケースが発生します。 たとえば、配列が [5, 5, 5, 5] の場合、両方の半分に同じマルチセットが含まれるため、2 つの半分に分割すると等しい合計が生成されます。 この場合、解決策は存在しません。 

[1, 1, 1, 2] など、配列の変動が非常に小さい場合、別のエッジ ケースが発生します。 素朴な直観は、何らかの賢いインターリーブによって合計を等化できるかもしれないと示唆するかもしれませんが、実際には、すべての値が同一でない限り、常に等価性を破ることができます。 

最も難しいのは、対称性が順列に関係なく平等を強制する場合を認識することです。 

## アプローチ

 ブルートフォース手法では、配列を並べ替えて、有効な分割が存在するかどうかを確認しようとします。 (2n) あるよ！ 1 つの順列を評価するだけでも O(n) となるため、これは完全に不可能です。 

たとえサンプリング順列に限定したとしても、依然として構造が欠けています。 実際の所見は、すべての順列が失敗する唯一の方法は、すべての要素が同一である場合であるということです。 この場合、各半分の和は同じ n · x になるため、等価になることは避けられません。 

少なくとも 2 つの異なる値が存在する場合、異なる合計を持つ 2 つの半分を意図的に構築できます。 最も簡単な方法は、配列をソートすることです。 並べ替えると、最小値が先頭に集中し、最大値が最後に集中します。 n 個の要素の後に分割すると、後半には前半の要素よりも厳密に大きい要素が少なくとも 1 つ含まれることが保証され、分布に応じてその逆も可能です。 これにより、合計額に深刻な不均衡が生じます。 

より具体的には、ソートにより、半分間の分離が最大限に確保されます。 前半はより小さい値に偏り、2 番目の半分はより大きな値に偏り、合計のギャップが生じます。 

したがって、問題は、均一性の単純なチェックとその後のソートに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース順列 | O((2n)!) | O(n) | 遅すぎる |
 | 並べ替え + 構築 | O(n log n) | O(1) おまけ | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を読み取り、すべての要素が等しいかどうかを確認します。 それらが一致する場合、すべての順列が同一の半和を生成し、不等号が不可能になるため、-1 を出力します。 
2. 配列を降順でない順に並べ替えます。 これにより、小さい値が左側にグループ化され、大きい値が右側にグループ化される構造が作成されます。 
3. ソートされた配列を直接出力します。 サイズ n を 2 つの半分に分割すると、重みの低い半分と重みの高い半分が比較されます。 
4. 終了します。 

### なぜ効果があるのか

並べ替えると、前半のすべての要素が後半のすべての要素以下となる単調な配置が作成されます。 配列が一様でない場合には少なくとも 1 つの厳密な不等式が存在するため、後半には厳密により大きな合計寄与が含まれます。 これにより、前半の要素をより大きな要素に置き換えると、後半の合計が最初の要素に比べて厳密に増加するため、2 つの半分の合計が一致しないことが保証されます。 

正確かどうかは、すべての要素が等しいという事実が、半分の間で考えられる厳密な順序付けをすべて削除する唯一の構成であるという事実にかかっています。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    if len(set(a)) == 1:
        print(-1)
        return
    
    a.sort()
    print(*a)

if __name__ == "__main__":
    solve()
```この解決策は、まず n 個と 2n 個の要素を読み取ります。 セットを使用した均一性チェックは、唯一不可能なケースを直接捕捉するため、非常に重要です。 これがなければ、並べ替えだけでも有効な順列が出力されますが、すべてが等しいエッジ ケースでは失敗します。 

並べ替えは、小さい値と大きい値を強制的に分離する建設的な手順です。 この問題では明示的に半分を形成する必要はなく、そのような分割の和が等しくないことを保証するだけなので、ソート後に配列をそのまま出力するだけで十分です。 

よくある間違いは、要素をインターリーブしたり、交互のパターンを構築しようとしたりすることです。 これらは、ソートが既に提供しているものを超えて保証を向上させるものではないため、不要です。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from contextlib import redirect_stdout
    out = io.StringIO()
    with redirect_stdout(out):
        solve()
    return out.getvalue().strip()

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    if len(set(a)) == 1:
        print(-1)
        return
    a.sort()
    print(*a)

# reverse order

```| テスト入力 | 期待される出力 | 検証内容 |

 ## 特殊なケース

 最も重要なエッジケースは、すべての要素が同一である場合です。 次のような入力の場合:```
3
7 7 7 7 7 7
```アルゴリズムが検出するのは、`len(set(a)) == 1`そしてすぐに -1 を出力します。 このチェックをスキップして配列を出力すると、両方の半分の合計は 3 × 7 = 21 となり、条件に違反します。 

次のようなほぼ均一なケースの場合:```
3
1 1 1 1 1 2
```セットのサイズが 1 より大きいため、並べ替えに進みます。```
1 1 1 1 1 2
```半和は次のようになります。 

前半 = 3、後半 = 4 なので、条件が成り立ちます。 これは、均一性からの逸脱が 1 つでもあれば、並べ替え後の有効な分割を保証するには十分であることを示しています。 

この動作は、完全に対称な場合にのみ構築が失敗し、それ以外の場合は成功することを確認します。
