 ## 解決策
 ## 問題の理解

 それぞれが 1 から 2 までの範囲にある整数のシーケンスを構築するように求められます。$2^n - 1$、隣接するセグメントには非常に具体的な制限があります。 連続するすべての部分配列について、その要素のビット単位の XOR を計算します。これらの XOR 値はいずれも 0 または指定された禁止値のいずれであってもなりません。$x$。 この制限を満たすすべてのシーケンスの中で、可能な限り最大の長さを持つシーケンスが必要です。 

問題を再構成する有効な方法は、プレフィックス XOR の観点から考えることです。 定義すると$p_0 = 0$そして$p_i = a_1 \oplus a_2 \oplus \dots \oplus a_i$、次に部分配列の XOR$[l, r]$は$p_r \oplus p_{l-1}$。 部分配列の XOR が 0 でないという条件、または$x$は、プレフィックス XOR セットにおける禁止されたペアごとの違いに関する条件になります。$p_i = p_j$(XOR 0 を避けるため)、決してそうしてはなりません。$p_i = p_j \oplus x$(XORを避けるため$x$）。 

したがって、構築上の問題は次のようになります。異なるプレフィックス XOR 状態のシーケンスを構築し、異なる状態のペアを回避します。$x$。 

制約$n \le 18$すべての値が最大でも同じサイズの世界に存在することを意味します$2^{18}$、およそ26万の可能性があります。 これは十分に小さいため、すべての状態に対するビットマスクベースのグラフ推論が可能です。 難しいのは計算の制限ではなく、禁止された XOR 関係が現れないように状態を構築することです。 

素朴な試みは、0 から開始して、前のプレフィックスとの禁止されたサブ配列 XOR をすぐに作成しない未使用の値を選択することで、シーケンスを貪欲に拡張することです。 この制約は、最近の要素に対してローカルではなく、プレフィックスのすべてのペアにわたってグローバルであるため、これは失敗します。 初期の選択が 1 つ間違っていると、現時点では安全であるように見えても、将来のほぼすべての拡張機能がブロックされる可能性があります。 

値を独立して処理しようとすると、別の障害モードが発生します。 プレフィックス XOR 関係をチェックせずに大きな整数セットを選択すると、制約が基本的に個々の要素ではなく、ハイパーキューブ上の XOR グラフの構造に関するものであることが無視されます。 

## アプローチ

 重要な再定式化は、完全にプレフィックス XOR 空間で作業することです。 一連の個別の値を構築します$p_i$から始まる$p_0 = 0$、選択された 2 つのプレフィックスが満たさないようにする$p_i \oplus p_j = x$。 このようなシーケンスを取得したら、次のように設定して実際の配列を復元します。$a_i = p_i \oplus p_{i-1}$。 

これにより、問題は、頂点がすべて同じであるグラフ内の最大長のパスを選択することに変わります。$2^n$ビットマスク。エッジは、選択されたセット全体で禁止されている XOR 関係に違反しない場合にのみ許可されます。 ただし、エッジを明示的に構築する代わりに、より強力な構造が観察されます: 各値$v$それ自体とのみ互換性がありません$v \oplus x$。 これは、頂点が自然に互いに素なペアを形成することを意味します$(v, v \oplus x)$いつ$x \ne 0$。 

各ペア内では、最大 1 つの要素を取ることができます。そうでない場合は、次の禁止された XOR を直ちに作成します。$x$。 残る唯一の問題は、構築された差異が有効なままとなるように、プレフィックスの順序付けの一貫性を確保することです。 

これは、0 から 0 までのすべての数値に対する貪欲な構築を示唆しています。$2^n - 1$。 値を反復処理し、数値もその XOR パートナーも使用されていない場合は数値を選択します。 これにより、禁止された各ペアから最大 1 つを選択することが保証されます。 次に、これらをプレフィックス状態のシーケンスとして使用することで、プレフィックス XOR の違いが有効なままになるように調整します。 

微妙な点は、異なる点が 2 つも存在しない代表のセットを選択した場合、0 から始まるということです。$x$の場合、誘導された配列は自動的に条件を満たします。これは、サブ配列の XOR が、選択された 2 つの異なるプレフィックス状態の XOR に正確に対応し、そのようなペアが 0 または 0 に等しくなり得ないためです。$x$。 

したがって、この構築は、次のグラフを接続する最大の独立集合を構築することに帰着します。$v$そして$v \oplus x$、これは貪欲なペアリングによって実現されます。

 ## アルゴリズムのチュートリアル

 1. 訪問した州の配列をすべての値に対して初期化します。$[0, 2^n)$。 その目的は、禁止された XOR ペアの両方の要素を決して選択しないようにすることです。 
2. すべての整数を反復処理します$v$0から$2^n - 1$。 もし$v$はまだ使用されていないため、構築に含めようとします。 この順序は任意ですが固定されており、決定性が保証されます。 
3. 値を選択するとき$v$、両方をマークします$v$そして$v \oplus x$使用済みとして。 これにより、禁止された XOR の差を生み出す 2 つの状態を選択することができなくなります。$x$。 
4.追記します$v$選択されたプレフィックス XOR 状態のリストに変換されます。 このリストが表すのは、$p_0, p_1, \dots$修正後$p_0 = 0$。 
5. プレフィックス XOR シーケンスを構築した後、隣接する XOR の差分を取得して、それを最終的な配列に変換します。$a_i = p_i \oplus p_{i-1}$。 

なぜそれが機能するかは、XOR の違いの構造に関係しています。 すべてのサブ配列の XOR は、2 つのプレフィックス状態の XOR と等しくなります。 同じ禁止されたペアから 2 つの状態を選択することは決してないため、$(v, v \oplus x)$、選択したプレフィックス間の違いは等しくありません$x$。 区別性により、サブ配列の XOR が 0 にならないことが保証されます。この不変条件は、順序とは関係なくグローバルに維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, x = map(int, input().split())
    N = 1 << n

    used = [False] * N
    p = []

    for v in range(N):
        if not used[v]:
            p.append(v)
            used[v] = True
            if v ^ x < N:
                used[v ^ x] = True

    # build array from prefix xor
    a = []
    for i in range(1, len(p)):
        a.append(p[i] ^ p[i - 1])

    print(len(a))
    if a:
        print(*a)

if __name__ == "__main__":
    solve()
```実装はペアリングのアイデアに直接準拠しています。 配列`used`XOR が禁止されたペアの両方のエンドポイントを選択しないようにします。 リスト`p`プレフィックス XOR 状態を保存します。 変換ステップ`p[i] ^ p[i-1]`実際の配列要素を再構築します。 

微妙な点は扱い方$v \oplus x$安全: 原則として境界を超えたとしても、XOR はビット幅を超えて増加させないため、常に範囲内に留まります。$n$。

 ## 特殊なケース

 エッジケースの 1 つは次の場合に発生します。$x = 0$。 この制約は、サブ配列の XOR が 0 に等しいことを禁止します。空でない配列ではこれは不可能です。これは、すべての単一要素サブ配列がそれ自体と等しい XOR を持ち、長い構造ではプレフィックスの衝突が繰り返されることが避けられないためです。 アルゴリズムは、各値をそれ自体とペアにすることでこれを処理し、事実上、値ごとに 1 つの代表のみを許可し、構築を非常に小さな安全なセットに崩壊させます。 

もう 1 つのエッジケースは次のような場合です$x$大きいですが、まだ範囲内です。 たとえ$v \oplus x$を超える$2^n - 1$、固定ビット幅の XOR によりこのようなことは決して起こらないため、ペアリングは追加の境界チェックなしで有効なままになります。 

最後のエッジケースは、貪欲なスキャン順序によって最適ではないペアリングが生成されるように見える場合です。 各競合は 2 要素の XOR ペアに対して厳密にローカルであるため、順序付けでは各ペアから 1 つだけが選択されるため、結果のサイズは不変となり、実行全体で一貫性が確保されます。
