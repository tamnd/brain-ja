 ## 解決策
 ## 問題の理解

 2 から n までのすべての整数にラベルを割り当てるように求められます。 これらのラベルは正の整数であり、強力な交互作用規則を満たす必要があります。つまり、2 つの数値が 1 より大きい公約数を共有しない場合、つまりそれらが互いに素である場合、割り当てられたラベルは異なる必要があります。 

これを言い換える便利な方法は、各整数 i をグラフ内のノードとして考えることです。gcd が 1 の場合、2 つのノードを接続します。このタスクでは、できるだけ少ない色を使用しながら、この「素グラフ」内の隣接するノードが常に異なる色を持つようにノードに色を割り当てます。 

出力は単に 2 ～ n に割り当てられた色のリストであり、すべての有効な色の中で、使用される最大の色の値を最小限に抑える必要があります。 

n ≤ 100000 という制約は、数値のすべてのペアを比較するアプローチは不可能であることを意味します。 すべてのペアにわたる二次または二次に近い構成は、時間制限を大幅に超えることになります。 線形または線形演算に近い動作が必要で、理想的にはペアごとのチェックではなく数論的構造を使用します。 

ここでの一般的な失敗モードは、貪欲な割り当てを試行することです。つまり、以前に割り当てられた互いに素な数値に基づいて、各数値に可能な限り小さい未使用の色を与えることです。 これは、以前のすべての数値に対して共値性を判断するのが遅すぎるため、また、最適化された簿記でもグローバル構造を見逃す傾向があるため、破綻します。 もう 1 つの間違いは、パリティまたは i mod k のような単純なモジュラー パターンによって色付けしようとすることです。 共素性が算術剰余クラスと一致していないため、これらは失敗します。 

隠れた構造は、共素性が素因数によって支配されるということです。 2 つの数値が素因数を共有する場合、それらが異なる必要はありません。 それらが素因数を共有していない場合は、それらは異なっている必要があります。 これは、最小の素因数または割り算構造によって数値をグループ化することを示唆しています。 

## アプローチ

 強引なアイデアは、色に一度に 1 つの番号を割り当てることです。 各 i について、以前に割り当てられたすべての番号 j をスキャンし、gcd(i, j) をチェックします。 gcd が 1 の場合、i と j が色を共有しないことが保証されます。 これは、繰り返し割り算をチェックするか、gcd を計算することで実装できます。 

このアプローチは制約を直接適用するので正しいですが、遅すぎます。 各 i について、以前のすべての値と比較すると、最悪の場合、およそ O(n^2) 個の gcd 計算が必要になります。 n = 10^5 では、これは実現可能な限界をはるかに超えています。 

重要な観察は、視点を反転することです。 互いに素数間の衝突を直接防ぐのではなく、衝突が決して起こらないグループを構築します。 重要な事実は、同じ素因数を共有するすべての数値が、その素数のみに関する共素性によって異なることを強制されることはないということです。 これは、素数自体が色の代表として機能する可能性があることを示唆しています。 

最適な構成は驚くほど単純です。各数値 i にその最小の素因数に等しい色を割り当てます。 すべての合成数はその最小の素約数の色を継承し、素数はそれ自体と等しい独自の色を取得します。 

これが機能するのは、2 つの数値が互いに素である場合、どの素因数も共有できないこと、特に同じ最小の素因数を共有できないためです。 したがって、それらは異なる色を持っている必要があります。 これにより、各素数が新しい色を導入し、すべての合成で既存の色が再利用されるため、使用される色の数も自然に最小限に抑えられます。

 ## アルゴリズムのチュートリアル

1. ふるいのようなプロセスを使用して、2 から n までのすべての整数の最小素因数 (SPF) を事前計算します。 これにより、各数字の「色」をすばやく判断できるようになります。 SPF が役立つ理由は、すべての数値の因数構造を単一の代表的な素数に圧縮するためです。 
2. サイズ n+1 の配列 spf を初期化します。ここで spf[i] には、最終的に i を除算する最小の素数が格納されます。 各数値は最初は潜在的に素数として扱われるため、すべての i に対して spf[i] = i を仮定することから始めます。 
3. 2 から n まで繰り返します。 spf[i] = i を維持する数値 i に遭遇すると、それが素数であることがわかります。 i の各倍数 j について、spf[j] がまだ設定されていない場合は、spf[j] = i を割り当てます。 これにより、すべての数値が最小の素約数を取得します。 
4. ふるいが完了したら、color[i] = spf[i] を割り当てます。 これはカラーリングを直接定義します。 
5. 2 から n までのすべての i の色を順番に出力します。 

### なぜ効果があるのか

 不変条件は、spf[i] が常に i を除算する最小の素数を格納することです。 これにより、最小の素因数を共有するすべての数値が同じ色の下にグループ化され、小さな素因数で除算するときに誤って大きな素数が割り当てられることがなくなります。 

2 つの数値 i と j が互いに素である場合、それらは素因数をまったく共有しません。 したがって、等しいということは素約数が共有されていることを意味するため、spf[i] と spf[j] は異なる必要があります。 したがって、着色制約は常に満たされます。 同時に、各素数は新しい色を 1 つだけ導入するため、不必要な分割は発生しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    spf = list(range(n + 1))

    for i in range(2, n + 1):
        if spf[i] == i:  # i is prime
            for j in range(i, n + 1, i):
                if spf[j] == j:
                    spf[j] = i

    res = []
    for i in range(2, n + 1):
        res.append(str(spf[i]))
    print(" ".join(res))

if __name__ == "__main__":
    solve()
```ふるいセクションは最小の素因数配列を構築します。 重要な詳細はコンディションです`if spf[j] == j`これにより、各数値に到達する最初の (最小の) 素数のみが割り当てられるようになります。 このガードがないと、後の素数が正しい値を上書きし、正確性が損なわれてしまいます。 

出力ループは SPF をカラーとして直接出力し、余分なマッピングや圧縮を回避します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import gcd

    n = int(inp.strip())
    spf = list(range(n + 1))
    for i in range(2, n + 1):
        if spf[i] == i:
            for j in range(i, n + 1, i):

## 特殊なケース

 n = 2 の場合、ふるいは spf[2] = 2 を割り当て、ただちに単一の値を出力します。 アルゴリズムは i = 2 を超えて内側のマーキング ループに入ることはなく、チェックするペアがないため、正確性は自明に保たれます。 

n = 3 の場合、素数 2 と 3 は異なる色を受け取ります。 2 と 3 は互いに素であるため、それらは異なるはずであり、アルゴリズムはまさにそれを生成します。 

n = 4 の場合、値 4 は素数ではなく、その SPF は 2 から取得されます。これにより、2 と 4 の間で繰り返されるカラー パターンが作成されますが、gcd(2,4) ≠ 1 であるため安全です。アルゴリズムは自然に新しいカラーを 4 に割り当てることを回避し、最小性を確認します。
