 ## 問題の理解

 このタスクは、小さなハッシュ テーブルへの数値の挿入をシミュレートします。 テーブルには固定数のバケットがあり、`x`バケットに割り当てられます`x mod p`。 各バケットには数値を 1 つだけ保存できます。 番号は指定された順序で 1 つずつ到着します。挿入ですでに別の番号が含まれているバケットを使用しようとする最初の位置を見つける必要があります。 すべての挿入が空のバケットに入る場合、答えは次のようになります。`-1`。 

入力はバケットの数を示します`p`、挿入する値の数`n`、次に値のシーケンス。 出力は、最初の競合する挿入の 1 から始まるインデックスです。 

制約は小さく、両方とも`p`そして`n`これは、単純なシミュレーションでも十分に高速であることを意味します。 挿入の数はわずか数百であるため、線形または二次動作のアルゴリズムは両方とも適合します。 テーブル全体が小さいため、高度なハッシュ構造は必要ありません。 

主なエッジ ケースは、挿入の順序と、見た目は異なっていても同じバケットにマップされる値に由来します。 たとえば、次のようになります。```
5 3
1
6
11
```正しい出力は次のとおりです。```
2
```なぜなら`1 mod 5`、`6 mod 5`、 そして`11 mod 5`すべて等しい`1`。 2 番目の挿入はすでに競合しています。 バケットの位置の代わりに元の数値を保存する不注意な実装では、3 つの値がすべて異なると誤って認識されてしまいます。 

別のケースは、すべてのバケットが競合せずに満たされている場合です。```
4 4
0
1
2
3
```正しい出力は次のとおりです。```
-1
```最後の挿入が失敗するはずだと仮定する解決策は間違っています。 すべての値が一意のバケットに挿入された場合、完全なテーブルは依然として有効です。 

最後の境界ケースは、同じ値が 2 回出現する場合です。```
10 2
123456789
123456789
```正しい出力は次のとおりです。```
2
```2 番目の値は、最初の値とまったく同じバケットにマップされます。 異なる値の間でも衝突が発生する可能性があるため、元の値が繰り返されているかどうかのみを比較する必要はありません。 

## アプローチ

 ブルートフォースアプローチは、説明どおりにハッシュテーブルを正確にシミュレートすることです。 すべてのバケットの現在の内容を維持します。 受信番号ごとに、剰余演算を使用してバケット インデックスを計算し、そのバケットがすでに占有されているかどうかを確認します。 空の場合は、使用済みとしてマークして続行します。 占有されている場合は、現在の位置が答えになります。 

この問題では実際の挿入順序の最初の競合が求められており、シミュレーションはその順序に直接従うため、この方法は正しいです。 最悪の場合の動作`n`挿入と挿入ごとに 1 つの定数時間チェックがあるため、直接実装した場合でも、必要な操作は約 300 のみです。 

重要な洞察は、ハッシュ テーブル自体が重要な唯一の状態であるということです。 値がバケット インデックスに変換されると、元の数値は今後の決定に影響を与えなくなります。 数値を保存する必要はまったくなく、各バケットがすでに要素を受け取ったかどうかだけを保存する必要があります。 

ここでは、総当たりシミュレーションと最適解は事実上同じ考え方です。 最適化では、状態がサイズの単純なブール配列で表現できることが認識されます。`p`。

 ## アルゴリズムのチュートリアル

 1. ハッシュ テーブルのバケットを表す配列を作成します。 各位置には、そのバケットがすでに使用されているかどうかが格納されます。 
2. 各番号を表示順に読みます。 バケット インデックスを次のように計算します。`x mod p`。 
3. 対応するバケットを確認します。 すでに占有されている場合は、最初の競合であるため、現在の挿入位置を出力します。 
4. バケットが空の場合は、使用中としてマークを付け、次の番号の処理を続行します。 
5. 矛盾が見つからずにすべての数値が処理された場合、出力`-1`。 

これが機能する理由は、今後の挿入はすべて、どのバケットが占有されているかにのみ依存し、占有されているバケットを作成した値には依存しないためです。 ハッシュ テーブルの動作を再現するには、この情報を正確に保持するだけで十分です。 

なぜ機能するのか: 最初の処理後`i`値を指定すると、バケット配列は実際のハッシュ テーブルと完全に一致します。`i`挿入。 次の値については、アルゴリズムは実際の挿入で使用されるのと同じバケットをチェックします。 占有されている場合、実際のプロセスとアルゴリズムの両方がこのステップで競合を検出します。 空の場合は、両方とも満たされているとしてマークを付けて続行します。 不変式は挿入のたびに維持されるため、最初に報告された競合は常に正しいものになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    p, n = map(int, input().split())
    used = [False] * p

    for i in range(1, n + 1):
        x = int(input())
        bucket = x % p

        if used[bucket]:
            print(i)
            return

        used[bucket] = True

    print(-1)

if __name__ == "__main__":
    solve()
```配列`used`ハッシュテーブルバケットを表します。 そのサイズはまさに`p`したがって、考えられるすべてのバケット インデックスには対応する位置があります。 

ループは次から始まります`1`なぜなら、答えはゼロから始まる配列インデックスではなく、挿入番号に基づいているからです。 コードは、バケットを占有済みとしてマークする前に、それがすでに使用されているかどうかを確認します。 最初に値を変更すると競合が隠れてしまうため、この順序は重要です。 

Python の整数は大きな入力値を直接処理するため、オーバーフローを特別に処理する必要はありません。 モジュロ演算は、すべての値を直ちに有効なバケット インデックスに換算します。`0`そして`p - 1`。

 ## テストケース```python
import sys

def solution(inp: str) -> str:
    data = inp.strip().split()
    if not data:
        return ""

    p = int(data[0])
    n = int(data[1])
    used = [False] * p

    index = 2
    for i in range(1, n + 1):
        x = int(data[index])
        index += 1
        bucket = x % p
        if used[bucket]:
            return str(i)
        used[bucket] = True

    return "-1"
