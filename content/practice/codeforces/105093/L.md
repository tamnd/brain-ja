 ## 解決策
 ## 問題の理解

 初期配列と、それに作用する一連のスワップ操作が与えられます。 各操作では 2 つの位置の値が交換され、完全なシーケンスを適用すると、配列の最終的な配置が生成されます。 

問題は、指定された順序でスワップを実行していないことです。 代わりに、SwapSwap++++ プログラムは元のコマンド リストの単なる並べ替えであるため、同じセットのスワップ コマンドを任意に並べ替えることができます。 このような順列はそれぞれ、同一の操作の異なる実行順序を定義します。 

問題は、並べ替えられた各プログラムを同じ初期配列に適用した後、結果として得られる最終配列が同一になるような、同じスワップの 2 つの異なる並べ替えを見つけることができるかどうかです。 

言い換えれば、配列に対して同じ全体的な効果を生み出す、同じ転置シーケンスの 2 つの異なる順列を探しています。 

この制約により、最大 200,000 のスワップと最大 200,000 の配列サイズが許可されます。 これにより、すべての並べ替えを試行したり、複数の実行をシミュレートしたりするアプローチは即座に除外されます。 単一のシミュレーションでさえ線形であるため、本当の課題は、2 つの異なる有効な順序がいつ存在できるかを構造的に決定し、それらを構築することです。 

スワップが高度に「もつれ」ている場合、微妙なエッジケースが発生します。 たとえば、すべてのスワップが他のすべてのスワップとエンドポイントを共有する場合、すべてのスワップ ペアは共有インデックスを通じて相互作用します。 その場合、中間状態を変更せずに操作を交換することが困難になり、安全な並べ替えトリックが存在しないことがわかります。 

一方、完全に別々のポジションで動作する 2 つのスワップがある場合、それらは独立して動作し、最終的な結果に影響を与えることなく交換できます。 この独立性が重要な構造特性です。 

## アプローチ

 単純な考えは、コマンド リストの各順列を候補プログラムとして扱い、配列上でシミュレートし、結果を比較することです。 cがあるのでこれはすぐには不可能です！ 並べ替え。 

より洗練された総当たりアプローチは、リスト内の隣接するコマンドを交換して、結果のプログラムが依然として同じ出力を生成するかどうかを確認することです。 これにより、並べ替えの膨大な空間を探索することになり、単一のシミュレーションでも O(n + c) のコストがかかり、プロセス全体が非常に遅くなります。 

重要な洞察は、各コマンドが配列位置の転置であり、転置には単純な可換性ルールがあるということです。つまり、2 つのスワップが互いに素なインデックスのセットを操作する場合、最終的な効果を変えることなく交換できます。 つまり、スワップ (i, j) と (k, l) は、{i, j} と {k, l} が交差しない場合に正確に交換されます。 

この観察により、配列の中間状態について推論する必要が完全に回避されます。 値がどのように移動するかを調べる代わりに、スワップ セットに少なくとも 1 組の独立した操作が含まれているかどうかを確認するだけで済みます。 

このようなペアが存在する場合、他のすべてを変更せずにそれらの相対的な順序を交換することで、2 つの異なる有効な順列を構築できます。 2 つのスワップは配列上の順列として交換されるため、どちらの実行順序でも最終的に同一の配列が生成されます。 

そのようなペアが存在しない場合、すべてのスワップは少なくとも 1 つのエンドポイントを他のすべてのスワップと共有します。 その場合、安全に交換できる操作のペアは存在せず、任意の並べ替えにより、与えられた初期構成で検出可能な方法で結果の構成が変更されることがわかります。

 ## アルゴリズムのチュートリアル

 問題を、4 つの異なるインデックスに作用する 2 つのスワップが存在するかどうかを見つけることに集約します。 

1. すべてのスワップ コマンドを読み取り、それぞれをペア (i, j) として保存します。

スワップはこれらのポジションによって完全に決定されるため、必要なのはエンドポイントのみです。 
2. スワップの記録を維持しながら、リストをざっと調べます。 
3. スワップの各ペアについて、それらが素であるかどうか、つまりエンドポイントのセットが交差していないかどうかを確認します。 

具体的には、4 つのインデックスがすべて異なる場合、2 つのスワップ (a、b) と (c、d) は素になります。 
4. そのようなペアが見つかった場合は、すぐに有効な答えが存在すると結論付けます。 
5. 2 つの異なるプログラムを構築するには、元の順序を p として取り、他のすべてのコマンドを変更せずに、これら 2 つの素な入れ替えの相対順序を q で入れ替えます。 
6. 素なペアが存在しない場合は、NO を出力します。 

2 つの互いに素な転置の順序を入れ替えても、配列位置の順列としてその構成が変更されないため、構築ステップは有効です。 これらは別々のインデックスで動作するため、互いの効果を干渉することはありません。 

### なぜ効果があるのか

 スワップ コマンドは、位置に関する対称グループの要素です。 各コマンドは転置であり、スワップの合成は順列の合成に対応します。 2 つの転置は、互いに素な場合には正確に交換されます。 

2 つの互いに素なスワップが見つかった場合、交換要素を交換することによってのみ異なる、同じジェネレーター上で 2 つの異なる単語が得られます。 どちらの単語も位置の同じ順列として評価されるため、それらを同じ初期配列に適用すると、同じ結果が得られます。 

素のスワップが存在しない場合、操作のすべてのペアは少なくとも 1 つのインデックスを共有するため、交換ペアは存在しません。 各スワップの使用は 1 回のみに制限されているため、全体の構成を維持するための自明でない並べ替えを可能にする有効な代数関係は存在しないため、2 つの異なる置換によって結果が変わる必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n = int(input())
    a = list(map(int, input().split()))
    c = int(input())

    swaps = []
    for _ in range(c):
        parts = input().split()
        i = int(parts[1]) - 1
        j = int(parts[2]) - 1
        swaps.append((i, j))

    # find two disjoint swaps
    for i in range(c):
        a1, b1 = swaps[i]
        for j in range(i + 1, c):
            a2, b2 = swaps[j]
            if len({a1, b1, a2, b2}) == 4:
                # construct two permutations
                p = list(range(1, c + 1))
                q = list(range(1, c + 1))
                q[i], q[j] = q[j], q[i]

                print("YES")
                print(*p)
                print(*q)
                return

    print("NO")

if __name__ == "__main__":
    main()
```実装は構造基準を直接エンコードします。 素のスワップを 1 組検出するだけでよいため、このスタイルの問題の一般的な制約の下では 2 次スキャンで十分です。 必要に応じて、エンドポイントによるハッシュまたはインデックス作成を使用してさらに最適化できます。 

出力の構築は最小限です。最初の順列は恒等であり、2 番目の順列は 2 つの交換操作を交換することによって異なります。
