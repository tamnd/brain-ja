 ## 問題の理解

 いくつかの独立したテスト ケースが与えられています。 それぞれに結晶のコレクションがあり、各結晶には色と放射値があります。 私たちはせいぜい選択しなければなりません$m$しかし、それらを使用する前に、そのうちの 2 つを、放射が元の 2 つの合計である 1 つと繰り返し置き換えることによって、同じ色のクリスタルをいくつでも結合することができます。 結合では色は変化せず、放射線が集約されるだけです。 

すべてのマージの後、同じ色の 2 つのクリスタルが残っている場合、それは最終的なデバイスでは無効になるため、残りの各色は最大 1 つのクリスタルに寄与します。 最終スコアは、選択されたすべての個別の色の結晶の放射値の積です。 任務は、$m$オリジナルのクリスタルを、色彩の中で最適に融合させ、この製品を最大限に引き出します。 

重要な構造上の制約は次のとおりです。$n \le 15$なので、指数関数的なサブセットも実現可能です。 ただし、放射値は小さく、乗算的な動作は、構成を列挙することなく貪欲な選択が明らかに安全ではないことを示唆しています。 この小さな$n$大規模な状態空間に対して最適化を試みたり、合計に対して連続 DP を実行しようとしたりするソリューションは即座に除外されますが、サブセットの列挙やビットマスク動的プログラミングを強く招きます。 

微妙な落とし穴は、「ナップザックのサイズ」を誤解していることです。$m$” 制約。色を選択するのではなく、元のクリスタルを選択します。しかし、結合とは、ある色の複数のクリスタルを選択すると、効果的にそれらを単一のより強力なアイテムに変換することを意味します。たとえば、色 2 の 3 つのクリスタルを選択すると、放射が合計された単一のクリスタルが生成され、最終製品の 1 つの要素に正確に寄与します。

 もう 1 つの微妙なケースは、融合後の生成物が増加しない限り、ある色の結晶をより多く摂取することが必ずしも有益であるとは限らないということです。 たとえば、放射線 1 と 1 を持つ 2 つの結晶は 2 になり、他の選択された値に応じて製品が改善される場合と改善されない場合があります。 

## アプローチ

 ブルートフォースアプローチは、最大でも次のサイズの結晶のすべてのサブセットを試すことです。$m$。 各サブセットについて、色ごとにグループ化し、グループごとの放射を合計することによってマージをシミュレートします。 次に、結果として得られる色ごとの合計の積を計算します。 これはプロセスを直接モデル化しているため、これは正しいです。 サブセットの数は$2^n$、そして$n \le 15$、これは最大 32768 サブセットであり、十分小さいです。 ただし、サブセット サイズの制約を適用し、サブセットごとのグループ化を計算する必要もあります。$O(n)$これは単独でも問題ありません。 

微妙な問題は、注意しないと実際には構造が二重にカウントされることです。マージ順序は重要ではなく、色ごとの合計のみが重要です。 したがって、各サブセットは、集約された重みを使用して色のマルチセットに一意にマッピングされます。 

重要な観察は、$n$は小さいため、DP 圧縮や貪欲な戦略を賢く使う必要はありません。 サブセットを直接列挙し、色ごとの合計を計算して、製品を評価します。 「サイズのナップサック」$m$” 制約は、より大きいサブセットをスキップするだけで処理されます。$m$。 

これにより、問題はサブセットごとの線形評価によるサブセット列挙に縮小されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

## アルゴリズムのチュートリアル

 1. テスト ケースごとに、すべての結晶を読み取り、色と放射線のペアとして保存します。 
2. すべてのビットマスクを反復処理します。$0$に$2^n - 1$ここで、各ビットマスクは結晶のサブセットを表します。 これは、マージ前にどのクリスタルを取得するかの決定をエンコードします。 
3. サブセットごとに、選択されたクリスタルの数を数えます。 これを超えると$m$、ナップザック制約に違反するため、サブセットは直ちに破棄されます。 
4. 色でインデックス付けされた配列または辞書を構築し、その色の選択されたすべての結晶の放射線値を累積します。 カラー内でのマージは合計と同等であるため、これは許可されているすべてのマージをシミュレートします。 
5. ゼロ以外のすべての色の合計の積を計算します。 
6. すべての有効なサブセットにわたる最大積を追跡します。 

正確さは、サブセットが固定されるとマージが決定的であるという事実にかかっています。つまり、特定の色のすべてのクリスタルが、それらの合計に等しい単一の値に崩壊します。 結果を変える代替構成はありません。 

### なぜ効果があるのか

 有効な最終構成は、元のクリスタルのサブセットを選択し、各色内で任意に結合することに対応します。 マージによって変更されるのは、色ごとの合計放射量ではなく、色ごとのアイテム数のみです。 したがって、各サブセットは最終製品を一意に決定し、すべての実行可能なソリューションは 1 つのサブセットに正確に対応します。 すべてのサブセットを使い果たすことで、考えられるすべての結果を検査することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n, m = map(int, input().split())
        c = []
        r = []
        for _ in range(n):
            ci, ri = map(int, input().split())
            c.append(ci)
            r.append(ri)

        ans = 0

        for mask in range(1 << n):
            if mask.bit_count() > m:
                continue

            color_sum = {}
            for i in range(n):
                if mask & (1 << i):
                    color_sum[c[i]] = color_sum.get(c[i], 0) + r[i]

            prod = 1
            for val in color_sum.values():
                prod *= val

            if prod > ans:
                ans = prod

        print(ans)

if __name__ == "__main__":
    solve()
```実装はサブセット列挙戦略に直接に従います。 の`bit_count()`check は、サイズ制約を早期に適用し、無効なサブセットを削除します。 辞書`color_sum`色ごとに放射線を集約し、暗黙的に許可されたすべてのマージをモデル化します。 

積の計算では、すべての集計値が乗算され、空の色は辞書に表示されないためスキップされます。 答えはすべてのサブセットにわたって貪欲に更新されます。 

微妙な点は、個々の放射線の値は小さいですが、製品はすぐに成長する可能性があることです。 Python の任意精度の整数はオーバーフローの問題を防ぐため、追加の処理は必要ありません。 

## 実用的な例

 3 つの結晶を使用した単純なケースを考えてみましょう。$(1, 3), (2, 2), (2, 2)$、 そして$m = 3$。 

サブセットを列挙します。 

| マスク | 選択されたクリスタル | 色の合計 | 製品 | 有効 |

 | 000 | なし | {} | 1 | はい |
 | 001 | (1,3) | {1:3} | 3 | はい |

 最大値は 12 で、すべてのクリスタルを取得し、2 つのカラー 2 クリスタルを結合することで達成されます。 

このトレースは、マージが決して決定点ではないことを示しています。サブセットが固定されると、集計は決定的になります。 

ここで考えてみましょう$m = 2$同じ入力で。 

| マスク | 選択済み | サイズ | 有効 | 製品 |

 最適な値は 6 です。これは、サブセット サイズを制限すると、マージによってメリットが得られる構成が直接プルーニングされることを示しています。
