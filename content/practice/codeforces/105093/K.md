 ## 解決策
 ## 問題の理解

 各セルに強度値が含まれる長方形のグリッドが与えられます。 1 つの特別なセルはプレーヤーの開始位置であり、もう 1 つはアンオブタニウム鉱山を含む目的地のセルです。 1 つおきのセルには、そのセルに格納されている値と同じ強さの敵が含まれています。 

プレイヤーは開始セルの強さから開始します。 4方向への移動が可能です。 プレイヤーが新しいセルに入るときは、厳密にそのセル内の敵よりも強い力を持たなければなりません。そうでないと、すぐに死んでしまいます。 勝てば敵の力を吸収し、その分自分の力も上がる。 

この問題を自明ではないものにする追加の制約があります。 戦闘が成功するたびに、隣接するすべてのセルがチェックされます。 近隣にプレイヤーの更新された強さよりも厳密に強い敵がいる場合、その近隣は即座にプレイヤーを攻撃して殺します。 したがって、戦闘で生き残れるかどうかは、現在のセルだけでなく、周囲のフロンティアにも依存します。 

タスクは、これらの進化する制約の下ですべての動きが安全であるような、スタートからターゲットまでのパスが存在するかどうかを判断することです。 

グリッドはテストごとに合計 10^6 セルほどの大きさになる可能性があるため、状態を繰り返し再検討したり、すべてのパスを明示的にシミュレートしたりするソリューションは失敗します。 各状態は電流の強さに依存し、電流の強さはパスに沿って変化し、状態空間が効果的に指数関数的になるため、単純な最短パスまたは状態にわたる DFS は実行不可能です。 

「復讐チェック」から微妙な特殊なケースが発生します。 たとえ細胞を倒すことができたとしても、戦闘後により強力な隣人によってすぐに死ぬ可能性があります。 たとえば、更新されたあなたの強さが 10 になり、隣人が強さ 12 を持っている場合、その隣人があなたのパス上にいない場合でも、その動きは無効になります。 ターゲット セルをチェックするだけの単純な BFS は、そのような遷移を誤って受け入れてしまいます。 

もう 1 つの注意が必要な状況は、ローカルではパスが安全に見えても、制限されたエリアに再訪問する前に、別のエリアで早期に強度を蓄積する必要がある場合に発生します。 これは、貪欲な最短経路の思考が失敗することを意味します。 

## アプローチ

 強引なアイデアは、これを、各状態が位置と現在の強さによって定義されるグラフ検索として扱うことです。 状態から、4 つの動きすべてを試し、強度を更新し、ターゲット セルとリベンジ制約の両方を検証します。 これは正しいですが、強さはすべてのセルの合計まで増加する可能性があり、同じセルがさまざまな強さで訪問される可能性があるため、すぐに爆発します。 最悪の場合、これにより指数関数的に多くの状態が作成されます。 

重要な観察は、リベンジ制約がパス履歴ではなく、_現在の強さ_にのみ依存するということです。 独房に入ると、唯一の問題は、自分の現在の体力が独房とその隣の独房の両方で生き残るのに十分であるかどうかです。 これは、ダイクストラのアルゴリズムと同様に、常に必要な強度の昇順でセルに到達するように努めるべきであることを示唆しています。 

この問題を、各セルを安全に占有するのに十分な強度があるときに各セルが使用可能になる到達可能性プロセスとして再解釈できます。 セルに入るたびに私たちの強さが増し、より多くのセルのロックが解除される可能性があります。 これはまさに単調な拡張プロセスであり、現在の強さによって順序付けされた優先キューが自然にそれを捕捉します。 

新しいセルのロックを解除する可能性が最大化されるため、常に現在到達可能な最強の状態から拡張します。 国家が弱体化しても、新しい地域への早期アクセスにつながることはありません。

 ## アルゴリズムのチュートリアル

1. 各グリッド セルを、強度要件に等しい重みを持つノードとして解釈しますが、収集されたときの値に等しい動的報酬を持ちます。 開始ノードは、セル値に等しい初期強度で始まります。 
2. 到達可能なセルの優先キューを維持し、到達時の現在の強さ順に並べます。 私たちは常に最も強度の高い状態を最初に拡張します。 これにより、より早い段階でより困難な領域のロックを解除できるパスを無視することがなくなります。 
3. 訪問したセルを追跡して、同じセルを複数回処理しないようにします。これは、セルを一度取得すると、その強度への寄与が永続的に追加されるためです。 
4. 現在のセルから 4 方向に移動してみます。 近隣ごとに、現在の強度が近隣の値よりも厳密に大きいかどうかを確認します。 そうでない場合はスキップしてください。 
5. 移動が許可される場合は、力を強めてセルに入るシミュレーションを行います。 強度を更新した後、リベンジ条件を検証します。新しいセルの 4 つの隣接セルはすべて、更新された強度以下の強度を持っている必要があります。 近隣の誰かがこれに違反した場合、その移動は破棄されます。 
6. 移動が有効で、近隣が訪問されていない場合は、更新された強度で優先キューにプッシュします。 
7. 宛先セルがキューからポップされたら、ただちに停止します。 キューに到達せずにキューが空になった場合、ターゲットには到達できません。 

重要な考え方は、セルを処理するたびに、そのセルに到達するために現在知られているすべての方法の中で可能な限り最大の強度で処理を行っているため、将来の改善はこれまで未踏の領域から得られる必要があるということです。 

### なぜ効果があるのか

 どの時点でも、アルゴリズムは、関連する強度値を持つ到達可能なセルのフロンティアを維持し、常に最大強度のフロンティアを最初に拡張します。 強度はパスに沿ってのみ増加し、減少することはないため、セルが特定の強度で処理されると、後で同じセルに到達する代替パスは、既に処理されたノードまたは以前に拡張されたであろうより強度の高い状態を通過することなく、より強い状態を生成することはできません。 これにより、最初にセルを完成させるときに、最大の強度でセルに到達するためのすべての方法がすでに考慮されているため、目的地へのより良いパスを見逃すことはできないことがわかります。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        r, c = map(int, input().split())
        grid = [list(map(int, input().split())) for _ in range(r)]
        isr, jsc, itr, jtc = map(int, input().split())
        isr -= 1
        jsc -= 1
        itr -= 1
        jtc -= 1

        start_val = grid[isr][jsc]
        target = (itr, jtc)

        visited = [[False] * c for _ in range(r)]
        pq = []
        heapq.heappush(pq, (-start_val, isr, jsc))

        dirs = [(1, 0), (-1, 0), (0, 1), (0, -1)]

        while pq:
            neg_str, x, y = heapq.heappop(pq)
            strength = -neg_str

            if visited[x][y]:
                continue
            visited[x][y] = True

            if (x, y) == target:
                print("UNOBTANIUM")
                break

            for dx, dy in dirs:
                nx, ny = x + dx, y + dy
                if nx < 0 or nx >= r or ny < 0 or ny >= c:
                    continue
                if visited[nx][ny]:
                    continue

                if strength <= grid[nx][ny]:
                    continue

                new_strength = strength + grid[nx][ny]

                ok = True
                for ddx, ddy in dirs:
                    ax, ay = nx + ddx, ny + ddy
                    if 0 <= ax < r and 0 <= ay < c:
                        if grid[ax][ay] > new_strength:
                            ok = False
                            break

                if ok:
                    heapq.heappush(pq, (-new_strength, nx, ny))
            else:
                continue
        else:
            print("UNOBTAINABLE")

def main():
    solve()

if __name__ == "__main__":
    main()
```この実装では、到達可能な最強の状態が常に最初に展開されるように、強度を無効にすることで最大ヒープを使用します。 訪問されたアレイにより、各セルがその最もよく知られている強度で 1 回処理されることが保証されます。 

重要な詳細は、状態をプッシュする前に、動きをシミュレートした直後にリベンジ条件がチェックされることです。 これにより、無効な状態が検索空間に伝播することが回避されます。 

## 実用的な例

 ### 例 1

 開始がすでに単調増加パスを通過するのに十分な強度を持っている小さなグリッドを考えてみましょう。 

| ステップ | セル | 前の強度 | 有効な移動 | |後の強度 リベンジチェック |
 | --- | --- | --- | --- | --- | --- |
 | 1 | (1,1) 開始 | 3 | - | 3 | OK |
 | 2 | (1,2) | 3 | はい (3 > 1) | 4 | OK |
 | 3 | (2,2) | 4 | はい (4 > 4? いいえ、無効です) | - | - |

 これは、パスが幾何学的に到達可能であるように見えても、等価性が移動をブロックし、誤った拡張を防ぐことを示しています。 

有効な継続が存在しないため、アルゴリズムは早期に正しく停止します。 

### 例 2

 迂回が必要な場合：

 | ステップ | セル | 前の強度 | 有効な移動 | |後の強度 リベンジチェック |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 開始 | 5 | - | 5 | OK |
 | 2 | 高価値の安全なノード | 5 | はい | 12 | OK |
 | 3 | ターゲット | 12 | はい | 15 | OK |

 ここで、優先キューの順序付けにより、より強力な中間状態が最初に探索され、ターゲットのロックが解除されますが、単純な BFS は最初に弱いルートを試みてブロックされる可能性があります。 

これは、展開順序が正確さのために不可欠であることを裏付けています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(rcログ(rc)) | 各セルはヒープに対して最大 1 回挿入され、ヒープから削除されます。各操作には対数的な時間がかかります。 
| スペース | O(rc) | グリッド、訪問済み配列、ヒープ ストアはセルごとに最大 1 つのエントリです。 

この制約により、テスト ケース全体のセルの総数が最大 10^5 であることが保証されるため、この複雑さは Python であっても制限内に問題なく収まります。
