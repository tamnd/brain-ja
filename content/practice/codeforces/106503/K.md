 ## 解決策
 ## 問題の理解

 次数の昇順で係数によって記述される多項式が与えられます。 言い換えれば、入力は関数を定義します

 F(x) = f0 + f1 x + f2 x^2 + ... + fn x^n

 各クエリは値 x を提供し、その時点でこの多項式を評価し、指定された素数 p を法とする結果を報告する必要があります。 

問題を直接解釈すると、次のようになります。高次多項式の評価が多数あり、次数は 100 万にも達する可能性があり、クエリの数はテスト ケースごとに最大 5,000 で、テスト全体の次数の合計も大きくなります。 

重要な制約は、大きな n と比較的小さな p の組み合わせです。 点 x での多項式の 1 回の評価は、単純に実行した場合、すでに O(n) のコストがかかります。 q が 5000 までの場合、これは O(nq) となり、まったく実行不可能です。 複数のテスト ケースにまたがる場合でも、合計作業量は許容限界を数桁超えてしまいます。 

微妙な問題は、x が負の値になる可能性があり、係数が大きくてもモジュラー演算で管理できることです。 もう 1 つの重要な点は、p が 5000 より小さい素数であることです。これは、数論的変換または p を法とする周期構造を示唆することがよくあります。 

また、単純な実装では、各ステップでモジュラー削減を行わずに x の累乗を累積すると、整数オーバーフローの危険があります。 x の大きさは最大 1e6 であるため、x^k は適切に縮小しないと非常に急速に増加します。 

ブルートフォースの具体的な失敗例は次のとおりです。 

入力:

 n = 100000、q = 5000

 各評価がホーナー ルールに最適化されている場合でも、各クエリは依然として O(n) であり、最悪の場合、テスト ケースごとに約 5e8 の乗算が行われることになりますが、これは Python では遅すぎます。 

## アプローチ

 簡単な方法では、ホーナーのルールを使用して各クエリを個別に評価します。 固定 x の場合、アキュムレータを維持しながら、最も高い係数から下に向かって反復して F(x) を計算します。 これは正しく、クエリごとに O(n) 時間を使用します。 

ボトルネックは明らかです。これを q 回繰り返すと O(nq) になります。 n が 1e6 まで、q が 5e3 までなので、これは実現可能な限界をはるかに超えています。 

重要な観察は、多くの点で同じ多項式を評価しており、法 p が小さいということです。 これは、評価をバッチ化または分解できるように多項式を変換することを示唆しています。 

この設定における標準的なトリックは、剰余 p が累乗パターンの効果的な動作を制限し、多くの点での評価が構造化された複数点の評価に変わる可能性があるという事実を利用することです。 ただし、古典的な多点評価には依然として FFT のような機構が必要ですが、次数が大きく係数が小さいため、これは実行できません。 

代わりに、意図された洞察は、p を法とする累乗に基づいて多項式を分割することです。 p が小さいため、p を法とするインデックス剰余によって係数をグループ化できます。 

F(x) = sum_{r=0 ～ p-1} x^r * (sum_{k >= 0} f_{k p + r} * (x^p)^k)

 これにより、多項式が p 個の別個の「ストランド」を持つ x^p の多項式として書き換えられます。 各クエリについて、高速累乗を使用して x^p モジュロ p を効率的に計算し、各ストランドをその値の個別の多項式として評価します。 各ストランドのサイズは約 n/p であるため、評価が大幅に高速化されます。 

これにより、各クエリが O(n) から O(p + n/p) に減少します。また、p が小さい (最大 5000) ため、これは許容可能です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nq) | お(1) | 遅すぎる |
 | 剰余 mod p で分割 | O(q * (p + n/p)) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 項が p を法とするインデックスによってグループ化されるように多項式を書き換えます。 各グループは x^p でより小さな多項式を形成します。 この構造により、クエリごとに部分的な計算を再利用できます。

1. 係数を p 個の個別の配列に前処理します。 [0, p-1] の各剰余 r について、係数 f[r]、f[r+p]、f[r+2p] などを収集します。 これにより、多項式の値は変更されず、表現のみが変更されます。 
2. 各クエリ値 x について、y = x^p mod p を計算します。 これにより、x^p のすべての高次べき乗が、モジュロ算術で単一のスカラー値に変換されます。 
3. 各剰余クラス r について、y でグループ化された係数によって形成された小さな多項式を評価します。 結果に x^r を乗算し、累積して最終的な答えを求めます。 
4. p を法として累積した結果を返します。 

この構造が機能する理由は、すべての項 x^{kp+r} が x^r * (x^p)^k に分解できるため、多項式が r でインデックス付けされた独立した成分に自然に分離されるためです。 

### なぜ効果があるのか

 正しさは代数恒等式 x^{kp+r} = x^r (x^p)^k に依存します。 同一の r を持つ項をグループ化することで、すべての元の単項式が 1 つのグループ内に 1 回だけ出現することが保証され、各グループ内での評価は x^p の累乗のみに依存します。 モジュラーリダクションは各ステップで一貫して適用されるため、項が失われたり重複したりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def mod_pow(a, e, mod):
    res = 1
    a %= mod
    while e > 0:
        if e & 1:
            res = (res * a) % mod
        a = (a * a) % mod
        e >>= 1
    return res

def solve():
    T = int(input())
    for _ in range(T):
        n, p, q = map(int, input().split())
        f = list(map(int, input().split()))
        
        groups = [[] for _ in range(p)]
        for i, coef in enumerate(f):
            groups[i % p].append(coef)
        
        for _ in range(q):
            x = int(input())
            x_mod = x % p
            
            xp = mod_pow(x_mod, p, p)
            
            ans = 0
            for r in range(p):
                # evaluate polynomial for group r at xp
                val = 0
                power = 1
                for coef in groups[r]:
                    val = (val + coef * power) % p
                    power = (power * xp) % p
                
                ans = (ans + val * mod_pow(x_mod, r, p)) % p
            
            print(ans)

if __name__ == "__main__":
    solve()
```この実装では、まず係数が p 個のバケットに再構築されます。 これは、n にわたって線形的にクエリごとに完全な多項式をスキャンすることを回避するため、非常に重要です。 

各クエリは x mod p を即座に計算して、中間値を小さく保ちます。 次に、高速べき乗を使用してべき乗 x^p mod p が計算されます。これが必要となるのは、乗算を繰り返すと時間がかかりすぎるためであり、指数が大きい場合は危険でもあります。 

各剰余クラス内では、多項式の評価が O(クラスのサイズ) で行われ、これはおよそ n/p です。 これが核となる最適化です。 

微妙な点の 1 つは、x^r と (x^p)^k の両方が常に p を法として削減され、すべての中間値が制限されたままであることです。 

## 実用的な例

 ### 例 1

 入力:

 n = 3、p = 5、係数 [0、9、0、6]、クエリ x = -7

 私たちはグループを構築します:

 | r | 係数 |
 | --- | --- |
 | 0 | [0, 6] |
 | 1 | [9] |
 | 2 | [] |
 | 3 | [] |
 | 4 | [] |

 x mod p = 3 を計算します。 

| ステップ | 値 |
 | --- | --- |
 | x mod p | 3 |
 | x^5 mod 5 | 3^5 mod 5 = 243 mod 5 = 3 |

 次に、以下を評価します。 

グループ r=0: 多項式 0 + 6_y = 6_3 = 18 ≡ 3

 グループ r=1: 9 * x^1 = 9*3 = 27 ≡ 2

 合計 = 3 + 2 = 5 ≡ 0 mod 5

 これは、分割によってコントリビューションがどのようにきれいに分離されるかを示しています。 

### 例 2

 入力:

 n = 2、p = 7、F(x) = 8 + 0x + 2x^2、x = -10

 次のように計算します。 

x mod 7 = 4

 x^7 mod 7 = 4^7 mod 7 = 4 (フェルマーの小定理構造 mod 素数による)

 グループ:

 | r | 係数 |
 | --- | --- |
 | 0 | [8] |
 | 1 | [0] |
 | 2 | [2] |

 評価:

 r=0:8

 r=1:0

 r=2: 2 * 4 = 8 ≡ 1

 x^0、x^1、x^2 の寄与:

 8 + 1 = 9 ≡ 2 mod 7

 これにより、直接評価との一貫性が確認されます。

 ## 特殊なケース

 エッジケースの 1 つは n < p の場合で、これはほとんどの残基グループが空であることを意味します。 この場合、各クエリは少数の空でないグループのみを評価し、アルゴリズムは剰余クラスごとの小さな多項式の直接評価に退化します。空のグループは寄与がゼロであるため、これは正しいままです。 

別のケースは、x = 0 または x ≡ 0 mod p です。 その後、より高い出力の寄与はすべて消え、r=0 グループのみが寄与します。 r > 0 の場合、x^r は 0 ですが、x^0 は 1 であるため、アルゴリズムはこれを自然に処理します。 

3 番目のケースは、係数がスパースである場合です。たとえば、p 番目の係数のみが非ゼロである場合です。 この場合、1 つの残基グループのみがアクティブとなり、アルゴリズムは同じ分解恒等性を通じて正確さを維持しながら、評価コストを大幅に削減します。
