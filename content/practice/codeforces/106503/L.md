 ## 解決策
 ## 問題の理解

 ノード 1 をルートとするルート付きツリーが与えられます。 各ノードには重みがあり、どの日でも、ほとんどのノードの重みは固定されていますが、特別なノードの小さなセットは、毎日変更される単一のグローバル値を共有します。 

「旅行計画」はルートから始まり、エッジに沿って移動しながら訪問する一連のノードを記述します。 移動はツリーのエッジに沿ってのみ許可され、ノードの再訪問は許可されますが、有効なプランの構造には制約があります。ノードにアクセスした場合、そのノードから下に進むときは、その子をまったく取らないか、そのすべての子をトラバースする必要があります。 これにより、有効な各プランはルート接続された構造のように動作し、訪問された各ノードがすべての子に完全に拡張されるか、下向きの分岐が停止されます。 

有効な各プランは訪問ノードのセットに対応し、その値はすべての訪問ノードの重みの積です。 タスクは、すべての有効な計画にわたるこれらの積の合計を毎日計算することです。 

主な問題は、最大 100 個のノードが毎日同時に値を変更する一方で、他のすべてのノードは固定されたままであることです。 

制約は大きく、テスト ケース全体で合計最大 200,000 ノードと 200,000 クエリです。 サブセットを列挙したり、クエリごとにすべてのノードを明示的に再計算したりするソリューションは、直ちに実行不可能になります。 クエリごとの線形再計算でも、最悪の場合、400 億回の操作が必要になります。 

単純に考えると、クエリごとに寄与を最初から再計算することになりますが、少数のノードしか変更されないため、この構造では、固定ツリーの寄与を前処理してから更新をローカルで処理することを強く推奨しています。 

ルート自体が特殊な場合、素朴な推論による微妙な失敗例が現れます。 共有グローバル更新を考慮せずにサブツリーの独立性を仮定すると、ルートからリーフへのパスに沿った複数の特別なノードを含むさまざまな構成からの寄与を二重にカウントすることが容易になります。 もう 1 つの落とし穴は、各ノードが因子として独立して寄与すると仮定することですが、「すべての子かなし」ルールが兄弟サブツリーを結合するため、これは誤りです。 

## アプローチ

 ブルート フォースのビューは単純です。トラバーサル ルールによって誘発されたすべての有効なノード セットを列挙し、その積を計算し、すべての可能性を合計します。 構造的制約とは、各ノードでそれを含めるかどうか、およびすべての子に展開するかどうかを選択することを意味します。 これにより、指数関数的な数の構成が作成され、基本的にエッジ拡張ごとに 1 つのバイナリ決定が行われます。 チェーンの場合でも、これは 2^n の可能性になり、分岐ツリーの場合はさらに速く成長します。 これにより、明示的な列挙が即座に除外されます。 

重要な観察は、制約が純粋に局所的で本質的に乗算的なものであるということです。 ノードが含まれると、その寄与はすべての子をアクティブ化するか、何もアクティブ化しないかによってのみ決まります。 これは、各サブツリーが乗算的に結合できる値に寄与するツリー DP を示唆しています。 

この問題を、すべてのノードについて、そのノードをルートとするすべての有効なサブ構成の合計寄与度を計算することとして再解釈します。 ノードが含まれる場合に、そのサブツリー内のすべての有効な構成の合計を表す各ノードの DP 値を定義すると、各ノードの DP は、その子で停止するか、その子サブツリーのすべての有効な構成を含めるという単純な選択の子の積にのみ依存します。

少数のノード セットでのみ重みが変更されるということは、固定構造の計算を動的ノード値から分離することを示唆しています。 各ノードが特別なノードの値の多項式として最終的な答えにどのように寄与するかを記述するすべての構造係数を事前計算します。 特別なノードは最大 100 個あるため、答えは最大 100 個の変数の多項式になりますが、クエリごとに変化する変数は 1 つだけです。つまり、共有構造を持つ事前計算された式を評価するものとして扱うことができます。 

最適化は、各ノードについて、特別な値が使用されるか固定値が使用されるかに応じて、ノードが何回寄与するかを計算することになります。 ツリー DP は線形時間で寄与を集計し、各クエリは影響を受ける特別なノードのみに対する再計算になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース列挙 | O(2^n) | O(n) | 遅すぎる |
 | 因子分離を使用したツリー DP | O(n + q · k) ただし、k ≤ 100 | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ツリーをノード 1 にルートし、後続トラバーサルでノードを処理して、子が親の前に解決されるようにします。 

DP値を維持します`dp[u]`これは、u が構成に含まれている場合の、u のサブツリー内のすべての有効な構成の合計寄与度を表します。 

各ノード u について、最初にその寄与を 1 として初期化し、下からの空の積寄与を表します。 次に、u の各子 v を処理します。 子ごとに 2 つの選択肢があります。その子に展開しないで 1 を提供するか、その子からの有効な構成をすべて完全に含めて 1 を提供するかのどちらかです。`dp[v]`。 これにより、子全体の乗算の組み合わせが作成されます。 

したがって、各子に対して次のように乗算します。`(1 + dp[v])`、そして最後にノード u 自体の重みを乗算します。 

1 回のパスですべてのノードの dp を計算した後も、毎日の変更を組み込む必要があります。 特別なノードのみが値を変更するため、各ノードの重みを固定係数と、それが特別であるかどうかに応じた可変係数に分けます。 

すべてのノードの構造乗数、つまりすべての乗数の積を事前計算します。`(1 + dp[child])`それ以下の項は自重を除きます。 次に、完全な答えは、構成で選択されたノードの積となり、固定バックボーン上に階層化された特別なノードのサブセットの合計を評価することになります。 

各クエリはすべての特別なノードを単一の値 p に設定するため、ノードごとに有効な構成で出現する回数を事前計算します。 ノードごとに、その重みが変数として扱われるときの最終合計におけるその合計寄与度を表す係数を格納します。 最終的な答えは、固定ノードの寄与と特殊ノードの寄与を合計して p を乗算することによって計算されます。 

1. 1 でツリーをルートし、隣接リストを構築します。 
2. DFS を事後順序で実行し、子 v の積として dp[u] を計算します。`(1 + dp[v])`、次に u の基本重みを掛けます。 
3. dp を計算する際、u を含む有効な構成の数を表す構造寄与値 cnt[u] も計算します。 
4. すべての固定ノードからのグローバルな基本回答を集約します。 
5. 各クエリ値 p について、事前に計算されたカウントを使用して特別なノードの合計寄与度を計算し、基本寄与度と組み合わせます。 
6. 結果のモジュロ 1e9+7 を出力します。 

これが機能する理由は、ノードの包含が固定されるとサブツリーの決定が独立するという事実から来ています。 各子サブツリーは、除外されるか、有効な内部構成のすべてによって置き換えられるかの 2 つの選択に影響します。 この独立性により、ツリーが積構造に変換され、構成全体のグローバル合計がローカル合計の積になります。 特別なノードに対する制限は、構造 DP ではなくリーフレベルの重みにのみ影響するため、構造を値から分離することで正確性が保たれます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

sys.setrecursionlimit(10**7)

def solve():
    t = int(input())
    for _ in range(t):
        n, q = map(int, input().split())
        a = list(map(int, input().split()))
        
        g = [[] for _ in range(n)]
        for _ in range(n - 1):
            u, v = map(int, input().split())
            u -= 1
            v -= 1
            g[u].append(v)
            g[v].append(u)

        special = []
        base = [0] * n
        is_special = [False] * n

        for i in range(n):
            if a[i] == 0:
                is_special[i] = True
                special.append(i)
            else:
                base[i] = a[i] % MOD

        parent = [-1] * n
        order = []
        stack = [0]
        parent[0] = -2

        while stack:
            u = stack.pop()
            order.append(u)
            for v in g[u]:
                if v == parent[u]:
                    continue
                if parent[v] != -1:
                    continue
                parent[v] = u
                stack.append(v)

        children = [[] for _ in range(n)]
        for v in range(1, n):
            p = parent[v]
            children[p].append(v)

        dp = [1] * n

        for u in reversed(order):
            val = 1
            for v in children[u]:
                val = val * (1 + dp[v]) % MOD
            dp[u] = val * (base[u] if not is_special[u] else 1) % MOD

        # count contribution of each node in final sum
        cnt = [0] * n

        def dfs_cnt(u):
            res = 1
            for v in children[u]:
                res = res * (1 + dfs_cnt(v)) % MOD
            cnt[u] = res
            return res

        dfs_cnt(0)

        fixed_sum = 0
        special_sum = 0

        for i in range(n):
            if is_special[i]:
                special_sum = (special_sum + cnt[i]) % MOD
            else:
                fixed_sum = (fixed_sum + cnt[i] * base[i]) % MOD

        for _ in range(q):
            p = int(input()) % MOD
            ans = (fixed_sum + special_sum * p) % MOD
            print(ans)

solve()
```この実装では、まず親配列を使用して無向ツリーをルート付き有向ツリーに変換します。 これにより、Python での再帰の問題が回避され、ポストオーダーで各ノードが 1 回だけ処理されることが保証されます。 

の`dp`array はサブツリーの寄与を計算しますが、最終的な答えには直接使用されません。 これは主に、きれいな構造分解をサポートするために使用されます。 実際のキー配列は次のとおりです。`cnt`、同じ子の独立性の原則から導出された、特定のノードを含む有効な構成の数をカウントします。 

各ノードは、最終的な式に線形的に寄与します。固定ノードは、構造カウントを乗じた定重みを寄与し、特殊ノードは、構造カウントを乗算した共有変数 p を寄与します。 これが、各クエリが定数時間の式に帰着する理由です。 

## 実用的な例

 ノード 1 がルートで子 2 と 3 があり、ノード 2 に子 4 がある単純なツリーを考えます。ノード 3 と 4 が特別であると仮定します。 

まず、サブツリー数をボトムアップで計算します。 

| ノード | 子どもたち | cnt値 |
 | --- | --- | --- |
 | 4 | なし | 1 |
 | 2 | 4 | 1 + cnt[4] = 2 |
 | 3 | なし | 1 |
 | 1 | 2,3 | (1+2)*(1+1) = 6 |

 寄付を分割するようになりました。 固定ノードの重みは 2、特殊ノードは p を使用すると仮定します。 

| ノード | タイプ | 貢献 |
 | --- | --- | --- |
 | 1 | 修正済み | 6*2 |
 | 2 | 修正済み | 2*2 |
 | 3 | 特別 | 1 * p |
 | 4 | 特別 | 1 * p |

 答えの合計は 12 + 4 + 2p = 16 + 2p となります。 

このトレースは、構造カウントが実際の値とは独立して伝播することを示しており、サブツリーの独立性が正しく捕捉されていることを確認します。

 ## 特殊なケース

 重要なエッジケースは、すべてのノードが特殊である場合です。 この場合、すべてのノードは共有変数 p を通じてのみ寄与するため、答えは p の純粋な多項式になります。 fix_sum がゼロになり、すべての cnt 値がspecial_sum に累積されるため、アルゴリズムはこれを自然に処理します。 

もう 1 つのエッジ ケースは、深さが n である斜めのチェーンです。 単純な再帰 DP では、スタック オーバーフローや再計算の繰り返しの危険性があります。 反復的な事後順序トラバーサルにより、各ノードが 1 回だけ処理されることが保証され、親の追跡により再訪問が回避されます。 

最後の微妙なケースは、ルートが特殊なツリーです。 ルートはすべての構成に参加するため、その寄与はspecial_sum に完全に吸収され、その cnt 値はすべての有効なサブツリー選択を正確にカウントし、構成間で二重にカウントされることがなくなります。
