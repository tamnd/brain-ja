 ## 問題の理解

 の行が与えられています$n$位置、各位置はすでに文字として固定されているか、`C`またはまだ空で、次のように表されます。`?`。 すべてを交換する必要があります`?`最終文字列に正確に含まれるように大文字で表記します。$k$パターンの出現`SCNUCPC`。 

「一致」は開始インデックスを選択することによって定義されます$i$の部分文字列が$i$に$i+6$まさに`SCNUCPC`。 重複が許可されているため、2 つの一致が文字を共有する可能性があり、有効な開始位置はすべて独立してカウントされます。 

出力は、制約を満たす完全に構築された 1 つの文字列、またはそのような補完が存在しないという宣言のいずれかです。 

長さ$n$まで可能です$2 \cdot 10^5$テストごとに最大で$10^3$合計のテスト ケース$n$によって制限される$2 \cdot 10^5$。 これにより、可能なすべての埋め込みを試みるアプローチは即座に除外されます。`?`あるいは、素朴な方法で開始位置のすべてのサブセットを試してみることさえできます。 どのソリューションも、テストごとに線形またはほぼ線形である必要があります。 

重要な点は、最初の文字列にすでに次の文字列が含まれている可能性があることです。`C`可能な配置を制限する文字`SCNUCPC`。 既存のものを変えることは許されないので、`C`、構築された出来事はそれらと一致する必要があります。 

いくつかの特殊なケースが自然に発生します。 

もし$n < 7$、長さ 7 の部分文字列は存在しないため、答えは次の場合にのみ可能です。$k = 0$。 の任意の割り当て`?`固定を尊重する`C`たとえば、すべてを次のように埋めると機能します。`A`。 

もし$k > n - 6$、しかないので無理です。$n - 6$可能な開始位置。 

修正された場合`C`文字が必要なパターンの位置と競合していますが、そうではありません。`C`内部`SCNUCPC`、配置は不可能です。 たとえば、必要な場合は、`S`位置はすでに固定されています`C`、その開始インデックスは使用できません。 

最後に、重なり合うパターンは相互作用する可能性があるため、貪欲な配置では、重なり合うオカレンス間に誤って矛盾が生じないようにする必要があります。 

## アプローチ

 ブルート フォース ビューは、どの開始位置が一致するかを選択することから始まります。 がある$n - 6$可能な開始インデックスがあり、正確に選択する必要があります$k$彼らのうち。 選択したセットごとに、完全な文字列を構築しようとします。選択した開始点ごとに、次のように書きます。`SCNUCPC`配列に挿入し、既存の修正との整合性をチェックします`C`価値観と以前に書かれた文字。 選択したパターンをすべて配置したら、残りを塗りつぶします`?`任意で、余分な一致が表示されないことを確認します。 

ポジションを選択する方法は次のとおりです。$\binom{n}{k}$、そして中程度の値であっても、これは爆発的に増加します。 それぞれの検証は、$O(n)$、そのため、ブルートフォースはすぐに実行不可能になります。 

パターンの構造`SCNUCPC`重要な簡素化です。 それぞれの有効なオカレンスは、その開始インデックスによって完全に決定され、パターンを位置に配置することを決定すると、$i$、7文字すべてが強制されます。 これは貪欲な構築を示唆しています。任意のサブセットを選択してチェックする代わりに、パターンを配置するかどうかをローカルで決定しながら、左から右へ答えを構築しようとします。 

主な観察は、これを短距離依存関係による制約充足問題として扱うことができるということです。 各配置はサイズ 7 のウィンドウにのみ影響するため、可能な限り早い有効な位置にパターンを配置することを貪欲に試みることができ、後で意図しない余分な一致が作成されないようにすることができます。 

建設的なプロセスをシミュレートします。左から右にスキャンし、所定の位置にパターンを配置するのがわかるたびに、$i$は既存の固定文字と一致していますが、さらに一致する必要がある場合はこれを配置します。 一貫性がない場合はスキップします。 最後まで到達しても達成できなかった場合$k$一致する場合、配置を遅らせても利用可能なポジションが減るだけであるため、完了が存在しないことがわかります。 

これにより、問題はローカル チェックによるリニア スキャンに帰着します。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. 文字列内に長さ 7 の部分文字列がいくつ収まる可能性があるかを数えます。 もし$k > n - 6$、すぐに出力`No`。 完全な自由があっても開始位置が十分ではないため、これは組み合わせの厳しい制限となります。 
2. 入力文字列から初期化された可変文字配列を操作します。 カウンターを維持する`need = k`まだ配置しなければならないパターンの数を表します。 
3. スキャンインデックス$i$から$0$に$n - 7$。 各位置で、配置できるかどうかをテストします`SCNUCPC`から始まる$i$。 これは、オフセットごとに$j$で$[0,6]$、現在のセルが`?`または、すでに必要な文字と一致しています。 
4. 配置が有効であり、`need > 0`、パターンを文字列に書き込み、上書きします`?`既存のマッチングを維持する`C`。 次にデクリメントします`need`。 ここで貪欲に配置する理由は、後で配置すると重複するオプションが少なくなるため、早めに配置しても、遅らせた場合に比べて将来の実現可能性が決して低下しないためです。 
5. スキャン後、次の場合は`need > 0`、出力`No`。 それ以外の場合は、構築された文字列を出力します。 
6. 最後に、意図せずに余分なオカレンスが作成されないようにします。 これは、明示的なパターンのみを配置し、配置時にチェックされなかった部分的な偶発的な補完を決して導入しないため、当然保証されます。 

### なぜ効果があるのか

 正確さは、重なりの一貫性を除いて、各配置が独立しているという事実にかかっています。 パターンを位置に配置すると$i$では、長さ 7 のブロックを完全に修正します。 今後の配置では、これらの制約を尊重する必要があります。 検討した時点でプレースメントが有効である場合、後で決定しても制約が追加されるだけなので、延期しても後で有効性が高まることはありません。 したがって、最も早い有効な位置で貪欲にコミットすると、すべての実行可能なソリューションが保存されます。 解決策が存在する場合、有効性を損なうことなく、選択されたすべての開始点ができるだけ左にシフトされる解決策に変換できます。これは、この貪欲な構造と一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

PAT = "SCNUCPC"
L = 7

def can_place(s, i):
    for j in range(L):
        if s[i + j] != '?' and s[i + j] != PAT[j]:
            return False
    return True

def place(s, i):
    for j in range(L):
        s[i + j] = PAT[j]

t = int(input())
for _ in range(t):
    n, k = map(int, input().split())
    s = list(input().strip())

    if k > n - 6:
        print("No")
        continue

    need = k

    i = 0
    while i <= n - 7:
        if need > 0 and can_place(s, i):
            place(s, i)
            need -= 1
        i += 1

    if need > 0:
        print("No")
    else:
        print("Yes")
        print("".join(c if c != '?' else 'A' for c in s))
```この実装では、貪欲なプロセスの直接シミュレーションを使用します。 の`can_place`関数は、配列を変更せずにパターンとのローカル互換性をチェックします。 の`place`関数は完全なパターンを配列に書き込みます。 

必要なオカレンスをすべて配置した後、残りの`?`で満たされています`A`、追加の有効な要素には寄与しないため、`SCNUCPC`発生し、既存の修正と競合することはできません`C`制約。 

アーリーバウンドチェック`k > n - 6`不可能なケースでの無駄な作業を防ぎます。

def run(inp: str) -> str:

 ## 特殊なケース

 タイトなケースは修正されると、`C`値はすでに複数の重複する候補ウィンドウと部分的に一致しています。 たとえば、次のような文字列`SC?????C`配置に応じて配置を強制または禁止できます。 アルゴリズムは、キャラクターがすでに固定されている場合には決して自由を仮定しないことによってこれを処理します。`can_place`あらゆる位置で正確な互換性を実現します。 

もう 1 つのエッジケースは次のような場合です$k = 0$。 この場合、パターンを配置せず、単にすべてを塗りつぶします。`?`と`A`。 紹介したことがないので、`S`、部分文字列が誤って形成されることはありません`SCNUCPC`、および既存のすべて`C`制約は変更されません。 

3 番目のケースは最大密度です。$k = n - 6$。 アルゴリズムはすべての有効な位置に配置しようとしますが、文字列が完全に空いていない限り、重複によってほとんどの配置がブロックされます。 これにより、不可能な構成が正しく拒否されます。これは、配置が近隣をブロックすると、その後のウィンドウが無効になり、`need`最後までプラスのままです。
