 ## 問題の理解

 長さのバイナリ文字列が与えられます$n$。 シーケンスを構築する必要があります$a_1, a_2, \dots, a_{n+1}$ここで、各値は 100 で区切られた小さな正の整数です。重要な条件は、シーケンス自体の算術に関するものではなく、基数に関連付けられた数論的なプロパティに関するものです。$k$： それぞれ$a_i$、baseで書かれた場合$k$、有限表現を持たなければなりません。 

隣接する要素間の相互作用はバイナリ文字列によって制御されます。 あらゆるポジションについて$i$、の値$s_i$間に特定の制約があるかどうかを決定します。$a_i$そして$a_{i+1}$強制されるかどうか。 この問題は、何も最適化せず、1 つの有効なシーケンスのみを構築するように設計されています。 

「基数における有限表現」に関する制約$k$有理数には終端基数があります。$k$換算された分母にその外に素因数がないときの正確な表現$k$。 ずっと$a_i$が整数である場合、禁止された暗黙的な除算動作を確実に回避できるように構成すれば、この条件は自明に満たされます。 本当の難しさは、このステートメントが整数論の深い依存性を示唆するような表現で表現されているにもかかわらず、実際の構造ではすべてを隣接する位置間の組み合わせ制約に還元していることです。 

与えられた$n \le 2 \cdot 10^5$すべてのテスト ケースにわたって、線形または線形に近い構造が必要です。 二次関数や算術プロパティの位置ごとのシミュレーションを伴うものはすべて、すぐに失敗します。 

「有限基底」を解釈しようとすると、微妙な故障モードが現れます。$k$」要件は、実際の値に依存するものとして誤って解釈されます。$k$。 それは不必要な因数分解や数字の DP アイデアにつながります。 もう 1 つのよくある間違いは、すべてのペア間の依存関係を想定することです。$a_i$一方、条件は隣接する要素のみをリンクします。 

## アプローチ

 素朴な解釈は、各位置を独立して扱うことです。つまり、$[1,100]$そしてすべての条件が維持されることを願っています。 バイナリ文字列には隣接性の制約が課されるため、独立した割り当てでは一貫性を保証できないため、これはすぐに失敗します。 もう少し素朴な試みとしては、それぞれをブルートフォース検索することです。$a_i$以前の値との互換性を確認しながら。 つまり、ポジションごとに最大 100 個の値を試し、それが次の条件を満たすかどうかを検証します。$a_{i-1}$。 これにより、$O(n \cdot 100)$、これは単独で許容されますが、有効性チェック自体が有効である場合に限ります。$O(1)$。 

本当の障害は、その状態が実際に何を意味するのかを解釈することです。 正しい構造形式に書き直されると、制約はローカルかつバイナリになります。つまり、各エッジは平等のような動作を強制するか、自由を許可するかのいずれかになります。 これが重要な簡素化です。 問題は、強制的な「同じ」関係と文字列に応じた「異なる」ブレークを尊重するシーケンスを構築することに帰着します。 

これにより、タスクは、一部のエッジが等価性を強制し、他のエッジが等価性を強制しない折れ線グラフ上に割り当てを構築することになります。 左から右に移動し、一貫性を維持しながら値を割り当てることで、これを貪欲に解決できます。 必要な値は 100 までであるため、いつでも小さな数値パレットを再利用し、必要に応じて切り替えることができます。 

強引なアイデアは、制約を数値的かつグローバルなものとして扱うため失敗しますが、正しい観点は純粋に構造的かつローカルなものです。 これが認識されると、構築は直線的になります。

 ## アルゴリズムのチュートリアル

 この文字列は、連続する位置間の制約を定義するものとして解釈されます。 いつ$s_i = 0$、私たちはそれを強制します$a_i$そして$a_{i+1}$同じ状態に属しているかのように動作する必要があります。 いつ$s_i = 1$、必要に応じて値の変更を使用してそれらを自由に分離できることを保証します。 

構築は、現在の値を維持し、シーケンスを段階的に拡張することによって進行します。 

1. から始める$a_1 = 1$。 先行制約がないため、この任意の選択は安全です。 
2. 現在の値を維持する$cur = a_i$。 
3. ポジションごとに$i$1から$n$、 決める$a_{i+1}$に基づく$s_i$。 
4. もし$s_i = 0$、 セット$a_{i+1} = cur$。 これにより連続性が維持され、ゼロによって暗示される「中断なし」条件が満たされます。 
5. もし$s_i = 1$、割り当てます$a_{i+1} = cur + 1$。 これが 100 を超える場合は、単調増加ではなく、個別の小さな整数のみが必要であるため、1 や 2 などの小さな値に戻ります。 
6.アップデート$cur = a_{i+1}$そして続けます。 

これが機能する理由は、「一致する必要がある」遷移と「異なることが許可される」遷移を区別するだけでよいためです。 実際の数値 ID は、必要に応じて十分な個別のラベルを提供すること以外には無関係です。 

### なぜ効果があるのか

 このシーケンスは、パス グラフのノードの色付けとして見ることができます。0 のラベルが付いたエッジは同じ色を強制しますが、1 のラベルが付いたエッジは隣接する色が異なることを許可します。 私たちの構築では、すべての強制等価エッジが同じ値を前方に伝播することを保証しますが、制約が許可する場合にのみ値を変更するため、すべての許可されたエッジは以前の等価性を決して侵害しない変更を導入します。 値は常に小さな有界セットから選択され、等価制約が衝突することはないため、矛盾は発生しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n, k = map(int, input().split())
        s = input().strip()

        a = [0] * (n + 1)
        a[0] = 1
        cur = 1

        for i in range(n):
            if s[i] == '0':
                a[i + 1] = cur
            else:
                # flip between small values
                if cur == 1:
                    a[i + 1] = 2
                else:
                    a[i + 1] = 1
            cur = a[i + 1]

        print(*a)

if __name__ == "__main__":
    solve()
```実装では、構築が厳密にローカルに保たれます。 の値$k$これは、基本表現条件が、利用する組み合わせ構造を制約しないことを反映しています。 

許可されている場合に平等を破る方法のみが必要なため、1 と 2 を交互に選択するだけで十分です。 連続するゼロのセグメントの場合、値は変更されずに伝播し、定数ブロックを形成します。 1 が表示されると反転し、以前に強制された等値に影響を与えることなく隣接性の区別を保証します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = io.StringIO()
    sys.stdout = output

    T = int(sys.stdin.readline())
    for _ in range(T):
        n, k = map(int, sys.stdin.readline().split())
        s = sys.stdin.readline().strip()

        a = [0] * (n + 1)
        a[0] = 1
        cur = 1

        for i in range(n):
            if s[i] == '0':
                a[i + 1] = cur
            else:
                a[i + 1] = 2 if cur == 1 else 1
            cur = a[i + 1]

        print(*a)

    sys.stdout = sys.__stdout__
    return output.getvalue().strip()

# all ones
assert run("1\n3 5\n111\n") in ["1 2 1 2", "1 2 1 2"]

# all zeros
assert run("1\n4 10\n0000\n") == "1 1 1 1 1"

# mixed pattern
assert run("1\n5 7\n01010\n") is not None

 ## 特殊なケース

 のために$n = 1$、あるだけです$a_1, a_2$制約が 1 つあります。 アルゴリズムセット$a_1 = 1$そして割り当てます$a_2$に基づく$s_1$。 もし$s_1 = 0$、両方とも 1 のままです。$s_1 = 1$、値は 2 に反転します。これは、グローバルな調整を必要とせずに、意図したローカルな解釈と一致します。 

ゼロが長く続く場合、値は変更されずにセグメント全体に伝播します。 代入は常に前の状態から直接コピーされるため、この構造では強制等価チェーン内に不一致が生じることはありません。 

次のような交互文字列の場合$010101$、シーケンスは 2 つの値の間で振動します。 各遷移は反転が許可されているため、等価性制約に違反することはなく、禁止されたエッジを越えて伝播が誤って適用されることもありません。
