 ## 解決策
 ## 問題の理解

 黒と白のセルで構成されるバイナリ グリッドが与えられます。 各テスト ケースは、$n \times m$各セルが黒の行列 (`*`) または白 (`.`）。 タスクは、「I」と呼ばれる特別なパターンを形成するこのグリッドのサブ長方形の数を数えることです。 

部分長方形は、厳密な構造条件を満たしている場合に有効です。 高さと幅は両方とも少なくとも 3 で、幅は奇数で、中央の列は完全に黒で、上の行と下の行は両方とも完全に黒です。 長方形内の他のすべてのセルは重要ではなく、どちらの色でもかまいません。 

したがって、有効なすべての「I」は、長方形を選択し、3 つの構造上の制約をチェックすることによって決定されます。つまり、完全に黒の上部行、完全に黒の下部行、および長方形の垂直方向の中点に位置する完全に黒の中央列です。 

制約はテスト ケース全体で合計すると大きくなり、グリッドの合計サイズは最大で$2 \cdot 10^5$。 これにより、四角形ごとのチェック手法が即座に除外されます。 すべての部分四角形を反復処理することさえ不可能です。$n \times m$グリッドは$O(n^2 m^2)$、これは小さなグリッドでも限界をはるかに超えています。 

単純な試みでは、中央の列をすべて拡張してから、外側に向かって有効な上部と下部の行をスキャンしようとする可能性があります。 これはすでにリスクがあります$O(nm^2)$あるいはさらに悪いことに。 

行が完全に黒である場合、微妙なエッジケースが発生します。 たとえば、次のようなグリッドの場合:```
*****
*****
*****
```任意の列を中心とする奇数幅のサブ長方形は、垂直方向の配置に応じて、多くの有効な「I」形状を形成する可能性があります。 四角形の総当たり列挙は、制約のチェック方法に応じて過大カウントまたは過少カウントになります。これは、有効性がローカル セグメントではなく行と列全体のカバレッジに依存するためです。 

もう 1 つの注意が必要な状況は、中央の列がいくつかの隙間を除いてほぼ完全に黒である場合です。 単純なアルゴリズムでは、局所的な連続性が十分であると想定される可能性がありますが、たとえ 1 つの白いセルでも、それを中心列として含むすべての四角形が分割されます。 

主な難点は、有効性がローカルな部分行列のチェックだけではなく、グローバルな行と列のプロパティに依存することです。 

## アプローチ

 ブルートフォース ソリューションでは、すべての部分四角形が列挙されます。 各長方形について、その幅が奇数で少なくとも 3 であるかどうか、その上部と下部の行が完全に黒であるかどうか、中央の列が完全に黒であるかどうかを確認します。 単一の長方形のチェックにかかるコスト$O(\text{area})$最悪の場合、直接実行された場合、または$O(n)$行および列ごとのプレフィックス合計で前処理された場合。 前処理があっても、$O(n^2 m^2)$長方形の場合、総コストが実行不可能になります。 

重要な観察は、有効な「I」の構造が中央の列と 2 つの境界行によって完全に決定されるということです。 センターコラムを固定したら$c$、有効な長方形は、左右の境界が対称である長方形のみです。$c$、その上部と下部の行は完全な黒の制約を満たしますが、列は$c$その垂直スパンにわたって継続的に黒になります。 

これにより、列ごとに問題が数えられるようになります。$c$、行のペアは何ペアか$(r_1, r_2)$柱のセグメントが存在するように$c$それらの間は完全に黒であり、両方の行は対応する水平スパンにわたってすべて黒でカバーされます。 長方形の観点から考える代わりに、視点を反転します。中央の列にアンカーして有効な垂直セグメントを展開し、行の制約と交差します。 

これを効率的に行うために、各セルを含む最長連続黒セグメントを行ごとに事前計算し、列ごとに連続する黒ランを事前計算します。 これにより、選択した中央列について、有効性を維持しながら左右にどこまで拡張できるかを知ることができます。 

次に、各列を個別に処理します。 各列について、連続する黒いセグメントを垂直方向に処理し、2 ポインターまたはプレフィックス カウント戦略を使用してそれらを行制約と組み合わせます。 これにより、問題は 4D 列挙から列と行にわたる線形スキャンに軽減されます。

 ## アルゴリズムのチュートリアル

 有効な展開が可能な場所を記述する構造にグリッドを再構築し、各列の中心にある有効な「I」形状をすべて数えます。 

1. 各行について、連続する長さを計算します。`*`セグメント。 これにより、どのセルについても、完全に黒い行セグメント内に留まりながら、左右にどこまで拡張できるかがわかります。 有効な「I」の上部と下部の行は、選択した長方形の幅全体にわたって完全に黒でなければならないため、これは不可欠です。 
2. 各列について、最大の連続垂直セグメントを計算します。`*`。 このような各セグメントは、その列を使用する「I」の考えられるすべての中心列候補を表します。 有効な中央列は、長方形の上部と下部の間で継続的に黒のままである必要があります。 
3. 各列について、すべての垂直セグメントを収集し、各セグメントを考えられる中間列スパンのプールとして解釈します。 一定の長さのセグメント内で$L$、 がある$\frac{L(L-1)}{2}$上部と下部の行を選択できます。 
4. 垂直の黒いセグメント内の行の候補ペアごとに、中央の列から左右にどれだけ拡張できるかを決定します。 これは、行方向の黒のランによって制限されます。長方形の幅は、選択された両方の行の最小水平ラン長によって制限される必要があります。 
5. 中央の固定列の場合、有効な各行を許容される幅の間隔に変換します。 次に、一貫した幅制約を生成する行ペアの数を数えます。 これは、制約をソートし、可能な幅にわたってスイープを使用することによって処理されます。 
6. すべての列からの寄与を合計して、最終的な答えを取得します。 

### なぜ効果があるのか

 すべての有効な「I」には、固有の中央列があります。 その列が固定されると、有効性は、垂直方向の連続性 (列は黒である必要がある) と水平方向の完全性 (選択した幅全体で上部と下部の行が完全に黒である必要がある) に関する独立した制約に分解されます。 これらの制約は異なる列間で相互作用しないため、列ごとにカウントすることで、重複や省略なく解の空間が分割されます。 

このアルゴリズムでは、カウントされるすべてのペアが 1 つの有効な四角形に正確に対応し、すべての有効な四角形がその中心列を介して 1 回だけカウントされることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n, m = map(int, input().split())
        g = [input().strip() for _ in range(n)]

        # left/right consecutive stars in each row
        left = [[0]*m for _ in range(n)]
        right = [[0]*m for _ in range(n)]

        for i in range(n):
            for j in range(m):
                if g[i][j] == '*':
                    left[i][j] = left[i][j-1] + 1 if j else 1
            for j in range(m-1, -1, -1):
                if g[i][j] == '*':
                    right[i][j] = right[i][j+1] + 1 if j+1 < m else 1

        # vertical runs in each column
        ans = 0
        for j in range(m):
            i = 0
            while i < n:
                if g[i][j] != '*':
                    i += 1
                    continue
                start = i
                min_width = float('inf')

                while i < n and g[i][j] == '*':
                    min_width = min(min_width, left[i][j] + right[i][j] - 1)
                    i += 1

                length = i - start
                if length >= 3:
                    # count pairs of rows in segment
                    cnt_pairs = length * (length - 1) // 2
                    # each pair contributes based on minimal width constraint
                    ans += cnt_pairs * (min_width // 2 - 1 if min_width >= 3 else 0)

        print(ans)

if __name__ == "__main__":
    solve()
```この解決策は、各行を 2 つの配列に前処理して、黒いセグメントが各セルから左右にどのくらい伸びているかを格納することから始まります。 これにより、特定の列を中心とする行セグメントの最大水平幅を求める定数時間クエリが可能になります。 

次に、各列が個別に処理されます。 黒セルの連続した垂直セグメントをスキャンします。 各セグメント内では、任意の行のペアが潜在的な「I」の上部と下部として機能しますが、これは構造上保証されているように、列が区間全体にわたって黒のままである場合に限ります。 

このようなセグメントごとに、セグメント内の行全体の最小許容幅を計算します。 この値は、上部と下部の行を完全に黒に保ちながら、長方形の幅を制限します。 次に、行ペアの数に、この制約から得られる有効な幅の数を掛けます。 

重要な点は、幅制約が行方向の拡張制限から派生するため、ペアごとに再計算するのではなく、セグメントを単一の最小値に圧縮することです。

 ## 特殊なケース

 完全に黒いグリッドが最も密度の高いケースです。 すべての列が垂直方向の長さのセグメントを形成します$n$、行のすべてのペアが有効です。 このアルゴリズムは、各セグメントを全行幅に等しい単一の最小幅に折りたたむことでこれを処理し、ペアごとの再計算を行わずに最大の寄与を生成します。 

星が孤立した非常にまばらなグリッドは、垂直セグメントを多くの長さ 1 または長さ 2 のブロックに分割します。 有効な「I」には少なくとも 3 の高さが必要であるため、アルゴリズムは行のペアを形成する前に十分な長さのセグメントのみをカウントするため、これらのセグメントは自動的に無視されます。 

チェッカーボードのようなパターンにより、すべての列セグメントが短くなり、すべての寄与がゼロになります。 前処理では、最小高さ制約を満たすことができない垂直セグメントが存在しないことが引き続き正確に識別され、誤検知が防止されます。
