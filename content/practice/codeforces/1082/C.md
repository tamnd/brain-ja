 ## 問題の理解

 各候補者は正確に 1 つの主題に属しており、プラスまたはマイナスの数値的な貢献をもたらします。 私たちは、構造的制約の下で候補者のグループを選択するように求められます。選択後、被験者のセットも選択します。選択されたすべての被験者について、その被験者内で選択された候補者の数が同一でなければなりません。 

この制約により、ソリューションは被験者間でカウントのバランスをとることが強制されます。 選択した各主題が正確に貢献する必要があると判断した場合$k$人々の場合、選択されたすべての被験者がそのトップを貢献する必要があります$k$なぜなら、より弱い候補を追加しても合計が減るだけであり、実現可能性には役立たないからです。 

出力は、すべての有効な選択肢の可能な限り最良の総和、またはすべての有効な空でない構成の合計が負の場合はゼロになります。 

制約は次のとおりです$10^5$候補者と主題。 被験者のすべてのサブセットまたは可能なすべてを試すソリューション$k$被験者ごとの値を個別に指定すると、すぐに失敗します。 二次関数の何か$n$あるいは$n \log^2 n$定数が大きいとタイムアウトになる危険性があります。 

最もデリケートなエッジケースは、すべての候補が否定的な場合、または一部の件名のみが肯定的な接頭語を持つ場合です。 たとえば、すべての値が負の場合、空でない選択は負の合計を生成するため、正解は 0 になります。 もう 1 つの微妙なケースは、個々の被験者の最適なカウントが異なるにもかかわらず、被験者を混合すると結果が向上する場合です。 主題ごとに最適なものを個別に選択する素朴な貪欲さは失敗する可能性があります。$k$要件はすべての主題を結合します。 

## アプローチ

 強引な発想は数字を決めること$k$、次に各主題について個別にトップを選択します$k$少なくとも$k$人々。 その後、すべての科目の貢献度を合計し、最適なものを選択します。$k$。 これは正しいです。なぜなら、固定された範囲内だからです。$k$、被験者ごとの最適性は独立しています。 

ただし、それぞれの評価にはコストがかかります$k$。 全部試してみたら$k$から$1$に$n$、それぞれについて$k$件名ごとにプレフィックスの合計を再計算するには、次の費用がかかります。$O(n)$あたり$k$、につながる$O(n^2)$最悪の場合の運用。 と$10^5$、これは不可能です。 

重要な観察は、各主題を前処理してスキルのソートされたリストにすることができ、その接頭辞の合計が 1 回計算されるということです。 それから固定用に$k$、合計寄与率は、インデックスにおけるプレフィックス合計のサブジェクト全体の合計です。$k$存在する場合。 ごとに再計算する代わりに$k$視点を反転すると、各プレフィックスの合計がすべてのプレフィックスの合計に寄与します。$k$そのため、サブジェクトを反復処理し、そのプレフィックスの合計を次のインデックスが付いたグローバル配列に分散することで、寄与を蓄積できます。$k$。 

これにより、問題は、並べ替え後の線形時間内ですべての主題にわたる寄与を集計することに変換されます。

 ## アルゴリズムのチュートリアル

 1. 候補者を主題ごとにグループ化します。 これは、制約が各サブジェクト内で個別に適用されるため必要です。 
2. 各主題について、そのスキル値を降順に並べ替えます。 これにより、最初の$k$要素はその主題に最適です。 
3. 各件名の接頭辞の合計を作成します。 位置の接頭辞$i$正確に取得した場合の可能な最大の合計を表します$i+1$その主題からの候補者。 
4. 件名ごとに、その接頭辞の合計を繰り返します。 のために$i$-th プレフィックスの合計。グループ サイズのグローバル アキュムレータに追加します。$k = i+1$。 これは、サイズに寄与する主題の中からこの主題を選択することを表します$k$。 
5. グローバル配列を維持する`best[k]`選択されたすべての被験者が正確に貢献した場合の貢献の合計を表す$k$参加者。 
6. すべての被写体を処理した後、すべての被写体をスキャンします$k$そして最大の正の値を取ります。 

ステップ 4 が機能する理由は、各被験者が独立して可能な限り均一なグループ サイズに貢献しているためです。$k$、そして主題間で互換性のある貢献を合計しています。 

### なぜ効果があるのか

 グループサイズを使用して有効なソリューションを修正する$k$。 そのソリューションでは、選択された各主題がまさにその最上位に貢献します$k$そうでない場合は、より良い候補を交換すると、制約に違反することなく合計が改善されます。 したがって、すべての有効な解決策は、被験者のサブセットを選択し、それらを合計することに正確に対応します。$k$-プレフィックス値。 アルゴリズムは、そのような寄与をすべて暗黙的に列挙し、可能なすべてを評価します。$k$したがって、有効な構成が失われることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import defaultdict

n, m = map(int, input().split())

subjects = defaultdict(list)

for _ in range(n):
    s, r = map(int, input().split())
    subjects[s].append(r)

best = [0] * (n + 1)

for vals in subjects.values():
    vals.sort(reverse=True)
    pref = 0
    for i, v in enumerate(vals):
        pref += v
        k = i + 1
        if pref > 0:
            best[k] += pref

print(max(0, max(best)))
```このコードは、最初に候補を件名ごとにグループ化し、次にプレフィックスの合計が固定グループ サイズごとの最適な選択肢を表すように各グループを並べ替えます。 の`best`配列は、各主題から何人が抽出されたかによってインデックス付けされた貢献を蓄積します。 

小切手`if pref > 0`結果を改善するプレフィックスのみを含めることを保証します。 負のプレフィックスは、それを使用する構成を悪化させるだけです$k$。 これは、やはりゼロでクランプする最後の最大化ステップと一致します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import defaultdict

    n, m = map(int, input().split())
    subjects = defaultdict(list)

    for _ in range(n):
        s, r = map(int, input().split())
        subjects[s].append(r)

    best = [0] * (n + 1)

    for vals in subjects.values():
        vals.sort(reverse=True)
        pref = 0
        for i, v in enumerate(vals):
            pref += v
            k = i + 1
            if pref > 0:
                best[k] += pref

    return str(max(0, max(best)))

 ## 特殊なケース

 完全にネガティブなインスタンスはフォールバック動作を示します。 のような入力の場合`[-1, -2, -3]`主題全体で、すべての接頭辞の合計は負であるため、$k$正の値が累積され、アルゴリズムは正しくゼロを返します。`max(best)`負またはゼロです。 

単一被験者の入力は、アルゴリズムが有効な解を形成するために複数の被験者を必要としないことをテストします。 サブジェクトの最良のプレフィックス合計が直接答えとなり、1 つのサブジェクトのみが寄与するため、累積メカニズムは引き続き機能します。 

各被験者の候補が 1 つだけのまばらな分布により、アルゴリズムが可能なすべての候補を正しく処理できるようになります。$k=1$貢献。 各サブジェクトは 1 回だけ貢献します`best[1]`、それ以上ではありません$k$が設定され、すべての正の単一エントリの合計が最大値に正しく反映されます。
