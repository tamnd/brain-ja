 ## 解決策
 ## 問題の理解

 長さのバイナリ文字列が与えられます$n$, ここで、各位置は、一列に配置されたトロフィーを表します。 各トロフィーは金色または銀色です。 重要なのは、連続する黄金セグメントの構造だけです。 

このタスクは、任意の 2 つの位置 (必ずしも隣接している必要はない) の間で最大 1 回の交換を実行し、ゴールデン トロフィーのみで構成される最長の連続ブロックの長さを測定することです。 この最長のゴールデン セグメントを最大化する方法でスワップを選択したいと考えています。 

制約に関する重要な観察点は、配列のサイズです。$10^5$。 これにより、すべてのスワップを試行するソリューションは即座に除外されます。$O(n^2)$スワップの可能性があり、それぞれを線形時間で評価することさえ遅すぎます。 受け入れられる解決策はすべて、線形時間またはそれに近い時間でグローバル構造を効果的に推論する必要があります。 

いくつかのエッジケースは、素朴な貪欲な思考がなぜ失敗するのかを明らかにします。 文字列に多くの銀のトロフィーで区切られた連続する金のブロックが 1 つだけある場合、ローカル スワップの決定は有益であるように見えますが、複数のギャップにわたるマージの機会を無視する場合は最適ではない可能性があります。 たとえば、次のような文字列では`GSGGGSG`、最初のギャップの周りで貪欲にスワップすると、より長い統合ブロックを生成する 2 番目のギャップに関係するより良いスワップを見逃す可能性があります。 

もう 1 つの微妙なケースは、1 つの銀を除いてすべてのトロフィーが金である場合です。 その場合、ブロックを拡張するための外部ゴールデン リソースがないため、スワップによって最長セグメントはまったく増加しません。 

最後に、次のようなゴールデン トロフィーが非常に少ないとき。`SSSGSSS`、スワップは新しいゴールドを生成できず、既存のゴールドを再配置するだけであるため、最適なスワップでも長いセグメントを作成することはできません。 

## アプローチ

 ブルートフォースソリューションでは、すべてのポジションのペアを試します。$(i, j)$、それらの交換をシミュレートしてから、次の最長の連続ブロックを計算します。`G`。 そのブロックの計算は$O(n)$したがって、完全なアプローチは次のようになります$O(n^3)$素朴に行われた場合、または$O(n^2)$最適化により。 と$n = 10^5$、 平$O(n^2)$不可能です。 

重要な変化は、個々のスワップの観点から考えるのをやめ、代わりに構造の観点から考えることです。固定された複数の文字セットを再配置していますが、スワップは 1 つだけ許可されます。つまり、単一のスワップを「借りる」ことができます。`G`1 つの場所から戦略的なギャップに配置します。 最適な配置は常に、既存のブロックをマージまたは拡張することを中心に展開します。`G`追加で 1 つ使用します`G`他の場所から、または単一の修理`S`ほぼ連続したブロック内。 

重要な洞察は、連続するブロックに焦点を当てることです。`G`。 考えられる最良の答えは次のいずれかです。 

スワップなしの最大の既存ブロック、または 2 つの隣接するブロックをマージして形成されたブロック`G`単一のセグメントで区切られたセグメント`S`、またはスワップしてブロックを拡張します。`G`隙間を埋めるために外側から。 

これにより、問題は次の実行の分析に減ります。`G`そして何個数えるか`S`最大 1 つのスワップを使用してセグメントを「ブリッジ」するために使用できます。 スワップは 1 つだけ許可されるため、事実上 1 つのスワップを変換できます。`S`有利な構造の内部に`G`、予備がある場合に限ります`G`他の場所で。

 ## アルゴリズムのチュートリアル

 まず、文字列を同一文字の最大の連続セグメントに圧縮します。 このステップでは、問題を交互の実行に関する推論に変えます。`G`そして`S`。 

1. 文字列をスキャンし、連続するセグメントの長さを記録します。 各セグメントは次のように保存されます。`(character, length)`。 答えは方法によってのみ決まるため、これが必要です`G`セグメントは次のように区切られています`S`個々の文字ではなくブロックです。 
2. 純粋なすべての中での最大長を計算します。`G`セグメント。 これは、スワップを実行しないベースラインの答えです。 有効な答えは少なくともこの値でなければなりません。 
3. の合計数を数えます。`G`文字列全体の文字。 スワップでは新しいセグメントが作成されないため、拡張セグメントはこの合計を超えることができないため、これは重要です。`G`s.
 4. あらゆる人にとって`S`で囲まれたセグメント`G`セグメント (パターン`G + S_block + G`)、隣接する 2 つのものをマージすることを検討してください。`G`1 つのスワップを使用するセグメント。 スワップは 1 つだけ許可されるため、変換できるのは 1 つだけです`S`そのような構造の中に`G`少なくとも 1 つ余分にあれば`G`合併地域の外側。 
5. このような構成ごとに、潜在的な結合長を次のように計算します。 

左の合計`G`セグメント、右`G`セグメント、および`S`ブロックは 1 回のスワップで変換されます (可能であれば、ゴールデン トロフィー 1 個分効果的に継続性が向上します)。 
6. このようなすべてのマージ機会の最大値を追跡します。 
7. 以下の中で最良の値を返します。 

最高のシングル`G`セグメント、および考えられるすべてのマージまたは拡張セグメント。 

### なぜ効果があるのか

 重要な不変条件は、スワップでは 1 つのみが移動するということです。`G`以前に占められていた地位に`S`、同時に1つを削除します`G`別の場所から。 これは、の合計数を意味します`G`s は固定されており、改善するにはそれらをより連続した構造に再編成する必要があります。 

1 回のスワップ後の最適な構成は、ローカル領域でのみ元の構成と異なります。`S`に置き換えられます`G`そして遠くの一つ`G`が削除されます。 これは、意味のある改善は既存のものを接続または拡張するものだけであることを意味します。`G`少数の`S`境界線。 より長い範囲の再配置でも同じ単一のスワップを消費するため、既存の実行間のローカルな連続性を最大化する構成を上回るパフォーマンスを発揮することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    s = input().strip()

    total_g = s.count('G')

    # build segments
    segs = []
    i = 0
    while i < n:
        j = i
        while j < n and s[j] == s[i]:
            j += 1
        segs.append((s[i], j - i))
        i = j

    # baseline: best pure G segment
    best = 0
    for ch, ln in segs:
        if ch == 'G':
            best = max(best, ln)

    # try merging G-S-G patterns
    for i in range(1, len(segs) - 1):
        if segs[i][0] == 'S' and segs[i-1][0] == 'G' and segs[i+1][0] == 'G':
            left = segs[i-1][1]
            right = segs[i+1][1]
            s_len = segs[i][1]

            # we can potentially convert one extra S if we have spare G outside
            merged = left + right
            if total_g > merged:
                merged += 1

            best = max(best, merged)

    print(best)

if __name__ == "__main__":
    solve()
```コードは、ゴールデン トロフィーの合計を数えることから始まります。これは、答えに対する厳密な上限として機能します。 次に、文字列をセグメントに圧縮して、隣接する構造が明確になるようにします。 ベースラインの答えは最大の単一の答えです`G`元の構成のブロック。 

セグメント上のループは、2 つの金色のブロックが銀色のブロックによって分離されているパターンに焦点を当てています。 これらは、1 回のスワップでより大きな連続領域を作成できる可能性がある唯一の場所です。 条件`total_g > merged`追加のカードを引く効果をシミュレートするときにゴールドを過剰に使用しないようにします`G`他の場所から。 

この構造は、生のインデックスを推論するのではなく、セグメント境界を明示的に処理することにより、off-by-one エラーを回避します。

 ## 特殊なケース

 完全に以下から構成される文字列`G`文字はどのような交換でも安定しています。 アルゴリズムは、最大の完全な長さで答えを初期化します。`G`セグメントは文字列全体であるため、マージ ロジックによって誤って削減される可能性はありません。
