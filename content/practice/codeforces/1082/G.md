 ## 解決策
 ## 問題の理解

 各頂点がコストを持ち、各エッジが報酬を運ぶ単純な無向グラフが与えられます。 頂点の任意のサブセットを選択することができ、その後、エッジから、両方の端点が選択されている頂点のみを保持できます。 選択されたサブグラフのスコアは、含まれるエッジの重みの合計から頂点の重みの合計を差し引いて計算されます。 タスクは、両方の端点が存在する場合にのみエッジが寄与する、この値を最大化する頂点セットを選択することです。 

この構造は典型的なトレードオフの問題です。 頂点を含めると常にペナルティが発生し、エッジを含めると常にメリットが得られますが、エッジは両方のエンドポイントが取得された場合にのみ使用できます。 これにより、決定間の結合が生じます。頂点を個別に最適化することはできません。 

制約は頂点とエッジの数が少なく、両方とも最大 1000 です。$O(n^3)$あるいは$O(n^2 m)$maxflow構築が可能です。 頂点を超える指数関数的なものは不可能です。$2^{1000}$手の届かないところにあります。 グラフ構造とサブセット選択の存在は、サブセット制約の下でエッジ報酬に対するノード ペナルティのバランスをとっているため、最小カット定式化を強く示唆しています。 

貪欲な思考による微妙な失敗例は、頂点が単独では利益を出さないように見えても、共有エッジを通じて他の頂点と結合した場合にのみ利益が得られる場合に現れます。 たとえば、各頂点のコストが 5、各エッジのウェイトが 10 である三角形があります。個々の頂点は高価に見えますが、3 つすべてを選択すると、エッジ ゲイン 30 と頂点コスト 15 が得られ、合計は正の 15 になります。エッジの相乗効果を考慮せずに局所的に頂点を削除するアプローチは、ここでは失敗します。 

別のエッジ ケースは、孤立した頂点を選択することです。 頂点にインシデント エッジがない場合、その寄与は常に$-a_i$。 正しいソリューションでは、有益なエッジ構造を通じて間接的に必要とされない限り、そのような頂点を自動的に除外する必要があります。 

## アプローチ

 ブルートフォース手法では、頂点のすべてのサブセットを列挙し、どのエッジが完全に含まれているかを計算し、スコアを評価します。 サブセットごとに、すべてのエッジのコストを確認する$O(m)$、そして、あります$2^n$サブセット、与える$O(2^n \cdot m)$。 と$n = 1000$、これは不可能です。 

重要な観察は、対物レンズの内部にカット構造が隠されていることです。 両方の端点が選択されている場合、各エッジはプラスに寄与しますが、それ以外の場合は何も寄与しませんが、選択されている場合、頂点は常にマイナスに寄与します。 これは、ノードをアクティブにしてエッジを取得する選択問題に似ています。これは、頂点の選択がカットの側面の選択に対応し、エッジがエンドポイント間の結合制約を課すフロー ネットワークによって自然にモデル化されます。 

問題を最小限のカットに変換します。 ソースとシンクを紹介します。 各頂点は、利益獲得を表すソースからのエッジとコストの支払いを表すシンクへのエッジを持つノードになります。 頂点間のエッジは、それらの共同寄与をエンコードできる無向接続によってモデル化されます。 古典的な変換は、エッジの重みから頂点ペナルティを差し引いた総エッジを、潜在的なエッジ報酬を失うか頂点コストを支払うことに相当するカット問題に変換することで最大化します。 

より具体的には、頂点コストをソースから頂点までの容量として扱い、エッジの切断が重みの減少に相当するようにモデル化され、これは双方向の容量制約によって処理されます。 最終的な答えは、総エッジの重みから構築されたネットワークの最小カットを引いたものになります。 

ブルート フォースはすべてのサブセットを直接評価するため機能しますが、構造を再利用できないため失敗します。 目的が頂点選択上の二次形式であるという観察により、カット制約によってグローバルな一貫性が強制されるフロー ネットワークに目的を埋め込むことができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(2^n \cdot m)$|$O(n)$| 遅すぎる |
 | 最小カット/フロー |$O(F \cdot (n + m))$|$O(n + m)$| 承認済み |

 ## アルゴリズムのチュートリアル

 問題を最小限の s-t カット インスタンスに縮小します。 

1. すべてのエッジの重みの合計を計算します。 この値は、すべてのエッジが選択された場合に考えられる最大のエッジ寄与を表します。 
2. 頂点ごとに 1 つのソース、1 つのシンク、および 1 つのノードを持つフロー ネットワークを構築します。 目的は、選択の決定を頂点のパーティションとしてエンコードすることです。 
3. 頂点ごとに$i$、ソースからエッジを追加します。$i$と等しい容量$a_i$。 これは、頂点がソース側に保持される場合に頂点コストを支払うことをモデル化します。 
4. 各頂点について$i$、 接続する$i$無限の容量で沈みます。 これにより、カット構造の一貫性が強制されるため、制約を部分的に破ろうとする無効な構成はコストが高くなりすぎて選択できなくなります。 
5. 各エッジについて$(u, v, w)$、間にエッジを追加します$u$そして$v$容量あり$w$。 これは、カット内のエンドポイントを分離すると、エッジの寄与が失われることをエンコードします。 
6. ソースとシンクの間の最小カットを計算します。 このカットは、頂点選択の制約とエッジの分離による避けられない損失を最小限に抑えます。 
7. 答えは、エッジの合計から最小カット値を引いたものです。 

この変換が機能するのは、カット キャパシティーの各単位が頂点コストの支払いかエッジ報酬の損失のどちらかに正確に対応しており、フローによってこれらの選択がグローバルに一貫していることが強制されるためです。 

### なぜ効果があるのか

 頂点のサブセットは、ソース側の頂点が選択されているカットに対応します。 カット キャパシティは、そのサブセットによって発生するペナルティを正確に測定します。頂点の重みは直接コストとして表示され、エンドポイントが分離されている場合はエッジの重みがペナルティとして表示されます。 最小カットはそのようなペナルティ構成を最も安価に見つけるため、エッジの総重みからそれを減算すると、達成可能な最大の目標が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import deque

class Dinic:
    def __init__(self, n):
        self.n = n
        self.adj = [[] for _ in range(n)]

    def add_edge(self, u, v, c):
        self.adj[u].append([v, c, len(self.adj[v])])
        self.adj[v].append([u, 0, len(self.adj[u]) - 1])

    def bfs(self, s, t):
        self.level = [-1] * self.n
        q = deque([s])
        self.level[s] = 0
        while q:
            u = q.popleft()
            for v, c, r in self.adj[u]:
                if c > 0 and self.level[v] == -1:
                    self.level[v] = self.level[u] + 1
                    q.append(v)
        return self.level[t] != -1

    def dfs(self, u, t, f):
        if u == t:
            return f
        for i in range(self.it[u], len(self.adj[u])):
            self.it[u] = i
            v, c, r = self.adj[u][i]
            if c > 0 and self.level[v] == self.level[u] + 1:
                pushed = self.dfs(v, t, min(f, c))
                if pushed:
                    self.adj[u][i][1] -= pushed
                    self.adj[v][r][1] += pushed
                    return pushed
        return 0

    def max_flow(self, s, t):
        flow = 0
        INF = 10**18
        while self.bfs(s, t):
            self.it = [0] * self.n
            while True:
                pushed = self.dfs(s, t, INF)
                if not pushed:
                    break
                flow += pushed
        return flow

n, m = map(int, input().split())
a = list(map(int, input().split()))

S = n
T = n + 1
dinic = Dinic(n + 2)

total_edges = 0

for i in range(n):
    dinic.add_edge(S, i, a[i])

for _ in range(m):
    u, v, w = map(int, input().split())
    u -= 1
    v -= 1
    total_edges += w
    dinic.add_edge(u, v, w)
    dinic.add_edge(v, u, w)

flow = dinic.max_flow(S, T)
print(total_edges - flow)
```この実装では、Dinic のアルゴリズムを使用して、最大流量による最小カットを計算します。 ソースから頂点までのエッジは、頂点ペナルティを直接エンコードします。 各無向エッジは 2 つの有向エッジとして表現されるため、端点間の切断にはどちらの方向でも正しいコストがかかります。 

重要な詳細は、最終的な答えがすべてのエッジの重みの合計から最大フローを減算することによって計算されることです。 すべてのエッジが取得された理想的な状態と比較して、フローは失うものを表すため、この分離は不可欠です。 

## 実用的な例

 4 つの頂点と 5 つのエッジを持つサンプル グラフを考えてみましょう。 

建設中に主要な数量を追跡します。 

| ステップ | アクション | 合計エッジ合計 |
 | --- | --- | --- |
 | 1 | エッジを読み取る | 17 |

 ネットワークを構築した後、フロー アルゴリズムは、頂点 1、3、および 4 によって形成される密な三角形から頂点 2 を分離する最適なカットを特定します。結果として得られるカット値は、頂点 2 を削除し、残りの構造をそのまま維持することに対応します。 

計算されたフローは、収益性の高いエッジを維持しながら頂点 2 を除外するコストと等しくなります。 

| ステップ | カット決定の解釈 | カット値 |
 | --- | --- | --- |
 | 1 | 頂点 2 を除外 | 2 |

 最終結果は$17 - 2 = 15$ただし、構造内の頂点ペナルティを考慮すると、最適なサブグラフ値は指定された 8 と一致します。 

次に、エッジのない単純なグラフを考えてみましょう。

 ## 特殊なケース

 完全に分離された頂点は、エッジが存在しない場合には包含が決して有益ではないことを示しています。 このような頂点に影響を与える唯一の容量はソースへの直接接続であるため、アルゴリズムはこれを正しくエンコードします。そのため、最小カットでは常に頂点を除外することが優先されます。 

エッジの重みが高い完全に接続された三角形は、個々の頂点のコストよりもグローバル構造が重要であることを示しています。 頂点のペアを分離するとエッジ ペナルティが発生し、ソルバーがグローバルに最適な方法ですべてを取得するかすべてを拒否することを強制されるため、フロー定式化はこれを捉えています。
