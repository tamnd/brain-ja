 ## 解決策
 ## 問題の理解

 私たちには、Polycarp がダイヤルする頻度に関連付けられた一連の電話番号が与えられます。 番号をダイヤルするたびに、物理的に数字を押す必要がありますが、電話では最大 2 つの数字を押すことができます。$k$特殊な短縮ダイヤルボタン。 各ボタンには完全な電話番号を 1 つだけ割り当てることができ、これを使用すると、数字をまったく入力せずにその番号を入力できます。 短縮ダイヤル ボタンを押した後は、部分的な入力は必要ないため、通話料金は 0 桁の押下になります。 

短縮ダイヤル ボタンに番号が割り当てられていない場合、通話するたびにその番号のすべての桁を手動で入力する必要があります。 目標は、最大で割り当てることです。$k$各番号が使用される頻度によって重み付けされ、すべての通話にわたって数字を押す合計回数が最小限になる方法で、これらのボタンに番号を割り当てます。 

したがって、この構造は文字列のサブセットに対する選択の問題です。各文字列には重み (頻度) とコスト (長さ) があり、それをボタンに割り当てると、その寄与がゼロになります。 

制約は非常に特殊な点で厳しいです。 数値は最大 500 個で、すべての文字列の合計長も最大 500 です。ボタンの数は最大 10 個です。これにより、すべての数値にわたる指数関数的なサブセット選択が即座に排除されます。 平$2^{500}$サブセットは不可能ですし、$O(n^k)$構造がなければ大きすぎます。 全長が短いということは、文字列が集合してコンパクトなトライを形成するため、「文字列ごと」の決定から「プレフィックス構造ごと」に考え方をシフトする必要があることを示唆しています。 

微妙なエッジケースは、プレフィックスの重なりから発生します。 次のような 2 つの数字`001`そして`0012`相互作用: 一方を割り当てると、もう一方を割り当てる限界値に影響を与える可能性があります。 文字列ごとに最も高い節約額を常に選択する単純な貪欲なアプローチは、節約額が独立していないため失敗します。 もう 1 つの失敗モードは、文字列を独立して処理し、最上位を選択することです。$k$による$m_i \cdot |s_i|$、共有プレフィックスと将来の分岐構造は無視されます。 

重要な問題は、文字列を割り当てるメリットが、それを拡張する他のすべての文字列に依存することです。これは、決定空間がフラットではなく階層的であることを意味します。 

## アプローチ

 直接的なアプローチでは、あらゆる方法で目的を達成しようとします。$k$短縮ダイヤルに割り当てる番号。 各サブセットについて、合計して総コストを計算します。$m_i \cdot |s_i|$未割り当ての文字列の場合。 これは正しいですが、評価が必要なため実行できません。$\sum_{i=0}^k \binom{n}{i}$、これはまだ天文学的な大きさです$n=500$そして$k=10$。 

構造上のブレークスルーは、文字列がトライを形成するという認識から生まれます。 プレフィックスに注目すると、そのプレフィックスを短縮ダイヤル エントリとして割り当てると、そのサブツリー内のすべての番号のコストが効果的に削除されます。 ただし、任意のプレフィックスを割り当てることはできません。 実際の電話番号のみを割り当てることができます。 これでもツリー状の依存関係構造が形成されます。各ノード (文字列) はそれ自体とすべての子孫を「カバー」できます。 

これは、トライに関する動的プログラミングの定式化を示唆しています。各サブツリー内に割り当てる短縮ダイヤル スロットの数を決定し、達成可能な最大の節約量を計算します。 

各ノードで、限られた数の「無料ショートカット」をその子、場合によってはノード自体に配布することを検討します。 ノードを割り当てることによる貢献は、その文字列コストと頻度の積に等しい加重節約の合計になりますが、これはそれをショートカットとして選択した場合に限ります。 

したがって、問題をツリー DP に変換し、各ノードが最大の使用量を使用して達成可能な最大の節約を返します。$t$サブツリー内のショートカット。 子の結合はナップザックのような畳み込みになりますが、$k \le 10$、これはまだ実現可能です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 文字列のブルート フォース サブセット |$O(\binom{n}{k} \cdot n)$|$O(n)$| 遅すぎる |
 | ナップザックをかぶってDPを試す$k \le 10$|$O(N \cdot k^2)$|$O(Nk)$| 承認済み |

 ## アルゴリズムのチュートリアル

 まず、すべての電話番号に対してトライを構築します。 各ノードには、整数がそこで終わる回数と、そのノードに対応する文字列の長さが格納されます。 

1. すべての文字列からトライを構築します。 各ノードはプレフィックスを表し、終端ノードは完全な電話番号を表します。 周波数を保存します$m_i$ターミナルノードで。 
2. 各ノードについて、そのノードの基本コスト寄与を計算します。これは、そのノードにショートカットを使用しない場合の合計の数字の押下です。 これは、周波数と深さ (文字列の長さ) の積です。 
3. 各ノードで DP 関数を定義します。`dp[u][t]`は、をルートとするサブツリーで達成できる最大の節約を表します。`u`せいぜい使用`t`短縮ダイヤルの割り当て。 
4.初期化`dp[u][0] = 0`ショートカットをまったく使用しないと節約が得られないためです。 
5. ノードの場合`u`は整数に対応するため、ここでは 1 つのショートカットを使用することを検討します。 これを割り当てると、コストの全額に相当する節約が得られます。 更新します`dp[u][1]`それに応じて。 
6. ナップサック畳み込みを使用して子 DP テーブルをマージします。 子ごとに、現在のサブツリーと子サブツリーの間のショートカット数の分布を組み合わせて、最適な節約量を更新します。 
7. すべてのノードを処理した後の答えは、合計基本コストから差し引いたものになります。`dp[root][k]`。 

重要な不変条件は次のとおりです`dp[u][t]`は常に、サブツリー内のすべての数値の入力コストの達成可能な最良の削減を表します。`u`せいぜい使用`t`割り当てられたショートカット。 サブツリーはトライ構造を介さない限り互いに素であるため、ナップザックを介して子を結合すると、決定の独立性が維持されます。 

各割り当てはトライ内のノードを 1 つだけ選択することに対応し、サブツリーのマージにより限られたリソースの独立した割り当てが保証されるため、ショートカットが 2 回カウントされることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

class Node:
    __slots__ = ("ch", "end", "freq")
    def __init__(self):
        self.ch = [-1] * 10
        self.end = 0
        self.freq = 0

def add(root, s, m, nodes):
    v = root
    for c in s:
        d = ord(c) - 48
        if nodes[v].ch[d] == -1:
            nodes[v].ch[d] = len(nodes)
            nodes.append(Node())
        v = nodes[v].ch[d]
    nodes[v].end += m
    nodes[v].freq += m

def dfs(u, k, nodes, depth):
    dp = [0] + [-10**18] * k
    base_cost = nodes[u].end * depth

    for d in range(10):
        v = nodes[u].ch[d]
        if v == -1:
            continue
        child_dp, child_cost = dfs(v, k, nodes, depth + 1)

        new_dp = [-10**18] * (k + 1)
        for i in range(k + 1):
            for j in range(k + 1 - i):
                new_dp[i + j] = max(new_dp[i + j], dp[i] + child_dp[j])
        dp = new_dp

        base_cost += child_cost

    best = dp[:]
    if nodes[u].end > 0:
        gain = nodes[u].end * depth
        for i in range(k, 0, -1):
            best[i] = max(best[i], dp[i - 1] + gain)

    return best, base_cost

def solve():
    n, k = map(int, input().split())
    nodes = [Node()]
    total_cost = 0

    for _ in range(n):
        s, m = input().split()
        m = int(m)
        add(0, s, m, nodes)
        total_cost += len(s) * m

    dp, _ = dfs(0, k, nodes, 0)
    print(total_cost - max(dp))

if __name__ == "__main__":
    solve()
```trie 構造はすべての文字列をコンパクトにエンコードするため、共有プレフィックスは 1 回保存されます。 DFS は、ノードごとに、節約がどのように上方に伝播するかを計算します。 

DP 配列はナップザック方式で慎重にマージされます。 内側の二重ループにより、最大で$k$重複することなく子全体のショートカットを作成できます。 

ショートカットとしてのノードのオプションの組み込みは、子をマージした後に処理されるため、下からのすべての構造的寄与がわかった場合にのみショートカットをノードに割り当てることが保証されます。 

## 実用的な例

 次のサンプル入力を考えてみましょう。```
3 1
0001 5
001 4
01 1
```トライ構造では、すべての文字列が単一のプレフィックス チェーンに沿って配置されます。 

| ノード | 深さ | 周波数 | 基本コスト | dp[0] | dp[1] |
 | --- | --- | --- | --- | --- | --- |
 | ルート | 0 | 0 | 0 | 0 | 5 |
 | 0 | 1 | 0 | 0 | 0 | 5 |
 | 00 | 2 | 0 | 0 | 0 | 5 |
 | 000 | 3 | 0 | 0 | 0 | 5 |
 | 0001 | 4 | 5 | 20 | 0 | 20 |

 最適な割り当ては、`0001`、そのノードの完全な節約が得られます。 残りの文字列は割り当てられないため、コストは残ります。 

ここで次のことを考えてみましょう。```
2 1
12 3
123 2
```| ノード | 深さ | 基本コスト | dp[0] | dp[1] |
 | --- | --- | --- | --- | --- |
 | 12 | 2 | 6 | 0 | 6 |
 | 123 | 3 | 6 | 0 | 6 |

 割り当てる`123`厳密には割り当てよりも優れています`12`より重要な用途をカバーするためです。 サブツリーの節約が蓄積されるため、DP はこれを正しくキャプチャします。 

これらの例は、アルゴリズムがサブツリーを支配する場合には、より深いノードを自然に優先し、冗長な割り当てを回避することを示しています。

 ## 特殊なケース

 重要なケースの 1 つは、複数の番号が長いプレフィックスを共有する場合です。 のような入力の場合`0001`、`0002`、 そして`0003`の場合、頻度と深さに応じて節約できるため、すべてをカバーする最も深いノードにショートカットを割り当てることは、中間プレフィックスを割り当てるよりも価値があります。 

周波数が大きく異なる場合には、別の特殊なケースが発生します。 非常に頻繁に使用される短い数値は、長いがめったに使用されないより深い文字列を上回る可能性があるため、DP は深さの優先順位を強制するのではなく、このトレードオフを自然に許可する必要があります。 

最後のエッジケースは次のような場合です$k$はターミナルノードの数より大きいです。 未使用のスロットには単にゼロの限界ゲインが含まれるため、DP は引き続き正しく動作し、答えは考えられるすべてのノードを割り当てることになります。
