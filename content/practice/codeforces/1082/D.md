 ## 解決策
 ## 問題の理解

 頂点のセットが与えられ、頂点ごとに、最大で参加できるエッジの数が通知されます。 私たちのタスクは、これらの次数制限を尊重し、そのようなすべてのグラフの中で直径を最大化する単純な無向接続グラフを実際に構築することです。 

ここでの直径は、任意の 2 つの頂点間のすべての最短経路距離の中で最も長いものです。 したがって、次数の上限に従いながら、頂点のペアを可能な限り離すような接続された構造を構築しようとしています。 

制約は十分に小さいため、構築ベースのアプローチが期待されます。 最大 500 個の頂点を使用すると、おおよそ 2 次、または慎重に実装すればわずかに 3 次となるあらゆる解が許容されます。 除外されるのは、グラフ構成を検索したり、大きな検索空間内で繰り返し直径を計算しようとするものです。 

重要な問題は、単に有効なグラフを構築しているだけではないということです。 直径を可能な限り大きくする必要があることを明示的に示す必要があります。これは、次数制約の下でどのような構造を選択すると最短経路距離が増加するかを理解する必要があることを意味します。 

すべての頂点が次数制限 1 を持つ場合、微妙な失敗ケースが発生します。その場合、3 つ以上の頂点には接続されたグラフが存在しないため、答えは不可能になるはずです。 もう 1 つの特殊なケースは、2 つの頂点のみが 1 より大きい次数を持つ場合です。これは、グラフが分岐が制限されたツリー状構造に強制され、直径の成長が厳密に制御されるためです。 単純にスパニング ツリーを貪欲に構築する単純なアプローチでは、正確に見えるグラフを簡単に生成できますが、必ずしも最大直径のグラフが生成されるとは限りません。 

## アプローチ

 強引なアイデアは、考えられるすべての接続されたグラフを試し、次数制約が維持されるかどうかを確認し、直径を計算することです。 木に限定しても、すでに指数関数的な数の構造物が得られます。$n^{n-2}$ラベルが貼られた木。 それぞれの直径の計算は線形であるため、非常に小さい場合でもこれは完全に実行不可能です。$n$。 これが爆発的に起こる主な理由は、制約を構造的に解釈しない限り、制約がトポロジを強く制限しないことです。 

重要な観察は、グラフが可能な限り「パス状」である場合、接続されたグラフの直径が最大になるということです。 分岐すると、離れた領域間にショートカットが作成されるため、距離が短くなる傾向があります。 ただし、度が許す限り追加のエッジを追加することが許可されており、それらのエッジは最長最短パスを必ずしも減らすことなく到達可能性を高める可能性があります。 

これは、単純なパスが木の直径をできるだけ大きくするため、できるだけ長いバックボーン パスから開始するという戦略を示唆しています。 次に、高次の頂点を使用して、その直径を減らさない方法で追加のエッジを接続します。 制約$a_i$各頂点が受け入れることができるエッジの数を決定するため、より高い容量を持つ頂点が潜在的な分岐点になりますが、ショートカットが発生する危険があるため、分岐は慎重に使用する必要があります。 

より正確に再定式化するには、最初にツリーを構築する観点から考えることです。追加のエッジを追加しても、ツリー状の設定では直径を増やすことはできず、通常はショートカットを作成することによって直径を縮小するだけであるためです。 したがって、次数制約の下で直径を最大化するツリーが必要になります。 このようなツリーの最適な方法は、常に「両端の貪欲パス構築」です。最初に利用可能な次数 1 の容量を使用して長いパスを構築し、一方、端を延長するために利用できる高次の頂点を維持します。 

利用可能な次数容量を持つ頂点を現在のパスの終端に繰り返し接続します。 より高い次数の制限を持つ頂点は内部で使用することも、分岐点として使用することもできますが、分岐を最小限に抑え、チェーンの長さを最大化すると、最長の直径が達成されます。 残りのすべての頂点が使い果たされているか、エンドポイントに接続するための残りの次数の容量が不足しているために、いずれかの時点でパスをさらに延長できない場合は、停止します。 

制約の下でグラフを接続することさえできない場合、つまりエッジに参加できる頂点が 2 つ未満である場合は、すぐに NO を返します。

 ## アルゴリズムのチュートリアル

 各頂点には、その次数制限に等しい初期「バジェット」があると解釈します。 追加した各エッジは、両方のエンドポイントから 1 つのユニットを消費します。 直径を直接的に最大化できるため、できるだけ長い単一パスを構築することを目指しています。 

1. まず、正の次数容量を持つ開始頂点を選択します。 この頂点は、最終的な最長パスの 1 つの終点になります。 目的は一意性ではなく最大限の拡張であるため、有効な頂点を選択しても機能します。 
2. エンドポイントによって表される現在のパスを維持します。 最初はパスは 1 つの頂点だけなので、両方の端点が一致します。 
3. まだ次数容量が残っている 1 つのエンドポイントに新しい頂点を接続して、パスを拡張しようとします。 私たちは常に、まだ使用されておらず、まだ容量が残っている頂点を選択します。 その理由は、頂点を再利用するとサイクルまたはショートカットが作成され、直径が減少するか、増加しない可能性があるためです。 
4. 頂点をエンドポイントにアタッチするたびに、両方の頂点の次数容量をデクリメントし、エンドポイントを新しく追加された頂点に更新します。 これは単純なチェーンを貪欲に成長させます。 
5. 残りの容量を持つ未使用の頂点がいずれかのエンドポイントに接続できなくなるまで、このプロセスを続けます。 この時点で、構築された構造は制約の下での最大パスになります。 
6. すべての頂点を使用した場合、または接続を維持しながらそれ以上拡張できない場合は、結果の構造が接続され有効であるかどうかを確認します。 すべての頂点が 1 つの連結コンポーネントに含まれていない場合は、NO が出力されます。 
それ以外の場合、パス グラフの直径はその長さに等しいため、構築されたグラフの直径は単にこのパス内のエッジの数になります。 

これが機能する理由は、分岐エッジを追加しても最長最短経路が増加しないか、最短経路を短縮するショートカットが作成されるかのいずれかであるという事実に根ざしています。 パスは、同じ頂点セット上にあるすべての接続された単純なグラフの間の端点間の距離を最大化する独自の構造です。 次数制約の下では、パス構造からの逸脱により、あるペアの端点間の距離が短くなったり、チェーンをさらに延長できなかったりするため、達成可能な最長パスはまさに期待できる最大直径になります。 貪欲な拡張により、単一の単純なパスの不変条件が常に保持されます。構築されたバックボーンでは、すべての頂点の次数が最大 2 であり、拡張の対象となる頂点はエンドポイントのみです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    # each vertex has remaining degree capacity
    deg = a[:]
    
    # store unused vertices
    unused = set(range(n))
    
    edges = []
    
    # pick a starting node with positive degree
    start = max(range(n), key=lambda i: deg[i])
    if deg[start] == 0:
        print("NO")
        return
    
    unused.remove(start)
    left = right = start
    
    # greedy path extension
    while True:
        extended = False
        
        # try extend from left
        for v in list(unused):
            if deg[v] > 0 and deg[left] > 0:
                edges.append((left, v))
                deg[left] -= 1
                deg[v] -= 1
                unused.remove(v)
                left = v
                extended = True
                break
        
        if extended:
            continue
        
        # try extend from right
        for v in list(unused):
            if deg[v] > 0 and deg[right] > 0:
                edges.append((right, v))
                deg[right] -= 1
                deg[v] -= 1
                unused.remove(v)
                right = v
                extended = True
                break
        
        if not extended:
            break
    
    if unused:
        print("NO")
        return
    
    diameter = len(edges)
    print("YES", diameter)
    print(len(edges))
    for u, v in edges:
        print(u + 1, v + 1)

if __name__ == "__main__":
    solve()
```このソリューションは、未使用の頂点のセットを保持し、2 つのエンドポイントから単一のパスを成長させます。 各エッジは両方のエンドポイントからの次数容量を消費し、制約に違反しないようにします。 未使用の頂点に対する貪欲なスキャンは許容されます。$n \le 500$、したがって、$O(n^2)$拡張子の検索は十分に高速です。 

実装の微妙な詳細は、常に未使用セットのスナップショットを反復処理することです。 これにより、反復中の変更が回避されます。 もう 1 つの重要な点は、エンドポイントからのみ拡張することです。これにより、グラフが常に単純なパスのままであるという不変条件が保持されます。

 ### 例 1

 入力:```
3

```すべての頂点にパスをサポートするのに十分な容量がある状態から始めます。 最初に頂点 1 が選択されるとします。 

| ステップ | 左 | 右 | 未使用 | エッジが追加されました |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 1 | {2,3} | なし |
 | 2 | 2 | 1 | {3} | (1,2) |
 | 3 | 2 | 3 | {} | (2,3) |

 結果として得られる構造は、長さ 2 の単一のパスです。最も遠い頂点が 1 と 3 であるため、直径は 2 です。 

### 例 2

 入力:```
4
1 4 1 1
```ここで、頂点 2 は高い容量を持っていますが、他のものは制限されています。 

| ステップ | 左 | 右 | 未使用 | エッジが追加されました |
 | --- | --- | --- | --- | --- |
 | 1 | 2 | 2 | {1,3,4} | なし |
 | 2 | 1 | 2 | {3,4} | (2,1) |
 | 3 | 1 | 3 | {4} | (1,3) |
 | 4 | 1 | 4 | {} | (1,4) |

 パス 2-1-3-4 で終了し、直径 3 を与えます。頂点 2 は、構造の一端でのみハブとして機能し、最大の終点距離を維持します。 

これらのトレースは、アルゴリズムが単一のバックボーン パスを一貫して保持し、エンドポイントの距離を短縮するショートカットを決して導入しないことを示しています。

 ## 特殊なケース

 1 つの頂点のみが正の次数の容量を持つ場合、1 つのエッジ ケースが発生します。 たとえば、入力が`3 0 0`、エッジを形成できず、接続は不可能です。 アルゴリズムは、有効な開始頂点を選択できない場合、またはエンドポイントから拡張できない場合に、これを即座に検出します。 

もう 1 つのケースは、すべての頂点の次数が 1 である場合です。各頂点を内部ノードまたはエンドポイントとして 1 回だけ使用できるため、構築は引き続き成功し、パスが生成されます。 貪欲な拡張機能により、頂点が未使用のまま残されることがなくなります。 

最後のケースは、高次の頂点が存在するものの、構築プロセスから分離されている場合に発生します。 未使用の頂点を常にグローバルにスキャンするため、有効なエッジに参加できる場合、利用可能な容量のある頂点は最終的にエンドポイントの 1 つに接続され、断片化を防ぎ、可能な限り単一の接続コンポーネントが形成されるようにします。
