 ## 解決策
 ## 問題の理解

 私たちには、1 から n までのページが 1 列に並んでいる本が与えられます。 Vasya はページ x から開始して、ページ y に到達したいと考えています。 ボタンを押すたびに、現在のページが d ページずつ前方または d ページずつ後方に移動しますが、間隔 [1, n] を離れるような移動は許可されません。 

タスクは、正確にページ y に到達するために必要なボタンの最小押下回数を計算するか、それが不可能であると判断することです。 

これは折れ線グラフ上の最短経路問題のように見えますが、構造は非常に厳格です。どのページ i からでも、可能な次の状態は、範囲内にある場合、i + d と i − d だけです。 つまり、グラフは重み付けされておらず、遷移が決定的ですが、数直線が十分に大きいため、n が最大 10^9 の場合、総当たりの走査は実行できません。 

重要な観察は、実際にすべてのページを探索する必要はなく、ステップ サイズ d での x と y の算術関係のみを探索する必要があるということです。 

ページ上の単純な BFS は概念的には機能しますが、n が大きい場合はすぐに失敗します。 探索を制限したとしても、最悪の場合、到達可能なセットが依然として大きくなる可能性があります。 

不用意な推論を打ち破るエッジケースは、境界ではなく算術上の制約により移動が不可能な場合に発生します。 たとえば、d = 2 の場合、移動によりパリティが維持されるため、n に関係なく、異なるパリティのターゲットに到達することは不可能になります。 

もう 1 つの微妙なケースは、境界により迂回が強制されるため、最適なパスが最初に直接方向から外に出る必要がある場合に発生します。 たとえば、x が 1 に近く、y が大きい場合、後退することは役に立たないか、不可能であり、単純に貪欲に前進することはステップを過小評価または過大評価する可能性があります。 

## アプローチ

 ブルート フォース ソリューションでは、各ページをグラフ内のノードとしてモデル化し、x から y に到達するまで BFS を実行します。 各ノードには最大 2 つのエッジ (有効な場合は i + d および i − d) があります。 BFS はすべてのエッジのコストが 1 であるため、最短パスを保証します。 

ただし、到達可能なコンポーネントが間隔の大部分に及ぶ可能性があるため、このアプローチでは最悪のケースで O(n) 状態が調査されます。 n が 10^9 までの場合、すべてのノードに触れることさえ不可能です。 

重要な洞察は、動きが直線的であり、算術構造によって制約されるということです。 移動するたびに位置が ±d ずつ変化するため、到達可能なページはモジュラー条件を満たす必要があります。つまり、到達可能なすべての位置は x モジュロ d に一致します。 これにより、直ちに実行可能条件が得られます。y は (y − x) % d == 0 を満たす必要があります。 

この条件が当てはまる場合、問題は境界を尊重しながら必要なステップ数を決定することになります。 最適なパスは、必要に応じて、一方向に直接移動するか、境界 1 または n から跳ね返ります。 グラフはステップ サイズが固定された単純な線であるため、考慮する必要があるのは最大でも 2 つの単調戦略だけです。x から y に直接進むか、1 つの境界を経由して y に進むかです。 

これにより、問題はグラフ検索ではなく、少数の一定数の算術チェックに軽減されます。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に解決します。

1. まず、ステップ サイズ d に関して x から y に到達可能かどうかを確認します。 これは、x と y の差が d で割り切れることを確認することで行われます。 そうでない場合は、y に正確に着地できる ±d の動きのシーケンスがないため、-1 を返します。 
2. 到達可能な場合は、x と y の間の直線距離を d 単位で考慮します。 これにより、ベースラインのステップ数が |x − y| として与えられます。 / d.
 3. ただし、[1, n] の外側にステップする必要がある場合は、直接移動が不可能な場合があります。 直線の進行が各ステップで範囲内に収まるかどうかを考慮する必要があります。 
4. ダイレクト ステッピングが有効な場合、移動するたびに距離が正確に d だけ減少するため、これが最適です。 
5. 直接ステッピングが境界によってブロックされている場合、唯一の代替手段はエンドポイントでリフレクトすることです。 これにより、1 または n を介した迂回が導入され、有効なステップでどの境界に到達できるかに応じて、パスが x → 1 → y または x → n → y に効果的に変換されます。 
6. 有効な場合は両方の境界ベースのルートを計算し、最小値を取得します。 

### なぜ効果があるのか

 すべての移動は d を法とする剰余クラスを保持するため、状態空間は独立した等差数列に分割されます。 1 つの進行内で、グラフは境界が切り取られる可能性のある線形チェーンになります。 追加の振動は到達可能性を拡大することなく経路長を厳密に増加させるため、おそらく境界での 1 回の反転を除いて、最短経路は単調でなければなりません。 これにより、すべての最短パスが直接進行するか、エンドポイントでの 1 回の反射に減ります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, x, y, d = map(int, input().split())

        # If direct reach is possible
        if abs(x - y) % d == 0:
            direct = abs(x - y) // d
        else:
            direct = float('inf')

        best = direct

        # via 1
        if (y - 1) % d == 0 and (x - 1) % d == 0:
            via1 = (x - 1) // d + (y - 1) // d
            best = min(best, via1)

        # via n
        if (n - x) % d == 0 and (n - y) % d == 0:
            vian = (n - x) // d + (n - y) // d
            best = min(best, vian)

        print(best if best != float('inf') else -1)

if __name__ == "__main__":
    solve()
```この実装では、まずモジュロ d を使用して算術到達可能性をチェックします。 直接遷移は、単純に絶対差を d で割ったものです。 

2 つの境界ケースは、x から 1 または n まで d ステップで移動することに対応します。これは、両方の終点が同じ等差数列内にある場合にのみ可能です。 パスは強制されるため、コストはそのようなステップの数だけです。 

すべての有効な戦略の中から最小値を採用します。 

実現可能性チェックに合格すると、すべての有効な距離が d で割り切れることが保証されるため、整数の割り算には注意が必要です。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = []
    
    t = int(input())
    for _ in range(t):
        n, x, y, d = map(int, input().split())

        if abs(x - y) % d == 0:
            direct = abs(x - y) // d
        else:
            direct = float('inf')

        best = direct

        if (y - 1) % d == 0 and (x - 1) % d == 0:
            best = min(best, (x - 1)//d + (y - 1)//d)

        if (n - x) % d == 0 and (n - y) % d == 0:
            best = min(best, (n - x)//d + (n - y)//d)

        output.append(str(best if best != float('inf') else -1))

    return "\n".join(output)

 ## 特殊なケース

 些細だが重要なケースは、x が y と等しい場合です。 直線距離はゼロであり、任意の d で割り切れるため、アルゴリズムは正しく 0 を返します。そのため、移動は必要ありません。 

別のケースは、d が n より大きい場合です。 ここで、x が y に等しくない限り、移動は不可能です。 モジュロ条件は、恒等の場合を除くすべての遷移を正しく除去します。 

境界が支配的なケースは、x が 1 または n に近い場合に発生し、最初は 1 方向のみが可能です。 このアルゴリズムは、エンドポイントへの算術的に有効なパスのみを考慮してこれを処理し、無効な中間ステップが想定されないようにします。 

最後の微妙なケースは、複数の有効なルートが存在し、1 つは直接ルート、もう 1 つは境界経由である場合です。 最小値を採用すると、すべての有効なパスが線形演算コストに削減されるため、明示的にパスを探索しなくても最適性が保証されます。
