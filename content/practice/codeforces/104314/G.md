 ## 解決策
 ## 問題の理解

 2 つの整数で構成される状態が与えられ、ちょうど 3 つの可逆操作を使用してこのペアを変換できます。 1 つの操作では最初の値から 2 番目の値を減算し、別の操作では 2 番目の値を最初の値に加算し、3 番目の操作では 2 つの座標を交換します。 タスクは、初期ペアをターゲット ペアに変換するこれらの操作の有限シーケンスが存在するかどうかを判断し、存在する場合は有効な操作シーケンスを出力することです。 

重要な視点は、頂点が整数のペアである無限のグラフ上を歩いているということです。 各頂点には、許可された操作に対応する 3 つの出力エッジがあります。 このグラフでは 2 つのノード間の到達可能性が求められますが、状態空間は両方向に制限がないため、単純なグラフ検索には直ちに疑問が生じます。 

この制約では、開始時とターゲット時に最大 100,000 の大きさの値を許可しますが、中間値は非常に大きくなる可能性があり、有効な構築中は絶対値が 10^18 未満に留まらなければならないという厳しい制限があります。 完全な状態空間における無制限の BFS または DFS は不可能であるため、これは建設的または数論的構造が存在することを示す強力なヒントです。 

いくつかの特殊なケースは分離する価値があります。 

まず、対称性は不可能性を隠すことができます。 たとえば、(1, 0) からは (±1, 0) の形式のペアにのみ到達できるため、スワップによって非ゼロ構造が作成されないため、(0, 1) に到達しようとすることは不可能です。 

次に、両方の座標がゼロの場合、状態は吸収中です。 (0, 0) からはすべての操作で変更されないため、他のペアに到達することは不可能です。 

第三に、サインのパターンが重要です。 演算は座標の線形結合であるため、特定のパリティと行列式のような不変量が現れます。 単純な順方向シミュレーションは、実際には変換行列が整数の可逆性に関して特異である場合に、到達可能性を示唆する可能性があります。 

## アプローチ

 直接的な総当たりアプローチでは、(a, b) から BFS を試み、各ステップで 3 つの遷移すべてを調査します。 状態グラフは境界領域内で明示的かつ有限であるため、これは原理的には正しいです。 ただし、州の数はすぐに爆発的に増加します。 各次元で値を 10^6 のような適度な境界に制限した場合でも、状態空間が巨大になり、操作によって安全な BFS 境界の外に値が簡単に押し出される可能性があります。 分岐係数は 3 であるため、k ステップ後にはすでに 3^k 個の可能な状態があり、適切なターゲット サイズに達するかなり前にこのアプローチは実行不可能になります。 

重要な点は、すべての演算がベクトル (m, n) に対する線形変換であるということです。 解釈に応じて、行列式 ±1 または 0 を持つ整数上の行列としてそれらを表すことができます。 スワップは可逆的であり、大きさの構造を保持しますが、加算と減算は基本的な行演算に対応します。 これは、単純な線形変換によって生成されたグループ内で効果的に作業していることを意味します。 

重要な構造的洞察は、到達可能なペアがまさに符号までの最大公約数を保持するペアであるということです。 加算と減算の両方で gcd(m, n) が保持され、スワップでもそれが変更されないため、2 つの数値の gcd はすべての演算の下で不変です。 これにより、必要な条件がすぐに得られます。gcd(a, b) は gcd(c, d) に等しくなければなりません。 これが失敗すると、シーケンスは存在しません。 

gcd が一致したら、逆に考えることができます。 (a, b) から (c, d) を構築する代わりに、逆演算を使用して (c, d) を (a, b) に還元しようとします。 スワップ自体が逆関数であり、加算/減算が符号変更のもとで対称であるため、逆構造は等価です。 これにより、拡張ユークリッド プロセスを使用してシーケンスを構築できます。操作を追跡しながら、一方のペアをもう一方の整数線形結合として表現します。

建設的なパスは Euclid のアルゴリズムから派生します。 大きい座標から小さい座標を繰り返し減算することにより、ユークリッド縮小をシミュレートします。 座標が gcd 構造と一致すると、ターゲットの基本表現に到達するまで交換して続行できます。

 ## アルゴリズムのチュートリアル

 逆ユークリッド還元を使用して (c, d) から (a, b) に戻るパスを構築し、シーケンスを反転します。 

1. まず、両方のペアが (0, 0) であるか、または 1 つだけが (0, 0) であるかを確認します。 一方がゼロで、もう一方がゼロではない場合、すべての変換でゼロ ベクトルが保持されるため、どの演算も役に立ちません。 両方がゼロの場合、答えは空です。 
2. ソースとターゲットの両方の座標の gcd を計算します。 これらの gcd 値が異なる場合は、直ちに不可能であると結論付けます。 これは、各操作が gcd を保持するという事実からわかります。 
3. ターゲット ペア (c、d) から逆方向に作業し、逆ユークリッド ステップを繰り返し適用します。 c と d が両方ともゼロでない場合は、それらの大きさを比較します。 |c| の場合 > |d|、繰り返し減算を使用して c を d の倍数で減らします。これは、符号の一貫性に応じて演算 1 または 2 の逆に相当します。 
4. |d| の場合 > |c|、タイプ 3 として記録されたスワップ操作を実行し、続行します。 これにより、縮小の対称性が維持され、より小さい座標への進行が保証されます。 
5. ペアが gcd スケーリングまでソースと一致するまで続行します。 スワップしない限り、各ステップは厳密に最大絶対値を減らすため、プロセスは終了する必要があります。 
6. 逆の順序で操作を記録し、それを反転して順方向の順序を取得します。 スワップはスワップのままですが、加算と減算は相互に反転します。 
7. シーケンスを出力します。 

### なぜ効果があるのか

 状態変換では、最初のペアの整数線形結合によって生成された格子構造が保存されます。 到達可能なすべてのペアは、gcd(a, b) で定義された同じ格子内にあります。 Euclid のアルゴリズムは、整数行演算を使用して、同じ gcd を持つ 2 つのペアを相互に変換できることを保証します。 スワップ操作により、削減する座標を常に選択できるようになり、1 つのコンポーネントが小さくてもゼロでない場合の停滞を防ぐことができます。 各縮小ステップは少なくとも 1 つの座標の大きさを厳密に減少させるため、無限ループは不可能であり、終了が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def gcd(x, y):
    while y:
        x, y = y, x % y
    return abs(x)

def build(a, b, c, d):
    # handle trivial cases
    if (a, b) == (c, d):
        return ""
    if (a == 0 and b == 0) or (c == 0 and d == 0):
        return None

    if gcd(a, b) != gcd(c, d):
        return None

    ops = []
    x, y = c, d

    # reverse-like reduction toward (a, b)
    # we simulate Euclid-style descent
    while (x, y) != (a, b):
        if abs(x) < abs(y):
            x, y = y, x
            ops.append('3')
            continue

        if y == 0:
            break

        # try to reduce x by y
        k = (x - a) // y if y != 0 else 0

        if k == 0:
            # single step reduction
            x = x - y
            ops.append('1')
        else:
            # multiple reductions compressed
            x = x - k * y
            ops.extend('1' * abs(k))

        if len(ops) > 10**6:
            return None

    if (x, y) != (a, b):
        return None

    return ''.join(reversed(ops))

def solve():
    a, b = map(int, input().split())
    c, d = map(int, input().split())

    res = build(a, b, c, d)
    if res is None:
        print("IMPOSSIBLE")
    else:
        print(res)

if __name__ == "__main__":
    solve()
```どの操作もゼロ座標構造を作成または破壊できないため、実装はゼロ ベクトルが出現する縮退ケースを処理することから始まります。 gcd チェックは、到達可能なすべての状態が同じ整数格子内に存在する必要があるという不変条件を強制します。 

メインの構築ループは、ターゲット ペアからの後方ユークリッド降下をシミュレートしようとします。 1 つの座標が絶対値で優勢である場合、スワップが適用されて、常に大きい方の成分で削減が行われるようになります。 減算ステップは操作 1 に直接対応し、反復された減算は効率化のために複数の文字に圧縮されます。 

ターゲットからソースへのパスを構築しますが、順変換シーケンスを出力する必要があるため、最後の反転が必要です。 長さガードにより、10^6 の演算制限が確実に遵守されます。

 ## 特殊なケース

 リダクション中に 1 つの座標がゼロになる場合、微妙なケースが発生します。 たとえば、(6, 2) から開始して減算を繰り返すと (0, 2) になります。 現時点では、これ以上減算すると停止してしまうため、進行状況を回復できるのはスワップのみです。 アルゴリズムは、 |x| が発生するたびに即座に交換することでこれを処理します。 < |y| により、ゼロから最初の座標状態に陥ることがなくなります。 

もう 1 つのケースは、値が符号内で振動する場合です。 たとえば、(5, -3) は減算中に符号を反転する可能性があります。 演算は線形であるため、符号の変更は gcd の不変性に影響を与えず、リダクションは依然として正規形式に収束します。 このアルゴリズムは、符号の単調性に依存せず、各有効ユークリッド ステップ後の振幅の減少のみに依存します。
