 ## 解決策
 ## 問題の理解

 私たちは、時針と分針が 1 分ごとにジャンプするのではなく、スムーズに動く連続アナログ時計を見ています。 分針は 60 分で一周し、時針は 12 時間で一周します。 開始時点では、時計は時と分のペアで指定された特定の時刻にあり、秒はゼロに固定されています。これは、両方の針が標準的な時計の形状に従って正確に配置されていることを意味します。 

この開始構成から、将来、両手の間の小さい角度が正確に指定された値になる最も早い瞬間を見つけるように求められます。$k$。 答えは時計の時間として表す必要があり、計算された時間を最も近い秒に切り捨てて、時、分、秒全体を報告する必要があります。 

重要な問題は、時間と手の角度との関係が連続的かつ周期的であることです。 両方の針は一定の角速度で動きますが、速度は異なるため、相対角度は 360 度を法として時間とともに線形に変化します。 これにより、問題は基本的にモジュラー制約の下で線形方程式を解き、最小の正の解を選択することになります。 

制約は十分小さいため、数秒または数分にわたる個別の検索は必要ありません。 全サイクルまでのすべての秒にわたる完全なブルート フォース シミュレーションは 43200 秒程度になりますが、これは簡単なことではありません。 ただし、指定された時間から目標角度に達するまで秒ごとにステップを進める単純なシミュレーションでは、角度が周期的であり、サイクルごとに複数回到達する可能性があるという事実を見落とす危険性があり、浮動小数点比較を使用して実装された場合には精度の問題も発生する危険性があります。 正しいアプローチでは、連続運動について代数的に推論する必要があります。 

現在の構成に必要な角度がすでにある場合、微妙なエッジ ケースが発生します。 「最も近い将来の瞬間」を厳密に解釈する場合、現在の瞬間が有効であるかどうかを確認する必要があります。 この問題では、条件が満たされる場合、開始点に対する相対的な時間ゼロが許可されるため、これは可能です。 

必要な角度が 0 度または 180 度の場合、別の特殊なケースが発生します。 これらは、サイクルごとに複数回発生する位置合わせと反対方向に対応しており、不注意なモジュラー演算により、開始時間以降の最も早い発生を誤ってスキップする可能性があります。 

## アプローチ

 ブルートフォース解釈では、時針と分針の位置を更新し、それらの角度をチェックしながら、時間を少しずつ進めるシミュレーションを行います。 毎秒、分針の角度を次のように計算できます。$6m + 0.1s$度および時針の角度は次のようになります$30h + 0.5m + \frac{0.5}{60}s$。 次に、それらの差を計算し、次の小さい方に正規化します。$x$そして$360 - x$。 これは時計の物理モデルに直接従うため、これは正しいです。 

問題は、最初の有効な一致まで毎秒チェックするには、最悪の場合、12 時間サイクル全体 (約 43,200 秒) のスキャンが必要になる可能性があることです。 これは大きくはありませんが、丸め誤差を避けるために精度を上げようとすると、実際の非効率が現れ、不必要な複雑さが生じます。 さらに重要なのは、力ずくで構造を曖昧にしてしまうことです。角度の差は時間の経過とともに線形に変化するため、検索ではなく線形合同を効果的に解いていることになります。 

重要な観察は、両手の間の角度が時間の線形関数であるということです。 スタートから時間を秒単位で計測すると、分針は次のように動きます。$6/60 = 0.1$度/秒、時針は$0.5/60 \approx 1/120$度/秒。 相対速度は一定であるため、角度の差も時間的に線形になります。 これは、絶対最小角度が以下に等しいときの方程式を書けることを意味します。$k$、それを 360 を法とする線形方程式を解くことに還元し、最小の非負の解を見つけます。 

これにより、時間の経過に伴うシミュレーションから、モジュラー ラップアラウンドを使用して単純な等差数列を解き、最小の有効な解を選択するという問題が軽減されます。

 ## アルゴリズムのチュートリアル

 最初の瞬間からすべての角度を度単位で、時間を秒単位で測定します。 

1. 初期クロック時間を絶対角度構成に変換します。 長針の始まりは$6m$度、時針は から始まります$30h + 0.5m$度。 これにより、両手間の初期の相対角度が確立されます。 
2. 初期の方向角の差を計算します。$d_0 = |hour - minute|$、次のように正規化されます。$[0, 360)$。 この問題では手の間の最小角度が使用されているため、これも次のように解釈します。$\min(d_0, 360 - d_0)$。 
3. 相対角度が時間の経過とともにどのように変化するかを表現します。 分針は 1 秒あたり 0.1 度で動き、時針は 1 秒あたり 1/120 度で動きます。 相対速度は$0.1 - 1/120 = 11/120$分から時を引いた単位での 1 秒あたりの度。 
4. 進化する差異を一次関数としてモデル化します。$d(t) = d_0 + \frac{11}{120}t \mod 360$、 どこ$t$秒単位です。 
5. できるだけ早くしたい$t \ge 0$最小角度が次と等しくなるように$k$。 これは 2 つのケースに分かれます。有向差が等しいか、$k$、または等しい$360 - k$。 各場合は線形合同になります。 
6. 各方程式を解きます。$$d_0 + \frac{11}{120}t \equiv k \pmod{360}$$そして$$d_0 + \frac{11}{120}t \equiv 360 - k \pmod{360}$$120 を掛けて端数を削除し、整数演算を行います。 
7. 各方程式について、最小の非負の解を計算します。$t$。 すべての有効な解決策の中で、最小のものを選択してください$t$。 
8. 選択した秒数を時、分、秒に変換します。秒の小数点以下は切り捨てられます。 

### なぜ効果があるのか

 重要な不変条件は、針間の相対角度が 360 度を法とする時間の一次関数であるということです。 両方の針は一定の角速度で回転するため、その差は途切れることなく発展します。 すべての有効な構成は、2 つの線形合同式のうちの 1 つの解に正確に対応し、最初に条件が満たされたとき、それらの合同式の中で最小の非負の解が得られます。 これにより、角度関数がすべての可能な値を定期的にカバーするため完全性が保証され、この線形展開を超える他の運動パターンが存在しないため正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    h, m, k = map(int, input().split())

    # angles in 120-based integer system to avoid fractions:
    # 1 second => hour hand moves 1/120 deg, minute hand moves 1/10 deg
    # scale by 120: degrees * 120 becomes integer
    hour = (30 * h + 0.5 * m) * 120
    minute = (6 * m) * 120

    # simplify scaled values:
    hour = int(round(hour))
    minute = int(round(minute))

    # relative speed: minute - hour = (6 - 0.5/1) deg/min? better use seconds form:
    # in scaled system per second:
    # minute: 6 deg/min = 0.1 deg/sec -> *120 = 12
    # hour: 0.5 deg/min = 1/120 deg/sec -> *120 = 1
    # so relative speed = 11 per second
    speed = 11
    MOD = 360 * 120

    start = (hour - minute) % MOD

    target1 = (k * 120) % MOD
    target2 = ((360 - k) * 120) % MOD

    def solve_eq(target):
        diff = (target - start) % MOD
        # solve speed * t ≡ diff (mod MOD)
        # 11 t ≡ diff (mod 43200)
        g = 11
        mod = MOD

        # modular inverse of 11 mod 43200/g
        mod //= g
        diff //= g
        speed_reduced = 11 // g

        inv = pow(speed_reduced, -1, mod)
        return (diff * inv) % mod

    t1 = solve_eq(target1)
    t2 = solve_eq(target2)

    t = min(t1, t2)

    total_seconds = t // 120  # convert back from scaled system

    h = (h + total_seconds // 3600) % 12
    total_seconds %= 3600
    m = total_seconds // 60
    s = total_seconds % 60

    print(h, m, s)

if __name__ == "__main__":
    solve()
```このソリューションでは、すべての角度を 120 倍にスケールすることで浮動小数点演算を完全に回避し、変換されたシステムで両方の手の速度を整数にします。 これにより、角度を比較する際の精度の問題が解消されます。 

中心となる計算は、時間が未知数であるモジュラー線形方程式を解くことに帰着します。 相対速度と係数は既知の構造を共有し、gcd で除算することで可解性が保証されるため、逆モジュラーの使用は安全です。 

最後に、計算された時間を標準の時、分、秒に変換し、必要に応じて最終ステップで切り捨てを注意深く維持します。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、開始時の構成がすでに必要な角度を満たしている場合です。 k = 0 の 3 0 0 のような入力の場合、最初の差は 0 であるため、正解は現在時刻になります。 合同式の 1 つが t = 0 をもたらし、それが最小値に含まれるため、アルゴリズムはこれを処理します。 

もう 1 つのケースは k = 180 で、両手が反対になります。 この構成は、全サイクルごとに 2 回発生します。 このアルゴリズムは k と 360 - k に対応する両方の合同式を解くため、両方とも同じ値に崩壊します。 モジュラー ソルバーは最小の非負の解を返し、正確さを保証します。 

最後の微妙なケースは、スケール表現から標準時間に戻す際の秒の丸めに関する精度です。 最終ステップでのみ切り捨てられるため、小数点以下の剰余は自然に破棄され、最も近い秒に切り捨てる要件と一致します。
