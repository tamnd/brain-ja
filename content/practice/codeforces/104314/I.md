 ## 解決策
 ## 問題の理解

 私たちに与えられた連鎖は、$N$番号の付いたリングが一列に並んでいます。 旅行者は、1 日あたり正確に 1 つの指輪を支払うことができるようにしたいと考えています。$N$ただし、事前にチェーンを別々の使用可能な部分に切断することは許可されています。 「カット」とは、チェーンからリングを取り外すことを意味し、隣接関係が壊れ、チェーンが複数のセグメントに分割される可能性がありますが、取り外されたリング自体は独立した部分になります。 

毎日、旅行者はすでに分割された部分のいくつかの組み合わせを渡すことができ、また、所有者が決して過小な支払いを受けない限り、以前に与えられた部分を取り戻すことで以前の支払いを再利用することもできます。 

タスクは、この柔軟な毎日の交換が常に可能になるように、できるだけ少ないカット操作を選択し、どのリング インデックスをカットするかを指定することです。$N$日々。 

制約により許可されるのは、$N$まで$10^9$。 これにより、日々のプロセスのシミュレーションや、すべてのポジションにわたる明示的なチェーン状態の維持に依存する構築は即座に排除されます。 有効な解決策は、次のバイナリ構造のみに依存する必要があります。$N$というのは、これが対数時間での構築を導くのに十分コンパクトな唯一の表現だからです。 

素朴な考えは、考えられるすべてのカット構成をシミュレートし、必要な毎日の支払いをすべて構築できるかどうかを確認することです。 カット位置のサブセットに限定しても、これは次のことにつながります。$2^N$最悪の解釈の可能性もあるが、それはたとえ$N = 40$、ましてや$10^9$。 

より巧妙で単純なアプローチは、プレフィックスを利用可能なセグメント長の合計として表現できない場合は常に、貪欲にカットを試みることです。 これは、チェーン構造が局所的に独立していないため、初期の貪欲な選択により、後のセグメントの組み合わせを形成する能力がブロックされる可能性があるため、問題が発生します。 

## アプローチ

 重要な観察点は、支払いプロセスは物理的なチェーン自体に関するものではなく、時間の経過とともに構成できるセグメント サイズのセットに関するものであるということです。 各カットはチェーンを再利用可能なピースに変換し、これらのピースはコイン システムの額面のように動作します。1 から 2 までのすべての整数値を表現できるようにしたいと考えています。$N$利用可能なピースを使用し、許可された「ギブ・アンド・テイクバック」メカニズムを通じてピースを一時的に再組み立てして再利用できるというさらなる柔軟性を備えています。 

この柔軟性により、問題はセグメント長の最小セットを構築することになり、すべての値が次の値に達するようになります。$N$が代表的です。 これを実現する最適な構造は、2 のべき乗と密接に関係しています。 2 の累乗は特別です。なぜなら、バイナリ表現を使用して任意の整数を増分的に構築でき、「再利用」操作により、数日間にわたってバイナリのキャリー動作を効果的にシミュレートできるからです。 

構造は表現に帰着します$N$バイナリで作成し、その構造を使用してどこでカットを行うかを決定し、結果として得られるセグメント システムがバイナリ ベースのように動作するようにします。 各有効ビットは 1 つの独立した構造単位に寄与し、そのような単位の数によって必要なカットの数が決まります。 

ブルートフォースアプローチでは、カット位置のサブセットを試し、1 から 2 までのすべての値の到達可能性を検証します。$N$、これには指数関数的な時間がかかります。 バイナリ構造により、これがビット全体の線形スキャンに削減されます。

 ## アルゴリズムのチュートリアル

 のバイナリ表現から直接ソリューションを構築します。$N+1$これは、チェーンを 2 のべき乗の構造セグメントにどのように分割する必要があるかをキャプチャします。 

1. のバイナリ表現を計算します。$N+1$。 このシフトは、間隔を完全にカバーする必要な分解を調整するため重要です。$[1, N]$完全なバイナリ構造を使用します。 
2. この表現に現れる 2 の累乗をすべて特定します。 設定された各ビットは、最終的なチェーン システムが独立してサポートできなければならない構造ブロック サイズに対応します。 
3. 最大のものを除く特定された 2 の累乗ごとに、チェーン内の対応する境界位置にカットを配置します。 境界位置は、カット間のセグメントがバイナリ分解によって暗示される必要なブロック サイズと一致するように選択されます。 
4. すべてのカット位置を収集します。 これらのインデックスは、残りのチェーンがサイズが 2 進累乗に一致する再利用可能なセグメントに自然に分割されるように、削除する必要があるリングです。 
5. カット数と選択したインデックスを出力します。 

### なぜ効果があるのか

 この構造により、残りの構造がバイナリ分解システムのように動作することが保証されます。 カット間に作成される各セグメントは、2 のべき乗のサイズのブロックに対応し、これらのブロックを異なるサブセットに組み合わせて、必要な日次支払いを形成できます。 バイナリ表現では、次の値までのすべての値が保証されます。$N$はこれらのブロック サイズの合計として表すことができ、「ギブバック」操作により、システムは追加のカットなしで再構成をシミュレートできます。 カットの数は、形成に必要な独立したバイナリ コンポーネントの数に正確に対応します。$N$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    N = int(input().strip())
    x = N + 1

    bits = []
    i = 0
    while (1 << i) <= x:
        if x & (1 << i):
            bits.append(i)
        i += 1

    # construct cut positions from all but the largest bit
    cuts = []
    for b in bits[:-1]:
        cuts.append((1 << b) - 1)

    print(len(cuts))
    if cuts:
        print(*cuts)

if __name__ == "__main__":
    solve()
```解決策はまず問題を次のように移行します。$N+1$これにより、バイナリ構造が素の 2 のべき乗成分にきれいに分離できるようになります。 次に、設定されたすべてのビットを抽出し、それぞれをフォームの境界位置に変換します。$2^b - 1$、サイズのブロックの最後のリングに対応します。$2^b$。 最大のブロックはバックボーン セグメントとして機能するためそのまま残され、すべての小さなブロックは必要なカットを定義します。 

主な微妙な点は、カットが生のビット位置からではなく、ブロック境界から派生することです。 このオフバイワン変換は、バイナリ構造を実際のリング インデックスにマッピングするものです。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque
    output = []

    N = int(sys.stdin.readline().strip())
    x = N + 1

    i = 0

 ## 特殊なケース

 のために$N = 1$、チェーンはすでに単一のリングで構成されているため、切断する必要はなく、システムは簡単に 1 日の支払いをサポートします。 

のために$N$2 の累乗であるなど、$16$、のバイナリ表現$N+1$最小限の構造境界のみが導入されたクリーンな構造を生成します。 先頭のブロックを越える小さな独立したバイナリ コンポーネントがないため、アルゴリズムは不必要なカットを自然に回避します。 

のために$N$2 のべき乗のすぐ下、たとえば$7$または$15$、複数のバイナリ コンポーネントが存在しますが、これらは非常に効率的なセグメンテーション パターンに崩壊し、戦略的に配置された少数のカットだけですべての毎日の支払いを完全に表現できるようになります。
