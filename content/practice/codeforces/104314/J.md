 ## 解決策
 ## 問題の理解

 2 つの非負の整数が与えられます。`a`そして`n`。 プログラムは値から始まります`b = 0`そして同じ更新ステップを正確に適用します`n`回:`b := (b - a) & a`ここでは、減算とビットごとの AND が 2 の補数演算を使用して 64 ビット整数に対して実行されます。 タスクは、の最終値を決定することです。`b`結局`n`繰り返しを行うが、ループのシミュレーションは行わない`n`と同じ大きさにすることができます$10^{18}$。 

入力サイズにより、直接のシミュレーションが直ちに除外されます。 線形反復`n`まで必要になります$10^{18}$これは実行可能な制限時間をはるかに超えています。 平$10^7$1 秒あたりの操作数では依然としてこれは不可能です。 

主な問題点は、トランジションが算術減算とビット単位のマスキングを混合していることです。`b`は明らかに単調または線形ではありません。 素朴な試みではステップバイステップで計算されますが、メモ化のような小さな最適化さえも不可能です。`a`大きくすることもでき、状態空間は 64 ビットです。 

微妙なエッジ ケースは、64 ビット演算の境界でのビット動作から発生します。 たとえば、次の場合`a = 0`、その後、再発は次のようになります`b = 0`永遠に、関係なく`n`。 もし`n = 0`、イニシャルを返さなければなりません`b = 0`トランジションを適用せずに。 もう 1 つの重要なケースは次のような場合です。`a`という形です`2^k - 1`、すべての下位ビットが設定されます。これは、AND 演算が算術増加ではなく、下位ビットのダイナミクスをマスクするように動作するためです。 

重要な観察は、64 ビット空間にもかかわらず、変換が高度に構造化されており、すぐにサイクルに達するということです。 

## アプローチ

 ブルートフォースのアイデアは簡単です。書かれたとおりにループをシミュレートします。 各反復で再計算が行われます`b = (b - a) & a`。 これは文字通りプログラムに従っているので、これは正しいです。 ただし、必要なのは`n`したがって、最悪の場合の複雑さは次のようになります。$O(n)$、次の場合は不可能です`n`できる$10^{18}$。 

重要な洞察は、変換を有限状態空間上の関数として扱うことです。 以来`b`は 64 ビット整数です。最大で$2^{64}$したがって、シーケンスは最終的には周期的になる必要があります。 さらに重要なのは、操作が決定的であり、初期値から非常に小さなサイクルにすぐに崩壊することです。`b = 0`。 

から始まるシーケンスを計算します`0`以前に確認された値に達するか、サイクルが検出されるまで。 サイクルが見つかったら、それ以上シミュレーションする必要はありません。 代わりに、削減します`n`プレピリオド後のサイクル長を法として、サイクルに直接インデックスを付けます。 

これが機能するのは、サイクルに入った後のすべての将来の状態は、完全な履歴ではなく、サイクル内の位置のみに依存するためです。

 ## アルゴリズムのチュートリアル

 プロセスを関数を繰り返し適用するものと見なします`f(b) = (b - a) & a`から始まる`b = 0`。 

1. から始める`b = 0`そして、以前に確認された値を記録するための空のマップまたはリスト。 また、各値が表示されるステップ インデックスも追跡します。 
2. 次の状態を繰り返し計算する`b_next = (b - a) & a`。 これは、問題によって定義された正確な遷移です。 
3. もし`b_next`以前にも見られたため、サイクルが検出されました。 最初の出現から現在のステップまでのセグメントは、繰り返しループを形成します。 その前の接頭辞は過渡フェーズです。 
4. サイクルが検出されたら、過渡部分の長さとサイクル長を計算します。 
5.減らす`n`：

もし`n`が過渡長より小さい場合、答えはそのまま次のようになります。`n`プレフィックスの - 番目の要素。 

それ以外の場合は、過渡長を減算し、モジュロサイクル長を取得して、ループ内の最終位置を見つけます。 
6. 対応する格納値を返します。 

サイクル検出で十分な理由は、変換が 64 ビット状態の有限セットに対する決定論的なマッピングであるためです。 状態が繰り返されると、関数には現在のメモリを超えるメモリがないため、その時点からのシーケンスが正確に繰り返される必要があります。`b`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    a = int(input().strip())
    n = int(input().strip())

    def f(x):
        return (x - a) & a

    seen = {}
    seq = []

    b = 0
    step = 0

    while b not in seen:
        seen[b] = step
        seq.append(b)
        if step == n:
            print(b)
            return
        b = f(b)
        step += 1

    start = seen[b]
    cycle = seq[start:]
    cycle_len = len(cycle)

    if n < len(seq):
        print(seq[n])
        return

    n -= start
    n %= cycle_len
    print(cycle[n])

solve()
```この関数は次の軌道を構築します。`b`繰り返しまで。 の`seen`ディクショナリには最初の出現インデックスが格納されますが、`seq`完全な順序が保存されます。 サイクルが見つかると、シーケンスをプレフィックスと繰り返しループに分割します。 

早めの退場`if step == n`不必要なサイクル処理を回避します。`n`は非反復接頭辞の内側にあります。

## 特殊なケース

 いつ`a = 0`、関数は次のようになります`b = (b - 0) & 0`したがって、すべての状態は次のように崩壊します。`0`。 最初に計算された遷移が開始状態と等しいため、アルゴリズムはこれを自然に処理し、サイクルは単一の要素として直ちに検出されます。 

いつ`n = 0`、ループには決して入りません。 アルゴリズムは明示的にチェックします`step == n`初期状態なので戻ります`0`直接、初期値と一致します`b`。 

小さなシーケンスなど、シーケンスがすぐに 2 サイクルに入る場合`a`、検出メカニズムは最初の繰り返しを記録し、サイクルを分離します。`[x, y]`。 モジュロインデックス作成ステップにより、`n`値はこの 2 要素ループに正しく変換され、追加のシミュレーションなしで正しい交互動作が生成されます。
