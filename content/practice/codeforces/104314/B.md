 ## 解決策
 ## 問題の理解

 空の位置と固定の比較記号が交互に並ぶ行が与えられます。 がある$N+1$1 から 2 までの異なる数字を入力する必要がある位置$N+1$、隣接する 2 つの位置ごとに、「<」または「>」のいずれかの制約が 1 つだけあり、その隣に配置された 2 つの数値によって満たされる必要があります。 

タスクは、サイズの順列を割り当てることができるかどうかを判断することです。$N+1$あらゆる不等式が成り立つように、これらの位置に配置します。 可能であれば、有効な順列を 1 つ出力する必要があります。 それ以外の場合は -1 を出力します。 

制約により許可されるのは、$N$まで$10^5$したがって、どのソリューションも線形または線形に近い時間で実行する必要があります。 順列をバックトラックすることを伴うものはすべて直ちに不可能です。$O(N!)$または$O(2^N)$アプローチが爆発する。 平$O(N^2)$建設が遅すぎるため、$10^5$二乗はすでに限界をはるかに超えています。 

貪欲な構築が将来の制約を考慮せずに極小値または極大値を選択する場合、微妙な失敗例が発生します。 たとえば、「<」が表示されるたびに常に可能な限り最小の数値を配置しようとすると、中間に以前は大きな値が必要だった後の「>」チェーンがブロックされる可能性があります。 

もう 1 つのエッジ ケースは、「< > < > < …」のような長く交互するチェーンです。 多くの素朴な貪欲戦略は、たとえ有効な解決策が常に存在するとしても、値を山と谷に正しく分散しないため、ここで失敗します。 

## アプローチ

 強引な解釈では、1 から 2 までの数値のすべての順列を試します。$N+1$そしてそれぞれが不等式を満たすかどうかを確認します。 これは妥当性の定義を直接テストするため正しいですが、生成する必要があります。$(N+1)!$順列、さらに 1 つの順列のチェックにもコストがかかります$O(N)$、全体の複雑さは天文学的に大きくなります。 

問題の構造は実際には、絶対値ではなく相対的な順序によって決まります。 各不等号の連鎖により、セグメントの増加と減少のパターンが強制されます。 連続する「<」記号のセグメントを見ると、数値はそのセグメントに沿って厳密に増加する必要があります。 同様に、連続した「>」記号のセグメントでは、厳密に減少する構造が強制されます。 重要な観察は、どの位置が「谷」のように動作し、どの位置が「山」のように動作するかを決定することによって、順列を段階的に構築できるということです。 

数値を直接割り当てるのではなく、視点を逆転させて、1 から 2 までの数値を挿入することを考えます。$N+1$すべての制約が有効なままになるように、昇順で各数値をどこに配置するかを決定します。 このような不等号の連鎖を満たす古典的な方法は、連続する「>」記号のブロックを、そのブロックに減少する値を割り当てることによって処理することですが、これには必然的にスタックのような順序の逆転が必要になります。 

シーケンスをスキャンし、不等号が「>」である最大のセグメントに分割します。 このようなセグメントに遭遇すると、順列内の対応するブロックが逆の順序で割り当てられる必要があることがわかります。 これにより、通常はインデックスを追加しますが、必要に応じてセグメントを反転する構造になります。 

ブルート フォースは、正確性を明示的にテストするため機能しますが、階乗増加により失敗します。 構造が単調な連続に分解されるという観察により、線形時間で有効な順列を構築することができます。

 | 最適 |$O(N)$|$O(N)$| 承認済み |

 ## アルゴリズムのチュートリアル

 不等号文字列に対する貪欲スキャンを使用して答えを作成し、位置を反転する必要があるブロックにグループ化します。 

1. 空のリストを初期化する`res`それが最終的な置換を保持します。 
2. 0 から 0 までの位置を繰り返します。$N$、各位置を数値間の境界として扱います。 
3. 不等式の現在のセグメントに「>」のみが含まれる位置に遭遇すると、インデックスを一時バッファーに蓄積します。 
4. 「<」を押すか終わりに達するとすぐにバッファをフラッシュします。 フラッシュとは、収集されたインデックスを逆の順序で追加することを意味します。`res`。 
5. すべての位置が処理されるまでこのプロセスを継続し、すべての最大の「>」チェーンが 1 回だけ反転されるようにします。 

「>」セグメントのみで反転する理由は、「>」のチェーンによって値が左から右に強制的に減少するためです。 自然に増加するインデックスを割り当てると制約に違反してしまうため、順序をローカルで反転します。 

### なぜ効果があるのか

 連続する「>」制約の各最大セグメントは、そのセグメントに配置された値に厳密な降順を適用します。 インデックスを順方向に収集し、出力時にそれらを逆にすることにより、より大きな数値がそのセグメントの前半に表示され、より小さな数値が後半に表示され、すべての不等式が満たされます。 セグメント間では、遷移点は「<」に正確に対応し、ブロック境界全体で自然な増加順序が維持されます。 これにより、すべての制約が独立して満たされ、グローバルな置換が有効なままであることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    s = input().split()
    
    res = []
    i = 0
    
    while i <= n:
        j = i
        while j < n and s[j] == '>':
            j += 1
        
        # we have a segment [i, j]
        # for '>' segment, we reverse
        for k in range(j, i - 1, -1):
            res.append(k + 1)
        
        i = j + 1
    
    print(*res)

if __name__ == "__main__":
    solve()
```このコードは、連続する「>」セグメントをスキャンし、そのような各ブロック内のインデックスを反転するという考えに従っています。 表現`k + 1`ゼロから始まる位置を必要な順列値に変換します。 

重要な実装の詳細は、境界を正しく処理することです。「>」セグメントを終了するときは、両方のエンドポイントを逆の順序で含める必要があります。 通常、ここでオフバイワンエラーが発生します。特に、セグメントが次で終了するかどうかを決定する際に発生します。`j`または`j-1`。

 ## 特殊なケース

 特殊なケースの 1 つは、「> > > >」のような完全に減少する接頭辞です。 このアルゴリズムは、プレフィックス全体を 1 つのセグメントとして収集し、それを反転して、開始時に厳密に減少するシーケンスを生成します。 入力の場合:```
4
> > > >
```スキャンは 0 ～ 4 のすべてのインデックスをカバーする 1 つのセグメントを形成し、出力は [5, 4, 3, 2, 1] となり、すべての制約を満たします。 

もう 1 つのエッジ ケースは、「>」記号がまったくない場合です。```
3
< < <
```ここでは逆転は起こらないため、インデックスは自然な順序で追加され、[1, 2, 3, 4] が生成され、すべての不等式が正しく満たされます。 

「< > > <」のような混合境界の場合は、アルゴリズムが独立した単調ブロックに正しく分割され、矛盾した順序付けを強制するセグメント間の相互作用が確実にないことを示しています。
