 ## 解決策
 ## 問題の理解

 私たちにはグリモアのコレクションが与えられており、それぞれが難易度値と潜在値という 2 つの属性を持っています。 購入された順序は固定されており、最終的なタイブレーカーとして重要です。 

それぞれで$n$ここで、未使用のグリモアを 1 つだけ選択する必要があります。 選択は気分フラグによって異なります。 気分が 1 の場合、最も可能性の高いグリモアを選択します。 ムードが 0 の場合は、代わりに最高難易度のグリモアを選択します。 いくつかのグリモアが主な基準で同点である場合、二次属性がより大きいグリモアを優先して同点を解決し、それでもなお同点である場合は、以前に購入したものを選択します。 

グリモアを選択すると、それは永久に削除され、残りのセットに対してこのプロセスを繰り返します。 

主な問題点は、選択ルールがステップごとに変化し、選択ごとに使用可能なセットが永続的に変更されることです。 これにより、動的な削除や変更される比較ルールの下での最大クエリの繰り返しをサポートする構造を持たずに、一度事前に並べ替えて単純にシミュレーションしようとするアプローチが除外されます。 

と$n \le 10^5$、各ステップで残りのアイテムをすべてスキャンするアプローチではコストがかかります$O(n^2)$、これは大きすぎます。 おおよその必要があります$O(n \log n)$。 

複数のグリモアが同じ主属性を共有する場合、微妙な失敗例が発生します。 たとえば、2 つのアイテムの可能性と難易度が等しい場合、早期に購入する指標が決定的になります。 データ構造が順序付けにおいてこれを明示的にエンコードしない場合、任意の要素が返され、正確さが損なわれる可能性があります。 

もう 1 つのよくある落とし穴は、同期せずに 2 つの別個の優先キューを維持しようとすることです。 各グリモアは選択されて永久に削除されるため、慎重にフィルタリングしない限り、古いエントリが蓄積されます。 

## アプローチ

 ブルートフォースシミュレーションは簡単です。 各ステップで、残りのすべてのグリモアをスキャンし、気分フラグに応じて、可能性または難易度による最大値を計算します。 各スキャンには時間がかかります$O(n)$、そして私たちはこれをします$n$につながる$O(n^2)$。 と$10^5$アイテム、これは注文です$10^{10}$比較することは不可能です。 

問題の構造は、古典的な動的選択タスクを示唆しています。つまり、変化するコンパレータの下で最大値を繰り返し抽出します。 重要な観察は、コンパレーターが変更されても、各クエリは依然として、異なる順序付けルールを持つ同じ基礎となるセットに対する最大値であるということです。 これは、同じアイテムの 2 つの優先ビューを維持することで処理できます。 

私たちはすべてのグリモアを 2 つのヒープに保存します。1 つは主に可能性によって並べられ、もう 1 つは主に難易度によって並べられます。 各ヒープにはすべての項目が含まれていますが、項目が削除されると、その項目は非アクティブとしてマークされます。 いずれかのヒープから抽出する場合、有効なエントリが見つかるまで古いエントリは破棄されます。 この遅延削除手法により、コストのかかる削除を行わずに正確性が保証されます。 

それぞれの操作は、$O(\log n)$償却され、すべてのグリモアは 1 回だけ削除されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^2)$|$O(n)$| 遅すぎる |
 | 遅延削除による 2 つのヒープ |$O(n \log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 私たちはすべてのグリモアに対して 2 つの優先キューを維持します。 1 つのヒープは可能性によって順序付けし、難易度によって関係を破り、次に以前のインデックスによって並べ替えます。 2 番目のヒープは難易度順に並べ替え、潜在的な順に並べ替え、次に以前のインデックス順に並べ替えます。 また、グリモアがすでに使用されているかどうかを示すブール配列も維持します。 

各ステップで、ムード フラグを参照し、まだ使用されていないグリモアが見つかるまで、対応するヒープから繰り返しポップします。 

1. すべてのグリモアとそのインデックスと属性を含む 2 つのヒープを構築します。 最初のヒープは、負の可能性、負の難易度、およびインデックスによってキー設定されます。 2 つ目は、マイナスの難易度、マイナスの可能性、インデックスによって決まります。 負号は、Python の min-heap を使用して max-heap 動作を実装します。 
2. 配列を初期化する`used`サイズの$n$、すべて嘘です。 これは、グリモアがすでに選択されているかどうかを追跡します。 
3. 各ステップごとに$i$1から$n$、気分フラグを読み取ります。 これにより、どのヒープにクエリを実行するかが決まります。 
4. ムードが 1 の場合、インデックスが使用済みとしてマークされていない要素が見つかるまで、ポテンシャル ヒープから繰り返しポップします。 使用済みとしてマークし、そのインデックスを出力します。 早期に削除するとヒープ内に古いエントリが残る可能性があるため、この繰り返しが必要です。 
5. ムードが 0 の場合は、難易度ヒープで同じプロセスを実行します。 
6. すべてのグリモワールが消費されるまで続けます。 

これが機能する理由は、各ヒープが元のセット全体で常に正しい順序を表しているという事実に関係しています。 要素が両方のヒープから物理的に一度に削除されない場合でも、遅延削除により、古いエントリが見つかった場合はすべて無視されます。 各グリモアは 1 回使用されたとマークされるため、そのステップでクエリされたヒープから 1 回だけ抽出されます。 

タイブレーク ルールはヒープ キーに直接エンコードされ、比較のあいまいさが問題ステートメントと一貫して解決されるようにします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import heapq

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    p = list(map(int, input().split()))
    
    used = [False] * n
    
    heap_b = []
    heap_a = []
    
    for i in range(n):
        heapq.heappush(heap_b, (-b[i], -a[i], i))
        heapq.heappush(heap_a, (-a[i], -b[i], i))
    
    res = []
    
    for i in range(n):
        if p[i] == 1:
            while used[heap_b[0][2]]:
                heapq.heappop(heap_b)
            _, _, idx = heapq.heappop(heap_b)
            used[idx] = True
            res.append(idx + 1)
        else:
            while used[heap_a[0][2]]:
                heapq.heappop(heap_a)
            _, _, idx = heapq.heappop(heap_a)
            used[idx] = True
            res.append(idx + 1)
    
    print(*res)

if __name__ == "__main__":
    solve()
```この解決策は、両方の比較順序をヒープ キーに直接エンコードすることに依存しています。 ポテンシャル ヒープとディフィシティ ヒープは対称的であり、それぞれが二次属性とインデックスを介して正しいタイブレークを保証します。 

遅延削除ループは不可欠です。これがないと、ヒープは他のモードですでに消費されている要素を返します。 各 while ループは、選択前にヒープの先頭が常に有効であることを保証します。 

インデックス付けは、内部的に 0 から始まるインデックスを保存し、出力時にのみ 1 から始まるインデックスに変換することによって慎重に処理されます。

def solve_io(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque
    import heapq

    n = int(sys.stdin.readline())
    a = list(map(int, sys.stdin.readline().split()))
    b = list(map(int, sys.stdin.readline().split()))
    p = list(map(int, sys.stdin.readline().split()))

    used = [False] * n
    hb = []
    ha = []

    for i in range(n):
        heapq.heappush(hb, (-b[i], -a[i], i))
        heapq.heappush(ha, (-a[i], -b[i], i))

    res = []

    for i in range(n):
        if p[i] == 1:
            while used[hb[0][2]]:
                heapq.heappop(hb)
            _, _, idx = heapq.heappop(hb)

                heapq.heappop(ha)
            _, _, idx = heapq.heappop(ha)

        res.append(str(idx + 1))

    return " ".join(res)

 ## 特殊なケース

 重要なエッジケースは、複数のグリモアが同一のプライマリ値とセカンダリ値を共有する場合です。 考慮する：```
a = [5, 5]
b = [5, 5]
p = [1, 0]
```どちらの項目もインデックスを除いて区別できません。 ヒープ キーには、決定的な選択を保証するためのインデックスが含まれている必要があります。 アルゴリズムストア`( -primary, -secondary, index )`したがって、インデックスはタイを正しく切断し、最初に選択されるものは気分にのみ依存し、任意のヒープの動作には依存しません。 

もう 1 つのエッジ ケースは、グリモワールが両方のヒープで最適であるにもかかわらず、最初にもう一方のヒープで消費される場合に発生します。 両方のヒープに同じインデックスが含まれており、常にチェックするためです。`used[]`、古いエントリは安全に破棄されます。 たとえば、項目 3 が難易度ヒープ経由で選択された場合、項目 3 はポテンシャル ヒープに残りますが、論理的に削除されるまでスキップされます。 これにより、相互削除を必要とせずに、交互のムード間で一貫性が確保されます。
