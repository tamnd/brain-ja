 ## 問題の理解

 長い年列が与えられ、各年には 2 つの整数値が含まれます。1 つは「良い」イベントの数を表し、もう 1 つは「悪い」イベントの数を表します。 

2 年は、2 つの異なる直接的な方法で関連付けることができます。 最初の関係は、良いイベントの数がどちらかの方向に分割される年を結び付けます。 2 番目の関係は、ある年の良い値が他の年の悪い値と一致する年を、やはりどちらかの方向に結び付けます。 

これらの関係は、一連の年にわたる接続性ルールを定義します。これらの直接関係のシーケンスを使用して年から年に移動できる場合、そのシーケンスのエンドポイントは関連していると見なされます。 約 2 年を尋ねる各クエリについて、それらがこれらのルールによって引き起こされる同じ接続構造に属しているかどうかを判断する必要があります。 

重要な観察は、その定義が単なる直接の隣接関係ではなく、可分性と等式条件によってエッジが暗黙的に定義されるグラフに対する推移閉包であるということです。 

制約は大きく、最大 300,000 年、最大 500,000 クエリです。 クエリごとにペアごとの関係を明示的にチェックしようとするソリューションは、すぐに失敗します。 すべてのエッジを単純に構築するだけでもコストがかかりすぎます。なぜなら、可分性関係だけでも密な場合には 2 次になる可能性があるからです。 

意図した構造は、暗黙的なエッジの下でのグラフの接続性の問題であるため、結合操作を効率的にサポートする表現を構築し、接続性チェックを通じてクエリに答える必要があります。 

すべての年が同じ値を共有する場合、微妙な特殊なケースが発生します。 その場合、すべてのノードは等価ルールを介して接続され、すべてのクエリは YES を返す必要があります。 もう 1 つの興味深いケースは、割り算の連鎖が存在する場合です。たとえば、2、4、8、16 のような値は、すべてのペアが直接割り切れない場合でも推移的に接続されます。 直接の割り算または直接の等価性のみをチェックする単純なアプローチでは、2 や 16 などの到達可能なペアに対して誤って NO が出力されます。 

## アプローチ

 直接的な解釈は、毎年がノードとなるグラフを構築し、2 つの直接関係のいずれかが成立するたびにノードを接続することを示唆しています。 このグラフを構築した後、クエリごとに BFS または DFS を実行して接続を確認します。 これは正しいですが、すぐには実行できません。 グラフには最大 n 個のノードを含めることができますが、割り算のみによる潜在的なエッジは 2 次の動作に達する可能性があり、クエリごとに走査を実行すると、クエリごとに O(n + m) のコストがかかり、最悪の場合は 10^11 を超える演算が発生します。 

重要な洞察は、実際にはクエリ時に明示的にパスをトラバースする必要がないということです。 2 つのノードが同じ接続コンポーネント内にあるかどうかを知る必要があるだけです。 これは、素の集合共用体構造を使用することを示唆していますが、それでも共用体を効率的に構築する必要があります。 

課題は、すべてのペアを列挙せずにエッジを具体化する方法です。 重要な構造は、割り算の関係は、インデックスを値ごとにグループ化し、整数の倍数を反復処理することで処理できるのに対し、配列 a と配列 b の間の等価関係は、いずれかの配列で同じ値を共有するインデックスをグループ化することによって処理できることです。 

すべての割り切れるペアを直接接続する代わりに、値を昇順に処理し、値が同じ基数の倍数であるすべてのインデックスを接続します。 配列全体で平等にするために、インデックスを値ごとにバケット化し、各バケット内ですべてを結合します。 これにより、問題は任意のグラフ構築から構造化されたふるいのような伝播へと軽減されます。 

すべての結合が実行された後、各クエリは 2 つのインデックスが同じ DSU ルートを共有しているかどうかを定数時間チェックします。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース グラフ + クエリごとの BFS | O(n² + q・n) | O(n²) | 遅すぎる |
 | 値バケット化 + 除数伝播を備えた DSU | O(n log A + A log A + q α(n)) | O(n + A) | 承認済み |

 ## アルゴリズムのチュートリアル

 すべての年にわたって素のセット和集合を構築します。最初は各年が分離されています。 

1. まず配列 a と b の間の等価性を処理します。 個別の値 v ごとに、a[i] = v または b[i] = v となるすべてのインデックス i を収集します。そのようなインデックスはすべて一緒にマージされます。 これは、ペアごとの比較ではなく、値ごとに 1 回のスイープですべての「ab-interesting」関係を処理します。 
2. 次に、分割可能性を構造化された方法で処理します。 各年 i は、a[i] で定義された値クラスに属していると解釈します。 最大値 a[i] までのすべての可能な値 x について、x のすべての倍数を考慮します。 データセット内で何らかの a 値として現れる複数の m = kx ごとに、m に対応するすべてのインデックスと x に対応するインデックスを結合します。 これにより、必要なすべての興味深い接続が構築されます。 
3. 空の値の反復を避けるために、各値のインデックスのリストを維持し、実際に発生する値のみを処理します。 存在する基本値 x ごとに、その倍数と他のアクティブな値との結合を繰り返します。 
4. すべての結合の後、find(x) が find(y) と等しいかどうかをチェックすることによって、各クエリ (x, y) が回答されます。 

正しさは、両方のタイプの関係が和集合演算によって完全に捕捉されるという事実から得られます。 等価関係は、各値クラス内の和集合の下で明示的に閉じられます。 すべてのペア (x, y) と x | が一致するため、割り切れる関係が捕捉されます。 y は、x のすべての倍数を処理することによって引き起こされる和集合のチェーンを通じて接続されます。 

問題の推移的定義はまさにグラフ内の接続関係であり、DSU は共用体検索操作の下で同値クラスを維持し、推移的閉包を暗黙的に保持します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    q = int(input())

    maxv = 300000

    parent = list(range(n))
    size = [1] * n

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    def union(x, y):
        x = find(x)
        y = find(y)
        if x == y:
            return
        if size[x] < size[y]:
            x, y = y, x
        parent[y] = x
        size[x] += size[y]

    pos_a = [[] for _ in range(maxv + 1)]
    pos_b = [[] for _ in range(maxv + 1)]

    for i in range(n):
        pos_a[a[i]].append(i)
        pos_b[b[i]].append(i)

    for v in range(maxv + 1):
        lst = pos_a[v] + pos_b[v]
        if len(lst) > 1:
            base = lst[0]
            for i in lst[1:]:
                union(base, i)

    active = [False] * (maxv + 1)
    for i in range(n):
        active[a[i]] = True

    for x in range(1, maxv + 1):
        if not active[x]:
            continue
        base_list = pos_a[x]
        if not base_list:
            continue
        for y in range(x * 2, maxv + 1, x):
            if pos_a[y]:
                for i in base_list:
                    for j in pos_a[y]:
                        union(i, j)

    out = []
    for _ in range(q):
        x, y = map(int, input().split())
        out.append("YES" if find(x - 1) == find(y - 1) else "NO")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装では、接続されたコンポーネントを維持するために DSU を使用します。 配列`pos_a`そして`pos_b`インデックスを値ごとにグループ化して保存するため、等価結合が簡単になります。 

割り算フェーズでは、可能な基本値を反復し、インデックスを接続します。`pos_a[x]`インデックス付き`pos_a[y]`倍数yの場合。 これは最もパフォーマンスに敏感な部分であり、`active`配列とチェック`pos_a[y]`結合を試みる前の存在。 

クエリ応答はクエリごとに 1 つの DSU ルート比較に削減されるため、500,000 クエリでも効率が保証されます。 

## 実用的な例

 割り算によって連鎖が作成される小さな概念的な例を考えてみましょう: a = [2, 4, 8]、b = [0, 0, 0]。 

最初に等しい b 値をマージしますが、すべてがゼロであるため、すべてのインデックスがすぐに接続されます。 

| ステップ | 操作 | DSUセット |
 | --- | --- | --- |
 | 初期化 | すべて別々 | {1}、{2}、{3} |
 | b=0 マージ | すべてのインデックスを結合する | {1,2,3} |

 b の等価性によりすべてが折りたたまれるため、すべてのクエリは YES になります。 

次に、混合構造、a = [2, 4, 8]、b = [0, 0, 0]、クエリ (1,3)、(2,3) を考えます。 

bの処理後、すべてのノードがすでに接続されています。 可分性フェーズは無関係になりますが、依然として有効です。 

これは、等価エッジがどのように構造を支配し、ただちに単一の連結成分を生成するかを示しています。

 ## 特殊なケース

 重要なケースは、b のすべての値が同一でゼロでない場合です。 この状況では、すべてのインデックスが単一の等価バケットを介して即座に接続されるため、a 値が大幅に異なる場合でも、クエリはいずれかのペアに対して YES を返す必要があります。 a 値のみを考慮する単純な解決策では、この完全な崩壊を見逃してしまいます。 

もう 1 つの微妙なケースは、a = [6, 10, 15] などのスパース割り切りです。 これらはいずれも互いに分割するものではありませんが、構築されたグラフの複数のステップを介した共有因子は、中間に構築された和集合に応じて間接的に接続することができます。 DSU アプローチは、接続がペアごとにローカルではなくグローバルに構築されるため、これを正しく処理します。 

3 番目のエッジ ケースは、大きな値が存在するが、ほとんどの数値が存在しない場合に発生します。 すべての値を単純に完全にふるい分けるとタイムアウトになりますが、処理をアクティブな値のみに制限することで、意味のある倍数のみを拡張し、不必要な反復を回避できます。
