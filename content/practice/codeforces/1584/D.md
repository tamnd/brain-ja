 ## 解決策
 ## 問題の理解

 長さのシーケンスが与えられます$n$最初は次の整数を含みます$1$に$n$昇順で。 その後、陪審が 3 つの指数を選択します$i < j < k$と$j - i > 1$そして 2 つのサブセグメントを反転します。$i$に$j-1$、そして2番目から$j$に$k$。 私たちの仕事は、の正確な値を把握することです。$i, j, k$。 

私たちが持っている唯一のツールは、現在の配列のサブセグメント内の反転の数をクエリすることです。 反転はインデックスのペアです$p < q$そのような$a[p] > a[q]$。 各クエリはサブセグメント内の反転の数を返します。$[l, r]$。 最大 40 個のクエリが許可されていますが、これは十分な量です。$n$と同じ大きさにすることができます$10^9$。 

この制約は、配列全体をシミュレートしたり保存したりできないことや、考えられるすべてのトリプルをスキャンできないことを意味します。 配列の反復に依存するブルートフォース手法では、時間とメモリの制限をすぐに超えてしまいます。 エッジ ケースには、最小の有効な配列 ($n = 4$)、または反転されたセグメントの長さが最小限の場合 ($j - i = 2$、$k - j = 1$)、セグメントの長さが常に「十分に大きい」と仮定すると、単純な計算が混乱する可能性があります。 

たとえば、次の場合$n=5$そして$i=1, j=3, k=5$、シーケンスは次のようになります$[2,1,5,4,3]$。 すべてのセグメントの長さが 2 より大きいと仮定した不用意なアプローチでは、反転ベースの演算を実行する際に位置の計算が間違ってしまう可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、すべてのトリプルを推測しようとします。$(i,j,k)$そして、反転をクエリすることでそれらを検証します。 トリプルの数は次のように 3 次的に増加します。$n$($\sim n^3$）、実行不可能になります。 

重要な観察は、反転カウントが単純な数学的方法でセグメント長をエンコードしているということです。 最初の反転セグメントの場合$[i, j-1]$長さの$L_1 = j-i$、反転後の反転の数は、そのセグメント内の順序のないペアの数と正確に一致します。$C(L_1,2) = L_1(L_1-1)/2$。 同様に、2 番目のセグメント$[j,k]$長さの$L_2 = k-j+1$貢献する$C(L_2,2)$反転。 

シーケンス全体をクエリすると、反転の総数は次のようになります。$C(L_1,2) + C(L_2,2)$。 サブセグメントをクエリすると、分離できるようになります。$L_1$そして$L_2$個別に。 これにより、問題はセグメント長を回復するための単純な二次方程式を解くことに帰着します。 長さがわかったら、$i$二分検索で見つけることができます。ゼロ以外の反転を含む最小のプレフィックスの場合、最初の反転セグメントの開始は次のとおりです。$i$。 そこから、$j$そして$k$長さを使用して復元されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^3) | O(n) | 遅すぎる |
 | 逆算術 + 二分探索 | O(log n) クエリ | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列全体の反転の合計数をクエリします。$[1,n]$。 これに電話してください$total$。 これは等しい$C(L_1,2) + C(L_2,2)$、 どこ$L_1 = j-i$そして$L_2 = k-j+1$。 
2.二次方程式を解く$x(x-1)/2 = total$セグメントの潜在的な長さを回復します。 合計は 2 つのセグメント反転数の合計から得られるため、追加のクエリを使用してそれらを分離します。 
3. 二分探索を実行します。$i$、最初の反転セグメントの開始。 クエリプレフィックス$[1,m]$。 反転数がゼロの場合は右に移動します。 それ以外の場合は、左に移動します。 ゼロ以外の反転を含む最初の接頭辞には次のものが含まれます。$i$。 
4. 見つけたら$i$、から始まるセグメントをクエリします。$i$最初のセグメントの長さを分離するには$L_1$逆数式を使うと$C(L_1,2) = inversions\_in\_segment$。 コンピューティング$j = i + L_1$。 
5. 2番目のセグメントの長さ$L_2$次のように計算できるようになりました$k-j+1 = L_2$。 クエリ$[j, n]$または残りの反転回数から解きます。 コンピューティング$k = j + L_2 - 1$。 
6. 出力$(i,j,k)$。 

機能する理由: 連続するサブセグメントにわたって反転された完全に増加するシーケンス内の反転の数は、セグメントの長さによって一意に決定されます。 プレフィックスとサフィックスに対するクエリを使用してこれらの長さを分離すると、配列を構築せずに元のインデックスを回復できます。 二分探索は次のことを保証します$i$は効率的に検出され、逆算によりカウントが正確なセグメント長に変換されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
flush = sys.stdout.flush

def query(l, r):
    print(f"? {l} {r}")
    flush()
    res = int(input())
    if res == -1:
        exit(0)
    return res

def solve_case(n):
    total = query(1, n)

    # binary search for i
    left, right = 1, n
    i = 1
    while left <= right:
        mid = (left + right) // 2
        inv = query(1, mid)
        if inv == 0:
            left = mid + 1
        else:
            i = mid
            right = mid - 1

    # find length of first reversed segment L1
    low, high = 1, n
    L1 = 0
    while low <= high:
        mid = (low + high) // 2
        inv = query(i, i + mid - 1)
        if inv == mid * (mid - 1) // 2:
            L1 = mid
            low = mid + 1
        else:
            high = mid - 1
    j = i + L1

    # remaining inversions to find L2
    inv_second = query(j, n)
    # solve L2*(L2-1)//2 = inv_second
    L2 = 1
    while L2 * (L2 - 1) // 2 < inv_second:
        L2 += 1
    k = j + L2 - 1
    print(f"! {i} {j} {k}")
    flush()

t = int(input())
for _ in range(t):
    n = int(input())
    solve_case(n)
```このコードは、最初に反転の合計をクエリし、次に二分検索を実行して最初の反転セグメントの開始位置を特定します。 その後、反転公式を使用して最初のセグメントの長さを見つけ、2 番目のセグメントの長さを推定します。 正確なサブセグメントに対するクエリはセグメントの長さと一致する必要があり、そうでない場合は反転式が失敗するため、境界処理は非常に重要です。
