 ## 解決策
 ## 問題の理解

 最大 10 個の文字列が与えられ、英語の小文字と大文字が混在したアルファベットが使用されます。 タスクは、指定されたすべての文字列のサブシーケンスとして現れる単一の文字列を構築することです。そのようなすべての文字列の中で、可能な限り長い文字列が必要です。 

サブシーケンスとは、順序を維持しながら文字列から文字を選択できることを意味しますが、文字をスキップすることはできます。 したがって、問題は、各入力文字列の文字を個別に削除することによって、すべての入力文字列に埋め込むことができる文字列を求めることです。 

主要な構造上の制約は、各文字がすべての文字列内で最大 2 回出現することです。 これにより、文字の内部順序制約がどれほど複雑になるかが即座に制限されます。 固定文字の場合、考慮する必要があるのは最大でも 2 回の出現だけなので、相対的な順序付け情報は小さな状態空間に収まります。 

文字列の数は少なく、最大でも 10 個です。これは、文字列または文字列から派生した状態に対してビットマスクを適用できることを示唆しているため、非常に重要です。 ただし、文字列の長さは長くなる可能性があるため、生の文字列内の位置に依存するソリューションでは、遷移を圧縮または事前計算する必要があります。 

単純な間違いは、n 個の文字列にわたる古典的な LCS DP の観点から考えることです。しかし、その場合、各文字列の位置を追跡する必要があり、状態空間は n で指数関数的、長さで線形になります。 もう 1 つの落とし穴は、すべての文字列にわたる実現可能性を追跡せずに、貪欲な文字ごとの構築を想定することです。 サブシーケンスの実現可能性はグローバルな順序付けの制約に依存するため、貪欲な選択を行うと、より長い継続が簡単にブロックされる可能性があります。 

たとえば、ある文字列が文字の出現を早めに強制し、別の文字列が文字の出現を遅くする場合、ある文字列で間違った出現を選択すると、その文字が他の場所に存在する場合でも、後の一致が不可能になる可能性があります。 

## アプローチ

 直接的な総当たりのアイデアは、選択した 1 つの文字列の考えられるすべての部分列を試し、それが他のすべての文字列の部分列であるかどうかを検証することです。 長さ L の最も短い文字列を選択すると、2^L 個の候補が得られ、各チェックのコストは O(nL) になります。 2^50 はすでに実行不可能であるため、これは L が 50 付近であっても不可能になります。 

重要な観察は、各文字が各文字列内で最大 2 回出現するため、固定文字の場合、その文字が占めることのできる意味のある「位置」は非常に少数しかないということです。 完全な文字列について推論する代わりに、有限状態抽象化を使用して、すべての文字列にわたって文字を一貫して配置する方法を推論できます。 

各文字列を、文字の出現によって定義される状態のグラフとして扱います。 各文字列の各文字について、最初に出現する文字を使用するか、2 番目に出現する文字を使用するか (または存在しないか) を知る必要があるだけです。 これにより、各文字列は 1 文字あたり最大 2n 個の関連位置に削減され、それらの間の遷移は決定的になります。 

ここで中心となる洞察です。サブシーケンスを直接構築する代わりに、ノードがすべての文字列の「現在位置」を同時に表し、エッジが次の文字の選択とすべてのポインターの一貫した前進を表すグラフを構築します。 各文字は文字列ごとに 2 回しか出現しないため、遷移を効率的に事前計算でき、文字列に対するビットマスクと組み合わせることで状態の総数を管理できます。 

次に、状態全体に対して最短パス スタイルの DP (重み付けされていない遷移に対する効果的な BFS またはダイクストラ) を実行します。ここで、各状態は各文字列内の現在位置をエンコードします。 ある状態から文字を追加してみて、順序に違反することなくすべての文字列内でその文字を進めることができる場合は、次の状態に遷移します。 サブシーケンスの長さに対応する、到達可能な最適な状態の深さを追跡します。

再構築は、親ポインターを保存することによって行われます。各状態について、その状態に到達するためにどの文字が使用されたか、およびどの前の状態から使用されたかを記憶します。 

これが機能するのは、制約によって文字列ごとの複雑さが小さなローカルな選択 (最大 2 回) に集約され、グローバルな相互作用が同期された状態遷移を通じて処理されるためです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 |---|---|---|

 | 1 つの文字列のブルート フォース サブシーケンス | O(2^L・nL) | お(1) | 遅すぎる |

 | 同期ポインタ + BFS/DP 上の状態グラフ | O(S・52・n) | O(S・n) | 承認済み |

 ここで S は、文字列ごとに最大 2 回の出現によって引き起こされる構造化遷移によって制限される、到達可能な同期状態の数です。 

## アルゴリズムのチュートリアル

 1. 各文字列について、すべての文字の位置を前処理し、文字ごとに最大 2 つのインデックスを保存します。 これにより、線形にスキャンするのではなく、オカレンス間を直接ジャンプすることができます。 
2. 状態をポインタのタプルとして定義し、文字列ごとに 1 つずつ、各文字列内の現在一致する位置を示します。 ポインタは、その文字列内で最後に一致した出現境界を表します。 
3. すべてのポインターが先頭 (概念的には最初の文字の前) にある状態を初期化します。 これは空のサブシーケンス状態です。 
4. 各状態について、「a」から「z」まで、および「A」から「Z」までのすべての文字を試してサブシーケンスを拡張することを検討します。 候補文字について、現在のポインターの後の有効な次の出現に進むことができるかどうかを文字列ごとに計算します。 
5. 文字列内でポインタ位置の後に文字が見つからない場合は、この文字拡張子を破棄します。 それ以外の場合は、各文字列の次のポインタを、現在のポインタの後の最も古い有効な出現として計算します。 
6. 結果の状態がまだ訪問されていない場合、またはその状態へのより長いパスが見つかった場合は、その距離を更新し、使用された遷移を記録します。 
7. 改善が不可能になるまで、BFS のような拡張を使用してこのプロセスを続けます。 
8. 見つかった最良の状態から遡って答えを再構築します。 

正確さは、各状態がすべての文字列間でプレフィックスを同期するための最良の方法を表すという不変条件に依存します。 ある状態に到達すると、関連するすべての順序付け情報がポインターの位置によって取得されるため、将来の拡張は現在のポインターのみに依存し、そこに到達するまでの履歴には依存しません。 

これにより、有効なサブシーケンスの欠落が防止されます。サブシーケンス内の各文字の出現がすべての文字列の実行可能な進行に対応するため、有効な共通サブシーケンスはこれらの同期状態を通る有効なパスを誘導します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import deque

def solve():
    n = int(input())
    s = [input().strip() for _ in range(n)]

    pos = []
    for i in range(n):
        mp = {}
        for j, ch in enumerate(s[i]):
            mp.setdefault(ch, []).append(j)
        pos.append(mp)

    alphabet = []
    for c in range(ord('a'), ord('z') + 1):
        alphabet.append(chr(c))
    for c in range(ord('A'), ord('Z') + 1):
        alphabet.append(chr(c))

    start = tuple([-1] * n)

    dist = {start: 0}
    parent = {}
    parent_char = {}

    q = deque([start])
    best_state = start

    def next_pos(i, ch, cur):
        lst = pos[i].get(ch, [])
        if not lst:
            return None
        if len(lst) == 1:
            return lst[0] if lst[0] > cur else None
        if cur < lst[0]:
            return lst[0]
        if cur < lst[1]:
            return lst[1]
        return None

    while q:
        state = q.popleft()

        if dist[state] > dist[best_state]:
            best_state = state

        for ch in alphabet:
            nxt = []
            ok = True
            for i in range(n):
                np = next_pos(i, ch, state[i])
                if np is None:
                    ok = False
                    break
                nxt.append(np)

            if not ok:
                continue

            nxt = tuple(nxt)
            if nxt not in dist:
                dist[nxt] = dist[state] + 1
                parent[nxt] = state
                parent_char[nxt] = ch
                q.append(nxt)

    res = []
    cur = best_state
    while cur != start:
        res.append(parent_char[cur])
        cur = parent[cur]

    res.reverse()
    print(len(res))
    print("".join(res))

t = int(input())
for _ in range(t):
    solve()
```前処理ステップでは、文字列ごとに文字位置リストを作成します。これは、すべての遷移クエリが出現チェックごとに O(1) で応答される必要があるため、不可欠です。 BFS は同期されたポインターの状態を調査し、各遷移は文字を選択し、各文字列のポインターを次の有効な出現箇所にジャンプすることに対応します。 

ポインタのタプルの使用は、中核となる状態表現です。 辞書ベースの DP により、各構成に到達する最もよく知られた方法のみが保持されることが保証されます。 親追跡により、完全なパスを保存せずに再構築が可能になります。 

ヘルパー関数`next_pos`「最大 2 回出現」という制約をカプセル化し、文字列ごと、文字ごとに定数時間の検索を保証します。 

## 実用的な例

 ### 例 1

 入力:```
2
ABC
CBA
```状態 (-1, -1) から開始します。 ここからは文字をテストしていきます。 

| 状態 | 「A」を試してください | 'B' を試してください | 'C' を試してください |
 | --- | --- | --- | --- |
 | (-1,-1) | (0,2) 有効 | (1,1) 有効 | (2,0) 有効 |

 3 つすべてが有効な状態であるため、BFS は深さ 1 でそれらを探索します。2 番目の文字は少なくとも 1 つの文字列の順序に違反するため、各状態からこれ以上の共通拡張は存在しません。 

したがって、アルゴリズムは最適な長さ 1 で終了します。 

これにより、複数の候補が存在する場合でも、両方の文字列間の同期により、より深い拡張が即座に制限されることが確認されます。 

### 例 2

 入力:```
3
abcde
aBcDe
ace
```初期状態は (-1,-1,-1) です。 3 つの文字列すべてにわたって存続できる文字は、順序の制約を考慮して、そのすべてに出現する文字だけです。 

| 状態 | 実現可能な拡張 | 次の状態 |
 | --- | --- | --- |
 | 開始 | | (0,0,0) |
 | (0,0,0) | c | (2,2,1) |
 | (2,2,1) | e | (4,4,2) |

 現時点では、これ以上の拡張は存在しません。 再構築されたパスは「ace」です。 

このトレースは、ポインターの同期によって、文字の存在だけでなく、すべての文字列にわたる順序制約の位置合わせが同時に強制される様子を示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(S・52・n) | 各状態はすべての文字を試し、チェックごとに一定時間で最大 n 個の文字列をチェックします。 
| スペース | O(S・n) | 訪問した状態、親、および遷移を保存します。 

状態の数 S は、各文字列が 1 文字あたり 2 回しか発生しないため、管理可能なままであり、到達可能なポインター構成が大幅に制限されます。 n ≤ 10 の場合、同期状態空間は 2 秒未満の BFS スタイルの探索の実行可能な制限内に留まります。

 ## 特殊なケース

 微妙なケースとしては、ある文字列では 2 回出現する文字が、別の文字列では 1 回しか出現しない場合があります。 たとえば、ある文字列では「aba」、別の文字列では「aa」になります。 アルゴリズムは、将来の拡張に応じて、最初の出現を取得するか 2 番目の出現を取得するかを正しく決定する必要があります。 の`next_pos`関数は、現在のポインタの後の最も古い有効な出現を常に選択することでこれを強制し、無効なスキップを防ぎます。 

もう 1 つのエッジ ケースは、複数の文字が同等に見えるが、将来の実現可能性が異なる状態につながる場合です。 状態は文字列ごとに正確なポインター位置をエンコードするため、同じタプルに到達する 2 つのパスがマージされ、将来の遷移の正確性を維持しながら、同等の構成を二重にカウントすることがなくなります。
