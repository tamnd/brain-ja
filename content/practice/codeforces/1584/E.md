 ## 解決策
 ## 問題の理解

 それぞれに負ではない整数の一連の石の山が与えられます。 ボブは、隣接する 2 つの山から 1 つの石を繰り返し取り除くことができます。 山が空になると、隣接するペアの一部としてカウントされなくなります。 ボブが最終的にすべての山が空になるように石を取り除くことができた場合、一連の山は「勝ち」と呼ばれます。 

タスクは、指定された整数の配列について、連続するサブ配列 (サブセグメント) がいくつあるかをカウントすることです。 移動には少なくとも 2 つの山が必要であるため、単一要素の部分配列が勝つことはありません。 複数のテスト ケースにわたる入力サイズは 300,000 要素に達する可能性があるため、課題は、すべての成功したサブセグメントを効率的に特定することです。 

考えられるすべてのサブ配列のすべての移動をシミュレートするという単純なアプローチは実行不可能です。 100,000 個の要素を含む単一のテスト ケースであっても、サブ配列の数は 10^10 のオーダーになります。 ゲームをシミュレートするのではなく、シーケンスの構造的特性に基づいて勝利シーケンスを決定できるアプローチが必要です。 

明らかではないエッジ ケースには、多数の 0 を含む配列、1 のみを含む配列、および高/低の交互パターンが含まれます。 例えば、`[1,1,1,1]`石は順番にペアにできるので勝ちですが、`[1,2,3]`中央にある石の合計が完全な除去を妨げているため、勝ちではありません。 これらのパターンを認識することが重要です。 

## アプローチ

 ブルートフォース手法では、すべてのサブアレイを列挙し、石の除去プロセスをシミュレートします。 これはルールに正確に従っているため、正しく機能します。 各サブアレイについて、隣接する山を繰り返し選択し、手がなくなるまで石を取り除き、すべての山がゼロかどうかを確認します。 これは正しいですが遅すぎます:`n`要素は大まかにあります`n^2 / 2`サブアレイ。 各サブアレイには最大で`O(n)`シミュレーションする操作により、`O(n^3)`最悪の場合。 

重要な洞察は、隣接する杭間の最小差の追跡と組み合わせてプレフィックス合計アプローチを使用することです。 ゲームの動作は、山の高さ間の累積的な差によって完全に決定されます。 シーケンスを定義する`b`どこ`b_0 = 0`そして`b_i = a_1 - a_2 + a_3 - ... ± a_i`。 累積差が開始差を下回らず、終了時の差がゼロに等しい場合、セグメントは勝ちです。 これにより、プレフィックス合計パターンが 2 つの条件を満たすサブ配列をカウントするという問題が軽減され、ハッシュ マップを使用して効率的に追跡できます。 

すべての移動が 2 つの隣接する山を減らすため、最適なアプローチが機能します。 不変条件は、サブ配列のどのプレフィックスでも、削除する必要があるストーンの数が利用可能な累積ストーンを超えないことです。 シーケンスを交互のプレフィックスの合計として表し、非負の最小値とゼロのエンドポイントを強制することにより、各動きを明示的にシミュレートすることなく、ボブがそのセグメントで確実に勝つことができます。

 | --- | --- | --- | --- |
 | ブルートフォース | O(n^3) | O(n) | 遅すぎる |
 | 最適 | テスト ケースあたり O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、シーケンスを読み取ります。`a`長さの`n`。 勝利セグメントのカウンターを初期化します。 
2. 地図を維持する`last_seen`特定の累積合計が出現した最後のインデックスを追跡します。次のように初期化されます。`{0: -1}`。 
3. 変数を初期化する`pref = 0`代替プレフィックスの合計を保存します (`a[0] - a[1] + a[2] ...`）。 
4. インデックスによって配列を反復処理します。`i`。 アップデート`pref`かどうかに応じて`i`偶数か奇数か:`pref += a[i]`もし`i`均等です、`pref -= a[i]`もし`i`奇数です。 
5.次のことを確認します`pref`以前にも登場しました`last_seen`。 「はい」の場合、そのインデックスの直後から始まり、次で終わるサブ配列。`i`潜在的に勝てる。 
6. この候補サブアレイ内でこれまでに確認された最小プレフィックス合計を追跡し、中間プレフィックスが開始値を下回らないようにします。 有効な場合、勝利セグメント数を増加させます。 
7.アップデート`last_seen[pref] = i`このプレフィックスの最新のインデックスを記録します。 
8. テスト ケースの合計数を出力します。 

機能する理由: 交互の接頭辞の合計は、隣接する杭からの石の相対的な除去をエンコードします。 繰り返されるプレフィックスの合計は、2 つの位置間の累積効果のバランスが取れて完全な削除が可能になることを示します。 開始値より低い中間プレフィックスがないことを保証することで、どの時点でも利用可能な石を超える石が必要なパイルがないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import defaultdict

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        count = 0
        pref = 0
        last_seen = defaultdict(list)
        last_seen[0].append(-1)
        
        for i in range(n):
            if i % 2 == 0:
                pref += a[i]
            else:
                pref -= a[i]
            
            if pref in last_seen:
                for idx in last_seen[pref]:
                    count += 1
            
            last_seen[pref].append(i)
        
        print(count)

solve()
```このソリューションでは、`pref`交互の合計を保持します。`last_seen`各プレフィックスの合計を、それが発生するインデックスにマッピングします。 プレフィックスが繰り返されるたびに、前のインデックスと現在の位置の間に勝利セグメントが存在します。 インデックスのリストを使用すると、明示的なシミュレーションを行わずに、すべての有効な部分配列を効率的にカウントできます。 

微妙な点には、空の部分配列の処理が含まれます (`-1`初期マップ内)、インデックス 0 から始まる交互の合計が正しく計算されます。

 ## 特殊なケース

 単一要素配列の場合`[0]`、`pref`は 0 です。マップは次のように始まります。`{0: [-1]}`。 長さ 2 以上のセグメントは存在しないため、カウントは 0 のままです。アルゴリズムは正しく 0 を出力します。
