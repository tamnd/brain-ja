 ## 解決策
 ## 問題の理解

 同じ長さの 2 つの整数配列が与えられます。 最初の配列で許可される操作は非常に具体的です。位置のサブセットを選択し、選択された各要素を 1 つだけ増やすことができます。 その後、配列を自由に並べ替えることができます。 

問題は、そのような操作フェーズを 1 つだけ使用して、最初の配列を 2 番目の配列に変換できるかどうかです。 

並べ替えのステップは、位置的な制約を取り除くため、非常に重要です。 インクリメントステップの後は、値の複数セットのみが問題になり、値がどこから来たのかは問題になりません。 これは、問題は基本的に、最初の複数セットの要素のいくつかに 1 を追加することによって、ある整数の複数セットを別の整数セットに変換できるかどうかであることを意味します。 

制約は小さく、配列サイズは最大 100、テスト ケースは最大 100 です。 要素のサブセットに対する直接的な指数関数的検索は、単一のテストの生の形式ではすでに許容できる境界線にありますが、すべてのケースにわたって明確に推論する場合はそうではありません。 それでも、制限が小さいということは、ソートと線形チェックで十分である可能性が高く、サブセットの組み合わせ列挙を伴う解決策は不要であることを示唆しています。 

置換ステップを考えすぎると、微妙な落とし穴が発生します。 たとえば、インデックスを直接照合して、ポジションごとに貪欲に決定しようとする場合があります。 最終的な並べ替えでは任意の再割り当てが許可されるため、これは失敗します。 

もう 1 つのよくある間違いは、固定順序に基づいてポジションごとにインクリメントする必要があるかどうかを個別に決定できると想定していることです。 順列は増分後に発生するため、元のインデックスではなく、並べ替えられた構造を比較するのが正しい観点です。 

この失敗モードを考慮してください。要素を元の順序で一致させようとすると、インクリメント後に有効な順列が存在する場合でも、不可能であると誤って結論付けられる可能性があります。 順序を変更すると、位置の意味が完全に破壊されます。 

## アプローチ

 ブルートフォースアプローチでは、インデックスのすべてのサブセットを増分しようとします。 サブセットごとに増分を適用し、並べ替えてターゲット配列と比較します。 2^n 個のサブセットがあり、各チェックのコストは O(n log n) ですが、定数係数が膨大で構造が不要なため、たとえ n が 100 であってもすぐに実行不可能になります。 

重要な点は、この操作では値が +1 だけ変更され、他の変換は導入されないことです。 つまり、最終的な配列の各要素は、元の配列の要素から取得され、変更されないか、一度インクリメントされなければなりません。 両方の配列をソートした後、ターゲット配列の各要素が 0 または 1 の差でソース配列の要素と一致するかどうかを事実上判断しようとしています。また、各 +1 演算は、選択された要素ごとに 1 回だけ使用されます。 

両方の配列がソートされると、自然なペアリングが実現可能性をテストするための最適な構造になります。 最小の要素は最小のターゲットと一致する必要があります。 そうしないと、ローエンドでの不一致は、後で並べ替えることによって修復できなくなります。 これにより、ソート後の線形スキャンの問題が軽減されます。

 | ブルート フォース (サブセット列挙) | O(2^n · n log n) | O(n) | 遅すぎる |
 | ソート + 貪欲なマッチング | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各テスト ケースを 2 つのソートされた配列間の比較に縮小します。

1. 両方の配列を非降順で並べ替えます。 これにより、最後の並べ替えステップによってもたらされる位置の曖昧さがすべて取り除かれます。 
2. 配列の合計の差の合計を計算します。 各操作で合計が 1 だけ増加するため、この値は増加する必要がある要素の数を表します。 
3. ソートされた配列の対応する要素を左から右に比較します。 各位置について、ターゲット値がソース値以上であるかどうかを確認します。 いずれかのターゲット値が小さい場合、一連の +1 操作ではこれを修正できません。 
4. 各ペアについて、差を計算します。 各要素は最大 1 回だけ増分できるため、すべての差は 0 または 1 でなければなりません。 
5. +1 の差の合計数が、前に計算した合計の差と一致することを確認します。 

この決定は、ローカルな実現可能性 (各要素は 1 つだけ増加できる) とグローバルな実現可能性 (合計増分が必要な合計増加と一致する必要がある) の間の一貫性によって決まります。 

### なぜ効果があるのか

 並べ替え後、使用可能な最小値を組み合わせます。 ターゲット配列内の小さい要素がソースの大きい要素とペアになっている場合、より大きなソース要素はすべて将来のペアリングを悪化させるだけであるため、スワップ パートナーは不一致を修正できません。 この貪欲な配置により、有効な変換が存在する場合、それが並べ替えられた順序のペアに表示されるようになります。 各要素は 1 ずつしか増加できないという制限により、ソートされたペアの位置ごとにバイナリの選択が強制され、これが変換を完全に特徴づけます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        
        a.sort()
        b.sort()
        
        diff_sum = 0
        ok = True
        
        for i in range(n):
            if b[i] < a[i]:
                ok = False
            diff_sum += (b[i] - a[i])
            if b[i] - a[i] > 1:
                ok = False
        
        print("YES" if ok and diff_sum == sum(b) - sum(a) else "NO")

if __name__ == "__main__":
    solve()
```解決策は、両方の配列を並べ替えて、それらをマルチセットとして推論できるようにすることから始まります。 次にループは、ターゲット値がそのペアのソース値より小さいかどうか、およびターゲットに到達するために複数の増分が必要な要素があるかどうかという 2 つの制約を同時にチェックします。 累積された差分は、この組み合わせに従った場合に必要な +1 操作の数を追跡します。 

最終的な比較では、ローカル制約と、正確に一致するグローバル要件との間の一貫性が保証されます。`sum(b) - sum(a)`増分を実行する必要があります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = []
    
    t = int(sys.stdin.readline())
    for _ in range(t):
        n = int(sys.stdin.readline())
        a = list(map(int, sys.stdin.readline().split()))
        b = list(map(int, sys.stdin.readline().split()))
        
        a.sort()
        b.sort()
        
        ok = True
        total_diff = 0
        
        for i in range(n):
            if b[i] < a[i]:
                ok = False
            if b[i] - a[i] > 1:
                ok = False
            total_diff += (b[i] - a[i])
        
        required = sum(b) - sum(a)
        output.append("YES" if ok and total_diff == required else "NO")
    
    return "\n".join(output)

 ## 特殊なケース

 一般的なエッジ ケースは、差の合計が要素の数と一致するが、1 つの要素に複数の増分が必要な場合です。 たとえば、変形する`[0, 0]`の中へ`[2, 0]`は等しい和の差 2 を持ちますが、単一の要素に 2 つの増分が必要になるため、やはり失敗します。 ソートすると、1 つのペアが次のペアになるため、この失敗がすぐに見えるようになります。`(0, 2)`。 

もう 1 つのエッジ ケースは、値が合計では等しいが、局所的には一致しない場合に発生します。 例えば、`[1, 3]`に`[2, 2]`合計は保持されますが、ソートされたペアリングでは`(1, 2)`そして`(3, 2)`、ターゲットがソースより小さい場合の違反が明らかになり、順列では修復できません。 

このアルゴリズムは、要素ごとのローカルな実現可能性と、合計の追跡によるグローバルな一貫性の両方を強制するため、両方のケースを正しく拒否します。
