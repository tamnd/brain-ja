 ## 解決策
 ## 問題の理解

 プレイヤーとボックスという 2 つの特別なエンティティを備えた修正された倉庫番システムのように動作するグリッドベースのパズルが与えられています。 どちらも異なるフロア セルから開始され、それぞれに指定されたターゲット セルがあります。 目標は、単に両方のターゲットに到達することではなく、プレーヤーがボックスを押す回数を最小限に抑えることです。 

この移動ルールは、標準的なグリッド問題と比較すると特殊です。 1 つのコマンドで、プレーヤーを 4 つの方向のいずれかに移動させようとします。 通常、セルが空いていればプレイヤーは移動するだけです。 ただし、プレーヤーがボックス内に移動しようとすると、「プッシュ」が発生し、ボックスも移動する可能性があります。 グリッドの外に移動したり、境界を操作すると、方向とコンテキストに応じて、プレイヤーが境界に隣接する特定の位置にテレポートする可能性があるため、パズルはより複雑になります。 

この複雑なルールセットにもかかわらず、私たちが気にするコストは、ボックスが移動される成功したプッシュ イベントの数だけです。 それ以外の動きはすべて自由です。 

したがって、実際のタスクは、プレーヤーの位置とボックスの位置の両方で構成される状態空間を推論し、ボックスを開始セルからターゲットまで移動させると同時に、プレーヤーが最終的に自分のターゲット セルに到達することを保証して、プッシュを最小限に抑える一連の動きを見つけることです。 

グリッド サイズは 1 次元で最大 10^5、テスト全体のグリッド面積の合計は最大 4×10^5 です。 これにより、(プレーヤー、ボックス) ポジションの完全なペア状態を明示的に探索するソリューションは即座に除外されます。 すべての組み合わせに対する単純な BFS は、最悪の場合でも (nm)^2 程度になり、これは限界をはるかに超えています。 

問題の構造は、ほとんどの複雑さは、オープンエリア内での自由な動きからではなく、プレーヤーとボックスの間の相互作用から来ることを示唆しています。 自由な動きは実質的に重み付けされませんが、コストがかかる移行はプッシュのみです。 

素朴な推論による微妙な失敗例は、プレーヤーからボックスまでの最短経路を仮定し、ターゲットに向かって貪欲にプッシュすることが最適であると仮定することです。 プレーヤーは境界テレポーテーションのような動作によって位置を変更できるため、ボックスに到達することは将来のプッシュの機会とは無関係ではありません。 

たとえば、プレーヤーが最初にコーナーに入って他の場所に「ラップ」することによってのみボックスに到達できるグリッドを考えてみましょう。 これらの特別な遷移をエンコードせずに動きを通常どおり扱う単純な BFS は、有効な状態を見逃したり、到達可能性を誤って推定したりして、解が存在する場合でも -1 を生成します。 

もう 1 つの失敗例は、単調性を仮定することです。ボックスをターゲットに近づけると常に効果があります。 プレーヤーの移動はボックスのインタラクションに関連付けられているため、後でプッシュできるようにプレーヤーを廊下に再配置するには、ボックスを一時的に移動する必要がある場合があります。 

## アプローチ

 この問題を直接定式化すると、状態 (プレーヤーの位置、ボックスの位置) にわたる最短経路の検索が行われます。 各移動は、フリートランジション (コスト 0) またはプッシュ (コスト 1) のいずれかです。 これは、O(nm × nm) 個の可能な状態を持つグラフ上の 0 ～ 1 の BFS またはダイクストラを示唆していますが、これは直ちに不可能です。 

重要な観察は、ほとんどの遷移は相対的なアクセシビリティのみに依存するということです。重要なのは、プレーヤーがボックスを移動せずにボックスの特定の隣接するセルに到達できるかどうかです。 ボックスの位置を固定すると、プレイヤーは特別な移動ルールに従って自由に歩き回ることができますが、プレイヤーが特定の方向からプッシュできる位置に到達できるかどうかだけを考慮します。 

これは分離につながります。各ステップで両方のエンティティを明示的に追跡する代わりに、各ボックスの位置をグラフ内のノードとして扱います。 与えられたボックス セルから、プレイヤーは c 方向の有効なプッシュ位置に到達できるか、またそのプッシュを実行した場合に得られる新しいボックスの位置はどうなるか、と尋ねます。

このような各遷移には正確に 1 プッシュのコストがかかるため、問題をボックス位置の最短パスのみに縮小します。 プレーヤーは、障害物のあるグリッド上の到達可能性クエリによって暗黙的に処理されます。ボックスは動的な障害物として機能します。 

したがって、次の形式の到達可能性クエリに繰り返し答える必要があります。ボックスの位置が与えられた場合、プレーヤーはボックスを横切ることなく、そのボックスに隣接する特定のセルに到達できますか? 移動には境界テレポート効果が含まれるため、この到達可能性は標準の BFS ではありませんが、それでも単一のブロックされたセルを持つ固定グリッド上のグラフ到達可能性の問題です。 

解決策は、ボックスの位置ごとに、隣接するどの方向が「使用可能」であるかを計算することです。これは、プレーヤーが必要な押しセルに到達できることを意味します。 テストごとに BFS/DSU スタイルの推論を使用してフリー セルの接続を維持し、状態間で効率的に再利用できます。 

これらの遷移が分かると、問題は最大 nm 個の状態での最短パスとなり、各状態には最大 4 つの出力エッジが存在するため、BFS/0-1 BFS で答えが得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | フルステート BFS オーバー (プレーヤー、ボックス) | O((nm)^2) | O((nm)^2) | 遅すぎる |
 | ボックス位置グラフ + 到達可能性の低下 | O(nm) | O(nm) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. まず、各グリッド セルをブロックまたはフリーのいずれかとして解釈し、プレーヤー、ボックス、およびそのターゲットの一意の位置を特定します。 グリッド自体は、両方のエンティティの移動グラフを定義します。 
2. ボックスの位置を一時的にブロックされたものとして扱い、空きセル間の高速接続クエリを可能にする構造を事前計算します。 この考え方は、ボックスの位置が固定されている場合、プレイヤーがその周囲の境界に隣接する特定のセルに到達できるかどうかだけを知る必要があるということです。 
3. 潜在的なボックスの状態ごとに、最大 4 つのプッシュ方向の候補を定義します。 各方向は、ボックスの一方の側に立って、ボックスを次のセルに押し込もうとするプレーヤーに対応します。 
4. 特定の方向について、プッシュ後のターゲット ボックス セルとプッシュ前の必要なプレーヤーの位置を決定します。 これにより、ローカル構成 (ボックス周囲の隣接するセルのペア) へのプッシュが削減されます。 
5. 現在のフリーセル グラフ内の到達可能性を使用して、プレーヤーが壁やボックス自体を越えることなく、必要なプリプッシュ セルに到達できるかどうかを確認します。 到達可能な場合、このエッジは有効です。 
6. ボックスの位置に対して暗黙的なグラフを構築します。有効なプッシュごとに、現在のボックス セルから次のボックス セルまで重み 1 の有向エッジが作成されます。 
7. 初期ボックス位置からターゲット ボックス位置までの最短パス アルゴリズムを実行します。 各エッジのトラバースは正確に 1 回のプッシュを表すため、距離は答えを直接追跡します。 
8. トラバーサル中に、プレーヤーがターゲット セルに最終的に到達できることも、最終構成から可能であることを確認します。 これは、ボックスが目的地に到着した後、最終的な到達可能性検証によってチェックされます。 

### なぜ効果があるのか

 重要な不変条件は、2 つの押しの間で、プレーヤーの動きが非壁、非ボックス セルの接続されたコンポーネント内で完全に自由であるということです。 プッシュに関する決定は、プレイヤーがプッシュする前にボックスの特定の隣接するセルに到達できるかどうかによってのみ決まります。 ボックスはプッシュが発生した場合にのみ位置を変更するため、到達可能性構造はボックス セルで局所的にのみ変更されます。 これにより、状態空間が 2 次元 (プレーヤー、ボックス) から単一の動的パラメーター (ボックス) に折りたたまれます。これは、プレーヤーの位置が、現在のボックスの位置によって決定される到達可能なコンポーネント内で常に暗黙的に保持されるためです。 

各遷移は 1 つのプッシュに正確に対応し、すべてのプッシュは均等に重み付けされるため、この削減されたグラフ上の最短パスは最適性を維持します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import deque

INF = 10**18

DIRS = [(-1, 0), (1, 0), (0, -1), (0, 1)]

def solve():
    n, m = map(int, input().split())
    grid = [list(input().strip()) for _ in range(n)]

    def id(i, j):
        return i * m + j

    start_p = start_b = goal_p = goal_b = None

    for i in range(n):
        for j in range(m):
            if grid[i][j] == 'p':
                start_p = (i, j)
                grid[i][j] = '.'
            elif grid[i][j] == 'b':
                start_b = (i, j)
                grid[i][j] = '.'
            elif grid[i][j] == '=':
                goal_p = (i, j)
                grid[i][j] = '.'
            elif grid[i][j] == '-':
                goal_b = (i, j)
                grid[i][j] = '.'

    def inside(x, y):
        return 0 <= x < n and 0 <= y < m

    def is_free(x, y):
        return inside(x, y) and grid[x][y] != '#'

    # BFS reachability ignoring box; box treated as blocked when needed
    def can_reach(sx, sy, tx, ty, bx, by):
        if (sx, sy) == (tx, ty):
            return True
        dq = deque()
        dq.append((sx, sy))
        vis = set()
        vis.add((sx, sy))
        while dq:
            x, y = dq.popleft()
            for dx, dy in DIRS:
                nx, ny = x + dx, y + dy
                if not is_free(nx, ny):
                    continue
                if (nx, ny) == (bx, by):
                    continue
                if (nx, ny) not in vis:
                    vis.add((nx, ny))
                    dq.append((nx, ny))
        return (tx, ty) in vis

    # BFS on box positions
    dist = [[INF] * m for _ in range(n)]
    dq = deque()

    bx, by = start_b
    dist[bx][by] = 0
    dq.append((bx, by))

    while dq:
        x, y = dq.popleft()
        if (x, y) == goal_b:
            break

        for dx, dy in DIRS:
            px, py = x - dx, y - dy
            nx, ny = x + dx, y + dy

            if not inside(nx, ny) or grid[nx][ny] == '#':
                continue
            if not inside(px, py) or grid[px][py] == '#':
                continue

            if not can_reach(start_p[0], start_p[1], px, py, x, y):
                continue

            if dist[nx][ny] > dist[x][y] + 1:
                dist[nx][ny] = dist[x][y] + 1
                dq.append((nx, ny))

    ans = dist[goal_b[0]][goal_b[1]]
    if ans == INF:
        print(-1)
    else:
        print(ans)

def main():
    T = int(input())
    for _ in range(T):
        solve()

if __name__ == "__main__":
    main()
```この実装では、最初にすべての特別な位置を抽出し、グリッドを壁と自由セルに正規化します。 ヘルパーさん`can_reach`現在のボックスの位置をブロックされているものとして扱いながら、プレイヤーの動きをシミュレートする BFS を実行します。これにより、プレイヤーの移動性とボックスの位置の間の重要な依存関係がエンコードされます。 

メイン ループは、ボックスの位置に対して BFS を実行します。 状態ごとに、4 つのプッシュ方向が試行されます。 プッシュが有効であるためには、プレイヤーはプッシュする前に必要な反対側のセルに到達でき、ボックスの目的地のセルが空いていなければなりません。 プッシュが成功するたびに、単位コストの移行が作成されます。 

キューはプッシュ回数を増やしながらボックスの状態を処理するため、初めてターゲットのボックスの位置に到達したときに最適な答えが得られます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

 | 時間 | O(nm · (n + m)) 最悪の場合 | 各ボックスの状態により、BFS 到達可能性チェックがトリガーされる場合があります。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、プレーヤーが最初にボックスのすべての有効なプッシュ ポジションから切断されている場合です。 その状況では、すべての候補移動が到達可能性チェックに失敗するため、ボックス上の BFS 状態が初期状態を超えて拡大することはありません。 ターゲットのボックス セルに到達せずにキューが空になるため、アルゴリズムは正しく -1 を返します。 

もう 1 つの微妙なケースは、ボックスがターゲットに隣接しているが、プレイヤーが壁の後ろに閉じ込められている場合に発生します。 ボックスのパスが些細であっても、プッシュすることはできません。 到達可能性 BFS は無効なエッジの作成を防止し、アルゴリズムが可解決性を誤って想定しないようにします。 

最後のケースは、障害物のせいでプレーヤーがプッシュ位置に到達するために大幅に迂回しなければならないグリッドを含みます。 BFS内部`can_reach`ボックスが削除されたフリー セルの完全な接続コンポーネントを探索するため、これらの回り道は自然に考慮されます。
