 ## 解決策
 ## 問題の理解

 私たちは、1 から n までの隠された「秘密タイプ」を持つシステムをシミュレートする一連の操作を構築しています。 いつでも、ゾーンには現在一連のシークレットが存在します。 ただし、決定的に複雑なのは、それぞれの秘密が実際には分からないことです。`add`を指します。 それぞれ`add`未知のシークレット タイプが 1 つ導入されていますが、後でこれらの追加に実際の数値を一貫して割り当てることができるようにする必要があります。`test`動作は満足です。 

あ`test x y`クエリは強制観察のように動作します。y = 1 の場合、シークレット x はテストの直前に存在する必要があり、削除されます。 y = 0 の場合、秘密 x はテストの直前に存在していなければなりませんが、結果に関係なく、x が存在した場合は削除されます。 重要な点は、シーケンス全体の有効性が、への代入に対して存在的に定義されていることです。`add`操作: テストによって課されるすべての制約が満たされるように、すべての追加に実際のシークレット ID を割り当てることができなければなりません。 

演算の各接頭辞を処理した後、有効な割り当てが存在しない場合は最後の演算を拒否するか、制約によってすでに強制されている内容を説明する 2 つの量を報告する必要があります。 最初の数値は、すべての有効な割り当てにおいて、その時点でゾーンに存在することが保証されているシークレット タイプの数です。 2 番目の数字は、欠席が保証される人数です。 

制約は大きく、テスト ケース全体の n と q の合計は最大 100,000 です。これにより、クエリごとに一貫性を最初から再計算しようとするソリューションや、代入を明示的にシミュレートするソリューションが除外されます。 イベントごとにほぼ一定または対数的な作業を伴う増分メンテナンスが必要です。 

微妙な問題は、「存在しなければならない」と「存在してはいけない」は、1 つの割り当ての実際の状態ではなく、考えられるすべての割り当てにわたってグローバルであるということです。 それぞれに対して貪欲な割り当てを選択する単純なシミュレーション`add`失敗します。 

典型的な失敗例は、複数の場合です。`add`操作は同じシークレット タイプに対応する可能性がありますが、後で矛盾するテストによって強制的に分離されます。 たとえば、初期の`add`、 に続く`test 1 0`、そしてその後`test 1 1`各操作がローカルでは有効に見えても、シーケンスが不可能になります。 

## アプローチ

 ブルートフォースアプローチでは、すべてのユーザーに秘密の番号を割り当てようとします。`add`表示されたらすぐに、割り当ての可能性ごとにゾーンの完全なシミュレーションを維持します。 これはすぐに指数関数的になります。`add`最大 n 個の選択肢に分岐し、それ以降も`test`操作によりこれらの選択肢が取り除かれます。 可能な割り当てのセットを維持しようとしても、状態空間は組み合わせ的に拡大します。 q が 100000 までの場合、これは不可能です。 

重要な点は、実際には割り当て全体を追跡する必要がないということです。 それぞれ`add`新鮮な未知のトークンを導入し、それぞれ`test x y`x を最新の未解決の構造に関連付ける制約を課します。 具体的な割り当てを追跡する代わりに、すべての一貫した割り当てにわたって、確実に存在する、または絶対に存在しないことが強制されるシークレットの数を追跡できます。 

これにより、問題は、部分的に順序付けされた構造に対する一貫性制約の維持に変わります。 それぞれ`add`は新しい変数です。 それぞれ`test x y`存在または不在を確認し、テストに一致する場合はその変数の最後の出現も解決します。 このプロセスは、追加の強制状態伝播を除いて、制約付きシーケンスの検証と同様の方法で、未解決の追加のスタックを維持し、それらをテストと照合するように動作します。 

重要な考え方は、シークレットの種類ごとに、観察されたすべての制約と一貫してシークレットを割り当てることが可能かどうかを維持することです。 また、矛盾を早期に検出するグローバル構造を維持しているため、制約を満たせない場合にはすぐに「バグ」を出力できます。 

妥当性が確認されたら、どのシークレット タイプが制約によってすでに決定されているかを追跡することによって強制状態を計算できます。すべての一貫した割り当てでゾーンにシークレットを配置する必要がある場合、シークレットは強制的に存在し、すべての割り当てで除外する必要がある場合は強制的に不在になります。 これは、タイプごとに、有効な割り当てでまだ「生きている」かどうかを追跡することになります。 

カウントは増分的に維持されます。制約によって型が存在する可能性がすべて排除されると、その型は強制的に存在しなくなります。 未解決のマッチング制約により構造が存在を保証する場合、構造は強制的に存在します。 データ構造は、アクティブな制約に対するブックキーピングを使用して、操作ごとに O(1) で償却されます。

 ## アルゴリズムのチュートリアル

 シーケンスを成長するプレフィックスとして扱い、未解決の構造を維持します。`add`イベントとそれによって引き起こされる一貫性制約`test`イベント。 

1. 私たちは保留中のスタックを維持します`add`それぞれの操作は、まだ具体的なアイデンティティに強制されていない、未知の秘密の出来事を表しています。 このスタックは、追加が新しい制約付き変数を導入するように動作するという事実を反映しています。 
2. 各シークレット タイプについて、それが現在強制的に存在するか、強制的に存在しないか、またはまだ未決定であるかを維持します。 最初はすべての秘密は未決定です。 
3. 処理するとき`add`、新しい未解決のノードをスタックにプッシュします。 この時点では、アイデンティティはまだ自由であるため、秘密は強制されません。 
4. 加工する場合`test x 1`、テストの直前に x が存在することが必要です。 これにより一貫性が強制されます。x は、この要件に法的に一致する未解決の追加に対応する必要があります。 最新の互換性のある未解決の追加を x に解決します。 そのような一致が存在しない場合、シーケンスは無効です。 
5. 処理する場合`test x 0`、x が存在しないことが必要です。 現在の未解決の構造が x が存在しなければならないことを暗示している場合 (x がすでに強制されているか避けられないため)、矛盾を検出して拒否します。 それ以外の場合は、この制約に違反する将来の追加に x を割り当てることができないことを単にマークします。 
6. 操作が成功するたびに、強制カウントを更新します。 シークレットを割り当てるすべての方法が事前の制約によって排除されている場合、シークレットは強制的に削除されます。 シークレットは、それが未解決の構造の唯一残っている候補である場合、またはそのアイデンティティを修正する方法でテストによって一致した場合に、強制的に存在します。 
7. いずれかのステップで矛盾が検出された場合、現在のイベントを削除し、「バグ」を出力します。 それ以外の場合は、強制的に存在するシークレットと強制的に存在しないシークレットの数を出力します。 

### なぜ効果があるのか

 このアルゴリズムは、抽象的な追加イベントと具体的な秘密 ID の間の一貫した部分的な割り当てを維持しながら、テスト制約がバインドされるとすぐに強制します。 不変条件は、すべての未解決の追加が、過去のすべてのテストと一致する何らかのシークレット タイプに依然としてマッピングできる、少なくとも 1 つの実行可能な割り当てに対応するということです。 テストでマッピングが強制または禁止されると、実行可能なマッピング空間が更新されます。 必要な制約に対してそのスペースが空になると、不可能であることが正しく検出されます。 強制カウントは、残りのすべての有効な割り当ての共通部分から導出されるため、強制存在または強制不在としてカウントされるシークレットは、すべての一貫した完了にわたって同じ状態でなければなりません。

 ## 特殊なケース

 主なエッジケースは次のような場合です。`test x 1`何の前触れもなく現れる`add`。 x にマッピングできる未解決のイベントがないため、アルゴリズムは直ちに拒否する必要があります。 これにより、何もないところから暗黙的に割り当てを作成することがなくなります。 

もう 1 つのエッジ ケースは、次のような矛盾する制約を交互に適用することです。`test x 1`その後に続いて`test x 0`。 最初の強制は存在を強制し、2 番目の強制は不在を強制します。システムは、複数の未解決の追加が存在する場合でも、この競合を伝播する必要があります。 このアルゴリズムは、シークレットがある状態に固定されると、その後の操作で無効化をトリガーせずにその状態を元に戻すことができないようにすることで、これを処理します。 

最後の微妙なケースは、多くの場合に発生します。`add`操作はテストの前に蓄積されます。 それらはすべてあいまいなままであるため、強制カウントはゼロのままでなければなりません。 テストによって ID が解決された後にのみ、強制的な存在または不在が表示され始めるため、時期尚早のカウントが防止されます。
