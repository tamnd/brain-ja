 ## 解決策
 ## 問題の理解

 2 つの整数シーケンスが与えられていますが、どちらのシーケンスも直接提供されません。 代わりに、両方とも、固定値を法とする同じ二次漸化式を繰り返し適用することによって生成されます。 まずシーケンス全体を生成します`s`長さの`n`、同じ繰り返しを続けて生成します`t`長さの`m`何もリセットせずに。 これにより、`t`生成したのと同じ基礎となるストリームの継続`s`。 

タスクは、両方に現れる最長のサブシーケンスの長さを計算することです。`s`そして`t`、各シーケンス内で順序を保持する必要がありますが、要素が連続している必要はありません。 

制約の観点から見ると、テスト ケース全体のすべてのシーケンスを合計した長さは最大 100 万です。 これにより、位置のペアに対する二次動的計画法は即座に除外されます。これは、最悪の場合のテストが 1 つだけでも、そのアプローチでは時間制限を数桁超えてしまうためです。 解は、生成される要素の総数が線形または線形に近い必要があり、場合によっては対数係数が使用されます。 

微妙な点は、生成プロセス自体に由来します。 どちらのシーケンスも単一の反復チェーンから来ているため、`s`は`A[1..n]`そして`t`は`A[n+1..n+m]`単一の非表示配列の場合`A`。 この構造は、2 つのシーケンスを独立したものとして扱うことを回避するための鍵となります。 

失敗することが多い単純な試みは、標準の LCS 動的プログラミングを実行したり、同じ値を貪欲に一致させようとしたりすることです。 これらは両方とも、繰り返される値が誤ったペアリングの決定を強制する単純なケースでは機能しません。 たとえば、次の場合`s = [1, 1]`そして`t = [1, 1]`、正解は 2 ですが、実装によっては、最初の出現の貪欲一致により簡単に 1 が生成される可能性があります。 

値が頻繁に繰り返される場合、別の故障モードが発生します。 もし`s = [5, 5, 5]`そして`t = [5, 5, 5, 5]`、答えは 3 ですが、グローバルな順序付けを強制しない単純なペアリング戦略では、一致がどのように消費されるかに応じて、過大カウントまたは過小カウントされる可能性があります。 

主要な問題は、それぞれの値が両方のシーケンスで何度も出現する可能性があることです。そのため、問題は等価性チェックだけではなく、グローバルに一貫した増加ペアの選択にあります。 

## アプローチ

 直接動的プログラミング ソリューションでは次のことが定義されます。`dp[i][j]`プレフィックスの LCS として`s[1..i]`そして`t[1..j]`。 これが機能するのは、すべての選択が 1 つのシーケンス内の要素をスキップするか、等しい要素に一致するためです。 ただし、これには次のことが必要です`O(nm)`これは、両方のシーケンスの長さが最大 ​​100 万に達する場合には不可能です。 

重要な観察は、2 つのシーケンスが任意ではないということです。 これらは、同じ生成された配列の 2 つの連続したセグメントにすぎません。`A`。 これは、次の間のすべての一致を意味します。`s`そして`t`インデックスのペアに対応します`(i, j)`そのような`i < j`そして`A[i] = A[j]`、両方の次元で順序を維持するようなペアのセットを選択する必要があるという追加の制約があります。 

これにより、問題は、部分的に順序付けされたセット内の点の最大チェーンを見つけることに変換されます。ここで、各点は、次のインデックス間の有効な等価性になります。`s`そしてインデックス`t`。 このような問題を解決する標準的な方法は、一方の次元で順序付けしながら、他方の次元で増加する最長のサブシーケンスに変換することです。 

具体的には、インデックスを処理します。`s`昇順で。 それぞれの値について`v = s[i]`、私たちはすべての位置を知っています`t`同じ値が発生する場所。 そういったポジションごとに`j`で終わるサブシーケンスの拡張を試みることができます。`j`前に終了する最適なサブシーケンスを使用する`j`。 

これを効率的にサポートするために、私たちはポジション全体にわたってフェンウィック ツリーを維持します。`t`、各インデックスには、その位置で終わる最適な LCS 長さが格納されます。 からの各要素`s`の複数のポジションの更新に貢献します`t`、各更新はプレフィックス クエリに依存します。`t`。 

主な問題は、値が何度も出現する可能性があることです。`t`ただし、入力サイズの合計はすべてのテストで 100 万に制限されているため、すべての出現を反復処理することは、集計的には引き続き実行可能です。

 ## アルゴリズムのチュートリアル

 生成プロセス全体を単一の配列の生成として扱います。`A`、 どこ`s = A[1..n]`そして`t = A[n+1..n+m]`。 

1. 各値の位置を`t`。 あらゆるインデックスに対して`j`で`t`、追加します`j`をキーとしたリストに`A[j]`。 これにより、2 番目のセグメントで値が発生する場所を高速に検索できます。 
2. のインデックスに対してフェンウィック ツリーを初期化します。`t`ここで、各位置は、その位置で終わる最適な LCS 長さを表します。 最初はすべての値がゼロです。 
3. 各要素を反復処理する`s[i]`順番に。 現在の値については`v = s[i]`、内のすべてのポジションのリストを取得します。`t`どこ`A[j] = v`。 
4. それぞれのポジションについて`j`、計算する`best = query(j - 1) + 1`、 どこ`query(j - 1)`位置の直前で終了する最良のサブシーケンスを返します`j`で`t`。 これにより、2 番目のシーケンスで昇順が確実に保持されます。 
5. この値のすべての候補更新を計算した後、それらをフェンウィック ツリーに適用します。 クエリと更新がこのように分離されているため、同じクエリからの更新を使用できなくなります。`s[i]`一貫性のない方法で複数回。 
6. これまでにフェンウィック ツリーに書き込まれた最大値を追跡します。 これが最終的な答えです。 

クエリと更新をそれぞれの中で分離する`s[i]`同じ値が複数出現するため、これは必須です。`t`の 1 つのステップ内で相互に連鎖してはなりません。`s`。 

### なぜ効果があるのか

 すべての有効な共通サブシーケンスはペアの選択に対応します`(i, j)`両方のシーケンスのインデックスが増加するようにします。 フェンウィック ツリーは、一致する位置を配置するときに、`j`で`t`、厳密に前で終了するサブシーケンスのみを拡張します。`j`。 処理`s`順序により、インデックスが`s`も増えています。 これにより、等しい値で定義された 2 部マッチング グラフ内の有効な増加チェーンのセットが正確に構築されます。 

すべての遷移は順序付け制約の両方を尊重し、一致するペアを段階的に選択することですべての有効なサブシーケンスを構築できるため、保存される最大値は正確に LCS 長になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def update(self, i, v):
        while i <= self.n:
            if v > self.bit[i]:
                self.bit[i] = v
            i += i & -i

    def query(self, i):
        res = 0
        while i > 0:
            if self.bit[i] > res:
                res = self.bit[i]
            i -= i & -i
        return res

def solve():
    T = int(input())
    for _ in range(T):
        n, m, p, x, a, b, c = map(int, input().split())

        s = [0] * n
        t = [0] * m

        for i in range(n):
            x = (a * x * x + b * x + c) % p
            s[i] = x

        pos = {}
        for i in range(m):
            x = (a * x * x + b * x + c) % p
            t[i] = x
            if x not in pos:
                pos[x] = []
            pos[x].append(i + 1)

        fw = Fenwick(m)
        ans = 0

        for i in range(n):
            v = s[i]
            if v not in pos:
                continue

            updates = []
            for j in pos[v]:
                best = fw.query(j - 1) + 1
                updates.append((j, best))

            for j, val in updates:
                fw.update(j, val)
                if val > ans:
                    ans = val

        print(ans)

if __name__ == "__main__":
    solve()
```このソリューションは、複数のポジションにわたってフェンウィック ツリーを慎重に維持します。`t`。 各クエリ ステップでは、現在の値と一致することで拡張できる最適なサブシーケンスが計算されます。`s`での出来事に`t`。 

微妙な実装要件は、次の値ごとに更新をバッファリングすることです。`s[i]`。 これを行わないと、位置を反復しながらフェンウィック ツリーを更新します。`t`同じ値が後で出現すると、同じ反復による以前の更新に誤って依存する可能性があります。 

フェンウィック ツリー内のすべてのインデックス付けは 1 から始まりますが、`t`プレフィックス クエリでのオフバイワンの間違いを避けるために、1 から始まる位置で保存されます。
