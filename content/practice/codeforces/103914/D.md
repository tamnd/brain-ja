 ## 解決策
 ## 問題の理解

 既知の 10 枚のカードが関与する完全なポーカー状況が与えられます。 アリスは 2 枚のプライベート カードから開始し、ボブは 2 枚のプライベート カードから開始します。テーブルには 6 枚の共有コミュニティ カードがあります。 プレイヤーは未知のデッキからドローするのではなく、すべてがすでに明らかにされています。 

ゲームはターン制で進行します。 アリスが最初に動き、2 人のプレイヤーが 6 枚のコミュニティ カードから 1 枚のカードを交互に取り、6 枚すべてが揃うまでカードを取ります。 したがって、各プレイヤーは、最初の 2 枚のプライベート カードと、選択した 3 枚のコミュニティ カードを組み合わせて、合計でちょうど 5 枚のカードを持つことになります。 すべてのピックが完了した後、テキサス ホールデムと同じ厳密なランキング システムを使用して両プレイヤーの最終的な 5 枚のカード ポーカー ハンドが評価され、最終的なハンド ランクを比較することによって勝者が決定されます。 両方のハンドの強さとタイブレーク表現が同じ場合、結果は引き分けになります。 

主な難点は、カード選択がインタラクティブであることです。 「常に自分にとって最良のカードを選択する」などの貪欲な選択は、それぞれのピックが両方のプレイヤーの将来の選択肢を変えるため、失敗します。 両方のプレーヤーがすべてのカードを見て最適にプレイするため、問題は基本的に 6 つのアイテムの非常に小さな共有プールをめぐる完全情報ゲームになります。 

制約はサイズではなく構造において非常に厳しいものです。 各テスト ケースには合計 10 枚のカードのみが含まれており、実際の分岐は 6 枚のコミュニティ カード上でのみ発生します。 これにより、単純な方法で完全なカード割り当てに対する階乗または N の指数解がすぐに除外されますが、3^6 は小さく 6 であるため、6 を超える指数は許容されることも強く示唆されます。 たったの720です。 

微妙な点は、最終的な評価が単純なスコアリングの意味で対称的ではないことです。 各プレイヤーに部分的な状態ごとに数値スコアを割り当てることはできません。結果は選択した 3 枚のカードとプライベート カードの組み合わせによって決まり、ポーカー ハンドの比較は構造化されたパターンに対する辞書編集的なものであり、加算的なものではないからです。 

エッジケースは主にタイルールと特殊なストレート処理から発生します。 

一例として、ホイールは真っ直ぐです。 

入力:

 アリス：A5

 ボブ: K Q

 コミュニティ: 2 3 4 6 7 8

 Ace を高いものとしてのみ扱う単純な評価者は、A-2-3-4-5 が特別な順序ルールを持つ有効なストレートおよびストレート フラッシュのバリアントであることを見落とすでしょう。 

正しい動作には、A が特定の直線パターンでハイにもローにも動作できることを認識する必要があります。 

もう 1 つのエッジ ケースは、同一のベスト ハンド構造です。 

入力:

 アリス：あ、あ

 ボブ: K K

 コミュニティ: A K Q J T 9

 どちらのプレイヤーも非常に強力なハンドを形成する可能性がありますが、勝者は、「同一でない限りロイヤル フラッシュが常に勝つ」などの非公式の直感ではなく、エンコードされたハンド ランクの辞書編集上の正確な比較に依存します。 

## アプローチ

 強引なアイデアは、6 枚のコミュニティ カードが 3 対 3 に分けてアリスとボブに分配されるあらゆる方法をシミュレートすることです。 がある$\binom{6}{3} = 20$このようなパーティション。 各パーティションについて、アリスの 2 枚のプライベート カードと選択した 3 枚のコミュニティ カードからアリスのベスト ハンドを計算し、同様にボブのベスト ハンドを計算し、結果を比較します。 これは有望に思えますが、実際の交互ターン順序の制約は無視されます。 パーティションの合法性は、最適なプレイでパーティションが発生することを保証するものではありません。選択の順序が重要であるためです。パーティション内で最終的にボブが入ったカードは、アリスが先にそれをプリエンプトできた場合、決して到達できない可能性があります。 

コミュニティ プールは小さいため、ゲームを完全な情報の逐次割り当てプロセスとしてモデル化できるというのが正しい観察です。 6 枚のコミュニティ カードはそれぞれアリスまたはボブのいずれかに割り当てられますが、割り当ては順番に交互に行われます。 これにより、問題は、部分的に割り当てられたカードの状態に関するゲームに変換されます。 

各カードは、未割り当て、アリスによって取得された、またはボブによって取得された 3 つの状態のいずれかになるため、合計の状態空間は次のようになります。$3^6 = 729$、これは徹底的な動的プログラミングには十分小さいです。 

次に、この状態空間に対してミニマックス検索を実行します。 各状態で、誰のターンに応じて、残りの 1 枚のカードをそのプレイヤーに割り当てて再帰的に試みます。 最終状態では、両プレイヤーの最終的な 5 カード ポーカー ハンドを評価し、比較します。 

単純なパーティショニングに対する主な改善点は、考えられるすべての最適なプレイ結果をカバーしながら、ターン順序を尊重して有効なピックのシーケンスのみを探索することです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | ブルートフォースパーティショニング | O(20・手の評価) | お(1) | モデルが間違っています (ゲーム順序を無視します) |
 | 代入に対するミニマックス | O(3^6 · 遷移) | O(3^6) | 承認済み |

 ## アルゴリズムのチュートリアル

 6 つのコミュニティ カードをインデックス 0 ～ 5 に圧縮します。各状態は、各カードが割り当てられていないのか、アリスによって取得されたのか、またはボブによって取得されたのかを追跡します。 また、誰のターンであるかを追跡します。これは、すでに割り当てられているカードの数から導き出すことができます。 

### ステップ

 1. 各カードをランク値とスートにエンコードし、エースロー ストレートの特別ルールでランク A、K、Q、J、T、9、…、2 を整数に変換します。 これにより、後でポーカー ハンドを迅速に評価できます。 
2. ちょうど 5 枚のカードが与えられた場合に、可能な限り最高の 5 枚カードのポーカー ハンドを評価する関数を定義します。 この関数は、ストレート フラッシュ、フォー オブ ア カインド、フルハウス、フラッシュ、ストレート、スリー オブ ア カインド、ツー ペア、ペア、ハイ カードの中で最も強いパターンを計算し、同等のタプルを返します。 タプルは、辞書編集的な比較がポーカー ルールと正確に一致するように構築されています。 
3. タプル表現を使用して 2 つのハンドの比較を事前計算または直接実装し、A-2-3-4-5 の特別な処理を含む、タイブレークが正確な順序付けルールに従うことを保証します。 
4. ゲームの状態を 6 つのポジションにわたる Base-3 エンコーディングとして表現します。 各位置には、未使用の場合は 0、アリスの場合は 1、ボブの場合は 2 が格納されます。 
5. 再帰関数を定義する`dp(state)`これは、最適なプレイを想定したアリスの視点からの最終結果を返します。 結果は、アリスが勝った場合は 1、引き分けの場合は 0、ボブが勝った場合は -1 としてエンコードされます。 
6. で`dp(state)`、6 枚すべてのカードが割り当てられている場合は、2 枚のプライベート カードと割り当てられた 3 枚のコミュニティ カードからアリスの最終ハンドを計算します。ボブについても同様です。 2 つを比較し、結果を返します。 
7. それ以外の場合は、すでに割り当てられているカードの枚数を数えることによって、誰の番になるかを決定します。 数字が偶数の場合はアリスの番、そうでない場合はボブの番です。 
8. アリスの番の場合は、すべての未割り当てのコミュニティ カードを繰り返し、1 枚をアリスに割り当て、すべてのトランジションで最大の結果を取得します。 ボブの番の場合は、同じことを行いますが、ボブはアリスの結果を最小限に抑えようとするため、最小限の結果を採用します。 
9. 各状態の結果をメモ化し、3^6 の各状態が 1 回だけ計算されるようにします。 

### なぜ効果があるのか

 各移動は現在のプレイヤーへの残りのカードの決定的な割り当てであるため、すべての有効なプレイ シーケンスは状態グラフ内の 1 つのパスに正確に対応します。 ミニマックス再帰により、各状態で、両側からの完璧なプレイを前提とした真の最適な結果が評価されることが保証されます。 状態空間には 6 つのコミュニティ カードのすべての部分分布が含まれるため、将来の結果が見逃されることはありません。 各プレイヤーの最終的なハンドはプライベート カードと割り当てられたコミュニティ カードによって完全に決定されるため、最終状態での評価は正しいです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

RANK = {r:i for i,r in enumerate("23456789TJQKA", start=2)}

def parse(card):
    r, s = card[0], card[1]
    return RANK[r], s

def hand_value(cards):
    # cards: list of 5 (rank, suit)
    ranks = sorted([r for r, s in cards], reverse=True)
    suits = [s for r, s in cards]

    from collections import Counter
    cnt = Counter(ranks)

    is_flush = len(set(suits)) == 1

    uniq = sorted(set(ranks))
    is_straight = False
    top = None

    # handle normal straight
    if len(uniq) == 5 and max(uniq) - min(uniq) == 4:
        is_straight = True
        top = max(uniq)

    # wheel straight A-2-3-4-5
    if set(ranks) == {14, 5, 4, 3, 2}:
        is_straight = True
        top = 5

    freq = sorted(cnt.items(), key=lambda x:(-x[1], -x[0]))

    if is_straight and is_flush:
        if set(ranks) == {10,11,12,13,14}:
            return (9,)
        return (8, top)

    if freq[0][1] == 4:
        four = freq[0][0]
        kicker = [r for r in ranks if r != four][0]
        return (7, four, kicker)

    if freq[0][1] == 3 and freq[1][1] == 2:
        return (6, freq[0][0], freq[1][0])

    if is_flush:
        return (5, ranks)

    if is_straight:
        return (4, top)

    if freq[0][1] == 3:
        three = freq[0][0]
        kickers = sorted([r for r in ranks if r != three], reverse=True)
        return (3, three, kickers)

    if freq[0][1] == 2 and freq[1][1] == 2:
        pairs = sorted([freq[0][0], freq[1][0]], reverse=True)
        kicker = [r for r in ranks if r not in pairs][0]
        return (2, pairs, kicker)

    if freq[0][1] == 2:
        pair = freq[0][0]
        kickers = sorted([r for r in ranks if r != pair], reverse=True)
        return (1, pair, kickers)

    return (0, ranks)

def solve():
    from functools import lru_cache

    a1, a2 = input().split()
    b1, b2 = input().split()
    comm = input().split()

    A = [parse(a1), parse(a2)]
    B = [parse(b1), parse(b2)]
    C = [parse(x) for x in comm]

    n = 6

    @lru_cache(None)
    def dp(mask, turn):
        # mask bit i: 1 if assigned, 0 otherwise
        if mask == (1 << n) - 1:
            a_cards = A[:]
            b_cards = B[:]
            for i in range(n):
                if (mask >> i) & 1:
                    # recompute ownership via separate tracking is not here
                    pass
            # we cannot reconstruct ownership from mask alone
            return 0

    # real solution uses state with ownership encoding
    from functools import lru_cache

    @lru_cache(None)
    def dfs(state, turn):
        if turn == 6:
            a_cards = A[:]
            b_cards = B[:]
            for i in range(6):
                owner = (state // (3**i)) % 3
                if owner == 1:
                    a_cards.append(C[i])
                elif owner == 2:
                    b_cards.append(C[i])
            av = hand_value(a_cards)
            bv = hand_value(b_cards)
            if av > bv:
                return 1
            if av < bv:
                return -1
            return 0

        best = -2 if turn % 2 == 0 else 2

        for i in range(6):
            owner = (state // (3**i)) % 3
            if owner == 0:
                nxt = state + (1 if turn % 2 == 0 else 2) * (3**i)
                res = dfs(nxt, turn + 1)
                if turn % 2 == 0:
                    best = max(best, res)
                else:
                    best = min(best, res)

        return best

    res = dfs(0, 0)
    if res == 1:
        print("Alice")
    elif res == -1:
        print("Bob")
    else:
        print("Draw")

t = int(input())
for _ in range(t):
    solve()
```このソリューションは、各コミュニティ カードの所有権を基数 3 でエンコードし、すべての状態が部分的なゲームを直接表すようにします。 各トランジションでは、未請求のカード 1 枚が現在のプレイヤーに割り当てられます。 DFS は有効なゲーム履歴のみを調査し、メモ化により各設定が 1 回計算されるようにします。 

最終評価では、両方のプレイヤーの 5 枚のカード ハンド全体が再構築され、辞書編集的に比較可能なタプルを返す厳密なポーカー ランキング関数を使用して比較されます。 

よくある落とし穴は、使用済みカードのビットマスクのみを保存しようとすることです。 これにより所有権情報が失われ、最終評価が不可能になります。 Base-3 表現では、完全な割り当て履歴を埋め込むことでこの問題を修正します。 

## 実用的な例

 アリスとボブが残りの 3 枚のコミュニティ カード C0、C1、C2 を決定している単純化された状態を考えてみましょう。 

DP の進行の一部を示します。 

| 状態 (所有権) | ターン | アクション | 結果 |

 | 000000 | アリス | C0を選択 | 再帰 |

 ## 特殊なケース

 重要なエッジケースの 1 つは、エースローストレートです。 ハンド評価者はセット {A,2,3,4,5} を明示的にチェックし、他のストレートよりも低い特別なランク値をそれに割り当てます。 これがないと、A-2-3-4-5 のようなハンドは、エースがハイとして扱われるため、誤ってハイ ストレートとして比較されてしまいます。 

もう 1 つのエッジケースは、ハンドの構造は同じですが、キッカーが異なるものです。 たとえば、両方のプレーヤーが 8 のペアを形成する場合がありますが、キッカーが勝者を決定します。 タプルエンコーディングにより、キッカーが辞書順にソートおよび比較されることが保証され、偶発的な等価性の崩壊が防止されます。 

最後のエッジケースは、最適なプレイを行うために、重要な組み合わせを無効にするために、一見弱いカードを早い段階で採用する必要がある場合です。 DP は、即時のハンドの強さではなく将来の完全な状態を評価するため、これを正しく捉えており、ミニマックス伝播を通じて拒否戦略が自然に発見されることを保証します。
