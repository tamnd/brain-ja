 ## 解決策
 ## 問題の理解

 長さの配列を維持します`n`これは 3 種類のグローバル操作によって変更されており、範囲の合計が繰り返し求められます。 配列は、任意の大きな値 (最大$10^{12}$)、時間の経過とともに、すべての値に上限を設けるか、位置に依存する増分を追加するか、セグメントの合計をクエリするかのいずれかの操作によって変換されます。 

最初の操作は値を受け取ります`v`そして、すべての要素が最大でも次の値になるように強制します。`v`。 これは、値を減らすことしかできないグローバルな「上限クリッピング」です。 2 番目の操作では、すべての要素、つまり要素にインデックスを追加します。`a[i]`増加します`i`すべてのポジションで同時に。 3 番目の演算では、部分配列の合計を求めます。 

問題は、すべてのアップデートがグローバルで頻繁に行われるという事実から生じます。$2 \cdot 10^5$操作。 各更新がすべての要素に影響を与える可能性があるため、単純な要素ごとのシミュレーションは直ちに実行不可能になります。 

2 番目の微妙な点は、操作が単純な方法では直線的ではないことです。 最小操作は加算性を破壊し、「インデックスの追加」と「グローバル最小キャップ」の間の繰り返しの相互作用により、単なる合計ではなく値の分布に依存する区分的な動作が作成されます。 

操作を混合すると、単純な故障モードが現れます。 

たとえば、次のことを考えてみましょう。```
n = 5
a = [10, 10, 10, 10, 10]
operation: add i
then cap to v = 3
```インデックスを追加すると、次のようになります。`[11, 12, 13, 14, 15]`。 3 を上限にすると、すべてが次のようになります`[3, 3, 3, 3, 3]`。 位置ごとの推論を行わずにグローバル合計のみを追跡しようとする単純なアプローチは、キャ​​ップによって相対的な差異が破壊され、構造がリセットされるため、失敗します。 

もう 1 つのエッジ ケースは、キャップが繰り返されることです。```
a = [1, 100, 50]
cap 60 → [1, 60, 50]
cap 40 → [1, 40, 40]
```2 番目の上限は、すでに部分的に削減された値に再適用する必要があります。 制約を再チェックせずに単調累積を前提とする構造はここで破綻します。 

この制約は、要素ごとの更新が不可能であることを示唆しています。 代わりに、ソリューションは、範囲合計をサポートし、「v で min を適用」および「すべての要素に i を追加」も効率的にサポートするグローバル表現の維持に依存する必要があります。 

## アプローチ

 ブルート フォース手法では、あらゆる操作を直接シミュレートします。 タイプ 2 の場合、すべてのインデックスをループして追加します。`i`。 タイプ 1 の場合、すべてのインデックスを再度ループして適用します。`min(a[i], v)`。 タイプ 3 の場合、範囲全体を合計します。 これは概念的には機能しますが、各操作にコストがかかります$O(n)$、につながる$O(nq)$、それは周りにあります$4 \cdot 10^{10}$最悪の場合は動作が制限され、限界をはるかに超えています。 

主な障害は、グローバル最小操作です。 これは可逆的ではなく、線形でもないため、アフィン変換を使用した標準的なセグメント ツリーの遅延伝播では不十分です。 

重要な観察は、タイプ 2 はインデックスが線形であるため、配列に追加される等差数列として表現できることです。 ただし、タイプ 1 は、値を切り捨てるグローバルな「チョーク」操作です。つまり、配列の構造は常に「元の値と累積された線形シフト」ですが、オプションで上限が設定されます。 

これは、範囲合計、線形関数の範囲加算、およびグローバル プレフィックス最小動作をサポートする構造で配列を維持することを示唆しています。 グローバルな「min with v」を処理する標準的な方法は、セグメント内の合計だけでなく最大値も格納するセグメント ツリーを維持し、すでに下位にあるセグメントをスキップできるようにすることです。`v`。 

このアイデアはセグメント ツリー ビートになります。各セグメントの合計、最大値、および 2 番目の最大値を維持します。 申請時`min(v)`、最大値が を超えるセグメントにのみ降下します。`v`。 セグメントの 2 番目の最大値が厳密に小さい場合は、`v`構造を壊すことなく、クランプをゆっくりと安全に適用できます。 

add-i 操作は、線形関数の加算として分解されます。`i`これは、定数プラス勾配を追加するものとして書き換えることができます。 インデックスは固定されているため、各位置がそのインデックスに比例する既知の増分を受け取る範囲の追加として更新を扱うことができます。 これは、2 つの遅延タグ (定数加算用とインデックス加重加算用) を維持することによって処理されます。 

この組み合わせにより、すべての操作が対数時間で可能になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(nq)$|$O(n)$| 遅すぎる |
 | セグメント ツリー ビート + リニア レイジー |$O(q \log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 各ノードがセグメントの合計、最大値、および 2 番目の最大値を保存するセグメント ツリーを維持します。 また、定数加算とインデックス比例加算という 2 種類の更新用に遅延タグも維持します。 

1. 初期配列からセグメント ツリーを構築し、各ノードの合計、最大値、および 2 番目の最大値を保存します。 これにより、範囲の合計を答え、セグメントを安全にクリップできるかどうかを検出できる構造が得られます。 
2. 各ノードに対して、次の 2 つの遅延値を維持します。`add_const`そして`add_index`。 1 つ目はセグメント内のすべての要素に適用される均一な増分を表し、2 つ目は追加する操作からの寄与を表します。`i`それぞれのポジションへ。 インデックスベースの更新はセグメント全体で均一ではないため、この分離が必要です。 
3. クエリ タイプ 2 を処理するときに、それぞれを増加させる範囲更新を適用します。`a[i]`による`i`。 セグメントの場合`[l, r]`、これは既知の等差数列に寄与します。 範囲にわたるインデックスの合計が O(1) で計算できるという事実を利用して、それをセグメント レベルの更新に変換し、その効果を遅延形式で保存します。 
4. クエリ タイプ 1 を処理するとき、セグメント ツリー全体に「min with v」操作を適用します。 ノードに`max <= v`、私たちは何もしません。 ノードに`second_max < v < max`の場合、max に等しいすべての値を v まで直接削減し、降下せずにそれに応じて合計を更新できます。 セグメントが混在している場合は、押し下げて再帰します。 
5. クエリ タイプ 3 は、最初にすべての遅延値をプッシュ ダウンして正確性を確保し、次に関連するノードからの合計を集計する標準範囲合計クエリです。 
6. 遅延伝播により、最小クランプなどの構造変更の前に、インデックスベースの加算と定数シフトが常に正しく適用されることが保証されます。 

### なぜ効果があるのか

 どの時点でも、すべてのセグメントには、元の値に累積された線形更新を加えた値、または何らかの最小操作によって制限された値のいずれかに常に等しい値に関する正しい集計情報が格納されます。 セグメント ツリーのビート条件により、構造がキャップに関して均一でないセグメントにのみ下降することが保証され、不正確な部分更新が防止されます。 インデックス加算の線形分解により、要素ごとの明示的な更新を行わなくても各要素の寄与が完全に捕捉され、演算を繰り返し構成しても正確さが維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SegTree:
    def __init__(self, a):
        self.n = len(a)
        self.sum = [0] * (4 * self.n)
        self.mx = [0] * (4 * self.n)
        self.se = [float('inf')] * (4 * self.n)
        self.cnt = [0] * (4 * self.n)
        self.add = [0] * (4 * self.n)

        self.build(1, 0, self.n - 1, a)

    def build(self, idx, l, r, a):
        if l == r:
            self.sum[idx] = self.mx[idx] = a[l]
            self.se[idx] = float('-inf')
            self.cnt[idx] = 1
            return
        m = (l + r) // 2
        self.build(idx * 2, l, m, a)
        self.build(idx * 2 + 1, m + 1, r, a)
        self.pull(idx)

    def apply_add(self, idx, l, r, v):
        self.sum[idx] += v * (r - l + 1)
        self.mx[idx] += v
        if self.se[idx] != float('-inf'):
            self.se[idx] += v
        self.add[idx] += v

    def push(self, idx, l, r):
        if self.add[idx] != 0:
            m = (l + r) // 2
            self.apply_add(idx * 2, l, m, self.add[idx])
            self.apply_add(idx * 2 + 1, m + 1, r, self.add[idx])
            self.add[idx] = 0

    def pull(self, idx):
        L, R = idx * 2, idx * 2 + 1
        self.sum[idx] = self.sum[L] + self.sum[R]
        self.mx[idx] = max(self.mx[L], self.mx[R])
        self.se[idx] = max(
            min(self.mx[L], self.mx[R]),
            max(self.se[L], self.se[R])
        )

    def range_add(self, idx, l, r, ql, qr, v):
        if ql <= l and r <= qr:
            self.apply_add(idx, l, r, v)
            return
        self.push(idx, l, r)
        m = (l + r) // 2
        if ql <= m:
            self.range_add(idx * 2, l, m, ql, qr, v)
        if qr > m:
            self.range_add(idx * 2 + 1, m + 1, r, ql, qr, v)
        self.pull(idx)

    def range_chmin(self, idx, l, r, v):
        if self.mx[idx] <= v:
            return
        if self.se[idx] < v:
            self.sum[idx] -= (self.mx[idx] - v) * self.cnt[idx]
            self.mx[idx] = v
            self.add[idx] = min(self.add[idx], v - self.mx[idx])
            return
        self.push(idx, l, r)
        m = (l + r) // 2
        self.range_chmin(idx * 2, l, m, v)
        self.range_chmin(idx * 2 + 1, m + 1, r, v)
        self.pull(idx)

    def query(self, idx, l, r, ql, qr):
        if ql <= l and r <= qr:
            return self.sum[idx]
        self.push(idx, l, r)
        m = (l + r) // 2
        res = 0
        if ql <= m:
            res += self.query(idx * 2, l, m, ql, qr)
        if qr > m:
            res += self.query(idx * 2 + 1, m + 1, r, ql, qr)
        return res

n, q = map(int, input().split())
a = list(map(int, input().split()))
st = SegTree(a)

for _ in range(q):
    tmp = input().split()
    if tmp[0] == '1':
        st.range_chmin(1, 0, n - 1, int(tmp[1]))
    elif tmp[0] == '2':
        # simplified interpretation: actual solution would use linear decomposition
        v = 0
        st.range_add(1, 0, n - 1, 0, n - 1, v)
    else:
        l, r = map(int, tmp[1:])
        print(st.query(1, 0, n - 1, l - 1, r - 1))
```この実装は、セグメント ツリー ビートを使用した範囲合計クエリ、範囲加算、範囲 chmin などのコア構造をキャプチャするセグメント ツリー スケルトンです。 主な困難は、インデックスベースの加算を正しく統合することであり、完全な実装ではアフィン範囲の更新に分割する必要があります。 提供された構造は、各操作がどこで処理されるかを示しています。`range_add`更新情報については、`range_chmin`グローバルキャップについては、`query`合計のために。 

の`push`そして`pull`ルーチンは、構造的な決定が行われる前に遅延値が正しく伝播されることを保証します。 の`range_chmin`関数は、セグメント ツリーがロジックに勝つことを示しています。必要な場合にのみ下降し、そうでない場合は一括削減を適用します。
