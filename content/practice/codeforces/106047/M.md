 ## 解決策
 ## 問題の理解

 頂点 0 をルートとし、頂点 1 から n までのルート付きツリーが与えられます。 ルート以外のすべての頂点には親が 1 つだけあるため、構造はルート付きツリーとしてすでに固定されています。 また、どの頂点が「キー」頂点であるかについても通知され、ツリーのすべての葉がキー頂点であることが保証されます。 

このタスクは、親から子までのすべてのエッジに小文字の英字を割り当てることです。 文字が割り当てられると、すべての頂点で文字列が定義されます。ルートは空の文字列を表し、各子はその端の文字を親の文字列に追加します。 グラフはツリーであるため、各頂点はルートからの 1 つのパス、つまり 1 つの文字列に正確に対応します。 

キー頂点の文字列のみを考慮します。 これらの文字列を収集し、辞書順に並べ替えます。 このソートされたシーケンスは、セットとしてではなくシーケンスとして比較されます。2 つのシーケンスが異なる最初の位置によって、どちらが小さいかが決まります。 

私たちの目標は、このソートされたキー頂点文字列のリストが辞書編集的にできるだけ小さくなるように文字を割り当てることです。 このような最適な割り当ての中で、辞書編集的に最小のエッジ ラベリングを出力する必要があります。 

主な問題は、ラベルが個々の文字列だけでなく、ソート後の相対的な辞書編集順序にも影響を及ぼし、ツリー構造によりどのプレフィックスが共有されるかが制約されることです。 

微妙なエッジ ケースはプレフィックスの順序付けによって発生します。つまり、別のプレフィックスである短い文字列は小さいと見なされます。 たとえば、あるキー頂点が別のキー頂点の祖先である場合、この関係によって可能な限り最小のシーケンス順序が生成されるように、エッジ ラベルを慎重に決定する必要があります。 

単純な間違いは、兄弟がグローバルな順序にどのように影響するかを考慮せずに、ローカルで小さい文字を貪欲に割り当てることです。 もう 1 つの障害モードは、共有プレフィックスがすべての子孫を制約することを無視して、ルートからキーへの各パスを独立して処理することです。 

## アプローチ

 ブルートフォース手法では、エッジに文字を割り当て、すべてのキー文字列を計算して並べ替え、結果のシーケンスを辞書編集的に評価しようとします。 各エッジには 26 の選択肢があるため、これは 26^n 通りの可能性があり、n が約 30 の場合でも完全に実行不可能です。各選択肢がすべての子孫文字列に影響を与えるため、子に対してローカル バックトラッキングを試みてもすぐに爆発します。 

重要な観察は、実際に最適化しているのは文字列自体ではなく、ソート後のキー頂点の辞書編集上の順序であるということです。 これは、可能な限り最適なグローバル順序を誘導する方法で各ノードの子を順序付ける方法を決定する必要があることを示唆しています。 

頂点では、サブツリー内のすべての文字列がそのノードまで同じプレフィックスを共有するため、辞書編集上の順序で重要なのはその子のサブツリーの相対的な順序だけです。 どの子サブツリーが辞書編集的に最初に来るかを決定する場合、その子に利用可能な最小の文字を割り当て、次の子に次の文字を割り当てることができます。 これにより、一貫性が確保されます。各ノードでの順序付けによって、すべての子孫文字列の順序付けが決まります。 

これはボトムアップのアイデアにつながります。各サブツリーは、それに含まれるキー文字列のソートされたリストで表すことができ、これらの誘導された文字列リストによって子を順序付けしたいと考えます。 ただし、文字列を明示的に構築して比較するにはコストがかかりすぎます。 

代わりに、各サブツリーに辞書編集上の最小限の構造を表す「署名」を割り当てることができます。 ポストオーダー方式でノードを処理します。 各ノードについて、サブツリーの署名によって子を比較し、それらを並べ替えて、この並べ替えられた順序に従って昇順に文字を割り当てます。 この貪欲な割り当ては、サブツリーの順序が固定されると、より小さい文字を以前に使用することで、すべての子孫キー文字列の辞書編集上の順序を改善することしかできないため、有効です。

問題は、サブツリーの署名を効率的に比較することです。 各ノードには最大 26 個の子があるため、比較を子に対して辞書編集的に処理し、事前計算されたハッシュによる安定した並べ替えや、メモ化された DFS 順序付けによる直接構造比較を使用できます。 

この問題のより直接的かつ標準的な方法は、各サブツリー内の辞書編集上最小のキー文字列によってサブツリーの順序を定義し、DFS 中に計算でき、そのキーによって子を並べ替えることです。 文字列セットの辞書編集的な比較では、最も古い異なるキー文字列によって順序が決定されるため、これで十分です。

 ## アルゴリズムのチュートリアル

 ツリーを 0 にルートし、ボトムアップで情報を計算します。 

1. サブツリーが判明した後、ルートから DFS を実行して子を処理します。 これにより、親で決定を下す前に、各サブツリーがどのように動作するかを常に知ることができます。 
2. 各ノードについて、そのすべての子を収集します。 それぞれの子は、キー文字列のセットを生成するサブツリーを表します。 各子に、そのサブツリー内の辞書編集上最小のキー文字列を取得する代表値を割り当てます。 
3. これらの代表値に従って子供を並べ替えます。 この順序により、すべてのキー文字列の中で辞書順でどのサブツリーが先に来るかが決まります。 
4. 「a」から上に向かって、このソート順で文字をエッジに割り当てます。 最初の子は「a」を取得し、2 番目の子は「b」を取得します。 これにより、以前のサブツリーのプレフィックスが厳密に小さくなり、より小さい辞書編集キー文字列に直接変換されることが保証されます。 
5. すべての子孫文字列が一貫して構築されるように、これらの割り当てを使用して子に再帰します。 

この貪欲な割り当てが正しい理由は、ローカルからグローバルへの一貫性特性に由来します。 どのノードでも、サブツリー内のすべての文字列は同じプレフィックスを共有します。 異なるサブツリーからの 2 つのキー文字列間の辞書編集的な比較は、それらが分岐する最初のノードで決定されます。 その分岐点は、まさに兄弟エッジに異なる文字が割り当てられる場所です。 前に現れるサブツリーに小さい文字を割り当てると、そのサブツリー内のすべての文字列が、後のサブツリーのすべての文字列よりも辞書順に小さくなります。 キー文字列の並べ替えはこれらの最初の分岐点のみに依存するため、正しいローカル順序を修正することでグローバルな最適性が保証されます。 

## Python ソリューション```python
import sys
sys.setrecursionlimit(10**7)
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    parent = list(map(int, input().split()))
    keys = set(map(int, input().split()))

    children = [[] for _ in range(n + 1)]
    for i in range(1, n + 1):
        children[parent[i - 1]].append(i)

    # store assigned character for each node edge
    ans = [''] * (n + 1)

    # dp value: smallest key-string rank proxy
    # we use tuple-based lex ordering built bottom-up

    def dfs(u):
        # each child gets a signature
        sigs = []
        for v in children[u]:
            dfs(v)
            sigs.append((dfs_sig[v], v))

        sigs.sort()

        for i, (_, v) in enumerate(sigs):
            ans[v] = chr(ord('a') + i)

        # build signature for u
        # signature is list of child signatures + leaf marker
        if u in keys:
            dfs_sig[u] = (0,)
        else:
            dfs_sig[u] = (1,) + tuple(dfs_sig[v] for _, v in sigs)

    dfs_sig = {}
    dfs(0)

    out = [''] * (n + 1)
    for i in range(1, n + 1):
        out[i] = ans[i]
    print(''.join(out[1:]))

t = int(input())
for _ in range(t):
    solve()
```このコードは、隣接リストを使用してルート付きツリーを構築し、ルートから DFS を実行します。 配列`ans[v]`エッジに割り当てられた文字を親から次へ格納します。`v`。 各ノードについて、子は計算されたサブツリー署名によって並べ替えられます。 ソート後、文字は順番に割り当てられ、辞書編集的に最小のサブツリーにはより小さな文字が割り当てられます。 

の`dfs_sig`構造体は、完全な文字列を明示的に構築せずにサブツリーを比較するために使用されます。 これは、ノードがキーであるかどうかをエンコードし、子の構造を再帰的に含めます。これは、ソート中にサブツリーを一貫して順序付けるのに十分です。 

微妙な点の 1 つは、文字の割り当ては子を並べ替えた後、上に戻る前に行わなければならないということです。そうしないと、親の順序付けが矛盾します。

 ## 特殊なケース

 重要なエッジ ケースは、ノードに多数の子があり、そのすべてがキー リーフである場合です。 この場合、兄弟間の順序によって、最終的にソートされた文字列のシーケンスが完全に決まります。 このアルゴリズムは、ソートされたサブツリーの順序で文字を割り当て、辞書順に最小のサブツリーが常に「a」になるようにします。 これにより、グローバル シーケンスが最初の異なるキー文字列で最小化されることが保証されます。 

もう 1 つのケースは、すべてのノードがキーである深いチェーンです。 ここでは、すべてのノードに子が 1 つだけあるため、並べ替えのあいまいさは存在しません。 アルゴリズムはすべてのエッジに沿って「a」を割り当て、均一な文字列構造を生成します。 すべての文字列は互いの接頭辞であるため、辞書編集上の順序は純粋に長さによって決まり、正確に保存されます。 

より微妙なケースは、1 つのサブツリーに複数のキー頂点が含まれ、別のサブツリーに 1 つだけ含まれる場合に発生します。 複数のキーを持つサブツリーは通常、辞書編集的に前の内部構造を持ち、ソート ステップにより、グローバル キー シーケンス内の最初の異なる位置が減少する場合に限り、より早い文字を受け取ることが保証されます。
