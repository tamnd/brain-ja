 ## 解決策
 ## 問題の理解

 いくつかの位置がすでに固定されているバイナリ文字列が与えられます。`0`または`1`、その他は不明でマークされています`?`。 すべてを交換する必要があります`?`どちらかで`0`または`1`。 文字列を埋めた後、隣接するペアを調べ、連続する文字が何回異なっているかを数えます。 そのカウントはターゲット値と正確に等しくなければなりません`k`。 

すべての有効な補完の中で、単に解決策を求められるわけではありません。 辞書編集的に最小の結果として得られるバイナリ文字列を構築する必要があります。 

重要な解釈の変更は、目的は 1 または 0 をグローバルに数えることではなく、隣接する位置間の遷移を制御することであるということです。 各位置は辞書編集順序に独立して寄与しますが、制約はフリップの回数によって隣接する位置を結合します。 

制約により、最大で$n = 10^5$テストごとと合計$10^6$したがって、どのソリューションもテスト ケースごとに本質的に線形である必要があります。 すべての割り当てに対する 2 次または状態展開のアプローチは、すぐには実行不可能です。`?`検索スペースが 2 倍になり、ブルート フォースが指数関数的に増加します。 

将来の実現可能性を追跡せずに、文字を左から右に貪欲に割り当てると、微妙なエッジケースが発生します。 たとえば、常に選択すると、`'0'`のために`?`辞書編集上の順序を最小限に抑えるために、後で必要な遷移数を超えるか、下回らざるを得なくなる可能性があります。 別の失敗例は、1 つの文字の変更が 2 つの境界に影響を与えることを考慮せずに、トランジションをローカルに修正しようとしたときに発生します。そのため、決定は独立していません。 

本当の難しさは、各位置が隣接関係によってのみ遷移数に寄与するため、問題はグローバルな変更バジェットを伴う制約されたパス構築になることです。 

## アプローチ

 ブルートフォースアプローチでは、すべての割り当てを試みます。`?`位置を調べて、隣接する不一致の数を計算します。 あれば$m$未知のもの、これは探ります$2^m$可能性があり、それぞれについて文字列をスキャンします。$O(n)$、与える$O(n 2^n)$最悪の場合。 これは実現可能な限界をはるかに超えています。 

重要な観察は、遷移の数は、前の位置と比較して同じビットを選択するか、異なるビットを選択するかによってのみ依存するということです。 これは、状態が最後に選択されたビットと、達成する必要がある遷移の数によって決定される動的プログラミングの解釈を示唆しています。 

文字列を左から右に構築することを考えることができます。 各位置で、制約と一致する値を選択し、すでに使用したトランジションの数を追跡します。 辞書編集上の最小要件は、常に試行する必要があることを示唆しています。`'0'`前に`'1'`ただし、最終目標が不可能にならない場合に限ります。 したがって、実現可能性のチェックが不可欠になります。 

現在の位置、最後の文字、および残りの移行予算を考慮してサフィックスを完了できるかどうかを追跡する DP を定義します。 ただし、すべての状態にわたる完全な DP の代わりに、実現可能性は残りの長さと残りの遷移のみに依存することに注意して圧縮します。`i`、少し配置すると、まだ達成可能なトランジションの数が正確にわかります。 

これは、実現可能性チェックを伴う貪欲な構築につながります。各位置で、暫定的に割り当てます。`'0'`または`'1'`、これが消費する遷移の数を計算し、残りの必要な遷移が残りのサフィックスで達成可能であることを確認します。 接尾辞の実現可能性は単純な限界に帰着します。`len`残りのポジション、可能なトランジションの数の範囲は次のとおりです。`0`に`len-1`。 

したがって、各ステップで現在のトランジションと以前のキャラクターを維持し、残りの必要なトランジションが確実に維持されるようにします。`k`実現可能な範囲内に留まります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n 2^n)$|$O(n)$| 遅すぎる |
 | 貪欲 + 実現可能性 |$O(n)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 前に選択した文字と、これまでに形成されたトランジションの数という 2 つの情報を維持しながら、左から右に文字列を構築します。 

1. 回答の構築を初期化します。 結果を文字ごとに構築していきます。 前の文字が決定されると、それも追跡します。 最初の位置には前の文字がないため、実現可能性と一致する値のみを選択します。 
2. ポジションごとに`i`、候補値を決定します。 もし`s[i]`が固定されている場合、その値のみを考慮します。 そうであれば`?`、試してみます`'0'`まずそして`'1'`2 番目は辞書編集上最小の出力を確保するためです。 
3. 各候補値について、ここに配置した場合に追加されるトランジションの数を計算します。 前の文字が存在しない場合、この寄与はゼロになります。 それ以外の場合は、`1`候補が前の文字と異なる場合、そうでない場合`0`。 
4. 暫定的な遷移カウントを更新し、残りの必要な遷移を次のように計算します。`k - used_so_far - new_transition`。 
5. サフィックスの実現可能性を確認します。 位置で`i`、 がある`n - i - 1`エッジが残っているため、将来の遷移の最大数は次のようになります。`n - i - 1`そして最小値は`0`。 残りの必要な遷移がこの間隔の外にある場合、この候補は無効です。 
6. 候補が実現可能性を満たした場合、それを修正し、現在の遷移数と前の文字を更新して、次に進みます。 
7. どこかのポジションに候補者がいない場合、建設は不可能です。 

### なぜ効果があるのか

 すべてのステップで、プレフィックスが固定されており、必要な残りの遷移数はサフィックスの何らかの完了によって達成できるという不変条件を保持します。 各配置は前の文字との境界を通過する遷移数にのみ影響するため、サフィックスの実現可能性は、以前の構造ではなく、残っているエッジの数にのみ依存します。 これにより、実現可能性を維持するローカルで有効な選択によって、すべてのグローバル ソリューションが排除されないことが保証され、`'0'`まず、実行可能なすべての補完の中で辞書編集的に最小限の出力が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        s = input().strip()

        res = []
        prev = None
        used = 0

        for i in range(n):
            candidates = []
            if s[i] == '?':
                candidates = ['0', '1']
            else:
                candidates = [s[i]]

            chosen = None

            for c in candidates:
                add = 0
                if prev is not None and c != prev:
                    add = 1

                new_used = used + add
                remaining = k - new_used
                rem_len = n - i - 1

                if 0 <= remaining <= rem_len:
                    chosen = c
                    used = new_used
                    prev = c
                    res.append(c)
                    break

            if chosen is None:
                print("Impossible")
                break
        else:
            if used == k:
                print("".join(res))
            else:
                print("Impossible")

if __name__ == "__main__":
    solve()
```解決策は厳密に左から右に進みます。 各ポジションについて、残りのターゲットを到達不可能にしない場合にのみ、キャラクターを受け入れます。 実現可能性チェックでは、残りの遷移は次の範囲のどこにでも存在できるという事実を利用します。`0`残りのエッジの数。 

微妙な実装の詳細は、最初の文字の処理です。前の文字がないため、遷移のカウントを避けます。 もう 1 つの重要な詳細は、`for-else`この構造により、成功した完了と初期の失敗を明確に区別できるようになります。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []

    for _ in range(t):
        n, k = map(int, input().split())
        s = input().strip()

        res = []
        prev = None
        used = 0
        ok = True

        for i in range(n):
            if s[i] == '?':
                cand = ['0', '1']
            else:
                cand = [s[i]]

            found = False
            for c in cand:
                add = 1 if prev is not None and c != prev else 0
                nu = used + add
                rem = k - nu
                if 0 <= rem <= n - i - 1:
                    res.append(c)
                    used = nu
                    prev = c
                    found = True
                    break

            if not found:
                out.append("Impossible")
                ok = False
                break

        if ok and used == k:
            out.append("".join(res))
        elif ok:
            out.append("Impossible")

    return "\n".join(out)

 ## 特殊なケース

 特殊なケースの 1 つは、弦が完全に固定されている場合です。 その状況では、アルゴリズムは分岐せず、遷移カウントが一致するかどうかのみをチェックします。`k`。 入力用`s = "0101"`そして`k = 3`、トラバーサルは遷移を次のように直接計算します。`3`なので、文字列は変更せずに受け入れられます。 

別の特殊なケースが発生するのは、`k = 0`。 有効な出力は定数文字列のみです。 入力用`????`、アルゴリズムは常に`'0'`なぜなら、それは決して実現可能性に違反することがなく、トランジションが許可されないため、すべてのステップで同じ文字が強制されるからです。 

最後のエッジケースは次のような場合です`k = n - 1`つまり、隣接するすべてのペアは異なっていなければなりません。 これにより、交互パターンが強制され、実行可能性チェックにより、位置 0 で選択が行われると、その後のすべての位置が一意に決定されることが保証されます。
