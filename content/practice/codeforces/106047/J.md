 ## 解決策
 ## 問題の理解

 都市は三角形の交差点の格子として見ることができます。 最初の行には 1 つのノードがあり、2 番目の行には 2 つのノードがあり、n 番目の行が n 個のノードを持つまで続きます。 各交差点は座標によって識別されます$(i, j)$、 どこ$i$は行であり、$j$はその行内の位置です。 

各ノードから$(i, j)$のために$i < n$、次の行への 3 つの外向き道路が考えられます。 1つはまっすぐに下に行きます$(i+1, j)$長さのある$a_{i,j}$、右下に進みます$(i+1, j+1)$長さのある$b_{i,j}$、間の次の行にも水平エッジがあります。$(i+1, j)$そして$(i+1, j+1)$長さのある$c_{i,j}$。 それぞれのトリプル$(a_{i,j}, b_{i,j}, c_{i,j})$は三角形を形成します。これは、そのようなすべてのトリプルに対して三角形不等式が成り立つことを意味します。 

から始めます$(1, 1)$そして到達しなければならない$(n, n)$。 課題は、どの道路も複数回通過せずに、全長を最大化する経路を見つけることです。 出力には、訪問した交差点の正確なシーケンスを再構築する必要もあります。 

重要な制約は、次のような階層化されたグラフを扱っていることです。$O(n^2)$ノードと$O(n^2)$エッジ。 以来$n \le 300$テストごとと合計$n$テスト全体で最大$5000$、おおよそ余裕があります$O(n^2)$または$O(n^2 \log n)$しかし、指数関数的に状態を再検討したり、組み合わせ方式でエッジを個別に処理したりすることは不可能です。 

単純な間違いは、これを DAG 内の一般的な最長パスとして扱い、「エッジ再利用なし」条件を無視することです。 たとえば、エッジの独立性を仮定してノードの DP を単純に最大化しようとすると、隣接する三角形を横断するときに水平エッジが暗黙的に再利用される構成が可能になる可能性があります。 これは、次のような小規模な構成では問題になります。 

もし$n=2$、ノードがあります$(1,1)$、$(2,1)$、$(2,2)$。 三角形を形成する 3 つの辺があります。 単純なアプローチでは、3 つのエッジすべての選択を独立した遷移として扱い、暗黙的にエッジを再訪するサイクルのようなパスを生成する可能性がありますが、これは許可されていません。 

したがって、主な問題は、各三角形がローカル構造を導入し、一部のエッジの選択が他のエッジを再利用できるかどうかに影響を与えることです。 

## アプローチ

 エッジの再利用に関する制約を少し無視すると、グラフは階層化された DAG であり、通常はノード上で単純な DP を実行し、次のノードから最適なパスを選択します。$(1,1)$に$(n,n)$。 ただし、これは、次の間を移動するという事実を無視しています。$(i+1,j)$そして$(i+1,j+1)$水平エッジを使用します$c_{i,j}$、上の行からのトランジションと相互作用します。 

強引な解釈では、上から下まで可能なすべての単純なパスを考慮し、エッジが 2 回使用されないようにします。 これはすでに指数関数的です。なぜなら、各三角形でその 3 つのエッジを通る経路を決定することができ、これらの決定がグリッド全体に伝播するからです。 最悪の場合、有効なパスの数は急激に増加します。$n$, したがって、これは実行できません。 

重要な観察は、各セルが実際にはローカルの三角形ガジェットのように動作し、各三角形を局所的に一貫した構造として扱うことで、「エッジは複数回使用されない」という制約を強制できることです。流れが三角形を通過する方法を一度決定したら、それを再検討する必要はありません。 ジオメトリにより、最適なパスが行全体で一貫した方向の選択肢に分解できることが保証されます。 

これにより、問題は構造化 DAG 内の最短/最長パスに変わります。各ノードの状態は、三角形の境界の左または右の頂点にいるかどうかをエンコードし、遷移は三角形のエッジの 1 つを選択するか、一貫した方向にスキップすることに対応します。 三角形不等式により、三角形内の迂回によって最適性が決して低下しないことが保証され、各状態が前の行の隣接する状態のみに依存する階層化された DP に問題を縮小することができます。 

したがって、エッジの再利用についてグローバルに推論する代わりに、グラフを状態グラフに変換します。$O(n^2)$状態と状態ごとの定数遷移。

 ## アルゴリズムのチュートリアル

 各行の遷移を一連の状態として解釈し、行内の各ノードにどのように到達するかを決定します。$i$。 重要なアイデアは、パスを再構築するのに十分な構造を追跡しながら、行ごとに最適な距離を計算することです。 

1. 定義する$dp[i][j]$からの有効なパスの最大長として$(1,1)$に$(i,j)$。 これだけでは水平方向の使用法を再構築するのに十分ではないため、以前の情報も別に保存します。 
2.初期化$dp[1][1] = 0$。 他のすべての状態は最初は到達できません。 これにより、パスが開始点に固定されます。 
3. 各行について$i$1から$n-1$、行から値を伝播します$i$漕ぐ$i+1$3 つの可能なエッジ タイプを使用します。 から$(i,j)$、私たちはに行くことができます$(i+1,j)$を使用して$a_{i,j}$またはへ$(i+1,j+1)$を使用して$b_{i,j}$。 これらは、階層構造における標準的な有向トランジションです。 
4. 水平エッジ$c_{i,j}$並んで住んでいる$i+1$そしてつながる$(i+1,j)$そして$(i+1,j+1)$。 独立したエッジとして扱う代わりに、行の初期 dp を計算した後に緩和します。$i+1$。 各行内で左から右および右から左の緩和を実行し、オプションで次を使用してパスを改善できるようにします。$c_{i,j}$。 水平エッジは同じレイヤー内の隣接するノードにのみ影響するため、これが機能します。 
5. dp 値が改善するたびに親ポインタを保存し、左上から来たのか、上から来たのか、水平緩和から来たのかを記録します。 これは完全なノード シーケンスを再構築するために必要です。 
6. すべての行を処理した後、$dp[n][n]$最大パス値が含まれます。 保存されている親を遡ってパスを再構築します。 

正確かどうかは、水平エッジが同じ行内の隣接するノードにのみ接続するという事実にかかっており、その影響は行をまたがるサイクルを作成することなく、その行内の局所的な緩和によって完全に解決できます。 

### なぜ効果があるのか

 各州$(i,j)$は、その交差点で終わる、達成可能な最良のプレフィックス パスを表します。 先頭から次への有効なパス$(i,j)$2 つの対角線のエッジのうちの 1 つを正確に通過するか、行内で水平方向に移動して改善する必要があります。$i$。 水平エッジは異なる行を接続しないため、層間の依存関係サイクルを導入することはできません。 これにより、一度行を実行すると、$i$完全に処理され、行に関係するすべての最適なインタラクションが行われます。$i$は最終化されており、後の行では改善されません。 

三角形の不等式は、三角形内の代替迂回がすでに考慮された直接 DP 遷移よりも厳密に優れた構成を生成できないことを保証するため、局所的な緩和で十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n = int(input())
        
        a = [None] * n
        b = [None] * n
        c = [None] * n
        
        for i in range(1, n):
            a[i] = list(map(int, input().split()))
        for i in range(1, n):
            b[i] = list(map(int, input().split()))
        for i in range(1, n):
            c[i] = list(map(int, input().split()))
        
        NEG = -10**30
        dp = [[NEG] * (i + 1) for i in range(n + 1)]
        par = [[None] * (i + 1) for i in range(n + 1)]
        
        dp[1][1] = 0
        
        for i in range(1, n):
            # move down
            for j in range(1, i + 1):
                if dp[i][j] == NEG:
                    continue
                
                v = dp[i][j]
                
                # (i,j) -> (i+1,j)
                if v + a[i][j - 1] > dp[i + 1][j]:
                    dp[i + 1][j] = v + a[i][j - 1]
                    par[i + 1][j] = (i, j)
                
                # (i,j) -> (i+1,j+1)
                if v + b[i][j - 1] > dp[i + 1][j + 1]:
                    dp[i + 1][j + 1] = v + b[i][j - 1]
                    par[i + 1][j + 1] = (i, j)
            
            # horizontal relaxations in row i+1
            for j in range(1, i + 1):
                u = dp[i + 1][j]
                v = dp[i + 1][j + 1]
                if u != NEG and v != NEG:
                    if u + c[i][j - 1] > v:
                        dp[i + 1][j + 1] = u + c[i][j - 1]
                        par[i + 1][j + 1] = (i + 1, j)
                    if v + c[i][j - 1] > u:
                        dp[i + 1][j] = v + c[i][j - 1]
                        par[i + 1][j] = (i + 1, j + 1)
        
        path = []
        i, j = n, n
        while True:
            path.append((i, j))
            if (i, j) == (1, 1):
                break
            i, j = par[i][j]
        
        path.reverse()
        
        length = dp[n][n]
        print(length)
        print(len(path))
        print(" ".join(str(x) for p in path for x in p))

if __name__ == "__main__":
    solve()
```DP 配列には、各行のノードごとに最もよく知られている値が格納されます。 行からの遷移$i$に$i+1$対角エッジを直接考慮します$a$そして$b$。 その後、単純な 2 方向スキャンを使用して新しい行内の水平エッジを緩和し、$c$以前の行を再処理せずにキャプチャされます。 

親配列は、前の行または水平方向の緩和から、それぞれの最良の状態がどのように達成されたかを記録します。 水平方向の移動は常に同じ行内の隣接するノード間で行われるため、ローカルの親リンクとして表すことができるため、これで十分です。

 ## 特殊なケース

 エッジ ケースの 1 つは、水平エッジが常に斜めの動きを支配しており、下降する前に最適なパスが行内で振動する場合です。 すべての下向き遷移の後に水平緩和が適用され、行内で改善された値を完全に伝播できるため、アルゴリズムはこれを処理します。 

別のケースは、すべての重みが等しい場合です。 多くのパスは最適ですが、親の再構築でも有効な単純なパスを生成する必要があります。 各更新は厳密な改善の場合にのみ発生するため、タイは有効な先行ファイルを恣意的に上書きせず、一貫性のある再構築を保証します。 

最後のケースは次のような場合です。$n=2$、三角形が 1 つだけ存在します。 DP は 2 つの対角エッジを直接比較し、次に水平エッジを 1 回適用して、エッジを繰り返すことなく 3 つのノードすべてを通る有効な走査を生成します。
