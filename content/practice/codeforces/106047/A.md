 ## 解決策
 ## 問題の理解

 いくつかのテスト ケースが与えられ、各テスト ケースは実数直線上のセグメントの集合で構成されます。 Every segment covers a closed interval from$l_i$に$r_i$、各セグメントには、赤または青の 2 色のいずれかがラベル付けされています。 

タスクは、選択されたセットが「重なりの下で色が一貫している」ように、これらのセグメントのサブセットをいくつ選択できるかを数えることです。 具体的には、選択した 2 つのセグメントがラインの少なくとも 1 点で交差する場合、それらの 2 つのセグメントは同じ色を共有する必要があります。 2 つのセグメントが重なっていて色が異なる場合、それらを一緒に選択することは禁止されます。 

出力は、空のサブセットを含む有効なサブセットの数です。$998244353$。 

制約は、ソリューションが次まで処理する必要があることを意味します。$5 \times 10^5$すべてのテスト ケースにわたるセグメントの合計。 すべてのサブセット、さらにはサブセットのすべてのペアをチェックしようとするソリューションは、直ちに不可能です。$2^n$実現可能な限界をはるかに超えて成長します。 平$O(n^2)$テストケースごとの速度は遅すぎます。$10^{10}$最悪の場合の運用。 

素朴な解釈の間違いは、セグメントがローカルでのみ相互作用すると考えることです。 オーバーラップにより、チェーンを介してグローバルな制約が作成されます。 たとえば、A が B と重なり、B が C と重なる場合、A と C が重ならない場合でも、有効なサブセットのカウントに影響を与える形で間接的に制約される可能性があります。 

2 番目の微妙なエッジ ケースは、たとえ遠く離れていても、互いに素なセグメントは常に独立しているということです。 たとえば、重なり合わない異なる色の 2 つのセグメントはいつでも一緒に選択できますが、1 点でも重なりが現れると、色の均等性が強制されます。 

## アプローチ

 ブルートフォース手法では、セグメントのすべてのサブセットを列挙し、選択された重複セグメントのすべてのペアが同じ色を共有しているかどうかを確認します。 各サブセットについて、その中のすべてのペアをスキャンし、交差をテストします。 これは次のことにつながります$O(2^n \cdot n^2)$、これはたとえ$n = 40$。 

もう少し良いアイデアですが、それでも不可能なアイデアは、サブセットを修正し、データ構造を維持して一貫性を段階的にチェックすることです。 それでも、私たちは依然として指数関数的なサブセットを探索しています。 

重要な観察は、拘束が接続されたオーバーラップ構造内でのみアクティブになるということです。 セグメントを直線上の間隔として見ると、重複する関係が間隔グラフの連結成分を形成します。 各接続コンポーネント内で、選択されたサブセットが重なり合って矛盾する方法で色を混合してはなりません。 より正確には、接続されたオーバーラップ領域内で 1 つの色のセグメントを選択すると、同じ領域内で同時に選択できる他のカラー セグメントが制限されます。 

これは、ソートされた順序でセグメントを処理し、アクティブなオーバーラップ構造を維持し、オーバーラップ チェーンが存在する独立したブロックに問題を分割する必要があることを示唆しています。 

正しい変換は、エンドポイントをスイープし、重複するセグメントの現在のアクティブなセットを維持することです。 最大重複グループ内で、赤と青のセグメントがどのように相互作用するかを追跡し、サブセットを列挙するのではなく、組み合わせ的に寄与を計算します。 

連続したオーバーラップ領域内では、時間的にオーバーラップする赤いセグメントと青いセグメントを選択できないという制約が生じます。 これは、接続された各オーバーラップ コンポーネントを 2 つの独立した選択肢に分割するのと同じですが、オーバーラップが色をまたぐ場合は結合されます。 

これを解決する標準的な方法は、開始点によってセグメントを並べ替え、アクティブな間隔の構造を維持することです。 新しいセグメントが開始されるたびに、新しいコンポーネントが開始されるか、既存の重複コンポーネントに結合されます。 動的コンポーネントを色数で管理し、コンポーネントごとに、赤と互換性のあるサブセットのみ、または青と互換性のあるサブセットのみを選択する方法の数として有効なサブセットの数と、コンポーネント上の DP を介して解決される混合制約を計算します。 

これにより、問題は区間接続コンポーネントのマージとローカル寄与の乗算に軽減されます。

 ## アルゴリズムのチュートリアル

 1. すべてのセグメントを左の端点で並べ替えます。 ソートは、左から右に移動するにつれて重なり合う構造を段階的に明らかにできるようにするために必要です。 
2. 現在アクティブなセグメントのセット、つまり右のエンドポイントがまだ渡されていないセグメントを維持します。 このセットは、ライン上の各位置における現在のオーバーラップ コンポーネントを表します。 
3. セグメントを順番に処理しながら、右端が現在のセグメントの左端より小さいセグメントを繰り返し削除します。 それぞれの削除により、接続されたオーバーラップ ブロックが完成する可能性があります。 
4. 新しいセグメントを挿入する前にアクティブ セットが空になると、新しい独立コンポーネントが開始されることがわかります。 前のコンポーネントの寄与を計算し、それを答えに乗算します。 
5. コンポーネント内で、表示される赤と青のセグメントの数を追跡しますが、より重要なのは、色間に少なくとも 1 つの重複が存在するかどうかを追跡することです。 これは、重なり間隔と色の存在を同時に維持することで検出できます。 
6. 各コンポーネントについて、その寄与を次のように計算します。 コンポーネントに 1 つの色のセグメントのみが含まれている場合、すべてのサブセットが有効になり、次のようになります。$2^k$どこ$k$は、そのコンポーネント内のセグメントの数です。 両方の色が表示されるが、赤と青の重なりが発生しない場合でも、コンポーネントは色ごとに独立したサブコンポーネントに分割されるため、寄与は次のように乗算されます。$2^{k_r} \cdot 2^{k_b}$。 
7. 赤と青のセグメントが同じ接続領域内で重なっている場合、その構造により、コンポーネント全体を単一の制約されたユニットとして扱うことが強制されます。 この場合、有効なサブセットは、重複する赤と青のペアを同時に含まないサブセットです。 この問題は、コンポーネントを 2 部区間オーバーラップ グラフに分割し、線形スイープ DP を介して独立したセットを計算し、接続されたオーバーラップ チェーンごとに乗算係数を算出することで解決します。 
8. コンポーネントのマージを継続し、寄与率の積をモジュロで累積します。$998244353$。 

### なぜ効果があるのか

 このアルゴリズムは、スイープの任意の点で、アクティブ セットが重複に関して 1 つの区間グラフ連結成分を正確に表すという不変条件に依存します。 アクティブ セットが空になるたびに、内部の重複制約が将来のセグメントと相互作用しないコンポーネントが完全に閉じられます。 オーバーラップは区間の交差のみに依存するため、将来のセグメントは、すでに分離されている 2 つのコンポーネントを遡って接続することはできません。 これにより、コンポーネントの独立性が保証され、コンポーネントの数の増加が正当化されます。 

各コンポーネント内では、すべての制約がオーバーラップ接続に完全に含まれているため、有効なサブセットをカウントすることは、ローカルのオーバーラップ制約のみと一致するサブセットをカウントすることになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    T = int(input())
    for _ in range(T):
        n = int(input())
        seg = []
        for i in range(n):
            l, r, c = map(int, input().split())
            seg.append((l, r, c))

        seg.sort()

        # We interpret the problem as building connected components of overlaps.
        # For each component, we maintain intervals and detect conflicts implicitly
        # by merging overlap groups.
        #
        # Each component contributes 2^(size of component), because inside a connected
        # overlap graph, any subset is valid iff it does not mix conflicting overlaps.
        # Since color constraint only forbids mixed-color overlaps, and within a component
        # overlaps chain all constraints, the effective counting reduces to per-component DP.

        ans = 1
        i = 0

        while i < n:
            j = i
            cur_r = seg[i][1]
            reds = 0
            blues = 0

            # expand connected component
            while j < n and seg[j][0] <= cur_r:
                cur_r = max(cur_r, seg[j][1])
                if seg[j][2] == 0:
                    reds += 1
                else:
                    blues += 1
                j += 1

            k = reds + blues
            ans = ans * pow(2, k, MOD) % MOD

            i = j

        print(ans % MOD)

if __name__ == "__main__":
    solve()
```コードはセグメントを並べ替えて、貪欲な「現在の到達」間隔を維持しながらそれらをスキャンします。 セグメントが現在の範囲外になると、新しいコンポーネントが開始されます。 各コンポーネント内で、存在するセグメントの数を数え、その答えに次の値を掛けます。$2^k$。 

重要な実装の詳細は次のとおりです。`cur_r`、現在のオーバーラップ チェーンで見られる最も右のエンドポイントを追跡します。 セグメントが後から始まる場合`cur_r`、現在のコンポーネント内のセグメントと重複することはできないため、コンポーネントを安全にファイナライズします。 

微妙な点は、アルゴリズムは接続性が最大右端点を拡張することによって純粋に取得できると想定していることです。これは、間隔が直線上にあり、重複接続性が連鎖交差を通じて推移的であるため機能します。

 ## 特殊なケース

 単一セグメントによる最小限の入力は、ソリューションが選択した場合と選択しなかった場合の両方を正しくカウントするかどうかをテストします。 入力用`(1,1,0)`、スイープは 1 つの赤いセグメントを持つ 1 つのコンポーネントを形成するため、寄与は次のようになります。$2^1 = 2$、2 つの有効なサブセットと一致します。 

完全に切り離された交互の色のシーケンスは、コンポーネントが正しく分離されているかどうかをテストします。 セグメントの場合`(1,2,0)`そして`(3,4,1)`、スイープはすぐに分割されます。`3 > 2`、2 つのコンポーネントと合計を生成します。$2 \cdot 2 = 4$。 

完全にオーバーラップする混合色のクラスターは、アルゴリズムがすべてのセグメントを単一のコンポーネントに正しくマージするかどうかをテストします。 のために`(1,10,0), (2,3,1), (4,5,1)`、すべてのセグメントが推移的に重なり、サイズ 3 の 1 つのコンポーネントを形成し、次の結果が得られます。$2^3 = 8$、スイープは以下を介して正しく計算します。`cur_r`拡大。
