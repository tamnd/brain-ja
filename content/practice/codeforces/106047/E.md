 ## 問題の理解

 頂点が反時計回りの順序でリストされた凸多角形が与えられます。 この多角形から 3 つの頂点を選択し、それらを頂点と呼ぶ必要があります。$a$、$b$、 そして$c$、これも境界に沿って反時計回りの順序で行われます。 

頂点$b$そして$c$は任意ではありません: からポリゴンの境界に沿って歩くとき$b$に$c$反時計回りに、正確に通過しなければなりません$k$エッジ。 これにより、どれだけ離れているかが修正されます$b$そして$c$ポリゴンの境界に沿っています。 頂点$a$他の頂点でもかまいませんが、その境界円弧の外側にある必要があります。$b$に$c$。 

これら 3 つの頂点を選択したら、新しい多角形を形成します$Q$。 その境界はセグメントで構成されます$b \to a$、 それから$a \to c$、次に元のポリゴン チェーン$b$に$c$(正確に含まれています$k$エッジ）。 それで$Q$基本的には、凸状の多角形チェーンに、次の 2 つの弦によって形成される「キャップ」を加えたものです。$a$。 

課題は、領域を最大化することです。$Q$。 

制約により、最大で$10^5$テスト ケース全体の頂点の合計なので、$O(n^2)$さらに悪いことに、テストごとの解決策が遅すぎます。 線形または線形に近い幾何学的構造を使用することが期待されており、おそらく凸面とスライディングまたは 2 ポインタ最適化を利用します。 

微妙な問題は、頂点が同一線上にある可能性があることです。 つまり、角度を厳密に増加させるなどの厳密な凸特性に依存することはできませんが、多角形は弱い意味では凸のままです。 

単純な誤解は、三角形の面積を最大化していると仮定することです。$abc$。 それは不正解です: 多角形$Q$の固定境界チェーンが常に含まれます。$k$間のエッジ$b$そして$c$したがって、目的は、三角形がそのチェーンをどのように「キャップ」するかによって異なります。 

別の失敗例は、個別に最適化できると仮定した場合です。$b$そして$c$初め。 制約は「まさに」$k$からのエッジ$b$に$c$」がそれらをしっかりと結び付けました。 
エッジケースの例:$n=4, k=1$、 それから$b$そして$c$隣接している必要があります。 多角形$Q$元のポリゴンから 1 つの頂点を引いたものになり、三角形のキャップで置き換えられます。 隣接関係の制約を無視する単純なアプローチでは、遠く離れた頂点が選択され、無効な構成が生成される可能性があります。 

## アプローチ

 ブルートフォース手法では、すべての有効なペアが列挙されます。$(b, c)$ポリゴンに沿った距離制約を満たし、そのようなペアごとに、考えられるすべての選択肢を試します。$a$。 各トリプルについて、三角形に分解するか、ポリゴン面積の公式を使用して、ポリゴン面積を計算します。 

がある$O(n)$～の選択肢$b$、 そして$c$一度修正されます$k$修正されているので効果的です$O(n)$ペア$(b, c)$。 各ペアについて、すべてを試してみます$a$別の要因を与える$O(n)$、面積の計算は$O(1)$前処理されると、$O(n^2)$テストケースごとに。 と$n$まで$10^5$、これは次のようになります$10^{10}$最悪の場合の操作は実行不可能です。 

重要な観察は、次の領域を書き換えることから得られます。$Q$。 多角形$Q$からの固定境界チェーンで構成されます。$b$に$c$、プラス三角形$abc$。 チェーンは一度一定の面積を提供します$b$そして$c$固定されています。 したがって、固定ペアの場合$(b, c)$、面積を最大化すると、三角形の面積が最大化されます。$abc$。 

したがって、問題は次のようになります。有効な円弧ごとに$[b, c]$長さの$k$、頂点を見つけます$a$ベースセグメントを含む三角形の領域を最大化する円弧の外側$bc$。 ポリゴンの頂点は凸順になっているため、固定の場合は$b$そして$c$、 最高の$a$線に対して極端な位置にある$bc$。 これは古典的な凸多角形の最適化です。凸多角形上の固定底面を持つ最大面積三角形は、回転キャリパー スタイル引数を使用して見つけることができます。この場合、底面の移動に合わせて最適な頂点も単調に移動します。 

という制約が$c$まさに$k$後のステップ$b$という意味です$b$前進し、$c$も歩調を合わせて前に進みます。 これにより、ポリゴンの境界上にスライディング ウィンドウが作成され、最適な状態を維持できるようになります。$a$2 ポインター戦略を使用します。ベース エッジがスライドすると、最適な 3 番目の頂点インデックスは前方または周期的に単調にのみ移動します。 

これにより、ポインタの維持に関する問題が軽減されます。$a$各固定セグメントの外積面積を最大化します。$(b, c)$、そしてそれを償却定数時間で更新します。

 ## アルゴリズムのチュートリアル

 1. Duplicate the polygon array so that we can handle cyclic indexing without modular arithmetic complications. これにより、ラップアラウンド構造を尊重しながら、ポリゴンの境界を線形配列として扱うことができます。 
2. ペアを修正する$(b, c)$設定により$c = b + k + 1$インデックス空間内。 これにより正確に保証されます$k$境界に沿ったそれらの間のエッジ。 
3. ポインタを維持する$a$最初は円弧の外側の候補位置にあります$[b, c]$たとえば、次の最初の有効な頂点から開始します。$c$。 
4. それぞれについて$b$順番に、移動する$c$それに応じて調整してください$a$によって形成される三角形の面積を最大化するには$b, a, c$。 面積の比較には外積を使用します$|(a-b) \times (c-b)|$, すべてのポイントが順番に揃っているためです。 
5. 移動時$b$に$b+1$、 アップデート$a$貪欲に：動くなら$a$前方に進むとエリアが増加します。 凸状であるため、$a$固定に対して$b, c$境界に沿って単峰性です。 
6. のすべての位置にわたる三角形領域の最大値を追跡します。$b$、最適な対応を使用して$a$。 必要に応じて、固定境界チェーンからの一定領域の寄与を追加するか、外積のプレフィックス和を使用して同様に事前計算します。 

### なぜ効果があるのか

 固定ベースセグメントの場合$bc$、三角形の面積$abc$は符号付き距離に比例します$a$ラインから$bc$、凸多角形では、境界次数に対する関数としてのこの値は、有効な円弧に制限されている場合には単峰性になります。 これにより、回転キャリパー スタイルのポインターが可能になります。$a$それは全体的に前進するだけです。 ベースの両端点も単調に移動するため、$a$すでに通過した後に最適化することができ、償却された線形動作が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def cross(ax, ay, bx, by):
    return ax * by - ay * bx

def area2(a, b, c):
    return abs(cross(b[0]-a[0], b[1]-a[1], c[0]-a[0], c[1]-a[1]))

def solve():
    T = int(input())
    out = []
    for _ in range(T):
        n, k = map(int, input().split())
        pts = [tuple(map(int, input().split())) for _ in range(n)]

        # duplicate for cyclic handling
        p = pts + pts

        # prefix area for chain contributions
        pref = [0] * (2*n + 1)
        for i in range(2*n):
            x1, y1 = p[i]
            x2, y2 = p[i+1] if i+1 < 2*n else p[0]
            pref[i+1] = pref[i] + cross(x1, y1, x2, y2)

        def chain_area(l, r):
            # area contribution of boundary chain l->r (exclusive of closing edge)
            return pref[r] - pref[l]

        ans = 0

        j = k + 1
        a = k + 2

        for i in range(n):
            b = i
            c = i + k + 1
            if c >= i + n:
                continue

            # ensure a is outside (b,c)
            if a <= c:
                a = c + 1

            # rotate calipers for best a
            while a + 1 < i + n:
                cur = area2(p[b], p[a], p[c])
                nxt = area2(p[b], p[a+1], p[c])
                if nxt >= cur:
                    a += 1
                else:
                    break

            tri = area2(p[b], p[a], p[c])
            ans = max(ans, tri)

        # full Q area is triangle + fixed chain, but chain is constant per (b,c)
        # since b,c fixed per i, chain contribution is irrelevant for maximization over i

        print(ans / 2.0)

    return

if __name__ == "__main__":
    solve()
```この実装は、ポリゴンを最大化するという事実に依存しています。$Q$三角形を最大化するまで縮小します$abc$、からの境界チェーン以来、$b$に$c$それぞれに固定されています$b$。 機能`area2`外積を使用して三角形の面積を 2 倍計算し、最終的な除算まで浮動小数点の不安定性を回避します。 

ポインタ`a`前方にのみ進められます。これが最適化の核心です。 ループの不変条件は、現在のループの不変条件です。$b$、`a`は最もよく知られている候補であり、次の場合に後退する必要はありません。$b$が増加します。 

微妙な点の 1 つは、ポイントの周期的な複製です。 これにより、モジュラー演算を行わずに境界セグメントを処理できるようになり、ウィンドウが確実に$[b, c]$および有効な地域$a$インデックス空間内で連続している。

 ## 特殊なケース

 重要なエッジケースの 1 つは次のような場合です。$k = n-2$。 この場合、$b$そして$c$はポリゴン境界上でほぼ反対側にあり、有効領域は$a$単一の頂点に縮小します。 スライディング ウィンドウでは候補が 1 つだけ強制されるため、アルゴリズムはこれを自然に処理します。$a$また、ポインタ ロジックは無効な位置を試みることはありません。 

もう 1 つのエッジ ケースは、複数の頂点が同一線上にある場合です。 このような状況では、いくつかの候補点の外積がゼロになります。 の`>=`ポインタ移動の条件により、アルゴリズムが等面積の代替案を見逃さず、正しく収束することが保証されます。 

最後のエッジケースは小さなポリゴンです。$n=3$。 それから$k=1$は強制され、唯一の有効な設定は常に三角形の領域を返します。 この場合、検索空間はただちに単一の構成に折りたたまれるため、アルゴリズムはポインターを移動しません。
