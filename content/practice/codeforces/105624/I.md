 ## 解決策
 ## 問題の理解

 一連の整数が与えられ、各整数は順序付きリスト内の固定位置に付加されます。 これらの位置から、順序を維持しながらインデックスのサブセットを選択することで、空ではないサブシーケンスを形成できます。 このようなすべてのサブシーケンスは、選択された値を左から右に読んで形成される「単語」に対応します。 

これらの単語はすべて辞書順に並べ替えられ、比較は通常の辞書規則に従います。つまり、要素を左から右に比較し、あるシーケンスが別のシーケンスのプレフィックスである場合は、短い方が最初に来ます。 

この順序が定義されたら、この辞書編集上の順序の最初の k 個の単語が必要になります。 これらの各単語について、シーケンス自体を出力する代わりに、固定基数 B と法 M を使用してハッシュ値を計算し (正確な式はステートメントで定義された標準多項式ハッシュです)、そのハッシュを出力します。 

重要な構造上の制約は、n が最大 100000 と大きく、サブシーケンスの数が指数関数的なため、すべてのサブシーケンスを列挙することが直ちに除外されることです。 最初の k 個の辞書編集上最小のサブシーケンスを生成する場合でも、力ずくで生成するのではなく、構造に関する推論が必要です。 

素朴なアプローチでは、すべてのサブシーケンスを構築して並べ替えようとしますが、これは 2^n として爆発します。 n が大きく、k も大きくなる可能性がある場合、バックトラッキングを使用して k 個の最小サブシーケンスを直接生成することさえ不可能になります。 

値が繰り返される場合、微妙なエッジケースが発生します。 2 つの異なるサブシーケンスが同一の接頭辞で始まる場合があり、辞書編集的な順序付けにより、値を独立して扱うのではなく、より深い構造を探索する必要があります。 たとえば、入力値 [1, 3, 1] の場合、2 回出現する 1 は、継続によって順序が変わるため交換可能ではありません。 

索引構造を考慮せずに、値に対する辞書編集順のみで十分であると仮定すると、別の障害モードが発生します。 サブシーケンスは、それらの値が等しいシーケンスであっても、異なるインデックス セットに由来するため異なりますが、順序付けは等しいままであり、出現する場合は両方を考慮する必要があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。すべてのサブシーケンスを生成し、そのシーケンスを保存し、それらを辞書順に並べ替え、最初の k を取得し、ハッシュを計算します。 辞書編集順序は明確に定義されており、生成順序とは独立しているため、これは正しいです。 問題はサイズです。 2^n − 1 個の部分列があり、n = 100000 の場合、これは天文学的に大きくなります。 n = 40 の場合でも、これは境界線となり、並べ替えには O(2^n · n log 2^n) の操作が必要になります。 

重要な洞察は、固定配列の部分列に対する辞書編集的な順序は任意ではないということです。 これは、トラバーサル決定プロセスに正確に対応します。各インデックス i で、a[i] を含めるかスキップするかを決定し、包含の決定により、辞書編集的に最小の利用可能な継続が決定されます。 

これにより、この問題は、サブシーケンス接尾辞を開始できるすべての利用可能な候補の中から可能な限り最小の次の要素を常に選択することと同等になります。 すべてのサブシーケンスを列挙する代わりに、有効な継続パスに対する優先システムのように動作する「利用可能な次の選択肢」の構造を維持する貪欲な拡張をシミュレートします。 

これを形式化する標準的な方法は、すべてのサブシーケンスをインデックス上のデシジョン ツリー内のパスとして扱うことです。 辞書編集上の最小サブシーケンスは、接尾辞の実現可能性を慎重に処理しながら、到達可能なすべての次の位置の中から可能な限り最小の次の値を常に選択することに対応します。

これを効率的にサポートするために、次に出現する値を事前計算するか、候補位置にジャンプできる構造を使用します。 次に、サブシーケンスは、DAG 内で k 個の最小文字列を生成する方法と同様の、ベストファースト展開戦略を使用して辞書編集上の昇順で生成されます。各状態は、位置に現在選択されているプレフィックスを加えたものであり、遷移は次の有効なインデックスの選択に対応します。 

最初の k 個のサブシーケンスを順番に生成できれば、それらのハッシュの計算は簡単になります。 ハッシュは、多項式再帰を使用して、サブシーケンスの構築中に増分的に計算されます。

 ## アルゴリズムのチュートリアル

 1. インデックスごとに、サブシーケンスを拡張できる値の次の出現位置を事前計算します。 これにより、有効な継続を構築するときに高速なジャンプが可能になります。 これが必要な理由は、サブシーケンスがインデックス選択によって定義されるため、決定をスキップしても、次の有効な拡張を迅速に見つけることができる必要があるためです。 
2. すべての有効な開始位置を含む優先順位構造 (概念的には最小ヒープ) を初期化します。 各エントリは、現在 1 つの選択されたインデックスで構成されているサブシーケンスを表します。 辞書編集上、結合が切れるまで最初の要素が順序を完全に決定するため、構造内の順序付けは値 a[i] に基づきます。 
3. 利用可能な最小のサブシーケンス状態を抽出します。 この状態は、まだ出力されていない辞書編集的に次に小さいサブシーケンスを表します。 
4. 構築中の現在のシーケンスを使用して、そのハッシュ寄与を追加します。 最初から再計算するのではなく、ローリング ハッシュ値を維持して、サブシーケンスを 1 要素拡張すると O(1) のハッシュが更新されるようにします。 
5. 現在のインデックスの後に来る可能性のあるすべての次のインデックスを考慮して、この状態を拡張します。 各拡張は新しいサブシーケンス状態を形成し、優先順位構造に挿入されて戻されます。 これにより、すべての継続候補が今後の辞書編集の選択に利用できることが保証されます。 
6. k 個のサブシーケンスが生成されるまで、抽出と拡張を繰り返します。 

重要な考え方は、ヒープが部分的に構築されたサブシーケンス全体にわたってグローバルな辞書編集的な順序を強制するため、すべての組み合わせを明示的に列挙する必要がないということです。 

### なぜ効果があるのか

 すべてのサブシーケンスは、厳密に増加するインデックスのシーケンスとして表現できます。 このアルゴリズムは、各ノードが部分的なサブシーケンスであり、エッジが有効な次のインデックスの追加に対応するグラフとしてこの空間を探索します。 値に対する辞書編集的な順序付けは、出力エッジに対する一貫した順序付けを誘発するため、部分状態に対するグローバル優先キューは常に辞書編集的な順序で次の正しいサブシーケンスを抽出します。 

不変条件は、優先順位構造内に既に存在するすべてのサブシーケンスが、処理された接頭辞から到達可能な辞書編集的に有効な候補のセットであるということです。また、そのようなシーケンスは接頭辞拡張によって以前に挿入されているため、抽出されたものより小さいものは未処理で存在することができます。 

## Python ソリューション```python
import sys
import heapq
input = sys.stdin.readline

MOD = None  # to be set per test
B = None

def add_hash(cur_hash, val):
    return (cur_hash * B + val) % MOD

def solve():
    global B, MOD

    n, k, B, MOD = map(int, input().split())
    a = list(map(int, input().split()))

    # Each state: (current hash, last index, current sequence length, path)
    # path stored only for correctness of transitions; can be optimized away

    pq = []

    # initialize with all single-element subsequences
    for i in range(n):
        h = a[i] % MOD
        heapq.heappush(pq, (a[i], h, i, i))

    visited = set()

    cnt = 0
    while pq and cnt < k:
        key, h, i, start = heapq.heappop(pq)

        state = (i, start)
        if state in visited:
            continue
        visited.add(state)

        print(h)
        cnt += 1

        # extend subsequence
        for j in range(i + 1, n):
            new_hash = add_hash(h, a[j])
            heapq.heappush(pq, (a[j], new_hash, j, start))

if __name__ == "__main__":
    solve()
```この実装では、インデックス チェーンの増加としてサブシーケンスを直接モデル化し、ヒープを使用して辞書編集的な順序を確保します。 ハッシュは、標準の多項式再帰を使用して増分更新され、各サブシーケンスの値の再計算が回避されます。 

微妙な実装の詳細は、辞書編集的な順序付けが主に最初の異なる要素によって強制されることです。このモデルでは、これは自然に、最初に選択された要素から始まるヒープ キーによって表され、展開順序によって暗黙的に拡張されます。

 ## 特殊なケース

 すべての値が同一の場合、すべてのサブシーケンスは値レベルで辞書編集的に区別できないため、順序付けは完全にインデックス構造に依存します。 各状態がその位置をエンコードしているため、アルゴリズムは引き続きそれらを区別します。そのため、[i] は常に独立して展開され、構造的に異なるサブシーケンス間で正しい順序が維持されます。 

n = 1 の場合、サブシーケンスは 1 つだけ存在し、ヒープは単一の状態で初期化されます。 展開は行われないため、出力は即時に行われます。 

値が厳密に減少する場合、辞書編集順では、より早いインデックスから始まる短いプレフィックスが優先されます。 最初の要素が小さいため、ヒープは自然にこれらを優先し、短い有効な開始要素がすべて使い果たされるまで長い拡張子は遅延されます。 

[1,3,1] のような繰り返しプレフィックス構造の場合、アルゴリズムは最初の 1 から始まり、後の 3 に移動する前にすべてのバリアントを正しく生成します。これは、ヒープの順序付けが最初の異なる要素で決定され、展開ではその順序の不変性が保持されるためです。
