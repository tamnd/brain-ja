 ## 解決策
 ## 問題の理解

 このグラフは、双方向のフェリー ルートで結ばれた島のグループを表しています。 各ルートには旅費がかかり、モアナが島を訪れることを選択した場合は、どの島にも税金を支払わなければなりません。 モアナは考えられるすべての島から別々に出発し、どこかの島を訪れて税金を支払い、その後出発地に戻りたいと考えています。 タスクは、すべての開始島についてこの最小合計コストを見つけることです。 元の問題は Codeforces Gym 105624、問題 B のものです。 

島の場合`u`、モアナが目的地を選択した場合`v`、旅行費`dist(u, v)`フェリーは双方向なので、行きと帰りの料金は同じです。 合計は次のようになります。```
2 * dist(u, v) + a[v]
```考えられるすべての宛先でこの値を最小化する必要があります`v`。 

入力サイズが十分に大きいため、すべてのアイランドを個別に処理することは不可能です。 まで`2 * 10^5`島とルート、すべての島から最短経路アルゴリズムを実行するアプローチには、約`n * (m log n)`これは、最悪の場合でも約 10 億回の操作に相当します。 意図したソリューションでは、グラフ全体をほぼ線形の時間で処理する必要があります。 

難しい部分は、最短経路そのものを見つけることではなく、考えられるすべての目的地を 1 つの計算に組み合わせることにあります。 不用意な解決策では、各島からディクストラを実行し、他の島に到達した後に最も安い税金を追加する可能性があります。 200,000 個の島を含むグラフの場合、これはほぼ同じ作業を何度も繰り返します。 

もう 1 つのエッジ ケースは、最も安い目的地が開始島自体である場合です。 例えば：```
Input
2 1
1 2 5
3 10
```島1の答えは、`3`, なぜなら、島1に滞在するのにかかるのはその税金だけだからです。 少なくとも 1 つのエッジに沿った移動のみを考慮するソリューションでは、誤った出力が発生します。`13`。 

2 番目の特殊なケースは、近くの高価な島よりも、税金が安い長い航路の方が良い場合です。 例えば：```
Input
3 2
1 2 5
2 3 1
100 1 2
```島1の場合、島3に行くには費用がかかります`5 + 1 = 6`片道なので合計は`12 + 2 = 14`。 島2を選択すると`10 + 1 = 11`, したがって、ここでは島2の方が実際には優れています。 直接隣接するもののみをチェックする実装では、より大きなグラフでは有効な宛先が失われる可能性があります。 

## アプローチ

 直接総当たり方式は簡単です。 開始島ごとに`u`、ダイクストラを実行して、他のすべての島までの距離を計算します。 次にすべての島をスキャンします`v`の最小値を取得します`2 * dist(u, v) + a[v]`。 ダイクストラは選択した開始点の正確な最短経路距離を与えるので、これは正しいです。 問題は繰り返し作業です。 と`n`実行すると、複雑さが増します`O(nm log n)`、これは制約が許容する範囲をはるかに超えています。 

重要な観察は、どの開始島も同じ種類の質問をするということです。 出発地を選択して目的地を検索する代わりに、視点を逆転させることができます。 すべての島にはすでに税金と同じ初期費用がかかっていると想像してください。 これらの値をグラフ全体に広げます。 島からの値の場合`v`エッジを横切って移動すると、最終的な答えにはエッジへの移動が含まれるため、エッジの重みが 2 倍になります。`v`そして復路。 

これにより、式が標準の最短経路問題に変換されます。 すべてのエッジの重みが 2 倍になるグラフを作成し、最初に`a[v]`すべての島の優先キューに入れる`v`、複数ソースのダイクストラは次のように計算します。```
min(a[v] + shortest doubled-edge distance from u to v)
```それは正確には:```
min(a[v] + 2 * dist(u, v))
```グラフ構造によりこれが可能になるのは、すべての目的地が潜在的な答えの独立した情報源であり、ダイクストラが自然に各島に到達する最も安価な目的地を維持するためです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nm log n) | O(n + m) | 遅すぎる |
 | 最適 | O((n + m) log n) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. アイランドの隣接リストを作成します。 すべてのフェリールートと料金`w`、コスト付きのエッジを保存します`2 * w`。 ここで 2 倍化が行われるのは、目的地に向かうすべての動きが同じ元に戻る動きとペアになっているためです。 
2. すべての島を独自の税額で優先キューに入れる`a[i]`初期距離として。 各島は、他のすべての島への答えとなる可能性のある目的地を表しています。 
3. ダイクストラのアルゴリズムを通常どおり実行します。 キューから島を削除するときは、2 倍のエッジ コストを使用して隣接するすべての島を緩和してみてください。 
4. 現在のアイランドを介して近隣に到達すると、より小さい値が得られる場合は、それを更新し、新しい値をキューにプッシュします。 
5. 優先キューが空になった後、各島に保存されている距離は、モアナがそこから開始するときに費やさなければならない最小量となります。 

機能する理由: 各初期値`a[v]`島の選択を表します`v`目的地として。 この値をグラフ内で移動すると、`2 * edge_cost`使用するフェリーごとに、行きの費用と正確に一致します。`v`そして戻る。 変換されたエッジの重みはすべて負ではないため、ダイクストラは常に各アイランドに到達する可能な限り最も安価な値を維持します。 考えられるすべての宛先がキュー内で開始されるため、各アイランドの最終値はすべての宛先の最小値になります。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    graph = [[] for _ in range(n)]

    for _ in range(m):
        u, v, w = map(int, input().split())
        u -= 1
        v -= 1
        w *= 2
        graph[u].append((v, w))
        graph[v].append((u, w))

    a = list(map(int, input().split()))

    dist = a[:]
    pq = [(a[i], i) for i in range(n)]
    heapq.heapify(pq)

    while pq:
        cur, u = heapq.heappop(pq)

        if cur != dist[u]:
            continue

        for v, w in graph[u]:
            nxt = cur + w
            if nxt < dist[v]:
                dist[v] = nxt
                heapq.heappush(pq, (nxt, v))

    print(*dist)

if __name__ == "__main__":
    solve()
```ルートの数は多いものの、入力サイズは線形であるため、隣接リストにはフェリー ネットワークが効率的に格納されます。 保存されているすべてのエッジにはすでに重みが 2 倍されているため、ダイクストラ緩和は必要な式と直接一致します。 

距離配列は、無限大ではなく島税を使用して初期化されます。 これが通常の単一ソースのダイクストラとの主な違いです。 すべての島が目的地となる可能性があるため、すべての島が回答源の候補として開始されます。 

より適切なルートが見つかった後、優先キューには古い値が含まれる可能性があります。 の`if cur != dist[u]`check はそれらのエントリを破棄し、アルゴリズムの効率を維持します。 

Python の整数はオーバーフローしないため、可能な最大パス コストが 32 ビット整数の制限を超える可能性があるため、これは便利です。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n + m) log n) | 各アイランドは優先キューに入り、各ルートは各エンドポイントから 1 回緩和されます。 |
 | スペース | O(n + m) | グラフにはすべてのフェリーのルートが保存され、配列には距離とキューのデータが保存されます。 |

 この制約により、最短パスの計算を繰り返さないようにする必要があります。 マルチソース ダイクストラ アプローチでは、グラフ全体が 1 回処理されるため、制限内に問題なく収まります。 

## テストケース```python
import sys
import io
import heapq

def solve_io(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n, m = map(int, input().split())
    graph = [[] for _ in range(n)]

    for _ in range(m):
        u, v, w = map(int, input().split())
        u -= 1
        v -= 1
        w *= 2
        graph[u].append((v, w))
        graph[v].append((u, w))

    a = list(map(int, input().split()))

    dist = a[:]
    pq = [(dist[i], i) for i in range(n)]
    heapq.heapify(pq)

    while pq:
        d, u = heapq.heappop(pq)
        if d != dist[u]:
            continue
        for v, w in graph[u]:
            nd = d + w
            if nd < dist[v]:
                dist[v] = nd
                heapq.heappush(pq, (nd, v))

    return " ".join(map(str, dist)) + "\n"

 ## 特殊なケース

 滞在が最適な場合:```
2 1
1 2 5
3 10
```両方のアイランドは優先キューから開始されます。 アイランド 1 は値で始まります`3`、フェリーを通過するたびにプラスの量が追加されるため、他の島を通過するパスは改善できません。 答えは残っている`3`。 

より良い目的地が隣接していない場合:```
3 2
1 2 5
2 3 1
100 1 2
```最初のキューには値が含まれています`100`、`1`、 そして`2`。 値`1`追加料金で島 2 から島 1 に広がります`10`、生産`11`。 アイランド 3 の値は、追加コストを伴いアイランド 1 に到達します。`12`、生産`14`。 アルゴリズムは小さい値を維持し、直接隣接するものだけではなく、考えられるすべての宛先が考慮されることを証明します。
