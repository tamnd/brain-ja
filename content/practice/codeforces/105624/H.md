 ## 問題の理解

 タスクは、ソートされた最終的な配列の中央値が正確になるように、既存の配列に最小数の整数を追加することです。`x`。 中央値の定義は、ソート後の左中央の要素であり、長さの配列の場合は次のようになります。`m`、中央値は位置の要素です`(m + 1) // 2`1 つのベースのインデックスを使用します。 これは、元の問題で使用されたものと同じ下位中央値の規則です。 

入力により、現在の値の数、必要な中央値、および配列自体が得られます。 新しい値を挿入することのみが可能であり、既存の値は変更できません。 出力は、必要な挿入値の最小数です。 

配列の長さは最大 500 です。これは、均等な解が存在することを意味します。`O(n^2)`フィットする可能性があります。 ただし、問題の構造により、より単純な問題が可能になります。`O(n log n)`仕分け後のアプローチ。 重要な観察は、以下の値の数だけが存在することです。`x`、に等しい`x`、より大きい`x`答えに影響します。 実際の挿入をシミュレートする必要はありません。 

不注意な解決策は、次のような場合に失敗することがよくあります。`x`が存在しないか、現在の中央値に近いが正確ではない場所`x`。 例えば：```
3 10
10 20 30
```答えは`1`。 既存のものだけをカウントするソリューション`x`値は失敗します。`x`はすでに存在しますが、現在の中央値は`20`。 

別の例:```
3 4
1 2 3
```答えは`4`。 1 つだけ追加する`4`与える`[1,2,3,4]`、その中央値は`2`、 ない`4`。 最終的な配列には、以下の値以上の十分な値が含まれている必要があります。`4`中央の位置が挿入された値に達するようにします。 

3 番目のよくある間違いは、すでに正しい中央値を誤って処理することです。```
5 3
1 2 3 4 5
```答えは`0`。 常に挿入するソリューション`x`それが表示されると、誤った肯定的な答えが生成されます。 

## アプローチ

 直接的な強引なアイデアは、値を 1 つずつ追加して、中央値が次になるかどうかを確認することです。`x`。 長さが変わると中央位置も変わるため、配列のソートやカウントを繰り返し行う必要があります。 考えられる多数の挿入カウントを試してみると、チェックの数はすぐに不要な作業になってしまいます。 関連するバリアントの入力サイズが大きい場合、ソートされた配列を繰り返し再構築することがボトルネックになります。 

重要な点は、実際に挿入された値が柔軟であるということです。 より小さい値を挿入できます`x`、に等しい`x`、またはそれより大きい`x`、そしてこれら 3 つのグループが重要です。 

させて`less`既存の値の数が以下であること`x`、 そして`equal`既存の値の数が以下に等しいこと`x`。 並べ替え後、中央値の位置は、すべての値が次の値より小さい必要があります。`x`、しかし結局のところ値は次の値に等しくありません`x`。 

もし`x`が欠落している場合は、最初に のコピーを 1 つ挿入します。`x`。 その後は、中央位置付近でカウントのバランスを再調整するだけです。 もし`x`すでに存在する場合は、中央位置をブロックに直接移動できます。`x`必要な側に値を追加して値を追加します。 

挿入後の中央値の位置を考慮することで貪欲に実装可能`x`必要に応じて、中央境界を移動するために必要な最小数の値のみを追加します。

 ## アルゴリズムのチュートリアル

 1. 配列をソートし、以下を含む最初と最後の位置を見つけます。`x`。 並べ替えは、以下の値をすべてグループ化します。`x`、に等しい`x`、より大きい`x`別々の範囲に分割するため、カウントについてのみ推論できます。 
2. もし`x`存在しません。のコピーを 1 つ挿入します`x`概念的に、答えを 1 つ増やします。 中央値は既存の値である必要があるため、この挿入がなければターゲット値は中央値になることはできません。 
3. ゼロベースのインデックスを使用して、現在の配列の中央位置を計算します。`(n - 1) // 2`。 
4. この位置がすでに以下に等しい値のブロック内にある場合`x`、これ以上挿入する必要はありません。 
5. 中央位置が最初の位置より前にある場合`x`より小さい値が多すぎます。`x`。 以上の値を追加します`x`中央の位置が内側に移動するまで`x`ブロック。 
6. 中央位置が最後の位置より後の場合`x`、より大きい値が多すぎます`x`。 以下の値を加算します`x`中央位置に達するまで`x`。 

これが機能する理由: ソートされた配列は 3 つの領域に分割されます。 中央値が失敗する唯一の方法は、中央値インデックスが、`x`。 反対側に数字を追加すると、既存の境界線を破壊することなく境界線が移動します。`x`ブロック。 すべての挿入で中央位置が最小限に変更されるため、貪欲な追加は最小限で済みます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, x = map(int, input().split())
    a = list(map(int, input().split()))

    ans = 0

    if x not in a:
        a.append(x)
        n += 1
        ans += 1

    a.sort()

    left = 0
    while left < n and a[left] < x:
        left += 1

    right = left
    while right < n and a[right] == x:
        right += 1

    median = (n - 1) // 2

    if left <= median < right:
        print(ans)
        return

    if median < left:
        need = 2 * left - n + 1
        ans += need
    else:
        need = n - 2 * right
        ans += need

    print(ans)

if __name__ == "__main__":
    solve()
```最初の部分では特殊なケースを扱います。`x`は不在です。 追加`x`中央値は最終的にソートされた配列の要素でなければならないため、これは必須です。 

並べ替えた後、`left`の最初の出現を指します`x`、 そして`right`最後に発生した直後のポイント`x`。 間隔`[left, right)`はまさに、中央値インデックスが到達する必要がある安全ゾーンです。 

中央値インデックスが小さすぎる場合、配列には以下の値が多すぎます。`x`。 大きな値を追加すると、配列の長さが長くなり、中央位置が右に移動します。 中央値インデックスが大きすぎる場合、小さな値を追加すると中央値の位置が左に移動します。 数式は、最小限必要なシフトをカウントします。 

式では整数演算のみが使用されます。 Python の整数はオーバーフローしませんが、固定幅の整数を使用する言語の同じ数式は慎重にチェックする必要があります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    old = sys.stdin
    sys.stdin = io.StringIO(inp)
    data = sys.stdin.read().split()
    sys.stdin = old

    if not data:
        return ""

    n = int(data[0])
    x = int(data[1])
    a = list(map(int, data[2:]))

    ans = 0
    if x not in a:
        a.append(x)
        n += 1
        ans += 1

    a.sort()

    left = 0
    while left < n and a[left] < x:
        left += 1

    right = left
    while right < n and a[right] == x:
        right += 1

    median = (n - 1) // 2

    if median < left:
        ans += 2 * left - n + 1
    elif median >= right:
        ans += n - 2 * right

    return str(ans)

""") == "0"
