 ## 解決策
 ## 問題の理解

 最大で 6 つの長方形のチェス盤があります。$10^9$行と列。 2 人のプレイヤーはそれぞれ、ルークまたはビショップのいずれか 1 つの駒を正確に制御します。 駒は通常のチェスの移動ルールを使用して移動します。ルークは行または列に沿って移動し、ビショップは対角線に沿って移動します。 プレーヤーは、自分の駒が相手の駒を捕獲するとすぐに勝ちとなります。 両プレイヤーは立場を理解しており、常に自分の結果を最大化する手を選択します。 

入力にはいくつかの独立したゲームが含まれています。 各ゲームについて、ボードのサイズ、マウイの駒の開始マスと種類、モアナの駒の開始マスと種類がわかっています。 マウイが先に動く。 マウイが勝利を強制できるか、モアナが勝利を強制できるか、あるいは最適なプレイが無限の引き分けにつながるかどうかを判断する必要があります。 

ボードの寸法は非常に大きいため、ボード上の動きをシミュレートすることは不可能です。 サイズのボード$10^9 \times 10^9$セルが多すぎて一度でも検査できません。 最大 5000 のテスト ケースを使用する場合、ソリューションは座標の演算のみを使用する必要があり、ボード領域に依存することはできません。 

重要なエッジケースは、さまざまな種類の動作の相互作用から発生します。 たとえば、1 つの行に 2 つのルークが配置されているとします。```
1
1 10
1 5 R
1 7 R
```正しい答えは、`WIN`。 現在の駒がすぐにキャプチャできるかどうかだけをチェックする不注意なアプローチはここでも機能しますが、プレイヤーがすぐにキャプチャせずに勝ちマスに移動できる位置では失敗します。 

もう 1 つの重要なケースは、同じ色の 2 人のビショップです。```
1
4 4
4 4 R
1 1 B
```正しい答えは、`DRAW`。 ルークはビショップの対角線に移動して最終的にキャプチャすることができますが、両方のプレイヤーは相手に永遠に安全なキャプチャの機会を与えることを避けることができます。 駒が互いに攻撃しているかどうかだけをチェックすると、この種の局面が見落とされます。 

最後によくある間違いは、ボードの境界を無視することです。 例えば：```
1
2 2
1 2 R
2 1 B
```正しい答えは、`WIN`。 ルークは、ビショップがすぐに応答できない唯一のマスに移動できます。 交差がボード内に留まるかどうかを確認せずに、無限のチェス ラインを生成すると、無効な手が生成される可能性があります。 

## アプローチ

 簡単なアイデアは、ゲーム ツリーをシミュレートすることです。 各ポジションから可能なすべての手を生成し、結果のポジションを再帰的に評価し、誰かがキャプチャしたときに停止します。 これは正しいです。最終的に誰かが勝てばゲームは有限であり、ミニマックスは最適なプレイを表すからです。 ただし、ルークはほとんどのことを行うことができます。$2 \cdot 10^9$巨大なボード上で可能な手を一度に生成することさえ不可能です。 最悪のケースは基板サイズに比例し、制約に収まりません。 

有益な観察は、プレイヤーは確実に占領の機会を生み出す正方形に移動できるかどうかだけを知る必要があるということです。 プレイヤーがマス目に移動し、そこから相手を攻撃するとします。 相手は 1 ターンの反応を得る。 相手が攻撃側の駒をすぐに占領できた場合、計画は失敗します。 それ以外の場合は、最初のプレイヤーが次の動きでキャプチャします。 これは、唯一関連する問題は、相手から攻撃を受けずに相手を攻撃する到達可能なマスが存在するかどうかであることを意味します。 

勝ちとなる可能性のあるマスはボード全体に広がっていません。 それらは動線間の交差点です。 ルークは行と列に貢献し、ビショップは対角に貢献します。 これらの小さなセットを交差させると、最大 4 つの候補正方形が得られます。 座標式を使用して各候補を直接確認できます。 

現在のプレイヤーがこの勝ち手を持っているかどうかを計算した後、同じロジックを対戦相手に適用します。 両方のプレイヤーが自分のターンから強制的な勝利の手を持っている場合、最初のプレイヤーが先に動いて勝ちます。 相手だけがそのような手を持っていた場合、先手のプレイヤーが負けます。 どちらのプレイヤーもそれを持っていない場合、両方とも永遠に負けることを避けることができるため、結果は引き分けになります。

 ## アルゴリズムのチュートリアル

 1. ある駒が別の駒を攻撃しているかどうかをチェックする機能を実装します。 ルークの場合、これは行または列を共有することを意味します。 司教にとって、これは同じ価値観を持つことを意味します。$x-y$または$x+y$。 
2. プレイヤーが勝ち手を持っているかどうかを判定する関数を実装します。 現在の駒がすでに相手を攻撃している場合、プレイヤーはすぐに捕まえて勝ちます。 
3. すぐに占領できない場合は、現在の駒と相手のマスの動線を構築します。 現在のプレイヤーが対戦相手を攻撃できるすべての正方形は、これらのラインの交点の 1 つになければなりません。 
4. これらの線のすべての交点を生成します。 各ピースには最大 2 つの動線ファミリーがあるため、可能な交差の数は一定数だけです。 
5. すべての候補マスについて 3 つの条件をチェックします。 マスはボード内にある必要があり、現在の駒が到達できる必要があり、対戦相手はそのマスを攻撃してはなりません。 そのようなマスが存在する場合、現在のプレイヤーは強制的に勝利します。 
6. マウイが勝利をもたらす能力を評価する。 マウイが強制的に勝利を収めることができない場合は、ターンを変更して得られた同じ位置からモアナが勝利を強制できるかどうかを評価します。 モアナができるなら、答えはこうだ`Lose`; そうでなければ答えは`Draw`。 

これが機能する理由: 不変条件は、勝ちの動きはすべて、移動中のプレイヤーが対戦相手を攻撃するマス目を通過する必要があり、すぐに捕まえることはできないということです。 そのようなマスが存在する場合、プレイヤーは最大 2 ターンで勝ちます。 そのようなマスが存在しない場合、直接的な脅威を生み出そうとする試みはすべて対戦相手によって応答される可能性があるため、シーケンスが強制的に勝利を生み出すことはできなくなります。 両方のプレイヤーが同じルールに従うため、起こり得る 3 つの結果は、2 人のプレイヤーの勝利能力をチェックすることによって完全に決定されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def attacks(piece, a, b):
    x1, y1, _ = a
    x2, y2, _ = b
    if piece == 'R':
        return x1 == x2 or y1 == y2
    return x1 - y1 == x2 - y2 or x1 + y1 == x2 + y2

def lines(piece, x, y):
    if piece == 'R':
        return [('v', x), ('h', y)]
    return [('d1', x - y), ('d2', x + y)]

def intersect(l1, l2):
    t1, a = l1
    t2, b = l2

    if t1 == t2:
        return None

    if t1 > t2:
        t1, a, t2, b = t2, b, t1, a

    if t1 == 'h' and t2 == 'v':
        return a, b
    if t1 == 'v' and t2 == 'd1':
        return a, a - b
    if t1 == 'v' and t2 == 'd2':
        return a, b - a
    if t1 == 'h' and t2 == 'd1':
        return b + a, a
    if t1 == 'h' and t2 == 'd2':
        return b - a, a
    if t1 == 'd1' and t2 == 'd2':
        if (a + b) % 2 != 0:
            return None
        return (a + b) // 2, (b - a) // 2

def inside(x, y, n, m):
    return 1 <= x <= n and 1 <= y <= m

def can_win(n, m, cur, opp):
    x, y, c = cur

    if attacks(c, cur, opp):
        return True

    for a in lines(c, x, y):
        for b in lines(opp[2], opp[0], opp[1]):
            p = intersect(a, b)
            if p is None:
                continue
            nx, ny = p
            if not inside(nx, ny, n, m):
                continue
            if (nx, ny) == (opp[0], opp[1]):
                continue
            if not attacks(c, cur, (nx, ny, c)):
                continue
            if not attacks(opp[2], opp, (nx, ny, opp[2])):
                return True
    return False

def solve():
    t = int(input())
    ans = []
    for _ in range(t):
        n, m = map(int, input().split())
        x1, y1, c1 = input().split()
        x2, y2, c2 = input().split()
        p1 = (int(x1), int(y1), c1)
        p2 = (int(x2), int(y2), c2)

        if can_win(n, m, p1, p2):
            ans.append("Win")
        elif can_win(n, m, p2, p1):
            ans.append("Lose")
        else:
            ans.append("Draw")
    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```の`attacks`関数はチェスのルールを 1 か所に分離し、ルークとビショップのロジックの重複を回避します。 対角チェックでは標準の不変条件が使用されます$x-y$そして$x+y$したがって、座標が次のように大きい場合でも機能します。$10^9$。 

の`intersect`関数は、考えられるすべての動線のペアを処理します。 ジオメトリでは勝利の可能性のあるマスの数が一定数しかないため、行、列、または対角線にわたるループはありません。 

ターン順序が重要であるため、メイン ルーチンは最初にマウイをチェックします。 マウイが勝利の手を持っている場合、モアナには彼女自身の勝利戦略を使用する機会は決してありません。 それ以外の場合は、モアナをチェックして次のいずれかを決定します。`Lose`そして`Draw`。

 ## 特殊なケース

 2 人のルークが 1 つの行を共有している場合、アルゴリズムはすぐに勝ちを返します。`attacks`中間の正方形を探す前にキャプチャ ラインを見つけます。 座標のみを比較するため、巨大なボード サイズは問題になりません。 

小さなボード上のルークとビショップのポジションの場合、アルゴリズムはルークのラインとビショップの対角線が交差する可能性を生成します。 ボード外の交差点を拒否し、相手がすぐに占領できないマス目のみを受け入れます。 これにより、不正な「無限ボード」の移動が防止されます。 

両方のプレーヤーに安全な勝ちマスがないポジションの場合、アルゴリズムは両方向をチェックします。 どちらの側も強制占領を作り出すことができない場合、すべてのプレイヤーは負けた位置を与えることなく動き続けることができるため、正しい結果は次のようになります。`Draw`。
