 ## 解決策
 ## 問題の理解

 最大で無向重み付きグラフが与えられます。$10^5$頂点まで$4 \cdot 10^5$エッジ。 各エッジには初期重みがあります。 グラフがつながっています。 

あらゆるエッジに$f$、他のエッジとは独立して、その重みのみを非常に広い範囲の任意の整数に変更することができます。 この新しい重みを修正した後、$f$では、グラフのすべてのスパニング ツリーを調べ、合計の重みが最小のもの、つまり最小のスパニング ツリーを検討します。 この質問では、エッジに割り当てることができる最大値を求めています。$f$このエッジを含む最小スパニング ツリーが少なくとも 1 つまだ存在するようにします。 

したがって、各エッジについて、それが元の MST に属しているかどうかは尋ねません。 グラフの残りの部分が変更されていないと仮定して、一部の MST で使用できる可能性を維持しながら、その重みをどこまで「膨らませる」ことができるかを考えています。 

この制約は、エッジごとに MST を最初から再計算しようとするソリューションは不可能であることを意味します。 単一の MST 計算は次のようになります。$O(m \log n)$、そしてそれをしていると$m$時間は限界をはるかに超えているでしょう。 二次関数であっても$n$または$m$はすぐに除外されます。 目的のソリューションでは、グローバル構造を 1 回前処理してから、ほぼ一定時間または対数時間で各エッジに応答する必要があります。 

微妙なエッジ ケースは、エンドポイント間に複数のパスが存在する、平行に見える構造から発生します。 たとえば、2 つの頂点が同様の重みを持つ複数のパスで接続されている場合、1 つのエッジの重みを増やすと、最適な代替ルートに応じて、その適格性が損なわれる場合とそうでない場合があります。 決定はグローバル接続に依存するため、ローカルの近隣のみを比較するような単純な考えは失敗します。 

もう 1 つの特殊なケースは、グラフに複数の等しい重みの MST 選択肢が含まれている場合です。 エッジが 1 つの MST に存在しない場合でも、別の MST に存在する可能性があるため、固定ツリーではなく、存在という観点から推論する必要があります。 

## アプローチ

 ブルートフォースのアイデアは簡単です: 各エッジに対して$f = (u, v)$、その重みを一時的に何らかの値に設定します$x$、最小スパニング ツリーを再計算し、その MST に含まれるかどうかを確認します。$f$。 バイナリ検索により$x$、有効な最大値を見つけることができました。 

MST の構築はよく理解されているため、概念的には機能しますが、計算的には実行不可能になります。 各 MST の計算コスト$O(m \log n)$、エッジごとに何度も必要になります。 二分探索を無視しても、各候補値をチェックするだけで、$O(m^2 \log n)$あるいはさらに悪いことに。 

重要な点は、実際には重みの変更をシミュレートする必要がないということです。 重要なのは MST の構造特性です。つまり、エッジが特定の MST に属することができるかどうかは、元のグラフ内のその端点間の代替パスにのみ依存します。 エンドポイント間に十分に安価な代替接続が存在する場合、エッジを重くしすぎるとそれが除外されます。 それ以外の場合は、存続可能です。 

これにより、問題は古典的なミニマックス パス クエリに集約されます。 エッジ用$(u, v)$、間のパスに沿った最大エッジ重みの可能な最小値が必要です。$u$そして$v$。 この値は、それを超えるとエッジがどの MST でも使用できなくなるしきい値を完全に決定します。 

グラフ理論の標準的な結果は、これらのミニマックス値がグラフの最小スパニング ツリー内のパス上の最大エッジの重みに正確であるということです。 したがって、1 つの MST を一度構築すれば、そのツリー上のパス最大クエリを使用してすべてのエッジ クエリに答えることができます。

 ## アルゴリズムのチュートリアル

 1. クラスカルのアルゴリズムを使用してグラフの最小スパニング ツリーを構築します。 目的は、パス クエリが元のグラフのミニマックス接続に対応する構造を抽出することです。 
2. MST を任意にルート化し、最低共通祖先 (LCA) クエリ用に前処理します。 バイナリ リフティングとともに、各ノードからその祖先までの最大エッジ重みを 2 のべき乗で保存します。 これにより、任意のツリー パス上の最大エッジの重みを効率的に計算できます。 
3. 各エッジについて$f = (u, v)$、MST にクエリを実行して、間の一意のパスに沿った最大エッジの重みを見つけます。$u$そして$v$。 この値は、これらのエンドポイント間の最良の代替接続のボトルネックになります。 
4. このボトルネック値をエッジの答えとして出力します$f$。 

ステップ 3 が機能する理由は、2 つの頂点間の MST パスが接続パスに沿った最大エッジを最小化するためです。 したがって、エッジに対して可能な限り最強の「競合」パスを直接提供します。$f$。 

### なぜ効果があるのか

 エッジを修正する$f = (u, v)$。 以下を含むスパニング ツリーを検討してください。$f$。 削除中$f$ツリーを 2 つのコンポーネントに分割し、カットを定義します。 間の代替パス$u$そして$v$他のエッジを使用してこのカットを横切る必要があります。 すべてのエッジの重みが厳密に特定の値よりも小さいパスが存在する場合$x$を設定してから、$f$体重をかける$x$～を不可能にする$f$サイクル交換では代替パスが常に優先されるため、あらゆる MST で競争力を維持できます。 

MST は、間のすべての可能なパスの中で、$u$そして$v$、最大エッジ重みを最小化するパスは、正確にこのしきい値を捕捉します。 したがって、最大安全重量は、$f$は、元のグラフの端点間の最小パス値であり、MST 構造から取得されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

n, m = map(int, input().split())
edges = []
for i in range(m):
    u, v, w = map(int, input().split())
    edges.append((w, u - 1, v - 1, i))

edges.sort()

parent = list(range(n))
size = [1] * n

def find(x):
    while parent[x] != x:
        parent[x] = parent[parent[x]]
        x = parent[x]
    return x

def union(a, b):
    a = find(a)
    b = find(b)
    if a == b:
        return False
    if size[a] < size[b]:
        a, b = b, a
    parent[b] = a
    size[a] += size[b]
    return True

adj = [[] for _ in range(n)]

for w, u, v, idx in edges:
    if union(u, v):
        adj[u].append((v, w))
        adj[v].append((u, w))

LOG = 20
up = [[-1] * n for _ in range(LOG)]
mx = [[0] * n for _ in range(LOG)]
depth = [0] * n

def dfs(v, p):
    for to, w in adj[v]:
        if to == p:
            continue
        up[0][to] = v
        mx[0][to] = w
        depth[to] = depth[v] + 1
        dfs(to, v)

dfs(0, -1)

for k in range(1, LOG):
    for v in range(n):
        if up[k - 1][v] != -1:
            up[k][v] = up[k - 1][up[k - 1][v]]
            mx[k][v] = max(mx[k - 1][v], mx[k - 1][up[k - 1][v]])

def get_max(u, v):
    if depth[u] < depth[v]:
        u, v = v, u
    res = 0

    diff = depth[u] - depth[v]
    for k in range(LOG):
        if diff & (1 << k):
            res = max(res, mx[k][u])
            u = up[k][u]

    if u == v:
        return res

    for k in reversed(range(LOG)):
        if up[k][u] != up[k][v]:
            res = max(res, mx[k][u], mx[k][v])
            u = up[k][u]
            v = up[k][v]

    res = max(res, mx[0][u], mx[0][v])
    return res

ans = [0] * m
for w, u, v, idx in edges:
    ans[idx] = get_max(u, v)

print("\n".join(map(str, ans)))

DFS はバイナリ リフティングの基本レベルを設定し、先祖と最大エッジの重みの両方を記録します。 倍増ステップはより高いジャンプを構築し、スキップできるようにします$2^k$発生した最大のエッジの重みを追跡しながら祖先を追跡します。 

機能`get_max`深さの標準 LCA アライメントを実行し、親が一致するまで両方のノードを同時にリフトし、パスに沿って発生する最大エッジ ウェイトを累積します。 

各クエリは対数時間で独立して回答されます。 

よくある実装の落とし穴は、DFS がすべてのコンポーネントから実行されていない場合、接続された方法で MST がノード 0 にルートされない可能性があることを忘れていることです。 ここではグラフの接続が保証されているため、単一の DFS で十分です。

 ## 特殊なケース

 すでにツリーになっているグラフの場合、MST はグラフ自体です。 エッジの場合、その端点間にパスは 1 つだけあるため、そのパス上の最大のエッジはエッジ自体になります。 このアルゴリズムは同じツリーを構築し、まったく同じ重みを返します。これは、そのエッジの重要性を軽減する代替ルートが存在しないという事実と一致します。 

等しい重みを持つサイクルの場合、すべてのエッジは交換可能です。 MST は任意のエッジを選択しますが、エンドポイント間のパス上の最大エッジは常に同じ重みであるため、各エッジは同一の出力を受け取ります。 すべてのリフトされたエッジの重みが等しいため、LCA ベースのクエリは依然として機能し、最大値は一貫して伝播します。 

複数の等しい重み MST を持つグラフの場合、構築された MST は理論的な MST とは異なる場合がありますが、ミニマックス パスのプロパティは不変です。 すべての MST が同じボトルネック距離を保持し、計算された答えがどの MST が選択されたかに依存しないため、どの MST でも十分です。
