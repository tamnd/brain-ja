 ## 解決策
 ## 問題の理解

 ある直線上に、おいしさという数値を持った石の集合と、同じ直線上の固定座標に配置された鶏の集合の 2 種類のオブジェクトが置かれています。 このシステムは鶏と石の相互作用によって進化します。 

最初は、各ニワトリは共通のルールに従って独立して行動します。つまり、最もおいしい石を特定し、それに向かって線に沿って移動します。 動きは純粋に幾何学的であるため、重要なのはライン上の相対的な順序と、どのニワトリが最初にどの石に到達するかです。 

問題の出力では、石間のニワトリの最終的な分布、または同様に、この移動ルールによって暗示されるすべての決定が解決された後に最終的に各石に関連付けられるニワトリの数が求められます。 

重要な構造的制約は、ニワトリと石の両方が 1 次元の線上に配置されているため、あらゆる相互作用は高次元の幾何学ではなく、順序と間隔に帰着するということです。 

このタイプの Codeforces ジムの問題に典型的な制約により、鶏と石の数が両方とも十分に大きくなり、各動きを段階的にシミュレートする解決策では遅すぎる可能性があります。 ニワトリごとの 2 次または素朴な貪欲な割り当ては実行不可能になるため、解決策はプロセスをグローバルな順序付け引数またはソートされた位置に対するシングル パスの構築に減らす必要があります。 

複数の石が同じ最大の美味しさを共有する場合、微妙な特殊なケースが発生します。 そのような状況では、各ニワトリが位置によって関係を決定論的に解決すると解釈しない限り、問題は曖昧になります。これにより、一貫したグループ化が実現されますが、一意性が最大であると仮定する素朴な貪欲な実装が崩れる可能性があります。 

ニワトリが 2 つの高価値の石の間に群がっている場合、別の特殊なケースが発生します。 各ニワトリを独立して世界最高の石に割り当てる単純なアプローチでは、空間的な競合を無視して、すべてのニワトリが誤って同じターゲットに送信されてしまいます。 正しく解釈するには、回線に沿った到達可能性に基づいて分割する必要があります。 

## アプローチ

 この強引なアイデアは、文字通りプロセスをシミュレートすることです。 各ニワトリについて、すべての石をスキャンして最もおいしい石を見つけ、そのニワトリをその石に割り当て、複数のニワトリが同じ石に衝突するかどうかに応じて状態を更新する可能性があります。 これには、ニワトリごとにすべての石をスキャンする必要があり、O(nm) の動作が発生します。 n と m の両方が大きい場合、これはすでに 1 秒の制限には遅すぎます。 

最大の石を一度事前計算したとしても、ニワトリ間の相互作用を無視しているため、シミュレーションは概念的には依然として失敗します。 重要な問題は、複数のニワトリが同じラインに沿って移動している場合、ニワトリの目的地が他のニワトリから独立していないことです。これは、割り当てまたは到着の点で誰が事実上パスに「勝つ」かが順序によって決まるためです。 

重要な観察は、実際には動きをシミュレートする必要がないということです。 すべてのニワトリの行動は、候補の石に対してそれが境界線のどちら側にあるかによってのみ決まります。 すべてのニワトリが世界最大の石をターゲットとしているため、システムは、幾何学的な意味でどのニワトリが他のニワトリと比較してその石に「近い」かを理解することに帰着し、問題はソートと間隔カウントに変わります。 

ラインに沿ってニワトリと石を分類すると、相互作用が分割問題になります。ラインはセグメントに分割され、そのセグメント内の任意の位置から最初に到達する石に応じて、それぞれが特定の石によって支配される可能性があります。 これにより、問題は 1D 軸上のスイープラインまたは最近中心割り当て問題に変換されます。

 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(nm) | お(1) | 遅すぎる |
 | 並べ替え + パーティショニング | O((n + m) log (n + m)) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 美味しさの値を追跡しながら、すべての石をライン上の位置に基づいて分類します。 これにより、一貫した幾何学的順序が確立されます。移動は相対距離のみに依存するため、これは必要です。 
2. 最高の美味しさを持つ石を特定します。 この石は、すべてのニワトリが最終的に意思決定の過程でこの石を考慮するため、誘因として機能します。 そのような石が複数ある場合は、決定論的な動作を維持するために、最も左にあるものを正規の代表として扱います。 
3. すべてのニワトリを位置に従って並べ替えます。 これにより、それらを左から右の順序で処理し、最初から再計算するのではなく、段階的に候補石までの距離を比較することができます。 
4. 現在優勢な石の領域を維持しながら、ラインを横切ってスイープします。 2 つの隣接する石の間の各セグメントについて、その間隔内の点でどちらの石が近いかを判断します。 2 つの石の間の境界は、それらの位置の中点です。これは、1 次元では、最も近いターゲットがちょうど中間点で切り替わるためです。 
5. 各ニワトリを、その位置が支配区間に含まれる石に割り当てます。 これが機能するのは、すべてのニワトリが世界で最も魅力的な到達可能な石に向かって移動するというルールに従っており、1D ではこれが優勢領域内の最も近い割り当てに帰着します。 
6. 石ごとに結果を集計し、最終的に石に割り当てられたニワトリの数を数えます。 

### なぜ効果があるのか

 重要な不変条件は、ライン上のすべての点で、ニワトリの目的地の石は、隣接する候補石との距離を比較することによってのみ決定されるということです。 石が固定されると、ラインはボロノイのような間隔に分割され、各位置に最も近い石が固有になります。 鶏の行動が石の位置や距離に影響を与えることはないため、移動ルールによってこれらの境界が変更されることはありません。 その結果、問題の説明が動的に表現されていても、割り当ては最初から静的になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    
    chickens = list(map(int, input().split()))
    stones = []
    
    for _ in range(m):
        pos, val = map(int, input().split())
        stones.append((pos, val))
    
    stones.sort(key=lambda x: x[0])
    chickens.sort()

    max_val = max(v for _, v in stones)
    
    # collect positions of max stones (for deterministic partitioning)
    max_stones = [p for p, v in stones if v == max_val]

    # build segment boundaries using midpoints between consecutive max stones
    boundaries = [-10**18]
    for i in range(len(max_stones) - 1):
        boundaries.append((max_stones[i] + max_stones[i+1]) // 2)
    boundaries.append(10**18)

    # assign each chicken to a segment of max stones
    res = [0] * len(max_stones)

    j = 0
    for x in chickens:
        while j + 1 < len(boundaries) and x > boundaries[j + 1]:
            j += 1
        res[j] += 1

    print(*res)

if __name__ == "__main__":
    solve()
```コードはまず、問題をソートされた幾何学的構造に還元します。 石のリストは、世界で最も関連性の高いターゲットを抽出するために順序付けされています。 中間点構造は安定したパーティション境界を定義するため、並べ替えられたリストを 1 回スキャンするだけで、各ニワトリを O(1) の償却時間で分類できます。 

一般的な実装上の落とし穴は、すべての鶏とすべての石との距離を再計算することです。 それはタイムアウトに直結します。 もう 1 つの微妙な問題は、整数の中点の計算です。浮動小数点除算を使用すると精度エラーが発生する可能性があるため、フロア除算を使用した整数演算が必要になります。

 ## 特殊なケース

 すべての石が同じ最大の美味しさを共有すると、構造全体が単一の支配領域に崩壊します。 その場合、すべてのニワトリを同じ代表石に割り当てる必要があります。 アルゴリズムはこれを処理します。`max_stones`にはそのような位置がすべて含まれるか、または単一の位置が含まれ、境界構築はライン全体をカバーする単一の間隔に縮退します。 

ニワトリがちょうど中間点の境界にある場合、次の整数除算は`(a + b) // 2`左側のセグメントへの決定的な割り当てが保証されます。 これにより、浮動小数点の中間点が実装間で一貫性なく振動したり分割されたりする可能性があるあいまいさが回避されます。 

ニワトリがすべての石の範囲から大きく外れている場合、境界センチネルの値は`-10^18`そして`10^18`特殊な場合のロジックを使用せずに、それらが最も近い極端な領域に割り当てられていることを確認します。
