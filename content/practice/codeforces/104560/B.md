 ## 解決策
 ## 問題の理解

 私たちは、目標を満たすための構造化された方法を数えるように求められます。$N \times N$「テント」を含むグリッド。選択した各セルにはちょうど 1 つのテントが含まれ、各テントはサイズ 1、2、または 3 の家族をホストします。重要な制約は個々のセルにローカルではなく、行と列ごとにグローバルです。すべての行とすべての列は、合計でちょうど 3 人を参加させる必要があります。 さらに、どの行または列にも 2 つを超える占有セルを含めることはできません。つまり、各行または列で 3 人全員を 1 つのセルに配置することも、ちょうど 2 つのセルに分割することもできます。 

すべての有効な詰め物のうち、少なくとも次のものを含むもののみに興味があります。$X$値 3 を持つセル、つまり少なくとも$X$単一のセルが全体の合計 3 に寄与する行と列。 

出力は、そのような有効なグリッドの数を法にしたものです。$10^9+7$。 

制約は次のとおりです$N \le 10^6$複数のテスト ケースにわたって、グリッド上で、または行と列のペア上で反復するソリューションは即座に除外されます。 線形または線形に近い前処理を超えるもの$N$遅すぎます。 これにより、階乗スタイルの事前計算と接頭辞の合計のみに依存する式が導かれます。 

素朴なアプローチでは、行と列の合計を追跡しながら、セルごとに値を割り当てようとします。 積極的にプルーニングを行ったとしても、各行は列制約を通じてすべての列と相互作用し、組み合わせ的に拡大する状態空間を生成します。 のために$N=20$、これはすでに後戻りの可能性をはるかに超えています。 

より微妙な故障モードは、列の対称性を無視することで発生します。 たとえば、行 1 の列 2 で 1 つの 3 が使用されていると判断した場合、列 2 にも 1 つまたは 2 つの占有セルがあり、合計が 3 になるという一貫性が保たれていることを直ちに確認する必要があります。行のみの構成では、無効な構成が上回ってカウントされます。 

## アプローチ

 「テント」という観点から考えるのをやめ、代わりに各行が値 3 を列全体にどのように分配するかという観点から考えると、構造がより明確になります。 

各行には 2 つの形状しかありません。 1 つの列に 1 つの 3 を配置するか、値が 1 と 2 である必要がある 2 つのゼロ以外のエントリを何らかの順序で配置します。 同じ制限が列にも対称的に適用されます。 

これは、「単一 3」パターンを使用する行の数に基づいてソリューションを分割することを直ちに示唆します。 その数値を次のように修正するとします$k$。 

行に列に 3 が 1 つ含まれる場合$j$、次に列$j$はすでにそのセルから割り当て量 3 をすべて受信しています。 他のゼロ以外のセルに参加することはできません。参加しないと、和または次数の制約が破られます。 これにより、このようなすべての行と列のペアが直接一致のように動作するようになります。つまり、単一 3 個のセルのセットが行と列の間で部分的な全単射を形成します。 

したがって、これらのポジションを選択することは、$k$行、$k$columns, and pairing them bijectively.

 これらを削除した後、$k$行と列が残ると、$(N-k)\times(N-k)$副問題では、すべての行と列がちょうど 2 つのセルを使用して残りの合計 3 を分配する必要があります。 つまり、残りの各行は 2 つの異なる列を選択し、残りの各列も全体でちょうど 2 回使用されます。 

この構造は、残りの要素に対して 2 つの独立した置換を行うことと同等です。$N-k$インデックス: 1 つの順列は「最初のエッジ」の位置を決定し、別の順列は「2 番目のエッジ」を決定します。 各行はちょうど 2 つの送信割り当てを受け取り、各列はちょうど 2 つの受信割り当てを受け取ります。 

最後に、この構造内の各連結成分はサイクルであり、各サイクルに沿って、どの順列が値 1 に寄与し、どの順列が値 2 に寄与するかを割り当てる有効な方法が 2 つあります。 

このカウントを実行することで、きれいな閉じたフォームが得られます。 固定資産の貢献$k$大幅に簡素化されます:$$\frac{(N!)^2}{k!}$$すべてを合計するだけで済みます$k \ge X$。

 ## アルゴリズムのチュートリアル

 組み合わせの結果を計算可能な式に変換します。 

1. 階乗を最大値まで事前計算する$N$テストケース全体で。 最終的な式は以下に依存するため、これが必要です。$N!$。 
2. 逆階乗を事前計算して、以下を取得します。$1/k!$モジュロ$10^9+7$一定時間あたり$k$。 
3. 各テスト ケースについて、次の内容を読んでください。$N$そして$X$。 
4. 逆階乗に対する接尾辞の合計を計算します。$$S = \sum_{k=X}^{N} \frac{1}{k!}$$これは、単一の 3 を使用する行数に関するすべての有効な選択肢を表します。 
5. 結果を乗算します。$(N!)^2$これは、どの行と列が参加するかを選択し、残りの構造で順列がどのように形成されるかを説明します。 
6. 結果のモジュロを出力します。$10^9+7$。 

### なぜ効果があるのか

 重要な不変条件は、すべての有効な構成が 2 つの独立した部分に一意に分解されることです。1 つの 3 セルによって形成されるマッチングと、残りの行と列によって形成される 2 つの正規の 2 部構造です。 マッチングは、以下にのみ依存する要因に寄与します。$k$、サイズが固定されると、残りの構造は特定のマッチングとは独立した項に寄与します。 この分離により、構成が 2 回カウントされず、有効な構成が欠落することがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def modinv(x):
    return pow(x, MOD - 2, MOD)

def solve():
    T = int(input().strip())
    tests = []
    max_n = 0

    for _ in range(T):
        n, x = map(int, input().split())
        tests.append((n, x))
        max_n = max(max_n, n)

    fact = [1] * (max_n + 1)
    invfact = [1] * (max_n + 1)

    for i in range(1, max_n + 1):
        fact[i] = fact[i - 1] * i % MOD

    invfact[max_n] = modinv(fact[max_n])
    for i in range(max_n, 0, -1):
        invfact[i - 1] = invfact[i] * i % MOD

    for tc, (n, x) in enumerate(tests, 1):
        suf = 0
        for k in range(x, n + 1):
            suf = (suf + invfact[k]) % MOD

        ans = fact[n] * fact[n] % MOD
        ans = ans * suf % MOD

        print(f"Case #{tc}: {ans}")

if __name__ == "__main__":
    solve()
```この実装は、前処理をテストごとの計算から分離することに依存しています。 階乗と逆階乗は最大まで一度構築されます。$N$テストごとに再計算すると時間がかかりすぎるため、これが必要です。 

逆階乗に対する接尾辞の合計は、テスト ケースごとに直接計算されます。$T$は十分に小さく、の合計は$N$複数のケースにわたって、意図した制約の下で管理可能な状態を維持します。 

よくある落とし穴は、最終的な式に次の要素が含まれていることを忘れることです。$(N!)^2$1 つの階乗だけではありません。 これは、分解で行と列の構造を個別に選択することに由来します。 

## 実用的な例

 検討してください$N=2, X=0$。 合計します$k=0,1,2$。 

| k | 1/k! | 貢献 |
 | --- | --- | --- |
 | 0 | 1 | 1 |
 | 1 | 1 | 1 |
 | 2 | 1/2 | 1/2 |

 したがって、合計は$N!^2 \cdot (2.5)$。 以来$N!=2$、私たちは得ます$4 \cdot 2.5 = 10$、式によって暗示される構造化された代入の数と一致します。 

ここで考えてみましょう$N=3, X=1$。 合計するだけです$k=1,2,3$。 

| k | 1/k! |
 | --- | --- |
 | 1 | 1 |
 | 2 | 1/2 |
 | 3 | 1/6 |

 この構造は、単一 3 行の最小数を増やすと、構造の階乗スケールのバックボーンを維持しながら、使用可能な構成がどのように減少するかを示しています。 

これらのトレースは、組み合わせの重みが、特定の位置ではなく、単一 3 セルに折りたたまれる行の数にのみ依存することを強調しています。

 ## 特殊なケース

 いつ$X=0$、可能なすべての分解が許可されるため、接尾辞の合計にはすべての逆階乗項が含まれます。 このアルゴリズムは、合計範囲が自然に間隔全体に拡張されるため、特別なケースを使用せずにすべての寄与を正しく累積します。 

いつ$X=N$、すべての行で単一の 3 が使用されている構成のみがカウントされます。 この場合、サフィックスの合計は次のように減少します。$1/N!$、最終的な式は次のようになります$(N!)^2 / N! = N!$これは、3 つのセルの行と列の間の完全な全単射を選択することに正確に対応します。
