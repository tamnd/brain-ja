 ## 解決策
 ## 問題の理解

 長さの配列を構築する必要があります`n`隣接するすべての製品がユニークになるようにします。 より正確には、値$$a_1a_2,\ a_2a_3,\ \dots,\ a_{n-1}a_n$$全部違うはずだ。 

この条件を満たすすべての配列の中で、配列内に現れる個別の値の数を最小限に抑えたいと考えています。 実際の値は次の範囲内にある必要があります。`1`そして`300000`。 

最初の問題は、配列をどのように構築するかということではなく、可能な個別の値がどれほど少ないかということです。 

だけを使用する場合`m`個別の値の場合、すべての隣接する積は、これらの値の順序のないペアを選択することによって形成されます。 2 つの隣接する要素が等しい場合、その積は値のループに対応します。 それらが異なる場合、その積は 2 つの値の間のエッジに対応します。 

から入手できるさまざまな製品の数`m`個別の素数はまさに$$m + \binom{m}{2} = \frac{m(m+1)}2.$$配列には次のものが含まれているため、`n-1`隣接する製品とそのすべてが区別できる必要があります。$$\frac{m(m+1)}2 \ge n-1.$$これにより、個別の値の数の下限がすでに決まります。 

制約`n ≤ 10^6`と合計`n`すべてのテストケースにわたって、最大でも`10^6`意図したソリューションでは出力サイズがほぼ線形である必要があることを強く示唆しています。 テスト ケースごとに二次作業を伴う構築は失敗します。 

微妙なエッジケースが現れるのは、`n=2`。 隣接する製品は 1 つだけです。 単一の値を 2 回使用するとすぐに機能するため、個別の値の最小数は次のようになります。`1`。 

もう 1 つの簡単な間違いは、異なる値のすべてのペアが自動的に異なる積を与えると仮定することです。 これは、任意の整数の場合は false になります。$$2\cdot 6 = 3\cdot 4.$$衝突を回避する標準的な方法は、個別の素数を使用することです。 その後、すべての積は、関係する素数のペアを一意に識別します。 

## アプローチ

 強引なアイデアは、個別の値の最小数を推測することです。`m`、次に、隣接するすべての製品が一意になるように配置してみます。 すべての個別の値を頂点として、すべての隣接する積をエッジとして見ることができます。 要件は、各エッジを最大 1 回使用するウォークを見つけることになります。 

問題は、そのような散歩を直接検索するのは絶望的であるということです。 数十の頂点であっても、可能性の数は膨大になります。 

重要な観察は、値として個別の素数を選択した場合、順序のない頂点のペアはすべて一意の積に対応するということです。 ループは以下に対応します$p_i^2$、エッジはに対応します$p_ip_j$。 

ここで、問題は純粋にグラフ理論になります。 

あるとします。`m`頂点。 すべての頂点にループがある完全なグラフを考えてみましょう。 エッジの数は$$m + \binom{m}{2} = \frac{m(m+1)}2.$$すべてのエッジは、1 つの固有の隣接する製品に対応します。 

このグラフのオイラー走査を生成できれば、走査内の連続する頂点によってすべてのエッジが 1 回だけ生成されます。 結果として得られる隣接する製品は自動的に区別されます。 

最初のものだけが必要です`n-1`このようなトラバースのエッジなので、最小のものを選択します`m`満足のいく$$\frac{m(m+1)}2 \ge n-1.$$次に、オイラー ツアーを生成し、最初のツアーを出力します。`n`そこからの頂点。

 ## アルゴリズムのチュートリアル

 1. 最小の整数を見つける`m`そのような$$\frac{m(m+1)}2 \ge n-1.$$より少ない数を使用するソリューション`m`個別の値では、十分な個別の隣接積を提供できません。 
2. 最初のものを取る`m`素数。 

個別の素数は、異なるグラフのエッジが異なる積に対応することを保証します。 
3. 以下から構成されるグラフを構築します。`m`頂点、すべての可能な無向エッジ、および各頂点上の 1 つのループ。 

グラフはまさに$$\frac{m(m+1)}2$$エッジ。 
4. Observe that every vertex has degree`m+1`。 

以来`m+1`社説で使用される標準構造を選択した場合でも、グラフはオイラー式です。 
5. Hierholzer のアルゴリズムを実行してオイラー ツアーを取得します。 

各エッジは 1 回だけ訪問されます。 
6. オイラー ツアーで頂点を訪問させます$$v_0,v_1,\dots,v_L.$$次にエッジ`i`で表されます`(v_i,v_{i+1})`。 
7.最初の出力`n`頂点インデックスを対応する素数に置き換えた後のオイラー ツアーの頂点。 

最初`n-1`ツアープロデュースの端`n-1`明確な隣接製品。 

### なぜ効果があるのか

 隣接するすべての積はグラフのエッジに対応します。 オイラー ツアーではエッジが繰り返されないため、隣接する積が繰り返されることはありません。 

素数を使用すると、2 つの異なるエッジが同じ製品を生成できないことが保証されます。 一意の因数分解により、製品がエンドポイントを一意に決定することが保証されます。 

グラフには正確に次の内容が含まれています$\frac{m(m+1)}2$異なる製品の可能性があります。 最小のものを選択する`m`満足のいく$\frac{m(m+1)}2 \ge n-1$これは、個別の値が少ない解は存在できないことを証明しています。 この構造はこの限界を達成するため、最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXP = 300000

def sieve(limit):
    is_prime = [True] * (limit + 1)
    is_prime[0] = is_prime[1] = False

    for i in range(2, int(limit ** 0.5) + 1):
        if is_prime[i]:
            step = i
            start = i * i
            for j in range(start, limit + 1, step):
                is_prime[j] = False

    return [i for i in range(2, limit + 1) if is_prime[i]]

primes = sieve(MAXP)

def build_sequence(n):
    if n == 2:
        return [primes[0], primes[0]]

    m = 1
    while m * (m + 1) // 2 < n - 1:
        m += 1

    g = [set() for _ in range(m)]

    for i in range(m):
        g[i].add(i)
        for j in range(i + 1, m):
            g[i].add(j)
            g[j].add(i)

    stack = [0]
    tour = []

    while stack:
        v = stack[-1]

        if g[v]:
            u = next(iter(g[v]))

            if u == v:
                g[v].remove(v)
            else:
                g[v].remove(u)
                g[u].remove(v)

            stack.append(u)
        else:
            tour.append(stack.pop())

    tour.reverse()

    ans = [primes[x] for x in tour[:n]]
    return ans

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        out.append(" ".join(map(str, build_sequence(n))))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```最初の部分では十分な素数が計算されます。 必要な最大のもの`m`おおよそです$\sqrt{2\cdot10^6}$したがって、必要な素数は 1500 未満であり、制限をはるかに下回ります。`300000`。 

値`m`下限式から選択されます。 これにより最適性が保証されます。 

グラフにはループと通常のエッジが格納されます。 通常のエッジを削除する場合は、両方の隣接セットを更新する必要があります。 ループは 1 回だけ保存されるため、特別な処理が必要です。 

Hierholzer のアルゴリズムは、エッジの数に対して線形時間でオイラー ツアーを生成します。 最初`n`結果として得られるツアーの頂点には、すでに十分な隣接プロダクトが提供されています。

 ## 特殊なケース

 検討してください`n = 2`。 

隣接する製品は 1 つだけ存在します。 使用する`[p,p]`すぐにすべての要件を満たします。 個別の値の最小数は次のとおりです。`1`、そして構築はこれを明示的に処理します。 

考慮する`n = 4`。 

よくある間違いは、隣接する製品が 3 つあるため、3 つの異なる値が必要であると想定することです。 2 つの素数を使用すると、すでに 3 つの異なる積が得られます。$$p^2,\ pq,\ q^2.$$建設が発見したのは、`m = 2`3 つの積すべてを実現するシーケンスを出力します。 

次のような合成数を使用した構成を考えてみましょう。`[2,6,3,4]`。 

それから$$2\cdot6 = 12, \quad 3\cdot4 = 12.$$一意性条件は失敗します。 素因数分解はすべてのエッジを一意に識別するため、個別の素数を使用すると、これが完全に防止されます。
