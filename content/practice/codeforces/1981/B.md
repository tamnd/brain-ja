 ## 問題の理解

 無限配列から始めます。$i$最初に値が含まれています$i$。 したがって、配列は、インデックスと値が等しいという単純な ID マッピングとして始まります。 

毎秒、すべての位置が同時に更新されます。 各位置は、それ自体とそのすぐ隣の位置のビット単位の OR になります。 より正確に言うと、位置$i$～から値を取得します$i-1$、$i$、 そして$i+1$、境界が処理されて、その位置が$0$位置との OR のみ$1$。 この更新ルールはすべてのインデックスに並行して適用されます。つまり、新しい配列が同時に適用されます。$t+1$時刻は配列から完全に計算されます$t$、同じ秒内に段階的にではありません。 

単一のインデックスの値を求められます$n$後$m$このようなグローバルアップデート。 難しさは、値がビットごとの OR を通じて外側に広がり、配列が無限であるため、ブルート シミュレーションが不可能であるという事実から来ています。 

制約により許可されるのは、$n, m$まで$10^9$まで$10^4$テストケース。 これにより、クエリごとに線形ステップ数さえもシミュレートするアプローチは即座に除外されます。 平$O(n)$テストケースごとに実行することは不可能なので、$n$それ自体は可能です$10^9$、総作業量は爆発的に増加します。 

重要な点は、ある位置の値が正確な算術伝播に依存するのではなく、近くの整数からビットがどのように拡散するかに依存することです。 素朴な精神的な罠は、固定されたウィンドウ内ではローカルな値のみが重要であると考えることです。 OR は情報を単調にマージし、上位ビットは異なる実効速度で伝播するため、これは誤りです。 

よくある間違った仮定は、値が少数のステップの後に安定するか、または次のような境界のある近傍のみに依存するというものです。$[n-m, n+m]$。 この部分は依存関係の範囲に当てはまりますが、その範囲内の各値自体が構造化されているものの自明ではない方法で時間の経過とともに変化するため、計算が直接単純化されるわけではありません。

 ## アルゴリズムのチュートリアル

 各クエリを変換します$(n, m)$範囲内に$[L, R]$どこ$L = \max(0, n-m)$そして$R = n+m$。 

1. コンピューティング$L$そして$R$。 これは、その値が位置に影響を与える可能性があるすべての元のインデックスを表します。$n$後$m$ステップ。 これは、各ステップが左右に 1 つのインデックスだけ影響力を拡大するという観察から来ています。 
2. もし$L = 0$、範囲はゼロから始まるものとして扱います。 これは、元のシーケンスが負のインデックスまで拡張されていないため、ビットに寄与する値が存在しないため重要です。 
3. すべての整数のビット単位の OR を計算します。$[L, R]$。 反復する代わりに、最上位ビットを特定します。$L$そして$R$異なる。 このビットは、バイナリ表現が分岐する最初の位置を決定します。 
4. 最も異なるビットが見つかると、範囲内のある時点でこれらのビットを独立して反転する値を構築できるため、結果の下位ビットはすべて 1 になります。 
5. 最終的な答えは、次の共通の接頭辞を維持することによって構築されます。$L$そして$R$、残りの下位ビットをすべて 1 で埋めます。 

### なぜ効果があるのか

 不変条件は、各ビット位置が OR 伝播の下で独立して進化し、プロセスが影響区間内のすべての中間整数値の到達可能性を維持することです。 更新ルールにより、到達可能な開始位置に設定されたビットが最終結果に寄与することが保証されます。 到達可能性は時間とともに対称的に拡大するため、寄与する初期インデックスのセットは正確に連続した間隔になります。 連続した区間にわたる OR は、エンドポイントのバイナリの発散によってのみ決定される安定したバイナリ構造を持ち、再構成の正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def range_or(l, r):
    if l == 0:
        # special case: OR from 0 to r
        # becomes all bits up to MSB of r are 1
        msb = r.bit_length() - 1
        return (1 << (msb + 1)) - 1

    # find highest differing bit between l and r
    x = l ^ r
    msb = x.bit_length() - 1

    # keep prefix above msb, set all lower bits to 1
    prefix = r & (~((1 << (msb + 1)) - 1))
    suffix = (1 << (msb + 1)) - 1
    return prefix | suffix

t = int(input())
for _ in range(t):
    n, m = map(int, input().split())
    l = max(0, n - m)
    r = n + m
    print(range_or(l, r))
```この実装は、反復ではなくバイナリ構造を使用して範囲にわたる OR を計算するヘルパーを中心に構造化されています。 特別な場合$l = 0$ゼロは範囲を固定し、すべての下位ビットが最上位ビットまで完全に飽和することを保証するため、個別に処理されます。$r$。 

一般的なケースでは、XOR を使用して場所を検出します。$l$そして$r$異なる。 その位置によって、可能な値の二分木がどの程度分岐するかが決まります。 そのレベル以下はすべて完全にカバーされるため、これらのビットを 1 に設定します。$r$範囲全体で同一である上位ビットの正確性を維持するために保存されます。 

微妙な実装の詳細は、`bit_length() - 1`最高の設定ビットを見つけます。 ここでのオフバイワンエラーはよくあることです。 構築されたマスク`(1 << (msb + 1)) - 1`は、そのビットまでの 1 の完全なブロックを正しく作成します。

import sys, io

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    def range_or(l, r):

            return (1 << (msb + 1)) - 1
        x = l ^ r
        msb = x.bit_length() - 1
        prefix = r & (~((1 << (msb + 1)) - 1))

        r = n + m
        out.append(str(range_or(l, r)))
    return "\n".join(out)

 ## 特殊なケース

 いつ$n = 0$、範囲は次のようになります$[0, m]$。 アルゴリズムは、ゼロから完全なプレフィックス OR に切り替えることで、これを明示的に処理します。 たとえば、$m = 5$、範囲は$[0,5]$、最上位ビットは 2 なので、結果は次のようになります。$2^3 - 1 = 7$、0 から 5 までのすべての数値の OR と一致します。 

いつ$m = 0$、範囲は次のように縮小します。$[n,n]$。 XOR が 0 になるため、相違するビットがなく、関数は戻ります。$n$変わらない。 これは、更新が行われないという事実と一致します。 

いつ$n < m$、左側の境界はゼロにクランプされます。 このクランプがないと、負のインデックスが誤って寄与してしまいます。 実装では明示的に設定することで正確性を保証します。$L = 0$、アレイドメインの物理的制約を維持します。
