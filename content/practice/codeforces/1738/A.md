 ## 解決策
 ## 問題の理解

 私たちには戦闘スキルのコレクションが与えられており、各スキルにはタイプ (火または霜) とダメージ値という 2 つの属性があります。 ヒーローはすべてのスキルを何らかの順序で 1 回だけ実行する必要があります。 連続するスキル間の唯一の相互作用は、直前のスキルとタイプが異なる場合、スキルのダメージが 2 倍になることです。 

目標は、この倍増ルールを適用した後に蓄積ダメージの合計を最大化するようにスキルを並べ替えることです。 

構造上の重要な点は、異なるタイプ間の遷移のみが重要であるということです。 同じタイプの連続したブロック内では、すべてのスキルはボーナスの影響を受けませんが、火と氷を切り替えるたびに、切り替え後の最初のスキルが 2 倍になります。 

この制約により、すべてのテストにわたってテスト ケースごとに最大 100,000 のスキルが許可されます。 すべての順列を試行したり、順序付けを超えて動的計画法を維持したりするソリューションは、階乗増加や二次遷移さえも制限を超えるため、実行不可能です。 テストケースごとに線形または線形算術的なアプローチが必要です。 

微妙な落とし穴は、すべてのスキルを 1 つのタイプにグループ化することが最適であると想定していることです。 タイプの切り替えにより機会が 2 倍になるため、これは一般的に間違っており、可能であればそれらの乗数を大きなダメージ値に適用する必要があります。 

2 番目の微妙な問題は、各スキルが最大 1 回まで 2 倍にできることを無視していることです。 タイプを何度も切り替えたとしても、スキルはその直前の移行からのみ恩恵を受けるため、その構造は、スキルのどのサブセットが倍増を受けるかを制御することになり、増幅が繰り返されるわけではありません。 

## アプローチ

 ブルートフォースアプローチでは、スキルのあらゆる順列を試し、シーケンスをシミュレートすることで結果として生じるダメージを計算します。 これは目的関数を直接評価するため正しいですが、まったく実行不可能です。 n 個のスキルがあれば、n 個あります。 順列があり、各評価のコストは O(n) であり、10^5 の制限をはるかに超える爆発につながります。 

重要な観察は、スキルの貢献に影響を与える唯一の要素は、そのスキルが異なるタイプ間の境界に配置されているかどうかであるということです。 これは、火と霜の 2 つのグループを配置し、作成するトランジションの数を決定するという観点から考える必要があることを示唆しています。 

開始タイプを固定すると、シーケンスは交互のブロックになります。 タイプを切り替えるたびに、新しいブロックの最初の要素を 2 倍にするトランジションを「消費」します。 したがって、最大の値を 2 倍になる位置に割り当てます。 

各スイッチは新しいセグメント内の 2 倍の要素を 1 つだけ提供するため、この構造は事実上、値の一部のサブセットに 2 を掛けた合計を最大化し、残りは 1x のままにする配置を選択することになります。 

最適な戦略は、すべてのスキルをダメージごとに分類し、どちらが「倍増しないベースライン」に寄与するかを決定することだけに依存していることがわかります。 それを理解する明確な方法は次のとおりです。考えられるすべての交互配置の中で、2 つの型数の正確な最小値によって、「強制ペアリング」がいくつ存在するかが決まります。また、支配的な型の最小の要素が 2 倍化されずに残され、より大きな要素が 2 倍化を得るために境界に配置されるように配置することができます。 

これにより、各型内の値を並べ替え、重複を回避できる要素の数を注意深く考慮することに基づいた貪欲なソリューションが得られます。

 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 すべてのスキルをファイアとフロストのタイプに基づいて 2 つの配列に分割し、ダメージ値のみを保存します。

1. 両方の配列を降順に並べ替えます。 これにより、最も有利なポジションに最初に最大値を割り当てることを常に考慮するようになります。 
2. 両方の配列のプレフィックスの合計を計算します。 これにより、どちらかのタイプから上位 k 個の要素を取得して高速に評価できます。 
3. 考えられる遷移の数ごとに、各側の要素の数が 2 倍になるか、2 倍にならないかを暗黙的に決定します。 有効なシーケンスの構造は、最大でも 1 つのタイプが、交互のバランスを超えて追加の非倍化要素に寄与できることを意味します。 
4. 1 つのタイプが交互パターンを支配する分割点を試して、達成可能な最良の構成を評価します。 具体的には、着火シーケンスと着霜シーケンスの 2 つのケースを考えます。 
5. それぞれのケースについて、すべての要素の合計に、タイプ切り替えの直後に到達する要素の追加ゲインを加えたものとして合計寄与度を計算します。 すべてのスイッチは 1 つの要素を 2 倍にするため、遷移に対応する位置で利用可能な最大の要素に 2 倍を割り当てます。 
6. 両方の開始選択肢の最大値を取得します。 

中心となる考え方は、最適な配置では常に高価値のスキルをトランジションポジションに配置するというものです。なぜなら、それが倍増が可能な唯一のポジションだからです。 

### なぜ効果があるのか

 有効な順序付けにより、一連のタイプの実行が引き起こされます。 各実行境界は、次の実行で 2 倍化された要素を 1 つだけ作成し、他のすべての要素は 2 倍化されません。 ランは遷移構造に影響を与えることなく内部的に再配置できるため、境界位置への値の割り当てのみが重要になります。 並べ替えにより、最大値がそれらの境界位置を占めるようになり、2 倍化による限界利益が最大化されます。 遷移の数を超える倍加イベントを作成できる構成はなく、貪欲な割り当てから離れた再分配では、より大きな 2 倍の値をより小さな 2 倍の値に置き換えるだけで、合計が減少します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        
        fire = []
        frost = []
        
        for i in range(n):
            if a[i] == 0:
                fire.append(b[i])
            else:
                frost.append(b[i])
        
        fire.sort(reverse=True)
        frost.sort(reverse=True)
        
        def best(start_fire):
            # simulate optimal greedy placement idea
            f = fire[:]
            r = frost[:]
            
            if start_fire:
                first, second = f, r
            else:
                first, second = r, f
            
            i = j = 0
            turn = 0
            total = 0
            
            # take alternation greedily
            while i < len(first) or j < len(second):
                if turn % 2 == 0:
                    if i < len(first):
                        total += first[i]
                        i += 1
                    else:
                        total += second[j]
                        j += 1
                else:
                    if j < len(second):
                        total += 2 * second[j]
                        j += 1
                    else:
                        total += first[i]
                        i += 1
                turn += 1
            
            return total
        
        ans = max(best(True), best(False))
        print(ans)

if __name__ == "__main__":
    solve()
```コードはスキルをタイプごとに分割し、両方のグループを並べ替えて、常により大きな値をより早く消費できるようにします。 次に、火から始めるか、霜から始めるかの 2 つの構造上の選択肢を評価します。 それぞれについて、タイプ変更直後に取得される要素が 2 倍になるという交互の消費パターンをシミュレートしており、ボーナス ダメージを生み出す唯一のメカニズムと一致します。 

貪欲なシミュレーションが機能するのは、両方のリストがソートされると、遷移の最適な使用法は、常にそれを受信型の最大の残りの値に適用することになるためです。 ポインタベースのシミュレーションでは、すべての順列に対して明示的な組み合わせ論を必要とせずに、そのルールが適用されます。 

実装の微妙な詳細は、1 つのタイプの枯渇を処理することです。 1 つのリストが空の場合、アルゴリズムは自然に倍増しない消費に戻ります。これは、それ以上の遷移が存在しないという事実と一致します。

 ## 特殊なケース

 最小限のエッジケースは、スキルが 1 つしかない場合です。 遷移が存在しないため、アルゴリズムはすぐにその値を返し、2 倍化は不可能です。 

2 番目のケースは、すべてのスキルが同じタイプの場合です。 その状況では、すべてのスキルが 1 回の実行で処理されるため、隣接するタイプの変更は発生しません。 シミュレーションでは 2 倍分岐はトリガーされません。これは、すべての乗数が 1 のままである必要があるという事実と一致します。 

3 番目のケースは、1 つのタイプが大きく優勢な場合です。 アルゴリズムは、小さいリストがなくなるまで交互に実行され、その後は直線で続行されます。 この時点で、それ以上の倍増は発生しません。これは、片側が枯渇すると遷移が不可能になることを正しく反映しています。
