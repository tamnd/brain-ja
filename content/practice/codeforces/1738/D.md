 ## 解決策
 ## 問題の理解

 左から右へ順列をスキャンしながら配列を構築する隠れたプロセスが与えられていますが、プロセス後に残るのは派生配列だけです。`b`。 私たちの仕事は、それを生成した可能性のある有効な順列としきい値を再構築することです。 

元の構築中、要素は非表示のしきい値に応じて 2 つのグループに分割されます。`k`: 値`1..k`「小さい」とみなされ、`k+1..n`「大きい」です。 順列を繰り返す間、新しい要素が現れるたびに、反対側のグループから最新の要素を遡ってそれを保存します。`b`現在の値に対応する位置にあります。 

それでそれぞれ`b[x]`からローカルに計算されません`x`、ただし、現時点でパーティションの反対側で最後に確認された要素に依存します。`x`が表示されます。 

私たちはただ見るだけです`b`ただし、両方のパーティション ポイントを再構築する必要があります。`k`そして、これらの最後に見られた関係を一貫性のあるものにする順列。 

制約により強制的に`O(n)`または`O(n log n)`テストごとのソリューション。 合計から`n`すべてのテストにわたって、`10^5`、候補の順列をシミュレートしたり、素朴な方法で次の出現を繰り返し再計算しようとするアプローチはタイムアウトになります。 テストごとに 1 回構造を構築し、一定またはほぼ一定の時間で各インデックスを処理するソリューションが必要です。 

よくある失敗例としては、`b[x]`順列における隣接性または順序を直接記述します。 たとえば、こう考えると、`b[x] = y`手段`y`直前です`x`それは間違っています、なぜなら`b[x]`一般に最後に出現するものではなく、最後の反対グループ要素に依存します。 もう一つの微妙な問題は治療です`0`そして`n+1`通常の値として。 これらは「反対の要素がまだ存在しない」ことを意味する番兵であり、実際の置換要素ではありません。 

## アプローチ

 強引なアイデアとしては、考えられるすべてのしきい値を試してみることです。`k`次に、定義と一致する順列の構築を試みます。 候補者ごとに`k`、両方のグループの最後に表示された要素を維持し、すべての制約を満たすことができるかどうかを確認しながら、ある順序で数値を挿入することをシミュレートします。`b`。 賢明な構築を試みたとしても、これは本質的に、バックトラッキングまたはマッチングのような動作を伴う制約付き順序付けの問題になります。 順列単独の検索空間は次のようになります。`n!`、そして修正さえも`k`各グループ内の順序付けにおける指数関数的な曖昧さは解消されません。 これは非常に小さいものを超えるとすぐに実行不可能になります`n`。 

重要な構造的洞察は次のとおりです。`b`恣意的な相互作用を説明するものではありません。 それは、2 つの未知のグループ間の厳密な交代パターンをエンコードします。 パーティションの一方の側に値が表示されるたびに、その値は`b`value は反対側の最新の値を指します。 これは、各値が反対側のグループの前の値に効果的に「リンク」され、それらのリンクが 2 つのグループ間で交互に行われるチェーンを形成することを意味します。 

これは、最初にパーティションを再構築することを提案します。 分割点候補を修正する場合`k`、すべてを解釈できます`b[x]`「いつ`x`が表示されると、最後に確認された反対グループの値は`b[x]`これにより、問題は、これらの依存関係エッジが常に辺を横切るように、各数値を 2 つの辺のいずれかに割り当てることができるかどうかを検証することに変わります。これらの辺の一貫性により、二部構造が強制され、分割が既知であれば、最後に出現する制約を尊重することで順列を貪欲に構築できます。 

順列としきい値の両方を推測する代わりに、次のように解釈してパーティションを導き出します。`b`値間の制約グラフとして。

 ## アルゴリズムのチュートリアル

 プロセスを逆に再解釈します。順方向の構築をシミュレートする代わりに、`b`どの値が反対側に属するかを推測します。 

1. あらゆる値を扱う`x`ノードとして解釈します`b[x]`パーティションの反対側にある必要がある前の値への参照として。 もし`b[x]`は`0`または`n+1`、つまり`x`にはこのタイプの制約はなく、グループ内の開始点として機能します。 
2. それぞれが有効な無向グラフを構築します。`b[x]`(つまり、`1 ≤ b[x] ≤ n`) の間にエッジを作成します`x`そして`b[x]`。 これが機能する理由は、`x`そして`b[x]`一方は元のスキャン中にもう一方にとって「最後に確認された反対タイプの要素」であったため、反対のグループに存在する必要があります。 
3. ここで問題は、このグラフを 2 色にできるかどうかを確認することになります。 色の割り当て`0`または`1`接続されている各コンポーネントに。 色の割り当ては、各値がしきい値のどちら側に属するかを選択することに対応します。 
4. ノードに`b[x] = 0`、それは現時点では次のことを意味します`x`が表示されますが、その前には反対の要素が存在しませんでした。`x`そのタイプの最初のものである必要があります。 同様に、`b[x] = n+1`同じロジックを逆方向に適用します。 これらのノードは、カラーリングを固定するのに役立ちます。 
5. すべてのノードに色が付けられたら、`k`「小さい」側に割り当てられる最大ラベルとして、つまり次のように選択された側を意味します。`1..k`。 ラベル自体は構造的制約ではなく順列制約であるため、一貫した分割は機能します。 
6. 最後に、ある色のすべての要素を最初に配置し、もう 1 つの色の要素を 2 番目に配置し、各グループ内で一貫性を尊重しながら任意に順序付けすることにより、有効な順列を構築します。`b`。 正確性は内部順序ではなくグループのメンバーシップのみに依存するため、単純な値による順序付けで十分です。 

### なぜ効果があるのか

 重要な不変条件は、有効な再構築はすべて、それぞれの再構築が行われるという事実を尊重しなければならないということです。`b[x]`2 つの固定セット間の交互をエンコードします。 これにより、すべての制約が「反対側でなければならない」関係 (まさに 2 部グラフのエッジ) に強制されます。 元の構造は一貫していることが保証されているため、このグラフは 2 部構成であり、有効な 2 色分けは有効なしきい値分割に対応します。 パーティションが修正されると、依存構造は一貫性を超えて内部順序を制約しなくなるため、単純な構築で十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        b = list(map(int, input().split()))

        adj = [[] for _ in range(n + 1)]

        for i in range(1, n + 1):
            x = i
            y = b[i - 1]
            if 1 <= y <= n:
                adj[x].append(y)
                adj[y].append(x)

        color = [-1] * (n + 1)

        for i in range(1, n + 1):
            if color[i] != -1:
                continue
            stack = [i]
            color[i] = 0
            while stack:
                u = stack.pop()
                for v in adj[u]:
                    if color[v] == -1:
                        color[v] = color[u] ^ 1
                        stack.append(v)

        group0 = []
        group1 = []
        for i in range(1, n + 1):
            if color[i] == 0:
                group0.append(i)
            else:
                group1.append(i)

        k = len(group0)
        a = group0 + group1

        pos = [0] * (n + 1)
        for idx, val in enumerate(a):
            pos[val] = idx + 1

        out.append(str(k))
        out.append(" ".join(map(str, a)))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このコードは、強制的に反対の関係の無向グラフを構築し、それを 2 色で表示して、非表示のしきい値によって暗示される 2 つの側面に値を分離します。 最初のグループは「小さい」側となり、`k`。 次に、2 つのカラー クラスを連結することによって順列が形成されます。 

重要な点は、元のスキャン順序を再構築しようとしないことです。 一貫性のあるパーティションのみを再構築します。 多くの順列が同じ結果を引き起こす可能性があるため、残りは柔軟です`b`。 

## 実用的な例

 ### 例 1

```制約を解釈するには、互いの制約に現れる値を結び付けます。`b`参考文献。 グラフの端は次のようになります。`(1,5)`、`(2,3)`、`(3,1)`、`(4,2)`有効な範囲に応じて異なります。 2 色使いはこれらのリンク全体に伝播します。 

| ノード | b[ノード] | 色の割り当て |

 | 1 | 5 | 0 |

これは、構造が純粋に 2 部構成であることを示しています。1 つのノードが固定されると、他のすべてのノードが交互の制約に従います。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    return sys.stdout.getvalue() if False else solve_capture(inp)

def solve_capture(inp: str) -> str:
    import sys
    input = sys.stdin.readline
    data = inp.strip().split()
    t = int(data[0])
    idx = 1
    res = []

    for _ in range(t):
        n = int(data[idx]); idx += 1
        b = list(map(int, data[idx:idx+n])); idx += n

        adj = [[] for _ in range(n + 1)]
        for i in range(1, n + 1):
            y = b[i - 1]
            if 1 <= y <= n:
                adj[i].append(y)
                adj[y].append(i)

        color = [-1] * (n + 1)
        for i in range(1, n + 1):
            if color[i] != -1:
                continue
            stack = [i]
            color[i] = 0
            while stack:
                u = stack.pop()
                for v in adj[u]:
                    if color[v] == -1:
                        color[v] = color[u] ^ 1
                        stack.append(v)

        g0, g1 = [], []
        for i in range(1, n + 1):
            (g0 if color[i] == 0 else g1).append(i)

        k = len(g0)
        a = g0 + g1

        res.append(str(k))
        res.append(" ".join(map(str, a)))

    return "\n".join(res)

 ## 特殊なケース

 主なエッジケースは、多数のエントリが`b`外にいる`1..n`、グラフのエッジがまったく生成されません。 その状況では、すべてのノードが分離されるため、DFS はすべてを同じデフォルトの色に割り当てます。 構築されたソリューション セット`k = n`または`k = 0`規則に従っており、代替制約が存在しないため、あらゆる置換が有効です。 隣接リストは空のままであり、色付けが競合することはないため、アルゴリズムはこれを自然に処理します。 

もう 1 つの微妙なケースは、依存関係が長いパスを形成するチェーン構造です。 例えば、`1 -> 2 -> 3 -> 4`。 DFS はチェーンに沿って色を交互に配置し、一貫した 2 分割を保証します。 出力の並べ替えでは、単に交互のノードが 2 つの連続したブロックに配置されます。すべての制約はグループ間であるため、内部順序の競合は発生しません。
