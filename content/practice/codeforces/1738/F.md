 ## 解決策
 ## 問題の理解

 無向グラフが与えられますが、最初は頂点の数と各頂点の次数だけがわかります。 タスクは、2 つの条件が成立するように各頂点に色を割り当てることです。 まず、色を共有する頂点がグラフ内の連結成分を形成する必要があります。 第 2 に、各カラー グループの頂点の次数の合計が、そのグループ内の頂点数の 2 乗を超えることはできません。 この相互作用により、各頂点の近傍をクエリできるようになりますが、各頂点のクエリは最大 1 回のみであり、クエリの総数が頂点の数を超えることはできません。 

制約は厳しいですが管理可能です。テスト ケースあたりの頂点の数は最大 1000 で、すべてのテスト ケースの頂点の合計が 1000 を超えません。これは、全体的に複雑なアルゴリズムはすべて、$O(n^2)$テスト ケースごとの数は許容されますが、それを超えるネストされたクエリを含むものは、クエリ制限に達する危険性があります。 各頂点をクエリできるのは 1 回だけであるため、エッジを探索する方法は戦略的に行う必要があります。 クエリ制限を考慮せずに完全な隣接リストを再構築しようとする単純なアプローチは、特に次数が高い場合には失敗します。 

エッジ ケースは、頂点が孤立している場合、次数が最大である場合、または単純に色付けすると次数の合計条件に違反する可能性のあるコンポーネントを形成する場合に発生します。 たとえば、頂点が次数 0 で分離されている場合、その頂点はシングルトン カラーになる必要があります。 すべての頂点に次数がある場合$n-1$、色の割り当てでは、条件を満たすように慎重に分割する必要があります。$s_c \le n_c^2$状態。 不注意なアプローチを行うと、高次数の頂点が 1 つの色にマージされ、次数の合計条件に違反する可能性があります。 

## アプローチ

 ブルート フォース アプローチでは、すべての頂点のすべての近隣ノードにクエリを実行して、完全な隣接リストを構築しようとします。 これは技術的には正しいです。なぜなら、グラフを理解したら、接続されたコンポーネントに色を付けて満足させることができるからです。$s_c \le n_c^2$は簡単です。 ただし、頂点ごとに最大 1 つのクエリに制限されているため、このアプローチはすぐに失敗します。 頂点を複数回クエリして近傍をキャッシュしようとしても、自明ではないグラフのクエリ制限を超えてしまいます。 

重要な洞察は、次数和の制約から得られます。 各カラー グループは次までの度数のみを蓄積できます。$n_c^2$。 次数の降順で頂点を処理し、常に現在の頂点の色付けされていない近傍を接続することによってグループを拡張する場合、制約に違反しないことが保証されます。 高次の頂点は自然にカラー グループのバックボーンを形成し、より小さい次数の近傍を追加しても境界を超えることはありません。 この貪欲なアプローチは、頂点を一度クエリすると、検出されたすべての近傍にすぐにその色を割り当てることができるため、機能します。 常に最高次数の無色の頂点を最初に処理することで、次数和の境界内に十分な余地がないグループが作成される可能性を最小限に抑えます。 

この戦略では、常に頂点からエッジに沿って拡張し、接続をスキップすることがないため、接続条件が自動的に保証されます。 次数の合計の限界が満たされるのは、最大次数の頂点から開始して貪欲に頂点を追加しても、グループ サイズの 2 乗を超える次数の合計が決して蓄積されないためです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) クエリ | O(n^2) | クエリ制限を超えると失敗します |
 | 程度によって貪欲 | O(n log n + n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 頂点の数とその次数を読み取ります。 色の付いていない頂点のリストを次数の降順に並べて保持します。 並べ替えにより、常に最も多くの近傍を持つ頂点から開始することが保証され、次数和の制約内で接続されたグループに色を付ける能力が最大限に高まります。 
2. カラーカウンターを 1 から初期化します。これにより、作成した各グループに一意の色が割り当てられます。 
3. 色付けされていない頂点が存在する場合、最も高い次数の色付けされていない頂点を選択します。 クエリを 1 回だけ実行して、(相互作用ルールに従って) 隣接するものの 1 つを取得します。 この頂点に現在の色を割り当てます。 
4. クエリによって返されたすべての色なしの近傍に対して、ただちに同じ色を割り当てます。 次数の降順で頂点を処理するため、各近傍の次数が開始頂点以下であるため、近傍を追加しても次数合計条件に違反しません。 
5. カラーカウンターをインクリメントし、降順で次の色のない頂点に進みます。 すべての頂点が色がつくまで繰り返します。 
6. カラーリングを出力します。 アルゴリズムが同じステップで頂点とその近傍に同じ色を割り当てるため、すべてのグループが接続されます。 次数の合計条件は、最大の次数が最初にグループ化され、追加された各頂点によって合計がグループ サイズの 2 乗を超えないため成立します。 

機能する理由: 不変条件は、各ステップで、現在のカラー グループの次数の合計がそのグループ内の頂点数の 2 乗を決して超えないことです。 最高次数の頂点から開始すると、近傍の貪欲な追加がこの境界に違反しないことが保証されます。 カラーリングは最初の頂点から実際のエッジに沿って伝播するため、接続性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
print_flush = lambda x: (print(x), sys.stdout.flush())

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        degrees = list(map(int, input().split()))
        uncolored = set(range(1, n+1))
        colors = [0] * n
        color_id = 1
        degree_order = sorted([(deg, i+1) for i, deg in enumerate(degrees)], reverse=True)

        for deg, u in degree_order:
            if colors[u-1] != 0:
                continue
            colors[u-1] = color_id
            print_flush(f"? {u}")
            neighbor = int(input())
            if neighbor != -1 and colors[neighbor-1] == 0:
                colors[neighbor-1] = color_id
            color_id += 1
        print_flush("! " + " ".join(map(str, colors)))

if __name__ == "__main__":
    solve()
```まず頂点を次数で並べ替えて、最大次数の頂点を最初に処理します。 頂点をクエリすると、その隣接頂点に色が付いていなければ、すぐに同じ色が割り当てられます。 各グループが終了した後にのみカラーカウンターをインクリメントします。 微妙な点の 1 つは、頂点を複数回クエリしないようにすることです。 これは、処理中に 1 回だけクエリを実行することで維持されます。 もう 1 つは、次数 0 の孤立した頂点を処理することです。これらの頂点には、自動的に一意の色が割り当てられます。
