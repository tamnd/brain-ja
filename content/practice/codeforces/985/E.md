 ## 解決策
 ## 問題の理解

 一連の鉛筆の彩度値が与えられているので、すべての鉛筆をボックスと呼ばれるグループに分割する必要があります。 すべての鉛筆は、正確に 1 つの箱に入れなければなりません。 私たちが使用する各箱には少なくとも k 個の鉛筆が入っていなければなりません。 単一ボックス内では、彩度の最小値と最大値の差が d を超えることはできません。 

タスクは、ボックスの数を最小化または最大化することではありません。 有効なパーティションが存在するかどうかを判断するだけで済みます。 

制約は大きく、最大 500,000 本の鉛筆があります。 すべてのパーティション、さらにはすべてのグループを明示的にチェックしようとするソリューションは失敗します。 これにより、指数関数的アプローチや二次関数的アプローチは即座に除外されます。 ペアに対する O(n^2) 推論でも遅すぎるため、解決策はソートと線形または線形に近いスキャンに依存する必要があります。 

微妙な問題は、制約間の相互作用から発生します。 ボックスは、サイズ制約と値範囲制約の両方によって定義されます。 単純な間違いは、これらを独立して扱うことです。たとえば、d 制約をグローバルにチェックせずにサイズ k のグループを貪欲に形成したり、最小サイズを保証せずに値の範囲によってグループ化したりします。 

素朴な推論を打ち破るエッジケースには、次のようなものがあります。 

まず、k が 1 に等しいとき。そのとき、すべての鉛筆は独自のボックスを形成でき、答えは d に関係なく常に YES になります。 範囲によるグループ化を要求するソリューションは誤って失敗する可能性があります。 

第 2 に、d が 0 など非常に小さい場合です。その場合、同じ値のみをグループ化できますが、各グループはサイズ ≥ k を満たさなければなりません。 たとえば、値が [1,1,1,2,2] で k = 3、d = 0 の場合、どちらの値クラスもサイズ 3 に達しないため、答えは NO になります。 

3 番目に、値がすでにクラスター化されているものの、k の倍数に揃っていない場合です。 常に次の k 要素を取得する貪欲な場合、たとえ別のグループ化が成功したとしても、d に違反するグループが作成される可能性があります。 

これらの問題は、グループを盲目的にローカルに構築するのではなく、ソートされた構造についてグローバルに推論する戦略が必要であることを示唆しています。 

## アプローチ

 ブルートフォースのアイデアは、ソートされた配列の可能なすべての分割を連続セグメントに考慮し、各セグメントが両方の条件を満たすかどうかを確認することです。 並べ替え後に連続するセグメントに制限したとしても、n 個の要素を分割するにはあらゆる方法を試す必要があり、これは指数関数的になります。 各パーティションの有効性の検証には O(n) のコストがかかるため、n = 30 の場合でも合計は実行不可能になります。 

重要な点は、ソート後、有効なボックスはソートされた配列内の連続したセグメントに対応する必要があるということです。 ボックスに大きなギャップのある 2 つの要素 i と j が含まれている場合、並べ替えられた順序でそれらの間にある要素も値の範囲の点で両端と互換性があるため、これを除外してもグループ化は難しくなるだけで、簡単にはなりません。 これにより、ソートされた配列を連続したセグメントに分割するという問題を軽減できます。 

この構造を修正したら、実際の課題はサイズ制約の実現可能性を確保することです。 各セグメントには少なくとも k 個の要素が必要で、その最大値から最小値を引いた値が ≤ d である必要があります。 これは、将来の割り当てを妨げないように、できるだけ遅く、またはできるだけ早くボックスを開始するように努めるべきであることを示唆しています。 

標準的な貪欲なアイデアが浮かび上がります。配列をソートし、動的計画法または 2 ポインター スキャンを使用して、範囲制約を満たす少なくとも k 以上の長さのセグメントの有効な開始位置を決定します。 各位置 i について、a[j] - a[i] ≤ d となるような最も遠い j を見つけます。 i で始まる有効なボックスは、[i + k - 1, j] 内で終了する必要があります。 これはインデックスの到達可能性の問題になります。有効な間隔を使用して配列をカバーし、グループ化できない k 未満の要素を持つサフィックスを決して残さないようにします。

配列内を進むポインタを維持し、制約を尊重しながら有効なボックスを貪欲に形成し、すべての点で残りの要素が有効なグループを形成するのに十分であることを確認します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースパーティション | O(2^n · n) | O(n) | 遅すぎる |
 | 2 つのポインターを使用して貪欲にソート | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、値の制約が連続するインデックスの間隔になるように配列を並べ替えます。 

次に、2 ポインター手法を使用して、各インデックス i について、i から r[i] までのすべての要素が a[r[i]] - a[i] ≤ d を満たすように最も遠い位置 r[i] を計算します。 これは、i から始まるボックスの最大有効範囲を定義します。 

次に、左から右へ貪欲なパーティションを構築します。 現在の位置 i で、i から始まるボックスを選択する必要があります。 このボックスには少なくとも k 個の要素が含まれている必要があるため、その終端は少なくとも i + k - 1 でなければなりません。また、値の制約も満たさなければならないため、その終端は r[i] を超えることはできません。 

1. 彩度の配列を並べ替えます。 
2. a[right] - a[i] ≤ d の間に右ポインタが拡張するスライディング ウィンドウを使用して、すべてのインデックス i の r[i] を計算します。 
3. ポインタ i = 0 に初期化します。 
4. i < n の間、i から始まるボックスの形成を試みます。 
5. r[i] - i + 1 < k の場合、最大許容セグメントでも小さすぎるため、有効なボックスをここで開始することはできません。 
6. それ以外の場合は、必要最小限の終了を表す j = max(i + k - 1, i) を設定します。 
7. [i, r[i]] を許容ウィンドウとして扱い、先に進みますが、有効なグループを割り当てた後、i を i + k にジャンプすることで、ボックスごとに少なくとも k 要素を確実に消費します。 
8. すべての要素が割り当てられるまで繰り返します。 

重要な考え方は、ボックスを遅らせると後の要素の柔軟性が低下するだけであるため、常にできるだけ早くボックスにコミットするということです。 

### なぜ効果があるのか

 並べ替え後、有効なボックスは連続したセグメントに対応する必要があります。 スライディング ウィンドウにより、開始位置 i ごとにエンドポイントの実現可能な範囲がすべてわかっていることが保証されます。 最も早い未割り当てインデックスからボックスを開始するという貪欲な選択により、以前に有効にグループ化できたはずのプレフィックスがグループ化されないままになることがなくなります。 不変条件は、各ステップで i より前のすべての要素がすでに有効なボックスに割り当てられており、アルゴリズムが正常に続行された場合には残りのサフィックスを引き続き分割できることです。 いずれかの時点でウィンドウ サイズ制約が失敗した場合、他のグループ化では問題を修正できません。これは、以前に開始した有効なボックスは、最小サイズ制約を満たすために必要な要素の数を増やすだけであるためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k, d = map(int, input().split())
    a = list(map(int, input().split()))
    a.sort()

    r = [0] * n
    j = 0
    for i in range(n):
        while j < n and a[j] - a[i] <= d:
            j += 1
        r[i] = j - 1

    i = 0
    while i < n:
        if r[i] - i + 1 < k:
            print("NO")
            return
        i += k

    print("YES")

if __name__ == "__main__":
    solve()
```解決策は、有効なグループ化が区間問題になるように彩度値を並べ替えることから始まります。 配列 r には、すべての値が距離 d 以内にとどまるという制約の下で、各開始点 i の到達可能な最大インデックスが格納されます。 

2 番目のループは、配列を少なくとも k 個のチャンクで消費しようとします。 実装上の重要な決定は、グループが i から開始できると判断したら、常に k ずつ進めるということです。 これが機能するのは、有効なパーティションは少なくとも k 個の要素を現在のボックスに割り当てる必要があり、ソートされた配列の単調性とウィンドウ制約により実現可能性を維持するには正確に k を取得するだけで十分であるためです。 

よくある落とし穴は、r[i] が配列全体にわたって計算され、グループ化ごとに再計算されないことを忘れていることです。 これは正しいです。ソートされた構造により、将来の有効性が以前のグループ化の決定ではなくインデックスのみに依存することが保証されるからです。 

## 実用的な例

 ### 例 1

 入力:```
6 3 10
7 2 7 7 4 2
```ソートされた配列は [2, 2, 4, 7, 7, 7] になります。 

r[i] を次のように計算します。 

| 私 | a[i] | r[i] (最大インデックス) |
 | --- | --- | --- |
 | 0 | 2 | 5 |
 | 1 | 2 | 5 |
 | 2 | 4 | 5 |
 | 3 | 7 | 5 |
 | 4 | 7 | 5 |
 | 5 | 7 | 5 |

 i = 0 から開始します。ウィンドウ [0..5] は有効で、サイズ ≥ 3 なので、少なくとも 3 つの要素でボックスを形成し、i = 3 にジャンプします。ここでも r[3] は完全なボックスを許可するため、さらに 3 つの要素を取得して終了します。 

これは、すべてのプレフィックスが有効なグループを形成するのに十分な柔軟性を備えているため、貪欲な消費が機能することを確認します。 

### 例 2

 入力:```
5 3 0
1 1 1 2 2
```ソートされた配列は [1, 1, 1, 2, 2] です。 

r を計算します。 

| 私 | a[i] | r[i] |
 | --- | --- | --- |
 | 0 | 1 | 2 |
 | 1 | 1 | 2 |
 | 2 | 1 | 2 |
 | 3 | 2 | 4 |
 | 4 | 2 | 4 |

 i = 0 では、r[0] - 0 + 1 = 3 なので、ボックスを形成できます。 私たちは3つの要素を消費します。 

i = 3 では、r[3] - 3 + 1 = 2 となり、k = 3 より小さいため、失敗します。 

これは、値がローカルにグループ化されている場合でも、アルゴリズムがクラスター サイズの不足をどのように検出するかを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | ソートが優先され、2 ポインタ スキャンは線形です。 
| スペース | O(n) | 配列とヘルパー r |

 この制約では最大 500,000 個の要素が許可されるため、O(n log n) の解は時間制限内に問題なく収まりますが、O(n^2) または指数関数的なアプローチは制限内に収まりません。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from sys import stdout
    stdout.flush = lambda: None

    input = sys.stdin.readline

    def solve():
        n, k, d = map(int, input().split())
        a = list(map(int, input().split()))
        a.sort()

        r = [0] * n
        j = 0
        for i in range(n):
            while j < n and a[j] - a[i] <= d:
                j += 1
            r[i] = j - 1

        i = 0
        while i < n:
            if r[i] - i + 1 < k:
                return "NO"
            i += k

        return "YES"

    return solve()

# provided sample
assert run("6 3 10\n7 2 7 7 4 2\n") == "YES"

# minimum case
assert run("1 1 0\n5\n") == "YES"

# impossible due to k
assert run("5 3 0\n1 1 2 2 3\n") == "NO"

# all equal large k
assert run("6 4 0\n1 1 1 1 1 1\n") == "YES"

# tight boundary
assert run("5 2 1\n1 2 10 11 12\n") in ["YES", "NO"]

 ## 特殊なケース

 エッジ ケースの 1 つは、k が 1 に等しい場合です。r[i] - i + 1 が常に少なくとも 1 であるため、アルゴリズムはこれを正しく処理し、すべての位置が独自のボックスを形成できます。 ループは常に進行し、YES を出力します。これは、シングルトン ボックスが常に制約を満たすという事実と一致します。 

もう 1 つのエッジ ケースは、d が 0 に等しい場合です。この場合、r[i] は同一の値にのみ拡張されます。 このアルゴリズムでは、各ボックスが少なくとも k 個の同一要素で構成されるように強制され、値クラスが k より小さい場合、r[i] チェックは直ちに失敗し、無効なグループ化が防止されます。 

3 番目のエッジ ケースは、配列がソートされていても、k = 3 で d が小さい [1,1,1,100,100,100] などの交互のクラスターで構成されている場合に発生します。 r[i] は位置に基づいて正しくリセットされるため、アルゴリズムは最初のクラスターを正常に処理し、次に 2 番目のクラスターを独立して処理します。
