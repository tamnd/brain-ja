 ## 解決策
 ## 問題の理解

 スイッチのコレクションが与えられ、それぞれがランプのサブセットを制御します。 スイッチを押すと、それに接続されているすべてのランプが常時点灯します。 ランプが一度オンになると、そのランプに影響を与える他のスイッチが後で押されても、ランプは再びオフになることはありません。 

すべてのスイッチを押すと、すべてのランプが確実に点灯します。 タスクは、残りのすべてのスイッチを押してもすべてのランプが点灯することを確認しながら、無視しても安全な単一のスイッチが存在するかどうかを判断することです。 

この問題を別の見方で見ると、各スイッチがランプのセットに寄与し、すべてのセットの和集合がすべてのランプをカバーするということです。 1 つのセットを削除しても結合が変更されないままになるかどうかを知りたいと考えています。 

この制約により、最大 2000 個のスイッチと 2000 個のランプが許可されるため、400 万回の操作を伴う二次またはわずかに悪いソリューションが許容されます。 行列構造上の 3 次関数は遅すぎますが、n の m 倍に比例する演算は問題ありません。 

ランプが 1 つのスイッチだけでカバーされている場合、微妙なエッジ ケースが発生します。 その場合、そのスイッチを外すとそのランプは点灯できなくなります。 たとえば、ランプ j がスイッチ i にのみ接続されている場合、スイッチ i は必須です。 正しいソリューションは、そのような一意性条件を暗黙的または明示的に検出する必要があります。 

複数のスイッチがすべてのランプを冗長的にカバーする場合、別のエッジ ケースが発生します。 たとえば、すべてのランプがすべてのスイッチに接続されている場合、いずれかのスイッチを取り外してもすべてのランプが点灯したままになります。 単純なアプローチではこれが複雑になりすぎて合格する可能性がありますが、すべてのランプにわたる冗長性がテスト対象のコア構造であることを認識することが重要です。 

## アプローチ

 直接的なアプローチは、各スイッチを 1 つずつ削除した場合の効果をシミュレートすることです。 固定スイッチ i の場合、他のすべてのスイッチを使用してどのランプが点灯したままであるかを再計算し、すべてのランプがまだカバーされているかどうかを確認します。 毎回カバレッジを最初から再計算すると、マトリックス全体を繰り返しスキャンすることになります。 

このブルート フォース手法では、n 個の候補をチェックし、各候補について n 個のスイッチと m 個のランプにわたるカバレッジを再計算します。 これにより、O(n^2 m) の操作が必要になります。 n と m が 2000 までの場合、これは約 8 × 10^9 演算に達しますが、これは非常に遅すぎます。 

重要な点は、実際にはすべてを再計算する必要はないということです。 スイッチを取り外すときに重要なのは、カバーが露出したランプが少なくとも 1 つ存在するかどうかです。 ランプ j の場合、唯一の危険な状況は、j を点灯するすべてのスイッチに、取り外されたスイッチが含まれている場合です。 同様に、各ランプ j について、それをカバーするスイッチの数を知る必要があるだけです。 ランプが少なくとも 2 回覆われている場合、1 つのカバー スイッチを取り外してもランプはオフになりません。 

これにより、問題は単純なカウント構造に縮小されます。 各ランプについて、それをアクティブにするスイッチの数を計算します。 次に、各スイッチについて、それがランプの一意のプロバイダーであるかどうかを確認します。 スイッチが一部のランプの唯一の提供者である場合、そのスイッチを削除することはできません。 それ以外の場合は安全です。 

カバレッジ数を事前に計算してから再度スキャンすることで、これを効率的にチェックできます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース再計算 | O(n^2m) | O(nm) | 遅すぎる |
 | ランプごとのカバレッジをカウント | O(nm) | O(m) | 承認済み |

 ## アルゴリズムのチュートリアル

1. どのスイッチがどのランプを作動させるかを説明する入力マトリックスを読みます。 この構造は、スイッチとランプ間の二部関係を定義します。 
2. 各ランプについて、それをオンにできるスイッチの数を数えます。 これにより、冗長性を確保するランプ上の周波数配列が得られます。 これが役立つ理由は、冗長性が 1 つだけの場合にのみ削除が危険であるためです。 
3. 各スイッチについて、それが作動するすべてのランプを確認します。 そのようなランプの合計数が 1 の場合、そのスイッチを必須としてマークします。 このスイッチを外すとそのようなランプは消灯してしまうという理屈です。 
4. 必須ではないスイッチが少なくとも 1 つ見つかった場合は、それを無視しても安全であり、すべてのランプを点灯したままにすることができます。 「YES」を出力します。 
5. すべてのスイッチが必須の場合、少なくとも 1 つの独自にサポートされるランプにすべてのスイッチが必要です。 その場合は「NO」を出力してください。 

### なぜ効果があるのか

 正しさは、失敗の単純な特徴付けに基づいています。 スイッチのみに依存するランプがない場合に限り、スイッチは取り外し可能です。 「スイッチを取り外した後もすべてのランプが点灯したままである」というグローバル条件は、ランプのアクティブ化が単調でスイッチを介して加算されるため、ランプごとの独立したチェックに分解されます。 各ランプは少なくとも 1 つのアクティブな隣接ランプを必要とするだけであるため、ランプが最後の支持エッジを失っていない場合には、スイッチを失っても無害です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    mat = [input().strip() for _ in range(n)]
    
    cnt = [0] * m
    
    for i in range(n):
        row = mat[i]
        for j in range(m):
            if row[j] == '1':
                cnt[j] += 1
    
    for i in range(n):
        row = mat[i]
        ok = True
        for j in range(m):
            if row[j] == '1' and cnt[j] == 1:
                ok = False
                break
        if ok:
            print("YES")
            return
    
    print("NO")

if __name__ == "__main__":
    solve()
```最初のパスでは、ランプ上に周波数配列を構築します。 これは、すべてのスイッチの相互作用を単純なカウントにまとめる重要な前処理ステップです。 

2 番目のパスでは、各スイッチを個別に評価します。 内側のループは、スイッチが独自にカバーされたランプを担当しているかどうかをチェックします。 単一の一意の依存関係が見つかると、スイッチは直ちに失格となるため、早期の中断が重要です。 

行列を文字列として保存する決定により、繰り返しの解析オーバーヘッドが回避され、メモリ使用量が最小限に抑えられます。

## 特殊なケース

 重要なエッジケースは、すべてのランプにサポート スイッチが 1 つだけある場合です。 例えば：```
2 2
10
01
```ここでは、各スイッチが 1 つのランプを一意に担当します。 アルゴリズムは、両方のスイッチがカウント 1 のランプをカバーしているため、両方のスイッチを必須としてマークします。これは正しく NO になります。 

もう 1 つのエッジ ケースは、スイッチが多くのランプをカバーしているにもかかわらず、スイッチに固有の責任がない場合です。 例えば：```
3 3
111
111
111
```すべてのランプのカウントは 3 であるため、スイッチが失格になることはありません。 アルゴリズムは、どのスイッチも削除できることを正確に識別します。 

スイッチが 1 つある最小限のケース:```
1 3
111
```すべてのランプのカウントは 1 であるため、単一のスイッチが必須であり、取り外すことはできません。 アルゴリズムは NO を出力し、要件に一致します。
