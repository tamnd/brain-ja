 ## 解決策

 ## 問題の理解

 それぞれが固定長の木製五線のコレクションが与えられます。 これらの譜表から正確に構築しなければなりません`n`バレル、および各バレルは正確に使用する必要があります`k`独特の譜表。 すべての五線は 1 回だけ使用されるため、マルチセット全体は次のように分割されます。`n`サイズのグループ`k`。 

バレルの価値は、その最も弱いコンポーネント、つまりバレル内の最も短い譜表によって決まります。 合計スコアは、すべてのバレルにわたるこれらの最小値の合計です。 

追加の結合制約があります。`n`バレル値、最大値と最小値の差を超えてはなりません`l`。 これにより、すべてのバレル最小値が比較的狭い数値範囲内に収まることになります。 

目標は、分割制約と「スプレッド ≤ l」制約の両方を尊重しながらバレル最小値の合計を最大化することです。 

入力サイズが大きく、最大`n * k ≤ 100000`これにより、パーティションを列挙したり組み合わせをテストしようとするものは即座に除外されます。 ソートベースの貪欲な戦略も受け入れられます。`O(m log m)`は十分に制限内ですが、譜表上の二次関数は制限内にありません。 

最小の譜表をどのように配置するかを制御せずに、最小の譜表を個別にバレルに貪欲に割り当てようとすると、微妙な失敗モードが発生します。 たとえば、大きな譜表を恣意的に混合してバレルの最小値を常に「ブースト」しようとすると、誤ってグローバル スプレッド制約に違反してしまう可能性があります。 

別の失敗例が発生するのは、`l = 0`。 その場合、すべてのバレルは同一の最小値を持たなければなりません。これにより、非常に厳格な構造が強制され、選択された最小値の平等性を明示的に強制しない場合、単純な貪欲なグループ化が失敗する可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、譜表を可能なすべてのサイズのグループに割り当てようとします。`k`、各グループの最小値を計算し、選択します。`n`合計を最大化しながら分散制約を満たすグループ。 パーティションの数が増えると、これはすぐに実行不可能になります。`n*k`要素をサイズのグループに分割する`k`超指数関数的に成長します。 すべてのグループを構築するだけでもすでに指数関数的です`m`、このアプローチは不可能です`m = 20`。 

重要な観察は、最小値のみが重要であり、各バレルの最小値は選択された最も弱い譜表によって完全に決定されるということです。 これは、どの要素が最小値になるかを制御し、そのように選択されたそれぞれの最小値がバレルの残りの部分を満たすのに十分な大きな要素によって「サポート」されるようにする必要があることを示唆しています。 

すべての譜表をソートすると、最大の側から後方に向かって潜在的な最小値を割り当てることを推論できます。 直観的には、大きな値は合計を増加させるため、可能な限り最小値として機能するようにします。 ただし、選択した最小値ごとに消費されます。`k`すべてのバレルを完成させる実現可能性を確保する必要があります。 

欲張りな視点を活用すると、最大の要素から順にバレルを構築することを想像できます。 バレルごとに最小値の候補を選択し、利用可能な最小の譜表をフィラーとして使用してその対価を「支払い」ます。 これにより、残りの構造が常に実行可能になります。 

2 番目の制約は、すべての最小値がサイズの範囲内に収まらなければならないというものです。`l`は、選択した最小値を選択した後は、選択した最大値がそれを超えてはいけないことを意味します。`l`。 これは当然、ソートされた配列に対するスライディング ウィンドウを考慮することになります。カットオフの最小値を選択し、選択されたすべての最小値がその範囲内に収まるようにします。`[x, x + l]`。 

最適な構築は次のようになります。十分なフィラー譜を確実に割り当てながら、実行可能な接尾辞から最小値として機能する要素を選択します。 最小値を選択するたびに、概念的には消費します`k - 1`残りのプールからの追加の譜表。 これにより、実現可能性を追跡しながら、最大の側から貪欲に選択することになります。 

## アルゴリズムのチュートリアル

 1. すべての五線の長さを昇順に並べ替えます。 これにより、どの値が最小値として機能するかを制御できるようになり、任意のサブセットではなく位置を使用して実現可能性を推論できるようになります。 
2. 要素を潜在的な最小値として扱う場合、任意の接尾辞からいくつのバレルを形成できるかを事前計算します。 最小値の候補セットの場合、それぞれは次の値を消費します`k - 1`追加の譜表があるため、実現可能性はそれらをサポートするのに十分な譜表が残っているかどうかによって決まります。 
3. 選択された最小値の可能な選択肢を繰り返します。 そういったポジションごとに`i`、私たちは解釈します`a[i]`最小バレル最小値として。 他のすべての最小値は接尾辞の中になければなりません`[i, i + l_window]`を超えない値`a[i] + l`。 
4. 開始点が固定されている場合は、可能な限り最大の要素を最小値として貪欲に選択します。これは、より大きな最小値を選択すると合計が増加し、フィラーを割り当てることができる限り実現可能性が損なわれないためです。 
5. フィラーロールの譜表の消費をシミュレートするポインターを維持します。 選択された最小値ごとに、利用可能な容量が次のように減少します。`k`, ただし、スコアに貢献するのはそのうちの 1 つだけです。 残り`k - 1`事実上、支持構造に「費やされて」います。 
6. 有効な選択ごとに合計を計算します。`n`範囲制約を満たす最小値を求め、最大値を追跡します。 

### なぜ効果があるのか

 重要な不変条件は、残りの最大の適格な要素を常にバレル最小値として割り当て、それ以外はすべてフィラーとして扱われるということです。 フィラー要素は目的には寄与しないため、その唯一の役割は実現可能性です。 ソートにより、より小さい選択された最小値とより大きい未使用の要素との交換が実行可能性を侵害することはなく、合計の改善または維持のみが可能になります。 したがって、ソートされた譜表に対する貪欲な選択が最適です。 

有界拡散制約は最小値の候補のセットを制限し、問題を選択に変えます。`n`埋めるのに十分な残りの要素が存在することを確認しながら、スライディング ウィンドウから要素を追加します。`n * (k - 1)`スロット。 この「スコア要素」と「フィラー要素」の分離により、貪欲な構造が有効になります。

def solve():

    # We use a greedy pointer strategy from the end.
    
    # We will try to pick candidates for minima in a controlled window.
    # suffix[i] means we consider a[i:] as potential pool.
    
    # rightmost we can safely consider
    res = 0

    # we simulate taking elements from the end
    i = m - 1

    remaining = m

    # each chosen minimum consumes k staves total
    
    # we try to pick minima in blocks
    # we move i backwards selecting minima greedily
    used = 0

    # greedy grouping: pick every k-th element from the back as candidate minima
    # but we must ensure constraint |max-min| <= l
    
    # collect candidates for minima
    candidates = []
    
    for idx in range(m - 1, -1, -1):
        candidates.append(a[idx])
    
    candidates.sort(reverse=True)

    best = 0
    
    prefix = [0] * (m + 1)
    for i in range(m):
        prefix[i + 1] = prefix[i] + a[i]
    
    # We choose minima from suffix greedily
    # simulate picking every k-th element as minimum source
    j = m - 1
    chosen = []

有効性チェック`chosen[-1] - chosen[0] > l`貪欲な選択の後にスプレッド制約を適用します。 失敗した場合、この最大-最小戦略を使用した実行可能な構成は、構築されたグループ内に存在しません。 

フィラー要素は目的に寄与しないため、合計は選択された最小値から直接計算されます。

 入力:```
n=4, k=2, l=1
2 2 1 2 3 2 2 3
```ソートされた配列:`[1, 2, 2, 2, 2, 2, 3, 3]`すべてを選択します`k=2`最後から - 番目の要素。 

| ステップ | インデックス j | 選択された値 | 選択されたセット |
 | --- | --- | --- | --- |
 | 1 | 7 | 3 | [3] |

 選択済みの並べ替え:`[2, 2, 2, 3]`範囲は`3 - 2 = 1`、以下で有効です`l = 1`。 

合計は`9`ただし、1 つのグループ化解釈によって有効なパッキングにおける有効な最小値の選択が減少するため、最終的な有効な配置により、達成可能な最大の一貫したセットが得られます。 

このトレースは、間隔がどのように変化するかを示しています。`k`大きな要素を優先しながら、ばらばらのバレル形成を強制します。 

### サンプル 2 (構築済み)

 入力:```

```並べ替え:`[5, 6, 7, 8, 9, 10]`最後から 3 番目ごとに選択します。 

| ステップ | j | 選択 | 選ばれた |

 ## 特殊なケース

 いつ`k = 1`、すべての譜表は独自のバレルであるため、グローバル範囲制約が適用される場合、答えは単純にすべての値の合計になります。 アルゴリズムは当然のことながら、すべての要素を選択し、`max(a) - min(a) ≤ l`、制約に直接一致します。 

いつ`l = 0`、選択されたすべての最小値が同一である必要があります。 貪欲な選択では依然として間隔のある要素が選択されますが、選択されたすべての値が一致しない限り、範囲チェックによってソリューションが折りたたまれ、厳密な実現可能性チェックが正しく強制されます。 

値がすでに厳密にソートされている場合、すべてのグループをステップ実行することによって生成されます。`k`-th 要素は有効な最小値を生成し、アルゴリズムは拒否なしで最適な候補を直接抽出します。
