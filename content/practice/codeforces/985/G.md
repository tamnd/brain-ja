 ## 問題の理解

 私たちに与えられたのは、`n`インデックス付けされたプレーヤー`0`に`n−1`、ここでのインデックスはランクでもあります。 正確に 3 人の異なるプレーヤーからなるグループを選択する必要があります。 グループは、選択された 3 つのペアのいずれも競合としてマークされていない場合にのみ有効です。 

すべての有効なトリプルは、昇順に並べ替えた後、その 3 つのランクから計算された数値を提供します。 ソートされたトリプルが`(i, j, k)`、その貢献度は`A·i + B·j + C·k`。 タスクは、すべての有効なトリプルにわたってこの値を合計することです。 

主な困難は、トリプルを数えることではなく、線形重み構造を尊重しながら、禁止されたペアを効率的に処理することです。 

制約により総当たり攻撃は不可能になります。 プレイヤー数は最大20万人、対戦数も最大20万回です。 すべてのトリプルを列挙するには、おおよその必要があります$\binom{n}{3}$のオーダーです。$10^{15}$最悪の場合。 単純にエッジを反復処理して 3 番目の頂点をすべてチェックしても、$O(nm)$、これも大きすぎます。 

したがって、解決策はトリプルの反復を明示的に回避し、代わりに合計の代数的分解と禁止された構成の慎重なカウントに依存する必要があります。 

グラフにエッジがない場合、微妙なエッジ ケースが発生します。 この場合、すべてのトリプルが有効になり、答えはすべてのトリプルにわたる純粋な組み合わせの合計になります。 もう 1 つの例外的なケースは、完全なスターです。つまり、1 つの頂点が他のすべての頂点に接続されています。 単純な「エッジごと」の減算では、包含-除外を使用して修正しない限り、複数の入射エッジを含むトリプルが過剰にカウントされます。 

## アプローチ

 まず競合を無視し、すべてのトリプルの合計を計算します。 重みはエッジではなくインデックスのみに依存するため、この部分は純粋に組み合わせです。 ポジションごとに`x`、最小、中間、または最大の要素として出現するトリプルの数を数えます。 これらの数は、インデックス順でその左右にある要素の数にのみ依存します。 これにより、線形時間での制約のない合計が得られます。 

難しさは、少なくとも 1 つの禁止エッジを含むトリプルを減算することに起因します。 直接的なアイデアは、各エッジを反復処理することです`(u, v)`両方のエンドポイントを含むすべてのトリプルの寄与を合計します。 これは最初の近似として機能しますが、3 つの頂点の中に 2 つまたは 3 つの禁止エッジを含むトリプルをすぐにオーバーカウントします。 

頂点の 3 つにより、正確に 4 つのエッジ構成が生成されます。つまり、エッジなし、正確に 1 つのエッジ、長さ 2 のパスを形成する 2 つのエッジ、または三角形です。 エッジに適用される包含-排他原理により、明確な同一性が得られます。エッジを合計し、隣接するエッジのペアを減算し、逆三角形を追加すると、不良トリプルはそれぞれ 1 回だけカウントされます。 

これにより、問題は 3 つの構造化された合計を計算することになります。 

1 つ目は 1 つのエッジと 3 番目の頂点すべての上にあります。 

2 つ目は、頂点を共有するエッジのペア上です。 

3 つ目はグラフ内の三角形の上です。 

固定ペアの場合、最初の合計は管理可能です。`(u, v)`、すべての貢献度を計算できます`w ≠ u, v`インデックスに対してプレフィックスの合計を使用します。 

2 番目と 3 番目の合計は、頂点とエッジの周囲で構造的に局所的です。 高次数の頂点における潜在的な二次爆発を処理するために、次数のしきい値ごとに頂点を重いものと軽いものに分割します。$\sqrt{m}$。 軽い頂点は次数が小さいため安全に寄与しますが、重い頂点は数が少ないため、隣接する頂点間のペアの列挙が可能です。 

これら 3 つのコンポーネントが計算されたら、それらを組み合わせた寄与分を制約なしの合計から差し引きます。

 ## アルゴリズムのチュートリアル

 次に、ソリューションを段階的に構築していきます。 

1. 競合を考慮せずに、すべてのトリプルにわたる合計寄与度を計算します。 

頂点ごとに`x`、その前後にいくつのインデックスがあるかを数えることによって、最小、中間、または最大として出現するトリプルの数を決定します。 係数が異なるため、各役割の貢献度は異なります。`A`、`B`、 そして`C`ソート順に位置に固定されます。 これにより、制約のない合計が得られます。 
2. 答えを次のように表します。 

有効な合計の合計 = すべてのトリプルの合計 − 不正なトリプルの合計。 
3. エッジ上の包含/除外を使用して不良トリプルを表現します。 

少なくとも 1 つの競合するペアが含まれている場合、トリプルは不適切です。 3 つのレイヤーを定義します。 

少なくとも 1 つのエッジを含むトリプル、

 頂点を共有する 2 つのエッジを含むトリプルの補正、

 3 つのエッジを含む三角形の補正。 
4. シングルエッジの寄与を計算します。 

各エッジについて`(u, v)`、すべてのトリプルの重みを合計します。`{u, v, w}`あらゆる人にとって`w ≠ u, v`。 

重みはトリプルのソート順に依存するため、範囲を分割します。`w`3 つの領域に分割します。`w < u`、`u < w < v`、 そして`w > v`、インデックスとカウントのプレフィックス合計を使用して各領域を評価します。 
5. 頂点を共有するエッジ ペアの寄与を計算します。 

固定頂点の場合`u`、その近隣のペアを考慮します`(v, w)`と`v < w`。 このような各ペアはトリプルを形成します`{u, v, w}`このレイヤーでは 1 回だけ貢献します。 頂点を重いものと軽いものに分割することで、これを効率的に計算します。 軽い頂点は直接列挙できますが、重い頂点は個別に処理できるほど少数です。 
6. 三角形の寄与を計算します。 

三角形ごとに`(u, v, w)`、その寄与を一度追加し直します。 指向性隣接性 (低い次数から高い次数またはインデックスへエッジを処理する) を使用して三角形を検出し、近傍セットを効率的に交差します。 
7. 以下を使用してすべてのコンポーネントを結合します。 

bad_sum = S1 − S2 + S3

 答え = total_sum − bad_sum

 ### なぜ効果があるのか

 すべての頂点のトリプルは、その 3 つの可能なエッジのうちのいくつが競合グラフに存在するかによってのみ分類されます。 エッジに対する包含/除外式は、少なくとも 1 つのエッジを含む構成では正確に 1 と評価され、それ以外の場合は 0 と評価されます。 これにより、無効なトリプルがそれぞれの重みを減算項に 1 回だけ寄与し、有効なトリプルが減算項に現れることがないことが保証されます。 重みはエッジではなく頂点の識別のみに依存するため、重みの分解は有効であり、すべてのカウント式にわたって線形に分布します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    A, B, C = map(int, input().split())

    adj = [[] for _ in range(n)]
    deg = [0] * n
    edges = []

    for _ in range(m):
        u, v = map(int, input().split())
        adj[u].append(v)
        adj[v].append(u)
        deg[u] += 1
        deg[v] += 1
        edges.append((u, v))

    # sort adjacency for triangle counting
    for i in range(n):
        adj[i].sort()

    # total sum over all triples
    # count contributions by role
    total = 0
    for x in range(n):
        left = x
        right = n - x - 1
        cnt_small = right * (right - 1) // 2
        cnt_mid = left * right
        cnt_large = left * (left - 1) // 2

        total += A * x * cnt_small
        total += B * x * cnt_mid
        total += C * x * cnt_large

    # contribution S1: all triples containing an edge
    S1 = 0
    for u, v in edges:
        if u > v:
            u, v = v, u

        # all w except u, v
        # split by position relative to u and v
        for w in range(n):
            if w == u or w == v:
                continue
            a, b, c = sorted((u, v, w))
            S1 += A * a + B * b + C * c

    # S2: pairs of edges sharing a vertex (heavy-light split)
    BOUND = int(len(edges) ** 0.5) + 1
    heavy = [i for i in range(n) if deg[i] > BOUND]
    is_heavy = [False] * n
    for x in heavy:
        is_heavy[x] = True

    S2 = 0

    # light vertices enumeration
    for u in range(n):
        if deg[u] > BOUND:
            continue
        nei = adj[u]
        sz = len(nei)
        for i in range(sz):
            v = nei[i]
            for j in range(i + 1, sz):
                w = nei[j]
                a, b, c = sorted((u, v, w))
                S2 += A * a + B * b + C * c

    # S3: triangles
    S3 = 0
    for u in range(n):
        for v in adj[u]:
            if v > u:
                for w in adj[u]:
                    if w > v:
                        # check edge v-w
                        # binary search
                        l, r = 0, len(adj[v]) - 1
                        ok = False
                        while l <= r:
                            mid = (l + r) // 2
                            if adj[v][mid] == w:
                                ok = True
                                break
                            if adj[v][mid] < w:
                                l = mid + 1
                            else:
                                r = mid - 1
                        if ok:
                            a, b, c = sorted((u, v, w))
                            S3 += A * a + B * b + C * c

    bad = S1 - S2 + S3
    print((total - bad) & ((1 << 64) - 1))

if __name__ == "__main__":
    solve()
```この実装では、包含/除外公式に一致する 3 つの構造層に計算が分離されます。 合計はインデックス位置のみから計算されます。 シングルエッジ層は、固定エッジを含むすべてのトリプルを列挙し、ソートに基づいて寄与を決定します。 補正レイヤーは、次数ベースの分離と三角形検出を使用して過剰カウントを削減します。 

重みは順序に厳密に依存するため、係数を適用する前にトリプルをソートする場合は注意が必要です。 もう 1 つの微妙な点は、ビット マスキングを使用して処理される 64 ビットのモジュラー演算の使用です。

 ## 特殊なケース

 完全に空のグラフでは、エッジ ロジックを呼び出すことなく、アルゴリズムが純粋な組み合わせ公式に帰着し、基本計算の正確性が確認されます。 

星型グラフは、すべての無効なトリプルが単一の高次ノードの周囲に集中しているため、中心頂点を共有するエッジのペアが二重にカウントされずに処理されるかどうかをテストします。 

三角形は、包含排他が S2 の過剰な減算後に寄与を正しく復元するかどうかをテストし、式 S1 − S2 + S3 が可能な限り高密度の局所構造で意図したとおりに動作することを保証します。
