 ## 解決策
 ## 問題の理解

 非負の配列があり、正確に (k-1) 個のカット位置を選択して、(k) 個の連続した空でないセグメントを生成する必要があります。 隣接するセグメントのすべてのペアについて、それらの合計が十分に近く、大きい方のセグメントの合計が小さい方のセグメントの合計を、いずれかのセグメントに含まれる最大の個別要素を超えて超えることができないようにする必要があります。 必要な出力は、これらすべての不等式を満たすカット位置のセットです。 元の問題とサンプルは (n\le 10^5) を使用しているため、カット位置に対する 2 次または指数関数の検索は実行できません。 

隠された重要な事実は、有効なパーティションが常に存在するということです。 元の不等式を一時的に忘れて、二乗セグメントの合計を最小にする分割を探すことができます。 

[
 s_1^2+s_2^2+\cdots+s_k^2。 
】

 2 つの隣接するセグメントに合計 (A>B) があり、その差が 2 つのセグメント内のすべての要素よりも大きいとします。 値が (x) である最初の正の要素に到達するまで、大きなセグメントから共通境界のすぐ隣にある要素を取得します。 すべての要素は最大でも大きなセグメントの最大値であるため、(0<x<A-B) になります。 このサフィックスを境界を越えて移動すると、2 つの合計が (A-x) と (B+x) に変わります。 

[
 (A-x)^2+(B+x)^2<A^2+B^2。 
】

 したがって、最小二乗分割は必要な不等式に違反することはできません。 これは、この問題の標準的な解決策の背後にある有用な再定式化です。 

不注意な実装を特に危険にする制約が 2 つあります。 しきい値 (0) を使用したしきい値ベースの貪欲な手順では、すべてのゼロが完了したセグメントであるとみなされるため、ゼロには特別な注意が必要です。 例えば、```
4 3
100 100 0 0
```カット`2 3`セグメントの合計が (200,0,0) である場合、最初の差は (200>100) であるため、そのパーティションは無効です。 しきい値がゼロになったときに単純に任意のカットを行う不注意な実装は、ここで失敗する可能性があります。 正しい構成では、正の要素が (k) より少ない場合は常に、すべての正の要素が別個のセグメントに保持されます。 

もう 1 つのエッジ ケースは、合計が単にしきい値に達するセグメントと、残りのサフィックスを含めることが許可されるセグメントとの区別です。 例えば、```
3 3
1 2 3
```自然な答えは、`1 2`、合計(1,2,3)を与えます。 貪欲な実装が、生成されるすべてのセグメントが空でないことを要求することを忘れた場合、空の残りを別のセグメントとして誤って扱う可能性があります。 

この制約により、カット セットの列挙が除外されます。 (\binom{n-1}{k-1}) 個の可能な分割があり、それらすべてを評価すると、最悪の場合、すでに指数関数的になります。 (n=100000) の場合、(k=3) であっても (\binom{99999}{2})、約 50 億の候補が得られますが、(n/2) に近い (k) の値では指数関数的に多くの候補が得られます。 意図した解決策は、二分探索反復ごとに線形に近いものでなければなりません。 

## アプローチ

 ブルートフォースアプローチは概念的には単純です。 (k-1) 個のカット位置のすべてのセットを列挙し、その (k) 個のセグメントの合計と最大値を計算し、すべての隣接ペアをチェックします。 プレフィックス合計を使用すると、セグメント合計を一定時間で取得でき、同時に候補パーティションのスキャン中に最大値を維持できます。 (O(k)) チェックを行ったとしても、総作業量は (O(k\binom{n-1}{k-1})) となり、(n=10^5) では絶望的です。 ブルート フォースが役立つのは、最終的に必要なものが明らかになるからです。正確に (k) 個のセグメントを持つすべてのパーティションの中から、特にバランスのとれたセグメント合計のコレクションを持つパーティションを見つけます。 

二乗和の観察により、より構造化されたターゲットが得られますが、正確に (k) 個のセグメントを直接最適化するのは依然として厄介です。 標準的な凸 DP アプローチが存在しますが、この問題に固有のより単純な構成があります。 中心となるアイデアは、数値閾値 (x) を導入することです。 

左から開始して、現在の合計が少なくとも (x) に達するまで要素を繰り返し累積し、セグメントを閉じます。 すべての値が負ではないため、この欲張りスキャンは (x) において単調です。(x) を増加しても、完了したセグメントの数は減少するだけです。 したがって、少なくとも (k) 個のそのようなセグメントを完了できる最大の (x) を二分探索できます。 

結果として得られる貪欲なセグメントには強力な特性があります。 セグメントが最後の要素 (u) で初めて (x) に到達した場合、(u) より前の要素は、(r\le u) で、ある正の (r) に対して合計 (x-r) を持ちます。 したがって、その合計は

 [
 x-r+u。 
】

 このような 2 つの連続するセグメントの場合、対応する値を (u_i,u_{i+1}) として、不足分を (r_i,r_{i+1}) として記述すると、それらの合計の差は次のようになります。 

[
 (u_i-r_i)-(u_{i+1}-r_{i+1})。 
】

 この差が正の場合、その絶対値は (u_i) よりも厳密に小さくなり、負の場合、その絶対値は (u_{i+1}) よりも厳密に小さくなります。 これらの最後の要素はそれぞれのセグメントに含まれているため、元の条件が続きます。 

唯一残っている問題は、左側の貪欲パーティションに (k) を超えるセグメントが含まれているか、別の (x) セグメントをトリガーするのに十分な大きさではないサフィックスが残っている可能性があることです。 ここで、(x) の最大値が重要になります。 同じ貪欲な構築を右側から実行しますが、しきい値 (x+1) を使用します。 左側の構成には少なくとも (k) 個のブロックがありますが、(x) が最大限に選択されているため、右側の構成には (k) 個未満のブロックがあります。 

標準の境界交差補題では、これら 2 つの貪欲なパーティションには共通の境界がなければならないと規定されています。 そうしないと、それらの順序付けされた境界が交差し、(x+1) の構築が (x) の境界を越えてシフトされて、少なくとも (k) 個の完成したブロックが生成され、(x) の最大値に矛盾する可能性があります。 これが、左から (x) を使用し、右から (x+1) を使用する構造的な理由です。 

共通の境界では、ジャンクションも有効です。 左側のセグメントは (x)-greedy セグメントであり、右側のセグメントは ((x+1))-greedy セグメントです。 最後の要素と最初の要素がそれぞれ (u) と (v) である場合、それらの合計は次のように書くことができます。 

[
 x-r+u
 \quad\text{および}\quad
 x+1-t+v、
 】

 ここで、(1\le r\le u) と (1\le t\le v) です。 それらの差は (\max(u,v)) によって制限されるため、スプライスによって無効な隣接ペアが導入されることはありません。

特殊なケースが 1 つあります。 最大のしきい値が (x=0) の場合、正の要素は (k) 個よりも少なくなります。 すべてのシングルトン セグメントから開始して、2 つの正の要素をマージしない場合にのみカットを削除できます。 結果として得られる各セグメントには最大 1 つの正の要素が含まれるため、その合計は最大値に等しく、隣接する 2 つのセグメントの合計は自動的に条件を満たします。 

この問題に対する受け入れられている解決策にも同じしきい値の構築があり、2 回目のスキャンでは (x+1) を使用し、共通の境界を探します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(k\binom{n-1}{k-1})) | (O(n)) | 遅すぎる |
 | しきい値貪欲 + 二分探索 | (O(n\log S)) | (O(n)) | 承認済み |

 ここでは (S=\sum a_i) および (S\le 5\cdot10^9) であるため、二分探索では約 33 回の反復のみが使用されます。 

## アルゴリズムのチュートリアル

 1. 正の要素の数を数えます。 (k) より小さい場合は、すべての配列要素を独自のセグメントとして開始します。 このようなペアをマージすると、少なくとも 2 つの正の値を含むセグメントが作成されるため、2 つの正の要素間のすべてのカットを保持します。 正確に (k) 個のセグメントが残るまで、他の任意のカットを削除します。 結果として得られる各セグメントには最大 1 つの正の要素が含まれるため、その合計が最大値となり、必要な不等式が成り立ちます。 
2. それ以外の場合は、左から右への貪欲スキャンで少なくとも (k) 個の完全なセグメントを作成できる最大の整数 (x\ge1) を二分探索します。 このスキャン中、現在の合計を維持します。 (x) に到達するたびに、現在位置をカットとして記録し、合計をリセットします。 
3. しきい値 (x) スキャンによって生成されたすべてのカット位置を保存します。 このようなカットの数は少なくとも（ｋ）である。 しきい値は最大であるため、しきい値 (x+1) で同じスキャンを実行すると、生成される完全なセグメントは (k) 個よりも少なくなります。 
4. しきい値 (x+1) を使用して、右から左に 2 回目の貪欲スキャンを実行します。 完了したすべてのセグメントの左端点を保存します。 左側の貪欲なセグメントの 1 つの終点であると同時に、右側の貪欲なセグメントの 1 つの開始の直前である境界を検索します。 
5. 共通の境界が (i) 左貪欲セグメントの後にあると仮定します。 この場合、右側は正確に (k-i) 個のセグメントに寄与する必要があります。 最初 (i) 個の left-greedy セグメントと最後の (k-i) right-greedy セグメントを保持します。 共通の境界により、これら 2 つのコレクションは重複やギャップがなく配列全体をカバーします。 
6. 左側の部分では、両方のセグメントがしきい値 (x) 貪欲ルールによって作成されているため、すべての隣接するペアが条件を満たします。 右側の部分内では、同じ引数がしきい値 (x+1) ルールに適用されます。 共通接合は、上記の (x) 対 (x+1) の計算による条件を満たします。 

### なぜ効果があるのか

 構築の背後にある不変条件は、しきい値に貪欲なセグメントがその最終要素でバランスが取れているということです。 その要素が追加される直前に、その部分和は厳密にしきい値を下回ります。 その結果、最終要素は欠落量を補うのに十分な大きさとなり、これにより隣接するセグメントの合計間の差に直接的な制限が与えられます。 

最大しきい値は、構築の後半を提供します。 (x) では、少なくとも (k) 個のセグメントを完了できますが、(x+1) では、(k) 個未満のセグメントを完了できます。 したがって、2 つの単調貪欲境界シーケンスは共通の位置で交差する必要があります。 そこでスプライシングすると、正確に (k) 個のセグメントが得られます。 すべてのセグメントは 2 つのしきい値構造のいずれかに属し、ジャンクション自体は連続したしきい値を使用するため、必要なすべての不等式が成り立ちます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(n, k, a):
    positive = sum(x > 0 for x in a)

    # If there are fewer positive elements than segments,
    # keep every positive element separated from every other positive.
    if positive < k:
        cuts = list(range(1, n))

        # A cut between two positive elements is mandatory.
        mandatory = [a[i - 1] > 0 and a[i] > 0 for i in range(1, n)]

        need_remove = n - k
        removable = [i for i in range(1, n) if not mandatory[i - 1]]

        removed = set(removable[:need_remove])
        ans = [i for i in cuts if i not in removed]
        return ans

    total = sum(a)

    def count_segments(x):
        cur = 0
        cnt = 0
        for v in a:
            cur += v
            if cur >= x:
                cnt += 1
                cur = 0
        return cnt

    # Largest threshold for which at least k full segments exist.
    lo, hi = 1, total
    x = 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if count_segments(mid) >= k:
            x = mid
            lo = mid + 1
        else:
            hi = mid - 1

    # Greedy partition from the left with threshold x.
    left = []
    cur = 0
    for i, v in enumerate(a, 1):
        cur += v
        if cur >= x:
            left.append(i)
            cur = 0

    # If it already gives exactly k segments and reaches n,
    # the construction is complete.
    if len(left) == k and left[-1] == n:
        return left[:-1]

    # Greedy partition from the right with threshold x + 1.
    right = []
    cur = 0
    for i in range(n, 0, -1):
        cur += a[i - 1]
        if cur >= x + 1:
            right.append(i)
            cur = 0

    # right is stored from right to left.
    # A common boundary has left[i - 1] == right[k - i - 1] - 1.
    for i in range(1, len(left) + 1):
        j = k - i
        if j < 1 or j > len(right):
            continue

        boundary = left[i - 1]
        if boundary == right[j - 1] - 1:
            ans = left[:i - 1]

            # right[j - 1] is the start of the first segment
            # on the right, so it is exactly boundary + 1.
            for t in range(j - 2, -1, -1):
                ans.append(right[t] - 1)

            ans.sort()
            return ans

    # The boundary lemma guarantees that this point is unreachable.
    raise AssertionError("No common boundary found")

def main():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    ans = solve_case(n, k, a)

    print("Yes")
    print(*ans)

if __name__ == "__main__":
    main()
```最初のブランチは、しきい値 (0) の場合を明示的に処理します。 すべてのシングルトン セグメントから開始すると、(n) 個のセグメントが得られます。 2 つのポジティブ要素の間のカットは残しておく必要がありますが、他の場所のカットは 2 つのポジティブ要素を同じセグメントに入れなくても削除できます。 正の要素が (k) 個よりも少ないため、正確に (k) 個のセグメントに到達するのに十分な除去可能なカットがあります。 

の`count_segments`function は二分探索述語です。 プルーフで使用される貪欲スキャンを正確に実行するため、しきい値が増加するにつれてカウントは単調になります。 合計を超える正のしきい値は 1 つの完全なセグメントさえも作成できないため、上限は配列の合計です。 

の`left`配列は、1 から始まる位置を使用してエンドポイントを格納します。 2 番目のスキャンでは、(n) から (1) に向かって進むため、左のエンドポイントが降順で格納されます。 もし`j = k - i`、 それから`right[j - 1] - 1`最初の (i) 左側セグメントの後、最初の (j) 右側のセグメントの前の境界です。 残りの右側の境界は、前の右側の端点を逆の順序でたどることによって取得されます。 

Python の整数には任意の精度があるため、潜在的に大きな合計とすべてのしきい値の計算は安全です。 また、実装では再帰呼び出しが回避され、線形サイズの配列のみが使用されます。

        cur = 0
        cnt = 0
        for v in a:
            cur += v
            if cur >= x:
                cnt += 1
                cur = 0
        return cnt

    lo, hi = 1, total
    x = 1

    while lo <= hi:
        mid = (lo + hi) // 2
        if count_segments(mid) >= k:
            x = mid
            lo = mid + 1
        else:
            hi = mid - 1

    left = []
    cur = 0
    for i, v in enumerate(a, 1):
        cur += v
        if cur >= x:
            left.append(i)
            cur = 0

    if len(left) == k and left[-1] == n:
        return left[:-1]

    right = []
    cur = 0
    for i in range(n, 0, -1):
        cur += a[i - 1]
        if cur >= x + 1:
            right.append(i)
            cur = 0

    for i in range(1, len(left) + 1):
        j = k - i
        if j < 1 or j > len(right):
            continue

        if left[i - 1] == right[j - 1] - 1:
            ans = left[:i - 1]
            for t in range(j - 2, -1, -1):
                ans.append(right[t] - 1)
            ans.sort()
            return ans

    raise AssertionError("No common boundary")

def run(inp: str) -> str:
    data = list(map(int, inp.split()))
    it = iter(data)
    n = next(it)
    k = next(it)
    a = [next(it) for _ in range(n)]

    ans = solve_case(n, k, a)
    return "Yes\n" + " ".join(map(str, ans)) + "\n"

def validate(inp: str, out: str):
    data = list(map(int, inp.split()))
    n, k = data[0], data[1]
    a = data[2:]

    lines = out.strip().splitlines()
    assert lines[0] == "Yes"

    cuts = list(map(int, lines[1].split()))
    assert len(cuts) == k - 1
    assert cuts == sorted(cuts)
    assert all(1 <= x < n for x in cuts)

    bounds = [0] + cuts + [n]

    sums = []
    maximums = []

    for l, r in zip(bounds, bounds[1:]):
        segment = a[l:r]
        assert segment
        sums.append(sum(segment))
        maximums.append(max(segment))

    for i in range(k - 1):
        assert abs(sums[i] - sums[i + 1]) <= max(
            maximums[i], maximums[i + 1]
        )

# Provided sample
sample = "5 3\n17 18 17 30 35\n"
validate(sample, run(sample))

# Minimum-size input
case_min = "3 3\n1 2 3\n"
validate(case_min, run(case_min))

# All equal values
case_equal = "8 4\n7 7 7 7 7 7 7 7\n"
validate(case_equal, run(case_equal))

# Zero-heavy boundary case
case_zero = "4 3\n100 100 0 0\n"
validate(case_zero, run(case_zero))

# Maximum-size input
case_max = "100000 100000\n" + ("1 " * 100000) + "\n"
validate(case_max, run(case_max))

 ## 特殊なケース

 最小サイズの入力の場合```
3 3
1 2 3
```空ではない 3 つのセグメントに分割できるパーティションは 1 つだけです。 アルゴリズムは (x=1) を見つけ、すべての要素の後にカットを作成し、最後のカットはエンドポイント (n) であるため削除します。 出力は`1 2`、必要に応じて正確に。 

ゼロヘビーの場合```
4 3
100 100 0 0
```3 つのセグメントをサポートする最大の正のしきい値は存在しないため、しきい値はゼロになります。 ゼロを通常の貪欲なしきい値として扱う代わりに、アルゴリズムは特別な構造を使用します。 2 つの正の値の間の境界を維持し、ゼロに関連する 1 つの境界を削除します。`100 | 100 | 0 0`。 各セグメントには最大でも 1 つの正の要素が含まれるため、その合計は最大値と等しくなります。 

次のようなすべての等しい値に対して、```
8 4
7 7 7 7 7 7 7 7
```多くのパーティションは同様に良好です。 特定のアルゴリズムを再現するためにアルゴリズムは必要ありません。 バリデーターは、固定された答えではなく構造条件をチェックします。これは、建設的なソリューションをテストする正しい方法です。 

(n=k=100000) の最大サイズの場合、各セグメントには 1 つの要素が含まれている必要があります。 このアルゴリズムの二分探索は依然として (O(\log S)) 回のスキャンのみを実行し、最終出力には正確に (99999) 個のカットが含まれます。 この実装では反復ループと整数演算が使用されるため、再帰の深さや浮動小数点の問題はありません。 

最も微妙な境界条件は、(n) でのカットと必要な出力カットの間の違いです。 貪欲スキャンでは当然最終セグメントのエンドポイントが記録されますが、出力には (k-1) 個の内部境界のみが含まれている必要があります。 この実装では、左側の構造ですでに正確に (k) 個の完全なセグメントが得られている場合は常に、最終位置を明示的に削除します。
