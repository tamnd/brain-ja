 ## 問題の理解

 バイナリ文字列があります`a`そして`b`。 許可される操作は、次の 3 つの特殊ブロックのいずれかを挿入または削除します。`aa`、`bbb`、 または`ababab`。 すべての操作は、対応する挿入または削除を実行することによって元に戻すことができるため、操作は文字列の等価クラスを定義します。 タスクは、正確な長さの異なる文字列がいくつあるかを判断することです。`x`指定された文字列と同じ等価クラスに属します`s`。 

制約は、大きな入力文字列と巨大なターゲット長の間で意図的に分割されます。 元の文字列には 300,000 文字を含めることができるため、その処理は基本的に線形である必要があります。 同時に、`x`できる`10^9`これにより、長さによってインデックス付けされた動的プログラミングと、ターゲット文字列の文字ごとに 1 つの遷移を実行するシミュレーションが除外されます。 1 秒の時間制限により、元の文字列に対する中程度の超線形作業さえも望ましくなくなります。そのため、主な課題は、同値関係を一定数の状態に圧縮することです。 公式声明によると、`n <= 300000`、`x <= 10^9`、制限時間は1秒です。

## アプローチ

 直接的なアプローチでは、長さのすべてのバイナリ文字列を列挙します。`x`から変換できるかどうかをテストします。`s`、成功したものを数えます。 まさにあります`2^x`候補文字列であるため、等価性をチェックする前であっても、最悪の場合には`2^x`候補者たち。 と`x = 10^9`、これはまったく不可能です。 もう 1 つの自然な総当たりアプローチは、可能なすべての挿入と削除を実行することですが、挿入によって中間文字列が任意に長くなる可能性があるため、これはさらに有用ではありません。 

すべての操作が関心のある等価関係を正確に保持するため、ブルート フォースが機能します。 問題は、文字列自体が巨大なオブジェクトであるのに対し、リレーションは生の表現が示すよりもはるかに多くの構造を持っていることです。 

重要な観察は、3 つの関係が代数的に次のように記述できることです。`a² = 1`、`b³ = 1`、 そして`(ab)³ = 1`。 

これらはまさに、交互群である四面体の回転対称群の定義関係です。`A4`。 そのグループには要素が 12 個しかありません。 同様に、すべての文字列はちょうど 12 の等価クラスに分割されます。 これらのクラスの一般的な代表セットは空の文字列です。`a`、`b`、`ab`、`ba`、`bb`、`aba`、`abb`、`bab`、`bba`、`babb`、 そして`bbab`。 この 12 状態構造は、この問題に対する標準的な解決策の基礎でもあります。 

2 つの文字を 4 つの頂点の順列として表すことにより、観察を完全に具体化することができます。 させて`a`順列になる`(0 1)(2 3)`そしてさせてください`b`なれ`(1 2 3)`。 どちらも偶数順列なので、`A4`。 彼らは満足します`a² = 1`、`b³ = 1`、 そして`(ab)³ = 1`、そしてそれらは の 12 要素すべてを生成します。`A4`。 

したがって、文字列を評価するということは、対応する順列を乗算することを意味します。 2 つの文字列は、同じグループ要素として評価される場合、正確に等価です。 どちらかを追加する`a`または`b`その後、これら 12 の状態のうちの 2 つの状態間の遷移になります。

 ## アルゴリズムのチュートリアル

 1. 各文字を 4 つの要素の順列で表します。 使用`a = (0 1)(2 3)`そして`b = (1 2 3)`。 順列は 4 つのイメージのタプルとして保存されるため、順列合成は 4 回の配列アクセスで実装できます。 

選択された順列は、許容される 3 つの関係を満たします。 これらは 4 つの要素の偶数順列をすべて生成するため、正確に 12 個の群状態に到達できます。 
2. 恒等順列から開始する幅優先検索で 12 個のグループ要素を生成します。 既知のすべての状態を乗算します。`a`そしてによって`b`。 新しく発見されたすべての順列を保存し、状態インデックスを割り当てます。 

名前をハードコーディングする代わりに状態を生成すると、実装は縮小された文字列の特定のリストから独立します。 唯一必要な事実は、生成されたグループに 12 個の要素があることです。 
3. 入力文字列に対応する状態を計算します`s`。 ID から開始して、各文字に関連付けられた順列を掛けます。 

これにはかかります`O(n)`時間をかけて、元の文字列全体を 12 の可能な状態のうちの 1 つに減らします。 
4. を構築します。`12 x 12`遷移行列`M`。 セット`M[i][j]`グループ状態を移動する文字の数に応じて`i`グループ状態へ`j`。 

すべての状態から発信される遷移は 2 つだけあり、1 つは追加用です。`a`もう 1 つは追加用です`b`。 両方の文字がたまたま同じ状態につながる場合、対応する行列のエントリは次のようになります。`2`。 
5. コンピューティング`M^x`2進累乗を使用します。 どの州でも`u`そして`v`、エントリ`(M^x)[u][v]`は長さの数値です -`x`で始まる文字列`u`そして終了`v`。 

すべてのバイナリ文字列は空の文字列に文字を追加することによって構築されるため、アイデンティティ状態から開始します。 
6. しましょう`target`の状態になる`s`そしてさせてください`identity`空文字列状態になります。 必要な答えは、`(M^x)[identity][target]`、剰余を取得`998244353`。 

これは、単にエンドポイントだけでなく、実際の文字シーケンスによって文字列をカウントします。 行列の乗算では、遷移のすべての個別のシーケンスが個別にカウントされます。 

機能する理由: 挿入または削除された各ブロックは ID として評価されるため、許可された挿入または削除はすべてグループ要素を保持します。 逆に言えば、関係`a² = b³ = (ab)³ = 1`は 12 要素の四面体グループを正確に与えるので、2 つのバイナリ文字列は、同じグループ要素を表す場合に、許可された操作によって正確に接続されます。 遷移行列は、1 つの文字を追加するとその要素がどのように変化するかを正確に記録します。 したがって、すべての長さ-`x`の等価クラスの文字列`s`1つの長さに対応します-`x`アイデンティティ状態から`target`、そのようなすべてのウォークは、そのクラス内の 1 つのバイナリ文字列に対応します。 したがって、アルゴリズムによって計算された行列エントリは、正確に必要な数になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353
K = 12

def compose(p, q):
    # p after q: (p o q)(i) = p(q(i))
    return (
        p[q[0]],
        p[q[1]],
        p[q[2]],
        p[q[3]],
    )

def build_group():
    identity = (0, 1, 2, 3)

    # a = (0 1)(2 3)
    a = (1, 0, 3, 2)

    # b = (1 2 3)
    b = (0, 2, 3, 1)

    generators = (a, b)

    states = [identity]
    index = {identity: 0}

    head = 0
    while head < len(states):
        cur = states[head]
        head += 1

        for g in generators:
            nxt = compose(cur, g)
            if nxt not in index:
                index[nxt] = len(states)
                states.append(nxt)

    return states, index, generators

def mat_mul(a, b):
    c = [[0] * K for _ in range(K)]

    for i in range(K):
        ci = c[i]
        ai = a[i]

        for k in range(K):
            x = ai[k]
            if x == 0:
                continue

            bk = b[k]
            for j in range(K):
                ci[j] = (ci[j] + x * bk[j]) % MOD

    return c

def mat_pow(a, e):
    result = [[0] * K for _ in range(K)]
    for i in range(K):
        result[i][i] = 1

    while e:
        if e & 1:
            result = mat_mul(result, a)
        a = mat_mul(a, a)
        e >>= 1

    return result

def solve():
    n = int(input())
    s = input().strip()
    x = int(input())

    states, index, generators = build_group()
    identity = states[0]

    a, b = generators

    transition = [[0] * K for _ in range(K)]

    for i, state in enumerate(states):
        to_a = index[compose(state, a)]
        to_b = index[compose(state, b)]

        transition[i][to_a] += 1
        transition[i][to_b] += 1

    target = identity
    for ch in s:
        if ch == 'a':
            target = compose(target, a)
        else:
            target = compose(target, b)

    target_index = index[target]
    powered = mat_pow(transition, x)

    print(powered[0][target_index] % MOD)

if __name__ == "__main__":
    solve()
```の`compose`関数は規約を使用します`p`後`q`、 それで`compose(cur, generator)`現在の単語の右側に新しい文字を追加することを表します。 状態の生成、遷移の構築、および評価に一貫して使用される限り、正確な規則は重要ではありません。`s`。`build_group`ID から開始し、2 つのジェネレーターを繰り返し適用します。 3 つの定義関係により、12 個の状態のみが表示されることが保証されます。 BFS は、これら 12 個の順列を検出した後に終了します。 

遷移行列は、現在の状態に行を使用し、次の状態に列を使用します。 各状態には次の文字が 2 つある可能性があるため、各行の合計の重みは 2 になります。 行列累乗は同じ解釈を保持します。`M^k[i][j]`長さの数を数えます-`k`状態を取る文字列`i`述べます`j`。 

入力文字列は、行列プロセスに挿入されるのではなく、個別に評価されます。 これが必要な理由は、`n`わずか 300,000 ですが、`x`10億になる可能性があります。 私たちは直線的な時間を費やします`s`、次に対数時間`x`。 

べき乗ループは単位行列から開始する必要があります。 このハンドルは`x = 0`自動的に`M^0`は単位行列なので、答えは次のようになります。`1`まさにいつ`s`アイデンティティクラスに属します。 

Python の整数はオーバーフローしませんが、各行列の累積モジュロを削減します。`998244353`中間値を小さく保ち、不必要な増加を回避します。 行列には 12 行と 12 列しかないため、定数係数は非常に小さいです。
