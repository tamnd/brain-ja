 ## 解決策
 ## 問題の理解

 元の順序を維持しながら、配列から正確に (k) 個の要素を保持する必要があります。 これらの要素が選択されると、サイクルが形成されます。連続して選択された要素がその合計に寄与し、最後に選択された要素も最初の要素とペアになります。 選択されたサブシーケンスのコストは、これらの (k) ペアの合計の最大値になります。 コストは可能な限り最小限に抑えたいと考えています。 

難しいのは、サブシーケンスが配列内の単なるパスではないことです。 最後の要素も最初の要素と互換性がある必要があるため、通常の左から右への動的プログラミング アプローチでは開始要素に関する情報が失われます。 

配列には最大 (200,000) 個の要素を含めることができ、各値は (10^9) までの大きさにすることができます。 (O(n^2)) アルゴリズムでは、最悪の場合でも既に約 (4\cdot10^{10}) 回の演算が必要となり、これは 3 秒の制限をはるかに超えています。 問題ごとに本質的に線形または (O(n\log n)) の作業が必要であり、できれば (k) に依存する係数がないことが必要です。 

誤って対処しやすい特殊なケースがいくつかあります。 まず、最後に選択した要素と最初に選択した要素の間の循環ペアが重要です。 例えば、```
5 3
5 1 100 1 5
```(1,1,5) を選択すると、答えは (6) になります。(5) は配列のどちらかの端から来ます。 通常の線形順序で小さな要素間のギャップのみを検査するチェックでは、この選択が見逃され、2 つの要素しか選択できないと誤って報告される可能性があります。 

正確な境界 (w_i = X/2) も重要です。 のために```
3 3
10 10 10
```答えは(20)です。 (X=20) をテストする場合、(10+10=20) であるため、(10) に等しい値は小さいものとして分類される必要があります。 (2w_i\le X) の代わりに厳密な不等式を使用すると、答えが誤って拒否されます。 

小さな要素がない場合も明示的に処理する必要があります。 のために```
3 3
10 11 12
```唯一可能な部分列は配列全体であり、その巡回ペアの合計は (21,23,22) であるため、答えは (23) になります。 常に少なくとも 1 つの小さな要素が存在することを前提とした実現可能性チェックでは、存在しないエンドポイントにアクセスしたり、しきい値を誤って実現可能と宣言したりする可能性があります。 

最後に、少なくとも (k) 個の小さな要素がすでに存在する場合、大きな要素はまったく必要ありません。 のために```
4 3
1 2 3 100
```答えは (1,2,3) を使用して (5) です。 すべてのギャップに大きな要素を追加することに固執する方法では、答えが不必要に大きくなる可能性があります。 

## アプローチ

 直接的な総当たりアプローチは簡単です。 (k) 個のインデックスのすべてのセットを列挙し、その順序を保持し、(k) 個の巡回隣接合計を計算し、最小最大値を保持します。 考えられるすべてのサブシーケンスが明示的に考慮されるため、これは正しいです。 そのコストは (\Theta!\left(\binom nk k\right)) で、(n) で指数関数的になります。 (k=n/2) 付近では、候補の数はおよそ (2^n/\sqrt n) であるため、総作業量は (2^n\sqrt n) 程度になります。 (n=200,000) では、これはリモートで実現可能ではありません。 

視点を変えると効果的なのは、最適なサブシーケンスを直接構築するのをやめるということです。 代わりに、候補の答え (X) がわかっていると仮定し、長さ (k) の有効なサブシーケンスが最大 (X) の巡回隣接合計を持つかどうかを尋ねます。 この述語は単調です。(X) が実行可能であれば、より大きな値もすべて実行可能です。 これにより、即座に答えの二分探索が行われます。 

ここで、1 つの固定しきい値 (X) を考えてみましょう。 次の場合に要素を small と呼びます。 

[
 2w_i\le X、
 】

 それ以外の場合は大きいです。 合計が最大 (X) であるすべてのペアには、少なくとも 1 つの小さな要素が含まれている必要があります。 2 つの大きな要素は、それらの合計が厳密に (X) より大きいため、選択したサイクル内で隣接することはできません。 これが中心的な構造観察です。 

さらに強力な事実があります。 しきい値 (X) の下で選択できる要素の数を最大化する場合、すべての小さな要素が選択されると常に想定できます。 小さな要素が欠落しているとします。 サイクルの前後で選択した小さな要素を見てください。 これら 2 つの選択された小さな要素の間には、最大 1 つの選択された大きな要素が存在できます。 存在する場合は、その大きな要素を不足している小さな要素で置き換えます。 両方の値が最大 (X/2) であるため、置換は隣接する両方の小さな要素との互換性を維持します。 隣接する小さな要素の間に選択された要素がない場合は、不足している小さな要素を追加するだけです。 したがって、すべての小さな要素を選択しても、達成可能なサブシーケンスの最大長が減少することはありません。 

すべての小さな要素が修正されると、問題ははるかに単純になります。 2 つの連続する小さな要素の間には他の小さな要素がないため、ギャップには大きな要素のみが含まれます。 最大で 1 つを選択できます。 最良の候補は単にそのギャップ内の最小値です。 2 つの境界の小さな値が (a) と (b) である場合、候補 (x) はまさに次の場合に有効です。 

[
 x+\max(a,b)\le X.
 】

 最後の小さい要素と最初の小さい要素の間の循環ギャップは、最後の小さい要素の後の接尾辞と最初の小さい要素の前の接頭辞の最小値を取ることによって処理されます。 

1 回の左から右へのスキャンで、すべての小さな要素をカウントし、すべてのギャップの最小値を見つけることができます。 したがって、1 つの実現可能性チェックは (O(n)) であり、すべてのペアの合計が (2) と (2\cdot10^9) の間にあるため、答えをバイナリ検索するのに必要なチェックは約 31 回だけです。

 | ブルートフォース | (\シータ!\left(\binom nk k\right)) | (O(k)) | 遅すぎる |
 | 最適 | (O(n\log 10^9)) | (O(n)) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 実行可能な最小しきい値 (X) を二分探索します。 実行不可能な下限として (0) を使用し、実行可能な上限として (2\max(w_i)) を使用します。これは、配列要素の各ペアの和が最大 (2\max(w_i)) であるためです。 
2. 固定 (X) の場合、(2w_i\le X) を満たすすべての値を小さいものとして分類します。 2 つの小さな値は、それらの合計が最大 (X) であるため、隣接することができます。 2 つの大きな値は、それらの合計が (X) を超えるため隣接できません。 
3. 配列をスキャンし、小さな要素を数えます。 それらのカウントがすでに少なくとも (k) である場合、任意の (k) 個の小さな要素が有効なサイクルを形成するため、しきい値は実現可能です。 
4. 小さな要素が存在しない場合、しきい値は不可能です。 すべてのエッジには、値が最大 (X/2) である少なくとも 1 つのエンドポイントが必要であるため、すべての有効なサイクルには小さな要素が含まれている必要があります。 
5. 連続する小さな要素の各ペアについて、それらの間の最小値を見つけます。 その区間内には小さな要素がないため、そこにあるすべての候補は大きく、選択できる候補は最大 1 つです。 
6. 連続する小さな値を (a) と (b) とし、(m) をそれらの間の厳密な最小値とします。 このギャップから 1 つの要素を正確に追加できるのは、
 [
 m+\max(a,b)\le X.
 】
 挿入された要素は両方の境界の小さな要素と有効なペアを形成する必要があるため、最大値が必要です。 
7. 最後の小さな要素と最初の小さな要素の間の循環ギャップを処理します。 その候補は、最後の小さなポジションの後の要素と最初の小さなポジションの前の要素です。 これら 2 つの領域の最小値が、そのギャップに対する最良の追加要素となります。 
8. 選択可能な要素の最大数は、小さな要素の数に 1 つの有効な大きな要素を許可するギャップの数を加えたものです。 このカウントが少なくとも (k) であれば、しきい値 (X) は実現可能です。 
9. 実行可能な最小のしきい値が残るまで二分探索を続けます。 

実現可能性チェックの背後にある不変条件は、すべての小さな要素を修正した後、残りのすべてのギャップが独立しており、追加の選択要素が最大 1 つだけ寄与するということです。 最適な最大カーディナリティの選択にはすべての小さな要素が含まれる可能性があることをすでに証明しているため、これらのギャップを正確に考慮しても解決策が失われることはありません。 1 つのギャップ内では、境界値が固定されており、小さい候補がどちらの隣接ペアにとっても悪くなることはないため、その最小値を選択することが最適です。 したがって、計算された数は、(X) で選択できる要素の最大数となります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(n, k, w):
    def feasible(x):
        half = x // 2

        small_count = 0
        first_small = -1
        last_small = -1

        extra = 0
        gap_min = None

        for i, value in enumerate(w):
            if value <= half:
                small_count += 1

                if first_small == -1:
                    first_small = i
                else:
                    if gap_min is not None:
                        if gap_min + max(w[last_small], value) <= x:
                            extra += 1
                            if small_count + extra >= k:
                                return True

                last_small = i
                gap_min = None
            else:
                if first_small != -1:
                    if gap_min is None or value < gap_min:
                        gap_min = value

        if small_count == 0:
            return False

        if small_count >= k:
            return True

        # The cyclic gap contains the suffix after the last small
        # element and the prefix before the first small element.
        wrap_min = None

        for i in range(last_small + 1, n):
            if wrap_min is None or w[i] < wrap_min:
                wrap_min = w[i]

        for i in range(0, first_small):
            if wrap_min is None or w[i] < wrap_min:
                wrap_min = w[i]

        if wrap_min is not None:
            if wrap_min + max(w[last_small], w[first_small]) <= x:
                extra += 1

        return small_count + extra >= k

    lo = 0
    hi = 2 * max(w)

    while lo + 1 < hi:
        mid = (lo + hi) // 2
        if feasible(mid):
            hi = mid
        else:
            lo = mid

    return hi

def main():
    n, k = map(int, input().split())
    w = list(map(int, input().split()))
    print(solve_case(n, k, w))

if __name__ == "__main__":
    main()
```の`solve_case`関数には最適化全体が含まれています。 外部二分探索では、特定の最大ペア合計が達成可能かどうかのみが尋ねられます。 

内部`feasible`、`half = x // 2`正確な条件 (2w_i\le X) を実装します。 整数の除算は意図的に行われているため、(X) が奇数の場合、(\lfloor X/2\rfloor) の値は小さいものとして分類されます。`first_small`そして`last_small`周期的ギャップの終点を特定します。`gap_min`前の小さい要素以降の最小の要素を格納します。 別の小さな要素が見つかるとすぐにギャップは完了し、最大で 1 つの大きな要素が寄与できるようになります。 

条件は以下を使用します`max(w[last_small], value)`、 ない`min`。 挿入された値は、隣接する両方の小さな値と互換性がある必要があるため、両方の不等式を満たさなければなりません。 同様に、(X-\max(a,b)) より大きくてはなりません。 

ラップアラウンド ギャップはスキャン後に個別に処理されます。 その最小値は、最後の小さな要素の後の接尾辞と最初の小さな要素の前の接頭辞の最小値です。 これは、問題の周期的な性質が通常の線形サブシーケンスと異なる唯一の場所です。 

Python の整数には任意の精度があるため、次のような合計が得られます。`2 * max(w)`オーバーフローしないでください。 二分探索では、`lo + 1 < hi`、 と`lo`実行不可能であることが知られており、`hi`これにより、off-by-one エラーが回避されます。 

## 実用的な例

 ### サンプル 1

 入力は```
5 3
17 18 17 30 35
```答えは(35)です。 最終しきい値 (X=35) では、小さい値は (2w_i\le35) を満たすため、値 (17,17) は小さく、(18,30,35) は大きくなります。 

| ポジション | 値 | 小さい？ | 現在のギャップ最小値 | 選択された数 |
 | --- | --- | --- | --- | --- |
 | 1 | 17 | はい | なし | 1 |
 | 2 | 18 | いいえ | 18 | 1 |
 | 3 | 17 | はい | 18 | 2 |
 | 4 | 30 | いいえ | 30 | 2 |
 | 5 | 35 | いいえ | 30 | 2 |
 | ラップギャップ | 30 | 候補者 | 30 | 2 |

 2 つの小さな値の間のギャップには候補 (18) があります。 その境界値は両方とも (17) であるため (18+17=35)、このギャップは使用可能になります。 巡回ギャップの最小値は (30) で、これは (30+17=47) となるため、使用できません。 

したがって、実現可能な最大選択サイズは (2+1=3) になります。 実際の部分列は (17,18,17) で、その巡回ペアの合計は (35,35,34) で、最大値は (35) になります。

```(X=20) を考えてみましょう。 小さいことのしきい値は (10) であるため、値 (10) は実際には小さいため、チェックは失敗しません。 (X=19) では、しきい値は (9) になるため、小さな要素は存在せず、チェックはすぐに false を返します。 これにより、二分探索では、実行不可能 (19) と実行可能 (23) の間の正しい遷移が得られます。これは、唯一の可能な部分列の実際の最大ペア合計です。 

十分な小さな要素がある場合、```

```(X=5) では、(2\cdot2=4\le5) であるため、小さい値は (1) と (2) ですが、(3) と (100) は大きいです。 小さな要素が 2 つしかないので、もう 1 つ必要です。 (1) と (2) の間のギャップには要素が含まれませんが、他のギャップには (3) または (100) が含まれます。 候補 (3) は (2) と互換性がありますが、間違ったギャップに配置された場合は (1) とは互換性がありません。有効な選択は、最大の巡回ペアの合計が (5) であるサブシーケンス (1,2,3) です。 スキャンはこのしきい値で正確に受け入れられます。
