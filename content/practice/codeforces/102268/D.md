 ## 解決策
 ## 問題の理解

 (t) 日ありますが、(d) 日は最大で (a_d) 日をホストできます。 各女の子は間隔 ([l_i,r_i]) と快感値 (p_i) で表されます。 彼女を選択した場合、その間隔内で正確に 1 日を彼女に割り当てる必要があり、その容量を超える日を受け取ることはできません。 

課題は、女の子のサブセットを選択し、選ばれたすべての女の子を合法的な日に割り当てて、合計の喜びができるだけ大きくなるようにすることです。 間隔は左右のエンドポイントの両方によってすでに順序付けされていますが、以下の解決策では実際にはその追加の順序付けプロパティは必要ありません。 

境界 (n,t\le 300,000) は、女の子のサブセットを考慮したもの、さらには女の子の数の 2 次を考慮したものを即座に除外します。 (300,000) 個の間隔が存在する可能性があるため、目標はおおよそ (O((n+t)\log(n+t))) になります。 喜びの値は (10^9) に達する可能性があり、選択された女の子の数は (300,000) 人になる可能性があるため、答えは約 (3\cdot10^{14}) になる可能性があります。 Python の整数はこれを自動的に処理しますが、C++ の実装には 64 ビットの整数が必要です。 

最初のエッジケースは容量がゼロです。 考慮する```
1 2
0 0
1 2 10
```女の子には空き期間はあるものの、使える日が無いので、答えは(0)です。 すべての間隔が空でないかどうかだけをチェックする実装では、彼女が誤って選択されてしまいます。 

2 番目のエッジケースは、複数の女の子が同じ 1 つのスロットをめぐって競合する場合です。```
2 1
1
1 1 10
1 1 9
```女の子は1人しか選べないので、答えは(10)になります。 すべての女の子を個別に扱う、または間隔を無視して女の子の数に対する総収容人数のみをチェックする不注意なアルゴリズムでは、両方の女の子を誤ってカウントする可能性があります。 

3 番目のエッジ ケースは、スケジュールの両端に接する包括的な境界と間隔に関するものです。```
2 2
0 1
1 1 5
1 2 4
```答えは(4)です。 最初の女の子は、容量がゼロの日 (1) のみを使用できます。 2番目の女の子は(2)の日を利用できるので、選択可能な女の子は彼女だけです。 ([l,r]) を半開区間として扱うか、実現可能性チェックで 1 つのエンドポイントを誤ってシフトすると、この答えが変わる可能性があります。 

## アプローチ

 直接的な解決策は、女の子のすべてのサブセットを列挙し、そのサブセットを日数に割り当てることができるかどうかを確認することです。 チェック自体は、日を左から右に処理し、利用可能な間隔を最も早い期限に割り当てることで、貪欲に実行できます。 これにより、女の子のあらゆる可能な選択が明示的に考慮されるため、正しい総当り方法が得られます。 

問題はサブセットの数です。 それらは (2^n) 個あるため、(O(n+t)) 個の実現可能性チェックでも (O(2^n(n+t))) 個の作業が必要になります。 (n=300,000) では、これはリモートで実現可能ではありません。 

重要な観察は、実現可能なサブセットが、任意のサブセットのコレクションよりもはるかに多くの構造を持っているということです。 毎日を、日 (d) のコピー (a_d) がある、いくつかの同一のスロットと考えてください。 女の子は、その間隔内の日に属するすべてのスロットに接続されます。 女の子のセットは、それらの女の子が個別のスロットに一致する場合にのみ実現可能です。 

二部グラフで照合できるサブセットのファミリーは、横断マトロイドです。 したがって、喜びの降順に女の子を処理し、結果として得られるセットが実行可能な場合は常に女の子を追加すると、受け入れられたセットの合計の重みは最大になります。 この貪欲なルールの背後にある交換特性が、喜びの値に対して動的プログラミングを必要としない理由です。 このマトロイドの解釈とそれに対応するホール条件の低減も、この問題に対する既知の解決策の中核です。 

実際の実装上の問題が残されています。価値の高い女の子を何人か受け入れた後、(O(\log t)) に別の間隔を挿入できるかどうかをどのようにテストできるでしょうか。 

ホールの定理が答えを与えます。 任意の日間隔 ([L,R]) について、利用可能な間隔全体が ([L,R]) に含まれる選択されたすべての女の子が、その日の定員に収まる必要があります。 したがって、選択されたセット (S) は、まさに次の場合に実行可能です。 

[
 #{[l_i,r_i]\in S\ge L,\ r_i\le R}
 \le
 \sum_{d=L}^{R}a_d
 】

 (1\le L\le R\le t) ごとに。 

しましょう

 [
 s_i=\sum_{d=1}^{i}a_d,\qquad s_0=0。 
】

 左側の端点を 1 つずらすと便利です。 (0\le i\le t) について、次のように定義します。 

[
 p_i=s_i-#{[l,r]\in S\le i}
 】

 そして

 [
 q_i=s_i-#{[l,r]\in S\le i}。 
】

 ホールコンディションはこうなります

 [
 p_i\le q_j
 】

 すべての場合 (0\le i<j\le t)。 これを確認するには、差 (q_j-p_i) は、正確に日数単位の容量 (i+1,\ldots,j) から、そこに完全に含まれる選択された間隔の数を引いたものになります。 

ここで、([l_0,r_0]) を挿入するとします。 これを追加すると、(i\ge l_0) を持つすべての (p_i) が 1 ずつ減少し、(i\ge r_0) を持つすべての (q_i) が 1 ずつ減少します。 違反する可能性のある不等式は (i<l_0) と (j\ge r_0) だけです。 他のすべての不平等は変わらないか、満たされやすくなります。 

したがって、挿入は次の場合に正確に実行可能です。 

[
 \max_{0\le i<l_0}p_i
 <
 \min_{r_0\le j\le t}q_j。 
】

 セグメント ツリーは、(p) の最大値、(q) の最小値、および遅延サフィックスの追加を維持できます。 受け入れられたすべての間隔で 2 つのサフィックス デクリメントが実行されます。1 つは (l_0) から始まる (p) で、もう 1 つは (r_0) から始まる (q) です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(2^n(n+t))) | (O(n+t)) | 遅すぎる |
 | 貪欲 + ホール条件 + セグメントツリー | (O(n\log n+n\log t+t)) | (O(n+t)) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 1 日の容量を読み取り、そのプレフィックスの合計 (s_0,s_1,\ldots,s_t) を計算します。 プレフィックスの合計により、連続するブロックの容量を 1 回の減算として表現できます。 
2. すべての女の子を喜びの少ない順に並べ替えます。 実現可能な集合はマトロイドを形成するため、最も価値のある女の子を最初に検討します。 重み付きマトロイドの貪欲定理では、各ステップで最高値の実現可能要素を受け入れると、最大重みの実現可能セットが生成されると述べています。 
3. 最初は女の子が選択されていないため、両方の配列が (p_i=q_i=s_i) を満たします。 葉がインデックス (0,\ldots,t) を表すセグメント ツリーを構築します。 各ノードは、その範囲内の最大値 (p_i) と最小値 (q_i) を、2 つの配列への保留中の追加の遅延値とともに保存します。 
4. 間隔 ([l,r]) を持つ女の子について、(0\le i<l) にわたる最大値 (p_i) と、(r\le j\le t) にわたる最小値 (q_j) をクエリします。 最初の値が 2 番目の値より厳密に小さい場合、女の子を追加できます。 女の子を追加すると、関連する (q) 値がちょうど 1 だけ減少するため、厳密な不等式が必要です。 
5. 女の子が受け入れられた場合、(i\ge l) ごとに (p_i) を 1 ずつ減らし、(i\ge r) ごとに (q_i) を 1 ずつ減らします。 どちらの操作もサフィックス範囲の加算であるため、セグメント ツリーは対数時間で処理します。 
6. 挿入が成功するたびに、女の子の喜びを答えに加えます。 実現可能性テストが失敗した場合は、セグメント ツリーを変更しないままにして、次の女の子に進みます。 

不変条件は、喜びで分類された女の子の接頭辞を処理した後、セグメント ツリーが受け入れられた女の子の (p) と (q) の値を正確に表し、それらの受け入れられた女の子が実行可能なセットを形成するということです。 選択されていない区間 ([l,r]) の場合、挿入後に偽になる可能性があるホール不等式は、(i<l) と (j\ge r) のペアだけです。 セグメント ツリーは、可能な最大値 (p_i) と可能な最小値 (q_j) を比較することによって、そのような最も強い不平等をチェックします。 したがって、受け入れられたすべての女の子は実現可能性を維持しますが、拒否されたすべての女の子を現在のセットに追加することはできません。 候補は重みを減らして処理され、実行可能なセットがマトロイドを形成するため、結果として得られるセットは最大の総合的な喜びをもたらします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from array import array

def solve():
    n, t = map(int, input().split())
    a = list(map(int, input().split()))

    girls = []
    for _ in range(n):
        l, r, p = map(int, input().split())
        girls.append((l, r, p))

    girls.sort(key=lambda x: x[2], reverse=True)

    # Prefix capacities s[0..t].
    pref = array('q', [0]) * (t + 1)
    cur = 0
    for i, x in enumerate(a, 1):
        cur += x
        pref[i] = cur

    # Segment tree over indices 0..t.
    size = 4 * (t + 1) + 5

    # Maximum p in a node.
    mxp = array('q', [0]) * size

    # Minimum q in a node.
    mnq = array('q', [0]) * size

    # Lazy suffix additions for p and q.
    lazy_p = array('i', [0]) * size
    lazy_q = array('i', [0]) * size

    def build(v, lo, hi):
        if lo == hi:
            x = pref[lo]
            mxp[v] = x
            mnq[v] = x
            return

        mid = (lo + hi) >> 1
        left = v << 1
        right = left | 1

        build(left, lo, mid)
        build(right, mid + 1, hi)

        mxp[v] = max(mxp[left], mxp[right])
        mnq[v] = min(mnq[left], mnq[right])

    def push(v):
        lp = lazy_p[v]
        lq = lazy_q[v]

        if lp:
            left = v << 1
            right = left | 1

            mxp[left] += lp
            mxp[right] += lp
            lazy_p[left] += lp
            lazy_p[right] += lp

            lazy_p[v] = 0

        if lq:
            left = v << 1
            right = left | 1

            mnq[left] += lq
            mnq[right] += lq
            lazy_q[left] += lq
            lazy_q[right] += lq

            lazy_q[v] = 0

    def max_prefix(v, lo, hi, qr):
        if hi <= qr:
            return mxp[v]

        push(v)
        mid = (lo + hi) >> 1
        left = v << 1
        right = left | 1

        if qr <= mid:
            return max_prefix(left, lo, mid, qr)

        x = maxp = mxp[left]
        y = max_prefix(right, mid + 1, hi, qr)
        return x if x > y else y

    def min_suffix(v, lo, hi, ql):
        if lo >= ql:
            return mnq[v]

        push(v)
        mid = (lo + hi) >> 1
        left = v << 1
        right = left | 1

        if ql > mid:
            return min_suffix(right, mid + 1, hi, ql)

        x = min_suffix(left, lo, mid, ql)
        y = mnq[right]
        return x if x < y else y

    def update(v, lo, hi, pl, ql):
        # No part of this segment belongs to either suffix.
        if hi < pl:
            return

        # Both suffixes fully cover this node.
        if lo >= ql:
            mxp[v] -= 1
            mnq[v] -= 1
            lazy_p[v] -= 1
            lazy_q[v] -= 1
            return

        # Only the p suffix fully covers this node.
        if lo >= pl and hi < ql:
            mxp[v] -= 1
            lazy_p[v] -= 1
            return

        if lo == hi:
            return

        # If p covers the whole node but q only covers part of it,
        # apply p here and descend for q.
        if lo >= pl:
            mxp[v] -= 1
            lazy_p[v] -= 1

        push(v)

        mid = (lo + hi) >> 1
        left = v << 1
        right = left | 1

        update(left, lo, mid, pl, ql)
        update(right, mid + 1, hi, pl, ql)

        mxp[v] = max(mxp[left], mxp[right])
        mnq[v] = min(mnq[left], mnq[right])

    build(1, 0, t)

    answer = 0

    for l, r, pleasure in girls:
        # The affected Hall inequalities have i < l and j >= r.
        left_max = max_prefix(1, 0, t, l - 1)
        right_min = min_suffix(1, 0, t, r)

        if left_max < right_min:
            answer += pleasure
            update(1, 0, t, l, r)

    return answer

if __name__ == "__main__":
    print(solve())
```の`pref`配列には、(s_0=0) を含む (s_i) が格納されます。 (0) から (t) までのインデックスを使用すると、ホール条件は (i<j) に対して自然に (p_i\le q_j) になります。 したがって、(l) で始まる女の子のクエリは正確に接頭辞 (0,\ldots,l-1) ですが、(r) で終わる彼女のクエリは接尾辞 (r,\ldots,t) になります。 

セグメントツリーストア`mxp`挿入には最大の左側 (p) が必要であるため、`mnq`挿入には最小の右側 (q) が必要になるためです。 2 つの遅延配列は、一般に 2 つのサフィックスが異なる位置で始まるため、別々です。 

の`update`関数は、1 回の走査で両方のサフィックスのデクリメントを処理します。 (l\le r) なので、2 つの更新境界はソートされた順序で発生します。 ノードは、両方のサフィックスの完全に外側にあることも、両方のサフィックスの完全に内側にあることも、(p) サフィックスのみの完全に内側にあることも、境界の 1 つをまたぐこともできます。 これにより、(O(t)) 個のデクリメントを実行するのではなく、各挿入が対数的に維持されます。 

比較には、`<`、 ない`<=`。 挿入前に最も強く影響を受ける不等式が (p_i=q_j) であると仮定します。 間隔を追加すると (q_j) が 1 つ減少するため、新しい不等式は (p_i\le q_j-1) となり、失敗します。 したがって、挿入前の等価性は、候補が拒否されなければならないことを意味します。 

Python の整数はすべてのプレフィックス容量と最終的な答えを安全に保持しますが、セグメント ツリーは`array('q')`数百万の Python 整数オブジェクトのメモリ オーバーヘッドを回避するために、大きな数値フィールドを使用します。 遅延値の範囲はおおよそ (-n) と (0) の間だけであるため、符号付き 32 ビット ストレージで十分です。 

## 実用的な例

 ### サンプル 1

 公式サンプルは、```
3 5
0 1 0 1 0
1 2 2
2 4 1
3 5 5
```プレフィックス容量は次のとおりです。 

[
 s=[0,0,1,1,2,2]。 
】

 女の子は喜びの順序で処理されます: ([3,5]) 喜び (5)、次に ([1,2]) 喜び (2)、次に ([2,4]) 喜び (1)。 

| 女の子 | (l,r) | 最大 (p_i)、(i<l) | min (q_j), (j\ge r) | 決定 | 答え |
 | --- | --- | --- | --- | --- | --- |
 | 快楽5 | 3、5 | 1 | 2 | 受け入れる | 5 |
 | 快楽2 | 1、2 | 0 | 1 | 受け入れる | 7 |
 | 喜び 1 | 2、4 | 0 | 0 | 拒否 | 7 |

 ([3,5]) を受け入れた後、インデックス (3,4,5) の (p) 値は 1 ずつ減少し、(q_5) のみが減少します。 ([1,2]) を受け入れると、(p_1,\ldots,p_5) と (q_2,\ldots,q_5) が減少します。 最後の区間 ([2,4]) では、最良の左側 (p) はすでに最小の右側 (q) と等しいため、これを挿入するとホールの条件に違反します。 

選択した女の子は、(2) 日と (4) 日にスケジュールでき、楽しみが得られます (2+5=7)。 これは、たとえ他の場所にいくらかの能力が残っているにもかかわらず、喜んで候補者 (1) を拒否しなければならない理由も示しています。

## テストケース

# Place this harness in the same file as solve().

import sys
import io

def run(inp: str) -> str:
    global input

    old_stdin = sys.stdin
    old_input = input

    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    try:
        return str(solve()).strip()
    finally:
        sys.stdin = old_stdin
        input = old_input

 ## 特殊なケース

 ### 容量ゼロ

 のために```
1 2
0 0
1 2 10
```初期のプレフィックス容量は (s=[0,0,0]) なので、(p=q=[0,0,0]) になります。 唯一の女の子の場合、左側のクエリでは (p_0=0) が得られ、右側のクエリでは (\min(q_2)=0) が得られます。 要求された厳密な不等式 (0<0) は満たされないため、女の子は拒否され、答えは (0) のままになります。 

このアルゴリズムでは、キャパシティがゼロの日に対する特別なケースは必要ありません。 これらは単に等しいプレフィックス値として表示され、ホール不等式により日付を割り当てることができないことが検出されます。 

### 複数の女の子が 1 日を競い合います

 のために```
2 1
1
1 1 10
1 1 9
```初期配列は (p=q=[0,1]) です。 (p_0=0<q_1=1) であるため、喜び (10) の女の子は受け入れられます。 サフィックスの更新により、インデックス (1) の両方の値がゼロになります。 

喜び (9) の女の子を考慮すると、テストは (p_0=0<q_1=0) となり、失敗します。 アルゴリズムは (10) を返します。これは、1 日にスロットが 1 つだけあるという事実と正確に一致します。 

### 包括的なエンドポイントと境界におけるゼロ容量

 のために```
3 3
0 1 0
1 1 5
2 2 7
1 3 6
```最高値の女の子は ([2,2]) なので、唯一使用可能な日を使用して彼女が受け入れられます。 次に ([1,3]) の女の子が考慮されますが、同じ残りの容量を争うため、追加できません。 ([1,1]) の女の子は、容量がゼロの (1) 日のみを使用できるため、これも拒否されます。 

答えは(7)です。 セグメント ツリー インデックス (0,\ldots,t) により、左側の境界 (l=1) はインデックス (0) のみを含むプレフィックスに対応し、右側の境界 (r=3) はインデックス (3) でサフィックスを開始します。 これはまさにホール定式化で必要なシフトであり、元の日間隔の 1 つずつずれた解釈を回避します。 

### 世界的には可能だが局所的には不可能な候補

 検討してください```
3 3
1 0 1
1 1 100
2 3 60
1 3 70
```最初の女の子は値 (100) を持ち、日 (1) しか使用できないため、彼女は受け入れられます。 2 人目の女の子は値 (70) を持ち、日 (1) から (3) を使用できますが、最初の受け入れ後も日 (3) を使用できるため、彼女も受け入れられます。 3 番目の女の子は値 (60) を持っており、日 (2) または (3) を使用できますが、日 (2) には容量がなく、柔軟な (70) 値の女の子には日 (3) がすでに必要です。 ホールテストでは彼女は不合格となった。 

このように、総残容量だけを確認するだけでは不十分であることがわかります。 実現可能性はその容量がどこで発生するかによって決まり、(p,q) 変換はすべての間隔ホール制約をセグメント ツリーによってクエリされる 2 つの極値に圧縮します。
