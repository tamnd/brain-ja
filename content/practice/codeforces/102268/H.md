 ## 解決策
 ## 問題の理解

 各辺にちょうど n 個の頂点を持つ 2 部グラフを構築する必要があります。 左頂点のサブセット A の場合、その近傍 N(A) は、A の少なくとも 1 つの頂点が接触するすべての右頂点で構成されます。サブセットは、実際に利用可能なものよりもさらに明確な右頂点を要求する場合に重要です。つまり、∣N(A)∣<∣A∣ を意味します。 

入力により、n (n≤20) とターゲット番号 k (0≤k<2 n) が与えられます。 左側には、空のサブセットを含めて 2 n 個のサブセットがあります。 空のサブセットは、そのサイズと近傍サイズの両方がゼロであるため、決して重要ではありません。 私たちのグラフでは、残りの 2 n −1 サブセットのうち正確に k 個をクリティカルにする必要があります。 

n≤20 という小さな値は、検証のためにサブセットの列挙が可能であることを示す強力なヒントですが、グラフを自由に探索するには十分ではありません。 n+n 頂点上の 2 部グラフには n 2 個の可能なエッジがあるため、グラフを列挙するには 2 n 2 個の可能性が必要になります。これは、n=20 の場合、すでに 2 400 個になります。 記述が多項式サイズのみを持つ直接的な構築が必要です。 

特に誤って処理されやすい境界ケースが 2 つあります。 n=1、k=0 の場合、グラフには単一のエッジが含まれている必要があります。 空ではない唯一のサブセットには隣接するものが 1 つあり、重要ではありません。 エッジを出力しない不注意な構築では、代わりに唯一のサブセットがクリティカルになります。 n=1,k=1 の場合、シングルトンの左サブセットには近傍が 0 であり重要であるため、正しいグラフにはエッジがありません。 もう 1 つのよくある間違いは、空のサブセットをクリティカルとしてカウントすることです。 決してそうではないので、非クリティカルで空でないサブセットの数は 2 n -k ではなく、2 n -1 -k になります。 

## アプローチ

 直接的なブルート フォース ソリューションでは、候補グラフを取得し、左側のすべてのサブセットを列挙できます。 各サブセットについて、その頂点をスキャンして右側の隣接頂点を収集し、2 つのカーディナリティを比較できます。 グラフが n×n の隣接行列で表される場合、O(n 2 2 n ) 回の演算が必要になります。 n=20 の場合、これはおよそ 400⋅1,048,576、つまり約 4.2×10 8 個の基本チェックに相当します。 考えられるすべてのエッジ セットを列挙してグラフ自体を検索することは、考えられるグラフが 2 n 2 個あるため、非常に困難になります。 

有益な観察は、任意のグラフが必要ないということです。 重要なサブセットを数えやすい非常に限定されたファミリーを意図的に構築することができます。 

左側の頂点を 1、…、n とし、整数を選択します

 n≧a 1 ≧a 2 ≧⋯≧a n ≧0。 

左の頂点 i を最初の a i 右の頂点に正確に接続します。 空ではないサブセット A を考え、i をその最小の左頂点とします。 シーケンス a i は増加しないため、選択された他のすべての頂点 t>i は t ≤a i になります。 したがって、すべての近傍の結合は正確に最初の a i 正しい頂点になります。 

∣N(A)∣=a i 。 

i の後には n−i 個の頂点があります。 ちょうど j 個が選択された場合、サブセットのサイズは j+1 になり、正確に次の場合は重要ではありません。 

j+1≤a i 、

 または j≤a i −1。 したがって、最小頂点が i である非臨界サブセットの数は次のようになります。 

j=0 ∑ a i −1 ( j n−i )。 

可能な最小の頂点をすべて合計すると、次のようになります。 

G= i=1 ∑ n j=0 ∑ a i －1 ( j n－i ),

 ここで、G は非クリティカルで空ではないサブセットの数です。 2 n −1 個の空ではないサブセットがあるため、次のようにする必要があります。 

Ｇ＝２ ｎ −１−ｋ。 

残りの問題は、a i をどのように選択するかです。 内和はパスカルの三角形の 1 行の接頭辞です。 n−1 から 0 までの行を処理します。行 r では、貪欲に

 ( 0 r )、( 1 r )、( 2 r )、…

 現在の剰余が十分に大きい限り。 最初の t 項を取ることは、対応する a i =t を設定することとまったく同じです。 

j=0 ∑ t−1 ( j r )。 

停止後、剰余は次の二項係数より小さくなります。 特に、それは最大でも 2 r −1 であり、これはまさに r 要素の空でないサブセットの最大数です。 同じ引数を残りの行に再帰的に適用できます。

これにより、直接 O(n 2 ) が構築されます。 重要な構造は、パスカルの三角形が、0 から 2 n -1 までのすべての可能なターゲットを表すのに十分な 2 の累乗を提供するということです。

 ## アルゴリズムのチュートリアル

 1. 非クリティカルで空ではないサブセットの必要な数を次のように計算します。 

Ｇ＝２ ｎ −１−ｋ。 

構築では重要でないサブセットが自然にカウントされるため、重要でないサブセットを処理します。 空のサブセットは 2 n −1 項によって除外されます。 
2. パスカルの三角形を行 n−1 まで構築し、次のように格納します。 

C[r][j]=( j r )。 

n≤20 であるため、通常の Python 整数で十分であり、最大値は ( 9 19 ) のみです。 
3. 最後の Pascal 行 r=n−1 から開始し、それを左頂点 1 に関連付けます。j=0,1,…,r をスキャンします。 現在の剰余 G が少なくとも C[r][j] である場合は常に、この値を減算し、左の頂点 1 から右の頂点 j+1 にエッジを追加します。 

j=0,…,t−1 を選択すると、結果として得られる左頂点 1 の近傍にはちょうど t 個の頂点が含まれます。 適切なサブセットの数に対するその寄与は、正確にはプレフィックスの合計です。 

j=0 ∑ t−1 ( j r )。 
4. 次の二項係数が大きすぎるとすぐに、この行の処理を停止し、r-1 に移動します。 次の行は左頂点 2 に対応し、同じ手順が続きます。 

この貪欲なステップが安全である理由は、可能な限り長いプレフィックスを取得した後の残りの値が、最初の未使用の二項係数よりも小さいためです。 したがって、これは確実に 2 r より小さいため、より小さいパスカル行を使用して表すことができます。 
5. 行 0 まで続けます。選択されたすべてのエッジは、1≤i,j≤n の形式 (i,j) になります。 固定された左頂点の場合、選択される右端点は常に 1,2,…,a i であるため、重複するエッジは存在しません。 
6. 選択したすべてのエッジを出力します。 構築されたグラフにはちょうど G 個の非クリティカルで空でないサブセットがあるため、残りの

 (2 n −1)−G=k

 サブセットは重要です。 

なぜそれが機能するのかは、不変条件によって要約できます。 行 n−1、n−2、…、r+1 を処理した後、すでに選択されているエッジは G から減算された量に正確に寄与し、残りのターゲットは行 r、r−1、…、0 を使用して表現できます。 行 r が処理されるとき、可能な限り長い二項プレフィックスが取得されます。 次の項を取得できない場合、剰余はその項より小さいため、残りの r 行で表現できる値の範囲全体である 2 r よりも小さくなります。 不変式は、剰余がゼロになるまで存続します。 次に、近傍引数は、選択された各プレフィックス長を、必要な数の非クリティカル サブセットに正確に変換します。 

## Python ソリューション```python
Pythonimport sysinput = sys.stdin.readline

def solve():    n, k = map(int, input().split())
    # Number of noncritical nonempty subsets we want.    need = (1 << n) - 1 - k
    # Pascal's triangle.    C = [[0] * (n + 1) for _ in range(n + 1)]    C[0][0] = 1    for i in range(1, n):        C[i][0] = C[i][i] = 1        for j in range(1, i):            C[i][j] = C[i - 1][j - 1] + C[i - 1][j]
    edges = []
    # Row r corresponds to left vertex n-r.    for r in range(n - 1, -1, -1):        left = n - r
        for j in range(r + 1):            if need >= C[r][j]:                need -= C[r][j]                edges.append((left, j + 1))            else:                break
    print(len(edges))    for u, v in edges:        print(u, v)
```変数`need`は、まだ実現されていない非クリティカルで空ではないサブセットの数です。 すべての空でないサブセットはクリティカルか非クリティカルであるため、最初は 2 n −1−k です。 

パスカル三角形は行 n−1 を通してのみ構築されます。 再帰では、貪欲分解に必要な二項係数が直接計算されます。 Python ではオーバーフローの心配はなく、固定幅言語であっても、ここでの値は 64 ビット整数としては十分に小さいです。 

外側のループの処理`r`から`n - 1`ゼロまで下げる。 対応する左頂点は次のとおりです。`n - r`、つまり、行 n−1 は頂点 1 の近傍を生成し、行 n−2 は頂点 2 の近傍を生成し、以下同様になります。 

行内では、右端の昇順にエッジが追加されます。 したがって、行が t 個のエッジを受け取る場合、それらはちょうど頂点 1,…,t の右側にあります。 これは、カウント引数に必要なプレフィックス近傍構造を与えるものです。 

の`break`も重要です。 一度`need < C[r][j]`、その行の後のすべての項は、任意の二項行に対して必ずしも大きいわけではないため、不注意な実装では、後のすべての係数が使用できないと単純に想定すべきではありません。 Here the construction specifically requires taking a prefix, so we stop at the first unavailable term. The mathematical argument guarantees that the remainder can be handled by smaller rows.

 The output contains at most 1+2+⋯+n=210 edges for n=20, so the construction is comfortably within the limits.

## テストケース

def construct(inp: str) -> str:    old_stdin = sys.stdin    sys.stdin = io.StringIO(inp)

 ## 特殊なケース

 のために`1 0`、必要な非クリティカルで空でないサブセットの数は次のとおりです。 

2 1 −1−0=1。 

唯一のパスカル係数は ( 0 0 )=1 であるため、アルゴリズムはエッジ (1,1) を追加します。 シングルトンの左サブセットには隣接するものが 1 つあり、クリティカルではないため、クリティカル サブセットはまったくゼロになります。 

のために`1 1`の場合、必要な非クリティカルで空でないサブセットの数はゼロです。 貪欲ループは何も減算できないため、エッジは出力されません。 唯一の空でないサブセットは近傍サイズが 0 でサブセット サイズが 1 であるため、重要になります。 答えには、重要なサブセットが 1 つだけ含まれています。 

のために`4 0`、非クリティカル サブセットのターゲット数は 15 です。アルゴリズムは行 3、2、1、0 のすべての係数を消費し、左側の 4 つの頂点のそれぞれに、右側の 4 つの頂点すべてを近傍として与えます。 空ではないサブセットの近傍サイズは 4 ですが、そのサイズは最大でも 4 であるため、重要なサブセットはありません。 

`4 15) の場合、非クリティカル サブセットの目標数はゼロです。 エッジがまったく選択されていません。 すべての空でないサブセットには空の近傍があるため、2 4 −1=15 の空でないサブセットのすべてが重要です。 

のために`20,2^{20}-1`の場合、アルゴリズムは再び非臨界サブセットを必要とせず、空のグラフを出力します。 空でない左サブセットはすべて近傍サイズ 0 を持つため、1,048,575 個の空でないサブセットはすべてクリティカルです。 これは、この構造が特別な場合の算術演算を行わずに k の上限を処理することも確認します。
