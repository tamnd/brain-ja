 ## 解決策
 ## 問題の理解

 最大 (10^5) 個の頂点と (10^5) 個のエッジを持つ無向グラフがあります。 使用可能な色の数 (k=1,2,\ldots,n) ごとに、隣接する頂点が異なる色を受け取る必要がある、適切な色の割り当ての数が必要です。 各答えはモジュロ (998244353) として計算されます。 

7 頂点ごとの異常な状態が重要な構造上の制限です。 接続コンポーネントに少なくとも 7 つの頂点が含まれているとします。 コンポーネントは接続されているため、1 つの頂点から開始して、ちょうど 7 つの頂点が得られるまで、すでに選択されているセットの近傍を繰り返し追加できます。 結果として得られる 7 つの頂点により、接続されたサブグラフが生成されます。 そのうちの 2 つの間には、これら 7 つの頂点のみを使用するパスが存在するため、7 つの頂点以外の頂点がペア間のすべてのパスに属することはできません。 それは与えられた条件と矛盾します。 したがって、すべての接続コンポーネントには最大 6 つの頂点があります。 

これが問題が対処可能になる理由のすべてです。 元のグラフには (10^5) 個の頂点がある可能性がありますが、色付けの問題に関連するすべての独立した部分には 6 つの頂点しかありません。 

直接の色検索は絶望的です。 (k=n=10^5) の場合、すべての代入を試すと検査されます。 

[
 n^n=(10^5)^{10^5}=10^{500000}
 】

 課題。 すべての (n) 頂点に対してサブセットベースの方法で一般的な色多項式を計算する場合でも、(n) で指数関数的な時間を必要とします。 

また、入力サイズにより、グラフ全体で負荷の高い作業を繰り返し実行するアルゴリズムも排除されます。 (10^5) 個の頂点とエッジの線形または線形に近いスキャンは問題ありませんが、(O(n^2)) はすでにおおよそ (10^{10}) 個の操作を意味します。 したがって、有用な指数関数的な仕事は、(n) ではなく、定数 6 のみに依存する必要があります。 

誤って対処しやすい特殊なケースがいくつかあります。 2 つの頂点が 1 つのエッジで結合されている場合、答えは (0,2) になります。これは、1 つの色ではエッジを適切に色付けできず、2 つの色ではどのエンドポイントがどの色を受け取るかについて 2 つの選択肢が与えられるためです。```

 】

## アプローチ

 ブルート フォースは、(k) 色のいずれかをすべての頂点に割り当て、割り当てが完了した後にすべてのエッジをチェックすることから始まります。 これは正しいです。考えられるすべての色が 1 回だけ表示されますが、(k=n=10^5) の場合は (10^{500000}) の割り当てが検査されます。 このアプローチの基本的な指数関数的な性質を変える有用な枝刈りはありません。 

有用な観察は、7 つの頂点条件により、すべての接続コンポーネントに最大 6 つの頂点が含まれるように強制されるということです。 異なる連結成分の適切な色付けには相互作用がないため、成分が (G_1,G_2,\ldots,G_s) である場合、それらの色多項式は次の条件を満たします。 

[
 P_G(k)=\prod_{i=1}^{s}P_{G_i}(k)。 
】

 したがって、コンポーネントごとに小さな問題を解決するだけで済みます。 

(t\le6) 個の頂点を持つコンポーネントの場合、その頂点をカラー クラスに分割することを検討します。 カラー クラスは、独立したセットである場合にのみ有効です。 コンポーネントを (S_r) の方法で (r) 個の独立したセットに分割できる場合、それらの (r) セットに (r) 異なる色を割り当てることができます。 

[
 (k)_r=r!\binom{k}{r}
 】

 方法。 その結果、

 [
 P_G(k)=\sum_{r=1}^{t} S_r(k)_r。 
】

 すべての設定されたパーティションを直接列挙できます。 6 つのラベル付き頂点のセット パーティションは (B_6=203) のみであるため、これは任意のカラーリングを列挙するよりもはるかに小さくなります。 ブロックが独立しているパーティションのみをカウントします。 

2 番目の一定サイズの観測があります。 6 つの頂点には多くのラベル付きグラフがありますが、6 つの頂点に接続されたグラフ間には異なる色多項式は 50 個しかなく、コンポーネント サイズ 1 ～ 6 全体で対応するカウントは (1,1,2,5,14,50) です。 したがって、発生する可能性のある異なる成分の色多項式は最大 73 個あります。 

同じ多項式を持つコンポーネントをグループ化します。 特定の多項式 (f(k)) が (c) 回出現する場合、その合計寄与は (f(k)^c) になります。 すべてのコンポーネントを (k) ごとに個別に処理する代わりに、それぞれの個別の多項式を 1 回処理し、その値を多重度に引き上げます。 

以下の実装は、Python をさらに一歩進めたものです。 すべての成分多項式の次数は最大 6 であるため、連続する整数の値は加算のみを使用して有限差分で生成できます。 これにより、(k) と多項式タイプのペアごとに 6 つの二項係数を評価する必要がなくなります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (k=n) の場合 (O(n^n m)) | (O(n+m)) | 遅すぎる |
 | 最適 | (O(n+m+3^6n+nT\log n)), (T\le73) | (O(n+m)) | 承認済み |

 (3^6) という用語は、一般的な小さなコンポーネントのサブセットの作業を表しますが、ここでの実装ではセット パーティションを使用するため、実際にはコンポーネントごとに最大でも数百の状態を探索します。 (T\le73) 境界は、最大 6 つの頂点を持つ接続されたグラフの可能な色多項式の有限集合から得られます。 

## アルゴリズムのチュートリアル

1. 隣接リストを作成し、DFS または BFS を使用してすべての接続コンポーネントを検索します。 上記の構造的な議論により、検出されたすべてのコンポーネントの頂点が最大 6 つであることが保証されるため、その内部隣接性をビットマスクで安全に表現できます。 
2. 1 つのコンポーネントの頂点のラベルを (0) から (t-1) に再ラベルし、すべてのローカル頂点に対して、その近傍を含む (t) ビット マスクを保存します。 ビットマスクは、「この頂点をこのカラー クラスに入れることができるか?」という疑問を生じさせます。 単一のビット単位の AND 演算。 
3. コンポーネント頂点のすべてのパーティションをブロックに列挙します。 頂点を昇順に処理します。 現在の頂点については、頂点がすべて隣接していない既存のブロックに挿入するか、新しいブロックを作成します。 頂点を固定順序で処理すると、すべてのセット パーティションが 1 回だけ表示されます。 
4. (S_r) を、正確に (r) 個の独立したブロックに分割する有効なパーティションの数とする。 これに (r!) を掛けて (\binom{k}{r}) の係数に変換します。 結果として得られるベクトルは、コンポーネントの色彩多項式を一意に記述します。 
5. この係数ベクトルを辞書に保存し、各ベクトルを持つコンポーネントの数を数えます。 同じベクトルを持つコンポーネントは、すべて (k) について正確に同じ数の適切なカラーリングを持つため、安全にグループ化できます。 
6. 個別の多項式ごとに、まず (k=0,1,\ldots,t) でその値を計算します。 これらの (t+1) 値は、次数 (t) 多項式を完全に決定します。 すべての差分次数の最初の値を保持して、有限差分テーブルを構築します。 
7. (k=1,2,\ldots,n) の多項式値を連続的に生成します。 現在の差分配列が (\Delta^0f,\Delta^1f,\ldots,\Delta^tf) の場合、(k) から (k+1) に進むことは、各差分を次のものに下位から上位に加算することによって行われます。 最初のエントリが (f) の新しい値になります。 
8. (k) ごとのグローバルな答えに、この多項式で表される成分の数まで累乗された現在の多項式値を掛けます。 指数は型の多重度であるため、等しいコンポーネントのコレクション全体が一度に処理されます。 
9. (k=1) から (n) までの結果の値を出力します。 すべての算術はモジュロ (998244353) で実行されます。 

### なぜ効果があるのか

 すべての連結コンポーネントについて、再帰的パーティショニングは、そのブロックが同じ色を受け取ることができるパーティションを正確に列挙します。 (r) 個の独立したブロックへの分割は、それらのブロックへの個別の色の割り当て (r!\binom{k}{r}) に正確に対応します。 したがって、計算された小さな多項式は、まさにコンポーネントの色多項式になります。 

異なる接続コンポーネント間にはエッジがないため、それらのカラーリングを個別に選択できます。 したがって、それらの色多項式は乗算されます。 等成分多項式のグループ化は、繰り返しの乗算を累乗で置き換えるだけであり、積は変更されません。 

有限差分位相は多項式を近似しません。 最大 6 次の多項式は 7 つの連続する値によって完全に決定され、その 7 番目の差分はゼロになります。 差分テーブルを進めると、後続のすべての整数で正確な値が再現されます。 したがって、最終的な答えに乗算されるすべての値は、そのコンポーネント タイプによってもたらされる色の正確な数になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def component_signature(adj_masks):
    """Return coefficients c[r-1] such that
       P(k) = sum_{r=1}^t c[r-1] * C(k, r).
    """
    t = len(adj_masks)
    ways = [0] * (t + 1)
    blocks = []

    def dfs(v):
        if v == t:
            ways[len(blocks)] += 1
            return

        bit = 1 << v
        forbidden = adj_masks[v]

        for i in range(len(blocks)):
            block = blocks[i]
            if forbidden & block == 0:
                blocks[i] = block | bit
                dfs(v + 1)
                blocks[i] = block

        blocks.append(bit)
        dfs(v + 1)
        blocks.pop()

    dfs(0)

    res = [0] * t
    fact = 1
    for r in range(1, t + 1):
        fact = fact * r % MOD
        res[r - 1] = ways[r] * fact % MOD

    return tuple(res)

def component_values(signature, n):
    """Generate P(1), P(2), ..., P(n) using finite differences."""
    t = len(signature)

    # Evaluate at k = 0, 1, ..., t.
    initial = []
    for k in range(t + 1):
        comb = 1
        value = 0
        for r in range(1, t + 1):
            comb = comb * (k - r + 1) % MOD
            comb = comb * pow(r, MOD - 2, MOD) % MOD
            value = (value + signature[r - 1] * comb) % MOD
        initial.append(value)

    # Build the first element of every finite-difference row.
    diff = initial[:]
    first = [diff[0]]
    for length in range(t, 0, -1):
        diff = [(diff[i + 1] - diff[i]) % MOD for i in range(length)]
        first.append(diff[0])

    # first[j] = Delta^j f(0).
    cur = first
    values = [0] * n

    for k in range(n):
        # Advance from x=k to x=k+1.
        for j in range(t):
            cur[j] = (cur[j] + cur[j + 1]) % MOD
        values[k] = cur[0]

    return values

def solve():
    n, m = map(int, input().split())

    graph = [[] for _ in range(n)]
    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        graph[u].append(v)
        graph[v].append(u)

    seen = [False] * n
    pos = [-1] * n
    types = {}

    for start in range(n):
        if seen[start]:
            continue

        stack = [start]
        seen[start] = True
        vertices = []

        while stack:
            u = stack.pop()
            vertices.append(u)
            for v in graph[u]:
                if not seen[v]:
                    seen[v] = True
                    stack.append(v)

        t = len(vertices)

        # The input guarantee implies t <= 6.
        for i, v in enumerate(vertices):
            pos[v] = i

        masks = [0] * t
        for i, u in enumerate(vertices):
            mask = 0
            for v in graph[u]:
                mask |= 1 << pos[v]
            masks[i] = mask

        signature = component_signature(masks)
        types[signature] = types.get(signature, 0) + 1

    answer = [1] * n

    for signature, count in types.items():
        values = component_values(signature, n)

        if count == 1:
            for i, value in enumerate(values):
                answer[i] = answer[i] * value % MOD
        elif count == 2:
            for i, value in enumerate(values):
                answer[i] = answer[i] * value * value % MOD
        elif count == 3:
            for i, value in enumerate(values):
                answer[i] = answer[i] * value * value % MOD
                answer[i] = answer[i] * value % MOD
        else:
            for i, value in enumerate(values):
                answer[i] = answer[i] * pow(value, count, MOD) % MOD

    print(*answer)

if __name__ == "__main__":
    solve()
```入力セクションはグラフを隣接リストとして保存し、スタックが線形時間で接続成分を見つけます。 すべての有効なコンポーネントには最大 6 つの頂点があるため、大規模な補助構造なしでローカル グラフをビットマスクに変換できます。 

の`component_signature`ルーチンは、小さなグラフ計算の中核です。 の`blocks`配列には、現在構築されているカラー クラスが含まれます。 頂点(v)をブロックに挿入すると、`adj_masks[v] & block`エッジにそのカラー クラスの両方の端点があるかどうかを確認します。 結果がゼロの場合は、ブロックが独立したままであることを意味します。 

再帰では、順序付けされていないパーティションがカウントされます。 これは意図的なものです。 (r) ブロックへの分割は、(r!\binom{k}{r}) ラベル付きの色の割り当てに対応します。これがまさにコードが乗算される理由です。`ways[r]`による`r!`。 

の`component_values`関数は結果の表現を使用します

 [
 P(k)=\sum_{r=1}^{t} c_r\binom{k}{r}。 
】

 小規模な初期評価では、二項係数の漸化式が使用されます。 (t\le6) なので、この作品は一定のサイズです。 後続の値は有限差分によって生成され、色数ごとに多項式評価を繰り返すことを回避します。 

べき乗セクションは、各多項式タイプの多重度を処理します。 多重度 1、2、および 3 の特殊なケースでは、最も一般的な小さなカウントに対するべき乗剰余への関数呼び出しが回避されます。 多重度が大きい場合は、Python の組み込み`pow(a,b,MOD)`最適化されたネイティブ コードでべき乗剰余演算を実行します。 

すべての値は減算法 (998244353) です。 Python の整数はオーバーフローしませんが、乗算後に値を減らしたままにすることで、値が不必要に大きくなるのを防ぎます。 

## 実用的な例

def run_captured(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

        sys.stdout = io.StringIO()
        solve()
        return sys.stdout.getvalue().strip()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

 ## 特殊なケース

 2 頂点グラフ```
2 1

```2 つの頂点を持つ 1 つの連結コンポーネントがあります。 その唯一の適切な分割は 2 つのシングルトン カラー クラスへの分割であるため、その多項式は (2\binom{k}{2}=k(k-1)) となります。 アルゴリズムは署名を記録します`(0, 2)`、(k=1,2) で評価し、次の値を取得します。`0 2`。 

6 頂点クリークの場合、各カラー クラスには頂点を 1 つだけ含めることができます。 パーティションの再帰は、6 つのシングルトン ブロックを含む 1 つの有効なパーティションに到達します。 (\binom{k}{6}) の係数は (6!=720) であるため、多項式は (720\binom{k}{6}) となります。 これにより、(k<6) の場合は 0、(k=6) の場合は (720) が得られ、ブロック数に関するループが誤って (t-1) で停止するエラーが検出されます。 

サンプル グラフでは、三角形と孤立した頂点が 3 つの接続されたコンポーネントとして検出されます。 三角形は (k(k-1)(k-2)) に寄与し、各シングルトンは (k) に寄与します。 したがって、大域積は (k^3(k-1)(k-2)) となります。 これは、一部のコンポーネントが小さいという理由だけでグラフ全体を 1 つの小さなコンポーネントとして扱うというよくある間違いを捉えています。 

最大サイズのテストにおける 50,000 の互いに素なエッジなど、多くの同一コンポーネントでは、すべてのコンポーネントが同じ署名を生成します。 辞書はそれらすべてを多重度 50,000 の 1 つのエントリに削減します。 色数 (k) の答えは ((k(k-1))^{50000}) となります。 これは、グループ化が不可欠になるケースです。すべてのエッジを (k) ごとに個別に処理するには、おおよそ (5\cdot10^9) 個のコンポーネント評価が必要になるためです。 

条件自体は、アルゴリズムにとって重要な方向にのみ使用されます。 有効な入力には、7 つ以上の頂点を持つ連結コンポーネントを含めることはできません。 このアルゴリズムはその逆を必要とせず、7 つの頂点条件を検証しようとしません。 この保証は問題によって提供される構造的な約束であり、実装がテストする必要がある条件ではないため、この区別は重要です。
