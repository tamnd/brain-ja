 ## 問題の理解

 2 つの整数配列を構築する必要があります`a`そして`b`その値は 2 つの異なる順列に従って順序付けされます。 順列`p`の値の非減少順序を決定します。`a`、 その間`q`の値の非減少順序を決定します。`b`。 

インデックス用`i < j`、このペアは次の場合にクールです`a[i] + b[j] < 0`。 課題は正確に作ることです`k`そんなペアたち。 値は次の範囲内にある必要があります`-n`そして`n`。 

制約は大きく、`n`まで`300000`ので、すべてチェックしてください`O(n^2)`ペアは無理です。 最大サイズでは約`4.5 * 10^10`2 秒の制限をはるかに超えたペアの可能性があります。 稼働時間がせいぜいおおよそである建設が必要です`O(n log n)`、理想的には線形に近いです。 

不可能な価値はありません`k`。 からのすべての整数`0`を通して`n(n-1)/2`は以下の構成で実現できるので、答えは常に`Yes`。 元の問題では、まさにこれらの境界と順序付け条件が使用されています。 

最初のエッジケースは`n = 1`。 唯一可能な値は次のとおりです`k = 0`とのペアがないため、`i < j`。 例えば、```
1 0
1
1
```生産しなければならない`Yes`、 ない`No`。 少なくとも 1 つのペアが存在することを前提としたソリューションは、ここで誤って失敗する可能性があります。 

2 番目のエッジケースは、`k = 0`。 例えば、```
3 0
1 2 3
1 2 3
```すべてのペアがクールではないことが必要です。 ポジティブな解決策を構築するだけでは十分ではありません`k`そして、初期化されていない境界値を残します。 この構造では、ターゲットがゼロに達した後、クールなペアの作成を意図的に停止します。 

3 番目のエッジ ケースは可能な最大値です。```
3 3
1 2 3
1 2 3
```3 つのペアのすべてがクールでなければなりません。 構築では、すべての関連性を考慮してこれを処理します。`b`ゼロとすべてに等しい値`a`値は負です。 を使用する不注意な実装`<= 0`必須の厳密な不等式の代わりに、誤った境界決定が行われる可能性もあります。 

4 番目のエッジ ケースは、ターゲットが 1 つのポジションの寄与の範囲内に厳密に含まれる場合です。 例えば、```
4 5

4 3 2 1
```途中で止めなければならない`q`位置。 それぞれを割り当てるだけで、`b`どちらか`0`または`n`特定の合計のみを生成できます。 部分的な代入により、欠損値が得られます。 

## アプローチ

 直接的なアプローチは、値を割り当てようとすることです。`a`そして`b`、次にすべてのペアを数えます`(i,j)`と`i < j`そして`a[i] + b[j] < 0`。 配列がすでに構築されている場合でも、この方法で答えを確認するには時間がかかります`O(n^2)`操作。 のために`n = 300000`、それは約です`4.5 * 10^10`ペアチェックなので、受け入れられたアルゴリズムの一部にすることはできません。 

有益な観察は、任意の配列を検索する必要がないことです。 意図的に次の値を作成できます。`a`すべてが明確で否定的です。 置く`a[p_t] = t - 1 - n`。 

したがって、それに沿って、`p`、値は正確に`-n, -n+1, ..., -1`, したがって、必要な注文は自動的に行われます。 

ここで 1 つの固定インデックスを考えてみましょう`j`そして推測してください`b[j] = 0`。 以来、`a[i]`すべてのインデックスが負です`i < j`～とクールなペアを形成します`j`。 その貢献はまさに`j - 1`。 

反対の極端な場合、`b[j] = n`、 それから`a[i] + b[j] >= 0`あらゆる人にとって`i`、 なぜなら`a[i] >= -n`。 その貢献度はゼロです。 

これにより、ターゲットを消費する便利な方法が得られます`k`。 で指定された順序でポジションを処理します。`q`。 現在のポジションについて`x = q_t`、割り当て`b[x] = 0`まさに貢献する`x - 1`。 残りのターゲットが少なくとも`x - 1`、それらのペアをすべて取得します。 

最終的には、残りのターゲットが配置される最初の位置が存在します。`r`よりも小さいです`x - 1`。 その時点で、私たちが正確に必要とするのは、`r`の`x - 1`考えられるペア`x`。 価値観以来、`a[1], ..., a[x-1]`区別されている場合は、それらを並べ替えます。 もし`c`ソートされたリスト、設定ですか`b[x] = -c[r]`ゼロベースのインデックスを使用すると、正確に`r`それらの値のうち満たすもの`a[i] + b[x] < 0`。 

そのポジションの後は、残りすべての`b`できる`n`、貢献度はゼロです。 

割り当てでは、必要な順序も保持されます。`b`。 部分位置の前の値は次のとおりです。`0`。 At the partial position,`b[x]`の間にあります`1`そして`n`。 その後の値は`n`。 したがって、それに沿って`q`シーケンスは非減少です。 

この構造は、この問題の公開されたソリューションで使用されている中心的なアイデアと同じです。つまり、一方の配列を厳密に順序付けし、もう一方の配列の部分的に割り当てられた単一の位置を使用して最終的な剰余を実現します。

 ## アルゴリズムのチュートリアル

 1.作成`a`によると`p`設定により`a[p[t]] = t - n - 1`1ベースの場合`t`。 結果の値は次のとおりです。`-n, -n+1, ..., -1`、 それで`a`に沿って厳密に増加しています`p`すべての値が許容範囲内にあります。 
2. 初期設定間隔`b[i] = n`。 このような値ではクールなペアは作成されません。`a[i] + n >= 0`。 
3. の要素を処理します。`q`左から右へ。 現在の要素を次のようにします`x = q[t]`。 設定すると`b[x] = 0`、次にすべてのインデックス`i < x`クールです`x`、正確に与える`x - 1`新しいペア。 
4. 残りのターゲットの場合`k`少なくとも`x - 1`、 セット`b[x] = 0`そして引きます`x - 1`から`k`。 これにより、このポジションで利用可能な貢献が完全に使用されます。 
5. それ以外の場合、残りの目標は満たされます。`0 <= k < x - 1`。 価値観を考慮する`a[1], ..., a[x-1]`そしてそれらを次のようにどんどん並べ替えます`c`。 セット`b[x] = -c[k]`、ゼロベースのインデックスを使用します。 まさに最初の`k`の値`c`より厳密に小さい`c[k]`、まさにそのとおりです`k`インデックス`i < x`満足する`a[i] + b[x] < 0`。 
6. 遅めに出発`b[q[t]]`に等しい`n`。 これらは何も貢献しないため、クールなペアの総数は変わりません。 
7. 出力`Yes`、 に続く`a`そして`b`。 すべてのポジションの合計能力は次のとおりであるため、この時点までに目標はゼロに達しているはずです`1 + 2 + ... + (n-1) = n(n-1)/2`、これは許容される最大値です`k`。 

### なぜ効果があるのか

 不変条件は、次のプレフィックスを処理した後、`q`、すでに割り当てられているポジションは、消費された元のターゲットの量に正確に寄与しますが、未処理のポジションはすべてゼロです。 全額寄付の場合`x-1`ゼロを代入して当てはめます`b[x]`ちょうどその数のペアを消費します。 適合しない場合、`a[1..x-1]`から正確に任意の数字を選択しましょう`0`を通して`x-2`適切なしきい値を選択することによって。 それ以降の値はすべて`b`は`n`、これ以降のペアはクールになることはできません。 したがって、クール ペアの最終的な数は要求されたとおりになります。`k`。 

順序付けの制約は構築からも同様に発生します。 の値`a`厳密に増加します`p`。 の値`b`平行`q`形式はゼロで、場合によっては 1 つの値が含まれます。`[1,n]`、 それから`n`s なので、減少していません。 割り当てられたすべての値は次のとおりです。`[-n,n]`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    p = list(map(int, input().split()))
    q = list(map(int, input().split()))

    a = [0] * (n + 1)
    b = [n] * (n + 1)

    # Along p, a contains -n, -n+1, ..., -1.
    for pos, x in enumerate(p):
        a[x] = pos - n

    remaining = k

    for x in q:
        full = x - 1

        if full <= remaining:
            # b[x] = 0 makes every i < x cool.
            b[x] = 0
            remaining -= full
        else:
            # Need exactly 'remaining' cool pairs ending at x.
            # a[1..x-1] are all distinct.
            values = sorted(a[1:x])

            # values[remaining] is the (remaining + 1)-st
            # smallest value. Exactly 'remaining' values are smaller.
            b[x] = -values[remaining]

            remaining = 0
            break

    print("Yes")
    print(*a[1:])
    print(*b[1:])

if __name__ == "__main__":
    solve()
```最初のループは、次の固定構造を確立します。`a`。 ゼロベースの場合`pos`、課題`pos - n`生成する`-n`の最初の要素に対して`p`そして`-1`最後に。 

2 番目のループは貪欲なプロセスを実装します。 変数`remaining`まだ必要なクール ペアの数です。 いつ`x - 1 <= remaining`、設定`b[x]`で終わるすべてのペアを使用するため、ゼロに設定しても安全です。`x`。 

ソートが必要となるのは部分的なケースだけです。 スライス`a[1:x]`より小さいインデックスに属する値が正確に含まれます。`x`。 なぜなら、すべての値は、`a`明確であり、`values[remaining]`まさに`remaining`より小さな要素。 これを否定すると、厳密な不等式に対する正しいしきい値が得られます。 

表現`values[remaining]`それよりも`values[remaining - 1]`1 点違いが一般的です。 もし`remaining = 0`の値は必要ありません。`a[1:x]`不等式を満たすため、最小値を選択し、ゼロ要素を選択するほど不等式を厳密にします。 

課題`b[x] = -values[remaining]`は常に許容範囲内にあります。`a`価値があるのは`[-n,-1]`したがって、その否定は次のとおりです。`[1,n]`。 

Python の整数には任意の精度があるため、大きな値になる可能性があります。`n(n-1)/2`オーバーフローしません。 入力は次のように読み取られます`sys.stdin.readline`大型の場合に必要な`n`。
