 ## 解決策
 ## 問題の理解

 英語の小文字の文字列が与えられます。 できるだけ多くの連続した部分にカットしたいと考えています。 単語は、少なくとも 1 つの母音と少なくとも 1 つの子音が含まれている場合にのみ有効な単語とみなされます。 出力は、文字列全体をカバーできる有効な部分の最大数です。 有効なピースが 1 つでも形成できない場合、答えはゼロです。 

重要な文字のプロパティはそのタイプだけです。 文字は母音のいずれかです`a, i, o, u, e, y`、または子音です。 パーティションを構築するには文字の位置が重要ですが、可能な部分の数は、存在する母音と子音の数によってのみ決まります。 

文字列の長さは次のとおりです$10^5$。 これにより、パーティションの数が指数関数的に増加するため、考えられるカット位置のすべてのセットを試すことができなくなります。 たとえ$O(n^2)$動的計画法は不必要であり、単純な線形スキャンに比べて遅すぎます。 意図したソリューションでは、すべての文字を一定の回数検査して、$O(n)$アルゴリズム。 

最初のエッジ ケースは、文字列に 1 種類の文字のみが含まれる場合です。 例えば：```
Input:
3
aaa

Output:
0
```母音はありますが子音が存在しないため、有効な単語は存在できません。 母音だけを数えて何かで割るという解決策では、誤って肯定的な答えが生成されてしまいます。 

もう 1 つのエッジ ケースは、一方の型の数が他方の型よりもはるかに小さい場合です。```
Input:
7
aaabbbb

Output:
3
```母音が 3 つ、子音が 4 つあります。 有効な単語を 3 つ作成できますが、すべての単語に母音が必要なため、4 つを作成することはできません。 リソースを制限するのは、より小さい数です。 

最後の境界ケースは、両方のタイプが 1 回だけ出現する場合です。```
Input:
2
ab

Output:
1
```文字列全体がすでに 1 つの有効な単語になっています。 あらゆる可能な位置で分割しようとすると、無効な 1 文字の部分が作成されてしまいます。 

## アプローチ

 自然な総当たりアプローチは、文字列の可能なすべての分割を試し、結果のすべての部分に母音と子音の両方が含まれているかどうかを確認することです。 これは、考えられるすべての答えを検査するので正しいですが、ある長さの文字列の分割数は検査されません。$n$は$2^{n-1}$隣接する文字間のすべてのギャップには、カットが含まれる場合と含まれない場合があるためです。 のために$n=10^5$、これはまったく不可能です。 

より良い試みは、左から右に貪欲に単語を構築することです。 ただし、重要な点は、実際にはカットの正確な位置を気にする必要はないということです。 すべての有効な単語は、少なくとも 1 つの母音と少なくとも 1 つの子音を使用します。 あれば$v$母音と$c$子音、これ以上のものを含むソリューションはありません$\min(v,c)$各単語には両方のグループの 1 文字が必要であるためです。 

残りの問題は、この上限を常に達成できるかどうかです。 母音と子音の両方が存在する場合、元の順序を維持しながら、希少なタイプを他のタイプの文字と繰り返しペアにすることができます。 より一般的なタイプの追加文字は、既存の単語に単純に付加できます。 これは、母音が制限リソースである場合、利用可能なすべての母音が別の単語に参加できることを意味し、子音が少ない場合にも同じ議論が機能します。 

したがって、問題は 2 つの文字カテゴリを数えるということになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 文字列内に出現する母音の数と、文字列内に出現する子音の数を数えます。 すべての単語には少なくとも各カテゴリの 1 文字が必要であるため、答えはこれら 2 つの量にのみ依存します。 
2. どちらかのカウントがゼロの場合、出力`0`。 有効な単語には両方のタイプが必要であるため、文字列を分割することはできません。 
3. それ以外の場合は、2 つのカウントのうち小さい方を出力します。 各単語は 1 つの母音と 1 つの子音を使用するため、これが可能な最大単語数です。 

なぜ効果があるのか:

 単語の最大数は、母音の数または子音の数を超えることはできません。$\min(v,c)$。 両方のカテゴリが存在する場合、小さいグループには単語ごとに 1 文字を分配できますが、大きいグループの残りのすべての文字は無効にすることなくこれらの単語に配置できます。 したがって、上限は常に達成可能であり、答えは正確に次のようになります。$\min(v,c)$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    s = input().strip()

    vowels = set("aiouey")
    v = 0
    c = 0

    for ch in s:
        if ch in vowels:
            v += 1
        else:
            c += 1

    if v == 0 or c == 0:
        print(0)
    else:
        print(min(v, c))

if __name__ == "__main__":
    solve()
```すべての文字分類は同じ操作であるため、コードは最初に母音セットを保存します。 スキャン中に、2 つのカウンタのうち 1 つがインクリメントされます。 最終的な答えは 2 つの合計によって完全に決定されるため、位置に関する情報を保存する必要はありません。 

条件`v == 0 or c == 0`不可能なケースを直接処理します。 決勝戦`min(v, c)`小さいカテゴリが唯一の制限要因であることが証明で示されているため、安全です。 

インデックス付け操作やネストされたループがないため、境界の問題やオフバイワンのケースはありません。 Python の整数もオーバーフローの問題を回避しますが、カウンターは最大でも$10^5$。

## 特殊なケース

 次のような母音のみを含む文字列の場合:```
3
aaa
```アルゴリズムが重要`v = 3`そして`c = 0`。 子音が存在しないため、ゼロチェックがトリガーされ、出力は次のようになります。`0`。 

子音のみを含む文字列の場合:```
4
bbbb
```カウンターはこうなる`v = 0`そして`c = 4`。 繰り返しますが、有効な単語には必須のカテゴリを両方含めることはできないため、答えは次のようになります。`0`。 

1 つのカテゴリが小さい文字列の場合:```
7
aaabbbb
```スキャンでは 3 つの母音と 4 つの子音が見つかります。 答えは`min(3, 4) = 3`。 3 つの単語はそれぞれ 1 つの母音と 1 つの子音を受け取ることができ、残りの子音はそれらの単語の 1 つに追加されます。 

最小の混合ケースの場合:```
2
ab
```カウントは母音 1 つと子音 1 つです。 アルゴリズムは戻ります`1`、唯一可能なパーティションと一致します。
