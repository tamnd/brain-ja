 ## 解決策
 ## 問題の理解

 並んでいます`n`正方形のセル。 これらの細胞の間および周囲には、`n + 1`各境界線には色を付けることも、色を付けないままにすることもできます。 セルはその直前の境界線とその直後の境界線に接しています。 すべてのセルについて、その 2 つの境界線のうち何個を色付けする必要があるかが正確に通知されます。`0`、`1`、 または`2`。 タスクは、すべてのセルを満たす境界線の色が存在するかどうかを判断することです。 

入力はシーケンスです`a`、 どこ`a[i]`に必要な色付きの側面の数を示します。`i`- 番目のセル。 出力は、`n + 1`国境国家が存在する。 

制約`n <= 100000`つまり、考えられるすべての境界線の色を試すことはできません。 がある`n + 1`それぞれの境界には 2 つの可能な州があるため、総当たり検索で調べられます。`2^(n+1)`数十個の細胞であっても不可能になる可能性があります。 このソリューションでは、配列を線形時間で処理する必要があります。 

厄介なケースは、隣接するセルが境界線を共有しているという事実によって引き起こされます。 1 つのセルに対して行われた選択は、すぐに次のセルに影響します。 

たとえば、1 つのセルの場合:```
Input:
1
0

Output:
Yes
```両方の外側の境界線は色付けされないままにすることができるため、答えは可能です。 すべてのセルに色付きの境界線が必要であると想定するソリューションは、ここでは失敗します。 

別の境界ケースは次のとおりです。```
Input:
2
2 0

Output:
No
```最初のセルでは、両方の境界線に色を付ける必要があります。 つまり、2 つのセル間の共有境界線が色付きになります。 2 番目のセルにはすでに 1 つの色付き境界線があるため、色付き境界線を 0 つで終了することはできません。 矛盾は共有境界から生じます。 

3 番目のよくある間違いは、長時間実行すると発生します。`1`s. 例えば：```
Input:
3
1 1 1

Output:
Yes
```境界線は色付きと無色を交互に切り替えることができます。 常に同じ側を選択する貪欲な方法`1`結局行き詰まってしまう。 

## アプローチ

 直接的なアプローチは、すべての境界の状態を 1 つずつ決定することです。 すべての境界線はバイナリであるため、可能な割り当てをすべて試して、各セルが必要な数の色付きの辺を受け取るかどうかを確認できます。 考えられるすべてのカラーリングが考慮されているため、これは正しいです。 ただし、`n + 1`国境、与える`2^(n+1)`課題。 と`n = 100000`、これは時間制限をはるかに超えています。 

重要な点は、これは実際にはグローバル検索の問題ではないということです。 セルはラインを形成し、各セルは 2 つの隣接する境界線のみに依存します。 セルには固定の合計数の色付き境界線が必要であるため、セルの左境界線が判明すると、右境界線が強制的に設定されます。 

境界線をセルの前に置く`i`なれ`x[i-1]`そしてその後の国境`x[i]`。 条件は次のとおりです。```
x[i-1] + x[i] = a[i]
```私たちが選ぶなら`x[0]`、以降のすべての境界値が決定されます。 最初の境界線は次のとおりです。`0`または`1`、確認できるパスは 2 つだけです。 

選択した開始値について、左から右に移動します。 各セルの次の境界線は次のとおりです。```
next_border = required - current_border
```この値がそうでない場合は、`0`または`1`、現在の選択は不可能です。 すべてのセルを処理した後、最終境界値もシーケンスの一部として生成されるため、自動的に有効になります。 

ブルートフォース手法はすべての境界線の組み合わせを探索するため失敗します。 配列の構造により、選択肢は 2 つの可能な開始状態のみに減ります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n * n) | O(n) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 左端の境界線の最初の可能な色を試します。 どちらでも構いません`0`または`1`。 この選択の後に全体の順序が決定されるため、両方の可能性をチェックするだけで十分です。 
2. 現在の左枠の色を保存しながら、セルを左から右にスキャンします。 現在のセルについて、必要な値を満たすために必要な右の境界線を計算します。 
3. 計算された右枠が正しくない場合`0`または`1`、この開始選択を拒否します。 境界線を部分的に色付けしたり、他の状態にすることはできません。 
4. それ以外の場合は、この新しく計算された境界線を左境界線として使用して、次のセルに移動します。 
5. いずれかの開始選択が正常に終了に到達した場合、出力します。`Yes`。 どちらの選択も失敗した場合は、印刷します`No`。 

なぜ効果があるのか:

 スキャン中に不変なのは、セルを処理する前に、保存されている境界線の値が、そのセルの左側に選択された色とまったく同じであるということです。 アルゴリズムは、セルを満たすことができる右側の唯一の可能な値を計算します。 その値が無効な場合、両側がすでにバイナリ値に制限されているため、そのセルには他に選択肢がありません。 最初の境界線が唯一の自由な決定であるため、両方の可能性をテストすることで、有効なすべての色がカバーされます。 

## Python ソリューション```python
import sys

input = sys.stdin.readline

def check(a, first):
    cur = first
    for need in a:
        nxt = need - cur
        if nxt < 0 or nxt > 1:
            return False
        cur = nxt
    return True

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    if check(a, 0) or check(a, 1):
        print("Yes")
    else:
        print("No")

if __name__ == "__main__":
    solve()
```の`check`関数は、最も外側の左境界線の 1 つの可能な色を表します。 変数`cur`現在のセルと共有される境界線を左側に保存します。 

すべてのセルに対して、右側の境界線が強制されます。 細胞が必要とする場合`need`色付きの境界線と左の境界線がすでに寄与しています`cur`、もう一方の境界線が貢献する必要があります`need - cur`。 境界線はバイナリであるため、外側の値はすべて`0`または`1`試行はただちに無効になります。 

main 関数は、このシミュレーションを 2 回のみ実行します。1 回目は色の付いていない最初の境界線で、もう 1 回は色付きの最初の境界線で実行されます。 現在の境界状態のみが重要であるため、スキャン中に配列は必要ありません。 

関係するすべての値は最大でも次の値であるため、オーバーフローの問題はありません。`2`、境界条件は、考えられる両方の初期境界をチェックすることによって処理されます。

import io

    input = sys.stdin.readline

 ## 特殊なケース

 アルゴリズムは依然として両方の可能な外側境界値を試行するため、1 セルのケースが処理されます。 入力の場合:```
1
0
```から始まる`0`次の境界線を次のように与えます`0`、これは有効です。 スキャンが終了して戻ります`Yes`。 

共有国境の矛盾は次のような箇所に現れます。```
2
2 0
```最初のセルでは、最初の選択に関係なく、中央の境界線が強制的に色付けされます。 2 番目のセルには、色の付いた境界線をゼロにすることはできません。 必要な次の境界線は次のようになるため、アルゴリズムはこれを捕捉します。`-1`。 

1 つの色の付いた側面を必要とするセルの長いシーケンスは、強制交互によって処理されます。 のために：```
3
1 1 1
```色の付いていない左側の境界線から開始して、シーケンスを作成します。```
0, 1, 0, 1
```各セルには 1 つの色の境界線が表示されるため、アルゴリズムはそれを受け入れます。 

このメソッドでは、2 色の境界線を必要とするセルに対して特別な処理は必要ありません。 の値`2`両方の隣接する境界線に強制的に色を付けるだけで、次のセルが処理されるときに競合が自然に発生します。 

この形式は、必要に応じて、より短いコンテストの論説、ブログ投稿スタイルの説明、またはより正式な証明を含むバージョンに適応させることができます。
