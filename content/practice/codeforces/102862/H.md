 ## 解決策
 ## 問題の理解

 すべての頂点に 2 つの数値が格納されるツリーがあります。`a`そして`b`。 興味深い値は、どちらかの数値だけではなく、その違いです。$$c_v = a_v - b_v$$頂点からの DFS ステップ`v`隣の頂点に移動できる`u`まさに次のとき:$$a_v+b_u=a_u+b_v$$並べ替えると次のようになります。$$a_v-b_v=a_u-b_u$$そのため、DFS は現在エンドポイントが同じであるエッジを通過するだけです。`c`価値。 頂点が DFS 内で終了すると、その頂点は`a`値がなる`b`、つまり、`c`値がゼロになります。 

タスクは 3 種類の操作を処理することです。 1 つの頂点を変更できます`a`値、1 つの頂点の現在の値を求める`a`値を使用するか、開始頂点から DFS プロセスを効率的にシミュレートします。 

制約により、最大で`5 * 10^5`頂点とクエリ。 ツリー全体を繰り返しスキャンしたり、3 回のクエリごとにすべての頂点に対して新しい DFS を実行したりするソリューションでは、非常に遅すぎます。 50 万回の操作があるため、すべての DFS シミュレーションの総作業量が線形に近づく必要があります。 

重要な点は、3 番目のクエリでは、現在の差がある頂点のみが変更されるということです。`c`はゼロではなく、開始頂点の差に等しい。 このような頂点が処理されると、その差はゼロになります。 頂点をゼロ以外に戻すことができるのは、頂点を 1 つだけ変更するタイプ 1 クエリを介してのみです。 これにより、償却された境界が得られます。つまり、実際のフラッド フィルによって訪問されるすべての頂点は、最初はゼロではなかった頂点の 1 つであるか、以前の更新によって非ゼロになった頂点のいずれかです。 

実装は慎重に行う必要があり、開始頂点が既に存在する場合に対処する必要があります。`a_v=b_v`。 例えば：```
1 1
5
5
```頂点からの 3 番目のクエリ`1`何もする必要はなく、値はそのまま残ります`5`。 差がゼロのコンポーネントを検索しようとする単純な実装では、ゼロ コンポーネント全体を繰り返し調べると時間が無駄になる可能性があります。 

もう 1 つのエッジ ケースは、同じ非ゼロの差を持つ複数の頂点を含むコンポーネントです。```
3 1
10 20 30
5 15 25
1 2
2 3
3 1
```違いはすべて`5`したがって、DFS は 3 つの頂点すべてを訪問し、操作後の出力は次のようになります。```
5 15 25
```彼らのために`a`価値観。 開始頂点のみをリセットする解決策は正しくありません。 

最後の重要なケースは、単一の更新によって大規模なコンポーネントが再接続される場合です。```
3 2
10 0 0
0 0 0
1 2
2 3
1 2 10
3 1
```更新後、3 つの頂点すべてに違いがあります`10`したがって、3 番目のクエリは 3 つすべてをクリアする必要があります。 アルゴリズムは、トラバース中に常に現在の差分を比較する必要があります。 

## アプローチ

 直接的な解決策は、説明されている DFS をシミュレートすることです。 タイプ 3 のクエリごとに、要求された頂点から開始し、現在の差分が一致する近傍を再帰的に訪問し、`a_v=b_v`戻った後。 これはまさにこのステートメントが説明していることなので、正しさはすぐにわかります。 

問題は、ツリー構造だけを見た場合、同じ頂点が多くの DFS トラバーサルに現れる可能性があることです。 パスまたは星型ツリーでは、1 つのクエリでほぼすべての頂点をタッチすることができ、それを何度も繰り返すと、`O(nq)`仕事。 

重要な洞察は、DFS が破壊的であるということです。 非ゼロ差分コンポーネントは、そのコンポーネント内のすべての頂点が差分ゼロになるため、処理後に消失します。 頂点がゼロ以外の差に戻ることができる唯一の方法はタイプ 1 クエリであり、これは 1 つの頂点に影響します。 したがって、実行全体にわたって、意味のあるすべての DFS 操作によって削除できる頂点の総数は、ゼロ以外の頂点の初期数と更新の数によって制限されます。 

これにより、単純な塗りつぶしアプローチを使用できるようになります。 操作自体が調査するグラフの部分を破壊するため、複雑な動的接続構造は必要ありません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nq) | O(n) | 遅すぎる |
 | 最適 | O(n + q) 償却 | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 現在の値を保存する`a`値と固定値`b`価値観。 3 番目のクエリごとに、現在の差分を計算します。`a[v]-b[v]`開始頂点の。 

この値がゼロの場合、DFS はすでに満たしている頂点のみを訪問します。`a=b`したがって、操作は何も変わりません。 すぐにスキップできます。 
2. ゼロ以外の開始差の場合は、スタックを使用して反復 DFS を実行します。 現在の塗りつぶし中に訪問した頂点をマークするタイムスタンプ配列を保持します。 

タイムスタンプにより、完全なクリアが回避されます。`visited`すべてのクエリの前に配列。これにはコストがかかります`O(n)`何も変更しないクエリであっても。 
3. 頂点の処理中に、隣接するすべての頂点を検査します。 未訪問の近隣ノードに同じ現在の差がある場合、それをスタックにプッシュします。 

等価性チェックでは、次の現在の値が使用されます。`a`、DFS の前の部分ですでに頂点が次のように変更されている可能性があるためです。`b`。 
4. 頂点がスタックから取得された後、次のように設定します。`a[v]=b[v]`。 

これは、その頂点を仕上げる元の DFS の効果と正確に一致します。 グラフはツリーであるため、すでに処理された頂点を変更しても、アクセスする必要がある追加のパスを作成することはできません。 

なぜ効果があるのか:

 DFS 条件は差の等価と等価です`a-b`。 したがって、元の手順では、等しい差間のエッジのみを含むグラフ内の開始頂点の接続コンポーネントを正確に参照します。 アルゴリズムは同じ検索を実行し、訪問したすべての頂点に同じ最終割り当てを適用します。 タイムスタンプは 1 回の検索内での頂点の再訪問を防ぐだけであり、償却された引数は、すべてのクエリにわたる検索の合計量が、最初のアクティブな頂点と更新の数で線形であることを証明します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    a = [0] + list(map(int, input().split()))
    b = [0] + list(map(int, input().split()))

    g = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)

    seen = [0] * (n + 1)
    timer = 0
    ans = []

    for _ in range(q):
        query = list(map(int, input().split()))
        t = query[0]

        if t == 1:
            v, x = query[1], query[2]
            a[v] = x

        elif t == 2:
            ans.append(str(a[query[1]]))

        else:
            v = query[1]
            diff = a[v] - b[v]

            if diff == 0:
                continue

            timer += 1
            stack = [v]
            seen[v] = timer

            while stack:
                x = stack.pop()

                for y in g[x]:
                    if seen[y] != timer and a[y] - b[y] == diff:
                        seen[y] = timer
                        stack.append(y)

                a[x] = b[x]

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```実装は維持します`a`タイプ 1 とタイプ 3 のクエリの両方で変更されるため、変更可能です。 の`b`配列は決して変更されないため、個別に保存されます。 

フラッド フィルでは、再帰ではなく明示的なスタックが使用されます。 と`5 * 10^5`頂点の場合、再帰的 DFS は Python の再帰制限を超え、スタック オーバーフローの危険性があります。 

ループ内の順序は重要です。 頂点が割り当てられています`a[x]=b[x]`近隣がチェックされた後。 これは元の DFS を反映しており、有効な子をすべて探索した後に割り当てが行われます。 割り当てが最初に行われた場合、差はゼロになり、検索で誤って情報が失われます。 

タイムスタンプ技術により、クエリごとに訪問される大規模な配列を割り当てたりリセットしたりする必要がなくなります。 実際の各塗りつぶしは、必要な頂点のみに触れます。
