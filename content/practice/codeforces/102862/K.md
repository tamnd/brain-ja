 ## 解決策
 # 問題の理解

 この問題は、その位置をグラフの頂点として表示できるバイナリ配列を記述します。 許可される各操作はエッジです。そのエッジを使用すると、そのエンドポイントで 2 ビットが反転されます。 すべてゼロの配列から始めて、特定のターゲット ビット構成を生成できるかどうかを判断する必要があります。 

入力により、位置の数、必要な最終ビット、および反転できる位置のペアのリストが与えられます。 出力は、これらのペアの反転の順序付けと繰り返しによって、ターゲットの配列を正確に作成できるかどうかです。 

制限が非常に大きいため、操作のシミュレーションは現実的ではありません。 まで$10^5$ポジションと$10^5$操作、利用可能な操作を繰り返し試行するアプローチでも、$10^{10}$最悪の場合は動作します。 解決策は線形に近い必要があります。これは、一連の操作を構築するのではなく、グラフの構造特性を探すことを示唆しています。 

重要なエッジ ケースはグラフ コンポーネントから発生します。 孤立した頂点を考えてみましょう。```
n = 2
target = [1, 0]
m = 0
```答えは`No`。 最初の位置にはエッジが接続されていないため、それをゼロから変更する操作はありません。 

2 番目のケースは、すべての頂点が接続されているが、ターゲットのパリティが奇数であるコンポーネントです。```
n = 3
target = [1, 1, 1]
m = 2
edges:
1 2
2 3
```答えは`No`。 すべての演算は正確に 2 ビットを反転するため、このコンポーネント内の 1 の数は常に 2 を法とする偶数だけ変化します。 コンポーネントは 0 の 1 から始まるため、偶数の 1 でのみ終了できます。 

不用意に実装すると、配列全体に 1 が偶数個あるかどうかだけがチェックされる可能性があります。 グラフに複数のコンポーネントがある場合、これは失敗します。```
n = 4
target = [1, 1, 1, 0]
m = 1
edge:
1 2
```答えは`No`。 最初のコンポーネントには 2 つのコンポーネントがあり、これは可能ですが、頂点 3 は 1 つのコンポーネントを持つ別個のコンポーネントであり、変更できません。 

# アプローチ

 ブルートフォースのアイデアは、操作を適用して、到達可能なすべてのバイナリ配列を追跡することです。 各ビットには 2 つの状態があるため、次のことが考えられます。$2^n$可能な配列。 たとえ$n=40$、これはすでに大きすぎるため、指定された制限は$10^5$状態の探索が不可能になります。 

もう 1 つの直接的なアプローチは、すべての演算をバイナリ値に対する方程式として扱うことです。 各エッジは、それを適用すると両方のエンドポイントが切り替わることを示しているため、最終状態は選択したエッジの XOR の組み合わせになります。 一般的なガウス消去法を使用して完全な線形システムを解くことは概念的には機能しますが、それは不必要であり、グラフ構造が必要とするよりも複雑になります。 

重要な観察は、操作によって接続コンポーネント内の 1 の数のパリティが決して変更されないことです。 エッジの両方の端点は同じコンポーネントに属しており、両方のビットを反転すると、1 のカウントがプラス 2、マイナス 2、または 0 のいずれかに変更されます。 モジュロ 2 算術では、コンポーネントのパリティは変化しません。 

この条件でも十分です。 1 つの接続されたコンポーネント内では、コンポーネント内のパスに沿って歩くことで、任意の頂点のペアを効果的に切り替えることができます。 このようなパス操作を組み合わせることで、偶数パリティを持つ任意の構成を作成できます。 少なくとも 1 つのエッジを持つコンポーネントはすべての偶数パリティ割り当てを生成できますが、孤立した頂点は変更できません。 

問題は、接続されたコンポーネントを見つけて、各コンポーネント内のターゲットの数を数え、これらのパリティ条件をチェックすることに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(2^n) | 遅すぎる |
 | 最適 | O(n + m) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 許可されたすべての操作が 2 つの位置間のエッジとなる無向グラフを構築します。 操作はどの頂点が接続されているかにのみ依存するため、エッジの正確な順序は重要ではありません。 
2. DFS または BFS を使用して、接続されているすべてのコンポーネントを検索します。 コンポーネントにアクセスしているときに、1 に等しいターゲット ビットの数を数え、コンポーネントに属する頂点の数を数えます。 
3. コンポーネントに頂点が 1 つだけ含まれており、そのターゲット ビットが 1 である場合、そのコンポーネントは直ちに拒否されます。 その頂点に触れる操作はないため、ゼロのままでなければなりません。 
4. エッジのあるすべてのコンポーネントについて、その中にあるコンポーネントの数を確認します。 そのカウントが奇数の場合、コンポーネントのパリティは変更できないため、ターゲットを拒否します。 
5. すべてのコンポーネントがこれらのチェックに合格した場合、ターゲットを受け入れます。 

機能する理由: 各操作は同じ接続コンポーネントから 2 つの頂点を反転するため、すべてのコンポーネントの頂点のパリティは不変です。 不変式は必要条件を与えます。 接続されたコンポーネントを使用すると、パスを介してトグルを移動し、エッジ操作を組み合わせることができます。これは、すべての均等なサイズの頂点セットを反転できることを意味します。 すべての有効なコンポーネント ターゲットは偶数パリティを持つため、そのようなターゲットはすべて到達可能です。 

# Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    b = list(map(int, input().split()))
    
    m = int(input())
    graph = [[] for _ in range(n)]
    
    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        graph[u].append(v)
        graph[v].append(u)

    visited = [False] * n

    for start in range(n):
        if not visited[start]:
            stack = [start]
            visited[start] = True
            ones = 0
            size = 0

            while stack:
                u = stack.pop()
                size += 1
                ones += b[u]

                for v in graph[u]:
                    if not visited[v]:
                        visited[v] = True
                        stack.append(v)

            if size == 1:
                if ones == 1:
                    print("No")
                    return
            else:
                if ones % 2 == 1:
                    print("No")
                    return

    print("Yes")

if __name__ == "__main__":
    solve()
```グラフの構造は、利用可能な操作を直接表します。 位置を反転するため、エッジは方向がありません$i$そして$j$ペアをどのように記述するかに関係なく、同じ効果があります。 

DFS ループは、一度に 1 つの接続コンポーネントを処理します。 変数`ones`重要なパリティ情報を保存します。`size`通常のコンポーネントと孤立した頂点を区別します。 偶数パリティ チェックでは単一のゼロ ビットを含むコンポーネントが誤って受け入れられ、カウント後にのみ拒否されるため、孤立した頂点の場合は個別の処理が必要ですが、単一のビットは決して生成されません。 

走査では、再帰ではなく明示的なスタックが使用されます。 Python の再帰の深さは、長さのパスを含むグラフに対して小さすぎます$10^5$したがって、反復 DFS はスタック オーバーフローを回避します。

 # エッジケース

 孤立した頂点の場合、アルゴリズムはサイズ 1 のコンポーネントを作成します。 入力の場合:```
3
0 1 0
1
1 3
```コンポーネントは`{1,3}`そして`{2}`。 2 番目のコンポーネントには頂点が 1 つと必須の頂点が 1 つあるため、アルゴリズムは次の値を返します。`No`。 その頂点に対する操作を発明しようとすることは決してありません。 

奇数パリティ連結成分の場合:```
3
1 1 1
2
1 2
2 3
```トラバースでは、3 つの頂点すべてを含む 1 つのコンポーネントが見つかります。 ターゲットの数は 3 で奇数であるため、アルゴリズムはそれを拒否します。 利用可能なすべての操作は 2 つの位置を反転し、コンポーネントのパリティは変更されません。 

接続されていないグラフの場合、各コンポーネントを個別にチェックする必要があります。```
4
1 1 1 0
1
1 2
```最初のコンポーネント`{1,2}`には 2 つあり、有効です。 残りの頂点は分離されており、頂点 3 には、いかなるエッジも含まれていない頂点が必要です。 アルゴリズムはそのコンポーネントで拒否し、1 の合計数のみをチェックするというよくある間違いを回避します。
