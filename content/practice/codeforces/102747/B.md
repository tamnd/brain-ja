 ## 問題の理解

 この問題は、一列に並んだ 3 台のプロジェクターをモデルとしています。 左、中、右、中の繰り返しの順序で一度に 1 秒ずつオンになります。 左側のプロジェクターは次の用途に使用できます。`A`合計で秒、真ん中の秒は`B`秒、および正しいもの`C`秒。 タスクは、電源をオンにする必要がある次のプロジェクターの寿命がなくなるまでに、プロセスが何秒続くかを見つけることです。 元のステートメントは Codeforces Gym の問題 102747B からのものです。 

入力は、左、中央、右のプロジェクターの動作可能な秒数を表す 3 つの非負の整数で構成されます。 出力は、無限回転シーケンスの最も長い有効なプレフィックスの長さです。 

制約の重要な部分は、利用可能な作業の総量が約`2 * 10^9`。 1 秒ごとに 1 台のプロジェクターをオンにするシミュレーションでは、数十億回の反復が必要になる可能性がありますが、これは短い制限時間としては遅すぎます。 シーケンスの繰り返し構造を使用し、大きな操作グループを一度にスキップする必要があります。 値が 3 つしかないため、目的の解は定数時間に近いものになるはずです。 

いくつかの特殊なケースにより、直接シミュレーションが中断されたり、間違った式が中断されたりする可能性があります。 中央のプロジェクターに寿命がない場合、プロセスは直ちに停止します。```
Input:
0
5
7

Output:
0
```可用性を確認する前に常に 1 つの完全なサイクルを追加するソリューションでは、決して発生しない秒数が誤ってカウントされます。 

もう 1 つの注意が必要なケースは、サイド プロジェクターの 1 つがちょうどサイクルの終わりに使い果たされる場合です。```
Input:
1
2
1

Output:
4
```順番は左、中、右、中です。 4 秒後、利用可能な有効期間がすべて使用されますが、次に左側のプロジェクターのアクティブ化は失敗します。 失敗したアクティベーションをカウントすると、`5`。 

3 番目のよくある間違いは、中央のプロジェクターを他のプロジェクターと同じように扱うことです。 4秒に2回使用するため、左右のプロジェクターとグループ化することはできません。```
Input:
10
1
10

Output:
1
```最初の左のアクティベーションのみが発生します。 次に必要なアクティブ化は中央のプロジェクターですが、すでに 1 秒を使い果たしています。 

## アプローチ

 直接的なアプローチは、このシーケンスを繰り返し実行し、現在のプロジェクターの残りの寿命を減らすことです。 1 秒ごとに 1 つの操作が実行され、その答えは、ライフタイムがゼロになるまでに成功した操作の数になります。 この方法は、ステートメントで説明されているプロセスに正確に従うため、正しいことを証明するのは簡単です。 

この問題は、利用可能な寿命が長い場合に発生します。 最悪の場合、3 つの値がすべて次の値に近い場合、`10^9`、シミュレーションには数十億のステップが必要です。 時間の複雑さは答え自体に比例するため、これは許容できません。 

有益な観察は、固定パターンから得られます。 プロセスは 4 秒ごとに、左側のプロジェクターで 1 秒、中央のプロジェクターで 2 秒、右側のプロジェクターで 1 秒を常に消費します。 これら 4 つのアクティベーションを個別に処理する代わりに、可能な限り多くの 4 つの完全なグループをジャンプできます。 

完了したサイクルの数は、次のサイクルに耐えられない最初のプロジェクターによって制限されます。 1 サイクルには左に 1 秒、中央に 2 秒、右に 1 秒必要なため、完全なサイクル数は次のようになります。`min(A, B // 2, C)`これらの完全なサイクルを削除した後、最大でさらに 4 つのアクティベーションをチェックする必要があります。 これが機能するのは、残りの唯一の障害が次の不完全なサイクル内で発生する必要があるためです。

 ## アルゴリズムのチュートリアル

 1. プロジェクターの 3 つの利用可能な寿命を読みます。 
2. 完全な 4 秒サイクルが何回発生できるかを計算します。 1 サイクルは左に 1 秒、中央に 2 秒、右に 1 秒を消費するため、完全なサイクルの数は次のように制限されます。`min(A, B // 2, C)`。 
3. 完全なサイクルごとに 4 秒を加算し、3 台​​すべてのプロジェクターから使用寿命を減算します。 このステップの後、少なくとも 1 台のプロジェクターは次のサイクル全体を完了できません。 
4. 次のいくつかのアクティベーションを左、中央、右、中央の順序で確認します。 完全なサイクルはもう不可能なので、これら 4 つの位置以上をチェックする必要はありません。 現在のプロジェクターにまだ寿命がある場合は、1 秒を消費して答えを増やします。 それ以外の場合は、停止してください。 
5. 成功した累積秒数を出力します。 

なぜ効果があるのか:

 このアルゴリズムは、すべてのプロジェクターから消費された正確な秒数を保存します。 完全なサイクルには固定された消費パターンがあるため、多くの個々の操作をサイクル ジャンプに置き換えてもシステムの状態は変わりません。 可能な最大数の完了サイクルを実行した後、残りの状態はさらにサイクル全体を存続することができません。 唯一可能な継続は次のサイクルのプレフィックスであり、そのプレフィックスをチェックすることで正確な最終的な長さが直接得られます。 

## Python ソリューション```python
import sys

input = sys.stdin.readline

def solve():
    a = int(input())
    b = int(input())
    c = int(input())

    cycles = min(a, b // 2, c)

    ans = cycles * 4
    a -= cycles
    b -= cycles * 2
    c -= cycles

    for i in range(4):
        if i == 0 or i == 2:
            if i == 0:
                if a == 0:
                    break
                a -= 1
            else:
                if c == 0:
                    break
                c -= 1
        else:
            if b == 0:
                break
            b -= 1
        ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```コードの最初の部分では、考えられるすべての完全なサイクルが削除されます。 表現`min(a, b // 2, c)`各サイクルには正確にそれらの量が必要であるため、 はリソースの制限を直接表します。 

この減少の後、部分的なサイクルが 1 つだけ発生する可能性があるという意味で、残りの値は小さくなります。 このループは、繰り返しパターン内の 4 つの可能な位置を処理します。 このコードはリソースを減らす前にチェックを行うため、失敗したアクティベーションのカウントが回避されます。 

シーケンスの長さは固定されているため、インデックス作成に関する懸念はありません。 利用可能な合計有効期間は問題の制約によって制限されるため、Python の整数でも最大の答えを得るのに十分です。

## テストケース```python
import sys
import io

def solution(inp: str) -> str:
    data = list(map(int, inp.split()))
    a, b, c = data

    cycles = min(a, b // 2, c)
    ans = cycles * 4
    a -= cycles
    b -= cycles * 2
    c -= cycles

    for i in range(4):
        if i == 0:
            if a == 0:
                break
            a -= 1
        elif i == 1 or i == 3:
            if b == 0:
                break
            b -= 1
        else:
            if c == 0:
                break
            c -= 1
        ans += 1

    return str(ans)
