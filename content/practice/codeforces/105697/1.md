 ## 解決策
 ## 問題の理解

 1 より大きい各自然数には、その最大の適切な約数として定義される「フレンド」が割り当てられます。これは、その自然数を正確に分割できる、その自然数より厳密に小さい最大の数を意味します。 たとえば、6 には適切な約数 1、2、3 があり、その友達は 3 です。 

このタスクは、2 から n までのすべての数値を考慮し、各数値のこの友人を計算し、これらの値をすべて合計することです。 

したがって、入力は単一の整数 n であり、出力は 2 から n までのすべての整数の最大の適切な約数の合計です。 

制約は最大約 1,000 万まであり、数値ごとに単純に約数を再計算することができなくなります。 整数ごとの単純な除数スキャンでは、最悪の場合、およそ O(n√n) 回の操作が必要になりますが、これでは遅すぎます。 O(n log n) のソリューションであっても、制限時間内に収まるように慎重に実装する必要があります。 

素数の周囲に微妙なエッジケースが現れます。 素数 p の場合、最大の適切な約数は常に 1 です。p² のような数値の場合、答えは p² / 2 や何らかの近似ではなく、p になります。 もう 1 つのエッジ ケースは、n = 2 または n = 3 です。この場合、項が少数しか存在せず、合計が小さいため、ループ境界内のオフバイ 1 エラーがすぐに現れます。 

たとえば、n = 6 の場合、値は次のようになります。 

2→1

 3→1

 4→2

 5→1

 6→3

 合計 = 8

 「最大の適切な約数」ではなく「1 以外の最小の約数」を誤って割り当てる単純なアプローチでは、6 に対して 3 ではなく 2 が誤って与えられてしまいます。 

## アプローチ

 ブルートフォースの方法は、各数値の最大の適切な約数を個別に計算することです。 固定 x の場合、x/2 または √x までのすべての約数をスキャンし、最大の有効な約数を追跡できます。 √x スキャンを使用した場合でも、これは約

 n × √n の演算。n = 10⁷ の場合、10¹⁰ ステップ程度になり、限界をはるかに超えます。 

重要な構造的観察は、数値の「友人」がその最小の非自明な因子によって逆の方法で決定されるということです。つまり、x の約数 d がわかっている場合、x は d を答えに寄与しますが、これは d が x の最大の適切な約数である場合に限ります。 これは、視点を反転すると、よりわかりやすく言い換えることができます。「各 x について、その最良の約数は何か」と尋ねる代わりに、「考えられる各約数 d について、どの数値が最大の適切な約数になるでしょうか?」と尋ねます。 

約数 d は、x = d × k で、k が 1 より大きい可能な最小の因数である場合に、x の最大の固有約数になります。つまり、k は、k の倍数構造の最小の素因数でなければなりません。 これは当然、ふるいのような構造になります。各数値 i について、i が最大の適切な約数であるその倍数に対する候補の答えとして i を伝播します。 

これを実装するきれいな方法は、エラトステネスの篩に似た篩を使用することですが、素数をマークする代わりに、i がこれまでに j を下回る最大の約数である場合にのみ、i の倍数 j ごとに値 i を割り当てます。 i を 1 から上に向かって反復すると、i を倍数に代入するたびに、その後のより大きな除数によって上書きされ、最終的に保存される値が最大の適切な除数であることが保証されます。 

これにより、ふるい内の調和系列の動作により、問題はおよそ n log n 回の操作に減ります。

 | ブルート フォース (除数スキャンごと) | O(n√n) | お(1) | 遅すぎる |

 ## アルゴリズムのチュートリアル

 1. 配列を作成する`best`サイズ n+1 は 0 に初期化されます。この配列には、各数値で見つかった最大の適切な約数が格納されます。 
2. i を 1 から n まで繰り返します。 値 i は、その倍数の候補として扱われます。 
3. 各倍数 j = 2i、3i、4i、…最大 n に対して、次の値を割り当てます。`best[j] = i`。 i を上に移動するので、より大きな i 値が小さな値を上書きします。 
4.ふるいが終わったら、すべての値を合計します`best[2] + best[3] + ... + best[n]`そして結果を出力します。 

2i からマークを開始する理由は、数値がそれ自身の適切な約数ではないため、i は i 自体に寄与できないためです。 

### なぜ効果があるのか

 値 i を処理する時点で、すべての倍数 j = i × k に i が除数の候補として割り当てられます。 その後、j も除算するより大きな約数 d に達すると、d が i を上書きします。 i を昇順に繰り返すため、各 j の最後の代入は、それを分割する j 未満の最大の約数に対応します。 それはまさに最大の適正約数の定義です。 

これにより、単調な上書き不変式が作成されます。`best[j]`は、これまでの走査で見つかった j の最大の約数を常に保持します。最終的にはすべての約数が見つかるため、最終的な値は正しい値になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    best = [0] * (n + 1)

    for i in range(1, n + 1):
        for j in range(2 * i, n + 1, i):
            best[j] = i

    ans = sum(best[2:])
    print(ans)

if __name__ == "__main__":
    solve()
```外側のループは、考えられるすべての除数候補を反復処理します。 内側のループは倍数を処理し、各数値がそのすべての約数から更新を確実に受け取るようにします。 重要な実装の詳細は次のとおりです。`2 * i`、これにより自己割り当てが防止されます。 

番号 1 は問題のドメインの一部ではないため、合計はインデックス 2 から始まります。

 ## 特殊なケース

 n = 2 の場合、数値 2 のみが寄与し、その最大の適切な除数は 1 です。 i = 1 の間、アルゴリズムは best[2] を 1 に初期化し、それ以降の値で上書きされないため、出力は正確になります。 

素数が多い範囲の場合、すべての素数 p は i = 1 からのみ割り当てられるため、best[p] は 1 のままです。 i > 1 が素数を分割しないため、ふるいは誤って素数を上書きしません。 

36 のような完全な平方の場合、正しい値は 18 です。スイープ中、i = 18 は 36 の以前の小さい約数をすべて上書きします。また、36 よりも大きい適切な約数は存在しないため、最終値として安定したままになります。
