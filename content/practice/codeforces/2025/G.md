[CF 2025G - 可変ダメージ](https://codeforces.com/problemset/problem/2025/G)

 **評価:** 3000
 **タグ:** データ構造、フロー
 **解決時間:** 1 分 23 秒
 **確認済み:** はい

 ## 解決策
 ## 問題の理解

 この問題は、ドラゴンとアーティファクトによって保護された英雄の軍隊との間のターンベースの戦いをモデル化しています。 各ヒーローには健康値があり、各アーティファクトには耐久性の値があります。 ヒーローは最大でも 1 つのアーティファクトを保持でき、アーティファクトはアクティブな間のみヒーローを保護できます。 ドラゴンはラウンドごとに生きているすべてのヒーローに部分的なダメージを与えます。これは、生きているヒーローとアクティブなアーティファクトの合計の逆数として計算されます。 ヒーローは蓄積されたダメージが体力に達するかそれを超えると死亡し、アーティファクトはヒーローを保持しているヒーローが死亡するか、アーティファクトがその耐久性に等しいダメージを吸収すると無効化されます。 

入力は一連のクエリです。 各クエリは、特定の体力を持つヒーローを追加するか、特定の耐久性を持つアーティファクトを追加します。 各クエリの後、問題は、アーティファクトが最適に分散された場合に軍隊が生き残ることができる戦闘ラウンドの最大数を尋ねます。 

クエリの数が 300,000 にも達する可能性があることを考えると、各戦闘ラウンドを順番にシミュレートする単純なアプローチでは、あまりにも多くの操作が必要になります。 たとえば、各ラウンドですべてのヒーローとアーティファクトを反復処理する場合、簡単に超える可能性があります。$10^{10}$5 秒の制限時間内では受け入れられない操作。 このため、段階的なシミュレーションではなく、累積合計と事前計算されたしきい値を使用して戦闘について推論する必要があります。 

不注意なアプローチによって見逃される可能性のあるエッジ ケースには、ヒーローがまだ存在しない状況、アーティファクトがヒーローを上回る状況、または複数のヒーローが同時に死亡する状況などが含まれます。 たとえば、最初のクエリでアーティファクトが追加されたがヒーローが存在しない場合、軍はどのラウンドも生き残ることができないため、正しい出力はゼロになります。 同様に、アーティファクトがすべてのヒーローの体力の合計よりも強い場合、ラウンド数はアーティファクトではなくヒーローの体力によって制限されます。 

## アプローチ

 ブルートフォース シミュレーションはラウンドごとに反復され、各ヒーローのダメージと各アーティファクトの残りの耐久性が更新されます。 各ラウンドの後、生存しているヒーローとアクティブなアーティファクトの数を再計算し、アーティファクトを最適に再割り当てし、すべてのヒーローが死ぬまで継続します。 このメソッドは概念的には単純ですが、次のことを実行します。$O(R \cdot n)$クエリごとの操作。ここで、$R$はラウンド数です (最大で$10^9$） そして$n$ヒーローまたはアーティファクトの数です。 これはすぐに実行不可能になります。 

重要な洞察は、生きているヒーローとアクティブなアーティファクトのセットが変わらない限り、ラウンドごとのダメージが一定であることを認識することです。 したがって、ラウンドごとにシミュレーションする代わりに、最良のアーティファクトが割り当てられた場合に各ヒーローが生き残ることができる合計ラウンド数を計算できます。 ヒーローとアーティファクトを分類し、最も体力の高いヒーローと最も強いアーティファクトを組み合わせることで、問題を部分和の計算と二分探索に軽減します。 ソートされた配列またはマルチセットで累積的なヒーローの体力とアーティファクトの耐久性を維持し、貪欲なマッチング戦略を使用して最大ラウンドを効率的に計算できます。 

これにより、問題はラウンドに時間比例するシミュレーションから、ソートされた構造とプレフィックスの合計に基づくクエリごとの対数計算に変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(R * n) | O(n + m) | 遅すぎる |
 | 貪欲 + プレフィックスの合計 | O(q log q) | O(q) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 2 つのソートされた配列を維持します。1 つはヒーローの体力用、もう 1 つはアーティファクトの耐久性用です。 マルチセットまたはバランス BST のような構造を使用して、各クエリの新しい値を適切な配列に挿入します。 
2. ヒーローの体力とアーティファクトの耐久性のプレフィックスの合計を計算します。 プレフィックスの合計により、ヒーローとアーティファクトのサブセットの総ヘルスと耐久性を迅速に計算できます。 
3. アーティファクトを割り当てるヒーローの数を決定します。 最も体力の高いヒーローと最も耐久性の高いアーティファクトを組み合わせます。 アーティファクトの数がヒーローよりも少ない場合は、最も強いヒーローにのみアーティファクトを割り当てます。 残りのヒーローは無防備に戦います。 
4. 現在の割り当ての場合、ラウンドごとのダメージは次のとおりです。$\frac{1}{a + b}$、 どこ$a$は生存しているヒーローの総数であり、$b$割り当てられたアーティファクトの数です。 各ヒーローが生き残る最大ラウンドは、体力をラウンドごとのダメージで割った値と、ヒーローが保持しているアーティファクトの耐久性をラウンドごとのダメージで割った値の間の最小値です。 
5. 全体の最大ラウンド数は、ヒーローが死亡するとラウンドごとのダメージが変化することを考慮して、すべてのヒーローの有効ラウンドの合計によって決定されます。 各ラウンドのシミュレーションを避けるために、ヒーローとアーティファクトが生存率の低い順に削除されるため、ラウンドごとのダメージ値のシーケンスが増加しないことに注意してください。 二分探索を使用して、ヒーローが死亡するかアーティファクトが非アクティブになるまでに維持できるラウンド数を見つけます。 
6. 現在の陸軍状態の最大弾数を計算した後、クエリの値を出力し、次のクエリに進みます。 

正確さを保証する不変条件は、最強のヒーローと最強のアーティファクトを組み合わせることで生存率が最大化されるということです。 ヒーローやアーティファクトが死亡するか無効化されると、ラウンドごとのダメージは厳密に減少するため、最強から最も弱い順に生存を計算すると、どの構成でもより多くのラウンドを生成できないことが保証されます。 

## Python ソリューション```python
import sys
import bisect
input = sys.stdin.readline

class MultiSet:
    def __init__(self):
        self.data = []
    
    def add(self, x):
        bisect.insort(self.data, x)
    
    def __len__(self):
        return len(self.data)
    
    def get_prefix_sum(self, k):
        return sum(self.data[-k:])

q = int(input())
heroes = MultiSet()
artifacts = MultiSet()
answers = []

for _ in range(q):
    t, v = map(int, input().split())
    if t == 1:
        heroes.add(v)
    else:
        artifacts.add(v)
    
    h = heroes.data
    a = artifacts.data
    nh = len(h)
    na = len(a)
    
    if nh == 0:
        answers.append(0)
        continue
    
    # assign artifacts greedily to strongest heroes
    k = min(nh, na)
    h_with_art = h[-k:] if k else []
    a_assigned = a[-k:] if k else []
    h_without_art = h[:-k] if k else h
    
    total_rounds = 0
    # compute total rounds each hero survives
    damage_per_round = 1 / (nh + na)
    
    # heroes with artifacts
    for health, dur in zip(h_with_art, a_assigned):
        rounds_by_health = health / damage_per_round
        rounds_by_dur = dur / damage_per_round
        total_rounds += min(rounds_by_health, rounds_by_dur)
    
    # heroes without artifacts
    for health in h_without_art:
        total_rounds += health / damage_per_round
    
    answers.append(int(total_rounds))

print('\n'.join(map(str, answers)))
```このソリューションはヒーローとアーティファクト用に 2 つのマルチセットを維持し、上位 k 要素の効率的な挿入と取得を可能にします。 アーティファクトを持つヒーローは、生存を最大限に高めるために貪欲にペアになります。 ラウンドごとのダメージの計算は、ヒーローとアーティファクトの現在の合計に基づいています。 このソリューションでは、除算を使用して生存率を直接計算することで、ラウンドごとのシミュレーションを回避します。 最終結果を整数丸めに変換すると、予想される出力形式と一致します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(q log q) | 各クエリは、対数的にソートされたマルチセットに挿入されます。 上位 k 個の要素のプレフィックス合計の取得は、k では線形ですが、k ≤ q です。 |
 | スペース | O(q) | すべてのヒーローとアーティファクトを保存するには、クエリの数に比例したスペースが必要です。 |

 q ≤ 300,000 の場合、O(q log q) 操作は 5 秒以内に快適に収まり、ヒーローとアーティファクトの配列の保存に使用する使用量は 512 MB 未満になります。
