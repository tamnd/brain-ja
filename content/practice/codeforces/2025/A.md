 ## 解決策
 ## 問題の理解

 それぞれ大文字のシーケンスを表示できる 2 つの画面が与えられています。 最初は両方の画面が空です。 毎秒、画面の 1 つに 1 文字を追加することも、シーケンス全体を 1 つの画面から別の画面にコピーして、ターゲット画面にあったものを置き換えることもできます。 タスクは、ターゲット文字列を表示するのに必要な最小秒数を決定することです。`s`最初の画面とターゲット文字列`t`2番目の画面で。 

各入力は、多数のテスト ケースで構成されます。 テストケースごとに 2 つの文字列を取得します。`s`そして`t`テスト ケースの総数は最大 500 であるため、理想的には文字列の長さの線形または線形に近い時間で、ケースごとに効率的に解を計算する必要があります。 

文字を追加するには 1 文字あたり 1 秒かかるため、すべてを 1 文字ずつ入力する素朴なアプローチは常に機能します。 ただし、これはコピー操作を無視するため、文字列が共通のプレフィックスを共有している場合、合計時間を大幅に短縮できます。 たとえば、次の場合`s`そして`t`同じ部分文字列で始まる場合、その部分文字列をある画面から別の画面にコピーするほうが、2 回入力するよりも高速です。 

エッジケースが発生するのは次の場合です`s`そして`t`共通のプレフィックスがまったくありません。 この場合、コピー操作は役に立ちません。最適な解決策は単に次の長さの合計になります。`s`そして`t`。 もう 1 つの微妙なケースは、一方の文字列が他方の文字列のプレフィックスである場合です。 次に、コピー操作を適用して、短い文字列を共通のプレフィックスの長さまですばやく「拡張」できます。 

## アプローチ

 ブルートフォース手法では、結果として生じる可能性のあるすべての操作シーケンスを検討します。`s`最初の画面と`t`2番目に。 これには、文字列の長さに応じて指数関数的に増加する、タイプ操作とコピー操作のすべてのシーケンスの探索が含まれます。 100 までの長さの場合、これは明らかに実行不可能です。 

効率的な解決策につながる重要な観察は、コピーが有益なのは、両方の文字列の先頭に共通の部分文字列がある場合のみであるということです。`s`そして`t`私たちが活用できるということ。 具体的には、次の最長の部分文字列を特定すると、`s`そして`t`同じインデックス (またはより単純に、最長の共通部分文字列) で始まる同じ位置に出現する場合、それを一度入力してコピーすることができ、繰り返し入力する必要がなくなります。 共通の部分文字列を超える文字は個別に入力する必要があるため、問題は、このコピー操作を使用することで回避できる最小の長さを計算することになります。 

正式に言うと、`lcs`の最長の共通部分文字列の長さです。`s`そして`t`、最小時間は`len(s) + len(t) - lcs`。 これが機能するのは、ある画面で共通の部分文字列を 1 回入力し、それをもう 1 つの画面にコピーして、残りの文字を各画面に追加できるためです。

 ## アルゴリズムのチュートリアル

 1. テスト ケースごとに文字列を読み取ります。`s`そして`t`。 
2. 変数を初期化する`max_common`ゼロに。 これにより、両方に共通する最長の部分文字列の長さが追跡されます。`s`そして`t`。 
3. 開始位置のすべてのペアを考慮する`(i, j)`で`s`そして`t`。 各ペアについて、部分文字列が次からどのくらいの長さで一致するかを確認します。`s[i]`そして`t[j]`。 アップデート`max_common`より長い一致が見つかった場合。 これは、標準的なネストされたループの部分文字列比較です。 
4. わかったら`max_common`、必要な最小秒数は次のとおりです。`len(s) + len(t) - max_common`。 論理は次のとおりです`max_common`文字は一度入力してからコピーされるため、保存されます`max_common`秒。 
5. 各テスト ケースの結果を出力します。 

機能する理由: 各文字を個別に入力すると、正確さが保証されます。 時間を短縮する唯一の方法は、共有部分文字列をコピーすることです。 このような最長の部分文字列は、達成できる最大の節約を表します。 より小さい部分文字列のコピーでは節約できる秒数は短くなりますが、両方の文字列で整列していない文字をコピーしようとしても、合計時間は短縮されません。 したがって、`len(s) + len(t) - max_common`最小限であることが証明されています。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    q = int(input())
    for _ in range(q):
        s = input().strip()
        t = input().strip()
        max_common = 0
        for i in range(len(s)):
            for j in range(len(t)):
                l = 0
                while i + l < len(s) and j + l < len(t) and s[i + l] == t[j + l]:
                    l += 1
                max_common = max(max_common, l)
        print(len(s) + len(t) - max_common)

if __name__ == "__main__":
    solve()
```最初の行はテスト ケースの数を読み取ります。 ネストされたループは、すべての開始位置を反復します。`s`そして`t`、それらの位置から一致する部分文字列の長さを数えます。 外側`for`ループはすべての開始点をカバーし、`while`ループは一致を可能な限り延長します。 使用する`.strip()`競技プログラミングでよくある落とし穴である改行文字を削除します。 ついに、`len(s) + len(t) - max_common`アルゴリズム ロジックと一致して、必要な最小秒数が得られます。

 ## 特殊なケース

 文字列に共通の文字がない場合、アルゴリズムは正しく検索します。`max_common = 0`、および出力`len(s) + len(t)`コピーは役に立たないからです。 例えば、`s = "ABCD"`、`t = "WXYZ"`、収量`8`、長さの合計と一致します。 

一方の文字列が完全にもう一方の文字列のプレフィックスである場合、次のようになります。`s = "AAAA"`、`t = "AAAAA"`、最も長い共通部分文字列は次のとおりです。`4`。 すると、最小時間は`4 + 5 - 4 = 5`これは、共有された文字を 1 回入力してコピーし、残りの文字を入力することを反映しています。 これにより、アルゴリズムがプレフィックスのエッジ ケースを最適に処理していることが確認されます。
