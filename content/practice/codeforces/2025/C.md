 ## 解決策
 ## 問題の理解

 ゲームは、それぞれ整数のラベルが付けられたカードのデッキを中心に展開します。 Monocarp は任意のカードを取ることで開始できます。 その後のターンでは、最後に取ったカードと同じ番号か、ちょうど 1 つ大きい番号のカードしか取ることができません。 さらに、Monocarp が収集する個別の数値の合計数は以下を超えることはできません。`k`。 目標は、有効な動きがなくなる前に、取得するカードの総数を最大化することです。 

入力は複数のテスト ケースを提供します。 各テスト ケースはカードの数を示します`n`、許可される個別の数値の最大数`k`、およびカード上の整数のシーケンス。 出力は、ルールに基づいて Monocarp が収集できるカードの最大数を表すテスト ケースごとに 1 つの整数である必要があります。 

とすれば`n`合計は 200,000 に達する可能性があります`n`すべてのテスト ケースが 200,000 に制限されているため、2 秒の制限時間内に収まるように、各テスト ケースでソリューションをおよそ O(n log n) 以上で実行する必要があります。 考えられるカードの順序をすべて試すという単純なアプローチでは、複雑さが倍増し、明らかに実行不可能です。 

微妙なエッジ ケースには、数値に大きなギャップがあるシーケンス、値の繰り返し、または次のような状況が含まれます。`k`は一意の番号の数よりも小さいです。 たとえば、入力の場合`n=5, k=1, a=[1,3,1,3,2]`、常に最初に利用可能なカードを選択する単純な貪欲なアプローチでは、誤ってカードを選択しようとする可能性があります。`2`または`3`早すぎるため、個別の数の制約に違反します。 正しい出力は次のとおりです`2`Monocarp は以下のカードしか取れないので、`1`このシナリオでは。 

## アプローチ

 ブルートフォースアプローチでは、すべての開始カードを試してゲームをシミュレートし、残りの手がなくなるまですべての有効なカード選択シーケンスを試みます。 このアプローチは原則的には正しいですが、最悪の場合、`n=200,000`、配列の数は天文学的であり、計算上不可能です。 

重要な観察は、重要な数字はカード上に存在する一意の整数だけであるということです。 Monocarp は数値からしか移動できないため、`x`に`x`または`x+1`、スキップすると後でカードを含めることができなくなるため、最適な戦略は、スキップせずに連続する数字を昇順に取得することです。 したがって、問題を、ソートされた一意の値のセット内で、セグメントの長さが次の値を超えない、最も長く連続する数値セグメントを数えるという問題に減らすことができます。`k`。 セグメントが特定されたら、このセグメント内のすべての数字のカウントを合計すると、Monocarp が取得できるカードの最大数が得られます。 

最適な解決策は、一意の数値をソートし、一定の長さのウィンドウに収まる連続する数値の数をカウントします。`k`。 辞書を使用して頻度を追跡すると、カード カウントに O(1) アクセスできます。 ソートされた一意の数値上でウィンドウをスライドさせると、すべての候補セグメントの合計を効率的に計算できます。 これにより、ソートにより複雑さが O(n log n) に軽減されます。

 | --- | --- | --- | --- |
 | ブルートフォース | お(ん!) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 辞書を使用して各数値の出現数を数えます。 これにより、リストを繰り返しスキャンすることなく、各番号に対して何枚のカードを取得できるかを知ることができます。 
2. 固有の番号を抽出して並べ替えます。 Monocarp は同じ番号または次に連続する番号にしか移動できないため、並べ替えが必要です。 ソートにより、連続するシーケンスを効率的に検討できます。 
3. ソートされた一意の数値に対して、2 ポインターまたはスライディング ウィンドウのアプローチを使用します。 ウィンドウは、Monocarp が取り得る個別の数値の候補シーケンスを表します。 両方のポインターをソートされた配列の先頭から開始します。 
4. ウィンドウ内の個別の値の数を超えない範囲で右ポインタを展開します。`k`そして数字は連続しています。 ウィンドウ内の数字のカードの合計の現在までの合計を記録します。 
5. ウィンドウが制約に違反している場合 (個別の数値が多すぎるか、連続する数値にギャップがある場合)、ウィンドウが再び有効になるまで左ポインタを縮小し、それに応じて累計を調整します。 
6. このプロセス中に観察された最大合計を追跡します。 この合計は、Monocarp が取得できるカードの最大数を表します。 
7. 各テスト ケースの最大合計を出力します。 

機能する理由: どの時点でも、スライディング ウィンドウには、個別の数値の数が以下の最大の連続数値シーケンスが含まれます。`k`。 このウィンドウ内のカウントを合計することで、Monocarp がルールに基づいて有効なすべてのカードを確実に取得できるようにします。 スライディング ウィンドウは、考えられるすべての有効な開始点を効率的に探索し、グローバル最大値が見つかることを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import Counter

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        count = Counter(a)
        unique_sorted = sorted(count.keys())

        max_cards = 0
        left = 0
        current_sum = 0

        for right in range(len(unique_sorted)):
            if right > 0 and unique_sorted[right] != unique_sorted[right - 1] + 1:
                # reset window if numbers are not consecutive
                left = right
                current_sum = 0
            current_sum += count[unique_sorted[right]]

            # shrink window if too many distinct numbers
            while right - left + 1 > k:
                current_sum -= count[unique_sorted[left]]
                left += 1

            max_cards = max(max_cards, current_sum)

        print(max_cards)

if __name__ == "__main__":
    solve()
```コードは、テスト ケースの数を読み取ることから始まります。 ケースごとに、出現回数をカウントし、一意の数値を並べ替えてから、スライディング ウィンドウを使用して最適な連続した数値セグメントを特定します。 規則に違反しないと連続しない番号を取得できないため、ギャップが検出されるとウィンドウがリセットされます。 ウィンドウを縮小すると、個別の数値の許容数を決して超えることがなくなります。`max_cards`見つかった最適なソリューションを保存します。
