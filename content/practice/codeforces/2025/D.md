 ## 解決策
 ## 問題の理解

 一連のゲーム記録が与えられ、各要素は属性ポイントの獲得または属性チェックの発生を表します。 キャラクターは筋力と知力がゼロから始まります。 シーケンス内のゼロは、強さまたは知力のいずれかに割り当てることができる 1 つの属性ポイントを受け取ることを示します。 正の数値は知力チェックを表します。キャラクターは知力がその値以上であれば合格します。 負の数値も同様に強度チェックを表します。 

目標は、レコードの順序を尊重しながら、パスしたチェックの数を最大化することです。 ポイントを遡って割り当てることはできません。どのポジションでも、以前に獲得したポイントのみが割り当て可能です。 

制約により、レコードは最大 200 万件まで存在できますが、最大で 5000 ポイントになります。 これは、考えられるすべての点の割り当てを単純にシミュレートすることはできないことを意味します。 すべての割り当てを探索するブルートフォースアプローチでは、$2^{5000}$可能性はありますが、それは完全に不可能です。 代わりに、比較的少数の点を利用して状態空間を制限する必要があります。 エッジ ケースには、ポイントの前にすべてのチェックがあり、結果としてゼロ チェックが通過することや、すべてのチェックで 1 つの属性のみが必要であるが、ポイントが 2 つの属性間で分散され、慎重な割り当てが必要になるシーケンスが含まれます。 

たとえば、入力を考えてみましょう`5 2`記録付き`1 -2 0 0 1`。 ここでは、両方のポイントが最初の 2 つのチェックの後に発生します。 順序を考慮せずにポイントを割り当てる単純な貪欲なアプローチは、一部のチェックが合格できると誤って主張することになりますが、正しい答えは、最後の 2 つのチェック (ポイントの後) のみが合格できる可能性があるということです。 

## アプローチ

 ブルートフォース手法では、シーケンスをトラバースするときにポイントを配布するために可能なすべての方法を試行します。 ゼロごとに、Strength または Intelligence を増加させ、チェックごとに合格するかどうかを確認します。 状態の数は$2^m$なぜならそれぞれの$m$ポイントには 2 つの割り当てオプションがあります。 と$m$最大 5000、これはおよその結果をもたらします$10^{1500}$可能性は明らかに大きすぎます。 

重要な観察は、多くのレコードがあるにもかかわらず、潜在的な割り当てに関して重要なのはポイント数だけであるということです。 到達可能なセットを追跡できます`(strength, intelligence)`シーケンスを処理するときにレベルを更新し、チェックに合格するかポイントを取得するたびにカウントを更新します。 動的プログラミングのアプローチは、割り当てられたインテリジェンス ポイントの数に応じて、可能な強度レベルの 1D 配列を保存することによって機能します。 具体的には、`dp[i]`正確に割り当てた場合に通過できるチェックの最大数になります。`i`インテリジェンスを指します。 それから残りの`m-i`ポイントは強度に自動的に割り当てられます。 値が時期尚早に上書きされることを避けるために、一時配列を使用して、レコードを反復処理し、新しいポイントと各チェックを考慮してこの DP 配列を更新します。 

これにより、状態空間が指数関数的に減少します。`m`に`O(m^2)`、これは実現可能です。`m ≤ 5000`。 メモリの使用も制御され、アルゴリズムは次のように線形に拡張されます。`n`サイズの DP 配列を更新するときに各レコードを 1 回だけ処理するためです。`m+1`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^m * n) | O(2^m) | 遅すぎる |
 | 最適 (DP) | O(n * m) | O(m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. DP 配列を初期化する`dp`長さの`m+1`あらゆる価値観で`-1`。 各インデックス`i`割り当てを表します`i`インテリジェンスを指します。 セット`dp[0] = 0`最初に割り当てられたゼロポイントとゼロチェックに合格したことを示します。 
2. 各レコードを反復処理する`r`順番に。 チェックまたはポイントごとに、一時的な DP 配列を維持します`new_dp`更新された値を保存します。 
3. もし`r`ゼロの場合、すべてを繰り返します`i`0から`m`。 それぞれについて`i`と`dp[i] >= 0`、増分`i`この新しいポイントをインテリジェンスと増分に割り当てることを表します`dp[i]`強度に割り当てることを表します。 アップデート`new_dp`どちらの可能性でも、合格したチェックの最大数を維持します。 
4. もし`r`正の数 (インテリジェンス チェック)、反復処理`i`0から`m`。 到達可能なそれぞれについて`i`、インテリジェンス ポイントが割り当てられているかどうかを確認します`i`少なくとも`r`。 「はい」の場合、次の値を増やします。`new_dp[i]`合格した小切手を数える。 それ以外の場合は、変更しないままにしておきます。 
5. もし`r`負の場合 (強度チェック)、繰り返します`i`0から`m`。 到達可能なそれぞれについて`i`、強みポイントが割り当てられているかどうかを確認します`m - i`少なくとも`abs(r)`。 「はい」の場合、次の値を増やします。`new_dp[i]`; それ以外の場合は、変更しないままにしておきます。 
6. レコードを処理した後、次のように置き換えます。`dp`と`new_dp`次のレコードに進みます。 
7. すべてのレコードを処理した後、次の最大値が表示されます。`dp`合格したチェックの最大数を表します。 

維持される不変条件は次のとおりです`dp[i]`常に正確に合格したチェックの可能な限り最良の数を保存します。`i`以前のすべての記録を考慮して、インテリジェンスに割り当てられたポイント。 これにより、ポイントを過剰にカウントしたり、順序の制約を無視したりすることがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
records = list(map(int, input().split()))

dp = [-1] * (m + 1)
dp[0] = 0

for r in records:
    new_dp = [-1] * (m + 1)
    if r == 0:
        for i in range(m + 1):
            if dp[i] == -1:
                continue
            # Assign point to Intelligence
            if i + 1 <= m:
                new_dp[i + 1] = max(new_dp[i + 1], dp[i])
            # Assign point to Strength
            new_dp[i] = max(new_dp[i], dp[i])
    elif r > 0:
        for i in range(m + 1):
            if dp[i] == -1:
                continue
            # Check Intelligence
            passed = dp[i] + (1 if i >= r else 0)
            new_dp[i] = max(new_dp[i], passed)
    else:
        for i in range(m + 1):
            if dp[i] == -1:
                continue
            # Check Strength
            passed = dp[i] + (1 if (m - i) >= -r else 0)
            new_dp[i] = max(new_dp[i], passed)
    dp = new_dp

print(max(dp))
```このコードは、処理ポイントをチェックから分離します。 一時的な`new_dp`配列により、このレコードの更新が同じステップ内の決定に干渉しないことが保証されます。 レコードがゼロの場合、2 つの更新が発生します。1 つは Intelligence に割り当てられ、もう 1 つは暗黙的に Strength に割り当てられます。 チェックの場合、決定は現在の割り当てがしきい値を満たしているかどうかによって決まります。

 | 時間 | O(n * m) | n 個のレコードのそれぞれについて、m+1 個の可能な割り当てを繰り返します。
