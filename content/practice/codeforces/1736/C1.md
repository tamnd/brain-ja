 ## 解決策
 ## 問題の理解

 各要素がサブ配列内のその位置と少なくとも同じ大きさである、指定された配列のすべての連続するサブ配列を数えるように求められます。 より具体的には、サブ配列がインデックスから始まる場合`l`そしてインデックスで終わります`r`、この部分配列の最初の要素は少なくとも 1、2 番目の要素は少なくとも 2、3 番目の要素は少なくとも 3 である必要があります。 これにより、元の配列が一種の「高さ要件」に変換されます。サブ配列内で奥に進むほど、各要素は大きくなければなりません。 

入力は複数のテスト ケースで構成され、各テスト ケースには最大 200,000 要素の配列があり、すべてのテスト ケースのすべての配列の長さの合計は 200,000 を超えません。 これにより、配列の長さが 2 次である解は即座に除外されます。 すべてのサブ配列を個別にチェックする総当り的なアプローチでは、大まかに次のものが必要になります。$n^2/2$到達できる配列ごとのチェック$2 \cdot 10^{10}$最悪の場合の運用。 これは 1 秒の制限時間内では実現不可能です。 したがって、線形または線形に近いアプローチが必要です。 

要素がサブ配列の位置と正確に等しい場合、または要素がサブ配列の位置より小さい場合、微妙なエッジ ケースが発生します。 たとえば、配列`[1,1,1]`単一要素のサブ配列のみを許可します。 単純なアルゴリズムでは、最初または最後の要素のみをチェックする場合、誤って長いサブ配列を有効なものとしてカウントする可能性があるため、位置相対要件に細心の注意を払うことが重要です。 

## アプローチ

 ブルート フォース アプローチは簡単です。すべての可能な開始インデックスを反復処理します。`l`次に、考えられるすべての終了インデックスを反復処理します。`r >= l`、すべての要素が`a[l..r]`満足する`a[l + i] >= i + 1`。 このアプローチは、各サブ配列を明示的にチェックするため、正しいです。 複雑さはテスト ケースごとに O(n^2) ですが、大規模な配列では許容できないほど遅くなります。 たとえば、`n = 2 * 10^5`、大まかに実行します$2 \cdot 10^10$小切手。 

より高速なソリューションのための重要な洞察は、サブ配列条件をより単純な数値条件に変換することで得られます。 で始まるサブ配列の場合`l`、新しい配列を定義します`c[i] = a[i] - (i - l + 1)`。 部分配列は、すべての要素が次の場合にのみ有効です。`c[i]`は非負です。 部分配列を左から右に拡張するとき、最小のものを追跡するだけで済みます。`c[i]`これまで見られた。 いつ`c[i]`が負になると、サブ配列はこの点を超えて拡張できないことがわかります。 これは、2 ポインターまたはスライディング ウィンドウ手法と同等です。`l`、 伸ばす`r`条件が壊れるまで可能な限り、次から始まるすべてのサブ配列を数えます。`l`そして限界点手前で終了。 そうすれば移動できます`l`条件を満たすことが保証されている要素を再チェックすることなく、先に進み続行します。 

この観察により、各インデックスが最大 2 回考慮されるため、配列あたりの複雑さが O(n^2) から O(n) に軽減されます (拡張時に 1 回)。`r`そして進むときに一度`l`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | お(1) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取ります。 テスト ケースごとに、配列の長さを読み取ります。`n`そして配列`a`。 
2. 変数を初期化する`ans`0 に設定すると、良好なサブアレイの数が累積されます。 
3. 2 つのポインターを使用する`l`そして`r`スライディングウィンドウを維持するため。 から始める`l = 0`そして`r = 0`。 
4. ながら`l < n`、増分`r`に限って`a[r] >= r - l + 1`。 これにより、現在のウィンドウ内のすべての要素が「位置ベース」の要件を満たすことが保証されます。 
5.追加`r - l`に`ans`、すべてのサブ配列は で始まるため、`l`そしてその前に終わる`r`有効です。 違い`r - l`開始位置のサブ配列の数を正確にカウントします。`l`。 
6. インクリメント`l`。 もし`r < l`、 セット`r = l`ウィンドウは左ポインタを超えて縮小できないためです。 
7. すべての開始インデックスが考慮されるまで続行します。 
8. 出力`ans`テストケース用。 

機能する理由: 不変条件は、アルゴリズムのどの時点でも、すべての部分配列が`[l, r-1]`良いです、そして`r`サブ配列が要件を満たさない最初のインデックスです。 これにより、すべての有効なサブ配列のみがカウントされることが保証されます。 各要素は最大 2 回評価され、線形の時間計算量が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    
    ans = 0
    r = 0
    for l in range(n):
        if r < l:
            r = l
        while r < n and a[r] >= r - l + 1:
            r += 1
        ans += r - l
    print(ans)
```初期化します`r = 0`ループオーバーの外側`l`これにより、適切な境界を効率的に拡張できるようになります。 条件`if r < l: r = l`次の場合にウィンドウが無効にならないようにします。`l`進歩します。 の`while`ループは、部分配列が位置条件を満たさなくなるまで、右側の境界を貪欲に拡張します。 最後に追加`r - l`から始まるすべてのサブ配列をカウントします。`l`開始インデックスごとに O(1) になります。
