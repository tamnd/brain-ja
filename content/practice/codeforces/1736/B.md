 ## 解決策
 ## 問題の理解

 配列が与えられています`a`。 別の配列が存在するかどうかを知りたい`b`長さの`n + 1`のすべての要素が`a`の 2 つの隣接する要素の GCD です。`b`:

 [
 a_i = \gcd(b_i, b_{i+1})
 】

 あらゆるポジションに。 

課題は、試行錯誤によって任意の有効なシーケンスを構築することではありません。 このようなシーケンスが少なくとも 1 つ存在するかどうかを判断するだけで済みます。 

すべてのテスト ケースにわたるすべての配列の合計長は、最大で (10^5) です。 これにより、(b) の考えられる値に対する検索が即座に除外されます。 二次アルゴリズムですら危険です。 テスト ケースごとに線形または線形に近いソリューションが必要です。 

微妙な点は、隣接する GCD 要件が相互作用することです。 満足

 [
 \gcd(b_i,b_{i+1})=a_i
 】

 そして

 [
 \gcd(b_{i+1},b_{i+2})=a_{i+1}
 】

 同時に共有値 (b_{i+1}) に制限を加えます。 ローカルな選択により、隣接する制約が簡単に破られる可能性があります。 

次のことを考慮してください。 

[
 a=[4,2,4]
 ]

 答えは`NO`。 単純なアプローチでは、すべての隣接するペアが互換性があるように見えることに気づき、誤って受け入れてしまう可能性があります。 中央の GCD は、隣接する GCD の 1 つを必要以上に大きくする要因を共有値に強制的に含めます。 

もう 1 つの重要なエッジ ケースは (n=1) です。 任意の正の整数は 2 つの等しい数の GCD として実現できるため、答えは常に次のようになります。`YES`。 

たとえば:

 [
 a=[343]
 ]

 (b=[343,343])を選択します。 

## アプローチ

 ブルートフォース戦略では、(b) の値を直接構築しようとします。 (b) のエントリは有効な方法で制限されていないため、検索スペースは膨大です。 候補を近くの値の約数に制限しても、実用的なアルゴリズムにはなりません。 

重要な観察は、標準的な候補シーケンスが存在するということです。 

すべての GCD 値がすでにわかっていると仮定します。 両方に参加する必要がある番号

 [
 a_i=\gcd(b_i,b_{i+1})
 ]

 そして

 [
 a_{i+1}=\gcd(b_{i+1},b_{i+2})
 ]

 両方の隣接する制約で必要なすべての素因数を含める必要があります。 そのような最小の選択は、

 [
 \演算子名{lcm}(a_i,a_{i+1})。 
]

 これは構造を示唆しています

 [
 b_1=a_1、
 ]

 [
 b_{n+1}=a_n、
 ]

 そして社内ポジションについては

 [
 b_i=\オペレーター名{lcm}(a_{i-1},a_i)。 
]

 有効なシーケンスが存在する場合、この構造が最も有力な候補となります。 次に、必要な GCD がすべて実際に再現されるかどうかを単純に検証します。 

すべての位置 (i) について、計算します。 

[
 \gcd(b_i,b_{i+1})。 
]

 どこでも (a_i) に等しい場合、答えは次のようになります。`YES`。 それ以外の場合はそうです`NO`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | 指数 | 遅すぎる |
 | LCM構築+検証 | (O(n \log V)) | (O(n)) | 承認済み |

 ここで (V) は配列の最大値です。 

## アルゴリズムのチュートリアル

 1. 配列を読み取ります (a)。 
2. (n=1) の場合、答えます`YES`。 
3. 補助配列を構築します (b)。 

セット

 [
 b_1=a_1、
 \qquad
 b_{n+1}=a_n。 
]
 4. すべての内部位置 (2 \le i \le n) に対して、次のように設定します。 

[
 b_i=\オペレーター名{lcm}(a_{i-1},a_i)。 
]

 これは、両方の隣接する GCD 要件で同時に割り切れる最小値です。 
5. すべての (i) について、計算します。 

[
 g_i=\gcd(b_i,b_{i+1})。 
]
 6. あれば (g_i \ne a_i) と答えてください`NO`。 
7. それ以外の場合は回答してください`YES`。 

### なぜ効果があるのか

 (b) のすべての内部要素は、両方の隣接する GCD 値で割り切れる必要があります。 最小公倍数は、その性質を持つ最小の数です。 

LCM 構築によって、ある位置で必要な値よりも大きな GCD がすでに生成されている場合、他のすべての有効な候補には少なくとも同じ素因数が含まれており、その GCD を目的の値に戻すことはできません。 したがって、この構造の失敗は不可能であることを証明します。 

逆に、計算されたすべての GCD がターゲット配列と一致する場合、構築されたシーケンス自体が有効な証人になります。 したがって、このテストは必要かつ十分です。 

## Python ソリューション```python
import sys
from math import gcd

input = sys.stdin.readline

def lcm(a, b):
    return a // gcd(a, b) * b

t = int(input())

for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))

    b = [0] * (n + 1)
    b[0] = a[0]
    b[n] = a[-1]

    for i in range(1, n):
        b[i] = lcm(a[i - 1], a[i])

    ok = True

    for i in range(n):
        if gcd(b[i], b[i + 1]) != a[i]:
            ok = False
            break

    print("YES" if ok else "NO")
```構築フェーズでは、内部ポジションに LCM 値が埋められます。 検証フェーズでは、必要なすべての GCD を 1 回だけチェックします。 

LCM公式

 [
 \演算子名{lcm}(x,y)=\frac{x}{\gcd(x,y)}y
 ]

 固定サイズの整数を使用する言語でのオーバーフローの問題を回避します。 Python は大きな整数を自動的に処理しますが、同じ式が標準的な方法です。 

インデックス作成は、オフバイワンの間違いがよく発生する唯一の場所です。 補助配列の長さは (n+1) ですが、元の配列の長さは (n) です。 

## 実用的な例

 ### 例 1

 [
 a=[4,2]
 ]

 構築:

 | ポジション | 値 |
 | --- | --- |
 | (b_1) | 4 |
 | (b_2) | lcm(4,2)=4 |
 | (b_3) | 2 |

 検証:

 | チェック | 値 |
 | --- | --- |
 | gcd(4,4) | 4 |
 | gcd(4,2) | 2 |

 どちらもターゲット配列と一致します。 

答え：`YES`。 

### 例 2

 [
 a=[4,2,4]
 ]

 構築:

 | ポジション | 値 |
 | --- | --- |
 | (b_1) | 4 |
 | (b_2) | 4 |
 | (b_3) | 4 |
 | (b_4) | 4 |

 検証:

 | チェック | 値 |
 | --- | --- |
 | gcd(4,4) | 4 |
 | gcd(4,4) | 4 |
 | gcd(4,4) | 4 |

 中央の値は 2 であるはずですが、4 になります。 

答え:`NO`。 

この例は、ローカル互換性だけでは十分ではない理由を示しています。 共有要素により、中央の GCD が要求された値よりも大きくなります。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(n \log V)) | 各 LCM および GCD の計算には対数的な時間がかかります。 
| スペース | (O(n)) | 補助配列 (b) |

 すべての (n) 値の合計は最大でも (10^5) であるため、アルゴリズムは容易に制限内に収まります。

 ## 特殊なケース

 (n=1) の場合、アルゴリズムは (b=[a_1,a_1]) を構築します。 検証ステップでは、(a_1) に等しい 1 つの GCD を正確に計算します。 答えはいつも`YES`。 

隣接する値が互いに分割する配列の場合、次のようになります。 

[
 [8,4,2]、
 ]

 LCM 構造は次のようになります。 

[
 [8,8,4,2]。 
]

 すべての検証 GCD はターゲット配列と一致するため、アルゴリズムは正しく受け入れます。 

次のような配列の場合

 [
 [4,2,4]、
 ]

 この構造では、両側から係数 (2^2) を強制的に含めた中間値が生成されます。 検証により、結果の GCD が (2) ではなく (4) であることが検出され、有効なシーケンスが存在しないことが証明されます。
