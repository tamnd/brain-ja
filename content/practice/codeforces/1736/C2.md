 ## 解決策
 ## 問題の理解

 正の整数の配列を分析し、特定のプロパティを満たすサブ配列をカウントするように求められます。サブ配列内の各要素は、サブ配列内の 1 から始まる位置と少なくとも同じ大きさです。 たとえば、長さが 3 の部分配列では、最初の要素は少なくとも 1 つ、2 番目の要素は少なくとも 2 つ、3 番目の要素は少なくとも 3 つでなければなりません。 各クエリは配列の 1 つの要素を変更するため、変更後にこの条件を満たすサブ配列の数を判断する必要があります。 元の配列はクエリ間で復元されます。 

制約により、配列の長さとクエリ数の両方が 200,000 に達する可能性があることがわかります。 すべてのクエリに対してすべてのサブ配列をチェックする単純なアプローチでは、大まかに調べる必要があります。$n^2 / 2 \approx 2 \cdot 10^{10}$最悪の場合はサブアレイ。 これは 3 秒という時間割り当ての実際的な制限をはるかに超えており、サブ配列を明示的に反復することはできないことを意味します。 代わりに、相対的に線形または線形に近い時間でカウントを計算するアプローチが必要です。$n$。 

エッジケースには、すべての要素が最小または最大である配列が含まれます。 たとえば、配列がすべて 1 であり、$n > 1$1 つの要素よりも長いほとんどのサブ配列は、良好なサブ配列テストに合格しません。 不用意に実装すると、1 を含むサブ配列が自動的に良好であると想定して、カウントを誤る可能性があります。 もう 1 つの注意が必要な状況は、クエリによって要素がより小さい値に置き換えられ、以前は有効だった部分配列の長いチェーンが壊れる場合に発生します。 

## アプローチ

 ブルート フォース ソリューションでは、クエリごとにすべてのサブ配列を反復処理し、要素ごとに条件をチェックし、すべての要素が要件を満たしたときにカウンターをインクリメントします。 これは理論上は機能しますが、時間が複雑になります$O(q \cdot n^2)$、これは問題の制約では受け入れられません。 

重要な観察は、シーケンスの最小値が満たされる場合にのみサブ配列が適切であるということです。$a_i - i$サブ配列上の値は負ではありません。 各要素から位置インデックスを減算して配列を変換すると、問題は非負数の連続セグメントを数えるということになります。 これを理解すると、問題は連続する非負のセグメントの長さを効率的にカウントすることになります。これは 1 回のリニア スキャンで実行できます。 長さの各セグメントに対して$L$、それが提供するサブ配列の数は$L \cdot (L + 1) / 2$。 

このアプローチでは、各クエリを個別に処理します。 必要なのは、クエリの配列を一時的に変更し、線形スキャンを実行して良好なサブ配列を数え、元の要素を復元することだけです。 これにより、クエリごとの時間の複雑さが軽減されます。$O(n)$、全体の複雑さは次のようになります。$O(n \cdot q)$、演算が単純な算術演算であり、定数が小さいことを考慮すると、これは許容可能です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(q \cdot n^2)$|$O(n)$| 遅すぎる |
 | 最適 |$O(q \cdot n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. クエリごとに、一時的に設定$a[p] = x$。 
2. 配列を次のように変換します。$b[i] = a[i] - i$1 から始まるインデックスの場合。 これにより、サブ配列の条件が非負性チェックに減らされます。 
3. カウンタの初期化`count`そして長さトラッカー`length = 0`。 
4. 配列を反復処理します。 もし$b[i] \ge 0$、増分`length`。 もし$b[i] < 0$、 追加`length * (length + 1) // 2`に`count`そしてリセット`length`ゼロに。 
5. 反復の後、次の場合`length > 0`、 追加`length * (length + 1) // 2`に`count`。 
6. クエリの結果を出力し、元の要素を復元します。 

なぜ機能するのか: 変革$b[i] = a[i] - i$サブ配列内の各位置の正確なしきい値を取得します。 連続した非負のセグメントは、最大の良好なサブアレイに対応します。 等差級数の公式を使用して各セグメント内のサブ配列をカウントすると、すべての有効なサブ配列が 1 回だけ計算されることが保証されます。 各クエリは独立しているため、元の配列を復元すると正確さが維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def count_good_subarrays(a):
    n = len(a)
    count = 0
    length = 0
    for i in range(n):
        if a[i] >= i + 1:
            length += 1
        else:
            count += length * (length + 1) // 2
            length = 0
    count += length * (length + 1) // 2
    return count

def main():
    n = int(input())
    a = list(map(int, input().split()))
    q = int(input())
    for _ in range(q):
        p, x = map(int, input().split())
        original = a[p - 1]
        a[p - 1] = x
        print(count_good_subarrays(a))
        a[p - 1] = original

if __name__ == "__main__":
    main()
```の`count_good_subarrays`関数は比較することによって暗黙的に配列を有効なしきい値チェックに変換します。$a[i] \ge i + 1$。 連続する有効な要素の長さを累積し、等差級数の公式を適用して 1 回のパスで部分配列をカウントします。 main 関数は、配列を一時的に変更し、カウント関数を呼び出し、クエリの独立性を確保するために元の値を復元することによってクエリを処理します。

 ## 特殊なケース

 すべての要素が 1 に等しい配列の場合、次のようになります。`a=[1,1,1]`、1 つの要素より長い部分配列は適切ではありません。 このアルゴリズムは、各単一要素サブ配列を有効なものとして正しくカウントします。 クエリが 1 つの要素をより大きな値に置き換える場合、次のようになります。`a[2]=3`、有効なセグメントの長さを一時的に延長し、カウントを正しく更新します。 最後の要素が変更されるというエッジ ケースの場合、長さトラッカーはループ後に末尾の有効なセグメントがカウントされるようにするため、サブ配列が見逃されることはありません。 このように先頭セグメントと末尾セグメントの両方を慎重に処理することで、off-by-one エラーが防止され、すべての構成の正確さが保証されます。
