 ## 問題の理解

 円形配列が与えられ、非常に具体的な走査ルールを繰り返しシミュレートします。 開始位置を選択します`s`固定ジャンプ長`k`。 から始まる`s`、私たちは正確に歩きます`n`ステップ。 各ステップで現在の配列値がスコアに加算され、次に次のように進みます。`k`位置のモジュロ`n`。 配列は円形であるため、最後に到達した後は最初から続行します。 

したがって、それぞれの選択は、`(s, k)`正確に訪問する決定論的なウォークを定義します`n`位置、場合によっては構造化されたパターンを繰り返す可能性があります`k`。 課題は両方を選択することです`s`そして`k`訪問した値の合計を最大化します。 配列内の各点が更新された後、この最大値を再計算する必要があります。 

重要な構造的制約は次のとおりです。`k`の間にあります`1`そして`n-1`したがって、1 ステップですべてをリセットする完全な単純なラップを取得することはできません。 誘発された散歩`(s, k)`配列を長さのサイクルに分割します`n / gcd(n, k)`、そして完全な`n`ステップは、これらのサイクル全体ですべてのノードを 1 回だけ通過します。 

この制約により、あらゆる解決策がすべてを試みる体制に私たちは追い込まれます。`(s, k)`クエリごとのペアは不可能です。 がある`O(n^2)`テスト ケースごとの状態、および 1 つのウォークの評価でも、`O(n)`、与える`O(n^3)`全体的に見て、これは完全に不可能です。 

さらに微妙な制約は、更新が動的であるということです。 たとえ静的なソリ​​ューションがあったとしても、更新ごとに最初から再計算すると、やはり時間がかかりすぎます。 

一般的な障害モードは、最良の答えが常に 1 つの固定された答えから得られると想定していることです。`k`のように`1`または`n/2`。 たとえば、配列が次の場合、`[1, 100, 1, 1]`、`k = 2`訪問インデックス`{1,3}`そして`{2,4}`開始に応じて個別に分割され、連続するセグメントのみを考慮する単純な解決策ではその構造が欠落します。 

## アプローチ

 ブルートフォースソリューションでは、すべてを反復処理することになります。`(s, k)`ペア。 ペアごとに、歩行をシミュレートします。`n`ステップを実行して合計を計算します。 これにより目的は正しく評価されますが、テスト ケースあたりのコストは次のようになります。`O(n^3)`。 

重要な観察は、`k`インデックスを次のように決定されるサイクルに分割します。`g = gcd(n, k)`。 各サイクルは独立しており、開始位置によってのみサイクルのどの要素から開始するかが決まります。 を完全に横断して、`n`ステップでは、すべてのサイクルを完全に取得するため、固定の寄与は`k`はすべてのサイクルの合計ですが、各サイクル内で最適な回転開始を自由に選択できます。 

これにより、問題は、`k`、最適な巡回接尾辞合計の動作を最大化する方法。 すべてを列挙するのではなく、`k`、グループ化します`g = gcd(n, k)`。 全て`k`同じように`g`同じサイクル構造を引き起こします。 

したがって、問題は各約数の維持に帰着します。`g`の`n`、各剰余クラスのモジュロから 1 つの要素を選択することによって形成されたシーケンスにわたる最良の循環最大合計`g`。 各更新は、1 つにつき 1 つの残差クラスにのみ影響します。`g`。 

すべての約数について維持します`g`、各剰余クラスのモジュロの合計`g`。 固定の場合`g`、答えは、ある長さにわたる最大の巡回部分配列の合計です。`n/g`これらのクラスの合計によって形成されるシーケンス。 グローバルな答えはすべての最大値です`g`。 

なぜなら`n`多くても`O(sqrt(n))`約数を増やすと、これらの構造を効率的に維持できます。

 ## アルゴリズムのチュートリアル

 1. すべての約数を事前計算します。`n`。 各約数`g`は、同一のサイクル構造を持つステップ サイズのクラスを表します。 これにより、あらゆる問題から生じるスペースが削減されます。`k`構造的代表者のみに。 
2. 各約数について`g`、配列を維持する`sum[g][r]`インデックスが一致する要素の合計を表す`r mod g`。 これは、その構造の各残差クラスの寄与をエンコードします。 
3. それぞれについて`g`、その値を超えて最良の循環アライメント値を維持します。`n/g`残留バケツ。 これは、循環最大部分配列合計動作をサポートするマルチセットまたはセグメント構造を使用して追跡できます。 
4. すべて初期化する`sum[g][r]`の初期配列から`O(n √n)`除数を反復処理することによって。 
5. 位置の更新ごとに`p`、すべての約数構造を調整します。`g`、更新します`sum[g][p mod g]`古い値を減算し、新しい値を加算します。 
6. 残差バケットを更新した後、そのバケットに対する影響を受ける最大寄与率を再計算します。`g`。 変更されるバケットは 1 つだけであるため、償却後の最良の循環合計を更新できます。`O(1)`または`O(log n)`構造によります。 
7. 全体にわたって世界最大値を維持する`g`各アップデートの後、それが答えです。 

### なぜ効果があるのか

 固定する`k`と`g = gcd(n, k)`トラバースが次のように分解されることを意味します`g`それぞれの長さの独立したサイクル`n/g`。 合計スコアは、サイクルごとに 1 つの要素を選択した合計であり、サイクリングにより最適な回転を選択できます。 これは、剰余クラスの合計の最適な巡回順序を選択することと同じです。 すべて有効なので、`k`正確に 1 つの約数にマッピングされます`g`、そのようなすべての構造がカバーされ、すべての構造の最大値が取られます。`g`最適なプログラムをキャプチャします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def get_divisors(n):
    ds = []
    i = 1
    while i * i <= n:
        if n % i == 0:
            ds.append(i)
            if i * i != n:
                ds.append(n // i)
        i += 1
    return ds

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n, q = map(int, input().split())
        a = list(map(int, input().split()))

        divs = get_divisors(n)

        # sum[g][r]
        sum_gr = {g: [0] * g for g in divs}

        for i, val in enumerate(a):
            for g in divs:
                sum_gr[g][i % g] += val

        def calc_g(g):
            arr = sum_gr[g]
            m = len(arr)
            # best cyclic subarray sum over one rotation array
            best = -10**30

            # duplicate for circular handling
            b = arr * 2

            cur = 0
            length = 0
            start = 0

            # classic kadane over length m window
            dq = []
            cur_sum = 0
            left = 0

            for right in range(2 * m):
                cur_sum += b[right]
                if right - left + 1 > m:
                    cur_sum -= b[left]
                    left += 1
                if right - left + 1 == m:
                    best = max(best, cur_sum)

            return best

        best_global = max(calc_g(g) for g in divs)
        out.append(str(best_global))

        for _ in range(q):
            p, x = map(int, input().split())
            p -= 1
            old = a[p]
            a[p] = x

            for g in divs:
                r = p % g
                sum_gr[g][r] += x - old

            best_global = max(calc_g(g) for g in divs)
            out.append(str(best_global))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```実装では、次の約数ごとに剰余クラスの集合体を構築します。`n`。 各更新では、除数ごとに 1 つの剰余エントリが変更されます。 機能`calc_g`サイズのウィンドウをスライドさせて、その除数の最適な循環セグメント合計を再計算します。`n/g`すべての循環回転をキャプチャする 2 倍の配列にわたって実行されます。 

微妙な点は、再計算することです。`calc_g`各更新後のすべての約数について。 ここではこれ以上最適化されていませんが、約数の総数は集約制約内で十分小さいため、これは許容可能なままです。 

## 実用的な例

 小さな配列を考えてみましょう`a = [1, 2, 3, 4]`と`n = 4`。 

約数は`1, 2, 4`。 のために`g = 2`、残差の合計は`[1+3, 2+4] = [4, 6]`。 長さの最適な循環ウィンドウ`n/g = 2`は`4+6 = 10`。 これは、これら 2 つのクラス間で交互にステップ サイズを選択することに対応します。 

のために`g = 1`、私たちは得ます`[10]`、自明に譲ります`10`。 全体を通しての最大値`g`は`10`。 

今すぐアップデートを適用してください`a[2] = 10`、したがって配列は次のようになります`[1, 2, 10, 4]`。 

のために`g = 2`、残差合計は次のようになります`[1+10, 2+4] = [11, 6]`、最適なウィンドウサムを与える`17`。 これは、単一の更新が除数ごとに 1 つの剰余バケットにのみ影響を及ぼしますが、最適な構造を大幅に変更する可能性があることを示しています。 

トレースは、各約数が配列を独立した循環グループに圧縮し、その合計が答えを決定することを示しています。

 ## 特殊なケース

 コーナーケースが発生するのは次の場合です`n`プライムです。 この状況では、約数は次のとおりです。`1`そして`n`, そのため、構造は配列全体または単一要素の剰余クラスのいずれかに折りたたまれます。 このアルゴリズムは、非常に少数の構成をチェックすることになり、各位置が各残基クラスに一意にマッピングされるため、更新は予測可能な方法で両方の構造に影響を与えます。 

もう 1 つの特殊なケースは、すべての値が同一である場合です。 すべての剰余クラスの合計は均一にスケールされ、すべての除数は同じ循環ウィンドウの合計を生成します。 最大値は、単一の値が変更されない限り、更新全体で一定のままです。変更された場合、影響を受けるすべての除数構造は、候補の順序を変更せずに均一にシフトします。 

最後の微妙なケースは、高度に複合されたシステム内の単一要素の更新です。`n`。 この更新はすべての除数構造に同時に影響しますが、除数ごとに 1 つの剰余インデックスのみが影響します。 このアルゴリズムは残差の集計を直接維持するため、影響を受けない部分を再計算することなく各構造が一貫して更新され、更新が繰り返されても正確さが維持されます。
