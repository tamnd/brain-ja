 ## 解決策
 ## 問題の理解

 文字列自体は与えられません。 代わりに、アルファベットの各文字が何回出現するかがわかります。 

フィボナッチ文字列は、等しい文字の連続したブロックから構築されます。 それらのブロックの長さは次のようにする必要があります。 

1、1、2、3、5、8、...

 その正確な順序で、あるフィボナッチ数で停止します。 異なるブロックは隣接するブロックとは異なる文字を使用する必要があります。使用しないと、より大きなブロックに結合されてしまいます。 

問題は、文字頻度のマルチセットを何らかのフィボナッチ文字列に再配置できるかどうかです。 言い換えれば、各文字が指定された頻度と正確に同じ回数使用されるように、フィボナッチ サイズのブロックを文字に割り当てることができるでしょうか?

 周波数は次のように大きくなります。$10^9$, しかし、文字の種類は最大でも 100 種類です。 テストケースの総数は、$10^4$。 

最初の観察は、文字列の合計の長さが固定されていることです。$$S = \sum c_i$$文字列がフィボナッチの場合、$S$最初のいくつかのフィボナッチ数の合計と等しくなければなりません。 

フィボナッチ数は指数関数的に増加するため、合計を最大にするには可能な限り最大のフィボナッチ インデックスが必要です。$100 \cdot 10^9$これは、頻度がどれほど大きいかに関係なく、すべてのテスト ケースに含まれるフィボナッチ値は数十個だけであることを意味します。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

考慮する：```
k = 2
c = [1, 2]
```全長は 3 です。これは、$1+1+2$。 不注意な解決策を講じると、すぐに「YES」と答える可能性があります。 実際、答えは「NO」です。 隣接するブロックは同じ文字を使用できないため、長さ 1 の 2 つのブロックは異なる文字に属している必要があります。 これら 2 つの単位ブロックを割り当てた後は、有効な割り当ては残りません。 

別の例は次のとおりです。```
k = 2
c = [2, 1]
```これは「はい」です。 さまざまな長さのブロックを使用できます$1,1,2$として：```
b a a
```ここで、頻度 2 の文字はサイズ 2 のブロックを受け取ります。 

より微妙なケースは次のとおりです。```
k = 3
c = [3,1,3]
```全長は 7 で、次と同じです。$1+1+2+3$。 多くの誤った解決策は、周波数をフィボナッチ数に分解できるかどうかのみをチェックします。 ブロック消費の順序が重要であるため、答えは依然として「NO」です。 構築中に、残っている最大のフィボナッチ ブロックが、前のステップで使用された文字上に強制的に配置される可能性がありますが、これは禁止されています。 

重要な問題は、合計が一致しないことです。 ブロック割り当ての順序を尊重しながら合計を照合します。 

## アプローチ

 ブルート フォース ビューでは、最初に全長がすべての周波数の合計に等しいフィボナッチ ブロックを決定します。 次に、隣接するブロックが異なる文字を使用し、各周波数が正確に使用されていることを確認しながら、ブロックの文字への可能なすべての割り当てを試します。 

これは、有効なフィボナッチ文字列の空間を直接検索するため、明らかに正しいです。 残念ながら絶望的に遅いです。 フィボナッチ ブロックが 40 個しかない場合でも、各ブロックを最大 100 文字のいずれかに割り当てると、膨大な検索スペースが作成されます。 

フィボナッチ数の構造は、より強力な観察を提供します。 

合計が等しいと仮定します$$f_1+f_2+\cdots+f_m.$$一番大きなブロックは、$f_m$。 有効な構造では、何らかの文字がこのブロックのすべての文字を提供する必要があります。 その文字には少なくとも頻度が必要です$f_m$。 

次に、建設を後ろから見てみましょう。 文字が最大のブロックを提供する場合、次の値を差し引くことができます。$f_m$その周波数から。 そのブロックを使用した後、次のブロック$f_{m-1}$連続するブロックは異なる文字に対応する必要があるため、同じ文字に割り当てることはできません。 

これにより、非常に自然な貪欲なプロセスが作成されます。 

すべてのステップで、残っている最大のフィボナッチ ブロックを配置する必要があります。 それをカバーできるほど大きな周波数がない場合、答えは不可能です。 すべての周波数の中で、利用可能な最大の周波数にブロックを割り当てることが常に安全です。 有効なソリューションでは、現在のフィボナッチ ブロックをどこかに配置する必要があり、最大のパイルを使用することで、将来の柔軟性が最大になります。 

唯一の追加の制約は、同じ文字が 2 つの連続するフィボナッチ ブロックを受け取ることができないことです。 前のステップでどの周波数が使用されたかを追跡し、それを一時的に禁止します。 

結果として得られるアルゴリズムは、最大の有効な周波数を繰り返し削除し、現在のフィボナッチ ブロックを減算し、残りを再挿入します。 

これはまさに受け入れられている貪欲な解決策です。

 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | 指数 | 遅すぎる |
 | 最適 |$O(k \log k)$テストケースごと |$O(k)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 周波数の総和を計算します。$S$。 
2. フィボナッチ数を生成する$1,1,2,3,5,\dots$累積合計がそれを超えるまで$S$。 
3. 累積合計が等しくない場合$S$、出力`"NO"`。 

長さのフィボナッチ文字列$S$最初のいくつかのフィボナッチ ブロック サイズを正確に使用する必要があります。 これ以外の全長はあり得ません。 
4. フィボナッチ ブロックを生成されたシーケンスとし、最大から最小の順に処理します。 
5. すべての周波数を最大ヒープに保存します。 
6. 前のフィボナッチ ブロックに使用された文字のインデックスを維持します。 
7. 現在のフィボナッチブロックサイズについて$f$、以前に使用した文字と異なる文字を持つ最大の周波数を抽出します。 

そのような周波数が存在しない場合は、出力`"NO"`。 
8. その周波数が以下の場合$f$、出力`"NO"`。 

利用可能な最大の周波数は現在のブロックをカバーできないため、他の周波数もカバーできません。 
9. 減算$f$その周波数から残りがまだ正であれば、残りをヒープに押し戻します。 
10. この文字を以前に使用した文字としてマークし、次のフィボナッチ ブロックに進みます。 
11. すべてのフィボナッチ ブロックが正常に割り当てられた場合、出力`"YES"`。 

### なぜ効果があるのか

 重要な不変条件は、フィボナッチ ブロックを処理する前に$f_i$、ヒープには残りの未使用の周波数が正確に含まれます。 

常に現在の最大のフィボナッチ ブロックを割り当てます。 有効な解決策では、残りの頻度が少なくとも次の文字を選択する必要があります。$f_i$。 すべての適格な文字の中で、残りの最大の頻度を取得することは、より小さい頻度はすべてそのまま残されるため、安全です。 対象となる最大の周波数ではカバーできない場合$f_i$、対象となる周波数はありません。 

唯一の追加の制限は、連続するブロックが同じ文字に属してはいけないことです。 アルゴリズムは、前のステップで使用された文字を禁止することで、これを明示的に強制します。 

貪欲な選択によって有効な解決策が犠牲になることはありません。 証明は、公式の解決策で使用されているのと同じ交換引数に従います。有効な構造が代入するたびに、$f_i$より大きな適格な周波数が存在する間に、より小さな適格な周波数に変更しても、将来のすべてのフィボナッチ ブロックが小さくなるため、これらの割り当てを交換しても後のステップが難しくなることはありません。 

結果として、貪欲なプロセスの失敗は、考えられるすべての構築の失敗を意味します。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    t = int(input())

    fib = [1, 1]
    pref = [1, 2]

    LIMIT = 100 * 10**9
    while pref[-1] < LIMIT:
        fib.append(fib[-1] + fib[-2])
        pref.append(pref[-1] + fib[-1])

    out = []

    for _ in range(t):
        k = int(input())
        c = list(map(int, input().split()))

        total = sum(c)

        pos = -1
        for i, s in enumerate(pref):
            if s == total:
                pos = i
                break
            if s > total:
                break

        if pos == -1:
            out.append("NO")
            continue

        blocks = fib[:pos + 1]

        pq = []
        for idx, x in enumerate(c):
            heapq.heappush(pq, (-x, idx))

        last = -1
        ok = True

        for need in reversed(blocks):
            first = heapq.heappop(pq)

            if first[1] == last:
                if not pq:
                    ok = False
                    break

                second = heapq.heappop(pq)

                if -second[0] < need:
                    ok = False
                    break

                rem = -second[0] - need

                heapq.heappush(pq, first)

                if rem:
                    heapq.heappush(pq, (-rem, second[1]))

                last = second[1]
            else:
                if -first[0] < need:
                    ok = False
                    break

                rem = -first[0] - need

                if rem:
                    heapq.heappush(pq, (-rem, first[1]))

                last = first[1]

        out.append("YES" if ok else "NO")

    sys.stdout.write("\n".join(out))

solve()
```最初の部分では、フィボナッチ数とそのプレフィックスの合計を事前計算します。 すべてのテスト ケースで同じシーケンスが使用されるため、これは 1 回だけ実行されます。 

各テスト ケースでは、最初に合計頻度がフィボナッチ プレフィックスの合計と一致することを確認します。 そうでない場合は、フィボナッチ文字列の可能性はありません。 

ヒープにはペアが格納されます`(-frequency, index)`そのため、Python の最小ヒープは最大ヒープのように動作します。 インデックスは文字を識別し、「前のブロックと異なる」条件を強制できるようにします。 

最大の周波数が以前に使用された文字に属している場合、それを一時的に削除し、代わりに 2 番目に大きい周波数を検査します。 これは、残りのすべての周波数に勝てる唯一の候補です。 その周波数でも現在のフィボナッチブロックをカバーできない場合、構築は不可能です。 

微妙な点の 1 つは、続行する前に一時的に削除した要素を再挿入することです。 この手順を忘れると、ヒープの状態が静かに破損します。 

もう 1 つの詳細は、ゼロに減少した周波数が押し戻されないことです。 ゼロ頻度のエントリを保持しても正確性は損なわれませんが、不必要なヒープ操作が発生します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(k \log k)$| 各周波数は一定の回数だけヒープに入り、ヒープから出ます。 
| スペース |$O(k)$| ヒープストアは最大でも$k$周波数 |

 合計頻度合計が最大で 50 であるため、フィボナッチ ブロックの数は 50 未満です。$10^{11}$。 と$k \le 100$、ヒープ操作は非常に安価です。 越えても$10^4$テスト ケースでは、ソリューションは制限内に問題なく収まります。 

## テストケース```python
import sys, io
import heapq

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())

    fib = [1, 1]
    pref = [1, 2]

    LIMIT = 100 * 10**9
    while pref[-1] < LIMIT:
        fib.append(fib[-1] + fib[-2])
        pref.append(pref[-1] + fib[-1])

    ans = []

    for _ in range(t):
        k = int(input())
        c = list(map(int, input().split()))

        total = sum(c)

        pos = -1
        for i, s in enumerate(pref):
            if s == total:
                pos = i
                break
            if s > total:
                break

        if pos == -1:
            ans.append("NO")
            continue

        pq = [(-x, i) for i, x in enumerate(c)]
        heapq.heapify(pq)

        last = -1
        ok = True

        for need in reversed(fib[:pos + 1]):
            a = heapq.heappop(pq)

            if a[1] == last:
                if not pq:
                    ok = False
                    break

                b = heapq.heappop(pq)

                if -b[0] < need:
                    ok = False
                    break

                heapq.heappush(pq, a)

                rem = -b[0] - need
                if rem:
                    heapq.heappush(pq, (-rem, b[1]))

                last = b[1]
            else:
                if -a[0] < need:
                    ok = False
                    break

                rem = -a[0] - need
                if rem:
                    heapq.heappush(pq, (-rem, a[1]))

                last = a[1]

        ans.append("YES" if ok else "NO")

    return "\n".join(ans)

 次のことを考慮してください。```

2

```全長は 3 で、フィボナッチ接頭辞と一致します。$1+1+2$。 アルゴリズムは最初にブロック 2 を処理し、それを周波数 2 に割り当てます。残りの周波数 1 は同じ文字に属しているため、最後の単位ブロックを割り当てることができません。 アルゴリズムは NO を返します。 これにより、合計をチェックするだけのソリューションが捕捉されます。
