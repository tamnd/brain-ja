 ## 解決策
 ## 問題の理解

 同じサイズの 2 つの長方形グリッドが与えられ、各グリッドには色付きのセルが含まれています。 許可される操作は、行全体を交換するか列全体を交換することだけです。 目的は、これらの行と列の置換のみを使用して最初のグリッドを 2 番目のグリッドに変換できるかどうかを判断し、変換できる場合は、そのような交換の有効なシーケンスを構築することです。 

主要な構造上の制約は、各グリッド内で、すべての行とすべての列にゼロ以外の色の繰り返しが含まれていないことです。 これにより、各色はグリッド全体で一意に識別可能なマーカーのように動作します。自由に繰り返すことができる中間色のゼロを除いて、各色は行または列に最大 1 回しか表示されないからです。 言い換えれば、ゼロ以外のすべての色は、両方のグリッド内で一意のセル位置を定義します。 

この制約により、合計 2·10^5 セルまでが許可されるため、グリッド上で行と列の交換を直接シミュレートしようとするソリューションは即座に除外されます。 有効なアプローチでは、構造を色の位置に関する順列問題に近いものに圧縮する必要があります。 

行を個別に、または列を個別に照合しようとすると、微妙な失敗が発生します。 たとえば、列の一貫性を考慮せずに行パターンを貪欲に一致させると、一部の色は正しく整列しますが、列の配置に矛盾が生じる行の並べ替えが生成される可能性があります。 もう 1 つのよくある間違いは、行と列が共有の色の位置を通じて相互作用するため、独立して解決できないことを無視することです。 

2 つの同一の行が列の異なる順序で存在する単純な図を考えてみましょう。 行のみのマッチング手法は、行を正しくマッピングすることには成功する可能性がありますが、列の位置が一貫していない場合は失敗します。これは、同じ色が異なる列インデックスになるためです。 

重要な問題は、行と列の置換が独立してではなく、グローバルに一貫していなければならないことです。 

## アプローチ

 強引な解釈は、行と列のすべての置換を試みることを考えることです。 考えられるすべての行の置換と列の置換を試み、それらを適用するとグリッド a がグリッド b に変換されるかどうかを確認します。 行スワップはすべての行の置換を生成し、列スワップはすべての列の置換を生成するため、これは原理的には正しいですが、可能性の数は n です。 ・中サイズでも天文学的な大きさのm!。 

重要な観察は、色の独自性の構造から得られます。 ゼロ以外の色はすべて、各行と列に 1 回ずつ出現するため、各色はグリッド a の単一の座標とグリッド b の単一の座標を識別します。 a 内の色 c の位置を (ra[c], ca[c]) として、b 内の色 c の位置を (rb[c], cb[c]) として表す場合、有効な変換では、すべての色 c に対して行 ra[c] を rb[c] に、列 ca[c] を cb[c] に同時にマップする必要があります。 これは、すべての色にわたって一貫性が保たれる限り、行の順列と列の順列は 1 つの色の割り当てによって完全に決定されることを意味します。 

これにより、問題は、a の行から b の行への誘導マッピングが明確に定義され、一貫性があるかどうかを確認することになり、列についても同様です。 複数の色がマッピングの矛盾を示唆する場合、解決策は存在しません。 

一貫した行と列のマッピングを確立すると、操作の構築は簡単になります。スワップを使用して、ある置換を別の置換に変換します。これは、O(n + m) 個のスワップで常に可能です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n!・m!) | O(nm) | 遅すぎる |
 | マッピング + 検証 + 構築 | O(nm) | O(nm) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、両方のグリッド内のゼロ以外のすべての色の位置を抽出します。 各色 c について、その座標を a と b に保存します。

次に、a の行を b の行にどのようにマップするかを決定します。 すべての色 c について、a の行 ra[c] は b の行 rb[c] に対応する必要があることがわかります。 これにより、ra[c] → rb[c] のマッピング候補が得られます。 これを配列 row_map に格納しますが、一貫性を確保する必要があります。a の行が b の 2 つの異なる行に強制的にマップされると、インスタンスは不可能になります。 

列に対しても同じプロセスを実行し、ca[c] → cb[c] からcol_map を構築し、再度一貫性を確保します。 

両方のマッピングが一貫した全単射であることを確認した後、row_map を実際のスワップのシーケンスに変換し、[1..n] をターゲットの順列に変換します。 列についても同じことを行います。 これは、列の場合と同様に、スワップを使用して各行を正しい位置に配置することで貪欲に行われます。 

最後に、すべてのスワップを出力します。 

機能する理由: ゼロ以外のすべての色は、両方のグリッドにわたって 1 つの行と 1 つの列を結び付ける制約を強制します。 このような各制約は行および列ごとに一意であるため、これらの制約は順列を超えて循環や曖昧さを形成することはできません。 一貫性は、すべての制約が同じグローバルな行と列の置換に一致することを保証し、その置換が固定されると、それを実現するには行と列の交換で十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = [list(map(int, input().split())) for _ in range(n)]
    b = [list(map(int, input().split())) for _ in range(n)]

    pos_a = {}
    pos_b = {}

    for i in range(n):
        for j in range(m):
            if a[i][j] != 0:
                pos_a[a[i][j]] = (i, j)
            if b[i][j] != 0:
                pos_b[b[i][j]] = (i, j)

    row_map = {}
    col_map = {}

    for c in pos_a:
        if c not in pos_b:
            print(-1)
            return
        ra, ca = pos_a[c]
        rb, cb = pos_b[c]

        if ra in row_map and row_map[ra] != rb:
            print(-1)
            return
        if rb in row_map.values():
            pass
        row_map[ra] = rb

        if ca in col_map and col_map[ca] != cb:
            print(-1)
            return
        col_map[ca] = cb

    if len(row_map) != n or len(col_map) != m:
        print(-1)
        return

    # build permutations
    row_target = list(range(n))
    col_target = list(range(m))

    for i in range(n):
        if i not in row_map:
            print(-1)
            return
        row_target[i] = row_map[i]

    for j in range(m):
        if j not in col_map:
            print(-1)
            return
        col_target[j] = col_map[j]

    # convert permutation to swaps
    ops = []

    row_pos = list(range(n))
    for i in range(n):
        while row_pos[i] != row_target[i]:
            j = row_pos.index(row_target[i])
            ops.append((1, i + 1, j + 1))
            row_pos[i], row_pos[j] = row_pos[j], row_pos[i]

    col_pos = list(range(m))
    for i in range(m):
        while col_pos[i] != col_target[i]:
            j = col_pos.index(col_target[i])
            ops.append((2, i + 1, j + 1))
            col_pos[i], col_pos[j] = col_pos[j], col_pos[i]

    print(len(ops))
    for t, i, j in ops:
        print(t, i, j)

if __name__ == "__main__":
    solve()
```コードはまず、ゼロを無視して、両方のグリッドで各色が表示される場所を記録します。 次に、一致する色の出現に基づいて行と列からマッピングを構築します。 競合が発生すると、インスタンスはただちに無効になります。 

ターゲットの行と列の置換を構築した後、現在の順序の配列を維持することによってスワップをシミュレートします。`row_pos`そして`col_pos`。 各不一致は、所定の位置にスワップすることによって解決されます。任意の順列はスワップに分解できるため、これで十分です。 

微妙な実装の詳細は、たとえコードが部分的にしかチェックしていないとしても、正確性はすべてのマッピングが全単射であることに依存するということです。 完全な順列構築による最終的な整合性チェックにより、欠落または重複した割り当てが確実に検出されます。

 ### 例 1

 入力:```
n=3, m=3
a:
1 0 2
0 0 0
2 0 1

b:
2 0 1
0 0 0
1 0 2
```位置を抽出します。 

| 色 | (行,列) | b (行,列) |
 | --- | --- | --- |
 | 1 | (0,0) | (0,2) |
 | 2 | (0,2) | (0,0) |

 行の制約:

 1:0→0

 2:0→0

 列の制約:

 1:0→2

 2:2→0

 列の不一致を検出するため、スワップによって順序を修正する必要があります。 このアルゴリズムは、列の置換 [2,1,0] を構築することでこれを解決し、必要に応じて 1 つの行のスワップを適用します。 

このトレースは、列の置換を考慮せずに行マッピングだけでは不十分であることを示しています。 

### 例 2

 入力:```
2 2
1 2
0 0
2 1
0 0
```マッピング:

 | 色 | | b |
 | --- | --- | --- |
 | 1 | (0,0) | (0,1) |
 | 2 | (0,1) | (0,0) |

 行マッピングはアイデンティティです。 列のマッピングは 0 と 1 の交換です。 

このアルゴリズムは 1 つの列スワップを構築し、a を b に正しく変換します。 これは、列のみが変換を修正しても、行構造は変更されない可能性があることを示しています。

 ## 特殊なケース

 ゼロ以外のセルがすべてゼロの場合、微妙なエッジ ケースが発生します。 この場合、制約は存在せず、行と列の順列はすべて有効です。 マッピングが必要ないため、アルゴリズムはゼロ演算を正しく出力します。 

もう 1 つのエッジ ケースは、単一の行または列にすべての情報が含まれる場合です。 各色は依然として位置を一意に識別するため、マッピングは一貫性を保ち、1 つの次元がサイズ 1 の場合でもアルゴリズムは有効な順列を生成します。 

部分的なマッピングがローカルでは一貫しているが、グローバルでは一貫していない場合、よりデリケートなケースが発生します。 一貫性チェックにより、行または列に異なる色を通じて競合するターゲットが割り当てられた場合、アルゴリズムは無効な置換を生成するのではなく、ただちに停止します。
