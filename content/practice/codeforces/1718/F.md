 ## 解決策
 ## 問題の理解

 各要素が小さな正の整数である配列が与えられ、多くの独立した範囲クエリに答えるように求められます。 各クエリは連続した部分配列を選択し、概念的にはその中のすべての値を単一の大きな数値に乗算します。 この積を実際に構築することはありませんが、1 から C までの範囲のどの整数が「許可される」かを定義するために使用します。整数は、その積と素因数を共有しない場合に有効です。 

タスクを再構成すると、乗算が完全に削除されます。 数値 x がセグメントの積と互いに素であるのは、x がそのセグメントの要素に現れる素数で割り切れない場合に限ります。 積は、指数や順序によってではなく、一連の異なる素因数によってのみ重要になります。 

これにより、問題の構造が即座に変わります。 各クエリは実際に尋ねています。部分配列が与えられ、その内部の因数分解に現れるすべての素数を収集し、[1, C] 内のそれらすべてを回避する数値がいくつあるかを数えます。 

制約により、自明ではない解決策が強制されます。 配列とクエリの数は最大 100000 ですが、配列内の値は最大 20000 です。つまり、因数分解は管理可能ですが、クエリごとの素数共用体の再計算は管理できないことを意味します。 セグメントをスキャンして割り算を最初から再計算するアプローチでは、最悪の場合、制限をはるかに超える約 10^10 の演算が必要になります。 

2 番目の隠れた問題は、C も最大 100000 と大きいことです。これは、素数のすべてのサブセット、さらにはすべての配列セグメントの答えを事前に計算することはできないことを意味します。 この構造はクエリ間で再利用する必要があります。 

要素が 1 の場合、微妙なエッジ ケースが発生します。単純な実装では、1 が制約を導入するものとして誤って扱われる可能性がありますが、1 は素数を提供しないため、共素性に影響を与えることはありません。 クエリごとに単純な包含-除外を使用すると、別の障害モードが発生します。各要素が小さい場合でも、セグメントに多数の異なる素数が蓄積される可能性があり、クエリごとの因子列挙のコストが高くなります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 クエリごとに、セグメント内のすべての要素を因数分解し、すべての素数を収集し、包含排他を使用してこれらの素数で割り切れない C までの数値がいくつあるかを計算します。 このアプローチは正しいとはいえ、各クエリで最大 n 個の要素をスキャンし、それぞれを因数分解する可能性があるため、遅すぎます。 高速因数分解を使用した場合でも、最悪の場合、クエリあたりおよそ O(n √m) になります。 

重要な観察は、製品の関連情報がセグメントに現れる素数のセットであるということです。 このセットをクエリごとに再計算するのではなく、スイープまたは Mo のアルゴリズムにわたって段階的に維持します。 ただし、変化する素数セットで割り切れない C までの整数を効率的に計算できない限り、動的な素数セットを維持しても、計数の問題は直接解決されません。 

重要な構造的洞察は、視点を逆転させることです。セグメントごとにクエリを処理する代わりに、出現ごとに素数の寄与を処理します。 各素数 p は配列全体で追跡でき、[1, C] 内の数値が p で割り切れる数がいくつあるかを維持します。 セグメントが固定されると、答えはその中に少なくとも 1 回出現する素数にのみ依存します。 これにより、問題は「範囲にわたる個別の素数和集合」問題に縮小されますが、C に対する包含と排他によって重み付けされます。

これを高速化するために、配列に対して標準の Mo のアルゴリズムを使用します。 現在のセグメントを維持し、因数分解で各素数が何回出現するかを追跡します。 素数が 0 から 1 に遷移すると、アクティブになります。 ゼロに戻ると非アクティブになります。 [1, C] 内の数値がアクティブ素数で割り切れる数の現在値を、乗算ふるいベースの事前計算によって維持します。C までの各数値について、その平方フリー カーネルがわかっているか、アクティブ素数に対するオイラーのトーティエントのような累積を使用して寄与を事前計算します。 最終的な答えは、C からアクティブな素数の倍数の和集合を引いたもので、[1, C] に対して事前に計算されたメビウス関数を介してエンコードされた包含排他を使用して計算されます。 

メビウスベースの再定式化により、これが扱いやすくなります。素数のサブセットを明示的に処理する代わりに、C までのすべての d に対して値 μ(d) を事前計算し、アクティブな素数によって引き起こされる約数に対する頻度配列を使用します。 素数がアクティブな場合、事前に計算された約数リストを使用して償却された O(C/p) 内の素数の倍数を更新します。 これにより、包含と除外の合計を動的に維持することができます。 

ブルート フォースはクエリごとに素数セットを明示的に構築するため機能しますが、再計算の繰り返しにより共有構造が無視されるため失敗します。 共素性はアクティブな素数のみに依存するという観察により、段階的に更新される C 上のグローバル構造を維持できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(q · n · √m + 包含-除外) | O(m) | 遅すぎる |
 | 最適 (Mo + 除数の更新) | O((n + q) √n + C log C) | O(C + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての数値 a[i] を個別の素数集合に因数分解します。 これは、m までの最小の素因数をふるいで行うことができます。 このステップは、更新で完全な数値ではなく素数のみを処理するために必要です。 
2. 最小限のポインターの移動で現在のセグメント [L, R] を調整できるように、クエリの Mo 順序付けを構築します。 これにより、各インデックスがアクティブ セグメントに O(√n) 回出入りすることが保証されます。 
3. 現在のセグメント内の素数の頻度マップ cnt[p] を維持します。 a[i]を挿入する場合、a[i]を分割する素数pごとにcnt[p]を増加させます。 外す場合は小さくしてください。 
4. 乗算の考え方を使用して、数値 1 から C までの「アクティブな寄与」構造を維持します。x を除算するアクティブな素数の数を表す配列 divCount[x] を維持します。 
5. C に初期化された実行中の答えを維持します。素数がアクティブになる (cnt[p] が 1 になる) と、[1, C] 内の p のすべての倍数に p の寄与を追加し、新しく除外された数値を効果的にマークします。 非アクティブになると、それらの貢献が差し引かれます。 
6. 各クエリ範囲を処理した後の答えは、divCount[x] = 0 の整数の数になります。 

正しさは、セグメント内に少なくとも 1 つの素数が出現する場合にのみ、数値 x がセグメントに対して無効であるという事実に依存します。 メンテナンス構造により、すべてのプライムのエフェクトがアクティブになったときに 1 回だけカウントされ、非アクティブになったときに 1 回だけ削除されることが保証されるため、divCount は禁止された倍数の結合を正しく反映します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXC = 100000

def build_spf(n):
    spf = list(range(n + 1))
    for i in range(2, int(n ** 0.5) + 1):
        if spf[i] == i:
            for j in range(i * i, n + 1, i):
                if spf[j] == j:
                    spf[j] = i
    return spf

def factorize(x, spf):
    res = []
    while x > 1:
        p = spf[x]
        res.append(p)
        while x % p == 0:
            x //= p
    return res

def mo_sqrt(n):
    import math
    B = int(n ** 0.5) + 1
    return B

def main():
    n, m, C, q = map(int, input().split())
    a = list(map(int, input().split()))

    spf = build_spf(m)

    fac = [[] for _ in range(n)]
    for i in range(n):
        fac[i] = factorize(a[i], spf)

    block = int(n ** 0.5)
    queries = []
    for i in range(q):
        l, r = map(int, input().split())
        queries.append((l - 1, r - 1, i))

    queries.sort(key=lambda x: (x[0] // block, x[1]))

    cnt = {}
    bad = [0] * (C + 1)
    cur_bad = 0

    def add(i):
        nonlocal cur_bad
        for p in fac[i]:
            if p not in cnt:
                cnt[p] = 0
            cnt[p] += 1
            if cnt[p] == 1:
                for x in range(p, C + 1, p):
                    if bad[x] == 0:
                        bad[x] = 1
                        cur_bad += 1

    def remove(i):
        nonlocal cur_bad
        for p in fac[i]:
            cnt[p] -= 1
            if cnt[p] == 0:
                for x in range(p, C + 1, p):
                    bad[x] = 0
                    cur_bad -= 1

    cur_l, cur_r = 0, -1
    ans = [0] * q

    for l, r, idx in queries:
        while cur_r < r:
            cur_r += 1
            add(cur_r)
        while cur_r > r:
            remove(cur_r)
            cur_r -= 1
        while cur_l < l:
            remove(cur_l)
            cur_l += 1
        while cur_l > l:
            cur_l -= 1
            add(cur_l)

        ans[idx] = C - cur_bad

    print(*ans)

if __name__ == "__main__":
    main()
```このソリューションは最小の素因数を事前に計算するので、すべての数値が個別の素数に効率的に因数分解されます。 Mo の順序付けにより、各配列インデックスが制限された回数だけ追加および削除されることが保証されます。 重要な構造は、少なくとも 1 つのアクティブな素数で割り切れる [1, C] 内の数値をマークするブール配列であり、実行中のカウンターにより毎回合計を再計算する必要がなくなります。 

微妙な実装の詳細は、素数ごとに複数回インクリメントするのではなく、アクティブな素数のアクティベーションごとに数値を「良いものから悪いもの」に反転するのは 1 回だけであることです。 これにより、複数の素数が同じ倍数を共有する場合の二重カウントが防止されます。 

## 実用的な例

 サンプル配列を考えてみましょう`[1, 2, 3, 2, 5]`C = 5の場合。 

問い合わせについては`[2, 4]`、セグメントは`[2, 3, 2]`なので、アクティブ素数は`{2, 3}`。 

| ステップ | アクティブなセグメント | アクティブプライム | 悪い数字 (≤5) | 答え |
 | --- | --- | --- | --- | --- |
 | 開始 | [] | {} | ∅ | 5 |
 | 2を追加 | [2] | {2} | {2,4} | 3 |
 | 3 を追加 | [2,3] | {2,3} | {2,3,4} | 2 |
 | 2を追加 | [2,3,2] | {2,3} | {2,3,4} | 2 |

 これにより、プライムが繰り返し発生してもアクティブ セットが変更されないことが確認されます。 

ここで考えてみましょう`[4,5]`わずかに変更された例では、4 は素数 2 に 2 回寄与しますが、アクティブ化されるのは 1 回だけです。 

| ステップ | セグメント | アクティブプライム | 不正な数値 ≤ 5 | 答え |
 | --- | --- | --- | --- | --- |
 | 4 を追加 | [4] | {2} | {2,4} | 3 |
 | 5 を追加 | [4,5] | {2,5} | {2,4,5} | 2 |

 トレースは、合成数がその基礎となる素数のみに寄与していることを示しています。

 ## 特殊なケース

 重大なエッジケースは、配列に 12 = 2・2・3 などの繰り返しの合成数が多数含まれる場合です。 この場合、Mo のプロセスで同じインデックスを複数回追加しても、素数が繰り返しアクティブ化されるべきではありません。 頻度チェックは`cnt[p] == 1`プライムの最初の出現によってその効果が有効になり、その後の重複には追加の効果がないことが保証されます。 

要素を削除するときに、別の特殊なケースが発生します。 セグメント内の他の場所にプライムがまだ存在する場合、1 つの出現を削除してもそれが非アクティブ化されてはなりません。 条件`cnt[p] == 0`最後の出現のみがグローバル構造からその寄与を削除し、アクティブな素数セットの正確さを維持することを保証します。
