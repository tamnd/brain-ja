 ## 解決策
 ## 問題の理解

 文字列が与えられ、実行できる操作は 1 つだけです。ある位置で文字を選択し、それを文字列の先頭に移動します。 目標は、この操作の後に辞書編集上可能な限り最小の文字列を生成することです。 入力は複数のテスト ケースで構成され、それぞれが文字列を与えます。 各テスト ケースの出力は、最適な移動後の結果の文字列です。 

制約により、各文字列は最大で次の値にできることがわかります。$10^5$文字数、テスト ケース全体のすべての文字列の長さの合計は最大で$10^5$。 これは、どのソリューションも文字列の長さに対してほぼ直線的な時間で実行する必要があることを意味します。$O(n^2)$アプローチには最大で以下が含まれます$10^{10}$実行不可能な操作。 

エッジ ケースには、最初の文字がすでに最小である文字列、文字が繰り返される文字列、複数の位置に同じ最小文字が含まれる文字列が含まれます。 たとえば、「aaa」の場合、どの移動でも文字列は変更されませんが、「cba」の場合は、最後の文字が前に移動して「acb」になります。 不注意な実装では、文字列の残りの順序を考慮せずに、グローバルで最も小さい文字だけを移動し、次善の結果が生じる可能性があります。 

## アプローチ

 ブルートフォースアプローチは簡単です: 各ポジションに対して$i$文字列内で、その文字を先頭に移動することをシミュレートし、結果の文字列を現在の最小値と比較します。 ある長さの文字列の場合$n$、各シミュレーションでは、新しい文字列を構築する必要があります。$O(n)$時間。 全員のためにこれを行う$n$ポジションは$O(n^2)$アルゴリズム。 これは正しいですが、遅すぎます$n = 10^5$。 

重要な洞察は、すべてのポジションをテストする必要はないということです。 文字の移動は、その文字が現在の最初の文字以下である場合にのみ意味を持ちます。そうでない場合、新しい文字列はより大きな文字で始まることになり、最適とは言えません。 最初の文字以下の候補のうち、移動後に最小の文字列を生成する左端の出現のみを考慮する必要があります。 このような候補を見つけるために 1 回反復し、結果の文字列を効率的に比較することで、問題を次のように軽減します。$O(n)$文字列ごとに。 この操作は最初の文字にのみ影響し、他のすべての文字の順序は保持されるため、問題の構造は単純です。これにより、直接比較が可能になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取ります。 
2. テスト ケースごとに、文字列を読み取ります。 
3. 最初の文字の移動が有効であると仮定して、結果を元の文字列として初期化します。 
4. 2 番目の文字から始まる文字列を繰り返します。 各文字について、その文字が現在の最初の文字より小さいか、等しいかどうかを確認します。 それが小さい場合は、それを前に移動し、この文字を除く部分文字列と連結して結果の文字列を構築することを検討してください。 この新しい文字列を現在の最高の文字列と比較します。 小さい場合は結果を更新します。 
5. すべての文字が考慮されたら、そのテスト ケースの結果を出力します。 

これが機能する理由: 不変条件は、これまでに確認された辞書編集上の最小の文字列を常に維持することです。 最初の文字を改善できる可能性のある文字の移動のみを考慮し、結果の文字列を完全に比較するため、正確に 1 回の移動後にグローバル最小値が見つかることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()
        best = s  # initially, moving the first char is a trivial option
        for i in range(1, n):
            candidate = s[i] + s[:i] + s[i+1:]
            if candidate < best:
                best = candidate
        print(best)

if __name__ == "__main__":
    solve()
```コードは高速 I/O を使用します。`sys.stdin.readline`。 最初の文字を移動しても文字列は変更されないため、2 番目の文字から各文字を繰り返し処理します。 候補文字列の構築にはスライスを使用します。これは、Python では新しい文字列を効率的に生成します。 Python の組み込み関数を使用して辞書順に比較します。`<`演算子。これは問題の定義と一致します。 Off-by-one エラーは、慎重にインデックスを作成することで回避されます。`s[:i]`現在のキャラクターを除外し、`s[i+1:]`その後に接尾辞を付けます。 

## 実用的な例

 ### 例 1: 「cba」

 | 私 | s[i] | 候補者 | 最高 |
 | --- | --- | --- | --- |
 | 1 | b | BCA | CBA |
 | 2 | | CB | CBA→ACB |

 トレースは、「a」を前に移動すると、「cba」よりも小さい「acb」が生成されることを示しています。 

### 例 2: 「acac」

 | 私 | s[i] | 候補者 | 最高 |
 | --- | --- | --- | --- |
 | 1 | c | ac | ac | アカク |
 | 2 | | ａ ａ ｃ ｃ | acac → aacc |
 | 3 | c | caca | aac |

 このトレースは、インデックス 2 で最適な 'a' を見つけるにはすべての位置を考慮する必要があることを示しています。また、移動された文字だけではなく、結果の文字列を完全に比較することの重要性も示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | 文字列ごとに O(n) | 各文字を反復処理し、スライスを使用して O(n) で新しい文字列を構築します。 |
 | スペース | 文字列ごとに O(n) | 候補文字列を保存するには、線形スペースが必要です。 |

 テスト ケース全体のすべての文字列の長さの合計は ≤ 10^5 であるため、合計実行時間は制限時間を十分に下回ります。 メモリ使用量は文字列の長さに線形であり、256 MB の制限に適合します。

 ## 特殊なケース

 単一文字入力「a」の場合、アルゴリズムは他の位置を考慮せず、元の文字列は変更されません。 「zzzzz」の場合、どの移動でも同じ文字列が生成され、比較により最良のものが変更されていないことが確認されます。 「bacab」では、インデックス 1 の「a」を前に移動すると、他の候補よりも小さい「abacb」が得られます。 「aabaaa」の場合、アルゴリズムは 2 番目の「a」（インデックス 2）を正しく選択して「aaabaa」を生成し、繰り返される最小限の文字が正しく処理されることを確認します。 

各ステップでのアルゴリズムの慎重な比較により、1 によるずれや不正な文字列形成が発生しないことが保証され、辞書編集的な比較により、すべてのエッジ ケースでグローバル最小値が正確に特定されます。
