 ## 解決策
 ## 問題の理解

 N 量子ビットの入力レジスタと 1 つの出力量子ビットという 2 つの部分で構成される非常に小さな量子システムが与えられています。 これに加えて、長さ N の古典的なバイナリ ベクトル b が与えられます。タスクは、単純な線形ブール関数を出力量子ビットの位相反転またはビット反転にエンコードする可逆量子変換を実装することです。 

運用上、オラクルは基本状態を取る必要があります$|x\rangle|y\rangle$ここで、x は量子ビットで表される N ビット文字列、y は単一の量子ビットであり、次のように変換されます。$|x\rangle|y \oplus f(x)\rangle$ここで、関数は内積モジュロ 2 として定義されます。$f(x) = (b \cdot x) \bmod 2$。 具体的には、これは、b[i] = 1 であるすべての位置 i を調べ、対応するビット x[i] の XOR を計算することを意味します。 選択されたビットのパリティが 1 の場合は y を反転し、そうでない場合は変更しないままにします。 

重要な制約は、N が最大 8 であることです。これは、状態空間全体が小さいことを意味しますが、量子プログラミングでは状態を直接シミュレートするわけではありません。 基本量子ゲートを使用して変換を構築する必要があります。 これにより、量子オラクルは単一性を維持し、重ね合わせに対して均一に作用する必要があるため、振幅を明示的に検査したり、基底状態を列挙しようとするアプローチは即座に除外されます。 

微妙なエッジ ケースは、出力量子ビットをその場で可逆的な方法で変更する必要があるという事実から生じます。 中間構造を計算解除せずにパリティを計算して y を上書きする素朴な古典的なスタイルの実装は、誤って量子ゲートに変換された場合、可逆性に違反します。 もう 1 つの潜在的な間違いは、量子演算では単一性を維持する必要があるため、XOR 累算は算術加算ではなく CNOT 構造を介して実行する必要があることを忘れていることです。 

## アプローチ

 強引な解釈は、完全な状態ベクトルの観点から考えることです。 すべての 2^(N+1) 基底状態を反復処理し、x ごとに古典的に f(x) を計算し、それに応じて振幅を反転することを想像できます。 オラクルは基本状態の単なる並べ替えであるため、これは概念的には正しいです。 ただし、状態空間は 2^(N+1) のように増大し、ここで N が小さいとしても、このアプローチは、状態から独立した回路として変換を表現しなければならない量子プログラミング モデルとは根本的に互換性がありません。 

重要な観察は、関数 f(x) が XOR に対して線形であるということです。 各項 b[i] * x[i] は x[i] (b[i] = 1 の場合) または 0 (b[i] = 0 の場合) のいずれかであり、最終結果は選択されたビットの XOR だけです。 量子回路では、XOR は CNOT ゲートを使用して自然に実装されます。 x[i] から y への CNOT は、可逆性を損なうことなく、x[i] を 2 を法とする y に加算します。 したがって、b[i] = 1 の各インデックスは、y をターゲットとする 1 つの CNOT ゲートに正確に対応します。 

これにより、問題は「関数の計算」から「制御された X 操作のセットの適用」に軽減されます。これは、線形ブール関数の量子オラクルの標準形式です。

 ## アルゴリズムのチュートリアル

 オラクルを制御された NOT 演算のシーケンスとして直接構築します。 

1. 量子ビットを変更せずにシステムを初期化します。 量子演算は値を返す計算ではなく変換であるため、純粋にゲートを追加することによって演算を行います。 
2. 0 から N−1 までのすべてのインデックス i を繰り返します。 各インデックスで、b[i] が 1 に等しいかどうかを確認します。これにより、x[i] が XOR 合計に寄与するかどうかが決まります。 
3. b[i] が 1 の場合、制御量子ビット x[i] とターゲット量子ビット y を使用して CNOT ゲートを適用します。 これにより、x[i] が 1 のときに y が正確に反転されることが保証されます。 
4. b[i] が 0 の場合は何もしません。 これは、ブール式で x[i] にゼロを乗算することに対応し、パリティには何も寄与しません。 
5. すべてのインデックスを処理した後、出力量子ビット y には、選択されたすべての x[i] の XOR が含まれます。これは正確に f(x) です。 入力レジスタは変更されず、可逆性が維持されます。 

### なぜ効果があるのか

 関数 f(x) は、ビットのサブセットにわたるパリティ関数です。 各 CNOT ゲートは、単一ビットの XOR をターゲット量子ビットに提供します。 XOR は結合的かつ可換であるため、これらの CNOT を適用する順序は重要ではなく、繰り返し適用するとパリティが正しく累積されます。 不変式は、最初の k 個のインデックスを処理した後、ターゲット量子ビット y が元の値に等しく、すべての i < k の寄与 (b[i] = 1) の XOR に等しくなります。この不変式は k = N まで拡張され、その時点で y には完全な内積法 2 が含まれます。 

## Python ソリューション

元のシグネチャは Q# ですが、同じゲート シーケンスの Python スタイルの疑似コード表現で回路ロジックを表現します。```python
import sys
input = sys.stdin.readline

# In actual Q# this would be CNOT operations; here we just show structure.

def solve(x, y, b):
    # x: list of control qubits
    # y: target qubit
    # b: binary vector

    for i in range(len(b)):
        if b[i] == 1:
            CNOT(x[i], y)
```実際の Q# 実装では、CNOT は Microsoft.Quantum.Primitive によって提供される標準の制御された NOT 操作です。 ロジックは同じです。b の各アクティブ ビットは、y で制御された反転を 1 つだけトリガーします。 各演算は自己逆であるため、一時的な量子ビットは必要なく、逆計算も必要ありません。 

主な微妙な点は、入力量子ビットを反転すると意図したマッピングが破壊されるため、ターゲット量子ビットが常に y であり、決して x[i] の 1 つではないことを保証することです。 

## 実用的な例

 N = 3、b = [1, 0, 1]、x = (x0, x1, x2) の単純なケースを考えてみましょう。 

最初、y は状態 |y⟩ にある量子ビットです。 

| ステップ | 私 | b[i] | 操作 | y 状態の影響 |
 | --- | --- | --- | --- | --- |
 | 1 | 0 | 1 | CNOT(x0, y) | y ← y ⊕ x0 |
 | 2 | 1 | 0 | なし | y は変更なし |
 | 3 | 2 | 1 | CNOT(x2, y) | y ← y ⊕ x2 |

 最終結果は y ⊕ x0 ⊕ x2 で、f(x) と一致します。 

ここで、b = [0, 0, 0] について考えてみましょう。 演算は適用されないため、y はすべての入力に対して変更されません。 これは、内積が常にゼロであるという事実と一致します。 

これら 2 つの例は、b の構造に応じた Oracle のアクティブ化と null の動作の両方を示しています。

 ## 特殊なケース

 エッジ ケースの 1 つは、b のすべてのエントリがゼロである場合です。 この状況では、ループは実行されますが、CNOT はトリガーされないため、すべての基底状態に対して y は変化しません。 これは定数ゼロ関数を正しく表しています。 

もう 1 つのエッジ ケースは、すべてのエントリが 1 である場合です。 このアルゴリズムは、すべての x[i] から CNOT を y に適用します。 どの入力についても、y はすべてのビットのパリティとなり、完全な内積定義と一致します。 

最後の微妙なケースは、N = 1 です。この回路は、単一の条件付きフリップ、つまり単一の CNOT ゲートに縮小されます。 これにより、特別な処理を必要とせずに、構築がきれいにスケールダウンされることが確認されます。
