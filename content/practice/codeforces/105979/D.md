 ## 解決策
 ## 問題の理解

 この問題では、すべての都市がエネルギー価値を持つ道路網を調べるように求められます。 都市から出発して、道路に沿って移動することはできますが、エネルギーが開始都市のエネルギーより大きくない都市にのみ入ることが許可されます。 すべての都市について、このルールの下で到達可能な都市の数を見つける必要があります。 このタスクは、Codeforces Gym 105979、問題 D からのものです。 

入力は無向グラフを記述します。 最初の部分は都市と道路の数を示し、次の部分は各都市のエネルギーを示し、残りの線は都市のペアを接続する道路を表します。 出力には都市ごとに 1 つの値が含まれており、その都市のエネルギー制限の到達可能な領域のサイズを表します。 

大きな境界は、正しい方向を選択するための鍵となります。 グラフには最大 100 万の都市と 100 万の道路を含めることができるため、すべての都市からグラフ検索を実行するソリューションでは、最悪の場合でもおよそ O(N(N+M)) の作業が必要になります。 ノードが 100 万個ある場合、可能なすべての反復トラバーサルのほんの一部に触れることさえ不可能です。 グラフ全体をほぼ線形に処理する必要があります。 

よくある間違いは、エネルギー価値の高い都市から始めれば、後で何とかして大きな都市へと拡大できると考えることです。 移動ルールは開始都市の値のみに基づいているため、許可されるセットは正確にその開始値以下のエネルギーを持つ都市になります。 これにより、エネルギーによる自然な秩序が生まれます。 

すべての都市が孤立しているグラフを考えてみましょう。```
3 0
5 5 5
```正しい出力は次のとおりです。```
1
1
1
```不注意な解決策は、エネルギーが等しい都市をグループ化し、値が一致するためにそれらの都市が接続されていると仮定する可能性があります。 エネルギーが等しいと道路が形成されるわけではないため、接続性は依然としてグラフのエッジのみに依存します。 

もう 1 つのエッジ ケースは、エネルギーが増大するチェーンです。```
3 2
1 2 3
1 2
2 3
```正しい出力は次のとおりです。```
1
2
3
```次の都市のエネルギーが高いため、最初の都市はどこにも行くことができません。 2 番目の都市は最初の都市に到達でき、3 番目の都市は 3 つすべてに到達できます。 すべての同等以下のノードを接続する前に、各エネルギーを個別に処理しながら応答するソリューションでは、この順序が間違っている可能性があります。 

最後の微妙なケースは、同じエネルギーを持つ複数の都市です。```
4 2
5 5 5 10
1 2
2 3
```正しい出力は次のとおりです。```
3
3
3
4
```3 つのエネルギー 5 都市すべてが同時に利用可能になります。 等しいエネルギーを 1 つずつ処理してすぐに答えると、最初に処理された都市には、誤って最終コンポーネントの一部しか表示されない可能性があります。 

## アプローチ

 直接的なアプローチは、すべての都市からグラフの走査を実行することです。 選択された開始都市については、より大きなエネルギー値を持つ都市への侵入を拒否しながら、隣接する道路を歩きます。 トラバースは移動ルールに正確に従っているため、これは正しいです。 ただし、グラフが大きい場合は、同じ道路や都市を何度も訪問することになります。 密集または高度に接続されたグラフでは、すべての都市からこれを繰り返すと、約 O(N(N+M)) の操作に達する可能性があります。これは、入力サイズが許容する範囲をはるかに超えています。 

問題の構造は、視点を逆転させる方法を与えてくれます。 「この都市はどこへ行くことができるのか？」と考えるのではなく、「都市を徐々に使用できるようにすると何が起こるのか？」と考えてください。 都市をエネルギー別に並べ替えます。 最小のエネルギーから最大のエネルギーまで都市を処理するとき、あるエネルギー値 x まですべての都市を活性化した後、活性化された都市間の接続されたコンポーネントは、まさにエネルギー x を持つ都市が探索できる領域になります。 

これが機能する理由は、許可されるすべての移動は、エネルギーが最大でも開始値の都市にのみ行われるためです。 都市を昇順に活性化すると、すでに活性化されている 2 つの都市の間のすべての道路は、現在のエネルギー制限内で移動する可能性を表します。 素の集合結合構造は、道路が追加されている間、これらの接続されたコンポーネントを維持できます。 

重要な点は、等しいエネルギーを扱うことです。 同じエネルギーを持つすべての都市は、答えを受け取る前に一緒に起動する必要があります。 そうでなければ、他の同じエネルギー都市を通る経路で接続されている 2 つの同じエネルギー都市がまだ合併していない可能性があります。

 | --- | --- | --- | --- |
 | ブルートフォース | O(N(N+M)) | O(N+M) | 遅すぎる |
 | 最適 | O((N+M) log N) | O(N+M) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての都市をエネルギー値で並べ替えます。 エネルギーが最も低い都市からエネルギーが最も高い都市まで処理します。これは、エネルギー x を持つ都市は、この順序で x 以降に出現する都市のみを考慮するためです。 
2. 互いに素なセット共用体構造を作成します。 最初はアクティブな都市がないため、すべてのコンポーネントは空です。 この構造には、どのアクティブな都市が接続されているか、および接続されている各コンポーネントのサイズが格納されます。 
3. 同じエネルギーを持つ都市のグループごとに、最初にすべての都市をアクティブにします。 都市をアクティブにマークすることは、そのエネルギーまたはその他のより大きなエネルギーを持つ都市のパスに参加できることを意味します。 
4. 新しくアクティブ化された都市ごとに、隣接する都市をすべてチェックします。 隣接コンポーネントがすでにアクティブな場合は、2 つのコンポーネントをマージします。 両方の終点が現在のエネルギー制限を満たしているため、道路は使用可能です。 
5. このエネルギーを持つすべての都市がアクティブ化され、統合されたら、グループ内のすべての都市にコンポーネント サイズを割り当てます。 この値は、そこから到達可能な都市の数です。 
6. 保存された回答を元の都市順に出力します。 

なぜ効果があるのか:

 不変条件は、エネルギー値 x のグループを終了した後、素集合和集合コンポーネントには、エネルギーが最大でも x である都市によって形成されるサブグラフの接続コンポーネントが正確に含まれるということです。 エネルギー x を持つ都市の考えられるすべての有効なパスはこのサブグラフ内に存在する必要があるため、そのコンポーネントのサイズが正確に答えになります。 等しいエネルギーをバッチとして処理すると、同じ制限を持つすべての都市が同時に利用可能になるため、不変条件が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    energy = list(map(int, input().split()))

    graph = [[] for _ in range(n)]
    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        graph[u].append(v)
        graph[v].append(u)

    parent = list(range(n))
    size = [1] * n
    active = [False] * n

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    def union(a, b):
        a = find(a)
        b = find(b)
        if a == b:
            return
        if size[a] < size[b]:
            a, b = b, a
        parent[b] = a
        size[a] += size[b]

    order = list(range(n))
    order.sort(key=lambda x: energy[x])

    ans = [0] * n
    i = 0

    while i < n:
        j = i
        value = energy[order[i]]
        while j < n and energy[order[j]] == value:
            j += 1

        for k in range(i, j):
            u = order[k]
            active[u] = True

        for k in range(i, j):
            u = order[k]
            for v in graph[u]:
                if active[v]:
                    union(u, v)

        for k in range(i, j):
            u = order[k]
            ans[u] = size[find(u)]

        i = j

    sys.stdout.write("\n".join(map(str, ans)))

if __name__ == "__main__":
    solve()
```道路の数が多くなる可能性があり、隣接する道路を効率的にスキャンする必要があるため、コードは最初に隣接リストを使用してグラフを保存します。 

素セット結合の実装では、サイズによるパス圧縮と結合が使用されます。 これらの最適化により、各マージ操作の時間をほぼ一定に保ちます。これは、グラフに約 100 万本の道路が含まれる場合に必要です。 

並べ替えステップでは、都市が利用可能になる順序が作成されます。 メインループは、等しいエネルギーグループを通って進みます。 各グループ内の 2 つの個別のループが必要です。最初にグループ内のすべての都市がアクティブになり、次にすべての道路が考慮されます。 同じパスでアクティブ化してマージすると、前述したのと同じエネルギー均等バグが発生します。 

答えは、すべてのマージが完了した後、ルートに保存されているコンポーネントのサイズから取得されます。 の`find`以前の組合の後は都市自体がルートではなくなる可能性があるため、電話が必要です。

## 特殊なケース

 孤立した都市の場合:```
3 0
5 5 5
```アルゴリズムは各都市をアクティブにしますが、道路がないため連合操作は発生しません。 各 DSU コンポーネントのサイズは 1 のままであるため、出力は次のようになります。`1 1 1`。 このアプローチでは、等しいエネルギーが接続性を生み出すことは決して想定されていません。 

増加するチェーンの場合:```
3 2
1 2 3
1 2
2 3
```エネルギー 1 の都市が最初に処理され、サイズ 1 のコンポーネントを形成します。 エネルギー 2 が処理されると、都市 2 がアクティブになり、都市 1 と合併してサイズ 2 が生成されます。 最後に、都市 3 がアクティブ コンポーネントに加わり、サイズ 3 が生成されます。 これは、到達可能なセットに正確に従います。 

エネルギーが等しい場合:```
4 2
5 5 5 10
1 2
2 3
```最初の 3 つの都市は、答えが書き込まれる前に一緒にアクティブ化されます。 2 つの道路はそれらをサイズ 3 の 1 つのコンポーネントに結合するため、エネルギー 5 の各都市は正しい値を受け取ります。 最後の都市は、以前のすべての都市を表示するのに十分なエネルギーを持って後でアクティブ化されるため、サイズ 4 が受信されます。 これは、等しいエネルギーを一度に 1 つずつ処理する実装を壊すケースです。
