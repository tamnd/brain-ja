 ## 解決策
 ## 問題の理解

 私たちは24時間制の起床時間と一定の間隔を与えられています。`x`数分で。 ジェイミーは、目覚める瞬間の未知の時間前にアラームを設定します。 目覚ましが鳴った後、彼は毎度スヌーズを繰り返します。`x`ちょうど起床時間に達するまであと数分。 

アラーム時刻を直接選択するのではなく、逆に考えます。 アラームが設定されているとします`y`目が覚める前に居眠りします。 そうすればアラーム時刻は正確に`y * x`目標時間の数分前。 スヌーズごとに時間が進みます`x`数分なのでその後`y`を押すと、目覚めの瞬間にアラームが届きます。 

唯一の制限は、最初のアラーム時刻が「幸運」でなければならないことです。つまり、`hh:mm`形式では、少なくとも 1 桁は`7`。 最小の非負の値が必要です`y`戻ったら`y * x`円形の 24 時間時計で起床時刻から 1 分後、結果の時刻には次の時間が含まれます。`7`桁。 

制約は非常に小さく、クロック状態空間は 24 * 60 = 1440 回しか存在しません。 スヌーズ ステップは最大 60 分であるため、可能なすべてのスキャンを完全にブルート フォース スキャンしても`y`値は循環してサイクルを繰り返す前に数千の状態に到達するだけです。 これにより、対数または高度なデータ構造の必要性が即座に排除されます。 線形シミュレーションで十分です。 

主な微妙な点は、時間が真夜中を中心にラップされることです。 から戻る`00:00`1分までに着陸します`23:59`。 モジュロ演算を忘れたソリューションでは、不正確な負の時間が生成されます。 

もう 1 つのよくある間違いは、起床時間から逆算するのではなく、順方向に幸運な時間が見つかったときに早めに停止することです。 この条件は、中間のスヌーズ時間ではなく、_開始アラーム時間_に関するものです。 

## アプローチ

 最も直接的なアイデアは、起床時間から逆方向にプロセスをシミュレートすることです。 可能なスヌーズ回数ごとに`y = 0, 1, 2, ...`、時間を計算します`y * x`起床時刻の数分前に、その時刻に数字が含まれているかどうかを確認します`7`。 

各チェックが O(1) であり、クロックが 1440 分ごとに繰り返されるため、このブルート フォース ビューはすでに最適に近づいています。 最大 1440 / gcd(1440, x) ステップの後、プロセスはサイクルに入り、以前の状態に戻ります。 以来`x ≤ 60`、このサイクルの長さは短く、最悪の場合、繰り返す前に検査するのはせいぜい数百または数千の状態です。 

重要な点は、個別のクロック状態が 1440 個しかないため、1 サイクルまでの可能性のあるすべての後方オフセットをチェックしても安全であるということです。 無限の時間や大きな限界について考える必要はありません。 減算を繰り返すことによって生成された有限の周期シーケンスを単純に検索しているだけです。`x`分。 

したがって、最適な解決策は、分単位でモジュラー演算を行う制御されたシミュレーションです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | y に対するブルート フォース シミュレーション | O(1440 / x) | お(1) | 承認済み |
 | モジュラークロック演算を使用した同じシミュレーション | O(1440) 最悪の場合 | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 ラップアラウンドを簡素化するために、00:00 から数分で作業を完了します。 

1.起床時間を合計分に変換します`t = hh * 60 + mm`。 これにより、あらゆる時間の演算に対して単一の線形スケールが得られます。 分単位で作業すると、時間と分の境界を繰り返し処理する必要がなくなります。 
2.初期化`y = 0`。 これはスヌーズがないことを表します。つまり、起床時刻自体がすでに有効なアラーム開始時刻であるかどうかを確認することから始めます。 
3. 次の操作を繰り返します。候補となるアラーム時刻を次のように計算します。`(t - y * x) mod 1440`。 Modulo 1440 により、24 時間サイクル内に収まるようになり、真夜中をまたぐラップアラウンドが正しく処理されます。 
4. この候補を時と分の形式に戻します。 数字を抽出し、4 つの文字のいずれかが含まれているかどうかを確認します。`'7'`。 
5. 条件が成立する場合は戻ります`y`すぐに。 繰り返すので`y`昇順では、最初の有効な値が最小であることが保証されます。 
6. それ以外の場合はインクリメントします`y`そして繰り返します。 

重要な構造上の考え方は、私たちは有限の状態空間上で決定論的なサイクルを通過しているということです。 それぞれの増分`y`正確に動く`x`分を遡って、モジュロ 1440 クロック グラフの単一軌道を調査します。 

### なぜ効果があるのか

 のすべての値`y`可能性のある 1 つのアラーム時刻に正確に対応します: 時刻`y * x`目覚める数分前。 時間は循環モジュロ 1440 であるため、増加します。`y`クロック状態の繰り返しシーケンスを通過します。 州は合計 1440 しかないため、このシーケンスは最終的に繰り返さなければなりません。つまり、到達可能なすべての候補が有限サイクル内に存在します。 

スキャンすることで`y`スヌーズ回数の増加順にアラーム時間をチェックします。 したがって、「数字 7 を含む」条件を最初に満たすものが、有効なスヌーズの最小数になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def has_seven(h, m):
    return '7' in f"{h:02d}{m:02d}"

def solve():
    x = int(input())
    hh, mm = map(int, input().split())

    start = hh * 60 + mm

    for y in range(0, 2000):
        t = (start - y * x) % 1440
        h = t // 60
        m = t % 60
        if has_seven(h, m):
            print(y)
            return

solve()
```このソリューションは時間を分に変換し、減算とラップアラウンドの処理を簡素化します。 ループオーバー`y`考えられるすべてのサイクルをカバーするのに十分な大きさの定数によって安全に制限されます。 状態空間は 1440 しかないため、2000 で十分です。 

ヘルパー関数は、時刻を固定幅文字列としてフォーマットし、先頭のゼロが確実に保持されるようにすることで数字の条件をチェックします。これは次のような場合に必要です。`07:xx`。

 ## 特殊なケース

 A common edge case is when the wake-up time itself is already lucky. 例えば、`00:07`どれでも`x`すぐに戻るべきです`0`。 アルゴリズムは次のことをチェックするため、これを処理します。`y = 0`引き算の前に。 

もう 1 つの微妙なケースは、真夜中を越える場合です。 起床時間が`00:00`そして分を差し引くと、着陸しなければなりません`23:xx`正しく。 モジュロ 1440 の算術演算により、負の結果が正しい上位日の間隔にラップされることが保証されるため、特別な処理は必要ありません。 

最後のケースは、サイクルが数回繰り返した後に同じタイミングで再び訪れる場合です。 検索空間は有限であるため、アルゴリズムは最終的に到達可能なすべての状態をループします。 最初の有効な出現で停止するため、繰り返しは正確さに影響を与えず、実行時間を制限するだけです。
