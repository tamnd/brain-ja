 ## 解決策
 ## 問題の理解

 さまざまな文脈で「is」という単語が含まれる可能性がある文を表す 1 行のテキストが与えられます。 タスクは、この文をスキャンし、両側がスペースで囲まれたスタンドアロンのトークンとして表示される場合にのみ、小文字の単語「is」が出現するすべてを置き換えることです。 大文字の「is」、行頭または行末の「is」、句読点やその他の文字に付加された「is」など、その他の形式は変更しないでください。 

入力サイズは最大 100,000 文字にすることができます。これは、文字列の連結の繰り返しや、部分文字列のグローバル置換の繰り返しを伴うソリューションは、2 次的な方法で単純に実装すると危険であることがすぐにわかります。 非効率的に文字列の検索や再構築を繰り返すアプローチでは、多くの置換が発生した場合、最悪の場合 O(n²) にまで低下する可能性があるため、リニア スキャンが必要です。 

「空間に囲まれた」という定義から、いくつかの特殊なケースが自然に現れます。 文字列が「is」で始まる場合は、先頭にスペースがないため、置換しないでください。 たとえば、「本です」という入力は変更されない必要があります。 同様に、「is」が「this is」のように最後に表示される場合は、その後に右側にスペースが続く場合にのみ置換されます。つまり、後続の位置も敏感になります。 もう 1 つの微妙なケースは句読点の隣接性です。単語が厳密にスペースで区切られていないため、「is」または「(is)」を置き換えてはなりません。 

スペースで分割して文を再構築する単純なアプローチも、単語の間に複数のスペースが含まれている場合、またはトークンに句読点が付加されている場合、元の書式が失われる危険性があるため失敗します。 

## アプローチ

 ブルートフォースのアイデアは、文字列の部分文字列を繰り返し検索することです。`" is "`それを次のように置き換えます`" was "`。 これは、両側にスペースがあるという条件を直接エンコードしているため、論理的には正しいです。 ただし、置換するたびに文字列が移動する可能性があり、再構築が必要になります。また、繰り返し使用して実装した場合は、`find`およびスライスでは、各操作には O(n) がかかります。 置換が頻繁に発生する最悪のケースでは、O(n²) の動作が発生します。 

より信頼性の高い観察は、文字列をその場で何度も変更する必要がないということです。 ローカル コンテキストを確認しながら、各文字を左から右に 1 回処理できます。 どの位置でも、現在の 3 文字のウィンドウが形成されるかどうかを判断するだけで済みます。`" is "`適切な境界線を持って。 そうであれば、私たちは排出します`" was "`元の部分文字列をコピーする代わりに。 それ以外の場合は、現在の文字をそのままコピーして先に進みます。 これにより、位置ごとに一定時間チェックを行う単一パスで問題が軽減されます。 

重要な構造特性は、「is」を置き換えるかどうかの決定が、そのすぐ隣にのみ依存することです。 グローバル情報は必要ないため、ストリーミング構築で十分です。

 ## アルゴリズムのチュートリアル

 1. 入力文字列を変数に読み込みます`s`。 答えを修正するのではなく、段階的に構築していきます`s`Python では文字列は不変であるため、適切に配置されます。 
2. 空のリストを初期化する`out`出力文字を効率的に保存します。 リストを使用すると、文字列連結の繰り返しコストが回避されます。 
3. インデックスを使用して文字列を反復処理します。`i`から`0`に`len(s) - 1`。 
4. 各ポジションで`i`、交換が可能かどうかを確認してください。 この条件では次のことが求められます。 

で始まる部分文字列`i`まさに`"is"`、その直前と直後にスペースがあるという意味`s[i-1] == ' '`そして`s[i+2] == ' '`。 

このチェックにより、他の単語の一部や句読点が付いたトークンではなく、孤立した単語のみが置換されることが保証されます。 
5. 条件が満たされる場合は、文字列を追加します。`"was"`出力リストに移動して次に進みます`i`2 文字を消費したため、2 ずつ増えます。 
6. 条件が成立しない場合は追加`s[i]`出力リストに移動して次に進みます`i`1までに。 
7. ループが終了したら、リストを最終文字列に結合して出力します。 

### なぜ効果があるのか

 正しさは、すべての決定がローカルであり、取り消しできないという事実から生まれます。 交換するたびに`" is "`と`" was "`、置換は周囲の文字が両方ともスペースである場合にのみ行われるため、後で重複または部分一致が影響を受けることはないことが保証されています。 これにより、隣接する一致間の競合が防止されます。 すべての文字は、一致または不一致のケースの一部として 1 回だけ検査され、重複や省略がなく完全にカバーされることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().rstrip('\n')
    n = len(s)
    out = []
    i = 0

    while i < n:
        if i > 0 and i + 2 < n:
            if s[i:i+2] == "is" and s[i-1] == ' ' and s[i+2] == ' ':
                out.append("was")
                i += 2
                continue

        out.append(s[i])
        i += 1

    print("".join(out))

if __name__ == "__main__":
    solve()
```この実装は、各候補位置の周囲のスライディング ウィンドウ チェックに依存しています。 重要な点は境界の安全性を確保することです: 条件`i > 0 and i + 2 < n`近隣のチェック時に範囲外のアクセスを防止します。 ループの進行は、一致したセグメント内の文字の二重処理を回避する置換が発生するかどうかによって異なります。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from contextlib import redirect_stdout
    import io as sio

    buf = sio.StringIO()
    with redirect_stdout(buf):
        solve()
    return buf.getvalue().strip()

def solve():
    s = sys.stdin.readline().rstrip('\n')
    n = len(s)
    out = []
    i = 0

        if i > 0 and i + 2 < n and s[i:i+2] == "is" and s[i-1] == ' ' and s[i+2] == ' ':
            out.append("was")
            i += 2
        else:
            out.append(s[i])
            i += 1
    print("".join(out))

assert run("Is it your pencil?") == "Is it your pencil?"
assert run("This is an island.") == "This was an island."
assert run("is") == "is"
assert run("A is B is C") == "A was B was C"

 ## 特殊なケース

 重要なエッジケースは、「is」が最初に現れる場合です。 たとえば、「is here」という入力は、前にスペースがないため、変更されないままでなければなりません。 インデックス 0 での反復中に、境界チェックが行われます。`i > 0`はすぐに失敗するため、アルゴリズムは一致を試行せずに文字を安全にコピーします。 

もう 1 つのケースは、「これは」のような後続の出来事です。 スキャンが最後の有効な位置に到達すると、条件は`i + 2 < n`文字列を超えて読み取らないようにするため、無効なアクセスは発生せず、最後の「is」はその後にスペースが続く場合にのみ置き換えられますが、その後にスペースが続く場合は置き換えられません。 出力は正しいままです。 

3 番目のケースには、「is,」などの句読点の隣接関係が含まれます。 部分文字列が「is」で始まっている場合でも、その後の文字はスペースではなくコンマであるため、置換条件は失敗します。 このアルゴリズムは元のテキストを正確に保存し、厳密な境界チェックによって独立した単語の定義が正しく適用されることを示しています。
