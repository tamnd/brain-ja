 ## 解決策
 ## 問題の理解

 私たちには一連の日が与えられ、毎日 kk は自分が何回間違った答えをしたのか (WA) を記録します。 これらの値は配列を形成します`a[1..n]`。 

スコアはゼロからスタートし、日々進化していきます。 処理日の場合`i`、WA カウントを比較します。`a[i]`前日ごとに`j < i`。 各比較は独立して寄与します。`a[j] < a[i]`、次の場合、スコアは 1 つ増加します。`a[j] > a[i]`、スコアは 1 つ減り、それらが等しい場合は何も変わりません。 前日とのすべての比較を適用した後、この新しいスコアがその日の現在のスコアになります。`i`。 1 日目には前日がないため、常にスコア 0 で終了します。 

2 つの値を出力する必要があります。1 つはすべての日の任意の時点で達成された最大スコア、もう 1 つはすべての日を処理した後の最終スコアです。 

制約`n ≤ 100000`すべての日を明示的に比較するものは避ける必要があります。 単純な二重ループでは、およそ n 乗の比較が必要になりますが、これは実現可能性をはるかに超えています。 どのようなソリューションでも、繰り返される「過去の値が現在よりも小さいか大きいか数え上げる」作業を、1 日あたり効率的に回答できるものに減らす必要があります。 

多くの値が等しい場合、微妙なエッジ ケースが発生します。 等しい値は何も寄与しないため、正しい解決策では、誤って二重にカウントしたり、等しい値のグループ間の遷移を見逃したりすることなく、それらが「大きい」カウントと「小さい」カウントの両方から除外されるようにする必要があります。 

シーケンスが厳密に増加または厳密に減少している場合、別の特殊なケースが発生します。 このような場合、時間の経過に伴うペアの寄与の単純な解釈ではスコアは二次関数的に増加しますが、実際の進化は前の要素からの寄与に関してステップごとに線形であり、ペアの更新を誤ってシミュレートしようとすると、この違いは誤解されやすくなります。 

## アプローチ

 ブルートフォース解釈は簡単です。 毎日のために`i`、過去のすべての日をスキャンします`j < i`そして明示的に比較する`a[j]`そして`a[i]`。 現在のスコアを維持し、最大値も追跡します。 これは、スコア更新ルールの定義に直接従うため、正しいです。 ただし、約`1 + 2 + ... + (n-1)`比較、これは次のとおりです`n^2 / 2`、そしてのために`n = 100000`これは完全に不可能です。 

重要な観察は、その日のスコアです。`i`以前の値がどれだけ小さいか、どれだけ大きいかによってのみ決まります。 次のように定義すると、

 -`less(i)`= の数`j < i`そのような`a[j] < a[i]`-`greater(i)`= の数`j < i`そのような`a[j] > a[i]`その場合、遷移は単純に次のようになります。`score[i] = score[i-1] + less(i) - greater(i)`したがって、問題は、現在の値に対する以前の要素のカウントを維持することに帰着します。 配列を左から右に処理する際に、以下をサポートできるデータ構造が必要です。 

1. 値の挿入`a[i]`2. 厳密に小さいまたは厳密に大きい既存の値がいくつあるかをクエリする

 値は以下までなので、`10^5`、それらをフェンウィック ツリー (またはセグメント ツリー) に圧縮できます。 これにより、頻度とクエリ プレフィックスの合計を効率的に維持できるようになります。 毎日が`O(log n)`の代わりに操作`O(n)`走査。 

最終的な答えを得るには、最終値だけでなく、プロセス中の最大プレフィックス スコアを追跡する必要があります。

 ## アルゴリズムのチュートリアル

 以前に確認されたすべての値の周波数構造を維持しながら、配列を左から右に処理します。 

1. フェンウィック ツリー (または同様の構造) を初期化し、すべてのカウントをゼロに設定します。 初期化もする`score = 0`そして`best = 0`。 これは、比較が存在する前の 1 日目を表します。 
2. 毎日について`i`1からnまで、私たちは扱います`a[i]`履歴に挿入している現在の値として。 
3.挿入する前に`a[i]`、厳密に小さい以前の値がいくつあるかをクエリします。 これは、最大のプレフィックス合計クエリです。`a[i] - 1`。 これにより、`less(i)`。 
4. また、以前の値が厳密にどれだけ大きいかをクエリします。 これは次のように計算されます`(i - 1) - count(≤ a[i])`。 プレフィックスの合計は次のとおりです`a[i]`は、それ以下の値の数を与えるため、前の要素の合計から減算すると、厳密に大きい要素が分離されます。 これにより、`greater(i)`。 
5. スコアを次のように更新します。`score += less(i) - greater(i)`。 これは、前日の毎日が今日の変化にどのように寄与するかの定義に直接当てはまります。 
6. アップデートする`best = max(best, score)`最大スコアは最終日の前に発生する可能性があるため、毎日の後。 
7.挿入します`a[i]`頻度を増やすことでフェンウィック ツリーに追加します。 

丸一日処理した後、`best`は確認された最大スコアであり、`score`は最終的な値です。 

### なぜ効果があるのか

 フェンウィック ツリーはいつでも、前日のすべての WA カウントのマルチセットを正確に表します。 その日のスコアへのあらゆる貢献`i`間の比較のみに依存します`a[i]`そしてそれ以前の要素。 この構造により、以前の各要素は「小さい」、「大きい」、または無視されたカテゴリのいずれかで 1 回だけカウントされ、これらのカテゴリは互いに素であることが保証されます。 スコアは独立したペアごとの寄与の合計として定義されるため、集計カウントを維持すると、過去の要素を再度検討する必要がなく、正確な値が保存されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    maxv = max(a)
    fw = Fenwick(maxv)

    score = 0
    best = 0

    for i, x in enumerate(a):
        less = fw.sum(x - 1)
        total_prev = i
        leq = fw.sum(x)
        greater = total_prev - leq

        score += less - greater
        best = max(best, score)

        fw.add(x, 1)

    print(best, score)

if __name__ == "__main__":
    solve()
```フェンウィック ツリーには、これまでに確認された WA カウントの頻度が保存されます。 プレフィックスの合計は次のとおりです`x-1`厳密に小さい以前の値の数を直接与えます。 プレフィックスの合計は次のとおりです`x`は、それ以下の値の数を与えるため、処理された要素の数から減算すると、厳密に大きな値が得られます。 スコアの更新はペア寄与ルールに正確に従い、最良の値が段階的に追跡されます。 

微妙な詳細は、`total_prev`単なるインデックスです`i`、処理日の前から`i`まさにあります`i`以前の要素。 これにより、余分なクエリが回避され、更新がクリーンな状態に保たれます。

 ## 特殊なケース

 すべての値が同一であるシーケンスの場合、すべての比較で等しい結果が得られるため、どちらも一致しません。`less`または`greater`スコアが変わります。 フェンウィック ツリーは両方のクエリに対して常に 0 を返し、スコアは全体を通して 0 のままです。 入力用`5 2 2 2 2 2`、アルゴリズムは毎日処理しますが、`less`そして`greater`はゼロであるため、最終スコアと最大スコアは両方ともゼロです。 

次のような厳密に増加するシーケンスの場合`1 2 3 4 5`、新しい要素はそれぞれ、以前のすべての要素よりも大きいため、`less(i) = i-1`そして`greater(i) = 0`。 スコアは次のように増加します`0, 1, 2, 3, 4`、累積して 10 になり、フェンウィック ツリーは各ステップでこの増大するプレフィックス分布を正しく反映します。
