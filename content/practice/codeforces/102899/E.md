 ## 解決策
 ## 問題の理解

 いくつかの独立したテスト ケースが与えられています。 各テスト ケースには、複数の「防御セッション」があります。 すべてのセッションで生徒のリストが表示され、各生徒の 2 つの要素の合計として計算された総合スコアが表示されます。 

1 人の特別生徒 KK が各セッションに 1 回登場し、そのセッションでスコアを獲得します。 他の生徒は 1 つまたは複数のセッションに参加する可能性があり、毎回異なるスコアが得られる可能性があります。 

学生がいずれかのセッションに登場するたびに、そのセッションでのスコアが同じセッションでの KK のスコアよりも厳密に低い場合、その学生は「KK に支配されている」とみなされます。 学生が 1 回のセッションでも KK に匹敵するかそれを超えた場合はカウントされません。 

タスクは、この条件を満たす個別の生徒の数を計算することです。 

入力の構造は小規模です。各テスト ケースには最大 10 個のセッションがあり、各セッションには最大 10 人が参加します。 これにより、単純な二次走査または線形走査を超えるものは即座に除外されます。 すべてのレコードに対する単純なネストされたスキャンであっても、テスト ケースあたり最大でも数千の操作であり、1 秒の制限の下では取るに足らないものです。 

主な微妙な点は、学生がセッション全体で複数回出現し、その有効性がすべての出現における全体的な条件に依存することです。 単純な間違いは、生徒の最初の出現のみをチェックしたり、セッション固有の KK 値ではなく単一の KK 値と比較したりすることです。 

具体的な失敗例はこんな感じです。 

セッション 1: KK スコアは 100、アリスのスコアは 90

 セッション 2: KK スコアは 50、アリスのスコアは 60

 アリスを一度だけ比較すると、彼女は大丈夫に見えるかもしれませんが、セッション 2 では厳密に KK よりも低いわけではないため、彼女はルールに違反します。 したがって、アリスは除外されなければなりません。 

もう 1 つの特殊なケースは、生徒が 1 回しか登場しない場合です。 そのセッションでスコアが KK よりも低い場合、それらは自動的に有効になりますが、その後の隠れた違反が存在しないことを確認した後でのみ有効になります (すべての発生を追跡する必要があります)。 

## アプローチ

 強引な解釈は次のようになります。すべての生徒の名前について、その生徒が登場するすべてのセッションを収集し、それらのセッションごとに、そのセッションでの生徒のスコアと KK のスコアを比較します。 すべての比較に合格した場合、生徒をカウントします。 

これは正しく機能しますが、各生徒のデータセット全体をスキャンするという単純な実装を行うと、すべてのエントリを繰り返し走査する可能性があります。 最悪の場合、学生 1 人あたり最大 100 件のエントリをチェックする可能性があり、無駄な繰り返し作業が発生する可能性があります。 

重要な点は、生徒ごとに再計算する必要がないということです。 代わりに、各レコードを 1 回処理し、セッションごとに KK のスコアを維持し、条件に違反した生徒を即座に無効にすることができます。 これにより、問題は名前に関するシングルパス集計の問題に変わります。 

私たちは、各学生がまだ有効であるかどうかを記録する辞書を管理しています。 各セッションを読みながら、すべての参加者をそのセッションの KK スコアと比較し、ステータスをすぐに更新します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 学生ごとの総当たりスキャン | テスト ケースごとの O(N²) | O(N) | 遅すぎる (不必要なオーバーヘッド) |
 | シングルパス検証 | テスト ケースあたり O(N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. セッション数を読み取ります。 KK は常にセッションの最初のエントリとして表示されるため、セッションごとに、最初に KK のスコアを特定します。 これにより、セッションごとのベンチマークが得られます。 
2. 辞書を作成する`valid[name] = True`各生徒がまだカウントされる資格があるかどうかを追跡するため。 
3. セッションのすべての参加者について、そのセッションのスコアと KK のスコアを比較します。 生徒が KK ではなく、そのスコアが KK のスコア以上である場合、直ちに無効としてマークされます。 
4. すべてのセッションの処理を続行し、一度生徒が無効とマークされると、今後のセッションに関係なく無効のままであることを確認します。 
5. すべてのセッションを処理した後、まだ有効とマークされている個別の名前 (KK を除く) の数を数えます。 

重要な設計上の選択は、即時無効化です。 これにより、セッションごとの完全な履歴の保存が回避されます。 

### なぜ効果があるのか

 各生徒について、私たちがチェックする条件は、生徒のすべての外見に対する普遍的な制約です。観察されたすべてのスコアは、対応するセッションでの KK のスコアよりも厳密に低くなければなりません。 アルゴリズムは、各発生を個別にチェックし、最初の失敗を無効にすることでこれを強制します。 無効化は単調で元に戻されないため、すべての比較が合格した場合に限り、学生は最後に有効とマークされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

T = int(input())
for _ in range(T):
    n = int(input())
    
    valid = {}
    kk_name = None

    for _ in range(n):
        a = int(input())
        
        session = []
        for i in range(a):
            s, b, c = input().split()
            b = int(b)
            c = int(c)
            total = b + c
            
            if i == 0:
                kk_name = s
                kk_score = total
            
            if s not in valid:
                valid[s] = True
            
            if s != kk_name:
                if total >= kk_score:
                    valid[s] = False

    ans = 0
    for name, ok in valid.items():
        if name != kk_name and ok:
            ans += 1

    print(ans)
```このコードは、各セッションの最初のエントリが KK に対応するという保証に依存しています。 これにより、そのセッションの残りの参加者を処理する前に、KK のスコアを取得することができます。 

微妙な点は、セッションごとの履歴を保存する必要がないことです。 名前ごとに現在の有効性ステータスのみを保存するため、メモリ使用量が最小限に抑えられ、ロジックがシンプルになります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    T = int(input())
    out = []
    for _ in range(T):
        n = int(input())
        valid = {}
        kk_name = None

        for _ in range(n):
            a = int(input())
            for i in range(a):
                s, b, c = input().split()
                b = int(b)
                c = int(c)
                total = b + c

                if i == 0:
                    kk_name = s
                    kk_score = total

                if s not in valid:
                    valid[s] = True

                if s != kk_name and total >= kk_score:
                    valid[s] = False

        ans = sum(1 for k,v in valid.items() if k != kk_name and v)
        out.append(str(ans))

    return "\n".join(out)

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、KK のスコアが非常に低いセッションにのみ生徒が登場する場合です。 各セッションは個別にチェックされるため、アルゴリズムはこれを正しく処理します。そのため、たとえ 1 つの高スコアのセッションでも生徒が無効になります。 

もう 1 つのケースは、単一のセッション内で同じ生徒が繰り返し登場することです。 各行を個別に処理するため、そのセッション内で違反が発生すると、その有効性が即座に反転され、その後発生しても結果は変わりません。 

最後の微妙なケースは、KK が他の生徒の名前として再利用されていることです。 このコードでは、名前比較によって KK を明示的に除外し、真の KK ベースラインのみが比較に使用されるようにします。
