 ## 解決策
 ## 問題の理解

 審査員によって割り当てられたスコアを表す整数のリストが与えられます。 すべての値はゼロ以外であり、すべて個別です。 これらの番号のうち 1 つだけを削除することができます。 それを削除した後、残ったすべての数値を掛け合わせ、その積が最終スコアとなります。 タスクは、結果の積ができるだけ大きくなるようにどの単一の数値を削除するかを選択し、削除された数値自体を出力することです。 

主な問題は、積が残りのすべての要素に同時に依存するため、1 つの要素を削除すると結果の大きさと符号にも影響を与えることです。 最大 30,000 の数値では、長い積を単純に繰り返し乗算するのは遅すぎるため、除去ごとに積を最初から再計算するアプローチは算術コストの観点から慎重に考慮する必要があります。 

微妙な側面は、標識の動作から生じます。 この積は、残っている負の数に応じて符号を反転できます。 負の数を削除すると、負の数のパリティが変更される可能性があり、正の数を削除すると、負の数を削除した場合とは異なる大きさに影響します。 このため、純粋に「最小の削除」または「最大の削除」という観点からの推論は不正確になります。 

素朴な直感を打ち破るエッジケースには、次のようなものがあります。 

たとえば、負の数が 1 つだけある場合、`[-5, 2, 3, 4]`、マイナスを削除すると積はプラスで大きくなりますが、プラスを削除するとマイナスの積が残ります。 貪欲な「最小値を削除」ルールは、符号の処理によっては失敗する可能性があります。 

などのマイナス要素が多い場合は、`[-4, -3, -2, -1, 10]`、マイナスを 1 つ削除すると、パリティが切り替わり、競合する方法で符号と大きさが大幅に変更される可能性があります。 

すべての数値は非ゼロであり、別個であるため、単調変化についての推論を単純化するため、同点やゼロ積の崩壊を扱うことはありません。 

## アプローチ

 ブルートフォース手法では、可能なすべての削除に対して 1 つの候補インデックスを除くすべての数値の積を計算します。 各 i について、以下のすべての要素を乗算します。`a[i]`そして結果を比較します。 これは問題の定義を直接評価するため、正しいです。 ただし、各評価には O(n) のコストがかかり、n 個の選択肢すべてに対してこれを行うと O(n²) 回の乗算が必要になります。 n が 3·10⁴ までの場合、これはおよそ 9·10⁸ の乗算となり、Python では遅すぎ、最適化された言語でも境界線に達します。 

重要な観察は、実際には完全な製品を繰り返し必要とするわけではないということです。 すべての要素の積を基本値とみなす場合、次の値を削除します。`a[i]`総積をで割ることに相当します`a[i]`。 課題は、積がオーバーフローする可能性があり、符号の比較を慎重に処理する必要があることです。 しかし、論理的には、すべての候補結果は次のように比例します。`P / a[i]`、 どこ`P`はすべての数値の積です。 

除算や膨大な数を直接扱う代わりに、各要素を削除すると製品がどのように変化するかを推論することで候補を比較できます。 すべての値がゼロ以外なので、比較すると`P / a[i]`異なる i 間での比較は比較と同等です`1 / a[i]`同じ基本製品に対する相乗効果の観点から。 ただし、符号と大きさは相互作用するため、より安全なアプローチは、Python の多倍長整数を使用して合計積を一度計算し、その後、整数除算によって各候補値を計算することです。 

これにより、問題は O(n) 回の計算に減ります。つまり、1 つの完全な積パスと、各除去を評価するための 1 つのパスです。

 ## アルゴリズムのチュートリアル

 ### 最適な戦略

 1. 配列内のすべての数値の積を計算します。 これにより、削除前の完全な乗算を表すベースライン値が得られます。 
2. 各要素を反復処理する`a[i]`そして、総積を で割ることにより、それを除去した値を計算します。`a[i]`。 これにより、その除去のスコアが得られます。 
3. これまでに確認された最大の生成結果を追跡し、対応するインデックスを保存します。 
4. すべての要素を確認した後、削除した結果が最大の積を生成した要素を出力します。 

重要な決定点は、製品全体を最初から再計算しないということです。 私たちは、積から 1 つの要素を削除することは、その要素で割ることと同等であるという代数的関係に依存しています。 

### なぜ効果があるのか

 すべての有効な結果は次のものに正確に対応します`P / a[i]`、 どこ`P`すべての要素の積です。 以来`P`すべての選択肢にわたって一定であり、最大化されます`P / a[i]`over i は、同じ基本量の最適な変換を選択することと同じです。 候補が見逃されることはなく、それぞれが 1 回だけ評価され、正確性が保たれます。 唯一の微妙な点は、Python では整数演算が正確な値を保持するため、浮動小数点エラーがなく比較の信頼性が高いことです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n = int(input().strip())
    a = list(map(int, input().split()))
    
    total = 1
    for x in a:
        total *= x
    
    best_val = None
    best_idx = 0
    
    for i, x in enumerate(a):
        val = total // x
        if best_val is None or val > best_val:
            best_val = val
            best_idx = i
    
    print(a[best_idx])

if __name__ == "__main__":
    main()
```このソリューションでは、最初に単一パスで全体の製品が構築されます。 Python の整数は任意の精度に自動的に拡張されるため、オーバーフローは問題にならないため、これは安全です。 

次に、総積を現在の要素で割ることにより、各除去を評価します。 すべての要素が総積の因数であるため、整数の除算は正確です。 比較ステップは簡単です。最大の商を生成するインデックスを保持します。 

よくある実装上の間違いは、各インデックスの積を再計算しようとしたり、部分的な再計算で乗算をシミュレートしようとしたりすることで、O(n²) が発生します。 もう 1 つの微妙な間違いは、浮動小数点除算を使って推論しようとすることです。これにより、製品が大きくなると精度誤差が生じる可能性があります。
