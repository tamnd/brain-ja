 ## 解決策
 ## 問題の理解

 複数のテストケースが与えられます。 各テスト ケースでは、次のシーケンスが説明されます。$n$個別の整数。これは次の順列です。$1 \ldots n$。 シーケンスは、ダンサーが観察者の前を通過する順序を表します。 観察の瞬間、ダンサーは円を描くように配置され、時計回りまたは反時計回りに動きます。 この円運動により、観察者が見るのは円の連続したセグメントですが、そのセグメントは方向に応じてどちらの方向にも読み取ることができます。 

タスクは、観察されたシーケンスが、$1 \ldots n$すべての要素を時計回りまたは反時計回りの順序で連続的に読み取ります。 言い換えれば、その順列が恒等次数の循環回転であるか、それとも逆順序の循環回転であるかが問われます。 

制約$n \le 10^4$テスト ケースあたり最大 10 個のテスト ケースは、合計入力サイズを意味します。$10^5$。 これにより、あらゆることが排除されます$O(n^2)$テストケースごとの比較は境界線ですが、それでも潜在的に許容できるのは小さな定数の場合のみです。 ただし、構造は、より単純な線形チェックで十分であることを示唆しています。 

ここで素朴な誤解がよく起こります。サイクルに並べ替えることができる順列はすべて有効であると考える人もいるかもしれませんが、条件はより厳密です。 シーケンスはジャンプのない円周上で単調でなければなりません。 

いくつかの微妙な特殊なケースが要件を示しています。 

考慮する$n = 4$、 順序$[1, 3, 2, 4]$。 これは円の一方向のトラバースではありません。1 から 3 に進んだ後、2 をスキップして元に戻り、サイクル上の隣接関係が壊れるからです。 

考慮する$n = 5$、 順序$[3, 4, 5, 1, 2]$。 これはソート順のローテーションであるため有効です。 

考慮する$n = 4$、 順序$[4, 3, 2, 1]$。 これは逆走査に対応するため、これも有効です。 

重要なプロパティは隣接モジュロです$n$。 

## アプローチ

 ブルートフォースのアイデアは、円内のすべての可能な開始点を試し、モジュロの昇順または降順でシーケンスを一致させようとすることです。$n$。 開始インデックスごとに、トラバーサルをシミュレートし、順列が一致しているかどうかを確認します。 各シミュレーションの費用$O(n)$、そして、あります$n$スタートポジション、$O(n^2)$テストケースごとに。 と$n = 10^4$、これは次のようになります$10^8$テスト ケースごとの操作数が多く、制限時間に対して遅すぎます。 

問題の構造により、すべての回転を試す必要がありません。 シーケンスが有効な場合、連続するすべてのペアはサイクル上の隣接ペアを表す必要があります。 つまり、最初のステップで方向を修正すると、後続のステップはすべて強制されます。 唯一のあいまいさは方向です: 昇順または降順モジュロ$n$。 

したがって、すべての回転をチェックする代わりに、順列が +1 ステップ シーケンス モジュロのいずれかと一致しているかどうかをチェックします。$n$(ラップアラウンドあり) または -1 ステップ シーケンス モジュロ$n$。 これにより、問題は 2 つのリニア スキャンに減ります。

 ## アルゴリズムのチュートリアル

 数値を長さのサイクル上の点として扱います$n$、その後$n$1が来て、1が来る前に$n$。 

1. シーケンスを読み取り、モジュロで連続する要素間の差を計算します。$n$。 生の減算の代わりに、2 つの連続する数値がサイクル上で前方または後方に 1 だけ異なるかどうかとして隣接関係を正規化します。 これは、隣接する値の場合を意味します。$a$そして$b$かどうかを確認します。$b = a + 1$、$b = a - 1$、またはラップケース$(a, b) = (n, 1)$または$(1, n)$。 
2. 最初のペアから方向を決定します。 最初のトランジションが 1 ずつ増加している場合 (からのラップを含む)$n \to 1$)、順方向を想定してシーケンス全体をテストします。 1減少している場合（からのラップを含む）$1 \to n$)、逆方向をテストします。 どちらも当てはまらない場合、答えは即座に「NO」になります。 
3. 選択した方向について、シーケンスを左から右にスキャンし、隣接するすべてのペアが同じステップ ルールに従っていることを確認します。 方向はすべてのトランジションで一貫していなければなりません。 
4. すべての遷移が順方向または逆方向のいずれかに一致する場合は YES を出力し、そうでない場合は NO を出力します。 

### なぜ効果があるのか

 有効な循環トラバーサルには厳格なローカル構造があり、すべての要素がサイクル上にちょうど 2 つの隣接要素を持ちます。 2 つの連続する要素を観察したら、どの隣接関係が使用されているかを判断します。 サイクルは均一であるため、このローカルな決定によってグローバルな構造が決まります。 後の遷移がこの隣接パターンから逸脱すると、シーケンスはどの方向へのサイクルの連続トラバースにも対応できなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def check(a):
    n = len(a)

    def ok_forward():
        for i in range(n - 1):
            if a[i + 1] != a[i] + 1 and not (a[i] == n and a[i + 1] == 1):
                return False
        return True

    def ok_backward():
        for i in range(n - 1):
            if a[i + 1] != a[i] - 1 and not (a[i] == 1 and a[i + 1] == n):
                return False
        return True

    return ok_forward() or ok_backward()

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    print("YES" if check(a) else "NO")
```この実装は、サイクルの 2 つの可能な走査を直接エンコードします。 前方チェックでは、特殊なラップ ケースを除き、すべてのステップが 1 つずつ増加するように強制されます。$n$に戻る$1$。 逆方向チェックでは、ラップからのデクリメントを対称的に強制します。$1$に$n$。 

微妙な点は、シーケンスを「回転」しようとしていないことです。 回転しても隣接関係は維持されるため、回転は無関係です。 有効なサイクル トラバーサルは、開始点に関係なく隣接プロパティを満たします。 

## 実用的な例

 ### 例 1:$[1, 2, 3, 4]$| 私 | a[i] | a[i+1] | チェック |
 | --- | --- | --- | --- |
 | 0 | 1 | 2 | +1 有効 |
 | 1 | 2 | 3 | +1 有効 |
 | 2 | 3 | 4 | +1 有効 |

 前方チェックは完全にパスしたため、出力は YES になります。 

2 は 0 ではない、または 1 から折り返されないため、最初の遷移で後方チェックはすぐに失敗します。 

これは、一方向へのきれいな単調なトラバースを示しています。 

### 例 2:$[3, 2, 1, 4]$| 私 | a[i] | a[i+1] | チェック |
 | --- | --- | --- | --- |
 | 0 | 3 | 2 | -1 有効 |
 | 1 | 2 | 1 | -1 有効 |
 | 2 | 1 | 4 | 有効なラップ |

 逆方向は全体を通して維持されるため、出力は YES になります。 

これにより、逆順序の回転が受け入れられることが確認されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = []
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        def check(a):
            n = len(a)

            def ok_forward():
                for i in range(n - 1):
                    if a[i + 1] != a[i] + 1 and not (a[i] == n and a[i + 1] == 1):
                        return False
                return True

            def ok_backward():
                for i in range(n - 1):
                    if a[i + 1] != a[i] - 1 and not (a[i] == 1 and a[i + 1] == n):
                        return False
                return True

            return ok_forward() or ok_backward()

        output.append("YES" if check(a) else "NO")
    return "\n".join(output)

# sample-like tests
assert run("1\n3\n1 2 3\n") == "YES"
assert run("1\n3\n1 3 2\n") == "YES"

# custom tests

assert run("1\n4\n4 3 2 1\n") == "YES"

 ## 特殊なケース

 のような最小限のケース$n = 1$単一の要素が前方サイクルと後方サイクルの両方を自明に形成するため、常にパスします。 

のために$n = 2$、 両方$[1, 2]$そして$[2, 1]$各ステップは 2 ノード サイクルでの有効な隣接移動であるため、これらは有効です。 各方向チェックはすぐに成功するため、アルゴリズムは両方を受け入れます。 

次のようなラップの多いシーケンスの場合$[n, 1, 2, \ldots, n-1]$、前方チェックは、からのラップ遷移を検証します。$n \to 1$そして一貫して続いています。 逆方向チェックはすぐに失敗しますが、必要なのは一方向だけです。 

次のような混合シーケンスの場合$[1, 3, 2, 4]$、最初の遷移は方向を示唆している可能性がありますが、2 番目の遷移は隣接関係に違反しています。 スキャンは 2 回目の比較時にこれを即座に検出し、誤認を防ぎます。
