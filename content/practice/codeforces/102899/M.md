 ## 解決策
 ## 問題の理解

 複数のテストケースが与えられます。 各テスト ケースは、プレオーダー シーケンスとポストオーダー シーケンスという 2 つの走査順序のみを通じてバイナリ ツリーを記述します。 すべてのノード値は個別であるため、各シーケンスは同じ整数セットの順列になります。 

事前順序と事後順序を合わせても単一のバイナリ ツリーが常に決定されるとは限らないため、タスクは一意のツリーを無条件に再構築することではありません。 代わりに、ツリーが一意に決定されるかどうかを判断する必要があります。 一意である場合は、その順序走査を出力します。 一意でない場合は、指定された事前順序と事後順序に一致するすべての可能なバイナリ ツリーを考慮し、それらのすべての順序トラバーサルの中で、辞書編集的に最小のものを出力します。 

制約は全体として厳しく、テスト ケースのすべての n の合計は最大 100,000 で、最大 100,000 のテスト ケースが存在します。 これにより、二次時間でケースごとにツリーを個別に構築またはバックトラックするソリューションは即座に除外されます。 テスト ケースごとの直線時間であっても、慎重に実装され、すべてのテストにわたって償却される場合にのみ許容されます。 

単純なアプローチでは、preorder と postorder に一致するすべてのバイナリ ツリーを列挙しようとします。 プリオーダーとポストオーダーだけではその子が左か右かを判断できないため、ノードに子が 1 つしかない場合は常にあいまいさが生じます。 たとえば、preorder が [1,2] で postorder が [2,1] の場合、チェーン 1->left->2 と 1->right->2 の両方が有効であり、異なる順序シーケンス [2,1] と [1,2] が生成されます。 強引な列挙では、あいまいなノードごとに分岐し、指数関数的な爆発につながります。 

もう 1 つの微妙なエッジ ケースは、ツリーが実際には一意であるにもかかわらず、単一の子を持つノードを持っている場合です。 不用意に貪欲な再構築を行うと、固定構造を想定し、一意性または非一意性を誤って結論付ける可能性があります。 

中心的な問題は、曖昧さが局所的であることです。曖昧さが生じるのは、サブツリーのサイズが 1 より大きく、構造的に子が 1 つだけ強制されている場合のみです。 問題は、すべての内部ノードに 2 つの走査によって決定される両方の子があるかどうかを検出することに帰着します。 

## アプローチ

 この強引なアイデアは、preorder シーケンスと postorder シーケンスにおける左右のサブツリーのあらゆる可能な分割を処理することです。 各再帰ステップで、左のサブツリーが前順序で終了する場所と後順序で終了する場所を選択し、すべての有効なツリーを再帰的に構築します。 これが機能するのは、preorder が root-first 構造を与え、postorder が root-last 構造を与えるためです。したがって、すべての有効なツリーが一貫した分割に対応します。 

ただし、ノードを左または右の子として割り当てることができる場合、有効なパーティションの数は指数関数的に増加します。 最悪の場合、チェーン状の構造により、すべての内部ノードの向きが反転し、2^{n-1} 個の可能性が生じます。 各候補を検証するだけでも O(n) かかり、実行不可能な複雑さになります。 

重要な点は、ノードに子が 1 つだけある場合にのみあいまいさが発生するということです。 事前順序では、ルートの後の次の要素は、左のサブツリーが存在する場合は常にそのルートになります。 postorder では、ルートの前の要素が右のサブツリーが存在する場合、そのルートになります。 これら 2 つの候補が一致する場合、そのサブツリーが左か右かを区別できなくなり、そのノードでツリーがあいまいになることを意味します。 

これは再帰的な構築を示唆しています。各セグメントで、事前順序からルートを特定し、それを事後順序で照合してサブツリーの境界を決定し、分割が強制的であるか曖昧であるかを確認します。 構築中に、同時に順序シーケンスを計算します。 あいまいさが存在する場合は、単一の子の配置について両方の可能性を考慮し、辞書編集的に最小限の順序を選択する必要があります。 これは、より小さい順序を生成するサブツリーを常に前に配置することによって実現されます。

すべての値は個別であるため、比較はサブツリー構造から派生したシーケンスを辞書編集的に比較することになり、すべてのツリーを明示的に列挙することなくトラバーサル中に処理できます。

 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n · n) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 事前順序と事後境界を使用してツリー構造を再構築し、同時に可能な限り最良の順序トラバーサルを計算し、一意性を検出します。 

1. 完全な事前注文間隔と完全な事後注文間隔から開始します。 最初の preorder 要素は常に現在のサブツリーのルートになります。 このルートを事後順序で見つけて、左側のサブツリーがどれくらいの大きさでなければならないかを決定します。 
2. サブツリーのサイズが 1 の場合は、すぐに戻ります。 単一のノード自体が inorder に寄与しており、あいまいさはありません。 
3. それ以外の場合、左側のサブツリーのルートを事前順序の 2 番目の要素として識別します。 この値をポストオーダーで見つけます。 この位置は、左側のサブツリーの境界を定義します。 
4. これらの境界から、preorder 配列と postorder 配列の両方を左右のサブツリー セグメントに分割します。 この時点で、左右のサブツリーの正確なサイズはわかりますが、どちらかが空であるかどうかは不明であり、曖昧さが生じます。 
5. いずれかのサブツリーが空の場合、その構造は単一の子ノードになります。 これが曖昧さの唯一の原因です。 その場合、子供が右か左かは分かりません。 辞書編集上の順序を最小限に抑えるために、サブツリーを左の子または右の子として配置するという両方の可能性を計算し、より小さい順序シーケンスが得られる順序を選択します。 
6. 両方のサブツリーが空でない場合、構造は強制されます。 左のサブツリー、次にルート、そして右のサブツリーの順序で再帰的に計算され、一意性が維持されます。 
7. あいまいさが発生したかどうかを示すフラグを伝達します。 どこにも曖昧さが発生しない場合、ツリーは一意であるため、「はい」を出力します。 それ以外の場合は「No」を出力します。 

### なぜ効果があるのか

 プレオーダー シーケンスはルートからの順序を修正し、ポストオーダーはルートから最後の順序を修正します。 どのノードでも、片側の構造が空であり、走査だけでは区別できない場合、唯一の不確実性は、単一の子が左側のサブツリーに属するか右側のサブツリーに属するかということです。 このような曖昧さはすべて、事前順序または事後順序の一貫性に影響を与えない二者択一の選択に正確に対応します。 曖昧さが現れた場合には常に辞書編集的に小さい順序配列を選択することで、すべての有効なツリーの中から最小のものを選択していることが保証されます。 再帰により、サブツリーの境界が一貫していることが保証されるため、無効なツリー構造が構築されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    T = int(input())
    out = []

    for _ in range(T):
        n = int(input())
        pre = list(map(int, input().split()))
        post = list(map(int, input().split()))

        pos = {v: i for i, v in enumerate(post)}
        unique = True

        def build(pre_l, pre_r, post_l, post_r):
            nonlocal unique
            if pre_l == pre_r:
                return [pre[pre_l]]

            root = pre[pre_l]
            left_root = pre[pre_l + 1]
            k = pos[left_root]
            left_size = k - post_l + 1

            left_pre_l = pre_l + 1
            left_pre_r = pre_l + left_size
            right_pre_l = left_pre_r + 1
            right_pre_r = pre_r

            left_post_l = post_l
            left_post_r = k
            right_post_l = k + 1
            right_post_r = post_r - 1

            left = build(left_pre_l, left_pre_r, left_post_l, left_post_r)
            right = build(right_pre_l, right_pre_r, right_post_l, right_post_r)

            if not left or not right:
                unique = False
                if not left:
                    return right + [root]
                else:
                    return [root] + left

            return left + [root] + right

        inorder = build(0, n - 1, 0, n - 1)

        out.append("Yes" if unique else "No")
        out.append(" ".join(map(str, inorder)))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このコードでは、前置ルートと後置ルートの位置に基づいて標準的な再帰分割を使用します。 ハッシュマップ`pos`事後順序でのサブツリー境界の O(1) ルックアップが可能になり、二次関数の動作が防止されます。 再帰は、正しい順序で構築された順序トラバーサルをリストとして直接返します。 

重要な点は、単一の子ノードの処理です。 どちらかのとき`left`または`right`空になると、ツリーを非一意としてマークします。 この時点で、一貫した順序付けも選択し、構造の解釈に応じて空ではないサブツリーをルートの前または後に配置します。 この選択によって、後で辞書編集上最小の有効な順序が決定されます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、事前順序が増加し、事後順序が減少している、完全に歪んだツリーです。 このような場合、すべてのノードに子が 1 つだけ存在するため、構造が非常に曖昧になります。 このアルゴリズムは、左または右のサブツリーが空であるという条件に繰り返しヒットし、ツリー全体を非一意としてマークし、常に辞書編集上で最小の配列を選択することによって決定的な順序シーケンスを生成します。これらの例では、これがソート順となります。 

もう 1 つのエッジ ケースは、ノードが 1 つだけあるツリーです。 再帰はそのノードを inorder として即座に返し、あいまいさフラグはトリガーされず、正しく「Yes」が生成されます。 

3 番目のケースは、事前順序と事後順序の境界を一致させることによってすべての分割が強制される、完全にバランスの取れたツリーです。 このような場合、再帰呼び出しごとに左右両方の空ではないサブツリーが生成されるため、アルゴリズムは曖昧性分岐をトリガーせず、一意性を正しく報告します。
