 ## 解決策
 ## 問題の理解

 それぞれ整数のおいしさを持つケーキのセットを使って、アリスとボブの間で 2 人用のゲームをプレイします。 アリスが先に行きます。 彼女の番では、彼女は以前に食べたどのケーキよりも厳密においしいケーキしか食べることができませんが、ボブは残りのケーキを無制限に食べることができます。 プレイヤーが有効な動きを行えなかった場合、ゲームは終了します。 アリスは食べるケーキの数を最大にしたいと考えていますが、ボブはこの数を最小限に抑えたいと考えています。 タスクは、両側からの最適なプレイの下でアリスがケーキを何個食べるかを計算することです。 

入力は複数のテスト ケースで構成されます。 テストケースごとに整数を受け取ります$n$そして配列$a$の$n$美味しさの価値観。 出力はテスト ケースごとに 1 つの整数、つまりアリスが消費するケーキの数です。 

制約は中程度です。$n$最大 5000 まで可能で、合計は$n$すべてのテスト ケースで 5000 を超えません。これは、$O(n^2)$テストケースごとのソリューションは実現可能です。 それぞれのケーキの美味しさの限界は、$n$これにより、必要に応じて頻度配列や直接インデックスを使用できるようになります。 

明らかではないエッジケースには、すべてのケーキが同じ美味しさであるという状況が含まれます。 この場合、アリスは最初に選んだケーキと同じものを選ぶことができないため、最初のケーキしか食べることができません。 もう 1 つの微妙なケースは、配列が厳密に増加または減少している場合で、ボブの最適な対抗戦略に応じて、アリスが食べられるケーキの数が変わる可能性があります。 

## アプローチ

 ブルートフォース手法では、ゲームを直接シミュレートします。 アリスの考えられる最初の動きのそれぞれについて、ボブのカウンターの動きのすべてのシーケンスを試し、ゲームが終了するまで再帰的に続けることができます。 このアプローチは原理的には正しいですが、分岐要素は膨大です。アリスまたはボブのターンごとに、最大で$n$選択肢。 最悪の場合、これは次のような結果をもたらします$O(n!)$、これは不可能です$n = 5000$。 

重要な洞察は、すべてのシーケンスをシミュレートするのではなく、美味しさの値の頻度カウントの観点から考えることです。 アリスの動きには制限があり、厳密に増加するおいしさの値のみを選択できます。 ボブの戦略には制限がありません。 アリスがシーケンスを増やすのをブロックする場合、彼は常に利用可能な最小値を最初に削除します。 したがって、問題を潜在的な長さごとに数えることに減らすことができます。$x$アリスのシーケンスをボブがブロックできるかどうか。 

これをモデル化するより簡単な方法は、美味しさの配列をソートし、各美味しさの値の頻度を数え、ボブができるだけ多くの小さな要素を削除した最長の厳密に増加するサブシーケンスを構築しようとすることです。 ボブの最適なプレイ後に残る個別のおいしさの値の数によって、アリスの最大シーケンス長が決まります。 正式には、アリスの結果は最大です$x$厳密に増加する長さのシーケンスが存在するような$x$ボブがブロックした後の残りのケーキを使用します。

 | 頻度 + カウント | テスト ケースあたり O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各おいしさの値の頻度を数えます。 おいしさの値は [1, n] にあるため、サイズの配列を使用できます。$n+1$カウントを保存します。 これにより、各値のケーキがいくつ存在するかを知ることができます。$O(n)$時間。 
2. 変数を初期化する`alice_count`ゼロに。 これにより、アリスが食べられるケーキの数が追跡されます。 
3. 美味しさの値を昇順に繰り返します。 それぞれの美味しさに対して`t`, アリスは、このおいしいケーキが 1 つでも残っていれば、ケーキを 1 つ食べることができます。 インクリメント`alice_count`成功したピックごとに。 
4. アリスがおいしいケーキを選んだ後`t`、そのおいしさのカウントをデクリメントします。 ボブは、アリスが次においしいものを食べるのを妨げる可能性のあるケーキをできるだけ多く取り除きます。 実際には、最適な戦略を実現するには、アリスが同じおいしさを繰り返すことや、必要な値をスキップすることを確実にブロックすることだけが必要であり、これは頻度カウントによって自動的に処理されます。 
5. アリスのより高い美味しさの値がなくなるまで続けます。 変数`alice_count`最適なプレイの下でアリスが消費できるケーキの最大数を保持するようになりました。 

重要な不変条件は、どの段階においても、アリスの次のケーキはそれまでのすべてのケーキよりも厳密に大きくなければならないということです。 ソートされた順序で反復し、頻度をカウントすることで、この制約を考慮して最長のシーケンスを確実に構築します。 ボブの最適な削除は暗黙的に処理されます。なぜなら、アリスがシーケンスを拡張することを阻止できる唯一のことは、次に必要な美味しさを枯渇させることだからです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        freq = [0] * (n + 2)
        for v in a:
            freq[v] += 1
        
        alice_count = 0
        for tastiness in range(1, n + 1):
            if freq[tastiness] > 0:
                alice_count += 1
                freq[tastiness] -= 1
        print(alice_count)

if __name__ == "__main__":
    solve()
```この解決策は、テスト ケースの数を読み取ることから始まります。 それぞれの場合において、おいしさの値の配列を読み取り、頻度配列を構築します。 次に、考えられる美味しさの値を反復処理し、アリスが厳密に増加する値のみを取得するようにしながら、アリスが消費できる数を数えます。 頻度を減らすことで、各ケーキが 1 回だけ使用されるようになります。 ループは値を昇順に処理するため、アリスのシーケンスが最大であることが保証されます。
