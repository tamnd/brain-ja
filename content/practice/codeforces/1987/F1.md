 ## 解決策
 ## 問題の理解

 長さの整数の配列が与えられます$n$。 各ステップでインデックスを選択できます$i$どこ$a_i = i$そして$i < n$、両方を削除します$a_i$そして$a_{i+1}$。 目標は、有効なインデックスが存在しなくなるまで、この操作を実行できる回数を最大化することです。 各テスト ケースは独立しており、すべてのテスト ケースの合計は$n$すべてのテスト ケースの数は 100 を超えません。これは小さいため、3 次または 2 次の動作を伴うソリューションを快適に検討できます。 

概念的には、これは 1 から始まるインデックスに一致する配列内のサブシーケンスを見つけて、それらを効率的に削除することに関する問題です。 単純なアプローチでは、すべての位置を繰り返しチェックし、有効な場合は 2 つの要素を削除して、続行することを検討する可能性があります。 ただし、エッジ ケースには注意が必要です。配列が厳密に増加しているがインデックスをスキップしている場合、または配列が非常に短い (長さ 1 または 2) 場合、操作が不可能になる可能性があります。 たとえば、次の場合$a = [1]$または$a = [2, 2]$、操作は発生せず、出力は 0 になるはずです。 

連続した操作が重複する可能性がある場合、別の微妙な問題が発生します。 考慮する$a = [1, 2, 2, 3]$。 インデックス 1 を選択すると、要素 [1,2] が削除され、[2,3] が残ります。 ここで、次の有効な操作は新しいインデックス 1 (元のインデックス 3) で発生します。アルゴリズムが可能な操作をスキップしないようにするために、慎重なアカウンティングが必要です。 

## アプローチ

 ブルートフォース手法では、配列を反復処理して有効なインデックスを検索します。$i$どこ$a_i = i$そして$i < n$。 見つかったら削除します$a_i$そして$a_{i+1}$、残りの要素を左にシフトし、有効なインデックスがなくなるまで繰り返します。 これは小さな配列では機能しますが、最悪の場合の複雑さは次のとおりです。$O(n^2)$なぜなら、削除するたびに要素を移動し、すべての位置を繰り返し確認する必要があるからです。 のために$n$100 までであれば、このアプローチは機能しますが、特により大きな制約に一般化したい場合、効率的に実装するのは面倒です。 

最適なアプローチの重要な観察は、配列が一連の連続セグメントとしてモデル化でき、各セグメントが動作条件に対して「場違い」な要素の数を表すということです。 各セグメント内で発生する可能性のある操作の数を追跡すると、動的計画法を使用して問題を解決できます。 具体的には、次のような DP 配列を維持できます。`dp[i]`インデックスで終わるプレフィックスに対して可能な操作の最大数です。`i`。 各ステップで、現在のインデックスが$i$満足する$a_i = i$、その後、以前のソリューションと組み合わせて、連続した削除を考慮します。 これにより、複雑さが軽減されます。$O(n^2)$すべてのステップで実際の配列の変更を必要とせずに済みます。 

つまり、ブルートフォースはプロセスを直接シミュレートするため機能しますが、明確さと一般化には失敗します。 問題をプレフィックス上の DP として観察すると、配列をシフトせずに最大演算数を計算できるため、解決策がすっきりして推論しやすくなります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n) | 小さい n に対しては機能しますが、退屈です |
 | 動的プログラミング | O(n^2) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 長さの DP 配列を初期化します。$n+1$ゼロ付き。 ここ`dp[i]`インデックスで終わる配列のプレフィックスに対して可能な操作の最大数を表します`i`。 
2. 配列を左から右に繰り返します。 インデックスごとに`i`(1 ベース)、以前のすべてのインデックスを考慮します`j < i`サブ配列かどうかを確認します`a[j..i]`有効な操作シーケンスを形成できます。 サブ配列は次の場合に有効です。`a[k] <= k-j+1`みんなのために`k`で`j..i`。 有効な場合は更新します`dp[i] = max(dp[i], dp[j-1] + 1)`。 
3. すべてのインデックスを処理した後の配列全体の最大操作数は次のとおりです。`dp[n]`。 
4. すべてのテスト ケースに対してこのプロセスを繰り返します。 

なぜ機能するのか: DP 配列は次の不変式を維持します。`dp[i]`は常に、プレフィックスに対して実行可能な最適な操作の数を表します。`[1..i]`。 で終了する有効な操作が可能な場合`i`、正確性を保証する前に、プレフィックスの最適解に 1 つの操作を追加します。 有効なサブ配列を決してスキップせず、常に最大化するため、これによりグローバルな最適化が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        dp = [0] * (n + 1)
        for i in range(n):
            cnt = 0
            for j in range(i, -1, -1):
                cnt += 1
                if a[j] == cnt:
                    dp[i+1] = max(dp[i+1], dp[j] + 1)
        print(dp[n])

solve()
```外側のループはテスト ケースの数を読み取ります。 Inside each test case, we initialize a DP array and iterate over the array indices. 内側のループは現在のセグメントの長さを逆方向にカウントし、要素が「セグメント開始からの距離」と一致するかどうかをチェックします。`a_i = i`セグメントに調整した時の状態。 更新中`dp[i+1]`これにより、各プレフィックスに対して可能な操作の最大数が蓄積されるようになります。
