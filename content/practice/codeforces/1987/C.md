 ## 解決策
 ## 問題の理解

 私たちは、それぞれの花が初期の高さを持っている、一列に配置された花の庭園をシミュレートするように求められました。 風は毎秒左から吹き、厳密なルールに従って一部の花の高さを低くします。つまり、列の最後の花であるか、すぐ右側の花よりも高い場合、花は縮みます。 それぞれの減少は正確に 1 単位であり、花がゼロを下回ることはありません。 タスクは、すべての花が高さ 0 に達するまでに何秒かかるかを決定することです。 

入力は複数のテスト ケースで構成され、それぞれが花の数と初期の高さを示します。 出力は、すべての高さがゼロになるまでの秒数です。 制約は重要です。花の数はテスト ケースごとに最大 10^5 であり、テスト ケース全体の合計も最大 10^5 です。 これは、高さが大きい場合、最悪の場合、最大 10^9 の操作が必要になる可能性があるため、花ごとに 1 秒ごとの単純なシミュレーションでは時間がかかりすぎることを意味します。 

重要なエッジ ケースは、高さが厳密に左から右に増加している場合 ([1、2、3] など) に発生します。 単純なシミュレーションでは、最初に最後の花だけをデクリメントし、その後、徐々に前の花をデクリメントします。 不用意に実装すると、すべての花を同時に減らそうとしたり、左から右の順序を無視しようとしたりして、不正確な結果が生じる可能性があります。 もう 1 つの微妙なケースは、すべての花が等しい場合です。 たとえば、[2, 2, 2] は、各花が同時に減少する可能性があるため、最大の高さと同じ数秒しかかかりません。ただし、次の花との比較に関するルールは、最初に最後の花のみが減少し、その後減少分が左に伝播することを意味します。 

## アプローチ

 ブルートフォース手法では、すべての花を反復処理してルールを適用することで、毎秒シミュレーションします。 概念的には単純で正しいですが、これにはテスト ケースごとに O(n * max(h_i)) の操作が必要ですが、n が 10^5 まで、高さが 10^9 までの場合は実行できません。 

重要な洞察は、位置 i にある花がゼロに達するまでにかかる秒数は、右から左に移動するときに発生する最大高さによって決まりますが、伝播制約があるということです。つまり、花が次の花より高くない場合、その花の減少は、次に高い花が低くなるまで遅延されます。 実際には、「風の効果」を右から左への高低差の伝播としてモデル化できます。 この観察により、右から左にスキャンし、伝播を考慮した後で各花の有効高さを追跡することで、合計時間を計算することができます。 最適なソリューションでは、シミュレーションがテスト ケースごとに 1 つの O(n) パスに削減され、1 秒ごとの反復が完全に回避されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(n * max(h_i)) | O(n) | 遅すぎる |
 | 右から左への伝播 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 変数を初期化する`seconds`ゼロにすると、必要な合計秒数が保存されます。 
2. 花の高さのスキャンを右から左に開始し、`current_max`これは、花が合計持続期間に寄与する有効最大高さを表します。 初期化する`current_max = 0`。 
3. 位置 i の各花 (左に移動する最後の花から開始) を更新します。`current_max`自身の高さの最大値として、`current_max + 1`。 の`+1`これは、右側の伝播が許可するまで左側の花が減少し始めることができないという事実を説明しています。 
4. アップデート後`current_max`花ごとに更新します`seconds`間の最大値として`seconds`そして`current_max`。 これにより、`seconds`これまでに処理されたすべての花がゼロになるまでに必要な時間を常に反映します。 
5. すべての花の処理が完了したら、`seconds`必要な合計秒数が含まれます。 

**機能する理由**: 伝播ロジックは、風によって背の高い花や最後の花が減り始めるまで花は減らないというルールを捉えています。 右から左にスキャンすると、各花の有効高さはそれ自体になるか、その右側の花の最大有効高さよりも 1 つだけ遅れます。 この不変条件により、すべての有効高さの最大値が、すべての花がゼロに達するまでの合計時間が正しく反映されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        h = list(map(int, input().split()))
        seconds = 0
        current_max = 0
        # Process flowers from right to left
        for height in reversed(h):
            current_max = max(height, current_max + 1)
            seconds = max(seconds, current_max)
        print(seconds)

if __name__ == "__main__":
    solve()
```コードはテスト ケースの数を読み取り、それぞれを個別に処理します。 高さのリストを逆にして、単一パスで右から左への伝播を適用します。`current_max`伝播の効果を蓄積し、`seconds`最大持続時間を追跡します。 このアプローチでは、1 秒ごとのシミュレーションが回避され、非常に大きな高さを効率的に処理できます。 

## 実用的な例

 最初のサンプル入力の場合`[1, 1, 2]`、右から左にスキャンします。 

| 私 | 身長 | 現在の最大値 | 秒 |
 | --- | --- | --- | --- |
 | 2 | 2 | 最大(2, 0+1)=2 | 2 |
 | 1 | 1 | 最大(1, 2+1)=3 | 3 |
 | 0 | 1 | 最大(1, 3+1)=4 | 4 |

 結果は`4`、サンプル出力と一致します。 

入力用`[7, 4, 4, 3, 2]`:

 | 私 | 身長 | 現在の最大値 | 秒 |
 | --- | --- | --- | --- |
 | 4 | 2 | 最大(2,0+1)=2 | 2 |
 | 3 | 3 | 最大(3,2+1)=3 | 3 |
 | 2 | 4 | 最大(4,3+1)=4 | 4 |
 | 1 | 4 | 最大(4,4+1)=5 | 5 |
 | 0 | 7 | 最大(7,5+1)=7 | 7 |

 結果は`7`、サンプル出力と一致します。

import sys, io

def run(inp: str) -> str:

        solve()
    return out.getvalue().strip()

 ## 特殊なケース

 一輪の花に対して`[5]`、アルゴリズムセット`current_max = max(5,0+1)=5`、`seconds=max(0,5)=5`、正しく出力されています`5`。 すべて同じ高さの場合`[2,2,2]`、逆スキャンの更新`current_max`2、3、4 のようになります。結果は次のようになります。`seconds = 4`。 これにより、遅延伝播が正確に捕捉されます。 このアルゴリズムは、1 秒ごとにシミュレーションを行わず、有効な最大値のみを伝播するため、大きな高さを自然に処理します。
