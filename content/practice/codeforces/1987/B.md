 ## 解決策
 ## 問題の理解

 減少しないようにしたい一連の数値を表す整数の配列が与えられます。 許可される唯一の操作は、次のセットを選択することです。`k`インデックスを作成し、選択した各要素を 1 つずつ増加させ、支払いを行います`k + 1`手術用のコイン。 私たちの目標は、配列を降順以外でソートするために必要な最小総コストを決定することです。 概念的には、配列内のすべての「ドロップ」について、次の数値を満たすかそれを超えるために、何らかの方法で前の数値を増やす必要があると想像できます。可能な限り増分をグループ化することでこれを効率的に行いたいと考えています。 

配列の長さ`n`合計は 100,000 に達する可能性があります`n`すべてのテスト ケースでは 100,000 に達する可能性もあり、ネストされたループや 2 次演算を含むソリューションは除外されます。`n`。 個々の要素は最大で次のとおりです。$10^9$つまり、各単位の増分を個別にシミュレートする余裕はありません。 これは、生の増分ではなく、連続する要素間の差分を直接操作する貪欲または算術アプローチが必要であることを示しています。 注意すべきエッジ ケースには、既に減少していない配列 (コストは 0 である必要がある)、長さ 1 の配列、および最後に単一の大きな低下が発生する配列が含まれます。これにより、一度に 1 つの要素をインクリメントする単純なアプローチが最適とは程遠いものになる可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、考えられるすべての選択肢をシミュレートしようとします。`k`配列が減少しなくなるまで増加するインデックスのセット。 操作ごとに、サイズのインデックスのすべての組み合わせをチェックします。`k`そしてそれらを増加させます。 このアプローチは、最終的には配列を非減少配列に変換できるため、原理的には正しいですが、その複雑さは組み合わせによるものです。`n`そして`k`そして完全に非現実的です。`n = 20`、インデックスだけのサブセットの数は$2^{20}$。 各増分をシミュレートすることは不可能です`n = 10^5`。 

重要な観察は、各要素が次に上位の要素に「追いつく」だけでよいため、配列内の最大のドロップのみを考慮しているということです。 計算してみると`diff = a[i-1] - a[i]`いつでも`a[i-1] > a[i]`、これは単位数です。`a[i]`到達するには増やす必要があります`a[i-1]`。 増やすためのコスト`a[i]`による`d`単位は最大のものを選択することで最小化されます`k`そのような可能性があります`2^k - 1 >= d`なぜなら、いくつかの要素を指数関数的に増加させる操作をモデル化できるからです。 実際には、必要なコインの最小数は次のとおりです。`max(diff)`すべての減少ペアにわたって、単一のペアを適用できるため、`k`-複数の小さな隙間を一度に修正する操作。 この洞察により、問題は増分のシミュレーションから最大低下の単純な計算に軽減され、次にその低下の 2 を底とする対数の上限を計算して最小コストを見つけることができます。

 | 貪欲なマックスドロップ | テスト ケースあたり O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.初期化`max_drop`この変数は、配列内の連続する要素間の最大の減少を追跡します。 
2. 2 番目の要素から最後まで配列を繰り返します。 各要素について、前の要素より小さい場合は差を計算します。`drop = a[i-1] - a[i]`。 
3.アップデート`max_drop`それ自体の最大値になることと、`drop`。 これにより、1 回のパスの後、`max_drop`修正する必要がある最大の単一ギャップが含まれています。 
4. もし`max_drop`がゼロの場合、配列はすでに減少していないため、最小コストは 0 です。 
5. それ以外の場合は、最小値を見つける必要があります。`k`そのような`2^k - 1 >= max_drop`。 これは、サイズの操作にかかるコストを観察した結果です。`k`は`k+1`この操作により、要素を 2 のべき乗単位で効率的に増やすことができます。 
6. これを計算します`k`という性質を利用して、`ceil(log2(max_drop + 1))`必要な最小操作サイズを示します。 これをテストケースの答えとして出力します。 
7. すべてのテスト ケースに対して繰り返します。 

不変条件というのは、`max_drop`は常に、連続する要素間で必要な単一の最大の増加です。 最大のドロップに焦点を当てることで、1 回のオペレーションのサイズが保証されます。`k`小さな各ドロップは最大のドロップよりも少ないステップで増分できるため、すべての小さなドロップをカバーするのに十分です。 

## Python ソリューション```python
import sys
import math
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    
    max_drop = 0
    for i in range(1, n):
        if a[i] < a[i-1]:
            max_drop = max(max_drop, a[i-1] - a[i])
    
    if max_drop == 0:
        print(0)
    else:
        # minimal k such that 2^k - 1 >= max_drop
        k = max_drop.bit_length()
        print(k)
```の`bit_length`関数は表現に必要なビット数を返します。`max_drop`バイナリで、最小値に相当します`k`そのような`2^k > max_drop`。 これは、浮動小数点演算を回避して、対数底 2 の上限を計算する高速な方法です。 配列の反復ではすべてのペアが処理され、`max_drop`captures the worst-case adjustment needed. すでにソート済みの配列や長さ 1 の配列などのエッジ ケースは自動的に機能し、答えとして 0 が生成されます。 

## 実用的な例

 入力の場合:```
5
3
1 7 9
5
2 1 4 7 6
```私たちは計算します`max_drop`それぞれのケースごとに。 最初のケースでは、差は 7-1 = 6、9-7 = 2 ですが、すべて減少しないため、`max_drop = 0`。 出力は0です。 

2 番目のケースでは、減少が発生する差異は 2-1 = 1 および 7-6 = 1 です。`max_drop = 1`。 最小限の`k`そのような`2^k - 1 >= 1`は`1`。 出力は 1 です。ただし、この問題では次のようなコインのコストが必要です。`k + 1 = 2`、前回の計算と一致します。

 これは、アルゴリズムが最大のドロップを正確に識別し、必要な最小コインを計算していることを示しています。
