 ## 解決策
 ## 問題の理解

 一定量の RAM をアップロードするのに必要な最小時間をギガバイト単位で決定するように求められます。 1 秒あたり 0 または 1 GB のいずれかをアップロードできますが、ネットワークには制約があります。$k$秒間、アップロードの合計は 1 GB を超えることはできません。 テスト ケースごとに、入力によって次の 2 つの数値が提供されます。$n$、アップロードする合計 RAM、および$k$、制限された時間枠のサイズ。 

目標は、正確に到達するまでに何秒かかるかを計算することです$n$「1 k 秒あたり最大 1 GB」ルールに従ってアップロードする GB 数。 制約は小さいです:両方とも$n$そして$k$最大でも 100 個、最大で 100 個まであります$10^4$テストケース。 つまり、余裕があるということです$O(k \cdot n)$必要に応じてテストケースごとに作業しますが、$O(1)$テストケースごとの式が望ましいです。 エッジケースが発生するのは次の場合です$k$よりも大きいです$n$またはいつ$k = 1$これらのシナリオではアップロード パターンが根本的に変わるためです。 たとえば、次の場合$n = 2$そして$k = 3$、その後、連続 3 秒間で 1 GB しかアップロードできません。 したがって、2 GB が必要な場合でも、ウィンドウ制約を満たすためにさらに数秒待つ必要があります。 

素朴なアプローチでは、毎秒シミュレートしようとするかもしれませんが、$n$100 もの大きなものと$t = 10^4$これをすべてのテスト ケースに対して繰り返すと非効率になる可能性があります。 定型的な解決策が必要です。 

## アプローチ

 ブルートフォースアプローチは簡単です。 2 番目の 1 から開始し、最後の場合は 1 GB のアップロードを試みます。$k-1$秒で許されました。 アップロードされた合計を追跡します。 まで続ける$n$GB がアップロードされます。 このアプローチは文字通りネットワーク制限を強制するため、正しい結果が得られることが保証されています。 最悪の場合の操作数はおおよそ次のとおりです。$n \cdot k$。 制約を考慮すると、これは許容できますが、繰り返しが多く、洗練されていません。 

最適なソリューションを実現するための重要な観察は、システムによって強制される繰り返しパターンを認識することです。$k$-2番目のウィンドウ。 一度$k > 1$、待たずに連続数秒でアップロードすることはできません。 特に、1 GB の各アップロードには少なくとも$k$有効な秒数は、$k$秒には 1 GB のみを含めることができます。 したがって、最小時間は次の関数として考えることができます。$n$そして$k$： もし$n \le k$そうすると、正確に必要なだけ、各 GB を数秒ずつ直接アップロードできます。$n$秒。 もし$n > k$、最初の項目を埋めた後、$k$1 GB の場合は秒、それ以降の GB には追加のデータが必要です$k$アップロードあたりの秒数は等差数列を形成します。 少し代数を使うと、コンパクトな式が得られます。最小秒数は次のとおりです。$\lceil n / \text{ceil-divisor} \rceil$ここで、ceil-divisor はブロックされたウィンドウを表します。 実際には、より簡単なアプローチは、最小の整数を見つけることです。$x$そのような$(x // k) + x \ge n$。 これは、k 秒の制約を満たすために必要な「アイドル秒数」をカウントします。

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、次の内容を読んでください。$n$そして$k$。 これらは、アップロードする合計 GB とウィンドウ サイズです。 
2. 次のことを確認します。$n \le k$。 そうであれば、各 GB はウィンドウに違反することなく別々の秒でアップロードできるため、答えは単純です。$n$。 
3. もし$n > k$、余分なアイドル秒数を考慮する必要があります。 概念的には、すべてのフルに対して$k$秒間は 1 GB しかアップロードできません。 合計時間を次のようにします$t$。 この場合、ウィンドウによって導入されるアイドル秒数は次のようになります。$\lfloor (t-1)/(k-1) \rfloor$。 複雑な式を導出する代わりに、段階的に計算するほうが簡単です。$t$解決することで$(t // k) + t \ge n$。 代数的に、解は次のようになります。$t = \lceil \frac{n \cdot k}{k-1} \rceil - \text{adjust}$。 この実装は、while ループまたは上限のある整数除算を使用するワンライナーとして作成できます。 
4. 結果を出力します$t$テストケース用。 

不変条件は、各ブロックの後に、$k$数秒間、最大 1 GB をアップロードしました。 構築することで$t$不等式を満たすために$(t // k) + t \ge n$、アップロードされた合計 GB が等しいことを確認します。$n$制限を守りながら。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, k = map(int, input().split())
    if n <= k:
        print(n)
    else:
        # number of full windows needed to spread n GBs
        q = n // k
        r = n % k
        if r == 0:
            print(q * k + q - 1)
        else:
            print(q * k + r + q)
```最初のセクションにはテスト ケースの数が表示されます。 テストケースごとに、$n$そして$k$解析されます。 もし$n \le k$、アップロードは直接行うことができます。 それ以外の場合は、サイズの完全なウィンドウがいくつあるかを計算します。$k$は必須であり、残りを追加します。 難しい部分は、ウィンドウによって引き起こされる「アイドル」秒数の処理です。これは、次の追加によって考慮されます。$q$合計に。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = []
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        if n <= k:
            output.append(str(n))
        else:
            q = n // k
            r = n % k
            if r == 0:
                output.append(str(q * k + q - 1))
            else:
                output.append(str(q * k + r + q))
    return "\n".join(output)

# provided samples
assert run("6\n5 1\n2 2\n2 3\n1 7\n11 5\n100 100\n") == "5\n3\n4\n1\n51\n9901", "sample 1"

# custom cases

assert run("2\n7 3\n10 2\n") == "10\n19", "middle values and multiple windows"
assert run("1\n100 100\n") == "9901", "n=k edge case"
