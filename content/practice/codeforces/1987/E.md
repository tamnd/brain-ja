 ## 解決策
 ## 問題の理解

 各ノードに整数値が割り当てられたルート付きツリーが与えられます。 ツリーのルートは頂点 1 です。リーフ以外のすべての頂点について、その値がその直接の子の値の合計以下である場合、そのツリーは「素晴らしい」とみなされます。 頂点の値を 1 ずつ増やす操作は何度でも実行できます。タスクは、ツリーを素晴らしいものにするために必要なそのような操作の最小数を見つけることです。 

入力は複数のテスト ケースで構成されます。 各テスト ケースは、頂点の数、頂点の初期値、およびツリー構造を定義する親配列を提供します。 出力は、必要な最小増分数を表すテスト ケースごとに 1 つの整数です。 

制約は中程度です。つまり、すべての制約を合計したものです。$n$これは、テスト ケースごとの二次アルゴリズムは許容できるが、それよりもさらに悪いものは遅すぎる可能性があることを意味します。 頂点の値は最大です$10^9$したがって、値自体に線形にスケールするアプローチを避ける必要があります。 

明らかではないエッジケースには次のようなものがあります。 

- すべてのノードが最初はゼロであるツリー。 たとえば、値を持つ 3 つのノードのチェーン`[0,0,0]`そしてエッジ`1-2, 2-3`。 素晴らしい条件を満たすには、リーフ以外のノードごとに最小限の増分が必要です。 
- 一部のノードが既に条件を満たしている一方で、他のノードが増分を必要とするツリー。 DFS 実装を不用意に行うと、必要な増加分を子から上に伝播できず、操作を過剰にカウントする可能性があります。 
- ルートに小さな値を持つ多くの子が含まれる星形のツリー。 ルートは子の合計条件を満たすために大幅な増分を必要とする場合がありますが、子も独自のサブツリーを満たすために再帰的に増分を必要とする場合があります。 

## アプローチ

 ブルートフォースアプローチは、ツリーが素晴らしいものになるまで、すべての非リーフノードを繰り返しチェックし、値を増分することです。 各反復ではすべてのノードがスキャンされ、値が 1 つずつ増加する可能性があります。 それは正しいですが、最悪の場合の複雑さは、必要なすべての増分を合計したものとほぼ同じであり、次のようなものになる可能性があります。$10^9$ノードごとに、明らかに実行不可能です。 

重要な洞察は、ツリーをボトムアップ方式で処理することです。 各子サブツリーに必要な値の合計が適切であることがわかっている場合は、この要件を親に伝播することができます。 具体的には、ノードが素晴らしいものであるためには、次の条件を満たす必要があります。$a_v \le \sum a_u$その子供たちに対して。 この不等式が成り立たない場合は、それを維持するために子の合計をどれだけ増分する必要があるかを正確に計算できます。 各サブツリーに必要な合計増分を再帰的に計算し、上方向に伝播することで、操作が過剰にカウントされることがないようにします。 これにより、問題は DFS に変わり、各ノードがそのローカル条件を満たすために必要な正確な数の操作を提供します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(合計増分 × n) | O(n) | 遅すぎる |
 | ボトムアップ DFS | テスト ケースあたり O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ツリー入力を解析し、親配列から隣接リストを構築します。 これにより、各ノードの子の効率的な走査が可能になります。 
2. 特定のノードに対して、そのサブツリー内の値の合計と、そのサブツリーを素晴らしいものにするために必要な増分の合計数を計算する再帰 DFS 関数を定義します。 
3. 各ノードの初期化`subtree_sum`独自の価値として、`operations`ゼロとして。 
4. すべての子供に対して繰り返します。 各子について、そのサブツリーの合計を次のように加算します。`subtree_sum`必要な操作を`operations`。 
5. すべての子を処理した後、現在のノードが次の条件を満たすかどうかを確認します。`a_v <= sum of children`。 そうでない場合は、差を計算し、それに応じて現在のノードの値を増分します。 この差を加えると、`operations`。 これにより、親はすでに素晴らしい条件を満たしている金額を確実に受け取ることができます。 
6. このノードをルートとするサブツリーと必要な操作の合計の合計を返します。 
7. DFS をルートから適用します。 ルートに対して返された操作の合計が答えになります。 

正確さを保証する不変条件は、各ノードの処理後、その値がその子の合計を超えず、すべての子自体が素晴らしいということです。 子からの操作と現在のノードで必要な増分を組み合わせることで、どのノードも 2 回カウントされないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10000)

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        p = list(map(int, input().split()))
        tree = [[] for _ in range(n)]
        for i, parent in enumerate(p):
            tree[parent - 1].append(i + 1)  # 0-indexed

        def dfs(v):
            if not tree[v]:
                return a[v], 0
            total_sum = 0
            ops = 0
            for u in tree[v]:
                child_sum, child_ops = dfs(u)
                total_sum += child_sum
                ops += child_ops
            if a[v] > total_sum:
                ops += a[v] - total_sum
                total_sum = a[v]
            else:
                total_sum = max(total_sum, a[v])
            return total_sum, ops

        _, ans = dfs(0)
        print(ans)

if __name__ == "__main__":
    solve()
```コードはまずテスト ケースの数を読み取り、各ケースを反復処理します。 ツリーは隣接リストとして表されます。 の`dfs`関数は、各サブツリーの値の合計と必要な操作の両方を再帰的に計算します。 リーフ ノードの場合、合計はノードの値とゼロの操作です。 内部ノードの場合、子の合計と演算を蓄積し、現在のノードが素晴らしい条件に違反しているかどうかを調整します。 

親から子へのインデックス付け、1 ベースのインデックスから 0 ベースのインデックスへの変換、および不要な操作を避けるためにリーフ ノードが正しく処理されるようにする場合は、細心の注意が必要です。 

## 実用的な例

 ### サンプル 1

 入力ツリー: 値`[9,3,4,1,2]`、エッジ`[1,1,3,3]`。 

| ノード | 子どもたち | 子供の合計 | ノード値 | 必要な操作 | 総運用数 |
 | --- | --- | --- | --- | --- | --- |
 | 4 | [] | 0 | 1 | 0 | 0 |
 | 5 | [] | 0 | 2 | 0 | 0 |
 | 3 | 4,5 | 3 | 4 | 1 | 1 |
 | 2 | [] | 0 | 3 | 0 | 0 |
 | 1 | 2,3 | 4+4=8 | 9 | 1 | 2 |

 これは、演算が子から上に向かって蓄積されるボトムアップ計算を示しています。 

### サンプル 2

 入力ツリー: 値`[5,3]`、エッジ`[1]`。 

| ノード | 子どもたち | 子供の合計 | ノード値 | 必要な操作 | 総運用数 |
 | --- | --- | --- | --- | --- | --- |
 | 2 | [] | 0 | 3 | 0 | 0 |
 | 1 | 2 | 3 | 5 | 2 | 2 |

 これにより、ルートに子の合計が不十分な場合でも、アルゴリズムが操作を正しくインクリメントしてカウントすることが確認されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | テスト ケースあたり O(n) | 各ノードは 1 回だけアクセスされ、ノードごとに一定の作業を実行します。 |
 | スペース | O(n) | 隣接リストと再帰スタックは深さ n までスタックされます。 |

 すべてのテスト ケースの n の合計は ≤5000 であるため、合計操作は最大 5000 であり、2 秒の制限に十分収まります。
