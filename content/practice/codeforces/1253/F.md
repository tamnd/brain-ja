 ## 解決策
 ## 問題の理解

 ノードのサブセットが「中心」となる重み付けされた無向グラフが与えられます。これは、ロボットがそこに到着するたびに、そのバッテリーが即座にフル容量まで充電されることを意味します。 ロボットは中央ノードで開始され、各クエリを終了する必要があります。 各エッジには重みがあり、それを横切るにはそれだけのエネルギーが消費されます。 ロボットは、その現在のエネルギーが少なくともエッジの重量に達しない限り、エッジを横切ることができません。 

問題は、バッテリー容量が固定されていないことです。 クエリごとに、ロボットが 1 つのセントラルでフル充電を開始し、別のセントラルに到達したい場合、エネルギー制約とセントラルでの再充電動作を考慮して、目的地に到達できるある程度の歩行 (必ずしも単純ではない) が存在するような、可能な最小のバッテリ容量はいくらですか?

 重要な構造の詳細は、ロボットがノードとエッジを再訪問する可能性がありますが、そのエネルギーをリセットできるのは中心のみであるということです。 非中心ノードは、リチャージ効果のない単なる中間状態です。 

制約が十分に大きいため、元のグラフ上のクエリごとの最短パスは遅すぎます。 最大 300,000 のエッジとクエリでは、クエリごとに 1 つのダイクストラさえも不可能です。 ノード上でエネルギーを明示的にシミュレートしようとするソリューションは、状態空間が「(ノード, 残りのエネルギー)」となり、大きすぎるため爆発します。 

あまり目立たない問題は、パスが複数のポイントでエネルギーを「リセット」できることです。これは、実効コストが通常の意味で単一のパスに沿って加算されないことを意味します。 元のグラフの中心間の単純な最短パスは制約を直接捉えません。各セグメントの最大エッジ重みがバッテリー容量によって制限されるセグメントに分割すると、長いパスが実現可能になる可能性があるからです。 

素朴な考えを打ち破るエッジ ケースには、単一の重いエッジを回避するために複数の中心部を経由する迂回を使用する最適なルートが含まれます。 たとえば、2 つの中心間の直接パスに重み 100 のエッジが含まれているが、すべてのエッジが 20 以下である中間の中心を通るより長いルートが存在する場合、たとえ最短パスに巨大なエッジが含まれていたとしても、容量 20 で十分です。 これは、総重量ではなくボトルネック制約を最適化していることを示しています。 

別の失敗例は、元のグラフの一部のパス上の最大エッジのみが必要であると仮定した場合です。 リチャージポイントは制約をリセットするため、複数の「局所的に実行可能な」セグメントをつなぎ合わせることが許可されているため、これも誤りです。 

## アプローチ

 強引なアイデアは、容量を固定することです`c`2 つの中心の間にパスが存在するかどうかを確認します。 これは、エッジの重みが現在のエネルギー以下であり、エネルギーが中心でリセットされる場合にのみエッジを横断できるという到達可能性の問題になります。 これをシミュレートするには、拡張状態の状態 BFS またはダイクストラが必要になります。`(node, energy)`あるいは、貪欲にパスをシミュレートしようとするでしょう。 いずれにせよ、単一の実現可能性チェックは大まかに次のとおりです。`O(m log n)`あるいはさらに悪いことに。 

各クエリではバイナリ検索が必要になるため、`c`、各小切手は高価なので、すぐに制限を超えます。 と`q = 3e5`、 平`O(m)`チェックあたりのサイズはすでに大きすぎます。 

重要な観察は、バッテリー制約が 2 つの再充電ポイント間で使用される最大エッジ重みのみを考慮するということです。 容量が決まったら`c`、事実上、ウェイト ≤ のエッジのみをトラバースすることが許可されます。`c`、しかし、中央でエネルギーをリセットするという点で「テレポート」できるという追加の自由があります。 これにより、グラフは、エッジをフィルタリングした後、中心間の接続のみが重要となる構造に変わります。 

これは、プロセスを逆にすることを示唆しています。つまり、クエリに個別に答える代わりに、すべてのエッジを重みでソートし、それらを段階的にアクティブ化します。 中心の各ペアについて、最小のしきい値を知りたいと考えています。`c`この「充電を意​​識した接続」の下で接続されるようになります。 

これはまさに、重みの増加順にエッジが追加されるグラフ上の動的な接続性の問題です。 セントラル間の接続は維持されますが、非セントラルはエンドポイントにならずにパスに接続できるため、接続はノード単独の標準 DSU ではありません。 標準的な方法はすべてのノードを処理することですが、DSU 接続はエッジがアクティブ化されると自動的に到達可能性を取得します。 すべてのエッジ ≤ c が存在すると、これらのエッジ内に留まるウォークは有効になるため、リチャージ制約は暗黙的に処理されます。中心間のすべてのセグメントは最大エッジ ≤ c を持ち、リチャージによりセグメント間の継続が可能になります。 

したがって、固定しきい値の場合、エッジ ≤ c のサブグラフ内の接続性があれば十分かつ必要です。 したがって、エッジ上にクラスカルのような構造を構築し、DSU を維持できます。 2 つのセントラルが接続された瞬間、DSU マージ パスに沿って使用される最大エッジがそのペアの答えとなります。 これは、マージが発生したときの追跡を強化したサイズ別ユニオン DSU を使用して保存します。通常は、Kruskal 再構築ツリーを構築するか、マージの重みを記録して LCA クエリに応答する DSU を使用することで解決されます。 

より洗練されたビューは、グラフ上に最小スパニング ツリーを構築することです。 MST では、2 つのノード間の一意のパス上の最大エッジが、元のグラフ内のすべての可能なパスの中で最小化されます。 実現可能性の条件は、リセットを伴う有効なウォークに沿って必要な最大エッジ キャパシティを最小限に抑えることであるため、MST パスの最大値が答えになります。

 ## アルゴリズムのチュートリアル

 この問題を、最小のスパニング ツリー上でパス上の最大エッジのクエリに答えるようにすることで解決します。 

1. すべてのエッジを重みで降順でない順に並べ替えます。 これにより、考えられる最小のボトルネックが最初に考慮されるため、実現可能性の高い順に接続が構築されます。 
2. クラスカルのアルゴリズムを実行して、最小スパニング ツリー (またはフォレスト、ただしグラフが接続されているためツリーになります) を構築します。 2 つのコンポーネントを結合するたびに、結合エッジと等しいエッジの重みを持つ親ノードが再構成ツリーに作成されます。 
3. 元のノードがリーフであり、各結合がマージされたコンポーネントを表す新しい内部ノードを作成する DSU ベースの再構成ツリーを構築します。 その内部ノードに保存されている重みは、マージを引き起こしたエッジの重みです。 この構造は、しきい値が増加するにつれて接続が現れる順序をエンコードします。 
4. この再構成ツリーで LCA を事前計算します。 各ノードについて、その深さとバイナリリフティングの親、およびそのノードからその祖先までの最大エッジ重みも保存します。 
5. 各クエリ (a、b) について、再構成ツリー内の LCA を計算します。 答えは、このツリーの a から b までのパスに沿った最大エッジ重みであり、これはプロセスの下でそれらを接続するために必要な最小容量に対応します。 

これが機能する理由は、Kruskal の構造により、2 つのノードが初めて接続されたときに、使用されるエッジがすべての可能な接続の中で最小限の最大重みを持つことが保証されるためです。 再構成ツリーはコンポーネントがマージするしきい値を正確にエンコードするため、LCA は 2 つの中心の最も早いマージ ポイントを捕捉します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

class DSU:
    def __init__(self, n):
        self.p = list(range(n))
        self.sz = [1]*n

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return False
        if self.sz[a] < self.sz[b]:
            a, b = b, a
        self.p[b] = a
        self.sz[a] += self.sz[b]
        return True

def solve():
    n, m, k, q = map(int, input().split())
    edges = []
    for _ in range(m):
        u, v, w = map(int, input().split())
        edges.append((w, u-1, v-1))

    edges.sort()

    # build Kruskal reconstruction tree
    N = 2*n
    dsu = DSU(N)
    tree = [[] for _ in range(N)]
    val = [0]*N
    ptr = n

    for w, u, v in edges:
        if dsu.union(u, v):
            ru = dsu.find(u)
            rv = dsu.find(v)
            new = ptr
            ptr += 1
            val[new] = w
            tree[new].append(ru)
            tree[new].append(rv)
            dsu.p[ru] = new
            dsu.p[rv] = new

    root = ptr - 1

    LOG = 20
    up = [[-1]*N for _ in range(LOG)]
    mx = [[0]*N for _ in range(LOG)]
    depth = [0]*N

    # build parent pointers
    order = list(range(ptr))
    for v in range(ptr):
        for to in tree[v]:
            up[0][to] = v
            mx[0][to] = val[v]
            depth[to] = depth[v] + 1

    for j in range(1, LOG):
        for v in range(ptr):
            if up[j-1][v] != -1:
                up[j][v] = up[j-1][up[j-1][v]]
                mx[j][v] = max(mx[j-1][v], mx[j-1][up[j-1][v]])

    def get(u, v):
        if depth[u] < depth[v]:
            u, v = v, u
        ans = 0
        diff = depth[u] - depth[v]
        for i in range(LOG):
            if diff >> i & 1:
                ans = max(ans, mx[i][u])
                u = up[i][u]
        if u == v:
            return ans
        for i in reversed(range(LOG)):
            if up[i][u] != up[i][v]:
                ans = max(ans, mx[i][u], mx[i][v])
                u = up[i][u]
                v = up[i][v]
        ans = max(ans, mx[0][u], mx[0][v])
        return ans

    for _ in range(q):
        a, b = map(int, input().split())
        print(get(a-1, b-1))

solve()
```DSU は、各結合が 2 つのコンポーネントが最初に接続された瞬間を表す新しいノードを導入する階層を構築します。 そのノードに格納されている値は、そのマージに関与するエッジの重みであり、まさにその接続イベントのしきい値コストです。 

バイナリ リフティング テーブルは祖先ジャンプに沿った最大エッジ重みを格納するため、クエリは再構築ツリー内の 2 つの中心間のパス上の最大マージ重みを計算することになります。 

微妙な点は、元のノードはこのツリーのリーフであるため、特別な処理を行わずに自然に LCA クエリに参加することです。 もう 1 つの詳細は、各結合の後に DSU 代表をリンクすることによって再構成ツリーが正しく構築されていることを確認する必要があることです。そうしないと、親子関係が矛盾してしまいます。 

## 実用的な例

 ### 例 1

 中心が分散している小さなチェーンを考慮し、そのうちの 2 つの間の接続性をクエリします。 

| ステップ | アクション | DSU の状態 | キーマージの重み |
 | --- | --- | --- | --- |
 | 1 | 最小のエッジを最初に処理する | コンポーネントが徐々に結合します | 2 |
 | 2 | 続けます。 より大きなコンポーネントのフォーム | 4 |
 | 3 | Merge が中央接続に到達 | ツリーノードが作成されました | 8 |

 クエリされた 2 つの中心間の LCA は、エッジの重み 12 が導入されたときに作成されたノードにあるため、答えは 12 になります。 

このトレースは、答えが、元のグラフの直接のパスによってではなく、クラスカル プロセスで中心を含む 2 つのコンポーネントが最初にマージされるときによって決定されることを示しています。 

### 例 2

 複数の代替ルートが存在するグラフを取り上げます。 

| ステップ | アクション | DSU の状態 | キーマージの重み |
 | --- | --- | --- | --- |
 | 1 | 明るいエッジを追加する | 小さなクラスターが形成されます。 5 |
 | 2 | 代替パスは重いエッジを回避します | コンポーネントは最大エッジを使用せずにマージします | 15 |
 | 3 | 直接の重いエッジは存在しますが、使用されていません。 MST では無視されます | 38 |

 再構築ツリーは、ノード間のパスが可能な限り最小限のボトルネックを使用することを保証し、重い直接エッジが存在する場合でも、より軽い接続構造が存在すれば答えに影響を与えないことを確認します。

 ## 特殊なケース

 主なエッジ ケースは、2 つの中心間の直接エッジが非常に大きいにもかかわらず、間接ルートが完全に小さなエッジを介して存在する場合です。 たとえば、ノード 1 と 2 が中心で、重み 1000 のエッジ (1,2) だけでなく、重み 2 と 3 のパス 1-3-4-2 がある場合、正解は 3 です。再構成ツリーでは、重み 1000 のエッジが MST で決して選択されないことが保証されているため、LCA ベースの答えでは正しく無視されます。 

もう 1 つのエッジ ケースは、複数の等しい重みのエッジがコンポーネントを異なる順序で接続する場合です。 Kruskal はそれらのいずれかを選択できますが、すべてが同じ重みを持っているため、再構成ツリー ノードは依然として同じ値を保持し、そのためパス上の最大クエリは安定したままになります。 

3 番目のケースは、中心が端点にある線形グラフです。 答えは単にチェーン上の最大エッジであり、LCA はその最大マージ ウェイトまで正確に減少し、再構成ツリーが元のパス構造の圧縮バージョンのように動作することが確認されます。
