 ## 解決策

 ## 問題の理解

 同じ長さの 2 つの配列が与えられ、非常に特殊な種類の変更が許可されます。最大 1 回だけ、連続するセグメントを選択し、そのセグメント内のすべての要素に同じ正の整数を追加できます。 タスクは、操作を行わないか、またはそのようなセグメントの追加を 1 つだけ使用して、最初の配列を 2 番目の配列に変換できるかどうかを判断することです。 

主な制限は、変更が単一の間隔にわたって均一であることです。 つまり、選択したセグメントの外側のすべてのインデックスは配列間ですでに一致している必要があり、セグメント内では対応する要素間の差が一定である必要があります。 

入力サイズは合計でテスト ケースごとに最大 100,000 に達するため、すべての可能なセグメントの二次チェックが明示的に除外されます。 どのソリューションでも、テスト ケースごとに各配列を線形時間でスキャンする必要があります。 

素朴な間違いは、差異が等しい複数の互いに素な「良好な」セグメントを選択できると想定することです。 連続セグメントが 1 つだけ許可されるため、これは失敗します。 たとえば、違いが次のようになった場合、`[0, 2, 0, 2, 0]`、それぞれ思うかもしれない。`2`は独立して修正できますが、1 回の操作で複数の別々の間隔をカバーすることはできません。 

もう 1 つの微妙なエッジ ケースは、差が負である 1 つの位置を除いてすべての差がゼロである場合です。 加算できるのは正の値のみであるため、負の差があるとすぐに答えは不可能になります。 

失敗例:

 入力:```
3
1 2 3
2 1 3
```ここでの違いは`[+1, -1, 0]`。 ほとんどのインデックスは問題がないように見えますが、マイナスの差が 1 つあるとそれが不可能になります。 

正しい出力:`NO`。 

## アプローチ

 ブルートフォース戦略では、考えられるすべてのセグメントを試します`[l, r]`陽性が存在するかどうかを計算します`k`追加する`k`そのセグメントに変換される`a`の中へ`b`。 固定セグメントの場合、すべての差を計算します。`b[i] - a[i]`セグメント内でそれらが同一で正であることを確認し、外側の要素がすべてすでに一致していることも確認します。 

ワンセグメントの料金を確認する`O(n)`最悪の場合、`O(n^2)`セグメントにつながる`O(n^3)`合計時間は遅すぎます。 

重要な観察は、この操作が差分配列上に非常に厳密な構造を定義していることです。`d[i] = b[i] - a[i]`。 最大 1 回の操作の後、すべての非ゼロ値が`d`は 1 つの連続したセグメント内に存在する必要があり、そのセグメント内ではすべての値が同一で正である必要があります。 他の場所はすべて正確にゼロでなければなりません。 

したがって、セグメントを検索する代わりに、差分配列の構造を直接分析します。 すべてのゼロ以外のエントリが正確に 1 つの連続ブロックを形成しているかどうか、およびそのブロック内のすべての値が等しく正であるかどうかを確認するだけです。 

これにより、問題は「セグメントの選択」から「1 パスでのパターンの検証」に軽減されます。

 ## アルゴリズムのチュートリアル

 差分配列を暗黙的に次のように定義します。`d[i] = b[i] - a[i]`。 

1. 最初のインデックスを計算します。`d[i]`はゼロではありません。 存在しない場合、配列はすでに等しいので、すぐに YES を返します。 これは、操作が必要ない場合に対処します。 
2. この最初のゼロ以外の位置から、値を決定します。`k = d[start]`。 操作では一定の増分が強制されるため、これが操作で追加できる唯一の値です。 
3. から順方向にスキャンします`start`差分がゼロでないすべての位置に正確な値があることを確認します`k`。 ゼロ以外の別の値が表示された場合、単一の均一な増分では変換を説明できないことを意味します。 
4. ゼロ以外のすべての差が単一の連続ブロックに現れることを確認します。 ゼロ以外の値のブロックを離れたら、後で別のゼロ以外の値に遭遇してはなりません。 そうする場合、必要な操作には 2 つの別個のセグメントが必要になりますが、これは許可されません。 
5.また、`k > 0`。 この演算では正の整数の加算のみが許可されるため、正以外の値は取得できません。 

機能する理由: この操作は、定数オフセットによって 1 つの間隔だけを変更するため、有効な操作後の差分配列は、すべての値が同じ正の定数に等しい、おそらく 1 つの連続した間隔を除くすべての場所でゼロでなければなりません。 アルゴリズムはこの構造特性を正確にチェックするため、逸脱は不可能であることを意味します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    i = 0
    while i < n and a[i] == b[i]:
        i += 1

    if i == n:
        print("YES")
        return

    k = b[i] - a[i]
    if k <= 0:
        print("NO")
        return

    while i < n and a[i] != b[i]:
        if b[i] - a[i] != k:
            print("NO")
            return
        i += 1

    while i < n:
        if a[i] != b[i]:
            print("NO")
            return
        i += 1

    print("YES")

t = int(input())
for _ in range(t):
    solve()
```この解決策では、まず不一致領域の開始位置を特定します。 このインデックスにより、唯一の実行可能な増分値が決定されます。 次に、不一致領域全体が一貫していて連続していることを検証し、最終的に、後でさらなる不一致が発生しないことを確認します。 

一般的な実装の落とし穴は、連続性を強制することを忘れることです。そのため、複数の分離されたブロックに不一致が現れるケースを受け入れることになります。 もう 1 つの微妙な問題は、負またはゼロを拒否できないことです。`k`、演算には厳密に正の加算が必要なため、これは無効です。

                return
            i += 1

        out.append("YES")

    for _ in range(t):
        solve()

    return "\n".join(out)

 ## 特殊なケース

 エッジケースの 1 つは、配列がすでに同一である場合です。 アルゴリズムは、不一致インデックスが見つからない場合にこれを検出し、計算を試行せずにすぐに YES を返します。`k`。 

もう 1 つのケースは、不一致は存在するが連続していない場合です。 入力用`a = [1,1,1,1]`、`b = [2,1,2,1]`、差分配列は`[1,0,1,0]`。 スキャンで不一致が見つかった後、ゼロに戻り、その後別の不一致が見つかりました。これは単一セグメントの要件に違反し、正しく NO が生成されます。 

最後のエッジケースは、最初の不一致がすでにポジティブ性を侵害している場合です。 もし`b[i] < a[i]`最初の異なるインデックスでは、`k`値が負になると、操作は値を増やすことしかできないため、アルゴリズムはすぐに拒否します。
