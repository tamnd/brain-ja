 ## 問題の理解

 ## アルゴリズムのチュートリアル

 まず、すべてのお菓子を甘さの低い順に並べ替えます。 これにより、この配列のプレフィックスを取得するときに、あらゆる固定に対して可能な限り最適なセットが常に選択されることが保証されます。$k$。 

すべての人に向けた答えの構築をシミュレーションします$k$すぐに:

 1. 配列のソート$a$昇順で。 これにより、より小さい値が早い日に割り当てられるようになります。 
2. 現在の日のブロック内の値の累計と、ゼロに初期化されたグローバル回答配列を維持します。 
3. 並べ替えたお菓子を繰り返し、その位置を追跡します。 
4. 位置の各要素について$i$、その日のインデックスを次のように決定します。$\lfloor i / m \rfloor + 1$。 
5. すべてのサフィックス回答に影響するため、その寄与を累計に加算します。$x_k$どこ$k \ge i+1$。 
6. 回答を段階的に蓄積します。各プレフィックスは、正確にその数のお菓子を選択するための候補ソリューションを定義します。 
7. 結果の配列を出力します。

なぜそれが機能するのかは、議論のやりとりに関係しています。 2 つのお菓子の価値が間違っているが、後の日または早い日に配置されるのが一貫していない場合、より大きな値のより小さな乗数が得られるようにそれらを交換すると、常に総コストが減少または維持されます。 毎日の中で順序は重要ではありませんが、日をまたぐと、単調性によりソートされた順序でグループ化されます。 したがって、最適な構造は、サイズのバッチを並べ替えて埋めることによって一意に決定されます。$m$。

def solve():

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    a.sort()
    
    res = []
    for i in range(n):
        day = i // m + 1
        if i == 0:
            res.append(a[i] * day)
        else:
            res.append(res[-1] + a[i] * day)
    
    return " ".join(map(str, res))

# provided sample

 ## 特殊なケース

 いつ$m = 1$, すべてのお菓子は新しい日になるため、ペナルティは並べ替え後のプレフィックスの合計になります。 すべてのインデックスが独自のブロックを形成し、乗数が位置に等しいため、アルゴリズムはこれを自然に処理します。 

いつ$m \ge n$、すべてのお菓子は 1 日目に食べられるため、答えは単にスケーリングなしでソートされた配列のプレフィックス合計です。 整数除算ではすべてのインデックスの 1 日目が得られるため、計算は正しく削減されます。 

すべての値が等しい場合、原理的にはどのような順序でも最適ですが、バッチ処理では依然として乗数が増加します。 このアルゴリズムは、容量の制約により避けられない、より大きな日のインデックスを後で割り当て、達成可能な最小合計と一致させます。
