 ## 解決策
 ## 問題の理解

 私たちには学生のグループと、彼らのペア間の出会いの記録が与えられます。 一部の学生は最初に感染し、感染した学生が別の学生と会ったことが記録されるたびに、その接触関係を通じて感染が広がります。 記録されたすべての遭遇を処理した後、どの生徒が最終的に感染したかを判断する必要があります。 

入力を言い換える便利な方法は、生徒をグラフ内のノードとして、記録された各遭遇を無向エッジとして考えることです。 感染は、2 人の生徒が接触するという事実以外に、タイミングや方向には依存しません。 学生が感染すると、一連の接触を通じて連絡可能なすべての学生も感染します。 

通常、出力は、この伝播が安定した後の最終的な感染した生徒のセットまたは数になります。つまり、新たな感染の可能性はありません。 

制約の観点から見ると、この構造は約$10^5$生徒と連絡先。 感染したノードごとに繰り返しグラフの走査を試みるアプローチは、感染が大規模な接続コンポーネントを介してカスケードする可能性があるため、密集した場合には二次的な動作に低下します。 これにより、理想的には線形に近い解決策が得られます。$O(n + m)$または$O(m \alpha(n))$。 

ここではいくつかの特殊なケースが重要です。 最初に感染した生徒がいない場合は、感染源がないため、接触者に関係なく、回答は空のままにする必要があります。 最初に生徒全員が感染した場合、接触者がいなくても生徒全員が感染したままになります。 もう 1 つの微妙なケースは、連絡先リストが空であっても初期感染が存在する場合に発生します。 この場合、伝播パスがないため、初期セットのみが報告されます。 

## アプローチ

 直接シミュレーションでは、すべての接触者を繰り返しスキャンし、ラウンドで感染を拡大します。 各ラウンドですべてのエッジをチェックし、1 つのエンドポイントが感染している場合は新しい感染をマークします。 感染は端に沿ってのみ移動し、外側にのみ拡大する可能性があるため、これは正しいです。 ただし、最悪の場合、感染が連鎖的に伝播する可能性があります。$m$、各ラウンドですべてをスキャンします$m$エッジ、作成$O(nm)$行動。 と$m$近く$10^5$、これはすぐに実行不可能になります。 

重要な観察は、感染は遭遇の順序ではなく、接続のみに依存するということです。 2 人の学生が一連の接触によってつながると、時間的な順序に関係なく、感染が学生間を移動する可能性があります。 これにより、問題は、無向グラフ内の接続コンポーネントを見つけて、最初に感染したノードを少なくとも 1 つ含むコンポーネントを完全に感染しているとマークするという問題に軽減されます。 

この構造は、まさに Disjoint Set Union (DSU) または Union-Find 構造が効率的にキャプチャしたものです。 連絡先が記録されるたびに学生をマージし、その後、どのコンポーネントに感染源が含まれているかを確認します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | シミュレーション (エッジ上のマルチパス BFS) |$O(nm)$|$O(n + m)$| 遅すぎる |
 | DSU / 接続コンポーネント |$O(m \alpha(n))$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各生徒が独自のコンポーネントで開始する DSU 構造を初期化します。 これは、最初は連絡先が不明であるため、各ノードが分離されていることを表します。 
2. すべての連絡先ペアを読み取り、DSU でそれらのエンドポイントを結合します。 直接の遭遇によってコンポーネント間の接続が保証されるため、各ユニオンは 2 つのコンポーネントをマージします。 
3. どの生徒が最初に感染したかを示すブール配列を維持します。 
4. すべての結合が完了したら、各生徒の DSU コンポーネントの代表者を決定します。 コンポーネント内の生徒が感染している場合は、そのコンポーネントを感染済みとしてマークします。 
5. 最後に、すべての生徒を反復処理し、コンポーネントが感染しているとマークされている生徒を出力します。 

すべての結合が完了するまで感染の伝播を延期する理由は、DSU が処理順序に関係なく接続をエンコードするためです。 ユニオン操作中に感染を伝播させようとしても、最終的にはコンポーネント レベルの状態を維持する必要があり、最終パスでの計算がより簡単になります。 

### なぜ効果があるのか

 DSU は学生を等価クラスに分割します。各クラスは接触グラフの接続コンポーネントに対応します。 感染はエッジに沿って単調です。コンポーネント内の 1 つのノードが感染すると、そのコンポーネント内のすべてのノードが到達可能になるため、感染します。 これにより、「感染した生徒」と「最初に感染したノードを少なくとも 1 つ含むコンポーネント」との間に直接の等価性が作成され、正確性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return
        if self.size[ra] < self.size[rb]:
            ra, rb = rb, ra
        self.parent[rb] = ra
        self.size[ra] += self.size[rb]

def solve():
    n, m = map(int, input().split())
    infected_count = int(input())
    infected = list(map(int, input().split())) if infected_count else []

    infected = [x - 1 for x in infected]

    dsu = DSU(n)

    for _ in range(m):
        u, v = map(int, input().split())
        dsu.union(u - 1, v - 1)

    infected_root = set()
    for x in infected:
        infected_root.add(dsu.find(x))

    res = []
    for i in range(n):
        if dsu.find(i) in infected_root:
            res.append(str(i + 1))

    print(" ".join(res))

if __name__ == "__main__":
    solve()
```DSU 実装では、サイズによるパス圧縮と結合を使用して、操作ごとのほぼ一定の償却された複雑さを保証します。 結合ステップでは、連絡先リストから段階的に接続を構築します。 その後、感染セットはコンポーネントの代表にマッピングされるため、感染は個々のノードではなくコンポーネント全体の特性となります。 

最終スキャンでは、感染したコンポーネントのメンバーシップがチェックされます。 これにより、グラフの走査の繰り返しが回避され、各ノードが一定の回数処理されることが保証されます。 

## 実用的な例

 ### 例 1

 学生 5 人、接触者: (1,2)、(2,3)、(4,5)、および最初に感染した学生 1 を想定します。 

結合を処理した後、コンポーネント {1,2,3} と {4,5} を取得します。 コンポーネント {1,2,3} で感染が始まるため、そのコンポーネント内のすべての生徒が感染します。 

| ステップ | 操作 | DSU コンポーネント | 感染した根 |
 | --- | --- | --- | --- |
 | 1 | 初期化 | {1}{2}{3}{4}{5} | {1} |
 | 2 | ユニオン(1,2) | {1,2}{3}{4}{5} | {1} |
 | 3 | ユニオン(2,3) | {1,2,3}{4}{5} | {1} |
 | 4 | ユニオン(4,5) | {1,2,3}{4,5} | {1} |
 | 5 | マーク感染 | 同じ | {1,2,3} コンポーネント |

 出力は`1 2 3`。 

これにより、感染は直接の隣接だけではなく、接続に従っていることが確認されます。 

### 例 2

 4 人の生徒、接触者 (1,2)、(3,4)、および最初に感染した生徒 1 と 3 について考えてみましょう。 

2 つの切断されたコンポーネントが取得され、それぞれに感染源があります。 

| ステップ | 操作 | DSU コンポーネント | 感染した根 |
 | --- | --- | --- | --- |
 | 1 | 初期化 | {1}{2}{3}{4} | {1,3} |
 | 2 | ユニオン(1,2) | {1,2}{3}{4} | {1,3} |
 | 3 | ユニオン(3,4) | {1,2}{3,4} | {1,3} |

 両方のコンポーネントが感染しているため、すべての学生が感染しています。 

出力は`1 2 3 4`。 

これは、複数の接続されていない発生が個別に、しかし均一に処理されていることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(m \alpha(n) + n \alpha(n))$| 各結合/検索はパス圧縮によりほぼ一定です。 
| スペース |$O(n)$| DSU アレイと感染追跡 |

 この構造は、一般的な制約内に快適に適合します。$10^5$実際には、DSU の操作はほぼ直線的にスケールされるためです。

 ## 特殊なケース

 主なエッジケースは、感染が始まっても接触者がいない場合です。 たとえば、エッジがゼロの 3 人の生徒システムで生徒 2 が感染した場合、DSU は分離されたノードのままになります。 感染したルート セットには生徒 2 の代表のみが含まれており、これを変更する結合はありません。 出力には生徒 2 のみが正しくリストされています。 

もう 1 つのケースは、最初はすべての生徒が感染しているが、グラフが切断されている場合です。 DSU は依然として複数のコンポーネントを生成しますが、すべてのコンポーネントにはすでに感染が含まれているため、構造に関係なくすべてのノードが感染済みとしてマークされます。 これにより、アルゴリズムが接続に誤って依存して感染を作成するのではなく、感染を伝播するだけであることが確認されます。
