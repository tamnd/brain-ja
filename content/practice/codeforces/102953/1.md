 ## 解決策
 ## 問題の理解

 利用可能なステッカーを表す小文字の長いストリップが与えられます。 完成した各バナーでは、利用可能な順にステッカーを使用して、固定語「coderams」をバナーごとに 1 回正確に綴る必要がありますが、元の文字列内の連続した位置である必要はありません。 

タスクは、入力文字列内の複数の文字セットから、この単語の結合されていない完全なコピーがいくつ形成できるかを判断することです。 各ステッカーは最大 1 回使用でき、完全なコピーを組み立てることができる限り、位置のサブセットを自由に選択できます。 

したがって、問題は基本的にリソースのカウントに関するものです。各バナーは各文字を特定の数だけ消費します。そして、すべての要件を同時に何回満たせるかを知りたいのです。 

入力サイズは次のように大きくできます。$10^5$これにより、文字列を繰り返しスキャンしながら各バナーの形成を 1 つずつシミュレートしようとするアプローチは即座に除外されます。 バナーごとに文字を削除するグリーディ スキャンを繰り返すと、パフォーマンスが低下する可能性があります。$O(n^2)$最悪の場合、多数の部分一致または繰り返しパスがある場合に発生します。 

必須の文字が完全に欠落している場合、微妙な特殊なケースが発生します。 たとえば、文字列が「abcdef」の場合、バナーを 1 つも形成することはできず、たとえ他の文字がたくさん出現したとしても、答えはゼロでなければなりません。 もう 1 つのケースは、1 つの文字が他の文字と比べて非常にまれである場合です。たとえば、1 回しか出現しない必須文字を除くすべての文字が 10,000 回出現する場合です。 その状況では、ボトルネックは明らかにその 1 文字です。 

## アプローチ

 ブルートフォースアプローチでは、貪欲にバナーを構築しようとします。文字列をスキャンし、「コードラム」を形成するために文字を選択し、完全な単語が形成できなくなるまで繰り返します。 すべてのバナーは独立しており、異なる文字を使用しているため、これは正しいです。 ただし、単一のバナーを形成するために文字列をスキャンするたびにコストがかかります$O(n)$最悪の場合、再起動または遅延失敗するまでにパスごとに数文字しか消費しない可能性があり、最大で$O(n)$バナーと全体$O(n^2)$ランタイム。 

重要な観察は、順序はまったく重要ではなく、頻度だけが重要であるということです。 各バナーには文字の固定マルチセットが必要なので、問題全体は、入力文字列の頻度テーブルからそのマルチセットを何回減算できるかを計算することに帰着します。 これにより、問題は単純なボトルネック計算に変換されます。必要な文字ごとに、入力がサポートできるコピー数を計算し、これらの値の最小値が答えを決定します。 

これが機能する理由は、すべてのバナーの構造が同一であるためです。 合計数がわかれば、位置間の相互作用や順序制約はなくなるため、頻度の比較で十分です。

 ## アルゴリズムのチュートリアル

 まず、すべての有効なバナーには「coderams」という単語の文字が正確に含まれている必要があることを認識し、そのターゲット パターンを修正します。 

1. 入力文字列内のすべての文字の頻度をカウントします。 このステップでは、すべての位置情報を 1 つの要約に圧縮し、タスクにとって重要なものを正確に保持します。 
2. 「coderams」という単語に各文字が何回出現するかを数えます。 これは固定された一定の参照パターンです。c、o、d、e、r、a、m、s はそれぞれ 1 回だけ表示されます。 
3. 「coderams」内の個別の文字ごとに、利用可能な周波数を必要な周波数 (ここではすべての文字で 1) で割ることにより、サポートできるフル バナーの数を計算します。 
4. 最終的な答えは、これらの計算された比率の最小値です。 このステップでは、すべてのバナーがすべての文字要件を同時に満たさなければならないという考えを強制するため、最もまれな必要文字が制限を決定します。 

これが機能する理由は、グローバルなパッキング不変条件に基づいています: 構築後$k$バナー、必要な各文字が正確に消費されている必要があります$k$回。 いずれかのキャラクターが他のキャラクターよりも早くなくなると、コンティニューできなくなるため、可能な限り$k$は、必要な文字の中で利用可能な最小供給量です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    s = input().strip()

    target = "coderams"
    need = {}
    for ch in target:
        need[ch] = need.get(ch, 0) + 1

    freq = {}
    for ch in s:
        freq[ch] = freq.get(ch, 0) + 1

    ans = float('inf')
    for ch, req in need.items():
        ans = min(ans, freq.get(ch, 0) // req)

    print(ans if ans != float('inf') else 0)

if __name__ == "__main__":
    solve()
```このソリューションでは、入力を頻度辞書に圧縮し、単語の固定要件と直接比較します。 分割ステップでは、各文字がサポートできる完全なコピーの数が取得され、必要な文字が過剰に使用されないように最小値が強制されます。 

よくある間違いは、文字列から直接バナーの構築をシミュレートしようとすることです。 これにより、実際には問題に必要のない、不必要な順序付けの複雑さが生じます。 もう 1 つの微妙な落とし穴は、欠落している文字の処理を忘れることです。 を使用して`.get(ch, 0)`不正なキー エラーを回避し、必要な文字が存在しない場合に容量を正しくゼロにします。

 ## 特殊なケース

 主なエッジケースは、1 つ以上の必須文字が入力から完全に欠落している場合です。 たとえば、入力が次の場合:```
5
abcde
```いくつかの必須文字の頻度はゼロであるため、計算された最小値はすぐにゼロになります。 アルゴリズムはこれを自然に処理します。`freq.get(ch, 0)`これはゼロを生成し、特別なケースを使用せずに最終的な答えを強制的にゼロにします。 

もう 1 つの特殊なケースは、すべての文字が存在するものの、比率が非常に不均一である場合です。 例えば：```
10
ccccoooood
```ほとんどの文字は頻繁に出現しますが、「r」、「a」、「m」、または「s」などの必須文字が 1 つでも欠けていると、結果がゼロに折りたたまれ、シミュレーションを必要とせずに頻度ベースの最小値がその制約を正しく捉えます。
