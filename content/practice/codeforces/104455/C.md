 ## 解決策
 ## 問題の理解

 同じ長さの 3 つの配列が与えられ、各位置には正の整数が含まれます。 これらの配列から、制約された順序や構造で要素を選択しているのではなく、各配列から 1 つのインデックスを選択して独立したトリプルを形成しているだけです。 あらゆるインデックスの選択に対して$i, j, k$、積を計算します$a_i \cdot b_j \cdot c_k$そして、そのようなトリプルが正確にターゲット値を生成する数を数えたいとします。$m$。 

したがって、タスクは値に関する純粋な組み合わせです。各配列内のすべての出現は独立して関与し、同一の値は多重性を除いて区別できません。 

重要な制約は、$n$と同じ大きさにすることができます$5 \cdot 10^5$。 すべてのトリプルを直接列挙すると、次のようになります。$n^3$最悪の場合、$1.25 \cdot 10^{17}$操作。 たとえ強剪定を行ったとしても、その規模は2秒ではまったく不可能です。 これにより、問題をインデックス空間ではなく周波数空間に圧縮することが直ちに強制されます。 

もう 1 つの重要な制約は、すべての配列要素が最大でも$m$、 そして$m \le 10^9$。 これは、割り算の構造が中心となるため重要です。値が割り切れない場合$m$、有効なトリプルに寄与することはできません。 

いくつかの微妙なエッジケースが自然に現れます。 

もし$m = 1$の場合、有効なトリプルはすべて 1 で構成されている必要があります。 たとえば、すべての配列が$[1, 2]$の場合、3 つのピックすべてが 1 であるポジションのみが貢献し、その他はすべて無関係になります。 

配列に分割されていない値が含まれている場合$m$、 のような$a = [2, 3]$そして$m = 6$、次に、の約数のみ$m$非除数は完全に無視できます。 

さらに微妙なケースが発生するのは、$m$反復因子構造を持っています。 例えば、$m = 18$。 トリプルのような$(2, 3, 3)$、$(3, 3, 2)$、順列はすべて寄与しており、カウントでは一意の値ではなく配列全体の多重度を考慮する必要があります。 

単純な推論の主な失敗モードは、各配列の周波数多重度を適切に考慮せずに、これを値に対する単一の検索として扱うことです。 

## アプローチ

 この問題を直接考える方法は、すべてのインデックスのトリプルを反復処理し、積を計算し、それが次と等しいかどうかを確認することです。$m$。 これは問題の定義と正確に一致するため、正しいです。 ただし、3 つのネストされたループが必要です。$n$、生産$O(n^3)$操作。 と$n = 5 \cdot 10^5$、 平$n^2$すでに大きすぎるので、$n^3$決定的に不可能です。 

重要な観察は、製品の状態が 3 つのアレイ間で明確に分離されていることです。 インデックスの観点から考える代わりに、値の頻度を数えることに移ります。 各値が各配列に何回出現するかがわかっている場合、値の各選択は乗算的に寄与します。$x$表示されます$f_a[x]$回$a$、$f_b[y]$回$b$、 そして$f_c[z]$回$c$、次に生成されるインデックス トリプルの数$(x, y, z)$は$f_a[x] \cdot f_b[y] \cdot f_c[z]$。 

したがって、問題はすべての値のトリプルを数えるということになります。$(x, y, z)$そのような$x \cdot y \cdot z = m$、周波数によって重み付けされます。 

これは問題を次の約数構造に移します。$m$。 配列内のすべての値を反復処理する代わりに、次の約数のみを考慮します。$m$、有効なトリプルの因数は除算する必要があるため、$m$。 約数の数$m \le 10^9$は小さいため (最悪の場合でも最大でも数千)、列挙が可能になります。 

したがって、最適な戦略は、3 つの配列すべての周波数マップを計算し、約数を列挙することです。$x$そして$y$の$m$、推測します$z = m / (x \cdot y)$、それが整数であり、3 番目の周波数マップに存在することを確認します。 

これにより、検索スペースが減少します。$n^3$組み合わせのインデックスを大まかに付ける$d(m)^2$値の組み合わせ。$d(m)$は約数の数です$m$。

 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^3)$|$O(1)$| 遅すぎる |
 | 周波数 + 除数の列挙 |$O(n + d(m)^2)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列内のすべての値の頻度をカウントします。$a$、$b$、 そして$c$。 これにより、インデックスベースのカウントを多重度ベースのカウントに置き換えることができます。 
2. すべての約数を計算します。$m$。 各約数は、有効なトリプルの任意の位置に現れる可能性のある値を表します。 このステップは非常に重要です。$m$と同等の製品に参加できます$m$。 
3. 各約数を反復処理します。$x$の$m$。 扱う$x$配列から選択された値として$a$。 値に寄与するインデックスを選択する方法の数を答えに掛けます。$x$、これはその周波数です$a$。 
4. それぞれについて$x$、各約数を反復処理します。$y$の$m$。 扱う$y$配列の値として$b$。 We multiply by its frequency in$b$。 
5. コンピューティング$z = m / (x \cdot y)$。 もし$m$で割り切れない$x \cdot y$、有効な 3 番目の値が存在しないため、このペアをスキップします。 
6.次のことを確認します。$z$配列内に存在します$c$周波数マップを使用します。 その場合は追加してください$f_a[x] \cdot f_b[y] \cdot f_c[z]$答えに。 

### なぜ効果があるのか

 インデックスの有効なトリプルはすべて、値のトリプルに対応します。$(x, y, z)$そのような$x \cdot y \cdot z = m$。 アルゴリズムは、そのような値をすべて 3 回ずつ正確に 1 回列挙します。$x$そして$y$～のすべての約数にわたる範囲$m$、 そして$z$有効かどうかは一意に決まります。 各寄与は 3 つの配列からの独立した多重度によって重み付けされるため、有効なインデックスの組み合わせが欠落したり二重にカウントされたりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import Counter
import math

n, m = map(int, input().split())
a = list(map(int, input().split()))
b = list(map(int, input().split()))
c = list(map(int, input().split()))

fa = Counter(a)
fb = Counter(b)
fc = Counter(c)

divs = []
for i in range(1, int(math.isqrt(m)) + 1):
    if m % i == 0:
        divs.append(i)
        if i * i != m:
            divs.append(m // i)

ans = 0

for x in divs:
    if x not in fa:
        continue
    for y in divs:
        if y not in fb:
            continue
        prod = x * y
        if m % prod != 0:
            continue
        z = m // prod
        if z in fc:
            ans += fa[x] * fb[y] * fc[z]

print(ans)
```頻度マップはインデックス追跡を完全に置き換え、繰り返される値を正確に考慮します。 除数リストは一度作成されるため、因数分解作業を繰り返す必要がなくなります。 ネストされた除数ループは、最悪の場合でも除数の数が小さいため安全です。 

微妙な実装の詳細を確認中`m % prod != 0`計算する前に`z`これにより、無効な整数の除算のケースが防止され、不必要な辞書検索が回避されます。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import math
    from collections import Counter

    n, m = map(int, sys.stdin.readline().split())
    a = list(map(int, sys.stdin.readline().split()))
    b = list(map(int, sys.stdin.readline().split()))
    c = list(map(int, sys.stdin.readline().split()))

    fa, fb, fc = Counter(a), Counter(b), Counter(c)

    divs = []
    for i in range(1, int(math.isqrt(m)) + 1):
        if m % i == 0:

        for y in divs:
            prod = x * y
            if m % prod != 0:
                continue
            z = m // prod
            ans += fa[x] * fb[y] * fc[z]

    return str(ans)

 ## 特殊なケース

 エッジケースの 1 つは次のような場合です$m = 1$。 この状況では、すべての有効なトリプルは値 1 のみを使用する必要があります。除数リストには 1 しか含まれていないため、アルゴリズムはこれを自然に処理します。ループは 1 つのチェックに減ります。$x = y = z = 1$、結果は次のようになります$f_a[1] \cdot f_b[1] \cdot f_c[1]$、まさにその通りです。 

もう 1 つのケースは、配列に分割されない多くの値が含まれている場合です。$m$。 これらの値は除数リストには決して表示されないため、周波数ベースのループでは自動的に無視されます。 たとえば、次の場合$m = 10$配列に多くの 3 が含まれている場合、3 は約数の候補として考慮されないため、これらのエントリは参加しません。 

最後の微妙なケースは次のような場合です。$x \cdot y$を超える$m$。 小切手`m % prod != 0`無効な 3 番目のコンポーネントを決して試行しないようにします。 たとえば、次の場合$m = 12$、選択する$x = 4$そして$y = 4$結果として製品 16 が生成されますが、これは 3 番目のマップを検索する前にすぐに破棄されます。
