 ## 解決策
 ## 問題の理解

 4 つの大きな整数が与えられます。 各整数は直接の対象ではありません。 代わりに、それぞれが特定の観光地を訪れたかどうかをエンコードします。 

4 つの値 A、B、C、D のそれぞれについて、単純な数字のプロパティを計算します。数値の 10 進数のすべての桁を合計します。 この桁の合計が少なくとも 16 であるか、正確に 6 に等しい場合、対応するビューポイントは訪問済みであると見なされます。 それ以外の場合は訪問されません。 

4 つの視点を個別に評価した後、そのうちの何視点が訪問済みとしてマークされているかを数えます。 この数に基づいて、5 つの固定文字列のうちの 1 つを出力します。 

この制約により、各数値を 10^18 まで大きくできるため、各桁の合計の計算には最大 19 桁が含まれます。 これにより、複雑さの点で、桁ごとの直接スキャンが簡単になります。 最悪の場合でも、数値ごとに一定量の作業のみを実行するため、ソリューション全体は事実上一定時間になります。 

微妙なエッジ条件は、「合計 ≥ 16 または合計 = 6」という二重条件から生じます。 等価条件は、すでに値が 16 以上である場合には冗長ですが、小さな桁の合計を区別する場合には重要です。 「合計 ≥ 16」のみをチェックする単純な実装では、桁の合計がちょうど 6 の数値を誤分類してしまいます。 

たとえば、入力について考えてみましょう。`111`。 桁の合計は 3 なので、訪問されません。 バグのある実装が別のしきい値ルールを誤って使用したり、エッジ条件を忘れたりした場合、訪問したビューポイントのカウントを誤って、最終的な出力カテゴリが変更される可能性があります。 

4 つの値がすべて同一であるか、すべて 0 である場合、別の特殊なケースが発生します。 のために`0 0 0 0`、各桁の合計は 0 であるため、ビューポイントは訪問されず、最も低いカテゴリの出力が生成されます。 

## アプローチ

 ブルートフォース解釈では、文字通り各数値のルールをシミュレートします。つまり、桁の合計を計算し、条件をチェックし、合格した数をカウントします。 これはすでに最適に聞こえますが、隠れた組み合わせ構造がない理由を定式化するのに役立ちます。 

4 つの数値のそれぞれについて、桁の合計を計算するには O(d) かかります。d は桁数で、最大 19 です。これを 4 回実行すると、最大約 76 桁の演算が行われます。 多くのテスト ケースで繰り返した場合でも、小さな定数係数を伴う入力サイズは線形のままです。 

唯一の「単純な」代替案は、数値の事前計算や変換など、より複雑なことを試みることですが、A、B、C、D の間に相互作用はありません。それぞれの決定は独立しているため、直接評価を超える最適化は意味がありません。 

重要な観察は、問題は数値ごとに純粋に局所的であり、最終結果は [0,4] 内の小さな整数のカウントのみに依存するということです。 これがわかれば、解決策は単純な分類になります。

 ## アルゴリズムのチュートリアル

 1. 4 つの整数 A、B、C、D を読み取ります。これらは個別に処理されるため、前処理を組み合わせる必要はありません。 
2. 各数値について、10 を法として繰り返して 10 で割ることにより、その 10 進数の合計を計算します。これにより、必要な特徴がエンコーディングから直接再構築されます。 
3. 桁の合計が条件を満たすかどうかを確認します。条件は少なくとも 16 であるか、正確に 6 に等しい必要があります。満たしている場合は、このビューポイントを訪問済みとしてマークします。 このステップでは、問題の定義をブール値の決定にエンコードします。 
4. 4 つの視点のうち、訪問済みとマークされている視点の数のカウンターを維持します。 このカウンタの範囲は 0 ～ 4 のみで、後で出力カテゴリが決定されます。 
5. 問題の仕様に従って、最終的なカウントを必要な文字列出力にマップします。 

### なぜ効果があるのか

 各視点の決定は 1 つの数値のみに依存し、その桁の合計によって完全に決定されます。 桁の合計の計算はルールに関して正確かつ無損失であるため、各分類は単独では正確です。 最終的な答えは真の分類の数のみに依存するため、追加の構造や順序付けを必要とせずに、それらをカウンターで集計することで正確さが保たれます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def digit_sum(x: int) -> int:
    s = 0
    while x > 0:
        s += x % 10
        x //= 10
    return s

A, B, C, D = map(int, input().split())

vals = [A, B, C, D]
cnt = 0

for x in vals:
    s = digit_sum(x)
    if s >= 16 or s == 6:
        cnt += 1

if cnt == 0:
    print("Bao Bao is so Zhai......")
elif cnt == 1:
    print("Oh dear!!")
elif cnt == 2:
    print("BaoBao is good!!")
elif cnt == 3:
    print("Bao Bao is a SupEr man///!")
else:
    print("Oh my God!!!!!!!!!!!!!!!!!!!!!")
```桁合計関数は、標準の基数 10 の分解ループを使用します。 これにより文字列変換のオーバーヘッドが回避されますが、入力サイズが小さい場合はどちらのアプローチも有効です。 最後の条件構造は、5 つの出力カテゴリを直接エンコードします。 

文字列は正確であり、句読点や大文字の使用に影響されるため、マッピングは慎重に実装する必要があります。 余分なスペースを含め、逸脱があると、誤った答えが返されます。

 ## 特殊なケース

 入力用`0 0 0 0`、各桁の合計は 0 として計算されます。条件には少なくとも 16 か正確に 6 のいずれかが必要なので、どれも条件に該当しません。 カウンタは 0 のままで、アルゴリズムは「訪問者なし」という文字列を選択します。 数値がゼロであるため、数値合計ループは値ごとにすぐに終了します。 

入力用`6 0 0 0`の場合、最初の数値の桁合計は 6 であり、16 未満であっても等価条件を満たします。カウンターは 1 になり、出力は単一訪問のカテゴリに分類されます。 このケースでは、等価性チェックが誤って純粋なしきい値チェックに置き換えられていないことを具体的に検証します。
