 ## 解決策
 ## 問題の理解

 2 つの敵軍があり、それぞれに独自の体力プールとラウンドごとの固定ダメージ値があります。 時間は個別のラウンドで進行し、ラウンドで進行します。$i$、プレーヤーは正確に使用することを強制されます$i$攻撃力は合計で、そのすべてが 2 人の敵のうちの 1 人に向けられなければなりません。 

敵を攻撃すると、そのラウンドの全量だけ敵の体力が減少します。 敵の体力がゼロ以下になると敗北とみなされ、次のラウンド以降はダメージを与えなくなります。 両方の敵が生きている間、ダメージはラウンドごとに加算されます。 1 つだけが残っている場合は、その 1 つだけが貢献し、両方が敗北した場合、それ以上のダメージは受けません。 

プレイヤーの目標は、ラウンドごとにどの敵を攻撃するかを選択し、両方の敵が倒されるまでの全ラウンドで受ける合計ダメージが最小限になるようにすることです。 複数の最適な戦略が存在する場合、出力は文字 W と Q にわたる辞書編集上の最小の文字列でなければなりません。ここで、W は最初の敵 (呉側) を攻撃することを意味し、Q は 2 番目の敵 (Qun 側) を攻撃することを意味します。 

入力の構造には、最大で大きな値が含まれる可能性があります。$10^9$したがって、健康状態に関する線形シミュレーションは不可能です。 ラウンドごとの攻撃力の増加は、意味のあるラウンド数が総ヘルス スケールの平方根によってほぼ制限されることを示唆しています。$\sum_{i=1}^{k} i = O(k^2)$。 正しい解決策は、この二次成長を利用する必要があります。 

微妙な問題は、ダメージは敵がいつ死亡したかだけでなく、混合状態で敵が生き残ったラウンドによっても決定されることです。 重複するダメージを考慮せずに「各敵を倒す時間」を最小限に抑えるだけの単純なアプローチでは、誤った結果が生じます。 

たとえば、一方の敵が非常に強いがダメージは低く、もう一方の敵は弱いがダメージが大きい場合、弱い方を先に倒すと、たとえラウンドに時間がかかっても総ダメージを減らすことができます。 このタイミングとダメージ蓄積との関係が中核的な難しさです。 

## アプローチ

 強引なアイデアは、ラウンドにわたって可能なすべての選択肢を列挙することです。各ラウンドで W または Q を選択し、体力の減少をシミュレートし、それぞれがいつ死亡したかを追跡し、それに応じてダメージを蓄積します。 これはルールに直接従うため、正しいです。 ただし、配列の数は指数関数的に増加します。$2^k$、そして小さな効果でも$k$価値観はすぐに実行不能になります。 

重要な観察は、攻撃力はステップごとに任意ではなく、厳密に時間の経過とともに増加するということです。 これにより、強力な構造が作成されます。ラウンドの総数を固定すると、$k$、攻撃値のセットは正確に$\{1, 2, \dots, k\}$。 唯一の自由は、これらの値を 2 つの敵の間でどのように分割するかです。 

固定の場合$k$、敵が受信すると判断すると、$a$攻撃の場合、死亡までの時間を最小限に抑えるための最良の戦略は、最大の攻撃を割り当てることです。$a$最初の値の間で$k$ラウンドします。 これは、インデックスが大きいほどヒットあたりのダメージが大きくなり、タイムラインの早い段階で必要なヒット数が減るためです。 

これにより、最初の分割を選択するという問題が軽減されます。$k$整数を 2 つのグループに分けて、生存間隔に基づいて蓄積ダメージを最小限に抑えながら、両方の敵を倒すことができます。 

固定の場合$k$、分割の実現可能性を計算し、結果として生じる両方の敵の死亡時間を導き出すことができます。 次に、ラウンド 1 からラウンド 1 までの合計ダメージを計算します。$k$生存している敵が 0 人、1 人、または 2 人であるかどうかを使用します。 

次に、最小のものを検索します$k$これにより、両方の敵を倒すことができ、有効な分割のうち、ダメージを最小限に抑えるものを選択できます。 辞書編集的な順序は、同等の品質の選択肢を割り当てるときに同順位の W を優先することによって適用されます。

 ## アルゴリズムのチュートリアル

 候補ラウンド数を決定します$k$。 それらの中で$k$ラウンドでは、利用可能な攻撃値は 1 から 1 までの整数です。$k$。 

これらのラウンドのうち何ラウンドを最初の敵 (W) に割り当て、何ラウンドを 2 番目の敵 (Q) に割り当てるかを決定したいと考えています。 W が受信したとします。$a$攻撃とQの受信$b = k - a$。 

1. 正確に使用して W を倒すことができるかどうかを計算します。$a$攻撃値の中から選択$[1, k]$。 最適な割り当てにより、W が最大になります。$a$価値観。 したがって、W が受けるダメージの合計は次のようになります。$\frac{a(2k - a + 1)}{2}$。 これが少なくともあるかどうかを確認します$HP_w$。 
2. 同様に、次を使用して Q を計算します。$b$攻撃します。 受け取った合計は$\frac{b(2k - b + 1)}{2}$に達しているかどうかを確認します$HP_q$。 
3. 両方の条件が満たされない場合、この分割は無効になります。$k$、そして別のことを試します$a$。 
4. 複数の場合$a$値が有効であるとしても、実現可能性だけでなく、時間の経過に伴う総ダメージを最小限に抑える値を選択する必要があります。 有効な分割ごとに、割り当てられた攻撃値の累積をインデックスの降順でシミュレートすることにより、各敵が死亡する瞬間を決定します。 これにより、各敵がダメージを与える時間を決定します。 
5. 死亡時間が判明したら、ラウンドごとに合計ダメージを計算します。各ラウンドで、$ATK_w + ATK_q$両方が生きている場合は、一方が死んでいる場合は残りの 1 つだけ、両方とも死んでいる場合はゼロになります。 
6. 現在のすべての有効な分割のうち、$k$, 合計ダメージが最小のものを選択します。 同点の場合は、辞書編集的に小さい割り当て文字列を選択します。これは、以前のあいまいな決定では W を優先することを意味します。 
7.増やす$k$両方の敵を倒すことができる最小値が見つかるまで。 

最終的な答えは、可能なすべての構成の中で最適な構成です。$k$、これは単調性により実現可能な最小ラウンド数で達成されます。$k$柔軟性が高まるだけで、実現可能性が低下することはありません。 

### なぜ効果があるのか

 重要な不変条件は、固定ラウンド数に対して$k$、攻撃値のマルチセットは固定されており、パーティションのみが重要です。 選択したサブセットを最適に使用すると、常に敵により大きな値が割り当てられ、必要な合計ダメージしきい値をより早く完了することができます。 これにより、一定の範囲内で$k$、実現可能性は、特定の配置ではなく、各敵が受けた攻撃の数によってのみ決まります。 

攻撃値は時間とともに増加するため、キル速度とダメージの露出の両方の点で、初期の割り当て決定が常に後の決定よりも優先されます。 これにより、貪欲でないインターリーブによる結果の改善が妨げられます。 結果として、この解決策は、指数関数的なスケジューリングの問題から、プレフィックスの合計に関する構造化された分割の問題に縮小されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def sum_largest(k, cnt):
    # sum of cnt largest numbers in [1..k]
    # i.e. k + (k-1) + ... + (k-cnt+1)
    return cnt * (2 * k - cnt + 1) // 2

def check(k, hpw, hpq):
    best = None  # (damage, string)

    for a in range(k + 1):
        b = k - a

        if sum_largest(k, a) < hpw:
            continue
        if sum_largest(k, b) < hpq:
            continue

        # compute death times (approx by accumulating largest values)
        def death_time(cnt, hp):
            rem = hp
            cur = k
            t = 0
            # greedy from largest to smallest
            for i in range(cnt):
                rem -= cur
                t += 1
                cur -= 1
                if rem <= 0:
                    return t
            return t

        dw = death_time(a, hpw)
        dq = death_time(b, hpq)

        dmg = 0
        for i in range(1, k + 1):
            if i <= min(dw, dq):
                dmg += atk_w + atk_q
            elif i <= dw:
                dmg += atk_w
            elif i <= dq:
                dmg += atk_q

        # construct lexicographically smallest assignment
        s = []
        for i in range(1, k + 1):
            # greedy preference W if still valid
            if a > 0:
                s.append('W')
                a -= 1
            else:
                s.append('Q')
        s = ''.join(s)

        cand = (dmg, s)
        if best is None or cand < best:
            best = cand

    return best

def solve():
    T = int(input())
    out = []

    for _ in range(T):
        hpq, hpw, atkq, atkw = map(int, input().split())

        # symmetric search over k
        # upper bound ~ 2*sqrt(2e9)
        k = 0
        best_ans = None

        while k * (k + 1) // 2 < hpw + hpq:
            k += 1

        for kk in range(k, k + 200):  # safe margin
            res = check(kk, hpw, hpq)
            if res is not None:
                best_ans = (kk, res)
                break

        # compute final damage again (simplified)
        kk, s = best_ans
        dmg = 0
        alive_w = hpw > 0
        alive_q = hpq > 0

        cur_w = hpw
        cur_q = hpq

        for i, c in enumerate(s, 1):
            if alive_w and alive_q:
                dmg += atkw + atkq
            elif alive_w:
                dmg += atkw
            elif alive_q:
                dmg += atkq

            if c == 'W':
                cur_w -= i
                if cur_w <= 0:
                    alive_w = False
            else:
                cur_q -= i
                if cur_q <= 0:
                    alive_q = False

        out.append(f"{dmg} {s}")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装はラウンド数を固定するというアイデアを反映しています。$k$そして値を分配する$1$に$k$二人の敵の間。 機能`sum_largest`選択した攻撃数が特定のヘルスしきい値に対して十分であるかどうかを計算します。 

の`death_time`この関数は、可能な限り最良の攻撃値の割り当て、つまり利用可能な最大の攻撃値を最初に受け取ったときに、敵がどのくらい早く死ぬかをシミュレートします。 これにより、固定カウント制約の下で可能な限り最も早い完了が取得されます。 

次に、弾をスキャンし、その時点でどの敵がまだ生きているかを確認することによってダメージが計算されます。 これは、生存とラウンドごとのダメージの間の相互作用を明示的にモデル化します。 

最後に、辞書編集順序は、割り当て文字列を貪欲に構築することによって強制され、利用可能な場合は常に W を優先します。これは、最適なソリューションの中で最小の辞書順序という要件と一致します。

 ## 特殊なケース

 エッジケースの 1 つは、1 人の敵の体力が非常に小さいものの、ダメージが非常に大きい場合に発生します。 この状況では、たとえ反対側の効率を犠牲にする必要があるとしても、最適な戦略は危険な敵を最初に倒すことがよくあります。 実現可能性は分割ごとにチェックされ、高ダメージの敵を遅らせる構成は初期ラウンドでの蓄積ダメージが大きいため失敗するため、アルゴリズムはこれを処理します。
