 ## 解決策
 ## 問題の理解

 このタスクは、複数のシナリオのコマンド ラインの進行状況インジケーターをレンダリングすることです。 各シナリオでは、作業の総量と、そのうちのどれだけがすでに完了しているかを説明します。 これから、完了したユニットがハッシュ文字として表示され、残りのユニットがハイフンとして表示されるビジュアル バーを構築する必要があります。 このバーの横に、完了した作業の割合を 100 に換算して切り捨てたパーセンテージ値も出力します。 

各テスト ケースでは、ユニットの合計数と完了したユニットの数という 2 つの整数が与えられます。 それぞれの場合の出力は、括弧で囲まれたバー、その後に続くスペース、およびパーセント記号付きの整数パーセントで構成される 1 行です。 

重要な構造上の詳細は、進行状況バーには合計作業単位ごとに 1 つの文字が表示されるということです。 これは、出力が抽象化またはスケーリングされず、入力サイズを直接反映することを意味します。 

この制約により、最大 10 個のテスト ケースが許可され、各テスト ケースには最大 10 万ユニットを含めることができます。 これは、二次時間で文字列を構築する素朴なソリューションは遅すぎるが、テスト ケースごとに線形時間で各出力行を構築するソリューションは快適に高速であることを意味します。 すべてのテスト ケースの合計作業量は最大 100 万文字であり、これは 1 秒あたりの一般的な出力制限内に十分収まります。 

何も進んでいない場合、またはすべてが完了している場合には、微妙なエッジケースが発生します。 完了がゼロの場合、バーにはハイフンのみが含まれ、パーセンテージはゼロになります。 完了と合計が等しい場合、バーにはハッシュのみが含まれ、パーセンテージはちょうど 100 になる必要があります。 もう 1 つのエッジ ケースは、合計が 1 の場合です。この場合、バーは 1 つの文字に縮退しますが、丸め動作は依然として正しい必要があります。 

よくある間違いは、浮動小数点の除算と丸めを使用してパーセンテージを計算しようとすることです。これにより、精度の問題や不正な丸め動作が発生する可能性があります。 もう 1 つの間違いは、整数の除算は四捨五入ではなく、フロアベースでなければならないことを忘れていることです。 

## アプローチ

 出力を構築する直接的な方法は、進行状況バーを 1 文字ずつシミュレートすることです。 各テスト ケースについて、ゼロから n マイナス 1 までを繰り返し、インデックスが m 未満の場合はハッシュを追加し、それ以外の場合はハイフンを追加します。 バーを作成した後、m を 100 で割って n で割る整数除算を使用してパーセンテージを計算します。 このアプローチは、出力形式の定義に直接従うため、正しいです。 

非効率性の懸念は、実装が不十分な場合に文字列の連結が繰り返されることによってのみ発生します。 ループ内で不変文字列に繰り返し追加すると、複雑さが二次的な動作にまで低下する可能性があります。 ただし、文字のリストを構築して一度結合するか、文字列の直接乗算を使用する場合、構築は線形のままです。 

重要な観察は、出力の両方の部分が単純な算術と繰り返しによって完全に決定されるということです。 インデックスが m より小さいかどうか以外の位置間の依存関係はありません。 これにより、直接構築以外のシミュレーションの必要がなくなります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 文字ごとの連結 (単純な文字列の追加) | O(n^2) 最悪の場合 | O(n) | 遅すぎる |
 | 繰り返しまたはリスト結合を使用した直接構築 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 各テスト ケースについて、全長 n と完成量 m を読み取ります。 これら 2 つの値によって、バーとパーセンテージの両方が完全に決まります。 
2. m 個のハッシュ文字とそれに続く n から m 個のハイフンで構成される文字列を作成して、進行状況バーを作成します。 これが機能するのは、各位置が 1 つの作業単位に直接対応し、完了した単位が常にプレフィックスを占有するためです。 
3. m と 100 を n で乗算した整数除算としてパーセンテージを計算します。 これにより、ゼロに向かって切り捨てられ、必要なフロア動作が一致します。 
4. バーを角括弧で囲み、スペースを追加して、計算されたパーセンテージとその後にパーセント記号を付けて出力をフォーマットします。 

機能する理由: プログレス バーは、固定長配列に対するプレフィックス条件を直接エンコードしたものです。 すべての有効な表現では、サンプル構造と一致するように完成したすべてのユニットを最初に配置し、その後に残りのユニットをすべて配置する必要があります。 パーセンテージの計算は同じ比率の線形スケーリングであるため、両方の出力は同じ基礎となる部分の一貫したビューになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        bar = "#" * m + "-" * (n - m)
        percent = (m * 100) // n if n > 0 else 0
        sys.stdout.write(f"[{bar}] {percent}%\n")

if __name__ == "__main__":
    solve()
```この実装は Python のネイティブな文字列の繰り返しに依存しています。これは、最終的な文字列をその長さに比べて線形時間で構築するため効率的です。 表現`"#" * m`増分連結オーバーヘッドなしで正確に m 文字を生成します。 ハイフン部分も同様です。 

パーセントの計算では、浮動小数点精度の問題を回避するために、除算の前に整数の乗算が使用されます。 の条件付きガード`n > 0`制約の下では技術的には不要ですが、不正な入力に対して計算が堅牢になります。 

## 実用的な例

 n が 10、m が 2 の場合を考えてみましょう。バーは 2 つの完了したユニットと、その後に 8 つの不完全なユニットを示す必要があります。 

| ステップ | n | メートル | バーの建設 | パーセンテージ |
 | --- | --- | --- | --- | --- |
 | 1 | 10 | 2 | "" | - |
 | 2 | 10 | 2 | "##-----" | - |
 | 3 | 10 | 2 | "##-----" | 20 |

 バーは 2 つのハッシュを先頭に正しく配置し、パーセンテージは Floor(20) です。 

ここで、n が 5 に等しく、m が 0 に等しいと考えてください。 

| ステップ | n | メートル | バーの建設 | パーセンテージ |
 | --- | --- | --- | --- | --- |
 | 1 | 5 | 0 | "" | - |
 | 2 | 5 | 0 | "-----" | - |
 | 3 | 5 | 0 | "-----" | 0 |

 これにより、進行状況がゼロの場合、完全な破線のバーとゼロパーセントが生成されることが確認されます。 

これらの例は、境界の動作と、視覚的表現と数値表現の間の一貫性の両方を確認します。

 | 測定 | 複雑さ | 説明 |

| スペース | O(n) | 出力文字列には、n | の単位ごとに 1 文字が格納されます。 

すべてのテスト ケースにわたる合計作業量は、すべての n 値の合計で線形であり、テスト ケースごとの n が最大 100,000 であり、ケースが最大 10 個あるため、制限内に問題なく収まります。 

## テストケース```python
import sys, io

def solve_io():
    input = sys.stdin.readline
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        bar = "#" * m + "-" * (n - m)
        percent = (m * 100) // n
        sys.stdout.write(f"[{bar}] {percent}%\n")

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout
    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()
    try:
        solve_io()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

# provided sample-style cases
assert run("1\n10 2\n") == "[##--------] 20%\n"
assert run("1\n5 0\n") == "[-----] 0%\n"

# minimum size
assert run("1\n1 0\n") == "[-] 0%\n"
assert run("1\n1 1\n") == "[#] 100%\n"

# full progress
assert run("1\n6 6\n") == "[######] 100%\n"

# mixed case
assert run("2\n3 1\n4 3\n") == "[#--] 33%\n[###-] 75%\n"

 ## 特殊なケース

 m が 0 に等しい場合、この構築では空のハッシュ セグメントと完全なハイフン セグメントが生成されます。 たとえば、入力 n が 5、m が 0 の場合、式は次のようになります。`"#" * 0 + "-" * 5`収量`"-----"`、およびパーセンテージ`(0 * 100) // 5`ゼロに評価されます。 ゼロを含む文字列の繰り返しでは空の文字列が生成されるため、アルゴリズムは特別な分岐を行わずにこれを自然に処理します。 

m が n と等しい場合、ハイフン セグメントは空になります。 n が 4、m が 4 の場合、バーは次のようになります。`"####"`これが機能するのは、n から m を引くとゼロが得られ、文字列を 0 回正しく繰り返しても出力に何も寄与しないためです。 

n が 1 の場合、バーは 1 つの文字に縮退します。 m がゼロの場合、次のようになります。`"-"`、m が 1 の場合、次のようになります。`"#"`。 整数の除算でも 0 または 100 が生成され、浮動小数点演算を必要とせずに予想される動作と一致します。
