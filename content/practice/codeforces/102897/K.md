 ## 解決策
 ## 問題の理解

 いくつかの独立した配列が与えられています。 各配列には整数が含まれており、すべての配列の要素の合計数は最大 10 万です。 これらの配列を読み取った後、一連のクエリを処理します。 各クエリは、インデックスによって配列のサブセットを選択し、概念的には、選択されたすべての配列を 1 つの大きなマルチセットにマージし、マージされたコレクション内の k 番目に小さい値を求めます。 

重要な点は、各クエリが独立しているということです。 配列は変更されず、以前のマージは保持されません。 すべてのクエリは新しい「仮想マージ」です。 

制約は特定の点で厳しいです。 配列とクエリの数は両方とも 10 万に達する可能性がありますが、すべての配列の要素の総数はわずか 10 万です。 同様に、すべてのクエリで使用されるインデックスの合計数も 10 万です。 これは、最悪の場合、大きなサブセットを繰り返しスキャンすることになるため、マージされたサイズにわたって線形時間でクエリごとの要素を処理するソリューションは全体として遅すぎることを強く示唆しています。 

マージされた配列をクエリごとに並べ替える単純なアプローチでは、選択した配列のサイズを合計する必要があり、最悪の場合、入力分布全体にわたって二次関数になります。 クエリごとにヒープ マージを使用しても、クエリがデータの大部分に繰り返しアクセスする場合は、依然として遅すぎます。 

多くのクエリでほぼすべての配列が選択される場合、微妙なエッジ ケースが発生します。 たとえば、すべての配列が大きく、すべてのクエリにすべてのインデックスが含まれている場合、クエリごとにすべての要素を繰り返しマージまたはコピーすると、個別には正しいにもかかわらず、すぐにタイムアウトになります。 

もう 1 つの特殊なケースは、配列が非常に不均等である場合です。 1 つの配列にはほぼすべての要素が含まれている一方で、他の配列には小さな要素が含まれている場合があります。 配列ごとに単純な k 番目の選択を行うと、大きな配列を何度もスキャンすることになりやすくなります。 

## アプローチ

 ブルート フォース ソリューションでは、各クエリが個別に処理されます。 クエリの場合、選択した配列からすべての要素を一時リストに収集し、並べ替えて、k 番目に小さい要素を返します。 これは正しいです。ソートによってマージされたマルチセットのグローバルな順序が明示的に構築されるからです。 ただし、クエリで合計サイズが M の S 個の配列を選択すると、コストは O(M log M) になります。 すべてのクエリにわたって、M の合計はバランスの取れた分布で 10 万に達する可能性がありますが、最悪の場合、クエリが重なり合い、同じ要素を繰り返し処理するため、全体の複雑さが O(nq log n) に達し、大きすぎます。 

ブルートフォースを少し改善した方法は、選択した配列間でヒープ マージを使用することです。 各配列の最初の要素を最小ヒープにプッシュし、その配列内で前進しながら最小値を繰り返し抽出します。 これにより、O(k log m) の k 番目の要素が計算されます。 これにより完全なソートが回避されますが、k 自体は選択された配列の合計サイズまで大きくなる可能性があります。 したがって、最悪の場合でも、クエリごとにほとんどの要素をスキャンすることになります。 

重要な構造上の観察は、完全な順序付けを出力するように求められるのではなく、事前に保存されたソートされたリストの和集合に対する k 次の統計に答えることだけを求められるということです。 これは当然、値ドメインで二分探索を使用することを示唆しています。 任意の値 x について、選択した配列内で ≤ x である要素の数をすぐに数えることができれば、k 番目に小さい要素が x の左側にあるか右側にあるかを判断できます。 値は最大 10^9 であるため、値を直接列挙しませんが、ソートされた候補をバイナリ検索したり、グローバル値圧縮を使用したりできます。 

各配列は事前に並べ替えることができます。 次に、クエリの場合、選択した配列内で ≤ x である要素の数をカウントすることが二分探索 (upper_bound) になります。 選択した配列を合計すると、合計数が得られます。 これにより、問題が x に関する単調述語に変換され、各クエリの二分探索が可能になります。

配列へのクエリ参照の合計は最大 10^5 であるため、すべてのクエリの合計作業量は管理可能になります。各クエリは、明示的にリストされている配列のみを処理します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (クエリごとのマージ + ソート) | クエリごとに O(Σ Mi log Σ Mi)、最悪合計 O(1e10) | お(お) | 遅すぎる |
 | 最適 (配列の並べ替え + クエリごとの二分検索) | O((Σ mi) log mi + Σ li log mi + Q log V) | O(Σミ) | 承認済み |

 ## アルゴリズムのチュートリアル

 この問題は、各クエリをソートされた配列に対するカウント決定問題に変換することで解決します。 

1. すべての配列を個別にソートします。 これにより、各配列が対数時間で「要素数 ≤ x」を答えることができるようになります。 このステップでは、バイナリ検索クエリ用にすべての配列を準備します。 
2. クエリごとに、関係する配列インデックスのリストを読み取ります。 候補値を繰り返しテストして、k 番目に小さい値を見つけます。 
3. 関数を定義する`count(x)`これは、選択したすべての配列の、その配列内の要素数 ≤ x の合計です。 各配列に対して、次を使用します。`bisect_right`ソートされたリストにあります。 この関数は、値 x までにマージされた配列に表示される要素の数を示します。 
4. 値の範囲 (通常は入力の最小値から最大値まで) に対してバイナリ検索を実行します。 中点 x については、次のように計算します。`count(x)`。 
5. もし`count(x) ≥ k`、これは、k 番目に小さいものが x または x の左側にあることを意味するため、検索空間を左半分に縮小します。 それ以外の場合は、右に進みます。 
6. 二分探索が単一の値に収束し、それがクエリの答えになるまで続行します。 

これが機能する理由は、`count(x)`x では単調です。 x が増加すると、より多くの要素が対象となるため、カウントが減少することはありません。 この単調な構造により、バイナリ検索は常に累積カウントが k と交差する正しいしきい値に向かって進むことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from bisect import bisect_right

def solve():
    n = int(input())
    arr = []
    
    for _ in range(n):
        tmp = list(map(int, input().split()))
        m = tmp[0]
        a = tmp[1:]
        a.sort()
        arr.append(a)
    
    q = int(input())
    
    for _ in range(q):
        tmp = list(map(int, input().split()))
        l = tmp[0]
        idx = tmp[1:1+l]
        k = tmp[1+l]
        
        # value range (safe bounds)
        lo = 1
        hi = 10**9
        
        def count(x):
            res = 0
            for i in idx:
                res += bisect_right(arr[i-1], x)
            return res
        
        while lo < hi:
            mid = (lo + hi) // 2
            if count(mid) >= k:
                hi = mid
            else:
                lo = mid + 1
        
        print(lo)

if __name__ == "__main__":
    solve()
```実装は、プレフィックスのカウントが効率的に行われるように、各配列をソートすることから始まります。 各クエリはローカル インデックス リストを構築し、ヘルパー関数を定義します。`count(x)`二分探索を使用して、選択されたすべての配列からの寄与を蓄積します。 次に、外側の二分探索により、少なくとも k 個の要素がその値以下となる最小値が見つかります。 

微妙な点は境界の選択です`[1, 10^9]`。 すべての配列値はこの範囲内に制限されるため、すべての答えが安全に囲まれます。 もう 1 つの微妙な点はインデックス付けです。Python では配列は 0 から始まりますが、クエリのインデックスは 1 から始まるため、アクセスするときに 1 を減算します。 

## 実用的な例

 3 つの配列を使用した単純化された例を考えてみましょう。 

配列 1 = [1, 5]、配列 2 = [2, 4]、配列 3 = [3, 6]

 クエリは配列 [1, 3]、k = 3 を選択します。 

値を二分探索します。 

| ステップ | ミッド | 配列 1 および 3 に対する count(mid) | 決定 |
 | --- | --- | --- | --- |
 | 1 | 3 | 3 (1,3) | count ≥ k、左に移動 |
 | 2 | 1 | 1 (1) | count < k、右に移動 |
 | 3 | 2 | 1 | 右に移動 |
 | 4 | 3 | 3 | 収束する |

 最終的な答えは 3 で、実際には 3 番目の要素が 5 であるマージされた並べ替えリスト [1,3,5,6] と一致します。 これは、慎重にカウントすることが重要である理由を示しています。mid=3 では、要素 ≤3 は {1,3}、カウントは 2 であるため、しきい値は正しく移動して 5 に収束します。 

2 番目の例:

 配列 1 = [10]、配列 2 = [20、30]、配列 3 = [15]

 クエリはすべての配列、k = 2 を選択します。 

ソートされたマージは [10,15,20,30]、答えは 15 です。二分探索では、count(x) が 2 に達し、15 で安定するまでしきい値が増加します。 

これらの例は、要素を直接追跡しているのではなく、累積カウントのみを追跡していることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((Σ mi) log mi + Q · L · log V) | すべての配列をソートし、各クエリについて値の範囲をバイナリ検索し、各ステップで L 個の選択された配列を合計します。 
| スペース | O(Σミ) | すべての配列をソートされた形式で保存 |

 Σ mi と Σ li はどちらも 10^5 で制限されているため、解は制限内に問題なく収まります。これは、総計数演算が対数因数まで線形のままであることを意味します。

 ## 特殊なケース

 エッジ ケースの 1 つは、選択されたすべての配列に同じ値が含まれている場合です。 たとえば、3 つの配列にはそれぞれ [7] のみが含まれています。 k = 2 の場合、正しい解は 7 を返す必要があります。バイナリ検索では、すべての中間値 ≥ 7 から要素の総数に等しいカウントが得られるため、検索は曖昧さなくただちに 7 に集約されます。 

もう 1 つのケースは、k が 1 に等しい場合です。配列が [10]、[20]、[30] であると仮定します。 正解は 10 です。二分探索では、10 未満の中間値がカウント 0 を生成することがすぐにわかり、10 に達するまで上にシフトし、カウントが 1 になり、答えがロックされます。 

最後の微妙なケースは、クエリが 1 つの配列のみを選択する場合です。 このアルゴリズムは、ソートされたリストの標準的な k 番目の要素に縮小します。 最初に配列をソートするので、`count(x)`は単純な接頭辞チェックとなり、二分探索は他の構造からの干渉なしに k 番目の要素に正確に収束します。
