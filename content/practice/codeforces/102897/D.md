 ## 解決策
 ## 問題の理解

 まずはコレクションから始めます$n$すべて同じ長さの文字列$m$、小文字のみ。 許可された操作では、いくつかの異なる方法で 2 つの文字列をマージするか、1 つの文字列を完全に破棄することで、繰り返し文字列の数を減らすことができます。 マージは、ある文字列を別の文字列の前後に連結するか、2 つの同じ長さの文字列を 1 文字ずつインターリーブして新しい長さの文字列を形成することによって行うことができます。$2m$。 

これらの一連の操作を実行すると、最終的に 1 つの文字列が得られます。 この最後の文字列から、それをいくつかの連続した部分文字列に分割することができます。各部分文字列は回文でなければなりません。 目的は、この最終パーティション内の回文部分の数ができるだけ多くなるように操作と分割を選択することです。 

重要な点は、パーティションを明示的に構築するように求められるのではなく、最適なマージ後に達成可能な回文セグメントの最大数を決定するだけであるということです。 

制約が意味するのは、$n$と同じ大きさにすることができます$10^5$、および合計入力サイズ$n \cdot m$せいぜい$10^6$。 これは、文字列のペアごとの比較やすべての連結に対する動的プログラミングを含む解決策は遅すぎることを直ちに示唆しています。 現実的に可能なのは、入力の線形または線形に近い読み取りだけです。 

チェックする価値のある微妙な問題は、マージ操作の構造によって最終的に使用できる文字列が制限されているかどうかです。 特に、インターリーブは 2 つの文字列から文字を交互に配置するため、制約が課されているように見える場合があります。 不注意な解釈は、最終的な文字列が任意ではないことを示唆する可能性があり、文字列構築の組み合わせ論について過度に複雑な推論につながる可能性があります。 

たとえば、インターリーブによってパリティ パターンが強制され、形成できる回文の数が制限されると考える人もいるかもしれませんが、インターリーブはオプションであり、最適化には必須ではないため、これは誤解を招きます。 

もう 1 つの潜在的な落とし穴は、最終的な文字列構造が回文分割にとって複雑な方法で重要であると仮定することです。 すべての文字はそれ自体が回文であるため、高度に構造化されていない文字列であっても常に最大数の回文部分に分割できます。 

## アプローチ

 まず、総当たり的な考え方について考えます。 マージと破棄の考えられるすべてのシーケンスをシミュレートして、到達可能なすべての最終文字列を生成し、それぞれについて最大回文分割を計算することを試みる場合があります。 マージごとに文字列の数が 1 つずつ減るため、これは直ちに実行不可能ですが、可能なマージ シーケンスの数は指数関数的に増加します。$n$。 文字列の構築を考える前に、分岐要素だけでも次のように成長します。$O(n!)$最悪の場合。 

操作の順序を無視して最後の文字列のみに注目したとしても、どの文字列が到達可能であるかという問題に直面します。 インターリーブ操作は、可能な構造の組み合わせが爆発的に増加することを示唆していますが、これは危険です。 実際にはそれらを列挙する必要はありません。 

重要な観察は、連結操作により、破棄しないことを選択したすべての文字列の長さの単純な合計の長さになる最終的な文字列を構築できるということです。 破棄が許可されているため、原理的には文字列の任意のサブセットを選択できます。 ただし、文字列を破棄してもメリットはありません。目的は回文セグメントの数を最大化することであり、全長を増やすことだけが効果があるからです。 

最終的な文字列の長さを修正したら$L$、分割できる回文部分文字列の最大数は次のとおりです。$L$それ自体を単一の文字に分割します。 すべての単一文字は自明の回文であるため、最適化を達成するために大きなブロック構造は必要ありません。 

これにより、内部操作への依存がすべて削除されます。 重要な唯一の数量は、すべての文字列で使用できる文字の合計数です。 

したがって、問題はすべての長さの合計に帰着します。$n \cdot m$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 運営と建設に対するブルートフォース | 指数 | 高 | 遅すぎる |
 | 全長の最適な短縮 |$O(n)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む$n$そして$n$ただし、長さを測定する以上にその構造を処理しようとしないでください。 内部の文字の配置が最終的な答えに影響することはありません。 
2. 各文字列について、その長さを累計に加算します。 すべての文字列には長さがあるので、$m$、これは計算に相当します。$n \cdot m$しかし、直接合計すると均一性を仮定することが回避されます。 
3. 全長を答えとして出力します。 

ここで停止する理由は、最終文字列内のすべての文字は独自の部分文字列として分離でき、そのような各部分文字列は回文であるということです。 各文字は正確に 1 つのセグメントに属している必要があるため、代替パーティションは文字数を超えることはできません。 

### なぜ効果があるのか

 この操作では、文字列がどのようにマージされるかのみが変更され、文字が保持されるという事実は変更されません。 明示的な破棄を除き、文字を削除する操作はありません。破棄すると、使用可能な合計長が減少するだけです。 したがって、最適な戦略は、何も破棄せず、最終的な文字列の合計文字数を最大化することです。 

最終的な文字列が固定されると、単一文字の部分文字列に分割することによって、可能な限り最良の回文分割が実現されます。 これにより、答えがすべての文字列を選択した後に使用できる文字の合計数になることがわかります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    total = 0
    for _ in range(n):
        s = input().strip()
        total += len(s)
    print(total)

if __name__ == "__main__":
    solve()
```実装では単に長さを蓄積するだけです。 文字列には小文字のみが含まれ、空白は含まれないため、入力行を削除するだけで十分です。 空行が誤読されないことを保証する以上の境界条件はありません。 

重要な実装の詳細は、マージ操作をシミュレートする試みを避けることです。 そのような試みは、結果を変えることなく不必要な複雑さをもたらすことになります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

        solve()
    return out.getvalue().strip()

 ## 特殊なケース

 潜在的な懸念は、文字ごとにより多くの回文セグメントを生成する別の構造を有効にして、破棄することで答えが改善されるかどうかです。 ただし、任意の長さの文字列に対する回文セグメントの最大数は制限されているため、これは起こり得ません。$L$まさに$L$、単一文字のパーティショニングによって実現されます。 

たとえば、次の入力を使用します。```
2
ab
cd
```1 つの文字列を破棄すると、全体の長さが減り、したがって回文セグメントの最大可能数が減ります。 両方を維持すると長さは 4 になり、最適な分割は 4 つの単一文字の回文になります。 

もう 1 つの懸念は、インターリーブによって回文セグメントの数が長さを超えて増加する構造が作成される可能性があるかどうかです。 その場合、セグメントに文字が含まれないか、パーティションが重複している必要がありますが、これは許可されていません。 すべてのパーティションは少なくとも 1 文字を使用するため、上限は厳密に合計の長さになります。 

したがって、インターリーブを使用したとしても、単にすべての文字を保存し、各文字をそれ自体の回文として扱う以上の目的を改善することはできません。
