 ## 解決策
 ## 問題の理解

 コインの種類のコレクションが与えられています。 各タイプには金額が固定されており、供給には限りがあります。 これらのコインから、コインの任意の組み合わせを使用して形成できる個別の合計がいくつあるかを知りたいのですが、1 から m までの合計のみを考慮します。 

各コイン タイプは、制限されたリソースのように動作します。i 番目のタイプでは、その値 ai を最大 2 回使用できます。 すべての種類のコインのサブセットが合計合計に寄与しており、1 から m の範囲のどの合計が少なくとも 1 回達成可能であるかに興味があります。 

出力は、区間 [1, m] 内の整数が有効な合計として表現できる数のカウントです。 

制約はソリューションを大きく左右します。 コインの種類は最大 100 種類あり、ターゲット範囲 m は最大 100000 です。カウント bi と値 ai も最大 100000 と大きくなる可能性があります。組み合わせの数は n と bi で指数関数的に増加するため、コインのすべての組み合わせを列挙する単純なアプローチは不可能です。 

さらに微妙な問題は、各コインを無制限として個別に扱うのは正しくないということです。 たとえば、価値 5 のコインが 1 回しか出現しない場合、単純な無制限のナップサック遷移ではそれが可能であっても、それを 2 回使用することはできません。 

不注意な解決策を打ち破る単純なエッジケースは、すべてのコインが同一であるものの、制限がある場合です。 

入力:

 n = 1、m = 10

 a = [2]、b = [3]

 2、4、6 を形成できるため、正しい出力は 3 です。単純な無制限のナップザックには、誤って 8 と 10 が含まれてしまいます。 

値がゼロの場合、別の失敗ケースが発生します。 値が 0 で正の量のコインは合計に影響を与えませんが、慎重に扱わないと単純な遷移が壊れる可能性があります。 

## アプローチ

 ブルートフォース解釈では、各コインの種類を考慮し、0 から 2 までのすべての可能な使用回数を試し、すべての可能性を再帰的に組み合わせます。 これにより、各レベルがコイン タイプに対応し、各ブランチがそのタイプのコインをいくつ取得するかを選択する検索ツリーが効果的に探索されます。 

各コイン タイプの分岐係数は bi + 1 であるため、状態の総数はすべての i にわたる (bi + 1) の積になります。 10 のような中程度の bi であっても、これは天文学的に大きくなります。 各状態では合計を計算し、到達可能な値をマークする必要があるため、このアプローチは完全に実行不可能になります。 

重要な観察は、これが古典的な境界のあるナップザックの到達可能性の問題であるということです。 それぞれのコインを何枚受け取るかを列挙するのではなく、合計が達成可能かどうかだけを気にします。 これにより、バインドされた各項目を効率的に処理できる構造に変換できます。 

直接 0/1 のナップザックでは、各コインを bi の個別のアイテムに分割しますが、bi は最大 100000 になる可能性があるため、この拡張も不可能です。 重要な最適化は、カウントのバイナリ分解です。 任意の整数 bi は 2 のべき乗の和として書くことができます。 コインの種類ごとに、それを O(log bi) 項目に分割し、それぞれが合計値が (2^k * ai) であるコインのグループを表します。 これにより、問題は最大 100 * log(100000) 項目、つまり約 1700 項目にわたる 0/1 のナップザックに変換されます。 

この変換の後、dp[x] が合計 x に到達可能かどうかを示す標準のブール ナップザックを実行します。 グループ化された各項目は、逆トランジションを使用して 1 回適用されます。 

これにより、bi までの使用カウントはバイナリ分解を使用して一意に表現できるため、問題が管理可能なサイズに縮小され、正確さが保たれます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース列挙 | O(∏(bi+1)) | O(n) | 遅すぎる |
 | バイナリ分解されたナップザック | O(m log bi sum) | O(m) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 数量 bi をバイナリ分割して、各コイン タイプを複数のアイテムに変換します。 分割された各項目の値は、ai に選択したブロック サイズを乗算したものと同じになります。 これにより、bi までの使用カウントをこれらのブロックの合計として重複なく表現できることが保証されます。 
2. サイズ m + 1 のブール配列 dp を初期化します。ここで、dp[0] は true、その他はすべて false です。 これは、現在達成可能な合計を表します。 
3. 分割された項目ごとに、m から項目値まで逆方向に繰り返します。 各位置 j について、dp[j - value] が true の場合、dp[j] を true に設定します。 これにより、同じ項目を複数回再利用することがなくなり、各分割ブロックの 0/1 の性質が維持されます。 
4. すべての項目を処理した後、1 から m までの dp[i] が true に等しいインデックスがいくつあるかを数えます。 

正確さは、バイナリ分解により、bi までのすべての整数使用カウントを選択されたブロックの合計として一意に表現できるという事実に依存します。 各ブロックは独立して処理され、逆 DP により各ブロックが最大 1 回使用されることが保証されます。 

全体を通して維持される不変条件は、各分割項目を処理した後、処理されたブロックのみを使用して達成可能なすべての合計を dp が正しく表すことです。 すべての有効な制限付き選択はバイナリ ブロックの 1 つの選択に正確に対応し、すべてのブロック選択は有効な制限付き選択に対応するため、DP は到達可能な合計を正確にカバーします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    items = []

    for i in range(n):
        val = a[i]
        cnt = b[i]
        k = 1
        while cnt > 0:
            take = min(k, cnt)
            items.append(val * take)
            cnt -= take
            k <<= 1

    dp = [False] * (m + 1)
    dp[0] = True

    for w in items:
        if w > m:
            continue
        for j in range(m, w - 1, -1):
            if dp[j - w]:
                dp[j] = True

    ans = sum(dp[1:])
    print(ans)

if __name__ == "__main__":
    solve()
```コードはまず、各コインの種類のバイナリ分割を実行します。 変数`items`分解された重みを保存します。 分割ループの各反復で cnt の一部が 2 のべき乗で消費され、対数的拡張が保証されます。 

DP 配列は、到達可能な合計を追跡します。 j に対する逆方向ループは重要です。前方反復により同じ項目が複数回再利用され、有界制約に違反することになるからです。 

dp[1:] の最終合計は、m までの到達可能な正の合計をすべてカウントします。 

## 実用的な例

 次の入力を考えてみましょう。 

n = 2、m = 10

 a = [1, 3]

 b = [2, 1]

 バイナリ分割では、1 (最初のコインから)、2 (残りの最初のコインから)、3 (2 番目のコイン) の項目が生成されます。 

| ステップ | 加工品 | dp 到達可能な合計 (サブセット ビュー) |
 | --- | --- | --- |
 | 開始 | なし | {0} |
 | 1 | 1 | {0,1} |
 | 2 | 2 | {0,1,2,3} |
 | 3 | 3 | {0,1,2,3,4,5,6} |

 処理後、到達可能な合計は 10 まですべて {1,2,3,4,5,6} の値になります。 最終的な答えは6です。 

このトレースは、組み合わせが増分的に構築されていること、およびバイナリ分割が複数の使用回数を明示的に列挙することなく正しくシミュレートしていることを示しています。 

次に、単一のコイン タイプを考えてみましょう。 

n = 1、m = 10

 a = [2]

 b = [3]

 項目は2、4になります。 

| ステップ | 加工品 | dp 到達可能な合計 |
 | --- | --- | --- |
 | 開始 | なし | {0} |
 | 2 | 2 | {0,2} |
 | 4 | 4 | {0,2,4,6} |

 分解では正確に 3 回の使用のみが許可され、無限の再利用は許可されないため、8 や 10 に到達することはありません。 これにより、境界のある処理が正しいことが確認されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(m log b + 項目合計 × m) | 各コインは O(log b_i) 個のアイテムに分割され、それぞれが m | 上の 0/1 ナップザック パスで処理されます。 
| スペース | O(m) | dp 配列は、m | までのすべての合計の到達可能性を格納します。

 ## 特殊なケース

 エッジケースの 1 つは、コインの価値がゼロの場合です。 入力の場合:

 n = 2、m = 5

 a = [0, 1]

 b = [10, 1]

 価値ゼロのコインは、重み 0 の分割アイテムを生成します。DP の間、これらのアイテムは無視されるか、変化を引き起こしません。これは、dp[j - 0] が dp[j] に等しいためです。つまり、新しい状態が導入されることはありません。 唯一の貢献アイテムは価値 1 のコインであり、到達可能な合計 {1} が得られます。 このアルゴリズムは、到達可能なカウントの増大を適切に回避します。 

もう 1 つのエッジ ケースは、すべてのコインが m を超える場合です。 たとえば:

 n = 2、m = 5

 a = [10, 20]

 b = [5, 5]

 すべての分割項目は m より大きいため、スキップされます。 dp は {0} のままなので、答えは 0 です。これにより、フィルタリング ステップが確認されます。`if w > m: continue`効率と正確さのために不可欠です。 

3 番目のケースは、多重度が高く、コインの種類が 1 つだけ存在する場合です。 バイナリ分割により、b が 100000 の場合でも、約 17 項目のみが処理されることが保証されます。 DP は、指数関数的な爆発を起こすことなく、標準的な境界のあるナップザックのように動作し、実現可能性を維持します。
