 ## 解決策
 ## 問題の理解

 ルート付きツリー構造は、エッジによってではなく、各ノードの深さのリストによって間接的に与えられます。 ノード 1 はルートとして固定されており、すべてのノード i には、それ自体を含むパス上のノードの数でルートからどれだけ離れているかを示す整数 ai が付属します。 したがって、ルートの深さは 1、その子は深さ 2 というようになります。 

ただし、実際の親子関係は示されていません。 深さ d のノードは複数の方法で深さ d − 1 のノードに接続できるため、多くの異なるルート付きツリーが同じ深さの割り当てに一致する可能性があります。タスクは、指定された深さの配列と一致する別個のルート付きツリーの数をカウントすることです。 

少なくとも 1 つのノードに異なる数の子がある場合、2 つのツリーは異なるものとみなされます。 したがって、構造だけで区別するのではなく、ノードごとの正確な子の数によって区別します。これはやはり、個別の有効な親の割り当てをカウントすることになります。 

n ≤ 100000 という制約により、すべての解が線形または線形に近い時間に向かうようになります。 すべての親の選択を明示的にチェックすることや、ツリー構造を列挙することを伴うものはすべて、組み合わせ論的に爆発します。 O(n log n) であっても問題ありませんが、ノードに対する O(n^2) の構築や、すべての代入に対する単純な DP は不可能です。 

重要なエッジケースは、深さの制約が一貫していない場合に発生します。 たとえば、深さ 3 にノードがあり、深さ 2 にノードが存在しない場合、ツリーは形成されないため、答えは 0 でなければなりません。もう 1 つの微妙なケースは、複数のノードが深さ 2 を共有しているが、深さ 1 に考えられる親が 1 つしかなく、スター状の構造を強いられる場合です。 単純なアプローチでは、各ノードが以前の深さレベルで 1 つの親を正確に選択する必要があることを考慮せずに、選択肢を誤って乗算する可能性があります。 

無効なケースの例:

 入力:

 n = 3

 a = [1, 3, 2]

 ここで、順序付けがノード インデックスによって厳密である場合、深さ 3 のノードには深さ 2 の可能な親がありません。 正解は0です。 

## アプローチ

 強引な解釈は、各ノード (ルートを除く) を前の深さレベルのノード間の親に割り当てることによってツリーを構築することを考えることです。 深さ d に kd ノードがあり、深さ d − 1 に kd−1 ノードがある場合、深さ d の各ノードは kd−1 個の親のいずれかを選択でき、そのレベルの (kd−1)^{kd} の可能性が生じます。 レベル間で乗算すると候補数が得られます。 

これはすでに解決策の構造を示唆していますが、ブルートフォースはすべての割り当てを明示的に構築またはシミュレートするか、再帰的にツリーを構築しようとします。 2 レベル構造のような最悪のケースでは、割り当ての数が n に応じて指数関数的に増加するため、これはすぐに実行不可能になります。 

重要な観察は、深さが有効な親候補を完全に決定するということです。深さ d にあるすべてのノードは、深さ d − 1 にあるノードに接続する必要があり、他の選択は重要ではありません。 ツリーを区別するにはノードごとの子の数のみが重要であるため、正確な割り当てを追跡する必要はなく、レベル d のノードがレベル d − 1 のノード間で自身を分散できる方法が何通りあるかだけを追跡する必要があります。各ノードは独立して親を選択するため、構成の総数はべき乗レベルの積となります。 

もう 1 つ隠れた制約があります。深さ d − 1 のすべてのノードには、分離されていない場合にその上に接続できる、より深いレベルに少なくとも 1 つのノードがなければなりません。ただし、ノードは親を自由に選択するため、これは自動的に処理されます。 私たちは主観性を保証する必要はありません。 

したがって、問題は深さによってノードをグループ化し、レベルごとに寄与を乗算することに帰着します。

 ## アルゴリズムのチュートリアル

 ## アルゴリズムのチュートリアル

1. 深さの値によってノードをグループ化し、各深さに存在するノードの数を数えます。 これにより、各深さ d の周波数マップ kd が得られます。 このステップにより、問題は個々のノードではなくレイヤーでの作業に変換されます。 
2. 深さ 1 にノードが 1 つだけ含まれていることを確認します。 そうでない場合、その構造はノード 1 をルートとするルート付きツリーを表すことができないため、答えはゼロになります。 これにより、固定ルート制約が強制されます。 
3. 深さが 1 から始まり、隙間なく連続していることを確認します。 深さ d > 1 が表示されるが、深さ d − 1 が欠落している場合、どのノードも有効な親に接続できないため、答えはゼロになります。 
4. 有効な親から子の方向でレベルを処理できるように、すべての個別の深さを昇順に並べ替えます。 
5. 答えを 1 として初期化します。各深度遷移からの寄与を乗算します。 
6. 2 から始まる各深さ d について、答えに (k_{d−1})^{k_d} を掛けます。 これは、深さ d の各ノードが深さ d − 1 のすべてのノードの中から 1 つの親を独立して選択し、ノードごとに k_{d−1} 個の選択肢を与えることを反映しています。 
7. すべての乗算を法 998244353 で計算します。これにより、剰余算術の正確さを維持しながら、数値が範囲内に保たれます。 

### なぜ効果があるのか

 各深さのレイヤーでは、構造的に自由なのは、前のレイヤーから各ノードの親を選択することだけです。 ノードが親を選択すると、その親に対して出力エッジが 1 つだけ提供され、この選択はカウントによる場合を除いて他のノードを制約しません。 この問題では子の数によってのみツリーが区別されるため、親を個別に割り当てると、個別の有効なツリーが生成されます。 ノード間の選択は独立しており、レイヤー間でも同様に独立しているため、合計数は深さの遷移に対するべき乗の積にきれいに因数分解されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def mod_pow(a, e):
    return pow(a, e, MOD)

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    from collections import Counter
    cnt = Counter(a)

    # root must be unique
    if cnt[1] != 1:
        print(0)
        return

    depths = sorted(cnt.keys())

    # check continuity of depths
    for i in range(1, len(depths)):
        if depths[i] != depths[i - 1] + 1:
            print(0)
            return

    ans = 1

    for i in range(1, len(depths)):
        prev_d = depths[i - 1]
        cur_d = depths[i]
        ans = (ans * pow(cnt[prev_d], cnt[cur_d], MOD)) % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```コードは、各深度に表示されるノードの数をカウントすることから始まります。 これにより、問題がレベル全体の周波数マップに圧縮されます。 ルート検証では、ルートが固定されているため、正確に 1 つのノードが深さ 1 にあることが保証されます。 

次に深さを分類し、それらが連続したチェーンを形成していることを確認します。 これにより、レベルに有効な親レベルがないという無効なケースが防止されます。 

最後に、深さの遷移を繰り返します。 連続する深さの各ペアについて、より深いレベルのすべてのノードは、前のレベルのすべてのノードの中からその親を選択し、べき乗項に寄与します。 乗算により、すべての独立した選択が累積されます。 

べき乗モジュラーは Python の組み込み pow を使用して処理されます。指数値は n によって制限されるため、n が 100000 までであれば十分効率的です。 

## 実用的な例

 小規模な有効なケースを考えてみましょう。 

入力:

 n = 4

 a = [1、2、2、3]

 深さのカウント:

 | ステップ | 深さ | カウント |
 | --- | --- | --- |
 | 1 | 1 | 1 |
 | 2 | 2 | 2 |
 | 3 | 3 | 1 |

 深さ 2 の両方のノードが単一のルートに接続する必要があるため、深さ 1 から 2 への遷移は 1^2 = 1 に寄与します。 深さ 3 のノードは 2 つの深さ 2 ノードのいずれかを親として選択できるため、深さ 2 から 3 への遷移は 2^1 = 2 に寄与します。 最終的な答えは 2 です。 

次に、より自由度の高いケースを考えてみましょう。 

入力:

 n = 5

 a = [1、2、2、2、3]

 深さのカウント:

 | ステップ | 深さ | カウント |
 | --- | --- | --- |
 | 1 | 1 | 1 |
 | 2 | 3 | 3 |
 | 3 | 1 | 1 |

 ここで:

 遷移 1 → 2 は 1^3 = 1 に寄与します。 

遷移 2 → 3 は 3^1 = 3 に寄与します。 

したがって、答えは 3 です。 

これらのトレースは、各層がどのように独立して寄与するか、およびべき乗が独立した親の選択をどのようにエンコードするかを示します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 周波数のカウントと深さレベルの反復は、ノード数において線形です。 
| スペース | O(n) | 深さの周波数マップのストレージ |

 すべての操作は入力に対してシングルパスであり、最大 O(n) である個別の深さに対してソートのみを行うため、ソリューションは制約内に簡単に適合します。

    MOD = 998244353

    n = int(input())
    a = list(map(int, input().split()))
    cnt = Counter(a)

    if cnt[1] != 1:
        return "0"

    depths = sorted(cnt.keys())

    for i in range(1, len(depths)):

    return str(ans)

 ## 特殊なケース

 特殊なケースの 1 つは、ルートが一意ではない場合です。 入力用`n = 3, a = [1, 1, 2]`の場合、ルート レベルには複数のノードがあるため、アルゴリズムはすぐに 0 を返します。 処理中、cnt[1] = 2 はルート制約に違反するため、それ以上の計算は行われません。 

もう 1 つのエッジ ケースは、次のような切断された深度シーケンスです。`a = [1, 2, 4]`。 深度マップには 1、2、4 が含まれていますが、3 がありません。 ソートされた深さリストは、2 から 4 に移動するときに連続性チェックに失敗し、アルゴリズムはべき乗を試行する前に 0 を正しく出力します。 

3 番目のケースは、次のような完全に有効なチェーンです。`a = [1, 2, 3, 4]`。 ここで、各深度にはノードが 1 つだけあるため、すべての遷移は 1^1 = 1 に寄与し、答えは全体を通して 1 のままであり、深度と一致する線形ツリー構造が 1 つだけ存在するという事実と一致します。
