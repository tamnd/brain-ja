 ## 解決策
 ## 問題の理解

 バイナリ文字列が与えられます`s`そしてその上に固定された間隔の集合。 各間隔で部分文字列が抽出され、抽出されたすべての部分文字列が連結されて新しい文字列が形成されます。`t(s)`。 の構造`t(s)`は間隔によって固定されるため、元の文字列のすべての位置が、最終的な連結の複数の位置に影響します。 

更新ごとに、次の 1 つの位置が`s`から反転されます`0`に`1`またはその逆。 フリップするたびに、文字を再配置することができます。`s`任意の 2 つの位置を何度でも交換できます。 報告するコストは、結果として生じる連結を実現するために必要なスワップの最小数です。`t(s)`のすべての可能な配置の中で辞書編集上最大となる`s`。 

ここでの辞書編集上の最大とは、私たちが望むことを意味します`t(s)`これは、バイナリ文字列では、より前の文字を作成することを意味します。`t(s)`として`1`可能な限り、以来`1`支配する`0`最初の異なる位置で。 

重要な観察は、次の構造を決して変更しないということです。`t(s)`、からの文字の割り当てのみ`s`の位置に`t(s)`間隔によって誘発されます。 の各インデックス`s`のいくつかの位置に表示されます`t(s)`、その多重度がそのインデックスの価値を決定します。 

制約は大きいです:`n, m, q ≤ 2⋅10^5`。 これにより、単純な再計算には少なくともコストがかかるため、クエリごとに寄与分を最初から再計算することが除外されます。`O(nm)`または`O(n)`クエリごとに、両方とも遅すぎます。 ポイントの更新をサポートし、グローバルな重み付けされた要約を維持する構造が必要です。 

間隔が重なり合うと、微妙な問題が発生します。 素朴なアプローチでは、各文字が間隔ごとに 1 回寄与すると仮定するかもしれませんが、寄与は、任意の方法で間隔が重なる頻度ではなく、各インデックスに含まれる部分文字列の数によって決まります。 

## アプローチ

 ブルートフォースアプローチは、すべてのポジションの寄与を再計算することです。`s`各フリップの後。 インデックスごとに`i`、それをカバーする間隔の数を数え、重みを与えます`w[i]`。 それから`t(s)`はマルチセットと同等です。`i`貢献する`w[i]`のコピー`s[i]`。 

作るには`t(s)`辞書編集的に最大なので、すべてが利用可能であることが必要です`1`の中で最も比重の高いポジションに配置される`t(s)`。 スワップはその数を数える以外は自由であるため、実際のタスクは次のようになります。指定された重みと現在のバイナリ値から、現在の配置を重みでソートされた最適な配置に変換するための最小スワップ数を計算します。 

クエリごとのすべての重みのブルート フォース再計算は次のようになります。`O(nm + qn)`、これは大きすぎます。 

重要な洞察は、各インデックスが`i`線形かつ独立して寄与し、最終的な構造は重みのみに依存します`w[i]`。 すべての間隔にわたって各位置が何回出現するかを事前に計算すると、問題はフリップ時に重み付けされたビットのマルチセットを維持することになります。 

次に 2 番目のアイデアです。すべてを再計算する代わりに、その数のカウントを維持します。`1`は各重量クラスに存在します。 常に最適な配置を配置するため、`1`最大の重みに分割するには、ソートされた重みの構造を維持し、その重みの数を追跡するだけで済みます。`1`s は、ソートされた重みの各プレフィックスを占めます。 スワップの数は、現在の分布とターゲットの分布の間の不一致によって決まります。 

インデックスを重みで一度ソートします。 次に、この注文に対してフェンウィック ツリーまたは BIT を維持し、現在含まれているポジションを追跡します。`1`。 フリップするたびに、1 つの位置を更新し、その位置の数を計算します。`1`は一番上にあるはずです`k`このソート順の位置。 それぞれが間違って配置されているため、不一致数はスワップコストに直接変換されます。`1`境界を越えて移動する必要があり、各スワップで 2 つの反転が修正されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(q・n・m) | O(n) | 遅すぎる |
 | ソート+BITメンテナンス | O((n + q) log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. インデックスごとに`i`元の文字列で計算します`w[i]`、部分文字列が含まれる間隔の数`i`。 これは、間隔エンドポイントにわたる差分配列を使用して行われます。 これは、各文字が最終的な連結文字列に寄与する回数を示します。 
2. インデックスの並べ替え`1..n`昇順に`w[i]`。 この順序は、次の位置を表します。`t(s)`最も重要でないものから最も重要なものまで。 最大の重みは、`1`辞書順に最も有利です。 
3. 並べ替えられた順序に基づいてフェンウィック ツリーを構築し、`s[i]`現在は`1`。 この構造は、重み順にソートされた高速プレフィックス合計をサポートします。 
4. クエリごとに、単一ビットを反転します。`s`、対応する位置でフェンウィック ツリーを更新します。 
5. 各更新後に、その数を計算します。`1`s は現在文字列内に存在します。 これをそのままにしておきます`k`。 最適な構成では、`k`の最大ウェイトポジション`t(s)`すべてを含める必要があります`1`s.
 6. フェンウィック ツリーをクエリして、その数を計算します。`1`現在トップに位置しています`k`ソート順の位置。 これをそのままにしておきます`good`。 残り`k - good`あるものは間違っています。 
7. それぞれの場所が間違っている`1`低重み領域から高重み領域に移動する必要があるユニットに対応します。 それぞれのスワップでこのような 2 つの誤配置が修正されるため、スワップの最小数は次のようになります。`(k - good)`。 

### なぜ効果があるのか

 この構造は、問題を重み付けされた位置の複数セットの再配置に変換します。 スワップでは任意の順列が許可されるため、最終的な配置のみが重要になります。 辞書編集的最大化により貪欲な割り当てが強制されます: all`1`は最も重みの高いスロットを占有する必要があります。 フェンウィック ツリーは、現在の構成がターゲットの割り当てからどの程度逸脱しているかを維持します。 各スワップでは、正しい半分と間違った半分の間で 2 つの反転が修正されるため、不一致の数によって完全に答えが決まります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

    def range_sum(self, l, r):
        return self.sum(r) - self.sum(l - 1)

n, m, q = map(int, input().split())
s = list(input().strip())

L = [0] * n
R = [0] * n

diff = [0] * (n + 2)

for _ in range(m):
    l, r = map(int, input().split())
    diff[l] += 1
    diff[r + 1] -= 1

cur = 0
w = [0] * n
for i in range(1, n + 1):
    cur += diff[i]
    w[i - 1] = cur

order = list(range(n))
order.sort(key=lambda i: w[i])

pos = [0] * n
for i, idx in enumerate(order):
    pos[idx] = i + 1

fw = Fenwick(n)

for i in range(n):
    if s[i] == '1':
        fw.add(pos[i], 1)

total_ones = sum(1 for c in s if c == '1')

for _ in range(q):
    x = int(input()) - 1

    if s[x] == '1':
        fw.add(pos[x], -1)
        s[x] = '0'
        total_ones -= 1
    else:
        fw.add(pos[x], 1)
        s[x] = '1'
        total_ones += 1

    k = total_ones
    if k == 0:
        print(0)
        continue

    good = fw.sum(n) - fw.sum(n - k)
    print(k - good)
```この解決策は、各インデックスを、連結された部分文字列内に出現する回数を表す重みに圧縮することから始まります。 これにより、間隔に対する構造的依存性が位置ごとの単一のスカラーに変換されます。 

この重みでインデックスを並べ替えることで、配置の優先順位が定義されます。`1`は。 フェンウィック ツリーは、これらのポジションのどれが現在保持しているかを追跡します。`1`s により、この順序での高速なプレフィックスおよびサフィックス クエリが可能になります。 

各クエリは 1 つの位置を更新し、グローバルな 1 の数を調整します。 重要な計算は、次の数を決定することです。`1`すでにトップに位置しています`k`重み付けされたポジション。 それらは正しく配置されています。 残りは移動する必要があり、スワップ数が直接続きます。

 ## 特殊なケース

 重要なエッジケースは、すべての間隔の重みが等しい場合です。 その状況では、`s`同じ構造上の重要性を生み出す`t(s)`したがって、答えは、文字列が 1 の位置に関してすでにソートされているかどうかによってのみ決まります。 このアルゴリズムは、並べ替えられた順序が任意ではあるが固定されたインデックス付けに退化するため、これを処理します。また、フェンウィックの計算では引き続き不一致が正しく測定されます。 

もう 1 つのケースは、1 の数が 0 以上の場合です。`n`。 フェンウィック ツリーでのプレフィックスとサフィックスの比較では完全な位置合わせが行われるか、必要な配置シフトが発生しないため、アルゴリズムは直ちにゼロ スワップを返します。
