 ## 解決策
 ## 問題の理解

 Nezzar には一連のボールがあり、各ボールには減少しない配列の番号がラベル付けされています。 彼は、同じ色のすべてのボールを分離すると、その数が厳密に増加する必要があるというルールに従って、できるだけ少ない色を使用してボールに色を付けたいと考えています。 厳密に増加するシーケンスでは、後続の各数値が前の数値よりも大きくなる必要があります。 単一のボールまたは孤立した要素の場合、これは自明のことです。 

入力は複数のテスト ケースで構成されます。 各テスト ケースでは、配列と配列自体の長さが示されます。 ボールの数字の範囲は 1 から$n$、配列は非減少です。 出力は、各テスト ケースに必要な最小限の色数である必要があります。 

制約は小さいです。$n$は 100 まで増加し、テスト ケースは最大 100 個になります。 これにより、次のようなアルゴリズムが可能になります。$O(n^2)$時間制限内で快適に実行するための複雑さ。 ただし、繰り返される数字を不注意に扱うと、間違った答えが生じる可能性があります。 たとえば、配列では`[1,1,2,2,3]`、重複を考慮せずに単に左から右に貪欲に色を割り当てようとする単純なアプローチでは、必要以上に多くの色が使用される可能性があります。 正解は 2 です。なぜなら、繰り返される数字の色を変えることができるからです。`[1,2,1,2,1]`。 

エッジ ケースには、すべての数値が同一である配列、単一の要素を持つ配列、および厳密に増加する数値を持つ配列が含まれます。 これらのシナリオは、アルゴリズムが繰り返し要素を正しくカウントするかどうかをテストします。 

## アプローチ

 強引なアプローチは、各ボールへの色の割り当てをすべて試し、結果として得られる各色のシーケンスが厳密に増加しているかどうかを確認することです。 このアプローチは正しいですが、指数関数的に複雑になります。$n$そしてそれはたとえ$n=20$。 

重要な点は、必要な色の最小数は、配列内の単一の数値の最大頻度によって決まるということです。 各色の厳密な増加条件を維持するには、繰り返される各数値を個別の色に入れる必要があります。 たとえば、数字の 2 が 3 回出現する場合、どの色でも 2 が 1 回しか出現しないため、少なくとも 3 つの色が必要になります。 

したがって、最適なアプローチは、各数値の頻度を数えて最大値を取ることです。 これにより、問題は、次の点に比べて線形な時間計算量を伴う単純な計数問題に縮小されます。$n$。 以来$n$が小さい場合、このアプローチは非常に効率的です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(k^n) | O(n) | 遅すぎる |
 | 最適 | テスト ケースあたり O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取ります。 
2. 各テスト ケースについて、次の内容を読んでください。$n$そして数値の配列。 
3. 頻度辞書または配列を初期化して、各数値が何回出現するかをカウントします。 
4. 配列を反復処理し、各数値のカウントをインクリメントします。 
5. すべての数値の中から最大の頻度を見つけます。 
6. この最大周波数を必要な最小色数として出力します。 

これが機能する理由: 任意の数値の最大周波数は、最も厳しいボトルネックを表します。 どの色にも同じ数字を複数含めることはできないため、繰り返される各数字を複数の色に分割する必要があります。 最大周波数よりも小さい場合は、ある数値に対する厳密な増加要件に違反します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import Counter

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    freq = Counter(a)
    print(max(freq.values()))
```コードは、次を使用して入力を効率的に読み取ります。`sys.stdin.readline`。`Counter`各数値の頻度を自動的にカウントします。 使用する`max(freq.values())`最小の色数に対応する最高周波数を直接抽出します。 これにより、手動ループや潜在的な off-by-one エラーが回避されます。

 最大頻度は 3 なので、3 色が必要です。 

**サンプル 2:**

 最大頻度は 2 なので、2 色が必要です。 

これらのトレースは、アルゴリズムが繰り返しの数値に基づいて色の要件を正確に識別していることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | テスト ケースあたり O(n) | カウント頻度は線形であり、最大値は最大 n | 個の一意の数値の数において線形です。 
| スペース | テスト ケースあたり O(n) | カウンタ ディクショナリは、各一意の数値の頻度を最大 n エントリで保存します。 

与えられた$n \le 100$そして$t \le 100$、合計操作は最大で$100*100=10^4$、1秒の制限内に十分収まります。 

## テストケース```python
import sys, io
from collections import Counter

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = []
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        freq = Counter(a)
        output.append(str(max(freq.values())))
    return "\n".join(output)

# provided samples
assert run("5\n6\n1 1 1 2 3 4\n5\n1 1 2 2 3\n4\n2 2 2 2\n3\n1 2 3\n1\n1\n") == "3\n2\n4\n1\n1", "samples"

# custom cases
assert run("2\n3\n1 1 1\n4\n1 2 3 4\n") == "3\n1", "all same / all distinct"
assert run("1\n5\n2 2 2 2 2\n") == "5", "max frequency all same"
assert run("1\n6\n1 1 2 2 3 3\n") == "2", "multiple repeated numbers"
assert run("1\n1\n1\n") == "1", "single element"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`3\n1 1 1\n4\n1 2 3 4`|`3\n1`| すべて同じとすべて異なるものを正しく処理する |
 |`5\n2 2 2 2 2`|`5`| 最大周波数は配列サイズに等しい |
 |`6\n1 1 2 2 3 3`|`2`| 同じ最大頻度を持つ複数の数値 |

 ## 特殊なケース

 のために`[2,2,2,2]`、アルゴリズムは 2 の出現を 4 回カウントします。最大頻度は 4 なので、4 が出力されます。番号 2 の 2 つのボールが同じ色を共有できないため、これは 4 色が必要であることを正しく反映しています。 

のために`[1]`、1 の頻度は 1、最大頻度は 1、出力は 1 です。単一要素配列には常に 1 つの色が必要です。 

のために`[1,2,3,4]`、すべての数値は個別であり、最大周波数は 1、出力は 1 です。これにより、アルゴリズムが不要な色を使用せずに厳密に増加するシーケンスを正しく処理していることが確認されます。 

すべてのエッジケースは、アルゴリズムが堅牢であり、問​​題の要件と正確に一致していることを示しています。
