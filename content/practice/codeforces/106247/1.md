 ## 解決策
 ## 問題の理解

 私たちには、24 時間のデジタル時計で 2 つの瞬間が与えられています。 すべての時計の読み取り値は次のように表示されます。`HH:MM`、時間は 2 桁を使用します。`00`に`23`と分は次の 2 桁を使用します`00`に`59`。 

次の少なくとも 1 つが当てはまる場合、そのタイムは美しいとみなされます。 

時の値は分の値と同じです。 例としては、`00:00`そして`21:21`。 

分の桁は、時の桁のまったく逆になります。 例えば、`21:12`。 

表示される 4 つの数字は、連続して増加する数字のシーケンスを形成します。 例えば、`01:23`、その数字は`0,1,2,3`。 

両方のエンドポイントを含め、指定された開始時間と終了時間の間に表示される美しい測定値の数をカウントする必要があります。 

制約はわずかです。 1 日に含まれるのは、`24 × 60 = 1440`可能な時計の読み取り値。 インターバル内で 1 分ごとに検査し、3 つの美しさの条件すべてを直接テストしたとしても、その作業はごくわずかです。 The intended solution is simple simulation.

 間違いの主な原因は、美しさのルールを正しく解釈することです。 

時間を考慮してください`12:12`。```
12
12
```時間は分に等しいので、これは美しいことです。 ミラーリングされた状態のみをチェックするソリューションでは、それを見逃してしまいます。 

時間を考慮してください`20:02`。```
20
02
```分の桁が時間の桁の逆になっているので、これは美しいです。 値を数値として扱い、先頭のゼロを削除すると、誤って比較されます。`20`と`2`。 

時間を考慮してください`01:23`。```
01
23
```表示される4桁は、`0,1,2,3`、連続して増加する数字です。 このルールは、時間と分の個別の数値ではなく、ディスプレイ上の数字に適用されます。 

最後のエッジケースは、開始時点と終了時点が同一である場合です。 このステートメントでは、その 1 つの読み取り値のみが考慮されると明示的に述べられています。 

## アプローチ

 強引なアイデアは、間隔内で可能なすべてのクロック読み取り値を生成し、それが美しいかどうかをテストすることです。 毎回、表示されている 4 桁を抽出し、3 つの条件を直接評価できます。 

1 日で最大 1,440 回の読み取りが行われるため、総当たりアプローチでも数千回の操作しか実行されません。 組み合わせ論、動的計画法、または高度な観察は必要ありません。 

重要な認識は、検索スペース自体が小さいということです。 時計の問題の多くは、時間が広範囲にわたるため、賢く数えることを必要としますが、ここでは有効な測定値の世界全体が 1 日に収まります。 実際には、分ごとに列挙することがすでに最適です。

 この問題では、総当たり解と最適解は事実上同じです。 

## アルゴリズムのチュートリアル

 1. 開始時刻を 1 分のインデックスに変換します。`start = h1 * 60 + m1`。 
2. 終了時刻を単一の分のインデックスに変換します。`end = h2 * 60 + m2`。 
3. 毎分繰り返します`t`から`start`に`end`、包括的。 
4. 現在の時と分を復元します。`h = t // 60`、`m = t % 60`。 
5. 表示されている 4 桁を抽出します。`h_tens`、`h_ones`、`m_tens`、`m_ones`。 
6. 時間が分であるかどうかを確認します。 

もし`h == m`、読み方は美しいです。 
7. 分の桁が時の桁と逆になっているかどうかを確認します。 

これはつまり：`h_tens == m_ones`そして`h_ones == m_tens`。 
8. 4 つの数字が連続して増加する数字を形成しているかどうかを確認します。`d1 + 1 == d2`、`d2 + 1 == d3`、`d3 + 1 == d4`。 
9. 少なくとも 1 つの条件が当てはまる場合、答えをインクリメントします。 
10. 間隔全体を処理した後、カウントを出力します。 

### なぜ効果があるのか

 このアルゴリズムは、必要な間隔に属するすべてのクロック読み取り値を検査し、定義にある 3 つの美しさの条件を正確に適用します。 読み取り値は、少なくとも 1 つの条件が満たされた場合にのみ、答えに寄与します。 すべての適格な時間が 1 回チェックされ、間隔外の時間は検査されないため、最終的なカウントは正確に美しい測定値の数になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

h1 = int(input())
m1 = int(input())
h2 = int(input())
m2 = int(input())

start = h1 * 60 + m1
end = h2 * 60 + m2

ans = 0

for t in range(start, end + 1):
    h = t // 60
    m = t % 60

    beautiful = False

    if h == m:
        beautiful = True

    ht = h // 10
    ho = h % 10
    mt = m // 10
    mo = m % 10

    if ht == mo and ho == mt:
        beautiful = True

    if ht + 1 == ho and ho + 1 == mt and mt + 1 == mo:
        beautiful = True

    if beautiful:
        ans += 1

print(ans)
```最初の部分では、入力時間を分のインデックスに変換します。 1 分進めるということは単に整数を 1 増やすことを意味するため、これにより反復が簡単になります。 

ループ内では、除算と剰余演算を使用して現在の時と分が再構築されます。 

ミラー状態は、整数の反転トリックではなく数字を使用してチェックする必要があります。 これにより、次のような先行ゼロに関する問題が回避されます。`20:02`。 

連続桁条件の場合は、表示されている 4 桁を直接比較します。 このルールは、時間フィールドと分のフィールドの数値ではなく、時計に表示される順序に関係します。 

ループは両端を含み、ステートメントと正確に一致します。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    h1 = int(input())
    m1 = int(input())
    h2 = int(input())
    m2 = int(input())

    start = h1 * 60 + m1
    end = h2 * 60 + m2

    ans = 0

    for t in range(start, end + 1):
        h = t // 60
        m = t % 60

        ok = False

        if h == m:
            ok = True

        ht, ho = divmod(h, 10)
        mt, mo = divmod(m, 10)

        if ht == mo and ho == mt:
            ok = True

        if ht + 1 == ho and ho + 1 == mt and mt + 1 == mo:
            ok = True

        if ok:
            ans += 1

    print(ans)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    global input
    input = sys.stdin.readline

    out = io.StringIO()
    old = sys.stdout
    sys.stdout = out

    solve()

    sys.stdout = old
    return out.getvalue()

# provided samples

assert run("0\n0\n0\n0\n") == "1\n", "00:00 satisfies multiple conditions"
assert run("1\n23\n1\n23\n") == "1\n", "consecutive digits"
assert run("20\n2\n20\n2\n") == "1\n", "mirror with leading zero"
assert run("5\n5\n5\n5\n") == "1\n", "hours equal minutes"
