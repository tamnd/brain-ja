 ## 解決策
 ## 問題の理解

 この問題は、1 つのパック サイズを選択したいショップについて説明しています`a`。 すべての顧客は、次の期間にある程度の量の缶を購入したいと考えています。`l`そして`r`。 顧客はまず、同じサイズのフルパックをできるだけ多く受け取ります`a`できるだけ。 残りの缶が少なくともパックの半分である場合、顧客は残りの缶を個別に購入する代わりに、追加のフルパックを 1 つ購入します。 

タスクは、パックサイズが存在するかどうかを判断することです`a`間隔内のすべての可能な顧客数が`[l, r]`結局、当初の希望よりもはるかに多くの缶を購入することになります。 

重要な観察は、選択されたパック サイズは、購入可能な間隔がパックの「切り上げ」領域内に収まるようにするだけでよいということです。 の値`l`そして`r`と同じ大きさにすることができます`10^9`, そのため、考えられるすべての梱包サイズを確認することは不可能です。 すべての値をループしても、`r`最悪の場合、多くの操作が必要になる可能性があります。 最大数千のテスト ケースを扱う場合、ソリューションは一定時間またはそれに近い時間で動作する必要があります。 

難しいのは境界を理解することです。 顧客がちょうど次の倍数を望んでいる場合`a`、彼らはすでに正確な量を購入しており、さらに購入することを強制することはできません。 また、残りがパックの半分未満の場合は、お客様は元の缶数を維持します。 不注意な解決策では、間隔の 1 つのエンドポイントのみをチェックし、間隔内の別の値の動作が異なることを見逃す可能性があります。 

たとえば、次のことを考えてみましょう。```
1
1 2
```正しい答えは次のとおりです。```
NO
```試しています`a = 2`顧客が購入しているため、有望に見えます`2`缶がパックを満たします。 しかし、購入するお客様は、`1`缶には残りがあります`1`そして、意図した方法で追加パックをトリガーするには厳密には十分ではないため、追加購入しません。 可能な限り短い間隔には特別な注意が必要です。 

別の例:```
1
3 4
```正しい答えは次のとおりです。```
YES
```選択する`a = 5`動作します。 購入する顧客`3`缶は残っています`3`、そして購入する顧客`4`缶は残っています`4`。 どちらの残りもパックの少なくとも半分であるため、どちらの顧客もパック全体を受け取り、さらに購入します。 

## アプローチ

 直接的なアプローチは、可能な限りすべてのパックサイズを試すことです`a`そして、からのすべての値かどうかをテストします`l`に`r`お客様の判断により大きくなります。 固定の場合`a`、あらゆる購入金額に対して顧客の行動をシミュレーションできます。 これは、問題に必要な正確な条件をチェックするため、正しいです。 

問題はチェックの数です。 間隔の長さは次のように大きくできます。`10^9`、可能なパックサイズも非常に大きくなる可能性があります。 ブルートフォースソリューションには次のものが必要になる可能性があります`10^18`最悪の場合、時間内に実行できる範囲をはるかに超えてチェックが行われます。 

重要な洞察は、条件を書き直すことで得られます。 価値のために`x`パックサイズを選択した後に増加します`a`、値`x`ある長さのブロックの後半になければなりません`a`。 顧客が元の金額を保持しているため、各ブロックの前半は失敗します。 後半は、顧客にもう 1 パックを摂取させるのに十分な量の残りがあるため、成功します。 

固定の場合`a`、成功するすべての範囲は次の形式になります。```
[a / 2, a - 1] relative to each block of size a
```すべての数値を保証する最も簡単な方法は、`l`に`r`成功するにはパックサイズを選択することです`a`これは左側の境界の 2 倍より大きくなります。 もし`a = 2 * l`の場合、最初に成功した領域は正確に次の位置で始まります。`l`、最初のパックの終わりまでのすべての値をカバーできます。 唯一の要件は、右側の境界がパックの最後に到達しないことです。 

これにより、質問は値が存在するかどうかを確認することになります。`a`どこ：```
2 * l <= a
and
r < a
```このような値が存在するのは、まさに次のような場合です。`r < 2 * l`。 この 1 つの比較で、すべてのテスト ケースに十分です。

 ## アルゴリズムのチュートリアル

 1. 間隔を読み取る`[l, r]`考えられるすべての顧客の購入を表します。 
2. 比較する`r`と`2 * l`。 この比較の理由は、パックのサイズが十分な大きさである必要があるためです。`l`収益性の高いパックの半分の始まりですが、正確なパック境界に達する顧客が存在しないように、間隔内のすべての値よりも大きくする必要があります。 
3. もし`r < 2 * l`、印刷`YES`。 それ以外の場合は、印刷します`NO`。 

なぜ機能するのか: いつ`r < 2 * l`、選択する`a = 2 * l`～からあらゆる数字を作る`l`に`r`最初のパックの終わりの前で、残りがパックの少なくとも半分である領域内に落ちます。 すべての顧客は追加のパックを 1 つ購入します。 もし`r >= 2 * l`、役立つのに十分な大きさのパックならどれでも`l`区間内のある値によって到達される境界があり、その値は増加しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []
    for _ in range(t):
        l, r = map(int, input().split())
        if r < 2 * l:
            ans.append("YES")
        else:
            ans.append("NO")
    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```このソリューションでは、印刷用に回答を保存するだけで済みます。 比較には、`2 * l`、Python 整数はこれらの値を安全に処理します。 

この条件は、アルゴリズムからの数学的観測を直接実装します。 シミュレーションや間隔にわたるループはなく、パック サイズ自体を構築する必要もありません。 

境界条件には厳密な不等式が使用されます。 もし`r == 2 * l`、間隔は顧客が失敗する可能性がある正確な点に達するため、答えは次のようになります。`NO`。
