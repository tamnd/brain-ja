 ## 解決策
 ## 問題の理解

 Jellyfish と Gellyfish という 2 人のプレイヤーがおり、それぞれ青リンゴのコレクションを持っています。 クラゲは`n`配列に値が格納されたリンゴ`a`、そしてGellyfishは`m`配列に値が格納されたリンゴ`b`。 彼らはゲームをします`k`ラウンドします。 奇数ラウンドでは、ジェリーフィッシュは自分のリンゴの 1 つをジェリーフィッシュのリンゴと交換するか、何もしない場合があります。 偶数ラウンドでは、Gellyfish も同様に交換される場合があります。 どちらも、リンゴの値の合計が最大になるように最適に再生されます。 結局のところ、目標はクラゲのリンゴの合計を計算することです`k`ラウンドします。 

制約は次のことを教えてくれます`n`そして`m`小規模（最大 50）ですが、`k`サイズは巨大になる可能性があります (最大 10^9)。 これは、すべてのラウンドをシミュレートするのは不可能であることを直ちに示します。 代わりに、_有効なスワップ_を特定するソリューションが必要です。ある時点以降、さらなるラウンドでは合計が変更されなくなるためです。 

エッジケースは、次のような状況から発生します。1 人のプレイヤーがリンゴを 1 つだけ持っている、`k`非常に大きい場合、または最高のリンゴがすでに適切な手に渡っている場合。 たとえば、Jellyfish が`[10]`そしてジェリーフィッシュは`[1]`と`k = 1000`、金額を増やすことができないため、彼女は決してスワップしません。 スワップを盲目的にシミュレートする単純なアプローチ`k`停止条件の計算を誤ると、反復により実行時間が長すぎたり、不正確な結果が生じたりする可能性があります。 

## アプローチ

 ブルートフォース手法は簡単です。ラウンドごとに、現在のプレイヤーにとって最適なスワップを特定し、合計が増加する場合はそれを実行し、すべてのプレイヤーに対してこれを繰り返します。`k`ラウンドします。 ゲームはターン制であり、両方のプレイヤーが貪欲に行動するため、これは正しいです。 ただし、`k`であっても最大 10^9 です`n, m ≤ 50`、シミュレーション`k`ラウンドは無理です。 

重要な観察は、合計が「厳密に改善」されない限り、プレイヤーは決してリンゴを交換しないということです。 つまり、せいぜい考慮するだけで十分です`min(n, m)`プレイヤーごとの交換: Jellyfish は自分の最小のリンゴを Gellyfish の最大のリンゴに置き換えるだけで、Gellyfish はその逆を行います。 最小のクラゲが最大のクラゲよりも大きくなると、それ以上交換することは有益ではありません。 このため、有効なスワップ数は次のように制限されます。`min(n, m, k)`、 ない`k`。 

したがって、最適なアプローチは次のとおりです。 

1. クラゲのリンゴを昇順に、クラゲのリンゴを降順に並べ替えます。 
2. 対応する要素 (最小のクラゲと最大のクラゲ) を交換します。`i = 0`に`min(n, m, k) - 1`。 
3. スワップによって Jellyfish の合計が増加しない場合はすぐに停止します。 

これにより、問題は潜在的に数十億回の操作から、テスト ケースごとに最大 50 回のスワップに軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(k * n * m) | O(n + m) | 遅すぎる |
 | 最適 | O(n log n + m log m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取ります。 テスト ケースごとに、次の内容を読んでください。`n, m, k`そしてリンゴの配列`a`そして`b`。 
2. Jellyfish の配列をソートする`a`昇順で。 これにより、交換の対象となる最小のリンゴを簡単に見つけることができます。 
3. Gellyfish の配列をソートする`b`降順で。 これにより、彼が所有する最大のリンゴが露出し、ジェリーフィッシュがそれを取る候補になります。 
4. コンピューティング`swap_count = min(n, m, k)`。 どちらかのプレイヤーが持っている以上のリンゴを交換することはできません。また、それ以上のリンゴを考慮する必要はありません。`k`ラウンドします。 
5. 反復処理`i = 0`に`swap_count - 1`： 比較する`a[i]`そして`b[i]`。 もし`b[i] > a[i]`、交換します。 そうでない場合は、これ以上交換しても Jellyfish の合計を改善できないため、早めに中断してください。 
6. Jellyfish の最終配列の合計を計算して出力します。`a`。 

効果がある理由: あらゆる段階で、Jellyfish は常に自分の最も価値のないリンゴと Gellyfish の最も価値のあるリンゴを考慮します。 この順序で交換することで、彼女は貪欲に合計額を最大化することが保証されます。 Gellyfish は最適に応答するため、Gellyfish に利益をもたらすスワップはソートされた選択によってすでに暗黙的にブロックされているため、ソートされたスワップ シーケンスは最悪の場合の反作用をすでに考慮しています。 最小のクラゲが最大のクラゲを超えると、それ以上の交換は不可能になり、停止条件が確立されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m, k = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        
        a.sort()
        b.sort(reverse=True)
        
        swap_count = min(n, m, k)
        for i in range(swap_count):
            if a[i] < b[i]:
                a[i], b[i] = b[i], a[i]
            else:
                break
        
        print(sum(a))

if __name__ == "__main__":
    solve()
```コードはまず、次を使用して複数のテスト ケースを効率的に読み取ります。`sys.stdin.readline`。 ソートにより、ラウンドごとにシミュレーションを行わなくても、スワップが最適になることが保証されます。 初期の`break`Jellyfish が合計額をさらに改善できない場合に、不必要なスワップを実行しないようにします。`sum(a)`効率を高めるため、テスト ケースごとに 1 回だけ計算されます。
