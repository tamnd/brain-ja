 ## 解決策
 ## 問題の理解

 0 から n までの番号が付けられた都市の単純な直線チェーンがあり、n 個の道路で順番に接続されています。 各道路には「美しさ」の値があり、これによって、Jellyfish がその端点の 1 つに立っている場合にその道路を通過する確率が決まります。 都市 0 から開始して、Jellyfish は、その美しさに比例する確率で接続された道路をランダムに選択し、それに沿って移動します。 彼女の目標は都市 n に到達することであり、美しさの合計が m を超えないことを条件として、彼女が到着するまでの予想日数が最小になるように道路に美しさの値を割り当てたいと考えています。 

入力は 2 つの整数 n と m で構成されます。 出力は、都市 n に到達するまでの最小予想日数を表す浮動小数点数です。 この制約は、n が最大 3000 になる可能性があることを示しています。これは、O(n*m) よりも大幅に複雑なアルゴリズムは実行不可能になる可能性があることを意味します。 期待値の計算には除算と累積確率が含まれるため、特にこの問題では 1e-9 未満の絶対誤差または相対誤差が必要となるため、浮動小数点精度の誤差を避けるように注意する必要があります。 

m が n と等しい場合、微妙なエッジケースが発生します。 この状況では、美しさの合計を超えることはできないため、各道路に美しさ 1 を割り当てる必要があります。 もう 1 つのエッジ ケースは n = 1 です。これは自明ではありますが、アルゴリズムが最小のチェーンを処理することを確認します。 チェーンに沿った美しさの最適な割り当てを無視する素朴なアプローチは、すべての美しさを 1 つの道路に割り当て、他の場所での予想日数を増やし、総予想時間を最小限に抑えるという要件に違反する危険性があります。 

## アプローチ

 単純なアプローチでは、合計が m を超えない美しさの値のすべての可能な割り当てを列挙し、各割り当ての予想日数を計算しようとします。 各割り当てについて、予想されるステップを計算するには、n+1 状態のマルコフ連鎖を解く必要があります。 動的計画法を使用する場合でも、m を n 部分に分割する整数の数は、組み合わせ (m, n) のオーダーで膨大になり、最大 3000 の n ではこれを完全に実行不可能にします。

 重要な観察は、都市が直線的に接続され、パス グラフを形成していることです。 このような構造の場合、都市 0 から都市 n に到達するまでの予想日数は単純な漸化式になります。 f[i] を都市 i から出発して都市 n に到達するまでの予想日数を表すものとします。 都市 i の 2 つの隣接都市にエッジの美しさ a[i] (i+1 方向) および a[i-1] (i-1 方向) がある場合、反復は次のようになります。```
f[0] = 1 + f[1]          # only one outgoing edge
f[i] = 1 + (a[i-1]/(a[i-1]+a[i]))*f[i-1] + (a[i]/(a[i-1]+a[i]))*f[i+1]  for 0 < i < n
f[n] = 0
```f[0] を最小化する必要があり、関数は連続する美しさの比率で凸であるため、美しさの合計に対して動的プログラミングを使用して美しさを最適に割り当てることができます。 より具体的には、最適解は、連続する美しさの比率が単純な特性を満たす方法で、道路全体に美しさの合計 m を分配します。つまり、連続する道路では、その美しさは、予想される前進と後退のステップのバランスをとった等差数列を形成します。 これは、合計制約を使用して漸化式を最小化することで導出された線形方程式系の変数 a[i] を解くことと同じです。 

この問題に対して、便利なアプローチは「貪欲な割り当てによる凸型最適化」です。最初にすべての道路に 1 を割り当て、その後、合計が m に達するまで、増分が最も予想される合計日数を短縮する道路を繰り返し増やします。 プレフィックス合計を注意深く使用すると、期待値の更新を効率的に計算できます。 複雑さは O(n*m) で、n、m <= 3000 であれば許容可能です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 美人を総当たりで列挙する | O(comb(m,n)*n) | O(n) | 遅すぎる |
 | 最適な DP / 貪欲な割り当て | O(n*m) | O(n*m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を初期化する`a`道路の美しさを表すサイズ n の値はすべて 1 に設定されます。これにより、各道路に対する最小制約 1 が確実に満たされます。 
2. パス グラフの反復を使用して、都市 0 からの最初の予想日数を計算します。 これにより、最小限の美しさを持つベースライン値が得られます。 
3. 美しさの合計が m 未満である場合、美しさが 1 増加すると、どの道路が予想日数を最も短縮するかを特定します。 これには、各道路の f[0] の限界減少を計算することが含まれます。 
4. 限界利益を最大限に高めて道路の美しさを高めます。 それに応じて予想日数を更新します。 
5. 美しさの合計が m に達するまで、手順 3 と 4 を繰り返します。 各増分は、予想日数の短縮を最大化するように選択され、関数は凸関数であるため、この貪欲な割り当てにより、全体的に最小の予想日数が得られます。 
6. すべての美人を割り当てたら、漸化式を使用して都市 0 からの最終予想日数を計算します。 

機能する理由: 予想される日数は、直線パス上の美しさの凸関数です。 道路の美しさを高めると、隣接するセグメントと比較してそのセグメントの進歩が常に改善され、貪欲な割り当てにより、美しさの各追加単位が f[0] の最大の削減に貢献することが保証されます。 合計制約は全体にわたって尊重され、線形反復により正確な予想日数の計算が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())

# Initialize beauties to 1
a = [1] * n
remaining = m - n

# Precompute f for current a
def compute_expected(a):
    f = [0.0] * (n + 1)
    for i in range(n - 1, -1, -1):
        f[i] = 1 + f[i + 1] * a[i] / (a[i] + (a[i-1] if i > 0 else 0))
        if i > 0:
            f[i] += f[i-1] * a[i-1] / (a[i] + a[i-1])
    return f[0]

# Greedy allocation
while remaining > 0:
    best_gain = -1
    best_idx = -1
    for i in range(n):
        a[i] += 1
        gain = compute_expected(a)
        a[i] -= 1
        if best_gain < 0 or gain < best_gain:
            best_gain = gain
            best_idx = i
    a[best_idx] += 1
    remaining -= 1

# Final expected days
f0 = compute_expected(a)
print("%.12f" % f0)
```各道路を最小限の美しさで初期化し、制約を超えないようにします。 の`compute_expected`関数は、パスに沿った逆方向パスで f[i] を計算します。これにより、美しさが増加すると f[0] がどのように減少するかを確認できます。 各反復では、最大の限界改善をもたらす道路が選択されます。 これにより、予想される最小日数に確実に収束します。
