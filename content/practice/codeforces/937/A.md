 ## 解決策
 ## 問題の理解

 参加者のスコアのリストが与えられるので、非常に特殊なルールに従って卒業証書を受け取る参加者のグループを選択できる方法が何通りあるのかを数える必要があります。 

有効なグループは、スコアしきい値を選択することによって決定されます。 何らかのスコアを持つ参加者を含めたら、そのスコア以上のスコアを持つすべての参加者も含める必要があります。 これは、選択されたセットがカットオフ値によって完全に決定されることを意味します。つまり、それ以上のすべてが選択され、それ以下のすべてが除外されます。 さらに、スコア 0 の参加者は有効なグループに含めることができないという制限が 1 つあります。 また、選択したグループを空にすることはできません。 

入力は単にスコアのリストです。 出力は、形成できる個別の有効なグループの数です。 

制約は小さく、参加者は最大 100 人であるため、二次または並べ替えベースのソリューションでも十分に高速です。 これは、最適化のトリックではなく、構造に関する推論に焦点を当てるべきであるという合図です。 

ゼロが存在する場合、微妙なエッジケースが発生します。 ゼロを区切らずにすべての個別のスコアしきい値をカウントする単純なアプローチでは、スコアがゼロの参加者が選択されたサフィックスの一部となる構成が誤って含まれてしまいます。 もう 1 つのエッジ ケースは、ゼロ以外のスコアがすべて等しい場合です。 この場合、並べ替えられた値の分割を機械的に考えれば、しきい値を選択する方法はたくさんありますが、有効な選択は 1 つだけです。 

たとえば、次の入力を考えてみましょう。```
5
0 1 2 2 3
```不用意に解釈すると、しきい値を 0、1、2、3 とカウントし、すべてが有効なグループを生成すると考える可能性があります。 ただし、しきい値 0 にはスコア 0 の参加者が含まれることになり、これは禁止されているため、その選択は除外する必要があります。 

別の例:```
3
0 5 5
```有効なグループは 1 つだけ存在します。スコア 5 を選択すると両方の 5 が含まれ、それ以外を選択するとルールに違反するか、同じセットが生成されます。 

## アプローチ

 ブルートフォースのアイデアは、参加者の可能なすべてのサブセットを試して、ルールを満たしているかどうかを確認することです。 各サブセットについて、2 つの条件を検証します。スコアがゼロの参加者は含まれていないこと、および参加者が含まれている場合は、それ以上のスコアを持つすべての参加者も含まれていることです。 参加者が n 人の場合、サブセットは 2^n あり、各サブセットのチェックには O(n) がかかり、O(n・2^n) が得られますが、これは中程度の n の場合でも実行不可能になります。 

重要な観察は、有効なサブセットの構造が非常に厳格であるということです。 ある程度のスコアが x の参加者を選択すると、少なくとも x のスコアを持つ参加者を全員に含めることになります。 したがって、インデックスのサブセットの観点から考えるのではなく、スコアのしきい値の観点から考える必要があります。 

スコアを並べ替えた後、すべての有効なグループは、カットオフとして個別のスコア値を選択することに対応しますが、それは正のスコアの間でのみ選択されます。 それぞれの個別の正のスコア値は、正確に 1 つの有効なセット、つまりその値以上のスコアを持つすべての参加者を定義します。 しきい値を高いスコアから低いスコアに移動する場合、参加者を追加するだけであり、個別のスコア レベルを超えて新しい構成を作成する方法で以前の参加者を削除することはありません。 

したがって、答えは、明確な正のスコア値がいくつ存在するかを数えることに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n・2^n) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(1) または O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのスコアを配列に読み取ります。 これは、個人のアイデンティティではなく価値の分布を分析する必要があるために必要です。 
2. すべてのゼロ値を削​​除または無視します。 これらの参加者は有効なグループに所属できないため、どのグループが存在するかに影響を与えることはできません。 
3. 残りの肯定的なスコアを並べ替えます。 グループを並べ替えると同じ値が得られるため、個別のスコア レベルを簡単に識別できます。 
4. ソートされたリストをざっと調べて、値が何回変化したかを数えます。 それぞれの個別の値は、新しい可能なしきい値を表します。 
5. この数を有効な卒業証書課題セットの数として出力します。 

重要な考え方は、それぞれの個別のポジティブ スコアが、選択されたセットが意味のある変化をする「カット ポイント」を 1 つだけ定義するということです。 

### なぜ効果があるのか

 並べ替え後、すべての参加者がスコア順に並べられます。 有効な選択はすべて、含まれる最小スコア x の選択に対応する必要があります。 x が固定されると、そのセットはスコア ≥ x を持つすべての要素として一意に決定されます。 したがって、有効なセットの数は、そのような最小値として機能する個別の値 x の数と正確に一致し、これは正確に個別の陽性スコアの数となります。 

同じ値内の 2 つの異なるしきい値が異なるセットを生成することはありません。ゼロは制限に違反するため、しきい値として機能できません。 これにより、有効なセットと個別の陽性スコア間のマッピングが 1 対 1 になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    a = [x for x in a if x > 0]
    a.sort()

    if not a:
        print(0)
        return

    cnt = 1
    for i in range(1, len(a)):
        if a[i] != a[i - 1]:
            cnt += 1

    print(cnt)

if __name__ == "__main__":
    solve()
```実装は、有効な選択においてゼロが明示的に禁止されているため、ゼロをフィルタリングして除外することから始まります。 並べ替えは、単一のパスで個別の値をカウントできるように、等しいスコアをグループ化するために使用されます。 

正のスコアの空でないリストは常に少なくとも 1 つの個別の値に寄与するため、カウンターは 1 から始まります。 次に、異なる値間の遷移が観察された場合にのみカウンターをインクリメントします。 

よくある間違いは、個別の値を数える前にゼロを削除するのを忘れることです。これにより、ゼロが有効なしきい値として扱われて、答えが間違って膨らみます。

 ## 特殊なケース

 重要なエッジ ケースは、少なくとも 1 つの非ゼロを保証する制約を除き、すべての要素がゼロである場合ですが、フィルタリングによってすべてが削除されるケースにも対処する必要があります。 次のような入力の場合:```
3
0 0 5
```フィルタリング後、次の結果が得られます`[5]`。 並べ替えても何も起こりません。 アルゴリズムはカウントを 1 として初期化し、唯一の有効な選択に対応する 1 を返します。つまり、スコア 5 とそれより上のすべて (参加者のみ) を取得します。 

もう 1 つのエッジ ケースは、すべての正の値が同一である場合です。```
4
0 7 7 7
```フィルタリングされたリストは`[7, 7, 7]`。 ループは値の変化を検出しないため、カウントは 1 のままです。これは、しきい値が 1 つだけ存在することを正しく反映しています。 

最後に、厳密にスコアを増やします。```
4
1 2 3 4
```フィルタリングおよびソートされたリストは変更されません。 トランジションごとにカウントが増加し、4 つの異なる有効なセットが生成され、各スコア レベルが異なるカットオフを定義するという考えと一致します。
