 ## 解決策
 ## 問題の理解

 木の枝の垂直構造を表す 2 つの整数が与えられます。 ブランチには、低いレベルから最大の高さまで昇順に番号が付けられます。 下位のブランチのサブセットにはバッタが含まれており、各バッタには決定的なジャンプ パターンがあります。つまり、現在のブランチから、ステートメントに暗示される固定算術規則によって決定される他の特定のブランチに繰り返し着地することができます。 

タスクは、最初の位置から開始して許可されたジャンプを使用して、バッタが決してその上に着地できないように、可能な限り高い枝を選択することです。 すべての枝に少なくとも 1 匹のバッタが到達できる場合、答えは存在しません。 

重要な点は、各バッタが恣意的に探索するのではなく、到達可能な位置の構造化されたセットを生成するということです。 これらすべての到達可能な位置を結合すると、一連の禁止された分岐が形成されます。 この共用体に含まれない範囲の最大の整数が必要です。 

制約は大きく、値は最大 10^9 です。 これにより、すべてのブランチにわたるシミュレーションが即座に除外されます。 すべてのブランチを線形に反復することさえ不可能です。 どのようなアプローチでも、明示的な走査ではなく、数論的な構造に依存する必要があります。 

微妙なエッジ ケースは、等差数列が重なっているためにすべての分岐が到達可能になる場合です。 たとえば、バッタが周期構造内のすべての残基を集合的にカバーする場合、安全な分岐は存在しません。 もう 1 つのエッジ ケースは、最も安全な分岐が到達可能な最大境界のすぐ下にある場合です。そのため、補完を注意深く追跡せずに完全なカバレッジを仮定すると、オフバイ 1 推論は間違いやすくなります。 

## アプローチ

 ブルートフォース解釈では、各バッタをシミュレートし、y までの到達可能なすべてのブランチをマークします。 各バッタは、到達可能な位置の等差数列を生成します。 バッタごとに、繰り返しジャンプして訪問した枝にマークを付けることができました。 これは概念的には正しいですが、すぐに複雑さが失われます。最悪の場合、単一のバッタが O(y) 個の位置を生成する可能性があり、問題構造の最悪の解釈では最大 O(y) 個の開始分岐が考えられます。 これにより、10^9 スケールの範囲では不可能な 2 次の動作が発生します。 

重要な観察は、各バッタの到達可能なセットが周期的であるということです。 このステートメントから、位置 x にある各バッタは、x、2x、3x などにジャンプできます。 これは、開始位置のすべての倍数に正確に到達できることを意味します。 したがって、ブランチが少なくとも 1 つのバッタ位置で割り切れる場合、そのブランチは安全ではありません。 

したがって、問題はきれいな整数論の問題に帰着します。2 から y までの整数のうち、[2, p] 内のどの整数でも割り切れない最大の整数が必要です。 範囲内のすべての数値が少なくとも 1 つのそのような値で割り切れる場合、-1 を返します。 

この構造は、y から下方向にスキャンし、2 から p までのすべての値に対して割り算をチェックすることを示唆しています。 p は最大 y である可能性があるため、候補ごとに直接チェックを単純に行うと、最悪の場合、時間がかかりすぎます。 ただし、検索する必要があるのは上から最初の有効な番号だけなので、見つかったらすぐに終了します。 実際には、有効な候補が見つかる前に少数の候補のみをテストするため、これは許容されます。

 ## アルゴリズムのチュートリアル

1. 可能な限り最高位の分岐 y から開始し、それを答えの候補とみなします。 目標は、最初の有効な候補が自動的に最適になるように、候補を降順でテストすることです。 
2. 各候補値 v について、[2, p] の範囲内の整数が v を除算するかどうかを確認します。そのような約数が存在する場合、その約数から始まるバッタが v に到達する可能性があるため、v は安全ではありません。 
3. [2, p] に約数が見つからない場合は、上位の候補が存在しないため、すぐに v を返します。 
4. v が安全でない場合は、v を 1 減らしてプロセスを繰り返します。 
5. 有効な値が見つからずに 2 未満に達した場合は、-1 を返します。これは、すべての分岐に少なくとも 1 つのバッタが到達できるためです。 

### なぜ効果があるのか

 位置 i から始まる各バッタは、i の倍数の集合に正確に到達できます。 したがって、分岐は 2 から p までの整数で割り切れない場合にのみ安全です。 このアルゴリズムは候補を降順で徹底的にチェックし、最初に見つかった安全な分岐が可能な最大の安全な分岐であることを保証します。 不変条件は、現在の候補より大きいすべての数値がすでにテストされ、安全でないと判断されているため、最初の成功が全体的に最適であるということです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    p, y = map(int, input().split())
    
    for v in range(y, 1, -1):
        ok = True
        for i in range(2, p + 1):
            if v % i == 0:
                ok = False
                break
        if ok:
            print(v)
            return
    
    print(-1)

if __name__ == "__main__":
    solve()
```解決策は、ブランチ システムの境界を読み取ることから始まります。 次に、最上位のブランチから下に向かって反復処理を行い、構築によって最大化を保証します。 各候補について、考えられるすべてのバッタの開始位置に対して割り切れるかどうかをチェックします。 内側のループは、除数が見つかるとすぐに早期に終了するため、多くの場合、不必要なチェックが回避されます。 有効な候補がない場合、関数は -1 を出力します。 

重要な実装の詳細は、厳密な降順反復です。 これがなければ、最大値を明示的に追跡する必要がありますが、降順検索により正確さが自動的に保証されます。

 ## 特殊なケース

 1 つのエッジ ケースは、すべての候補が [2, p] 内の少なくとも 1 つの数値で割り切れる場合に発生します。 たとえば、p が y に比べて大きい場合、小さな約数でほぼすべての整数がカバーされます。 この状況では、ループはすべての値を 2 まで使い果たし、-1 を正しく出力します。 

もう 1 つのエッジ ケースは、y 自体が範囲内のどの数値でも割り切れない場合です。 たとえば、y が p より大きい素数の場合、アルゴリズムは下方検索を行わずに直ちにそれを受け入れます。 

最後に、y が小さく p が大きい場合、約数が 2 や 3 など小さいため、多くの候補はすぐに失敗しますが、アルゴリズムは候補を個別にチェックし、最初の有効な候補で停止するため、引き続き機能し、グローバルな前処理を必要とせずに正確さを保証します。
