 ## 解決策
 ## 問題の理解

 1 日のさまざまな時刻における乗客の流れを表す長い配列の値が与えられます。 「シフト」は 3 つのパラメータによって定義されます: 開始時間インデックス`s`、固定回数の旅行`k`、一定の時間差`d`連続した旅行の合間に。 

時間どおりに始めれば`s`、地下鉄は時々運行しています`s, s + d, s + 2d, ..., s + (k−1)d`。 このシフトの総乗客数は、まさにこれらの位置の配列値の合計です。 タスクは開始位置を選択することです`s`選択されたすべてのインデックスが配列内に存在する必要があるという制約の下で、この合計ができるだけ大きくなるようにします。 

形式的には、配列内の固定等差数列の合計を最大化します。 有効性に関する制約は、最後のインデックスが`s + (k−1)d`配列の境界を超えてはなりません。 

入力サイズが十分に大きいため、すべての有効な開始を反復し、各合計を直接再計算するソリューションは遅すぎます。 単純なアプローチでは、効果的に次のように計算されます。`O(N · k)`周りに崩れる操作`10^10`最悪の場合の構成では実現不可能です。 

重要な微妙な点は、ステップバイ`d`場合を除き、単一の連続セグメントではない構造を作成します。`d = 1`。 いつ`d > 1`、インデックスは独立した剰余クラスに分割されます。`d`であり、各クラスは独自の小さな線形配列のように動作します。 

単純なスライディング ウィンドウ アプローチの典型的な失敗例は、これを通常の部分配列問題のように扱おうとする場合です。`d > 1`。 たとえば、次の場合`d = 2`、合計内の隣接する要素は元の配列では隣接していないため、連続するセグメントに対する標準のプレフィックスやスライディング ウィンドウは適用されません。 

## アプローチ

 ブルートフォースソリューションは出発点を修正します`s`そして明示的に合計します`k`要素の間隔`d`。 これは定義に直接従うため、正しいです。 ただし、そのような計算にはそれぞれコストがかかります`O(k)`、まであります`O(N)`可能な開始点があるため、全体の複雑さは次のようになります。`O(Nk)`。 両方のとき`N`そして`k`が大きいと、すぐに遅くなりすぎます。 

重要な観察は、ステップによって定義される等差数列であるということです。`d`配列を独立したチェーンに分割します。 任意のインデックス`i`フォームのインデックスとのみ対話します`i + td`。 これは、要素をインデックスモジュロでグループ化すると、`d`、各グループは個別のシーケンスを形成しますが、問題は長さの連続するセグメントを選択することになります。`k`そのシーケンスの中で。 

この分解が行われると、プレフィックス合計またはスライディング ウィンドウを使用して、古典的な固定長の最大部分配列合計問題とまったく同じように各グループを解くことができます。 すべての要素は 1 つのグループにのみ属するため、すべてのグループにわたる合計作業量は次のように線形になります。`N`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(Nk) | お(1) | 遅すぎる |
 | 残基分解 / プレフィックスまたはウィンドウ | O(N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 インデックスモジュロに基づいて配列を独立したチェーンに分割することで問題を解決します。`d`。 

1. 要素を剰余クラスのモジュロでグループ化します。`d`。 各グループには、開始剰余クラスを固定するときに等差数列に連続して現れる要素が含まれています。 このステップは必要です。`d`異なる残基クラスを決して混合しないでください。 
2. 各残基クラスについて`r`、シーケンスを抽出します`b = a[r], a[r+d], a[r+2d], ...`。 これにより、元の「スキップされたインデックス」問題が標準の線形配列問題に変換されます。 
3. 各シーケンスについて`b`、長さの連続するセグメントの最大合計を正確に計算します。`k`。 これは、サイズのスライディング ウィンドウを計算するのと同じです。`k`。 最初のウィンドウの合計を初期化してから、出力要素を削除し、入力要素を追加することでそれをシフトします。 
4. すべての残基クラスのすべてのウィンドウにわたる最大値を追跡します。 このグローバル最大値は、元の配列内の最適な有効な開始位置に対応します。 

### なぜ効果があるのか

 インデックスから始まる各有効な等差数列`s`完全に単一の残基クラス内にあります`s mod d`。 そのクラス内では、進行は連続したブロックになります。 したがって、すべての候補シフトは、正確に 1 つのクラス内の正確に 1 つのウィンドウに対応し、そのようなすべてのウィンドウは有効なシフトに対応します。 すべてのクラスのすべてのウィンドウを評価するため、候補を見逃すことはなく、無関係なインデックスを混合することもありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k, d = map(int, input().split())
    a = list(map(int, input().split()))

    if k == 1:
        print(max(a))
        return

    ans = -10**30

    for r in range(d):
        # build window on residue class r
        window = []
        s = 0

        for i in range(r, n, d):
            window.append(a[i])
            s += a[i]

        if len(window) < k:
            continue

        cur = sum(window[:k])
        ans = max(ans, cur)

        for i in range(k, len(window)):
            cur += window[i] - window[i - k]
            ans = max(ans, cur)

    print(ans)

if __name__ == "__main__":
    solve()
```ソリューションは配列を読み取り、すべての剰余クラスを法として反復処理します。`d`。 クラスごとに、ステッピングによって到達可能なすべての位置を表す縮小配列を構築します。`d`。 次に、長さの固定サイズのスライディング ウィンドウを使用します。`k`合計を効率的に計算するため。 

重要な実装の詳細は、元のインデックス システムで直接合計を計算しようとしないことです。 すべての計算は圧縮された剰余シーケンスで行われ、線形の合計作業量が保証されます。

## 特殊なケース

 のために`k = 1`、アルゴリズムは最大の要素を即座に返す必要があります。 スライディング ウィンドウ ロジックは引き続き機能しますが、ガードがないと少なくとも 1 つの遷移が存在すると誤って想定する可能性があります。 

以下の場合については、`len(b) < k`残余クラスでは、そのクラスを完全にスキップする必要があります。 そうしないと、部分ウィンドウが誤って考慮されてしまいます。 

大型用`d`に近い`n`、ほとんどの残基クラスには最大でも 1 つの要素しか含まれていません。つまり、次の場合を除き、有効なウィンドウが存在しません。`k = 1`。 このような場合にはスライディング ループは実行されないため、アルゴリズムはこれを自然に処理します。
