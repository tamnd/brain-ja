 ## 問題の理解

 この問題は、特定の等差数列が与えられた整数で割り切れる数を生成するかどうかに事実上関心を持つプロセスを記述しています。$N$。 シーケンスは固定されており、小さなオフセットから開始して一定のステップで増加します。$2, 5, 8, 11, \dots$。 次の各値は 3 を加算することによって取得されるため、シーケンスは次の形式のすべての数値として見ることができます。$a_i = 3i + 2$。

このステートメントは組み合わせまたはプロセスベースの解釈の観点から表現されていますが、計算の核心は純粋に数論です。つまり、線形等差数列に次の倍数が含まれているかどうかをチェックしています。$N$。 

制約は明示的には示されていませんが、声明内の議論は潜在的に大きな制約を示唆しています。$T$そして大きい$N$、単純な反復で最大$N$ステップ全体が遅すぎます。 これにより、進行に対するテストごとの線形スキャンが即座に排除されます。 

素朴な推論が微妙に失敗するケースは、「最終的には」すべてのことが起こると仮定した場合に現れます。$N$無限の成長によりシーケンスに表示されます。 たとえば、$N = 3$、シーケンスは次のとおりです$2, 5, 8, 11, \dots$この間違いは、3 を法とするシーケンスの固定剰余クラスを無視したことに起因します。

## アプローチ

 直接的なアプローチは、シーケンスをシミュレートし、各項の割り算をテストすることです。 私たちは生成します$a_i = 3i + 2$かどうかを確認してください$a_i \bmod N = 0$。 これは、条件を必要に応じて正確にテストするため、正しいです。 ただし、最悪の場合、$N$大きいため、最大まで調べる必要があるかもしれません$N$剰余は剰余であるため、解が存在しないと結論付ける前に候補を探索します。$N$ピリオドを付けて繰り返す$N$。 多くのテスト ケースにわたって、これにより全体的な複雑さが次のようになります。$O(T \cdot N)$、両方の値が大きい場合、これは非常に遅くなります。 

重要な洞察は、大きな数を生成するという観点から考えるのをやめ、代わりにモジュラー演算に切り替えることです。 シーケンス$3i + 2$は 3 を法とする固定剰余を持ち、常に 2 に等しい。つまり、すべての項は 3 を法とする単一の合同クラスに属することを意味する。これらの数値のいずれかが次の数で割り切れるかどうか。$N$の剰余クラスがどのように決まるかに完全に依存します。$N$この構造と相互作用します。 

もし$N$が 3 で割り切れる場合は、次の倍数ごとに$N$も 3 で割り切れるため、3 を法とする剰余クラス 0 にあります。シーケンスは 3 を法とする剰余クラス 2 に留まっているため、交差は発生しません。

したがって、問題全体は次のことを確認することに集約されます。$N$は 3 で割り切れません。

 ## アルゴリズムのチュートリアル

 各テスト ケースを単一のモジュール チェックに縮小します。

### なぜ効果があるのか

 シーケンス$a_i = 3i + 2$3 を法とする定数であり、常に 2 に等しい。次で割り切れる任意の数。$N$によって決定される残基がなければなりません$N$モジュロ 3.If$N \equiv 0 \pmod{3}$、その倍数は剰余 2 と一致しないため、解は存在しません。 もし$N \not\equiv 0 \pmod{3}$、適切な係数による乗算により残基が整列され、次の値の倍数が保証されます。$N$同じ等差数列クラスに分類されます。 シーケンスと倍数の集合の両方が$N$が無限かつ周期的モジュロ 3 である場合、剰余互換性は必要かつ十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        if n % 3 == 0:
            out.append("NO")
        else:
            out.append("YES")
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このソリューションはすべてのテスト ケースを読み取り、それぞれを一定時間で独立して処理します。 ケースごとの唯一の計算はモジュロ演算であり、等差数列から導出される構造条件を直接取得します。 

決定ルールは、導出された条件どおりに実装されます。3 で割り切れる場合は失敗を意味し、それ以外の場合は成功を意味します。 

よくある実装上の間違いは、シーケンスをシミュレートしようとしたり、明示的に倍数を検索しようとしたりすることです。 シーケンスの残基クラスにより列挙の必要性が完全に排除されるため、これは不要です。

 ## 特殊なケース

 のために$N = 3$、アルゴリズムは次のように計算します。$3 \bmod 3 = 0$そしてすぐに「NO」を返します。 序列は残る$2, 5, 8, \dots$、すべて 2 モジュロ 3 に合同なので、3 で割り切れるものはありません。 

のために$N = 6$、計算の構造は同じです。$6 \bmod 3 = 0$、したがって、答えは再び「NO」です。 6 の方が大きいにもかかわらず、その倍数は依然として剰余クラス 0 モジュロ 3 に留まり、シーケンスの固定剰余クラスと交差することはありません。 

のために$N = 4$、私たちは得ます$4 \bmod 3 = 1$、そのため、アルゴリズムは「YES」を出力します。 これは、剰余クラス 2 モジュロ 3 にある 4 の倍数の存在に対応し、数列と一致します。 この構造により、明示的に検索する必要がなくても、そのような倍数が存在することが保証されます。
