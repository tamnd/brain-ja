 ## 問題の理解

 私たちは、ウイルスの初期量が毎秒一定の乗算係数で拡大する単純な指数関数的増殖モデルを扱っています。 正式には、ある時点でのウイルスの数$t$形式のべき乗関数に従います$v(t) = b \cdot q^t$、ここで両方の初期量$b$そして成長因子$q$は未知の整数です。 

与えられる代わりに$b$そして$q$、このプロセスについて観察された 2 つの測定値が与えられます。$v(t)$2つの異なる時間に。 指数曲線上のこれら 2 つの点から、基礎となるパラメーターを再構築し、次の完全な式を出力するように求められます。$v(t)$。 

したがって、入力は未知の指数関数に対する 2 つの制約を表し、出力はその関数の明示的な閉じた形式であり、具体的な整数値に簡略化されます。 

一見したところ、この構造は十分に決定されていないように見えますが、指数関数的な増加によって除算が初期値の完全なキャンセルに変わるため、2 回の測定で十分です。 

アルゴリズムの複雑さに関する懸念を引き起こす複雑なデータ構造や大きな入力制約はありません。 問題全体は、整数演算とべき乗と根の注意深い処理に帰着します。 唯一の微妙な失敗ケースは、特に中間計算が整数形式で保持されていない場合に、浮動小数点の精度と書式設定によって発生します。 

式を次のような代替の等価形式に書き換えるときによくある落とし穴が発生します。$v(t) = 21 \cdot 7^{t-1}$。 有効な実数に対して代数的には同一ですが、$t$、この表現は次のように評価されるときに小数値を導入します。$t = 0$、次のような浮動小数点出力が発生する可能性があります`3.0`の代わりに`3`、厳密な出力フォーマット要件に違反します。 

## アプローチ

 この問題を考える直接的な方法は、それを 2 つの未知数を持つ 2 つの方程式として扱うことです。 モデルから$v(t) = b \cdot q^t$、すぐに次のものを取得します。$v_3 = b \cdot q^3$そして$v_6 = b \cdot q^6$。 

強引なアイデアは、次のすべての妥当な整数値を試してみることです。$b$そして$q$、両方の方程式をシミュレートし、一貫性を確認します。 値が小さければ、これは機能します: 可能性のあるものを反復処理します。$q$、計算する$b$1 つの式から計算し、2 番目の方程式に対して検証します。 

すべての候補ペアが両方の制約に対して明示的にテストされるため、この総当りは正しいです。 ただし、入力の大きさに応じて可能性の空間が拡大し、べき乗の構造を使用していないため、これは不必要であり、中程度の境界であっても概念的に無駄になります。 

重要な観察は、2 つの方程式を除算すると次のことが解消されるということです。$b$完全に。 これにより、問題は 2 変数の検索から 1 変数の抽出に変換されます。$$\frac{v_6}{v_3} = \frac{b q^6}{b q^3} = q^3$$これにより、構造全体が純粋な電力方程式に崩壊します。 一度$q^3$既知である、抽出する$q$立方根問題になります。 その後、$b$いずれかの式への代入から直接得られます。 

これが重要な単純化です。指数関数的な増加により、観測値の比率が基底のきれいな検出力に変換されます。

 ## アルゴリズムのチュートリアル

 1. プロセスに関する 2 つの所与の観察結果を読み取ります。$(t_1, v_1)$そして$(t_2, v_2)$。 この問題では、これらは次のようになります。$(3, v_3)$そして$(6, v_6)$。 
2. 比率を計算する$r = \frac{v_2}{v_1}$。 両方の値が同じ指数関数から得られるため、このステップは有効であり、未知の乗数は完全に相殺されます。 これにより、成長因子の影響が分離されます。 
3. 比率を底のべき乗として解釈します。$r = q^{t_2 - t_1}$。 時差が3なので、$r = q^3$。 
4. コンピューティング$q$の整数の立方根を抽出することにより、$r$。 これは整数演算として慎重に行う必要があります。$q$意図した構造では整数であることが保証されます。 
5.回復$b$先ほどの式を使用すると$v_1 = b \cdot q^3$。 並べ替えると$b = \frac{v_1}{q^3}$。 この分割は構造上正確です。 
6. 最終関数を出力する$v(t) = b \cdot q^t$簡略化された整数形式で。 

### なぜ効果があるのか

 正確さは、両方の測定値が同一の底を持つ同じ指数曲線上にあるという不変式から得られます。$q$。 2 点の任意の比率により係数が消去されます。$b$の純粋な力だけを残して、$q$。 指数の差は指数減算に直接変換されるため、システムは単一の未知の指数方程式に帰着します。 一度$q$比率の整数の立方根として一意に決定され、代入バックにより回復されます。$b$曖昧さなく正確に。 他の整数のペアは両方の方程式を同時に満たすことができないため、再構成は一意になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def cube_root(x):
    lo, hi = 0, int(1e6)
    while lo <= hi:
        mid = (lo + hi) // 2
        val = mid * mid * mid
        if val == x:
            return mid
        if val < x:
            lo = mid + 1
        else:
            hi = mid - 1
    return hi

v3 = 1029
v6 = 352947

ratio = v6 // v3
q = cube_root(ratio)
b = v3 // (q ** 3)

print(f"{b} * {q}^t")
```実装は派生を直接反映します。 最初のステップでは、指定された観察結果を修正します。 この問題では正確な割り算が保証されているため、比率の計算では整数の割り算が使用されます。 立方根は浮動小数点エラーを避けるために二分探索によって計算されます。これは、整数の等価性を検証する際に、わずかな精度の問題でも正確性が損なわれるためです。 

決定した後$q$、ベース$b$直接置換によって回復されます。 最終出力では、再構築された数式が、予期される形式と一致するシンボリック形式で出力されます。

import sys, io

 ## 特殊なケース

 最も敏感なエッジ ケースは、比率が完全な立方体であるが、根を抽出するために浮動小数点演算が使用される場合に発生します。 たとえば、次の場合$v_3 = 3$そして$v_6 = 1029$、比率は$343$。 使用する`round(ratio ** (1/3))`リスクを生み出す`6.999999999`これは、精度に応じて 7 または場合によっては 6 に誤って丸められ、誤った再構築につながります。 

正しい整数ベースのアプローチでは、これを完全に回避します。 二分探索では、立方体が比率を超えない最大の整数が計算され、正確さが保証されます。 

もう 1 つの微妙なケースは、代数変換を使用する場合の出力フォーマットです。 書き込み$v(t) = 21 \cdot 7^{t-1}$正しい値を生成します$t \ge 1$ただし、システムが評価または出力した場合は、$t = 0$、式は次のようになります$21 / 7$、次のように表すことができます。`3.0`浮動小数点形式で。 必要な出力形式は小数点のない整数表現を想定しているため、正規形式を維持します。$b \cdot q^t$このクラスのエラーを回避します。 

最終的な構造上のエッジケースは次のような場合です。$q = 1$。 このシナリオでは、両方の測定値が等しく、比率は 1 になります。アルゴリズムは引き続き機能します。1 の立方根は 1 であり、$b$次のように直接復元されます$v_3$、特別なケースを使用せずに正確さを維持します。
