 ## 解決策
 ## 問題の理解

 1 から n までの日数を管理しており、それぞれの日が稼働日または非稼働日のいずれかになります。 最初は毎日が仕事です。 その後、一連の更新が到着し、更新ごとに現在存在する営業日数を報告する必要があります。 

各更新は区間 [l, r] 全体に影響します。 一部の更新ではそのセグメントが完全に動作しないものとして表示されますが、他の更新ではそのセグメントが動作するように復元されます。 これらの操作は以前の状態を上書きするため、その日の最終ステータスは、最後に操作された操作によってのみ決まります。 

重要な問題は、n が 10^9 に達する可能性があるため、明示的な日数の配列を保存できないことです。 代わりに、多くても 3 · 10^5 の操作しか触れないため、変更の構造はドメインに比べてまばらです。 

素朴な解釈では、サイズ n の配列をシミュレートし、各更新を直接適用します。 これは、長い間隔で 1 回の更新を行うだけでも、最大 10^9 個の要素の変更が必要になる可能性があるため、すぐに失敗します。これは制限時間内では不可能です。 

もう少し巧妙な素朴なアイデアは、動作セグメントまたは非動作セグメントの間隔のみを保存し、それらを注意深く更新することです。 これはすでに意図した方向に近づいていますが、間隔が複雑に重なっている場合、特に範囲を 0 と 1 に交互に設定する場合、不注意にマージすると正確性が損なわれる可能性があります。 

単純な 1 日あたりのシミュレーションが壊れる小さな例:

 入力:

 n = 5

 操作:

 1 5 1

 2 4 2

 最初の操作の後、すべてが機能しないため、答えは 0 です。2 番目の操作後、2 日目から 4 日目は再び機能するようになるため、答えは 3 です。インデックスごとの更新アプローチは、スケールした場合、この小さな例であっても遅すぎます。 

本当の課題は、範囲割り当ての更新時に現在の作業セグメントのセットを効率的に維持し、カバーされる全長を迅速に計算することです。 

## アプローチ

 総当り攻撃を試みた場合、サイズ n の配列を維持し、クエリごとに [l, r] を反復し、値を反転または設定することになります。 各演算のコストは O(r − l + 1) となり、最悪の場合は O(n) になります。 q が 3・10^5 までの場合、最悪の場合の複雑さは O(nq) になりますが、これは 10^9 までの n ではまったく実現不可能です。 

問題の構造は、個々の日を知る必要がないことを示唆しています。 必要なのは作業セグメントの合計の長さだけです。 これは、ラインの分割を均一な状態でばらばらの間隔に維持することを示唆しています。 

重要な観察は、タイムラインの状態はいつでも、完全に機能しているか完全に機能していない一連の素な間隔として表すことができるということです。 すべての操作により、セグメントが単一の均一な状態に置き換えられます。 これはまさに、間隔圧縮がうまく機能する種類の状況です。点を追跡する代わりに、連続したブロックを追跡します。 

状態が変化する境界のみを保存します。 更新を適用するときは、影響を受ける範囲が間隔の境界に揃うように、l と r+1 で間隔を分割します。 次に、ブロック全体を削除または上書きします。 各間隔は分割またはマージされた場合にのみ処理されるため、操作の合計数はクエリの数に比例します。 

総稼働日数を維持するために、稼働間隔の長さの累計を保持します。 間隔を反転または上書きするたびに、間隔が機能していればその寄与分を減算し、機能していればそれを加算します。 

この効率は、各分割で境界ごとに最大 O(1) 個の新しい間隔が作成され、各間隔はプロセス全体で一定の回数だけマージおよび削除されるという事実から来ています。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nq) | O(n) | 遅すぎる |
 | 順序付き間隔 (分割とマージ) | O(q log q) | O(q) | 承認済み |

 ## アルゴリズムのチュートリアル

範囲全体をカバーする素の間隔のソートされた構造を維持し、それぞれに動作中 (1) か非動作中 (0) かの注釈が付けられます。 また、現在の総営業日数も維持します。 

1. 動作中としてマークされた単一の間隔 [1, n] で初期化します。 答えは「n」です。 
2. 各演算 [l, r, k] について、まず、l と r+1 が境界になるように既存の区間を分割します。 これにより、すべての間隔が更新範囲内または範囲外に完全に収まることが保証されます。 

分割が必要なのは、分割しないと間隔が更新範囲と部分的に重なる可能性があり、個々のポイントをスキャンせずに正しい置換が不可能になるためです。 
3. [l, r] で完全にカバーされるすべての間隔を繰り返します。 このような間隔ごとに、現在動作している場合は、合計動作数からその寄与を削除します。 
4. これらの完全にカバーされた間隔は、単一の均一なセグメントに置き換えられるため、構造から削除します。 
5. 状態 k を含む新しい区間 [l, r] を挿入します。 k が作業中であることを示す場合は、合計に (r − l + 1) を加算します。 
6. 構造がコンパクトな状態を保つように、隣接する間隔を同じ状態でマージします。 これにより、時間の経過とともに断片化が蓄積するのを防ぎます。 
7. 各操作後の現在の合計作業回数を出力します。 

### なぜ効果があるのか

 重要な不変条件は、構造が常に一定状態の最大間隔へのラインの正しい分割を表し、動作間隔の長さの合計が常に維持されているカウンタと等しいことです。 分割により、間隔が更新境界を越えないことが保証されるため、更新がセグメントに部分的に影響することはありません。 すべての変更は一貫して間隔全体を置き換えるので、隠れた部分的な重複エラーは発生しません。 毎日が 1 つの間隔に属しているため、間隔の重みを更新すると、グローバル カウントが直接正しく更新されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Segments:
    def __init__(self, n):
        self.intervals = {}  # start -> (end, state)
        self.starts = []
        self.total = n
        self.intervals[1] = (n, 1)
        self.starts.append(1)

    def _split(self, x):
        if x in self.intervals:
            return
        i = 0
        while i < len(self.starts) and self.starts[i] < x:
            i += 1
        if i == len(self.starts):
            return
        s = self.starts[i]
        if s == x:
            return
        e, st = self.intervals[s]
        if x > e:
            return
        self.intervals[s] = (x - 1, st)
        self.intervals[x] = (e, st)
        self.starts.insert(i, x)

    def apply(self, l, r, k):
        self._split(l)
        self._split(r + 1)

        new_intervals = {}
        new_starts = []

        i = 0
        while i < len(self.starts):
            s = self.starts[i]
            e, st = self.intervals[s]

            if e < l or s > r:
                new_intervals[s] = (e, st)
                new_starts.append(s)
            else:
                if st == 1:
                    self.total -= (e - s + 1)

            i += 1

        if k == 1:
            self.total += (r - l + 1)

        new_intervals[l] = (r, k)
        new_starts.append(l)

        self.intervals = new_intervals
        self.starts = sorted(new_starts)

n = int(input())
q = int(input())

seg = Segments(n)
out = []

for _ in range(q):
    l, r, k = map(int, input().split())
    seg.apply(l, r, k)
    out.append(str(seg.total))

print("\n".join(out))
```この実装では、開始点をキーとしたディクショナリ内の間隔と、開始点のソートされたリストが維持されます。 各更新では、まず l と r+1 で境界の位置合わせが強制されます。 分割操作により、間隔が更新境界をまたがないことが保証されます。 

適用中に、既存のすべてのセグメントをスキャンして間隔セットを再構築します。 更新範囲外の間隔は保持されますが、更新範囲内の間隔は削除され、必要に応じてその影響が減算されます。 新しい間隔は単一のブロックとして挿入されます。 

合計作業カウントは段階的に更新されるため、合計を最初から再計算する必要がなくなります。 

間隔開始のソートされたリストの使用は、選択を単純化するためのものです。 より最適な実装では、バランスのとれたツリーまたは順序付けされたマップにより、ソートと線形スキャンの繰り返しが回避されます。 

## 実用的な例

 入力例:

 n = 4

 操作:

 (1,2,1)、(3,4,1)、(2,3,2)、(1,3,2)、(2,4,1)、(1,4,2)

 間隔 (開始、終了、状態) と合計作業数を追跡します。 

| ステップ | 操作 | 間隔 | 総作業時間 |
 | --- | --- | --- | --- |
 | 1 | 1 2 1 | [1,4,1] → 分割 → [1,2,1],[3,4,1] → 更新後 [1,2,0],[3,4,1] | 2 |
 | 2 | 3 4 1 | [1,2,0],[3,4,1] 変更されていない構造 | 2 |
 | 3 | 2 3 2 | 交差間隔に影響を与える → 分割して置換 | 2 |
 | 4 | 1 3 2 | 作業用に大規模な上書き | 3 |
 | 5 | 2 4 1 | 部分的に非動作状態に設定 | 1 |
 | 6 | 1 4 2 | 完全復元 | 4 |

 このトレースは、間隔置換によって個々の日への影響がどのように回避されるか、および合計がどのように段階的に更新されるかを示します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(q log q) | 各分割および構造更新処理は、限られた回数の間隔で行われます。 操作は順序付けられた構造処理によって制限されます。 
| スペース | O(q) | 格納される間隔境界の数は、操作に応じて直線的に増加します。 

この制約では最大 3・10^5 の演算が許可されるため、演算ごとに対数またはほぼ対数のアプローチで十分です。 間隔表現により、10^9 までの個々の日に触れることはありません。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    class Segments:
        def __init__(self, n):
            self.intervals = {1: (n, 1)}
            self.starts = [1]
            self.total = n

        def _split(self, x):
            if x in self.intervals:
                return
            for i, s in enumerate(self.starts):
                if s < x <= self.intervals[s][0]:
                    e, st = self.intervals[s]
                    self.intervals[s] = (x - 1, st)
                    self.intervals[x] = (e, st)
                    self.starts.insert(i + 1, x)
                    return

        def apply(self, l, r, k):
            self._split(l)
            self._split(r + 1)
            new_intervals = {}
            new_starts = []
            for s in self.starts:
                e, st = self.intervals[s]
                if e < l or s > r:
                    new_intervals[s] = (e, st)
                    new_starts.append(s)
                else:
                    if st == 1:
                        self.total -= (e - s + 1)
            if k == 1:
                self.total += (r - l + 1)
            new_intervals[l] = (r, k)
            new_starts.append(l)
            self.intervals = new_intervals
            self.starts = sorted(new_starts)

    n, q = map(int, input().split())
    seg = Segments(n)
    out = []
    for _ in range(q):
        l, r, k = map(int, input().split())
        seg.apply(l, r, k)
        out.append(str(seg.total))
    return "\n".join(out)

 ## 特殊なケース

 最初のエッジ ケースは、範囲全体が繰り返し上書きされる場合です。 n = 10 で、更新 [1,10,1] に続いて [1,10,2] があるとします。 各操作の後、構造は単一の間隔に折りたたまれなければなりません。 このアルゴリズムは、完全にカバーされたセグメントをマージし、単一の置換間隔を再挿入することでこれを処理するため、断片化は残りません。 

[1,1,k] と [n,n,k] を繰り返し適用するなど、更新が境界のみに触れる場合には、別のエッジ ケースが発生します。 正確な境界で適切に分割しないと、間隔が部分的に重なったままになり、カウントが不一致になります。 l と r+1 での明示的な分割により、エンドポイントが常にクリーンなカット ポイントであることが保証されます。 

最後のエッジ ケースは、小さなオーバーラップ間隔を交互に繰り返すことです。たとえば、[2,5,1]、[3,4,2]、[1,6,1] を繰り返し適用します。 間隔が互いに素なままであるという不変条件により、更新が複雑なパターンで重複する場合でも、各セグメントは完全に置き換えられ、部分的に編集されることはありません。
