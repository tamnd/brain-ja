 ## 問題の理解

 2 つの整数が与えられます。`a`そして`b`。 私たちの仕事は、次の桁を並べ替えることです。`a`を超えない最大の数値を生成する`b`。 結果の数値は、次のすべての桁を使用する必要があります。`a`必ず 1 回だけ実行し、先頭にゼロを付けることはできません。 数値は非常に大きくなる可能性があり、最大で$10^{18}$つまり、固定ビット幅のデータ型に依存することはできませんが、Python は任意の長さの整数をネイティブに処理します。 

重要な制約は、答えが次の桁数と同じでなければならないということです。`a`したがって、サイズを調整するために数字を削除したり、先頭のゼロを追加したりすることはできません。 これにより、最大の順列が`b`。 すべての順列を生成する単純な実装は正しいですが、18 桁の数値の順列の数が達する可能性があるため、非常に非効率的です。$18! \approx 6 \times 10^{15}$。 

明らかではないエッジケースには、次のような状況が含まれます。`a`数字が繰り返されており、最初の数字は`b`の最初の桁より小さいです`a`、または各ステップに複数の選択肢が存在するが、有効な数値につながるシーケンスは 1 つだけです。 たとえば、次の場合`a = 123`そして`b = 213`、各位置で利用可能な最大の数字を単純に選択すると、次のようになります。`321`、これは無効です。 正しい答えは、`213`、これには、より高い桁での失敗した試行からのバックトラックが必要です。 

## アプローチ

 ブルートフォースアプローチは、次のすべての順列を生成することです。`a`を超えない最大のものを選択します`b`。 これは、有効な候補をすべて明示的に列挙するため正しいですが、複雑さは次のとおりです。$O(n!)$、 どこ$n$の桁数です`a`。 最大 18 桁の場合、このアプローチは完全に実行不可能です。 

効率的な解決策につながる重要な観察は、すべての順列を生成する必要はないということです。 2 つの可能性を維持しながら、左から右に 1 桁ずつ結果を構築できます。`b`残りの最大の桁を自由に選択できます。または、完全に一致します。`b`これまでのところ、対応する桁を超えない桁を選択する必要があります。`b`。 これは当然、枝刈りを伴う再帰的または深さ優先の検索アプローチにつながります。 数字を降順に並べ替えると、各ステップで残っている最大の有効な数字をすばやく選択できます。 

の各桁を考慮すると、`b`選択が有効な継続につながらない場合は、順番に慎重に後戻りして、構築する最初の有効な完全長の数値が最大であることを保証します。 これにより、階乗問題が桁レベルの再帰で管理可能な問題に変換されます。複雑さは桁の 2 乗で制限されます。これは、各位置で最大でも試行するためです。`n`桁数と再帰の深さは`n`。

 ## アルゴリズムのチュートリアル

 1. 両方を変換する`a`そして`b`文字列に`A`そして`B`。 の各桁の頻度を数えます。`a`。 結果の文字列を段階的に構築していきます。 
2.長さの場合`a`の長さより短いです`b`、並べ替えることができます`a`の数字を降順に並べて出力します。 すべての順列は自動的に以下より小さくなります`b`。 
3. 長さが等しい場合、再帰関数を定義します`dfs(pos, tight)`どこ`pos`は現在の数字のインデックスであり、`tight`これまでに構築された数値が接頭辞と等しいかどうかを示します。`b`。 から始めます`pos = 0`そして`tight = True`。 
4. 各位置で、9 から 0 までの数字を繰り返します。その数字が頻度カウントで使用可能であり、違反していない場合は、`tight`、それを選択してください。 そのカウントを減らし、再帰的に次の位置に進みます。 再帰が成功した場合は、選択した数字を結果に追加します。 
5. もし`tight`が True の場合、以下の数字のみが許可されます。`B[pos]`。 もし`tight`が False の場合、降順の残りの数字はすべて有効です。 
6. ある位置で機能する桁がない場合は、桁数を復元して次の小さい桁を試してバックトラックします。 
7. すべての位置が入力されたら、選択した数字を結合して結果を出力します。 

機能する理由: このアルゴリズムは、これまでに選択されたすべての数字が、対応する接頭辞を超えない有効な接頭辞を形成するという不変条件を維持します。`b`。 降順で数字を探索し、必要に応じてバックトラックすることにより、最初に構築された完全な数字が最大の有効な順列であることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    A = input().strip()
    B = input().strip()
    n = len(A)
    m = len(B)

    if n < m:
        print("".join(sorted(A, reverse=True)))
        return

    from collections import Counter
    count = Counter(A)
    result = []

    def dfs(pos, tight):
        if pos == n:
            return True
        limit = int(B[pos]) if tight else 9
        for d in range(limit, -1, -1):
            if count[str(d)] > 0:
                count[str(d)] -= 1
                result.append(str(d))
                if dfs(pos + 1, tight and d == limit):
                    return True
                result.pop()
                count[str(d)] += 1
        return False

    dfs(0, True)
    print("".join(result))

if __name__ == "__main__":
    solve()
```このソリューションでは、まず次のような自明なケースをチェックします。`a`よりも桁数が少ない`b`。 カウンタを使用して利用可能な桁を追跡し、降順で再帰的に桁を選択し、それを超えるパスを枝刈りします。`b`。 バックトラッキングにより、必要に応じて代替の数字を探索できるようになります。
