 ## 解決策
 ## 問題の理解

 一連の整数が与えられます。 私たちの目標は、このシーケンスを、各サブシーケンスが「値が連続している」最小数のサブシーケンスに分割することです。 つまり、サブシーケンス内では、隣接するすべてのペアが 1 つだけ異なります。 

たとえば、`[3, 4, 3, 2]`、有効なサブシーケンスは次のようになります。`[3, 4, 3, 2]`1ステップごとに±1ずつ変化しますが、`[3, 3, 4]`は無効です。`3`に`3`の差は0です。 

各テスト ケースの出力は、単にこのプロパティを満たすサブシーケンスの最小数です。 元のシーケンス内の各整数は、正確に 1 つのサブシーケンスに出現する必要があります。 

制約により、最大で次のことが許可されます。`10^6`すべてのテスト ケースにわたる要素の合計。 これにより、二次関数となる解は除外されます。`n`、 なぜなら`10^12`操作が必要になります。 したがって、線形または線形算術的なアプローチが必要です。 

明らかではないエッジ ケースは、要素が繰り返されるシーケンスです。 例えば、`[2, 2, 2]`すべてを 1 つのサブシーケンスに含めることはできません。`2-2=0`。 それぞれ`2`新しいサブシーケンスを開始する必要があります。 同様に、次のような値を「飛び回る」シーケンスも、`[1, 3, 2, 3, 2]`、慎重にカウントする必要があります。単純に欲張って左から右にマージすると、必要以上に多くのサブシーケンスが生成される可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、連続差分特性を満たすすべての可能なサブシーケンスを生成し、最小限のカバーを選択しようとします。 サブシーケンスを選択する方法は指数関数的にたくさんあるため、これは明らかに実行不可能です。 適切な記録を行わずに欲張りな左から右への代入を行っても失敗する可能性があります。これは、後のサブシーケンスにマージされる可能性のある要素が分離されたままになる可能性があるためです。 例えば、`[3, 2, 3]`left-to-right を貪欲に実行すると、1 つではなく 3 つのサブシーケンスが作成される可能性があります。 

重要な洞察は、順序ではなく頻度と接続の観点から考えることです。 各整数について`x`、現在終了するサブシーケンスの数がわかっている場合`x-1`、添付できます`x`そのうちの1人に。 存在しない場合は、次の位置で新しいサブシーケンスを開始する必要があります。`x`。 これにより、問題は各数値で終わる「開いた部分列」を数えるということになります。 

整数値をその数値で終わるサブシーケンスの数にマッピングする辞書 (または配列) を使用して、これを効率的に実装できます。 数値ごとにシーケンスを繰り返します`x`で終わる開いたサブシーケンスがあるかどうかを確認します`x-1`。 ある場合は添付してください`x`(カウントをデクリメントします)`x-1`、増分カウント`x`）。 それ以外の場合は、次の位置で新しいサブシーケンスを開始します。`x`。 処理後、すべてのカウントの合計がサブシーケンスの総数になります。 これが機能するのは、各番号が前のチェーンを継続するか、新しいチェーンを開始するかのいずれかであり、どの番号に接続するかを貪欲に選択できるためです。`x-1`最小限のサブシーケンスを保証します。

 ## アルゴリズムのチュートリアル

 1. カウンタを初期化する`end_count`これは、整数をその値で現在終了しているサブシーケンスの数にマップします。 
2. 各要素を反復処理します。`x`任意の順序でシーケンスで。 それぞれについて`x`、どうかを確認してください`end_count[x-1] > 0`。 
3. で終わるサブシーケンスの場合`x-1`存在する、減少する`end_count[x-1]`そして増加します`end_count[x]`。 これにより効果的に取り付けられます`x`その続きへ。 
4. で終了するサブシーケンスがない場合`x-1`、増分`end_count[x]`新しいサブシーケンスを開始します。 
5. すべての要素を処理した後、次のすべての値の合計が求められます。`end_count`はサブシーケンスの最小数です。 各カウントは、その番号で終わるサブシーケンスを表します。 

機能する理由: すべての要素は既存のサブシーケンスを拡張するか、新しいサブシーケンスを開始します。 添付する`x-1`シーケンスが継続する可能性のある番号が孤立したままになることがないよう、貪欲に保証します。 繰り返される要素は自然に新しいサブシーケンスを作成します。`x-1`利用可能な端がゼロになる可能性があります。 不変条件とは、`end_count`は常に現在の「オープンチェーン」を追跡しており、マージの機会を決して逃しません。 

## Python ソリューション```python
import sys
from collections import defaultdict
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        end_count = defaultdict(int)
        for x in a:
            if end_count[x - 1] > 0:
                end_count[x - 1] -= 1
            end_count[x] += 1
        print(sum(end_count.values()))

if __name__ == "__main__":
    solve()
```ソリューションでは、`defaultdict(int)`キーの存在をチェックしないようにするため。 各数値について、次で終わるサブシーケンスに接続できるかどうかを確認します。`x-1`。 そうであれば、そのサブシーケンスをデクリメントし、次のようにインクリメントします。`x`。 それ以外の場合は、新しいサブシーケンスを開始します。 最終的な合計額は、`end_count.values()`サブシーケンスの最小数を与えます。
