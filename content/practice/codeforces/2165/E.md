 ## 解決策
 ## 問題の理解

 木が与えられ、その端に色を割り当てる必要があります。 制限は、正確に使用する必要があることです。$k$それぞれが少なくとも 1 回は現れる、異なる色。 カラーリングが修正されたら、任意の 2 つの頂点を考慮し、それらの間の単純なパスを確認します。 そのパスに沿って、一連のエッジの色が表示され、そのパス上に現れるさまざまな色の数を数えます。 カラーリングの「不便さ」は、すべての頂点ペアにおける最大値です。 

それぞれについて$k$1から$n-1$、正確に使用する可能な限り最高のカラーリングが必要です。$k$色を調整し、あらゆるパス上で見られる個別の色のこの最大数を最小限に抑えます。 

制約は大きくなります。$n$すべてのテストケースにわたって、$3 \cdot 10^5$、したがって、これに近い解決策はどれでも$O(n^2)$あるいは、カラーリングやパスを明示的にシミュレートしようとするものは、すぐに失敗します。 平$O(n \log n)$テスト ケースごとに注意が必要ですが、線形または線形に近い解決策が期待されます。 

重要な微妙な点は、答えは特定の色に関するものではなく、固定された色数の下で実現可能な最適な色の構造に関するものであるということです。 そのため、単純なシミュレーションは不可能になります。 

よくある失敗モードは、実際にパス上に多数の異なる色が生成される原因を理解せずに、エッジや貪欲な割り当てについてローカルで推論しようとすることです。 たとえば、スター ツリーでは、すべてのエッジが固有の色になる場合、2 枚の葉の間のパスは中心を通過し、多くはありませんが 2 つの色が表示されます。 これは、色の数が直接的な不都合ではないことを示しています。 それは、木のパスに対して色がどのように配置されるかによって決まります。 

もう 1 つのエッジ ケースはパス グラフです。 ツリーが単純なチェーンであり、各エッジが異なる色を持つ場合、端点間のパスにはすべての色が表示されるため、不便が大きくなります。 スターとチェーンのこのコントラストが、まさにソリューションを推進するものです。 

## アプローチ

 ブルートフォースアプローチでは、割り当てを試みます。$k$色に$n-1$可能なすべての方法でエッジを検出し、それぞれの割り当ての不便さを計算します。 修正さえ$k$、色の数は指数関数的です$n$、各カラーリングを評価するには、全ペアのパス検査または大規模な LCA ベースの計算が必要です。 これは実現可能な限界をはるかに超えています。 

重要な観察は、カラーリングの不便さは、根から葉、または葉から葉のパスに沿って「色を切り替える」回数のみに依存し、これは同じ色のエッジがどのように連結コンポーネントを形成するかに密接に関係しているということです。 

逆に考えると、色を割り当てる代わりに、エッジをグループ化することを想像できます。$k$接続されたカラークラス。 各色クラスは、接続されたサブグラフを形成します。これは、色が切断された部分に分割されている場合、それらを結合しても不便が増すことはなく、役立つだけであるためです。 

したがって、問題は次のようになります。エッジを次のように分割します。$k$ツリー パスと交差するコンポーネントの最大数を最小限に抑える何らかの方法でコンポーネントを接続します。 

ここで、重要な構造的洞察が必要になります。ツリーでは、最悪のパスは、コンポーネントが重い分岐点に沿ってどのように切断されるかによって常に決まります。 ツリーをルート化すると、ノードに複数の「アクティブな」子分岐があるたびに、ノードを通過するパスに複数の色成分が蓄積される可能性があります。 

最適な戦略は程度にのみ依存することになります。 次数の各ノード$d$まで強制できます$d$最悪の場合のパス構築では、明確な「色の遷移」が発生します。 制限要因は最大分岐構造となり、全体的な答えは、エッジを個別の色領域に「分離」する数を制御することになります。これは、効果的に、除去によって形成されるフォレスト内のコンポーネントの数を増やすように動作します。$k-1$エッジ。 

これにより、問題は、エッジを切断したときにツリーがどのように分解されるか、および最悪のパスに沿って現れる「セグメント」の数を計算することに変換されます。 最終的な結果は、追加の色ごとに最悪の場合の個別の色を最大 1 ずつ増加させることができますが、それはツリーの直径構造によって決定される特定の飽和しきい値を超えた後でのみであるという事実によって決まります。 これにより、単調関数が得られます。$k$これは、分岐ノードの寄与に関するサブツリー DP から計算できます。 

最適なソリューションでは、ノードごとに強制的に通過できる「カラー セグメント」の数を計算し、グローバルに集計して各ノードの不都合を最小限に抑える DP を使用します。$k$。

 ## アルゴリズムのチュートリアル

 1. 任意のノード (便宜的にノード 1) でツリーをルートします。これにより、親子構造とサブツリーの寄与について推論できます。 
2. 各ノードについて、その次数を計算し、それを通過するパスが異なる子サブツリー間で切り替わることを観察します。 ノードでの潜在的なカラー遷移の数は、ノードを通過するパス上のエッジに寄与する個別のサブツリーの数によって制御されます。 
3. サブツリーのサイズと構造を計算して、すべてのノードについて、パスの色の多様性の増加に寄与できる「独立した分岐」がいくつあるかを理解します。 
4. 各ノードで、そのインシデント分岐を「分離」するために必要な追加の色の数を表す値を定義します。 これは事実上、ベースライン 1 を超える超過度数になります。これは、不便を増すことなく 1 つのブランチを 1 つのカラー フローにマージできるためです。 
5. これらの寄与をグローバルに合計して、一連のしきい値を取得します。 増えるたびに$k$, 効果的に、もう 1 つのエッジを独自の色コンポーネントに分離できるようになり、最も重要な分岐点での混雑が軽減されます。 
6. これらのしきい値を最終的な回答配列に変換します。 不都合は 1 から始まります$k=1$別の分岐制約を分離するのに十分な色が存在する場合にのみ増加します。 

### なぜ効果があるのか

 重要な不変条件は、不便を増すことなく、どの色も、各色が接続された部分グラフを誘発するものに変換できるということです。 色が接続されたコンポーネントになると、パスの不便さはまさにパスが通過する個別のカラーコンポーネントの数になります。これは、パスがエッジを横切る回数に相当し、エッジを削除するとコンポーネントの数が増加します。 

したがって、問題は、パスが交差するコンポーネントの数を制御することに帰着します。これは、エッジ除去によってツリーがどのように分割されるかによってのみ決まります。 DP は最小限の配布方法を捉えています。$k-1$パスに多くの分離されたセグメントが蓄積されないようにカットします。 ツリー パスは層状構造で重なり合うため、ローカル次数ベースの寄与が全体的な最適性を完全に決定します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        adj = [[] for _ in range(n)]
        for _ in range(n - 1):
            u, v = map(int, input().split())
            u -= 1
            v -= 1
            adj[u].append(v)
            adj[v].append(u)

        if n == 2:
            print()
            continue

        deg = [len(adj[i]) for i in range(n)]

        # core observation: contribution depends on branching excess
        excess = []
        for d in deg:
            if d > 1:
                excess.append(d - 1)

        excess.sort(reverse=True)

        # prefix sums simulate adding colors that resolve branching
        res = [0] * (n - 1)

        current = 1
        idx = 0

        for k in range(1, n):
            # each extra color can reduce one unit of excess
            if idx < len(excess):
                current += 1
                excess[idx] -= 1
                if excess[idx] == 0:
                    idx += 1
            res[k - 1] = current

        print(*res)

t = int(input())
solve()
```最終的な答えに影響を与える情報は分岐構造だけであるため、実装は隣接リストを構築し次数を計算することから始まります。 リーフはパス分岐の複雑さを増加させないため、無関係です。 

すべての次数の超過値を収集します。これは、単純なチェーン構造を超えて各ノードで強制的に追加の「分割」が何回行われるかを表します。 それらを並べ替えることで、最も重要な分岐制約を最初に解決するシミュレーションを行うことができます。 

それから繰り返します$k$、余分な分岐を減らすためにカラー容量を段階的に「消費」します。 各ステップは、競合の 1 単位を解決することによって達成可能な構造を増加させます。これは、最大の不便さを減らすことに相当します。 

結果の配列には、それぞれの最小の不都合が格納されます。$k$。

| ステップ | k | 過剰状態 | 現在の不都合 |

 これは、初期色では中央での分岐をすぐに解決できず、徐々に混雑を軽減するしかないことを示しています。 

このトレースは、高次のノードが初期の動作を支配し、追加の色が最初に消費されてその過剰な次数を中和することを示しています。 

### 例 2

| ステップ | k | 過剰状態 | 現在の不都合 |

 ここでは、すべてのノードの次数が最大 2 であるため、超過は最小限になります。 不便さはゆっくりと増加し、線形構造のみを反映します。 

これは、分岐がなければ、色を追加しても初期段階では複雑さがほとんど発生しないことを裏付けています。

 ## 特殊なケース

 パス状のツリーは、最も単純なエッジ ケースです。 すべてのノードの次数は最大 2 であるため、大きな超過に寄与するノードはありません。 アルゴリズムはこれを分岐能力がほとんどないものとして扱うため、不便さは徐々に増加します。$k$、長いチェーンのみがグローバルな色の蓄積を生み出すという直観と一致します。 

星型の木は逆の動作を示します。 1 つのノードに次数があります$n-1$、大きな超過価値を生み出します。 アルゴリズムは早期に消費します$k$これは、最も不便な点が多くのパスが交差する中心ノードに集中していることを正しく反映しています。 

1 つの高次ノードと多数の小さな分岐を含む混合ツリーでは、過剰なソートによって支配的なボトルネックが最初に正しく優先され、確実に改善されることが確認されています。$k$マイナーブランチに触れる前に、最も制限的な構造に即座に影響を与えます。
