 ## 解決策
 ## 問題の理解

 各試験は時間的に固定されたスロットを占有し、試験が重複することはありません。 各試験について、準備をしなかった場合は通常の終了時間のままにするか、事前に十分な学習時間を費やした場合は早く終了することができます。 

重要な点は、準備が単一の連続した間隔に関連付けられていないことです。 試験間の空き時間に勉強することはできますが、試験中は決して勉強することはできません。 試験が終了するまでに少なくとも必要な勉強時間を蓄積できれば、その試験の実際の終了時間が早くなり、次の試験が始まるまでの自由時間が増えます。 

課題は、利用可能なすべてのギャップに学習時間を配分した後、「準備済み」バージョンで終了する試験の数が最大になるように、どの試験を準備するかを決定することです。 

入力により、時間順に並べられた一連の検査が得られます。 各試験には開始時刻、準備されている場合は短縮された終了時刻、そうでない場合は通常の終了時刻、および短縮版を受験するために必要な学習時間があります。 試験が指定された順序で重複することはないため、自由時間の構造は、どの試験を短縮するかの選択によって完全に決まります。 

微妙な問題は、試験を準備することを選択すると、学習時間が消費されるだけでなく、試験がタイムラインに占める時間を短縮するため、将来の利用可能性も変更されることです。 この削減は後で使用できるようになるため、決定はグローバルに結合されます。 

最大 2000 件の試験では、3 次以上の戦略は実行不可能です。 準備された試験のすべてのサブセットを試すという単純な考えでは、指数関数的な結果が得られます。 サブセットに対する動的プログラミングさえ不可能です。 有効なソリューションでは、正確な履歴ではなく、使用可能な学習時間の蓄積のみを追跡するように状態を圧縮する必要があります。 

よくある失敗例は、準備を独立したものとして扱うことから生じます。 たとえば、各試験が以前の空き時間に AI を費やすだけであると仮定すると、試験の準備によって将来の自由時間が変化することは無視されます。 

次のシナリオを考えてみましょう。 

入力```
2
0 5 10 5
10 20 30 5
```両方を準備すると、両方の時間が短縮され、より多くの時間が生まれ、準備が容易になります。 「可能であれば今すぐ選ぶ」という貪欲なアプローチは、早期の決定が後の学習時間が存在するかどうかに影響を与えるため、失敗します。 

もう 1 つの落とし穴は、試験が始まる前にすべての勉強を完了しなければならないと想定していることです。 実際には、学習時間は以前のすべてのギャップにわたって蓄積される可能性があるため、状態は試験ごとのローカルではなく累積されます。 

## アプローチ

 強引なアプローチでは、試験のすべてのサブセットを準備しようとすることになります。 固定サブセットについては時間をシミュレーションし、ギャップにどれだけの学習が蓄積されているかを追跡し、選択した各試験を満足できるかどうかを確認します。 このシミュレーションは線形ですが、サブセットが 2ⁿ あるため、n が小さい場合でもこの方法は完全に実行不可能になります。 

この強引な方法が概念的に機能する理由は、準備された一連の試験が決定されると、タイムラインが決定的になるためです。 失敗は組み合わせ爆発です。試験ごとに可能性の数が 2 倍になります。 

重要な洞察は、どの試験が選択されたかを実際に覚えておく必要はなく、現在使用可能な学習時間の量と、ある試験から次の試験に移行する際にそれがどのように変化するかだけを覚えておく必要があるということです。 問題の構造により、状態が各試験境界における累積学習時間の量であり、遷移が現在の試験の準備またはスキップをシミュレートする動的プログラミングの解釈が可能になります。 

重要な観察は、関連するすべての時間変化は加算的であり、単一のスカラー リソースの変化として表現できるということです。 試験の準備にはこのリソースの ai 単位が消費されますが、試験が (ei − pi) だけ短縮されるため、将来の利用可能時間が増加します。 これにより、問題はアイテムがリソースを消費し生成するナップザックのような DP になります。 

n 個を超える試験を準備することはできないため、追跡される学習時間の上限を n に設定します。そのため、n 単位を超えるスラックがあっても、完了できる試験の数を数えるのには決して役に立ちません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース サブセット | O(2ⁿ・n) | O(n) | 遅すぎる |
 | 動的プログラミング | O(n²) | O(n²) | 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは試験を時系列順に処理し、各試験の直前に現在使用可能な学習時間を把握するための DP を維持します。 

各 DP 状態は、試験 i に到達した時点で利用可能な一定量の累積学習時間を前提として、最初の i 試験のうちすでに完全に準備できる試験の最大数を表します。 

1. 最初の試験の前に DP を初期化します。 この時点では、学習は蓄積されておらず、試験も完了していないため、唯一有効な状態は、準備された試験がゼロで、利用可能な学習時間がゼロであることです。 
2. 各試験について、まず、前の試験の終了と現在の試験の開始の間の時間ギャップを考慮します。 既存の DP 状態は、そのギャップに等しい追加の自由学習時間を獲得します。これは、学習が可能な中断のない時間であるためです。 
3. ギャップを組み込んだ後、試験 i の 2 つの選択肢を検討します。 1つ目は、準備をしないことです。 この場合、何も費やさないため、現在利用可能な学習時間を単に繰り越します。試験は終了時間いっぱいまで続き、それに応じて次のギャップに影響します。 
4. 2 番目の選択肢は、試験 i を準備することです。 これには、現在の状態に少なくとも ai 単位の利用可能な学習時間が必要です。 その場合、状態から ai を減算し、準備に成功した試験の数を 1 つ増やします。 
5. 試験 i を準備すると、試験は ei ではなく pi で終了するため、後で余分な自由時間が得られます。 この差 (ei − pi) は、次の試験が始まる前に使用できるようになるため、将来の移行のために利用可能な学習時間に追加されます。 
6. 両方の選択肢を評価した後、次の試験に進み、更新されたすべての DP 状態を繰り越し、利用可能な学習時間によって再びインデックス付けされます。

DP テーブルは、n 単位を超える空き時間を確保しても準備された試験の数を改善できないため、学習時間が n を超えないように切り捨てられます。 

### なぜ効果があるのか

 DP 状態は、試験の境界ごとに、今後の試験に再配分できる学習時間を正確に把握します。 利用可能な学習時間が同じになる 2 つの履歴は交換可能です。将来の決定は、学習時間がどのように取得されたかではなく、学習に費やすことができる量のみに依存するためです。 

この移行では、時間の節約が正しくモデル化されています。つまり、ギャップがあると使用可能な時間が追加され、準備がそれを消費し、準備が成功すると試験が短縮されて将来のさらなるギャップが生じます。 すべての変換は線形であり、隣接する検査に対してローカルであるため、履歴を単一のスカラー状態に圧縮しても隠れた依存関係が失われることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    exams = []
    for _ in range(n):
        s, p, e, a = map(int, input().split())
        exams.append((s, p, e, a))
    
    CAP = n
    
    dp = [-10**9] * (CAP + 1)
    dp[0] = 0
    
    prev_end = 0
    
    for i in range(n):
        s, p, e, a = exams[i]
        
        gap = s - prev_end
        
        ndp = [-10**9] * (CAP + 1)
        
        for t in range(CAP + 1):
            if dp[t] < 0:
                continue
            
            nt = t + gap
            if nt > CAP:
                nt = CAP
            
            best = dp[t]
            
            ndp[nt] = max(ndp[nt], best)
            
            if t >= a:
                nt2 = t - a + (e - p)
                nt2 += gap
                if nt2 > CAP:
                    nt2 = CAP
                ndp[nt2] = max(ndp[nt2], best + 1)
        
        dp = ndp
        prev_end = e
    
    print(max(dp))

if __name__ == "__main__":
    solve()
```DP 配列には、累積学習時間の可能な量ごとに、既に準備が完了した試験の最大数が格納されます。 重要な実装の詳細は、現在の試験にトランジションを適用する前に、まず試験間の時間ギャップを吸収することです。 

試験をスキップする場合、ギャップを追加する以外は状態を変更せずに引き継ぎます。 試験を準備する際には、十分な学習時間を確保し、それを差し引き、試験時間短縮による利益を加え、さらにギャップ寄与分も加えます。 最終的な答えは、到達可能なすべての DP 状態の中で最良の値です。 

よくある間違いは、両方の選択肢が次の試験の境界に達するため、両方の分岐にギャップを適用する必要があることを忘れることです。 もう 1 つは、複雑さを制限したままにする DP 状態の制限に失敗していることです。 

## 実用的な例

 最初のサンプルを考えてみましょう。```
3
10 20 30 5
30 50 100 15
100 101 200 50
```DP の状態を (study_time → best_count) として追跡します。 キートランジションのみが表示されます。 

最初のギャップが吸収された後は、限られた勉強しか存在しないため、早期の試験の準備は、早い時期から十分な余裕を蓄積することにかかっています。 

| ステップ | 試験 | 主要な DP 状態 (簡略化) |
 | --- | --- | --- |

 | 3 | (100,101,200,50) | 最終的な最高値が最大値に達する |

 このトレースは、早期の決定が、後の大規模な研究要件を満たすことができるかどうかをどのように決定するかを示しています。 

次に、より厳密なケースを考えてみましょう。```
2

 2 番目の試験は、最初の選択が十分な学習能力を維持し、相互依存性を示した場合にのみ実行可能になります。 

これらの例は、最適な選択が局所的な実現可能性ではなく、累積的な研究時間に依存することを強調しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n²) | 各試験は最大 n 個の DP 状態を処理します。 
| スペース | O(n) | サイズ n の 2 つの DP 配列だけが保持されます。 

二次境界は、n が 2000 までであれば十分であり、約 400 万回の状態遷移が得られ、一般的な制約内に快適に収まります。

 ## 特殊なケース

 重要なエッジケースは、ギャップが正確にゼロまたは非常に小さい場合に発生します。 このような状況では、外部の学習時間が発生しないため、実現可能性はすべて、過去の試験が準備されているかどうかに完全に依存します。 

例えば：```
2
0 1 2 2
2 3 4 2
```1次試験は時間の積み重ねが足りず準備ができず、2次試験も不可能になってしまいます。 DP は、完全に状態をゼロに正確に保ち、​​自由時間を生み出すことはありません。 

もう 1 つのエッジ ケースは、試験の準備に必要以上の時間がかかり、将来の決定を下すのに時間がかかる場合です。 DP は累積学習時間を n に制限し、過剰なスラックによって状態空間が膨張したり、同等の構成間に人為的な区別が生じたりしないようにします。 

これにより、10⁹ のような大きな値が入力に現れた場合でも、DP が安定し、制限されたままであることが保証されます。
