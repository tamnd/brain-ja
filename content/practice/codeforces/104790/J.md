 ## 問題の理解

 私たちに与えられたのは、根を張った木です。$n$頂点の番号付け$0$に$n-1$。 各エッジはノードをその親に接続するため、入力はルート構造を暗黙的に定義します。 すべての頂点は含めることも除外することもできますが、ツリー内の接続されたサブグラフを形成する頂点のサブセットのみに関心があります。つまり、選択されたすべての頂点は、元のツリーのエッジを使用して他の選択されたすべての頂点から到達可能でなければならず、選択された頂点は正確に一致する必要があります。$k$それぞれの数で$k$。 

あらゆるサイズに対応$k$から$1$に$n$、サイズの接続されたサブツリーの数を数える必要があります。$k$存在する。 ここでの接続されたサブツリーは、単にツリーの接続された誘導サブグラフです。 

制約$n \le 1000$すべてのサブセットにわたってクエリごとに二次関数を除外します。 すべてのサブセットの素朴な列挙は次のようになります。$2^n$、それは直ちに不可能です。 すべてのノードのペアを列挙して接続を拡張しようとしても、各拡張がツリーの大部分を繰り返し通過する可能性があるため、非常に時間がかかりすぎます。 

この問題の微妙な問題は、異なるサブセットの構造が大きく重複する可能性があるため、サブセットごとに接続性を最初から再計算すると、同じトラバーサル パターンを何度も繰り返すことになることです。 

構造を明らかにする小さなエッジケースは星型の木です。 ノード 0 が他のすべてのノードに接続されている場合、接続されているすべてのサブツリーにはノード 0 が含まれている必要があり、中心と結合されたリーフのサブセットはすべて有効です。 のために$k=1$、答えは$n$、ただし、より大きな場合は$k$、組み合わせになります。 単純な DFS ベースの列挙では、同一の構成が何度も過剰にカウントされたり、再計算されたりする可能性があります。 

もう 1 つのエッジ ケースはパス グラフです。 ここで、接続されたサブツリーはパスに沿った間隔に正確に対応します。 順序やサブツリー構造を暗黙的にキャプチャしないソリューションは、回避するのが困難になります。$O(n^3)$すべての間隔と接続性チェックの列挙。 

主要な問題は、ツリー内の接続が十分に制限されているため、サブセットは任意ではないものの、依然として多数であるため、直接列挙することが不可能であることです。 

## アプローチ

 ブルートフォースのアイデアは、頂点のすべてのサブセットを考慮することから始まります。 各サブセットについて、選択した頂点に制限された DFS または BFS を実行することで接続されているかどうかを確認し、そのサイズをカウントして、対応する回答を増分します。 これは、接続されたサブツリーの定義を直接検証するため、正しいです。 

このアプローチの問題は、サブセットの数です。$2^n$。 それぞれの接続チェックが線形であっても、全体の作業量は次のようになります。$O(n 2^n)$、これは実現不可能です$n = 1000$。 

各サブセットを個別に扱うことは避ける必要があります。 重要な観察は、ツリー内の接続性が固有の構造を暗示しているということです。接続されたサブセットにはサブセット内の最上位ノードという意味で固有の「ルート」があり、残りのノードはそのルート付きサブツリー構造内の接続されたコンポーネントを形成します。 これは、子の貢献を上方にマージすることで答えを構築する、根付いた DP を示唆しています。 

サブセットを列挙する代わりに、ノードごとに計算します。$u$多項式のような構造$dp_u[k]$、サイズの接続されたサブツリーの数を表します$k$のサブツリーに完全に含まれています$u$そして含まれます$u$。 接続されたすべてのサブツリーには最上位ノードが 1 つだけあり、そのルートに割り当てることで各サブツリーを 1 回だけカウントできるため、この制限は重要です。 

子をマージするときは、ナップザック スタイルの畳み込みを使用してサブツリー サイズの分布を結合します。子のサブツリーを取得しないか、接続されているサブツリーの 1 つを現在のコンポーネントに接続します。$u$。 これは、指数列挙を多項式マージ プロセスに変換するものです。 

ブルート フォースはすべてのサブセットを明示的にチェックするため機能しますが、同一のサブツリー計算を繰り返すため失敗します。 接続されたすべてのサブツリーに一意の最上位ノードがあるという観察により、グローバルなカウントをツリー構造に沿ったローカル DP マージに分解できます。

 ## アルゴリズムのチュートリアル

 ツリーをノード 0 にルートします。各ノードについて$u$、DP 配列を維持します$dp_u$どこ$dp_u[s]$サイズの接続されたサブツリーの数です$s$完全にサブツリー内にあるもの$u$含める必要があります$u$。 

1.初期化$dp_u[1] = 1$すべてのノードに対して$u$。 これは、以下のみから構成されるサブツリーを表します。$u$自体。 子を処理する前に他の構造が存在することはできません。 
2. ノードを事後順序で処理します。これにより、ノードのすべての子が$u$前にすでに処理されています$u$。 これにより、子 DP テーブルをマージするときに確実に準備が整います。 
3. それぞれの子どもたちに$v$の$u$、マージ$dp_v$の中へ$dp_u$。 新しい一時配列を作成します$ndp$、最初はコピー$dp_u$、子供を完全に無視するという選択を表します。 
4. あらゆるサイズに対応$i$で$dp_u$そしてあらゆるサイズ$j$で$dp_v$、更新します$ndp[i + j] += dp_u[i] \cdot dp_v[j]$。 これは、接続されたサブツリーを接続することに対応します。$v$に根ざした構造に$u$、より大きな接続されたサブツリーを形成します。 間のツリー エッジがあるため、接続は有効です。$u$そして$v$接続を保証します。 
5. すべての子を処理した後、次のように設定します。$dp_u = ndp$。 これにより、子の貢献度のすべての可能な組み合わせが累積されます。 
6. DP が終了したら、すべてのノードを合計します。$u$そして集めます$dp_u[k]$サイズの答えとしては$k$接続されたすべてのサブツリーはその最上位ノードで一意にカウントされるためです。 

過剰にカウントしない理由は、接続されたすべてのサブツリーがルート ツリー内に一意の最上位ノードを持っているためです。 そのノードはまさにサブツリーがその DP 状態に完全に含まれている場所であり、同じ構造の有効なルートとして別の DP に再び現れることはありません。 これにより、異なるノード間での重複が防止されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n = int(input())
    parent = [-1] * n
    g = [[] for _ in range(n)]

    for i in range(1, n):
        p = int(input())
        parent[i] = p
        g[p].append(i)

    dp = [None] * n

    sys.setrecursionlimit(10**7)

    def dfs(u):
        dp_u = [0] * (n + 1)
        dp_u[1] = 1

        for v in g[u]:
            dfs(v)
            dp_v = dp[v]

            ndp = dp_u[:]
            for i in range(1, n + 1):
                if dp_u[i] == 0:
                    continue
                for j in range(1, n + 1 - i):
                    if dp_v[j] == 0:
                        continue
                    ndp[i + j] = (ndp[i + j] + dp_u[i] * dp_v[j]) % MOD

            dp_u = ndp

        dp[u] = dp_u

    dfs(0)

    ans = [0] * (n + 1)
    for u in range(n):
        for k in range(1, n + 1):
            ans[k] = (ans[k] + dp[u][k]) % MOD

    print(*ans[1:])

if __name__ == "__main__":
    solve()
```実装は DP 定義に直接準拠します。 再帰により事後処理が確実に行われるため、マージ前に子が完全に計算されます。 ネストされたループは、合計サイズが決して超過しないように慎重に制限された親と子の DP 配列の間で畳み込みを実行します。$n$。 

実装の微妙な詳細は、新しいコピーを初期化することです`ndp = dp_u[:]`子供を統合する前に。 これにより、子からサブツリーを取得しないというオプションが保持されます。 これがないと、すべての子サブツリーから少なくとも 1 つのノードを誤って強制的に含めることになります。 

もう 1 つの重要な詳細は、内側のループを次のように制限することです。$j \le n - i$これにより、インデックスのオーバーフローや有効なサブツリー サイズを超える不必要な計算が防止されます。 

## 実用的な例

 ノード 0 に子 1 と 2 がある小さなツリーを考えてみましょう。 

### 例 1

 入力:```
3
0
0
```初期化により、各ノード dp[u][1] = 1 が与えられます。 

ノード 1 と 2 には子が存在しません。 

ノード 0 の場合、子 1 をマージすると dp_0[2] += 1 が生成され、子 2 をマージすると同様に dp_0[2] が生成されます。 最後に dp_0 = [0,1,2,0] となります。 

| ノード | dp[1] | dp[2] |
 | --- | --- | --- |
 | 1 | 1 | 0 |
 | 2 | 1 | 0 |
 | 0 | 1 | 2 |

 これは、サイズ 2 の 2 つの接続されたサブツリーがあり、それぞれがルートを持つ 1 つの葉を選択していることを示しています。 

### 例 2

 入力:```
4
0
1
1
```これにより、0-1-2-3 のチェーンが形成されます。 

ボトムアップ処理では、ノード 3 はサイズ 1 のみを提供します。ノード 2 はサイズ 1 と 2 を形成します。ノード 1 はサイズ 1、2、3 を形成します。 ノード 0 はこれらを再度結合します。 

| ノード | dp[1] | dp[2] | dp[3] | dp[4] |
 | --- | --- | --- | --- | --- |
 | 3 | 1 | 0 | 0 | 0 |
 | 2 | 1 | 1 | 0 | 0 |
 | 1 | 1 | 2 | 1 | 0 |
 | 0 | 1 | 3 | 3 | 1 |

 これにより、パス内では、接続されているすべてのサブツリーが連続セグメントに対応し、DP は明示的に列挙することなく、そのようなセグメントをすべて自然にカウントすることが確認されます。

## テストケース```python
import sys, io

MOD = 10**9 + 7

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from sys import stdin

    n = int(stdin.readline())
    g = [[] for _ in range(n)]
    for i in range(1, n):
        p = int(stdin.readline())
        g[p].append(i)

    dp = [None] * n

    def dfs(u):
        dp_u = [0] * (n + 1)
        dp_u[1] = 1
        for v in g[u]:
            dfs(v)
            dp_v = dp[v]
            ndp = dp_u[:]
            for i in range(1, n + 1):
                if dp_u[i] == 0:
                    continue
                for j in range(1, n + 1 - i):
                    if dp_v[j] == 0:
                        continue
                    ndp[i + j] = (ndp[i + j] + dp_u[i] * dp_v[j]) % MOD
            dp_u = ndp
        dp[u] = dp_u

    dfs(0)

    return " ".join(str(sum(dp[u][k] for u in range(n)) % MOD) for k in range(1, n + 1))

# sample-like test
assert run("3\n0\n0\n") == "3 2"

# chain test
assert run("4\n0\n1\n2\n") == "4 3 2 1"

# star test
assert run("4\n0\n0\n0\n") == "4 3 3 1"

 ## 特殊なケース

 単一ノード ツリーは初期化の正確さを明らかにします。 入力あり`1`の場合、DP はサイズ 1 のサブツリーを 1 つすぐに返す必要があります。子が存在することを前提とするマージ ロジックはここで失敗しますが、DP の初期化は失敗します。`dp[u][1] = 1`直接処理します。 

星型ツリーは、マージが独立した子からの組み合わせを適切に蓄積するかどうかをテストします。 各リーフは独立して寄与し、ルートは内部構造を混合することなく、異なるブランチからのサブセットを正しく結合する必要があります。 DP は、状態を上書きするのではなく、畳み込みを使用することでこれを保証します。 

ディープチェーンは、マージを繰り返してもアルゴリズムが正確さを維持するかどうかをテストします。 各ノードは以前の DP 状態を 1 レベルだけ拡張し、最終的な分布は連続するセグメント数と一致する必要があります。 すべてのプレフィックスが拡張前に完全に解決されるため、ポストオーダー トラバーサルでは正確さが保証されます。
