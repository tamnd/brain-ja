 ## 解決策
 ## 問題の理解

 新しい郡のすべての都市には同じ長さの名前が付いています。 郡の最終的な名前は一度に 1 文字ずつ選択されます。 各ポジションについて、各都市はそのポジションに表示される独自の名前の文字に投票します。 最も多くの票を獲得した文字が、郡名の対応する文字になります。 複数の文字が同じ最高得票数を獲得した場合、アルファベット順で最も小さい文字が選択されます。 

入力は、都市の数、各都市名の共通の長さ、そして名前自体で構成されます。 必要な出力は、すべての文字位置に投票ルールを個別に適用することによって生成される単一の名前です。 

制約はかなり小さいです。 都市名は最大 1000 個あり、それぞれの文字数は最大 1000 文字です。 これは、入力文字数が合計で最大 100 万文字であることを意味します。 各文字を 1 回または一定回数処理するアルゴリズムは、一般的なコンテストの制限内に簡単に収まります。 ここでは、考えられるすべての答えを求めてすべての文字列を繰り返し再スキャンするアルゴリズムはまだ許容されますが、直接カウントするソリューションが存在する場合、追加の作業を行う理由はありません。 

最初の明白ではないエッジケースは、複数の文字間の結合です。 インプットを考慮する```
2 1
b
a
```どちらの手紙も 1 票を受け取るため、正しい出力は次のようになります。```
a
```最初に発生した最大値を保持するだけの不注意な実装では、誤った出力が発生します。`b`。 

もう 1 つのケースは、すべての都市が同じ名前を持つ場合です。 例えば、```
3 4
code
code
code
```答えは次のとおりです。```
code
```すべての立場が満場一致で合意しているため、タイブレークのロジックが干渉することはありません。 

最後のケースは、すべてのポジションで勝者が異なる場合です。 例えば、```
3 3
abc
bbc
cac
```出力は```
abc
```各列は個別に処理する必要があります。 異なる位置からの情報を組み合わせると、間違った結果が生成されます。 

## アプローチ

 最も直接的な解決策は、各位置を個別に処理することです。 1 つの列について、すべての都市名の中で各文字が何回出現するかを数え、最も頻度が高い文字を選択します。 複数の文字が同じ頻度を持つ場合は、アルファベット順で最も小さい文字を選択します。 これをすべての位置に対して繰り返すと、必要な答えが得られます。 

このアプローチでは、各入力文字に対してパスが 1 回だけ実行されます。 文字数は最大で 100 万文字であるため、合計の作業は約 100 万回のカウント操作に加えて、すべての位置で 26 個の小文字をチェックすることになります。 それは簡単に十分に速いです。 

重要な観察は、すべての文字の位置が他のすべての位置から完全に独立しているということです。 最初の手紙の決定が 2 番目の手紙の決定に影響することはありません。 アルファベットには 26 個の小文字しか含まれていないため、各列のサイズ 26 の頻度配列を維持することは簡単かつ効率的です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 |---|---:|---:|---|
 | ブルートフォース | O(n × m × 26) | お(26) | 承認済み |
 | 最適 | O(n × m + 26 × m) | お(26) | 承認済み |

 アルファベットのサイズが一定であるため、両方の行の漸近的な複雑さは本質的に同じですが、頻度をカウントする定式化は自然で意図された解決策です。 

## アルゴリズムのチュートリアル

 1. の値を読み取ります。`n`そして`m`、すべての都市名を保存します。 

2. 最終的な郡名の文字を保持する空のリストを作成します。 

3. すべての文字位置について、`0`に`m - 1`、ゼロに初期化された長さ 26 の周波数配列を作成します。 

4. すべての都市名を訪問し、現在の位置に表示される文字に対応するカウンターをインクリメントします。 

各都市は現在の列に正確に 1 票を提供するため、このパスの後、頻度配列にはその位置の完全な選挙結果が含まれます。 

5. 26 個のカウンターをアルファベット順にスキャンし、最も頻繁に使用される文字を追跡します。 

スキャンはから実行されるため、`'a'`に`'z'`、厳密に大きい周波数が見つかった場合にのみ答えを更新すると、周波数が同点になるたびに自動的にアルファベット順の最小文字が保持されます。 

6. 選択した文字を回答に追加します。 

7. すべての位置が処理されたら、収集した文字を文字列に結合して印刷します。 

### なぜ効果があるのか

 アルゴリズムは、ポジションごとに、考えられるすべての手紙が受け取った票数を正確にカウントします。 これらの数は選挙の定義と正確に一致します。 最大数の文字を選択すると多数決の法則が満たされ、アルファベット順に文字をスキャンすると、最小の文字を優先して同点が解決されることが保証されます。 すべての位置が独立して処理されるため、構築された名前のすべての文字が正しくなり、出力全体が正しくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
names = [input().strip() for _ in range(n)]

answer = []

for col in range(m):
    freq = [0] * 26

    for name in names:
        freq[ord(name[col]) - ord('a')] += 1

    best = 0
    for i in range(1, 26):
        if freq[i] > freq[best]:
            best = i

    answer.append(chr(best + ord('a')))

print("".join(answer))
```プログラムは、すべての列に効率的にアクセスできるように、すべての都市名を読み取ることから始まります。 

列ごとに、小文字ごとに 1 つのエントリを含む新しい頻度配列が作成されます。 すべての都市は、適切なカウンターをインクリメントすることで 1 票を寄付します。 

変数`best`現在の当選レターのインデックスを保存します。 スキャンは次から始まります`'a'`第一候補としては。 比較には、`>`の代わりに`>=`。 この詳細がタイブレーク ルールを実装するものです。 2 つの文字の頻度が等しい場合、アルファベットの最初の文字が最初に出現したため、選択されたままになります。 

最後に、選択された文字が再び文字に変換されてリストに収集され、最終的な郡名に結合されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

## テストケース```python
import sys
import io

def solve():
    input = sys.stdin.readline

    n, m = map(int, input().split())
    names = [input().strip() for _ in range(n)]

    ans = []

    for col in range(m):
        freq = [0] * 26
        for name in names:
            freq[ord(name[col]) - ord('a')] += 1

        best = 0
        for i in range(1, 26):
            if freq[i] > freq[best]:
                best = i

        ans.append(chr(best + ord('a')))

    print("".join(ans))

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out

# provided samples
assert run("3 5\napple\nmaple\nalpha\n") == "aaple\n", "sample 1"
assert run("3 4\nicpc\nback\nlaps\n") == "bapc\n", "sample 2"

# minimum size
assert run("1 1\nz\n") == "z\n", "single city"

# tie breaking
assert run("2 1\nb\na\n") == "a\n", "alphabetical tie"

# all equal
assert run("3 3\ncat\ncat\ncat\n") == "cat\n", "identical names"

# different winners per column
assert run("3 3\nabc\nbbc\ncac\n") == "abc\n", "independent columns"
```| テスト入力 | 期待される出力 | 検証内容 |
 |---|---|---|
 | 1 つの文字で 1 つの都市 |`z`| 最小入力サイズ |
 | 二つの名前`b`そして`a`|`a`| アルファベット順のタイブレーク |
 | 3 つの同じ名前 | 同じ名前 | 全会一致の投票 |
 |`abc`、`bbc`、`cac`|`abc`| 各列は独立して処理されます。 

## 特殊なケース

 タイブレークの例を考えてみましょう。```
2 1
b
a
```唯一の列の周波数配列は次のようになります。`[1, 1, 0, ..., 0]`。 スキャンは次から始まります`'a'`現在の優勝者として。 いつ`'b'`を調べた場合、その頻度は大きいのではなく等しいため、勝者は変わりません。 出力は正しく行われています`a`。 

次に全会一致の投票について考えてみましょう。```
3 4
code
code
code
```各列には、異なる文字が 1 つだけ含まれます。 周波数配列にはそれぞれ 1 つの最大値があるため、選択された文字は次のようになります。`c`、`o`、`d`、 そして`e`。 アルゴリズムの出力`code`まさに予想通り。 

最後に、さまざまな列のさまざまな勝者を検討します。```
3 3
abc
bbc
cac
```最初の列には頻度が含まれます`{a:1, b:1, c:1}`、 それで`a`アルファベット順に勝ちます。 2 番目の列には、`b`2回登場して勝者となります。 3 番目の列には、`c`すべての名前で、満場一致になります。 このアルゴリズムは列間で情報を混合することはなく、正しい答えを生成します。`abc`。
