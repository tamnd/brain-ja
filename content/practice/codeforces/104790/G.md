 ## 解決策
 ## 問題の理解

 平面内に 4 つの点が与えられ、すでに時計回りの順序で配置されており、厳密に凸状の四角形を形成することが保証されています。 これらの点を順番に結んで形成される形状を分類し、サイクルを閉じることが私たちのタスクです。 

分類は階層的です。 四角形が正方形、長方形、ひし形、平行四辺形、台形、凧であるか、あるいはなしであるかを決定し、常に最も適合する最も具体的なものを出力する必要があります。 これは、形状が複数の定義を満たす場合、指定された順序で最も制限的なラベルを選択することを意味します。 

テスト ケースごとに四角形が 1 つしかないため、入力サイズの制約は緩いです。 これにより、定数時間のジオメトリ計算を超える前処理や漸近的な最適化の必要がなくなります。 本当の課題は、最大 10^9 の整数座標での幾何学的分類の正確さです。これは、浮動小数点エラーを回避し、二乗距離や外積などの整数演算に依存する必要があることを意味します。 

ポイントが凸状で順序付けられている場合でも、いくつかのエッジの状況が重要になります。 1 つ目は、平行四辺形と台形を区別することです。これは、どちらも並列性に依存しており、単純なチェックでは共有並列構造を誤って 2 回カウントする可能性があるためです。 2 つ目は、正方形、長方形、ひし形を区別することです。これは、すべて追加の制約が加えられた平行四辺形の特殊なケースであるためです。 3 番目は凧の検出です。これは、隣接する 2 つの等しい辺を持つ四角形と誤解されることがよくありますが、より強力な分類がすでに適用されている場合は、慎重に除外する必要があります。 

たとえば、(0,0)、(0,1)、(1,1)、(1,0) のような正方形は、技術的には複数の対称軸があるとしても、凧として分類されるべきではありません。正方形の方が制限が厳しいためです。 

もう 1 つの微妙なケースは、(1,1)、(2,3)、(4,5)、(3,3) など、長方形やひし形ではない一般的な平行四辺形で、向かい合う辺は平行ですが、角度と長さが異なります。 側面の等価性のみまたは傾斜だけをチェックする不注意な実装では、誤って分類されます。 

最後に、台形検出では、少なくとも 1 つではなく、1 組の平行な辺を正確に識別する必要があります。 平行四辺形にはそのようなペアが 2 つあり、台形として数えてはなりません。 

## アプローチ

 四角形を分類する強引な方法は、すべての定義をその幾何学的記述から直接明示的にテストすることです。 内積を使用してすべての角度条件を確認し、距離を使用してすべての辺の等式を確認し、外積を使用してすべての平行度条件を確認してから、各形状ルールを 1 つずつ評価できます。 

これは、各プロパティが第一原理、すなわち二乗距離による辺の等しさ、内積ゼロによる直角、外積ゼロによる平行度からチェックできるため、正しく機能します。 ただし、単純な構造は同じ量を繰り返し再計算する傾向があり、注意しないと浮動角推論が混入します。 さらに重要なことは、正規化を行わずに各定義を文字通りに解釈すると、特にカイト対称性の場合、冗長なチェックと脆弱なロジックが発生することです。 

重要な洞察は、すべての必要なプロパティが、再利用可能なプリミティブの小さなセット (エッジの長さの二乗、隣接するエッジ間の内積、および反対側のエッジ間の外積) に縮小されるということです。 4 つのエッジ ベクトルを計算すると、すべての分類条件はこれらのプリミティブの組み合わせになります。 これにより、一貫した数値安定性を保ちながら、すべての形状タイプを一定時間で評価できるようになります。 

幾何学的定義を個別に考えるのではなく、四角形をベクトルのサイクルとして扱い、その表現からすべてのプロパティを導き出します。

## アルゴリズムのチュートリアル

 点を順番に A、B、C、D とラベル付けします。 

### 1. エッジ ベクトルと辺の長さの二乗を計算します。 

ベクトル AB、BC、CD、DA を形成し、それらの二乗長を計算します。 二乗長は浮動小数点エラーを回避し、等価比較には十分です。 

### 2. 直角の内積を計算します。 

AB・BC、BC・CD、CD・DA、DA・ABを計算します。 ドット積ゼロは直角を示します。 

### 3. 並列処理のための外積を計算します。 

AB × CD と BC × DA を計算します。 ゼロクロス積は平行線を示します。 

### 4. チェックスクエア

 すべての辺が等しいこと、すべての角が直角であることを確認します。 これは、凸四角形の正方形を完全に特徴づけます。 

### 5. 四角形をチェックする

 すべての角度が直角であることを確認します。 辺の長さは等しい必要はありません。 

### 6.ひし形を確認する

 4 つの辺がすべて等しいことを確認します。 角度は凸面を超えて制限されません。 

### 7. 平行四辺形をチェックする

 対辺の両方のペアが平行であることを確認します。 

### 8. 台形をチェックする

 正確に 1 組の対辺が平行であることを確認します。 これには、2 つの並列チェックで XOR ロジックが必要です。 

### 9. チェックカイト

 AB が BC に等しく、CD が DA に等しいか、BC が CD に等しく、DA が AB に等しいことを検証します。 これは、隣接する等しい辺の 2 つのペアをエンコードします。 

### 10. それ以外の場合は何も出力しません

 ### なぜ効果があるのか

 すべての分類は、ユークリッド幾何学に基づく四角形の代数的不変量に帰着します。 辺の等しさは二乗距離で捉えられ、角度構造は内積で捉えられ、平行構造は外積で捉えられます。 すべての条件が同じ標準表現に基づいて評価されるため、幾何学的な曖昧さは残りません。 この階層により、複数のプロパティが保持される場合は常に、最も制限的なプロパティが最初に選択され、誤分類が防止されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def sq_dist(x1, y1, x2, y2):
    dx = x1 - x2
    dy = y1 - y2
    return dx * dx + dy * dy

def dot(ax, ay, bx, by):
    return ax * bx + ay * by

def cross(ax, ay, bx, by):
    return ax * by - ay * bx

x = []
y = []

for _ in range(4):
    xi, yi = map(int, input().split())
    x.append(xi)
    y.append(yi)

ax, ay = x[0], y[0]
bx, by = x[1], y[1]
cx, cy = x[2], y[2]
dx, dy = x[3], y[3]

AB = (bx - ax, by - ay)
BC = (cx - bx, cy - by)
CD = (dx - cx, dy - cy)
DA = (ax - dx, ay - dy)

s1 = sq_dist(ax, ay, bx, by)
s2 = sq_dist(bx, by, cx, cy)
s3 = sq_dist(cx, cy, dx, dy)
s4 = sq_dist(dx, dy, ax, ay)

right1 = dot(*AB, *BC) == 0
right2 = dot(*BC, *CD) == 0
right3 = dot(*CD, *DA) == 0
right4 = dot(*DA, *AB) == 0

par1 = cross(*AB, *CD) == 0
par2 = cross(*BC, *DA) == 0

if s1 == s2 == s3 == s4 and right1 and right2 and right3 and right4:
    print("square")
elif right1 and right2 and right3 and right4:
    print("rectangle")
elif s1 == s2 == s3 == s4:
    print("rhombus")
elif par1 and par2:
    print("parallelogram")
elif par1 ^ par2:
    print("trapezium")
else:
    kite1 = (s1 == s2 and s3 == s4)
    kite2 = (s2 == s3 and s4 == s1)
    if kite1 or kite2:
        print("kite")
    else:
        print("none")
```コードは最初にエッジ ベクトルを構築し、すべての幾何学的テストが単純な算術演算になるようにします。 精度の問題を避けるために、平方距離が一貫して使用されます。 チェックの順序は必要な階層に従い、より具体的な形状が一般化される前に検出されます。 

実装の微妙な詳細は、台形検出に XOR を使用することです。 平行四辺形は両方の並列チェックを満たすため、XOR によって確実に除外されます。 もう 1 つの重要な点は、より強力なクラスがすべて除外されるまで凧の検出が延期され、正方形やひし形の誤ったラベル付けが防止されることです。

 ## 特殊なケース

 重要なエッジケースは、四角形が正方形である場合です。 その状況では、技術的には凧対称性と菱形の特性も満たしますが、階層により最初に正方形が選択されます。 正方形の条件が他の条件よりも先にチェックされ、等しい辺と直角の両方を同時に必要とするため、アルゴリズムはこれを処理します。 

もう 1 つのエッジ ケースは、正方形ではない菱形です。 すべての辺は等しいですが、角度は 90 度ではありません。 このアルゴリズムは、内積がゼロでないため、長方形のチェックを正しくスキップし、平行四辺形に達する前に菱形として分類します。 

長方形または菱形ではない平行四辺形は、純粋に外積チェックを通じて処理されます。 反対側の辺の両方のペアが平行であるため、台形の XOR 条件は偽となり、隣接する等しい辺がないため凧条件は失敗し、正確に平行四辺形に分類されます。 

台形の場合は、ちょうど 1 組の対辺が平行である場合に発生します。 XOR 条件により、平行四辺形が誤って適格となることがなくなります。 これは、「並列ペアが存在するかどうか」だけをチェックする単純な実装における誤分類の最も一般的な原因です。
