 ## 解決策
 ## 問題の理解

 私たちには番号が与えられています$n$、これは、クローだけに頼った場合に、敵のロボットを完全に解体するために必要な単一ユニットのクロー操作の回数を表します。 それぞれの爪の操作で正確に 1 つの構造単位が削除されますが、ロボットは概念的には大きく、私たちが知っているのはその全体のサイズだけです。 

爪以外にも剣の施術もございます。 剣による切断では、材料が直接除去されるわけではありません。 代わりに、現在アクティブなロボットを 2 つの部分に分割し、モーターがちょうど半分の内側にあるため、そのうちの 1 つだけが動き続けます。 どの半分にモーターが含まれているかはわかりません。そのため、私たちの観点から見ると、最悪のケースは、より大きな、またはより問題のある半分が常に生き残ることです。 つまり、剣で一定の大きさの部分を切った後$x$、次の状態は事実上単一のサイズのセグメントです$\lceil x/2 \rceil$。 

目標はロボットを完全に破壊すること、つまりアクティブなセグメント サイズをゼロに減らすことです。 剣を切るたびにロボットが最悪の進化を遂げる場合の操作回数を最小限に抑えたいと考えています。 

微妙なのは、ランダム性を制御していないということです。 剣で斬られるたびに、私たちは生き残る側の悪い方に追い込まれるため、それぞれの決断はその結果に対して堅牢でなければなりません。 素朴な解釈では、楽観的な意味で剣の切断は常にサイズを半分に減らすものとして扱うかもしれませんが、ここでは天井の動作が重要であり、それが複雑になります。 

制約$n \le 10^{18}$以下の値に対する動的プログラミングは即座に除外されます。$n$、一次推論や二次推論ですら不可能です。 どのような解決策でも、問題のサイズを乗算的に小さくするか、対数時間で評価する閉再帰を使用する必要があります。 

よくある間違いは、剣を「ほぼ半分になるので常に爪で切るよりも優れている」と扱う場合に発生します。 これは、値が小さい場合には必ずしも当てはまりません。 たとえば、次のようなとき$n = 2$、剣は 1 に減少しますが、爪の効率と一致するもう 1 つのステップが必要です。 いつ$n = 1$、剣は何も役に立たず、爪は必須です。 この境界動作は、過度に貪欲な仮定を打ち破るものです。 

もう 1 つの落とし穴は、答えが次の値に比例すると仮定することです。$\log n$直接。 このシーケンスは、線形の爪が支配的であるか剣の使用と結びついている小さな接頭語の後でのみ対数的に動作し始めます。 

## アプローチ

 ブルート フォース戦略では、考えられるすべての操作シーケンスをシミュレートし、現在のセグメント サイズを維持し、各ステップで両方の選択肢を検討します。次のいずれかを適用します。$x \to x-1$、または剣の減少を適用します$x \to \lceil x/2 \rceil$。 これにより、州全体にわたる検索ツリーが形成されます。 結果をメモ化しても、状態空間は 1 から 1 までのすべての整数です。$n$、各状態は 2 つの遷移に依存します。 

単純な DP の再帰式は次のようになります。$$f(x) = 1 + \min(x-1, f(\lceil x/2 \rceil)).$$これを単純に評価するのは正しいですが、$x \le n$不可能なとき$n$到達する$10^{18}$。 

重要な観察は、一度爪の操作が完全に劣ってしまうということです。$x$半減を繰り返すと線形減少が急速に支配されるため、 は十分に大きいです。 しきい値が小さい場合、最適な戦略は常にソードを使用することです。これは、問題のサイズが指数関数的に縮小され、単一の追加ステップのオーバーヘッドが急速な縮小によって補われるためです。 

これにより、問題は再帰式を繰り返し適用することになります。$$f(x) = 1 + f(\lceil x/2 \rceil),$$直接値が既知である小さなベース領域に到達するまで。 これにより、プロセス全体が、小さな値を慎重に処理しながら、1 に達するまで天井半分を何回繰り返し取得できるかをカウントするだけになります。

 ## アルゴリズムのチュートリアル

 現在のサイズを縮小するために必要な最小操作数を計算したいと考えています。$n$から 0 まで、各ステップは 1 を引くか、数値を上限の半分に置き換えます。 

1. 現在のサイズについて観察することから始めます。$x$の場合、結果は 2 つの選択肢にのみ依存します。$x-1$、または次のように削減します$\lceil x/2 \rceil$。 答えは常に、これら 2 つの継続のうち良い方に 1 を加えたものになります。 
2. 関数を定義する$f(x)$一定のサイズのセグメントを破棄するために必要な最小限の操作として$x$。 のために$x = 0$、操作は必要ありません。 
3. のために$x = 1$、爪だけが意味があるので、$f(1) = 1$。 これにより、半分にすることが役に立たない基本的なケースが確立されます。 
4. のために$x > 1$、2 つの戦略を比較します。 爪はコストを与える$x$。 剣はコストを与える$1 + f(\lceil x/2 \rceil)$。 
5. それを一度観察してください$x \ge 4$、剣を繰り返し適用すると、状態が指数関数的に減少し、繰り返しの爪の線形コストが常に悪化するため、優勢になります。 
6. したがって、すべての意味のある大きな値に対して、漸化式を使用します。$f(x) = 1 + f(\lceil x/2 \rceil)$。 
7. この変換を次から繰り返し適用します。$n$、1に達するまで何回適用するかを数えます。 

なぜ効果があるのか

 核となる不変条件は、剣を操作するたびに問題が同じ形式の厳密に小さいインスタンスに縮小され、最適な決定構造が現在のサイズ以外の隠れた状態に依存しないことです。 再帰により、各ステップで大域的に最適な操作が選択されていることが保証されます。これは、最適性を高めることなく、その爪を後の剣に置き換えることによって、以前に爪を使用する代替シーケンスを少なくとも同じステップ数のシーケンスに変換できるためです。 問題は単一の決定論的な還元チェーンに崩壊します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    
    # base cases
    if n <= 1:
        print(1)
        return
    
    # f(1)=1, f(2)=2, f(3)=3 are special small values
    # but recurrence f(x)=1+f((x+1)//2) works for all x>=2
    res = 0
    x = n
    
    while x > 0:
        res += 1
        if x == 1:
            break
        x = (x + 1) // 2
    
    print(res)

if __name__ == "__main__":
    solve()
```この実装は、以前に導出された反復に直接続きます。 ループは変換を繰り返し適用します$x \to \lceil x/2 \rceil$として実装されています。$(x+1)//2$、歩数を数えながら。 各反復は、最適戦略の 1 つの操作に正確に対応します。 

微妙な点は、終了条件の処理です。 一度$x$が 1 になっても、それを破棄する最終操作がカウントされるため、ループによってこのステップが正しく含まれることが保証されます。

 ## 特殊なケース

 のために$n = 1$の場合、状態を半分にすることはできないため、アルゴリズムはすぐに 1 を返します。 繰り返しを適用しようとする場合は、必須の最終破棄ステップを考慮する必要があります。 

次のような小さな値の場合$n = 2$そして$n = 3$、再帰遷移は依然として正しいですが、漸近的な半減動作はまだ示されていません。 アルゴリズムは同じループを通じてそれらを均一に処理し、特別な大文字と小文字の間違いがないようにします。 

2 のべき乗をわずかに超える値の場合、たとえば$n = 2^k + 1$、天井分割により、最初のリダクションが完全なバイナリ分割のように動作しないことが保証されます。 の使用$(x+1)//2$はこの非対称性を正しく保存しており、トレースは逸脱することなく同じ決定論的な縮小シーケンスに従います。
