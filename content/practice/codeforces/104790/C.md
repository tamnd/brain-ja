 ## 解決策
 ## 問題の理解

 Unix のようなファイルシステムには、いくつかの絶対ファイル パスが与えられています。 ツリー内のどこにでも単一の作業ディレクトリを選択できますが、ファイル内では選択できません。 作業ディレクトリを選択したら、標準ルールを使用して、すべての絶対パスをそのディレクトリからの相対パスとして書き換える必要があります。一致するプレフィックス セグメントは省略され、残りの部分は上向きの移動を使用して表現されます。`..`その後に下向きのディレクトリ名が続きます。 

選択した作業ディレクトリのコストは、書き換えられたすべての相対パスにわたるパス コンポーネントの総数として定義されます。 コンポーネントはディレクトリ名または特殊記号のいずれかです`..`。 この総コストを最小限に抑える作業ディレクトリを選択する必要があります。 

各入力パスは、ルートから始まるディレクトリ名の絶対シーケンスです。 パスの数は最大 100,000 と多く、合計文字数は最大 100 万であるため、どのソリューションも入力サイズが基本的に線形になる必要があります。 

単純な間違いは、グローバル ルートまたはすべてのパスの最も深い共通プレフィックスで作業ディレクトリをルート化することが最適であると想定することです。 これは、最適なディレクトリはトレードオフに依存するため、失敗します。ルートをより深く移動すると、一部のパスの上向きの移動が減少し、他のパスの上向きの移動が増加します。 

2 番目の微妙な失敗モードは、作業ディレクトリが任意の文字列プレフィックスではなく、既存のディレクトリでなければならないということを無視したことに起因します。 パスの暗黙的なトライ内の実際のノードに対応するプレフィックスのみが有効な候補となります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 ファイルシステム内の考えられるすべてのディレクトリについて、そのディレクトリに対する相対的なすべてのパスを表現するための総コストを計算します。 候補ディレクトリを評価するには、ディレクトリとすべてのパスの間で最も長い共通プレフィックスを計算し、残りのコンポーネントの数と必要なコンポーネントの数を合計します。`..`動きます。 O(合計ノード) の候補ディレクトリがあり、各評価はすべてのパスに影響する可能性があるため、最悪の場合、これは実行可能な制限をはるかに超えて二次関数になります。 

重要な観察は、コスト関数がすべてのパスのトライのサブツリー構造にのみ依存する方法で書き換えられるということです。 すべての候補ルートを最初から再計算する代わりに、寄与を集約し、ツリー全体で効率的に答えを「再ルート」することができます。 

本質的な構造は、ディレクトリ ツリーの 1 つのエッジを越えて作業ディレクトリを移動すると、そのエッジを通過するパスのみが、予測可能な段階的な方法で相対表現を変更するということです。 これにより、最初に 1 つのルートの答えを計算し、その後、トライの再ルート動的プログラミング手法を使用して、その答えを隣接するルートに伝播することができます。 

まず、すべてのパスのトライを構築します。 次に、ルートが実際のファイルシステムのルートである場合のコストを、すべてのパスからの寄与を合計することによって計算します。 その後、サブツリー統計、つまり各サブツリーにパスの終端がいくつあるか、およびそれらの深さがどれくらいあるかを計算します。 これらを使用すると、エッジごとに O(1) の償却時間でルートをノードからその子に移動できます。

 ## アルゴリズムのチュートリアル

 パスのセットを、各ノードがディレクトリ プレフィックスに対応するトライとして扱います。 

### 1. すべてのパスのトライを構築する

 各パスをセグメントごとに挿入します。 すべてのノードはディレクトリを表し、パスが終了するノードをマークします。 これにより、すべてのプレフィックスにわたるツリー構造が得られます。 

すべての有効な作業ディレクトリはまさにこれらのノードの 1 つであるため、トライが必要です。 

### 2. サブツリーのメタデータを計算する

 すべてのノードに対して、ルートから DFS を実行して計算します。 

そのサブツリー内のパスのエンドポイントの数と、それらのエンドポイントの深さの合計。 

これらの値を使用すると、ノードの「下」にあるパスの数とそれらの距離をすぐに推論できます。 

### 3. ルートでの計算コスト

 作業ディレクトリがトライルートの場合、すべてのパスが完全な絶対パスとして出力されます。 コストは、コンポーネント内のすべてのパス長の単純な合計です。 

これは、DFS の蓄積中に 1 回計算されます。 

### 4. DP 移行を再ルートする

 ここで作業ディレクトリをノードから移動することを検討します。`u`その子の一人に`v`。 

のサブツリー内のパスのみ`v`それらの表現では先頭のディレクトリが 1 つ失われるため、ルートに近くなります。 他のすべてのパスは、必要な条件という点でさらに一歩遠ざかります。`..`コンポーネント。 

以下を使用してコストを更新します。 

サブツリー(v)内のパスの数と、その外側のパスの総数。 

これにより、親からの O(1) で各子の答えを計算できるようになります。 

### 5. グローバルミニマムを採用する

 リルート中にすべてのノードを評価し、コストを最小限に抑えます。 

### なぜ効果があるのか

 重要な不変条件は、どのノードでもコストをサブツリー内のパスとサブツリー外のパスからの寄与に分解できることです。 エッジを越えてルートを移動すると、それらのパスに追加のパスが必要かどうかが変わるだけです`..`または、先頭のディレクトリ セグメントが 1 つ少なくなります。 すべてのパスはリルート ステップごとに最大 1 つのエッジの影響を受けるため、遷移は線形かつ正確であり、完全なパスにわたる再計算は必要ありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

class Node:
    __slots__ = ("ch", "end", "sub", "dp")
    def __init__(self):
        self.ch = {}
        self.end = 0
        self.sub = 0
        self.dp = 0

root = Node()

def insert(path):
    cur = root
    parts = path.strip().split('/')[1:]
    for p in parts:
        if p not in cur.ch:
            cur.ch[p] = Node()
        cur = cur.ch[p]
    cur.end += 1

def dfs1(u, depth):
    u.sub = u.end
    u.dp = 0
    for v in u.ch.values():
        dfs1(v, depth + 1)
        u.sub += v.sub
        u.dp += v.dp + v.sub
    # u.dp counts total path length sum (in components) from this node as root

total_cost = 0
N = 0

def dfs_init(u, depth):
    global total_cost
    total_cost += u.end * depth
    for v in u.ch.values():
        dfs_init(v, depth + 1)

def dfs_reroot(u, parent_cost, total_paths, ans):
    ans[0] = min(ans[0], parent_cost)
    for v in u.ch.values():
        # move root from u to v
        outside = total_paths - v.sub
        inside = v.sub
        # when moving root down:
        # inside paths become 1 closer, outside become 1 farther
        child_cost = parent_cost + outside - inside
        dfs_reroot(v, child_cost, total_paths, ans)

for _ in range(int(input())):
    insert(input().strip())

# compute subtree sizes
def compute(u):
    u.sub = u.end
    for v in u.ch.values():
        compute(v)
        u.sub += v.sub

compute(root)

total_paths = root.sub

# initial cost: sum of full lengths
def init_cost(u, depth):
    res = u.end * depth
    for v in u.ch.values():
        res += init_cost(v, depth + 1)
    return res

start = init_cost(root, 0)

ans = [10**30]
dfs_reroot(root, start, total_paths, ans)

print(ans[0])
```トライ構造では、各パスが一連のノードに変換されるため、すべての候補作業ディレクトリがノードとして正確に表現されます。 サブツリーの計算では、各ノードの下にパス エンドポイントがいくつあるかが格納されます。これが、遷移に必要な唯一の量です。 

初期化ステップでは、作業ディレクトリがルートである場合のコストを計算します。つまり、各パスがその全長に寄与します。 

次に、reroot 関数はトライを通じてコストを伝播します。 ノードから子に移動すると、その子サブツリー内にないすべてのパスはさらに 1 つ上向きに移動しますが、内部のパスはプレフィックスが 1 ステップ失われます。 この違いは、サブツリー サイズを使用した単純な線形補正に集約されます。 

## 実用的な例

 単純化した構造を考えてみましょう。 

入力:```
/a/b
/a/c
/x
```トライを構築します。`/a`に分岐します`b`そして`c`、 そして`/x`は別です。 

| ステップ | ノード | サブツリーのサイズ | コスト |
 | --- | --- | --- | --- |
 | 初期化 | ルート | 3 | 5 |

 ルートでは、コストは全長です: 2 + 2 + 1 = 5。 

今すぐリルートしてください`/a`:

 | ステップ | 内部 (/サブツリー) | 外側 | コストの変化 | 新しいコスト |
 | --- | --- | --- | --- | --- |
 | ルート → a | に移動します。 2 | 1 | +1 -2 = -1 | 4 |

 それで`/a`コスト4が得られます。 

次にリルートします`/x`:

 | ステップ | 内部 (/x サブツリー) | 外側 | コストの変化 | 新しいコスト |
 | --- | --- | --- | --- | --- |
 | ルート → x に移動 | 1 | 2 | +2 -1 = +1 | 6 |

 それで`/x`コスト6が得られます。 

したがって、最良の答えはノードで 4 です。`/a`。 

これは、フルパスを再処理せずに、サブツリーのサイズだけで再ルートの効果がどのように決まるかを示しています。

 ## 特殊なケース

 微妙なケースとしては、すべてのパスが同一である場合があります。 トライは単一のチェーンに折りたたまれ、すべてのノードのサブツリー サイズはパスの合計と同じになります。 ルートを下に移動すると、内項と外項が予測可能な方法で相殺されるため、コストは常に線形に削減されます。 各遷移では正確なサブツリー数が使用されるため、過剰カウントは発生しないため、アルゴリズムはこれを処理します。 

もう 1 つのケースは、すべてのパスがルートで分岐する場合です。 すべての子サブツリーのサイズは 1 であるため、ルートをいずれかのブランチに移動すると、多くの外部パスに追加のパスが必要になるため、コストが増加します。`..`。 リルート式はこの非対称性を正しく反映しています。 

最後に、深くネストされた単一パス構造は、深さの累積が一貫しているかどうかをテストします。 各ノードのコストはサブツリーのサイズのみに依存し、パスの再構築には依存しないため、最大深さのチェーンであってもソリューションは安定したままになります。
