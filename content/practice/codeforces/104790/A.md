 ## 解決策
 ## 問題の理解

 ソフトウェア パッケージのコレクションが与えられ、それぞれのダウンロード サイズが既知です。 アップグレード プロセス中のある時点で、正確にいくつかのパッケージのダウンロードがすでに完全に完了している一方で、最大一定数のパッケージが同時にダウンロードされる可能性があることが観察されます。 ダウンロードは並列化されるため、最大でもいつでも`k`パッケージはアクティブにダウンロードされており、完了したパッケージはアクティブではなくなります。 

重要な点は、進行状況インジケーターが「完全にダウンロードされているが完了マークがまだ付いていない」と「まだ進行中」を完全に区別していないことです。そのため、観測時点では、一部のアクティブなダウンロードは、正式には完了していなくても、表示される進行状況にフルサイズで効果的に寄与する可能性があります。 

正確に観察した時点ですでに完了している可能性のある総ダウンロード サイズのうち、可能な最大の部分を計算するように求められます。`m`完成したパッケージ、最大でも`k`パッケージは同時にダウンロードされており、ダウンロードの順序はまったく不明です。 

言い換えれば、正確に条件が満たされている限り、どのパッケージが完了し、どのパッケージが現在ダウンロード中で、どのパッケージがまだ開始されていないのかを自由に選択できます。`m`終わっていて、せいぜい`k`活動中です。 完成したパッケージと現在進行中のパッケージ (ほぼ完成していると想定できる) の両方を含め、これまでにダウンロードされたデータの総量が最大になるような方法でこれを調整したいと考えています。 

入力サイズ`n`まで可能です`100000`したがって、ソートを伴うあらゆる解決策は実行可能ですが、二次関数や順列に対する繰り返しシミュレーションを伴うものは実行できません。 完成したパッケージと進行中のパッケージのすべてのサブセットを試すソリューションは、組み合わせが爆発的に増加するため、非常に遅くなります。 

微妙なエッジケースが現れるのは、`k`に比べて大きい`n`。 その場合、完成したパッケージを選択した後に残っているすべてのパッケージは引き続き進行中であると見なすことができます。つまり、基本的にすべてが進行状況の合計に寄与する可能性があります。 

もう 1 つの重要なケースは次のような場合です。`m = 0`。 それでは何も完全に終わったわけではなく、`k`パッケージは、進行中のダウンロードとしてフル サイズを提供できます。 

## アプローチ

 ブルートフォースアプローチでは、考えられるすべての選択方法をシミュレートしようとします。`m`完成したパッケージと最大`k`残りのアクティブなダウンロード。 構成ごとに、合計寄与サイズを計算し、最大値を追跡します。 これは原理的には正しいですが、完成したセットとアクティブなセットを選択する方法の数は組み合わせによるものであるため、完全に実行不可能です。`n`。 

重要な観察は、問題の構造が時間順序にまったく依存していないことです。 完全にカウントされたパッケージの数のみを考慮します (`m`) および進行中であるために完全に貢献できる追加パッケージの数 (`k`）。 これは、単にサイズのセットを選択しているだけであることを意味します`m + k`からの`n`観察された進捗に全面的に貢献するパッケージ。 

合計の進行状況を最大化するには、完成したセットと進行中のセットの両方で常に最大のパッケージを選択する必要があります。これは、どちらの場合も各パッケージがそのフル サイズに寄与するためです。 ペナルティや部分的なトレードオフはありません。選択されたすべてのパッケージが、パーセンテージの分子に独立して完全に寄与します。 

したがって、最適な戦略は、すべてのパッケージ サイズを降順に並べ替え、最大のパッケージ サイズを合計することになります。`m + k`価値観。 分母はすべてのパッケージ サイズの合計です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (完了したセットと進行中のセットを選択) | 指数 | O(n) | 遅すぎる |
 | 並べ替えてトップを取る`m + k`| O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 パッケージのサイズを配列に格納します。 

1. すべてのパッケージ サイズの合計を計算します。 これが最終的なパーセンテージの分母になります。 
2. 大きいパッケージが最初に考慮されるように、配列を降順に並べ替えます。 
3. 最初のものを取る`m + k`このソートされたリストの要素。 これらは、完了しているか、進行中であるが実質的に完了としてカウントされることによって、観察された進捗に完全に貢献できるパッケージの可能な限り最良の選択を表します。 
4. これらを合計します`m + k`要素を使用して、観測時に達成可能な最大ダウンロード サイズを取得します。 
5. この合計を合計で割り、100 を掛けてパーセンテージに変換します。 

ステップ 3 が有効である理由は、事後的にパッケージに役割を自由に割り当てることができるためです。`m`「終了」となり、次に大きいもの`k`「現在ダウンロード中ですが、事実上完全にカウントされています」になります。 

### なぜ効果があるのか

 まさに観測の瞬間に、`m`パッケージは完成した状態にあり、`k`アクティブにダウンロードすることができます。 すべてのアクティブなダウンロードは、そのフル サイズまで表示される進行状況に寄与する可能性があり、完成したパッケージも同様にフル サイズに寄与します。 

これは、カウントされる進行状況の合計が、純粋に最大までの選択によって決定されることを意味します。`m + k`フルサイズが合計に含まれるパッケージ。 どの特定のパッケージを完了する必要があるかという制約はなく、完了する必要があるパッケージの数だけであるため、役割の割り当ては有効です。 したがって、合計を最大化するとは、利用可能な最大のパッケージ サイズを選択することになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m, k = map(int, input().split())
sizes = list(map(int, input().split()))

total = sum(sizes)
sizes.sort(reverse=True)

take = min(n, m + k)
best = sum(sizes[:take])

print((best / total) * 100)
```このソリューションはまず入力を読み取り、すべてのパッケージの合計サイズを計算します。 次に、最も価値のある貢献を最初に貪欲に選択できるように、パッケージ サイズを降順に並べ替えます。 

変数`take`利用可能なパッケージの数を超えないようにします。`m + k > n`。 最終結果は浮動小数点パーセンテージとして計算されます。 必要な精度は Python の float 除算を使用するだけで十分です。`1e-4`。 

実装でよくある落とし穴は、クランプを忘れることです。`m + k`による`n`これにより、インデックス作成エラーや不正確な合計が発生する可能性があります。 もう 1 つの微妙な問題は整数の除算です。これはパーセンテージを計算するときに避けなければなりません。

## テストケース```python
import sys, io

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, m, k = map(int, input().split())
    a = list(map(int, input().split()))
    total = sum(a)
    a.sort(reverse=True)
    take = min(n, m + k)
    best = sum(a[:take])
    return str((best / total) * 100)

# provided samples (second sample)
assert abs(float(solve("5 0 4\n4 2 7 1 3\n")) - 94.117647059) < 1e-6

# custom: minimum case
assert solve("1 0 1\n5\n").startswith("100")

# all equal values
assert solve("4 2 2\n10 10 10 10\n").startswith("100")

# k = 0 case
assert solve("5 2 0\n1 2 3 4 5\n").startswith("60")

# m + k > n
assert solve("3 2 5\n1 2 3\n").startswith("100")
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1 0 1 / 5`|`100%`| 単一要素の正確性 |
 | すべて等しい |`100%`| 対称性と役割の割り当て |
 |`k = 0`| 部分和のみ | 進行中の貢献はありません |

 ## 特殊なケース

 いつ`m = 0`、アルゴリズムは最大のものを選択することになります。`k`パッケージ。 ソートされた選択は引き続き直接適用され、結果は単純に上位の合計になります。`k`合計を超えるサイズ。 

いつ`k = 0`、進行中の投稿は存在しないため、上位のみ`m`パッケージはカウントされます。 アルゴリズムはまだ機能します。`m + k = m`。 

いつ`m + k >= n`、すべてのパッケージが合計額に含まれるため、答えは常に次のようになります。`100%`。 クランプのステップにより、配列の境界を超えようとしないことが保証され、ロジックは自然に崩壊してすべてを合計します。
