 ## 解決策
 ## 問題の理解

 私たちに与えられたのは、$n$1 から 1 までのインデックスに従って並べられた王国$n$。 各王国には 2 つの数値属性があります。$a_i$そして$b_i$。 これらの属性は、2 つの王国が方向のない道路によって直接接続される幾何学的条件を定義します。 

どのペアでも$i < j$、指数の違いと属性の違いが 2 つの対称不等式系のいずれかを満たしている場合、道路は存在します。 1 つのシステムがいくらかを比較します$a$どれくらい減りますか$b$から移動するにつれて減少します$i$に$j$、もう1つは逆方向の同じ条件です。 概念的には、各ペアは実現可能性チェック、つまり間のセグメントを定義します。$i$そして$j$によって引き起こされる両方の勾配制約と一致する必要があります。$a$そして$b$、順方向または逆方向のいずれかです。 

これらの道路が確立されると、グラフの方向性がなくなり、形成される接続コンポーネントの数をカウントする必要があります。 

制約により、最大で$n = 10^6$これにより、すべてのペアを検査するソリューションが即座に除外されます。 エッジのみの二次構築には約$10^{12}$比較は、接続性を考慮する前にさえ実行不可能です。 

微妙な問題は、エッジが明らかな意味でローカルではないことです。 インデックスが遠く離れた 2 つの王国でも接続できるため、隣接するインデックスを比較するだけのアプローチや、1 次元の単調構造を仮定するアプローチは失敗します。 

よくある落とし穴は、状態を 2 つの独立したチェックに分離できるものとして扱うことです。$a$そして$b$。 たとえば、次の基準で並べ替えると誤って仮定する可能性があります。$a$または$b$隣接性が明らかになります。 これは当てはまりません。なぜなら、制約はインデックスの距離と属性の違いを結合しているからです。 

1 つのキーでソートした後、連続するインデックス間でのみ貪欲結合を試行すると、別の失敗モードが発生します。 たとえば、3 つのノードがある場合、$a$増えますが、$b$振動すると、ローカル接続はグローバル接続を反映しないため、推移性が失われます。 

## アプローチ

 ブルートフォース解釈は簡単です: すべてのペアを扱います$(i, j)$、条件をテストし、有効であればそれらを結合します。 これはグラフの定義を直接エンコードしているため、これは正しいです。 問題は規模だ。 と$n = 10^6$、これは大まかに確認する必要があります$n(n-1)/2$ペア、つまり約$5 \times 10^{11}$実行可能な限界をはるかに超えています。 

重要な観察は、条件が任意のペアごとのロジックではなく、単調構造によってエッジを順序付ける形式に書き換えることができる制約であるということです。 両方の不等式を拡張すると、各ノードをそのインデックスに対して 2 つの線形式を定義するものとして再解釈できます。 間の条件$i$そして$j$は、変換された点間の優劣関係と等価になります。 

このタイプの構造は通常、スイープ ラインまたは並べ替えベースの接続性の問題に陥ります。 エッジを明示的に構築する代わりに、接続の実現可能性を維持するソートされた順序でポイントを処理しながら、到達可能なノードのフロンティアを維持することを目指しています。 正しく順序付けされると、各ノードはアクティブな制約を表す少数の候補をチェックするだけで済み、結合検索構造を使用して接続を維持できます。 

この縮小により、密なグラフ定義が、各ノードが、変換されたキーの下での「可能な限り最良の先行者」である代表の限定されたセットと対話する構造に変わります。

 | ブルートフォース |$O(n^2)$|$O(n)$| 遅すぎる |
 | スイープ + ユニオン検索 |$O(n \log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 それぞれの王国を書き換える$i$制約を同等のスカラー キーに分割する変換された表現に変換されます。 重要なアイデアは、どのように捉えるかです。$a_i$そして$b_i$インデックスに対して相対的に動作する$i$, そのため、元の不等式は順序付き点の比較になります。 

### ステップ

 1. 各インデックスの 2 つの導出値を計算します。$i$、エンコード方法$a_i$そして$b_i$位置に関してシフトします。 これらの導出された値は、エッジ状態が単調になる変換された空間内の座標として機能します。 
2. 導出された座標の 1 つによってすべての王国を並べ替えます。通常は、実行可能な遷移の自然な順序に対応する座標です。 この順序により、接続が可能であれば、この並べ替えられた順序で近い要素間にのみ接続が表示されることが保証されます。 
3. 各王国が最初に独自のコンポーネントを形成するユニオン検索データ構造を維持します。 
4. ソートされた王国をくまなく調べ、到達可能なコンポーネントの候補代表を格納するデータ構造を維持します。 各王国について、変換された制約を使用して以前に確認された王国に接続できるかどうかを判断します。 
5. 有効な接続が見つかった場合は、現在の王国をその到達可能な構造の代表者と結合します。 Union-find は推移的であるため、繰り返される間接接続は自動的にマージされます。 
6. すべての王国が処理されるまで続行し、制約によって暗示されるすべての可能な接続が、変換された順序で 1 回だけ考慮されるようにします。 

### なぜ効果があるのか

 この変換により、有効なエッジがソートされたシーケンス内の一貫した順序に対応することが保証されます。 つまり、スイープ順序に違反する 2 つの要素を接続するエッジは存在しないため、2 番目のエンドポイントが処理されるときにすべての有効な接続が表示されます。 Union-Find 構造は、これらのローカル マージ間の接続を維持し、推移性により、コンポーネントが元のグラフの接続されたコンポーネントを正確に形成することが保証されます。 

重要な不変条件は、$k$ソート順の - 番目の要素、2 番目の端点が最初の端点内にあるすべてのエッジ$k$要素は完全に考慮されており、すべての接続は正しくマージされています。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return
        if self.size[ra] < self.size[rb]:
            ra, rb = rb, ra
        self.parent[rb] = ra
        self.size[ra] += self.size[rb]

def solve():
    n = int(input())
    a = []
    b = []
    for i in range(n):
        x, y = map(int, input().split())
        a.append(x)
        b.append(y)

    pts = list(range(n))

    pts.sort(key=lambda i: (a[i] - i, b[i] + i))

    dsu = DSU(n)

    stack = []

    for i in pts:
        while stack:
            j = stack[-1]
            # connectivity check derived from transformed constraints
            if a[i] - a[j] <= i - j and b[j] - b[i] <= j - i:
                dsu.union(i, j)
                break
            else:
                stack.pop()
        stack.append(i)

    comps = len({dsu.find(i) for i in range(n)})
    print(comps)

if __name__ == "__main__":
    solve()
```この解決策は、すべての属性を読み取り、それらをインデックスと一緒に保存することから始まります。 ソートステップでは変換されたキーを使用します$a[i] - i$そして$b[i] + i$、実行可能なエッジが並べ替えられた順序で隣接して整列するように、方向の傾き制約をエンコードします。 

スタックは、制約の下でも潜在的に接続可能な王国の候補チェーンを維持するために使用されます。 新しい王国を処理するときは、それを最新の有効な候補に接続しようとします。 制約が失敗した場合、ソートによって引き起こされる単調な順序付けの下では、その候補が後の要素との有効な将来の接続を形成できないため、スタックはポップされます。 

Union-find は、接続が確立されると、明示的にエッジを保存せずに接続がグローバルに追跡されることを保証します。

 ## 特殊なケース

 重大なエッジケースは、不平等が双方向で破綻するためにすべての王国が孤立する場合です。 このような場合、スタックは有効なユニオンを生成せず、DSU は完全に分割されたままとなり、次のような結果になります。$n$コンポーネント。 

別のエッジケースは、属性が複数の互いに素な単調チェーンを作成する場合に発生します。 ソートされた変換でも候補は正しくグループ化されますが、クロスチェーン結合は発生しないため、DSU は個別のコンポーネントを正しく保存します。 

最後に、不平等の中に平等が成立する場合には、慎重に対処する必要があります。 この条件では非厳密な不等式が使用されるため、正確な境界一致でもエッジが生成され、接続性をチェックするときに結合ステップで等価比較をスキップしてはなりません。
