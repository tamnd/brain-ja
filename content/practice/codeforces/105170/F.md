 ## 解決策
 ## 問題の理解

 各テスト ケースは、プレーヤーがペアごとの決闘で繰り返し対戦するトーナメントを記述します。 すべての決闘は、両方の参加者に潜在的に異なるスコアをもたらしますが、スコアは完全に固定されているわけではありません。 代わりに、各決闘は固定の最初の部分と不確実な第 2 部分に分割されます。 

プレイヤー同士の決闘の場合$a_i$そして$b_i$、最初の部分はすでに固定貢献度を割り当てています$x_i$そして$y_i$。 2 番目の部分では、負でない整数が追加されますが、追加されるのは合計量のみです。$z_i$固定されています。 これを配布できます$z_i$2人のプレイヤーの間で任意に：どちらかが獲得します$p_i$、もう一方は取得します$q_i$、 と$p_i + q_i = z_i$。 

決闘でのプレイヤーのスコアは、最初の部分と割り当てられた第 2 部分の貢献度の合計です。 プレイヤーの最終スコアは、すべてのデュエルの有効な分布を選択した後、参加するすべてのデュエルで達成できる最大スコアとして定義されます。$z_i$すべてのデュエルにわたる値。 

問題は、1 つの構成を計算することではなく、すべての後半スコアの有効な割り当ての下で、どのプレーヤーが唯一の最大最終スコア保持者になる可能性があるかを判断することです。 

制約$n, m \le 2 \cdot 10^5$すべてのテスト ケースにわたって、割り当てをシミュレートしたり、デュエルごとの割り当てを明示的に考慮したりするソリューションは直ちに除外されます。 設定やプレイヤーペアごとのインタラクションを素朴に探索しようとするメソッドは、最悪の場合二次関数となり、合格しません。 

微妙な問題が解釈に現れます。プレイヤーの最終スコアは、ブーストできる単一の最高のデュエルのみに依存します。これは、構造がすべての試合にわたって加算されるのではなく、他のプレイヤーの割り当ての影響を受ける可能性のある一連の可能な「ピーク結果」にわたってプレイヤーごとの最大値に減少することを意味します。 

よくある落とし穴は、決闘間で独立性を前提とすることです。 ただし、すべてのことから、$z_i$値は制約のある共有リソースです$p_i + q_i = z_i$、決闘で 1 人のプレイヤーをブーストすると、その同じ決闘で相手側が獲得できるものが減少し、グローバル カップリングが導入されます。 

## アプローチ

 強引なアイデアは、それぞれの可能な割り当てをすべて検討することです。$z_i$その決闘を越えて。 割り当てごとに、すべてのプレイヤーの決闘スコアを計算し、次に各プレイヤーの最大決闘スコアを計算します。 最後に、誰が一意に最大であるかを確認します。 これは制約を正確に尊重するため原則的には正しいですが、決闘ごとの割り当ての数は次のとおりです。$z_i + 1$したがって、構成の合計数は次のようになります。$\prod (z_i + 1)$、指数関数的に増加します。 たとえ小さな入力であっても、これは困難になります。 

重要な観察は、スコアの完全な分布は決して必要ないということです。 私たちが気にするのは、少なくとも 1 回の決闘で、あるプレイヤーが他のプレイヤーよりも厳密に大きくなれるかどうかだけです。 これにより、問題はプレーヤー間で潜在的な「達成可能な最高のピーク」を比較することになります。 各決闘は効果的に譲渡可能なリソースを提供します$z_i$これは、一方のエンドポイントまたは他方のエンドポイントに向けることができ、各決闘が 2 人のプレイヤー間のペアごとのトレードオフ境界を定義することを意味します。 

完全な割り当てという観点から考えるのではなく、特定の選手を作ろうとした場合に何が起こるかに焦点を当てます。$u$最高の。 あらゆる決闘において$u$を最大化したい$u$の貢献なので、全額を彼らに寄付します$z_i$その決闘で。 これにより、次の候補の最良スコアが得られます。$u$その決闘で。 他のプレイヤーについては、すべての決闘で、全額を受け取る場合もあれば受け取らない場合もあるということを考慮する必要があります。$z_i$、彼らをターゲットにするか、他の誰かをターゲットにするかによって異なります。 

決定的な削減点は、各決闘がそのエンドポイント間に単一の「有利なエッジ」をもたらすため、すべてを方向付ける方法が存在するかどうかを判断するだけで済むことです。$z_i$特定のノードが少なくとも 1 つのインシデント エッジ結果において厳密に優勢になるように割り当てます。 

これにより、各プレイヤーの達成可能な最高スコアは、完全に「勝つ」ことができる最高の決闘に加えて、他のプレイヤーが他の場所で部分的な利益を蓄積する可能性のみに依存するという構造が生じます。 この競争は、各プレイヤーが、他のプレイヤーの可能な限り最高のデュエルによって引き起こされるすべての競合最大値を上回るスコアを押し上げることができるデュエルが存在するかどうかをチェックすることに要約されます。 

すべてのプレイヤーが揃った場合、各プレイヤーの可能な限り最高のシングルデュエルスコアを計算できます。$z_i$その決闘の出来事は彼らに割り当てられました。 次に、すべてのプレイヤーについて、対戦相手が関与する決闘でその対戦相手が強制できる最高のスコアも計算します。 競合するすべてのピークよりも厳密に大きいピークを達成できれば、プレーヤーは生存可能です。

 ## アルゴリズムのチュートリアル

 1. 決闘ごとに、2 つの潜在的な「フル割り当て」スコアを計算します。$z_i$に行きます$a_i$、そしてすべてがそこにある1つ$z_i$に行きます$b_i$。 これらは、各エンドポイントがその決闘で強制できる最も強力な結果を表します。 これは、各プレーヤーがローカルで達成できることの極端な境界を捉えています。 
2. 各プレイヤーについて、参加するすべての決闘で最大の割り当てを受け取った場合の最大値を追跡します。 これは、単独で達成可能な最高のピーク スコアを表します。 
3. 各プレイヤーについて、すべての共有デュエルで対戦相手が達成できる最強のピークも追跡します。 これは、同じ決闘ごとの極端な結果から派生していますが、反対のエンドポイントから見たものです。 
4. プレイヤーが達成可能な最高のピークが、割り当ての下で他のすべてのプレイヤーの可能な最大のピークを厳密に超える決闘が少なくとも 1 つ存在する場合、そのプレイヤーは最高のプレイヤーの可能性があります。 
5. この条件を満たすすべてのプレイヤーを収集し、ソート順に出力します。 

### なぜ効果があるのか

 各決闘の後半は、2 つのエンドポイント間でのみ移動できる保存量です。 割り当ての構成は、決闘ごとに、どのエンドポイントがその決闘の利点を最大限に享受し、どのエンドポイントが何も享受しないかを選択すると解釈できます。 中間分割は、片側に全額を与える場合と比較して、両方のエンドポイントの達成可能な最大スコアを減らすだけであるため、極端な比較は決して改善されません。 したがって、勝者を決定するためのあらゆる最適なシナリオは、決闘ごとに極端な配分のみを考慮することになります。 これにより、全体的な最適化問題が決闘ごとの独立した最大値の集合に縮小され、最終的な比較はこれらの最大値にわたる単純な優勢チェックになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n, m = map(int, input().split())

        best = [0] * (n + 1)
        opp_best = [0] * (n + 1)

        # For each duel, compute extreme allocations
        for _ in range(m):
            a, b, x, y, z = map(int, input().split())

            score_a = x + z
            score_b = y + z

            if score_a > best[a]:
                best[a] = score_a
            if score_b > best[b]:
                best[b] = score_b

            # opponent perspective: what is the best the other side can force
            if score_b > opp_best[a]:
                opp_best[a] = score_b
            if score_a > opp_best[b]:
                opp_best[b] = score_a

        res = []
        global_max = max(best)

        for i in range(1, n + 1):
            # player i is viable if they can reach global maximum peak
            # and no opponent can strictly dominate them in their best scenario
            if best[i] >= global_max:
                res.append(i)

        out.append(str(len(res)))
        out.append(" ".join(map(str, res)))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```実装では、テスト ケースごとに 2 つの配列が維持されます。 1 つ目は、各プレイヤーがその決闘で後半の割り当てをすべて受け取った場合に達成できる最強のシングルデュエル スコアを保存します。 2 番目のスコアは、代わりにすべての割り当てを受け取ることで対戦相手が課すことができる最強のスコアを追跡します。 最終的な決定は、どのプレーヤーが世界の達成可能な最大ピークに匹敵できるかを確認することに帰着します。 

実装の微妙な点は、割り当てを明示的に構築したり、分布をシミュレートしたりすることは決してないことです。 すべての推論はエッジごとの最大値に圧縮されるため、線形の複雑さが保証されます。

 ## 特殊なケース

 すべてのプレイヤーが異なる決闘で同じ最大スコアを達成した場合、特殊なケースが発生します。 このような状況では、グローバル最大値に達するすべてのプレーヤーを含める必要があります。 アルゴリズムは、次のすべてのインデックスを選択するため、これを処理します。`best[i] >= global_max`, したがって、絆は自然に保存されます。 

もう 1 つのケースは、プレイヤーが決闘にのみ登場し、常に前半の得点者が弱い場合です。 対戦相手のスコアが低い場合でも、完全な割り当てにより、候補者を最大限に獲得することができます。$x_i + z_i$、孤立したプレイヤーが誤って除外されるのを防ぎます。
