 ## 問題の理解

 バイナリで書かれた非常に大きな整数が与えられています。`n`。 通常の方法で数値として解釈して 1 から 1 までループするのではなく、`n`、バイナリ表現を直接操作するように求められます。

したがって、問題は実際には数値を反復することではありません。 これは、バイナリ制限で定義された広大な範囲にわたってポップカウントの関数を集計することです。 

主な難点は、`n`最大 10^7 ビットを含めることができます。 これにより、値を最大で反復するアプローチは即座に除外されます。`n`、またはすべての中間整数を構築することもできます。 すべての数値を保存することさえ不可能です。 使用できる唯一の構造はバイナリ文字列そのものです。 

重要な観察は、次の値が`g(i)`どのビット位置が 1 として選択されるかによってのみ決まります。`i`。 したがって、問題は整数の個数を数えるということになります。`i ≤ n`まさに持っています`k`それぞれにビットを設定します`k`、そして合計します`f(k)`それらのカウントによって重み付けされます。

## アプローチ

 ブルートフォースアプローチの概念は単純です。 繰り返します`i`1から`n`、ポップカウントを計算し、そのカウントのフィボナッチ値を評価し、結果を累積します。 これは正しいですが、まったく実行不可能です。 O(1) でポップカウントを計算できたとしても、反復回数は次のとおりです。`n`、 そして`n`それ自体は最大 10^7 ビットの 2 進整数であるため、その大きさは天文学的に大きくなります。 

この故障は、ビット パターンではなく値を反復処理しているために発生します。 実際に必要な構造は数値順序ではなく、ビット位置のサブセットにわたる組み合わせ構造です。 

重要な洞察は、すべての数字について視点を切り替えることです`i ≤ n`結果の 2 進数が次の値を超えないようにビット位置のサブセットを選択することに対応します。`n`。 固定サブセットサイズの場合`k`、貢献度は`f(k)`サイズの有効なサブセットの数を乗算します。`k`。 

これにより、問題は、次のバイナリ表現に関する数値動的計画法の問題に変わります。`n`ここでは、指定された数の選択されたプレフィックスで有効な数値を生成するプレフィックスの数を数えます。

## アルゴリズムのチュートリアル

 バイナリ文字列を左から右に処理し、プレフィックス以下の数値をいくつ形成できるかをカウントします。`n`。 

1. フィボナッチ値を最大で事前計算します。`L`、任意の数値のポップカウントは最大でも`L`ビット数を超えることはできません`L`。 これにより、1 のカウントを即座にそのフィボナッチ値にマッピングできるようになります。 
2. DP テーブルを設定します。`dp[tight][k]`は、処理された接頭辞を使用して数値を形成できる方法が何通りあるかを表します。`k`これまでに選ばれたものと、`tight`の接頭辞が依然として正確に一致しているかどうかを示します`n`。 
3.初期化`dp[1][0] = 1`つまり、ビットを処理する前に、プレフィックスに一致する空の構造が 1 つだけ存在することになります。 
4. バイナリ文字列の各ビットについて`n`、DP を更新します。 

現在の位置に 0 または 1 を配置することを検討しますが、タイトな状態にある場合は、プレフィックスによって課される制約を尊重する必要があります。 現在のビットの場合、`n`が 0 の場合、1 をタイトな状態に置くことはできません。 1 の場合、両方の選択肢が可能ですが、1 を選択すると、完全に一致するかどうかに応じて、引き続きタイトな状態が維持されるか、タイトな状態が壊れる可能性があります。 
5. 各トランジションでは、選択されたトランジションの数も更新され、増加します。`k`1 を置いたとき。 
6. すべてのビットを処理した後、ポップカウントによってグループ化された有効な数値のカウントが得られ、タイトな状態と非タイトな状態の両方にわたって蓄積されます。 
7. 合計して最終的な答えを計算します。`dp[0][k] + dp[1][k]`乗算`f(k)`全体`k`。 

### なぜ効果があるのか

 すべての整数`i ≤ n`この数字 DP の 1 つの有効なパスに正確に対応します。`i`マッチ`n`これまでに、またはすでに小さくなり、使用した数を追跡します。 厳しい制約により、決して超えないことが保証されます`n`、状態分割により、有効な数値がそれぞれ 1 回だけカウントされることが保証されます。 ポップカウントは選択されたものの数によって完全にキャプチャされるため、次のようにグループ化します。`k`で十分であり、最終的な合計は範囲内のすべての整数の寄与を正しく集計します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

s = input().strip()
L = len(s)

# Fibonacci up to L
fib = [0] * (L + 2)
fib[1] = 1
for i in range(2, L + 2):
    fib[i] = (fib[i - 1] + fib[i - 2]) % MOD

# dp[tight][k]
# tight = 0 or 1
dp0 = [0] * (L + 1)
dp1 = [0] * (L + 1)

dp1[0] = 1  # start tight, 0 ones used

for ch in s:
    bit = int(ch)
    ndp0 = [0] * (L + 1)
    ndp1 = [0] * (L + 1)

    for k in range(L + 1):
        val1 = dp1[k]
        if val1:
            # place 0
            if bit == 1:
                ndp0[k] = (ndp0[k] + val1) % MOD
            else:
                ndp1[k] = (ndp1[k] + val1) % MOD

            # place 1
            nk = k + 1
            if nk <= L:
                if bit == 1:
                    ndp1[nk] = (ndp1[nk] + val1) % MOD
                # if bit == 0, cannot place 1 in tight state

        val0 = dp0[k]
        if val0:
            # already smaller, can place freely
            ndp0[k] = (ndp0[k] + val0) % MOD
            ndp0[k + 1] = (ndp0[k + 1] + val0) % MOD if k + 1 <= L else ndp0[k + 1]

    dp0, dp1 = ndp0, ndp1

ans = 0
for k in range(L + 1):
    cnt = (dp0[k] + dp1[k]) % MOD
    ans = (ans + cnt * fib[k]) % MOD

print(ans)
