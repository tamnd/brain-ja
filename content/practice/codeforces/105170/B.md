 ## 解決策
 ## 問題の理解

 各頂点が値を持つルート付きツリーが与えられます。 ルートから開始して深さ優先の走査を実行しますが、任意のノードの子にアクセスする順序は完全に柔軟です。 これは、固定の DFS 順序が与えられていないことを意味します。 代わりに、すべてのノードで子の順列を選択し、結果として得られる頂点の事前順序シーケンスを変更できます。 

DFS プレオーダー シーケンスが生成されると、そのシーケンス内の偶数の位置に現れる頂点の値を合計することによって評価されます。インデックス付けは 1 から始まります。したがって、2 番目、4 番目、6 番目などの要素のみがスコアに寄与します。 

タスクは、このスコアが最大化されるように、すべてのノードで子の順序を選択することです。 

この制約は、すべてのテスト ケースにわたるノードの合計数が最大 2 × 10^5 であることを意味します。 これにより、子のすべての順列を試行したり、DFS 順序を明示的にシミュレートしたりするソリューションは即座に除外されます。 すべての並べ替えをローカルで処理する場合でも、最悪の場合は指数関数的になるため、解決策は列挙ではなく DFS トラバーサルの構造的特性に依存する必要があります。 

この問題の微妙な問題は、DFS 順序におけるノードの位置パリティがローカルに固定されていないことです。 サブツリーを走査するとき、その内部のすべてのノードは事前順序シーケンスのグローバル インデックスを継承し、それが寄与するかどうかは、その前に訪問されたノードの数によって決まります。 これにより、兄弟サブツリー間に依存関係が作成されます。2 つのサブツリーを交換すると、内部の順序だけでなく、その後に続くすべてのパリティの配置も変更されます。 

素朴な推論の小さな失敗例は、2 つの子を持つルートです。1 つはサイズ 1 のサブツリー、もう 1 つはサイズ 2 です。どちらのサブツリーが最初にアクセスされるかに応じて、2 番目のサブツリー内の位置のパリティが反転し、寄与するノードが変わります。 サブツリーを独立して扱う貪欲なアプローチは、このパリティ シフトを無視するため、ここでは失敗します。 

## アプローチ

 ブルート フォース アプローチでは、すべてのノードで子の考えられるすべての順列を列挙し、その結果の DFS オーダーを生成し、スコアを計算します。 次数 d のノードであっても、これには d! が関係します。 各順序付けはすべての子孫 DFS トラバーサルに影響を与えるため、作業量の合計はツリー全体で乗算的に爆発的に増加します。 星型ツリーでは、これはすでに n の階乗になっており、実行不可能です。 

重要な点は、DFS 事前順序付けでは、サブツリーに対応する連続したセグメントが連結されるということです。 各サブツリーは、自身の子の順序が選択されると内部構造が固定されるブロックに寄与しますが、グローバル シーケンス内でのそのブロックの配置によって、そのルートが偶数位置で始まるか奇数位置で始まるかが決まります。 開始パリティが判明すると、サブツリー内のすべてのノードは決定的なパリティ パターンを持ちます。 

これは動的プログラミングの定式化を示唆しています。サブツリーごとに、そのルートが奇数の位置から始まる場合と偶数の位置から始まる場合に、そのサブツリーがどの程度の値に寄与するかを計算します。 難しいのは、子を結合する場合、各子の開始パリティが以前に処理された子のサイズに依存するため、子を処理する順序が重要になることです。 

これにより、各項目が 1 つのサイズと、現在のパリティに応じて 2 つの考えられる寄与を持つ「項目」(子サブツリー) の順序付けの問題が軽減されます。 さらに、サブツリーのサイズが奇数の場合、処理後にパリティ状態が反転するため、順序付けと将来の決定の間にカップリングが生じます。 この構造では、偶数パリティで開始する場合と奇数パリティで開始する場合のゲイン差の比較に基づいて貪欲な順序付けが可能になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | O(n) | 遅すぎる |
 | ツリー DP + 貪欲な順序付け | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

ツリーを 1 にルートし、事後走査を実行します。 

各ノードについて、2 つの情報を計算します。 まず、サブツリーのサイズです。 2 つ目は 2 つの DP 値です。ノードがグローバル DFS 順序の奇数の位置に入力された場合のサブツリーの可能な限り最良の寄与、およびノー​​ドが偶数の位置に入力された場合の可能な最良の寄与です。 

1. 各リーフ ノードについて、サブツリーはそれ自体のみで構成されます。 変な位置に入力しても何も影響しません。 偶数の位置に入力すると、それ自体の値が寄与します。 サブツリーのサイズは 1 です。 
2. 内部ノードの場合、最初にすべての子に対してこれらの DP 値を再帰的に計算します。 この時点で、各子はどちらかのパリティで入力できる「ブロック」のように動作し、結果とそのサブツリー サイズの両方がわかります。 
3. ここで、子を現在のノードの下の DFS 順序を表す単一のシーケンスにマージする必要があります。 ノード自体が最初に配置されるため、常に現在のグローバル パリティでアクセスされます。 
4. 次に訪問するノードが奇数の DFS 位置にあるか偶数の DFS 位置にあるかを表す実行パリティ状態を維持します。 最初に、現在のノードにアクセスした後、1 つの位置を消費したため、パリティが反転します。 
5. その後、各子サブツリーが何らかの順序で追加されます。 子が処理されるとき、現在のパリティが偶数であれば、子の「偶数エントリ」DP 値が取得されます。 それ以外の場合は、その「奇数エントリ」の DP 値を取得します。 子の処理後、奇数長のブロックは後続の位置の位置合わせを変更するため、その子のサブツリーのサイズが奇数である場合に限り、パリティが反転します。 
6. 私たちに与えられた唯一の自由は、子供たちを選ぶ順序です。 これを決定するために、偶数パリティで入力された場合と奇数パリティで入力された場合の寄与の差を使用して子を比較します。 偶数エントリーでより大きなアドバンテージを持つ子は、早期に優先順位を付ける必要があります。これは、フリップが蓄積される前に、早期の配置が影響の大きいパリティ状態に影響を与えることが多いためです。 
7. この差の降順に子を並べ替え、その順序でマージ プロセスをシミュレートし、最良の寄与を累積します。 

すべてのノードをボトムアップで処理した後、奇数の位置に入力されたルートの答えが最終結果になります。 

### なぜ効果があるのか

 各サブツリーは、固定数の DFS 位置を消費し、そのサイズに応じてパリティ フリップを引き起こすセグメントのように動作します。 DP は、固定エントリ パリティについて、サブツリーがすでに内部的に最適であることを保証します。 残る自由はセグメントの順序だけです。 貪欲な順序付けが機能するのは、サブツリーを早めに配置する場合と遅く配置する場合の寄与の差は、各パリティ状態で評価される頻度のみに依存し、この効果は 2 つの DP 状態の差に関して単調であるためです。 パリティ フリップはサブツリーのサイズのみに依存し、内部構造には依存しないため、各サブツリーは署名された優先順位を持つアトミック ブロックとして扱うことができ、ソート引数が有効になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    g = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    parent = [-1] * n
    order = []
    stack = [0]
    parent[0] = -2

    while stack:
        x = stack.pop()
        order.append(x)
        for y in g[x]:
            if parent[y] == -1:
                parent[y] = x
                stack.append(y)

    children = [[] for _ in range(n)]
    for v in order[1:]:
        children[parent[v]].append(v)

    dp0 = [0] * n
    dp1 = [0] * n
    sz = [1] * n

    for x in reversed(order):
        best0 = 0
        best1 = a[x]  # if x starts at even position, contributes
        size = 1

        info = []

        for y in children[x]:
            info.append(y)

        def key(y):
            return dp1[y] - dp0[y]

        info.sort(key=key, reverse=True)

        cur_parity = 0  # 0 means next node is odd position (since x itself handled outside)
        for y in info:
            if cur_parity == 0:
                best0 += dp0[y]
                best1 += dp0[y]
            else:
                best0 += dp1[y]
                best1 += dp1[y]

            if sz[y] % 2 == 1:
                cur_parity ^= 1

            size += sz[y]

        sz[x] = size
        dp0[x] = best0
        dp1[x] = best1

    print(dp0[0])

t = int(input())
for _ in range(t):
    solve()
```このソリューションでは、明示的なルート ツリーを構築し、逆の DFS 順序でノードを処理して、すべてのサブツリーがその親の前に計算されるようにします。 各ノードはサブツリー サイズと 2 つの DP 値を維持します。 マージ ステップでは、エントリ パリティが偶数である場合と奇数である場合に子がどの程度適切に動作するかに基づいて、子の貪欲な順序付けが使用されます。 最終的な答えは、ルートが奇数の DFS 位置に入力されたときの DP 値であり、実際のトラバース開始に対応します。 

マージ中のパリティ追跡には注意が必要です。 次のサブツリーが偶数位置に入るのか奇数位置に入るのかを追跡する変数は、奇数長のセグメントのみが後続のセグメントのパリティ アライメントを反転するため、子サブツリーのサイズが奇数の場合にのみ反転する必要があります。 

## 実用的な例

 ### 例 1

 値 3 を持つ 1 つのリーフ A と値 5 を持つ 1 つのリーフ B という 2 つの子を持つルートを考えます。 

| ステップ | ノード | エントリーパリティ | 貢献 | メモ |
 | --- | --- | --- | --- | --- |
 | 1 | あ | 偶数 | 3 | 葉が貢献します |
 | 2 | B | 奇数 | 0 | 葉がスキップされました | 写真 葉がスキップされました
 | 3 | ルート | 奇数 | 0 | ルートはカウントされません |

 順序を入れ替えると:

 | ステップ | ノード | エントリーパリティ | 貢献 | メモ |

 | 2 | あ | 奇数 | 0 | スキップしました |

 これは、順序付けによってどのサブツリーが偶数の位置に配置されるかが直接変化することを示しています。 

### 例 2

 値 [1,2,3,4] を持つチェーン状のツリー 1 → 2 → 3 → 4。 

| ノード | サブツリーのサイズ | dp0 | dp1 |

 | 3 | 2 | 4 | 4 |
 | 2 | 3 | 4 | 6 |
 | 1 | 4 | 6 | 6 |

 これは、パリティの伝播が単一のパスに沿ってどのように蓄積されるか、およびアライメントのシフトに応じて偶数の位置がどのように値を収集するかを示しています。

 ## 特殊なケース

 ルートが位置 1 (奇数) で訪問されるため、単一ノード ツリーは常に寄与ゼロになります。そのため、値はカウントされません。 DP は dp1 をノード値として正しく初期化しますが、ルートには dp0 を返し、結果はゼロになります。 

2 ノード ツリーでは、サブツリーが 1 つしかないため、順序は無関係です。 2 番目のノードは常に位置 2 にあるため、その値は常にカウントされます。 子サブツリーが偶数エントリ パリティの下でその値を提供するため、DP はこれを正しく反映します。 

星型ツリーでは、リーフ処理の順序によって、パリティ フリップが発生する前に偶数の位置に落ち込むリーフの数が決まります。 dp1 から dp0 を引いたものに基づく貪欲な順序付けにより、均等なエントリーがより早く配置されることでより多くの恩恵を受けるリーフが確保され、合計ゲインが最大化されます。
