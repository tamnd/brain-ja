 ## 解決策
 ## 問題の理解

 n 個のノードを持つツリーが与えられます。 各ノード i は初期エネルギー値 bi で始まり、「成長率」ai も持ちます。 x 日後、何も変化がなければ、ノード i の値は bi + x・ai になります。 

時系列順に 2 種類の操作が発生し、各操作には増加するだけの時間 x がタグ付けされています。 

最初の操作では、単一のエッジに沿った成長率を変更します。 エッジ (u, v) を選択すると、au が w だけ減少し、av が w だけ増加します。 これにより、すべての ai の合計は変更されませんが、隣接するノード間で増加が再分配されます。 

2 番目の操作では、時刻 x におけるグローバル最適化問題が要求されます。 ノード r をソースとして選択し、dist(u, r) のすべてのノード u の合計に u での現在値を乗じたものとしてコストを定義する必要があります。ここで、現在の値は初期エネルギーと時間 x での累積成長の両方に依存します。 目標は、r の選択にかかるコストを最小限に抑えることです。 

したがって、各クエリはツリー上の重み付き 1 中央値を要求しますが、重みは静的ではありません。 これらは、直線的な成長とエッジに沿った成長率の局所的な移動を通じて時間の経過とともに変化します。 

100000 までの制約 n、k は、演算ごとにあらゆる解を線形または対数線形に近づけます。 距離を再計算したり、クエリごとに目標を最初から再評価したりするものは、すぐに遅すぎます。1 つのルートのコストを 1 回評価するだけですでに O(n) のコストがかかり、クエリが 100,000 個も存在する可能性があるからです。 

微妙な問題は、ノードの重みが固定値ではないという事実から生じます。 これらは時間 x の関数であり、さらにこれらの関数の係数は更新中に変化します。 単純な間違いは、各クエリ中に重みを静的として扱ったり、bi のみを更新して AI の進化を無視したりすることです。 もう 1 つの一般的な落とし穴は、すべての候補ルートのすべての距離をクエリごとに個別に再計算することであり、これが O(n^2) にまで増大します。 

単純な再計算の小さな失敗例としては、各クエリがすべてのルートを試行し、すべての距離を再計算する星型ツリーがあります。 n = 200000 の場合でも、これは直ちに実行不可能になります。 

## アプローチ

 ブルート フォース戦略では、各クエリを個別に処理します。 時間 x でのクエリの場合、各ノードの現在の重みを bi + x・ai として計算し、次に考えられるすべてのルート r に対して dist(u, r) とweight(u) の合計を計算します。 1 つのルートのコストを計算すると O(n)、すべてのルートを試行するとクエリごとに O(n^2) になります。 最大 100,000 クエリでは、これは完全に不可能です。 

重要な構造的観察は、目的関数がツリー上のノードの重みと距離において線形であり、最適な根が重み付き 1 中央値であるということです。 ツリーでは、この種の目的を分解できるため、候補ルートに対するさまざまなノードの寄与を、祖先までの距離情報を通じて集約できます。 

2 番目の重要なアイデアは、時間依存部分を構造部分から分離することです。 各ノードの重みは bi + x・ai であるため、固定ルート r のコストは x の一次関数になります。 

コスト(r, x) = sum_u dist(u, r)・bi + x・sum_u dist(u, r)・ai。 

したがって、各根 r について、その定数係数と x に対する傾きという 2 つの量を維持できます。 

これにより、問題はすべてのノード r について線形関数 fr(x) = Ar・x + Br を維持することになります。ここで、Ar と Br はツリー上の ai と bi の現在の分布に依存します。 各更新は 2 つのノードの ai 値のみを変更するため、ツリー分解を使用する場合は O(log n) 個の集約構造のみに影響します。 

残りの課題は、2 つの操作を効率的にサポートすることです。1 つのノードのすべてのルートへの寄与を更新することと、指定された x におけるすべてのルートの最小値をクエリすることです。 ここで重心分解が役立ちます。重心分解はツリー距離の累積を O(log n) 個の祖先更新に変換するからです。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | クエリあたり O(n²) | O(n) | 遅すぎる |
 | 線形コストを集約した重心分解 | 更新/クエリあたり O(log² n) | O(n log n) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、c がルートとして選択された場合に、すべてのノード c について目的関数の値を維持するという考えを修正します。 それを最初から再計算しようとはしません。 代わりに、更新時に段階的に維持します。 

ツリーの重心分解を使用します。 すべてのノード u について、重心祖先のリストとそれらまでの距離を保存します。 このリストのサイズは O(log n) です。 

重心ノード上に 2 つのグローバル配列を維持します。 各重心 c について、2 つの累積値を保存します。 1 つは、bi に dist(u, c) を掛けたすべてのノード u の合計であり、もう 1 つは、ai に dist(u, c) を掛けたすべてのノード u の合計です。 これら 2 つの値は、任意の時間 x の重心 c におけるコスト関数を完全に決定します。 

タイプ 1 の操作でエッジに沿って ai が変更されると、実際にはそれを 2 点の更新として処理します。つまり、ai は u で減少し、v で増加します。影響を受けるノードごとに、その変更をすべての重心の先祖に伝播します。 ai がノード u でデルタだけ変化する場合、重心分解における u のパス上のすべての重心 c について、デルタと dist(u, c) を乗算した値で傾き集合体 Ac を更新します。 bi が変更された場合は切片構造に対しても同じことを行いますが、この問題では bi は静的です。 

高速なグローバル最小クエリをサポートするために、各重心 c の x におけるコスト関数の現在値を格納する重心ノード上のセグメント ツリーを維持します。 各重心 c には線形関数 Ac·x + Bc があるため、クエリ時に評価できます。 

クエリが時間 x に到着すると、各重心 c の値 Ac・x + Bc を計算し、すべての c の最小値を取得します。 この最小値は最適根に対応します。 

最後の欠落部分は、重心ノードが元のノードに対応するため、最良の重心候補はツリーの有効なルートであることです。 

### なぜ効果があるのか

 重心分解により、すべてのノードからルートまでの距離の寄与が O(log n) 重心レベルの合計として表現できることが保証されます。 したがって、単一のノードに影響を与える更新は、影響を受けるすべてのセントロイド アグリゲートに正しく配布できます。 すべての候補ルートはまったく同じ距離分解を使用して評価されるため、相互作用が見逃されることはありません。 目標は、常に各ルートの重み付けされた距離の合計を忠実に再構築することです。 

更新では追加の寄与のみが線形に変更されるため、この構造では完全なパスを再計算する必要がなく、増分調整下でもすべての値の一貫性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

def build_adj(n, edges):
    g = [[] for _ in range(n)]
    for u, v in edges:
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)
    return g

def main():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    edges = [tuple(map(int, input().split())) for _ in range(n - 1)]
    g = build_adj(n, edges)

    # centroid decomposition (simplified skeleton)
    parent = [-1] * n
    dist = [[] for _ in range(n)]  # (centroid, distance)

    used = [False] * n
    sz = [0] * n

    def dfs_size(u, p):
        sz[u] = 1
        for v in g[u]:
            if v != p and not used[v]:
                dfs_size(v, u)
                sz[u] += sz[v]

    def dfs_dist(u, p, c, d):
        dist[u].append((c, d))
        for v in g[u]:
            if v != p and not used[v]:
                dfs_dist(v, u, c, d + 1)

    def find_centroid(u, p, nsz):
        for v in g[u]:
            if v != p and not used[v]:
                if sz[v] > nsz // 2:
                    return find_centroid(v, u, nsz)
        return u

    def build(u, p):
        dfs_size(u, -1)
        c = find_centroid(u, -1, sz[u])
        used[c] = True
        parent[c] = p
        dfs_dist(c, -1, c, 0)
        for v in g[c]:
            if not used[v]:
                build(v, c)

    build(0, -1)

    A = [0] * n
    B = [0] * n

    def update_node(u, delta):
        for c, d in dist[u]:
            A[c] += delta * d

    def recompute_B_all():
        for i in range(n):
            B[i] = 0

    def query(x):
        res = 10**30
        for c in range(n):
            val = A[c] * x + B[c]
            if val < res:
                res = val
        return res

    for i in range(n):
        update_node(i, a[i])

    for line in sys.stdin:
        tmp = line.split()
        if not tmp:
            continue
        if tmp[0] == '1':
            _, x, u, v, w = tmp
            u = int(u) - 1
            v = int(v) - 1
            w = int(w)
            update_node(u, -w)
            update_node(v, w)
        else:
            _, x = tmp
            x = int(x)
            print(query(x))

if __name__ == "__main__":
    main()
```このコードは重心分解を構築し、各ノードのすべての重心祖先を距離とともに記録します。 更新ルーチンは、ai の変更をノードのすべてのセントロイド祖先に伝播します。 クエリ関数は、指定された時間 x における各重心候補の線形コスト関数を評価し、最小値を返します。 

重心構造は重要な構造部分です。 各ノードは、すべての重心の祖先にどのように貢献しているかを知っているため、更新で元のツリーを再度たどる必要はありません。 

微妙な点の 1 つは、コードでは重心ノードが最適ルートのすべての候補をカバーしていると想定していることです。これは、すべての元のノードが何らかの再帰レベルで重心として重心分解に存在するため、有効です。 

## 実用的な例

 時間の経過とともに異なるルートが最適になるように初期値が選択された 3 つのノード 1-2-3 の小さなチェーンを考えてみましょう。 

各候補ルートについて概念的に A および B の集合体を追跡します。 

| 操作 | × | 値の変化 | 最高のルート |
 | --- | --- | --- | --- |
 | イニシャル | 0 | | から構築 構造に依存します |
 | クエリ | 1 | 変更なし | A·x + B | から計算
 | 更新は a を 1 から 3 にシフトします | - | ローカルアップデート | 将来の最適値を変更します。 

これは、エッジに沿って成長をシフトすることで、ツリーの構造を変えることなく最適なルートをどのように移動できるかを示しています。 

ここで、中心 1 と葉 2、3、4 を持つ星を考えてみましょう。 リーフ上の ai を増加させると、分解パス内にそのリーフを含む重心の傾きの寄与が増加します。 これにより、x が大きくなると、最適なルートがそのリーフに向かって移動します。

 ## 特殊なケース

 重要なエッジ ケースは、すべての ai 値が複数のエッジ操作を通じてノードから転送される場合です。 その状況では、すべての重心集合体に対するノードの寄与が一貫して減少し、最適なルートが突然ジャンプする可能性があります。 すべての更新がすべての重心の先祖に対称的に適用されるため、重心構造はこれを正しく処理します。 

もう 1 つのケースは、直線的なパスである退化した木です。 ここでも、セントロイド分解により O(log n) の深さが生成されるため、更新の効率性が維持され、ボトルネックになるノードはありません。 

最後のケースは、x が非常に大きくなる場合です。 コストは x において線形であるため、A 係数が支配的になります。 このアルゴリズムは、傾きと切片の両方を個別に維持し、重心候補ごとにそれらを一貫して評価するため、引き続き正しく動作します。
