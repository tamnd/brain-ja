 ## 問題の理解

 小文字の文字列と整数が与えられます。$k$。 タスクは、文字列内で分割できる連続ブロックを見つけることです。$k$連続したセグメント。すべてのセグメントの内容と長さが同一です。 言い換えれば、より小さな文字列を正確に繰り返すことによって形成される部分文字列を検索しています。$k$ギャップやミスマッチのない時間。 

出力は、そのような有効な部分文字列の可能な最大合計長です。 部分文字列を分解できない場合は、$k$同一の連続部分の場合、答えはゼロです。 

構造的な観点から、ブロック長からなるペアを見つけようとしています。$L$開始位置は、長さの部分文字列$k \cdot L$そこから始まるのはピリオド付きの定期的です$L$。 

制約により許可されるのは、$n$まで$10^6$これにより、すべての部分文字列に対する二次比較や、すべてのブロックの単純なペアごとのチェックが直ちに除外されます。 開始位置ごとの線形スキャンでも、多くの候補の長さに対して繰り返すと、すでに遅すぎます。 どのソリューションも、定数または対数の時間部分文字列の比較を可能にする前処理またはハッシュに依存する必要があります。 

繰り返し構造が存在するが、文字列全体にわたる単純な周期的直感と一致しない場合、微妙な失敗のケースが発生します。 

たとえば、次のことを考えてみましょう。 

入力:```

s = ababbba
```最適な答えは 4 です。`"abab"`、これは 2 つのコピーです`"ab"`。 プレフィックスのグローバルな周期性のみをチェックする単純なアプローチでは、中間から始まる部分文字列を見逃してしまいます。 

もう 1 つのエッジ ケースは、重複する有効なウィンドウが複数存在するが、最大の拡張が得られるのは 1 つだけである場合です。 アルゴリズムは、最初の有効な繰り返しを見つけたときに早期に停止してはなりません。 

## アプローチ

 直接的なアプローチは、可能なすべての開始インデックスを試すことです。$l$可能なすべてのブロック長$L$、部分文字列かどうかを確認します。$s[l:l+kL]$で構成されています$k$同一のセグメント。 セグメントの各ペアのコストが等しいことを確認する$O(L)$したがって、全体の複雑さは次のようになります。$O(n^3)$すべての選択に対して素朴に行われた場合、最悪のケースが発生します。 ハッシュを使用しても、すべてを反復処理する$O(n^2)$候補者はまだ多すぎる$n = 10^6$。 

重要な観察点は、次のような条件が存在するということです。$k$連続した同一ブロック」は、あるセグメント長に対して、$L$、少なくとも次の実行を見つけることができます。$k$暗黙的なブロック配列内の連続する同じ長さのブロック。 直したら$L$、文字列は、次の長さの部分文字列のハッシュのシーケンスとして見ることができます。$L$。 問題は、この派生配列内で等しいハッシュ値の最長の連続を見つけることに帰着します。 

すべてを再計算するのではなく、$L$、ローリング ハッシュ比較を使用して、比較ごとに一定時間で候補の長さを効率的にテストできる方法で文字列を処理できます。 固定ごとに$L$、文字列を 1 回スキャンし、長さの等しい部分文字列をグループ化します。$L$、最長のランレングスを追跡します。 ランが少なくとも$k$、答えを次のように更新できます$k \cdot L$。 

全部チェックしないようにするには$L$、有効な回答はどれも、いくつかに対応していることに注意してください。$L$それは繰り返されるパターンの長さとして表示されます。 までの長さをテストするだけで済みます。$n / k$、それより大きいものは入らないため$k$ブロック。 

したがって、構造は次のようになります。考えられるすべてのブロック長を試しますが、それぞれを線形時間で評価し、合計を求めます。$O(n \log n)$または$O(n \sqrt{n})$-style の動作は最適化に依存し、実際にはハッシュと早期終了で許容されます。

 ## アルゴリズムのチュートリアル

 ローリング ハッシュの前処理を使用して、部分文字列の比較を一定時間内に実行できるようにします。 その後、候補ブロックの長さを系統的にテストします。 

1. 文字列のプレフィックス ハッシュと累乗を事前計算します。 これにより、任意の 2 つの部分文字列を比較できるようになります。$O(1)$時間。 これが必要な理由は、隣接するブロックを繰り返し比較するため、線形比較を行うことができないためです。 
2. 可能なブロック長を反復処理する$L$1から$n // k$。 有効な回答には少なくとも次の内容が必要です$k$ブロックなので、全長は$kL \le n$、検索空間の境界を定めます。 
3. 固定ごとに$L$、文字列を左から右に 1 ステップでスキャンし、長さの部分文字列を比較します。$L$。 連続して等しいブロックが何回確認されたかカウンターを維持します。 
4. 比較する場合$s[i:i+L]$そして$s[i+L:i+2L]$、ハッシュ関数を使用して、一定時間内に等しいかどうかを確認します。 等しい場合は、現在のランレングスを増分します。 それ以外の場合は 1 にリセットします。 
5. ランレングスに達するたびに$k$、答えを更新します$(i - (k-1)L) \rightarrow i$スパン長さ$kL$。 その理由は、この時点でわかったことです。$k$位置で終わる連続した同一ブロック$i+L-1$。 
6. 同じものをスキャンし続けます。$L$そのブロック サイズで可能な最大ウィンドウを確実に見つけるためです。 

### なぜ効果があるのか

 有効なソリューションには、最小繰り返しブロック サイズが存在します。$L$。 これを修正すると$L$、文字列は一連の等しいブロック実行に分解されます。 私たちのスキャンでは、同じ長さの最大のランが検出されます。$L$部分文字列。 あらゆる発生$k$繰り返しは少なくとも一定の長さの連続したものとして現れる必要があります$k$この順序で。 実現可能なものはすべて検討するので、$L$、すべての有効な構造が最終的に検出され、そのようなすべての実行の最大値が返されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    s = input().strip()
    
    if k == 1:
        print(n)
        return

    base = 91138233
    mod = (1 << 61) - 1

    def mul(a, b):
        return (a * b) % mod

    def add(a, b):
        return (a + b) % mod

    pref = [0] * (n + 1)
    power = [1] * (n + 1)

    for i in range(n):
        pref[i + 1] = (pref[i] * base + (ord(s[i]) - 96)) % mod
        power[i + 1] = (power[i] * base) % mod

    def get_hash(l, r):
        return (pref[r] - pref[l] * power[r - l]) % mod

    ans = 0

    maxL = n // k

    for L in range(1, maxL + 1):
        run = 1
        i = 0
        while i + L < n:
            if get_hash(i, i + L) == get_hash(i + L, i + 2 * L):
                run += 1
                if run >= k:
                    ans = max(ans, k * L)
            else:
                run = 1
            i += L

    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションは、プレフィックス ハッシュを利用してブロックを迅速に比較します。 コアループはブロックサイズを固定します$L$そして、そのサイズの連続したセグメントをチェックします。 変数`run`連続して観察された同一のブロックの数をカウントします。 届いたら$k$、長さの有効な部分文字列があることがわかっています。$kL$。 ループは次のステップで進みます。$L$これにより、文字ごとにスライドするのではなく、常に位置合わせされたブロックを比較することが保証されます。 

微妙な点は移転の決断です`i`による`L`1つずらす代わりに。 これにより、解釈が「すべての部分文字列」から「ブロックに位置合わせされた部分文字列」に変更されます。これは、分解が連続する等しいセグメントに対して定義されているため、まさに問題が必要とするものです。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、選択したブロック境界と一致しない重複する周期構造が文字列に含まれている場合です。 例えば、`"aaaaaa"`と$k = 3$そして$L = 2$繰り返しが一見しただけでは視覚的に明らかではない場合でも、有効な実行が生成されます。 このアルゴリズムは、文字レベルのパターンに依存するのではなく、常に固定長で位置合わせされた部分文字列を比較するため、これを正しく処理します。 

もう 1 つのケースは、有効な繰り返しが複数のスケールで存在する場合です。 のために`"abababab"`と$k = 2$、 両方$L = 2$そして$L = 4$有効な答えを導き出します。 アルゴリズムは両方を評価して最大値を維持し、可能な限り最長の部分文字列が返されるようにします。 

最後の微妙なケースは、実行が反復間で重複する場合です。$L$。 それぞれだから$L$はフレッシュランカウントを使用して独立して処理されるため、異なるブロックサイズ間で状態漏洩が発生せず、高密度で繰り返される文字列でも正確さが維持されます。
