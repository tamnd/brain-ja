 ## 解決策
 ## 問題の理解

 長方形のグリッドが与えられ、各セルには固定スキル値を持つ競合他社が含まれます。 すべての競技者がボード上で同時にスタートします。 各ラウンドでは、すべての競技者は 4 つの基本的な方向を見て、各方向で最も近い残りの競技者が存在する場合はそれを特定します。 それらの目に見える競合他社は「隣人」とみなされます。 

競技者に少なくとも 1 人の隣人がいて、そのスキルがそれらの隣人の平均スキルよりも厳密に小さい場合、競技者はラウンド後に除外されます。 重要なのは、除去は現在のラウンドの構成に基づいて計算され、すべての除去はラウンド間で同時に発生します。 削除された競合他社は、そのラウンドの計算中に引き続き近隣としてカウントされるため、同じラウンドの評価内で削除がカスケードされることはありません。 

各ラウンドでは、たとえ次のラウンドの前に敗退したとしても、そのラウンドの開始時にまだ存在していた競技者のすべてのスキルの合計に等しいスコアが与えられます。 ラウンドで敗退が発生しない場合、プロセスは停止します。 

出力は、すべてのラウンドにわたる合計累積スコアです。 

グリッド サイズはすべてのテスト ケースにわたって最大 100,000 セルであるため、ラウンドごとに隣接関係を最初から再計算する必要が直ちに排除されます。 グリッドを繰り返しスキャンして可視性を再計算する単純なシミュレーションでは、ラウンドごとに少なくとも O(RC) のコストがかかり、最悪の場合、ラウンド数が RC で線形になる可能性があり、非常に遅すぎる二次爆発につながります。 

微妙なエッジ ケースは、近隣の定義から生じます。可視性は、各方向で最も近い残りの競合他社にのみ依存します。 削除後は、ある方向の「次の」近隣が変更されるため、隣接関係を動的に維持しない実装は失敗します。 

もう 1 つの明白ではないケースは安定性です。 すべての値が等しい場合、厳密に隣の平均よりも小さい競合他社は存在しないため、プロセスは 1 ラウンド後に終了します。 同じラウンド内の部分削除後に平均を誤って再計算するソリューションでは、誤ってノードが削除されてしまいます。 

## アプローチ

 直接シミュレーションでは、グリッドを動的システムとして扱います。 各ラウンドでは、すべてのセルをスキャンし、生きているセルが見つかるまで外側に向かって歩いて最大 4 つの方向に隣接するセルを見つけ、それらの平均を計算して、セルを削除するかどうかを決定します。 すべての削除をマークした後、構造を再構築して繰り返します。 

これは正しいですが、高価です。 4 方向のスキャンによる隣接ノードの検索は、前処理を慎重に行った場合、ラウンドあたり合計で O(RC) ですが、削除後の更新では隣接関係を更新する必要があります。 病理学的ケースで RC ラウンドまでを想定すると、合計の複雑さは O((RC)²) にまで縮退しますが、これは 105 個のセルには大きすぎます。 

重要な観察は、各セルが 4 方向で最も近い生きている隣接セルに接続する、動的に変化するグラフの直近の隣接セルにのみエリミネーションが依存するということです。 これらのリンクを再計算する代わりに、増分的に維持します。 各セルは 4 つの潜在的な隣接関係のみに参加し、セルが削除されると、各方向の直接の隣接セルのみが影響を受けます。 

これにより、各ノードがその現在の有効な隣接ノードと安定性メトリック (隣接ノードの合計と数) を保存するグラフのようなシミュレーションが行われます。 「不安定」なセルのキューを維持します。これは、セルが現在除去条件を満たしていることを意味します。 セルが削除されると、隣接するセルのみが更新され、再評価されます。 

各エッジは一定の回数更新されるため、合計の作業量は線形になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O((RC)²) | O(RC) | 遅すぎる |
 | 増分近隣メンテナンス | O(RC) | O(RC) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 初期グリッド構造を構築し、各セルの 4 つの方向すべてで最も近い生存セルを計算します。 これは、行および列ごとの単調スイープを使用して実行できます。 目的は、「可視性グラフ」を線形時間で正しく初期化することです。 
2. 各セルについて、隣接値の合計と隣接セルの数を保存します。 隣接セルがゼロのセルは削除できないため、すぐに安定します。 
3. すべてのセルをチェックし、除外条件を満たすかどうかを計算します。セルには少なくとも 1 つの近傍があり、その値は近傍の値の平均よりも厳密に小さいです。 このようなセルはすべて、候補のキューに挿入されます。 
4. キューをラウンドで処理します。 各ラウンドの開始時に、すべての生存細胞の現在の合計を記録します。 これは答えに貢献します。 
5. キューから候補を繰り返し取り出します。 セルがすでに削除されている場合は、スキップします。 それ以外の場合は、現在の近隣の合計とカウントを使用してその有効性を再計算します。 それでも削除の対象となる場合は、削除済みとしてマークします。 
6. セルが削除されると、その 4 つの方向に隣接するセルが更新されます。 方向ごとに、可視性が維持されるように、前と次の生きているセルを再接続します。 これは重要な構造メンテナンス手順です。 
7. 隣接ノードを再接続するたびに、保存されている隣接ノードの合計とカウントを更新します。 これにより、削除条件を満たすかどうかが変化した場合は、キューにプッシュします。 
8. フルパスでセルが除去されなくなるまで続けます。 最後に記録されたラウンドがその合計を提供し、プロセスは終了します。 

### なぜ効果があるのか

 このプロセスは、各ノードの状態が現在表示されている隣接ノードのみに依存する動的グラフを維持します。 可視性は各方向で最も近い生存ノードとして定義されるため、ノードの削除はその行と列に沿った隣接関係にのみ影響し、広範囲にわたる変更が生じることはありません。 すべての更新はローカライズされるため、削除条件はすべてのステップで定義と一貫性が保たれます。 システム内のすべての変更は削除によってのみトリガーされ、各削除は O(1) 個の近傍にのみ影響するため、無効なグローバル再計算は必要ありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for tc in range(1, T + 1):
        R, C = map(int, input().split())
        a = [list(map(int, input().split())) for _ in range(R)]

        n = R * C

        # flatten grid
        val = [0] * n
        for i in range(R):
            for j in range(C):
                val[i * C + j] = a[i][j]

        alive = [True] * n

        left = [-1] * n
        right = [-1] * n
        up = [-1] * n
        down = [-1] * n

        # build initial neighbors using sweeps
        for i in range(R):
            prev = -1
            for j in range(C):
                idx = i * C + j
                left[idx] = prev
                if prev != -1:
                    right[prev] = idx
                prev = idx

        for i in range(R):
            prev = -1
            for j in range(C - 1, -1, -1):
                idx = i * C + j
                right[idx] = prev
                if prev != -1:
                    left[prev] = idx
                prev = idx

        for j in range(C):
            prev = -1
            for i in range(R):
                idx = i * C + j
                up[idx] = prev
                if prev != -1:
                    down[prev] = idx
                prev = idx

        for j in range(C):
            prev = -1
            for i in range(R - 1, -1, -1):
                idx = i * C + j
                down[idx] = prev
                if prev != -1:
                    up[prev] = idx
                prev = idx

        from collections import deque

        def neighbors_sum_cnt(x):
            s = 0
            c = 0
            for y in (left[x], right[x], up[x], down[x]):
                if y != -1 and alive[y]:
                    s += val[y]
                    c += 1
            return s, c

        q = deque()
        inq = [False] * n

        total = sum(val)
        ans = 0

        for i in range(n):
            s, c = neighbors_sum_cnt(i)
            if c > 0 and val[i] * c < s:
                q.append(i)
                inq[i] = True

        while True:
            ans += total
            removed_any = False
            nxt = deque()

            while q:
                x = q.popleft()
                inq[x] = False
                if not alive[x]:
                    continue
                s, c = neighbors_sum_cnt(x)
                if c == 0 or val[x] * c >= s:
                    continue

                alive[x] = False
                total -= val[x]
                removed_any = True

                for nb in (left[x], right[x], up[x], down[x]):
                    if nb == -1:
                        continue

                    if nb == left[x]:
                        if right[nb] == x:
                            right[nb] = right[x]
                    if nb == right[x]:
                        if left[nb] == x:
                            left[nb] = left[x]
                    if nb == up[x]:
                        if down[nb] == x:
                            down[nb] = down[x]
                    if nb == down[x]:
                        if up[nb] == x:
                            up[nb] = up[x]

                    if not inq[nb] and alive[nb]:
                        s2, c2 = neighbors_sum_cnt(nb)
                        if c2 > 0 and val[nb] * c2 < s2:
                            q.append(nb)
                            inq[nb] = True

            if not removed_any:
                break

        print(f"Case #{tc}: {ans}")

if __name__ == "__main__":
    solve()
```この実装ではグリッドが平坦化されるため、隣接処理が 1D 配列でのポインター操作になり、方向の更新が簡素化されます。 4 つの方向性アレイは最近アライブネイバー構造をエンコードし、ノードが削除されるとこれらのポインタがローカルにパッチされます。 

消去条件は、値の乗算、比較による浮動小数点除算を回避します。`val[x] * cnt < sum`、整数演算での正確性が維持されます。 

重要な点は、近隣更新は直前の先行者と後続者のみを再接続することです。 削除してもグリッド構造の一貫性が保たれるため、グローバルな再計算は必要ありません。

 ## 特殊なケース

 単一セルのグリッドには隣接するグリッドが存在しないため、ちょうど 1 ラウンドだけ生き残り、その値を 1 回だけ提供します。 このアルゴリズムは、隣接カウントをゼロに初期化し、削除のためにセルをキューに入れないことによってこれを処理します。 

均一なグリッドでは、すべてのノードに等しい隣接ノードがあるため、厳密な不等式は満たされません。 キューは初期化後も空のままで、ループは最初のラウンドの合計のみを加算した後に終了します。 

1×N や N×1 などの細長いグリッドでは、隣接関係が線に崩れます。 初期化時に左/右または上/下のチェーンが正しく形成され、2D 構造がなくても正しい可視性が保証されるため、方向ポインタ ロジックが引き続き適用されます。
