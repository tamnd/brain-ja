 ## 解決策
 ## 問題の理解

 私たちは一番上のセルからパスカルの三角形の上を歩いています。 三角形の各位置には二項係数に等しい値があり、目的地が三角形の内側にある限り、任意のセルから、左上、右上、左、右、左下、または右下の 6 つの隣接するセルのいずれかに移動できます。 セルを再訪問せず、常に先頭のセルから開始し、最大 500 個のセルを訪問し、訪問したすべてのセルの値の合計が指定された数に等しい単純なパスを作成する必要があります。$N$。 

重要な問題は、各セルの重さが均一ではないことです。 初期の行には小さな値が含まれていますが、より深い行には大きな二項係数が含まれており、行全体が 2 のべき乗である構造化された合計を持っています。 これにより、問題はジオメトリに関するものではなく、総重量のうち慎重に選択された部分を「収集する」パスの構築に関するものになります。 

制約の規模は広範囲にわたります$N$、 まで$10^9$ただし、パスの長さは 500 によって制限されます。これにより、直接表現しようとするアプローチは即座に除外されます。$N$個々のセル値の合計として貪欲に計算するか、グリッドを探索します。 その代わりに、それぞれの構造上の選択が予測可能な程度に大きく貢献する構造が必要です。 

微妙なエッジケースが現れるのは、$N$小さいです。 もし$N = 1$、パスは単なる開始セルです。 わずかに大きい値の場合、単純な試みで貪欲に下方向に移動しようとする可能性がありますが、個々のエントリが単調ではなく、構造の再検討が禁止されているため、それは失敗します。 もう 1 つの落とし穴は、目的の値を持つセルを個別に選択できると仮定していることですが、隣接制約によりパスが連続化し、再訪問が大幅に制限されます。 

唯一の実行可能な戦略は、パスカルの三角形の完全な行の合計が非常にきれいであるという事実を利用し、行を完全に消費するか、行を最小限に通過できるウォークを設計することです。 

## アプローチ

 ブルートフォースアプローチでは、各状態が位置と訪問セルのセットであるグラフ検索としてこれを扱い、正確に到達するまで合計を累積しようとします。$N$。 これはすぐに実行不可能になります。 積極的な枝刈りを行ったとしても、長さ 500 までの可能な単純なパスの数は指数関数的に増加し、各パスはパスカルの三角形の値を合計する必要があります。 これは、合理的な計算予算をはるかに超えて爆発的に増加します。 

重要な構造的観察は、パスカルの三角形の行には強力なアイデンティティ、つまり行内の値の合計があるということです。$r$は$2^{r-1}$。 これは、各行全体が偽装された 2 進数のように動作することを意味します。 行を完全に横断するか、制御された方法で行をスキップするウォークを設計できれば、問題は分解するのと同等になります。$N$2 の累乗になります。 

This leads to a constructive idea. 行ごとに下に移動し、選択した行についてはジグザグ パターンで行全体をたどって、すべてのセルを正確に 1 回訪問し、行全体の合計を収集します。 For other rows, we only pass through a single boundary cell, contributing a minimal controlled amount. By choosing which rows to fully traverse, we can encode$N$バイナリで。 

残りの課題は、有効な単純なパスを維持することです。 これは行ごとに方向を変えることで処理されるため、セルにジャンプしたり再訪問したりする必要はありません。

 ## アルゴリズムのチュートリアル

 のバイナリ分解を利用します。$N$ここで、各ビットは行を完全に横断するか、行を通過するだけかどうかを決定します。 

1. 位置から開始$(1,1)$。 これにより、固定の初期値 1 が決まります。これは、パスカルの三角形の最初の行に対応します。 
2. 各行を交互に配置する現在の方向フラ​​グを維持します。 これにより、次の行に接続したまま、セルを再度訪問することなく行を蛇行することができます。 
3. 行インデックスごとに$r$2 以降は、 のビット表現に基づいて決定します。$N$。 もし$(r-2)$-番目のビット$N$が設定されている場合、行を完全に横断します$r$方向に応じて、左から右へ、または右から左へ。 これはまさに貢献します$2^{r-1}$合計に。 
4. ビットが設定されていない場合は、現在の行の境界からエッジに沿って次の行に直接移動し、その行の新しいセルを 1 つだけ訪問します。 これにより、パスがシンプルに保たれ、誤って余分な重量が蓄積することがなくなります。 
5. 選択した行からの累積貢献度が次の値に達するまで続行します。$N$。 なぜなら$N \le 10^9$、完全なコントリビューションに必要な行はわずか約 30 行であり、パスの残りの部分は線形トラバースであり、全長は 500 以内に十分に保たれます。 
6. 訪問した座標のシーケンスを順番に出力します。 

### なぜ効果があるのか

 完全に走査された各行は正確に寄与します$2^{r-1}$、そのような各行は、寄与の点で他の行から独立しています。 各行は単一の単調スイープで走査されるため、パスの構築により、セルを再訪問することがないことが保証されます。 残りの部分移動は境界セルにのみ接触するため、バイナリ エンコード構造には干渉しません。 これにより、合計は行パワーの選択されたサブセットと正確に等しくなります。これは、次のバイナリ表現に対応します。$N$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(n):
    path = []
    r = 1
    k = 1
    path.append((r, k))

    remaining = n
    direction = 1  # 1 means moving right, 0 means moving left

    # We process rows until remaining becomes 0
    # We decide whether to take full row r or not based on bits of remaining
    for r in range(1, 31):
        if remaining == 0:
            break

        # If we are at row 1, we already included (1,1)
        if r == 1:
            continue

        bit = remaining & 1
        remaining >>= 1

        if bit == 1:
            # traverse full row r
            if direction == 1:
                for c in range(1, r + 1):
                    path.append((r, c))
            else:
                for c in range(r, 0, -1):
                    path.append((r, c))
        else:
            # move only along the edge
            if direction == 1:
                path.append((r, 1))
            else:
                path.append((r, r))

        direction ^= 1

    return path

def solve():
    t = int(input())
    for tc in range(1, t + 1):
        n = int(input())
        path = solve_case(n)

        print(f"Case #{tc}:")
        for r, k in path:
            print(r, k)

if __name__ == "__main__":
    solve()
```このソリューションでは、パスを行ごとに構築します。 変数`remaining`バイナリ分解のうちどれだけがまだ割り当てられていないかを追跡します。 各反復は 1 ビットを消費し、対応する行が完全に走査されるか、境界にのみタッチされるかを決定します。 の`direction`変数を使用すると、行を完全に走査するときに直線の単調なスイープで移動することが保証され、これによりセルの再訪問が回避され、隣接関係が有効に保たれます。 

よくある間違いは、行全体の走査が連続的である必要があることを忘れていることです。 エンドポイント間をジャンプすると隣接ルールに違反するため、コードは明示的にすべての列を順番に実行します。

 ## 特殊なケース

 のために$N = 1$、アルゴリズムは初期化を超えて行トラバーサル ロジックに入ることはありません。 出力は単なる開始セルであり、すでに合計要件を正確に満たしています。 

次のような 2 のべき乗の場合$N = 1024$、バイナリ分解により、単一の深い行が選択されます。 このアルゴリズムは、正確に 1 行の完全な走査を実行し、他のすべての行をスキップし、長くても有効な単調なジグザグ パスを生成します。 必要な行数は約 10 行だけであるため、これが 500 の制限に違反することはありません。 

次のような交互ビット数値の場合$N = 170$、全行トラバースと境界ステップの間で構築が交互に行われます。 方向反転により、これらの交互の決定間の連続性が保証され、再訪問が防止され、歩行全体を通じて隣接性が維持されます。
