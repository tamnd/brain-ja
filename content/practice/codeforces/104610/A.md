 ## 解決策
 ## 問題の理解

 いくつかのパターンがあり、それぞれが大文字とワイルドカード文字で構成されています。`*`。 それぞれ`*`は、空の文字列を含む任意の大文字の文字列に独立して置き換えることができます。 すべての置換の後、パターンは具体的な文字列になります。 

タスクは、ワイルドカードを適切に置き換えることによってすべてのパターンから同時に取得できる、長さが最大 ​​10,000 の単一の文字列が存在するかどうかを判断することです。 そのような文字列が存在する場合、有効な例を 1 つ出力できます。 それ以外の場合は、単一のコマンドで失敗を報告する必要があります。`*`。 

重要な点は、各パターンが文字列全体を均一に制約しないことです。 代わりに、構造を制約します。星間の部分は順番に出現する必要がありますが、星は任意に伸縮することができ、柔軟なギャップが可能になります。 

制約は小さく、パターンは最大 50 個、各パターンの長さは最大 100 です。これにより、すべてのワイルドカード置換に対する指数関数的な構築が排除されます。 パターンごとの線形または線形に近い集約で十分です。 

単純な間違いは、各パターンを正規表現として扱い、完全な交差オートマトンを構築しようとしたり、部分文字列のすべての配置を試行したりすることです。 たとえば、次のようなパターン`A*C*E`そして`*B*D*`すべてのセグメントの組み合わせの整列について考えたくなるかもしれません。 このアプローチはすぐに爆発します。`*`無制限の選択肢を導入します。 

より微妙な失敗は、接尾辞制約を対称的に処理せずに接頭辞だけをチェックするか、部分文字列だけをチェックすることによって発生します。 例えば、`HE*`そして`*LO`どちらも個別に多くの一致を許可しますが、で始まる文字列のみが許可されます。`HE`そしてで終わる`LO`このロジックを誤って組み合わせると誤検知が発生することがよくあります。 

## アプローチ

 ブルートフォース手法では、候補文字列を構築し、それをすべてのパターンに対して検証しようとします。 それぞれなので`*`任意の長さの文字列を表現できるため、検索スペースは事実上無制限です。 たとえ長さ 10,000 までの文字列に制限したとしても、考えられるすべての構成を試すことは不可能です。 

代わりに、すべてのパターンが 3 つの意味のある部分に分解できることがわかります。最初のプレフィックスです。`*`、最後の後の接尾辞`*`、および星間のすべての中間セグメント。 重要な点は、最終的な答えのプレフィックスはすべてのパターンのプレフィックスと互換性があり、サフィックスについても同様である必要があるということです。 中間部分には、順序を維持する以上の位置合わせ制約は必要ありません。 単純に連結することができます。 

これにより、問題は 2 つの整合性チェックと 1 つの構築ステップに減ります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 |---|---|---|---|
 | 文字列の総当たり列挙 | 指数 | 高 | 遅すぎる |
 | 連結によるプレフィックス/サフィックスのマージ | O(パターンの全長) | O(パターンの全長) | 承認済み |

 ## アルゴリズムのチュートリアル

 各パターンを個別に処理し、構造上の制約を抽出します。 

### 1. 各パターンをセグメントに分割します
 すべてのパターンを次のように分割します`*`、固定文字列のリストを生成します。 最初のセグメントはプレフィックス制約として動作し、最後のセグメントはサフィックス制約として動作し、その間にあるものはすべて柔軟な内部コンテンツです。 

この分離が有効である理由は、`*`は任意の数の文字を吸収できるため、セグメントの相対的な順序のみが重要になります。 

### 2. プレフィックス制約を収集する
 各パターンについて、その最初のセグメントを取得します。 これらすべてのプレフィックスの中で、最も長いプレフィックスを特定します。 この最長のプレフィックスが、最終的な回答の候補プレフィックスになります。 

次に、他のすべての接頭辞がこの候補と互換性があること、つまり対応する開始文字と一致する必要があることを確認します。 両方が文字を定義する位置でいずれかのプレフィックスが一致しない場合、構築は不可能です。 

### 3. サフィックス制約を収集する
 サフィックスについても同じロジックを最後から繰り返します。 パターンごとに、その最後のセグメントを取得します。 最終的な回答の候補サフィックスとして最も長いサフィックスを選択し、最後に揃えたときに他のすべてがそのサフィックスと一致することを確認します。 

これにより、すべてのパターンが正しく終了できるようになります。 

### 4. 中間セグメントを収集する
 すべてのパターンのすべての中間セグメントは任意の順序で連結されますが、各パターン内の内部順序は維持されます。 これらのセグメントは、順番のどこかに出現する必要がある強制された部分文字列に対応します。 

以来`*`任意の挿入が許可されているため、選択したプレフィックスとサフィックスの間にすべての中間セグメントを安全に配置できます。 

### 5. 最終候補を構築する
 最終的な文字列は次のように形成されます。 

プレフィックス + すべての中間セグメントの連結 + サフィックス

 ### 6. 長さの制約を検証する
 結果の文字列が 10,000 文字を超える場合でも、許可されている場合にのみ出力されます。 そうでない場合は拒否します。 制約が与えられると、入力が敵対的でない限り、これはほとんど起こりませんが、それでも強制します。 

### なぜ効果があるのか

 重要な不変条件は、すべてのパターンがその固定セグメントを順番に埋め込む必要があるということです。 プレフィックス集約により、すべての必須の開始制約が単一の最大プレフィックスによって満たされることが保証されます。 サフィックス集約により、最終的に同じであることが保証されます。 残りのセグメントはすべてスターの間にあるため、順序以外の位置の競合はなく、連結によって有効性が維持されます。 

あらゆる矛盾は、プレフィックスまたはサフィックスのアライメントで重複する位置を占めることを強制される 2 つの固定セグメント間の不一致として現れる必要があり、互換性チェックではまさにこれが検出されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for tc in range(1, T + 1):
        n = int(input())
        
        parts = []
        prefixes = []
        suffixes = []
        mids = []
        
        possible = True
        
        for _ in range(n):
            s = input().strip()
            seg = s.split('*')
            
            prefixes.append(seg[0])
            suffixes.append(seg[-1])
            
            if len(seg) > 2:
                mids.extend(seg[1:-1])
        
        # build prefix: take longest
        pref = max(prefixes, key=len)
        for p in prefixes:
            if len(p) > len(pref):
                if pref != p[:len(pref)]:
                    possible = False
                    break
            else:
                if p != pref[:len(p)]:
                    possible = False
                    break
        
        # build suffix: longest, check reversed compatibility
        suf = max(suffixes, key=len)
        for s in suffixes:
            if len(s) > len(suf):
                if suf != s[-len(suf):]:
                    possible = False
                    break
            else:
                if s != suf[-len(s):]:
                    possible = False
                    break
        
        if not possible:
            print(f"Case #{tc}: *")
            continue
        
        ans = pref + "".join(mids) + suf
        
        if len(ans) > 10000:
            print(f"Case #{tc}: *")
        else:
            print(f"Case #{tc}: {ans}")

if __name__ == "__main__":
    solve()
```プレフィックス ロジックは、主要な開始文字列を構築し、他のすべてを先頭に埋め込むことができることを検証します。 サフィックス ロジックはこれを端から反映します。 星は自由に配置できるため、中間セグメントは相互作用の制約なしで収集されます。 

実装でよくある落とし穴は、サフィックスの位置合わせは最初からではなく最後から行う必要があることを忘れていることです。 もう 1 つは、プレフィックスが包含によって比較されるのではなく連結できると仮定することです。 これは、次のような互換性のないプレフィックスを誤ってマージします。`AB`そして`AC`。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 |---|---|---|
 | 時間 | O(パターンの全長) | 各パターンは 1 回スキャンされて分割され、その後線形のプレフィックスとサフィックスのチェックが行われます。 
| スペース | O(パターンの全長) | すべてのパターンにわたる保存されたセグメント |

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、パターンに星が含まれていない場合です。 その場合、文字列全体がプレフィックス制約とサフィックス制約の両方として同時に機能します。 プレフィックスとサフィックスの配列には同一の完全な文字列が含まれており、一貫性チェックではすべてのパターンにわたる等価性の強制が行われるため、アルゴリズムがこれを処理します。 

パターンが次で開始または終了する場合、別の特殊なケースが発生します。`*`、空のプレフィックスまたはサフィックス セグメントが生成されます。 空の文字列はすべての文字列の接頭辞および接尾辞であるため、これらは常に互換性があり、構築を制限することはありません。 

より微妙なケースは、複数のパターンに競合する内部構造があるが、プレフィックスまたはサフィックスの競合がない場合です。 内部セグメントをグローバルに位置合わせする必要がないため、アルゴリズムはこれを正しく許可します。 構築された文字列のどこかに順序どおりに出現する必要があるだけであり、連結によってこの順序が確実に保持されます。
