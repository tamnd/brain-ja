 ## 解決策
 ## 問題の理解

 直線上に配置された離散的な位置からなるパスが与えられ、各位置には自由に選択できる高さの値が与えられます。 パスは高さ 0 で開始し、高さ 0 で終了する必要があります。また、隣接する 2 つの位置の間では、高さは上下 1 単位までしか変更できません。 このようなすべての有効な高さプロファイルの中で、パスに沿った任意の場所に表示できる最大の高さを決定することが課題となります。 

これを別の見方で見ると、長さ L の「地形プロファイル」を構築していると言えます。できるだけ高い頂上が必要ですが、2 つの条件によって制約されます。1 つは、地形の両端が地面に接している必要があり、1 ステップあたり 1 単位を超える急な斜面を持つことはできないということです。 問題は、これらの制約の下でどれだけ高い山を形作ることができるかになります。 

L が 100000 までという制約は、L において最悪の場合でも線形または対数となる解が必要であることを意味します。有効なシーケンスの数が指数関数的に増加するため、考えられるすべての高さ構成を試行する構築やシミュレーションは不可能です。 セグメントに対する二次アプローチでさえ遅すぎます。 

長さが短い場合、キーエッジケースが表示されます。 L が 1 または 2 の場合、地形は強制的に高さ 0 のままになるか、すぐに 0 に戻るため、頂上は存在しません。 L が 3 または 4 に等しいようなわずかに大きな値の場合、小さな三角形のピークのみが形成されます。両端がゼロでなければならないという境界制約を無視すると、より大きなピークが可能であると誤って仮定することが容易になります。 

たとえば、L が 4 の場合、有効な構成は 0、0、1、0 で、最大高さは 1 です。素朴な直感では、あまりにも早く上昇させることで高さ 2 が可能であると示唆するかもしれませんが、隣接する差分制約がそれをブロックします。 

## アプローチ

 強引なアイデアは、ゼロで始まりゼロで終わる長さ L の有効な高さシーケンスをすべて構築してみて、隣接制約を検証し、各シーケンスの最大高さを計算することです。 これは、実行可能なすべての地形を列挙するため、原理的には正しいですが、シーケンスの数は制約付きランダム ウォークのように増加します。 中程度の L の場合でも、可能性の数は天文学的なものになり、非常に小さな入力を超えると完全に実行不可能になります。 

問題の構造は、典型的な整数の制約付きウォークです。 各ステップの高さの変化は最大 1 であり、開始および終了は 0 です。 可能な限り最も高いピークは、ゼロに戻らなければならない前にウォークを可能な限り上方に押し上げることに対応します。 制限要因は、ステップごとに高さを 1 ずつ増やした場合、同じ勾配制約でゼロに戻るのに十分な残りのステップも必要であることです。 

これにより、単純な幾何学的解釈が得られます。 高さ H に到達したい場合、1 回の移動につき最大 1 ステップずつ増加できるため、ゼロから登るには少なくとも H ステップが必要です。 H に到達した後、ゼロに戻るにはさらに H ステップが必要です。 したがって、高さ H のピークには、上下の動きに少なくとも 2H のステップが必要であり、さらに、位置の観点から考えると、ピーク自体の位置が 1 つ必要になります。 これは、可能な最大の高さを利用可能な長さ L に直接結び付けます。 

したがって、問題は、高さ H の対称の山が L 位置の内側に収まるような最大の整数 H を見つけることに帰着します。 その構造は離散三角形です。 ピークを中央に配置する場合、必要な全長は 2H + 1 です。したがって、2H + 1 ≤ L となるような最大 H が必要です。 

この不等式から、答えはfloor((L - 1) / 2)となります。

 ## アルゴリズムのチュートリアル

1. パス内の位置の数を表す整数 L を読み取ります。 目標は、移動と境界の制約の下で、有効な最高ピークがどのくらいの高さにできるかを決定することです。 
2. 高さ H のピークは、0 から H への単調増加と 0 への単調減少によって形成される必要があることに注目してください。より大きなジャンプは許可されていないため、増加または減少の各ステップで高さが正確に 1 だけ変化するのは、最良の場合です。 
3. このようなピークを形成するために必要な位置の最小数を計算します。 0 から H に上がるには H ステップがかかり、H から 0 に戻るにはさらに H ステップがかかり、これですでに 2H の遷移が考慮されます。 ピーク位置は 1 回カウントされるため、必要な位置の総数は 2H + 1 です。 
4. 2H + 1 ≤ L を要求することで実現可能性を強化します。この不等式は、山全体が利用可能なセグメントの長さ内に収まらなければならないという事実を捉えています。 
5. H の不等式を解き、H ≤ (L - 1) / 2 を求めます。この制約を満たす最大の整数 H が最終的な答えになります。 

### なぜ効果があるのか

 最大値 H に達する有効な高さシーケンスでは、高さの変化は移動ごとに最大 1 つであるため、少なくとも H ステップの増加と H ステップの減少を費やす必要があります。 これにより、高さ H のピークをサポートするために必要な長さの厳密な下限が作成されます。対称構造 0、1、2、...、H、...、2、1、0 はこの限界を正確に達成するため、これ以上効率的な構造は存在しません。 必要性の議論と一致する構造の両方が存在するため、境界は厳しく、式は正確です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

L = int(input().strip())

print((L - 1) // 2)
```ソリューション全体は、高さの制約を個別の山の最小長さの要件に変換することにかかっています。 このコードは、シミュレーションを行わずに導出された式を直接適用します。これは、単一の不等式に帰着する問題に対して、反復的な構築は不必要なオーバーヘッドとなるためです。 

唯一の微妙な点は、整数の除算です。 (L - 1) // 2 を使用すると、(L - 1) // 2 の実数値が正しく下敷きされ、H が制約を満たす整数でなければならないという要件と一致します。 

## 実用的な例

 ### 例 1

 入力:

 L = 4

 計算された値は (4 - 1) // 2 = 3 // 2 = 1 です。 

| ステップ | Ｌ | 計算された H |
 | --- | --- | --- |
 | 開始 | 4 | - |
 | 式を適用 | 4 | 1 |

 結果の高さは、0、0、1、0 のような有効な構成に対応します。これは、上昇の余地がある場合でも、ゼロに戻ると必要なスペースが消費され、ピークの高さが制限されることを示しています。 

### 例 2

 入力:

 L = 5

 計算された値は (5 - 1) // 2 = 4 // 2 = 2 です。 

| ステップ | Ｌ | 計算された H |
 | --- | --- | --- |
 | 開始 | 5 | - |
 | 式を適用 | 5 | 2 |

 有効な地形は 0、1、2、1、0 です。これにより、利用可能なすべての位置が正確に使用され、境界が厳密であることが確認されます。 

この例は、奇数の長さではピークが完全に中央に配置されるのに対し、偶数の長さではわずかに平らな構造になることを示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    input = _sys.stdin.readline
    L = int(input().strip())
    return str((L - 1) // 2)

# provided samples
assert run("4\n") == "1"
assert run("5\n") == "2"

# custom cases
assert run("1\n") == "0", "minimum length"
assert run("2\n") == "0", "too short for any peak"
assert run("3\n") == "1", "smallest non-trivial peak"
assert run("10\n") == "4", "larger symmetric structure"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 | 0 | 最小境界の場合 |

 | 3 | 1 | 有効な最小の山 |
 | 10 | 4 | より大きな偶数の長さの正確性 |

 ## 特殊なケース

 L が 1 に等しい場合、シーケンスには開始と終了の両方でなければならない単一の位置のみが含まれ、どこでも高さがゼロになります。 アルゴリズムは (1 - 1) // 2 = 0 を返し、上昇が不可能であるという事実と一致します。 

L が 2 の場合、ゼロで開始および終了する場合、±1 制約の下で上昇および下降する余地はありません。 この式では (2 - 1) // 2 = 0 が得られ、誤ったピークが正しく防止されます。 

L が 3 の場合、唯一の有効な構造は高さ 1 の単一ピーク、つまり 0、1、0 です。計算により (3 - 1) // 2 = 1 が得られ、最適な構造と正確に一致します。 

L が大きい場合、アルゴリズムは、明示的に構築されない場合でも、最大の対称的な山の形状を暗黙的に構築します。 この正確さは、この高さを超えようとすると、ステップ制約または境界制約のいずれかに違反する必要があるという事実から得られます。
