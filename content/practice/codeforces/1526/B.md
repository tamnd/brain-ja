 ## 問題の理解

 許可されるすべての数値は非常に特殊な形式になります。$$11,\ 111,\ 1111,\ 11111,\dots$$クエリごとに目標値が与えられます。$x$、そして、各値を無制限に再利用して、これらの数値の合計として表すことができるかどうかを判断する必要があります。 

最初の反応は、これを無制限のナップザック問題とみなすことです。 各宗派の用途は無限にあり、特定の金額に到達できるかどうかを知りたいと考えています。 

制約により、問題についてどのように考えるべきかが完全に変わります。 まであります$10^4$テスト ケース。各値は次のように大きくできます。$10^9$。 に直接依存する動的プログラミングのアプローチ$x$不可能です。 たとえ$O(x)$単一のテスト ケースのアルゴリズムではすでに遅すぎるでしょう。 

興味深いのは、許可されているすべての数値が、数字の 1 の繰り返しから構築されていることです。 さらに詳しく見てみると、$$111 = 10 \cdot 11 + 1$$そして同様に、$$1111 = 100 \cdot 11 + 11$$11 より大きい許容されるすべての数値は、111 と 11 のいずれかを使用して表現できます。 この構造により、問題をはるかに小規模な検索に減らすことができます。 

よくある間違いは、理由を証明せずに、十分に大きな数値がすべて機能すると仮定することです。 たとえば:

 入力:```
1
69
```出力：```
NO
```69 はかなり大きい値ですが、許可された数値を組み合わせてもこの値は生成されません。 

もう 1 つの簡単な間違いは、111 のコピーを 1 つだけ試行することです。以下を考慮してください。 

入力:```
1
144
```出力：```
YES
```なぜなら$$144 = 111 + 11 + 11 + 11.$$いくつかの厳選された組み合わせだけをチェックするアプローチでは、このようなケースは見逃されます。 

最小値にも注意が必要です。 たとえば:

 入力:```
1
1
```出力：```
NO
```数値 1 自体は加数として使用できないため、小さな値には自動的に到達できません。 

## アプローチ

 ブルート フォース ソリューションでは、許可されたすべての数値が硬貨の額面として扱われ、無制限のナップザック計算が実行されます。 以来$x$と同じくらい大きいかもしれない$10^9$、そのようなDPには数十億の州が必要であり、まったく実行不可能です。 

重要な観察は、11 と 111 の関係から得られます。 

以来$$111 \equiv 1 \pmod{11},$$111 のコピーを 1 つ使用するたびに、11 を法とした剰余はちょうど 1 ずつ増加します。 

を使用するとします$k$111 のコピー。残りの値は次のようになります。$$x - 111k.$$残りを 11 秒だけで埋めることができる場合、$$x - 111k$$負ではなく、11 で割り切れる必要があります。 

これにより、問題は、$k$そのような$$x - 111k \ge 0$$そして$$(x - 111k) \bmod 11 = 0.$$一見して$k$サイズは大きくなる可能性がありますが、モジュロ 11 を使用するとすべてが変わります。 以来$$111 \equiv 1 \pmod{11},$$割り切れる条件は次のようになります$$x - k \equiv 0 \pmod{11}.$$したがって$k$に一致する必要があります$x \pmod{11}$。 

させて$$r = x \bmod 11.$$最小の非負候補は次のとおりです。$k=r$。 If even this smallest valid choice makes$111k > x$, then every larger valid choice is worse and no solution exists.

 したがって、問題全体はチェックに帰着します$$111 \cdot (x \bmod 11) \le x.$$これにより、$O(1)$テストケースごとのソリューション。

 ## アルゴリズムのチュートリアル

 1. 目標値を読み取る$x$。 
2. 剰余を計算します$$r = x \bmod 11.$$有効な数の 111 は次の条件を満たす必要があります。$k \equiv r \pmod{11}$。 
3. 最小の非負候補を選択します。$k=r$。 

他の有効な候補者はすべて、$r+11, r+22,\dots$、111 のさらに多くのコピーが使用されます。 
4. かどうかを確認します。$$111r \le x.$$true の場合、次を使用します$r$111枚の葉のコピー$$x-111r,$$これは負ではなく、11 で割り切れます。 
5. 出力`"YES"`条件が成立する場合、そうでない場合は出力`"NO"`。 

### なぜ効果があるのか

 111 と 11 のみを使用して、あらゆる表現を書き換えることができます。 ソリューションが次のように使用すると仮定します。$k$111 のコピー。$x-111k$11 の負でない倍数でなければなりません。$111 \equiv 1 \pmod{11}$、これには必要です$k \equiv x \pmod{11}$。 

その合同を満たすすべての値の中で、負でない最小の値は次のとおりです。$r=x\bmod 11$。 もし$111r>x$、その後、他の有効な候補者ごとに$r+11m$さらに多くの 111 を使用し、$x$。 解決策は存在しません。 

もし$111r\le x$、 それから$x-111r$は負ではなく、11 で割り切れるため、有効な構造が得られます。 アルゴリズムは必要かつ十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())

ans = []
for _ in range(t):
    x = int(input())
    r = x % 11

    if 111 * r <= x:
        ans.append("YES")
    else:
        ans.append("NO")

print("\n".join(ans))
```実装は数学的特徴付けに直接従います。 

各テスト ケースについて、11 を法とする剰余を計算します。その剰余は、割り算要件を満たすことができる 111 の最小数です。 

条件`111 * r <= x`111 のコピーが目標合計内に収まるかどうかをチェックします。 そうする場合、残りの値は自動的に 11 の負ではない倍数になるため、11 秒だけを使用して完了できます。 

サイズに依存するループはありません$x$値は次のように大きくなる可能性があるため、これは非常に重要です。$10^9$。
