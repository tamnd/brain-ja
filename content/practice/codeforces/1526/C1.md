 ## 解決策
 ## 問題の理解

 一連のポーションが並んでおり、それぞれのポーションが正または負の整数値によって健康状態を変化させます。 体力ゼロから始めて、最初のポーションから最後のポーションまで進みます。 各ステップで、ポーションを飲むか飲まないかを選択できますが、健康状態がゼロを下回ってはなりません。 目標は、飲むポーションの数を最大化することです。 

この簡易バージョンでは入力サイズが制限されているため、$n \le 2000$、次の二次方程式の解を考えることができます。$n$, ただし、それを超えると制限時間を超える可能性があります。 健康値自体は非常に大きくなる可能性があります (最大$10^9$そのため、自動大きな整数を持たない言語では整数のオーバーフローを避けるために累積和に注意する必要がありますが、Python はこれを自然に処理します。 

一部のエッジケースでは、単純な実装が騙される可能性があります。 すべてのポーションがマイナスの場合、ポーションを飲むとすぐに体力がゼロ以下になるため、正しい出力はゼロになります。 もう 1 つの微妙なケースは、次のようなシーケンスです。`[5, -10, 5]`。 常にポジティブなポーションを飲み、ネガティブなポーションをスキップするという素朴な貪欲なアプローチは失敗する可能性があります。なぜなら、少量のネガティブなポーションを受け入れて、後でさらにポーションを飲めることがあるからです。 

## アプローチ

 ブルートフォース ソリューションでは、ポーションのすべてのサブセットを順番に試し、健康状態がマイナスでないかどうかを追跡します。 各ポーションについて、それを摂取するかスキップするかの 2 つの可能性に分岐します。 これにより、$2^n$組み合わせ。 たとえ$n = 20$これにはすでに 100 万を超える可能性があり、$n = 2000$それは全く不可能です。 ブルートフォースはすべての可能性を列挙するため機能しますが、大規模な場合は失敗します。$n$操作数が指数関数的に増加するためです。 

重要な洞察は、私たちがマイナスでない健康状態を維持し、ポーションの数を最大化することだけを気にしているという観察から得られます。 貪欲にポーションを順番に飲もうとする場合、どのネガティブなポーションを受け入れたかを追跡するだけでよく、そうすることで健康状態がマイナスにならない場合は、より大きなネガティブなポーションをより小さなポーションに置き換えることができます。 これは、最小ヒープ (優先キュー) を使用して効率的に実装できます。 ポーションを飲むたびに、その値が現在の健康状態の合計に追加されます。 合計がゼロを下回った場合、これまでに飲んだ最も有害なポーション (ヒープ内の最小値) が削除され、そのプレフィックスのポーション数を最大に保ちながら健康状態が回復されます。 ポジティブポーションは健康状態を低下させることはなく、いつでも追加できます。 

この観察により、解決策は次のように簡略化されます。$O(n \log n)$ヒープへの挿入と削除にはそれぞれコストがかかるため、$O(\log n)$、各ポーションを一度だけ処理します。 これは十分に制限内です$n = 2000$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | 最適 (ヒープベースの貪欲) | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 変数を初期化する`health = 0`現在の健全性と最小ヒープを追跡する`taken`飲むことにしたポーションの値を保存します。 
2. ポーション配列を反復処理します。 ポーションごとに`a[i]`に追加します`health`そしてそれをヒープにプッシュします。 私たちは常に現在のポーションを飲んでカウントを最大化しようとします。 
3. ポーションを追加した後、次のことを確認します。`health`はマイナスです。 その場合は、ヒープから最小のポーションを取り出し、その値を次の値から引きます。`health`。 これにより、これまでに飲んだ最も有害なポーションが効果的に廃棄され、健康状態がマイナスにならずに保たれます。 
4. すべてのポーションが処理されるまで続行します。 最終的なヒープのサイズによって、非負の健康状態を維持しながら飲むことができるポーションの最大数が決まります。 

効果がある理由: ヒープには、私たちが飲むと約束したポーションが、健康への影響が大きい順に常に保持されます。 ゼロを下回るリスクがある場合は常に最もマイナスなポーションを破棄することで、健康上の制約に違反することなくポーションの数を最大化します。 ポジティブなポーションは決して削除されず、ネガティブなポーションは絶対に必要な場合にのみ削除されるため、最終的なカウントが最適になります。 

## Python ソリューション```python
import sys
import heapq
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

health = 0
taken = []

for potion in a:
    health += potion
    heapq.heappush(taken, potion)
    if health < 0:
        smallest = heapq.heappop(taken)
        health -= smallest

print(len(taken))
```ソリューションが初期化されます`health`そして最小ヒープ`taken`。 ポーションごとに、それを追加します`health`そしてそれをヒープにプッシュします。 もし`health`ゼロ以下に下がると、最も有害なポーションが除去されます。`taken`、マイナスではない健康状態を回復します。 最後の山の長さは、まさに私たちが飲むことができるポーションの最大数です。 負の値をヒープに正しくプッシュし、ヒープから削除するときに負の値を減算するように注意する必要があります。`health`。

 | 2 | -4 | 0 | [-4、4] | ドリンク |

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | 各ポーションは最小ヒープにプッシュされ、潜在的に 1 回ポップされ、操作ごとに O(log n) のコストがかかります。 
| スペース | O(n) | ヒープには最大で n 個すべてのポーションが保存されます。 

のために$n \le 2000$、$n \log n$オペレーションは 20,000 未満で、1 秒未満に快適に収まり、ヒープは 256 MB に簡単に収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    a = list(map(int, input().split()))
    import heapq
    health = 0
    taken = []
    for potion in a:
        health += potion
        heapq.heappush(taken, potion)
        if health < 0:
            health -= heapq.heappop(taken)
    return str(len(taken))

# provided sample
assert run("6\n4 -4 1 -3 1 -3\n") == "5", "sample 1"

# custom cases
assert run("3\n5 -10 5\n") == "2", "negative recovery"
assert run("5\n-1 -2 -3 -4 -5\n") == "0", "all negative"
assert run("4\n1 1 1 1\n") == "4", "all positive"
assert run("1\n-1000000000\n") == "0", "single huge negative"
assert run("5\n10 -1 -2 5 -3\n") == "5", "mixed positive and negative"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 3\n5 -10 5 | 2 | 健全性を維持するためにスキップする必要があるネガティブな処理 |
 | 5\n-1 -2 -3 -4 -5 | 0 | ネガティブ専用ポーションは飲めません |
 | 4\n1 1 1 1 | 4 | ポジティブなポーションをすべて飲む |
 | 1\n-1000000000 | 0 | 単一の大きなマイナスのポーション |
 | 5\n10 -1 -2 5 -3 | 5 | 選択的ネガティブ除去を備えた混合シーケンス |

 ## 特殊なケース

 入力用`[5, -10, 5]`、ヒープは次から始まります`[5]`最初のポーションの後。 -10 を追加すると体力が -5 になるので、-10 をポップします。 体力は 5 に戻り、最後のポーションを安全に飲むことができ、体力 10 で終わります。出力は 2 で、まさに可能な最大値です。 これにより、アルゴリズムが、実行中のプレフィックス内の最も有害なポーションを正しく破棄して、禁止事項に違反することなくカウントを最大化していることが確認されます。
