 ## 解決策
 ## 問題の理解

 私たちには木があります$2n$頂点にはそれぞれ 1 人の人物が所属します。 すべての人は、次のいずれかに対応するバッジを持ちます。$n$各取引は人々の間でちょうど 2 回出現します。 同じ取引バッジを持っている 2 人が隣接する頂点にいる場合、取引は即座に締結され、利益が得られます。$w_i$。 

再シャッフルは 1 回許可されています。一致するエッジのセットを選択し (頂点を共有する 2 つのエッジはありません)、選択した各エッジ上の人物を交換します。 目標は、この再編後に完了した取引から得られる利益の合計を最大化することです。 

各テスト ケースは取引の数を指定します$n$、利益$w_1 \ldots w_n$、頂点上の人々の配置$a_1 \ldots a_{2n}$、そして木の端。 出力は、そのような 1 回の再シャッフル後に達成可能な最大合計利益です。 

与えられた$n$到達できる$10^5$まであるかもしれません$10^4$合計を含むテストケース$n$すべてのケースにわたって、$10^5$、私たちはおおよそより悪いものを買う余裕はありません$O(n)$テストケースごとに。 これにより、可能なすべてのマッチングやペア間のすべての交換を明示的に試みるアプローチが除外されます。 

取引の 2 つのノードがすでに隣接しているか、長さ 2 のパスを介して間接的に接続されている場合、明らかではないエッジ ケースが発生します。 たとえば、取引の 2 人がすでに隣接する頂点にいる場合、それらを別の場所に交換すると、不適切に処理された場合、実際には利益が減少する可能性があります。 もう 1 つの注意が必要なシナリオは、複数の高価値取引が隣接する頂点を共有する場合です。間違ったマッチングを選択すると、これらの利益を逃す可能性があります。 

## アプローチ

 ブルートフォースアプローチは簡単です。 ツリー内のエッジの一致の可能性ごとに、ペアを交換し、成立した取引の数を再計算します。 木があるので、$2n$頂点には$2n-1$エッジ、あります$2^{2n-1}$可能なエッジのサブセット。 頂点を共有しないマッチングの枝刈りでも、オプションの数は依然として指数関数的です。 これは明らかに不可能です$n \sim 10^5$。 

重要な洞察は、取引ごとに 2 人の位置に隣接するエッジのみを考慮すればよいことに気づくことから得られます。 各取引には正確に 2 人が含まれるため、重要な交換は 2 人の関係を近づけるものだけです。 ツリーは非巡回であるため、任意の 2 つのノード間の一意のパスは独立して考慮できます。 このパスに沿って、どのスワップによって 2 人が隣接するかを決定できます。 このパスの外側にあるエッジの場合、スワップは取引に影響を与えません。 

この観察により、問題はツリー動的プログラミング タスクに帰着します。つまり、各ノードについて、合計利益を増やすために一致するエッジに沿ってその人を交換することが有益かどうかを維持します。 マッチング (非隣接エッジ) に沿ってのみ交換できるため、各ノードでエッジを親へのマッチングに含めるかどうかを検討する DP を実行します。 これは事実上、ツリー問題における重み付けされた最大マッチングであり、重みは、そのエッジに沿ってスワップすることによって取引を締結することによって得られる潜在的な利益です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^(2n)) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各取引をマッピングする$i$木の中の二人の位置に。 これにより頂点のペアが得られます$(u_i, v_i)$取引ごとに。 
2. すでに締結されている (2 つの頂点が隣接している) 取引からの利益に対する現在の寄与を計算します。 初期化する`total_profit`この金額で。 
3. 2 人が隣接していない取引ごとに、ツリー内の 2 つの頂点間のパスを計算します。 このパスに沿ったすべてのエッジに、この取引を締結することで得られる潜在的な利益をマークします。 各エッジは、スワップ マッチングに含まれる場合に提供できる最大ゲインを認識します。 
4. ツリーに対して DP を実行して、マッチングにおけるエッジの重みの最大合計を見つけます。 各ノードについて、次の 2 つの値を維持します。`dp[node][0]`その親へのエッジがマッチングに含まれていない場合、および`dp[node][1]`それが含まれている場合。 各ノードで、すべての子を考慮します。 

1. 子へのエッジが含まれる場合は、その重量に加えて、`dp[child][0]`。 
2. 子へのエッジが除外される場合は、`max(dp[child][0], dp[child][1])`。 

ルートの最大 DP 値は、マッチング スワップを通じて達成可能な最大の追加利益を与えます。 
5. 最終的な答えは次の合計です。`total_profit`最初に締結された取引と DP の結果から。 

それが機能する理由: 各取引は最大 1 回だけ利益をもたらします。 2 つのノード間のパスに沿ってエッジをマークすることで、マッチングにエッジを含めることが取引の成立に役立つことを保証します。 ツリー DP は、マッチング制約を考慮して、2 つの隣接するエッジが同時に選択されないことを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(1 << 20)

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        w = list(map(int, input().split()))
        a = list(map(int, input().split()))
        
        pos = [[] for _ in range(n)]
        for idx, badge in enumerate(a):
            pos[badge - 1].append(idx)
        
        tree = [[] for _ in range(2 * n)]
        for _ in range(2 * n - 1):
            u, v = map(int, input().split())
            u -= 1
            v -= 1
            tree[u].append(v)
            tree[v].append(u)
        
        # Build parent and depth arrays for LCA path retrieval
        parent = [-1] * (2 * n)
        depth = [0] * (2 * n)
        def dfs(node, par):
            parent[node] = par
            for nei in tree[node]:
                if nei != par:
                    depth[nei] = depth[node] + 1
                    dfs(nei, node)
        dfs(0, -1)
        
        # Mark edge weights for potential deal gains
        edge_weight = {}
        total_profit = 0
        for i in range(n):
            u, v = pos[i]
            if v in tree[u]:
                total_profit += w[i]
                continue
            # Move u and v up to LCA
            def add_path(u, v, val):
                while u != v:
                    if depth[u] > depth[v]:
                        edge_weight[(min(u, parent[u]), max(u, parent[u]))] = max(
                            edge_weight.get((min(u, parent[u]), max(u, parent[u])), 0), val)
                        u = parent[u]
                    else:
                        edge_weight[(min(v, parent[v]), max(v, parent[v]))] = max(
                            edge_weight.get((min(v, parent[v]), max(v, parent[v])), 0), val)
                        v = parent[v]
            add_path(u, v, w[i])
        
        # Tree DP for max matching
        dp = [[0,0] for _ in range(2 * n)]
        def tree_dp(node, par):
            incl = 0
            excl = 0
            for nei in tree[node]:
                if nei == par:
                    continue
                tree_dp(nei, node)
                e = edge_weight.get((min(node, nei), max(node, nei)), 0)
                incl += dp[nei][0] + e
                excl += max(dp[nei][0], dp[nei][1])
            dp[node][0] = excl
            dp[node][1] = incl
        tree_dp(0, -1)
        print(total_profit + max(dp[0][0], dp[0][1]))

if __name__ == "__main__":
    solve()
```このソリューションは、入力の解析と取引のマッピング、取引参加者間のパスに沿ったエッジの潜在的なゲインのマーク付け、最適なマッチングを選択するためのツリー DP の実行という 3 つの主要な段階で進行します。 0 ベースのインデックス付けには細心の注意が払われ、エッジ キーの順序が一貫していることが保証され、最初に隣接性をチェックすることで二重カウントが回避されます。
