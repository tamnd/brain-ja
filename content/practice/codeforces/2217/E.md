 ## 問題の理解

 固定の順列が与えられています`p`サイズの`n`。 それぞれの立場を考えてみる`i`位置インデックスとその値という 2 つの独立したラベルを持つ点として`p_i`。 

別の順列を構築する必要があります`q`すべてのインデックスに対して`i`、インデックスの数を数えることができます`j > i`次の 2 つの条件を同時に満たします。`p_j > p_i`そして`q_j > q_i`。 このカウントは、指定されたターゲット値と一致する必要があります`d_i`。 

したがって、各ペア`(i, j)`に貢献する`d_i`場合のみ`j`の右側にあります`i`そして`j`よりも大きいです`i`両方の順列で`p`そして`q`。 タスクは割り当てることです`q`これらの支配関係により、必要なカウントが正確に生成されるようになります。 

主な難点は、`q`インデックスごとに独立していません。 割り当ては比較をグローバルに変更し、インデックスの各ペアは 2 つの異なるインデックスに影響を与える可能性があります。`d`値は順序制約に応じて非対称になります。 

制約により合計が許可されます`n`すべてのテストで最大 5000 なので、`O(n^2 log n)`あるいは`O(n^2)`ソリューションはテストごとに許容されます。 立方体的なものは最悪の場合、すでに危険です。 

主要な構造上のエッジケースは、定義からすぐに現れます。 インデックスの場合`i`有効なものがありません`j > i`と`p_j > p_i`、それからその`d_i`ゼロでなければなりません。 ゼロ以外の場合、答えは不可能です。 これは、優勢には両方の座標が厳密に増加する必要があるためです。`p_i`はすでに接尾辞の最大値であるため、今後のインデックスはそれを超えることはできません`p`。 

もう 1 つの微妙なケースは、実現可能性は各ポジションに有力な候補者が何人存在するかによって決まるということです。 候補者が存在する場合でも、すべての組織に一貫して候補者を配分できなければなりません。`d_i`順列制約に違反しない値`q`。 

## アプローチ

 ブルートフォース戦略では、すべての順列が試行されます。`q`そして各インデックスの優勢カウントを計算します。 候補者ごとに`q`、すべてのペアをスキャンします`(i, j)`誘導されたカウントが一致するかどうかを確認します`d`。 これには費用がかかります`O(n^2)`順列ごとに、`n!`順列は、たとえ`n = 10`。 

構築する少し賢い総当たり力さえも`q`各配置は非局所的な方法で将来の支配関係を変更するため、漸進的には依然として組み合わせ爆発に直面しています。 

重要な洞察は状態を再解釈することです`p_j > p_i and j > i`によって引き起こされる固定半順序として`p`そしてインデックスの順番。 私たちに与えられた唯一の自由は、`q`。 一度`p`固定、各インデックス`i`には、それを支配する可能性のある一連の潜在的な後継者がいます。 このうち、私たちが気にするのは、彼らが`q`値がより大きい`q_i`。 

これにより、問題は順列の構築に変換されます。`q`それぞれの位置が`i`まさに`d_i`有効なサクセサの既知のセットの中の「larger-q サクセサ」。 これは、ソートされた位置に対する貪欲な割り当てのように動作する実現可能性制約を尊重しながらランクを割り当てることと同じです。 

正しいアプローチは、インデックスを降順に処理することです。`p`そして割り当てます`q`利用可能な「将来有効な」ポジションがどれだけ残っているかを追跡する構造を維持しながら、昇順で。 値を割り当てるたびに、残りを満たすために正確な数の将来の候補が消費されることを確認します。`d`。 

私たちはこの問題をインデックス順に並べられた動的セットに対する貪欲な構造に落とし込み、必要な位置を常に選択します。`d_i`残りのサフィックスの利用可能な容量と一致します。

 ## アルゴリズムのチュートリアル

 私たちは構築します`q`ただし、サフィックスの残りの容量を追跡する構造を使用して実現可能性を維持します。 

1. インデックスを降順に並べ替えます`p_i`。 これにより、インデックスを処理する際に、可能な限りすべてのことが確実に行われます。`j > i`と`p_j > p_i`より優先度の高い決定がまだ割り当てられていません。 この順序付けにより、依存関係の方向が処理順序と一致します。 
2. 将来のドミネーターとしてカウントされる資格のあるアクティブなインデックスのデータ構造を維持します。 各アクティブなインデックスは潜在的なインデックスに対応します。`j`以前に処理されたインデックスの場合。 
3. インデックスごとに`i`減少中`p_i`で位置を決めます。`q`現在アクティブな要素を基準にして、正確に`d_i`アクティブな要素はその後ろに配置されます`q`。 
4. これを実現するために、フェンウィック ツリー、つまりポジション間のバランスの取れた構造を維持します。`q`以下をサポートします:

 - 新しいインデックスの挿入、
 - 指定された位置の後に現在配置されているアクティブな要素の数を数えます。 
- 特定の「反転のランク」が発生する位置を見つける。 
5. 割り当てます`q`値を貪欲に処理する: インデックスを順番に処理し、右側に要素の数が多くなる構造にインデックスを配置します。`q`マッチ`d_i`。 
6. どこかの段階で`d_i`利用可能な将来互換性のある要素の数を超えると、直ちに不可能と結論付けられます。 
7. それ以外の場合は、有効な順列を抽出します`q`構築された順序から。 

重要な操作は、挿入ごとに、必要な支配数と正確に一致する固定数の大きな要素をその右側に強制することです。 

### なぜ効果があるのか

 現時点ではインデックスを処理しています`i`、両方の次元でそれを支配する可能性のあるすべてのインデックスは、アクティブな構造ですでに考慮されています。 どこに置くかの選択`i`進化する順列の中で`q`これらのアクティブな要素のうちのいくつがその右側に配置されるかを正確に決定します。 支配力はそれだけに依存するので、`j > i`、`p_j > p_i`、 そして`q_j > q_i`を減少させて処理します。`p`、有効なセット`j`は、まさに現在のアクティブ セットです。 したがって満足のいく`d_i`ローカルでグローバルに正しさを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

    def kth(self, k):
        cur = 0
        bitmask = 1 << (self.n.bit_length())
        while bitmask:
            nxt = cur + bitmask
            if nxt <= self.n and self.bit[nxt] < k:
                k -= self.bit[nxt]
                cur = nxt
            bitmask >>= 1
        return cur + 1

def solve():
    n = int(input())
    p = list(map(int, input().split()))
    d = list(map(int, input().split()))

    order = sorted(range(n), key=lambda i: -p[i])

    bit = Fenwick(n)
    used = 0

    q = [0] * n

    for i in order:
        if d[i] > used:
            print(-1)
            return

        pos = used - d[i] + 1
        idx = bit.kth(pos)

        q[i] = idx
        bit.add(idx, 1)
        used += 1

    print(*q)

t = int(input())
for _ in range(t):
    solve()
```フェンウィック ツリーは、どの位置にあるかを維持します。`q`すでに占領されています。 変数`used`これまでに配置された要素の数を追跡します。 インデックスごとに`i`、アルゴリズムは、正確に挿入される必要がある位置を決定します。`d[i]`すでに配置されている要素は、最終的にはその右側に配置されます。`q`。 

の`kth`クエリは実際の位置を見つけます`q`これは必要な反転構造に対応します。 これは、抽象的な要件「正確に持っている」を変換します。`d_i`「私の後の大きな要素」を具体的な位置選択問題に当てはめます。 

減少による順序付け`p`ポジションを割り当てるたびに、将来の有効なドミネーターがすべてシステム内にすでに存在することが保証されます。

 ## 特殊なケース

 インデックスがサフィックスの最大値である場合、重大なエッジ ケースが発生します。`p`。 例えば：```

貪欲な構造はこれも自然に処理します。`p=3`、肯定的な意見を正当化できる現役の候補者はいません。`d`。 ゼロ以外の要件を割り当てようとすると、条件に違反します。`d[i] ≤ used`、失敗を引き起こします。
