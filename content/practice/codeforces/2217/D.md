 ## 解決策
 ## 問題の理解

 バイナリ配列と、すべての値が同一である特別なインデックスのセットが与えられます。 私たちの目標は、最小限の反転操作を使用して、配列全体をこれらの特別なインデックスの値と等しくすることです。 反転操作を使用すると、少なくとも 1 つの特別なインデックスを含む連続したサブ配列を選択し、そのサブ配列内のすべてのビットを反転できます。 

この問題では複数のテスト ケースを処理する必要があり、すべてのケースの配列サイズの合計は 200,000 に達する可能性があります。 これにより、可能なすべての部分配列を明示的に検査する解決策は除外されます。これは、二次関数以上になるためです。 代わりに、配列の長さにおいて線形またはほぼ線形に機能するアプローチが必要です。 

特別な値とは異なる連続ビットが存在するが、セグメント内に特別なインデックスがない場合、微妙なエッジ ケースが発生します。 すべての違いを反転する単純なアプローチでは、特別なインデックスを含めずにセグメントを反転しようとする可能性がありますが、これは無効です。 もう 1 つのエッジ ケースは、配列がすでに均一である場合です。 正しい答えは反転がゼロですが、不注意で貪欲な戦略により、不必要にセグメントを反転しようとする可能性があります。 たとえば、配列の場合`[1,1,1,1]`特別なインデックスを使用した`[2,3]`、必要な最小限のフリップは次のとおりです。`0`。 

## アプローチ

 ブルートフォース ソリューションでは、すべての要素を反復処理し、特別な値と異なる場合は、特別なインデックスを含むすべての可能な範囲を試して反転します。 最終的にはすべてのビットが一致するため、これは原理的には正しいですが、テスト ケースごとに最大 O(n^2) の演算を実行するため、n が 200,000 までの場合は遅すぎます。 

最適なソリューションを実現するための重要な洞察は、特別な値とは異なる要素の連続したセグメントのみを考慮する必要があるということです。 このような各セグメントは、セグメントの最初の要素から両側の最も近い特殊インデックスまでを拡張する 1 回のフリップで無効化できます。 これが機能するのは、各フリップに少なくとも 1 つの特別なインデックスを含めることができ、セグメント全体を反転して、セグメント内のすべてのビットを正しい値にすることができるためです。 配列を左から右に処理し、1 回の操作で各「間違った」セグメントを貪欲に反転することで、配列全体を効率的にカバーできます。 

貪欲なアプローチが機能するのは、問題が線形であるためです。間違ったセグメントの外側のビットを反転する必要はなく、反転は重複しないセグメントに対して冪等です。 範囲に特別なインデックスが含まれている場合は 1 回の操作で十分であるため、重複するセグメントや同じセグメント上の複数の反転を考慮する必要はありません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取ります。 各テスト ケースについて、n、k、配列を読み取ります。`a`、および特別なインデックスのリスト`p`。 変換する`p`配列の処理を容易にするために、ゼロベースのインデックスに変更します。 
2. 目標値を決定する`x`特別なインデックスで。 すべての特別なインデックスは同じ値を持つことが保証されているため、次の値を選択できます。`a[p[0]]`。 
3. カウンタの初期化`ops`ゼロとインデックスへ`i`ゼロに。 配列を左から右にスキャンします。 
4. ながら`i`未満です`n`、どうかを確認してください`a[i]`等しい`x`。 そうなった場合はインクリメントします`i`そして続けます。 
5. もし`a[i]`とは異なります`x`、反転する必要があるセグメントの始まりが見つかりました。 インクリメント`ops`1.その後移動します`i`次の要素に到達するまで前進します`x`または配列の終わり。 これにより、1 回の操作で間違ったセグメント全体がスキップされます。 
6. アレイが終了するまで手順 4 ～ 5 を繰り返します。 加工後、`ops`必要な最小限の操作が含まれています。 

貪欲なアプローチが機能するのは、ビットのすべてのセグメントが異なるためです。`x`少なくとも 1 回は反転する必要があります。 フリップを最も近い特殊なインデックスに拡張することにより、すべてのフリップに特殊なインデックスが含まれるという制約が満たされます。 セグメントが一度反転されると、そのビットは一致するため、重複するセグメントを反転する必要はありません。`x`そして再びひっくり返されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        p = list(map(int, input().split()))
        p = [pi - 1 for pi in p]  # convert to 0-based
        x = a[p[0]]  # target value
        ops = 0
        i = 0
        while i < n:
            if a[i] == x:
                i += 1
            else:
                ops += 1
                while i < n and a[i] != x:
                    i += 1
        print(ops)

if __name__ == "__main__":
    solve()
```コードは、入力を読み取り、特殊なインデックスをゼロベースに変換することから始まります。 ターゲット値は、最初の特別なインデックスから取得されます。 配列をスキャンし、異なるセグメントが見つかるたびに、`x`、操作カウンターをインクリメントし、セグメント全体をスキップします。 これにより、各フリップが最小限かつ必要であることが保証されます。 while ループは次の時点で停止するため、境界条件は自然に処理されます。`n`。
