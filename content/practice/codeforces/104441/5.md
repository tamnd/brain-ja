 ## 解決策
 ## 問題の理解

 2 つの条件を同時に満たす 1 から n の範囲の整数を数えるように求められます。 まず、数値が偶数である必要があります。 次に、その数値を 2 進数で記述する場合、設定ビットの数、つまり 2 進数表現における 1 の数も偶数でなければなりません。 

したがって、組み合わせたパリティ制約によって最大 n までの自然数の接頭辞をフィルタリングしています。つまり、値自体のパリティとそのポップカウントのパリティは両方ともゼロでなければなりません。 

制約 n は最大 10^9 であり、これはバイナリ表現が最大 30 ビットであるほど十分に小さいです。 これは、固定数の位置でビット単位の数字 DP を操作できることをすぐに示唆しています。 n までの総当たりスキャンも、10^5 付近の n では実行可能ですが、10^9 では完全に不可能です。 

素朴なアプローチは、1 から n までのすべての数値を反復処理し、それぞれのポップカウントを計算することです。 これは正しいですが、O(n log n) ビット演算を実行し、上限では約 10^9 演算に達するため、最悪の場合は遅すぎます。 それは制限時間を超えます。 

微妙なエッジ ケースは、パリティの相互作用から発生します。 たとえば、1、3、5 などの数値は奇数であるため、ポップカウントに関係なく除外されます。 ただし、2 (10₂) や 6 (110₂) のような数値は両方の制約に依存し、どちらかの制約が欠けていると過剰カウントにつながります。 

もう 1 つの微妙な点は、popcount パリティの数値が単調ではないことです。 隣接する数値はキャリーにより最後のビットと複数の上位ビットの両方を反転する可能性があるため、プレフィックスベースの推論では状態を明示的にエンコードする必要があります。 

## アプローチ

 ブルート フォース戦略は簡単です。1 から n までのすべての整数 x を反復処理し、x が偶数であるかどうかを確認し、バイナリ表現で 1 の数を計算し、その数が偶数であるかどうかをテストします。 これは、定義を直接適用するため、正しいです。 

このコストは、数値ごとにポップカウントを繰り返し計算することで発生します。 各ポップカウントは O(log n) であり、n 個の数値があるため、O(n log n) となります。 n = 10^9 の場合、これは実現可能な限界をはるかに超えています。 

重要な観察は、私たちが関心があるのは数値の正確な値ではなく、そのバイナリ構造とパリティ特性だけであるということです。 これは、数値をビット文字列として扱い、制約を追跡しながら数字を 1 桁ずつ構築することを示唆しています。 n は最大 30 ビットなので、バイナリ表現ではなく標準的な数字 DP を使用できます。 

最上位から最下位の順にビットを処理し、次の 3 つの状態を維持します。つまり、プレフィックス n がまだタイトであるかどうか、現在構築されている数値がすでに偶数であるか奇数であるか (より直接的には、配置する最後のビットがパリティを決定します)、そしてこれまでに確認された 1 の数のパリティです。 

数値自体のパリティは最後のビットのみに依存するため、値のパリティに完全な状態は必要なく、最後に最下位ビットがゼロであることを確認するだけです。 これは、DP では有効な補完のみを考慮することによって当然強制されます。 

問題は、最後のビット 0 およびポップカウントで 2 進数 ≤ n をカウントすることに帰着します。

 | ブルートフォース | O(n log n) | お(1) | 遅すぎる |

 ## アルゴリズムのチュートリアル

 n のバイナリ表現に対して数字 DP を使用して問題を解決します。

1. n を、最上位から最下位までのビットのリストとしてバイナリ表現に変換します。 これにより、プレフィックスごとに一致する固定長表現が得られます。 
2. DP 関数 dp(pos, tiny, ones_parity, last_bit) を定義します。ここで、pos は現在のビット インデックス、tight はこれまでのプレフィックスが n のプレフィックスと正確に等しいかどうかを示し、ones_parity はこれまでに使用された 1 の数が偶数か奇数かを追跡し、last_bit は最後に偶数を強制できるように最後に選択されたビットを追跡します。 
3. 各位置に 0 または 1 を配置してみます。tight が true の場合、n の対応するビットを超えることはできません。 それ以外の場合は、0 または 1 を自由に選択できます。 
4. ビットを配置するとき、ビットが 1 の場合は、ones_parity を切り替えて更新します。また、last_bit を選択した値に更新します。 
5. 最終位置に到達すると、last_bit が 0 (偶数であることが保証される) であり、ones_parity が偶数である場合にのみ、数値を受け入れます。 
6. 最上位ビットから始まるすべての有効な補完を合計します。 

機能する理由: DP は、すべてのプレフィックスで、将来の有効性を決定するために必要なパリティ関連情報を正確に保存します。 同じ位置、タイトなステータス、1 のパリティ、および最後のビットを共有する 2 つのプレフィックスは、残りの決定がこれまでに構築された正確な数値ではなく、これらの値のみに依存するため、交換可能です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    n = int(input().strip())
    bits = list(map(int, bin(n)[2:]))
    L = len(bits)

    from functools import lru_cache

    @lru_cache(None)
    def dp(pos, tight, ones_parity, last_bit, started):
        if pos == L:
            if not started:
                return 0
            return int(last_bit == 0 and ones_parity == 0)

        limit = bits[pos] if tight else 1
        res = 0

        for b in range(limit + 1):
            ntight = tight and (b == limit)
            nstarted = started or (b == 1)

            if not nstarted:
                # still leading zeros
                res += dp(pos + 1, ntight, 0, 0, nstarted)
            else:
                npar = ones_parity ^ (b == 1)
                res += dp(pos + 1, ntight, npar, b, nstarted)

        return res

    print(dp(0, 1, 0, 0, 0))

if __name__ == "__main__":
    solve()
```この解決策は、ビット位置に対するメモ化された再帰を使用します。 の`tight`flag は上限 n を強制します。 の`ones_parity`変数は、XOR 累積を使用して設定ビットのパリティを追跡します。 の`started`flag は、未使用のプレフィックス ビットがポップカウントまたはパリティ制約に寄与するものとして誤って扱われないように、先行ゼロを処理します。 

の`last_bit`これは、数値が偶数である必要があるという要件を強制するために追跡されます。これは、有効なゼロ以外の数値において構築された最下位ビットがゼロであることを保証することと同じです。 

## 実用的な例

 ### 例 1: n = 20 (10100₂)

 DP の決定を高レベルで追跡します。 

| 位置 | タイト | ワンズパリティ | 最後のビット | 始めました | アクション |
 | --- | --- | --- | --- | --- | --- |
 | 0 | 1 | 0 | 0 | 0 | 1 または 0 を選択してください |
 | 1 | さまざまです | さまざまです | さまざまです | 1 | 有効なプレフィックスを調べる |
 | 最終 | - | - | - | - | 有効な結末を数える |

 DP は、10100₂ 以下のすべての 2 進数を検索し、偶数のポップカウントで 0 で終わるものをフィルターします。 有効な数値は 2、4、8、10、20 で、出力は 5 になります。 

これにより、DP がプレフィックス制限とパリティ制限の両方を同時に正しく処理することが確認されます。

 ## 特殊なケース

 1 つのエッジ ケースは n = 1 です。唯一の数値は 1 であり、これは奇数であるため、数えてはなりません。 last_bit = 1 で終わる構築された数値は最終状態で拒否されるため、DP はこれを処理します。 

もう 1 つのエッジ ケースは、2 のような小さな偶数です。バイナリは 10₂、ポップカウントは 1 で、奇数であるため除外されます。 DP は、ones_parity を正しく伝播し、リーフで拒否します。 

さらなるケースは 2 の累乗です。 これらには常に 1 つのセットビットがあるため、popcount パリティは常に奇数であり、0 を除く 2 の累乗は適格ではないことを意味します。 DP はこれを自然にエンコードします。ones_parity はシングルホット ビット パターンに対して 1 になり、ビットを追加しない限り 0 に戻ることはなく、タイト モードの境界を超えるためです。
