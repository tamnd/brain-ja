 ## 解決策
 ## 問題の理解

 このタスクは、休憩時間で区切られた繰り返しの作業ブロックで構成されるトレーニング セッションの合計時間を計算することです。 各トレーニング セッションは次の内容で構成されます$N$同一のセット。 1 セットにかかる時間は分と秒で指定されます。 連続する 2 セットごとに、秒単位で測定される固定の休憩があります。 

出力は、すべてのセットと休憩に費やした合計時間を分と秒に正規化したものです。 これは、最初にすべてを 1 つの単位 (最も自然には秒) に蓄積し、次に標準の分と秒の表現に変換し直す必要があることを意味します。 

制約は小さいです。$N \le 100$、1セットあたりの分と秒は59で制限されており、休憩は最大120秒です。 これにより、オーバーフローやパフォーマンスのプレッシャーに関する懸念が排除されます。 定数時間の算術ソリューションで十分です。 

通常、間違いが発生する主な場所は、単位の変換と休憩の数の処理です。 まさにあります$N - 1$休憩ではなく$N$。 よくある誤った想定は、休憩時間を次のように掛けることです。$N$これにより、最終セットの後に誤って余分な休憩時間が追加されてしまいます。 

もう 1 つの微妙な問題は正規化です。 合計秒数が 60 を超える場合は、分に繰り越す必要がありますが、残りの秒数が 60 を法として減らされることも確認します。 

具体的な失敗例としては、$N = 1$。 この場合、休憩はまったくあってはならない。 たとえば、1 セットが 2 分 30 秒、休憩が 100 秒であるとすると、単純な式は次のようになります。$N \cdot \text{set} + N \cdot \text{break}$トレーニングが一時停止しない場合でも、誤って休憩を追加してしまう可能性があります。 

## アプローチ

 ブルート フォース シミュレーションでは、各セットを明示的にモデル化し、その期間を追加し、最後を除く各セットの後にブレークを追加します。 This approach is already linear in$N$、そしてそれ以来$N \le 100$、快適に過ぎます。 ただし、この構造は純粋に算術集計であり、セット間に分岐依存関係がないため、これは不要です。 

重要な観察は、すべてのセットが同一であり、すべてのブレークが同一であることです。 これにより、プロセス全体が直接和に分解されます。合計時間は次のとおりです。$N$1 セット持続時間の倍とプラス$(N - 1)$休憩時間の倍。 すべてを秒単位で表現してしまえば、あとは整数演算と変換だけです。 

ブルートフォースは実際のプロセスを反映するため機能しますが、反復ごとに何も変わらないため冗長になります。 繰り返しが一様であるという観察により、繰り返しを 1 つの欠落したブレークの乗算と減算に置き換えることができます。

 ## アルゴリズムのチュートリアル

 ## アルゴリズムのチュートリアル

 1. 計算により 1 つのトレーニング セットを合計秒数に変換します$M \cdot 60 + S$。 これにより単一の単位表現が得られるため、後の算術演算に一貫性があり、単位混合エラーが回避されます。 
2. 単一セットの所要時間に次の値を掛けて、すべてのセットに費やした合計時間を計算します。$N$。 これは、アクティブなトレーニング セグメントごとに考慮されます。 
3. 合計休憩時間を乗算して計算します。$P$による$N - 1$。 1 の減算は、シーケンス内の唯一の不連続点である最後のセットの後にブレークがないことを反映しています。 
4. 合計設定時間と合計休憩時間を加算します。 この時点で、構造的なギャップのないスケジュール全体を表す完全な期間が秒単位で得られます。 
5. 合計秒を 60 で割って分と秒に変換します。商が分、余りが秒になります。 

機能する理由: トレーニング スケジュールは、継続時間が順序や状態に依存しない、ばらばらの時間間隔を連結したものです。 すべてのセットは固定の追加量に寄与し、最後のセットを除くすべてのブレークは固定の追加量に寄与します。 加算は結合的かつ可換であるため、構造を同一のセグメントの数に折りたたむと、合計期間が正確に保存されます。 分と秒への変換は純粋に表現ステップであり、計算された数量は変更されません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    N = int(input())
    M = int(input())
    S = int(input())
    P = int(input())

    set_seconds = M * 60 + S
    total_sets = N * set_seconds
    total_breaks = (N - 1) * P if N > 1 else 0

    total = total_sets + total_breaks

    minutes = total // 60
    seconds = total % 60

    print(minutes)
    print(seconds)

if __name__ == "__main__":
    main()
```この解決策は、各セットを秒単位に正規化することから始まります。これにより、蓄積中に繰り返しキャリー処理を行う必要がなくなります。 の乗算$N$同一のセグメントを効率的に集約します。 ブレーク計算は明示的に保護します。$N = 1$この場合、式はあるものの、$(N - 1) \cdot P$すでに自然にゼロが生成されます。 警備員は単に意図を明示するだけです。 

最後に、逆変換では整数の除算とモジュロが使用され、秒数が以内に残るようにします。$[0, 59]$、必要に応じて。
