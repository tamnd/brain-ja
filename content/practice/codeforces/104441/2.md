 ## 解決策
 ## 問題の理解

 私たちは、1 から N までラベル付けされた TV チャンネルの線形シーケンスを操作しています。リサは、あるチャンネル P から開始し、2 つのボタンのあるリモコンを使用して別のチャンネル U に到達したいと考えています。 

各ボタンには、押し方に応じて 2 つの動作があります。 短く押すと、1 から N の範囲内に留まりながら、正確に 1 つのチャネルを前方または後方に移動します。長押しすると、サイズ K のより大きなジャンプで移動します。ここでも、ジャンプが境界を越える場合は、最も近いエンドポイント、つまりチャネル 1 またはチャネル N にスナップするという特別なルールが適用されます。 

タスクは、P から U に移動するために必要なボタンを押す最小回数を計算することです。 

構造上の重要な点は、すべての動きには単位コストがあるが、利用できる動きは均一ではないということです。境界クランプを使用して、1 または K ずつシフトすることができ、エッジ付近の大きなジャンプを効果的に「終点へのテレポート」動作に変えることができます。 

制約により N は 10^9 まで許可されるため、ライン全体にわたってプロセスをシミュレートすることはできません。 N での線形時間ですら不可能であるため、チャネルを個別に訪問することに依存する解決策は、すぐに遅すぎます。 

チャネル上の単純な BFS は、各チャネルをノードとして扱い、各ボタンのアクションをエッジとして扱います。 それは原理的には正しいでしょうが、状態空間が大きすぎます。 

境界では微妙なエッジの動作もあります。 たとえば、K が大きく、チャネル N の近くにいる場合、長押しは K だけ移動せず、直接 N に到達します。このクランプを無視する不用意なモデルでは、端近くで誤った遷移が生成されますが、実際には、この境界動作は内部点間の最短パスの最適な構造を変更しません。 

誤った推論を明らかにするいくつかの特殊なケース:

 N = 20、K = 5、P = 18、U = 19 の場合、単純な「常に最初に K ジャンプを使用する」戦略は失敗します。5 ジャンプするとすぐに 20 に到達し、進行状況が無駄になるためです。 

P = 2、U = 17、K = 5 の場合、常に +1 または -1 を使用することは正しいですが、最適とは言えません。これは、K ジャンプを混合するとステップが大幅に削減されるためです。 

これらのケースは、問題は、貪欲に 1 つのタイプを選択することではなく、小さなローカル ステップと大きなジャンプのバランスをとることであることを示しています。 

## アプローチ

 ブルート フォース解釈では、各チャネルがグラフ内のノードとして扱われます。 各位置 i から、境界でクランプしながら、i−1、i+1、i−K、または i+K に移動できます。 P から U への BFS は、移動するたびに 1 回押す必要があるため、最短経路を正しく計算します。 

これが機能するのは、グラフが重み付けされておらず、遷移が決定的であるためです。 障害点はスケールです。グラフには最大 10^9 ノードがあるため、BFS は完全に実行不可能です。 

重要な観察は、境界クランプを無視すると、システムは無限の整数線のように動作するということです。 どの位置からでも、移動は ±1 および ±K ずつ対称にシフトします。 これにより問題は変換不変となり、答えは差 d = |P − U| のみに依存します。 

位置について推論する代わりに、サイズ 1 と K の演算を使用して変位 d を表現する方法を推論します。方向に関係なく、各演算のコストはちょうど 1 です。 

一連の動きは 2 種類の寄与に再配置できます。1 つは K ブロック単位で位置をシフトする K ステップ、もう 1 つは ±1 ステップを使用する残りの調整です。 x K ステップをネットすることを選択した場合、合計で x・K を移動し、|d − xK| を使用して残りの距離を固定します。 単一のステップ。 総コストは |x| になります。 + |d − xK|。 

したがって、問題は、整数 x に対する単純な関数を最小化することに帰着します。 この関数は区分的に線形で凸であるため、絶対値式の動作が変化する点 (x = 0 および x ≈ d/K) の近くで最小値が発生します。 

これらのブレークポイント付近で一定数の候補をテストするだけで済みます。

 ## アルゴリズムのチュートリアル

 方向は重要ではないので、問題を P と U の間の距離に取り組むことに集約します。 

### ステップ

 1. d = |P − U| を計算します。 これにより、サイズ 1 または K の手を使用して 0 から開始して距離 d に到達する問題に問題が変換されます。すべての手に同じコストの逆の手が含まれるため、対称性が機能します。 
2. サイズ K (x は正または負) の x 回のロングジャンプを使用することにした場合、それらの操作を使用して x・K 距離をカバーすることに効果的に取り組んでいることに注目してください。 残りのギャップは±1手で埋める必要があります。 
3. 総コストを関数 f(x) = |x| として表現します。 + |d − xK|。 最初の項は長押しをカウントし、2 番目の項は残りの距離を修正するために必要な短押しをカウントします。 
4. 関数が傾きを変更できる x の候補値を特定します。 これらは、x が 0 と交差するとき、および d − xK が 0 と交差するときに発生します。これは、x ≈ d/K に相当します。 
5. x = 0、x = Floor(d/K)、および x = Floor(d/K) + 1 で f(x) を評価します。これらの点は、絶対値構造が変化するすべての区間をカバーします。 
6. これらの評価の最小値を答えとします。 

### なぜ効果があるのか

 x と (d − xK) の符号が変化しない固定領域では、関数は x において線形です。 線形関数は内部最小値を持つことができないため、最適な値は領域間の境界で発生する必要があります。 これらの境界は、x = 0 および x = d/K で正確に発生します。 x は整数であるため、これらのブレークポイントの周囲で最も近い整数をチェックすると、最適な解が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    N = int(input())
    K = int(input())
    P = int(input())
    U = int(input())

    d = abs(P - U)

    # candidates for number of K-steps
    candidates = set()

    # around 0
    candidates.add(0)

    # around d/K
    x = d // K
    for c in [x - 1, x, x + 1]:
        candidates.add(c)

    ans = 10**30

    for x in candidates:
        cost = abs(x) + abs(d - x * K)
        if cost < ans:
            ans = cost

    print(ans)

if __name__ == "__main__":
    solve()
```解決策は、問題を単一の整数距離に縮小することから始まります。 候補のセットは、コスト関数のすべての意味のあるブレークポイントをカバーするように選択されます。 ループ内の式は、派生コスト式を直接実装します。ここで、1 つの項は ​​K ジャンプを考慮し、もう 1 つの項は残留 1 ステップ補正を考慮します。 

最良の戦略は K ジャンプを完全に回避する可能性があるため、x = 0 を明示的に含める場合には注意が必要です。 d // K の周囲の範囲により、大きなジャンプの使いすぎと使いすぎの両方を確実にテストできます。

 ## 特殊なケース

 P と U が隣接している場合、最適解は K に関係なく常に 1 を返す必要があります。この状況では d = 1 となり、関数の評価では当然 x = 0 が優先され、コスト 1 が与えられます。 

K が距離より大きい場合、ロングジャンプはすぐにオーバーシュートしてしまうため、事実上使用できなくなります。 たとえば、N = 100、K = 50、P = 10、U = 12 の場合、d = 2 となります。 x ≠ 0 の場合は、1 回の K ジャンプでも不要な修正が強制されるため、コストが増加します。そのため、アルゴリズムは ±1 の動きのみを正しく選択します。 

P が一方の境界の近くにあり、U がもう一方の境界の近くにある場合、クランプによって境界テレポートへの大きなジャンプが効果的に低減されるため、K ジャンプによるオーバーシュートが最適になる可能性があります。 |d − xK| による負の残差補正が可能であり、物理パスが境界に触れている場合でもオーバーシュートをきれいに考慮できるため、この式はこれを引き続き捉えています。
