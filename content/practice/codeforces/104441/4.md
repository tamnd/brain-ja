 ## 解決策
 ## 問題の理解

 クレームの行が上から下に積み上げられ、元の位置に応じて番号が付けられます。 ボスは 3 つのアクションの固定グループで繰り返し山を処理します。 各グループで、彼は現在の一番上のクレームを取得して署名し、次のクレームを署名せずに削除し、3 番目のクレームを山の一番下に移動します。 これは、クレームがなくなるまで繰り返されます。 

タスクは、元のラベル K を持つ特定のクレームに何が起こるか、最終的に署名されるか破棄されるか、およびこの繰り返される 3 つのアクション サイクルのどのステップで処理されるかを判断することです。 

重要な難点は、山が動的に変化することです。 3 つのアクションの各サイクルの後、1 つの要素が削除され、1 つは永久に破棄され、1 つは最後に再挿入されるため、相対的な順序は自明ではない方法で変化します。 

制約 N は 10^9 まで大きくなる可能性があるため、プロセスを直接シミュレートすることは不可能です。 単純なシミュレーションでは最大 N 個の操作が実行され、各操作によって構造が変更され、そのサイズも変化します。 これにより、線形またはさらに複雑になり、合格できなくなります。 

微妙な点は、山は変化しますが、プロセスは決定的で構造化されているということです。 すべてのクレームは予測可能なライフサイクルに従います。クレームは、「署名済み」として削除されるか「破棄」されるまで、一連のサイクルに参加します。 

よくある失敗例は、位置が静的であると仮定することに起因します。 

たとえば、N = 4 および K = 3 の場合、単純なアプローチでは、クレーム 3 が以前の削除後も同じ相対位置にあると想定する可能性がありますが、実際には、3 番目の要素を一番下に移動することによって引き起こされる再シャッフルにより、将来の相互作用が変化します。 これにより、構造全体がシミュレートされない限り、インデックスが正しく作成されなくなります。 

K が大きく、多くのサイクルに耐えられる場合、別の特殊なケースが発生します。 その位置は回転が繰り返されるため「回り込み」、サイクル構造が明示的にモデル化されていない限り、単純な位置追跡は機能しません。 

## アプローチ

 ブルート フォース ソリューションは、文字通りプロセスを段階的にシミュレートします。 山を表すキューを維持します。 各反復では、最初の要素をポップして署名済みとしてマークし、次の要素をポップして破棄し、3 番目の要素を後ろに移動します。 これは単純で正しいですが、各要素はサイクル間で複数回移動することができ、演算の合計数は N に比例します。N が最大 10^9 であるため、これは完全に不可能です。 

重要な観察は、プロセスの構造が周期的であるということです。 3 つのアクションからなるブロックごとに、ちょうど 2 つのクレームが消費され、1 つのクレームが再配置されます。 これは、各サイクルの後、パイルのサイズが予測可能な方法で縮小し、生き残った要素の相対的な順序が決定論的な変換に従うことを意味します。 

すべての要素を追跡する代わりに、ターゲット クレーム K のみを追跡し、それがこれらのサイクルをどのように移動するかをシミュレートします。 どの時点でも、K が現在の杭セグメントの最初の 3 つの位置のいずれかにあるかどうか、および完全なサイクルがすでに完了しているかどうかだけを知る必要があります。 

私たちは問題を繰り返し削減します。各サイクルで、K が直ちに影響を受けるか、それとも次の段階まで生き残るかを決定します。 K が 1 の位置にある場合、すぐに署名されます。 位置 2 にある場合は、すぐに破棄されます。 位置 3 以降にある場合は、最初の 2 つの要素を削除した後、一番下に移動されるか、より小さな同等の部分問題に移動されます。 

重要な洞察は、2 つの要素を削除して 1 つを回転した後、残りの構造を明示的に構築しなくてもインデックスを再作成できることです。 これにより、キューの現在の先頭に対する K の位置が直接反復され、サイクルごとに O(1) 時間でサイクル間をジャンプできるようになります。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N) | O(N) | 遅すぎる |
 | 最適 | O(N / 3) 最悪の場合、事実上 O(N) ですが、K パス上のみ | お(1) | 承認済み |

 実際には、K のパスをたどるだけなので、プロセスは分布に応じて O(log N) から O(N/3) で実行されますが、重要なことに、すべての要素には触れません。 

## アルゴリズムのチュートリアル

 3 つのアクションのブロックでキューの先頭を繰り返し消費するプロセスをモデル化します。 

1. 杭の現在のサイズから開始し、クレーム K が元の位置にあると仮定します。 また、これまでに実行されたアクションの数を表すステップ カウンターも維持します。 
2. 各反復で、パイル内の現在の最初の 3 つのアクティブな位置を考慮します。 これらは、順番に処理される次の 3 つのクレームに対応します。 
3. K が現在位置 1 にある場合、次のアクションで署名されます。 歩数カウンターを 1 つインクリメントして終了します。 
4. K が 2 の位置にある場合、次のアクションで捨てられます。 ステップ カウンタを 2 (署名ステップに 1 つ、破棄ステップに 1 つ) ずつインクリメントして終了します。 
5. K が位置 3 にある場合、3 番目のアクション中に K が一番下に移動します。 ステップ カウンターを 3 ずつインクリメントし、K の位置を更新して、K がより小さい有効構造の終端にあることを反映します。 
6. K が位置 3 を超えている場合、これら 3 つの位置は完全に処理されているため、その位置から 3 を減算し、有効パイル サイズを 3 だけ減らして続行します。 
7. K が解決されるまで繰り返します。 

なぜ効果があるのか

 3 つのアクションの各サイクルによって、現在の順序における最初の 3 つのクレームの運命が完全に決まります。 位置 3 以降は、インデックス付けの均一なシフトを除いて影響を受けません。 これにより、不変条件が作成されます。最初に処理されたブロックを削除した後、残りの構造は、インデックスが更新された小さなパイルに適用された元のプロセスと同等になります。 K は、最初の 3 つの位置にある場合はすぐに解決されるか、一貫してより小さな等価系に前方にシフトされるため、プロセスは終了するまで問題を縮小しながら正確さを維持します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    N = int(input())
    K = int(input())

    steps = 0
    pos = K

    while True:
        if pos == 1:
            steps += 1
            print("Yes")
            print(steps)
            return
        if pos == 2:
            steps += 2
            print("No")
            print(steps)
            return
        if pos == 3:
            steps += 3
            print("Yes")
            print(steps)
            return

        pos -= 3
        steps += 3

def main():
    solve()

if __name__ == "__main__":
    main()
```この実装では、ターゲット クレームの相対位置のみが追跡されます。 このループは 3 つのアクションのブロックを繰り返し削除し、K の有効インデックスを縮小します。ステップ カウンターは、各ブロックの処理で「消費された」操作の数に正確に応じて増加します。 

唯一のデリケートな部分は、pos が 1、2、または 3 の場合の正確な終了ケースの処理です。これらは、サイクル内で考えられる 3 つの結果に直接対応しており、減算ステップを実行する前にチェックする必要があります。 

## 実用的な例

 ### 例 1

 入力:

 N = 4、K = 3

 K の位置を追跡します。 

| ステップ | 位置 | アクション |
 | --- | --- | --- |
 | 0 | 3 | 開始 |
 | 1 | 3 | サイクルの 3 番目の位置 |

 pos = 3 では、クレームは一番下に移動され、ローカル サイクルのステップ 3 で処理されます。 ただし、初期のサイクルで要素が消費されているため、最終的な解決はシフト後に発生し、最終ステップ 5 と結果 No. が得られます。 

これは、位置 3 の K がすぐには削除されず、プロセスの後半で破棄される前にローテーションを生き延びる様子を示しています。 

### 例 2

 入力:

 N = 5、K = 3

 | ステップ | 位置 | アクション |
 | --- | --- | --- |
 | 0 | 3 | 開始 |
 | 1 | 3 | 最初のサイクルシフトを生き残る |
 | 2 | 1 | 回転後にトップになる |
 | 3 | 1 | 署名済み |

 ここで、K は以前の削除の後、最終的に位置 1 に到達し、最終ステップで署名されます。 

これは、位置 3 の要素がどのように 1 サイクルを生き残り、後で最上位の要素として再び入ることができるかを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N/3) 最悪の場合、通常は O(K/3) | K に達するまで、各反復でちょうど 3 つの位置が削除されます。 
| スペース | お(1) | カウンタと現在位置のみが保存されます |

 N = 10^9 の場合でも、理論上の最悪の場合でも反復回数は最大でも N/3 程度であり、実際には K までのセグメントのみが処理されるため、このアルゴリズムは制約内に容易に適合します。

 ## 特殊なケース

 N = 1、K = 1 の場合、アルゴリズムは直ちに pos = 1 を検出し、ステップ 1 で Yes を出力します。サイクルがないため、変換は適用されません。 

N = 2、K = 2 の場合、pos は最初のサイクルで 2 になり、すぐに破棄され、ステップ 2 で No が生成されます。ループは減算ステップの前に終了します。 

大きい N の K = 3 の場合、アルゴリズムは pos == 3 のケースに入り、回転を直接処理します。 クレームはすぐには破棄されませんが、3 番目のアクションの一部として処理されるため、後のサイクルが関係する場合でも正しい歩数カウントが保証されます。
