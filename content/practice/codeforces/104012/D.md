 ## 解決策
 ## 問題の理解

 私たちに与えられているのは、$n \times n$各セルが固定の色の値を持つグリッド。 立方体は左上のセルから始まり、右下のセルに移動する必要があります。 各移動は 1 ステップ下または 1 ステップ右のいずれかであり、各移動は、異なる面が新しい底になるように立方体を物理的に回転させることに対応します。 

重要なルールは、訪問したすべてのセルで、立方体の底面がそのセルのグリッドの色と一致する必要があるということです。 立方体の 6 つの面すべての最初の色を選択できます。 その後、立方体の向きはパスに基づいて決定論的に変化します。そのため、問題は、次の少なくとも 1 つの単調パスに沿ってすべての制約が満たされるように、初期の面の色を割り当てることができるかどうかです。$(1,1)$に$(n,n)$。 

出力は、立方体面の有効な初期カラーリング、またはそのような割り当てが存在しないというステートメントのいずれかです。 

制約は、テスト ケース全体の合計サイズが小さく、$\sum n^2 \le 2500$これにより、セルごとに線形または線形に近いもの以上のものは即座に除外されます。 各セルまたは各エッジを一定回数検査する推論は可能ですが、立方体状態の指数関数的な探索を伴う推論はできません。 

グリッドが立方体の反対側の面に矛盾する要件を強制する場合、微妙なエッジ ケースが発生します。 たとえば、同じ色が、異なるパスによって引き起こされる左面と右面の両方の制約として同時に機能する必要がある場合、単純なパスベースの構築では実現可能性を誤って仮定する可能性があります。 別の失敗モードは、すべての可能な継続にわたる立方体の回転の一貫性を考慮せずに、任意のハミルトニアンのような単調パスで十分であると仮定することです。 

## アプローチ

 この問題を考える強引な方法は、立方体の 6 つの面の考えられるすべての初期カラーリングを試し、各ステップで底面の制約を尊重する左上から右下への有効な単調パスが存在するかどうかをシミュレートすることです。 各面はグリッド内に表示される任意の色を取ることができるため (最大$n^2$選択肢)、これは即座に不可能な検索空間に爆発します。 色をグリッド内の色に限定しても、私たちは依然として課題に直面しています。$O((n^2)^6)$それぞれの可能性について、グリッド内の多くのパスを指数関数的にチェックする必要があります。 これは実行可能な計算をはるかに超えています。 

重要な観察は、私たちが実際に実現可能性を決定する道を選択しているわけではないということです。 代わりに、少なくとも 1 つの単調パスと一致する必要がある立方体の方向を選択しています。 重要な構造の単純化は、からのすべての有効なパスが$(1,1)$に$(n,n)$まさに$n-1$下への動きと$n-1$右に移動し、立方体の最終的な向きは、特定のグリッド値ではなく、これらの移動の回数と順序のみに依存します。 これは、キューブ制約がグローバル パス列挙ではなく、エッジに沿ったローカルな一貫性条件に限定されることを意味します。 

パスを検索する代わりに、視点を逆転させます。 右に移動するたびに、底面が以前は左/右関連の面であったものになるように、立方体の面の色を割り当てようとします。下に移動する場合も同様です。 グリッドは動きのパターンを制約しません。 訪問した各下部位置にどの色を表示する必要があるかを制約するだけです。 これは、より強力な制限を示唆しています。移動中に 2 つの隣接するセルを連続して訪問する必要がある場合、それらの色は有効な立方体の回転遷移に対応する必要があります。 立方体には面間の固定された隣接関係があるため、有効な解決策は基本的に、グリッドの色と立方体の面の ID の間の一貫したマッピングをエンコードします。 

これにより、問題は、グリッドが単調なパス構造に沿った面の割り当ての一貫した伝播を許可するかどうかをチェックすることに集約されます。 グリッドは完全に既知であるため、次から始まる制約を伝播できます。$(1,1)$、その色を底面に割り当て、隣接する面に必要な色を決定的に導き出します。 矛盾があれば解決策はありません。 それ以外の場合、誘導された制約によって、有効な初期立方体カラーリングが一意に定義されます。

 ## アルゴリズムのチュートリアル

 立方体を、固定された隣接関係を持つ 6 つの面を持つものとして扱います。 から始まるグリッドに沿って制約を伝播することで、一貫した割り当てが存在するかどうかを判断します。$(1,1)$。 

1. 立方体の底面を次の位置に固定します。$(1,1)$色があること$c_{1,1}$、これは必須なので。 これによりシステム全体が固定されます。 
2. 立方体の面に抽象的なアイデンティティ (底面、上面、左面、右面、前面、背面) を割り当てます。 目標は、右または下に移動することによって引き起こされる遷移がグリッドの色と一致するように、各面がどのような色をとるべきかを決定することです。 
3. 開始セルから 2 つの可能な手を検討します。 右に移動すると、立方体が強制的に回転し、左右の面の関係によって新しい底が決まります。 下に移動する場合も同様に、前面トランジションを使用します。 これにより、隣接する面にどの色を表示する必要があるかについての制約が即座に与えられます。$c_{1,1}$。 
4. これらの制約を BFS のような方法でグリッドを通じて伝播します。 から移動するとき$(i,j)$に$(i+1,j)$、底になる面が一致する必要があることを強制します$c_{i+1,j}$、右の動きについても同様です。 各伝播ステップは、立方体面の固定順列に変換されます。 
5. どこかの時点で顔に 2 つの異なる色が必要な場合、私たちは立ち止まって不可能であると結論付けます。 それ以外の場合は、伝播が安定したら、6 つの面すべてに割り当てられた色を抽出します。 

重要な点は、私たちは決して道を選ばないということです。 代わりに、有効な単調移動シーケンスが同じ基礎となるキューブ方向ルールと一致している必要があることを強制します。 これにより、ローカルな遷移からグローバルな一貫性が強制されます。 

### なぜ効果があるのか

 立方体には固定された回転グループ構造があり、すべての動きは面のアイデンティティの順列に対応します。 グリッドは各訪問ノードの底面のみを拘束するため、すべての有効な解決策は、すべての誘発された回転によってすべてのエッジにわたってこれらのラベルが保持されるような、立方体の面の一貫したラベル付けに対応します。 伝播により、グリッド内のすべてのエッジが同じ決定論的変換を強制することが保証されるため、グリッドが同じ面に互換性のないラベルを強制する場合にのみ矛盾が発生します。 矛盾が発生しない場合、構築されたラベルは、次のような単調なパスに対して機能する立方体を定義します。$(1,1)$に$(n,n)$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

# face indices:
# 0 bottom, 1 left, 2 back, 3 front, 4 right, 5 top

def roll_right(b, l, r, f, bck, t):
    # when moving right, bottom becomes left
    # cycle: bottom -> right, right -> top, top -> left, left -> bottom
    return (l, t, bck, f, r, b)

def roll_down(b, l, r, f, bck, t):
    # when moving down, bottom becomes front
    # cycle: bottom -> back, back -> top, top -> front, front -> bottom
    return (f, l, r, t, bck, b)

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        g = [list(map(int, input().split())) for _ in range(n)]

        # we maintain possible states for cube orientation at each cell
        # each state is a 6-tuple of face colors
        from collections import deque

        start = (g[0][0], None, None, None, None, None)
        q = deque([start])
        seen = {(0, 0, start)}

        ok = True
        final_state = None

        while q:
            i, j, state = q.popleft()

            if i == n - 1 and j == n - 1:
                final_state = state
                break

            b, l, back, front, r, tface = state

            if j + 1 < n:
                nb = g[i][j+1]
                # enforce bottom consistency
                if b != None and b != nb:
                    pass
                else:
                    new_state = roll_right(b, l, r, front, back, tface)
                    if (i, j+1, new_state) not in seen:
                        seen.add((i, j+1, new_state))
                        q.append((i, j+1, new_state))

            if i + 1 < n:
                nb = g[i+1][j]
                if b != None and b != nb:
                    pass
                else:
                    new_state = roll_down(b, l, r, front, back, tface)
                    if (i+1, j, new_state) not in seen:
                        seen.add((i+1, j, new_state))
                        q.append((i+1, j, new_state))

        if final_state is None:
            print("No")
        else:
            b, l, back, front, r, tface = final_state
            print("Yes")
            print(b, l, back, front, r, tface)

if __name__ == "__main__":
    solve()
```このコードは、立方体の方向状態と組み合わせたグリッド位置に対する BFS を実装します。 各状態は立方体面への現在の色の割り当てをエンコードし、各遷移は右または下に移動することによって引き起こされる決定的な回転を適用します。 

重要な部分は、立方体の回転が 6 つの額面の固定順列としてモデル化されていることです。 右に移動すると、下が前の左側の関係になり、他の面も同様です。 BFS により、到達可能な一貫した構成のみが探索されることが保証されます。 

実装上の微妙な問題は、すべてのステップでグリッド制約との一貫性を確保する必要があることです。 底面は、現在いるグリッド セルと常に一致する必要があります。 それ以外の場合、状態は無効であるため、展開すべきではありません。 

## 実用的な例

 行に沿って色が単調増加パターンを形成する小さなグリッドを考えてみましょう。 BFS は次から始まります$(1,1)$底部を固定した状態で$c_{1,1}$。 右に移動すると、回転によりキューブの状態が更新され、BFS は最上部の行に沿って固有の一貫した構成を記録します。 下に移動すると、互換性のある回転シーケンスが伝播されます。 

| ステップ | ポジション | 下 | 左 | 戻る | フロント | 右 | トップ |
 | --- | --- | --- | --- | --- | --- | --- | --- |
 | 1 | (1,1) | c11 | ? | ? | ? | ? | ? |
 | 2 | (1,2) | c12 | ... | ... | ... | ... | ... |
 | 3 | (2,2) | c22 | ... | ... | ... | ... | ... |

 このトレースは、一貫した伝播が存在すると、BFS が矛盾なく自然にターゲット セルに到達することを示しています。 

ここで、2 つのパスが同じ面に対して矛盾する方向を強制するグリッドを考えてみましょう。 このような場合、BFS は暗黙のキューブ方向が異なるセルで状態を再訪しようとしますが、seen-set により互換性のない構成のマージが妨げられ、最終的にキューは到達することなく空になります。$(n,n)$。 

これは、実現可能性が、グリッド グラフ全体でグローバルに一貫した立方体の回転の伝播が存在することと同等であることを示しています。

 ## 特殊なケース

 1 つのエッジ ケースは、すべてのグリッド値が同一である場合に発生します。 この場合、すべての移動はローカルで有効であり、BFS で色の不一致が発生することはありません。 アルゴリズムは状態を伝播し続け、最終的には右下のセルに到達します。 矛盾が存在しないため、正しく有効なカラーリングが出力されます。 

もう 1 つのエッジ ケースは、グリッドによってループ状の矛盾が強制される場合です。$2 \times 2$右に移動してから下に移動すると、下に移動してから右に移動する場合とは異なる下部の色が暗示される構成。 BFS は、両方のルートを別々の状態遷移として探索します。 これら 2 つの誘導された状態が同じセルでマージされる時点で、訪問セットがそれらを分離し、一貫した方向のみが生き残ります。 両方がグリッド制約と矛盾する場合、両方のパスは終了し、答えは「いいえ」になります。 

最終的なエッジケースは最小サイズです$n = 2$、すべての移動シーケンスには 2 つのステップしかありません。 このアルゴリズムは、からの両方の遷移を満たす単一の一貫した 6 面割り当てが存在するかどうかを効果的にチェックします。$(1,1)$に$(1,2)$そして$(2,1)$。 BFS は両方のブランチを明示的にシミュレートし、両方に同一のキューブ制約を適用するため、これを自然に処理します。
