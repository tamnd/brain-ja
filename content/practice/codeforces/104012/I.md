 ## 問題の理解

 円形の配置があります$n$各セクターは最初は最大でも 1 つのエンベロープを保持します。 数ラウンドを経て、ただ、$k$エンベロープは残り、円上の正確な位置が時計回りにわかります。 これらの残りの封筒の 1 つは特別なもので、セクターにあります。$s$。 ゲームは均一にランダムにセクターを選択することを繰り返すことで進行します。 選択したセクターに既にエンベロープが含まれている場合は、そのエンベロープが開かれて削除されます。 エンベロープが空の場合、ホストは次に残るエンベロープまで時計回りに移動し、代わりにそのエンベロープを開きます。 

このプロセスはすべての封筒が開かれるまで続き、特別な封筒が開かれるまでの予想ラウンド数が求められます。 

重要な点は、ランダム セクターがエンベロープを直接選択するのではなく、円上の位置を選択してから、次に残っているエンベロープに「前方にジャンプ」することです。 これは、空のギャップは時計回りの順序で次のエンベロープに「属する」ため、各エンベロープが単純な方法で選択される確率が同じではないことを意味します。 

制約は、どの構造を利用する必要があるかを示す主な信号です。 その間$n$と同じ大きさにすることができます$10^9$、残りの封筒の数$k$は最大でも 200 です。これにより、どのような解も$n$すべてのセクターを線形に繰り返すことも、さらには反復することも不可能です。 唯一意味のある状態は、$k$エンベロープの位置とそれらの間のギャップ。 循環的な性質は、問題が根本的に個々のセクターではなく、それらのギャップに関するものであることを意味します。 

単純な考えでは、アクティブなエンベロープのセットを維持し、ランダムなセクターを繰り返しサンプリングして、プロセスをラウンドごとにシミュレートします。 各ステップが次のとおりであるため、これは失敗します。$O(k)$次のエンベロープを見つけるための、予想されるステップ数も$O(k)$、につながる$O(k^2)$シミュレーションごとに実行され、期待値の推定には多くのシミュレーションが必要になります。 さらに悪いことに、正確な確率を計算するには、多くの除去状態を指数関数的に追跡する必要があります。 

さらに微妙な失敗例は、「次の封筒を時計回りに」というルールを無視した場合に発生します。 たとえば、封筒が次の位置にある場合、$[1, 1000]$大きな円上では、2 ～ 1000 の間のほぼすべてのセクターがエンベロープ 1000 にマッピングされます。エンベロープごとに均一であるという単純な仮定は、ここでは完全に間違っています。 

## アプローチ

 本質的な問題は、各エンベロープが、時計回りの順序で次のエンベロープとして選択される開始セクターの数に等しい「重み」を持っていることです。 エンベロープを削除すると隣接するギャップがマージされるため、これらのウェイトはエンベロープが削除されると動的に変化します。 

残りのエンベロープだけに注目すると、円は次のように分割されます。$k$円弧。 各アークは、そのすべてのセクターを時計回りに次のエンベロープに寄与します。 封筒の場合$i$ギャップ長さがある$g_i$(前のエンベロープまでの距離)、それらのいずれかを選択します$g_i$セクターは最終的にはエンベロープにつながる$i$。 

これは封筒という意味です$i$に比例する確率で選択されます$g_i / n$、 どこ$n$はセクターの総数であり、重要なことは$n$ギャップ全体の分布が進化する一方で、固定されます。 

エンベロープが削除されると、2 つの隣接するギャップがマージされるため、ローカルな更新のみが行われます。 以来$k \le 200$、ギャップ構成上のマルコフ過程としてプロセスを正確にモデル化できます。 ただし、すべての州に完全に分散する必要はありません。 必要なのは、特定のエンベロープが削除されるまでの予想時間だけです。 

これは、残りのエンベロープのサブセットに対する動的プログラミングを示唆していますが、それでも大きすぎます。$2^k$不可能です。 

重要な単純化は、視点を逆転させることです。 削除を前方にシミュレートする代わりに、各ステップの予想時間寄与を考慮します。どの状態でも、次の削除までの予想時間は次のとおりです。$n / (\text{number of active envelopes})$なぜなら、すべてのセクターは最終的に 1 つのアクティブなエンベロープにマッピングされ、$k$エンベロープなので、すべてのエンベロープにわたる確率質量の合計は分母と合計して 1 になります。$n$ただし、各ステップでは常に 1 つのエンベロープが消費されます。 どのエンベロープが選択されるかの分布はギャップ構造のみに依存しますが、除去間の待ち時間は均一なサンプリングにのみ依存します。$n$セクター。 

したがって、予想される時間は、ランダムな削除によって引き起こされる順序での連続した削除間の予想される待ち時間の合計になります。 残りのタスクは、特殊なエンベロープが削除されるまでの予想されるステップ数を計算することです。これは、各エンベロープが時変する選択確率を持つランダムな削除順序で特殊なエンベロープの予想される位置を計算することに帰着します。 

なぜなら$k$が小さい場合、循環シーケンス上の間隔にわたって DP を定義し、エンベロープのセグメントが残り、特別なエンベロープがその中にある場合の予想コストを追跡できます。 各遷移では、その弧の長さに比例する確率で選択された 1 つのエンベロープが削除され、2 つの小さなセグメントに分割されます。 

これは、古典的な「循環加重構造でのランダムな削除」DP であり、$O(k^3)$、十分な$k \le 200$。

 ## アルゴリズムのチュートリアル

 1. 円形の位置を、連続するエンベロープ間のギャップの配列に変換します。 各封筒$i$隙間ができる$g_i$、時計回りの投影でそれにマップされる開始セクターの数を表します。 このステップにより、大きなファイルが圧縮されます。$n$宇宙へ$k$意味のある重み。 
2. エンベロープの円形間隔にわたって DP 状態を構築します。 インデックスを剰余として扱います$k$ただし、DP の便宜上、円形セグメントが直線セグメントになるように配列を複製します。 
3. DP 関数を定義する$dp[l][r]$インデックスからのエンベロープのみが存在する場合、特別なエンベロープが削除されるまでの予想ラウンド数を表します。$l$に$r$残る。 
4. 一定の間隔で$[l, r]$、総重量を計算します$W = \sum g_i$その間隔にわたって。 これは、残りのエンベロープにつながるセクターの総数を表します。 
5. 考えられる封筒ごとに$i$で$[l, r]$、それが次に削除された封筒であると考えてください。 これは確率で起こります$g_i / W$。 
6. もし$i$特別な封筒である場合、それを削除するとプロセスが停止します。 その貢献はまさに期待されるもう一つのステップです。 
7. それ以外の場合は、削除します$i$間隔を 2 つの独立した間隔に分割します$[l, i-1]$そして$[i+1, r]$。 この分岐の期待値は、2 つの部分間隔の DP 値の合計に、削除自体の 1 ステップを加えたものです。 
8. 確率で重み付けされた寄与を合計してすべての選択肢を結合し、$dp[l][r]$。 

最終的な答えは、$dp[l][r]$すべてのエンベロープと特別なエンベロープを含む完全な円形の間隔。 

### なぜ効果があるのか

 いつでも、プロセスは次から均一にセクターを選択します。$n$ただし、時計回りの転送により、すべてのセクターが 1 つのアクティブなエンベロープに決定的にマッピングされます。 これにより、現在のアーク長に比例するエンベロープ上の確率分布が引き起こされます。 エンベロープの削除は隣接する円弧をマージするだけなので、総質量は維持されます。$n$、プロセスは現在の間隔構造に関してメモリレスです。 DP はまさにこのマルコフ進化を捉えています。つまり、すべての状態遷移は現在の間隔の重みにのみ依存し、次に考えられるすべての除去は正しい確率で考慮されます。 これにより、計算された期待値が真の確率過程と一致することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modinv(x):
    return pow(x, MOD - 2, MOD)

def solve():
    n, k, s = map(int, input().split())
    q = list(map(int, input().split()))

    idx = q.index(s)

    # compute gaps
    g = []
    for i in range(k):
        j = (i + 1) % k
        dist = (q[j] - q[i]) % n
        if dist == 0:
            dist = n
        g.append(dist)

    # duplicate for circular dp
    g2 = g * 2

    # prefix sums
    pref = [0] * (2 * k + 1)
    for i in range(2 * k):
        pref[i + 1] = pref[i] + g2[i]

    def get_sum(l, r):
        return pref[r + 1] - pref[l]

    # dp[l][r]
    dp = [[0] * (2 * k) for _ in range(2 * k)]

    for length in range(1, k + 1):
        for l in range(2 * k - length + 1):
            r = l + length - 1
            total = get_sum(l, r)

            res = 0
            for i in range(l, r + 1):
                prob = g2[i] * modinv(total) % MOD

                if i % k == idx:
                    res = (res + prob * 1) % MOD
                else:
                    left = dp[l][i - 1] if i > l else 0
                    right = dp[i + 1][r] if i < r else 0
                    res = (res + prob * (1 + left + right)) % MOD

            dp[l][r] = res

    print(dp[idx][idx + k - 1] % MOD)

if __name__ == "__main__":
    solve()
```実装は、円をギャップ重みに圧縮することから始まり、ギャップ重みは各エンベロープにつながる開始セクターの数をエンコードします。 DP テーブルは重複した配列に基づいて構築されるため、円形の間隔が直線セグメントになり、ラップ処理が回避されます。 

遷移は、最後に削除されたエンベロープ候補をループし、区間内の総重みの逆数によって計算されたモジュラー確率を使用します。 特別なエンベロープが選択されると、プロセスはコスト 1 で終了します。それ以外の場合、区間は 2 つの独立した部分問題に分割され、それらの DP 値が現在のステップとともに追加されます。 

実装上の主なリスクは、循環構造を誤って扱うことです。 配列を複製することにより、残りのアクティブなエンベロープを表す連続セグメントが、DP 内のモジュール式インデックス ロジックなしで表現可能になります。

| 状態 | 間隔 | 総重量 | 貢献 |
 | --- | --- | --- | --- |
 | 開始 | [2、3] | 3 | 3 または 2 を選択してください |

期待される：$$\frac{1}{3} \cdot 1 + \frac{2}{3} \cdot 2 = \frac{5}{3}$$これは DP の結果と一致します。特別なエンベロープを早期に削除すると、最小限のコストで済みますが、遅延すると追加の手順が必要になります。

 ## 特殊なケース

 エッジ ケースの 1 つは、すべてのエンベロープが円内で連続している場合です。次のような場合です。$q = [1,2,3,4]$。 この場合、ラップ ギャップを除くすべてのギャップは 1 であり、エンベロープ上の確率分布はほぼ均一です。 DP は、すべてのエンベロープが同様に動作する対称除去プロセスに帰着し、アルゴリズムは特別なケーシングに依存せずに各間隔を一貫して処理します。 

もう 1 つのエッジ ケースは、特別なエンベロープが線形化された配列内の重複セグメント間の境界にある場合です。 シーケンスを複製するため、同じ循環間隔が 2 回表示されますが、DP は正しいインデックスで始まるセグメントのみを選択します。 これにより、正しいラップアラウンド動作を維持しながら、二重カウントが回避されます。 

最後のエッジケースは、封筒が 1 つだけ残っている場合です。 次の選択で DP を開く必要があり、分割はできないため、DP はすぐに値 1 を割り当てます。
