 ## 解決策
 ## 問題の理解

 私たちには 1 組のコンピューターが与えられ、それぞれに 1 本の発信線が装備されています。 コンピューターがワイヤーを直接使用する場合、1 ビットの送信には、コンピューター自体の遅延値に等しい固定時間がかかります。 これらのワイヤに加えて、限られた数のポートを備えたハブがあります。 各コンピュータは、その単一のワイヤをハブに直接接続するか、別のコンピュータのポートに接続する必要があり、最終的にデータをハブに導く有向構造を効果的に形成する必要があります。 

重要な要件は、直接的な意味での接続です。つまり、すべてのコンピューターから発信ワイヤをたどって、最終的にハブに到達できる必要があります。 中間コンピュータはデータを転送するときに遅延を追加しないため、コンピュータの合計遅延は、そのコンピュータからチェーンがハブで終了するまでの直接チェーンに沿った遅延の合計になります。 

タスクは、ハブには k 個のポートしかないため、最大で k 台のコンピュータがハブに直接接続できることを考慮して、ハブに接続されたルートで終わる有向チェーンのフォレストにこれらのコンピュータを接続する方法を選択することです。 他のすべてのコンピューターは、他の 1 台のコンピューターに接続する必要があります。 目標は、ハブまでのすべての遅延の合計を最小限に抑えることです。 

制約は小さく、n は最大 100、di は最大 100 です。これにより、小さな組み合わせ状態を超える置換やグラフ構造にわたる指数関数的なものは即座に排除されます。 3 次または 2 次の解が許容され、動的プログラミングまたは貪欲なソートのアプローチはどちらも妥当です。 

連鎖によってすべてのダウンストリーム コストが変化することを考慮せずに、k 個のハブ スロットを最小の di に貪欲に割り当てようとすると、微妙な失敗例が発生します。 たとえば、すべての di が等しい場合、最適な構造は、複数の短いチェーンではなく、1 つのハブ接続にフィードする単一のチェーンです。これは、各コンピュータの遅延がチェーン内の位置に沿って蓄積するためです。 

## アプローチ

 単純な解釈では、ハブに直接接続する k 個のルートを選択するあらゆる方法を試し、残りのすべてのノードに親を割り当て、ルート付きツリーのフォレストを形成します。 このような構造ごとに、チェーンを横断することによってハブまでの距離を計算します。 これは、親割り当ての数が n^(n-k) として増加し、ハブ ルートの選択ですら n が k を選択する場合に組み合わせとなるため、すぐに扱いにくくなります。 

重要な観察は、構造が恣意的ではないということです。 各ノードには出力エッジが 1 つだけあるため、最終的なネットワークは有向ツリーの集合となり、各ツリーはハブ接続されたノードをルートとします。 各ツリー内では、ノードの遅延の寄与はルートからの深さのみに依存し、各エッジはその子の遅延をチェーン内のその上のすべてのノードに寄与します。 

これは問題を再構成します。すべてのノードの di は、チェーン内でその上にあるすべてのノードに対して 1 回支払われるコストのように機能します。 ノードがハブの近くに配置されると、そのコストはより多くのノードに影響します。 したがって、高価な di 値が構造のより深くに表示されるようにして、支払われる回数を減らしたいと考えています。 

ここで、ハブ ポートの役割を考えてみましょう。 各ポートは効率的に新しいチェーンを開始します。 使用するチェーンの数が k 個より少ない場合は、チェーンをマージすることで上部付近の高コストの重複が削減されるため、これは役に立ちます。 したがって、ハブで開始するチェーンの数と、蓄積されたプレフィックスの合計を最小限に抑えるためにノードをチェーンに配置する方法を効果的に選択しています。 

よく知られている変換が現れます。ノードを di でソートし、小さい値がハブに近く表示される順序で割り当てると、累積寄与の合計が最小化されます。 最適な構造は、ネットワークをハブから外側へ k 個のチェーンを構築するものとして扱い、常に最大の残り di last でチェーンを拡張することで、大きなコストの乗算回数が少なくなるようにすることです。

これは、貪欲なスケジューリングの解釈につながります。つまり、ノードがその上に接続できるチェーンの数を決定し、より少ないノードに影響を与える構造内でより大きな di を常に下に配置したいと考えます。 最適な構築は、バランスのとれた方法で k チェーン全体にノードをソートして分散することになります。これは、利用可能な最も浅いチェーンに di の昇順でノードを繰り返し割り当てることと同等であることがわかります。 

これにより、O(n log n) の貪欲なソリューションが得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (すべての親/ハブ割り当て) | 指数関数 | O(n) | 遅すぎる |
 | ソートとバランスの取れた割り当てによる最適な貪欲 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. di を増やしてすべてのコンピュータを並べ替えます。これにより、最小の遅延ワイヤが最初に処理されます。 これにより、低コストのエッジがハブに最も近い場所、またはより多くのノードに影響を与えるチェーン内のより高い位置に配置されるようになります。 
2. それぞれがハブから始まるパスを表す k 個のチェーンを維持します。 概念的には、各チェーンは現在の合計累積深度コストを追跡します。 
3. 最初の k 個の最小要素を各チェーンの最初のノードとして挿入します。 これらはハブに直接接続されたコンピュータに対応し、k 個のルートを確立します。 
4. 残りの各コンピュータを di の昇順に、現在の累積コストが最小であるチェーンに割り当てます。 これにより、合計の累積レイテンシが少なくなる場所に、より重いコストを配置することが保証されます。 
5. ノードがチェーンに追加されると、その di がチェーンの累積状態に追加され、この更新されたコストがその後の配置に影響します。 
6. すべてのノードが配置された後、構築によって暗示される蓄積されたプレフィックス効果を合計することによって合計寄与度を計算します。これは、すべてのノードのレイテンシの合計に相当します。 

利用可能な最小のチェーンを常に選択する理由は、各チェーンがすでにどれだけの「コスト圧力」が蓄積されているかを表しているためです。 新しいノードをより高価なチェーンに配置すると、その寄与が不必要に増幅されます。 

### なぜ効果があるのか

 不変条件は、ソートされた順序で最初の t ノードを処理した後、アルゴリズムがすべての有効な部分構造間のプレフィックス合計の最小分布を表す累積コストを表す k チェーンを維持することです。 新しいノードは常に、合計レイテンシーの増加が最小限に抑えられる場所に挿入されます。また、di は減少しない順序で処理されるため、スワップ引数によって、より大きな di をチェーンの前に配置すると、合計の寄与が増加するか、変更されないままになり、決して減少しないことがわかります。 この交換プロパティにより、貪欲な割り当てがすべてのステップで最適性を維持することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    d = list(map(int, input().split()))
    
    d.sort()
    
    if k >= n:
        print(sum(d))
        return
    
    # each chain represents a hub-connected path
    chains = [0] * k
    
    # initialize k roots with smallest k elements
    for i in range(k):
        chains[i] = d[i]
    
    # assign remaining nodes greedily
    import heapq
    heap = chains[:]
    heapq.heapify(heap)
    
    for i in range(k, n):
        x = heapq.heappop(heap)
        x += d[i]
        heapq.heappush(heap, x)
    
    # total latency is sum of all accumulated contributions
    print(sum(heap))

if __name__ == "__main__":
    solve()
```この解決策は、小さい値が最初に処理されるように遅延を並べ替えることから始まります。 貪欲な戦略では、最もコストの低いコンポーネントから段階的に構造を構築することに依存しているため、これは不可欠です。 

最初の k 要素は、k 個のハブ接続チェーンを初期化します。 これらは、すべての可能なパスのルートとして機能します。 最小ヒープは、現在最もコストの低いチェーンを常に拡張するために使用され、合計レイテンシーの増加が最も少ない場所に新しい追加が配置されるようにします。 

ヒープには、個々のノードではなく、蓄積されたチェーン コストが保存されます。これが、貪欲な作業を効率的に行うための重要な抽象化です。 チェーンを拡張するたびに、その増加した貢献がすぐに反映されます。 

最後に、ヒープを合計すると、合計レイテンシが得られます。これは、各チェーン ルートの累積によって、そのパス構造に沿って伝播されたコスト全体がすでにエンコードされているためです。

 ## 特殊なケース

 n が 1 の場合、コンピュータは 1 台だけなので、可能であればハブに直接接続する必要があります。 このアルゴリズムは単一のチェーンを初期化し、ヒープには d1 に等しい累積値が 1 つだけ含まれ、正しい結果が即座に生成されます。 

k が n 以上の場合、すべてのコンピュータがハブに直接接続できます。 初期化ステップでは各 di を独自のチェーンに配置し、それ以上のマージは行われないため、結果は単にすべての di の合計になります。 

すべての di が等しい場合、貪欲な動作はバランスの取れたチェーンを形成しますが、構造に偏差があると同じコストがかかります。 すべてが等しいため、ヒープは繰り返し任意のチェーンを選択し、最終的な合計には偏りのない均一な蓄積が反映されます。
