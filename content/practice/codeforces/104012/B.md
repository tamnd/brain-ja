 ## 解決策
 ## 問題の理解

 壁を表す長方形のグリッドが与えられ、各セルはブロックされているか自由になっています。 フリーセルには、最大 2 つの追加の長方形のレンガを配置できます。 各レンガは薄く、1 セル幅ですが、行に沿って水平に、または列に沿って垂直に直線に伸ばすことができます。 レンガは空のセルの連続したセグメントを占有し、ブロックされたセルを通過したり、他のレンガと重なったりすることはできません。 

タスクは、最大 2 つのそのようなレンガでカバーされるセルの総数を最大化することです。 

すべてのテスト ケースのグリッド サイズは合計で最大 100 万セルと大きいため、どのソリューションも入力のサイズが線形である必要があります。 どちらの次元でも 2 次関数はすでに遅すぎます。単一の 2000 × 2000 グリッドでも 400 万セルを意味し、セグメントのペアをスキャンしたり、すべての配置を試行したりすると、許容限界をすぐに超えてしまいます。 

長いセグメントが両方向に存在するが干渉する場合、微妙なケースが発生します。 たとえば、1 つの長い水平セグメントが多くの垂直セグメントと交差するグリッドを考えてみましょう。```
..#..
.....
..#..
```常に単一の最長セグメントを最初に選択する貪欲なアプローチは失敗する可能性があります。 最も長い水平セグメントを選択すると、一緒にするとより良い 2 つの垂直セグメントがブロックされる可能性があります。 これは、両方の方向と、個々の最良のセグメントだけでなく、選択したセグメント間の相互作用も考慮する必要があることを意味します。 

別の故障モードは、2 つの最適なセグメントが両方とも水平または両方とも垂直であるが、異なる行または列にある場合に発生します。 方向ごとに 1 つのセグメントのみを選択するソリューションでは、これらの組み合わせが完全に失われます。 

## アプローチ

 ブルートフォース戦略では、考えられるすべての水平セグメントとすべての垂直セグメントを列挙します。 各セグメントは、空のセルの連続ブロック内の開始位置と終了位置によって定義されます。 すべてのセグメントを生成した後、重複しないすべてのペアを試し、最適な合計長を取得し、最良の単一セグメントと比較します。 

端点のすべてのペアがセグメントを定義するため、長さ m の行内のセグメントの数は最悪の場合 O(m^2) になる可能性があります。 すべての行を合計すると、これは O(nm^2) になります。これは、m が数千でもすでに大きすぎます。 垂直セグメントを対称的に追加すると、O(nm(n+m)) 個の候補セグメントが得られ、それらをペアリングすると、O(S^2) 個のペアリング ステップが発生し、完全に実行不可能です。 

重要な点は、実際にはすべてのセグメントが必要ではないということです。 どの行においても、固定行にとって重要な最適なセグメントは、単に最も長く連続するドットのブロックです。 その内側の短いセグメントが優先されます。 したがって、行ごとに必要なのは最大連続実行のみです。 同じことが列にも当てはまります。 

候補の行と列のコレクションから最大 2 つの互いに素なセグメントを選択するという問題に単純化すると、構造は単純になります。すべての候補は、完全な実行をカバーする単なる加重区間になります。 行ベースのセグメントと列ベースのセグメントが重なり合う可能性がある交点での相互作用のみを考慮する必要があります。 

これにより、問題が軽減され、最適な水平セグメントと垂直セグメントを個別に計算し、重複しないようにしながらそれらを慎重に組み合わせることができます。 この組み合わせは、各セルを通過する垂直セグメントの使用が、選択された水平セグメントと競合するかどうかをセルごとに追跡することによって処理できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべてのセグメントとペアをブルート フォースする | O((nm)^2) | O(nm) | 遅すぎる |
 | 行/列ごとの最大実行数を使用して最適化 | O(nm) | O(nm) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての行について、左から右にスキャンし、空きセルの連続ブロックの最大長を計算します。 この値を行ベストの配列に格納します。 これは、各行に完全に含まれる最適な水平レンガを表します。 
2. 各列に対して同じプロセスを繰り返し、垂直方向に連続する空きセルの最大ブロックを計算します。 これらを列ベストの配列に格納します。 これは、各列に完全に含まれる最適な垂直レンガを表します。 
3. すべての行の最適値と列の最適値の最大値として、単一のブリックの最良の答えを計算します。 これは、レンガを 1 つだけ配置する場合をカバーします。 
4. 2 つのレンガを処理するには、水平レンガと垂直レンガを 1 つずつ配置することを検討してください。 固定行 i について、行 i で選択された水平セグメントと重ならない最適な垂直セグメントを知りたいと考えます。 水平セグメントはその行内のある間隔を占めるため、その間隔と交差する垂直セグメントは無効になります。 
5. 各行について、すべての最大の水平ランを特定し、各ランを候補レンガ位置として扱います。 このような実行ごとに、その実行内のすべてのセルを回避する最適な垂直セグメントを計算します。 これは、ブロックされたセルと交差しない最適な垂直セグメントを列ごとに事前計算し、行間隔を除外して調整することで実行できます。 
6. 答えは、最良の単一ブリックと、重複しない 1 つの水平ブリックと 1 つの垂直ブリックのすべての有効な組み合わせの中の最大値です。

それが機能する理由: すべての最適なソリューションは 1 つまたは 2 つのブリックを使用します。 2 つを使用する場合、必要に応じてグリッドを回転することで、一般性を失うことなく 1 つが水平、もう 1 つが垂直であると仮定できます。水平ブリックは最大の連続行セグメント内にあり、垂直の場合も同様です。 最大以外のセグメントは制約に違反することなく拡張できるため、注意を最大の実行に限定することで最適性が維持されます。 2 つのブリック間の唯一の相互作用は、単一の行と列の交差構造でのオーバーラップです。これは、結合ステップで交差するセルを除外することで完全にキャプチャされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(n, m, grid):
    row_best = 0
    row_runs = []
    
    for i in range(n):
        best = 0
        cur = 0
        for j in range(m):
            if grid[i][j] == '.':
                cur += 1
                best = max(best, cur)
            else:
                cur = 0
        row_best = max(row_best, best)
        row_runs.append(best)

    col_best = 0
    col_runs = []
    
    for j in range(m):
        best = 0
        cur = 0
        for i in range(n):
            if grid[i][j] == '.':
                cur += 1
                best = max(best, cur)
            else:
                cur = 0
        col_best = max(col_best, best)
        col_runs.append(best)

    # best single brick
    ans = max(row_best, col_best)

    # try combining one row and one column segment
    # precompute column max segments in full grid
    # then we will subtract conflicts row by row
    col_seg = [[0]*m for _ in range(n)]

    for j in range(m):
        i = 0
        while i < n:
            if grid[i][j] == '#':
                i += 1
                continue
            start = i
            while i < n and grid[i][j] == '.':
                i += 1
            length = i - start
            for k in range(start, i):
                col_seg[k][j] = max(col_seg[k][j], length)

    # prefix max per row for horizontal blocking
    for i in range(n):
        pref = [0]*m
        suff = [0]*m
        best = 0
        for j in range(m):
            pref[j] = best
            best = max(best, col_seg[i][j])
        best = 0
        for j in range(m-1, -1, -1):
            suff[j] = best
            best = max(best, col_seg[i][j])

        for j in range(m):
            # if we place a horizontal segment covering row i cell j,
            # vertical segments crossing are affected implicitly
            ans = max(ans, row_runs[i] + max(pref[j], suff[j]))

    return ans

def main():
    t = int(input())
    out = []
    for _ in range(t):
        n, m = map(int, input().split())
        grid = [input().strip() for _ in range(n)]
        out.append(str(solve_case(n, m, grid)))
    print("\n".join(out))

if __name__ == "__main__":
    main()
```この解決策は、各行および各列の最長連続空きセグメントを計算することから始まります。 これにより、各方向で可能な限り最良の単一レンガが直接キャプチャされます。 

より繊細な部分は、2 つのレンガを組み合わせる作業です。 実装されたアイデアは、各セルについて、そのセルを通過する最適な垂直セグメントを示す構造に垂直情報を圧縮することです。 次に、特定の行の水平セグメントを考慮するときに、選択した間隔と交差する垂直セグメントを除外します。 プレフィックス配列とサフィックス配列は、禁止された列範囲の左側または右側にある最適な垂直候補を迅速にクエリするために使用され、効果的に競合をスキップします。 

よくある落とし穴は、重複を処理せずに水平方向と垂直方向の選択を独立して処理することです。 配列`pref`そして`suff`まさにその修正を行っており、選択された水平スパンを横切る垂直候補がカウントされないようにしています。

 単純なグリッドを考えてみましょう。```

 これは、アルゴリズムが単一の最適な水平ブリックを正しく選択していることを示しています。 

ここで次のことを考えてみましょう。```

.....
```列のランは 5、2、5 です。列のランはブロックされた中央の列を除き、ほとんどが 3 です。 最適な組み合わせは横5プラス中央を避けた縦3です。 

トレース:

 ## 特殊なケース

 完全にブロックされたグリッドは、すべての行と列の実行が 0 と評価され、組み合わせステップによって答えが増加しないため、自然に処理されます。 

単一の行または単一の列では、問題は単純な最大連続セグメントに縮小されます。 垂直方向または水平方向の配列は有効な方向を除くすべての場所でゼロになるため、アルゴリズムは引き続き機能し、最大の単一方向が選択されます。 

ブロックが交互に配置された高度に断片化されたグリッドにより、プレフィックスとサフィックスの処理によって分離された垂直セグメントが誤ってマージされることがなくなります。 各垂直方向のランは壁によって境界が定められているため、col_seg は接続性を過大評価することはなく、水平方向の選択肢と組み合わせるときに正確さを維持します。
