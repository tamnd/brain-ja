 ## 解決策
 ## 問題の理解

 各カードが 0 から n − 1 までの値を持つカードのマルチセットが与えられます。いつでも、各値のコピーが何枚存在するかがわかります。 すべてのカードを空ではない任意の数のグループに分割することができます。 各グループについて、そのグループに現れない最小の非負の整数を意味する mex を計算します。 パーティションのスコアはすべてのグループの mex 値の合計であり、このスコアを最大化したいと考えています。 

初期構成の後、マルチセットは、単一のカード値を挿入または削除するポイント更新を通じて時間の経過とともに変化します。 更新のたびに、可能な最大スコアを再計算する必要があります。 

重要な問題は、パーティションが固定されていないことです。 これを構築することは求められず、達成可能な最良の mex 値の合計を計算することだけが求められます。 

制約は大きく、n と更新回数 q は両方とも約 2 × 10^5 に達し、各操作で 1 つの周波数が変更されます。 これにより、更新ごとに答えを最初から再計算するソリューションは即座に除外されます。O(n) の再計算でも、最悪の場合、約 4 × 10^10 の操作が必要になるからです。 更新ごとにほぼ対数時間で答えを維持する構造が必要です。 

更新のたびにローカルで貪欲にパイルを形成しようとすると、微妙な失敗例が発生します。 たとえば、常に既存の杭を「拡張」しようとすると、すぐに非ローカル依存関係に遭遇します。追加の 0 を 1 つ追加すると、明らかに構造を共有していない杭であっても、多くの異なる杭の mex が同時に増加する可能性があります。 これにより、更新時に貪欲な構築が不安定になります。 

もう 1 つのよくある間違いは、答えが形成できる完全な「0 ～ k」チェーンの総数のみに依存すると仮定することです。 より高い値の寄与は、プレフィックス制約がすべての値に同時にどのように伝播するかに依存するため、その直感は近いですが不完全です。 

## アプローチ

 まず、最適化をより構造的な方法で言い換えます。 パイルの観点から考える代わりに、視点を反転します。パイルは、その mex が少なくとも x + 1 になるように、すべての整数 x の最終合計に 1 を与えます。これは、パイルに 0 から x までのすべての値が含まれている場合に正確に発生します。 

したがって、mex M を持つ各パイルは答えに M を寄与し、M より下のすべてのプレフィックスしきい値に 1 を寄与します。 

次に、しきい値 x を修正します。 x より大きい mex を持つことができる杭がいくつあるかを尋ねます。つまり、0 から x までのすべての値を含める必要があります。 このような各パイルには、そのプレフィックス内のすべての値のコピーが少なくとも 1 つ必要です。 したがって、そのようなパイルの最大数は、そのプレフィックス内の最も希少な値、つまり a[0]、a[1]、...、a[x] の中での最小頻度によって制限されます。 

b[x] = min(a[0..x]) と定義すると、b[x] は正確に mex が x より大きい山の最大数になります。 すべてのしきい値にわたる寄与を合計すると、すべての x にわたるこれらのプレフィックス最小値の合計として答えが得られます。 

したがって、問題全体は、ポイント更新時に配列のプレフィックス最小値の合計を維持することに帰着します。 

ブルート フォース ソリューションでは、O(n) の各更新後にプレフィックス最小値が再計算され、O(nq) が得られますが、最大制約では遅すぎます。 

重要な観察は、プレフィックスの最小値が非増加シーケンスを形成していることです。 単一の位置が変更されると、プレフィックス最小シーケンスはそのインデックス以降でのみ変更され、その変更は非常に構造化された形状になります。つまり、単調な実行最小値の再計算になります。 

この構造により、そのセグメントの prefix-min シーケンス全体を格納するセグメントを維持し、左側のセグメントの最小値によるクリッピングを考慮した方法でそれらをマージすることができます。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 更新ごとに再計算する | O(nq) | O(n) | 遅すぎる |
 | prefix-min シーケンス上のセグメント構造 | O(q log n) 償却 | O(n log n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### 核となるアイデア

 配列 a を維持し、b[i] が a[0..i] の最小値である派生配列 b を概念的に定義します。 答えはすべての b[i] の合計です。 

更新のたびに b を明示的に再構築する代わりに、各ノードがそのセグメントの完全な prefix-min 動作を保存するセグメント ツリーを維持します。 

### 1. セグメントの表現

 配列のすべてのセグメントについて、プレフィックスの最小シーケンスの圧縮表現をペアのリストとして保存します。 各ペアは値と、その値を持つ prefix-min 配列内の連続する位置の数を表します。 

これは、プレフィックスの最小値が減少するだけで増加しないため、シーケンスが自然に区分的に一定になるため機能します。 

また、セグメントを結合するときに必要な最小値もセグメントに保存します。 

### 2. リーフの初期化

 単一の位置 i の場合、prefix-min シーケンスは 1 つの値 a[i] のみです。 したがって、リーフ ノードには (a[i], 1) を含む 1 つのセグメントが格納され、その合計は a[i] に等しくなります。 

### 3. 2 つのセグメントの結合

 左側のセグメント L と右側のセグメント R を組み合わせる場合、L のすべての接頭辞は R の前に来るため、最初に L からすべての接頭辞の最小値を変更せずに取得します。 

R の場合、R 内のプレフィックスの最小値は L に見られる最小値を超えることができないという事実を考慮する必要があります。この最小値は、R のプレフィックス最小シーケンス内のすべての値を減らすグローバル キャップのように機能します。 

したがって、概念的には R の格納されたシーケンスを取得し、L の最小値よりも大きいすべての値をその最小値に置き換えます。 このクリッピングの後、R は依然として有効な非増加シーケンスであるため、必要に応じてそれを L の末尾にマージします。 

このマージにより、連結の prefix-min シーケンスが生成されます。 

### 4. 回答の抽出

 セグメント ツリーのルートでは、保存されている prefix-min シーケンス内のすべての値を単純に合計します。 この合計は、必要な答えと等しくなります。 

### なぜ効果があるのか

 不変条件は、すべてのノードがそのセグメントに限定された定義 b[i] = min(a[0..i]) に基づいてそのセグメントの prefix-min シーケンスを正確に格納し、このシーケンスが常に圧縮された単調形式で保持されることです。 連結のプレフィックスの最小値は左側のセグメントのプレフィックスの最小値のみに依存し、右側のセグメントの均一なキャップとして機能するため、マージ操作では正確さが維持されます。 接頭辞の最小値は単調であるため、クリッピングによって不一致が生じることはなく、等しい値のみがマージされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Node:
    __slots__ = ("mn", "seq", "sum")
    def __init__(self, mn=10**18, seq=None, s=0):
        self.mn = mn
        self.seq = seq if seq is not None else []
        self.sum = s

def merge(L: Node, R: Node) -> Node:
    if not L.seq:
        return R
    if not R.seq:
        return L

    res = Node()
    res.mn = min(L.mn, R.mn)

    seq = []

    for v, c in L.seq:
        seq.append([v, c])

    cap = L.mn
    for v, c in R.seq:
        nv = min(v, cap)
        if seq and seq[-1][0] == nv:
            seq[-1][1] += c
        else:
            seq.append([nv, c])

    res.seq = [(v, c) for v, c in seq]
    res.sum = sum(v * c for v, c in res.seq)
    res.mn = min(L.mn, R.mn)
    return res

def build(a, v, l, r):
    if l == r:
        node = Node(a[l], [(a[l], 1)], a[l])
        v[l + size] = node
        return
    m = (l + r) // 2
    build(a, v, l, m)
    build(a, v, m + 1, r)
    v.append(merge(v[l + size], v[m + 1 + size]))

def update(v, idx, val):
    i = idx + size
    v[i] = Node(val, [(val, 1)], val)
    i //= 2
    while i:
        v[i] = merge(v[2 * i], v[2 * i + 1])
        i //= 2

def query(v):
    return v[1].sum

n = int(input())
a = list(map(int, input().split()))
q = int(input())

size = 1
while size < n:
    size *= 2

seg = [Node() for _ in range(2 * size)]

for i in range(n):
    seg[size + i] = Node(a[i], [(a[i], 1)], a[i])

for i in range(size - 1, 0, -1):
    seg[i] = merge(seg[2 * i], seg[2 * i + 1])

out = []
out.append(str(seg[1].sum))

for _ in range(q):
    p, v = map(int, input().split())
    if p == 1:
        a[v] += 1
    else:
        a[v] -= 1

    i = v + size
    seg[i] = Node(a[v], [(a[v], 1)], a[v])

    i //= 2
    while i:
        seg[i] = merge(seg[2 * i], seg[2 * i + 1])
        i //= 2

    out.append(str(seg[1].sum))

print("\n".join(out))
```この実装では、ボトムアップのセグメント ツリーが使用されます。 各ノードは、圧縮された prefix-min シーケンスを値ブロックのリストとそのシーケンスの合計として保存します。 更新により単一のリーフが変更され、マージ操作を使用して祖先が再計算されます。 

重要な詳細は、すべての変更がローカルであるということです。1 つの増分または減分は 1 つのリーフにのみ影響し、すべての上位ノードは O(log n) マージで再構築されます。 

正確さは、各ノードが元の配列値ではなく、そのセグメントの prefix-min シーケンスを表すという不変条件を維持することに依存します。 

## 実用的な例

 小さな配列 a = [2, 1, 3] について考えてみましょう。 

プレフィックス最小値を作成します: b = [2, 1, 1]、したがって、答えは 4 です。 

| ステップ | 配列 a | プレフィックス最小値 b | 合計 |
 | --- | --- | --- | --- |
 | 初期化 | [2,1,3] | [2,1,1] | 4 |

 ここで、インデックス 1 に 0 を追加すると、= [2,2,3] となります。 接頭辞の最小値は [2,2,2] になり、合計は 6 になります。 

| ステップ | 配列 a | プレフィックス最小値 b | 合計 |
 | --- | --- | --- | --- |
 | 更新 | [2,2,3] | [2,2,2] | 6 |

 これは、単一の変更がその後のすべてのプレフィックス位置にどのように伝播するかを示しています。 

トレースは、更新がローカル値にのみ影響するのではなく、サフィックス全体の動作を平坦化または再形成する可能性があることを確認します。そのため、セグメント レベルのメンテナンスが必要です。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(q log n) 償却 | 各更新は O(log n) ノードを再構築し、各マージは圧縮セグメント サイズにおいて線形です。 
| スペース | O(n log n) | 各セグメント ツリー ノードには、圧縮されたプレフィックス最小表現が格納されます。 

各演算は対数数のノードのみに触れ、各ノードはコンパクトな単調データを格納するため、複雑さは n と q の制限内で最大 2 × 10^5 内に収まります。

 ## 特殊なケース

 重要なエッジケースは、すべての値がゼロの場合です。 この状況では、すべてのプレフィックスの最小値はゼロのままであるため、更新に関係なく、答えは常にゼロになります。 すべてのノード シーケンスが 1 つの繰り返し値に折りたたまれ、マージによって何も変更されないため、セグメント構造はこれをきれいに処理します。 

もう 1 つのエッジ ケースは、単一のポジションが新しいグローバル ミニマムになる場合です。 たとえば、要素がゼロに減少すると、その要素以降のすべてのプレフィックスの最小値も強制的に削除されます。 セグメント ツリーは、マージ中のクリッピング ステップを通じてこれを処理し、影響を受けるすべてのサフィックス ノードが新しいグローバル境界を正しく反映するようにします。 

3 番目のケースでは、同じインデックスでトグルが繰り返されます。 各更新ではリーフが完全に上書きされ、その祖先が再計算されるため、更新を繰り返してもエラーが蓄積されません。 ツリーは常に、影響を受けるパスに沿って正確な prefix-min 構造を最初から再構築します。
