 ## 解決策
 ## 問題の理解

 テーブルの脚の現在の長さを表す 4 つの数値が与えられます。 テーブルは、4 本の脚がすべてまったく同じ長さになって初めて安定します。 また、最大 1 本の脚に取り付けることができる固定長のパッドが 1 つあり、その脚の長さをその分だけ長くすることも、完全に無視することもできます。 

課題は、必要に応じてこのパッドを 4 本の脚のうちの 1 本に 1 回だけ適用した後、4 本の脚すべての長さが等しくなるかどうかを判断することです。 

制約は非常に小さく、各値は最大 100 です。これにより、大量の計算が必要なくなります。 意味のある状態は 5 つしかないため、すべての可能性を直接チェックすることさえ簡単ではありません。つまり、操作なし、または 4 つの脚の 1 つにパッドを適用しているということです。 

隠れたパフォーマンス上の懸念はありません。 主な困難は、論理的な完全性であり、「すでにフラットな」ケースと「1 回調整が必要な」ケースの両方を正しく考慮することを保証します。 

複数のレッグがすでに最大値を共有しており、パッドが誤って使用されてオーバーシュートする場合、微妙なエッジ ケースが発生します。 たとえば、足がすでに等しい場合、パッドを不必要に使用すると平等が崩れますが、パッドを使用しないことが許可されているため、正解の可能性は残ります。 

もう 1 つの厄介な状況は、元の値のサブセットが以前に等しかった場合でも、パッドを適用すると等価性が生じる場合です。 たとえば、現在の最大値に一致するように小さい脚を変換します。 

## アプローチ

 ブルートフォースアプローチでは、あらゆる可能なアクションが明示的に試行されます。 何もしないか、4 つの脚のうち 1 つを選択してそれにパッドの長さを追加します。 結果として得られる各構成について、4 つの値がすべて等しいかどうかを確認します。 構成は合計で 5 つしかないため、これは一定時間の作業となります。 

総当たりの正しさは徹底的さから生まれます。 すべての有効なソリューションは、これら 5 つの状態のいずれかに正確に対応する必要があります。 

ただし、「すべての操作を試す」という観点から考えると、少し間接的になります。 より明確な観察は、操作後の最終値は何らかの共通の目標値でなければならないということです。 その目標は、元の最大値 (それを超えて何も増やさない場合)、または小さい方のレッグの 1 つを高い方のレッグと一致するように増加することによって形成された値のいずれかです。 

したがって、アクションを列挙する代わりに、単一の均一な値に到達する実現可能性について推論することができます。 チェックする価値のある唯一の候補は、現在の最大値と、各脚を b ずつ増加させることによって形成される値です。

 ## アルゴリズムのチュートリアル

 問題を単純化して、単一の要素に最大 1 回のインクリメント操作を適用した後で 4 つの数値をすべて等しくできるかどうかを確認します。 

1. 4 つの脚の長さとパッドの長さを読み取ります。 便宜上、それらを小さなリストとして保持します。 
2. 4 本の脚の最大値を計算します。 すべての脚がすでに等しい場合、この最大値が最終目標となり、パッドを使用せずにすぐに成功を返すことができます。 
3. 最初に「操作なし」の場合を試してください。 4 つの値がすべてすでに等しい場合は、すぐに成功を返します。 これにより、変更に関する不必要な推論が回避されます。 
4. 次に、4 つの脚のそれぞれに 1 つずつパッドを使用することを検討します。 各インデックスについて、その脚にパッドの長さを一時的に加算し、4 つの値がすべて等しくなるかどうかを確認します。 
5. これら 4 つの変更のいずれかがすべてのレッグにわたって等しくなる場合、成功を返すことができます。 
6. 5 つの構成のいずれも機能しない場合は、テーブルを平らにすることは不可能であると結論付けます。 

### なぜ効果があるのか

有効な最終構成は、何もしないか、パッドを片方の脚にのみ適用するかのどちらかで作成される必要があります。 他の変換は許可されないため、解空間はこれら 5 つの状態によって完全にカバーされます。 各状態を明示的にチェックするため、有効な構造を見逃すことはありません。また、毎回直接等価性を検証するため、無効な構造を受け入れることはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ok(a):
    return a[0] == a[1] == a[2] == a[3]

a = [int(input()) for _ in range(4)]
b = int(input())

if ok(a):
    print(1)
    sys.exit(0)

for i in range(4):
    brr = a[:]
    brr[i] += b
    if ok(brr):
        print(1)
        sys.exit(0)

print(0)
```この実装は、直接の状態列挙を反映しています。 ヘルパー関数は 4 つのレッグすべての平等性をチェックします。これが成功に必要な唯一の条件です。 

最初に変更されていない構成を明示的にテストします。パッドの使用はオプションであるため、これは必要です。 次に、パッドを各脚に個別に適用するシミュレーションを行います。 毎回配列をコピーすることで、「シングル パッド」制約に違反する複数のアプリケーションを誤って蓄積することがなくなります。 

入力サイズは一定であるため、微細な最適化よりもシンプルさの方が価値があります。

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys

        return a[0] == a[1] == a[2] == a[3]

 ## 特殊なケース

 特殊なケースの 1 つは、テーブルがすでに平らになっている場合です。 のような入力の場合`3 3 3 3`の場合、アルゴリズムは不要な変更を試行することなく、すぐに成功を返します。 等価性チェックは、シミュレーションの前にこれを検出します。 

もう 1 つのケースは、パッドを間違った脚に適用すると等価性を超えてしまう場合です。 のために`2 2 2 2`と`b = 1`の場合、どの脚にもパッドを適用すると不一致が生じますが、最初に「何もしない」ケースもチェックするため、依然として正しく成功を返します。 

3 番目のケースは、パッドを追加した後、片方の脚だけが小さく、他の脚と正確に一致する場合です。`4 4 4 1`と`b = 3`。 ループは各インデックスを正しくテストし、最後のレッグに適用するときに有効な変換を見つけて、単一操作のカバレッジが十分であることを確認します。
