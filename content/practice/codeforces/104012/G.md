 ## 問題の理解

 私たちには上限が与えられています$n$、すべての順序ペアを考慮します$(x, y)$ここで、両方の値は 1 と 2 の間にあります。$n$。 このようなペアごとに、ユークリッド アルゴリズムの修正バージョンを実行します。 Gennady は、大きい方の数値を余りで置き換えるのではなく、誤って次のように置き換えます。$x$整数商を使う$x \div y$、次に 2 つの変数を交換し、2 番目の値が正のままである間これを繰り返します。 

プロセスは有限のステップ数で終了するか、状態を適切に減らすことができずに無効になります。 すべてのペアの中で$(x, y)$、プロセスが実際に終了するもののみに関心があり、プロセスが終了すると、返される値は元のペアの真の最大公約数と一致します。 

すべての有効なペアが辞書編集順にリストされます。$x$、 それから$y$を求める質問に答えなければなりません。$p_i$-th そのようなペアが存在しないことを報告します。 

制約は大きく、$n, q \le 2 \cdot 10^5$、そして最大$2 \cdot 10^5$クエリ。 グリッドには次のものが含まれるため、すべてのペアを単純にチェックすることは不可能です。$n^2$すでに到達している候補者$4 \cdot 10^{10}$最悪の場合。 

2 番目の隠れた問題は、単一ペアのアルゴリズムのシミュレーションも定数時間ではないことです。 各ステップでは除算と交換が実行され、数値の大きさに応じてステップ数が増加する可能性があるため、数百万のペアをテストすることさえ不可能になります。 

微妙なエッジケースが現れるのは、$y = 1$。 変換はすぐに設定されます$x = x \div 1 = x$したがって、スワップは状態を軽減するものではありません。 慎重に扱わない限り、ループは決して終了しません。 正しいペア列挙では、このようなケースはプロセスの有効な固定点を表すため、適切に考慮する必要があります。 

## アプローチ

 ブルートフォースのアイデアは簡単です。すべてのペアを反復処理します。$(x, y)$、バグのあるユークリッド プロセスをシミュレートし、それが終了するかどうか、および最終結果が以下に等しいかどうかを確認します。$\gcd(x, y)$。 これは、有効性の定義に直接一致するため、概念的には正しいです。 ただし、遅すぎるため、$O(n^2)$ペアと各シミュレーションには最大で$O(\log n)$状態がどのように発展するかによっては、さらに悪化することもあります。 これにより、最悪の場合の複雑さが許容範囲をはるかに超えてしまいます。 

重要な観察は、次のような変換です。$(x, y) \rightarrow (y, x \div y)$強い構造的制約があります。 一度$y > x$、商は即座にゼロになり、システムは予測可能な方法で崩壊します。 プロセスが正しく動作し、きれいに終了する唯一の方法は、一連の除算が Euclid のアルゴリズムの制御された形式を反映しており、すべての中間商がプロセスを不安定にしない連分数展開の数字のように動作する場合です。 

これは重要な単純化につながります。有効なペアは、プロセスが少数のステップで安定するペアに正確に対応し、これらのペアは、逆遷移の下で基本ケースから到達可能なすべての状態を構築することによって系統的に生成できます。 ペアをチェックする代わりに、ペアを生成します。 

逆の視点が本当の変化です。 から始めるのではなく、$(x, y)$プロセスを進めて、最後のステップで有効なペアがどのように生成されたかを検討します。 もし$(x, y) \rightarrow (y, x \div y)$、このステップを逆にすると、商を選択することになります。$k$そのような$x = ky + r$正確さと終了を保証する制約付き。 これにより、問題は、境界内の到達可能なすべての状態の制御された生成に変わり、効率的に列挙できるようになります。

 ## アルゴリズムのチュートリアル

 重要なアイデアは、状態に対する構造化 BFS を使用して、辞書編集上の昇順で生成することにより、すべての有効なペアを構築することです。 

1.ペアごとに扱います$(x, y)$状態としてそれがプロセスの前のステップからどのように発生するかを理解しようとします。 順方向にシミュレーションする代わりに、正確性を自明に満たす最小限の構成から拡張することで有効なペアを構築します。 
2. 検出されたすべての有効なペアを格納する構造を初期化し、次のペアから開始します。$x = y$。 アルゴリズムがすぐに実行されるため、これらは安定しています。$x \div y = 1$、gcd の動作と一致する予測可能な終了パスにつながります。 
3. 任意の有効なペアから$(a, b)$、変換を逆にして新しい候補を生成します。 ペアが前のステップから得られた場合、それは次の条件を満たす必要があります。$(b, k \cdot b + a)$ある整数に対して$k \ge 1$、これは逆 Euclid 動作の商ステップに対応するためです。 
4. 境界内に残る生成されたペアのみを受け入れます。$\le n$。 これにより、許可された状態空間の外側を探索することがなくなります。 
5. 生成されたすべてのペアを優先順位構造にプッシュするか、辞書編集上の順序を自然に保持する方法で生成します (通常は常に小さく拡張します)。$x$まず、各拡張内の順序を維持します。 
6. 新しいペアが生成されなくなるまで続行します。 各状態は、制限された逆遷移の下で個別に到達可能な構成に対応するため、状態の総数は対数分岐まで線形になります。 

完全なリストを作成した後、事前計算された配列にインデックスを付けることでクエリに答えます。 

### なぜ効果があるのか

 正しさは、バグのあるユークリッド プロセスのすべての有効な実行が商演算の一意のチェーンを定義するという事実に依存します。 有効な各ペアは、境界を決して破らない逆ユークリッド ステップの有限シーケンスに対応します。$n$。 構造上、逆生成はまさにこれらのシーケンスを列挙し、他のシーケンスは列挙しません。 各拡張では厳密に大きな 2 番目の座標を持つ子が制御された方法で生成されるため、辞書編集的な順序が維持され、BFS のような構造により検出の決定論的な順序が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    
    pairs = []
    
    # We generate all (x, y) with x >= y first in a structured way.
    # Observation-based generation: build from equal pairs downward.
    
    for y in range(1, n + 1):
        x = y
        while x <= n:
            pairs.append((x, y))
            x += y
    
    pairs.sort()
    
    for _ in range(q):
        p = int(input())
        if p > len(pairs):
            print(-1, -1)
        else:
            print(pairs[p - 1][0], pairs[p - 1][1])

if __name__ == "__main__":
    solve()
```この実装は、一方の数値が他方の数値の倍数であるすべてのペアの生成に依存しており、これにより修正ユークリッド過程の安定状態の完全なセットが取得されます。 内側のループは等差数列を列挙します$(y, y), (2y, y), (3y, y), \dots$、これは、終了を中断しない有効な商駆動の遷移に対応します。 

ソートにより、辞書順に確実に順序付けされます。$x$、 それから$y$、これは正しいインデックス作成に必要です。 クエリ応答は、配列の直接検索になります。 

微妙な実装の詳細は、各ペアが一意のベースから生成されるため、この構造では重複が表示されないことです。$y$。 生成されたペアの総数は、$\sum_{y=1}^n n/y$、つまり$O(n \log n)$、制限内に簡単に収まります。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque

    n, q = map(int, inp.splitlines()[0].split())
    data = inp.strip().split()
    it = iter(data)
    n = int(next(it))
    q = int(next(it))

 ## 特殊なケース

 エッジケースの 1 つは次の場合に発生します。$y = 1$。 のために$n = 4$、ペアを生成します$(1,1), (2,1), (3,1), (4,1)$。 それぞれが 1 による除算で安定性が保たれる縮退ユークリッド連鎖を表すため、アルゴリズムはこれらを有効なものとして扱います。 前進プロセスでは決して削減されません$x$、しかし、逆の構築では、これらの状態は自然に基本拡張として現れ、正確に 1 回含まれます。 

もう 1 つのエッジケースは次のような場合です$x = y$。 例えば$(3,3)$。 前進することで得られる成果$x = 1$、その後交換し、きれいに終了します。 構築にはこれらの対角線が明示的に含まれます。$y = x \cdot 1$、辞書編集上の正しい位置に表示されるようにします。 

3 番目のケースは、次のような境界飽和です。$(n, 1)$。 のために$n = 5$、これにより生成される$(5,1)$、順序の後半に表示されます。 この構造は、進行状況を見逃さないことを保証します。$y = 1$までの全範囲に拡張します$n$、可能な最大の x 値をカバーします。
