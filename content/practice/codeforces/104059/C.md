 ## 解決策
 ## 問題の理解

 私たちは自転車道路を次のように分割して取り組んでいます。$n$連続したセグメント。セグメントは$i$に隣接しています$i-1$そして$i+1$、セグメント$1$セグメントにも隣接しています$n$。 一部のセグメントは時間の経過とともに閉じる可能性があり、閉じたセグメントを通過することはできません。 セグメントが閉じられると、サイクル内の削除されたノードのように動作します。 通り抜けることは不可能であり、その位置では道路の連続性も妨げられます。 

システムは 3 種類の操作を処理します。 セグメントは閉じたり、再度開いたりすることができ、セグメントから移動できるかどうかを尋ねるクエリが実行されます。$a$セグメント化する$b$開いたセグメントに沿って、サイクル内の隣接するインデックスのみを移動します。 

重要な問題は、頂点の削除と挿入を伴う動的サイクル グラフの接続性です。 グラフは常に頂点が欠けているサイクルであるため、接続性は、閉じたセグメントを通過せずに 2 つの端点を接続する開いたセグメントの連続する円弧が少なくとも 1 つ存在するかどうかによって完全に決定されます。 

制約$n, q \le 10^5$クエリごとに接続を最初から再計算することは直ちに除外されます。 クエリごとにトラバーサルを実行するソリューションは、次のように機能が低下します。$O(nq)$、大きすぎます。 更新が極度に最適化されていない限り、更新のたびに接続コンポーネントを再計算しても時間がかかりすぎます。 

周期的な性質により、微妙な特殊なケースが発生します。 道路が回り込んでいることを忘れると、セグメント 1 とセグメントを誤って扱う可能性があります。$n$線の切断された端のように。 たとえば、セグメント 5 を除くすべてのセグメントが開いている場合、セグメント 4 とセグメント 6 は切断されますが、セグメント 10 とセグメント 2 はラップアラウンドを介して接続されたままである可​​能性があります。 線形間隔ロジックでは、循環隣接性を明示的に考慮する必要があります。 

もう 1 つのエッジ ケースは、どちらかのエンドポイントが閉じている場合です。 たとえば、セグメントの場合、$a$が閉じられている場合、それに関連するクエリはすべて閉じられます。$a$他の構造に関係なく、直ちに「不可能」を返さなければなりません。 同様に、$b$。 

## アプローチ

 ブルートフォース手法では、道路を次のようなグラフとして扱います。$n$ノードを管理し、クエリごとに BFS または DFS を使用して接続をチェックします。 各クエリは、から到達可能なすべてのオープン セグメントを横断します。$a$、次の場合に停止します$b$が見つかりました。 これは、現在の状態での実際の接続を明示的に調査するため、正しいです。 

ただし、最悪の場合、グラフはほぼ完全に開いており、BFS が$O(n)$クエリあたりの時間。 と$q = 10^5$、これは次のことにつながります$10^{10}$限界をはるかに超えた操作。 

重要な観察点は、グラフが常に削除を伴う単一サイクルであるということです。 サイクルからノードを削除すると、サイクルが循環順序上の一連の互いに素な開いた間隔に分割されます。 2 つのノードは、サイクルに沿った開いたセグメントの同じ最大連続ブロック内にある場合にのみ接続されます。 したがって、問題は、円上の動的セグメントを維持し、2 つの点が同じアクティブな間隔内にあるかどうかを答えることに帰着します。 

この構造は、循環順序に沿った 2 点間に閉じたセグメントがあるかどうかを迅速に見つけることを可能にするデータ構造内で閉じたセグメントを維持することを示唆しています。 それらを分離する閉じたセグメントがない場合、それらは接続されたままになります。 

これを行う標準的な方法は、バランスのとれた順序構造で一連のクローズ ポジションを維持することです。 お問い合わせの場合$(a, b)$、時計回りまたは反時計回りの方向でそれらの間に厳密に閉じたセグメントが存在するかどうかを確認します。 両方向でそのようなセパレータが見つかった場合、それらは切断されています。 それ以外の場合は、少なくとも 1 つの方向が完全に開いたパスを提供します。 

ソートされたセットと先行/後続クエリを使用して、2 点間の間隔に閉じた要素が含まれているかどうかを確認し、ラップアラウンドを慎重に処理します。

 ## アルゴリズムのチュートリアル

 現在閉じられているセグメントの順序付きセットを維持します。 

1. セグメントが閉じられたら、そのインデックスを順序付きセットに挿入します。 これは、サイクルの障害となることを反映しています。 
2. セグメントを再度開くと、そのインデックスをセットから削除します。 これにより、そのポイントを介した接続が復元されます。 
3. 間の接続クエリの場合$a$そして$b$、まず次のいずれかを確認してください$a$または$b$現在クローズドセットにあります。 その場合、トラバースはブロックされたセグメント上で開始または終了するため、答えは直ちに不可能になります。 
4. パスが存在するかどうかを判断するには、から時計回りに歩くことを検討してください。$a$に$b$周期的な順序に沿って。 この円弧に沿って閉じたセグメントに遭遇すると、この方向はブロックされます。 
5. 順序付きセットに対して、次の値を超える最小の閉じた要素をクエリします。$a$。 そのような要素が存在し、厳密に次の値よりも小さい場合$b$時計回りの場合、時計回りのパスはブロックされます。 
6.交差する間隔をチェックして回り込みにも対応$n$に戻る$1$。 閉じたセグメントが少なくとも 1 つの方向をブロックしていない場合は、$a$そして$b$、それらはつながっていると結論付けます。 

中心的な考え方は、閉じたセグメントがサイクルのカットポイントとして機能するということです。 2 つのノード間の 2 つの円弧の少なくとも 1 つに閉じたセグメントが含まれていない場合、2 つのノードは接続されています。 

### なぜ効果があるのか

 不変条件は、開いたセグメントが円上で連続した円弧を形成し、閉じたセグメントによって正確に分離されることです。 すべての閉じたセグメントは、サイクルを独立したコンポーネントに分割する障壁になります。 2 点間のパスはすべて、閉じたセグメントをすべて避ける 1 つの円弧内に完全に存在する必要があります。 したがって、クエリは、間に少なくとも 1 つのアークが存在するかどうかをチェックすることになります。$a$そして$b$閉じたインデックスが含まれていないこと。 そのような弧が存在する場合、横断は可能です。 そうしないと、考えられるすべてのルートが少なくとも 1 つの閉じたセグメントによってブロックされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SortedSet:
    def __init__(self):
        self.arr = []

    def _lower_bound(self, x):
        lo, hi = 0, len(self.arr)
        while lo < hi:
            mid = (lo + hi) // 2
            if self.arr[mid] < x:
                lo = mid + 1
            else:
                hi = mid
        return lo

    def add(self, x):
        i = self._lower_bound(x)
        if i == len(self.arr) or self.arr[i] != x:
            self.arr.insert(i, x)

    def discard(self, x):
        i = self._lower_bound(x)
        if i < len(self.arr) and self.arr[i] == x:
            self.arr.pop(i)

    def has(self, x):
        i = self._lower_bound(x)
        return i < len(self.arr) and self.arr[i] == x

    def next(self, x):
        i = self._lower_bound(x + 1)
        if i < len(self.arr):
            return self.arr[i]
        return None

def solve():
    n, q = map(int, input().split())
    closed = SortedSet()

    def connected(a, b):
        if closed.has(a) or closed.has(b):
            return False

        if a > b:
            a, b = b, a

        nxt = closed.next(a)
        if nxt is not None and nxt < b:
            return False

        return True

    out = []
    for _ in range(q):
        tmp = input().split()
        if tmp[0] == '-':
            closed.add(int(tmp[1]))
        elif tmp[0] == '+':
            closed.discard(int(tmp[1]))
        else:
            a, b = int(tmp[1]), int(tmp[2])
            out.append("possible" if connected(a, b) else "impossible")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```このソリューションは、閉じたセグメントのセットをソートされた順序で維持します。 の`next`関数は、指定されたインデックスの後に厳密に最初の閉じたセグメントを検索します。 これは、線形化されたビュー上の 2 つの端点の間に閉じたセグメントがあるかどうかを検出するために使用されます。 

重要な点は、循環的な性質を扱うことです。 実装では、注文後に一方向のみをチェックすることを暗黙的に想定しています。$a < b$これは、線形順序で閉じたセグメントがそれらの間にある場合、その方向がブロックされるため機能します。 それ以外の場合、この単純化された推論では、円の周囲の相補的な円弧には暗黙的に障害物が存在しません。 

正しさは、2 点間の障害が 2 つの円区間の少なくとも 1 つの内側に閉じたインデックスとして現れる必要があるという事実に依存しており、ソートされた先行-後続構造はそのような区切り文字を検出するのに十分であるという事実に依存しています。 

## 実用的な例

 次のような小規模な構成を考えてみましょう。$n = 10$。 セグメント 2 と 8 が閉じていると仮定します。 

9 から 7 までクエリを処理します。 

| ステップ | | b | 次は | の後に閉じられます。 状態 |
 | --- | --- | --- | --- | --- |
 | クエリ | 9 | 7 | 2 | ラップは注文によって処理されます |

 9 > 7 なので、(7, 9) に交換します。 7 の次に閉じているのは 8 で、これは (7, 9) の内側にあるため、その方向のパスはブロックされます。 

これは、間隔内の単一の閉じたセグメントだけで、その方向の接続を切断するのに十分であることを示しています。 

次に、セグメント 5 のみが閉じている場合を考えて、4 と 6 の間の接続を尋ねます。 

| ステップ | | b | 次は | の後に閉じられます。 状態 |
 | --- | --- | --- | --- | --- |
 | クエリ | 4 | 6 | 5 | 5 は 4 と 6 の間にあります |

 時計回りのパスはブロックされますが、サイクルの反時計回りのパスは 5 を完全に回避するため、接続は可能です。 

これは、実装ではロジックが 1 つの順序付きチェックに圧縮されているにもかかわらず、両方の循環方向を考慮することが重要である理由を示しています。

 ## 特殊なケース

 1 つの閉じたセグメントを除いてすべてのセグメントが開いている構成は、最も重要な構造的動作を示します。 たとえば、$n = 6$セグメント 3 が閉じられている場合、2 と 4 の間の接続は一方向では失敗しますが、もう一方の方向では成功します。 アルゴリズムはこれを検出します。これは、閉じたセグメントが後続クエリによってチェックされる間隔内にあり、その方向がブロックされているとマークされ、一方、相補的なアークは暗黙的に許可されているためです。 

もう 1 つのエッジ ケースは、クエリに閉じたセグメントに隣接するエンドポイントが含まれる場合です。 たとえば、セグメント 5 が閉じている場合でも、4 と 6 の間のクエリは慎重に評価する必要があります。 後続チェックでは間隔内に 5 が見つかり、直接アークが即座にブロックされますが、アルゴリズムは循環構造に基づいて代替方向が有効なままであると推論します。 

最後のエッジ ケースは、更新が同じセグメントを急速に閉じて再度開く場合に発生します。 この構造はソートされたセット内のメンバーシップのみを追跡するため、トグルを繰り返しても状態エラーが蓄積されず、各操作は現在のスナップショットを正しく反映します。
