 ## 解決策
 ## 問題の理解

 文字列として表される一連のカードが与えられます。各文字は、スートに対応する 4 種類のいずれかです。 目標は、同じスートのすべてのカードが 1 つの連続したブロックに表示され、4 つのブロックがスートのグローバルな固定順序で表示されるように、このシーケンスを変換することです。 許可される操作は、任意の 1 枚のカードを選択し、シーケンス内の他の場所に挿入することですが、必要なそのような動きの数を最小限に抑えたいと考えています。 

プロセスを再解釈する便利な方法は、一部のカードを所定の位置に保持し、残りを「再配置」して、最終的な配置がスートごとにグループ化されるようにすることを考えることです。 移動する必要がなく、最終的なグループ化された構造にすでに適合しているすべてのカードは最適解に貢献しますが、構造を壊すすべてのカードは移動を強制します。 

文字列の長さは最大 100,000 です。 動きをシミュレートしたり、配置の順列を調べたりしようとするソリューションは、10^10 程度の 2 次作業でさえ 2 秒の実行時間の制限をはるかに超えているため、すぐに失敗します。 これにより、線形スキャン、または最悪の場合でもサイズ 4 の固定アルファベット上での小さな定因数動的プログラミングが行われるようになります。 

微妙な点は、スーツの最終的な順序が明示的に示されていないことです。 つまり、答えは 4 つのスート ブロックの最適な組み合わせを選択することに依存します。 素朴なアプローチでは、h、d、c、s のような固定順序を想定するかもしれませんが、異なる順序によってより多くのカードが所定の位置に留まるケースを見逃してしまいます。 

簡単な例でその危険性を示します。 文字列が`chch`。 h、c、その他の順序を強制すると、多くのカードを移動する必要があります。 しかし、c を選択してから h を選択すると、より適切な位置合わせが得られます。 この順序への依存が重要な難点です。 

1 つのスートが完全に存在しない場合、別の特殊なケースが発生します。 例えば`hhhhh`すでに有効な単一ブロック配置であるため、順序に関係なく手は必要ありません。 

## アプローチ

 ブルート フォース ソリューションでは、4 つのスートのすべての順列を試し、順列ごとに、すでにその順序と一致しているカードの数を計算します。 固定順列の場合、文字列をスキャンして各文字をターゲット セグメントに割り当て、不一致をカウントしたり、ブロック構造に適合する最長のサブシーケンスを計算したりできます。 これが機能するのは、順序が固定されると、基本的に、正しい相対位置にすでに何枚のカードが配置されているかを確認することになるからです。 

4つしかないよ！ = 24 個の順列があるため、それらを列挙することはボトルネックではありません。 ボトルネックは、特定の順列に対する最適なアライメントを効率的に計算することです。 代入を直接シミュレートする場合、非減少ブロック順序で既に出現している文字数を最大化する最長部分列問題として扱うことができます。 

重要な観察は、スートの固定順列の場合、文字列をその順序に対応する 4 つのセグメントに分割した場合に、その位置に留まることができる文字数を知る必要があるだけであるということです。 順列の各プレフィックスについて、左から右へのスキャン中に、一致する文字をいくつ割り当てることができるかを維持します。 これは 4 つの状態にわたる小さな動的計画法になります。 

全体的な最適な答えは、カードの合計数から、すべての順列にわたって保持できるカードの最大数を引いたものです。 これにより、移動の最小化から保存された構造の最大化へと問題が再構成されます。

 ## アルゴリズムのチュートリアル

 4 つのスートの各順列を最終順序の候補として扱います。 このような順序ごとに、再配置を必要とせずに残せる文字数を計算します。 

1. 4 つのスートのすべての順列を生成します。 各順列は、最終的にグループ化されたブロックの順序を表します。 
2. 固定順列の場合、4 つの状態にわたる動的プログラミング テーブルを維持します。 状態は、順列の最初の i ブロックに既に正常に割り当てられた文字の数を表します。 
3. 文字列を左から右にスキャンします。 文字ごとに、それがまだ収まる順列内の可能な限り最初のブロックに配置しようとします。 これにより、後で属する可能性があるキャラクターの以前の位置を無駄にしないことが保証されます。 
4. DP トランジションを更新して、文字が現在のブロックに一致する場合、そのブロック内にそれを保持するか、スキップして将来のブロックを検討できるようにします。 これにより、カウントの正確性を確保しながら柔軟性が維持されます。 
5. 完全な文字列を処理した後、この順列に対してすべての状態に割り当てられる最大文字数を計算します。 
6. すべての順列にわたって最良の結果を追跡します。 
7. 最終的な答えは、全長から達成可能な最大の保持数を引いたものになります。 

順列内でこの貪欲な配置が機能する理由は、ブロックが順序付けされているためです。そのため、キャラクターが後のブロックに割り当てられると、そのキャラクターは前のブロックには決して貢献できなくなります。 この単調な制約により、問題はカウントの階層的な累積に帰着します。 

### なぜ効果があるのか

 固定順列の場合、可能な限り最良の配置は、ブロック順序を尊重する文字列のサブシーケンスを選択することに対応します。 有効な最終的な配置では、そのようなサブシーケンスが発生します。つまり、ブロック i に割り当てられた文字は、元の文字列のブロック i+1 に割り当てられた文字より前に出現する必要があります。 DP は、そのような構造化されたサブシーケンスの最大サイズを計算します。 すべての有効な最終配置はそのようなサブシーケンスの 1 つに対応し、その逆も同様であるため、DP 値を最大化すると最小の移動数が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from itertools import permutations

def solve():
    s = input().strip()
    n = len(s)

    suits = ['h', 'd', 'c', 's']
    best_keep = 0

    for perm in permutations(suits):
        dp = [0, 0, 0, 0]

        for ch in s:
            new_dp = dp[:]

            for i in range(4):
                if ch == perm[i]:
                    new_dp[i] = max(new_dp[i], (dp[i-1] if i > 0 else 0) + 1)

            for i in range(4):
                new_dp[i] = max(new_dp[i], dp[i])

            dp = new_dp

        best_keep = max(best_keep, dp[3])

    print(n - best_keep)

if __name__ == "__main__":
    solve()
```この実装は、すべてのスーツの順序を列挙し、ブロック構造を尊重した最適なサブシーケンスをそれぞれ計算することに依存しています。 DP アレイ`dp[i]`ブロックに割り当てられる最大文字数を格納します`i`。 遷移は、現在のブロックを拡張するか、以前の最良の値を繰り越します。 

微妙な点は、私たちは常に読んでいることです`dp[i-1]`ブロックを拡張するときに、有効なブロック進行のみを構築するようにします。 フォールバック`dp[i] = max(dp[i], dp[i])`伝播により、割り当てを強制することなく文字のスキップが許可されるようになります。 

## 実用的な例

 インプットを考慮する`hccdhcd`。 

順列を評価しますが、1 つの適切な順序に焦点を当てます`h c d s`。 

| キャラクター | 前の dp | アクション | |後の dp
 | --- | --- | --- | --- |
 | h | 0 0 0 0 | h に配置 | 1 0 0 0 |
 | c | 1 0 0 0 | C に配置します | 1 1 0 0 |
 | c | 1 1 0 0 | C に配置します | 1 2 0 0 |
 | d | 1 2 0 0 | d | の位置 1 2 1 0 |
 | h | 1 2 1 0 | 改善できない | 1 2 1 0 |
 | c | 1 2 1 0 | C に配置します | 1 3 1 0 |
 | d | 1 3 1 0 | d | の位置 1 3 2 0 |

 これにより、h に 3 文字、c に 3 文字、d に 2 文字が生成されますが、保持可能な最大のサブシーケンスに対応する、最良の構造化された進行として重要なのは最後の dp[3] だけです。 

のために`cchhdshcdshdcsh`より混合された配置である DP では、文字をブロック全体に分散させることができ、厳密な順序を強制するのではなく、繰り返されるクラスターを整列させる順列を識別します。 

トレースは、順序で許可されている場合にのみ、異なるブロック間で文字を再利用できる方法と、DP が不正な後方割り当てをどのように自然に防止するかを示しています。

 ## 特殊なケース

 次のような完全に均一な文字列`sssssss`すべての順列が最初のブロックで完全に一致し、DP がアライメントを失うことがなく、移動がゼロになるため、 は正しく処理されます。 

次のような厳密に交互のパターン`hdhdhdhd`順列の選択に依存します。 このアルゴリズムは 24 個の順序すべてを評価し、最良の順序付けによってすべての同一のスーツが連続ブロックにグループ化され、ローカルの貪欲スキャンが成功しない場合でも DP が最大限の保持を確実に捕捉します。 

1 つ以上のスーツが欠落しているケース。`hhddcc`、順列内の空のブロックは制約に寄与しないため、自然に処理されます。 DP は、正確さに影響を与えることなく未使用のブロックを単純にスキップし、最良の置換によって残りのスーツが最適に配置されます。
