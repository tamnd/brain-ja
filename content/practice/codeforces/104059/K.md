 ## 解決策
 ## 問題の理解

 2 × n ブリッジは n 個の位置から構築されます。各位置には、左と右の 2 つの可能なタイルがあります。 各位置で 2 つのうち 1 つだけが安全であり、位置 i の安全側は長さ n の文字列によって与えられます。各文字は、左のタイルが正しいか右のタイルが正しいかを示します。 

プレイヤーは決められた順序で 1 人ずつ橋を渡ります。 各プレイヤーは、n 個のポジションをすべて通過しようとします。 最初のプレーヤーには事前情報がなく、決定的な「切り替え」動作に従います。位置 1 で左のタイルを踏むことから始めて、次の位置ごとにサイドを交互に変えます。 

以降のプレイヤーは部分的な知識を持っています。 前のプレイヤーがタイルをうまく踏むと、そのタイルはその位置で安全であることが確認されます。 プレイヤーが間違ったタイルを踏んだ場合、彼女はすぐに落ちますが、その失敗により、どのタイルがその位置に正しかったかが明らかになり、将来のすべてのプレイヤーはこの新しい情報を使用します。 まだ確定していないポジションについては、プレイヤーは再び最後のステップから同じ切り替え動作に従います。 

タスクは、失敗するたびに知識が蓄積されることを前提として、何人のプレイヤーが位置 n に正常に到達できるかを決定することです。 

制約 n、k ≤ 1000 は、O(nk) シミュレーションでも十分に高速であることを意味します。 各プレーヤーは最大で n ステップを実行するため、単純なシミュレーションは制限内に快適に収まります。 

初期のプレイヤーがすぐに失敗する場合、微妙なエッジケースが発生します。 たとえば、最初のポジションが R の場合、最初のプレーヤーは常に L から開始し、即座に倒れ、正しい選択が明らかになります。 これは連鎖的に発生し、その後の動作が大きく変化する可能性があります。 もう 1 つのエッジ ケースは、プレイヤーが橋全体を完了したときに発生します。これは、新しい情報が追加されず、後のすべてのプレイヤーが同じように動作するため、答えが飽和状態になります。 

## アプローチ

 素朴なアイデアは、各プレーヤーを独立してゼロからシミュレートし、常に既知の内容を再計算し、切り替えルールを適用しながら n ステップすべてを実行することです。 各シミュレーションでは文字列全体がスキャンされ、不一致が発生するたびにグローバルな情報が更新され、次のプレーヤーが再起動されます。 

これはすでに説明したプロセスと一致していますが、重要な非効率性は、すでに完全に認識され安定しているブリッジの部分であっても、各プレーヤーが決定を再計算していることです。 それでも、k と n は最大 1000 までしかないため、この繰り返しスキャンでも約 10^6 回の操作以内にとどまるため、より高度な最適化は必要ありません。 

重要な観察は、プレイヤー間で重要となる唯一の状態は、どのポジションがすでに公開されているかであるということです。 ポジションが判明すると、その後のすべてのプレイヤーはそこで決定論的に行動し、そのポジションではそれ以上の変更は起こりません。 したがって、何かを再計算する代わりに、既知の位置のブール配列を維持し、各プレーヤーを 1 回シミュレートするだけです。 

ブルートフォースアプローチはルールに直接従うため機能しますが、毎回既知の情報を再取得する方法が概念的に冗長になります。 最適化されたアプローチでは、すべての履歴が 1 つの進化する状態に折りたたまれ、各プレーヤーがその状態の継続として実行されます。

 ## アルゴリズムのチュートリアル

 各位置で正しいプレートがすでに発見されているかどうかを示す長さ n の既知の配列を維持します。 

また、実際の構成を表す指定された文字列 s も保持します。 

選手一人一人をシミュレーションしていきます。 

### ステップ

1. すべての値を false に設定して既知の配列を初期化します。これは、最初に位置が確認されないことを意味します。 
2. 各プレーヤーを 1 から k まで繰り返します。 
3. 各プレイヤーのトラバースの開始時に、変数 last を L に設定します。 これは、プレーヤーが前の位置で踏んだ側を表し、すべてのトラバースは左ステップから始まるというルールによって固定されています。 
4. 0 から n − 1 までの各位置 i について、次の手を決定します。 
5. known[i] が true の場合、正しい側はすでに決定されているため、プレイヤーは単に s[i] にステップし、それに応じて最後に更新します。 
6. known[i] が false の場合、プレーヤーは切り替えルールに従い、最後と反対側に進みます。 
7. 選択したサイドが s[i] と一致する場合、プレーヤーはこのポジションを生き残り、選択したサイドを最後に更新します。 
8. 選択した側が s[i] と一致しない場合、プレーヤーは位置 i に落ちます。 正しい側が s[i] であることが判明したため、known[i] を true としてマークし、このプレーヤーの処理を直ちに停止します。 
9. プレーヤーが落下せずに位置 n に到達した場合、このプレーヤーは成功したと見なされます。 

### なぜ効果があるのか

 既知のポジションはいつでも、将来のすべてのプレイヤーにそこで同じ正しいアクションを強制する固定的な制約のように動作します。 唯一の不確実性は未知のポジションに存在し、すべてのプレーヤーは直前のステップのみに基づいて同じ決定論的な交互ルールに従います。 

失敗するたびに既知の情報の量が厳密に増加し、以前の知識が無効になることはありません。 これにより、単調なプロセスが作成されます。既知の状態は拡大するだけです。 各拡張は未知の位置での失敗によってトリガーされ、位置は n 個しかないため、プロセスは最大でも n 回の暴露後に安定し、後続のプレイヤーは同じように動作します。 したがって、シミュレーションはゲーム内の情報の進化を正確に反映します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    s = input().strip()

    known = [False] * n
    ans = 0

    for _ in range(k):
        last = 'L'
        ok = True

        for i in range(n):
            if known[i]:
                choice = s[i]
            else:
                choice = 'R' if last == 'L' else 'L'

            if choice == s[i]:
                last = choice
            else:
                known[i] = True
                ok = False
                break

        if ok:
            ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションは、進化する知識状態を維持します。`known`。 各プレーヤーは独立してシミュレートされますが、この共有状態を使用します。 変数`last`は、すべてのトラバースが左のタイルを踏むことから始まるというルールを強制するために、各プレイヤーに対してリセットされます。 未知の位置にヒットすると、アルゴリズムが切り替えルールを適用して移動を決定します。 不一致があると、現在のプレーヤーが終了し、その位置の正しいタイルが表示されます。 

よくある落とし穴は、間違った持ち方をすることです`last`プレイヤー全体で。 各プレイヤーは交代ロジックを再起動する必要があります。そうしないと、切り替えパターンが意図したルールから逸脱し、誤った移行が発生します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

 | 時間 | O(nk) | k 人のプレーヤーはそれぞれ、最大で n 個のポジションを 1 回スキャンします。 
| スペース | O(n) | 各位置の既知のステータスを保存します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, k = map(int, input().split())
    s = input().strip()

    known = [False] * n
    ans = 0

    for _ in range(k):
        last = 'L'
        ok = True
        for i in range(n):
            if known[i]:
                choice = s[i]
            else:
                choice = 'R' if last == 'L' else 'L'

            if choice == s[i]:
                last = choice
            else:
                known[i] = True
                ok = False
                break
        if ok:
            ans += 1

    return str(ans)

# provided samples
assert run("3 5\nLRL\n") == "3"
assert run("3 2\nRRR\n") == "1"

# minimum size
assert run("1 1\nL\n") == "1"

# all equal safe left
assert run("5 4\nLLLLL\n") == "4"

# alternating pattern
assert run("4 3\nLRLR\n") == "3"

# immediate failure cascade
assert run("2 3\nRL\n") == "2"

 ## 特殊なケース

 最初の位置が不明で、最初のプレイヤーにとって不一致である場合、アルゴリズムは即座にその位置を既知としてマークし、後のすべてのプレイヤーが正しい情報で開始できるようにします。 失敗すると次のプレーヤーに移動する前に更新がトリガーされるため、これは正しく処理されます。 

すべてのポジションが同じ入力の場合、最初のプレーヤーの交互のパターンが予測可能な一連の失敗を引き起こし、最終的にシステムを安定させます。その後、残りのすべてのプレーヤーが決定的に成功するか失敗します。 既知は増加するだけでリセットされないため、シミュレーションはこれを捉えます。 

k が n に比べて大きい場合、システムは最大でも n 回の暴露後にすぐに固定状態に到達します。 その時点以降、すべてのプレイヤーは同じように行動し、アルゴリズムは特別なケースを必要とせずに、残りの成功したプレイヤーを自然にカウントします。
