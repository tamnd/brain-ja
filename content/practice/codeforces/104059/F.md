 ## 解決策
 ## 問題の理解

 頂点が平面地図の交差点であり、エッジが道路セグメントである幾何学グラフが与えられます。 道路は指定された端点間の直線セグメントであり、重要な幾何学的保証は、任意の 2 つのセグメントが共有端点でのみ交差することであるため、描画はグラフの有効な平面直線埋め込みになります。 

これらの道路から、閉ループを形成するセグメントのサブセットを選択する必要があります。 グラフの用語では、単純なサイクルを探しています。 選択したループの品質は、ループに含まれる交差の数、つまりサイクル上に頂点がいくつあるかによって測定されます。 タスクはこの数値を最小化することなので、事実上、グラフ内の最短サイクルの長さが求められます。 

この制約により、スパースグラフの考え方が推進されます。 最大 100,000 個の頂点と 300,000 個のエッジでは、すべてのサイクルを明示的に検査しようとするアプローチは不可能です。 頂点を越える 3 次または 2 次の戦略は手の届かないものであり、$O(nm)$推理が遅すぎる。 構造が十分に疎であるため、隣接リストに対する線形または線形に近いトラバーサル手法が唯一の実行可能な方向となります。 

小さなサイクルがまったくないグラフからは、微妙なエッジ ケースが発生します。 たとえば、非常に長い迂回を伴うツリー状の構造では、答えが大きくなる可能性があり、三角形や小さなサイクルが存在すると仮定する素朴なアプローチは失敗します。 もう 1 つの問題は、マルチグラフ解釈で複数のエッジによって 2 サイクルが作成される可能性があることですが、ここでは平行エッジが禁止されているため、可能な最小サイクル長は少なくとも 3 になります。 

主な問題点は、サイクルがグローバル オブジェクトであるのに対し、入力はローカルな隣接情報であることです。 正しいソリューションでは、頂点を繰り返さない最短の閉じたウォークを効率的に検出する必要があります。 

## アプローチ

 直接的なアプローチは、単純なサイクルをすべて列挙することです。 各頂点から開始して DFS を実行し、いつ開始に戻るかを検出しながら訪問した状態を追跡することができます。 これによりサイクルが正しく検出されますが、考えられる DFS パスの数はグラフの密な領域で指数関数的に増加します。 グラフ内の単純なサイクルの数は指数関数的に増加する可能性があるため、再訪問を枝刈りしても最悪の場合は保存されません。 

より構造化された改善は、最短経路推論を使用することです。 重み付けされていないグラフでは、サイクルがエッジを取っているように見えることがあります$u-v$、一時的に削除し、からの最短パスを見つけます。$u$に$v$。 削除されたエッジを追加するとサイクルが閉じるため、サイクルの長さは最短パスに 1 を加えたものになります。 1 つのエッジが削除されると、どのサイクルも 2 つの隣接する頂点間のパスになるため、これは正しいです。 

これにより、隣接する頂点の多くのペア間の最短パスを計算するという問題が軽減されます。 各エッジに対して BFS を最初から実行すると、次のようになります。$O(m(n+m))$、これは大きすぎます$m = 3 \cdot 10^5$。 

重要な点は、エッジごとに個別に正確な最短パスを求める必要はないということです。 代わりに、BFS 探索を再利用し、これまでに見つかった最良のサイクルをすでに超えている場合は常に早期に停止できます。 最小サイクルのみに関心があるため、現在の最良の回答を超えて拡大する検索は無関係であり、積極的に剪定することができます。 

これにより、動的カットオフによる BFS 実行の繰り返しが問題となります。 理論的には依然として最悪の二次方程式ですが、実際には、このような問題に特有の疎なグラフの制約の下では、このアプローチは合格することを目的としています。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | DFS 経由ですべてのサイクルを列挙する | 指数 | O(n + m) | 遅すぎる |
 | エッジ最短パスごとの BFS | O(m(n + m)) | O(n + m) | 遅すぎる |
 | プルーニングを備えたマルチソース BFS | O(n(n + m)) 最悪、事実上はるかに小さい | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは繰り返しの BFS 実行に依存しており、それぞれが頂点から開始し、その開始から形成できる最短のサイクルを発見しようとします。 重要なトリックは、現在のベストアンサーを改善できなくなったらすぐに BFS を停止することです。 

1. 答えを非常に大きな数値として初期化します。 これは、これまでに見つかった最良のサイクル長を表します。 
2. 道路セグメントからグラフの隣接リストを作成します。 これが私たちが繰り返したどる構造です。 
3. 各頂点に対して、その頂点から他のすべての頂点までの最短距離を計算する BFS を実行します。ただし、深さが現在の最良の回答から 1 を引いた値にすでに達しているパスの拡張は停止します。 この頂点を通じて検出されるサイクルは、少なくとも距離に 1 つのエッジを加えた長さでなければならないため、このカットオフは有効です。 
4. BFS 中に、BFS ツリー内の直接の親ではなく、既に訪問されている頂点にエッジをトラバースするたびに、サイクルが検出されます。 サイクル長は、2 つの BFS 深さに 1 を加えた合計です。 この値が小さい場合は、グローバル回答を更新します。 
5. いずれかの時点で BFS の深さが現在の最良の回答を超えるか等しい場合、より良いソリューションに貢献できないため、その BFS を早期に終了します。 
6. すべての頂点から BFS を実行した後、見つかった最適なサイクル長を出力します。 

正確かどうかは、BFS が固定開始から長さの増加順にすべての最短パスを探索するという事実にかかっています。 その開始頂点を含むサイクルは、最短パス ツリー接続を閉じるバック エッジを通じて検出されます。 

### なぜ効果があるのか

 すべての単純なサイクルは、BFS 探索中に最初に繰り返される頂点で交わる 2 つの最短パスに分解できます。 BFS は、非ツリー エッジを通じて以前に訪問した頂点に初めて遭遇したときに、検出されるパスの長さがソースから最小であることを保証します。 これにより、BFS ルートから検出されたサイクルがそのルートに関して最小であることが保証され、すべてのルートの最小値を取ることでグローバル最小サイクルが取得されます。 

部分パスが既知の最良のサイクルを超えると、それを拡張してもより長いサイクルしか生成されないため、枝刈りによって最適なソリューションは削除されません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n, m = map(int, input().split())
    
    coords = [tuple(map(int, input().split())) for _ in range(n)]
    
    adj = [[] for _ in range(n)]
    for _ in range(m):
        a, b = map(int, input().split())
        a -= 1
        b -= 1
        adj[a].append(b)
        adj[b].append(a)

    INF = 10**9
    ans = INF

    for start in range(n):
        if ans == 3:
            break

        dist = [-1] * n
        parent = [-1] * n
        q = deque()

        dist[start] = 0
        q.append(start)

        while q:
            v = q.popleft()

            if dist[v] >= ans - 1:
                continue

            for to in adj[v]:
                if dist[to] == -1:
                    dist[to] = dist[v] + 1
                    parent[to] = v
                    q.append(to)
                elif parent[v] != to:
                    cycle_len = dist[v] + dist[to] + 1
                    if cycle_len < ans:
                        ans = cycle_len

    print(ans if ans != INF else -1)

if __name__ == "__main__":
    solve()
```このコードは、道路セグメントから標準の隣接リストを構築します。 BFS は、距離配列を使用して現在の開始ノードからの最短距離を格納し、親配列を使用してツリーのエッジをサイクルとしてカウントすることを回避します。 

重要な実装詳細は条件です。`parent[v] != to`これにより、BFS ツリーのエッジをすぐにはサイクルとして扱わなくなります。 親ではない訪問済みの近傍を見つけると、サイクルを閉じるバックエッジが見つかったことになります。 

剪定の様子`if dist[v] >= ans - 1`これは、これまでに見つかった最良のサイクルを改善できないパスの探索を回避することで、ランタイムを制御下に保つものです。 

## 実用的な例

 ### サンプル 1

 小さなサイクルが存在するグラフから始めます。 異なる開始点からの BFS は徐々にサイクルを検出しますが、最小のものは早期に検出されます。 

| 開始 | BFS の発見 | 検出されたサイクル | 最高の答え |
 | --- | --- | --- | --- |
 | 0 | 近隣を探索し、バックエッジを素早く見つけます | サイクル長 4 | 4 |
 | 1 | 同様の探索 | サイクル長 ≥ 4 | 4 |
 | 2 | 改善なし | なし | 4 |

 コンパクト ループに到達する最初の BFS はすでに最適な答えを確立しており、枝刈りによって他の頂点からの不必要な完全な走査が防止されます。 

### サンプル 2

 このグラフには、異なるサイズの複数の重なり合うサイクルが含まれています。 

| 開始 | BFS の発見 | 検出されたサイクル | 最高の答え |
 | --- | --- | --- | --- |
 | 0 | 最初に長いサイクルを見つけます | 6 | 6 |
 | 3 | より小さいループを見つけます | 4 | 4 |
 | 7 | 改善なし | なし | 4 |

 トレースは、複数の BFS ルートが必要な理由を示しています。異なる開始点により異なるサイクル構造が明らかになり、グローバルな最小値のみが問題となります。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n(n + m)) 最悪の場合、通常ははるかに少なくなります。 BFS は各ノードから実行されますが、実際にはプルーニングにより完全な探索が妨げられます。 
| スペース | O(n + m) | 隣接リストと BFS 配列 |

 グラフはまばらであり、$m \le 3n$これにより、実際の BFS 操作の効率が維持されます。 現在の最適なサイクルに基づく枝刈りは、小さなサイクルが見つかったときに検索スペースがすぐに崩壊するようにするために不可欠です。

## 特殊なケース

 重要なエッジ ケースは、ほぼツリーであるが、非常に大きなサイクルを形成する 1 つの余分なエッジを含むグラフです。 ほとんどのノードから BFS を開始すると、バックエッジを見つける前にほぼグラフ全体が探索されますが、枝刈りロジックにより、小さなサイクルが他の場所で見つかると、それ以上の探索は早期に打ち切られることが保証されます。 アルゴリズムは、より小さなサイクルが存在しない場合でも、最終的には正しい大きなサイクルを発見します。 

もう 1 つのケースは、複数の短いサイクルが重なる密なローカル クラスタリングです。 異なるルートからの BFS により、少なくとも 1 つのルートが最短サイクルを早期に公開し、グローバル最小値が即座に更新されます。 

最後の微妙なケースは、最短サイクルに BFS の開始頂点が含まれていない場合です。 そのような状況でも、サイクルの両方のエンドポイントには最初から最終的に到達し、2 番目のエンドポイントが処理されるときにバックエッジ条件がトリガーされるため、BFS はサイクルを検出します。
