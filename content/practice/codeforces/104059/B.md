 ## 解決策
 ## 問題の理解

 それぞれが正の整数の「周期性」値を持つセミのコレクションが与えられています。 それらの一部を破棄することは許可されており、その後、残ったものだけを検討します。 

残りのセミはペアになり、各ペアは周期が 2 つの値の合計となる新しいセミを生成します。 重要な要件は、残りのセミがどのようにペアになっているかに関係なく、可能なすべての交配が非素数周期性を生成する必要があるということです。 これは強力な条件です。つまり、ペアリング戦略を選択しているのではなく、最悪のペアリングであっても素数和が得られるペアが存在しないようなサブセットを選択しているのです。 

目標は、この特性を確実に維持しながら、できるだけ多くのセミを飼育することです。 

n < 750 という制約は、O(n^2) の構築は実行可能ですが、サブセットに対する 3 次または指数探索を伴うものは不可能であることを示唆しています。 2^n 個のサブセットがあり、1 つのサブセットを単純に検証する場合でもペアリングを考慮する必要があるため、これにより、総当りのサブセット チェックから即座に遠ざけられます。 

「好きなように交尾できる」という表現には微妙な問題が現れています。 これは、固定されたペアリング戦略を想定することができないことを意味します。 これを「適切な組み合わせを選択できる」と解釈するのは単純な間違いであり、これははるかに簡単ではありますが、間違った定式化につながる可能性があります。 この要件はすべてのペアに共通です。 

もう 1 つの落とし穴は、パリティ相互作用を無視することです。 2 を除くすべての素数は奇数であるため、和が素数であることはどのペアが重要であるかを大きく制約し、これを見落とすと、過度に複雑になったり不正確なグラフ モデルが生成されます。 

## アプローチ

 直接的なアプローチは、セミのすべてのサブセットを試し、各サブセットについて、考えられるすべての組み合わせが素数和を回避しているかどうかを確認することです。 サイズ k のサブセットを修正したとしても、敵対的マッチングを考慮する必要があるため、すべてのペアリングのチェックは k の階乗になります。 これはすぐに実行不可能になります。 

より構造化された観点は、モデルの互換性です。 それぞれのセミをノードと考え、2 つのノードの合計が素数であれば接続します。 セミのサブセットを飼うということは、基本的に、このサブセット内のどのペアリングにおいても、決して優位に立ってはいけないと言っていることになります。 これは、サブセットには「不良エッジ」で接続されたノードのペアが含まれてはならないと言っているのと同じです。 

したがって、条件は次のようになります。内部にエッジが存在しないような頂点の最大のサブセットを選択します。 これはまさに、エッジが「不良ペア」を表すグラフにおける最大独立集合問題です。 

ここで重要な構造が表示されます。pi + pj が素数で、両方の値が整数の場合、合計は素数であるため、特別な素数 2 を除いて奇数になります。2 は唯一の偶数の素数であるため、2 より大きい素数の合計は奇数でなければなりません。これは、一方の端点が偶数で、もう一方の端点が奇数であることを意味します。 したがって、すべてのエッジが偶数と奇数を接続し、グラフが 2 部構成になります。 

グラフが 2 部構成であると認識されると、問題はきれいに変化します。 どのグラフでも、最大独立セットは合計頂点から最小頂点カバーを引いたものに等しくなります。 2 部グラフでは、ケーニッヒの定理により、頂点カバーの最小値は一致の最大値と等しくなります。 したがって、最大の 2 部マッチングを計算し、そのサイズを n から減算するだけで済みます。 

問題全体は、偶数と奇数の 2 部グラフを構築し、素な「悪いペア」の最大数を見つけることに集約されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース サブセット + ペアリング チェック | O(2^n・n!) | O(n) | 遅すぎる |
 | 二部グラフ + 最大マッチング | O(E √V) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### ステップ 1: パリティによってノードを分離する

 周期が偶数か奇数かに基づいて、セミを 2 つのグループに分けます。 これは任意ではありません。 これは、2 より大きい素数の合計は奇数でなければならないという事実によって強制されます。これは、一方の数が偶数で、もう一方の数が奇数でなければならないことを意味します。

### ステップ 2: 最大 2 × 10^7 の素数を事前計算する

 多くのペアについて pi + pj が素数であるかどうかをテストする必要があります。 値は 10^7 までなので、合計は 2 × 10^7 までになります。 この範囲にわたるエラトステネスのふるいにより、その後の定時間素数チェックが可能になります。 

### ステップ 3: 2 部グラフを構築する

 偶数のインデックスを持つセミと奇数のインデックスを持つセミの合計が素数である場合、それらの間にエッジを作成します。 これらのエッジは、最終セット内の禁止されたペアを表します。 

### ステップ 4: 最大の 2 部マッチングを計算する

 このグラフに対して 2 部マッチング アルゴリズムを実行します。 一致した各エッジは、独立したセットに両方を一緒に保つことができない一対のセミを表します。 

### ステップ 5: 一致を回答に変換する

 最大の安全なサブセットは、正確にすべてのノードから、すべての不良エッジを解消するために削除する必要があるノードを差し引いたものであり、これは n から最大一致のサイズを引いたものに等しくなります。 

### なぜ効果があるのか

 すべてのエッジは、和が素数であるペアに対応するため、両方の端点を保持すると、禁止されたペアが許可されます。 サブセットは、そのようなペアが含まれていない場合、つまり独立したセットである場合に有効です。 2 部グラフでは、ケーニッヒの定理により、最大マッチングの補数により最大独立セット サイズが得られます。 すべての禁止された相互作用はパリティ クラスをまたぐため、グラフは 2 部となり、定理が直接適用されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def sieve(limit):
    is_prime = bytearray(b"\x01") * (limit + 1)
    is_prime[0:2] = b"\x00\x00"
    for i in range(2, int(limit ** 0.5) + 1):
        if is_prime[i]:
            step = i
            start = i * i
            is_prime[start:limit+1:step] = b"\x00" * (((limit - start) // step) + 1)
    return is_prime

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    max_sum = 2 * (10**7)
    is_prime = sieve(max_sum)

    evens = []
    odds = []

    for i, x in enumerate(a):
        if x % 2 == 0:
            evens.append((i, x))
        else:
            odds.append((i, x))

    adj = [[] for _ in range(len(evens))]

    for i, (ei, ev) in enumerate(evens):
        for j, (oi, ov) in enumerate(odds):
            if is_prime[ev + ov]:
                adj[i].append(j)

    match = [-1] * len(odds)

    def dfs(u, vis):
        for v in adj[u]:
            if vis[v]:
                continue
            vis[v] = True
            if match[v] == -1 or dfs(match[v], vis):
                match[v] = u
                return True
        return False

    matching = 0
    for u in range(len(evens)):
        vis = [False] * len(odds)
        if dfs(u, vis):
            matching += 1

    print(n - matching)

if __name__ == "__main__":
    solve()
```この実装では、まず各エッジ チェックが O(1) になるように高速素数テーブルを構築します。 二部構造は、インデックスを偶数グループと奇数グループに分割することによって明示的に構築されます。 隣接リストには偶数側から奇数側へのエッジのみが格納されます。 

マッチングには、標準の DFS ベースの拡張パス アプローチが使用されます。 偶数ノードごとに、空きまたは再ルーティング可能な奇数パートナーの検索を試みます。 訪問された配列は試行ごとにリセットされます。これは、1 回の拡張検索でのサイクルを回避するために重要です。 

最後に、答えは n から成功した一致の数を引いたものとして計算されます。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    from math import isqrt

    def sieve(limit):
        is_prime = bytearray(b"\x01") * (limit + 1)
        is_prime[0:2] = b"\x00\x00"
        for i in range(2, isqrt(limit) + 1):
            if is_prime[i]:
                is_prime[i*i:limit+1:i] = b"\x00" * (((limit - i*i)//i) + 1)
        return is_prime

    n = int(input())
    a = list(map(int, input().split()))

    max_sum = 2 * (10**7)
    is_prime = sieve(max_sum)

    odds = []

    for i, x in enumerate(a):
        if x % 2 == 0:
            evens.append(x)
        else:
            odds.append(x)

    adj = [[] for _ in range(len(evens))]
    for i, ev in enumerate(evens):
        for j, ov in enumerate(odds):
            if is_prime[ev + ov]:
                adj[i].append(j)

    match = [-1] * len(odds)

    def dfs(u, vis):
        for v in adj[u]:
            if vis[v]:
                continue
            vis[v] = True
            if match[v] == -1 or dfs(match[v], vis):

                return True
        return False

    matching = 0
    for u in range(len(evens)):
        vis = [False] * len(odds)
        if dfs(u, vis):
            matching += 1

    return str(n - matching)

 ## 特殊なケース

 すべての値が偶数の場合、1 つのエッジ ケースが発生します。 この状況では、2 の可能性を除いて、2 つの偶数の合計が素数になることはありませんが、すべての値が少なくとも 1 であり、合計はすぐに 2 を超えるため、グラフにはエッジがありません。 このアルゴリズムは空の 2 部グラフを構築します。最大一致は 0 で、答えは n になり、すべてのセミが正しく許可されます。 

もう 1 つの特殊なケースは、値がすべて奇数である場合です。 繰り返しますが、奇数と奇数を加算すると、2 より大きい偶数の和が得られますが、素数になることはできないため、グラフは空になります。 一致はゼロで、すべてのセミが保持されます。これは、禁止されたペアが存在しないため、要件に一致します。 

最後の微妙なケースは、偶数または奇数が 1 つだけ存在する場合です。 マッチングにはその単一ノードのみが関与するため、削除されるペアは最大でも 1 つだけです。 DFS マッチングはこれを自然に処理します。これは、ノードが一度マッチングされると再利用できず、アルゴリズムはすべての拡張可能性を探索した後に終了するためです。
