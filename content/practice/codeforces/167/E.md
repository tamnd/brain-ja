 ## 解決策
 ## 問題の理解

 有向非巡回グラフが与えられます。 一部の頂点はソースであり、エッジがそこに入らないことを意味します。 一部の頂点はシンクになっており、エッジが頂点から離れることはありません。 ソースとシンクの数は等しいことが保証されます。 

有効な構成は、すべてのソースが正確に 1 つのシンクに接続され、すべてのシンクが正確に 1 つのパスを受信するような、頂点が分離された有向パスで構成されます。 パスは頂点が分離されているため、すべての頂点は選択された 1 つのパスに属することができます。 

シンクが頂点番号の増加順に並べられ、ソースも同じように並べられているとします。 沈んだ場合`i`ソースに接続されています`a[i]`、次に順列`a`構成の符号を決定します。 反転数も寄与します`+1`、奇数の反転数が寄与します`-1`。 

タスクは、素数を法として、互いに素なパスの有効なコレクションすべてにわたってこれらの符号を合計することです。`p`。 

これは、一致を列挙するように求めているわけではありません。 すべての完全なソースからシンクへのパス システムにわたる交互の合計を要求します。 

グラフには最大 600 個の頂点と 100,000 個のエッジがあります。 これにより、ソースまたはシンクのサブセットに対する指数関数的なアプローチが即座に排除されます。 平`2^20`すでに大きすぎるでしょうが、ここでは端末の数自体が 600 に近づく可能性があります。 

グラフは非循環的であり、これはソリューション全体が依存する構造特性です。 DAG では、トポロジ順に動的プログラミングを使用してパスのカウントを実行できます。 小さな限界`n`を強く示唆する`O(n^3)`または同様の代数的解決策が意図されています。 

複数のエッジが許可されます。 平行エッジを 1 つのエッジに圧縮する不用意な実装は、パスを過小評価する可能性があります。 例えば：```
2 2
1 2
1 2
```からの 2 つの異なるパスがあります。`1`に`2`、1つではありません。 

頂点は同時にソースとシンクになる場合があります。 例えば：```
1 0
```単一の頂点はソースとシンクの両方になります。 頂点からそれ自体までの空のパスで構成される有効なパス システムが 1 つだけ存在するため、答えは次のようになります。`1`。 

もう 1 つの微妙なケースは、一部のソースが一部のシンクに到達できない場合です。 到達不可能なペアがゼロになることを忘れる単純な決定式の実装では、誤って無効な一致がカウントされる可能性があります。 例：```
4 2
1 3
2 3
```ソースは次のとおりです。`{1,2}`、シンクは`{3,4}`。 シンク`4`に到達できないため、有効なパス システムが存在しません。 答えは`0`。 

最も難しい落とし穴は、そもそも交互の合計が表示される理由を理解することです。 交差しないパス システムのみを直接カウントしようとすると、包含と除外が面倒になってしまいます。 重要な観察は、行列式がすでに順列の兆候をエンコードしており、交差する経路系は自動的にキャンセルされるということです。 

## アプローチ

 ブルートフォースアプローチは概念的には単純です。 各ソースから各シンクまでの可能なすべてのパスを列挙し、パスのすべての組み合わせを試し、それらが頂点に共通点がないかどうかを確認し、誘発された順列を計算して、以下を追加することができます。`+1`または`-1`。 

これが機能するのは、答えの定義が文字通り有効なパス システムの符号付き合計であるためです。 

問題は、DAG 内のパスの数がすでに指数関数的に増加している可能性があることです。`n`。 レイヤーごとに出力の選択肢が 2 つしかない階層化されたグラフでも、ソースからシンクへのパスが指数関数的に多く作成されます。 すべての組み合わせを試すことは完全に不可能になります。 

最初の有益な観察は、符号がソースからシンクへの置換のみに依存するということです。 それはまさに行列式がエンコードする構造です。 

マトリックスを構築するとします`A`どこ：```
A[i][j] = number of paths from source i to sink j
```それから：$\det(A)=\sum_{\pi} \operatorname{sgn}(\pi) \prod_i A_{i,\pi(i)}$各製品は、すべてのソースから割り当てられたシンクへの 1 つのパスの選択に対応します。 

行列式は交差するものも含めてパスのすべてのタプルをカウントするため、一見するとこれは間違っているように見えます。 奇跡はリンドストローム・ゲッセル・ヴィエノの補題です。DAG では、すべての交差するパス タプルが行列式展開でペアごとにキャンセルされます。 

頂点が分離されたパス システムのみが生き残ります。 

したがって、問題全体は次のようになります。 

1. すべてのソースとシンクの間のパス数を計算します。 
2. マトリックスを構築します。 
3. その行列式モジュロを計算します`p`。 

以来`n ≤ 600`、3次ガウス消去法は完全に実現可能です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | 指数 | 遅すぎる |
 | 最適 | O(n^3 + km) | O(n^2) | 承認済み |

 ここ`k`はソースとシンクの数です。 

## アルゴリズムのチュートリアル

 1. グラフを読み取り、入次数と出次数を計算します。 

ソースは、次数 0 の頂点です。 シンクは出次数が 0 の頂点です。 それらの順序付けは、ステートメントで要求されているとおりに、頂点インデックスの増加に従う必要があります。 
2. DAG のトポロジー的順序付けを計算します。 

グラフは非巡回であるため、カーンのアルゴリズムは有効な順序を生成します。 この順序により、パス DP を正しく実行できます。 
3. ソースごとに`s`からパスの数を計算します。`s`あらゆる頂点に。 

初期化:```
dp[s] = 1
```次に、トポロジ順に頂点を処理します。 あらゆるエッジに`u -> v`:```
dp[v] += dp[u]
```モジュロ`p`。 

グラフは非循環であるため、処理する頃には`u`、到達するためのあらゆる方法`u`すでに最終決定されています。 
4. マトリックスを埋める`A`。`A[i][j]`ソースからのパスの数に等しい`i`沈む`j`。 
5. 行列式モジュロを計算します。`p`。 

逆モジュラーでガウス消去法を使用します。 

ピボット行が現在の行と異なる場合は常に、行を交換し、行列式に次の乗算を行います。`-1`。 

以来`p`が素数の場合、非ゼロのピボットごとに逆モジュラが存在します。 
6. 行列式モジュロを出力する`p`。 

### なぜ効果があるのか

 行列式の展開は、ソースからシンクへの割り当てのすべての順列を合計します。 固定順列の場合、積項は、その割り当てを実現するパスのすべてのタプルをカウントします。 

交差するタプルは反対の符号で 2 回出現し、互いに打ち消し合います。 この取り消しは、リンドストローム・ゲッセル・ヴィエノットの補助定理の中核となるステートメントです。 

頂点に共通でないパス システムのみが残り、それぞれが順列の符号によって重み付けされます。 それはまさに、この問題で計算が求められている量です。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def modinv(a, p):
    return pow(a, p - 2, p)

def determinant(mat, p):
    n = len(mat)
    det = 1

    for col in range(n):
        pivot = -1

        for row in range(col, n):
            if mat[row][col] % p != 0:
                pivot = row
                break

        if pivot == -1:
            return 0

        if pivot != col:
            mat[pivot], mat[col] = mat[col], mat[pivot]
            det = (-det) % p

        pivot_val = mat[col][col] % p
        det = (det * pivot_val) % p

        inv_pivot = modinv(pivot_val, p)

        for row in range(col + 1, n):
            if mat[row][col] == 0:
                continue

            factor = mat[row][col] * inv_pivot % p

            for k in range(col, n):
                mat[row][k] = (mat[row][k] - factor * mat[col][k]) % p

    return det % p

def solve():
    n, m, p = map(int, input().split())

    g = [[] for _ in range(n)]
    indeg = [0] * n
    outdeg = [0] * n

    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1

        g[u].append(v)
        indeg[v] += 1
        outdeg[u] += 1

    sources = [i for i in range(n) if indeg[i] == 0]
    sinks = [i for i in range(n) if outdeg[i] == 0]

    k = len(sources)

    q = deque()

    cur_indeg = indeg[:]

    for i in range(n):
        if cur_indeg[i] == 0:
            q.append(i)

    topo = []

    while q:
        u = q.popleft()
        topo.append(u)

        for v in g[u]:
            cur_indeg[v] -= 1
            if cur_indeg[v] == 0:
                q.append(v)

    mat = [[0] * k for _ in range(k)]

    for i, s in enumerate(sources):
        dp = [0] * n
        dp[s] = 1

        for u in topo:
            if dp[u] == 0:
                continue

            val = dp[u]

            for v in g[u]:
                dp[v] += val
                if dp[v] >= p:
                    dp[v] %= p

        for j, t in enumerate(sinks):
            mat[i][j] = dp[t] % p

    ans = determinant(mat, p)
    print(ans % p)

solve()
```最初のセクションでは DAG を構築し、頂点の昇順でソースとシンクを正確に識別します。 このステートメントではこのように暗黙的に番号付けが定義されているため、別の方法で並べ替えると符号規則が変更され、間違った答えが生成される可能性があります。 

トポロジカルソートは標準のカーン処理です。 元の値は後でソースを識別するために必要になるため、indegree 配列をコピーします。 

ソースごとに、DAG 上でパスカウント DP を実行します。 以来`n`はわずか 600 なので、ソースごとに 1 つの DP を実行するのは十分に安価です。 伝播中に各エッジが個別に寄与するため、複数のエッジが自然に処理されます。 

行列式の実装では、モジュラー ガウス消去法を使用します。 よくある間違いは、行の交換によって決定要因の符号が変わることを忘れていることです。 もう 1 つのよくあるバグは、逆モジュラーで乗算する代わりに通常の除算を行うことです。 

マトリックスは削除中に適切に変更されます。 元の値は後で必要になることはないので、これは問題ありません。

## 特殊なケース

 孤立した頂点の場合を考えてみましょう。```
1 0 13
```単一の頂点には入次数 0 と出力次数 0 があるため、ソースとシンクの両方になります。 

パス行列は次のとおりです。 

| | v1 |
 | --- | --- |
 | v1 | 1 |

 頂点からそれ自体への空のパスは、DAG パスのカウントで有効です。 決定要因は`1`したがって、アルゴリズムは次のように出力します。`1`。 

ここで、到達不能なシンクについて考えてみましょう。```
4 2 17
1 3
2 3
```ソースは次のとおりです。`[1,2]`、シンクは`[3,4]`。 

シンクに到達する経路がない`4`したがって、行列は次のようになります。 

| | 3 | 4 |
 | --- | --- | --- |
 | 1 | 1 | 0 |
 | 2 | 1 | 0 |

 その行列式はゼロです。 消去中、2 番目のピボット列にはゼロ以外のピボットがないため、アルゴリズムはすぐに戻ります。`0`。 

最後に、平行エッジを考慮します。```
2 2 97
1 2
1 2
```からの異なる有向パスが正確に 2 つあります。`1`に`2`、各エッジに 1 つずつ。 

DP は両方のエッジを独立して処理します。```
dp[2] += dp[1]
dp[2] += dp[1]
```与える`dp[2] = 2`。 

の決定要因は、`1 × 1`マトリックス`[2]`は`2`、これが正解です。
