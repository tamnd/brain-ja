 ## 解決策
 ## 問題の理解

 各トロリーバスは決まった出発時刻に車庫から出発します。 それはスピードから始まります`0`、最大で加速できます`a`、独自の速度制限を超えることはできません`v[i]`。 目的地は`d`数メートル離れています。 ブレーキは無制限なので、トロリーバスは必要に応じていつでも速度を下げることができます。 

トロリーバスなら`i`トロリーバスを捕まえます`i-1`、追い越しは不可能です。 その瞬間から、二人は一緒にトロリーバスで移動します`i`トロリーバスより早く到着することはできません`i-1`。 

すべてのトロリーバスについて、加速制限、速度制限、追い越し禁止規則を尊重しながら、最終駅に可能な限り早く到着する時刻を計算する必要があります。 

制約によって、意図する複雑さが完全に決まります。 まであります`10^5`したがって、動きを継続的にシミュレートしたり、トロリーバスのすべてのペアを比較したりするソリューションは遅すぎます。 アン`O(n^2)`解決策には大まかに必要になります`10^10`限界をはるかに超えた最悪の場合の動作。 線形または線形に近いアプローチが必要です。 

物理的な部分も重要です。 トロリーバスは常に最高速度で巡航することに時間を費やすわけではありません。 時には距離が近すぎて届かないこともある`v[i]`。 すべてのトロリーバスが加速することを前提とした不注意な実装`v[i]`最初は不正確な時間を生成します。 

次の入力を考えてみましょう。```
1 10 5
0 100
```トロリーバスは移動するだけで済みます`5`メートル。 到達速度`100`その距離では無理です。 正しい動きは純粋な加速です。```
distance = 1/2 * a * t^2
5 = 5 * t^2
t = 1
```したがって、答えは次のとおりです。```
1.0000000000
```もう 1 つの簡単な間違いは、後のトロリーバスは前のトロリーバスより早く到着できないことを忘れていることです。 

例：```
2 1 10
0 1
1 100
```最初のトロリーバスには次のものが必要です。```
10 seconds
```線路が空いていれば 2 台目のトロリーバスが物理的に早く到着する可能性がありますが、追い越しは禁止されています。 正しい答えは次のとおりです。```
10.0000000000
10.0000000000
```各トロリーを個別に計算する単純な実装では、次のような結果が誤って出力されてしまいます。`5.47`2台目のトロリーバスへ。 

3 番目の微妙なケースは、トロリーバスが目的地で別のトロリーバスを捕まえたときに発生します。 それでも同時に到着したものとしてカウントされます。 

例：```
2 1 1
0 1
1 100
```始発のトロリーバスが定刻に到着`1.5`。 2台目のトロリーバスもちょうど次の時間に駅に到着します。`1.5`。 正しい出力は次のとおりです。```
1.5000000000
1.5000000000
```比較ロジックで厳密な不等式を使用すると、この境界で失敗する可能性があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 各トロリーバスについて、物理的制約から無制限の最早到着時間を計算します。 次に、それを以前のすべてのトロリーバスと比較して、目的地までにいずれかのトロリーバスを捕まえられるかどうかを判断します。 

トロリーバスは順番に移動し、追い越しできないため、これが機能します。 トロリーバスなら`i`トロリーバスより早く到着します`j`、その後、ある時点で追いつく必要があります。 

問題は規模だ。 すべてのペア間の相互作用を確認するには、次のことが必要です`O(n^2)`比較。 と`10^5`トロリーバスは絶望的に遅くなります。 

重要な観察点は、追い上げが発生する場所を実際にシミュレートする必要がないということです。 

トロリーバスを想定してみよう`i`独立して時間通りに到着できる`T[i]`。 もし`T[i]`前のトロリーバスの実際の到着時間より小さい場合、トロリーバス`i`最終的には目的地に到着する前に捕まえる必要があります。 追い越し不可なのでトロリーバス`i`まったく同じ時間に到着する必要があります。 

つまり、実際の到着時間は次のようになります。```
answer[i] = max(answer[i-1], independent_time[i])
```すべては、1 台のトロリーバスの物理的に可能な最も早い到着時刻を計算することに帰着します。 

動作パターンは2種類のみ。 

トロリーバスが目的地に到着する前に最高速度に達した場合、次のようになります。 

1.から加速する`0`に`v`。 
2. 一定速度で継続します。 

目的地が近すぎる場合は、ずっと加速するだけです。 

遷移点は加速距離の式から求められます。```
v^2 = 2ad
```もし`v^2 <= 2ad`、トロリーバスは目的地手前で最高速度に達します。 

そうでなければ決して届かない`v`。 

これにより、完全な結果が得られます`O(n)`解決。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む`n`、`a`、 そして`d`。 
2. 各トロリーバスについて、線路が空いていると仮定して、可能な限り最速の到着時間を計算します。 
3. トロリーバスが走行距離の前に制限速度に達できるかどうかを判断する`d`。 

から加速するのに必要な距離`0`に`v`は：$s = \frac{v^2}{2a}$この値が最大でも`d`、その後トロリーバスは全速力に達します。 
4. トロリーバスが全速力に達した場合:

 1. 加速時間を計算します。$t = \frac{v}{a}$2. 加速距離を計算します。$s = \frac{v^2}{2a}$3. 残りの距離を一定速度で走行します。 
4. 出発時刻を追加する`t[i]`。 
5. それ以外の場合、トロリーバスは走行中ずっと加速します。 

使用：$d = \frac{1}{2}at^2$これは次のようになります:$t = \sqrt{\frac{2d}{a}}$6. この計算値を次のようにします。`independent`。 
7. 実際の到着時刻は、前のトロリーバスの到着時刻より早くなることはできません。 

セット：```
answer[i] = max(answer[i-1], independent)
```8. すべての回答を出力します。 

### なぜ効果があるのか

 The invariant is simple: after processing trolleybus`i`、`answer[i]`すべての追い越し禁止の制約を尊重しながら、物理的に達成可能な最も早い到着時間に相当します。 

各トロリーバスは常に可能な限り積極的に加速し、強制されない限り決して減速しないため、独立したモーション計算が最適です。 

もし`independent[i] >= answer[i-1]`、その後トロリーバス`i`前のトロリーバスに追いつくことがないため、最適なスケジュールを維持できます。 

もし`independent[i] < answer[i-1]`、その後トロリーバス`i`トロリーバスより早く目的地に到着するだろう`i-1`。 追い越しは不可能であるため、目的地よりも前、または目的地の正確なところで追いつきを行う必要があります。 その瞬間から彼らはトロリーバスを強制的に一緒に移動します`i`に到着する`answer[i-1]`。 

したがって、実行最大値を取得すると、物理的な制限が正確にモデル化されます。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

def solve():
    n, a, d = map(int, input().split())

    ans = []

    for _ in range(n):
        t, v = map(int, input().split())

        accel_dist = v * v / (2.0 * a)

        if accel_dist >= d:
            travel_time = math.sqrt(2.0 * d / a)
        else:
            accel_time = v / a
            remaining = d - accel_dist
            travel_time = accel_time + remaining / v

        arrival = t + travel_time

        if ans:
            arrival = max(arrival, ans[-1])

        ans.append(arrival)

    print("\n".join(f"{x:.10f}" for x in ans))

solve()
```最初の部分では、1 台のトロリーバスの無制限の最適な移動時間を計算します。 

表現:```
accel_dist = v * v / (2.0 * a)
```から加速するのに必要な距離を表します`0`に`v`。 

この距離が次の値以上の場合`d`, その場合、トロリーバスは目的地までに最高速度に達することはありません。 移動全体が加速運動であるため、次のように解きます。```
d = 1/2 * a * t^2
```平方根の公式を使用します。 

それ以外の場合、トロリーバスは最初に加速して、`v`、その後は一定の速度で移動します。 移動時間は次のようになります。```
time_to_accelerate + time_at_constant_speed
```最も重要な実装の詳細は、最後の行です。```
arrival = max(arrival, ans[-1])
```これがないと、後のトロリーバスが出力内で前のトロリーバスを違法に追い越してしまう可能性があります。 

もう 1 つの微妙な点は、随所で浮動小数点演算を使用していることです。 式には平方根と除算が含まれるため、整数演算では値が切り捨てられ、精度が損なわれます。 

条件:```
if accel_dist >= d:
```平等を含める必要があります。 トロリーバスが目的地で正確に最高速度に達した場合、巡航フェーズは存在しません。

 ## 特殊なケース

 ### トロリーバスは最高速度に達しない

 入力:```
1 10 5
0 100
```速度に達するために必要な加速距離`100`は：```
100^2 / (2 * 10) = 500
```でも目的地はただ`5`数メートル離れています。 

アルゴリズムは平方根分岐に入ります。```
t = sqrt(2 * 5 / 10) = 1
```出力：```
1.0000000000
```常に加速するバグのある実装`v`最初に行うと、大きく間違った答えが生成されます。 

### 速いトロリーバスは遅れて出発します

 入力:```
2 1 10
0 1
1 100
```2台目のトロリーバスが自主的に到着します。`5.47`が、最初のトロリーバスが到着します。`10.5`。 

アルゴリズムは以下を計算します。```
answer[1] = max(5.47, 10.5) = 10.5
```これにより、キャッチアップ イベントが正しくモデル化されます。 

### 目的地で正確にキャッチ

 入力:```
2 1 1
0 1
1 100
```最初のトロリーバスが到着します`1.5`。 

2台目のトロリーバスも単独で目的地に到着します。`1.5`。 

アルゴリズムは以下を維持します。```
answer[1] = max(1.5, 1.5) = 1.5
```代わりに厳密な不等式を使用する`max`浮動小数点比較により、ロジックが誤って答えを分離する可能性があります。
