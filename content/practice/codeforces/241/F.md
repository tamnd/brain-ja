 ## 解決策
 ## 問題の理解

 都市はグリッドで表されます。 すべてのセルは建物、または道路タイルのいずれかであり、そこからの移動コストがかかります。`1`に`9`、または小文字でラベル付けされたジャンクション。 

移動ルールが珍しい。 移動できるのは、エッジを共有する隣接するセル間のみですが、次のとおりです。 

- 道路タイルから隣接する別の道路タイルに移動すると、移動先の道路タイルに書かれた値がかかります。 
- 交差点と隣接する道路タイルの間の移動には正確な料金がかかります`1`、
 - 建物が封鎖されています。 

車は道路タイルから出発し、指定された順序で一連の交差点を通過し、最後に別の道路タイルで停止する必要があります。 これらのチェックポイントを満たすすべてのパスの中で、常にグローバルに最短のパスが選択されます。 目的地に到着すると、そこに永遠に留まります。 

正確に位置を決定する必要があります`k`分。 

まず気づくのはマップの広さです。 グリッドは最大でも`100 × 100`, したがって、最大でも`10^4`細胞。 これは、多くのソースからのダイクストラのようなグラフ アルゴリズムにとっては十分な小ささです。 結合シーケンスの長さは最大で`1000`したがって、高価な最短パスを毎分再計算するのは無駄ですが、セグメントごとに再計算することは完全に実行可能です。 

厄介な点は、ステートメントが最短距離を求めていないことです。 その後、正確な位置を尋ねます`k`1 つの最適なルートに沿って数分。 つまり、距離だけでなく実際の動きを再構築する必要があるということです。 

もう 1 つの微妙な点は、最短パスが一意であるとは限らないことです。 任意の最短パスを再構築する不用意な実装は、タイブレークが矛盾している場合に審査員の同意を得ない可能性があります。 意図された解決策は、都市の特殊な構造を利用することでこれを回避します。 

この都市には非常に強力な幾何学的制限があります。 

- 道路はまっすぐです、
 - 2 つのジャンクションが隣接していない、
 - 道路が横に接していない。 

これは、道路ネットワークが本質的に、ジャンクションを介して接続された独立したコリドーの集合体であることを意味します。 2 つの隣接するジャンクション間では、移動は強制的に直線になります。 道路内では、真の経路選択は決してありません。 

以下は、一般的な最短パスの再構築が誤って失敗する可能性がある小さな例です。 

入力：```
3 7 3
#######
#a111b#
#######
2 3 ab 2 5
```唯一の有効なルートは次のとおりです。```
(2,3) -> a -> ... -> b -> (2,5)
```実装がすべてのエッジを均一に扱い、不用意に先行エッジを再構築すると、必要な接合順序が誤ってスキップされる可能性があります。 

別の簡単な間違いが現れるのは、`k`合計移動時間を超えます。 

入力：```
3 5 20
#####
#a1b#
#####
2 3 ab 2 3
```数分前に目的地に到着する`20`。 正しい出力は次のとおりです。```
2 3
```車は永遠にそこに残るからです。 

もう 1 つの微妙な問題は、移動のタイミングです。 通りのタイルを入力すると、元のタイルではなく、そのタイルに書かれた数字がかかります。 ジャンクションに入るには常に料金がかかります`1`。 ここでのオフバイワンのミスで軌道は完全に変わってしまう。 

## アプローチ

 最も直接的な解決策は、グリッド全体を重み付きグラフとしてモデル化することです。 通過可能なすべてのセルがノードになり、エッジは適切な移動コストで隣接する有効なセルを接続します。 その後、ダイクストラを繰り返し実行できます。 

- スタートから最初のジャンクションまで、
 - あるジャンクションから次のジャンクションまで、
 - 最後の交差点から目的地まで。 

すべての最短経路を再構築した後、それらを連結し、時間まで分ごとに動きをシミュレートします。`k`。 

ダイクストラは任意の正のエッジの重みを処理するため、これは正しいです。 グラフには最大でも`10^4`頂点と大まかに`4 × 10^4`エッジがあるため、1 回の Dijkstra 実行はすでに手頃な価格です。 

問題は、パス再構築の曖昧さです。 一般的な重み付きグラフには複数の最短経路が存在する場合があります。 このステートメントは、一連のジャンクションが有効なルートを形成することを保証しますが、タイブレーク ルールは提供しません。 任意の最短パスを再構築すると、不整合が生じる可能性があります。 

重要な観察は、この都市が任意のグラフではないということです。 通りは孤立した廊下です。 どの 2 つのエンドポイントに接続しているかがわかったら、ルートが強制されます。 

私たちが交差点に立っているとします。 隣接する道路タイルはすべて、正確に 1 つの道路コリドーに属します。 その廊下を進むことは、次の理由により決定的です。 

- 道路タイルが横に分岐することはありません。 
- 2つの通りが互いに接触することはありません。 
- ジャンクションは廊下を分離します。 

したがって、最短経路アルゴリズムを実行する代わりに、文字通りチェックポイント間の固有の通路に沿って歩くことができます。 

完全なルートは決定的になります。 

- 開始通り→最初の交差点、
 - ジャンクション→ジャンクション、
 - 最後のジャンクション→目的地。 

各セグメントについて、前のタイルではない唯一の有効な次のタイルに繰り返し移動します。 途中で到着時間を記録します。 累積時間が一定以上になると`k`、現在位置がわかります。 

これにより、問題は疎な決定論的構造上の純粋なシミュレーションに変わります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | グラフ上の総当たりダイクストラ | O(L × mn log(mn)) | O(mn) | 受け入れられましたが、不必要に重い |
 | コリドーシミュレーション | O(経路の合計長) | お(1) | 承認済み |

 ここ`L`はルートセグメントの数で、最大でも約`1000`。 

## アルゴリズムのチュートリアル

 1. グリッドを読み取り、すべてのジャンクション文字の座標を保存します。 
2. 順序付けされたチェックポイント リストを作成します。 

- ストリートセルを開始し、
 - 文字列からの各ジャンクション、
 - 目的地の街路セル。 
3. チェックポイントの連続するすべてのペアを個別に処理します。 
4. 1 つのセグメントについて、最初の手を決定します。 

現在のセルが道路タイルの場合、ターゲット交差点に向かって移動する隣接する通過可能なセルは 1 つだけです。 

現在のセルがジャンクションの場合、次のチェックポイントにつながる隣接する道路コリドーは 1 つだけです。 
5. 廊下を一歩ずつ歩きます。 

すべてのステップで:

 - 前の位置とは異なる隣接する移動可能なセルを選択します。 
- 移動コストを計算します。 
- 経過時間に加算します。 
- 現在の位置を更新します。 
6. 移動するたびに、経過時間が経過したかどうかを確認します`k`。 

「はい」の場合、車は現在、新しく入力されたセル上に立っています。そのため、その位置をすぐに出力します。 
7. すべてのセグメントが完了するまで続行します。 
8. 総移動時間がまだ短い場合`k`、車はそこに永遠に留まるため、目的地の位置を出力します。 

### なぜ効果があるのか

 都市の制約により、すべての街路が単純なチェーンのように動作することが強制されます。 内側の道路タイルには、前のタイルと次のタイルの 2 つの通過可能な隣接タイルが存在します。 コリドーの終点では、継続はジャンクション構造によって一意に決定されます。 

このため、チェックポイントの順序が決まると、実際の最短ルートも決まります。 すべての移動コストはプラスであるため、迂回するとタイルを不必要に再訪問し、総コストが増加します。 

アルゴリズムは常にこの固有のコリドーに沿って進むため、シミュレートされたすべての動きは最短の有効なルートに属します。 正確な移動コストを時系列で累積していきますので、到着時間が最初に到達した地点が`k`正確には後の位置です`k`分。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

DIRS = [(-1, 0), (1, 0), (0, -1), (0, 1)]

def solve():
    m, n, k = map(int, input().split())

    grid = [list(input().strip()) for _ in range(m)]

    junctions = {}

    for i in range(m):
        for j in range(n):
            ch = grid[i][j]
            if 'a' <= ch <= 'z':
                junctions[ch] = (i, j)

    rs, cs, s, re, ce = input().split()

    rs = int(rs) - 1
    cs = int(cs) - 1
    re = int(re) - 1
    ce = int(ce) - 1

    checkpoints = [(rs, cs)]

    for ch in s:
        checkpoints.append(junctions[ch])

    checkpoints.append((re, ce))

    elapsed = 0
    current = checkpoints[0]

    def traversable(r, c):
        return (
            0 <= r < m and
            0 <= c < n and
            grid[r][c] != '#'
        )

    for idx in range(len(checkpoints) - 1):
        start = checkpoints[idx]
        target = checkpoints[idx + 1]

        prev = None
        cur = start

        while cur != target:
            r, c = cur

            nxt = None

            for dr, dc in DIRS:
                nr = r + dr
                nc = c + dc

                if not traversable(nr, nc):
                    continue

                if prev is not None and (nr, nc) == prev:
                    continue

                nxt = (nr, nc)
                break

            nr, nc = nxt

            cell = grid[nr][nc]

            if '1' <= cell <= '9':
                cost = int(cell)
            else:
                cost = 1

            elapsed += cost

            cur = nxt
            prev = (r, c)

            if elapsed >= k:
                print(nr + 1, nc + 1)
                return

    print(re + 1, ce + 1)

if __name__ == "__main__":
    solve()
```この実装はコリドー シミュレーションを直接反映しています。 

の`checkpoints`配列には完全な必須ルート構造が含まれています。 連続する要素は常に固有の廊下で接続されます。 

最もデリケートな部分は近隣の選択です。 私たちはBFSやダイクストラを決して実行しません。 代わりに、現在のすべてのセルから、前のセルとは異なる唯一の通過可能な隣接セルを選択します。 都市の制約により、ルートが一意に決定されることが保証されます。 

もう 1 つの微妙な詳細は、移動コストの規則です。 コストは入力されたセルによって異なります。 

- 数字タイルを入力すると、その数字が消費されます。 
- ジャンクションコストの入力`1`。 

このコードは、次のセルを選択する前ではなく、選択した後にコストを計算します。 

の`elapsed >= k`チェックは新しいタイルに入った直後に行われます。 これは、必要な移動時間を費やした後、車は目的地タイルに到着し、次の移動までそこに留まります。という記述と正確に一致します。 

最後に、全ルートが時間内に終了した場合`k`、車は二度と動かないので、最終目的地を出力します。
