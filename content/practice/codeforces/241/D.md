 ## 解決策
 ## 問題の理解

 一連の個別の整数が与えられます。 元の順序を維持して後続のシーケンスを保持し、残りを削除する場合があります。 

残りのシーケンスは 2 つの条件を同時に満たさなければなりません。 

まず、残りのすべての数値の xor がゼロでなければなりません。 

第二に、残りの数値の 10 進表現を 1 つの巨大な 10 進数に連結する場合、その数値は素数で割り切れなければなりません。`p`。 

辞書編集上の最小の答えや最短の部分列は必要ありません。 空でない有効なサブシーケンスはどれでも受け入れられます。 

制約によってソリューションが完全に形作られます。 両方`n`そして`p`せいぜい`50000`。 すべてのサブシーケンスに対するブルート フォースではチェックが必要になります。`2^n`不可能になる可能性`n = 40`。 線形または二次に近いものが必要です。`p`、 なぜなら`50000^2`Python ではすでに大きすぎます。 

シーケンス要素は個別であり、すべての値はそれらの間にあります。`1`そして`n`。 この制限は、すべての数値の xor の合計が有限であり、代数的に操作できるほど小さいことを意味するため、非常に便利です。 

連結は順序に依存するため、割り算の条件は微妙です。 数字を付けると`x`と`d`数字をプレフィックス値に変換する`v`、新しい剰余モジュロ`p`になる$$(v \cdot 10^d + x) \bmod p$$したがって、問題は有限オートマトンの遷移のように動作します。 

最も難しいのは、無関係な 2 つの条件を同時に満たさなければならないことです。 xor を使用したサブセット`0`多くの場合、簡単に構築できます。 連結が次で割り切れるサブセット`p`動的プログラミングでも管理可能です。 課題は、状態空間を爆発させずに両方を結合することです。 

素朴な考えを打ち破るようなエッジケースがいくつかあります。 

xor を使用してサブセットのみを検索するとします。`0`。 

入力：```
3 5
1 2 3
```配列全体に xor があります`0`、 なぜなら`1 xor 2 xor 3 = 0`。 しかし、連結すると`123`、 そして`123 mod 5 = 3`, したがって、これは無効です。 

ここで、可分性のみを検索するとします。 

入力：```
3 3
1 2 3
```連結`123`で割り切れます`3`、しかし、まだ xor が必要です`0`。 ここではセット全体が機能します。`1 xor 2 xor 3 = 0`しかし、多くの割り切れる部分列は xor 条件に失敗します。 

もう 1 つの注意が必要なケースは、解決策が存在しない場合です。 

入力：```
1 2
1
```唯一の空ではないサブシーケンスは、`[1]`。 そのxorは`1`、 ない`0`、したがって、正しい答えは次のとおりです。`"No"`。 

不用意に実装すると、順序は変更できないということを忘れてしまう可能性があります。 選択した値が`{12, 3}`、連結された数値は次のようになります。`"123"`場合のみ`12`前に現れます`3`オリジナルの順序で。 セットではなくサブシーケンスを選択しています。 

## アプローチ

 強引なアイデアは単純明快です。 空ではないすべてのサブシーケンスを列挙し、その xor を計算し、連結された剰余モジュロを計算します。`p`。 両方の条件が満たされる場合、サブシーケンスを出力します。 

XOR 計算は安価です。 数値を段階的に処理する場合、モジュロ計算も安価になります。 問題は部分列の数です。 がある`2^n - 1`空ではない選択肢。 たとえ`n = 50`、これはすでに実現可能性をはるかに超えています。 

次の観察は、連結モジュロです。`p`決定論的な移行システムのように動作します。 現在の残りが`r`そして値を追加します`x`、新しい余りは次のようになります$$(r \cdot 10^{len(x)} + x) \bmod p$$これは、剰余に対する動的計画法を示唆しています。 

残念ながら、xor も追跡する必要があるため、剰余のみを追跡するだけでは十分ではありません。 直接の DP オーバー`(remainder, xor)`各州は約`50000 × 65536`あまりにも大きすぎる州。 

重要な洞察は数値の xor 構造に隠されています`1..n`。 

個別の整数の場合、すべての要素の XOR を調べると、XOR 条件がはるかに簡単になります。 させて$$X = a_1 \oplus a_2 \oplus \cdots \oplus a_n$$もし`X = 0`の場合、シーケンス全体を保持することですでに xor 条件が満たされるため、割り算を修正するだけで済みます。 

もし`X ≠ 0`に等しい値を 1 つだけ削除します。`X`残りの xor はゼロに等しくなります。$$X \oplus X = 0$$すべての価値は個別であり、そこに存在するため、`1..n`、値`X`配列内で一意に存在するか、まったく存在しません。 

これにより、検索スペースが劇的に崩壊します。 意味のある xor 有効な候補は最大 2 つあります。 

1. total xor がゼロの場合は、すべてを保持します。 
2. total xor に等しい一意の要素を削除します。 

ここで、問題は、どちらかの候補が次で割り切れる連結を与えるかどうかをチェックすることに帰着します。`p`。 

連結剰余は線形時間で計算できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n \cdot n) | O(n) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. シーケンスを読み取り、すべての要素の XOR を計算します。 
2. 事前計算能力`10`モジュロ`p`桁の長さまで`5`、すべての数値は最大でも`50000`。 
3. 剰余モジュロを計算します`p`シーケンス全体の連結。 

現在の残りが`r`そして次の値は`x`と`d`数字、更新:$$r = (r \cdot 10^d + x) \bmod p$$4. 合計 xor がゼロで、連結剰余もゼロの場合、シーケンス全体を出力します。 
5. それ以外の場合、合計 xor を次のようにします。`X`。 

値が次と等しい要素を検索します`X`。 

そのような要素が存在しない場合、サブシーケンスは xor ゼロを持つことができません。 出力`"No"`。 
6. 概念的にその 1 つの要素を削除し、残りのシーケンスの連結の残りを再計算します。 

他のすべての要素の順序は変更されません。 
7. 結果の連結余りが 0 の場合、削除されたインデックスを除くすべてのインデックスを出力します。 
8. それ以外の場合は出力`"No"`。 

### なぜ効果があるのか

 任意のサブセットに対して`S`、 させて`T`元の配列内のすべての数値の xor になります。 

削除された数値の xor が次と等しい場合、残りの数値の xor は正確に 0 に等しくなります。`T`、 なぜなら$$(\text{xor of kept}) \oplus (\text{xor of removed}) = T$$複数の数値を削除した場合でも、それらの xor は等しくなければなりません`T`。 しかし、すべての値は個別であり、次によって制限されるため、`1..n`、唯一保証されている単純な構造は、単一の数値を削除することです。`T`自体。 

もし`T = 0`、何も削除しないと、すでに xor 条件が満たされます。 

もし`T ≠ 0`そしてその値`T`がシーケンス内に存在する場合、それを削除すると xor ゼロが残ります。$$T \oplus T = 0$$他の単一の除去は機能しません。 

したがって、xor が有効な候補は最大でも 2 つあり、両方の割り算をチェックすれば十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def digits(x):
    return len(str(x))

def concat_mod(arr, p):
    r = 0
    for x in arr:
        d = digits(x)
        r = (r * pow(10, d, p) + x) % p
    return r

def solve():
    n, p = map(int, input().split())
    a = list(map(int, input().split()))

    total_xor = 0
    for x in a:
        total_xor ^= x

    full_mod = concat_mod(a, p)

    if total_xor == 0 and full_mod == 0:
        print("Yes")
        print(n)
        print(*range(1, n + 1))
        return

    remove_idx = -1

    for i, x in enumerate(a):
        if x == total_xor:
            remove_idx = i
            break

    if remove_idx == -1:
        print("No")
        return

    b = []
    ans_idx = []

    for i, x in enumerate(a):
        if i == remove_idx:
            continue
        b.append(x)
        ans_idx.append(i + 1)

    if not b:
        print("No")
        return

    if concat_mod(b, p) == 0:
        print("Yes")
        print(len(ans_idx))
        print(*ans_idx)
    else:
        print("No")

if __name__ == "__main__":
    solve()
```このソリューションには 2 つの独立した部分があります。 

最初の部分は XOR 条件を処理します。 すべての数値の xor を 1 回計算します。 すでにゼロである場合、すべてを維持することが唯一の自然な候補です。 それ以外の場合は、その xor 値に等しい一意の要素を削除しようとします。 

2 番目の部分では、割り算を次のように評価します。`p`。 巨大な連結 10 進数を明示的に構築する代わりに、その剰余モジュロのみを維持します。`p`。 

現在の連結数に余りがあると仮定します。`r`、そして数字を追加します`x`と`d`数字。 追加中`x`古い数値を左にシフトします`d`小数点以下の桁数を乗算します。`10^d`。 次に追加します`x`。 

それは次のようになります:$$r' = (r \cdot 10^d + x) \bmod p$$この増分式はオーバーフローを回避し、すべての操作を一定時間を保ちます。 

微妙な点の 1 つは、順序を維持することです。 要素を削除するだけであり、並べ替えることはありません。 コードは残りのシーケンスを元の順序で自動的に構築します。 

もう 1 つの微妙な点は、空のサブシーケンスです。 xor 要素を削除しても数値が残らない場合、残りのシーケンスは空ではない必要があるため、答えは無効になります。
