 ## 解決策
 ## 問題の理解

 都市と片道のフライトの有向非循環グラフが与えられます。 どのフライトも最初は 1 時間かかります。 当社は独自にフライト時間を 1 時間または 2 時間に変更する場合があります。 

目標は、都市 1 から都市 n までの考えられるすべての経路の合計移動時間がまったく同じになるように、所要時間を割り当てることです。 

すべてのエッジが番号の小さい都市から番号の大きい都市に向かうため、グラフは非周期的です。 この特性こそが、問題が対処可能である理由のすべてです。 これがなければ、サイクルによって無限に多くのパスが作成される可能性があるため、一般的なグラフ内のすべてのパスの長さを等しくすることは非常に困難になります。 

入力では最大 1000 個の頂点と 5000 個のエッジが与えられます。 すべてのエッジにわたるブルートフォース割り当てでは、以下までのチェックが必要になります。$2^m$可能性。 と$m = 5000$、それはまったく不可能です。 

グラフのサイズは、何か必要があることを示唆しています$O(nm)$または$O(m \log n)$。 グラフは DAG であるため、トポロジカルな順序での動的計画法が自然な方向になります。 

難しいのは、単に 1 つの最短パスまたは最長パスを見つけるだけではないということです。 1 から n までのすべてのパスを等しくする必要があります。 つまり、割り当てられたエッジの重みは、DAG 全体にわたる一貫性制約のシステムを満たす必要があります。 

単純な実装は、グラフの切断された領域で失敗することがよくあります。 例えば：```
4 3
1 2
2 4
3 4
```都市 3 は、都市 1 から到達できないため無関係です。これに関連する制約は重要ではありません。 すべてのノードを盲目的に処理すると、システムに一貫性がないと誤って判断してしまう可能性があります。 

もう 1 つの微妙なケースは、ノードに矛盾する値を強制する 2 つの発信パスがある場合です。 

例：```
4 4
1 2
1 3
2 4
3 4
```以下を代入できるため、これは解決可能です。```
1->2 = 1
1->3 = 1
2->4 = 2
3->4 = 2
```どちらのパスも全長は 3 です。 

しかし、次のように考えてください。```
5 5
1 2
1 3
2 5
3 4
4 5
```構造的に1エッジごとに経路長が異なります。 すべてのエッジの重みは 1 または 2 であるため、最初のパスは合計 2、3、または 4 のみを持つことができ、2 番目のパスは合計が 3、4、5、または 6 のみを持つことができます。それらの重複が存在するため、このグラフはまだ解くことができます。 

強制されない限り重みを常に 1 に保つ不注意で貪欲な戦略は、必要な調整を検出できません。 

実際に不可能なケースは、制約によって一部のエッジに重み 0 または 3 が必要になる場合に発生します。 

例:```
4 4
1 2
2 4
1 3
3 4
```次のことを強制しようとするとします。 

- ノード 2 を通る 1 から 4 までの距離は 2 に等しくなります。 
- ノード 3 を通る距離は 4 に等しい

 その場合、一部のエッジには 2 より大きい重みが必要になります。有効な範囲の制限が、実際の不可能性の原因です。 

## アプローチ

 ブルートフォースのアイデアは単純です。 すべてのエッジは独立して重み 1 または 2 を受け取ることができるため、すべてを試すことができます$2^m$課題。 割り当てごとに、1 から n までのすべてのパス長を計算し、それらが同一であるかどうかを確認します。 

文字通りすべての可能な構成をテストするため、正確性はすぐにわかります。 問題はスケールです。 わずか 50 エッジでも、$2^{50}$すでに天文学的です。 ここには 5000 個のエッジがある可能性があります。 

重要な観察は、「すべてのパスの全長が等しい」がポテンシャル関数のように動作するということです。 

すべてのノードがあるとします$v$価値がある$dp[v]$、からの一般的な残りの距離を意味します。$v$に$n$。 次に、すべてのエッジについて$u \to v$、$$w(u,v) + dp[v] = dp[u]$$並べ替えると次のようになります。$$w(u,v) = dp[u] - dp[v]$$すべてのエッジの重みは 1 または 2 でなければならないため、$$dp[u] - dp[v] \in \{1,2\}$$これで、問題ははるかにすっきりしました。 到達可能なエッジごとにラベルが正確に 1 または 2 だけ減少するように、整数のラベルを頂点に割り当てる必要があります。 

グラフは DAG であるため、これらのラベルをノードから逆方向に計算できます。$n$。 

各ノードについて:

 - 発信エッジがある場合、すべての発信遷移で一貫した値が許可される必要があります
 - ノードの値はその子によって決定されます

 具体的にはエッジに関しては$u \to v$、

 -$dp[u]$どちらかに等しくなければなりません$dp[v] + 1$または$dp[v] + 2$2 つの出力エッジによって互換性のない値が強制される場合、答えは不可能です。 

これにより、指数関数的な検索が線形グラフ DP に変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(2^m \cdot (n+m))$|$O(n+m)$| 遅すぎる |
 | 最適 |$O(n+m)$|$O(n+m)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 有向グラフと逆グラフを作成します。 

逆グラフは、どの頂点が実際に都市に到達できるかを判断するのに役立ちます$n$。 
2. 都市 1 から到達可能なすべての頂点を見つけます。 

このセットの外にある頂点は 1 から n までの有効なルートに参加していないため、制約は課されません。 
3. 都市に到達できるすべての頂点を見つけます$n$。 

から始まる反転グラフで DFS または BFS を実行します。$n$。 
4. 1 から n までのパス上にある頂点のみを保持します。 

頂点は次の場合にのみ重要になります。$$reachable\_from\_1[v] = true$$そして$$can\_reach\_n[v] = true$$5. 頂点を逆の順序で処理します。$n$1まで下げます。 

グラフは非循環であり、すべてのエッジが小さいインデックスから大きいインデックスに進むため、これはすでに逆のトポロジー順序になっています。 
6. 以下を設定します。$$dp[n] = 0$$これは、からの残りの距離を意味します$n$それ自体はゼロです。 
7. 有用なノードごとに$u$、すべての出力エッジを調べます$u \to v$。 

各エッジでは次のことが可能になります。$$dp[u] = dp[v] + 1$$または$$dp[u] = dp[v] + 2$$すべての発信エッジは、少なくとも 1 つの共通の値に同意する必要があります。$dp[u]$。 
8. すべての許容値の交差を計算します。 

交差点が空になるとグラフは作成できなくなります。 
9. 有効な値を選択します。$dp[u]$。 

最も単純な選択は、有効な最小値です。 
10. エッジの重みを回復します。 

あらゆる有用なエッジについて:$$w(u,v) = dp[u] - dp[v]$$これは常に 1 または 2 になります。 
11. 無関係なエッジは、たとえば 1 などの任意の値を受け取ることができます。 

なぜ効果があるのか:

 不変条件とは、$dp[u]$ノードからの共通の残り距離を表します$u$ノードへ$n$。 

すべての発信エッジに対して$u \to v$、そのエッジを横切ると重量が消費されます$w(u,v)$、その後の残りの距離は$dp[v]$。 したがって、合計距離は次を満たす必要があります。$$dp[u] = w(u,v) + dp[v]$$すべてのパスの長さは$u$に$n$が等しい必要がある場合、この式はすべての出力エッジに対して同時に成立する必要があります。 

このアルゴリズムは、まさにそのようなシステムを明示的に構築します。 あるノードに共通の値が存在しない場合、すべての出力制約を満たす割り当てはありません。 それ以外の場合、構築された重みにより、すべてのパスが同じ合計を累積することが保証されます。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    edges = []
    g = [[] for _ in range(n + 1)]
    rg = [[] for _ in range(n + 1)]

    for i in range(m):
        u, v = map(int, input().split())
        edges.append((u, v))
        g[u].append((v, i))
        rg[v].append(u)

    # reachable from 1
    vis1 = [False] * (n + 1)
    q = deque([1])
    vis1[1] = True

    while q:
        u = q.popleft()
        for v, _ in g[u]:
            if not vis1[v]:
                vis1[v] = True
                q.append(v)

    # can reach n
    vis2 = [False] * (n + 1)
    q = deque([n])
    vis2[n] = True

    while q:
        u = q.popleft()
        for v in rg[u]:
            if not vis2[v]:
                vis2[v] = True
                q.append(v)

    useful = [vis1[i] and vis2[i] for i in range(n + 1)]

    dp = [None] * (n + 1)
    dp[n] = 0

    ans = [1] * m

    for u in range(n - 1, 0, -1):
        if not useful[u]:
            continue

        possible = None

        for v, idx in g[u]:
            if not useful[v]:
                continue

            cur = {dp[v] + 1, dp[v] + 2}

            if possible is None:
                possible = cur
            else:
                possible &= cur

        if not possible:
            print("No")
            return

        dp[u] = min(possible)

    for u, v in edges:
        if useful[u] and useful[v]:
            w = dp[u] - dp[v]
            if w < 1 or w > 2:
                print("No")
                return

    for i, (u, v) in enumerate(edges):
        if useful[u] and useful[v]:
            ans[i] = dp[u] - dp[v]
        else:
            ans[i] = 1

    print("Yes")
    print("\n".join(map(str, ans)))

```最初の部分では、通常のグラフと反転グラフの両方を構築します。 最終的に都市に到達できるノードを特定する必要があるため、反転したグラフが必要です。$n$。 

2 つの BFS トラバーサルは見落とされがちですが、重要です。 任意の 1-to- の外側のノード$n$パスは制約に参加しないでください。 とにかくそれらを処理すると、システムには解決策がないと誤って結論付ける可能性があります。 

エッジは常により大きなインデックスに向かうため、動的計画法は逆方向に進みます。 ノードを処理するまでに$u$、すべての子供たち$v$すでに完成した$dp[v]$。 

微妙な部分は交差ロジックです。 すべての発信エッジは、次の 2 つの許容値に寄与します。$dp[u]$:$$dp[v] + 1$$そして$$dp[v] + 2$$すべてのエッジは 1 つの共通の値に一致する必要があります。 集合交差を直接使用すると、実装が簡単かつ安全になります。 

最後の検証ステップは、DP が正しい場合には技術的に冗長ですが、実装ミスを防ぎ、デバッグが容易になります。
