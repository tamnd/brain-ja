 ## 解決策
 ## 問題の理解

 すでにソート済みの都市 A の気温シーケンスが与えられています。`a1, a2, ..., an`。 異なるシーケンスの数を数える必要があります`b1, b2, ..., bn`B の温度も下がらず、`bi <= ai`毎日のために。 すべての温度は次の整数です。`1`に`n`、答えは必須です`998244353`。 公式の制限は次のとおりです`n <= 2 * 10^5`、合計で`n`最大でもすべてのテストケースにわたって`5 * 10^5`、制限時間は 8 秒、メモリは 512 MB です。 

単調性が重要な構造特性です。 有効な`b`位置ごとに 1 つの値を任意に選択するわけではありません。 一度`b_i`が選択されている場合、以降のすべての値は少なくともその値でなければなりませんが、すべての位置にも異なる上限があります。 直接列挙することはすでに絶望的です。上限がなくても、長さが減少しないシーケンスの数は`n`以上`n`価値観は`C(2n-1,n)`したがって、すべての候補をチェックするには、大まかに必要になります`n * C(2n-1,n)`最悪の場合の運用。 簡単な動的プログラム`dp[i][j]`これを次のように削減します`O(n^2)`、 しかし`n = 2 * 10^5`約を意味します`4 * 10^10`制限時間をはるかに超えています。 合計入力サイズ`5 * 10^5`また、二次コストがテスト ケース全体に単に分散されるアルゴリズムも除外します。 

よくある誤った解釈を明らかにする境界例がいくつかあります。 のために`n = 1`そして`a = [1]`、可能な順序は次のとおりです。`b = [1]`、したがって、答えは次のとおりです`1`。 誤ってゼロを許可したり、最初の位置を異なる方法で処理したりすると、誤ったカウントが生成される可能性があります。 

のために`a = [1, 2, 3, 4]`、答えは`14`。 魅力的なグリッドの解釈は、パスのみをカウントすることです。`(n, a_n)`、それは与える`5`、しかしそれは選択の自由を失います`b_n`。 正しく構築すると、行と列が 1 つ追加され、最終的な下向きの移動が次のようになります。`b_n`; 結果のカウントはカタロニア数です`C_4 = 14`。 

のために`a = [4, 4, 4, 4]`、すべての有効な`b`は単に以下の 4 つの値の非減少シーケンスです。`{1,2,3,4}`。 そのカウントは`C(7,4) = 35`。 4 つの位置を独立したものとして扱うと、次のようになります。`4^4 = 256`などのローカルな選択肢を掛け合わせながら、`4 * 3 * 2 * 1`また、ある位置での選択により、その後の位置ごとに下限が変化するため、間違った答えが得られます。 

繰り返される値も重要です。 のために`a = [2,2,3]`、可能なペア`(b1,b2)`は`(1,1)`、`(1,2)`、 そして`(2,2)`。 それぞれ許可します`3`、`2`、 そして`2`～の選択肢`b3`、与える`7`。 プラトー全体をまとめて処理せずに等しい値を分割する分割統治の実装では、その平坦な境界に沿ったパスを二重にカウントしたり見逃したりする可能性があります。 

## アプローチ

 最も直接的な解決策は、すべての非減少シーケンスを列挙します。`b`、小切手`bi <= ai`、有効なものをカウントします。 これは文字通り候補の完全なセットを検査するため正しいですが、上限をチェックする前にさえ、`C(2n-1,n)`非減少シーケンス。 のために`n = 2 * 10^5`、その数は指数関数的です`n`, したがって、このアプローチは使用できません。 

自然な改善は動的プログラミングです。 させて`dp[i][j]`で終わる有効なプレフィックスの数になります。`b_i = j`。 それから`dp[i][j] = dp[i-1][1] + dp[i-1][2] + ... + dp[i-1][j]`いつでも`j <= ai`。 プレフィックスの合計により各遷移は定数時間になりますが、それでも`O(n^2)`州。 制約がローカルであるため総当り攻撃は機能しますが、可能な温度値の数が大きくなると失敗します。 

より高速な解決策を明らかにする観察は、この DP がまさに格子パス問題であるということです。 行を描画する`i`と`ai`セル、左揃え。 パスは右または下のみに移動します。 パスが行から移動するたびに`i`漕ぐ`i+1`、その下降移動が発生する列を記録します。 これらの記録された列は非減少シーケンスを形成し、その行が`i`のみが含まれます`ai`細胞が与える`bi <= ai`。 

全てを代表するために`n`の値`b`、追加の値を 1 つ追加します`a_{n+1}=n+1`。 余分な下方への移動は、元の最終値を表します。`b_n`、パスは右下隅で終了します。 行を反転して、減少しない境界を増加しない階段に変えることができます。 結果として生じる問題は、フェラーズ形状の領域内の単調パスをカウントすることです。 

この領域の長方形部分については、通常の DP には次の再帰があります。`F(i,j) = F(i-1,j) + F(i,j-1)`。 

長方形の上端と左端の値がわかっている場合、その下端と右端のすべての値は二項畳み込みとして表現できます。 高さのある長方形の場合`h`と幅`w`、上部境界値からの寄与`x_j`一番下の位置に`i`は`x_j * C(i-j+h-1, h-1)`、

 一方、左境界値からの寄与`y_j`一番下の位置に`i`は`y_j * C(i+h-1-j, i)`。 

右側の境界に対応する式は対称です。 

二項係数には階乗が含まれているため、各畳み込みは通常の多項式乗算に変換できます。 例えば、`C(i-j+h-1, h-1) = (i-j+h-1)! / ((h-1)! (i-j)!)`。 

1 つの因子を反転し、階乗シーケンスまたは逆階乗シーケンスを乗算すると、遷移全体が 1 つの多項式畳み込みになります。 係数以来`998244353`NTT をサポート、各畳み込みコスト`O(k log k)`二次時間ではなく。 

境界自体は分割統治によって処理されます。 各再帰レベルで、単調境界の中間の高さを選択し、その高さを持つ最大の長方形を抽出し、NTT を使用してその境界遷移を解決し、残りの 2 つの部分を再帰します。 隣接する等しい値は同じ四角形内に保持され、これによりプラトーが正しく処理されます。 

再帰の深さが固定されている場合、長方形は互いに素であるため、その幅と高さの合計は次のようになります。`O(n)`。 がある`O(log n)`レベルと各レベルのパフォーマンス`O(n log n)`合計で働きます。 結果として生じる複雑さは、`O(n log^2 n)`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべて列挙する`b`|`O(n C(2n-1,n))`|`O(n)`| 遅すぎる |

 ## アルゴリズムのチュートリアル

 1. すべての有効なシーケンスを解釈する`b`格子パスとして。 グリッドを作成します。`i`- 番目の行には`ai`細胞。 列から下に移動`i`列で`j`記録`bi = j`。 右に移動すると列が増加するため、記録された値は減少しません。 行幅制限により、`bi <= ai`。 
2. 幅のある行を 1 行追加します。`n+1`。 この最後の行により、最後の下向きステップがエンコードされます。`b_n`, したがって、答えは左上隅から新しい右下隅までのパスの数になります。 
3. 行の順序を逆にします。 オリジナル`a`は減少していないため、反転後も増加しません。 これにより、境界は最大の水平方向の長方形に分解できる階段になります。 
4. 階乗および逆階乗モジュロを事前計算する`998244353`まで`2n+2`。 長方形の遷移で使用されるすべての二項係数は、一定時間で評価できます。 
5.高さのある長方形の場合`h`と幅`w`、その上部境界の値を配列に格納します`top`配列内のその左側の境界の値`left`。 経路は右方向と下方向の移動の位置によって決まるため、各境界位置から目的地までの経路の数は二項係数となります。 
6. 畳み込みを使用して上部境界から下部境界を計算します。`bottom[i] += sum(top[j] * C(i-j+h-1,h-1))`。 

左側の境界も下部に影響します。`bottom[i] += sum(left[j] * C(i+h-1-j,i))`。 

最初の合計は、シーケンスとの通常の畳み込みです。`C(k+h-1,h-1)`。 2 番目は乗算後の畳み込みになります`left[j]`による`1/(h-1-j)!`そしてもう一方の因数に階乗を掛けます。 

1. 右側の境界を対称的に計算します。 上部境界は次のような影響を及ぼします。`right[i] += sum(top[j] * C(i+w-1-j,i))`、

 左側の境界は次のように寄与します。`right[i] += sum(left[j] * C(i-j+w-1,w-1))`。 

これらは、幅と高さを交換した同じ 2 つの畳み込みパターンです。 

1. 十分に大きな畳み込みごとに NTT を使用します。 短い配列の場合、Python では直接乗算の方が高速であるため、実装は小さなしきい値を下回ると 2 次法に切り替わります。 
2. 中央の列をとって階段を分割します。 複数の連続する行の境界の高さが同じである場合、それらを 1 つの最大プラトーとして扱います。 プラトーの上の部分を再帰的に解決し、プラトーによって占められている長方形を解決してから、その下の部分を再帰的に解決します。 プラトーをそのままの状態に保つことで、同じ境界パスが 2 回処理されるのを防ぎます。 
3. 初期状態は左上隅です。 階段全体が処理された後、必要な答えは最後の右下隅の DP 値です。 

### なぜ効果があるのか

 グリッド構造により、法的規則と法的規則の間の全射が可能になります。`b`シーケンスと単調なパス。 すべての長方形の内部では、標準的なラティス パスの反復が正確であるため、二項式は完全な計算とまったく同じ DP 値を計算します。`O(n^2)`テーブルには次のものが含まれます。 分割統治では、境界値が計算される順序が変更されるだけです。 その不変条件は、子四角形に必要なすべての値がその上または左の境界にすでに存在していることです。 階段は互いに素な長方形に分割されており、長方形の遷移ではいずれかの境界を通過するすべてのパスが 1 回だけカウントされるため、すべての正当なパスは最終コーナーに 1 回到達し、不正なパスはカウントされません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353
G = 3
NAIVE_LIMIT = 4096

def ntt(a, invert):
    n = len(a)

    j = 0
    for i in range(1, n):
        bit = n >> 1
        while j & bit:
            j ^= bit
            bit >>= 1
        j ^= bit
        if i < j:
            a[i], a[j] = a[j], a[i]

    length = 2
    while length <= n:
        wlen = pow(G, (MOD - 1) // length, MOD)
        if invert:
            wlen = pow(wlen, MOD - 2, MOD)

        half = length >> 1
        for start in range(0, n, length):
            w = 1
            end = start + half
            for i in range(start, end):
                u = a[i]
                v = a[i + half] * w % MOD

                x = u + v
                if x >= MOD:
                    x -= MOD
                y = u - v
                if y < 0:
                    y += MOD

                a[i] = x
                a[i + half] = y
                w = w * wlen % MOD

        length <<= 1

    if invert:
        inv_n = pow(n, MOD - 2, MOD)
        for i in range(n):
            a[i] = a[i] * inv_n % MOD

def convolution(a, b):
    if not a or not b:
        return []

    need = len(a) + len(b) - 1

    if len(a) * len(b) <= NAIVE_LIMIT:
        c = [0] * need
        for i, x in enumerate(a):
            if x:
                for j, y in enumerate(b):
                    c[i + j] = (c[i + j] + x * y) % MOD
        return c

    size = 1
    while size < need:
        size <<= 1

    fa = a[:] + [0] * (size - len(a))
    fb = b[:] + [0] * (size - len(b))

    ntt(fa, False)
    ntt(fb, False)

    for i in range(size):
        fa[i] = fa[i] * fb[i] % MOD

    ntt(fa, True)
    return fa[:need]

def count_arrays(original):
    n = len(original)

    # Add the extra row, then reverse the staircase.
    a = [0] + original + [n + 1]
    a[1:] = reversed(a[1:])

    max_fact = 2 * n + 2
    fac = [1] * (max_fact + 1)
    invfac = [1] * (max_fact + 1)

    for i in range(1, max_fact + 1):
        fac[i] = fac[i - 1] * i % MOD

    invfac[max_fact] = pow(fac[max_fact], MOD - 2, MOD)
    for i in range(max_fact, 0, -1):
        invfac[i - 1] = invfac[i] * i % MOD

    def comb(x, y):
        if y < 0 or y > x:
            return 0
        return fac[x] * invfac[y] % MOD * invfac[x - y] % MOD

    # dp[row] stores only boundary values that are needed later.
    dp = [dict() for _ in range(n + 2)]

    def add_dp(row, col, value):
        d = dp[row]
        d[col] = (d.get(col, 0) + value) % MOD

    def rect(l, r, bot, top):
        if l == 1 and r == 1 and top == n + 1:
            for col in range(bot, top + 1):
                dp[1][col] = 1
            return

        width = r - l + 1
        height = top - bot + 1

        # Top boundary.
        upper = [
            dp[l + i].get(top + 1, 0)
            for i in range(width)
        ]

        # Left boundary.
        left = [
            dp[l - 1].get(top - i, 0)
            for i in range(height)
        ]

        bottom = [0] * width
        right = [0] * height

        # Left -> bottom.
        x = [
            left[i] * invfac[height - 1 - i] % MOD
            for i in range(height)
        ]
        y = fac[:width + height - 1]
        z = convolution(x, y)

        for i in range(width):
            bottom[i] = (
                bottom[i]
                + z[height - 1 + i] * invfac[i]
            ) % MOD

        # Top -> bottom.
        kernel = [
            comb(i + height - 1, height - 1)
            for i in range(width)
        ]
        z = convolution(upper, kernel)

        for i in range(width):
            bottom[i] = (bottom[i] + z[i]) % MOD

        # Top -> right.
        x = [
            upper[i] * invfac[width - 1 - i] % MOD
            for i in range(width)
        ]
        y = fac[:width + height - 1]
        z = convolution(x, y)

        for i in range(height):
            right[i] = (
                right[i]
                + z[width - 1 + i] * invfac[i]
            ) % MOD

        # Left -> right.
        kernel = [
            comb(i + width - 1, width - 1)
            for i in range(height)
        ]
        z = convolution(left, kernel)

        for i in range(height):
            right[i] = (right[i] + z[i]) % MOD

        for i in range(width):
            add_dp(l + i, bot, bottom[i])

        # The lower-right corner belongs to both boundaries.
        for i in range(top, bot, -1):
            add_dp(r, i, right[top - i])

    def solve_staircase(l, r, bot):
        if l > r:
            return

        mid = (l + r) >> 1

        x = mid
        while x - 1 >= l and a[x - 1] == a[mid]:
            x -= 1

        y = mid
        while y + 1 <= r and a[y + 1] == a[mid]:
            y += 1

        solve_staircase(l, x - 1, a[mid] + 1)
        rect(l, y, bot, a[mid])
        solve_staircase(y + 1, r, bot)

    solve_staircase(1, n + 1, 1)
    return dp[n + 1].get(1, 0)

def solve_data(data):
    it = iter(map(int, data.split()))
    t = next(it)
    out = []

    for _ in range(t):
        n = next(it)
        a = [next(it) for _ in range(n)]
        out.append(str(count_arrays(a)))

    return "\n".join(out)

def solve():
    data = sys.stdin.buffer.read()
    sys.stdout.write(solve_data(data))

if __name__ == "__main__":
    solve()
```すべての四角形遷移では二項係数が使用されるため、階乗初期化が最初に行われます。 最大の要因指数は最大でも`2n+2`、長方形には最大でも`n+1`行と`n+1`列。 

の`convolution`ルーチンには意図的に小さな直接乗算分岐が含まれています。 NTT にはビット反転といくつかの変換パスによる固定オーバーヘッドがあるため、2 つの小さな配列を直接乗算する方が高速です。 大きな製品は係数固有の原始ルートを使用します`3`、これは有効です。`998244353 = 119 * 2^23 + 1`。 

レクタングル ルーチンは 4 つの境界転送を正確にたどります。 の`height - 1 + i`そして`width - 1 + i`インデックスは最もデリケートな部分です。 これらは、階乗が二項係数を 2 つの 1 次元シーケンスの積に変換するように畳み込みをシフトすることで得られます。 

の`dp`完全なグリッドは二次サイズであるため、構造は疎です。 長方形の境界上にある値のみが保存されます。 新しい値が既存の境界に属する場合、`add_dp`上書きするのではなく追加します。 右下隅は下と右の両方の計算によって生成されるため、実装では 2 回目の挿入では意図的にそれをスキップします。 

Python の整数はオーバーフローしませんが、すべての乗算は依然として剰余化されます。`998244353`すぐに。 各階段領域がその中央付近で分割されるため、再帰の深さは対数になります。そのため、分割統治自体には通常の Python 再帰制限で十分です。 

この実装は、コンテストで受け入れられたアプローチと同じ長方形と NTT 戦略に従います。 元の問題とその公式制限は Codeforces で入手できます。

| ステージ | グリッド境界 | パスの数 |
 | --- | --- | --- |
 | 開始 |`(1,1)`|`1`|
 | 最初の階段レベルを通過した後 | 幅`1`|`1`|
 | 2 番目のレベル以降 | 幅`2`|`2`|
 | 3 レベル以降 | 幅`3`|`5`|
 | 4 レベル以降 | 幅`4`|`14`|

 シーケンス`1, 2, 5, 14`カタルーニャ語シーケンスの始まりです。 この例は、追加の行が必要な理由も示しています。 元の 4 行目までのパスのみをカウントすると、次のように表される最後の自由選択をエンコードする前に停止します。`b4`。 

公式サンプル第3弾は、`a = [4,4,4,4]`、答えがあります`35`、4 つの可能な温度から選択された 4 つの減少しない値の直接の星と棒の数と一致します。 公式のサンプル出力は次のとおりです。`1`、`14`、 そして`35`。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |`O(n log^2 n)`| 各分割統治レベルには、長方形の境界の合計サイズがあります。`O(n)`、各境界遷移は NTT 畳み込みを使用します。 
| スペース |`O(n log n)`| 階乗の使用`O(n)`一方、まばらな四角形の境界は、位置ごとに最大でも対数的に多くの保存レイヤーを必要とします。 

合計`n`すべてのテストケース全体で最大でも`5 * 10^5`, そのため、対数因数は制限された合計入力サイズ全体で共有されます。 意図された C++ 実装は、公式の 8 秒および 512 MB 制限内に問題なく収まります。

 ## 特殊なケース

 のために`n = 1`そして`a = [1]`、拡張されたシーケンスは次のようになります。`[1,2]`。 可能な値は 1 つだけです`b1`、つまり`1`。 グリッドには有効なパスが 1 つだけあるため、アルゴリズムは値を持って最後のコーナーに到達します。`1`。 

のために`a = [1,2,3,4]`、拡張境界は`[1,2,3,4,5]`。 階段のパス数は`14`。 元の行で停止する構造`n`だけを数えます`5`パス、まだ選択を表していないため、`b_n`。 追加の行は、回転することでこの境界の間違いを修正します。`b_n`最後の下降トランジションに入る。 

のために`a = [4,4,4,4]`、すべての非減少 4 要素シーケンス`{1,2,3,4}`有効です。 カウントは`C(4+4-1,4) = C(7,4) = 35`。 逆グリッドでは、境界はほとんど平坦であるため、最大プラトー ロジックは、等しい各行を独立した境界変更として扱うのではなく、繰り返されるセクション全体を 1 つの長方形として扱います。 

のために`a = [2,2,3]`、答えは`7`。 最初の 2 つの位置は次のとおりです。`(1,1)`、`(1,2)`、 または`(2,2)`。 それらが修正されると、最終的な値はそれぞれ`3`、`2`、 または`2`可能な値。 長方形のトランジションは、個別のパスを誤ってマージすることなく、これらのパス ファミリを追加します。`7`。 

最大サイズの場合`n = 200000`あらゆるものと`ai = 1`、 毎`bi`も等しくなければなりません`1`、したがって答えは残ります`1`。 アルゴリズムは完全なものを構築することはありません`200000 × 200000`DPテーブル。 まばらな境界値のみを保存し、分割統治を浅く保つために平らな階段を使用します。
