 ## 解決策
 ## 問題の理解

 私たちは (n) 個の軸を揃えた長方形のスキャナーを持っています。 スキャナ (i) は現在、座標が内側にあるすべてのグリッド正方形をカバーしています

 [
 [a_i,c_i]\times[b_i,d_i]。 
】

 移動すると 1 つのスキャナ全体が水平方向または垂直方向に 1 正方形だけ移動するため、スキャナを ((\Delta x,\Delta y)) だけ移動すると、(|\Delta x|+|\Delta y|) のコストがかかります。 総移動数を最小限に抑えながら、少なくとも 1 つのグリッド正方形が各スキャナーに属するようにスキャナーの位置を変更したいと考えています。 

最初の便利な簡略化は、最終的なスキャナの位置を忘れて、代わりにすべてのスキャナがカバーする正方形を選択することです。 この正方形が固定されると、すべてのスキャナーを個別に最適化できます。 残りの問題は、最良の共通正方形をどのように選択するかです。 

1 つのテスト ケースには最大 (10^5) 個のスキャナーがあり、すべてのテスト ケースにわたるスキャナーの合計数は最大で (10^6) です。 座標は (10^9) に達する可能性があるため、可能な位置を列挙するアルゴリズムは直ちに不可能になります。 2 秒の制限時間がある場合、(O(n^2)) メソッドでも (n=10^5) ではコストが高すぎます。座標範囲に依存するメソッドはさらに悪化します。 基本的に (O(n\log n)) 個以上の総作業量が必要です。 

誤って対処しやすい特殊なケースがいくつかあります。 単一のスキャナには、それ自身と共通の覆われた正方形がすでに存在するため、```
1
1
5 7 9 11
```生産しなければならない```
0
```選択したグローバル座標に向かって常に移動する不注意な実装では、移動が必要ない場合でも肯定的な応答が生成される可能性があります。 

2 つの四角形は、どちらの四角形ももう一方の四角形に含まれていない場合でも、すでに重なっている場合があります。 例えば、```
1
2
1 1 5 5
3 3 7 7
```答えがあります`0`、正方形 ((3,3)) が両方でカバーされているためです。 長方形の中心のみに基づくアプローチでは、これを見逃す可能性があります。 

覆われた正方形は整数正方形であり、端点が含まれるため、境界での接触もカウントされます。 のために```
1
2
1 1 1 1
2 1 2 1
```答えは`1`: いずれかのスキャナを水平に 1 マス移動します。 間隔を開いたものとして扱うと、境界位置が誤って拒否されます。 

長方形は他の長方形よりもはるかに幅が広い場合があります。 考慮する```

最終的に、座標は (10^9) まで大きくなります。 のために```

## アプローチ

 直接的な総当たりソリューションでは、候補となる正方形 ((x,y)) を選択し、その正方形をカバーするために各スキャナーがどれだけ移動する必要があるかを計算し、最小の総コストを維持できます。 これは正しいです。すべての有効な最終構成には共通のカバーされた四角形があるため、考えられるすべての共通四角形を考慮すると、最適な構成も考慮されます。 

問題は候補者の数だ。 有用な座標はすべて入力四角形の境界ボックス内にあるため、(10^9) 個の (x) 座標と (10^9) 個の (y) 座標が存在する可能性があります。 これにより、(10^{18}) 個もの正方形の候補が得られます。 各候補のすべての (n) スキャナを評価するには、(n=10^5) の場合に最大 (10^{23}) 個の距離計算が必要になります。 ブルート フォースは概念的には単純ですが、実現可能とは程遠いものです。 

重要な観察は、2 つの座標が完全に独立しているということです。 共通の正方形が (x) 座標 (x) を持つと仮定します。 スキャナ (i) の場合、その水平間隔は ([a_i,c_i]) です。 (x) がすでにこの区間に属している場合、水平方向の移動は必要ありません。 (x<a_i) の場合、スキャナは左側の境界が (x) に達するように左または右に移動し、コストは (a_i-x) になります。 同様に、(x>c_i) の場合、コストは (x-c_i) になります。 

したがって、スキャナー (i) の水平コストは、(x) から間隔 ([a_i,c_i]) までの距離と正確に一致します。 

[
 \演算子名{距離}(x,[a_i,c_i])。 
】

 したがって、水平コストの合計は次のようになります。 

[
 F(x)=\sum_i \演算子名{dist}(x,[a_i,c_i])。 
】

 垂直座標では、間隔 ([b_i,d_i]) に関して同じ問題が発生します。 2 つの 1 次元の問題を独立して解き、その答えを加算することができます。 

残りの問題は、間隔までの距離の合計を最小化する方法です。 有用なアイデンティティは

 (r-l)+2\演算子名{距離}(x,[l,r])。 
】

 並べ替えると、

 \frac{|x-l|+|x-r|-(r-l)}{2}。 
】

 これをすべての区間にわたって合計すると、(x) に関係する項は、(x) からすべての (2n) 端点までの絶対距離の合計になります。 絶対距離の合計は中央値で最小になります。 したがって、必要なのは左右のエンドポイントすべての中央値だけです。 

ブルートフォースが機能するのは、共通の正方形を明示的に検索するためです。 検索スペースが膨大なため失敗します。 移動コストが座標によって分離されるという観察により、問題は 2 つの 1 次元区間の問題に変わり、エンドポイントの同一性により、それぞれの問題が中央値を見つけることに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(n\cdot 10^{18})) | (O(1)) | 遅すぎる |
 | 最適 | (O(n\log n)) | (O(n)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのスキャナについて、水平方向の端点 (a_i,c_i) を 1 つの配列に収集し、垂直方向の端点 (b_i,d_i) を別の配列に収集します。 また、合計の水平幅 (\sum(c_i-a_i)) と垂直高さ (\sum(d_i-b_i)) を累積します。 水平方向の移動によって垂直方向のカバレッジが変更されることはないため、2 つの軸は独立して処理できます。 
2. (2n) 個の水平端点を並べ替えます。 ゼロベースのインデックスを使用して、インデックス (n-1) の要素を水平ターゲット座標 (x) として選択します。 これは 2 つの中間エンドポイントのうちの 1 つであるため、すべての (2n) エンドポイントの有効な中央値です。 
3. (x) とすべての水平端点間の絶対差の合計を計算します。 ソートされたエンドポイントが (e_1,\ldots,e_{2n}) の場合、水平方向の移動コストは次のようになります。 

[
 \frac{\sum_j |e_j-x|-\sum_i(c_i-a_i)}{2}。 
】

 合計幅を減算すると、すでに自由になっている動きが削除されます。これは、ターゲット座標が両方の端点を強制的に四角形に近づけるのではなく、四角形の内側に配置できるためです。

1. 垂直端点についても同じ計算を繰り返します。中央の垂直端点に等しい (y) を使用し、長方形の高さの合計を減算します。 
2. 水平コストと垂直コストを加算します。 水平方向または垂直方向の変位のすべての単位が 1 つの許可された操作に正確に対応するため、これは個々のスキャナの移動の最小数です。 

### なぜ効果があるのか

 任意の固定ターゲット正方形 ((x,y)) について、スキャナ (i) は正確に

 [
 \演算子名{距離}(x,[a_i,c_i])
 +
 \演算子名{距離}(y,[b_i,d_i])
 】

 動く。 スキャナーを合計すると、対物レンズが (x) のみの部分と (y) のみの部分に分離されるため、2 つの座標を個別に最小化することが最適です。 

1 つの区間 ([l,r]) に対して、

 \frac{|x-l|+|x-r|-(r-l)}{2}。 
】

 すべての間隔を合計した後、(x) に依存する唯一の部分は、(x) からすべての (2n) 端点までの絶対距離の合計です。 すべての中央値はそのような合計を最小化します。 したがって、選択された中間エンドポイントは可能な最小の水平コストを与え、同じ引数は最小の垂直コストを与えます。 2 つのコストは独立しているため、それらの合計はグローバルに最適になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def axis_cost(endpoints, span_sum, n):
    endpoints.sort()
    median = endpoints[n - 1]

    distance_sum = sum(abs(x - median) for x in endpoints)
    return (distance_sum - span_sum) // 2

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())

        xs = []
        ys = []
        x_span = 0
        y_span = 0

        for _ in range(n):
            a, b, c, d = map(int, input().split())

            xs.append(a)
            xs.append(c)
            ys.append(b)
            ys.append(d)

            x_span += c - a
            y_span += d - b

        answer = axis_cost(xs, x_span, n)
        answer += axis_cost(ys, y_span, n)

        out.append(str(answer))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```入力ループは、各軸に必要な 2 つのエンドポイントを正確に保存します。 元の長方形の端点と幅を記録した後、元の長方形を保持する必要はありません。`axis_cost`最初に (2n) 個のエンドポイントを並べ替えて選択します`endpoints[n - 1]`。 (2n) 個の値があるため、両方の中間位置が有効な中央値になります。 中央の下位の値を選択すると、浮動小数点演算の必要がなくなり、特にゼロベースのインデックス付けに便利です。 

表現```
distance_sum - span_sum
```証明からアイデンティティを実装します。 すべての間隔 ([l,r]) について、その 2 つのエンドポイント寄与は (|x-l|+|x-r|) であり、その幅 (r-l) が減算されます。 結果は、間隔までに必要な距離のちょうど 2 倍になります。 整数の 2 による除算は、結果の数量が整数になるため安全です。 

入力座標は最大でも (10^9) ですが、合計の答えは (2\cdot10^{14}) 程度になる可能性があるため、Python の任意精度の整数は便利です。 オーバーフローの危険はありません。 

除算は、合計が計算された後に行う必要があります。 2 で割る前に 2 つのエンドポイント項と区間幅を結合する必要があるため、個々のエンドポイント寄与を最初に除算することは不正確です。
