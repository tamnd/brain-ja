 ## 解決策
 ## 問題の理解

 元のグラフ (G) はツリーであるため、(n) 個の頂点と正確に (n-1) 個の重み付けされたエッジがあります。 折れ線グラフ (L(G)) は、元のすべてのエッジを頂点に変換します。 2 つの元のエッジが (G) の同じ頂点で出会うたびに、(L(G)) の対応する頂点が接続され、新しいエッジの重みは 2 つの元のエッジの重みの合計に等しくなります。 

タスクは (L(G)) を構築することではありません。これは既に (G) よりもはるかに大きくなる可能性があります。 必要なのは、最小スパニングツリーの総重み (L(G)) だけです。 

重要な構造的事実は、元のツリーの 1 つの頂点 (v) を見ることで得られます。 その入射エッジに重み (a_1,a_2,\ldots,a_k) があるとします。 折れ線グラフでは、それら (k) 個の元のエッジが (k) 個の頂点になり、それらの間のすべてのペアは隣接します。 それらは完全なグラフを形成します。 頂点 (i) と (j) を結合するエッジの重みは (a_i+a_j) です。 

したがって、元の頂点ごとに、折れ線グラフ内に 1 つの重み付きクリークが生成されます。 (G) はツリーであるため、2 つの異なる元の頂点は 2 つの元のエッジを共有できません。 したがって、これらのクリークは (L(G)) の個々の頂点でのみ重なり、そのグローバル構造自体がツリー状になります。 

入力には 1 つのテスト ケースに最大 (10^5) 個の頂点が含まれており、すべてのテスト ケースの (n) の合計は最大で (10^6) です。 二次アルゴリズムはすでに大きすぎます。 この区別が特に重要になるのは、星型ツリーがほぼすべての (n-1) 個の折れ線グラフの頂点を含むクリークを作成するためです。したがって、折れ線グラフを明示的に構築するには数十億のエッジが必要になる可能性があります。 ソリューションでは、元のツリーを基本的に 1 回処理する必要があります。 

不注意な式や実装が失敗する可能性がある小さなケースがいくつかあります。 たとえば、```
1
2
1 2 100
```元のツリーにはエッジが 1 つだけあるため、(L(G)) には頂点が 1 つだけあります。 その MST にはエッジが含まれておらず、答えは (0) です。 元のエッジの重みを盲目的に追加する実装では、誤って (100) が生成されます。 

もう 1 つの便利なケースは、異なる重みを持つパスです。```
1
4
1 2 1
2 3 2
3 4 3
```折れ線グラフは 3 つの頂点のパスです。 2 つのエッジの重みは (1+2=3) と (2+3=5) であるため、答えは (8) になります。 各頂点での最小入射重みを加算するだけの式では、折れ線グラフの 2 つのエッジによって寄与される合計が不足する可能性があります。 

ケースが分岐すると、もう 1 つのよくある間違いが明らかになります。```
1
4
1 2 1
1 3 1
1 4 1
```元の 3 つのエッジは三角形の 3 つの頂点になり、折れ線グラフの各エッジには重み (2) が設定されます。 三角形の MST には 2 つの辺があるため、答えは (4) になります。 3 つのクリーク エッジをすべて数えると、誤って (6) が得られます。 

## アプローチ

 直接的なアプローチは、折れ線グラフを明示的に作成することです。 元のツリーには (n-1) 個のエッジがあるため、折れ線グラフには (n-1) 個の頂点があります。 次数 (d) の元の頂点では、その入射エッジのすべてのペアが折れ線グラフ エッジを作成し、(\binom d2) エッジを与えます。 それらをすべて生成し、重みで並べ替えて、クラスカルのアルゴリズムを実行することができます。 結果として得られるグラフは正確に (L(G)) であり、Kruskal がその MST を計算するため、これは正しいです。 

問題は生成されるエッジの数です。 (n-1) 個の葉を持つ星を考えてみましょう。 その中心の次数は (n-1) であるため、(L(G)) には次の値が含まれます。 

[
 \binom{n-1}{2}
 】

 エッジ。 (n=100000) の場合、これは次のようになります。 

[
 \frac{99999\cdot99998}{2}=4,999,850,001
 】

 エッジ。 それらを生成するだけでは、ソートする前からすでに利用可能なリソースをはるかに超えています。 一般的なクラスカル実装では、最悪の場合 (O(n^2\log n)) の時間が必要となり、すべての折れ線グラフのエッジが格納される場合は (O(n^2)) のメモリが必要になります。 

問題を線形にする観察は、クリーク全体が決して必要ないということです。 入射エッジの重みが (a_1,\ldots,a_k) である 1 つの元の頂点 (v) を考え、(m) をそれらの最小値とします。 折れ線グラフ クリークには、すべてのペア間の重み (a_i+a_j) のエッジが含まれています。 

重み (a_i) の入射エッジに対応するすべての頂点について、その頂点から別のクリーク頂点への最も安価なエッジは、その頂点を最小重みエッジ (m) に接続するエッジです。 その重みは (a_i+m) です。 したがって、クリーク頂点を 1 つおきに最小重み頂点に直接接続すると、星が与えられます。 その総重量は

 \sum_i a_i +(k-2)m,
 】

 ここで、(p) は最小重みの位置です。 

このスターはクリークのMSTです。 1 つの非最小頂点で構成されるカットには、最小重み頂点に向かう最も安価な出力エッジがあるため、カット プロパティによってこれらのエッジの選択が正当化されます。 

元のツリーでは、元の頂点ごとにそのようなクリークが 1 つ与えられます。 2 つの異なるクリークが折れ線グラフの頂点で交差できるのは最大 1 つで、元のグラフ自体にはサイクルがないため、すべてのクリーク内の MST を一緒に取得すると、折れ線グラフ全体の MST が生成されます。 派閥間で複雑な選択を調整する必要はありません。 

元の頂点 (v) の結果の式は次のようになります。 

S_v+(\deg(v)-2)m_v,
 】

 ここで、(S_v) は (v) に付随するエッジの重みの合計であり、(m_v) はそれらの最小重みです。 

葉の場合、(\deg(v)=1) なので、式は (S_v-m_v=0) になります。これは、次数 1 の元の頂点が折れ線グラフの頂点を 1 つだけ含むクリークを作成するため、必要に応じて正確に計算されます。 

必要なのは、元の頂点ごとの次数、合計、最小入射重みだけです。 すべての入力エッジは、その 2 つの端点でこれら 3 つの量を更新します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(n^2\log n)) 最悪の場合 | (O(n^2)) | 遅すぎる |
 | 最適 | (O(n)) | (O(n)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 元の頂点の 3 つの配列を作成します。`degree[v]`、`sum_weight[v]`、 そして`min_weight[v]`。 1 つ目は入射エッジをカウントし、2 つ目はその合計の重みを保存し、3 つ目は最小の入射エッジの重みを保存します。 
2. 元のツリーの各エッジ ((u,v,w)) を読み取ります。 両方のエンドポイントの次数を増やし、両方のエンドポイントの合計に (w) を追加し、(w) が小さい場合は最小入射重みを置き換えます。 

これらの更新後に元のエッジを保存する必要はありません。 最終的な式は、これら 3 つの集計値のみに依存します。 
3. すべての (n-1) 個のエッジが処理された後、すべての元の頂点 (v) にアクセスして追加します。 

[
 \text{合計重量}[v]
 +
 (\text{度}[v]-2)\cdot\text{min_weight}[v]
 】

 答えに。 

この式は、(v) の入射エッジによって作成されたクリークの MST 重みとまったく同じです。 
4. テスト ケースの累積された回答を印刷します。 

### なぜ効果があるのか

 すべての元の頂点 (v) について、その入射エッジは (L(G)) のクリークになります。 星の中心として最小重みの入射エッジを選択すると、他のすべてのクリーク頂点に対して、そのクリーク内の可能な限り最も安価な接続が得られます。 カット プロパティにより、これらの選択肢はそのクリークの MST を形成します。 

元のグラフはツリーであるため、そのエッジ クリークはツリー状のブロック構造を形成します。 このような 2 つのクリークは、複数の折れ線グラフの頂点を共有できません。 したがって、各クリークの MST を結合すると、サイクルを導入せずにすべての折れ線グラフの頂点が接続されます。 すべてのクリークは最小限のコストですでに接続されているため、クリークの一部をより安価な構造に置き換えることは不可能です。 したがって、個々のクリークの MST コストの合計は、まさに (L(G)) の MST 重みになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    INF = 10**30

    for _ in range(t):
        n = int(input())

        degree = [0] * (n + 1)
        total = [0] * (n + 1)
        minimum = [INF] * (n + 1)

        for _ in range(n - 1):
            u, v, w = map(int, input().split())

            degree[u] += 1
            total[u] += w
            if w < minimum[u]:
                minimum[u] = w

            degree[v] += 1
            total[v] += w
            if w < minimum[v]:
                minimum[v] = w

        ans = 0

        for v in range(1, n + 1):
            ans += total[v] + (degree[v] - 2) * minimum[v]

        out.append(str(ans))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```入力ループは、ステップ 1 と 2 の集計を実装します。元の各エッジは正確に 2 つの頂点に影響を与えるため、すべてのエッジは一定時間で処理されます。 

最後のループはステップ 3 を直接実装します。 リーフの次数は (1) であり、その寄与は次のとおりです。 

[
 w+(1-2)w=0。 
】

 葉について特別なケースが必要ないため、これは便利です。 (n\ge2) であり、入力グラフはツリーであるため、すべての頂点には少なくとも 1 つの入射エッジがあります。`minimum[v]`使用時には常に実際のエッジの重みに初期化されます。 

Python の整数には任意の精度があり、答えが 32 ビット整数を超える可能性があるため、これは重要です。 エッジの重みが最大 (10^9) および (10^5) 頂点の場合、答えは (10^{14}) 程度になります。 

このコードでは、隣接関係リストの保存も回避します。 隣接リストは依然として線形で完全に有効ですが、式に必要のない情報が含まれています。 配列を 3 つだけ保持すると、実装が簡素化され、メモリ使用量が削減されます。
