 ## 解決策
 ## 問題の理解

 (n) 個の超高層ビルの列があり、(i) 個の超高層ビルの目標高さは (a_i) です。 すべての高さがゼロに等しい状態から開始すると、1 つの建設段階で、1 つの連続した間隔内のすべての超高層ビルを正確に 1 増やすことができます。 

固定ターゲット アレイの場合、問題は、可能な限り最良の構築計画でそのような間隔の増分が何回必要になるかということです。 次に、ある間隔ですべての (a_i) に同じ値 (k) を加算する操作によって配列が変更されます。 クエリは間隔 ([l,r]) を選択し、その間隔の外側にあるすべての超高層ビルをターゲットの高さが 0 であるものとして扱い、その結果のプロファイルを正確に構築するために必要な最小ステージ数を要求します。 

公式の制約では 1 つのテスト ケースで (n,m\le 100000) が許可されますが、テスト ケース全体のすべての (n) とすべての (m) の合計は最大でも (10^6) になります。 多くの範囲の追加が蓄積される可能性があるため、構築の高さが最初の (10^5) 境界よりも大幅に大きくなる可能性もあります。 クエリ間隔全体をスキャンするソリューションには (O(nm)) かかり、約 (10^{10}) 個の要素の訪問に達する可能性があります。 これは、数秒間の競技プログラミングの制限が処理できる範囲をはるかに超えています。 各更新とクエリには、ほぼ対数の時間がかかる必要があります。 元の問題には 4 秒の時間制限と 512 MB のメモリ制限があります。 

主なエッジケースは、隣接する超高層ビル間の増加のみが問題となるという事実から来ています。 考慮する```
1
1 1
5
2 1 1
```答えは (5) です。1 つの超高層ビルには 5 つの単位間隔が必要だからです。 隣接する位置間の変化のみをカウントし、左側の境界を無視する数式は、誤ってゼロを返します。 

2番目の例は```
1
3 1
2 7 3
2 2 2
```答えは(7)です。 クエリでは中央の超高層ビルのみが保持されるため、その有効なプロファイルは ([0,7,0]) になります。 7つの段階が必要です。 位置 (1) にある元の左側の境界を使用して答えを計算する不注意な実装では、クエリで明示的に高さ (2) がゼロにリセットされているにもかかわらず、誤って高さ (2) が含まれる可能性があります。 

3 番目のケースは、負の差異が寄与してはいけない理由を示しています。```
1
3 1
5 2 4
2 1 3
```答えは(7)です。 最初の超高層ビルを建設するには 5 つのステージが必要で、次に 3 番目の超高層ビルをカバーする 2 つの追加ステージが必要です。 (5) から (2) への低下には新たな段階は必要ありません。 すべての差の絶対値を使用する式では、(3) が誤って加算されてしまいます。 

最後に、範囲の加算により、隣接する差分の符号が変更される可能性があります。 例えば、```
1
3 2
1 1 1
1 1 2 5
2 1 3
```更新後の目標は ([6,6,1]) で、答えは (6) です。 差分列は ([1,0,0]) から ([6,0,-5]) に変わります。 元の正の差分のみを保存し、差分が変化したときに古い寄与を削除しないデータ構造では、間違った結果が返されます。 

## アプローチ

 直接的な解決策では、レベルごとに建設をシミュレートできます。 固定ターゲット プロファイルの場合、各ステージで一定の間隔をカバーでき、有用な間隔を繰り返し見つけてそれを増やすことができます。 これは概念的には正しいです。なぜなら、各ステージが連続する超高層ビルのセットに 1 単位の高さを与え、許可された操作と正確に一致するからです。 ただし、それぞれの高さが (10^5) の (10^5) 個の超高層ビルを持つターゲットには、(10^{10}) ものステージが必要になる場合があります。 各ステージで配列全体を処理する実装でも、(10^{15}) 個程度の基本演算が必要になります。 

最小ステージ数を特徴付けるもっと簡単な方法があります。 ターゲットの高さを左から右にスキャンすることを想像してください。 現在の高さが以前の高さよりも大きい場合、その増加はここから開始する必要がある新しい間隔を表します。 以前に開始された間隔は減少する前に単純に終了する可能性があるため、減少には新たに何も必要ありません。 

クエリされた間隔の直前にゼロの高さを導入します。 プロファイル (b_1,b_2,\ldots,b_s) の場合、最小ステージ数は次のとおりです。 

[
 b_1+\sum_{i=2}^{s}\max(0,b_i-b_{i-1})。 
】

 たとえば、([1,3,1,4,5]) の場合、必要な数は次のとおりです。 

[
 1+(3-1)+(4-1)+(5-4)=7。 
】

 この特徴は、インターバル層から直接理解することもできます。 各ステージは、高さプロファイル内の 1 つの水平単位セグメントに対応します。 プロファイルが (x) 上がるたびに、少なくとも (x) 個の新しいセグメントを開始する必要があります。 これが低下すると、既存のセグメントが終了する可能性があります。 したがって、ステージの合計数は、すべての正の上昇の合計となります。 

ブルート フォース スキャンは、これらの正の上昇を正確に計算するため機能しますが、同じ間隔で多くのクエリがスキャンされると失敗します。 重要な観察は、差分配列を通じて正の上昇発現を維持できるということです。 

定義する

 [
 d_i=a_i-a_{i-1}、
 】

 (a_0=0) となります。 クエリ ([l,r]) の場合、(l) より前はすべてゼロにリセットされるため、最初の有効な高さは (a_l) になります。 その後の正の上昇はすべて、正の差 (d_i) で表されます。 その結果、

 a_l+\sum_{i=l+1}^{r}\max(0,d_i)。 
】

 最初の項 (a_l) 自体が接頭辞の合計です

 [
 a_l=\sum_{i=1}^{l}d_i。 
】

 したがって、クエリに必要なのは 2 つの範囲合計だけです。(l) までのすべての差のプレフィックス合計と、(l+1) から (r) までの正の差の合計です。 

ここで、範囲加算が差分配列にどのような影響を与えるかを考えてみましょう。 (l\le i\le r) のすべての (a_i) に (k) を追加すると、厳密には区間内のすべての差は変更されません。 変更できる境界は次の 2 つだけです。 

[
 d_l\マスレル{+}=k、
 】

 そして (r<n) の場合、

 [
 d_{r+1}\mathrel{-}=k。 
】

 したがって、元の配列に対する範囲の加算は、差分配列では最大 2 点の更新になります。 

フェンウィックの木を2本維持できます。 1 つ目は (d_i) ごとに保存し、差分配列のプレフィックス合計を取得できるようにします。 2 番目は (\max(0,d_i)) を格納し、正の差のみを合計できるようにします。 いずれか (d_i) が変更されると、それに応じて両方のフェンウィック ツリーが更新されます。 

これにより、すべての操作が (O(\log n)) に削減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(nm)) スキャンクエリ間隔 | (O(n)) | 遅すぎる |
 | 最適 | (O((n+m)\log n)) テスト ケースごと | (O(n)) | 承認済み |

 ## アルゴリズムのチュートリアル

1. (i>1) に対して (d_1=a_1) および (d_i=a_i-a_{i-1}) を設定して、現在の高さから差分配列 (d) を構築します。 範囲の追加では 2 つの端点の差分のみが変更されるため、この表現は便利です。 
2. (d_i) を含む 1 つのフェンウィック ツリーと、(\max(0,d_i)) を含むもう 1 つのフェンウィック ツリーを構築します。 最初のツリーは差の接頭辞の合計を返しますが、2 番目のツリーは正の差の合計を返します。 
3. 更新 (1\ l\ r\ k) の場合、(d_l) を (k) だけ増加します。 (r<n) の場合、(d_{r+1}) を (k) だけ減らします。 変更された位置ごとに両方のフェンウィック ツリーを更新します。 すべての内部境界の両側に同じ (k) が追加されるため、他の違いは変わりません。 
4. クエリ (2\ l\ r) の場合、最初のフェンウィック ツリーから (l) を介したプレフィックスの合計として (a_l) を取得します。 これは、違いが拡大するため機能します。 

[
 d_1+d_2+\cdots+d_l=a_l。 
】

 1. ([l+1,r]) の正の差について 2 番目のフェンウィック ツリーをクエリします。 この値を (a_l) に加算します。 結果として得られる式は、

 [
 a_l+\sum_{i=l+1}^{r}\max(0,d_i),
 】

 これはまさに最小の構築段階数です。 

1. すべてのタイプ 2 イベントの結果を出力します。 すべての操作は元の順序で処理されるため、維持される差分配列は常に現在のターゲットの高さを表します。 

### なぜ効果があるのか

 不変条件は、最初のフェンウィック ツリーが現在の差分配列を正確に保存し、2 番目のフェンウィック ツリーが現在の各差分の正の部分を正確に保存することです。 クエリされた任意の間隔について、建設コストは、最初の高さとその後のすべての正の増加によって決定されます。 最初の高さは、位置 (1) から (l) までの差を伸縮することによって回復され、その後の増加はすべて、対応する正の差によって表されます。 範囲の追加では (d_l) と (d_{r+1}) のみが変更されるため、2 つのフェンウィック ツリーは更新のたびに正しいままになります。 したがって、すべてのクエリは正確な最小ステージ数を返します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    __slots__ = ("n", "bit")

    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, delta):
        n = self.n
        bit = self.bit
        while i <= n:
            bit[i] += delta
            i += i & -i

    def sum(self, i):
        bit = self.bit
        res = 0
        while i > 0:
            res += bit[i]
            i -= i & -i
        return res

    def range_sum(self, l, r):
        if l > r:
            return 0
        return self.sum(r) - self.sum(l - 1)

def solve():
    input = sys.stdin.readline
    T = int(input())
    out = []

    for _ in range(T):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))

        diff = [0] * (n + 1)

        prev = 0
        for i in range(1, n + 1):
            cur = a[i - 1]
            diff[i] = cur - prev
            prev = cur

        bit_diff = Fenwick(n)
        bit_pos = Fenwick(n)

        for i in range(1, n + 1):
            d = diff[i]
            bit_diff.add(i, d)
            if d > 0:
                bit_pos.add(i, d)

        for _ in range(m):
            query = list(map(int, input().split()))

            if query[0] == 1:
                _, l, r, k = query

                old = diff[l]
                new = old + k
                diff[l] = new

                bit_diff.add(l, k)

                old_pos = old if old > 0 else 0
                new_pos = new if new > 0 else 0
                bit_pos.add(l, new_pos - old_pos)

                if r < n:
                    pos = r + 1

                    old = diff[pos]
                    new = old - k
                    diff[pos] = new

                    bit_diff.add(pos, -k)

                    old_pos = old if old > 0 else 0
                    new_pos = new if new > 0 else 0
                    bit_pos.add(pos, new_pos - old_pos)

            else:
                _, l, r = query

                first_height = bit_diff.sum(l)
                positive_rises = bit_pos.range_sum(l + 1, r)

                out.append(str(first_height + positive_rises))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```の`Fenwick`クラスは、標準のポイント更新、プレフィックスサムのデータ構造を実装します。 その`add`操作により (O(\log n)) に格納されている 1 つの値が変更され、`sum`(O(\log n)) のプレフィックス合計を取得します。 

の`diff`配列では 1 から始まるインデックスが使用されます。`diff[i]`は常に現在の値 (a_i-a_{i-1}) であり、暗黙的 (a_0=0) です。 更新では、プラスの寄与を正しく調整するために、変更された差分の古い値が必要になるため、この配列を明示的に保持することが必要です。 

初期化中に、`bit_diff`あらゆる違いを受け入れますが、`bit_pos`正の差分のみを受け取ります。 負の差分とゼロの差分は、2 番目のツリーに何も寄与しません。 

更新の場合は、位置`l`によって変化します`+k`。 もし`r < n`、 位置`r + 1`によって変化します`-k`。 更新間隔が配列の終わりに達すると (d_{n+1}) が存在しないため、この条件が必要です。 

ポジティブなフェンウィックの木には特別な注意が必要です。 差が次から変化すると仮定します。`-3`に`2`。 最初の木が受け取ります`+5`、一方、2 番目のツリーは受信する必要があります`+2`、 ない`+5`。 逆に、差が次から変化した場合、`4`に`-1`、2番目の木は負けなければなりません`4`。 コンピューティング`max(0, new) - max(0, old)`特別な場合を除いて 4 つの符号遷移すべてを処理します。 

クエリの場合は、`bit_diff.sum(l)`(l) までのターゲットの高さの合計ではなく、(a_l) を与えます。 この区別が中心です。 ツリーには差分が格納されているため、プレフィックスの合計は位置 (l) の単一の高さに伸縮します。 次に、2 番目のツリーが (l) の後に正の立ち上がりを供給します。 

Python の整数はオーバーフローしないため、潜在的に大きな累積高さに特別な整数型は必要ありません。 Fenwick メソッド内でローカル参照を使用すると、入力の合計 (10^6) スケールに対して実装の効率性も維持されます。 

## 実用的な例

 公式サンプルは、```
1
5 4
1 3 1 4 5
2 1 5
1 3 4 2
2 2 4
2 1 5
```初期の差分配列は ([1,2,-2,3,1]) です。 

| 操作 | 現在の高さ | 差分配列 | 最初の高さ | プラスの上昇 | 答え |
 | --- | --- | --- | --- | --- | --- |
 | イニシャル | [1、3、1、4、5] | [1、2、-2、3、1] | 1 | 6 | 7 |
 |`2 1 5`| [1、3、1、4、5] | [1、2、-2、3、1] | 1 | 6 | 7 |
 |`1 3 4 2`| [1、3、3、6、5] | [1、2、0、3、-1] | 1 | 5 | フルレンジの場合は 6 |
 |`2 2 4`| [1、3、3、6、5] | [1、2、0、3、-1] | 3 | 3 | 6 |
 |`2 1 5`| [1、3、3、6、5] | [1、2、0、3、-1] | 1 | 5 | 6 |

 最初のクエリでは (1+2+3+1=7) が得られます。 更新後、変更された差異は、(2) 増加する (d_3) と (2) 減少する (d_5) だけです。 結果のプロファイルは ([1,3,3,6,5]) です。 クエリ ([2,4]) の場合、有効なプロファイルは ([0,3,3,6,0]) で、(3+0+3=6) となります。 最後の全範囲クエリは (1+2+3=6) です。 

2 番目の例では、低下したプロファイルを分離します。```
1
3 1
5 2 4
2 1 3
```| ポジション | 高さ | 違い | プラスの貢献 |
 | --- | --- | --- | --- |
 | 1 | 5 | 5 | 5 |
 | 2 | 2 | -3 | 0 |
 | 3 | 4 | 2 | 2 |

 クエリの答えは (5+0+2=7) です。 目標高さが低下すると建設間隔が終了する可能性があるため、位置 (2) の負の差は無視されます。 位置 (3) の正の差によって表される 2 つの追加ステージは、そこから開始し、3 番目の超高層ビルのみをカバーできます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O((n+m)\log n)) | Fenwick ツリーの構築には (O(n\log n)) かかり、すべての更新またはクエリには (O(\log n)) の Fenwick 操作が使用されます。 
| スペース | (O(n)) | 差分配列と 2 つのフェンウィック ツリーはそれぞれ線形空間を使用します。 

すべてのテスト ケースの合計 (n) と合計 (m) は最大でも (10^6) であるため、全体の実行時間は小さな定数係数までは (O(10^6\log 10^5)) となります。 これにより、クエリ間隔をスキャンする潜在的な (10^{10}) 作業が置き換えられ、意図された制限に適合します。 

## テストケース```python
import sys
import io

def solve():
    input = sys.stdin.readline
    T = int(input())
    out = []

    class Fenwick:
        __slots__ = ("n", "bit")

        def __init__(self, n):
            self.n = n
            self.bit = [0] * (n + 1)

        def add(self, i, delta):
            while i <= self.n:
                self.bit[i] += delta
                i += i & -i

        def sum(self, i):
            res = 0
            while i > 0:
                res += self.bit[i]
                i -= i & -i
            return res

        def range_sum(self, l, r):
            if l > r:
                return 0
            return self.sum(r) - self.sum(l - 1)

    for _ in range(T):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))

        diff = [0] * (n + 1)
        prev = 0

        for i in range(1, n + 1):
            diff[i] = a[i - 1] - prev
            prev = a[i - 1]

        bit_diff = Fenwick(n)
        bit_pos = Fenwick(n)

        for i in range(1, n + 1):
            d = diff[i]
            bit_diff.add(i, d)
            if d > 0:
                bit_pos.add(i, d)

        for _ in range(m):
            q = list(map(int, input().split()))

            if q[0] == 1:
                _, l, r, k = q

                old = diff[l]
                new = old + k
                diff[l] = new
                bit_diff.add(l, k)
                bit_pos.add(
                    l,
                    (new if new > 0 else 0) -
                    (old if old > 0 else 0)
                )

                if r < n:
                    p = r + 1
                    old = diff[p]
                    new = old - k
                    diff[p] = new
                    bit_diff.add(p, -k)
                    bit_pos.add(
                        p,
                        (new if new > 0 else 0) -
                        (old if old > 0 else 0)
                    )
            else:
                _, l, r = q
                answer = bit_diff.sum(l) + bit_pos.range_sum(l + 1, r)
                out.append(str(answer))

    sys.stdout.write("\n".join(out))

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_input = globals()["input"]

    sys.stdin = io.StringIO(inp)
    globals()["input"] = sys.stdin.readline

    try:
        solve()
        # solve writes directly to stdout, so this helper is replaced below.
    finally:
        sys.stdin = old_stdin
        globals()["input"] = old_input

def run_capture(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout
    old_input = globals()["input"]

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()
    globals()["input"] = sys.stdin.readline

    try:
        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin

 ## 特殊なケース

 単一の超高層ビルの場合、たとえば```
1
1 1
5
2 1 1
```差分配列は単純に ([5]) です。 クエリは計算します`bit_diff.sum(1)=5`そして、ゼロに寄与する空の範囲 ([2,1]) 内の正の差を求めます。 結果は(5)です。 これは、隣接するペアがまったくない場合を直接処理します。 

途中で始まるクエリについては、次のことを考慮してください。```
1
3 1
2 7 3
2 2 2
```完全な差分配列は ([2,5,-4]) です。 クエリは最初に位置 (2) の高さ (2+5=7) を取得します。 (l=r=2) であるため、正の上昇範囲は空です。 答えは(7)です。 位置 (1) の元の高さは、クエリによってその位置がゼロにリセットされるため、構造に入力されることはありません。 

降順ペアの場合、次のことを考慮します。```
1
3 1
5 2 4
2 1 3
```違いは ([5,-3,2]) です。 最初のフェンウィック ツリーは位置 (1) で (5) を報告しますが、正の差分ツリーは位置 (2) から (3) までの (2) のみを報告します。 結果は(7)です。 負の値 (-3) は、正のツリーには意図的に欠如しており、下降するプロファイルには新しい構築段階が必要ないという事実と一致しています。 

適切なエンドポイントに関わる更新については、次のことを考慮してください。```
1
3 2
1 1 1
1 1 3 5
2 1 3
```更新は配列全体をカバーするため、(d_1) のみが変更されます。 更新された範囲は (n) で終了するため、変更する (d_4) はありません。 差分配列は ([6,0,0]) となり、クエリは (6) を返します。 位置 (r+1) を無条件に更新しようとすると、無効な余分な境界が作成され、一般的な off-by-one エラーとなります。 

ゼロをまたぐ差については、次のように考えます。```
1
3 2
1 5 5
1 2 2 5
2 1 3
```最初の差分は ([1,4,0​​]) です。 (2) の位置に (5) を追加すると、([1,9,-5]) に変更されます。 位置 (2) での差が (4) から (9) に変化するため、正のツリーは (5) を獲得します。 位置 (3) での新しい負の差は何も寄与しません。 答えは(1+9=10)です。 これは、各点の更新で、符号が変化しないと仮定するのではなく、生の差とその正の部分の両方を調整する必要がある理由を示しています。
