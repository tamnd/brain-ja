 ## 解決策
 ## 問題の理解

 1 から n までのラベルが付けられたピザのセットが与えられます。ここで、各ラベルはその半径でもあります。 すべてのピザを単一の垂直スタックに配置する必要があります。これは、1 から n までの数字の順列を選択するのと同じです。 

スタック内の 2 つのピザについて、物理的に下にあるピザとその上にあるピザを考慮します。 下のピザの半径が上のピザよりも大きい場合、そのペアは、この問題でいうところの「適切なペア」に寄与します。 順列言語では、これはまさに反転です。つまり、i の値が j の値より大きくなるような、i < j のインデックスのペアです。 

したがって、タスクは、ちょうど k 個の反転を含むサイズ n の順列がいくつあるかを数えるようになります。 

n ≤ 1000 および k ≤ 1000 という制約は、階乗空間または指数空間で直接作業を行っていないことを直ちに示唆します。 すべての順列に対する単純な列挙には n! が含まれます。 可能性はありますが、n = 12 または 13 あたりではすでに不可能になります。n = 100 でさえも到達をはるかに超えています。 これにより、要素を徐々に挿入し、形成される反転の数を追跡することで順列をカウントする動的プログラミング アプローチが推進されます。 

エッジケースのほとんどは、実装のバグではなく構造的なものです。 k = 0 の場合、増加順列のみが機能します。 k が最大である k = n(n − 1)/2 の場合、減少する順列のみが機能します。 どのような解決策でも、たとえ k ≤ 1000 が DP 状態空間の上限であるとしても、k < n や k が n に比べて小さいなどの仮定に依存せずに、これらの極端な値を正しく処理する必要があります。 

微妙なケースは、n が大きいが k が小さい場合です。 たとえば、n = 1000 および k = 1 の場合でも、すでに固定されている多数の相対位置の中でちょうど 1 つの要素を順番どおりに配置することによって単一の反転をどのように作成できるかを推論する必要があります。 これは、DP 構造が慎重に定義されていない限り、単純な組み合わせ論が失敗する傾向がある場所です。 

## アプローチ

 ブルートフォース手法では、1 から n までのすべての順列が生成され、それぞれの反転がカウントされます。 順列ごとの逆変換の計算には O(n^2) がかかり、n 個あります。 したがって、総作業量は O(n! · n^2) となり、すぐに実行不可能になります。 

順列を段階的に構築する構造が必要です。 重要な点は、ラベルの昇順に番号を 1 つずつ挿入することを考えることです。 数値 1 から i − 1 までの有効な配列がすでに構築されているとします。数値 i を挿入するときは、既存の i − 1 要素内の任意の位置に配置できます。 これを左から位置 t に挿入すると、多くの小さな要素の前に配置されるため、正確に i − 1 − t 個の新しい反転が作成されます。 

これにより、きれいな反復が得られます。各挿入は、その位置にのみ応じて、制御可能な数の新しい反転に寄与します。 この独立性により、動的プログラミングが可能になります。 

dp[i][j] を、正確に j 回の反転を持つ最初の i 個の数値の順列の数として定義します。 各 i について、サイズ i − 1 の順列への i のすべての可能な挿入位置を試し、反転寄与を蓄積します。 

直接遷移では、各状態に対して O(i) 個の位置を試行するため、合計時間は O(n^3) になります。 ただし、前の dp 行のプレフィックス合計を使用して最適化できます。 これにより、内部遷移が O(1) に変わり、完全な解が O(nk) に減ります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n! · n^2) | O(n) | 遅すぎる |
 | プレフィックス合計を含む DP | O(nk) | O(nk) | 承認済み |

 ## アルゴリズムのチュートリアル

 dp[i][j] が正確に j 回の反転を含む {1..i} の順列をカウントするテーブル dp を構築します。

1. dp[1][0] = 1 を初期化します。単一の要素には、順列が 1 つと反転が 0 つだけ含まれます。 これにより構造が固定されます。 
2. 2 から n までの各 i について、dp[i − 1] から dp[i] を計算します。 この段階では、小さいセットのすべてのカウントがすでに正しいと仮定します。 
3. 固定 i の場合、要素 i をサイズ i − 1 の順列の可能なすべての位置に挿入することを検討します。要素 i を位置 p (0 からインデックス付き) に挿入すると、(i − 1 − p) の反転に寄与します。 
4. これを漸化式に変換します。 dp[i][j] は、0 から i − 1 までのすべての t にわたる dp[i − 1][j − t] の合計に等しくなります。ここで、 t は i を挿入することによって導入される反転の数です。 これは、dp[i − 1] にわたるスライディング ウィンドウの合計です。 
5. dp[i − 1] のプレフィックス合計を使用して dp[i][j] を効率的に計算します。 各 j について、dp[i − 1] の最後の i 値にわたる実行ウィンドウの合計を維持します。 
6. より大きな値は答えに無関係であるため、j から k までのみを考慮するようにしてください。 

これが機能する主な理由は、最大の要素 i を挿入しても 1..i − 1 間の相対的な順序が乱されないため、すべての反転構造はその配置によってのみ得られるためです。 サイズ i のすべての順列は、サイズ i − 1 の順列内の 1 つの位置に i を挿入することによって一意に形成されるため、DP は重複することなくすべての状態をカバーします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

n, k = map(int, input().split())

dp = [[0] * (k + 1) for _ in range(n + 1)]
dp[1][0] = 1

for i in range(2, n + 1):
    window_sum = 0
    for j in range(0, k + 1):
        window_sum += dp[i - 1][j]
        if j - i >= 0:
            window_sum -= dp[i - 1][j - i]
        dp[i][j] = window_sum % MOD

print(dp[n][k] % MOD)
```このコードは DP を行ごとに構築します。 の`window_sum`は、現在の数値 i の i 個の可能な挿入位置に正確に対応する、前の行に対するサイズ i のスライディング ウィンドウを維持します。 各 dp[i][j] は、dp[i − 1][j]、dp[i − 1][j − 1]、...、dp[i − 1][j − (i − 1)] からの寄与を蓄積します。 

よくある落とし穴は、ウィンドウ サイズが i とともに大きくなるということを忘れていることです。 もう 1 つの微妙な問題は、 j − i が負になった場合の境界処理です。これは配列にインデックスを付けてはなりません。 オーバーフローを防ぐために、状態が更新されるたびにモジュロが適用されます。 

## 実用的な例

 ### 例 1: n = 3、k = 0

 dp を行ごとに計算します。 

| 私 | j | window_sum ソース | dp[i][j] |
 | --- | --- | --- | --- |
 | 1 | 0 | ベース | 1 |
 | 2 | 0 | dp[1][0] | 1 |
 | 2 | 1 | dp[1][0] (シフト) | 1 |
 | 3 | 0 | dp[2][0] | 1 |

 n = 3 の場合、増加順列 1 2 3 のみが反転を持ちません。 どのスワップでも少なくとも 1 つの反転が生じるため、答えは 1 になります。 

### 例 2: n = 3、k = 1

 | 私 | j | 貢献 | dp[i][j] |
 | --- | --- | --- | --- |
 | 1 | 0 | ベース | 1 |
 | 2 | 1 | 1 の前に 2 を挿入 | 1 |
 | 3 | 1 | dp[2][1] + dp[2][0] から | 2 |

 n = 3 および k = 1 の場合、有効な順列は 1 3 2 および 2 1 3 です。それぞれは、単一のローカル スワップによって形成される 1 つの反転に正確に対応します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(nk) | 各 dp 行は、k 状態にわたる単一のスライディング ウィンドウを使用して計算されます。 
| スペース | O(nk) | サイズ n × k の完全な DP テーブル |

 n、k ≤ 1000 の場合、解は約 10^6 の遷移を実行しますが、これは問題なく制限内に収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import comb

    MOD = 10**9 + 7

    n, k = map(int, inp.split())
    dp = [[0] * (k + 1) for _ in range(n + 1)]
    dp[1][0] = 1

    for i in range(2, n + 1):
        window_sum = 0
        for j in range(k + 1):
            window_sum += dp[i - 1][j]
            if j - i >= 0:
                window_sum -= dp[i - 1][j - i]
            dp[i][j] = window_sum % MOD

    return str(dp[n][k] % MOD)

# provided samples
assert run("3 0") == "1"
assert run("3 1") == "2"

# custom cases
assert run("1 0") == "1"
assert run("4 0") == "1"
assert run("4 6") == "1"
assert run("5 1") == "4"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 0 | 1 | 基本ケースの単一要素 |
 | 4 0 | 1 | ソートされた順列のみ |
 | 4 6 | 1 | 完全に逆の順列 |
 | 5 1 | 4 | 単一反転配置 |

 ## 特殊なケース

 n = 1 および k = 0 の場合、DP は dp[1][0] = 1 を初期化し、すぐにそれを返します。 移行ステップがないため、dp[0] や無効なインデックスにアクセスするリスクはありません。 

n = 4 および k = 0 の場合、より高い反転カウントはすべて無関係であるため、スライディング ウィンドウは dp[i][0] を超えて正の寄与を蓄積することはありません。 最大の要素を最後に挿入すると反転がゼロになり、他のすべての挿入は k 境界によって除外されるため、アルゴリズムはすべてのレベルで dp[i][0] = 1 を維持します。 

n = 4 および k = 6 (4 要素の最大反転カウント) の場合、DP は完全に反転した順列のみを正しくカウントします。 スライディング ウィンドウは、各順列の開始時に連続して強制的に配置されることにより、正確に 1 つの有効な構築パスを自然に蓄積します。
