 ## 解決策
 ## 問題の理解

 私たちには一連の生徒が与えられ、それぞれが決まった順序で一定数のピザのスライスを要求します。 同一のピザが K 枚あり、各ピザには同じ未知の容量 S 枚のスライスがあります。 生徒は 1 人ずつ提供されます。現在のピザに次の生徒のリクエストに十分な量がまだ残っている場合は、その生徒にそのピザが提供されます。 そうでなければ、そのピザの残りのスライスは捨てられ、新しいピザが開かれ、生徒には新しいピザが提供されます。 

重要な問題は、提供がどのように進むかということではなく、最大で K 個のピザが利用可能であると仮定した場合、ピザを切らさずにこのプロセスを完了できるようにするには、S がどのくらいの大きさでなければならないかということです。 

したがって、タスクは、この貪欲な提供プロセスをシミュレートするときに、K 個を超えるピザが必要とならないように、最小の整数 S を選択することです。 

入力サイズでは、最大 100,000 人の学生と最大 100,000 個のピザが許可されます。 これにより、各候補のプロセスをシミュレートすることによって S のすべての可能な値をチェックしようとするソリューションは即座に除外されます。 S の単純な上限はすべての要求の合計であり、最大 10^11 になる可能性があるため、S に対する線形探索は完全に不可能になります。 

問題を単調な実現可能性チェックに還元する解決策が必要です。 

いくつかの微妙なケースが重要です。 

1 人の生徒が非常に多数のスライス (たとえば d_i = 10^6) を要求した場合、S は少なくともその大きさでなければなりません。 そうしないと、アルゴリズムが 1 人の生徒のためにピザを繰り返し開くことになります。これは許可されていますが、容量を無駄にします。 さらに重要なことは、正確さの条件はまだ保持されていますが、S が小さい場合には実現可能性が不可能になります。 

K が N に比べて大きい場合、別のエッジ ケースが現れます。たとえば、K ≥ N の場合、S = max(d_i) であっても常に機能します。これは、原則として各生徒が新しいピザを始めることができるためです。 これは応答構造を変更しませんが、エッジ処理の正確性を確認するのに役立ちます。 

最後に、主な微妙な点は、新しいピザを開けるときに、残ったスライスが常に破棄されることです。 これは、シーケンスを効果的にセグメントに分割していることを意味します。各セグメントの総和は最大でも S ですが、セグメントは最適なパッキングではなくオーバーフローによって強制されます。 この強制的な貪欲な構造が解決策を推進します。 

## アプローチ

 直接的な総当たりアプローチでは、候補値 S を試し、提供プロセスをシミュレートします。つまり、現在のピザの残りのスライスを維持し、生徒に提供するときにそれを減らし、新しいピザを開く必要がある回数を数えます。 K を超えると、S は無効になります。 

このシミュレーションは固定 S に対して正確であり、コストは O(N) 時間です。 ただし、S 自体はすべての要求の合計と同じくらい大きくなる可能性があります。 max(d_i) 以降のすべての値を試すには、最大 10^11 のチェックが必要になりますが、これは不可能です。 

重要な観察は、実現可能性は S において単調であるということです。与えられた S が K 個のピザ内ですべての生徒にサービスを提供するのに十分な場合、さらに大きな S でも十分です。これは、容量を増やすとピザの開口部の数を減らすか維持することしかできないためです。 これにより、問題は S に対する二分探索に変わります。 

それぞれの実現可能性チェックは貪欲なスキャンです。プロセスをシミュレートし、使用されたピザの数をカウントします。 任意の時点で 1 つの要求が S を超えると、S が無効であることがすぐにわかります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース S の列挙 | O(N * 合計 d_i) | お(1) | 遅すぎる |
 | 二分探索 + シミュレーション | O(N log max d_i) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 最大で K 枚のピザを使用してすべての生徒に提供できる最小の S を探します。

1. S の探索範囲を max(d_i) から sum(d_i) までに設定します。 どの生徒も 1 つのピザ セグメントに収まらなければならないため、下限が必要です。 
2. ピザ容量 S で生徒にサービスを提供することをシミュレートする関数 can(S) を定義します。pizzas_used = 1 および Remaining = S を初期化します。 
3. 各需要 d_i について、現在の残り容量に適合するかどうかを確認します。 残りが d_i 以上の場合は、残りから d_i を減算して続行します。 
4. 残り < d_i の場合、pizzas_used を 1 だけ増分し、残りを S にリセットしてから、d_i を減算します。 これは、残ったスライスを破棄し、新しいピザを開くことをモデル化しています。 
5. いずれかの時点で、pizzas_used が K を超えた場合は、S が不十分であるため、すぐに False を返します。 
6. S の二分探索。can(S) が true の場合は、より小さい値を試します。 それ以外の場合は、S を増やします。 

重要な設計上の選択は、学生のグループ化方法を決して最適化しようとしないことです。 このプロセスは強制的なものであるため、貪欲なシミュレーションが唯一有効な解釈です。 

### なぜ効果があるのか

 固定 S の場合、残りの容量不足によって強制的に新しいピザが開かれるだけであるため、シミュレーションでは可能な限り最小限の数のピザが生成されます。 ピザをより早くオープンする代替戦略は、使用量を増やすだけです。 したがって、実現可能性を正しく反映できます。 

単調性により、有効な S 値のセットが整数のサフィックスを形成することが保証され、バイナリ検索の正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can(d, n, k, s):
    pizzas_used = 1
    remaining = s

    for x in d:
        if x > s:
            return False
        if remaining >= x:
            remaining -= x
        else:
            pizzas_used += 1
            if pizzas_used > k:
                return False
            remaining = s - x

    return pizzas_used <= k

def solve():
    n, k = map(int, input().split())
    d = list(map(int, input().split()))

    lo = max(d)
    hi = sum(d)

    while lo < hi:
        mid = (lo + hi) // 2
        if can(d, n, k, mid):
            hi = mid
        else:
            lo = mid + 1

    print(lo)

if __name__ == "__main__":
    solve()
```このコードは、明確さと正確さを保つために不可欠な二分探索から実現可能性チェックを分離します。 この関数は、強制オープン ルールを慎重に適用できます。残りの容量が不十分な場合は、すぐに新しいピザを開いてカウンターをリセットします。 

微妙な点の 1 つは、lo を max(d) として初期化することです。 これにより、無効な S 値に対する不必要なチェックが回避され、シミュレーションでピザが保持できる以上のスライスを生徒に割り当てようとすることがなくなります。 

各ステップが単調な実現可能性に基づいて区間 [lo, hi) を縮小するため、二分探索は収束します。 

## 実用的な例

 要求が [5, 2, 7, 3] で K = 2 である入力を考えてみましょう。 

候補 S = 7 をテストします。 

| 学生 | 需要 | 前に残っている | アクション | 使用したピザ |
 | --- | --- | --- | --- | --- |
 | 1 | 5 | 7 | サーブ、残り = 2 | 1 |
 | 2 | 2 | 2 | サーブ、残り = 0 | 1 |
 | 3 | 7 | 0 | 新しいピザを開く | 2 |
 | 3 (続き) | 7 | 7 | サーブ、残り = 0 | 2 |
 | 4 | 3 | 0 | 新しいピザを開く | 3 |

 K = 2 を超えているため、S = 7 は無効です。 これは、すべての需要が個別に適合しているにもかかわらず、断片化により余分なピザが必要になることを示しています。 

ここで S = 10 をテストします。 

| 学生 | 需要 | 前に残っている | アクション | 使用したピザ |
 | --- | --- | --- | --- | --- |
 | 1 | 5 | 10 | サーブ | 1 |
 | 2 | 2 | 5 | サーブ | 1 |
 | 3 | 7 | 3 | 新しいピザを開けて提供する | 2 |
 | 4 | 3 | 3 | サーブ | 2 |

 ちょうど 2 枚のピザを使用するため、S = 10 が実現可能です。 これは、S を増やすと強制ブレークポイントでの断片化がどのように減少するかを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N log M) | 各実現可能性チェックではすべての生徒を 1 回スキャンし、S に対する二分探索が対数範囲で実行されます。 M = sum(d_i) |
 | スペース | お(1) | カウンタと入力配列のみが保存されます。 

N ≤ 10^5 という制約により線形スキャンが許容可能になり、log M は一般的な範囲で最大でも約 40 となり、解は十分に制限内に保たれます。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    def can(d, n, k, s):
        pizzas_used = 1
        remaining = s
        for x in d:
            if x > s:
                return False
            if remaining >= x:
                remaining -= x
            else:
                pizzas_used += 1
                if pizzas_used > k:
                    return False
                remaining = s - x
        return pizzas_used <= k

    def solve():
        n, k = map(int, input().split())
        d = list(map(int, input().split()))
        lo, hi = max(d), sum(d)
        while lo < hi:
            mid = (lo + hi) // 2
            if can(d, n, k, mid):
                hi = mid
            else:
                lo = mid + 1
        print(lo)

    solve()
    return sys.stdout.getvalue().strip()

# provided sample
assert run("5 3\n2 10 3 6 7\n") == "10"

# minimum case
assert run("1 1\n5\n") == "5"

# all equal small
assert run("4 2\n2 2 2 2\n") == "4"

# tight fragmentation
assert run("3 2\n5 5 5\n") == "10"

# large K (each student separate allowed)
assert run("3 3\n8 1 1\n") == "8"

 | 1 1/5 | 5 | 一人の生徒のベースライン |
 | 4 2 / 2 2 2 2 | 4 | 均等分布 |

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、単一の要求が現在の候補 S を超える場合です。たとえば、d = [10, 1, 1] および S = 5 です。実行可能なセグメンテーションが存在しないため、アルゴリズムはそれ以上のシミュレーションを行わずに S を即座に拒否します。 これにより、無駄な計算が防止され、二分探索範囲の正確さが維持されます。 

もう 1 つのケースは、K ≥ N など、K が非常に大きい場合です。d = [3, 4, 2]、K = 10 では、最適な S は max(d) = 4 になります。シミュレーションでは、残りの容量を超える需要によって強制されない限り、2 番目のピザが開くことはありません。また、それぞれの需要が適合するため、簡単に K 内に留まります。 

最後のケースは重度の断片化です: d = [6, 6, 6]、K = 2。S = 6 の場合、すべての生徒は新しいピザを強制し、3 枚のピザが必要になりますが、失敗します。 S = 12 の場合、最初の 2 人の生徒は 1 つのピザに収まり、最後の生徒は 2 番目の生徒を強制して K 内に留まります。これは、S が単なる局所的な実現可能性ではなくセグメンテーションをどのように制御するかを示しています。
