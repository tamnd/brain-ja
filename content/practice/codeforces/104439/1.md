 ## 解決策
 ## 問題の理解

 3 つの長さが与えられています。 そのうちの 2 つは、建設に使用される丸太の長さを記述しています。1 つのタイプの丸太には長さがあります。`a`もう1つは長さがあります`b`、 と`a < b`。 3番目の数字`c`切断する必要がある単一の木製梁の全長です。 

構築プロセスは、繰り返しのレイヤーで厳密に構造化されています。 1 つの層は 5 つのログで構成されます: 2 つの長いログ`b`3本の短い丸太`a`。 このような各層は、建物の高さを正確に 1 単位だけ増加させます。 レイヤーは交互のパターンで積み重ねられますが、この問題により、すべての完全なレイヤーが常に同じ組成を持つことが保証されます。 構造は、3 つの短い丸太の完全な層で最上部で終了する必要があります。これは、構造が整数の完全な層で構成されている必要があることを意味します。 

各丸太は、一定の長さの単一の梁から切断する必要があります。`c`、そしてカットは必要な部分の合計に正確に等しい長さを消費します。 層間の再利用や結合の残りがないため、唯一の制限は、必要なすべての丸太を切断するのに十分な全長が残っているかどうかです。 

タスクは、1 つのビームから構築できる完全なレイヤーの最大数を決定することです。 

制約は次のとおりです`10^18`これにより、個々のユニットにわたるシミュレーションや、単位長さごとの貪欲な切断が即座に除外されます。 正しい解決策は、算術関係のみに依存して、テスト ケースごとに一定時間または対数時間で機能する必要があります。 

微妙なエッジ ケースは、丸太の部分セットは完成できるものの、完全な層は完成しない残材が存在する場合です。 たとえば、残りの長さが 2 つの長いログには十分であるが、3 つの短いログには十分ではない場合、そのレイヤーは無効であるため、破棄する必要があります。 各層が一定の総材料量を消費することを考慮せずに、貪欲に交互に切断しようとすると、別の失敗例が発生します。 

## アプローチ

 単純なアプローチでは、レイヤーごとに建設をシミュレートします。 各層について、残りの長さから 2 つの長い丸太と 3 つの短い丸太のコストを差し引き、成功した場合は高さカウンターをインクリメントします。 レイヤーあたりのコストは固定です。`2b + 3a`。 これにより、各層が独立しており、コストが同一であるため、正確性が簡単になります。 

ただし、すべてのレイヤーがまったく同じ量のマテリアルを消費することを認識すれば、この単純なシミュレーションは不要になります。 定義すると`cost = 2b + 3a`の場合、レイヤーの最大数は単にこのコストが何倍に適合するかになります。`c`。 最上層が 3 つの短い丸太であるという最後の制約は、異なるコスト構造を導入するものではありません。 構成順序についてのみ説明しており、別の消費ルールについては説明しません。 

したがって、問題は整数の除算に帰着します。利用可能なビーム長に収まる 5 つのログの完全なグループがいくつあるかを計算します。 

重要な洞察は、レイヤー間に相互作用がなく、異なるタイプのログ間で再利用が残らないことです。 これを観察すると、問題は 1 つの除算演算に集約されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(c / (2b + 3a)) | お(1) | 遅すぎる |
 | ダイレクトフォーミュラ | お(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 3 つの整数を読み取ります`a`、`b`、 そして`c`。 これらは、短い丸太、長い丸太、および利用可能な材料の合計の固定サイズを表します。 
2. 1 つの完全なレイヤーを構築する総コストを次のように計算します。`cost = 2 * b + 3 * a`。 これは、単一の完全な構造ユニットの正確な材料消費量を反映しています。 
3. 整数除算によってこのような層が何層形成できるかを計算します。`height = c // cost`。 部分的なレイヤーは高さに寄与しないため、整数の除算が必要です。 
4. 出力`height`答えとして。 

### なぜ効果があるのか

 有効な各レイヤーの構成は同一で固定されており、レイヤー間でマテリアルを再配置したり部分的に再利用したりする柔軟性はありません。 これにより、ビームがサイズの異なるセグメントに厳密に分割されます。`2b + 3a`。 この量より少ない残りの材料は有効な層を形成できません。丸太が 1 本欠けていても構造要件を満たさないからです。 したがって、レイヤーの数は、サイズの完全なセグメントの数と正確に一致します。`cost`に適合する`c`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    a = int(input())
    b = int(input())
    c = int(input())
    
    cost = 2 * b + 3 * a
    print(c // cost)

if __name__ == "__main__":
    solve()
```このソリューションは 3 つの入力を直接読み取り、レイヤーごとのコストを計算します。 重要な演算は整数の除算です`c // cost`これにより、完全なレイヤーのみがカウントされるという要件が強制されます。 

すべてのレイヤーが独立しており、リソース消費量が同一であるため、ループやシミュレーションは必要ありません。 

## 実用的な例

 残りの 10 ユニットは、2 つの長い丸太と 3 つの短い丸太からなる別の完全なセットを形成するには不十分です。 答えは`1`。 

### サンプル 2

 入力:```

```私たちは計算します`cost = 2 * 2 + 3 * 1 = 4 + 3 = 7`。 

| ステップ | 残りの c | アクション | レイヤー |

 | 1 | 100 | ビルドレイヤー | 14 |

 以来`100 // 7 = 14`、14 個の完全なレイヤーが得られます。 

これにより、残りの材料が部分的な高さに寄与しないことが確認されます。

 ## 特殊なケース

 よくある失敗例は、残りの材料が完全な層に近いものの、完全な層には十分ではない場合です。 たとえば:

 入力:```
a = 1, b = 2, c = 6
```ここ`cost = 7`。 アルゴリズムは計算します`6 // 7 = 0`、部分構造を形成する可能性を正しく拒否します。 ログを個別に配置しようとする貪欲な実装では、2 つの長いログを誤って配置し、完全なレイヤーが不可能であることに気付かずに停止してしまう可能性があります。 

もう 1 つのエッジケースは次のような場合です`c`非常に大きい、近い`10^18`。 計算には乗算と整数の除算のみが使用されるため、Python はこれをオーバーフローせずにネイティブに処理しますが、固定幅整数言語では 64 ビットの算術演算を保証する必要があります。
