 ## 問題の理解

 から連続する整数のセグメントが与えられます。$A$に$B$、包括的。 2 人がこのセグメント内で異なるルールで数えています。1 人は、次の数で割り切れる数を数えます。$K$、もう 1 つは、次の数で割り切れる数を数えます。$M$。 ここでのタスクは、両方のカウントを出力することではなく、その差分、つまり次の値の倍数だけを出力することです。$K$マイナス何倍か$M$、間隔に制限されています$[A, B]$。 

重要な点は、数字を明示的に列挙しているわけではないということです。 範囲は非常に大きく、最大で$2 \cdot 10^9$したがって、すべての整数を直接スキャンすることは不可能です。 ループするすべてのソリューション$A$に$B$かかるだろう$O(B - A)$、最悪の場合、実行可能な限界をはるかに超えます。 

代わりに、問題は基本的に範囲内の倍数を数えることに関するものであり、これは閉じた形式の算術アプローチを示唆しています。 

微妙なエッジケースが現れるのは、$K = M$。 この場合、両方のカウントはどの間隔でも同一であるため、答えは常にゼロでなければなりません。 もう 1 つのエッジ ケースは、間隔の境界が倍数と正確に一致する場合です。たとえば、次のような場合です。$A$または$B$で割り切れます$K$または$M$これにより、単純な数式で off-by-one エラーが発生する可能性があります。 

## アプローチ

 ブルート フォース ソリューションでは、次のすべての整数を反復処理します。$A$に$B$、割り切れるかどうかを確認します$K$、一致を数え、それを繰り返します$M$。 これは問題の定義に直接従うため、正しいです。 ただし、実行時間は間隔のサイズによって異なります。 もし$A = 1$そして$B = 2 \cdot 10^9$の場合、何十億もの操作が必要になりますが、通常の時間制限では実現できません。 

重要な観察は、プレフィックス内の倍数をカウントすることです。$[1, X]$は簡単です: で割り切れる整数の数$K$まで$X$は$\lfloor X / K \rfloor$。 これから、カウントイン$[A, B]$は 2 つのプレフィックス数の差になります。 これにより、問題は範囲にわたる反復から定数の算術式の評価へと変換されます。 

同じ推論が両方に独立して適用されます$K$そして$M$, そして結果を減算します。

 ## アルゴリズムのチュートリアル

 ## アルゴリズムのチュートリアル

 1. 整数の読み取り$K, M, A, B$。 これらは、同じ間隔にわたる 2 つの独立した計数プロセスを定義します。 
2. ヘルパー関数を定義する$f(x, d)$整数がいくつあるかを計算します$[1, x]$で割り切れます$d$。 これは単純に、$x // d$。 これが機能する理由は、すべてのブロックが$d$連続する数値はちょうど 1 の倍数に寄与します。 
3. の倍数を計算します。$K$寝そべる$[A, B]$として：$f(B, K) - f(A - 1, K)$。 これは前のすべてを差し引きます$A$有効な範囲のみを残します。 
4. 同じ数量を計算します。$M$:$f(B, M) - f(A - 1, M)$。 
5. 最初のカウントから 2 番目のカウントを減算し、結果を出力します。 

重要な考え方は、プレフィックス カウントにより反復が回避され、範囲制約が 2 つのエンドポイントでの算術演算に変換されるということです。 

### なぜ効果があるのか

 任意の固定約数の場合$d$、倍数のシーケンスは周期的です。$d$。 完全な期間の数$[1, x]$まさに$\lfloor x / d \rfloor$、各ピリオドは 1 つの有効な数値を正確に提供します。 プレフィックス カウントを減算すると、どの間隔でも正確な包含/除外が維持されるため、数値が二重にカウントされたり欠落したりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def count(x, d):
    if x <= 0:
        return 0
    return x // d

K = int(input())
M = int(input())
A = int(input())
B = int(input())

k_cnt = count(B, K) - count(A - 1, K)
m_cnt = count(B, M) - count(A - 1, M)

print(k_cnt - m_cnt)
```ヘルパー関数はプレフィックス ロジックを適切に処理します。 明示的なチェック$x \le 0$次の場合に負の除算のエッジ ケースを回避します。$A = 1$、 以来$A - 1$ゼロまたはマイナスになります。 このような場合、プレフィックスに有効な数値がないため、カウントはゼロになります。 

メインの計算では、包含/除外の考え方を約数ごとに 1 回ずつ、計 2 回適用してから、必要な差分を計算します。

 ## 特殊なケース

 主なエッジケースは次のような場合です$A = 1$、それは$A - 1 = 0$。 たとえば、$K = 4$、$A = 1$、$B = 10$、接頭辞の減算は次のようになります。$f(10, 4) - f(0, 4)$。 ヘルパーは次の場合にゼロを返します。$f(0, 4)$したがって、結果は単純に次のようになります。$\lfloor 10/4 \rfloor = 2$、数字の 4 と 8 に対応します。 

もう 1 つのエッジケースは次のような場合です$K = M$。 この場合、両方のカウントはどの間隔でも同一です。 入力用$K = M = 7, A = 3, B = 50$、両方のプレフィックス式は同じ値に評価されるため、減算は常にゼロとなり、これは意図したキャンセル動作と一致します。 

最後の境界ケースは次の場合に発生します。$A = B$。 単一の数が次の数で割り切れる場合$K$しかしそうではありません$M$、結果は$1$。 両方で割り切れば、$0$。 プレフィックス式は、減算によって 1 つのエンドポイントを正確に分離するため、これを引き続き正しく処理します。
