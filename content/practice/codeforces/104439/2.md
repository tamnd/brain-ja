 ## 解決策
 ## 問題の理解

 この絵には、正方形のセルに描かれた 1 本の木が含まれています。 

幹は常に 1 セルの幅で、木全体を垂直に通っています。 木には美しさがある`n`、つまり、まさに存在します。`n`幹の両側に枝があります。 一番下の枝には長さがある`n`、次のものは長さがあります`n - 1`など、一番上の枝まで続きます。その長さは`1`。 

隣接する枝の各ペアの間には、枝のない幹セルが 1 つあります。 また、最も低いブランチの下に 1 つの追加のトランク セルがあり、最も高いブランチの上に 1 つの追加のトランク セルがあります。 

タスクは、図面全体に属するグリッド セルの数を計算することです。 

唯一の入力は美しさです`n`。 出力は総占有面積です。 

の値`n`と同じ大きさにすることができます`2 · 10^9`, したがって、画像を構築することは不可能です。 ループするアルゴリズムでも`n`回には数十億回の反復が必要になります。 答えは数式を使用して直接計算する必要があります。 このステートメントでは、結果が 32 ビット整数に収まらないため、実装は 64 ビット演算に依存する必要があることも警告しています。 Python の整数はすでに任意精度をサポートしています。 

よくある間違いの原因は、幹の高さを間違って数えることです。 たとえば、次のようなとき`n = 1`、幹は下のセル、枝の行、上のセルで構成されており、合計は`3`細胞ではなく、`2`。 

もう 1 つの簡単な間違いは、すべての枝が幹の両側に伸びていることを忘れることです。 たとえば、次のようなとき`n = 2`、ブランチ行が貢献します`(2 + 2) + (1 + 1) = 6`枝細胞ではなく、`3`。 

最小の入力もチェックする価値があります。 入力用```
0
```支店はまったくありません。 トランク セルが 1 つだけ残るので、正解は次のとおりです。```
1
```## アプローチ

 直接シミュレーションでは、図面の各行を構築し、占有されているセルをカウントし、それらを合計します。 このアプローチは定義に正確に従っているため、正しいです。 その実行時間は、`O(n)`あるので`2n + 1`行があるため、次の場合には完全に非実用的になります。`n`20億に達します。 

図面は非常に規則的な構造になっているため、すべての貢献を独立してカウントできます。 

トランクは各行の 1 つのセルを占めます。 がある`n`枝の行、`n - 1`連続する分岐の間には空の行があり、最も低い分岐の 1 行下と、最も高い分岐の 1 行上にあります。 つまり`n + (n - 1) + 2 = 2n + 1`幹細胞。 

枝は両側の長さの合計に寄与します。`2 × (1 + 2 + ... + n)`。 

等差数列公式を使用すると、`2 × n(n + 1) / 2 = n(n + 1)`。 

両方の部分を追加すると、`(2n + 1) + n(n + 1) = n² + 3n + 1`。 

計算全体は 1 つの多項式の評価に集約されます。

 ## アルゴリズムのチュートリアル

 1. 値を読み取る`n`。 
2. トランクセルの数を次のように計算します。`2 * n + 1`。 各行に幹セルが 1 つだけ含まれるため、これが木の高さになります。 
3. ブランチセルの数を次のように計算します。`n * (n + 1)`。 これは合計の 2 倍に相当します`1 + 2 + ... + n`。 
4. 2 つの量を加算し、結果を出力します。 

### なぜ効果があるのか

 占有されているすべてのセルは、2 つのカテゴリのいずれかに正確に属します。 

最初のカテゴリはトランクです。 各行はちょうど 1 つのトランク セルに寄与するため、トランクは`2n + 1`細胞。 

2 番目のカテゴリはブランチです。 長さのある枝`k`貢献する`k`左側のセルと`k`右側に。 すべての分岐の長さを合計すると、次のようになります。`n(n + 1)`細胞。 

幹と枝は、幹そのものを除いて重なり合うことはありません。枝の長さには幹のセルが含まれていないため、すでに 1 回だけカウントされています。 占有されているすべてのセルは 1 回だけカウントされるため、合計面積は次のようになります。`n² + 3n + 1`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
print(n * n + 3 * n + 1)
```実装は、上で導出した閉じた形式の式にすぎません。 Python は 64 ビットを超える整数を自動的に処理するため、最大入力であってもオーバーフローの心配はありません。 

式を次のように書くと`n * n + 3 * n + 1`浮動小数点演算を完全に回避します。 すべての演算は整数演算にとどまり、丸めの問題が排除されます。

def solve():
    input = sys.stdin.readline
    n = int(input())

def run(inp: str) -> str:
