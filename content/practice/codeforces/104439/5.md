 ## 解決策
 ## 問題の理解

 時間の経過とともに記録された金融取引を表す一連の整数が与えられます。 このシーケンスを、正確に 3 つの連続した空ではない部分に分割する必要があります。 各部分は、そのセグメント内のすべての値を合計する「月」に対応します。 目標は、3 つのセグメントの合計がすべて等しくなるように 2 つのカット位置を選択できる方法が何通りあるかを数えることです。 

言い換えれば、インデックスのペアを探しています。$i, j$次のような:

 - 最初のセグメントは$a[1..i]$- 2番目のセグメントは$a[i+1..j]$- 3 番目のセグメントは、$a[j+1..n]$- 3 つのセグメントの合計はすべて同一です

 入力サイズは最大です$10^5$したがって、カットポイントのすべてのペアを直接試すソリューションは、チェックが必要になるため遅すぎます。$O(n^2)$最悪の場合は分裂します。 線形または線形に近いものが必要です。 

重要な制約は、セグメントが連続していて空であってはいけないということです。 これにより、要素の再配置や位置のスキップを伴うトリックは即座に排除されます。 

配列の合計が 3 で割り切れない場合、微妙なエッジ ケースが発生します。その場合、3 つの等和部分が存在することは不可能なので、答えは 0 になります。 もう 1 つのエッジ ケースは、合計がゼロになる場合です。 この場合、各セグメントの合計はゼロになる必要があり、特にプレフィックスの合計が頻繁に繰り返される場合には、有効な分割が多数存在する可能性があります。 

## アプローチ

 ブルートフォース戦略では、すべてのカット ポイントのペアを試します。$i < j$、各セグメントの合計を計算し、等しいかどうかを確認します。 各セグメントの合計は、プレフィックスの合計を使用して O(1) で計算できますが、すべてのセグメントを反復処理します。$O(n^2)$ペアはまだ約$10^{10}$限界をはるかに超えた最悪の場合の操作。 

重要な観察は、「3 つのセグメントの合計が等しい」という条件は、プレフィックスの合計を使用して書き換えることができるということです。 合計を$S$。 有効な分割が存在する場合、各セグメントの合計は次のようになります。$S/3$。 この値を$T$。 次に、次のものが必要です。 

- 最初のカット時のプレフィックスの合計が等しい$T$- 2 番目のカットでのプレフィックスの合計が等しい$2T$したがって、タスクはプレフィックス合計を持つインデックスの数を数えることに減ります。$T$、および有効な 2 番目のカット位置ごとに、その前に有効な最初のカットがいくつ存在するか。 

これは、プレフィックスの合計と頻度のカウントを使用して、二次探索を単一パス問題に変換します。

 ## アルゴリズムのチュートリアル

 配列を 1 回スキャンしながらプレフィックスの合計を構築します。 合計の合計、セグメントごとの目標の合計、最初の目標と等しいプレフィックスの合計がすでに確認された回数の 3 つの情報を使用します。 

1. 配列の合計を計算します。 3 で割り切れない場合は、すぐに 0 を返します。 これが必要なのは、他の方法では等しい整数セグメントの合計が存在できないためです。 
2. 定義する$T = \frac{S}{3}$。 現在、プレフィックスの合計が等しい位置を検索しています$T$そして$2T$。 
3. 現在のプレフィックス合計を維持しながら配列を走査します。 
4. カウンターを維持する`count_T`これは、プレフィックスの合計が次と等しいのを何回見たかを保存します。$T$これまでのところ。 
5. プレフィックスの合計が等しい場合$2T$、有効な 2 番目のカットを形成できます。 以前に発生したプレフィックス合計のすべて$T$この 2 番目のカットで有効な最初のカットが形成されるため、次のように追加します。`count_T`答えに。 
6. 最後までスキャンを続けます。 

順序付けは重要です。厳密に 2 番目のカットの前に出現する有効な最初のカットのみをカウントします。これは、左から右に処理して累積することによって自然に強制されます。`count_T`。 

### なぜ効果があるのか

 このアルゴリズムは、プレフィックスの合計がセグメントの合計を完全に決定するという事実に基づいています。 3 つの等和部分への分割は、次の 2 つのプレフィックス和境界に正確に対応します。$T$そして$2T$。 すべての有効なペアは、プレフィックスの合計を持つ位置に到達した瞬間に 1 回だけカウントされます。$2T$、プレフィックスの合計を持つ以前のすべての位置$T$最初のカットでは有効な選択肢であり、後で間違って再利用されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
arr = [int(input()) for _ in range(n)]

total = sum(arr)

if total % 3 != 0:
    print(0)
    sys.exit()

target = total // 3
second_target = 2 * target

prefix = 0
count_first = 0
ans = 0

for i in range(n - 1):  # last element cannot be a cut before second cut
    prefix += arr[i]

    if prefix == second_target:
        ans += count_first

    if prefix == target:
        count_first += 1

print(ans)
```コードは最初に合計の割り切れ性をチェックするため、不要な処理が防止されます。 ループは次で停止します`n-1`2 番目のカットでは空ではない 3 番目のセグメントを残す必要があるためです。 変数`count_first`現在のインデックスまでに有効なファーストカット位置がいくつ存在するかを格納します。 2 番目のカットの候補に達したら、これまでに確認されたすべての有効な最初のカットを追加します。 

微妙な順序の選択は、`second_target`更新する前に`count_first`。 これにより、無効な方法でカット位置を誤って 1 番目と 2 番目の両方としてカウントすることがなくなります。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、合計が 3 で割り切れない場合です。たとえば、次のように入力します。```
4
1
2
3
4
```合計は 10 ですが、10 mod 3 はゼロではありません。 アルゴリズムはすぐに 0 を返しますが、これは正しい整数セグメントの合計を形成できないためです。 

もう 1 つのケースは、すべての要素がゼロの場合です。 この場合、すべてのプレフィックスの合計はゼロに等しいため、カット位置のすべてのペアが有効な分割を形成します。 このアルゴリズムは、最初のターゲットの累積出現を通じて組み合わせをカウントし、明示的に列挙することなく、組み合わせによる解の数を正確に生成します。 

3 番目のケースは、有効なカットは存在するが、疎である場合です。次に例を示します。```
5
3
-3
3
-3
3
```ここで、接頭辞の合計は 0 と 3 の間で変動し、有効な分割は特定の位置にのみ表示されます。 プレフィックスカウント方法により、構造的に有効な (最初のカット、2 番目のカット) ペアのみがカウントされ、互換性のないインデックスが混在しないことが保証されます。
