 ## 問題の理解

 私たちには、指数によって決定される 2 の 3 つのべき乗が与えられます。$a$、$b$、 そして$c$、整数を形成します$$x = 2^a + 2^b - 2^c.$$値は正であることが保証されており、指数は$a$そして$b$は異なります。 

この数値が形成されたら、それを 2 進数で書き込み、その 2 進数表現で選択した数字が何回出現するかを数えるように求められます。 最後の入力値$d$は、0 と 1 のどちらを数えるべきかを教えてくれます。 

したがって、タスクはバイナリ表現を明示的に計算することではなく、少数のシフトされた 2 のべき乗から構築された数値のバイナリ展開に 0 または 1 がいくつ現れるかを判断することです。 

制約により許可されるのは、$a, b, c$まで$10^9$。 これにより、数値を直接構築したり、整数範囲全体にわたってビット単位の演算をシミュレートしたりするアプローチは即座に排除されます。 均等に保管$2^a$不可能です。 どのようなソリューションも、ビット位置レベルでのバイナリの加算と減算の構造を純粋に使用して機能する必要があります。 

素朴な解釈では、整数を構築するか、除算を繰り返してバイナリに変換しようとします。 番号自体が最大であるため、これは失敗します。$10^9$ビットなので、書き留めることさえ不可能です。 

減算時のキャンセルで微妙な問題が発生$2^c$。 バイナリでの借用は多くのビットに伝播する可能性があります。つまり、最終的な表現は、単にセットされたビットの結合ではありません。$a$そして$b$1ビットマイナス$c$。 正しいソリューションは、潜在的に長く連続するゼロ ブロックにわたる借用を正しく処理する必要があります。 

## アプローチ

 直接的なアプローチでは、整数が構築されます。$x$そしてそれをバイナリに変換します。 これは概念的には簡単です。$2^a$、$2^b$、減算$2^c$、次にビットをカウントします。 正しいことは明らかですが、数字の大きさからそれは不可能です。 Python の整数でも、精度は任意ですが、最大の指数に比例したビット長を格納する必要があります。$10^9$、バイナリへの変換には、その程度の線形時間がかかります。 

重要な観察は、この数値にはアクティブなビット位置が 3 つしかないということです。 の追加$2^a$そして$2^b$2 つの独立した 1 ビットを作成します。 の引き算$2^c$以下の位置のビットにのみ影響します$c$、その効果は、バイナリ借用が連続するゼロ ビットを通じてどのように伝播するかという観点から完全に理解できます。 

整数を構築する代わりに、ビット構造に対するこれらの演算の影響をシミュレートします。 バイナリ表現は、ビット イベントのまばらなセット、つまり 2 つの正の寄与と 1 つの負の寄与として解釈できます。 構造は依然として十分に単純であるため、借用が特定の領域を通過するかどうか、および 0 から 1、またはその逆に反転するビットの数を追跡するだけで済みます。 

これにより、問題は巨大な整数の処理から、相対的な順序付けに関する推論へと軽減されます。$a$、$b$、 そして$c$、および 2 の 1 乗の減算が他の 2 つの和とどのように相互作用するかについて説明します。

 ## アルゴリズムのチュートリアル

 まず、一般性を失わずに次のように仮定します。$a > b$、それらを交換しても合計の値は変わらないためです。 

式は次のようになります$$x = 2^a + 2^b - 2^c.$$バイナリ表現の構造は完全に次の相対位置に依存します。$c$に比べ$a$そして$b$。 

1. もし$c > a$の場合、減算は合計の両方の設定ビットを厳密に上回って行われます。 この場合、$2^a + 2^b$位置にビットがありません$c$なので、引き算すると$2^c$上位ビットから始まるボローチェーンが発生します。 これにより、数値が以下の連続するブロックに実質的に変換されます。$c$、その構造は借用がどこまで伝播するかによって決まります。 バイナリ表現は、元の最上位ビットの下に反転された構造が続く 1 のシーケンスになります。 
2. もし$c = a$の場合、最上位ビットは直接キャンセルされます。 式は次のようになります$2^b$、したがって、バイナリ表現は位置にある単一の 1 ビットです。$b$。 0 または 1 を数えるのは、状況に応じて簡単になります。$d$。 
3. もし$c = b$、同様に 2 番目のビットはキャンセルされ、残ります。$2^a$。 
4. もし$c < b$、その後、両方の設定ビットの下で減算が行われます。 この場合、$2^a$そして$2^b$高い位置ではそのまま残り、下部の構造のみが変化します。 減算により、ビットを反転するボローが作成されます。$c$1 ビットに到達するまで上向きに移動します。これは慎重に追跡する必要があります。 この相互作用により、予測可能なパターンが生成されます: 上記のビット$b$間のビットは影響を受けません$b$そして$c$借用伝播によりすべて 1 になり、ビットは$c$引き算すると消えます。 

これらのケースではバイナリ構造が完全に決定されるため、1 を直接数えて合計ビット長から 0 を導き出すことができます。 

## なぜ機能するのか

 2 のべき乗の和の 2 進数表現はスパースであり、減算の前に設定されるビットは最大でも 2 つです。 2 の 1 乗を減算するとボロー チェーンが導入されますが、そのチェーンは決定的で分岐できません。各ボローは 1 に遭遇するまで連続するビットを反転します。初期の 1 ビットは最大 2 つであるため、可能なボロー伝播の構造は次の順序によって完全に決定されます。$a$、$b$、 そして$c$。 これにより、最終的なビット パターンが絶対的な大きさではなく、相対的な順序のみに依存することが保証されます。

def count_ones(a, b, c):
    if a < b:

 ## 特殊なケース

 エッジケースの 1 つは次の場合に発生します。$c = a$。 例えば：```
a = 6, b = 2, c = 6
```式は次のようになります。$$2^6 + 2^2 - 2^6 = 2^2.$$バイナリは$100_2$、したがって、1 の数は 1 です。最上位ビットを減算すると先頭の構造が完全に削除されるため、アルゴリズムはキャンセル後に式を直ちに折りたたむことでこれを処理します。 

もう 1 つのエッジ ケースは、次のような減算によってロングボロー チェーンがトリガーされる場合です。```
a = 10, b = 1, c = 3
```ここでは、位置 3 のビットが 1 を含まない数値から削除されるため、借用は上位の設定ビットに到達するまで下位ビットを通過する必要があります。 最終的なパターンは中間領域で密になりますが、実装は直接整数演算に依存しているため、Python は借用を正しく解決します。
