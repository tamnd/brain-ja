 ## 解決策
 ## 問題の理解

 ボードは無限であるため、重要な情報は開始マスと選択した目的地のマスの間の相対位置だけです。 すべてのテスト ケースで、ナイトの初期位置の 2 つの座標とターゲット位置の 2 つの座標が与えられます。 奇数のナイトの動きを使用してナイトがターゲットに到達する方法が存在するかどうかを判断する必要があります。 そのような道が存在する場合、勝者はモンケです。 そうでなければポテトが勝ちます。 

座標は次のように大きくできます。$10^6$、テスト ケースの数は次のとおりです。$10^5$。 これにより、ボードを探索するシミュレーションは即座に除外されます。これは、1 つの位置の周囲で幅優先の小さな探索を行ったとしても、多くのマス目を訪問し、そのプロセスを繰り返すことになるためです。$10^5$実行できる操作時間を超える可能性があります。 座標から直接機能する一定時間の観測が必要です。 

難しいのは、ボードが無限であるため、単純なアプローチでは、最短のナイト パスを推論したり、検索グラフを構築したりする可能性があることです。 答えは正確な距離には依存しません。 それはナイト グラフの色付けプロパティのみに依存します。 

よくある間違いは、ターゲットに 1 回の移動で到達できるかどうかだけを確認することです。 たとえば、入力`1 1 4 5`は、ターゲットがナイトの 1 移動先にない場合ですが、ナイトは奇数の手でターゲットに到達できるため、答えはやはりモンケです。 もう 1 つの間違いは、偶数手でマス目に到達するということは、奇数のルートも存在する可能性があることを意味すると仮定していることです。 のために`1 1 1 3`、座標の色は同じであるため、すべての可能なルートの長さは均等になります。 正しい出力は次のとおりです`Potato`。 

## アプローチ

 直接的な総当たりの解決策は、開始正方形からグラフ検索を実行することです。 各四角形はノードであり、ナイトの動きごとにエッジが作成されます。 幅優先探索では目的地までの最短距離を見つけることができ、その距離が奇数であればモンケが勝ちます。 重み付けされていないグラフ内の最短パスは BFS によって検出されるため、このアプローチは正しいです。 

問題はグラフの大きさです。 目的地が 1 つだけ必要な場合でも、無限ボード上の BFS は多数の正方形を検査する必要がある場合があります。 と$10^5$テスト ケースでは、検索ベースの方法は不可能です。 In the worst case, if a search visits$K$テスト ケースごとの正方形の場合、総作業量は次のようになります。$O(10^5K)$、それは限界をはるかに超えています。 

重要な観察は、チェス盤のマスの色を見ることから得られます。 正方形は次のパリティによって色付けできます。$x+y$。 騎士の動きごとに変化する$x+y$移動によって 1 つの座標が 1 だけ変更され、もう 1 つの座標が 2 だけ変更されるため、奇数の量になります。これらの変更を加算すると、常に奇数の値が得られます。 その結果、騎士が動くたびに正方形の色が変わります。 

これは、ナイト グラフが 2 部構成であることを意味します。 奇数の移動数を持つパスは反対の色で終了し、偶数の移動数を持つパスは同じ色で終了する必要があります。 残りの問題は、反対色のすべての四角形に到達できるかどうかです。 ナイトは無限のボード上のすべてのマスに到達できるため、重要な条件は色の違いだけです。 

ブルート フォースはグラフ定義に直接従うため機能しますが、グラフが大きすぎるために失敗します。 カラーリング プロパティは、グラフ全体を 1 つのパリティ チェックに圧縮します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(K)$テストケースごと、ここで$K$は探索された正方形の数です |$O(K)$| 遅すぎる |
 | 最適 |$O(1)$テストケースごと |$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 次を使用して開始正方形の色を計算します。$(x_1+y_1)\bmod 2$。 チェス盤の色は 2 マスごとに繰り返されるため、合計の正確な値は必要ありません。奇数か偶数かだけが必要です。 
2. 次を使用して目的の正方形の色を計算します。$(x_2+y_2)\bmod 2$。 これにより、ナイトが終了しなければならない色のクラスが決まります。 
3. 2 つの色を比較します。 それらが異なる場合、騎士は奇数の動きをしたに違いないので、次のように出力します。`Monke`。 それらが同じ場合、考えられるすべてのパスの長さは均等であるため、次のように出力します。`Potato`。 

なぜそれが機能するのか: ナイトが動くたびに、同等性が切り替わります。$x+y$。 1 回移動すると色が反転し、2 回移動すると元に戻り、これがすべてのパスの長さで続きます。 宛先の色は、その正方形へのすべての可能なパス長のパリティを完全に決定します。 無限ナイト ボードではすべてのマス目が到達可能であるため、反対の色は奇数の手で到達可能な位置に正確に対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        x1, y1, x2, y2 = map(int, input().split())

        if (x1 + y1) % 2 != (x2 + y2) % 2:
            ans.append("Monke")
        else:
            ans.append("Potato")

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```入力は一度に 1 つのテスト ケースで処理されるため、ケースが多い場合でもメモリ使用量が一定に保たれます。 プログラムは、出力文字列をまとめて印刷する前に出力文字列を保存するだけで、多くの個別の出力操作のオーバーヘッドを回避します。 

表現`(x1 + y1) % 2`ソリューションの中核全体です。 重要なのはパリティだけなので、座標値が大きくても問題はありません。 Python の整数では、オーバーフローの問題も回避されますが、ここで考えられる最大合計は、他の言語の標準的な整数型としてはすでに十分小さいものになっています。 

比較は 2 つの正方形の色間で直接行われます。 無限ボードは境界効果を取り除くため、距離を計算したり、ナイトの動きを生成したり、特殊な座標の場合を処理したりする必要はありません。

import sys
import io

def solution(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    ans = []

    for _ in range(t):
        x1, y1, x2, y2 = map(int, input().split())
        if (x1 + y1) % 2 != (x2 + y2) % 2:
            ans.append("Monke")
        else:
            ans.append("Potato")

    return "\n".join(ans)

# provided sample
assert solution("""3

100 2 9 11
1 1 1 2
""") == """Monke
Potato
Monke""", "sample"

# minimum-size style case: same square
assert solution("""1
1 1 1 1
""") == "Potato", "same square"

# boundary values
assert solution("""1
1000000 1000000 1 2
""") == "Monke", "large coordinates"

# same color but far apart
assert solution("""1
1 1 1000000 1000000
""") == "Potato", "same parity"

# opposite color adjacent coordinates
assert solution("""1

""") == "Monke", "parity difference"

 ## 特殊なケース

 場合について`1 1 1 1`、両方の正方形はパリティを持っています$(1+1)\bmod 2=0$。 アルゴリズムは同じ色を比較して出力します。`Potato`。 有効な奇数パスとしてゼロ移動カウントを想定する不注意な実装では、誤って出力されてしまいます。`Monke`。 

場合について`1 1 1 3`、両方の正方形も偶数パリティを持ちます。 ナイトは、すべての移動で色が反転し、奇数回反転すると元の色に戻ることができないため、奇数の移動で到達することはできません。 アルゴリズムは直ちに等しいパリティを検出し、出力します。`Potato`。 

場合について`1000000 1000000 1 2`、開始マスにはパリティがあります$0$、宛先にパリティがある間$1$。 値は大きくなりますが、問題となるのは座標合計の最後のビットだけです。 アルゴリズムはさまざまな色を見つけて出力します`Monke`ボードのサイズに依存することはありません。
