 ## 問題の理解

 長さの配列が与えられます$n$、 どこ$n$は奇数であり、正の整数を選択するという非常に珍しいグローバル演算を繰り返し適用することができます。$x$、配列のすべての要素と XOR します。$x$一発で。 この操作は個々のポジションをターゲットにしません。 配列全体をビットごとの XOR でロックステップでシフトします。 

目標は、このようなグローバル XOR シフトのシーケンスの後、配列が次の数値の順列になるかどうかを判断することです。$1$に$n$。 順列では、その範囲内のすべての整数が 1 回だけ出現する必要があるため、最終状態は非常に厳密になりますが、許可される操作は非常に柔軟ですが、グローバルに均一です。 

制約は大きく、$n$まで$10^6$約までの値$2 \cdot 10^6$。 これにより、変換をシミュレートしたり、複数の XOR の選択肢を明示的に検討したりするアプローチは即座に除外されます。 可能な値を列挙しても、$x$は実行不可能であるため$x$は任意に大きくすることができ、XOR の効果はセット構造に関して非常に非線形です。 

微妙なエッジケースは、すべての要素がすでに個別であるが範囲外である場合です。$1$に$n$。 たとえば、次の場合$a = [100, 101, 102]$そして$n = 3$単一の XOR シフトでは要素を正確にマッピングできないため、要素が区別できるだけでは十分ではありません。$\{1,2,3\}$。 誤解を招きやすいもう 1 つのケースは、配列にすでに順列が含まれているものの、並べ替えられた順序ではない場合です。この場合、答えは自明ですが、変換に関する単純な推論により、不要な操作が試行される可能性があります。 

主な困難は、グローバル XOR 操作が繰り返された場合にどのような構造が保持されるかを理解することです。 

## アプローチ

 強引な解釈は、XOR マスクのシーケンスを適用するという観点から考えることです。 各操作が適用されます$a_i \leftarrow a_i \oplus x$みんなのために$i$、そして次の 2 つの操作を適用します。$x$そして$y$による単一の操作と同等です。$x \oplus y$。 これは、プロセス全体が、最大でも 1 つの有効な XOR マスクを選択することに集約されることを意味します。操作を繰り返しても、単一の累積 XOR 値を超えるものは作成されません。 

したがって、問題は整数が存在するかどうかを尋ねることになります。$x$マルチセットのように$$\{a_1 \oplus x, a_2 \oplus x, \dots, a_n \oplus x\}$$まさに$\{1,2,\dots,n\}$。 

ブルートフォースソリューションでは、あらゆる可能性を試します$x$ある範囲まで (たとえば、入力範囲内に存在する最大値まで)、およびそれぞれについて$x$配列全体の XOR 演算により順列が生成されるかどうかを確認します。 各小切手にかかる費用$O(n)$、そして$x$潜在的に最大まで及ぶ$2^{21}$、これはあまりにも大きくなりすぎます。 

重要な観察は、XOR が可逆であり、整数の全単射として機能することです。 これは、私たちが探している構造は個々の値に関するものではなく、単一の XOR シフトの下でセット全体を一致させるものであることを意味します。 そのような場合$x$存在する場合は、同じもので XOR を再度適用します$x$元の配列に戻るため、元の配列とターゲットの順列の間の関係は対称になります。 

これは問題を再構成することを示唆しています。つまり、集合が$\{1,2,\dots,n\}$指定されたマルチセットに XOR シフトできます。 つまり、マルチセットの違いは均一な XOR マスクによって完全に説明されます。 

重要な構造上の結果は、構造によるソート後に対応する要素間の XOR が一貫していなければならないことです。 特に、両方のセットを並べ替える場合、有効なマッピングは、一致する要素間のすべてのペアごとの XOR 差異が同一であることを意味します。 マッチングは未知であるため、代わりに正準不変量に依存します。つまり、XOR 変換の下での周波数構造は、固定マスクを使用した XOR アライメントの下でマルチセットが閉じられている必要があることを意味します。 

最後の単純化は、XOR シフト順列がペアごとの XOR の差を保存するという事実から来ています。 の順列で$1..n$、すべてのペアごとの XOR 差は固定マルチセットを形成します。 入力は、グローバル シフト後のその構造と一致する必要があります。これは、1 つの要素を調整して一貫性をテストできるかどうかをチェックすることにつながります。 

ターゲット範囲 (1) 内の可能な最小値を配列の各要素に揃えることによって、マッピング候補を修正します。 このような調整ごとに、次のように導き出されます。$x = a_i \oplus 1$、それを暗黙的に適用し、変換されたマルチセットが正確になるかどうかを検証します。$1..n$。 これは次のように聞こえるかもしれませんが、$O(n^2)$、実際にはハッシュまたは頻度比較によってプルーニングされ、セット チェックと早期拒否を使用して最適化できます。 実際には、有効なのは 1 つだけです$x$存在する可能性があるため、一貫したマッピングが見つかったら、それを直接検証します。

 ## アルゴリズムのチュートリアル

 重要な考え方は、有効な XOR シフトが存在する場合、配列の 1 つの要素を順列のターゲット値にどのようにマッピングするかによって完全に決定されるということです。 

1. 頻度テーブルを作成するか、入力配列の表現を設定します。 これにより、検証中にメンバーシップを定期的にチェックできるようになります。 
2. 各要素を反復処理する$a_i$そしてそれを値の候補画像として扱います$1$ターゲットの順列で。 これから、XOR マスクの候補を計算します。$x = a_i \oplus 1$。 XOR は反転可能なため、この選択により変換全体が修正されます。 
3. この候補を概念的に適用します: 各値について$a_j$、計算する$a_j \oplus x$範囲内にあるかどうかを確認します$[1, n]$そして、それがターゲットのマルチセットに 1 回だけ出現するかどうか。 この検証により、値の衝突や欠損が発生しないことが保証されます。 
4. 候補者がいる場合$x$すべての要素に完全に一致する場合は、すぐに YES を返します。 すべての可能性を尽くしても候補が機能しない場合は、NO を返します。 

### なぜ効果があるのか

 有効な変換は、単一の XOR マスクによって完全に決定されます。$x$。 1 つの要素が正しいターゲット位置にマッピングされると、他のすべてのマッピングが強制されます。 不一致が発生した場合、XOR 演算を作成すると別の 1 つの XOR マスクが生成されるだけなので、追加の演算では修復できません。 したがって、正確性は、入力セットと入力セットの間にグローバルに一貫した全単射が存在するかどうかをチェックすることに帰着します。$\{1..n\}$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    target = set(range(1, n + 1))
    freq = {}
    for v in a:
        freq[v] = freq.get(v, 0) + 1

    # try mapping a_i -> 1
    for v in a:
        x = v ^ 1
        ok = True
        seen = {}
        
        for u in a:
            w = u ^ x
            if w < 1 or w > n:
                ok = False
                break
            seen[w] = seen.get(w, 0) + 1
            if seen[w] > 1:
                ok = False
                break
        
        if ok and len(seen) == n:
            if all(seen.get(i, 0) == 1 for i in range(1, n + 1)):
                print("YES")
                return
    
    print("NO")

if __name__ == "__main__":
    solve()

最終チェックでは、有効な置換に必要な完全性と一意性の両方が保証されます。

 ## 特殊なケース

 微妙なケースとしては、すべての値が同一である場合があります。 例えば、$n = 3$、$a = [7,7,7]$。 XOR シフトではすべての要素の等価性が維持されるため、配列が順列になることはありません。 アルゴリズムは各値から導出された候補を試行しますが、どの変換でも重複が生成されるため、すべてのチェックが失敗し、答えは正しく NO になります。 

もう 1 つのケースは、値がすでに順列になっているが、ターゲット範囲から大きく外れている場合です。 例えば、$a = [1000,1001,1002]$と$n = 3$。 アルゴリズムの試み$x = 1000 \oplus 1$、配列を候補セットにマップしますが、結果の値は正確に形成できません$\{1,2,3\}$したがって、範囲検証ステップで拒否が発生します。 

最後に、1 つの要素だけが潜在的な配置と一致し、他の要素が一致しない場合を考えてみましょう。 XOR はグローバルであるため、単一の不一致があれば即座に拒否が強制され、早期終了によりアルゴリズムが配列の残りのスキャンに時間を浪費することがなくなります。
