 ## 解決策
 ## 問題の理解

 毎日の一連の解決数が間接的に与えられます。 元の配列には毎日解決された問題の数が含まれていますが、最近の日の合計のみが提供されます。 まず最初に`k`日の場合、値は月初めからその日までに解決された問題の合計数を表します。 その後、各値は直前の値の合計を表します。`k`あの日で終わる日々。 

タスクは、元の日次カウントに関する十分な情報を回復して、毎日プラスの解決カウントがあった最長の連続間隔を見つけることです。 

制約により、私たちは線形の解決策に向かうことになります。 すべてのテスト ケースの合計日数は最大で`3 * 10^5`、だから、`O(n)`または`O(n log n)`方法が現実的です。 考えられるすべての間隔をチェックするか、合計を繰り返し再構築するソリューションには、約`O(n^2)`最悪の場合、2 秒の制限をはるかに超えて操作が可能になります。 

いくつかの特殊なケースでは、不注意な実装が失敗する可能性があります。 いつ`k = n`、配列全体は単なるプレフィックスの合計であるため、すべての値を通常のスライディング ウィンドウの合計として扱うと、不正確な差が生じます。 例えば：```
Input:
1
3 3
1 2 2
```本来の日々は、`[1, 1, 0]`、したがって、答えは次のとおりです`2`。 間違ったスライディング ウィンドウのみのアプローチは、最初のウィンドウの後に完全なウィンドウがないため失敗する可能性があります。`k`日々。 

もう 1 つの注意が必要なケースは、スライド合計が減少する場合です。 古い正の日がウィンドウを離れる可能性があるため、減少は現在の日のソルブ数がゼロであることを直接意味するものではありません。 例えば：```
Input:
1
5 2
1 2 1 0 0
```本来の日々は、`[1, 1, 0, 0, 0]`、したがって、答えは次のとおりです`2`。 連続した値が増加するか減少するかだけを見ると、日を誤って分類する可能性があります。 

3 番目のケースは、すべての日がプラスの場合です。```
Input:
1
5 2
1 2 2 2 2
```答えは`5`。 毎日のカウントを再構築するのではなく、指定された配列内の変更を検索する方法では、連続記録が誤って早期に停止されてしまいます。 

## アプローチ

 直接的なアプローチは、元の日次カウントを再構築することです。 隠し配列を次のようにします`x`。 まず最初に`k`日の場合、指定された値はプレフィックスの合計であるため、前のプレフィックスの合計を減算することで毎日を見つけることができます。 後日`k`、現在の値はウィンドウ合計です。 前のウィンドウを削除し、新しい日を追加すると、次の関係が得られます。`a[i] - a[i-1] = x[i] - x[i-k]`それで：`x[i] = a[i] - a[i-1] + x[i-k]`これにより、それぞれの隠れた値を定数時間で計算できるようになります。 

ブルート フォース ソリューションでは、最初に配列全体を再構築し、次にすべての開始日から拡張することで、考えられるすべてのストリークをテストできます。 考えられるすべての間隔がチェックされるため、これは正しいですが、最悪の場合は実行されます。`O(n^2)`仕事。 と`n = 300000`、これは約 900 億回の操作を意味します。 

隠された各日は値のみに依存するという観察`k`より早い位置に置くと問題は完全に変わります。 間隔を繰り返し検索する必要はありません。 日々を再構築しながら、現在の連続長さを維持できます。 回復された値が正になるたびに、ストリークは増加します。 ゼロになると連続記録が終了し、最良の回答が更新されます。 毎日 1 回処理されるため、問題全体は線形になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を作成する`days`これには、毎日解決された問題の回復された数が保存されます。 後日の繰り返しには、次の値が必要です。`k`数日前に設定されているため、以前の値を保持することで移行が可能になります。 
2.最初のを回復する`min(n, k)`プレフィックス合計を使用した日数。 初日は以下に等しい`a[0]`。 このプレフィックス領域では毎日、`a[i] - a[i-1]`。 指定された値は累積合計であるため、これらの値は実際の毎日のソルブを表します。 
3. 最初の日以降毎日`k`日、次を使用して非表示の値を計算します。`a[i] - a[i-1] + days[i-k]`。 引き算は、窓から出た古い日と足し算を表します。`days[i-k]`削除された貢献を復元します。 
4. 毎日回復しながら、現在の連続記録を更新します。 回復された値がゼロより大きい場合は、現在のストリークを増加させ、最大値を更新します。 ゼロの場合、ゼロ解決の日は連続した解決を中断するため、現在のストリークをリセットします。 
5. すべての日が処理された後に見つかった最大の縞を出力します。 

機能する理由: 再構成の式は、各スライディング ウィンドウの定義に正確に従っています。 まず最初に`k`日、プレフィックスの違いにより、可能な日次値のみが得られます。 後の日については、2 つの隣接するウィンドウの合計の差から、古い日を 1 つ削除し、新しい日を 1 つ追加することによって生じた変化がわかります。 配列は有効であることが保証されているため、再構築された値は元の日次カウントとまったく同じになります。 次に、ストリーク計算により、正の値の最長連続が直接測定されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))

        days = [0] * n
        best = 0
        cur = 0

        for i in range(n):
            if i == 0:
                days[i] = a[i]
            elif i < k:
                days[i] = a[i] - a[i - 1]
            else:
                days[i] = a[i] - a[i - 1] + days[i - k]

            if days[i] > 0:
                cur += 1
                if cur > best:
                    best = cur
            else:
                cur = 0

        ans.append(str(best))

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```配列`days`再構築された毎日の解決数を保存します。 ゼロからインデックスが付けられるので、`days[i-k]`日を計算するときにスライディング ウィンドウを離れる日です`i`。 

最初のブランチでは、以前のプレフィックス合計がないため、0 日目を個別に処理します。 2 番目のブランチは入力のプレフィックス合計部分をカバーしており、隣接する値を減算することで正確な日次カウントが得られます。 最後のブランチでは、スライディング ウィンドウの繰り返しを使用します。 

Python の整数は自動的に使用されるため、可能な大きな値は`a[i]`オーバーフローの問題を引き起こさないでください。 繰り返しにおける操作の順序も重要です。前のウィンドウの差は、出発日の寄与を加算し直すことによって修正する必要があります。 

## 実用的な例

 最初のサンプルの場合:```
n = 5, k = 2
a = [1, 2, 1, 4, 5]
```| 日 | 使用される式 | 回復されたソルブ | 現在の連続記録 | 最大 |
 | --- | --- | --- | --- | --- |
 | 1 |`a[0]`| 1 | 1 | 1 |
 | 2 |`a[1]-a[0]`| 1 | 2 | 2 |
 | 3 |`a[2]-a[1]+days[0]`| 0 | 0 | 2 |
 | 4 |`a[3]-a[2]+days[1]`| 4 | 1 | 2 |
 | 5 |`a[4]-a[3]+days[2]`| 1 | 2 | 2 |

 再構築によって得られるものは、`[1, 1, 0, 4, 1]`。 3日目のゼロは最初の連続記録を破り、答えは次のようになります。`2`。 

3 番目のサンプルの場合:```
n = 5, k = 2
a = [1, 2, 2, 2, 2]
```| 日 | 使用される式 | 回復されたソルブ | 現在の連続記録 | 最大 |
 | --- | --- | --- | --- | --- |
 | 1 |`a[0]`| 1 | 1 | 1 |
 | 2 |`a[1]-a[0]`| 1 | 2 | 2 |
 | 3 |`a[2]-a[1]+days[0]`| 1 | 3 | 3 |
 | 4 |`a[3]-a[2]+days[1]`| 1 | 4 | 4 |
 | 5 |`a[4]-a[3]+days[2]`| 1 | 5 | 5 |

 回復された値はすべてプラスであるため、連続記録は月全体に達します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 毎日が 1 回再構築され、処理されます。 |
 | スペース | O(n) | 将来の日付には次の値が必要となるため、復元された配列が保存されます。`k`前の位置。 |

 合計`n`すべてのテスト ケースの境界は次のとおりです`3 * 10^5`, したがって、リニアパスは制限時間に簡単に適合します。 メモリ使用量も 256 MB の制限内にあります。 

## テストケース```python
import sys
import io

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)

    def solve():
        input = sys.stdin.readline
        t = int(input())
        out = []

        for _ in range(t):
            n, k = map(int, input().split())
            a = list(map(int, input().split()))

            days = [0] * n
            cur = 0
            best = 0

            for i in range(n):
                if i == 0:
                    days[i] = a[i]
                elif i < k:
                    days[i] = a[i] - a[i - 1]
                else:
                    days[i] = a[i] - a[i - 1] + days[i - k]

                if days[i] > 0:
                    cur += 1
                    best = max(best, cur)
                else:
                    cur = 0

            out.append(str(best))

        return "\n".join(out)

    result = solve()
    sys.stdin = old_stdin
    return result

 ## 特殊なケース

 いつ`k = n`、すべての値はプレフィックスの合計です。 のために：```
1
3 3
1 2 2
```このアルゴリズムはプレフィックス再構成ブランチのみを使用します。 日数がかかります`[1, 1, 0]`、連続記録を更新します`2`、ゼロの後にリセットされます。 出力は`2`。 

ウィンドウが減少すると、アルゴリズムは新しい日がゼロであると想定しません。 のために：```
1
5 2
1 2 1 0 0
```回復した日々は`[1, 1, 0, 0, 0]`。 繰り返しは窓から出た古い日を正しく説明しているので、答えは残ります`2`。 

毎日がポジティブであれば、リセットはありません。 のために：```
1
5 2
1 2 2 2 2
```再構成された各日は等しい`1`, したがって、現在の連続記録は`1`に`5`そして最終的な答えは`5`。 アルゴリズムは、入力配列内のパターンではなく、再構成された毎日の値をチェックするため、これを処理します。
