 ## 解決策
 ## 問題の理解

 各ノードが数値を保持するルート付きツリーが与えられます。 すべてのクエリでは、アリス用とボブ用の 2 つの開始ノードが与えられます。 各人はそれぞれの開始点から、親から子へのエッジに沿って下方向にのみ移動できます。 彼らは任意の順序で自分の動きを自由にインターリーブできますが、1 つの制約を尊重する必要があります。それは、ノードがすでに他の人によって訪問されている場合、そのノードは禁止されるということです。 

クエリの目的は、どのように段階的に移動するかを計算することではなく、最終的な量を決定することです。アリスとボブのそれぞれについて、両方が最適に動作すると仮定して、この制約された探索中に確認できる最大ノード値はいくらか、ということです。 

重要な観察は、ノードはいつでも一時停止して後で分岐できるため、「ノードが見える」ということは、移動中のある時点でノードに到達できることと同等であるということです。 したがって、問題は、他のプレーヤーが最初にノードを占有することによってツリーの一部をブロックする可能性があることを考慮して、各プレーヤーがどのノードに到達できるかを理解することに帰着します。 

移動は厳密に下向きであるため、ツリー構造はサブツリー範囲による前処理を直ちに示唆します。 各開始ノードは到達可能なサブツリーを定義しますが、2 つの開始位置が重なると非対称ブロッキングが発生します。一方の開始ノードが他方のサブツリーの内側にある場合、1 人のプレイヤーがブランチ全体を封鎖する可能性があります。 

制約は大きく、最大 50 万のノードとクエリがあります。 移動をシミュレートしたり、クエリごとのサブツリーを直接探索しようとするソリューションでは、クエリごとに線形作業が必要となり、最悪の場合、約 10¹¹ の操作が必要となり、これは実現可能な制限をはるかに超えています。 これにより、前処理後に各クエリが対数時間または定数時間で処理されるソリューションが強制されます。 

一方の開始ノードが他方の開始ノードのサブツリー内にある場合、微妙なエッジ ケースが発生します。 たとえば、アリスがボブの祖先から開始する場合、ボブは最初に自分のサブツリーを「要求」し、アリスがそれに入るのを防ぐことができますが、アリスはそのブロックされた領域の外側にあるすべての残りのブランチを探索できます。 この相互作用を無視し、単純に両方のノードのサブツリー最大値を取る単純な解決策では、このような場合、アリスの答えが過大評価されてしまいます。 

もう 1 つのエッジ ケースは、2 つの開始ノードが完全に別々のサブツリーにある場合です。 その状況では、相互作用はまったくなく、どちらの答えも独立したサブツリー クエリになります。 

## アプローチ

 ブルートフォース解釈は探索をシミュレートします。 各開始ノードから下方向の検索を実行し、他のプレイヤーが訪問したノードを動的にマークします。 動きの順序は柔軟であるため、すべてのインターリーブを考慮するか、敵対的なプロセスをシミュレートする必要があります。 これを単純化し、1 つの固定順序を仮定したとしても、各クエリは影響を受けるサブツリー内のすべてのノードにアクセスする必要があります。 クエリごとに最大 n 個のノードと q 個のクエリを使用すると、作業量が O(nq) となり、大きすぎます。 

重要な簡素化は、移動制約によって上方向への移動が決して許可されないことを認識することで実現します。そのため、プレイヤーの到達可能な領域は常に、あるサブツリーから、他のプレイヤーによって除外される可能性のある 1 つのサブツリーを差し引いたものになります。 相互作用全体は、オイラー巡回区間の幾何学的問題に崩壊します。 

ツリーをルート化すると、各サブツリーはオイラー ツアー次数の連続セグメントに対応します。 これにより、問題が配列上の範囲クエリに変換されます。各クエリは 2 つの区間になり、答えはサブ区間を除いた 1 つの区間の最大値になります。 この除外により、クエリは最大 2 つの独立したセグメントに分割されます。 

次に、範囲最大値のクエリに迅速に応答できるデータ構造が必要になります。 O(n) 個の前処理後に O(log n) 個のクエリをサポートするオイラー次数のセグメント ツリーで十分です。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(nq) | O(n) | 遅すぎる |
 | オイラーツアー + セグメントツリー | O((n + q) log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ノード 1 でツリーをルートし、DFS を実行して、すべてのノードの開始時刻と終了時刻を計算します。 これにより、各サブツリーが連続セグメントに対応するオイラー ツアー順序が生成されます。 この変換により、サブツリー クエリが間隔クエリになることが可能になります。 
2. アレイを構築する`euler`ここで、各位置は DFS 順序のノードに対応し、その値が格納されます。 各ノードは、サブツリー クエリの場合、このレイアウトに 1 回だけ表示されます。 
3. 範囲最大クエリをサポートするオイラー配列に対してセグメント ツリーを構築します。 この構造により、任意のサブツリー内の最大値を対数時間で計算できます。 
4. 開始ノード x および y を持つ各クエリについて、それらを間隔 [tin[x], tout[x]] および [tin[y], tout[y]] に変換します。 
5. 間隔の包含をチェックして、一方のノードが他方のサブツリー内にあるかどうかを判断します。 tin[x] ≤ tin[y] ≤ tout[x] の場合、y は x のサブツリー内にあり、逆の場合も同様です。 
6. サブツリーが互いに素である場合は、間隔ごとに単一の範囲最大クエリを使用して独立して回答を計算します。 
7. y が x のサブツリー内にある場合、x の区間を [tin[x], tin[y] − 1] と [tout[y] + 1, tout[x]] の 2 つの部分に分割してアリスの答えを計算します。 両方のセグメントの最大値を取得します。 ボブの答えは、単に彼の完全なサブツリーの最大値です。 
8. x が y のサブツリー内にある場合を対称的に処理します。 

### なぜ効果があるのか

 DFS の順序付けにより、すべてのサブツリーが連続した間隔に正確に対応することが保証されます。 サブツリーの外側にあるノードは完全にその間隔の外側にあるため、子孫サブツリーを除外することはサブ間隔を削除することと同じになります。 すべての値は独立しており、最大値のみを考慮するため、互いに素なセグメントに分割すると正確さが保たれます。 アリスとボブの間の対話では、単一の除外されたサブツリーを超えて部分的な断片化が生じることはありません。これは、エントリをブロックする接続された下向きのパスを「占有する」ことができるのは 1 人のプレイヤーだけであるためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))
    
    g = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    tin = [0] * n
    tout = [0] * n
    euler = [0] * n
    parent = [-1] * n
    timer = 0

    stack = [(0, 0, 0)]  # node, parent, state (0 enter, 1 exit)

    while stack:
        v, p, state = stack.pop()
        if state == 0:
            parent[v] = p
            tin[v] = timer
            euler[timer] = a[v]
            timer += 1
            stack.append((v, p, 1))
            for to in g[v]:
                if to != p:
                    stack.append((to, v, 0))
        else:
            tout[v] = timer - 1

    size = 1
    while size < n:
        size *= 2
    seg = [-10**18] * (2 * size)

    for i in range(n):
        seg[size + i] = euler[i]
    for i in range(size - 1, 0, -1):
        seg[i] = max(seg[2 * i], seg[2 * i + 1])

    def query(l, r):
        if l > r:
            return -10**18
        l += size
        r += size
        res = -10**18
        while l <= r:
            if l % 2 == 1:
                res = max(res, seg[l])
                l += 1
            if r % 2 == 0:
                res = max(res, seg[r])
                r -= 1
            l //= 2
            r //= 2
        return res

    out = []

    for _ in range(q):
        x, y = map(int, input().split())
        x -= 1
        y -= 1

        def in_sub(u, v):
            return tin[u] <= tin[v] <= tout[u]

        ax_l, ax_r = tin[x], tout[x]
        ay_l, ay_r = tin[y], tout[y]

        if not in_sub(x, y) and not in_sub(y, x):
            ax = query(ax_l, ax_r)
            ay = query(ay_l, ay_r)
        elif in_sub(x, y):
            ay = query(ay_l, ay_r)
            ax = max(query(ax_l, ay_l - 1), query(ay_r + 1, ax_r))
        else:
            ax = query(ax_l, ax_r)
            ay = max(query(ay_l, ax_l - 1), query(ax_r + 1, ay_r))

        out.append(f"{ax} {ay}")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```中心となる実装の選択は、サブツリー クエリが連続範囲となる線形配列として保存されるオイラー ツアーです。 その後、セグメント ツリーはすべての最大クエリを均一に処理します。 唯一のデリケートな部分は、あるサブツリーが別のサブツリーの中にネストされている場合に、区間を正しく分割することです。この場合、削除されたセグメントの両側を除外することを忘れることが誤った答えの一般的な原因です。 

## 実用的な例

 いくつかの枝の深さとともにノード値が増加する、根を持つ小さなツリーを考えてみましょう。 アリスがボブの先祖から始まるとします。 アリスに関連する区間は、ボブのサブツリーの周囲で 2 つの部分に分割されます。 

| ステップ | アリス間隔 | ボブ間隔 | 関係 | アリスの答え | ボブの答え |
 | --- | --- | --- | --- | --- | --- |
 | 1 | [tin[x]、tout[x]] | [tin[y]、tout[y]] | x の中に y | 分割クエリ | 完全なサブツリー |

 これは、ボブのサブツリーがオイラー順序で連続したブロックを占有することによってのみ、アリスの到達可能な領域が切断されることを示しています。 

2 番目の例として、異なるブランチにある 2 つのノードを考えてみましょう。 それらのオイラー区間はまったく重なりません。 

| ステップ | アリス間隔 | ボブ間隔 | 関係 | アリスの答え | ボブの答え |
 | --- | --- | --- | --- | --- | --- |
 | 1 | [l1、r1] | [l2、r2] | ばらばら | フルマックス | フルマックス |

 これにより、サブツリー間隔がネストされない場合は常に独立性が維持されることが確認されます。

 ## 特殊なケース

 アリスがボブの祖先から開始する場合、アルゴリズムはアリスの区間からボブのサブツリーを正確に除外する必要があります。 オイラー ツアー表現では、このサブツリーが単一の連続したセグメントであることが保証されるため、左右の部分に分割すると、無関係なノードを失うことなく、ボブの影響が完全に除去されます。 

両方のノードが別々のブランチにある場合、包含チェックは両方向で失敗します。 その場合、アルゴリズムは間隔の分割を回避し、2 つの独立した範囲最大クエリを実行して、正確さを維持します。 

一方のノードが他方のサブツリーの奥深くにある場合、セグメント ツリーのクエリは、l > r の [l, r] などの空の間隔に縮退する可能性があります。 実装では、中立の最小値を返すことでこれを処理し、有効なセグメントのみが最大値に寄与するようにします。
