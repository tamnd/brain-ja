 ## 解決策
 ## 問題の理解

 グリッドは無限であり、各テスト ケースは開始タイルと宛先タイルを記述します。 移動により、1 つの座標が 1 単位ずつ変更されます。 x 座標と y 座標を独立して変更する必要がある距離を数えるだけでよいため、通常の最短経路は単純にマンハッタン距離になります。 

追加ルールにより状況は変わります。`k`一方向に移動すると、次の移動を同じ方向に続けることはできません。 タスクは、ターゲットに到達する最短の有効な一連の動きを見つけることです。 

入力には最大で次のものが含まれます`10^5`独立したテストケース。 座標は次のように大きくできます。`10^9`絶対値で表現されるため、パスをシミュレートすることは不可能です。 1 つのテスト ケースには数十億の移動が必要になる可能性があるため、点間の距離に比例する解法であっても遅すぎます。 と`10^5`ケースごとに、ソリューションはケースごとに一定量の演算のみを実行する必要があります。 

主なエッジ ケースは、最短のマンハッタン パスに修正が必要ない場合、または 1 つの軸に必要な動きがない場合に発生します。 

から始めることを検討してください`(0,0)`そして到達する`(0,0)`と`k = 5`。 答えは`0`。 移動制限のために常に何らかの補正を加えるソリューションは、ここでは失敗します。 

考慮する`(0,0)`に`(10,0)`と`k = 3`。 答えはそうではありません`10`, 10回連続の右打ちは違法だからです。 移動制限により、最終的な y 座標が変更されていない場合でも、別の軸上で余分な移動が強制されます。 

考慮する`(0,0)`に`(5,5)`と`k = 5`。 答えは`10`。 不用意にアプローチすると、両方向がブロックに分割され、不必要なターンが追加される可能性がありますが、各方向はすでに 1 つのブロックで完了できます。 

## アプローチ

 簡単なアプローチは、動きをシミュレートすることです。 目的地に向かって繰り返し移動し、到着するたびに`k`一方向への連続移動の場合は、別の方向への移動を挿入してストリークをリセットします。 これにより有効なパスが生成され、最初にターゲットに到達したときに正しい答えが得られます。 

問題はスケールです。 座標の違いとして考えられるのは、`2 * 10^9`そのため、シミュレーションでは 1 つのテスト ケースに対して数十億回の反復が必要になる可能性があります。 と`10^5`場合によっては、最悪のケースが発生する可能性があります`10^14`制限時間をはるかに超えた作戦。 

有益な観察は、2 つの必要な距離のうち大きい方のみが問題を引き起こす可能性があるということです。 大きい方の距離があるとします。`dx`そして小さい方は`dy`。 小さい軸に沿ったすべての動きは、大きい軸に沿った動きのブロックを分離できます。 可能な限り最善の取り決めは、`k`大きい軸に沿って移動し、次に小さい軸に沿って移動し、これを繰り返します。 

最初`dy`小さい軸上で移動して作成します`dy`区切り文字。 までの最終グループもあります`k`大軸は最後のセパレータの後に移動するため、余分な移動なしでカバーできる大軸の合計距離は次のようになります。$$(dy+1) \times k$$もし`dx`最大でもこの値であれば、マンハッタン距離が達成可能です。 

いつ`dx`大きい軸上の残りの距離には、より多くのセパレータが必要です。 追加の大きな軸のブロックの各ペアには、小さな軸上で 2 つの追加の移動が必要です。1 つはターゲット軸から遠ざかる移動、もう 1 つは戻る移動です。 追加のセパレータの移動のペアごとに、別のセパレータの移動が可能になるため、`2k`大きな軸で進行すると、補正を直接計算できます。

 ## アルゴリズムのチュートリアル

 1. 開始座標とターゲット座標の間の絶対距離を計算します。 そのままにしておきます`dx`そして`dy`。 
2. もし`dx`よりも小さいです`dy`、交換します。 この操作の後、`dx`はより長い距離を表し、`dy`距離が小さいことを表します。 軸は対称であるため、この順序でいつでも式を適用できます。 
3. 必要なマンハッタンの移動のみを使用して、長距離のうちどの程度の距離を処理できるかを確認します。 利用可能な容量は、`(dy + 1) * k`。 もし`dx`この値より大きくない場合、答えは単純です。`dx + dy`。 
4. もし`dx`その容量を超える場合は、残りの長軸距離を計算します。 それぞれの追加`2 * k`ユニットではセパレータを作成するために 2 つの追加の動きが必要なため、次を追加します。$$2 \times \left\lceil\frac{dx-(dy+1)k}{2k}\right\rceil$$マンハッタンの距離まで。 

1. マンハッタン距離に計算された補正を加えた値を出力します。 

なぜ効果があるのか:

 利用可能なセパレータを使い果たす可能性があるのは、より大きな軸の移動だけです。 小さい軸の動きはすでに行われている必要があり、そのそれぞれが大きい軸の動きの 1 つのブロックを中断することができます。 最初`(dy + 1)`余分な動きをせずにブロックを完成させることができます。 残りの長軸距離は、最大でも次のサイズのブロックに分割する必要があります。`k`、追加のブロックのペアごとに、小さい方の軸上で 2 つの移動の迂回が必要になります。 この式は、そのような迂回路の最小数を正確にカウントするため、生成される値は達成可能かつ最小限になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    sx, sy, tx, ty, k = map(int, input().split())

    dx = abs(sx - tx)
    dy = abs(sy - ty)

    if dx < dy:
        dx, dy = dy, dx

    ans = dx + dy

    if dx > (dy + 1) * k:
        extra = dx - (dy + 1) * k
        ans += 2 * ((extra + 2 * k - 1) // (2 * k))

    print(ans)

t = int(input())
for _ in range(t):
    solve()
```動きの量のみが重要であるため、コードは最初に座標の変化を距離に変換します。 方向の標識は制限に影響しません。 

スワップにより、より大きな変位に常に名前が付けられます。`dx`。 これにより、水平方向と垂直方向の動きについて 2 つのケースを別々に記述する必要がなくなります。 

条件`dx > (dy + 1) * k`制限が答えに影響を与える唯一の場所です。 false の場合、必要なすべての動きが有効なブロックに収まります。 true の場合、残りの距離は追加のセパレータの移動によって処理されます。 

表現```
(extra + 2 * k - 1) // (2 * k)
```整数の上限除算です。 グループの数を数えます。`2*k`残りの進捗が必要です。 乗算`2`それらのグループを追加の手数に変換します。 

Python の整数には任意の精度があるため、大きな座標値には特別な処理は必要ありません。

 ## 特殊なケース

 次のように、開始とターゲットが同一の場合:```
0 0 0 0 5
```距離は両方ともゼロです。 交換確認後、`dx`そして`dy`ゼロのままです。 容量チェックは false なので、答えはそのままです`0`。 人工的な動きは導入されていません。 

1 つの軸上にのみ存在する動きの場合:```
0 0 10 0 3
```我々は持っています`dx = 10`そして`dy = 0`。 空き容量は、`(0 + 1) * 3 = 3`、したがって、残りの距離は`7`。 それぞれの追加分`2 * 3`進行には 2 つの動きが必要です。`ceil(7 / 6) * 2 = 4`余計な動き。 答えは`10 + 4 = 14`。 

ダイレクト パスがすでに機能している場合:```
0 0 5 5 5
```より長い距離は`5`、距離が小さいほど`5`、容量は`(5 + 1) * 5 = 30`。 距離が長いほど容量が大きくなりますので、答えはまさに`5 + 5 = 10`。 

最大座標範囲の場合:```
0 0 1000000000 0 1
```大きい距離は 10 億、小さい距離は 0 です。 容量はたったの`1`、出発`999999999`カバーするユニット。 天井分割により、`500000000`追加の修正のグループ、追加`1000000000`動きと制作`1999999999`。 Python の整数はオーバーフローしないため、算術演算は安全です。
