 ## 解決策
 ## 問題の理解

 長さの文字列が与えられます$n$英語の小文字で作られています。 文字列を固定の文字位置として扱う代わりに、各文字のいくつかの出現を「選択」し、これらの選択されたインデックスを文字ごとに 1 つずつ、26 のグループに編成することができます。 

文字ごとに$i$、文字列内でその文字が出現するインデックスの空でないサブセットを選択します。 これらの選択されたインデックスは、グローバルな順序付け制約 (文字に対して選択されたすべてのインデックス) を尊重する必要があります。$a$文字の選択されたすべてのインデックスの前に出現する必要があります$b$など、アルファベット順に続きます。 文字内では、その出現のサブセットを自由に選択できますが、文字全体にわたってこの増加するブロック構造を壊すことはできません。 

有効な構造の品質は、各文字に対して選択したインデックスの数によってのみ決まります。 もし$s_i$レター用に選択されたセットです$i$、値は文字のすべてのペアの合計として計算されます。$i < j$の$(|s_i| + |s_j|)^2$。 この値を最大化するか、すべての文字に対して少なくとも 1 つの出現を選択することが不可能な場合は 0 を出力します。 

制約$n \le 2000$これは、サブセットのすべての選択肢に対して重い内部ループを使用して文字ごとに 3 次または 2 次の構築を行う余裕がないことを意味します。 26 個のサブセットすべて、または文字列の 26 セグメントへの可能なすべての分割を列挙しようとするソリューションは、非常に遅すぎます。 のようなものでも$O(26 \cdot n^2 \cdot n)$すでにボーダーラインに達しているため、各レターでの決定を管理可能な移行に減らす構造が必要です。 

重要な微妙な点は、出現する文字をすべて使用する必要はないということですが、出現する文字の数を少なくすると、グローバルな順序付けの制約により、後の文字の実行可能性に影響を与える可能性があります。 もう 1 つの微妙な点は、実現可能性は文字ごとの数だけではなく、元の文字列内の位置に依存することです。 

素朴な間違いは、ポジティブなものを独自に選択できると考えることです。$k_i$文字ごとに、常に意識してください。 これは、文字列内に異なる文字が交互に出現する可能性があり、大きな文字を選択することができないため、失敗します。$k_i$後の手紙をブロックせずに早めに。 

## アプローチ

 ブルートフォースアプローチでは、からの各手紙に対して決定を試みることになります。$a$に$z$、グローバルな順序付け制約を尊重しながら、取得するオカレンスの数と正確にどのインデックスを割り当てるかを決定します。 これはすぐに指数関数的になり、各文字には最大で$O(n)$ブロックに寄与する出現のプレフィックスの選択、およびこれらの選択は 26 文字すべてにわたって相互作用します。 元の文字列内の連続したセグメントに制限しても、おおよその結果が得られます。$O(n^{26})$すべての文字の境界は前の文字の境界に依存するため、単純に実行した場合の -style 構造。 

重要な簡略化は、任意のサブセットという観点から考えるのをやめ、代わりに文字列全体の 1 つのスイープという観点から考えることです。 文字のブロックを「終了」する場所を修正したら$i$、文字に対して選択されたすべての出現$i$前のカットの後の連続した間隔になければなりません。 したがって、各文字がセグメントに寄与します$(prev\_cut, cur\_cut]$、そのセグメント内で、その文字の出現箇所を正確に取得します。 これにより、問題は文字列に沿って 26 個のカット位置 (文字ごとに 1 つ) を選択することになります。 

これにより、構造が文字と位置に関する動的プログラミングに縮小されます。 文字ごとに$i$、そのセグメントがどこで終了するかを決定し、そのセグメントにその文字が少なくとも 1 回含まれていることを確認します。 セグメントの寄与は、その文字がその中に何回出現するかによってのみ決まります。 

最終的な洞察は、目的を純粋にセグメント サイズの観点から書き換えることができ、これにより DP 遷移中の増分計算が可能になるということです。

 ## アルゴリズムのチュートリアル

 文字はアルファベット順に処理されます。 文字ごとに、そのセグメントが文字列内で終了する位置を選択します。 

1. すべての文字について、文字列内でその文字が出現する位置のリストを事前計算します。 また、任意の間隔内に文字が何回出現するかをクエリできるように、プレフィックス数も構築します。$(l, r]$で$O(1)$。 
2. DP 状態を定義する$dp[i][r]$、 どこ$i$すでに割り当てられている文字の数です（から$a$に$i$-番目の文字)、および$r$文字として選択されたセグメントの終了インデックスです$i$。 この状態は、レターの処理を完了する最適な方法を表します。$i$最後に選択したインデックスが の位置にあるようにします。$r$。 
3. 手紙からの移行のために$i-1$位置で終わる$l$手紙を書く$i$位置で終わる$r$、私たちは必要とします$l < r$。 レターのセグメント$i$は$(l, r]$。 私たちは計算します$k_i$、文字の出現数$i$プレフィックス合計を使用してこのセグメント内で。 もし$k_i = 0$、トランジションは無効です。 
4. DP とともに 2 つの実行数量を維持します。$K$、処理された文字全体で選択されたインデックスの合計数、および$S$、セグメントサイズの二乗和。 各 DP 遷移では、以下を使用してこれらの値が更新されます。$$K' = K + k_i,\quad S' = S + k_i^2$$5. 最後に完全な目標を再計算する代わりに、それを段階的に維持します。 現在の値が$V = K^2 + 24S$、次に新しい文字を追加します$k$出現により値は次のように変更されます。$$V' = V + 2Kk + 25k^2$$これにより、各トランジションが一定時間でスコアを更新できるようになります。 
6. 答えは、26 文字すべてを処理した後の最大 DP 値です。 

### なぜ効果があるのか

 DP は、選択されたサブシーケンスの順序において各文字が連続セグメントを占めることを強制します。これは、文字の選択されたすべてのインデックスが、次の文字の選択されたインデックスよりも厳密に前になければならないという制約と同等です。 すべての有効な構造は、セグメント エンドポイントの 1 つのシーケンスに正確に対応し、すべての有効なエンドポイント シーケンスは有効なパーティションを生成します。 

目標の増分式により、各州が将来の拡張を評価するために必要な完全な情報を確実に保持します。 遷移は以前のセグメント内の内部構造ではなく、前のカット位置のみに依存するため、DP 状態は十分であり、隠された情報が失われることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    s = input().strip()

    pos = [[] for _ in range(26)]
    for i, ch in enumerate(s):
        pos[ord(ch) - 97].append(i + 1)

    # prefix counts
    pref = [[0] * (n + 1) for _ in range(26)]
    for c in range(26):
        idx = 0
        for i in range(1, n + 1):
            pref[c][i] = pref[c][i - 1]
            if idx < len(pos[c]) and pos[c][idx] == i:
                pref[c][i] += 1
                idx += 1

    def count(c, l, r):
        if r <= l:
            return 0
        return pref[c][r] - pref[c][l]

    NEG = -10**30

    # dp[i][r] = best value after i letters ending at position r
    dp_prev = [-10**30] * (n + 1)
    dp_prev[0] = 0

    # also track K and S aligned with dp states
    K_prev = [[0] * (n + 1) for _ in range(27)]
    S_prev = [[0] * (n + 1) for _ in range(27)]
    K_prev[0][0] = 0
    S_prev[0][0] = 0

    for i in range(1, 27):
        dp_cur = [-10**30] * (n + 1)
        K_cur = [[0] * (n + 1) for _ in range(1)]
        S_cur = [[0] * (n + 1) for _ in range(1)]

        for r in range(1, n + 1):
            for l in range(r):
                if dp_prev[l] == NEG:
                    continue

                c = i - 1
                k = count(c, l, r)
                if k == 0:
                    continue

                K = K_prev[i - 1][l] + k
                S = S_prev[i - 1][l] + k * k
                val = dp_prev[l] + 2 * K_prev[i - 1][l] * k + 25 * k * k

                if val > dp_cur[r]:
                    dp_cur[r] = val
                    K_prev[i][r] = K
                    S_prev[i][r] = S

        dp_prev = dp_cur

    ans = max(dp_prev)
    print(0 if ans < 0 else ans)

if __name__ == "__main__":
    solve()
```この実装では、文字ごとのプレフィックス カウントが構築され、各遷移が一定時間内に候補セグメント内に文字が何回出現するかをカウントできるようになります。 DP は文字とすべての可能なセグメントの終点を反復処理し、トランジションごとに以前のすべてのカット位置を試行します。 

微妙な点は、DP 値と累積値の両方を保持する必要があることです。$K$そして$S$なぜなら、移行コストは以前のスコアだけでなく、現在選択されている要素の合計数に依存するからです。

 ## 特殊なケース

 重大なエッジ ケースは、一部の文字が文字列にまったく表示されない場合です。 この状況では、各セットが空であってはいけないため、有効なパーティションは存在しません。 すべての DP 遷移では、選択されたセグメント内で少なくとも 1 つの遷移が発生する必要があるため、アルゴリズムはこれらのケースを自然に拒否します。 

別の特殊なケースは、文字が交互に出現するなど、高度にインターリーブされたパターンで出現する場合に発生します。 DP はこれを正しく処理します。これは、現在の文字が少なくとも 1 回出現する有効な連続セグメントが形成できる遷移のみを許可し、すべてのステップで実現可能性が強制されるためです。 

最後のエッジケースは、文字が複数回出現するが、すべての出現が必要なカット境界より前にある場合です。 その場合、ゼロカウントを生成するすべての遷移は破棄され、無効な累積が防止され、実行不可能なパスが正しくブロックされます。
