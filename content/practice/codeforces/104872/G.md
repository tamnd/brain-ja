 ## 問題の理解

 隠された整数のペア、つまり値を扱っています。$x$範囲内で$1 \le x \le 10^9$、およびベース$b$範囲内で$2 \le b \le 2023$。 私たちはどちらも直接見ることはできません。 代わりに、最初に桁数が通知されます。$x$ベースに書かれた場合にあります$b$。 その後、次のように置き換えた場合に桁数がどのように変化するかを問い合わせることができます。$x$と$x + d$、 どこ$d$1 から までの任意の整数です$10^{18}$。 各クエリは基数の数字の長さのみを返します。$b$値そのものではありません。 

課題は両方を回復することです$x$そして$b$このようなクエリは最大 100 個使用します。 

ソリューションを形成する主な制約は、クエリあたりの情報帯域幅が非常に小さいことです。 各答えは単なる整数の桁数であり、値がべき乗を超えた場合にのみ変化します。$b$。 つまり、インタラクション全体がどこで制御されるかということです。$x, x+d, x+2d, \dots$閾値に対して嘘をつく$b^k$。 以来$x \le 10^9$、可能な桁長の数は、大きな基底であってもごくわずかであり、この単調なステップ構造が利用できる唯一の信号です。 

素朴な試みは、$x$桁長クエリを使用して値をバイナリ検索することで直接実行できます。 ただし、桁の長さは任意の基数での加算の滑らかな関数ではありません。 未知の境界線を飛び越える$b^k$したがって、標準の二分探索$x$知らずに一貫性を保つことはできません$b$。 もう一つの素朴な考えは推測することです$b$そして再構築する$x$、 しかし$b$には 2,000 を超える可能性があり、各検証には制限を超える多くのクエリが必要になります。 

異なるペアの場合、微妙な失敗のケースが発生します。$(x, b)$小さなシフトに対して同一のローカル桁長動作を生成します。 たとえば、小さい$x$大きな基数では、長い範囲の加算にわたって一定の桁の長さのように動作するため、より大きな基数と区別できなくなります。$x$ベースパワーの境界付近を慎重に調査しない限り、わずかに小さなベースで発生します。

 ## アルゴリズムのチュートリアル

 のべき乗を交差するときに桁の長さが正確に変化することを利用します。$b$したがって、隠された番号に関するすべての情報はこれらのしきい値にエンコードされます。 

1. まず、小さな増分をクエリします。$d = 1, 2, 4, 8, \dots$(倍増戦略) 初期値と比較して桁の長さが増加することが検出されるまで。 そのような最初の$d$次の累乗がどのくらい遠くなるかのおおよそのスケールを与えます。$b$境界線はからです$x$。 このステップは、境界が存在することが保証されている領域を特定するために必要です。 
2. 桁の変化が発生する範囲がわかったら、その範囲内で二分探索を行って最小のものを見つけます。$d$桁の長さが長くなります。 これにより、からの正確な距離が特定されます。$x$次の力へ$b^k$。 これが機能する理由は、桁の長さが単調であるためです。$x+d$、したがって、述語「桁の長さは増加しますか」は単調です$d$。 
3. この臨界距離を次のようにします。$D$。 そうすればわかります$x + D = b^k$一部の人にとっては$k$。 この時点で、私たちは回復のアンカーであるベースの純粋な力を発見しました。$b$。 
4. ここで、連続累乗が次の条件を満たすという事実を利用します。$b^{k} / b^{k-1} = b$。 辺りを調べてみると$x + D$慎重に選択されたオフセットを使用すると、次のように推測できます。$b$次の桁の境界を越えるのに必要な増分数をテストすることにより、$b^k$。 これにより隔離されます$b$なぜなら、真の塩基のみが閾値間に一貫した間隔を生成するからである。 
5. 1回$b$既知なので計算します$k$桁の長さから 1 を引いた値です。$b^k$は最小の数です$k+1$底の数字$b$。 
6. 最後に回復します$x = b^k - D$。 

### なぜ効果があるのか

 正確さは、桁長の変更が正確な累乗でのみ発生するという構造に依存します。$b$。 すべてのクエリは、数直線をこれらの累乗で区切られた区間に分割します。 二分探索の終わり$d$述語「桁長が増加する」が単調であるため、これは有効です。$d$、一度パワー境界を越えると、より大きな値はすべて上位桁領域に留まるためです。 ひとつの力があれば$b^k$が特定されると、連続累乗の乗法構造が一意に決定されます。$b$なぜなら、他の整数基底は同じ桁長ジャンプの間隔パターンを生成しないからです。

    base_len = n

        hi *= 2

        else:

    k_plus_1 = ask(D)
    k = k_plus_1 - 1

            if v == val:

            if v < val:

            else:
