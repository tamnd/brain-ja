 ## 解決策
 ## 問題の理解

 Katya は固定文字列を入力したいと考えていますが、キーボードの一部のキーが定期的に動作しなくなることがあります。 各壊れた文字キーを押しても、毎回確実に文字が生成されるわけではありません。 代わりに、一定のサイクルで失敗と成功を繰り返します。キーは 1 回押しても何も生成されず、一定回数押すと正しい文字が生成され、その後もう一度失敗し、このパターンを永久に繰り返します。 

その結果、Katya が壊れたキーを押すたびに、そのキーのサイクルの現在位置に応じて、実際にエッセイにキャラクターを貢献できる場合とそうでない場合があります。 サイクルの長さは、そのキーの指定されたパラメーターによって決まります。 目標は、サイクルが最初にどのように揃っているかに関係なく、ある程度の回数押した後、Katya がターゲット文字列全体を生成することを保証することです。 

入力によりターゲット文字列が与えられ、壊れたキーのリストとそのサイクル長が与えられます。 出力は、すべてのサイクルで考えられる最悪の位置合わせで文字列が完全に生成されることを保証する、キーを押す最小回数です。 

文字列の長さは最大 100,000 ですが、壊れたキーは最大 26 個です。 これは、どのような解も文字列の長さにキーの数を加えたものが線形である必要があることを強く示唆しています。 文字列の長さを超える二次関数は遅すぎます。 

重要な点は、文字列内の各文字が対応するキーのサイクルによって独立して影響を受けますが、サイクルを敵対的に揃えることができることです。 状態空間は壊れたキーの数で指数関数的であるため、考えられるすべての位相の組み合わせを追跡しようとする単純なシミュレーションは不可能です。 

もう 1 つの微妙な問題は、さまざまな文字が独立しているものの均一ではないことです。壊れている文字もあれば、壊れていない文字もあります。 途切れのない文字は、印刷ごとに常に正確に 1 文字を生成するため、決定論的に寄与します。 壊れたキーのみが遅延を引き起こします。 

## アプローチ

 直接的なアプローチでは、キーを押すごとに入力プロセスをシミュレートし、壊れた各キーがそのサイクルのどこにあるかを追跡します。 ターゲット文字列内で文字に遭遇するたびに、次に必要なその文字が出現するまで、対応するキーを押し続けます。 サイクルは周期的であるため、最悪の場合の位相調整も考慮する必要があります。つまり、必要なときにキーが障害状態になる可能性があります。 

このシミュレーションのアイデアは本質的には正しいですが、最悪の場合、各文字に最大 O(x_i) 回の無駄なプレスが必要になる可能性があり、文字列の長さが長くなる可能性があるため、破綻しています。 さらに悪いことに、複数の文字にわたる相互作用により、単純なシミュレーションが曖昧になります。私たちは単一の決定論的プロセスをシミュレートしているのではなく、すべての初期段階にわたる最悪の場合の保証を計算しています。 

重要な洞察は、文字を区切ることです。 各文字は、必要な印刷の合計に独立して寄与します。 文字が壊れていない場合は、押すたびに 1 文字が反映されるため、1 回の出現につき 1 回押すだけで済みます。 パラメーター x を持つ壊れた文字の場合、動作は周期的です。x を押すすべてのブロックで、x-1 のみが出力を生成します。 これは、最悪の場合の効率が (x-1)/x であることを意味し、同様に、k 回の成功した出力を保証するには、時折発生する強制的な無駄なプレスを考慮する必要があります。 

より具体的には、どのような一連の押下においても、壊れたキーを x 回連続して押す各ブロックには、正確に 1 つの失敗が含まれます。 敵対的な観点から見ると、x を押すたびに x-1 回の有用な出力のみが保証されるため、k 回の発生を生成するには、それらの発生に分散される避けられない失敗の数に等しい追加の押下を支払う必要があります。

これにより、問題は、各文字について、文字列内に出現する回数と、そのサイクルによって引き起こされるコストインフレ係数を乗算した値を合計することになります。 微妙な部分は、最悪の場合の調整により、Katya が成功した出力を必要とするときに敵が正確に失敗を配置できることです。これにより、文字の頻度ごとに天井分割効果が効果的に追加されます。

 | サイクルのブルート フォース シミュレーション | O( | s | · max x_i) |
 | 文字ごとの頻度ベースの演算 | O( | s | + n) |

 ## アルゴリズムのチュートリアル

 1. ターゲット文字列内の各文字の頻度を数えます。 これにより、各キーに必要な出力の数が個別に分離されます。 
2. 壊れたキーごとにサイクル パラメータ x を保存します。 文字が壊れていない場合は、その x を 1 として扱います。これは、すべてのプレスが成功したことを意味します。 
3. 各文字について、x 回のプレスのうち 1 回が最悪の位置合わせで無駄になるサイクルの下で、その頻度を確実に生成するために必要なプレスの回数を計算します。 これは、必要な出力を完全な生産ブロックに分割し、それらの間に挟まれた避けられない失敗プレスを考慮するものとしてモデル化できます。 
4. すべての文字にわたるプレスの合計数を累積します。 
5. 合計をキーストロークの最小保証数として返します。 

重要なステップは、定期的な故障を決定論的な算術コストに変換することです。 フェーズを追跡する代わりに、必要なすべてのプレスの成功の前に、サイクル構造が許す限り多くの失敗が発生するという最悪の場合の同期を想定します。 

### なぜ効果があるのか

 壊れたキーはそれぞれ、x 回押すごとに 1 回だけ失敗するという固定の定期的なスケジュールで動作します。 長いシーケンスにわたって、総プレス数に対する失敗の割合は一定です。 敵対者はいつでも障害位置を調整して、必要な出力に対する無駄な労力を最大化できますが、サイクル ウィンドウごとに 1 つの障害を超えることはできません。 したがって、k 個の出力を生産するための総コストは、周期損失が k に達した後の「実効歩留まり」が正確に最小のプレス機の数になります。これは、必要な出力をサイクル全体に分配し、完全な各ブロックでの必須の故障を考慮することによって取得されます。 

これにより、動的なスケジューリングの問題が、静的な文字ごとの算術計算に変わります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = int(input())
    
    x = {}
    for _ in range(n):
        c, v = input().split()
        x[c] = int(v)
    
    freq = {}
    for ch in s:
        freq[ch] = freq.get(ch, 0) + 1
    
    ans = 0
    
    for ch, cnt in freq.items():
        if ch in x:
            v = x[ch]
            full = cnt // (v - 1)
            rem = cnt % (v - 1)
            ans += full * v + rem
        else:
            ans += cnt
    
    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションでは、まずターゲット文字列の頻度マップを構築します。 これにより、位置ではなくカウントのみが重要となるため、順序の問題が回避されます。 次に、壊れたキーのサイクル長を O(1) アクセスの辞書に読み取ります。 

各キャラクターの重要な考え方は、サイクルごとに 1 回の強制失敗により、x-1 回の成功した出力のグループごとに x 回のプレスで支払いを受ける必要があるということです。 式 full * v + rem は、完全なサイクルを満たさない残りの文字を考慮しながら、必要な出力をサイクルにパッキングすることを実装します。 

よくある落とし穴は、途切れていない文字は暗黙的に x = 1 として扱われなければならないことを忘れていることです。そうしないと、ゼロによる除算や不正なインフレーションが発生します。 もう 1 つの微妙な点は、整数の除算でフロア動作が確実に使用されるようにすることです。これは、使用可能な出力の完全なサイクルがどのように形成されるかに一致します。

 ## 特殊なケース

 最小限のエッジケースは、壊れたキーがない場合です。 この場合、すべての文字は 1 回の押下に寄与するため、答えは文字列の長さと等しくなければなりません。 辞書 x が空であり、すべての文字がデフォルトのケースに該当するため、アルゴリズムはこれを処理します。 

もう 1 つのエッジ ケースは、x = 2 の 1 つの壊れた文字だけで構成される文字列です。成功するすべての文字には失敗と成功が交互に繰り返される必要があるため、k 個の文字を生成するには、最悪の位置合わせで正確に 2k - 1 回押す必要があります。 式 full * v + rem は、最後の出力を除く各出力と必須の無駄なプレスを組み合わせることで、このパターンを正しく再現します。 

最後のエッジケースは、x が周波数と比較して大きい場合です。 cnt < x - 1 の場合、完全なサイクルは存在せず、攻撃者は初期の位置ずれを超えて部分サイクル内で完全な失敗を強制できないため、答えは単純に cnt になります。 剰余項 rem は、オーバーカウントせずにこのケースを直接捉えます。
