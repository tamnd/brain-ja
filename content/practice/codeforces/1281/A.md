 ## 解決策

 ## 問題の理解

 複数の独立した文が与えられます。 各文は、スペースの代わりにアンダースコアを使用して単語が結合された単一の文字列です。 私たちの仕事は、文の終わり方だけを見て、各文を 3 つの言語のいずれかに分類することです。 

分類ルールは純粋に接尾辞ベースです。 文が特定の固定パターンで終わる場合、それを言語名にマッピングします。 語尾までの文の構造はまったく重要ではなく、最後の文字だけが答えを決定します。 

制約は小さく、最大 30 文、各最大 1000 文字です。 これにより、各文字を検査したり、テスト ケースごとに定数時間のサフィックス チェックを実行したりするソリューションは、十分に高速であることがすぐにわかります。 文字列ごとにすべての可能なサフィックス一致をチェックする素朴なアプローチであっても、合計作業量が約 30,000 文字に制限されるため、これらの制限の下では簡単です。 

注意すべき微妙なエッジケースは、文字列の最後にあるサフィックスのみと一致し、誤って文字列内で一致しないようにすることです。 たとえば、「po」を単純に検索すると、語尾のみが重要となるため、間違っています。 もう 1 つの潜在的な落とし穴は、サフィックスの長さが重複していることです。 たとえば、「ます」と「です」は両方とも日本語を示すため、実装では単一の固定接尾辞長を想定せずに両方を正しくチェックする必要があります。 

## アプローチ

 強引な解釈では、各文をスキャンし、最後から文字を手動で比較することにより、既知の接尾辞のいずれかで終わっているかどうかを確認します。 各文字列について、スライスして等しいかどうかを確認することで、すべてのサフィックスと比較できます。 サフィックス候補が 4 つしかないため、このアプローチではテスト ケースごとに最大 4 つの比較が実行され、最悪のケースでは各比較が O(L) になります (L がサフィックスの長さ)。 L の境界が 1000 であっても、これは依然として非常に小さいです。 

重要な点は、前処理や複雑な解析が必要ないということです。 問題は完全に、文字列がいくつかの固定パターンのいずれかで終わるかどうかをチェックすることに帰着します。 つまり、接尾辞の比較演算を直接使用できるということです。 入力の構造により、正確に 1 つのサフィックスが一致することが保証されるため、あいまいさの処理や優先順位のルールは必要ありません。 

ブルート フォースから最適な方法への移行は、基本的に、決定空間のサイズが一定であることを認識することです。 スキャンや解析を行う代わりに、各テスト ケースを少数の文字列比較に削減します。

 ## アルゴリズムのチュートリアル

 各文を個別に処理し、接尾辞チェックを使用して言語を判断します。 

1. テスト ケースの数を読み取ります。 これにより、実行する独立した分類操作の数が定義されます。 
2. 各文について、接尾辞「mnida」で終わっているかどうかを確認します。 存在する場合は、「KOREAN」を出力します。 このチェックは一意であり、他のサフィックスとの不必要なあいまいさを避けるため、最初に実行されます。 
3.「ムニダ」で終わっていない場合は、「です」で終わるか「ます」で終わるかを確認してください。 どちらかの条件が成立した場合は「JAPANESE」を出力します。 これら 2 つの接尾辞は同じ言語グループに属しているため、OR 条件を使用して論理的に結合されます。 
4. 上記のどちらにも一致しない場合、文は「po」で終わる必要があるため、「FILIPINO」を出力します。 この問題により、すべての入力が有効なサフィックスの 1 つで終わることが保証されるため、フォールバック検証は必要ありません。

接尾辞はあいまいさを引き起こすような形で重複していないため、この問題ではチェックの順序は厳密には必要ありませんが、接尾辞を明示的に記述することでロジックが明確に保たれ、ルールが拡張された場合に偶発的な誤分類が回避されます。 

### なぜ効果があるのか

 各文は、固定セットからの 1 つの有効な接尾辞で終わることが保証されています。 接尾辞の等価性は決定論的な特性であるため、言語を一意に識別するには、最後の文字を直接チェックするだけで十分です。 このアルゴリズムは、有効な文は最後に複数の言語接尾辞と一致できないという不変式に依存しているため、最初の一致条件は常に正しいです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    s = input().strip()

    if s.endswith("mnida"):
        print("KOREAN")
    elif s.endswith("desu") or s.endswith("masu"):
        print("JAPANESE")
    else:
        print("FILIPINO")

条件の順序は、サフィックスの論理グループを反映しています。 韓国語は単一接尾辞の明確なカテゴリであるため、最初にチェックされます。 次に日本語は、結合された OR 条件を使用して処理されます。 この問題によりサフィックス セットの完全性が保証されるため、フィリピン語がデフォルトのケースになります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        s = input().strip()
        if s.endswith("mnida"):
            out.append("KOREAN")
        elif s.endswith("desu") or s.endswith("masu"):
            out.append("JAPANESE")
        else:
            out.append("FILIPINO")
    return "\n".join(out)

 ## 特殊なケース

 特殊なケースの 1 つは、文が非常に短く、接尾辞自体のみで構成されている場合です。 たとえば、入力`po`それでも正しくフィリピン人として分類されるはずです。 アルゴリズムはこれを自然に処理します。`endswith("po")`は、文字列全体がちょうど 2 文字の場合でも true です。 

もう 1 つのエッジ ケースは、複数の接尾辞パターンが文の前半で部分文字列として出現する可能性がある場合です。 例えば、`po_desu_mnida_po`内部には 3 つのトークンがすべて含まれていますが、重要なのは最後のサフィックスのみです。 文字列全体をスキャンするのではなく、末尾のみをスキャンするので、この実装は正しいです。 

最後の特殊なケースは、サフィックスの長さが重複していることです。 以来`"desu"`そして`"masu"`言語は同じですが語尾が異なるため、両方を明示的にチェックする必要があります。 OR 条件により、両方が同等に扱われることが保証され、最後の一致のみが重要となるため、優先順位の問題は発生しません。
