 ## 解決策
 ## 問題の理解

 各頂点が値を保持するルート付きツリーが与えられます。 この構造は親子関係を定義し、すべてのノードはルートからの 1 つのパス上に存在します。 

どのノードについても、ルートからそのノードに至るまでに遭遇する一連の値を考慮してください。 タスクは、ルートからノードへのパスに沿った値から形成できる、厳密に増加する最長のサブシーケンスの長さをノードごとに計算することです。 サブシーケンスは連続している必要はなく、パスに沿った順序のみが維持される必要があります。 

出力は各ノードの LIS 長であり、通常はノード インデックスの順に出力されます。 

主な制約の意味は、ノードごとに LIS を個別に再計算する単純なアプローチでは、重複するパスを繰り返し処理することになるということです。 各パスの長さは O(n) になるため、チェーン形状のツリーでは O(n^2) の作業が必要になります。 一般的な Codeforce ツリーの問題では n が約 200,000 に達するため、二次または二次に近い手法は実行不可能です。 目的のソリューションでは、すべてのノードをほぼ線形または n log n 時間で処理し、理想的には DFS トラバーサルに沿って計算を共有する必要があります。 

値の繰り返しと分岐構造では、微妙な問題が発生します。 たとえば、値が異なるブランチに沿って繰り返される場合、ロールバックせずにグローバル状態を誤って再利用するソリューションでは、無関係なパス間で情報が混合されてしまいます。 

小さなケースを考えてみましょう。 

入力ツリー:

 1(3)

 ━─2(1)

 ━─3(2)

 ノード 3 の場合、パスは値 [3,1,2] で 3 → 1 → 2 で、LIS の長さは 2 です。状態を復元しない単純な「グローバル LIS」更新では、兄弟ブランチからの影響が誤って伝達され、単一のルートからノードへのパス上にないシーケンスが過剰にカウントされる可能性があります。 

## アプローチ

 ブルート フォース ソリューションでは、各ノードが個別に処理されます。 固定ノードの場合、ルートからそのノードまで歩き、パス上のすべての値を収集し、テールの一時配列を使用して標準 LIS アルゴリズムを O(k log k) で実行します。 これをすべてのノードに対して繰り返すと、歪んだツリーの合計複雑さは O(n^2 log n) になります。 標準 LIS 手順を使用して各ノードが独立して解決されるため、正確性は簡単です。 

ボトルネックは冗長性です。 隣接するノードはパスのほぼ全体を共有するため、LIS を最初から再計算すると、同一のプレフィックスに対して無駄な作業が行われます。 

重要な観察は、DFS がルートから現在のノードへのパスを段階的に自然に構築するということです。 現在の DFS パスの LIS 構造を維持する場合、ノードごとに O(log n) で更新し、バックトラック時に復元できます。 私たちが維持する LIS 構造は、古典的な「忍耐ソート尾部配列」です。ここで、tails[len] には、長さ len の増加するサブシーケンスの最小可能な終了値が格納されます。 

DFS 中にノードに入ると、二分探索を使用してその値をこの構造に一時的に挿入します。 ノードを離れると、前の状態が復元されます。 これにより、すべてのノードが 1 回の挿入と 1 回のロールバックに寄与することになり、全体として O(n log n) のソリューションが得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2 log n) | O(n) | 遅すぎる |
 | DFS + LIS ロールバック | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ツリーのルートをノード 1 に設定します。動的配列を維持します。`tails`、 どこ`tails[i]`長さが増加するサブシーケンスの可能な最小の終了値です。`i+1`現在の DFS パスに沿って。 

回答配列も維持しています`ans`各ノードごとに。 

1. DFS をルートから起動します。 ノードに入る前に、`tails`は空です。 これは、現在のパスに沿った空のサブシーケンスを表します。 
2. ノードで`u`、位置を特定します`pos`どこ`a[u]`に挿入できます`tails`二分探索を使用します。 この位置は最初のインデックスです。`tails[pos] >= a[u]`。 
3. もし`pos`現在の長さに等しい`tails`を追加して構造を拡張します。`a[u]`。 それ以外の場合は交換いたします`tails[pos]`と`a[u]`。 
4. ノードの LIS 長`u`は`pos + 1`これは、DFS パスのこの時点で終了する最適なサブシーケンスを表すためです。 これを保存します`ans[u]`。 
5. のすべての子を再帰します。`u`、更新を維持する`tails`。 各子は、同じルートから現在のノードへのパスを拡張します。 
6. すべての子孫を終了した後、`u`、復元しなければなりません`tails`処理前の状態に戻す`u`。 これは、古い値のスナップショットを作成するか、追加したか置換したかを注意深く追跡することにより、ステップ 2 と 3 で行われた変更を元に戻すことによって行われます。 

正確かどうかは、どの DFS ノードでも、`tails`は、ルートから現在のノードへのパス上の 1 つの有効な増加サブシーケンス構造を表します。 親に戻る前に状態を復元するため、異なるブランチの値が混在することはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

from bisect import bisect_left

def solve():
    n = int(input())
    a = [0] + list(map(int, input().split()))
    
    g = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)

    ans = [0] * (n + 1)
    tails = []

    def dfs(u, p):
        # find insertion position
        pos = bisect_left(tails, a[u])
        
        old = None
        replaced = False
        
        if pos == len(tails):
            tails.append(a[u])
        else:
            old = tails[pos]
            tails[pos] = a[u]
            replaced = True
        
        ans[u] = pos + 1
        
        for v in g[u]:
            if v == p:
                continue
            dfs(v, u)
        
        # rollback
        if replaced:
            tails[pos] = old
        else:
            tails.pop()

    dfs(1, -1)
    print(*ans[1:])

if __name__ == "__main__":
    solve()
```DFS は単一のグローバルを維持します。`tails`現在のルートからノードへのパスの状態を表す配列。 重要な実装の詳細はロールバック メカニズムです。配列を拡張した場合はポップします。 要素を置き換えた場合は、前の値が復元されます。 これにより、分岐再帰全体での正確性が保証されます。 

よくある間違いはそれを忘れることです`tails`アクティブな再帰パスのみを反映する必要があります。 修復を行わない共有突然変異は兄弟サブツリーを汚染します。
