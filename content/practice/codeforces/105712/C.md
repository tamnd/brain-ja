 ## 解決策
 ## 問題の理解

 それぞれに整数配列が含まれるいくつかのテスト ケースが与えられています。 タスクは、特定の「バランス」条件を満たす連続したサブ配列の数を数えることです。つまり、2 つのエンドポイントの合計は、厳密にそれらの間のすべての要素の合計に等しくなります。 

形式的には、インデックスからのセグメントの場合$l$に$r$と$l < r$, 左端の値と右端の値を足した値が中央の値の合計と等しいかどうかを確認します。 単一要素セグメントは、比較する両端がないため、自動的に無効になります。 

条件をより便利な代数形式で書き直すと役立ちます。 部分配列の総和を次のようにします。$S(l,r)$。 条件には次のように書かれています。$$a_l + a_r = S(l,r) - a_l - a_r$$これを再配置すると次のようになります。$$S(l,r) = 2(a_l + a_r)$$したがって、問題はすべてのペアを数えるということになります$(l, r)$区間の合計がそのエンドポイントの合計の 2 倍に等しくなるようにします。 

制約により、最大で$2 \cdot 10^5$テストケース全体の配列の合計サイズ。 これにより、すべての部分配列にわたる二次関数またはそれより悪い解が排除されます。 すべてを超えた強引な力$(l, r)$ペアは約について検討します$O(n^2)$テストケースごとの間隔、これでは遅すぎます。$n = 2 \cdot 10^5$一度でも。 

すべての有効な条件は部分配列の合計に依存するため、接頭辞の合計の考え方は必須です。 課題は、条件がエンドポイントと内部の両方に依存するため、プレフィックスの合計を直接比較しても、プレフィックス値間の単純な等価性がすぐには得られないことです。 

素朴な考えを打ち破るようなエッジケースはすぐに現れます。 

1 つはすべての要素がゼロの場合です。 両辺が 0 であるため、少なくとも 2 の長さのすべての部分配列が有効です。 たとえば、`[0, 0, 0]`の場合、長さ ≥ 2 の 3 つの部分配列はすべて有効であるため、答えは 3 になります。単純な解決策では、長さの制約を見逃したり、セグメントを二重にカウントしたりする可能性があります。 

もう 1 つのケースは、配列に要素が 1 つだけある場合です。`[5]`。 有効な部分配列が存在しないため、正解は 0 です。 を忘れたいくつかの処方$l < r$制約が誤って有効としてカウントされます。 

より微妙な問題は、値が交互に複数の有効な重複セグメントを作成する場合に発生します。`[1, 0, 1, 0, 1]`。 多くの候補サブアレイが条件を満たしますが、それらは明らかなパターンで局所化されていないため、貪欲なスキャン手法は失敗します。 

## アプローチ

 ブルートフォースソリューションでは、すべてのペアを列挙します。$(l, r)$、プレフィックス合計を使用して部分配列の合計を計算し、条件を確認します。 それぞれの合計を計算する$O(1)$合計を作る$O(n^2)$テストケースごとに。 と$2 \cdot 10^5$要素の合計、これはおおよそ次のようになります$10^{10}$最悪の場合は運用が不可能になります。 

重要な観察は、条件を書き換えることから得られます。$$S(l,r) = 2(a_l + a_r)$$プレフィックスサムの使用$P[i]$、 どこ$S(l,r) = P[r] - P[l-1]$、次のようになります。$$P[r] - P[l-1] = 2a_l + 2a_r$$並べ替え:$$P[r] - 2a_r = P[l-1] + 2a_l$$これは重要な変換です。右端の変換値が左端の変換値から 1 位置を引いた値と一致する場合、すべての部分配列は有効です。 

定義する：$$F(i) = P[i] - 2a_i$$すると条件は次のようになります。$$F(r) = F(l-1) + 2a_l$$これにはまだ依存関係があります$a_l$そこで、エンドポイントの寄与をプレフィックス状態の表現にシフトすることで、視点をさらに洗練させます。 両方のエンドポイントを対称的に分離しようとする代わりに、左から右に処理し、以前の位置が将来の右エンドポイントの有効な左境界としてどのように機能するかを維持します。 

より現実的な観点は、正しいエンドポイントを修正することです$r$。 すると条件は次のようになります。$$P[r] - 2a_r = P[l-1] + 2a_l$$それぞれについて$r$、以前の位置を見つける必要があります$l$この等式を満たすもの。 これは、次の形式の候補値の追跡として再構成できます。$P[i] + 2a_{i+1}$インデックスをどのようにシフトするかによって異なります。 

重要な構造的洞察は、すべての有効なサブ配列を、その右端にあるプレフィックス由来のキーと、その左端の事前計算されたキーのセットとの間の関係に分解できるということです。 これにより、配列を 1 回繰り返す間にハッシュ マップ内のプレフィックス状態のカウントを維持するという問題が軽減されます。 

ブルート フォースは各ペアが明示的にチェックされるため機能しますが、合計を繰り返し再計算するため失敗します。 プレフィックス ID への変換により、各チェックが定数時間の検索に変わり、問題が線形時間に短縮されます。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. 配列を反復処理しながらプレフィックスの合計を計算するため、任意の部分配列の合計を定数時間で表現できます。 これにより、重複する間隔に対して繰り返し合計を再計算することが回避されます。 
2. 潜在的な左端点から導出された、変換されたプレフィックス状態の頻度を格納するハッシュ マップを維持します。 これらの状態は、開始インデックスが将来の有効な部分配列にどのように寄与するかを表します。 
3. ポジションごとに$r$、バランス状態への寄与をキャプチャする適切なエンドポイントから導出される値を計算します。具体的には、$P[r] - 2a_r$。 これは、一致する左境界の「必要なパートナー値」を表します。 
4. この要件に一致する以前の状態の数をハッシュ マップに問い合わせます。 各一致は、次で終わる有効なサブ配列に対応します。$r$, そのため、その頻度を答えに追加します。 
5.加工後$r$、インデックスの寄与を挿入します$r$潜在的な将来の左エンドポイントとして。 これにより、サブ配列が次から始まることが保証されます。$r+1$後で正しくペアリングできます。 

順序付けは重要です。単一の要素がそれ自体と誤ってペアにならないように、更新の前にクエリが実行されます。 

### なぜ効果があるのか

 アルゴリズムは、すべてのインデックスに対して不変条件を維持します。$i$、ハッシュ マップには、厳密に現在位置の左側にあるすべての有効な左境界に対応するプレフィックス由来の状態のセットが正確に含まれています。 加工時$r$、で終わるすべての有効なサブ配列$r$変換された等価条件を満たす、以前に保存された状態と 1 対 1 に対応します。 変換は元のバランス条件と代数的に等価であるため、有効な部分配列が失われることはなく、無効なペアはカウントされません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        pref = 0
        freq = {}
        freq[0] = 1

        ans = 0

        for x in a:
            pref += x

            key = pref - 2 * x

            ans += freq.get(key, 0)

            left_key = pref - 2 * x
            freq[left_key] = freq.get(left_key, 0) + 1

        print(ans)

if __name__ == "__main__":
    solve()
```この実装は、実行中のプレフィックス合計と変換された状態の頻度テーブルを維持します。 変数`key`現在の位置で終わる有効な部分配列に必要なものを表し、`freq`互換性のある左側の境界が出現する頻度をカウントします。 

微妙な点は、長さ 1 の部分配列が決してカウントされないように、クエリ後にマップが更新されるようにすることです。 もう 1 つは、合計が次の値に達する可能性があるため、概念的に 64 ビット整数を使用する方法です。$10^{14}$ですが、Python の整数はすでにこれを安全に処理しています。

 ## 特殊なケース

 長さが 1 の配列の場合、ループは引き続き実行されますが、右端点が別個の左端点とペアにならないため、有効な部分配列は形成できません。 更新は各要素の処理後にのみ行われ、一致する以前の状態がないため、ハッシュ マップ メカニズムでは一致が生成されません。 

すべてゼロの配列の場合、すべてのプレフィックスの状態が同一になり、すべての新しいインデックスが以前のすべてのインデックスと一致します。 このアルゴリズムは、インデックスのすべてのペアが有効なバランスの取れたサブ配列を形成するという事実を反映して、周波数の増加を通じて三角数を正確に累積します。 

交互配列または対称配列の場合、プレフィックス変換が正確に一致する場合にのみ一致が表示され、ハッシュ マップにより有効な履歴構成のみが寄与することが保証され、互換性のないエンドポイントの誤ったペアリングが回避されます。
