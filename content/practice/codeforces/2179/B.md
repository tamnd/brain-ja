 ## 解決策
 ## 問題の理解

 Blackslex が順番に訪問する必要がある一連のフロアが与えられており、フロア間の移動には、連続するフロア間の絶対差に比例して時間がかかります。 Blackslex はシーケンス内で最大 1 フロアをスキップできます。 目標は、スキップする最適なフロアを選択した場合に達成できる最小合計時間を計算することです。 

形式的には、フロア番号を表す整数の配列の場合、デフォルト時間は連続する要素間の絶対差の合計です。 単一の要素を削除する$a_k$合計を隣接する 2 つの差の合計で減算します。$|a_{k-1}-a_k| + |a_k - a_{k+1}|$それを単一のジャンプに置き換えます$|a_{k-1}-a_{k+1}|$。 合計を最小化するには、どのフロアを削除するかを決定する必要があります (存在する場合)。 

制約により、最大で$2 \cdot 10^5$すべてのテスト ケースにわたるフロアと、各テスト ケースには最大で$2 \cdot 10^5$床。 合計から$n$すべてのテストケースで次を超えない$2 \cdot 10^5$、テスト ケースごとに各フロアを一定回数処理するソリューションは効率的に実行されます。 これにより、以下を含むアルゴリズムが除外されます。$O(n)$テストケースごとに。 

削除するのに最適なフロアがアレイの最初または最後である場合、明らかではないエッジ ケースが発生します。 最初または最後のフロアをスキップすると、2 つの違いが結合されるのではなく 1 つの違いだけが削除されるため、これを慎重に考慮する必要があります。 たとえば、与えられた$a = [1, 100, 2]$、真ん中の床を取り除くと時間がかかります$|1-2| = 1$ただし、最初または最後の要素を削除しても、1 から 100 までの最大値は減少しません。スキップされる要素が境界に存在しないと想定する不注意な実装では、正しい最小値を見逃す可能性があります。 

## アプローチ

 ブルートフォース ソリューションでは、削除できるすべてのフロアを反復処理します。 候補フロアごとに$k$、隣接する 2 つの差分を調整して除去した後、絶対差分の合計を計算します。 この方法は、考えられるすべてのスキップを正確にシミュレートするため機能しますが、次のことが必要です。$O(n^2)$すべての候補について合計を最初から再計算すると、最悪の場合、時間がかかります。 のために$n \approx 2 \cdot 10^5$、これでは遅すぎます。 

重要な洞察は、床を取り除くことの効果です。$a_k$ローカルです。 合計額は次のように減少します$|a_{k-1}-a_k| + |a_k - a_{k+1}|$そして増加します$|a_{k-1}-a_{k+1}|$。 したがって、差の合計を一度事前に計算し、その後、可能なスキップを繰り返すことができます。$O(n)$各候補の変化を計算することによって。 この観察により、複雑さが軽減されます。$O(n^2)$に$O(n)$テストケースごとに。

 | ブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 合計して初期合計時間を計算します。$|a[i+1]-a[i]|$のために$i = 0$に$n-2$。 これにより、フロアをスキップすることなく時間が得られます。 
2. 変数を初期化する`min_time`この合計で。 
3. 2 番目のフロアから最後から 2 番目のフロアまで (インデックス 1 から n-2) を繰り返します。 各フロアごとに$a[i]$、スキップした場合のコスト削減を計算します。変化は次のとおりです。`abs(a[i-1]-a[i]) + abs(a[i]-a[i+1]) - abs(a[i-1]-a[i+1])`。 
4.アップデート`min_time`現在の値と合計からこの減少を差し引いた値の最小値になります。 
5. エッジフロアは個別に扱ってください。 最初のフロアをスキップすると最初の差分のみが減少し、最後のフロアをスキップすると最後の差分のみが減少します。 これらの削減を比較してください`min_time`。 
6. 出力`min_time`テストケース用。 

この正しさは、要素を削除すると、そのすぐ隣の要素にのみ影響するという観察から得られます。 合計を 1 回計算してからスキップ候補を調整すると、合計時間に対する影響が正確に把握されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        total = sum(abs(a[i+1]-a[i]) for i in range(n-1))
        min_time = total
        
        # consider skipping each interior floor
        for i in range(1, n-1):
            reduction = abs(a[i-1]-a[i]) + abs(a[i]-a[i+1]) - abs(a[i-1]-a[i+1])
            min_time = min(min_time, total - reduction)
        
        # consider skipping first or last floor
        min_time = min(min_time, total - abs(a[1]-a[0]))
        min_time = min(min_time, total - abs(a[n-1]-a[n-2]))
        
        print(min_time)
```コードはまず入力を読み取り、絶対差の初期合計を計算します。 次に、内部のフロアを反復処理し、各フロアをスキップすることによる純利益を計算します。 最後に、最初または最後のフロアをスキップした場合の利益と比較します。 使用する`min()`不必要な条件なしでグローバル最小値が見つかることを保証します。 高速 I/O は、大きな入力サイズを効率的に処理します。

**サンプル 2:**`a = [2, 4, 8]`中央をスキップ: |2-4| + |4-8| - |2-8| = 2 + 4 - 6 = 0、合計 - 0 = 6? 最初に合計の計算を待ちます: |4-2| + |8-4| = 2 + 4 = 6。4 をスキップすると、合計 - 削減 = 6 - 0 = 6 になりますか? ただし、サンプル出力は 2 です。 チェック: 秒をスキップ: 合計は |8-2| になります。 = 6? うーん、サンプルには 2 と書いてあります。ああ、もしかしたら最後にスキップしたかも？ すべてを計算しましょう: 最初にスキップします: |8-4| = 4、最後をスキップ: |4-2| = 2、中央をスキップ: |2-8| = 6。最小値は 2 です。したがって、エッジケースでは、最初/最後のスキップが重要であることが確認されます。 

これは、アルゴリズムが最初と最後を別々に処理する必要がある理由を示しています。
