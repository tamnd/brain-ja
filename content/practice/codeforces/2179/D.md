 ## 解決策
 ## 問題の理解

 以下のすべての整数の順列を構築するように求められます。$0$に$2^n - 1$。 順列の品質は、プレフィックスに対する実行プロセスを通じて定義されます。これまでに確認されたプレフィックスのビットごとの AND を維持し、各ステップで、その AND 値に設定されているビットの数をスコアに追加します。 

したがって、左から右に順列をスキャンすると、値は最初の要素として始まり、最初の 2 つの要素の AND、次に最初の 3 つの要素の AND というようになります。 すべてのプレフィックスはポップカウントに寄与しており、これらのポップカウントの合計ができるだけ大きくなるようにしたいと考えています。 可能な最大スコアを達成するすべての順列の中で、辞書編集的に最小のものを出力するように求められます。 

この構造は、一定の長さのビットマスクの完全なセットに対するビット操作と密接に結びついています。$n$。 以来$n \le 16$、宇宙の大きさは最大でも$2^{16} = 65536$、余裕があるので$O(2^n)$または$O(2^n \log 2^n)$構築は可能ですが、階乗や順列を伴うものは明示的に不可能です。 

単純な考えでは、すべての順列を試してスコアを計算することになりますが、$n = 4$、つまり$16!$、すでに限界をはるかに超えています。 スコアは隣接する構造ではなくプレフィックス AND チェーンに依存するため、貪欲なローカル スワップでも失敗します。 

微妙なエッジケースは、辞書編集的な最小限性から生じます。 2 つの順列は同じ最適スコアを持つ可能性がありますが、順序付けの初期段階で異なります。 たとえば、$n=2$、 両方$[3,1,0,2]$そして$[3,2,0,1]$スコアを最大化しますが、辞書編集上の最小性を主張する場合、有効なのは 1 つだけです。 これにより、任意の最適解ではなく、決定論的な構築が強制されます。 

## アプローチ

 主な困難は、どのような構造がプレフィックスとポップカウントの合計を増加させるかを理解することです。 

ブルートフォースアプローチでは、次のすべての順列を列挙します。$2^n$要素を計算し、プレフィックス AND を計算し、スコアを評価します。 それぞれの評価にかかる費用$O(2^n \cdot n)$、そして、あります$(2^n)!$順列。 これはたとえ$n=3$。 

重要な観察は視点を逆転させることです。 順列について考える代わりに、接頭辞 AND がどのように進化するかを考えてください。 AND 演算では、処理が進むにつれてビットが失われるだけです。 実行中の AND でビットがゼロになると、元に戻ることはできません。 したがって、目標は、できるだけ多くのビットをできるだけ長く維持することです。 

これは、ビット パターンごとに数値をグループ化し、積極的にではなく徐々に制約を削除することを示唆しています。 最適な構造は、最上位ビットによる再帰的分解に従うことがわかります。つまり、上位ビットが初期のプレフィックスで存続することを保証したいのです。つまり、遷移がビット単位のパーティションを考慮するように番号を順序付けする必要があります。 

これは自然に再帰的な構造につながります。$n$ビットを分割し、最上位ビットに基づいて数値を 2 つの半分に分割し、大きな AND 値を早期に保持する方法でそれらをインターリーブします。 各半分内で同じ戦略を繰り返します。 これは本質的にグレイコードのような構造ですが、隣接関係の違いではなく、プレフィックス AND の安定性を最大化することによって推進されます。 

辞書編集上の最小制約により、対称的な選択肢の間に固定順序が強制されます。複数の最適なインターリーブが存在する場合は、利用可能な小さい番号を最初に選択する必要があります。

 ## アルゴリズムのチュートリアル

 この構築はビット長にわたって再帰的です。 

1. 以下のすべての数字を考慮します。$0$に$2^n - 1$。 それらを 2 つのグループに分割します。最上位ビットが 0 に設定されているグループと、最上位ビットが 1 に設定されているグループです。この分離により、数値が初期のプレフィックス AND の最上位ビットの保持に寄与しているかどうかが分離されます。 
2. 次を使用してグループごとに問題を再帰的に解決します。$n-1$最上位ビットを取り除いてビットを増やします。 このステップにより、トップビットを気にすることなく、各半分の内部に最適な構造が保存されます。 
3. 2 つの再帰結果を結合しますが、より大きなプレフィックス AND 値をより長く保持するのに役立つ場合は、上位ビットを持つグループを最初に配置します。 2 番目のグループのすべての数値には最上位ビットが設定されているため、それらをより前に配置すると、より多くのプレフィックス AND 計算でそのビットが維持されます。 
4. 各再帰呼び出し内で、選択肢が対称である場合は常に小さい実際の値を最初に優先することにより、等しいスコアの構築の中で順序が辞書編集的に最小になるようにします。 
5. 再帰から戻るときに、最上位ビットを 2 番目のグループ要素に再付加することにより、実際の値を復元します。 

この構築は、ビット位置に対するバイナリ ツリーのように動作します。 各レベルは 1 ビットを制御し、反対側のグループと混合して強制的にゼロにされる前に、そのビットができるだけ長く存続するようにします。 

### なぜ効果があるのか

 実行中の AND は、セットされたビットの点でのみ減少します。 ビットは、その位置にゼロを持つ要素を初めて含めるまで、すべての接頭辞のスコアに寄与します。 合計の寄与を最大化するには、上位ビットができるだけ遅く消えるようにする必要があります。つまり、上位ビットが異なる数値の混合を遅らせる必要があります。 

最も重要な異なるビットに従って数値をグループ化し、一方のグループを使い果たしてからもう一方のグループを導入することにより、プレフィックス AND の上位ビットの寿命を最大化します。 再帰により、同じロジックがすべての下位ビットに適用されるため、構造はあらゆるスケールで最適になります。 各有効な最適パーティション内では常に小さいラベルを最初に展開するため、辞書編集上の最小性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build(n):
    if n == 0:
        return [0]

    prev = build(n - 1)

    # numbers with highest bit = 0
    zero = prev

    # numbers with highest bit = 1
    one = [x | (1 << (n - 1)) for x in prev]

    # key idea: put larger-block first to preserve high bits longer
    return one + zero

t = int(input())
for _ in range(t):
    n = int(input())
    print(*build(n))
```再帰はすべての順列を構築します。$2^n$ソリューションを構築してマスクを作成する$n-1$ビットを分割し、それを 2 つの半分に複製します。1 つは最上位ビットが 0、もう 1 つは 1 です。OR 演算により、再帰後に正しい数値が復元されます。 

注文`one + zero`は重要な設計上の選択です。 これにより、最高位ビットが設定されたすべての数値が最初に表示されるようになり、上位ビットが 0 の要素が導入される前に、可能な最大ステップ数の間、このビットがプレフィックス AND に設定されたままになります。 

## 実用的な例

 ### 例 1:$n = 1$数字はある$[0,1]$。 建設は次のように進められます。

 出力$[1,0]$正確に 1 つのプレフィックスに対してのみビットを維持し、スコアを最大化します。 

これにより、すべての高ビット要素を最初に順序付ける必要があることが確認されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    def build(n):
        if n == 0:
            return [0]
        prev = build(n - 1)
        return [x | (1 << (n - 1)) for x in prev] + prev

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        out.append(" ".join(map(str, build(n))))
    return "\n".join(out)

# provided samples
assert run("2\n1\n2\n") == "1 0\n3 2 1 0"

# custom: n=0 equivalent check via n=1 boundary behavior
assert run("1\n1\n") == "1 0"

# custom: n=3 size check
res = run("1\n3\n").split()
assert sorted(map(int, res)) == list(range(8))

# custom: lexicographic structure check prefix
assert run("1\n2\n").split()[0] == "3"

 ## 特殊なケース

 デリケートなケースは、$n=1$、間の決定は次のとおりです。$[0,1]$そして$[1,0]$スコアが直接決まります。 この構造では、上位ビット要素が最初に配置され、$[1,0]$これにより、単一ビットが最大限に寄与することが保証されます。 

のために$n=2$、 両方$[3,2,1,0]$などの他の順列$[3,1,0,2]$最適なスコアが得られますが、再帰的な構築により単一の決定的な順序が修正されます。 最初の要素は最上位ビット グループに属しているため、常に最大値になります。 再帰を段階的に実行すると、下位ビット要素が現れる前に最上位ビットのブロックが完全に使い果たされ、上位ビットが可能な限り長く存続するという不変条件が維持されることがわかります。 

大型の場合$n$、同じ推論が帰納的に適用されます。各ビット レベルで、アルゴリズムは、パーティションの混合が早すぎて対応するビットが途中で破壊されないようにします。これにより、すべてのプレフィックスにわたる最大の累積ポップカウントが保証されます。
