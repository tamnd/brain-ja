 ## 解決策
 ## 問題の理解

 接続された 2 部グラフ上で 2 つの部分からなる通信問題を解くように求められます。 最初の部分では、エージェントは 3 色を使用して頂点に色を付け、方向情報をエンコードします。 2 番目の部分では、Blackslex は、隣接する頂点の色のみを確認しながら、ランダムな頂点から頂点 1 まで移動する必要があります。 エージェントと Blackslex は実行中に直接通信できないため、戦略全体について事前に合意する必要があります。 

最初の実行への入力により、各テスト ケースの完全なグラフ (頂点、エッジの数、およびエッジのリスト) が提供されます。 エージェントは次の長さの文字列を出力する必要があります$n$, ここで、各文字は対応する頂点に割り当てられた色を表します。 2 回目の実行では、クエリごとに、現在の頂点の近傍の数と各近傍の色が与えられます。 Blackslex は、頂点 1 に向かって移動するために近傍を 1 つ選択する必要があります。グラフが 2 部構成で接続されていることが保証されており、頂点 1 を除く各頂点が開始点になる可能性があります。 

制約が示すのは、$n$そして$m$と同じ大きさにすることができます$10^5$テスト ケースごとに、すべてのテスト ケースの合計も次の制限を受けます。$10^5$。 これにより、以下よりも悪いアルゴリズムが除外されます。$O(n+m)$したがって、2 回目の実行中に各頂点からの繰り返し検索を伴うアプローチは遅すぎます。 各クエリからの単純な BFS では、最大で次のような結果が得られます。$10^5 \times 10^5 = 10^{10}$実行不可能な操作。 

明らかではないエッジ ケースは、頂点 1 から同じ距離にある頂点に複数の近傍がある場合です。エージェントがそれらのすべてを同じ色にすると、Blackslex は頂点 1 に近づけない近傍を選択し、行き詰まってしまう可能性があります。 もう 1 つのエッジ ケースは、グラフが単純なパスまたはスターである場合です。色付けでは、隣接する選択に対して方向を明確にエンコードする必要があります。 

## アプローチ

 ブルートフォースアプローチは、エージェントが特別なことを何もせず、Blackslex にその場で BFS を試みさせることです。 彼は近隣を調査し、発見的に 1 つを選択しました。 これは理論的には正しいですが、頂点インデックスではなく色だけが見えるため、実際には不可能です。 制約を考慮すると、クエリ時の BFS は遅すぎるため、このアプローチは失敗します。 

重要な洞察は、グラフが 2 部構成であるということです。 2 部グラフでは、頂点を 2 つのセットに分割し、すべてのエッジがそれらのセットの間に入るようにすることができます。 頂点 1 からの距離モジュロ 3 に基づいて色を割り当てると、頂点 1 に向かうグラデーションをエンコードできます。$v$距離がある$d$頂点 1 から、以下に基づいて色を割り当てます。$d \mod 3$。 次に、頂点 1 に近い近傍は、予測可能な方法で現在の頂点の色とは異なる色になります。 2 回目の実行中、Blackslex は、距離を法 3 で 1 引いた値に対応する近傍を選択するだけで、頂点 1 への進行が保証されます。これにより、問題が前処理ステップと定数時間のクエリ ステップに変換され、全体の複雑さが軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとのブルート フォース BFS | O(q*(n+m)) | O(n+m) | 遅すぎる |
 | mod 3 による距離ベースのカラーリング | O(n+m) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 最初の実行では、エージェントは頂点 1 から BFS を実行することから開始します。BFS は頂点 1 から他のすべての頂点までの距離を計算します。 頂点 1 自体の距離は 0 です。 
2. 距離がわかったら、それに基づいて各頂点に色を割り当てます。$\text{distance} \mod 3$。 たとえば、0 → 'r'、1 → 'g'、2 → 'b' を割り当てます。 数値と色との正確なマッピングは、一貫性がある限り任意です。 
3. グラフを表す色の文字列を出力します。 これでエージェントのタスクは完了です。 
4. 2 回目の実行では、Blackslex は現在の頂点の近傍のカラーを受け取ります。 それぞれの近隣について、どの近隣が対応する色を持っているかを確認します。$(\text{current color} - 1) \mod 3$。 その近傍は頂点 1 に一歩近づくことが保証されます。 
5. 選択した近傍のインデックスを返します。 この手順をクエリごとに個別に繰り返します。 前のステップを記憶する必要はありません。 

なぜ機能するのか: 不変条件は、頂点 1 からの BFS において、距離にある頂点の任意の隣接点であることです。$d$どちらかの距離にあります$d-1$または$d+1$。 3 つの色を循環的に使用することで、色のある隣人$(c-1) \mod 3$遠くにあるはずだ$d-1$これにより、Blackslex は最大でも任意の開始頂点から常に頂点 1 に移動できることが保証されます。$n-1$ステップ。 

## Python ソリューション```python
import sys
from collections import deque
input = sys.stdin.readline

def agent():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        adj = [[] for _ in range(n)]
        for _ in range(m):
            a, b = map(int, input().split())
            adj[a-1].append(b-1)
            adj[b-1].append(a-1)

        dist = [-1] * n
        dist[0] = 0
        q = deque([0])
        while q:
            u = q.popleft()
            for v in adj[u]:
                if dist[v] == -1:
                    dist[v] = dist[u] + 1
                    q.append(v)

        color_map = ['r', 'g', 'b']
        res = ''.join(color_map[d % 3] for d in dist)
        print(res)

def blackslex():
    t = int(input())
    for _ in range(t):
        q = int(input())
        for _ in range(q):
            d = int(input())
            c = input().strip()
            target = (ord(c[0]) - ord('r') - 1) % 3  # find neighbor with color one less modulo 3
            for i, ch in enumerate(c):
                if (ord(ch) - ord('r')) % 3 == target:
                    print(i+1)
                    break

if __name__ == "__main__":
    mode = input().strip()
    if mode == "first":
        agent()
    else:
        blackslex()
```BFS は頂点 1 からの距離を効率的に計算します。$O(n+m)$。 mod 3 カラーリングにより、Blackslex は実際の距離を知らなくても方向をデコードできるようになります。 2 回目の実行では、コンピューティング$(\text{ord}(ch)-ord('r')) \% 3$カラーを数値にマッピングし、モジュロ 3 でカラー 1 を引いた近傍を選択すると、頂点 1 に向かう進行が保証されます。空の文字列や単一の近傍などの境界チェックは暗黙的に処理されます。
