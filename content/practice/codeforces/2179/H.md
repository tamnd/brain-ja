 ## 解決策
 ## 問題の理解

 1 から n までのインデックスが付けられた一連の植物が与えられます。これらの植物はすべて、最初は水を保持していません。 各クエリはセグメントを指定します$[l, r]$、そしてすべてのポジションについて$i$そのセグメントに、距離に応じて値を追加します。$i$からです$l$。 定義すると$x = i - l + 1$、次に位置での貢献度$i$は$f(x)$、 どこ$f(x)$等しい$x$最下位設定ビットの値を乗算します。 

最下位の設定ビットは、除算する 2 の最大の累乗です。$x$。 それで、もし$x = 12 = 1100_2$、値は$4$、 そして$f(12) = 12 \cdot 4 = 48$。 したがって、すべてのクエリは、その間隔にわたって構造化パターンを 1 から開始して挿入します。$l$、その後のシーケンスに従います$f(1), f(2), f(3), \dots$。 

出力は、すべてのクエリを処理した後の各プラントの最終的な蓄積水です。 

制約は厳しいです: 両方の合計$n$すべてのテスト ケースにわたるクエリの総数は次のように制限されます。$2 \cdot 10^5$。 これにより、クエリの全範囲を反復し、すべての要素を直接更新することで各クエリを処理するアプローチは除外されます。これは、最悪の場合は 2 次関数となるためです。 

単純なシミュレーションでは、$O(r-l+1)$クエリごとに動作するため、$O(nq)$全体。 と$n, q$まで$2 \cdot 10^5$、それくらいでしょう$4 \cdot 10^{10}$実行可能な限界をはるかに超えた操作。 

パターンが重なり合うと、微妙なエッジケースが発生します。 各クエリは高度に非線形なシーケンスに寄与するため、プレフィックスの合計を事前計算しようとする試みはすべて、$f(x)$セグメント間で構造を再利用する方法を理解しない限り、それだけではすぐには役に立ちません。 

## アプローチ

 ブルートフォース手法は簡単です。 クエリごとに$[l, r]$、すべての位置をループします$i$そして計算する$x = i - l + 1$を追加します。$f(x)$答えに。 これは定義に直接従うため正しいですが、すべてのクエリの長​​さの合計が大きい場合は遅すぎます。 

重要な点は、クエリが配列の異なるセグメントに作用するにもかかわらず、適用される関数は常に 1 から始まる同じシーケンスであるということです。$f(x)$のみに依存する$x$、絶対的な位置ではありません。 これは、各クエリが固定の無限配列のシフトされたコピーを追加することと同等であることを意味します。$A[x] = f(x)$。 

問題は、固定パターン プレフィックスの範囲の追加を多数サポートする必要があることです。これは、問題を「指定されたオフセットで各位置をカバーするアクティブなクエリの数」という形式の寄与の管理に変換することを示唆しています。 

プロセスを再解釈する有効な方法は、立場ごとに考慮することです。$i$、それをカバーするすべてのクエリ。 固定クエリの場合$[l, r]$、地位への貢献$i$に依存します$i - l + 1$。 したがって、位置ごとのクエリ、またはクエリごとの位置を反復する代わりに、オフセットごとに寄与を集計したいと考えています。 

ここでの標準的なトリックは、関数を中断してコントリビューションを処理することです。$f(x)$複数の整列されたシーケンスにわたる異なる配列で処理できるコンポーネントに変換します。 重要な構造は、最下位セット ビットが整数を 2 のべき乗のサイズのブロックに分割することです。 各ブロック内では、LSB は一定であり、$f(x)$区間にわたる区分的線形関数に変換する$[2^k, 2^{k+1})$。 

これにより、各クエリの寄与を次のように分解できるようになります。$O(\log n)$ブロック構造ごとに算術セグメントを作成し、差分配列を使用して範囲加算を適用します。 あらゆるものに触れるのではなく、$x$, we update whole power-of-two aligned intervals.

 This reduces each query from linear time to logarithmic time.

 ## アルゴリズムのチュートリアル

 の構造を利用します。$f(x)$最下位設定ビットが定数である範囲。 

1. n までのすべての値は x のみに依存するため、n を超えるグローバル配列を事前計算しません。 それぞれについて$x$、明示的には保存しません$f(x)$, しかし、私たちはそのブロック構造に依存しています。 
2. クエリごとに$[l, r]$、貢献は追加であると解釈します。$f(1)$に$l$、$f(2)$に$l+1$、などまで$f(r-l+1)$。 これはプレフィックスで揃えられたパターンです。 
3. オフセットの範囲を分解する$x \in [1, r-l+1]$セグメントに分割される$\text{lowbit}(x)$は一定です。 これらのセグメントは正確に範囲です$[2^k, 2^{k+1}-1]$。 
4. このようなセグメントごとに、寄与式を計算します。 セグメント上で$\text{lowbit}(x) = 2^k$、 我々は持っています$$f(x) = x \cdot 2^k$$これは線形です$x$。 
5. 固定セグメントの場合$[L, R]$を追加する必要があります$x \cdot 2^k$ポジションへ$i = l + x - 1$。 これを展開すると次のようになります。$$x \cdot 2^k = (i - l + 1) \cdot 2^k = i \cdot 2^k - (l - 1)\cdot 2^k$$したがって、各セグメントは次の線形関数の範囲更新になります。$i$。 
6. 2 つの差分配列を維持します。1 つは次の係数用です。$i$、もう 1 つは定数用です。 各セグメントは以下に貢献します。 

係数配列への線形範囲の更新、

 そして、対応する範囲が定数配列に更新されます。 
7. すべてのクエリを処理した後、両方の配列のプレフィックスの合計を計算して、各位置の最終値を取得します。 

### なぜ効果があるのか

 すべてのクエリは、結合されていない 2 のべき乗のセグメントに分解され、最下位セット ビットが固定されます。 各セグメント内では、関数はターゲット インデックス内で線形になります。 線形関数は範囲加算で閉じられるため、情報を失うことなく差分配列を使用してすべての寄与を集計できます。 最終的な再構成では、各位置でのアクティブな線形寄与をすべて合計するだけです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    
    for _ in range(t):
        n, q = map(int, input().split())
        
        A = [0] * (n + 2)
        B = [0] * (n + 2)
        
        for _ in range(q):
            l, r = map(int, input().split())
            length = r - l + 1
            x = 1
            
            while x <= length:
                k = (x & -x)
                start = x
                end = min(length, (x | (k - 1)))
                
                L = l + start - 1
                R = l + end - 1
                
                # f(x) = x * k = i*k - (l-1)*k
                A[L] += k
                A[R + 1] -= k
                
                B[L] += (-(l - 1) * k)
                B[R + 1] -= (-(l - 1) * k)
                
                x = end + 1
        
        curA = curB = 0
        res = []
        for i in range(1, n + 1):
            curA += A[i]
            curB += B[i]
            res.append(str(curA * i + curB))
        
        out.append(" ".join(res))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装では、2 つの異なる配列が維持されます。 線形項の係数を次のように格納します。$i$、その他は定数を格納します。 各ブロックの更新は、次の範囲に対応します。$f(x)$は線形に動作するため、元のインデックス範囲にわたるアフィン更新に変換します。 

最終パスでは、両方のコンポーネントを累積して評価することによって値を再構築します。$a_i \cdot i + b_i$それぞれの位置で。 

主な微妙な点は、オフセット間のマッピングを注意深く行うことです。$x$そして実際のインデックス$i$、特にシフト$i = l + x - 1$。 ここでオフバイワンエラーが発生すると、線形分解が壊れます。

 ## 特殊なケース

 重大なエッジ ケースは、クエリが同じプレフィックスで重なり合う場合です。 その状況では、単純な実装では、シフトを忘れるとオフセットが誤って二重にカウントされる可能性があります。$i - l + 1$。 このソリューションでは、シフトはアフィン変換の定数項に吸収されるため、重複するクエリは係数を加算するだけです。 

もう 1 つのエッジケースは次のような場合です$r = l$。 それからのみ$x = 1$貢献して以来$lowbit(1) = 1$の場合、更新は 1 の単一点加算に減ります。分解では依然として 1 つのセグメントが生成されるため、特別な処理は必要ありません。 

3 番目のエッジ ケースは、次のようなブロック境界で発生します。$x = 8, 16, 32$。 これらはまさに最下位設定ビットが変更される場所であり、誤ったグループ化により異なる線形関数が混在する可能性があります。 バイナリ ブロック分解により、これらの境界が確実に分離され、正確さが維持されます。
