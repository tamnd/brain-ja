 ## 解決策
 ## 問題の理解

 一列に並べられた一連の整数が与えられます。 1 回の操作で、隣接する 2 つの要素を取得し、その合計で置き換えることで、他の部分の順序を維持しながら、シーケンスを効果的に 1 要素分短縮することができます。 タスクは、回文になるまでシーケンスを減らすことであり、そのようなマージ操作の使用数を最小限に抑えたいと考えています。 

ここでの回文とは、すべての変換の後、シーケンスを左から右に読み取ると、右から左に読み取る場合と同じ値が得られることを意味します。 マージによって順序は維持されますが、セグメンテーションは変更されるため、実際の問題は、両端の合計値が一致するように連続する要素をグループ化する方法を決定することです。 

要素数が 100 万個までという制約は、考えられるすべてのマージ シーケンスを試したり、すべての間隔で動的プログラミングを使用したりするソリューションは、遅すぎることを意味します。 マージの決定はローカルですが配列が大きいため、二次関数以上のものは失敗します。 

いくつかのエッジの状況が重要です。 

配列がすでに前後方向に同じ内容を読み取っている場合、次のようになります。`[2, 2]`または`[1, 3, 1]`の場合、マージは必要ないため、答えはゼロです。 

すべての要素が異なり、配列が長い場合、たとえば`[1, 2, 3, 4, 5]`、両端の累積値を揃えるために複数のマージが必要になります。 

単純な考え方による微妙な失敗例は、値のマージと累積が許可されていることを考慮せずに、端の値のみを比較すると仮定することです。 例えば、`[1, 10, 100]`最初はバランスが取れていませんが、マージすると構造が変更されるため、生の要素ではなくセグメントの合計で比較を行う必要があります。 

## アプローチ

 ブルートフォース解釈では、回文が現れるまで隣接するペアをマージするあらゆる可能な方法をシミュレートし、最小限の操作数を追跡します。 マージするたびに長さが 1 ずつ減り、各状態でマージ先の選択肢が複数あります。 

可能なマージ シーケンスの数は指数関数的に増加します。これは、各ステップで最大`O(n)`有効なマージ位置を指定して実行します`O(n)`ステップ。 これにより、実行可能な限界をはるかに超える検索スペースが得られます。`n`100万まで。 

重要な観察は、最終的な構造は、配列を合計が回文を形成する連続セグメントにどのように分割するかによってのみ決定されるということです。 マージを明示的にシミュレートする代わりに、両端から内側に向​​かってスキャンする 2 つのポインターの観点から考えることができ、各側で現在のセグメントの合計を維持します。 

いつでも、左側のセグメントの累積合計と右側のセグメントの累積合計を比較します。 それらが等しい場合、最後の回文の「ブロック」が一致したため、両方の側が内側に進むことができます。 一方の辺が小さい場合は、次の要素をそのセグメントにマージしてその辺を拡張する必要があります。 このような各拡張は 1 つのマージ操作に対応します。 この貪欲なプロセスが機能するのは、マージはローカルのプレフィックスまたはサフィックスの蓄積にのみ影響を及ぼし、小さな不一致をスキップして後の不一致を最初に解決するメリットが得られないためです。

 ## アルゴリズムのチュートリアル

 2 つのポインターを使用して、2 つの等しい値のエンドの構築をシミュレートします。 

1. 配列の先頭と末尾に 1 つのポインタを初期化します。 また、現在の圧縮セグメントを表す 2 つの累計を左からと右から保持します。 最初は両方ともそれぞれ最初と最後の要素にすぎません。 
2. ポインタが一致すると、配列全体が回文構造に正しく一致したため、プロセスは終了します。 
3. 左側の合計が右側の合計と等しい場合、一致する外側セグメントの形成に成功しています。 両方のポインターを内側に移動し、両方の累計を次の未カバーの要素にリセットします。 
4. 左の合計が小さい場合は、左から次の要素を現在の左セグメントにマージする必要があります。 その要素を左の合計に追加し、左ポインタを右に移動します。 2 つの隣接する要素を結合しているため、これは 1 回のマージ操作に相当します。 
5. 右の合計が小さい場合は、次の要素を右の合計に追加し、右ポインタを左に移動することにより、右側から対称的にマージします。 これも 1 回の操作としてカウントされます。 
6. ポインタが一致するまでこのプロセスを繰り返し、実行されるマージの数を累積します。 

欲張りな選択は、有効な回文パーティションの構造をオーバーシュートすることなく、その側だけが他の側と一致するように追いつくことができる可能性があるため、常に合計の小さい側を拡張することです。 

### なぜ効果があるのか

 すべてのステップで、アルゴリズムはポインター間の配列がまだ処理されていないという不変条件を維持しますが、左右のセグメントは潜在的な回文分解の部分ブロックを表します。 有効な解は最終的に、対応する各ブロックの両端の合計と一致する必要があります。 一方の側の合計が小さい場合、その拡張を遅らせても役に立ちません。これを増やす唯一の方法は、その側でのみ利用可能な隣接する要素をマージすることであるためです。 したがって、小さい側を貪欲に拡張しても有効な最適な構築が妨げられることはなく、各マージが対称ブロック間の 1 つの不一致の解決に直接貢献することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    a = list(map(int, input().split()))
    
    if n <= 1:
        print(0)
        return

    l, r = 0, n - 1
    left_sum = a[l]
    right_sum = a[r]
    ans = 0

    while l < r:
        if left_sum == right_sum:
            l += 1
            r -= 1
            if l < r:
                left_sum = a[l]
                right_sum = a[r]
        elif left_sum < right_sum:
            l += 1
            left_sum += a[l]
            ans += 1
        else:
            r -= 1
            right_sum += a[r]
            ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、2 つのポインターを保持し、両方の累積セグメント合計が一致するまで小さい方の側を拡張します。 均等になると、双方が内側に進み、新しいセグメントが開始されます。 各展開ステップは 1 つのマージ操作としてカウントされ、これは 2 つの隣接する要素の圧縮に正確に対応します。 

一致後にセグメント合計をリセットする場合は注意が必要です。 新しいセグメントが次の未処理の要素から始まることを確認する必要があります。 そうしないと、古い部分和が誤って引き継がれ、不変条件が崩れてしまいます。

 ## 特殊なケース

 次のような単一要素の配列`[7]`はすでに回文です。 アルゴリズムはすぐに終了します。`l == r`開始時なので、マージはカウントされません。 

次のようなすでに対称な配列の場合`[1, 2, 2, 1]`の場合、両端は等しく始まり、ポインタはマージをトリガーせずに内側に移動します。 どのセグメントも展開を必要としないため、不変条件が成り立ちます。 

のような場合には`[1, 3, 2, 2]`、最初は右側の合計が大きいため、左側と一致するまで要素が吸収されます。 プロセスは 1 回のマージ後に停止します。これは、アルゴリズムが構造的な不均衡が存在する場合にのみマージを実行し、不要な操作を決して導入しないことを示しています。
