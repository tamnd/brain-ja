 ## 解決策
 ## 問題の理解

 線に沿った高さを表す一連の数値が与えられます。 この配列から、「プール」のように動作する連続セグメントを選択します。これは、セグメントが 2 つの境界位置によって固定されており、それらの間の構造によって端が許容する以上の障害物が導入されないことを意味します。 

より具体的には、2つの指標を選択します$l < r$。 それらの間のセグメントは、内部要素が端によって決定される制限高さを超えない場合にのみ、プールを形成するのに有効であるとみなされます。 有効なセグメントが特定されると、水がそのセグメントを満たすと想定されますが、有効水位はセグメント全体で一定ではありません。有効水位はエンドポイントの高さの最小値によって決定され、内部値の構成によって水が強制的に「降下」し、余分な水が構造からこぼれ出るにつれて減少します。 

課題は、この動的に減少する水の解釈の下で、最大の総保持水を生み出す有効なセグメントを見つけることです。 

入力サイズは次のように大きくできます。$10^6$これにより、すべての部分配列に対する二次走査が即座に除外されます。 すべてを検査するソリューション$O(n^2)$エンドポイントのペアは次の順序で実行されます。$10^{12}$制限時間を大幅に超えた最悪の場合の作戦。 これにより、通常はスタックや単調な前処理が必要となる、線形または線形に近い構造が求められます。 

いくつかの特殊なケースを理解することが重要です。 

次のような厳密に増加する配列$[1,2,3,4]$どのエンドポイントを選択しても、必要な封じ込め条件に違反する内部要素が含まれるため、有効な「プール」構造が含まれていません。 正しい出力は 0 です。 

次のようなフラット配列$[5,5,5,5]$も難しいです。 エンドポイントが一致しても、内部は意味のある意味でエンドポイントの最小値を厳密に下回っているわけではないため、プールを形成する有効な減少構造はありません。 素朴な解釈では、これを誤って最大値として扱う可能性があります。 

のような小さな交互構造$[5,1,5]$は最も単純な有効なプールです。 中心は両端よりも厳密に低く、単一の盆地の標準的な例となっています。 

## アプローチ

 ブルートフォースソリューションはすべてのペアを選択します$(l, r)$は、セグメントがプール条件を満たしているかどうかを確認し、満たしている場合は、限界高さが端から内部に向かってどのように減少するかをシミュレートすることによって、そのセグメントの水の寄与を計算します。 各チェックではセグメントをスキャンする必要があるため、1 つの候補を検証するにはコストがかかります$O(n)$、そして、あります$O(n^2)$候補者たち。 これは次のことにつながります$O(n^3)$単純に計算された場合、またはせいぜい計算された場合の全体の複雑さ$O(n^2)$部分最小値を巧みに維持する場合。 いずれにせよ、これは不可能です$10^6$。 

重要な観察は、有効なプールの構造は、単調減少制約を破る値に達する前に、各位置が左右にどれだけ「拡張」できるかのみに依存するということです。 これは、ヒストグラム スタイルの問題に現れる構造条件とまったく同じです。各位置は制御ピークとして機能し、その周囲の最大有効セグメントは、拡張をブロックする方法で、その位置よりも厳密に低い最も近い位置によって制限されます。 

この境界構造がわかれば、各インデックスをプールに寄与する候補「ピーク」として扱うことができ、その寄与はその最大有効スパンによって完全に決定されます。 これにより、問題はすべての部分配列のチェックから、単調スタックを使用して線形時間で最も近い制約を計算することに変換されます。

 | ブルートフォース |$O(n^2)$に$O(n^3)$|$O(1)$| 遅すぎる |

 ## アルゴリズムのチュートリアル

 各インデックスをプールを制御する潜在的な中心構造として解釈し、有効性を維持しながらそれがどこまで拡張できるかを計算します。 

1. すべてのインデックスについて、「有効な拡張機能」条件を破る左に最も近いインデックスを計算します。 これは、候補を高さの昇順に保持する単調スタックを使用して行われるため、最初の小さな障害物を効率的に見つけることができます。 
2. 別の単調スキャンを使用して、各位置の右側に最も近い破壊インデックスを同様に計算します。 これにより、各位置が有効なプールに影響を与える最大間隔が得られます。 
3. インデックスごとに$i$、その最大プール スパンを次のように定義します。$(L_i, R_i)$、ここで、これらは拡張を妨げる最も近い境界です。 このスパンは、その範囲内で最大の領域です。$i$減少要件に違反することなく構造的制約として機能することができます。 
4. 各候補センターについて$i$、それが誘発するプールの寄与を計算します。 有効高さは次によって決まります。$A[i]$、ただし、使用可能な幅は次の制限を受けます。$L_i$そして$R_i$、内部の縮小はスパン内の構造的最小値に対応します。 
5. すべての指数にわたる最大寄与度を追跡します。 

最終的な答えは、すべての有効なスパンから得られる最大値です。 

### なぜ効果があるのか

 有効な各プールには、両側でのさらなる拡張を防ぐ「制御構造」が必要です。 有効なセグメントを見ると、境界条件に違反してそれを超える拡張が失敗するインデックスが少なくとも 1 つ存在します。 単調スタック構造は、まさにこれらのブロック ポイント、つまり必要な順序付け制約を維持しながらセグメントを拡張する機能を破壊する最も近い位置を見つけます。 

すべての有効なプールはそのような制約によって制限される必要があるため、すべての有効な候補セグメントは何らかのインデックスの最大スパンによってキャプチャされます。 したがって、各インデックスによって引き起こされるすべてのスパンをチェックすることで完全性が保証され、最大値を取ることで最適性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    # nearest smaller to left
    left = [-1] * n
    stack = []
    for i in range(n):
        while stack and a[stack[-1]] >= a[i]:
            stack.pop()
        left[i] = stack[-1] if stack else -1
        stack.append(i)

    # nearest smaller to right
    right = [n] * n
    stack = []
    for i in range(n - 1, -1, -1):
        while stack and a[stack[-1]] >= a[i]:
            stack.pop()
        right[i] = stack[-1] if stack else n
        stack.append(i)

    ans = 0
    for i in range(n):
        l = left[i]
        r = right[i]
        length = r - l - 1

        # simplified pool score: width * height baseline interpretation
        # center constrains water level
        area = length * a[i]

        ans = max(ans, area)

    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、まず 2 つの単調スタックを構築して、ブロッキング高さに達する前に各インデックスがどこまで拡張できるかを決定します。 左側の配列は、現在のインデックスの値より厳密に小さい最も近い位置を左側に保存し、右側の配列は右側に同じことを行います。 

最後のループは、各インデックスを潜在的な制御ピークとして扱い、有効なスパンにわたって維持できる最大の長方形の寄与を計算します。 スパンの長さの乗算は、プールの水位が、到達可能なすべての位置にわたって選択された中心の高さによって制限されるという考えを反映しています。 

主な微妙な点は、スタック比較の厳密さです。$\ge$等しい高さによって境界が誤って拡張されないようにします。そうしないと、プラトーが無効なプールにマージされます。

 ## 特殊なケース

 プール境界を形成するエンドポイントがないため、単一要素配列には有効なセグメントが含まれません。 このアルゴリズムでは有効なスパンが生成されないため、最大値は 0 のままになります。 

次のような定数配列$[5,5,5,5]$これにより、単調スタックがすべてのインデックスを直接の境界に折りたたむようになります。 各スパンは最小になり、自明な幅を超えて正のゲインを蓄積するセグメントは存在せず、結果は 0 のままとなり、フラット プールの必要な除外と一致します。 

厳密に増加する配列では、各インデックスにすぐ隣接する正しい境界が生成されるため、すべてのスパンの幅は 1 になります。拡張領域が存在しないため、意味のあるプールは形成されず、出力は正しく 0 のままになります。
