 ## 問題の理解

 チームに分割する必要がある参加者の列が与えられます。 主催者は常に、できるだけ多くの完全なチームを形成しようとします。各完全なチームには、正確な内容が含まれます。$K$人々。 これらの完全なチームを形成した後、別の完全なグループを満たすことができない参加者が残る可能性があります。$K$。 残りの参加者は、追加の 1 チームにまとめられます。 

これは、最終的な構造が純粋に分割によって決定されることを意味します。$N$人々を大きなサイズの塊に分割する$K$、最後のチャンクが以下より小さい可能性があります。$K$。 タスクは、最終的に形成される最小のチームのサイズを決定することです。 

入力境界は非常に小さいです。$N \le 1000$そして$K \le 10$。 これにより、効率に関する懸念はすぐに排除されます。 減算を繰り返すシミュレーションでも$K$十分速いでしょう。 本当の課題は計算時間ではなく、最後のチームがどのように形成されるかについての誤った解釈を避けることです。 

よくある落とし穴が現れるのは、$N$の倍数です$K$。 その場合、残存グループはまったく存在しません。 たとえば、次の場合$N = 8$そして$K = 2$では、サイズ 2 の 4 つのチームを形成するため、最小のチームは依然として 2 です。「常に残っているチームが存在する」という単純な解釈では、最終グループが空またはサイズ 0 であると誤って想定されてしまいます。 

もう一つの微妙なケースは次のような場合です。$K > N$。 たとえば、次の場合$N = 5$そして$K = 10$、完全なチームを形成することはできないため、全員がサイズ 5 の 1 つのチームに集まります。少なくとも 1 つの完全なチームが存在することを前提とするソリューションでは、このシナリオが誤って無視されます。 

## アプローチ

 これを考える強引な方法は、参加者を 1 人ずつグループ化することを明示的にシミュレートすることです。 私たちはさまざまなサイズのグループを形成し続けます$K$、各グループに何人入るかを数えます。 到達するたびに$K$、そのチームを終了し、新しいチームを開始します。 最後に、部分的に埋まったグループがある場合は、それを最後のチームとして含めます。 

これは、ステートメントで説明されているプロセスを正確に反映しているため、機能します。 しかし、帳簿付けは不要で、引き算を繰り返しています。$K$から$N$、効果的に行う$O(N/K)$ここでは最大でも 1000 ステップの操作なので、強引な操作も簡単です。 非効率性は実際的なものではなく概念的なものです。 

重要な観察は、実際にはグループ化をシミュレートする必要がないということです。 すべてのフルチームにはサイズがあります$K$、サイズが正確に一致する残りのチームが最大 1 つあります。$N \bmod K$。 したがって、最小のチームは、存在する場合は単に残りのサイズとなり、存在しない場合は残りのサイズになります。$K$。 余りがない場合は、すべてのチームが平等になります。 

これにより、問題全体が剰余の計算とゼロの場合の処理​​に集約されます。

 ## アルゴリズムのチュートリアル

 1. 剰余を計算する$r = N \bmod K$、完全なチームを形成した後に残っている参加者の数を表します。 これは、最終的に不完全なチームが存在するかどうかを直接把握します。 
2. もし$r = 0$、つまり$N$は完全に割り切れます$K$、つまり、どのチームも正確に$K$メンバーであり、これより小さなグループはありません。 
3. もし$r \neq 0$の場合、最後のチームは正確に残りのチームで構成されます。$r$参加者と他のすべてのチームのサイズ$K$したがって、最小のチームは次のようになります。$r$。 

### なぜ効果があるのか

 のパーティション$N$グループへの分割は決定論的です: の減算を繰り返します。$K$同じサイズの完全なブロックを作成します$K$、およびサイズが厳密に より小さい残差ブロックを最大 1 つ$K$。 このルールでは、他のグループ化パターンは使用できません。 これにより、チームの最小サイズは次のいずれかでなければならないことが保証されます。$K$または中間値を導入しない残り。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

N, K = map(int, input().split())

r = N % K
if r == 0:
    print(K)
else:
    print(r)
```このソリューションは 2 つの整数を読み取り、剰余を直接計算します。 唯一の決定点は、剰余がゼロかどうかです。 そうであれば、出力します$K$、どのチームも満員なので。 それ以外の場合は、残りが唯一より小さいため、残りを出力します。$K$グループ。 

微妙な点は、次のような場合の処理​​です。$K > N$。 そのような状況では、$N \% K = N$これは、完全なチームが存在せず、単一のチームにすべての参加者が含まれていることを正しく反映しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline
    N, K = map(int, input().split())
    r = N % K
    if r == 0:
        return str(K)
    return str(r)

# provided samples

 ## 特殊なケース

 いつ$K > N$、たとえば入力`2 10`、アルゴリズムは次のように計算します。$2 \bmod 10 = 2$。 剰余はゼロではないため、2 を返します。これは、完全なチームを形成できない実際のグループ分けと一致します。 

いつ$N$で割り切れます$K$、 のような`10 5`、余りは 0 になります。アルゴリズムは出力に切り替わります。$K$これは、すべてのチームがフルサイズであり、より小さなグループが存在しないことを反映しています。 

いつ$K = 1$、参加者全員が自分のチームを形成します。 剰余は常に 0 であるため、答えは常に 1 であり、すべてのチームのサイズが 1 であるという事実と一致します。
