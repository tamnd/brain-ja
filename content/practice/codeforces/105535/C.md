 ## 問題の理解

 固定の 32 ビット符号なし整数が与えられます。$a$。 各テスト ケースで、すべての 32 ビット符号なし整数を見つける必要があります。$b$モジュロで見たときに 2 つの量が同一になるようにする$2^{32}$:

 最初の量は電力です$a^b$、通常の数学的な意味で計算され、2 番目の量はビット単位の XOR です。$a \oplus b$。 特別な約束事とは、$a^0 = 1$たとえいつでも$a = 0$。 

したがって、タスクは整数に関する方程式を解くことです。$$a^b \equiv (a \oplus b) \pmod{2^{32}}$$そして毎に出力します$b$範囲内で$[0, 2^{32}-1]$それはそれで満足です。 

入力サイズはテスト ケースの数が大きく、最大で$10^5$ただし、各テスト ケースは 1 つの整数のみで構成されます。 これにより、広範囲にわたる探査を試みるアプローチは即座に排除されます。$b$テストケースごとに。 全体の反復に依存するものすべて$b$あるいはそのかなりの部分さえも、$2^{32}$スペースは無理です。 最大リニアスキャン$2^{32}$テスト ケースごとに制限時間を大幅に超過してしまう可能性があります。 

微妙な問題は、左側が次の関数として非常に速く成長することです。$b$、一方、右側は次のように滑らかに変化する単純なビット単位の演算です。$b$。 この不一致は、解決策が非常に制約された状況でのみ発生する可能性があることを示唆しています。 

いくつかの特殊なケースは見落とされがちです。 

いつ$a = 0$、定義により強制されます$0^0 = 1$、それで、$b = 0$私たちは得ます$1 \neq 0$、そしてのために$b > 0$私たちは得ます$0^b = 0$その間$0 \oplus b = b$、次の場合にのみ一致します$b = 0$、すでに無効です。 したがって、有効な値はありません。 

いつ$b = 0$、私たちはいつも得ます$a^0 = 1$、 その間$a \oplus 0 = a$。 これは次の場合にのみ機能します$a = 1$、これはまれな有効な固定点になります。 

もう 1 つの微妙なケースは、式が小さい指数に対して適切に動作したとしても、大きい指数に対しては何も保証されないということです。$b$、大小の治療$b$一様に、誤ったブルートフォースの仮定につながります。 

## アプローチ

 直接試行すると、考えられるすべての値が試行されます。$b$、計算する$a^b \bmod 2^{32}$、計算する$a \oplus b$と比較してみます。 これは論理的には正しいですが、すぐには実行不可能です。 各べき乗には少なくともコストがかかります$O(\log b)$、そしてそれを繰り返す$2^{32}$候補者はすでに原理的に不可能です。 テスト ケースあたりの候補者を数百万人に制限したとしても、$10^5$テストケース。 

重要な点は、実際には関数全体を理解する必要はないということです。$a^b \bmod 2^{32}$巨大な領域にわたって。 我々が知る必要があるのは、それが次の単純なビットごとの線形関数と等しくなる可能性がある場所だけです。$b$。 これは、有効な解決策が存在するとしても、それは非常に小規模で構造化された一連のセットでのみ発生する必要があることを強く示唆しています。$b$価値観。

これにより、問題はごく少数の候補セットのみをチェックすることになります。すべて小さいものです。$b$、さらに特殊なケース$b = a$。

 ## アルゴリズムのチュートリアル

 探索空間を 2 つの素な部分、つまり直接計算が安全な小さな指数と、潜在的な単一の大きな固定小数点として扱います。 

1. 各テスト ケースについて、次の内容を読んでください。$a$。 もし$a = 0$、すぐに解決策がないと結論付けます。$0^b$決して一致することはありません$0 \oplus b$誰にとっても$b$。 
2. 次のすべての値を考慮します。$b$から$0$に$31$。 この範囲は十分小さいため、安全に計算できます。$a^b \bmod 2^{32}$高速べき乗剰余演算を使用します。 
3. それぞれについて$b$、計算する$a^b \bmod 2^{32}$そしてそれを比較してください$a \oplus b$。 一致する場合は記録する$b$。 これは、べき乗がまだ複雑な周期動作に入っていないすべての「ローカル」解を捕捉します。 
4. 候補者を別途確認する$b = a$。 もし$a < 2^{32}$の場合、これは常に有効な 32 ビット候補になります。 コンピューティング$a^a \bmod 2^{32}$そしてそれを比較してください$a \oplus a$、これは常にゼロです。 等価が成り立つ場合は、含めます$b = a$。 これは、指数を入力値自体と一致させ、まれな自己参照条件を作成するため、狭い範囲の外にある唯一の意味のある候補です。 
5. 収集されたすべての値を並べ替えて出力します。 

中心的な考え方は、すべての解は小さな指数の間で発生するか、指数と XOR 構造が一致する単一の自己矛盾のない固定点に崩壊するかのどちらかであるということです。 

### なぜ効果があるのか

 機能$f(b) = a^b \bmod 2^{32}$小さい人に対して規則的に行動する$b$、しかし高度に構造化され、最終的には周期的になります。 機能$g(b) = a \oplus b$は、ビット 反転に関して線形に増加し、極端に制限された場合を除いて、べき乗と周期的に一致しません。 境界領域の外側で等価性が持続する唯一の方法は、指数自体が両方の変換の安定点と一致する場合であり、それがまさに候補です$b = a$。 他のすべては、べき乗が単純な値からまだ分岐していない小さなプレフィックス内に存在する必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 1 << 32

def mod_pow(a, e):
    res = 1
    base = a % MOD
    while e > 0:
        if e & 1:
            res = (res * base) % MOD
        base = (base * base) % MOD
        e >>= 1
    return res

t = int(input())
for _ in range(t):
    a = int(input())
    ans = []

    if a == 0:
        print(0)
        continue

    for b in range(32):
        if mod_pow(a, b) == (a ^ b):
            ans.append(b)

    if a < MOD:
        if mod_pow(a, a) == (a ^ a):
            ans.append(a)

    ans = sorted(set(ans))
    print(len(ans), *ans)
```実装は検索空間の分離の直後に行われます。 べき乗モジュラ関数は、モジュラスに基づいた標準の 2 進べき乗です。$2^{32}$。 ループオーバー$b < 32$テスト ケースごとに一定の費用がかかるだけなので安全です。 

唯一の微妙な実装上の選択は、明示的に使用することです。$2^{32}$この問題では符号なし 32 ビットのラップアラウンド動作が必要なため、Python 整数ではなく算術演算を使用します。 特別候補者$b = a$は、制限された列挙範囲外にあるため、個別にチェックされますが、依然として有効である可能性があります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    MOD = 1 << 32

    def mod_pow(a, e):
        res = 1
        base = a % MOD
        while e > 0:
            if e & 1:
                res = (res * base) % MOD
            base = (base * base) % MOD
            e >>= 1
        return res

    t = int(input())
    out_lines = []
    for _ in range(t):
        a = int(input())
        ans = []

        if a == 0:
            out_lines.append("0")
            continue

        for b in range(32):
            if mod_pow(a, b) == (a ^ b):
                ans.append(b)

        if a < MOD:
            if mod_pow(a, a) == (a ^ a):
                ans.append(a)

        ans = sorted(set(ans))
        out_lines.append(str(len(ans)) + (" " + " ".join(map(str, ans)) if ans else ""))

    return "\n".join(out_lines)

# custom cases

assert run("1\n1\n") == "1 0", "a=1 gives b=0"
assert run("1\n2\n") == "0", "no trivial solution"
assert run("2\n1\n0\n") == "1 0\n0", "mixed cases"

 ## 特殊なケース

 のために$a = 0$の場合、アルゴリズムはすぐに値を返しません。 ループオーバー$b < 32$はこの早期終了後にのみスキップされ、誤って含まれるのを防ぎます。$b = 0$これは、有効な等価性を誤って示唆することになります。$0^0$は 1 として定義されますが、XOR は 0 を返します。 

のために$a = 1$、アルゴリズムがチェックします$b = 0$明らかに狭い範囲にあります。 で$b = 0$、両側はそれぞれ 1 と 1 に評価されるため、正しく含まれます。 その他すべて$b$狭い範囲では、べき乗が一定のまま XOR によって値が変更されるため、失敗します。 

大型の場合$a$、候補者$b = a$別途評価されます。 アルゴリズムは両方を直接計算します。$a^a \bmod 2^{32}$そして$a \oplus a$、構造の単純化を前提とせずに正確性を保証します。 それらが一致する場合、その大きさに関係なく含まれ、固定点が最初の境界検索の外側にある場合を安全に処理します。
