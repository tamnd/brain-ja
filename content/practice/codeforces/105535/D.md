 ## 解決策
 ## 問題の理解

 平面内には 1 つの点が欠けていることを除いて、一連の点が与えられています。 すでにあります$n-1$固定点があり、最終的な座標を選択することができます。$n$- 点目。 この点が追加されると、点間のすべてのペアごとの距離が考慮されますが、距離はユークリッドまたはマンハッタンではありません。 代わりに、それはチェビシェフ距離であり、水平座標と垂直座標の差の最大値として定義されます。 

したがって、すべての点のペアが値に寄与し、最終的には次の複数のセットが得られます。$\frac{n(n-1)}{2}$距離。 なぜなら$n$が奇数の場合、このマルチセットのサイズは奇数であるため、明確に定義された中央値があります。$\frac{m+1}{2}$- 番目に小さい要素$m$ペアの数です。 

タスクは、すべてのペアごとのチェビシェフ距離の中央値が正確になるように、大きな境界ボックス内の欠落点の整数座標を選択することです。$k$、またはそのような配置が存在しないと判断します。 

制約が意味するのは、$n$と同じ大きさにすることができます$2 \cdot 10^5$これにより、すべてのペアごとの距離を明示的に計算するアプローチが即座に除外されます。 それらを保存するだけでも、約 2 \cdot 10^5^2 エントリが必要になりますが、これは現実的ではありません。 どのような解決策でも、ペアの列挙を避け、代わりに距離のカウントまたは構造的特性に依存する必要があります。 

微妙な難しさは、1 つのポイントを追加すると、既存の距離は変更されずに、それに関係するすべての距離が変更されるという事実から生じます。 つまり、静的な中央値の問題を解決しているのではなく、正確に導入することで分布を調整しているということです。$n-1$新しい価値観。 

よくある失敗例は、ローカル ジオメトリに基づいて新しい点を貪欲に推測しようとすることです。 たとえば、既存のポイントがすべてクラスター化されているが、中央値が大きくなければならない場合は、新しいポイントを遠くに配置してみるかもしれません。 ただし、これにより同時に距離が大きくなりすぎて、中央値が反対方向に移動する可能性があります。 新しい点と既存のすべての点の間の結合により、単純な幾何学的直観が信頼できなくなります。 

## アプローチ

 ブルートフォースのアイデアは、許可されたグリッド内の新しい点に対して可能なすべての整数座標を試し、そのたびに中央値を再計算することです。 候補ポジションごとに$(x_n, y_n)$の場合、すべてのペアごとのチェビシェフ距離を計算します。$n$ポイントを並べ替えて、中央値を確認します。 すべての距離を計算するには$O(n^2)$すべてのグリッド点を試すと、これに最大で乗算されます。$10^{12}$限界をはるかに超えた可能性。 

重要な点は、すべての距離を明示的に知る必要はないということです。 中央値は距離の数にのみ依存します。$\le k$そして何人ですか$> k$。 したがって、問題はしきい値カウントの制御に帰着します。 

チェビシェフ距離の条件は、$\max(|x_i-x_j|, |y_i-y_j|) \le k$両方と同等です$|x_i-x_j| \le k$そして$|y_i-y_j| \le k$。 これは各点を辺の正方形に変換します$2k$ペアの座標が重なり合う正方形内にある場合、ペアは「良好」です。 

ペアについて直接推論する代わりに、視点を反転します。各点について、ある点の中に他の点がいくつあるかを考慮します。$k$-半径チェビシェフ地区。 新しいポイントの追加が貢献します$n-1$新しい距離、そしてそれらのそれぞれは次のいずれかです$\le k$または$> k$。 したがって、新しいポイントの効果は、半径のチェビシェフ ボール内に既存のポイントがいくつあるかによって完全に決まります。$k$。 

したがって、タスクを、その中に存在する点の数が以下になるような点を見つけることに縮小します。$k$-近傍は、最終中央値で必要なバランスを正確に生成します。 これは、軸に合わせた制約に関する幾何学的実現可能性の問題になります。 

最適解は、回答空間を既存の点から導出される候補座標に縮小できるという事実を利用します。 制約は以下の差異のみに依存するため、$k$、任意の最適な位置を移動して、によって形成される境界に合わせることができます。$x_i \pm k$そして$y_i \pm k$、これにより検索スペースが減少します。$O(n)$候補者たち。

 ## アルゴリズムのチュートリアル

 1. まず、既存のペア間の距離の数を計算します。$n-1$ポイントは固定なので、「」への貢献度は$\le k$" そして "$> k$「」はすでに決まっており、これは変更できないベースラインとなります。 
2. しましょう$C$距離のある既存のペアの数になります$\le k$。 実装の好みに応じて、スイープ スタイルの構造または変換された座標での並べ替えを使用して、これを 1 回計算します。 
3. 新しい点を挿入した後のペアの総数は次のようになります。$\frac{n(n-1)}{2}$。 これから中央値指数を計算します$m$、条件「中央値が等しい」を翻訳します。$k$」をどれくらいの距離でなければならないかの要件に組み込む$\le k$。 
4. しましょう$t$必要な距離とペアの数になります$\le k$。 既存の構成が貢献する$C$したがって、新しいポイントは正確に寄与する必要があります$t - C$その中の「良い」エッジ$n-1$入射エッジ。 
5. 候補者について$(x,y)$、満たしている既存のポイントの数を計算します。$\max(|x-x_i|, |y-y_i|) \le k$。 このカウントは、新しい距離の数を直接示します。$\le k$。 
6. 条件は、このカウントがステップ 4 で導出された固定ターゲットと等しいかどうかをチェックすることになります。一致する場合、ポイントは有効です。 
7. すべての格子点をスキャンするわけではありません。 代わりに、ラインを横切った場合にのみカウントが変化することが観察されます。$x_i \pm k$または$y_i \pm k$。 したがって、これらの境界から形成される候補位置をテストするだけで十分です。 
8. そのような候補者をすべて列挙します$x$そして$y$値、それぞれをテストする$O(n)$、有効な点を出力します。 

### なぜ効果があるのか

 チェビシェフ制約は、既存の各点の周囲に軸に沿った正方形の領域を作成します。そのような正方形内の点の数は、垂直および水平の境界線によって形成される配置の各セル内で一定です。$x_i \pm k$そして$y_i \pm k$。 どの最適解も、距離内にある点を変更せずにセル内で移動できます。$k$したがって、境界によって引き起こされる代表に注意を限定することで、考えられるすべての妥当性ケースが保存されます。 これにより、ペアカウント条件を変更せずに、連続探索空間が有限個の同値領域に変わります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def count_within(points, x, y, k):
    c = 0
    for xi, yi in points:
        if max(abs(x - xi), abs(y - yi)) <= k:
            c += 1
    return c

def solve():
    n = int(input())
    k = int(input())
    pts = [tuple(map(int, input().split())) for _ in range(n - 1)]

    total_pairs = n * (n - 1) // 2
    median_pos = (total_pairs + 1) // 2

    # We binary interpret condition:
    # need exactly median_pos pairs <= k
    # existing pairs fixed; we only adjust via new point

    # compute existing contribution C (O(n^2) naive for clarity; optimized solutions use data structures)
    C = 0
    for i in range(n - 1):
        for j in range(i + 1, n - 1):
            if max(abs(pts[i][0] - pts[j][0]), abs(pts[i][1] - pts[j][1])) <= k:
                C += 1

    target = median_pos - C

    xs = set()
    ys = set()

    for x, y in pts:
        xs.add(x)
        xs.add(x + k)
        xs.add(x - k)
        ys.add(y)
        ys.add(y + k)
        ys.add(y - k)

    xs = list(xs)
    ys = list(ys)

    for x in xs:
        for y in ys:
            cnt = count_within(pts, x, y, k)
            if cnt == target:
                print(x, y)
                return

    print(-1)

if __name__ == "__main__":
    solve()
```このソリューションでは、まず中央値要件を正確なカウント条件に修正します。 次に、既存のポイントからの寄与が計算されるため、新しいポイントからどのくらいの「良好な」エッジが得られるかを正確に知ることができます。 

候補生成のステップは非常に重要です。 グリッド全体を検索するのではなく、既存の点をシフトした座標のみを考慮します。$k$、点がチェビシェフ距離内にあるかどうかを示すインジケーター関数があるためです。$k$それらのしきい値でのみ変化します。 これにより、有効なポジションがどこかに存在する場合、その地域から少なくとも 1 人の代表者がテストされることが保証されます。 

機能`count_within`候補者が満たす制約の数を評価します。 線形スキャンとして記述されていますが、縮小された候補セットに適用され、意図した推論のために全体の複雑さを管理しやすく保ちます。

 ## 特殊なケース

 既存のすべての点が一致する場合、すべてのペアの距離はゼロになるため、新しい点によって十分な非ゼロ距離が作成されない限り、中央値は自明にゼロになります。 アルゴリズムは、既存の大規模な計算を計算することでこれを処理します。$C$、ターゲットの寄与を強制的にマイナスまたは不可能にし、必要なときに正しく解決策を生成しません。
