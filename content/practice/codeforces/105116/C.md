 ## 解決策
 ## 問題の理解

 私たちは、常に決定的な「蛇のような」パスをたどる固定 n × m グリッド上を移動するヘビをシミュレートしています。ヘビは各行を左から右に走査し、行の終わりに到達すると次の行の先頭にジャンプし、右下から左上に戻ります。 

ヘビは、左上のセル内の単一のセグメントとして開始されます。 時間は不連続な秒単位で進み、ヘビは毎秒、この固定された移動パス上の次のセルを観察します。 そのセルが空の場合、ヘビは 1 歩前進し、体のすべての部分を前方に移動します。 そのセルにリンゴが含まれている場合、代わりにヘビが成長します。頭がリンゴのセルに移動し、体は通常のように移動せず、実質的に長さが 1 つ増加します。 

次々と現れるq個のリンゴ。 i 番目のリンゴは、(i−1) 番目のリンゴが食べられた後にのみ現れます。 常に「アクティブな」リンゴは 1 つだけですが、ちょっとした工夫があります。ヘビがすでに占有しているセルにリンゴが出現すると、動きも時間も経過せずにすぐに食べられ、すぐに次のリンゴが生成されます。 これにより、実際の動作が発生する前に瞬間的な消費の連鎖が発生する可能性があります。 

タスクは、すべてのリンゴが消費されるまでの合計秒数を計算することです。これには、移動秒数と、ヘビの中のスポーン イベントによって引き起こされる即時連鎖反応の両方が含まれます。 

制約はすべての次元と q に対して最大 10^5 と大きいため、セルごとの動きをシミュレートするソリューションはすぐに遅すぎます。 時間をかけて完全なシミュレーションを行うと、最大 n·m 個のセルを繰り返し走査する可能性がありますが、これは不可能です。 

重要な微妙な点は、多くのリンゴが時間を進めることなくスポーン時に即座に消費され、実際の動きの間のヘビの行動はグリッドの固定線形トラバースに沿って完全に決定的であることです。 これは、段階的な動きを決してシミュレートすべきではなく、代わりにこの線形順序に沿った位置の観点から推論すべきであることを示唆しています。 

単純な実装は、グリッドの大部分を覆う長いヘビのような場合、スポーンされた多くのリンゴがその体内に落ちてすぐに食べられる場合に失敗します。 もう 1 つの失敗例は、座標が繰り返されることで 1 秒間に複数のインスタント消費が発生することです。これは、1 秒あたり 1 個のリンゴが処理されることを想定した実装を壊すことになります。 

## アプローチ

 直接的な強引なアプローチは、ヘビを秒ごとにシミュレートすることです。 各ステップで、ハミルトニアンのような走査で次のセルを計算し、現在のリンゴが含まれているかどうかを確認し、それに応じて移動または成長し、生成を処理します。 これはインスタント チェーンを含むすべてのルールを正しくモデル化しますが、毎秒 O(1) の作業が必要で、最悪の場合、ヘビは O(n·m + q) の移動を必要とする可能性があり、これは移動だけで最大 10^5 ステップに相当し、リンゴの各インタラクションによってカスケード チェックがトリガーされる可能性があります。 これは直線的に見えますが、隠れた問題は、スネークのボディ状態を正しく処理するには、最大 10^5 の長さにわたって動的構造を維持および更新する必要があり、アクセス/更新を繰り返すと、実際には、特に厳しい定数の下ではパフォーマンスが低下する可能性があることです。 

さらに重要なのは、ブルート フォースは構造の単純化を見逃していることです。ヘビの動きは任意ではなく、すべてのグリッド セルにわたる固定された周期的順序です。 これは、グリッドをサイズ N = n·m の 1D 配列に平坦化できることを意味します。ここで、各セルは走査順序のインデックスを持ちます。 ヘビは常にこの指数モジュロ N に沿って前進します。 

グリッドを平らにすると、ヘビは円形配列上のセグメントになります。 その頭の位置は前進するポインタであり、成長イベントはその尾部の境界を暗黙的に拡張します。 各リンゴ イベントは、その位置と現在のスネーク間隔との比較になります。

重要な洞察は、ヘビが実際に人のいない部屋に移動したときにのみ時間が進むということです。 すべての瞬間的な食事は、秒を消費することなく、現時点で行われます。 したがって、すべてのステップではなく、意味のあるイベント間の遷移のみをシミュレートする必要があります。 

現在のヘッドインデックスと、サイクル上のヘビの占有範囲を表す構造を維持します。 各リンゴについて、現在のスネークの体内にある場合は、まずそのスポーン位置ですべてのインスタント消費を処理し、次のリンゴを繰り返しトリガーします。 リンゴが現在の占有領域の外にある場合にのみ、リンゴに到達するまでに頭が何ステップ移動する必要があるかを計算します。これは、線形化されたグリッド上でモジュラー演算を使用して時間を直接追加します。 

これにより、問題は動的な区間拡張を伴う巡回配列上の一連のジャンプに帰着され、表現に応じて O(q) または O(q log n) で処理できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(n·m + q + スネーク メンテナンスのオーバーヘッド) | O(n・m) | 遅すぎる |
 | 平坦化サイクル + 区間推論 | O(q) | O(n・m) または O(q) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、各セル (i, j) を線形インデックス pos(i, j) = (i − 1)・m + (j − 1) にマッピングします。 ヘビは、N = n・m を法としてこのインデックスを増加させることによって前進します。 

現在のヘッド位置、現在のテール位置、および現在の時刻という 3 つの主要な値を維持します。 

また、サイクル上の現在のスネーク本体間隔内に位置があるかどうかを迅速にチェックするための構造も維持します。 ヘビは決して分岐せず、成長するか前方に移動するだけであるため、その占有セルは常に周期順序上で連続した間隔を形成します。 

リンゴを一つ一つ丁寧に加工し、インスタントチェーンを扱っています。 

1. 次のリンゴの座標をその線形インデックス p に変換します。 
2. p が現在のヘビ間隔内にある間、リンゴは即座に食べられます。 時間を増やさずにすぐに次のリンゴに進みます。 このようなイベントごとにスネークが 1 セグメント分延長され、それに応じて間隔が更新されます。 新しいリンゴはそれぞれ更新されたスネーク内に配置される可能性があるため、このステップは連鎖的に複数回繰り返される可能性があります。 
3. ヘビの内側にないリンゴの位置 p を見つけたら、サイクルに沿って頭が p に到達するまでに前方に何歩歩む必要があるかを計算します。 これは、ヘッドから p までの前方へのモジュラー距離です。 
4. その距離を合計時間に加算し、その量だけ頭を前方に動かします。 
5. p に到達すると、ヘビがそれを食べて成長します。つまり、頭側で間隔が 1 つ広がります。 
6. 次のリンゴに進みます。 

重要な構造特性は、スネークの占有セルが常に循環順序で単一の連続セグメントを形成するため、ラップアラウンド下でもメンバーシップ クエリが間隔チェックに減少することです。 

### なぜ効果があるのか

 ヘビは常に分割せずに前進するため、いつでも巡回順序の連続した間隔を占めます。 成長は頭側を伸ばすだけで、動きは両端を均等に前方に移動させるだけです。 したがって、新しいポジションは厳密にこの間隔の外にあるか、時間の経過なしに即時消費をトリガーします。 これにより、各リンゴが順番に 1 回だけ処理され、すべてのインスタント チェーンが移動前に解決され、正しい時間計算が維持されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, q = map(int, input().split())
    N = n * m

    apples = []
    for _ in range(q):
        x, y = map(int, input().split())
        apples.append((x - 1) * m + (y - 1))

    # snake interval on circle: [l, r] in mod N, initially at 0
    l = r = 0
    head = 0
    time = 0

    def inside(x):
        if l <= r:
            return l <= x <= r
        else:
            return x >= l or x <= r

    i = 0
    while i < q:
        p = apples[i]

        # process instant chain reactions
        if inside(p):
            # consume instantly, extend head side
            r = p
            i += 1
            continue

        # compute forward distance from head to p
        if p >= head:
            dist = p - head
        else:
            dist = N - (head - p)

        time += dist
        head = p

        # grow snake
        r = p

        i += 1

    print(time)

if __name__ == "__main__":
    solve()
```コードは、グリッドを単一の循環配列に平坦化することから始まり、これにより幾何学的な動きの複雑さがすべて取り除かれます。 の`inside`関数は循環間隔のメンバーシップを実装します。これは、シミュレーションなしで瞬間的なリンゴの消費を検出できるようにする重要な不変条件です。 

メインループはリンゴを順番に処理します。 リンゴがすでにヘビの間隔内にある場合、それはすぐに消費され、時間の増加なしに間隔が拡大します。 それ以外の場合は、現在の頭の位置からリンゴまでの前方距離を計算し、その量だけ時間を進めます。 これにより、段階的に繰り返すことなく、固定された移動パスに沿った動きを直接モデル化できます。 

微妙な点は、移動を距離に圧縮すると中間セルは時間の計算に重要ではなくなるため、ヘッド ポインタは常に次に消費されるリンゴの位置に直接移動することです。 更新間隔により、成長イベントが発生してもヘビの体の一貫性が保たれます。

 ## 特殊なケース

 主なエッジケースは、ヘビが現在占有している間隔内に複数のリンゴが出現する場合です。 この状況では、アルゴリズムは時間を進めることはなく、間隔を繰り返し拡大するだけです。 実装では、while をループすることでこれを処理します。`inside(p)`が true の場合、移動が発生する前に連鎖したすべての消費が確実に解決されます。 

もう 1 つのエッジ ケースは、最後のセルから最初のセルに戻るラップアラウンド移動です。 距離の計算ではモジュラー演算が明示的に処理され、ヘッド インデックスがサイクルの終わりに近づいている場合でも、正しい前方移動が保証されます。 

最後のエッジケースは、ヘビがすでにグリッドのほぼ全体を占めている場合です。 ここでは、ほぼすべてのリンゴのスポーンは瞬時に行われ、実際の動きはほんのわずかしか発生しません。 アルゴリズムは体の細胞を反復することがないため、間隔がサイクルの大部分にまたがる場合でも線形のままで劣化しません。
