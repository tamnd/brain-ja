 ## 問題の理解

 2 種類の正方形タイルが与えられており、これらを固定幅の長方形のボックスに詰め込む必要があります。 ボックスには幅があります$K$そして未知の長さ$X$、すべてのタイルは重ならないように軸を揃えて配置する必要があります。 

タイルの種類の 1 つは、$2 \times 2$正方形、そしてそこにあります$A$彼らのうち。 もう一つのタイプは、$1 \times 1$正方形、そしてそこにあります$B$彼らのうち。 タスクは、次の可能な最小値を決定することです。$X$すべてのタイルを内側に配置できるようにする$K \times X$矩形。 

幅$K$修正され、すべてのテスト ケースで共有されます。 唯一の自由は、正方形をどのように配置するか、およびそれらを収容するために長方形の高さがどれくらいになる必要があるかです。 

制約は次のとおりです$A, B \le 10^8$したがって、セルごとに配置をシミュレートしようとしたり、明示的なグリッドを構築したりするソリューションは、直ちに不可能になります。 高さも大きくなる可能性があり、操作の数は入力サイズではなく答えに応じて増加するため、行に対する単純な貪欲なシミュレーションでも失敗します。 解決策は純粋に算術的でなければなりません。 

微妙なエッジケースが現れるのは、$K$小さいです。 もし$K = 2$、 唯一$2 \times 2$タイルは水平スライスごとにフィットし、水平方向の柔軟性はありません。 もし$K = 3$、内部にはまだ無駄な幅があります。$2 \times 2$配置パターン。 このようなケースでは、残りのスペースが大きな正方形が領域をブロックする方法と相互作用するため、誤った「エリアのみ」の推論が崩れることがよくあります。 

単純な間違いは、総面積を計算して次の値で割ることです。$K$、ジオメトリを無視します。 これは失敗します。$2 \times 2$タイルは 4 つの独立したものに相当しません$1 \times 1$ストリップパッキング設定のタイル。 それらは構造を課します。$2 \times 2$幅にどれだけ効率的に配置できるかを制限する設置面積$K$。 

## アプローチ

 簡単なアプローチは、タイルを 1 行ずつ配置することを考えることです。 次のいずれかを配置して、長方形の構築をシミュレートできます。$2 \times 2$タイルか$1 \times 1$現在利用可能なスペースにタイルを貪欲に配置し、いっぱいになると次の行に移動します。 これは注意深く実装すれば正しいですが、次の理由により実行不可能です。$A$そして$B$行数も大きくなる可能性があります。 どのようなシミュレーションでも、各タイルまたは各行を個別に効果的に処理するため、線形的な複雑さが生じます。$A + B$が遅すぎます。 

重要な観察は、最適なパッキングの構造が、大きなタイルでは高さ 2 の層に自然に分離するということです。 それぞれ$2 \times 2$タイルは$2 \times 2$ブロックなので、グリッドを高さ 2 の水平バンドにグループ化するのが自然です。そのようなバンド内で、実際に次の数を解決しています。$2 \times 2$タイルは一定の幅に収まります$K$、これは存在する列のペアの数にのみ依存します。 

それぞれ$2 \times 2$タイルは、隣接する 2 つの列と 2 つの行を消費します。 したがって、高さ 2 の任意の水平バンドには、最大でも次のように収まります。$\lfloor K/2 \rfloor$このようなタイル。 これにより、配置の問題が変わります$A$大きなタイルを、完全な 2 行バンドがいくつ必要かという単純な容量の問題に変換します。 

大きなタイルがこれらのバンドに最適に配置されると、それらのバンド内の残りの空のセルを再利用できます。$1 \times 1$タイル。 残りのスペースをすべて埋めた後でのみ、純粋に専用の追加行が必要になる可能性があります。$1 \times 1$タイル。 

これにより、問題は幾何学的パッキングから容量と残りのアカウンティングの組み合わせに軽減されます。

 | --- | --- | --- | --- |
 | 行ごとのシミュレーション |$O(A + B)$|$O(1)$| 遅すぎる |
 | バンド容量 + 残りの演算 |$O(1)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 グリッドを 2 行のブロックに分けて処理します。$2 \times 2$タイルはちょうど 2 行にまたがります。 

1. 何個かを計算します$2 \times 2$タイルは高さ 2 の 1 つの水平バンドに収まります。これは$c = \lfloor K/2 \rfloor$。 各タイルは 2 列を消費するため、これは純粋に幅パーティショニングの問題です。 
2. すべてを配置するために必要なフルバンドの数を計算します。$A$大きなタイル。 これは$t = \lceil A / c \rceil$。 各バンドは高さ 2 に寄与するため、大きなタイルに割り当てられる現在の高さは次のようになります。$2t$。 
3. これらのバンドが実際に提供するスペースの量を計算します。 各バンドにはエリアがあります$2K$したがって、バンド全体の総面積は次のようになります。$2Kt$。 大きなタイルは消費します$4A$領域なので、配置後に残った空きセルは$free = 2Kt - 4A$。 
4. この空きスペースを使用して配置します$1 \times 1$タイル。 もし$B \le free$とすると、小さなタイルはすべて既存の構造内に収まり、答えは単純です。$2t$。 
5. それ以外の場合は、残りの小さなタイルを計算します$B' = B - free$。 これらは高さ 1 の追加の行に配置する必要があり、各行が容量に影響します。$K$。 余分な行の数は、$\lceil B'/K \rceil$。 
6. 最終的な答えは次のとおりです。$X = 2t + \lceil B'/K \rceil$。 

### なぜ効果があるのか

 重要な不変条件は、割り当て後の$t$バンド、みんな$2 \times 2$タイルは完全に配置されており、これ以上再配置してもスペースの使用率を向上させることはできません。$2 \times 2$幅のタイル$K$ストリップは独立した高さの 2 つのバンドに分解され、それぞれに容量があります$\lfloor K/2 \rfloor$。 フルバンド使用率からの逸脱は、大きなタイルの容量を増やすことなく幅を無駄にするだけであるため、最適化により飽和が最大まで強制されます。$t$バンド。 その構造が修正されると、残りのスペースは純粋に長方形になり、ユニット セルの標準的なビンパッキング問題のように動作します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    A = int(input().strip())
    B = int(input().strip())
    K = int(input().strip())

    c = K // 2  # number of 2x2 tiles per height-2 band

    if c == 0:
        # This case never happens since K >= 2, but kept for clarity
        c = 1

    t = (A + c - 1) // c

    total_area_in_bands = 2 * K * t
    used_by_large = 4 * A
    free = total_area_in_bands - used_by_large

    if B <= free:
        print(2 * t)
        return

    B -= free
    extra_rows = (B + K - 1) // K
    print(2 * t + extra_rows)

if __name__ == "__main__":
    solve()
```この実装はバンド分解を直接反映しています。 唯一の微妙な部分は、残りの容量を正しく計算することです。正確な幾何学的配置を追跡する代わりに、固定された最適なタイル構造内の領域の保存に依存しています。 天井分割により、必要なバンドや行が過小評価されることがなくなります。

 ## 特殊なケース

 いつ$K = 2$、各バンドには 1 つだけ含めることができます。$2 \times 2$タイル。 アルゴリズムはまだ機能します。$c = 1$したがって、各タイルは帯域全体の容量を消費し、$t = A$。 部分的なパッキングは発生せず、残りの計算は正確になります。 

いつ$B = 0$、アルゴリズムは、大きなタイルに必要なバンド数の計算のみに正しく削減され、余分な行は追加されません。 これにより、1 ユニット領域の不必要な割り当てが回避されます。 

いつ$A = 0$、バンド構造は高さゼロのバンドに崩壊します。$t = 0$そして、解決策は単純な行パッキングに帰着します。$1 \times 1$幅にタイルを並べる$K$となり、$\lceil B/K \rceil$。
