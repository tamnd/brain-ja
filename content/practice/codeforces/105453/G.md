 ## 解決策
 ## 問題の理解

 出発予定時刻ごとに並べ替えられた一連のフライトが与えられます。 各便には滑走路を理想的に使用したい時間が設定されており、その時間に正確に出発できる場合は支払いが行われ、許可されない場合はペナルティが課せられます。 

空港は滑走路が 1 本に縮小されているため、実際に予定時刻近くに出発できるのは一部の便だけです。 フライトが時間通りに出発できれば、プラスの報酬が得られます。 選択されない場合、航空会社が遅延を補償するため、延期され、代わりにマイナスの値が与えられます。 

運用上の制限は、フライトを定刻に出発させることを選択した場合は常に、次に選択した出発までに少なくとも T 時間単位が経過することを確認する必要があることです。 これにより、問題は、総利益を最大化しながら間隔の制約を尊重するフライトのサブセットを選択することになります。選択された各フライトには 1 つの値が与えられ、スキップされた各フライトには別の値が与えられます。 

出力は、どのフライトが定刻に出発し、どのフライトが遅延するかを決定した後に達成可能な最大合計利益です。 

この制約により、N が 100 万に達する可能性があることが明らかになり、二次動的計画法や対数二乗動的計画法さえ即座に除外されます。 すべてのフライトのペアを検査したり、州ごとに大量の検索を実行したりするソリューションでは、制限時間を超えてしまいます。 重要な要件は、分類されたフライトに対して本質的に線形または線形に近いスキャンを行うことです。 

単純に解釈すると、スケジュールの制約がすべてのフライトではなく、選択したフライト間にのみ適用されるということも見逃してしまいます。 この違いにより、貪欲なローカル決定やフライトごとのローカル決定が不正確になるのです。 

すべてのフライトが時間的に近い場合、微妙なエッジケースが発生します。 たとえば、T が大きく、すべての t_i が密に詰め込まれている場合、フライトは 1 つだけ選択できます。 常に最良の即時利益 b_i - c_i を選択する素朴な貪欲な戦略は失敗する可能性があります。 

入力:```
3 10
1 100 -1
2 90 -1
3 80 -1
```欲張りな選択では、ゲインが最も高い最初のフライトを選択する可能性がありますが、他の構造化されたケースでは、時間が許せば後の組み合わせによりより良い間隔が得られることを見逃す可能性があります。 実際の制約は、複数のインデックス間の意思決定を結び付けます。 

もう 1 つのエッジ ケースは、c_i が他のフライトよりもゼロに近い場合、遅延が一部のフライトにとって実際に有益である場合です。 c_i が負であるため、構造を無視してスキップされたフライトをすべてゼロコストとして扱うと、正確性が完全に崩れてしまいます。 

## アプローチ

 最初の自然な試みは、フライトごとに時間通りに乗るか遅延するかを個別に決定することです。 これは、T 間隔の制約により、フライトの利用が今後どのフライトに参加できるかに影響するため、すぐに失敗します。 すべてのフライトが選択またはスキップされる可能性があるため、間隔を満たすフライトのすべてのサブセットを列挙しようとすると、指数関数的に複雑になります。 

より構造化されたブルート フォースは、フライトを順番に処理し、最後に選択された時刻を追跡しながら、フライトごとにそのフライトに乗るかどうかを再帰的に決定することです。 これにより、各ステップが 2 つの選択肢に分岐する状態空間が生成され、状態の数は最悪の場合、およそ 2^N のように増加します。 時間がまばらな場合、有効なサブセットは依然として非常に多数であるため、無効なスケジュールを削除しても十分な効果はありません。 

重要な観察は、欠航便の影響は、スケジュールの決定に関係なく一定であるということです。 選択されていない場合、すべてのフライトが c_i に寄与します。 すべてのフライトが遅延するベースラインから開始すると、合計は単にすべての c_i の合計になります。 唯一の実際の決定は、どのフライトを遅延から定刻にアップグレードするかということであり、アップグレードごとに b_i - c_i の利益増加が得られます。 

これにより、問題は、時間によって決定されるインデックスの間隔制約に従って、それぞれの重量が増加するフライトのサブセットを選択することに変換されます。 このように再構成すると、構造は並べ替えられたリストに基づいた古典的な加重間隔スケジューリングの問題になり、互換性は任意の間隔ではなく時間ギャップによって定義されます。 

フライトはすでに時間順に並べ替えられているため、各フライト i について、t_j + T <= t_i となる、その前の最後のフライト j を知る必要があるだけです。 次に、フライト i に乗ってそのゲインを j までの最適解に追加するか、スキップするかを決定します。 

これは、2 ポインター手法を使用して線形時間で評価できる動的プログラミングの定式化に直接つながります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 選択肢に対するブルートフォース再帰 | O(2^N) | O(N) | 遅すぎる |
 | 先行検索を使用した DP | O(N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、各フライトを、遅延するよりも時間どおりに提供することがどれだけ良いかを表す値に変換します。 その値は b_i - c_i です。 また、すべての c_i の合計としてベースライン寄与を計算します。 

次に、時間の増加順にフライトを処理し、動的プログラミング テーブルを構築します。 

1. 各フライトのゲインを b_i - c_i として計算します。 これにより、フライトの選択による決定の影響が分離されます。 
2. T ギャップ制約に違反することなく、現在のフライトの前にスケジュールできる最新のフライトを追跡するポインター j を維持します。 
3. 各フライト i について、t_j + T <= t_i が成立する間、できるだけ j を進めます。 時間がソートされているため、j は実行全体にわたって前方にのみ移動し、プロセスを線形に保ちます。 
4. dp[i] を最初の i フライトを使用して達成可能な最良のゲインとして定義します。 各 i について、2 つの選択肢があります。フライト i を無視して dp[i-1] を維持するか、フライト i を選択してそのゲインを dp[j] に追加するかです。 
5. これら 2 つの選択肢の最大値として dp[i] を更新します。 
6. すべてのフライトを処理した後、すべての c_i のベースライン合計を dp[N] に加算して、完全な利益を復元します。

正確性は、フライト i を選択したとおりに修正すると、以前の選択に対する唯一の制約は、それらが t_i - T またはそれより前に終了しなければならないという事実にかかっています。i を含む最適解は、それを互換性のある以前のフライトの最適解と組み合わせる必要があり、dp[j] はすでにその最適を表しています。 

dp 状態は、フライトのすべてのプレフィックスに対して達成可能な最良のゲインを取得するため完全であり、時間順序の単調性により遷移で有効な候補がスキップされることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    T = int(next(it))

    t = [0] * n
    b = [0] * n
    c = [0] * n

    for i in range(n):
        t[i] = int(next(it))
        b[i] = int(next(it))
        c[i] = int(next(it))

    base = 0
    gain = [0] * n

    for i in range(n):
        base += c[i]
        gain[i] = b[i] - c[i]

    dp = [0] * (n + 1)

    j = 0
    for i in range(1, n + 1):
        ti = t[i - 1]

        while j < i and t[j] + T <= ti:
            j += 1

        take = dp[j] + gain[i - 1]
        skip = dp[i - 1]
        dp[i] = take if take > skip else skip

    print(base + dp[n])

if __name__ == "__main__":
    solve()
```コードは、すべてのフライトを読み取り、ベースラインのペナルティ構造を決定に依存するコンポーネントから分離することから始まります。 dp 配列には、「すべて遅延した」シナリオに対する増分改善のみが保存されるため、移行が簡素化されます。 

ポインタ j は単調に進みます。これは、線形の複雑さを保証する重要な実装の詳細です。 互換性ウィンドウは時間が増加するにつれてのみ前進するため、i ごとにリセットされることはありません。 

よくある落とし穴は、i ごとに j を最初から再計算することです。これにより、パフォーマンスが二次時間まで低下します。 もう 1 つの微妙な問題は、dp[j] が j 自体を含まず、互換性のある最後のフライトの前で終わるプレフィックスを参照していることを忘れていることです。そのため、ポインターは慎重に進められます。 

## 実用的な例

 次のサンプル入力を考えてみましょう。```
4 5
2 1000 -100
5 500 -500
7 300 -500
9 1000 -100
```ベースライン合計 c_i を -1200 として計算します。 ゲインは 1100、1000、800、1100 です。 

互換性を重視して dp を構築します。 

| 私 | t_i | j (最後に有効な) | ゲイン | dp[i] |
 | --- | --- | --- | --- | --- |
 | 1 | 2 | 0 | 1100 | 1100 |
 | 2 | 5 | 1 | 1000 | 1100 |
 | 3 | 7 | 2 | 800 | 1100 |
 | 4 | 9 | 3 | 1100 | 2200 |

 最終的な答えは、-1200 + 2200 = 1000 です。 

このトレースは、複数のフライトが正のゲインを持っているにもかかわらず、間隔の制約によりすべてのフライトを積み重ねることができず、DP が互換性のあるサブセットを正しく選択していることを示しています。 

次に、より厳密なケースを考えてみましょう。```
3 10
1 100 -1
2 90 -1
3 80 -1
```T が大きいため、すべてのフライトは互いに互換性がありません。DP は最大 1 つのゲインしか選択できませんが、最良の 1 つの改善を正確に選択し、最終的な答えは -3 + 99 = 96 になります。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N) | 各フライトは 1 回処理され、ポインタ j は配列 | 内を前方にのみ移動します。 
| スペース | O(N) | 配列は時間、ゲイン、dp 値を保存します。 

リニア スキャンとモノトニック ポインタにより、ソリューションは制限時間内で最大 100 万回のフライトを快適に処理できます。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    def solve():
        data = sys.stdin.read().strip().split()
        it = iter(data)
        n = int(next(it))
        T = int(next(it))
        if n == 0:
            print(0)
            return

        t = [0] * n
        b = [0] * n
        c = [0] * n

        for i in range(n):
            t[i] = int(next(it))
            b[i] = int(next(it))
            c[i] = int(next(it))

        base = sum(c)
        gain = [b[i] - c[i] for i in range(n)]

        dp = [0] * (n + 1)
        j = 0

        for i in range(1, n + 1):
            ti = t[i - 1]
            while j < i and t[j] + T <= ti:
                j += 1
            dp[i] = max(dp[i - 1], dp[j] + gain[i - 1])

        print(base + dp[n])

    solve()
    return sys.stdout.getvalue().strip()

 ## 特殊なケース

 T がゼロの場合、すべてのフライトは他のフライトと互換性があり、すべてのゲインが独立しているため、最適な戦略はすべてのフライトを選択することになります。 j は常に i に進み、dp 遷移を正のゲインの単純な累積に変えるため、アルゴリズムはこれを処理します。 

T が非常に大きい場合、選択できるフライトは 1 つだけです。 この状況では、dp[j] はすべての有効な j に対して常に 0 になるため、dp は自然にすべてのフライトから最大ゲインを選択することになります。 

すべてのゲインが負の場合、dp はゼロを超えることはありません。つまり、最適な戦略はすべてのフライトを遅らせることです。 dp が非正のままであり、基本コストが避けられないため、これは正しく捕捉されます。 

フライトが時間的に非常に密集している場合、ポインタ j はゆっくりと進み、アルゴリズムは標準の加重スケジューリング DP のように動作し、以前のフライトを再検討することなく、常に最新の互換性境界を尊重します。
