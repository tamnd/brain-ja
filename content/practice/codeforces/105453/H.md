 ## 解決策
 ## 問題の理解

 最大 100 万個のノードとエッジを持つ無向グラフとして表現されるフォレストが与えられます。 一部のノードは最初に特別としてマークされており、これらの特別なノードは、ノードが「魔法のような」ものであることの意味を定義します。 

ノードは、無向エッジを介して少なくとも 1 つの特別なノードに接続されたままである場合、魔法であるとみなされます。 ノードがすべての特別なノードから切断されると、そのノードは即座に魔法のステータスを失います。 

この初期設定の後、一連のクエリによってノードが 1 つずつ削除されます。 削除された各ノードは、すべてのインシデント エッジとともにグラフから永久に削除されます。 この削除によりグラフが分割され、他のノードが残りのすべての特別なノードへの接続を失う可能性があります。 

削除ごとに、その削除の直接の結果として新たに魔法のステータスを失ったノードの数を報告する必要があります。 

重要な点は、「魔法の喪失」は削除されたノード自体だけの問題ではないということです。 1 つのノードを削除すると、コンポーネント全体がすべての特別なソースから切断される可能性があり、それらのコンポーネント内のすべてのノードが同時に非魔法的になります。 

この制約は十分に大きいため、最初から削除するたびに接続をシミュレートするアプローチは失敗します。 最大 100 万のノード、エッジ、クエリがある場合、クエリごとの線形トラバーサルでも 2 次の最悪のケースが発生し、これは実行可能な制限をはるかに超えています。 

単純なアプローチでは、BFS または DFS を使用して削除するたびに特別なセットから到達可能性を再計算します。 これにはクエリごとに O(N + M) のコストがかかり、最悪の場合は 10^12 の演算に達する可能性があります。 

2 番目の単純なアイデアは、削除時に動的接続を直接維持することです。 標準の動的グラフ接続は、プロセスを逆にしない限り高価になります。 

長いチェーンを介して特別なノードにまだ接続されていた、以前は特別ではなかった領域が削除によって切断される場合、微妙なエッジ ケースが発生します。 単一の関節点でその連鎖が切れると、多くのノードが同時に魔法を失います。 たとえば、単一の特別なノードに接続された非特別なノードを中心とする星です。中心を削除すると、すべての葉が切断され、たとえ葉自身が削除されなかったとしても、すべての葉は即座に非魔法的になります。 

## アプローチ

 主な問題は、無向グラフでは削除を処理するのが難しいことです。 Union-find のような接続構造は、削除を効率的にサポートしません。 

重要なアイデアは時間を逆転させることです。 ノードを 1 つずつ削除するのではなく、クエリされたすべてのノードがすでに削除されている最終状態から開始して、逆の順序で再導入することを想定します。 これにより、削除が挿入に変換され、union-find 構造で効率的に処理できます。 

まず、削除されるすべてのノードにマークを付けます。 これらのノードは最初は存在しないものとみなされます。 この縮小されたグラフでは、残りのすべてのノードをアクティブ化し、union-find で接続しますが、現在「生きている」ノード間でのみ行います。 

特殊なノードを処理するために、union-find コンポーネントに少なくとも 1 つの特殊なノードが含まれているかどうかの概念を維持します。 コンポーネントは、その代表がマージされたセットに少なくとも 1 つの特別なノードを持っている場合に限り、魔法のようになります。 

ノードを再挿入すると、そのノードが現在アクティブなすべての隣接ノードに接続されます。 ノード自体が特別な場合、非魔法のコンポーネントを魔法のコンポーネントに変えることができます。 重要な観察は、特別なノードに接続されたコンポーネントのみが重要であるということです。 他のすべてのコンポーネントは答えとは無関係です。 

ノードが再挿入されると、魔法になるノードの数は、この挿入により特別なノードに新たに接続されるようになったコンポーネントのサイズに正確に対応します。 コンポーネントのサイズとコンポーネントに特別なノードが含まれているかどうかを追跡することで、デルタを効率的に計算できます。 

反転により、各エッジが最大 1 回考慮されるようになり、線形に近い複雑さが得られます。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (クエリごとに BFS を再計算) | O(Q(N+M)) | O(N+M) | 遅すぎる |
 | 逆削除 + DSU | O((N+M) α(N)) | O(N+M) | 承認済み |

 ## アルゴリズムのチュートリアル

 Union-find 構造を使用して問題を逆方向に処理します。 

1. クエリで削除されるすべてのノードをマークします。 これらのノードは最初は非アクティブとみなされます。 
2. 他のすべてのノードをアクティブとして初期化します。 これらは、すべての削除後の最終的なグラフの状態を表します。 
3. すべてのエッジを反復処理し、両方のエンドポイントがアクティブな場合にのみエンドポイントをマージすることにより、アクティブなノード上にユニオン検索構造を構築します。 

これにより、すべての削除が行われた後でも接続が可能になります。 
4. 各 Union-find コンポーネントについて、そのサイズと、少なくとも 1 つの特別なノードが含まれているかどうかという 2 つの情報を維持します。 
5. コンポーネントが現在「マジカル」であるかどうか、つまりコンポーネントが少なくとも 1 つの特別なノードに接続されているかどうかを追跡する配列を初期化します。 
6. クエリを逆の順序で処理します。 各ステップで 1 つのノードが再アクティブ化されます。 
7. ノードが再アクティブ化されると、最初はそのノードをシングルトン コンポーネントとして扱います。 特別な場合は、そのコンポーネントを魔法としてマークします。 
8. すでにアクティブになっている再アクティブ化されたノードの各隣接ノードについて、そのコンポーネントを結合します。 

2 つのコンポーネントをマージする場合は、マージされたコンポーネントに特別なノードが含まれているかどうかを注意深く追跡してください。 
9. すべての結合の後、このノードを含む新しく形成されたコンポーネントが魔法であるかどうかを確認します。 そうである場合、特別なノードに接続されているマージされたコンポーネント内の以前は非魔法のノードが新たに魔法になります。 
10. このステップの答えは、このアクティブ化により非魔法から魔法に移行したノードの数です。 
11. この値を保存し、次の逆クエリに進みます。 
12. 最後に、保存された回答を逆にして、元の順序で結果を取得します。 

### なぜ効果があるのか

 不変条件は、逆時間の各ステップで、union-find 構造が、まだ再アクティブ化されていないノードによって引き起こされるグラフの接続性を正確に表すことです。 各コンポーネントは、非アクティブなノードを経由せずに相互に到達可能なノードを正確に反映します。 ノードが魔法になるのは、そのノードが特別なノードを含むコンポーネントに属している場合に限り、魔法のステータスを判断するには、コンポーネントに特別なノードが含まれるかどうかを追跡するだけで十分です。 

すべてのエッジは逆方向に 1 回だけ導入されるため、接続情報が二重にカウントされたり、欠落したりすることはありません。 各ノードの非魔法から魔法への移行は、そのコンポーネントが特別なノードに初めて接続された瞬間に 1 回だけ記録されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n, special):
        self.parent = list(range(n))
        self.size = [1] * n
        self.has_special = special[:]  # component contains special node
        self.active = [False] * n      # node exists in current reversed graph

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return 0

        gain = 0

        # merge rb into ra
        if self.size[ra] < self.size[rb]:
            ra, rb = rb, ra

        # before merge: if one side had special and the other didn't,
        # and rb side becomes newly connected to special through ra,
        # we need to compute activation effect carefully
        was_ra = self.has_special[ra]
        was_rb = self.has_special[rb]

        self.parent[rb] = ra
        self.size[ra] += self.size[rb]
        self.has_special[ra] = was_ra or was_rb

        # gain happens when a component becomes connected to special via merge
        if self.has_special[ra] and not (was_ra and was_rb):
            # This merge may activate all nodes in the non-special side
            if was_ra and not was_rb:
                gain += self.size[rb]
            elif was_rb and not was_ra:
                gain += self.size[ra] - self.size[rb]

        return gain

def solve():
    n, m, c = map(int, input().split())
    special = [0] * n
    for x in map(int, input().split()):
        special[x - 1] = 1

    edges = []
    adj = [[] for _ in range(n)]

    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        edges.append((u, v))
        adj[u].append(v)
        adj[v].append(u)

    q = int(input())
    queries = [int(input()) - 1 for _ in range(q)]

    removed = [False] * n
    for x in queries:
        removed[x] = True

    dsu = DSU(n, special)

    # activate nodes not removed in final state
    for i in range(n):
        if not removed[i]:
            dsu.active[i] = True

    # initial unions
    for u, v in edges:
        if dsu.active[u] and dsu.active[v]:
            dsu.union(u, v)

    # we will track whether node is currently contributing to answer
    in_comp_special = [0] * n

    def comp_has_special(x):
        return dsu.has_special[dsu.find(x)]

    # process queries in reverse
    ans = [0] * q

    for i in range(q - 1, -1, -1):
        v = queries[i]
        dsu.active[v] = True

        # start new component effect
        newly = 0
        if special[v]:
            newly += 1

        # union with active neighbors
        for to in adj[v]:
            if dsu.active[to]:
                newly += dsu.union(v, to)

        ans[i] = newly

    for x in ans:
        print(x)

if __name__ == "__main__":
    solve()
```この解決策は、コンポーネントに特別なノードが含まれているかどうかに関するメタデータで強化された Union-find 構造に依存します。 再アクティブ化された各ノードは、すでにアクティブな隣接ノードに接続され、ユニオン操作は、以前は魔法ではなかった領域がいつ特別なセットに接続されるかを識別する役割を果たします。 主な微妙な点は、結合後に元のコンポーネントの境界が失われるため、移行の瞬間にサイズの計算が確実に行われるようにすることです。 

ノードが再アクティブ化されると段階的にエッジを再接続する必要があるため、隣接リストが必要です。 アクティブ アレイにより、反転プロセスにまだ存在しないノードを介して接続することがなくなります。

 ## 特殊なケース

 重要なエッジ ケースは、複数の大きなコンポーネントを 1 つの特別なノードに接続するブリッジ ノードを削除するときに発生します。 フォワードタイムでは、これにより魔法のノードが突然大量に非アクティブ化されます。 

たとえば、ノード 2 を中心とし、リーフ 3、4、5 を持つスターがあり、特別なノード 1 はノード 2 を介してのみ接続されています。ノード 2 を削除すると、接続が切断されます。 逆に、ノード 2 を追加すると、すべてのリーフが再接続され、非魔法のコンポーネントが魔法になる単一の DSU マージがトリガーされます。これは 1 回だけカウントされます。 

もう 1 つのエッジ ケースは、削除されたノード自体が特別である場合です。 この場合、逆に再アクティブ化すると、そのコンポーネントは即座に魔法としてマークされますが、接続の変更によって追加の到達可能な特別なノードが導入されない限り、他のノードはカウントされるべきではありません。
