 ## 解決策
 ## 問題の理解

 この問題は、円形の領域とそれを 2 つの部分に分割するカットを含む幾何学的状況を記述しています。 1 つの部分は「緑色」のセグメント状の領域であり、その面積は高さパラメータに依存します。$h$、半径$R$、および円形セグメントのジオメトリ。 ステートメント自体は通常の CF 形式では不完全ですが、提供された式は重要な計算を明らかにします。つまり、円セクターから三角形を引いた構造から導出される面積式を評価することが期待されています。 

具体的には、このタスクは、半径の円を切断することによって定義される円形セグメントの面積を計算することになります。$R$高さに水平線が入っている$h$。 緑色の領域は、そのカットの上または下の円の部分に対応し、その面積は逆余弦項と線形補正項を使用して表されます。$R - h$。 与えられた式は次のとおりです。$$a = R^2 \arccos\left(1 - \frac{h}{R}\right) - (R - h)\sqrt{2Rh - h^2}$$これは円形のセグメント領域の標準的な表現で、最初の項は扇形領域に対応し、2 番目の項は弦によって形成される三角形の領域を減算します。 

したがって、入力は、1 つ以上のそのような幾何学的構成を記述する値、通常は半径と切断高さを含むペアまたはトリプルで構成されます。 出力は、各構成について計算された緑色の領域です。 

計算の観点から見ると、重要な制約の意味は、これが組み合わせやグラフの問題ではなく、浮動小数点の評価問題であるということです。 まででも$10^5$クエリでは、安定した数値関数を使用して、各クエリに一定時間内に応答する必要があります。 これにより、クエリごとの幾何学的再構成や反復数値積分が即座に排除されます。 

主なエッジ ケースは、関数 arccos のドメイン境界に由来します。 いつ$h$非常に小さい、または非常に近い$2R$、平方根またはアークコス内の式は数値的に不安定になる可能性があります。 たとえば、次の場合$h = 0$、面積はゼロになるはずです。 もし$h = 2R$、面積は完全な円である必要があります$\pi R^2$。 浮動小数点値をクランプしない単純な実装では、精度のドリフトにより、アークコスのドメイン エラーや平方根以下の負の値が発生する可能性があります。 

## アプローチ

 ブルートフォース解釈では、ジオメトリを明示的に再構築しようとします。 円を細かい角度ステップに離散化し、小さな領域の寄与を合計し、セグメントを数値的に近似することができます。 リーマン和は真の面積に収束するため、これは原理的には正しいと考えられますが、各クエリには$O(K)$ステップどこ$K$は離散化解像度です。 控えめでも$K = 10^6$入力サイズが大きい場合、クエリごとに実行できなくなり、$10^{11}$最悪のシナリオでの運用。 

重要な観察は、円形セグメントの幾何学形状が閉じた形式の表現を持っているということです。 緑色の領域が弦の高さによって完全に決定されることが認識されると、問題全体はクエリごとの定数時間式の評価に集約されます。 アークコス項は弦によって定められる中心角に由来し、平方根項は弦の端点によって形成される三角形の高さです。 

これにより、問題は数値近似から、導出された解析式の直接評価に変換されます。 残された唯一の課題は、数値の安定性と境界ケースの正しい処理です。

 ## アルゴリズムのチュートリアル

 各テスト ケースが半径を提供すると仮定します。$R$そして高さ$h$、切断線が円の底部からどのくらいの距離にあるかを示します。 

1.読む$R$そして$h$。 ジオメトリは対称であるため、セグメントを決定するにはこれら 2 つの値のみが必要です。 
2. コードに関連する中間量を計算します。$$x = 1 - \frac{h}{R}$$これは、正規化された形式で中心角の半分の余弦を表します。 これは arccos 関数内で使用されます。 
3. クランプ$x$有効なドメインに$[-1, 1]$。 これにより、浮動小数点エラーによって arccos への無効な入力が生成されるのを防ぎます。 このステップを行わないと、次のような値になります。$1.0000000002$計算がクラッシュする可能性があります。 
4. 中心角を計算します。$$\theta = \arccos(x)$$この角度は、セグメントの一部を形成する扇形に対応します。 
5. 高さに基づく三角形の項を計算します。$$t = \sqrt{h(2R - h)}$$これは、弦の下の三角形の領域を減算するために使用される垂直距離コンポーネントです。 
6. 両方の部分を最後の領域に結合します。$$a = R^2 \theta - (R - h)t$$この式は、セクターから三角形を減算して緑色の領域を生成します。 
7. 十分な精度 (通常は小数点以下 10 ～ 15 桁) で結果を出力します。 

### なぜ効果があるのか

 このアルゴリズムは、円セグメントの幾何学的分解を扇形から二等辺三角形を引いたものに直接転写したものです。 不変条件は、有効なすべての時点で、$h$、セグメント領域は、弦によって定められる中心角によって一意に決定されます。 arccos 変換により、円のジオメトリを正確に保持しながら、線形の高さを角度の測定値に正しくマッピングできるようになります。 どちらのコンポーネントも正確なユークリッド恒等式から導出されるため、誤差の唯一の原因はクランプによって制御される浮動小数点演算です。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

def solve():
    data = input().strip().split()
    if not data:
        return
    
    it = iter(data)
    out = []
    
    for R_s, h_s in zip(it, it):
        R = float(R_s)
        h = float(h_s)

        if h <= 0:
            out.append("0.0000000000")
            continue
        if h >= 2 * R:
            out.append(f"{math.pi * R * R:.10f}")
            continue

        x = 1 - h / R
        x = max(-1.0, min(1.0, x))

        theta = math.acos(x)
        tri = math.sqrt(max(0.0, h * (2 * R - h)))

        area = R * R * theta - (R - h) * tri
        out.append(f"{area:.10f}")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このソリューションは、1 回のパスですべての値を読み取り、ペアごとに一定時間で処理します。 特殊な場合$h \le 0$そして$h \ge 2R$無効な平方根を防ぎ、セグメントがゼロ領域または完全な円に縮退する正確な幾何学的限界を復元します。 

の使用`max(0.0, h * (2R - h))`数値安定性を確保する$h$境界線に極めて近い状態です。

 ## 特殊なケース

 いつ$h = 0$、コードは円の下部の点まで折りたたまれます。 このアルゴリズムは、arccos を評価せずにただちに 0 を返し、縮退した角度の計算を回避します。 三角項もゼロになります。$h(2R-h) = 0$。 

いつ$h = 2R$、カットは円の上部を通過し、ディスク全体が含まれます。 アルゴリズムは次のように切り替わります。$\pi R^2$、精度の低下を引き起こす可能性がある 2 つのほぼ等しい大きな項の間のキャンセルを回避します。 

いつ$h$どちらかの境界に非常に近いため、浮動小数点の丸めによりプッシュされる可能性があります$1 - h/R$少し外側$[-1, 1]$。 クランプステップにより、アークコスが定義されたままになることが保証され、`max(0.0, ...)`ガードは、精度のドリフトによって引き起こされる小さな負の数の平方根を取るのを防ぎます。
