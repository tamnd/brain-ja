 ## 解決策
 ## 問題の理解

 小さな都市地図のように動作する長方形のグリッドが与えられます。 道路の監房もあれば、動きを妨げる建物の監房もあり、限られた視野で一定の方向を見つめる警察官が収容されている監房もあります。 逃亡者は特定のセルから出発し、道路セルを通って基本的な 4 つの方向にのみ移動して、指定された隠れ家セルに到達したいと考えています。 

重要な問題は、すべてのロードセルが安全であるわけではないことです。 警察官の視界に入った独房は危険となり、逃亡者はそこに入ることができず、通り抜けることさえできません。 各警官は自分が向いている方向を距離 D までまっすぐに見ていますが、建物や他の警官に当たると視界が早期に停止します。 

任務は、安全な道路セルのみを使用して、逃亡者の出発点から隠れ家までの経路が存在するかどうかを判断することです。 

グリッドは 1000 x 1000 までの大きさになるため、最大 100 万個のセルが存在します。 すべてのセルからすべての警察官に向けて可視性を素朴にチェックしたり、動きごとにスキャンを繰り返したりするソリューションは遅すぎます。 グリッド上の線形または線形に近い走査が必要です。これには、安全でないセルを一度マークしてから、標準の最短パスまたは到達可能性の検索を実行する前処理が必要になる場合があります。 

複数の警察官が視線を重ねると、微妙なケースが発生します。 たとえば、2 人の警官が間に壁がなく向かい合っている場合、警官を邪魔者として扱わない単純なアプローチでは、警官を通して誤って視界が広がる可能性があります。 

別のエッジ ケースは、パスが幾何学的に存在するものの、_間接的に_ 安全でないだけのセルを通過する場合に発生します。 たとえば、監房には警官がいない可能性がありますが、その先には遮られた長い視界の通路内に正確に位置している可能性があります。 

## アプローチ

 直接的な総当たり戦略は、すべての警察官の可視性を個別にシミュレートすることです。 各警官ごとに、D セルまで、またはブロッカーにぶつかるまで、その向いている方向に一歩ずつ歩き、訪問したすべてのセルを危険としてマークします。 すべての警察官を処理した後、危険なセルを避けて逃亡者から隠れ家までBFSまたはDFSを実行します。 

このアプローチは論理的には正しいですが、最悪の場合のコストは高くなります。 多くの警察官がいる密なグリッドでは、各スキャンが最大 D ステップで行われ、最悪の構成ではマーキング フェーズだけで O(N × M × D) かかる可能性があります。これは、すべてのセルが多くの警察官のスキャン パス内にある可能性があるためです。 N、M、D がすべて 1000 に達すると、これは非常に遅くなります。 

重要な点は、再帰的または繰り返しの方法で各警察官のビジョンを個別にシミュレートする必要がないということです。 各警察官の視線は、グリッド上の単純な指向性光線です。 役員ごとの可視性を再計算する代わりに、4 方向のスイープでグリッドを前処理できます。 各スイープでは、現在アクティブな視覚セグメント内にいるかどうかを維持しながら、最も近いブロック エンティティを伝播します。 

具体的には、行を左から右および右から左に、列を上から下および下から上にスキャンできます。 掃討中、最後に遭遇した警察官と、その警察官が目撃されてからの距離を維持します。 距離が D を超えるか、遮るものに遭遇すると、視覚は停止します。 これにより、役員ごとのシミュレーションの繰り返しが、セルごと、方向ごとの一定の作業に変換されます。 

すべての安全でないセルをマークした後、ブロックされたセルを含むグリッド上の F から H までの標準的な到達可能性検索に問題を落とし込みます。 これは、O(NM) の単純な BFS です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 役員ごとのブルート フォース シミュレーション | O(N・M・D) | O(NM) | 遅すぎる |
 | 指向性スイープ + BFS | O(N・M) | O(NM) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ブール値グリッドを構築する`danger`false に初期化されます。 これにより、視界の壁であるか、少なくとも 1 人の警官が直接見えるすべてのセルにマークが付けられます。 
2. すべての行で左から右へのスイープを実行します。 右を向いた最新の警察官を追跡します (`>`）。 視界を遮る建物や他の警官に遭遇すると、追跡をリセットします。 アクティブな右向きの警官の後の各セルについて、距離が D を超えるまで危険とマークします。これにより、有効な中断のないセグメントに沿ってのみ可視性が伝播されることが保証されます。 
3. すべての行で右から左へのスイープを実行し、左向きの役員にも同じロジックを適用します (`<`）。 再びブロッカーで伝播を停止し、距離 D を尊重します。 
4. 上向きの役員のすべての列で上から下へのスイープを実行します (`^`）。 ブロックされるか距離が D を超えるまで、最も近いアクティブな上方ビジョン ソースを維持し、セルにマークを付けます。 
5. 下向きの役員のすべての列で下から上へのスイープを実行します (`v`）。 到達可能なすべてのセルを同じ制約された方法でマークします。 
6. 4 回のスイープすべてが完了すると、すべてのセルが でマークされます。`danger`は逃亡者が立ち入ることができない独房を表します。 
7. 開始セルから BFS を実行します。`F`。 境界内にあり、建物ではなく、危険とマークされていないセルのみを通過してください。 到達したら`H`、YESを出力します。 それ以外の場合は NO を出力します。 

これが機能する理由は、各将校のビジョンが直線軸に沿って単調であるためです。 役員の影響を受けるセルは、その方向の最も近いブロック セグメントによってのみ決定されます。 スイープにより、役員ごとのセルを再検討することなく、最大の連続セグメントを正確にシミュレートできるようになります。 次に、BFS は完全に事前計算された静的安全マップに基づいて動作し、有効なパスが検出されることを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

n, m, D = map(int, input().split())
grid = [list(input().strip()) for _ in range(n)]

danger = [[False] * m for _ in range(n)]

# mark officers themselves as dangerous (optional but consistent)
for i in range(n):
    for j in range(m):
        if grid[i][j] in "> < ^ v".split():
            danger[i][j] = True

# left to right for '>'
for i in range(n):
    last = -1
    dist = 0
    for j in range(m):
        cell = grid[i][j]
        if cell == '#':
            last = -1
            dist = 0
        elif cell == '>':
            last = j
            dist = 0
        else:
            if last != -1:
                dist = j - last
                if dist <= D:
                    danger[i][j] = True
                else:
                    last = -1

# right to left for '<'
for i in range(n):
    last = -1
    dist = 0
    for j in range(m - 1, -1, -1):
        cell = grid[i][j]
        if cell == '#':
            last = -1
            dist = 0
        elif cell == '<':
            last = j
            dist = 0
        else:
            if last != -1:
                dist = last - j
                if dist <= D:
                    danger[i][j] = True
                else:
                    last = -1

# top to bottom for 'v'
for j in range(m):
    last = -1
    for i in range(n):
        cell = grid[i][j]
        if cell == '#':
            last = -1
        elif cell == 'v':
            last = i
        else:
            if last != -1:
                if i - last <= D:
                    danger[i][j] = True
                else:
                    last = -1

# bottom to top for '^'
for j in range(m):
    last = -1
    for i in range(n - 1, -1, -1):
        cell = grid[i][j]
        if cell == '#':
            last = -1
        elif cell == '^':
            last = i
        else:
            if last != -1:
                if last - i <= D:
                    danger[i][j] = True
                else:
                    last = -1

# BFS
for i in range(n):
    for j in range(m):
        if grid[i][j] == 'F':
            sx, sy = i, j
        if grid[i][j] == 'H':
            tx, ty = i, j

q = deque([(sx, sy)])
vis = [[False] * m for _ in range(n)]
vis[sx][sy] = True

dirs = [(1, 0), (-1, 0), (0, 1), (0, -1)]

while q:
    x, y = q.popleft()
    if (x, y) == (tx, ty):
        print("YES")
        sys.exit(0)
    for dx, dy in dirs:
        nx, ny = x + dx, y + dy
        if 0 <= nx < n and 0 <= ny < m:
            if not vis[nx][ny] and grid[nx][ny] != '#' and not danger[nx][ny]:
                vis[nx][ny] = True
                q.append((nx, ny))

print("NO")
```コードは最初に 4 つの線形パスを使用して安全でない領域を構築します。 各パスでは、レイ トレーシングを繰り返す必要がある内容が 1 回のスキャンに圧縮されます。 次に、BFS セクションは、建物や危険ゾーンが通行できない標準的な障害物グラフとしてグリッドを扱います。 実装でよくある落とし穴は、壁にぶつかったときにアクティブなオフィサーをリセットするのを忘れることです。これにより、誤って視界が建物を通過してしまいます。 もう 1 つの微妙な問題は距離の処理です。これは、D を超えた後すぐにスイープを停止し、それ以上のセルのマークを続行しない必要があるためです。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N×M) | 各セルは、4 つの方向スイープと 1 つの BFS にわたって一定の回数処理されます。 
| スペース | O(N×M) | グリッド、危険マップ、BFS 訪問状態を保存 |

 この制約では最大 100 万セルが許可されるため、線形時間前処理と BFS は制限時間内に問題なく収まります。 各操作は単純な配列アクセスまたはキューのプッシュであり、Python では効率的です。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    from collections import deque

    n, m, D = map(int, input().split())
    grid = [list(input().strip()) for _ in range(n)]
    danger = [[False] * m for _ in range(n)]

    for i in range(n):
        for j in range(m):
            if grid[i][j] in "> < ^ v".split():
                danger[i][j] = True

    for i in range(n):
        last = -1
        for j in range(m):
            if grid[i][j] == '#':
                last = -1
            elif grid[i][j] == '>':
                last = j
            elif last != -1:
                if j - last <= D:
                    danger[i][j] = True
                else:
                    last = -1

    sx = sy = tx = ty = 0
    for i in range(n):
        for j in range(m):
            if grid[i][j] == 'F':
                sx, sy = i, j
            if grid[i][j] == 'H':
                tx, ty = i, j

    q = deque([(sx, sy)])
    vis = [[False]*m for _ in range(n)]
    vis[sx][sy] = True
    dirs = [(1,0),(-1,0),(0,1),(0,-1)]

    while q:
        x,y = q.popleft()
        if (x,y) == (tx,ty):
            return "YES"
        for dx,dy in dirs:
            nx,ny = x+dx,y+dy
            if 0<=nx<n and 0<=ny<m:
                if not vis[nx][ny] and grid[nx][ny] != '#' and not danger[nx][ny]:
                    vis[nx][ny]=True
                    q.append((nx,ny))

    return "NO"

 ## 特殊なケース

 特殊なケースの 1 つは、警察官が逃亡者または隠れ家のすぐ隣にいる場合です。 その場合、スイープは最初のセルを含む距離 D までのみをマークする必要があります。 距離の計算が役員の位置から開始され、すぐに隣接するセルが距離 1 として評価されるため、アルゴリズムはこれを処理します。 

もう一つのケースは、警察官が同じ方向を向いており、遮るものが何もない状態で鎖につながれている場合です。 スイープでは、最新の役員のみがアクティブとして正しく扱われるため、近くの役員が遠い役員をオーバーライドして、二重カウントを防ぎます。 

3 番目のケースは、建物がマップを多数の小さなセグメントに分割する密なグリッドです。 建物に遭遇するとアクティブな視覚状態がリセットされ、パーティション間で漏れが発生しないようにするため、各セグメントは独立して処理されます。
