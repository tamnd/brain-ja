 ## 解決策
 ## 問題の理解

 私たちには、N 羽のニワトリに対する指向性のある影響力ネットワークが与えられています。 各ニワトリは固定長 L のバイナリ文字列状態を維持し、この状態は日々進化します。 1 日目には、すべてのニワトリが最初のバイナリ文字列を持ちます。 

2 日目以降、各ニワトリは前の文字列を変更せずに維持するか、他のニワトリ A からの受信影響エッジが 1 つだけある場合は、前の文字列と A の前の文字列の XOR を計算して更新します。 重要な点は、XOR では同日の更新された状態ではなく、前日の状態が使用されるため、概念的にはすべての更新が同時に行われるということです。 

K 日目の構成を計算するように求められます。K は 10^4 まで大きくなります。 L は最大 20 であるため、各ニワトリの状態は大きな文字列ではなく小さなビットマスクであるため、ビット単位の操作が可能です。 

依存関係の構造は、各ノードが最大 1 つの入力エッジを持つ関数グラフです。 これは、インフルエンサーのないノードにルートを持つチェーンとおそらくツリーを即座に示唆します。 

素朴な解釈では、N 個の状態すべてを K 回再計算して、毎日シミュレーションします。 これには O(KN L) のコストがかかりますが、K が 10^4 で N が 1000 の場合、これは大きすぎます。 

さらに微妙な問題は、更新が XOR に対して線形であるため、複数の影響経路が寄与を蓄積する可能性があることです。 ニワトリがチェーン A → B → C の影響を受ける場合、B は A に依存し、C は B に依存するため、C は効果的に XOR 寄与を蓄積し、それが時間の経過とともにチェーンの下方に伝播します。 単純な毎日のシミュレーションは正しいかもしれませんが、不必要に遅くなります。 

チェーンが長い場合、エッジケースが発生します。 たとえば、1 → 2 → 3 で初期状態が任意の場合、各ノードの値は以前のノードの階層化された XOR になります。 K が大きい場合、再計算を繰り返すとコストが増大します。 もう 1 つのエッジ ケースは、着信エッジが存在しない孤立したノードです。そのため、状態は K に関係なく一定に保たれなければなりません。すべてのノードが更新されると想定する誤った実装は、ここで失敗します。 

## アプローチ

 強引なアイデアは、毎日を明示的にシミュレートすることです。 2 から K までの毎日、すべてのニワトリに受信インフルエンサーがあるかどうかを確認し、インフルエンサーの前の状態と XOR を適用することで、すべてのニワトリの次の状態を計算します。 各状態は長さ L のバイナリ文字列であるため、各更新のコストは O(L) で、K 日間で N 個のチキンが存在し、O(KNL) 回の操作が行われます。 K が最大 10^4、N が最大 1000、L が最大 20 の場合、これは最悪の場合約 2×10^8 ビット演算に達し、Python では限界か遅すぎます。 

重要な観察は、XOR 更新が GF(2) に対して線形であり、各ノードの最終状態が初期状態の線形結合であるということです。 さらに重要なことは、各ノードが最大 1 つの入力エッジを持つため、この構造は有向チェーンのフォレストであるということです。 これは、各ノードがチェーンを開始するか、または影響伝播の 1 つのチェーン上に存在することを意味します。 

K 個のステップをシミュレートする代わりに、プロセスを再解釈します。各ノードは、影響の逆方向にその祖先からの XOR 寄与を蓄積します。寄与が現れる回数は、K とチェーンに沿った距離のみに依存します。 これはフォレスト上の組み合わせ伝播問題となり、K ステップ内で影響がどこまで伝わるかを事前計算できます。 

エッジを反転してルートから下方向に処理し、入力チェーンに沿った距離 K 内のノードの累積 XOR 効果を各ノードに対して計算できます。 K が小さいため、O(KN) のチェーンに沿って寄与を伝播できますが、各ノードが単一の祖先パスにのみ依存することを観察することでさらに最適化できるため、チェーンの代表を事前計算して寄与を効率的にジャンプできます。 

したがって、何日も繰り返す代わりに、プロセスを各チェーンを 1 回走査し、距離 K までプレフィックス XOR 伝播を適用するようにまとめます。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(K N L) | O(N L) | 遅すぎる |
 | チェーンベースの伝播 | O(N L + K N) | O(N L) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各バイナリ文字列を整数ビットマスクに変換し、XOR 演算が O(1) になるようにします。 これは、L ≤ 20 であるため有効であり、すべての状態が標準の整数に収まります。 
2. アレイを構築する`parent`どこ`parent[v] = u`u が影響する場合 v. インフルエンサーのないノードは、`parent[v] = -1`。 
3. 各ノードについて、ルートに到達するまで親ポインタをたどることにより、ノードが属するチェーンを計算します。 これを実行している間、そのチェーン内のノードのシーケンスをルートからリーフの順序で保存します。 これが機能するのは、各ノードの親が最大 1 つであるため、分岐が発生しないためです。 
4. 各チェーンについて、チェーンに沿った初期状態のプレフィックス XOR を事前計算します。 これにより、任意のセグメントの XOR を定数時間でクエリできるようになります。 
5. チェーン内の位置 i (ルートから 0 からインデックス付けされた) の各ノードについて、K - 1 個の遷移後にチェーン内の祖先の数がそのノードに影響を与えるかを計算します。 毎日の移動は 1 ステップ前進するため、K 日目のノードは、チェーン内でその上にある距離 K - 1 までのノードに依存します。 
6. 各ノードの最終状態を、max(0, i - (K - 1)) から i までのプレフィックス セグメントの XOR として設定します。 これにより、K ステップ以内にノードに到達するすべての寄与が集約されます。 
7. すべての最終ビットマスクを固定長 L のバイナリ文字列に変換して出力します。 

微妙な点は、インフルエンスはチェーンに沿って 1 日に 1 ステップしか移動しないため、K - 1 個の遷移の後は、祖先パスの最後の K ノードのみが問題になるということです。 

### なぜ効果があるのか

 各ノードの状態は、有向パスに沿って線形 XOR 演算子を繰り返し適用することで進化します。 各ノードには最大でも 1 つの親があるため、依存関係グラフは独立したチェーンに分解されます。 各チェーンに沿って、t 日の状態は、前の状態のスライディング ウィンドウの XOR です。そのサイズは t に応じて線形に増加しますが、チェーンの長さによって制限されます。 このスライディング ウィンドウの解釈により、チェーンおよびスライス ウィンドウにわたるプレフィックス XOR の計算により、K 同期更新とまったく同じ累積が再現されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def to_mask(s):
    return int(s, 2)

def to_bin(x, L):
    return format(x, '0{}b'.format(L))

N, M, K = map(int, input().split())
init = input().split()

parent = [-1] * N
for _ in range(M):
    a, b = map(int, input().split())
    parent[b - 1] = a - 1

visited = [False] * N
chains = []

for i in range(N):
    if parent[i] == -1:
        cur = i
        chain = []
        while cur != -1:
            chain.append(cur)
            cur = -1 if parent[cur] == -1 else parent[cur]
        chains.append(chain)

ans = [0] * N
L = len(init[0])

for chain in chains:
    pref = [0]
    for node in chain:
        pref.append(pref[-1] ^ to_mask(init[node]))

    for i, node in enumerate(chain):
        l = max(0, i - (K - 1))
        ans[node] = pref[i + 1] ^ pref[l]

for i in range(N):
    print(to_bin(ans[i], L), end=' ')
```この実装ではバイナリ文字列が整数に圧縮されるため、XOR は 1 つの演算になります。 各チェーンはルートから下方向に親ポインターをたどることによって抽出され、各ノードが線形時間で正確に 1 回処理されることが保証されます。 

プレフィックス XOR 配列を使用すると、O(1) 内の任意の連続セグメント XOR を計算できます。これは、K ステップ インフルエンス ウィンドウを効率的に適用するために不可欠です。 

微妙な詳細は、固定幅 L のバイナリ文字列への変換です。パディングがないと、先頭のゼロが失われ、基になる値が正しい場合でも、不正確な出力フォーマットが生成されます。 

## 実用的な例

 ### 例 1

 入力:```
3 2 3
101 010 111
1 2
2 3
```1 → 2 → 3 のチェーンを形成します。マスクに変換します: 101=5、010=2、111=7。 

| ノード | ポジション | プレフィックス XOR | ウィンドウの開始 | 最終値 |
 | --- | --- | --- | --- | --- |
 | 1 | 0 | 5 | 0 | 5 |
 | 2 | 1 | 5^2=7 | 0 | 7 |
 | 3 | 2 | 7^7=0 | 0 | 0 |

 K=3 の場合、各ノードには最大 2 つの祖先を含めることができます。 ノード 3 はチェーンに沿って 3 つの初期値すべてを累積し、結果は 5^2^7 = 0 になります。 

これにより、スライディング ウィンドウがチェーン全体の寄与を正しく集計していることが確認されます。 

### 例 2

 入力:```
4 1 2
1 0 1 1
1 3
```チェーン: 1 → 3、ノード 2 と 4 は分離されています。 

| ノード | チェーン | 私 | ウィンドウ | 最終回 |
 | --- | --- | --- | --- | --- |
 | 1 | 1,3 | 0 | [1] | 1 |
 | 3 | 1,3 | 1 | [1,0] | 1 |
 | 2 | - | - | [0] | 0 |
 | 4 | - | - | [1] | 1 |

 孤立したノードは K に関係なく変化しませんが、チェーン ノードは利用可能な履歴に沿って蓄積されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N + M + N) | 各ノードは、チェーンとプレフィックス配列の構築中に 1 回アクセスされます。 
| スペース | O(N) | 親ポインター、チェーン、プレフィックス XOR 配列のストレージ |

 この制約では最大 1000 ノードが許可されるため、線形トラバーサルと定数時間の XOR 演算は容易に十分に高速になります。 メモリ使用量の大部分は、グラフとサイズ N のいくつかの配列の保存によって占められます。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    N, M, K = map(int, input().split())
    init = input().split()

    parent = [-1] * N
    for _ in range(M):
        a, b = map(int, input().split())
        parent[b - 1] = a - 1

    ans = [0] * N
    L = len(init[0])

    def to_mask(s):
        return int(s, 2)

    def to_bin(x):
        return format(x, '0{}b'.format(L))

    chains = []
    for i in range(N):
        if parent[i] == -1:
            cur = i
            chain = []
            while cur != -1:
                chain.append(cur)
                cur = -1 if parent[cur] == -1 else parent[cur]
            chains.append(chain)

    for chain in chains:
        pref = [0]
        for node in chain:
            pref.append(pref[-1] ^ to_mask(init[node]))
        for i, node in enumerate(chain):
            l = max(0, i - (K - 1))
            ans[node] = pref[i + 1] ^ pref[l]

    return ' '.join(to_bin(x) for x in ans)

 ## 特殊なケース

 分離されたノードの場合、`parent[i] = -1`そしてチェーン抽出ステップでは単一ノード チェーンを作成します。 そのチェーンのプレフィックス XOR 配列には初​​期値のみが含まれており、ウィンドウは K に関係なく常にその 1 つの要素に折りたたまれるため、出力は変更されません。 

K がチェーンの長さを超える長いチェーンの場合、ウィンドウ クランプは`max(0, i - (K - 1))`プレフィックス全体が取得されることを保証します。 これは、十分な日数が経過すると、すべての祖先がすべ​​ての子孫に影響を与えるという動作と一致するため、最終状態はそのノードまでの完全なチェーン プレフィックスの XOR になります。
