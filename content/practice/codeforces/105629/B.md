 ## 解決策
 ## 問題の理解

 このタスクは、標準的な丸めルールを適用することを中心に展開します。これは、算術で学ぶ「最も近い整数に四捨五入する」という考え方と同じですが、テキストまたは数字ベースの形式で与えられた数値に実装されます。 この問題では、浮動小数点演算を行う代わりに、その桁を使用して数値を直接操作することが求められます。 

実際には、入力は 10 進数で書かれた非負の整数として解釈できます。目的は、1 回の丸め演算を実行して入力を変換することです。削除される最下位桁を調べ、それが低い値に近いか高い値に近いかを判断し、必要に応じてキャリーを伝播します。 出力は、このプロセスの結果として得られる丸められた数値です。 

主な難点は、数値が大きくなる可能性があるため、一部の言語では組み込みの整数型に安全に格納できないことです。また、たとえ格納できたとしても、演算自体が算術値ではなく数字に基づいて構造的に定義されることです。 

素朴だがよくある間違いは、桁上げ伝播を行わずに丸めを実装するときに発生します。 たとえば、1995 のような入力について考えてみましょう。カスケード キャリーを処理せずに最後の桁を検査し、下から 2 番目の桁を切り上げるだけの場合、正しい 2000 ではなく、誤って 1990 または 2005 が生成される可能性があります。別の失敗ケースは、999 など、複数の 9 にまたがって丸めがカスケードされる場合です。この場合、四捨五入後にすべての桁が変化し、1000 が生成されます。どのようなソリューションでも、この連鎖反応を正しく処理する必要があります。 

もう 1 つの微妙な問題は、最後の桁のみが重要であると想定していることです。 実際、丸めによって数字が 10 になると、それより上位のすべての数字に影響が及ぶため、このプロセスは本質的に反復的または逆伝播的になります。 

## アプローチ

 ブルートフォース手法では、文字列を数値に変換し、算術規則を使用して丸めを実行してから、文字列に変換し直します。 これは概念的には簡単です。値を解釈し、丸め位置での剰余を計算し、それに応じて調整します。 このアプローチの問題は、ネイティブの整数または浮動小数点表現に依存していることです。 入力が大きい場合、変換自体がオーバーフローしたり精度が失われたりする可能性があり、そうでない場合でも、丸めに必要な桁レベルの伝播動作がわかりにくくなります。 

より堅牢なアプローチは、数字配列に直接作用します。 重要な観察は、丸めは丸め境界のすぐ右側の数字にのみ依存しますが、丸めの効果は左方向に伝播する可能性があることです。 これは、キャリーを追加する必要があるかどうかを維持しながら、右から左へのプロセスをシミュレートできることを意味します。 桁が切り上げられると判断したら、別のキャリーが発生する場合は、その増分をさらに左に伝播し続ける必要がある場合があります。 

これにより、問題は数値の終わりからの 1 つのパスに変わり、早期に停止するか、問題が解決されるまでキャリーの伝播を継続します。 この構造により、線形な時間計算量が確保され、変換の問題が回避されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (変換と計算) | O(n) かそれ以上のオーバーヘッド | O(n) | 危険/信頼性が低い |
 | 数字の伝播 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 数値を文字のリストとして扱うので、その場で数字を変更できます。

1. 右端の桁から開始して左にスキャンして、丸めを適用する必要がある最初の位置を見つけます。 これは、破棄された部分で 5 以上の値をトリガーする最初の桁です。 このステップでは、丸めによって数値が変化するピボット ポイントを特定します。 
2. ピボットが見つかったら、ピボットの桁をインクリメントする必要があることを示すキャリーを設定します。 これは、その位置での切り上げを表します。 
3. ピボットから左に移動し、キャリーを追加して各桁を更新します。 桁が 10 になると、それを 0 に設定し、キャリーを 1 のままにします。そうでない場合は、キャリーを 0 にリセットし、伝播を停止します。 
4. 最上位桁に到達しても桁上げがある場合は、新しい先頭桁 1 を挿入します。これにより、999 が 1000 になるなどのケースが処理されます。 
5. 四捨五入によりその寄与が排除されるため、ピボットの右側にあるすべての数字がゼロに置き換えられます。 

これが機能する理由は、丸めでは 1 つの位置で 1 単位の増加のみが導入され、カスケード効果は純粋に基数 10 のオーバーフローによるものであるためです。 このアルゴリズムは、現在位置の右側にあるものはすべて四捨五入ルールと一致しているという不変条件を維持し、未解決のオーバーフローを表すキャリーは常に 1 つだけ存在する可能性があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = list(input().strip())
    n = len(s)

    # find first digit that causes rounding when looking from right
    pivot = -1
    for i in range(n - 1, -1, -1):
        if s[i] >= '5':
            pivot = i

    if pivot == -1:
        print("".join(s))
        return

    carry = 1

    # set all digits right of pivot to zero
    for i in range(pivot + 1, n):
        s[i] = '0'

    # propagate carry from pivot leftwards
    i = pivot
    while i >= 0 and carry:
        val = (ord(s[i]) - ord('0')) + carry
        if val == 10:
            s[i] = '0'
            carry = 1
        else:
            s[i] = str(val)
            carry = 0
        i -= 1

    if carry:
        s.insert(0, '1')

    print("".join(s))

if __name__ == "__main__":
    solve()
```解決策は、丸めを行う必要がある右から最初の位置を特定することから始まります。 これらの桁は四捨五入後に破棄されるため、その位置の右側にあるものはすべて直ちにゼロに設定されます。 

伝播ループは重要な部分です。 ピボットで 1 つのユニットの追加をシミュレートし、桁ごとにオーバーフローを処理します。 文字演算を使用すると、文字列全体を整数に変換する必要がなくなり、非常に大きな入力に対してもソリューションが安全に保たれます。 

微妙な点は、連続する複数の数字が 9 であっても、それぞれ 0 になってキャリーが継続されるため、伝播を続行する必要があることです。

### 例 2: 1995 年

 | ステップ | 番号 | ピボット | キャリー | アクション |
 | --- | --- | --- | --- | --- |
 | 1 | 1995年 | 3 | 1 | ピボットが見つかりました |
 | 2 | 1990年 | 3 | 1 | 最後の桁は 0 になります |

これは、オーバーフローにより複数の桁が変化するカスケード キャリーを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各桁は、スキャンおよびキャリー伝播中に最大でも一定の回数アクセスされます。

 ## 特殊なケース

 主なエッジケースは、数字全体が 9 で構成されている場合です。 999 のような入力では、丸めによりすべての桁が 0 にリセットされ、先頭に追加の 1 を作成する必要があります。 アルゴリズムは、最上位桁の処理後にキャリーをアクティブのままにし、新しい桁の挿入をトリガーすることでこれを処理します。 

もう 1 つのエッジ ケースは、四捨五入をトリガーする桁がない場合です。 このような場合、ピボットは設定されないままとなり、アルゴリズムは元の数値を変更せずに返します。 これにより、不必要な変更が回避され、120 や 5000 などの入力の正確さが保証されます。 

最後のエッジケースには、1 桁の入力が含まれます。 桁が 5 未満の場合、番号は変更されません。 5 以上の場合は 10 となり、結果の長さを伸ばす必要があります。
