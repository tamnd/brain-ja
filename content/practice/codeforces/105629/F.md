 ## 問題の理解

 固定長のバイナリ文字列を扱っています$n$。 各位置は 0 または 1 なので、合計スペースには次の値が含まれます。$2^n$文字列。 これらのうち、次の 2 つの条件のうち少なくとも 1 つを満たすものがいくつあるかを数えたいと思います。文字列に少なくとも 1 つの連続したブロックが含まれています。$a$ゼロ、または少なくとも次の連続ブロックが含まれています$b$もの。 答えは必須です$10^9 + 7$。 

この種の状態は、補足的な観点から推論するのが簡単です。 通常、「長い連続を含む」文字列を直接カウントするのではなく、両方の悪いイベントを回避する文字列をカウントします。つまり、ゼロの連続が長さに達しないということです。$a$、長さに達するものはありません$b$。 最終的な答えは、合計文字列からこの制限されたセットを差し引いたものになります。 

入力できるサイズは、$n$あたりまで$10^6$、したがって、任意の二次 DP 以上$n$あるいは$O(n \cdot a)$すぐには実行不可能です。 平$O(n \log n)$定数が大きい場合は境界線になります。 これにより、状態ごとに一定または償却された一定の遷移を伴う線形時間 DP が実現されます。 

微妙なエッジケースが現れるのは、$a = 1$または$b = 1$。 もし$a = 1$の場合、どの文字列にもすでに長さ 1 以上のゼロの連続が含まれているため、すべての文字列が有効になります。 同様に、$b = 1$、すべての文字列が有効です。 単純な補数 DP は、すでに不可能な状態を誤って禁止しようとし、オフバイワンの間違いや空の状態の遷移につながる可能性があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。すべてを生成します。$2^n$バイナリ文字列を検索し、0 と 1 の最長連続連続ランをスキャンしてそれぞれをチェックします。 これは正しいですが、すぐに失敗します。$2^n$指数関数的に成長します。 たとえ$n = 40$、これは大きくなりすぎるので、ここで$n$までです$10^6$、完全に使用できなくなります。 

重要な観察は、私たちが関心を持っているプロパティは、連続する同一文字の現在の実行にのみ依存するということです。 プレフィックスの末尾に連続する 0 または 1 が何個あるかがわかれば、完全な履歴は必要ありません。 これは問題を有限オートマトンに変えます。現在の文字とその現在の実行の長さを追跡します。$a-1$ゼロと$b-1$人のために。 制限を超える遷移は禁止されます。 

これは、文字列を左から右に構築する動的プログラミングの定式化につながります。 最後の文字とそのランレングスに基づいて状態を定義しましょう。 ランレングスを持つ 0 で終わる状態の 2 つのグループを維持します。$1 \dots a-1$、およびランレングスが 1 で終わる状態$1 \dots b-1$。 各ステップで、ランレングスをシフトするかリセットして、0 または 1 だけ延長します。 

単純な DP は、これらすべての状態を明示的に維持し、位置ごとに更新します。 それには費用がかかります$O(n(a+b))$、大きすぎます。 重要な構造は、各グループ内の遷移がプレフィックス シフト操作であり、プレフィックスの合計を使用して高速化できることです。 各状態を個別に再計算するのではなく、有効な以前の状態の累積合計を計算して、各層を状態の数にわたって線形時間で更新し、ローリング プレフィックス技術を使用してさらに最適化して、合計が$O(n)$。 

最後に、補数を計算しているので、答えは次のようになります。$2^n - \text{valid}(n)$、 どこ$\text{valid}(n)$両方の長いランを回避する文字列の数です。

 ## アルゴリズムのチュートリアル

 まず、次までの 2 の累乗を事前計算します。$n$、バイナリ文字列の総数は$2^n$。 これにより、補体ステップのベースラインが得られます。 

次に、有効な文字列、つまり、次のような文字列の実行を回避する文字列の DP を構築します。$a$ゼロを使​​用して次のランを避ける$b$もの。 

2 つの配列を維持します。1 つは 0 で終わる状態用、もう 1 つは 1 で終わる状態用です。各配列には、ランレングスによってインデックス付けされたカウントが格納されます。 ステップで$i$、これらの配列は、長さのすべての有効な文字列を表します。$i$。 

新しい文字を追加するたびに、次のように新しい配列を計算します。 0 を追加する場合、長さを増やして以前の 0 のランを拡張するか、1 のランから長さ 1 の 0 のランに切り替えます。 1 を追加する場合も同じ対称ロジックが適用されます。 

「反対の文字で終わるすべてのラン」から「現在の文字で終わるすべてのラン」への移行では、プレフィックスの合計が重要になります。 新しい状態ごとに、考えられるすべての以前の実行長を反復する代わりに、各更新を状態ごとに一定の時間で計算できるように累積合計を維持します。 

すべての位置を処理した後、両方のグループにわたるすべての有効な終了状態を合計します。 これにより、両方の禁止された実行を回避した文字列の数が得られます。 これを引くと$2^n$最終的な答えが得られます。 

### なぜ効果があるのか

 不変条件は、処理後の位置です。$i$、すべての DP 状態は、長さの有効なプレフィックスの数を正確にカウントします。$i$特定の文字とランレングスで終わるもの。 禁止されたしきい値を厳密に下回っている実行のみを拡張するため、すべての遷移は有効性を保持します。 すべての有効な文字列は、各プレフィックスでランレングスに一意に分解されるため、文字列が二重にカウントされたり欠落したりすることはありません。 DP は少なくとも 1 つの制約に違反する文字列の補完セットを正確にカバーするため、補完ステップは有効です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n, a, b = map(int, input().split())

    # if any constraint allows everything
    if a == 1 or b == 1:
        print(pow(2, n, MOD))
        return

    # dp0[i] = ways ending with 0-run length i (1..a-1)
    # dp1[i] = ways ending with 1-run length i (1..b-1)
    dp0 = [0] * a
    dp1 = [0] * b

    # initial state: single 0 or single 1
    dp0[1] = 1
    dp1[1] = 1

    total_len = 1

    for _ in range(2, n + 1):
        ndp0 = [0] * a
        ndp1 = [0] * b

        # prefix sums for fast range transitions
        pre0 = [0] * (a + 1)
        pre1 = [0] * (b + 1)

        for i in range(1, a):
            pre0[i] = (pre0[i - 1] + dp0[i]) % MOD
        for i in range(1, b):
            pre1[i] = (pre1[i - 1] + dp1[i]) % MOD

        # transitions to dp0
        # extend previous 0-runs
        for i in range(1, a):
            ndp0[i] = dp0[i - 1] if i > 1 else 0
        # switch from all valid 1-runs
        ndp0[1] = pre1[b - 1]

        # transitions to dp1
        for i in range(1, b):
            ndp1[i] = dp1[i - 1] if i > 1 else 0
        ndp1[1] = pre0[a - 1]

        dp0, dp1 = ndp0, ndp1

    valid = (sum(dp0) + sum(dp1)) % MOD
    ans = (pow(2, n, MOD) - valid) % MOD
    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、2 つのランレングス DP 配列が保持され、レイヤーごとに更新されます。 微妙な部分は、「同じ文字の拡張」と「文字の切り替え」を区別することです。切り替えでは常にランレングスが 1 にリセットされ、互換性のあるすべての以前の状態がプレフィックス合計を介して集約されるためです。 

よくある間違いは、状態ごとに以前のすべてのランレングスを明示的に反復しようとすることです。$O(n^2)$爆破。 もう 1 つの典型的な問題は、ランレングスが以下に厳密に制限されていることを忘れていることです。$a$そして$b$したがって、配列のサイズはそれに応じて設定する必要があり、遷移は無効な状態に決してアクセスしてはなりません。

### 例 2

```長いゼロは許可されますが、連続するゼロは禁止されます。 

遷移後、DP は 1 が連続して出現しない文字列をカウントすることに収束します。 

| ステップ | dp0 | dp1 |

これは、非対称コンストレイントが DP を制限のないキャラクターに大きく偏らせる様子を示しています。

 | 時間 |$O(n)$| 各位置は、有界状態配列に対するプレフィックス集約を使用して定数時間遷移を実行します。 
| スペース |$O(a + b)$| 0 と 1 のランレングス状態のみが保存されます。 

制約により、最大で$10^6$、したがって線形時間が必要です。 DP は状態ごとのネストされた反復を回避し、ステップごとに線形スキャンのみを実行します。これは、小さな定数係数とローリング配列により引き続き実行可能です。
