 ## 問題の理解

 配列が与えられています`a`長さの`n`。 その要素の一部を変更することができます。 これらの変更後、配列が別の配列の存在と互換性を持つようにする必要があります。`b`長さの`n+1`、ここでのすべての値は、`a`は、次の 2 つの隣接する値の最大値として定義されます。`b`。 

つまり、それぞれ`a_i`の長さ 2 のセグメントのピークを表します。`b`: 等しい必要があります`max(b_i, b_{i+1})`。 だから、すべての`a_i`の 2 つの隣接する位置にローカル制約を適用します。`b`、そして同時に、これら 2 つのポジションのうち少なくとも 1 つが`b`実際にはこの最大値に達します。 

タスクは最小限の変更を行うことです`a`有効なものが少なくとも 1 つ存在するようにする`b`これらすべての制約を満たします。 

重要な点は、私たちは建設しているわけではないということです`b`明示的に。 私たちが気にするのは、そのようなかどうかだけです`b`の要素を最小限に調整した後に存在します。`a`できるだけ。 

制約は大きく、テスト ケース全体の長さは最大で`2⋅10^5`。 これにより、可能な構造をシミュレートまたは検索しようとするあらゆるソリューションが除外されます。`b`テストごとの二次推論でさえ遅すぎるため、明示的にです。 ソリューションはテスト ケースごとに線形である必要があります。 

素朴な故障モードは、次の 1 つの要素が存在する場合に現れます。`a`近隣のものと比べて「大きすぎる」。 たとえば、要素が隣接する要素よりも厳密に大きい場合、要素の中間構造に不可能な要件を強制する傾向があります。`b`なぜなら、共有エッジの最大値として実現可能でありながら、両方の隣接する制約を同時に支配する必要があるからです。 こうした局所的な不一致は、まさに検出して修正する必要があるものです。 

## アプローチ

 直接的なアプローチは、次のように構築してみることです。`b`固定用`a`。 それぞれのポジションを扱います`i`制約を課すものとして`(b_i, b_{i+1})`、次に値を割り当てようとします。`b`すべての制約を同時に満たします。 これは、全体的な制約充足問題になります。`n+1`変数と`n`重複する制約。 

これはバックトラッキングまたは状態の伝播で解決できますが、制約間の相互作用は配列全体に伝播します。 最悪の場合、1 つのペアのすべての決定が将来のすべてのペアに影響を及ぼし、テスト ケースごとに指数関数的分岐または少なくとも 2 次伝播が発生します。 

重要な観察は、構造が純粋にローカルであるということです。`a_i`隣接する 2 つの位置のみを接続します`b`。 したがって、グローバルに考えるのではなく、`b`、それぞれについて局所的に推論することができます。`a_i`隣接するものと互換性を持たせることができます。 

重要な単純化は、`b`隣接する要素間の局所的な一貫性の観点から実現可能性を完全に再解釈します。`a`。 このように書き換えると、問題は一貫した割り当てを妨げるローカル違反を検出して修正することになります。`b`。 

この変換後、各位置は隣接する位置を使用して一定時間でチェックでき、すべての違反を除去するために変更する必要がある位置の数をカウントするだけです。

 ## アルゴリズムのチュートリアル

 明示的な構築を避ける方法で条件を再解釈します。`b`。 それぞれ`a_i`の 2 つの隣接する位置にわたる「ピーク制約」に対応します。`b`。 このような構造に一貫性を持たせるためには、隣接する制約でサポートできない孤立した値を単一の制約で強制することはできません。 

重要な点は、不整合が局所的にのみ発生することです。`a_i`の両方の隣接する値と比較して大きすぎます`a`。 このような要素は、有効な構築においてどちらの側もサポートすることはできません。`b`ので、変更する必要があります。 

以下のように進めていきます。 

1. テスト ケースごとに、配列を読み取ります。`a`。 
2. ポジションごとに`i`、隣接する値の小さい方から受け取ることができる最も強い「サポート」を計算します。 内部ポジションの場合、これは`min(a_{i-1}, a_{i+1})`。 エンドポイントの場合、欠落している近傍を適切な方向に無限に許容するものとして扱います。 
3. かどうかを確認します。`a_i`双方から得られるサポートを超えています。 もし`a_i`両方の近隣よりも厳密に大きい場合、有効な構成はありません`b`変更せずにこの値を実現できます`a_i`。 
4. そのような位置をすべて数えます。 それぞれが必須の変更に対応します。 
5. テスト ケースごとの合計数を出力します。 

### なぜ効果があるのか

 有効な構成では、次のすべての値が必要です。`a`の共有エッジの最大値として実現できます。`b`。 要素の場合`a_i`両方の隣接する制約よりも厳密に大きい場合、どちらの隣接セグメントも`b`重なり合うエッジ構造の最大条件に違反することなく、それを「ホスト」できます。 そのピークには代替の配置がないため、実現可能性を回復する唯一の方法は、その要素を変更することです。 

逆に、もし`a_i`が両方の隣接値よりも厳密に大きいわけではない場合、それをサポートできる方向が少なくとも 1 つ存在します。つまり、対応する制約を常に次の方向に向けることができます。`b`一貫して。 これにより、局所的に不可能な位置を正確に修正するだけで十分であることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    INF = 10**18
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        if n == 1:
            print(0)
            continue
        
        ans = 0
        
        for i in range(n):
            left = a[i - 1] if i - 1 >= 0 else INF
            right = a[i + 1] if i + 1 < n else INF
            
            if a[i] > left and a[i] > right:
                ans += 1
        
        print(ans)

if __name__ == "__main__":
    solve()
```このソリューションは各テスト ケースを個別に処理し、一定時間ですべての位置をチェックします。 境界要素については、真の内部競合のみがカウントされるように、欠落している隣接要素を非制限的なものとして扱います。 

この実装は単一の線形スキャンに依存しており、補助構造は必要ありません。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        if n == 1:
            out.append("0")
            continue
        ans = 0
        INF = 10**18
        for i in range(n):
            left = a[i-1] if i-1 >= 0 else INF
            right = a[i+1] if i+1 < n else INF
            if a[i] > left and a[i] > right:
                ans += 1
        out.append(str(ans))
    return "\n".join(out) + "\n"

# provided sample
assert run("1\n4\n2 4 6 3\n") == "1\n"

# custom cases
assert run("1\n1\n100\n") == "0\n", "single element"
assert run("1\n3\n1 2 3\n") == "0\n", "monotone increasing"
assert run("1\n3\n3 2 1\n") == "0\n", "monotone decreasing"
assert run("1\n5\n1 5 1 5 1\n") == "2\n", "alternating peaks"
```| テスト入力 | 期待される出力 | 検証内容 |

 |`1 3 1 2 3`|`0`| ローカルピークなし |
 |`1 3 3 2 1`|`0`| 境界動作の減少 |
 |`1 5 1 5 1 5 1`|`2`| 交互の違反 |

 ## 特殊なケース

 のために`n = 1`、隣接する制約がないため、単一の値を選択することで常に実現できます。`b = [x, x]`。 どの位置にも条件に違反する 2 つの近傍がないため、アルゴリズムは正しく 0 を返します。 

厳密に単調な配列の場合、すべての要素は少なくとも 1 つの側面でサポートされるため、隣接する両方の要素より厳密に大きい要素はありません。 スキャンでは変更がまったく生成されません。これは、一貫した`b`チェーンに沿って値を伝播することでいつでも構築できます。 

高低が交互に現れるパターンでは、局所的なピークが両方の隣接ピークを超える高い位置に正確に表示されるため、そのような各ピークを修正する必要があります。 アルゴリズムはそれらの位置を正確にカウントし、実行不可能性を取り除くために必要な最小限の修復を照合します。
