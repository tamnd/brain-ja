 ## 解決策
 ## 問題の理解

 偶数のノードを持つツリーが与えられるので、すべてのノードはちょうど 1 つの友人ペアに属します。 各ペアは 2 つのノードを接続しており、これらのノード間の固有の単純なパスに沿ってツリー内を移動する固定関係と考えることができます。 

すべての木のエッジについて、そのエッジを削除し、どの友達のペアが最初に異なるコンポーネントに分割されるかを尋ねます。 ここでの「最初」とは、エッジの削除後に 2 つのエンドポイントが最終的に切断されるペアの最小インデックスを意味します。 そのエッジを削除してもペアが分離されない場合、答えは -1 です。 

したがって、概念的には、各ペアはツリー内にパスを誘導し、各ツリーのエッジは、それを通過するすべてのペア パスの中で最小のインデックスを知りたいと考えます。 

制約により、私たちは線形または線形に近い動作を強いられます。 すべてのテスト ケースにわたるノードの合計数は最大 5e5 で、各テスト ケースはツリーです。 各ツリーには n-1 個のエッジと潜在的に n/2 のペアがあり、各パスの長さは O(n) であるため、最短パスを再計算したり、エッジごとの接続性を再チェックしようとしたソリューションは、すぐに二次動作に低下します。 これはすでに、各ペアと各エッジを少量の一定回数だけ処理する必要があることを示唆しており、通常は入力全体で償却されます。 

各エッジの削除をシミュレートしてからすべてのペアをテストするという単純な考えがありますが、これでは O(n) 個のエッジと O(n) 個のペアを乗算して O(n^2) となり、大きすぎます。 

オーバーラップを注意深く制御せずにペアを個別に処理し、パス上のエッジをマークしようとすると、より微妙な障害モードが発生します。 単純にすべてのパスを計算し、各エッジにこれまでに確認した最小のインデックスを割り当てる場合、論理的には正しいですが、すべてのパスを明示的に計算することがボトルネックになります。 

## アプローチ

 直接的なブルート フォース アプローチでは、DFS または LCA 分解を使用して各ペア間のパスを計算し、ペア インデックスが現在保存されている値より小さい場合、そのパス上のすべてのエッジをそのペア インデックスで更新します。 これは正しいです。すべてのエッジがどのペア パスに含まれるかを正確に認識しているためです。ただし、最悪の場合、各パスの走査には O(n) のコストがかかり、O(n) 個のペアが存在するため、チェーン形状のツリーでは合計作業量が O(n^2) になります。 

重要な構造的観察は、ペア インデックスの昇順でペアによって初めてエッジが「要求」されたときのみを考慮するということです。 エッジが最小インデックスを受け取ると、それ以降のペアはそのエッジには無関係になります。 これにより、問題は、エッジがツリーから徐々に削除されるプロセスに変わります。これは、エッジが割り当てられた後、その答えが固定され、再度検討する必要がないためです。 

これは、インデックスの昇順でペアを処理し、各ペアに対してそのパスに沿って歩き、そのパス上のまだ割り当てられていないすべてのエッジを割り当てることを示唆しています。 各エッジは、最初の割り当てを取得したときに 1 回だけ削除されます。 課題は、時間の経過とともにエッジが消える動的ツリー内のパス上に残っているアクティブなエッジを効率的に見つけて横断することです。 

これは、ノード上のセグメント ツリー (エッジを親に表す) と組み合わせた重光分解を使用して解決します。 セグメント ツリーを使用すると、パス上のまだアクティブなエッジを対数時間で見つけることができ、削除を繰り返すことで各エッジが 1 回だけ処理されるようになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ペアごとのブルート フォース パスの再計算 | O(n^2) | O(n) | 遅すぎる |
 | HLD + 増分削除付きセグメント ツリー | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ツリーをノード 1 にルートし、各エッジをその子ノードに属するものとして扱います。 ノードからその親までのエッジがまだ「未割り当て」であるかどうかを追跡する構造を維持します。

また、パス上にアクティブなエッジが存在するかどうかをクエリすることと、そのようなノードを 1 つ効率的に見つけることの 2 つの操作をサポートするノード上のセグメント ツリーも維持します。 

インデックスの昇順でペアを処理するため、最初にエッジに触れた時点でその答えが得られることが保証されます。 

### ステップ

 1. ツリーを任意にルート化し、親配列と深さ配列を計算します。 ルートを除く各ノードは、その親に接続する 1 つのエッジに正確に対応します。 
2. 重光分解を構築して、任意のパスを基本配列上の O(log n) セグメントに分割できるようにします。 
3. 基本配列の位置にセグメント ツリーを構築します。各位置には、親へのエッジがまだ割り当てられていない場合は 1 が格納され、それ以外の場合は 0 が格納されます。ルートの位置は常に 0 です。 
4. インデックスの昇順でペアを繰り返します。 ペア (u, v) について、u と v の間のパス上のアクティブ エッジを繰り返し検索します。 
5. アクティブなエッジを見つけるには、パスを HLD セグメントに分解します。 各セグメントについて、値 1 を持つ任意の位置についてセグメント ツリーをクエリします。すべてのセグメントにわたって何も存在しない場合、パスは完全に処理され、停止します。 
6. アクティブなノード x が見つかった場合、それは x とparent[x] の間のエッジを表します。 ans[edge(x,parent[x])] を現在のペアのインデックスに割り当て、セグメント ツリー内でこの位置を 0 としてマークします。 
7. パス上にアクティブなエッジがなくなるまで、同じペアの検索を繰り返します。 

### なぜ効果があるのか

 このアルゴリズムはペア インデックスを厳密に昇順に処理するため、ペア パス上で初めてエッジが検出されたとき、そのペア インデックスはそのエッジを使用するすべてのペアの中で最小になります。 割り当て後、エッジは構造から削除されるため、後でより大きなインデックスを割り当てることはできません。 すべてのペアは現在アクティブなエッジとのみ対話するため、各エッジは 1 回だけ割り当てられ、割り当てはそれに触れる最も早いペア インデックスで行われます。 これは、各エッジの答えの定義と正確に一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

class SegTree:
    def __init__(self, n):
        self.n = n
        self.t = [0] * (4 * n)

    def build(self, a, v, l, r):
        if l == r:
            self.t[v] = a[l]
            return
        m = (l + r) // 2
        self.build(a, v * 2, l, m)
        self.build(a, v * 2 + 1, m + 1, r)
        self.t[v] = self.t[v * 2] + self.t[v * 2 + 1]

    def update(self, v, l, r, i):
        if l == r:
            self.t[v] = 0
            return
        m = (l + r) // 2
        if i <= m:
            self.update(v * 2, l, m, i)
        else:
            self.update(v * 2 + 1, m + 1, r, i)
        self.t[v] = self.t[v * 2] + self.t[v * 2 + 1]

    def query_any(self, v, l, r, ql, qr):
        if qr < l or r < ql:
            return -1
        if self.t[v] == 0:
            return -1
        if l == r:
            return l
        m = (l + r) // 2
        res = self.query_any(v * 2, l, m, ql, qr)
        if res != -1:
            return res
        return self.query_any(v * 2 + 1, m + 1, r, ql, qr)

def solve():
    n = int(input())
    g = [[] for _ in range(n + 1)]
    edges = []

    for _ in range(n - 1):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)
        edges.append((u, v))

    pair = [tuple(map(int, input().split())) for _ in range(n // 2)]

    parent = [0] * (n + 1)
    depth = [0] * (n + 1)
    heavy = [0] * (n + 1)

    def dfs(u, p):
        size = 1
        max_sub = 0
        parent[u] = p
        for v in g[u]:
            if v == p:
                continue
            depth[v] = depth[u] + 1
            sz = dfs(v, u)
            size += sz
            if sz > max_sub:
                max_sub = sz
                heavy[u] = v
        return size

    dfs(1, 0)

    head = [0] * (n + 1)
    pos = [0] * (n + 1)
    cur = 0

    def decompose(u, h):
        nonlocal cur
        head[u] = h
        cur += 1
        pos[u] = cur - 1
        if heavy[u]:
            decompose(heavy[u], h)
        for v in g[u]:
            if v != parent[u] and v != heavy[u]:
                decompose(v, v)

    decompose(1, 1)

    base = [0] * n
    for i in range(2, n + 1):
        base[pos[i]] = 1

    st = SegTree(n)
    st.build(base, 1, 0, n - 1)

    ans = [-1] * (n - 1)

    def query_path(u, v):
        while True:
            if head[u] == head[v]:
                if depth[u] > depth[v]:
                    u, v = v, u
                res = st.query_any(1, 0, n - 1, pos[u], pos[v])
                return res
            if depth[head[u]] < depth[head[v]]:
                u, v = v, u
            res = st.query_any(1, 0, n - 1, pos[head[u]], pos[u])
            if res != -1:
                return res
            u = parent[head[u]]

    def remove_node(idx):
        st.update(1, 0, n - 1, idx)

    for i, (u, v) in enumerate(pair):
        while True:
            x = query_path(u, v)
            if x == -1:
                break
            node = x + 1
            ans_idx = i
            if ans[node - 1] == -1:
                ans[node - 1] = ans_idx + 1
            remove_node(x)

    print(*ans)

if __name__ == "__main__":
    solve()
```このソリューションは、重光分解を構築して、ツリー パスが連続した間隔の集合になるようにします。 セグメント ツリーは、まだ割り当てられていないエッジを追跡し、パス上でアクティブなエッジを見つけるたびに、すぐにそれを割り当てて、今後の考慮事項から削除します。 繰り返されるクエリ ループは安全です。各反復で少なくとも 1 つのエッジが削除されるため、すべてのペアにわたる合計作業量は対数オーバーヘッドまでエッジの数が線形になります。 

微妙な点は、エッジが直接エッジとしてではなく子ノードに保存されることです。 これにより、個別のエッジ分解構造を持つことが回避され、各ツリー エッジが 1 つのセグメント ツリー位置に正確に対応することが保証されます。 

## 実用的な例

 ### 例 1

 ノード 1、2、3 がチェーンを形成し、1 つのペア (1,3) がある小さなツリーを考えてみましょう。 

| ステップ | アクティブパス 1-3 | エッジが見つかりました | アクション |
 | --- | --- | --- | --- |
 | 1 | 1-2-3 | エッジ (2,3) | インデックス 1 を割り当てる |
 | 2 | 1-2 | エッジ (1,2) | インデックス 1 を割り当てる |
 | 3 | なし | - | 停止 |

 唯一のペアが両方のエッジを使用するため、アルゴリズムは両方のエッジにインデックス 1 を割り当てます。 

これは、繰り返し抽出が完全なパスに沿って正しく伝播することを示しています。 

### 例 2

 1 を根とし、(2,3)、(3,4)、(4,5) のペアを持つ星を考えてみましょう。 

| ペア | 最初にアクティブなエッジが見つかりました | エッジが削除されました |
 | --- | --- | --- |
 | (2,3) | 構造に応じて 2-1 または 3-1 | パス上の 1 つのエッジ |
 | (3,4) | 残りのパス エッジ | 次のエッジが削除されました |
 | (4,5) | 最後に残ったパスのエッジ | 最終エッジを削除 |

 各エッジは、処理されたパス上に最初に存在するときに正確に割り当てられ、ペア処理の順序が最終的な答えを決定することが確認されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | 各エッジは 1 回削除され、削除ごとに対数 HLD + セグメント ツリーの作業がかかります。 
| スペース | O(n) | 隣接関係、分解配列、セグメント ツリー ストレージ |

 テスト ケース全体のノード数の合計は 5e5 であるため、実装でフルパス スキャンの繰り返しが回避されていれば、O(n log n) アプローチは Python であっても制限内に問題なく収まります。

 ## 特殊なケース

 縮退したケースは、すべてのペアが長いパスにまたがるチェーン状のツリーです。 この場合、各ペアはすべてのエッジに接触する可能性があり、アルゴリズムは同じパスからエッジを繰り返し剥がします。 各エッジは 1 回だけ削除されるため、走査を繰り返しても、総作業量はエッジの数において線形のままです。 

もう 1 つのケースは、中心ノードで多くのペアが重なっている星です。 すべてのペア パスは同じ中央エッジ構造を共有しますが、中央エッジが削除されると、後続のクエリはすぐに縮小され、割り当て後にエッジが再訪問されなくなります。
