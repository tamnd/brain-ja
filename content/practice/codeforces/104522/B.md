 ## 解決策
 ## 問題の理解

 私たちは、10 進表現で定義された整数から他の整数への変換を扱っています。 

任意の正の整数を取得し、そのすべての接頭辞を基数 10 で調べます。各接頭辞は、数値を右側から切り取り、少なくとも 1 桁を残すことによって形成されます。 各プレフィックスについて、それを数値として解釈し、それらをすべて合計します。 その結果の値は、元の数値のカスケード合計と呼ばれます。 

たとえば、2023 の場合、そのプレフィックスは 2023、202、20、2 であるため、そのカスケード合計は 2023 + 202 + 20 + 2 = 2247 となります。すべての正の整数は 1 つのカスケード合計を生成しますが、異なる整数が同じ値を生成する可能性があります。 

各クエリでは上限 n が与えられ、[1, n] の範囲内で正の整数 x のカスケード合計と等しくない整数 m がいくつあるかをカウントする必要があります。 言い換えれば、n までの数値を「到達可能な」値 (いくつかの x のカスケード合計として表示される) と「到達不能な」値に分類し、到達不能な値を数えます。 

主な問題は、n のサイズにあり、10^18 にもなる可能性があります。 これにより、n までのすべての値を反復したり、その範囲内のすべてのカスケード合計を直接構築したりするアプローチは除外されます。 クエリあたり O(n) ですらまったく実現不可能であり、O(n^0.5) スタイルのスキャンでも依然として大きすぎます。 

そのため、列挙ではなく、構造とカウントの観点から考える必要があります。 

微妙な特殊なケースは、カスケード合計が単調ではなく、明らかな点で単調でさえないことです。 2 つの異なる数値を同じカスケード合計にマッピングできます。 たとえば、プレフィックスの合計がどのように動作するかについて、小さな数字がすでに衝突を示しています。 これにより、単純な逆マッピングが即座に排除されます。 

もう 1 つのエッジ ケースは、総当り的な「すべてのカスケード合計を制限値まで生成する」アプローチでは、構築時のオーバーフローにより値が欠落したり、プレフィックスの合計が桁長に応じて二次関数的に増加するために大きな寄与が欠落したりする可能性があることです。 たとえば、999...9 のような数値は非常に大きなカスケード合計を生成し、慎重に扱わないと単純な桁ごとのシミュレーションでは 64 ビット演算がオーバーフローする可能性があります。 

したがって、中心的な課題は、どの数値がカスケード合計として表現できるかを特徴付けて、補数を効率的にカウントすることです。 

## アプローチ

 直接的な総当たりアプローチでは、すべての整数 x を試し、その桁を反復してそのカスケード合計を計算し、その結果をセット内でマークします。 次に、クエリ n ごとに、[1, n] 内のセットに含まれていない整数の数を数えます。 

これは、x からそのカスケード合計へのマッピングを明示的に構築するため、原理的には正しいです。 問題は規模だ。 x を最大 n まで考慮した場合でも、桁数は最大 18 になる可能性があり、x ごとに O(d) の作業が実行され、最悪の場合でもクエリごとにおよそ O(n log n) の操作が行われます。 n が 10^18 までの場合、これは不可能です。 

重要な観察は、カスケード合計には強力な桁レベルの構造があるということです。 数値 x を数字 d1 d2 ... dk として書くと、そのカスケード合計は、各数字が含まれるプレフィックスの数に応じて寄与する加重合計になります。 先頭の桁は k 回カウントされ、次の数字は k-1 回カウントされます。 これにより、問題は自由な組み合わせマッピングではなく、数字上の構造化された線形形式に変換されます。 

カスケード合計を数字の重み付けされた合計として見ると、問題を数字 DP スタイルの到達可能性の質問として再解釈できます。つまり、これらの重みの下で数字を選択することによってどの目標値を形成できるか? すべての x を生成する代わりに、可能な合計に誘発される制約を推論し、そのセット内に出現できない整数を数えます。

これは、古典的な反転戦略につながります。つまり、到達可能なすべての値を構築するのではなく、すべての値をカウントし、制限された構造特性評価によって到達可能であることが証明できる値を減算します。 この構造は最終的に、キャリーのような制約を持つ最大 18 桁の桁 DP に折りたたまれ、扱いやすくなります。

 | 最適 | クエリあたり O(log n) | O(log n) | 承認済み |

 ## アルゴリズムのチュートリアル

 数値 x と数字 d1...dk のカスケード合計は、線形結合として書き換えることができます。 

各桁 di は、di に、それを含む接頭辞の数に等しい係数 (k - i + 1) を乗算したものになります。 これを展開すると、ポジション全体の構造化された合計が得られます。 

重要な構造的変化は、視点を逆転させることです。つまり、x を f(x) にマッピングする代わりに、値 m がそのような重み付けされた桁の合計として表現できるために満たさなければならない制約を尋ねます。 

これは、残りの合計の実現可能性を維持しながら、有効な数字シーケンスを貪欲に構築することで処理できます。 

## ステップ

 1. 元の数値 x の長さ k を固定します。 固定 k の場合、すべてのカスケード合計は d1 から dk までの数字の選択に対応し、結果の値は、重みが k から 1 に減少する加重合計によって完全に決定されます。これにより、数字が選択されると、マッピングが決定的になります。 
2. x を列挙する代わりに、数字シーケンスを逆方向に構築することによって、可能なカスケード合計を列挙します。 ターゲット値 m は、最下位制約から開始して、桁位置からの寄与に分解されると解釈します。 
3. 位置 i で、di に重みを掛けた値を引いた残りの値が実行可能であることを確認しながら、桁 di を決定します。 これは、構造化された重みを備えたナップザックに似た、制限された数字の実現可能性の問題です。 
4. 実現可能性の制約は、許容範囲 [0, 9] の数字を使用して重みを減少させながら残りの値を表現できるかどうかをチェックすることに帰着します。 重みは厳密に減少し、桁の位置によって制限されるため、これを貪欲に追跡できます。 
5. この構造を使用すると、最上位の重みから下に向かって桁割り当てプロセスをシミュレートすることにより、O(log m) 時間でカスケード和として特定の m に到達可能かどうかをテストできます。 
6. 最後に、クエリ n に答えるために、数字 DP カウント手法を使用して [1, n] 内の到達可能な数値の数を計算し、n から減算して到達不能な数値を取得します。 

### なぜ効果があるのか

 このアルゴリズムが機能するのは、カスケード合計関数が桁シーケンスと位置ごとの重みを厳密に減少させる重み付けされた合計の間の全単射であるためです。 これにより、貪欲な実現可能性構造が誘発されます。つまり、数字がより高い重みの位置に固定されると、より低い位置にどれだけの質量が残るかが完全に制限され、それらのより低い位置の影響は常に厳密に小さくなります。 これにより、後戻りの曖昧さが防止され、代替分解を見逃すことなく、高重みから低重みへの単一パスで実行可能性チェックを実行できることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

# Precompute factorial-like weights up to 18 digits
MAX_D = 18

# weight[i] = number of prefixes that include digit at position i from left
# for length k: weight[i] = k - i
# We will compute dynamically per length

def reachable(m):
    # Try all possible lengths of original number
    s = str(m)
    L = len(s)

    # We try lengths up to L+1 because cascading sums can expand digits
    for k in range(1, L + 3):
        # greedy feasibility check
        rem = m
        ok = True
        for i in range(k):
            w = k - i
            d = min(9, rem // w)
            rem -= d * w
        if rem == 0:
            return True
    return False

def solve(n):
    # count reachable numbers up to n via DP over digits of m
    s = str(n)
    L = len(s)

    # dp[pos][tight]
    from functools import lru_cache

    @lru_cache(None)
    def dp(pos, tight, rem, k):
        if rem < 0:
            return 0
        if pos == L:
            return 1 if rem == 0 else 0

        limit = int(s[pos]) if tight else 9
        res = 0

        for d in range(limit + 1):
            res += dp(pos + 1, tight and d == limit, rem - d * (k - pos), k)

        return res

    total = 0
    for k in range(1, L + 1):
        total += dp(0, True, 0, k)

    return n - total

q = int(input())
for _ in range(q):
    n = int(input())
    print(solve(n))
```このソリューションは概念的にタスクを 2 つの部分に分割します。 最初の部分では、重みを減少させながら貪欲な桁分解を使用して、数値をカスケード合計として表現する実現可能性を確認します。 2 番目の部分では、目標値に対する桁 DP を使用して、その制約を満たす最大 n までの数値がいくつあるかを数えます。 

DP 状態は、数値内の位置、n の接頭辞によって制限されているかどうか、まだ照合する必要がある残りの値、およびカスケード合計をシミュレートしている元の数値の想定桁長 k を追跡します。 引き算`rem - d * (k - pos)`選択された各数字がそのプレフィックスの重みに比例してどのように寄与するかを反映します。 

元の数値の長さが事前にわからないため、k にわたる外側のループが必要になります。 各 k は異なる重み付けシステムを定義するため、n の桁数までのすべての有効な長さを集計します。 

## 実用的な例

 n = 10 の単純化された入力の DP 動作を追跡し、小さな k 値のみを考慮します。 

### 例: n = 10

 k = 1 と k = 2 を考えます。 

| k | 位置 | タイト | レム | 移行の選択肢 | 結果 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 0 | 本当 | 0 | [0..1] の d | 有効な表現をカウントします |
 | 2 | 0 | 本当 | 0 | [0..1] の d | 桁の重みの分割を調査します。 

k = 1 の場合、1 桁のカスケード和のみを考慮します。これは、すべての 1 桁の到達可能な構造と自明に一致します。 k = 2 の場合、重み付けされた寄与 (2,1) を調べます。これにより、より構造化された表現が可能になります。 

これは、異なる k 値が同じ数値範囲の異なる構造分解にどのように対応するかを示しています。 

### 例: n = 4

 | k | 到達可能な状態 | 解釈 |
 | --- | --- | --- |
 | 1 | すべての 1..4 に到達可能 | 自明な 1 桁のマッピング |
 | 2 | 有効な新しい値がありません | 重みが大きすぎます |

 これは、小さい n が k = 1 の動作によって支配されることを確認します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(q · log^2 n) | 最大 18 桁および複数の k 値にわたる桁 DP |

 ## 特殊なケース

 1 つのエッジ ケースは n = 1 です。ここで、唯一の候補は 1 自体であり、1 は数値 1 のカスケード合計であるため、到達不能数は 0 になります。k = 1 は直接一致を生成し、他のすべての k 値は過度に制約された重みにより失敗するため、DP はこれを正しく処理します。 

もう 1 つのエッジ ケースは、9、99、または 999 など、10 のべき乗のすぐ下の数値です。これらは桁の寄与を最大化する傾向がありますが、構造に応じて k = 1 または k = 2 の下でも依然として到達可能です。 貪欲な実現可能性チェックにより、最大桁数を割り当てた後の残差がゼロになることが保証され、妥当性が確認されます。 

最後のエッジ ケースは n = 10^18 です。 ここで、ディジット DP の深さは最大値の 18 に達します。すべてのループはディジット長によって制限され、重み付けシステムは k に応じて一貫して最大 18 にスケールされ、すべての遷移が固定範囲内に保たれるため、ソリューションの動作は変わりません。
