 ## 問題の理解

 開始整数が与えられます$x$、小さな整数を選択することで調整できます。$y$0 ～ 100 の間で選択します。$y$、数値を計算します$n = x + y$、次に 2 つの値を形成します。$n^2$そして$n^3$。 両方の数値を先頭のゼロなしで 10 進数で書き、それらを連結します。 結果の数字列には、0 から 9 までのすべての数字が 1 回だけ含まれている必要があります。 

したがって、このタスクは、広い範囲にわたって何かを最適化したり、数式を見つけたりすることではありません。 検索スペースは小さく、最大でも 101 個の候補が存在します。$y$、各受験者は基本的な算術と桁数の計算のみを必要とします。 課題は純粋に条件を正しくシミュレートし、候補が有効な 10 桁の順列を生成するかどうかを確認することです。 

境界により、この問題は計算上非常に小さくなります。 おおよそ 150 までの数値の 2 乗と 3 乗は簡単なことなので、候補者ごとの単純なチェックでも継続的な作業が必要です。 これは、すべての可能性を試すソリューションは簡単に十分に高速であり、枝刈りや数論のトリックは必要ないことを意味します。 

主なエッジケースは、書式設定と数字の処理に起因します。 先頭のゼロは、整数を文字列に変換するときに自動的に削除されるため、明示的に処理する必要はありません。 ただし、最も一般的な失敗モードは、数値を固定幅として扱ったり、連結が算術ではなく文字列ベースであることを忘れたりして、誤って桁数を数えることです。 

もう 1 つの微妙な問題は、桁の一意性を検証せずに、連結された文字列がちょうど 10 桁でなければならないと想定していることです。 たとえば、候補者が 10 桁の文字列を生成しても、数字が繰り返されたり、1 桁が欠けていたりすると、無効となります。 

## アプローチ

この問題では、解が存在する場合、それが許容範囲内にあることが保証されるため、このアプローチは正しいです。$y$。 からの変換のため、この限定された検索を超えて利用できる構造はありません。$y$数字パターンは 2 乗と 3 乗により非常に非線形になります。 

ブルートフォースのコストは非常に小さいです。 最大 101 個の候補を評価し、各候補には定数時間演算と最大数桁の演算が含まれます。 各チェックに O(20) の操作が必要だと悲観的に仮定したとしても、合計の作業量は無視できます。

2. コンピューティング$n = x + y$。 これは、解析する平方と立方体の候補となる基数です。 
3. コンピューティング$a = n^2$そして$b = n^3$。 これらは、連結する必要がある 2 つの値を定義します。

### なぜ効果があるのか

 正しさは、問題の唯一の自由度に対する網羅性に依存します。$y$。 候補者ごとに$y$、結果として得られる数字列を完全に決定し、それを厳密な一意性条件に照らしてチェックします。 からのマッピング以来、$y$数字セットへの変換が決定的であり、検索空間が完全である場合、反復中に有効な解が見つかる必要があります。 数字チェックでは、連結された文字列と 0 ～ 9 の数字のセットの間で全単射が強制されるため、受け入れられた候補は要件を正確に満たすことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def is_valid(s: str) -> bool:
    if len(s) != 10:
        return False
    return sorted(s) == list("0123456789")

def main():
    x = int(input().strip())

    for y in range(0, 101):
        n = x + y
        s = str(n * n) + str(n * n * n)
        if is_valid(s):
            print(y)
            return

if __name__ == "__main__":
    main()
```実装はアルゴリズムを直接翻訳したものです。 ヘルパー関数は数字検証ロジックを分離するため、メイン ループでの間違いのリスクが軽減されます。 重要な点は、手動で桁数をカウントしようとするのではなく、検証に文字列ソートを使用することです。これにより、周波数配列での off-by-one エラーが回避されます。 

ループの反復回数は 101 回に厳密に制限されており、予測可能な実行時間が保証されます。 有効な候補が見つかると、関数は不要な計算を避けるためにすぐに戻ります。

 ## 特殊なケース

 主なエッジケースは次のような場合です$n^2$または$n^3$はそれぞれ 4 桁または 6 桁未満です。 たとえば、次の場合$n = 2$、私たちは得ます$n^2 = 4$そして$n^3 = 8$、文字列「48」が生成されます。 長さチェックがすぐに失敗するため、アルゴリズムはこれを正しく拒否し、不正確な桁順列の評価を防ぎます。 

もう 1 つの特殊なケースは、2 つの数字にわたって数字が繰り返されることです。 たとえば、候補が「1123456789」を生成した場合、まだ 10 桁ありますが、重複のため無効です。 並べ替えの比較では、並べ替えの結果が厳密なシーケンス "0123456789" と一致しないため、これが検出されます。
