 ## 解決策
 ## 問題の理解

 根のあるツリーが与えられ、各エッジには、プロセスがそのエッジを通過する可能性を定義する重みが与えられます。 プロセスはルートから始まります。 ノードを「アクティブ化」するたびに 1 単位のコストが消費され、そのノードは空になります。 ノードに子がある場合、その子の正確に 1 つがエッジの重みに比例する確率でランダムに選択され、プロセスはその子から続行されます。 ノードがリーフの場合、それ以上移動する場所がないため、プロセスは停止します。 

各ノードはキャンディーのタイプを表します。 内部ノードには最初はキャンディーのコピーが 1 つしかありませんが、リーフには無限に多くのコピーがありますが、この区別により、主にリーフが進行をブロックしないことが保証されます。 

私たちが計算しなければならない重要な量は、すべてのノード i について、この確率的カスケード プロセスを通じてキャンディ i を取得するまでに費やされる予想される合計金額です。 

入力サイズはテスト ケース全体で 2 × 10^5 ノードに達するため、どのソリューションもテスト ケースごとに基本的に線形である必要があります。 ノードごとまたはパスごとに個別に再計算を行うと、遅すぎます。 また、ツリー構造は、各ノードの答えが、任意のグローバルな相互作用ではなく、その先祖のみに依存していることを示唆しています。 

素朴な考え方による微妙な失敗例は、ノード間の独立性を前提とすることです。 たとえば、各ノードに到達するまでプロセスを繰り返しシミュレーションしようとする場合がありますが、ツリーが深くなり、確率が乗算されて非常に小さな値になるため、単一のシミュレーションですら制限がありません。 

もう 1 つのよくある間違いは、予想されるコストがサブツリーのサイズやリーフの数に依存すると考えることです。 そうではありません。 それは、ランダム カスケードが特定のノードで正確に終了する確率にのみ依存します。 

## アプローチ

 ブルートフォース解釈では、確率過程を何度も明示的にシミュレートし、各ノードに到達する確率を推定します。 1 つのシミュレーションは、ルートから始まり、リーフに到達するまでランダムな子をたどる単一のカスケードに対応します。 このプロセスを繰り返すと、各ノードが最終エンドポイントになる頻度、またはエンドポイントに到達するまでに必要なカスケードの数を推定できます。 

これは予想としては正しいですが、計算上は使用できません。 試行ごとに 1 つのパスを生成する場合でも、最悪の場合は O(n) であり、期待値を正確に推定するには、法外な試行回数が必要になります。 n が 2 × 10^5 までの場合、モンテカルロ法や反復シミュレーションのアプローチはすぐに無効になります。 

重要な構造上の観察は、各カスケードがツリー全体にわたる任意のランダム性ではなく、遷移確率が各ノードで局所的に固定される単一のランダムなルートからリーフ ウォークであるということです。 つまり、特定のノードで終了する確率は、ルートからノードへの一意のパスに沿ったエッジ確率の積とまったく同じになります。 

単一のカスケードがノード i で終了する確率 p_i がわかれば、ノード i に到達するのに必要なカスケードの予想数は、成功確率 p_i (1 / p_i に等しい) を持つ幾何分布の予想にすぎません。 

したがって、問題全体は、各ノードの p_i を効率的に計算し、その逆モジュラーを出力することに帰着します。 

パスに沿った確率は、w(u, v) / sum_w(u) の形式の項の積であるため、その逆数は sum_w(u) / w(u, v) の積になります。 これにより、答えがツリー上の単純な乗算 DP に変換されます。

 ## アルゴリズムのチュートリアル

 ツリーを 1 でルートし、すべてのノードについて、その子に送られるエッジの重みの合計を計算します。 この値は、そのノードでの遷移確率の正規化係数を表します。

次に、ルートから DFS を実行し、各ノードに対して 1 つのカスケードで到達する相互確率を維持します。 

1. 確率的な決定が行われる前にルートに到達するため、dp[1] = 1 を設定します。 
2. 各ノード u について、u からその子までのエッジの重みの合計である S(u) を計算します。 
3. 重み w でエッジ u → v をトラバースする場合、u にいると仮定して v を選択する確率は w / S(u) です。 
4. したがって、v に到達する確率は dp_prob[v] = dp_prob[u] × (w / S(u)) となります。 
5. 確率を直接保存しません。 代わりに、 dp[v] = 1 / dp_prob[v] を保存します。これにより、パスに沿ったモジュール逆変換の繰り返しが回避されます。 
6. これにより、dp[v] = dp[u] × (S(u) / w) が得られます。 w の逆モジュラーを使用してモジュラー算術でこれを計算します。 
7. ツリー全体を 1 回走査し、dp 値をルートからリーフまで伝播します。 

それが機能する理由は、単一の不変条件に関連付けられています。つまり、すべてのノード u で、dp[u] は常に、ルートからの単一のカスケードが正確に u で終了する確率の逆数に等しくなります。 すべてのエッジが確率にローカル遷移係数を乗算し、逆数が乗算を同じ方向の逆比に変換するため、再帰ではこれが維持されます。 すべてのノードには一意の親パスがあるため、重複する部分問題や交差項は存在しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modinv(x):
    return pow(x, MOD - 2, MOD)

def solve():
    n = int(input())
    g = [[] for _ in range(n + 1)]
    
    for _ in range(n - 1):
        u, v, w = map(int, input().split())
        g[u].append((v, w))
        g[v].append((u, w))
    
    parent = [0] * (n + 1)
    pw = [0] * (n + 1)
    order = []
    
    stack = [1]
    parent[1] = -1
    
    while stack:
        u = stack.pop()
        order.append(u)
        for v, w in g[u]:
            if v == parent[u]:
                continue
            parent[v] = u
            pw[v] = w
            stack.append(v)
    
    children_sum = [0] * (n + 1)
    
    for u in range(1, n + 1):
        for v, w in g[u]:
            if parent[v] == u:
                children_sum[u] = (children_sum[u] + w) % MOD
    
    dp = [1] * (n + 1)
    
    for u in order:
        for v, w in g[u]:
            if parent[v] == u:
                dp[v] = dp[u] * children_sum[u] % MOD * modinv(w) % MOD
    
    print(*dp[1:])

if __name__ == "__main__":
    solve()
```この実装では、最初にツリーが構築され、次に明示的なスタックを使用してルート化された親構造が修正され、再帰の深さの問題が回避されます。 その後、各ノードの発信重みの合計を計算します。 これは、遷移確率に必要な正規化係数です。 

DP 伝播ステップは、以前に導出された正確な反復に従います。つまり、各子は、親からの値に、エッジの重みに対する合計出力重みの比率を乗算した値を継承します。 逆モジュラは、998244353 を法とする除算を処理するために使用されます。 

微妙な点は、ノードごとに確率を最初から再計算することは決してないということです。 すべてが 1 回の走査で流れ、直線的な複雑さが保証されます。 

## 実用的な例

 単純なツリーを考えてみましょう。 

ノード 1 には子 2 と 3 があり、それぞれ重みが 2 と 3 です。 

| ステップ | ノード | dp値 | 説明 |
 | --- | --- | --- | --- |
 | 1 | 1 | 1 | ルートベースケース |
 | 2 | 2 | (2+3)/2 = 5/2 | 2 に達する逆確率 |
 | 3 | 3 | (2+3)/3 = 5/3 | 3 に達する逆確率 |

 ノード 2 の場合、1 つのカスケードの確率は 2/5 であるため、期待される試行回数は 5/2 になります。 ノード 3 の場合、確率は 3/5 であるため、期待値は 5/3 です。 

次に、より深いチェーンを考えてみましょう。 

1 → 2 → 3 の重み 4 と 5。 

| ステップ | ノード | dp値 | 説明 |
 | --- | --- | --- | --- |
 | 1 | 1 | 1 | ルート |
 | 2 | 2 | 4/4 = 1 | 一人っ子、決定的 |
 | 3 | 3 | 1/5 | 逆数の積 |

 これは、決定論的なエッジがどのように確率をきれいに崩壊させ、分岐ノードのみが非自明なスケーリングに寄与するかを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各ノードとエッジは DFS で 1 回処理されます。 
| スペース | O(n) | 隣接リストと DP 配列 |

 この制約では合計 2 × 10^5 ノードが許可されるため、テスト ケースごとに線形走査で十分です。 このソリューションは、ノードごとの再計算やパス処理の繰り返しを回避し、ランタイムを制限内に快適に保ちます。

    input = sys.stdin.readline
    
    n = int(input())
    g = [[] for _ in range(n + 1)]

    for _ in range(n - 1):
        u, v, w = map(int, input().split())
        g[u].append((v, w))
        g[v].append((u, w))
        edges.append((u, v, w))

    pw = [0] * (n + 1)
    
    stack = [1]
    parent[1] = -1
    order = []
    
    while stack:
        u = stack.pop()
        order.append(u)
        for v, w in g[u]:
            if v == parent[u]:
                continue
            parent[v] = u
            pw[v] = w
            stack.append(v)
    
    children_sum = [0] * (n + 1)
    for u in range(1, n + 1):

            if parent[v] == u:

 ## 特殊なケース

 単一ノード ツリーは最も単純な境界です。 このアルゴリズムは dp[1] = 1 を初期化し、子がないため遷移は発生しません。 出力は正しく 1 のままです。 

完全に線形のツリーでは、すべてのノードに子が 1 つだけ存在することが保証されます。 その場合、各 S(u) は単一エッジの重みに等しいため、すべての比率は 1 になります。DP はチェーンの下に定数値を伝播し、カスケードが唯一のパスをたどる確率が 1 であるという事実と一致します。 

高次ルートは正規化をテストします。 ルートに多くの子がある場合でも、重要なのは重みの合計だけです。 各子の値は同じ根因数を使用して独立してスケーリングされ、DFS によりブランチ間の干渉が発生しないことが保証されます。
