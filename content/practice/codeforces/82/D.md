 ## 解決策
 ## 問題の理解

 私たちは、各顧客のサービス時間が既知である顧客の列をシミュレートするように求められました。 レジ係は同時に 2 人にサービスを提供できます。一度に 2 人にサービスを提供できる時間は、それぞれの最大時間です。 Vasya のヒューリスティックは、選択できるペアを制限します。キューに少なくとも 3 人がいる場合、最初の 3 人だけがペアリングの対象として考慮されます。 目標は、すべての顧客にサービスを提供するのにかかる合計時間を最小限に抑え、最小限の時間だけでなく、これを達成するペアまたはシングルトンのシーケンスも出力することです。 

入力は、整数 _n_ (顧客の数) と、サービス時間を表す正の整数のリストで構成されます。 出力は、最小合計サービス時間と、Vasya のヒューリスティックに従った正確なサービス順序で構成されます。 境界は小さく、_n_ ≤ 1000 および _a_<sub>i</sub> ≤ 10^6 であるため、O(n^2) 演算による解決が可能です。 

間違いやすいエッジ ケースとしては、_n_ = 1 (1 人のみ、ペアリングなし)、キューの長さがちょうど 2 または 3 の場合 (ペアリングの選択肢が制限されている)、および複数の顧客のタイムが等しい場合があり、最適なシーケンスでのタイブレークに影響を与える可能性があります。 たとえば、入力の場合`3\n5 2 4`、単純な貪欲なアプローチでは、最初の 2 人が自動的にペアになる可能性がありますが、これは常に最適であるとは限りません。 

## アプローチ

 ブルートフォース ソリューションでは、最初の 3 人の顧客から 2 人の顧客を繰り返し選択するすべての可能なシーケンスを検討し、最小合計サービス時間を再帰的に計算します。 これは、許可されているすべてのシーケンスを明示的に調査するため、正しいと考えられます。 ただし、可能なシーケンスの数は _n_ とともに指数関数的に (およそ 2^(n/2) のように) 増加するため、_n_ = 1000 の場合は実行不可能になります。 

重要な洞察は、問題が最適な下部構造を示しているということです。 最初の _k_ 人の顧客にサービスを提供するための最小時間は、前の 1 人または 2 人の顧客、つまり最後にサービスを提供した 1 人または 2 人の顧客が到達できる状態にのみ依存します。 したがって、動的計画法を適用することができます。 定義する`dp[i]`最初の _i_ 顧客にサービスを提供するために必要な最小限の時間として。 それぞれについて`i`、最後にサービスを受けたフェーズを 1 人の人物と見なします。`i`または最後の 3 つから選択されたペア (`i-2`そして`i-1`、`i-1`そして`i`、 または`i-2`そして`i`）。 それぞれの選択が更新されます`dp[i]`前の値の最小値に、選択したペアまたはシングルの最大サービス時間を加えた値を取得します。 

この DP アプローチは、問題を状態ごとに O(1) 遷移を伴う O(n) 状態に削減し、効率的な解決策を生成します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^(n/2)) | O(n) | 遅すぎる |
 | 動的プログラミング | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を初期化する`dp`長さの`n+1`どこ`dp[i]`最初のサービスを提供するまでの最小合計時間を保存します`i`顧客。 セット`dp[0] = 0`基本ケースとして。 維持する`choice`同じ長さの配列を使用して提供順序を再構築します。 
2. 反復処理する`i`1から`n`。 それぞれについて`i`、すべての有効な最後のフェーズを考慮します。 

- 顧客のみにサービスを提供する`i`一人で。 アップデート`dp[i] = dp[i-1] + a[i-1]`。 
- もし`i ≥ 2`、最後の 2 人の顧客に一緒にサービスを提供します。`dp[i] = dp[i-2] + max(a[i-1], a[i-2])`。 
- もし`i ≥ 3`、必要に応じて、最後の 3 つのうちの最初と 3 番目をペアにすることを検討してください (`i-2`そして`i`) 合計時間が短縮されるかどうかを確認します。 すべての有効なオプションを比較し、最小値となる選択肢を保存します。`dp[i]`。 
3.充填後`dp`、からバックトラックしてサービングシーケンスを再構築します。`i = n`を使用して`choice`配列。 各ステップで、最後のフェーズが 1 人の顧客にサービスを提供したか、2 人の顧客にサービスを提供したかを記録し、デクリメントします。`i`それに応じて、選択したインデックスを出力シーケンスの先頭に追加します。 
4. 印刷`dp[n]`最小合計時間として、その後にサービングシーケンスが続きます。 

不変条件とは、`dp[i]`最初の最小合計時間を常に保存します。`i`顧客。 DP は、Vasya のヒューリスティックに基づく有効なフェーズに対応する以前の状態のみを使用し、正確性を保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

dp = [0]*(n+1)
choice = [0]*(n+1)  # 1 if last phase is single, 2 if last phase is a pair

for i in range(1, n+1):
    # option 1: serve i alone
    dp[i] = dp[i-1] + a[i-1]
    choice[i] = 1
    
    # option 2: serve last two together
    if i >= 2 and dp[i-2] + max(a[i-2], a[i-1]) < dp[i]:
        dp[i] = dp[i-2] + max(a[i-2], a[i-1])
        choice[i] = 2
    
    # option 3: serve i-2 and i together if i >= 3
    if i >= 3 and dp[i-3] + max(a[i-3], a[i-1]) < dp[i]:
        dp[i] = dp[i-3] + max(a[i-3], a[i-1])
        choice[i] = 3

# reconstruct the serving order
res = []
i = n
while i > 0:
    if choice[i] == 1:
        res.append([i])
        i -= 1
    elif choice[i] == 2:
        res.append([i-1, i])
        i -= 2
    else:
        res.append([i-2, i])
        i -= 3

res.reverse()

print(dp[n])
for group in res:
    print(' '.join(map(str, group)))
```この実装は DP の手順に正確に従っています。 微妙な点としては、`choice`正しく配列し、インデックスを確保します`res`は 1 から始まり、次のようなオプションのフェーズを考慮します。`i-2`そして`i`先着3名様に。 Off-by-one エラーは次の方法で回避できます。`i-1`ゼロベースの配列にアクセスします。 

## 実用的な例

 ### サンプル 1

 入力:`4\n1 2 3 4`| 私 | dp[i] | 選択[i] |
 | --- | --- | --- |
 | 1 | 1 | 1 |
 | 2 | 2 | 2 |
 | 3 | 5 | 2 |
 | 4 | 6 | 2 |

 再構築されたサービングシーケンス: [1,2]、[3,4]。 合計時間 = 6。 

### サンプル 2

 入力:`3\n5 2 4`| 私 | dp[i] | 選択[i] |
 | --- | --- | --- |
 | 1 | 5 | 1 |
 | 2 | 5 | 2 |
 | 3 | 9 | 2 |

 サービングシーケンス: [1,2]、[3]。 合計時間 = 9。これは、最初の 3 つの組み合わせの中から常に最適な組み合わせを選択するヒューリスティックを示しています。
