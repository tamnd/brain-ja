 ## 解決策
 ## 問題の理解

 都市 1 にルートを持つ根付きツリーがあります。どの都市にも、最初は 1 つの軍事師団が含まれています。 分割`i`街から始まる`i`そして優先権がある`a[i]`、値が小さいほど優先度が高くなります。 

各エッジには容量があります。 毎日、各非ルート都市は親都市に向けて 1 本の列車を送ります。 その列車は最大でも運べる`c`エッジを通る分割。 市内でさらに多くの師団が待機している場合は、優先順位が最も低い師団が最初に出発します。 

部門は 1 日に 1 つのエッジを移動します。 首都に到達すると、プロセスから消えます。 すべての部門について、都市 1 に到着する最初の日を計算する必要があります。 

ツリーには最大 5000 個の頂点があります。 これにより、ノードごとの二次関数や数日にわたる重いシミュレーションは即座に排除されます。 容量 1 のボトルネックにより長いキューが作成されるため、直接シミュレーションには何日もかかる場合があります。 最悪の場合、到着時間が約2時間になる可能性があります。`n²`, そのため、毎日シミュレーションするのは遅すぎます。 

正確なタイムラインよりもプロセスの構造が重要です。 部門は常に一定のパスに沿って上に移動し、優先順位が変わることはありません。 難しいのは、各エッジでどれだけの待機が発生するかを判断することです。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

どこでも容量 1 のチェーンを考えてみましょう。```
1 - 2 - 3 - 4
priorities: 4 3 2 1
```Division 4 は最高の優先順位を持ち、最初にすべてのエッジを通過します。 ディビジョン 2 はルートに近いかもしれませんが、それでもディビジョン 4 よりも遅く到着します。距離のみに基づく解決策は間違っています。 

もう 1 つの危険なケースは、複数のサブツリーがマージされる場合です。```
    1
   / \
  2   3
```両方のエッジの容量は 1 です。都市 3 の部門が都市 2 の部門よりも優先度が高い場合、それらは異なるエッジを使用するため、干渉することはありません。 輻輳は、同じエッジを共有する部門にのみ依存します。 

3 番目の微妙なケースは、待ち時間が同じであることです。 エッジの容量が 2 で、最終的に 4 つの部門がエッジを横切るとします。 最初の 2 つはすぐに交差し、次の 2 つはちょうど 1 日余分に待ちます。 待機中の式では、整数の除算を慎重に使用する必要があります。 

例えば：```
1 2 2
5 1
1 2 2
```Division 2 は 2 日目ではなく 1 日目に到着します。`(k + c - 1) / c`の代わりに`(k / c)`間違った場所に配置すると、off-by-one エラーが発生します。 

## アプローチ

 強引なアイデアは、システムを毎日シミュレートすることです。 

各都市ごとに、待機部門の優先列を維持しています。 毎日、私たちが立ち寄るのは、`c`各都市から分割して親に移動します。 部門がルートに達したら、その日を記録します。 

このシミュレーションは、ステートメントに正確に従っているため、正しいです。 問題は走行時間です。 師団はいくつかの端で他の師団の後ろで待機する場合があります。 長い道のりの中で`n`容量 1 の場合、合計完了時間はおよそになります`1 + 2 + ... + n = O(n²)`日々。 毎日シミュレーションして多くのキューを処理すると、おおよその結果は次のようになります。`O(n³ log n)`最悪の場合の動作が大きすぎます。 

重要な観察は、部門がエッジを共有する場合にのみ相互作用するということです。 

ノードから優位に立つ`v`容量のある親に`c`。 サブツリー内のすべての部門`v`このエッジを正確に 1 回通過する必要があります。 これらは厳密に優先順位の昇順に交差します。 

部門があるとします。`k`-このサブツリー内で 2 番目に小さい優先順位。 次に:

 - 最初の`c`部門は 0 日目に交差します。 
- 次の`c`1日目に部門が交差し、
 - 次の`c`2日目に部門が交差します。 

したがって、この部門は正確に待機します`floor((k - 1) / c)`エッジに入る数日前。 

端を越えた後、さらに 1 日かけて上向きに進みます。 

これにより問題は完全に変わります。 列車をシミュレートする代わりに必要なのは、次のものだけです。 

1. ノードごとに`v`、サブツリー内のすべての部門の優先順位を知る`v`。 
2. ルートへのパス上のすべてのエッジから待機中の寄与を追加します。 

以来`n ≤ 5000`、ベクトルを結合してサブツリーをソートする余裕があります。 全体の複雑さは次のようになります。`O(n²)`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n3 log n) | O(n²) | 遅すぎる |
 | 最適 | O(n²) | O(n²) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. DFS を使用してノード 1 でツリーをルートします。 

すべてのノードについて、その親とその親につながるエッジの容量を保存します。 
2. すべてのノードについて`v`、そのサブツリー内の部門のリストを計算します。 

優先度順に並べて保存する`a[i]`。 優先順位は一意であるため、順序は厳密です。 
3. ノードの処理中`v`、すべての子サブツリー リストをマージし、除算も挿入します。`v`。 

結果として得られるソートされたリストは、分割がエッジを横切る正確な順序を表します。`v`に`parent[v]`。 
4. 除算を仮定します`x`の位置に表示されます`pos`ソートされたサブツリーリスト内で`v`。 

それではまさに`pos`このサブツリー内では、部門のほうが厳密に優先されます。 
5. エッジ容量が`c`、次に除算`x`待機後にこのエッジを通過します。```
pos // c
```余分な日数。 

最初`c`部門には`pos = 0..c-1`そして 0 日間待機します。これはプロセスと一致します。 
6. 横断するたびに 1 つの移動日がかかります。 

したがって、エッジを越えることは次のことに寄与します。```
1 + pos // c
```割り算の最終答えへ`x`。 
7. ルートへのパス上のすべての祖先エッジにこの寄与を追加します。 
8. ルートには出力エッジがないため、ディビジョン 1 はすでに首都から始まり、答えは 0 です。 

### なぜ効果があるのか

 どのエッジについても、対応するサブツリー内のすべての分割は最終的にそのエッジを 1 回だけ交差します。 トレインは常に最小の優先順位を最初にロードするため、交差順序は正確に優先順位でソートされたサブツリーになります。 

容量はこの注文をサイズのバッチに分割します`c`。 バッチ 0 はすぐに交差し、バッチ 1 は 1 日待機する、というようになります。 部門の待機時間は、同じエッジを共有する優先度の高い部門がいくつあるかによってのみ決まります。 

異なるエッジは独立して動作し、すべての部門が一意のルート パスを通過するため、エッジ全体の寄与を合計することで正確な到着時間が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(1 << 25)

n = int(input())
a = [0] + list(map(int, input().split()))

g = [[] for _ in range(n + 1)]

for _ in range(n - 1):
    u, v, c = map(int, input().split())
    g[u].append((v, c))
    g[v].append((u, c))

parent = [0] * (n + 1)
cap = [0] * (n + 1)

ans = [0] * (n + 1)

def build(v, p):
    parent[v] = p
    for to, c in g[v]:
        if to == p:
            continue
        cap[to] = c
        build(to, v)

build(1, 0)

def dfs(v, p):
    cur = [(a[v], v)]

    for to, _ in g[v]:
        if to == p:
            continue

        child = dfs(to, v)

        if len(child) > len(cur):
            cur, child = child, cur

        merged = []
        i = 0
        j = 0

        while i < len(cur) and j < len(child):
            if cur[i][0] < child[j][0]:
                merged.append(cur[i])
                i += 1
            else:
                merged.append(child[j])
                j += 1

        while i < len(cur):
            merged.append(cur[i])
            i += 1

        while j < len(child):
            merged.append(child[j])
            j += 1

        cur = merged

    if v != 1:
        c = cap[v]

        for pos, (_, node) in enumerate(cur):
            ans[node] += 1 + pos // c

    return cur

dfs(1, 0)

print(*ans[1:])
```最初の DFS はツリーをルート化し、各ノードのエッジに関連付けられた容量をその親に記録します。 

2 番目の DFS は、ソートされたサブツリー リストを構築します。 各リストにはペアが含まれます`(priority, division_id)`。 ソートされたリストをマージする方が、すべてを収集してソートを繰り返すよりも高速です。 

ノードのソートされたサブツリーリストを取得した後`v`、エッジを通じて正確な交差順序がわかります。`(v, parent[v])`。 インデックスの除算`pos`バッチに属します`pos // c`, そのため、通過するまでにその分余分に日数がかかります。 

の`+1`エッジを横切る実際の移動時間を考慮します。 

実装の微妙な詳細は、エッジを処理するたびにサブツリー全体の答えを更新することです。 これが機能するのは、すべての分割がすべての祖先エッジを 1 回だけ交差するためです。 

もう 1 つの簡単な間違いは、待機式で 1 ​​ベースのポジションを使用することです。 最初`c`部門はゼロ日待機する必要があるため、ポジションはゼロから開始する必要があります。

### 正しい洞察

 各ノードについて、そのノードからその親に向かう一連の出発時刻を維持する必要があります。 

子部門が時間の経過とともに到着すると、それらは動的にローカル優先キューに入ります。 

受け入れられた`O(n²)`ソリューションでは、順序付けされた挿入シミュレーションで DFS を使用します。

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n²) | 各サブツリー マージは最大で O(n) 個の要素を処理します。 
| スペース | O(n²) | 再帰全体で保存されたサブツリー ベクトル |

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    sys.setrecursionlimit(1 << 25)

    n = int(input())
    a = [0] + list(map(int, input().split()))

    g = [[] for _ in range(n + 1)]

    for _ in range(n - 1):
        u, v, c = map(int, input().split())
        g[u].append((v, c))
        g[v].append((u, c))

    parent = [0] * (n + 1)
    cap = [0] * (n + 1)

    def dfs0(v, p):
        for to, c in g[v]:
            if to == p:
                continue
            parent[to] = v
            cap[to] = c
            dfs0(to, v)

    dfs0(1, 0)

    ans = [0] * (n + 1)

    from heapq import heappush, heappop

    states = [[] for _ in range(n + 1)]

    def dfs(v, p):
        pq = []
        heappush(pq, (a[v], 0, v))

        for to, _ in g[v]:
            if to == p:
                continue

            child = dfs(to, v)

            while child:
                heappush(pq, heappop(child))

        if v == 1:
            while pq:
                _, t, node = heappop(pq)
                ans[node] = t
            return []

        c = cap[v]
        day = 0
        nxt = []

        arr = []

        while pq:
            arr.append(heappop(pq))

        idx = 0

        while idx < len(arr):
            take = arr[idx:idx + c]

            for pr, tm, node in take:
                nt = max(tm, day) + 1
                heappush(nxt, (pr, nt, node))

            idx += c
            day += 1

        return nxt

    dfs(1, 0)

    print(*ans[1:])

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out.strip()
