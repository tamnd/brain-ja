 ## 解決策
 ## 問題の理解

 私たちは、一連の状態のように動作する構造上でゲームのようなプロセスを与えられます。各状態はワールド内の位置を表し、状態間の遷移は可能な動きを表します。 プレイヤーは初期位置から開始し、固定ルールに従って前進するか、困難なセグメントで生き残ることを可能にするリソースを消費するアクションを繰り返し実行します。 目標は、プレイヤーが失敗状態に達することなく無期限に続行できるかどうか、あるいは同様に、ゲームの仕組みによって課せられるすべての制約を尊重しながら構造を横断する方法が存在するかどうかを判断することです。 

入力は、状態のシステムとそれらの間の有向遷移をエンコードします。 それぞれの遷移にはコストや条件が課せられる場合があり、プレイヤーが移動できるかどうかは、パスに沿って蓄積された制約の実現可能性を維持できるかどうかにかかっています。 出力は通常、最適なプレイで生存が可能かどうかに応じて、二分決定または最大の生存可能な条件を表す計算値です。 

この制約は、状態の数が数十万のオーダーで大きくなり、同様の規模の遷移が発生する可能性があることを意味します。 これにより、すべてのパスを明示的に探索したり、パスごとに繰り返し状態の再計算を実行したりするソリューションは即座に除外されます。 探索された州で指数関数的に成長するアプローチは失敗します。 状態空間に対する二次アプローチですら実現不可能であるため、解は遷移数が線形またはほぼ線形でなければならず、場合によっては対数的なオーバーヘッドが発生します。 

遷移構造にサイクルが存在する場合、一般的な微妙なエッジ ケースが発生します。 たとえば、サイクルで正味のリソース獲得が可能であれば、生存は無制限になる可能性がありますが、単純なパス シミュレーションでは、この蓄積効果が認識されずに誤って終了したり、ループしたりする可能性があります。 別のエッジ ケースは、複数のパスが異なるリソース レベルで同じ状態に達する場合に発生します。この場合、最良の状態のみが保持されるべきですが、単純な BFS または DFS によって必要な情報が上書きまたは破棄される可能性があります。 

2 番目の微妙な問題は、遷移が個別には有効でも、全体としては実行不可能である場合に発生します。 たとえば、パスはステップごとに実行可能に見えますが、累積制約が中間ステップでグローバル境界に違反します。 ローカルの有効性のみをチェックする単純な貪欲トラバーサルでは、そのようなパスが誤って受け入れられてしまいます。 

## アプローチ

 問題の強引な解釈は、初期状態から開始して考えられるすべてのパスをシミュレートし、途中でリソースまたは生存値を追跡し、いずれかのパスが制約を無期限に満たすか、またはターゲット条件に到達するかどうかをチェックすることです。 これは、あらゆる可能性を逃さずに完全な状態空間を探索するため、概念的には正しいです。 ただし、有向グラフ内のパスの数は、特にサイクルが存在する場合、深さとともに指数関数的に増加する可能性があり、計算量の爆発的な増加につながります。 単純なパスに限定したとしても、密なグラフでは数値が階乗スケールに達する可能性があり、これは実行可能な計算をはるかに超えています。 

重要な洞察は、この問題では、達成可能な最良の状態を超えた状態に到達するさまざまな方法を区別する必要がないということです。 より弱いリソース値で同じ状態に到達することは、より強いリソース値で到達することによって厳密に支配されることが認識されると、探索空間を状態全体にわたる動的プログラミングの形式に圧縮することができます。 これにより、問題は、支配的な構成を継続的に破棄しながら、遷移を通じて最適な値を伝播することに変わります。

構造にサイクルと累積効果が含まれている場合、問題はさらに、改善が無限に伝播できるかどうかを検出することに帰着します。これは、変換されたグラフに正の改善サイクルが存在するかどうかを検出するのと同じです。 ここで、最短経路型の推論またはベルマン・フォードのよ​​うな緩和が適用されます。 緩和するたびに状態値が改善され、改善が一定の限界を超えて続く場合、それは無制限の生存を意味します。 

したがって、パスを列挙する代わりに、遷移を繰り返し緩和し、最もよく知られている状態値のみを維持します。

 | オプティマル (DP / リラクゼーション) | モデルに応じて O(N + M) または O(NM) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 各ノードが最もよく知られている生存可能性の値を格納するグラフとしてシステムを再解釈します。 トランジションは、エッジにエンコードされた制約に基づいてこれらの値を更新します。 

### ステップ

 1. 配列を初期化する`best[]`ここで、各エントリは、そのノードに到達したときに存続可能な最大値を表します。 開始ノードの値を初期リソース レベルに設定し、他のすべての値を未到達の状態を表す非常に負の数に設定します。 これにより、実行可能な構成からのみ伝播することが保証されます。 
2. 更新がローカルに伝播する場合は開始ノードを処理構造 (通常はキュー) に挿入し、グローバルな伝播が必要な場合は繰り返し緩和パスを準備します。 選択は、エッジの重みが均一に動作するか、それとも繰り返しの改善が必要かによって決まります。 
3. ノードからの各エッジについて`u`ノードに`v`、候補生存可能性の値を次の関数として計算します。`best[u]`そしてエッジ制約。 この候補者がより優れている場合`best[v]`、 アップデート`best[v]`。 
4.いつでも`best[v]`が改善されたら、からのすべての出力エッジを再検討することで、この改善を前方に伝播させます。`v`。 これにより、中間ノードで途中で停止するのではなく、依存状態を通じて改善がカスケードされることが保証されます。 
5. エッジ上の完全なパスで更新が発生しなくなるまで、またはキューベースの伝播によってすべての改善が使い果たされるまで、このプロセスを続けます。 
6. 収束後、目標条件が満たされているかどうか、または無限の成長を示すしきい値を超えて改善可能なノードが残っているかどうかを確認します。 その場合は、可能な限り生存を報告し、それ以外の場合は失敗を報告します。 

### なぜ効果があるのか

 正確さは優勢不変式に依存します。いつでも、各ノードについて、その値に到達したときに達成可能な最大生存可能値を維持することだけが必要です。 将来のすべての遷移はこの保存された値とエッジ制約のみに依存するため、より小さい値で同じノードに到達するパスは、より良い結果をもたらすことはありません。 すべての緩和は保存された値を厳密に改善し、値は問題の制約またはサイクルの検出によって制限されるため、プロセスは終了するか、制限のない改善を正確に識別する必要があります。 これにより、最終状態がすべての有効なパス上で可能な限り最良の生存可能性を反映することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    g = [[] for _ in range(n)]

    for _ in range(m):
        u, v, w = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append((v, w))

    INF_NEG = -10**18
    best = [INF_NEG] * n

    start = 0
    best[start] = 0

    changed = True
    for _ in range(n - 1):
        if not changed:
            break
        changed = False
        for u in range(n):
            if best[u] == INF_NEG:
                continue
            for v, w in g[u]:
                cand = best[u] + w
                if cand > best[v]:
                    best[v] = cand
                    changed = True

    for u in range(n):
        if best[u] == INF_NEG:
            continue
        for v, w in g[u]:
            if best[u] + w > best[v]:
                print("Infinite")
                return

    print("Finite")

if __name__ == "__main__":
    solve()
```この実装は、距離を最小化する代わりに生存性スコアを最大化するように適応されたベルマン・フォード スタイルの緩和手順です。 最初のフェーズでは、最大で各ノードの達成可能な最良の値を計算します。`n-1`すべてのシンプルパスの改善が確実にキャプチャされるようにラウンドします。 

2 番目のフェーズでは、収束後も値を改善できるエッジがないかチェックします。 このようなエッジは正のサイクルを示し、ループによって生存率が無限に増加する可能性があり、これは無限の結果に相当します。 

よくある微妙な問題は、到達不能なノードを正しくスキップすることです。 小切手`best[u] == INF_NEG`無効な状態から伝播することがないことを保証し、到達不能なコンポーネントからの人為的な値のインフレを防ぎます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(NM) | 各緩和パスはすべてのエッジを処理し、最大 N 回繰り返します。 
| スペース | O(N + M) | グラフストレージと最適なアレイ |

 この制約により、最大数十万のエッジが許可されるため、特に更新が発生しない場合の早期停止を伴う、制限付き緩和アプローチが引き続き実現可能です。

 ## 特殊なケース

 正の重みを持つ単一ノードの自己ループは、無限の生存が可能である最も直接的なケースです。 初期化後、アルゴリズムはこれに正しくフラグを立てます。`best[0]`が負でなくなり、自己ループによってさらに改善され、サイクル検出チェックがトリガーされます。 

サイクルを含む切断されたコンポーネントは、最初から到達できない限り、結果に影響を与えてはなりません。 の`best[u] == INF_NEG`ガードは、到達不能なノードが緩和に参加しないことを保証するため、分離されたコンポーネントのサイクルは正しく無視されます。 

長い非環式鎖により、繰り返しの緩和が最大で 1 回後に安定します。`n-1`通ります。 アルゴリズムはこの限界を尊重し、改善が起こらない場合は早期終了条件により不必要な反復を防ぎます。
