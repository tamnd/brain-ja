 ## 解決策
 ## 問題の理解

 私たちは、マラソン中の他の 3 人のランナーに対するティムールの位置を判断するように求められました。 各テスト ケースでは 4 つの異なる整数が提供されます。最初にティムールの距離、次に他の 3 人の参加者が走った距離が続きます。 課題は、ティムールよりも厳密に長い距離を走破したランナーが何人いるかを数えることです。 

問題の構造は単純ですが、境界を理解することは役に立ちます。 各距離は 0 ～ 10,000 の範囲であり、最大 10,000 のテスト ケースを含めることができます。 これは、テスト ケースの数が線形であるソリューションが必要であることを示しています。小さな 4 要素配列の O(n²) であっても (4² は自明であるため) 技術的には許容されますが、テスト ケース間で不必要な比較を試みるコードを作成すると、非効率になる可能性があります。 

注意すべきエッジケースは、ティムールが 4 つの中で最大の距離を走ったとき、または最小の距離を走ったときです。 たとえば、Timur が 10,000 を実行し、他の人が 0、1、2 を実行した場合、正しい出力は 0 です。 Timur が常に最初か最後であると仮定した場合、不注意な解決策ではソートを使用しようとしてインデックスを誤って取得する可能性があります。 もう 1 つの微妙なエッジは、ティムールの距離を中心に他の参加者の距離が 3、4、5、2 のように連続して形成され、ティムールが 4 である場合です。不注意なロジックにより、厳密に先行する参加者と同点または後ろの参加者を誤ってカウントする可能性があります。 

## アプローチ

 最も単純なアプローチは、ティムールと他の 3 人の参加者それぞれとの距離を個別に確認することです。 カウンタを 0 に初期化し、3 つの距離にわたって繰り返し、ティムールの値より大きい値が見つかるたびにカウンタを増分します。 この総当り攻撃が機能するのは、比較する数値が他に 3 つしかないためです。したがって、最悪の場合でも、テスト ケースごとに 3 つの比較が行われます。 10,000 のテスト ケースがあるとすると、これは 30,000 の比較に相当しますが、これは最新の CPU にとっては些細なことです。 強引なやり方は正しいので、ここでは速度は問題になりません。 

最適化のための重要な洞察は、厳密に必要というわけではありませんが、リストのサイズが常に 4 であることを認識することです。 4 つの数字を並べ替えて、ティムールの順位を直接見つけることができました。 4 つの数値を並べ替えるのも簡単ですが、単純な 3 つの比較アプローチよりも多くの演算が必要になります。 並べ替えは概念的に重いため、明確さとオーバーヘッドを最小限に抑えるために比較アプローチが推奨されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | テスト ケースごとに O(1) | お(1) | 承認済み |
 | ソートベース | テスト ケースごとに O(4 log 4) | お(1) | 受け入れられるが不要 |

 結論としては、最も単純なアプローチも最適であるということです。つまり、3 つの距離のうち、ティムールの距離を超える距離がいくつあるかを数えます。 

## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取ります。 
2. テスト ケースごとに 4 つの距離を読み取り、ティムールの距離を 1 つの変数に保存し、他の変数をリストに保存します。 
3. カウンタをゼロに初期化します。 このカウンターは、ティムールより先に参加者の数を追跡します。 
4. 他の 3 つの距離のリストを繰り返し処理します。 各距離について、それがティムールの距離よりも厳密に大きいかどうかを確認します。 そうであれば、カウンターをインクリメントします。 
5. 3 人の参加者全員を確認した後、カウンターを出力します。 これはティムールの前走者の数です。 

機能する理由: このアルゴリズムは単純な不変条件を維持します。つまり、反復のどの時点でも、カウンターはこれまでに処理された参加者の中でティムールよりも遠くまで走った参加者の数を正確に反映します。 最終的には、ティムールの後ろの同点や距離を誤ってカウントする危険がなく、前方のすべての参加者を正確にカウントします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    a, b, c, d = map(int, input().split())
    counter = 0
    for distance in (b, c, d):
        if distance > a:
            counter += 1
    print(counter)
```このコードは、まずテスト ケースの数を読み取ります。 各テスト ケースでは、4 つの整数を直接アンパックします。 カウンタは、ティムールより厳密に前の参加者に対してのみインクリメントされます。 他の 3 つの距離にタプルを使用すると、反復が簡潔になり、一時的なリストの作成が回避されます。 比較は単純な整数であるため、オーバーフローや精度の問題が発生するリスクはありません。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = io.StringIO()
    sys.stdout = output
    t = int(input())
    for _ in range(t):
        a, b, c, d = map(int, input().split())
        counter = 0
        for distance in (b, c, d):
            if distance > a:
                counter += 1
        print(counter)
    return output.getvalue().strip()

# Provided samples
assert run("4\n2 3 4 1\n10000 0 1 2\n500 600 400 300\n0 9999 10000 9998\n") == "2\n0\n1\n3"

assert run("1\n10000 9999 9998 9997\n") == "0", "maximum Timur"
assert run("1\n5 5 5 5\n") == "0", "all equal (invalid for distinct but for robustness)"
assert run("1\n7 6 8 9\n") == "2", "Timur in the middle"
```| テスト入力 | 期待される出力 | 検証内容 |

## 特殊なケース

 ティムールが 4 人の中で最大の距離を走るとき、たとえば、`10000 0 1 2`、反復チェック`0 > 10000`、`1 > 10000`、`2 > 10000`、すべて嘘です。 カウンタはゼロのままで、正しい出力が生成されます。 ティムールが最小距離を走るとき、たとえば、`0 1 2 3`、比較するたびにカウンタがインクリメントされ、`3`、先の参加者の数と一致します。 

ティムールの距離付近で数字が連続している場合でも、次のようになります。`4 3 5 2`、アルゴリズムは厳密に大きいもののみをカウントします (`5`)、正しく返されます`1`。 各値をティムールの距離に対して明示的にチェックするため、これらのエッジケースを処理するために並べ替えや追加のデータ構造は必要ありません。 

この社説は、読者が第一原則に基づいて推論できることを保証します。つまり、ティムールと各参加者を比較し、先の数を数えます。これは正しく、問題のサイズにとって最適です。
