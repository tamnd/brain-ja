 ## 解決策
 ## 問題の理解

 私たちは次の結果を知っています$n$事前にサイコロを振る。 マリアンは値を選択します$a$、およびラウンドの連続セグメント$[l,r]$。 そのセグメントの各ラウンド中、彼は常に同じ値を推測します。$a$。 

実際のロール値が等しいときはいつでも$a$、彼のお金は2倍になります。 それ以外の場合は半分になります。 

マリアンはちょうど 1 ドルから始まるので、その値を見つける必要があります。$a$とセグメント$[l,r]$それが彼の最終的な金額を最大化します。 

最初の観察は、2 のべき乗のみが現れるということです。 セグメントに次の内容が含まれている場合$k$成功した推測と$m$推測が失敗した場合、最終的な金額は次のようになります。$$2^k \cdot 2^{-m} = 2^{k-m}.$$お金を最大化することは、指数を最大化することとまったく同じです$k-m$。 

セグメントの全長は、$k+m$、 それで$$k-m = k-(\text{length}-k)=2k-\text{length}.$$固定値の場合$a$、すべての発生$a$貢献する$+1$に$k$、一方、すべての非$a$地位が貢献する$-1$指数に。 課題は、最適な値と最適なセグメントを見つけることです。 

制約は大きいです。 すべての合計$n$テスト ケース全体の値は最大でも$2 \cdot 10^5$。 すべてのペアを検査するソリューション$(l,r)$それは大まかに必要になるため不可能です$n^2$仕事。 と$n=2\cdot10^5$、二次アルゴリズムは数百億の演算を実行します。 

線形に近いものが必要です。$O(n \log n)$。 

値が 1 回だけ発生する場合、微妙なエッジ ケースが発生します。 

例：```
1
5
1 2 3 4 5
```最良の答えは、任意の 1 つのポジションです。 より長いセグメントを選択すると、損失が発生するだけです。 常に複数のオカレンスを接続しようとするソリューションでは、このケースが見逃されます。 

2 つの出来事が非常に離れている場合、別の注意が必要な状況が発生します。```
1
5
7 1 1 1 7
```値 7 にセグメント全体を使用すると、指数が得られます。$$2\cdot2-5=-1.$$1 つの出現のみを使用すると指数が得られます$1$。 

最適な答えは、両方の出現を含むセグメントではなく、長さ 1 のセグメントです。 

3 番目の落とし穴は、値の最適なセグメントが必ずしも連続して開始および終了するとは限らないことです。 

考慮する：```
1
7
5 2 5 3 4 5 5
```値 5 の最適なセグメントには、ギャップがあるにもかかわらず、4 つの出現がすべて含まれます。 どの出現が最適なセグメントに属するかを自動的に決定するメソッドが必要です。 

## アプローチ

 ブルートフォースソリューションでは、考えられるすべての値が試行されます。$a$、すべての左端点、すべての右端点。 各セグメントについて、等しい位置の数がカウントされます。$a$そして、結果として得られる指数を計算します。 

これは、あらゆる法的戦略を明示的に評価するため、正しいです。 

問題は走行時間です。 がある$O(n^2)$各セグメントを単純に評価すると別のコストがかかります$O(n)$。 周波数を前処理した後でも、すべてのセグメントのチェックが残ります$O(n^2)$、それは限界をはるかに超えています。 

重要な観察はスコアの書き直しから得られます。 

いくつかの値を修正する$a$。 Let its occurrence positions be$$p_1 < p_2 < \cdots < p_m.$$セグメントがオカレンスから始まると仮定します。$p_i$そして発生時に終了します$p_j$。 価値に最適なセグメント$a$の発生で開始および終了すると想定できます。$a$なぜなら、それらを超えて拡張すると失敗が増えるだけだからです。 

このセグメント内:$$k = j-i+1.$$長さは$$p_j-p_i+1.$$指数は次のようになります。$$2(j-i+1) - (p_j-p_i+1).$$拡張:$$(j-i+1) - (p_j-p_i).$$再配置:$$(p_i-i) - (p_j-j) + 1.$$ここで定義します$$b_t = p_t - t.$$固定用$j$、スコアを最大化するとは、以前の最大値を見つけることを意味します。$b_i$。 

これは、各個別の値の出現リストにおける最大部分配列形式の問題になります。 

もう 1 つの表示方法はさらに簡単です。 2 つの連続した出現の間には、$$p_t-p_{t-1}-1$$非$a$要素。 それらの出現を接続すると、スコアが次のように変化します。$$1-(p_t-p_{t-1}-1) = 2-(p_t-p_{t-1}).$$これにより、各値の出現に対して自然な Kadane のような動的プログラミングが行われます。 

すべての配列位置は 1 つの出現リストにのみ属するため、すべての値にわたる合計作業量は線形です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^2)$に$O(n^3)$|$O(1)$| 遅すぎる |
 | 最適 |$O(n)$テストケースごと |$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 個別の値ごとに、それが表示されるすべての位置を収集します。 

位置を次のようにします。$$p_1,p_2,\ldots,p_m.$$この出現リストに対してカダン式 DP を実行します。 

1. 最初の出現箇所からセグメントを開始します。 
2. しましょう`cur`現在のオカレンスで終了する最良のセグメントのスコアになります。 

1 回の正しい推測と 0 回の失敗で指数 1 が得られるため、1 回の発生はスコア 1 に寄与します。 
3.発生から移行する場合$p_{i-1}$に$p_i$、現在のセグメントの拡張によるゲインは次のとおりです。$$2-(p_i-p_{i-1}).$$用語$2$距離は、それらの間に発生した障害を差し引く一方で、もう 1 回発生することによって得られます。 
4. もし$$cur + (2-(p_i-p_{i-1}))$$スコア 1 から新たに開始するよりも優れており、現在のセグメントを拡張します。 
5. それ以外の場合は、発生時に新しいセグメントを開始します。$p_i$。 
6. アップデート後`cur`、グローバルベストアンサーと比較してください。 それより大きい場合は、次のものを保管します。 

- 値$a$、
 - 開始出現位置、
 - 終了出現位置。 
7. 個別の値ごとに繰り返します。 

### なぜ効果があるのか

 固定値の場合$a$、すべての候補セグメントは、そのセグメント内の最初と最後の出現によって一意に決定されます。 ある出現から次の出現に拡張すると、指数は正確に変化します$2-(p_i-p_{i-1})$。 セグメントの合計指数は、これらの遷移ゲインに最初の出現からの初期寄与 1 を加えた合計になります。 

これにより、問題は出現リスト上で最大和の連続部分列を見つけることに変わります。 Kadane のアルゴリズムはまさにこのタスクに最適です。 すべての値に対して個別に最適なセグメントを解決し、全体的に最良の結果を選択するため、最終的な答えは全体的に最適になります。 

## Python ソリューション```python
import sys
from collections import defaultdict

input = sys.stdin.readline

def solve():
    t = int(input())

    out = []

    for _ in range(t):
        n = int(input())
        arr = list(map(int, input().split()))

        pos = defaultdict(list)

        for i, x in enumerate(arr, start=1):
            pos[x].append(i)

        best_score = -10**18
        best_a = arr[0]
        best_l = 1
        best_r = 1

        for value, positions in pos.items():
            cur_score = 1
            cur_start = positions[0]

            if cur_score > best_score:
                best_score = cur_score
                best_a = value
                best_l = cur_start
                best_r = positions[0]

            for i in range(1, len(positions)):
                gain = 2 - (positions[i] - positions[i - 1])

                if cur_score + gain < 1:
                    cur_score = 1
                    cur_start = positions[i]
                else:
                    cur_score += gain

                if cur_score > best_score:
                    best_score = cur_score
                    best_a = value
                    best_l = cur_start
                    best_r = positions[i]

        out.append(f"{best_a} {best_l} {best_r}")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```最初の部分は、等しい値をグループ化し、その位置をすべて保存します。 値の最適化はその値が出現する場所のみに依存するため、これは重要な前処理ステップです。 

出現リストごとに、`cur_score`現在のオカレンスで終了するセグメントの中で最高のスコアを保存します。 トランジションゲイン`2 - gap`指数の代数変換から直接得られます。 

再起動条件は Kadane のアルゴリズムと同じです。 拡張によって新しい単一出現セグメントのスコアを下回るスコアが生成された場合は、前のセグメントを破棄し、現在の出現から再度開始します。 

保存された境界は、出現リスト内のインデックスではなく、実際の配列の位置です。 この詳細は間違いやすいです。 

スコアは最大でも次のとおりであるため、整数オーバーフローの問題は存在しません。$O(n)$、Python の整数はとにかく無制限です。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io
from collections import defaultdict

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        arr = list(map(int, input().split()))

        pos = defaultdict(list)

        for i, x in enumerate(arr, 1):
            pos[x].append(i)

        best_score = -10**18
        ans = None

        for value, positions in pos.items():
            cur = 1
            start = positions[0]

            if cur > best_score:
                best_score = cur
                ans = (value, start, positions[0])

            for i in range(1, len(positions)):
                gain = 2 - (positions[i] - positions[i - 1])

                if cur + gain < 1:
                    cur = 1
                    start = positions[i]
                else:
                    cur += gain

                if cur > best_score:
                    best_score = cur
                    ans = (value, start, positions[i])

        out.append(f"{ans[0]} {ans[1]} {ans[2]}")

    return "\n".join(out)

# minimum size
assert run("1\n1\n5\n") == "5 1 1"

# all equal
assert run("1\n5\n7 7 7 7 7\n") == "7 1 5"

# isolated repeats, best is single element
assert run("1\n5\n7 1 1 1 7\n") in {
    "7 1 1",
    "7 5 5",
    "1 2 2",
    "1 3 3",
    "1 4 4",
}

# adjacent occurrences should merge
assert run("1\n4\n9 9 9 9\n") == "9 1 4"

# off-by-one boundary
assert run("1\n5\n3 1 3 3 1\n") == "3 1 4"

 ## 特殊なケース

 ### 値は 1 回だけ出現します

 入力:```
1
1
100
```出現リストは`[1]`。 

アルゴリズムは次のように初期化します。 

| ポジション | スコア |
 | --- | --- |
 | 1 | 1 |

 遷移は存在しません。 答えは次のようになります。```
100 1 1
```すべての最適なセグメントに複数のオカレンスが含まれると想定するソリューションは、ここでは失敗します。 

### 大きなギャップで区切られた値の繰り返し

 入力:```
1
5
7 1 1 1 7
```値 7 の場合:

 | 発生 | ポジション | ゲイン | スコア |
 | --- | --- | --- | --- |
 | 1 | 1 | - | 1 |
 | 2 | 5 | -2 | 再起動 |

 延長スコアはマイナスとなるため、カダネは5番からリスタート。 

2 つの発生箇所を接続すると損失が多すぎるため、アルゴリズムは単一位置セグメントを正しく返します。 

### 最適なセグメントは中央から始まります

 入力:```
1
7
5 1 1 5 5 1 5
```5 が出現する位置は次のとおりです。```
1 4 5 7
```最初のギャップは大きく、マイナスの寄与を生み出します。 Kadane の再起動では、初期の発生が破棄され、後でより適切なセグメントが開始されます。 

これがまさに、アルゴリズムが最初に出現した値とは別に現在のセグメントの開始を保存する理由です。 その再起動メカニズムがなければ、答えは次善の策になります。
