 ## 解決策
 ## 問題の理解

 正の整数の配列が与えられ、合計が数字 3 で終わる 3 つの異なる要素を選択できるかどうかを知りたいと考えています。つまり、選択した要素を次のように表すかどうかを知りたいと考えています。$a_i$、$a_j$、 そして$a_k$、 それから$(a_i + a_j + a_k) \mod 10 = 3$。 入力は複数のテスト ケースで構成され、それぞれが配列サイズと要素自体を指定します。出力は、そのようなトリプルが存在する場合は「YES」、存在しない場合は「NO」になります。 

制約により、最大で$2 \cdot 10^5$すべてのテスト ケースにわたる要素の合計。 単純な三重ネストループはチェックします$O(n^3)$テストケースごとに組み合わせが必要ですが、これは明らかに実行不可能です。$n^3$到達できた$10^{15}$最悪の場合の運用。 平$O(n^2)$このアプローチは、最大の配列に対して遅すぎる可能性があります。 したがって、可能なすべてのトリプルを直接反復することを避ける戦略が必要です。 

合計は最後の桁のみに関係するため、微妙な点が 1 つ発生します。 たとえば、配列では$[11, 12, 13]$、10 を法とするすべての 3 要素トリプルの合計は、桁によってのみ決定されます。$[1, 2, 3]$。 これは、各要素の完全な値ではなく、各要素の最後の桁を処理するように問題を縮小できることを示しており、これにより、個別の可能性の数が大幅に減少します。 考慮すべきもう 1 つのエッジケースは、同一の番号が複数ある場合です。 たとえば、配列$[10, 10, 10]$合計は 30 で、3 ではなく 0 で終わります。不注意な実装では、繰り返しの数値を使用すると常に効果があると誤って想定する可能性がありますが、インデックスは個別である必要があります。 

## アプローチ

 ブルート フォースの解決策は簡単です。3 つの異なるインデックスのすべての組み合わせを反復処理し、その合計が 3 で終わるかどうかを確認します。このアプローチは、すべての可能性を明示的にテストするため、正しいことが保証されていますが、大規模な配列の場合は失敗します。$O(n^3)$複雑。 たとえば、$n = 2000$、これには大まかに必要になります$1.3 \cdot 10^9$通常の制限時間を超えるチェック。 

重要な洞察は、各数値の最後の桁のみが結果に影響を与えるということです。 数字の範囲は 0 から 9 であるため、配列を最後の数字ごとに最大 3 回出現するリストに減らすことができます。 有効なトリプルは最大 3 つのコピーを使用して形成できるため、最後の桁が同じ番号を 3 つ以上使用する必要はありません。 これにより、候補の数が最大 30 個の要素に減ります。 この縮小されたサイズでは、三重にネストされたループを安全に適用できます。$30^3 = 27,000$テストケースごとの操作は許容されます。 

解決策のストーリーは次のとおりです。ブルート フォースは機能しますが、配列サイズが大きいため速度が遅くなります。 問題が最後の桁のみを考慮していることを観察すると、有効なトリプルを失うことなく、冗長な数値を安全に破棄し、配列を管理可能なサイズに縮小することができます。 これにより、シンプルさと正確さを効率的に組み合わせることができます。

 ## アルゴリズムのチュートリアル

 1. テスト ケースごとに、数値の配列を読み取ります。 
2. モジュロ 10 を使用して各数値を最後の桁に変換します。 
3. 最後の 1 桁につき最大 3 つの数字を含むリストを作成します。 同じ桁の数値を 3 つ以上使用すると、10 を法とする新しい合計を作成できないため、この手順により、最後の桁の合計が 3 になるトリプルを失わないようにすることができます。 
4. 縮小されたリストからすべてのトリプルを列挙します。 各トリプルについて、その要素の合計を 10 を法にして計算します。 
5. 三重の合計が 3 で終わる数字になる場合は、そのテスト ケースに対して直ちに「YES」を出力し、次のテスト ケースに進みます。 
6. すべての可能性をチェックした後、有効なトリプルが見つからない場合は、「NO」を出力します。 

機能する理由: 合計が最後の 1 桁の 3 になる可能性がある 3 つの数値のすべての組み合わせには、各最後の 1 桁のインスタンスが最大 3 つ含まれることが保証されます。 1 桁あたり 3 つの要素だけを保持することにより、候補となるトリプルは削除されません。 モジュロ演算により、各数値の関連部分のみに焦点を当てることが保証され、縮小されたセット内のすべてのトリプルを反復処理することで正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        digits = [[] for _ in range(10)]
        for num in a:
            d = num % 10
            if len(digits[d]) < 3:
                digits[d].append(d)
        
        candidates = []
        for lst in digits:
            candidates.extend(lst)
        
        found = False
        m = len(candidates)
        for i in range(m):
            for j in range(i+1, m):
                for k in range(j+1, m):
                    if (candidates[i] + candidates[j] + candidates[k]) % 10 == 3:
                        found = True
                        break
                if found:
                    break
            if found:
                break
        
        print("YES" if found else "NO")

solve()
```このソリューションでは、最初に数値を最後の桁ごとにグループ化し、各グループを 3 つの要素に切り捨てます。 これにより、候補セットを小さく保ちながら、可能な最後の桁のトリプルがすべて保存されることが保証されます。 次に、三重にネストされたループは、10 を法とする合計を明示的にチェックし、インデックスに関する off-by-one エラーを回避します。 適切なタイミングでモジュロを使用すると、大きな数値に対する整数のオーバーフローの問題を防ぐことができます。
