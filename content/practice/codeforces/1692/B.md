 ## 解決策
 ## 問題の理解

 整数の配列が与えられます。 1 回の操作で、配列からちょうど 2 つの要素を削除する必要があります。 削除された 2 つの要素は、異なる位置からのものであれば、どのような値でも構いません。 

私たちの目標は、残りの配列に個別の値のみが含まれるように、そのような操作を 0 個以上実行することです。 それを達成するあらゆる方法の中で、残りの配列をできるだけ長くしたいと考えています。 

テスト ケースごとに、要素がすべて異なる最終配列の可能な最大長を出力する必要があります。 

制約は非常に小さいです。 各配列には最大 50 個の要素が含まれ、最大 1000 個のテスト ケースがあります。 比較的非効率なアプローチであっても、制限内に問題なく収まります。 課題はパフォーマンスではなく、問題の構造を認識することです。 

重要な点は、重複が唯一の障害であるということです。 配列に次のものが含まれる場合$k$個別の値の場合、有効な最終配列には各値のコピーを 1 つだけ含めることができるため、その長さが超えることはできません。$k$。 

微妙な部分は操作そのものです。 単一の要素を削除することはできません。 削除するたびに、正確に 2 つの要素が削除されます。 つまり、削除される要素の数は常に偶数でなければなりません。 

次の配列を考えてみましょう。```
1 1 2
```がある$k=2$明確な価値観。 各値のコピーを 1 つ保持すると、長さが残ります。$2$、理想的だと思われます。 ただし、長さに達すると、$2$要素を 1 つだけ削除する必要がありますが、削除はペアで行われるため不可能です。 長さを残したまま 2 つの要素を削除する必要があります$1$。 

したがって、正しい答えは次のようになります。```
1
```見落としやすいもう 1 つのケースは次のとおりです。```
1 1 2 2
```がある$k=2$明確な価値観と$n-k=2$重複した要素。 重複の数はすでに偶数であるため、それらの重複を正確に削除して保持できます。```
1 2
```答えは次のとおりです。```
2
```個別の値のみをカウントする不用意なソリューションは、重複の数が奇数の場合には失敗します。 

## アプローチ

 ブルートフォースアプローチでは、考えられるすべてのペア削除シーケンスを試し、どの最終配列に個別の値が含まれているかを確認します。 小さな配列の場合でも、可能な削除シーケンスの数は爆発的に増加します。 すべての操作で 2 つのインデックスが選択され、次の操作は異なる配列状態で動作します。 これはすぐに実行不可能になります。 

より良い解決策を見つけるには、最終的な配列がどのようなものでなければならないかを考える必要があります。 

配列に次のものが含まれているとします。$k$明確な価値観。 有効な最終配列には、各値を最大 1 回のみ含めることができるため、可能な限り長い個別の配列には長さが理想的です。$k$。 

このような配列を取得するには、以下を正確に削除します。$$n-k$$要素。 

これらは正確に、各値の最初の出現を超えた追加のコピーです。 

もし$n-k$が偶数であれば、それらの重複を正確に削除できます。 残りの配列には長さがあります$k$、すべての要素は個別です。 

もし$n-k$が奇数の場合、すべての操作で 2 つの要素が削除されるため、重複のみを削除することは不可能です。 何らかのペアの一部として追加の要素を 1 つ削除する必要があります。 これにより、最終的な長さがさらに 1 つ減り、長さが得られます。$k-1$。 

問題全体は、個別の値を数えることと、重複数のパリティをチェックすることに帰着します。

 ## アルゴリズムのチュートリアル

 1. 配列を読み取ります。 
2. で示される個別の値の数を計算します。`k`。 
3. 重複する要素の数を計算します。$$d = n - k$$すべての値のコピーを 1 つ保持したい場合は、これらの要素を削除する必要があります。 
4. かどうかを確認します。`d`は均等です。 

もし`d`が偶数であれば、ペアの削除を使用してそれらの重複を正確に削除できるため、答えは次のようになります。`k`。 
5. もし`d`が奇数の場合、削除される要素の合計数は偶数でなければならないため、余分な要素が 1 つ削除されなければなりません。 

その場合の答えは、`k - 1`。 
6. 結果を出力します。 

### なぜ効果があるのか

 すべての有効な最終配列には、それぞれの個別の値のコピーを 1 つまで含めることができるため、その長さは個別の値の数を超えることはできません。$k$。 

重複したコピーをすべて削除するには、正確に削除する必要があります$n-k$要素。 この数が偶数の場合、動作要件と一致し、すべてを維持できます。$k$明確な価値観。 

いつ$n-k$が奇数である場合、重複のみを削除するには奇数の要素を削除する必要がありますが、すべての操作で 2 つの要素が削除されるため、これは実現できません。 少なくとも 1 つの追加要素を削除して、達成可能な最大長を 1 つ減らす必要があります。 したがって、可能な限り最適な長さは次のようになります。$k-1$。 

可能性はこれら 2 つだけであるため、アルゴリズムは最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())

for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))

    distinct = len(set(a))
    duplicates = n - distinct

    if duplicates % 2 == 0:
        print(distinct)
    else:
        print(distinct - 1)
```実装は数学的観察に直接従います。 

セットには各値のコピーが 1 つ保存されるため、`len(set(a))`個別の要素の数を示します。 違い`n - distinct`一意の値のみを残すために削除する必要がある重複要素の数と等しくなります。 

この数量のパリティによって、重複を削除した後に停止できるかどうか、または 1 つの余分な要素も削除する必要があるかどうかが決まります。 

難しい境界条件はありません。 すべての値が異なる場合、`duplicates = 0`は偶数であるため、答えは残ります。`n`。 すべての値が等しい場合、`distinct = 1`、そして数式は依然として正しい結果を生成します。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    t = int(input())
    ans = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        distinct = len(set(a))
        duplicates = n - distinct

        if duplicates % 2 == 0:
            ans.append(str(distinct))
        else:
            ans.append(str(distinct - 1))

    sys.stdout.write("\n".join(ans))

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out

    solve()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out.getvalue()
