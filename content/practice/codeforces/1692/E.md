 ## 解決策
 ## 問題の理解

 長さのバイナリ配列が与えられます$n$、各要素が 0 または 1 であることを意味します。タスクは、各操作で配列の最初または最後の要素を削除する一連の操作を実行することです。 これらの削除をいくつか行った後、残りの要素の合計が目標値に等しくなる必要があります。$s$。 この合計に達するために必要な操作の最小数を見つけるか、それが不可能な場合は -1 を報告する必要があります。 

入力は複数のテスト ケースを提供し、それぞれに配列サイズが指定されます。$n$、目標金額$s$、および配列自体。 すべての合計$n$すべてのテスト ケースの数は 200,000 を超えないため、ソリューションは各テスト ケースを効率的に、理想的には配列のサイズに対して線形時間で処理する必要があります。 可能なすべてのプレフィックスとサフィックスを明示的に試すなどの 2 次ソリューションは、最大の配列を必要とする可能性があるため、非常に遅くなります。$n^2$テストケースごとの操作。 

エッジケースは、目標合計がすでに達成されている場合に発生します。$s$ゼロまたは配列の合計に等しいか、すべての要素が同一である場合。 たとえば、配列が次の場合、$[1, 1, 1]$そして$s = 0$、最初から要素を削除するだけの単純なアプローチでは、最後から要素を削除することを検討できない可能性があります。 もう 1 つの微妙なケースは、次のように配列の両端に 0 がある場合です。$[0, 1, 1, 0]$と$s = 2$; ゼロを削除しても合計には影響しないことを認識し、演算を最小限に抑える必要があります。 

## アプローチ

 ブルートフォース手法では、削除のすべての組み合わせを反復します。$i$正面からの要素と、$j$背面からの要素。 組み合わせごとに、残りの配列の合計を計算します。 これは、考えられるすべてのサブ配列を正しく探索するため、小さな配列に対して機能しますが、次のことが必要です。$O(n^2)$最悪の場合のテストケースごとの操作。 と$n$最大 200,000 の場合、このアプローチでは最悪の場合 400 億の操作が必要になりますが、これは完全に不可能です。 

重要な洞察は、問題を書き直すことで得られます。何を削除するかを考える代わりに、何を保持するかを考えます。 配列の合計が$total\_sum$、要素を削除して合計に達します$s$は、合計が次のような連続した部分配列を保持することと同じです。$s$。 両端から要素を削除できるため、保持する部分配列は連続的である必要があります。 これにより、問題は、合計が次の値に等しい最長の連続する部分配列を見つけることになります。$s$。 この部分配列の長さがわかったら、最小の演算数は単純に要素の総数から部分配列の長さを引いたものになります。 

これは当然、2 ポインタまたはスライディング ウィンドウのソリューションにつながります。 スライディング ウィンドウは配列に 0 と 1 のみが含まれるため効率的に機能し、ウィンドウの合計を一定時間内に増分更新できます。

 | ブルートフォース | O(n²) | お(1) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列の合計を計算します。 もし$s$合計より大きい場合は、到達できないためすぐに -1 を返します$s$。 もし$s$合計と等しい場合は、演算が必要ないため 0 を返します。 
2. 2 つのポインターを初期化します。`left = 0`ウィンドウの開始と`current_sum = 0`ウィンドウ内の要素の合計。 合計が以下に等しい最長の部分配列を見つけようとします。$s$。 
3. インデックスを使用して配列を反復処理します。`right`。 追加`array[right]`に`current_sum`。 もし`current_sum`を超える$s$、移動します`left`ポインタの前進と減算`array[left]`から`current_sum`それまで`current_sum <= s`。 
4.いつでも`current_sum`等しい$s$、変数を更新します`max_length`このような部分配列の最大長を追跡します。 
5. ループ後、if`max_length`-1 のままですが、有効な部分配列が見つからなかったため -1 を返します。 それ以外の場合は戻ります`n - max_length`、これは、配列を目的の合計に減らすために必要な演算の最小数を表します。 

なぜ機能するのか: スライディング ウィンドウの不変条件により、次のことが保証されます。`current_sum`は常に、次で終わる連続した部分配列の合計を表します。`right`。 調整することで`left`、必要な場合にのみウィンドウを縮小し、すべての候補部分配列が和を持つことを保証します。`s`と考えられます。 最大長を追跡することで、削除の回数を最小限に抑えることができます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def min_operations_to_sum(n, s, arr):
    total = sum(arr)
    if s > total:
        return -1
    if s == total:
        return 0
    
    max_len = -1
    left = 0
    current_sum = 0
    
    for right in range(n):
        current_sum += arr[right]
        while current_sum > s and left <= right:
            current_sum -= arr[left]
            left += 1
        if current_sum == s:
            max_len = max(max_len, right - left + 1)
    
    return n - max_len if max_len != -1 else -1

t = int(input())
for _ in range(t):
    n, s = map(int, input().split())
    arr = list(map(int, input().split()))
    print(min_operations_to_sum(n, s, arr))
```このソリューションでは、まず不可能なケースを迅速に処理し、次にスライディング ウィンドウを使用して、目標の合計を持つ最長の部分配列を見つけます。 の`while`内部のループ`for`合計が次の値を超えたときにウィンドウが正しく縮小されるようにします。$s$。 の`max_len`変数は最長の有効な部分配列を追跡します。 戻る`n - max_len`保持された部分配列を最小数の削除に変換します。
