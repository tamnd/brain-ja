 ## 解決策
 ## 問題の理解

 小さな文字列書き換えプログラムを構築する必要があります。 プログラムは順序付けられたコマンドで構成されます。 各コマンドは部分文字列を検索し、最初に出現した部分文字列を別の文字列に置き換えます。 一部のコマンドは置換後も実行を継続しますが、他のコマンドはすぐに終了します。 

一般に、タスクはすべての整数をインクリメントすることではありません。 必要なのは、指定された一連の数値に対して機能するプログラムだけです。 すべての入力数値は最大 1024 であるため、全体で最大 1025 個の値が可能です。 50 コマンドの制限は、入力サイズ自体よりもはるかに制限的です。 

重要な詳細は、コマンドがどのように選択されるかです。 各反復中に、アルゴリズムはコマンドを上から下にスキャンし、左側が現在の文字列のどこかに現れる最初のコマンドを実行します。 これは、コマンドの順序が動作を完全に決定することを意味します。 コマンドが誤って別の番号と一致すると、意図したコマンドが実行されなくなる可能性があります。 

コマンドの文字列には数字と文字が含まれる場合があります。`?`。 このステートメントでは、ワイルドカード セマンティクスが指定されることはありません。`?`, したがって、通常のキャラクターとして動作します。 すべての入力数値には数字のみが含まれるため、次の内容を含むコマンドはすべて`?`左側では決して一致しません。 最も単純な解決策は無視します`?`全体的に。 

制約はわずかです。 それぞれ 1025 未満の番号は最大 100 個しかなく、許可されるコマンドは 50 個だけです。 すべての数値間の二次検査さえも簡単です。 この課題は純粋に建設的なものであり、相互作用が互いに干渉しないコマンドを設計することです。 

単純なアプローチでは、番号ごとに 1 つのコマンドが作成されます。```
x<>x+1
```サンプルについて`{10, 79}`、これは機能します:```
10<>11
79<>80
```しかし、ある数値が別の数値の部分文字列になると、これは失敗します。 セットが次のようになっているとします。```
1
10
```配置すると:```
1<>2
10<>11
```それから入力してください`10`最初のコマンドを実行します。`1`中に現れる`10`。 結果は次のようになります`20`、それは間違いです。 

順序を逆にしても失敗します。```
10<>11
1<>2
```今すぐ入力してください`10`になる`11`ですが、アルゴリズムは続行され、2 番目のコマンドが再び一致し、結果が生成されます。`22`。 

明らかではない危険は、交換によって新しい一致が作成される可能性があることです。 意図した変換後は、それ以降のコマンドがトリガーされないことを保証する必要があります。 

もう 1 つの微妙なケースは、部分文字列のチェーンです。```
1
10
100
```不注意な注文は簡単に書き換えられる可能性があります`100`いくつかの意図しない中間状態を経ます。 

この問題は、パターン間の衝突を回避するための慎重な演習になります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 入力番号ごとに`x`、終了コマンドを追加します。```
x<>x+1
```どの数値も別の数値の部分文字列でない場合、これは直ちに正しいことになります。 最初に一致したコマンドは入力を一意に識別し、置換後に終了します。 

この問題は、ある数値が別の数値の中に出現する場合に発生します。 コマンドは文字列全体ではなく部分文字列に対してグローバルにチェックされるため、短いパターンは大きな数値をハイジャックする可能性があります。 

考えられる総当たり修復の 1 つは、一時的なマーカー文字と複数の書き換えステージを導入することです。 たとえば、最初に特定の数字を特殊記号でマークし、後でそのマーカーを最終的な答えに変換することができます。 コマンド文字列には次のものが含まれる場合があるため、`?`、この文字は、元の入力には決して表示されないプライベート マーカーとして機能します。 

この方向は機能しますが、厄介になります。 一時的な状態、コマンドの順序、クリーンアップ間の相互作用を注意深く管理する必要があります。 コマンドの数も急速に増加する可能性があります。 

重要な観察は、ドメインが非常に小さいということです。 すべての入力数値は 1025 未満であるため、その 10 進数の長さは最大 4 桁です。 さらに重要なことは、元の文字列は 1025 個しかないということです。 

部分文字列の衝突と直接戦う代わりに、古典的なトライスタイルのアイデアを使用できます。 短い文字列よりも長い文字列を処理すると、短い数値が長い数値の部分文字列になるたびに、長い数値が優先されます。 

長い数値を置き換えた後の結果には別のパターンが含まれる可能性があるため、これでもすべてが解決されたわけではありません。 主な改善点は、次のようにしてすべてのコマンドを終了させることです。`<>`。 意図した置換が行われると、実行は直ちに停止します。 それ以降のコマンドは干渉できません。 

ここで、正しさの条件は 1 つに減ります。 

入力番号ごとに`a`、左側が内側に表示されるすべてのコマンドのうち`a`、の正しいコマンド`a`最初に来なければなりません。 

これを保証するのは簡単です。 文字列の長さを短くして数値を並べ替えます。 2 つの数値が同じ長さの場合、それらが同一でない限り、どちらももう一方の部分文字列になることはできません。 入力はセットを表すため、重複は問題になりません。 

長さの降順で並べ替えた後、各数値自体のコマンドが、その中に一致する可能性のあるすべての短い部分文字列のコマンドの前に表示されます。 

ブルートフォース構造は、正しい順序と組み合わせると再び有効になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 単純な順序付けされていないコマンド | O(n²) 検証 | O(n) | 不正解 |
 | 長さ順の終了コマンド | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての数値を文字列として読み取ります。 
2. 必要に応じて重複を削除します。 同じコマンドを複数使用する必要はありません。 
3. 文字列を長さの降順に並べ替えます。 
4. 文字列ごとに`s`、終了コマンドを作成します。```
s<>str(int(s)+1)
```1. コマンドをこの順序で出力します。 

仕分けのステップがすべての鍵です。 数字を考えてみましょう`a`別の数字が含まれている`b`部分文字列として。 それから`|b| < |a|`なぜなら、同じ長さの異なる文字列は、互いの部分文字列になることができないからです。 長い文字列を最初に処理するため、次のコマンドは`a`コマンドの前に表示されます`b`。 

入力時`a`が処理されると、それ自体のコマンドが最も早く一致したコマンドになります。 交換用途は`<>`, そのため、実行はすぐに停止します。 これより小さい部分文字列コマンドは実行される機会がありません。 

### なぜ効果があるのか

 任意の入力文字列を考慮します`x`。 

それ自体のコマンドは明らかに一致します。`x`それ自体が部分文字列として含まれます。 

ここで、一致する可能性のある以前のコマンドを検討してください。`x`。 コマンドは長さの降順に並べられるため、それ以前のコマンドは、少なくとも次の長さの文字列に対応します。`|x|`。 

明確に長い文字列を部分文字列にすることはできません。`x`。 異なる同じ長さの文字列を部分文字列にすることはできません。`x`。 の唯一の等しい長さの部分文字列`x`は`x`自体。 

したがって、最初に一致するコマンドは、正確に次のコマンドである必要があります。`x`。 

そのコマンドは次のように置き換えます`x`と`x+1`を使用しているため、すぐに終了します`<>`。 

したがって、すべての入力数値は後続数値に変換され、意図しないコマンドは実行できません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    
    nums = []
    seen = set()
    
    for _ in range(n):
        s = input().strip()
        if s not in seen:
            seen.add(s)
            nums.append(s)
    
    nums.sort(key=lambda x: (-len(x), x))
    
    ans = []
    
    for s in nums:
        t = str(int(s) + 1)
        ans.append(f"{s}<>{t}")
    
    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```順序付け引数を理解すれば、構築自体は単純なので、実装は短くなります。 

部分文字列の動作は数値ではなくテキスト表現に依存するため、数値を文字列として保存します。 これらを整数に変換するのが早すぎると、先行ゼロ構造が失われますが、この問題により標準 10 進表記での正の整数が保証されます。 

入力がセットであることが保証されている場合、重複の削除は技術的にはオプションですが、それを保持すると構築がよりクリーンになり、コマンドの繰り返しが回避されます。 

並べ替えキーは重要な行です。```
nums.sort(key=lambda x: (-len(x), x))
```長さの短い順に並べ替えます。 二次辞書編集順序は正確さとは無関係ですが、決定的な出力を与えます。 

すべてのコマンドは使用します`<>`、 ない`>>`。 この微妙な選択により、正しい変換がすでに行われた後のカスケード再書き込みが防止されます。 

置換文字列は単純に`int(s) + 1`、10 進数形式に変換し直します。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    n = int(input())

    nums = []
    seen = set()

    for _ in range(n):
        s = input().strip()
        if s not in seen:
            seen.add(s)
            nums.append(s)

    nums.sort(key=lambda x: (-len(x), x))

    ans = []

    for s in nums:
        ans.append(f"{s}<>{int(s)+1}")

    print("\n".join(ans))

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out.strip()

# provided sample
assert run("2\n10\n79\n") == "10<>11\n79<>80", "sample 1"

# minimum size
assert run("1\n1\n") == "1<>2", "single number"

# substring chain
assert run("3\n1\n10\n100\n") == "100<>101\n10<>11\n1<>2", "substring ordering"

# boundary value
assert run("1\n1024\n") == "1024<>1025", "largest allowed value"

# equal lengths without substring relation
assert run("3\n12\n34\n56\n") == "12<>13\n34<>35\n56<>57", "same length numbers"

# duplicate handling
assert run("3\n7\n7\n7\n") == "7<>8", "duplicate inputs"

 |`1\n1024\n`|`1024<>1025`| 最大許容値 |

 ## 特殊なケース

 次の入力を考えてみましょう。```
2
1
10
```生成されるコマンドは次のとおりです。```
10<>11
1<>2
```実行日`10`は次のように進みます。 

アルゴリズムはコマンドを上から下までチェックします。`10<>11`すぐに一致するので、`10`になる`11`そして実行は終了します。 危険な短いパターン`1`決して実行されません。 

ここで次のことを考えてみましょう。```
3
1
10
100
```コマンドは次のとおりです。```
100<>101
10<>11

```入力`100`両方が含まれています`10`そして`1`部分文字列として使用されますが、独自のコマンドが最も長いため最初に表示されます。 置換はすぐに終了するため、短いコマンドはトリガーされません。

12

```どちらの文字列も長さが同じで別個であるため、もう一方の文字列の部分文字列になることはできません。 どのような順序でも機能します。 生成されるコマンドは次のとおりです。```

1

```生成されたコマンドは次のとおりです。```
1024<>1025
```この問題により、1024 を超える出力が許可されます。元の入力のみが制限されます。 この構造では、通常の整数加算によってこれを自然に処理します。
