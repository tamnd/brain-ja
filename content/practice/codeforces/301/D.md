 ## 解決策
 ## 問題の理解

 からの数値の順列が与えられます。`1`に`n`。 クエリ間隔ごとに`[l, r]`、順序付けされた位置のペアが何組あるかを数えなければなりません`(q, w)`その間隔内で次の条件が満たされます。$$p[q] \mid p[w]$$すべての値は個別であり、順列を形成するため、すべての数値は 1 回だけ表示されます。 このタスクは、インデックス間の割り切りについては尋ねるのではなく、それらのインデックスに格納されている値の間の割り切りのみを求めます。 

たとえば、部分配列に値が含まれている場合、`[2, 6, 3]`の場合、有効な順序ペアは次のとおりです。 

-`(2, 2)`すべての数字はそれ自体を割るからです
 -`(2, 6)`-`(3, 3)`-`(6, 6)`答えは次のようになります。`4`。 

ここでの本当の課題は制約です。 両方`n`そして`m`到達できる`2 * 10^5`。 すべてのクエリ間隔内のすべてのペアを検査する単純なアプローチでは、最大で次の作業が必要になります。$$O(m \cdot n^2)$$最悪の場合の操作は2秒の制限ではまったく不可能です。 

すべてのペアをグローバルに一度反復するだけでも、すでに存在します。$$(2 \cdot 10^5)^2 = 4 \cdot 10^{10}$$これは実用的な限界をはるかに超えています。 

順列の構造は非常に重要です。 なぜなら、からのすべての値は、`1`に`n`が 1 回だけ出現すると、すべての数値の位置を前処理し、インデックスの代わりに値を使用して割り切れる可能性を推論できます。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

考慮する：```
n = 1
p = [1]
query = [1,1]
```正しい答えは、`1`、 なぜなら`1`それ自体を分割します。 個別の数値のペアのみをカウントする不注意な実装では、誤った値が返されます。`0`。 

もう 1 つの微妙なケースは、配列内の倍数の後に除数が現れる場合です。```
p = [6,2]
query = [1,2]
```有効なペアは次のとおりです。 

-`(6,6)`-`(2,2)`-`(2,6)`答えは`3`。 

ペア`(2,6)`たとえ有効であっても`2`配列の後半に表示されます。 条件は値に関するものであり、インデックスの順序ではありません。 誤ってカウントのみを行う多くの誤った解決策`i <= j`。 

もう 1 つの危険な状況は、対称ペアを二重にカウントすることです。```
p = [2,4]
```のみ`(2,4)`は有効ですが、そうではありません`(4,2)`。 可分性には方向性があります。 これを順序のない関係として扱うと、間違った答えが生成されます。 

## アプローチ

 ブルートフォースアプローチは簡単です。 あらゆるクエリに対して`[l, r]`、区間内の位置のすべてのペアを反復処理し、一方の値が他方の値を割るかどうかを確認します。 

擬似コードのアイデアは次のようになります。```
for q in [l, r]:
    for w in [l, r]:
        if p[w] % p[q] == 0:
            answer += 1
```これは問題の定義に直接従うため、正しいです。 残念ながら、その複雑さはひどいものです。 

単一のクエリには次のものが含まれる場合があります`O(n^2)`ペア。 と`m = 2 * 10^5`、合計作業量はおおよそ次のようになります。$$O(mn^2)$$到達できるのは`8 * 10^{15}`操作。 

次の観察が重要な転換点となります。 

実際には、任意の値のペアは気にしません。 一方の数値がもう一方の数値を割るペアのみを考慮します。 

固定値の場合`x`、唯一の候補はその倍数です。$$x, 2x, 3x, \dots$$以下の数値間の約数と倍数の関係の総数。`1`に`n`は：$$\sum_{x=1}^{n} \frac{n}{x}$$これはおよそ次のとおりです。$$n \log n$$これでも十分小さいです。 

配列は順列であるため、すべての値の正確な位置がわかります。 有効な約数関係ごとに`(x, y)`どこ`x | y`、ポジションのペアを作成できます。$$(pos[x], pos[y])$$クエリは、完全に内部に存在するそのようなペアがいくつあるかを尋ねます。`[l, r]`。 

これにより、問題は幾何学的計数問題に変換されます。 

次を満たす有効な位置ペアがいくつあるかを数えます。$$l \le a \le r$$

$$l \le b \le r$$便宜上、常にペアを次のように保存します。$$(\min(a,b), \max(a,b))$$その場合、クエリは次のようになります。 

次のペアをカウントします。$$a \ge l$$

$$b \le r$$これは、オフラインのフェンウィック ツリーの古典的な問題です。 

クエリを増やすことで処理します`r`。 左から右にスイープすると、より大きい端点が現在の位置に等しいすべてのペアがアクティブになります。 アクティブ化されたペアごとに`(a,b)`、追加します`1`位置にある`a`フェンウィックツリーの中。 

それからクエリのために`[l,r]`、フェンウィック ツリーには、より大きなエンドポイントが最大で以下のペアが正確に含まれます。`r`。 サフィックスの合計をクエリする`l`に`n`それらのうちの何個が同様に満足するかを数えます`a >= l`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(mn²) | お(1) | 遅すぎる |
 | 最適 | O(n log n + m log n) | O(n log n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 順列を読み取り、計算します。`pos[x]`、値が入る位置`x`が表示されます。 
2. すべての約数の関係を列挙します。 

あらゆる価値観に対して`x`から`1`に`n`、すべての倍数を反復処理します。`x`:```
y = x, 2x, 3x, ...
```以来`x`分割する`y`、ペアは有効です。 
3. 値のペアを位置のペアに変換します。 

させて：```
a = pos[x]
b = pos[y]
```ペアを次のように保存します。```
(min(a,b), max(a,b))
```この正規化により、すべてのペアを一貫して扱うことができます。 
4. より大きなエンドポイントごとにペアをグループ化します。 

ペアが次のようになったとします。`(a,b)`と`a <= b`。 

店`a`に関連付けられたバケット内`b`。 

その後、位置を処理するときに`b`、このペアをアクティブ化します。 
5. クエリを適切なエンドポイントで並べ替える`r`。 

位置を左から右に処理します。 位置に着いたら`r`、最大でもより大きなエンドポイントを持つすべてのペア`r`すでにアクティブになっているはずです。 
6. ポジション上でフェンウィック ツリーを維持します。 

位置処理時`b`を追加して、保存されているすべてのペアをアクティブにします。`1`より小さなエンドポイントで`a`。 
7. 質問に答えます。 

問い合わせ用`[l,r]`、すべてのアクティブなペアはすでに次の条件を満たしています。```
larger endpoint <= r
```まだ必要なものは次のとおりです。```
smaller endpoint >= l
```これはまさに接尾辞の合計です。```
sum(n) - sum(l-1)
```8. 元のクエリの順序で回答を出力します。 

### なぜ効果があるのか

 値間のすべての有効な約数関係により、正規化された位置ペアが 1 つだけ生成されます。`(a,b)`と`a <= b`。 

クエリ間隔`[l,r]`区間内に完全に含まれるペアを正確にカウントする必要があります。 この条件は次と同等です。$$a \ge l \quad \text{and} \quad b \le r$$スイープ中に一度位置決め`r`が処理されると、フェンウィック ツリーには次のすべてのペアが含まれます。`b <= r`。 このような各ペアは貢献します`1`インデックスで`a`。 

サフィックスのクエリ`[l,n]`小さい端点が少なくとも次の値であるペアを正確にカウントします。`l`。 両方の条件を組み合わせると、完全に間隔内にあるペアが正確に得られます。 

どのペアも見逃されず、どのペアも 2 回カウントされません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, idx, val):
        while idx <= self.n:
            self.bit[idx] += val
            idx += idx & -idx

    def sum(self, idx):
        res = 0
        while idx > 0:
            res += self.bit[idx]
            idx -= idx & -idx
        return res

    def range_sum(self, l, r):
        return self.sum(r) - self.sum(l - 1)

def solve():
    n, m = map(int, input().split())
    p = [0] + list(map(int, input().split()))

    pos = [0] * (n + 1)
    for i in range(1, n + 1):
        pos[p[i]] = i

    events = [[] for _ in range(n + 1)]

    for x in range(1, n + 1):
        y = x
        while y <= n:
            a = pos[x]
            b = pos[y]

            if a > b:
                a, b = b, a

            events[b].append(a)
            y += x

    queries = [[] for _ in range(n + 1)]

    for idx in range(m):
        l, r = map(int, input().split())
        queries[r].append((l, idx))

    bit = Fenwick(n)
    ans = [0] * m

    for r in range(1, n + 1):
        for a in events[r]:
            bit.add(a, 1)

        for l, idx in queries[r]:
            ans[idx] = bit.range_sum(l, n)

    print("\n".join(map(str, ans)))

solve()
```最初の重要な前処理ステップはビルドです。`pos`。 配列は順列であるため、すべての値の位置に一定時間アクセスできます。 

ネストされた複数のループが最適化の中心です。 すべての値のペアをチェックするのではなく、割り切れることが保証されているペアのみを検査します。 反復の合計数は調和級数の増加のように動作します。$$n \left(1 + \frac12 + \frac13 + \dots \right)$$これはおよそ`n log n`。 

正規化:```
if a > b:
    a, b = b, a
```が不可欠です。 クエリでは、両方のエンドポイントが間隔内にあるかどうかのみが考慮されます。 値が表示される順序は気にしません。 

フェンウィック ツリーには、小さいエンドポイントによってインデックス付けされたカウントが保存されます。 右端点を処理する場合`r`、すべてのアクティブなペアはすでに満たされています`b <= r`。 サフィックスクエリの終了`[l,n]`を含むものを正確にフィルタリングします`a >= l`。 

実装の微妙な詳細の 1 つは、次のペアです。`x == y`も含める必要があります。 すべての数値はそれ自身を割り算するため、対角線のペアは有効であり、必要です。 

もう 1 つの簡単な間違いは、クエリに答えるときに接尾辞の合計ではなく接頭辞の合計を使用することです。 必要なものは次のとおりです。```
a >= l
```ない：```
a <= l
```したがって、クエリは次のようにする必要があります。```
bit.range_sum(l, n)
```## 実用的な例

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n + m log n) | 倍数の列挙には調和系列時間がかかり、フェンウィック演算には対数時間がかかります。
