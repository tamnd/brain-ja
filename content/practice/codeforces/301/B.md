 ## 解決策
 ## 問題の理解

 2D グリッド上に配置された一連のステーションが与えられます。 2 つの駅間の移動には、マンハッタンまでの距離に定数を乗じた時間に比例します。$d$。 各駅$i$(最初と最後を除く) 利用可能な時間を 1 回だけ増やすボーナスを提供します。$a_i$。 ステーション 1 から小さなプラスの時間で開始し、単位時間あたり 1 の固定コストでステーション 1 のみで追加の時間を購入することもできます。 

タスクは、ステーション 1 から開始して最終的にステーションに到達できるように、ステーション 1 で費やさなければならない最小金額を決定することです。$n$タイマーがゼロになることはありません。 

これは基本的にはツイストを加えた最短経路問題です。エッジのコストはパラメーター (制限時間) に依存し、ボーナスを集めたり、追加の初期時間を購入したりすることでそのパラメーターを増やすことができます。 

制約$n \le 100$すぐに示唆する$O(n^3)$あるいは$O(n^2 \log n)$アプローチは受け入れられます。 すべてのペアにわたる完全なグラフは、$10^4$エッジなので、最短パスの計算が可能です。 実現不可能なのは、訪問するステーションの可能なサブセットをすべて列挙しようとすることです。これは、指数関数的に爆発的に増加するためです。 

微妙な点は、時間はエッジに沿って消費されるリソースであるだけでなく、ノードでも増加し、お金によって部分的に制御できることです。 このため、「利用可能な時間予算」を状態チェックまたは実現可能性チェックに慎重に統合しない限り、単純な最短経路の定式化は不正確になります。 

エッジケースは次の場合に発生します。 

1 から n への直接パスは幾何学的に存在しますが、純粋な距離の意味でそれらの駅が訪問するのに最適ではない場合でも、中間駅なしでは実現できません。 もう 1 つの問題は、ボーナス ステーションを早期に収集すると、後の長いエッジの実現可能性が高まる場合です。これは、リソースの獲得を考慮しない最短パスが失敗することを意味します。 

## アプローチ

 強引なアイデアは、ステーションの各サブセットを収集されたボーナスの可能なセットとして扱い、ステーションに到達できるかどうかを計算しようとすることです。$n$これらのボーナスと初期資金のみを使用します。 各サブセットについて、固定エネルギー容量を使用してグラフに対してダイクストラまたは BFS を実行できます。 ただし、これには次のことが必要です$O(2^n)$サブセット、それぞれ少なくともコストがかかります$O(n^2 \log n)$、それは完全に不可能です。 

重要な観察は、どのサブセットが最適であるかを明示的に決定する必要がないということです。 代わりに、二分探索で答えを得ることができます。つまり、金額によって最初の時間予算が決まります。 初期予算が決まっている場合、駅に到着するかどうかを確認するだけで済みます。$n$途中でボーナスを集めながら可能です。 

この実現可能性のチェックは、ダイクストラを使用して行うことができます。ダイクストラでは、州が各駅に到着したときの最大残り時間を追跡します。 エッジを通過するたびに、移動コストが差し引かれます。 駅に到着したら、その駅のボーナスを 1 回追加します。 

重要な構造的洞察は単調性です: 駅に到達できるかどうか$n$ある程度の初期資金があれば$X$なら、どんな方法でも到達できます。$X' > X$。 これにより、答えに対する二分探索が可能になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース サブセット + 最短パス |$O(2^n \cdot n^2 \log n)$|$O(n^2)$| 遅すぎる |
 | 二分探索 + ダイクストラの実現可能性 |$O(n^2 \log n \log V)$|$O(n^2)$| 承認済み |

 ## アルゴリズムのチュートリアル

 まず、すべてのペアごとのマンハッタン距離を事前計算し、次の乗算を行います。$d$。 これにより、完全な重み付きグラフが得られます。 

1. 関数を定義する`can(X)`それは駅に到着できるかどうかをチェックします$n$初期時間から始める$X$駅1で。 
2.内部`can(X)`、各状態が次のようなプライオリティ キュー (最大ヒープ) を使用します。`(remaining_time, node)`。 から始めます`(X, 1)`。 
3. 配列を維持する`best[i]`これまでに駅で達成した最大の残り時間を表す$i$。 この値が改善される場合にのみ、状態を拡張します。 これにより、冗長な探索が回避されます。 
4. 状態をポップするとき`(t, u)`、すべての隣人を考慮します$v$。 旅費は、$cost(u, v)$。 もし$t \ge cost(u, v)$に移動できます$v$残り時間で$t - cost(u, v)$。 
5. 駅に到着したら$v$、すぐにそのボーナスを追加します$a_v$もし$v \neq 1, n$。 ノードごとに最良の到着状態のみを維持するため、これは 1 回限りの性質をモデル化します。 より悪い、または同じ時間をかけて再訪しても、将来の状態を改善することはできません。 
6. いつか駅に着いたら$n$、trueを返します。 
7. 最小の二分探索$X$そのような`can(X)`それは本当です。 

機能する理由: アルゴリズムは、次の不変条件を維持します。`best[i]`駅に到着した時点で達成可能な最大残り時間です。$i$現在の初期予算に基づいて訪問ノードの有効なシーケンスを介して実行されます。 すべてのエッジ コストは負ではなく、ボーナスはノード エントリごとに固定されているため、ノードでの残り時間が厳密に優れていないパスは将来の移行には役立ちません。 これにより、支配的な状態を枝刈りすることで正確さが保たれることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import heapq

def solve():
    n, d = map(int, input().split())
    a = [0] * n
    if n > 2:
        vals = list(map(int, input().split()))
        for i in range(1, n - 1):
            a[i] = vals[i - 1]

    pts = [tuple(map(int, input().split())) for _ in range(n)]

    dist = [[0] * n for _ in range(n)]
    for i in range(n):
        x1, y1 = pts[i]
        for j in range(n):
            x2, y2 = pts[j]
            dist[i][j] = (abs(x1 - x2) + abs(y1 - y2)) * d

    def can(X):
        best = [-1] * n
        pq = [(-X, 0)]
        best[0] = X

        while pq:
            neg_t, u = heapq.heappop(pq)
            t = -neg_t

            if t < best[u]:
                continue

            if u == n - 1:
                return True

            for v in range(n):
                if v == u:
                    continue
                cost = dist[u][v]
                if t < cost:
                    continue

                nt = t - cost
                if 0 <= v < n and v != 0 and v != n - 1:
                    nt += a[v]

                if nt > best[v]:
                    best[v] = nt
                    heapq.heappush(pq, (-nt, v))

        return False

    lo, hi = 0, 10**7
    while lo < hi:
        mid = (lo + hi) // 2
        if can(mid):
            hi = mid
        else:
            lo = mid + 1

    print(lo)

if __name__ == "__main__":
    solve()
```コア実装は以下を中心に展開します`can(X)`、固定された開始予算の下で可能な限り最良の動きをシミュレートします。 優先キューにより、常に最も有望な状態が最初に拡張されます。 の`best`アレイは、支配的な状態を破棄することで指数関数的な爆発を防ぎます。 二分探索は、この実現可能性チェックをラップします。 

微妙な点は、駅ボーナスは出発時ではなく到着時に適用されることです。 もう 1 つは、残り時間を厳密に多くして到着しない限り、ノードへの再訪問を決して許可しないことです。これにより、訪問セットを明示的に追跡することなく、1 回限りのステーションの使用が正しくモデル化されます。

 ## 特殊なケース

 重要なエッジケースは、強制されない限り、最適なルートがボーナスの高い駅を決して訪問しない場合です。 状態は残り時間を改善する場合にのみ伝播するため、アルゴリズムはこれを処理し、不必要な迂回は自然に回避されます。 

もう 1 つのケースは、ステーションがこれまで不可能だったロング エッジを実現可能にするのに十分なボーナスを提供する場合です。 到着時にすぐにボーナスを追加するため、ダイクストラ状態は、出力エッジを探索する前に拡張された機能を正しく反映します。 

最後に、複数のパスが異なる残り時間で同じノードに到達する場合、最良のものだけが生き残ります。`best`、潜在的に最適な将来の展開をすべて保持しながら、次善の到着によって検索スペースが破損しないようにします。
