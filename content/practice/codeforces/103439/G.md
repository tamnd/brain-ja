 ## 解決策
 ## 問題の理解

 配列が与えられています$A$非減少シーケンスに変換したいと考えています。 別途セットもご用意しております$B$予備の値の。 あらゆる要素が$A$そして$B$は区別されます。 

許可される唯一の操作は、値を取得することです。$B$の任意の位置を上書きします$A$それに伴い、各要素も$B$最大 1 回まで使用できます。 目的は並べ替えではない$A$直接ではなく、使用される置換の数を最小限に抑えながら、最終的な配列が非降順でソートされるように一部のエントリを戦略的に置換するためです。 どの置換シーケンスもソートされた配列を実現できない場合、答えは次のようになります。$-1$。 

主要な構造上の制約は、代替品を自由に再利用できないことです。 の各値$B$は使い捨てツールであるため、問題は単に「間違っている位置の数」ではなく、「どの位置をどの使用可能な値で修復できるか」です。 

制約により許可されるのは、$N, M$まで$5 \cdot 10^5$これにより、置換をシミュレートしたり、サブセットを試したりしようとするソリューションは直ちに除外されます。 二次関数の何か$N$または$M$遅すぎます。 有効なアプローチは、前処理後のソートと線形または線形に近いスキャンに依存する必要があります。 

微妙な点は、次のことを要求されていないということです。$A$要素の再配置または挿入によって並べ替えられますが、厳密には置換によって並べ替えられます。 これは、すべての最終値が元の配列または配列から取得される必要があることを意味します。$B$そして、どの位置を「固定」するか、どの値を割り当てるかを効果的に選択しています。 

素朴な推論を打ち破るようなエッジケースは見落とされがちです。 たとえば、次の場合$A = [2, 6, 13, 10]$そして$B = [5]$13 を 5 に置き換えると反転が 10 に修正されると思うかもしれませんが、後でより大きな値が必要になった場合、左側の順序制約が破られる可能性があります。 これがまさに、ローカル修正が失敗する理由です。置換は、最終的なモノトーン構造と全体的に一貫していなければなりません。 

もう 1 つのエッジ ケースは、すべての要素が$B$必要な制約を修復するには小さすぎるか大きすぎます。 たとえば、次の場合$A = [3, 1, 2]$そして$B = [0]$、残りの実現可能性を維持しながら、3 と 1 の間の逆転を修正する方法はありません。 

## アプローチ

 ブルートフォース戦略では、ポジションのすべてのサブセットが試行されます。$A$を置換し、サブセットごとに異なる値を割り当てることができるかどうかを確認します。$B$結果の配列がソートされるようにします。 サイズの固定サブセットの場合$k$、どちらかを選択する必要もあります。$k$からの値$B$それらを使用して位置に合わせます。 実現可能性チェックが線形だったとしても、サブセットの数は$2^N$、値を割り当てると階乗計算が追加されます。 これは非常に小さいものを超えると完全に実行不可能です$N$。 

重要な観察は、最終的な配列がソートされると、その構造が厳格になるということです。一致する必要があるターゲットの非減少シーケンスがあり、どの位置が最終的にどのような値になるかについて制約が課されます。 任意の置換という観点から考えるのではなく、強制的に使用する頻度を最小限に抑えながら、左から右へ有効にソートされた配列を構築する方法を考えることに移行します。$B$。 

問題を再構成する有効な方法は、ソートされた最終的な配列を、元の配列と「互換性がある」必要がある非減少シーケンスとして考えることです。$A$。 加工すれば$A$左から右に、できるだけ多くの元の値を保持したいと考えていますが、それは世界的に増加する構造にまだ適合できる場合に限られます。 要素が実現可能性を損なう場合はいつでも、それを置き換えることができますが、次の値から利用可能な最小値を使用する必要があります。$B$一貫性を保つことができます。 実現可能性がポジションの同一性ではなく、順序付けの制約のみに依存することを理解すれば、これは当然、貪欲な戦略を示唆します。 

より深い洞察は、問題を次の最長のプレフィックスを構築するものとして扱うことができるということです。$A$これは、利用可能な置換を使用してソートされた配列に拡張可能でありながら、変更しないままにすることができます。 保持できない要素がある場合は置換を使用する必要があり、置換の選択は将来の順序を考慮する必要があるため、両方をソートする方向に進むことになります。$A$そして$B$そして制約を貪欲に一致させます。 

最終的な解決策は、最終配列で最後に選択した値を維持し、維持するかどうかを決定するスイープになります。$A[i]$または可能な限り小さいものに置き換えます$B$値は依然として減少しない順序を維持します。 どちらも不可能な場合、構成は不可能です。

 ## アルゴリズムのチュートリアル

 ## アルゴリズムのチュートリアル

 1. 両方の配列をソートします$A$そして$B$。 仕分け$B$これにより、必要なときに常に使用可能な最小の代替品を選択できるようになります。これは非常に重要です。なぜなら、大規模な代替品は将来の実現性を難しくするだけだからです。 
2. ポインタを初期化する$j = 0$のために$B$、および変数$last = -\infty$構築された最終配列に配置された最後の値を表します。 これは単調な制約を追跡します。 
3. 各要素をスキャンします$A[i]$左から右に、それを維持するか交換するかを決定します。 より早い決定が将来のすべてのポジションを制限するため、この順序は重要です。 
4. もし$A[i] \ge last$、安全に保管できます$A[i]$、そして私たちは設定しました$last = A[i]$。 元の値を維持すると置換の回数が減るため、これは最適です。 
5. それ以外の場合は、次を使用して違反を修復しようとします。$B$。 ポインタを進める$j$最小のものを見つけるまで$B[j] \ge last$。 そのような要素が存在する場合は、それを使用し、置換カウントをインクリメントして更新します。$last = B[j]$、その後移動します$j$フォワード。 
6. どちらでもない場合$A[i]$残りの値もありません$B$満足できる$last$、プロセスは不可能であると判断し、戻ります$-1$。 これは、単調性を壊すことなしには埋めることができない利用可能な値のギャップに対応します。 
7. すべての要素が表示されるまで続けます。$A$が処理され、使用された置換の数を返します。 

### なぜ効果があるのか

 アルゴリズムは、インデックスの処理後も不変条件を維持します。$i$、構築されたシーケンスは、置換のサブセットを使用して達成可能な辞書編集上可能な最小の非減少シーケンスです。 仕分け$B$置換を挿入する必要がある場合は常に、実行可能な最小値を使用することで、将来の位置に対する最大限の柔軟性が確保されます。 唯一の要件は元の値に近づくことではなく、非減少次数であるため、より大きな選択を行っても、現在の実現可能性を改善することなく、将来の制約が強化されるだけです。 この貪欲な優位性により、ソリューションが存在する場合、アルゴリズムが不必要にブロックすることがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    
    a.sort()
    b.sort()
    
    j = 0
    last = -10**18
    used = 0
    
    for x in a:
        if x >= last:
            last = x
        else:
            while j < m and b[j] < last:
                j += 1
            if j == m:
                print(-1)
                return
            last = b[j]
            j += 1
            used += 1
    
    print(used)

if __name__ == "__main__":
    solve()
```この実装は、貪欲な構造を直接反映しています。 両方の配列をソートすることは、問題を単調なマッチング プロセスに変える構造的なステップです。 ポインターが上にある$B$各置換が最大 1 回使用され、常に最小値が選択されるようにします。 

実装の微妙な詳細は、$last$これにより、最初の要素の特殊なケースが回避されます。 もう 1 つは、以前の選択を再検討しないため、ソート後のスキャンは厳密に線形であることです。

 ## 特殊なケース

 主なエッジケースは、配列がすでにソートされている場合です。 アルゴリズムが置換ブランチに入ることはありません。$A[i]$は単調条件を満たすため、答えはゼロ置換のままになります。 

もう 1 つのエッジ ケースは、すべての要素が$B$現在の制約よりも小さいです。 この状況では、ポインタ$B$有効な候補が見つからずに実行され、アルゴリズムが正しく返されます。$-1$。 これは、置き換えが単調な要件を埋めることができないギャップに対応します。 

3 番目のケースは、最小の有効な値を選択するなど、貪欲な選択が危険に見える場合です。$B$価値。 トレースは、早い段階で大きな値を使用すると、後の実行可能性が妨げられる可能性があることを示しています。 このアルゴリズムは、実行可能な最小限の置換を常に消費し、将来の要素のために最大のスラックを保存することでこれを回避します。
