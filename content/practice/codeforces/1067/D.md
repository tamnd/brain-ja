 ## 解決策
 ## 問題の理解

 クエストのコレクションが与えられ、それぞれに 2 つの報酬値と成功確率が設定されています。 Ivan は毎秒 1 つのクエストを選択し、それに挑戦します。 試みが成功した場合、彼はそのクエストの基本報酬を受け取り、また、任意の 1 つのクエストを 1 回アップグレードする能力も獲得します。これにより、将来の成功の完了に対する報酬が永久に増加します。 試行が失敗した場合、何も起こりません。 クエストは完了しても消えないため、イワンは同じクエストを無限に再試行し続けることができます。 

このプロセスは固定秒数で実行され、目標は予想される合計報酬を最大化することです。 

主要な構造は、成功した試行ごとに 2 つの効果があるということです。1 つはクエスト報酬からの即時期待利益、もう 1 つは将来の報酬を増やすために最適に割り当てることができるグローバル アップグレード リソースです。 アップグレードは永続的でクエストごとに 1 回のみ使用できるため、限られた数のアップグレードをクエスト全体に割り当てる方法と、毎秒どのクエストを試行するかが決まります。 

制約は非常に厳しく、クエスト数は最大 100,000、時間は最大 10¹⁰ 秒です。 これにより、時間の経過に伴う動的プログラミングや秒に依存する状態が即座に除外されます。 1 秒あたりの線形シミュレーションさえ不可能です。 有効なソリューションでは、時間の次元を分析上の期待値まで削減し、クエストごとに集計された統計に基づいて意思決定を行う必要があります。 

成功頻度が確率に依存することを考慮せずに、成功ごとにアップグレードを貪欲に扱うと、単純な落とし穴が発生します。 たとえば、わずかな確率で報酬が高いクエストは、アップグレードするには魅力的に見えるかもしれませんが、それを正当化するほど十分な成功が得られることは決してないかもしれません。 もう 1 つの失敗例は、アップグレードが常に最も高い b-a 差まで行われる必要があると想定している場合です。 これは、アップグレードが決定的に行われるのではなく、成功した場合にのみ行われることを無視しています。 

## アプローチ

 直接シミュレーションでは、どのクエストがアップグレードされるかを記述する状態を維持し、t 秒間シミュレーションして、各ステップで最適なクエストを選択します。 これは不可能です。なぜなら、t は最大 10¹⁰ であり、すべてのシーケンスに対する期待値を評価しても、指数関数的なサイズの分岐プロセスにつながるからです。 

重要な観察は、アップグレードの真のボトルネックは秒数ではなく成功数であるということです。 試行が成功するたびに、アップグレードの機会が 1 回だけ生成されます。 したがって、システム全体を、期待される成功数と、成功ごとに期待される貢献度という観点から再構築することができます。 

確率 p でクエストが試行された場合、t 秒間で期待される成功数は、それを選択する頻度に比例します。 これは、最適な戦略では、1 秒あたりの個別の選択の観点から考える必要はなく、むしろ各クエストに時間の一部を割り当てる観点から考える必要があることを示唆しています。 各クエストは、期待成功率と期待報酬率に直線的に寄与します。 

長期的な固定ポリシーを最適化していることを受け入れると、問題はクエスト全体に試行を分散する方法と、期待される成功あたりの限界利益を最大化するためにアップグレードを割り当てる方法を決定することに帰着します。 重要な洞察は、各クエストがちょうど 1 回アップグレードされることで (b_i − a_i) に等しいわずかな利点があるということですが、その利点は、クエストが成功する可能性が高く、したがってアップグレードの機会を得るのに十分な回数選択された場合にのみ実現されるということです。

これは、貪欲な再重み付け解釈につながります。各クエストには、p_i a_i の試行ごとのベースライン期待値があり、アップグレードでは、p_i (b_i − a_i) に比例して追加の期待寄与が追加されますが、それは、そのクエストでアップグレード スロットを実際に「使用する」可能性がどのくらいかを考慮した上でのみです。 最適なソリューションでは、プロセスを 2 つの層に分割します。試行の最適な定常状態分布を計算し、次に期待されるアップグレードを、成功あたりの期待限界利得の降順でクエスト全体に分配します。 

最終的な構造は、導出された値によってクエストをソートし、期待されるアップグレードの合計数が期待される成功の合計数に等しいという事実を利用して、期待されるアップグレードをその順序で貪欲に割り当てることになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | t 秒にわたるブルート フォース シミュレーション | O(t) | O(n) | 遅すぎる |
 | 最適な期待 + 貪欲な割り当て | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. クエストがアップグレードされない場合、試行ごとに予想される報酬を計算します。 これは単に各クエストの p_i * a_i です。 これは、アップグレードとは無関係に、あらゆる戦略のベースラインの寄与を形成します。 
2. 各クエストのアップグレードによる限界利益、p_i * (b_i − a_i) を計算します。 これは、アップグレードの適用後に正常に完了するごとに予想される報酬の増加を表します。 
3. 成功したすべての試行でアップグレードの機会が 1 つだけ得られるため、予想されるアップグレードの合計数は、すべてのクエストの予想される成功の合計数に等しいことに注意してください。 これにより、問題は、予想される固定数のアップグレードの割り当てに変換されます。 
4. 定常状態でクエスト間で試行をどのように分散するかを決定します。 各試行は期待値に直線的に寄与し、確率は変化しないため、最適な戦略は、順番ではなく期待される寄与の観点から各クエストを独立して扱うことです。 これにより、注文時間を切り離すことができます。 
5. クエストを限界アップグレード値 p_i * (b_i − a_i) で降順に並べ替えます。 これにより、アップグレードの機会は、成功ごとに期待される改善が最も高いクエストに最初に割り当てられるようになります。 
6. 予想されるアップグレード数をこの順序で貪欲に割り当てます。 各クエストは最大 1 つのアップグレードを受け取るため、min(1、割り当てられた利用可能な期待アップグレード量) を取得し、それに応じて貢献度を蓄積します。 
7. t 秒にわたるベースラインの予想報酬を加算し、予想されるアップグレード特典の合計を加算します。 

重要な点は、アップグレードは決定的なリソースではなく、成功に結びつく予想されるイベントであるということです。 貪欲な割り当てが機能するのは、各アップグレードが期待に独立した線形寄与を持っているためであり、割り当て間に相互作用コストが発生しないためです。 

### なぜ効果があるのか

 このアルゴリズムは、期待の線形性分解に依存しています。 各クエストは試行を通じて期待される報酬に独立して貢献し、成功するたびに 1 単位のアップグレード リソースが貢献します。 アップグレードの利点は追加的であり、クエスト間で独立しているため、問題は、予想される限界利益によるソートによって最適な割り当てが得られる部分的な割り当てになります。 この順序から逸脱すると、より高い価値の候補が存在する一方で、より低い期待限界値を持つクエストにアップグレードが割り当てられ、期待される総報酬が厳密に減少します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n, t = map(int, input().split())
    
    quests = []
    base = 0.0
    upgrades = []
    
    for _ in range(n):
        a, b, p = input().split()
        a = float(a)
        b = float(b)
        p = float(p)
        
        base += t * p * a
        upgrades.append(p * (b - a))
    
    upgrades.sort(reverse=True)
    
    # expected number of successful attempts equals t * average success probability
    # but since we already accounted per-quest baseline over t, upgrades sum directly
    expected_successes = t  # conceptual scaling absorbed in baseline distribution
    
    ans = base
    for i, gain in enumerate(upgrades):
        if i >= t:
            break
        ans += gain
    
    print(ans)

if __name__ == "__main__":
    main()
```コードは、問題をベースラインの期待報酬とアップグレードの利益に分けます。 ベースラインは、クエストあたり t 回の試行にわたって p_i * a_i を累積します。 アップグレード リストには、わずかな改善が保存されます。 並べ替えにより、最適なアップグレードが最初に考慮されるようになります。 このループは概念的には最大 t のアップグレード機会を割り当てますが、n 個のアップグレードしか存在しないため、自動的に切り捨てられます。 

微妙な点は、確率と期待値は非整数であり、精度の制約により標準の倍精度が許可されるため、浮動小数点の累積が必要であるということです。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | 限界アップグレード値によるクエストの並べ替えが計算を支配します。 
| スペース | O(n) | クエストパラメータとアップグレードゲインの保存 |

 ## 特殊なケース

 クエストが 1 つだけの場合、アルゴリズムは同じクエストを繰り返し試行することになります。 アップグレード ゲインは 1 回適用されるだけで、ベースラインが優先されます。 貪欲な構造により、利用可能な 1 つのアップグレードがそのクエストに正しく割り当てられます。 

確率が非常に小さい場合、ベースラインの寄与は縮小しますが、アップグレードの利益は p_i に比例したままになります。 これにより、(b_i − a_i) ギャップが補正できるほど大きくない限り、そのようなクエストは自然に優先順位が低くなり、ソート ルールが正しくキャプチャされます。 

すべてのクエストが同じ (b_i − a_i) である場合、順序は重要ではありません。 アルゴリズムはそれらの間でアップグレードを任意に割り当てますが、限界ゲインが等しいため、どの順序でも同じ期待値が得られ、正確さが維持されます。
