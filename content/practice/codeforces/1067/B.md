 ## 解決策
 ## 問題の理解

 私たちに与えられた木は、$n$頂点をパラメータ化し、非常に特殊な再帰的構築によって生成できるかどうかを尋ねました。$k$。 構築は、ハリネズミと呼ばれる特別なツリーから始まります。このツリーでは、ちょうど 1 つの頂点が中心ハブとして動作し、他のすべての頂点はそれに接続された葉になります。さらに、この中心の次数が少なくとも 3 であることが必要です。 

大型の場合$k$、構造は再帰的に構築されます。前の段階のすべての葉が新しいハリネズミ全体に置き換えられ、元の葉の隣の葉が新しいハリネズミの中心に接続されます。 このプロセスを繰り返すと、中心の芯から外側に向かって広がっていくハリネズミの入れ子のようなツリーが作成されます。 

タスクは、指定されたツリーが正確に取得されたかどうかを判断することです。$k$といった拡張ステップ。 

入力制約により、最大で次のことが可能になります。$10^5$頂点と$k$と同じくらい大きい$10^9$。 これは、構築を明示的にシミュレートできないことがすぐにわかります。 レイヤーを 1 つずつ構築または剥離しようとするソリューション$O(k)$あるいは$O(nk)$不可能です。 

さらに微妙な意味は、答えは特定の構築履歴ではなく、木の構造特性のみに依存するということです。 ツリーは固定されており非循環であるため、再帰的な「階層化されたハブとリーフの展開」構造を持っているかどうかを検出する必要があります。 

いくつかの特殊なケースでは、定義の制約が強調されています。 

ツリーが中心次数が 3 未満の単純なスター (たとえば、長さ 2 のパス) である場合、それは有効な 1 マルチハリネズミですらないため、答えは次の条件に関係なく「いいえ」でなければなりません。$k$。 

もし$k$は大きいですが、ツリーの高さは非常に低く、たとえば、より深いネストを持たないサイズ 100 のスターの場合、再帰的な構築により構造のレイヤーが繰り返されるため、より高いレベルのマルチハリネズミを表すことはできません。 

もう 1 つの失敗モードは、複数の頂点が異なる深さで潜在的な「中心」として機能しているように見えるが、その近傍が互いに素なハリネズミ拡張を形成していない場合です。 局所的に次数をチェックするだけの単純なアプローチでは、そのようなツリーは誤って受け入れられてしまいます。 

## アプローチ

 重要な問題は、定義がハリネズミベースからの再帰的拡張を記述していることです。これは、ルートの周りのレイヤーの観点から考えることを示唆しています。 強引な再構築を試みる場合は、葉の崩壊をシミュレートしようとする可能性があります。すべての次数 1 の頂点を繰り返し見つけて削除し、残りのグラフが別のハリネズミ構造を形成しているかどうかを検出しようとして、このプロセスを繰り返します。$k$回。 

このアプローチは概念的には正しいです。各逆ステップは 1 つの拡張レイヤーを元に戻すことに対応するからです。 ただし、各レイヤーではすべての頂点をスキャンして次数を更新する必要があり、$O(n)$最悪の場合は層になります。 これは次のことにつながります$O(n^2)$長いチェーンや深く入れ子になった構造など、縮退したツリーでの動作は遅すぎます。$n = 10^5$。 

重要な観察は、この構造により、最も深いハリネズミの中心構造からの距離に等しい「層番号」を頂点に割り当てることができるツリーが生成され、各層が外側に広がる BFS 波のように動作することです。 明示的にシミュレーションする代わりに$k$反復により、すべてのリーフから内側への距離構造を計算し、再帰的ヘッジホッグ拡張を、リーフがコアからどれだけ離れていてもよいか、および各層での分岐がどのように動作するかについての制約として解釈できます。 

具体的には、この構造は、頂点の次数が少なくとも 3 (元のハリネズミの中心) である中心領域を強制し、このコアの外側のすべての頂点は、前の層の一意の親に向かうパス上に存在する必要があり、入れ子になった星型の拡張のツリーを形成します。 これにより、葉からの距離を計算し、剪定レイヤーが深さまで有効なシーケンスを生成するかどうかを検証する問題が軽減されます。$k$。 

効率的なソリューションでは、すべてのリーフから開始するマルチソース BFS を使用します。 内側に伝播し、各ノードに「削除時間」(またはレイヤー インデックス) を割り当てます。 割り当てられた最大の深さは、存在する拡張レイヤーの数を示します。 次に、深部で残っているコアの構造が確認されているかどうかを確認します。$k$まだハリネズミの条件を満たしています。

 | BFS レイヤの割り当て |$O(n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての頂点の次数を計算し、すべてのリーフ (次数 1 の頂点) でキューを初期化します。 

すべての展開ステップで新しいリーフが作成されるため、これらのリーフは再帰的構造の最外層を表します。 
2. 各リーフにレイヤー値 0 を割り当て、BFS キューにプッシュします。 

この層は、構造の最初の除去可能な境界を表します。 
3. BFS を内側に実行します: 頂点を処理するとき$v$、その近傍の次数を減らす$u$。 もし$u$の次数が 1 になり、レイヤーを割り当てます$\text{layer}[v] + 1$そしてそれをエンキューします。 

これは、樹木を外側から内側に向​​かって層ごとに剥がすことをシミュレートします。 
4. BFS が完了すると、すべてのノードには、反復的なリーフ ストリッピングで削除されるタイミングに対応するレイヤー値が設定されます。 
5. しましょう$L$最大レイヤ値になります。 構造はまさに$L + 1$概念的なレイヤー。 
6.次のことを確認します。$k$この構造と互換性があります。 根のハリネズミは深さまで生き残らなければなりません$k$、ということを検証します。$k \le L$。 もし$k > L$、ツリーは浅すぎて、$k$-マルチハリネズミ。 
7. レイヤーのノードを考慮する$k$。 これらのノードは「コア」を形成します。$k$-剪定の第2段階。 有効な構造では、このコアには次数 3 以上の頂点 (ハリネズミ中心) が 1 つだけ含まれている必要があり、そのコア内の他のすべての頂点は、誘導された構造内で次数 1 を持つ必要があります。 
8. 少なくとも層を持つノードによって引き起こされる部分グラフを抽出します$k$、このサブグラフ内の次数を再計算し、ハリネズミ条件を検証します。正確に 1 つのノードの次数が 3 以上で、他のすべてのノードの次数は 1 です。 

### なぜ効果があるのか

 BFS ピーリング プロセスは、再帰的構造を逆にエンコードします。 定義の各展開ステップは、ハリネズミの中心に取り付けられた葉のレイヤーを追加することに対応し、そのステップを逆に行うと、それらの葉が正確に削除されます。 グラフはツリーであるため、すべての葉の削除は独立しており、他の葉と干渉せず、階層化が明確に定義されます。 

重要な不変条件は、ノードにレイヤーが割り当てられることです。$d$まさに距離にある$d$反復的なリーフ除去の下で外側の境界から。 これは再帰構造の深さと一致します。 したがって、層で誘導されたサブグラフは、$k$後の残りの構造に正確に対応します$k$構築手順を逆にします。 この段階で hedgehog プロパティをチェックすると、再帰が有効であり、どのレベルでも構造違反が発生していないことが検証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

n, k = map(int, input().split())
adj = [[] for _ in range(n)]
deg = [0] * n

for _ in range(n - 1):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    adj[u].append(v)
    adj[v].append(u)
    deg[u] += 1
    deg[v] += 1

layer = [-1] * n
q = deque()

for i in range(n):
    if deg[i] == 1:
        layer[i] = 0
        q.append(i)

while q:
    v = q.popleft()
    for u in adj[v]:
        if layer[u] == -1:
            deg[u] -= 1
            if deg[u] == 1:
                layer[u] = layer[v] + 1
                q.append(u)

max_layer = max(layer)

if k > max_layer:
    print("No")
    sys.exit()

nodes = [i for i in range(n) if layer[i] >= k]

if len(nodes) == 1:
    print("Yes")
    sys.exit()

indeg = {v: 0 for v in nodes}
s = set(nodes)

for v in nodes:
    for u in adj[v]:
        if u in s:
            indeg[v] += 1

centers = 0
ok = True

for v in nodes:
    if indeg[v] >= 3:
        centers += 1
    elif indeg[v] == 0:
        ok = False

if centers == 1 and ok:
    print("Yes")
else:
    print("No")
```実装は、隣接リストを構築し、次数を計算することから始まります。 BFS キューはすべてのリーフで初期化されます。ピーリング プロセスはマルチソースであるため、これは不可欠です。一度に 1 つのリーフだけを削除すると、レイヤーの解釈が破壊されます。 

レイヤー配列は、反復枝刈り中に各頂点がいつリーフとして露出されるかを記録します。 これは施工深さの逆になります。 

レイヤーを計算した後、次のことを確認します。$k$最大深さを超えています。 そうなった場合は無効です$k$-マルチヘッジホッグ構造が存在する可能性があります。 

少なくともレイヤーを持つ頂点上に誘導されたサブグラフ$k$次に検査されます。 このサブグラフ内で次数を再計算し、ハリネズミ条件を適用します。正確に 1 つのノードの次数が少なくとも 3 でなければならず、他のすべてのノードはこのコア内のリーフでなければなりません。 

微妙な点は、単一ノードのコアが自明に有効であるため、そのケースを個別に受け入れることです。

この誘導されたコア内では、正確に 1 つの頂点が次数 ≥ 3 を持ち、他のすべての頂点がリーフであることが観察されます。 これにより、有効なヘッジホッグ コアが確認されます。 

これは、BFS レイヤ化が再帰的構造の深さを正しく再構築していることを示しています。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、枝刈り後にツリー全体が単一のノードに折りたたまれる場合です。$k$層。 この場合、誘導されたサブグラフのサイズは 1 であり、すぐに受け入れられます。 これは、すべての拡張が最終的に単一の生き残った中心に収束し、ハリネズミ条件が空虚に満たされる状況に対応します。 

複数の頂点が領域内に残っている場合、別のエッジ ケースが発生します。$k$-core ですが、少なくとも 3 の次数を持つのは 1 つだけです。BFS 階層化は引き続き構造を正しく識別しますが、元のグラフの単純な次数チェックでは、外部リーフに応じて誤って拒否または受け入れられてしまいます。 誘導されたサブグラフ内の次数を再計算することにより、このアルゴリズムは、全体的な次数ではなく構造的制限の下での正確性を保証します。 

最後のエッジケースは長いパスです。 パスでは、ピーリング中にすべてのノードが最終的にリーフになり、最大レイヤーはパスの中央に等しくなります。 どれについても$k \ge 1$、誘導されたコアには次数 ≥ 3 の頂点が含まれることは決してないため、アルゴリズムはそれを正しく拒否します。
