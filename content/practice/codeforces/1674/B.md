 ## 解決策
 ## 問題の理解

 私たちは、すべての有効な単語が 2 つの異なる英小文字で構成される小さな言語を与えられています。 アルファベットは固定されており小さいため、次のような異なる文字の順序付きペアを選択することで、考えられるすべての単語を生成できます。`ab`、`ac`、`ba`、 等々。 

これらの単語は辞書順に並べ替えられます。まず最初の文字で並べ替えられ、同じ最初の文字を共有する単語については 2 番目の文字で並べ替えられます。 言い換えれば、これはすべての有効な 2 文字の文字列に対する辞書編集順であり、両方の文字が異なっていなければならないという制限があります。 

各クエリ単語について、このグローバルな順序付けにおける位置を決定する必要があります。 

重要な制約は、辞書に含まれる単語の数が最大 26 × 25 = 650 であることです。 これは、リスト全体を明示的に構築するアプローチであっても、どのようなアプローチでも十分に高速であることがすぐにわかります。 ただし、目標は、何も構築する必要がないことを認識することです。 

よくある単純な間違いは、次のようなペアを忘れることです。`aa`、`bb`、などは有効な単語ではないため、辞書順に推論するときに誤ってそれらを数えてしまいます。 たとえば、すべてのペアを処理した場合`(i, j)`と`i ≤ j`場合、無効なエントリが誤って含まれ、すべてのインデックスがシフトされてしまいます。 

もう 1 つの微妙な利点は、1 ずつずらしたインデックス付けです。 辞書の位置は 1 から始まりますが、文字の演算は当然ゼロベースであるため、不用意なインデックス付けは一貫したシフトにつながります。 たとえば、前に来る単語の数を数え間違える`ba`は一般的な障害点です。誤って含まれている可能性があります。`az`そして、から続けます`ba`除外された自己ペアを適切に考慮せずに。 

## アプローチ

 簡単なアプローチは、有効な 2 文字の文字列をすべて生成し、並べ替えてから、対象の単語を線形にスキャンすることです。 可能性は 650 しかないので、これはすでに効率的です。 構築と並べ替えのコストは実際には一定ですが、概念的には O(26² log 26²) であり、各クエリには最大 650 エントリにわたる線形スキャンが必要になります。 最大 650 のテスト ケースを使用しても、これでも快適に動作します。 

ただし、これは順序の構造を無視します。 辞書は任意のものではなく、各最初の文字が 25 単語のブロック (それ自体を除くすべての 2 番目の文字) を定義する完全な辞書編集グリッドです。 この構造を認識すると、答えを直接計算できます。 

与えられた単語に対して`s = xy`、その前に有効な単語が何個あるかを数えたいとします。 厳密に以下の文字で始まるすべての単語`x`最初に来てください。 このような開始文字ごとに、有効な 2 番目の文字がちょうど 25 個あるため、それぞれが固定ブロック サイズに寄与します。 

その後、 で始まる単語のブロック内で、`x`、厳密に以下の有効な 2 番目の文字が何文字あるかを数えます。`y`ただし、2 番目が 1 番目と等しい場合は除きます。 これはアルファベット上の単純なインデックス調整になります。 

スペースが小さいため総当り攻撃は機能しますが、一般的な戦略としては失敗します。 各最初の文字がサイズ 25 の均一なブロックに寄与しているという観察により、問題はテスト ケースごとの定数時間演算に帰着します。

 ## アルゴリズムのチュートリアル

 1. 単語の両方の文字をゼロベースのインデックスに変換します。`a`そして`b`、 どこ`'a' → 0`、`'b' → 1`、...、`'z' → 25`。 これにより、アルファベットに対する算術推論が可能になります。 
2. 厳密に次の値よりも小さいすべての最初の文字から有効な単語がいくつあるかを計算します。`a`。 このような最初の文字はそれぞれ、それ自体を除くすべての文字と組み合わせることができるため、25 単語になります。 したがって、これは貢献します`a × 25`。 
3. で始まる単語のブロック内`a`、厳密に以下の有効な 2 番目の文字が何文字あるかを数えます。`b`。 これは通常、`b`ただし、次の場合は 1 を減算する必要があります。`b > a`なぜならペアは`(a, a)`は無効であり、そうでない場合はカウントが誤ってシフトされます。 
4. 1 を追加すると、0 から始まるカウントから 1 から始まる辞書インデックスに変換されます。 

### なぜ効果があるのか

 辞書は、最初の文字ごとに 1 つずつ、26 の連続したブロックとして表示できます。 各ブロックは、無効な 2 番目の文字が 1 つ削除されていることを除いて、構造が同一です。 この欠けているエントリは常に対角線のペアであるため、`(x, x)`、それ自体のブロック内の相対位置にのみ影響し、以前のブロックのサイズは決して変更されません。 この不変性により、完全なブロックをカウントし、ローカルで修正することで正確なグローバル インデックスが得られることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        s = input().strip()
        a = ord(s[0]) - ord('a')
        b = ord(s[1]) - ord('a')

        # words before block a
        ans = a * 25

        # position inside block a
        if b > a:
            ans += b
        else:
            ans += b - 1

        print(ans + 1)

if __name__ == "__main__":
    solve()
```コードの最初の部分では、現在の最初の文字の前に単語の完全なブロックがいくつ存在するかを計算します。 各文字は正確に 25 個の有効な単語を構成するため、アルファベット インデックスを乗算します。`a`by 25 は、先行するすべての単語の完全なカウントを返します。 

2 番目の部分は、現在のブロック内のローカル順序付けを処理します。 通常、2 番目の文字インデックスが直接寄与します。`b`位置はありますが、無効なペアです`(a, a)`はこのシーケンス内にあるため、スキップする必要があります。 そのため、2 番目の文字がアルファベットの最初の文字の後にある場合にのみ 1 を減算します。 

最後に、1 を追加して、辞書のゼロベースのカウントから必要な 1 ベースのインデックス付けに移行します。

 ## 特殊なケース

 メインエッジの動作は、欠落している対角ペアを中心に展開します`(x, x)`。 たとえば、次のように考えてみましょう`ba`。 ここ`b = 1`そして`a = 0`。 修正せずに数えます`b = 0`2 番目の文字の位置ですが、これは誤って想定しています`bb`存在するかそれ`ba`予定よりも遅れて表示されます。 調整`b - 1`すべての無効な自己ペアがブロックごとに 1 回だけスキップされるようにします。 

のために`ac`、 どこ`a = 0`そして`c = 2`の場合、2 番目の文字は最初の文字より大きいため、減算は適用されません。 索引は純粋な辞書編集順との一貫性を維持します。 

のために`zx`、その前に 25 の完全なブロックが存在するという事実に依存します。`25 × 25 = 625`言葉。 最後のブロック内では、`x`それ自体とすべての小さい有効な文字を除外し、特別な大文字小文字を必要とせずに正しい最終位置を生成します。 

すべてのケースにおいて、アルゴリズムは辞書を明示的に構築することはありませんが、均一なブロック構造と単一のローカル修正を組み合わせることで正確な順序を保持します。
