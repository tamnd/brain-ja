 ## 解決策
 ## 問題の理解

 頂点が 0 から n−1 までラベル付けされた無向グラフが与えられます。 グラフは接続されたコンポーネントに分割され、頂点が永久に削除されるため、ゲームの進行に応じて構造が変化します。 

移動は、現在存在する接続コンポーネントを選択することで構成されます。 コンポーネントが選択されると、プレーヤーはそのコンポーネント内の最小ラベルを持つ頂点を強制的に削除します。 頂点を削除すると、すべての入射エッジも削除されるため、コンポーネントが複数の小さなコンポーネントに分割される可能性があります。 2 人のプレイヤーが交互に動き、指定された頂点を先に削除した方が勝ちです。 

タスクは、潜在的な勝利ターゲットとして扱われるすべての頂点について、両側から最適なプレイを想定して最初のプレーヤーが勝利を強制できるかどうかを判断することです。 

主な難点は、プレイヤーがどの頂点を削除するかを直接選択しないことです。 コンポーネントを選択するだけで、ラベルの低い頂点が最初に消えるため、コンポーネントの構造は動的に進化します。 

制約から、n と m は両方ともテスト ケースごとに 100000 に達し、合計は最大 2×10^6 になります。 これにより、ゲームを段階的にシミュレートするアプローチは除外されます。 頂点ごとに O(n log n) であっても許容されますが、状態ごとにグラフの走査を繰り返すようなものは許容されません。 

微妙なエッジ ケースは、頂点を削除するとコンポーネントが非自明な方法で分割される可能性があるという事実から生じます。 たとえば、パス 0-1-2-3-4 で 1 を削除すると、グラフが {0} と {2,3,4} に分割されます。 元のコンポーネントのみを追跡する単純なシミュレーションは、接続が静的ではないため失敗します。 

もう 1 つの注意が必要な状況は、複数の小さな頂点がコンポーネントの異なる部分に配置されているものの、接続されていない場合です。 たとえそれらが同じ初期コンポーネント内にあったとしても、異なる順序で個別に削除される可能性があるため、単純な「コンポーネントの順序」推論は信頼できなくなります。 

## アプローチ

 ゲームについて強引に考える方法は、考えられるすべての一連の動きをシミュレートすることです。 状態は現在のグラフであり、各移動によりコンポーネントが選択され、その最小頂点が削除されます。 これは、分岐要素がコンポーネントの数であり、深さが n であるゲーム ツリーを定義します。 小さなグラフの場合でも、削除ごとにコンポーネントが分割され、新しい選択肢が作成される可能性があるため、これは組み合わせ的に爆発的に発生します。 状態の数は n で指数関数的であるため、このアプローチは実行できません。 

重要な観察点は、コンポーネントから削除された唯一の頂点は、その現在の最小ラベルであるということです。 これは、固定された接続領域内では頂点が昇順に削除されますが、プレイヤーは領域を選択することでどの領域を「進める」かを制御することを意味します。 グラフの構造は、小さなラベルから大きなラベルへの流れをどのように制限するかによってのみ重要になります。 

決定的な洞察は視点を逆転させることです。 ゲームがグローバルにどのように進化するかを考える代わりに、ある頂点が、同じ接続された構造内でそれより小さい他の頂点によって「保護」できるかどうかを考えてみましょう。 対戦相手のアクセスを遅らせる方法で頂点がすべての小さな頂点から分離されている場合、その頂点は接続性に応じて遅かれ早かれ戦略的に削除できるようになります。 

これにより、グラフ伝播ビューが得られます。各頂点 v は、v より大きい頂点を通過しないパスを介して接続されている、より小さいラベルを持つ頂点によってのみ影響を受けます。これにより、問題はフィルターされたグラフでの到達可能性の分析に変換され、頂点を昇順に処理し、すでに「アクティブな」頂点間の接続を維持します。

最適な解決策は、段階的に明らかにされるグラフに対して素の集合和集合構造を使用します。 頂点を昇順に処理する場合、各頂点をアクティブ化し、すでにアクティブ化されている隣接頂点に接続します。 これは、頂点 ≤ v によって引き起こされる接続性を正確に捉えており、v が脆弱な位置に「強制」されるか、戦略的にアクセス可能な状態を維持するかを決定します。

 ## アルゴリズムのチュートリアル

 すでに処理された頂点によって引き起こされるサブグラフ上の DSU を維持しながら、ラベルの昇順で頂点を処理します。 

1. 最初はエッジを追加せずに、すべての頂点にわたって素セット共用構造を初期化します。 グラフの隣接リストも用意します。 
2. 頂点 v を 0 から n−1 まで昇順に繰り返します。 ステップ v では、v を「アクティブ化された」ものとして扱います。これは、v が処理された頂点の誘導されたサブグラフの一部になったことを意味します。 
3. u < v となる v のすべての近傍 u について、DSU で v と u をマージします。 これにより、両方のエンドポイントがすでにアクティブ化されているすべてのエッジが現在の接続構造で表現されることが保証されます。 
4. v のすべての結合が適用された後、v を含む DSU コンポーネントを調べます。このコンポーネントに複数の頂点が含まれる場合、v はプレフィックス構造内で分離されておらず、勝者とみなされます。 そうでなければ負けです。 

ステップ 4 の背後にある推論は、v がアクティブになった瞬間にそれよりも小さいか等しい頂点間で孤立したままである場合、コンポーネントの選択を通じて到達可能になったときに対戦相手が制御できる位置に構造的に強制されるということです。 それがすでにより大きな構造に統合されている場合、対戦相手が除去のタイミングを孤立させることを防ぐ、相互作用の代替パスがあります。 

### なぜ効果があるのか

 不変条件は、頂点 v を処理した後、DSU がラベル ≤ v の頂点によって引き起こされるサブグラフ内の接続性を正確に表すということです。元のグラフに存在するこのような 2 つの頂点間のパスは、上位ラベルの頂点がまだアクティブ化されていないため、頂点 ≤ v のみを通過できます。 

これは、v に到達した時点で、v のアクセシビリティに影響を与える可能性のあるすべての小さなラベル構造がすでに完全に説明されていることを意味します。 その時点で v がより大きなコンポーネントにマージされるかどうかによって、それが以前の頂点によって構造的に制約されるか、独立したままになるかが決まります。 この構造的な違いは、対戦相手がコンポーネント最小値として v を遅延させるか即時に露出させるかを正確に決定します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return
        if self.size[ra] < self.size[rb]:
            ra, rb = rb, ra
        self.parent[rb] = ra
        self.size[ra] += self.size[rb]

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n, m = map(int, input().split())
        adj = [[] for _ in range(n)]
        for _ in range(m):
            u, v = map(int, input().split())
            adj[u].append(v)
            adj[v].append(u)

        dsu = DSU(n)
        active = [False] * n

        ans = []

        for v in range(n):
            active[v] = True
            for u in adj[v]:
                if u < v and active[u]:
                    dsu.union(u, v)

            if dsu.size[dsu.find(v)] > 1:
                ans.append(v)

        out.append(" ".join(map(str, ans)))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この解決策は、頂点の段階的なアクティブ化に依存しています。 隣接リストは、各新しい頂点を以前に処理された頂点にのみ接続するために使用され、各エッジが順方向に 1 回だけ考慮されるようにします。 

DSU 構造は、増加するプレフィックス グラフ内で接続されたコンポーネントを維持します。 サイズ チェックは、頂点のすべての結合が完了した後に実行されるため、そのプレフィックスでの接続の最終状態が反映されます。 

よくある実装の落とし穴は、順序に関係なくすべての近傍を結合しようとすることです。これにより、二重にカウントされたり、将来の頂点が誤って導入されたりします。 共用体を u < v に制限すると、DSU が常に有効なプレフィックス誘導サブグラフを表すことが保証されます。

 ## 特殊なケース

 重要なエッジケースは、グラフが完全に切断されている場合です。 その状況では、すべての頂点がアクティブ化時に孤立したままになるため、DSU がサイズ 1 を超えて拡大することはありません。アルゴリズムは、すべての頂点を負けまたは勝ちなしとして正しく分類し、接続によって戦略的優位性を獲得する頂点がないという事実と一致します。 

特定の低インデックス頂点を処理した後にのみグラフが接続される場合、別のエッジ ケースが発生します。 この時点で、DSU ユニオンは後の頂点に伝播します。これは、ブリッジ ノードを早期にアクティブ化すると、後続のすべてのコンポーネントの構造が変更されることを意味します。 エッジは両方のエンドポイントがすでにアクティブな場合にのみ追加されるため、インクリメンタルな構築ではこれを自然に処理します。 

最後の微妙なケースは、0 を中心とする星形グラフです。最初に 0 を処理するとき、それは分離されたままですが、より高い頂点がそれに接続し直すと、それらはすべて 1 つの DSU コンポーネントにマージされます。 これは、ラベルの低い単一のハブが後続の複数の頂点のマージをどのように制御するかを正確に反映しており、これはまさにゲームが依存する構造効果です。
