 ## 解決策
 ## 問題の理解

 左から右に厳密に増加する位置に配置されたドミノの列が与えられます。 各ドミノには高さがあり、落ちるとその手の届く範囲にあるすべてのものを右側に押し出すことができます。ここで、リーチとは、その位置からその位置に高さを加えた間隔を意味します。 

ドミノが倒れると、カスケードが引き起こされる可能性があります。新しく倒れたドミノは同じように前進し続けます。 このプロセスは決定的であり、ドミノが以前に倒れたドミノの手の届く範囲内にあるかどうかによってのみ決まります。 

問題は、最初のドミノから最後のドミノまでのこのカスケードに関する 3 つの主張についてです。 ある主張では、最初のドミノが最終的に最後のドミノを倒すことはできないと言われています。 別の人はそれができると言っています。 3 番目のドミノは可能であると言っていますが、内部ドミノを 1 つ削除すると、最初のドミノが最後のドミノに到達する能力が失われます。 

したがって、私たちは実際にライン上の到達可能性構造を分析しています。各ドミノは配列の一部のサフィックスに直接的な影響を及ぼし、1 から n までのグローバルな接続性と、単一の内部ノードが削除された場合にその接続性がどれほど脆弱であるかを理解したいと考えています。 

この制約により、テストごとに最大 20,000 個のドミノ、および最大 100 個のテストが許可されます。 最悪の場合、およそ 4e8 回の演算に達する可能性があるため、テストごとの 2 次シミュレーションは遅すぎます。 これにより、テスト ケースごとに線形またはほぼ線形のスイープが強制されます。 

単純な落とし穴は、3 番目のクレームをチェックするときに、削除されたインデックスごとに完全な伝播をシミュレートすることです。 そのためには、到達可能性を n 回再計算する必要があり、それぞれが O(n) になる可能性があり、O(n^2) になりますが、これでは遅すぎます。 

もう 1 つの微妙な問題は、ドミノ 1 がドミノ n に到達できる場合、中間のドミノがすべて何らかの形で必要であると仮定することです。 これは誤りです。 複数のドミノはリーチ内で重複する可能性があるため、一部はチェーンを維持するために冗長になります。 

## アプローチ

 最初のステップは、ドミノ 1 が最終的にドミノ n に到達するかどうかを計算する方法を理解することです。 位置はソートされるため、最初のドミノから開始して現在の「アクティブなリーチ間隔」を維持すると考えることができます。 ドミノが現在のリーチ内にある場合は常に、そのリーチをさらに拡張する可能性があります。 

ブルート フォース シミュレーションでは、すべてのドミノを繰り返しスキャンし、到達可能なインデックスを繰り返し拡張します。 最悪の場合、各展開で O(n) がスキャンされ、これが O(n) 回発生し、O(n^2) になります。 これは、多くのテスト ケースにわたる 20,000 要素にとっては、すでに限界ギリギリの速度です。 

重要な観察は、プロセスが貪欲な区間拡張のように動作することです。 ドミノを位置の昇順に処理したら、これまでに到達可能な最も遠い点を維持するだけで済みます。 ポジションがその範囲内にあるすべてのドミノは候補拡張に寄与し、ポジションは厳密に増加しているため、以前の決定を再検討する必要はありません。 

これにより、到達可能性チェックが 1 から n に減り、単一の線形スキャンになります。 

より難しいのは 3 番目の主張です。すべての内部ドミノはおそらく重要であり、どれかを削除すると到達可能性が損なわれることを意味します。 これは、到達可能性チェーンが一意に強制され、拡張のどの段階でも冗長な寄与者が存在しないと言っているのと同じです。 

スイープ中に、到達可能なフロンティアが増加するたびに、その増加は、間隔が前の最大値を超えた少なくとも 1 つのドミノによって引き起こされます。 いずれかの段階で、同じ最大拡張を生成する可能性のある複数の異なるドミノが存在する場合、それらの 1 つを削除しても、別のドミノを介して同じ拡張が発生することは妨げられないため、チェーンは一意ではありません。 

同様に、現在の最大値の延長にまったく寄与しないドミノは、他のドミノによって常にバイパスされるため、最後のドミノに到達するために必須ではありません。 

したがって、必要な構造は、到達可能性だけではなく、グリーディ スイープ内のすべての拡張イベントの一意性です。

|---|---|---|

 | 除去のための総当たりシミュレーション | O(n²) | O(n) | 遅すぎる |

 | 貪欲なリーチ + 独自性の追跡 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各テスト ケースを個別に処理し、リーチの拡大ごとにどのドミノが原因であるかを注意深く追跡しながら、ドミノ効果がどこまで伝播するかをシミュレートします。 

### アルゴリズム

 1. 最初のドミノから開始し、現在の最も遠いリーチをその位置に高さを加えた値に設定します。 これは、ドミノ 1 から始まるカスケードによって現在影響を受けている右端のポイントを表します。 
2. ドミノを左から右にスキャンします。 現在の到達範囲を超えていない位置にあるすべてのドミノについて、これまでのチェーンによって「アクティブ化」されているとみなします。 
3. アクティブ化されたドミノを見つけるたびに、そのリーチと現在の最大リーチを比較します。 到達距離がさらに伸びる場合は、到達可能な最も遠いポイントを更新します。 
4. グローバル最遠リーチが増加するたびに、どのドミノがこの増加を達成したかを正確に記録します。 複数のドミノが同じ段階で同じ最大拡張を達成する場合、その構成を非固有としてマークします。 
5. すべてのドミノが処理されるか、現在のリーチがすでに最後のドミノをカバーするまで続行します。 
6. 最終リーチが最後のドミノをカバーできない場合、答えはすぐにゴールは不可能であるという最初の兄弟の主張になります。 
7. 最後のドミノに到達可能であるが、プロセスの拡張イベントにあいまいさがなく、すべての内部ドミノが独自の展開チェーンに参加している場合、内部ドミノを削除するとチェーンが切断され、3 番目の要求と一致します。 
8. そうでなければ、鎖は十分に壊れにくいので、2番目の兄弟の主張は正しいです。 

### なぜ効果があるのか

 グリーディ リーチ プロセスでは、インデックス i までのすべてのドミノを処理した後、維持される最も遠いリーチが、プレフィックス内のドミノのみを使用して到達可能な最大の位置に等しいという不変条件が維持されます。 すべてのドミノはその右側のインデックスにのみ影響するため、同じ間隔オーバーラップ構造を経由せずに、後の決定で以前のリーチ値を遡って改善することはできません。 

一意性条件は、リーチの拡大が貢献者の単一の強制シーケンスに依存するかどうかをキャプチャします。 いずれかの段階で複数のドミノが独立して同じ拡張を生成できる場合、少なくとも 1 つのドミノが削除されても生き残る代替の有効な伝播パスが存在します。 これは、すべての内部ドミノが 1 から n までの到達可能性構造のカット頂点であるという要件と真っ向から矛盾します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        p = []
        h = []
        for _ in range(n):
            x, y = map(int, input().split())
            p.append(x)
            h.append(y)

        far = p[0] + h[0]
        i = 1
        used_unique = True

        # track which index caused last expansion
        last_expander = 0

        while i < n and p[i] <= far:
            best_reach = far
            best_idx = -1

            j = i
            # process current active window
            while j < n and p[j] <= far:
                reach = p[j] + h[j]
                if reach > best_reach:
                    best_reach = reach
                    best_idx = j
                elif reach == best_reach:
                    used_unique = False
                j += 1

            if best_reach == far:
                break

            # update reach
            far = best_reach

            # if more than one candidate could achieve this extension, not unique
            if best_idx == -1:
                # shouldn't happen if best_reach > old far
                pass
            else:
                # check ambiguity: if another had same best_reach already flagged above
                last_expander = best_idx

            i = j

        if far < p[n - 1]:
            print("Pep")
        else:
            if used_unique:
                print("Ivet")
            else:
                print("Cesc")

if __name__ == "__main__":
    solve()
```この実装では、最初に単一のスイープを使用してリーチの前方伝播を計算します。 変数`far`ドミノ 1 から現在到達可能な最大位置を格納します。ポインター`i`次の未処理のドミノを追跡します。 

アクティブなウィンドウ内。位置がその範囲内にあるすべてのドミノによって定義されます。`far`、リーチを最も伸ばすであろうドミノを探します。 複数のドミノが同じ最大拡張を達成する場合、その構成は一意に強制されていないものとしてマークされます。 

旗`used_unique`脆弱なチェーンと冗長性のあるチェーンを区別する鍵となります。 いずれかの時点でリーチの拡大方法に曖昧さが現れた場合、適切なドミノを削除しても接続は破壊されません。 

最後に、計算されたリーチを最後のドミノの位置と比較します。 到達できない場合は、ペップの言うことが正しいです。 到達可能で完全に一意であれば、Ivet が正しいです。 それ以外の場合は、セスクが正しいです。 

ポインタを進めるのを忘れたり、ウィンドウの境界を誤ったりすると、到達可能な遷移が過大または過少にカウントされる可能性があるため、アクティブ ウィンドウを正しく処理するには微妙な注意が必要です。 

## 実用的な例

 すべてのドミノの高さが同じで、それぞれのドミノの間隔が狭く、それぞれのドミノが直接届く範囲にあるという単純なケースを考えてみましょう。 

スイープを追跡します。 

| ステップ | i 範囲 (アクティブ) | 遠く | 最高の拡張機能 | 独自性 |
 | --- | --- | --- | --- | --- |
 | 開始 | 1 | p1+h1 | なし | 本当 |
 | 展開する | 2..k | 更新されました | 単一または複数 | 追跡された |

 緊密に連鎖した例では、各ドミノはそのステップでリーチを拡張できる唯一のドミノであるため、一意性が保たれます。 

ここで、2 つのドミノが重なり合い、両方のドミノが同じ点を超えてリーチを伸ばすことができる場合を考えてみましょう。 同じアクティベーション ウィンドウ中に、両方とも同じ最大リーチを生成します。これは、一意性を即座に破り、チェーン全体を壊すことなく少なくとも 1 つのドミノを削除できることを示します。

 ## 特殊なケース

 一般的なエッジ ケースは、ドミノの間隔が離れすぎて、最初のステップを越えてチェーンが存在しない場合です。 このような場合、アクティブ ウィンドウが拡張されず、リーチが最初のドミノで止まったままになるため、アルゴリズムは直ちに停止します。 最後のドミノに到達しないため、これにより Pep が正しく生成されます。 

もう 1 つのエッジ ケースは、すべてのドミノが重なっているが、複数のドミノが同時にリーチを均等に伸ばすことができる場合です。 スイープは、リーチが更新される同じアクティブ ウィンドウ中にこれを検出します。 複数の候補が同じ最適な拡張子を共有するため、一意性が失われ、結果は Ivet できません。 

最後の微妙なケースは、各ドミノが厳密に必要であり、代替パスが存在しない完全な線形チェーンです。 その状況では、各拡張ステップには 1 つのコントリビューターが存在し、内部ドミノを削除すると伝播チェーンが完全に切断されます。 アルゴリズムは、`used_unique`スイープ全体で true としてフラグを立て、Ivet を生成します。
