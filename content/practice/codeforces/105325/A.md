 ## 解決策
 ## 問題の理解

 完全なグラフのすべてのエッジに重みを割り当てるように求められます。$n$ラベル付けされた都市。 がある$\frac{n(n-1)}{2}$無向エッジなので、各整数を次から配置する必要があります。$1$に$\frac{n(n-1)}{2}$まさに一度。 

ツイストは、これらの重みによって引き起こされるメトリックの一貫性条件です。 重みをエッジの長さとして解釈し、2 つの都市間の距離をグラフ内の最短経路距離として定義すると、同じ数のペアに対して$(u,v)$可能な限り、最短パス距離は、間の直接エッジの重みと等しくなければなりません。$u$そして$v$。 言い換えれば、ほとんどのエッジが、中間頂点を経由するルーティングによって決して改善されない「メトリック エッジ」のように動作するようにしたいのです。 

単純に解釈すると、完全な状態ですべての個別の重みを使用しながら、グラフをツリー メトリックのように動作させようとしていることがわかります。 これは世界的に不可能です。なぜなら、どのサイクルでも、重みが任意の場合、三角形不等式により少なくとも 1 つのエッジが改善可能になるからです。 スコアリング関数はこれを裏付けています。条件を満たすペアの数に比例して報酬が与えられるため、構築が完璧である必要はなく、ダイレクトエッジの最適性を最大化するように構築されていれば十分です。 

制約は小さいですが、$n \le 52$、だからどれでも$O(n^2)$または$O(n^3)$建設は簡単です。 本当の課題は純粋に組み合わせの問題です。つまり、ほとんどの直接エッジが最短パスのままとなる重みの順序を決定することです。 

単純な考え方による微妙な失敗例は、エッジを行ごとに埋めたり、ラベルをランダムに並べ替えたりするなど、重みを恣意的に割り当てることです。 このような構造では、ほぼすべての三角形が$(i,j,k)$3 番目の頂点を経由すると非最適化される、より重いダイレクト エッジを持つことになります。 たとえば、次の場合$w(i,j)$は大きいですが、両方とも$w(i,k)$そして$w(k,j)$が小さい場合、間の最短経路は$i$そして$j$ダイレクトエッジを回避し、コンディションをブレイクする。 

したがって、目標は、直接エッジが最小のルートになるように強制されるという意味で、ほとんどの三角形が「タイト」になるように重みを構造化することです。 

## アプローチ

 完全なグラフは、「重要性」によってエッジを順序付けるという観点から考えることを示唆しています。 重要な障害は、三角形の 3 つの辺の間で競合が発生することです。 すでに小さなエッジによって適切に接続されているグラフの領域に小さな重みを配置すると、それらのエッジは最適なままになる可能性が高くなりますが、後で配置された大きな重みはバイパスされやすくなります。 

強引なアイデアは、すべてのエッジの重みの順列を試し、ペアごとに直接エッジが最短かどうかを計算することです。 これには、順列ごとにすべてのペアの最短パスを実行する必要がありますが、これは不可能です。$(n^2)!$順列、および 1 つの候補を評価する場合でも、$O(n^3)$フロイド・ウォーシャル経由。 

重要な洞察は、グローバルな最短パスに関する推論を避け、代わりにエッジの大規模なサブセットの最適性を保証するローカル構造を強制することです。 個別の重みを持つ完全なグラフでこれを実現する標準的な方法は、新しい頂点が接続されたときに、その入射エッジが制御された方法で以前に配置されたすべてのエッジよりも大きくなるように、注意深く順序付けられた方法でエッジを構築することです。 これにより、後の頂点はより大きな迂回を導入するだけであるため、前のエッジが後の頂点をバイパスできないことが保証されます。 

基本的には成長プロセスをシミュレートします。エッジが小さい小さなコアから始めて、徐々に大きなウェイトを持つ新しい頂点を追加します。 この構造内では、新しい頂点を通る代替パスではより大きな重みが使用されるため、以前の頂点内のエッジは保護されます。 新しい頂点を含むエッジは最適性を失う可能性がありますが、その数は比較的少なく、構築により保持されるエッジの数が最大化されます。 

これにより、グラフが入れ子になった階層のように動作するように、「層の深さ」を増やす際にエッジの一貫した順序を決定するという問題が軽減されます。

 ## アルゴリズムのチュートリアル

 エッジの重みを昇順に構築し、上三角隣接行列に行ごとに埋めていきます。 

1. カウンタを初期化する$cur = 1$。 これは、次の未使用のエッジの重みを表します。 
2. 最初の頂点を反復処理します。$i$から$1$に$n-1$。 それぞれについて$i$、エッジに重みを割り当てます$(i, j)$みんなのために$j > i$。 
3. それぞれのペアについて$(i, j)$、割り当てます$w(i, j) = cur$、次に増加します$cur$。 
4. 上三角行列のすべての行をこの正確な順序で出力します。 

重要な考え方は、前の頂点が後の頂点に向かってより小さいラベルを持つエッジを取得し、下に移動するにつれて、$i$、エッジは徐々に大きくなります。 

### なぜ効果があるのか

 あらゆるエッジを考慮する$(i, j)$と$i < j$。 からの代替パス$i$に$j$中間の頂点を通過する必要があります$k$。 もし$k < i$、次に両端$(k,i)$そして$(k,j)$割り当てが早かったり、小規模な場合でも、迂回できる構造になっています。$k$ダイレクト エッジはダイレクト エッジに比べてコストが削減されないため、$(i,j)$を含む前の行に付随するすべてのエッジの後に割り当てられます。$i$すでに制御された昇順に配置されています。 

もし$k > i$、次にエッジ$(i,k)$そして$(k,j)$行内のエッジ以上の重みを厳密に持つ$i$、2 段階のパスを作成します。$k$順序が固定されると、厳密には直接エッジよりも高価になります。 

この順序付けにより、単調な構造が強制されます。行列の左上に近いエッジが潜在的な迂回路を支配するため、ペアの大部分で最短パスが直接エッジと一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    cur = 1

    for i in range(n - 1):
        row = []
        for j in range(i + 1, n):
            row.append(str(cur))
            cur += 1
        print(" ".join(row))

if __name__ == "__main__":
    solve()
```この実装は、上三角隣接行列の構築に直接続きます。 唯一の状態はグローバルカウンターです`cur`、からのすべての整数が保証されます。$1$に$\frac{n(n-1)}{2}$は 1 回だけ使用されます。 

ループ構造は出力形式と正確に一致します: row$i$プリント$n-i-1$エッジに対応する値$(i, j)$みんなのために$j > i$。 値がすぐに生成されて出力されるため、完全な行列を保存する必要はありません。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    cur = 1
    out = []
    for i in range(n - 1):
        row = []
        for j in range(i + 1, n):

 ## 特殊なケース

 自明ではない最小のケースは次のとおりです。$n=3$。 アルゴリズムは次のように割り当てます。$(1,2)=1$、$(1,3)=2$、$(2,3)=3$。 出力は次のとおりです。```
1 2
3
```順序には曖昧さはなく、すべてのエッジが 1 回だけ使用されます。 任意のエッジをその直接の重みよりも小さくできる 3 番目の頂点の代替手段がないため (三角形は 1 つだけあります)、この構造は意図した構造を自明に満たします。 

上限で$n=52$、アルゴリズムは依然として 1326 個の割り当てのみを実行します。 出力は厳密に三角形のままであり、ループ構造が必要な形式を直接反映しているため、行割り当ての不一致は発生しません。
