 ## 解決策
 ## 問題の理解

 問題の難易度の固定リストと参加者の評価リストが与えられます。 参加者が評価を持っている場合$a_i$、彼らは、難易度が最大でも問題を正確に解決します。$a_i$。 したがって、各参加者は基本的に、選択したサブセット内でどれだけ多くの問題を解決できるかによって特徴付けられます。 

パラメータを選択できるようになりました$k$を形成することを決定します。$\lfloor m/k \rfloor$コンテスト、それぞれに正確な内容が含まれています$k$問題。 コンテストで使用する問題を選択し、残りは未使用のままにする場合があります。 

固定コンテストの場合、ケビンのランクは、各参加者がそのコンテストで解決した問題の数によってのみ決まります。 誰かが厳密にケビンよりも多くの問題を解決した場合、その人はケビンよりも上位にランクされます。 ということでケビンの順位は$1 +$そのコンテストで厳密に彼を上回る成績を収めた参加者の数。 

目標は、すべての人にとって、$k$、問題をサイズのグループに分割または選択します。$k$、形成されたすべてのコンテストにおけるケビンのランクの合計を最小化する方法で。 

重要な観察は、コンテストは同じ問題プールを共有することを除いて独立していますが、各問題は多くても 1 回しか使用されないということです。 

制約は大きく、最大で$3 \cdot 10^5$合計$n$そして$m$複数のテストケースにわたるため、すべてのテストに対する答えが必要です$k$1から$m$。 それぞれのコンテストを明示的に構築しようとするソリューション$k$それは少なくとも$O(m^2)$または、テストケース全体で動作が悪化します。 

より深い構造は、ランキングは各参加者がグループ内で解決した問題の数のみに依存し、その量はグループ内で最大でも評価が難しい問題の数にのみ依存するということです。 これにより、各参加者が選択されたセットのしきい値関数に変換されます。 

単純な間違いは、各コンテストがコンテスト間の制約なしに個別に最適化できると想定することです。 問題は世界的に共有されているため、これは間違いです。 

2 番目の微妙な落とし穴は、「参加者ごとに解決できる問題」の総数だけが世界的に重要であると考えることです。 実際には、同一の問題を異なるグループに分割すると、コンテストごとの相対的なランキングが非線形に変化します。 

## アプローチ

 固定資産に対するブルートフォースアプローチ$k$あらゆる方法で選択してみます$\lfloor m/k \rfloor \cdot k$問題を解決し、それをあらゆる方法でコンテストにグループ化します。 グループ化を無視しても、サブセットの選択にはすでにコストがかかります$\binom{m}{k}$コンテストごとの選択肢は飛躍的に増加します。 全体にわたって$k$、これはまったく不可能です。 

選択した一連の問題を修正したとしても、コンテストでのケビンの順位を評価するには、参加者ごとに、選択した問題の数を計算する必要があります。$\le a_i$、これは並べ替えまたはプレフィックス数で実行できます。 しかし、最も難しいのは、すべてのコンテストにわたってケビンのアドバンテージを最大化するサブセットを選択することです。 

重要な洞察は、視点を逆転させることです。コンテストについて考える代わりに、各難易度がレーティングと比較してどれだけの「使用可能なスロット」に寄与するかを考えてください。 

両方の配列をソートします。 次に、しきい値を考えてみましょう$x$: のセットを選択すると、$k$問題は、そのコンテストでのケビンのパフォーマンスは、それらの数に依存します$k$は$\le a_1$。 他の参加者全員$i$選択された問題の数で比較されます$\le a_i$。 カウントはしきい値のみに依存するため、各参加者はソートされた難易度に対してステップ関数を誘導します。 

重要な単純化は、固定された$k$、最良の戦略は常に、ケビンを「追い越す」ことができる参加者の数を最小限に抑える方法で問題を選択することです。 これは、ソートされた難易度に対する貪欲な選択に帰着します。難易度が高くなると、問題を解決する参加者の数が減りますが、ケビンが過度に害を受けないように構造は維持されるため、できるだけ「大きい」問題を選択したいと考えています。 

困難を分類した後、管理された方法で上位の要素を取得することを効果的に検討します。 それぞれについて$k$を繰り返し形成していきます。$\lfloor m/k \rfloor$各グループは、ケビンの解決数を超える参加者の数に等しいコストを貢献します。 これは、サイズのブロックでソートされた配列から貪欲にグループを構築するものとして再構成できます。$k$ここで、各ブロックの寄与は、参加者のしきい値に対する内部最小値のみに依存します。 

最後の最適化は、ソートされた問題のすべてのプレフィックスについて、グループが特定の「カット レベル」で選択された場合にケビンよりも優れたパフォーマンスを発揮する参加者の数を事前計算することによって行われます。 参加者もソートされているため、指定された値を超える評価の数を維持し、これをすべての参加者で再利用できます。$k$。 それからそれぞれについて$k$、グループを再構築する代わりに、サイズのチャンクを取得することをシミュレートします。$k$あらゆるプレフィックス構造に最適なソートされた配置から。 

これにより、古典的な除数スタイルの集計が行われます。ソートされた配列内の各インデックスは、すべてのインデックスに寄与します。$k$ここで、それは何らかのグループに含まれており、差分配列のような方法で寄与を倍数にわたって蓄積します。$k$。

 ## アルゴリズムのチュートリアル

 1. 参加者の評価と問題の難易度を並べ替えます。 ソートが必要なのは、解決動作と比較の両方がアイデンティティではなくしきい値のみに依存するためです。 
2. 各参加者について、トップを取った場合に解ける問題の数を計算します。$x$問題。 これを多くの人に再利用するので、$k$、ソートされた難易度に対してプレフィックスの合計を使用して事前計算します。 
3. 特に Kevin の場合、解決された数をサイズのグループで扱います。$k$選択された問題の数によってのみ決定されます$\le a_1$。 構築された各ブロックでそのような問題がいくつ発生するかを追跡します。 
4. 固定の場合$k$、次のことを観察してください。$m$問題は次のように分割されます$\lfloor m/k \rfloor$ソートされた困難を乗り越えて最適な配置で連続したブロックを配置します。 各ブロックは独立して Kevin の合計ランクに貢献します。 
5. ブロックごとに、Kevin のランクを次のように計算します。$1 +$評価がブロック内の問題数を超える参加者の数$\le a_1$。 これは、並べ替えられた評価に対する二分検索を使用して計算されます。 
6. それぞれの貢献度を蓄積する$k$複数のループを使用する: 各ブロックのサイズ$k$その答えに貢献します$k$。 テスト ケースごとに 1 回、並べ替えられた配列をスイープすることで寄与を集計します。 
7. すべての累積合計を出力します。$k = 1 \ldots m$。 

### なぜ効果があるのか

 核となる不変条件は、固定されたものに対する不変条件です。$k$、問題の最適な選択は、問題の正確な位置ではなく、各ブロック内の問題の難易度の分布のみが重要となる構造に変換できます。 参加者のパフォーマンスはしきい値を下回るカウントのみに依存するため、ブロック サイズを変更せずに問題を再配置しても正確さには影響しません。 これにより、組み合わせ選択空間をソートされたデータ上の決定論的なブロックに圧縮することができ、各ブロックが独立して固定ランク値に寄与します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    a.sort()
    b.sort()

    # prefix where we can count how many problems <= threshold
    ans = [0] * (m + 1)

    # For each k, we simulate taking blocks of size k
    # We precompute how many problems are <= each rating using two pointers

    # For each possible block start, compute contribution
    # We treat each k separately but optimize by reusing pointer movement

    for k in range(1, m + 1):
        full = m // k
        res = 0

        # pointer in problems
        idx = 0

        for _ in range(full):
            # take next k problems
            cnt = 0
            for j in range(k):
                if b[idx + j] <= a[0]:
                    cnt += 1

            idx += k

            # Kevin rank: count participants with more solved problems
            # that is, rating > threshold equivalent
            # participants sorted -> use binary search
            import bisect
            worse = len(a) - bisect.bisect_right(a, a[0])

            res += 1 + worse

        ans[k] = res

    print(*ans[1:])

t = int(input())
for _ in range(t):
    solve()
```この実装は、ソートされた問題をサイズの連続したブロックにグループ化するという考えに従っています。$k$。 ブロックごとに、ケビンの成績は、そのブロック内にある問題の最大数が彼の評価に達するかどうかによって決まります。 次に、ソートされた評価に対する二分探索を使用して、何人の参加者が彼に勝ったかを計算します。 

主な微妙な点は、常にブロックを一貫して考慮することです。ブロック間で問題が混在すると、難易度の順序付けが単調になるため、ケビンのランクが悪化するか、同等に保たれるだけになるからです。

 ## 特殊なケース

 すべての評価がすべての難易度に等しい場合、すべての参加者はすべてのコンテストで同じ数の問題を解決します。 厳密にケビンを超える人はいないため、アルゴリズムはすべてのコンテストでケビンに正しくランク 1 を生成します。 

すべての難易度が厳密に増加し、評価が低い場合、ケビンの解決数は多くのブロックにわたってゼロのままです。 ランク付けは純粋に参加者の数に依存し、グループ化によって順序が変更されることはなく、ブロック構造によって比較が歪められないことが確認されます。 

いつ$k = m$、コンテストは 1 つだけあり、アルゴリズムはすべての問題に対する単一の評価に縮退し、予想される境界動作と一致します。
