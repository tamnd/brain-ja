 ## 解決策
 ## 問題の理解

 バイナリ文字列が与えられます`s`で構成されています`0`と`1`s. ケビンは特別な操作を繰り返し実行できます: 位置を選択します`p`、その前のすべての文字をそれ自体の最大値と次の文字に置き換え、位置にある文字を削除します`p`。 正式には、`1 ≤ i < p`、 セット`t_i = max(t_i, t_{i+1})`、削除します`t_p`。 目標は、このような操作を任意の回数実行した後に生成できる、空ではない個別の文字列の総数を決定することです。 

入力には複数のテスト ケースが含まれており、それぞれの長さは次のとおりです。`10^6`。 すべてのテスト ケースの長さの合計は次のように制限されます。`10^6`。 出力は、個別の文字列のモジュロ数です。`998244353`。 

制約は、一定の長さの文字列に対して、すべての操作のブルートフォース シミュレーションが不可能であることを意味します。`n`、あるかもしれない`O(2^n)`欠失の順序が異なるため、指数関数的なアプローチは実行不可能になります。 このため、組み合わせプログラミングまたは動的プログラミングのアプローチを探す必要があります。 エッジ ケースには、すべて 0 またはすべて 1 の文字列が含まれます。 例えば、`0000`はゼロの部分文字列のみを生成できますが、`1111`最大演算により潜在的に維持されるため、より多くの組み合わせがあります`1`前にいます。 

## アプローチ

 単純なアプローチでは、考えられるすべての選択肢をシミュレートしようとします。`p`再帰的に、結果として得られるすべての文字列を追跡します。 これは原理的には正しいですが、操作の数は文字列の長さに応じて指数関数的に増加します。 最大の入力サイズの場合 (`n = 10^6`）、乱暴に扱う必要があるため、これは剪定を行っても実行できません。`2^n`可能性。 

重要な観察点は、操作が単調であるということです。 どれでも`0`の左側にある`1`に変えることができます`1`このプロセスによって、ただし一度だけ`1`と表示されると元に戻せません`0`。 これは、個別の文字列が主に ** 連続した文字列の実行によって決定されることを示唆しています。`1`文字列内の s**。 具体的には、連続するすべてのブロックが、`1`s は独立して動作します。要素を削除する方法の数によって、生成できる個別の部分文字列の数が決まります。 

詳しく見ると、個別の文字列の数が、空ではない連続する 1 の部分列の数と、先行する 0 との組み合わせに対応していることがわかります。 これにより、動的プログラミングを使用してこれらのシーケンスを効率的にカウントするという問題が軽減されます。 連続するブロックごとに`1`s では、以前の計算によって拡張できる方法が何通りあるのかを追跡します。 これにより、文字列の長さの線形時間アルゴリズムが実現します。

 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(2^n) | 遅すぎる |
 | 連続DP`1`s | O(n) | O(1) または O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. カウンタを初期化する`res = 0`個別の文字列の総数を保存します。 
2. 文字列を反復処理し、連続するシーケンスを追跡します。`1`s. させて`current_ones`現在の長さになります`1`走る。 
3. それぞれについて`0`見つかった場合、または文字列の最後に、1 の連続によって生成される個別の部分文字列の数を追加します。 長いランの場合`k`、 がある`(k*(k+1))/2`空ではない連続したサブシーケンス。 
4.アップデート`res`これらのカウントでは、モジュロの処理に注意してください`998244353`。 
5. 次の実行に進みます。`1`文字列の終わりまで。 
6. 文字列全体を処理した後、必要に応じて空の文字列を追加するか、問題が空でない文字列のみをカウントする場合は無視します。 
7. 各テストケースの結果を出力します。 

**なぜ機能するのか**: 不変条件は、個別の文字列が次の位置によって決定されるということです。`1`として、`0`のみに変換できます`1`彼らの左側にあります。 連続する 1 のシーケンスを数え、それらを前の部分文字列と組み合わせることで、許可された操作を通じて取得できるすべての可能な個別の文字列を考慮します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    t = int(input())
    for _ in range(t):
        s = input().strip()
        n = len(s)
        res = 0
        i = 0
        while i < n:
            if s[i] == '1':
                length = 0
                while i < n and s[i] == '1':
                    length += 1
                    i += 1
                # Number of non-empty contiguous subsequences of this block
                res += length * (length + 1) // 2
                res %= MOD
            else:
                i += 1
        print(res % MOD)

if __name__ == "__main__":
    solve()
```このソリューションは、1 の実行をカウントしながら文字列を反復処理します。 実行ごとに、そのブロックから取得できる個別の文字列に対応する連続サブシーケンスの合計数が計算されます。 モジュラー演算を使用すると、結果が制限内に収まります。

## 特殊なケース

 ゼロのみを含む文字列、例:`000`、明確な空でない文字列は生成されません。 このアルゴリズムはゼロを正しくスキップし、カウントを追加しません。 のために`111`の場合、アルゴリズムは長さ 1、2、および 3 の連続したサブシーケンスをカウントし、合計すると 6 になります。`10101`それぞれを処理して対処します`1`別々に実行して、二重カウントを回避します。 モジュラー演算により、結果が範囲内に収まることが保証されます。`998244353`大きな文字列でも。 

このアプローチは、入力サイズに比例してスケールし、Kevin の操作を通じて導出できるすべての個別の文字列を正確にカウントします。
