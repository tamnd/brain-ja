 ## 解決策
 ## 問題の理解

 ラテン文字の大文字の入力文字列にシーザー暗号を実装するように求められます。 概念的には、これは各文字が _k_ で示される固定位置数だけアルファベット内で前方にシフトされることを意味します。 シフトが「Z」を超えると、「A」に戻ります。 たとえば、シフトを 3 にすると、「X」は「A」、「Y」は「B」、「Z」は「C」になります。 

入力は 1 ～ 10 文字の長さの文字列で構成されるため、非常に小さいデータセットが保証されます。 2 行目は 0 ～ 25 の整数 _k_ で、シフトにアルファベットの複数サイクルが必要ないことを意味します。 出力は、すべての文字にシーザー暗号を適用した後の変換された文字列である必要があります。 

微妙なエッジ ケースは、文字がアルファベットの終わり近くにあり、_k_ が文字を「Z」を超えて押し出すときに発生します。 たとえば、入力の場合`"XYZ"`そして`k = 5`、期待される出力は次のとおりです`"CDE"`。 ラップせずに単に各文字の ASCII 値に _k_ を追加する単純なアプローチでは、「Z」を超える無効な文字が与えられてしまいます。 もう一つのエッジケースは、`k = 0`、文字列は変更されないままにする必要があります。 

## アプローチ

 ブルートフォース手法は単純です。各文字を反復処理し、アルファベット内の位置に対応する 0 ～ 25 の数値に変換し、_k_ を追加して、モジュロ 26 を使用してラップアラウンドします。これが機能するのは、アルファベットのサイズが固定されており、ASCII 算術を使用して文字を簡単に整数にマップできるためです。 長さが _n_ の文字列の場合、このアプローチでは正確に _n_ 回の操作が必要になります。この場合、操作数は最大 10 です。パフォーマンスの問題はありません。 「ブルート フォース」は、制約を考慮すると本質的に最適です。 

すべてを単純化する観察は、モジュロ演算が本質的にラップアラウンドを処理するということです。 具体的には、「A」を 0、「B」を 1、...、「Z」を 25 にマッピングすると、次のようになります。`(index + k) % 26`正しいシフトされたインデックスが生成されます。 このモジュロ演算が必要な唯一の重要な洞察です。 文字ではなく数値インデックスの観点から考えると、問題は単純な配列変換に帰着します。

 ## アルゴリズムのチュートリアル

 1. 入力文字列と整数シフト _k_ を読み取ります。 文字列は一連の文字として扱われ、_k_ は 0 ～ 25 の範囲内であることが保証されます。 
2. 結果の文字を保持する空のリストを初期化します。 文字列を段階的に構築する代わりにリストを使用すると、文字列が不変である言語での二次時間計算量を回避できます。 
3. 入力文字列内の各文字を繰り返し処理します。 「A」の ASCII 値を減算して、文字を 0 ～ 25 のインデックスに変換します。 これにより、算術に適した数値表現が得られます。 
4. _k_ を追加し、モジュロ 26 を取得して、シフト後の新しいインデックスを計算します。モジュロにより、シフトが 'Z' から 'A' に正しく折り返されることが保証されます。 
5. ASCII 値「A」を追加して新しいインデックスを文字に変換し、結果リストに追加します。 
6. 文字のリストを 1 つの文字列に結合し、出力します。 

機能する理由: このアルゴリズムは、文字から数値インデックスへの一貫したマッピングを維持し、26 を法とする閉数値系でシフトを適用し、文字にマッピングし直します。 不変条件は、すべての文字のインデックスが常に 0 ～ 25 の間にあることです。そのため、モジュロ演算により、小さなシフトと境界シフトの両方の正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

s = input().strip()
k = int(input())

result = []

for char in s:
    index = ord(char) - ord('A')
    new_index = (index + k) % 26
    result.append(chr(new_index + ord('A')))

print(''.join(result))
```コードは最初に文字列とシフトを読み取り、余分な改行文字を取り除きます。 次に、各文字を反復処理して、ゼロから始まるインデックスに変換します。 _k_ を追加し、モジュロ 26 を取得すると、ラップアラウンドが正しく処理されるようになります。 最後に、シフトされた各インデックスを文字に変換して戻し、出力文字列を組み立てます。 使用する`ord`そして`chr`文字インデックスのマッピングは標準であり、off-by-one エラーを避けるために操作の順序が慎重に調整されています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    s = sys.stdin.readline().strip()
    k = int(sys.stdin.readline())
    result = [chr((ord(c) - ord('A') + k) % 26 + ord('A')) for c in s]
    return ''.join(result)

# Provided samples
assert run("CODEFORCES\n5\n") == "HTIJKTWHJX", "sample 1"

# Minimum-size input
assert run("A\n0\n") == "A", "min size, no shift"

# Maximum-size input
assert run("ABCDEFGHIJ\n25\n") == "ZABCDEFGHI", "max size, wrap-around"

# All-equal letters
assert run("ZZZZZ\n1\n") == "AAAAA", "all Zs wrap to A"

# Boundary shift
assert run("XYZ\n5\n") == "CDE", "wrap-around near end"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | A\n0 | あ | 最小長、ゼロシフト |
 | ABCDEFGHIJ\n25 | ZABCDEFGH | 最大長、ほぼフルシフト |
 | ZZZZZ\n1 | ああああ | すべての文字は Z から A に折り返されます。 
| XYZ\n5 | CDE | 境界の回り込み |

 ## 特殊なケース

 入力用`"XYZ"`と`k = 5`、数値インデックスは 23、24、25 です。5 を加算すると 28、29、30 が得られ、26 を法とする結果は 2、3、4 になります。これらを文字にマッピングし直すと、次のようになります。`"CDE"`。 このアルゴリズムは、特別な分岐や条件なしでアルファベットの終わりに近い文字を正しく処理し、モジュロ演算がエッジの折り返しを完全に管理していることを確認します。
