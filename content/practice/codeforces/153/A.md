 ## 解決策
 ## 問題の理解

 2 つの整数の合計を計算するように求められますが、出力の形式を注意深く設定することに重点が置かれています。 具体的には、入力は 2 つの数値で構成され、それぞれが独自の行にあり、先頭にゼロを付けずにそれらの合計を出力する必要があります。 これは、たとえ合計が次のような場合でも、ということを意味します。`00015`、出力する必要があります`15`。 

制約は単純です。どちらの整数も 1 ～ 100,000 です。 これらの境界は十分小さいため、Python での整数のオーバーフローを心配する必要はありません。また、合計は常に 200,000 以下になります。 入力サイズは小さいため、適切なアルゴリズムはマイクロ秒以内に実行されます。 課題は効率ではなく正確さです。 

明らかではないエッジケースは、入力が文字列として誤って解釈される可能性から発生します。 たとえば、1 つの数字があったとします。`"00012"`(A と B は正の整数であるため、技術的には入力制約の範囲外ですが、問題のバリエーションで現れる可能性があります)、不注意な文字列の連結または出力により、`"00015"`の代わりに`"15"`。 別のシナリオは、合計自体が正確に次のとおりである場合です。`100000`または、出力が数値であり、先頭のゼロが取り除かれているかどうかを再度テストする境界値。 

## アプローチ

 単純なアプローチでは、数値を文字列として扱い、それらを整数に変換し、加算して、結果を出力します。 これが機能するのは、Python が任意の大きな値まで整数演算を正しく処理するためです。 入力範囲が小さく、Python 整数が自動的に繰り越しを管理するため、加算を桁ごとに手動で実装する必要はありません。 ブルート フォース シナリオでは、各桁を最下位から最上位まで繰り返して手動で合計することもできますが、これは不必要に冗長になり、エラーが発生しやすくなります。 

重要な観察点は、Python の組み込み`int`type は、文字列から数値を解析することと、文字列に戻すときに先頭のゼロを削除することの両方をすでに処理しています。`print`。 したがって、最適なアプローチは、単純に各数値を読み取り、それを整数に変換し、合計し、結果を出力することです。 配列、ループ、または追加のチェックは必要ありません。 総当たりアプローチは、大きな整数のサポートがない仮想言語では「遅すぎる」だけですが、ここでは事実上最適です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 手動による桁ごとの加算 | O(log(最大(A,B))) | O(log(最大(A,B))) | 不必要、冗長 |
 | Python 組み込み算術演算 | お(1) | お(1) | 受け入れられ、シンプルで正しい |

 ## アルゴリズムのチュートリアル

 1. 入力の最初の行を読み取り、それを整数に変換します。 これにより、入力に先行ゼロが存在する場合でも、それが自動的に無視されます。 
2. 入力の 2 行目を読み取り、同じ理由で整数に変換します。 
3. 2 つの整数の合計を計算します。 
4. 合計を直接出力します。 の`print`関数は、整数を文字列に変換します。デフォルトでは、先頭のゼロは含まれません。 

これが機能する理由: ここで不変なのは、すべてのステップで真の整数値を操作するということです。 文字列から整数に即座に変換することで、先頭のゼロから曖昧さを取り除きます。 2 つの正の整数の合計は常に正の整数を生成し、Python で整数を出力すると先頭にゼロがないことが保証され、問題の要件と正確に一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

A = int(input())
B = int(input())
print(A + B)
```最初の 2 行は入力を読み取り、それを整数に変換します。 この変換では、偶発的な先行ゼロの削除が自動的に処理されます。 最後の行では合計を計算して出力します。 問題ではループや条件が必要ないため、ループや条件はありません。 入力サイズが非常に小さいため、このコードは時間とメモリの制限内で十分に実行されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    A = int(input())
    B = int(input())
    return str(A + B)

# provided sample
assert run("12\n3\n") == "15", "sample 1"

# minimum input
assert run("1\n1\n") == "2", "minimum input"

# maximum input
assert run("100000\n100000\n") == "200000", "maximum input"

# mixed size inputs
assert run("100\n5\n") == "105", "small and small input"

# edge case for output without leading zeros
assert run("00012\n00003\n") == "15", "leading zeros input"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 12\n3 | 15 | 正規和 |
 | 1\n1 | 2 | 最小入力値 |
 | 100000\n100000 | 200000 | 最大入力値 |
 | 100\n5 | 105 | 小さな値が混在 |
 | 00012\n00003 | 15 | 先頭にゼロを付けて入力します。 

## 特殊なケース

 先頭に偶発的なゼロが含まれる入力の場合、次のようになります。`"00012"`そして`"00003"`の場合、アルゴリズムは両方をすぐに整数に変換します。 Python インタープリタ`"00012"`12 と`"00003"`合計は 15 として計算され、先頭のゼロなしで出力されます。 入力形式が特殊な場合でも、内部変換により正確さが保証されます。 境界値 1 と 100,000 により、整数のオーバーフローやフォーマットミスが発生しないことが確認されます。
