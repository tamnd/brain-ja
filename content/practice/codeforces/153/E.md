 ## 解決策
 ## 問題の理解

 2D 平面上には最大 50 点が与えられます。 各点は整数の座標を持ち、いくつかの点が一致する場合があります。 タスクは、任意の点のペア間の最大ユークリッド距離を見つけることです。 

2点の場合$(x_1, y_1)$そして$(x_2, y_2)$、ユークリッド距離は次のとおりです。$d=\sqrt{(x_1-x_2)^2+(y_1-y_2)^2}$点をドラッグして 2 点間の距離を更新します。-10-8-6-4-2246810-10-5510A(6.0, 6.0)B(-6.0, -6.0)d = 16.97Delta x = 12Delta y = 12

 各座標が独自の行で指定されるため、入力形式は少し特殊です。 読んだ後`n`、私たちは読みます`2n`追加行: 1 行`x`、 1つ`y`、ポイントごとに繰り返されます。 

制約は非常に小さいです。 わずか 50 ポイントの場合、ペアの合計数は最大でも次のようになります。$\frac{50\cdot49}{2}=1225$2 秒の制限としては非常に小さいです。 たとえ$O(n^2)$アルゴリズムは数千回の距離計算のみを実行しますが、これは簡単です。 

主な危険はパフォーマンスではなく、正確さと正確さです。 

簡単な間違いの 1 つは、ユークリッド距離には平方根が使用されることを忘れることです。 不用意に実装すると、二乗距離が最大化され、それが直接出力される可能性があります。

```なぜなら：$\sqrt{3^2+4^2}=5$印刷`25`むしろ間違っているでしょう。 

もう 1 つの微妙なケースは、重複ポイントです。```

```2 つの点は同一であるため、それらの距離はゼロです。 正しい最大距離は次のとおりです。`(1,1)`そして`(4,5)`。 

すべてのポイントが個別であると仮定するバグのある実装では、誤って有効な比較をスキップしたり、インデックス付けを誤って処理したりする可能性があります。 

浮動小数点出力フォーマットも問題の一般的な原因です。 判定者は小さな誤差許容を受け入れるため、標準の浮動小数点精度で出力するだけで十分ですが、整数の除算や切り捨ては失敗します。 

## アプローチ

 最も直接的な解決策はブルートフォースです。 すべての点のペアをチェックし、それらの間のユークリッド距離を計算し、これまでに確認された最大値を維持します。 

これは、答えが文字通りすべてのペアの最大値として定義されるため機能します。 すべてのペアを一度だけ正確に検査すれば、最適なペアを見逃すことはありません。 

ブルート フォース アルゴリズムは次のことを実行します。$O(n^2)$距離の計算。 と`n = 50`、これは最大 1225 ペアを意味しますが、これは無視できる程度です。 

制約が大きい場合、このアプローチには問題が生じる可能性があります。 もし`n`だった$10^5$、ペアごとのチェックには大まかに必要になります$10^{10}$制限時間内では不可能な操作。 これらの設定では、最も遠いペアが凸包上に存在する必要があるため、凸包や回転キャリパーなどの計算幾何学的手法が必要になります。 

この問題にはそれらの最適化は必要ありません。 制約は意図的に十分に小さくされているため、実際には単純なペアごとの解決策がすでに最適化されています。 重要な点は、より高度なジオメトリ アルゴリズムを構築しようとすると、複雑さが増すだけで何のメリットもないということです。

 | ジオメトリの最適化 | O(n log n) | O(n) | 不要 |

 ## アルゴリズムのチュートリアル

 1. 整数を読み取る`n`。 
2. すべてのポイントをリストに読み込みます。`(x, y)`ペア。 
3. 変数を初期化する`best = 0.0`。 
4. すべてのインデックスのペアを反復処理します。`(i, j)`と`i < j`。 
5. 各ペアについて、座標の差を計算します。$dx=x_i-x_j$

$dy=y_i-y_j$6. ユークリッド距離を計算します。$d=\sqrt{dx^2+dy^2}$7.アップデート`best`この距離がもっと大きい場合。 
8. すべてのペアが処理された後、印刷します。`best`。 

### なぜ効果があるのか

 このアルゴリズムは、考えられるすべての点のペアの距離を明示的に評価します。 答えの定義はすべてのペア間の最大距離であるため、反復中に最適なペアが現れることが保証されます。 より大きな距離が見つかるたびに、`best`が更新されます。 ループが終了したら、`best`はペアの完全なセットにわたる最大距離に等しく、これはまさに必要な答えです。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

# solution
def solve():
    n = int(input())
    
    points = []
    for _ in range(n):
        x = int(input())
        y = int(input())
        points.append((x, y))
    
    best = 0.0
    
    for i in range(n):
        x1, y1 = points[i]
        
        for j in range(i + 1, n):
            x2, y2 = points[j]
            
            dx = x1 - x2
            dy = y1 - y2
            
            dist = math.sqrt(dx * dx + dy * dy)
            best = max(best, dist)
    
    print(best)

if __name__ == "__main__":
    solve()
```最初のセクションでは、すべてのポイントをリストに読み込みます。 座標は別々の行に分割されるため、ポイントごとに 2 つの整数を読み取り、それらをタプルとしてまとめて保存します。 

ネストされたループは、順序付けされていないペアをすべて 1 回だけ列挙します。 使用する`j`から`i + 1`次のような重複した比較を回避します`(A,B)`そして`(B,A)`、また、点とそれ自体の比較もスキップします。 

距離の計算では、平方根を求める前に差の二乗を使用します。 座標は十分小さいため、Python ではオーバーフローは不可能ですが、二乗項を直接使用することで、最終ステップまで不必要な浮動小数点演算を回避できます。 

答えの変数は次から始まります`0.0`距離は負ではないからです。 計算されたすべての距離が現在の最大値と比較されます。 

最後の print ステートメントでは、Python のデフォルトの浮動小数点書式設定が使用されており、審査員の許容要件を満たす十分な精度がすでに提供されています。
