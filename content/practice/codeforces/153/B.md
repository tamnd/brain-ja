 ## 解決策
 ## 問題の理解

 単一の正の整数が与えられ、その表現を基数 2 で出力する必要があります。言い換えれば、数値を 2 のべき乗として表現し、対応するビットのシーケンスを出力したいと考えています。 

たとえば、10 進数の 13 は次と等しくなります。$13 = 1\cdot2^3 + 1\cdot2^2 + 0\cdot2^1 + 1\cdot2^0$したがって、そのバイナリ表記は次のようになります`1101`。 

制限は非常に小さいです。 の値`n`これは、次の理由により、バイナリ表現に含まれるビット数が最大 20 ビットであることを意味します。$2^{20}=1048576$合理的なアルゴリズムであれば、制限時間内に簡単に収まります。 数値を繰り返し 2 で割るアプローチでも、反復は約 20 回しか実行されません。 

難しいのはパフォーマンスではなく、フォーマットに関する正確さです。 

よくある間違いの 1 つは、ビットを逆の順序で出力することです。 2 で除算を繰り返すと、最下位から最上位のビットが得られます。 すぐに印刷すると答えが逆になります。 

たとえば:

 入力:```
5
```残りは次の順序で表示されます。 

| 現在の n | n%2 |

 |---|---|---|

 | 5 | 1 |

 | 2 | 0 |

 | 1 | 1 |

 直接印刷すると、次のようになります。`101`上から下ではなく、下から上へ。 

もう 1 つの間違いは、先行ゼロを生成することです。 2 進数表記は、設定された最上位ビットから始める必要があります。 

たとえば:

 入力:```
1
```正しい出力:```
1
```不用意に固定幅を実装すると、次のようなメッセージが出力される可能性があります。`00000001`、これは許可されていません。 

3 番目のエッジ ケースは、最小の数値を正しく処理することです。 ループ条件が正しく記述されていない場合、プログラムは空の文字列を生成する可能性があります。`n = 1`。 

入力：```
1
```正しい出力:```
1
```アルゴリズムは、少なくとも 1 ビットが出力されることを保証する必要があります。 

## アプローチ

 最も直接的なアイデアは、2 進数表記の定義をシミュレートすることです。 すべての 2 進数は、特定の 2 のべき乗が数値の分解に関与しているかどうかを示します。 

ブルートフォース手法では、2 の累乗を大きい値から小さい値までチェックします。 ポジションごとに、そのパワーが残りの値に適合するかどうかを判断します。 そうであれば、出力します`1`そしてそれを差し引きます。 それ以外の場合は出力します`0`。 

たとえば、`13`:$13 = 8 + 4 + 0 + 1$ビットは次のようになります`1101`。 

バイナリ表記はまさに 2 のべき乗への分解であるため、この方法は正しいです。 問題は、最初に関連する最大の電力を決定する必要があることです。 べき乗を繰り返したり、多くの不必要な位置をスキャンしたりして単純に実装すると、そのような単純なタスクに対してコードは不格好になります。 

2 進数がどのように形成されるかをより明確に観察できます。 最下位ビットは 2 で割ったときの余りに等しくなります。$n = 2q + r,\quad r\in\{0,1\}$残り`r`は正確に現在の 2 進数です。 抽出した後、数値を 2 で割って商を続けます。 

たとえば、から始めて、`13`:

 | n | n%2 | n // 2 |
 | --- | --- | --- |
 | 13 | 1 | 6 |
 | 6 | 0 | 3 |
 | 3 | 1 | 1 |
 | 1 | 1 | 0 |

 ビットは逆の順序で表示されます。`1011`。 それらを逆にすると、`1101`。 

このアプローチは、各反復で 1 つの 2 進数が削除されるため、最適です。 100 万までの数値は約 20 ビットしかないため、アルゴリズムはほぼ瞬時に終了します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(log n) | お(1) | 承認済み |
 | 最適 | O(log n) | O(log n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 整数を読み取る`n`。 
2. 空のリストを作成する`bits`2進数を保存します。 
3. その間`n > 0`、次の操作を行います。 

1. コンピューティング`n % 2`。 
2. この余りを次のように追加します。`bits`。 
3. 交換する`n`と`n // 2`。 

剰余は、現在の最下位 2 進数を示します。 整数の除算では、その桁が削除され、数値が 1 ビット右にシフトされます。 
4. リストを反転します`bits`。 

数字は最下位から最上位の順に生成されるため、逆にすると適切な順序が復元されます。 
5. 数字を文字列に結合し、結果を出力します。 

### なぜ効果があるのか

 反復のたびに、アルゴリズムは、収集された剰余と現在の値から元の数値を再構築できるという不変条件を維持します。`n`。 

現在の値が`n`。 私たちはこう書きます：$n = 2\left\lfloor\frac{n}{2}\right\rfloor + (n\bmod 2)$余りは常にどちらかです`0`または`1`、これは 2 進数と正確に一致します。 この数字を記録した後、商を続けます。 このプロセスを繰り返すと、すべての 2 進数が右から左に抽出されます。 収集した数字を反転すると、標準の左から右への 2 進表記が復元されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())

bits = []

while n > 0:
    bits.append(str(n % 2))
    n //= 2

bits.reverse()

print("".join(bits))
```プログラムは、標準入力から整数を読み取ることから始まります。 

リスト`bits`バイナリ数字を文字列として保存します。 それらを文字列として保存すると、出力構築中の追加の変換ステップが即座に回避されます。 

ループ内では、`n % 2`現在の最下位ビットを抽出します。 それから`n //= 2`数値からそのビットを削除します。 ループは数値がゼロになるまで継続します。 

操作の順序が重要です。 割る前に余りを記録しなければなりません。 これら 2 つの行を反転すると、現在のビットが失われます。 

ループの後、数字は右から左に収集されるため、逆になります。 ついに、`"".join(bits)`出力を効率的に構築します。 

条件`while n > 0`問題が保証されているため、正しく動作します`n ≥ 1`。 ゼロが許可されている場合、ループは実行されないため、特別な処理が必要になります。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    import sys
    input = sys.stdin.readline

    n = int(input())

    bits = []

    while n > 0:
        bits.append(str(n % 2))
        n //= 2

    bits.reverse()

    print("".join(bits))

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out

# provided sample
assert run("5\n") == "101\n", "sample 1"

# minimum value
assert run("1\n") == "1\n", "minimum input"

# power of two
assert run("8\n") == "1000\n", "single leading 1"

# alternating bits
assert run("10\n") == "1010\n", "checks ordering of bits"

# maximum constraint neighborhood
assert run("1000000\n") == bin(1000000)[2:] + "\n", "large input"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1`|`1`| 最小の有効な入力 |
 |`8`|`1000`| 2 の累乗の正しい処理 |
 |`10`|`1010`| 数字は正しい順序で表示される必要があります。 
|`1000000`|`11110100001001000000`| 制約限界に近い大きな入力 |
