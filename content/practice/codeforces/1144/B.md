 ## 解決策
 ## 問題の理解

 整数のシーケンスが与えられ、前回の削除に依存するパリティ制約の下で要素を 1 つずつ削除できます。 最初に削除される要素は何でも構いません。 その後、削除するたびに、最後に削除した要素と比較してパリティを交互にする必要があります。偶数を削除したばかりの場合、次の要素は奇数でなければならず、その逆も同様です。 この代替ルールを満たす有効な要素が存在しなくなると、プロセスはすぐに停止します。 

目標は、削除する要素の数を最大化することではなく、行き詰まったときに配列内に残る要素の合計を最小化することです。 すべての削除は無料であり、スコアは残り物の合計であるため、パリティ代替制約を尊重しながら、できるだけ大きく価値のある要素のサブセットを削除したいと考えています。 

重要な制約は、各移動が、その値や位置ではなく、最後に削除された要素のパリティのみに依存するということです。 これにより、問題の構造が大幅に軽減されます。つまり、パリティが交互に現れる一連の削除を効果的に構築しており、削除の合計の重みを最大化したいと考えています。 

配列サイズは最大 2000 であり、すべての削除順序の指数関数的なシミュレーションが除外されます。 三次またはそれより悪いアプローチは失敗する可能性があります。 ただし、O(n^2) または O(n^2 log n) の解は実行可能です。 これは、すべてのシーケンスを探索するのではなく、パリティ グループごとに最適な選択を推論できる可能性が高いため、貪欲またはソートベースの構造を強く示唆しています。 

最適な戦略が削除数を最大化することではなく、どのパリティ チェーンから開始するかを慎重に選択することである場合、微妙な失敗例が発生します。 たとえば、非常に小さな開始要素を選択すると、後でより大きな要素を削除する、より優れた交互チェーンのロックが解除される可能性があります。 「常に当面の最善の選択から始める」ことを前提としたアプローチは安全ではありません。 

## アプローチ

 ブルートフォース解釈では、考えられるすべての削除シーケンスをシミュレートします。 どの状態からでも、逆パリティの有効な次の要素を選択し、スタックするまで続行します。 各パスは候補残余合計を生成します。 ただし、各ステップで多くの有効な要素の中から選択する可能性があるため、最悪の場合、可能なシーケンスの数は階乗になります。 順序が依然として重要であり、同じサブセットが多くの順序で到達する可能性があるため、パリティによる枝刈りでも十分な効果はありません。 

重要な観察は、要素の実際のアイデンティティは、そのパリティと値以外には重要ではないということです。 残りの合計を最小化しているので、削除された合計を最大化したいと考えています。 この制約は交互を強制するだけです。つまり、有効な削除シーケンスは、単に選択された要素の交互シーケンスです。 パリティが交互に存在する限り、削除の順序を任意に変更できるため、偶数要素と奇数要素をいくつ取り、どのような交互構造にするかを決定するだけで済みます。 

重要な単純化は、すべての要素を並べ替えることを考慮することです。 特定の数の偶数と奇数を交互に取得することにした場合、選択した要素をより小さい要素と交換しても実現可能性が損なわれることはなく、目的が向上するため、常に各パリティの利用可能な最大の要素を取得する必要があります。 

これにより、問題は開始パリティを選択し、貪欲に交互に行われ、一方の側がなくなるまで必要なパリティの残りの最大要素を常に消費するようになります。 両方の開始パリティを試して、最良の結果を取得します。

 ## アルゴリズムのチュートリアル

 数値を偶数と奇数に分割し、両方のグループを降順に並べ替えて、常に最も価値のある削除を最初に考慮します。

1. パリティ、偶数、奇数に基づいて配列を 2 つのリストに分割します。 ゲームのルールは順位ではなくパリティ遷移のみに依存するため、これが必要です。 
2. 両方のリストを降順に並べ替えます。 これにより、パリティ クラスから選択するときは必ず最大の残りの要素が取得され、ローカルで削除された要素の合計が最大化されます。 
3. 偶数要素から開始する貪欲な削除プロセスをシミュレートします。 偶数リストと奇数リストへの 2 つのポインターを保持します。 ピックは交互に行います。偶数を取った後は奇数を取り、その逆も同様です。 
4. リストが 1 つなくなるまで交互に繰り返します。 その時点で、それ以上有効な手は存在しないため、プロセスは終了します。 このシミュレーションで取得されたすべての要素の合計を計算します。 
5. 最初に奇数の要素から始めて同じプロセスを繰り返します。 これは、最初の動きには制限がなく、チェーン全体に強い影響を与えるという事実を説明しています。 
6. 答えは、すべての要素の合計から 2 つのシミュレーションから得られた最大合計を引いたものです。 

これが機能する理由: 開始パリティが固定されると、プロセスは決定論的な交互のウォークを強制され、各ステップで唯一の自由はそのパリティのどの要素を取るかです。 必要なパリティの利用可能な最大の要素を常に選択するため、何らかの偏差が発生しても、実現可能性に影響を与えることなく、選択した要素がより小さい要素に置き換えられます。 これにより、目的を厳密に改善または維持しながら有効性が維持されるため、各固定開始パリティ内で貪欲な選択が最適になります。 両方の開始パリティの最大値を取ると、すべての有効なシーケンスがカバーされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def simulate(evens, odds, start_even):
    i = j = 0
    take_even = start_even
    total = 0

    while True:
        if take_even:
            if i >= len(evens):
                break
            total += evens[i]
            i += 1
        else:
            if j >= len(odds):
                break
            total += odds[j]
            j += 1
        take_even = not take_even

    return total

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    evens = sorted([x for x in a if x % 2 == 0], reverse=True)
    odds = sorted([x for x in a if x % 2 == 1], reverse=True)

    total_sum = sum(a)

    best_take = max(
        simulate(evens, odds, True),
        simulate(evens, odds, False)
    )

    print(total_sum - best_take)

if __name__ == "__main__":
    solve()
```この解決策は、問題を 2 つの決定論的な貪欲シミュレーションに減らすことで機能します。 ソートされたパリティ リストにより、パリティ クラスから選択するたびに、ローカルでの寄与が最大化されます。 2 つのランは、制約のない最初の動きを説明します。 

よくある微妙な点は、最初の手が制限されていないことを忘れていることです。そのため、一方を恣意的に修正するのではなく、両方の開始パリティを評価する必要があります。

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    def simulate(evens, odds, start_even):
        i = j = 0
        take_even = start_even
        total = 0
        while True:
            if take_even:
                if i >= len(evens):
                    break
                total += evens[i]
                i += 1
            else:
                if j >= len(odds):
                    break
                total += odds[j]
                j += 1
            take_even = not take_even
        return total

    n = int(input())
    a = list(map(int, input().split()))

    evens = sorted([x for x in a if x % 2 == 0], reverse=True)
    odds = sorted([x for x in a if x % 2 == 1], reverse=True)

    total_sum = sum(a)

    best_take = max(
        simulate(evens, odds, True),
        simulate(evens, odds, False)

    return str(total_sum - best_take)

# edge: single element

# all same parity

# large alternating imbalance

 ## 特殊なケース

 単一要素の配列は単純です。何も移動しないか、最初に要素が削除され、ゲームは直ちに終了し、残りの合計はゼロになります。 

すべての要素が同じパリティを持つ場合は、別の特殊なケースです。 例えば、`[2, 4, 6]`最初の要素を削除した後は、継続する反対のパリティがないため、削除は 1 つだけ許可されます。 パリティ リストの 1 つがすぐに空になるため、アルゴリズムはこれを正しく処理します。そのため、シミュレーションは 1 ステップ後に停止し、残りはそのまま残ります。 

非常に不均衡なパリティ数は、開始パリティが重要である理由を示しています。 偶数が多くオッズが少ない場合、偶数から始めるとすぐにオッズを使い果たす可能性があり、オッズから始めると構造が早く無駄になる可能性があります。 デュアル シミュレーション アプローチにより、両方の可能性が確実に評価され、最大の削除合計が選択されます。
