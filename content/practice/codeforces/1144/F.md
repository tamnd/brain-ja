 ## 解決策
 ## 問題の理解

 次のような接続された無向グラフが与えられます。`n`頂点と`m`エッジ。 私たちのタスクは、結果として得られる有向グラフに長さ 2 以上のパスが含まれないように、すべてのエッジに方向を割り当てることです。 長さ 2 のパスは、単純に 3 つの頂点のシーケンスです。`u → v → w`両端がどこにあるのか`u→v`そして`v→w`有向グラフには存在します。 言い換えれば、有向グラフ内の頂点は、入力エッジと出力エッジの両方を持つことができません。 各頂点は、ソース (出力エッジのみ) またはシンク (入力エッジのみ) のいずれかである必要があります。 

入力グラフは非常に大きくなる可能性があり、最大 200,000 個の頂点と 200,000 個のエッジになります。 これにより、長さ 2 のすべてのパスを検査するだけでも遅すぎるため、すべてのパスを明示的に考慮したり、考えられるすべてのエッジ方向を試したりするアプローチは除外されます。 私たちのソリューションは、おおよそ頂点とエッジの数に比例して線形時間で実行する必要があります。`O(n + m)`。 

問題は微妙な方法で制限されています。 すべてのグラフが「長さ 2 のパスなし」ルールを満たすように方向付けできるわけではありません。 たとえば、グラフに三角形が含まれている場合、どの頂点をソースとして選択しても、他の 2 つの頂点は有向パスを形成するため、そのエッジの向きによって長さ 2 のパスを妨げることはできません。 したがって、そのような配向を可能にするグラフ内の構造を探しており、その構造が不適切である場合を検出する必要があります。 

小さな例は、失敗例を明確にするのに役立ちます。 のような 3 つの頂点のサイクル`1-2-3-1`長さ 2 のパスを形成せずに送信することはできないため、正しい出力は「NO」です。 1 つの中心頂点が多数のリーフに接続されている星形のグラフは、中心をソースまたはシンクにすることで常に方向を指定でき、有効な有向グラフが得られます。 

## アプローチ

 ブルート フォース アプローチでは、エッジの可能な方向をすべて試してから、長さ 2 のパスをチェックします。 各エッジには 2 つの可能な方向があるため、`2^m`可能な方向。 小さなグラフでも、`m = 20`、これにより、100 万を超える可能性が生じます。 長さ 2 のパスの各方向をチェックすると、別のパスが追加されます`O(n + m)`操作。 明らかに、これは不可能です`m`200,000まで。 

重要な洞察は、入力エッジと出力エッジの両方を持つ頂点が存在する場合に限り、長さ 2 のパスが存在することを観察することで得られます。 これは、すべての頂点に役割 (ソースかシンクのいずれか) を割り当てる必要があることを意味します。 この割り当ては、グラフの 2 つの部分に相当します。1 つの部分にはソースが含まれ、もう 1 つの部分にはシンクが含まれます。 入力グラフには方向性がないため、ソースとシンクを表す 2 色で着色することを試みることができます。 グラフが 2 部構成の場合、有効な方向が存在します。つまり、すべてのエッジがソース カラーからシンク カラーに向けられています。 グラフが 2 部構成でない場合は、奇数の長さのサイクルが存在し、どの向きでもどこかに長さ 2 のパスが生成されます。 

二部チェックは、深さ優先または幅優先のトラバーサルを使用して効率的に実行できます。`O(n + m)`時間。 すべての頂点に色を割り当てたら、各エッジを色の低い頂点から色の高い頂点に向けることで、有効なエッジの向きが得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^m * (n+m)) | O(n + m) | 遅すぎる |
 | 二部 DFS/BFS | O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. サイズのカラー配列を初期化します。`n+1`-1 に設定すると、色の付いていない頂点を表します。 ソースには 0、シンクには 1 を割り当てます。 
2. 色付けされていない頂点ごとに、深さ優先検索 (DFS) を実行します。 頂点にアクセスするときは、その頂点にその親の反対の色を割り当てます。 近傍が既に現在の頂点と同じ色を持っている場合、グラフは 2 部構成ではないため、「いいえ」と報告されます。 
3. DFS が競合なしで完了した場合、グラフは 2 部構成になります。 長さの空の結果リストを初期化します。`m`各エッジの方向を保存します。 
4. 各エッジについて`u-v`元の入力順序で、端点の色に基づいて方向を割り当てます。 エッジをソース色の頂点からシンク色の頂点に向けます。 もし`u`はカラー 0 であり、`v`は色 1、result[i] = '0' (u → v) を設定します。 それ以外の場合は、result[i] = '1' (v → u) を設定します。 
5. 「YES」と結果の文字列を出力します。 

機能する理由: DFS は、隣接する頂点が反対の色を持つことを保証します。 各エッジはカラー 0 の頂点をカラー 1 の頂点に接続するため、各頂点は出力エッジ (ソース) のみ、または入力エッジ (シンク) のみになります。 定義上、頂点は入力エッジと出力エッジを同時に持つことができないため、長さ 2 のパスは存在しません。 この不変式により正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(1 << 25)

def main():
    n, m = map(int, input().split())
    edges = []
    graph = [[] for _ in range(n + 1)]
    
    for i in range(m):
        u, v = map(int, input().split())
        edges.append((u, v))
        graph[u].append(v)
        graph[v].append(u)
    
    color = [-1] * (n + 1)
    
    def dfs(u, c):
        color[u] = c
        for v in graph[u]:
            if color[v] == -1:
                if not dfs(v, 1 - c):
                    return False
            elif color[v] == c:
                return False
        return True
    
    for i in range(1, n + 1):
        if color[i] == -1:
            if not dfs(i, 0):
                print("NO")
                return
    
    result = []
    for u, v in edges:
        if color[u] == 0 and color[v] == 1:
            result.append('0')
        else:
            result.append('1')
    
    print("YES")
    print(''.join(result))

if __name__ == "__main__":
    main()
```DFS は、二部性をチェックしながら各頂点を色付けします。 エッジの向きはこのカラーリングを使用して、入力エッジと出力エッジの両方を持つ頂点がないことを保証するため、長さ 2 のパスは存在できません。 次の再帰制限を使用する`1 << 25`ディープ DFS トラバーサルによって Python がクラッシュしないようにします。
