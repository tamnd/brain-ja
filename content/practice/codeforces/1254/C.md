 ## 解決策
 ## 問題の理解

 平面内の隠れた点のセットが与えられ、各点は 1 から n までのインデックスによってのみ識別されます。 座標を見ることはできませんが、3 つの異なるインデックスを含む幾何学的クエリを実行できます。 これらのクエリから、三角形の符号付き面積の 2 倍を取得するか、3 点で形成されるターンの方向を取得できます。 

隠された約束は、これらの点が厳密に凸状の多角形を形成し、正答はまさにその頂点の反時計回り方向の循環順序であるということです。 さらに、頂点 1 は位置 p1 のポリゴン オーダーの一部であることが保証されます。 

タスクは、幾何学的プリミティブと最大 3n 個のクエリのみを使用して、この循環順序を再構築することです。 

インタラクションの構造により、基本的に便利な 2 つのツールが得られます。 面積クエリは、順列の下で一貫した大きさの情報を提供しますが、外積クエリの符号は、アフィン変換の下で不変である方向を与えます。 ただし、クエリ数に制約があるため、ソリューションではジオメトリの完全なペアごとの再構築に似たものを回避する必要があります。 

最も重要な制約は、最大 1000 ポイントの 3n クエリ制限です。 これにより、すべてのペアまたはすべてのトリプルの比較に依存する O(n²) アプローチが即座に排除されます。 O(n² log n) の構築さえ不可能です。 クエリに関しては本質的に線形時間で凸包の順序付けを構築する必要があります。つまり、各ポイントは一定の回数だけ「タッチ」できることになります。 

微妙なエッジケースは、縮退の回避にあります。 この問題では、3 つの点が同一線上にないことが保証されるため、すべての方向クエリは +1 または -1 を返します。 これがなければ、多くの貪欲な船体構造は、タイブレークの曖昧さのために失敗するでしょう。 

もう 1 つの落とし穴は、頂点 1 が一番左または一番下の点であると仮定することです。 そうではない。 唯一の保証は、それが最終循環順序に現れることです。 最初に船体の構造を特定せずに、固定基準の周囲の角度によってポイントを並べ替えようとするソリューションは失敗します。 

## アプローチ

 素朴なアイデアは、距離と面積のクエリを使用して座標を明示的に再構築することです。 ペアごとの距離または正確な三角形の領域を決定できれば、点を埋め込み、標準ジオメトリを使用して凸包を計算できます。 ただし、相対位置を決定するには各点を他の多くの点と比較する必要があるため、座標を再構築するには O(n²) の情報が必要です。 わずか 3n 個のクエリでは、これは不可能です。 

2 番目の単純なアイデアは、基準点を選択し、方向クエリを使用して極角によって他のすべての点を並べ替えることです。 これは意図した構造に近づいていますが、依然として問題があります。並べ替えには O(n log n) の比較が必要であり、各比較にはクエリが含まれます。 これではすでにクエリの予算を超えてしまいます。 

重要な観察は、固定ピボットからの完全な角度順序は必要ないということです。 代わりに、凸包の循環順序のみが必要です。 凸多角形の場合、ローカル構造で十分です。各頂点にはちょうど 2 つの近傍があり、連続するトリプル間の方向条件は一貫しています。 

これは、船体を段階的に構築することを示唆しています。 既知の頂点から開始し、凸性を維持する次の頂点を選択してチェーンを繰り返し拡張します。 各ステップで、部分ハルの最後のエッジに対して候補をテストするだけで済みます。 構造は凸状であるため、正しい次の頂点は単純な方向基準によって一意に決定されます。 

候補チェーンを維持し、方向クエリを使用して無効な遷移を排除できます。 各ポイントは、ハルに受け入れられるか破棄される前に、一定数のチェックのみに参加します。 これにより、クエリの総数が O(n) 以内に抑えられます。

エリアクエリは、順序付けに厳密には必要ありません。 一貫性チェックや初期化の解決に使用できますが、コアの順序付けは方向付けによって決まります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースジオメトリ再構築 | O(n²) クエリ | O(n²) | 遅すぎる |
 | 固定ピボットからの極ソート | O(n log n) クエリ | O(n) | クエリが多すぎます |
 | インクリメンタル凸型チェーン構造 | O(n) クエリ | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 方向テストを使用して反時計回りの順序で次の頂点を一貫して選択できれば、凸包を回復できるという事実に依存しています。 

1. 点 1 をハル シーケンスの開始頂点として固定します。 反時計回りに船体を成長させていきます。 
2. 2 番目の頂点の最初の候補を選択します。 一般的なトリックは、ポイント 2 を試すことです。正確かどうかは、この選択には依存せず、一貫した方向の処理にのみ依存します。 
3. 現在の順序付きリストを維持する`hull`、最初は [1, 2] を含みます。 
4. 3 から n までの残りの各点 i について、凸性が維持されているかどうかを確認して、ハル チェーンへの挿入を試みます。 これは、最後の 2 つのハル点の方向を候補点 i と比較することによって行われます。 ターンが時計回りの場合、最後の船体ポイントは無効になるため、削除する必要があります。 
5. ハルに少なくとも 2 つの点があるか、それ以上の除去が必要なくなるまで、凸面チェックを繰り返します。 次に、新しい点 i を追加します。 
6. すべての点を処理した後、最後と最初の点が 2 番目と最後から 2 番目の点に対して凸性を維持していることを確認してサイクルを閉じます。 そうでない場合は、ハルが凸になるまで端から最終除去を実行します。 
7. 結果として得られるリストは、点 1 から始まる反時計回りの順序の凸包です。 

全体を通して重要な操作は、orientation(i, j, k) で、セグメント i→j から j→k への回転が反時計回りかどうかを示します。 これにより、単調な凸チェーンを維持できることが保証されます。 

### なぜ効果があるのか

 どの段階でも、維持されるシーケンスは凸状のチェーンです。連続するトリプルはすべて反時計回りの方向を維持します。 新しいポイントが追加されるとき、凸性の違反はチェーンの接尾部でのみ現れる可能性があります。これは、以前の部分がすでに凸状であり、挿入の影響を受けないためです。 末尾から削除すると不変式が復元されます。 

最終的なポイントのセットは凸状の多角形であるため、船体に属するすべてのポイントはすべての削除に耐える必要がありますが、凹状のターンを作成するポイントはすべて削除されます。 これにより、残りのシーケンスが正確な循環順序の境界となることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def cross(i, j, k):
    print(2, i, j, k, flush=True)
    return int(input().strip())

def build_order(n):
    hull = [1, 2]

    for i in range(3, n + 1):
        hull.append(i)
        while len(hull) >= 3:
            a, b, c = hull[-3], hull[-2], hull[-1]
            if cross(a, b, c) == -1:
                hull.pop(-2)
            else:
                break

    # final cleanup to ensure convex cycle
    changed = True
    while changed and len(hull) > 2:
        changed = False
        if cross(hull[-2], hull[-1], hull[0]) == -1:
            hull.pop()
            changed = True
        if len(hull) > 2 and cross(hull[-1], hull[0], hull[1]) == -1:
            hull.pop(0)
            changed = True

    # rotate so that 1 is first
    idx = hull.index(1)
    hull = hull[idx:] + hull[:idx]

    return hull

def main():
    n = int(input())
    ans = build_order(n)
    print(0, *ans, flush=True)

if __name__ == "__main__":
    main()
```このソリューションでは方向クエリのみが使用され、座標の回復は試みられません。 ハル リストは、新しい点が追加されるたびに、無効な中間頂点を削除することによって修正される動的チェーンとして維持されます。 の`cross`この関数は対話型タイプ 2 クエリに直接対応し、すべての呼び出しは対話プロトコルの要求に応じて直ちにフラッシュされます。 

最後の回転ステップでは、頂点 1 が出力順列の最初に出現する必要があるという要件への準拠が保証されます。 

## 実用的な例

 インタラクション自体は隠れたジオメトリに依存するため、小さな概念的な実行を構築します。 

点がすでに 1、2、3、4 の凸順序になっている場合を考えてみましょう。 

| ステップ | 船体 | 操作 | クエリ結果 |
 | --- | --- | --- | --- |
 | 開始 | [1、2] | 初期化 | |
 | 3を追加 | [1、2、3] | チェック (1,2,3) | +1 |
 | 4を追加 | [1、2、3、4] | チェック (2,3,4) | +1 |

 すべての旋回は一貫して反時計回りであるため、船体は変化しません。 

ここで、点 3 が投影順序で 1、2、4 によって形成される三角形の内側にある場合を考えてみましょう。 

| ステップ | 船体 | 操作 | クエリ結果 |
 | --- | --- | --- | --- |
 | 開始 | [1、2] | 初期化 | |
 | 3を追加 | [1、2、3] | チェック (1,2,3) | -1 |
 | 修正 | [1、3] | ポップ2 | |
 | 4を追加 | [1、3、4] | チェック (1,3,4) | +1 |

 これは、無効な中間点が凸性を壊したときにどのように即座に削除されるかを示しています。 

2 番目のトレースは、重要な不変条件を示しています。つまり、凸境界の方向と一致する点だけが、繰り返しの枝刈りに生き残ります。

 ## 特殊なケース

 特殊なケースは、最初に選択した 2 番目の頂点が実際の船体の 1 に隣接していない場合です。 その状況では、アルゴリズムは最初に全体的に正しくないチェーンを構築しますが、凸面枝刈りにより、後の点との向きに違反する誤った中間頂点が確実に削除されます。 最終的には、真の船体の頂点だけが残ります。 

もう 1 つのケースは、複数のポイントがハル以外の位置に早い段階で表示される場合です。 これらのポイントは一時的にチェーンに挿入できますが、後のポイントがそれらのポイントとともに凹型ターンを作成するとすぐに、それらは中央から削除されます。 これは、アルゴリズムが船体のメンバーシップを事前に知る必要がない理由を示しています。
