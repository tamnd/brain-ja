 ## 解決策
 ## 問題の理解

 アリスとボブという 2 人のプレイヤーがおり、それぞれが同じ長さの整数の独自の配列を持っています。 ゲームはターン制です。各ターンで、プレイヤーは配列から任意の要素を削除できます。 プレイヤーがターンで獲得するスコアは、配列内の残りの要素の合計です。 アリスが先に動きます。 タスクは、両方が最適にプレイしたと仮定して、アリスとボブがゲーム終了までに取得する合計スコアを決定することです。 

入力は複数のテスト ケースで構成されます。 各テスト ケースは、配列のサイズと、アリスの配列とボブの配列の要素を示します。 各テスト ケースの出力は、アリスの合計スコアとボブの合計スコアの 2 つの数値です (両方とも最適に再生された場合)。 

配列には最大約 10^5 個の要素を含めることができるという制約があります。 これは、考えられるすべての削除シーケンスを反復する解決策は実行不可能であることを意味します。 テスト ケースごとに線形または O(n log n) で実行されるアプローチが必要です。 エッジケースは、配列にすべてゼロ、同一の要素、または n = 1 のような非常に小さいサイズが含まれる場合に発生します。これは、そのようなシナリオでは最適な選択が明らかではないためです。 

たとえば、アリス = [1]、ボブ = [2] を考えてみましょう。 アリスが先手を取る。 彼女の唯一の要素を削除すると次のターンは 0 になり、ボブは自分の 2 を削除してスコア 0 になります。したがって、合計スコアはアリス 1、ボブ 2 となります。順序なしで最大値を素朴に合計すると、答えは間違ってしまいます。 もう 1 つのエッジ ケースは、複数の最適な戦略が存在する等しい要素を持つ配列です。 

## アプローチ

 素朴なアプローチは、ゲームをターンごとにシミュレートすることです。 各ターン、即時の利益を最大化する要素を削除します。 削除するたびに、残りの要素の合計を再計算します。 これはゲームのルールを正確に反映しているため機能しますが、各除去後の残りの要素の合計にはターンごとに O(n) かかるため、最悪の場合は O(n^2) になります。 n が 10^5 までの場合、10^10 の演算が行われる可能性があり、これでは遅すぎます。 

重要な観察は、ゲームがソートされた結合配列に対する貪欲な選択に帰着するということです。 各プレイヤーは自分のスコアを最大化したいと考えているため、残りの最大の数字を取ることを優先し、順番が回ってきたプレイヤーを優先して同点が解消されます。 具体的には、すべての数値を絶対値の降順に並べ替えると、アリスとボブは交互に数値を取得し、アリスが最初になります。 プレイヤーが自分の配列から数値を取得すると、それがスコアに貢献します。 相手の配列から数値を取得する場合、そうではありません。 

この洞察により、ゲーム シミュレーションを単一のソートされたトラバースに折りたたむことができます。 各ステップで、現在のプレーヤーのスコアにその数値が追加されます (スコアがそのプレーヤーのものである場合)。その後、次の数値に進みます。 これにより、ソートの場合は O(n log n)、トラバーサルの場合は O(n) で解が得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(n^2) | O(n) | 遅すぎる |
 | 貪欲なソート | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取ります。 各テスト ケースについて、配列サイズ n を読み取り、次に 2 つの配列 a と b を読み取ります。 
2. ペアのリストを作成する`(value, owner)`どこ`owner = 0`アリスと`1`ボブのために。 これにより、各数値がどの配列から来たのかを追跡できるようになります。 
3. このリストを値の降順に並べ替えます。 これにより、常に最大の残りの数値が最初に処理されるようになります。 
4.初期化`alice_score`そして`bob_score`ゼロに。 これらは合計スコアを蓄積します。 
5. インデックス i を使用してソートされたリストを繰り返し処理します。 i が偶数の場合は、アリスの番です。 奇妙であればボブの番。 
6. アリスの番で、その数字がアリスのものであれば、それを彼女のスコアに追加します。 それ以外の場合は無視してください。 ボブの番で、その番号がボブのものであれば、それを彼のスコアに追加します。 それ以外の場合は無視してください。 
7. トラバース終了後、印刷します。`alice_score`そして`bob_score`。 

**機能する理由**: 不変条件は、各ステップで常に最大の残りの数値が処理されるということです。 プレイヤーは合計を最大化することを目指しているため、自分に属する利用可能な最大の数字を取得することで、最適なスコアが保証されます。 この交代により、ターン順序が確実に尊重され、対戦相手の番号を無視することで、対戦相手の番号を取得してもスコアが増加しないというルールが正しくモデル化されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    
    combined = [(a[i], 0) for i in range(n)] + [(b[i], 1) for i in range(n)]
    combined.sort(reverse=True, key=lambda x: x[0])
    
    alice_score = 0
    bob_score = 0
    
    for i, (val, owner) in enumerate(combined):
        if i % 2 == 0:  # Alice's turn
            if owner == 0:
                alice_score += val
        else:  # Bob's turn
            if owner == 1:
                bob_score += val
    
    print(alice_score, bob_score)
```このソリューションは、次を使用して入力を効率的に読み取ります。`sys.stdin.readline`、所有者のメタデータを組み合わせた配列を構築し、降順に並べ替えます。 の`enumerate`確実にターンを追跡します。偶数のインデックスはアリス、奇数のインデックスはボブです。 現在のプレーヤーに属する値のみを追加すると、二重カウントが防止され、ルールが正確にモデル化されます。

 | 0 | 2 | 1 | アリス | 0 | 0 |
 | 1 | 1 | 0 | ボブ | 0 | 0 |

 アリスは 0 を取得し、ボブは 0 を取得します。これは、最大の数字が相手からのものであっても、自分のターンでは無視されることを示しています。

 ## 特殊なケース

 単一要素の配列の場合、アリスは常に最初に移動します。 要素がボブに属する場合、アリスは 0 を獲得します。たとえば、アリス = [1]、ボブ = [2]、ソートされた結合配列は [(2,1),(1,0)] となります。 アリスは 2 (ボブに属する) を見る → 無視し、ボブは 1 (アリスに属する) を見る → 無視します。 出力は0 0です
