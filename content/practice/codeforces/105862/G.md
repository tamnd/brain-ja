 ## 解決策
 ## 問題の理解

 各テスト ケースは、数日間にわたって繰り返されるランダムなプロセスを記述します。 毎日、ランナーは 0 ～ 12 キロメートルの整数の距離を独自に選択し、各値にはパーセンテージで与えられる独自の固定確率があります。 以上$n$数日間、選択したすべての距離の合計を気にします。タスクは、この合計が正確に一致する確率を計算することです。$x$。 

計算の観点から見ると、これは古典的な和の分布の問題です。同じ離散確率分布をそれ自体で繰り返し畳み込みます。$n$回になるので、結果の分布の単一の係数が必要になります。 

入力サイズにより構造が明確になります。 各テスト ケースでは最大で次のことが可能です$n = 10^5$、およびすべての合計$n$テスト全体での到達範囲$3 \cdot 10^5$。 これにより、すべての結果をシミュレートしたり、二次時間でテスト ケースごとに完全な分布を素朴に維持しようとしたりするソリューションは即座に排除されます。 直接動的プログラミングによるアプローチ$O(n \cdot x)$遷移も安全ではありません。$x$到達できる$12n$、最悪の場合の状態空間を大まかに作成します。$1.2 \cdot 10^6$テストごとに、それに乗算します$n$実現可能な限界をはるかに超えています。 

最も難しいのは、毎日小さな確率変数が追加され、その合計を分布する必要があることです。 隠れた構造は、サポートが小さく、0 から 12 まで固定されていることです。これは、畳み込みが大幅に最適化できることを示唆しています。 

いくつかの危険な状況は、不注意なアプローチが失敗する理由を明らかにします。 

すべての確率質量がゼロである場合、答えは自明であり、次の場合に 1 に等しくなります。$x = 0$正しく正規化されていない単純な畳み込み実装で​​も、浮動エラーや非整数モジュラーの不一致が発生する可能性があります。 

すべての確率質量が 12 のような単一の値にある場合、合計は決定的であり、次と等しくなります。$12n$。 範囲を誤って切り捨てたり、インデックスをシフトしたりする DP は、この境界ケースを簡単に見逃す可能性があります。 

もし$n$大きいですが$x$が小さい場合、多くの DP アプローチでは、決して到達できない状態を埋めるために時間が無駄になります。これが、排除する必要がある主な非効率です。 

## アプローチ

 簡単な方法は、次のような DP を定義することです。$dp[i][s]$はその後の確率です$i$日、合計は$s$。 毎日、考えられる距離ごとに 13 の次の状態に遷移します。 これはプロセス定義を直接エンコードしているため、これは正しいです。 

ただし、この定式化のコストは、おおよそ状態の数と遷移の数に比例します。$O(n \cdot (12n) \cdot 13)$、合計範囲は次のように直線的に増加するため、$n$。 In worst cases this becomes around$10^5 \cdot 10^6$、それは完全に不可能です。 

重要な観察は、任意の遷移を扱っているのではなく、固定された小さなステップの畳み込みを扱っているということです。 毎日、同じ多項式の乗算を現在の分布に適用します。 DP 層の観点から考える代わりに、12 次の多項式の繰り返し畳み込みの観点から考えることができます。 

これにより、問題はモジュラー演算による効率的な多項式乗算に移行します。 多項式の次数は小さいですが指数なので$n$が大きい場合、単純な累乗を避け、代わりに分割統治法または FFT のような畳み込み戦略を使用します。 ただし、次数が 12 しかないため、セグメント全体にわたってバランスの取れた分割統治 DP を使用し、各マージ ステップで結果を畳み込みで結合する方が、より速く簡単なアプローチです。 各マージにかかるコスト$O(13^2)$、これは定数であり、$O(n \log n)$合計で合併します。 

これにより、指数関数的な繰り返しが対数深さの畳み込みツリーに変換されます。

 ## アルゴリズムのチュートリアル

 毎日の分布を多項式として扱います$P(x)$12次の、ここでの係数$P[k]$は$p_k / 100$。 最終的な答えは次の係数です。$x^x$で$P(x)^n$。 

1. 各分布を長さ 13 の配列として表します。これは、1 日の確率質量関数をエンコードします。 
2. 日のセグメントの分布を計算する再帰関数を定義します。 1 日について、基本多項式を返します。 
3. 日数の間隔を 2 つの半分に分割し、各半分の分布を再帰的に計算します。 これはコンピューティングに相当します$P^{len}$各セグメントごとに。 
4. 多項式畳み込みを使用して 2 つの結果をマージします。 位置の係数$s$マージされた分布内の値は、すべての分割を合計することによって計算されます。$i + j = s$、左右のセグメントからの確率を乗算します。 
5. 全範囲まで繰り返します。$n$日が処理されます。 
6. インデックスの係数を抽出する$x$、これは必要な確率です。 

これが機能する本質的な理由は、独立した合計に対する確率分布が畳み込みによって正確に構成されるためです。 各再帰的マージは独立した日のブロックを結合しており、独立性により確率の乗算と合計の加算が保証されます。 

維持される不変条件は、すべてのセグメント関数がそのセグメント長にわたる合計距離の正確な分布を返すということです。 マージ時には、独立性により、左と右の合計のすべての組み合わせが正確に 1 回カウントされ、交差項が見逃されたり二重にカウントされたりすることがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def inv(x):
    return pow(x, MOD - 2, MOD)

def convolve(a, b):
    res = [0] * 13
    for i in range(13):
        if a[i] == 0:
            continue
        for j in range(13):
            if b[j] == 0:
                continue
            if i + j < 13:
                res[i + j] = (res[i + j] + a[i] * b[j]) % MOD
    return res

def solve_case(n, x, p):
    base = [v * inv(100) % MOD for v in p]

    def build(k):
        if k == 1:
            return base
        half = build(k // 2)
        if k % 2 == 0:
            return convolve(half, half)
        else:
            return convolve(convolve(half, half), base)

    dp = build(n)
    return dp[x] if x < len(dp) else 0

t = int(input())
for _ in range(t):
    n, x = map(int, input().split())
    p = list(map(int, input().split()))
    print(solve_case(n, x, p))
```各パーセンテージがスケーリングされるため、コードは 100 のモジュラー逆数を使用して確率をモジュラー形式に変換します。 畳み込み関数は、有界次数 12 の構造を強制し、不必要な状態の拡張を保証しません。 

再帰的累乗構造により、次の分布が構築されます。$n$乗算の代わりに畳み込みを使用する二乗法を繰り返し使用する日。 

微妙な点は、固定サイズの 13 配列であり、これにより無効な合計へのオーバーフローが防止されます。 12 を超えるインデックスは 1 日では不可能であるため無視され、再帰によってマージ ステップごとにこの境界が保持されます。 

## 実用的な例

 次のような小さなシナリオを考えてみましょう。$n = 3$、$x = 2$、分布は均一です$\{0, 1\}$、毎日、確率 1/2 で 0 または 1 が寄与することを意味します。 

1 日後の分布は次のようになります。 

| 合計 | 確率 |
 | --- | --- |
 | 0 | 1/2 |
 | 1 | 1/2 |

 2日後:

 | ステップ | 0 | 1 | 2 |
 | --- | --- | --- | --- |
 | 1日目 | 1/2 | 1/2 | 0 |
 | 2日目 | 1/4 | 1/2 | 1/4 |

 3日後:

 | ステップ | 0 | 1 | 2 | 3 |
 | --- | --- | --- | --- | --- |
 | 組み合わせ | 1/8 | 3/8 | 3/8 | 1/8 |

 アルゴリズムは再帰的に分割することでこれを再現します。$3$の中へ$1 + 2$、各辺を計算し、畳み込みます。 

ここで、すべての確率質量が 12 である縮退ケースを考えてみましょう。任意の日数後の分布には、インデックスに 0 以外のエントリが 1 つだけあります。$12n$。 2 つのデルタ分布を乗算すると、質量を拡散することなくインデックスが加算的にシフトされるため、畳み込みステップではこれが維持されます。

 ## 特殊なケース

 すべての確率がゼロに集中している場合、すべての畳み込みはインデックス 0 に単一の非ゼロ係数を保存します。畳み込みはゼロ位置のエントリのみを乗算し、再帰を通じて他のすべてのインデックスはゼロのままであるため、アルゴリズムはこれを処理します。 

すべての確率が 12 に集中している場合、各マージは加算によって分布を正確にシフトします。 単一の再帰的なビルド ステップで、インデックスに蓄積されるデルタ分布が生成されます。$12n$、他のインデックスのクエリは、畳み込み中にそれらの位置が決して埋められないため、正しくゼロを返します。 

いつ$x$を超える$12n$、ノードごとに 13 の固定サイズと制限されたマージにより、DP 配列はそのようなインデックスを決して割り当てないため、明示的なチェックを必要とせずに、最終アクセスは安全にゼロを返します。
