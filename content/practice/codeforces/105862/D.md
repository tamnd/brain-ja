 ## 解決策
 ## 問題の理解

 整数のコレクションが与えられ、これらの数値のサブセットを取得し、ビットごとの OR を使用してそれらを組み合わせることで形成できるすべての値を調べるように求められます。 この到達可能な結果セットから、結果として決して表示されない最小の非負の整数を決定する必要があります。 

このタスクを言い換える便利な方法は、ゼロから開始し、オプションで各数値を OR 演算して現在の値に「加算」することを想像することです。 各サブセットは、各要素を含めるかどうかの一連の選択に対応し、そのサブセットの OR により 1 つの値が生成されます。 対象となる最後のオブジェクトは、そのようなすべての OR 結果のセットであり、このセットから欠落している最初の整数を探します。 

この問題の制約は、生の数値サイズではなく、ビットごとの OR の構造を中心に設計されています。 値が大きく見える場合でも、OR はビットを介してのみ相互作用するため、有効な状態空間は最大値を表すのに必要なビット数によって決まります。 これにより、要素数が指数関数的に増加するため、サブセットを明示的に列挙するアプローチは即座に除外されます。 代わりに、唯一の実現可能なアプローチは、問題をビットマスク上の管理可能な状態空間に圧縮する必要があります。 

サブセット OR 構造ではなく入力配列の観点からのみ考えると、いくつかの特殊なケースを見逃しがちです。 配列にゼロのみが含まれている場合、すべてのサブセット OR はゼロであるため、到達可能なセットは次のようになります。`{0}`そして答えは次のようになります`1`。 単純な間違いは、すべての要素が新しい値に寄与すると想定し、複数の異なる OR 結果が存在すると誤って考えることです。 

もう 1 つの微妙なケースは、値がビット単位で重なり合う場合に発生します。 たとえば、入力の場合`[1, 2, 3]`、サブセット OR の結果は次のようになります。`{0, 1, 2, 3}`なぜなら`1 | 2 = 3`、しかし形成する方法はありません`4`。 単純なアプローチでは、ビット 0 と 1 が出現するので、それまでのすべての数値が有効であると誤って仮定する可能性があります。`3`はカバーされており、メキシコもカバーされるべきである`4`, しかし、これはただ真実であるだけです。`4`どの要素にも存在しない新しいビットが必要です。 

最後に、グローバル OR が密であるものの、表現性にギャップがまだ残っている入力を考えてみましょう。 すべての要素の OR が成立しても、`7`、からのすべての数字が含まれることを意味するものではありません。`0`に`7`到達可能です。 この「ビット カバレッジ」と「値カバレッジ」の不一致が、単純な推論が失敗する主な理由です。 

## アプローチ

 ブルート フォースのアプローチは簡単です。配列のすべてのサブセットを列挙し、そのビットごとの OR を計算し、すべての結果をセットに格納し、最後にゼロから上方向にスキャンして、最初に欠落している整数を見つけます。 これは、問題の定義を明示的に構築するため、正しいです。 ただし、すべてを繰り返す必要があります`2^n`サブセット、およびサブセットごとに最大で OR を計算します。`n`最悪の場合の要素。 これはおおよそ次のことにつながります`O(n * 2^n)`操作は不可能になります。`n = 25`ましてや、より大きな制約はありません。 

重要な観察は、実際にはどのサブセットが値を生成したかは気にせず、値が到達可能かどうかだけを気にしているということです。 これにより、問題は OR 状態をめぐる到達可能性の問題に変わります。 それぞれの数字が現在の状態を変える`x`新しい状態へ`x | a_i`。 OR はビットを追加するだけでビットを削除しないため、状態空間は遷移が繰り返されると閉じられ、入力で表現できる最大ビットマスクによって制限されます。 

これにより、問題をビットマスクに対する動的プログラミングとして扱うことができます。つまり、OR 値が達成可能なブール配列を維持し、各配列要素を使用してそれを反復的に拡張します。 各要素は、現在到達可能なすべての状態からの遷移に寄与します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n · 2^n) | O(2^n) | 遅すぎる |
 | ビットマスク DP | O(n · 2^B) | O(2^B) | 承認済み |

 ここ`B`配列内の最大値を表すために必要なビット数です。 

## アルゴリズムのチュートリアル

 1. 配列内の値を表すために必要な最大ビット長を決定し、制限を設定します`MAX_MASK = 2^B`。 OR では新しいビットを導入できないため、これにより、考えられるすべての OR 結果の範囲が定義されます。 
2. ブール配列を作成する`dp`どこ`dp[x]`一部のサブセットが OR 値を生成するかどうかを示します`x`。 初期化する`dp[0] = True`、空のサブセットを表します。 
3. 各数値を処理する`a`配列内で。 現在到達可能な値ごとに`x`、私たちも到達することができます`x | a`。 同じ反復内で情報が上書きされるのを避けるために、現在の状態のスナップショットから更新を計算します。 
4. すべての要素を処理した後、スキャンします。`dp`から`0`上向きに移動し、最初のインデックスを返します`mex`そのような`dp[mex]`は誤りです。 

スナップショットが必要な理由は、インプレース更新を許可すると、同じ反復内で単一の要素が誤って複数回連鎖し、実質的に同じ配列要素の再利用をシミュレートし、サブセット制約に違反するためです。 

### なぜ効果があるのか

 アルゴリズムは、最初のデータを処理した後も不変条件を維持します。`i`要素、`dp[x]`最初のサブセットが存在する場合にのみ true になります。`i`OR が等しい要素`x`。 それぞれのトランジション`x -> x | a_i`を含めるかどうかを決定することに正確に対応します。`i`サブセット内の - 番目の要素。 すべてのサブセットの決定は要素ごとに 1 回だけ表現されるため、到達可能な OR 値が失われることも、無効な値が導入されることもありません。 したがって、最終スキャンでは、サブセット OR として表現できない最小の整数が正確に識別されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    arr = list(map(int, input().split()))

    max_val = 0
    for x in arr:
        max_val |= x

    # number of bits needed to represent max_val
    B = max_val.bit_length()
    size = 1 << B

    dp = [False] * size
    dp[0] = True

    for a in arr:
        ndp = dp[:]  # snapshot
        for x in range(size):
            if dp[x]:
                ndp[x | a] = True
        dp = ndp

    for i in range(size):
        if not dp[i]:
            print(i)
            return

if __name__ == "__main__":
    solve()
```この実装では、最初に状態空間を実際に入力に現れるビットのみに圧縮します。 これにより、到達不可能な上位マスクに対する不必要な作業が回避されます。 

コアループの構築`ndp`から`dp`各要素がサブセットの決定ごとに 1 回だけ使用されるようにします。 移行`x | a`現在の要素の包含をエンコードします。 たとえ到達可能性がそうでなくても、インデックス付けにおいて OR 状態空間が連続しているため、最後の線形スキャンは安全です。 

微妙な点は、サブセットを明示的に追跡する必要はなく、到達可能な OR 値のみを追跡する必要があることです。 これにより、ソリューションを管理可能な範囲内に留めることができます。`2^B`指数関数の代わりに状態空間`n`。

 ### 例 1

これは、ビットのすべてのペアがカバーされているにもかかわらず、既存のビットを超える新しいビットを導入する組み合わせがないことを確認します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n · 2^B) | 各要素について、すべてのビットマスク状態をスキャンし、OR 遷移を伝播します。 
| スペース | O(2^B) | 可能なビットマスクごとに到達可能性を保存します。 

値`B`は入力値の最大ビット数によって制限されるため、実際には状態空間が小さく保たれます。 これは、値がおよそ以下の一般的な制約内に快適に適合します。`10^6`または`10^7`、最大でも 20 ～ 25 ビットを与えます。

 ## 特殊なケース

 ゼロのみで構成される入力の場合、アルゴリズムは初期化します。`dp[0] = True`そしてそれを決して拡大しません。 ゼロからスキャンすると、`0`到達可能ですが、`1`ではないため、出力は正しくなります`1`。 

すべての値が 2 の累乗である入力の場合、各要素は単一の新しいビットを導入し、OR 遷移がそれらのビットの組み合わせを徐々に埋めていきます。 DP はビットのすべてのサブセットを正しく構築しますが、複数の同一ビットを必要とする数値は不可能であり、それに応じてスキャンによって最初の欠落している整数が検出されます。 

配列に次のような大きな値がすでに含まれている場合`2^k`、そのビットは OR を介して到達可能なすべての状態に即座に伝播しますが、中間値が埋められることは保証されません。 アルゴリズムは引き続きすべての候補を明示的にチェックし、連続したカバレッジについて仮定が行われないことを保証します。
