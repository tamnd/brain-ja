 ## 解決策
 ## 問題の理解

 この問題により、3 のべき乗のサイズのスイカを束ねて提供する販売者が得られます。 各束のサイズ$3^x$費用$3^{x+1} + x \cdot 3^{x-1}$コイン。 買い手はまさにそれを望んでいます$n$取引の数を最小限に抑えながらスイカを購入します。これは、できるだけ多くのスイカを大きな束で購入するのと同じです。 私たちの仕事は、正確に取得するための最小コストを計算することです。$n$最も少ない取引数を使用するスイカ。 

入力は次のもので構成されます$t$テストケース。 各テスト ケースは単一の整数です$n$買い手が望むスイカの数を表します。 出力はテスト ケースごとに 1 つの整数、つまりその最小コストです。$n$。 

制約とは次のようなものです$n$まで可能です$10^9$、最大で$10^4$テストケース。 サブセットの数は指数関数的になるため、これには取引のすべての可能なサブセットを検査するソリューションは除外されます。 それぞれの答えを大まかに計算するアプローチが必要です。$O(\log n)$制限時間内にとどまる時間。 

次のような、3 の累乗をわずかに超える数値の場合、微妙なエッジ ケースが発生します。$n = 4$。 単純なアプローチでは、以下より小さい最大のバンドルを購入しようとする可能性があります。$n$そして残りを最小の束で覆います。 これはここでは機能しますが、常に最小数の取引を購入するようにするには慎重な取り扱いが必要です。バンドル数を考慮せずに、単純に最も安い組み合わせを選択することはできません。 

## アプローチ

 ブルートフォースアプローチでは、考えられるすべての取引が次の形式で生成されます。$3^x$のために$x \ge 0$すべての組み合わせを試して正確に合計してください$n$。 これは原理的には正しいですが、$n$まで$10^9$、可能な組み合わせの数は指数関数的に増加します。 それぞれの能力を1回ずつ使用することに限定しても、能力の数は約20個あります（$3^{19} \approx 10^9$)、すべてのサブセットの生成はまだ$2^{20} \approx 10^6$テストケースごとに。 乗算$10^4$テストケース、これは遅すぎます。 

重要な洞察は、取引規模が指数関数的に増加するということです。 これにより、問題を貪欲な分解のように扱うことができます。つまり、以下を超えない最大のバンドルを購入することを常に考慮します。$n$残りについても繰り返します。 ただし、難しいのは、コストがバンドルのサイズに比例しないことです。 毎回最大のバンドルを直接選択しても、コインの総コストが最小化されるとは限りません。 その代わりに、すべての数字が$n$は「3 値」形式で表すことができます。各桁は、次のバンドルの数を示します。$3^x$カバーする必要がある$n$。 取引の最小数は、この 3 進表現の桁の合計に対応し、キャリーを処理するために必要な場合は切り上げられます。 

これは、カバーするために必要な 3 のべき乗の合計として最小取引数を繰り返し計算することで利用できます。$n$および関連するコスト計算式。 各サイズの取引$3^x$～のコストに貢献する$2 \cdot 3^x$さらに、式からの追加の線形成分も含まれる可能性がありますが、主なトリックは次のとおりです。$n$効率的に 3 のべき乗の合計として計算されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (サブセットの合計) | テスト ケースごとに O(2^log3(n)) | O(log3(n)) | 遅すぎる$n$最大 10^9 |
 | 三項分解で貪欲 | テスト ケースあたり O(log3(n)) | O(log3(n)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 最大までの 3 の累乗を事前計算します。$3^x \le 10^9$。 これにより、考えられるすべての取引サイズが得られます。 それらを昇順でリストに保存します。 
2. 各テスト ケースについて、次の内容を読んでください。$n$。 変数を初期化する`total_cost = 0`。 
3. 3 の最大累乗から下方向に繰り返します。 各ステップで、残りのスイカにこのサイズの取引がいくつ収まるかを決定します。`count = n // power`。 減算`count * power`から`n`。 
4. 各サイズの取引について$3^x$、次の式でコストを計算します。$3^{x+1} + x \cdot 3^{x-1}$そして追加します`count * cost`に`total_cost`。 
5. まで繰り返します。`n`ゼロに達します。 常に最大の利用可能なバンドルを採用するため、取引の数は最小限に抑えられます。 
6. 出力`total_cost`。 

機能する理由: 3 の累乗は指数関数的に増加するため、最初に最大のバンドルを使用すると取引が少なくなります。 各取引の計算式はサイズに応じて厳密に増加するため、より小さい取引を使用すると、取引の総数または総コストが増加するだけです。 分解することで$n$3 のべき乗を貪欲に計算することで、取引の最小数と正しいコスト計算の両方を保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

# precompute powers of 3 up to 10^9
powers = [1]
while powers[-1] * 3 <= 10**9:
    powers.append(powers[-1] * 3)

def deal_cost(x):
    if x == 0:
        return 3
    return 3**(x+1) + x * 3**(x-1)

t = int(input())
for _ in range(t):
    n = int(input())
    total_cost = 0
    remaining = n
    # iterate from largest power to smallest
    for i in reversed(range(len(powers))):
        count = remaining // powers[i]
        if count:
            total_cost += count * deal_cost(i)
            remaining -= count * powers[i]
    print(total_cost)
```コードは、累乗の繰り返しを避けるために、最初に 3 の累乗を事前計算します。 の`deal_cost`関数は、特殊なケースを含む数式を処理します。$x=0$。 各テスト ケースでは、すべてのスイカが購入されるまで、可能な限り最大のバンドルを貪欲に選択します。 逆反復を使用すると、取引の数が最小限に抑えられ、次のように乗算されます。`count`同じサイズの複数の取引を効率的に処理します。 

## 実用的な例

 **入力:`n = 8`**

 | ステップ | 考慮される電力 | カウント | 残り n | 総コスト |
 | --- | --- | --- | --- | --- |
 | 3^1=3 | 3 | 2 | 8-6=2 | 2*10=20 |
 | 3^0=1 | 1 | 2 | 2-2=0 | 20+2*3=26 |

 この表では、サイズ 3 の取引を 2 つとサイズ 1 の取引を 2 つ使用すると、最小コストが 26 になることが確認されています。 

**入力:`n = 10`**

 | ステップ | 考慮される電力 | カウント | 残り n | 総コスト |
 | --- | --- | --- | --- | --- |
 | 3^2=9 | 9 | 1 | 10-9=1 | 1*28=28 |
 | 3^1=3 | 3 | 0 | 1 | 28 |
 | 3^0=1 | 1 | 1 | 1-1=0 | 28+3=31 |

 より小さな組み合わせを確認すると、サイズ 3 の取引 2 つ (スイカ 6 個) + サイズ 1 の取引 4 つ (スイカ 4 個) のコストは 2_10+4_3=32 となり、これより高くなります。 貪欲なアプローチにより、最小限のコストが発生します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(t * log3(n)) | 各テスト ケースについて、n までの 3 の累乗すべてを繰り返します。 3^19 > 10^9 であるため、累乗の数は最大 20 です。 |
 | スペース | O(log3(n)) | 10^9 までの 3 の累乗をすべて保存します。 最大 20 個の整数。 |

 これは制限内にうまく収まります。$10^4$テスト ケース × 20 の操作は、それぞれ約 2×10^5 の操作にすぎません。
