 ## 解決策
 ## 問題の理解

 この問題は、Vadim と Kostya という 2 人のプレイヤーのチームに提示されます。彼らはそれぞれ、数値を持つカードのコレクションを持っています。 各ラウンドでは、指定された枚数のカードを正確に選択するように求められますが、各プレイヤーは自分のカードを何枚提供できるかについて個人的な上限を持っています。 タスクは、各ラウンドで選択されたカードの合計を最大化することです。 

正式には、ヴァディムは`n`価値観のあるカード`a_1`を通して`a_n`、そしてコスティアは`m`カード`b_1`を通して`b_m`。 クエリごとに`(x_i, y_i, z_i)`、チームは正確に選択する必要があります`z_i`カード、最大でも`x_i`ヴァディムから、せいぜい`y_i`コスチャから。 目標は、これらの可能な最大合計を計算することです。`z_i`カード。 

この問題の制約は厳しく、すべてのテスト ケースにわたるカードの総数は、Vadim と Kostya それぞれで最大 200,000 枚、ラウンド数は最大 100,000 です。 これにより、サイズ 100,000 のサブセットを選択するだけでも指数関数的に増加するため、ラウンド内のカードの組み合わせを反復する強引なアプローチは即座に排除されます。 重要な観察は、各ラウンドは、`k`各プレイヤーのカードのソートされた配列から、個々の制限を尊重して最大のカードを選択します。 

明らかではないエッジ ケースには、要求されたカードの数がゼロである場合や、1 人のプレイヤーにカードが 0 枚許可されている場合などがあります。 たとえば、ヴァディムがカードを持っている場合`[10, 20]`そしてコスチャ`[5, 15]`、ラウンドは`(x=0, y=2, z=2)`、たとえヴァディムがより価値の高いカードを持っていたとしても、チームはコスチャからすべてのカードを選ばなければなりません。 常に最大のグローバル カードを選択しようとする単純なアプローチは、ここでは失敗します。 

## アプローチ

 ブルートフォースアプローチは、次のすべての組み合わせを反復します。`k`Vadim と Kostya のコレクションの制約を尊重したカード。 組み合わせごとに合計を計算し、最大値を返します。 これは正しいですが、その複雑さはカードの数が指数関数的に増加し、実行可能な制限時間をはるかに超えています。`n, m ~ 2*10^5`。 

最適なアプローチは、並べ替えとプレフィックスの合計に依存します。 Vadim と Kostya の両方のカードが降順でソートされている場合、プレフィックスの合計を事前計算して、上位のカードの合計をすばやく決定できます。`k`あらゆるカード`k`まで`n`または`m`。 各ラウンドでは、ヴァディムが貢献できるカードの数を単純に繰り返します (0 から 2000 まで)。`min(x_i, z_i)`）、到達するためにコスティアが提供する必要があるカードの枚数を計算します。`z_i`。 その数値が制限内にある場合は、プレフィックスの合計を使用して合計を計算し、最大値を追跡します。 

これは、各ラウンドの最大合計がプレフィックス合計を使用する O(min(x_i, z_i)) 操作で求められ、ソートとプレフィックス合計の事前計算が O(n + m) であるため、効率的に機能します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^(n+m)) | O(n+m) | 遅すぎる |
 | 並べ替え + プレフィックスの合計 | O((n+m) log(n+m) + q * min(x_i, z_i)) | O(n+m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.ヴァディムのカードを降順に並べ替えます。 これにより、最初の`k`カードは常に`k`最大。 
2. 同じ理由で、Kostya のカードを降順に並べ替えます。 
3. Vadim と Kostya の両方のプレフィックスの合計を計算します。 させて`pref_a[k]`最初の合計になる`k`ヴァディムのカードと`pref_b[k]`コスティアのために。 これにより、上位の定数時間合計クエリが可能になります。`k`カード。 
4. 各クエリについて`(x, y, z)`、反復します`i`から`max(0, z - y)`に`min(z, x)`ヴァディムから奪ったカードの数を表します。 この範囲は、Vadim の制限の両方を尊重し、Kostya が残りのカードを貢献できることを保証します。 
5. それぞれについて`i`、計算する`j = z - i`コスチャから奪ったカードの数として。 反復をスキップする場所`j > y`コスティアの限界を超えているからです。 
6. 合計を次のように計算します。`pref_a[i] + pref_b[j]`有効なすべての最大値を追跡します`i`。 
7. ラウンドの最大合計を返します。 

機能する理由: このアルゴリズムは、各ステップですべての有効な分割方法を考慮するという不変条件を維持します。`z`それぞれの制限内でヴァディムとコスチャの間でカードを交換します。 プレフィックスの合計を事前にソートして使用することで、どのような分割でも、各プレイヤーからの可能な限り最大のカードを使用し、合計が最大になることを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m, q = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        
        a.sort(reverse=True)
        b.sort(reverse=True)
        
        # Prefix sums
        pref_a = [0]
        for val in a:
            pref_a.append(pref_a[-1] + val)
        
        pref_b = [0]
        for val in b:
            pref_b.append(pref_b[-1] + val)
        
        res = []
        for _ in range(q):
            x, y, z = map(int, input().split())
            max_sum = 0
            # i is number of cards from Vadim
            for i in range(max(0, z - y), min(z, x) + 1):
                j = z - i
                if j <= y:
                    current_sum = pref_a[i] + pref_b[j]
                    max_sum = max(max_sum, current_sum)
            res.append(str(max_sum))
        print("\n".join(res))

if __name__ == "__main__":
    solve()
```このソリューションでは、最初にカードを並べ替えてプレフィックスの合計を計算し、上位のカードの合計を迅速にクエリします。 クエリ ループは、Vadim が提供できる有効な数のカードに対してのみ反復され、Kostya からの対応するカードが自動的に計算されます。 慎重な使用`max(0, z - y)`不正な負の選択を防止し、プレフィックス合計インデックスが正しいことを保証します。 

## 実用的な例

 サンプル 1 の使用:

 | クエリ | バディム限界x | コストヤ限界 y | 必要な合計 z | 私は範囲 | 最大合計 |
 | --- | --- | --- | --- | --- | --- |
 | 0 0 0 | 0 | 0 | 0 | [0] | 0 |
 | 3 4 7 | 3 | 4 | 7 | [3,4] | 70 |

 2 番目のクエリでは、Vadim は最大 3 枚のカードを提供でき、Kostya は最大 4 枚のカードを提供できます。合計 7 枚のカードが必要なので、Vadim は少なくとも 3 枚のカードを提供する必要があります (`max(0,7-4)=3`）、コスチャに4を残します。 合計は`30+20+10 + 4+3+2+1 = 70`。 

トレースは、プレフィックス合計アプローチが制限を尊重しながら可能な限り最大のカードを正しく選択していることを示しています。 

## 複雑さの分析

 | 時間 | O((n+m) log(n+m) + q * min(x_i, z_i)) | 最初は配列のソートが優先され、その後、各クエリが z カードの可能な分割をループします。
