 ## 問題の理解

 それぞれの取引で正確に購入できるようになります$3^x$スイカ用$$3^{x+1} + x \cdot 3^{x-1}$$コイン。 

正確に購入する必要があります$n$スイカ。 最大でも使用できます$k$お得。 それを行う有効な方法の中で、総コストを最小限に抑えたいと考えています。 

の値$n$そして$k$と同じくらい大きい$10^9$、まであります$10^4$テストケース。 線形に依存するアルゴリズム$n$すぐには無理です。 有益な観察は、3 のべき乗が非常に急速に増加するということです。 以来$$3^{19} > 10^9,$$までのすべての数字$10^9$3 進数は約 20 桁しかありません。 これは、ソリューションが次の 3 項表現で機能する必要があることを強く示唆しています。$n$、個々のスイカではありません。 

微妙な点は、制限が「​​最大でも$k$「まさに」ではなく「お得」$k$不注意な解決法では、強制的に取引数を同じにしようとする可能性があります。$k$たとえそのカウントに到達できない場合でも。 

例えば：```

```唯一の表現は次のとおりです。$$3$$1回の取引で、または$$1+1+1$$3つの取引で。 

2つの取引は不可能です。 正解は 10 で、1 つの取引を使用します。 

もう 1 つの簡単な間違いは、最小値と最大値の間のすべての取引数が達成可能であると仮定することです。 

例えば：```

3 番目の罠は実現可能性です。 取引の最小可能数を既に超えている場合$k$、有効な解決策はありません。

 ## アルゴリズムのチュートリアル

 1.変換$n$三進法に。 
2. しましょう$a_x$位置の 3 進数字である$x$。 

最小取引表現は正確に使用します$a_x$サイズの取引$3^x$。 
3. コンピューティング$$D_0=\sum a_x,$$可能な最小限の取引数。 

もし$D_0 > k$、有効な解決策は存在せず、答えは次のとおりです。$-1$。 
4. 最小取引表現の追加コストを計算します。$$E_0=\sum a_x \cdot x3^{x-1}.$$5. しましょう$$T=\min(k,n).$$どの表現もこれ以上のものを使用することはできません$n$なぜなら、最小の取引ではスイカ 1 個が買えるからです。 
6. 分割するたびに取引数がちょうど 2 ずつ増加するため、到達可能なすべての取引数は次と同じパリティになります。$D_0$。 

到達可能な最大の取引数を超えないものを選択してください$T$:$$D= \begin{cases} T,& T\equiv D_0\pmod 2\\ T-1,& \text{otherwise} \end{cases}$$7. 必要な分割数は$$S=\frac{D-D_0}{2}.$$8. 各レベルに存在する分割機会の数を計算します。 

させて$N_x$サイズのノードの合計数になります$3^x$すべての大きな権力が完全に分割された場合、それはいつか現れる可能性があります。 

これらは満足します$$N_x=a_x+3N_{x+1}.$$9. 最大から最小までのプロセス レベル。 

レベルでの分割$x$利益を生む$$3^{x-1}.$$より高いレベルでは常に大きな利益が得られるため、残りの最大レベルから可能な限り多くの分割を貪欲に取得します。 
10. 選択したものからの合計利益を計算します$S$分割される$R$。 

最小限に抑えられる追加コストは、$$E=E_0-R.$$11. 答えは$$3n+E.$$### なぜ効果があるのか

 3 値表現は、最小の取引数で一意の表現を提供します。 有効な表現はすべて、1 つを繰り返し置き換えることによって取得できます。$3^x$3つで$3^{x-1}$。 

このような操作ごとに、取引数が正確に変更されます$+2$そして目標を正確に削減します$3^{x-1}$。 すべての分割により厳密にコストが改善されるため、最適なソリューションでは常に、到達可能な最大数を超えない取引が使用されます。$k$。 

固定回数の分割を実行するすべての方法の中で、より高いレベルの分割を選択することは、その利益が大きいため、常に、より低いレベルの分割を選択する場合と少なくとも同じくらい収益性が高くなります。 したがって、分割機会を最上位レベルから下に向かって処理すると、合計の削減が最大化されます。 これにより、コストが最小限に抑えられます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n, k = map(int, input().split())

        digits = []
        x = n
        while x:
            digits.append(x % 3)
            x //= 3

        m = len(digits)

        pow3 = [1] * max(1, m)
        for i in range(1, m):
            pow3[i] = pow3[i - 1] * 3

        d0 = sum(digits)

        if d0 > k:
            out.append("-1")
            continue

        e0 = 0
        for i, d in enumerate(digits):
            if i > 0:
                e0 += d * i * pow3[i - 1]

        tmax = min(k, n)
        if (tmax - d0) & 1:
            d = tmax - 1
        else:
            d = tmax

        splits = (d - d0) // 2

        N = [0] * m
        N[-1] = digits[-1]
        for i in range(m - 2, -1, -1):
            N[i] = digits[i] + 3 * N[i + 1]

        reduction = 0
        s = splits

        for level in range(m - 1, 0, -1):
            take = min(s, N[level])
            reduction += take * pow3[level - 1]
            s -= take
            if s == 0:
                break

        answer = 3 * n + (e0 - reduction)
        out.append(str(answer))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```3 進数は最小取引表現を形成します。 変数`d0`取引数を保存し、実行不可能なケースを即座に処理します。 

数量`e0`固定ベースラインを超えたコストの追加部分です`3 * n`。 

パリティ調整は見落としがちです。 分割するたびに取引カウントが 2 ずつ変更されるため、到達可能なカウントは等価性を維持します。 コードは、両方を超えない、到達可能な最大のカウントを選択します。`k`そして`n`。 

配列`N`最も重要な実装の詳細です。`N[level]`より大きなレベルを完全に展開した後に表示される、そのサイズの考えられるすべてのノードをカウントします。 このような各ノードは、そのレベルで 1 つの潜在的な分割に寄与します。 

すべての算術演算は Python の整数に快適に適合します。 最大の答えは数十億のオーダーです。
