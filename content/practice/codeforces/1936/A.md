 ## 解決策
 ## 問題の理解

 0 から 0 までの数字の隠された順列が与えられています。$n-1$。 Our task is to identify two indices$i$そして$j$これらの位置の値の XOR は、$p_i \oplus p_j$、できるだけ大きいです。 順列への直接アクセスは禁止されていますが、オラクルに問い合わせることはできます。 各クエリで 4 つのインデックスを選択できます。$a, b, c, d$、オラクルは最初の 2 つの値のビットごとの OR を比較します。$p_a \mid p_b$、2 番目の 2 つの値のビット単位の OR に対して、$p_c \mid p_d$。 オラクルは、最初の OR が 2 番目の OR より小さいか、等しいか、大きいかを返します。 

問題は対話型であり、クエリの総数は次のように制限されます。$3n$。$n$と同じ大きさにすることができます$10^4$したがって、二次複雑性を伴うアプローチは実行不可能です。 具体的には、インデックスのすべてのペアを列挙し、それらの XOR または OR を計算するには、$O(n^2)$に達するであろう操作$10^8$最悪の場合の操作 - 2 秒の制限には遅すぎます。 これは、最大値を分離するために戦略的にクエリを実行する線形または線形演算アプローチが必要であることを意味します。 

素朴な落とし穴は、単に隣接する要素の OR を比較するだけで十分であると想定していることです。 小型用$n$、これは偶然に機能する可能性がありますが、隠れた順列では、最大の XOR は通常、最大の数値と 2 番目に大きい数値の間で発生し、必ずしも隣接する数値とは限りません。 たとえば、次の場合$p = [0, 3, 1, 2]$、最大 XOR は次のとおりです。$3 \oplus 0 = 3$または$2 \oplus 1 = 3$。 隣接する要素のみを選択する単純なアプローチでは、これらのペアを見逃す可能性があります。 

## アプローチ

 ブルートフォース手法では、インデックスのすべてのペアが試行されます。$(i, j)$そして計算する$p_i \oplus p_j$最初に再構築することで$p$完全にクエリを通じて。 各数値を再構成するには、次のことが必要です$\Theta(n)$OR 比較のみを使用して数値ごとにクエリを実行するため、$O(n^2)$全体的なクエリ。 クエリ制限が次のとおりであるため、これは実行できません。$3n$。 

重要な洞察は、XOR の特性を理解することから得られます。 2 つの数値間の XOR は、それらの最大設定ビットが異なる場合に最大になります。 の順列で$0$に$n-1$、最大の数は$n-1$、そして 2 番目に大きい数値は通常、ほとんどのビットを次のものと共有します。$n-1$ただし、最上位ビットが異なります。 したがって、XOR を最大化するには、順列で最大の 2 つの数値を見つけるだけで十分です。 これを効率的に行うために、OR 比較を利用します。$(p_a \mid p_b)$の間の大きい方の数によって支配されます。$p_a$そして$p_b$。 したがって、トーナメント形式の比較を使用して、次の最大数を見つけることができます。$n-1$クエリ。 最大値がわかったら、別のパスを実行して、最大値と XOR 演算したときに最大の結果を生成する数値を見つけます。これは、ビット単位の寄与の点で実質的に 2 番目に大きい数値になります。 

これにより、問題は配列上の 2 つの線形パスに軽減され、それぞれのパスでは最大で次の値が使用されます。$n-1$クエリ、合計を与える$2n-2 < 3n$、これはクエリ制限を尊重します。

 ## アルゴリズムのチュートリアル

 1. 最大値の現在の候補として最初の要素から開始します。 他のすべてのインデックスを反復処理します。 インデックスごとに$i$、現在の最大候補とそれ自体の OR をクエリし、それを次の OR と比較します。$i$それ自体と一緒に。 結果が新しい要素の方が大きいことを示している場合は、現在の最大候補を更新します。 後$n-1$比較すると、最大要素のインデックスが得られます。 
2. XOR の 2 番目の候補を初期化します。 他のすべてのインデックスを反復処理します。 インデックスごとに$i$最大値と等しくない場合は、最大値の OR をクエリします。$i$そして、それを現在の 2 番目の候補との最大値の OR と比較します。 結果がより高い OR を示した場合は、2 番目の候補を更新します。 後$n-1$比較すると、最大値との XOR が最大になる数値が 2 番目の候補となります。 
3. 最大候補と 2 番目の候補のインデックスを解として出力します。 

このアルゴリズムが機能するのは、OR ベースの比較により、正確な値を知らなくても数値の相対的な大きさを判断できるためです。 XOR はビット パターンの点で最大のものと 2 番目に大きいものの間で最大化されるため、最大の XOR を生成するペアを見つけるにはこれら 2 つのパスで十分です。 すべてのクエリは 3n 制限を尊重します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
print_flush = lambda x: (print(x), sys.stdout.flush())

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        max_idx = 0
        # find maximum element index
        for i in range(1, n):
            print_flush(f"? {max_idx} {max_idx} {i} {i}")
            res = input().strip()
            if res == "<":
                max_idx = i
        # find element that maximizes XOR with maximum
        second_idx = 0 if max_idx != 0 else 1
        for i in range(n):
            if i == max_idx:
                continue
            print_flush(f"? {max_idx} {i} {max_idx} {second_idx}")
            res = input().strip()
            if res == ">":
                second_idx = i
        print_flush(f"! {max_idx} {second_idx}")

if __name__ == "__main__":
    solve()
```最初のループでは、候補の OR をそれ自体と比較することで最大の要素を特定します。 2 番目のループでは、最大値と OR をとったときに最大値が得られる要素を見つけます。これにより、最大の XOR も保証されます。 使用する`print_flush`インタラクティブな通信のための適切なフラッシングを保証します。 境界条件は初期化によって処理されます`second_idx`最大値とは異なる有効なインデックスに設定します。
