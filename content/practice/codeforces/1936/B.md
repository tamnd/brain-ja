 ## 解決策
 ## 問題の理解

 長さの 1 次元グリッド上を移動するピンボールをシミュレートするように求められます。$n$、各セルには矢印があり、「<」は左を指すか、「>」は右を指します。 ピンボールは現在のセルの矢印に従って移動し、移動するたびにピンボールが残した矢印が反転します。 ピンボールはグリッドの外に出るとすぐに止まります。 開始セルごとに、ピンボールがグリッドから離れるまでに必要なステップ数を計算する必要があります。 

入力は複数のテスト ケースで構成され、それぞれがグリッドの長さを指定します。$n$と長さの文字列$n$矢印を表します。 出力は次のリストです。$n$各テスト ケースの整数。各数値は、その位置から始まるピンボールの脱出時間を表します。 

制約は厳しいです:$n$まで可能です$5 \cdot 10^5$すべてのテスト ケースの合計もその数値によって制限されます。 ピンボールの各動きを個別にステップ実行する単純なシミュレーションでは、次のような時間がかかります。$O(n^2)$最悪の場合、遅すぎます。 すべての脱出時間を効率的に計算するには、問題の構造を利用する必要があります。 エッジケースは、境界線や連続する同方向の矢印、特に右端の「>」または左端の「<」のシーケンスで発生し、ピンボールがすぐに抜ける可能性があります。 

## アプローチ

 ブルートフォースアプローチは簡単です。 セルで始まる各クエリについて$i$、ピンボールの経路を段階的にシミュレートし、毎回矢印を更新し、グリッドから離れるまでカウンターを増分します。 これは正しく動作しますが、最大時間がかかります$O(n^2)$大きなグリッドの合計。 たとえば、「><><><><...」のような文字列を使用すると、各ピンボールがグリッドの大部分を移動することになり、クエリごとに数十万の移動が発生し、2 秒の制限時間を超えてしまう可能性があります。 

より速くアプローチするための重要な洞察は、各ピンボールの経路が最も近い「ボーダー フリップ ポイント」によって決定されるということです。 言い換えれば、終了するのにかかる時間は、最も近い境界につながる連続する同一の矢印の数に関係します。 ピンボールが左端に当たる前に左に移動できる距離、または右端に当たる前に右に移動できる距離を事前に計算しておけば、すべてのクエリに線形時間で答えることができます。 

ピンボールが一方向に移動すると、矢印が反転することがわかります。 次の動きが戻ると、再び反転します。 したがって、同じ矢印のシーケンスは、一方向の連続したステップを表すため、重要です。 最適な戦略は、位置ごとに最も近い境界または最も近いフリップ ポイントまでの距離を事前計算し、これらの距離を組み合わせて、2 パス リニア スキャンを使用して脱出時間を効率的に計算することです。

 ## アルゴリズムのチュートリアル

 1. テスト ケースごとに、矢印の文字列を読み取り、2 つの配列を初期化します。`left_steps`そして`right_steps`、長さの$n$、ピンボールがその位置から戻らずに左または右に移動し始めた場合に、ピンボールが出るまでにかかる歩数を保存します。 
2. 左から右へのパスを実行して埋める`right_steps`。 各セルの矢印が「>」の場合、ピンボールは右に移動します。 1 と次のセルの値を加算します (ピンボールが次にそこにステップし、同じ計算を継続するため)。 矢印が「<」の場合、ピンボールは左に移動しますが、再利用することはできません`right_steps`方向性が変わるから。 代わりに、次のステップですぐに左に移動するため、カウンターを 1 にリセットします。 
3. 右から左へのパスを実行して埋める`left_steps`対称的に。 矢印が「<」の場合、左隣に基づいてステップを増分します。 「>」の場合、カウンタは右に移動するのでリセットします。 
4. 組み合わせる`left_steps`そして`right_steps`各セルの合計脱出時間を計算します。 ピンボールは最初に示された方向に移動し、場合によっては矢印を反転し、境界に到達するまで動き続けます。 脱出時間は常に、一連の移動に沿って事前に計算された距離の合計になります。 
5. すべてのポジションの計算された時間を順番に出力します。 

機能する理由: このアルゴリズムは、同一の矢印のシーケンスではエスケープ時間が単調であるという事実を利用しています。 一方向に抜けるまでの距離を計算し、文字列に沿って動的プログラミングを使用することで、すべてのピンボールを個別にシミュレートするのではなく、計算を再利用できます。 2 パス スキャンにより、考えられる両方の初期方向を効率的にカバーできることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()
        ans = [0] * n

        # Find first left-most '<' and right-most '>'
        left_end = n
        for i in range(n):
            if s[i] == '>':
                left_end = i
                break

        right_end = -1
        for i in reversed(range(n)):
            if s[i] == '<':
                right_end = i
                break

        for i in range(n):
            if i <= left_end:
                ans[i] = i + 1
            elif i >= right_end:
                ans[i] = n - i
            else:
                ans[i] = max(i + 1, n - i)

        print(*ans)

solve()
```この解決策では、まず、ピンボールがすぐに左に出る場合の一番左の位置と、すぐに右に出る場合の一番右の位置が特定されます。 最初の「>」の前または最後の「<」の後の位置の場合、エスケープ時間は単に境界までの距離です。 中間の位置では、左右の距離の最大値により、最終的に矢印を反転して逃げることになる可能な限り長いパスがカウントされます。
