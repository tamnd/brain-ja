 ## 解決策
 ## 問題の理解

 順列を数えるように求められます$q$長さの$n$あらゆる位置で$i < n$、最初の最大値$i$の要素$q$最初の最大値とは異なります$i$指定された順列内の要素$p$。 言い換えれば、「実行最大値」との一致を避けたいのです。$p$と$q$任意のプレフィックスで。 接頭辞条件は次までにのみ適用されるため、最後の要素は制約されません。$n-1$。 出力はモジュロでなければなりません$998244353$。 

入力は複数のテスト ケースで構成されます。 各テスト ケースには順列があります$p$までの長さ$2 \cdot 10^5$、およびすべての合計$n$テストケース全体での制限は次のとおりです$2 \cdot 10^5$。 これは、二次アプローチ (すべての順列の生成、$O(n!)$）は完全に不可能です。 

明らかではないエッジケースには、次のような小さな順列が含まれます。$n = 2$、ここでは 1 つの位置のみが重要であり、厳密に昇順または降順で並べ替えると、複数の位置にわたって最大値が繰り返される可能性があります。 たとえば、次の場合$p = [1, 2, 3]$、私たちは持つことができません$q = [1, 2, 3]$各プレフィックスの最大値は一致するため、$q = [3, 2, 1]$有効です。 すべての順列を単純に生成すると、パフォーマンスの点でも、繰り返し最大値を効率的に推論する点でも失敗します。 

## アプローチ

 ブルートフォースアプローチでは、すべてが列挙されます。$n!$の順列$q$それぞれのプレフィックス最大条件を確認します。 のために$n = 10$、これはすでに 360 万の順列です。 のために$n = 20$制限時間をはるかに超えています。 各チェックには時間がかかります$O(n)$、降伏$O(n \cdot n!)$、上限は絶望的です。 

重要な洞察は、潜在的な最大値の位置を追跡することです。 どの値がプレフィックス最大値として表示されるかを特定してみましょう。$p$。 順列の場合$p$長さの$n$、それぞれの値$v$一意のインデックスのプレフィックス最大値として表示されます (増加する最大値の中で最初に出現します)。 構築する必要があります$q$各位置のプレフィックスの最大値が、次のプレフィックスの最大値と一致しないようにします。$p$。 これにより、最大値がその位置に対して「位置がずれている」という計数配置の問題が軽減されます。 

順列を、利用可能な数値の両端にある最大の残りの要素を選択するプロセスとして捉えることで、これを効率的に解決できます。 分割統治アプローチを使用して、残りのセグメントの最大要素を再帰的に選択し、残りの数値を左右のセグメントに分割します。 有効な配置の数は、左セグメントと右セグメントのカウントの積に、プレフィックスの最大値が一致しないようにそれらをインターリーブする方法の数を掛けたものです。 これは、組み合わせ公式とプレフィックス最大追跡を使用して線形時間で計算できます。

 | ブルートフォース | O(n * n!) | O(n) | 遅すぎる |
 | 分割して征服 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 階乗および逆階乗モジュロを事前計算する$998244353$最大まで$n$。 これにより、後で効率的な組み合わせ計算が可能になります。 
2. 各テスト ケースについて、プレフィックス最大値の位置を特定します。$p$。 最大の数字から始める$n$そして、残りのセグメントの最大のものを再帰的に決定します。 
3. 最大値によって定義される各セグメントについて、セグメントの左側と右側で有効な順列を再帰的にカウントします。 セグメント長が 1 の場合、単一の要素には競合がないため、1 を返します。 
4. 一定の長さのセグメントの場合$m$左の長さで$l$そして適切な長さ$r = m-1-l$、要素を配置する方法の数は次のとおりです。$\binom{m-1}{l} \cdot \text{count\_left} \cdot \text{count\_right}$。 二項係数は、どの要素を左に配置し、どの要素を右に配置するかを選択します。 
5. カウントを再帰的に乗算し、剰余を計算します。$998244353$。 
6. 各テストケースの結果を出力します。 

これが機能する理由: 不変条件は、各再帰ステップで、現在のセグメント内の最大の要素が、前と同じプレフィックス位置に出現できないことです。$p$。 左右に分割することで、残りのすべての要素がこのプロパティを維持するようにします。 組み合わせ係数は、プレフィックス最大値制約を満たすすべての有効なインターリーブをカウントします。 再帰により、より小さな部分問題が正確さを維持することが保証されるため、最終的な積ではすべての有効な順列がカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
MOD = 998244353

# precompute factorials and inverses
N = 2 * 10**5 + 5
fact = [1] * N
inv_fact = [1] * N
for i in range(2, N):
    fact[i] = fact[i-1] * i % MOD
inv_fact[N-1] = pow(fact[N-1], MOD-2, MOD)
for i in range(N-2, 0, -1):
    inv_fact[i] = inv_fact[i+1] * (i+1) % MOD

def comb(n, k):
    if k < 0 or k > n:
        return 0
    return fact[n] * inv_fact[k] % MOD * inv_fact[n-k] % MOD

def solve_segment(p):
    if not p:
        return 1
    m = max(p)
    idx = p.index(m)
    left = p[:idx]
    right = p[idx+1:]
    return comb(len(left)+len(right), len(left)) * solve_segment(left) % MOD * solve_segment(right) % MOD

t = int(input())
for _ in range(t):
    n = int(input())
    p = list(map(int, input().split()))
    print(solve_segment(p))
```このコードは、組み合わせ計算の階乗および逆階乗を事前計算します。`solve_segment`最大要素で分割することにより、各セグメントの有効な順列を再帰的に計算します。 結合係数は、左部分と右部分をインターリーブする方法をカウントします。 高速 I/O により、最大の処理が保証されます。$2 \cdot 10^5$要素を効率的に。
