 **評価:** 2400

 ## 解決策
 ## 問題の理解

 トラックの順序は決まっています。 私たちはすべてのトラックについて、その価値、車内の人数、および 2 つの恐怖の制約を知っています。 

トラックが生き残ってトンネルに入った場合、生き残ったすべてのトラックの間で次のことが行われます。 

- その前の人の合計数は等しくなければなりません`l`- その後の人数の合計は同じである必要があります`r`トラックのサブセットは削除できますが、残りのトラックの相対的な順序は変更できません。 私たちの目標は、生き残ったトラックの価値の合計を最大化することです。 

重要な詳細は、制約が元の位置ではなく、生き残っている人々の観点から表現されていることです。 生き残った車列に乗客数のトラックが含まれている場合:`c[a1], c[a2], ..., c[ak]`次に、選択したトラックごとに`ai`:

 -`c[a1] + ... + c[a(i-1)] = l[ai]`-`c[a(i+1)] + ... + c[ak] = r[ai]`両方の方程式を追加すると、次のようになります。`total_people = l[i] + c[i] + r[i]`これが初めての構造観察です。 生き残ったすべてのトラックは、最終的な車列内の合計人数が同じになるように同意する必要があります。 

制約が十分に大きいため、二次動的計画法は不可能です。 と`n = 10^5`、`O(n^2)`遷移数はおよそに達するでしょう`10^10`限界をはるかに超えた操作。 に近いものが必要です`O(n log n)`。 

難しいのは、条件がグローバルであることです。 トラックは前後の人数の合計が完全に一致する場合にのみ有効です。 トラックを個別にチェックする単純な実装は、1 つのトラックを選択すると、後続のすべてのトラックで認識されるプレフィックスの合計が変化するため、失敗します。 

次の例を考えてみましょう。```
3
5 2 0 2
5 2 2 0
100 1 0 0
```トラック 3 のみで合計人数が有効です`1`。 

トラック 1 と 2 は合わせて合計人数で有効です`4`。 

正解はトラック 3 のみです。`100`よりも大きいです`10`。 

互換性のあるチェーンを常に拡張するという貪欲な戦略では、トラック 1 と 2 が誤って保持されてしまいます。 

複数のトラックが同じプレフィックス要件を共有する場合、別の微妙なケースが発生します。```
4
10 1 0 2
1 1 0 2
10 1 1 1
10 1 2 0
```トラック 2 は、同じ合計内で互換性のないプレフィックスを必要とするため、トラック 3 と共存することはできません。 ローカル互換性のみをチェックする不注意な DP は、誤ってそれらを連鎖させる可能性があります。 

2 台のトラックが共存できないという特殊なケースもあります。```
2
5 1 0 0
7 2 0 0
```各トラックは個別に有効な護送隊を形成します。 答えはトラック 2 のみを選択する必要があります。 

これは、DP がどのトラックからでも新しい車列を出発することを当然許可しなければならないことを意味します。 

## アプローチ

 ブルートフォースアプローチでは、トラックのすべてのサブセットを列挙し、順序を保持し、残っているプレフィックスの合計を計算し、すべての制約を検証します。 これは有効性の定義が明示的であるため機能しますが、`2^40`もう絶望的だし、ここで`n`到達する`10^5`。 

より現実的な総当たり DP では、すべての先行バージョンを試すことになります。 トラックを左から右に処理し、次のように定義するとします。`dp[i] = best value of a valid convoy ending at i`から移行するには`j`に`i`、次のものが必要になります。 

- 両方のトラックは同じ総人口に属します
 - 前の人々`i`以前の人々と同等`j`プラス`c[j]`これはすでに連鎖構造を示唆しています。 トラックの場合`i`プレフィックス要件がある`l[i]`の場合、その前任者は次を満たさなければなりません。`l[j] + c[j] = l[i]`そして両方が同じものを共有する必要があります。`T = l + c + r`二次 DP は以前のすべてのトラックをチェックします`j`あらゆる人にとって`i`。 それは与える`O(n^2)`トランジション、まだ遅すぎる。 

重要な観察は、すべての遷移は次の 2 つの値のみに依存するということです。 

- 護送船団の合計`T`- 必要なプレフィックスの数`l`一定の合計に対して最適な輸送隊がわかっているとします。`T`プレフィックスの追加で終了します`x`。 次に、トラックには次のものが含まれます。 

- 合計`T`- プレフィックス`l = x + c_prev`すぐに延長できます。 

これにより、問題は次のようにインデックス付けされたスパース状態 DP に変換されます。`(T, l)`。 

各トラックについて:

 - 計算する`T = l + c + r`- 先行するものはすべて同じである必要があります`T`- 先行者の終了プレフィックスは等しい必要があります`l`したがって、次のように維持します。`best[T][prefix] = best achievable state`各状態には最大値と再構築情報が格納されます。 

ハッシュマップを使用すると平均が得られます`O(1)`遷移するため、ソリューション全体は線形になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース DP | O(n²) | O(n) | 遅すぎる |
 | 最適なハッシュ DP | O(n) 平均 | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. トラックを左から右に処理します。 

護送船団の順序は変更できないため、順序は重要です。 トラックの有効な前任者`i`入力の前の方に現れる必要があります。 
2. すべてのトラックについて、次を計算します。```
T = l[i] + c[i] + r[i]
```同じ生き残った車列内のすべてのトラックは、この正確な総人口を共有する必要があります。 
3. DP 状態のハッシュ マップを維持します。 

合計ごとに`T`、プレフィックス人口によってインデックス付けされた別のハッシュ マップを保存します。 

状態は次のことを表します。```
best[T][p]
```総人口が`T`現在のプレフィックス人口が等しい`p`。 
4. プレフィックスの意味を注意深く解釈してください。 

輸送隊がトラックで終了した場合`j`、それを受け取った後、護送船団に蓄積された人の合計は次のようになります。```
l[j] + c[j]
```これは、次の互換性のあるトラックで必要なプレフィックスになります。 
5.トラック用`i`、前の状態を探します。```
best[T][l[i]]
```以前の護送船団はトラックで延長されたため、`i`すでに正確に含まれている必要があります`l[i]`人々。 
6. そのような状態が存在する場合は、それを拡張します。```
new_value = previous_value + v[i]
```それ以外の場合はトラック`i`次の場合にのみ新しい護送隊を開始できます`l[i] == 0`。 

トラックから始まるコンボイ`i`その前には人がいない。 
7. 新しいコンボイは蓄積されたプレフィックスで終了します。```
l[i] + c[i]
```アップデート：```
best[T][l[i] + c[i]]
```新しい値の方が優れている場合。 
8. 更新中に親ポインタを保存します。 

再構築のために、次のことを維持します。 

- 以前の状態
 - 以前のトラックインデックス
 9. 累積プレフィックスが等しいすべての州の中で`T`、最大値を選択します。 

護送隊は、累計人数の合計が護送隊の合計と等しくなった場合にのみ完了します。 

### なぜ効果があるのか

 生き残ったすべての輸送隊は、厳密に増加するプレフィックス集団のシーケンスを定義します。```
0,
c[a1],
c[a1]+c[a2],
...
```トラック用`ai`、その前の人々は、独自の乗客を追加する前の累積人口と正確に等しくなります。 その値は`l[ai]`。 

DP 状態`best[T][p]`総人口を含む最適な部分的な護送船団を表す`p`護送船団内にすでに蓄積されており、最終的な合計は`T`。 

次のトラックが必要なときこそ、移行は合法です。`l[i] = p`。 コンボイ内のすべてのトラックは同じ合計を共有するため、`T`、構築されたすべてのシーケンスは、前面と背面の両方の恐怖条件を自動的に満たします。 

すべてのコンボイは、増加するプレフィックス合計に従って一意に再構築できるため、有効なコンボイが見逃されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    trucks = [None]

    for _ in range(n):
        v, c, l, r = map(int, input().split())
        trucks.append((v, c, l, r))

    # dp[T][prefix] = (best_value, state_id)
    dp = {}

    # state:
    # value, previous_state, truck_index, T, prefix
    states = [None]

    best_final = -1
    best_state = -1

    for i in range(1, n + 1):
        v, c, l, r = trucks[i]

        T = l + c + r

        if T not in dp:
            dp[T] = {}

        cur_map = dp[T]

        best_val = -1
        prev_state = -1

        if l == 0:
            best_val = v

        if l in cur_map:
            prev_val, st_id = cur_map[l]

            if prev_val + v > best_val:
                best_val = prev_val + v
                prev_state = st_id

        if best_val == -1:
            continue

        new_prefix = l + c

        new_state_id = len(states)
        states.append((best_val, prev_state, i, T, new_prefix))

        if (
            new_prefix not in cur_map
            or best_val > cur_map[new_prefix][0]
        ):
            cur_map[new_prefix] = (best_val, new_state_id)

        if new_prefix == T and best_val > best_final:
            best_final = best_val
            best_state = new_state_id

    ans = []

    while best_state != -1:
        value, prev_state, truck_idx, T, prefix = states[best_state]
        ans.append(truck_idx)
        best_state = prev_state

    ans.reverse()

    print(len(ans))
    print(*ans)

solve()
```実装における中心的な考え方は、DP 状態の解釈です。 

総人口が一定の場合`T`、護送船団内の進歩を特定する鍵は、これまでの累積人口です。 パラメータを使用してトラックを選択した後`(c, l)`、累積人口は次のようになります。`l + c`。 

移行ステップ:```
if l in cur_map:
```正確に含む有効な部分コンボイをすでに構築していることを意味します`l`人々。 トラック`i`恐怖の制約には正確な要求があるため、合法的に次に来る可能性があります`l`その前の人たち。 

初期化:```
if l == 0:
    best_val = v
```このトラックから護送隊を出発できるようになります。 

微妙な点は、次の状態を更新することです。`new_prefix = l + c`、のためではありません`l`。 新しい状態は、現在のトラックを挿入した後の輸送隊を記述します。 

もう 1 つの簡単な間違いは、複数のパスが同じにつながる可能性があることを忘れることです。`(T, prefix)`州。 今後の遷移はこれら 2 つの数値のみに依存するため、最大値のみを保持します。 弱い状態は後で最適になることはありません。 

再構築では、インデックスの配列をコピーする代わりに、親状態 ID を保存します。 これにより、記憶が直線的に保たれます。
