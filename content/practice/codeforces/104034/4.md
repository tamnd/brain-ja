 ## 解決策
 ## 問題の理解

 まず、各値が数直線上にあるトークンのように動作する配列から始めます。 許可される移動は、1 エネルギーを消費して 1 つのユニットが残す小さなステップ、または k エネルギーを消費して床 (x/2) への大きなジャンプのいずれかです。 タスクは、すべてのトークンの合計コストを最小限に抑えて、すべてのトークンを値 1 まで下げることです。 

配列要素は、1 つの要素に対する操作が他の要素に影響を与えないという意味で独立しているため、問題は各値 ai の最小コストを計算し、結果を合計することに帰着します。 

この制約では、最大約 5×10^4 の数値 (それぞれ最大 10^9) が許可されます。 これにより、最悪の場合、すべての減分を個別に処理するステップごとのシミュレーションが即座に排除されます。10^9 のような単一の値を単純に処理すると、数十億回の演算が必要になるからです。 どのソリューションでも、各値が対数時間以上で処理されるように遷移を圧縮する必要があります。 

微妙な問題は、「可能な場合は常に除算する」または「偶数になるまで常に減分する」などの貪欲なローカル決定は失敗する可能性があることです。 たとえば、k が大きい場合、早期に分割を繰り返すと最適なパスをオーバーシュートする可能性があります。これは、半分にすることは、後で多くの単位の減分を回避する場合にのみ有益であるためです。 逆に、k が小さい場合、除算を無視すると、大きな範囲がすぐに崩壊してしまうため、無駄になります。 

具体的な失敗例は、k が中程度で、値が 2 の累乗をわずかに超える場合に現れます。 x = 17 で、k が 8 よりわずかに大きいとします。直接半分にすると、コスト k で 17 → 8 が得られ、次に 8 → 4 → 2 → 1 になりますが、最初に減分を行う方がコストが安くなる可能性があります。 「可能な場合は常に半分にする」という貪欲なアプローチは、誤って高価なジャンプを強制することになります。 

最大の難しさは、各数値が半分と減算を交互に繰り返すパスを介して 1 に達する可能性があり、指数関数的に多くのそのようなパスの中から最適なシーケンスを選択する必要があることです。 

## アプローチ

 ブルート フォース アプローチでは、各値を独立して扱い、1 に到達するまですべての可能な一連の操作を試行します。デクリメントするたびに値が 1 ずつ減り、除算ごとに値が半分になります。そのため、ai までのすべての整数が到達可能であるため、状態の数は依然として多くなります。 明白なサイクルを枝刈りしても、数値ごとの最悪の探索は ai に比例し、O(∑ ai) となり、10^9 までの値では完全に実行不可能です。 

重要な観察は、最適なパスの構造が非常に制限されているということです。 一連の演算は常に下方向に進み、2 で除算すると対数構造が作成されます。任意の x から、半減を繰り返すと、O(log x) ステップで 1 に達します。 これは、繰り返されるフロアを 2 で分割するチェーンに沿った状態のみを考慮する必要があることを示唆しています。 

x から 1 まで前向きに考えるのではなく、視点を逆転させます。 半減演算の下で、x から 1 までのパス上に現れる可能性のあるすべての数値を考慮します。 これらの数値は、x、floor(x/2)、floor(x/4) などのチェーンを形成します。 これらの「アンカー ポイント」間では、移動する唯一の方法は減少することです。 

したがって、最適な戦略は、x を繰り返し半分にすることによって得られるすべての可能な数値 y を試し、除算して y に到達するまでのコストを計算し、1 まで減算して終了することです。そのような各 y について、コストは、半分にするステップの数の k 倍と残りの線形コスト y − 1 で構成されます。このようなすべての選択肢の最小値を採用します。 

これにより、各要素が O(log x) 個の候補に減り、問題全体が効率的になります。

 ## アルゴリズムのチュートリアル

 それぞれの数値について、除算演算を繰り返し適用することで到達可能なすべての状態を調べます。

1. 元の値 x から開始し、答えを無限大として初期化します。 
2. 2 によるフロア除算を繰り返し適用した後、値を追跡する可変電流を維持します。 
3. このような現在の値ごとに、特定の数の除算演算を使用してその値に到達するコストを考慮します。 
4. この時点でも、減算演算のみを使用して電流を 1 まで減らす必要があり、そのコストは電流 − 1 になります。 
5. これら 2 つのコストを組み合わせて、答えを更新します。 
6. それ以上の遷移は無関係であるため、電流が 0 になるまで電流を 2 で除算し続けます。 

重要な考え方は、すべての最適なパスを次のようにみなすことができるということです。除算を何回か適用し、その後完全に減算に切り替えます。 減算、除算、再度減算などの代替は、コストを増加させることなくこの形式に再構築できます。減算は除算前の値を減らすだけであり、追加のコストを補う方法で必要な除算の数を改善することはできないためです。 

### なぜ効果があるのか

 不変条件は、x から到達可能なすべての状態は、バイナリ半分化チェーンの深さ d を選択し、正確に d 回の除算演算に、結果の値から 1 までの線形コストを加えたものとして表現できるということです。任意の混合シーケンスは、選択したすべての除算が終わるまですべての減分を延期することによって、この標準形式に変換できます。 除算コストは​​固定され、減算コストは​​残りの値において線形であるため、この変換によってコストが増加することはありません。そのため、減算を早く実行しても、同じエンドポイントに到達するために必要な除算の数を減らすことはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    k = int(input())
    a = [int(input()) for _ in range(n)]

    ans = 0

    for x in a:
        cur = x
        best = float('inf')

        steps = 0
        while cur > 0:
            cost = steps * k + (cur - 1)
            if cost < best:
                best = cost
            cur //= 2
            steps += 1

        ans += best

    print(ans)

if __name__ == "__main__":
    solve()
```各数値は独立して処理されます。 cur に対するループは半分化チェーンに従いますが、ステップではコストのかかる除算演算が使用された回数がカウントされます。 (cur − 1) という項は、減算のみで終了することを意味します。 

よくある間違いは、ゼロ除算をまったく適用する状態 (最初の反復で cur = x に相当する) を含める必要があることを忘れていることです。 もう 1 つの微妙な問題は、中間コストが 10^9 を超える可能性があるため、固定 32 ビット整数を使用する言語で実装された場合にオーバーフローが発生することです。 

## 実用的な例

 ### 例 1

 入力:

 x = 4、k = 1

 半分化チェーンを追跡します。 

| ステップ | カー | コスト = ステップ*k + (cur−1) |
 | --- | --- | --- |
 | 0 | 4 | 3 |
 | 1 | 2 | 1 |
 | 2 | 1 | 2 |
 | 3 | 0 | 3 |

 最小値は cur = 2 で得られる 1 です。これは、1 回の除算 (4 → 2) から 1 まで減算することに相当します。 

これは、最適な解が常に減算または除算によって完全に減少するとは限らず、中間の半分の点で停止する可能性があることを確認します。 

### 例 2

 入力:

 x = 10、k = 100

 | ステップ | カー | コスト |
 | --- | --- | --- |
 | 0 | 10 | 9 |
 | 1 | 5 | 100 + 4 = 104 |
 | 2 | 2 | 200 + 1 = 201 |
 | 3 | 1 | 300 + 0 = 300 |

 最高は 9 です。これは、コストのかかる除算演算をまったく使用しないことを意味します。 

これは、k が大きい場合、アルゴリズムがすべての半分の遷移を自然に拒否することを示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input())
    k = int(input())
    a = [int(input()) for _ in range(n)]

    ans = 0
    for x in a:
        cur = x
        best = float('inf')
        steps = 0
        while cur > 0:
            best = min(best, steps * k + (cur - 1))
            cur //= 2
            steps += 1
        ans += best

    return str(ans)

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、値がすでに 1 である場合です。アルゴリズムはゼロ操作を正しく許可する必要があります。 最初の状態が cur = x をチェックし、コスト 0 を与えるため、これがキャプチャされます。 

もう 1 つのケースは 2 の大きなべき乗で、繰り返し半分にするとすぐに 1 に達します。 アルゴリズムはすべての中間パワーを正確に探索し、正しい深度で最小値が見つかるようにします。 

k が非常に大きい場合、線形減分と比較して、各半分のステップがすぐにコストが高すぎるため、アルゴリズムは自然に除算を完全に回避します。 これは、貪欲にコミットするのではなく、すべての候補状態を評価することによって自動的に処理されます。 

最後の微妙なケースは、最適な停止点が x や 1 ではなく、2 や 4 などの中間値である場合です。半減チェーンにより、これらが常に訪れることが保証されるため、アルゴリズムは有効な最適値を決して見逃すことはありません。
