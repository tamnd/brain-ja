 ## 解決策
 ## 問題の理解

 各テスト ケースでは単語が与えられ、その単語について、正確に 1 文字を挿入した後、短い文字列の「拡張」バージョンとして認識できるかどうかを判断する必要があります。 

より正確には、文字列を探しています。`t`のどこかに 1 文字を挿入すると、`t`、与えられた単語を取得します`s`。 から 1 文字を削除するすべての方法の中で、`s`の場合、同じ方法で他の位置を削除しても結果として短い文字列が生成されない、少なくとも 1 つの削除位置が必要です。 そのような位置が存在する場合は、その結果の文字列を出力します。 それ以外の場合は出力します`-1`。 

入力サイズは単語数という点では非常に小さく、最大でも 10 文字ですが、各単語は非常に長くなり、最大 10 万文字になる可能性があります。 この不均衡は重要です。各語長で二次関数を再計算しようとするソリューションはすぐに失敗しますが、ワードごとの線形スキャンは簡単に十分です。 

微妙な失敗例は、単語に繰り返し文字のみが含まれている場合に発生します。 たとえば、次のように考えてみましょう`"aaaa"`。 任意の 1 つの位置を削除すると、常に次の結果が得られます。`"aaa"`ただし、同じ結果を生成する有効な削除位置が複数あるため、「挿入位置」は一意ではありません。 その場合の正解は、`-1`たとえもっと短い文字列が存在したとしても。 

もう 1 つの特殊なケースは、次のような単語です。`"abca"`。 最初のものを削除する`'a'`そして最後`'a'`どちらも生産します`"bca"`したがって、結果は曖昧で無効です。 単純に任意の位置を削除する単純なアプローチでは、そのようなケースを誤って受け入れることになります。 

## アプローチ

 この問題を考える簡単な方法は、単語内のすべての可能な位置を試し、その文字を削除し、その結果を候補タスク文字列として扱うことです。 これは原理的には正しいです。すべての有効なタスク文字列は、正確に 1 文字を削除することで得られる必要があります。 

ただし、正しさだけでは十分ではありません。 削除も一意である必要があります。 2 つの異なる位置から同じ短縮文字列が生成される場合、削除された文字をその文字列に挿入し直しても一意の位置は決定されず、要件に違反します。 

直接のブルートフォース実装では、インデックスごとに短縮文字列を構築し、それを他のすべての削除と比較して一意性を確保します。 これにより、$O(n^2)$削除されるたびに新しい長さの文字列が作成されるため、単語ごとに構築されます。$O(n)$、比較も$O(n)$。 最大の単語長$10^5$、このアプローチは完全に不可能になります。 

重要な観察は、削除された文字が同一で周囲の構造がすべて同じである場合にのみ、2 つの異なる削除位置が同じ結果を生み出す可能性があるということです。これは、削除された文字が単語内に複数回出現する場合にのみ可能です。 これにより、一意性条件は単純な頻度チェックに縮小されます。つまり、削除位置は、その位置の文字が単語全体で 1 回だけ出現する場合にのみ有効になります。 

これにより、問題は組み合わせ検索から単語ごとの単一の頻度スキャンに変わります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 単語ごとの O(n³) ワーストケース | O(n) | 遅すぎる |
 | 周波数ベースのスキャン | 単語ごとに O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 各単語を個別に処理します。 

1. 単語内のすべての文字の頻度を数えます。 これにより、どの文字がユニークで、どの文字が繰り返されるかがわかります。 これを最初に行う理由は、削除の一意性は完全に、その文字が他の場所にある別の同一の文字と一致するかどうかに依存するためです。 
2. 単語を左から右にスキャンし、文字列全体でその文字が 1 回だけ出現する位置を探します。 他の削除では同じ文字を削除して同じ結果が得られないため、この位置は安全です。 
3. そのような位置が見つかった場合は、その文字を削除して応答文字列を構築し、すぐに出力します。 有効なタスク文字列はどれでも受け入れられ、問題は辞書編集上の最小または最大の結果を必要としないため、早期に停止できます。 
4. 固有に発生する文字が見つからずにスキャンが完了した場合は、次の出力が行われます。`-1`。 これは、単語内のすべての文字が少なくとも 2 回出現することを意味するため、削除の可能性はすべて曖昧になります。 

正確性の背後にある中心的な考え方は、一度出現した文字を削除すると、結果の文字列と元の位置との間に 1 対 1 のマッピングが作成されるということです。 単語内の他の場所には同一の文字が存在しないため、他のインデックスは同じ短縮文字列を生成できません。 逆に、すべての文字が複数回出現する場合、削除は同じ文字の別の位置に反映され、一意性が損なわれる可能性があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    if not s:
        return

    from collections import Counter
    cnt = Counter(s)

    for i, ch in enumerate(s):
        if cnt[ch] == 1:
            print(s[:i] + s[i+1:])
            return

    print(-1)

if __name__ == "__main__":
    solve()
```実装は周波数優先戦略に直接従います。 の`Counter`文字の頻度を線形時間で計算します。 次に、スキャンによって各位置がチェックされ、最初の有効な削除がすぐに出力されます。 

一般的な実装の落とし穴は、実際にすべての可能な削除を作成し、文字列を比較することによって一意性を検証しようとすることですが、これが暗黙のうちに二次関数になってしまいます。 もう 1 つの間違いは、隣接する文字が異なるかどうかなど、グローバルな一意性要件とは関係のない、ローカルな条件のみをチェックすることです。

## テストケース```python
import sys, io
from collections import Counter

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = []
    n = int(input())
    for _ in range(n):
        s = input().strip()
        cnt = Counter(s)
        ans = -1
        for i, ch in enumerate(s):
            if cnt[ch] == 1:
                ans = s[:i] + s[i+1:]
                break
        out.append(str(ans))
    return "\n".join(out)

# provided sample
assert run("4\naaab\nzzz\njunior\ntracktor\n") == "-1\n-1\nunior\ntrcktor"

# all equal characters
assert run("1\naaaa\n") == "-1"

# single unique middle character
assert run("1\naabaaa\n") == "aabaaa".replace("b","")

# unique only at end
assert run("1\nxxxy\n") == "xxx"

# already valid mixed
assert run("1\nabca\n") == "-1"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`aaaa`|`-1`| 一意の削除は不可能 |
 |`abca`|`-1`| 重複文字のあいまいさ |
 |`xxxy`|`xxx`| 末尾のユニークな文字 |
 |`aabaaa`|`aabaaa`それなし`b`| 中央の一意の文字のケース |

 ## 特殊なケース

 すべての文字が同一である単語 (例:`"bbbbbb"`、これは、単純な削除戦略が失敗することを示しています。 すべての削除によって生成されるのは、`"bbbbb"`ただし、各結果は複数の位置から取得できるため、有効なタスク文字列は存在せず、出力は次のようにする必要があります。`-1`。 

みたいな言葉で`"abca"`、いずれかを削除します`'a'`同じ短縮された文字列が生成されます`"bca"`。 これより短い文字列が存在する場合でも、それは一意の挿入位置に対応しないため、頻度が正確に 1 の文字がないため、アルゴリズムはその文字列を正しく拒否します。
