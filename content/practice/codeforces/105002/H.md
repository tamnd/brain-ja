 ## 解決策
 ## 問題の理解

 ラテン文字の小文字で構成される文字列が与えられます。 2 人のプレイヤーが交互にターンします。 ターンでは、プレイヤーは文字列から 1 つの文字を削除できますが、その文字がどちらの端にもなく、削除しても 2 つの同一の隣接する文字が作成されない場合に限ります。 プレイヤーは、プレイヤーが正当な手を持たなくなり、そのプレイヤーが負けるまで続行します。 初期文字列には、隣接する等しい文字がないことが保証されます。 

キーオブジェクトは文字そのものではなく、削除可能な位置です。 エンドポイントは決して削除できないため、重要なのは内部の文字だけであり、その中でも、ある文字は、削除後に隣接する文字が異なるままである場合にのみ削除可能です。 

までの制約$10^6$文字列は、移動ごとに明示的に文字列を更新するシミュレーションを即座に除外します。 移動ごとに線形時間で文字列を繰り返しスキャンまたは変更するソリューションは、最悪の場合、二次的な動作に低下しますが、これは実行不可能です。 

微妙な点は、削除によって将来の移動の可能性が変わる可能性があるということです。 キャラクターを削除すると、新しい削除可能なポジションが作成されたり、既存のポジションが破壊されたりするため、構造が動的に進化します。 これにより、グローバル不変式を使用しない貪欲な「常に何かを削除する」シミュレーションが排除されます。 

いくつかのエッジ パターンによって落とし穴が明らかになります。 

たとえば、文字列が厳密に交互になる場合、`ababab`、最初はすべての内部位置が削除可能に見えますが、削除後は隣接制約により近くの移動が無効になる可能性があります。 初期の取り外し可能なポジションをカウントする単純な戦略では、カウントしすぎてしまいます。 

文字列に単一の文字で区切られた同じ文字の孤立した「ブロック」がある場合、1 つの文字を削除するとコンテキストがマージされ、遠く離れた有効な動きが突然作成または破壊される可能性があります。 

正しい解決策は、局所的な除去可能性を直接追跡するのではなく、最適なプレイの下で安定を保つグローバルな不変量を捕捉する必要があります。 

## アプローチ

 ブルートフォースアプローチはゲームをシミュレートします。 現在の文字列を維持し、すべての内部位置をスキャンして有効な削除を見つけ、移動を適用し、移動がなくなるまで繰り返します。 各スキャンにかかる費用$O(n)$、最大まであります$O(n)$削除、与える$O(n^2)$時間。 と$n = 10^6$、これはまったく不可能です。 

重要な観察は、ゲームが実際に重要なのは文字ではなく、独立した「安全な内部スロット」がどれだけ存在するかであるということです。 文字列には最初は等しい隣接文字がないため、すべての削除は、交互構造を局所的に保持しながら、内部位置を 1 つ削除するものと考えることができます。 隣接制約により、等しい隣接文字の作成が妨げられます。つまり、削除では同一の文字をマージできず、交互を維持しながら文字列が短縮されるだけです。 

この構造は、重要なのは内部ポジションの観点から最初に有効な手がいくつ存在するかだけであることを意味します。 各移動はちょうど 1 文字を削除しますが、文字列が交互に残るという事実は基本的に変わりません。 したがって、ゲームは単純な計数問題に帰着します。プレイ可能な内部ポジションの数は、最適なプレイ全体で同等に固定されます。 

ポジションだけなので$2$を通して$l-1$候補として存在し、パリティを変更する方法で将来の手を定義する機能を変えることなく、すべての手がそれらのうちの 1 つを正確に削除する場合、勝者はこのカウントが奇数か偶数かによって決まります。 

つまりゲームはコンピューティングに崩壊する$l - 2$、内部位置の数、およびパリティの決定。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション |$O(n^2)$|$O(n)$| 遅すぎる |
 | パリティ削減 |$O(1)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 文字列の長さを読み取ります。 隣接関係の制限は初期設定ですでに保証されているため、実際の文字は最終的な決定とは無関係です。 
2. 取り外し可能な位置の数、つまり内部インデックスの数を計算します。 これは$l - 2$。 これらはまさにエンドポイントではない位置です。 
3. この数値が奇数か偶数かを判断します。 
4. 奇数の場合は、最初の手が最後の手まで強制交代のシーケンスを開始するため、最初のプレーヤーが勝ちます。 偶数の場合は、完全にペアがオフになるため、2 番目のプレーヤーが勝ちます。 

### なぜ効果があるのか

 すべての移動は内部文字を 1 つだけ削除し、以前は無効だった位置が構造的に新しい独立したコンポーネントとなり、利用可能な移動の合計の同等性が変化するという状況を引き起こす移動はありません。 したがって、ゲームは固定パイルサイズのテイクアウェイゲームのように動作します。$l - 2$。 最適なプレイとは、枯渇するまで交互に除去を行うことになるため、この山の同等性が勝者を決定します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    s = input().strip()
    # only interior positions matter
    moves = n - 2
    if moves % 2 == 1:
        print("First")
    else:
        print("Second")

if __name__ == "__main__":
    solve()
```実装では、文字列の内容を読み取った後は完全に無視されます。これは、初期に等しい隣接文字がないことが保証されているため、構造の変更を追跡する必要がなくなるからです。 

唯一の微妙な点は、短い長さを確実に正しく処理できるようにすることです。 いつ$n = 3$、内部ポジションは 1 つだけなので、最初のプレイヤーが常に勝ちます。 式$n - 2$これを直接処理します。

 ## 特殊なケース

 ### 最小長の動作

 入力:```
3
abc
```内部キャラクターは 1 人だけです。 アルゴリズムは計算します$3 - 2 = 1$これは奇数であるため、First が返されます。 最初の動きの後にゲームは終了し、最小ではないサイズでの正しさが確認されます。 

### 最大交互構造

 入力:```
10
ababababab
```内部の位置は 8 です。アルゴリズムは次のように計算します。$10 - 2 = 8$、これは偶数であるため、Second を返します。 すべての文字が交互に配置され、構造が非常に動的であるように見えますが、グローバル不変式を変更せずに、移動するたびに同じカウントが 1 つずつ減少するため、パリティ引数は変化しません。
