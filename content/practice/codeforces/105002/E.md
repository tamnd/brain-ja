 ## 解決策
 ## 問題の理解

 私たちには、一定の順序で並べられた一連のカードが与えられます。 各カードには 1 から m までの整数値が含まれます。 カードのサブセットを削除することはできますが、残りのカードを並べ替えることはできません。 削除後、残りのシーケンスは厳密に 1 つずつ増加するチェーンを形成する必要があります。これは、隣接するすべてのペアが 1 つずつ正確に異なることを意味します。 

したがって、タスクは、元の順序を維持しながら、x、x+1、x+2 などのような部分列を選択し、残っているカードの枚数を最大化することです。 

重要な点は、任意のカードを選択しているのではなく、連続する整数の実行のように動作する部分列を選択しているということです。 

n ≤ 100000 という制約により、すべてのサブシーケンスを試行したり、すべての開始点を試行してネストされたスキャンで貪欲に拡張したりするソリューションは除外されます。 二次関数以上のものはタイムアウトになります。 線形または n log n に近いものが必要です。 

値が繰り返される場合、または複数の候補チェーンが重なっている場合、微妙なエッジ ケースが発生します。 たとえば、配列が 1 2 1 2 3 の場合、多くのチェーンを拡張できると考えたくなるかもしれませんが、重要なのは順序を考慮したサブシーケンスと正確な +1 遷移のみであるため、頻度だけではなく実現可能性を注意深く追跡する必要があります。 

もう 1 つの注意が必要なケースは、最適なチェーンがその開始値の最初の出現位置と一致しない場合です。 たとえば、2 3 2 1 4 では、最初の 2 から開始することは、後の 2 から開始するよりも、より長い連続実行を構築する上で悪くなります。 

## アプローチ

 ブルートフォース解釈では、すべての開始位置 i を試し、a[i] をチェーンの始まりとして扱い、貪欲に右にスキャンして a[i]、a[i]+1、a[i]+2 などを収集します。 開始するたびにポインターを維持し、前方へのスキャンを繰り返して、次に必要な値を見つけます。 これは正しく機能します。有効なサブシーケンスは要素を順番に選択する必要があり、可能な限り早い出現を貪欲に取得することで実現可能性が保たれるためです。 

ただし、このアプローチではアレイが繰り返しスキャンされます。 最悪の場合、n 個の開始位置のそれぞれについて、最大 n 個の要素をスキャンして、O(n²) が得られる可能性があります。 n が最大 100000 の場合、これは約 10¹⁰ の操作となり、実行可能ではありません。 

構造上の観察は、開始値 x を固定すると、問題は、選択した位置の後に次に出現する x+1 を繰り返し見つけることになるということです。 「インデックス p の次に値 v が出現する」と素早く答えることができれば、各チェーンを効率的にシミュレートできます。 これは、各値の位置を前処理し、二分探索を使用することを示唆しています。 

値ごとに、それが表示されるインデックスのソートされたリストを保存します。 次に、値 x を持つ特定の開始位置 i について、現在のインデックスの後に現れる x+1 の最初の出現箇所に繰り返しジャンプして前方に進みます。 各ジャンプには二分探索による O(log k) のコストがかかり、最大で m ステップを実行しますが、実際には既存の連続した値に沿ってのみ実行されます。 

これにより、アレイ全体を繰り返しスキャンするのではなく、実行可能なチェーンのみをスキャンするという問題が軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 位置リスト + 二分探索 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各値 v から、配列内で v が出現するインデックスのリストへのマッピングを構築します。 

これにより、ソートされた順序で任意の値の出現を迅速に見つけることができます。 
2. 配列内のすべてのインデックス i を反復処理し、それを潜在的な開始点として扱います。 

a[i] から始まる最長の有効な連続サブシーケンスを構築しようとします。 
3. 現在の値を a[i]、現在位置を i とします。 長さを 1 に初期化します。 
4. 現在の値 + 1 の値までチェーンを延長することを繰り返し試みます。

その値の位置リストを検索し、二分探索を使用して現在の位置より厳密に大きい最小のインデックスを見つけます。 
5. そのようなインデックスが存在する場合は、そのインデックスに移動し、チェーンの長さを増やして続行します。 

存在しない場合、チェーンは停止します。 
6. すべての開始位置にわたって最大チェーン長さを追跡します。 

各ステップでは、厳密に連続した値のみを選択しながら、常に元の順序を尊重することが保証されます。 

### なぜ効果があるのか

 有効な解決策の場合、サブシーケンスは値 v の開始位置に固定されている必要があります。その時点以降、次の要素はすべて、前の選択後の最初に使用可能な v+1 の出現でなければなりません。 後で何かを選択しても、将来の選択肢が減るだけです。 したがって、最も早い有効な次の出現への貪欲なジャンプによって最適性が低下することはありません。 すべての開始インデックスが考慮されるため、考えられるチェーンを見逃すことはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from bisect import bisect_right

n, m = map(int, input().split())
a = list(map(int, input().split()))

pos = [[] for _ in range(m + 2)]
for i, v in enumerate(a):
    pos[v].append(i)

ans = 1

for i in range(n):
    v = a[i]
    cur_idx = i
    length = 1

    while v + 1 <= m:
        lst = pos[v + 1]
        if not lst:
            break
        j = bisect_right(lst, cur_idx)
        if j == len(lst):
            break
        cur_idx = lst[j]
        v += 1
        length += 1

    if length > ans:
        ans = length

print(ans)
```このソリューションは、すべての「次のステップ」クエリが二分探索になるように位置を前処理することに依存しています。 最適なチェーンは、任意の値の出現時に開始される可能性があるため、外側のループでは、考えられるすべての開始インデックスが試行されます。 内側のループは連続する値を順に進み、常に最も早い実行可能な値にジャンプします。 

インデックスの厳密な前進を保証する必要があるため、bisect_right の使用は不可欠です。 同じカードを再利用できないため、平等は許可されません。

## 複雑さの分析

## テストケース```python
import sys, io
from bisect import bisect_right

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n, m = map(int, input().split())
    a = list(map(int, input().split()))

    pos = [[] for _ in range(m + 2)]
    for i, v in enumerate(a):
        pos[v].append(i)

    ans = 1

    for i in range(n):
        v = a[i]
        cur = i
        length = 1
        while v + 1 <= m:
            lst = pos[v + 1]
            if not lst:
                break
            j = bisect_right(lst, cur)
            if j == len(lst):
                break
            cur = lst[j]
            v += 1
            length += 1
        ans = max(ans, length)

    return str(ans)

# provided samples
assert solve("5 4\n2 3 2 1 4\n") == "3"
assert solve("7 10\n1 2 3 4 7 8 9\n") == "4"
assert solve("3 8\n3 2 1\n") == "1"

# custom cases
assert solve("1 5\n3\n") == "1", "single element"
assert solve("5 5\n1 1 1 1 1\n") == "1", "all equal"
assert solve("6 6\n1 3 2 4 5 6\n") == "4", "interleaving but valid chain"
assert solve("8 8\n8 7 6 5 4 3 2 1\n") == "1", "strictly decreasing"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 単一要素 | 1 | 最小サイズの正確性 |
 | すべて等しい | 1 | 連続した遷移は不可能です |
 | インタリーブですが有効なチェーン | 4 | 順序に依存した構築 |
 | 厳密に減少 | 1 | 連鎖の最悪の順序 |

 ## 特殊なケース

 主なエッジ ケースは、必要な値が複数存在するが、後続の値のみが継続を許可する場合です。 たとえば、1 2 1 2 3 では、最初の 2 から開始すると行き止まりになる可能性がありますが、2 番目の 2 から開始すると 3 に到達できます。アルゴリズムはこれを処理します。これは、すべての出現が開始点とみなされ、二分検索では常に現在の位置の後に最初に有効な次の出現が選択されるためです。 

もう 1 つのケースは、シーケンスの途中で値が欠落している場合です。 1 と 3 は存在するが 2 が存在しない場合、1 より長いチェーンは形成できません。 この状況では、2 の位置リストは空であり、アルゴリズムは拡張を即座に停止し、ギャップを介した誤った連鎖を正しく防止します。 

最後の微妙なケースは、1 1 1 2 2 3 のように、順番にクラスター化された繰り返し値です。アルゴリズムは常にインデックス空間内で前方にジャンプするため、以前の重複の再利用を回避し、長さ 3 で達成可能な最大のチェーン 1 → 2 → 3 を見つけます。
