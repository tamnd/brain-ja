 ## 解決策
 ## 問題の理解

 サイズ n × m のグリッドが与えられます。各セルには、空のセルを示す文字またはドットが含まれます。 このグリッド上で、指定された単語 s が有効な「スネーク」パスとしてすでに表示されているかどうかを判断したいと考えています。 

有効な外観とは、開始セルを選択し、各ステップが隣接するセルに進むように 4 つの基本方向に段階的に移動できること、セルを再利用することがないこと、訪問されたセルのシーケンスが正確な順序で表示されることを意味します。 すでに文字が含まれているセルのみが使用可能であり、訪問した各セルの文字は s の対応する文字と一致する必要があります。 

単語 s には、そのすべての文字が異なるという追加の特性があります。 この制限は、成功したパスの長さを最大 26 に制限し、単語内の同じ文字位置の再訪問を防ぐため、重要です。ただし、パス ルールを強制しない限り、グリッド セルの再訪問を直接妨げるわけではありません。 

グリッド自体の合計サイズは最大 10^6 セルに達する可能性があるため、グリッド構造に対して単純な DFS 方式ですべてのパスを検索しようとするソリューションは、指数関数的な数のパスを探索する危険があり、時間内に終了しません。 

素朴な解決策を壊すことが多い微妙な点は、分岐とパスの有効性の間の相互作用です。 単語が短い場合でも、単一の文字がグリッド内の多くの位置に出現する可能性があり、出現するたびに単純に後戻りすることで、重複する領域を繰り返し探索することができます。 もう 1 つの一般的な障害モードは、「セルの再利用禁止」制約を忘れることです。これは、適切に追跡されないと、誤って無効なサイクルを許可する可能性があります。 

たとえば、グリッドが の遷移と一致する同じ文字分布で満たされた大きな開いた領域である場合、単純な DFS は、たとえ語長が短くても、異なるパスを通じて同じ領域を再訪問し、組み合わせ的に爆発する可能性があります。 

したがって、タスクはグリッド内で任意に検索するのではなく、連続する位置がグリッド内で隣接するような有効な位置のチェーンが s の文字ごとに 1 つ存在するかどうかを効率的にチェックすることです。 

## アプローチ

 最も直接的なアイデアは、最初の文字が出現するたびに開始して、単語を段階的に構築しようとする DFS または BFS を実行することです。 現在の各セルからその 4 つの隣接セルを探索し、次の文字が一致する場合は続行します。 

これは、単語をつづるすべての可能なパスを列挙するため、論理的には正しいです。 ただし、その複雑さは各ステップでの分岐選択肢の数によって異なります。 密なグリッドでは、各ステップが最大 4 方向に分岐する可能性があり、開始位置が複数あると検索スペースが増加する可能性があります。 語長が最大 26 であっても、特に多くのグリッド セルが中間文字に一致する場合、検索ツリーは非常に多数の部分パスに拡張される可能性があります。 

問題を単純化する重要な観察は、単語の長さが非常に小さいのに対し、グリッドは大きいということです。 任意のパス探索の観点から考える代わりに、レイヤーごとの伝播の観点から考えることができます。 単語内の各文字位置はレイヤーを形成しており、有効な部分パス内でどのグリッド セルがその位置を表すことができるかを知ることだけが必要です。 

最初の文字に一致するすべてのセルから始めます。 次に、次の各文字について、前のレイヤーの少なくとも 1 つの到達可能なセルに隣接し、必要な文字を含むすべてのグリッド セルを計算します。 各セルの遷移はローカルであり、レイヤーごとに 1 回だけチェックされるため、このプロセスはレイヤーごとのグリッド セルの数において線形のままです。 

これにより、問題は最大 26 層にわたる制御された動的伝播に変換され、指数関数的な分岐が完全に回避されます。

 ## アルゴリズムのチュートリアル

 1. グリッドを読み取り、単語の最初の文字に一致するすべてのセルを見つけます。 有効なパスはいずれもそれらの 1 つから開始する必要があるため、これらは到達可能な位置の初期セットを形成します。 
2. 現在の文字インデックスでどのセルに到達できるかを追跡するブール グリッドまたは訪問マーカーを維持します。 これにより、1 つのレイヤー内の同じセルの重複した処理が防止されます。 
3. 単語内の次の文字ごとに、現在到達可能なすべてのセルをスキャンし、その 4 つの隣接セルをチェックすることによって、到達可能な位置の新しいセットを構築します。 隣接文字に必要な次の文字が含まれている場合、その文字は次の層で到達可能になります。 
4. 現在の到達可能なセットを新しく構築されたセットで置き換え、次の文字に進みます。 
5. いずれかの段階で到達可能なセットが空になった場合、単語は有効なパスとして形成できず、早期に停止します。 
6. すべての文字を処理した後、最後の文字で少なくとも 1 つのセルに到達できる場合、その単語はボード上に存在します。 

### なぜ効果があるのか

 このアルゴリズムは、単語の i 番目の文字を処理した後、アクティブ セルのセットが接頭辞 s[0..i] を綴る有効なパスのすべての端点に正確に対応するという不変条件を維持します。 各遷移ステップは、次の文字に一致する 1 つの隣接移動によってのみ有効なパスを拡張します。 すべての有効なパスは隣接するステップを通じて段階的に構築する必要があり、有効な拡張を決して破棄しないため、ソリューションが失われることはありません。 同時に、記録されたすべての状態が実際のパス セグメントに対応するため、無効なパスが導入されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    grid = [input().strip() for _ in range(n)]
    s = input().strip()
    k = len(s)

    # current reachable cells
    cur = set()

    # initialize with positions of first character
    for i in range(n):
        row = grid[i]
        for j in range(m):
            if row[j] == s[0]:
                cur.add((i, j))

    if not cur:
        print("NO")
        return

    dirs = [(1, 0), (-1, 0), (0, 1), (0, -1)]

    for idx in range(1, k):
        nxt_char = s[idx]
        nxt = set()

        for x, y in cur:
            for dx, dy in dirs:
                nx, ny = x + dx, y + dy
                if 0 <= nx < n and 0 <= ny < m:
                    if grid[nx][ny] == nxt_char:
                        nxt.add((nx, ny))

        cur = nxt
        if not cur:
            print("NO")
            return

    print("YES")

if __name__ == "__main__":
    solve()
```この実装は、階層化された伝播のアイデアに直接準拠しています。 初期スキャンでは、すべての有効な開始点が収集されます。 各反復では、有効なグリッド隣接のみを拡張することによって、1 文字ずつ進められます。 セットを使用すると、各セルがレイヤごとに最大 1 回処理されるようになり、複数のパスが同じ位置に到達する場合の冗長な伝播が防止されます。 

重要な実装の詳細は、絶対パスを追跡しようとしないことです。 プレフィックス長ごとに到達可能なエンドポイントのみを追跡します。単語自体が必要な文字のシーケンスを一意に決定するため、これで十分です。

 ## 特殊なケース

 最初の文字がグリッド上で何度も出現するが、それらの出現のどれも実際には 2 番目の文字に接続できない場合、重大なエッジ ケースが発生します。 初期セットが大きい可能性があるため、アルゴリズムはこれを自然に処理しますが、最初の伝播ステップではすぐに隣接性に基づいてフィルター処理され、1 回の反復でフロンティアが崩壊します。 

もう 1 つのケースは、キャラクターがループを形成するクラスターで出現する場合です。 多くのパスがローカルで循環する場合でも、セットベースの伝播により同じレイヤー内での繰り返しの拡張が防止されるため、ループによって状態空間が膨張することはありません。 

最後に、単語の長さが 1 の場合、最初のセット自体がすでに最終的な答えであるため、その文字がグリッド内のどこかに存在する場合に限り、アルゴリズムは正しく YES を返します。
