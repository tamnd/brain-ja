 ## 解決策
 ## 問題の理解

 一列に配置された一連のチェストが与えられ、各チェストには正または負の値が含まれます。 プレイヤーは最初の宝箱の前からスタートし、限られた数のトークンを持っています。 プレイヤーは厳密に左から右に移動しますが、その動きは単純に段階的に行われるわけではありません。 代わりに、各移動は、ジャンプの長さを選択し、そのジャンプに応じてコストを支払い、そのジャンプで到達したチェストを開くことで構成されます。 

プレイヤーが長さ 1 のジャンプを選択した場合、トークン 1 を支払い、次の宝箱を開けます。 長さ 2 のジャンプを選択した場合、1 + 2 トークンを支払い、間にあるチェストを 1 つだけスキップして、前方の 2 番目のチェストに着地します。 より一般的には、ジャンプ長さ k を選択すると、k 番目の三角数、つまり 1 + 2 + ... + k トークンが消費され、プレーヤーは途中で k − 1 個のチェストをスキップしながら、k 個の位置だけ前に移動します。 各ジャンプの後、プレーヤーはいつでも停止できます。 

目標は、開かれたチェストの値の合計を最大化しながら、総コストが利用可能なトークンを超えないように、一連のジャンプを選択することです。 

制約があるため、構造が重要になります。 チェストの数は最大 100 個、トークンの数は最大 1000 個です。これは、位置と残りの予算の両方で状態を探索する動的プログラミング ソリューションを使用できることをすぐに示唆していますが、m が 100 までであっても、動きをジャンプに分割する方法の数は指数関数的に増加するため、すべてのジャンプ シーケンスを単純にシミュレートしようとするものは爆発的に増加します。 

貪欲な直感を使うと、微妙な失敗例が現れます。 たとえば、初期のチェストには小さな正の値があり、後のチェストには大きな値があると考えます。 初期の利益を得るために常に最も安価なジャンプを取る貪欲な戦略は、後でより大きなジャンプを可能にするトークンを無駄にする可能性があります。 逆に、大きなジャンプに備えて常に節約していると、予算内にぴったり収まる安価な増分利益を逃す可能性があります。 この構造により、グローバルにトレードオフを評価する必要があります。 

もう 1 つの特殊なケースは、負の値から発生します。 宝箱を開けると合計スコアが減少するため、たとえ到達可能な場合でも多くの宝箱をスキップするのが最適な場合があります。 これは、トークンがなくなるまで常に移動を消費する必要があるというアプローチを打ち破ります。 

## アプローチ

 ブルートフォースアプローチでは、ジャンプの長さの可能なすべてのシーケンスが試行されます。 各ジャンプ長 k は三角形の数に等しいコストを持ち、位置を k だけ進めます。 開始点からすべての有効な k 値を再帰的に試行し、コストを差し引き、宝箱に着地したときにスコアを蓄積できます。 これは、ルールで定義されているとおりにすべての有効な戦略を正確に列挙するため、正しいです。 

ただし分岐要素は大きい。 三角形の数は二次関数的に増加するため、どの位置からでも、トークンの制限内で最大約 40 のジャンプ サイズが可能です。 最大 100 の位置にわたって、巨大な再帰ツリーが作成されます。 枝刈りを行ったとしても、同じ部分問題が頻繁に繰り返されます。同じ残りのトークンで同じインデックスに到達することは、さまざまなジャンプのシーケンスを通じて発生する可能性があります。 この冗長性が主な非効率性です。 

重要な観察は、問題の状態が 2 つのパラメーター (現在のチェスト インデックスと残りのトークン) によって完全に決定されるということです。 与えられた予算で与えられた指標に到達したら、そこに至るまでの過程に関係なく、将来の選択肢は同じです。 これにより、指数ツリーを動的プログラミング テーブルに折りたたむことができます。 

各状態から、三角コストが残りのバジェットを超えず、宛先インデックスが m を超えないように、すべての可能なジャンプ長 k を試行します。 私たちはあらゆる移行において最良のものを採用します。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべてのジャンプ シーケンスに対するブルート フォース再帰 | 指数 | O(m) 再帰の深さ | 遅すぎる |
 | DP オーバーポジションと残りのトークン | O(m · n · sqrt(n)) | O(m・n) | 承認済み |

 ## アルゴリズムのチュートリアル

 状態 dp[i][t] を、現在チェスト インデックス i (つまり、次に開く可能性のあるチェストは i+1) にいて、トークンが t 個残っているときに達成可能な最大スコアとして定義します。 

1. すべての dp 状態を非常に小さな値で初期化し、最後のチェストに到達またはそれを超えると、それ以上の開口部がないため、追加のゲインがゼロになると定義します。 これにより、いつでもプロセスを終了することを選択できる自然な停止条件が作成されます。 
2. ジャンプ長に対する三角コストを事前計算します。 各 k のコストは k(k+1)/2 であり、最大トークン バジェットを超えない値のみが保持されます。 これにより、状態ごとの遷移の数が制限されます。 
3. 状態 (i, t) から、直ちに停止するオプションを常に考慮します。これにより、さらなるスコアはゼロになります。 
4. 1 から始めてすべてのジャンプ長 k を試します。 各 k について、i + k が m を超えない場合、チェスト i + k に着地できます。 コスト T_k が残りのトークンの範囲内にあるかどうかを確認します。 そうであれば、dp[i + k][t − T_k] に遷移し、結果に a[i + k] を追加します。 
5. 停止トランジションとすべての有効なジャンプトランジションの中から最大値を取得します。 
6. 最終的な答えは dp[0][n] で、トークンバジェットがいっぱいの最初のチェストの前から開始することを表します。 

重要な考え方は、すべての有効なプレイ シーケンスがこの DP グラフ内の 1 つのパスに正確に対応し、すべての DP 遷移がゲーム内で法的に許可されている動きを表すということです。 

### なぜ効果があるのか

 正しさは、状態 (i, t) が関連するすべての履歴を完全にキャプチャしているという事実に依存します。 今後の動きから得られるスコアは、どのチェストに到達したか、および残っているトークンの数にのみ依存し、どのようにしてそこに到着したかには依存しません。 すべての有効なジャンプ シーケンスは、状態を通過する正確に 1 つのパスにマップされ、すべての DP 遷移は、移動の制約とトークンの消費の両方を尊重するため、合法性が維持されます。 考えられるすべての遷移が考慮されるため、DP は重複することなく実現可能なソリューション空間全体を探索します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))

    # 1-index the array for convenience
    a = [0] + a

    # precompute triangular costs
    tri = []
    k = 1
    while k * (k + 1) // 2 <= n:
        tri.append(k * (k + 1) // 2)
        k += 1
    maxk = len(tri)

    NEG = -10**18

    # dp[i][t] = best score starting at position i with t tokens left
    dp = [[NEG] * (n + 1) for _ in range(m + 2)]

    # base: at or beyond last chest, score is 0
    for t in range(n + 1):
        dp[m][t] = 0
        dp[m + 1][t] = 0

    for i in range(m - 1, -1, -1):
        for t in range(n + 1):
            best = 0  # option: stop immediately

            for k in range(maxk):
                cost = tri[k]
                j = i + (k + 1)
                if j > m:
                    break
                if cost > t:
                    break
                best = max(best, a[j] + dp[j][t - cost])

            dp[i][t] = best

    print(dp[0][n])

if __name__ == "__main__":
    solve()
```実装は状態定義を直接反映します。 DP テーブルは、将来のインデックスへの遷移がすでに計算されているように、位置を右から左に反復することによってボトムアップで構築されます。 各状態は直ちに停止することを考慮します。これは重要です。一部のパスは、負の値によるさらなる開口部を意図的に回避するためです。 

三角コストは、DP ループ内の算術計算の再計算を避けるために 1 回事前計算され、コストが残りのバジェットを超えるか位置が範囲外になると、k にわたるループは自然に早期に終了します。 

## 実用的な例

 ### サンプル 1

 入力:```
n = 4, m = 6
a = [1, 2, 3, 4, 5, 6]
```私たちはいくつかの代表的な州のみを追跡します。 

| 状態 (i, t) | 最良の選択 | 説明 |
 | --- | --- | --- |
 | (0, 4) | ジャンプ1 | 宝箱 1 を取ると +1 が得られ、トークンが 3 つ残ります。 
| (1, 3) | ジャンプ1 | +2 で宝箱 2 を取る |
 | (2, 2) | ジャンプ1 | 宝箱 3 を取って +3 にするか、予算に応じて停止します。 最適は継続します |
 | (3,1) | ジャンプ1 | +4 で宝箱 4 を取る |
 | (4,0) | 停止 | 予算が残っていない |

 このパスでは 1 + 2 + 3 + 4 = 10 が得られます。 

トレースは、すべての値が正であり、コストが単純なユニット ジャンプと一致しているため、予算が少ない場合でも、連続した安価なジャンプが優勢であることを示しています。

 ## 特殊なケース

 初期のチェストがすべて陰性であるが、後のチェストが非常に陽性である場合、重大なエッジ ケースが発生します。 DP は、どの状態でも停止を常に許可し、負の値の強制的な蓄積を防ぐため、これを処理します。 

もう 1 つのケースは、最適な戦略が大きなジャンプで複数の宝箱をスキップする必要がある場合です。 遷移にはすべての k 値が含まれるため、アルゴリズムは、遠く離れた高価値のチェストに直接到達するために大きな三角形のコストを支払うことを正しく考慮しますが、段階的に貪欲なアプローチではこれを見逃してしまいます。 

最後に、予算が少ない場合は、k = 1 のみが実現可能です。 DP は自然に、オプションの停止を伴う単純なプレフィックス蓄積に縮退し、特別なケースを使用せずに正確さを維持します。
