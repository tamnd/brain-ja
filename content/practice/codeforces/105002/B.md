 ## 解決策
 ## 問題の理解

 私たちには 3 つの科学カードの山が与えられ、各山は異なるシンボルに対応しています。 1 つの山には、タイプ R、別の S、および別の T のカードがカウントされます。また、「科学者のギルド」という特別なカードが 1 枚あり、最初の配布を確認した後、3 つのタイプのいずれかに割り当てることができます。 

スコアリング システムには 2 つのコンポーネントがあります。 まず、各シンボルは、最終的にそのシンボルのカードの枚数の 2 乗に等しいスコアを与えます。 第 2 に、3 つのシンボルのそれぞれから 1 枚のカードを取得して形成された完全なトリプルごとに 7 ポイントのボーナスが与えられます。この場合、そのようなトリプルの数は 3 つの最終カウントの中で最小になります。 

タスクは、最終スコアが最大になるように特別なカードを結合するシンボルを選択し、その最大スコアを計算することです。 

入力サイズは非常に大きく、カウントごとに最大 10^9 であるため、どのソリューションも定数時間で実行する必要があります。 繰り返し回数やシミュレーションを超えるものは、直ちに除外されます。 スコアリング関数の構造は、唯一の決定は 1 つの追加アイテムをどこに配置するかであるため、一定数の構成を評価するだけでよいことを示唆しています。 

山の 1 つが非常に小さいかゼロの場合、微妙な落とし穴が現れます。 ボーナス項は 3 つの値の最小値に依存するため、最小の山を増やすと平方項とトリプルの数の両方が増加する可能性があります。 たとえば、1 つの山が 0 の場合、そこに追加のカードを配置すると、より大きな山のローカル ゲインを上回るボーナス ポイントがロック解除される可能性があります。 

## アプローチ

 ブルートフォース戦略では、追加カードの可能な割り当てをすべて試して、スコアを直接計算します。 選択肢が 3 つしかないため、これはすでに小さいですが、それでも各ケースの完全なスコア公式を計算する必要があります。 単純なバージョンではさらに進んで、複数の仮説調整を分散したり、非効率的に最小値を再計算したりしようとする可能性があります。 これにより、三重カウントの不必要な再計算と、大きな値に対する二次演算が発生します。 

重要な観察は、スコアは最後のトリプルのみに依存するということです。`(R, S, T)`それらの 1 つに 1 つだけを追加した後。 配置を選択すると、直接算術を使用してスコアが O(1) で計算されます。 評価する状態は 3 つだけなので、すべてを計算して最適なものを選択できます。 

関数の構造は非常に単純であるため、可能な 3 つの増分を列挙する以外に、より深い最適化は必要ありません。

 ## アルゴリズムのチュートリアル

 スペシャル カードは、3 つのカウントのうち 1 つに正確に追加できるユニットとして扱われます。 オプションごとに、結果のスコアを計算して比較します。 

1. 元のカウント R、S、T から始めます。 

また、3 つの候補州も考慮します。追加のカードを R、S、または T に追加します。 
2. 各候補について、最終的な数を計算します。 

カードが R に追加された場合、新しい状態は (R+1, S, T) になります。 他の人も同様です。 
3. 状態ごとに、次の式を使用してスコアを計算します。 

各山の平方和に 3 つの山の最小値の 7 倍を加えたもの。 

このステップは 3 つの算術演算と 1 分だけを必要とするため、定数時間です。 
4. これまでに確認された最高のスコアと、それに対応するシンボルの選択を記録します。 

厳密に優れたスコアが見つかった場合は常に、回答を更新します。 
5. 3 つのオプションをすべて評価した後、最大スコアを生成したシンボルとスコア自体を出力します。 

### なぜ効果があるのか

 決定空間は完全に離散的であり、3 つの可能性に制限されています。 スコアリング関数は最終カウントのみに依存し、それらのカウントを超える隠れた相互作用はありません。 各構成が正確に評価されるため、アルゴリズムは実現可能な空間全体を探索します。 したがって、すべての実行可能な配置の最大値が見つかることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def score(r, s, t):
    m = min(r, s, t)
    return r * r + s * s + t * t + 7 * m

def main():
    R, S, T = map(int, input().split())

    best_val = -1
    best_choice = "R"

    # put in R
    v = score(R + 1, S, T)
    if v > best_val:
        best_val = v
        best_choice = "R"

    # put in S
    v = score(R, S + 1, T)
    if v > best_val:
        best_val = v
        best_choice = "S"

    # put in T
    v = score(R, S, T + 1)
    if v > best_val:
        best_val = v
        best_choice = "T"

    print(best_choice, best_val)

if __name__ == "__main__":
    main()
```このソリューションでは、スコアリングをヘルパー関数に分離して、各候補構成が一貫して評価されるようにします。 重要な詳細は、各ケースが独立して計算され、状態間での偶発的な繰り越しが確実に発生しないことです。 

比較は厳密な改善のみですが、同点の場合は有効な選択肢を返すことができるため、これは問題ありません。

## テストケース```python
import sys, io

def solve():
    import sys
    input = sys.stdin.readline

    def score(r, s, t):
        m = min(r, s, t)
        return r * r + s * s + t * t + 7 * m

    R, S, T = map(int, input().split())

    best_val = -1
    best_choice = "R"

    v = score(R + 1, S, T)
    if v > best_val:
        best_val = v
        best_choice = "R"

    v = score(R, S + 1, T)
    if v > best_val:
        best_val = v
        best_choice = "S"

    v = score(R, S, T + 1)
    if v > best_val:
        best_val = v
        best_choice = "T"

    print(best_choice, best_val)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from contextlib import redirect_stdout
    out = io.StringIO()
    with redirect_stdout(out):
        solve()
    return out.getvalue().strip()

# provided samples
assert run("5 4 0") == "R 52", "sample 1"
assert run("2 2 2") == "T 31", "sample 2"

# custom cases
assert run("0 0 0") in ["R 8", "S 8", "T 8"], "all zeros"
assert run("10 0 0") == "R 147", "dominant pile increases bonus only slightly"
assert run("1 2 3") is not None, "random small case"

 ## 特殊なケース

 すべての山が 0 の場合、任意のシンボルにカードを追加すると、同一の構造が生成されます。1 つの二乗項は 1 に等しく、その他は 0 ですが、最小値は 0 のままです。アルゴリズムは 3 つのケースすべてを独立して評価するため、任意のシンボルを正しく返します。 

1 つの山が優勢で、他の山が 0 の場合、優勢な山に追加すると平方は大幅に増加しますが、より小さい山に追加しても最小値は意味のある形で変更されません。 アルゴリズムは両方の効果を明示的に評価するため、必要に応じて自然に支配的なパイルを優先します。 

すべての値が等しい場合、3 つの候補状態はそれぞれ増分後に対称になるため、計算されたすべてのスコアが一致します。 アルゴリズムは最適な答えのみを必要とするため、最初に見つかった最大値を返すことは正しいことです。
