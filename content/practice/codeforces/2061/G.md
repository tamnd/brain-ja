 ## 解決策
 ## 問題の理解

 私たちに与えられたのは、$n$すべてのペアが、友情か非友情かという隠れた二項関係によって接続されている人々。 この関係は事前に知られていないため、対話型バージョンではクエリに反応することもあります。 

この人たちの中から、私たちが選びたいのは、$2k$個別の個人を分割し、$k$素のペア。 各ペアは 2 人組のチームです。 この要件は特殊です。選択されたすべてのペアにわたって、すべてのペアが友達で構成されているか、すべてのペアが友達以外で構成されている必要があります。 混合は禁止されており、すべてのペアのタイプが均一でなければなりません。 

まず最大値を出力する必要があります$k$それは、隠された関係がどのように配置されているかに関係なく、常に保証できます。 その後、実際のコンポーネントを構築する必要があります。$k$最大で使用するペア$n$クエリ。 

重要な問題は、敵が適応力があることです。 形式のすべてのクエリは「$u$そして$v$「友達」は将来の答えに影響を与える可能性があるため、グローバル構造の学習に依存することはできません。グラフ全体またはその大部分を再構築しようとする戦略は、すぐにクエリ制限を超えるか、適応性によって無効になります。 

制約は大きく、合計すると$n \le 10^5$テストケース全体で。 これにより、クエリの数が線形または線形に近くなり、テストされるペアの数が超線形に増加するものは基本的に禁止されます。 各クエリでは 1 ビットの情報しか明らかにされないため、ソリューションでは完全な知識ではなく構造上の保証を抽出する必要があります。 

次の場合、微妙なエッジケースが発生します。$n = 2$。 この場合、関係に関係なく、常に正確に 1 つのペアを形成できます。 単純な考えとしては、多数派のエッジについて推論しようとしたり、多くのペアをクエリした後で一貫性のあるマッチングを貪欲に構築しようとすることですが、グラフが固定されていないため、適応性の下ではどちらも失敗します。 

もう 1 つの失敗例は、「友人ペア」と「非友人ペア」のどちらが大きいかを識別する必要があると仮定した場合です。 この問題は多数決構造を要求するものではなく、選択されたすべてのペアが 2 つの可能な解釈の 1 つと一致することのみを要求します。 

## アプローチ

 強引な解釈では、すべてのペアをクエリし、グラフ全体を再構築し、エッジ全体の内側または非エッジ全体の内側で大規模な一致を検索します。 これには必要になります$\Theta(n^2)$これは、適応型インタラクターを考慮する前でさえ不可能です。 

重要な観察は、2 つのタイプの関係をグローバルに区別する必要がないということです。 選択した 1 つの解釈の下で内部的に一貫した素のペアのセットを構築するだけで済みます。 つまり、構造を構築する際に、「友人」または「非友人」へのコミットメントを完全に遅らせることができるということです。 

この構築は、固定ピボット頂点に対する一連の比較により、残りの頂点が動的に維持される 2 つのグループに分割されるという事実に基づいています。 各クエリは新しい頂点を 1 つの代表と比較するだけで、グラフ全体を探索しなくても一貫したペアリング構造を強制するにはこれで十分です。 

中心となる考え方は、未知の関係を、選択したアンカーに対する 2 値のラベル付け問題として扱うことです。 固定または進化する参照に対して頂点を繰り返し比較し、一方の側が常にペアリングに互換性があるパーティションを維持します。 十分な構造が蓄積されたら、制御された方法でパーティション全体の要素を照合します。 

これにより、任意のペア間の実際のエッジ ラベルを知る必要がなくなります。 代わりに、少数の代表との比較の一貫性のみに依存します。これは、頂点の少なくとも半分を使用可能な一致構造に強制するのに十分です。

 ## アルゴリズムのチュートリアル

 このアルゴリズムは、まだペアになっていない頂点の増大するセットを維持し、大規模で均一なマッチングを保証する構造を徐々に構築します。 

未処理の頂点を代表として繰り返し選択します。 次に、それをまだ処理されていない他の頂点と比較し、クエリを使用して代表頂点と一致するか異なるかに応じて頂点を 2 つのグループに分類します。 この分類は一貫しています。なぜなら、一度頂点が代表に相対的に割り当てられると、以前の決定に関連して再検討する必要がないからです。 

グループの 1 つがサイズのマッチングをサポートするのに十分な大きさに達するまで続行します。$k$。 各比較には 1 つのクエリが必要であり、同じペアを 2 回比較することはないため、クエリの総数は線形のままです。 

十分に大きなグループができたら、そのグループ内で頂点を任意にペアにします。 グループ内のすべての頂点は、同じアンカー構造に対する同一の比較によって分類されたため、同じリレーション タイプの下で一貫性があることが保証されます。 

### なぜ効果があるのか

 不変条件は、グループに配置されたすべての頂点が、アンカーの固定セットに関して同一の関係シグネチャを共有することです。 これは、同じグループ内の任意の 2 つの頂点が、インタラクターによって引き起こされる関係の同じ解釈の下で一貫していなければならないことを意味します。 インタラクターはペアごとに一貫して回答する必要があるため、グループ化により矛盾した分類が防止されます。 その結果、選択したグループ内のどのペアも、すべてのペアがすべてフレンドであるか、すべて非フレンドであるという要件を満たします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ask(u, v):
    print("?", u, v)
    sys.stdout.flush()
    return int(input().strip())

def solve():
    n = int(input().strip())
    k = n // 2
    print(k)
    sys.stdout.flush()

    used = [False] * (n + 1)
    groups = []

    i = 1
    while i <= n:
        if used[i]:
            i += 1
            continue

        group = [i]
        used[i] = True

        for j in range(i + 1, n + 1):
            if used[j]:
                continue
            if ask(i, j) == 1:
                group.append(j)
                used[j] = True

        groups.append(group)
        i += 1

    big = max(groups, key=len)

    res = []
    for i in range(0, len(big) - 1, 2):
        res.append(big[i])
        res.append(big[i + 1])

    print("!", *res)
    sys.stdout.flush()

def main():
    t = int(input().strip())
    for _ in range(t):
        solve()

if __name__ == "__main__":
    main()
```この解決策は、各グループの代表を固定し、残りの未訪問の頂点すべてに対してその代表をクエリすることから始まります。 同じリレーションを返す場合、各頂点は代表のグループに配置されます。 これにより、ローカル アンカーによって定義された一貫したコンポーネントへのパーティションが確保されます。 

すべてのグループを構築した後、最大のグループが選択されます。 内部のすべての頂点はそのアンカーに対して一貫しているため、それらを任意にペアリングすると、均一なタイプの有効なチームが生成されます。 

微妙な点は、アンカー以外の頂点間の一貫性を直接検証しようとしないことです。 これにより、二次クエリが回避され、相互作用が制限内に保たれます。 

## 実用的な例

 検討してください$n = 6$ここで、隠れた構造は、初期のアンカーと比較して一貫した応答の 3 つのグループを偶然形成します。 

| ステップ | アクション | グループ結成 | クエリ結果 |

 最大のグループはおそらく$[3,4,5]$、そしてペアリングします$(3,4)$出発する$5$未使用。 

このトレースは、グローバル構造ではなく、ローカル代表との比較によってグループ化がどのように行われるかを示しています。 

ここで考えてみましょう$n = 4$均一な応答 (すべて 1)。 次に、すべての頂点が最初のグループに加わり、単一の大きなコンポーネントが生成されます。$[1,2,3,4]$。 任意にペアリングすると 2 つの有効なチームが得られ、均質な構造の下での正しさが確認されます。

 ## 特殊なケース

 のために$n = 2$の場合、単一のクエリで分類が決定されるため、アルゴリズムはすぐに両方の頂点を含む 1 つのグループを形成します。 ペアリングは簡単で、答えに関係なく常に有効です。 

のために$n = 3$、グループ化後も 1 つの頂点が一致しないままになります。 このアルゴリズムは依然として最大のグループから有効な単一のペアを生成しますが、残りの頂点は制約の下で 2 番目のペアに寄与できないため無視されます。$2k \le n$。 

均一に一貫した応答 (すべての応答が等しい) の場合、すべての頂点は 1 つのグループに吸収されます。 ペアリングのステップでは、単純にリストを調べて、$\lfloor n/2 \rfloor$追加のチェックを必要とせずに有効なペアを確認します。
