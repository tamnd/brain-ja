 ## 解決策
 ## 問題の理解

 Kevin のグラフでは、各頂点に最初は石が含まれているか、空である可能性があります。 彼はまた、石がどこに到達する必要があるかを示すターゲット構成も持っています。 移動するたびに、ケビンは各石を現在の頂点から隣接する頂点に同時に移動できますが、2 つの石が同時に同じ頂点を占有することはできません。 タスクは、これらの操作を 0 個以上使用して、初期構成からターゲット構成に到達できるかどうかを判断することです。 

入力は複数のテスト ケースを提供し、それぞれが頂点とエッジの数、初期バイナリ文字列とターゲット バイナリ文字列、グラフのエッジを指定します。 初期状態とターゲット状態の石の数は等しいことが保証されます。 制約は中程度です。すべてのテスト ケースで頂点が最大 2000、エッジの合計が最大 10^4 です。 これは、慎重に実装すれば、テスト ケースごとに O(n^2) のアルゴリズムを実現できることを意味します。 

単純な解決策では、考えられるすべての動きのシーケンスをシミュレートしようとします。 たとえば、頂点が 1-2-3 で、頂点 1 と 2 に石があり、ターゲットが 2 と 3 に石を配置している三角形のグラフを考えてみましょう。考えられるシーケンスの数が指数関数的に増加するため、すべての動きの組み合わせを試すとすぐに爆発してしまいます。 同様に、孤立した頂点、接続されていないコンポーネント、または奇数の長さのサイクルにより、移動をシミュレートするのではなくグラフ内の到達可能性を考慮しない限り、直接的で貪欲な移動アプローチが失敗するシナリオが作成される可能性があります。 

微妙なエッジケースは、コンポーネントが切断されていることです。 1 つのコンポーネントには初期状態でストーンがありますが、そのコンポーネントのターゲット ストーンは切断された別のコンポーネントにあるとします。 単純なアルゴリズムでは石をグローバルに交換しようとする可能性がありますが、石は切断されたコンポーネントを横切ることができないため、一連の合法的な動きは存在しません。 同様に、コンポーネントの頂点の数が奇数であるが、パリティに依存した方法で石を移動する必要があるグラフでは、有効/無効な構成が区別される可能性があります。 

## アプローチ

 ブルートフォースアプローチは、可能な同時移動をすべて列挙し、目標構成に到達したかどうかを確認することです。 移動するたびに、石ごとに移動先の隣接頂点を選択する必要があります。 k 個の石があり、それぞれに d 個の隣接石がある場合、手ごとに d^k 個の選択肢があります。 n=2000 と小さい場合でも、石の数は O(n) になる可能性があるため、d^k はすぐに実行不可能になります。 このアプローチは原理的には正しいですが、妥当な時間内に完了することはできません。 

重要な洞察は、各動きがエッジに沿ったグローバルな順列であることを観察することで得られます。石はエッジに沿ってのみ交換されるため、問題は基礎となるグラフの到達可能性に帰着します。 より具体的に言うと、石は接続されたコンポーネント内でのみ移動できます。 したがって、各接続コンポーネントについて、初期構成とターゲット構成のマルチセットのストーン数が一致する必要があります。 コンポーネントの最初の石の数とターゲットの石の数が異なる場合、そのコンポーネントに石を移動することはできません。 それ以外の場合は、エッジに沿った一連の同時移動を使用して、コンポーネント内で石を任意に並べ替えることができます。 これにより、問題がグラフ接続性チェックとマルチセット比較に変換され、テスト ケースあたり O(n + m) で実行可能になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(d^k) | O(n) | 遅すぎる |
 | コンポーネントの到達可能性 | O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

1. テスト ケースの数を読み取ります。 各テスト ケースについて、n、m、初期文字列 s、およびターゲット文字列 t を読み取ります。 
2. m 個のエッジからグラフの隣接リストを作成します。 これにより、近隣の効率的なトラバースが可能になります。 
3. 訪問した頂点をマークするために配列を初期化します。 
4. すべての頂点を反復処理します。 未訪問の頂点が見つかった場合は、深さ優先検索 (DFS) または幅優先検索 (BFS) を実行して、同じ接続コンポーネント内のすべての頂点を識別します。 
5. 接続されたコンポーネントごとに、初期構成の石の数とターゲット構成の石の数を数えます。 
6. コンポーネントのこれらのカウントが等しい場合、コンポーネントを有効としてマークします。 いずれかのコンポーネントの石数が一致しない場合、テスト ケースの答えは「いいえ」になります。 
7. すべてのコンポーネントの石数が一致する場合、答えは「はい」です。 

機能する理由: 石は接続されたコンポーネントから離れることができません。 コンポーネント内で同時に移動すると、パスに沿って石を任意に並べ替えることができます。 したがって、初期石とターゲット石の複数セットがコンポーネントごとに一致する限り、石をターゲットに再配置するための一連の動きが存在します。 正確さは、グラフが無向であること、および接続成分が最大であることに依存します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10000)

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        s = input().strip()
        t_str = input().strip()
        adj = [[] for _ in range(n)]
        for _ in range(m):
            u, v = map(int, input().split())
            adj[u-1].append(v-1)
            adj[v-1].append(u-1)
        visited = [False]*n
        possible = True

        def dfs(u, component):
            visited[u] = True
            component.append(u)
            for v in adj[u]:
                if not visited[v]:
                    dfs(v, component)

        for i in range(n):
            if not visited[i]:
                component = []
                dfs(i, component)
                init_count = sum(int(s[x]) for x in component)
                target_count = sum(int(t_str[x]) for x in component)
                if init_count != target_count:
                    possible = False
                    break
        print("Yes" if possible else "No")
```コードは入力を効率的に読み取り、隣接リストを構築します。 DFS を使用して、接続されているコンポーネントを検索します。 各コンポーネントについて、初期構成とターゲット構成の石の数を比較します。 いずれかのコンポーネントがこのチェックに失敗した場合、直ちに「いいえ」が出力されます。 グラフが長いチェーンを形成する場合に深い DFS を処理できるように、再帰制限が増加しました。

 ## 特殊なケース

 サイズ 1 のコンポーネントを持つ切断されたグラフの場合、アルゴリズムは各頂点を独自のコンポーネントとして識別します。 その頂点の初期石と目標石が異なる場合は「いいえ」を出力します。 長いチェーンの場合、DFS はコンポーネントを正しく見つけてストーンを合計します。 全結合グラフでは、単一成分の合計によってあらゆる順列が実現可能であることが保証され、マルチセット比較不変条件が十分であることが実証されます。
