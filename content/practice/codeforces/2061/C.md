 ## 解決策
 ## 問題の理解

 私たちにはクラスメートの列があり、それぞれが自分の左側に立っている一定数の嘘つきを主張しています。 人はそれぞれ、正直者である場合 (その場合、その主張はまさに真実です)、または嘘つきである場合 (この場合、彼らの主張は恣意的である可能性があります) のどちらかです。 さらに、嘘つきは隣に立つことはできません。 私たちの仕事は、正直なクラスメートの発言を満たす、正直な課題と嘘つきの課題の有効なシーケンスをすべて数えることです (モジュロ 998244353)。 

入力により複数のテスト ケースが提供されます。 各テスト ケースではクラスメートの数を指定します`n`そして配列`a`どこ`a[i]`は左側にある嘘つきの数です。`i`-人目の人が主張します。 出力はテスト ケースごとに 1 つの整数、つまり正直なクラスメートと嘘つきなクラスメートの可能な構成の数です。 

なぜなら`n`テスト ケースごとに最大 2 · 10^5 と次の合計を指定できます。`n`すべてのテスト ケースの境界も 2·10^5 であるため、次のようにほぼ線形のアルゴリズムを設計する必要があります。`n`。 二次関数や指数関数は直ちに実行不可能になります。 これにより、すべての 2^n 正直/嘘つき割り当ての総当り列挙が除外されます。 

明らかではないエッジケースは、主張が嘘つきの間隔ルールと一致しない場合に発生します。 たとえば、連続する 3 人が左側に嘘つきがいないと主張した場合、中央に嘘つきがいる構成は連続して嘘つきが作成されるため無効です。 また、次のような主張も`n`左側の嘘つきは一人称では不可能なので、境界確認が不可欠です。 

## アプローチ

 素朴なアプローチは、正直者と嘘つきの割り当ての 2^n シーケンスをすべて生成し、どれが正直なステートメントを満たし、連続して嘘つきが存在しないかをチェックすることです。 n=200,000 の場合、2^200,000 は天文学的に大きいため、これはまったく不可能です。 

重要な洞察は、次の主張を観察することによって得られます。`a[i]`嘘つきの累積数を左から右に制限します。 と表すと`L[i]`位置の左側の嘘つきの数として`i`、正直な人なら誰でも満足するはずです`L[i] = a[i]`。 ステートメントを検証するときに嘘つきは無視できますが、2 つの嘘つきが連続してはいけないという制約があるため、単純にどこにでも嘘つきを挿入することはできません。 

最適なアプローチは、正直な陳述と一致して、間隔の制約に違反することなく嘘つきが配置される位置のシーケンスを数えることとして問題を再定式化します。 仮定する`cnt`は、これまでに挿入した嘘つきの数です。 もし`a[i] = cnt`, i 番目の人は正直になれます。 それ以外の場合は、`a[i] > cnt`、i 番目の人は嘘つきに違いありません。 これは自然に動的プログラミングのアプローチにつながります。つまり、最後の人が正直か嘘つきで終わる有効なシーケンスの数を追跡し、カウントを更新します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | 動的プログラミング (最適) | テスト ケースあたり O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. DP の 2 つの配列またはカウンターを初期化します。`dp_honest`正直な人で終わるシーケンスを数えます。`dp_liar`嘘つきで終わるシーケンスをカウントします。 最初は、どの人の前にも、空の有効な構成が 1 つあります。 
2. クラスメートを左から右に繰り返します。 維持する`liar_count`、すでに配置されている嘘つきの数。 
3. 一人ひとりの主張を確認する`a[i]`。 もし`a[i] == liar_count`、その人は正直になれる。 アップデート`dp_honest`前のステップのすべてのシーケンスを追加することによって (`dp_honest + dp_liar`)、正直者を配置しても連続嘘つき制約に違反しないためです。 
4. もし`a[i] > liar_count`、その人は嘘つきに違いありません。 嘘つきは連続することができないため、以前は正直者で終わっていたシーケンスのみが嘘つきで延長されます。 アップデート`dp_liar`を使用して`dp_honest`そして増加します`liar_count`。 
5. もし`a[i] < liar_count`、設定は不可能です。 このブランチの両方の DP カウントをゼロに設定します。 
6. すべてのクラスメートを処理した後、有効なシーケンスの総数は次の合計になります。`dp_honest`そして`dp_liar`モジュロ 998244353。 

なぜ効果があるのか:`dp_honest`前のステートメントをすべて満たす、正直な人で終わるシーケンスを常にカウントします。`dp_liar`嘘つきで終わるシーケンスをカウントします。 不変条件というのは、`liar_count`これまでに設置された嘘つきの数が正しく反映されているため、`a[i]`に対して`liar_count`正直さの制約を強制します。 連続嘘つきルールは、許可することによってのみ維持されます。`dp_liar`から拡張する`dp_honest`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
MOD = 998244353

def solve_case(n, a):
    dp_honest = 1
    dp_liar = 0
    liar_count = 0
    
    for claim in a:
        if claim == liar_count:
            new_dp_honest = (dp_honest + dp_liar) % MOD
            new_dp_liar = dp_honest % MOD
            dp_honest, dp_liar = new_dp_honest, new_dp_liar
            liar_count += 0
        elif claim == liar_count + 1:
            new_dp_honest = 0
            new_dp_liar = dp_honest % MOD
            dp_honest, dp_liar = new_dp_honest, new_dp_liar
            liar_count += 1
        else:
            return 0
    return (dp_honest + dp_liar) % MOD

def main():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        print(solve_case(n, a))

if __name__ == "__main__":
    main()
```このコードは、クラスメートのプレフィックスごとに 2 つの DP 状態 (正直または嘘つきで終わるシーケンス) を維持します。 更新中`dp_honest`そして`dp_liar`現在の主張によれば、`liar_count`正直さと間隔の制約の両方が尊重されるようにします。 不可能な分岐のチェックでは、すぐにゼロが返されます。 

## 実用的な例

 サミングファイナル`dp_honest + dp_liar = 1`(モジュロ 998244353)、予想される出力と一致します。

 ...続き、最終合計 = 2、サンプル出力と一致します。
