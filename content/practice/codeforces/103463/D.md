 ## 問題の理解

 からの連続した範囲の整数が与えられます。$a$に$b$、そして最初はそれぞれの数字が独自の山として独立しています。 各山で素因数を共有する数を見つけることができれば、2 つの山を結合することができます。$t$と$t \ge p$。 マージが発生すると、2 つの山は 1 つになり、このプロセスはマージができなくなるまで続きます。 タスクは、最後に残っている杭の数を決定することです。 

プロセスを再解釈する便利な方法は、各数値をグラフ内のノードとして考えることです。 2 つの数値が少なくとも次の素因数を共有する場合、それらを結び付けます。$p$。 最終的な杭の数は、このグラフの接続されたコンポーネントの数と正確に一致します。 

範囲制約$b \le 10^5$線形または線形に近い前処理が必要であることがすぐにわかります。 単純なペアごとのチェックには次のことが必要です$O((b-a+1)^2)$が遅すぎます。 各数値を個別に因数分解してセットを比較しても、比較が多すぎます。 

微妙なエッジ ケースは、しきい値を満たす素因数がない場合です。$p$。 たとえば、次の場合$p = 7$、範囲は$10$に$20$の場合、7、11、13、17、19 のような素数を含む数値のみが問題となり、2、3、5 のみで構成されるものはすべて分離されたままになります。 もう 1 つのエッジケースは次のような場合です$p = 2$ここで、任意の素因数を共有するすべての数値が接続されます。これは、基本的に、共有される素因数の完全な標準和集合を復元することを意味します。 

重要な問題は、マージが推移的であることです。$x$そして$y$素数を直接共有しているわけではありませんが、中間数を介して接続されている可能性があります。 このため、ペアごとの直接的なマージではなく、接続性の観点から考える必要があります。 

## アプローチ

重要な観察は、実際には各数値の完全な因数分解は気にしておらず、素数だけを気にしているということです。$\ge p$。 これは、以下のすべての素数を無視できることを示唆しています$p$、大きな素数の倍数を介した接続のみを追跡します。 

それぞれの数値をチェックする代わりに、素数を反復処理できます。$t \ge p$。 このような素数ごとに、次のすべての倍数を接続します。$t$範囲内で$[a, b]$。 これにより、問題は範囲内のインデックスに対する和集合検索に変わり、各素数がその倍数をリンクする「コネクタ」として機能します。 これは本質的にふるいベースのグループ化問題です。適格な素数はそれぞれ、その倍数にわたって和集合の連鎖を引き起こします。 

間隔のみに取り組むことでさらに最適化できます$[a, b]$と相対的なインデックスのマーキング$a$、セグメント化されたふるいに似ています。 それぞれの素数$t$インデックス間の結合に貢献します$i$そのような$a + i$で割り切れます$t$。

 ## アルゴリズムのチュートリアル

 素の集合共用体構造を使用して、問題を範囲内のインデックス間の接続性に帰着させます。 

1. 次のすべての整数に対して DSU を初期化します。$a$に$b$ここで、各インデックスは最初に 1 つの山を表します。 これは、マージが行われていない開始状態をモデル化します。 
2. ふるいを作ります$b$すべての素数を識別します。 素因数だけが共有可分性関係を定義できるため、必要なのは素数だけです。 
3. すべての素数を反復処理します。$t \ge p$。 このような素数ごとに、次のすべての倍数を見つけます。$t$に横たわっている$[a, b]$。 この素因数を共有する 2 つの数値を接続する必要があるため、このステップは非常に重要です。 
4. 固定素数の場合$t$、次を使用して範囲内の最初の倍数を見つけます。$start = \lceil a/t \rceil \cdot t$。 そこからは、次のような手順で歩きます。$t$そして、DSU 内の対応するすべてのインデックスを結合します。 これにより、割り切れるすべての数値が保証されます。$t$1 つの接続されたコンポーネントの一部になります。 
5. すべての有効な素数を処理した後、インデックス間に異なる DSU ルートがいくつ存在するかを数えます。$a$に$b$。 各ルートは最終的な杭に対応します。 

### なぜ効果があるのか

 DSU は、共有される素因数の連鎖が存在する場合に限り、2 つの数値が同じセット内にあるという不変条件を維持します (少なくともそれぞれ$p$）それらを接続します。 すべての素数$t \ge p$その要素によって引き起こされる必要な接続を正確に強制し、すべての有効なマージはそのようなプライムから発生する必要があるため、接続を見逃したり、無効な接続を作成したりすることはありません。 推移性は DSU マージによって自動的に処理されるため、間接的な接続が正しくキャプチャされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    a, b, p = map(int, input().split())
    n = b - a + 1

    parent = list(range(n))
    size = [1] * n

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    def union(x, y):
        x = find(x)
        y = find(y)
        if x == y:
            return
        if size[x] < size[y]:
            x, y = y, x
        parent[y] = x
        size[x] += size[y]

    is_prime = [True] * (b + 1)
    is_prime[0] = is_prime[1] = False

    for i in range(2, int(b ** 0.5) + 1):
        if is_prime[i]:
            for j in range(i * i, b + 1, i):
                is_prime[j] = False

    for t in range(max(p, 2), b + 1):
        if not is_prime[t]:
            continue

        start = ((a + t - 1) // t) * t
        first = (start - a)

        prev = -1
        for val in range(start, b + 1, t):
            idx = val - a
            if prev != -1:
                union(prev, idx)
            prev = idx

    roots = set()
    for i in range(n):
        roots.add(find(i))

    print(len(roots))

if __name__ == "__main__":
    solve()

重要な実装の詳細は、倍数がどのように処理されるかです。素数の倍数のすべての組み合わせをペアにする代わりに、それらをチェーンでリンクします。 これにより、複雑さが素数ごとの二次から倍数の線形に軽減されます。

## 特殊なケース

 重要なエッジケースの 1 つは次のような場合です。$p$は区間内のすべての素数よりも大きくなります。 たとえば、入力では`1 10 11`、範囲内に 11 以上の素数はありません。 このアルゴリズムは自然にすべての素数をスキップし、すべての要素を独自の DSU セットに残し、10 個の山を生成します。 

もう一つのケースは次のような場合です。$p = 2$。 ここでは、すべての素数が寄与し、接続が密になります。 のために`1 10 2`、2、3、5、7 の倍数にわたる DSU ユニオンはほとんどのノードを徐々にマージし、アルゴリズムは推移的マージを通じて接続されたコンポーネントを正しく折りたたみます。 

最後の微妙なケースは、区間内に素数の倍数が 1 つしかない場合です。 たとえば、`10 20 7`、7 で割り切れるのは 14 だけです。結合する 2 番目の要素がないため、DSU は変更されず、分離が正しく維持されます。
