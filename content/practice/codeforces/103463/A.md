 ## 解決策
 ## 問題の理解

 0 から n までの数字のセットが与えられ、これらの数字の考えられるすべての並べ替えを考慮するように求められます。 各順列は、数字を順番に連結することによって数値として解釈されます。 ただし、ゼロで始まる順列は先頭にゼロが付く数値を生成するため、破棄されます。 

すべての有効な順列のうち、指定された整数 m で割り切れる結果の数値がいくつあるかを数えます。 

したがって、中心となるタスクは、数値を直接構築することではなく、先行ゼロがないことと、形成された数値が m で割り切れるという 2 つの制約の下で、小さな数字のセットの順列をカウントすることです。 

制約は小さく、n は最大 15、m は最大 100 です。これは、(15 + 1) であるため、最大 16 階乗までの階乗スケールの列挙を明示的に実行することは不可能であることを直ちに示唆しています。 すでに天文学的な規模になっています。 どのソリューションでも、順列の直接生成を回避する必要があります。 

先頭のゼロの規則から、微妙な特殊なケースが発生します。 たとえば、n = 2 の場合、桁は {0,1,2} になります。 012 や 021 のような順列は、すべての数字の順列であっても無効です。 最初の桁がゼロ以外の順列のみがカウントされます。 単純な順列ジェネレーターは、最初にすべての配置をカウントし、後でフィルター処理する可能性がありますが、これでは無効な状態での計算が無駄になり、依然としてスケールできません。 

もう 1 つの重要なエッジ ケースは、n = 0 の場合です。この場合、唯一の数値は 0 自体であり、割り算は 0 % m = 0 かどうかによって決まります (これは常に真です)。 正しい解決策は、この些細なケースを誤って破棄しないようにする必要があります。 

## アプローチ

 ブルートフォースソリューションでは、0 から n までの数字のすべての順列を生成し、対応する整数を構築し、m で割り切れるかどうかをテストします。 これは概念的には簡単です。すべての可能な順序を試し、ゼロで始まる順序をスキップし、有効な順序を数えます。 

問題は、順列の数が桁数の階乗に応じて増加することです。 n は 15 までなので、合計 16 桁になり、16 になります。 これは実行可能な計算をはるかに超えています。 たとえ各チェックが一定時間だったとしても、列挙自体は不可能です。 

重要な点は、完全な数値を明示的に構築する必要がないということです。 数字を一桁ずつ構築するときに、剰余 m を追跡するだけで済みます。 現在の剰余と使用された桁がわかっている場合は、未使用の桁を追加して数値を拡張し、剰余演算を使用して効率的に剰余を更新できます。 

これにより、問題は桁と剰余値のサブセットに対する状態空間検索に変換されます。 各状態は部分順列を表し、使用される数字と現在の剰余モジュロ m のビットマスクによってエンコードされます。 最大で 2^(n+1) 個の部分集合と m 個の可能な剰余が存在するため、状態の総数は最大約 2^16 × 100 となり、これは容易に管理可能です。 

次に、サブセットに対して動的プログラミングを使用し、順列を段階的に構築し、有効な完了数を累積します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O((n+1)!) | O(n) | 遅すぎる |
 | ビットマスク DP | O(2^n・n・m) | O(2^n・m) | 承認済み |

 ## アルゴリズムのチュートリアル

 0 から n までの各数字を、順列に配置できる要素として扱います。 サブセットに対する動的プログラミングを使用して、すべての有効な順列を構築します。

1. ビットマスクと剰余 m で構成されるペアで各状態を表します。 ビットマスクはどの桁がすでに使用されているかを示し、剰余はそれまでに形成された法 m の数値を追跡します。 
2. dp[0][0] = 1 で DP テーブルを初期化します。これは、剰余 0 の空の数値を形成する方法が 1 つあることを意味します。 
3. 各状態 (マスク、レム) に対して、未使用の数字 d を追加してみます。 数字 d がすでにマスク内にある場合は、スキップします。 それ以外の場合は、新しいマスクと新しい剰余を計算します。 残りの更新は rem_new = (rem * 10 + d) % m に従います。 このステップは、大きな整数を明示的に構築することを避けるため、非常に重要です。 
4. ゼロで始まる数字がないことを確認する必要があります。 この制約は、最初に選択された数字がゼロでマスクが空である場合の遷移を防ぐことによって強制されます。 
5. すべての状態を処理した後、r = 0 であるすべての dp[full_mask][r] を合計します。これらは、すべての桁を使用し、m で割り切れる完全な置換を表します。 

正確さは、dp[mask][rem] が常に、m を法とする剰余 rem の数値を生成するマスク内の数字を正確に使用して部分順列を構築する方法の数を格納するという不変式から得られます。 数字を追加すると、10 進数の動作と一致してマスクと剰余の両方が更新されるため、各遷移ではこの不変条件が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    digits = list(range(n + 1))
    N = n + 1
    
    if N == 1:
        return 1 if 0 % m == 0 else 0

    dp = [[0] * m for _ in range(1 << N)]
    dp[0][0] = 1

    for mask in range(1 << N):
        for rem in range(m):
            cur = dp[mask][rem]
            if not cur:
                continue
            for i in range(N):
                if mask & (1 << i):
                    continue
                if mask == 0 and digits[i] == 0:
                    continue
                nmask = mask | (1 << i)
                nrem = (rem * 10 + digits[i]) % m
                dp[nmask][nrem] += cur

    full = (1 << N) - 1
    return dp[full][0]

if __name__ == "__main__":
    print(solve())
```この実装は、前述したサブセット上の DP に直接続きます。 dp テーブルにはマスクと剰余によってインデックスが付けられ、各状態に到達する方法のカウントが保存されます。 遷移はすべての未使用の桁をループし、マスクと剰余の両方を更新します。 

先頭のゼロ制限は、最初の遷移レベルで明示的に処理されます。つまり、マスクがゼロの場合、数字 0 の選択が禁止されます。これにより、ゼロで始まる無効な置換が生成されることがなくなります。 

モジュロ更新は次を使用して増分的に実行されます。`(rem * 10 + digit) % m`これは、大きな整数を構築せずにモジュラー演算で数値を維持する標準的な方法です。 

## 実用的な例

 次のサンプル入力を考えてみましょう。 

入力:```
2 3
```数字は {0、1、2} です。 完全な順列は 102、120、201、210 です。3 で割り切れるものを数えます。 

小さなサブセットの簡略化された DP の進行を追跡します。 

| マスク | 選択された数字 | 残りの状態 (部分的な概要) |
 | --- | --- | --- |
 | 000 | {} | {0:1} |
 | 001 | {0} 無効な開始がスキップされました | |
 | 010 | {1} | {1:1} |
 | 100 | {2} | {2:1} |

 これらの部分的なビルドから、完全な置換により剰余が得られます。 

102 % 3 = 0

 120 % 3 = 0

 201 % 3 = 0

 210 % 3 = 0

 したがって、4 つの順列はすべて有効で、3 で割り切れるので、答えは 4 になります。 

このトレースは、DP がすべての有効な順序を正しく累積し、剰余の伝播が完全な数の割り算と一致していることを示しています。 

2 番目の例:

 入力:```
1 2
```数字は {0,1} です。 有効な順列は「10」のみです（「01」は無効であるため）。 10 % 2 = 0 なので、答えは 1 です。 

これにより、最小の非自明なケースにおける先行ゼロ制約の動作がチェックされます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(2^(n+1) · (n+1) · m) | 各状態は最大 n+1 個の遷移を試行し、m 個の残りを更新します。 
| スペース | O(2^(n+1) · m) | サブセット マスクとモジュロ状態によってインデックス付けされた DP テーブル |

 n ≤ 15 および m ≤ 100 の場合、状態空間は約 16 × 2^16 × 100 となり、Python の制限内に十分収まります。

 ## 特殊なケース

 n = 0 および m = 1 の場合、入力は「0 1」です。 DP は 1 桁のセット {0} に減ります。 有効な順列は数値 0 自体だけです。 アルゴリズムは dp[0][0] = 1 を初期化し、これを完全なマスク状態として直接カウントし、予想される出力 1 と一致する剰余 0 を生成します。 

「1 100」など、n = 1 で m が大きい入力の場合、桁は {0,1} になります。 DP は 0 で始まる順列を正しく拒否し、「10」のみを考慮します。 剰余は (1 * 10 + 0) % 100 = 10 として計算されますが、これはゼロではないため、結果は 0 になります。有効な順列はすべて、許可された最初の桁の選択と一貫したモジュール更新によってのみ構築されるため、遷移ルール​​によって正確さが保証されます。
