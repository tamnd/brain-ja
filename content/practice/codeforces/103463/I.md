 ## 解決策
 ## 問題の理解

 軸に沿って整列した一連の長方形が与えられ、すべてが X 軸上にあります。つまり、すべての長方形の下端が X 軸上にあります。$y = 0$。 それぞれの長方形$i$ある間隔にまたがる$[L_i, R_i]$X 軸上にあり、高さがあります$H_i$。 長方形を順番に処理するときに、これまでに見られたすべての長方形の和集合を考慮し、その面積を計算します。$P_i$。 

重要な点は、重なりが重なり合わないことです。2 つの長方形が重なり合う場合、重なり合う領域は、その位置に存在する最大の高さを使用して、結合領域内で 1 回だけカウントされます。 積を計算するように求められます$P_1 \times P_2 \times \cdots \times P_n$モジュロ$998244353$。 

これを解釈する便利な方法は、左から右にスカイラインを構築し、時間の経過とともに各長方形が追加される様子を想像することです。 ステップで$i$、最初の少なくとも 1 つがカバーする領域を測定します。$i$長方形。 

制約は非常に大きく、最大で$10^6$長方形と座標まで$10^9$。 これにより、ポイントごとのシミュレーションや、X 軸を直接スキャンするアルゴリズムが即座に排除されます。 平$O(n \log n)$長方形ごとの処理は遅すぎるため、各間隔が合計でほぼ 1 回処理される構造が必要です。 

微妙な問題は、四角形が任意の方法で重なる可能性があるため、結合領域の単純なプレフィックス再計算が実行できないことです。 

素朴な直感を打ち破るエッジケースの 1 つは、多くの長方形が重なり合う場合です。 

たとえば、すべての長方形が$[1, 10]$身長が下がると、$P_1$大きいですが、すべて後ほど$P_i$同一のままです。 毎回結合を最初から再計算する単純な試みでは、同じ領域を繰り返し再計算することになり、壊滅的な非効率につながります。 

もう 1 つの特殊なケースは、長方形が互いに素な間隔である場合です。 次に、すべての長方形がそのステップで完全に寄与し、$P_i$断片的に直線的に成長します。 空間範囲ではなく高さだけが単調に増加することを前提としたソリューションは、ここでは失敗します。 

## アプローチ

 直接的なアプローチは、すべてのプレフィックスの結合領域を再計算することです。$1..i$すべてのアクティブな長方形上でスイープ ラインまたはセグメント ツリーを使用します。 それぞれについて$i$、合併します$i$長方形を抽出し、X 軸上のカバレッジを計算します。 これには少なくとも費用がかかります$O(n \cdot n \log n)$、各再計算で以前のすべての四角形が処理されるためです。 と$n = 10^6$、これはまったく不可能です。 

重要な観察は、高さが増加しないという制約から得られます。$H_1 \ge H_2 \ge \cdots \ge H_n$。 これにより、厳密な優先順位が作成されます。 以前の長方形は常に、後の長方形と少なくとも同じ高さになります。 

これは、エリアの所有権について重要なことを意味します。 どの点でも$x$、結合後の高さ$i$ステップは、シーケンス内の最初の長方形によって決まります。$x$、その長方形は、同様にカバーされる将来のすべての長方形の中で最大の高さを持つことが保証されているためです。$x$。 後の長方形は高さに関して以前の長方形をオーバーライドすることはできず、以前に覆われていない領域を埋めるだけです。 

したがって、ポイントごとの最大高さを考える代わりに、最初のカバレッジについて考えることができます。 各 x 位置は、それをカバーする最も古い長方形によって「要求」され、その面積への寄与はその時点で固定されます。 

これにより、問題は、X 軸のどの部分がまだカバーされていないかを維持することに変わります。 長方形の場合$i$到着すると、その間隔のカバーされていない部分に正確に寄与し、次の値を掛けます。$H_i$。 

圧縮された座標に対するセグメント ツリーを使用して、カバーされていないセグメントを維持できます。 各セグメントは完全にカバーされているか、まだ利用可能です。 長方形を処理するとき、その間隔のどのくらいがまだカバーされていないかをクエリし、その寄与を$P_i$を選択し、それらの部分をカバー済みとしてマークします。 

これにより、各セグメントが全体で 1 回だけカバーされるようになり、ソリューションが効率的になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | プレフィックス共用体を再計算する |$O(n^2 \log n)$|$O(n)$| 遅すぎる |
 | カバレッジ追跡を備えたセグメント ツリー |$O(n \log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 すべての座標を圧縮して、各間隔のエンドポイントがセグメント ツリー上で管理可能なインデックスになるようにします。 

X 軸のどの部分がまだカバーされていないかを追跡するセグメント ツリーを維持します。 各ノードは、その間隔が完全にカバーされているかどうかを知っています。 

ランニングバリューも維持$P_i$、および実行中のアンサー製品。 

### ステップ

 1.すべての座標を収集する$L_i$そして$R_i$、それらを並べ替えて、インデックスに圧縮します。 これにより、連続した x 軸を隣接する座標間の離散セグメントとして表すことができます。 
2. 各リーフが連続する圧縮座標間の基本間隔を表すセグメント ツリーを構築します。 最初はすべてのセグメントがカバーされていないため、各ノードはその全長を利用可能なものとして保存します。 
3. 長方形を次から順に処理します。$1$に$n$。 長方形の場合$i$、その圧縮された間隔を考慮します$[L_i, R_i)$。 
4. 内部のカバーされていない合計の長さをセグメント ツリーに問い合わせます。$[L_i, R_i)$。 これにより、新しい領域に寄与する長方形の部分が正確に得られます。 
5. このカバーされていない長さに次の値を掛けます。$H_i$そしてそれを追加します$P_i$。 これが機能するのは、新しくカバーされた各 x 位置がこのステップで最初で唯一の高さの寄与を受けるためです。 
6. セグメント ツリーを更新して間隔をマークします。$[L_i, R_i)$完全にカバーされているため、将来の四角形はこれらの部分を無視します。 
7. 現在の答えを次のように乗算します。$P_i$モジュロ$998244353$。 

### なぜ効果があるのか

 不変条件は、すべての x セグメントが 1 つの四角形 (入力順序でその四角形をカバーする最初の四角形) に割り当てられることです。 高さは増加しないため、後の四角形は、すでに割り当てられているセグメントに対してより高い寄与を生み出すことはできません。 したがって、セグメントがカバーされているとマークされると、そのセグメントの将来のすべてのセグメントに対する貢献度は低くなります。$P_j$固定されており、決して変更されません。 

これにより、x-length の各単位が正確に 1 回処理され、その寄与が正しいタイム ステップで考慮されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

class SegTree:
    def __init__(self, coords):
        self.coords = coords
        self.n = len(coords) - 1
        self.size = 4 * self.n
        self.covered = [False] * self.size
        self.length = [0] * self.size
        self._build(1, 0, self.n - 1)

    def _build(self, v, l, r):
        if l == r:
            self.length[v] = self.coords[l + 1] - self.coords[l]
            return
        m = (l + r) // 2
        self._build(v * 2, l, m)
        self._build(v * 2 + 1, m + 1, r)
        self.length[v] = self.length[v * 2] + self.length[v * 2 + 1]

    def query(self, v, l, r, ql, qr):
        if ql <= l and r <= qr:
            if self.covered[v]:
                return 0
            return self.length[v]
        if r < ql or qr < l:
            return 0
        if self.covered[v]:
            return 0
        m = (l + r) // 2
        return self.query(v * 2, l, m, ql, qr) + self.query(v * 2 + 1, m + 1, r, ql, qr)

    def cover(self, v, l, r, ql, qr):
        if ql <= l and r <= qr:
            self.covered[v] = True
            return
        if r < ql or qr < l:
            return
        if self.covered[v]:
            return
        m = (l + r) // 2
        self.cover(v * 2, l, m, ql, qr)
        self.cover(v * 2 + 1, m + 1, r, ql, qr)
        if self.covered[v * 2] and self.covered[v * 2 + 1]:
            self.covered[v] = True

def get_idx(coords, x):
    # binary search
    lo, hi = 0, len(coords)
    while lo < hi:
        mid = (lo + hi) // 2
        if coords[mid] < x:
            lo = mid + 1
        else:
            hi = mid
    return lo

def main():
    n = int(input())
    rects = []
    coords = []

    for _ in range(n):
        l, r, h = map(int, input().split())
        rects.append((l, r, h))
        coords.append(l)
        coords.append(r)

    coords = sorted(set(coords))
    st = SegTree(coords)

    ans = 1
    pref_area = 0

    for l, r, h in rects:
        l = get_idx(coords, l)
        r = get_idx(coords, r) - 1

        if l <= r:
            add_len = st.query(1, 0, st.n - 1, l, r)
            if add_len > 0:
                pref_area = (pref_area + add_len * h) % MOD
                st.cover(1, 0, st.n - 1, l, r)

        ans = ans * pref_area % MOD

    print(ans)

if __name__ == "__main__":
    main()
```セグメント ツリーは圧縮された座標間隔に基づいて構築され、各リーフは実際の x セグメントを表します。 の`query`この関数は、まだカバーされていない間隔の部分のみを返します。 の`cover`関数は、それらのセグメントを使用済みとして永続的にマークし、以降の四角形が再びそこに寄与できないようにします。 

微妙な点は、カバレッジをセグメントごとに 1 回だけ割り当てることで、全体の複雑さが四角形の数ではなくセグメントの数に線形に保たれることです。 

## 実用的な例

 2 つの長方形について考えてみましょう。$$(1, 4, 5), (2, 3, 5)$$圧縮後、カバレッジの構造は次のように変化します。 

### トレース

 | ステップ | 長方形 | 照会されたカバーされていない長さ | 追加エリア | プレフィックスエリア$P_i$| 対象セグメント |
 | --- | --- | --- | --- | --- | --- |
 | 1 | (1,4,5) | 3 | 15 | 15 | [1,4) |
 | 2 | (2,3,5) | 0 | 0 | 15 | [1,4) |

 2 番目の長方形は、すでにカバーされている領域内に完全にあるため、何も寄与しません。 

これは、領域が一度主張されると、たとえそれらが強く重なり合ったとしても、その後の長方形はその領域に影響を及ぼさないことを示しています。 

ここで、互いに素な長方形を考えてみましょう。$$(1,2,3), (3,5,4)$$### トレース

 | ステップ | 長方形 | カバーされていない長さ | 追加エリア | プレフィックスエリア | カバーされた |
 | --- | --- | --- | --- | --- | --- |
 | 1 | (1,2,3) | 1 | 3 | 3 | [1,2) |
 | 2 | (3,5,4) | 2 | 8 | 11 | [1,2)、[3,5) |

 ここでは、両方の長方形が互いに素な領域を占有するため、両方の長方形が完全に寄与します。 

これらの例は、アルゴリズムが重複処理を素の累積から正しく分離していることを確認します。

 ## 特殊なケース

 次のような完全にネストされたケース$(1,10,5), (2,9,4), (3,8,3)$は、最初の長方形だけが最大の高さで区間全体をカバーしているため、どこでも寄与していることを示しています。 セグメント ツリーでは、最初の更新後に全範囲がカバーされるとマークされるため、後続の更新では寄与がゼロになります。 

のような完全に支離滅裂なケース$(1,2,10), (3,4,9), (5,6,8)$は、各長方形が完全に寄与していることを示しています。 セグメントの重複は存在しないため、すべてのクエリは完全な長さを返し、カバレッジは競合することなく段階的に割り当てられます。 

混合オーバーラップの場合は、部分的な充填動作を確認します。部分区間が前の長方形でカバーされると、後の長方形はカバーされていないギャップにのみ寄与し、各 x セグメントが 1 回だけ割り当てられるという不変条件と一致します。
