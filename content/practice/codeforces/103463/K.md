 ## 解決策
 ## 問題の理解

 ワインボトルの列は左から右に配置され、各ボトルには固定された固有の価値があります。 毎日、現在の行の左端または右端からボトルが 1 つずつ取り出されます。 面白いのは、ボトルから得られる価値はそれを摂取した日によって異なるということです。早い日には選択したボトルの価値に小さな係数が乗算され、遅い日にはさらに増幅されます。 

より正確に言うと、基本価値のあるボトルの場合、$v_i$当日に撮影されます$t$、報酬は$v_i \cdot t$。 1日1本取り外すので、$n$最終的にボトルが取り出され、プロセスは正確に続きます$n$日々。 

目標は、蓄積された報酬の合計を最大化する一連の左右の除去を選択することです。 

制約$n \le 2000$周囲の解決策を意味します$O(n^2)$は実現可能ですが、左右の決定のすべてのシーケンスを直接シミュレートしようとする戦略は、各ステップが 2 つの選択肢に分岐して生成されるため、指数関数的に爆発的に増加します。$2^n$可能性。 

大きな値が中央に位置する場合、単純な貪欲な推論による微妙な失敗例が現れます。 たとえば、値が次の場合、$[1, 100, 1]$、最初に端から取得するのは無害に見えるかもしれませんが、中間値を後日に遅らせると、より大きな係数が乗算され、最適な決定が完全に変わります。 これは、ローカルな選択では最終的な答えを決定できないことを示しています。 

値が等しいが位置が異なる場合、別の特殊なケースが発生します。 たとえ全部だとしても$v_i = 1$削除の順序は正確さにとって重要ではありませんが、アルゴリズムが特殊な場合のロジックに依存せずに一貫した構造を生成していることを確認するのに役立ちます。 

## アプローチ

 ブルートフォース戦略は、ボトルを左右から取り出すあらゆる可能なシーケンスをシミュレートすることです。 各ステップには 2 つの選択肢があるため、有効なシーケンスの数は次のとおりです。$2^n$。 各シーケンスについて、結果のスコアを線形時間で計算し、合計の複雑度は次のようになります。$O(n \cdot 2^n)$。 これは中程度の人でも実行不可能になります$n$、 以来$2^{2000}$天文学的に大きいです。 

重要な観察は、プロセスがボトルの現在の残り間隔によって完全に決定されるということです。 いつでも、関連するすべての履歴が現在の左右の境界によって捕捉され、現在の日はすでに取り出されたボトルの数によって暗黙的に決定されます。 これにより、決定の完全なシーケンスを追跡する必要がなくなります。 

この構造は当然、区間動的計画法の定式化につながります。 配列の任意の連続セグメントに対して達成可能な最良のスコアを定義し、どちらかのエンドポイントを削除することによって得られるより小さいセグメントの観点からそれを表現します。 各状態は、次に左または右のボトルを選択することに対応する 2 つの小さなサブ問題にのみ依存します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n \cdot 2^n)$|$O(n)$| 遅すぎる |
 | インターバルDP |$O(n^2)$|$O(n^2)$| 承認済み |

 ## アルゴリズムのチュートリアル

 動的プログラミング テーブルを定義します。$dp[l][r]$インデックスにまたがるサブ配列から取得できる最大合計報酬を表します$l$に$r$、プロセスが現在その間隔に制限されていると仮定します。 

1. 単一要素の DP を初期化します。 いつ$l = r$、残りは1本だけです。 当日に服用しなければなりません$n$、 それで$dp[l][l] = v_l \cdot n$。 これにより、計算は可能な限り最小の間隔で固定されます。 
2. 任意の間隔に関連付けられた日を計算します。$[l, r]$。 現在の残りの間隔が長ければ$len = r - l + 1$、 それから$n - len$ボトルは既に撤去されておりますので、本日は$t = n - len + 1$、これを単純化すると、$t = n - r + l$。 
3. 間隔の長さを増やすために DP テーブルを埋めます。 この順序により、計算するたびに次のことが保証されます。$dp[l][r]$、どちらも小さな副問題$dp[l+1][r]$そして$dp[l][r-1]$はすでに知られています。 
4. インターバルごとに$[l, r]$、2 つの候補遷移を計算します。 左のボトルを取れば得られる$v_l \cdot t$そしてインターバルに移ります$[l+1, r]$。 適切なボトルを飲めば利益が得られます$v_r \cdot t$そしてに移動します$[l, r-1]$。 これら 2 つのオプションのうち、より良い方を選択します。 
5. 最終的な答えは次のとおりです。$dp[1][n]$、これは 1 日目の完全な間隔に相当します。 

### なぜ効果があるのか

 どの状態であっても、将来の結果に影響を与える唯一の決定は、次にどのエンドポイントを削除するかということです。 現在の間隔の境界と、その日の計算でエンコードされる歩数を除いて、過去に関するその他の情報はすべて無関係です。 DP 状態はこの状況を完全に捉えており、エンドポイントを選択することで問題がすでに最適に解決されている厳密に小さい間隔に縮小されるため、すべての遷移で最適な下部構造が保存されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input().strip())
v = [0] + [int(input().strip()) for _ in range(n)]

dp = [[0] * (n + 2) for _ in range(n + 2)]

for i in range(1, n + 1):
    dp[i][i] = v[i] * n

for length in range(2, n + 1):
    for l in range(1, n - length + 2):
        r = l + length - 1
        day = n - r + l
        dp[l][r] = max(
            v[l] * day + dp[l + 1][r],
            v[r] * day + dp[l][r - 1]
        )

print(dp[1][n])
```この実装では、間隔境界によってインデックス付けされた 2D テーブルが構築されます。 ベースケースは、ボトルが 1 つだけ残る斜めのエントリに充填されます。 ネストされたループにより間隔サイズが増加するため、遷移に必要なサブ間隔はすでに計算されています。 その日の計算は、間隔の長さとすでに発生した削除の数との関係から直接得られます。 

DP は入力配列と一致するように 1 から始まるため、インデックス付けには注意が必要です。 時間乗数はエンドポイント間に残っている要素の数に依存するため、日の式は再帰の深さごとではなく間隔ごとに計算する必要があります。 

## 実用的な例

 インプットを考慮する$[1, 3, 1, 5, 2]$。 

私たちはいくつかの代表的な民進党州を追跡します。 

| 間隔 (l, r) | 日 | 左の選択肢 | 正しい選択 | dp[l][r] |
 | --- | --- | --- | --- | --- |
 | (2, 4) | 3 | 3・3 + dp[3][4] | 5・3 + dp[2][3] | 最良の計算結果 |
 | (1, 3) | 3 | 1・3 + dp[2][3] | 1・3 + dp[1][2] | 最良の計算結果 |
 | (1, 5) | 1 | 1·1 + dp[2][5] | 2・1 + dp[1][4] | 最終的な答え |

 このトレースは、アルゴリズムが正しい時間乗数を使用して両方のエンドポイントを一貫して評価する方法と、より大きな間隔が以前に解決されたより小さな間隔にどのように依存するかを示します。 

次に対称の場合を考えてみましょう$[2, 2, 2]$。 

| 間隔 | 日 | 左 | 右 | DP |
 | --- | --- | --- | --- | --- |
 | (2,2) | 3 | 6 | 6 | 6 |
 | (1,2) | 2 | 2・2+6 | 2・2+6 | 10 |
 | (1,3) | 1 | 2・1+10 | 2・1+10 | 12 |

 これは、値が同一の場合、両方の選択肢が同等のままであり、特別なケースを使用せずに DP が自然に正確さを維持することを示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input().strip())
    v = [0] + [int(input().strip()) for _ in range(n)]

    dp = [[0] * (n + 2) for _ in range(n + 2)]

    for i in range(1, n + 1):
        dp[i][i] = v[i] * n

    for length in range(2, n + 1):
        for l in range(1, n - length + 2):
            r = l + length - 1
            day = n - r + l
            dp[l][r] = max(
                v[l] * day + dp[l + 1][r],
                v[r] * day + dp[l][r - 1]
            )

    return str(dp[1][n])

# minimum size
assert run("1\n10\n") == "10"

# small case
assert run("3\n1\n3\n1\n") == "14"

# all equal
assert run("4\n5\n5\n5\n5\n") == str(5*1 + 5*2 + 5*3 + 5*4)

# increasing
assert run("3\n1\n2\n3\n") == run("3\n1\n2\n3\n")

# provided style example
assert run("5\n1\n3\n1\n5\n2\n") == "43"

 ## 特殊なケース

 1 本のボトルの場合、間隔は常に$[1,1]$、アルゴリズムはそれを日に直接割り当てます$n$、可能な唯一の結果と一致します。 

値が等しい場合、すべての遷移で同じ結果が得られるため、DP は各ステップで左または右のいずれかを選択できます。 計算される日は、間隔が縮小しても正しく増加し、合計が固定の等差数列と値を乗算した合計になることが保証されます。 

配列を厳密に増加または減少させる場合、アルゴリズムは間隔の長さごとに両方のエンドポイントを評価することで貪欲なトラップを回避します。 一方の端が局所的に最適であると思われる場合でも、DP は、後のより高い乗数の日のためにより大きな値を保存する可能性がある代替パスを引き続きチェックします。
