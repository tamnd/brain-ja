 ## 解決策
 ## 問題の理解

 私たちは、リンゴの山 1 個から始まり、m 個の子供の列を経て移行する決定論的な転移プロセスをモデル化しています。 最初の子は n 個のリンゴをすべて受け取ります。 各子は同じ操作を実行します。つまり、ちょうど 1 つのリンゴを消費し、残りのリンゴを x 個の等しい山に分割しようとします。 これらのパイルの 1 つは保持され、他の x − 1 パイルは次の子の入力として前方に渡されます。 

重要な制約は、すべてのステップで、リンゴを 1 つ食べた後に残っているリンゴの数が x で割り切れなければならず、最後の子の残りの山が正の整数でなければならないということです。 このタスクは、m 個の子すべてを通してこのプロセス全体を有効にする、リンゴの最小の初期数 n を決定し、その最小 n モジュロ 998244353 を出力することです。 

この構造は本質的に逐次的です。各子は、1 による減算と x による除算を含む線形算術条件を介して、入力値をより小さい出力値に変換します。 1 つのステップの出力は次のステップの入力になるため、システム全体は反復であり、m 回の遷移の間有効であり続ける必要があります。 

この制約により、m は最大 10^9、x は最大 10^9 まで許容されますが、テスト ケースの数は 10^3 に達する可能性があります。 これにより、テスト ケースごとの O(m) でも大きすぎるため、すべての子にわたるシミュレーションが即座に除外されます。 ソリューションでは、同じ変換を m 回繰り返す効果を閉じた形式の式に圧縮する必要があります。 

x = 2 または m が大きい場合、微妙なエッジ ケースが発生します。再帰が非常に急速に増大し、中間値が標準範囲を超えるため、モジュラー演算や閉じた形式を使用しない反復乗算に依存するアプローチは失敗します。 もう 1 つの微妙な点は、割り算がすべてのステップで成立する必要があるため、最終的な式が正しいように見えても、すべての算術シーケンスが有効であるとは限らないことです。 

## アプローチ

 直接シミュレーションしようとすると、未知の n から開始して変換を繰り返し適用します。つまり、1 を減算し、x で除算し、前方に伝播します。 n がすでにわかっていなければ中間値がわからないため、これを前進させることはできません。 

代わりに、プロセスを逆にします。 i 番目の子が何らかの値 a を受け取るとします。 リンゴを 1 つ食べた後、残りの a − 1 は、次の子に渡される値の x 倍に等しくなければなりません。 つまり、a − 1 は常に x で割り切れ、次の状態は (a − 1) / x になります。 これは逆反復を定義します。最後の有効な値がわかっていれば、前の値を再構築できます。 

最後の子の残りの山を 1 とします。これは正の整数でなければならず、最小の開始値が必要なためです。 m 回逆方向に作業すると、幾何学的構成に従って数値が拡張されます。各逆方向のステップで x が乗算され、1 が加算されます。これを m 回繰り返すと、閉じた形式の等比級数が得られます。 

これにより、式 n = 1 + x + x^2 + ... + x^{m} が得られます。 これは標準的な幾何学和であり、x ≠ 1 の場合、(x^{m+1} − 1) / (x − 1) として書き直すことができます。x ≥ 2 であるため、x − 1 は可逆剰余 998244353 であるため、剰余算術では除算は常に有効です。 

したがって、問題は高速なべき乗とモジュラー逆計算に帰着します。

 ## アルゴリズムのチュートリアル

 ### 1. プロセスを逆に再定式化する

 各子の後に状態を定義します。 子が値 a を持つ場合、前の状態は整数 b に対して a = x * b + 1 を満たす必要があります。 この反転は、1 を引いた後の残りを x 個の山に均等に分割する必要があるという要件によって強制されます。 

### 2. 最小限の有効な最終状態を特定する

最後の子は正の整数の山で終わる必要があります。 初期値を最小限に抑えるために、この最終値を 1 に設定します。これより大きな値を選択すると、以前に再構築されたすべての値が厳密に増加します。 

### 3. 繰り返し後方に展開します

 逆変換を繰り返し適用します。 

a_{k-1} = x * a_k + 1

 a_m = 1 から始めて、以下を生成します。 

a_{m-1} = x + 1

 a_{m-2} = x^2 + x + 1

 など。 

このパターンは、k 回の逆ステップの後、値が x のべき乗の合計になることを示しています。 

### 4. 幾何学的構造を認識する

 m ステップ後の初期値は次のようになります。 

n = sum_{i=0 ～ m} x^i

 これにより、逐次依存関係が閉じた形式の式に変換されます。 

### 5. 係数に基づいて効率的に計算する

 高速べき乗法 998244353 を使用して x^{m+1} を計算します。次に、法が素数であるため、フェルマーの定理を使用して x − 1 の逆剰余を計算します。 最後にそれらを次のように結合します。 

n = (x^{m+1} − 1) * inv(x − 1)

 ### なぜ効果があるのか

 逆再帰では、最終状態が固定されると、以前の状態がすべて一意に決定されます。 各ステップはアフィン (一次関数と定数) であるため、合成を繰り返すと等比数列が生成されます。 すべての有効な前方構成は、正確に 1 つの後方再構成に対応するため、最小の最終値を選択すると、最小の初期値が適用されます。 すべての変換が線形であり、法が素数であるため、モジュラー演算では等価性が維持され、x − 1 に対して逆数が存在することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modpow(a, e):
    res = 1
    while e:
        if e & 1:
            res = res * a % MOD
        a = a * a % MOD
        e >>= 1
    return res

def solve():
    T = int(input())
    for _ in range(T):
        m, x = map(int, input().split())

        if x == 1:
            # degenerate case: sum of 1 repeated (m+1) times
            print((m + 1) % MOD)
            continue

        # geometric sum: (x^(m+1) - 1) / (x - 1)
        num = modpow(x, m + 1) - 1
        num %= MOD

        den_inv = modpow(x - 1, MOD - 2)
        ans = num * den_inv % MOD
        print(ans)

if __name__ == "__main__":
    solve()
```コードは、閉じた形式の導出を直接実装します。 高速べき乗関数は、対数時間でべき乗を計算します。これは、m が最大 10^9 であるために必要です。 998244353 が素数であるため、逆モジュラーではフェルマーの定理が使用されます。 

特殊なケース x = 1 は、幾何学的公式が縮退するため、個別に処理されます。 すべての項が 1 であるため、合計は m + 1 になります。

## テストケース```python
import sys, io

MOD = 998244353

def modpow(a, e):
    res = 1
    while e:
        if e & 1:
            res = res * a % MOD
        a = a * a % MOD
        e >>= 1
    return res

def solve():
    input = sys.stdin.readline
    T = int(input())
    for _ in range(T):
        m, x = map(int, input().split())
        if x == 1:
            print((m + 1) % MOD)
            continue
        num = (modpow(x, m + 1) - 1) % MOD
        den = modpow(x - 1, MOD - 2)
        print(num * den % MOD)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    from contextlib import redirect_stdout
    out = io.StringIO()
    with redirect_stdout(out):
        solve()
    sys.stdin = old_stdin
    return out.getvalue().strip()

# sample-like checks
assert run("1\n3 2\n") == "15"
assert run("1\n2 3\n") == "13"

# edge cases
assert run("1\n0 5\n") == "1"
assert run("1\n5 1\n") == "6"
assert run("1\n1 2\n") == "3"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | m=3、x=2 | 15 | 幾何学的な展開の正確さ |
 | m=2、x=3 | 13 | モジュラー逆正正性 |
 | m=0、x=5 | 1 | 空のチェーンの動作 |
 | m=5、x=1 | 6 | 縮退 x=1 の処理 |
 | m=1、x=2 | 3 | 単一遷移の正確性 |

 ## 特殊なケース

 x = 1 の場合、各ステップは − 1 = 1 * next_value になるため、各ステップは単純に 1 を減算します。 最後の値 1 から始めて、m 回反転すると、n = m + 1 になります。幾何学式では MOD を法としてゼロによる除算が試行されるため、実装ではこのケースを明示的に処理します。 

m = 0 の場合、事実上変換は行われません。 最後の子は最初の子でもあるため、有効な値は n = 1 のみです。 

m が大きい x = 2 の場合、値は指数関数的に増加しますが、べき乗剰余演算によりオーバーフローが防止されます。 すべての演算が線形であり、反復ではなく累乗によって処理されるため、再帰はモジュロの下で安定します。
