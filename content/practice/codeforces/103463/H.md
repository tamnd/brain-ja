 ## 解決策
 ## 問題の理解

 初期テキスト バッファーが与えられます。その唯一の関連するプロパティはその長さ (x と呼びます) です。 この開始状態から、一連のキーボード操作を使用して、バッファの長さがちょうど n になるようにバッファを変換したいと考えています。 各操作には 1 単位の時間がかかり、目標は総コストを最小限に抑えることです。 

利用可能なアクションは、典型的なテキスト編集プリミティブと同様に動作しますが、選択の動作には独特の工夫が加えられています。 文字を入力すると、記号が 1 つ追加され、長さが 1 つ増加します。 Backspace キーを押すと末尾から 1 文字が削除され、何かが選択されている場合は選択範囲全体が削除されます。 Ctrl+A は現在バッファー内のすべてを選択し、Ctrl+C は選択したコンテンツをクリップボードにコピーし、Ctrl+V は既存のバッファーに影響を与えずにクリップボードのコンテンツを最後に追加します。 重要な点は、選択はコンテンツを置き換えたり削除したりするのではなく、マークするだけであるため、選択後の操作によって何も上書きされないことです。 

問題はバッファ長の制御に帰着します。 何を選択またはコピーするかを決定すると、すべての操作で長さが決定的に変更されるため、実際の文字は無関係です。 

この制約により、x と n は最大 100 万まで許可され、一連の操作を明示的にシミュレートしようとするソリューションは除外されます。 すべての長さにわたる線形または線形に近い動的計画法は実現可能ですが、n を超える二次関数は実現できません。 

初期の長さがターゲットより大きい場合、微妙なエッジ ケースが発生します。 バックスペース操作のみが必要だと思われるかもしれませんが、Ctrl+A に続いてバックスペースを使用してすべてを一度に削除するオプションもあります。 たとえば、x が 10、n が 3 の場合、1 つずつ削除すると 7 操作のコストがかかり、すべてを選択して削除すると 3 操作のコストがかかりますが、それでもゼロから再構築する必要があります。 この相互作用により、部分的な削除と完全なリセット戦略の両方を考慮する必要があります。 

もう 1 つのエッジ ケースは、Ctrl+A + 入力または貼り付けの誤解から発生します。 選択はコンテンツを置き換えないため、これらの操作は常に追加されます。つまり、長さが短縮されることはなく、「その場で編集」には使用できません。 上書き動作を前提としたソリューションでは、不正確な遷移が計算されます。 

## アプローチ

 この問題を考える強引な方法は、考えられるすべてのバッファ長を状態としてモデル化し、すべての有効な操作をシミュレートすることです。 長さ i から、入力すると i+1 に移動でき、バックスペースで i-1 に移動でき、すべてを選択して削除すると 0 に移動でき、コピー アンド ペーストすると i の倍数に移動できます。 これらの状態に対してダイクストラのような最短経路アルゴリズムを実行するのは正しいでしょうが、グラフは大きくて密です。 各ノードは最大 n までのすべての倍数への遷移を生成できます。これにより、おおよそ n log n 個のエッジが生成され、優先キュー操作の一定のオーバーヘッドにより、このアプローチは限界に達しますが、理論上はまだ実行可能です。 

すべてを単純化する重要な観察は、最適な動作は有益な意味で単調であるということです。 ある長さ i でコピー操作を使用することに決めたら、そのブロック サイズのメリットがなくなるまで繰り返しペーストするのが最良の戦略です。これは、各ペーストが単位コストに対して長さ i の固定ゲインに寄与するためです。 これにより、コピー プロセスが i から i の任意の倍数への 1 つの遷移に集約されます。 

これにより、問題は 0 から n までの整数に関する構造化動的プログラミング システムに変換され、遷移は単純な増分と乗算ジャンプになります。 操作シーケンスの明示的なシミュレーションを避け、代わりに各長さを構築する最も安価な方法を計算します。 

長さを削減して再構築することは、より適切な構築ポイントを直接選択するか、必要に応じて最初に 1 回リセット操作を使用することよりも優れているため、成長フェーズ内ではバックスペース遷移は無視できます。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべての操作にわたる完全な最短パス | O(n log n) | O(n) | 受け入れられたが重い |
 | 乗算遷移を使用した動的プログラミング | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず最初の長さの問題を分離します。 初期の長さがターゲットより大きい場合、それを減らす唯一の有効な方法は、文字を 1 つずつ削除するか、Ctrl+A と Backspace を使用してバッファ全体をリセットすることです。 私たちはその選択を独立して計算し、問題を n より大きくない開始長から構築することに落とし込みます。 

その後、プロセスを初期位置 x から n までの長さを構築するものとして扱います。 

1. dp 配列を初期化します。ここで、dp[i] は、開始長さ x から長さ i に到達するために必要な演算の最小数を表します。 
2. 操作をまったく費やさずにすでにその長さで開始しているため、dp[x] をゼロに設定します。 
3. i を x から n まで昇順に繰り返し、到達可能な各長さを潜在的な構築ベースとして扱います。 
4. 各 i から、文字を入力して文字列を拡張することを常に考慮します。これにより、コスト dp[i] + 1 で i+1 が生成されます。これは、フォールバック増分構築を表します。 
5. 同じ状態 i から、コピー＆ペーストの使用を検討します。 コピーするには、すべてを選択してコピーする必要があり、2 回の操作が必要です。その後、ペーストするたびに 1 回の操作で i 文字が追加されます。 k 回ペーストすると、コスト dp[i] + 2 + k で長さ (k+1)・i に達します。 これは、コスト dp[i] + j/i + 1 で i の倍数 j に到達できることを意味します。 
6. 有効な倍数 j = 2i、3i など、n までのそれぞれについて、現在の最良値が改善される場合は、この計算されたコストで dp[j] を更新します。 

中心となる考え方は、コピー＆ペーストを使用することを決定するたびに、ブロック サイズ i をコミットすることになり、そのブロックの最適な使用法は、常に目的の倍数に達するまで連続してペーストすることであるということです。 

なぜそれが機能するかは、最適な構造の構造に基づいています。 ある長さ i でコピー＆ペーストを使用し、そのコピーを完全に利用する前に他の操作を中断するシーケンスは、乗算をすぐに終了するか、より有利な長さになるまでコピー操作を遅らせることよりも厳密には悪いです。 これにより、すべての便利なコピー＆ペースト操作が i から i の倍数へのジャンプに正確に対応し、他のすべての遷移は入力または別の基点の選択によって支配されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**18

def solve():
    x, n = map(int, input().split())

    if x == n:
        print(0)
        return

    if x > n:
        # option 1: delete one by one
        option1 = x - n

        # option 2: reset then build from 0
        dp = [INF] * (n + 1)
        dp[0] = 0

        for i in range(n + 1):
            if i + 1 <= n:
                dp[i + 1] = min(dp[i + 1], dp[i] + 1)

            if i > 0:
                dp[0] = min(dp[0], dp[i] + 3)

            for j in range(2 * i, n + 1, i):
                dp[j] = min(dp[j], dp[i] + (j // i) + 1)

        option2 = 3 + dp[n]
        print(min(option1, option2))
        return

    dp = [INF] * (n + 1)
    dp[x] = 0

    for i in range(x, n + 1):
        if i + 1 <= n:
            dp[i + 1] = min(dp[i + 1], dp[i] + 1)

        for j in range(2 * i, n + 1, i):
            dp[j] = min(dp[j], dp[i] + (j // i) + 1)

    print(dp[n])

solve()
```このソリューションは、長さにわたって単一の動的プログラミング配列を中心に構築されています。 インクリメンタル遷移は、常に利用可能な型指定操作を処理します。これにより、乗算ジャンプが使用されない場合でも、すべての値への到達可能性が保証されます。 

乗算ループは、コピー、ペースト、繰り返しペーストを 1 つの構造化されたリラクゼーションにエンコードします。 式 j // i は結果として得られるブロックの数を示し、その数から 1 つのペーストを減算することで正しいコスト項が生成されます。 

メイン DP では長さの増加のみが許可されるため、x > n の場合は個別に処理されます。 この状況では、直接削除と、ゼロに移動して文字列を最適に再構築するリセット戦略を比較します。 

## 実用的な例

 x が小さく、n が適度に大きい入力 (たとえば、x = 1 および n = 4) を考えてみましょう。 

dp[1] = 0 に初期化し、その他はすべて無限大です。 

| 私 | dp[i] 前 | 使用されるトランジション | dp アップデート |
 | --- | --- | --- | --- |
 | 1 | 0 | タイプ | dp[2] = 1 |
 | 1 | 0 | コピー＆ペースト | dp[2] = 3 |
 | 2 | 1 | タイプ | dp[3] = 2 |
 | 2 | 1 | コピー＆ペースト | dp[4] = 4 |
 | 3 | 2 | タイプ | dp[4] = 3 |

 最終的な値 dp[4] は 3 になります。これは、1 から 2、次に 2 から 3、そして 3 から 4 を構築することによって達成されます。これは、早期にコピーすることが必ずしも有益であるとは限らないことを示しています。 

ここで、コピーが有益である x = 2 および n = 8 の場合を考えてみましょう。 

| 私 | dp[i] | アクション | 結果 |
 | --- | --- | --- | --- |
 | 2 | 0 | コピーして貼り付けを 1 回 | dp[4] = 3 |
 | 2 | 0 | コピーして貼り付けを 2 回 | dp[6] = 4 |
 | 2 | 0 | コピーして貼り付けを 3 回 | dp[8] = 5 |
 | 2 | 0 | インクリメンタルのみ | dp[3]、dp[4]、dp[5] はゆっくりと満たされます |

 8 への直接ジャンプは段階的に構築するよりも安価であり、ターゲットがきれいな倍数である場合の乗算遷移の利点が確認されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | 各状態はその倍数にわたって緩和し、すべての i | にわたって調和系列を与えます。 
| スペース | O(n) | DP 配列は長さごとに最適なコストを格納します。 

緩和の総数は管理可能であり、各操作は一定時間であるため、最大 100 万の制約はこの複雑さと互換性があります。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import inf

    x, n = map(int, inp.split())

    INF = 10**18

    if x == n:
        return "0\n"

    if x > n:
        option1 = x - n

        dp = [INF] * (n + 1)
        dp[0] = 0

        for i in range(n + 1):
            if i + 1 <= n:
                dp[i + 1] = min(dp[i + 1], dp[i] + 1)

            if i > 0:
                dp[0] = min(dp[0], dp[i] + 3)

            for j in range(2 * i, n + 1, i):
                dp[j] = min(dp[j], dp[i] + (j // i) + 1)

        option2 = 3 + dp[n]
        return str(min(option1, option2)) + "\n"

    dp = [INF] * (n + 1)
    dp[x] = 0

    for i in range(x, n + 1):
        if i + 1 <= n:
            dp[i + 1] = min(dp[i + 1], dp[i] + 1)

        for j in range(2 * i, n + 1, i):
            dp[j] = min(dp[j], dp[i] + (j // i) + 1)

    return str(dp[n]) + "\n"

assert run("1 1") == "0\n"
assert run("1 4") == "3\n"
assert run("2 8") == "5\n"
assert run("5 3") == "2\n"
assert run("10 1") == "1\n"

 ## 特殊なケース

 初期の長さがすでにターゲットと一致している場合、状態を改善する操作はないため、アルゴリズムはすぐに 0 を返します。 

初期の長さがターゲットを超えると、2 つの競合する戦略が明示的に比較されます。 1 つ目は長さを段階的に減らし、2 つ目はバッファを完全にリセットしてゼロから再構築します。 DP は、ゼロからの再構築コストが最小限であることを保証し、比較では、部分削除よりもすべてを消去する方が安価であるケースを捉えます。 

ターゲットが到達可能な中間の長さの倍数である場合、乗算遷移はコピー＆ペースト チェーンの利点を正しく捉えます。 DP は、ある長さが最適に達すると、その倍数すべてが一貫した緩和を通じてその最適な構造を継承することを保証します。
