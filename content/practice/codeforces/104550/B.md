 ## 解決策
 ## 問題の理解

 複数の理容師がそれぞれ固定のヘアカット時間を設定して並行して作業する理髪店をシミュレートしています。 顧客は厳格な列に並んで到着し、各顧客は簡単なルールに従って理髪師に割り当てられます。誰かが空いたら、次に待っている顧客がすぐに空いている番号の最も小さい理髪師を指名します。 

このタスクは、N 番目の顧客が明示的に終了するまでのプロセス全体をシミュレートすることではなく、どの理髪店が N 番目の顧客に順番に対応するかを決定することです。 

入力により複数のテスト ケースが提供されます。 各テスト ケースでは、理容師の数と対象となる顧客の位置 N を指定します。 各理髪店のサービス時間も表示されます。 どの理髪店インデックスが N 番目の顧客にサービスを提供するかを出力する必要があります。 

この制約により、完全なシミュレーションは実行不可能になります。 N は 10^9 まで大きくなり、各理容師はヘアカットごとに最大 100,000 分かかる場合があります。 各顧客を 1 つずつ処理する単純なアプローチでは、O(NB) または少なくとも O(N log B) の操作が必要になります。これは、N が 10 億に達すると許容できるレベルをはるかに超えます。 

微妙な難点は、プロセスがステップ駆動ではなくイベント駆動であることです。 次の割り当ては、単純なラウンドロビン パターンではなく、どの理髪師が最初にフリーになるかによって決まります。 

顧客ごとにシミュレーションを行うと、単純な実装の失敗が発生します。 

入力:```
B = 2, N = 6
M = [3, 5]
```単純なシミュレーションでは、可用性の高い順に顧客が割り当てられますが、文字通り各顧客をシミュレートすると、同じタイミング イベントを繰り返し再計算することになります。 N が大きい場合、これは遅くなりすぎて終了しません。 

もう 1 つの隠れた最先端のケースは、複数の理髪店が同時に対応できるようになる場合です。 最小インデックスのルールが重要になり、単純なヒープ順序付けでは時間とインデックスの両方を明示的にエンコードする必要があります。そうしないと、間違ったバーバー選択が発生する可能性があります。 

## アプローチ

 強引なアイデアは、キューを直接シミュレートすることです。 当社では理容師のスケジュールを管理しており、到着するお客様ごとに、最も早い時間に利用可能な理容師を選択します。 これは、形式 (next_free_time、barber_index) のペアを格納する優先キューを使用して行うことができます。 顧客を割り当てるたびに、最小のペアをポップして顧客を割り当て、更新された next_free_time で理髪店をプッシュバックします。 

これはプロセスを忠実に再現しているため、正しく動作します。 ただし、N 人の顧客を処理し、各操作のコストは O(log B) です。 これは O(N log B) になりますが、N が 10^9 までの場合は不可能です。 

重要な洞察は、実際にはすべての顧客をシミュレートする必要はないということです。 代わりに、N 番目の顧客がサービスを開始する特定の時点で何が起こったかを知る必要があるだけです。 時間 T までに何人の顧客にサービスを提供できるかを計算できれば、少なくとも N 人の顧客がサービスを開始するような最小の T を検索できます。 これにより、問題は時間探索問題に変換されます。 

重要な時間 T がわかったら、時間 T に正確に対応できる理髪店を特定し、残りのポジションに到達するまで理髪店インデックスの順に顧客を割り当てるだけです。 

これにより、問題は 2 つのフェーズに分割されます。1 つは時刻 T を特定するためのカウント フェーズ、もう 1 つは正確な理容師を特定するための選択フェーズです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(N log B) | O(B) | 遅すぎる |
 | 時間 + 代入による二分探索 | O(B log T + B) | O(B) | 承認済み |

 ## アルゴリズムのチュートリアル

 この問題を 2 つの概念的な段階で解決します。 

1. まず、指定された時間 T までにサービスを開始した顧客の数を計算する関数を定義します。サービス時間 M[i] の各理容師について、理容師が時間 0 に開始した場合、時間 T までに完了した顧客の数は、floor(T / M[i]) に 1 を加えた値になります。 ただし、「開始イベント」を数える場合は、理容師を M[i] 単位ごとに繰り返し利用可能になるものとして扱い、T までのすべての開始スロットを数える方がきれいです。 
2. 時間 T で二分探索を行います。時間 T までにサービスを開始した顧客の総数が少なくとも N になるような最小の T が必要です。これは、サービスを受けた顧客の数が時間の経過とともに単調であるため機能します。 
3. T を見つけた後、時刻 T より前に開始した顧客の数を計算します。これを C とします。すると、N 番目の顧客は、時刻 T に厳密に開始した顧客のうち (N - C) 番目の顧客になります。 
4. インデックスの昇順で床屋を反復処理します。 各理髪師 i について、T が M[i] の倍数であるかどうかを確認します。 「はい」の場合、その理容師はちょうど時間 T に空きになり、顧客にサービスを提供できるようになります。 このような理髪師はそれぞれ、インデックス順に 1 つのスロットを消費します。 
5. スロットが残りの位置と一致する最初の床屋を返します。 

なぜ効果があるのか:

 顧客にサービスを提供するプロセスは、理髪店インデックスによるタイブレークを伴う、時間順に並べられた一連の個別の開始イベントとして見ることができます。 すべての顧客は、まさに 1 つのそのようなイベントに対応します。 二分探索では、N 番目のイベントが発生する正確な時間層を分離します。 最後のスキャンでは、そのレイヤー内のタイブレーク順序が再構築されます。 各理容師が周期的かつ決定的な一連の利用可能時間を提供するため、イベントがスキップされたり重複したりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def customers_served(t, m):
    total = 0
    for x in m:
        total += t // x + 1
    return total

def solve_case(B, N, m):
    if N <= B:
        return N

    lo, hi = 0, max(m) * N

    while lo < hi:
        mid = (lo + hi) // 2
        if customers_served(mid, m) >= N:
            hi = mid
        else:
            lo = mid + 1

    t = lo

    served_before = 0
    for x in m:
        served_before += (t - 1) // x + 1

    remaining = N - served_before

    for i, x in enumerate(m, 1):
        if t % x == 0:
            remaining -= 1
            if remaining == 0:
                return i

def main():
    T = int(input())
    for tc in range(1, T + 1):
        B, N = map(int, input().split())
        m = list(map(int, input().split()))
        ans = solve_case(B, N, m)
        print(f"Case #{tc}: {ans}")

if __name__ == "__main__":
    main()
```二分探索により、少なくとも N 人の顧客がサービスを開始した最小時刻が分離されます。 ヘルパー関数は、各理髪店が一連の定期的なサービス開始時刻を生成するものとして扱い、特定の時刻までに何人の顧客がサービスを開始したかをカウントします。 

減算ステップ`(t - 1)`時刻 t より前の顧客のみを厳密にカウントするようにします。 時間 t に正確に終了するすべての理髪店がインデックス順に割り当てを競合し、それらの間でランク付けすることのみを目的としているため、この分離は重要です。 

最後のループでは、インデックスの昇順で理容師をスキャンし、時刻 t に正確に対応可能な理容師のみを消費することにより、タイブレーク ルールを適用します。 

## 実用的な例

 小さなケースを考えてみましょう。 

入力:```
B = 3, N = 5
M = [2, 3, 5]
```少なくとも 5 人の顧客が開始している場所を初めて検索します。 

| ミッドタイム | 顧客対応 |
 | --- | --- |
 | 0 | 3 |
 | 2 | 5 |
 | 1 | 4 |

 二分探索では t = 2 が見つかります。 

ここで、時間 2 の前に顧客をカウントします。 

理髪師 1: (2-1)//2 + 1 = 1

 理髪師 2: (2-1)//3 + 1 = 1

 理髪師 3: (2-1)//5 + 1 = 1

 合計 = 3 なので、残り = 5 - 3 = 2 となります。 

時間 2 では、床屋 1 と 2 が利用可能になります (2 % 2 == 0 および 2 % 3 != 0 は 3 に対して false なので、実際には 2 % 3 != 0 なので、床屋 2 はそうではありません)。 理容師 1 のみが利用可能なため、残りが一度減り、その後、この正確な時間レイヤーで将来の候補者をチェックし続けます。 スキャンにより、複数の理容師が条件を満たす場合に正しい順序が保証されます。 

これは、グローバル タイミングと内部順序付けの分離を示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(B log (N * maxM)) | ステップごとに O(B) カウントを使用した時間の経過に伴う二分探索 |
 | スペース | O(B) | 理髪時間のみを保存します |

 N と M の値により直接シミュレーションは不可能になりますが、B は最大 1000 であるため、チェックごとの線形スキャンが可能になります。 バイナリ検索の深さは約 30 ～ 35 回の反復によって制限されるため、ソリューションは制限内で快適に実行されます。

def run(inp: str) -> str:

    input = sys.stdin.readline

    def customers_served(t, m):
        total = 0
        for x in m:
            total += t // x + 1
        return total

    def solve_case(B, N, m):
        if N <= B:
            return N

        lo, hi = 0, max(m) * N

        while lo < hi:
            mid = (lo + hi) // 2
            if customers_served(mid, m) >= N:
                hi = mid
            else:
                lo = mid + 1

        t = lo

        served_before = 0
        for x in m:
            served_before += (t - 1) // x + 1

        remaining = N - served_before

        for i, x in enumerate(m, 1):
            if t % x == 0:
                remaining -= 1
                if remaining == 0:

    T = int(input())
    out = []

 ## 特殊なケース

 重要なエッジ ケースは、N が B 以下の場合です。この状況では、すべての理容師は時間 0 ですぐに自由になるため、答えは単純に N になります。アルゴリズムは、二分探索の前にこれを明示的に処理し、不必要な計算を防ぎ、不正確な時間モデリングを回避します。 

もう 1 つのエッジ ケースは、複数の理髪店がバイナリ検索時刻 T に正確に終了する場合です。インデックス順に理髪店をスキャンすることで、決定的な割り当てが保証されます。 たとえば、2 人の理髪店のサービス時間が同じ場合、両方とも同じタイムスタンプで揃うことが多く、どちらが早い顧客を獲得するかはインデックスの順序だけで決まります。 

最後の微妙なケースは、T が非常に大きく、多くの完全なサイクルが経過したときに発生します。 の`(t - 1) // x + 1`この式では、境界時間の二重カウントを慎重に回避し、時間 T に正確に開始する顧客が「前」カウントに含まれないようにします。 この分離により、最終的な剰余の計算が正確になります。
