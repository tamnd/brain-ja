 ## 解決策
 ## 問題の理解

 一定の時間間隔で取得された一連の観察が与えられます。各値は、その瞬間に皿の上にあるキノコの数を表します。 観察の合間にキノコを任意に加えたり、食べたりすることもできます。 

課題は、ケイリンの食行動の 2 つの異なる解釈に基づいて、ケイリンが食べたはずのキノコの最小総数を再構築することです。 

最初の解釈では、食事には時間と速度の制限がありません。 連続した観察の各ペアの間でキノコ数が減少した場合、その減少は食事によって説明されなければなりません。 数値が増加した場合は、キノコが追加されたと考えられるため、その変化を説明するために食べる必要はありません。 

2 番目の解釈では、ケイリンは最初の観察から始めて、キノコが存在するときはいつでも一定の速度で食事をします。 これは、観察されたすべての減少が皿を決して陰性にすることなく説明でき、バーソロミューの追加によってのみキノコが蓄積するような単一の摂食率を見つけなければならないことを意味します。 

入力サイズは、テスト ケースあたり最大 1000 の観測値、および最大 100 のテスト ケースになります。 テスト ケースごとの 2 次またはそれより悪い解は理論的にはまだ許容されますが、各ステップは前の値にのみ依存するため、構造は線形スキャンで十分であることを示唆しています。 大域最小値を再計算したり、考えられるすべての食事スケジュールをシミュレートしようとしたりするソリューションは不必要であり、非効率となる危険性があります。 

一般的なエッジ ケースは、シーケンスが非減少の場合に発生します。 この状況では、最初の方法では減少がまったく起こらないため、結果はゼロになりますが、2 番目の方法では、強制的な食事速度が必要ないため、結果もゼロになります。 もう 1 つの微妙なケースは、シーケンスが長いプラトーの後に急激に低下する場合であり、「食事による自然な減少」と「必要な一定の消費率」を区別できない実装で誤解を招く可能性があります。 

## アプローチ

 最初の計算では、隣接するペアをスキャンし、シーケンス内のすべてのドロップを合計するのが自然なアプローチです。 時間 i の値が時間 i+1 の値よりも大きい場合、その差は、食べることによって消えたキノコを表しているに違いありません。 このようなドロップをすべて合計すると、下限が得られ、実際には正確な最小値が得られます。バーソロミューはキノコを追加するだけで、ケイリンは減少を説明するのに必要な量を正確に食べると常に想定できるためです。 

これが機能するのは、各間隔が独立しているためです。増加は食事の制約にならず、減少は将来の状態に影響を与えることなく常に消費に直接起因することができます。 

キノコが存在する場合、ケイリンの食事は一定の速度に制限されるため、2 番目の計算はより微妙です。 重要な観察は、この率が 2 つの連続する観察の間の最大の低下によって決定されるということです。 10 秒の間隔で皿が a から b に減少した場合、ケイリンはその間隔で少なくとも (a − b) 個のキノコを食べていたはずです。 各間隔は同じ長さであるため、必要なレートは、そのようなすべてのドロップの最大値を間隔の長さで割ったものになります。 この速度が固定されたら、プロセスをシミュレーションします。各ステップで、ケイリンがその速度で 10 秒間食事をすると仮定します (ゼロ以下の境界)。期待値と観測値の間の不足は加算によって説明されます。 

強引なアイデアは、考えられるすべての食事速度を試し、それぞれのプロセス全体をシミュレーションして、実現可能性をチェックすることです。 これでは遅すぎます。レートの範囲が配列の最大値に達する可能性があり、各シミュレーションが N で線形であるため、2 次またはそれ以上の複雑さになるからです。 

単一ステップの最大降下のみが重要であるという観察により、問題は単一パスの計算に帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N * 最大値) | お(1) | 遅すぎる |
 | 最適 | O(N) | お(1) | 承認済み |

## アルゴリズムのチュートリアル

 ### 方法 1 (無制限の食事)

 1. 連続する観測値のペアを繰り返します。 
2. 数列が m[i] から m[i+1] に減少するたびに、m[i] − m[i+1] を答えに加算します。 
3. 増加は、摂食行動ではなく、新しいキノコの追加によって説明できるため、無視します。 

各減算は、消滅したはずのキノコを直接表しており、モデルでは任意の食べるタイミングが許可されているため、異なる間隔の間に相互作用はありません。 

### 方法 2 (食べる速度を一定にする)

 1. 連続する観測間の最大減少を計算します。 これにより、実現可能な最小の一定レートが決まります。 
2. 10 秒ごとにこの速度で食事をシミュレートします。 
3. 各ステップごとに、現在の皿の値とレートの小さい方の量が食べられます。 
4. 一定期間にわたって食べたすべてのキノコを合計します。 

現在の値で最小値を取る主な理由は、皿がゼロになると、たとえ一定のレートがそれ以上食べるべきであることを示唆していても、ケイリンはそれ以上食べることができないということです。 

### なぜ効果があるのか

 最初の方法では、他のメカニズムで数が減少しないため、すべての減少は消費されたキノコに正確に対応する必要があります。 これにより、間隔ごとに直接保存の議論が作成されます。 

2 番目の方法では、観測された最悪の低下によって一定のレートが強制されます。 これより小さい金利はその低下を説明できませんが、これより大きい金利はマイナスカウントなしで維持することは不可能です。 固定されると、シミュレーションは決定論的になります。プレートは追加と制限された消費を考慮して独自に進化するため、総消費量はプロセスによって完全に決定されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(arr):
    # Method 1: sum of all decreases
    y = 0
    for i in range(len(arr) - 1):
        if arr[i] > arr[i + 1]:
            y += arr[i] - arr[i + 1]

    # Method 2: determine eating rate
    rate = 0
    for i in range(len(arr) - 1):
        rate = max(rate, arr[i] - arr[i + 1])

    z = 0
    for i in range(len(arr) - 1):
        z += min(arr[i], rate)

    return y, z

def main():
    t = int(input())
    for tc in range(1, t + 1):
        n = int(input())
        arr = list(map(int, input().split()))
        y, z = solve_case(arr)
        print(f"Case #{tc}: {y} {z}")

if __name__ == "__main__":
    main()
```最初のループは、すべての下向き遷移を集計することによって強制消費量の合計を計算します。 2 番目のループでは、最悪のドロップを特定し、一定の食事制限を定義します。 

最終的なシミュレーションでは、10 秒間隔でケイリンが最大で食べられる量を想定しています。`rate`、しかしまた、存在するもの以上に食べることはできません。 これが理由です`min(arr[i], rate)`消費量を正しく制限します。 

実装上の微妙な点は、2 番目の方法では時間を継続的にシミュレートしないことです。 各間隔は均一であるため、観測境界での消費のみが考慮されます。

def run(inp: str) -> str:

    t = int(data[0])

 ## 特殊なケース

 次のような厳密に増加するシーケンス`[1, 2, 3, 4]`どちらのモデルでも消費量はゼロです。 最初の方法では減少が発生しないため、項は追加されません。 2 番目の方法では、最大ドロップ量ゼロが計算され、摂食率がゼロになるため、シミュレーションでは何も消費されません。 

大幅な下落とその後の回復`[10, 0, 10]`、最初の遷移により、2 番目のメソッドがレートを 10 に設定するように強制されます。 次のステップでは、値が上昇しても消費量は現在の値に制限され、合計 20 個が食べられます。 最初の方法では、単一の低下のみが考慮され、10 が得られます。これにより、ローカルな減額計算とグローバルな料金適用が分離されていることが確認されます。 

次のようなフラットなシーケンス`[0, 0, 0, 0]`どちらのメカニズムもトリガーされることはありません。 減少や必要なレートが存在しないため、どちらの計算も全体を通じてゼロのままです。
