 ## 問題の理解

 それぞれ最大次数の 2 つの整数多項式を作成するように求められます。$n$、非常に小さな係数 (各係数は -1、0、または 1) で、先頭の係数は両方とも 1 に等しい。これら 2 つの多項式に対して、多項式の標準ユークリッド アルゴリズムを実行し、各ステップでペアを置き換えます。$(A(x), B(x))$と$(B(x), A(x) \bmod B(x))$、そのような遷移ごとにステップがカウントされます。 

タスクは gcd を計算することではなく、このユークリッド処理が正確に実行されるように入力多項式を設計することです。$n$終了する前の分割ステップ。 また、最初の多項式の次数が 2 番目の多項式の次数よりも厳密に大きいことを確認する必要があります。 

多項式のユークリッド アルゴリズムは整数と同様に動作します。各剰余の次数は除数よりも厳密に小さいため、プロセスは終了する必要があります。 ただし、ステップ数は、度がどの程度「ゆっくり」減少するかに大きく依存します。 課題は、特定の境界に対して考えられる最悪の動作を強制することです$n$。 

制約$n \le 150$線形または二次の複雑さを持つ構築は自明であることを意味します。 本当の難しさは構造的なものです。ユークリッド連鎖の長さが正確である多項式を明示的に設計する必要があります。$n$。 これは計算上の問題ではなく、建設的な問題です。 

微妙なエッジ制約は、係数が次のように制限されることです。$[-1, 1]$。 これにより、慎重にエンコードしない限り、二項展開やフィボナッチのような成長などの任意の整数構造が排除されます。 もう 1 つの制約は、先頭の係数が 1 でなければならないため、ユークリッド構造を単純化するために多項式をスケールすることができないことです。 

単純な試みでは、ランダムな疎多項式や次のような単純なパターンを試す可能性があります。$x^n$そして$x^{n-1}$、しかし、これらは即座の縮小と非常に短いユークリッド連鎖を生成します。 通常、アルゴリズムは 1 つまたは 2 つのステップで崩壊し、必要なステップとは程遠いものになります。$n$。 

## アプローチ

 ブルートフォースの観点では、多項式を段階的に構築しようとしながら、ユークリッド アルゴリズムをシミュレートします。 貪欲に多項式を構築しようとする人もいるかもしれません。各ステップで、剰余が除数より正確に 1 つ少ない次数になるように係数を選択し、これにより連鎖が拡張されることを期待します。 ただし、各係数の選択は将来のすべての剰余に影響を与え、次数が小さくても候補多項式が指数関数的に多く存在するため、これはすぐに手に負えなくなります。 たとえ$n = 20$、総当たり的な係数の割り当てが爆発的に増加します。 

重要な洞察は、一般的な多項式の観点から考えるのをやめ、代わりにユークリッド アルゴリズムを制御された次数削減プロセスのように動作させることです。 偶発的に大きくジャンプすることなく、各除算ステップで次数を 1 だけ減らす必要があります。 これは、各剰余が本質的に前の除数のシフトされたバージョンであるチェーンを構築し、決定的な動作を保証することを示唆しています。 

最大長のユークリッド実行を強制する標準的な方法は、連分数のような構造を多項式形式でエンコードすることです。 剰余が段階的なシフトを模倣する多項式を構築します。$$A_0, A_1, A_2, \dots, A_n$$次のような:$$A_{i-1} = x \cdot A_i + A_{i+1}$$それぞれと$A_i$学位を持っている$n-i$。 これにより、ステップごとに正確に 1 度の降下が保証され、一定の長さのチェーンが生成されます。$n$。 

この漸化式は、各ステップが次に低い次数の項にのみ影響を与える制御された減算を導入する「階段」多項式を慎重に構築することによって、{-1, 0, 1} の係数を使用して実現できます。 

この構築は、次の定義に要約されます。$$A_0 = x^n, \quad A_1 = x^{n-1} + x^{n-2} + \cdots + 1$$次に、ユークリッド アルゴリズムがフィボナッチのような剰余チェーンを伝播するように強制します。 ソリューションで使用されるより安定した定式化は、次の形式の連続する剰余に対応する多項式を構築することです。$$A_i = x^{n-i} + A_{i+1}$$これにより、各分割が先頭の用語を 1 つだけ削除し、構造的に同一の小さなインスタンスが残ることが保証されます。 

これにより、制御されたカスケードが生成されます。$n$ステップ。

 ## アルゴリズムのチュートリアル

 2 つの多項式を構築します$A(x)$そして$B(x)$Euclid のアルゴリズムは一度に 1 度ずつ繰り返し削除します。 

1. 一連の多項式を定義することから始めます$A_0, A_1, \dots, A_n$、 どこ$A_i$学位を持っています$n-i$。 Euclid のアルゴリズムが次から移行することを強制します。$(A_i, A_{i+1})$に$(A_{i+1}, A_{i+2})$。 
2. 最後の多項式が定数になるようにチェーンのベースを設定します。$A_n = 1$。 これにより終了が保証されます。 
3. 以下を確保して逆方向に構築します。$$A_i = x \cdot A_{i+1} + A_{i+2}$$このアイデンティティは、次のような分割を強制します。$A_{i+1}$余りを生み出す$A_{i+2}$、レベルごとに正確に 1 つのユークリッド ステップを保証します。 
4. から始めてボトムアップで係数を構築することにより、この繰り返しを明示的にエンコードします。$A_n$そして$A_{n-1}$、すべての係数が {-1,0,1} に留まるようにします。 
5. 出力$A_0$そして$A_1$2 つの必要な多項式として。 

### なぜ効果があるのか

 この構築では、各除算ステップが連続する多項式間の漸化式によって事前に決定される決定論的なユークリッド連鎖が強制されます。 それぞれだから$A_i$よりちょうど 1 度低いです$A_{i-1}$、除算では常に商が得られます。$x$そして残り$A_{i+1}$。 これにより、次数のショートカットの削減が防止されるため、ユークリッド アルゴリズムは早期に終了できず、正確に実行する必要があります。$n$トランジション。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input().strip())

# We construct polynomials A0 and A1.
# A_i will be represented implicitly; we build coefficient lists bottom-up.

# A_n = 1
cur = [1]

# We iteratively build A_{i-1} from A_i by setting:
# A_{i-1} = x * A_i + A_{i+1}
# We simulate a simple staircase where A_{i+1} is a shifted version.
for i in range(n):
    # shift cur by multiplying by x
    shifted = [0] + cur

    # next polynomial introduces +1 at constant term
    nxt = shifted[:]
    nxt[0] += 1

    cur = nxt

# cur corresponds to A_0
A0 = cur

# build A1 similarly by reversing one step
cur = [1]
for i in range(n - 1):
    shifted = [0] + cur
    nxt = shifted[:]
    nxt[0] += 1
    cur = nxt

A1 = cur

# pad A1 if needed
if len(A1) < len(A0) - 1:
    A1 += [0] * (len(A0) - 1 - len(A1))

print(len(A0) - 1)
print(*A0)
print(len(A1) - 1)
print(*A1)
```最初のループは、シフトされた累積パターンに従う係数を持つ多項式を構築し、繰り返しを効果的にエンコードします。$x$-制御された定数項注入による乗算。 これにより、厳密に増加する次数チェーンが保証されます。 

2 番目の多項式は 1 ステップ短く構成されているため、最初の除算は自明ではなくなり、ユークリッド プロセスは厳密な次数ギャップで開始され、最初の多項式の次数が高いという要件が満たされます。 

パディングステップにより、出力形式で必要とされる係数の長さの位置合わせが保証されます。
