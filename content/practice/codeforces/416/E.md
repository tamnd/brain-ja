[CF 416E - 大統領の道](https://codeforces.com/problemset/problem/416/E)

 **解決時間:** 2 分 4 秒

 ## 解決策
 ## 問題の理解

 グラフが与えられました`n`によってつながる都市`m`それぞれ正の長さを持つ双方向の道路。 目標は、都市のペアごとに決定することです。`(s, t)`と`s < t`、**少なくとも 1 つの最短パス**上に現れる道路は何本ありますか`s`に`t`。 出力は、これらのカウントを辞書編集順にリストしたフラット シーケンスです。`(s, t)`。 

入力はグラフをエッジとして指定します`(x, y, l)`、出力では、各都市ペア間の最短パスの一部である可能性のあるエッジがカウントされます。 2 つの都市が接続されていない場合、カウントはゼロになります。 

制約が教えてくれるのは`n`は最大 500 です。これは、次の操作が行われることを意味します。`O(n^3)`実現可能ですが、何でも`O(n^4)`遅すぎる可能性があります。 各エッジの長さは 10^6 に達する可能性があるため、小さな重みを想定することはできません。 この問題により、`m`これは、一部の都市が接続されていない可能性があることを意味します。 

微妙なエッジ ケースには、2 つの都市間の複数の最短パスを含むグラフ、切断されたペア、および等しい重みのエッジのサイクルを含むグラフが含まれます。 たとえば、長さ 1 のエッジがサイクルを形成する 4 つの都市の正方形では、頂点 1 から 3 への最短パスはどちらの対角ルートも使用できるため、エッジの数には最短パスに参加するすべてのエッジが含まれます。 単一のパスのみをカウントする単純なアプローチでは、ここでは過小評価されてしまいます。 

## アプローチ

 ブルートフォースアプローチは簡単です: すべてのペアに対して`(s, t)`、ダイクストラまたは BFS を実行してすべての最短パスを検索し、それらのエッジにマークを付けます。 しかし、これを素朴に行うと、次のようになります。`O(n * (n + m) log n)`ペアごとに、あきらめる`O(n^2 * (n + m) log n)`操作。 と`n = 500`そして`m ~ n^2`、これは数億の操作に達する可能性があり、これでは遅すぎます。 

重要な洞察は、最初に **すべてのペアの最短距離** を計算できることです。 わかったら`dist[u][v]`すべてのペアについて、エッジかどうかを判断できます。`(u, v)`～からの最短経路上にあります`s`に`t`単純な距離チェックを使用する: if`dist[s][u] + length(u, v) + dist[v][t] == dist[s][t]`、エッジはからの最短経路上に現れることができます。`s`に`t`。 これにより、計算の繰り返しが削減され、すべてのパスを明示的に列挙することが回避されます。 

最適なアプローチでは、各ノードから **Floyd-Warshall** または Dijkstra を使用して、すべてのペアの最短パスを計算します (`O(n^3)`フロイド・ウォーシャルの場合）。 次に、ソースごとに、`s`、すべてのエッジと宛先を反復処理します。`t`最短経路条件を確認します。 これにより、入れ子構造が形成されますが、その構造は内部に残ります。`O(n^3)`各チェックは一定時間であるためです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2 * (n + m) log n) | O(n + m) | n=500 では遅すぎる |
 | 最適 | O(n^3) | O(n^2 + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 距離行列を初期化する`dist`サイズの`n x n`無限大とセット付き`dist[u][u] = 0`。 これは、各都市から他のすべての都市までの現在の最短距離を表します。 
2. 人口を投入する`dist`直接エッジの長さ: 各エッジについて`(u, v, w)`、 セット`dist[u][v] = dist[v][u] = min(dist[u][v], w)`複数のエッジを考慮するためです (問題では最大でも 1 つと記載されていますが、これにより偶発的な上書きが回避されます)。 
3. フロイド-ウォーシャルを適用: 各中間都市に`k`、ペアごとに`(i, j)`、 アップデート`dist[i][j] = min(dist[i][j], dist[i][k] + dist[k][j])`。 このステップの後、`dist[i][j]`～からの最短距離を保つ`i`に`j`。 
4. 配列を初期化する`count`サイズの`n x n`少なくとも 1 つの最短パス上のエッジの数をそれぞれに保存します。`(s, t)`。 
5. 各エッジについて`(u, v, w)`、すべてのソース都市を反復処理します。`s`およびすべての目的地都市`t`と`s < t`。 もし`dist[s][u] + w + dist[v][t] == dist[s][t]`または`dist[s][v] + w + dist[u][t] == dist[s][t]`、増分`count[s][t]`by 1. これはエッジかどうかをテストします。`(u, v)`～からの最短経路上にあります`s`に`t`。 
6. 平らにする`count`みんなのために`s < t`単一のシーケンスにまとめて印刷します。 

**機能する理由**: フロイド-ウォーシャル ステップは次のことを保証します。`dist[s][t]`真の最短距離が含まれています。 チェック中`dist[s][u] + w + dist[v][t] == dist[s][t]`パスがエッジを通過することを保証します`(u, v)`最小距離を超えません。 チェックは対称なので、`(u, v)`そして`(v, u)`、すべての最短パスをキャプチャします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
edges = []
INF = 10**18

dist = [[INF] * n for _ in range(n)]
for i in range(n):
    dist[i][i] = 0

for _ in range(m):
    u, v, w = map(int, input().split())
    u -= 1
    v -= 1
    dist[u][v] = w
    dist[v][u] = w
    edges.append((u, v, w))

# Floyd-Warshall
for k in range(n):
    for i in range(n):
        for j in range(n):
            if dist[i][k] + dist[k][j] < dist[i][j]:
                dist[i][j] = dist[i][k] + dist[k][j]

count = [[0] * n for _ in range(n)]

for u, v, w in edges:
    for s in range(n):
        for t in range(s + 1, n):
            if dist[s][u] + w + dist[v][t] == dist[s][t] or dist[s][v] + w + dist[u][t] == dist[s][t]:
                count[s][t] += 1

result = []
for s in range(n):
    for t in range(s + 1, n):
        result.append(str(count[s][t]))

print(" ".join(result))
```の`dist`初期化は使用します`INF`到達不可能な都市を表す。 Floyd-Warshall は、すべてのペアの距離が正しいことを保証します。 エッジをチェックする場合、2 つの条件により道路の無向性の性質が説明されます。 平坦化ループは、`s < t`要件。
