 ## 解決策
 ## 問題の理解

 未知の整数値に関する一連のステートメントが与えられます。$y$。 各ステートメントの制限事項$y$ある整数のしきい値を基準にして$x$、厳密または非厳密のいずれかです。 各ステートメントの後に、そのステートメントが真か偽かについても通知されます。 

タスクは決定することではありません$y$一意ですが、少なくとも 1 つの整数が存在するかどうかを判断するため$y$それは与えられたすべての真実評価と一致します。 そのような値が存在する場合は、有効な整数を 1 つ出力する必要があります。 それ以外の場合は、制約が互いに矛盾していることを報告する必要があります。 

各クエリは、可能な値のセットを狭めたり拡張したりします。$y$。 自然な解釈は、すべてのステートメントは、それが肯定されるか否定されるかに応じて、次の形式の制約に寄与するというものです。$y$これらすべての制約が少なくとも 1 つの整数点で重複する場合、最終的な答えが存在します。 

制約では最大 10,000 個のステートメントが許可され、値は最大 10,000 個に達します。$10^9$したがって、候補値を 1 つずつ試すアプローチは実行不可能です。 可能な値の範囲にわたる線形スキャンには、最大で次のことが必要になります。$4 \cdot 10^9$これは制限時間をはるかに超えています。 

微妙な特殊なケースは、否定されたステートメントによって生じる矛盾から生じます。 たとえば、次のように言われたら、$y > 5$それは偽です、それでは$y \le 5$。 後々、そう言われたら$y \le 3$また、これらは厳密な境界と非厳密な境界と相互作用する可能性があり、off-by-one エラーが発生しやすくなります。 

もう 1 つの注意が必要なケースは、実数値の間隔がエンドポイントで重複しているにもかかわらず、制約によって整数の解が残らない場合に発生します。 たとえば、組み合わせると、$y > 5$そして$y < 6$は有効ですが、組み合わせると$y \ge 6$そして$y < 6$不可能です。 

## アプローチ

 ブルートフォースアプローチでは、すべての整数が試行されます。$y$許容範囲内で$[-2 \cdot 10^9, 2 \cdot 10^9]$すべての制約を満たしているかどうかを確認します。 各小切手にかかる費用$O(n)$したがって、全体の複雑さは次のようになります。$O(n \cdot R)$、 どこ$R$ドメインのサイズです。$4 \cdot 10^9$。 これでは遅すぎます。 

重要な観察は、各ステートメントは制約のみを行うということです。$y$下限または上限のいずれかに影響を与えることによって。 すべての条件は、それが主張されるか否定されるかに応じて、4 つの形式のいずれかの単純な不等式として書き直すことができます。 これは、任意のセットを追跡する必要がなく、可能な限り厳しい下限と上限のみを追跡する必要があることを意味します。 

したがって、一連の候補を維持する代わりに、間隔を維持します。$[L, R]$各ステートメントの処理後に使用可能なすべての値の合計。 各クエリは、新しい制約と交差することによってこの間隔を更新します。 最終的な答えは、次の場合にのみ存在します。$L \le R$すべてを処理した後。 

これにより、問題は、多くの可能性を推論することから、たった 2 つの数値を維持することに軽減されます。

 ## アルゴリズムのチュートリアル

 可能なすべての値を表します$y$現在の有効な間隔を使用して$[L, R]$、最初はすべての整数をカバーします。 

1.初期化$L = -2 \cdot 10^9$そして$R = 2 \cdot 10^9$。 これにより、有効な値を途中で除外せずに、出力制約を確実に遵守することができます。 
2. 各ステートメントについて、演算子、しきい値を解析します。$x$、そしてそのステートメントが真か偽か。 
3. 各ステートメントを直接制約に変換します。$y$。 このステートメントが真の場合、不等式を直接適用します。 それが false の場合、論理否定を適用します。これにより、不等式の方向が反転し、多くの場合、厳密なものから非厳密なものに変わります (逆も同様)。 
4. 各制約は、下限または上限のいずれかを更新します。 

- のような状態$y > x$になる$L = \max(L, x + 1)$。 
- のような状態$y \ge x$になる$L = \max(L, x)$。 
- のような状態$y < x$になる$R = \min(R, x - 1)$。 
- のような状態$y \le x$になる$R = \min(R, x)$。 
5. 各制約を適用した後、間隔は$[L, R]$縮みます。 いつでも$L > R$、すべての制約を満たす整数はないため、すぐに不可能であると結論付けます。 
6. すべてのステートメントを処理した後、任意の整数を出力します。$[L, R]$、 例えば$L$。 

なぜ効果があるのか

 各ステップの間隔$[L, R]$は、これまでに処理されたすべての制約を満たす整数のセットを正確に表します。 新しい制約はそれぞれ、否定処理後に、しきい値を下回る値またはしきい値を上回る値、あるいはその両方を削除します。 すべての制約は線形で独立しているため、すべての制約の交差部分は常に間隔 (または空) になります。 すべての下限の最大値とすべての上限の最小値を維持すると、この交差部分が正確に保存されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 2_000_000_000

def apply(L, R, op, x, truth):
    if op == ">":
        if truth:
            L = max(L, x + 1)
        else:
            R = min(R, x)
    elif op == "<":
        if truth:
            R = min(R, x - 1)
        else:
            L = max(L, x)
    elif op == ">=":
        if truth:
            L = max(L, x)
        else:
            R = min(R, x - 1)
    else:  # "<="
        if truth:
            R = min(R, x)
        else:
            L = max(L, x + 1)
    return L, R

def solve():
    n = int(input())
    L, R = -INF, INF

    for _ in range(n):
        op, x, ans = input().split()
        x = int(x)
        truth = (ans == "Y")

        L, R = apply(L, R, op, x, truth)

    if L > R:
        print("Impossible")
    else:
        print(L)

if __name__ == "__main__":
    solve()
```この実装では、実行可能な間隔が維持されます。 ヘルパー関数は、各クエリを境界の直接調整に変換します。 最もデリケートな部分は、否定を正しく処理することです。偽のステートメントは不等式を逆転させ、厳密さを変更します。たとえば、「not (y > x)」は次のようになります。$y \le x$、 ない$y < x$。 

下限制約には max を使用し、上限制約には min を使用して常に境界を更新し、実行可能領域を誤って拡大しないようにします。 戻るという最後の選択$L$間隔内の整数はすべて有効であるため、安全です。

 ## 特殊なケース

 エッジケースの 1 つは、否定によって厳密性が反転される場合です。 たとえば、ステートメントが「$y > x$」と答え、答えが「いいえ」の場合、正しい制約は次のようになります。$y \le x$、 ない$y < x$。 このアルゴリズムは、記号的に否定するのではなく、各演算子と回答のペアを正確な不等式に明示的にマッピングすることでこれを処理します。 

もう 1 つのエッジ ケースは、境界がある点で正確に一致する場合です。 もし終わったら$L = R$、有効な整数は 1 つだけです。 どちらかの境界を返すことは正しいままであり、実装は戻り値を返します。$L$。 

最後のケースは初期矛盾です。 たとえば、広い間隔から開始すると、シーケンスがすぐに崩れてしまう可能性があります。 小切手$L > R$実行可能なセットが空になるとすぐに論理的に終了し、残りの制約を処理する必要がなくなります。
