 ## 解決策
 ## 問題の理解

 長さのシーケンスが与えられます$n$、各位置は固定の正の整数か未知のいずれかです (次のようにマークされています)。$-1$）。 課題は、この数列を、いくつかの等差数列を次々に連結することによって形成されるものとして解釈することです。 各セグメント内では、連続する要素は一定値だけ異なっている必要があり、セグメントが重複することはできません。 

すべての既知の値が変更されない限り、未知の位置は、選択した任意の正の整数で埋めることができます。 目標は、これらの詰め物を選択し、結果として得られる完全なシーケンスを可能な限り最小限の等差数列セグメントに分割することです。 

したがって、実際の決定はどこで分割するかだけでなく、値をどのように割り当てるかということも重要です。$-1$余分な分割を強制しない方法でエントリを作成します。 

制約$n \le 2 \cdot 10^5$すべてのセグメンテーションを明示的に考慮しようとするものは直ちに除外されます。 すべてのセグメント エンドポイントにわたる 2 次またはそれより悪い DP は遅すぎます。$O(n^2)$遷移は許容限界を数桁超えてしまう可能性があります。 解は線形または線形に近く、位置ごとにローカルな決定のみを行う必要があります。 

微妙な難しさの原因は、$-1$一貫性と相互作用します。 単純なアプローチでは、可能な限りセグメントを貪欲に拡張しようとする可能性がありますが、単一の既知の値によって遡及的に矛盾が強制される可能性があります。 

たとえば、次のようなパターンを考えてみましょう。```
3 5 -1 9
```+2 の差を仮定すると、欠損値は 7 になり、すべてが一致します。 しかし、代わりに次のようなことがあったとしたら:```
3 5 -1 10
```同じ仮定された差は最後の位置で中断されます。 将来の制約をチェックしない貪欲な拡張は失敗する可能性があります。 

もう 1 つの特殊なケースは、長さ 1 のセグメントが暗黙的に現れる場合です。 未知の値に囲まれた単一の既知の値は、互換性のない複数の方法で拡張可能な場合があり、誤った貪欲な選択によりセグメント数が人為的に増加する可能性があります。 

主な困難は、各セグメント内のすべての固定点と一致する差分を同時に選択しながら、シーケンスを分割する必要があることです。 

## アプローチ

 ブルートフォースアプローチでは、配列をセグメントに分割するためにあらゆる方法を試し、セグメントごとに、値を割り当てることができるかどうかを確認しようとします。$-1$すべての固定値が単一の等差数列上にあるようにします。 

セグメントの場合$[l, r]$、実現可能性のチェックには、2 つの既知の値から共通の差異を推定するか、すべての既知の値にわたる一貫性を検証することが含まれます。 事前計算を使用すると、各チェックは次のようになります。$O(1)$ただし、パーティションの数はおおよそ指数関数的です。$2^{n-1}$、これはたとえ$n = 50$。 

より構造化された DP では次のように定義されます。$dp[i]$プレフィックスをカバーするセグメントの最小数として$1..i$をクリックして、以前のすべての分割ポイントを試します。 これにより、$O(n^2)$トランジション。 セグメントごとに一定時間の実現可能性チェックを行ったとしても、これでは遅すぎます。$2 \cdot 10^5$。 

重要な観察は、有効なセグメント内では、一度差が決定されると、次のすべての値が強制的に適用されるということです。$-1$。 これは、一貫性が許す限りセグメントを貪欲に拡張し、一貫性が崩れた場合にのみ再開できることを意味します。 

唯一の本当の複雑さは、セグメントの違いが事前に分からないことです。 ただし、セグメント内の最初の 2 つの固定値が見つかるとすぐに決定されます。 その時点から、後続のすべての固定値は一致するか、強制的にカットされます。 

これにより、現在のセグメントの暗黙の算術構造を維持しながら、左から右へのスキャンの問題が軽減されます。

 | 最適 |$O(n)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 現在のセグメントとその暗黙の等差数列を維持しながら、配列を左から右に処理します。 

1. 位置 1 から新しいセグメントを開始します。その一般的な違いはまだわかりません。 
2. 違いを定義できる既知の値の最初のペアが見つかるまで先に進みます。 これまでセグメントにある固定点が 2 つ未満の場合、差は未定義のままであり、セグメントは自由に適応できます。 
3. 同じセグメント内に 2 つの固定値が表示されたら、必要な差を計算します。$d$。 これにより、セグメントの構造が完全にロックされます。 
4. スキャンを続行します。 新しいポジションごとに:

 - 値が$-1$、常に一貫性があり、何も制約しません。 
- 既知の場合は、それが現在のセグメントによって暗示される期待値と一致するかどうかを確認します。 

一致しない場合、セグメントはこの位置より前で終了する必要があります。 
5. 不一致が発生した場合、セグメント数をインクリメントし、現在の位置から新しいセグメントを再開します。 新しいセグメントは、固定された差異なしで再び始まります。 
6. 配列の最後まで続けます。 

微妙な点は、違いが分からない初期段階をどうするかです。 そのフェーズでは、どのような割り当ても、$-1$一貫性を維持するために選択できるため、既知の値がすでに確立されている進行と矛盾しない限り、強制的に分割することはありません。 

### なぜ効果があるのか

 各セグメントは、その内部のすべての固定値が単一の等差数列に適合する必要があるという制約の下で最大限に拡張されます。 2 つの固定値が一意の違いを定義した瞬間、セグメントは固定的になります。 その時点から、すべての要素は固有の期待値を持ちます。 矛盾が生じた場合、再割り当ては行われません。$-1$固定値の 1 つを壊さずに修正できるため、その時点での分割は避けられません。 

これにより、貪欲な構造が作成されます。すべてのセグメントは論理的に可能な限り拡張され、分割を遅らせても将来の制約が軽減されることはないため、早期に分割してもセグメントの総数は改善されません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    segments = 1

    # current segment state
    d = None
    first = None
    prev = None
    prev_val = None

    for i in range(n):
        if a[i] == -1:
            # unknown value does not constrain anything
            if prev is not None:
                prev += 1  # placeholder progression step, value irrelevant
            continue

        if first is None:
            first = a[i]
            prev = i
            prev_val = a[i]
            continue

        if prev_val is None:
            prev_val = a[i]
            d = (a[i] - first) // (i - prev)
            prev = i
            continue

        # expected value from progression
        dist = i - prev
        expected = prev_val + d * dist

        if expected != a[i]:
            segments += 1
            # reset segment
            first = a[i]
            prev = i
            prev_val = a[i]
            d = None
        else:
            prev = i
            prev_val = a[i]

    print(segments)

if __name__ == "__main__":
    solve()
```実装は、現在のセグメントがその等差数列を決定したかどうかを追跡します。 変数`first`最初の固定値をセグメントに保存します。`prev_val`そして`prev`2 番目の固定値が現れたら、違いを定義するのに役立ちます。 

このロジックは、かつて`d`が確立されると、すべての新しい固定要素を一定時間内に検証できます。 不一致が見つかった場合は、そのインデックスでセグメントを再開します。 

取り扱いには注意が必要です$-1$なぜなら、それらは進行の決定や検証には寄与しないからです。 コードは制約を更新せずにそれらを効果的にスキップします。 

よくある落とし穴は、差分が繰り返し更新できると誤って想定していることです。 一度固定されると、そのセグメントでは一定のままでなければなりません。

def run(inp: str) -> str:

    n = int(input())

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、シーケンスの開始時に既知の値が 1 つだけ含まれており、他のすべてがずっと後になるまで不明である場合です。 このアルゴリズムは差異を修正せずにセグメントを開いたままにするため、誤った構造に早まって固定されることはありません。 最初の 2 番目の固定値が現れると、その 2 点から一貫して差分が設定されます。 

もう一つのケースは、差異が解消された直後に矛盾が現れる場合です。 例えば：```
3 5 7 10
```7までは差+2でセグメントが有効になりますが、10で切れてしまいます。 アルゴリズムは最初の無効な比較でこれを検出し、正確に 10 で新しいセグメントを開始し、最小限のセグメント化を保証します。 

3 番目のケースは、複数の解釈をサポートできる既知の値と未知の値が交互に現れるケースです。 制約を強制するために未知の値が使用されることはないため、アルゴリズムは固定値にのみ反応し、セグメント構造の過剰な制約を防ぎます。
