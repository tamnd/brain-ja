 ## 問題の理解

 無向の単純なグラフを構築するように求められます。$n$ラベル付きの頂点。 すべての頂点には正確な次数が必要です$d$、各ステーションが正確に接続されていることを意味します$d$他の駅。 自己ループと複数のエッジは禁止されているため、これは標準的なシンプルです$d$-通常のグラフ。 

このグラフを構築した後、その接続コンポーネントを概念的に検討します。 各接続コンポーネントは、後で次のいずれかに割り当てられます。$c$同じ部門内のステーションは通信できる必要がありますが、異なる部門内のステーションは通信できません。 通信はまさにグラフの接続であるため、この要件はより強力な構造条件に変換されます。つまり、グラフは正確に次のものを持っている必要があります。$c$コンポーネントは接続されており、すべてのコンポーネントは内部で接続されている必要があります。 

重要な問題は、部門への割り当てを選択していないことです。 代わりに、正確に分割できるグラフを構築する必要があります。$c$接続されたコンポーネントには、後でそれぞれの部門が割り当てられます。 したがって、私たちは効果的に$d$-接続成分の数が正確である通常のグラフ$c$、各コンポーネントには少なくとも 1 つの頂点が含まれている必要があります。 

制約は強力です。$n$まで可能です$10^5$、エッジの総数は次のように制限されます。$n \cdot d \le 2 \cdot 10^5$。 これにより、グラフがまばらであることがすぐにわかります。そのため、どのような解も線形または線形に近いものでなければなりません。$n + nd$。 隣接行列の構築やすべてのペアに対するグローバル検索の繰り返しを伴うものは不可能です。 

いくつかの構造観察がすぐに重要になります。 まず、$d$-通常のグラフは次の場合にのみ存在できます。$n \cdot d$エッジ数の 2 倍に等しいため、偶数になります。 次に、最もデリケートな制約は接続性です。$d = 0$、すべての頂点は分離されているため、次のようにする必要があります。$c = n$。 もし$d = 1$、グラフは完全に一致しているため、すべてのコンポーネントのサイズはちょうど 2 です。つまり、$c$おおよそです$n/2$(パリティによっては問題が残る可能性があります)。 より大きな$d$柔軟性が高まりますが、グラフを正確に分割できることを確認する必要があります。$c$規則性を保ちながら接続されたコンポーネント。 

よくある失敗例は次のような場合に現れます。$c$大きいですが$d$も大きいです。 たとえば、次の場合$d \ge n-1$、グラフは常に接続された完全なグラフ構造に強制されるため、$c$1 である必要があります。それより大きいもの$c$不可能です。 もう一つの微妙なケースは次のような場合です。$d$小さいですが$c$は小さすぎるため、次数制約によって強制される自然なコンポーネント構造を収容できません。 

たとえば、次の場合$n = 4$、$d = 1$、$c = 1$4 つのノード上の 1 つの通常のグラフにはちょうど 2 つの互いに素なエッジがあるため、これは不可能です。そのため、コンポーネントは 1 つではなく 2 つでなければなりません。パリティや強制的なコンポーネント サイズを無視する単純なアプローチでは、誤ってすべてを接続しようとします。 

## アプローチ

 強引なアイデアは、これを制約付きのグラフ構築問題として扱うことです。$n$ノードを追加し、まだ利用可能な次数スロットがあるノード間にエッジの追加を繰り返し試行し、ノードが次数を超えるたびにバックトラックします。$d$またはコンポーネント数が無効になります。 これは本質的に、$d$-検索による接続制約のある通常のグラフ。 

これは、すべての有効な構成を調査するため、概念的には機能しますが、規模的にはすぐに失敗します。 状態空間は、次数が制限されたすべての単純なグラフのセットであり、超指数関数的に増加します。 バックトラッキング中にエッジを貪欲に構築しても、特に次数の割り当てで初期の選択が後の行き詰まりを強いる場合、最悪の場合、指数関数的な動作に劣化する可能性があります。 

重要な観察は、実際には任意の構造が必要ないということです。 必要なのは次のようなグラフだけです$d$-定期的で正確にあります$c$接続されたコンポーネント。 これは、コンポーネントを個別に明示的に構築し、各コンポーネントが内部にあることを確認する必要があることを示唆しています。$d$-通常。 

これにより、問題は古典的な分解に移行します。つまり、1 つのグローバル グラフを構築する代わりに、頂点を分割します。$c$グループを作成し、各グループ内で接続されたグループを構築します。$d$-通常のグラフ。 唯一の困難は、コンポーネント サイズごとにこのようなグラフが存在することを確認することです。 

つながった$d$-通常のグラフオン$k$ノードは標準条件下で存在します。$k \ge d+1$、 そして$k \cdot d$は均等です。 これらの条件が満たされたら、単純な巡回シフト法を使用して構築できます。各ノードを接続します。$i$に$i+1, i+2, \dots, i+d$モジュロ$k$。 これにより、次のような循環グラフが生成されます。$d$-定期的でつながりがある。 

したがって、実際のタスクは次のようになります。$n$頂点に入る$c$グループ、それぞれのサイズが少なくとも$d+1$、各グループ サイズが有効な構築を可能にすることを確認します。 したがって、最小合計要件は次のようになります。$c \cdot (d+1) \le n$。 これが失敗した場合は、すぐに「No」が出力されます。 

サイズが固定されたら、循環構築を使用して各コンポーネントを個別に構築し、すべてのコンポーネントが互いに素になるように頂点ラベルをオフセットします。

 ## アルゴリズムのチュートリアル

 ### 1. 実現可能条件を確認する

 まず次のことを保証します$c \cdot (d+1) \le n$。 これにより、各コンポーネントが次数をサポートするのに十分な頂点を持つことが保証されます。$d$シンプルさとつながりを保ちながら。 

この条件が満たされない場合は、たとえ最小の有効な値であってもすぐに「いいえ」を返します。$d$- 通常の接続コンポーネントには少なくとも次のものが必要です$d+1$ノード。 

### 2. 頂点を分割します。$c$グループ

 頂点を順番に割り当てます。$c$グループ。 各グループは最初は正確に取得します$d+1$残りの頂点は 1 つずつ任意のグループに分配されます。 これにより、柔軟性を確保しながら最小サイズ要件が維持されます。 

このステップにより、コンポーネントのサイズを明示的に制御できるようになります。これは、グラフ構造がグループ サイズに完全に依存するため必要です。 

### 3. を構築する$d$- 各グループ内の通常の接続グラフ

 各サイズのグループごとに$k$、その頂点にローカルでラベルを付けます。$0$に$k-1$。 次に各頂点を接続します$i$に$i+1, i+2, \dots, i+d$モジュロ$k$。 

これにより、循環グラフが作成されます。$d$-register は、各ノードが正確に$d$順方向接続、および対称性により無向エッジが確保されます。 

### 4. ローカル インデックスをグローバル ラベルにマッピングし直す

 各グループには、元の頂点の番号付けにグローバル オフセットがあります。 ローカル インデックスをグローバル頂点 ID に変換し、隣接リストを保存します。 

また、出力形式の要求に応じて隣接リストがソートされていることも確認します。 

### 5. グラフを出力する

 各頂点の隣接リストを出力します。 

### なぜ効果があるのか

 この構造では、2 つの不変条件が同時に適用されます。 まず、各コンポーネント内で、すべての頂点が正確に接続されます。$d$その他は循環パターンの構築によるものです。 第 2 に、異なるグループ間にはエッジが作成されないため、各グループは孤立した連結コンポーネントになります。 循環グラフでは各ノードがサイズ 1 の繰り返しステップを介して他のノードに到達できるため、接続性が維持され、すべてのコンポーネントが接続されます。 明示的に正確に作成するため、$c$グループを正確に取得します$c$接続されたコンポーネント。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, d, c = map(int, input().split())

    if c * (d + 1) > n:
        print("No")
        return

    groups = []
    remaining = n

    for i in range(c):
        size = d + 1
        groups.append(size)
        remaining -= size

    i = 0
    while remaining > 0:
        groups[i] += 1
        remaining -= 1
        i = (i + 1) % c

    adj = [[] for _ in range(n)]
    start = 0

    for size in groups:
        nodes = list(range(start, start + size))
        start += size

        for i in range(size):
            for j in range(1, d + 1):
                u = nodes[i]
                v = nodes[(i + j) % size]
                adj[u].append(v)
                adj[v].append(u)

    for i in range(n):
        adj[i] = sorted(adj[i])
        print(*adj[i])

if __name__ == "__main__":
    solve()
```構築は、コンポーネントの最小サイズ要件を強制する実現可能性チェックから始まります。 これがなければ、$d$-通常の構造はノードが少なすぎます。これは不可能です。 

グループ化ロジックにより正確に保証されます。$c$最小サイズの制約を尊重しながらコンポーネントを作成します。 残りの頂点を均等に分配するとバイアスは回避されますが、循環構築はどの頂点に対しても機能するため、正確さには影響しません。$k \ge d+1$。 

各グループ内の入れ子になったループが中心的な構造です。 各頂点はオフセットによって前方に接続されます$1$に$d$、すべてのエッジが対称的に追加されるため、次数の一貫性が自動的に維持されます。 

最後の並べ替えは、出力の準拠性のためにのみ必要であり、正確さのために必要ではありません。
