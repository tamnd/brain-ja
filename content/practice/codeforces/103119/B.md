 ## 解決策
 ## 問題の理解

 ランダムな文字列構築プロセスが与えられます。 最初の文字列から始めて、一度に 1 文字ずつ繰り返し追加します。 各文字は、サイズが固定されたアルファベットから独立して選択されます。`k`、既知の確率で。 現在の文字列の内部のどこかに、いくつかの禁止パターンのうちの少なくとも 1 つが部分文字列として含まれると、プロセスはすぐに停止します。 

任意の開始文字列に対して`S`では、この停止条件が最初に満たされたときに予想される文字列の合計長を表す値を定義します。 直感的には、禁止された文字列の 1 つが表示されるまでランダムな文字列を増やし続け、どれくらい待つことが予想されるかを尋ねます。 

ここでの工夫は、1 つの開始文字列の代わりに、基本文字列が与えられることです。`R`、そして私たちはすべてのプレフィックスについてこの期待に答えなければなりません`R`。 それぞれについて`i`、私たちは取る`R[1..i]`を開始文字列として使用し、同じランダム プロセスで予想される最終的な長さを計算します。 

この制約は、すべての禁止パターンの合計の長さが最大 ​​10000 であり、アルファベットが小さいことを意味します (`k ≤ 26`）。 これは、予想される停止時間が非常に長くなり、可能な文字列の数が指数関数的に増加する可能性があるため、ランダム プロセスのブルート フォースが不可能であることを直ちに示唆しています。 

構造上の重要な点は、将来の進化は、禁止パターンの一致に関連する文字列の現在のサフィックスのみに依存するということです。 これは古典的な「ランダム拡張下のパターン マッチング」設定であり、オートマトン ベースの状態圧縮を強く示唆しています。 

素朴だが重要なエッジケースは、開始文字列にすでに禁止されたパターンが含まれている場合です。 その場合、プロセスは直ちに停止し、答えは正確に現在の長さになります。 これを忘れ、継続を常に前提とするソリューションは、過大なカウントを引き起こします。 

もう 1 つの微妙なケースは、プロセスが禁止パターンに到達できない状態に到達した場合です。 このような状況では、期待は無限大ですが、問題によってそれが起こり得ないことが保証されます。 

## アプローチ

 直接シミュレーションでは、ランダムな文字を繰り返し追加し、禁止された文字列が部分文字列として表示されるかどうかを確認します。 これは概念的には正しいですが、計算的には役に立ちません。 単一のシミュレーションでも、終了までに膨大な数のステップが必要となる場合があり、サンプルではなく期待値が必要になります。 これにより、ブルートフォースは基本的に実行不可能になります。 

状態を圧縮する正しい方法は、重要なのは文字列全体ではなく、禁止されたパターンに拡張できる現在の文字列の最長のサフィックスであることに注意することです。 これにより、当然のことながら、禁止された文字列のトライが構築され、それが失敗リンクで拡張され、Aho-Corasick オートマトンが形成されます。 このオートマトンの各状態は、関連するサフィックス情報を正確に表します。 

このオートマトンを取得すると、プロセスはオートマトンの状態にわたるマルコフ連鎖になります。 各状態から、次のランダムな文字に従って遷移します。 一部の状態は吸収しており (禁止された文字列と一致したことに対応します)、そのような状態はすべて、残り時間がゼロであると予想されます。 

これにより、問題は有限マルコフ連鎖における予想ヒット時間の計算に軽減されます。 非吸収状態ごとに`u`、次の形式の線形方程式が得られます。`E[u] = 1 + sum over c of p[c] * E[next(u, c)]`、禁止状態に移行する遷移は将来の期待に寄与しません。 

これは、最大 10000 個の変数を含む線形方程式系です。 強引なアプローチでは、密なガウス消去法で直接解決しようとしますが、これでは遅すぎます。 ただし、各方程式には最大でも次のものしか含まれません。`k + 1`条件、および`k ≤ 26`、システムがまばらになります。 

この疎性により、オートマトン グラフ全体にガウス消去法を注意深く適用することができ、疎な行構造を維持しながら状態を消去できます。 各状態は少数の固定数の遷移と相互作用するため、全体の複雑さは管理可能なままです。 

計算後`E[u]`すべてのオートマトン状態について、各プレフィックス クエリに答えることは、プレフィックス文字列を使用してオートマトンを探索し、対応する事前計算された期待値を出力することになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | 指数 | お(1) | 遅すぎる |
 | オートマトン + 線形システム (疎状態でのガウス消去法) | O(N · k²) | O(N・k) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### ## アルゴリズムのチュートリアル

 1. すべての禁止文字列のトライを構築し、それを障害リンクを含む Aho-Corasick オートマトンに拡張します。 各ノードは、現在の文字列の最長の接尾辞を表します。これは、何らかの禁止されたパターンの接頭辞でもあります。 これにより、関連するすべての履歴が 1 つの状態に圧縮されます。 
2. 禁止された文字列の末尾に対応するすべてのオートマトン状態を終端としてマークします。 これらの状態は停止条件を表すため、予想される残りの長さはゼロです。 
3. オートマトンを使用して、すべての状態およびすべての文字の遷移関数を構築します。 これにより、各状態が正確に一致する有向グラフが得られます。`k`発信トランジション。 
4. あらゆる非終端状態について`u`、期待方程式を書きます。`E[u] = 1 + sum p[c] * E[v]`、 どこ`v = next(u, c)`、そして終末状態への移行は将来の期待に寄与しません。 
5. 各方程式を線形形式に並べ替えます。`E[u] - sum p[c] * E[v] = 1`、終端遷移は未知数から省略されます。 
6. すべての状態にわたるガウス消去法を使用して、この疎な線形システムを解きます。 各行には最大でも次への遷移のみが含まれます。`k`状態になるため、更新は引き続き管理可能です。 
7. すべてを計算した後`E[u]`、文字列を処理します`R`段階的に。 文字を読み取っている間、現在のオートマトンの状態を維持します。 各プレフィックスエンドポイントについて、出力`len(prefix) + E[state]`。 

### なぜ効果があるのか

 オートマトンの状態は、現在の文字列のサフィックスで禁止されたパターンが一致したかどうかを判断するために必要なすべての情報を完全にキャプチャします。 プロセスが特定の状態になると、将来の進化は以前の履歴とは無関係であるため、期待はその状態にのみ依存します。 

線形方程式は、期待値を最初のステップと期待される残りのステップに正確に分解することをエンコードします。 すべての遷移はシステム内に留まるか、最終吸収状態に到達するため、システムは明確に定義されており、解決可能です。 ガウス消去法は、すべての方程式の等価性を維持しながら状態間の依存関係を解決し、計算された値がすべての遷移制約を同時に満たすことを保証します。

```python
# Full solution

import sys
input = sys.stdin.readline

MOD = 10**9 + 7

class Node:
    __slots__ = ("next", "fail", "out", "term", "id")
    def __init__(self):
        self.next = {}
        self.fail = 0
        self.out = False
        self.term = False
        self.id = -1

def build_automaton(patterns, k):
    nodes = [Node()]

    def insert(s):
        u = 0
        for ch in s:
            c = ord(ch) - 97
            if c not in nodes[u].next:
                nodes[u].next[c] = len(nodes)
                nodes.append(Node())
            u = nodes[u].next[c]
        nodes[u].term = True

    for p in patterns:
        insert(p)

    from collections import deque
    q = deque()

    for c, v in nodes[0].next.items():
        nodes[v].fail = 0
        q.append(v)

    for i in range(k):
        if i not in nodes[0].next:
            nodes[0].next[i] = 0

    while q:
        u = q.popleft()
        nodes[u].term = nodes[u].term or nodes[nodes[u].fail].term
        for c in range(k):
            if c in nodes[u].next:
                v = nodes[u].next[c]
                nodes[v].fail = nodes[nodes[u].fail].next[c]
                q.append(v)
            else:
                nodes[u].next[c] = nodes[nodes[u].fail].next[c]

    for i, nd in enumerate(nodes):
        nd.id = i

    return nodes

def gauss(mat, n):
    for col in range(n):
        pivot = col
        for r in range(col, n):
            if mat[r][col]:
                pivot = r
                break
        mat[col], mat[pivot] = mat[pivot], mat[col]

        inv = pow(mat[col][col], MOD - 2, MOD)
        for j in range(col, n + 1):
            mat[col][j] = mat[col][j] * inv % MOD

        for r in range(n):
            if r != col and mat[r][col]:
                factor = mat[r][col]
                for j in range(col, n + 1):
                    mat[r][j] = (mat[r][j] - factor * mat[col][j]) % MOD

def solve():
    n, m, k = map(int, input().split())
    p0 = list(map(int, input().split()))
    p = [x * pow(100, MOD - 2, MOD) % MOD for x in p0]

    patterns = [input().strip() for _ in range(n)]
    R = input().strip()

    nodes = build_automaton(patterns, k)
    N = len(nodes)

    idx = [i for i in range(N) if not nodes[i].term]
    id_map = {v: i for i, v in enumerate(idx)}
    S = len(idx)

    mat = [[0] * (S + 1) for _ in range(S)]

    for u in idx:
        i = id_map[u]
        mat[i][i] = 1
        mat[i][S] = 1

        for c in range(k):
            v = nodes[u].next[c]
            if not nodes[v].term:
                mat[i][id_map[v]] = (mat[i][id_map[v]] - p[c]) % MOD

    gauss(mat, S)

    E = [0] * N
    for u in idx:
        E[u] = mat[id_map[u]][S]

    # build transitions again for traversal
    trans = [[0] * k for _ in range(N)]
    for u in range(N):
        for c in range(k):
            trans[u][c] = nodes[u].next[c]

    state = 0
    out = []
    length = 0

    for ch in R:
        c = ord(ch) - 97
        state = trans[state][c]
        length += 1
        out.append(str((length + E[state]) % MOD))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```コードは最初に Aho-Corasick オートマトンを構築し、すべての状態が関連するサフィックス履歴を正確にエンコードするようにします。 次に、予想される残りのステップを表す非終了状態ごとに線形方程式を設定します。 ガウス消去法は、このスパース システムのモジュロを解くために使用されます。`1e9+7`。 最後に、次のプレフィックスを調べます。`R`、現在のオートマトンの状態を維持し、プレフィックス長と予想される残りのステップを出力します。 

重要な実装の詳細は、最終状態を線形システムから完全に分離することです。 これにより、無効な自己依存関係の導入が回避され、吸収状態がゼロに正しく寄与することが保証されます。

| ステップ | プレフィックス | 状態 | ターミナル | E[状態] | 答え |

 | 3 | R[1..3] | u3 | はい | 0 | 3 |

 このトレースは、最終状態に到達すると、期待値の寄与が完全に消失することを示しています。

| ステップ | プレフィックス | 状態 | ターミナル | E[状態] | 答え |
 | --- | --- | --- | --- | --- | --- |

 これは、期待がオートマトンの現在の状態にのみ依存し、その状態にどのように到達したかには依存しないことを示しています。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、最初のプレフィックスがすでに禁止されたパターンと一致する場合です。 その状況では、オートマトンは終了状態で開始されるため、`E[state] = 0`、答えはプレフィックス長と等しくなります。 終端状態は線形システムから除外され、ゼロが直接割り当てられるため、アルゴリズムはこれを正しく処理します。 

もう 1 つのエッジ ケースは、複数の禁止パターンが重なる場合です。 Aho-Corasick 構造は、障害リンクを通じて終端フラグを伝播し、パターンを完成するサフィックスが終端としてマークされることを保証します。 これにより、一致後に有効な継続が誤って存続しないことが保証されます。 

3 番目のケースは、特定の文字分布の下での自己ループ オートマトン状態です。 遷移は循環する可能性がありますが、ガウス消去法は線形制約のシステム全体を解決するため、循環依存関係は発散することなく一貫して解決されます。
