 ## 解決策
 ## 問題の理解

 増加する一連の数値が与えられます。各数値は 0 ～ 255 であるため、すべての値は 8 ビットに収まります。 更新のたびに、シーケンス内の特定の位置から 2 人用ゲームを開始するよう求められる場合があります。 

開始インデックス k から、トークンは位置 k に位置します。 プレイヤーは最初のプレイヤーから順番に交互に動きます。 現在の位置 i から、移動はある位置 j > i へ前方にジャンプすることで構成されますが、これは、それらの位置の値が、バイナリ表現の違いが最大 1 ビットであるという意味で非常に類似している場合に限られます。 つまり、Ai と Aj の間のハミング距離は最大 1 です。 

動けないプレイヤーは即負けとなります。 クエリごとに、最適なプレイで最初のプレーヤーが勝つかどうかを判断する必要があります。 

シーケンスは静的ではありません。 新しい要素は時間の経過とともに追加され、クエリはこれらの追加にインターリーブされるため、ゲーム グラフは左から右に段階的に表示されます。 

制約は大きく、最大 200,000 操作です。 各操作は定数時間または対数時間に近い時間で処理される必要があります。 到達可能性やゲーム結果をクエリごとに最初から再計算するソリューションは、クエリごとのリニア スキャンでさえ、最悪の場合、すでに 4e10 オペレーションに達してしまうため、すぐに遅すぎます。 

微妙な点は、各値が 8 ビットのみであることです。 これにより、互換性関係が非常に小さくなり、構造化されます。これが、問題が扱いやすくなる主な理由です。 

いくつかの特殊なケースでルールが明確になります。 

すべての値が個別であり、ビット空間内で大きく離れている場合、手はまったく存在せず、すべての開始位置が負けになります。 たとえば、シーケンス [0, 255] で位置 1 から開始する場合、有効な j > 1 は存在しないため、最初のプレーヤーが負けます。 

値が繰り返される場合、同じ数値はゼロビット異なり、常に互換性があるため、同じ値を介して移動が連鎖する可能性があります。 

主な問題は、グラフが事前に知られておらず、オンラインで構築されるため、グローバル DP を 1 回のパスで事前計算できないことです。 

## アプローチ

 シーケンスが修正された場合、問題は有向非巡回グラフ上の標準的なゲームに縮小されます。各位置はノードであり、エッジは互換性のある値に進み、後方動的計画法を使用して各ノードが勝っているか負けているかを計算します。 

右端の位置から後方に向かって、j が負けているような到達可能な j > i が存在する場合、位置 i は勝ちです。 すべてのエッジが前方を向いているため、これは機能します。 

ブルート フォース バージョンでは、すべての位置 i について、すべての j > i をスキャンし、互換性と DP ステータスをチェックします。 これにより、O(n^2) 個の遷移が発生し、200,000 個の要素にとっては遅すぎます。 

シーケンスが動的であるため、難易度は高くなります。 各追加の後、事実上、新しいノードが DAG に挿入され、以前のノードの DP 状態が変更される可能性があります。 挿入のたびに直接再計算することは不可能です。 

重要な構造的観察は、DP 状態が一方向にのみ移動するということです。 新しいノードを追加すると、既存のノードは負けから勝ちにのみ切り替わり、その逆はできません。 これは、新しいノードを追加するとオプションが追加されるだけであるために発生します。 既存の移動が削除されることはありません。 

この単調性により、段階的なプロセスが可能になります。 現在負けている一連のポジションを維持します。 新しいポジションが追加されると、出ていくエッジがないため、負けとして開始されます。 その後、以前のノードを「アクティブ化」することができます。この新しい位置にジャンプできる以前のノードは、すぐに勝ちになります。 

残りのタスクは、互換性ルールに基づいて新しく追加されたノードに到達できる以前の位置をすべて効率的に見つけることです。

値は 0 ～ 255 のみであるため、各値にはそれ自体を含めて最大 9 個の互換性のある値があります (8 ビットのそれぞれを反転して ID を加えたもの)。 したがって、各値について、その値を持つ現在負けているすべてのポジションを格納する構造を維持できます。 新しい損失ノードが追加された場合、これらの 9 つの値バケットをチェックし、そのバケット内の以前のすべてのインデックスをアクティブにするだけで済みます。 

各インデックスは最大 1 回アクティブ化できるため、プロセス全体の合計作業量は、順序付けられた構造からの対数因数まで線形になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 各更新後に DP を再計算する | O(n²m) | O(n) | 遅すぎる |
 | 固定グラフ DP (オフライン) | O(n · 256 · 8) | O(n) | オンラインでは適用されません |
 | 値バケットによる増分伝播 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 シーケンスが増加するにつれて次の状態を維持します。DP 配列。dp[i] は位置 i が勝っているかどうかを示し、各値 v について、Ai = v で dp[i] が現在負けているようなバランスの取れたインデックス i のセットを維持します。 

また、値 x ごとに、最大 1 ビットを反転することで x から到達可能な値のリストを事前計算します。 この隣接リストのサイズは最大 9 です。 

操作を順番に処理していきます。 

1. 位置 i に新しい値 x を追加するとき、最後の要素からの移動がないため、最初は dp[i] = false に設定します。 値 x に対応するバケットに i を挿入します。 
2. この新しい位置 i について、x の隣接リスト内のすべての値 y を考慮します。 このような y ごとに、まだ負けている値 y を持つインデックスのセットを調べます。 
3. このような各セットから、すべてのインデックス j < i を抽出します。 このようなすべての j には i に対する新しい勝ち手があり、dp[j] が true になります。 インデックスが勝利すると、そのインデックスはその値バケットから永久に削除されます。 
4. j からさらに伝播する必要はありません。 j の状態が変化しても、それは負けから勝ちに変わるだけであり、それはそれを負けのセットから削除することしかできず、以前に発見された勝ちの遷移を無効にすることはできません。 
5. 位置 k から始まるクエリを受信すると、dp[k] が true の場合は「Grammy」を出力し、そうでない場合は「Alice」を出力します。 

それが機能する理由は、ダイナミックなフロンティアとして負けているポジションを追跡することにあります。 ポジションがサフィックス内の少なくとも 1 つの負けノードに到達できる場合、そのポジションは勝利しています。 私たちが維持するセットは常に負けているノードの現在のサフィックスを表しており、新しい負けているノードが現れるたびに、それがすぐに使用されて、到達可能なすべての以前のノードを勝ちのあるノードに変換します。 どのノードも損失に戻ることはないため、すべてのノードが最大 1 回処理されるため、伝播は正確で有限なままになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
A = list(map(int, input().split()))

# precompute neighbors for 8-bit values
adj = [[] for _ in range(256)]
for x in range(256):
    seen = set()
    seen.add(x)
    for b in range(8):
        y = x ^ (1 << b)
        seen.add(y)
    adj[x] = list(seen)

from collections import defaultdict
import bisect

# we maintain sorted lists of losing positions per value
# using list + bisect for simplicity
pos = [[] for _ in range(256)]

dp = [False] * (n + m + 5)

for i, v in enumerate(A, start=1):
    pos[v].append(i)

for v in range(256):
    pos[v].sort()

for v in range(256):
    for i in pos[v]:
        dp[i] = False

def activate(x, i):
    # remove all j < i from pos[x]
    arr = pos[x]
    idx = bisect.bisect_left(arr, i)
    for j in arr[:idx]:
        if not dp[j]:
            dp[j] = True
    pos[x] = arr[idx:]

# initially everything is losing, dp already False

current_n = n

for _ in range(m):
    tmp = input().split()
    op = int(tmp[0])

    if op == 1:
        k = int(tmp[1])
        current_n += 1
        A.append(k)
        i = current_n

        v = k
        dp[i] = False
        pos[v].append(i)

        for u in adj[v]:
            activate(u, i)

    else:
        k = int(tmp[1])
        if dp[k]:
            print("Grammy")
        else:
            print("Alice")
```コードは DP 状態を増分的に維持します。 新しいインデックスが追加されるたびに、そのインデックスは損失位置として値バケットに挿入されます。 次に、すべての互換性のある値バケットで以前の負けポジションがスキャンされ、勝ちポジションに反転されて削除されます。 

重要な点は、削除は永久的であるということです。 ポジションが勝ちとマークされると、そのポジションはいかなる構造にも再び入ることはなく、処理されるインデックスの合計数が実行全体にわたって線形であることが保証されます。 

クエリのステップは直接的です。単に dp[k] を読み取るだけです。 

## 実用的な例

 値が [1, 2, 3] であり、バイナリの近さによってエッジが決定される小さなシーケンスを考えてみましょう。 

値を追加して dp を追跡します。 

### トレース 1

 シーケンスは [1, 2, 3] として構築されます。 完全なビルド後に位置 2 をクエリします。 

| ステップ | 操作 | 新しい価値 | アクティブ化されたノード | dp 状態 (関連) |
 | --- | --- | --- | --- | --- |
 | 1 | 追加 | 1 | なし | dp[1]=0 |
 | 2 | 追加 | 2 | 互換性がある場合は 1 | dp[2]=0、dp[1]=1 |
 | 3 | 追加 | 3 | 互換性によって異なります | dp[3]=0 または 1 に応じて |

 これは、後で負けたノードが前のノードを反転することはできるが、その逆は決してないことを示しています。 

トレースでは、新しい到達可能な損失ノードが出現したときにのみ dp 値が false から true に遷移することが確認されます。 

### トレース 2

 シーケンス [0, 1, 0]。すべての値の互換性が高くなります。 

| ステップ | 操作 | 値 | 以前にバケットを紛失しました | 変更点 |
 | --- | --- | --- | --- | --- |
 | 1 | 追加 | 0 | {1} | dp[1]=0 |
 | 2 | 追加 | 1 | {1} | dp[2]=0、1 をアクティブにする |
 | 3 | 追加 | 0 | {3} | 1 と 2 をアクティブにする |

 このケースは、新しい負けノードが複数の以前のポジションを即座に解決できるカスケード アクティベーションを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | 各インデックスはバランスのとれた構造に対して 1 回挿入され、1 回削除されます。各削除には対数的な時間がかかります。 
| スペース | O(n) | すべてのポジションにわたって DP 状態と値バケットを保存します。 

この制約では最大 200,000 の操作が可能で、各操作は償却対数仕事のみに寄与するため、ソリューションは制限内に問題なく適合します。 

## テストケース```python
import sys, io

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n, m = map(int, input().split())
    A = list(map(int, input().split()))

    adj = [[] for _ in range(256)]
    for x in range(256):
        s = {x}
        for b in range(8):
            s.add(x ^ (1 << b))
        adj[x] = list(s)

    import bisect
    pos = [[] for _ in range(256)]
    dp = [False] * (n + m + 5)

    for i, v in enumerate(A, 1):
        pos[v].append(i)

    for v in range(256):
        pos[v].sort()

    def activate(x, i):
        arr = pos[x]
        idx = bisect.bisect_left(arr, i)
        for j in arr[:idx]:
            dp[j] = True
        pos[x] = arr[idx:]

    cur = n

    out = []
    for _ in range(m):
        t = list(map(int, input().split()))
        if t[0] == 1:
            cur += 1
            v = t[1]
            A.append(v)
            dp[cur] = False
            pos[v].append(cur)
            for u in adj[v]:
                activate(u, cur)
        else:
            k = t[1]
            out.append("Grammy" if dp[k] else "Alice")

    return "\n".join(out)

 ## 特殊なケース

 最初のエッジケースは、すべての値が同一である場合です。 同一の値はゼロビットだけ異なるため、すべての新しい位置はすぐに前のすべての位置に接続されます。 アルゴリズムは、すべてのインデックスを同じ値バケットに配置することでこれを処理します。 新しいノードが追加されると、1 回のスイープで以前のすべてのインデックスがアクティブ化され、プレフィックス全体が正しい順序で段階的に勝利するように反転されます。 

もう 1 つのエッジ ケースは、0 と 255 など、高度に接続されたパターンの間で値が交互に現れる場合です。それぞれの値が極端であっても、それらの互換性は制限されており、構造により大きなカスケードが防止されます。 バケットベースのアクティブ化により、有効な近隣ノードのみが考慮されることが保証されます。 

最後のエッジ ケースは、多くの追加の前にクエリが出現する場合に発生します。 dp は既存のすべてのポジションに対して常に維持され、遅延的に再計算されることはないため、将来の更新は以前のポジションを強化するだけであるため、初期のインデックスをクエリすると、将来の更新に関係なく常に正しい現在の状態が返されます。
