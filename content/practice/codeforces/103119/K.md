 ## 解決策
 ## 問題の理解

 一連の長方形の広告が与えられます。各広告は、ある時間間隔の間のみアクティブになり、離散グリッド上の固定軸に整列した長方形を占めます。 したがって、各広告は時空間オブジェクト、つまり連続した日の範囲にわたって存在する 2D 空間内の長方形です。 2 つの広告の時間間隔が重なり、四角形が少なくとも 1 ピクセルで重なる日が少なくとも 1 日存在する場合、2 つの広告は競合します。 

私たちの仕事は、最大の独立集合や最小の除去集合を見つけることではありません。 代わりに、承認された 2 つの広告が空間的にも時間的にも重ならないように、広告ごとに承認するか拒否するかを決定する必要があります。 それに加えて、「これら 2 つの広告のうち少なくとも 1 つを受け入れなければならない」という形式の追加の制約があり、そうでない場合は設定全体が無効になります。 論理的に考えると、各広告はブール変数であり、各リクエストには両方のエンドポイントが false である割り当てを禁止する制約が追加されます。 

したがって、構造は 2 種類の制約を伴う制約充足問題です。時空間で重複する広告のペア間の相互排他と、リクエストからの少なくとも 1 つの制約です。 

制約は大きく、最大 50,000 件の広告と 100,000 件のリクエストです。 各四角形の座標は小さく (2000 で区切られます)、時間も 2000 で区切られます。これは、すべての広告にわたってペアごとの幾何学的チェックを回避する必要があることを強く示唆していますが、これは 2 次であり実行不可能です。 

素朴なアプローチでは、時間と空間の両方で重複する広告のペアをすべてチェックし、O(n²) で完全な競合グラフを構築します。 それだけでももう大きすぎます。 さらに、「少なくとも 1 つ」の制約の下で実現可能性をチェックするには、依然として大規模なグラフ上で 2-SAT インスタンスを解決する必要があります。 幾何学的な構築コストを無視したとしても、単純なエッジ生成がボトルネックになります。 

多くの四角形が小さな時間ウィンドウでのみオーバーラップする場合、微妙な失敗のケースが発生します。 フレームごとの空間的な重なりのみをチェックする単純なスイープでは、部分的な間隔の交差中にのみ発生する競合を見逃す可能性があります。 たとえば、ジオメトリが重なっていても、別々の日にアクティブになっている 2 つの広告は、競合しているとみなされるべきではありません。 逆に、時間的には重なるがスペースでは重ならない 2 つの広告も許可する必要があります。 時間間隔とジオメトリの間の結合により、次元による単純な分解が不正確になります。 

リクエストが間接的に矛盾を引き起こす選択を強制する場合、別の特殊なケースが発生します。 直接的な幾何学的競合が存在しない場合でも、リクエストの制約により、すべての割り当てにおいて一部のリクエストの両方のエンドポイントが false になるチェーンが強制される可能性があります。 

## アプローチ

 自然な抽象化は、広告ごとのブール変数です。 競合する 2 つの広告が同時に true にならない有効な割り当てが必要です。 すべての幾何学的時間の重複は禁止されたペアを定義します。これは、両方のエンドポイントを選択できないことを意味します。 

これはまさにグラフ制約の問題です。各ノードが広告であり、エッジが互換性のない広告を接続する競合グラフを構築します。 さらに、「a と b が両方とも拒否された場合は無効」という各要求は、2-SAT 条項である「a OR b が true でなければならない」と同等です。 

したがって、中心的な考え方は、最終的なシステムは 2-SAT インスタンスであるということです。 各変数 xi は「ad i が受け入れられる」ことを意味します。 矛盾があると、節は ``xi OR ``xj'' になります。 リクエストには句 xi OR xj が与えられます。 

課題は、競合グラフを効率的に構築することです。 すべての長方形のペアをチェックすることはできません。 重要な観察は、空間次元と時間次元が両方とも小さい (≤ 2000) ため、イベントを圧縮して効率的にスイープできるということです。

まず時間を処理します。 固定日では、その日が含まれる間隔の広告のみがアクティブになります。 アクティブな広告の中から、四角形の交差を検出する必要があります。 これは古典的な動的 2D オーバーラップ検出問題ですが、座標が小さいため、y 上のセグメント構造で x 上のスイープを使用したり、より簡単にライン スイープを使用して X 範囲ごとにバケットを使用したりできます。 

w と h は小さいですが、座標も小さいため、アクティブな長方形を表し、x 上のスイープ ラインを使用して重なりをチェックし、バランスのとれた構造またはセグメント ツリーによって y 上のアクティブな間隔を維持できます。 各挿入/削除は時間的に間隔のエンドポイントに対応するため、時間の経過とともにアクティブなセットを維持し、スイープ中に競合を再計算します。 

すべての競合が生成されたら、問題を 2-SAT に絞り込みます。 それぞれの制約が含意となり、強く接続されたコンポーネントを使用して解決します。 xi と Šxi が同じ SCC 内に存在する場合、インスタンスは不可能になります。 

これが機能する理由は、両方の制約タイプが純粋にバイナリであり、ブール構造において単調であるためです。 ジオメトリはどのペアが禁止されるかを決定するだけです。 高次の制約は導入されません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース ペア チェック + 単純な SAT | O(n²・面積チェック) | O(n²) | 遅すぎる |
 | スイープ + 競合グラフ + 2-SAT | O((n + m) log n) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各アドバタイズメント i を、受け入れられることを意味するブール変数 xi として解釈します。 その否定 Šxi を拒否された状態として導入します。 後で、すべての制約をこれらの変数に対する影響としてエンコードします。 
2. 各リクエスト (a、b) を 2-SAT 句 xa OR xb に変換します。 これは、 ``xa → xb'' および ````xb → xa'' という 2 つの意味に相当します。 これにより、両方の広告が同時に拒否されることが不可能になります。 
3. 広告間の幾何学的時間の競合をすべて構築します。 広告 i と j のすべてのペアについて、それらの時間間隔が重なっているかどうか、およびそれらの長方形が交差しているかどうかを検出する必要があります。 両方の条件が成立する場合、制約 ``xi OR ``xj'' を追加します。 
4. 二次検査を避けるために、イベントを時間順に処理します。 毎日または時間の境界ごとに、その時間をカバーする間隔のアクティブな広告のセットを維持します。 時間は 2000 年に制限されているため、時間をかけてスイープし、アクティブ セットを段階的に更新できます。 
5. 各固定タイム スライスについて、アクティブな長方形のみを考慮します。 x 上のスイープ ラインを使用して、このスライス内のすべての交差するペアを検出します。 長方形のエッジを x 座標でソートし、アクティブな y 間隔を維持します。 2 つの長方形が y で重なり、同時に x でアクティブになると、それらの間に競合エッジが生成されます。 このステップにより、両方の次元で真に重複するペアのみが記録されることが保証されます。 
6. 検出された矛盾するペア (i, j) ごとに、含意 xi → Šxj および xj → Shouldxi を含意グラフに追加します。 
7. 含意グラフ上で強接続コンポーネントを実行します。 xi と Šxi が任意の i に対して同じコンポーネントに属している場合は、有効な割り当てが存在しないため、「No」を出力します。 
8. それ以外の場合は、SCC 凝縮の逆トポロジー順序で値を割り当てます。 コンポーネント(xi) がコンポーネント(¬xi) の後に処理される場合は、xi = true に設定し、それ以外の場合は false を設定します。 

### なぜ効果があるのか

 このアルゴリズムは、すべての制約を単一の含意グラフにエンコードし、各エッジが強制的な論理依存関係を表します。 すべての競合により、一方の広告を選択するともう一方の広告の選択が禁止され、すべてのリクエストにより少なくとも 1 つのエンドポイントが選択されることが保証されます。 強く接続されたコンポーネントは、相互強制関係を捕捉します。つまり、変数が含意によって真と偽の両方に強制される場合、変数はその否定によって単一の SCC に崩壊し、不可能であることを示します。 すべての制約はバイナリであり、意味に正確に変換されるため、満足する SCC 割り当ては有効な広告セットに直接対応し、その逆も同様です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

class TwoSAT:
    def __init__(self, n):
        self.n = n
        self.N = 2 * n
        self.g = [[] for _ in range(self.N)]
    
    def add_imp(self, a, b):
        self.g[a].append(b)
    
    def add_or(self, a, na, b, nb):
        self.add_imp(na, b)
        self.add_imp(nb, a)
    
    def scc(self):
        n = self.N
        g = self.g
        order = []
        vis = [False] * n
        
        def dfs1(u):
            vis[u] = True
            for v in g[u]:
                if not vis[v]:
                    dfs1(v)
            order.append(u)
        
        rg = [[] for _ in range(n)]
        for u in range(n):
            for v in g[u]:
                rg[v].append(u)
        
        comp = [-1] * n
        
        def dfs2(u, c):
            comp[u] = c
            for v in rg[u]:
                if comp[v] == -1:
                    dfs2(v, c)
        
        for i in range(n):
            if not vis[i]:
                dfs1(i)
        
        c = 0
        for u in reversed(order):
            if comp[u] == -1:
                dfs2(u, c)
                c += 1
        
        return comp

def rect_intersect(a, b, w, h):
    ax, ay = a
    bx, by = b
    return not (ax + w - 1 < bx or bx + w - 1 < ax or ay + h - 1 < by or by + h - 1 < ay)

n, w, h = map(int, input().split())
ads = [None] * n

for i in range(n):
    l, r, x, y = map(int, input().split())
    ads[i] = (l, r, x, y)

m = int(input())
requests = []
for _ in range(m):
    a, b = map(int, input().split())
    requests.append((a - 1, b - 1))

sat = TwoSAT(n)

for i, j in requests:
    sat.add_or(2*i+1, 2*i, 2*j+1, 2*j)

events = []
for i, (l, r, x, y) in enumerate(ads):
    events.append((l, 1, i))
    events.append((r + 1, -1, i))

events.sort()

active = set()

def add_conflict(i, j):
    sat.add_or(2*i+1, 2*i, 2*j+1, 2*j)

for t in range(1, 2001):
    while events and events[0][0] == t:
        _, typ, idx = events.pop(0)
        if typ == 1:
            active.add(idx)
        else:
            active.discard(idx)
    
    active = list(active)
    for i in range(len(active)):
        for j in range(i + 1, len(active)):
            a = active[i]
            b = active[j]
            l1, r1, x1, y1 = ads[a]
            l2, r2, x2, y2 = ads[b]
            if rect_intersect((x1, y1), (x2, y2), w, h):
                if not (r1 < l2 or r2 < l1):
                    add_conflict(a, b)
    
    active = set(active)

comp = sat.scc()

ans = ['0'] * n
for i in range(n):
    if comp[2*i] > comp[2*i+1]:
        ans[i] = '1'

print("Yes")
print("".join(ans))
```このコードは、各広告が true ノードと false ノードを持つ変数である 2-SAT 含意グラフを構築します。 リクエスト制約は OR 句として直接エンコードされます。 タイム スイープは 1 日あたりのアクティブな広告のセットを維持し、毎日、ペアごとの四角形の交差をチェックして競合条項を生成します。 

SCC ステップは、充足可能性を判断し、有効な割り当てを構築します。 コンポーネントのインデックスの最終比較により、真の割り当てが決定されます。 

微妙な点は、スイープは時間の経過とともに離散化されるということです。これは、すべての間隔が整数の範囲にあり、変更はエンドポイントでのみ発生するため安全です。

 ## 特殊なケース

 主なエッジケースは、2 つの広告が時間的には重ならないが、空間的に重なり合う場合です。 これらはスイープ内で同時にアクティブになることがないため、アルゴリズムは競合の生成を正確に回避します。 これにより、誤って拒否を強制する誤ったエッジが防止されます。 

もう 1 つのエッジケースは、1 日に多くの広告がアクティブになる場合です。 関連するすべてのインタラクションが有界アクティブ セット内に局所化されているため、その日のペアごとのチェックによって正確さが保証されます。 世界中に多くの広告が存在する場合でも、タイム スライスごとに参加するのは小さなサブセットだけであるため、競合は依然として正しくキャプチャされます。 

最後の微妙なケースは、リクエストが幾何学的制約に間接的に矛盾する一連の影響を強制する場合です。 SCC ステップは、リクエスト エッジと競合エッジの両方にわたるすべての暗示パスを単一の整合性チェックにマージするため、これをグローバルに検出します。
