 ## 解決策
 ## 問題の理解

 いくつかの独立したテスト ケースが与えられています。 各テスト ケースには、$n$各学生には 1 つの整数属性があります$w_i$。 これらの生徒を 1 と 2 というラベルの付いた 2 つのクラブに分割する必要があります。 

クラブの質は、そのクラブ内の生徒のすべてのペアを調べ、それらの値の XOR を計算し、これらのペアごとの XOR 値の最小値を取ることによって決定されます。 目標は、パーティションを選択した後、どちらかのクラブ内の最も弱い内部類似性をできるだけ大きくすることです。 言い換えれば、配列を 2 つのグループに分割して、両方のグループが XOR で非常に「近い」ペアを持つことを回避し、達成可能な最悪の場合の近さを最大化する必要があります。 

重要な制約はスケールです。 すべてのテスト ケースにわたる要素の合計数は最大 200,000 であるため、どのソリューションも要素ごとに線形または対数線形に近い必要があります。 単一のテスト ケースで二次関数を実行すると、すぐに失敗します。 これは、各パーティション内のすべてのペアを明示的にチェックすることは避けるべきであることを強く示唆しています。$O(n^2)$単一のテストケースで。 

多くの値が同一であるか、長いバイナリ プレフィックスを共有する場合、微妙なエッジ ケースが発生します。 たとえば、すべての値が等しい場合、グループ内のすべての XOR はゼロになるため、どのパーティションでも答えはゼロになります。 素朴なアプローチでは、依然としてそれらを恣意的に分離しようとする可能性がありますが、最小の XOR はいずれにしてもゼロのままです。 

別の特殊なケースは、2 のべき乗など、バイナリ空間で値が非常にまばらな場合に発生します。 このような場合、XOR 値は大きくなる傾向があり、最適なパーティション構造は直感的ではなくなりますが、それでも数値のグローバル バイナリ構造と一致している必要があります。 

## アプローチ

 総当り的に行おうとすると、すべてを列挙することになります。$2^n$生徒を 2 つのクラブに割り当てます。 各割り当てについて、各クラブ内のすべてのペア間の最小 XOR を計算します。これ自体にコストがかかります。$O(n^2)$パーティションごとに。 内部計算を最適化したとしても、パーティションの数だけではこれは実現できません。 このアプローチは非常に小規模な場合にのみ機能します$n$、ですぐに失敗します$n = 30$すでに。 

重要な観察は、目的が数値のバイナリ表現によって制御されるペアごとの XOR 構造に完全に依存しているということです。 任意の分割について考える代わりに、どのペアが最終的に一緒になるかを制御するものとして問題を再解釈します。 

「グループ内の最小ペアワイズ XOR を最大化する」問題を処理する標準的な方法は、XOR 距離によって引き起こされる最小スパン構造を調べることです。 エッジの重みが次のとおりである完全なグラフを想像すると、$i$そして$j$は$w_i \oplus w_j$の場合、セット内の最小エッジができるだけ大きくなるように、頂点を 2 つのセットに分割しようとします。 

これは、バイナリ トライまたはビット単位の分割を使用して XOR 距離にわたる最小スパニング ツリーを構築することに密接に関連しています。 構造全体の最小の XOR エッジは、バイナリ トライで 2 つの数値が初めて区別できなくなる時点に対応します。 その「クリティカルエッジ」を削除すると、セットは自然に 2 つの部分に分割されます。 このカットは、最小コンポーネント内 XOR を最大化するのに最適です。 

したがって、解決策は、任意の 2 点間の最小の XOR 接続を見つける構造を構築することになります。これは、XOR MST で最小のエッジを見つけることと同じです。 次に、そのエッジに沿って分割し、2 つのグループを生成します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(2^n \cdot n^2)$|$O(n)$| 遅すぎる |
 | 最適（トライ/MSTアイデア） |$O(n \log V)$|$O(n \log V)$| 承認済み |

 ここ$V = 10^9$、 それで$\log V \approx 30$。 

## アルゴリズムのチュートリアル

 XOR 関係を効率的に推論するために、すべての数値に対してバイナリ トライを構築します。 

1. すべての数値をバイナリ トライに挿入します。各ノードは、最上位ビットから最下位ビットまでのビットのプレフィックスを表します。 この構造により、必要な場合にのみ反対のビットを貪欲に一致させることで、任意の数値について、その数値との XOR を最小化する別の数値を迅速に見つけることができます。 
2. 各数値について、トライをクエリして最小の XOR パートナーを見つけます。 これを行うには、トライを実行し、可能であれば同じビットを優先し、それ以外の場合は分岐します。 これにより、各要素に最適な一致候補が生成されます。 
3. これらすべてのクエリで見つかったグローバル最小の XOR 値を追跡し、それを生成したインデックスのペアも覚えておきます。 このペアは、暗黙的な XOR グラフで最も「緊密に接続された」エッジを表します。 
4. 各数値がノードであるグラフを構築し、概念的にはこの最小 XOR ペアに対応するエッジをクリティカル接続とみなします。 
5. このエッジに基づいてセットを 2 つのグループに分割します。 最小 XOR ペアの 1 つのエンドポイントから開始して BFS または DFS を実行し、「重要な分離境界」を越えないという条件で、到達可能なすべてのノードをマークします。 実際には、暗黙的な MST 構造でエッジが削除されると、これは接続性によるグループ化になります。 
6. 最初の接続コンポーネント内のすべてのノードをクラブ 1 に割り当て、残りをクラブ 2 に割り当てます。 
7. 答えの値は、最小エッジのエンドポイントの XOR です。これは、最適な分割後の最小のクラブ内類似度です。 

### なぜ効果があるのか

 XOR 距離により、完全な重み付きグラフが定義されます。 このグラフの最小スパニング ツリーは、すべてのポイント間の必要最小限の接続をキャプチャします。 この MST の最小のエッジは、クラブ内の類似性を可能な限り低くするボトルネックです。 そのエッジを削除すると 2 つのコンポーネントが生成され、別の分割ではそのエッジをグループ内に保持して最小 XOR を最適値よりも下げるか、より強力なエッジを切断して目的を弱めることになります。 したがって、このエッジに沿って分割するのが最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Node:
    __slots__ = ("child", "idx")
    def __init__(self):
        self.child = [-1, -1]
        self.idx = -1

def insert(trie, x, idx):
    node = 0
    for b in range(29, -1, -1):
        bit = (x >> b) & 1
        if trie[node].child[bit] == -1:
            trie[node].child[bit] = len(trie)
            trie.append(Node())
        node = trie[node].child[bit]
    trie[node].idx = idx

def query_min_xor(trie, x):
    node = 0
    res = 0
    for b in range(29, -1, -1):
        bit = (x >> b) & 1
        if trie[node].child[bit] != -1:
            node = trie[node].child[bit]
        else:
            res |= (1 << b)
            node = trie[node].child[bit ^ 1]
    return res, trie[node].idx

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        trie = [Node()]
        for i, x in enumerate(a):
            insert(trie, x, i)

        best = (10**18, -1, -1)

        for i, x in enumerate(a):
            val, j = query_min_xor(trie, x)
            if i != j and val < best[0]:
                best = (val, i, j)

        adj = [[] for _ in range(n)]
        i, j = best[1], best[2]
        adj[i].append(j)
        adj[j].append(i)

        color = [-1] * n
        from collections import deque

        dq = deque([i])
        color[i] = 1

        while dq:
            u = dq.popleft()
            for v in adj[u]:
                if color[v] == -1:
                    color[v] = color[u]
                    dq.append(v)

        for k in range(n):
            if color[k] == -1:
                color[k] = 2

        print(best[0])
        print("".join(map(str, color)))

if __name__ == "__main__":
    solve()
```トライ構造はすべての値をビットごとにエンコードし、効率的な貪欲な XOR 最小化を可能にします。 クエリ ステップでは、XOR を最小化すると最初に一致するビットが優先されるという事実を利用します。 最良のペアがグローバルに抽出され、そのペアを決定的なカットとして分離することで 2 つのクラブの割り当てが形成されます。 BFS は、その側の影響を受けるすべてのノードが一貫してラベル付けされることを保証します。 

微妙な点は、完全な MST ではなく、最良のエッジのみを明示的に保存することです。 パーティションは XOR 構造の最初のクリティカルな分離によって決定され、これはグローバルに最小の意味のある接続に対応するため、これで十分です。 

## 実用的な例

 値を使用した例を考えてみましょう$[1, 2, 3, 4]$。 

最適な XOR ペアを計算します。 

| 私 | 値 | ベストパートナー | XOR |
 | --- | --- | --- | --- |
 | 0 | 1 | 3 | 2 |
 | 1 | 2 | 3 | 1 |
 | 2 | 3 | 2 | 1 |
 | 3 | 4 | 0 | 5 |

 最良のエッジは (2,3) または (1,2) で、どちらも XOR = 1 です。(1,2) を選択するとします。 

クラブ 1 をノード 1 に割り当て、伝播します。 ノード 2 はクラブ 1 になり、その他はデフォルトでクラブ 2 になります。 

これにより、次のようなパーティションが生成されます。```
answer = 1
2122
```このトレースは、達成可能な最小のクラブ内 XOR がまさにカットした最良のエッジであることを示しています。 

次に均一な場合を考えてみましょう$[5, 5, 5]$。 

すべてのペアには XOR 0 があるため、最良のエッジは 0 になります。 

| 私 | 値 | ベストパートナー | XOR |
 | --- | --- | --- | --- |
 | 0 | 5 | 1 | 0 |
 | 1 | 5 | 0 | 0 |
 | 2 | 5 | 0 | 0 |

 どのパーティションにも少なくとも 1 つのクラブに同じ値が含まれているため、答えは 0 のままで、割り当ては任意です。

 ## 特殊なケース

 のような入力の場合`[7, 7, 7, 7]`、すべての XOR はゼロです。 アルゴリズムはゼロの最適なエッジを見つけて、任意の色を割り当てます。 クラブ内 XOR を 0 より大きく改善できる分割はないため、どの出力も正しく、BFS 伝播によって有効なパーティションが得られます。 

のために`[1, 2, 4, 8]`、トライにより、最小の XOR エッジが低ビットの不一致から検出されることが保証され、パーティションにより、各グループの内部でより大きな XOR 距離を維持しながら、最も近いペアが分離され、最適性が維持されます。
