 ## 解決策
 ## 問題の理解

 各装備スロットに 1 つずつ、合計 5 つのアーティファクト アイテムが与えられます。 各アーティファクトは正確に 5 つの統計ラインに寄与し、すべてのアーティファクトにわたって、フラット ATK、ATK パーセンテージ、クリティカル率、クリティカル ダメージの 4 つの統計だけを考慮します。 

最終的なキャラクター モデルは、固定の基本統計値 (攻撃力 1500、クリティカル率 5%、クリティカル ダメージ 50%) から始まります。 アーティファクトは、統計タイプに応じてこれらの値を加算または乗算的に変更します。 フラットATK値は直接合計されます。 ATK パーセント値は、基本 ATK に適用される 1 つの乗数に累積されます。 クリティカル率とクリティカルダメージもアーティファクト全体で加算的に蓄積されます。 

集計後、ATK は 1500 に (1 + 合計 ATK パーセント) と合計フラット ATK を掛けたものとして計算されます。 クリティカル率は、100 パーセントを超える値がちょうど 100 パーセントになるようにクランプされます。 クリティカルダメージにはそのような上限はありません。 

最後に、予想されるダメージは、通常のヒットとクリティカル ヒットの混合として定義されます。 

E = ATK×非クリティカル確率+ATK×クリティカル倍率×クリティカル確率。 これは、正常な結果と重大な結果の間の加重平均に単純化されます。 

入力は純粋にテキストであるため、主な困難は、パーセンテージ形式と浮動小数点精度が混在する値を解析して正しく累積することです。 

制約は小さく、アーティファクトが 5 つとそれぞれ 5 行だけなので、合計 25 行になります。 これにより、O(1) の解析と算術を超える最適化の必要性が排除されます。 本当のリスクは数値上の間違いです。パーセント記号の解釈を間違えたり、基本の 5 パーセントのクリティカル率を忘れたり、クリティカル率を誤って 100 パーセントに固定したりすることです。 

合計後にクリティカル率が 100% を超えると、微妙なエッジケースが発生します。 たとえば、アーティファクトのクリティカル率が合計 150 パーセントである場合、実効値は正確に 100 パーセントに固定する必要があります。そうしないと、予想されるダメージが過大評価されてしまいます。 

もう 1 つのよくある落とし穴は、パーセンテージ スケーリングの混合です。 ATK レートはパーセント形式で示されますが、乗数として適用されます (x パーセントは x を 100 で割った値になります)。 これを直接加算と誤解すると、出力が 100 倍オフになります。 

## アプローチ

 ブルートフォース解釈では、スロットごとにアーティファクトの選択肢の組み合わせを列挙しようとしますが、ここでは各スロットに 1 つのアーティファクトがあり、すべてが選択されるため、組み合わせ検索は行われません。 作業は集計だけです。 

中心的な観察は、最終評価ステップまで、すべての統計が独立して線形に寄与するということです。 これにより、問題を 25 個の文字列の解析と 4 つの累計の合計に減らすことができます。 

合計が計算されたら、ATK と予想ダメージの計算式を直接適用します。 唯一の非線形動作はクリティカル レートの上限 1.0 です。これは合計の後、期待値を計算する前に適用する必要があります。 

最終的な式まではすべてが加算されるため、4 つの浮動アキュムレータを超えるデータ構造は必要ありません。

 ## アルゴリズムのチュートリアル

1. 4 つのアキュムレータを初期化します: 合計フラット ATK、合計 ATK パーセント、合計クリティカル率、および合計クリティカル ダメージ。 基本統計は最終的な式で個別に処理されるため、これらはゼロから始まります。 
2. 25 行すべてを読み取り、プラス記号で分割して各統計文字列を解析します。 左側は統計タイプを示し、右側はパーセント記号を含む場合と含まない場合がある数値を示します。 
3.ステータスがATKの場合、その数値をフラットATKの合計に直接加算します。 
4. ステータスが攻撃率の場合、割合を 100 で割って小数に変換し、合計攻撃率に加算します。 
5. ステータスがクリティカル率の場合、10 進数に変換して合計クリティカル率に加算します。 
6. ステータスがクリティカル ダメージの場合、10 進数に変換して合計クリティカル ダメージに加算します。 
7. すべてのアーティファクトを処理した後、最終的な ATK を 1500 に (1 プラス合計 ATK パーセント) と合計フラット ATK を掛けたものとして計算します。 これにより、ベース スケーリングと追加のフラット ボーナスが分離されます。 
8. クリティカル率を最大 1.0 にクランプします。 これにより、確率は確実性を超えることができないというルールが強制されます。 
9. 加重式を使用して予想ダメージを計算します: ATK と (1 マイナス クリティカル率) と ATK と (1 プラス クリティカル ダメージ) とクリティカル 率を乗算します。 
10. 誤差制約を満たすのに十分な精度で結果を出力します。 

### なぜ効果があるのか

 すべての統計の寄与は独立しており、最終的な期待値の計算式まで加算されます。 これは、成果物間の順序や相互作用の影響を心配することなく、各カテゴリを安全に集約できることを意味します。 唯一の非線形変換はクリティカル レートの上限であり、確率の飽和は個々のソースではなく合計にのみ依存するため、合計後に適用され、正確性が保たれます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

BASE_ATK = 1500.0
BASE_CRIT_RATE = 0.05
BASE_CRIT_DMG = 0.50

flat_atk = 0.0
atk_rate = 0.0
crit_rate = 0.0
crit_dmg = 0.0

for _ in range(25):
    s = input().strip()
    typ, val = s.split('+')

    if val.endswith('%'):
        x = float(val[:-1]) / 100.0
    else:
        x = float(val)

    if typ == "ATK":
        flat_atk += x
    elif typ == "ATK Rate":
        atk_rate += x
    elif typ == "Crit Rate":
        crit_rate += x
    elif typ == "Crit DMG Rate":
        crit_dmg += x

atk = BASE_ATK * (1.0 + atk_rate) + flat_atk

crit_rate = BASE_CRIT_RATE + crit_rate
crit_dmg = BASE_CRIT_DMG + crit_dmg

if crit_rate > 1.0:
    crit_rate = 1.0

expected = atk * (1.0 - crit_rate) + atk * (1.0 + crit_dmg) * crit_rate

print(expected)
```このソリューションは、関連する統計ごとに 1 つずつ、計 4 つの独立したアキュムレーターを中心に構成されています。 解析はすべての行に対して均一に行われ、パーセンテージ値の単純なチェックが行われます。 よくある実装上の間違いは、集計の前にパーセンテージ統計を 100 で割る必要があることを忘れていることです。 

ATK パーセントは直接の加算項として機能するのではなく、基本値を変更するため、ATK の計算式はすべての貢献が収集された後にのみ適用されます。 クリティカル率クランプは、ベースとアーティファクトの両方の寄与が確率上限を適用する前に結合されるため、ベース 5 パーセントを追加した後に適用されます。

 最終的な計算は次のように行われます。 

ATK = 1500 × 1.1 + 10 = 1660

 クリティカル率 = 0.05 + 0.10 = 0.15

 クリティカルダメージ = 0.50 + 0.10 = 0.60

 期待値 = 1660 × (0.85 + 1.60 × 0.15) = 1660 × 1.09 = 1809.4

 これは、基本統計と追加修飾子が正しく分離されていることを示しています。 

### 例 2

 クリティカル率 = 0.05 + 1.20 = 1.25、その後 1.0 にクランプ

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import math

    BASE_ATK = 1500.0
    BASE_CRIT_RATE = 0.05
    BASE_CRIT_DMG = 0.50

    flat_atk = 0.0
    atk_rate = 0.0
    crit_rate = 0.0
    crit_dmg = 0.0

    for _ in range(25):
        s = sys.stdin.readline().strip()
        typ, val = s.split('+')
        if val.endswith('%'):
            x = float(val[:-1]) / 100.0
        else:
            x = float(val)

        if typ == "ATK":
            flat_atk += x
        elif typ == "ATK Rate":
            atk_rate += x
        elif typ == "Crit Rate":
            crit_rate += x
        elif typ == "Crit DMG Rate":
            crit_dmg += x

    atk = BASE_ATK * (1.0 + atk_rate) + flat_atk
    crit_rate = BASE_CRIT_RATE + crit_rate
    crit_dmg = BASE_CRIT_DMG + crit_dmg
    crit_rate = min(1.0, crit_rate)

    return str(atk * (1.0 - crit_rate) + atk * (1.0 + crit_dmg) * crit_rate)

# sample-like test
inp = "\n".join(["ATK+10"] * 25)
assert float(run(inp)) > 1500

# crit cap test
inp = "\n".join(["Crit Rate+50%"] * 3 + ["ATK+0"] * 22)
assert float(run(inp)) > 1500

# all damage stats
inp = "\n".join(["ATK Rate+10%", "Crit Rate+10%", "Crit DMG Rate+10%", "ATK+10", "ATK+10"] * 5)
assert float(run(inp)) > 0

# zero case
inp = "\n".join(["ATK+0"] * 25)
assert abs(float(run(inp)) - 1500 * (1 - 0.05 + 1.5 * 0.05)) < 1e-6

 ## 特殊なケース

 重要なエッジケースはクリティカル率オーバーフローです。 すべてのアーティファクトを合計した後で合計クリティカル率が 1.0 を超えた場合、正しい動作はそれをクランプすることです。 アルゴリズムは、集計後に min 操作を適用することでこれを処理し、確率が 100% を超えないようにします。 

もう 1 つのケースは、パーセント形式の混合です。 パーセント記号が含まれる値と含まれない値があるため、100 で割ることによる正規化に失敗すると、ATK 率またはクリティカル率が 100 倍に膨らみます。解析ステップでは、パーセント記号が明示的にチェックされ、一貫して変換されます。 

最後の微妙なケースは浮動小数点精度です。 必要な誤差許容値は 1e-6 であるため、Python の浮動小数点演算を使用するだけで十分ですが、判定では相対的な誤差が許容されるため、書式設定制御なしで印刷することも許容されます。
