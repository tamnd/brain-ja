 ## 解決策
 ## 問題の理解

 一連のボール挿入の後に、グリッドの最終的な占有パターンが与えられます。 

ボールは行の左側または列の上側から押すことができます。 ボールはセルに到達するまで前方に移動します。 そのセルが空の場合は、そこに残ります。 そのセルにすでにボールが含まれている場合、入ってくるボールはその位置を占め、移動したボールは同じ方向に移動し続けます。 

このプロセスは、要素を行または列の先頭に繰り返し挿入し、既存のボールをグリッドの奥深くに移動するのと似ています。 

タスクは、一連の操作を再構築することではありません。 指定された最終グリッドを生成する有効なシーケンスが少なくとも 1 つ存在するかどうかを判断するだけで済みます。 

グリッドの寸法は最大 50 × 50 で、すべてのテスト ケースにわたるセルの総数は最大 10,000 です。 これは非常に小さな入力サイズです。 たとえ$O(nm)$または$O(nm(n+m))$ソリューションは簡単に十分に高速です。 高度なデータ構造は必要ありません。 

難しいのは、どの最終構成に到達できるかを理解することです。 

よくある間違いは、ボールを含むすべてのセルが他のボールを介して上または左の境界線に接続されている必要があると考えることです。 それは必要以上に強いです。 

考慮する：```
111
111
111
```この構成は明らかに到達可能です。 すべてのセルにはボールが含まれています。 

ここで次のことを考えてみましょう。```
010
111
010
```角のセルが空であっても、これも到達可能です。 単純な接続引数では、誤って拒否されてしまいます。 

もう 1 つの簡単な間違いは、操作の順序に注目することです。 可能な挿入シーケンスの数は指数関数的に増加するため、小さなグリッドであっても直接シミュレーションやバックトラッキングは実行できません。 

重要なのは、到達可能なすべての構成が満たし、到達可能性にとっても十分な構造特性を特定することです。 

特に明らかな反例は次のとおりです。```
000
000
001
```答えは`NO`。 

右下隅にあるボールをグリッド内に押し込むには、その左か上のどこかにボールが存在する必要があります。 どちらも存在しないため、どのシーケンスもこの孤立したセルを作成できません。 

## アプローチ

 ブルートフォースアプローチでは、考えられるすべての挿入シーケンスをシミュレートしようとします。 各操作では 1 つの行または 1 つの列が選択されます。 5 × 5 グリッドの場合でも、可能なシーケンスの数は膨大になります。 テストケースには最大 2500 個のボールが存在する可能性があるため、網羅的な検索は完全に不可能です。 

より良いアプローチを見つけるには、プッシュが実際に何を行うのかを理解する必要があります。 

細胞を想定してください$(i,j)$最終構成にはボールが含まれています。 どうしたらそこにボールが届くのでしょうか？ 

行を通して挿入された場合$i$、次に停止する前に$(i,j)$、その行の左側のすべてのセルにはすでにボールが含まれている必要があります。 そうでなければもっと早く止まっていたでしょう。 

同様に、列を通して挿入された場合$j$の場合、その列の上にあるすべてのセルにすでにボールが含まれている必要があります。 

この観察により、次の必要条件が即座に得られます。 

最初の行にも最初の列にもない占有されているすべてのセルについて、上または左に隣接するセルの少なくとも 1 つも占有されている必要があります。 

実際、両方の隣が空の場合、ボールがその位置に到達する方法はありません。 

驚くべきことは、この条件も十分であるということです。 

占有されているすべての内部セルの真上または真左にボールがある場合、いつでも構成を構築できます。 これを確認する 1 つの方法は、プロセスを逆にすることです。 下に占有セルがなく、右側にも占有セルがない占有セルは、最後に挿入されたボールと見なされます。 このような細胞を繰り返し除去しても条件に違反することはありません。 最終的には構成全体が消え、有効な構成が存在することが証明されます。 

これにより、問題全体が単純なグリッド チェックに集約されます。

 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | 指数 | 遅すぎる |
 | 最適 | O(nm) | O(1) おまけ | 承認済み |

 ## アルゴリズムのチュートリアル

 1. グリッドを読み取ります。 
2. すべてのセルを繰り返し処理します。 
3. を含むセルを無視します。`0`制約を課さないためです。 
4. セルが最初の行または最初の列にある場合、そのセルは常に有効です。 

ボールはいつでも対応するボーダーから直接挿入できます。 
5. 占有セルごとに`(i, j)`と`i > 0`そして`j > 0`、上のセルを確認してください`(i-1, j)`そして左側のセル`(i, j-1)`。 
6. 両方の隣接するものが含まれている場合`0`、すぐに答えます`"NO"`。 

このようなセルには、どちらの挿入方向からもアクセスできません。 
7. 占有されているすべての内部セルがチェックに合格した場合、応答します。`"YES"`。 

### なぜ効果があるのか

 上の行または左の列にない占有セルを考慮してください。 

最終的にこの位置を占めるボールがその列を通って入った場合、その列のその前のすべての位置は、ボールが到着したときに占有されなければなりませんでした。 特に、そのすぐ左のセルには、最終構成でボールが含まれている必要があります。 

代わりに、その列から入った場合は、すぐ上のセルに最終構成でボールが含まれている必要があります。 

したがって、到達可能なすべての構成は、アルゴリズムによってチェックされた条件を満たします。 

十分な効果を得るには、下に占有されている隣接セルと右側に占有されている隣接セルがない占有セルを繰り返し削除します。 このようなセルは、最後に挿入されたボールである可能性があります。 ローカル条件は、それを削除した後も、残りの占有セルが依然として同じ特性を満たすことを保証します。 このプロセスを継続すると、最終的にすべてのボールが削除され、有効な逆構造が生成されます。 したがって、チェックに合格したすべての構成に到達可能になります。 

条件は必要かつ十分であるため、アルゴリズムは正しいです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())

for _ in range(t):
    n, m = map(int, input().split())
    g = [input().strip() for _ in range(n)]

    ok = True

    for i in range(1, n):
        for j in range(1, m):
            if g[i][j] == '1':
                if g[i - 1][j] == '0' and g[i][j - 1] == '0':
                    ok = False

    print("YES" if ok else "NO")
```実装は証明に直接続きます。 

ボールは対応する境界線から直接入力できるため、最初の行と最初の列をチェックする必要はありません。 

占有されている 1 つおきのセルについて、少なくとも 1 つのサポートする隣接セルが存在するかどうかをテストします。 上隣にも左隣にもボールが含まれていない場合、構成は不可能であり、テスト ケースを無効としてマークします。 

シミュレーションは実行されません。 ソリューション全体はグリッドの 1 回のスキャンです。 

よくある間違いは、すべてのセルをチェックしてアクセスすることです。`i-1`または`j-1`いつ`i=0`または`j=0`。 からループを開始します`1`この問題を完全に回避します。
