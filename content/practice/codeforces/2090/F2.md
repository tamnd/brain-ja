 ## 解決策
 ## 問題の理解

 私たちは、複数人の間で連続的なキーアンドロック ゲームをシミュレートするように求められます。`n`選手たち。 がある`l`それぞれのロックには一意の対応するキーがあり、`k`いかなる錠も開かない偽造鍵。 各ターン、プレーヤーは鍵と錠前を選択して、以前の試行を考慮して成功の確率を最大化します。 一度ロックが開かれると再度開くことはできず、使用済みのキーは破棄されます。 目標は、各プレーヤーの予想成功オープニング数を計算することです。 

入力はプレーヤーの数を提供します`n`、ロックの数`l`、および偽のキーの数`k`for multiple test cases. 出力は、各プレイヤーのモジュロで予想される成功した一致の数である必要があります。$10^9 + 7$。 

制約により許可されるのは、`n`100までと`l`すべてのテスト ケースで最大 5000 件、`k`最大 25。これは、$O(n \cdot l \cdot k)$または$O(n \cdot l^2)$解決策は実現可能かもしれません。 階乗関数が多数存在するため、キーのすべての順列を反復する単純な再帰シミュレーションは実行不可能です。 

明らかではないエッジケースとしては、次のような場合があります。`k = 0`(すべてのキーが有効です) そしていつ`l = 1`(ロックは 1 つだけです)。 別の厄介なシナリオが発生するのは、`k`に匹敵する`l`; プレイヤーの最適な戦略は、決定的な選択ではなく確率に大きく依存します。 

たとえば、`n = 3, l = 1, k = 4`、単一のロックは 5 つの鍵の 1 つで開けることができ、ターン順序に応じて各プレイヤーに異なる確率が与えられます。 確率を無視した単純な決定論的なシミュレーションでは、不正確な結果が生成されます。 

## アプローチ

 ブルートフォースアプローチでは、各ターンのキー選択の考えられるすべてのシーケンスをシミュレートし、期待される成功を合計します。 各ロックと各キーについて、確率を再帰的に計算できます。 これは正しいですが、その複雑さは階乗的に増加します。`l + k`、不可能になります`l`5000まで。 

重要な洞察は、どの状態でも、残りの有効なキーはすべて対称であり、残りのロックはすべて同等であるということです。 これにより、状態を 2 つの整数 (残りのロックの数) で単純に表すことができます。`l_rem`と残りのキーの数`k_rem`。 その後、動的プログラミングを適用できます。`(l_rem, k_rem)`、各プレイヤーの予想される成功数を計算します。 以来`k <= 25`、DP 状態の総数は管理可能です。 

DP の移行は簡単です。 させて`dp[l_rem][k_rem]`ゲームの最初のプレイヤーに期待される成功を表します`l_rem`ロックと`k_rem`追加のキー。 最初のプレイヤーがキーを選んだ場合:

 - 確率付き`l_rem / (l_rem + k_rem)`、キーが正しく、ロックが開き、`l_rem`1までに。 
- 確率付き`k_rem / (l_rem + k_rem)`、キーは偽物です、減少します`k_rem`1までに出発します`l_rem`変わらない。 

現在のプレイヤーに期待される成功は、`p_correct * (1 + dp_next_correct) + p_fake * dp_next_fake`。 最初のプレーヤーの期待値を計算した後、すべてのプレーヤーの結果をローテーションできます。`n`選手たち。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O((l+k)!) | O((l+k)!) | 遅すぎる |
 | DP オン (ロック、追加キー) | O(l * k * n) | O(l * k) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. モジュラー逆関数を最大で事前計算します。`l+k`モジュロ$10^9+7$剰余算術における除算を効率的に処理するため。 これにより、確率を整数モジュロとして計算できるようになります。$10^9+7$。 
2. DP 配列を初期化する`dp[l_rem][k_rem]`ゲームにおける現在のプレイヤーの期待される成功を表します。`l_rem`ロックと`k_rem`追加のキー。 セット`dp[0][k_rem] = 0`ロックが残っていないため。 
3. DP テーブルを次から繰り返し入力します。`l_rem = 0`まで`l`そして`k_rem = 0`まで`k`。 各州について:

 - しましょう`total_keys = l_rem + k_rem`。 
- 正しいキーを選択する確率`p_correct = l_rem / total_keys`。 
- 偽のキーを選択する確率`p_fake = k_rem / total_keys`。 
- 現在のプレイヤーに期待される成功:```
dp[l_rem][k_rem] = p_correct * (1 + dp[l_rem-1][k_rem]) + p_fake * dp[l_rem][k_rem-1]
```すべての演算はモジュロで実行されます$10^9+7$モジュラーインバースを使用します。 
4. DP テーブルを計算した後、すべての成功の期待値を計算します。`n`ローテーションをシミュレートすることでプレーヤーを動かします。 させて`E[i]`プレイヤーに期待される成功を蓄積する`i`:

 - 順番にロックが解除されるたびに、DP の結果に基づいて期待値を分配し、プレーヤーをローテーションします。 
5. 出力`E[i]`モジュロ$10^9 + 7$プレイヤーごとに。 

機能する理由: このアルゴリズムは、各 DP 状態が、任意の数の残りのロックと追加のキーが与えられたターンのプレイヤーに期待される成功を保存するという不変条件を維持します。 キーとロックの対称性により、順列を明示的にシミュレートすることなく、結果をローテーションしてすべてのプレイヤーの期待を得ることができます。 DP ではすべての結果を再帰的に考慮しているため、確率は正確です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def modinv(x):
    return pow(x, MOD-2, MOD)

def solve():
    t = int(input())
    for _ in range(t):
        n, l, k = map(int, input().split())
        # DP table: dp[locks][extra_keys]
        dp = [[0] * (k+2) for _ in range(l+2)]
        for l_rem in range(l+1):
            for k_rem in range(k+1):
                if l_rem == 0:
                    dp[l_rem][k_rem] = 0
                    continue
                total = l_rem + k_rem
                inv_total = modinv(total)
                p_correct = l_rem * inv_total % MOD
                p_fake = k_rem * inv_total % MOD if k_rem else 0
                val = p_correct * (1 + dp[l_rem-1][k_rem]) % MOD
                if k_rem:
                    val = (val + p_fake * dp[l_rem][k_rem-1]) % MOD
                dp[l_rem][k_rem] = val

        # Compute expected values for n players
        res = [0] * n
        for i in range(l):
            idx = i % n
            # expected success for this lock
            p_lock = dp[l - i][k]
            # incremental contribution: distribute fairly among rotations
            res[idx] = (res[idx] + p_lock - dp[l - i - 1][k] + MOD) % MOD
        print(" ".join(map(str, res)))
```このソリューションは、残りのロックと偽のキーのすべての組み合わせに対して DP テーブルを初期化します。 逆モジュラは、モジュロ演算で除算を安全に処理します。 最後のステップでは、各ロックの貢献を対応するターンに分配することによって、プレイヤーを通じて期待される成功をローテーションします。
