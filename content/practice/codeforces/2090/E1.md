 ## 解決策
 ## 問題の理解

 2 つの整数列が与えられています。`a`そして`b`、両方の長さ`n`。 目標は、すべての要素を削減することです。`a`_round_ と呼ばれる繰り返し操作を実行してゼロにします。 各ラウンドは 3 つのステップで構成されます。まず、要素ごとの最小値を減算します。`a`そして`b`両方のアレイから。 次に、のすべての要素をシフトします。`a`右に 1 ステップ (ラップアラウンドあり)。 第三に、繰り返します。 この簡単なバージョンでは、最初の変更はありません。`a`許可されています (`k=0`）。 タスクは、すべての要素を作成するために必要な最小ラウンド数を見つけることです。`a`ゼロ。 

制約が教えてくれるのは`n`テスト ケースごとに最大 200,000 まで可能で、合計は`n`すべてのテスト ケースの数も 200,000 によって制限されます。 これは、`O(n log n)`ソリューションは許容されますが、単純にラウンドをシミュレートしようとするソリューションは、次のような結果になる可能性があります。`10^9`動作が遅すぎます。 

エッジケースは、以下の要素が含まれる場合に発生します。`a`対応するものよりも大幅に大きい`b`値、または要素が`a`は小さいですが、回転後の分布によりゼロ化が遅れます。 たとえば、次の場合`a = [10, 1]`そして`b = [1, 10]`、回転を考慮しない単純なアプローチでは、必要なラウンド数が過小評価されてしまいます。`a[0]`に移行した後はゆっくりとしか減少しません`a[1]`。 

## アプローチ

 ブルートフォースアプローチではラウンドを明示的にシミュレートします。 ラウンドごとに計算します`t = min(a_i, b_i)`あらゆる人にとって`i`、減算`t`両方の配列から取得し、回転します`a`。 すべての要素が得られるまで繰り返します。`a`ゼロになる。 これは正しいですが、各ラウンドが異なるため遅すぎます。`O(n)`最大で`max(a)`ラウンド、それは可能性があります`10^9`最悪の場合。 

重要な洞察は、最小ラウンド数が各ラウンドの量によって決まることに気づくことです。`a_i`のシーケンスによって「カバー」されます`b`回転による値。 それぞれ`a_i`からの投稿が表示されます`b_i, b_{i+1}, ..., b_{i+n-1}`として`a`回転します。 したがって、問題はそれぞれの条件を見つけることになります。`i`、最小ラウンド数`r`の合計が`b`～によって遭遇した価値観`a_i`で`r`回転数は少なくとも`a_i`。 

これにより、すべての最小ラウンドを計算できます。`a_i`独立して。 一定の長さのウィンドウをスライドさせることができます`n`の倍増配列に対して`b`回転を処理し、それぞれについて`a_i`、必要なラウンド数に対して二分探索を実行します。 全体的な複雑さは、`O(n log n)`、制約に適合します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * max(a_i)) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る`t`。 テスト ケースごとに、次の内容を読んでください。`n`そして`k`(常にゼロ)、配列`a`、および配列`b`。 
2. 2倍にする`b`配列へ`b2 = b + b`。 これにより、明示的な回転を実行するのではなく、連続した部分配列として回転をシミュレートできるようになります。 
3. プレフィックスの合計を計算します`pref`の`b2`、 となることによって`pref[i]`最初の合計が含まれます`i`要素。 これにより、連続した範囲にわたる合計を迅速に計算できます。 
4. 各インデックスについて`i`で`a`、ラウンド数で二分探索を実行します。`r`の合計が`b`要素`b[i], b[i+1], ..., b[i+r-1]`少なくとも`a[i]`。 プレフィックス合計を使用して、これらの合計を定数時間で計算します。 
5. テストケースに必要なラウンド数は最大です。`r`全体`i`、なぜならすべて`a_i`ゼロにならなければなりません。 
6. 結果を印刷します。 

重要な不変条件は、それぞれが`a_i`対応する分だけ減少します`b`現在の回転の値、および回転によりそれぞれの値が保証されます。`a_i`最終的にはあらゆるものと一致します`b_j`。 プレフィックス合計と二分探索を使用することにより、それぞれが行われる最初のラウンドを正確に捕捉します。`a_i`のシーケンスで完全にカバーされています`b`価値観。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        
        b2 = b + b
        pref = [0] * (2 * n + 1)
        for i in range(2 * n):
            pref[i+1] = pref[i] + b2[i]
        
        res = 0
        for i in range(n):
            lo, hi = 1, n
            while lo < hi:
                mid = (lo + hi) // 2
                total = pref[i+mid] - pref[i]
                if total >= a[i]:
                    hi = mid
                else:
                    lo = mid + 1
            res = max(res, lo)
        print(res)

if __name__ == "__main__":
    solve()
```コードは最初に 2 倍の配列を構築します。`b2`回転を効率的にシミュレートします。 プレフィックス合計を使用すると、任意のウィンドウにわたって合計を定数時間で計算できます。 それぞれについて`a_i`、二分探索により必要な最小ラウンド数が見つかり、テスト ケースの結果はすべてのラウンドの中で最大になります。`a_i`。 二分探索による反復の防止`n`単純に丸めますが、大規模なものには遅すぎるでしょう`a_i`。
