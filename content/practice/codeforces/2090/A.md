 ## 問題の理解

 私たちは、リトル B とリトル K の 2 人のうち、誰が最初に埋蔵金を掘り出すかを決定するように求められています。宝物はほんのわずかな深さに埋まっています。`a.5`メートル、これが重要です。これは、しきい値が常に一定であることを意味します。`.5`整数を超えるメートル`a`。 リトル B の掘り出し物`x`リトル K は毎日数メートル掘る`y`彼女の場合はメートルで、リトル B から順番に始まります。各テスト ケースについて、次のように出力します。`NO`もしB子が先に宝物を掘り出したら、`YES`リトルKがそうするなら。 

入力は複数のテスト ケースで構成され、それぞれが整数を提供します`x`、`y`、 そして`a`。 各値は 10^9 までの大きさが可能で、テスト ケースは最大 1000 個まで存在できます。 この制約により、毎日の掘削のシミュレーションは除外されます。これは、直接シミュレーションを行うと、最悪の場合、1 秒の制限を超える数十億回の反復が必要になる可能性があるためです。 この問題は本質的に数学的なものであり、鍵となるのは累積深度とターン順序を代数的に推論することです。 

両方の掘削量が等しい場合、微妙な特殊なケースが発生します。 たとえば、次の場合`x = y = 2`そして`a = 1`、宝物はここにあります`1.5`メートル。 小さなBは初日に2メートルを掘り、すぐに1.5メートルを超えました。 部分的なしきい値を考慮せずに交互の日を想定する単純なアプローチは、K の順番が重要であることを示唆するかもしれませんが、実際には最初の調査で十分です。 もう 1 つのエッジ ケースは、一方の掘削量が他方よりもはるかに大きい場合に発生し、結果が最初の人に移される可能性があります。`a`。 

## アプローチ

 強引なアプローチでは、掘削プロセスを毎日シミュレートすることになります。 合計深さのカウンターを初期化します。 毎日、次のいずれかを追加します`x`または`y`誰の番かによります。 追加するたびに、累積深さが次の値を超えているかどうかを確認します。`a.5`。 これは正しく機能しますが、大規模な入力の場合は非効率的です。 各テスト ケースには最大で次のものが必要になる可能性があります`a/x + a/y`反復回数は、最悪の場合、最大 10^9 になります。 これは明らかに制限時間を超えています。 

最適なアプローチは、**累積深度が誰の日を超えたかだけを気にすることを観察することから生まれます。`a.5`**、正確な毎日の進行ではありません。 宝の深さを正規化すると、`2a + 1`端数を避けるために、問題は最初と 2 番目のディガーのスケーリングされた合計を順番に比較することに帰着します。 重要な洞察は、宝の深さは、`x + y`結果が決まります。 数学的に言うと、`a // (x + y)`B と K の両方の全サイクルでは、依然として より大きい剰余が残ります。`x`、その後、リトル B は次のターンで宝物を掘り返します。 それ以外の場合は、リトル K が行います。 これにより、各テスト ケースが数回の整数演算、つまり O(1) 時間に短縮されます。

 | 最適 | お(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 宝の深さを倍増する`a.5`2 で整数のしきい値を取得します`threshold = 2 * a + 1`。 これにより分数が回避され、比較と算術が簡素化されます。 
2. Little B の毎日の発掘量に 2 を掛けて、`b2 = 2 * x`。 Little K の毎日の発掘量に 2 を掛けると、`k2 = 2 * y`。 これにより、発掘量がしきい値と同じスケールになります。 
3. 交互のターンを、次のサイクルを繰り返すものと考えてください。`b2 + k2`。 整数除算を使用して、しきい値に収まる完全なサイクルの数を計算します。`cycles = threshold // (b2 + k2)`。 
4. これらの全サイクル後の残りの深さを計算します。`remainder = threshold - cycles * (b2 + k2)`。 この余りは以下です`b2 + k2`最後の未完了の日を表します。 
5. 剰余を次と比較します。`b2`。 もし`remainder <= b2`、それはリトル B が次のターンでしきい値を超えることを意味するため、答えは次のようになります。`NO`。 それ以外の場合は、Little K が最初に到達し、答えは次のようになります。`YES`。 

機能する理由: すべてを 2 でスケーリングすると、日順を維持しながら、分数のしきい値が整数の問題に変換されます。 不変条件は、両方の掘削機の各フル サイクルの後、残りの深さは常に最後の 1 ターンで処理され、それを B の掘削量と比較することで、誰が最初にしきい値を越えるかを正確に決定することです。 スケールが考慮されているため、あいまいさやオフバイワンエラーはありません。`.5`明示的にメートル。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    x, y, a = map(int, input().split())
    threshold = 2 * a + 1
    b2 = 2 * x
    k2 = 2 * y
    remainder = threshold % (b2 + k2)
    if remainder <= b2:
        print("NO")
    else:
        print("YES")
```コードは、次を使用して入力を効率的に読み取ります。`sys.stdin.readline`複数のテストケースの場合。 しきい値は 2 でスケールされ、`.5`当然。 フルサイクル後にのみ残りを計算し、それを超える最初の採掘者を決定します。 比較`<= b2`Little B が最初に宝物に到達したかどうかを直接確認します。 

微妙な点は、整数へのスケーリングと、不完全な最後のターンを分離するための係数演算です。 どちらかを省略すると、小数点以下のしきい値または非常に大きなしきい値について不正確な結果が得られます。`a`。

 小さなBは1メートルを掘り、Kは2メートルを掘り、それを繰り返します。 2 でスケーリングすると、しきい値は 9、B = 2、K = 4 になります。1 つの完全なサイクル (B+K=6) の後、剰余は 3 になります。3 > 2 であるため、K が最初にしきい値を超えます。

これらのトレースは、アルゴリズムが正しくスケーリングし、サイクルを削減し、誰が最初にしきい値を超えたかを処理することを確認します。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = io.StringIO()
    sys.stdout = output
    
    t = int(input())
    for _ in range(t):
        x, y, a = map(int, input().split())
        threshold = 2 * a + 1
        b2 = 2 * x
        k2 = 2 * y

            print("NO")
        else:
            print("YES")
    
    return output.getvalue().strip()
