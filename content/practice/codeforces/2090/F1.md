 ## 解決策
 ## 問題の理解

 ターンベース ゲームの各参加者について、キーロック マッチの成功予想数を計算するように求められます。 がある$n$メンバーが順番に交代し、$l$ロック、そしてまさに$l$キー (以来$k = 0$この簡単なバージョンでは)。 各キーは 1 つのロックを正確に開きます。 プレイヤーは、一致が成功する確率を最大化する鍵と錠前を選択し、複数の選択肢の可能性が等しい場合は、均一にランダムに選択します。 ロックが一度開かれると、そのロックも対応するキーも再度使用されることはありません。 目標は、各メンバーの期待される成功数を出力モジュロで見つけることです。$10^9+7$。 

入力により複数のテスト ケースが提供されます。 Each test case has the number of players$n$、ロックの数$l$、および偽のキーの数$k$、このバージョンでは常に 0 です。 出力は$n$テスト ケースごとの整数。各メンバーの予想される成功一致をモジュラー整数として表します。 

制約は動的プログラミング ソリューションを可能にするのに十分小さいものです。$n$100までです、$l$5000までとその合計$l$すべてのテスト ケースの数は最大 5000 です。これは、すべてのテスト ケースが存在することを意味します。$O(n \cdot l)$または$O(l^2)$解決策は実現可能です。 難しいのは、分数とモジュロ演算を使用して期待値を正しく計算することです。 

注意すべきエッジケースは次のような場合です$l < n$、 例えば$n=3, l=1$。 最初のプレイヤーのみが成功でき、残りのメンバーの期待試合はゼロです。 プレーヤー間でロックを均等に分割する単純なアプローチでは、誤った結果が生じる可能性があります。 もう一つの微妙なケースは、$l > n$、プレイヤーは複数のラウンドを持ち、期待される貢献度の端数が蓄積されます。 

## アプローチ

 ブルート フォース ソリューションでは、考えられるすべてのキー選択シーケンスをシミュレートし、正確な確率を計算します。 これは、一様なランダムな選択をモデル化し、利用可能なキーとロックを各ターンで更新するため、原理的には正しいです。 ただし、シーケンスの数は階乗的に増加します。$l$が遅すぎます。$l \le 5000$。 

重要な観察は、この問題では、すべてのキーとロックが最初は対称的であり、偽のキーが存在しないことです。 したがって、プレイヤーが自分のターンで成功する確率は、ロックがどれだけ残っているかによってのみ決まります。 具体的には、$m$ロックが残っており、プレイヤーの番です。ロックが開く確率は次のとおりです。$1/m$すべての選択の可能性が等しいため、試行するロックごとに実行されます。 プレイヤーがロックを開くと、残りのロックが 1 つ減り、次のプレイヤーの期待される貢献度も同様に計算されます。 これは、残りのロックの数と誰の順番に基づいて予想される一致を追跡する動的プログラミング アプローチにつながります。 

定義できます$dp[i][j]$プレイヤーの予想成功数として$i$いつ$j$ロックはターンの開始時に残ります。 ターン回転モジュロのプロパティを使用する$n$成功するたびに残りのロックを更新すると、期待値を計算できます。$O(n \cdot l)$テストケースあたりの時間。 分数の期待値は、問題のモジュロ要件を満たすためにモジュラー逆算を使用して処理されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(l!) | O(l!) | 遅すぎる |
 | モジュール分数を使用した DP | O(n * l) | O(l) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. リストを初期化する`expected`サイズの$n$各プレイヤーの予想される一致をゼロから保存します。 
2. 1 から 1 までの各ロックについて$l$、どのプレイヤーのターンであるかを計算します。`(lock_index % n)`。 
3. 試行されるロックごとに、プレイヤーは残りのすべてのロックで成功するチャンスを均等に持ちます。 初期状態では、各ロックの確率は次のとおりです。`1 / remaining_locks`。 
4. モジュラー演算とモジュラー逆数を使用して分数を処理し、この確率を現在のプレイヤーの期待値に加算します。 
5. 残りのロック数を 1 減らして次のプレイヤーに移ります。 
6. Repeat until all locks are processed.

 不変条件は、各ターンで、成功した一致の予想数が残りのロックの数に比例して配分され、均一確率の原則に従うということです。 これにより、期待値が線形に蓄積され、各ロックが 1 回だけ処理されるため、正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
MOD = 10**9 + 7

def modinv(x):
    return pow(x, MOD-2, MOD)

t = int(input())
for _ in range(t):
    n, l, k = map(int, input().split())
    expected = [0] * n
    remaining_locks = l
    player = 0
    for _ in range(l):
        expected[player] = (expected[player] + modinv(remaining_locks)) % MOD
        remaining_locks -= 1
        player = (player + 1) % n
    print(' '.join(str(x) for x in expected))
```機能`modinv(x)`数値の逆剰余を計算します`x`フェルマーの小定理を使用します。素数を法として計算し、分数確率を処理する必要があるため、これが必要になります。 すべてのロックを反復処理し、モジュラー部分を追加します。`1 / remaining_locks`現在のプレイヤーの期待値に。 モジュロ演算により、整数の除算によって精度が失われることがなくなります。

    sys.stdin = io.StringIO(inp)
    MOD = 10**9+7

    t = int(input())
    res = []
    for _ in range(t):
        n, l, k = map(int, input().split())
        expected = [0] * n
        remaining_locks = l
        player = 0
        for _ in range(l):
            expected[player] = (expected[player] + modinv(remaining_locks)) % MOD
            remaining_locks -= 1
            player = (player + 1) % n
        res.append(' '.join(str(x) for x in expected))
    return '\n'.join(res)
