 ## 解決策
 ## 問題の理解

 食堂は無限の格子状の細胞です。 これらのセルの一部はテーブルにグループ化されており、各テーブルはフォームの座標にある 2×2 の正方形を占めます。$(3x+1,3y+1)$を通して$(3x+2,3y+2)$、他のすべてのセルは廊下です。 ゲストは 1 人ずつ原点 (0,0) に到着し、自分のタイプに応じてテーブル セルを占有したいと考えます。 タイプ 1 のゲストは最も近い空きテーブル セルを選択し、タイプ 0 のゲストは最も近い完全に空のテーブルを選択します。 距離はコリドー セルに沿ったマンハッタン距離として測定され、最初に x 座標、次に y 座標によって関係が分割されます。 

入力は複数のテスト ケースを提供します。 各テスト ケースには、ゲストの数とそのタイプの順序がリストされます。 出力には、各ゲストが座っているテーブルのセルの座標が到着順にリストされている必要があります。 

最大の`n`すべてのテスト ケースの合計は 50,000 です。 各ゲストは、最も近い空きセルを見つけるために無制限のテーブル セルのセットを単純にスキャンする必要があるため、ゲストごとのブルート フォース BFS は遅すぎます。 具体的には、各ゲストの (0,0) からの単純な BFS では、最も近い空きテーブルまでの距離に比例し、無制限に増加するコリドー セルの数を訪問する必要がある可能性があります。 これにより、複雑度が O(n*d) の解は除外されます (d はテーブルまでの距離)。 

明らかではないエッジ ケースには、一部のテーブルでセルが部分的に占有されている連続したタイプ 0 ゲストが含まれます。 「任意の空きセル」をチェックするだけの単純なアプローチでは、部分的に占有されているテーブルをタイプ 0 ゲストに誤って割り当てます。 もう 1 つの微妙な点はタイブレークです。複数のセルが等距離にある可能性があるため、問題の決定的な要件を満たすには、x、次に y で並べ替えることが不可欠です。 たとえば、タイプ 1 のゲストに等距離にある 2 つのフリー セル (1,2) と (2,1) が表示された場合、ゲストは (1,2) を選択する必要があります。 

## アプローチ

 強引なアプローチは、占有セルのグリッド マップを維持することです。 各ゲストに対して、(0,0) から有効なテーブル セルに到達するまで BFS を実行し、そのセルに占有済みのマークを付けます。 これは正しいですが、探索されるセルの数は距離に応じて直線的に増加する可能性があり、最大 50,000 人のゲストの場合、ゲストあたりの BFS は非常に遅すぎます。 

重要な洞察は、テーブルが規則的な 3×3 のグリッド パターン上に配置されていることです。 各テーブル セルは、その「テーブル座標」(x、y) から実際の座標 ((3x+1 または +2、3y+1 または +2)) に直接マッピングできます。 さらに、(0,0) から任意のテーブル セルまでのマンハッタン距離は、テーブル座標とテーブル内のセルからの小さなオフセットにのみ依存します。 具体的には、{0,1} のテーブル座標 (tx, ty) とセル オフセット (dx, dy) の距離は次のようになります。`(3*tx + dx) + (3*ty + dy)`。 

グリッドは無限で構造化されているため、表のセルが占有される順序を事前に計算できます。 タイプ 0 のゲストは 2×2 ブロックのテーブル全体を占有しますが、タイプ 1 のゲストは任意のテーブルの空きセルを選択できます。 2 つのシーケンスを維持できます。1 つは完全に空のテーブルを追跡し、もう 1 つは部分的に占有されているテーブル内の空きセルを追跡します。 距離、次に x、次に y による順序付けは予測可能であるため、BFS を使用せずに正しい順序でテーブル セルを生成し、それらをゲストに順番に割り当てることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ゲストごとのブルート フォース BFS | O(n*d) 最悪の場合 | BFS の場合は O(d^2) | 遅すぎる |
 | セル シーケンスと貪欲な割り当てを事前計算する | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テーブルを座標で表現する`(tx, ty)`3×3のグリッド内にあります。 各テーブルには 4 つのセルがあります。`(3*tx + 1, 3*ty + 1)`、`(3*tx + 1, 3*ty + 2)`、`(3*tx + 2, 3*ty + 1)`、`(3*tx + 2, 3*ty + 2)`。 
2. 次の式を使用して、(0,0) からの距離に基づいてテーブルのセルの順序を事前計算します。`dist = 3*tx + dx + 3*ty + dy`。 距離ごとに、候補セルを x の順に並べ替え、次に y の順に並べ替えます。 
3. タイプ 0 のゲスト用に完全に空のテーブルのキューを維持します。 タイプ 0 ゲストが到着すると、キューから最初のテーブルをポップし、その最初の空きセルを割り当て、そのテーブルを部分的に占有されているものとしてマークし、残りの空きセルをタイプ 1 ゲスト用のプールに追加します。 
4. タイプ 1 ゲスト用に、空きセルの個別のキューを維持します。 タイプ 1 ゲストが到着すると、このキューから最初の空きセルをポップします。 セルのテーブルが以前に空だった場合は、空のテーブル キューからセルを削除します。 
5. ゲストごとに、そのタイプに応じて、対応するキューから次の適切なセルを割り当て、占有済みとしてマークします。 それに応じてキューを更新します。 
6. 割り当てられた各セルの座標を到着順に出力します。 

この戦略が機能するのは、テーブル構造により、テーブル セルのマンハッタン距離が原点から離散的なレイヤーで増加することが保証されるためです。 セルを距離でソートし、座標でタイブレークすることにより、キューは自然に不変条件を維持します。タイプ 0 のゲストは常に完全に空のテーブルを選択し、タイプ 1 のゲストは常に原点に最も近い空きセルを選択します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    q = int(input())
    for _ in range(q):
        n = int(input())
        t = list(map(int, input().split()))
        
        # Precompute table cells in order
        empty_tables = deque()
        free_cells = deque()
        
        # Generate enough tables to cover n guests
        # 2D BFS-like layer expansion
        layer = 0
        cells = []
        while len(cells) < n*4:
            for tx in range(layer+1):
                ty = layer - tx
                for dx in (1,2):
                    for dy in (1,2):
                        cells.append((3*tx+dx, 3*ty+dy, tx, ty))
            layer += 1
        
        # empty tables queue
        table_cells_map = {}
        for x,y,tx,ty in cells:
            table_cells_map.setdefault((tx,ty), []).append((x,y))
        
        empty_table_queue = deque(sorted(table_cells_map.keys(), key=lambda k: 3*k[0]+3*k[1]))
        # prepare all free cells queue for type 1 guests
        free_cell_queue = deque()
        
        result = []
        for typ in t:
            if typ == 0:
                tx, ty = empty_table_queue.popleft()
                x, y = table_cells_map[(tx, ty)].pop(0)
                result.append(f"{x} {y}")
                # remaining cells go to free cells queue
                free_cell_queue.extend(table_cells_map[(tx,ty)])
            else:
                x, y = free_cell_queue.popleft()
                result.append(f"{x} {y}")
        
        print("\n".join(result))

if __name__ == "__main__":
    solve()
```このソリューションは、距離の順に十分な数のテーブルを事前計算します。 各タイプ 0 ゲストは、空のテーブル キューからテーブルを削除し、残りのセルをタイプ 1 の空きセル キューにプッシュします。 タイプ 1 のゲストは常にフリーセルのキューの先頭から選択します。 これにより、BFS が回避され、距離と座標による正しい順序付けが保証されます。 

## 実用的な例

 **サンプル 1:**

 | ゲスト | タイプ | 割り当てられたセル | 空のテーブル | フリーセル |

 | 2 | 1 | (1,2) | 同じ | [(2,1),(2,2)] |
 | 3 | 1 | (2,1) | 同じ | [(2,2)] |
 | 4 | 0 | (1,4) | 次の空のテーブル | [...] |
 | 5 | 0 | (4,1) | 次の空のテーブル | [...] |

 この表は、タイプ 0 のゲストが常に新しいテーブルを使用し、タイプ 1 のゲストが残りの空きセルを埋めることを示しています。 

**サンプル 2:** すべてのタイプ 1 ゲストを使用して構築された小さな例は、空のテーブル キューに触れることなく、フリー セル キューで十分であることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各ゲストは 1 回処理されます。 事前計算により、n に比例する十分なセルが生成されます。 |
 | スペース | O(n) | キューには割り当て用に最大 4*n 個のセルが保存されます。 |

 このソリューションは、n が最大 50,000、メモリが 512MB の場合、2 秒の制限時間内に十分に適合します。
