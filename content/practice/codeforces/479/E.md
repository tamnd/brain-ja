 ## 解決策
 ## 問題の理解

 1 から n までのフロアの行が与えられています。 フロア a から開始し、正確に k 回移動します。 各移動は現在のフロア x とは異なる新しいフロア y を選択しますが、制限があります。禁止されたフロア b と比較して絶対距離が「遠すぎる」移動は許可されません。 形式的には、距離 |x − y| の場合にのみ、x から y に行くことができます。 は厳密に |x − b| より小さいです。 

移動するたびに、訪問したフロアを記録します。 k 個の記録されたフロアの異なるシーケンスがいくつ可能であるかが尋ねられます。 

重要なオブジェクトは位置だけではなく、許可される次の動きのセットが b が現在位置を基準にしてどこにあるかによって決まるという事実です。 b から遠い場合は、多くの移動が許可されます。 近い場合、許可される領域は急激に縮小します。 

n、k ≤ 5000 という制約により、シーケンスを明示的に列挙するアプローチは即座に除外されます。 ステップごとにおおよそ n 個の選択肢を分岐させると、n^k 個の状態が生成され、これは天文学的に大きくなります。 正しい解決策は、重複する部分問題を再利用する必要があります。多くの異なるパスが、同じ回数移動した後に同じフロアにつながります。 

開始位置がすでに b に近い場合、微妙なエッジ ケースが発生します。 たとえば、a = b − 1 の場合、許可される方向は b から離れる方向だけであり、多くの中間位置は不可能になります。 逆に、a が b から遠い場合、最初の動きは非常に柔軟ですが、後の動きは縮小領域にウォークを「閉じ込める」可能性があります。 貪欲なカウントやシミュレーションベースのカウントは、同じフロアに到達するさまざまな履歴の組み合わせ爆発を無視するため、失敗します。 

もう 1 つの落とし穴は、シーケンスがエンドポイントだけでなくフルパスによって区別されることを忘れていることです。 同じフロアで終わる 2 つのパスは、中間のステップが異なる場合、別々にカウントされます。 

## アプローチ

 ブルートフォース戦略では、a から始まるすべての k ステップ パスをシミュレートします。 現在のフロア x から、制約を満たすすべての y を試し、再帰的に続行します。 これは、移行ルールを正確に尊重するため、原則として正しいです。 ただし、状態の数はツリーのように増加し、各ノードは O(n) まで分岐でき、深さは k になります。 枝刈りを行ったとしても、パスの数は k で指数関数的になりますが、k が 5000 までの場合は不可能です。 

重要な観察は、このルールはフロアの絶対的な同一性ではなく、b までの距離のみに依存するということです。 a 位置が b の左にあるのか右にあるのか、そしてそれがどのくらい離れているのかがわかれば、間隔の観点から遷移を特徴付けることができます。 

位置 x から見たすべての有効な移動は、厳密に b よりも x に近いフロアです。 d = |x − b| と定義すると、有効な目的地は、x 自体を除く区間 (x − d + 1, x + d − 1) 内のすべてのフロアになります。 これにより、各状態がラインの連続セグメントにわたる遷移に変わります。 

遷移を個別に列挙する代わりに、動的プログラミング テーブル dp[t][x]: t が移動した後にフロア x に到達する方法の数を維持します。 各州はカウントを宛先の範囲に分散します。 これは古典的な「ポイントクエリへの範囲更新」構造であり、差分配列またはプレフィックス合計を使用して解決できます。 

各 x について、その有効な区間 [L, R] を計算し、x 自体を中心に分割し、x を除くその区間内の y のすべての dp[t+1][y] に dp[t][x] を加算します。 dp[t+1] の差分配列を使用して、各状態が O(1) に寄与し、接頭辞の合計を使用して実際の値を再構成します。 

遷移構造は層ごとに線形のままであるため、合計の複雑さは O(nk) になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^k) | O(k) 再帰 | 遅すぎる |
 | 範囲更新付きの DP | O(nk) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. dp[x] を、現在の移動回数の後にフロア x に到達する方法の数として定義します。 単一の既知の位置から開始するため、最初は dp[a] = 1 です。 
2. 1 から k までの各ステップに対して、ゼロに初期化された新しい配列 ndp を作成します。 これにより、次の動きのためにすべてのトランジションが蓄積されます。 
3. すべてのフロア x について、その許容移動半径 d = |x − b| を計算します。 これにより、x からどれだけ離れられるかが決まります。 
4. これを有効な宛先の間隔 (|x − y| となるすべての y) に変換します。 < d、これは y ∈ [x − d + 1, x + d − 1] となり、x 自体は除外されます。 
5. dp[x] をすべての y に個別に加算する代わりに、差分配列を使用して ndp の範囲更新を実行します。つまり、dp[x] を左側の境界に追加し、右側の境界の後で減算し、x の周囲で分割して除外します。 
6. すべての x を処理した後、ndp のプレフィックス合計を取得して、各フロアの実際のカウントを再構築します。 
7. dp を ndp に置き換えて、次のステップに進みます。 

k 回の反復の後、すべての dp[x] はすでに x で終わる完全なシーケンスを表しており、答えはすべての x の合計であるため、合計は必要ありません。 

### なぜ効果があるのか

 各ステップで、dp[x] は x で終わるすべての個別の履歴を集計します。 遷移規則は x と b のみに依存し、x にどのように到達したかには依存しません。 これにより、プロセスはマルコヴィアンになります。つまり、x で結合するすべてのパスは、その数を除いて区別できなくなります。 各 dp[x] はすべての有効な次の位置に独立して分散されるため、範囲の更新では正確な多重度が保持されます。 x を除外すると、無効な自己ループがカウントされなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n, a, b, k = map(int, input().split())
    
    dp = [0] * (n + 1)
    dp[a] = 1

    for _ in range(k):
        diff = [0] * (n + 3)

        for x in range(1, n + 1):
            val = dp[x]
            if not val:
                continue

            d = abs(x - b)
            if d <= 1:
                continue

            L = max(1, x - d + 1)
            R = min(n, x + d - 1)

            # add to [L, R]
            diff[L] = (diff[L] + val) % MOD
            diff[R + 1] = (diff[R + 1] - val) % MOD

            # remove x itself
            diff[x] = (diff[x] - val) % MOD
            diff[x + 1] = (diff[x + 1] + val) % MOD

        ndp = [0] * (n + 1)
        cur = 0
        for i in range(1, n + 1):
            cur = (cur + diff[i]) % MOD
            ndp[i] = cur

        dp = ndp

    print(sum(dp[1:]) % MOD)

if __name__ == "__main__":
    solve()
```dp 配列は、各移動後のパスの分布を表します。 差分配列は各開始フロアの範囲加算をエンコードし、プレフィックス合計は実際の値を効率的に再構築します。 

x の周りの分割は最もデリケートな部分です。 単一の区間 [L, R] には x が含まれるため、区間の残りの部分はそのままにして、位置 x でのみ dp[x] を減算することで補正します。 

オーバーフローを防止し、問題の要件に一致させるために、すべての算術演算は 1e9+7 を法として実行されます。

 ## 特殊なケース

 重要なエッジ構成の 1 つは、x が b からちょうど 1 ステップ離れたときに発生します。 たとえば、n=5、b=3、x=2。 ここで d=1、条件 |x-y| < 1 では、整数 y はまったく許可されません。 計算された間隔が崩壊し、差分更新によってすべてがキャンセルされるため、DP はそのような状態からの寄与を正しく生成しません。 

もう 1 つのケースは、x=1 および b=n など、x が b から遠い場合です。 この場合、d は大きくなり、x 自体を除くほぼすべての範囲が許可されます。 範囲更新では、完全な間隔を適用して x で減算することでこれをきれいに処理し、すべての有効な宛先が二重にカウントされることなく同じ寄与を確実に受け取るようにします。 

最後の微妙なケースは、差分配列内の負の値の蓄積です。 境界で減算するため、中間値が負になる可能性がありますが、プレフィックスの合計の前にモジュロ正規化を行うことで正確さが保証されます。
