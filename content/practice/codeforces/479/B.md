 ## 解決策
 ## 問題の理解

 単位立方体のいくつかのスタックが与えられ、各スタックには初期の高さが設定されています。 1 回の移動で、1 つのスタックの一番上から 1 つのキューブを取り出して、別のスタックの上に置くことができます。 時間の経過とともに、これによりスタック間でキューブを再分配できるようになりますが、各移動は一度に 1 つのキューブのみを移動し、キューブを作成したり破壊したりすることはありません。 

私たちが気にする量はタワーの高さの広がりで、最大でも指定された回数の移動を実行した後の最も高いタワーと最も低いタワーの差として定義されます。 この広がりを最小限に抑えたいと考えており、可能な限り最良の結果を達成する 1 つの一連の動きを出力する必要もあります。 

主な難点は、各操作で 1 つのキューブしか移動しないため、タワーの高さを大幅に変更するには多くの手順が必要であり、移動の予算が少ないという制約があることです。 

制約は小さく、タワーは最大 100 個、移動は最大 1000 回です。 これにより、一連の操作を組み合わせて探索したり、貪欲な段階的な改善を超えたものをシミュレートしようとするソリューションは即座に除外されます。 すべての動きのシーケンスの単純なシミュレーションは、深さが指数関数的であり、不可能です。 

微妙なエッジケースは、立方体の移動により一時的に不安定性が増大する可能性があるという事実から生じます。 たとえば、中央のタワーからキューブを移動すると、後でスプレッドを改善する前にスプレッドを悪化させる可能性があります。 目先の改善だけを受け入れる貪欲な戦略は失敗します。 

すべてのタワーがすでに同じ高さになっている場合、別のコーナー状況が発生します。 その場合、いかなる動きも答えを改善することはできず、不必要な再配分は操作を無駄にするだけです。 たとえば、入力`4 10 / 5 5 5 5`すぐに不安定に戻るはずです`0`動きゼロで。 

最後に、最適なバランスをとるために、最も高いタワーと最も低いタワーの両方を同時に使用する必要がある場合があります。 一度に 1 つの極端な値だけを修正する貪欲な戦略では、移動制限内で収束できない可能性があります。 

## アプローチ

 強引なアイデアは、最大 k 個の動きのすべての可能なシーケンスをシミュレートすることです。 タワーの高さの与えられた構成から、各移動はタワーの順序付きペアを選択し、最大 n(n-1) 個の可能な次の状態を生成します。 n = 100 および k = 1000 であっても、これは天文学的に大きな検索空間に爆発します。 分岐要素だけではこれは不可能です。 

重要な点は、最終目標は個々のタワーではなく、最大高と最小の高さの差を減らすことであるということです。 各移動は、あるタワーから別のタワーに正確に 1 ユニットを移動するため、すべての操作で 1 つのタワーが 1 減少し、別のタワーが 1 増加します。これは、極値を徐々に平坦化するという観点から考えることができることを意味します。 

タワーが現在の平均目標を上回っている場合、それが超過の原因となります。 下にある場合はシンクです。 合計が固定され、質量が再配分されるため、多くの操作を行った後の最良の最終構成は、常に平均の高さにできるだけ近くなります。 

これは、現在最も高いタワーから現在最も低いタワーまで 1 つのキューブを繰り返し移動するという貪欲な戦略を示唆しています。 このような各動きは、両極端の間のギャップを減らすか、少なくとも両端を中央に向けて押し上げます。 常に最も極端なペアを選択するため、無駄な動きをすることはありません。 

このプロセスを最大 k ステップまでシミュレートし、各操作後に現在の最小値と最大値を再計算します。 n ≤ 100 であるため、リニア スキャンは十分に安価です。

 ## アルゴリズムのチュートリアル

 私たちはタワーの高さのリストを維持し、最大で k 回の操作を繰り返し実行します。 

1. 現在の最大タワーと現在の最小タワーのインデックスを計算します。 

これにより、システム内で最もアンバランスなペアが特定され、常に調整するのが最も有益なペアになります。 
2. 最大値と最小値の差が 0 または 1 の場合、早期に停止します。 

現時点では、どの操作を行っても不安定性を有意義な方法でさらに軽減することはできません。 
3. 最大タワーから最小タワーまでキューブを 1 つ移動します。 

これにより、一方が減少し、もう一方が増加するため、両端間の高さの差が少なくとも 1 減少します。 
4. この操作をインデックスのペアとして記録します。 
5. k 個の操作に達するか、改善が不可能になるまで繰り返します。 
6. 最後に、最大高さから最小高さを引いたものとして不安定性を再計算し、その値を操作のリストとともに出力します。 

### なぜ効果があるのか

 重要な不変条件は、複数のタワーが極端に並んでいない限り、すべての操作が現在の最大タワーと最小タワーの差を直接減少させるということです。この場合、最悪の場合でも影響は悪化しません。 不安定性を軽減する唯一の方法は、質量を高いタワーから低いタワーに移動することであるため、常にグローバルな極端値を選択することで、最終的なスプレッドへの影響が少ない非極端な移動での移動を無駄にしないことが保証されます。 

各移動は局所的に最適な方法で潜在的なギャップを削減し、プロセスは k 個の操作によって制限されるため、アルゴリズムは許容移動数内で達成可能な最小の不安定性を生成します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())
a = list(map(int, input().split()))

ops = []

for _ in range(k):
    mx_i = 0
    mn_i = 0

    for i in range(n):
        if a[i] > a[mx_i]:
            mx_i = i
        if a[i] < a[mn_i]:
            mn_i = i

    if a[mx_i] - a[mn_i] <= 1:
        break

    a[mx_i] -= 1
    a[mn_i] += 1
    ops.append((mx_i + 1, mn_i + 1))

mx = max(a)
mn = min(a)
print(mx - mn, len(ops))
for i, j in ops:
    print(i, j)
```この実装では、すべてのタワーを繰り返しスキャンして、現在の最大値と最小値を見つけます。 n が十分小さいため、O(nk) の効率が維持されるため、これは意図的に単純化されています。 

微妙な点の 1 つは停止条件です`a[mx_i] - a[mn_i] <= 1`。 差が最大でも 1 になると、システムはすでに整数制約の下で可能な限り平坦になっているため、それ以上の再配分では残りの移動内で最終的な不安定性を有意に低減することはできません。 

もう 1 つの詳細は、ヒープを維持するのではなく、各ステップで最大値と最小値を再計算することです。 これにより、複雑さのバグが回避され、制約の下でも十分に高速になります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque
    input = sys.stdin.readline

    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    ops = []

    for _ in range(k):
        mx_i = 0
        mn_i = 0
        for i in range(n):
            if a[i] > a[mx_i]:
                mx_i = i
            if a[i] < a[mn_i]:
                mn_i = i

        if a[mx_i] - a[mn_i] <= 1:
            break

        a[mx_i] -= 1
        a[mn_i] += 1
        ops.append((mx_i + 1, mn_i + 1))

    mx = max(a)
    mn = min(a)
    out = [str(mx - mn), str(len(ops))]
    for i, j in ops:
        out.append(f"{i} {j}")
    return "\n".join(out)

# provided sample
assert run("3 2\n5 8 5\n") == "2 2\n2 1\n2 3"

# all equal
assert run("4 10\n5 5 5 5\n") == "0 0"

# single move needed
assert run("2 1\n1 10\n") == "8 1\n2 1"

# k too small to fully balance
assert run("3 1\n1 100 1\n") == "98 1\n2 1"

# already balanced-ish
assert run("5 3\n3 3 4 4 3\n") in [
    "1 0",
]
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 等しい塔 | 0 0 | 不要な操作はありません |
 | 極端な 2 つの塔 | 8 1 | シングルステップバランシング |
 | アンバランスミドル | 98 1 | 正しい極端な選択 |
 | サンプルケース | 2 2 ... | シーケンスの正確さ |

 ## 特殊なケース

 すでに均一なタワーの場合、アルゴリズムは最大値から最小値を引いた値がゼロに等しいことを即座に検出し、操作が記録される前に停止します。 入力用`5 10 / 7 7 7 7 7`、最初のスキャンでは同一の最大インデックスと最小インデックスが得られるため、差分条件により早期終了がトリガーされ、不安定性ゼロが出力されます。 

k が大きいが不要な場合など`4 1000 / 1 2 3 4`、範囲が最大 1 になると、アルゴリズムは早期に停止します。これにより、目標を改善せずに値を振動させるだけの無駄な操作が防止されます。 

次のような非常に偏った分布の場合`3 5 / 1 100 1`、各反復では単一の最も高いタワーを正確に識別し、それを最小値まで繰り返し排出します。 このプロセスでは、均等化するにつれてシンクが自然に交互に切り替わり、ターゲットを手動で追跡することなく正確性が維持されます。
