 ## 問題の理解

 N 個のクレヨンが入った山があります。 2 人のプレイヤーが交互にターンを行い、各ターンでプレイヤーがちょうど 1、5、または 13 個のクレヨンを取り除きます。 最後に残ったクレヨンを取ったプレイヤーが即勝ちです。 両方のプレイヤーは現在のパイルサイズを知っており、常に勝つ可能性を最大化する手を選択します。 課題は、最初のプレーヤーと 2 番目のプレーヤーのどちらが勝利する戦略を持っているかを判断することです。 

入力には、クレヨンの初期数である単一の整数 N が含まれます。 出力は、勝利を強制できるプレーヤーの番号です。プレーヤー 1 が最初に動き、プレーヤー 2 が次に動きます。 

N の上限は 10000 です。これは十分に小さいため、線形動的計画法ソリューションが容易に可能です。 各ポジションが最大 3 つの次のポジションに分岐する可能性があるため、考えられるすべてのゲーム シーケンスを試すソリューションは飛躍的に成長します。 すべてのパイル サイズはいくつかのより小さいパイル サイズにのみ依存するため、二次アプローチさえも不要です。 

トリッキーなケースは、ゲームの終わりに近い位置から発生します。 たとえば、クレヨンが 1 つしかない場合:```
1
```正しい出力は次のとおりです。```
1
```プレイヤーは唯一のクレヨンを取り除くことができ、勝ちとなります。 プレイヤーが 5 個または 13 個のクレヨンを取れるかどうかだけをチェックする不注意な解決策では、誤って負けとマークされる可能性があります。 

別の境界ケースは次のとおりです。```
2
```正しい出力は次のとおりです。```
2
```最初のプレイヤーはクレヨンを 1 つ取り除き、残り 1 つを対戦相手に残さなければなりません。 次に、2 番目のプレーヤーが最後のクレヨンを受け取ります。 手のサイズのみに基づく単純なパターンでは、小さな負けの状態が以前の状態によって決定されることを見落とす可能性があります。 

## アプローチ

 直接的なアプローチは、考えられるすべてのゲームをシミュレートすることです。 与えられた数のクレヨンについて、1、5、または 13 個のクレヨンを再帰的に試して、いずれかの選択が相手の立場を失うことにつながるかどうかを確認できます。 これは正しいです。考えられるすべての動きが考慮され、他のプレーヤーが勝利を強制できない状態に移動できたときにプレーヤーが勝ちます。 

この方法の問題は、繰り返される状態の数です。 たとえば、サイズ 10000 の山を分析しているときに、多くの異なる一連の動きは最終的に同じ小さな山サイズに達します。 結果を保存せずに、再帰は同じ位置を何度も探索します。 可能な移動シーケンスの数はほぼ指数関数的であるため、非常に遅くなります。 

重要な観察は、現在のクレヨンの数のみが重要であるということです。 移動履歴は将来の可能性に影響を与えません。 これは、すべてのパイル サイズが個別のゲーム状態であることを意味し、その状態が勝っているか負けているかを知る必要があるだけです。 

現在のプレイヤーが対戦相手を負け状態にする 1 つの動きを行うことができた場合、その状態を勝利と定義します。 そうでないと国家は負けてしまいます。 最小の山から始めて、N までのすべての状態を計算できます。これにより、再帰的検索が単純な動的プログラミング プロセスに変換されます。 

ブルートフォース手法は、あらゆる可能な未来を探索するため機能しますが、多くの異なるパスを介して同じパイル サイズに到達すると失敗します。 ゲームの状態はクレヨンの残りの数にのみ依存するという観察により、すべての状態を 1 回で解決できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(3^N) | O(N) 再帰の深さ | 遅すぎる |
 | 最適 | O(N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. インデックス i の値が、i 個のクレヨンを含む山がそのターンのプレイヤーの勝利かどうかを表す配列を作成します。 true 値は、現在のプレーヤーが強制的に勝利できることを意味し、false 値は、すべての手が最終的に負けることを意味します。 
2. ゼロクレヨンの状態を負けとして設定します。 クレヨンを持たずにターンを開始したプレイヤーは移動できないため、この状態が基本ケースとなります。 
3. 1 から N までの山のサイズごとに、1、5、または 13 個のクレヨンを削除する 3 つの可能な動きを確認します。 移動が可能で、相手に負けの状態が残る場合、現在の状態を勝ちとしてマークします。 

これが機能する理由は、プレイヤーが成功する手は 1 つだけであるためです。 相手を不利な立場に置いておくことができれば、最適なプレーにより相手は敗北を避けることができなくなります。 

1. N 個のクレヨンの状態を計算した後、状態が勝利している場合はプレーヤー 1 を出力し、そうでない場合はプレーヤー 2 を出力します。 

なぜ効果があるのか:

 動的計画法の不変条件は、山サイズ i を処理した後、保存された値が i 個のクレヨンが残ったときのゲームの結果を正確に表すということです。 クレヨンがゼロということは、前のプレイヤーがすでに勝ったことを意味するため、基本ケースは正しいです。 他のすべての状態については、アルゴリズムはすべての正当な手をチェックします。 いずれかの手が負け状態になった場合、現在のプレイヤーがそれを選択して勝ちます。 そのような手が存在しない場合、あらゆる手で相手に勝ちを与えてしまうため、現状では負けています。 状態が計算される時点で、より小さな状態はすべて既知であるため、すべての決定は正しい情報に基づいて行われます。 

## Python ソリューション```python
import sys

input = sys.stdin.readline

def solve():
    n = int(input())
    
    win = [False] * (n + 1)
    
    moves = [1, 5, 13]
    
    for i in range(1, n + 1):
        for move in moves:
            if i >= move and not win[i - move]:
                win[i] = True
                break
    
    print(1 if win[n] else 2)

if __name__ == "__main__":
    solve()
```配列`win`は、0 から N までのすべてのパイル サイズのゲーム結果を保存します。負け状態に達する有効な手を見つけた後にのみ状態が勝ちになるため、すべての値が負けに設定されて始まります。 

ループは状態を昇順に処理します。 計算するとき`win[i]`、すべての州`win[i - move]`移動後の残りの山は常に i より小さいため、 はすでに最終値を持っています。 

の`break`ステートメントは、勝ち手が見つかると手のチェックを停止します。 勝利の選択肢が 1 つあれば十分なので、さらに検索する必要はありません。 境界チェック`i >= move`無効な負のインデックスへのアクセスを防ぎます。 

Python の整数はこの問題に対して十分な大きさであり、最大配列サイズはわずか 10001 要素であるため、メモリ使用量は最小限で済みます。

## テストケース```python
import sys
import io

def solve_input(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    
    n = int(sys.stdin.readline())
    win = [False] * (n + 1)
    
    for i in range(1, n + 1):
        for move in (1, 5, 13):
            if i >= move and not win[i - move]:
                win[i] = True
                break
    
    ans = "1" if win[n] else "2"
    
    sys.stdin = old_stdin
    return ans

assert solve_input("1\n") == "1", "minimum case"
assert solve_input("2\n") == "2", "first losing position"
assert solve_input("5\n") == "1", "direct move of size five"
assert solve_input("13\n") == "1", "direct move of size thirteen"
assert solve_input("10000\n") in ("1", "2"), "maximum size"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 | 1 | 可能な限り小さな山はすぐに取ることができます。 |
 | 2 | 2 | 相手に最後の手を与えて負けた状態。 |
 | 5 | 1 | より大きな許容手を使用して勝利した状態。 |
