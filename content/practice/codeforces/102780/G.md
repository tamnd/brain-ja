 # 問題の理解

 砂時計は最大でも 4 つあります。 各砂時計は 1 つの固定時間を測定し、その砂はどちらの方向にも流れることができます。 砂時計をひっくり返すことは、少なくとも 1 つの砂時計が空になった瞬間にのみ許可されます。 最初のアクションは時間 0 に発生し、目標はちょうど k 分の時点で砂時計が空になるようにすることです。 出力は、これが可能かどうかだけではありません。砂時計がひっくり返る瞬間の正確なシーケンスを出力する必要があります。 

少数の砂時計が主な手がかりとなります。 デバイスは最大 4 つまでしかなく、各デバイスの持続時間は最大 20 分です。 したがって、1 つの砂時計で考えられる内部状況は非常に少数です。 目標時間は 1440 まで大きくなる可能性があるため、目標時間に達するまで考えられるすべての戦略をシミュレートするには注意が必要です。 フリップのすべてのシーケンスを試行するソリューションは指数関数的に増加するため不可能ですが、個別の構成の数は限られているため、状態ベースの検索は適合します。 

よくある間違いは、プロセスの正確な瞬間を考慮せずに、現在の残り時間だけが重要であると考えることです。 もう 1 つの間違いは、任意のタイミングで反転を許可することです。 たとえば、入力の場合```
1
5
3
```正しい出力は```
-1
```なぜなら、1 つの 5 分砂時計は 5 の倍数でしか終了できないからです。 開始直後に反転し、3 分後に停止できると想定する貪欲なアプローチはルール違反になります。 

もう一つのエッジケースは、最後の瞬間です。 入力用```
2
3 5
5
```答えは存在します。 時間ゼロで両方をひっくり返し、5 分間のグラスが空になるまで待つことができます。 最終出力には、時刻 5 に砂時計が反転していない行が 1 行含まれている必要があります。 不注意な実装では、移行中に目標時間に到達したことがわかったときに停止し、必要な出力がまさにその瞬間のイベントを記述していることを忘れてしまう可能性があります。 

3 番目の微妙なケースは、すでに空になっている砂時計をひっくり返すことです。 入力用```
2
3 5
7
```5 分ガラスがまだ実行中であっても、3 分ガラスは時間 3 で再び反転することができます。 検索では、イベントが発生したときに、空になったばかりの砂時計も含め、砂時計のサブセットをひっくり返すことができる必要があります。 

# アプローチ

 直接的な総当たりのアイデアは、考えられるすべてのフリップ シーケンスをシミュレートすることです。 各イベントの瞬間には最大 4 つの砂時計があるため、反転できるサブセットは最大 16 個になります。 シミュレーションはすべてのサブセットを再帰的に試行し、目標時間に到達するか、分岐が失敗することが証明されるまで継続します。 

このアプローチは正しいです。なぜなら、すべての法的測定はまさに一連の法的選択であり、再帰ではそれらすべてが調査されるからです。 問題は繰り返される状態の数です。 シーケンスが異なると砂時計の構成が同じになる可能性がありますが、ブルート フォースではそれらを個別に探索します。 可能なパスの数はイベントの数に応じて指数関数的に増加するため、個々の遷移が小さい場合でも速度が非常に遅くなります。 

重要な観察は、未来は現在の時刻と各砂時計の現在の状態にのみ依存するということです。 この状況に至った経緯は関係ありません。 これにより、同じ状況を幅優先検索でマージすることができます。 

ステートには、現在の分と、砂時計ごとに、現在実行中のサイドが空になるまでの残り時間が保存されます。 2 つの異なるシーケンスが同じ状態に達した場合、どちらもまったく同じ継続の可能性があるため、1 つだけを保持する必要があります。 

可能な状態はそれほど多くありません。 現在時刻には 1441 個の値しかなく、各砂時計には少数の残り時間値しか含めることができません。 4 つの砂時計と最大 20 の持続時間があるため、この状態空間は BFS にとって十分小さいです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | イベント数の指数関数的増加 | 指数 | 遅すぎる |
 | 最適 | O(k * 積(ti + 1) * 2^n) | O(k * 積(ti + 1)) | 承認済み |

 # アルゴリズムのチュートリアル

 1. 時間ゼロの空の構成から BFS を開始します。 初期状態は、砂時計が開始される前の瞬間を表します。 この状態を維持すると、最初の操作は他のすべての操作と同様に時間ゼロで実行できます。 
2. 訪問した状態ごとに、現時点で反転できる砂時計のすべてのサブセットを試します。 砂時計は最大 4 つあるため、サブセットは最大 16 個あります。 
3. 選択した反転を適用します。 砂時計が空の場合、それをひっくり返すと、残りの期間がすべて残った状態で砂時計が開始されます。 現在の方向に残り x 分で走行している場合、反対側にはすでに落ちている砂があるため、反転すると残り時間は t - x に変わります。 
4. 最小の正の残り時間を取得して、次のイベントの瞬間を見つけます。 次回は、少なくとも 1 つの砂時計が空になったときです。 
5. 時間をその量だけ進め、正の残り時間を同じ量だけ減らします。 ゼロに達した砂時計は空になります。 
6. まだアクセスされていない場合は、新しい状態を BFS に挿入します。 完全なシーケンスを再構築できるように、以前の状態と反転されたサブセットを保存します。 
7. 時間 k の状態に到達したら、パスを再構築します。 砂時計が空になると測定が終了するため、最後に出力されたイベントは反転のないターゲットの瞬間です。 

なぜ効果があるのか:

 BFS の不変条件は、保存されているすべての状態が、許可されたイベントの瞬間の直後に正当な状況であるということです。 すべての遷移は、正当な反転セットを 1 つだけ適用し、砂時計が空になる次の瞬間に進むため、生成されたすべての状態も正当です。 BFS は到達可能なすべての状態を調査し、一意の設定を決して破棄しないため、時刻 k に到達すると、有効なシーケンスが存在することになります。 BFS が時間 k に到達せずに終了した場合、考えられるすべての正当なシーケンスは調査された何らかの状態によって表されているため、解決策は存在しません。 

# Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    n = int(input())
    t = list(map(int, input().split()))
    k = int(input())

    start = (0, (0,) * n)
    queue = deque([start])

    parent = {start: None}
    action = {}

    answer = None

    while queue:
        time, rem = queue.popleft()

        if time == k:
            answer = (time, rem)
            break

        for mask in range(1 << n):
            new_rem = list(rem)

            for i in range(n):
                if mask & (1 << i):
                    if new_rem[i] == 0:
                        new_rem[i] = t[i]
                    else:
                        new_rem[i] = t[i] - new_rem[i]

            if all(x == 0 for x in new_rem):
                continue

            delta = min(x for x in new_rem if x > 0)
            new_time = time + delta

            if new_time > k:
                continue

            for i in range(n):
                if new_rem[i] > 0:
                    new_rem[i] -= delta

            state = (new_time, tuple(new_rem))

            if state not in parent:
                parent[state] = (time, rem)
                action[state] = mask
                queue.append(state)

    if answer is None:
        print(-1)
        return

    path = []
    cur = answer

    while parent[cur] is not None:
        path.append((cur, action[cur]))
        cur = parent[cur]

    path.reverse()

    print(len(path) + 1)
    print(0, 0)

    for state, mask in path:
        time = state[0]
        flipped = [str(i + 1) for i in range(n) if mask & (1 << i)]
        print(time, len(flipped), *flipped)

if __name__ == "__main__":
    solve()
```BFS キューには、法的なイベントの直後に発生する状態のみが含まれます。 の`rem`タプルは、各砂時計が空になるまでの残り時間を保存します。 値 0 は、砂時計が現在空であり、裏返すことで再開できることを意味します。 

移行ロジックはソリューションの中核です。 グラスをひっくり返すと、残り時間は反対側の砂の量になります。 長さ t の砂時計の残り時間が x 分の場合、その量は t - x です。 すべての反転が適用されると、シミュレーションは分ごとに進むのではなく、次のイベントに直接ジャンプします。 

親辞書は再構築にのみ使用されます。 各状態にどのように到達したかを記録するため、すべての BFS ノード内に完全なパスを保存する必要がなくなります。 これにより、メモリ使用量が低く抑えられます。 

最後の再構成では、最初の瞬間を出力し、その後、k に到達するために使用されたすべてのイベントを出力します。 BFS は砂時計が空になった後にのみ状態を作成するため、最後の遷移は時刻 k に達します。そのため、ターゲットの瞬間は自動的に有効な終了イベントになります。 

# 実用的な例

7

| 時間 | イベント後の残り | 反転 |

 | 5 | 1、0 | 3分グラス |
 | 7 | 0、0 | なし |

 すべての遷移が空になる瞬間に正確に到達するため、検索は時間 7 に達します。 最終状態では、不要なフリップを実行せずに測定が終了したことが確認されます。

| 時間 | イベント後の残り | 反転 |

# 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(k * 積(ti + 1) * 2^n) | 各状態は、可能なすべてのフリップのサブセットを試行します。 |
 | スペース | O(k * 積(ti + 1)) | 到達可能な時刻と砂時計の設定はそれぞれ 1 回保存されます。 |

 砂時計の最大数はわずか 4 つで、各持続時間は最大でも 20 であるため、可能な内部構成の数は少なくなります。 目標時間の 1440 分は、BFS 状態空間がメモリ制限内に収まるのに十分な時間でもあります。

 # エッジケース

 期間 5、ターゲット 3 の 1 つのグラスの場合:```
1
5
3
```BFS は空の状態から始まります。 ガラスを反転すると時間 5 に達しますが、これはすでに目標を超えているため、時間 3 の状態は生成されません。 アルゴリズムは正しく印刷します`-1`。 

最後のイベント要件については、次のようになります。```
2
3 5
5
```BFS は、5 分間グラスが空になってから 5 時間後の状態に達します。 再構築では、最初のフリップとフリップがゼロの最後のイベントが出力されます。 このアルゴリズムでは、目標時間に到達することと別の操作が必要なことを混同しません。 

空のグラスをひっくり返す場合:```
2
3 5
7
```時刻 3 で 3 分間のグラスが空になると、残り時間はゼロになります。 移行コードを使用すると、再び反転して 3 分間の空き時間で再起動できます。 これはまさに 7 分間の測定値を作成するために必要な操作です。 

コンテスト形式の短いバージョンや、より正式な校正指向のバージョンが必要な場合は、編集の長さやスタイルをさらに調整できます。
