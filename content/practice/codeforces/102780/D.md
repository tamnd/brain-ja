 ## 解決策
 ## 問題の理解

 a の指数 x の累乗が x の指数 b の累乗と等しくなるような最小の正の整数 x を見つける必要があります。 2 つの入力値はこの方程式に含まれる基数であり、答えは 10^18 を超えない最小の有効な x です。 そのような整数が存在しない場合は、0 が出力されます。 

a と b の値は最大 10000 であるため、入力自体の検索空間は小さいですが、x は非常に大きくなる可能性があります。 答えが 10^18 の上限に近い可能性があるため、考えられる x 値を直接検索することは不可能です。 解決策は、候補を 1 つずつ試すのではなく、方程式の数学的構造を使用する必要があります。 

隠れた主な難点は、x が基数と指数の両方として現れることです。 不注意な解決策では浮動小数点の対数を比較しようとする可能性がありますが、精度エラーにより等価性チェックが不正確な結果に変わる可能性があります。 もう 1 つのよくある間違いは、いくつかの小さな例が機能するため、解決策が常に存在すると仮定することです。 

たとえば、入力`2 6`解決策はなく、正しい出力は次のとおりです`0`。 少数の候補のみをチェックする検索では、間違って早期に停止し、値が機能しないという事実を見落とす可能性があります。 

もう 1 つのエッジ ケースは、有効な x が a に等しくない場合です。 入力用`2 4`、答えは`16`、 なぜなら`2^16 = 16^4`。 基数から x を推測したり、a に関連する x の値だけをチェックしたりすると、実際の解が得られません。 

3 番目のケースは、a の素因数が共通の指数構造を持つ場合に発生します。 入力用`100 20`、答えは`10`。 解決策は、a に近い値を試すことではなく、a の素指数を減らすことによって得られます。 

## アプローチ

 ブルートフォースソリューションでは、1 から 10^18 までのすべての整数 x をテストし、`a^x = x^b`。 等価性チェックは整数演算で実行できるため、この方法は正しいと考えられますが、候補の数がプログラムで処理できる量をはるかに超えています。 候補ごとに 1 つの操作を行うだけでも、約 10^18 の操作が必要になりますが、1 秒の制限では、はるかに少ない数の操作しか許可されません。 

有用な観察は、素因数を調べることで得られます。 a の素因数分解が次のようになると仮定します。```
a = p1^c1 * p2^c2 * ... * pk^ck
```方程式の右辺は、`x^b`したがって、x のすべての素因数はすでに a に出現している必要があります。 x に新しい素数が含まれている場合、その素数は右側には表示されますが、左側には表示されません。 

すべての素数 pi について、x の指数を ei とします。 両辺の素指数を比較すると次のようになります。```
x * ci = b * ei
```これは、すべての指数 ei が x によって制御されることを意味します。 まず、b と a のすべての指数が共有する公約数を削除します。 させて：```
g = gcd(b, c1, c2, ..., ck)
```それから：```
b = g * b'
ci = g * ci'
```方程式は次のようになります。```
ei = x * ci' / b'
```したがって、b'はxを除算しなければなりません。 書く：```
x = b' * n
```これを指数の式に代入すると、次のようになります。```
ei = n * ci'
```したがって：```
x = p1^(n*c1') * p2^(n*c2') * ... * pk^(n*ck')
```これは次のように書き換えることができます。```
x = (p1^c1' * p2^c2' * ... * pk^ck')^n
```させて：```
q = p1^c1' * p2^c2' * ... * pk^ck'
```ここで問題全体は、次を満たす正の整数 n を見つけることになります。```
q^n = b' * n
```q の値は少なくとも 2 です。x = q^n は 10^18 を超えてはいけないため、n は最大でも約 60 までしかありません。 この小さな範囲内で考えられるすべての n 値を単純にテストできます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(10^18) | お(1) | 遅すぎる |
 | 最適 | O(log(10^18) + sqrt(a)) | O(a の素因数の数) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. a を因数分解し、各素数指数を格納します。 これにより、方程式の両側の素数べき乗を比較するために必要な値 ci が得られます。 
2. コンピューティング`g`、b の最大公約数、および a の因数分解からのすべての指数。 g で除算すると、不要な共有部分が削除され、削減された値 b' と ci' が残ります。 
3. 換算された指数を使用して q を構築します。```
q = product of p^(ci/g)
```この値は、リダクション後に累乗が x になる底を表します。 

1. n の値を 1 から増やしていきます。n ごとに、次の値を計算します。`q^n`10^18を超えると停止します。 もし：```
q^n == b' * n
```それから`q^n`は有効な x です。 n は昇順にチェックされ、q は 1 より大きいため、最初に見つかった答えが最小の答えになります。 

1. n の可能な値がすべて失敗した場合は、許容範囲内に有効な x が存在しないため、0 が出力されます。 

なぜ効果があるのか:

 素因数の比較により、元の方程式がはるかに小さな方程式に変換されます。 考えられるすべての解決策は形式を持たなければなりません`x = q^n`、すべての有効な n は次の条件を満たす必要があります。`q^n = b'n`。 アルゴリズムはこれらの考えられる値を正確にチェックするため、解決策を見逃すことはありません。 検索は最小の n から開始されるため、最初の一致では可能な限り最小の x が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

LIMIT = 10**18

def factorize(x):
    factors = []
    d = 2
    while d * d <= x:
        if x % d == 0:
            cnt = 0
            while x % d == 0:
                x //= d
                cnt += 1
            factors.append((d, cnt))
        d += 1 if d == 2 else 2
    if x > 1:
        factors.append((x, 1))
    return factors

def solve():
    a, b = map(int, input().split())

    factors = factorize(a)

    g = b
    for _, c in factors:
        g = __import__("math").gcd(g, c)

    b_red = b // g

    q = 1
    for p, c in factors:
        q *= p ** (c // g)

    power = 1
    n = 1
    while True:
        power *= q
        if power > LIMIT:
            break

        if power == b_red * n:
            print(power)
            return

        n += 1

    print(0)

if __name__ == "__main__":
    solve()
```因数分解関数は、a の素数表現を抽出します。 入力制限が 10000 であるため、試行除算は簡単に十分に高速になります。 

最大公約数の計算では、証明で導出されたとおりに指数が正確に減算されます。 変数`q`は縮小された基数を格納するため、すべての回答候補は q を繰り返し乗算することによって生成された形式になります。 

ループは次から始まります`power = q`、n が 1 に等しいことを表します。反復ごとに n が 1 ずつ増加し、q^n が更新されます。 値が 10^18 を超えると、q が少なくとも 2 であるため、後の値はさらに大きくなり、検索は安全に停止できます。 

すべての計算には Python 整数が使用されるため、オーバーフローのリスクはありません。 明示的な制限チェックにより、巨大な権力の不必要な拡大が防止されます。 

## 実用的な例

 入力用`2 4`、因数分解は次のようになります。 

| n | q^n | b' * n | 結果 |
 | --- | --- | --- | --- |
 | 1 | 2 | 4 | 等しくない |
 | 2 | 4 | 8 | 等しくない |
 | 3 | 8 | 12 | 等しくない |

 ここ`g = gcd(4, 1) = 1`、 それで`q = 2`そして`b' = 4`。 最初に一致する n は 4 で、x = 16 となります。 

入力用`2 6`、縮小された方程式は次のようになります。 

| n | q^n | b' * n | 結果 |
 | --- | --- | --- | --- |
 | 1 | 2 | 6 | 等しくない |
 | 2 | 4 | 12 | 等しくない |
 | 3 | 8 | 18 | 等しくない |
 | 4 | 16 | 24 | 等しくない |
 | 5 | 32 | 30 | 等しくない |
 | 6 | 64 | 36 | 等しくない |

 2 の累乗は、最終的には一次式 6n よりも速く増加し、値の制限に達する前に等価性は現れません。 アルゴリズムは 0 を出力します。

## テストケース```python
import sys
import io
import math

def solution(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    a, b = map(int, input().split())

    def factorize(x):
        factors = []
        d = 2
        while d * d <= x:
            if x % d == 0:
                cnt = 0
                while x % d == 0:
                    x //= d
                    cnt += 1
                factors.append((d, cnt))
            d += 1 if d == 2 else 2
        if x > 1:
            factors.append((x, 1))
        return factors

    factors = factorize(a)
    g = b
    for _, c in factors:
        g = math.gcd(g, c)

    b_red = b // g
    q = 1
    for p, c in factors:
        q *= p ** (c // g)

    power = 1
    n = 1
    while True:
        power *= q
        if power > 10**18:
            break
        if power == b_red * n:
            return str(power)
        n += 1

    return "0"

 ## 特殊なケース

 のために`2 6`、アルゴリズムは次のことを見つけます。`g = 1`、`q = 2`、 そして`b' = 6`。 考えられるすべての n 値をチェックします。`2^n`限界以下に留まります。 満足する値がありません`2^n = 6n`これにより、有効に見える方程式に整数の解がない状況が処理されます。 

のために`2 4`、アルゴリズムは、答えが a に近いとは想定しません。 縮小された方程式を構築します`2^n = 4n`、n が 4 に等しいことを検出し、返します。`2^4 = 16`。 これは、生成された x が元の基数よりもはるかに大きくなる可能性があることを確認します。 

のために`100 20`、因数分解すると、`100 = 2^2 * 5^2`。 b の gcd と指数は 2 で、次のようになります。`q = 10`そして`b' = 10`。 最初のチェックでは、`10^1 = 10 * 1`したがって、アルゴリズムはすぐに 10 を返します。 これは、素数指数を減らすことで小さな解が作成される場合をカバーします。
