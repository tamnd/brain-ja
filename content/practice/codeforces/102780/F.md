 ## 解決策
 ## 問題の理解

 ゲームは単語で行われますが、文字の順序は重要ではありません。 移動では、各文字のコピーが何部残っているかのみが考慮されます。 文字が複数回出現する場合、プレイヤーはその文字の 1 つのコピーを削除するか、ちょうど 2 つのコピーを削除するか、または残りのすべてのコピーを削除することができます。 残り文字数の合計をゼロにしたプレイヤーが勝ちとなります。 

入力は、最大 40 文字の大文字の単語 1 つです。 両方のプレイヤーが最適な手を選択した場合、出力はどちらのプレイヤーが勝利戦略を持っているかを示します。 元の問題は中央ロシア地域コンテスト 2019 のものです。 

ワード長が短いということは、最初はすべてのゲーム状態に対する単純な検索が可能であるように見えるかもしれないことを意味します。 ただし、文字の分布が異なると位置も異なるため、可能な状態の数は急速に増加します。 すべての状態を調査するソリューションは指数時間に近づく可能性がありますが、これは長さが 40 の場合でも不要です。代わりに、各文字数の数学的特性を見つける必要があります。 

主なエッジケースは、移動を通常の除去として扱うことから生じます。 不注意な解決策では、1 つまたは 2 つの文字を削除することは持ち帰りゲームに似ているため、カウントが 3 で割り切れる文字が常に負けると仮定する可能性があります。 すべてのコピーを削除するのは特殊な操作であるため、これは失敗します。 たとえば、入力`AAA`答えがあります`Alice`。 カウントは 3 ですが、アリスは 3 文字すべてをすぐに削除できます。 

もう 1 つのよくある間違いは、1 回しか出現しない文字を無視することです。 入力用`A`、答えは`Alice`唯一の移動で最後の文字が削除されるからです。 ペアまたは完全なグループのみをチェックするソリューションでは、誤って負けとしてマークされてしまいます。 

3 番目のエッジ ケースは、単語全体が単一のゲーム値を持たないことです。 入力用`AB`、答えは`Bob`、各文字が独立して寄与し、その効果がキャンセルされるためです。 全長のみを考慮するソリューションでは、この相互作用が見逃されてしまいます。 

## アプローチ

 直接的なアプローチは、現在の単語の状態をモデル化し、あらゆる可能な動きを再帰的に試すことです。 すべての文字について、そのカウントを 1 つ減らすか、可能であれば 2 つ減らすか、ゼロに設定することができます。 再帰的状態に少なくとも 1 つの手が負け状態につながる場合、その状態は勝ちです。 そうでなければ負けです。 

この強引な方法は、最適なプレイの定義に正確に従っているため、正しいです。 問題は州の数です。 可能な文字数は 26 で、短い単語でもさまざまな分布を作成できます。 最悪のケースでは、文字数が指数関数的に増加します。これは、削除の考えられるすべてのサブセットが個別の状態として現れる可能性があるためです。 

問題を変える観察は、すべての文字タイプが独立したゲーム コンポーネントのように動作するということです。 これは標準的な公平なゲーム状況であり、各コンポーネントには Grundy 値があり、全体の位置はそれらの値の XOR 演算によって決定されます。 

出現する文字を 1 つだけ考えてみましょう`c`回。 させて`g(c)`グランディ値になります。 その動きは次のとおりです`c - 1`、`c - 2`、 そして`0`それらの動きが存在するとき。 最初の値を計算すると次のようになります。 

| カウント | グランディな価値 |
 | --- | --- |
 | 0 | 0 |
 | 1 | 1 |
 | 2 | 2 |
 | 3 | 3 |
 | 4 | 1 |
 | 5 | 2 |
 | 6 | 3 |

 このパターンは 3 カウントごとに繰り返されます。 3 で割り切れる正のカウントは値 3 を持ち、他のカウントはその余りに等しい値を持ちます。 

したがって、単語全体は 26 文字の値の XOR になります。 xor が 0 でない場合、アリスは 0 xor の位置に移動して勝つことができます。 xor が 0 の場合、すべての動きがボブに勝利の位置を与えます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | 指数 | 遅すぎる |
 | 最適 | O(n + 26) | お(26) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 単語内に各大文字が何回出現するかを数えます。 ゲームの状態はこれらの周波数のみに依存し、文字の位置には依存しません。 
2. 頻度のあるすべての文字について`c`、グランディ値を計算します。 もし`c`ゼロであれば、何も貢献しません。 それ以外の場合は、使用します`c % 3`残りのゼロを値 3 に置き換えます。 
3. 26 個の値すべてを XOR します。 xor は、異なる文字で表される独立したゲームを組み合わせたものです。 
4. 印刷`Alice`xor がゼロ以外の場合。 印刷する`Bob`xor がゼロの場合。 

最後のステップが機能する理由は、公平な組み合わせゲームではゼロ XOR ポジションが負けているためです。 非ゼロの XOR 位置は常にゼロの XOR 位置に移動できますが、ゼロの XOR 位置は別のゼロの XOR 位置に移動できません。 

なぜ効果があるのか:

 各文字の頻度は独立した山です。 移動によって変更されるのは 1 つの山だけであり、他の山には影響しません。 グランディ値は、1 つの山の可能なあらゆる将来を要約します。 したがって、すべてのパイル値の xor が単語の完全な値になります。 この値がゼロの場合、両方のプレイヤーは負け状態に直面します。 それがゼロでない場合、現在のプレイヤーは xor をゼロにする動きをしており、対戦相手は負けた状態になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()

    cnt = [0] * 26
    for ch in s:
        cnt[ord(ch) - ord('A')] += 1

    x = 0
    for c in cnt:
        if c:
            value = c % 3
            if value == 0:
                value = 3
            x ^= value

    print("Alice" if x else "Bob")

if __name__ == "__main__":
    solve()
```配列`cnt`独立したゲームコンポーネントを保存します。 それらは 26 個しかないため、実装では動きをシミュレートする必要はありません。 

グランディ変換は正の周波数に対してのみ実行されます。 頻度ゼロの文字は値ゼロを持ち、xor には影響しません。 サイズ 3 の山はサイズ 0 の山と同等ではないため、3 の倍数の特別な処理が必要です。 すべての文字を削除する移動により、繰り返しパターンが変更されます。 

最終的な XOR は次の場所に保存されます。`x`。 Python の整数はオーバーフローしませんが、ここでの値はとにかく非常に小さいです。 入力には 1 つの単語が含まれているため、1 回の呼び出しで`readline`十分です。 

## 実用的な例

 のために`ZADACHA`、文字数は次のとおりです。 

| 手紙 | カウント | グランディな価値 | 現在の xor |
 | --- | --- | --- | --- |
 | あ | 3 | 3 | 3 |
 | C | 1 | 1 | 2 |
 | D | 1 | 1 | 3 |
 | H | 1 | 1 | 2 |
 | Z | 1 | 1 | 3 |

 最後の xor はゼロではないため、アリスが勝ちます。 

のために`WORD`、カウントは次のとおりです。 

| 手紙 | カウント | グランディな価値 | 現在の xor |
 | --- | --- | --- | --- |
 | W | 1 | 1 | 1 |
 | ああ | 1 | 1 | 0 |
 | R | 1 | 1 | 1 |
 | D | 1 | 1 | 0 |

 最後の xor はゼロなので、ボブが勝ちます。 

これらのトレースは、結果が単語の元の順序ではなく文字の頻度に依存する理由を示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 文字を数えるには単語を 1 回通過する必要があり、その後 26 個の値のみが処理されます。 |
 | スペース | お(1) | アルゴリズムは 26 個のカウンターのみを保存します。 |

 最大長はわずか 40 であるため、線形解は容易に制限内に収まります。 一定のメモリ使用量は、入力が大きくなっても変化しません。 

## テストケース```python
import sys
import io

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    result = sys.stdout.getvalue().strip()

    sys.stdin = old_stdin
    sys.stdout = old_stdout
    return result

assert run("ZADACHA\n") == "Alice", "sample 1"
assert run("WORD\n") == "Bob", "sample 2"

assert run("A\n") == "Alice", "single letter"
assert run("AAA\n") == "Alice", "all equal letters"
assert run("AB\n") == "Bob", "xor cancellation"
assert run("A" * 40 + "\n") == "Bob", "maximum size multiple of three"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`A`| アリス | 取り外し可能な単一の文字が当選する必要があります。 |
 |`AAA`| アリス | すべての文字を移動すると、グランディ パターンが 3 の倍数で変更されます。 |
 |`AB`| ボブ | 独立した文字は、全長ではなく xor によって結合されます。 |

 ## 特殊なケース

 入力用`AAA`の場合、アルゴリズムは頻度 3 の 1 文字をカウントします。 その Grundy 値は 3 なので、xor は 3 で、Alice が出力されます。 これは、1 つまたは 2 つのコピーを取得するよりもすべてのコピーを削除する方が良い場合に対処します。 

入力用`A`、カウントは 1 で、グランディ値は 1 になります。xor はゼロではないため、アリスは唯一の文字を削除するだけですぐに勝ちます。 

入力用`AB`、両方の文字の頻度が 1 で、どちらも値 1 に寄与します。xor は次のようになります。`1 ^ 1 = 0`, なのでポジションは負けています。 すべての動きでちょうど 1 文字が残り、対戦相手は最後の文字を取り除きます。 

同じ文字のコピーが 40 個含まれる単語の場合、カウントは 40 です。グランディ値は次のとおりです。`40 % 3 = 1`, つまりポジションは勝ちです。 このアルゴリズムは、可能な手の数に依存せずに最大入力サイズを処理します。
