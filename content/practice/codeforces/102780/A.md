 # 問題の理解

 課題は、得られる混合物の温度が正確に 80 度になるように、マグカップにスプーン何杯の熱湯と冷水を入れるかを選択することです。 お湯には温度がある`t1`、冷たい水には温度があります`t2`、必要な出力はボリュームのペアです`v1`そして`v2`。 考えられるすべてのペアの中で、スプーン一杯の合計数が最も少ないペアが必要です。 

混合ルールでは、混合後の総熱量が 2 つの温度の加重平均と一致する必要があると規定されています。 この問題の場合、それは次のことを意味します。`t1 * v1 + t2 * v2 = 80 * (v1 + v2)`制約により、温水の温度は 80 度を下回ることはなく、冷水の温度は常に 80 度を下回ることがわかります。値は十分に小さいため、多くの組み合わせをチェックしても適合しますが、方程式には定数時間で直接解くのに十分な構造があります。 シミュレーションや検索は必要ありません。 

主なエッジケースは、混合物の片側が不要になったり、比率が非常に単純になったりする温度に起因します。 もし`t1`温度はすでに 80 度なので、お湯だけで必要な温度が得られます。 入力用`80 20`、正しい出力は次のとおりです。`1 0`。 一般的な比の式のみに基づいた不用意な解法では、ゼロで除算する可能性があります。`t1 - 80`ゼロになります。 

もう 1 つの特殊なケースは、温度差が互いに素でない場合です。 入力用`100 20`、違いは次のとおりです`20`そして`60`。 生の比率は`v1 : v2 = 60 : 20`ですが、最小の有効なペアは次のとおりです。`3 : 1`。 分数を減らさないソリューションでは、不必要に大きな値が出力されます。 

3 番目のケースは、2 つの温度差の公約数がすでに 1 より大きいが、一方の側が目標に近い場合です。 入力用`81 79`、必要な比率は`1 : 1`、したがって、答えは次のとおりです`1 1`。 片側のみから検索したり、浮動小数点計算を使用すると、ここで丸め間違いが発生する可能性があります。 

# アプローチ

 簡単なアプローチは、スプーン数の可能なすべてのペアを試してみることです。 すべてを反復処理できます`v1`そして`v2`0 から 1000 までの値を計算し、方程式が満たされるかどうかを確認し、合計が最小となるペアを保持します。 許可されているすべての回答が考慮されるため、これは正しいです。 最悪の場合、約 100 万ペアがチェックされます。`1001 * 1001`組み合わせ。 

強引なアプローチは、指定された制限に対しては機能しますが、問題の数学的構造が隠蔽されます。 許可されるスプーンの数が大幅に増加すると、組み合わせの数は二次関数的に増加し、すぐに実用的ではなくなります。 

有益な観察は、温度方程式を整理すると得られます。`t1 * v1 + t2 * v2 = 80 * v1 + 80 * v2`項を移動すると次のようになります。`(t1 - 80) * v1 = (80 - t2) * v2`左側は熱水が温度を 80 度以上にどれだけ上げるかを示し、右側は冷水が温度を 80 度以下にどれだけ下げるかを示します。この 2 つの効果は正確にバランスをとる必要があります。 

これにより、2 つの体積間の直接的な比率が得られます。 お湯の量は比例する必要があります`80 - t2`、一方、冷水の量は次のように比例する必要があります。`t1 - 80`。 この比率を最大公約数で減らすと、最小の整数解が得られます。

 # アルゴリズムのチュートリアル

 1. 温水と冷水の温度を読み取ります。 
2. お湯の温度が正確に 80 度であるかどうかを確認します。この状況では、冷水をいくら加えても温度が目標値から離れるだけであるため、スプーン 1 杯のお湯とゼロスプーンの冷水が最小の有効な答えになります。 
3. 2 つの温度差を計算します。`hot_difference = t1 - 80`そして`cold_difference = 80 - t2`。 これらの値は、水の種類ごとに、混合物の温度が目標からどれだけ変化するかを表します。 
4. 2 つの違いの最大公約数を見つけます。 両方の値をこの除数で割ると、バランス方程式を真に保ちながら、比率が減少します。 
5. 出力`cold_difference / gcd`お湯の量と`hot_difference / gcd`冷水の量として。 冷水が 80 をはるかに下回る場合にはより多くの冷水が必要となり、温水が 80 をはるかに超える場合にはより多くの温水が必要となるため、このように値が配置されています。 

それが機能する理由: すべての有効な混合物は方程式を満たさなければなりません`(t1 - 80) * v1 = (80 - t2) * v2`。 これは、2 つのボリュームが反対側の温度差と同じ比率を持つ必要があることを意味します。 アルゴリズムはその比率を正確に構築し、最大公約数で除算して、方程式を満たす最小の正の整数のペアを生成します。 他の有効なペアはこの縮小されたペアの倍数になるため、これより小さい合計ボリュームは存在できません。 

# Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t1, t2 = map(int, input().split())

    if t1 == 80:
        print(1, 0)
        return

    a = t1 - 80
    b = 80 - t2

    g = __import__("math").gcd(a, b)

    print(b // g, a // g)

if __name__ == "__main__":
    solve()
```最初の部分では、熱水がすでに目標温度に達しているという特殊なケースを扱います。 一般的な式では、熱水が 80 を超えるプラスの量の熱を与えると想定されているため、この場合は個別に処理する必要があります。 

変数`a`そして`b`目標温度からの 2 つの偏差を保存します。 方程式では、温水の量は冷水の偏差に関係し、冷水の量は温水の偏差に関係しているため、最終的な出力ではそれらが逆の順序で使用されます。 

最大公約数は、比率を下げるために使用されます。 この削減がなければ、答えは方程式を満たしますが、スプーンの合計数が最小値にならないことになります。 

すべての計算では整数が使用されるため、浮動小数点の精度の問題はありません。 値も Python の整数制限をはるかに下回っているため、オーバーフローは心配ありません。

# テストケース```python
import sys
import io
import math

def solve_data(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)

    t1, t2 = map(int, sys.stdin.readline().split())

    if t1 == 80:
        ans = "1 0"
    else:
        a = t1 - 80
        b = 80 - t2
        g = math.gcd(a, b)

    return ans

 # エッジケース

 入力用`80 20`、アルゴリズムは、お湯の温度が希望の温度に等しいことをすぐに検出します。 出力します`1 0`, なぜなら、スプーン1杯のお湯だけで80度の混合物ができるからです。 高温温度の差がゼロであるため、式のみの実装はここで失敗する可能性があります。 

入力用`100 20`、アルゴリズムは次のように計算します。`hot_difference = 20`そして`cold_difference = 60`。 最大公約数は 20 なので、換算比率は次のようになります。`60 / 20 = 3`そして`20 / 20 = 1`。 出力は`3 1`、最小限のスプーンを使用します。 

入力用`81 79`、アルゴリズムは次のように計算します。`hot_difference = 1`そして`cold_difference = 1`。 それらの最大公約数は 1 であるため、約定する必要はありません。 出力`1 1`ターゲットからの距離が等しい場合は、両方の水が同量必要であることを示しています。
