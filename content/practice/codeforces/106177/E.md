 ## 解決策
 ## 問題の理解

 整数の配列が与えられ、そこから連続するセグメントを 1 つだけ削除することができます。 そのセグメントを削除した後、残りの要素は順序を変更せずに接着され、新しい配列が作成されます。 

削除されたセグメントのこのような選択ごとに、結果として得られる配列の最大部分配列合計を計算します。 タスクは、結果として生じるこの最大サブ配列合計を最大化する方法で、削除されたセグメントを選択することです。 

つまり、構造は次のとおりです。配列内の「穴」を選択し、残りの中で最良の連続合計がどのくらい大きくなるかを尋ねます。 

この難しさは、セグメントを削除すると正常なサブ配列が破壊されるだけでなく、左側のプレフィックスと右側のサフィックスを接続して新しいサブ配列が作成される可能性があるという事実から生じます。 

テスト全体にわたる制約により、合計で最大約 200,000 個の要素が許可されます。 これにより、削除されたセグメントまたは部分配列の二次列挙が除外されます。 すべての O(n^2) 個の削除を試行したり、削除ごとにカダンを最初から再計算したりするものは、時間内に終了しません。 ソリューションは、テスト ケースごとに線形または線形に近いものでなければなりません。 

いくつかのエッジな状況は、誤って対処しやすいものです。 

すべての数値が負の場合、有用なものを除いてすべてを削除することで実質的に空の配列になることができるため、削除後の最適な部分配列の合計は 0 になります。 例えば、`[−5, −2, −8]`配列全体を削除して空のままにすることができるため、答えは次のとおりです`0`。 空ではない部分配列が誤って返されることを前提とした単純な Kadane のみのアプローチ`−2`。 

別の障害モードは、負の中間ブロックで区切られた正のプレフィックスとサフィックスを維持することが最適な戦略である場合に発生します。 例えば`[5, -100, 6]`。 最適なオリジナルの部分配列は次のとおりです。`6`または`5`、しかし、削除した後`[-100]`、配列は次のようになります`[5, 6]`そして最良の部分配列は`11`。 元の最大部分配列のみを考慮するアプローチでは、この「ブリッジ」効果が失われます。 

最後の微妙なケースは、最適な部分配列内のセグメントを削除すると、実際に答えが増加する場合です。 例えば`[3, -1, 3, -1, 3]`、削除`[-1, 3, -1]`葉`[3, 3]`合計付き`6`、元の部分配列の合計よりも大きくなります。 

## アプローチ

 ブルートフォースのアイデアは簡単です。考えられるすべてのセグメントを試してください。`[l, r]`を削除し、残りの配列を構築し、Kadane のアルゴリズムを実行してその部分配列の最大合計を計算します。 各 Kadane の実行時間は O(n) で、除去の選択肢は O(n^2) 個あり、合計時間は O(n^3) になります。 たとえ計算を部分的に再利用したとしても、根本的に最大部分配列構造を何度も再計算していることになります。 

重要な点は、セグメントの削除は、完全に左にあるサブ配列、完全に右にあるサブ配列、または削除されたセグメントの境界を横切るサブ配列にのみ影響するということです。 最終的な配列内の最適なサブ配列は、2 つのカテゴリのいずれかに分類される必要があります。完全に元のプレフィックスまたはサフィックスに含まれるか、削除されたセグメントの前で終わるサフィックスとその後で始まるプレフィックスを連結することによって形成されます。 

これは、除去のたびに Kadane を最初から再計算する必要がないことを意味します。 代わりに、「i で終わる最適なサブ配列」を取得するプレフィックス情報と、「i で始まる最適なサブ配列」を取得するサフィックス情報を事前計算します。 次に、削除境界ごとに、これらの事前計算された値を O(1) で組み合わせて、削除されたセグメントが中央に位置する場合の最良の結果を評価できます。 

より有用な再構成は、削除されたセグメントをギャップとして考えることです。 ギャップの片側全体にある最適なサブ配列、またはギャップを飛び越えるサブ配列のいずれかを最大化したいと考えています。これは、左側の最適なサフィックスと右側の最適なプレフィックスの合計になります。 

この分解が可視化されると、問題はセグメント上のスキャンではなく、考えられるギャップ位置上の線形スキャンになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | ブルートフォース (すべての除去を試す + カダネ) | O(n3) | O(n) | 遅すぎる |
 | 接頭辞/接尾辞カダネ分解 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 標準の Kadane プレフィックス配列を計算します。`pref[i]`インデックスで終わるサブ配列の最大合計を格納します`i`。 これにより、各位置で正確に終了するすべてのサブ配列がキャプチャされます。 
2. サフィックス Kadane 配列を計算します。`suf[i]`インデックスから始まるサブ配列の最大合計を格納します`i`。 これにより、各位置で正確に始まるすべてのサブ配列がキャプチャされます。 
3. 事前計算`best_left[i]`そのうちの最大値として`pref[0..i]`。 これは、プレフィックスに完全に含まれる最適なサブ配列を表します。`i`。 
4. 事前計算`best_right[i]`そのうちの最大値として`suf[i..n-1]`。 これは、から始まるサフィックスに完全に含まれる最適なサブ配列を表します。`i`。 
5. 次に、セグメントの削除を検討してください。`[l, r]`。 削除後、配列は左側の部分に分割されます`[0, l-1]`そして右側の部分`[r+1, n-1]`。 この構成における最適なサブ配列は、最大 3 つのオプションです。左側の部分全体で最適なもの、右側の部分全体で最適なもの、または、左側の部分で始まり、で終わるサフィックスを結合して右側の部分に続くサブ配列です。`l-1`で始まるプレフィックス付き`r+1`。 
6. 間の各境界について`i`そして`i+1`、除去によって引き起こされる潜在的な切り傷として扱います。 で終わる最適なサフィックスを使用して、最適な相互寄与を計算します。`i`プラスで始まる最良のプレフィックス`i+1`。 
7. すべてのカット位置の最大値を取得し、セグメントの削除は役に立たない可能性があるため、削除せずにグローバル最大サブアレイ合計と比較します。 

### なぜ効果があるのか

 最終的な配列内のサブ配列は、削除されたセグメントの片側に完全に存在するか、セグメント全体にまたがります。 完全に片側にある場合は、プレフィックスまたはサフィックスの Kadane 値によってすでにキャプチャされています。 複数にまたがる場合、削除されたセグメント内の要素は利用できないため、削除の直前に終わるサフィックスとその直後から始まるプレフィックスで構成される必要があります。 事前に計算された配列により、両端に最適な選択肢が得られることが保証されるため、すべての有効な候補部分配列はカットごとに一定時間内に 1 回だけ表現されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    # Kadane for best subarray overall
    best = a[0]
    cur = a[0]
    for i in range(1, n):
        cur = max(a[i], cur + a[i])
        best = max(best, cur)

    # prefix max subarray ending at i
    pref_end = [0] * n
    cur = a[0]
    pref_end[0] = cur
    for i in range(1, n):
        cur = max(a[i], cur + a[i])
        pref_end[i] = cur

    # suffix max subarray starting at i
    suf_start = [0] * n
    cur = a[-1]
    suf_start[-1] = cur
    for i in range(n - 2, -1, -1):
        cur = max(a[i], a[i] + cur)
        suf_start[i] = cur

    # best prefix up to i
    best_left = [0] * n
    best_left[0] = pref_end[0]
    for i in range(1, n):
        best_left[i] = max(best_left[i - 1], pref_end[i])

    # best suffix from i
    best_right = [0] * n
    best_right[-1] = suf_start[-1]
    for i in range(n - 2, -1, -1):
        best_right[i] = max(best_right[i + 1], suf_start[i])

    ans = best

    # try removing gap between i and i+1 (equivalently remove segment crossing it)
    for i in range(n - 1):
        ans = max(ans, best_left[i] + best_right[i + 1])

    print(ans)

if __name__ == "__main__":
    solve()
```このコードでは、Kadane を「ここで終わる」バージョンと「ここで始まる」バージョンに分けています。これは、削除操作によりギャップを挟んでサフィックスとプレフィックスを接着する必要があるためです。 配列`best_left`そして`best_right`削除ごとに何も再計算せずに、その接着剤に可能な限り最適なエンドポイントを選択できるようにします。 

実装でよくある落とし穴は、除去を直接シミュレートしようとすることです。 すべての場合に同じサブ問題が再計算されるため、これは失敗します。`(l, r)`。 もう 1 つの微妙な間違いは、最良の答えには削除されたセグメントをまったく横断する必要がない可能性があるため、最初の Kadane 結果を常に保持する必要があることを忘れていることです。 

## 実用的な例

 配列を考慮してください`[1, 2, 3, 4]`。 

まず、接頭辞の Kadane 終了値を計算します。`[1, 3, 6, 10]`。 サフィックスの開始値は次のとおりです。`[10, 9, 7, 4]`。 一番左になります`[1, 3, 6, 10]`そして最良の権利は`[10, 9, 7, 4]`。 

| 私 | ベスト左[i] | ベスト右[i+1] | 候補者 |
 | --- | --- | --- | --- |
 | 0 | 1 | 9 | 10 |
 | 1 | 3 | 7 | 10 |
 | 2 | 6 | 4 | 10 |

 最高なのは`10`, 除去効果を必要とせずに達成されます。 

ここで考えてみましょう`[1, -2, 3, 4]`。 

接頭語カダネ語尾:`[1, -1, 3, 7]`。 サフィックス開始:`[7, 6, 7, 4]`。 一番左:`[1, 1, 3, 7]`。 一番右:`[7, 7, 7, 4]`。 

| 私 | ベスト左[i] | ベスト右[i+1] | 候補者 |
 | --- | --- | --- | --- |
 | 0 | 1 | 7 | 8 |
 | 1 | 1 | 7 | 8 |
 | 2 | 3 | 4 | 7 |

 ここで削除します`-2`作成します`[1, 3, 4]`境界を越えたマージが可能になり、`8`。 これにより、最適な解決策では、2 つのポジティブ領域を接続するためにネガティブ ブロックを削除する必要があることが確認されます。

 ## 特殊なケース

 次のような単一要素配列の場合`[-5]`、カダネが与える`-5`ただし、唯一の要素を削除すると、コストを含む空の配列が生成されます。`0`。 アルゴリズムはこれを処理します。`best`はカダネから始まり、クロスギャップの組み合わせでは単一要素構造が改善されることはないため、正しく比較して返します。`0`。 

最適なセグメントが完全に片側の内側にある配列の場合、次のようになります。`[2, -1, 2, -1, 2]`、Kadane ベースラインはすでに答えを捉えています`2`または`3`構造に依存し、それを超える除去ベースの組み合わせはありません。 ギャップをスキャンすると、分割によって利用可能な連続性が低下するため、内部最大値を超えることのない値が生成されます。 

次のようなポジティブブロックを分離する大きなネガティブブロックがある場合`[10, -100, 10]`、中央のセグメントを削除すると、2 つの正の値が完全にマージされ、インデックス 0 と 1 の間の分割におけるアルゴリズムの境界チェックが正しく評価されます。`10 + 10 = 20`、それが最終的な答えになります。
