 ## 解決策
 ## 問題の理解

 マップは長方形の島のグリッドです。 一部のセルは海にあり立ち入ることができませんが、残りのセルは陸地です。 いくつかの陸上セルには、大文字で表されるユニークな光景が含まれています。 船長は一連の歩行指示を知っていますが、地図上の開始位置は不明です。 唯一可能な開始位置は、照準器を含むセルです。 

あらゆる光景について、そこから出発して一連の指示に従うことで、船長が旅の間ずっと陸上に留まるかどうかを判断する必要があります。 複数の照準器が機能する場合は、それらの文字をアルファベット順に印刷する必要があります。 どれもうまくいかない場合、答えは次のとおりです。`no solution`。 

グリッドの寸法は最大 1000 x 1000 であるため、最大 100 万個のセルが存在できます。 命令の数は 100000 に達する可能性があり、1 つの命令で最大 1000 個のセルを移動できます。 合計歩行距離が 1 億セルに達する可能性があるため、可能な開始ごとにセルごとにパスをシミュレートすると、時間がかかりすぎます。 ただし、可能な開始位置の数は文字数によって制限されており、最大 26 文字です。これにより問題は完全に変わります。各命令が一定時間で処理される限り、あらゆる光景の命令シーケンスをシミュレートする余裕があります。 

不注意な解決策でも、いくつかの点で失敗する可能性があります。 よくある間違いは、長い移動の後に移動先のセルだけをチェックすることです。 例えば：```

```正しい出力は次のとおりです。```

```から始まる`A`、目的地のセルは開いていますが、パスは途中で海のセルを横切ります。 すべての中間セルが有効である必要があります。 

もう一つの間違いは、キャプテンがマップから離れることを許可したことです。 境界は海ですが、実装がセグメント全体をチェックしない場合、移動は依然として外側を横切ろうとする可能性があります。 例えば：```

## アプローチ

 直接的なアプローチは、すべての光景から始めて、指示を 1 つずつ実行することです。 これは正しいです。指示によって、選択した開始点からの船長のルートが完全に決定されるからです。 問題は、各命令のコストを安くすることです。 単純な実装では、移動中に個々の正方形をすべて通過します。 最悪のケースでは、開始照準器が 26 個、命令が 100,000 個あり、各命令で 1,000 個のセルが移動し、およそ 26 億個のセル チェックが行われます。 それは利用可能な時間をはるかに超えています。 

有益な観察は、開始点の数は少ないが、グリッドは大きいということです。 長い直線の動きをすぐに確認できるように、グリッド上で前処理時間を費やす必要があります。 すべての命令は水平または垂直に移動するため、「この行セグメントまたは列セグメント内のすべてのセルはランドですか?」という形式のクエリに答えるだけで済みます。 

海のセルの接頭辞の和を構築します。 行プレフィックスを使用すると水平セグメントをチェックでき、列プレフィックスを使用すると垂直セグメントをチェックできます。 移動セグメント内の海のセルの数がゼロの場合、移動は有効です。 その後、すべての命令は数回の配列アクセスと算術演算になります。 

ブルートフォース手法は、交差する個々のセルごとに作業を繰り返すため、失敗します。 プレフィックス合計の観測により、繰り返されるスキャンが削除され、各完全なシミュレーションが命令の数に削減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(26 * k * L) ここで、L は最大移動長 | O(nm) | 遅すぎる |
 | 最適 | O(nm + 26k) | O(nm) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 地図を読み取り、すべての観光スポットの位置を保存します。 これらのセルのみが開始位置となるため、他のセルからシミュレーションする必要はありません。 
2. 海洋セル用に 2 つのプレフィックス構造を構築します。 行ごとに 1 つのプレフィックスが維持され、水平セグメントのクエリに応答します。 もう 1 つは列ごとに維持され、垂直セグメントのクエリに応答します。 
3. すべての照準器について、現在位置をその照準器の座標に設定し、すべての命令を順番に処理します。 移動が海のセルを横切る場合は、この視界を直ちに破棄してください。 
4. 水平移動の場合は、行プレフィックスを使用して、現在の列と目的の列の間の海のセルをカウントします。 垂直方向の移動の場合は、同じ方法で列の接頭辞を使用します。 カウントがゼロの場合は、現在位置を更新します。 
5. すべての指示が正常に処理されたら、このサイトの文字を回答に追加します。 
6. 集めた手紙を分類して印刷します。 コレクションが空の場合は印刷します`no solution`。 

なぜ効果があるのか:

 開始照準が固定されている場合、シミュレーションは指示に記載されたルートを正確にたどります。 移動は、プレフィックスの合計によって、通過したすべてのセルが着地していることが証明された場合にのみ受け入れられるため、シミュレートされた位置は常にマップ上の正当な歩行と一致します。 アルゴリズムが照準を拒否した場合、対応する命令は実際に海を通過します。 照準を受け入れた場合、無効なセルに入力することなくすべての命令が完了したことになります。 あらゆる可能な出発点がテストされるため、最終的に受け入れられた手紙のセットがまさに必要な答えとなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    grid = []
    sights = []

    for i in range(n):
        row = input().strip()
        grid.append(row)
        for j, ch in enumerate(row):
            if 'A' <= ch <= 'Z':
                sights.append((ch, i, j))

    row_pref = [[0] * (m + 1) for _ in range(n)]
    col_pref = [[0] * (n + 1) for _ in range(m)]

    for i in range(n):
        for j in range(m):
            row_pref[i][j + 1] = row_pref[i][j] + (grid[i][j] == '#')
            col_pref[j][i + 1] = col_pref[j][i] + (grid[i][j] == '#')

    k = int(input())
    moves = []
    for _ in range(k):
        d, x = input().split()
        moves.append((d, int(x)))

    ans = []

    for ch, sr, sc in sights:
        r, c = sr, sc
        ok = True

        for d, x in moves:
            if d == 'E':
                nr, nc = r, c + x
                if nc > m - 1:
                    ok = False
                    break
                if row_pref[r][nc + 1] - row_pref[r][c + 1] != 0:
                    ok = False
                    break
                c = nc
            elif d == 'W':
                nr, nc = r, c - x
                if nc < 0:
                    ok = False
                    break
                if row_pref[r][c] - row_pref[r][nc] != 0:
                    ok = False
                    break
                c = nc
            elif d == 'S':
                nr, nc = r + x, c
                if nr > n - 1:
                    ok = False
                    break
                if col_pref[c][nr + 1] - col_pref[c][r + 1] != 0:
                    ok = False
                    break
                r = nr
            else:
                nr, nc = r - x, c
                if nr < 0:
                    ok = False
                    break
                if col_pref[c][r] - col_pref[c][nr] != 0:
                    ok = False
                    break
                r = nr

        if ok:
            ans.append(ch)

    if ans:
        print(''.join(sorted(ans)))
    else:
        print("no solution")

if __name__ == "__main__":
    solve()
```入力解析では、グリッドの読み取り中に大文字のセルの位置が保存されます。 これにより、開始位置をテストするときにグリッド全体を再度スキャンする必要がなくなります。 

行と列のプレフィックス配列には、海のセルの数が保存されます。 例えば、`row_pref[r][b] - row_pref[r][a]`行内でブロックされたセルの数を返します`r`列の間`a`そして`b - 1`。 同じ考え方が列にも使用されます。 

各移動では、開始セルを除き、宛先セルを含むセグメントがチェックされます。 開始セルは有効なサイトであることがすでにわかっているため、セグメント クエリには影響しません。 チェックが成功すると、現在位置が更新されます。 

境界チェックは、プレフィックス配列をクエリする前に行われます。 これにより、無効な配列アクセスが防止され、グリッドから外れる移動も正しく処理されます。
