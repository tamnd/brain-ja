 ## 解決策
 ## 問題の理解

 正の整数が与えられます`n`。 選択した任意の正の整数に対して`m`、関数を見てみましょう`f(m, i)`すべての約数候補に対して`i`から`1`に`n`。 機能が貢献します`1`まさに分割するとき`m`による`i`残りを残す`1`、そうでない場合は貢献します`0`。 

タスクは、`m`成功した値の合計数を最大化します。`i`、選択した両方を印刷します`m`そして最高得点。 入力には複数の独立した値が含まれています。`n`。 

主な難点はそのサイズにあります。`n`。 届くよ`10^9`したがって、可能な限りすべてのことを繰り返します`i`すべてのテストケースには最大で`10^12`すべてのテストにわたって操作を行うことは不可能ですが、これは不可能です。 範囲のスキャンを回避する数学的構造を見つける必要があります。 

考慮すべき主なケースは、次の小さな値です。`n`そしてその制限は`m`。 たとえば、次のようなとき`n = 1`、有効な余りはありません`1`なぜなら`m mod 1`いつもです`0`、したがって、答えにはスコアが必要です`0`。 からのすべての値を想定するソリューション`1`に`n`満足できる場合はここで失敗します。 

もう 1 つの重要なケースは次のような場合です。`n`の許容最大値で処理できる値を超えています。`m`。 たとえば、以下のすべての数値の最小公倍数`100`すでによりもはるかに大きくなっています`10^18`。 を使用した直接構築`lcm(1, n)`～の制限に違反することになる`m`。 

## アプローチ

 簡単なアプローチは、可能な限りすべてのことを試してみることです`m`値の数を数えます`i`満足する`m mod i = 1`。 可能な範囲が限られているため、これは現実的ではありません。`m`膨大であり、すべてをチェックしても`i`1人の候補者にはすでに費用がかかります`O(n)`。 

より良い方法は、条件を逆にすることです。 方程式`m mod i = 1`ということです`m - 1`で割り切れます`i`。 定義すると`x = m - 1`、問題は数字を見つけることになります`x`できるだけ多くの値が`i`で`[1, n]`できるだけ分ける`x`。 

多くの数を割る自然な方法`x`最小公倍数を取ることです。 もし`x`に等しい`lcm(1, 2, ..., k)`、次に、からのすべての数字`1`に`k`分割する`x`、だから選択する`m = x + 1`のスコアを与える`k - 1`なぜなら`i = 1`決して貢献しない。 

残りの問題はどれくらいの大きさかということです`k`できる。 の値`m`を超えてはなりません`10^18`, したがって、最小公倍数がその制限内に収まる限り繰り返し拡張します。 値が制限を超えるまでに可能な拡張はわずかです。 与えられた`n`、利用可能な最大のものを採用します`k`それは以下のものです`n`。 

これが最適である理由は、数値が`x`ある値のセットでそれを除算すると、それらの値の最小公倍数でも除算する必要があります。`x`。 最小公倍数を超えることはできないので、`10^18 - 1`、より連続した値を分割できる解決策はありません`x`可能な最大のプレフィックスを超えています。

 ## アルゴリズムのチュートリアル

 1. 内に収まる最小公倍数の最大のプレフィックスを事前計算します。`10^18`。 から開始`lcm(1) = 1`値が許容制限をオーバーフローしない限り、次の整数を掛け続けます。 結果のリストには、有用なプレフィックス長がすべて含まれます。 
2. 各テスト ケースについて、最大のプレフィックス長を見つけます。`k`次のような事前計算されたリストから`k <= n`。 これは、すべてを分割できる連続する値の最大数です。`m - 1`。 
3. しましょう`x`なれ`lcm(1, 2, ..., k)`事前に計算された値から。 出力`m = x + 1`。 
4. スコアは`k - 1`いつ`k`少なくとも`1`、すべての値が`2`を通して`k`条件と値を満たす`1`決してそうではありません。 

機能する理由: 選択した値`m`もっている`m - 1`までのあらゆる数字で割り切れる`k`, したがって、スコアは次のようになります。`k - 1`。 より良い答えには、より多くの数字が必要です`2`分割に向けて`m - 1`これにより、これらの数値の最小公倍数が、事前に計算された最大可能値よりも大きくなります。 それは制限に矛盾します`m`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

LIMIT = 10**18 - 1

lcm_values = [1]
cur = 1
k = 1

while True:
    nxt = cur * (k + 1)
    if nxt > LIMIT:
        break
    cur = nxt
    k += 1
    lcm_values.append(cur)

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n = int(input())

        k = 1
        for i in range(len(lcm_values)):
            if i + 1 > n:
                break
            k = i + 1

        m = lcm_values[k - 1] + 1
        ans.append(f"{m} {k - 1}")

    print("\n".join(ans))

solve()
```事前計算により、すべての可能な最小公倍数プレフィックスが一度に構築されます。 最小公倍数は非常に速く成長して通過するため、ループはすぐに停止します。`10^18`わずか数十ステップの後に。 

各テスト ケースの変数は、`k`使用可能な最大のプレフィックス長を格納します。 事前に計算されたリストは小さいため、スキャンは事実上一定時間になります。 答えは、保存された最小公倍数を再計算する代わりに直接使用するため、オーバーフローや不要な作業が回避されます。 

出力値は`lcm + 1`元の状態は残りくらいなので`m`、一方、割り算の方が使用を推論しやすいです。`m - 1`。 最後に 1 を追加すると、必要な値が復元されます。 

## 実用的な例

 のために`n = 3`、便利な接頭辞は次のとおりです。

 | イニシャル | 1 | 1 | 2 | 0 |

のために`n = 5`、プレフィックスは 5 つの数字まで拡張できます。

 | イニシャル | 1 | 1 | 2 | 0 |

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    LIMIT = 10**18 - 1
    lcm_values = [1]
    cur = 1
    k = 1

    while True:
        nxt = cur * (k + 1)
        if nxt > LIMIT:
            break
        cur = nxt
        k += 1
        lcm_values.append(cur)

    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        k = 1
        for i in range(len(lcm_values)):
            if i + 1 > n:
                break
            k = i + 1
        out.append(f"{lcm_values[k - 1] + 1} {k - 1}")

    return "\n".join(out)

## 特殊なケース

 のために`n = 1`、アルゴリズムが選択します`k = 1`そして出力`m = 2`。 唯一チェックされる値は`1`、 そして`2 mod 1`は`0`、スコアは正しいです`0`。 

次のような大きな値の場合、`n = 10^9`、以下の完全な最小公倍数`n`制限内に収めることは不可能です。 アルゴリズムは、最大の有効なプレフィックスで停止します。`43`、そして使用します`lcm(1..43) + 1`。 からのすべての値`2`に`43`機能しますが、最小公倍数が許容最大値を超えるため、これより大きなプレフィックスを強制することはできません。`m - 1`。 

最小公倍数境界に正確にある値の場合、次のようになります。`n = 5`、アルゴリズムには新しい値が含まれています。`lcm(1..5)`まだフィットします。 この境界を欠くと、スコアが小さくなります。そのため、プレフィックス検索に等価性が含まれます。
