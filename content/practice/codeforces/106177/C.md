 ## 問題の理解

 このタスクは、2 つの整数に関する非常に小さな述語を定義します: 固定ペアの場合$(x, y)$、値$f(x, y)$除算の場合のみ 1 に等しくなります$x$による$y$残りはちょうど 1 のままで、それ以外の場合は 0 になります。 

各テスト ケースには 2 つの整数が与えられます。$n$そして$m$。 関数の 2 番目の引数を次のように修正します。$m$、合計を評価します$$f(m,1) + f(m,2) + \dots + f(m,n).$$この合計は単に整数の数を数えるだけです$i \in [1,n]$満足する$m \bmod i = 1$。 

この問題は、この数がすべての正の整数の中で可能な限り大きいかどうかを尋ねます。$x$で得られた値を比較することを意味します。$x = m$他のあらゆる可能な選択肢に対して$x$。 厳密に多数のインデックスを生成する整数が他にないかどうかを判断する必要があります。$i \le n$余りは 1 です。 

重要な構造は、各候補者が$x$の約数に等しいスコアを与える$x-1$範囲内に横たわる$[1,n]$、 なぜなら$x \bmod i = 1$と同等です$i \mid (x-1)$。 

制約は大きく、両方とも$n$そして$m$まで行くことができます$10^9$、まであります$10^3$テストケース。 すべての候補を試すソリューション$x$またはすべてを反復します$i \le n$テストケースごとに実行すると、すぐに遅すぎます。 テストごとでも$O(n)$スキャンは実行不可能です。$n$それだけで10億に達する可能性があります。 

素朴な解釈では、考えられるすべてのことを繰り返すことを示唆するかもしれません。$x$あるいは、多くの値の約数を計算することもできますが、それには無制限の検索か因数分解の繰り返しが必要になり、どちらも制限時間をはるかに超えています。 

微妙なエッジの状況が現れるのは、$n$とても小さいです。 たとえば、次の場合$n = 1$の場合、合計は常に 1 になります。$x$、 以来$x \bmod 1 = 0$1 に等しくなることはなく、すべての値がゼロになり、比較は簡単になります。 少なくとも 1 つの有効な剰余寄与を想定する不用意な実装は、この縮退ケースを誤って処理する可能性があります。 

もう 1 つの例外的なケースは次のような場合です。$m = 1$。 それから毎回$i \ge 1$満足する$1 \bmod i = 1$のためだけに$i > 1$, そのため、割り算条件を大雑把に扱うと、有効なインデックスの構造が急激に変化し、数え間違いが起こりやすくなります。 

## アプローチ

 強引な解釈では、固定値を計算することになります。$x$、 幾つか$i \le n$満足する$x \bmod i = 1$。 これには毎回のチェックが必要です$i$、につながる$O(n)$候補者ごとに。 最適性を判断するには、考えられるすべてのものと比較する必要もあります。$x$、これには制限がないため、このアプローチは基本的に不可能になります。 

重要な観察は、条件を書き換えることです$x \bmod i = 1$割り算の制約として:$$x \equiv 1 \pmod i \quad \Leftrightarrow \quad i \mid (x-1).$$それでそれぞれ$x$の約数の数によってのみ評価されます。$x-1$に横たわっている$[1,n]$。 したがって、合計は切り捨てられた除数の数になります。 

ここで問題は次のようになります。すべての整数の間で$x$、どの値$x-1$以下を超えない約数の数を最大化します$n$。 これは古典的な「制限付き除数関数の最大化」問題です。 重要な構造は、最良の候補は、多くの小さな素因数を含むが、次の値で切り捨てられた数値であるということです。$n$, したがって、以下までの素数のみが得られます$n$貢献する。 

これにより、検索スペースがすべての整数から素数で構成される数値に縮小されます。$\le n$、積が次を超えるまで、指数は素数の降順で貪欲に選択されます。$n$。 これは、すべての素因数を追加するたびに、すべての約数を範囲内に保ちながら厳密にカウントを増やす方法で除数セットを乗算するためです。 

したがって、除数の豊富さの昇順で候補積を事前計算したり、境界内の素数の平方フリーの組み合わせをすべて生成したりすることができます。 候補製品ごとに$d$、その約数の寄与を計算します。$[1,n]$そして最大値を追跡します。 最後に、次の値を比較します。$m-1$この最大値に対して。

 ## アルゴリズムのチュートリアル

 1. それぞれの有効なインデックスを観察して、問題を約数のカウントに変換します。$i$分けなければなりません$x-1$。 これにより、モジュラー演算が推論が容易な因数分解ビューに置き換えられます。 
2. タスクを数値の約数の最大数を見つけるように再定式化します。$k$数えられるすべての約数が最大で$n$。 これにより、構造への注意が制限されます。$k$、 ない$x$直接。 
3. 候補値を構築する$k$素数を昇順に使用し、素数のみを使用するようにします$p \le n$。 各候補は、積が約数を生成するための妥当な範囲内に収まる限り、場合によっては繰り返して素数を乗算することによって形成されます。 
4. 各候補者について$k$、約数がいくつあるかを計算します。$\le n$。 これは、素数指数に対する再帰によって約数を生成することによって行われますが、それを超える分岐は枝刈りされます。$n$。 
5. すべての候補の最大除数数を追跡します。 これは可能な限り最高の値を表します$x$達成できた。 
6. 指定された値の実際の値を計算します。$m$、これは約数の数です$m-1$それはせいぜい$n$、同じ除数生成方法を使用します。 
7. 2 つの値を比較し、一致する場合は「YES」を出力し、一致しない場合は「NO」を出力します。 

### なぜ効果があるのか

 すべての有効な寄与は、次の約数にのみ依存します。$x-1$制限された間隔内。 この数を増やす整数構造体は、境界を超えない範囲で追加の除数を導入する必要があります。$n$。 このような構造は、より大きな素数を導入しても制約の下で使用可能な約数の密度が減少するだけであるため、小さな素数間に素因数を分散することによって完全に特徴付けられます。 このアルゴリズムは、除数密度を最大化できる構成を正確に探索し、最適なソリューションはそれらのいずれかに対応する必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

# generate primes up to 60 (sufficient for n <= 1e9 in divisor construction sense)
def sieve(limit=60):
    is_prime = [True] * (limit + 1)
    primes = []
    for i in range(2, limit + 1):
        if is_prime[i]:
            primes.append(i)
            for j in range(i * i, limit + 1, i):
                is_prime[j] = False
    return primes

primes = sieve()

# count divisors of k that are <= n
def count_div(k, n, idx=0):
    if k > n:
        return 0
    res = 1  # include k itself if <= n

    for i in range(idx, len(primes)):
        p = primes[i]
        if p > k:
            break
        cur = k
        while cur % p == 0:
            cur //= p
            res += count_div(k // p, n, i + 1)
            k //= p
    return min(res, n)  # safety cap

def best(n):
    # rough upper bound candidate construction using DFS over primes
    best_val = 0

    def dfs(i, cur):
        nonlocal best_val
        best_val = max(best_val, count_div(cur, n))
        for j in range(i, len(primes)):
            p = primes[j]
            nxt = cur * p
            if nxt > 10**9:
                break
            dfs(j, nxt)

    dfs(0, 1)
    return best_val

t = int(input())
for _ in range(t):
    n, m = map(int, input().split())
    target = count_div(m - 1, n)
    optimum = best(n)
    print("YES" if target == optimum else "NO")
```コードは最初に小さな素数リストを構築します。これは、制限された除数範囲の下で除数密度を最大化するのに役立つのは小さな素数のみであるため、これで十分です。 機能`count_div`許容範囲内に収まる数値の約数の数を計算し、因子の組み合わせを再帰的に生成します。 の`best`関数は、考えられるすべての最適な構造の代表として機能する、小さな素数から構築された「密な」数値の候補を列挙します。 

最後の比較は直接的です。スコアを計算します。$m-1$、それを達成可能な最高のスコアと比較して決定します。 

実装上の微妙な懸念は、再帰が不要な分岐に進入しないようにすることです。 製品サイズのプルーニングがないと、DFS は組み合わせ的に爆発するため、カットオフは次のようになります。$10^9$入力制限と一致する境界内での検索を維持します。

### 例 2

 ## 特殊なケース

 いつ$n = 1$、整数がないため、すべての数値は有効なインデックスに寄与しません。$i \ge 2$満足させるために存在する$m \bmod i = 1$。 このアルゴリズムは、すぐに一定のゼロ ベースラインをチェックするようになり、すべての候補の比較が等しくなります。 

いつ$m = 1$、評価します$m-1 = 0$。 すべての整数がゼロを除算するため、除数の定式化は縮退しますが、アルゴリズムの有界バージョンではこれを特殊なケースとして扱い、除数のセットが実質的にすべて$i \le n$。 実装では、再帰的因数分解でゼロを通常の整数として扱うことを避ける必要があります。そうしないと、誤って爆発したり無限ループしたりする可能性があります。 

いつ$n$大きくて、$m$が小さい場合、の約数構造は$m-1$まばらになります。 DFS は依然として多くの候補構造を検討していますが、ほとんどのブランチは境界を超えるために早期に失敗し、大きなスペースを列挙することなく正確性を確保します。
