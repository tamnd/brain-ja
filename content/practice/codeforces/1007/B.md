 ## 解決策
 ## 問題の理解

 辺の長さを指定した固定の長方形のボックスが与えられます。$A, B, C$。 異なるトリプルが何個あるかを数えたい$(a,b,c)$、そのように注文しました$a \le b \le c$は、すべてのコピーが同じ方向で使用される場合、この小さなボックスのコピーが大きなボックスに正確にタイル表示されるようにするための構成要素として機能します。 

重要な幾何学的制約は、小さなボックスの各辺が大きなボックスの 1 つの軸と一貫して位置合わせされている場合にのみタイリングが可能であるということです。$(a,b,c)$大きなボックスの対応する寸法を剰余なく除算する必要があります。 個々のタイルを個別に回転することはできませんが、大きなボックスに対する小さなボックスの全体的な配置を選択することはできます。 

タスクは、異なる非減少トリプルの数を数えることです。$(a,b,c)$このタイリング条件を満たします。 

入力は最大で構成されます$10^5$テスト ケース、各テスト ケースのディメンションは最大$10^5$。 これにより、すべてのトリプルを直接列挙するソリューションは除外されます。 各数値のすべての約数を個別に列挙し、すべての組み合わせを試しても、注意深く構成せずにテスト ケースごとに単純に実行すると、非常に遅くなります。これは、完全なクロス積推論では、最悪の場合の約数と組み合わせが爆発する可能性があるためです。 

一般的な失敗例は、正確さに影響を与えることなく、任意の 3 倍の約数を軸間で任意に並べ替えることができるとソリューションが想定している場合に発生します。 たとえば、立方体では$2 \times 2 \times 2$、トリプル$(1,1,2)$機能しますが、軸に値を誤って割り当てると、順列の処理方法によっては、値が誤って拒否されたり、二重にカウントされたりする可能性があります。 すべての次元が等しい場合、別の微妙な問題が発生します。 軸の割り当てが正規化されていない場合、対称構成は過大にカウントされる傾向があります。 

中心的な困難は、有効な約数を見つけることではなく、順序制約と軸の位置合わせの一貫性の下で、それらの構造化された組み合わせを数えることです。 

## アプローチ

 直接的なアプローチでは、すべての候補トリプルを列挙します。$(a,b,c)$まで$\min(A,B,C)$、それぞれが有効な方向でディメンションを分割しているかどうかを確認し、機能するものを数えます。 これは原理的には正しいですが、遅すぎます。 トリプルまでの数$10^5$の順序です$10^{15}$、これを実行不可能にします。 

構造を単純化するための重要な点は、ジオメトリをカウントから分離することです。 固定軸の割り当ての場合、次のように決定したとします。$a$一つの次元に一致し、$b$もう一人と、そして$c$最後の場合、妥当性条件は純粋に割り算制約になります。$$a \mid A,\quad b \mid B,\quad c \mid C.$$これにより、問題は各次元から 1 つの約数を選択して強制することになります。$a \le b \le c$。 

この解釈を修正すると、問題は単調制約を使用して 3 つの約数セットから抽出された順序付きトリプルを数えることになります。 この構造により、トリプル列挙をプレフィックスカウントに置き換えることができます。 

各次元の約数を計算し、並べ替えてから、トリプルを数えます。$(a,b,c)$満足のいく$a \le b \le c$中央の要素上でスイープを使用する$b$。 それぞれについて$b$、有効な数を数えます$a$は$\le b$そして有効な数はいくつですか$c$は$\ge b$、次に乗算します。 

これにより、3 次の組み合わせが除数の数を超えて線形に近いものに変換されます。

 ## アルゴリズムのチュートリアル

 1. 次のようにディメンションを並べ替えます。$A \le B \le C$。 

これにより、カウントの方向が一貫して固定され、軸の並べ替えによる曖昧さが回避されます。 
2. すべての約数を計算します。$A$、$B$、 そして$C$、ソートされた配列に格納します$D_A, D_B, D_C$。 

これらは、小さなボックスがその軸に沿っている場合に、その各辺が取り得るすべての値を表します。 
3. 各約数について$b \in D_B$、要素の数を数えます$a \in D_A$満足する$a \le b$。 

これにより、最初の 2 つの次元間の順序制約が保証されます。 
4. 同じように$b$、要素の数を数えます$c \in D_C$満足する$c \ge b$。 

これにより、強制的に$b \le c$。 
5. これら 2 つのカウントを乗算し、累積して答えを求めます。 

それぞれの有効な選択肢のペア$a$そして$c$固定中間値と組み合わせる$b$有効な非減少トリプルを形成します。 
6. 最終的な累積合計を出力します。 

### なぜ効果があるのか

 軸が固定され順序付けされると、有効なタイリングはすべて、選択した約数に正確に対応します。$a,b,c$それぞれが割り当てられた次元を分割し、順序付けの制約が維持されるようにします。 割り算制約は軸ごとに独立していますが、順序制約は隣接する選択肢を結合するだけです。 中間の値に固定することにより$b$では、制約を 2 つの独立したプレフィックス条件に分解します。これにより、すべてのトリプルの明示的な列挙を回避しながら正確性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def divisors(x):
    small = []
    large = []
    i = 1
    while i * i <= x:
        if x % i == 0:
            small.append(i)
            if i * i != x:
                large.append(x // i)
        i += 1
    return small + large[::-1]

def solve():
    t = int(input())
    for _ in range(t):
        A, B, C = map(int, input().split())
        A, B, C = sorted((A, B, C))

        DA = divisors(A)
        DB = divisors(B)
        DC = divisors(C)

        DA.sort()
        DB.sort()
        DC.sort()

        # prefix counts for DA
        ans = 0

        # two pointers for DA and DC
        i = 0
        k = 0
        nA = len(DA)
        nC = len(DC)

        for b in DB:
            while i < nA and DA[i] <= b:
                i += 1
            while k < nC and DC[k] < b:
                k += 1

            cntA = i
            cntC = nC - k
            ans += cntA * cntC

        print(ans)

if __name__ == "__main__":
    solve()
```コードは、ディメンションが並べ替えられるように各テスト ケースを正規化することから始まります。 これにより、最小の次元を一貫して次の次元とペアになったものとして扱うことができます。$a$、真ん中に$b$、そして最大のものは$c$。 

除数生成関数は以下で実行されます。$O(\sqrt{n})$、冗長な作業を行わずに効率的に約数のペアを収集します。 最小のオーバーヘッドでソート順序を維持するために、大小の約数を分割します。 

各テスト ケース内で、次のすべての約数を繰り返します。$B$、これは中間値として機能します。 2 つのポインターは、約数の数を維持します。$A$は現在次のように有効です$a \le b$、および約数はいくつあるか$C$満足する$c \ge b$。 どちらのポインター スキャンも前方にのみ進むため、総コストは除数の数において線形のままです。 

微妙な点は、ポインタを決してリセットしないことです。$b$, これは効率化のために不可欠です。 リセットすると、除数の数が 2 次まで複雑さが増加します。

 次のような完全に対称なボックス$1 \times 1 \times 1$実装が単一要素の除数セットを正しく処理するかどうかを明らかにします。 この場合、各約数リストには、$[1]$したがって、アルゴリズムは 1 回の反復を実行し、正確に 1 つの構成を返します。
