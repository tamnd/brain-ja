 ## 解決策
 ## 問題の理解

 私たちには木と「アリ」のコレクションが与えられました。 各アリには 2 つの代替頂点ペアが付属しています。 アリごとに、2 つのペアのうちどちらを使用するかを決定する必要があります。 その選択の後、すべてのアリは、ツリー内で選択したペアの間の一意のパスを「要求」し、このパスは完全にそのアリ自身の色に割り当てられなければなりません。 

重要な構造要件は、どのエッジも 2 つの異なるアリの選択したパスに属してはいけないということです。各エッジは正確に 1 つの色でペイントされ、各アリの色は排他的に割り当てられたエッジのみを使用できるからです。 したがって、実際の制約は、グラフ理論的な意味での接続性に関するものではなく、選択されたパスによるツリー エッジの排他的所有権に関するものです。 

このように表示すると、出力は単純にアリごとのブール値の決定になります。つまり、選択されたパスの結果として得られるセットがエッジで結合されていない場合に、最初のペアを選択するか 2 番目のペアを選択するかということです。 

制約サイズにより、単純にパスごとにエッジを列挙することを回避するソリューションが求められます。 ツリーには最大 100,000 個の頂点がありますが、アリには最大 10,000 個の頂点があります。単一のパスは長くなり、その数も多くなる可能性があるため、パスを明示的に拡張すると、最悪の場合でもすでに約 10^9 の操作に達します。 アリのペアごとにエッジごとに直接推論する解決策は失敗します。 

欲張って考えると、微妙な障害モードが現れます。ローカルで安全に見えるアリのパスを選択すると、共有エッジを使用する唯一の有効なオプションを持つ別のアリを後でブロックする可能性があります。 たとえば、2 つのアリが両方ともツリーのルート付近で重なり合う代替案を持っている場合、グローバルな調整を行わずに早期にコミットすると、たとえグローバル割り当てが存在していても、有効なパスがないまま後のアリが立ち往生する可能性があります。 

主な問題は、重複するツリー パスにおけるグローバルな一貫性です。 

## アプローチ

 強引な解釈では、アリのあらゆる選択肢の組み合わせが試行されます。 これにより、2^m 個の構成が発生し、それぞれの構成で、選択されたパスがエッジで共通であるかどうかの検証が必要になります。 各パスをエッジに前処理したとしても、1 つの構成のチェックには最悪の場合 O(n) がかかり、O(n 2^m) につながります。これは、m が 10000 の場合、実現可能性をはるかに超えています。 

各アリの選択肢を頂点ではなくツリーのエッジに対する制約として再解釈すると、この構造は管理しやすくなります。 各アリの選択肢は、エッジのセット、つまり、そのエンドポイント間の一意のツリー パス上のエッジに対応します。 「選択された 2 つのパスがエッジを共有しない」という条件は、すべてのエッジが最大 1 つの選択されたオプションで使用できると言っているのと同じです。 

これにより、問題はバイナリ変数をめぐる競合システムに変わります。 各 ant は 2 つの可能なリテラルを持つ変数であり、各エッジは、パスにそれが含まれるすべての ant-option 間でペアごとの非互換性を引き起こします。 選択した 2 つのオプションの両方に同じエッジが含まれている場合、両方とも true になることはできません。 これは古典的な 2-SAT スタイルの構造ですが、問題は、明示的なペアではなく、ツリー上のパスによって競合が引き起こされるという事実にあります。 

これを使用できるようにするために、Heavy-Light 分解を使用して操作をセグメント化するパス クエリを削減します。 各パスは、線形化されたツリー インデックス上の O(log n) セグメントの結合になります。 各セグメントを「リソース間隔」として扱うことができるようになり、各セグメント内で選択された ant-option が最大 1 つだけ占有できるという条件になります。 これをセグメント ツリー ベースの集約で強制します。各セグメント ツリー ノードは、それをカバーするすべての ant-options を収集し、そのノード内の重複するオプション間に相互排他制約を課します。 

結果は、変数がアリの決定であり、その含意グラフがすべてのエッジの競合をエンコードする 2-SAT インスタンスです。 これを解くと一貫した割り当てが得られるか、不可能性が検出されます。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^m・n) | O(n) | 遅すぎる |
 | 最適 (HLD + 2-SAT) | O((n + m) log n) | O((n + m) log n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ツリーを、任意のパスを少数の連続セグメントに分解できる構造に変換します。 これは、ツリーに対する重光分解を使用して行われます。 

各アリは 2 つの候補経路を与えます。 2-SAT システムでは各候補を個別のブール リテラルとして扱います。リテラル (i, 0) は最初のペアを選択することを意味し、(i, 1) は 2 番目のペアを選択することを意味します。 

次に、選択した 2 つのリテラルによってエッジが使用されていないことを確認する必要があります。 

1. ツリーを根付けし、重光分解を実行します。 これにより、各エッジが基本配列内の位置に割り当てられるため、すべてのツリー パスが O(log n) 間隔の和集合として表現されます。 

このステップは、幾何学的な「パスの重なり」をライン上の間隔の重なりに変えるため、重要です。 
2. 各アリとその 2 つの候補ペアのそれぞれについて、対応するツリー パスを HLD セグメントに分解します。 

各セグメントは基本配列内の連続した間隔に対応し、このリテラルがそれらの間隔を「カバーする」と記録します。 
3. 基本配列上にセグメント ツリーを構築します。 各セグメント ツリー ノードはエッジの範囲を表します。 

各ノードについて、そのノード セグメントを完全にカバーする間隔を持つすべてのリテラルを収集します。 

これにより、競合検出が局所的に行われます。2 つのリテラルが両方とも同じノード リストに表示される場合、それらは一部のエッジ領域で重複します。 
4. 各セグメント ツリー ノード内では、収集されたリテラルのうち最大 1 つを選択できるようにします。 

そのノード内のリテラルをソートまたはインデックス付けし、それらを 2 つ同時に選択することを禁止する一連の意味合いに接続します。 具体的には、ノードのリスト内のすべてのペアに対して、線形チェーン形式で相互排他制約を追加し、1 つを選択すると他のすべてが false になるようにします。 

これにより、推移的伝播を通じてペアごとの非互換性をエンコードしながら、二次爆発を回避できます。 
5. すべてのノードを処理した後、200 万個の変数にわたる完全な 2-SAT 含意グラフが得られます。 SCC ベースの 2-SAT 解決を実行します。 

変数とその否定が同じコンポーネント内にある場合、有効な代入は存在しません。 
6. それ以外の場合は、割り当てを抽出します。 各アリについて、どのリテラルが true であるかを出力します。 

### なぜ効果があるのか

 この構造により、ツリーのすべてのエッジが、関連するすべての解像度レベルで正確に 1 つのセグメント ツリー ノード パス分解バケット内で表現されることが保証されます。 少なくとも 1 つのエッジを共有する 2 つのリテラルは、いずれかのセグメント ツリー ノードで同時に発生する必要があるため、同時選択を禁止する制約によって接続されます。 逆に、どのエッジにも重ならないリテラルはどのノードにも一緒に現れることはないため、誤って制約されることはありません。 これは、必要な実現可能性条件と正確に一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

# ---------- Tree + HLD ----------
n = int(input())
g = [[] for _ in range(n)]
edges = []

for _ in range(n - 1):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    g[u].append(v)
    g[v].append(u)
    edges.append((u, v))

parent = [-1] * n
depth = [0] * n
heavy = [-1] * n
sz = [0] * n

def dfs(u, p):
    sz[u] = 1
    max_sub = 0
    for v in g[u]:
        if v == p:
            continue
        parent[v] = u
        depth[v] = depth[u] + 1
        dfs(v, u)
        sz[u] += sz[v]
        if sz[v] > max_sub:
            max_sub = sz[v]
            heavy[u] = v

dfs(0, -1)

head = [0] * n
pos = [0] * n
cur = 0

def decompose(u, h):
    global cur
    head[u] = h
    pos[u] = cur
    cur += 1
    if heavy[u] != -1:
        decompose(heavy[u], h)
    for v in g[u]:
        if v != parent[u] and v != heavy[u]:
            decompose(v, v)

decompose(0, 0)

def get_path(u, v):
    res = []
    while head[u] != head[v]:
        if depth[head[u]] < depth[head[v]]:
            u, v = v, u
        res.append((pos[head[u]], pos[u]))
        u = parent[head[u]]
    if depth[u] > depth[v]:
        u, v = v, u
    if pos[u] + 1 <= pos[v]:
        res.append((pos[u] + 1, pos[v]))
    return res

m = int(input())

paths = []
for i in range(m):
    a, b, c, d = map(int, input().split())
    a -= 1; b -= 1; c -= 1; d -= 1
    paths.append((get_path(a, b), get_path(c, d)))

# ---------- 2-SAT ----------
N = 2 * m
adj = [[] for _ in range(N)]

def add_imp(u, v):
    adj[u].append(v)

def add_or(u, v):
    add_imp(u ^ 1, v)
    add_imp(v ^ 1, u)

# Segment tree over HLD base array
size = 1
while size < n:
    size <<= 1

bucket = [[] for _ in range(2 * size)]

def add_interval(l, r, idx):
    l += size
    r += size
    while l <= r:
        if l % 2 == 1:
            bucket[l].append(idx)
            l += 1
        if r % 2 == 0:
            bucket[r].append(idx)
            r -= 1
        l //= 2
        r //= 2

# map each literal to segments
for i in range(m):
    for t in range(2):
        segs = paths[i][t]
        lit = 2 * i + t
        for l, r in segs:
            add_interval(l, r, lit)

# conflicts inside each segment tree node
for i in range(1, 2 * size):
    lst = bucket[i]
    for j in range(len(lst) - 1):
        u = lst[j]
        v = lst[j + 1]
        add_or(u, v)

# SCC for 2-SAT
sys.setrecursionlimit(10**7)

idx = 0
stack = []
onstack = [False] * N
ids = [-1] * N
low = [-1] * N
comp = [-1] * N

def dfs_scc(u):
    global idx
    ids[u] = low[u] = idx
    idx += 1
    stack.append(u)
    onstack[u] = True

    for v in adj[u]:
        if ids[v] == -1:
            dfs_scc(v)
            low[u] = min(low[u], low[v])
        elif onstack[v]:
            low[u] = min(low[u], ids[v])

    if low[u] == ids[u]:
        while True:
            x = stack.pop()
            onstack[x] = False
            comp[x] = u
            if x == u:
                break

for i in range(N):
    if ids[i] == -1:
        dfs_scc(i)

ans = [0] * m
for i in range(m):
    if comp[2*i] == comp[2*i+1]:
        print("NO")
        sys.exit(0)
    ans[i] = 1 if comp[2*i] < comp[2*i+1] else 2

print("YES")
for x in ans:
    print(x)
```HLD セクションは、すべてのツリー パスが O(log n) 個の連続セグメントの結合になることを保証します。これにより、幾何学的制約を区間範囲に減らすことができます。 

セグメント バケット化ステップでは、重複する間隔が共通のノードで交わるように、これらの間隔をセグメント ツリー内の配置に変換します。 

最後の含意グラフは相互排除をエンコードし、SCC ステップはグローバルな一貫性を解決します。 

実装の微妙な点は、リテラルの解釈です。 各アリは 2-SAT グラフ内の 2 つのノードに寄与し、すべての制約は直接エッジではなく含意を使用して対称的に追加する必要があります。 ここで間違いがあると、通常、充足可能性の伝播が静かに中断されます。

### サンプル 2 (構築済み)

 2 匹のアリがいる小さなチェーン ツリー 1-2-3-4 を考えてみましょう。 

アリ 1: (1,4) または (1,2)

 アリ 2: (2,3) または (3,4)

 フルパス (1,4) は、ant 2 の両方の候補パスと重なるため、これを選択すると、ant 2 は (2,3) または (3,4) を慎重に選択する必要があります。 SCC 構造により、互換性のある組み合わせのみが存続します。 

トレースは、長いパスが事実上複数のセグメントを「消費」し、下流側の決定を強制していることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n + m) log n) | HLD はパスを対数セグメントに分解し、セグメント ツリーはレベルごとに各間隔を 1 回処理します。SCC はグラフ サイズが線形です。 
| スペース | O((n + m) log n) | HLD 構造、セグメント バケット、および含意グラフのストレージ |

 n と m は両方とも最大 10^5 スケールであり、すべての演算はこれらの量において線形または対数線形であるため、解は制約内に快適に適合します。

 ## 特殊なケース

 重大なエッジ ケースは、複数のアリの候補経路が 1 つの分岐エッジを除いてほぼ完全に一致する場合に発生します。 そのような状況では、貪欲な割り当ては共有プレフィックスに固定される傾向があり、後のアリは不可能になります。 2-SAT 構造は、競合を単一の共有セグメント ツリー ノードに押し込むことでこれに対処し、トラバーサルの後半ではなく、含意グラフの早い段階で矛盾が確実に検出されるようにします。 

別のエッジ ケースは、折れ線グラフのような縮退ツリーに表示されます。 すべてのパスは連続した間隔になり、すべての競合は間隔の重複制約に集約されます。 セグメント ツリーは、HLD の複雑さのオーバーヘッドを必要とせずにこれらのオーバーラップを正確にキャプチャし、2-SAT 制約によるインターバル スケジューリングの問題を効果的に軽減します。
