 ## 解決策
 ## 問題の理解

 数値の配列が与えられ、それらを自由に並べ替えることができます。 再配置後、新しい配列を元の配列と位置ごとに比較します。 順列後にその位置に配置された値が、その位置に元々あった値よりも厳密に大きい場合、その位置は「良好」であるとみなされます。 

課題は、そのような適切なポジションの数を最大化する順列を選択することです。 言い換えれば、すべての要素を 1 回だけ使用しながら、できるだけ多くの位置が以前より厳密に大きな値を受け取るように要素を一致させたいと考えています。 

制約$n \le 10^5$すべての順列を試行するアプローチは直ちに除外されます。$n!$実現可能な限界をはるかに超えて成長します。 平$O(n^2)$このサイズでは Python では解が限界ギリギリで遅すぎるため、解は本質的に線形であるか、または$n \log n$。 

素朴な間違いは、位置ごとに、より大きな未使用の要素を常に見つけることができるとローカルに考えることです。 大きな要素が早期に「無駄」になると、これは失敗します。 

たとえば、次の配列を考えてみましょう。```
[1, 2, 3, 100, 101]
```注意せずに最も大きな要素を最も小さな位置に貪欲に割り当てると、100 と 101 を使用するのが早すぎて、中間の位置に有効な改善が残らない可能性があります。 正解は、ローカル ペアリングではなく、グローバル マッチングに依存します。 

もう 1 つの微妙な失敗例は、重複が優勢な場合です。```
[5, 5, 5, 1, 1]
```大きな値が存在する場合でも、それらが割り当てられると、厳密に改善される一致の数は、元の構造に存在する厳密に小さい値の数によって制限されます。 

主な困難は、厳密な不等式制約の下で配列の 2 つのコピーを効果的に照合していることです。 

## アプローチ

 ブルートフォース手法では、すべての順列を生成し、元の配列と比較してどれだけの位置が改善されるかをカウントします。 各順列について、元の配列と要素ごとに比較し、コストを計算します。$O(n)$順列ごとに。 あるので$n!$順列すると、これは次のようになります$O(n \cdot n!)$、これはたとえ$n = 10$。 

問題の構造は、一致する解釈を示唆しています。 次のように、元の値と並べ替えられた値をペアにしたいと考えています。$b[i] > a[i]$できるだけ多くのインデックスについて、$b$の順列です$a$。 これは、ソートされたマルチセットでの 2 部マッチングの問題です。 

配列がソートされたら、わずかに小さい元の要素を上回る、可能な限り最小の「勝ち」要素を割り当てるという観点から考えることができます。 貪欲なアイデアが明らかになります。利用可能な最小のより大きな値を使用して、残っている最小の元の値を常に破ろうとすれば、すでに簡単な一致で大量の数値を無駄にすることを避けられます。 

これは、ソートされた配列に対する古典的な 2 ポインター戦略です。 配列をソートし、大きい要素をもう一方の端の小さい要素に一致させようとします。ポインタを慎重に進めて、成功する厳密な不等式を最大化します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n \cdot n!)$|$O(n)$| 遅すぎる |
 | 最適 (ソート + 貪欲なマッチング) |$O(n \log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは、配列の要素をそれ自体の並べ替えられたコピーと照合するという問題として再解釈します。 

1. 配列を降順でない順に並べ替えます。 これにより、比較が予測可能になり、貪欲な選択が安全になる構造化されたビューが得られます。 
2. 2 つのポインターを使用します: 1 つのポインター`i`打ち負かしたい「小さい側」を表し、もう 1 つのポインターを表します。`j`それに勝てる候補者を代表する。 
3.初期化`i = 0`そして`j = 0`、カウンターを維持します`ans = 0`。 
4. 配列内を移動して、一致するものを見つけます。 もし`a[j] > a[i]`、成功したペアを形成できるので、インクリメントします。`ans`、両方のポインタを進めます。 これは、一致しない現在の最小値を超えるために、厳密に大きな値を割り当てることを表します。 
5. もし`a[j] <= a[i]`、 それから`a[j]`殴るのには役に立たない`a[i]`、だから前進するだけです`j`。 これにより、このターゲットの一致の増加に寄与できない値がスキップされます。 
6. いずれかのポインタが配列の末尾に到達するまで続行します。 

このプロセスにより、成功したすべての一致が有効であり、潜在的な改善が途中でスキップされないことが保証されます。 

### なぜ効果があるのか

 並べ替え後の有効な割り当ては、大きい要素と小さい要素のペアに対応します。 貪欲な戦略は常に、勝つことができる最小の「勝者」と最小の「敗者」を一致させます。 値が現在残っている最小のターゲットに勝てない場合、それ以降の (より大きな) ターゲットにも勝てないため、値をスキップしても最適性は低下しません。 これにより、残りの要素に対して最大限の柔軟性が維持されるという意味で、成功した各ペアが不可逆的に最適になる単調なマッチング プロセスが作成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    a.sort()
    
    i = 0
    j = 0
    ans = 0
    
    while i < n and j < n:
        if a[j] > a[i]:
            ans += 1
            i += 1
            j += 1
        else:
            j += 1
    
    print(ans)

if __name__ == "__main__":
    solve()
```ソートステップは、問題を単調なマッチングタスクに変えるため、不可欠です。 並べ替えがなければ、「機能する最小の要素を使用する」という貪欲なルールが適切に定義されなくなります。 

2 ポインタ ループは明確な分離を維持します: ポインタ`i`まだ克服する必要がある次に小さい要素を追跡します。`j`厳密にそれより大きい候補を検索します。 条件`a[j] > a[i]`問題の要件を正確に満たして厳密な改善を保証します。 

重要な微妙な点は、`i`一致するものが見つかった場合にのみ先に進みます。 これにより、成功したすべてのインクリメントが一意のペアに対応し、要素が再利用されないことが保証されます。

 ## 特殊なケース

 次のような単一要素配列の場合`[7]`、ソートされた配列は残ります`[7]`。 ポインタ`j`より厳密に大きい値は見つかりません`i = 0`したがって、増分は発生せず、出力は 0 のままになります。 

次のような一様な配列の場合`[2, 2, 2, 2]`、すべての比較は厳密な不等式チェックに合格しないため、アルゴリズムは前進するだけです`j`、決して増加しない`ans`。 これは、すべての値が同じである場合、ポジションを改善することが不可能であることを直接反映しています。
