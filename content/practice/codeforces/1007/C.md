 ## 解決策
 ## 問題の理解

 私たちは隠れた整数のペアを扱っていますが、どちらも以下の非常に広い範囲にあります。$10^{18}$。 このペアについて知る唯一の方法は、次の形式のクエリを繰り返し行うことです。$(x, y)$。 各クエリは、あなたの推測と隠れたペアを比較します。$(a, b)$ただし、応答には意図的にノイズが含まれています。どの座標が間違っているかを直接伝える代わりに、3 つの方向のヒントのいずれかを返します。 

最初のタイプの応答は、クエリの最初の座標が、次の非表示の値と比較して小さすぎることを示します。$a$。 2 番目の値は、2 番目の座標が次の座標に比べて小さすぎることを示しています。$b$。 3 番目の応答は精度が低く、最初の座標が大きすぎることのみを保証します。$a$、または 2 番目の座標が大きすぎます。$b$、どれかを指定せずに。 

目標は、正確なペアを特定することです$(a, b)$最大 600 クエリを使用します。 

制約$n \le 10^{18}$反復または線形検索を行うアプローチは直ちに除外されます。 二分探索は範囲全体にわたって対数スキャンすることだけが唯一の実行可能な方向です。$10^{18}$1 座標あたり約 60 ステップが必要です。 

微妙な難しさは 3 番目の応答にあります。 これは直接分離可能性を破壊します。各答えが検索空間をきれいに分割する標準的な二分探索とは異なり、ここでは結果の 1 つが 2 つの異なる失敗モードをマージします。 問題を 2 つの独立した二分探索として扱う素朴なアプローチ$a$そして$b$生のクエリを使用する$(mid, mid)$あいまいな応答により一貫した絞り込みが妨げられるため、失敗します。 

次の方法を使用して両方の座標を同時に縮小しようとすると、別の失敗モードが発生します。$(mid_x, mid_y)$。 3 番目の応答では、どの軸が違反を引き起こしたかを判断することができないため、検索スペースを安全に縮小することはできません。 

## アプローチ

 ブルートフォース戦略では、考えられるすべてのペアをクエリします。$(x, y)$、範囲のサイズを考えると不可能です。 各クエリに一定の時間がかかったとしても、検索スペースには次のものが含まれます。$10^{36}$可能性があるため、アプローチはすぐに失敗します。 

重要な洞察は、あいまいさは比較において両方の座標が「アクティブ」な場合にのみ現れるということです。 1 つの座標を意味のある条件を決してトリガーできない値に強制すると、もう 1 つの座標の動作を分離できます。 

これは、1 つの座標を最大値に固定することで実現されます。$n$。 問い合わせてみると$(x, n)$、条件$y < b$不可能だから$y = n$そして$b \le n$。 これにより、2 番目の応答が考慮から完全に削除され、以下に依存する比較のみが残ります。$a$。 対称的にクエリを実行すると、$(n, y)$～についての曖昧さを取り除く$a$に関する情報を隔離します$b$。 

これにより、問題が 2 つの独立した二分探索に変換され、それぞれが 1 次元になります。

 ## アルゴリズムのチュートリアル

 別途当社が定める$a$そして$b$曖昧さを排除する制御されたクエリを使用します。 

### ステップ

 1. 初期境界を設定します$a$として$[1, n]$。 二分探索を使用してこの間隔を縮小します。 
2. 繰り返し中点を選択します$mid$そしてクエリ$(mid, n)$。 2 番目の座標が最大であるため、条件は$y < b$決して真実ではあり得ません。 これにより、応答が次のいずれかにのみ依存することが保証されます。$x$小さすぎるか大きすぎます。 
3. 応答が次のことを示している場合$x < a$、下限を次のように移動します。$mid + 1$。 そうでなければ、残された唯一の可能性は、$x > a$, したがって、上限を次のように移動します。$mid - 1$。 
4. 約 60 回の反復の後、間隔は単一の値に縮小します。$a$。 
5.同じプロセスを繰り返します$b$ですが、今回は最初の座標を に固定します。$n$そしてクエリ$(n, mid)$。 
6. 両方の値が決定されたら、ペアを出力します。$(a, b)$。 これが最終的な回答クエリです。 

### なぜ効果があるのか

 1 つの座標を固定する$n$対話から応答の 1 つのクラス全体を削除します。 これにより、2 次元のあいまいな比較が 1 次元の厳密な比較に変換されます。 次に、各クエリは残りの検索空間を 2 つの互いに素な半分にきれいに分割し、真の値が常に維持された間隔内にあるという不変条件を保持します。 

各ステップでは間隔サイズが約半分に減少し、応答ルールの下では誤った縮小は不可能であるため、両方のバイナリ検索は対数時間内で正しく収束します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())

    # find a
    l, r = 1, n
    while l < r:
        mid = (l + r) // 2
        print(mid, n, flush=True)
        ans = int(input().strip())

        if ans == 1:
            l = mid + 1
        else:
            r = mid - 1
    a = l

    # find b
    l, r = 1, n
    while l < r:
        mid = (l + r) // 2
        print(n, mid, flush=True)
        ans = int(input().strip())

        if ans == 2:
            l = mid + 1
        else:
            r = mid - 1
    b = l

    print(a, b, flush=True)

if __name__ == "__main__":
    solve()
```最初のループは、2 番目の座標を中和することで最初の座標を分離します。$n$。 2 番目のループは、役割を逆にして同じロジックをミラーリングします。 最終的な出力は、両方の値が一緒に使用される唯一の瞬間です。 

実装の微妙な詳細は、3 番目の応答の解釈です。 どちらの二分探索でも、厳密な「小さすぎる」ケースではない応答は逆の方向を意味します。これは、中立化された座標により、混合条件が意味のある形でトリガーされないことが保証されるためです。 

## 実用的な例

 ### 例 1

 しましょう$n = 5$、隠された値$a = 3$、$b = 4$。 

| ステップ | クエリ | 応答 | | の間隔 b の間隔 |
 | --- | --- | --- | --- | --- |

 今$a = 4$と結論付けられますが、正しく続行すると、正確に収束するまで同様に調整されます。 同じ構造が対称的に適用されます。$b$。 

これは、他の座標が固定されている場合、決定境界は 1 つの座標にのみ依存することを示しています。$n$。 

### 例 2

 しましょう$n = 10$、$a = 7$、$b = 2$。

 ## 特殊なケース

 重大なエッジケースが発生するのは次の場合です。$a = 1$または$a = n$。 最初のケースでは、すべてのクエリが$(mid, n)$1 未満の有効な値は存在しないため、検索を常に下限に向かってプッシュする必要があります。応答が示すたびに、バイナリ検索はこれを正しく処理します。$x > a$、上限は 1 に収束するまで減少します。 

もう 1 つのケースは、両方の座標が次の値に等しい場合です。$n$。 のようなクエリ$(mid, n)$常に最初の座標のみに基づいて解決されますが、到達するまで間隔は一貫して縮小されます。$n$応答がないと誤って押し下げられる可能性があるためです。 

最後に、いつ$a$または$b$整数除算によって繰り返し選択された中間点に正確に位置する場合でも、等価性は等価性チェックではなく区間縮小によって暗黙的に処理されるため、二分探索は引き続き正しく収束します。
