 ## 問題の理解

 このタスクでは、長さを数えるよう求められます。`N`文字だけを使用してシーケンスを作成できます`A`、`B`、 そして`C`, ここで、`B`文字数は最大でも 3 文字です。 この制限を満たす場合、シーケンスは有効な単語とみなされ、有効なシーケンスの合計数を出力するだけで済みます。 

入力には単一の整数が含まれています`N`、単語の必要な長さ。 出力は、その正確な長さの可能な単語の数です。 制約は小さく、`N`最大でも 20 なので、組み合わせ論や小さな動的プログラムを使用したソリューションでも十分に高速です。 すべての単語を総当りで生成することは、依然として悪い選択です。`3^N`可能なシーケンス。 いつ`N = 20`、これは 34 億を超える可能性があり、個別にチェックできる範囲をはるかに超えています。 

主な問題は、答えのサイズではありません。これは、この制約の標準的な整数範囲に問題なく収まるためです。 課題は、文字の数を除いて、すべての文字の正確な位置は気にしないことを認識することです。`B`の文字が表示されます。 すべての単語を個別に扱うと、この構造が無視されます。 

不注意な実装が失敗する可能性がある特殊なケースがいくつかあります。 もし`N = 1`、3 つを超えることはできないため、すべての 1 文字の単語が有効です。`B`文字。 入力の場合:```
1
```正しい出力は次のとおりです。```
3
```0、1、2、または 3 の単語のみを数えるソリューション`B`文字はありますが、残りの位置はすべて独立して指定できることを忘れています。`A`または`C`答えを過小評価するでしょう。 

もう 1 つの境界ケースは次のような場合です。`N = 3`。 長さ 3 の単語には 4 つ以上を含めることはできないため、考えられるすべての単語が有効です。`B`文字。 入力の場合:```
3
```正しい出力は次のとおりです。```
27
```3 つで終わる解決策`B`すべてを考慮せずにキャラクター`3^N`この長さで可能な単語は、より小さい値を生成する可能性があります。 

## アプローチ

 直接的なアプローチは、可能な長さのすべての単語を生成することです。`N`、その数を数えます`B`文字数が 3 文字以下の場合はそのままにしておきます。 これは正しい単語の定義を正確にチェックするためです。 ただし、検討が必要です`3^N`文字列。 のために`N = 20`、つまり 3,486,784,401 人の候補者をチェックすることになりますが、これでは遅すぎます。 

有用な観察は、次のような位置が含まれているということです。`B`制限のある唯一のポジションです。 それを正確に決めたら`k`位置に含まれる`B`、 どこ`k`が 0 ～ 3 の場合、残りのすべての位置には独立して次のいずれかを含めることができます。`A`または`C`。 

固定値の場合`k`、の位置`B`でキャラクターを選択できます`C(N, k)`方法。 残り`N - k`ポジションにはそれぞれ 2 つの選択肢があるため、貢献します`2^(N-k)`可能性。 これらのケースを追加すると、`k = 0, 1, 2, 3`答えを出します。 

すべての有効な単語が 1 回だけカウントされるため、総当たり法が機能します。 より高速な方法では、同じ数え方の考え方を維持しますが、同じ数の単語をすべてグループ化します。`B`文字を作成する必要がなくなります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(3^N) | O(N) | 遅すぎる |
 | 最適 | O(N) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. の値を読み取ります。`N`。 答えは単語の長さのみに依存するため、個別の文字列を保存または生成する必要はありません。 
2. 考えられるそれぞれの数を検討します。`B`からのキャラクター`0`に`3`。 これより大きな数値は条件に違反するため、答えに影響するのはこれらのケースだけです。 
3. 選択した番号について`k`の`B`文字を配置する方法が何通りあるかを計算します。 これは`C(N, k)`、正確に選択するため`k`範囲外のポジション`N`利用可能なポジション。 
4. これを乗算します`2^(N-k)`。 全部配置したら`B`文字の場合、残りのすべての位置は独立して次のいずれかになります。`A`または`C`。 
5. 4 つのケースすべての寄与を加算して、最終的なカウントを取得します。 

なぜ機能するのか: すべての有効な単語には正確な数字が含まれています`k`の`B`文字であり、その値は次のいずれかである必要があります。`0`、`1`、`2`、 または`3`。 このアルゴリズムは、特定の単語を含むすべての単語をカウントします。`k`を選択することで`B`ポジションを取得し、他のすべてのポジションを次のように埋めます。`A`または`C`。 これらのグループは互いに素であり、すべての有効な単語が一緒に含まれるため、合計がまさに必要な答えとなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    ans = 0
    comb = 1

    for k in range(4):
        if k > 0:
            comb = comb * (n - k + 1) // k
        ans += comb * (1 << (n - k))

    print(ans)

if __name__ == "__main__":
    solve()
```変数`comb`現在の二項係数を保存します`C(N, k)`。 それは次のように始まります`C(N, 0) = 1`。 各反復では、次の関係を使用して更新されます。`C(N, k) = C(N, k-1) * (N-k+1) / k`これにより階乗の計算が回避され、実装が単純になります。 

0 ～ 3 回しか発生しないため、ループは 4 回のみ実行されます。`B`許可されています。 表現`1 << (n - k)`計算する`2^(n-k)`、非の選択肢を表します。`B`ポジション。 

Python の整数は中間値のサイズを自動的に処理するため、オーバーフローの心配はありません。 

## 実用的な例

 入力の場合:```

| k | C(4, k) | エアコンの選択肢 | 貢献 |
 | --- | --- | --- | --- |
 | 0 | 1 | 2^4 = 16 | 16 |

```この例は、アルゴリズムが各単語を構築するのではなく、単語のグループをカウントすることを示しています。

| k | C(3, k) | エアコンの選択肢 | 貢献 |

 ## 特殊なケース

 のために`N = 1`、アルゴリズムは次のように考慮します。`k = 0`そして`k = 1`。 貢献内容は、`2^1 = 2`なしの言葉`B`そして`C(1,1) * 2^0 = 1`1つを含む単語`B`。 最終結果は`3`、言葉と一致する`A`、`B`、 そして`C`。 

のために`N = 3`、アルゴリズムは、可能なすべての分布を合計します。`B`文字。 貢献内容は、`8`、`12`、`6`、 そして`1`、合計`27`。 可能な単語の総数も`3^3 = 27`、これは、この長さでは無効な単語が存在しないことを確認します。 

のために`N = 20`、アルゴリズムは文字列を生成しません。 許容される数ごとに 1 つずつ、合計 4 つの組み合わせのみが評価されます。`B`文字。 計算は小規模のままであり、何十億もの個別のチェックを回避しながら正しいカウントを生成します。
