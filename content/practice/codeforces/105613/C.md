 ## 問題の理解

 未知の整数に関する一連の制約が与えられています$y$。 各制約は値との比較を記述します。$x$, ただし、意味は演算子によって異なります。 いくつかの制約では、$y$厳密にそれより大きいか小さい必要があります$x$、他の人は平等を認めます。 各行は、そのステートメントが真か偽かを示します。 

～について直接推論するのではなく、$y$という値の範囲で考えると簡単です。$y$取ることが許されています。 すべてのステートメントは次のいずれかを制限します$y$あるしきい値より上または下にあること。 「はい」の答えは不等式の方向に有効範囲を狭めますが、「いいえ」の答えは条件を反転して逆の方向に狭めます。 

したがって、タスクは、まだ存在する可能性のあるすべての整数の間隔を維持することになります。$y$。 当初は、$y$任意の整数を指定できますが、各制約を処理するにつれて、この間隔は縮小されます。 最後に、間隔が空でない場合は、その中の任意の整数を出力できます。 それ以外の場合、制約は互いに矛盾します。 

入力サイズは十分小さいため、各制約を 1 回処理するだけで十分です。 最大制限であっても、制約上の線形スキャンは十分に時間制限内であるため、これより悪い解決策はありません。$O(n)$は不要です。 重要な点は、候補を明示的に保存する必要はなく、現在の実行可能な間隔だけを保存する必要があるということです。 

制約に一貫性がないにもかかわらず、最終的に矛盾が明らかになる場合、微妙なエッジ ケースが発生します。 もう 1 つの注意が必要なケースは、厳密な不等式と非厳密な不等式が密接に重なっている場合、たとえば組み合わせた場合に発生します。$y > x$と$y \le x$、これでは整数は不可能になります。 また、センチネル値を使用する場合は、オーバーフローの問題を避けるために、大きな境界を慎重に処理する必要があります。 

## アプローチ

 ブルートフォース解釈では、広範囲の可能なすべての整数が試行されます。$-2 \cdot 10^9$に$2 \cdot 10^9$、すべての制約を満たしているかどうかを確認します。 これは、すべてのクエリに対して有効性を直接テストできるため概念的には機能しますが、最悪の場合は数十億の値を反復処理する必要があり、各チェックですべての制約がスキャンされるため、実行不可能な数の操作が発生します。 

重要な洞察は、すべての制約は境界を変更するだけであるということです。 「」のような条件$y > x$" または "$y \le x$」は、の特定の値には依存しません。$y$、それがしきい値の上か下かだけです。 これは、すべての制約を 2 つの数値 (可能な限り低い上限と可能な限り高い下限) に圧縮できることを意味します。 各クエリを正しく解釈すると、各ステップではこれら 2 つの値のみが更新されます。 

すべての候補者をシミュレーションするのではなく、一定の間隔を維持します。$[L, R]$。 各ステートメントは次のいずれかを引き起こします$L$または下げる$R$、条件が満たされるか拒否されるかに応じて。 すべての制約を処理した後、実現可能性は以下のことをチェックすることになります。$L \le R$。

 ## アルゴリズムのチュートリアル

 各制約を解釈し、有効な間隔を維持します。$y$。 

1.初期化$L = -2 \cdot 10^9$、$R = 2 \cdot 10^9$。 これは許可された出力範囲と一致し、有効な回答が途中で除外されることがなくなります。 
2. 形式「演算子」の各制約について$x$、答え」、の値を決定します。$y$それを満足させます。 
3. ステートメントを間隔制限に変換します。 

ステートメントが true の場合、制約を直接適用します。 

false の場合は、反対の制約が適用されます。 

たとえば、ステートメントが「$y > x$」と答えたら、答えは「はい」です$L$になる$x+1$。 

答えが「いいえ」の場合、$y \le x$、 それで$R$になる$x$。 
4. 4 つの演算子すべてを同様に処理します。 

「>」と「>=」は真理値に応じて下限を調整します。 

「<」と「<=」は真理値に応じて上限を調整します。 
5. 各制約を処理した後、更新します$L$そして$R$新しい制限と交差することによって。 
6. すべての制約が処理されたら、実現可能性をチェックします。 

もし$L > R$の場合、すべての条件を満たす整数はないため、「不可能」と出力します。 

それ以外の場合は、任意の整数を出力します$[L, R]$、 例えば$L$。 

重要な考え方は、すべてのクエリで数直線の下側または上側のセグメントが削除されるため、実行可能なセットは常に 1 つの区間のままになるということです。 

### なぜ効果があるのか

 すべてのステップで、有効な整数のセットは、前の実行可能セットと現在のステートメントから導出された半線制約との正確な交差になります。 どちらも区間であるため、それらの交点も区間になります。 これにより、2 つの境界だけで状態を表現しても情報が失われることはありません。 解が存在する場合、その解はすべての制約の最後の交差部分に存在する必要があり、交差部分が空の場合、すべてのステートメントを同時に満たす整数は存在しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def apply(L, R, op, x, truth):
    if op == '>':
        if truth == 'Y':
            L = max(L, x + 1)
        else:
            R = min(R, x)
    elif op == '>=':
        if truth == 'Y':
            L = max(L, x)
        else:
            R = min(R, x - 1)
    elif op == '<':
        if truth == 'Y':
            R = min(R, x - 1)
        else:
            L = max(L, x)
    else:  # <=
        if truth == 'Y':
            R = min(R, x)
        else:
            L = max(L, x + 1)
    return L, R

def solve():
    n = int(input())
    L, R = -2_000_000_000, 2_000_000_000

    for _ in range(n):
        op, x, ans = input().split()
        x = int(x)
        L, R = apply(L, R, op, x, ans)

    if L > R:
        print("Impossible")
    else:
        print(L)

if __name__ == "__main__":
    solve()
```の`apply`関数は、各ステートメントを境界更新に変換するロジックを分離します。 これにより、実装時に間違いがよく発生する、解析と推論の混合が回避されます。 

メインループは単純に間隔を段階的に調整します。 最終的な決定は、間隔がすべての制約に耐えられるかどうかによってのみ決まります。

 ## 特殊なケース

 境界のみのケースは、すべての制約によって間隔が単一の値に押し上げられる場合に発生します。 たとえば、必要な場合は、$y \ge 5$、$y \le 5$、間隔は$[5,5]$。 両方の更新が同じ境界に収束するため、アルゴリズムは 5 を正しく出力します。 

矛盾のケースは、次のような 1 つの制約によって有効な整数がすべて削除される場合に発生します。$y > 10$に続く$y \le 10$。 最初のステップセット$L = 11$、第2セット$R = 10$、生産$L > R$。 最終チェックでは、不可能であることが即座に検出されます。 

符号反転エッジ ケースは、ステートメントが false で、不等号の方向が逆転する場合に発生します。 例えば、 "$y < x$」の答えは「いいえ」になります$y \ge x$。 実装では、真理値に基づいて明示的に分岐することでこれを処理し、厳密性が正しく保持され、off-by-one エラーが発生しないようにします。
