 ## 解決策
 ## 問題の理解

 私たちはラップトップのコレクションを与えられました。 各ラップトップには価格と品質の価値があります。 価格もすべて異なり、品質もすべて異なります。 

Dima 氏は、より高価なラップトップは常により優れた品質を備えている必要があると信じています。 アレックスは、これは必ずしも真実ではないと主張します。 同氏は、ラップトップが 2 台存在し、実際には安価なラップトップの方が高価なラップトップよりも高品質である可能性があると述べています。 

私たちの仕事は、指定されたラップトップのセットに対して Alex の主張が正しいかどうかを判断することです。 

入力は最大で構成されます$10^5$ラップトップ。 各ラップトップについて、価格と品質という 2 つの整数を受け取ります。 出力は`"Happy Alex"`安価なラップトップがより高価なラップトップよりも高品質であるペアが少なくとも 1 つ存在する場合。 それ以外の場合は印刷します`"Poor Alex"`。 

制約$n \le 10^5$すべてのラップトップをチェックすることは直ちに除外されます。 二次アルゴリズムはおおよそのパフォーマンスを発揮します$$\frac{10^5 \cdot (10^5 - 1)}{2} \approx 5 \times 10^9$$最悪の場合の比較は、1 秒以内に実行できる範囲をはるかに超えています。 周りに何かが必要です$O(n \log n)$またはそれ以上です。 

微妙な点は、ラップトップのインデックスは重要ではないということです。 価格と品質の関係のみが重要です。 入力の最初の方に表示されるラップトップは、それがより安いかより高価であることを意味するものではありません。 

次の例を考えてみましょう。```
3
10 100
20 200
30 300
```正しい出力は次のとおりです。```
Poor Alex
```価格の上昇には品質の向上が伴います。 

ここで次のことを考えてみましょう。```
3
10 300
20 200
30 100
```正しい出力は次のとおりです。```
Happy Alex
```価格が 10 のラップトップは、価格が 20 および 30 のラップトップよりも品質が優れています。 

もう 1 つの簡単な間違いは、隣接する入力行のみを比較することです。```
3
30 300
10 200
20 100
```正しい出力は次のとおりです。```
Happy Alex
```この矛盾は、ラップトップを価格で注文した後に初めて明らかになります。 元の入力順序には有用な構造が含まれていません。 

## アプローチ

 最も直接的な解決策はブルートフォースです。 すべてのラップトップを他のすべてのラップトップと比較します。 2 台のラップトップがあり、そのうちの 1 台の価格が安く、品質が高ければ、Alex の主張が証明され、私たちは立ち止まることができます。 

これが機能するのは、問題ステートメントから正確な条件を明示的にチェックするためです。 残念ながら、$10^5$ラップトップ、ペアの数は約$5 \times 10^9$。 非常に高速な実装であっても、制限時間内にそれほど多くの比較を処理することはできません。 

重要な観察は、条件が価格の順序のみに依存するということです。 すべてのラップトップを価格で並べ替えると、右側のすべてのラップトップは左側のすべてのラップトップよりも高価になります。 

価格で並べ替えて品質のシーケンスを取得するとします。```
100 200 150
```品質は 200 から 150 に低下しますが、価格は上昇します。 これにより、有効なペアがすぐに得られます。 品質 200 のラップトップは、品質 150 のラップトップよりも安価です。 

より一般的には、価格で分類した後、品質も厳密に向上している場合に限り、ディマの信念は真実です。 すべての品質値は異なるため、品質が低下した場合は、より安価で品質の高いラップトップが見つかったことを意味します。 

したがって、価格で並べ替えて、結果の品質をスキャンするだけで済みます。 いずれかの位置で現在の品質が以前の品質より小さい場合、アレックスは正しいです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのラップトップを次のように読み替えます`(price, quality)`ペア。 
2. ラップトップを価格の昇順に並べ替えます。 

並べ替えると、すべてのラップトップがより高価なすべてのラップトップより前に表示されます。 
3. ソートされたリストを左から右にスキャンします。 
4. 隣接するペアごとに、その品質を比較します。 
5. 現在のラップトップの品質が以前のラップトップよりも低い場合は、印刷`"Happy Alex"`そして終了します。 

以前のラップトップは並べ替え順のおかげで安価でありながら、より高品質です。 これはまさにアレックスが説明した状況です。 
6. 品質の低下が確認されずにスキャンが終了した場合は、印刷します。`"Poor Alex"`。 

### なぜ効果があるのか

 価格で並べ替えた後、ラップトップは安いものから高いものへと並べられます。 右に進む間に品質が低下した場合、安価なラップトップの方が高価なラップトップよりも品質が高く、これが Alex の主張を証明します。 

逆に、品質が決して低下しない場合は、価格とともに品質も向上します。 すべての品質が異なるため、より高価なラップトップはすべてより高品質であることを意味します。 矛盾するペアは存在できません。 

アルゴリズムはこのプロパティを正確にチェックするため、正しい答えが生成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
laptops = []

for _ in range(n):
    price, quality = map(int, input().split())
    laptops.append((price, quality))

laptops.sort()

for i in range(1, n):
    if laptops[i][1] < laptops[i - 1][1]:
        print("Happy Alex")
        break
else:
    print("Poor Alex")
```最初の部分では、すべてのラップトップの説明をペアのリストに読み取ります。 The call to`sort()`価格は各タプルの最初の要素であるため、価格で順序付けします。 

スキャンは 2 台目のラップトップから開始されます。 すべてのポジションについて、その品質を直前のラップトップの品質と価格順に比較します。 

質の低下はアレックスの主張を証明するのに十分だ。 このような減少が見つかれば、答えは判明しており、直ちに終了します。 

の`for-else`ここではconstructが便利です。 の`else`ブロックは、ループが発生せずに完了した場合にのみ実行されます。`break`、品質の低下は見られなかったことを意味します。 

すべての値が最大値であるため、オーバーフローの懸念はありません。$10^5$、アルゴリズムは比較と並べ替えのみを実行します。

4

2 20
3 30
4 40
```価格順に並べ替えると、次のようになります。 

| インデックス | 価格 | 品質 |
 | --- | --- | --- |
 | 0 | 1 | 10 |

 | 2 | 3 | 30 |

 スキャン:

 | 私 | 以前の品質 | 現在の品質 | 減少？ |
 | --- | --- | --- | --- |

 | 2 | 20 | 30 | いいえ |
 | 3 | 30 | 40 | いいえ |

 ## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | 並べ替えが実行時間の大半を占めます。 
| スペース | O(n) | Storage of all laptop pairs |

 と$n = 10^5$、$O(n \log n)$ソリューションは簡単に十分に高速です。 メモリ使用量も少なく、必要なストレージは$10^5$ペア。 

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    n = int(input())
    laptops = [tuple(map(int, input().split())) for _ in range(n)]

    laptops.sort()

    for i in range(1, n):
        if laptops[i][1] < laptops[i - 1][1]:
            print("Happy Alex")
            return

    print("Poor Alex")

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out

    solve()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out.getvalue().strip()

# provided sample
assert run("2\n1 2\n2 1\n") == "Happy Alex", "sample 1"

# minimum size
assert run("1\n5 10\n") == "Poor Alex", "single laptop"

# already increasing
assert run("4\n1 10\n2 20\n3 30\n4 40\n") == "Poor Alex", "perfect agreement"

# contradiction appears after sorting
assert run("3\n30 300\n10 200\n20 100\n") == "Happy Alex", "must sort first"

# contradiction far apart
assert run("5\n1 10\n2 20\n3 30\n4 40\n5 15\n") == "Happy Alex", "late decrease"

# two laptops only, opposite ordering
assert run("2\n100 200\n200 100\n") == "Happy Alex", "smallest non-trivial case"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 単一のラップトップ | かわいそうなアレックス | ペアが存在しません |
 | 品質を徹底的に高める | かわいそうなアレックス | ディマの信念は変わらない |
 | 未ソートの入力 | ハッピーアレックス | 価格順に並べ替える必要があります |
 | 後期の品質低下 | ハッピーアレックス | スキャンはアレイ全体で続行する必要があります。 
| 向かい合う 2 台のラップトップ | 写真 ハッピーアレックス | 最小の有効な矛盾 |
