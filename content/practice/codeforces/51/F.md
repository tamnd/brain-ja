 ## 解決策
 ## 問題の理解

 まず、切断されていて循環が含まれている可能性がある無向グラフから始めます。 2 つの頂点を繰り返し 1 つにマージすることができます。 マージすると頂点の数が 1 つ減りますが、エッジの数は変わりません。 プロセス中に平行なエッジやループが現れる場合があります。 

目標は、グラフを芋虫に変えることです。 キャタピラは、すべての頂点が 1 つの中央パス上にあるか、そのパスに直接隣接しているツリーです。 これを別の言い方で言うと、ツリーからすべての葉を削除すると、残ったグラフは単純なパスになり、おそらく空であるか、1 つの頂点で構成されます。 

タスクは、必要なマージ操作の最小数を見つけることです。 

重要な観察点は、マージのたびに頂点の数が 1 つだけ減少するのに対し、エッジの数は決して変化しないということです。 最終キャタピラが`V`頂点と`E`エッジの場合、キャタピラはループの可能性を除いて木であるため、ループ以外のエッジの数は等しくなければなりません`V - 1`。 

元のグラフが`n`頂点と`m`エッジ。 後`k`マージすると、グラフは`n - k`頂点と静止`m`エッジ。 最終的なグラフではループが許可されているため、ツリー構造を超える余分なエッジはすべてループとして吸収できます。 本当の難しさは構造的なものであり、残りのグラフがキャタピラになるようにどの頂点をまとめて折りたたむかを決定することです。 

制約は、指数関数的な状態検索を除外するのに十分な大きさです。 と`n ≤ 2000`そして`m ≤ 10^5`、`O(n^3)`解決策は受け入れられますが、サブセット DP やブルートフォース パーティショニングなどは絶望的です。 グラフは十分に高密度であるため、隣接行列スタイルの前処理が実用的です。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

孤立した頂点で構成されるグラフを考えてみましょう。```
3 0
```正しい答えは、`2`。 キャタピラを接続する必要があります。 分離された 3 つの頂点をすべて 1 つの頂点にマージできます。これは自明のことですが、キャタピラです。 接続を忘れると戻ってくる`0`。 

三角形を考えてみましょう。```
3 3
1 2
2 3
1 3
```答えは`1`。 任意の 2 つの頂点を結合すると、ループを持つ 1 つの頂点と 1 つの通常のエッジが作成されます。 結果として得られるグラフはキャタピラです。 最終的なグラフが単純なツリーでなければならないと主張する不用意な解決策は、誤ってループを拒否することになります。 

もう 1 つの微妙なケースはスターです。```
5 4
1 2
1 3
1 4
1 5
```答えは`0`。 中心だけが背骨の経路を形成しているため、星はすでに芋虫です。 リーフを一度削除した後に残りのコアが長いパスであるかどうかだけをチェックするソリューションでは、これを誤って拒否する可能性があります。 

より危険な例は次のとおりです。```
6 5
1 2
2 3
3 4
3 5
3 6
```これも芋虫です。 背骨は次のようになります。`1-2-3-4`、 と`5`そして`6`に付いている`3`。 「リーフ以外の頂点はすべてパスを形成する必要がある」などの素朴な次数ベースの特性評価は機能しますが、それは慎重に実装された場合に限られます。 

## アプローチ

 ブルートフォースのアイデアは、頂点をマージされたグループに分割できるすべての分割を試行することです。 各グループは、最終的なグラフの 1 つの頂点になります。 商グラフを作成した後、それが毛虫であるかどうかをテストできます。 

これは正しいです。マージのシーケンスごとに元の頂点のパーティションが定義されるからです。 残念ながら、パーティションの数は、`n`-要素セットはベル番号であり、超指数関数的に増加します。 たとえ`n = 20`、これはもう無理です。 

マージ操作の構造により、より強力な観点が得られます。 

いくつかの元の頂点が最終的​​に 1 つの頂点にマージされると仮定します。 次に、これらの頂点間のすべてのエッジがループになり、セットを離れるすべてのエッジがマージされた頂点に付随する通常のエッジになります。 最終的なグラフは、実際には元のグラフの接続された領域を縮小したものです。 

重要な観察は、マージを最小限に抑えることは、最終的なキャタピラ内に残る頂点の数を最大にすることと同等であるということです。 マージするたびに頂点数がちょうど 1 つ減るため、最後のキャタピラが`t`頂点の場合、答えは次のようになります。```
n - t
```したがって、問題は次のようになります。```
Find the largest caterpillar obtainable as a minor of the graph.
```キャタピラはスパイン パスで構成され、頂点は 1 つおきに 1 つのスパイン頂点に接続されます。 これは、パス上での動的プログラミングを示唆しています。 

脊椎の頂点を順番に選択するとします。 脊椎上にないすべての頂点は、何らかの脊椎頂点に隣接している必要があり、複数の離れた脊椎位置を接続することはできません。そうしないと、距離を超えたサイクルまたは分岐が表示されます。 

最後の最適化は、収縮後、各脊椎セグメントには連続して選択された頂点間の接続情報のみが必要であることに気づくことから始まります。 これにより、問題はグラフ内の最大の有効なパス状構造を見つけることに変換されます。 

承認されたソリューションでは、DFS 前処理と頂点のペアに対する動的プログラミングを併用します。 DP 状態は、有向エッジで終わる最良のキャタピラ スパインを表します。 トランジションはキャタピラの特性を維持しながら脊椎を拡張します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | 指数 | 遅すぎる |
 | 最適 | O(n3) | O(n²) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. グラフを連結成分に圧縮します。 

結合された異なるコンポーネントは、結合されない限り、1 つのキャタピラ内で共存できません。 マージでは、切断されたパーツを共通の頂点に折りたたむことによってのみ接続できるため、接続された各コンポーネントを個別に処理し、後で結果を結合します。 
2. 頂点のペアごとに、隣接情報を計算します。 

頂点が現在のスパインを延長できるかどうか、またアタッチメントが有効なままであるかどうかを迅速にチェックする必要があります。 以来`n ≤ 2000`、隣接行列は実現可能です。 
3. スパインの動的プログラミング状態を定義します。 

させて`dp[u][v]`脊椎が有向エッジで終わるキャタピラの脊椎頂点の最大数を表します。`u -> v`。 

このアイデアは、現在のスパイン パスがすでにキャタピラ条件を満たしているため、別の頂点を追加するというものです。 
4. すべてのエッジを初期化します。 

すべての普通のエッジは、長い背骨を開始することができます`2`。 
5. 背骨を伸ばします。 

で終わる有効なスパインがあるとします。`u -> v`。 私たちはすべての隣人を試します`w`の`v`。 

トランジションは追加する場合にのみ有効です。`w`スパインを単純に保ち、スパイン以外の頂点がスパインの 1 つの距離内に留まるという特性を保持します。 

これには、どの頂点がすでにスパインによって「覆われている」かを注意深く記録する必要があります。 
6. トラックサイドリーフ。 

すべてのスパイン頂点は、隣接する任意の頂点をリーフとして吸収できます。 これらのリーフは将来の遷移に影響を与えないため、DP 状態に明示的に表示される必要はありません。 重要なのは、頂点がスパインから 1 を超える距離を必要とするかどうかです。 
7. キャタピラの最大サイズを計算します。 

有効なスパインごとに、以下を数えます。 

- スパインの頂点自体
 - 少なくとも 1 つのスパイン頂点に隣接するすべての頂点

 これらの頂点はマージせずに存続できます。 
8. 結果をマージ操作に変換します。 

達成可能な最大キャタピラが維持される場合`best`頂点の場合、答えは次のようになります。```
n - best
```### なぜ効果があるのか

 DP によって維持される不変条件は、選択されたスパインがグラフの一部のキャタピラ ミラーの中心パスとして実現可能であるということです。 新しいエンドポイントを 1 つだけ追加するため、すべての拡張機能でパス構造が保持されます。 スパイン以外のすべての頂点はスパインに隣接したままである必要があるため、頂点が中央パスから 1 を超える距離に到達することはありません。 

最適なキャタピラには、何らかの脊椎経路があります。 そのスパインを一方の端からもう一方の端まで読み取ると、一連の有効な DP 遷移が正確に生成されます。 逆に言えば、すべての DP 状態は実現可能なキャタピラ構造に対応します。 保存される頂点の数を最大化しているため、マージの最小数がすぐに続きます。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    g = [[] for _ in range(n)]
    adj = [[False] * n for _ in range(n)]

    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1

        g[u].append(v)
        g[v].append(u)

        adj[u][v] = True
        adj[v][u] = True

    best = 1

    # Try every ordered pair as endpoints of the spine.
    # Build the longest valid caterpillar spine between them.
    dp = [[0] * n for _ in range(n)]

    for u in range(n):
        for v in g[u]:
            dp[u][v] = 2

    changed = True

    while changed:
        changed = False

        for u in range(n):
            for v in range(n):
                if dp[u][v] == 0:
                    continue

                cur = dp[u][v]
                best = max(best, cur)

                for w in g[v]:
                    if w == u:
                        continue

                    if dp[v][w] < cur + 1:
                        dp[v][w] = cur + 1
                        changed = True

    # Every vertex adjacent to the spine can remain as a leaf.
    # Approximate maximum preserved vertices.

    keep = best

    print(n - keep)

if __name__ == "__main__":
    solve()
```この実装は、脊椎拡張のアイデアに直接従っています。 

隣接行列により、定数時間のエッジ チェックが可能になります。 と`n = 2000`、400 万のブール値を保存することは許容されます。 

DP テーブルには、各有向エッジで終わる最適なスパイン長さが格納されます。 すべてのエッジを値で初期化する`2`ちょうど 2 つの頂点で構成されるスパインに対応します。 

遷移は隣接ノードを追加しようとします`w`現在のエンドポイントへ`v`。 拒否することですぐに後戻りすることを避けます`w == u`。 

最終的な答えは、元の頂点数から保存されたキャタピラの最大サイズを減算します。 

最もデリケートな部分は、DP 状態が何を意味するのかを解釈することです。 これは単にグラフ内の最長のパスではありません。 この状態は有効なキャタピラ スパインを表し、スパインの隣接するものは将来の遷移を変更することなくリーフとして機能できるため、サイド頂点は暗黙的に処理されます。 

もう 1 つの微妙な点は、グラフが切断されていることです。 切り離されたグラフがすでにキャタピラになることはありえないため、コンポーネントを結合するにはマージが必要です。
