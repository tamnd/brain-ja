 ## 解決策
 ## 問題の理解

 整数配列が与えられ、それを 3 つのカテゴリのいずれかに分類する必要があります。 

実数が存在する場合、シーケンスは等比数列とみなされます。$c$そして$b$すべての要素が次の形式を持つようにする$c \cdot b^{i-1}$。 簡単に言うと、分割が意味のある場合は常に、連続する要素が同じ比率を共有する必要があります。 

このタスクは、配列全体がすでに等比数列を形成しているかどうかをチェックするだけでなく、要素を 1 つだけ削除するだけで等比数列にできるかどうかもチェックすることです。 必要な出力は次のとおりです。 

-`0`シーケンスがすでに幾何学的である場合。 
-`1`要素を 1 つ削除すると幾何学的なものになる場合があります。 
-`2`さもないと。 

配列サイズは次の範囲に達します$10^5$これにより、配列の大部分を繰り返しスキャンするアルゴリズムが即座に除外されます。 二次関数の解法には大まかに次のものが必要になります。$10^{10}$最悪の場合、制限時間をはるかに超えて操作が行われる可能性があります。 線形時間に近いものが必要です。 

難しいのは、ゼロが出現した場合、累進比が小数になったり、負になったり、さらには未定義になる可能性があることです。 浮動小数点演算を使用すると、精度エラーによって比較が静かに中断される可能性があるため危険です。 実装では比率を正確に比較する必要があります。 

いくつかのエッジケースでは、単純なソリューションが失敗します。 

考慮する：```
3
0 0 0
```正しい答えは、`0`。 すべての要素がゼロであるため、すべての比率は有効です。 前の要素で除算する不用意な実装は、ゼロによる除算でクラッシュします。 

もう一つの危険なケースは次のとおりです。```
4
1 2 4 7
```正しい答えは、`1`削除するので`7`完璧な幾何級数を残します。 最初の 2 つの要素から比率を修正し、不一致を即座に拒否する単純な方法では、最後の要素を削除することで問題が解決されることを見落とす可能性があります。 

負の比率も重要です。```
5
2 -4 8 -16 32
```これはすでに比で幾何学的です`-2`。 比率が負ではないことを前提とした実装は失敗します。 

より微妙なケースは次のとおりです。```
5
1 0 0 0 0
```答えは`1`。 最初の要素を削除すると、すべてゼロが残り、これは幾何学的なものになります。 ただし、単一の比率変換がないため、元の配列自体は幾何学的ではありません。`1`の中へ`0`そしてすべての一貫性を保ちます。 

最後に、短い配列には特別な処理が必要です。 常に適切な定数を選択できるため、長さが最大 ​​2 のシーケンスは自動的に幾何学的になります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 削除された可能性のあるすべてのインデックスについて、残りのシーケンスを構築し、それが等比数列を形成しているかどうかを確認します。 削除のない元の配列もテストします。 

1 つの候補シーケンスをチェックするには、すべての隣接する比率を検証する必要があるため、直線的な時間がかかります。 削除するたびにこれを繰り返すと、$O(n^2)$時間の複雑さ。 

のために$n = 10^5$、つまり周りを意味します$10^{10}$まったく実行不可能な操作です。 

重要な観察は、1 つの要素を削除した後にシーケンスが幾何学的になる場合、配列のほぼ全体がすでに 1 つの公比に従っていることです。 一定数のポジションのみが不整合に関与する可能性があります。 

連続するトリプルを比較するとします。 等比数列で言うと：$$a_i^2 = a_{i-1} \cdot a_{i+1}$$これにより除算が完全に回避され、負の値でも機能します。 この等価性が満たされない場合は、必ず近くの要素の 1 つが問題に関与している必要があります。 単一の不適切な削除では、無関係な多くの不一致を任意に修復することはできません。 

つまり、疑わしいインデックスをいくつか特定し、その周囲の削除をテストするだけで済みます。 各テストには依然として直線的な時間がかかりますが、テストされる削除の数は一定となり、全体的に直線的な複雑さになります。 

最後のアルゴリズムは、配列を 1 回スキャンして最初の違反を特定し、次に、次のような近くの要素の削除を試みます。$i-1$、$i$、 または$i+1$。 有効な回答が存在する場合、これらのいずれかが削除された要素である必要があります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^2)$|$O(1)$| 遅すぎる |
 | 最適 |$O(n)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 小さな配列をすぐに処理します。 

長さが最大 ​​2 の配列は自動的に幾何学的になるため、次のように出力します。`0`。 
2. ヘルパー関数を定義する`good(skip)`。 

この関数は、インデックスを削除した後にシーケンスが幾何学的になるかどうかをチェックします。`skip`。 もし`skip = -1`、何も削除されません。 
3. 内部`good(skip)`、実際に新しい配列を作成せずに、残りのシーケンスを論理的に構築します。 

インデックスを反復処理し、スキップされたものは無視します。 
4. 残りのシーケンスの長さが最大 ​​2 の場合は、戻り値を返します。`True`。 

任意の 2 つの数値は常に等比数列を形成します。 
5. 残りの最初の 3 つの要素を見つけて、予想される関係を計算します。 

比率を保存する代わりに、相互乗算を使用して比較します。$$a_i \cdot a_{j-1} = a_{i-1} \cdot a_j$$これにより、浮動小数点の問題やゼロ除算が回避されます。 

1. 残りのシーケンスのスキャンを続けます。 

フィルタリングされたシーケンス内の連続するトリプルごとに、次のことを確認します。$$x_2^2 = x_1 \cdot x_3$$いずれかのトリプルがこの条件に違反する場合は、戻り値を返します。`False`。 

1. 元の配列を 1 回スキャンして、最初の違反しているトリプルを見つけます。 

何も存在しない場合、シーケンスはすでに幾何学的であるため、次のように出力します。`0`。 
2. 最初の違反がインデックスの周囲で発生したとします。`i-1`、`i`、 そして`i+1`。 

1 つの削除でシーケンスを修正できる場合、削除された要素はこの違反の近くにある必要があります。 近くにあるインデックスをそれぞれ削除してみます。 
3. 候補を削除するたびに、`good(candidate)`。 

いずれかの呼び出しが成功した場合は、出力します`1`。 
4. すべての候補者が不合格の場合は、印刷します。`2`。 

### なぜ効果があるのか

 等比数列は次の局所条件を満たします。$$a_i^2 = a_{i-1} \cdot a_{i+1}$$あらゆるミドルポジションに対応します。 

1 つの要素を削除してシーケンスを修復する場合、元の配列内のすべての違反には、その削除された位置が含まれている必要があります。 最初の壊れたトリプルに遭遇すると、削除された要素はその近傍に属している必要があります。 離れた要素を削除すると、違反はそのまま残ります。 

アルゴリズムはそのような近い可能性をすべてテストし、ヘルパー関数は結果のシーケンスの正確な検証を実行します。 すべての有効な解がこれらの候補の中に出現する必要があるため、アルゴリズムは正解を見逃すことはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def is_geometric(arr):
    m = len(arr)

    if m <= 2:
        return True

    for i in range(1, m - 1):
        if arr[i] * arr[i] != arr[i - 1] * arr[i + 1]:
            return False

    return True

def good(a, skip):
    b = []

    for i in range(len(a)):
        if i != skip:
            b.append(a[i])

    return is_geometric(b)

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    if is_geometric(a):
        print(0)
        return

    bad = -1

    for i in range(1, n - 1):
        if a[i] * a[i] != a[i - 1] * a[i + 1]:
            bad = i
            break

    candidates = set()

    for x in [bad - 1, bad, bad + 1]:
        if 0 <= x < n:
            candidates.add(x)

    for idx in candidates:
        if good(a, idx):
            print(1)
            return

    print(2)

solve()
```機能`is_geometric`ID を使用して実際の検証を実行します。$$a_i^2 = a_{i-1} \cdot a_{i+1}$$これは中心的な実装の詳細です。 除算を使用すると、ゼロと浮動小数点の精度に関する問題が発生します。 相互乗算により、すべてが整数で正確に保たれます。 

ヘルパーさん`good`1 つの要素の削除をシミュレートします。 一定数の削除のみがテストされるため、残りのシーケンスは一時配列にコピーされ、合計作業量は線形のままです。 

main 関数は、最初に元の配列が既に機能しているかどうかを確認します。 そうでない場合は、最初に違反している中間インデックスが検索されます。 近くのインデックスのみが削除候補としてテストされます。 

一連の候補は、違反が最初または最後近くに現れた場合、重複したチェックを回避します。 

Python の整数は大きな積を自動的に安全に処理するため、ここではオーバーフローは問題になりません。 C++ などの言語では、`long long`必要だろう。

import io

def solve_io(inp: str) -> str:

    input = sys.stdin.readline

    def is_geometric(arr):
        m = len(arr)

        if m <= 2:
            return True

        for i in range(1, m - 1):
            if arr[i] * arr[i] != arr[i - 1] * arr[i + 1]:

 ## 特殊なケース

 すべてゼロのシーケンスを考えてみましょう。```
3
0 0 0
```アルゴリズムは以下をチェックします。$$0^2 = 0 \cdot 0$$これはすべてのトリプルに当てはまります。 どこにも除算が発生しないため、ゼロ除算エラーのリスクはありません。 出力は次のようになります`0`。 

次に、次のことを調べます。```
4
1 2 4 7
```最初の悪いトリプルは、`(2, 4, 7)`なぜなら：$$4^2 \ne 2 \cdot 7$$アルゴリズムはインデックスの削除をテストします`1`、`2`、 そして`3`。 削除中`7`生成する`[1,2,4]`、次の条件を満たす。$$2^2 = 1 \cdot 4$$出力は`1`。 

負の比率の場合:```
5
2 -4 8 -16 32
```チェックは次のようになります。$$(-4)^2 = 2 \cdot 8$$

$$8^2 = (-4) \cdot (-16)$$

$$(-16)^2 = 8 \cdot 32$$すべてが有効であるため、シーケンスはすぐに受け入れられます。 実装は決して肯定的なものを想定しません。 

最後に、次のことを考慮してください。```
5
1 0 0 0 0
```最初の違反は次の場所に表示されます。`(1,0,0)`なぜなら：$$0^2 \ne 1 \cdot 0$$インデックスの削除`0`葉`[0,0,0,0]`、すべてのチェックに合格します。 アルゴリズムは正しく印刷します`1`。
