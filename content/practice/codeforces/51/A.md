 ## 解決策
 ## 問題の理解

 それぞれのアミュレットは、`2 x 2`～の数字が入った四角形`1`に`6`。 これは 4 つのセルとして考えることができます。```
a b
c d
```一方を回転させてもう一方に入れることができる場合、2 つのアミュレットは同じ山に属します。 反転は禁止されており、回転のみが可能です`90°`、`180°`、 または`270°`許可されています。 

入力するといくつかのお守りが得られます。 すべてのお守りは 2 つの長さの文字列として書かれています`2`、連続するお守りの間には区切り線があります`"**"`。 課題は、異なる回転パターンがいくつ出現するかを数えることです。 

制約はわずかです。 多くてもあります`1000`すべてのお守りには 4 つの価値しか含まれていません。 たとえ`O(n²)`比較アプローチは制限内で快適に実行されます。`1000² = 1,000,000`ペア チェックであり、各チェックでは 4 つのセルのみが検査されます。 それでも、すべてのアミュレットを固有の正規表現に還元し、それらの表現をセットに保存すれば、問題ははるかにすっきりします。 

難しいのは、回転を正しく処理することです。 よくある間違いは、元の方向のみを比較することです。 例えば：```
12
34
```そして```
31
42
```最初のアミュレットを時計回りに回転させると 2 番目のアミュレットが得られるため、実際には同じアミュレットです。 

複数の回転によって同じ配置が生成される場合、別の微妙なケースが発生します。 考慮する：```
11
11
```どの回転も同じです。 個別のアミュレットの代わりに個別の回転をカウントしようとする不注意な実装では、誤ってカウントしすぎてしまう可能性があります。 

もう 1 つのバグの原因は、区切り線の読み取りです。 最後のアミュレットには何もありません`"**"`その後。 すべてのアミュレットの後でセパレータを盲目的に読み取るコードは、誤って次のテスト入力の一部を消費したり、誤って EOF にヒットしたりする可能性があります。 

## アプローチ

 最も直接的な解決策はブルートフォースです。 すべてのお守りについて、以前に見たすべての山と比較します。 2 つのアミュレットが同等かどうかをテストするには、1 つのアミュレットの 4 つの回転をすべて生成し、それらのいずれかがもう一方と一致するかどうかを確認します。 

これは、回転の等価性がまさに問題で求められているものであるため、機能します。 アミュレットには常に 4 つのセルがあるため、各比較には一定の時間がかかります。 と`n = 1000`、最悪のケースでは約 100 万回の比較が実行されますが、それでも許容範囲内です。 

ここでのブルートフォースアプローチの弱点はパフォーマンスではなく、構造にあります。 回転を繰り返し再計算し、同じパターンを繰り返し比較します。 すべてのアミュレットに標準形式を割り当てると、問題ははるかにすっきりします。 

重要な観察は、同じアミュレットのすべてのローテーションが 1 つの等価クラスに属しているということです。 4 つのローテーションを生成し、辞書編集的に最小の表現を選択すると、同じクラスのすべてのアミュレットはまったく同じ正規文字列を生成します。 

例えば：```
12
34
```次の回転が生成されます。```
1234
3142
4321
2413
```最小の文字列は`"1234"`。 このアミュレットの回転バージョンも同じ 4 つの文字列を生成するため、最小値は依然として`"1234"`。 

すべてのアミュレットが標準形式に変換されると、問題は個別の文字列をカウントすることになります。 セットはこれを自然に処理します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 承認済み |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. お守りの数を読み取ります。 
2. 各お守りについて、その 2 行を読み取り、4 桁の数字を抽出します。```
a b
c d
```3. 4 つの回転すべてを生成します。 

回転は次のとおりです。 

オリジナル:```
a b
c d
```90°:```
c a
d b
```180°:```
d c
b a
```270°:```
b d
a c
```4. すべての回転を長さの文字列に変換します`4`。 

例えば：```
a b
c d
```になる`"abcd"`。 
5. 辞書編集上最小の回転文字列を選択します。 

これがアミュレットの標準的な表現になります。 回転的に等価なすべてのアミュレットは、同じ正規文字列を生成します。 
6. 正規文字列をセットに挿入します。 

セットは重複を自動的に削除するため、同一の同値クラスは 1 つのエントリにまとめられます。 
7. すべてのお守りを処理した後、セットのサイズを印刷します。 

なぜ効果があるのか:

 アミュレットの有効なローテーションはすべて、生成された 4 つの構成の中に表示されます。 2 つのアミュレットは、回転のセットが同一である場合、回転的に正確に等価です。 常に最小のローテーション文字列を標準形式として選択するため、すべての同等のアミュレットは同じ値にマッピングされますが、同等でないアミュレットは異なる値にマッピングされます。 設定されたサイズは、個別のパイルの数と正確に一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())

seen = set()

for i in range(n):
    r1 = input().strip()
    r2 = input().strip()

    a, b = r1[0], r1[1]
    c, d = r2[0], r2[1]

    rotations = [
        a + b + c + d,
        c + a + d + b,
        d + c + b + a,
        b + d + a + c
    ]

    seen.add(min(rotations))

    if i != n - 1:
        input()

print(len(seen))
```プログラムはすべてのお守りを正規化された形式で保存します。 

4 つの変数`a`、`b`、`c`、 そして`d`正方形を表す：```
a b
c d
```の`rotations`list は、4 つの可能な方向を明示的に構築します。 アミュレットのサイズは固定されているため、変換を直接記述する方が、行列回転コードを使用するよりも簡単でエラーが発生しにくくなります。 

への呼び出し`min(rotations)`正規表現を選択します。 すべての文字列が同じ長さであるため、辞書編集的比較は自然に機能します。 

区切り線`"**"`アミュレット間のみスキップされます。 条件:```
if i != n - 1:
    input()
```最後のアミュレットの後の入力の終わりを超えて読むことを避けます。 

セット`seen`同値クラスごとに 1 つの代表を格納します。 最終的なサイズは杭の数になります。

# helper: run solution on input string, return output string
import sys, io

def solve():
    import sys
    input = sys.stdin.readline

    n = int(input())

    seen = set()

    for i in range(n):
        r1 = input().strip()
        r2 = input().strip()

        a, b = r1[0], r1[1]
        c, d = r2[0], r2[1]

        rotations = [
            a + b + c + d,
            c + a + d + b,
            d + c + b + a,
            b + d + a + c
        ]

        seen.add(min(rotations))

        if i != n - 1:
            input()

    print(len(seen))

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out

    solve()

    sys.stdout = sys.__stdout__
    return out.getvalue()
