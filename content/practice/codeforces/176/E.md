[CF 176E - 考古学](https://codeforces.com/problemset/problem/176/E)

 **評価:** 3100
 **タグ:** データ構造、dfs および同様のもの、ツリー
 **解決時間:** 2 分 40 秒
 **確認済み:** いいえ

 ## 解決策
 ## 問題の理解

 重み付けされたツリーが与えられます。 村は頂点に対応し、道路は重み付けされたエッジに対応します。 

現時点でも、「生きている」村は一部だけです。 村は時間の経過とともに追加および削除できます。 更新のたびに、実際に使用されている道路の総延長を求められる場合があります。 

重要なフレーズは、人々は現在存在するすべての村間の移動を可能にする最小限の道路を使用するということです。 元のグラフはツリーであるため、答えは単純に、すべてのアクティブな頂点を含む最小の接続されたサブツリーの合計重みになります。 

これを別の言い方で言えば、元のツリーのすべてのエッジのうち、2 つのアクティブな頂点間のパス上にあるエッジを正確に保持するということです。 それらの重みの合計が必要な答えになります。 

ツリーには以下が含まれます$10^5$頂点があり、最大$10^5$更新と問い合わせ。 変更のたびに最小サブツリーを最初から再計算することは不可能です。 たとえ$O(n)$更新ごとの走査には約$10^{10}$最悪の場合の運用。 

この問題では、挿入、削除、およびサブツリー長のクエリを使用して、静的ツリー内の頂点の完全に動的なセットが要求されます。 

いくつかの特殊なケースは誤解されやすいものです。 

単一のアクティブな頂点を考えてみましょう。```
1
?
```1 つの頂点を接続するのにエッジは必要ないため、答えは 0 になります。 

アクティブな頂点間の距離を常に合計する不注意な実装では、誤って正の値が生成される可能性があります。 

パスで接続された 2 つのアクティブな頂点を考えてみましょう。```
1 --5-- 2 --7-- 3
active = {1,3}
```答えは$5+7=12$。 

最小サブツリーはまさにそれらの間の一意のパスです。 

ここで、3 つのアクティブな頂点を考えてみましょう。```
    2
    |
1 --3-- 4
```すべての頂点がアクティブな場合、答えは 3 つのエッジすべての合計になります。 

「ペアごとの距離を合計し、何かで割る」などの単純なアイデアは、各エッジが多くのペアごとのパスに参加しているため、失敗します。 

難しいのは、アクティブな頂点のシュタイナー ツリーのサイズを維持しながら、挿入と削除をサポートすることです。 

## アプローチ

 ブルートフォースの解決策は簡単です。 

更新のたびに、アクティブな頂点をすべて収集します。 これらの頂点の仮想ツリーを構築するか、アクティブな頂点間のパスに属するすべてのエッジを単純にマークし、対応するエッジの重みを合計します。 

これは正しいです。答えはまさにすべてのアクティブな頂点にわたる最小の接続されたサブツリーであるからです。 

残念ながら、もしあるとしたら、$k$アクティブな頂点、ゼロから答えを構築する場合でも、少なくともコストがかかります$O(k \log n)$、 頻繁$O(n)$。 と$10^5$更新すると、これはあまりにも大きくなりすぎます。 

この画期的な進歩は、木の古典的な特性から生まれました。 

アクティブな頂点をオイラー ツアーのエントリ時間順に並べます。 連続するアクティブな頂点をその巡回順序で接続し、それらのペアごとの距離を合計すると、シュタイナー ツリーのすべてのエッジが正確に 2 回カウントされます。 

したがって：$$\text{SteinerWeight} = \frac{ \sum d(v_i,v_{i+1}) }{ 2 }$$ここで、順序は DFS 順序で循環的です。 

これにより、問題はサブツリーの維持から頂点の循環セットの維持に変わります。 

頂点が挿入されるとき、オイラー順序におけるその先行者と後続者のみが問題になります。 地球規模のサイクルは局所的に変化します。 

挿入された頂点が$x$、前任者は$p$、後継者は$s$。 

以前の投稿には以下が含まれていました$$d(p,s)$$挿入後はこうなります$$d(p,x)+d(x,s)$$したがって、維持されるサイクル合計は次のように変化します。$$d(p,x)+d(x,s)-d(p,s).$$削除は逆の操作を実行します。 

残りのタスクは、距離を迅速に計算することです。 ツリーは決して変更されないため、深さ、ルート距離、LCA を前処理します。 

それから$$d(u,v) = distRoot[u] + distRoot[v] - 2\,distRoot[lca(u,v)].$$各更新には、順序付きセット内の先行/後続クエリと一定数の距離計算のみが必要です。

 ## アルゴリズムのチュートリアル

 ### 前処理

 1. 任意の頂点、たとえば頂点 1 でツリーをルートします。 
2. DFS を実行し、オイラーエントリ時間を計算します。`tin[u]`。 
3. LCA の深さ、ルート距離値、バイナリリフティング祖先を計算します。 
4. すべての頂点について、ペアを保存します`(tin[u], u)`。 アクティブな頂点は次の順序で維持されます。`tin`。 

### 動的メンテナンス

 保守:

 - オイラー時間でソートされたアクティブな頂点の順序付きセット。 
- 値`cycle_sum`。`cycle_sum`は$$\sum d(v_i,v_{i+1})$$循環 DFS 注文を超えて。 

### 頂点の挿入

 1. オイラー順序で新しい頂点の前任者と後続者を見つけます。 
2. これが最初のアクティブな頂点である場合は、単純に挿入します。 
3. それ以外の場合は追加します$$d(pred,x)+d(x,succ)-d(pred,succ)$$に`cycle_sum`。 

4. 頂点を順序付きセットに挿入します。 

サイクルの古いエッジは 2 つの新しいエッジに置き換えられます。 

### 頂点の削除

 1. 頂点の先行者と後続者を検索します。 
2. それが唯一のアクティブな頂点である場合は、それを削除し、サイクル寄与をゼロに設定します。 
3. それ以外の場合は追加します$$d(pred,succ)-d(pred,x)-d(x,succ)$$に`cycle_sum`。 

4. 頂点を削除します。 

これは挿入操作をまったく逆にします。 

### 質問に答える

 1. アクティブな頂点が 2 つ未満の場合は、0 と答えます。 
2. それ以外の場合は出力$$\frac{\text{cycle\_sum}}{2}.$$### なぜ効果があるのか

 アクティブな頂点を DFS 順序に従って周期的にリストします。 

あらゆるエッジを利かせてください$e$すべてのアクティブな頂点にわたる最小サブツリーの。 削除中$e$ツリーを 2 つのコンポーネントに分割します。 以来$e$Steiner ツリーに属し、両側にアクティブな頂点が含まれます。 

巡回 DFS 順序では、正確に 2 つの連続するペアが一方の側からもう一方の側に交差します。 このような各交差は、次の重みに寄与します。$e$距離の合計に 1 回。 

したがって、すべてのシュタイナー ツリー エッジは、循環距離の合計に正確に 2 倍寄与します。 シュタイナー ツリーの外側のエッジは寄与度がゼロです。 

したがって、維持される量は常に答えのちょうど 2 倍になります。 挿入と削除によって巡回順序がローカルに更新されるため、不変条件はすべての操作の後でも true のままです。 

## Python ソリューション```python
import sys
from bisect import bisect_left, insort

input = sys.stdin.readline

def solve():
    n = int(input())

    g = [[] for _ in range(n)]
    for _ in range(n - 1):
        a, b, c = map(int, input().split())
        a -= 1
        b -= 1
        g[a].append((b, c))
        g[b].append((a, c))

    LOG = 17
    while (1 << LOG) <= n:
        LOG += 1

    tin = [0] * n
    depth = [0] * n
    root_dist = [0] * n
    up = [[0] * n for _ in range(LOG)]

    timer = 0

    stack = [(0, 0, 0, 0)]
    while stack:
        u, p, state, idx = stack.pop()

        if state == 0:
            tin[u] = timer
            timer += 1

            up[0][u] = p

            stack.append((u, p, 1, 0))

            for v, w in reversed(g[u]):
                if v == p:
                    continue
                depth[v] = depth[u] + 1
                root_dist[v] = root_dist[u] + w
                stack.append((v, u, 0, 0))

    for k in range(1, LOG):
        prev = up[k - 1]
        cur = up[k]
        for v in range(n):
            cur[v] = prev[prev[v]]

    def lca(a, b):
        if depth[a] < depth[b]:
            a, b = b, a

        diff = depth[a] - depth[b]
        bit = 0
        while diff:
            if diff & 1:
                a = up[bit][a]
            diff >>= 1
            bit += 1

        if a == b:
            return a

        for k in range(LOG - 1, -1, -1):
            if up[k][a] != up[k][b]:
                a = up[k][a]
                b = up[k][b]

        return up[0][a]

    def dist(a, b):
        c = lca(a, b)
        return root_dist[a] + root_dist[b] - 2 * root_dist[c]

    q = int(input())

    active = []
    cycle_sum = 0

    def add_vertex(x):
        nonlocal cycle_sum

        key = (tin[x], x)

        if not active:
            insort(active, key)
            return

        pos = bisect_left(active, key)

        succ = active[pos % len(active)][1]
        pred = active[(pos - 1) % len(active)][1]

        cycle_sum += (
            dist(pred, x)
            + dist(x, succ)
            - dist(pred, succ)
        )

        active.insert(pos, key)

    def remove_vertex(x):
        nonlocal cycle_sum

        key = (tin[x], x)

        pos = bisect_left(active, key)

        if len(active) == 1:
            active.pop()
            cycle_sum = 0
            return

        pred = active[(pos - 1) % len(active)][1]
        succ = active[(pos + 1) % len(active)][1]

        cycle_sum += (
            dist(pred, succ)
            - dist(pred, x)
            - dist(x, succ)
        )

        active.pop(pos)

    out = []

    for _ in range(q):
        s = input().split()

        if s[0] == '+':
            add_vertex(int(s[1]) - 1)
        elif s[0] == '-':
            remove_vertex(int(s[1]) - 1)
        else:
            out.append(str(cycle_sum // 2))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```コード ブロックの後の重要な観察は、維持された循環距離の合計です。 アクティブな頂点は常に DFS 順序で保存されます。 すべての更新はそのサイクル内の 1 か所のみを変更するため、シュタイナー ツリーを再構築する必要はありません。 

LCA 前処理により、距離クエリが提供されます。$O(\log n)$。 挿入または削除のたびに、そのような距離の計算と先行/後続検索が一定数実行されます。 

C++ では、目的のソリューションは順序付きセットを使用します。 Python では、運用品質に認められたソリューションは通常、バランスツリー実装を使用します。 上記の編集コードは、数学的な更新式を明確に示していますが、受け入れられている Codeforces 実装では、真の順序セットを使用してデータを保持しています。$O(\log n)$更新情報。
