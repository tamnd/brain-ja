 ## 解決策
 ## 問題の理解

 各操作では、現在の単語の空でない接頭辞と空でない接尾辞を選択し、それらの順序を入れ替えます。 現在の単語が次のように書かれている場合`xy`、ここで両方とも`x`そして`y`が空ではない場合、操作により次のように変換されます。`yx`。 

この操作を循環回転として表示すると便利です。 単語の長さが次の場合`n`そしてポジションの後で分割しました`p`、長さの接尾辞`n-p`前に移動します。 すべての分割は正確に 1 つの非自明な回転に対応し、すべての非自明な回転は正確に 1 つの分割に対応します。 

言葉`start`そして`end`等しい長さを持つ`n`、 どこ`2 ≤ n ≤ 1000`。 正確に何シーケンスかを数えなければなりません`k`分割操作の変換`start`の中へ`end`。 分割位置が異なると異なる操作が生成されるため、あるステップで異なる分割ポイントを選択した場合、2 つのシーケンスは異なるものとみなされます。 

単語の長さは最大 1000 文字ですが、`k`到達できる`10^5`。 考えられるすべての操作シーケンスを明示的に追跡するアルゴリズムは絶望的です。 すべての回転とすべてのステップで DP 状態を維持する場合でも、約`1000 × 100000 = 10^8`トランジションが多すぎます。 

重要な観察は、すべての操作で文字の循環順序が維持されるということです。 単語から出発して、その回転に到達することしかできません。 もし`end`の回転ではありません`start`、答えはすぐにゼロになります。 

いくつかの特殊なケースは見落とされがちです。 

考慮する：```
ab
ab
0
```答えは`1`。 すでにターゲットから開始されており、操作は実行されません。 少なくとも 1 つの操作が存在することを前提としたソリューションは、誤って返します。`0`。 

考慮する：```
aaaa
aaaa
1
```すべての分割で同じ表示文字列が生成されます`"aaaa"`ですが、使用する分割位置が異なるため、操作は依然として異なります。 がある`3`有効なワンステップシーケンス。 個別の分割をカウントせずに状態を文字列として扱うと、アンダーカウントになります。 

考慮する：```
abcd
bcda
1
```有効な分割は 1 つだけです。 1 位置ずつ左に回転すると、最初の文字の後の分割に対応します。 実際の操作パスではなくターゲット回転の発生をカウントするソリューションでは、カウントが過剰になる可能性があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 あらゆるステップで、すべてを試してください`n-1`可能な分割位置を調べて、結果の単語を再帰的に生成します。 まさにその後`k`操作、最後の単語が次と等しいかどうかを確認します`end`。 

これは、すべての法的な操作手順を調査しているため、正しいです。 残念ながら、分岐要因は`n-1`、つまり、探索された州の数はおおよそ次のとおりです。`(n-1)^k`。 たとえ小さな値であっても、`k`、これは巨大になります。 

次のアイデアは、分割操作が実際に何を行うかを観察することです。 ポジション後の分割`p`文字列を回転させます`n-p`ポジション。 分割を繰り返しても、文字の循環順序が変更されることはありません。 到達可能なすべての単語は単純に回転したものです`start`。 

長さがあるとします。`n`。 多くてもあります`n`異なる回転状態。 頂点が回転で、エッジが次のいずれかの選択に対応するグラフを構築できます。`n-1`自明ではない回転。 どの回転からでも、1 回の移動で他のすべての回転に到達できますが、同じ回転にとどまることは、たまたま同じ文字列を生成する回転によってのみ可能です。 

重要な簡素化は、回転を 2 つのカテゴリのみにグループ化することで実現します。 

最初のカテゴリには、以下に等しい回転が含まれます。`end`。 

2 番目のカテゴリには、次の値と等しくない回転が含まれます。`end`。 

させて`cnt`の回転数になります`start`等しい`end`。 

この場合、すべての回転は 2 つのクラスのいずれかに属し、遷移は特定の回転ではなくクラスにのみ依存します。 これにより、問題は 2 状態の DP に変わり、最大 2 時間処理できます。`10^5`ステップ。 

この DP を使用するには、回転かどうかを知る必要があります。`0`の`start`はすでに等しい`end`、合計回転数はどれくらいか`end`。 両方の量は、次の出現を検索することで取得できます。`end`内部`(start + start)[:-1]`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O((n-1)^k) | O(k) | 遅すぎる |
 | 最適 | O(n + k) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### 1. ターゲットの回転をカウントする

 しましょう```
T = start + start
```毎回転`start`の開始位置に対応します`T`。 

すべての出現箇所を検索します`end`で`T[:-1]`。 出現回数はまさに回転数です。`start`に等しい`end`。 

この値を呼び出します`cnt`。 

もし`cnt = 0`、 それから`end`の回転ではありません`start`、そして答えは`0`。 

### 2. 初期状態を決定する

 しましょう```
good0 = 1 if start == end else 0
```2 つの DP 状態を定義します。`good[i]`回転に等しい方法の数は次のとおりです`end`後`i`操作。`bad[i]`と等しくない回転をする方法の数です`end`後`i`操作。 

最初に:```
good = good0
bad = 1 - good0
```開始ローテーションは 1 つだけです。 

### 3. 遷移数を導出する

 現在、良好なローテーションが行われているとします。 

がある`n-1`可能なスプリットポジション。 

すべての回転の中で以下に等しい`end`そのうちの 1 つは現在の回転そのものです。 すべての操作は重要である必要があるため、現状にとどまることはできません。 

したがって、良好な状態から別の良好な状態への遷移の数は次のようになります。```
cnt - 1
```良好な状態から不良状態への遷移の数は次のとおりです。```
n - cnt
```ここで、ローテーションが悪いと仮定します。 

その中で、`cnt`回転が良好で、すべてを 1 回の動作で達成できます。 

不適切な宛先の場合、1 回転は現在の状態そのものであり、選択できません。 したがって：```
good transitions = cnt
bad transitions = n - cnt - 1
```### 4. DP を更新する

 各ステップについて:```
new_good =
    good * (cnt - 1)
    + bad * cnt

new_bad =
    good * (n - cnt)
    + bad * (n - cnt - 1)
```すべての計算はモジュロで実行されます`10^9+7`。 

### 5. k 回の操作を繰り返します

 トランジションを適用する`k`回。 

答えは最終的な値です。`good`。 

### なぜ効果があるのか

 元の問題のすべての状態は次の回転です。`start`。 最終目標に関連する唯一の情報は、その回転が等しいかどうかです。`end`。 

させて`cnt`を表す回転数になります。`end`。 どの回転からでも、分割を選択することは、他の回転インデックスを選択することと同じです。 良好な状態と不良な状態への出力エッジの数は、現在の状態が良好か不良かによってのみ決まります。 特定の回転数には依存しません。 

同じカテゴリ内のすべての状態は同じ遷移動作を行うため、それらを 2 つの DP 状態に集約すると、パスの正確な数が保持されます。 繰り返しでは、分割位置のすべての有効なシーケンスが 1 回だけカウントされます。 正確に処理した後`k`操作、`good`に等しい回転で終了する操作シーケンスの数に等しい`end`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 1000000007

def kmp_count(text, pattern):
    m = len(pattern)

    pi = [0] * m
    j = 0
    for i in range(1, m):
        while j > 0 and pattern[i] != pattern[j]:
            j = pi[j - 1]
        if pattern[i] == pattern[j]:
            j += 1
        pi[i] = j

    cnt = 0
    j = 0
    for ch in text:
        while j > 0 and ch != pattern[j]:
            j = pi[j - 1]
        if ch == pattern[j]:
            j += 1
        if j == m:
            cnt += 1
            j = pi[j - 1]

    return cnt

def solve():
    start = input().strip()
    end = input().strip()
    k = int(input())

    n = len(start)

    cnt = kmp_count((start + start)[:-1], end)

    if cnt == 0:
        print(0)
        return

    good = 1 if start == end else 0
    bad = 1 - good

    for _ in range(k):
        new_good = (good * (cnt - 1) + bad * cnt) % MOD
        new_bad = (good * (n - cnt) + bad * (n - cnt - 1)) % MOD

        good = new_good
        bad = new_bad

    print(good)

if __name__ == "__main__":
    solve()
```最初の部分は計算します`cnt`、の回転数`start`に等しい`end`。 KMP を使用すると、このステップは文字列の長さにおいて線形に保たれます。 

表現`(start + start)[:-1]`重要です。 最後の文字を削除しないと、元の回転が 2 回表示され、余分な一致が 1 つ発生します。 

DP には 2 つの値のみが保存されます。`good`目標回転で終了する方法をカウントします。`bad`他の場所で終わる方法を数えます。 遷移係数は、各カテゴリに至る分割操作の数を数えることから直接得られます。 

微妙な点は、`cnt - 1`良い状態から良い状態への移行期にあります。 適切なローテーションの 1 つは現在のローテーション自体ですが、分割操作は両側で空でなくてはなりません。そのため、同じローテーションにとどまることは操作として許可されません。 この引き算を忘れることは、この問題で最もよくある間違いです。
