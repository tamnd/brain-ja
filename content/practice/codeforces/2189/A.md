 ## 解決策
 ## 問題の理解

 数値の配列があります。 そこから任意の偶数の要素を選択し、それらを順序付けられたペアに分割することができます。 

ペア`(x, y)`貢献する`1`行の場合のみテーブルに`x`そしてコラム`y`存在する。 テーブルにはあるので、`h`行と`l`列、これは必要があることを意味します`1 ≤ x ≤ h`そして`1 ≤ y ≤ l`。 

増分を受け取る実際のセルは、最終的な答えには関係ありません。 この問題では、テーブル内のすべての値の合計を求めます。 すべての有効なペアは、ちょうど 1 つのセルを増加させます。`1`したがって、テーブルの合計を最大化することは、形成できる有効なペアの数を最大化することと同じです。 

配列の長さは最大でも`100`、小さいです。 かなり非効率なソリューションでも快適にフィットします。 課題はパフォーマンスではなく、正しい貪欲な観察を認識することです。 

配列から要素を選択してそれらをペアにするため、数値は最大 1 回のみ使用できます。 配列内で同じ値が複数回出現する場合、同じ値が複数回出現する可能性があります。 

主な微妙な点は、ペアの 2 つのポジションが異なる役割を持っていることです。 最初の要素として使用される数値は以下でなければなりません`h`ただし、2 番目の要素として使用される数値は最大でも`l`。 両方の条件を満たす値は、どちらの役割も果たすことができます。 

考慮する`h = 2`、`l = 5`、および配列`[1, 1, 1]`。 3 つの数値はすべて有効な行と列です。 不注意な解決法では、使用可能な数字を 3 つ数えて答えてしまう可能性があります。`3`, ただし、1 つのペアは 2 つの数値を消費するため、有効なペアは 1 つだけ形成できます。 正しい答えは、`1`。 

もう 1 つの注意が必要なケースは、数値が 1 つの役割でのみ有効な場合です。 仮定する`h = 1`、`l = 100`、および配列`[1, 50]`。 値`1`行と列を指定できますが、`50`列のみにすることができます。 私たちは形成することができます`(1, 50)`、答えを与える`1`。 再利用を追跡せずに行対応の数値と列対応の数値を個別にカウントするソリューションでは、より多くの組み合わせが可能であると誤って判断される可能性があります。 

最後のエッジケースは、行として使用できる数値がない場合に発生します。 例えば：```
n = 2, h = 1, l = 1
a = [5, 5]
```有効なペアが存在しないため、答えは次のようになります。`0`。 

## アプローチ

 ブルートフォースの考え方は、どのペアを形成できるかを尋ねることから始まります。 すべての要素は、未使用であるか、ペアの最初のメンバーになるか、ペアの 2 番目のメンバーになるかのいずれかになります。 考えられるすべての組み合わせを探索すると、すぐに組み合わせが可能になります。 たとえ`n = 100`、一致する可能性のある数は天文学的に多くなります。 

重要な点は、どの有効なセルが増分を受け取るかは気にしないということです。 成功したすべてのペアは正確に貢献します`1`答えに。 

役割に応じて配列の各要素を分類してみましょう。 

値の場合`x`満足する`x ≤ h`、行インデックスとして機能します。 

値の場合`x`満足する`x ≤ l`、列インデックスとして機能します。 

ペアを有効にするには、選択した 1 つの要素に行の役割を割り当て、選択した別の要素に列の役割を割り当てる必要があります。 

配列を一度に 1 要素ずつ処理するとします。 すべての有効なペアには、行対応要素と列対応要素が 1 つずつ必要です。 両方の条件を満たす要素は柔軟性があり、現在必要な役割を果たすことができます。 

これは、行スロットと列スロットの間のマッチングの問題になります。 すべてのペアはちょうど 2 つの要素を消費するため、有効なペアの最大数は、作成できる行と列の一致の最大数と等しくなります。 

非常にシンプルな欲張り作品。 

確認した一致しない行対応要素の数と、確認した一致しない列対応要素の数を維持します。 

新しい番号を処理する場合:

 行として機能できる場合は、以前に一致しなかった列要素が存在する場合は、その要素とすぐにペアにしたいと考えます。 

同様に、列として機能できる場合は、以前に一致しなかった行要素が存在する場合は、その要素とペアにしたいと考えます。 

さらに明確なビューは、要素を 3 つのカテゴリに分類することです。 

値を含む`x ≤ min(h,l)`どちらの役割も果たせます。 

値を含む`min(h,l) < x ≤ h`行のみにすることができます。 

値を含む`min(h,l) < x ≤ l`列のみにすることができます。 

させて`R =`行対応要素の数 (`x ≤ h`)`C =`列対応要素の数 (`x ≤ l`)

 すべての有効なペアには、行の役割と列の役割が 1 つずつ必要です。 私たちが作成する場合`k`ペア、私たちは消費します`k`行の割り当てと`k`列の割り当て。 各配列要素は 1 回だけ使用できるため、消費される要素の総数は次のようになります。`2k`を超えてはなりません`n`。 

柔軟な要素は、役割割り当ての競合を自動的に解決します。 可能なペアの最大数は単純に次のようになります。`min(R, C, n // 2)`その理由を確認するには、次のことが必要です`k ≤ R`各ペアには行要素が必要なので、`k ≤ C`各ペアには列要素が必要であるため、`k ≤ n/2`各ペアが 2 つの要素を消費するためです。 

不足している側に柔軟な要素を割り当てることができるため、これらの境界も達成可能です。

 ## アルゴリズムのチュートリアル

 1. 満たす配列要素の数を数えます。`a[i] ≤ h`。 この値を呼び出します`R`。 
2. 満たす配列要素の数を数えます。`a[i] ≤ l`。 この値を呼び出します`C`。 
3. すべての有効なペアには 1 つの行対応要素と 1 つの列対応要素が必要であるため、ペアの数はどちらかを超えることはできません。`R`または`C`。 
4. 各ペアも 2 つの配列要素を消費するため、ペアの数が を超えることはできません。`n // 2`。 
5. 答えは次のとおりです。```
min(R, C, n // 2)
```6. テストケースの答えを出力します。 

### なぜ効果があるのか

 有効なペアは、行位置に割り当てられた 1 つの要素と列位置に割り当てられたもう 1 つの要素にすぎません。 

作成したい場合は、`k`有効なペア、少なくとも必要です`k`行対応要素と少なくとも`k`列対応要素、境界を与える`k ≤ R`そして`k ≤ C`。 各ペアは 2 つの異なる配列要素を使用するため、次のことも必要になります。`2k ≤ n`、それは与える`k ≤ n // 2`。 

制限はこれらのみです。 両方の条件を満たす要素は、必要な役割に割り当てることができます。 したがって、いつでも、`k`3 つの不等式をすべて満たす場合、構造が存在します。 実現可能な最大値は正確に`min(R, C, n // 2)`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    
    for _ in range(t):
        n, h, l = map(int, input().split())
        a = list(map(int, input().split()))
        
        rows = sum(x <= h for x in a)
        cols = sum(x <= l for x in a)
        
        print(min(rows, cols, n // 2))

solve()
```実装は数学的特徴付けに直接続きます。 

変数`rows`ペアの最初のメンバーとして使用できる要素の数をカウントします。 変数`cols`2 番目のメンバーとして使用できる要素の数をカウントします。 

最終的な答えは、必要な 3 つの制限すべてによって制限されます。 最小値を取ると、有効なペアの達成可能な最大数が得られます。 

すべての値が小さいため、オーバーフローの心配はありません。 確認する価値のある唯一の詳細は、各テスト ケースに正確な内容が含まれていることです。`n`数字とかそれ`n // 2`小数のペアは不可能であるため、整数の除算を使用します。

 入力:```

```どの要素も行インデックスまたは列インデックスとして機能できないため、有効なペアは存在しません。 

### 使用可能な数値は多数ありますが、より多くのペアを作成するには要素が不足しています

 入力:```

```以下を取得します。```

```答えは次のようになります。```

```すべての要素は両方の役割で有効ですが、存在する要素は 3 つだけであるため、形成できるペアは最大 1 つです。 

### 行候補と列候補間の大きな不均衡

 入力:```
1
6 5 2
1 2 3 4 5 5
```カウント:```

cols = 2

```アルゴリズムは次を返します。```

```列として機能できる要素は 2 つだけであるため、使用可能な行対応要素がいくつあるかに関係なく、3 番目の有効なペアを作成することは不可能です。 

### 両方の役割で有効な値

 入力:```

4 1 1

```カウント:```

cols = 4

```答え：```

```すべての要素は柔軟であり、どちらかの役割を割り当てることができます。 アルゴリズムは、2 つのペアが形成できることを正しく認識します。
