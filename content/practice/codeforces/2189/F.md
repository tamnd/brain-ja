 ## 問題の理解

 うちには木があります。 頂点`i`最初に含まれています`a_i`ナッツ。 

電気代には2種類あります。 

最初のコストは、特別な再分配操作から発生します。 頂点を選択します`v`。 次に、頂点が 1 つおきに、距離が大きいものから小さいものへと処理されます。`v`。 処理された頂点に現在少なくとも 1 つのナットが含まれている場合、ちょうど 1 つのナットが 1 つのエッジに近づけて移動されます。`v`。 

2 番目のコストは、すべての再配布操作が完了した後に発生します。 ゾーラは空ではないすべての頂点からナッツを食べて、お金を支払います`q`少なくとも 1 つのナットがまだ含まれている各頂点に対して。 

私たちの目標は、移動コストと食事コストの合計が最小限になるように、どの頂点を中心に再配分操作を何回実行するかを決定することです。 

最初に理解すべきことは、再配布操作が実際に何を行うのかということです。 

中心頂点を固定する`v`。 1 つの操作を中心に考えてみましょう`v`。 を除くすべての頂点`v`最大で 1 個のナットを失う可能性があります。 そのナットの一方の端が次の方向に移動します。`v`。 頂点は距離の大きい方から小さい方へ処理されるため、子から到着したナットはすぐにさらに遠くに転送できます。`v`中間頂点に元々送信するナットがあった場合。 この順序は、問題の重要な構造特性です。 

制約は大きいです。 すべての合計`n`オーバーテストケースは最大でも`10^5`、したがって、何か必要があります`O(n log n)`または`O(n)`テストケースごとに。 すべてのセンターを試して操作を明示的にシミュレートするソリューションは、すぐに遅くなりすぎます。 平`O(n^2)`不可能なとき`n = 10^5`。 

頂点に多くのナットが含まれる場合、微妙なエッジ ケースが発生します。 

例：```
1 - 2
a = [100, 0]
```頂点を中心とした 1 つの操作`2`頂点からナットを 1 つだけ移動します`1`頂点へ`2`, ナッツ100個すべてではありません。 操作を不用意に解釈すると、すべてのナットが同時に動くと想定してしまうことがよくあります。 それは間違いです。

```頂点を中心とした 2 つの操作`3`すべてのナッツを頂点に集める`3`。 答えは、木の直径や各ナットを個別に動かすことによって決まるわけではありません。 この操作はすべての頂点に同時に作用するため、繰り返し適用することが非常に強力になります。 

3つ目の落とし穴は、`q = 0`。

```答えは`0`。 空ではないすべての頂点を無料で食べることができます。 頂点を自動的にマージしようとするアルゴリズムは、過剰な負担を伴います。 

## アプローチ

 ブルート フォース アプローチでは、考えられるすべての中心頂点を試し、再分配操作をシミュレートし、空ではない頂点のセットがどのように進化するかを追跡します。 

中心を固定するとします`v`。 させて`x_u`最初に頂点にあるナットの数になります`u`。 1 つの操作を直接シミュレーションするには、ツリー全体を走査する必要があります。 多くの操作を実行する可能性があるため、潜在的に最大距離まで`v`、複雑さは少なくとも 2 次になります。 考えられるすべての中心に対してこれを繰り返すことは完全に不可能です。 

重要な観察は、固定中心の周りで繰り返される操作が実際に何を行うかを理解することから得られます。 

離れたところにある頂点を考慮する`d`選んだセンターから`v`。 

すべての操作で、その頂点から最大 1 つのナットを頂点に一歩近づけることができます。`v`。 後`k`せいぜいオペレーション`k`ナッツはその頂点を離れることができます。 したがって、次の場合には頂点は空ではないままになります。```
a_u > k
```1 回の操作で正確に 1 つのナットを取り外すことができるためです。 

これにより、より強力な何かがすぐに明らかになります。 演奏後`k`中心周りの作戦`v`、からの距離が遠いすべての頂点`v`せいぜい`k`より深い頂点から到着するすべてのナットを転送できます。 プロセス全体は、各頂点が独立して貢献しているかのように動作します。```
max(a_u - k, 0)
```残ったナッツ。 

頂点が空になるのは、まさに次の場合です。`a_u ≤ k`。 

食べるコストは、空でない頂点がいくつあるかによってのみ決まります。 もし```

ツリー構造が入ります。

したがって、すべての頂点までの距離が次を満たす中心が必要です。`a_u > k`せいぜい`k`。 

同様に、定義すると、```
S(k) = { u | a_u > k }
```それなら必要です```
radius(S(k)) ≤ k
```ここで、半径は、セットの中心からすべての頂点までの最小可能な最大距離を意味します。 

古典的な木の事実によれば、頂点のサブセットの半径は次のとおりです。```

```ここで、直径はサブセット内の 2 つの頂点間の最大距離です。 

したがって、特定の条件に対する実現可能性`k`になる```

 ## アルゴリズムのチュートリアル

 ### プロセスの再定式化

 一定回数の操作の場合`k`、頂点は空ではないままになります。`a_u > k`。 

させて```
S(k) = {u : a_u > k}.
```食費は、```
|S(k)| * q.
```移動コストは、```
k * p.
```残る唯一の問題は、これらの生き残った頂点を単一の中心で処理できるかどうかです。 

### 直径条件

 中心はすべての頂点に存在します。`S(k)`距離内にあります`k`その中心から。 

このような最大距離の最小値は、次の半径に等しくなります。`S(k)`。 

ツリーメトリクスの場合:```
radius = ceil(diameter / 2).
```したがって、実現可能性はまさに```
diameter(S(k)) ≤ 2k.
```### アクティブ セットの維持

 として`k`増加すると、頂点がセットから外れます。```
k >= a_u.
```したがって、頂点は値の降順に消えます。 

増やすのではなく、`k`、しきい値を大きいものから小さいものに処理し、値が現在のしきい値を超える頂点を追加します。 

アクティブな頂点は正確に`S(k)`。 

### アクティブな頂点の動的直径

 ツリー内の一連の頂点の場合、その直径の端点によってすべての最大距離が完全に決まります。 

2 つのアクティブな頂点を維持する`A`そして`B`現在の直径を表します。 

新しい頂点のとき`x`が挿入されます:

 1. コンピューティング`dist(x,A)`。 
2. コンピューティング`dist(x,B)`。 
3. いずれかの距離が現在の直径の長さを超える場合は、直径の終点を更新します。 

これは、標準的な増分直径維持手法です。 

距離は次のように答えられます。`O(1)`LCA 前処理を使用します。 

### しきい値の評価

 アクティブ セットが変更されるしきい値のみが重要です。 

のプロセス値`k`降順で。 

各しきい値について:

 1. より大きい値を持つすべての頂点を追加します。`k`。 
2. Maintain active-set diameter.
 3. しましょう`D`直径の長さになります。 
4. しきい値は次の場合に実現可能です。```
D ≤ 2k.
```5. 可能な場合は更新します```
answer = min(answer, k*p + active_count*q).
```ケース`k`どれよりも大きい`a_i`アクティブな頂点とコストは残りません`k*p`正確に選択することに勝るものはありません`k=max(a_i)`空セットの場合は、関連するしきい値を確認するだけで十分です。 

### なぜ効果があるのか

 後`k`操作では、すべての頂点が最大で寄与できる`k`ナットを中心に向かって。 以上の頂点`k`ナッツにはその後もナッツが含まれている必要があります。 したがって、生き残った頂点はまさに次の頂点です。`a_u > k`。 

すべての生存者が距離内に存在する場合、センターは生存しているすべての頂点を処理できます。`k`それの。 ツリー メトリックでは、これは生存者セットの半径が最大であることに相当します。`k`、これは直径が最大であることに相当します。`2k`。 

アクティブ セット メンテナンスでは、現在アクティブな頂点の実際の直径が常に保存されます。 したがって、すべてのしきい値は、実行可能または実行不可能として正しく分類されます。 すべての実行可能なしきい値の中で、アルゴリズムは正確なコスト式を評価するため、見つかった最小値が最適な答えとなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

LOG = 17

def solve():
    t = int(input())

    for _ in range(t):
        n, p, q = map(int, input().split())
        a = list(map(int, input().split()))

        g = [[] for _ in range(n)]
        for _ in range(n - 1):
            u, v = map(int, input().split())
            u -= 1
            v -= 1
            g[u].append(v)
            g[v].append(u)

        depth = [0] * n
        up = [[0] * n for _ in range(LOG)]

        stack = [0]
        parent = [-1] * n
        parent[0] = 0

        order = [0]
        while stack:
            v = stack.pop()
            for to in g[v]:
                if to == parent[v]:
                    continue
                parent[to] = v
                depth[to] = depth[v] + 1
                stack.append(to)
                order.append(to)

        for v in range(n):
            up[0][v] = parent[v]

        for j in range(1, LOG):
            prev = up[j - 1]
            cur = up[j]
            for v in range(n):
                cur[v] = prev[prev[v]]

        def lca(a_, b_):
            if depth[a_] < depth[b_]:
                a_, b_ = b_, a_

            diff = depth[a_] - depth[b_]
            bit = 0
            while diff:
                if diff & 1:
                    a_ = up[bit][a_]
                diff >>= 1
                bit += 1

            if a_ == b_:
                return a_

            for j in range(LOG - 1, -1, -1):
                if up[j][a_] != up[j][b_]:
                    a_ = up[j][a_]
                    b_ = up[j][b_]

            return parent[a_]

        def dist(u, v):
            w = lca(u, v)
            return depth[u] + depth[v] - 2 * depth[w]

        by_value = {}
        for i, x in enumerate(a):
            by_value.setdefault(x, []).append(i)

        values = sorted(by_value.keys(), reverse=True)

        active = 0
        diameter_len = 0
        end1 = -1
        end2 = -1

        ans = n * q

        idx = 0
        m = len(values)

        current_active = 0

        for k in range(values[0], -1, -1):
            while idx < m and values[idx] > k:
                val = values[idx]

                for v in by_value[val]:
                    current_active += 1

                    if end1 == -1:
                        end1 = end2 = v
                    else:
                        d1 = dist(v, end1)
                        d2 = dist(v, end2)

                        if d1 > diameter_len:
                            diameter_len = d1
                            end2 = v
                        elif d2 > diameter_len:
                            diameter_len = d2
                            end1 = v

                idx += 1

            if diameter_len <= 2 * k:
                ans = min(ans, k * p + current_active * q)

        print(ans)

if __name__ == "__main__":
    solve()
```このソリューションは、標準的な LCA 前処理から始まります。 アクティブセットの直径を維持しながら、任意の頂点間の距離が何度も必要になるため、`O(1)`後の距離クエリ`O(n log n)`前処理は必須です。 

頂点はナット数によってグループ化されます。 しきい値が`k`が減少すると、値がしきい値より大きくなった頂点がアクティブ セットに入ります。 

アクティブ セットは常に次のことを表します`S(k) = {u : a_u > k}`。 その直径の終点を段階的に維持します。 新しい頂点が挿入されると、直径が変更される唯一の方法は、この頂点が新しい直径の 1 つの端点になる場合です。 現在のエンドポイントまでの距離を確認するだけで十分です。 

すべてのしきい値について、実現可能性の条件をテストします。`diameter ≤ 2k`。 それが当てはまる場合、正確なコスト式を評価し、答えを更新します。 

この実装では、反復 DFS を使用して、長いパスでの再帰の深さの問題を回避します。
