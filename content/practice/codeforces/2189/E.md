 ## 解決策
 ## 問題の理解

 バイナリ文字列が与えられます`s`長さの`n`。 私たちの目標は、この文字列を単一の文字に変換することです。`"1"`特別な操作を使用すると、任意の連続した部分文字列を取得し、その部分文字列内の他の文字と少なくとも同じ回数出現する文字に置き換えることができます。 このような各操作には、使用される部分文字列の長さに等しいコストがかかります。 総コストを最小限に抑えたい、または`-1`それが不可能な場合。 

簡単に言うと、すべての操作は文字列の一部をその部分の過半数の文字に削減します。 文字列が既に次のもののみで構成されている場合`"1"`s、操作は必要ありません。 文字列にのみが含まれている場合`"0"`s、到達することは不可能です`"1"`。 課題は、文字列に 0 と 1 が混在している場合に発生します。総コストを最小限に抑えるために、賢い方法で部分文字列を選択する必要があります。 

制約は厳しいです:`n`まで行くことができます`5⋅10^5`、との合計`n`すべてのテスト ケースにわたって、同じ数によって制限されます。 すべての部分文字列を試行する単純なアプローチではパフォーマンスが大まかになるため、これにより O(n^2) アルゴリズムが除外されます。`n^2/2`テスト ケースごとの操作が大きすぎます。 

明らかではないエッジケースには次のようなものがあります。 

- シングル`"0"`: 変換できないので、答えは次のようになります。`-1`。 
- シングル`"1"`: すでにターゲットになっており、コストは`0`。 
- ブロックが連続した文字列`"0"`に囲まれて`"1"`: 部分文字列の選択を誤ると、必要以上のコストが発生する可能性があります。 
- すでにすべてが終わっている長い文字列`"1"`: どのアルゴリズムでもこれを効率的に検出して返さなければなりません`0`。 

## アプローチ

 ブルートフォース手法では、考えられるすべての操作シーケンスをシミュレートします。 各部分文字列について、大部分の文字を計算し、それを置換し、再帰します。 これは正しいですが、明らかに指数関数的です。文字列を分割する方法の数は長さに応じて超指数関数的に増加するため、次のような場合には実行できません。`n`まで`5⋅10^5`。 

重要な洞察は、どのような演算でも、1 の間または末尾にある連続するゼロのシーケンスを単一の 0 に折りたたむことができるということです。`"1"`少なくとも 1 つあれば`"1"`部分文字列に含まれます。 逆に、ゼロの部分文字列は`"1"`生産できない`"1"`。 このことから、次の 2 つのことがわかります。まず、文字列は次のようにしか縮小できません。`"1"`少なくとも 1 つ含まれている場合`"1"`; 第 2 に、最適な戦略は貪欲です。1 の隣に最も長く連続する 0 ブロックを繰り返し操作します。 

最適なアプローチでは、連続するゼロのブロックをそれぞれ独立したセグメントとして扱います。 各セグメントについて、それを削減するための最小コストは、そのセグメントを隣接するセグメントと組み合わせるコストの合計に等しくなります。`"1"`大多数がそうなる形で`"1"`。 操作には以下が含まれる可能性があるため、`"1"`ブロックの一方の端で、1 で囲まれた 0 のブロックを折りたたむコストは、ブロックの長さに 1 を加えたものになります。 開始または終了のエッジ ゼロ ブロックは、最も近いブロックも含めて同様に処理されます。`"1"`。

 ## アルゴリズムのチュートリアル

 1. まず、文字列をスキャンします`s`。 含まれていない場合`"1"`、 戻る`-1`すぐに。 
2. 文字列がすでに存在する場合`"1"`、 戻る`0`。 
3. 総コスト変数を次のように初期化します。`0`。 
4. 文字列をトラバースして、連続するゼロのブロックを特定します。 各ゼロブロックについて:

 - 最初または最後にあり、何もない場合`"1"`左または右にある場合でも、最も近い値を含めることで減らすことができます。`"1"`部分文字列内。 
- ゼロブロックの長さに 1 を加えたものを合計コストに加算します。 これは、`"1"`手術中。 
5. 累計コストを返します。 

機能する理由: 各ゼロブロックは少なくとも 1 つのブロックと組み合わせる必要があります。`"1"`に崩壊する`"1"`。 ゼロと 1 の長さを数えることで、過半数が確実に含まれる最小限の部分文字列が含まれることが保証されます。`"1"`。 どの操作もゼロブロックに触れずに折りたたむことはできません。`"1"`したがって、この貪欲なアプローチはおそらく最小限です。 不変条件は、すべてのゼロブロックを処理した後、すべてのブロックが`"0"`削除されるか、次のものに置き換えられます`"1"`1 回の操作で。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()
        if '1' not in s:
            print(-1)
            continue
        if s == '1':
            print(0)
            continue
        total_cost = 0
        i = 0
        while i < n:
            if s[i] == '0':
                j = i
                while j < n and s[j] == '0':
                    j += 1
                # length of zero block
                total_cost += j - i
                # include adjacent '1' for majority
                total_cost += 1
                i = j
            else:
                i += 1
        print(total_cost)

if __name__ == "__main__":
    solve()
```コードはまず、些細なエッジ ケース、つまり文字列を処理します。`"1"`そしてすでに文字列`"1"`。 次に、各ゼロブロックを調べて、コストへの寄与を計算します (長さに 1 を加えたものを含めます)。`"1"`)、それらを合計します。 2 つのポインターを使用する (`i`そして`j`) ネストされたループを回避し、O(n) 時間を保証します。
