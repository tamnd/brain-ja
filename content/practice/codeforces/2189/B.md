 ## 解決策
 ## 問題の理解

 カエルが無限数直線に沿って位置 0 から目標位置まで移動するのを手伝うように求められます。$x$。 カエルは、$n$魔法のジャンプの一種。 各ジャンプの種類$i$カエルは最大で前に進むことができます$a_i$ユニットですが、カエルは呪われています:$b_i$-そのタイプの 2 番目のジャンプは強制的にロールバックされます$c_i$ジャンプ前のユニット。 目標は、正確な位置に到達するためにカエルが耐えなければならないロールバックの最小回数を決定することです。$x$、またはそれは不可能であると報告します。 

入力では複数のテスト ケースを指定します。 それぞれのケースリスト$n$それぞれのジャンプ タイプ$a_i, b_i, c_i$。 制約は大きいです:$x$まで可能です$10^{18}$そして$n$すべてのテストケースを合計すると、$10^5$。 これにより、すべてのジャンプを個別にシミュレートしようとするソリューションは除外されます。これを行うには、次のような処理が必要となるからです。$x$最悪の場合の運用。 各ジャンプをシミュレートせずに結果を計算する数学的または貪欲なアプローチが必要です。 

最大ジャンプ距離を超えると、明らかではないエッジケースが発生します。$a_i$ロールバック未満です$c_i$頻繁に繰り返されるジャンプの場合。 たとえば、$x = 4$そしてジャンプ$a = 2, b = 2, c = 3$ロールバック効果を無視した単純なアプローチでは、カエルがターゲットに到達できると誤って結論付ける可能性があります。 もう 1 つのエッジ ケースは、ターゲットがどのジャンプ距離よりも小さいが、1 回のジャンプで正確に到達できる場合です。 この場合、ロールバックの最小数は 1 ではなく 0 です。 

## アプローチ

 ブルート フォース アプローチでは、すべてのジャンプ タイプを段階的にシミュレートし、ジャンプのすべての組み合わせを試し、ロールバックを追跡し、到達した時点で停止します。$x$。 これは正しいですが、ターゲットが$x$非常に大きくなる可能性があり、各ジャンプ シーケンスには数十億のステップが含まれる可能性があります。 

重要な洞察は、各ジャンプ タイプを個別に扱い、指定された数のロールバックでカエルがどこまで到達できるかを計算することです。 ジャンプタイプの場合$i$、させれば$k$発生したロールバックの数を表すと、達成可能な合計距離は次のようになります。$a_i \cdot (k \cdot b_i) - k \cdot c_i + r$、 どこ$r < b_i$次のロールバックまでのジャンプの数です。 ロールバックを最小限に抑える最適化は、有効なジャンプ距離の最大化につながります。$a_i - \frac{c_i}{b_i}$。 整数演算を使用して各ジャンプ タイプの最小ロールバックを計算し、最も少ないロールバックで目標を達成するジャンプ タイプを選択できます。 

すべてのジャンプをシミュレートするのは不可能であるため、総当りアプローチは失敗します。 ジャンプ パラメーターに基づいてロールバックを直接計算できるという観察により、問題はジャンプ タイプごとの定数時間の計算に帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(x * n) | お(1) | 遅すぎる |
 | 最適 | テスト ケースあたり O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ジャンプの種類ごとに$i$、どうかを確認してください$a_i \ge x$。 「はい」の場合、カエルは到達できます$x$ロールバックなしの 1 回のジャンプで。 回答候補としてゼロを記録します。 
2. ジャンプ タイプの場合、$a_i < x$、必要なロールバックの最小数を計算します。 各ロールバックは次の間隔で発生します。$b_i$ジャンプしてネット距離を短縮します$c_i$。 させて$k$ロールバックの数になります。 到達可能な最大距離$k$ロールバックは$$\text{distance} = a_i \cdot (\text{total jumps}) - k \cdot c_i$$ここで、合計ジャンプには、ロールバックを引き起こすジャンプと残りのジャンプの両方が含まれます。 最小の整数を求める$k \ge 0$そんな距離$\ge x$。 

1. コンピューティング$k$整数計算を使用: 到達するジャンプの数$x$ロールバック効果がなければ、$\lceil x / a_i \rceil$。 合計のロールバック距離は次のとおりです。$\lfloor (\text{jumps} - 1)/b_i \rfloor \cdot c_i$。 調整する$k$ロールバックを含む合計距離が以上になるまで$x$。 
2. 最小限を追跡する$k$すべてのジャンプタイプにわたって。 ジャンプタイプが届かない場合$x$、出力$-1$。 それ以外の場合は、見つかった最小ロールバックを出力します。 

このアルゴリズムが機能するのは、ロールバックが周期的で予測可能であり、累積的な影響を直接計算できるためです。 各ジャンプ タイプを個別にチェックできるため、タイプ全体で最小限のロールバック構成がキャプチャされることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, x = map(int, input().split())
        min_rollbacks = float('inf')
        for _ in range(n):
            a, b, c = map(int, input().split())
            if a >= x:
                min_rollbacks = min(min_rollbacks, 0)
                continue
            if a * b <= c:
                continue
            # compute minimum rollbacks needed
            k = (x - a + (a * b - c) - 1) // (a * b - c)
            if k >= 0:
                min_rollbacks = min(min_rollbacks, k)
        print(-1 if min_rollbacks == float('inf') else min_rollbacks)

if __name__ == "__main__":
    solve()
```コードはまず、1 回のジャンプでターゲットに到達できる単純なケースを処理します。 次に、ロールバック ペナルティがサイクルあたりの正味距離を超えるために役に立たないジャンプ タイプをフィルターで除外します。 残りのジャンプ タイプについては、整数演算によって必要なロールバックの正確な数が計算されます。 使用する`float('inf')`達成不可能なケースに正しくフラグが立てられるようにします。
