 ## 解決策
 ## 問題の理解

 長さの文字列が与えられます$n$0 と 1 で構成されます。 順列の場合$p$の$[0, 1, \dots, n-1]$、関数$f(w)$位置ごとに次のような順列の数を数えます。$i$、最小除外値 (MEX) 条件が満たされている場合:$w_i = 1$、MEX が等しい部分配列が存在します。$i$; もし$w_i = 0$、MEX が等しいサブ配列はありません$i$。 私たちのタスクは、文字列が与えられると、$s$「？」なしで 文字と整数$c$、最小値を決定します$f(w)$(モジュロ$10^9+7$) すべての文字列の間で$w$～から入手可能$s$そのような$f(w)$で割り切れない$c$、または不可能な場合は -1 を出力します。 

制約は大きいです:$n$到達できる$2 \cdot 10^5$と合計$n$すべてのテスト ケースの上限も次のとおりです。$2 \cdot 10^5$。 これにより、順列の総当り列挙が即座に除外されます。$n!$成長が早すぎます。 有効なソリューションは、テスト ケースごとに線形または線形に近い時間で動作する必要があります。 エッジ ケースには、完全に 0 または 1 からなる文字列が含まれており、どの順列が有効であるかに大きく影響します。 各ポジションの貢献度を慎重に計算しない単純なアプローチ$i$これらの場合は失敗します。 たとえば、$s = "001"$、2 の部分配列 MEX を生成する順列は存在しないため、$f(w) = 0$答えは -1 です。 

## アプローチ

 ブルートフォースソリューションでは、すべてが列挙されます。$n!$の順列$[0, 1, \dots, n-1]$そして、MEX 条件を満たすものがいくつあるかを数えます。 これは原理的には正しいですが、次の場合には実行できません。$n$各チェックには、MEX を計算するためにすべてのサブ配列を反復処理することが含まれるため、複雑さは次のようになります。$O(n! \cdot n^2)$、明らかに非実用的です。 

重要な洞察は、どの数値がどの位置を占めることができるかを推論することによって、問題を組み合わせ公式に帰着できるということです。 簡単なバージョンでは、「?」を使用せずに、1 を MEX としてどこかに出現する必要がある位置として扱い、0 をそうでない位置として扱うことができます。 直接的な公式があります。文字列内の各 1 は、順列での配置に係数 2 を与えます。 より正確には、$f(w)$は、文字列内の連続する 1 ブロックの 2 のべき乗の積として計算できます。 このアプローチは次の点で線形です。$n$ブロックを識別するために文字列を 1 回反復するだけだからです。 

もう 1 つの微妙な側面は、次のような割り算をチェックすることです。$c$。 以来$f(w)$急速に成長するため、モジュロを計算します$10^9+7$オーバーフローを防ぐために各乗算で。 最終的な値が次の値で割り切れる場合$c$の場合、有効な文字列は存在せず、答えは -1 になります。 このロジックにより、複数のことを考慮する必要がなくなります。$w$この簡単なバージョンのように、文字列、$w = s$が唯一の候補です。

 ## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取ります。 テスト ケースごとに、次の内容を読んでください。$n$、$c$、および文字列$s$。 
2. 変数を初期化する`res = 1`。 これは保持されます$f(w)$モジュロ$10^9+7$。 
3. 文字列を反復処理して、連続する 1 のブロックをカウントします。 このような長さのブロックごとに$k$、乗算する`res`\(10^9+7 を法とする 2^k` で計算します。これは、すべて 1 について MEX 条件を満たすことができる置換の数をカウントします。
 4. すべてのブロックを処理した後、次のことを確認します。`res % c == 0`。 その場合は設定してください`res = -1`。 
5. 出力`res`。 

機能する理由: 不変条件は、1 の連続ブロックごとに有効な順列の数が 2 倍になることです。これは、新しい 1 ごとに 2 つの選択肢があるためです。MEX 条件を満たすために、順列内で前に検討した要素の前または後に配置するということです。 0 のブロックは MEX の出現を制限するだけなので、カウントには影響しません。これはブロックの乗算で当然考慮されます。 モジュロ演算により値が決してオーバーフローしないことが保証され、割り算チェックにより次の条件が満たされることが保証されます。$c$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

t = int(input())
for _ in range(t):
    n, c = map(int, input().split())
    s = input().strip()
    
    res = 1
    i = 0
    while i < n:
        if s[i] == '1':
            cnt = 0
            while i < n and s[i] == '1':
                cnt += 1
                i += 1
            res = (res * pow(2, cnt, MOD)) % MOD
        else:
            i += 1

    if res % c == 0:
        print(-1)
    else:
        print(res)
```このソリューションは、まず入力を効率的に読み取り、次に文字列を反復処理して 1 のブロックを識別します。 ブロックごとに、現在の結果に次の値を乗算します。$2^k$モジュロ$10^9+7$。 0 のブロックは乗算に寄与しないため、単純にスキップされます。 文字列を処理した後、モジュロチェックが行われます。$c$出力が問題の割り算要件を満たしていることを確認します。 

## 実用的な例

 インプットを考慮する`3 4 1001`。 この文字列の 1 と 4 の位置には 1 があります。1 の単一長ブロックが 2 つあります。 最初の 1 については、`res = 1 * 2 = 2`。 2番目の1については、`res = 2 * 2 = 4`。 ついに、`4 % 100 = 4`なので、出力は 4 になります。 

| ステップ | 私 | s[i] | CNT | 解像度 |
 | --- | --- | --- | --- | --- |
 | 開始 | 0 | '1' | 0 | 1 |
 | 最初のブロックを処理 | 0-0 | '1' | 1 | 2 |
 | ゼロをスキップ | 1-2 | '0' | - | 2 |
 | 2 番目のブロックを処理 | 3 | '1' | 1 | 4 |

 のために`3 1 111`、3 つ連続する 1 のブロックが 1 つあります。`res = 1 * 2^3 = 8`。 以来`8 % 1 == 0`の場合、出力は -1 です。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    MOD = 10**9 + 7
    out = []
    t = int(input())
    for _ in range(t):
        n, c = map(int, input().split())
        s = input().strip()
        res = 1
        i = 0
        while i < n:
            if s[i] == '1':
                cnt = 0
                while i < n and s[i] == '1':
                    cnt += 1
                    i += 1
                res = (res * pow(2, cnt, MOD)) % MOD
            else:
                i += 1
        if res % c == 0:
            out.append("-1")
        else:
            out.append(str(res))
    return "\n".join(out)
