 ## 解決策
 ## 問題の理解

 サイバーランドの都市を表す接続された無向グラフでクエリを処理するように求められます。 各都市にはお土産の価格があり、道路は都市のペアを結んでいます。 クエリ タイプは 2 つあります。1 つは都市のお土産の価格を更新するクエリ、もう 1 つは 2 つの都市間の単純なパスに沿った最小のお土産の価格を尋ねるクエリです。 単純な道では都市を再訪することはできません。 

入力により、都市、道路、クエリの数が提供され、次に各都市の価格、道路接続、およびクエリのシーケンスが提供されます。 出力は旅行クエリごとに 1 つの数値で、指定された 2 つの都市間の有効なルートに沿ったお土産の最低価格を表します。 

制約を考慮すると、グラフは非常に大きくなる可能性があります (最大 10^5 のノードとエッジ、および 10^5 のクエリ)。 各旅行クエリの単純なパスをすべて列挙する単純なアプローチは実行不可能です。 最悪の場合、すべてのパスを列挙すると都市の数が指数関数的に増加し、2 秒で処理するのは不可能になります。 この問題は、価格の動的な更新によってさらに複雑になり、すべてのペアごとの最小値を一度に前処理することができなくなります。 

明らかではないエッジ ケースには、パス上の最も安価な都市が開始都市または終了都市である場合、または異なる極小値を持つ複数のパスが存在する場合が含まれます。 たとえば、価格の三角グラフでは`[3,1,2]`、都市 1 から 3 までの最低価格は、直接エッジ 1-3 を介した 2 ではなく、パス 1-2-3 を介した 1 です。 更新が発生すると、以前は最適だったパスが最小ではなくなる可能性があるため、動的なアプローチが必要になります。 

## アプローチ

 ブルートフォース手法では、各旅行クエリの開始都市と終了都市の間のすべての単純なパスを検索し、各パスに沿った最低価格を計算しようとします。 これは正しいですが、最大 10^5 のノードとエッジを使用すると、単純なパスの数が指数関数的に増加する可能性があり、時間の複雑さが管理できなくなります。 各クエリの深さ優先検索でもクエリごとに O(n + m) がヒットし、結果は O(q * (n + m)) となり、最悪の場合は 10^10 になります。 これでは遅すぎます。 

重要な洞察は、接続された無向グラフでは、2 つのノード間のパスに沿った最低価格は、両方のノードを含む接続コンポーネントの最低価格によって決定されるということです。 グラフ内のサイクルにより、コンポーネント内の任意の都市に制限なく移動できます。 したがって、接続された各コンポーネントについて、パスに沿った最小価格は、単にそのコンポーネント内の都市の最小価格になります。 都市の価格が変化した場合、そのコンポーネントの最低価格を更新するだけで済みます。 

これにより、問題は動的な接続コンポーネントの最小クエリの問題に帰着します。 Union-Find (Disjoint Set Union、DSU) はコンポーネントを効率的に管理できますが、各コンポーネントの最低価格を追跡する必要もあります。 セットあたりの最低価格を維持するために、DSU 構造を強化します。 更新された都市が以前に最小値であった場合、価格の更新ごとにコンポーネントの最小値の再計算が必要になる場合があります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとのブルート フォース DFS | O(q * (n + m)) 最悪の場合 | O(n + m) | 遅すぎる |
 | コンポーネント最小追跡機能を備えた DSU | O((n + m + q) * α(n)) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. の Union-Find 構造体を初期化します。`n`都市。 各都市は独自のコンポーネントとして開始され、コンポーネントの最低価格は都市の現在の価格に初期化されます。 
2. 全体を反復処理する`m`道路。 都市を結ぶそれぞれの道路に`u`そして`v`、それらのコンポーネントを結合します。 マージするときは、2 つのコンポーネントの最小値のうち小さい方になるようにコンポーネントの最小値を更新します。 
3. を処理します。`q`順次クエリを実行します。 「C a w」タイプのクエリの場合は、都市の価格を更新します。 都市がそのコンポーネントの現在の最小値である場合、コンポーネント内のすべての都市をスキャンしてコンポーネントの最小値を再計算します。 それ以外の場合は、保存されている都市の価格を更新するだけです。 
4. 「A a b」タイプのクエリの場合、両方の都市のルート コンポーネントを見つけます。 それらが同じコンポーネント内にある場合は、コンポーネントに保存されている最低価格を返します。 接続が切断されている場合 (問題により不可能であることが保証されます)、それに応じて処理してください。 

機能する理由: 無向接続コンポーネントでは、任意の 2 つの都市が少なくとも 1 つの単純なパスで接続されます。 同じコンポーネント内の 2 つの都市間のパスの最低価格は、そのコンポーネントの最低価格より小さくすることはできません。また、最小価格で都市を通過するパスを常に選択できます。 コンポーネントの最小値を維持すると、各クエリが一定時間内に正しい結果を返すことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n, prices):
        self.parent = list(range(n))
        self.min_price = prices[:]
        self.size = [1]*n

    def find(self, x):
        if self.parent[x] != x:
            self.parent[x] = self.find(self.parent[x])
        return self.parent[x]

    def union(self, x, y):
        x_root = self.find(x)
        y_root = self.find(y)
        if x_root == y_root:
            return
        if self.size[x_root] < self.size[y_root]:
            x_root, y_root = y_root, x_root
        self.parent[y_root] = x_root
        self.size[x_root] += self.size[y_root]
        self.min_price[x_root] = min(self.min_price[x_root], self.min_price[y_root])

    def update_price(self, x, price):
        x_root = self.find(x)
        self.min_price[x_root] = min(price, self.min_price[x_root])

    def get_min(self, x):
        return self.min_price[self.find(x)]

n, m, q = map(int, input().split())
prices = [int(input()) for _ in range(n)]
dsu = DSU(n, prices)

for _ in range(m):
    u, v = map(int, input().split())
    dsu.union(u-1, v-1)

for _ in range(q):
    parts = input().split()
    if parts[0] == 'C':
        a, w = int(parts[1])-1, int(parts[2])
        prices[a] = w
        dsu.update_price(a, w)
    else:  # 'A'
        a, b = int(parts[1])-1, int(parts[2])-1
        print(dsu.get_min(a))
```このソリューションは、コンポーネントの最小価格で DSU を初期化し、道路に基づいて都市を結合し、クエリに効率的に回答します。 価格を更新するとき、コンポーネントの最小値が一貫していることが保証されます。 各旅行クエリは、開始都市を含むコンポーネントの保存された最小値を返すだけです。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n + m + q) * α(n)) | パス圧縮とサイズによるユニオンを使用した Union-Find により、クエリごとにほぼ一定の償却操作が保証されます。 
| スペース | O(n) | 各都市の親、サイズ、コンポーネントの最小値を保存する |

 これは、n、m、q ≤ 10^5 には十分であり、2 秒の時間制限と 256 MB のメモリ制限内に快適に収まります。
