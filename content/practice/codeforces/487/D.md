 ## 解決策
 ## 問題の理解

 コンベア ベルトで満たされたサイズ _n_ × _m_ の長方形のテーブルが与えられます。 各コンベア ベルトはどちらか上を向いています (`^`）、 左 （`<`)、または右 (`>`）。 テーブルの周りにはディナー席があり、列として論理的に番号が付けられています。`0`そして`n+1`とコラム`0`そして`m+1`。 パンをベルトコンベアに乗せると、パンはベルトの指示に従ってベルトに沿って移動し、テーブルの外の席に着きます。 パンがベルト内のサイクルに入った場合、シートに到達することはなく、無限ループに陥っていると報告する必要があります。 

テーブルは動的に更新されます。`q`2 種類のクエリ。`A x y`からのパンをシミュレートするように要求します`(x, y)`最終的な位置を報告するか、`-1 -1`無限ループした場合。`C x y c`でコンベアを変更します`(x, y)`新しいタイプに`c`。 

制約は大きくなります。`n`100,000 に達する可能性がありますが、`m`クエリ数も最大 100,000 で、変更クエリは最大 10,000 です。 これにより、クエリごとにテーブルの先頭から素朴にパンの動きをシミュレートすることが除外されます。`O(n*q)`ステップ数は 10^10 の操作に達する可能性があり、制限時間を大幅に超えます。 一方で、小さいのは、`m`これは、列方向の構造を効率的に活用できることを示唆しています。 

ベルトが 1 つまたは 2 つの列で小さなループを作成する場合、微妙なエッジ ケースが発生します。 たとえば、ベルトが上下を向いている 2 列のカラムでは、パンが無限に閉じ込められる可能性があります。 もう 1 つのケースは、非常口座席のすぐ隣でパンが始まる場合です。 それはすぐに出発します。 サイクルを検出しない単純なコードは永久にループします。 

## アプローチ

 ブルートフォースアプローチにより、あらゆるパンの動きをシミュレートします。`A`ステップバイステップでクエリを実行します。 各クエリについて、コンベアがテーブルから離れるまで、またはサイクルが検出されるまでコンベアを追跡します。 サイクルの検出は、訪問セットを使用して実行でき、単一のシミュレーション中に訪問したセルをマークします。 それは正しいことですが、コストがかかる可能性があります`O(n*q)`最悪の場合、大規模な場合は失敗します`n`と多くの問い合わせが。 

重要な観察は、ベルトが左、右、または上に動くため、列内の動きはほとんどが垂直であるということです。 と`m`最大 10 であれば、パンが最終的にテーブルから離れる場所、またはサイクルに入る場所をセルごとに事前計算できます。 この事前計算は、動的プログラミングを使用して、一番上の行から下に向かって実行できます。 複雑さは次のように比例します。`O(n*m)`最初にこのテーブルを構築します。 そうすれば、コンベアが変更されたときに、影響を受ける列を再計算するだけで済みます。これは効率的です。`m`は小さく、変更は最大 10,000 件です。 

最適なアプローチはセルごとに保存することに依存します`(x, y)`、その「出口点」`(tx, ty)`またはループのマーカー。 それぞれについて`A`クエリの場合は、単に保存された結果を返します。`C`クエリの場合、影響を受ける列の終了ポイントを再計算し、必要な場合にのみ更新を伝達します。 これにより、クエリごとの時間が潜在的に短縮されます。`O(n)`に`O(m)`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n*q) | O(n*m) | 遅すぎる |
 | 最適 | O(n_m + q_m) | O(n*m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テーブルの寸法を読む`n`、`m`そしてクエリの数`q`。 テーブルを文字列のリストとして保存します。 
2. を初期化します。`exit`サイズの配列`n x m`各位置の終了セルを保存するには、または`(-1, -1)`それがループにつながる場合。 
3. 再帰関数を定義する`dfs(x, y)`の出口を計算する`(x, y)`：

- もし`(x, y)`テーブルの外にあります、戻ります`(x, y)`すぐに。 
- もし`(x, y)`すでに計算されています`exit`、保存された値を返します。 
- マーク`(x, y)`サイクルを検出するための「訪問」として。 
- 次のセルを計算します`(nx, ny)`コンベヤのタイプに基づいて。 
- 再帰的に呼び出す`dfs(nx, ny)`。 
- 再帰呼び出しが戻った場合`(-1, -1)`、 マーク`(x, y)`サイクルの一部として、そして戻る`(-1, -1)`。 
- それ以外の場合は、出口を次の場所に保存します。`exit[x][y]`そしてそれを返します。 
4. を事前計算します。`exit`実行による配列`dfs(x, y)`すべての細胞に。 
5. 各クエリについて:

 - そうだとしたら`A x y`、事前計算された終了点を出力します。`exit[x-1][y-1]`。 
- そうだとしたら`C x y c`、テーブルを更新し、影響を受ける列の出口を無効にします。 を再計算します`exit`を使用してその列のすべての行の値を取得します`dfs`。 
6. すべての結果を返す`A`順番にクエリを実行します。 

正確さは、各セルが最終的な出口を持つか、サイクルの一部としてマークされるかのいずれかの不変条件に依存します。 コンベアの更新は、その上の同じ列のセルにのみ影響します。`dfs`伝播により、変更のたびに常に正しい出口が計算されるようになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**6)

n, m, q = map(int, input().split())
table = [list(input().strip()) for _ in range(n)]
exit_pos = [[None]*m for _ in range(n)]
visiting = [[False]*m for _ in range(n)]

def dfs(x, y):
    if x < 0:
        return (0, y+1)
    if x >= n:
        return (n+1, y+1)
    if y < 0:
        return (x+1, 0)
    if y >= m:
        return (x+1, m+1)
    if visiting[x][y]:
        return (-1, -1)
    if exit_pos[x][y] is not None:
        return exit_pos[x][y]

    visiting[x][y] = True
    c = table[x][y]
    if c == '^':
        nxt = dfs(x-1, y)
    elif c == '<':
        nxt = dfs(x, y-1)
    else:  # '>'
        nxt = dfs(x, y+1)
    visiting[x][y] = False
    exit_pos[x][y] = nxt
    return nxt

# Initial computation
for i in range(n):
    for j in range(m):
        if exit_pos[i][j] is None:
            dfs(i, j)

for _ in range(q):
    parts = input().split()
    if parts[0] == 'A':
        x, y = int(parts[1])-1, int(parts[2])-1
        tx, ty = exit_pos[x][y]
        print(tx, ty)
    else:
        x, y, c = int(parts[1])-1, int(parts[2])-1, parts[3]
        table[x][y] = c
        # Invalidate and recompute column
        for i in range(n):
            exit_pos[i][y] = None
        for i in range(n):
            dfs(i, y)
```DFS は、サイクルが正しく検出されることを保証します。`visiting`。 再帰制限を増やす必要があるため、`n`最大 10^5 にすることができ、それ以外の場合はスタック再帰がオーバーフローする可能性があります。 コンベアを更新するときは、再計算を最小限に抑えるために列のみを無効にします。
