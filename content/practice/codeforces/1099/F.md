 ## 解決策
 ## 問題の理解

 各頂点にクッキーの山が含まれる根付きツリーが与えられます。 すべての頂点には、その頂点で 1 つのクッキーを食べるためのコストもあり、ノードからその親までのすべてのエッジには、それに沿って上に移動するためのコストがかかります。 チップは根元から始まります。 

2 人のプレイヤーがこの構造物を操作します。 Mitya は各ターンで子を選択することでチップを下に移動しますが、Vasya は現在のチップ位置から 1 つの出ていくエッジを削除するかスキップすることで進行をブロックできます。 ミーティアはいつでも止まるかもしれない。 彼が停止するとゲームは終了し、チップは現在のノードからルートに戻らなければなりません。 ダウンしてからアップする間、Mitya は訪問したノードで任意の数の Cookie を食べることができ、Cookie ごとにコストを支払います。 すべての移動と食事の合計コストは、固定予算 T を超えてはなりません。目標は、ヴァシャが妨害するために最適にプレイすると仮定して、ミーチャが食べられるクッキーの数を最大化することです。 

重要な問題は、Vasya がエッジを段階的に削除できることです。つまり、Mitya は完全なサブツリーが利用可能なままであると想定できないことを意味します。 Mitya が最終的に使用するパスは、この敵対的なプロセスに依存するため、最悪の場合のプルーニングの下で​​、ルートからノード、ルートへの可能な限り最善のルートを保証する戦略を効果的に探しています。 

この制約により、おおよそ O(n log n) または O(n) スタイルの推論が強制されます。 最大 100,000 のノードと最大 10^18 の非常に大きな T があるため、ゲームプレイをシミュレートしたり、パスを明示的に試行したりすることはできません。 すべてのパスを考慮したり、段階的にインタラクションをシミュレートしようとするソリューションは、各ノードの選択が分岐し、Vasya の削除によってさらに分岐が追加されるため、組み合わせ爆発が発生します。 

Vasya を完全に無視し、ツリー上の貪欲または DP によってルートから葉への最適なパスを選択するだけの場合、微妙な失敗のケースが発生します。 これは、Vasya がエッジを削除することで Mitya を局所的に最適なブランチから強制的に遠ざけることができることを無視しています。 食事効率 t_i を考慮せずに距離コストのみを最適化すると、別の失敗ケースが発生します。これは、食事とトラバーサルが組み合わされているためです。時間予算に比べて食事にコストがかかる場合、多くの Cookie を持つノードは依然として悪い可能性があります。 

## アプローチ

 直接的な総当たり解釈は、ゲーム ツリーをシミュレートすることです。 各ステップで、Mitya は子を選択し、Vasya は 1 つのエッジを削除します。そして、Mitya がすべての可能なノードで停止するまで、結果として得られる可能性のあるすべてのサブツリーを探索します。 停止時間では、上りパスでの最適な時間配分を評価します。 これはすぐに指数関数的に増加します。移動するたびに子が分岐し、Vasya の削除により、残りのツリーの組み合わせが爆発的に増加します。 チェーン上でもこれはなんとかなりますが、枝分かれしたツリーでは n が 20 付近を超えると不可能になります。 

重要な観察は、Vasya の削除は、Mitya がどのサブツリーの探索を継続できるかを制御していると解釈できるということですが、最適なプレイ均衡では、各ノードで利用可能な最良の継続のみが重要になります。 明示的なゲーム状態を追跡する代わりに、兄弟サブツリーがブロックされる可能性があるという事実を考慮しながら、Mitya がノードに到達し、その後最適に下方に進んだ場合に保証される最良の結果を各ノードに対して計算するプロセスとして再解釈します。 

これにより、たどることのできる子パスが 1 つだけであり、そのパスが制約の下で達成可能な最適なパスであることを反映する方法で、子からの寄与を組み合わせて各ノードを評価するツリー DP が得られます。 2 番目の変換は、「クッキーの数」から「時間予算の実現可能性」に移行することです。固定された候補の答え k (食べられたクッキー) に対して、最適な再生制約の下で時間 T 内に k 個のクッキーを収集できるルートツールート ツアーが存在するかどうかを尋ねることができます。 これにより、問題は単調な実現可能性チェックに変換されます。

次に、答えを二分探索します。 各ノードについて、降下コストと上昇コストと食事コストの両方を考慮して、有効なパスに沿ったサブツリー内の k 個の Cookie を収集するのに必要な最小時間を計算します。 1 回の走査では 1 つの分岐のみをたどることができるため、DP は実行可能な最適な継続を選択して子をマージします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(2^n) | O(n) | 遅すぎる |
 | ツリー DP + 二分探索 | O(n log T log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 この問題を、時間 T 内に指定された数 k の Cookie を収集できるかどうかを確認するものとして再定式化します。 

1. 値 k を固定し、Mitya がルートから開始してルートに戻るまでに少なくとも k 個の Cookie を収集することを保証できるかどうかを判断しようとします。 これにより、最適化が実現可能性のチェックに変換されます。 
2. 敵対的ブロックにより完全に利用できるのは 1 つの子ブランチのみであることを考慮しながら、サブツリー内の最大 k 個の Cookie を収集するのに必要な最小時間を表す DP 状態を各ノードで定義します。 DP は下向きの動きと上向きの戻りの両方を考慮します。 
3. ツリーの事後走査を実行して、親の前に子が処理されるようにします。 これにより、ノードを処理するときに、すべての子孫から達成可能な最良の結果がすでにわかっていることが保証されます。 
4. 各ノードについて、ノード自体で Cookie を収集することと、場合によっては 1 つの選択された子サブツリーに拡張することという 2 つのコンポーネントを考慮します。 敵対的エッジ削除では 1 つの継続パスのみが実行可能であるため、子を合計するのではなく、子の中から最良のものを取得します。 
5. 親と子の間で遷移するときに移動コスト l_i を組み込み、ルートに戻るときに、選択したパスに沿って蓄積された上向きエッジ コストが含まれることを確認します。 
6. また、k に到達するために必要な残りの予算まで、各ノードで選択した Cookie の数に比例した時間を消費するものとして Cookie の収集を扱うことにより、Cookie あたりの食事コスト t_i も考慮します。 
7. 与えられた k の DP 実現可能性を計算した後、合計時間が T 以内に収まるかどうかを確認します。可能であれば、二分探索を使用してより大きな k を試し、そうでない場合はより小さな k を試します。 
8. 最終的な答えは、実現可能性を通過する最大の k です。 

### なぜ効果があるのか

 敵対的削除モデルでは、すべての分岐選択肢が 1 つの強制パスに折りたたまれます。これは、Mitya がプレイのセグメントごとに 1 つの生き残った子チェーンからのみ恩恵を受けることができるためです。 コレクションを複数のサブツリーに分散しようとする試みは、Vasya が代替の継続を削除することによって中断される可能性があるため、最適な再生は常に任意のノードから下位の単一の最適なパスに集中します。 DP は、複数のサブツリーを集約するのではなく、常に最適な子継続を選択することでこれを実現します。 k の単調性により、二分探索の正確性が保証されます。k 個の Cookie が達成可能であれば、同じ戦略構造の下でそれより小さい数も達成可能です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n, T = map(int, input().split())
x = list(map(int, input().split()))
t = list(map(int, input().split()))

children = [[] for _ in range(n)]
parent = [-1] * n
move_cost = [0] * n

for i in range(1, n):
    p, l = map(int, input().split())
    p -= 1
    parent[i] = p
    move_cost[i] = l
    children[p].append(i)

# We will binary search answer k
# Check if k cookies can be collected

def feasible(k):
    # dp[u] = minimal time contribution if we try to collect k cookies in subtree of u
    dp = [0] * n
    cnt = [0] * n

    def dfs(u):
        total_cookies = 0
        best_child = 0

        for v in children[u]:
            dfs(v)

        # take cookies at u greedily
        take = min(x[u], k)
        total_cookies = take

        # collect best single child contribution
        best = 0
        for v in children[u]:
            best = max(best, dp[v] + move_cost[v])

        dp[u] = take * t[u] + best
        cnt[u] = total_cookies

    dfs(0)
    return dp[0] <= T

# binary search
lo, hi = 0, sum(x)
ans = 0

while lo <= hi:
    mid = (lo + hi) // 2
    if feasible(mid):
        ans = mid
        lo = mid + 1
    else:
        hi = mid - 1

print(ans)
```この実装では、対話を Cookie の数に対する二分探索に圧縮しようとします。 DFS は、ノードごとに、最適な子拡張機能に、ノード自体で Cookie を食べるコストを加えたものを計算します。 重要な実装の詳細は、最適なプレイ シナリオで効果的に使用できるブランチが 1 つだけであることを反映して、子を結合するのではなく、子全体の最大値のみを取得するようにすることです。 子サブツリーに入るときに移動コストが追加され、クッキーを食べるコストは x[u] * t[u] として線形に累積されますが、上限は k です。 

微妙な点は、DP は分岐を選択するとサブツリー間の独立性を仮定するということですが、これは敵対的削除解釈の下での正確性のために不可欠です。

 ## 特殊なケース

 最小の単一ノード ツリーにより、DP が子処理を必要とせず、x[1] によって正しくキャップされることが確認されます。 チェーン状のツリーは、移動コストが分岐の曖昧さなしに 1 つのパスに沿って正しく蓄積されるかどうかをテストします。 星型ツリーでは、アルゴリズムが子サブツリーを 1 つだけ選択するように強制され、子間の誤った合計が過大にカウントされるかどうかが明らかになります。 ゼロウェイト エッジは、DP の蓄積に除算や順序付けの問題を導入することなく、実装が自由な動きを正しく処理するかどうかをテストします。
