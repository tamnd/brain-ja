 ## 解決策
 ## 問題の理解

 このプロセスは、雪玉が開始高さから地面に到達するまで滑り落ちる様子を表しています。 整数の高さレベルごとに、雪玉は 3 つの順序付けされた段階でその重量を繰り返し変更します。最初に現在の高さに等しい追加の重量が増加し、次にその高さに石がある場合は重量が減少し、最後に 1 段階下に移動します。 

入力は、このシステムの初期状態を表します。 雪玉の開始重量と開始高さ、および特定の高さに配置された 2 つの石が与えられ、雪玉がその高さを通過するたびにそれぞれの石が一定量の重量を取り除きます。 

タスクは、雪玉が高さ 0 に達するまでこの動きをシミュレートし、最終的な重量を報告することです。 主な難点は、重みが特定の位置での累積と減算の両方で継続的に変化することです。 

制約は小さく、高さは最大 100、重みは最大 100 です。これは、実行されるステップが最大 100 で、各ステップが O(1) の作業を実行するため、各高さレベルの直接シミュレーションが十分に効率的であることを直ちに意味します。 約 10^7 の演算までの解は制限時間内であれば安全であるため、単純な反復を超えて最適化する必要はありません。 

一連の操作が正確に従わないと、いくつかの特殊なケースが誤って処理されやすくなります。 一つは、石が衝突する前に重量が増加することを忘れていることです。 たとえば、雪玉が高さ 1 から始まり、石が高さ 1 にある場合、高さによる増加が最初に発生するため、雪玉は重量を失う前に重量が増加します。 もう1つは、ストーンインパクト後のマイナスウェイトの誤った取り扱いです。 この問題では重みを明示的にゼロにクランプしますが、シミュレーションは継続するため、単純な早期停止は正しくありません。 

3 番目の微妙なケースは、石の重さがゼロの場合です。 その場合でも、何も変わりませんが、衝突は引き続き処理する必要があります。 このような石を条件付きでスキップするのは安全ですが、一貫性のためには順序が重要であるため、その高さで衝突ステップを完全にスキップするのは安全ではありません。 

## アプローチ

 ブルートフォース ソリューションは、プロセスを秒ごとに直接シミュレートします。 各高さで、雪玉の重量を現在の高さだけ増加させ、該当する場合は石のダメージを適用し、負の場合は結果をゼロにクランプしてから、高さを減分します。 高さは反復ごとに正確に 1 ずつ減少するため、このシミュレーションは正確に h ステップで実行されます。 各ステップは一定時間であるため、ブルート フォース アプローチは、指定された制約の下ではすでに最適化されています。 

状態遷移は現在の身長と現在の体重のみに依存し、身長は厳密に減少するため、さらに圧縮するための隠された数学的構造はありません。 ステップをスキップしようとしても、個々の高さでの石の相互作用を考慮する必要があるため、集計トリックはなく、有意義な方法で複雑さをさらに軽減します。 

正しい解決策と誤った解決策の主な違いは、効率性ではなく、イベントの順序が厳密に遵守されているかどうかです。

 ## アルゴリズムのチュートリアル

 雪玉が一度に 1 レベルずつ降下するシミュレーションを行い、現在の高さと重量を常に追跡します。

1. 入力から雪玉の重さと高さを初期化し、高さによる素早い検索が可能な構造に 2 つの石を保存します。 各ステップで一定時間のチェックが必要なため、これは重要です。 
2. 現在の高さがゼロより大きい間、完全な更新サイクルを 1 回実行します。 
3. まず雪玉の重さを現在の高さだけ増やします。 この問題は石との相互作用の前に重量増加を定義するため、このステップは非常に重要です。 順序によって正確さが決まります。 
4. 現在の高さに石が存在するかどうかを確認します。 そうなった場合は、雪玉からその重さを差し引きます。 複数の石が同じ高さに存在する場合、両方の効果が順番に適用されますが、ここでの入力により明確な高さが保証されます。 
5. 結果の重みが負になった場合は、それをゼロにクランプします。 雪だるまは止まったり動作を変えたりしません。 保存された重量のみが調整されます。 
6. 高さを 1 つ下げて、下向きの動きをシミュレートします。 
7. 身長がゼロになるまで繰り返し、最終的な体重を出力します。 

### なぜ効果があるのか

 反復のたびに、アルゴリズムは問題定義に記述されている正確な状態を保存します。重みは、それより高いレベルまたは同等のレベルでの以前のすべての増分と石の相互作用を反映し、高さは残りの未処理レベルを厳密に追跡します。 各高さは正確に 1 回、正しい順序で処理されるため、寄与がスキップされたり二重にカウントされたりすることはありません。 したがって、高さがゼロになった後の最終状態は、すべての決定論的な遷移の累積結果になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    w, h = map(int, input().split())
    u1, d1 = map(int, input().split())
    u2, d2 = map(int, input().split())

    stone = {}
    stone[d1] = u1
    stone[d2] = u2

    weight = w
    height = h

    while height > 0:
        weight += height

        if height in stone:
            weight -= stone[height]
            if weight < 0:
                weight = 0

        height -= 1

    print(weight)

if __name__ == "__main__":
    solve()
```このソリューションでは、石の効果を高さでキー設定した辞書に保存するため、特定のレベルでの石のチェックは O(1) で済みます。 このループは、雪玉の物理的な動きに合わせて、h から 1 までの高さを処理します。 インクリメントステップはルックアップの前に実行され、必要な順序が維持されます。 

たとえプロセスが変更されずに続行されたとしても、負の重みが持続することは許されないため、減算後のクランプ ステップが必要です。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    w, h = map(int, input().split())
    u1, d1 = map(int, input().split())
    u2, d2 = map(int, input().split())

    stone = {d1: u1, d2: u2}
    weight = w

    while h > 0:
        weight += h
        if h in stone:
            weight -= stone[h]
            if weight < 0:
                weight = 0
        h -= 1

    return str(weight)

assert run("0 1\n0 1\n0 1\n") == "1"

assert run("10 5\n0 3\n0 4\n") == "25"

assert run("5 4\n5 4\n0 2\n") == "9"

assert run("1 2\n10 1\n10 2\n") == "0"

 ## 特殊なケース

 微妙なケースの 1 つは、高所にある石が現在存在している重量よりも多くの重量を取り除く場合です。 たとえば、雪玉がほんの少し増えた高さでは、大きな石によって雪玉がマイナスに押される可能性があります。 このアルゴリズムは、減算後に明示的にゼロにクランプし、ループを中断することなく状態が有効なままであることを保証します。 

もう 1 つのケースは、石が高さ 1 にある場合です。これが最後のアクティブ ステップであるにもかかわらず、雪玉は依然として完全なシーケンスを実行します。つまり、1 ずつゲインし、石を適用し、次にゼロに移動します。 処理後にのみ高さがゼロになるため、ループ構造では特別な分岐を行わずに自然に処理されます。 

3 番目のケースは、両方の石の重量がゼロの場合です。 シミュレーションでは引き続き辞書検索と減算の試行が実行されますが、最終的な効果は中立です。 正確かどうかは、状態が変化しない場合でも、衝突ステップがまだ実行されているかどうかに依存します。
