 ## 解決策
 ## 問題の理解

 ノード 1 をルートとするツリー状の状態構造が与えられます。ここで、新しい状態はそれぞれ以前の状態に接続され、接続には小文字が付けられます。 すべてのノードは、ルートからそのノードまでの一意のパスに沿って文字を読み取ることによって形成される文字列に対応します。 

各ノードについて、ルートからノードまでの文字列を調べ、その文字列に最小のピリオドがあるかどうかを調べます。 長さ P の短い文字列を少なくとも 2 回繰り返すことによって文字列を構築できる場合、ピリオド P は有効です。 すべてのノードの中で、最大の最小期間が必要です。 

したがって、タスクは単純な方法でノードごとに独立して期間を計算することではなく、ルートからノードまでのすべての文字列にわたって最大の「繰り返し構造の強度」を見つけることです。 

入力制約では最大 100,000 ノードが許可されるため、各ノードの文字列の長さを O(n) にすることもできます。 文字列の周期性をノードごとに O(length) で最初から再計算するソリューションは、O(n^2) まで低下します。これは、一般的な 1 ～ 2 秒の制限で許容される値をはるかに超えています。 

文字列がほぼ周期的であるが、完全には周期的ではない場合、微妙な問題が発生します。 たとえば、「abababa」のような文字列は強力な構造を持っていますが、完全な繰り返しには失敗しますが、「ababab」は完全に周期的です。 フルタイリングを強制せずにプレフィックスとサフィックスの同等性のみをチェックする単純なアプローチでは、文字列の一部のみが一致するケースを誤って受け入れてしまいます。 

もう 1 つの特殊なケースは、この問題では、単一文字または非反復文字列が定義により周期性 0 に寄与するはずであるということです。 たとえば、「abc」を形成するパスには有効な繰り返しがないため、最大値に影響を与えてはなりません。 

## アプローチ

 ブルートフォースアプローチは簡単です。 各ノードについて、ルートから完全なパス文字列を構築し、1 から文字列長の半分までのすべての可能な期間長 P をテストします。 各候補 P について、すべての文字が前の 1 つの P 位置と一致するかどうかを検証します。 有効な P が存在する場合は、そのような最小の P を記録します。 

これは周期性の定義を直接チェックするので正しいです。 ただし、各文字列の構築にはノードごとに累積的に O(n) のコストがかかり、すべての期間のチェックにはさらに O(n) かかるため、各ノードのコストは O(パスの長さ) になります。 すべてのノードを合計すると、O(n^2) になりますが、n が 100000 に達すると、これでは遅すぎます。 

重要な点は、実際には完全な文字列を実体化する必要がないということです。 すべてのノードの文字列はツリー内の根から葉へのパスのプレフィックスであるため、問題はパスに沿った周期構造に関するものです。 構造を最初から再計算するのではなく、情報を段階的に維持します。 

重要な構造的洞察は、周期性が一定距離離れた位置の一致に依存し、これらの位置が祖先チェーンに沿って存在するということです。 2 つのノード上の文字を任意の深さで効率的に比較できれば、周期性をツリー全体の動的なプロパティとして扱うことができます。 

これは、ルート パス上でローリング ハッシュまたはプレフィックス ハッシュを使用することを示唆しています。 ハッシュを使用すると、O(1) で部分文字列の同等性をチェックできるため、そのプレフィックスがそれ自体のシフトされたバージョンと等しいかどうかを検証することで、ノードの周期性をテストできるようになります。 

「このノードの文字列はピリオド P で周期的であるか」をすばやくテストできたら、引き続き最小の有効な P を見つける必要があります。すべての P を単純にスキャンする代わりに、有効なピリオドが構造的な意味で文字列長を分割する必要があるという事実を利用し、プレフィックス関数 (KMP) と同様の障害リンク スタイルの推論を再利用できます。 これにより、ノードごとにその文字列の最も長い適切な境界を維持し、そこから周期性を導き出すことができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 |---|---|---|---|
 | ブルートフォース | O(n^2) | O(n^2) | 遅すぎる |
 | 最適 (ツリー + プレフィックス関数 / ハッシュ) | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各ノードはより小さい親インデックスに依存するため、ノードを昇順に処理します。

1. 各ノードについて、ローリング ハッシュと深度追跡を使用して、ルートからノードへの文字列の表現を定義します。 これにより、ノードで終わるプレフィックスを一定時間で比較できるようになります。 

2. 各ノードの文字列に対して KMP スタイルのプレフィックス関数を計算しますが、最初から再計算するのではなく、親の構造を 1 文字拡張します。 これが機能するのは、ノードを追加すると親の文字列に 1 文字だけが追加されるためです。 

3. ノード i について、そのプレフィックス関数値 pi[i] を計算します。これにより、その文字列のサフィックスでもある最長の適切なプレフィックスが得られます。 この値は、文字列内の最大の自己オーバーラップをキャプチャします。 

4. pi[i] から、候補期間長を len[i] - pi[i] として導出します。 これは、プレフィックスとサフィックスの構造を調整する最小のシフトです。 

5. この期間が少なくとも 2 回繰り返されるという意味で有効かどうかを確認します。 これは、len[i] が候補ピリオドで割り切れるかどうか、または繰り返し構造によって文字列が完全に再構成されているかどうかをチェックすることと同じです。 有効な場合、グローバル最大周期を更新します。 

6. すべてのノードに対してこのプロセスを継続し、常にプレフィックス関数の状態をツリーに沿って伝播します。 

### なぜ効果があるのか

 prefix 関数は、文字列のすべての境界情報をエンコードします。つまり、接尾辞でもあるすべての可能な接頭辞がキャプチャされます。 周期性とは、ピリオドによるシフトが文字列全体の平等性を維持することを意味するため、有効なピリオドはすべて境界の繰り返しパターンに対応する必要があります。 

すべてのノードの文字列は、最後に追加される 1 文字だけ親と異なるため、すべての境界線の関係はローカルで更新されます。 これにより、候補期間を決して見逃すことがなくなり、プレフィックス関数により、最小の繰り返し構造が常に最長の境界から導出されることが保証されます。 その結果、すべての有効な周期文字列が正しく検出され、すべてのノードの最大値が正確になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    parent = list(map(int, input().split()))
    s = input().strip()

    g = [[] for _ in range(n)]
    for i, p in enumerate(parent, start=1):
        g[p - 1].append(i)

    pi = [0] * n
    ans = 0

    stack = [(0, 0, 0)]  # node, prefix function value, depth

    # We simulate DFS carrying KMP state
    def dfs(u, p, cur_pi):
        nonlocal ans
        depth = cur_pi
        if u != 0:
            c = s[u - 1]
            j = p
            while j > 0 and s[j] != c:
                j = pi[j - 1]
            if j < u and s[j] == c:
                j += 1
            pi[u] = j
            depth = j

            length = u + 1
            if depth > 0:
                period = length - depth
                if length % period == 0:
                    ans = max(ans, period)

        for v in g[u]:
            dfs(v, u, depth)

    dfs(0, 0, 0)
    print(ans)

if __name__ == "__main__":
    solve()
```このコードはツリーを構築し、各ノードのルート パス文字列の形成時にプレフィックス関数の値を計算します。 DFS は、各ノードがその親の一致する状態を継承することを保証し、これにより KMP 遷移がエッジごとに償却定数時間で発生することが可能になります。 

周期性チェックは、プレフィックス関数を計算した直後に実行されます。これは、その値がすでに最大の境界を決定しており、したがって候補となる繰り返し構造が決定されているためです。 

よくある落とし穴は、KMP 障害チェーンの代わりに生の親インデックスを使用してプレフィックス値を再計算しようとすることです。 そうなると、線形時間の保証が破られ、不一致が過剰にカウントされてしまいます。 

## 実用的な例

 「ababab」を形成するラベルを持つ単純なチェーンを考えてみましょう。 各ノードは前の文字列を拡張します。 

| ノード | 文字列 | 円周率 | 期間 | 有効？ |
 |---|---|---|---|---|
 | 1 | | 0 | - | いいえ |
 | 2 | アブ | 0 | 2 | いいえ |
 | 3 | アバ | 1 | 2 | いいえ |
 | 4 | アバブ | 2 | 2 | はい |
 | 5 | アババ | 3 | 2 | いいえ |
 | 6 | アババブ | 4 | 2 | はい |

 このトレースは、繰り返し構造が蓄積するにつれてプレフィックス関数がどのように増加するか、および最後の完全なアライメントのみが有効な期間を生成する様子を示しています。 

ここで、「abcde」のような非周期的なチェーンを考えてみましょう。 

| ノード | 文字列 | 円周率 | 期間 | 有効？ |
 |---|---|---|---|---|
 | 1 | | 0 | - | いいえ |
 | 2 | アブ | 0 | 2 | いいえ |
 | 3 | ABC | 0 | 3 | いいえ |
 | 4 | ABCD | 0 | 4 | いいえ |
 | 5 | ABCDE | 0 | 5 | いいえ |

 これは、境界が存在しないと全体の周期性がゼロになることを裏付けています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 |---|---|---|
 | 時間 | O(n) | 各ノードは 1 回処理され、KMP 遷移はエッジごとに償却されます。 
| スペース | O(n) | ツリーストレージとプレフィックス関数配列 |

 ## 特殊なケース

 単一ノード ツリーの場合、パス文字列の長さは 1 であり、繰り返しシーケンスを形成できないため、プレフィックス関数は 0 のままで、アルゴリズムは正しく 0 を返します。 

「aaaaa」のような完全に均一なチェーンの場合、すべての拡張によりプレフィックス関数が現在の長さから 1 を引いた値に増加し、すべてのノードでピリオド 1 が生成されます。 すべての文字が以前の境界と一致するため、DFS はこれを継続的に維持し、各ステップで最大値が更新されます。 

「ababab」などの交互パターンの場合、接頭辞関数は振動しますが、均一な深さで安定した境界に収束します。 境界の長さによって繰り返し構造がすでにエンコードされているため、アルゴリズムはすべての約数を明示的にチェックすることなくこれを取得します。
