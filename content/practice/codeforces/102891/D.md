 ## 解決策
 ## 問題の理解

 都市は塔の列として表され、それぞれの塔の高さは正の値になります。 非常に特殊な操作を繰り返し実行することができます。つまり、1 つのタワーを選択して隣接するタワーに移動し、それらを 2 つのタワーの合計の高さになる 1 つのタワーに統合します。 結合後は 2 つの位置が 1 つのタワーになるため、タワーの合計数は 1 つ減ります。 

このような結合を何回行っても、左から右への高さが減少していなければ、残りの一連のタワーは「良好」であるとみなされます。 タスクは、そのような適切な構成に到達するために必要なマージ操作の最小数を見つけることです。 

これをより構造的な方法で再構成すると、元の配列を連続したセグメントに圧縮することになります。 各セグメントは最終的な塔に対応し、その高さは内部の要素の合計になります。 マージは隣接セグメント間でのみ発生するため、操作ルールはセグメントが連続している必要があることを保証します。 

目標は、セグメントの数を最大化しながら、セグメントの合計が左から右に減少しないように、配列のセグメントへの分割を選択することです。 マージごとにセグメントの数が 1 つずつ減るため、操作を最小限に抑えることは、保持できる有効なセグメントの数を最大限に増やすことと同じです。 

この制約により、最大 5000 のタワーが許可されます。 3 次の動作を伴う解決策は遅すぎるため、重い遷移を伴う 2 次のアプローチであっても境界線に達する可能性があります。 これは、線形または線形に近い貪欲な構造またはスタックベースの構造を強く示唆しています。 

単純な推論による微妙な失敗例は、ローカル マージが有益であるように見えても、実際には将来のより良い構造を妨げる場合に現れます。 たとえば、隣接するタワー間の減少が確認されるたびに貪欲にマージすると、早期に過剰にマージし、最終セグメントの数が不必要に減少する可能性があります。 正しい解決策は、元の値に対するローカルなペアごとの決定ではなく、セグメント合計のグローバルな単調性を強制する必要があります。 

## アプローチ

 強引な解釈では、シーケンスが減少しなくなるまで、隣接するタワーを結合するあらゆる可能な方法が試行されます。 操作ごとにタワーの数が 1 つずつ減り、各ステップで、結合する隣接するペアを選択できます。 マージのたびに構造が変化し、将来のマージの選択肢が異なるため、これにより膨大な分岐プロセスが作成されます。 配列のすべてのパーティションを連続セグメントに探索するようにこれをモデル化したとしても、パーティションの数は n で指数関数的になるため、非常に小さい入力を超えると実行不可能になります。 

重要な観察は、最終状態は連続セグメントへの分割によって完全に決定され、有効な分割に対する唯一の制約は、これらのセグメントの合計が左から右に減少しないことであるということです。 すべてのパーティションを検索する代わりに、有効性を維持しながら左から右へ貪欲に最適なパーティションを構築できます。 

決定的な構造は、A ≤ B > C となるような合計 A、B、C を持つ 3 つの連続するセグメントがある場合は常に、中央のセグメント B が実現可能性をブロックするということです。 B と C を結合すると、右側のセグメントが増加し、単調性が回復する可能性があります。 この動作は、離散シーケンスに対する等張回帰と同様に、セグメント合計のスタックを維持し、違反を即座に修復することで自然に処理されます。 

これにより、問題が 1 つのパスに変わり、単調性に違反するたびに後方へのマージが継続され、常に有効なセグメントの最大数で終了することが保証されます。

 ## アルゴリズムのチュートリアル

 各要素が最終パーティションのセグメントの合計を表すスタックを維持しながら、配列を左から右に処理します。

1. 空のスタックから開始します。 配列の各要素は、最初は独自のセグメントを形成します。 
2. 配列内の値ごとに、その単一の値を含む新しいセグメントを作成し、スタックにプッシュします。 
3. プッシュ後、最後の 2 つのセグメントが非減少順序に違反しているかどうかを確認します。つまり、最後から 2 番目のセグメントの合計が最後のセグメントより大きいことを意味します。 
4. このような違反が存在する場合は常に、最後の 2 つのセグメントを、それらの合計が合計となる単一のセグメントに置き換えることによってマージします。 次に、新しくマージされたセグメントが以前の隣接セグメントとの単調性に違反する可能性があるため、このチェックを再度繰り返します。 
5. スタックが空になるか、すべての隣接するセグメントの合計が非減少順になるまで、このプロセスを続けます。 
6. すべての要素を処理した後、スタックに残っているセグメントの数が最終タワーの可能な最大数であり、答えは実行されたマージの数であり、n からスタック サイズを引いたものに等しくなります。 

この繰り返しのマージが機能する理由は、隣接するセグメント間の違反を将来の要素によって後で修正できないためです。 より大きなセグメントが右側に表示される場合、左側の順序制約は役に立たないため、実現可能性を回復する唯一の方法は、問題のあるセグメントを直ちに結合することです。 

重要な不変条件は、各反復の後、スタックが処理されたプレフィックスの有効なパーティションを表し、そのようなパーティションすべての中で、非減少制約と一致するセグメントの最大可能数を維持することです。 違反が発生するたびにマージを遅らせても、セグメントの数を増やすことなく、避けられない修正を延期するだけであるため、即時マージすることで最適性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    stack = []

    for x in a:
        stack.append(x)

        while len(stack) >= 2 and stack[-2] > stack[-1]:
            stack[-2] = stack[-2] + stack[-1]
            stack.pop()

    # number of merges = n - number of segments
    print(n - len(stack))

if __name__ == "__main__":
    solve()
```この実装はセグメントの構造を直接反映しています。 各スタック要素は、1 つの現在のセグメントの合計です。 while ループは重要な修復ステップです。新しく形成されたセグメントが左隣のセグメントと比較して減少を引き起こすたびに、それらを直ちにマージします。 マージによって違反がさらに左に伝播する可能性があるため、繰り返し条件が必要です。 

最終的な答えは、実行された操作の数と一致するセグメント数の合計削減量として計算されます。 

## 実用的な例

 インプットを考慮する`5 8 2 7 3 1`。 

各挿入後にセグメント スタックを追跡します。 

| ステップ | 挿入されました | スタック (セグメントの合計) |
 | --- | --- | --- |
 | 1 | 8 | [8] |
 | 2 | 2 | [8, 2] → マージ → [10] |
 | 3 | 7 | [10, 7] → マージ → [17] |
 | 4 | 3 | [17, 3] → マージ → [20] |
 | 5 | 1 | [20, 1] → マージ → [21] |

 すべての新しい要素が小さすぎるため、減少しないセグメント合計を維持できないため、プロセスは継続的にマージされます。 最終的なスタックのサイズは 1 なので、答えは 5 − 1 = 4 回の演算となります。 

ここで考えてみましょう`3 5 2 1`。 

| ステップ | 挿入されました | スタック |
 | --- | --- | --- |
 | 1 | 5 | [5] |
 | 2 | 2 | [5, 2] → マージ → [7] |
 | 3 | 1 | [7, 1] → マージ → [8] |

 繰り返しますが、すべてが 1 つのセグメントに折りたたまれます。 このメソッドは、安定した分割が不可能であることを正確に識別します。 

これらのトレースは、プレフィックス全体が一貫性を持ち、グローバルな正確性が保証されるまで、アルゴリズムがローカルで単調性を繰り返し適用していることを示しています。 

## 複雑さの分析

| スペース | O(n) | スタックには、マージ前に要素ごとに最大 1 つの値が保存されます。

 ## 特殊なケース

 単一タワーの最小限の入力は、どの操作も順序を改善したり変更したりできないため、スタック ロジックがマージをトリガーせず、答えがゼロであることを示しています。 

次のような厳密に減少するシーケンス`4 3 2 1`すべてのステップで繰り返しマージをトリガーします。 新たに挿入するたびに累積されたセグメントに違反が発生し、マージを繰り返すとすべてが 1 つのセグメントにまとめられ、n − 1 個の操作が生成されます。 単調性が回復するまでマージごとにスタック サイズが削減されるため、アルゴリズムはこれを自然に処理します。 

のような局所反転が小さい場合`1 5 2 3`は、貪欲な隣接比較が不十分な理由を示しています。 値`2`とのマージを強制します`5`ただし、これにはプレフィックス全体を折りたたむ必要はなく、スタックは必要な場合にのみマージすることで最大のセグメンテーションを正しく保存します。
