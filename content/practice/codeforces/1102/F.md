 ## 解決策
 ## 問題の理解

 数値の長方形グリッドがあります。$n$行と$m$列。 行の順序は自由に変更できますが、各行内の数字の順序は固定されています。 注文を選択した後、グリッドを列ごとに上から下に移動し、訪問した数字を線形シーケンスに書き留めます。 タスクは最大の整数を見つけることです$k$このシーケンス内の連続する数値間の差異はすべて少なくとも$k$。 出力はこれが最大です$k$。 

制約は次のことを教えてくれます$n$は最大でも 16 と小さいですが、$m$と同じ大きさにすることができます$10^4$。 この組み合わせは、アルゴリズムが指数関数的に増加することを強く示唆しています。$n$実現可能ですが、それに合わせて拡張できるものは何でも$m^n$そうではありません。 各行には多くの数値があるため、大規模なデータに対して行の値のすべての順列を直接ブルート フォースすることはできません。$m$; 代わりに、行の順序に焦点を当てたアプローチが必要です。 

エッジケースには、すべての行が同一またはほぼ同一であるシナリオが含まれます。$k$非常に小さい行列、または一部の列では差が大きく、他の列では差が小さい行列です。 たとえば、次の場合$n = 3$、$m = 2$、行列は```
1 2
2 1
1 1
```最初の列だけを考慮する素朴な貪欲なアプローチは過大評価する可能性があります$k$。 正しいアプローチでは、連続する行が列ごとにどのように相互作用するかを考慮する必要があります。 

## アプローチ

 ブルートフォース手法では、行のすべての置換を試み、結果のシーケンスを計算し、連続する数値間の最小差をチェックします。 がある$n!$順列と各シーケンスは$n \cdot m$要素があるため、複雑さは$O(n! \cdot n \cdot m)$。 と$n = 16$そして$m = 10^4$、これはまったく不可能です。 

重要な観察点は、問題は各列の 1 つの行の最後の要素と次の行の最初の要素の間の最小の差のみに依存しているということです。 同じ列内の行のペア間の最大差を事前に計算できます。 以来$n$が小さい場合、行のサブセット (ビットマスク DP) に対して動的プログラミングを使用して、特定の候補の有効な順序を見つけることができます。$k$。 候補者にとって$k$、トラバーサル内のすべての連続するペアについて、数値の差が少なくとも次のような行の順列が存在するかどうかを確認します。$k$。 二分探索が可能$k$値を使用すると、最大値を効率的に見つけることができます。 

ブルート フォース アプローチは、小さな入力に対しては正確性が保証されるため機能しますが、大きな入力に対しては失敗します。$m$階乗行置換のため。 サブセットに対する DP が可能になる洞察は、行数が少ないため、使用される行をビットマスクとして表現できるということです。 任意の 2 つの行間の最小許容差を事前に計算することで、候補をチェックできるようになります。$k$効率的に価値を高めます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n! * n * m) | O(n*m) | 遅すぎる |
 | ビットマスク DP + 二分探索 | O(2^n * n^2 * m * log(最大値)) | O(2^n * n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての行のペア間の列方向の差を事前計算します。 2列用$i$そして$j$、行から開始するときに各列の最小絶対差を記録します。$i$漕ぐ$j$。 の最後の要素との違いも記録します。$i$そしての最初の要素$j$列間の隣接性の場合。 
2. 二分探索を設定します$k$。 下限は 0 から始まり、上限は考えられる最大の差になります。たとえば、$10^9$。 
3. 候補者にとって$k$、DP 配列を初期化します。`dp[mask][i]`サブセット内の行を順序付けできるかどうかを示します`mask`行で終わる`i`を満たす$k$-許容可能な状態。 
4. 基本ケース: 単一行の各サブセットは自明に有効であるため、`dp[1<<i][i] = True`。 
5. 行のすべてのサブセットを繰り返します。 サブセットごとに`mask`そして最後の行`last`、新しい行の追加を検討してください`next`入っていない`mask`。 間の最小の差があるかどうかを確認します`last`そして`next`すべての列にわたって、および最後の列と最初の列の境界をまたいで少なくとも`k`。 その場合は設定してください`dp[mask | (1<<next)][next] = True`。 
6. DP テーブルに記入した後、DP テーブルが存在するかどうかを確認します。`dp[(1<<n)-1][i]`は本当です。 「はい」の場合、候補者は$k$実現可能です。 そうしないと大きすぎます。 
7. 二分探索を使用して最大化します$k$。 検索後、最後に実行可能なもの`k`が答えです。 

機能する理由: DP は、ビットマスクを使用してサブセット内のすべての可能な行の順序を列挙し、追加された各行が最小の差を尊重するようにします。 すべてのサブセットとすべての行の組み合わせをチェックするため、有効な順序が見つかります。 二分探索により、実現可能な最大値に収束することが保証されます$k$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n, m = map(int, input().split())
    a = [list(map(int, input().split())) for _ in range(n)]

    # Precompute differences
    diff = [[0]*n for _ in range(n)]
    boundary = [[0]*n for _ in range(n)]
    for i in range(n):
        for j in range(n):
            if i == j:
                continue
            min_col = min(abs(a[i][c] - a[j][c]) for c in range(m))
            diff[i][j] = min_col
            boundary[i][j] = abs(a[i][-1] - a[j][0])

    def can(k):
        dp = [ [False]*n for _ in range(1<<n) ]
        for i in range(n):
            dp[1<<i][i] = True

        for mask in range(1<<n):
            for last in range(n):
                if not dp[mask][last]:
                    continue
                for nxt in range(n):
                    if mask & (1<<nxt):
                        continue
                    if diff[last][nxt] >= k and boundary[last][nxt] >= k:
                        dp[mask | (1<<nxt)][nxt] = True

        full_mask = (1<<n) - 1
        return any(dp[full_mask][i] for i in range(n))

    low, high = 0, 10**9
    answer = 0
    while low <= high:
        mid = (low + high) // 2
        if can(mid):
            answer = mid
            low = mid + 1
        else:
            high = mid - 1
    print(answer)

if __name__ == "__main__":
    main()
```事前計算ステップでは、すべての列のすべての行ペアの最小絶対差と境界差が計算されます。 の`can(k)`関数はビットマスク DP を使用して実現可能性をチェックします。 二分探索の更新`answer`そのときだけ`k`実現可能です。 ビットマスクを使用すると、冗長な計算を行わずにすべての行の順序を効率的に調べることができます。 Off-by-one エラーは、マスクに包括的なインデックスを使用し、DP 基本ケースを注意深く初期化することで回避されます。
