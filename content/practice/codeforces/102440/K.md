 ## 解決策
 ## 問題の理解

 バイナリ配列があります。 その絶対値は、1 の数と 0 の数の間の絶対差です。 1 つの連続セグメントを変更した後 (何も変更しない可能性も含めて)、取得できる最大の絶対値が必要です。 次に、個々の配列要素が一度に 1 つずつ反転され、そのような更新のたびにこの最大値を再計算する必要があります。 

配列を表す便利な方法は、すべてを置き換えることです。`1`による`+1`そしてすべての`0`による`-1`。 結果の値を (b_i) とします。 配列全体の合計は次のようになります。 

[
 S=\sum b_i=c_1-c_0。 
】

 配列の絶対値は単純に (|S|) です。 

変換された配列内の合計が (X) であるセグメントを反転するとします。 そのセグメント内のすべての要素の符号が変わるため、その寄与は (X) から (-X) に変わります。 したがって、配列全体の合計は次のようになります。 

[
 S-2X。 
】

 したがって、現在の配列の答えは次のようになります。 

[
 \max_{\text{segment } I}|S-2\operatorname{sum}(I)|。 
】

 セグメントの合計には任意のサブ配列の合計を使用できるため、重要な値はサブ配列の合計の最小値と最大値だけです。 (mn) が最小サブ配列合計であり、(mx) が最大サブ配列合計である場合、

 [
 c_A=\max\left(|S-2mn|,\ |S-2mx|\right)。 
】

 入力には最大 (2\cdot10^5) 個の要素と最大 (2\cdot10^5) 個の更新が含まれます。 更新のたびに配列全体をスキャンするアプローチでは、(O(nq)) 個の作業が実行され、約 (4\cdot10^{10}) 個の要素操作に達する可能性があります。 すべての部分配列の合計を最初から再計算することさえ、制約が許容する範囲をはるかに超えています。 関連情報はほぼ対数時間で更新する必要があります。 

不注意な実装が露呈する可能性のあるエッジケースがいくつかあります。 たとえば、単一の要素の場合、```
1 1
0
1
```配列は次のようになります`[1]`、したがって、答えは次のとおりです`1`。 すべての内部ノードに 2 つの子があると誤って仮定したセグメント ツリーの実装は、このケースを誤って処理する可能性があります。 

すべて等しい配列も便利なチェックです。 のために```
3 1
0 0 0
1
```アップデートにより生成される`[1,0,0]`。 最後の 2 つの要素を反転すると、`[1,1,1]`、したがって、答えは次のとおりです`3`。 単一の位置を反転することのみを考慮する実装では、誤った結果が得られます。`1`。 

最適なセグメントは配列境界で開始または終了する可能性があるため、エンドポイントも重要です。 のために```
4 1
1 0 0 1
1
```更新後の配列は`[0,0,0,1]`。 最初の 3 つの要素を反転すると、`[1,1,1,1]`、したがって、答えは次のとおりです`4`。 プレフィックスまたはサフィックスの処理が正しくない最大サブ配列の実装では、このセグメントが失われる可能性があります。 

最後に、最適なセグメントは内部セグメントである可能性があります。 提供されたサンプルでは、​​最初の更新後、変換された配列は次のようになります。`[1,1,1,-1,-1,1]`。 2 つを含むセグメント`-1`値には合計があります`-2`を反転すると、合計が から変わります。`2`に`6`。 プレフィックスまたはサフィックスだけを見ると、最適なものを見逃してしまいます。 

## アプローチ

 直接的な解決策は、ポイントを更新するたびに、考えられるすべてのセグメントを試してみることです。 固定セグメントの場合、その合計を計算し、結果の絶対値を評価できます。 (O(n^2)) 個のセグメントがあるため、各 (q) 更新後にこれを実行すると、(O(qn^2)) 時間がかかります。 すべてのサブ配列の合計をプレフィックスの合計で計算することで固定配列の部分を改善したとしても、まだ (O(n^2)) 個の検査すべきセグメントが存在します。 (n=q=2\cdot10^5) では、これは完全に不可能です。 

より良い総当たりアプローチは、更新のたびに Kadane のアルゴリズムを使用して配列をスキャンすることです。 Kadane のアルゴリズムは、(O(n)) で部分配列の最大値と最小値の両方の合計を与え、その後、上記の式からすぐに答えが得られます。 これにより、全体の複雑さは (O(nq)) に軽減されますが、最悪の場合でも、依然として約 (4\cdot10^{10}) 個の配列要素演算が含まれます。 

重要な観察は、答えがすべての部分配列に個別に依存しないということです。 総和 (S) がわかったら、式 (|S-2X|) は (X) の可能な極限値で最大化されます。 したがって、必要なのは最小と最大の部分配列の合計だけです。 

これはまさにセグメント ツリーが保持できる情報です。 配列の各セグメントについて、その合計、プレフィックスの最大合計、サフィックスの最大合計、サブ配列の最大合計、および対応する 3 つの最小値を保存します。 2 つの隣接するセグメントを結合すると、これらの量はすべて、2 つの子の対応する量から計算できます。 ポイント フリップでは 1 つのリーフのみが変更されるため、(O(\log n)) 個のセグメント ツリー ノードのみを再計算する必要があります。 

Kadane のアルゴリズムは 2 つの極端な部分配列の合計を正しく検出するため、総当たりの解決策は機能しますが、(2\cdot10^5) の更新後にそれらの値を再計算する必要がある場合は失敗します。 必要な情報が構成可能なセグメント構造を持っているという観察により、代わりにそれらの値を動的に保存することができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべてのセグメントに対するブルート フォース | (O(qn^2)) | (O(n)) | 遅すぎる |
 | 更新ごとにカダネ | (O(qn)) | (O(n)) | 遅すぎる |
 | セグメントツリー | (O((n+q)\log n)) | (O(n)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての配列値を (+1) または (-1) に変換します。 あ`1`になる`+1`、そして`0`になる`-1`。 変換された配列の合計は、正確に 1 と 0 の数の差になります。 
2. すべてのセグメント ツリー ノードに対して、合計合計、最大プレフィックス合計、最大サフィックス合計、最大サブアレイ合計、最小プレフィックス合計、最小サフィックス合計、および最小サブアレイ合計の 7 つの値を保存します。 空ではないプレフィックス、サフィックス、サブ配列を使用します。 
3. 2 つの隣接するノード (L) と (R) について、それらの合計を次のように計算します。 

[
 合計=L合計+R合計。 
】

 最大のプレフィックスは完全に (L) の内側にあるか、すべての (L) とそれに続く最大のプレフィックス (R) で構成されます。 

[
 maxPref=\max(L.maxPref,L.sum+R.maxPref)。 
】

 最大のサフィックスは対称です。 

[
 maxSuff=\max(R.maxSuff,R.sum+L.maxSuff)。 
】

 最大部分配列は、左側の子に完全に存在するか、右側の子に完全に存在するか、それらの境界を越えています。 したがって、

 [
 maxSub=\max(L.maxSub,R.maxSub,L.maxSuff+R.maxPref)。 
】

 最小値は、次の式とまったく同じ式を使用して取得されます。`min`の代わりに`max`。 

1. 最初に変換された配列からセグメント ツリーを構築します。 値 (x) を表す各リーフには、(x) に等しい 7 つの格納された量がすべて含まれています。 
2. 位置 (p) を反転すると、そのリーフを (x) から (-x) に変更します。 ルートに戻るパス上のすべての祖先を再計算します。 他のすべてのセグメントは影響を受けないため、(O(\log n)) 個のノードのみが変更されます。 
3. ルートに総和 (S)、最小サブ配列合計 (mn)、および最大サブ配列合計 (mx) が含まれるようにします。 sum (mn) でセグメントを反転すると合計 (S-2mn) が生成され、sum (mx) でセグメントを反転すると (S-2mx) が生成されます。 
4. 出力

 [
 \max\left(|S-2mn|,\ |S-2mx|\right)。 
】

 これら 2 つの候補で十分である理由は、(f(X)=|S-2X|) が (X) の V 字関数であるためです。 達成可能なすべての部分配列の合計では、2 つの極値のいずれかで最大値に達します。 

### なぜ効果があるのか

 セグメント ツリーの不変条件は、すべてのノードに、対応する配列セグメントの正確な 7 つの集計値が含まれていることです。 マージ式は、最適なプレフィックス、サフィックス、またはサブ配列の可能なすべての位置を列挙するため、2 つの正しい子を結合すると、常に正しい親が生成されます。 ポイント更新では 1 つのリーフが変更され、ルートへの一意のパスに沿ってこの不変式が復元されます。 

ルートでは、(S) は変換された配列全体の合計であり、すべての正当な反転されたセグメントには何らかの部分配列の合計 (X) があります。 その結果の合計は (S-2X) になります。 この式の絶対値は可能な最小または最大 (X) の中で最大値に達するため、ルートの最小部分配列の合計と最大部分配列の合計によって正確な答えが得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    size = 1
    while size < n:
        size <<= 1

    # Each node is:
    # sum, max_prefix, max_suffix, max_subarray,
    # min_prefix, min_suffix, min_subarray
    tree = [(0, 0, 0, 0, 0, 0, 0) for _ in range(2 * size)]

    for i in range(n):
        x = 1 if a[i] else -1
        tree[size + i] = (x, x, x, x, x, x, x)

    def merge(left, right):
        ls, lp, lsf, lm, lnp, lns, lmin = left
        rs, rp, rsf, rm, rnp, rns, rmin = right

        total = ls + rs

        max_prefix = max(lp, ls + rp)
        max_suffix = max(rsf, rs + lsf)
        max_sub = max(lm, rm, lsf + rp)

        min_prefix = min(lnp, ls + rnp)
        min_suffix = min(rns, rs + lns)
        min_sub = min(lmin, rmin, lns + rnp)

        return (
            total,
            max_prefix,
            max_suffix,
            max_sub,
            min_prefix,
            min_suffix,
            min_sub,
        )

    for i in range(size - 1, 0, -1):
        tree[i] = merge(tree[i << 1], tree[i << 1 | 1])

    out = []

    for _ in range(q):
        p = int(input()) - 1
        pos = size + p

        old = tree[pos][0]
        x = -old
        tree[pos] = (x, x, x, x, x, x, x)

        pos >>= 1
        while pos:
            tree[pos] = merge(tree[pos << 1], tree[pos << 1 | 1])
            pos >>= 1

        total = tree[1][0]
        max_sub = tree[1][3]
        min_sub = tree[1][6]

        answer = max(
            abs(total - 2 * max_sub),
            abs(total - 2 * min_sub)
        )
        out.append(str(answer))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```配列は、リーフの作成時に最初に暗黙的に変換されます。 保管する`+1`1つと`-1`ゼロの場合、ゼロと 1 のカウントの間で繰り返し変換することを避けます。 

すべての親集合体は 2 つの子のみを使用して表現できるため、各タプルの 7 つの値で十分です。 特に、境界を越える最大のサブ配列は、左側の子の最適なサフィックス、次に右側の子の最適なプレフィックスでなければなりません。 同じ推論により、最小の部分配列の式が得られます。 

反復ツリーでは 2 のべき乗の基数が使用されます。 前の位置`n`には実数の配列要素が含まれますが、残りの葉は中立のゼロ セグメントです。 これは、ルート集合体が使用される場合にツリーが実数値にのみ基づいて構築され、葉がゼロであっても、空でない実セグメントからすでに取得できる最大値や最小値が変更されないため、きれいに機能します。 すべての実リーフはゼロ以外の値を持つため、ルートの極値は空でない部分配列の極値のままになります。 

更新中、古いリーフ値は直接否定されます。 元の値はすでに何度も反転されている可能性があるため、元のバイナリ配列を参照するよりも安全です。 その後、更新はルートに到達するまで上向きに進みます。 

すべての合計は最大 (n) 個の絶対値を持つため、Python の整数には十分な範囲があります。 固定幅の整数を使用する言語では、符号付き 32 ビット整数で十分ですが、通常は 64 ビット整数を使用するのが安全な選択です。

import io
from contextlib import redirect_stdout

def solve():
    input = sys.stdin.readline

    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    size = 1
    while size < n:
        size <<= 1

    tree = [(0, 0, 0, 0, 0, 0, 0) for _ in range(2 * size)]

    for i, value in enumerate(a):
        x = 1 if value else -1
        tree[size + i] = (x, x, x, x, x, x, x)

    def merge(left, right):
        ls, lp, lsf, lm, lnp, lns, lmin = left
        rs, rp, rsf, rm, rnp, rns, rmin = right

        total = ls + rs

        max_prefix = max(lp, ls + rp)
        max_suffix = max(rsf, rs + lsf)
        max_sub = max(lm, rm, lsf + rp)

        min_prefix = min(lnp, ls + rnp)
        min_suffix = min(rns, rs + lns)
        min_sub = min(lmin, rmin, lns + rnp)

        return (
            total,
            max_prefix,
            max_suffix,
            max_sub,
            min_prefix,
            min_suffix,
            min_sub,
        )

    for i in range(size - 1, 0, -1):
        tree[i] = merge(tree[i << 1], tree[i << 1 | 1])

    ans = []

    for _ in range(q):
        p = int(input()) - 1
        pos = size + p

        x = -tree[pos][0]
        tree[pos] = (x, x, x, x, x, x, x)

        pos >>= 1
        while pos:
            tree[pos] = merge(tree[pos << 1], tree[pos << 1 | 1])
            pos >>= 1

        total = tree[1][0]
        max_sub = tree[1][3]
        min_sub = tree[1][6]

        ans.append(str(max(
            abs(total - 2 * max_sub),
            abs(total - 2 * min_sub)
        )))

    print("\n".join(ans))

def run(inp: str) -> str:
    old_stdin = sys.stdin
    output = io.StringIO()

    try:
        sys.stdin = io.StringIO(inp)
        with redirect_stdout(output):
            solve()
    finally:
        sys.stdin = old_stdin

    return output.getvalue()

 ## 特殊なケース

 次のような単一要素配列の場合```
1 1
0
1
```唯一の要素が次から変更されます`0`に`1`。 変換されたツリーは、値を持つ 1 つの実際の葉で構成されます。`1`したがって、その合計、最小部分配列、および最大部分配列の合計はすべて次のようになります。`1`。 答えは

 [
 |1-2\cdot1|=1。 
】

 セグメント ツリーは、この状況に対して特別なケースを必要としません。 

すべてゼロの配列の場合、```
3 1
0 0 0
1
```アップデートにより得られるもの`[1,0,0]`、として表されます`[1,-1,-1]`。 合計は`-1`、最小の部分配列の合計は次のとおりです。`-2`、部分配列の最大合計は次のようになります。`1`。 最小合計セグメントを反転すると、合計が次のように変わります。 

[
 -1-2(-2)=3、
 】

 だから答えは`3`。 このアルゴリズムは、バイナリ カウントについて明示的に推論することなく、2 つのゼロを含むセグメントを自然に見つけます。 

左側の境界に接する最適なセグメントの場合、```
4 1
1 0 0 1
1
```更新された変換された配列は`[-1,-1,-1,1]`。 その合計は`-2`そしてその最小部分配列合計は`-3`。 最初の 3 つの要素は最小の部分配列を形成するため、それらを反転すると次のようになります。 

[
 -2-2(-3)=4。 
】

 したがって、答えは次のとおりです`4`。 ツリー内の最大プレフィックス フィールドと最大サフィックス フィールドにより、このような境界をまたぐセグメントを正しく組み合わせることができます。 

内部の最適化については、4 つの更新すべての後の提供されたサンプルの最終状態を考慮してください。```
0 1 1 0 1 0
```になる```
-1 1 1 -1 1 -1.
```その合計は`0`、その最大部分配列合計は`2`、位置にある 2 つの隣接するものから取得されます。`2`そして`3`。 そのセグメントを反転すると、合計が次のように変わります

 [
 0-2\cdot2=-4、
 】

 だから答えは`4`。 これは、ソリューションがプレフィックス、サフィックス、または個々の実行だけではなく、本物のサブ配列を追跡する必要がある理由を裏付けています。 

最後に、同じ位置を繰り返し更新するには、元の入力値ではなく現在のリーフ値を使用する必要があります。 例えば、```
1 3
0
1
1
1
```変換された値を変更します`-1`、`+1`、`-1`、`+1`。 現在のリーフを毎回否定すると、これが自動的に処理されます。 別のブール配列を保持することもできますが、リーフ自体には、次の更新に必要な状態がすでに正確に含まれています。
