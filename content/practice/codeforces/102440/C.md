 ## 問題の理解

 ちょうど 3 つの整数が与えられており、それらを並べ替えることができます。 目標は注文書を印刷することです`x y z`そのような`x + y = z`。 このプロパティを持つ順列がない場合は、次のように出力します。`-1 -1 -1`。 有効な注文はすべて受け付けられます。 

入力値が満たしている`-2^63 < a_i < 2^63`。 したがって、数値は符号付き 64 ビット整数の制限に近づく可能性があるため、実装では値がより小さい整数型に適合するという仮定を避ける必要があります。 Python の整数には任意の精度があるため、次のような算術演算が可能です。`a + b`数学的合計が入力範囲外の場合でも安全です。 

数字は3つだけです。 これにより、検索空間が一定になります。順列は最大 6 つあり、それぞれのチェックには一定の時間がかかります。 すべての順列を直接列挙するだけでも十分に高速です。 この問題の興味深い部分はパフォーマンスではなく、数値がどのような選択肢として機能するかという選択肢が 3 つしかないことを認識していることです。`C`。 

いくつかの特殊なケースにより、不注意な実装が失敗する可能性があります。 まず、数値にはゼロを含めることができます。 入力用`0 0 0`、正しい出力は次のとおりです。`0 0 0`、 なぜなら`0 + 0 = 0`。 ゼロを特別な失敗値として扱う実装は間違っています。 

重複した値も有効です。 入力用`1 1 2`、出力`1 1 2`機能するので`1 + 1 = 2`。 3 つの数値がすべて異なるものでなければならないと仮定する解決策は、有効なケースを拒否します。 

負の値には特別な処理は必要ありません。 入力用`-5 2 -3`、正しい出力は次のとおりです。`-5 2 -3`、 以来`-5 + 2 = -3`。 正の合計だけを探すと、誤って拒否されてしまいます。 

最後に、入力値は 64 ビット境界近くになる可能性があります。 例えば、`9223372036854775807 -1 9223372036854775806`有効な順序があります。 比較する前にオーバーフロー加算を実行する固定幅の実装では、不正確な結果が生成される可能性がありますが、Python は計算を正確に処理します。 

## アプローチ

 最も直接的なアプローチは、3 つの数値の可能な順序をすべて試してみることです。 がある`3! = 6`順列。 順列ごとに、最初の 2 つの値が 3 番目の値に加算されるかどうかを確認します。 1 つの順列が方程式を満たす場合、それをすぐに出力します。 6 つすべてが失敗した場合、有効な順序は存在しません。 

この強引な方法は、実際の問題にはすでに最適です。 最悪のケースではちょうど 6 回のチェックが実行されるため、実行時間は次のようになります。`O(6)`、これは単純に`O(1)`。 6 つのチェックが遅くなるような入力サイズはありません。 

意味のある選択は 3 つの数値のうちどれになるかだけであることを観察することで、一定の作業量をさらに小さくすることができます。`C`。 もし`a`は`C`、他の 2 つは次のとおりです。`b`そして`c`、それで確認します`b + c = a`。 同様に、チェックします`a + c = b`そして`a + b = c`。 これらはまさに 3 つの可能な方程式であり、成功した各方程式は必要な順序を即座に与えます。 

置換空間が小さいため、総当たりアプローチが機能します。 構造観察により、順列の生成を完全に回避でき、解を 3 つの算術比較に減らすことができます。 どちらのアプローチも受け入れられますが、直接 3 チェック バージョンの方が単純であり、推論が特に透明になります。

 ## アルゴリズムのチュートリアル

 1. 3 つの整数を次のように読み取ります。`a`、`b`、 そして`c`。 右側の 3 つの可能な選択肢をそれぞれ直接チェックできるため、元の順序を維持します。 
2. かどうかを確認します。`a + b = c`。 true の場合は印刷します`a b c`。 ここ`c`は選択された右側ですが、`a`そして`b`は 2 つの加数です。 
3. それ以外の場合は、`a + c = b`。 true の場合は印刷します`a c b`。 これは、`b`を右側として指定し、他の 2 つの値を最初に配置します。 
4. それ以外の場合は、`b + c = a`。 true の場合は印刷します`b c a`。 これは、右側で可能な最後の選択肢です。 
5. 3 つの方程式のいずれも当てはまらない場合は、次のように出力します。`-1 -1 -1`。 考えられるすべての順序付けでは、3 つの入力値のうち 1 つを 3 番目の値として選択する必要があるため、考えられるすべてのケースがすべて網羅されました。 

### なぜ効果があるのか

 重要な不変条件は、すべての有効な順序付けでは、右側として 1 つの入力数値を正確に指定する必要があるということです。`C`。 もし`C`は`c`、必要な方程式は次のとおりです。`a + b = c`。 もし`C`は`b`、それは`a + c = b`。 もし`C`は`a`、それは`b + c = a`。 アルゴリズムはこれら 3 つの可能性を正確にチェックするため、有効な順序を出力するときは必ず、その順序が必要な方程式を満たします。 3 つのチェックがすべて失敗した場合、選択の余地はありません`C`つまり、順列を並べ替えても解決策になりません。

    global input

    old_input = input

 ## 特殊なケース

 オールゼロの場合`0 0 0`最初の条件に達するので、`0 + 0 = 0`。 アルゴリズムは出力します`0 0 0`したがって、重複値とゼロには特別な分岐は必要ありません。 

重複するゼロ以外の値については、次の点を考慮してください。`1 1 2`。 最初のチェックでは、`1 + 1 = 2`、プログラムは次のように出力します`1 1 2`。 2 つの入力位置に同じ値が含まれていても、演算が変更されたり、順序が無効になったりすることはありません。 

負の値の場合は、次の点を考慮してください。`-5 2 -3`。 最初のチェックは成功します。`-5 + 2 = -3`、そしてプログラムは出力します`-5 2 -3`。 アルゴリズムは、オペランドまたは結果が正であるとは決して想定しません。 

最初の入力値が合計である場合については、次のように考えます。`12 5 7`。 最初のチェックテスト`12 + 5 = 7`そして失敗します。 2回目のテスト`12 + 7 = 5`そして失敗します。 3回目のテスト`5 + 7 = 12`成功したため、出力は次のようになります`5 7 12`。 これは、アルゴリズムが右辺の 3 つの可能な選択肢すべてをチェックしていることを確認します。 

数値境界では、`9223372036854775807 -1 9223372036854775806`満足する`9223372036854775807 + (-1) = 9223372036854775806`。 Python はこれを正確に計算するため、境界値によってオーバーフローや切り捨てが発生することはありません。 

ついに、`2 4 42`失敗パスを実行します。 考えられる 3 つの方程式は次のとおりです。`2 + 4 = 42`、`2 + 42 = 4`、 そして`4 + 42 = 2`、すべて嘘です。 3 番目の値の考えられる選択肢はすべて拒否されたため、`-1 -1 -1`が唯一の正しい応答です。
