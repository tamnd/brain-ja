 ## 解決策
 ## 問題の理解

 すべてのグリッド セルをグラフの頂点と考えてください。 直接テレポーテーションは、2 つの頂点が同じ行または列にあり、同じ文字を含み、厳密にそれらの間に同じ文字が少なくとも 1 回以上出現する場合、2 つの頂点間のエッジです。 

クエリでは 2 つのセルが与えられ、それらがこのグラフの同じ接続コンポーネントに属しているかどうかが尋ねられます。 複数のテレポーテーションが許可されているため、問題は 2 つのセルに直接テレポーテーションがあるかどうかではなく、それらを接続する有効なテレポーテーションのシーケンスがあるかどうかです。 

グリッドには最大で (1000 \times 1000 = 10^6) 個のセルが含まれますが、最大 (10^6) 個のクエリを含めることができます。 これにより、すべてのクエリに対してグラフ検索を最初から実行する必要が直ちに排除されます。 クエリごとに (O(nm)) セルのみにアクセスする検索でも、最悪の場合は (10^{12}) セルの訪問が実行される可能性があります。 前処理中にグリッドのサイズにほぼ線形の時間を費やし、ほぼ瞬時に各クエリに答える必要があります。 

テレポーテーションのルールにはもう一つの難しさが隠されています。 行に 4 つの等しい文字が含まれている場合、隣接する等しいセルは直接テレポートできませんが、4 つのセルは 1 つの連結成分を形成できます。 たとえば、`aaaa`、位置 1 と 3 はテレポートでき、位置 2 と 4 はテレポートでき、位置 1 と 4 はテレポートできます。 これにより、4 つの位置がすべて接続されます。 隣接する等しいセルのみを考慮するソリューション、または距離がちょうど 2 のペアのみを考慮するソリューションでは、この接続が見逃される可能性があります。 

ちょうど 3 回発生する場合も特殊です。 で`aaa`、位置 1 と 3 はテレポートできますが、位置 2 はどちらにもテレポートできません。 したがって、3 つのセルは 1 つのコンポーネントを形成しません。 位置 1 から位置 2 までのクエリの正解は次のとおりです。`No`、位置 1 から位置 3 までは`Yes`。 

同じセルには、テレポートを行わなくても、それ自体からすでに到達可能です。 したがって、次のようなクエリは、```
1 1
a
1
1 1 1 1
```生産しなければならない`Yes`。 すべての頂点はそれ自体と同じコンポーネントに属するため、グラフ接続構造はこれを自然に処理します。 

最後に、異なる文字を結び付けることはできません。 すべてのテレポートでは文字が保持されるため、長時間のテレポートでも現在の建物の文字を変更することはできません。 例えば、```
1 2
ab
1
1 1 1 2
```生成する`No`。 

## アプローチ

 直接的なアプローチは、すべての有効なテレポーテーションをグラフ エッジとみなして、クエリごとに BFS または DFS を実行することです。 必要な答えは正確にグラフの接続性であるため、検索は正しいです。 問題はクエリ数です。 (10^6) 個のセルと (10^6) 個のクエリを使用すると、すべてのクエリに対してグリッド全体を探索する検索で、(10^{12}) 個の訪問済みセルに到達できます。 1 つの文字のコピーを多数含む行には、二次的に多くの有効なペアが含まれる可能性があるため、考えられるすべてのテレポーテーション エッジを明示的に構築することも魅力的ではありません。 

1 行に同じ文字を配置する構造により、はるかに小さな表現が得られます。 1 行に 1 つの固定文字が左から右の順序で出現することを考えてみましょう。 番号を付けます (1、2、\ldots、k)。 有効な直接エッジは、常に (j-i\ge 2) 発生 (i) と発生 (j) の間に存在します。 

これらのエッジすべてが必要なわけではありません。 出現 (i) と出現 (i-2) を接続するだけで、1 つの小さなギャップを除いてシーケンス全体を処理するのに十分です。 4 つのオカレンスの場合、エッジ (1\leftrightarrow3) と (2\leftrightarrow4) によって 2 つの別個のコンポーネントが作成されるため、さらにオカレンス 4 をオカレンス 1 に接続します。これで、最初の 4 つのオカレンスが接続されます。 以降のすべての出現 (i) は、以前の出現にすでに接続されている (i-2) に接続されます。 その結果、これらの少数のエッジは、すべての有効なテレポーテーション エッジとまったく同じ接続コンポーネントを生成します。 

これは、行をスキャンしているときに、新しい出現ごとに最初の出現とその直前の 2 つの出現のみを記憶する必要があることを意味します。 通常、現在のオカレンスから 2 つ前のオカレンスにエッジを追加します。 現在の出現が 4 番目の出現である場合、さらにそれを最初の出現に接続します。 

まったく同じ構造を柱にも適用します。 実際のテレポーテーション エッジはすべて、この縮小されたエッジ セットで表されるため、素セット結合構造 (DSU) を使用して、グリッドの処理中に接続されたコンポーネントを維持できます。 

ブルートフォースアプローチと最適アプローチは次のように要約できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(qnm)) 最悪の場合 | (O(nm)) | 遅すぎる |
 | 最適 | (O(nm\alpha(nm)+q\alpha(nm))) | (O(nm)) | 承認済み |

 ここで (\alpha) は逆アッカーマン関数であり、これらの入力サイズに対して事実上一定です。 

## アルゴリズムのチュートリアル

 1. すべてのセル ((x,y)) を、識別子 (x\cdot m+y) を持つ DSU 頂点として扱います。 テレポーテーションがまだ処理されていないため、最初はすべてのセルが独自のコンポーネント内にあります。 
2. グリッドを行ごとに処理します。 26 文字のそれぞれについて、最初に出現した文字、最後に出現した文字、2 番目に最近出現した文字、および現在の行内での少数の出現カウントを保持します。 
3. 文字 (c) を含むセルを処理する場合、同じ行内で 2 番目に新しく出現した (c) を調べます。 存在する場合は、現在のセルと結合します。 これら 2 つの発生には、間に (c) が 1 つ以上発生するため、テレポートは有効です。 
4. 現在のセルが行内で 4 番目に出現する (c) である場合、それを最初に出現したセルと結合します。 この追加のエッジは、距離 2 のエッジのみを使用した後は分離されたままとなる 2 つのグループを接続します。 
5. このレターに関して保存されている出来事を更新します。 現在のセルが最新のセルになり、前のセルが 2 番目に新しいセルになります。 
6. グリッドを上から下にスキャンしながら、同じ方法で列を処理します。 垂直状態は、列と文字のペアごとに個別に保持されます。 これにより、グリッド上の 2 番目のネストされたパスが回避され、実装が線形に保たれます。 
7. すべての水平接続と垂直接続を追加したら、すべてのクエリを読み取ります。 両方の座標を DSU 頂点識別子に変換し、それらのルートを比較します。 ルートが等しいということは、一連の有効なテレポーテーションが存在することを意味するため、次のように出力します。`Yes`。 ルートが異なるということは、そのようなシーケンスが存在しないことを意味するため、出力します`No`。 

### なぜ効果があるのか

 任意の固定行と文字について、その出現箇所が (1,2,\ldots,k) であると仮定します。 このアルゴリズムは、(i\ge3) のたびにエッジ (i\leftrightarrow i-2) を追加し、(k\ge4) のときに (1\leftrightarrow4) を追加します。 3 回発生した場合、追加されたエッジは (1\leftrightarrow3) のみであり、これがまさに唯一の可能な接続です。 4 つの出現の場合、(1\leftrightarrow3)、(2\leftrightarrow4)、および (1\leftrightarrow4) は 4 つすべてを接続します。 以降の出現 (i) ごとに、エッジ (i\leftrightarrow i-2) がシーケンスのすでに接続されている部分に接続されます。 したがって、これらの選択されたエッジは、その行内のすべての有効なテレポーテーション エッジとまったく同じ接続コンポーネントを持ちます。 

同じ引数がすべての列と文字に独立して適用されます。 すべての有効なテレポーテーションは、これらの縮小された折れ線グラフの 1 つの接続性によって表され、アルゴリズムによって追加されたすべてのエッジ自体が有効なテレポーテーションであるため、DSU コンポーネントは、元のテレポーテーション グラフの接続されたコンポーネントとまったく同じになります。 したがって、DSU ルートを比較すると、すべてのクエリに対して正しい答えが得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    grid = [input().strip() for _ in range(n)]

    total = n * m

    # parent[x] < 0 means x is a root and -parent[x] is its component size.
    parent = [-1] * total

    def find(x):
        while parent[x] >= 0:
            if parent[parent[x]] >= 0:
                parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    def union(a, b):
        a = find(a)
        b = find(b)
        if a == b:
            return

        if parent[a] > parent[b]:
            a, b = b, a

        parent[a] += parent[b]
        parent[b] = a

    # Horizontal state. It is reset for every row.
    first_h = [-1] * 26
    last1_h = [-1] * 26
    last2_h = [-1] * 26
    count_h = [0] * 26

    # Vertical state. One state exists for every (column, letter).
    states = m * 26
    first_v = [-1] * states
    last1_v = [-1] * states
    last2_v = [-1] * states
    count_v = bytearray(states)

    for i in range(n):
        # Start a fresh occurrence history for this row.
        for c in range(26):
            first_h[c] = -1
            last1_h[c] = -1
            last2_h[c] = -1
            count_h[c] = 0

        row = grid[i]
        base = i * m

        for j in range(m):
            idx = base + j
            c = row[j] - 97

            # Horizontal connections.
            p2 = last2_h[c]
            if p2 != -1:
                union(idx, p2)

            if count_h[c] == 3:
                union(idx, first_h[c])

            if count_h[c] == 0:
                first_h[c] = idx

            last2_h[c] = last1_h[c]
            last1_h[c] = idx
            if count_h[c] < 4:
                count_h[c] += 1

            # Vertical connections.
            s = j * 26 + c
            p2 = last2_v[s]
            if p2 != -1:
                union(idx, p2)

            if count_v[s] == 3:
                union(idx, first_v[s])

            if count_v[s] == 0:
                first_v[s] = idx

            last2_v[s] = last1_v[s]
            last1_v[s] = idx
            if count_v[s] < 4:
                count_v[s] += 1

    q = int(input())
    out = bytearray()

    for _ in range(q):
        x1, y1, x2, y2 = map(int, input().split())
        a = (x1 - 1) * m + (y1 - 1)
        b = (x2 - 1) * m + (y2 - 1)

        if find(a) == find(b):
            out.extend(b"Yes\n")
        else:
            out.extend(b"No\n")

    sys.stdout.buffer.write(out)

if __name__ == "__main__":
    solve()
```DSU は負の値を使用します。`parent`コンポーネントのサイズを保存します。 これにより、別のサイズの配列が回避され、メモリ使用量が小さく抑えられます。 サイズによる結合により、ツリーが深くなるのを防ぎますが、パス圧縮により、後続のルート検索がほぼ一定時間になります。 

異なる行のオカレンスは同じ水平テレポートに参加できないため、水平状態は各行の先頭でリセットされます。 列はすべての行にわたって継続するため、垂直状態はリセットされません。 

の`count`値は、0、1、2、3、および少なくとも 4 つの出現を区別する必要があるだけです。 文字が 1 行に 4 回出現すると、特別な 1 番目から 4 番目のエッジがすでに追加されており、その後の出現は 2 つ前の出現との接続のみが必要になります。 あ`bytearray`垂直方向のカウントには十分です。 

条件`count == 3`カウントを増やす前に意図的にチェックされます。 3 番目ではなく 4 番目の出現を識別します。 4 回目の出現については、`first`発生 1 であり、`last2`は出現 2 であるため、アルゴリズムは必要な両方の接続を追加します。 

入力からのすべての座標は 1 から始まります。 変換では、ゼロから始まる頂点識別子を計算する前に、両方の座標から 1 が減算されます。 Python には整数オーバーフローの問題はなく、最大の識別子は (10^6) よりも小さくなります。 

出力は、`bytearray`100 万個の文字列の Python リストではありません。 これにより、メモリ使用量が予測可能になり、出力呼び出しの繰り返しが回避されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(nm\alpha(nm)+q\alpha(nm))) | 各セルは一定数の DSU 操作のみに参加し、その後に要求ごとに 2 つのルート クエリが続きます。 |
 | スペース | (O(nm)) | DSU はセルごとに 1 つの値を格納しますが、グリッド配列とラインステート配列は入力サイズが線形です。 |

 最大で (10^6) 個のセルと (10^6) 個のクエリが存在します。 前処理では各セルに一定の回数だけアクセスし、クエリ フェーズではクエリごとに 2 つの DSU 検索のみを実行します。 したがって、アルゴリズムは、グリッド サイズにクエリ数を乗算するのではなく、実際の入力サイズに応じて逆アッカーマン係数まで線形にスケールします。
