 ## 解決策
 ## 問題の理解

 順列から始めます`p`からの数字のうち`1`に`n`。 どの要素も削除できますが、残りの要素は元の順序のままである必要があるため、考えられるすべての結果は順列の部分列になります。 

選択した長さの部分列に対して`m`、その美しさは`m`その反転数を引いたもの。 反転とは、前の要素が後の要素よりも大きい残りの要素のペアです。 したがって、保持するすべての要素は 1 つの美点を与えますが、保持する要素間のすべての反転は 1 点を削除します。 

タスクは、最終値が次の部分列を選択することです。`number of kept elements - number of inversions`できるだけ大きいです。 

バウンド`n <= 2 * 10^5`すべてのサブシーケンスを検査するアルゴリズムはすぐに除外されます。`2^n`彼らのうち。 二次アルゴリズムであっても、一般にこの規模では大きすぎます。 周りに何かが必要です`O(n log n)`最悪の場合、線形時間に近くなります。 すべての値が個別であるため、入力が順列であるという事実も役立ちます。そのため、「増加」とは、等しい値についての曖昧さなしに厳密に増加することを意味します。 

根底にある観察が見逃された場合、実装を騙す可能性のあるエッジケースがいくつかあります。 のために`n = 1`、可能なサブシーケンスは次のとおりです。`[1]`、したがって、答えは次のとおりです`1`。 少なくとも 1 つの反転が存在することを前提とするメソッドは、誤ってゼロを返す可能性があります。 

考慮する```
4
1 2 3 4
```全体の順列には反転がないため、その美しさは次のとおりです。`4`。 したがって、答えは次のとおりです`4`。 パターンを検出するたびに要素を不必要に削除する実装では、最適な要素が失われる可能性があります。 

ここで考えてみましょう```
2
2 1
```両方の要素を保持すると長さが得られます`2`反転が 1 つあるため、美しさは次のとおりです。`1`。 どちらか一方だけを残しても美しさは生まれる`1`。 したがって、答えは次のとおりです`1`。 単純に元の長さを返すメソッドは、間違った値を返します。`2`。 

それほど明白ではないケースは、```
5
3 1 2 5 4
```全体のシーケンスには 2 つの反転があり、その美しさは`5 - 2 = 3`。 増加するサブシーケンス`[1, 2, 5]`長さがある`3`反転がないので美しい`3`。 これは、最適な答えには、要素の最大数を維持する必要がないことがわかります。 

## アプローチ

 直接的な総当たりアプローチは、順列のすべてのサブシーケンスを考慮することです。 選択したサブシーケンスごとに、その反転を数えてその美しさを計算し、最大値を維持します。 すべての正当な結果は 1 つのサブシーケンスによって表されるため、これは正しいです。 

問題は部分列の数です。 がある`2^n`選択肢、そして最大まで検査すると`n`要素を使用してサブシーケンスを構築し、その後、`n^2`反転をカウントするためにペアを使用する場合、単純な実装には時間がかかります。`O(2^n n^2)`時間。 部分列だけを列挙することさえ不可能です。`n = 2 * 10^5`。 

より構造化された試みは、サブシーケンスに対して動的プログラミングを使用することですが、反転項は選択された要素のすべてのペアを結合します。 1 つの要素を選択すると、後で選択される多くの要素のコストに影響する可能性があるため、単純な最長再帰は美しさを直接的に説明するものではありません。 

重要な観察により、その問題は完全に解消されました。 

選択したサブシーケンスに少なくとも 1 つの反転が含まれていると仮定します。 に参加する要素を選択してください`k`逆転。 その要素を削除すると、サブシーケンスの長さは正確に減少します。`1`、反転数は正確に減少します`k`。 

その美しさは、`(-1) - (-k) = k - 1`。 

もし`k >= 1`、要素を削除しても美しさが低下することはありません。 いつ`k > 1`、実際に美しさが増します。 いつ`k = 1`、美しさは変わりません。 

倒置に属する要素は繰り返し削除できます。 最終的に反転は残らないため、結果として得られる部分列は厳密に増加します。 このプロセスの間、美しさが損なわれることはありません。 

これは、すべてのサブシーケンスには、その美しさが元のサブシーケンスの美しさと少なくとも同じくらい大きくなるサブシーケンスが増加していることを意味します。 増加する部分列には反転が存在しないため、その美しさは単純にその長さです。 

したがって、可能な限り最高の美しさは、元の順列の増加する部分列の正確な最大長になります。 言い換えれば、この問題は LIS を見つけることと同じです。 

標準`O(n log n)`LIS アルゴリズムは配列を維持します`tails`、 どこ`tails[k]`長さが増加するサブシーケンスの可能な最小の終了値です。`k + 1`これまで見られた。 すべての順列値について、二分探索により、値が少なくとも現在の値である最初の位置が検索されます。 その値を置き換えると、将来の可能性が最大限に保たれます。 現在の値が保存されているすべての末尾よりも大きい場合、LIS を拡張します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |`O(2^n n^2)`|`O(n)`サブシーケンスごと | 遅すぎる |
 | 最適 |`O(n log n)`|`O(n)`| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 空の配列を作成する`tails`。 その長さは、これまでに見つかった最長の増加サブシーケンスの長さと常に等しくなります。 
2. 左から右へ順列を処理します。 現在の値については`x`、最初の位置の二分探索`pos`で`tails`そのような`tails[pos] >= x`。 
3. そのような位置が存在する場合は、置き換えます。`tails[pos]`と`x`。 We do not change the length of the represented subsequence, but we obtain a smaller ending value, which gives more opportunities to extend it with future elements.
 4. そのようなポジションが存在しない場合、`x`現在のすべての尾部よりも大きいです。 に追加します`tails`増加するサブシーケンスを 1 つの要素によって拡張できるためです。 
5. すべての値が処理された後、戻り値を返します。`len(tails)`。 上記の観察によれば、この LIS の長さはまさに達成可能な最大限の美しさです。 

末尾の置換が安全である理由は、各サブシーケンスの長さに対して考えられる最良の終了値のみを考慮しているためです。 増加する 2 つのサブシーケンスが同じ長さであるが、1 つは次のように終わると仮定します。`4`そしてもう一つはで終わります`7`。 で終わる後続`4`後に続く可能性のあるすべての将来の値があるため、後で拡張する場合には常に少なくとも同じくらい役立ちます。`7`フォローすることもできます`4`。 したがって、可能な限り最小のテールを維持することが正しい状態圧縮です。 

### なぜ効果があるのか

 美しさを伴うあらゆる後続を考慮してください`B`。 反転が含まれている場合は、少なくとも 1 つの反転に関与している要素を選択して削除します。 その要素が関与している場合`k`反転すると、長さが 1 つ減少し、反転カウントが 1 つ減少します。`k`、によって美しさが変わります。`k - 1 >= 0`。 このプロセスを繰り返すことで、少なくとも美しさを備えた増加するサブシーケンスが生成されます`B`。 したがって、サブシーケンスは LIS の長さを超える美しさを持つことはできません。 

逆に、LIS自体は増加しているため、反転はゼロです。 その美しさはまさにその長さです。 したがって、LIS の長さは達成可能な美しさであると同時に、あらゆる可能な美しさの上限でもあり、正確な答えになります。 

## Python ソリューション```python
import sys
from bisect import bisect_left

input = sys.stdin.readline

def solve():
    n = int(input())
    p = list(map(int, input().split()))

    tails = []

    for x in p:
        pos = bisect_left(tails, x)

        if pos == len(tails):
            tails.append(x)
        else:
            tails[pos] = x

    print(len(tails))

if __name__ == "__main__":
    solve()
```入力は次を使用して読み取られます`sys.stdin.readline`これにより、次のような場合に不必要なオーバーヘッドが回避されます。`n`と同じくらい大きいです`2 * 10^5`。 

の`tails`配列は最初は空です。 あらゆる価値観に対して`x`、`bisect_left`以上の値を含む最初の位置を検索します。`x`。 元の入力は順列であるため、すべての値は個別ですが、`bisect_left`目的のサブシーケンスは厳密に増加しているため、これは依然として正しい選択です。 値が重複する可能性がある場合は、次を使用します。`bisect_right`サブシーケンスを拡張するために等しい値が誤って許可されてしまいます。 

いつ`pos`等しい`len(tails)`、`x`は現在のすべてのテールよりも大きいため、表現された LIS を拡張できます。 それ以外の場合は交換`tails[pos]`と`x`同じサブシーケンス長を維持しながら、終了値を下げます。 

Python の整数はオーバーフローしませんが、答えは最大でも`n`ともかく。 二分探索では空の検索も処理されます。`tails`正しく配列されているので、`n = 1`特別なケースは必要ありません。

 | --- | --- | --- |
 | 時間 |`O(n log n)`| それぞれの`n`値は 1 つのバイナリ検索を実行します`tails`。 |
 | スペース |`O(n)`|`tails`LIS の長さごとに最大 1 つの値が含まれます。 |

## テストケース```python
import sys
import io
from bisect import bisect_left

def solve():
    input = sys.stdin.readline
    n = int(input())
    p = list(map(int, input().split()))

    tails = []

    for x in p:
        pos = bisect_left(tails, x)
        if pos == len(tails):
            tails.append(x)
        else:
            tails[pos] = x

    print(len(tails))

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    try:
        sys.stdin = io.StringIO(inp)
        sys.stdout = io.StringIO()
        solve()
        return sys.stdout.getvalue().strip()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

# Provided samples
assert run("""5
1 2 3 5 4
""") == "4", "sample 1"

assert run("""6
2 1 3 4 5 6
""") == "5", "sample 2"

# Minimum-size valid permutation
assert run("""1
1
""") == "1", "single element"

# Completely decreasing permutation
assert run("""5
5 4 3 2 1
""") == "1", "strictly decreasing"

# Completely increasing permutation
assert run("""5
1 2 3 4 5
""") == "5", "strictly increasing"

# Mixed case with several replacements in tails
assert run("""7
4 1 6 2 5 3 7
""") == "4", "multiple LIS tail replacements"

# Generalized robustness case with equal values.
# Equal values are not valid under the permutation guarantee,
# but bisect_left correctly computes a strictly increasing subsequence.
assert run("""4
2 2 2 2
""") == "1", "duplicate values"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1 / 1`|`1`| 最小サイズと空バイナリ検索境界 |
 |`5 / 5 4 3 2 1`|`1`| 増加するペアは存在しません |
 |`5 / 1 2 3 4 5`|`5`| 全体の順列はすでに増加しています。 
|`7 / 4 1 6 2 5 3 7`|`4`| LISの長さを変えずにテールを交換 |
 |`4 / 2 2 2 2`|`1`| LIS の厳密性と`bisect_left`; 公式の置換契約外 |

 すべてが等しいケースは、有効な問題インスタンスではなく、堅牢性テストとして意図的にマークされています。 このステートメントは順列を保証するため、公式入力では等しい値が発生することはありません。 大文字と小文字を含めることは、実装の二分探索規則が厳密に増加する部分列の定義と一致することを確認するのに役立ちます。 

## 特殊なケース

 単一要素入力の場合```
1
1
```

`tails`空から始まります。 値`1`位置 0 に挿入され、`[1]`、そして答えは`1`。 減算する反転は存在しないので、可能な唯一の美しさは確かに`1`。 

減少順列の場合```
2
2 1
```最初の値が作成します`tails = [2]`。 値`1`置き換える`2`、与える`tails = [1]`。 LISの長さは`1`。 元の 2 要素シーケンスには 1 つの反転と美しさがあります`2 - 1 = 1`、どちらかの要素を削除すると美しさも得られます`1`。 これは、アルゴリズムが、より多くの要素を保持することで常に美しさが向上すると仮定していないことを裏付けています。 

すでに増加している順列の場合```
4
1 2 3 4
```すべての値は現在の最終末尾より大きいため、`tails`に成長する`[1, 2, 3, 4]`。 答えは`4`。 反転がないので、完全なシーケンスはすでにその美しさを実現しています。 

美しさを失わずに反転を削除できるシーケンスについては、次のことを考慮してください。```
5
3 1 2 5 4
```シーケンス全体には 2 つの反転があり、`(3,1)`、`(3,2)`、そしてまた`(5,4)`、その美しさは実際には`5 - 3 = 2`。 LIS アルゴリズムが生成するのは、`tails`州`[3]`、`[1]`、`[1,2]`、`[1,2,5]`、そして最後に`[1,2,4]`、長さの LIS を与える`3`。 続いて`[1,2,4]`反転がなく美しさがある`3`これは厳密にはすべてを保持するよりも優れています。 このケースは、反転を考慮する前にサブシーケンスの長さを最大化するという目的に縮小できない理由を示しています。 

境界値については`n = 2 * 10^5`の場合でも、アルゴリズムは入力値ごとに 1 回のバイナリ検索を実行します。 のサイズ`tails`せいぜい`2 * 10^5`したがって、すべての操作は`O(log n)`縛られた。 再帰は使用されないため、再帰の深さの問題が回避され、Python の整数表現で十分に答えが得られます。
