 ## 解決策
 ## 問題の理解

 シートは、(n \times m) 個のセルの長方形グリッドです。 最終的な描画は、単に色付けされたセルのサブセットです。 色付けプロセスは任意のセルから開始され、新しく色付けされたすべてのセルは、以前に色付けされたセルと面を共有する必要があります。 すでに色付けされているセルを再度訪問することは許可されているため、セルを訪問する実際の順序は最終的な描画には関係ありません。 

重要な再定式化は、色付きのセルがグリッド グラフ内で接続セットを形成する場合にのみ、空ではない描画が可能であるということです。 色付きのセルが接続されている場合、任意の色付きのセルから開始して、接続されているサブグラフをたどって、すべての色付きのセルを訪問することができます。 逆に、ルールによって作成されたすべての描画にはそのようなウォークがあるため、色付きのセルは接続されている必要があります。 

したがって、タスクは、(n \times) グリッドの頂点の空でない接続されたサブセットをすべてカウントすることです。 

境界 (n,m\le 12) は 1 次元では小さいですが、すべての (2^{nm}) 個の描画を列挙するには大きすぎます。 (12\times12) シートには 144 個のセルが含まれるため、(2^{144}) 個の可能なサブセットが存在します。 1 つのサブセットを一定時間でテストすることさえ不可能です。 グリッド幅が小さいということは、別のアプローチを示唆しています。つまり、処理済みセルと未処理セルの間の現在の境界で何が起こっているかだけを記憶しながら、一度に 1 セルずつボードを処理します。 

誤って対処しやすい特殊なケースがいくつかあります。 

(1\times1) の場合、空ではない描画には単一のセルが含まれている可能性があるため、答えは (1) になります。 空の図面を誤ってカウントする実装では、(2) が返されます。 

(1\times2) の場合、描画できるのは左のセル、右のセル、および両方のセルであり、(3) が得られます。 2 つのセルにエッジが必要な不注意な接続テストを行うと、シングルトン描画が誤って拒否されてしまいます。 

(2\times2) の場合、答えは (13) です。 サイズ 1 の 4 つの図面、隣接するペアで構成される 4 つの図面、3 つのセルで構成される 4 つの図面、および 4 つのセルすべてを含む 1 つの図面があります。 4 つのセルの描画では、セルの再訪問が許可されているため、トラバース ルールに問題はありません。 色の順序を単純なパスとして扱う実装では、一部の有効な描画が誤って拒否されてしまいます。 

空の図面の場合は開始セルがないため、指定されたプロセスでは取得できません。 したがって、DP は完全に色付けされていないボードを除外する必要があります。 

## アプローチ

 直接的な解決策は、(nm) 個のセルのすべてのサブセットを列挙し、その誘導されたグリッド グラフが接続されているかどうかをテストすることです。 (2^{nm}) 個のサブセットがあり、DFS または BFS で 1 つのサブセットをチェックするには (O(nm)) 時間がかかります。 最悪の場合こうなる

 [
 O(nm\cdot 2^{nm})。 
]

 (n=m=12) の場合、これは (144\cdot2^{144}) となり、計算可能な範囲をはるかに超えています。 

すべての最終的な描画は色付きのセルのセットによって完全に決定されるため、強引な方法が機能します。 セットの数はボードの領域全体に指数関数的に依存するため、これは失敗します。 

私たちを救う観察は、グリッドの幅が狭いということです。 セルを行ごとにスキャンするとします。 セルの一部のプレフィックスを処理した後、将来の接続に影響を与える可能性がある唯一の情報は、既に選択されているセルが処理領域と未処理領域の境界にどのように接触するかということです。 

この境界には (m) 個の位置のみが含まれます。 すべての境界位置について、それが空であるかどうか、色が付いている場合は、それが処理された図面のどの接続コンポーネントに属しているかを知る必要があります。 境界上に表示されなくなったコンポーネントは将来のセルに接続できないため、直ちに処理する必要があります。

境界は平面グリッドから得られるため、そのコンポーネント構造は交差しません。 これにより、任意のセット パーティションと比較して、可能な状態の数が大幅に減少します。 結果として得られる状態空間は、(nm) ではなく (m) に指数関数的に依存します。 これは、標準的なフロンティアまたはプロファイル DP のアイデアです。 

すべてのセルを 2 つの方法で処理できます。 空のままにするか、色を付けます。 これに色を付けると、接続できるすでに処理済みのセルは左と上に隣接するセルだけになります。 それらのコンポーネントのラベルは、1 つのコンポーネントを拡張しているのか、新しいコンポーネントを開始しているのか、または 2 つのコンポーネントをマージしているのかを示します。 

重要なのは、辺境から消え去ったコンポーネントを処理することです。 そのコンポーネントが残りのコンポーネントのみである場合、色付きの描画全体が完成し、残りのすべてのセルは空のままでなければなりません。 別のコンポーネントがまだ存在する場合、消えたコンポーネントは今後のセルに到達できないため、図面を接続することはできません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(nm2^{nm})) | (O(nm)) | 遅すぎる |
 | フロンティアDP | (O(nm\cdot 5^m)) | (O(5^m)) | 承認済み |

 (5^m) 項は、フロンティア幅に対する指数関数的な依存性を表します。 より正確には、州はフロンティアの交差しない部分的な区画であり、その数は (5) に近いベースで増加します。 (m=12) の場合、可能な正規境界分割の数はまだ 100 万未満であり、これはこの方法を実用化できる規模です。 

## アルゴリズムのチュートリアル

 1. 必要に応じて、(m\le n) になるようにボードを回転します。 DP 指数は幅に依存するため、フロンティアとして小さい方の寸法を使用することが常に推奨されます。 
2. 現在のフロンティアを (m) 個のラベルの配列で表します。 ゼロは、対応するフロンティア位置が空であることを意味します。 等しい正のラベルは、それらの位置が同じ連結成分に属していることを意味します。 ラベルは正規に保たれます。つまり、コンポーネントが最初に出現する順序でラベルに番号が付けられます。 
3. 完全に空のフロンティアから始めます。 セルがまだ処理されておらず、色付きコンポーネントも存在しないため、DP 値は 1 です。 
4. セルを左から右、上から下に処理します。 列 (c) のセルでは、フロンティア位置 (c) はその上隣を表し、(c>0) の場合、位置 (c-1) はその左隣を表します。 
5. 現在のセルを空のままにすることを検討してください。 そのフロンティア位置はゼロになります。 これにより、最後に出現した 1 つのコンポーネントが削除された場合、そのコンポーネントは境界から消えたことになります。 別のコンポーネントが残っている場合、その 2 つのコンポーネントは後で出会うことができないため、その状態は不可能になります。 コンポーネントが残っていない場合、接続された図面は終了しているため、今後の唯一の合法的なアクションは、残りのセルをすべて空のままにすることです。 
6. 現在のセルに色を付けることを検討してください。 左隣も上隣もコンポーネントに属していない場合、セルは新しいコンポーネントを開始します。 コンポーネントに隣接するセルが 1 つだけ属している場合、新しいセルはそのコンポーネントに加わります。 両方の隣接セルが同じコンポーネントに属している場合、セルはコンポーネントの数を変更せずにそのコンポーネントに結合します。 
7. 左隣と上隣のセルが異なるコンポーネントに属している場合、現在のセルに色を付けると、これら 2 つのコンポーネントがマージされます。 いずれかのラベルが付いたすべてのフロンティア位置は、同じ新しいラベルに変更する必要があります。 結果として得られるラベルは、状態が DP テーブルに挿入される前に正規化されます。 
8. 結果として得られるすべての状態に到達する方法の数を、常にモジュロ (10^9+7) で加算します。 同じフロンティア状態を生み出す異なる着色履歴は、将来の可能性が同一であるため、統合されます。 
9. 特別な完成状態を導入します。 最後のアクティブなコンポーネントがフロンティアから消えると、描画はすでに完了しています。 完成した状態は、色付けされていないセルを選択することによって、残りのすべてのセルに単純に伝播します。 
10. すべて (nm) 個のセルが処理された後、完成状態の値が答えとなります。 初期の空の状態は意図的にカウントされません。

中心的な不変条件は、DP 状態がフロンティアにまだ接触している色付きセルの接続されたコンポーネントを正確に記録する一方で、消失したすべてのコンポーネントは完全な描画が不可能であるか、完全な図面と同等であることがすでに証明されているということです。 セルが追加されると、処理領域への接続はその上と左の隣接セルを介した接続のみとなるため、4 つの遷移ケースは考えられるすべての接続変更をカバーします。 したがって、すべての有効な接続された図面には DP を通過するパスが 1 つだけあり、カウントされたすべてのパスが接続された図面を記述します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 1_000_000_007

def canonical(s):
    """Return the component labels in canonical form."""
    mp = {}
    nxt = 1
    res = []

    for x in s:
        if x == 0:
            res.append(0)
        else:
            if x not in mp:
                mp[x] = nxt
                nxt += 1
            res.append(mp[x])

    return tuple(res)

def count_connected(n, m):
    if m > n:
        n, m = m, n

    start = (0,) * m

    # -1 is the terminal state:
    # the only colored component has already disappeared,
    # so all remaining cells must be empty.
    dp = {start: 1}

    for pos in range(n * m):
        c = pos % m
        ndp = {}

        for state, ways in dp.items():
            if state == -1:
                ndp[-1] = (ndp.get(-1, 0) + ways) % MOD
                continue

            # Option 1: leave the current cell empty.
            cur = list(state)
            removed = cur[c]
            cur[c] = 0

            if removed != 0 and removed not in cur:
                # A component disappeared from the frontier.
                # If another component is still alive, the final
                # drawing can never be connected.
                if any(cur):
                    pass
                else:
                    ndp[-1] = (ndp.get(-1, 0) + ways) % MOD
            else:
                ns = tuple(cur)
                ndp[ns] = (ndp.get(ns, 0) + ways) % MOD

            # Option 2: color the current cell.
            cur = list(state)

            up = cur[c]
            left = cur[c - 1] if c > 0 else 0

            if up == 0 and left == 0:
                # Start a new component.
                new_label = max(cur, default=0) + 1
                cur[c] = new_label
                ns = tuple(cur)
                ndp[ns] = (ndp.get(ns, 0) + ways) % MOD

            elif up == 0:
                # Attach to the component on the left.
                cur[c] = left
                ns = tuple(cur)
                ndp[ns] = (ndp.get(ns, 0) + ways) % MOD

            elif left == 0:
                # Attach to the component above.
                cur[c] = up
                ns = tuple(cur)
                ndp[ns] = (ndp.get(ns, 0) + ways) % MOD

            elif up == left:
                # Both neighbors already belong to the same component.
                cur[c] = up
                ns = tuple(cur)
                ndp[ns] = (ndp.get(ns, 0) + ways) % MOD

            else:
                # Merge two different components.
                a = min(up, left)
                b = max(up, left)

                for i in range(m):
                    if cur[i] == b:
                        cur[i] = a

                cur[c] = a
                ns = canonical(cur)
                ndp[ns] = (ndp.get(ns, 0) + ways) % MOD

        dp = ndp

    return dp.get(-1, 0)

def solve():
    n, m = map(int, input().split())
    print(count_connected(n, m))

if __name__ == "__main__":
    solve()
```実装の最初のステップでは、必要に応じてディメンションを交換します。 (n\times) グリッドと (m\times n) グリッドは同型であるため、答えは変わりませんが、フロンティアの幅が減少します。 

辞書キーとして格納されたタプルは完全なフロンティア状態です。 ラベル自体には数学的な意味がないため、((1,2,2,0)) と ((7,3,3,0)) など、名前だけが異なる 2 つの状態は同一のものとして扱われなければなりません。 の`canonical`関数はまさにこの人為的な区別を取り除きます。 

空セルの遷移は最もデリケートな部分です。 現在のフロンティア位置をゼロに設定すると、最後に出現したコンポーネントが消えることがあります。 他のラベルが残っている場合、そのコンポーネントはそれらから永久に分離されているため、その状態は破棄する必要があります。 ラベルが残っていない場合は描画が完了したばかりなので特殊な状態になります。`-1`今後はすべてのセルを空にしておく必要があると記録します。 

色付きのセルの場合、下と右のセルはまだ処理されていないため、上と左のラベルのみが問題になります。 コンポーネントの開始、左側のコンポーネントの結合、上部コンポーネントの結合、または既存のコンポーネントの結合またはマージの 4 つのケースが可能性をカバーしています。 

モジュロ演算は、値が次の辞書に挿入されるたびに適用されます。 Python の整数はオーバーフローしませんが、値を減らすと辞書の算術演算が小さく保たれ、必要な出力係数に従います。 

実装では、初期のすべて 0 の状態はカウントされません。 最初の色付きセルが新しいコンポーネントを開始し、後でそのコンポーネントがフロンティアから消えると完成状態になるため、シングルトン図面は正しく処理されます。 

## 実用的な例

 ### サンプル 1: (2\times2)

 セルは 4 つしかないため、辺境の州は小さいままです。 次のトレースは、各セルが処理された後の状態の数と完成した図面に焦点を当てています。 

| 処理された細胞 | 主な状況 | 完成した図面 | アクティブな状態 |
 | --- | --- | --- | --- |
 | 0 | 空のボード | 0 | 1 |
 | 1 | 最初のセルは空でも色付きでも構いません。 0 | 2 |
 | 2 | 隣接または別々の選択肢が表示されます | 1 | いくつか |
 | 3 | コンポーネントは 3 番目のセルを介してマージできます。 より完成した形状 | いくつか |
 | 4 | 接続されているすべてのサブセットはアクティブか終了しています。 13 | 0 未完成の形状 |

 最終的な値は (13) で、サンプルと一致します。 4 つのシングルトン描画、4 つの隣接ペア、4 つの 3 セル描画、および完全な (2\times2) ボードはすべて 1 回だけ表現されます。 

### サンプル 2: (3\times3)

 (3\times3) ボードの場合、同じフロンティアには 3 つのポジションしか含まれないため、状態空間は依然として小さいです。 

| 処理された細胞 | フロンティアの幅 | 可能なアクションの種類 | 完成した図面 |
 | --- | --- | --- | --- |
 | 0 | 3 | 空のスタート | 0 |
 | 1 | 3 | 開始またはスキップ | 0 |
 | 3 | 3 | 拡張機能と新しいコンポーネント | いくつかのシングルトン形状 |
 | 6 | 3 | マージが可能になります | より多くの接続された図形 |
 | 9 | 3 | 最終状態のみが残ります | 218 |

 必要に応じて、最終的な答えは (218) になります。 この例は、どのフロンティア セルが占有されているかを追跡するだけでは不十分である理由を示しています。 同じ占有位置を持つ 2 つの状態は、異なるコンポーネント構造を持つことができ、それらの構造によって、将来のセルがコンポーネントをマージするか、切り離したままにするかが決まります。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(nm\cdot5^m)) | 各 (nm) 個のセルはフロンティア状態を処理し、最大 2 つの遷移を作成します。 |
 | スペース | (O(5^m)) | 現在および次のフロンティア DP マップのみが保存されます。 |

 この方法の重要な点は、指数係数がセルの総数ではなく、より小さい基板の寸法に依存するということです。 (m\le12) の場合、フロンティアには少数の非交差コンポーネント構造しかないため、DP は最大ボード サイズに対して実用的です。 (12\times12) グリッドの接続された空でないサブセットの既知の数は (294516896499779486414143877573183893666) で、その値のモジュロ (10^9+7) は (76792658) です。

# Maximum-size case.

```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1 1`|`1`| 最小ボードと空図面の除外 |
 |`1 12`|`78`| 一次元の接続性とフロンティアの境界 |
 |`2 3`|`40`| 長方形グリッドとコンポーネントの結合 |
 |`12 12`|`76792658`| 最大次元とモジュラー演算 |

 ## 特殊なケース

 のために`1 1`、初期状態は空のままにするか、唯一のセルに色を付けることができます。 色を付けると 1 つのコンポーネントが作成されます。 セルが最後にフロンティアを離れると、他にアクティブなコンポーネントは存在しないため、DP は 1 回だけ終了状態に入ります。 出力は`1`。 

のために`1 12`、グリッドは単なるパスです。 パスの接続された空でないサブセットはすべて、連続した間隔になります。 左のエンドポイントには (12) の選択肢があり、右のエンドポイントには (12) の選択肢があり、通常の順序制限があります。 

[
 \frac{12\cdot13}{2}=78。 
]

 フロンティア DP は特別なケースなしでこれを処理します。 フロンティアの幅は 1 であるため、同時に 2 つのアクティブなコンポーネントが存在することはできません。 

のために`2 2`、シングルトンが唯一のコンポーネントである場合、状態を無効にすることなくフロンティアから消える可能性があります。 これはまさに、不注意な実装によって「コンポーネントがフロンティアから消えた」ことと「描画が切断された」ことを混同する可能性がある点です。 正しい解釈は、描画が終了し、その後のセルはすべて空でなければならないということです。 最終的なカウントは (13) です。 

のために`12 12`、接続された図面の生の数は通常のマシンの整数よりもはるかに大きいため、実装ではすべての DP 加算をモジュロ (10^9+7) で実行する必要があります。 正確なカウントは (294516896499779486414143877573183893666) で、必要な出力は (76792658) です。 

この社説はフロンティア不変条件を中心に構成されており、これは接続された領域を含む他のグリッド問題に引き継がれる再利用可能なアイデアです。
