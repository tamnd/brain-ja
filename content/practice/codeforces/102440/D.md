 ## 問題の理解

 配列 (a) と非負のしきい値 (k) があります。 部分配列から最大 1 つの要素を削除した後、最大値から最小値を引いた値が最大 (k) になる場合、その部分配列は美しいと呼ばれます。 クエリ ([L,R]) は、部分配列 (a_l,\ldots,a_r) が美しくなるような (L\le l<r\le R) のペア ((l,r)) の数を求めます。 

「削除できる要素は 1 つだけ」というフレーズが、この問題を興味深いものにしています。 元の範囲がすでに最大 (k) である場合は、何も削除する必要はありません。 それ以外の場合、1 つの要素を削除しても、その要素が一意の最小値または一意の最大値である場合にのみ役立ちます。 最小値が 2 回発生する場合、1 つの最小値を削除すると、別のコピーが同じ値のままになります。 最大値についても同様です。 

ウィンドウに最小値 (mn)、最大値 (mx)、2 番目に小さい要素 (mn_2)、2 番目に大きい要素 (mx_2) があるとします。ここで、極値が少なくとも 2 回発生する場合、2 番目の値は対応する極値と等しくなることが許可されます。 まさにそのとき窓が美しい

 [
 mx-mn\le k、
 】

 または、最大値が 1 回だけ発生し、

 [
 mx_2-mn\le k、
 】

 または、最小値が 1 回だけ発生し、

 [
 mx-mn_2\le k.
 】

 この制約により、クエリごとにすべてのサブ配列を検査するアルゴリズムが除外されます。 長さ (2\cdot10^5) の配列にはエンドポイントのペアがほぼ (2\cdot10^{10}) あるため、すべての部分配列の (O(1)) チェックでさえすでにコストが高すぎます。 美しい部分配列は遺伝するという事実を利用する必要があります。つまり、美しい配列のすべての部分配列も美しいのです。 これにより、2 ポインタ スキャンに必要な単調な構造が得られます。 

誤って対処しやすい特殊なケースがいくつかあります。 

考慮する```
2 1 4
0 10
1 2
```答えは(1)です。 間隔 ([1,2]) の範囲は (4) より大きい範囲 (10) ですが、どちらかの要素を削除すると範囲 (0) のシングルトンが残ります。 チェックのみを行う実装`max - min <= k`誤って (0) を出力してしまいます。

長さが 1 のクエリは、別の境界ケースです。 例えば、```

## アプローチ

 直接的なアプローチは、すべてのクエリ内のエンドポイントのすべてのペアを列挙し、そのサブ配列が美しいかどうかを判断することです。 配列全体をカバーする 1 つのクエリについて、これは検査することを意味します。 

[
 \frac{n(n-1)}2
 】

 候補間隔。 (n=200000)、つまり (19,999,900,000) 間隔です。 たとえ美人テストが魔法のように（O(1)）だったとしても、これはすでに限界をはるかに超えています。 各間隔をスキャンして極値を見つけると、コストは 3 乗になります。 

このブルート フォースは、文字通りすべての可能なペア ((l,r)) の定義をチェックするため、正しいのですが、隣接する部分配列間の重複は完全に無視されます。 ウィンドウを 1 要素分拡張すると、その内容のほとんどすべてが変更されません。 左端点が 1 位置移動した場合も同様です。 

重要な観察は、美しさは縮小すると単調であるということです。 部分配列が美しい場合は、削除の範囲が最大 (k) になる要素を選択します。 より小さいサブ配列には、その要素が含まれていない (この場合、その範囲はすでに同じ引数によって制限されているか、要素が含まれているため、再度削除できます) かのどちらかです。 したがって、どの小さなサブ配列も美しいです。 

これは、すべての固定右端点 (r) に対して、([f[r],r]) が美しい最小の左端点 (f[r]) が存在することを意味します。 (l\ge f[r]) を含むすべての区間 ([l,r]) は美しくなります。 (r) が右に移動しても、(f[r]) が左に移動することはありません。 

すべての (f[r]) をスライディング ウィンドウで見つけることができます。 残る唯一の困難は、現在のウィンドウが美しいかどうかをテストすることです。 単調最小デクは最小値を与え、単調最大デクは最大値を与えます。 値の頻度を使用すると、現在の最小値または最大値が 1 回発生するかどうかを判断できます。 極値が一意である場合、対応する単調デクの 2 番目のエントリは次の明確な極値を与えます。 

(f[r]) を計算した後、クエリは 1 次元の計数問題になります。 (f[r]) は非減少であるため、二分探索ではすべてのクエリを (f[r]\le L) の位置と (f[r]>L) の位置に分割できます。 プレフィックス合計により、二分探索後の両方の部分が定数時間になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(qn^2)) (O(1)) の美しさテストでも | (O(n^2)) テストが事前計算されている場合 | 遅すぎる |
 | 最適 | (O(n+q\log n)) | (O(n)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を左から右に処理する間、スライディング ウィンドウ ([left,r]) を維持します。 ウィンドウは、縮小が完了すると、常に (r) で終わる最小の美しいウィンドウになります。 
2. 最小値についてはインデックスの単調増加デクを維持し、最大値についてはインデックスの単調減少デクを維持します。 新しい値が挿入されるときは、再び最小値または最大値になることができないインデックスを後ろから削除します。 両方のエンドポイントは前進のみであるため、すべてのインデックスが各デキューに出入りするのは最大 1 回だけです。 
3. 現在ウィンドウ内の値の頻度辞書を維持します。 最小デキューにはその値を表す値が 1 つしか格納されていない場合でも、最小デキューの先頭の値が複数回出現する可能性があるため、頻度が必要になります。 
4. 現在のウィンドウをテストします。 (mn) と (mx) をその最小値と最大値とします。 (mx-mn\le k) の場合、窓はそのまま美しいです。 
5. (mx-mn>k) の場合、削除が成功する可能性があるのは、一意の極端な場合だけです。 最大値が 1 回発生した場合、それを削除すると、2 番目に大きい値が新しい最大値として残ります。 結果の範囲 (mx_2-mn) が最大 (k) であれば、ウィンドウは美しいです。 対称的に、最小値が 1 回発生し、(mx-mn_2\le k) になると、ウィンドウは美しくなります。 
6. ウィンドウが美しくない場合は、インクリメントしてください`left`そして (a[左]) を窓から外します。 削除された値は頻度辞書から削除され、必要に応じてそのインデックスがいずれかの両端キューの先頭から削除されます。 窓が美しくなるまで繰り返します。 
7. 結果を保存します`left`(f[r]) として。 以前のウィンドウは (r-1) に対してすでに最小であったため、新しい要素を追加しても、以前は無効だった小さい左側のエンドポイントを再び有効にすることはできません。 したがって、シーケンス (f[0],f[1],\ldots,f[n-1]) は減少しません。 
8. インデックスと (f[r]) のプレフィックスの合計を作成します。 クエリ ([L,R]) の場合、(f[r]\le L) の場合、エンドポイント (r) は (L) から (r-1) までのすべての有効な左エンドポイントを提供します。 その寄与は (r-L) となります。 
9. (f[r]>L) の場合、有効な左端点は (f[r]) から始まるため、寄与は (r-f[r]) になります。 (f[r]) は非減少であるため、二分探索では (f[r]>L) となるクエリ内の最初の (r) が見つかります。 
10. プレフィックスの合計を使用して、クエリの両方の部分を評価します。 シングルトン エンドポイント (r=L) は自動的にゼロを提供するため、個別の特別なケースは必要ありません。 

### なぜ効果があるのか

 すべての右端点 (r) について、スライディング ウィンドウの不変条件は、縮小後の ([f[r],r]) は美しいが、(l<f[r]) のすべての間隔 ([l,r]) は美しくないということです。 音程が縮まっても美しさが保たれるので、(f[r])から(r)まではすべて美しい音程を生み出します。 クエリはシングルトン (l=r) のみを除外し、正確に (r-\max(L,f[r])) の有効な開始部分を残します。 

単調デックは現在の最小値と最大値を示します。 先頭のエントリは極値を表し、次のエントリは、対応する極値が一意になると次の候補値を与えます。 頻度辞書は、固有の極端なケースと繰り返される極端なケースを区別します。 したがって、美しさのテストは定義と正確に一致します。 

最後に、左側の境界は右にのみ移動するため、(f[r]) は減少しません。 これにより、クエリ分割が有効になり、1 回の二分検索で (f[r]\le L) を使用してすべてのエンドポイントを識別できるようになります。 

## Python ソリューション```python
import sys
from bisect import bisect_right
from collections import deque

input = sys.stdin.readline

def solve():
    n, q, k = map(int, input().split())
    a = list(map(int, input().split()))

    minq = deque()
    maxq = deque()
    freq = {}

    f = [0] * n
    left = 0

    def add(i):
        x = a[i]

        while minq and a[minq[-1]] >= x:
            minq.pop()
        minq.append(i)

        while maxq and a[maxq[-1]] <= x:
            maxq.pop()
        maxq.append(i)

        freq[x] = freq.get(x, 0) + 1

    def remove(i):
        x = a[i]

        freq[x] -= 1
        if freq[x] == 0:
            del freq[x]

        while minq and minq[0] < left:
            minq.popleft()

        while maxq and maxq[0] < left:
            maxq.popleft()

    def beautiful():
        mn = a[minq[0]]
        mx = a[maxq[0]]

        if mx - mn <= k:
            return True

        if freq[mx] == 1:
            mx2 = a[maxq[1]]
            if mx2 - mn <= k:
                return True

        if freq[mn] == 1:
            mn2 = a[minq[1]]
            if mx - mn2 <= k:
                return True

        return False

    for r in range(n):
        add(r)

        while not beautiful():
            left += 1
            remove(left - 1)

        f[r] = left

    pref_index = [0] * (n + 1)
    pref_f = [0] * (n + 1)

    for i in range(n):
        pref_index[i + 1] = pref_index[i] + i
        pref_f[i + 1] = pref_f[i] + f[i]

    out = []

    for _ in range(q):
        L, R = map(int, input().split())
        L -= 1
        R -= 1

        # First position p in [L, R] with f[p] > L.
        p = bisect_right(f, L, lo=L, hi=R + 1)

        # For r in [L, p), contribution is r - L.
        count1 = p - L
        sum_r1 = pref_index[p] - pref_index[L]
        ans = sum_r1 - count1 * L

        # For r in [p, R], contribution is r - f[r].
        sum_r2 = pref_index[R + 1] - pref_index[p]
        sum_f2 = pref_f[R + 1] - pref_f[p]
        ans += sum_r2 - sum_f2

        out.append(str(ans))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```の`minq`deque は、挿入のたびに値が厳密に増加するインデックスを格納します。 新しい値が後ろの値以下の場合、新しいインデックスがウィンドウ内に残っている間は、古いインデックスは最小値になることができないため、破棄されます。`maxq`対称ルールを使用します。 

頻度辞書は意図的に両端キューから分離されています。 等しい最小値は両端キュー内で折りたたまれますが、その多重度は依然として重要です。 たとえば、現在の最小値が (0) で 3 回表示される場合、1 回の出現を削除してもウィンドウから (0) を削除できません。 辞書はまさにこの状況を検出します。 

の`remove`関数は現在のグローバルを使用します`left`境界。 後でより適切な候補が挿入されたため、インデックスはすでに両端キューから消えている可能性があるため、クリーンアップは次のように記述されます。`while`削除されたインデックスが存在すると仮定するのではなく、ループします。 

美しさのテストでは、まず通常の範囲をチェックします。 範囲が大きすぎる場合にのみ、固有の極端なケースが検査されます。 最大値が一意の場合、`maxq[1]`は次の最大値です。 最小値が一意の場合、`minq[1]`は次の最小値です。 最初の範囲チェックが失敗した場合は常に、現在のウィンドウに少なくとも 2 つの異なる値があるため、チェックは安全です。 

配列`f`ゼロベースのインデックスを使用します。 固定エンドポイント (r) の場合、`f[r] <= L`、(L) から (r-1) までのすべての開始が機能し、(r-L) の選択肢が与えられます。 それ以外の場合、開始点は (f[r]) から (r-1) であり、(r-f[r]) の選択肢が与えられます。 インデックスの接頭辞の合計は最初の式を処理しますが、インデックスの接頭辞の合計は`f`2番目を処理します。 

Python の整数には任意の精度があるため、答えがオーバーフローすることはありません。 考えられる最大の答えはおおよそ (n^2/2) で、これは (n=2\cdot10^5) の場合約 (2\cdot10^{10}) になります。

    pref_f = [0] * (n + 1)

    for i in range(n):
        pref_index[i + 1] = pref_index[i] + i
        pref_f[i + 1] = pref_f[i] + f[i]

    ans = []

    for _ in range(q):
        L, R = map(int, input().split())
        L -= 1
        R -= 1

        p = bisect_right(f, L, lo=L, hi=R + 1)

        count1 = p - L
        sum_r1 = pref_index[p] - pref_index[L]
        cur = sum_r1 - count1 * L

        sum_r2 = pref_index[R + 1] - pref_index[p]
        sum_f2 = pref_f[R + 1] - pref_f[p]
        cur += sum_r2 - sum_f2

        ans.append(str(cur))

    sys.stdout.write("\n".join(ans))

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

 ## 特殊なケース

 最初のエッジ ケースは、範囲が (k) より大きい 2 要素区間です。 のために```
2 1 4
0 10
1 2
```現在のウィンドウ`[0,10]`の範囲は (10) なので、最初の美条件は失敗します。 どちらの極端な点もユニークです。 どちらかを削除すると、範囲が (0) のシングルトンが残ります。 したがって、アルゴリズムは次のようになります。`left=0`、レコード (f[1]=0)、クエリは 1 つの有効なペア ((1,2)) をカウントします。 

2 番目のエッジ ケースには、極端な状況が繰り返されます。```
4 1 0
0 0 10 10
1 4
```完全なウィンドウが存在する場合、最小値と最大値の両方が 2 回発生します。 通常の範囲は (10>0) ですが、もう 1 つのコピーが残っているため、どちらの極端な値も 1 回の削除では削除できません。 アルゴリズムはウィンドウを正しく拒否し、移動します`left`。 最終的には 2 つの美しい長い間隔が得られます`[0,0,10]`そして`[0,10,10]`、一緒に`[0,0]`そして`[10,10]`、(4)を与えます。 

3 番目のエッジ ケースは、長さが 1 のクエリです。```
1 1 0
7
1 1
```シングルトンは美しいため、前処理ではレコード (f[0]=0) が記録されます。 ただし、クエリの間、エンドポイント (r=L) の寄与は (r-L=0) になります。 したがって、シングルトンは特別なクエリ分岐なしで正しく除外されます。 

4 番目のエッジ ケースは、すべての値が等しい場合です。 のために```
4 1 0
7 7 7 7
1 4
```すべてのウィンドウの範囲は 0 なので、最初の条件はすぐに成功します。 境界配列は`[0,0,0,0]`、クエリは長さが 1 より大きい部分配列を (1+2+3=6) 個カウントします。 これは、通常の範囲がすでにしきい値を満たしている場合には、2 番目の極端なロジックが必要ないことも検証します。 

5 番目のエッジ ケースは、最小値の削除が唯一の有効な操作である場合です。 サンプル 1 では、ウィンドウ`[0,10,10]`最大値 (10) が 2 回あるため、1 つの最大値を削除しても大きな値を削除できません。 最小値 (0) は一意であり、これを削除すると残ります。`[10,10]`。 このアルゴリズムは、最大値の頻度を使用して最初の削除方向を拒否し、最小値の頻度を使用して 2 番目の削除方向を受け入れます。 この区別が、周波数辞書が必要な主な理由です。
