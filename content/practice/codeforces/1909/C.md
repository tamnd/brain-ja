 ## 解決策
 ## 問題の理解

 私たちに与えられたのは、$n$数直線上の間隔。 各間隔には左端があります$l_i$、右端点$r_i$、単位長さあたりの重量$c_i$。 間隔の実際の重みは次のように計算されます。$c_i \cdot (r_i - l_i)$。 目標は、すべての間隔にわたる重みの合計を最小化することです。 

おもしろいのは、配列を個別に並べ替えることができることです。$l$、$r$、 そして$c$。 唯一の制限は、並べ替え後も各間隔が有効なままでなければならないことです。$l_i < r_i$。 基本的に、この問題により、間隔が適切に形成されている限り、左のエンドポイント、右のエンドポイント、およびコストを任意の組み合わせでペアにすることができます。 すべてのエンドポイントは個別であるため、それらを並べ替えることで重複のない有効な間隔が生成されることが保証されます。 

この制約は、すべてのテスト ケースにわたる間隔の合計数が次を超えないことを示します。$10^5$、つまり任意の$O(n \log n)$テストケースごとのソリューションは許容されます。$O(n^2)$ブルートフォース手法は除外されます。 明らかではないエッジ ケースには、最小の左エンドポイントが最大の右エンドポイントとペアになる可能性があり、非常に大きな間隔が生じる状況が含まれます。 不注意なアプローチでは、配列が正しい順序でソートされなかったり、最高のコストと最小の長さが組み合わされなかったりして、合計の重みが最適ではなくなる可能性があります。 

たとえば、次の場合$l=[1,3]$、$r=[5,2]$、$c=[10,1]$、ペアリング$1\to5$と$10$そして$3\to2$と$1$～により無効です$3>2$、したがって、並べ替える必要があります$r$に$[2,5]$。 この場合の最適なペアリングは次のとおりです。$l=[1,3]$、$r=[2,5]$、$c=[10,1]$、重みを与える$10_1 + 1_2 = 12$。 ペアにするだけの素朴な貪欲さ$c$どの間隔でも失敗する可能性があります。 

## アプローチ

 ブルートフォースアプローチは、次のすべての順列を試すことです。$l$、$r$、 そして$c$、有効性をチェックし、合計を計算します。 のために$n$間隔、あります$n!^3$完全に不可能な組み合わせです。 すべてのペアだけを試してみても、$l$そして$r$固定付き$c$は$O(n!^2)$これも遅すぎます。 

重要な洞察は、総重量が製品の合計であることを観察することによって得られます。$c_i \cdot (r_i - l_i)$。 この合計を最小化するには、最小の差をペアにする必要があります$(r_i - l_i)$最大のコストがかかる$c_i$、または同様に、差を昇順に並べ替え、コストを降順に並べ替えて、それらをペアごとに乗算します。 同様に、差異自体を最小限に抑えるには、最小のものをペアにする必要があります。$l_i$最小のもので$r_i$それはまだそれより大きいです。 これは並べ替えることで実現できます$l$そして$r$昇順で独立してインデックス的に照合します。 

つまり、最適な解決策は、左側のエンドポイントを並べ替えることです。$l$昇順で、適切なエンドポイント$r$コストの低い順に$c$降順で。 次に、次の合計を計算します。$c_i \cdot (r_i - l_i)$それぞれに$i$。 並べ替えにより有効な間隔が保証されます ($l_i < r_i$) 異なるエンドポイントのため、降順$c$最小の間隔長に最大のコストが適用されるようにします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n!^3) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る$t$。 
2. 各テスト ケースについて、次の内容を読んでください。$n$、左側の端点$l$、右端点$r$、およびコスト$c$。 
3. 配列をソートする$l$昇順で左のエンドポイントを最小から最大まで取得します。 
4. 配列をソートする$r$昇順で、最小から最大まで正しいエンドポイントを取得します。 
5. 配列をソートする$c$降順で、最大のコストと最小の間隔の長さを組み合わせます。 
6. 変数を初期化する`total_weight`ゼロに。 
7. すべての間隔にわたって反復します。$i=0$に$n-1$:

 - 間隔の長さを次のように計算します。$length = r[i] - l[i]$。 
- 対応するコストを掛けます`c[i]`間隔の重みを取得します。 
- これを追加します`total_weight`。 
8. 現在のテスト ケースの総重量を出力します。 

なぜ機能するのか: 並べ替え$l$そして$r$昇順により、すべての$i$、$l_i < r_i$すべてのエンドポイントが異なるため、これが成り立ちます。 仕分け$c$降順では、単位長さあたりの最大のコストが可能な限り最小の長さに乗算され、積の合計が最小化されます。 他のコストと間隔の組み合わせでは、大きなコストをより長い長さに割り当てて合計が増加するか、間隔の有効性に違反するため、貪欲な特性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    l = list(map(int, input().split()))
    r = list(map(int, input().split()))
    c = list(map(int, input().split()))

    l.sort()
    r.sort()
    c.sort(reverse=True)

    total_weight = 0
    for i in range(n):
        total_weight += c[i] * (r[i] - l[i])
    print(total_weight)
```説明: このソリューションでは、まず次のコマンドを使用して入力を効率的に読み取ります。`sys.stdin.readline`。 仕分け`l`そして`r`昇順はソート中に有効な間隔を保証します`c`降順にすると合計が最小になります。 ループは対応する要素を乗算し、その合計を累積します。 使用する`reverse=True`のために`c`この手順を忘れると、小さなコストと小さな間隔が組み合わされることになり、次善の策となるため、これは非常に重要です。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | 3 つの配列のソートが優先され、合計を計算するための線形パス |
 | スペース | O(n) | テスト ケースごとに 3 つの配列を保存する |

 という制約を考慮すると、$n$まで$10^5$と合計$n$テスト ケース ≤ 10^5 では、このソリューションは時間とメモリの制限内で快適に実行されます。
