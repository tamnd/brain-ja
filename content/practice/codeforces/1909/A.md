 ## 解決策
 ## 問題の理解

 私たちは原点から始まる無限のグリッド上を移動するように求められます。 上、下、左、右の 4 つの基本方向に対応する 4 つの可能な動きがあります。 各動作はコントローラーの個別のボタンによってトリガーされますが、コントローラーは壊れやすいため、移動中に 4 つのボタンすべてを少なくとも 1 回押すと壊れてしまいます。 したがって、指定されたすべての点に到達するには、最大 3 つの異なる方向を使用することに制限されます。 各テスト ケースは整数座標を持つ一連のポイントを提供し、4 つのボタンすべてを押さずにすべてのポイントにアクセスできるかどうかを判断する必要があります。 

制約は中程度です。 テスト ケースごとに最大 100 ポイント、テスト ケースごとに最大 1000 ポイントを指定できます。 各座標は -100 ～ 100 の間と小さいため、非効率を気にせずに座標全体の単純なスキャンを実行できます。 重要な課題は計算パフォーマンスではなく、幾何学的な推論です。すべての点に到達するにはどの方向が必要かを理解する必要があります。 

単純な間違いは、任意の順序でポイントを訪問し、正確なボタンの押下を追跡しようとすることです。 たとえば、点が原点に対して 4 つの象限すべてにまたがっている場合、不注意なアプローチにより各象限を順番に訪れるパスを試行し、それが常に可能であると誤って仮定する可能性があります。 例えばポイントの場合`(1,1)`、`(-1,-1)`、`(1,-1)`、 そして`(-1,1)`、どのパスも 4 方向すべてを使用する必要があるため、正解は「いいえ」です。 

## アプローチ

 ブルートフォースアプローチでは、ポイントのすべての順列を試し、最大 3 つの方向を使用してポイントを訪問する順序が存在するかどうかを確認します。 これは非現実的です。なぜなら、順列の階乗増加は、たとえ控えめな値であっても爆発的に増加するからです。`n=10`。 原理的には正しいですが、制約により実行できません。 

重要な点は、パスや順序をシミュレートする必要がないということです。 原点を基準とした各点の象限によって、必要な方向が決まります。 各点を x 座標と y 座標で分類できます。 

- x > 0 の点に到達するには、右に移動できなければなりません。 
- x < 0 の点に到達するには、左に移動できなければなりません。 
- y > 0 の点に到達するには、上に移動できなければなりません。 
- y < 0 の点に到達するには、下に移動できなければなりません。 

これにより、4 つのボタンに対応する 4 つの潜在的な方向が得られます。 ポイントに到達するために 4 方向すべてが必要な場合、コントローラーは壊れてしまいます。 それ以外の場合は安全です。 

したがって、テスト ケースごとに、正の x、負の x、正の y、および負の y を持つ点が同時に存在するかどうかを確認します。 4 つすべてが存在する場合、答えは「NO」です。 それ以外の場合は「YES」です。 これにより、問題は単純な座標のスキャンに軽減されます。

 | ブルートフォース | お(ん!) | O(n) | 遅すぎる |
 | 最適 | テスト ケースあたり O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースごとに、次の 4 つのフラグを初期化します。`need_right`、`need_left`、`need_up`、`need_down`に`False`。 これらは、任意の点に到達するために対応するボタンを押す必要があるかどうかを表します。 
2. テスト ケース内のすべてのポイントを反復します。 それぞれのポイントについて`(x, y)`、フラグを更新します。 

- もし`x > 0`、 セット`need_right = True`。 
- もし`x < 0`、 セット`need_left = True`。 
- もし`y > 0`、 セット`need_up = True`。 
- もし`y < 0`、 セット`need_down = True`。 
3. すべてのポイントを処理した後、4 つのフラグがすべて揃っているかどうかを確認します。`True`。 そうであれば、すべてのポイントを訪問するには 4 つのボタンすべてが必要となるため、「NO」を出力します。 それ以外の場合は「YES」を出力します。 
4. Repeat for all test cases.

 機能する理由: フラグは、すべてのポイントに到達するために必要な最小限の方向のセットをキャプチャします。 不要なボタンがあればコントローラーは壊れません。 どのボタンが必要かを数えているだけなので、訪問ポイントの実際の順序は関係ありません。 このソリューションは、多くても 3 つのボタンが必要な場合にのみ、「はい」と正しく答えます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    need_right = need_left = need_up = need_down = False
    for _ in range(n):
        x, y = map(int, input().split())
        if x > 0:
            need_right = True
        if x < 0:
            need_left = True
        if y > 0:
            need_up = True
        if y < 0:
            need_down = True
    if need_right and need_left and need_up and need_down:
        print("NO")
    else:
        print("YES")
```コードはアルゴリズムに従って段階的に実行されます。 フラグはポイントごとに独立して更新されます。 必要なのは方向情報のみであるため、ポイントの保存は避けます。 点が軸上にある境界条件は自動的に処理されます。`x=0`または`y=0`水平方向または垂直方向の動きは必要ありません。 使用する`sys.stdin.readline`多数のテスト ケースの高速入力を保証します。 

## 実用的な例

 最初のサンプル テスト ケースを考えてみましょう。 

| ステップ | ポイント`(x, y)`| 更新後のフラグ |
 | --- | --- | --- |
 | 1 | (1, -1) | 右 = True、左 = False、上 = False、下 = True |
 | 2 | (0, 0) | 右 = True、左 = False、上 = False、下 = True |
 | 3 | (1, -1) | 右 = True、左 = False、上 = False、下 = True |

 どのフラグも同時にすべてではありません`True`したがって、出力は「YES」になります。 トレースでは、右ボタンと下ボタンの 2 つのボタンだけが必要であることが確認されています。 

3 番目のサンプルを考えてみましょう。 

| ステップ | ポイント`(x, y)`| 更新後のフラグ |
 | --- | --- | --- |
 | 1 | (1,1) | 右 = True、左 = False、上 = True、下 = False |
 | 2 | (-1,-1) | 右=真、左=真、上=真、下=真 |
 | 3 | (1,-1) | 右=真、左=真、上=真、下=真 |
 | 4 | (-1,1) | 右=真、左=真、上=真、下=真 |

 4 つのフラグはすべて True であるため、出力は「NO」になります。 トレースは、4 つの象限すべてのポイントに 4 つのボタンすべてが必要であることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
