 ## 問題の理解

 正の整数と数値の複数セットが与えられます。$k$。 任意の数字を繰り返し選択できます$x$黒板に書いた文字を消して、2 つの正の整数に置き換えます$y$そして$z$そのような$y + z = x + k$。 目標は、すべての数値を等しくできるかどうかを判断し、できる場合はそのような演算の最小数を見つけることです。 各演算により数値の合計が増加します。$k$、 なぜなら$y + z = x + k$正確に追加します$k$元の数値よりも多い$x$。 

入力は大きくなる可能性があります。$n$まで$2 \cdot 10^5$そして最大の数字$10^{12}$。 分割をシミュレートする単純なアプローチは機能しません。組み合わせにより操作の数が爆発的に増加する可能性があり、複数のテスト ケースを効率的に処理する必要があるためです。 これは、解決策がブルートフォース シミュレーションではなく算術推論に依存する必要があることを示唆しています。 

微妙なエッジケースは次のような場合です$k = 0$。 そうすれば、すべての演算で合計が保持され、数値を元の合計と正確に一致する数値に分割することしかできなくなります。 最初に数値が等しくない場合、分割しても合計を減らすことができないため、すべてを等しくすることは不可能です。 もう 1 つのエッジ ケースは、すべての数値がすでに等しい場合であり、操作が必要ない場合です。 負の数は許可されないため、分割では常に厳密に正の整数を生成する必要があります。 

## アプローチ

 ブルートフォースのアイデアは、考えられるすべての分割をシミュレートし、数値が等しくなるまですべてのシーケンスを試行することです。 それぞれの番号について、すべてを試すことができます$y, z$満足のいく組み合わせ$y + z = x + k$。 これは、特に次のような場合には、分割の数に応じて演算数が指数関数的に増加するため、すぐに実行不可能になります。$n$まで$2 \cdot 10^5$。 最大数を繰り返し分割することのみを考慮しても、州の数は膨大なままです。 

重要な観察は、最大の数から逆方向に作業することです。 すべての数値が最終的に何らかのターゲットに等しくなければならない場合$M$、次にそれぞれの数字$a_i$の 1 つ以上のコピーに変換可能でなければなりません$M$スプリットを使用して。 各分割は正確に加算されます$k$合計するので、各数値を次のようにモデル化できます。$x$のコピー$M$合計が増加します$k$操作ごとに。 代数的に必要なのは、$a_i + t_i \cdot k = c_i \cdot M$いくつかの正の整数の場合$t_i, c_i$。 これは、次のことを確認することになります。$(M - a_i) \% k = 0$、分割数は次のようになります。$(M - a_i) / k$。 最適な$M$は配列内の最大数です。これをさらに増やすと、必要な操作の数が増えるだけです。 

したがって、問題はすべての数値が次の条件を満たすかどうかをチェックすることになります。$(M - a_i) \% k = 0$そして合計$(M - a_i) / k$みんなのために$i$最小限の操作数を取得します。

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る$t$。 テスト ケースごとに、次の内容を読んでください。$n$そして$k$、その後に配列$a$。 
2. 最大数を計算する$M$配列内で。 これは、すべての要素が変換されるターゲット番号です。 より小さい数値を選択すると、$M$負の分割が必要ですが、これは無効であり、それより大きい数値は必要です。$M$不必要に操作が増えます。 
3. 操作の合計数のカウンターを初期化します。 
4. 各数値を反復処理します。$a_i$配列内:

 - 差を計算します$diff = M - a_i$。 
- もし$diff \% k \neq 0$、到達することは不可能です$M$から$a_i$ので、出力します$-1$このテストケースでは。 
- それ以外の場合は、必要な操作の数を計算します。$a_i$として$ops_i = diff // k$そしてトータルカウンターに加算します。 
5. すべての数値を処理した後、合計操作数を出力します。 

これが機能する理由は、すべての操作で数値が増加するためです。$k$総計で。 最大数を目標とすることで、各数値を繰り返し分割して、最終的には同じ合計貢献度に達することができます。$M$。 不変条件は、分割するたびに合計が ずつ増加するということです。$k$操作ごとに、正確に次の倍数に達するように分割を選択します。$M$。 逸脱があるとモジュロ条件が壊れ、不可能であることが示されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        M = max(a)
        total_ops = 0
        possible = True
        for num in a:
            diff = M - num
            if diff % k != 0:
                possible = False
                break
            total_ops += diff // k
        print(total_ops if possible else -1)

if __name__ == "__main__":
    solve()
```コードはまず、ターゲットとして最大数を特定します。 各数値について、サイズの整数分割で最大値に達することが可能かどうかを確認します。$k$。 の`diff % k`check は、数値を小数部に分割しようとする試みを防ぎます。 整数除算の最終的な合計により、最小の演算数が得られます。$k$1 回の分割操作が必要です。 このループは、余分な状態を保存することなく、複数のテスト ケースを効率的に処理します。
