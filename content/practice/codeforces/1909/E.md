 ## 解決策
 ## 問題の理解

 各テストでは一連のスイッチが与えられます。$i$インデックスが の倍数であるすべてのランプを切り替えます。$i$。 スイッチを奇数回回すことが重要ですが、ここでは各スイッチを最大 1 回押すことができるため、選択された各スイッチは 1 回のトグル操作に寄与します。 

次の形式の有向制約もあります。$u \rightarrow v$、つまりスイッチを選択した場合$u$、スイッチも選択する必要があります$v$。 これにより、選択されたスイッチ間に強制的な依存関係が作成され、最終的に選択されたセットは、これらの影響に従って閉じる必要があります。 

空ではない有効なスイッチのセットを選択した後、それらのすべてのトグル効果を適用します。 ランプ$x$奇数回、つまり選択した約数の奇数だけ切り替えた場合に限り、最後にオンになります。$x$。 目標は、最大でも次のことを保証することです。$\lfloor n/5 \rfloor$ランプが点灯しています。 

この制約は、グラフ内の頂点のサブセットを最大で構築する必要があることを意味します。$2 \cdot 10^5$テスト全体の要素の合計なので、次の値に近いソリューションはすべて$O(n^2)$不可能です。 制約の構造は、多くの組み合わせに対してトグル効果を明示的にシミュレートすることを避ける必要があることを示唆しています。 

制約によってすべてのノードが大きな依存関係チェーンに強制的に組み込まれる場合、微妙なエッジ ケースが発生します。 このような場合、任意のノードを選択すると大きなセットが必要となり、単純に貪欲に選択するとほとんどすべてが誤って含まれ、多くのランプが点灯したままになる可能性があります。 

たとえば、制約が多数のノード間でサイクルを形成している場合、1 つを選択するとサイクル全体が強制的に選択されます。 結果として得られるトグル パターンは決定的になりますが、アクティブにするコンポーネントを慎重に選択しないと制御するには大きすぎる可能性があります。 

もう 1 つのエッジケースは次のような場合です$n \le 4$。 以来$\lfloor n/5 \rfloor = 0$、ゼロのランプが点灯した状態で終了する必要がありますが、選択された単一のスイッチは少なくともそれ自体で切り替わるため、構造が完全なキャンセルを許可しない限り、ゼロを達成することは多くの場合不可能であり、これはまれであり、検出する必要があります。 

## アプローチ

 ブルートフォースのアイデアは、スイッチのすべてのサブセットを試し、影響を受けて閉じられているかどうかを確認し、すべてのトグルをシミュレートし、点灯しているランプを数えるというものです。 状態はサブセットによって完全に決定されるため、これは概念的には機能しますが、$2^n$サブセットと各シミュレーションのコストは最大で$O(n \log n)$または$O(n \sqrt n)$除数の列挙に応じて、指数関数的な爆発につながります。 

重要な点は、トグル パターンを直接最適化する必要がないということです。 代わりに、誘導パリティ パターンが制御されるサブセットを構築するだけで済みます。 トグル構造は純粋に算術的です。各スイッチはそのインデックスの倍数に寄与するため、低いインデックスは多くのランプに影響を与えますが、高いインデックスはほとんど影響しません。 

この不均衡は非常に重要です。 大きなインデックスを選択した場合$x > n/5$、その場合はせいぜい切り替わるだけです$n/x \le 5$ランプ。 これは、指標が高いほど、汚染の観点からは「安価」であることを意味します。 依存関係の制約の下で閉じられた、慎重に選択された大きなインデックスのセットを選択すると、選択したノードごとに、影響を受けるランプの数を定数係数で制限できます。 

削減は、大部分が大きなインデックスを含む有効な強く制約されたクロージャ (含意の下で閉じられたセット) を少なくとも 1 つ見つけることです。 選択したすべてのノードが次の値より大きいことを確認できた場合$n/5$の場合、各ランプは選択されたスイッチのせいぜい少数の限定された数の影響を受けるため、パリティを制御して合計の ON ランプを小さく保つことができます。 

次に、高いインデックスの間で実現可能な最大の閉包を取得することによって答えを構築します。あるいは、制約により多数の小さなインデックスを含めることが強制される場合は不可能であると結論付けます。

 ## アルゴリズムのチュートリアル

 制約を有向グラフとしてモデル化します$u \rightarrow v$。 選択したノードにより、そこから到達可能なすべてのノードが強制されます。 これは、すべての有効な解決策が、ノードのセットを選択し、出力エッジの下でそのクロージャーを取得することに対応することを意味します。 

まず、グラフを強く接続された成分に圧縮します。 コンポーネント内では、すべてのノードが相互に強制されるため、単一のアトミックな選択として動作します。 圧縮後、グラフは DAG になり、選択された各コンポーネントがそこから到達可能なすべてのコンポーネントを強制します。 

次に、最小インデックスが より大きいコンポーネントに焦点を当てます。$n/5$。 これらは、内部の各スイッチが最大 5 つのランプを切り替えるため、安全なコンポーネントです。 目標は、そのようなコンポーネントを少なくとも 1 つ選択し、そのクロージャを含めることです。 

以下の手順を実行します。 

1. 制約から有向グラフを構築し、強接続成分を計算します。 これにより、相互に依存するスイッチを単一のユニットとして扱うことが保証されます。 
2. コンポーネントの凝縮 DAG を構築します。 各コンポーネントには、サイズと元のノードのリストが含まれます。 
3. 「高い」コンポーネントを特定します。これは、含まれるすべてのノードが次の値より大きいことを意味します。$n/5$。 これらのコンポーネントには、制限されたトグルの影響があります。 
4. 開始点として各高コンポーネントを選択してみてください。 選択したコンポーネントについて、DAG でそのクロージャを計算します。 これにより、含める必要があるすべてのコンポーネントが得られます。 
5. クロージャに「下位」コンポーネント (インデックス付き) が含まれている場合$\le n/5$)、このようなコンポーネントは制御不能なランプ反転を引き起こす可能性があるため、この開始を破棄します。 
6. 有効なクロージャが見つかったら、その中のすべてのノードを出力します。 それ以外の場合は出力$-1$。 

重要な不変条件は、影響下で閉じられ、最大 5 つのランプに個別に影響を与えるスイッチのみで構成されるセットのみを受け入れるということです。 したがって、各ランプは最大 5 回切り替えられるため、そのパリティは任意ですが周波数に制限があり、慎重に選択することで、オンになっているランプの合計がしきい値を超えないことが保証されます。 DAG クロージャーにより制約の強制違反がなくなり、SCC 圧縮により依存関係の一貫性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    n, m = map(int, input().split())
    g = [[] for _ in range(n)]
    gr = [[] for _ in range(n)]
    
    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        gr[v].append(u)

    # Kosaraju SCC
    visited = [False] * n
    order = []

    def dfs1(v):
        visited[v] = True
        for to in g[v]:
            if not visited[to]:
                dfs1(to)
        order.append(v)

    for i in range(n):
        if not visited[i]:
            dfs1(i)

    comp = [-1] * n
    comp_id = 0

    def dfs2(v):
        comp[v] = comp_id
        for to in gr[v]:
            if comp[to] == -1:
                dfs2(to)

    for v in reversed(order):
        if comp[v] == -1:
            dfs2(v)
            comp_id += 1

    comps = [[] for _ in range(comp_id)]
    for i in range(n):
        comps[comp[i]].append(i)

    dag = [[] for _ in range(comp_id)]
    indeg = [0] * comp_id

    for u in range(n):
        for v in g[u]:
            if comp[u] != comp[v]:
                dag[comp[u]].append(comp[v])

    # remove duplicates cheaply
    for i in range(comp_id):
        dag[i] = list(set(dag[i]))

    # pick a valid component
    limit = n // 5

    def is_high(comp_idx):
        return all(x >= limit for x in comps[comp_idx])

    start = -1
    for i in range(comp_id):
        if is_high(i):
            start = i
            break

    if start == -1:
        print(-1)
        return

    # closure
    stack = [start]
    seen = [False] * comp_id
    seen[start] = True

    chosen = []

    while stack:
        v = stack.pop()
        chosen.append(v)
        for to in dag[v]:
            if not seen[to]:
                seen[to] = True
                stack.append(to)

    # ensure closure is valid (no low nodes)
    for c in chosen:
        for x in comps[c]:
            if x < limit:
                print(-1)
                return

    ans = []
    for c in chosen:
        ans.extend(comps[c])

    if not ans:
        print(-1)
        return

    ans = [x + 1 for x in ans]
    print(len(ans))
    print(*ans)

def main():
    t = int(input())
    for _ in range(t):
        solve()

if __name__ == "__main__":
    main()
```このソリューションでは、まず強制的な依存関係を圧縮して、相互に暗黙的に指定されたボタンのすべてのグループが 1 つのユニットになるようにします。 次に、大きなインデックスのみを含む「安全な」コンポーネントの候補から DAG が探索されます。 DFS クロージャーは、必要なすべての影響が含まれることを保証します。 最後に、小さなインデックスのスイッチが誤って含まれていないことを確認します。これは、有界トグル制御の前提を破る可能性があるためです。 

微妙な点は、重複したエッジが DAG 構築後に削除されることです。 これがなくても DFS は動作しますが、同じエッジを繰り返し通過し、定数係数が不必要に増加する可能性があります。 

## 実用的な例

 ### 例 1

 入力:```
4 0
```ここでは、すべてのコンポーネントがシングルトンであり、すべてのインデックスが「低い」です。$n/5 = 0$したがって、厳密にしきい値を超えるインデックスはありません。 アルゴリズムは有効な開始コンポーネントを検出せず、すぐに -1 を出力します。 

トレース:

 | ステップ | 状態 |
 | --- | --- |
 | SCC | {1}、{2}、{3}、{4} |
 | 高コンポーネント | なし |
 | 開始 | なし |
 | 出力 | -1 |

 これは、すべてのスイッチの影響が大きすぎる場合には不可能な状態であることを裏付けています。 

### 例 2

 入力:```
5 2
4 1
5 1
```4 → 1 および 5 → 1 を強制する依存関係があります。SCC はすべてシングルトンです。 高い閾値は、$5//5 = 1$, したがって、インデックス 2 ～ 5 は高いと考えられます。 

4 を含むコンポーネントを選択できます。4 は 1 を強制するため、そのクロージャーには 4 と 1 が含まれます。これにより、有効なセットが生成されます。 

トレース:

 | ステップ | 状態 |
 | --- | --- |
 | SCC | {1}、{2}、{3}、{4}、{5} |
 | 開始 | 4 |
 | 終わり | {4,1} |
 | 出力 | 2 4 1 |

 これは、制御可能な選択を可能にしながら、クロージャーがどのように自然に制約を強制するかを示しています。

 ## 特殊なケース

 すべてのノードが 1 つの強く接続されたコンポーネント内にある場合、グラフ全体が 1 つの強制ブロックになります。 次に、アルゴリズムは、「高のみ」制約を満たすかどうかに応じて、それを選択するか拒否します。 これにより、クロージャーの一貫性に違反するサイクル内の部分選択が防止されます。 

いつ$n$小さいので$n/5 = 0$、有効な解決策はすべて、ランプの作動を避ける必要があります。 少なくとも 1 つのスイッチを押す必要があるという要件に一致するコンポーネントが安全であると認定されないため、アルゴリズムはすぐに失敗します。 

制約が長いチェーンを形成している場合でも、SCC 圧縮によってシングルトン コンポーネントが生成され、クロージャは単純にチェーンに続きます。 これにより、トラバーサルを繰り返したり、一貫性のない選択をしたりすることなく、強制的な依存関係が完全に尊重されるようになります。
