 ## 解決策
 ## 問題の理解

 あらゆるポジションについて$i$、接頭辞を見てください。$p_1,\dots,p_i$順列の。 

定義する$$f(i)=\#\{j\le i \mid p_j\le i\}.$$一部の位置には規定の値が含まれています$a_i$、 意味$f(i)$まさにそうでなければなりません$a_i$。 とのポジション$a_i=-1$制限を課さない。 

指定された制約をすべて満たす順列の数を数えなければなりません。 

すべてのテスト ケースの合計の長さは最大でも$2\cdot 10^5$したがって、二次関数はすぐに除外されます。 平$O(n\sqrt n)$不快だろう。 本質的に線形のもの、または線形に小さな定数を掛けたものが必要です。 

難しいのは、拘束が選択された位置にのみ与えられることです。 単純な解釈では順列を直接構築しようとしますが、条件は位置と値にも同時に依存するため、局所的な推論が非常に困難になります。 

特に危険なエッジケースは最終ポジションです。 

のために$i=n$、$$f(n)=n$$すべての順列に対して、すべての値は最大でも$n$。 

もし$a_n$指定されており、$a_n\neq n$、答えはすぐにわかります$0$。 

例：```
n = 3
a = [-1, -1, 2]
```正しい答えは、$0$。 最後の位置の特別な役割を無視するソリューションでは、無効な構成がカウントされます。 

もう 1 つの微妙なケースは、指定された値を減らすことです。 

例：```
n = 4
a = [1, -1, 0, 4]
```以来$f(i)$は減少しないため、後で指定した値が以前の値よりも小さくなることはあり得ません。 答えは$0$。 

3番目のトラップは、長い距離があるときに表示されます。$-1$。 欠落している位置は独立していません。 制約は次に指定されたチェックポイントでのみ重要となるため、未知の位置をそれぞれ個別に処理すると、カウントが大幅にオーバーカウントされます。 

## アプローチ

 ブルートフォースアプローチはすべてを生成します$n!$順列を作成し、すべての制約をチェックします。 

固定順列の場合、すべての値を計算できます。$f(i)$で$O(n)$または$O(n\log n)$、しかしそれは問題ではありません。 たとえ$n=12$、$12!\approx 4.8\cdot 10^8$、すでに絶望的です。 

重要な観察は、この条件がルークの配置の問題に変換できるということです。$n\times n$ボード。 

ルークを置く$(i,p_i)$。 なぜなら$p$は順列であり、すべての行とすべての列に 1 つのルークが含まれます。 

ここで考えてみましょう$$f(i)=\#\{(r,c): r\le i,\ c\le i\}.$$言い換えると、$f(i)$ちょうど左上の内側のルークの数です$i\times i$四角。 

この幾何学的解釈により、問題は、特定の入れ子になった正方形内の規定数のルークを含む置換行列をカウントすることに変わります。 

仮定する$j$そして$i$連続した位置です。$a\neq -1$。 

それらの間で、ボードが成長します。$j\times j$正方形に$i\times i$四角。 

させて$$t=a_i-a_j.$$それらの$t$新しいルークは、正方形を拡張するときに追加された L 字型の領域に配置する必要があります。 

次元を書き換えると、計数の問題は次のようになります。 

配置方法を数える$t$から取得した L 字型ボード上の非攻撃ルーク$y\times y$を削除して正方形にする$x\times x$左下隅から正方形。 

指定されたさまざまな間隔は独立しているため、カウントは増加します。 

残りのタスクは、L 字型のルークの配置を数えることです。 

包含/除外を使用します。 

させて$F(n,m)$配置する方法の数になります$m$非攻撃ルーク$n\times n$ボード。 

行を選択し、列と一致させます。$$F(n,m)=\binom{n}{m}\frac{n!}{(n-m)!}.$$禁断の為に$x\times x$ブロック、そのブロックに強制的に入れられたルークの数を包含/除外すると、次のようになります。$$\sum_{k=0}^{t} (-1)^k F(x,k)\, F(y-k,t-k).$$これにより、$O(t)$1 つのセグメントの計算。 全セグメントの合計が増加するため、$t$テストケース全体で最大でも$n$、全体の複雑さは線形です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n!\cdot n)$|$O(n)$| 遅すぎる |
 | 最適 |$O(n)$テストケースごとの合計 |$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 階乗および逆階乗を最大で事前計算します。$2\cdot10^5$。 
2. 定義する$$A(n,m)=\frac{n!}{(n-m)!}, \qquad C(n,m)=\binom{n}{m}.$$1. 定義する$$F(n,m)=C(n,m)\cdot A(n,m).$$これは配置方法の数です$m$非攻撃ルーク$n\times n$ボード。 

1. もし$a_n$指定されており、$a_n\neq n$、出力$0$。 
2. 交換する$a_n$による$n$。 最後の正方形には常にすべてが含まれます$n$ルーク、だから扱います$n$必須チェックポイントとしてロジックを簡素化します。 
3. しましょう$j$最初は以前に指定された位置になります$0$と$a_0=0$。 
4. 指定位置ごと$i$:

 1. コンピューティング$$t=a_i-a_j, \qquad x=j-a_j, \qquad y=i-a_j.$$2. もし$t<0$、出力$0$。 
3. コンピューティング$$\text{ways} = \sum_{k=0}^{\min(x,t)} (-1)^k F(x,k) F(y-k,t-k).$$4. 答えにこの値を掛けます。 
5.セット$j=i$。 
5. 累積積モジュロを出力します。$998244353$。 

### なぜ効果があるのか

 指定されたチェックポイントごとに、値$a_i-a_j$は、入れ子になった 2 つの正方形の間に追加された L 字型の領域に新しいルークが何個出現するかを正確に示します。 

異なるチェックポイント間隔に対応する領域は互いに素であるため、ある間隔で行われた選択が別の間隔に影響を与えることはありません。 彼らの数は倍増します。 

セグメント内の唯一の禁止領域は、削除された領域です。$x\times x$四角。 包含/除外では、ボード全体の配置をカウントし、禁止されたセルを使用している配置を差し引きます。 用語$F(x,k)$を選択します$k$禁じられたルーク、一方$F(y-k,t-k)$行や列を競合させずに残りのルークを配置します。 

すべての有効な順列は、正確に 1 つのルーク配置構成に対応し、カウントされたすべてのルーク配置は、正確に 1 つの順列行列に対応します。 したがって、アルゴリズムによって生成されるカウントは、正確に適切な順列の数になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353
MAXN = 200000

fac = [1] * (MAXN + 1)
for i in range(1, MAXN + 1):
    fac[i] = fac[i - 1] * i % MOD

ifac = [1] * (MAXN + 1)
ifac[MAXN] = pow(fac[MAXN], MOD - 2, MOD)
for i in range(MAXN, 0, -1):
    ifac[i - 1] = ifac[i] * i % MOD

def C(n, r):
    if r < 0 or r > n or n < 0:
        return 0
    return fac[n] * ifac[r] % MOD * ifac[n - r] % MOD

def A(n, r):
    if r < 0 or r > n or n < 0:
        return 0
    return fac[n] * ifac[n - r] % MOD

def F(n, m):
    return C(n, m) * A(n, m) % MOD

t = int(input())

for _ in range(t):
    n = int(input())
    a = [0] + list(map(int, input().split()))

    if a[n] != -1 and a[n] != n:
        print(0)
        continue

    a[n] = n

    ans = 1
    prev = 0

    ok = True

    for i in range(1, n + 1):
        if a[i] == -1:
            continue

        t_inc = a[i] - a[prev]

        if t_inc < 0:
            ok = False
            break

        x = prev - a[prev]
        y = i - a[prev]

        ways = 0

        lim = min(x, t_inc)
        for k in range(lim + 1):
            cur = F(x, k) * F(y - k, t_inc - k) % MOD
            if k & 1:
                ways -= cur
            else:
                ways += cur

        ways %= MOD
        ans = ans * ways % MOD
        prev = i

    print(ans if ok else 0)
```階乗表と逆階乗表を使用すると、すべての二項係数と順列カウントを一定時間で評価できます。`F(n, m)`rook-count 式を直接実装します。 メインループは、指定されたチェックポイントのみを処理します。 セグメントごとに包含と除外の合計を計算し、それを乗算してグローバルな答えを求めます。 

微妙なディテールが強制的です`a[n] = n`。 これは追加の制限ではありません。 すべての順列はすでにそれを満たしています。 この変更は、最終セグメントが均一に処理されることを保証するだけです。 

もう 1 つの簡単な間違いは、次のような中間用語を忘れることです。`y - k`マイナスになる可能性があります。 ヘルパー関数は、無効なパラメーターに対して自動的にゼロを返します。これは、組み合わせの意味と一致します。

 ## 特殊なケース

 次のことを考慮してください。```
1
3
-1 -1 2
```すべての順列が満たされるので、$f(3)=3$、要件$a_3=2$不可能です。 アルゴリズムは、カウントする前にこれをチェックし、すぐに返します。$0$。 

考慮する：```
1
4
1 -1 0 4
```指定された値は次から始まります$1$まで$0$。 2 番目のチェックポイントを処理するときに、アルゴリズムは以下を計算します。$$t = a_i-a_j < 0.$$新しく追加されるルークの数がマイナスになることは不可能なので、答えは次のようになります。$0$。 

考慮する：```
1
5
-1 -1 -1 -1 -1
```人工的なチェックポイントだけ$a_5=5$存在します。 ボード全体を 1 つのセグメントとして扱い、$$F(5,5)=5!=120.$$すべての順列は 1 回だけカウントされます。
