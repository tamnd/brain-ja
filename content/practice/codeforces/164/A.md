[CF 164A - 変数、またはそこからまた戻る](https://codeforces.com/problemset/problem/164/A)

 **評価:** 1700
 **タグ:** dfs および類似のグラフ
 **解決時間:** 1 分 51 秒
 **確認済み:** はい

 ## 解決策
 ## 問題の理解

 すべてのノードがプログラムの状態を表す有向グラフが与えられます。 各状態は変数に対して次の 3 つのうちの 1 つを実行します。`0`変数が無視されることを意味します。`1`変数に新しい値が割り当てられることを意味します。`2`変数が使用されていることを意味します。 

状態が次の構造を持つ少なくとも 1 つの有向パスに属している場合、その状態は興味深いと呼ばれます。 

パスは割り当て状態で開始され、使用状態で終了します。割り当ての開始後はパス上に他の割り当てはありません。 

この最後の条件が問題の難しさ全体です。 2 番目の割り当てが表示されると、古い値は上書きされ、関連性がなくなります。 

すべての頂点について、このタイプの有効なパス上に存在できるかどうかを出力する必要があります。 

グラフには最大で次のものを含めることができます$10^5$頂点と$10^5$エッジ。 これにより、すべてのパスを明示的に探索しようとするアルゴリズムが即座に除外されます。 すべての割り当てノードから独立して DFS を実行しても、密度が高い場合にはコストが高くなりすぎます。 おおよそ線形時間に近いものが必要です$O(n + m)$。 

また、グラフが非循環であることも保証されません。 サイクルが重要なのは、別の割り当てに触れずに割り当てから到達可能な領域に入ると、その領域内のすべてのノードが無期限に有効なままになる可能性があるためです。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

次のグラフを考えてみましょう。```
1(assign) -> 2(assign) -> 3(use)
```入力：```
3 2
1 1 2
1 2
2 3
```正しい答えは次のとおりです。```
0 1 1
```状態 1 は面白くありません。 1 から使用ノードへのパスはすべて状態 2 を通過し、最初に値が上書きされます。 「使用ノードに到達できるかどうか」だけをチェックする不注意な到達可能性ソリューションでは、誤って状態 1 がマークされてしまいます。 

もう 1 つの微妙なケースは、割り当てノード自体が唯一の興味深いノードでもある場合です。```
1(assign) -> 2(ignore)
```入力：```
2 1
1 0
1 2
```正しい出力:```
0 0
```使用状態に到達することはないため、割り当てられた値は重要ではありません。 

サイクルにも注意が必要です。```
1(assign) -> 2(ignore) -> 3(ignore)
                  ^         |
                  |---------|
3 -> 4(use)
```4 つのノードはすべて興味深いものです。1 での割り当ての後、最終的に 4 に到達するまで任意に何度もループできるからです。DAG 構造を前提とするアルゴリズムはここで失敗します。 

## アプローチ

 ブルートフォースのアイデアは単純です。 すべての割り当てノードに対して、別の割り当てノードに遭遇するたびに停止するグラフ トラバーサルを実行します。 最終的に使用ノードにつながる可能性のあるすべての訪問ノードは、有効なパスに属します。 

これは正しいです。走査では、元の値が存続するすべてのパスが正確にシミュレートされるからです。 問題はコストです。 最悪の場合はこうなる可能性もある$10^5$割り当てノード、および各走査でグラフ全体をスキャンできます。 複雑さは次のようになります$O(n(n+m))$、これは大きすぎます。 

重要な観察は、どの代入ノードが値を開始したかは実際には気にしないということです。 ある割り当てから別の割り当てを越えることなくノードに到達できるかどうか、および別の割り当てによって値が上書きされる前にそのノードから使用状態に到達できるかどうかだけを考慮します。 

これは、検索を繰り返し再開するのではなく、情報を世界中に広めることを示唆しています。 

変数の現在の値がまだ有効である場合、その状態を「生きている」と定義します。 割り当てノードから、値が有効になります。 無視または使用ノードを通過すると、それが保持されます。 別の割り当てに移動すると、古い値が破棄され、新しい値が開始されます。 

これにより、問題はバリアのあるグラフ到達可能性の問題に変換されます。 

これは 2 つの段階で解決できます。 

まず、すべての割り当てノードから前方に伝播しますが、別の割り当てノードを超えて続行することはありません。 現在の値を維持したまま、訪問したすべてのノードに到達できます。 

次に、それらの到達可能なノードのうち、別の割り当てを越えることなく使用ノードに到達できるノードを決定します。 これは、グラフを反転し、すべての使用ノードから逆方向に伝播し、再び割り当て境界で停止することによって実行できます。 

両方の条件が同時に成立する場合、ノードは興味深いものになります。 

プロセス全体がすべてのエッジを一定回数だけ訪問するため、線形の複雑さが生じます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n(n+m))$|$O(n+m)$| 遅すぎる |
 | 最適 |$O(n+m)$|$O(n+m)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 有向グラフとその逆グラフを作成します。 

逆グラフは、使用ノードからの逆方向伝播に必要です。 
2. すべての割り当てノードからマルチソース BFS または DFS を開始します。 

これらのノードは、値が有効になる場所を表します。 
3. このトラバーサル中、通常どおり出力エッジを通過しますが、別の割り当てノードから続行しないでください。 

割り当てノードから開始した場合`s`、その後、別の割り当てノードに到達すると、元の値がそこで上書きされることを意味します。 
4. 訪問したすべてのノードを次のようにマークします。`from_assign`。 

これは、有効な変数値を保持しながらノードに到達できることを意味します。 
5. 別のマルチソース トラバーサルを開始します。今度はすべての使用ノードから、ただしグラフを反転します。 

逆方向にたどることで、「このノードは最終的に使用状態になる可能性があるか?」という質問に答えます。 
6. 繰り返しますが、割り当てノードをまたぐときは伝播を停止します。 

別の割り当てを通過すると、現在の値が変化するため、以前の状態は最終的な使用量に寄与しなくなります。 
7. 訪問したすべてのノードを次のようにマークします。`to_use`。 

これは、最初に値を上書きせずに、ノードから使用状態へのパスが存在することを意味します。 
8. すべてのノードについて、出力します。`1`両方の場合`from_assign[node]`そして`to_use[node]`本当です。 それ以外の場合は出力`0`。 

### なぜ効果があるのか

 ノードが興味深いのは、それが割り当てで始まり、中間割り当てのない使用で終わるパス上にあるときです。 

順方向トラバーサルでは、値が上書きされる前に、何らかの割り当てから到達可能なすべてのノードを識別します。 

逆方向トラバーサルでは、別の割り当てが表示される前にまだ使用量に到達できるすべてのノードが識別されます。 

両方の条件がノードに当てはまる場合、2 つの対応するパス セグメントを 1 つの有効な完全なパスに連結できます。 逆に、ノードが有効なパスに属している場合は、定義により両方のプロパティを満たす必要があります。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    f = list(map(int, input().split()))

    g = [[] for _ in range(n)]
    rg = [[] for _ in range(n)]

    for _ in range(m):
        a, b = map(int, input().split())
        a -= 1
        b -= 1
        g[a].append(b)
        rg[b].append(a)

    from_assign = [False] * n
    q = deque()

    for i in range(n):
        if f[i] == 1:
            from_assign[i] = True
            q.append(i)

    while q:
        u = q.popleft()

        for v in g[u]:
            if from_assign[v]:
                continue

            from_assign[v] = True

            if f[v] != 1:
                q.append(v)

    to_use = [False] * n
    q = deque()

    for i in range(n):
        if f[i] == 2:
            to_use[i] = True
            q.append(i)

    while q:
        u = q.popleft()

        for v in rg[u]:
            if to_use[v]:
                continue

            to_use[v] = True

            if f[v] != 1:
                q.append(v)

    ans = []

    for i in range(n):
        ans.append('1' if from_assign[i] and to_use[i] else '0')

    print('\n'.join(ans))

solve()
```2 つの走査では到達可能性の反対の質問に答えるため、グラフと逆グラフの両方が必要です。 

最初の BFS は、すべての割り当てノードから同時に開始されます。 微妙な点は、割り当てノードは依然として到達可能としてマークされていますが、ノード自体が最初のソースでない限り、伝播はそこで停止することです。 これは上書きを正しくモデル化します。 

2 番目の BFS は、反転したグラフ上の同じロジックをミラーリングします。 使用状況ノードから開始して後方に進むと、最終的にどの状態が使用状況に寄与できるかが決まります。 

条件:```
if f[v] != 1:
    q.append(v)
```は両方の走査において重要なラインです。 割り当て状態自体は興味深い可能性があるため、割り当てノードを到達可能としてマークしますが、古い値を使用してノードを超えて続行することはありません。 

最終的な答えは、2 つの到達可能性セットの交差部分です。

 ## 特殊なケース

 上書きシナリオをもう一度考えてみましょう。```
3 2
1 1 2
1 2
2 3
```前方トラバーサルは両方の割り当てノードから開始されます。 

ノード 1 からトラバーサルはノード 2 に到達しますが、ノード 2 は別の割り当てであるため、そこで停止します。 古い値をこれ以上継続することはできません。 

ノード 2 からノード 3 に到達します。 

ノード 3 からの逆方向トラバーサルはノード 2 に到達しますが、ノード 2 が値を上書きするため、ノード 2 を超えてノード 1 まで続行することはできません。 

交差点はこうなります`{2,3}`のみ、生成します:```
0
1
1
```ここでサイクルの例を考えてみましょう。```
4 4
1 0 0 2
1 2
2 3
3 2
3 4
```ノード 1 からの前方トラバーサルは 2 と 3 の間のサイクルに入り、両方のノードが到達可能であることをマークします。 どちらのノードも割り当てではないため、伝播は通常どおり続行されます。 

ノード 4 からの逆方向トラバーサルはノード 3 に到達し、次に反転したサイクル エッジを介してノード 2 に到達します。 

すべてのノードが両方の条件を満たすため、すべてのノードが興味深いとマークされます。 

最後に、割り当てはあるが役に立たないグラフを考えてみましょう。```
3 2
1 0 0
1 2
2 3
```順方向トラバーサルは、割り当てから到達可能なすべてのノードをマークします。 使用状態がないため、逆方向の走査はノードなしから開始されます。 

の`to_use`配列は完全に false のままであるため、すべての答えは次のようになります。`0`。 

これは、値は最終的に使用される場合にのみ重要であるという事実を正しく捉えています。
