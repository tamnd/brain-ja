 ## 解決策
 ## 問題の理解

 数直線上に配置された人々のセットが与えられています。 各人は乗客またはタクシー運転手のいずれかであり、すべての役職は個別に区別されており、すでに昇順にソートされています。 

乗客がタクシーをリクエストすると、システムは常に、ライン上の絶対距離の観点から最も近いタクシー運転手にそのリクエストを割り当てます。 2 人のタクシー運転手が同じくらい近い場合、座標が小さい運転手が選択されます。 各乗客は独立して 1 つのリクエストを生成します。全員が同時にタクシーをリクエストした場合、各タクシー運転手に何人の乗客が割り当てられるかを知りたいと考えています。 

タスクは、すべてのタクシー運転手について、運転手間の座標が増加する順に、この最近接同点規則に基づいて何人の乗客がその運転手と一致するかを計算することです。 

入力サイズは合計 200,000 人に達します。 これにより、各乗客をすべてのタクシー運転手と個別に比較するようなソリューションは即座に除外されます。これは、最悪の場合、時間制限をはるかに超えて二次関数となるためです。 解決策は線形または線形演算に近いものでなければなりません。 

複数の乗客が 2 人の隣接するタクシー運転手のちょうど中間点に位置する場合、微妙なエッジ ケースが発生します。 このような場合、タイブレークにより常に左側のタクシー運転手に割り当てが押し付けられます。 たとえば、ドライバーが 2 と 6 にいて、ライダーが 4 にいる場合、ライダーは 2 に進みます。どのソリューションも、この決定的な境界動作を尊重する必要があります。 

もう 1 つの特殊なケースは、すべてのドライバーがライダー クラスターの片側にいる場合です。 たとえば、すべてのタクシーが右側にある場合、利用可能な中で最も近い左端のタクシーがすべての乗客に割り当てられます。 

## アプローチ

 問題を解決する直接的な方法は、各乗客を個別に処理し、すべてのタクシー運転手をスキャンして最も近い運転手を見つけることです。 各ライダーについて、m 人のドライバー全員までの距離を計算し、最小値を選択します。 これは問題定義に直接従うため、正しいです。 

ただし、このアプローチには O(nm) の操作が必要です。 n と m が最大 100,000 の場合、これは最大 10^10 の比較になり、これは現実的ではありません。 

重要な観察は、乗客とタクシー運転手の両方がソートされた線上に位置しており、距離の比較は相対的な順序のみに依存しているということです。 固定の乗客の場合、最適となる可能性があるのは、左側に最も近いタクシー運転手と右側に最も近いタクシー運転手だけです。 他のすべてのドライバーは厳密にさらに遠くにあります。 

これにより、各乗客の両側で最も近いタクシー運転手を維持するという問題が軽減されます。 ドライバーの位置を追跡しながらラインをソートまたはスキャンすると、前処理後の O(1) の償却時間で各ライダーを割り当てることができます。 これを実現する標準的な方法は、最後に見たタクシー運転手を維持しながらラインを左から右にスイープし、さらに右にある次のタクシー運転手を事前計算することです。 これら 2 つの近傍がわかっているので、距離を比較し、座標順序を使用して関係を解決します。 

これにより、問題はライダーごとに一定時間の決定を伴う線形スキャンに変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nm) | お(1) | 遅すぎる |
 | 最近傍を使用した最適なスイープ | O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、位置を 2 つのリストに分割します。1 つはすべてのタクシー運転手の座標を含み、もう 1 つはすべての乗客の座標を含みます。 元のシーケンスはすでに座標によってソートされているため、これらのリストを 1 回のパスで作成できます。 

次に、各タクシー運転手の座標から、ソートされた運転手のリスト内のインデックスへのマッピングを準備します。 これが必要なのは、出力を入力順序ではなくドライバー座標によって順序付けする必要があるためです。

次に、ライン上のすべての位置について、左側に最も近いタクシー運転手を計算します。 私たちは最後に見たタクシー運転手を思い出しながら、左から右へと走ります。 タクシー運転手に遭遇するたびに、この値を更新します。 位置 x にいるライダーの場合、左側の最も近い候補が得られます。 

同様に右から左にスイープすることで、右に最も近いタクシー運転手も計算します。 

各乗客の候補者は最大で 2 人です。左のタクシー運転手と右のタクシー運転手です。 ライダーとの距離を比較します。 どちらかが近い場合は、そのドライバーにライダーを割り当てます。 両方が同等に近い場合は、座標が小さいため、左側に割り当てます。 

最後に、選択したタクシー運転手のカウンターをインクリメントし、ドライバー座標の昇順ですべてのカウントを出力します。 

### なぜ効果があるのか

 乗客の割り当ては、最寄りのタクシー運転手にのみ依存します。 線上では、どの点にもセット内で一意の最も近い要素があり、その最も近い要素は並べ替え順ですぐ左かすぐ右にある必要があります。 他のすべての候補は、厳密にはこれら 2 つのうちの少なくとも 1 つよりも遠いです。 タイブレーク ルールは、等距離の場合には常に左側を優先することと一致しているため、これら 2 つの候補間の比較によって結果が完全に決まります。 

これにより、検索スペースをライダーごとに 2 つの候補に減らすことで、すべての割り当ての正確性が維持されることが確立されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
x = list(map(int, input().split()))
t = list(map(int, input().split()))

riders = []
drivers = []

for i in range(n + m):
    if t[i] == 1:
        drivers.append(x[i])
    else:
        riders.append(x[i])

drivers.sort()

# maps driver position to its index in output order
pos_to_idx = {drivers[i]: i for i in range(m)}

INF = 10**18

left_driver = [-1] * (n + m)
right_driver = [-1] * (n + m)

last = -1
for i in range(n + m):
    if t[i] == 1:
        last = x[i]
    else:
        left_driver[i] = last

last = -1
for i in range(n + m - 1, -1, -1):
    if t[i] == 1:
        last = x[i]
    else:
        right_driver[i] = last

ans = [0] * m

for i in range(n + m):
    if t[i] == 0:
        x0 = x[i]

        L = left_driver[i]
        R = right_driver[i]

        # both exist
        if L != -1 and R != -1:
            dL = x0 - L
            dR = R - x0

            if dL <= dR:
                ans[pos_to_idx[L]] += 1
            else:
                ans[pos_to_idx[R]] += 1

        elif L != -1:
            ans[pos_to_idx[L]] += 1
        else:
            ans[pos_to_idx[R]] += 1

print(*ans)
```この実装は 2 方向のスイープに依存しています。 最初のスイープでは、乗客の位置ごとに、その左側に最も近いタクシー運転手が記録されます。 2 番目のスイープは右側に対して同じことを行います。 最後のループでは、最大 2 人の候補を比較することで各ライダーを個別に解決し、1 人当たりの一定時間の処理を保証します。 

重要な詳細はタイブレーク条件です`dL <= dR`これにより、ライダーがちょうど真ん中にいる場合、座標が小さいため、左側のタクシー運転手が優先されるようになります。 

辞書`pos_to_idx`ドライバの座標を出力インデックスに変換し、結果を必要な順序で蓄積できるようにします。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + m) | すべてのポジションにわたる 2 つの線形スイープと 1 つの最終割り当てパス |
 | スペース | O(n + m) | 配列は各ポジションの左と右の最も近いドライバーを格納します。 

このソリューションは、ライダーやドライバーに対するネストされた反復がなく、入力要素ごとに一定量の作業のみを実行するため、制限内で快適に実行されます。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, m = map(int, input().split())
    x = list(map(int, input().split()))
    t = list(map(int, input().split()))

    drivers = []
    riders = []
    for i in range(n + m):
        if t[i] == 1:
            drivers.append(x[i])
        else:
            riders.append(x[i])

    drivers.sort()
    pos_to_idx = {drivers[i]: i for i in range(m)}

    left_driver = [-1] * (n + m)
    right_driver = [-1] * (n + m)

    last = -1
    for i in range(n + m):
        if t[i] == 1:
            last = x[i]
        else:
            left_driver[i] = last

    last = -1
    for i in range(n + m - 1, -1, -1):
        if t[i] == 1:
            last = x[i]
        else:
            right_driver[i] = last

    ans = [0] * m

    for i in range(n + m):
        if t[i] == 0:
            x0 = x[i]
            L = left_driver[i]
            R = right_driver[i]

            if L != -1 and R != -1:
                if x0 - L <= R - x0:
                    ans[pos_to_idx[L]] += 1
                else:
                    ans[pos_to_idx[R]] += 1
            elif L != -1:
                ans[pos_to_idx[L]] += 1
            else:
                ans[pos_to_idx[R]] += 1

    return " ".join(map(str, ans))

# provided sample
assert run("3 1\n1 2 3 10\n0 0 1 0\n") == "3"

# all drivers, symmetric
assert run("2 2\n1 2 3 4\n1 1 0 0\n") == "2 2"

# tie case
assert run("1 2\n1 2 3\n0 1 1\n") == "1 0"

# edge: single rider
assert run("1 1\n5 10\n0 1\n") == "1"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | すべてのドライバーが単一 | 3 | 1 台のタクシーがすべての乗客を吸収します。 
| 対称分割 | 2 2 | バランスのとれた割り当ての正確さ |
 | ネクタイケース | 1 0 | 等距離での左優先 |
 | シングルライダー | 1 | 最小限の境界動作 |

 ## 特殊なケース

 特殊なケースの 1 つは、タクシー運転手が 1 人だけである場合です。 このスイープでは、左右の候補者がどちらか一方に不在として割り当てられるため、すべてのライダーはその 1 人のドライバーに頼ることになります。 アルゴリズムは、すべてのライダーの唯一のカウンターを正しくインクリメントします。 

もう 1 つのエッジ ケースは、すべての乗客が 2 人のタクシー運転手の間に両側から等距離に位置している場合です。 条件`dL <= dR`左側のドライバーへの決定的な割り当てが保証されます。 スイープにより両方の候補者が正しく識別されることが保証されるため、タイブレークはライダーごとに 1 回だけ適用されます。 

最後のエッジケースは、乗客が最初のタクシー運転手より前、または最後のタクシー運転手の後に現れたときに発生します。 どちらの状況でも、2 つの候補方向のうち 1 つだけが存在し、アルゴリズムは無効な比較を試行することなく、そのようなすべての乗客を唯一の利用可能な近隣に安全に割り当てます。
