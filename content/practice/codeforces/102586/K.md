 ## 問題の理解

 私たちはモンスターのマルチセットを管理しています。 モンスターは現在の HP によってのみ識別され、クエリは特定の HP 値を持つモンスターの数を変更するか、両方のプレイヤーが最適にプレイした場合に指定された数のモンスターを除去するのにボブのターンが何回必要かを尋ねます。 

ゲームの重要な量は、攻撃の正確な順序ではなく、除去する必要がある HP の量です。 HPのあるモンスター1体を考える`x`。 アリスは常に最初に動き、ボブが攻撃するたびにこのモンスターを 1 増やすことができます。 後`t`ボブはこのモンスターに集中して攻撃し、それを受け取ります`t`増加し、`2t`ダメージがあるので残りHPは`x + t - 2t = x - t`。 まさにその瞬間に消えてしまう`t = x`。 これはHPを持つモンスター1体を意味します`x`正確にコストがかかります`x`ボブは振り向いて外そうとする。 

複数のモンスターについても同様の考え方が適用されます。 ボブが合計 HP を持つモンスターを選択した場合`S`、彼は正確に過ごすことができます`S`回してそれらを削除します。 その理由は、ボブのターンごとに 2 ダメージが与えられるのに対し、アリスは 1 HP しか与えられないため、1 ラウンドで選択したモンスターの合計 HP が 1 減少するためです。 ボブはいつでもアリスが増加したばかりのモンスターを攻撃できるため、アリスが単一のモンスターに余分なHPを蓄積するのを防ぎます。 アリスは、初期 HP 値の合計を超えてプロセス全体を遅らせることはできません。 

ボブはできるだけ早く終わらせたいので、HP 値が最も小さいモンスターを選択します。 を求めるクエリ`k`したがって、死亡数は次の合計を求めています。`k`現在存在する最小の HP 値。 

到達できるクエリの数`3 * 10^5`したがって、すべてのクエリに対してすべてのモンスターをスキャンすることは不可能です。 HP 値の制限は次のとおりです。`10^6`これは、HP によってインデックス付けされた情報を保存できることを意味します。 更新のたびにすべてのモンスターを並べ替えるソリューションでは、モンスターの数も非常に多くなる可能性があるため、時間がかかりすぎます。 1 つの HP 値のカウントの変更と、指定された数のモンスターを含むプレフィックスの検索をサポートする対数データ構造が必要です。 

重要なエッジ ケースは、重複した HP 値と境界位置の周囲に集中しています。 クエリは、同じ HP 値のすべてのモンスターを要求することも、同じ HP を持つグループの途中で停止することもできます。

## アプローチ

 直接的なアプローチでは、すべてのモンスターをリストに保存します。 タイプ 2 クエリの場合、現在の HP 値を並べ替えて、最初の値を取得します。`k`を追加してください。 ゲームは選択することになるので、これは正しいです。`k`HPの最小値。 ただし、最大で`3 * 10^5`クエリ、モンスターの数は最大約`10^11`各アップデートでは最大までのカウントを設定できるため、`10^6`。 ソートコストを無視したとしても、すべてのモンスターを反復処理することは不可能です。 クエリごとに並べ替えると、制限時間を大幅に超えてしまいます。 

有益な観察は、HP 値自体が小さいということです。 すべてのモンスターを個別に知る必要はありません。 各 HP 値について必要な情報は 2 つだけです`x`: HPを持つモンスターの数`x`、およびそれらのモンスターの合計貢献度、つまり`x * count[x]`。 

これにより、問題は固定座標範囲にわたる周波数と加重和の維持に変換されます。 更新は 1 つの位置に影響し、クエリにはプレフィックスの合計が必要なため、フェンウィック ツリーは自然に適合します。 1 つのフェンウィック ツリーにはカウントが保存され、もう 1 つは HP 値の合計が保存されます。 クエリに答えるために、プレフィックス数が次の値に達する最小の HP 値を見つけます。`k`。 小さい値はすべて完全に取得され、残りのモンスターはその最終 HP 値から取得されます。 

比較は次のとおりです。

 ## アルゴリズムのチュートリアル

 1. HP によってインデックス付けされた 2 つのフェンウィック ツリーを保存します。 最初のツリーには、各 HP 値で存在するモンスターの数が格納されます。 2 番目のツリーには、その値によって寄与される合計 HP が格納されるため、`x`店舗`x * count[x]`。 
2. HPを持つモンスターの数を変更する更新クエリの場合`x`に`y`、前回のカウントとの差を計算します。 この差をカウント フェンウィック ツリーに追加し、`x`この差をフェンウィック ツリーの合計に掛けます。 
3. 最初の質問の場合`k`モンスターを HP 順にソートし、カウント フェンウィック ツリーを使用して最小の HP 値を見つけます`pos`ここで、プレフィックス数は少なくとも`k`。 
4. すべての HP 値が以下の値より小さい`pos`が完全に含まれています。 フェンウィック ツリーの合計から合計 HP を追加します。 
5. 残りの必要なモンスターはHPから取得されます`pos`。 残りのカウントを掛ける`pos`そしてそれを答えに追加します。 

これが機能する理由は、答えがソートされた HP 値の複数セットにのみ依存するためです。 フェンウィック ツリーを使用すると、すべてのモンスターを明示的に保存しなくても、この並べ替えられた順序をナビゲートできます。 

### なぜ効果があるのか

 アリスとボブのラウンドが完了するたびに、ボブがそのコレクション内で攻撃すると、選択したモンスターのコレクションの合計 HP がちょうど 1 減少します。 ボブは、除去したいモンスターが必要なダメージを受けるように攻撃を常に選択できますが、アリスの追加 HP はラウンドごとにその進行度の 1 ポイントのみをキャンセルします。 したがって、総HPを持つモンスターのコレクション`S`正確に必要です`S`ボブは向きを変えて姿を消します。 

ボブは、次の中で総 HP を可能な限り小さくしたいと考えています。`k`モンスターなので、最適な選択はまさに`k`HPの最小値。 データ構造は正確にこの合計を返し、アルゴリズムが正しい答えを生成することを証明します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXX = 10**6

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, idx, val):
        while idx <= self.n:
            self.bit[idx] += val
            idx += idx & -idx

    def sum(self, idx):
        res = 0
        while idx:
            res += self.bit[idx]
            idx -= idx & -idx
        return res

    def kth(self, k):
        idx = 0
        step = 1 << (self.n.bit_length() - 1)
        while step:
            nxt = idx + step
            if nxt <= self.n and self.bit[nxt] < k:
                idx = nxt
                k -= self.bit[nxt]
            step >>= 1
        return idx + 1

def solve():
    q = int(input())
    cnt_tree = Fenwick(MAXX)
    sum_tree = Fenwick(MAXX)
    cnt = [0] * (MAXX + 1)

    ans = []

    for _ in range(q):
        query = input().split()
        t = int(query[0])

        if t == 1:
            x = int(query[1])
            y = int(query[2])
            diff = y - cnt[x]
            cnt[x] = y
            cnt_tree.add(x, diff)
            sum_tree.add(x, diff * x)

        else:
            k = int(query[1])
            pos = cnt_tree.kth(k)
            before = cnt_tree.sum(pos - 1)
            total = sum_tree.sum(pos - 1)
            total += (k - before) * pos
            ans.append(str(total))

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```の`cnt`配列は、更新を差分に変換できるように、すべての HP 値の現在の頻度を保存します。 フェンウィック ツリーには、クエリに必要な集約情報のみが保存されます。 

の`kth`関数は、フェンウィック ツリーでバイナリ リフティングを実行します。 プレフィックス数が要求された値に達する最初の位置を見つけます。`k`。 これにより、プレフィックス クエリを繰り返す二分検索が回避され、各クエリが対数に保たれます。 

答えの計算では、完全に含まれたプレフィックスと、部分的に含まれた最終的な HP 値が分離されます。 通常、ここで off-by-one エラーが発生します。 前のカウント`pos`除外する必要があります。`k - before`からのモンスター`pos`貢献する。 

Python の整数は、オーバーフローすることなく可能な最大の合計を処理します。 考えられる最大の寄与は 32 ビットの制限をはるかに超えているため、通常の Python 算術演算を使用すると、追加の処理を回避できます。

import io

    sys.stdin = io.StringIO(inp)

    data = sys.stdin.read().split()
    if not data:
        return ""

    q = int(next(it))

    MAXX = 10**6

    class Fenwick:
        def __init__(self, n):
            self.n = n
            self.bit = [0] * (n + 1)

        def add(self, i, v):
            while i <= self.n:
                self.bit[i] += v
                i += i & -i

        def sum(self, i):
            r = 0
            while i:
                r += self.bit[i]
                i -= i & -i
            return r

        def kth(self, k):
            idx = 0
            step = 1 << (self.n.bit_length() - 1)
            while step:
                nxt = idx + step
                if nxt <= self.n and self.bit[nxt] < k:
                    idx = nxt
                    k -= self.bit[nxt]
                step >>= 1
            return idx + 1

    c = Fenwick(MAXX)
    s = Fenwick(MAXX)
    cur = [0] * (MAXX + 1)
    out = []

    for _ in range(q):
        t = int(next(it))
        if t == 1:
            x = int(next(it))
            y = int(next(it))

            b = c.sum(p - 1)
            out.append(str(s.sum(p - 1) + (k - b) * p))

    sys.stdin = old
    return "\n".join(out)
