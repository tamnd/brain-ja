 ## 解決策
 ## 問題の理解

 数直線上にソートされた 2 つの点のセットがあります。 最初のセットにはロボットの位置が含まれ、2 番目のセットにはアンテナの位置が含まれます。 アンテナをアクティブにするたびに、アンテナはまだ生きている最も近いロボットを削除し、それらの間の距離を支払います。 タスクは、最終的なマッチングを直接決定することではなく、支払われるすべての距離の合計ができるだけ小さくなるようにアンテナのアクティブ化の順序を選択することです。 

出力には 2 つの部分があります。 最初の行は、可能な最小合計距離です。 2 行目は、その値を達成するすべてのアンテナのアクティブ化順序です。 

ロボットの数は 200,000 に達する可能性があります。二次解では最悪の場合でも約 400,000,000 回の操作が実行されますが、これは 2 秒の制限をはるかに超えています。 線形または線形時間に近いアルゴリズムが必要です。 座標は 10^9 まで大きくなるため、実装では距離に 64 ビット整数を使用する必要があります。 

いくつかの詳細が、他の点では合理的な解決策を壊す可能性があります。 1 つ目は、起動するたびに最も近いロボットが変更される可能性があることです。 たとえば、ロボットが 0 と 10 にあり、アンテナが 4 と 6 にある場合、アンテナ 4 をアクティブにすると、まず 0 のロボットが削除されますが、その後、アンテナ 6 が強制的に 10 のロボットを取得します。最も近いロボットをすべて 1 回事前計算するソリューションは間違っています。 

2番目の問題はタイルールです。 アンテナが 2 台のロボットのちょうど真ん中にある場合、左側のロボットは消えます。 たとえば、ロボットが 0 と 10、アンテナが 5 の場合、選択されるロボットは 10 ではなく 0 になります。このルールを無視すると、結果の順序が変わる可能性があります。 

3 番目の問題は、答えには最低額だけではなく順序が必要であるということです。 最小コストのマッチング アルゴリズムだけでは、有効なアクティブ化シーケンスを記述できません。 

## アプローチ

 直接的なアプローチでは、プロセスをシミュレートし、次にアクティブにする必要があるアンテナを繰り返し検索します。 考えられるすべての次のアンテナを試し、すべてのロボットをスキャンして最も近い残りのロボットを見つけると、複雑さは O(N^3) になります。 二分探索による最近傍ロボット探索を改善しても、考えられるすべてのアクティブ化の選択肢を検討すると、依然として O(N^2) アプローチが残ります。 

重要な観察は、最良の次の動きは常に現在最も近いロボットとアンテナのペアであるということです。 最も近い残りのペアの距離が d であると仮定します。 最初に他のアンテナをアクティブにすると、そのコストは少なくとも d になります。 選択したロボットとアンテナはまだ生きているため、他のアンテナを削除しても、選択した最も近いペアを安くすることはできません。 最も近いペアを即座にアクティブ化すると、可能な限り最小額が支払われ、より小さなセットに同じ種類の問題が残ります。 この貪欲な選択を繰り返すことで、最適なシーケンスが得られます。 

残りの課題は、最も近い反対色のペアを効率的に維持することです。 1 つの次元では、最も近いロボットとアンテナが、残りのすべての点のソート順で隣接している必要があります。 それらの間に別の点がある場合、その点は 2 つのうちの 1 つとさらに短いクロスカラー ペアを作成します。 これは、マージされたリスト内の隣接するペアのみを維持する必要があることを意味します。 

ペアが削除されると、新しい隣接関係は 1 つだけ表示されます。削除されたペアの直前のポイントとその直後のポイントです。 すべての隣接ペアの候補を優先キューに保存し、ローカルな変更のみを更新できます。 これにより、プロセス全体が O(N log N) に削減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N^3) | O(N) | 遅すぎる |
 | 最適 | O(N log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

1. すべてのロボットとアンテナを 1 つの並べ替えられた配列に結合します。 要素ごとに、その座標、タイプ、およびアンテナの場合は元のアンテナ インデックスを保存します。 この配列の順序は、数直線上で生き残っている点の現在の順序を表します。 
2. このマージされた配列内のすべての隣接するペアについて、一方の要素がロボットで、もう一方の要素がアンテナである場合、ペアとその距離を最小ヒープに挿入します。 これらはまさに、最初に考えられる最も近いペアです。 
3. ヒープから最小距離のペアを繰り返し取得します。 いずれかの要素がすでに削除されているか、2 つの要素が隣接していない場合は、その要素を破棄して続行します。 それ以外の場合、これは次の貪欲なアクティベーションです。 
4. このペアの距離を答えに加算し、アンテナ インデックスを出力順序に追加します。 アンテナとロボットの両方を生存ポイントのリンク リストから削除します。 
5. ペアを削除した後、以前の生き残ったネイバーを次の生き残ったネイバーに接続します。 これら 2 つの新しい近隣のタイプが異なる場合は、この新しい候補ペアをヒープに挿入します。 
6. すべてのアンテナがアクティブになるまで続けます。 収集されたアンテナ インデックスは必要な順序です。 

貪欲な選択が機能する理由は、現在のロボットとアンテナの距離を最小にすることが避けられないためです。 そのペアは残りのすべてのポイントの中で可能な限り最も近い相互作用であるため、少なくとも 1 つのアンテナ起動ではその金額以上を支払う必要があります。 先にそれを選択すると、この下限が達成され、同じ問題が 2 点減って残ります。 帰納法により、その後のすべてのステップも最適化されます。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    points = []
    for i, x in enumerate(a):
        points.append((x, 0, -1))
    for i, x in enumerate(b):
        points.append((x, 1, i + 1))

    points.sort()

    m = 2 * n
    left = [-1] * m
    right = [-1] * m
    for i in range(m):
        if i:
            left[i] = i - 1
        if i + 1 < m:
            right[i] = i + 1

    def add_pair(u, v):
        if u == -1 or v == -1:
            return
        if points[u][1] != points[v][1]:
            heapq.heappush(heap, (points[v][0] - points[u][0], u, v))

    heap = []
    for i in range(m - 1):
        add_pair(i, i + 1)

    ans = 0
    order = []

    while order.__len__() < n:
        while True:
            d, u, v = heapq.heappop(heap)
            if right[u] == v and left[v] == u:
                break

        ans += d
        if points[u][1] == 1:
            order.append(points[u][2])
        else:
            order.append(points[v][2])

        l = left[u]
        r = right[v]

        if l != -1:
            right[l] = r
        if r != -1:
            left[r] = l

        add_pair(l, r)

    print(ans)
    print(*order)

if __name__ == "__main__":
    solve()
```マージされた配列は最初に 1 回ソートされます。 配列`left`そして`right`この並べ替え順序に対するリンク リストとして機能します。 通常の Python リストから要素を削除すると、削除するたびに多くの要素が移動する可能性があるため、時間がかかりすぎます。 

ヒープには、隣接するペアの候補が格納されます。 一部のエントリは後で削除すると無効になるため、コード チェックが行われます。`right[u] == v and left[v] == u`ペアを使用する前に。 この遅延削除により、高価なヒープ更新が回避されます。 

距離の計算には Python 整数が使用され、およそ 2 * 10^14 までの可能な合計距離を安全に処理します。 アンテナ インデックスはその座標とは別に保存されるため、最終出力では元の番号が使用されます。

 ## 特殊なケース

 最初のエッジケースは、最も近いロボットを変更することです。 入力用```
2
0 10
4 6
```最初のアクティブ化では、コスト 4 で 0 のロボットが削除されます。次に、残りのアンテナがコスト 4 で 10 のロボットを削除します。アルゴリズムは、古い最近傍情報を保持するのではなく、削除のたびにマージされたリンク リストを更新するため、これを処理します。 

2 番目のエッジケースは引き分けです。 入力用```
2
0 10
5 20
```同点が左に行くため、アンテナ 5 はロボット 0 を選択します。 マージされた順序には正確な座標順序が保存されるため、隣接ペア表現では正しい選択が保持されます。 

3 番目のエッジ ケースは、ペアを削除すると、新しい最も近いペアが作成される場合です。 入力用```
3
0 50 100
10 90 200
```最初の近いペアが削除された後、それによって分離されていた 2 つの点が隣接する可能性があります。 ヒープはリンク リストの更新直後にこの新しい候補を受け取るため、次の貪欲な選択は正しいままになります。
