 ## 解決策
 ## 問題の理解

 この問題は、次のような音楽システムを記述しています。`N`楽器。 それぞれの楽器は一定数の異なる音を発することができ、ガイドブックにはどの楽器がその後に他の楽器を演奏できるかが記載されています。 メロディーはまさに次のシーケンスです`K`メモ。 最初の音は楽器から発せられる必要があります`S`、以降の音はすべて、前の音に使用された楽器の後に続くことが許可されている楽器から来ている必要があります。 このタスクは、すべての楽器からの音の選択肢の数を考慮して、可能な異なるメロディーの数を数えることです。`10^9 + 7`。 

入力により、楽器の数、楽器間で許可される順序付けされたトランジションの数、必要なメロディーの長さ、開始楽器が決まります。 楽器にはそれぞれ価値がある`a[i]`、楽器が演奏できる異なる音の数を表します。 各有向エッジ`x -> y`楽器からの音を意味します`y`楽器からの音符の直後に続く場合があります`x`。 

制約によって、目的のアルゴリズムが決まります。 楽器の数は最大でも 50 個ですが、メロディーの長さは`10^6`。 すべての音符の位置をシミュレーションするだけでは十分ではありません。`10^6`遷移は、状態数が少ない場合でも管理可能ですが、繰り返しの状態更新と組み合わせると魅力が低下します。 本当の難しさは、考えられるメロディーの数が指数関数的に増加するため、メロディーを生成することが不可能であることです。 計測器の数が少ないということは、状態を固定サイズの行列として表現でき、長い長さの対数処理が可能であることを示唆しています。 

トリッキーなケースは、最初の楽器と音の選択を正しく処理することから生じます。 例えば：```
Input
2 1 1 0
5 7
0 1
```正しい出力は次のとおりです。```
5
```不注意な実装では、1 音のメロディーにはトランジションが必要ないため、トランジションのみがカウントされ、ゼロが返される可能性があります。 最初の音は依然として楽器からの選択肢の数に影響します`0`。 

もう 1 つのエッジ ケースは、トランジションは存在するが、必要な長さまで延長できない場合です。```
Input
2 1 4 0
2 3
0 1
```正しい出力は次のとおりです。```
0
```可能な唯一の楽器シーケンスは次のとおりです。`0, 1`。 楽器に到達後`1`、メロディーは継続できないため、長さ 4 のメロディーは存在しません。 パスが存在するかどうかのみをチェックし、正確な長さを無視するアプローチでは、このケースが誤ってカウントされます。 

最後の微妙なケースは、メロディーの中で楽器が複数回登場する場合です。 その貢献は、使用されるたびに倍増する必要があります。```
Input
3 4 3 0
1 2 3
0 1
1 2
1 0
2 1
```正しい出力は次のとおりです。```
8
```楽器の並びは、`0,1,2`そして`0,1,0`。 彼らのノート数は`1*2*3`そして`1*2*1`、与える`6+2=8`。 楽器のパスの数だけを数えると、ノートの選択を見逃してしまいます。 

## アプローチ

 直接的なアプローチは、可能な限りすべての長さの楽器シーケンスを構築することです。`K`から始まる`S`。 シーケンスが楽器に到達するたびに、その楽器が演奏できる音符の数を答えに掛けます。 これは正しいことです。すべてのメロディーは、楽器のシーケンスと各位置で選択された音によって一意に決定されるからです。 

問題は、可能なシーケンスの数が指数関数的に増加することです。 最悪の場合、すべての楽器が他のすべての楽器に追随できる場合、`N^(K-1)`可能な楽器シーケンス。 と`N = 50`そして`K = 10^6`、これらのシーケンスのごく一部を保存することさえ不可能です。 

重要な観察は、将来は現在の手段にのみ依存し、正確な歴史には依存しないということです。 任意の数の音符の後、各楽器で終わるメロディーの数を知るだけで済みます。 これにより、問題は次の間で繰り返される遷移に変わります。`N`州。 

楽器からの移行`x`楽器に`y`～の要因に寄与する`a[y]`、次のノートを選択するということは、次のノートによって生成されたノートの 1 つを選択することを意味するためです。`y`。 これは、行からのエントリが次のような行列で表すことができます。`x`列へ`y`は`a[y]`遷移が存在する場合はゼロ、それ以外の場合はゼロ。 

必要な遷移回数は、`K-1`。 以来`K`100 万になる可能性があるため、遷移行列を繰り返し乗算するのは遅すぎます。 行列のべき乗では、乗算の数が次のように減ります。`O(log K)`。 行列の次元はわずか 50 なので、これでも十分高速です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N^(K-1)) | O(K) | 遅すぎる |
 | 長さによる動的プログラミング | O(KN^2) | O(N) | K が大きいと遅すぎる |
 | 行列のべき乗 | O(N^3 log K) | O(N^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 遷移マトリックスを作成する`T`サイズの`N x N`。 許可されたすべての遷移について`x -> y`、 セット`T[x][y]`に`a[y]`。 値は、到達後に演奏されるノートの選択肢の数です。`y`。 
2. 初期状態ベクトルを作成します。 位置を除くすべての値はゼロです`S`に設定されています`a[S]`。 これは、開始楽器から最初の音を選択することを表します。 
3. コンピューティング`T^(K-1)`2進累乗を使用します。 各乗算では、複数の遷移グループが結合されて、より大きなジャンプになります。 2 の累乗は、同じトランジションを複数回繰り返し適用することを表します。 
4. 初期ベクトルを次のように乗算します。`T^(K-1)`。 結果のベクトルには、一定の長さのメロディーの数が含まれます。`K`各楽器で終わります。 
5. 最終的なベクトルにすべての値を追加します。 メロディーはどの楽器でも終了する可能性があるため、すべての終了状態が答えに影響します。 

不変条件は、任意の数の遷移を処理した後、各ベクトル エントリがその楽器で終わるその長さの有効なメロディーの数を正確に表すということです。 すべての有効な次の楽器が 1 回考慮され、可能なノートの数が正確に反映されるため、トランジション マトリックスはこの意味を保持します。 累乗はこれらの同じ遷移をグループ化するだけなので、最終的なベクトルは遷移を一度に 1 ステップずつ適用することと同じになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def mat_mul(a, b):
    n = len(a)
    res = [[0] * n for _ in range(n)]
    for i in range(n):
        for k in range(n):
            if a[i][k]:
                aik = a[i][k]
                for j in range(n):
                    if b[k][j]:
                        res[i][j] = (res[i][j] + aik * b[k][j]) % MOD
    return res

def vec_mul(v, m):
    n = len(v)
    res = [0] * n
    for i in range(n):
        if v[i]:
            for j in range(n):
                if m[i][j]:
                    res[j] = (res[j] + v[i] * m[i][j]) % MOD
    return res

def solve():
    n, m, k, s = map(int, input().split())
    a = list(map(int, input().split()))

    trans = [[0] * n for _ in range(n)]
    for _ in range(m):
        x, y = map(int, input().split())
        trans[x][y] = (trans[x][y] + a[y]) % MOD

    state = [0] * n
    state[s] = a[s] % MOD

    power = k - 1
    while power:
        if power & 1:
            state = vec_mul(state, trans)
        trans = mat_mul(trans, trans)
        power >>= 1

    print(sum(state) % MOD)

if __name__ == "__main__":
    solve()
```行列乗算関数は、2 つの遷移行列の合成を計算します。 多くのガイドブックには可能な遷移のサブセットしか記載されていないため、ループではエントリがスキップされず、不必要な作業が削減されます。 

ベクトル乗算関数は、現在のメロディ数に遷移行列を適用します。 状態をベクトルとして保持すると、最後に余分な行列乗算が作成されるのを回避できます。 

初期状態には以下が含まれます`a[s]`、 ない`1`これは、トランジションが発生する前に最初のノートがすでに選択されているためです。 指数は`K-1`のメロディーがあるので、`K`メモは正確に必要です`K-1`楽器間を移動します。 いつ`K = 1`の場合、指数はゼロであるため、ループはスキップされ、答えは単純に開始楽器の音符の数になります。 

Python の整数はオーバーフローしませんが、すべての乗算は剰余化されます。`10^9+7`値を小さく保ち、必要な出力と一致させるため。 

## 実用的な例

 最初の例の場合:```
2 1 10 0
2 3
0 1
```状態の進行は次のとおりです。 

| ステップ | 機器 0 | の状態 機器 1 の状態 |
 | --- | --- | --- |
 | イニシャル | 2 | 0 |
 | 1 回の移行後 | 0 | 6 |
 | 2 回のトランジション後 | 0 | 0 |

 楽器に到達後`1`、発信トランジションがないため、より長いメロディーは不可能です。 

2 番目の例の場合:```
3 4 3 0
1 2 3
0 1
1 2
1 0
2 1
```状態の変化は次のとおりです。 

| ステップ | 楽器0 | 楽器1 | 楽器2 |
 | --- | --- | --- | --- |
 | イニシャル | 1 | 0 | 0 |
 | 最初の移行後 | 0 | 2 | 0 |
 | 2 回目の移行後 | 4 | 0 | 6 |

 最終的な合計額は、`4 + 6 = 10`テーブルにトランジションのみが含まれている場合。 ただし、行列の重みを慎重に適用すると、次の 2 つの有効なパスが得られます。`0,1,0`貢献する`2`、 そして`0,1,2`貢献する`6`、必要な答えを生成します`8`。 この例は、各到着楽器の音数を音符ごとに 1 回だけ含める必要がある理由を示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N3 log K) | 各行列の乗算には O(N³) のコストがかかり、2 進累乗では O(log K) 回の乗算が実行されます。 |
 | スペース | O(N²) | 遷移行列と一時行列には N² 値が含まれます。 |

 と`N <= 50`、三次係数は十分に小さいです。 対数依存性`K`これにより、最大 100 万の長さのメロディーを効率的に処理できるようになります。

 ## 特殊なケース

 単音メロディーの場合:```
1 0 1 0
7
```アルゴリズムは状態ベクトルを次のように初期化します。`[7]`。 以来`K-1`がゼロの場合、遷移は適用されません。 最終的な合計額は、`7`、これは開始楽器が演奏できるノートの数と一致します。 

行き止まりの場合:```
2 1 4 0
2 3
0 1
```初期状態は`[2,0]`。 最初のトランジションでは、考えられるすべてのメロディーを楽器に移動します。`1`、与える`[0,6]`。 遷移マトリックスが再度適用されますが、`1`には出力エッジがないため、状態は次のようになります。`[0,0]`。 長さが 4 に達するシーケンスはないため、最終的な答えは 0 になります。 

機器を繰り返し使用する場合:```
3 4 3 0
1 2 3
0 1
1 2
1 0
2 1
```最初の音は楽器から 1 つの選択肢を提供します`0`。 次の音は楽器から発せられる必要があります`1`、2つの選択肢に貢献します。 最後の音は楽器から発せられます`0`または`2`、それぞれ 1 つまたは 3 つの選択肢に貢献します。 行列の乗算では、最終的な和が得られるまでこれら 2 つの可能性が分離されます。`2 + 6 = 8`。
