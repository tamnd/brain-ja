 ## 解決策
 ## 問題の理解

 この問題では、忘れたパスワードをいくつかの回復コードから回復するように求められます。 各コードは正確に`k`しかし、すべてのコードは同じ未知の桁位置の再配置の影響を受けています。 結果として得られる最大のコードを結果として得られる最小のコードにできるだけ近づける位置の順列を見つけ、その差を可能な限り最小限に出力する必要があります。 

入力には以下が含まれます`n`コードと桁数`k`各コードで。 の単一の順列`k`位置はすべてのコードに適用する必要があります。 その順列を選択すると、各コードが新しいコードになります。`k`目標は、変換された最大値と最小値の差を最小限に抑えることです。 

最も重要な次元における制約は小さいです。 コードは最大 100 個まで使用でき、各コードは最大 9 桁です。 考えられるすべての桁の再配置をスキャンするソリューションが可能です。`9! = 362880`、大きいですが、それでも管理可能です。 すべてのコードに対して個別に数字の任意の割り当てを試みるソリューションは、すべてのコードが同じ順列を共有するという事実を無視するため、爆発する可能性があります。 

主なエッジケースは、コードを固定長の数字列ではなく通常の整数として扱うことから生じます。 先頭のゼロはコードの一部であり、他の位置に移動できます。 例えば：```
Input
2 2
12
32
```最良の順列では、数字が元の順序に保たれます。 数字は次のようになります`12`そして`32`、したがって、答えは次のとおりです`20`。 コードを整数として保存する不用意な実装では、他の場合に先行ゼロに関する情報が失われる可能性があります。 

もう 1 つのエッジ ケースは、すべてのコードが等しい場合です。```
Input
3 3
111
111
111
```すべての順列は同じ値を生成するため、正しい出力は次のようになります。`0`。 厳密に小さい値が見つかった場合にのみ答えを更新する実装では、最初の順列を正しく処理しないと、誤って無限の初期値が保持される可能性があります。 

最後のケースは、最良の置換によって最上位にゼロが配置される場合です。```
Input
2 3
100
200
```最後の桁を前に移動する順列は次のようになります。`001`そして`002`、したがって、違いは次のようになります`1`。 順列を適用する前に先頭のゼロを削除するコードでは、この答えを見つけることはできません。 

## アプローチ

 直接的なアプローチは、可能な限りの置換を試みることです。`k`桁の位置。 順列ごとに、すべてのコードを変換し、変換された最小の数値と最大の変換された数値を追跡し、それらの差で答えを更新します。 すべての法的再調整は明示的にチェックされるため、これは正しいです。 

コストがかかるのは順列の数です。 最悪の場合、`k = 9`、与える`9! = 362880`順列。 それぞれの順列について、すべてを処理する必要があります`n = 100`コードとすべて`k = 9`桁、つまり約`3.2 * 10^8`数字の操作。 Python では、これには注意深い実装が必要ですが、小さなコード セットに対する順列の影響を事前計算することで改善できます。 

重要な観察は次のとおりです`k`小さくて固定されていますが、`n`も小さいです。 置換ループ中に、変換された文字列を繰り返し再構築する必要はありません。 考えられるすべての位置の並べ替えを一度保存​​し、それを各コードに効率的に適用できます。 すべてのコードは同じ順列を使用するため、検索スペースは`k!`、コードの数に指数関数的に依存するものではありません。 

可能な桁の並べ替えの数は限られているため、総当たりが機能します。 最適化は、各再配置をコンパクトに表現し、最も内側のループ内での繰り返し作業を回避することで実現します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(k! * n * k) | お(1) | 最適化しないと遅すぎる |
 | 最適 | 効率的な実装による O(k! * n * k) | O(k! * k + n * k) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのリカバリ コードを文字列として読み取り、先頭のゼロを保持します。 位置にすばやくアクセスできるように、各文字を整数に変換します。 
2. 位置のあらゆる順列を生成する`0`を通して`k - 1`。 それぞれの順列は、タブレットが数字を並べ替える可能性のある 1 つの方法を表します。 
3. すべての順列について、すべてのコードの桁を新しい順序で読み取ることによって変換します。 現在の値に 10 を乗算し、次の桁を加算することを繰り返して、結果の数値を作成します。 
4. 変換されたコードを処理している間、変換された最小値と最大値を維持します。 それらの違いは、この順列のパスワード候補です。 
5. すべての順列の中で見つかった最小の差を保持し、それを出力します。 

なぜ効果があるのか:

 数字の位置の考えられる一般的な再配置はすべて、生成された順列の中で 1 回だけ表示されます。 固定順列の場合、アルゴリズムはその再配置によって生成される正確な最大値と最小値を計算し、その場合に正しいパスワード候補を評価します。 最適な順列は生成された順列の 1 つである必要があるため、すべての候補の最小の差を取ることで必要な答えが得られます。 

## Python ソリューション```python
import sys
from itertools import permutations

input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    nums = [list(map(int, input().strip())) for _ in range(n)]

    perms = list(permutations(range(k)))

    answer = 10 ** k

    for p in perms:
        mn = 10 ** k
        mx = -1

        for num in nums:
            value = 0
            for idx in p:
                value = value * 10 + num[idx]

            if value < mn:
                mn = value
            if value > mx:
                mx = value

        diff = mx - mn
        if diff < answer:
            answer = diff

    print(answer)

if __name__ == "__main__":
    solve()
```置換中に先頭のゼロが表示されたままでなければならないため、入力は整数ではなく数字のリストとして保存されます。 たとえば、コードは`001`整数とは異なります`1`3 つの位置は後で再配置できるためです。 

順列リストは、検索が開始される前に 1 回生成されます。 各順列には、再配置後に表示される順序で元の数字の位置が含まれます。 

内側のループは、算術演算を使用して変換された数値を直接構築します。 これにより、一時的な文字列を繰り返し作成することが回避され、数値の作成時に先頭の 0 は単に何も寄与しないため、先頭の 0 も自然に処理されます。 

最小値と最大値は順列ごとにリセットされます。 これを忘れると、さまざまな再配置の値が比較され、無効な結果が生成されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(k! * n * k) | すべての数字の並べ替えがテストされ、すべてのテストですべてのコードとその数字が検査されます。 |
 | スペース | O(k! * k + n * k) | 保存された入力の順列と数字表現がメモリ使用量の大半を占めます。 |

 と`k <= 9`、順列の数は最大で`362880`。 入力サイズは十分に小さいため、可能なすべての再配置をチェックすると制限内に収まります。 

## テストケース```python
import sys
import io
from itertools import permutations

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    
    def solve():
        input = sys.stdin.readline
        n, k = map(int, input().split())
        nums = [list(map(int, input().strip())) for _ in range(n)]

        ans = 10 ** k
        for p in permutations(range(k)):
            mn = 10 ** k
            mx = -1
            for num in nums:
                value = 0
                for i in p:
                    value = value * 10 + num[i]
                mn = min(mn, value)
                mx = max(mx, value)
            ans = min(ans, mx - mn)

        return str(ans)

    return solve()

assert run("""2 2
12
32
""") == "2", "sample 1"

assert run("""4 4
1842
0141
5581
1581
""") == "1017", "sample 2"

assert run("""3 3
111
111
111
""") == "0", "all equal values"

assert run("""2 3
100
200
""") == "1", "leading zero permutation"

assert run("""2 1
0
9
""") == "9", "single digit boundary"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`111,111,111`|`0`| 同一のコードを正しく処理します。 
|`100,200`と`k=3`|`1`| 先行ゼロを作成する順列をチェックします。 
| 1桁のコード`0,9`|`9`| Checks the smallest possible digit length |
 | サンプルケース | サンプル出力 | Confirms the general algorithm |

 ## 特殊なケース

 値が等しい場合、アルゴリズムはすべての順列をテストしますが、変換されたすべての値は同一のままです。 のために：```
3 3
111
111
111
```すべての順列により、次の 3 つのコピーが生成されます。`111`したがって、最小値と最大値は両方とも`111`そして答えは次のようになります`0`。 

先行ゼロの場合:```
2 3
100
200
```順列`(2, 0, 1)`コードをに変更します`001`そして`002`。 アルゴリズムはこれらを整数として構築します`1`そして`2`、そのため、違いが正しく検出されます`1`。 数値が作成される前に順列が適用されるため、ゼロの位置は失われません。 

1 桁の場合:```
2 1
0
9
```可能な順列は 1 つだけです。 変換された値は次のとおりです。`0`そして`9`、したがって、アルゴリズムは戻ります`9`。 これは、順序の選択肢がない場合でも、順列生成が機能することを確認します。
