 ## 解決策
 ## 問題の理解

 この問題は島間の航海をモデル化しています。 各島には 2D 平面上の位置と多数の物資があります。 開始島は最初の島であり、目的地は最後の島です。 キアナのボートの初期移動能力は、開始島ですでに使用されている物資と同じです。 別の島に到着するたびに、その島の物資を集めて、1 回の旅行で移動できる最大距離を増やします。 

課題は、最終的に目的地に到達できる一連の島が存在するかどうかを判断することです。 移動は、島間にすでに描かれている経路に限定されません。 キアナが現在いる島からのユークリッド距離がボートの現在の能力以内であればいつでも、島を訪れることができます。 

島の数は 1000 未満です。考えられる島の順序の数は膨大になる可能性があるため、これではすべての可能なルートを探索することは直ちに不可能になります。 1000 の 2 乗は 100 万回の演算にすぎず、1 秒の制限としては小さいため、2 次解は許容されます。 

主なエッジ ケースは、問題を通常のグラフ検索と同様に扱うことで得られます。 グラフ自体はそれまでに収集した物資の量に依存するため、最初に一度エッジを構築すると、誤った結果が得られる可能性があります。 例えば：```
3
0 0 5
4 0 10
10 0 0
```正しい出力は次のとおりです。```
YES
```距離が 4 であるため、最初の島は 2 番目の島に到達できます。さらに 10 個の物資を集めると、容量は 15 になり、目的地に到達できます。 初期容量のみを考慮する不注意な実装は、ルートを誤って拒否する可能性があります。 

もう 1 つのエッジ ケースは、供給がゼロの島が依然として必要なチェーンです。```
3
0 0 3
3 0 0
6 0 0
```正しい出力は次のとおりです。```
YES
```最初のジャンプは正確に可能であり、2 番目のジャンプも同じ容量で可能です。 範囲を拡大する島のみを考慮する実装では、有効なパスが失われる可能性があります。 

3 番目のよくある間違いは、開始島の物資を無視したり、物資を 2 回追加したりすることです。```
2
0 0 5
5 0 0
```正しい出力は次のとおりです。```
YES
```目的地はちょうど最初の限界にあります。 開始供給はすでにアクティブになっているため、一度カウントする必要があります。 

## アプローチ

 直接的な強引なアプローチでは、開始島からのあらゆる可能なルートが試行されます。 現在のすべての島について、すべての未使用の島を試し、距離が到達可能になるたびに再帰的に続行します。 これは、考えられるすべての訪問順序を検査するため正しいですが、ルートの数は階乗的に増加します。 1,000 近くの島があるため、考えられるすべての経路のほんの一部を考慮することさえ不可能です。 

この問題を考察するためのより有効な方法は、すでに収集されている島の正確な順序を気にしないことです。 いかなる時点においても、将来の移動に影響を与える唯一の情報は、現在到達可能な島のセットと、そこから収集された物資の総量だけです。 物資は決して撤去されないため、新しく到達した島は将来の移動を容易にするだけです。 

これにより、貪欲な拡張プロセスが実現されます。 最初に訪れた島から始めて、現在到達可能なすべての島を繰り返し収集します。 島を収集するたびに容量が増加し、より多くの到達可能な島が表示される可能性があります。 目的地が回収されるか、新しい島に到達できない場合、プロセスは終了します。 

最初に特別な島を選択する必要がない理由は、現在到達可能な島であればどの島に行っても問題ないからです。 それは供給を追加するだけであり、将来起こり得る一連の動きを減らすことはありません。 到達可能な島を遅らせても、同じ島は同じかそれ以上の容量で後で利用可能になるため、メリットはありません。 

この実装では、未訪問の島から訪問済みの島までの最小距離が維持されます。 その最小距離が現在の容量を超えない場合はいつでも、アイランドを追加できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 最悪の場合は O(N!) | O(N) 再帰スタック | 遅すぎる |
 | 最適 | O(N²) | O(N²) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのアイランドを読み取り、アイランドの各ペア間の二乗距離を事前計算します。 距離を二乗すると、ボートの容量と比較する際の浮動小数点エラーが回避されます。 
2. 開始島を訪問済みとしてマークし、現在の供給能力を設定します。 始動用品はすでにボートに取り付けられています。 
3. 未訪問の島をすべて繰り返しスキャンします。 距離が現在のキャパシティ内にある訪問済みの島が存在する場合、その島を訪問済みとしてマークし、その物資をキャパシティに追加します。 
4. 新しい島が追加できなくなるか、目的地が訪問できなくなるまで拡張を続けます。 
5. 出力`YES`目的地に到達した場合、それ以外の場合は出力`NO`。 

この貪欲な拡張が有効である理由は、訪問する島々が現在の収集物資量で到達できる最大のセットを形成するためです。 ある時点で島に到達できる場合、それを早めに収集しても利用可能な容量が増えるだけです。 アルゴリズムは改善の可能性を決してスキップしないため、アルゴリズムが停止すると、未訪問の島はすべて本当に到達できなくなります。 

なぜ効果があるのか:

 すでに訪問済みとしてマークされている島を正確に使用して、訪問済みのすべての島に到達できるという不変条件を維持します。 このアルゴリズムは、島へのボート旅行が可能であることを確認した後にのみ島を追加するため、不変条件は true のままです。 島が追加されると、その物資によって容量が増加します。つまり、以前に可能であったすべての移動が引き続き可能になることを意味します。 目的地が追加されない場合、最終スキャンにより、現在到達可能な領域から未訪問の島に到達できないことが証明され、継続は存在しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n_line = input().strip()
    if not n_line:
        return
    n = int(n_line)

    islands = []
    for _ in range(n):
        x, y, s = map(int, input().split())
        islands.append((x, y, s))

    dist = [[0] * n for _ in range(n)]
    for i in range(n):
        xi, yi, _ = islands[i]
        for j in range(i + 1, n):
            xj, yj, _ = islands[j]
            d = (xi - xj) ** 2 + (yi - yj) ** 2
            dist[i][j] = d
            dist[j][i] = d

    visited = [False] * n
    visited[0] = True
    capacity = islands[0][2]
    remaining = n - 1

    while remaining:
        changed = False
        for i in range(1, n):
            if visited[i]:
                continue
            reachable = False
            for j in range(n):
                if visited[j] and dist[i][j] <= capacity * capacity:
                    reachable = True
                    break
            if reachable:
                visited[i] = True
                capacity += islands[i][2]
                remaining -= 1
                changed = True

        if visited[n - 1]:
            print("YES")
            return
        if not changed:
            break

    print("YES" if visited[n - 1] else "NO")

if __name__ == "__main__":
    solve()
```最初の部分では二乗距離を計算します。 2 乗値を使用すると、平方根を繰り返し呼び出すことがなくなり、距離が正確に境界上にある場合の精度の問題が回避されます。 

訪問した配列は、物資がすでに収集されている島を表します。 容量変数は、ボートが 1 回の連続旅行で現在移動できる合計マイル数です。 

メインループは貪欲な拡張を実行します。 各パスは、現在訪れている地域から到達できる島を見つけようとします。 島が追加されると、その供給は同じパスまたは将来のパスの後のチェックに直ちに影響します。 

比較には、`dist[i][j] <= capacity * capacity`なぜなら`dist`二乗距離を保存します。 ボートの限界ギリギリで島に到達することが許可されているため、等しいケースが含まれています。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N²) | 各拡張では島のペアがチェックされ、追加が成功したのは最大でも N 個です。 |
 | スペース | O(N²) | 距離行列には、島のすべてのペアが格納されます。 |

 島の数が 1,000 未満の場合、距離行列には約 100 万のエントリが含まれており、メモリに無理なく収まります。 二次走査も、指定された制限に対して十分小さいです。

 ## 特殊なケース

 ゼロサプライチェーンの場合:```
3
0 0 3
3 0 0
6 0 0
```アルゴリズムは容量 3 から始まります。アイランド 1 は、その二乗距離が 9 (容量の二乗に等しい) であるため追加されます。 容量は 3 のままですが、島 1 は新しい位置になり、そこから島 2 も距離 3 にあります。目的地に到着しました。 

新しい物資が遠くの島のロックを解除する場合:```

4 0 10
15 0 0
```最初の島は 2 番目の島に到達できます。 物資を10個集めると容量が15個になり、目的地に到達できるようになります。 新しく訪問した島はその後の到達可能性チェックにすぐに含まれるため、アルゴリズムはこれを検出します。 

境界を正確に移動するには:```
2
0 0 5
5 0 0
```距離の 2 乗は 25、容量の 2 乗も 25 です。比較には以下を使用します。`<=`したがって、島は到達可能であると正しくみなされます。 厳密に比較すると、間違った答えが得られます。
