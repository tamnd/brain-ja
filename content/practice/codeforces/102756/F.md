 ## 解決策
 ## 問題の理解

 迷路はちょうど 3 列の通路で、`n`列。 各文字は 1 つのタイルを表します。 あ`0`タイルはアリスが立つことができる場所ですが、`1`タイルがブロックされています。 アリスは、最初の列の開いているタイルから開始し、上下左右のみを移動して最後の列の開いているタイルに到達したいと考えています。 タスクは、そのようなパスが存在するかどうかを判断することです。 

入力サイズが主な手がかりとなります。 届く幅は`10^4`, ただし、高さは 3 行のみに固定されています。 到達可能なすべてのタイルを探索する一般的なグリッド アルゴリズムですでに十分です。`3 * n`ポジション。 パスの数は列の数とともに指数関数的に増加するため、可能なパスを列挙しようとするアプローチは不可能です。 

高さが低いのは隠れた構造です。 不用意な解決策はこれを通常の大きなグリッドとして扱い、不必要な複雑さを追加する可能性がありますが、迷路には 3 つの層しかありません。 もう 1 つのよくある間違いは、すべての列に開いているタイルがあるかどうかだけを確認することです。 行間のギャップによりパスが切断される可能性があるため、これでは十分ではありません。 

例えば：```
2
00
10
00
```答えは次のとおりです。```
Solvable!
```パスは左上から開始し、右に移動し、下に移動して、最後の列に到達することができます。 ここでは列ごとのチェックが機能しますが、接続性は証明されません。 

別のケースは次のとおりです。```
2
01
10
10
```答えは次のとおりです。```
Unsolvable!
```最後の列には開いたタイルが含まれ、最初の列には開いたタイルが含まれますが、それらはブロックされたセルによって区切られています。 両端のオープンセルの存在を確認するだけのソリューションでは、それが誤って受け入れられてしまいます。 

問題を推論する最も安全な方法は、開いているタイルをグラフの頂点として表示することです。 グラフには`3n`頂点の場合、到達可能なコンポーネントの検索は簡単に十分に高速です。 

## アプローチ

 直接的なアプローチは、最初の列のすべての開始タイルからグラフの走査を実行することです。 各開いたタイルはノードであり、エッジは隣接する開いたタイルを接続します。 幅優先検索または深さ優先検索は、到達可能なすべてのタイルを訪問し、最後の列に到達できるかどうかを示します。 これは正しいです。グラフ トラバーサルでは、開始ノードを含む接続コンポーネントが正確に探索されるからです。 

ただし、考えられるすべての最初の列のタイルから個別の走査を開始すると、作業が繰り返されます。 最悪の場合、開始位置が 3 つあるため、繰り返しは実際には有害ではありませんが、不必要です。 さらに重要なことは、すべての有効な開始が同じグラフを介して接続されていることを認識すると、問題がより明確になります。 すべての最初の列の開いているタイルを 1 つの最初の検索に追加し、到達可能な領域全体を一度に探索できます。 

迷路の高さが固定されているという観察により、通路全体を小さなグラフとしてモデル化できます。`O(n)`ノード。 単一の BFS または DFS は各タイルを最大 1 回処理し、単純な線形ソリューションを提供します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n) | O(n) | 受け入れられましたが、不要な繰り返し検索 |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 迷路の 3 行を読み取り、その 3 行の訪問済み配列を作成します。`n`グリッド。 グリッドの寸法は固定されているため、この表現はあらゆる可能な位置を直接保存します。 
2. 最初の列の開いているすべてのタイルを BFS キューに入れ、訪問済みとしてマークします。 アリスはこれらの位置のいずれからでも開始できるため、検索はすべての位置から同時に開始する必要があります。 
3. キューからポジションを繰り返し削除し、その 4 つの隣接するポジションを検査します。 隣人が迷路内にいて、開いていて訪問されていない場合は、訪問済みとしてマークを付けてキューに追加します。 
4. 検索中に、訪問した位置が最後の列にあるかどうかを確認します。 存在する場合、迷路には最初から最後まで有効なルートがあります。 
5. 最後の列に到達せずにキューが空になった場合は、到達可能なすべての位置が探索されており、解決策は存在しません。 

これが機能する理由: BFS によって維持される不変条件は、訪問されたすべてのタイルが最初の列の有効な開始タイルから到達可能であるということです。 BFS が終了すると、開始領域に接続されているすべてのタイルが訪問されます。 最後の列に訪問済みのタイルが含まれている場合、有効なパスがあります。 そうでない場合、開始領域からのあらゆる可能な移動がすでに調査されているため、パスは存在できません。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    n = int(input())
    grid = [input().strip() for _ in range(3)]

    visited = [[False] * n for _ in range(3)]
    q = deque()

    for r in range(3):
        if grid[r][0] == '0':
            visited[r][0] = True
            q.append((r, 0))

    directions = [(1, 0), (-1, 0), (0, 1), (0, -1)]

    while q:
        r, c = q.popleft()

        if c == n - 1:
            print("Solvable!")
            return

        for dr, dc in directions:
            nr = r + dr
            nc = c + dc

            if 0 <= nr < 3 and 0 <= nc < n:
                if not visited[nr][nc] and grid[nr][nc] == '0':
                    visited[nr][nc] = True
                    q.append((nr, nc))

    print("Unsolvable!")

if __name__ == "__main__":
    solve()
```このコードは、任意の 1 つの開始を選択するのではなく、考えられるすべてのエントリ タイルから BFS を開始します。 アリスは最初の列のどこからでも始められるため、これは問題の定義と一致します。 

境界チェックにより、外部の行へのアクセスが防止されます。`0`に`2`または外側の列`0`に`n - 1`。 訪問したセルをキューに追加する前にマークすると、キュー エントリの重複が防止され、各タイルが 1 回処理されることが保証されます。 

コラム到達時の早期復帰`n - 1`最後の列のタイルに到達するだけで迷路を解くことができるため、安全です。 成功がすでに証明された後で探索を続ける必要はありません。

 ## 特殊なケース

 最初の重要なエッジケースは、複数の開始位置が存在する場合です。 で：```
2
00
00
00
```BFS は、最初の列の 3 つのセルすべてから始まります。 このアルゴリズムは、アリスが特定の行から開始することを想定していないため、考えられるあらゆる入り口が処理されます。 

2 番目のケースは、最後の列に開いたセルがあるが、それらに到達できない場合です。```
2
01
10
10
```検索は次から始まります`(0,0)`。 隣接するキューはグリッドの外側にあるか、ブロックされているため、キューは空になります。 最終列セルが訪問されなかったため、アルゴリズムは次のように出力します。`Unsolvable!`。 

3 番目のケースは長くて狭い迷路です。```
10000
00000000000000000000...000
11111111111111111111...111
00000000000000000000...000
```と`10000`列。 BFS は引き続き、到達可能な各タイルを 1 回ずつ訪問します。 再帰の深さや可能なパスの数に依存しないため、最大幅を安全に処理します。
