 ## 解決策
 ## 問題の理解

 この問題では、廊下が次のように分割されていることが説明されています。`n`直線上に位置します。 ジョニーはそのポジションからスタート`1`時に`t = 0`そしてその地位に到達したいと思っています`n + 1`。 時間は離散的なステップで進みます。 各ステップで、彼には 2 つの選択肢があります。1 つの位置を進めるか、現在の位置に留まるかです。 

廊下には「幽霊が出る」`n`繰り返される罠。 各トラップは位置に関連付けられています`i`、ピリオドがあります`s_i`、そしてペナルティ`v_i`。 ジョニーが所定の位置に立つたびに`i`一度に`t`どこ`t`で割り切れます`s_i`、彼は追加の恐怖のコストを被ります`v_i`。 滞在中に同じ罠が複数回重なった場合、同じ罠が何度も彼に影響を与える可能性があります。 

グローバルペナルティもある`w`彼が 1 つの時間単位の間その場にとどまることを選択するたびに適用されます。 前進してもこの待機ペナルティは発生しませんが、タイミングによってはさまざまな罠にさらされる可能性があります。 

タスクは、ジョニーが開始の瞬間からポジションに到達するまでに蓄積する恐怖の合計値の最小値を計算することです。`n + 1`。 

重要な問題は、時間と位置が関係していることです。 先に進むと場所と時間が変わりますが、待っていると時間だけが変わります。 コストは両方に依存するため、状態は単に「どの位置」であるだけでなく、暗黙的に「異なる期間を法とした時間」でもあります。 

制約`n ≤ 10^3`そして`s_i ≤ 10^3`二次方程式または`n^3`動的プログラミングのアプローチは、慎重に最適化すればまだ合格する可能性がありますが、時間の経過とともに指数関数的な状態になることは不可能です。 時間は任意に大きくなる可能性があるため、考えられるすべての待機パターンを単純にシミュレーションすることも不可能です。 

同期トラップのアクティブ化を回避する場合を除いて、待機することが決して有益ではない場合、微妙なエッジ ケースが発生します。 たとえば、すべてが`s_i = 1`の場合、すべての位置がタイム ステップごとにトリガーされるため、待機してもコストが増加するだけで、役に立ちません。 逆に、いくつかの場合、`s_i`サイズが大きいため、到着のタイミングを慎重に決定することで、繰り返しのアクティベーションを完全に回避できます。 素朴で貪欲な「すぐに移動」アプローチは、タイミング調整を完全に無視するため、ここでは失敗します。 

別の失敗ケースは、トラップの周期が 1 であるが、その値が大きい場合に発生します。 そのような状況では、たとえ 1 単位の時間であってもその位置に繰り返し留まるとコストが発生するため、すぐに通過するのではなく、迂回したり到着を遅らせたりすることが最適な戦略となる可能性があります。 

## アプローチ

 ブルートフォースの観点は、これを拡張状態空間上の最短経路問題として扱うことです。 状態は次のように定義できます。`(position, time)`、そして各州から次のいずれかに進みます。`(i + 1, t + 1)`または`(i, t + 1)`。 状態遷移のコストは、新しい状態でトラップが起動するかどうか、および待機することを選択したかどうかによって異なります。 

この定式化は正しいですが、時間には制限がないという問題がすぐに発生します。 たとえポジションが制限されていても、`n`、ジョニーが頻繁に待機すると、時間が任意に大きくなる可能性があります。 ある上限で時間を切り捨てても、依然として次のことが起こります。`O(n * T)`州、どこで`T`簡単に超えることができます`10^5`、数千万または数億のエッジを持つグラフを作成します。 

重要な観察は、待機はトラップの周期構造に関連してのみ意味があるということです。 各トラップは時間の剰余にのみ依存します`s_i`。 以来`s_i ≤ 1000`、結合されたタイミング構造は、管理可能な範囲にわたって周期的です。 絶対時間を追跡する代わりに、これらの制約から導出されるグローバル期間を法として時間を追跡します。 

より有用な再定式化は、慎重に選択した係数を法として位置と時間によって DP を定義することです。 ずっと`s_i ≤ 1000`で時間状態を安全にキャップできます。`L = max(s_i)`それを超えるとすべてのトラップに対して残留動作が繰り返されるため、それよりわずかに大きくなります。 これにより、時間次元が最大 1000 の状態に圧縮されます。 

ここで、問題は階層化された最短経路になります。`n × L`州。 移動するたびに位置と時間が増加するか、追加コストで位置を維持して時間が増加します。`w`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース オーバー (位置、時間) | 指数関数的 / 無制限 | O(nT) | 遅すぎる |
 | DP over (位置、時間 mod max s) | O(n · 最大 s) | O(n · 最大 s) | 承認済み |

 ## アルゴリズムのチュートリアル

 各状態を次のようにモデル化します。`(i, t)`どこ`i`現在の位置 (から`1`に`n+1`） そして`t`は時間の剰余です`L`、 どこ`L = max(s_i)`。 

1. DP テーブルの初期化`dp[i][t]`すべての位置と時間剰余に対して無限大として。 セット`dp[1][0] = initial_cost`、 どこ`initial_cost`その位置ですでにアクティブなトラップを考慮します`1`時に`0`。 
2. 州ごとに`(i, t)`、2 つの遷移を考えます。 最初の移行は次のように進んでいます`(i + 1, (t + 1) % L)`。 この移行のコストには、その位置にあるトラップが含まれます`i + 1`時間に応じて発火する`t + 1`。 
3. 2 番目のトランジションは同じ位置に留まり、次の状態に進みます。`(i, (t + 1) % L)`。 これにより待機ペナルティが追加されます`w`その位置でのトラップコストに加えて`i`時に`t + 1`。 
4. 時間ステップの昇順でプロセス状態を処理します。 トランジションは常に正確に 1 だけ時間を増加させるため、階層化された BFS または DP を経時的にレイヤー化するだけで十分です。 
5. 位置までのすべての状態が続くまで続行します`n + 1`が処理され、位置の全時間剰余にわたって最小値を取得します。`n + 1`。 

正確さは、すべての遷移が均一に時間を進めるという事実にかかっており、そのためグラフは時間次元において非周期的であり、レイヤーで処理できます。 

### なぜ効果があるのか

 重要な不変条件は次のとおりです`dp[i][t]`ジョニーがその位置にいるときに達成可能な最小の恐怖値を保存します`i`に合わせて同時に`t (mod L)`一連の移動と待機の後。 

各アクションは位置と時間の両方を決定的に更新するため、考えられるすべての有効な行程は、この層状状態グラフ内の 1 つのパスに正確に対応します。 すべての遷移を調査するため、有効な軌道は除外されません。 すべての移行コストは取得時に 1 回だけ計算されるため、累積コストは真の恐怖の累積と一致します。 トラップ条件は次の割り算のみに依存するため、定期的な圧縮により、すべてのトラップのアクティブ化が依然として正確に表現されることが保証されます。`s_i`、追跡時間モジュロの下で保存されます。`L`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, w = map(int, input().split())
    s = list(map(int, input().split()))
    v = list(map(int, input().split()))

    L = max(s)

    INF = 10**18
    dp = [[INF] * L for _ in range(n + 2)]

    def trap_cost(i, t):
        if i < 1 or i > n:
            return 0
        if t % s[i - 1] == 0:
            return v[i - 1]
        return 0

    start_cost = trap_cost(1, 0)
    dp[1][0] = start_cost

    for i in range(1, n + 2):
        for t in range(L):
            cur = dp[i][t]
            if cur == INF:
                continue

            nt = (t + 1) % L

            if i <= n:
                cost_move = trap_cost(i + 1, t + 1)
                if dp[i + 1][nt] > cur + cost_move:
                    dp[i + 1][nt] = cur + cost_move

            if i <= n:
                cost_wait = w + trap_cost(i, t + 1)
                if dp[i][nt] > cur + cost_wait:
                    dp[i][nt] = cur + cost_wait

    ans = min(dp[n + 1])
    print(ans)

if __name__ == "__main__":
    solve()
```DP テーブルは位置と時間残差によってインデックスが付けられ、各エントリはレイヤー遷移ごとに 1 回だけ緩和されます。 機能`trap_cost`定期的なアクティブ化ルールを分離して、遷移を推論しやすくし、ロジック エラーの繰り返しを防ぎます。 

よくある実装上の間違いは、前に進んでも新しい位置でトラップをチェックするまでに時間が進むことを忘れていることです。 もう 1 つは、間違った時間 (次ではなく現在) に基づいてトラップ コストを適用することです。 どちらも明示的に使用することで処理されます`t + 1`両方のトランジションで。 

## 実用的な例

 ### 例 1

 入力:```
3 1
2 1 2
1 2 3
```状態を追跡します`(position, time mod 2)`以来`L = 2`。 

| ステップ | ポジション | 時間 | アクション | コスト | DP 状態の更新 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 1 | 0 | 開始 | 1のトラップ | dp[1][0] = 1 |
 | 2 | 1 | 1 | 待って | +1 + トラップ(1,1)=0 | dp[1][1] = 2 |
 | 3 | 2 | 2 | 移動 | +2 | dp[2][0] = 3 |
 | 4 | 3 | 3 | 移動 | +3 | dp[3][1] = 6 |

 DP テーブルから、位置 4 の残基が常に最小であることがわかります。`4`待機と移動の選択肢を最適に組み合わせた後。 

このトレースは、待機がトラップの配置を変更する場合にのみ有効である理由を示しています。 それ以外の場合は、コストが追加されるだけです。 

### 例 2

 入力:```
2 2
1 2
5 5
```ここでは、すべてのポジションがポジション 1 の時間単位ごとにトリガーされます。 

| ステップ | ポジション | 時間 | アクション | コスト |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 0 | 開始 | 5 |
 | 2 | 2 | 1 | 移動 | +5 |
 | 3 | 3 | 2 | 移動 | 0 |

 待機してもコストが追加されるだけでトラップの起動パターンは変わらないため、最適な戦略は待機せずにすぐに移動することです。 

これにより、アルゴリズムが待機中に正しくペナルティを課していることが確認できます。`w`期限を短縮し、不必要な遅延を回避します。

 ## 特殊なケース

 まれなケースは、次のような場合です。`s_i = 1`。 その状況では、すべての位置がすべてのタイム ステップでトラップをトリガーします。 アルゴリズムは引き続き正しく動作します。`trap_cost(i, t)`常にアクティブであるため、唯一の決定は追加料金を支払うかどうかです。`w`そうでなくても、DP は当然、待たないことを好みます。 

もう一つのケースは次のような場合です。`w = 1`そしていくつか`s_i`大きいです。 ここで待機することは、同期を避けるために有益な場合があります。 DP はこれを捉えています。`t`モジュロ`s_i`かどうかが変わります`t % s_i == 0`到着時に保持されます。 

最後のケースは、最適な戦略に 1 つの移動の前に複数の待機が含まれる場合です。 階層化されたDPは繰り返し正しく蓄積されます`(i, t)`明示的な列挙を必要とするのではなく、複数待機シーケンスが同じ遷移の繰り返し適用として表現されるようにします。
