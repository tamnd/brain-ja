 ## 解決策
 ## 問題の理解

 この問題では、以下からのみ作られた 2 つの文字列が得られます。`L`そして`R`。 最初の文字列は、ドラムヒットの実際のシーケンスを記述します。 各ヒットにより、録音されたサウンド内に 1 つの可視文字または 2 つの同一の可視文字が作成されます。 2 番目の文字列は、私たちが聞く録音です。 最初の文字列のすべてのヒットを同じ文字の 1 つまたは 2 つのコピーに拡張して 2 番目の文字列を形成できるかどうかを決定する必要があります。 

たとえば、ヒットシーケンス`LR`なることができる`LR`、`LLR`、`LRR`、 または`LLRR`。 元の各キャラクターの拡張は独立しているため、唯一許可される変更は、すべてのキャラクターを 1 回複製できることです。 

この制約により、考えられるすべての拡張を直接シミュレーションすることが不可能になります。 文字列に長さがある場合`n`、各キャラクターには 2 つの選択肢があるため、可能なすべての録音を試すには、次の点まで確認する必要があります。`2^n`可能性。 たとえ数十文字の場合でも、これは不可能になります。 意図したソリューションでは、各文字を一定の回数処理して、`O(n)`アルゴリズム。 

難しい部分は、大きな文字列ではなく、同じ文字のグループ間の境界です。 よくある間違いは、2 つの文字列が同じ圧縮形式であるかどうかだけを確認することです。 グループの長さが重要であるため、圧縮だけでは十分ではありません。 

例えば：```
Input:
p = "L"
s = "LLL"
```正しい出力は次のとおりです。```
NO
```不用意に解決すると、両方の文字列が次のものだけで構成されていることがわかるかもしれません。`L`そしてそれらを受け入れてください。 ただし、1 つのオリジナル ヒットから最大 2 つのヒットが生成されることもあります。`L`文字なので3文字は無理です。 

もう 1 つのエッジ ケースは、グループの順序が変更される場合です。```
Input:
p = "LR"
s = "LLL"
```正しい出力は次のとおりです。```
NO
```2 番目の文字列には、次のグループが 1 つだけ含まれます。`L`、元のシーケンスには 2 つの異なるヒットがあります。 行方不明者`R`を展開して作成することはできません`L`。 

最後の境界ケースは、記録された文字列が短い場合です。```
Input:
p = "LL"
s = "L"
```正しい出力は次のとおりです。```
NO
```各元のキャラクターは少なくとも 1 つのキャラクターに貢献する必要があるため、2 つのヒットが 1 つの記録されたキャラクターに消えることはできません。 

## アプローチ

 ブルートフォースアプローチでは、最初の文字列を展開するためにあらゆる方法が試行されます。 キャラクターごとに、1 つのキャラクターのままにするか 2 つのコピーになるかを選択し、生成された結果を記録と比較します。 これは、ヒットのあらゆる考えられる解釈を検査するため、正しいです。 問題は、次の長さの文字列です。`n`もっている`2^n`拡張の可能性があり、すぐに大きくなりすぎます。 

有益な観察は、元の文字列内のすべての文字が、記録内の同じ文字の連続したブロックに対応しているということです。 アン`L`作成することしかできません`L`文字があり、そのうち 1 つまたは 2 つの文字を作成する必要があります。 同じことが当てはまります`R`。 

これは、展開される可能性のある文字列を構築する必要がないことを意味します。 必要なのは、両方の文字列を調べて、一致するグループを比較することだけです。 元の文字列に次のグループがある場合、`k`同一の文字の場合、記録される文字列には、次の長さの同じ文字のグループが含まれている必要があります。`k`そして`2k`。 この問題では、元の文字列のすべての文字が個別にヒットするため、元の各グループの長さが直接カウントされます。 これにより、問題はランレングスの比較に限定されます。 

すべての有効な展開がヒットのルールに従っているため、ブルート フォースは機能しますが、ローカルでチェックできる選択肢を探索するため失敗します。 すべてのヒットはその連続ブロックにのみ影響するという観察により、指数関数的な探索を線形スキャンに置き換えることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 元の文字列と記録された文字列の先頭に 2 つのポインタを設定します。 ポインタは、次の未処理のヒットとサウンドを表します。 
2. 元の文字列内の現在の文字について、等しい文字が連続して何個あるかを数えます。 記録された文字列内の対応するグループに対して同じことを行います。 ヒットは次から変更できないため、グループは同じ文字で始まる必要があります。`L`に`R`またはその逆。 
3. 2 つのグループの長さの関係を確認します。 すべてのヒットで 1 つのサウンドが作成されるため、記録されるグループの長さは少なくとも元のグループの長さである必要があります。また、すべてのヒットで最大 2 つのサウンドが作成されるため、元のグループの長さの 2 倍以下である必要があります。 
4. 両方のポインタを次のグループに移動し、文字列の 1 つがなくなるまで繰り返します。 
5. スキャンが終了したら、両方の文字列が完全に消費された場合にのみ受け入れます。 文字が残っている場合は、1 つの文字列に一致しないヒットまたはサウンドが含まれていることを意味します。 

なぜ効果があるのか:

 元の文字列内の等しい文字の最大ブロックはすべて、同じドラムでの連続したヒットのシーケンスを表します。 これらのヒットは記録内の他の文字と混合できないため、記録された文字列内の 1 つのブロックに正確に対応する必要があります。 各ヒットは 1 文字または 2 文字のいずれかに寄与するため、考えられる唯一の違いはそのブロックの長さです。 アルゴリズムはブロックごとにこの条件を正確にチェックするため、有効な録音を正確に受け入れます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        p = input().strip()
        s = input().strip()

        i = 0
        j = 0
        ok = True

        while i < len(p) and j < len(s):
            if p[i] != s[j]:
                ok = False
                break

            pi = i
            while i < len(p) and p[i] == p[pi]:
                i += 1

            sj = j
            while j < len(s) and s[j] == s[sj]:
                j += 1

            p_len = i - pi
            s_len = j - sj

            if s_len < p_len or s_len > 2 * p_len:
                ok = False
                break

        if i != len(p) or j != len(s):
            ok = False

        ans.append("YES" if ok else "NO")

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```メインループは、文字列ごとに 1 つずつ、合計 2 つのインデックスを保持します。 決して後戻りすることはないため、全体の作業は直線的になります。 

内側のループは現在のブロックの終わりを見つけます。 彼らが終わった後、`p_len`はこのブロックを生成するヒット数であり、`s_len`録音内のサウンドの数です。 有効な範囲は次のとおりです。`p_len`に`2 * p_len`。 

最終的な比較は、`i`そして`j`1 つの文字列が終了するとメイン ループが停止する可能性があるため、これが必要になります。 このチェックを行わないと、実装は余分な文字を無視してプレフィックス一致を誤って受け入れる可能性があります。 

アルゴリズムは長さとインデックスのみを保存するため、Python の整数はここでは問題になりません。 最大値は入力サイズによって制限されます。

        j = 0
