 ## 解決策
 ## 問題の理解

 長さの順列が与えられています$n$、1 から 1 までのすべての数字を意味します。$n$は 1 回だけ表示されますが、位置の行に沿って任意の順序で配置されます。$1 \dots n$。 値$a_i$どのラベルがその位置にあるかを示します$i$、そしてこれは順列であるため、各ラベルは正確に 1 つの位置に対応します。 

ここで、ラベルを昇順にアクセスする必要があると想像してください。最初に値 1 が配置される位置、次に値 2 が配置される位置、というように値が表示されるまで続きます。$n$。 移動コストは、連続して訪問した位置間の絶対差の合計です。 値の位置の場合$x$は$p_x$の場合、コストは次の合計になります。$|p_{x+1} - p_x|$。 

2 つのラベルの訪問順序を入れ替える操作は、最大 1 つまで実行できます。 同様に、2 つの値を選択します$x$そして$y$、そしてその順序で$1,2,\dots,n$他のすべての値は自然な順序のままですが、それらの位置を交換します。 

課題は、結果として生じる出張コストを最小限に抑えることです。 

制約は次のとおりです$n \le 5000$。 ナイーブ$O(n^2)$または$O(n^3)$解決策は境界線にありますが、まだ実行可能な可能性があります。ただし、すべてのスワップ候補のフルパスを再計算するなどすると、おおよその結果が得られます。$O(n^3)$が遅すぎます。 コスト関数の構造を利用しなければなりません。 

いくつかの特殊なケースが重要です。 

順列がすでにソートされている場合、つまり$a_i = i$の場合、ポジションはすでに昇順になっており、コストは正確に$n-1$。 スワップは隣接構造を悪化させるか維持するだけなので、答えは変わらないはずです。$n-1$。 不用意な解決策では、変更されていない構造を処理しないため、スワップを試行し、誤ってコストを削減する可能性があります。 

順列を逆にすると、すべての位置が最大限に分散され、中央の 2 つの要素を交換すると、隣接するいくつかの違いが劇的に変化する可能性があります。 ブルート フォースの再計算では、ローカルな変更のみを正しく考慮する必要があります。 そうしないと、影響を受けないエッジが過剰にカウントされる可能性があります。 

微妙なケースは、5 と 6 を交換するなど、交換された要素が値の順序で隣接している場合です。コストの変化は隣接する要素の周囲で局所的ですが、2 つのエッジのみを調整する単純な再計算では、両方の要素が交換後に異なる隣接エッジに寄与しているという事実が見落とされる可能性があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。初期コストを計算し、すべての値のペアを試します。$(x,y)$、訪問順序でそれらを交換することをシミュレートし、全コストを最初から再計算し、最小値を取得します。 

ゼロから計算するにはコストがかかります$O(n)$、そして、あります$O(n^2)$スワップ、与える$O(n^3)$。 と$n = 5000$、これは次の順序です。$1.25 \times 10^{11}$限界をはるかに超えた操作。 

重要な観察は、2 つの値を交換すると、一連の位置におけるそれら 2 つの要素の位置にのみ影響するということです。$p_1, p_2, \dots, p_n$。 他のすべての隣接する差異は変更されません。 したがって、全体の合計を再計算する代わりに、交換された要素に関係するエッジの寄与のみを再計算する必要があります。 

あらゆる値に対して$x$、元の合計に含まれるエッジは 2 つだけです。$|p_x - p_{x-1}|$そして$|p_{x+1} - p_x|$。 交換後$x$そして$y$、これら 4 つのエッジはローカルで変更され、その他はすべて同一のままです。 これにより、各スワップの評価が次のように減少します。$O(1)$。 

まだあります$O(n^2)$スワップしますが、それぞれの時間は一定になり、快適にフィットします。 

さらなる改良点は、新しいシーケンスを明示的に構築する必要がないことです。 位置配列を操作し、影響を受ける差分を直接計算するだけです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (スワップごとにフル パスを再計算) |$O(n^3)$|$O(n)$| 遅すぎる |
 | ローカルの差分更新と交換する |$O(n^2)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 まず、順列を逆配列に変換します。$p$、 どこ$p[x]$値の位置です$x$。 訪問順序はインデックスではなく値に基づいているため、これは不可欠です。 

1. 配列を計算する$p$これにより、順列内の各値を即座に見つけることができます。 これにより、アレイを繰り返しスキャンすることが回避されます。 
2. 合計してベースラインコストを計算します。$|p[i] - p[i-1]|$みんなのために$i \ge 2$。 これは、交換前の元の移動距離を表します。 
3. ゼロスワップの実行が許可されているため、このベースライン値で応答を初期化します。 
4. すべての値のペアを反復処理します。$(x, y)$と$x < y$。 各ペアは訪問順序を交換することを表します。 
5. 各ペアについて、スワップによって生じるコストの変化を計算します。$x$そして$y$。 フルパスを再構築する代わりに、次のような古いコントリビューションを削除します。$x$そして$y$、位置を交換した後、新しい貢献を追加します。 

重要な点は、値シーケンスの隣接性が重要であるため、隣接するもののみであるということです。$x-1, x+1, y-1, y+1$が関与している。 位置の絶対的な違いを使用して、古いエッジを慎重に減算し、新しいエッジを追加します。 

1. 得られた最小値で答えを更新します。 

### なぜ効果があるのか

 コスト関数は、値の順序付けにおける隣接するペアの合計です。 スワップでは 2 つの値の位置が変更されるだけなので、どちらの値も含まない項は同一のままです。 合計は加算され、エッジは独立しているため、正確性とは、影響を受ける項を正確に更新することになります。 これらの隣接関係を超える隠れた依存関係は存在しないため、ローカルな寄与のみを追跡すると、合計が正確に保存されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    # p[v] = position of value v
    p = [0] * (n + 1)
    for i, v in enumerate(a):
        p[v] = i

    def cost_at(i, j):
        return abs(p[i] - p[j])

    base = 0
    for i in range(2, n + 1):
        base += abs(p[i] - p[i - 1])

    ans = base

    for x in range(1, n + 1):
        for y in range(x + 1, n + 1):
            px, py = p[x], p[y]

            # remove old contributions around x and y
            old = 0
            if x > 1:
                old += abs(p[x] - p[x - 1])
            if x < n:
                old += abs(p[x] - p[x + 1])
            if y > 1:
                old += abs(p[y] - p[y - 1])
            if y < n:
                old += abs(p[y] - p[y + 1])

            # avoid double counting if adjacent in value
            if abs(x - y) == 1:
                # one edge counted twice in above, adjust carefully
                old = 0
                for i in range(2, n + 1):
                    old += abs(p[i] - p[i - 1])

            # swap positions
            p[x], p[y] = p[y], p[x]

            new = 0
            if x > 1:
                new += abs(p[x] - p[x - 1])
            if x < n:
                new += abs(p[x] - p[x + 1])
            if y > 1:
                new += abs(p[y] - p[y - 1])
            if y < n:
                new += abs(p[y] - p[y + 1])

            if abs(x - y) == 1:
                new = 0
                for i in range(2, n + 1):
                    new += abs(p[i] - p[i - 1])

            ans = min(ans, base - old + new)

            # revert swap
            p[x], p[y] = p[y], p[x]

    print(ans)

if __name__ == "__main__":
    solve()
```この実装は、各値の位置が O(1) になるように逆位置配列を維持することに依存しています。 スワップ ループは、2 つの値の位置を一時的に交換し、隣接合計の差分を計算して、配列を復元します。 

最もデリケートな部分は、値空間での隣接性の処理です。$x$そして$y$その場合、ローカル寄与の単純な減算により共有エッジが 2 倍にカウントされるため、正確性を保つために完全な再計算フォールバックが使用されます。

 ## 特殊なケース

 重要なエッジケースは、順列がすでにソートされている場合です。 アルゴリズムはベースライン コストを次のように正確に計算します。$n-1$、すべてのスワップ評価では、影響を受ける寄与のみが再計算され、隣接構造がすでに最小限であるため、誤った改善が生じることはありません。 

スワッピングなど、値の順序で隣接する値を交換するときに、別のエッジ ケースが発生します。$x$そして$x+1$。 この場合、両方の値がコスト定義で直接隣接しているため、単純なローカル減算は二重カウントになる危険性があります。 アルゴリズムは、そのスワップの完全な再計算にフォールバックすることでこれを処理し、依存関係の重複が発生した場合でも正確さを保証します。 

最後の微妙なケースは、交換された要素が値 1 や値などの境界近くにある場合です。$n$。 このような場合、一方または両方の隣接項が存在しません。 実装では境界を明示的にチェックします$x>1, x<n$したがって、部分コストを正しく更新しながら、無効な近傍へのアクセスを回避します。
