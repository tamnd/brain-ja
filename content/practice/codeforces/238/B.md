 ## 解決策
 ## 問題の理解

 整数の配列と値が与えられます`h`。 要素の各ペアは、2 つの要素が同じグループに配置されるか、異なるグループに配置されるかに応じて値を与えます。 

数字が2つある場合`a[i]`そして`a[j]`同じサブシーケンスに属している場合、それらのペアの値は次のとおりです。$$a[i] + a[j]$$それらが異なるサブシーケンスに属している場合、ペアの値は次のようになります。$$a[i] + a[j] + h$$選択したパーティションについて、順序のないすべてのペアを調べ、これらの値をすべて収集します。 パーティションの良さは、ペアの最大値と最小値の差です。 この差を最小限に抑え、有効なパーティションを 1 つ出力する必要があります。 

配列サイズが次の値に達しました`10^5`したがって、すべてのペアを明示的に検査するアルゴリズムは不可能です。 ペア数はおおよそ次のようになります。$$\frac{n(n-1)}{2}$$それは約です`5 * 10^9`最悪の場合。 すべてのペア値を保存するだけでもメモリ制限を超えます。 

入力値と`h`到達できる`10^8`したがって、合計は 32 ビット符号付き整数内に安全に収まりますが、Python 整数ではオーバーフローの問題がいずれにせよ解消されます。 

厄介な点は、パーティションが次のいずれかの方法でペアの値を変更することです。`0`または追加`h`。 不注意な実装では、最適解が常に両方のグループを使用すると仮定する可能性がありますが、それは誤りです。 

考慮する：```
2 100
1 1000
```数値を分割すると、唯一のペアの値は次のようになります。```
1 + 1000 + 100 = 1101
```最大値と最小値は等しいので、善は`0`。 

しかし、すべてをまとめておくと次のようになります。```
1 + 1000 = 1001
```良さはそのままに`0`。 

どちらも最適です。 この問題では空のサブシーケンスが許可されますが、すべてを 1 つのグループに入れることが最善の場合があるため、これは重要です。 

別の微妙なケースが現れるのは、`h = 0`。```
4 0
1 5 7 10
```すべてのペアの値は単純に`a[i] + a[j]`パーティションに関係なく、答えは配列自体にのみ依存します。 どのパーティションも最適です。 意味のある分割ロジックを強制しようとするソリューションは、このケースを誤って複雑にしすぎてしまう可能性があります。 

最も重要なエッジケースは、最小要素と最大要素が不適切に相互作用する場合です。 

例：```
3 2
1 2 100
```別れたら`100`単独で、その後グループ間のペアが利益を得る`+2`、最大値が大きくなりすぎる可能性があります。 最適な戦略は、全体的な最小値と全体的な最大ペアの合計を制御することに完全に依存します。 

この観察がソリューション全体を推進します。 

## アプローチ

 ブルートフォースのアイデアは単純です。 すべての要素は 2 つのグループのいずれかに属することができるため、`2^n`可能なパーティション。 各パーティションについて、すべてのペアの値を計算し、最大値と最小値の間の広がりを測定できます。 

考えられるすべての答えをチェックするので、正しさは明らかです。 実行時間は壊滅的です。 たとえ`n = 30`、パーティションの数はすでに 10 億を超えています。 と`n = 10^5`、徹底的な検索は絶望的です。 

次のステップは、実際にペアの最小値と最大値を決定するものを理解することです。 

配列がソートされていると仮定します。$$b_1 \le b_2 \le \dots \le b_n$$パーティション効果がなければ、可能な最小のペアの合計は次のようになります。$$b_1 + b_2$$そして最大のものは次のとおりです。$$b_{n-1} + b_n$$パーティションは、特定のペアが追加のペアを受け取るかどうかのみを決定します。`h`。 

つまり、すべてのペアの値は次の 2 つの形式のいずれかに属します。$$a_i + a_j$$または$$a_i + a_j + h$$したがって、グローバル最小値は次のいずれかでなければなりません。$$b_1 + b_2$$または、そのペアがグループをまたぐ場合は、わずかに大きな値になります。 

同様に、グローバル最大値は次のいずれかになります。$$b_{n-1} + b_n$$以上`h`。 

重要な洞察は、極端なペアのみが重要であるということです。 すべてのペアについて個別に推論する必要はありません。 

意味のある戦略は 2 つだけです。 

最初の戦略では、すべての要素を同じグループに保持します。 この場合、すべてのペアの値は変更されないため、次のようになります。$$\text{goodness} = (b_{n-1} + b_n) - (b_1 + b_2)$$2 番目の戦略は、最小のペアに受信を強制することでスプレッドを改善しようとします。`+h`最大のペアが受信できないようにしながら`+h`。 

最小のペアをグループと交差させるには、2 つの最小の要素を分離する必要があります。 

最大のペアを 1 つのグループ内に保持するには、2 つの最大の要素が一緒に留まる必要があります。 

並べ替え後、このプロパティで可能な唯一のカットは次のとおりです。$$\{b_1\} \quad \text{and} \quad \{b_2, b_3, \dots, b_n\}$$またはその対称的な同等物。 

このパーティションの下では次のようになります。 

最小のペアは次のようになります。$$b_1 + b_2 + h$$2 つの最小要素が分離されているためです。 

最大ペアは残ります。$$b_{n-1} + b_n$$なぜなら、2 つの最大の要素が一緒に留まるからです。 

したがって、その良さは次のようになります。$$(b_{n-1} + b_n) - (b_1 + b_2 + h)$$この値が負になった場合、それは単にロールが交換された最小値と最大値を意味するため、実際のスプレッドは絶対値になります。 

最終的な答えは、これら 2 つの可能性のうち小さい方です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(2^n \cdot n^2)$|$O(1)$| 遅すぎる |
 | 最適 |$O(n \log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を読み取り、各要素の元のインデックスを記憶します。 
2. 要素を値で並べ替えます。 
3. すべての要素が同じグループ内にある場合の良さを計算します。$$d_1 = (b_{n-1} + b_n) - (b_1 + b_2)$$1 つのサブシーケンスが空である可能性があるため、このパーティションは常に有効です。 

1. 最小の要素のみが分離される特別な分割の適合性を計算します。$$d_2 = |(b_{n-1} + b_n) - (b_1 + b_2 + h)|$$最小ペアを次のように増やすため、絶対値が必要です。`h`以前の最大値を超える可能性があります。 

1. 比較する`d_1`そして`d_2`。 
2. もし`d_1 <= d_2`、すべての要素をグループに配置します`1`。 
3. それ以外の場合は、最小の要素をグループに配置します`1`他のすべての要素をグループに追加`2`。 
4. 元の入力順序で回答を復元し、選択した良さとパーティションを出力します。 

### なぜ効果があるのか

 配列全体の最小のペアの合計は、ソート後の 2 つの最小の要素によって常に形成されます。 同様に、最大のペアの合計は常に 2 つの最大の要素によって形成されます。 

パーティションは追加のみ可能です`h`選択したペアに。 答えを改善するには、ペアの最大値を増やすことなく、ペアの最小値を増やす必要があります。 

最小値を増やす唯一の方法は、2 つの最小要素を分離することです。 最大値の増加を避ける唯一の方法は、2 つの最大要素を一緒に保つことです。 

配列がソートされると、これら 2 つの要件によって最適な非自明なパーティションが一意に決定されます。 他のパーティションでは、最小値が変更されないままになるか、最大値が不必要に増加します。 

したがって、最適なものは、2 つの候補のうちの 1 つ、つまり、オールインワン グループか最小のものを分離する必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, h = map(int, input().split())
a = list(map(int, input().split()))

arr = [(a[i], i) for i in range(n)]
arr.sort()

same_group = (arr[-1][0] + arr[-2][0]) - (arr[0][0] + arr[1][0])
split_group = abs(
    (arr[-1][0] + arr[-2][0]) -
    (arr[0][0] + arr[1][0] + h)
)

if same_group <= split_group:
    ans = [1] * n
    print(same_group)
    print(*ans)
else:
    ans = [2] * n
    ans[arr[0][1]] = 1
    print(split_group)
    print(*ans)
```並べ替えによって順序が変更されるため、最初の部分には値と元のインデックスの両方が格納されますが、出力は元の入力順序と一致する必要があります。 

ソート後、最小の 2 つの要素は次の位置にあります。`0`そして`1`、最大の 2 つはポジションにあります`n-2`そして`n-1`。 

変数`same_group`すべての要素が同じサブシーケンスに属するパーティションに対応します。 ペアは受信しません`+h`。 

変数`split_group`最小の要素を分離することに相当します。 最小のペアがグループを越えて受信します。`+h`、最大のペアは変化しません。 

絶対値は微妙な部分です。 仮定する：```
h = 100
array = [1, 2, 3]
```それから：```
largest pair = 5
smallest cross pair = 103
```スプレッドは次のようになります。```
103 - 5 = 98
```ない`5 - 103`。 

最後に、パーティションを再構築します。 自明な分割が最適であれば、すべての要素にラベルが付けられます`1`。 それ以外の場合は、グローバルに最小の要素のみがラベルを受け取ります`1`。

 入力:```
3 2

```並べ替え後:

 | ポジション | 値 | オリジナルのインデックス |

| 数量 | 値 |

 | 分割グループ | \|5 - (3 + 2)\| = 0 |

パーティション:

 | 要素 | グループ |
 | --- | --- |
 | 1 | 1 |
 | 2 | 2 |
 | 3 | 2 |

| ペア | 値 |
 | --- | --- |
 | (1,2) | 5 |
 | (1,3) | 6 |
 | (2,3) | 5 |

 スプレッドは`6 - 5 = 1`。 

このトレースは、最小ペアのみを変更すると範囲が大幅に減少する理由を示しています。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(n \log n)$| 並べ替えが実行時間を支配します。 
| スペース |$O(n)$| ソートされた配列と回答配列にはすべての要素が格納されます。 

この制約により、制限時間内でおよそ数百万回の操作を快適に行うことができます。 仕分け`10^5`要素の処理は Python で簡単に十分に高速であり、残りの作業は直線的です。 

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    n, h = map(int, input().split())
    a = list(map(int, input().split()))

    arr = [(a[i], i) for i in range(n)]
    arr.sort()

    same_group = (arr[-1][0] + arr[-2][0]) - (arr[0][0] + arr[1][0])
    split_group = abs(
        (arr[-1][0] + arr[-2][0]) -
        (arr[0][0] + arr[1][0] + h)
    )

    if same_group <= split_group:
        ans = [1] * n
        print(same_group)
        print(*ans)
    else:
        ans = [2] * n
        ans[arr[0][1]] = 1
        print(split_group)
        print(*ans)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out

# provided sample
assert run("3 2\n1 2 3\n") == "1\n1 2 2\n"

# minimum size
assert run("2 0\n5 10\n") == "0\n1 1\n"

# all equal values
assert run("5 3\n7 7 7 7 7\n") == "0\n1 2 2 2 2\n"

# large h prefers single group
assert run("4 100\n1 2 3 4\n") == "4\n1 1 1 1\n"

# off-by-one style ordering check
assert run("5 2\n10 1 9 2 8\n") == "3\n2 1 2 2 2\n"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`2 0 / 5 10`| 善良さ`0`| 最小配列サイズと`h = 0`|
 |`5 3 / 7 7 7 7 7`| 1 つの要素を分離する | 等しい値でも分割によるメリットが得られます。 
|`4 100 / 1 2 3 4`| オールインワングループ | 大きい`h`分割すると有害になる可能性があります。 
|`5 2 / 10 1 9 2 8`| 分離された最小の元のインデックス | 元の順序の正しい復元 |

 ## 特殊なケース

 すべての数値が等しい場合を考えてみましょう。 

入力：```
5 3
7 7 7 7 7
```分割しないと、すべてのペアの値は等しくなります`14`、だから善は`0`。

アルゴリズムは以下を正しく比較します。```
same_group = 0
split_group = 3
```そしてすべてを一つにまとめます。 

次に、分割が劇的に役立つケースを考えてみましょう。

3 2
1 2 3
```生のペアの範囲は次のとおりです。```
5 - 3 = 2
```最小の要素を分離すると、最小値が上にシフトします。```
1 + 2 + 2 = 5
```最大値が残っている間に`5`。 

スプレッドは崩壊します`0`。 

最後に、危険なオーバーシュートの場合を考えてみましょう。 

入力：```
4 100
1 2 3 4
```最小のペアを分離すると、最小値が次から変更されます。`3`に`103`、古い最大値よりも大きくなります`7`。 

アルゴリズムは以下を使用します。```
abs(7 - 103)
```真のスプレッドを計算するには`96`。 

絶対値がないと、実装では誤って否定的な答えが生成されてしまいます。
