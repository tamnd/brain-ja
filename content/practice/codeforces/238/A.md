 ## 解決策
 ## 問題の理解

 長さの配列を扱います`n`、すべての要素は次の整数です。`0`に`2^m - 1`。 

xor が次のような連続した部分配列が存在する場合、シーケンスは「ウール」と呼ばれます。`0`。 ウールではないシーケンスがいくつあるかを数えるように求められます。これは、すべての連続する部分配列がゼロ以外の xor を持つことを意味します。 

答えはモジュロで計算する必要があります`10^9 + 9`。 

最初に注目すべきことは、部分配列に対する xor が自然にプレフィックス xor に接続されていることです。 定義すると$$p_i = a_1 \oplus a_2 \oplus \cdots \oplus a_i$$と`p_0 = 0`、次に部分配列の xor`[l, r]`等しい$$p_r \oplus p_{l-1}$$2 つの接頭辞 xor が等しい場合、部分配列 xor は正確にゼロになります。 

したがって、問題は密かに次のことを尋ねています。 

「ペアごとに異なるプレフィックス xor を生成する配列の数`p_0, p_1, ..., p_n`？」

 その再構築こそが問題なのです。 

制約が十分に大きいため、総当たりの列挙は不可能です。 両方`n`そして`m`到達できる`10^5`。 配列の数は$$(2^m)^n = 2^{mn}$$これは、中程度の値であっても天文学的に大きくなります。 二次形式で位置ごとに配列、サブセット、または XOR 状態を反復するソリューションは失敗します。 

ターゲットの複雑さは、ほぼ線形または対数的です。`n`そして`m`。 

見落としやすいエッジケースがいくつかあります。 

もし`n >= 2^m`、答えは自動的にゼロになります。 あるのは`2^m`可能なプレフィックス XOR 値ですが、必要なのは`n + 1`異なる値のため、`p_0`。 鳩の巣原理によ​​り、繰り返しは避けられません。 

例えば：```
n = 2, m = 1
```許可される値は次のとおりです`{0, 1}`。 

可能なプレフィックス xor は 2 つだけですが、3 つの異なる値が必要です。$$p_0, p_1, p_2$$無理なので正解は`0`。 

不注意な実装では、負の項を使用して下降階乗を計算しようとし、誤ってゼロではなくガベージが生成される可能性があります。 

もう 1 つの微妙なケースは、ゼロを含む配列です。 任意の要素`a_i = 0`すぐに長さ 1 のゼロ xor 部分配列を作成します。 

例えば：```
n = 1, m = 3
```許可される数値は次のとおりです`0..7`。 

値のみ`0`は禁止されていますので、答えは`7`。 

を忘れたバグだらけの派生`p_i != p_{i-1}`間違ってすべてを数えてしまう`8`配列。 

## アプローチ

 ブルートフォースアプローチは簡単です。 すべての長さの配列を生成します`n`、すべての部分配列の xor を計算し、xor がゼロに等しいかどうかを確認します。 

がある`2^{mn}`配列。 プレフィックス xor を使用してサブ配列の xor 計算を最適化したとしても、各配列は依然としてすべてをチェックする必要があります。`O(n^2)`サブアレイ。 

全体の複雑さは次のようになります。$$O(2^{mn} \cdot n^2)$$これは、たとえ小さな入力であっても絶望的です。 

プレフィックス xor を使用して条件を書き直すと、この問題は管理可能になります。 

定義する：$$p_0 = 0$$

$$p_i = a_1 \oplus a_2 \oplus \cdots \oplus a_i$$それから：$$a_i = p_i \oplus p_{i-1}$$プレフィックス xor を選択するたびに、配列が一意に決定されます。 

サブアレイ`[l, r]`次の場合に xor ゼロが存在します。$$p_r = p_{l-1}$$したがって、すべてのプレフィックス xor が異なる場合、シーケンスは厳密にはウールではありません。 

さて、問題は組み合わせになります。 

がある`2^m`可能な XOR 値。 

すでに修正済みです`p_0 = 0`。 

選択するには`p_1`を除く任意の値を使用できます。`0`、与える:$$2^m - 1$$選択肢。 

のために`p_2`、使用される 2 つの値を避ける必要があります。$$2^m - 2$$選択肢。 

このプロセスを続けると、次のようになります。$$(2^m - 1)(2^m - 2)\cdots(2^m - n)$$これは単なる下降階乗です。 

もし`n >= 2^m`, 因数が 1 つ 0 になるので、答えは 0 になります。 

問題全体はモジュラー乗算に帰着します。

 | 最適 |$O(n + \log m)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む`n`そして`m`。 
2. コンピューティング$$K = 2^m \pmod{10^9+9}$$高速べき乗剰余演算を使用します。 

1. もし`n >= K`通常の整数算術では、次の必要があるため、答えはゼロでなければなりません。`n + 1`異なるプレフィックス XOR 値のみ`K`価値観が存在する。 

以来`2^m`巨大になる可能性があるため、直接計算はしません。 かどうかだけを知る必要があります。`2^m <= n`。 

なぜなら`n ≤ 10^5`、安全に確認できます:

 - もし`m >= 17`、 それから`2^m > 10^5`、 それで`n < 2^m`自動的に
 - それ以外の場合は計算します`1 << m`1.初期化`answer = 1`。 
2. あらゆる人にとって`i`から`1`に`n`、乗算:$$answer \gets answer \times (K - i)$$モジュロ`10^9 + 9`。 

これは、各ステップで新しい個別のプレフィックス xor を選択することに対応します。 

1. 最終的な回答を印刷します。 

### なぜ効果があるのか

 不変条件は、処理後の位置です。`i`、接頭辞の xor 値$$p_0, p_1, \dots, p_i$$はすべて異なります。 

ステップで`i`、 その通り`i`xor 値はすでに使用されているため、次のようになります。$$2^m - i$$～に対する有効な選択肢`p_i`。 

次の理由により、個別のプレフィックス xor の有効なシーケンスはすべて、正確に 1 つの配列に対応します。$$a_i = p_i \oplus p_{i-1}$$そして、すべての配列は、正確に 1 つのプレフィックス XOR シーケンスを生成します。 

したがって、有効な配列をカウントすることは、個別のプレフィックス XOR 値を段階的に選択する方法をカウントすることと同じです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 9

def solve():
    n, m = map(int, input().split())

    # Check whether 2^m <= n without overflow
    if m < 17 and (1 << m) <= n:
        print(0)
        return

    total = pow(2, m, MOD)

    ans = 1

    for i in range(1, n + 1):
        ans = (ans * (total - i)) % MOD

    print(ans)

solve()
```最初の重要な詳細は、初期のゼロ チェックです。 

数学的条件は次のとおりです。$$n \ge 2^m$$しかし直接計算する`2^m`不必要に大きくなる可能性があります。 以来`n`せいぜい`100000`、 どれでも`m >= 17`自動的に次の条件を満たします。$$2^m > 100000$$したがって、鳩の巣原理から答えがゼロになることはありません。 小さいだけ`m`値を明示的にチェックする必要があります。 

変数`total`店舗:$$2^m \bmod MOD$$すべての演算はモジュロであるため、以降のすべての乗算にはこれで十分です。`MOD`。 

ループは次のように乗算されます。$$(2^m - 1)(2^m - 2)\cdots(2^m - n)$$組み合わせ導出と正確に一致します。 

減算はモジュロ乗算の前に行う必要があります。 ここで括弧を忘れることはバグの一般的な原因です。

# helper: run solution on input string, return output string
import sys, io

MOD = 10**9 + 9

def solve():
    input = sys.stdin.readline

    n, m = map(int, input().split())

    if m < 17 and (1 << m) <= n:
        print(0)
        return

    total = pow(2, m, MOD)

    ans = 1

    for i in range(1, n + 1):
        ans = (ans * (total - i)) % MOD

    print(ans)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out

    solve()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out.getvalue().strip()

# provided sample
assert run("3 2\n") == "6", "sample 1"

# minimum input
assert run("1 1\n") == "1", "single nonzero value"

# impossible because n >= 2^m
assert run("2 1\n") == "0", "pigeonhole principle"

# another small manual case
assert run("1 3\n") == "7", "all values except zero"

# boundary where n = 2^m - 1
assert run("3 2\n") == "6", "largest possible nonzero case"

# large m where zero condition should not trigger
res = int(run("100000 100000\n"))
assert 0 <= res < MOD, "large limits"

 ## 特殊なケース

 次のことを考慮してください。```
2 1
```XOR 状態は 2 つだけです。`0`そして`1`。 

アルゴリズムは以下をチェックします。$$2^1 = 2$$以来`n = 2`、必要です`3`個別のプレフィックス xor は不可能です。 初期の状態が戻ります`0`。 

これにより、誤って計算してしまうことを避けられます。$$(2-1)(2-2)=0$$多くの不必要な演算を経たモジュラー演算を通じて。 

次に、次のことを考えてみましょう。```
1 3
```許可される値は次のとおりです`0..7`。 

アルゴリズムは以下を計算します。 

| ステップ | 係数 | 答え |
 | --- | --- | --- |
 | 開始 | - | 1 |
 | i = 1 | 8 - 1 = 7 | 7 |

 唯一禁止されている配列は、`(0)`なぜなら、単一のゼロがすでにゼロ xor 部分配列を形成しているからです。 

アルゴリズムはこれを自動的に処理します。`p_1`等しくない`p_0 = 0`。 

最後に次のことを考慮してください。```
3 1
```ここ：$$2^1 = 2$$ただし、4 つの異なるプレフィックス xor が必要になります。 

早期チェックはすぐに返されます`0`。 

このチェックを行わないと、不注意な実装により負の値を法的に乗算し続ける可能性があります。`MOD`、意味のないゼロ以外の答えが生成されます。
