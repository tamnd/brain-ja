 ## 解決策
 ## 問題の理解

 私たちは独立した木のコレクションを与えられています。 各ツリーのすべての頂点には、有効な再構成で必要な 2 つの異なる色の入射エッジの数を記述する 2 つの数値が付いています。 ツリー内のすべてのエッジには、白または黒の 2 つの色のうちの 1 つを正確に割り当てる必要があり、これらの割り当ては頂点ごとの要件と一致している必要があります。 

形式的には、すべての頂点について、入射する白いエッジの数が最初に指定された値と一致し、入射する黒いエッジの数が 2 番目の値と一致する必要があります。 タスクは、木の端にそのような色付けが存在するかどうかを判断し、存在する場合は有効な色付けを構築することです。 

入力サイズが十分に大きいため、すべての解はすべてのテスト ケースにわたる頂点の総数において本質的に線形である必要があります。 n の合計は最大 3 · 10^5 であるため、O(n log n) 解であっても許容されますが不要ですが、テスト ケースごとに二次関数は不可能です。 

局所的に考えると微妙な問題が生じます。それは、頂点制約だけでは実現可能性を保証するのに十分ではありません。 たとえば、ある頂点は、部分的な割り当てで次数が許容する以上の白いエッジを要求する場合がありますが、これは隣接する頂点を考慮した後でのみ明らかになります。 もう 1 つの失敗モードは、グローバルな一貫性を維持せずにエッジごとに貪欲に色を割り当てることです。これにより、後の走査で簡単に制約に違反する可能性があります。 

最小限の失敗例は、中央の頂点に 2 つの白いエッジが必要であるが、1 つの端点が独自の制約によりすでに黒いエッジを強制している 3 つの頂点のパスです。 単純なローカル割り当てでは、正確な値に応じてグローバル ソリューションが存在する場合と存在しない場合があっても、色を個別に割り当てて、最終的に中心で一貫性がなくなる可能性があります。 

中心となる問題は、2 つの色にわたるノードごとの次数分割制約を持つツリー上でグローバルな実現可能性問題を解決していることです。 

## アプローチ

 ブルートフォース手法では、各ツリーの n−1 個のエッジのすべての可能な色付けを試し、頂点制約が満たされているかどうかを確認します。 各エッジには 2 つの選択肢があるため、ツリーごとに 2^(n−1) 個の可能性があります。 n = 50 の場合でもこれは実行不可能になり、n が 3・10^5 までの場合は完全に不可能になります。 

問題の構造は、基礎となるグラフがツリーであるという事実を利用することを示唆しています。 ツリーを使用すると、リーフを削除すると、残りの部分間にサイクルや依存関係を作成せずに問題のサイズが縮小するため、ボトムアップの推論が可能になります。 重要な観察は、各エッジは 2 つのエンドポイントにのみ寄与するため、その色の決定は頂点間での「需要」の転送と解釈できることです。 

ツリーをルート化すると、各頂点は、残りの要件を上に渡しながら、その子にエッジを使用して満たす必要がある白いエッジの数を決定できます。 これは当然、ボトムアップのフロー解釈につながります。各サブツリーは、親に送信する必要がある白いエッジの数を計算します。 

重要な洞察は、すべてのノードで、すべての子が処理されると、その親に影響を与える残りのエッジは親エッジ自体だけになるということです。 つまり、各サブツリーが上向きに残りの自由度を 1 つだけ伝達することを保証することで、一貫性を強制できるということです。 

これにより、問題は DFS を介してエッジ カラーの一貫した割り当てを計算することに変換され、各サブツリーがまだ必要な白いエッジの数を報告し、その値が親エッジの選択と一致することを確認します。

 ## アルゴリズムのチュートリアル

 ツリーを任意のノード (たとえば 1) にルートします。次に、深さ優先トラバーサルを実行し、各サブツリーを内部制約を満たす必要がある単位として扱い、同時に残差要件を上方に報告します。

1. 任意の場所にツリーをルートし、DFS を実行して親子関係を確立します。 このステップにより、サイクルなしで制約を伝播する方向が決まります。 
2. 各ノード u に対して、u をルートとするサブツリー内のいくつの白いエッジが u をその親に接続する必要があるかを表す値 rem[u] を定義します。 最初は、rem は不明であり、ボトムアップで計算されます。 
3. DFS 中に、最初に u のすべての子 v を処理します。 各子は、v から u までいくつの白いエッジが必要かを表す rem[v] を返します。 この値はすぐに決定として解釈されます。エッジ (u, v) は集約動作ではちょうど rem[v] 回白になりますが、エッジは使い捨てであるため、一貫した構造では rem[v] は 0 または 1 になります。 
4. 各子エッジ (u, v) について、v での一貫性を強制することによってその色を決定します。内部サブツリー解決後も v がその要件を満たすために 1 つの白いエッジを必要とする場合は、(u, v) を白として割り当てます。 それ以外の場合は黒を割り当てます。 これにより、v の要件がそれに応じて減少します。 
5. ノード u では、すべての子を処理した後、親エッジからまだ必要な白いエッジの数を計算します。 これは、元の wi から、白として割り当てられた子のエッジによって満たされる寄与を差し引いたものから導出されます。 
6. u がルートではない場合、この残余要件を rem[u] として上方に渡します。 u がルートの場合、残差要件ゼロで終了する必要があります。そうでない場合、解は存在しません。 
7. どこかの時点でノードの要件がマイナスになったり、利用可能な度合いを超えたりした場合、直ちに不可能であると結論付けます。 

微妙な点は、ツリー構造により、子が処理されると、親への単一のエッジを除いてすべての内部制約がすでに固定されていることが保証されるため、各サブツリーは単一のスカラー要件に減らされるということです。 

### なぜ効果があるのか

 不変条件は、ノード u を処理した後、そのサブツリー内のすべてのエッジが固定され、おそらくエッジから u の親への寄与を除いて、そのサブツリー内のすべての頂点が必要な白と黒のインシデント数を満たしていることです。 値 rem[u] は、u のサブツリーを実現可能にするために、その親エッジにまだいくつの白いエッジを割り当てる必要があるかを正確に表します。 

各サブツリーは単一のスカラーのみを上向きに通信するため、競合する要件が蓄積されることはありません。 より深いサブツリーが解決されると、すべての決定はエッジに対してローカルになります。また、ツリーにはサイクルがないため、競合する制約を持つエッジが再検討されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        w = [0] * (n + 1)
        b = [0] * (n + 1)

        for i in range(1, n + 1):
            wi, bi = map(int, input().split())
            w[i] = wi
            b[i] = bi

        g = [[] for _ in range(n + 1)]
        for _ in range(n - 1):
            u, v = map(int, input().split())
            g[u].append(v)
            g[v].append(u)

        parent = [0] * (n + 1)
        order = []
        stack = [1]
        parent[1] = -1

        while stack:
            u = stack.pop()
            order.append(u)
            for v in g[u]:
                if v == parent[u]:
                    continue
                if parent[v] != 0:
                    continue
                parent[v] = u
                stack.append(v)

        children = [[] for _ in range(n + 1)]
        for v in range(2, n + 1):
            children[parent[v]].append(v)

        rem = [0] * (n + 1)
        ok = True
        edges = []

        for u in reversed(order):
            need = w[u]
            for v in children[u]:
                if rem[v] > 1:
                    ok = False
                    break
                if rem[v] == 1:
                    edges.append((u, v, 'W'))
                    need -= 1
                else:
                    edges.append((u, v, 'B'))
                need -= 0 if rem[v] == 1 else 0
            if not ok:
                break
            if need < 0 or need > 1:
                ok = False
                break
            rem[u] = need

        if not ok or rem[1] != 0:
            out.append("No")
        else:
            out.append("Yes")
            for u, v, c in edges:
                out.append(f"{u} {v} {c}")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装では、再帰の深さの問題を回避するために、反復 DFS を使用してルート付きツリーを構築します。 の`parent`配列は構造を確立し、`children`は隣接性をルート形式で保存するため、各エッジはボトムアップ順序で 1 回だけ処理されます。 

鍵の状態は、`rem[u]`これは、u がその親に対してまだ白いエッジを必要とするかどうかをエンコードします。 子を処理するとき、各子は白または黒のエッジを提供し、これにより u での残りの需要が直接減少します。 ルートには親エッジがないため、残りの需要がゼロになるように終了する必要があります。 

よくある落とし穴は、各エッジを 1 回だけ記録する必要があることを忘れることです。 親から子への処理中にエッジを保存し、一意性を確保します。 

## 実用的な例

 チェーン 1-2-3 内の 3 つのノードからなる単純なツリーを考えてみましょう。頂点 2 には 1 つの白いエッジが必要で、頂点 1 と 3 にはゼロが必要です。 

1 をルートとしてボトムアップで処理します。 

| ノード | 処理された子 | レム値 | エッジでのアクション | レム[u] |
 | --- | --- | --- | --- | --- |
 | 3 | なし | w[3]=0 | なし | 0 |
 | 2 | 3 | レム[3]=0 | (2,3)=B | 1 |
 | 1 | 2 | レム[2]=1 | (1,2)=W | 0 |

 これは、ノード 2 の要求がエッジ 3 を使用してどのように満たされ、その後上向きに伝播されるかを示しています。 

ここで、ルートが制約を満たすことができない場合、つまり w=1 の単一ノードを考えてみましょう。 縁がないので無理です。 

| ノード | 処理された子 | レム値 | アクション | レム[u] |
 | --- | --- | --- | --- | --- |
 | 1 | なし | w[1]=1 | なし | 1 |

 root は rem[1]=0 でなければならないため、答えは不可能です。

 ## 特殊なケース

 単一の頂点のケースでは、ルートが残差需要ゼロで終了する必要があるという要件が明らかになります。 アルゴリズムは rem[1]=w[1] を割り当てますが、これを満たす親エッジがないため、ゼロ以外の値は即座に拒否を強制されます。 

中心が多くの白いエッジを必要とするが、子が不十分な星形のツリーは、失敗の伝播を示します。 各リーフは多くても 1 つのエッジに寄与するため、中心が利用可能な隣接エッジよりも多くの白いエッジを必要とする場合、処理中に rem が負になり、ルートに到達する前に拒否がトリガーされます。
