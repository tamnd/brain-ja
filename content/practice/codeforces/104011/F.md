 ## 問題の理解

 各出場者は、解決できる問題の個人的なリストを持っています。 出場者向け$i$、 問題$j$ゼロ以外の時間があります$a_{i,j}$解決できる場合は、そうでない場合は使用できません。 

コンテストが始まる前に、各出場者は解決可能な問題を取り上げ、それらをランダムに並べ替えます。 次に、そのシャッフルされた順序で問題を解決し、進むにつれて時間を蓄積します。 問題は、それまでの累積時間がコンテスト制限を超えない場合にのみ解決されます。$k$。 

それぞれの問題について$j$、時間内に問題を解決できたすべての出場者を調べます。 その中で、最も早くその問題をクリアした参加者が賞を獲得します。 複数の出場者がまったく同時にゴールした場合、全員が賞を受け取ります。 

このタスクは、すべての出場者について、すべての順列のランダム性を引き継いで、すべての問題にわたって獲得される予想される賞の数を計算することです。 

重要な問題は、「固定問題の終了時間」が出場者間で独立しておらず、出場者内では他のすべての解決可能な問題のランダムな順序に依存することです。 

問題の次元では制約は小さく、$m \le 26$、ただし出場者の数は中程度、$n \le 500$、そして時間制限付き$k \le 300$。 これは、サブセットに対する参加者ごとのナップザック スタイルの分散と、それに続く参加者に対する問題ごとの集約を強く示唆しています。 

単純なシミュレーションでは、各出場者のすべての順列を明示的に列挙します。これは階乗です。$m$たとえ一人の出場者であっても完全に実行不可能です。 

ランダムな順列における問題の位置が一様であると仮定すると、より微妙な故障モードが現れます。 位置を知るだけでは十分ではありません。 ランダムに順序付けされた重み付けされた項目のプレフィックス合計の分布が必要です。 

たとえば、出場者が 3 つの問題を時間をかけて解くことができた場合、$[1, 1, 100]$、特定の問題の予想終了時間は、重い​​アイテムが問題の前に現れるかどうかによって大きく異なります。 位置だけを治療すると、この構造は完全に失われます。 

## アプローチ

 ブルートフォースの観点は単純です。 各出場者について、解決可能な問題のすべての順列を列挙し、プレフィックスの合計をシミュレートし、各問題の終了時間を記録し、各問題について出場者間で比較します。 これは正しいですが、$m = 26$、1 人の出場者がすでに$26!$実行可能な計算をはるかに超えた順列。 

重要な観察は、順列をサブセット プロセスで置き換えることができるということです。 ランダムな置換では、固定要素の前に現れる要素のセットは、他の要素のすべてのサブセット間で一様にランダムになります。 これは、順列を部分集合和の分布問題に変換します。 

出場者を修正したら$i$そして問題$j$、の終了時間$j$前に現れる他の解決可能な問題のサブセットにのみ依存します。$j$、およびその総重量。 したがって、サイズのサブセットがいくつあるかを数えるナップザック DP を計算できます。$s$合計時間があります$t$。 サイズのサブセットが存在する確率と組み合わせると、$s$前に現れます$j$の終了時間の正確な分布を取得します。$j$その出場者のために。 

この後、問題は次のようになります。$j$、まであります$n$終了時間の離散分布。 各出場者について、その値が問題を解いたすべての出場者の中で最小である確率を計算する必要があります。$j$。 これは、分布を生存関数に変換し、それらを乗算的に組み合わせることで行われます。

 ## アルゴリズムのチュートリアル

 出場者を修正します$i$そして問題$j$。 

1. セットを構築する$S$出場者が抱える問題について$i$を除いて解決できます$j$。 このセットは、前に表示できるすべてのものを決定します。$j$ランダムな順列で。 
2. のサブセット上にナップザック DP を構築します。$S$。 させて`cnt[s][t]`サイズのサブセットの数になります$s$合計時間は誰ですか$t$。 これは、項目を反復処理し、サイズと合計の遷移を更新することによって計算されます。 制約$k \le 300$すべての合計を制限します。 
3. サブセット数を確率に変換します。 固定サブセット$P$サイズの$s$前に現れます$j$まさに$$\frac{s!(|S|-s)!}{(|S|+1)!}$$を含むすべての順列に対して相対的な方法$j$。 したがって、各ペア$(s,t)$既知の組み合わせの重みに次の値を乗算します。`cnt[s][t]`。 

1. これから構築します$f_{i,j}(x)$、出場者がそうなる確率$i$問題を終了します$j$正確な時間に$x + a_{i,j}$コンテストの制限内にある場合に限ります。$k$。 
2.変換$f_{i,j}$生存関数に：$$S_{i,j}(x) = P(T_{i,j} \ge x)$$経時的な接尾辞の合計によって計算されます。 

1. 解決された問題の場合$j$、計算する$$P_{\text{all}}(x) = \prod_i S_{i,j}(x)$$解ける出場者全員で$j$。 

1. 各出場者について$i$、部門ごとの貢献を削除します。$$P_{\text{others}}(x) = \frac{P_{\text{all}}(x)}{S_{i,j}(x)}$$1. 出場者が当選する確率$i$勝ちの問題$j$は$$\sum_x f_{i,j}(x) \cdot P_{\text{others}}(x)$$1. すべての問題についてこの値を合計します。$j$出場者が予想される数の賞を獲得するため$i$。 

### なぜ効果があるのか

 核となる不変条件は、固定された出場者に対して、ランダムな並べ替えにより、各区別された問題の先行する要素のサブセット全体に一様な分布が生じるということです。 これにより、順序付けが完全に削除され、サブセットのカーディナリティと重みの合計に置き換えられます。 競技者間の独立性により、終了時間は競技者間で独立しているため、最小値を計算するときに分布を乗算的に組み合わせることができます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modinv(x):
    return pow(x, MOD - 2, MOD)

def solve():
    n, m, k = map(int, input().split())
    a = [list(map(int, input().split())) for _ in range(n)]

    # precompute factorials up to 26
    maxm = m
    fact = [1] * (maxm + 1)
    for i in range(1, maxm + 1):
        fact[i] = fact[i - 1] * i % MOD

    invfact = [1] * (maxm + 1)
    invfact[maxm] = modinv(fact[maxm])
    for i in range(maxm, 0, -1):
        invfact[i - 1] = invfact[i] * i % MOD

    def build_dist(times, exclude_idx):
        # times: list of solvable times, excluding j
        # DP: cnt[s][t]
        dp = [[0] * (k + 1) for _ in range(len(times) + 1)]
        dp[0][0] = 1

        for w in times:
            for s in range(len(times) - 1, -1, -1):
                for t in range(k - w + 1):
                    if dp[s][t]:
                        dp[s + 1][t + w] = (dp[s + 1][t + w] + dp[s][t]) % MOD

        return dp

    ans = [0] * n

    for j in range(m):
        # build distributions for all i
        f = [[0] * (k + 1) for _ in range(n)]
        S = [[0] * (k + 2) for _ in range(n)]

        for i in range(n):
            if a[i][j] == 0:
                continue

            times = []
            for p in range(m):
                if p != j and a[i][p] > 0:
                    times.append(a[i][p])

            dp = build_dist(times, j)
            sz = len(times)

            total_perm = fact[sz + 1]

            # probability scaling
            inv_total = modinv(total_perm)

            # compute finish distribution
            for s in range(sz + 1):
                ways_s = (fact[s] * fact[sz - s]) % MOD
                for t in range(k + 1):
                    if dp[s][t]:
                        prob = dp[s][t] * ways_s % MOD * inv_total % MOD
                        ft = t + a[i][j]
                        if ft <= k:
                            f[i][ft] = (f[i][ft] + prob) % MOD

            # survival
            for t in range(k, -1, -1):
                S[i][t] = (S[i][t + 1] + f[i][t]) % MOD if t < k else f[i][t]

        # product of survivals
        P_all = [1] * (k + 2)
        for t in range(k + 1):
            prod = 1
            for i in range(n):
                prod = prod * S[i][t] % MOD
            P_all[t] = prod

        invS = [[0] * (k + 2) for _ in range(n)]
        for i in range(n):
            for t in range(k + 1):
                if S[i][t]:
                    invS[i][t] = modinv(S[i][t])

        for i in range(n):
            if a[i][j] == 0:
                continue
            res = 0
            for t in range(k + 1):
                if f[i][t]:
                    others = P_all[t] * invS[i][t] % MOD
                    res = (res + f[i][t] * others) % MOD
            ans[i] = (ans[i] + res) % MOD

    print(*ans)

if __name__ == "__main__":
    solve()
```この実装では、まず出場者ごとおよび問題ごとにサブセット合計分布を構築し、次にそれを終了時間分布に変換します。 生存関数はこれらの分布から計算されます。これは、「確率変数を超える最小値」を積構造に変換するために重要です。 最後のステップでは、最早完走者になる確率を計算する際に、各出場者自身の貢献度を慎重に取り除きます。 

微妙な点は、生存確率に逆モジュールを使用していることです。 すべての確率はモジュロで保存されるため、$998244353$、除算はモジュラー逆数による乗算として実装され、生存値がゼロ以外である必要があります。 実際には、生存率ゼロは不可能な比較に相当し、有効な合計には影響しません。 

## 実用的な例

 2 人の出場者と 1 つの問題があり、両方が解決できる単純化されたケースを考えてみましょう。 出場者 1 がタイムを持っていると仮定します。$[1,2]$出場者 2 はタイムを持っています$[2]$、 そして$k$大きいです。 

出場者 1 の場合、サブセット DP は以上です$[2]$得られるもの:

 | サブセットのサイズ | 合計 |
 | --- | --- |
 | 0 | 0 |
 | 1 | 2 |

 これにより、2 番目の項目が前か後かに応じて、終了時間が 1 と 3 になります。 

出場者 2 には他に項目がないため、終了時間は常に 2 になります。 

この比較では、タイム 1 で終了した場合は出場者 1 が勝ち、それ以外の場合は出場者 2 が勝ちであることがわかります。 

このトレースは、置換位置ではなくサブセットの選択によって分布がどのように決まるかを示しています。 

次に、両方の出場者が同じ分布を持っている場合を考えてみましょう。 対称性は同一の生存関数を意味し、製品の構築により同等の期待される賞が得られ、同一の入力の下での公平性が確認されます。

 ## 特殊なケース

 重要なエッジケースは、出場者が問題をまったく解決できない場合に発生します。 その場合、そのペアのすべての分布はゼロとなり、生存積には何も寄与しません。 アルゴリズムはそれらを自然にスキップし、勝利合計には決して含まれないため、ゼロによる除算は行われません。 

出場者が問題を解決しても常に時間を超過する場合、別の特殊なケースが発生します。$k$。 それから$f_{i,j}$も同様にゼロであり、再び何も寄与しません。 これにより、最終的な集計で誤って勝者として表示されることがなくなります。 

最後に、複数の出場者の終了時間の分布が同一である場合、積の定式化では同時最小値が許可されるものとして平等とみなされるため、同点は正しく処理されます。 生存ベースの比較では同点が解消されることはなく、最も早い時点で複数の出場者に賞を与えるという要件は維持されます。
