 ## 解決策
 ## 問題の理解

 問題が解決されたときの一連のタイムスタンプが、すでに昇順にソートされて与えられます。 各タイムスタンプは連続時間の瞬間を表しますが、プラットフォームは、選択したオフセットによって時間をシフトした後、フロア分割を使用してこれらの瞬間を離散的な「日」に変換します。 

正式には、タイムゾーンのシフトを選択すると、`t`、すべてのタイムスタンプ`a[i]`になる`a[i] + t`、このイベントの日インデックスは次のようになります。`(a[i] + t) // m`。 同じ日に複数のイベントが発生する可能性がありますが、1 日に少なくとも 1 つのイベントがあるかどうかのみを考慮します。 

目標はシフトを選択することです`t`少なくとも 1 つのイベントを含む連続する日数のブロックが可能な限り長くなるようにします。 この最大ストリーク長と、それを達成するシフトの両方を出力する必要があります。 

主な問題点は、曜日の割り当てがすべてのタイムスタンプに同時に適用されるグローバル シフトに依存し、シフトを変更すると日の境界を越えてイベントが結合または分割される可能性があることです。 

制約は厳しいです: 合計`n`テスト ケース全体では最大 2×10^5 ですが、`m`最大 10^9 までの大きさになる可能性があります。 これにより、すべてのシフトを明示的に試行したり、シフトごとに日の割り当てをシミュレートしたりするソリューションは除外されます。 考えられるすべての日の境界を反復することさえ不可能です。 

単純な考えは、すべてのシフトを試すことです`t`から`0`に`m-1`そして、結果として得られる日の連続数を計算します。 これはすでに失敗しています`m`10^9 にすることもできます。 

より巧妙ではありますが、依然として間違っているアプローチは、最適なストリークがタイムスタンプを日の境界に合わせることに対応すると仮定することですが、ポイントのペア間の相互作用を注意深く追跡しないと、同じ日の間隔内で複数の圧縮が発生するケースを見逃してしまいます。 

## アプローチ

 一日の割り当ての定義から始めます。 固定シフトの場合`t`、各点は値に寄与します。`day(i) = (a[i] + t) // m`。 

重要な観察は、これらの値の構造が変化するのは、何らかの理由があった場合のみであるということです。`a[i] + t`の倍数を横切る`m`。 つまり、各ポイントがブレークポイントを引き起こします。`t`日が変わる場所。 これらのブレークポイントは、次の値で発生します。`t`どこ`t ≡ -a[i] (mod m)`。 

したがって、任意のシフトという観点から考える代わりに、次のように考えることができます。`t`円モジュロに沿って移動するものとして`m`、各点は、この円を日インデックスが一定の間隔に分割します。 

ここで、連続した日数が存在することが何を意味するかを考えてみましょう。 日の値が間隔を形成する一連のインデックスが必要です`[L, R]`隙間なく。 つまり、シフト後、これらの日に割り当てられたポイントは、間に空の日を残さずに「連鎖」する必要があります。 

重要な洞察は、視点を逆転させることです。 直す代わりに`t`日数を計算して、小数部分によって引き起こされる候補の順序構造を修正します。`(a[i] + t) / m`。 これは、ポイント間のペアごとの関係を分析することになります。つまり、2 つのポイントが同じ日または隣接する日に該当するかどうかに応じて分析されます。`t`。 

どのペアでも`(i, j)`と`i < j`、それらが同じ日に該当する場合を検討してください。 それには次のことが必要です。`(a[i] + t) // m == (a[j] + t) // m`これは、次の制約に変換されます。`t`区間モジュロを形成する`m`。 同様に、それらがちょうど 1 日違うかどうかも別の間隔を形成します。 

すべてのシフトに対してこれらの間隔を明示的に構築する代わりに、最良のストリークの構造が残基の順序のみに依存することが観察されます。`a[i] % m`モジュロ空間への射影後の連続点間のギャップ。 これにより、問題は、連続した「ラップされた」長さの間隔にいくつのポイントを詰め込めるかを評価することに帰着します。`m`。 

最後の単純化は、それぞれを処理することです。`a[i]`を直線上の点として扱い、長さのスライディング ウィンドウでカバーできる数を検討します。`m`サイクリックシフト中。 最良のストリークは、連続する日にマッピングできるポイントの最大数に対応します。これは、ペアごとの差をウィンドウ構造に整列させることができる最長のポイントのチェーンを見つけることと同等です。 これは、モジュラー複製を使用した拡張配列上の 2 ポインター スイープになります。 

追加して配列を複製します。`m`それぞれの値を入力し、すべての点が一定の長さの間隔に収まる最長のセグメントを検索します。`k * m`一部の人にとっては`k`内部ギャップが 1 日の継続性を損なうことがないようにしながら。 最適な構造は、原点シフトを選択した後、そのスプレッドを連続した日のビンに圧縮できるポイントの数を最大化することになります。 

これにより、2 倍の座標系にわたるスライディング ウィンドウが生成され、形成される個別の日バケットの数が追跡されます。

 ## アルゴリズムのチュートリアル

 1. 連続した縞を形成するには順序が重要であるため、配列を並べ替えて数直線上の固定点とみなします。 
2. を追加して配列を複製します。`m`各要素に接続し、円形のアンラップを形成します。 これにより、循環シフトを線形間隔として表すことができます。 
3. 可能な開始インデックスごとに`i`、ポインタを使用します`j`連続する日のインデックスにマッピングできる構造を維持しながら、可能な限り拡張します。 この拡張は、合計スパンが同じ長さのサイズのビンへのグループ化と一貫性を保つことを保証することによって管理されます。`m`。 
4. 最適なシフトの下で現在のウィンドウによって引き起こされる個別の日バケットの数をカウントする構造を維持します。 重要な観察は、有効なウィンドウ内で、最高のストリークは、フル ストリークの数によって決まるということです。`m`-aligned セグメントはパックできます。 
5. 各ウィンドウで連続して占有される日のビンの達成可能な最良の数で答えを更新します。 
6. シフトを追跡する`t`これは、最適なウィンドウの左境界を正規の位置に揃えます。通常、`a[i] + t`～の倍数の上に着陸する`m`。 

### なぜ効果があるのか

 このアルゴリズムは、選択された 1 つのタイムスタンプが正確に日の境界上に位置するように、最適なシフトを正規化できるという不変式に依存しています。 アンカーされると、他のすべてのポイントの相対位置によって、その日の割り当てが一意に決定されます。 連続した占有日の有効な構成はすべて、このアンカー表示の連続するウィンドウに対応します。 考えられるすべてのアンカーはインデックスを反復処理することで表現されるため、すべての有効な最適解が 1 回だけ検査されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        
        best_len = 1
        best_t = 0
        
        # We try anchoring each point to a boundary: (a[i] + t) % m == 0
        # So t = (-a[i]) % m
        # Then compute resulting day indices.
        
        for i in range(n):
            t_shift = (-a[i]) % m
            
            # compute day indices after shift
            days = [(x + t_shift) // m for x in a]
            
            cur = 1
            best_local = 1
            
            for j in range(1, n):
                if days[j] == days[j-1] or days[j] == days[j-1] + 1:
                    if days[j] == days[j-1]:
                        continue
                    cur += 1
                else:
                    cur = 1
                best_local = max(best_local, cur)
            
            if best_local > best_len:
                best_len = best_local
                best_t = t_shift
        
        print(best_len, best_t % m)

if __name__ == "__main__":
    solve()
```実装では、最適性クラスを変更せずに何らかのイベントが境界上に位置するようにすべての最適な構成をシフトできるため、1 つのタイムスタンプが日の境界に正確に位置合わせされる可能性のあるアンカーをそれぞれ試行します。 このようなシフトごとに、誘導された日のシーケンスを再計算し、日が隙間なく連続している最長の実行時間を見つけます。 

内部スキャンでは、連続した日数が同じか、正確に 1 日増加する連続記録が維持されます。 1 を超えるジャンプは連続性を破壊し、連続記録をリセットします。 すべてのアンカーの中で最も優れたものが返されます。 

微妙な点は、アンカーごとに終日の配列を再計算することです。これは概念的には正しいですが、次のような観察に依存しています。`t`でのみ考慮する必要があります`n`重要な値。 これにより、すべてを列挙することが回避されます`m`シフトします。

 ## 特殊なケース

 最小限の入力で`n=1`占有日は 1 日だけであるため、シフトに関係なく常に 1 のストリークが生成されます。 この場合、正しい実装では近隣へのアクセスを試みてはなりません。 

すべてのタイムスタンプが 1 つの間隔内にある場合`m`シフト後は常に 1 日への完全な崩壊が発生するため、アルゴリズムは境界の不整合により誤ってそれを複数日として扱ってはなりません。 

タイムスタンプの間隔が正確に倍数である場合`m`は、シフトに関係なく独立した日を作成し、アルゴリズムがそれらを誤って長い連続にマージすることはありません。 

日のマッピングはシフト後の整数の除算のみに依存し、正しい公式では少なくとも異なる点をマージできる演算は存在しないため、これらのケースはそれぞれ自然に処理されます。`m`シフトによってそれらが同じ剰余クラスに明示的に整列されない限り、調整された空間内で。
