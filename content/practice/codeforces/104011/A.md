 ## 解決策
 ## 問題の理解

 簡略化されたタイムライン上に 2 つのポイントが与えられ、各年が AD システムまたは BC システムのいずれかでラベル付けされます。 各入力行は、「AD 2022」や「BC 5508」などの年を表します。 このタスクは、最初に指定された年の初日と 2 番目に指定された年の 1 日の間に厳密に何年あるかを計算することです。 

重要な微妙な点は、0 年というものは存在しないという歴史的な慣習です。移行期の年順は…紀元前 2 年、紀元前 1 年、西暦 1 年、西暦 2 年…となります。 このため、マッピングを注意深くエンコードしないと、符号付き整数の直接減算が少し難しくなります。 

制約は小さく、年は 1 から 9999 までです。これにより、テスト ケースごとに一定時間で実行されるソリューションであれば十分であり、繰り返しの解析や単純な算術でさえ無視できることがすぐにわかります。 

主なエッジケースは、BC から AD の境界を越えることです。 たとえば、「紀元前 1 年」と「西暦 1 年」の間には、ちょうど 1 年の境界ステップがあるため、答えは 2 ではなく 1 になります。 BC 年をゼロを含む負の数として扱う単純なマッピングは、ここでは失敗します。 

もう 1 つの特殊なケースは注文です。 古い日付が最初に来るとは保証されないため、解決策は一貫した数値マッピングで絶対差を取得することによって正規化する必要があります。 

## アプローチ

 この問題を考える強引な方法は、早い日付から開始して、後の日付に達するまで増分または減分しながら歩数を数えながら、年ごとにシミュレーションすることです。 これは概念的には単純で常に正しいですが、不必要な作業です。 範囲は狭いとはいえ、紀元前から紀元への移行が最悪の場合、エンドポイント間の差は最大約 20,000 年になる可能性があります。これはまだ小さいですが、エレガントではなく、拡張すると扱いにくくなります。 

本当の洞察は、これは不連続性がゼロの単なる線形順序付け問題であるということです。 隣接関係が時間隣接関係に正確に対応する単一の整数線に各年をマッピングできれば、答えは単純な絶対差になります。 

自然な構造では、西暦年を正の整数として割り当て、紀元前年を負の整数として割り当てますが、修正します。0 年がないため、紀元前 1 年が -1 にマッピングされ、西暦 1 年が +1 にマッピングされるようにする必要があります。これにより、遷移ギャップは生の整数ではちょうど 2 単位になりますが、実際には 1 年だけになります。 これを修正するには、変換時に紀元前の年を 1 つずらし、事実上数直線のゼロをスキップします。 

両方の年がこの修正された整数軸にマッピングされると、それらの間の年数は単に絶対的な差になります。

 ## アルゴリズムのチュートリアル

 各入力年を統合タイムライン上の整数に変換します。連続する整数は歴史の連続する年に対応します。 

1. 各行を、年の数値と方向マーカー (AD または BC) で構成されるペアに解析します。 
2. 年を符号付き整数表現に変換します。 年が西暦の場合は、+year に直接マッピングします。 年が BC の場合は、-year にマップします。 この段階でBC1は-1、AD1は+1となります。 
3. これら 2 つの整数間の生の差を計算します。 ただし、この生の差異は、欠落しているゼロ年の移行を 2 倍にカウントします。 
4. BC 側を 1 単位だけ前にシフトしたものとしてマッピングを調整します。 これは、BC 年 y を -(y - 1) にマッピングすることで同等に実装できます。これにより、-1 が 1 BC に対応し、0 が AD 1 の先行スロットに対応し、存在しない年のギャップが効果的に削除されます。 
5. 変換後、マップされた 2 つの値間の絶対差を取得します。 これにより、1 月 1 日の 2 つの境界間の正確な年ごとの推移の数が得られます。

### なぜ効果があるのか

 整数マッピングは、実際の歴史年と単位間隔を持つ整数の間の全単射を構築します。 マップされた値の 1 の増分は、BC から AD の境界を越える場合も含め、正確に 1 暦年進むことに対応します。 マッピングでは隣接性が維持され、人為的なゼロ点が削除されるため、整数空間内の距離はリアルタイムで経過した年数と同じになります。 したがって、差の絶対値は、年の推移の数を正確にカウントします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def parse(line: str) -> int:
    parts = line.strip().split()
    if parts[0] == "AD":
        return int(parts[1])
    else:
        y = int(parts[0])
        return -(y - 1)

a = parse(input())
b = parse(input())

print(abs(a - b))
```このソリューションは 2 行を読み取り、それぞれを統一された整数のタイムライン値に変換します。 ヘルパー関数は、人為的なゼロ点が存在しないように、BC 年をシフトすることで BC と AD の間の非対称性を処理します。 

最終的な答えは絶対差として計算されます。マッピングによって線形隣接性が保証されるため、これは有効です。 

よくある間違いは、BC 年をシフトせずに負の整数に直接マッピングすることです。 これにより、「1 BC」が -1、「AD 1」が +1 になり、距離 2 が誤って意味されます。修正されたシフトにより、この問題が正確に修正されます。

## テストケース```python
import sys, io

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    def parse(line: str) -> int:
        parts = line.strip().split()
        if parts[0] == "AD":
            return int(parts[1])
        else:
            y = int(parts[0])
            return -(y - 1)

    a = parse(input())
    b = parse(input())
    return str(abs(a - b))

def run(inp: str) -> str:
    return solve(inp)

# provided samples
assert run("1 BC\nAD 1\n") == "1"
assert run("AD 1\nAD 2001\n") == "2000"

# custom cases
assert run("AD 2022\n5508 BC\n") == str(abs(2022 - (-(5508 - 1)))), "cross era large gap"
assert run("1 BC\n2 BC\n") == "1", "within BC consecutive years"
assert run("AD 1\nAD 1\n") == "0", "same year"
assert run("9999 BC\nAD 9999\n") == str(abs(-(9999 - 1) - 9999)), "max boundary cross"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 紀元前 1/1 年 | 1 | BC-AD 境界の正確性 |
 | AD 1 / AD 2001 | 2000年 | 通常のAD減算 |
 | 西暦2022年 / 紀元前5508年 | 計算された | 時代を超えた大きなギャップ |
 | 紀元前 1 年 / 紀元前 2 年 | 1 | BC 順序付けの正確さ |

 ## 特殊なケース

 BC から AD への遷移については、入力「1 BC」と「AD 1」を考慮します。 パーサーは、BC を 1 つシフトした後、それらをそれぞれ 0 と 1 にマップします。 差は 1 で、境界を越えた単年の推移と一致します。 

「2 BC」や「1 BC」などの純粋な BC 入力の場合、マッピングでは -1 と 0 が与えられます。差は 1 で、連続する年を逆時系列で正しく反映しています。 

「AD 2022」と「AD 2022」などの同じ年の場合、両方とも 2022 にマッピングされ、予想どおり 0 が生成されます。 

シフト ロジックにより、すべての不連続性が連続した整数ラインに吸収されるため、考えられるすべての順序付けが 1 回の絶対差分の計算に減ります。
