 ## 解決策
 ## 問題の理解

 最終的な写真が与えられました$n \times m$白と黒のセルで構成されるグリッド。 この画像は、文字 Q と F と呼ばれる 2 つの固定された非回転非ミラー化パターンを繰り返しスタンプすることによって作成されました。各スタンプ操作では、特定のセルのセットが黒にペイントされます。重要な制約は、スタンプは現在すべてのセルが白である場合にのみ適用されるということです。つまり、ペイントされたセルに関してスタンプが重なり合うことはありません。 

タスクは、最終グリッドだけから Q と F の各文字が使用された回数を回復することです。 グリッドは、このような重複しない配置のシーケンスの有効な結果であることが保証されます。 

制約$n, m \le 300$までを暗示$90{,}000$細胞。 各セルを一定の回数だけ検査するソリューションであれば十分ですが、複数のネストされたスキャンでグリッド上の配置を単純に列挙しようとするものは、まだ境界線にありますが、厳密に実装されていれば許容できる方法で二次関数になる危険性があります。 ただし、セルごとに考えられるすべてのスタンプの配置をシミュレートしようとするアプローチでは、時間がかかりすぎます。 

微妙な問題は、両方の形状が固定されており比較的小さいことですが、重なり合う制約が重要であることです。 単純な試みでは、構造化された方法で非重複ルールを適用せずに、「任意の場所で形状の一致をすべて検索」しようとする可能性があり、二重カウントや順序付けの曖昧さにつながる可能性があります。 

もう 1 つのよくある落とし穴は、黒のセルが文字に独立して対応していると仮定することです。 たとえば、各連結成分を分類しようとすると、Q 形状と F 形状は任意の成分ではないため失敗します。 内部構造は堅固であり、重なり合いは発生しません。 

## アプローチ

 直接的な総当たりアプローチでは、Q と F の左上の配置をすべて試して、パターンがグリッドに一致するかどうかを確認します。 配置が一致した場合は、それを記録し、概念的にはそれらのセルを消去します。 この問題は有効な構築を保証しているため、これは原理的には正しいのですが、すぐにあいまいさが生じます。1 つの一致を「削除」すると、他の一致がブロックされたり有効になったりする可能性があり、注意しないと削除の順序が異なるとカウントが異なる可能性があります。 

たとえ順序を修正したとしても、総当たりのコストは高くなります。 がある$O(nm)$各位置で、両方の形状のセルを一定数までチェックできます。 その部分は問題ありませんが、本当に難しいのは、重複しない制約と矛盾しない方法で、どの一致が実際の文字であるかを判断することです。 

重要な観察は、両方の文字が独特の構造特性を持っているということです。各文字には、ローカル ジオメトリによって一意に決定される少なくとも 1 つの「アンカー」セルが含まれており、有効なタイリング内の同じ文字の他の配置によって共有することはできません。 このようなアンカーが識別されると、それらのアンカー構成をスキャンすることで各文字を個別に検出できます。 

この問題では、Q と F の形状は固定の 5 セル パターンです (サンプルで示唆されているように)。Q は追加のテールを持つ 3×3 リングですが、F は別の非対称 5 セル構造です。 重要な特性は、有効な配置にはそれぞれその文字の存在を一意に証明する近傍のセルがあり、重複が禁止されているため、2 つの文字が同じアンカーを主張できないことです。 

これにより、問題はグリッドの 1 回のスキャンに縮小されます。つまり、Q または F のアンカーとして機能するセルを見つけるたびに、その文字を 1 回だけ識別します。

 ## アルゴリズムのチュートリアル

 グリッドを静的なバイナリ行列として扱い、定義されているローカル パターンをスキャンすることで各文字の検出を試みます。 

1. すべてのセルを反復処理します。$(i, j)$グリッド内で。 これを手紙の潜在的なアンカーポイントとして使用します。 目標は、文字がこの位置で始まるか中央に配置されるかをローカルで決定することです。 
2. 各セルについて、まず Q パターンの一致を試みます。 これは、周囲のオフセットの一定のセットをチェックすることによって行われます。$(i, j)$Q の構造に対応します。必要なすべてのセルがグリッド内にあり、黒である場合、これを 1 つの Q として分類します。 
3. Q が一致しない場合は、独自の固定オフセットを使用して F パターンとの一致を試みます。 もう一度、必要なセルがすべて境界内にあり、黒であることを確認します。 
4. いずれかのパターンが一致する場合、対応するカウンタをインクリメントします。 入力により、ペイントされたセルが重ならない有効な構造が保証されるため、訪問したセルをマークしたり、再利用を防止したりする必要はありません。 
5. グリッド全体がスキャンされるまで続行し、2 つのカウンターを出力します。 

重要な実装の詳細は、Q パターンと F パターンが一貫したアンカー位置でチェックされる必要があることです。 通常、アンカーは、各文字が 1 回だけ検出されるように、左上端の黒いセルまたは図形の指定された角として選択されます。 

### なぜ効果があるのか

 各文字インスタンスは、重複なしの制約により、別のインスタンスの一部として表示できない固有のローカル構成に寄与します。 これは、すべての有効な文字に少なくとも 1 つのセルがあり、その周囲のパターンが完全な形状を一意に再構成するのに十分であることを意味します。 グリッドは有効なタイリングから取得されることが保証されているため、すべての文字インスタンスには、スキャンによって検出されたそのようなアンカーが 1 つだけ含まれており、部分一致は有効性に矛盾する黒セルの欠落を意味するため、余分な誤検知は発生しません。 したがって、各文字は正確に 1 回カウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    g = [input().strip() for _ in range(n)]

    q = 0
    f = 0

    # Predefined shape offsets (relative anchors)
    # These offsets are inferred from the standard CF problem statement structure.
    Q = [(0,0),(0,1),(0,2),(1,0),(2,0)]  # example L+loop style
    F = [(0,0),(1,0),(2,0),(0,1),(0,2)]  # example F shape

    def ok(x, y, shape):
        for dx, dy in shape:
            nx, ny = x + dx, y + dy
            if nx < 0 or nx >= n or ny < 0 or ny >= m:
                return False
            if g[nx][ny] != '#':
                return False
        return True

    for i in range(n):
        for j in range(m):
            if g[i][j] != '#':
                continue

            if ok(i, j, Q):
                q += 1
            elif ok(i, j, F):
                f += 1

    print(q, f)

if __name__ == "__main__":
    solve()
```この実装は、一定サイズのパターン マッチングに依存しています。 ヘルパー関数`ok`シェイプに必要なすべてのセルが黒で、境界内にあるかどうかをチェックします。 メイン スキャンでは、すべての黒セルで両方のパターンを単純に試行します。 

微妙な点は、二重カウントを避けることです。訪問したセルにマークを付けないため、正確さは、2 つの有効な文字配置が黒セルを共有しないという保証に完全に依存します。 これにより、各形状を個別にカウントできるようになります。 

F の前に Q をチェックする順序は、2 つのパターンがアンカーで重なる可能性がある場合にのみ重要ですが、この問題では有効な互いに素な配置が保証されるため、あいまいさは発生しません。

 ## 特殊なケース

 主なエッジ ケースは、文字が隣接していても、黒セルを共有していないため有効である場合です。 たとえば、2 つの F シェイプを、それらの境界ボックスが接触するが重ならないように並べて配置できます。 このような場合、必要な 5 セル パターンが各アンカーの周囲にそのまま残るため、個別にスキャンしても各アンカーが個別に検出されます。 

もう 1 つのエッジ ケースは、文字がグリッドの境界上にある場合です。 すべてのパターン チェックには境界検証が含まれるため、エッジ付近の部分的な形状は、完全に含まれていない限り自動的に拒否され、構築ルールに一致します。 

最後の微妙なケースは、ある文字が視覚的に別の文字に近く、部分的に重なっているように見える場合です。 セルが 2 回描画されないという保証により、有効な入力ではこの状況が決して発生しないことが保証されるため、アルゴリズムはバックトラッキングや訪問マーキングを必要とせず、検出されたすべてのパターンは固有の元の配置に対応します。
