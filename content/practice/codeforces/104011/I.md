 ## 問題の理解

 サイズの隠された順列が与えられています$n$、値は 1 から 1 までの整数を並べ替えたものです。$n$。 配列を直接見ることはできません。 代わりに、2 つの操作を使用して操作できます。 1 つの操作では、非標準のコンパレータを使用して 2 つの位置を比較します。このコンパレータは、2 つの値の相対的な差が極端に近い場合を除き、通常の比較と同様に動作します。この場合、「等しい」が返されます。 もう 1 つの操作は 2 つの位置を交換し、交換後に配列が完全にソートされたかどうかを示します。 

私たちのタスクは、クエリの総数を 300,000 という大きな制限内に保ちながら、これらの対話型操作を使用して並べ替えを並べ替えられた順序に復元することです。 

重要な構造上の意味は、基本的に、ほぼ完全なコンパレーターに基づいてソートを行っているが、個別の値が区別できない可能性がある小さな領域があるということです。 ただし、基になる配列は 1 から 1 までの整数の真の置換であるため、$n$、実際の重複は存在しないため、「等しい」という結果は、実際の等しいというよりもコンパレーターの結果です。 これは、比較は順序付けを誘導するために引き続き使用できることを意味しますが、場合によっては不確実性があり、スワップとグローバル構造を通じて間接的に解決する必要があります。 

制約は大きいです:$n$最大 16384 まで可能です。これにより、おおよそより悪いものは排除されます。$O(n \log n)$各比較は対話型のクエリであるため、比較さえも慎重に実装する必要があります。 ナイーブ$O(n^2)$最悪の場合、10^8 を超える比較が必要になるため、並べ替えアプローチは完全に実行不可能です。 

微妙なエッジ ケースとして、配列がすでにソートされている場合でも、少なくとも 1 つのスワップ クエリを実行する必要があることが挙げられます。 これは、要素をそれ自体と交換するなど、無害な交換を含める必要があることを意味します。 これを行わないと、配列がすでに正しい場合でも、出力終了信号は生成されません。 

もう 1 つの微妙な問題は、対話の正確性です。すべてのクエリは直ちにフラッシュされる必要があり、配列がソートされたことがスワップによって返されたらすぐにプログラムを終了する必要があります。 それ以降の継続は無効となります。 

## アプローチ

 ブルートフォース手法では、標準の比較ベースの並べ替えとまったく同じように比較を使用して配列を並べ替えようとします。 ペアを繰り返し比較して順序を入れ替える、選択ソートまたはバブル ソートを思い浮かべる人もいるかもしれません。 正しさは単純ですが、複雑さは法外です。 バブルソートには次のことが必要です$O(n^2)$比較と交換、$n = 16384$2 億 6,800 万件を超える比較が行われ、インタラクティブなオーバーヘッドを考慮する前でも制限をはるかに超えています。 

重要な観察は、実際には完全な古典的な並べ替えプロセスを慎重にシミュレートする必要がないということです。 配列がソートされるまで、無秩序を徐々に減らす一連のスワップを生成するだけでよく、これがいつ起こるかが明示的に通知されます。 これにより、ソートされたプレフィックスを厳密に維持したり、あらゆる場所で決定論的な比較を実行したりするのではなく、有効な順列変換を構築するという観点から考えることができます。 

重要な洞察は、分割統治またはランダム化された分割戦略によって配列を並べ替え可能として扱うことができるということです。比較はローカルな順序付けをガイドするためにのみ使用され、スワップは修正と進行状況の追跡の両方に使用されます。 インタラクションフィードバック (「ソートされたかどうか」) は、問題を効果的に適応プロセスに変えます。各ステップの後に完全な順序付けを証明する必要はなく、プロセスが迅速に収束することを確認するだけです。 

この制約条件に対する標準的な最適な考え方は、比較を慎重に制限しながら、クイックソートのようなパーティショニングやマージソートのような再構築などの効率的な比較ベースの並べ替え構造をシミュレートすることです。$O(n \log n)$。 それぞれの比較は構造上の決定を導き、スワップは新たな順序を強制するために必要な場合にのみ使用されます。

 ## アルゴリズムのチュートリアル

 クイックソートからヒントを得た、対話型制約に適応した再帰的パーティショニング戦略を使用して、比較ベースの並べ替えプロセスをシミュレートします。 

1. 現在のセグメント (通常はセグメントの中央のインデックス) からピボット要素を選択します。 ピボットは、残りの要素を分割するための参照として機能します。 
2. インタラクティブなコンパレーターを使用して、セグメント内の他のすべての要素をピボットと比較します。 それぞれの比較により、相対的な順序付けが行われます。つまり、不正確さの規則により、より小さいか、より大きいか、場合によっては等しいかのいずれかになります。 
3. セグメントを、ピボットより小さいと判断された要素とピボットより大きい要素の 2 つのグループに分けます。 真の重複は順列には存在しないため、あいまいな「等しい」結果はいずれも片側でグループ化することによって一貫して処理されます。 
4. スワップ操作を使用して、このパーティションを物理的に強制します。 小さい要素をセグメントの左側に移動し、大きい要素を右側に移動します。 各スワップは不一致の位置間で実行され、ローカル構造が徐々に復元されます。 
5. セグメントがごく小さくなる (サイズ 1 または 2) まで、同じ手順を左と右のセグメントに再帰的に適用します。セグメントが小さくなった時点で、セグメントは本質的にソートされるか、一定数のスワップで修正できます。 
6. すべての再帰的パーティショニングが完了したら、グローバルな一貫性を確保するために、インデックスの昇順で隣接するスワップの最終スイープを実行します。 各スワップは対話型システムによってチェックされ、配列が完全にソートされたことがレポートされるとすぐに終了します。 

システムが分類されたことを確認したら安全に停止できる理由は、この信号が全体的に正しく、さらなる検証の必要がないためです。 

### なぜ効果があるのか

 すべての再帰ステップで、左側のパーティションに配置されるすべての要素がピボットよりも小さくなるように意図され、右側のパーティションに配置されるすべての要素がピボットより大きくなるように意図されるという不変条件を維持します。 コンパレータの不正確さが時折誤分類を引き起こす場合でも、その後のスワップと再帰的改良により局所的な不一致が修正されます。 各パーティションは問題のサイズを厳密に削減するため、プロセスは完全に順序付けされた配置に収束します。$O(n \log n)$構造的なステップ。 スワップ フィードバック メカニズムにより、正確性が達成された後にオーバーシュートしたり、不必要に継続したりすることがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ask_compare(i, j):
    print(f"C {i} {j}", flush=True)
    return int(input().strip())

def ask_swap(i, j):
    print(f"S {i} {j}", flush=True)
    return int(input().strip())

def quicksort(l, r, idx):
    if l >= r:
        return
    i, j = l, r
    pivot = idx[(l + r) // 2]

    while i <= j:
        while ask_compare(idx[i], pivot) == -1:
            i += 1
        while ask_compare(idx[j], pivot) == 1:
            j -= 1
        if i <= j:
            idx[i], idx[j] = idx[j], idx[i]
            ask_swap(idx[i], idx[j])
            i += 1
            j -= 1

    quicksort(l, j, idx)
    quicksort(i, r, idx)

def main():
    n = int(input().strip())
    idx = list(range(1, n + 1))

    quicksort(0, n - 1, idx)

    for i in range(1, n):
        if ask_swap(idx[i - 1], idx[i]) == 1:
            return

    ask_swap(1, 1)

if __name__ == "__main__":
    main()
```この実装は、配列がインデックスによって暗黙的に表されるクイックソート スタイルのパーティショニングに従います。 の`ask_compare`関数は対話型の比較を実行し、`ask_swap`終了を確認しながらスワップを実行します。 

ピボットは現在のセグメントの中央から選択され、これによりパーティションの深さが安定し、構造化された置換での最悪の場合の劣化が回避されます。 パーティショニング中に、両側がピボットの間違った側にあることが検出された場合、2 つのポインターを内側に移動し、スワップによって間違って配置された要素を修正します。 

最後のループでは、少なくとも 1 つのスワップが実行されるという要件への準拠が保証されます。 配列が予想よりも早くすでにソートされている場合は、セルフスワップを使用して終了します。 

微妙な点は、すべてのスワップがすぐにチェックされ、「1」を受け取ったらすぐにプログラムを終了する必要があることです。 これは、から戻ることによって強制されます。`main()`すぐに。

 ## 特殊なケース

 重要なエッジケースは、順列がすでにソートされている場合です。 この状況でも、アルゴリズムは少なくとも 1 つのスワップを発行する必要があります。 最後のループは、以前に終了が発生しない場合にインデックス 1 でセルフスワップを実行することでこれを保証します。 インタラクティブなジャッジはすぐに成功を返し、クリーンな終了を許可します。 

別のエッジ ケースは、ピボットがコンパレータの不正確さの影響を受ける領域に繰り返し入るときに発生します。 等しい応答が表示される可能性があるため、要素が一貫性なく分割される可能性があります。 このアルゴリズムは、再帰的改良を継続することによってこの問題を解決します。また、スワップは個別の比較ではなくグローバル パーティション構造によって導かれるため、配置ミスは後の再帰レベルで最終的に修正されます。 

最後のエッジ ケースは、ピボットが常にセグメント内の最小または最大の要素である場合など、パーティショニングにおける極端な不均衡です。 この場合でも、分割後に少なくとも 1 つの辺が厳密に小さくなり、無限ループが防止され、最終的な収束が保証されるため、再帰は依然として進行します。
