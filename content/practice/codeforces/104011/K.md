 ## 解決策
 ## 問題の理解

 重み付けされたエッジを持つ無向グラフが与えられます。重みはカラフルさと呼ばれます。 タスクは都市 1 から都市 n まで移動することですが、任意の経路を通るだけではありません。 

まず、すべての可能なルートのうち、最小数のエッジを持つルート、つまり重みではなくホップ数の観点からの最短パスのみに関心があります。 このような最短のホップ数のパスすべての中で、パスに沿ったエッジのカラフルさの最大値と最小値の差を最大にするパスが必要になります。 

したがって、問題は基本的に 2 レベルの最適化です。 最初の制約により、エッジの数に関して最短パスのサブグラフ内に固定されます。 その制限されたセット内で、エッジの重みに対して定義された範囲値を最大化するパスを選択する必要があります。 

制約は大きく、最大 100,000 個のノードと 200,000 個のエッジがあります。 密なグラフ内の最短パスの数は指数関数的に増加する可能性があるため、これによりすべての最短パスの列挙が直ちに除外されます。 すべての候補パスを保存または列挙しようとするソリューションは失敗します。 

おそらく BFS と追加の最適化ステップを使用した、O(n + m) または O(m log m) スタイルのソリューションが期待されるはずです。 

複数の最短パスが存在する場合、微妙な問題が発生します。 単純なアプローチでは、最短パス ツリーを計算し、それを貪欲に調整しようとする可能性がありますが、最短パス ツリーは一意ではなく、BFS の親の選択が異なると、達成可能なカラフルさの範囲が大幅に変わる可能性があります。 

もう 1 つの罠は、世界的に最高の色彩範囲パスも最短であると仮定していることです。 パスの長さをわずかに長くすると、色の範囲がさらに良くなる可能性がありますが、最短パスの制約が優先されるため、これは無効です。 

素朴な考えによる小さな失敗例を示します。 

グラフを考えてみましょう。 

1 - 2 - 3 - 4 (すべてのエッジの重み 1)

 1 ～ 3 (エッジの重み 100)

 1 ～ 4 (エッジの重み 0)

 1 から 4 までの最短パスの長さは 2 です。1-3-4 または 1-2-3-4 は、長ければ最短ではありません。 単純なアルゴリズムでは、重みが極端に大きいため 1-3-4 が優先される可能性がありますが、考慮する必要があるのは最短パスのみです。 

したがって、課題は、エッジの重みよりも二次的な目的を最適化しながら、最短パスへの注意を効率的に制限する方法です。 

## アプローチ

 最も直接的なアイデアから始めます。ノード 1 から BFS を実行して、すべてのノードまでのエッジの最短距離を計算します。 次に、最短パスの階層化を考慮するエッジに限定します。つまり、距離 d のノードから距離 d+1 のノードへの遷移のみを考慮します。 これにより、BFS レベルで階層化された有向非環状構造が形成されます。 

この構造を取得したら、問題は、パスに沿ったエッジの重みの最大値と最小値の差を最大化しながら、レイヤー 0 からレイヤー dist[n] までのパスを選択することになります。 

この DAG 内での強引な方法は、すべてのパスを列挙するか、これまでに確認された最小と最大のエッジの重みの両方を追跡する状態に対して DP を実行することです。 ただし、その DP 状態は大きすぎます。各ノードには多くの可能な最小値と最大値の組み合わせがあり、そのような状態の数は最悪の場合 O(2^n) に爆発的に増加する可能性があります。 

重要な観察は、答えは最小および最大のカラフルさの値として機能するパスに沿ったエッジのペアの選択にのみ依存するということです。 これら 2 つの境界を修正したら、重みがその区間内にあるエッジ内に留まり、依然として 1 から n を正確に最短の長さで接続する最短パスが存在するかどうかを確認するだけで済みます。 

これにより、問題は、BFS 実現可能性チェックと組み合わせて、ソートされたエッジの重みに関する古典的な 2 ポインターの実現可能性問題に変換されます。 

すべてのエッジをカラフルさで並べ替えます。 次に、可能な最小エッジ値と最大エッジ値に対してスライディング ウィンドウを使用します。 各候補ウィンドウ [L, R] について、重みがこの範囲内にあるエッジのみを使用して、1 から n までの最短パスが存在するかどうかを確認します。

実現可能性を確認するために、フィルタリングされたグラフで BFS を実行し、distans[n] がグラフ全体で事前に計算された最短距離と等しいかどうかを確認します。 

これが機能するのは、エッジを制限しても、一部のエッジが削除されることを除いて BFS レイヤー構造が変更されないためです。 制限下で最短パスがまだ存在する場合、BFS 距離は同じままになります。 

ソートされたエッジの重みに対する 2 つのポインターを維持し、必要に応じて R を拡張し、L を縮小し、最適な実行可能な間隔を追跡します。 

最後に、最適な間隔が見つかったら、フィルター処理されたグラフ内の BFS 親ポインターを使用して実際のパスを再構築します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 最小/最大追跡によるパス上のブルート フォース DP | 指数 | O(nm) 状態 | 遅すぎる |
 | BFS レイヤ化 + スライディング ウィンドウ + 実現可能性 BFS | O(m log m + m n BFS 償却) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. グラフ全体のノード 1 から BFS を実行して、すべてのノードまでのエッジの数に関する最短距離を計算します。 この距離は、有効なソリューションに許可される唯一のパス長を定義します。 ノード n に到達できない場合は停止しますが、問題によっては接続が保証されます。 
2. ノード n までの最短距離を target_length として保存します。 有効な答えは、まさにこの長さのパスでなければなりません。 
3. すべてのエッジをカラフルさの値で並べ替えます。 これにより、許容される重みの候補区間を昇順に推論することができます。 
4. ソートされたリストのエッジ インデックスに関して現在の間隔 [L, R] を維持しながら、ソートされたエッジ上で 2 ポインターのスライディング ウィンドウを使用します。 この間隔は、カラフルさが 2 つの選択された値の間にあるエッジのみを許可することに対応します。 
5. 候補区間ごとに、グラフ上に一時的な BFS を構築しますが、カラフルさが [L, R] にあるエッジのみを使用します。 BFS 中に、ノード 1 からの最短距離を計算します。 
6. ノード n が到達可能で、その距離が target_length に等しい場合、エッジの重みを制限しながら最短パスの最適性が維持されるため、この間隔は実現可能です。 
7. 可能な場合は、間隔を拡張して、最大のカラフルさと最小のカラフルさの差を増やすように試みます。 それ以外の場合は、間隔を縮小または移動して実行可能性を復元します。 
8. 実現可能性を維持しながら、R_value から L_value を引いた値を最大化する最適な間隔を追跡します。 
9. 最適な間隔を見つけた後、親ポインターを保存しながら、その間隔に制限された最後の BFS を 1 つ実行して、実際の最短パスを再構築します。 
10. 親配列を使用して、1 から n までの再構成されたパスを出力します。 

### なぜ効果があるのか

 このアルゴリズムは、2 つの入れ子になった単調構造に依存しています。 まず、BFS レイヤ化により、すべての有効なソリューションが最短距離で定義された DAG 上に存在する必要があります。 第 2 に、固定重み間隔に関する実現可能性は単調です。間隔 [L, R] が最短経路を許可する場合、L' ≤ L および R' ≥ R である任意のより大きな間隔 [L', R'] も最短経路を許可します。 この単調性により、スライディング ウィンドウは最適なソリューションを見逃さずに候補範囲を効率的に探索できます。 BFS チェックは、エッジ制約の下で最短長のパスが存在するかどうかを正確に特徴付けるため、正確性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def bfs(n, adj, allowed):
    dist = [10**18] * (n + 1)
    parent = [-1] * (n + 1)
    dist[1] = 0
    q = deque([1])

    while q:
        u = q.popleft()
        for v, idx in adj[u]:
            if not allowed[idx]:
                continue
            if dist[v] > dist[u] + 1:
                dist[v] = dist[u] + 1
                parent[v] = u
                q.append(v)

    return dist, parent

def solve():
    n, m = map(int, input().split())
    edges = []
    adj = [[] for _ in range(n + 1)]

    for i in range(m):
        u, v, c = map(int, input().split())
        edges.append((u, v, c))
        adj[u].append((v, i))
        adj[v].append((u, i))

    # BFS for shortest path length
    dist0 = [10**18] * (n + 1)
    q = deque([1])
    dist0[1] = 0

    while q:
        u = q.popleft()
        for v, _ in adj[u]:
            if dist0[v] > dist0[u] + 1:
                dist0[v] = dist0[u] + 1
                q.append(v)

    target = dist0[n]

    # sort edges by colorfulness
    order = sorted(range(m), key=lambda i: edges[i][2])
    colors = [edges[i][2] for i in order]

    allowed = [False] * m

    def check(l, r):
        for i in range(m):
            allowed[i] = False
        for i in range(l, r + 1):
            allowed[order[i]] = True

        dist, parent = bfs(n, adj, allowed)
        return dist[n] == target, parent

    best_l, best_r = 0, 0
    j = 0

    for i in range(m):
        while j < m:
            ok, _ = check(i, j)
            if ok:
                if colors[j] - colors[i] > colors[best_r] - colors[best_l]:
                    best_l, best_r = i, j
                j += 1
            else:
                break

    ok, parent = check(best_l, best_r)

    path = []
    cur = n
    while cur != -1:
        path.append(cur)
        cur = parent[cur]

    path.reverse()

    print(len(path) - 1)
    print(*path)

if __name__ == "__main__":
    solve()
```このソリューションでは、まずノード 1 からすべてのノードまでの最小ホップ距離を計算します。 これにより、唯一の有効なパス長が固定されます。 次に、エッジをカラフルさによって並べ替え、これらの値に対して最適な連続間隔を選択するものとして問題を処理します。 

チェック関数は、ブール マスクを使用してフィルター処理されたグラフを暗黙的に再構築し、BFS を実行して制約の下で最短パスがまだ存在するかどうかを確認します。 不必要なメモリ オーバーヘッドを避けるために、親ポインタは最後の再構築呼び出しにのみ保存されます。 

微妙な点は、エッジを削除しても距離が増えるだけであるため、フィルタリングされた各 BFS 内のターゲットの長さを再計算するのではなく、元の最短距離と比較する必要があることです。 

## 実用的な例

 ### 例 1

 入力グラフ:

 1-2 (1)、2-4 (5)、1-3 (10)、3-4 (6)

 まず、1 から 4 までの最短距離を計算します。これは、すべての有効な最短ルートでは 2 になります。 

エッジを重み順に並べ替えます: 1、5、6、10。 

間隔をテストします。 

| Ｌ | R | 許可されるエッジ | 最短距離で到達可能 | 結果 |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | (1-2) のみ | いいえ | 失敗 |
 | 1 | 2 | (1-2,2-4) | はい | 有効 |
 | 1 | 3 | (1-2、2-4、3-4) | はい | より良い |
 | 2 | 3 | (2-4,3-4) | いいえ | 失敗 |

 最適な間隔は [1,3] で、最大-最小 = 5-1 = 4 のパス 1-2-4 になります。 

このトレースは、ウィンドウを拡張するとある点までは実現可能性が向上し、その後必要な構造が削除されることを示しています。 

### 例 2

 グラフ:

 1-2 (3)、2-5 (4)、1-3 (100)、3-5 (101)

 最短パスの長さは 2 です。パス 1-2-5 と 1-3-5 は両方とも有効な最短パスです。 

間隔を考慮します。 

| Ｌ | R | パス 1-2-5 | パス 1-3-5 | 実現可能 |
 | --- | --- | --- | --- | --- |
 | 3 | 4 | はい | いいえ | はい |
 | 3 | 101 | はい | はい | はい |

 最適な間隔は [3,101] となり、範囲 101 ～ 3 のパス 1-3-5 を選択します。 

これは、アルゴリズムが最短ホップ制約を尊重しながら色の広がりを最大化するパスを正しく選択していることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(m log m + m * (n + m)) 最悪の場合 | エッジのソートと BFS 実現可能性チェックの繰り返し |
 | スペース | O(n + m) | グラフ ストレージ、BFS 配列、エッジ インデックス |

 BFS 制約により、各実現可能性チェックがエッジにわたって線形時間で実行されることが保証され、スライディング ウィンドウにより実際の冗長なチェックが削減されます。 m が 2e5 までなので、これは一般的なコンテストの制限内に収まります。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、最適な間隔が単一のエッジの重みに崩壊する場合です。 この場合、1 つの色のエッジのみが許可されますが、BFS は最短パスが存在する場合にはそれを正しく検索します。 区間 [L, L] は有効であり、他の区間と同様にチェックされるため、アルゴリズムはこれを自然に処理します。 

もう 1 つのケースは、ホップ数は同じだがエッジ セットが完全に異なる複数の最短パスが存在する場合です。 BFS 実現可能性チェックでは、選択した間隔に完全に含まれるパスのみが寄与することが保証されるため、エッジの誤った混合は発生しません。 より短い色範囲のパスが存在する場合でも、それが最短距離での到達可能性を維持している場合にのみ選択されます。 

最後の微妙なケースは、エッジを削除するとグラフが切断される場合です。 このような場合、BFS は n に無限距離を返し、間隔は拒否されます。 これにより、最短パス制約の下で接続を切断する、実行不可能な色の範囲を誤って受け入れることがなくなります。
