 ## 解決策
 ## 問題の理解

 2 つのシーケンスが与えられています。`a`長さの`n-1`そして`b`長さの`n`。 要素を増やすのが目標です`b`最小の増分を使用して、隣接するすべてのペアに対して`(b_i, b_{i+1})`、それらのビット単位の AND は等しい`a_i`。 増分ごとに要素が 1 ずつ増加し、要素を減らすことはできません。 出力は最小増分数、または`-1`すべての条件を満たすことが不可能な場合。 

制約は厳しいです。 と`n`まで`10^5`と合計`n`すべてのテストケースにわたって、`2*10^5`、線形よりも遅い解`n`遅すぎるでしょう。 すべてのインクリメント シーケンスを試す単純な総当りアプローチは実行不可能です。大規模な場合、操作の数が急速に増加する可能性があるためです。`b_i`そして`a_i`、各要素には最大で`2^29`増加します。 これにより、個々の増分を反復するソリューションは即座に排除されます。 

エッジケースは微妙です。 もし`a_i`ゼロのビットが含まれている場合は、対応するビットの少なくとも 1 つが`b_i`または`b_{i+1}`以前の AND 制約に違反することなく増やすことができます。 不用意なアプローチは貪欲に増加する可能性があります`b_i`合わせる`a_i`それがどのような影響を与えるかを考えずに`b_{i-1} & b_i`。 たとえば、次のように考えてみましょう`a = [1, 0]`そして`b = [0, 0, 0]`。 最初の要素をインクリメントするだけで条件を満たすことができます。`b_1 & b_2 = 1`満足できなくなる可能性があります`b_2 & b_3 = 0`。 

別の特殊なケースが発生する場合`b`すでにいくつかの AND 制約を満たしています。 やみくもに増加させるとオーバーシュートが発生し、操作数が不必要に増加する可能性があります。 

## アプローチ

 ブルート フォース アプローチでは、すべての増分シーケンスが試行されます。`b`全部まで`b_i & b_{i+1} = a_i`所有。 原理的には正しいのですが、異常に遅くなります。 各ペアごとに`(b_i, b_{i+1})`、特定の項目と一致させる必要がある場合`a_i`、増分のすべての組み合わせを試してみます。`b_i`そして`b_{i+1}`。 わずか 30 ビットであっても、可能な増分の数は指数関数的です。 

最適なソリューションを実現するための重要な洞察は、AND 演算が増分に関して単調であるということです。 ビットが 0 の場合`a_i`、その後、少なくとも 1 つ`b_i`または`b_{i+1}`そのビットには 0 がなければなりません。 ビットが 1 インチの場合`a_i`、 両方`b_i`そして`b_{i+1}`そのビットには 1 がなければなりません。 これは、問題を独立して少しずつ解決できることを意味します。 それぞれの最小値を表すことができます。`b_i`すべての制約を満たすために下限として要求されます。 したがって、最小増分数は、単にこの下限と元の境界との差の合計になります。`b_i`。 解は線形です`n`最大 30 ビットにわたってビット単位で動作するため、O(30 * n) 時間がかかります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | ビットごとの貪欲 / DP | O(n * 30) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 0 ～ 29 の各ビット位置について、そのビットが`a_i`設定されているかどうか。 それぞれについて`a_i`、ビットが 1 の場合、両方とも`b_i`そして`b_{i+1}`最終的にはこのビットを設定する必要があります。 ビットが 0 の場合、少なくとも 1 つは`b_i`または`b_{i+1}`このビットを設定解除することもできます。 
2.初期化`min_b[i]`に`b[i]`それぞれに`i`。 これは、インデックスで到達する必要がある最小値を表します`i`増分後。 
3. 反復処理`a`左から右へ。 それぞれについて`i`そして各ビット、もし`a_i`そのビットに 1 があることを確認してください`min_b[i]`そして`min_b[i+1]`どちらも、ビットが設定されている次の値に潜在的に増加することによって、このビットを設定します。 調整で値を減らす必要がある場合は、`b_i`、それは不可能なので戻ります`-1`。 
4. すべてのペアのすべてのビットを処理した後の最小演算数は、すべてのペアの合計です。`i`の`min_b[i] - b[i]`。 
5. テスト ケースに対してこの合計を出力します。 

このアルゴリズムが機能するのは、AND 制約がビットごとに分離できるためです。 各ビットの要件は、関係する要素の下限だけです。 要素の増加は、AND ペアで重複する場合にのみ将来の操作に影響しますが、シーケンスに沿って最小要件を伝播することで、実現可能性が保証されます。 各ビットが必要最小限のレベルに設定されているため、アルゴリズムは増分を過大評価することはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        min_b = b[:]
        possible = True

        for bit in range(30):
            mask = 1 << bit
            for i in range(n - 1):
                if a[i] & mask:
                    if not (min_b[i] & mask):
                        min_b[i] |= mask
                    if not (min_b[i + 1] & mask):
                        min_b[i + 1] |= mask
                else:
                    if (min_b[i] & mask) and (min_b[i + 1] & mask):
                        possible = False
                        break
            if not possible:
                break

        if not possible:
            print(-1)
        else:
            ops = sum(min_b[i] - b[i] for i in range(n))
            print(ops)

solve()
```コードは最初にテスト ケースの数を読み取ります。 それぞれの場合にコピーします`b`の中へ`min_b`、最小の調整値を追跡します。 0 から 29 までの各ビットについて、必要なビット制約を隣接する要素に伝播します。 ゼロビットが入っている場合`a[i]`両方と衝突する`b_i`そして`b_{i+1}`すでに設定されている場合、そのタスクは不可能です。 最後に、増分の合計により最小限の操作が得られます。
