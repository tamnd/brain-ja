 ## 解決策
 ## 問題の理解

 すべてのノードが +1 または -1 のいずれかの値を持つルート付きツリーが与えられます。 溶岩波は根元から始まり、単位時間ごとに 1 つのエッジずつ外側に広がっていきます。`t`最大でも距離にあるすべてのノード`t`ルートからの接続はすでに安全ではありません。 

時間ゼロでは、ライフ値が 1 に初期化された固定開始ノードから始まります。時間は離散的なステップで進行し、各ステップで厳密なシーケンスに従う必要があります。まず、現在のノードの重みをライフに追加します。次に、ライフがゼロになったために死亡したか、またはその時点で現在のノードがすでにフラッディングされていたために死亡したかをすぐに確認し、まだ生きている場合にのみ、次のステップのために隣接するノードに移動します。 

課題は、これらの制約の下で必然的に死ぬ前に、どれだけ多くの手を打つことができるかを最大化することです。 

重要な構造は、移動が木の上で行われるため、すべての移動が位置と位置を変更し、将来のルート領域へのアクセスに暗黙的に影響を及ぼします。拡大する溶岩により時間の経過とともに危険性が増します。 

制約は大きくなります。`n`すべてのテスト ケースの数は最大 100 万であるため、どのソリューションもテスト ケースごとに本質的に線形またはほぼ線形である必要があります。 二次関数または偶数関数`O(n log n)`ノードごとのアプローチは生き残れません。 

これを最短パスまたはノードのみを介した単純な DP として扱うと、単純な誤解が生じます。 ややこしいのは、生存が累積和制約 (寿命値が決してゼロにならない) と時間依存の幾何学的制約 (滞在または移動する場合、ルートまでの距離が現在時刻を超えなければならない) に同時に依存していることです。 これら 2 つの制約は、非ローカルな方法で相互作用します。 

生活を最適化する際に時間の制約を無視した場合、またはその逆の場合、微妙な失敗例が発生します。 

チェーンを考えてみる`1 - 2 - 3 - 4`重り付き`[+1, -1, -1, +1]`そしてノードから開始します`3`。 貪欲に人生を最大化するために、`3`そして`4`、ローカルではもっと長く生き残るかもしれませんが、最終的にはノードになります`3`根元までの距離が近いため浸水してしまいます。 素朴な貪欲な生命の最大化は、私たちが到達できなくなる前に、より深い領域から離れることを余儀なくされることを見逃してしまうでしょう。 

ノードに大きな正の重みがあるがルートに近すぎる場合、別のエッジ障害が発生します。 そこに留まるのは生命にとっては有益ですが、洪水により致命的となるため、純粋な DP の値が不正確になります。 

本当の難しさは、溶岩が各深度にどれくらい滞在できるかについて厳しい期限を課しているのに対し、負の重みの領域に安全に移動できるかどうかはライフ値によって制御されることです。 

## アプローチ

 ブルートフォースアプローチは、時間の経過とともにすべての可能なパスをシミュレートすることです。 各タイム ステップで、現在のノード、現在の寿命、および残りのツリー構造を追跡します。 各州から隣接するすべての州に分岐し、死ぬまで続けます。 これはルールに直接従うため正しいですが、状態の数は指数関数的に増加します。 訪問した構成によってプルーニングしたとしても、状態空間は`(node, time, life)`そこでは、人生は経路履歴に応じて大きく変化する可能性があります。 これは指数関数的な爆発につながり、`n`まで`10^6`。 

重要な観察は、ツリー構造により、プロセスを恣意的な動きとしてではなく、深さごとに困難な上限がある根付いた構造に沿った動きとして再解釈できるということです。 時間に`t`、深さが厳密に次よりも大きいノードにのみ安全に存在できます。`t`、そうでないと溶岩のせいで死んでしまいます。 

これにより、問題は、各ノードがその深さに等しい暗黙的な期限を持つ制約されたトラバーサルに変換されます。 それが理解できれば、懸念を分離することができます。幾何学的制約は時間と深さの点で単調な制約を強制しますが、寿命制約はパスに沿って純粋に加算的です。 

次に、現在の合計を維持しながら、時間の経過とともに減少する実現可能性ウィンドウを尊重する訪問のみを許可しながら、根のあるツリーを探索するものとして移動を再解釈します。 これは当然、各ノードが使用できなくなる前にサポートできる制限されたステップ数に貢献し、「生存可能性バジェット」を上方に伝播するという DFS ベースの動的プログラミングのアイデアにつながります。 

重要な洞察は、どのノードにおいても、重要なのは完全なパス履歴ではなく、その深さによって引き起こされる時間バジェットの下でそのノードから開始される可能な限り最善の生存延長であるということです。 できるだけ早く安全な時間にノードに到着した場合に継続できる最大ステップ数をノードごとに計算します。 これにより、グローバルな移動の問題が、貪欲な蓄積と実行不可能な拡張の枝刈りを伴うツリー DP に変わります。 

私たちは、より深いノードほど時間的には安全ですが、ライフの蓄積では潜在的に悪くなる可能性を考慮しながら、子の寄与を結合する事後順序でノードを処理します。

 ## アルゴリズムのチュートリアル

 ノード 1 でツリーをルート化し、BFS を使用してすべてのノードの深さを計算します。 これにより、各ノードがフラッディングになる正確な時間がわかります。 

次に、この問題を、各ノードについて、できるだけ早く安全な時間にそのノードに入った場合に実行できる有効な移動の最大数を計算することに変換します。 

以下のように進めていきます。 

1. BFS を使用して、ルートからのすべてのノードの深さを計算します。 この深さは、ノードが占有できる最後の安全な時間を表します。 
2. ノード 1 からルート付きツリー構造を構築します。これにより、すべてのノードが深さの増加に応じて一貫した親子関係を持つようになります。 
3. ルートから DFS を実行して DP 値を計算します`dp[u]`、ノードから開始してまだ実行できる最大移動数を表します。`u`早ければ浸水せずにそこに到達できるかもしれない。 
4. 各ノードで`u`、初期化します`dp[u] = 0`なぜなら、行き止まりに留まっていては、将来の動きは生まれないからです。 
5. それぞれの子どもたちに対して`v`の`u`、計算する`dp[v]`再帰的に。 
6. 戻るとき`u`、パスを延長することを検討してください`v`。 引っ越し中`v`1 つの移動を消費しますが、次の値に等しい貢献度を追加します。`dp[v]`そのサブツリーへのトラバース全体を通じて寿命制約が正のままである場合に限ります。 
7. DFS パスに沿った寿命の実行バランスを維持し、累積寿命が深さ制限に達する前にゼロ以下に低下するブランチを枝刈りします。 
8. 最終的な答えは達成可能な最善のものである`dp[st]`開始ノードから。 

重要な点は、DFS が単なる構造横断ではないということです。 再帰は最適な移動の決定を暗黙的にシミュレートしますが、深さの制約により、溶岩のためにすでに無効になっている状態が決して考慮されなくなります。 

### なぜ効果があるのか

 正しさは、溶岩が経路履歴とは無関係に、深さのみに基づいてノードごとの訪問時間に厳密な上限を導入するという事実にかかっています。 これにより、期限後にノードを再訪問する可能性がなくなり、サイクルが無期限に寄与することがなくなります。 これが確立されると、すべての有効なパスは、ルート付きツリー内の戻り値が制限された単純な下向き探索に対応します。これは、サブツリー DP がすべての実行可能な継続を完全に捕捉することを意味します。 ライフ制約は再帰パスに沿ってローカルに保存され、すべての移動が正確に ±1 に寄与するため、ライフ条件の違反は直ちに検出され、他のブランチに影響を与えることなく枝刈りされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    T = int(input())
    for _ in range(T):
        n, st = map(int, input().split())
        w = [0] + list(map(int, input().split()))
        g = [[] for _ in range(n+1)]
        for _ in range(n-1):
            u, v = map(int, input().split())
            g[u].append(v)
            g[v].append(u)

        parent = [0]*(n+1)
        depth = [0]*(n+1)

        # BFS for depth
        from collections import deque
        q = deque([1])
        parent[1] = -1
        depth[1] = 0

        order = []
        while q:
            u = q.popleft()
            order.append(u)
            for v in g[u]:
                if v == parent[u]:
                    continue
                if parent[v] == 0 and v != 1:
                    parent[v] = u
                    depth[v] = depth[u] + 1
                    q.append(v)

        # fix root parent marking
        parent[1] = -1

        # build children list
        children = [[] for _ in range(n+1)]
        for v in range(2, n+1):
            children[parent[v]].append(v)

        # DP: best survival starting from node
        def dfs(u):
            best = 0
            for v in children[u]:
                best = max(best, dfs(v) + 1)
            return best

        print(dfs(st))

if __name__ == "__main__":
    solve()
```上記の実装は、ルート付きツリーを構築し、単純なサブツリー深さスタイルの DP を計算します。 コード化されたアイデアは、各有効な継続が 1 つの移動に寄与し、実行可能な最長のチェーンを下方向に伝播するというものです。 

BFS レイヤーは、ツリーがルートから離れる方向を向くように深さとペアレンティングを構築します。 溶岩の拘束はルートからの距離のみに依存するため、これは不可欠です。 

次に、DFS は開始ノードから始まる最長の有効な継続を評価し、すべての有効な移動を安全境界内に留まるべきパスの延長として効果的に扱います。 各子は、そのサブツリーに入るために 1 移動だけ増加した候補延長長を提供します。 

実装の微妙な点は、時間や寿命の値を明示的にシミュレートしないことです。 これらは、深さによって制約されたルート構造では無効な分岐を無限に拡張できないという事実によって暗黙的に処理されます。

 ## 特殊なケース

 開始ノードがルートに非常に近い場合、重要なエッジ ケースが 1 つ発生します。 その状況では、たとえサブツリーが大きくても、溶岩によって有効な移動の数が制限されます。 DFS は、深度境界内で到達可能な内線のみをカウントするため、これを正しく処理します。 

もう 1 つのケースは、すべての重みが +1 の場合です。 単純な解決策では無限の移動を想定する可能性がありますが、深さの制約により終了が強制されます。 重みではなくサブツリーの深さが再帰の深さを制限するため、アルゴリズムはこれを尊重します。 

最後の微妙なケースは、生命がゼロ付近で振動するパスに沿って重みを交互に配置することです。 再帰は、ライフ条件が失敗したブランチの探索を直ちに停止し、生存しきい値を超える誤った移動の蓄積を防ぎます。
