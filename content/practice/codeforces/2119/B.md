 ## 解決策
 ## 問題の理解

 平面上には、出発地と目的地という 2 つの固定点が与えられます。 一連の移動長も受け取ります。 ステップで`i`、現在位置から、現在位置からのユークリッド距離が正確に一致する任意の点に移動する必要があります。`a_i`。 方向は完全に自由ですが、距離は固定です。 

すべての動きを実行した後、目標点に正確に着地できるかどうかを知りたいと考えています。 

主な難点は、各移動が方向に連続的な自由を導入するため、各ステップ後の到達可能なポイントのセットが単一のポイントではなくディスクの境界になることです。 複数のステップを経た後、到達可能な領域は、固定長セグメントのすべての可能なベクトル和によって定義される成長する幾何学的形状になります。 

制約は非常に具体的な意味で重要です。 すべてのテスト ケースにわたる操作の合計数は最大 2 · 10^5 であるため、ジオメトリを明示的にシミュレートしたり、点のセットを保存したりするアプローチは不可能です。 ポリゴンを維持したり方向をサンプリングしたりするだけでも遅すぎます。 

自然な失敗モードは、方向の選択について貪欲に考えることから生じます。 たとえば、常にターゲットに向かって照準を合わせようとすると、初期の選択によって後の動きが最終距離をオーバーシュートまたはアンダーシュートする可能性があるため、失敗する可能性があります。 もう 1 つの失敗は、合計のみが重要であると仮定し、キャンセル効果を無視していることです。 

たとえば、開始点と終了点の間の距離だけをすべての合計と比較すると、`a_i`、次のように言うかもしれません。 

- 距離 ≤ 合計の場合、はい

 これは間違いです。 考慮する：```
start = (0,0), end = (1,0)
a = [2, 2]
```合計は 4 なので、素朴なロジックでは到達可能と言えますが、実際には距離 1 で終了することはできません。これは、長さ 2 の 2 つのセグメントは [0,4] の距離にしか到達できませんが、ベクトル合成にはパリティのような制約があるためです。 

正しい解決策は、全長だけでなく、セグメント間のキャンセルがどの程度可能かにも依存します。 

## アプローチ

 ブルートフォース解釈では、各移動後に到達可能なすべての位置の完全なセットを追跡します。 ステップ後`i`、到達可能なすべての点は、前の各点を中心とする半径の円に拡張されます。`a_i`。 これはすぐに連続領域になり、その境界はますます複雑になります。 実際には、その後の到達可能な領域は、`i`ステップは、半径がセグメントの長さの全体構造にのみ依存する円盤ですが、これを幾何学的に導出するには、やはりミンコフスキー和を理解する必要があります。 明示的なシミュレーションは不可能です。 

重要な観察は、重要な唯一の不変条件は、スタートからの最終距離の可能な範囲であるということです。 各セグメントの後に、事実上、固定長だが方向は任意のベクトルを追加していることになります。 これにより、すべての移動後の原点からの可能な最小距離と最大距離を追跡するという問題が軽減されます。 

逆に考えると、すべてのセグメントの後、始点に対する終点は固定された大きさのベクトルの合計になります。 このようなすべての合計のセットは、最小値と最大値の間のすべての距離である円環を形成します。 

最大距離は簡単です。すべてのセグメントを同じ方向に揃えると、次のようになります。```
max_dist = sum(a_i)
```最短距離はキャンセルにより異なります。 1 つのセグメントが他のセグメントに比べて大きすぎる場合、そのセグメントを完全にキャンセルすることはできません。 何も並べ替えずに直接推論した場合、達成可能な最小距離は次のようになります。```
min_dist = max(0, 2 * max(a_i) - sum(a_i))
```これは、最大のセグメントを除くすべてのセグメントがそれに反対できるという考えから来ています。 最大のセグメントが他のすべてのセグメントの合計よりも大きい場合、超過部分が残ります。 

到達可能な間隔がわかったら`[min_dist, max_dist]`の場合、問題は、開始点と終了点の間の実際の距離がその内側にあるかどうかを確認することになります。 

させて：```
D = distance between start and end
```次の場合は「はい」と答えます。```
min_dist ≤ D ≤ max_dist
```| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースジオメトリ | 指数関数 / 連続関数 | 大 | 遅すぎる |
 | 距離の間隔 | テストあたり O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 次に、その推論を具体的な手順に変換します。 

1. 開始点と終了点の間の二乗ユークリッド距離を計算します。 後で二乗値を比較することで平方根を回避します。 
2. すべてのセグメントの長さの合計を計算します。 これは、すべての動きが同じ方向に揃っている場合に到達可能な最も遠い距離を表します。 
3. セグメントの最大長を特定します。 これにより、他のセグメントが完全にキャンセルできるかどうかが決まります。 
4. 以下を使用して、可能な最小最終距離を計算します。```
min_dist = max(0, 2 * max_a - sum_a)
```これにより、最適なキャンセル後に残った「アンバランスな」長さがキャプチャされます。 
5. 目標距離と間隔を比較する`[min_dist, sum_a]`。 内側にある場合は「Yes」を出力し、内側にない場合は「No」を出力します。 

これが機能する理由は、到達可能なエンドポイントが連続した距離範囲を形成しているためです。 セグメントの方向を継続的に回転させて極端な構成間を補間できるため、最小値と最大値の間の任意の値を実現できます。 ベクトル和の幾何学的形状により、この間隔内にギャップがないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        px, py, qx, qy = map(int, input().split())
        a = list(map(int, input().split()))
        
        total = sum(a)
        mx = max(a)
        
        dx = px - qx
        dy = py - qy
        dist_sq = dx * dx + dy * dy
        
        min_dist = max(0, 2 * mx - total)
        
        # compare squared distances to avoid sqrt
        if min_dist * min_dist <= dist_sq <= total * total:
            print("Yes")
        else:
            print("No")

if __name__ == "__main__":
    solve()
```実装は派生間隔チェックの直後に行われます。 唯一の微妙な点は、浮動小数点エラーを回避するために二乗距離を使用することです。 最小距離と最大距離は線形時間で計算されます。 

表現`2 * mx - total`単一のセグメントが支配的でない場合、キャンセルにより変位を完全に除去できるため、 はゼロにクランプされます。 最終チェックは純粋にインターバルメンバーシップテストです。

 ## 特殊なケース

 すべてのセグメントの長さが同一で、ターゲットが同じ点である場合、キャンセルにより完全に原点に戻ることができます。 アルゴリズムは計算します`max_a = total / n`、与える`min_dist = 0`したがって、距離がゼロのターゲットはすべて受け入れられます。 

セグメントが 1 つだけの場合、到達可能なセットはまさに半径の円になります。`a1`。 式は次のようになります。`min_dist = max_dist = a1`、つまり正確な距離を指すだけです`a1`ジオメトリを正確に一致させて受け入れられます。 

1 つのセグメントが他のすべてのセグメントを支配する場合:`[10,1,1]`の場合、最小距離は正になります。 アルゴリズムはこれを次のように捉えます`2 * 10 - 12 = 8`これは、最終位置が開始からの距離 8 よりも近づくことができないことを意味し、最長移動の削減不可能な超過を反映しています。
