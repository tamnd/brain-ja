 ## 解決策
 ## 問題の理解

 サイズの隠された順列が与えられています$n$, しかし、私たちはそれを直接見ることはありません。 代わりに、その順列からの 3 つの要素の連続するブロックをすべて確認します。 次に、各ブロックが内部でスクランブルされ、すべてのブロックが相互にシャッフルされます。 

したがって、入力は次のマルチセットです$n-2$順序付けされていないトリプル。 各トリプルはもともと同じ順列の 3 つの連続した位置から来ていますが、各トリプル内の順序とトリプルの順序の両方が失われます。 

タスクは、まさにこのトリプルのコレクションを生成する可能性のある置換を再構築することです。 

制約$n \le 10^5$つまり、候補の順列をテストしたり、指数関数的再構成を使用したりすることはできません。 本質的に線形または線形に近い動作が必要です。$O(n \log n)$または$O(n)$は許容されますが、ペアまたは順列に対する二次推論は許容されません。 

微妙な点は、すべての値が個別であるため、すべての数値が隠れた順列内の 1 つの位置に正確に対応することです。 これにより、問題は、マルチセットの曖昧さではなく、隣接制約に基づいた再構成タスクに変わります。 

各トリプルが順序付けされていると仮定すると、1 つの故障モードが表示されます。 たとえば、トリプルを固定順序として扱うと、存在しない隣接関係が誤って強制されてしまいます。 もう 1 つの失敗モードは、エンドポイントを識別せずにトリプルを貪欲にステッチしようとすることです。これにより、チェーンの途中で矛盾が発生する可能性があります。 トリプルは元の構造ではちょうど 2 つの要素で重複しますが、順序が失われるため、単純なマージでは簡単に誤って分岐する可能性があります。 

## アプローチ

 直接的な総当りのアイデアは、各トリプルを可能な順序付けられたシーケンスとして扱い、バックトラッキングによって順列を再構築しようとすることです。 各トリプルについて、1 つの順序を選択し、それを他の順序に並べて、重複の一貫性をチェックすることができます。 各トリプルには$3! = 6$内部発注もあり、$n-2$3 倍になると、巨大な検索スペースが作成されます。 トリプルの順列を無視しても、これは次のようになります。$6^{n}$最悪の場合は可能ですが、それは完全に不可能です。 

重要な観察は、順序は失われますが、隣接情報は依然として暗黙的に保持されていることです。 元の順列では、各内部要素はちょうど 2 つのトリプルに現れますが、エンドポイントは 1 つだけ現れます。 つまり、頻度を数えることによってエンドポイントを回復できるということです。一度だけ現れる 2 つの数値が順列の終わりです。 

エンドポイントを修正したら、チェーンを繰り返し拡張することで残りの順列を再構築できます。 重要な構造上の事実は、各トリプルが長さ 3 のスライディング ウィンドウをエンコードしているため、有効な再構成では、すべての連続するペアが少なくとも 1 つのトリプルに一緒に現れることを満たさなければなりません。 これにより、問題はローカル制約によって定義されたパスに沿って歩くことになり、すでに使用されている要素によって曖昧さが取り除かれます。 

ブルートフォースとこのアプローチの違いは、トリプルの組み合わせ順序付けを、次数制約と局所的一貫性によって駆動される決定論的なグラフのような再構成に置き換えることです。

 ## アルゴリズムのチュートリアル

 この問題を、どの値がどのトリプルに現れるか、そしてそれらがどのくらいの頻度で現れるかを追跡することに変換します。 

1. すべてのトリプルにわたって各数値の出現を数えます。 内部要素はちょうど 2 つのトリプルで出現するのに対し、エンドポイントは 1 回出現するため、これによりエンドポイントが識別されます。 これは、すべての内部位置が正確に 2 つのスライディング ウィンドウに寄与するため機能します。 
2. 頻度 1 の 2 つの数値を特定します。これらは順列の最初と最後の要素でなければなりませんが、順序はまだわかっていません。 
3. 開始点として 1 つのエンドポイントを選択します。 この時点から、左から右への順列を再構築します。 
4. 前処理: 各数値について、どのトリプルにその数値が含まれているかを保存します。 これにより、シーケンスを拡張するときに候補となるトリプルをすばやく見つけることができます。 
5. 順列を段階的に構築します。 最初のエンドポイントから開始し、現在のペア コンテキストを含むトリプルを使用して次の番号を繰り返し検索します。 具体的には、連続する 2 つの数値を取得した場合、次の要素は、両方を含むトリプルの 3 番目の要素でなければなりません。 
6. 各ステップで、一致するトリプルから未使用の要素を選択します。 構造は有効なチェーンを形成することが保証されているため、未使用の候補が 1 つだけ存在します。 
7.すべて終わるまで続けます$n$要素が配置されます。 

再構成は基本的に、長さ 3 のウィンドウからの重なり合う制約によって各ステップが決定される固有のパスをたどることになります。 

### なぜ効果があるのか

 順列内の各内部要素は正確に 2 つの連続するトリプルに属し、エンドポイントは 1 つに属します。 これにより、トリプルの暗黙的なハイパーグラフにパスのような構造が強制されます。 エンドポイントが固定されると、周波数制約に違反することなく現在のウィンドウを一貫して拡張できるのは 1 つのトリプルだけであるため、連続する要素の各ペアは次の要素を一意に決定します。 これにより、分岐が防止され、すべての要素を 1 回だけカバーする単一の一貫した走査が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    triples = []
    
    freq = [0] * (n + 1)
    where = [[] for _ in range(n + 1)]
    
    for i in range(n - 2):
        a, b, c = map(int, input().split())
        triples.append((a, b, c))
        for x in (a, b, c):
            freq[x] += 1
            where[x].append(i)
    
    ends = [i for i in range(1, n + 1) if freq[i] == 1]
    
    adj = {}
    for i, (a, b, c) in enumerate(triples):
        arr = [a, b, c]
        for x in arr:
            for y in arr:
                if x != y:
                    adj.setdefault(x, []).append(y)
    
    # pick first endpoint
    start = ends[0]
    
    used = [False] * (n - 2)
    used_v = [False] * (n + 1)
    
    res = [start]
    used_v[start] = True
    
    if n == 1:
        print(start)
        return
    
    # choose second element
    nxt = None
    for v in adj.get(start, []):
        nxt = v
        break
    
    res.append(nxt)
    used_v[nxt] = True
    
    for _ in range(n - 2):
        a, b = res[-2], res[-1]
        candidates = set()
        for ti in where[a]:
            if used[ti]:
                continue
            x, y, z = triples[ti]
            if b in (x, y, z):
                candidates.update([x, y, z])
                break
        for v in candidates:
            if not used_v[v]:
                res.append(v)
                used_v[v] = True
                break
    
    print(*res)

if __name__ == "__main__":
    solve()
```コードは、エンドポイントを検出するために発生回数をカウントすることから始まります。 次に、トリプルから補助的な隣接構造を構築します。これは、1 つのエンドポイントから最初の方向を選択するのに役立ちます。 

再構築フェーズでは、トリプルの使用済み配列と値の使用済み配列を維持します。 各ステップで、最後に選択した 2 つの要素を含むトリプルを検索し、3 番目の未使用の値を抽出します。 構造の一貫性が保証されているため、この検索は曖昧さなく常に成功します。 

実装の微妙な詳細は、順列に既に配置されている数値を決して再利用しないようにすることです。 もう 1 つは、グローバル検索ではなく、現在のペアを含むトリプルからのローカル整合性のみが必要であることです。

 ## 特殊なケース

 重要なエッジ ケースは、再構築の初期段階で複数のトリプルに重複するペアが含まれる場合です。 このような場合、「未使用要素」制約を適用しない単純な貪欲選択では、間違った拡張子が選択される可能性があります。 アルゴリズムは、使用されている値をマークし、候補を未使用の要素のみに制限することでこれを回避します。 

もう 1 つのエッジ ケースは、エンドポイントが高周波の内部ノードも含むトリプルで表示される場合です。 周波数分析を行わないと、中間要素を開始点として誤って選択してしまい、曖昧な分岐が発生する可能性があります。 頻度 1 ルールは、真のエンドポイントを確実に分離します。 

最後に、トリプルが任意の順序で処理される場合、単純な隣接グラフは複数の次の候補を示唆する可能性があります。 スライディング ウィンドウ構造により、各ステップで有効な未使用の拡張子が 1 つだけ保証されるため、入力トリプルの激しいスクランブル下でも不整合が防止されます。
