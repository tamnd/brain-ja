 ## 解決策
 ## 問題の理解

 この問題では、配列内の位置の順序付きペアをすべて調べて、選択した 2 つの値の合計を計算するように求められます。 ペア`(i, j)`とは異なります`(j, i)`、つまり、まさにあります`N²`可能な金額。 を見つける必要があります。`K`これらすべての合計の中で - 番目に小さい値。 

入力には複数のテスト ケースが含まれています。 テスト ケースごとに、配列のサイズ、目的の位置を受け取ります。`K`ペアの合計のソートされたリストと配列自体。 出力は、position に表示される値です。`K`すべてのペアの合計を明示的に生成して並べ替えた場合。 

ハードバージョンでは、`N`到達する`100000`そして`K`と同じ大きさにすることができます`N²`。 直接構築するには、最大 100 億の金額を作成する必要がありますが、これは記憶や時間に収まる範囲をはるかに超えています。 すべてのペアをチェックするだけでも時間がかかります`O(N²)`操作と`N = 100000`それは約です`10^10`ペアチェックを行うため、どのソリューションでもペアの列挙を避ける必要があります。 

値は負の値にすることも、次のように大きくすることもできます。`10^9`絶対値で言うと。 これは、答えが次のように小さくなる可能性があることを意味します`-2 * 10^9`または同じ大きさ`2 * 10^9`, そのため、検索空間は二分探索には十分小さいです。 テストケースの数も少ないため、`O(N log C)`スタイル ソリューション、ここで`C`は値の範囲です。 

いくつかの特殊なケースでは、より単純な実装が壊れる可能性があります。 考慮する：```
1
2 4
1 1
```4つの合計は、`2, 2, 2, 2`、したがって、答えは次のとおりです`2`。 とのペアのみを考慮する方法`i < j`この問題では順序付けされたペアがカウントされるため、誤って 1 つのペアのみが認識され、失敗します。 

別のケースは次のとおりです。```
1
3 2
-5 0 10
```合計は`-10, -5, 5, -5, 0, 10, 5, 10, 20`。 2番目に小さいのは、`-5`。 配列がすでにソートされていることを前提とし、最初にソートせずに位置で二分検索を使用する実装では、誤ってカウントされる可能性があります。 

最後の厄介なケースは次のとおりです。```
1
3 7
1 2 100
```ソートされた合計は次のとおりです`2, 3, 3, 4, 101, 101, 102, 102, 200`、したがって、答えは次のとおりです`102`。 よくある間違いは、候補値以下ではなく、厳密に小さい合計を持つペアをカウントすることです。これにより、等しい合計が多数存在する場合、バイナリ検索の結果がシフトします。 

## アプローチ

 簡単なアプローチは、考えられるすべてのカップルを生成することです。 あらゆるインデックスに対して`i`、ペアリングできます`a[i]`あらゆるものと`a[j]`、 店`a[i] + a[j]`、結果のリストをソートし、位置の要素を返します。`K`。 

これは、問題で説明されている正確なマルチセットを文字通り作成するため、正しいです。 ただし、必要なのは`N²`記憶と`N² log(N²)`仕分けの時間。 と`N = 100000`、生成される合計の数は`10^10`, したがってアプローチは不可能です。 

重要な観察は、実際にソートされた合計のリストが必要ないということです。 私たちが知る必要があるのは、どこにあるのかだけです。`K`-番目の値は存在します。 「X 以下のペアの合計はいくつありますか?」という質問に答えることができれば、最小のものを二分探索することができます。`X`カウントが到達する人`K`。 

元の配列をソートすると、カウントが効率的になります。 最初の要素ごとに`a[i]`、を満たす 2 番目の要素がいくつあるかを知る必要があります。```
a[i] + a[j] <= X
```これは以下と同等です:```
a[j] <= X - a[i]
```配列はソートされているため、有効な数は`j`値は上限二分探索で見つけることができます。 これらのカウントをすべて合計すると、`i`以下のペアの合計の数を与える`X`。 

ブルート フォースは順序付きリストを直接構築するため機能しますが、次の場合には失敗します。`N`大きいです。 値の検索とソートされた配列を使用した高速カウントによって答えが見つかるという観察により、問題はテスト ケースごとに数十億のペアから約 100 万の操作に減少します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N² log N) | O(N²) | 遅すぎる |
 | 答えの二分探索 | O(N log N log A) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列をソートします。 順序付けにより、二分探索を使用してしきい値を下回る要素の数をカウントできるようになります。 
2. 答えの二分探索範囲を設定します。 可能な最小のペアの合計は、最小の要素とそれ自体の合計であり、最大の可能なペアの合計は、最大の要素とそれ自体の合計です。 
3. 中間値の場合`mid`、最大で合計が得られる順序ペアの数を計算します。`mid`。 あらゆる人にとって`a[i]`、最大のインデックスを見つけます`j`どこ`a[j] <= mid - a[i]`。 有効な 2 番目の位置の数は、そのインデックスまでの要素の数になります。 
4. カウントが少なくとも`K`、答えは最大でも`mid`, そこで検索範囲を左半分に移動します。 それ以外の場合は、合計が少なすぎると十分小さいため、右半分に移動します。 
5. 検索間隔に値が 1 つ含まれる場合、その値は、ペアの和の数が少なくとも`K`。 

count 関数が機能する理由は、すべての順序付きペアが 1 つの固定の最初の位置を選択するためです。 その位置について、ソートされた配列は、2 番目の位置の選択肢がいくつあれば合計が十分に小さくなるかを正確に示します。 これらの独立したカウントを追加すると、すべてがカバーされます`N²`ペアを正確に 1 回注文しました。 

## Python ソリューション```python
import sys
from bisect import bisect_right

input = sys.stdin.readline

def solve_case(n, k, a):
    a.sort()

    def count_leq(x):
        total = 0
        for v in a:
            total += bisect_right(a, x - v)
        return total

    low = a[0] + a[0]
    high = a[-1] + a[-1]

    while low < high:
        mid = (low + high) // 2
        if count_leq(mid) >= k:
            high = mid
        else:
            low = mid + 1

    return low

def main():
    t = int(input())
    ans = []

    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        ans.append(str(solve_case(n, k, a)))

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    main()
```後のすべての操作は順序付けされる要素に依存するため、このソリューションでは最初に配列を並べ替えます。 の`count_leq`関数は、ウォークスルーからの核となる観察を実装します。 考えられる最初の要素ごとに、`bisect_right`すべての有効な 2 番目の要素の後の最初の位置を返すため、返されるインデックスは有効な選択肢の数と正確に一致します。 

二分探索では、可能な答えの包括的な範囲が使用されます。 Python では整数の除算は切り捨てられるため、中点の計算は負の値であっても正しく機能しますが、更新ルールでは、答えが区間内にとどまるという不変条件が維持されます。 

よくある実装上の間違いは、`bisect_left`の代わりに`bisect_right`。 候補以下の合計をカウントするため、カウントには制限に等しい値が必要です。 間違った境界を使用すると、有効なペアが無視され、二分探索が右端に移動しすぎる可能性があります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N log N + N log N log A) | ソートのコストは O(N log N) です。 各二分探索反復は O(N log N) でカウントされ、回答範囲は値によって制限されるため、反復回数は約 32 回になります。 |
 | スペース | O(N) | ソートされた配列と一時変数のみが保存されます。 |

 最大`N`は二次アルゴリズムが失敗するほど十分に大きいですが、対数因数により演算の総数は管理可能に保たれます。 答えの範囲はわずか数十億個の値であるため、外側の二分探索は小規模です。

    def solve_case(n, k, a):
        a.sort()

        def count_leq(x):
            total = 0
            for v in a:
                total += bisect_right(a, x - v)
            return total

        high = a[-1] + a[-1]

            else:
                low = mid + 1
        return low

    t = int(input())
    res = []
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        res.append(str(solve_case(n, k, a)))
    return "\n".join(res)

 ## 特殊なケース

 単一要素の場合:```
1

7
```可能なペアは次のとおりです。`(1,1)`、合計を与える`7`。 ソートされた配列には 1 つの値が含まれており、両方の二分探索境界は`7`したがって、アルゴリズムはすぐに正しい結果を返します。 

繰り返される値の場合:```
1
3 9
5 5 5
```注文したペアごとに、`10`。 カウント中、以下のすべての検索しきい値`10`ペアはゼロですが、`10`9 つのペアすべてが得られます。 二分探索により、最初に到達するしきい値が見つかります。`K`。

```可能な最小の合計は、それ自体に追加される最初の要素です。`-2000000000`。 答えの検索はまさにそこから始まるため、負の数に対する特別な処理は必要ありません。

1
3 7
1 2 100
```7 番目に小さい合計は`102`。 カウント関数は中間点以下の値をカウントするため、等しい合計を正しく処理します。 中間点の場合`102`の場合、7 つの有効なペアすべてがカウントされるため、二分探索ではこの値を超えずにこの値が保持されます。
