 ## 解決策
 ## 問題の理解

 このタスクでは、配列内の順序付けされた位置のペアをすべて調べるように求められます。 ペア用`(i, j)`、選択した 2 つの要素を加算して値を形成します。 がある`N²`最初の位置と 2 番目の位置の選択は独立した選択であるため、このような値が使用されます。 を見つける必要があります。`K`これらすべてのペアの合計の中で 2 番目に小さい値。 

簡単なバージョンでは、`N`最大 500、テスト ケースは 20 までです。 これは直接的なことを意味します`O(N²)`このアプローチでは、テスト ケースごとにすでに約 250,000 の操作が行われており、これは許容範囲内です。 ただし、すべてを並べ替えるなどの余分な作業を追加すると、`N²`合計すると、作成された値の数も 250,000 になり、ソートはまだ問題ありません。 意図された解決策は、通常、すべてを具体化するのではなく、ペアの合計の特別な構造を使用することです。これは、より大きなバリアントにも使用されるテクニックを教えるためです。 

配列内の値は次のように大きくできます。`10^9`絶対値で答えられるので、`2 * 10^9`。 ソリューションでは、これらの値を安全に保持できる整数型を使用する必要があります。 Python の整数はこれを自動的に処理します。 

最初のトリッキーなケースは次のような場合です。`K`重複した合計を指します。 例えば：```
1
3 4
1 1 5
```ペアの合計は次のとおりです。```
2 2 6
2 2 6
6 6 10
```正しい答えは、`6`4 番目に小さい値。 一意の合計のみを保存するソリューションでは、誤った値が返されます。`10`。 

別のエッジ ケースが負の値で表示されます。```
1
2 2
-5 -1
```合計は`-10, -6, -6, -2`、したがって、答えは次のとおりです`-6`。 答えが正であると仮定したり、その境界が間違って初期化されたりする二分探索は、ここでは失敗します。 

## アプローチ

 簡単なアプローチは、考えられるすべてのカップルを生成することです。 あらゆるインデックスに対して`i`、すべてのインデックスを試します`j`そして追加します`a[i] + a[j]`リストに追加します。 全部生成したら`N²`合計すると、リストをソートし、その位置の要素を取得します`K - 1`。 

これが機能するのは、並べ替えによって合計の完全なマルチセットが正確に必要な順序で配置されるためです。 問題は、大規模な中間配列を作成し、ソートコストを支払うことです。 生成される値の数は`N²`、それらを整理するにはコストがかかります`O(N² log(N²))`。 簡単な制限の場合はこれで問題ありませんが、制約が大きくなるとうまく拡張できなくなります。 

解決策を改善する観察は、元の配列をソートした後、「X 以下のペアの合計はいくつありますか?」という別の質問に答えることができることです。 これにすぐに答えることができれば、少なくとも K 個の合計を含む最小の X を二分探索できます。 

固定値の場合`X`、ソートされた配列を考えてみましょう。 左側の要素ごとに`a[i]`、すべての有効なパートナーは、実装に応じてサフィックスまたはプレフィックスを形成します。 配列はソートされているため、2 つのポインターを使用できます。 Starting from the largest index on the right, if`a[i] + a[j]`より大きい`X`、私たちは移動します`j`左。 有効になると、からのすべてのインデックスが`0`に`j`も有効です。`j + 1`可能性のあるパートナー。 

ブルート フォースは、可能なすべての合計を明示的に確認するため機能します。 並べ替えられた順序により一度に多くの合計をカウントできるため、より高速な方法が機能します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N² log(N²)) | O(N²) | 簡易バージョンとして受け入れられます |
 | 答えの二分探索 | O(N log V + N log N) | O(1) おまけ | 承認済み |

 ここ`V`可能な答えの範囲、約`2 * 10^9`したがって、二分探索には約 31 回の反復が必要です。 

## アルゴリズムのチュートリアル

 1. 配列をソートします。 ソート順を使用すると、すべてのペアをチェックしなくても、合計が選択した値を下回るペアがいくつあるかを数えることができます。 
2. 二分探索範囲を最小のペア合計から最大のペア合計までに設定します。 可能な最小の合計は最小の 2 つの要素から作成され、可能な最大の合計は最大の 2 つの要素から作成されます。 
3. 現在の中間値について`mid`、注文されたペアの数を数えます`(i, j)`満足する`a[i] + a[j] <= mid`。 
4. 効率的に数を数えるには、ポインタを保持してください`j`ソートされた配列の末尾から開始します。 あらゆる人にとって`i`、 減少`j`一方、現在のペアは大きすぎます。 一度`a[i] + a[j]`有効です。からのすべてのインデックス`0`に`j`で動作します`i`ので、追加します`j + 1`カウントに。 
5. カウントが少なくとも`K`、答えは次のようになります。`mid`以下の場合は、二分探索の右境界を下に移動します。 それ以外の場合は、合計が十分に小さくないため、左の境界を上に移動します。 
6. 検索が終了すると、左の境界は少なくとも次の値を持つ最小値になります。`K`ペアの合計がそれを超えないこと。 

機能する理由: カウント関数は単調です。 値の場合`X`少なくとも`K`合計がそれを超えない場合、より大きな値には少なくとも次の値が含まれます。`K`合計。 以下の場合は、`K`、より小さい値はすべて、次の値よりも少なくなります。`K`。 二分探索では、条件が true になる最初の値が見つかります。これはまさに`K`- 番目に小さい合計。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    a.sort()

    def count_pairs(x):
        res = 0
        j = n - 1
        for i in range(n):
            while j >= 0 and a[i] + a[j] > x:
                j -= 1
            res += j + 1
        return res

    left = a[0] + a[0]
    right = a[-1] + a[-1]

    while left < right:
        mid = (left + right) // 2
        if count_pairs(mid) >= k:
            right = mid
        else:
            left = mid + 1

    return str(left)

def main():
    t = int(input())
    ans = []
    for _ in range(t):
        ans.append(solve_case())
    print("\n".join(ans))

if __name__ == "__main__":
    main()
```カウント関数は単調順序に依存するため、配列が最初にソートされます。 並べ替えを行わないと、ポインタを移動しても、考えられるすべてのパートナーが表示されるわけではありません。 

の`count_pairs`関数はポインタを維持します`j`スキャン中は左にのみ移動します。 これがカウントの理由です`O(N)`の代わりに`O(N²)`。 の値`j`新しいたびにリセットされることはありません`i`。 

二分探索では、`left < right`位置ではなく値を探しているため、インデックスを検索するのではありません。 最終的な値は、`left`少なくとも次の値が含まれる最初の合計しきい値です。`K`ペア。 

境界は、実際の最小値と最大値の合計から計算されます。 これにより、負の数が正しく処理され、入力範囲に関する仮定が回避されます。

## テストケース```python
import sys
import io

def solution(data):
    sys.stdin = io.StringIO(data)
    input = sys.stdin.readline

    def solve_case():
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        a.sort()

        def count_pairs(x):
            res = 0
            j = n - 1
            for i in range(n):
                while j >= 0 and a[i] + a[j] > x:
                    j -= 1
                res += j + 1
            return res

        l, r = a[0] + a[0], a[-1] + a[-1]
        while l < r:
            m = (l + r) // 2
            if count_pairs(m) >= k:
                r = m
            else:
                l = m + 1
        return str(l)

    t = int(input())
    out = []
    for _ in range(t):
        out.append(solve_case())
    return "\n".join(out)

""") == "4"

 ## 特殊なケース

 重複の場合:```
1
3 4
1 1 5
```ソートされた配列はそのまま残ります`[1, 1, 5]`。 ソートされた順序でのペアの合計は次のとおりです。`2, 2, 2, 2, 6, 6, 6, 6, 6`。 二分探索中、しきい値は`2`4つのペアを数えるので、答えは次のようになります`2`。 このアルゴリズムは個別の値ではなく出現回数をカウントするため、重複は自然に処理されます。 

負の値の場合:```
1
2 2
-5 -1
```検索は次から始まります`-10`に`-2`。 確認するときは`-6`の場合、カウント ステップでは、最初の要素は両方の要素とペアになることができるが、2 番目の要素はしきい値を超えることができないことがわかります。 カウントが 2 になるので、答えは次のようになります。`-6`。 境界は配列値から直接取得されるため、負の範囲が機能します。
