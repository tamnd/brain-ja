 ## 解決策
 ## 問題の理解

 _n_ 個のノードを持ち、_n-1_ 個のエッジで記述されたツリーが与えられます。 ツリーは接続された非巡回グラフであるため、任意の 2 つの頂点間には 1 つのパスが存在します。 ボブは、エッジの任意のサブセット (場合によってはまったく削除しないこともある) を削除して、結果として得られる接続コンポーネントのサイズを調べます。 彼のスコアは、すべてのコンポーネントのサイズの積です。 私たちのタスクは、エッジを最適に削除することで達成可能な最大スコアを計算することです。 

たとえば、5 つのノードが並んでいる場合`1-2-3-4-5`ノード 2 と 3 の間のエッジを削除すると、ツリーがサイズ 2 と 3 の 2 つのコンポーネントに分割されます。積は 6 です。この場合、他の削除戦略でこれより高い積を生成することはありません。 

ノードの数は最大 700 まで可能です。これは十分に小さいため、おおよそのアルゴリズムを使用できます。$O(n^3)$操作は適切な時間内に実行できる可能性があります。 _n_ が指数関数的に複雑になるものは実行不可能です。$2^{700}$天文学的です。 したがって、エッジのすべての可能なサブセットを直接列挙することを回避する動的プログラミング ソリューションを目指す必要があります。 

エッジケースには非常に小さな木が含まれます。 ノードが 1 つだけの場合、コンポーネントは 1 つだけであるため、最大積は 1 になります。 星型ツリーでは、中央で分割することで製品を最大化できます。 たとえば、葉の端の切断のみを考慮する不注意なアプローチは、このようなトポロジでは失敗する可能性があります。 

## アプローチ

 ブルート フォース アプローチの説明は簡単です。エッジのサブセットごとに、結果の連結成分を計算し、そのサイズを決定し、積を計算します。 次に、見つかった最大の積を返します。 これはすべての可能性を徹底的に検索するため正しく機能しますが、その複雑さは次のとおりです。$O(2^{n-1} \cdot n)$。 _n_ が最大 700 であるため、これは実現不可能です。 

重要な洞察は、問題には最適な下部構造があるということです。 ツリー内の任意のエッジを考慮してください。 カットされているか、カットされていないかのどちらかです。 切り取られない場合、両側の 2 つのサブツリーが 1 つのコンポーネントに寄与します。 これを切り取ると、問題は 2 つの独立したサブ問題 (各サブツリーに 1 つずつ) に分割されます。 これは、ツリーに対する動的プログラミングのアプローチを示唆しています。 サブツリーと、それが属する接続コンポーネント内のノードの数に基づいて DP 状態を定義できます。 

具体的には、`dp[u][v]`をルートとする 2 つのサブツリーから取得できる最大の積を示します。`u`そして`v`エッジ接続を考慮すると`u`そして`v`切断される可能性があるため。 すべての子のペアを反復処理し、次の式を使用して結果を結合します。`dp[u][v] = max(dp[u][v], size1*size2 + recursive values)`。 サブツリーのサイズを事前に計算すると、これらの計算が簡素化されます。 注意深い順序で反復し、中間結果を保存することで、再計算を回避し、実行可能な結果を​​達成します。$O(n^3)$解決。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n * n) | O(n) | 遅すぎる |
 | DP オン ツリー | O(n^3) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ツリーを隣接リストに読み取ります。 ツリーには _n-1_ 個のエッジがあるため、これは簡単です。 
2. DFS を使用して、すべてのノードをルートとする各サブツリーのサイズを計算します。 ノードの場合`u`親と一緒に`p`、そのサイズは`1 + sum(subtree_size[v] for v in children excluding p)`。 これらのサイズは、エッジを切断するときにコンポーネントのサイズの積を計算するために重要です。 
3. DP テーブルの初期化`dp[u][v]`ノードのすべてのペアに対して。`dp[u][v]`間のエッジを考慮すると、取得可能な最大の積が格納されます。`u`そして`v`それぞれのコンポーネントを分離するものとして。 
4. あらゆるエッジに`(u, v)`、計算する`dp[u][v]`再帰的に。 もし`u`は 1 つのサブツリーのルートとみなされ、`v`もう一方のルートでは、それぞれのサブツリーの切断エッジの結果を結合し、もう一方のコンポーネントのサイズを掛けます。 本質的には、`dp[u][v] = max(dp[child_u][v] + (size_v - subtree_size[child_u]) * subtree_size[child_u] for all child_u)`そして対称的に`dp[v][u]`。 
5. 答えは次の最大値です。`dp[u][v]`すべてのエッジにわたって`(u, v)`。 これが機能するのは、それぞれ`dp[u][v]`は、選択したエッジに沿ってツリーを再帰的に分割するあらゆる方法を検討します。 

機能する理由: DP は、サブツリー分離の最大積を正確に取得します。 各エッジは潜在的なカットとみなされ、再帰的な構造により、考えられるすべての分解が確実にカバーされます。 不変条件とは、`dp[u][v]`エッジに沿った切断に最適な製品を常に保管します`(u,v)`、子サブツリーからのソリューションをマージすると、正確さが維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10000)

n = int(input())
adj = [[] for _ in range(n)]

for _ in range(n-1):
    a, b = map(int, input().split())
    a -= 1
    b -= 1
    adj[a].append(b)
    adj[b].append(a)

# Precompute subtree sizes
size = [0]*n

def dfs(u, p):
    size[u] = 1
    for v in adj[u]:
        if v == p:
            continue
        dfs(v, u)
        size[u] += size[v]

dfs(0, -1)

# DP table for all pairs of nodes
dp = [[0]*n for _ in range(n)]

def solve(u, p):
    for v in adj[u]:
        if v == p:
            continue
        solve(v, u)
        for x in range(n):
            dp[u][x] = max(dp[u][x], dp[v][x] + size[v]*(size[x]-size[v]))
            dp[x][u] = dp[u][x]  # symmetric

solve(0, -1)

ans = 0
for i in range(n):
    for j in range(n):
        ans = max(ans, dp[i][j])

print(ans)
```まず入力を読み取り、隣接リストを構築します。 の`dfs`関数はサブツリーのサイズを計算します。これは標準です。 の`solve`関数は、`dp`子を反復し、ソリューションを再帰的に組み合わせることでテーブルを作成します。 対称性により、個別の計算が必要ないことが保証されることに注意してください。`dp[v][u]`。 最後に、DP テーブルをスキャンして最大積を見つけます。 

微妙な点: Python は 0 から始まるインデックスなので、入力を読み取るときにインデックスをインクリメントします。 再帰の深さに注意してください -`sys.setrecursionlimit`これにより、深いツリーに対する Python のデフォルト制限に達しないことが保証されます。 アップデート時`dp[u][x]`、カット後の他のコンポーネントを表すために、常に正しいサイズの差を乗算します。
