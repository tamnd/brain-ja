 ## 解決策
 ## 問題の理解

 私たちは持っています`2N - 1`箱。 すべての箱には、リンゴの数とオレンジの数という 2 つの数字が含まれています。 正確に選択しなければなりません`N`選択されたセットに、すべてのボックスのすべてのリンゴの少なくとも半分とすべてのオレンジの少なくとも半分が含まれるようにボックスを配置します。 

合計が奇数になる可能性があるため、「少なくとも半分」という文言が重要です。 リンゴの合計数が`S`、選択したボックスに少なくとも次のものを含める必要があります。`ceil(S / 2)`リンゴ。 同じ条件がオレンジにも独立して当てはまります。 

出力は、そのようなサブセットが存在するかどうかだけではありません。 また、インデックスの有効なコレクションを 1 つ出力する必要があります。 

最大の制約は次の合計です。`N`すべてのテスト ケースにわたって、最大でも`10^5`。 各テストには次のものがあるため、`2N - 1`ボックスの場合、合計入力サイズは線形です。 これにより、サブセット列挙アプローチが即座に除外されます。 たとえ`N = 30`、サイズのすべてのサブセットをチェックします`N`すでに天文学的な規模になっているでしょう。 解決策`O(N log N)`または`O(N)`テストあたりの値が現実的な目標です。 

難しいのは、2 つの独立したバランス条件を同時に満たさなければならないことです。 リンゴだけを最適化する貪欲な戦略は、オレンジでは簡単に失敗する可能性があります。 

次の例を考えてみましょう。```
N = 2

Box 1: (100, 1)
Box 2: (1, 100)
Box 3: (50, 50)
```最も多くのリンゴが入っている 2 つの箱を選択すると、箱が与えられます`1`そして`3`、十分な量のリンゴが含まれていますが、`51`オレンジが切れた`151`。 それだけでは十分ではありません。 

もう 1 つの簡単な間違いは、正確に必要なことを忘れることです。`N`「せいぜい」ではなく、ボックス`N`"。 例えば：```
N = 2

(10, 10)
(1, 1)
(1, 1)
```最初の 1 つのボックスにはすでに両方のフルーツの半分以上が含まれていますが、それでも正確に 2 つのインデックスを出力する必要があります。 

合計が奇数の場合、より微妙なエッジケースが発生します。```
N = 1

(3, 5)
```リンゴの半分は、`1.5`、したがって、少なくとも必要です`2`。 オレンジの半分は、`2.5`、したがって、少なくとも必要です`3`。 整数の除算を間違えると、より小さい値が誤って受け入れられる可能性があります。 

この問題の驚くべき点は、答えが常に可能なことです。 この挑戦は純粋に建設的なものです。 

## アプローチ

 ブルートフォースのアイデアは単純です。 サイズのすべてのサブセットを試します`N`、その中にあるリンゴとオレンジの合計を計算し、両方の合計が全体の合計の少なくとも半分であるかどうかを確認します。 

これが機能するのは、サブセットが修正されると、条件を簡単に検証できるためです。 問題はサブセットの数です。 以下を調べる必要があります。$$\binom{2N-1}{N}$$選択肢。 のために`N = 20`、これはすでに 350 億を超えるサブセットです。 たとえ常時チェックを行っていたとしても、これは絶望的です。 

そこで本当の疑問は、有効なサブセットが常に存在することを保証する隠れた構造は何でしょうか?

 重要な観察はペアリングから得られます。 相違点に基づいてボックスを並べ替えます。$$a_i - o_i$$オレンジよりもリンゴの方が多い箱は片側に行き、リンゴよりオレンジの方が多い箱は反対側に行きます。 

次に、この順序で隣接するペアを見てみましょう。 どのペアでも、1 つの箱は比較的リンゴが多く、もう 1 つは比較的オレンジが多くなります。 各ペアからちょうど 1 つのボックスを選択すると、不均衡が相殺される傾向があります。 

あるので`2N - 1`ボックス、並べ替えた後、形成できます`N - 1`隣接するペアと残りの中央ボックス 1 つ。 次に、すべてのペアから 1 つのボックスを選択し、残りのボックスも含めて、正確に与えます。`N`選ばれた箱たち。 

素晴らしい点は、これを行うための自然な方法が 2 つしかないということです。 

最初の選択肢:

 すべてのペアから左側の要素と残りのボックスを取得します。 

2 番目の選択肢:

 すべてのペアと残りのボックスから右の要素を取得します。 

これら 2 つのセットのうち 1 つは常に両方の果実条件を満たします。 

なぜ？ これら 2 つの候補セットを組み合わせると、残りのボックスを除くすべてのボックスが分割されるためです。 彼らのリンゴの合計はリンゴの総数になります。オレンジについても同じことが当てはまります。 一方の候補者が半分未満のリンゴを持っている場合、もう一方の候補者は自動的に半分以上のリンゴを持ちます。 による注文`a_i - o_i`同じ方向がオレンジでも機能することを保証します。 

これにより、不可能な組み合わせ検索が、単純な並べ替えベースの構造に変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(\binom{2N-1}{N} \cdot N)$|$O(N)$| 遅すぎる |
 | 最適 |$O(N \log N)$|$O(N)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのボックスを読んで、リンゴとオレンジの合計数を計算します。 
2. すべてのボックスについて、値を計算します。$$a_i - o_i$$これは、箱がリンゴが多いかオレンジが多いかを測定します。 

1. この値でボックスを並べ替えます。 

ソート後、隣接するボックスは相互にバランスがとれます。 一方では大きなプラスの差が現れ、もう一方では大きなマイナスの差が現れます。 

1. 2 つの候補解答セットを作成します。 

最初の候補は次の位置にあるボックスを取得します。```
0, 2, 4, ...
```2 番目の候補は、次の位置にあるボックスを取得します。```
1, 3, 5, ...
```配列の長さが奇数であるため、これらの候補の 1 つは正確に次の値を含みます。`N`ボックスともう一方には含まれます`N - 1`。 最後に残ったボックスを小さい方のセットに追加します。 

1. 1 つの候補セットのフルーツ和を計算します。 

両方の果物の少なくとも半分がすでに含まれている場合は、それを印刷します。 

1. それ以外の場合は、他の候補セットを印刷します。 

証明により、2 つのうちの 1 つが機能することが保証されます。 

### なぜ効果があるのか

 で並べ替えた後、`a_i - o_i`、すべてのペア`(2k, 2k+1)`を満たす:$$(a_{2k} - o_{2k}) \le (a_{2k+1} - o_{2k+1})$$並べ替えると次のようになります。$$a_{2k} + o_{2k+1} \le a_{2k+1} + o_{2k}$$これは、ペアの左側の要素から右側の要素に切り替えると、少なくともオレンジが減少するのと同じくらいリンゴが増加することを意味します。 

ここで 2 つの候補セットについて考えてみましょう。 一緒にすべてのボックスを分割します。 彼らのリンゴの合計はグローバルなリンゴの合計に加算され、オレンジ色の合計はグローバルなオレンジの合計に加算されます。 

最初の候補のリンゴの数が半分未満の場合、2 番目の候補のリンゴの数は半分以上になります。 上記の不等式により、2 番目にも少なくとも半分のオレンジが含まれることが保証されます。 対称的に、最初の候補者が十分なリンゴを持っている場合、それは十分なオレンジも持っています。 

したがって、1 人の候補者が両方の条件を満たさなければなりません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())

        boxes = []
        total_a = 0
        total_o = 0

        for i in range(1, 2 * n):
            a, o = map(int, input().split())
            boxes.append((a - o, a, o, i))
            total_a += a
            total_o += o

        boxes.sort()

        cand1 = []
        cand2 = []

        sum1_a = 0
        sum1_o = 0

        sum2_a = 0
        sum2_o = 0

        for i in range(2 * n - 1):
            _, a, o, idx = boxes[i]

            if i % 2 == 0:
                cand1.append(idx)
                sum1_a += a
                sum1_o += o
            else:
                cand2.append(idx)
                sum2_a += a
                sum2_o += o

        need_a = (total_a + 1) // 2
        need_o = (total_o + 1) // 2

        if sum1_a >= need_a and sum1_o >= need_o:
            out.append("YES")
            out.append(" ".join(map(str, cand1)))
        else:
            out.append("YES")
            out.append(" ".join(map(str, cand2)))

    sys.stdout.write("\n".join(out))

solve()
```実装は構築に直接続きます。 

各ボックスは次のように保存されます。```
(a - o, a, o, index)
```最初の値は並べ替えキーですが、元のカウントとインデックスは後で使用できるように保存されます。 

ソート後、インデックスのパリティによって配列を分割します。 ボックスの総数は奇数であるため、偶数の位置には正確に次の値が含まれます。`N`要素と奇数の位置には以下が含まれます`N - 1`。 構築定理により、偶数のインデックス付きセットで十分であることが保証されます。そうでない場合は、逆のパリティ規則を選択した場合は、奇数のインデックス付きセットで十分です。 ソートされた長さは`2N - 1`、偶数インデックスの位置には、次のものが含まれます。`N`要素。 

半分の要件は、天井分割を使用して計算されます。```
(total + 1) // 2
```これは、合計が奇数の場合に重要です。 

Python の整数は、次の値まで安全に処理します。`10^9`したがって、オーバーフローは問題になりません。
