 ## 解決策
 ## 問題の理解

 パーティーを方向性のない友情グラフとして考えることができます。 すべての人が頂点であり、エッジは 2 人が友人であることを意味します。 

このプロセスでは、人々が順番に削除されます。 まず、学位をお持ちの皆様`0`葉。 これらの排除の後、残った何人かは学位を取得できるようになる`1`、それで彼らは次に出発します。 それから学位を持った人は`2`休暇などを取得し、到達するまで段階的に必要な学位を上げていきます。`n - 1`。 

質問は、特定のグラフをシミュレートするように求めているわけではありません。 その代わりに、一定の人数に対して、`n`、プロセス全体が終了した後、できるだけ多くの人が生き残れるように、可能な限り最善の方法で友情グラフを設計する必要があります。 

制約は概念的には非常に小さいですが、最大で`10^5`テストケース。 各テスト ケースには整数が 1 つだけ含まれます`n`、出力は 1 つの整数の答えだけです。 これは、意図したソリューションが数学的または建設的であり、テスト ケースごとに一定時間の処理を行うものであることを直ちに示唆しています。 無向グラフの数が膨大になるため、グラフを列挙しようとするアルゴリズムは絶望的です。`n`頂点は`2^(n(n-1)/2)`。 

問題の微妙な部分は、「最後には生き残る」ということが実際に何を意味するのかを理解することです。 不注意な解釈をすると、人には十分な友達がいるなら、彼らは永遠に残ると仮定するかもしれません。 削除の度合いは動的に変化するため、これは誤りです。 

考慮する`n = 3`。 

三角グラフの次数はすべて次のようになります。`2`。 孤立した頂点がないため、最初のラウンドでは誰も退出しません。 次数 1 の頂点がないため、2 番目のラウンドでは誰も退出しません。 その後、プロセスはある程度のレベルに達します`2`と3人揃って出発。 正しい答えは、`0`、 ない`3`。 

別のグラフの方が効果的です。 1 つのエッジと 1 つの孤立した頂点を取得します。 孤立した頂点が最初に残ります。 残りの 2 つの頂点にはそれぞれ次数があります`1`, したがって、彼らは次のラウンドで退場します。 そのうちの 1 人は最後に削除された人なので、プロセスの最後に残るのは 1 人だけです。 答えは次のようになります`1`。 

もう 1 つの簡単な間違いは、答えが常に次であると仮定することです。`1`。 

取る`n = 4`。 長さのサイクル`4`すべての頂点次数を与える`2`。 程度で辞める人はいない`0`または`1`。 プロセスが一定のレベルに達すると`2`、4 つの頂点すべてが離れます。 もう一度言いますが、最終的な答えは、`0`。 

しかし、三角形と 1 つの孤立した頂点を使用すると、より良い結果が得られます。 孤立した人が先に去ります。 三角形は次の次まで存続します`2`3 つの三角形の頂点がすべて削除されるステージ。 最後に削除された頂点数はまだ残っています`1`、 ない`3`。 

重要な観察は、このプロセスでは常に最終的には全員が削除されるということです。 私たちがコントロールできる唯一のことは、最後の撤去段階の直前に何人の人がまだ存在しているかということです。 

## アプローチ

 ブルートフォースアプローチは、考えられるすべての友情グラフを列挙することです。`n`頂点を選択し、削除プロセスをシミュレートします。 

固定グラフの場合、シミュレーションは簡単です。 ステージにて`k`、現在の次数と等しい現在生きている頂点をすべて削除します。`k`。 すべてのステージが処理されるまで続行します。 次に、最終的な削除の直前に生き残った頂点の数を記録します。 

これが機能するのは、プロセス定義が明示的かつ決定的であるためです。 問題はグラフの数です。 無向グラフ`n`頂点には`n(n-1)/2`可能なエッジがあるため、$2^{\frac{n(n-1)}{2}}$異なるグラフ。 

たとえ`n = 20`、これは天文学的な大きさです。 いくら最適化してもブルートフォースを実行可能にすることはできません。 

画期的な進歩は、プロセス中に何が起こるかを分析することから生まれます。 

ある瞬間に`m`人々はまだ生きています。 それぞれが最大で学位を取得できます`m - 1`。 最終的にプロセスは段階に達します`m - 1`。 その段階で、残っている人は全員辞めなければなりません。なぜなら、誰もそれ以上の学位を持つことができないからです。`m - 1`。 

つまり、プロセスは常に、現在残っているすべての頂点をまとめて削除することで終了します。 

ここで問題は、最終的なグループの最大のサイズはどれくらいでしょうか?

 最後に生き残ったグループにはサイズがあると仮定します。`m`。 最後のステップの直前に、それらのすべてが`m`頂点には次数が正確になければなりません`m - 1`そうでない場合は、遅かれ早かれ削除されていたでしょう。 したがって、最後のグループはサイズの完全なグラフを形成する必要があります。`m`。 

しかし、グラフ全体が最初に正確に`m`その後、最終段階ですべての頂点が一緒に消え、プロセス後には誰も残りません。 1 人がより長く生き残るためには、クリークの外側に少なくとも 1 つの追加の頂点が必要です。 

これは最適な構築を示唆しています。 

1. クリークを構築する`m`頂点。 
2. 孤立した頂点を 1 つ追加します。 

孤立した頂点はステージで消えます`0`。 クリークはステージまでそのまま残ります`m - 1`、すべてのクリーク頂点がまとめて削除される場合。 

この構築では、`m + 1`頂点の合計。 したがって、当然のことながら`n`、可能な最終的なクリークの最大サイズは次のとおりです。$m=n-1$したがって、答えは単純です`n - 1`。

 ## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取ります。 
2. の各値について`n`、計算する`n - 1`。 

完全なグラフを取得することで、いつでもこの値を達成できます。`n - 1`頂点と 1 つの孤立した頂点。 
3. 結果を印刷します。 

なぜこれが正しい答えなのでしょうか? 孤立した頂点は次数の間に即座に消えます`0`ステージ。 その後、残ったものは、`n - 1`頂点はクリークを形成するため、すべての頂点には次数があります`n - 2`。 それらの次数は現在の除去数よりも大きいため、どの初期段階でも生き残ります。 プロセスが段階に達すると`n - 2`、それらはすべて一緒に削除されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())

for _ in range(t):
    n = int(input())
    print(n - 1)
```すべての作業が証明内にあるため、実装は意図的に小さくなっています。 

プログラムは各テスト ケースを個別に読み取り、出力します。`n - 1`。 数学的引数によって最適値がすでに証明されているため、グラフの構築やシミュレーションは必要ありません。 

唯一の境界条件は、`n = 1`。 その場合、式は次のようになります。`0`、それは正しいです。 孤立した一人の人物が学位途中で退学`0`ステージなのでその後は誰も残りません。 

Python の整数には制限がないため、制限がはるかに大きくてもオーバーフローの心配はありません。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    t = int(input())
    ans = []

    for _ in range(t):
        n = int(input())
        ans.append(str(n - 1))

    print("\n".join(ans))

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out

# provided sample
assert run("1\n3\n") == "2\n", "sample 1"

# minimum size
assert run("1\n1\n") == "0\n", "single isolated vertex"

# small boundary

# multiple test cases
assert run("4\n1\n2\n5\n10\n") == "0\n1\n4\n9\n", "multiple independent cases"

# large value
assert run("1\n100000\n") == "99999\n", "maximum constraint"
