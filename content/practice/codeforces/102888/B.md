 ## 解決策
 ## 問題の理解

 次のような無向の単純なグラフが与えられます。\(n\)頂点と\(m\)エッジ。 グラフにはすでに複数の接続コンポーネントが含まれている可能性があります。つまり、頂点の一部のグループは内部で相互に到達できますが、異なるグループ間にパスが存在しない可能性があります。 

タスクは、新しいエッジをできるだけ少なく追加して、追加後にグラフ全体が接続されるようにすることです。 また、必ずしも一意である必要はない、このようなエッジの有効なセットを 1 つ出力する必要もあります。 

入力は、任意のグラフ構造を記述します。 出力には、挿入することを選択した追加のエッジが記述されています。 追加された各エッジは 2 つの異なる頂点を接続する必要があり、エッジを自分で選択するため、重複を回避すると仮定する自由を除き、エッジが入力にすでに存在するかどうかに制限はありません。 

制約\(n, m \le 10^5\)これは、あらゆるソリューションが線形または線形に近い時間で実行される必要があることを意味します。 すべてのノードのペアを試したり、任意の頂点間の接続性を繰り返しチェックしたりする 2 次アプローチは、次の理由により遅すぎます。\(n^2\)操作はすでに行われています\(10^{10}\)、実現可能な限界をはるかに超えています。 

重要な構造上のエッジケースは、グラフがすでに接続されている場合です。 その場合、正解はエッジの追加がゼロです。 もう 1 つのエッジ ケースは、たとえば、孤立した頂点が多数ある場合です。\(n = 5, m = 0\)ここで、各頂点は独自のコンポーネントです。 次に、ソリューションはそれらすべてを正確に接続する必要があります\(n-1\)ツリーを形成するエッジ。 

コンポーネントの構造を理解せずに貪欲にエッジを追加しようとすると、微妙な障害モードが発生します。 たとえば、異なるコンポーネントをブリッジしていることを確認せずに頂点をランダムに接続すると、同じコンポーネント内に冗長なエッジが追加され、許可された操作が無駄になり、最小化に失敗する可能性があります。\(k\)。 

## アプローチ

 単純な戦略は、接続されていることがわかっていない 2 つの頂点を繰り返し選択し、それらの間にエッジを追加することです。 追加するたびに、グラフ全体が接続されるまで、DFS または BFS を最初から使用するなどして、接続性を再計算します。 

追加された各エッジはコンポーネントをマージすることしかできないか、何も実行できないため、これは論理的に機能しますが、エッジごとに接続を再計算するのはコストがかかります。 各 DFS には \(O(n + m)\) のコストがかかり、最大で\(n\)加算すると \(O(n(n+m))\) になり、これでは遅すぎます。\(10^5\)ノード。 

重要な点は、最終的な接続グラフは 1 つのコンポーネントのみで構成されている必要があるため、既存の接続コンポーネントをマージするだけでよいということです。 最初にすべての接続コンポーネントを計算すると、各コンポーネントは単一の代表ノードで表すことができます。 これらの代表を取得すると、コンポーネントを接続することは、これらの代表ノードをチェーンで接続することと同じになります。 簡単な方法は、コンポーネント 1 をコンポーネント 2 に接続し、コンポーネント 2 をコンポーネント 3 に接続するというように接続することです。 これは正確に使用します\(c-1\)エッジどこ\(c\)is the number of connected components, which is minimal because each added edge can reduce the number of components by at most one.

 | アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 |---|---|---|---|
 | 各エッジ後に DFS を繰り返す | \(O(n(n+m))\) | \(O(n+m)\) | 遅すぎる |
 | 接続されたコンポーネント + リンク | \(O(n+m)\) | \(O(n)\) | 承認済み |

 ## アルゴリズムのチュートリアル

 We begin by identifying all connected components in the graph. これは、DFS または DSU を使用して実行できます。 During this process, we assign each vertex a component identifier and also record one representative vertex per component.

 Once components are identified, we collect the representatives in a list. あると仮定します\(c\)コンポーネントと代表者\(r_1, r_2, \dots, r_c\)。 

次に、接続して答えを構築します\(r_1\)に\(r_2\)、\(r_2\)に\(r_3\)、などまで\(r_{c-1}\)に\(r_c\)。 このような各エッジは 2 つの異なるコンポーネントをマージするため、すべての追加の後、グラフは接続されます。 

最後に、追加されたエッジの数を出力します。\(c-1\)、次に構築したエッジが続きます。 

これが正しい理由は、接続されたコンポーネントが頂点セットのパーティションを形成し、2 つの異なるコンポーネント間のエッジはコンポーネントの数を厳密に 1 つ減らすためです。 から始まる\(c\)少なくともコンポーネント\(c-1\)エッジを単一のコンポーネントにマージするにはエッジが必要です。 構築されたチェーンはまさにこの下限を達成しているため、最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

n, m = map(int, input().split())
g = [[] for _ in range(n + 1)]

for _ in range(m):
    u, v = map(int, input().split())
    g[u].append(v)
    g[v].append(u)

vis = [False] * (n + 1)
components = []

def dfs(start):
    stack = [start]
    vis[start] = True
    rep = start
    while stack:
        u = stack.pop()
        rep = u
        for v in g[u]:
            if not vis[v]:
                vis[v] = True
                stack.append(v)
    return rep

for i in range(1, n + 1):
    if not vis[i]:
        components.append(dfs(i))

k = len(components) - 1
print(k)
for i in range(k):
    print(components[i], components[i + 1])
```グラフは隣接リストを使用して構築されるため、トラバースは線形になります。\(n + m\)。 DFS はコンポーネントごとに 1 人の代表者を収集します。 訪問されていない各ノードは新しい DFS をトリガーし、すべてのコンポーネントが 1 回だけ検出されるようにします。 

最後のループは連続する代表者を接続します。 代表は異なるコンポーネントから取得されることが保証されているため、追加の検証は必要ありません。 

よくある間違いは、代表を追跡せずに和集合演算を試行することです。これにより、実際にどのエッジを出力すべきかが分からなくなります。 ここでは、コンポーネントごとに 1 つの頂点を明示的に保存し、出力の構築を簡単にします。

 | 測定 | 複雑さ | 説明 |

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, m = map(int, input().split())
    g = [[] for _ in range(n + 1)]
    for _ in range(m):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)

    vis = [False] * (n + 1)
    comps = []

    def dfs(s):
        stack = [s]
        vis[s] = True
        rep = s
        while stack:
            u = stack.pop()
            rep = u
            for w in g[u]:
                if not vis[w]:
                    vis[w] = True
                    stack.append(w)
        return rep

    for i in range(1, n + 1):
        if not vis[i]:
            comps.append(dfs(i))

    k = len(comps) - 1
    out = [str(k)]
    for i in range(k):
        out.append(f"{comps[i]} {comps[i+1]}")
    return "\n".join(out)

assert run("2 0\n") == "1\n1 2"

assert run("5 0\n") in [
    "4\n1 2\n2 3\n3 4\n4 5",
    "4\n1 2\n2 3\n3 4\n4 5"
]

 ## 特殊なケース

 ノード 1 からの DFS がすでにすべてのノードを訪問し、コンポーネントが 1 つだけ生成されるため、余分なエッジを必要としない完全に接続されたグラフは自然に処理されます。 代表的なリストのサイズは 1 であるため、追加されるエッジの数は 0 であり、出力エッジは印刷されません。 

完全に空のグラフ。\(m = 0\)、生成します\(n\)孤立したコンポーネント。 DFS ループはノードごとに新しいコンポーネントを開始し、すべての頂点を代表として収集します。 次に、アルゴリズムはそれらをチェーンで接続し、正確な接続を保証します。\(n-1\)エッジ。 

すでに 2 つの大きなコンポーネントに分割されているグラフも同様に動作します。 たとえば、ノードの場合、\(1..k\)1つのコンポーネントを形成し、\(k+1..n\)他のものを形成する場合、アルゴリズムはそれぞれから 1 つの代表を選択し、それらを 1 つのエッジに接続します。 単一のエッジではコンポーネントの数を 1 つ以上削減できないため、これは最適です。
