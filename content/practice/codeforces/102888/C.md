 ## 解決策
 ## 問題の理解

 表示内容は次のとおりです。`n`7 セグメント数字、ただし数字のみ`0`、`2`、`5`、`6`、`8`、 そして`9`他のセグメントが壊れているために表示される可能性があります。 

ディスプレイ全体を 180 度回転すると、2 つのことが同時に起こります。 数字の順序が逆になり、各数字が回転に従って変換されます。 有効なマッピングは次のとおりです。`0 ↔ 0`、`2 ↔ 2`、`5 ↔ 5`、`8 ↔ 8`、`6 ↔ 9`。 

回転の前後の両方で先頭のゼロを使用できます。 

タスクは長さを数えることです`n`この回転後も、数字列はまったく同じままになります。 以来`n`まで持つことができます`10^10`10進数表現での数字は何ですか？ いいえ。この声明の意味は、`n < 10^10`、 それで`n`それ自体は約100億にもなる可能性があります。 このような値は、すべての位置を個別に処理するアルゴリズムには大きすぎます。 複雑さが比例するあらゆるソリューション`n`不可能です。 答えは直接数式から取得し、高速累乗を使用して計算する必要があります。 

簡単な間違いの 1 つは、回転すると桁の順序が逆になることを忘れることです。 たとえば、次のようなとき`n = 2`、文字列`69`になるので有効です`69`反転して交換した後、もう一度`6`そして`9`。 各位置でマッピングを個別に処理すると、マッピングが誤って拒否されます。 

もう 1 つの微妙なケースは、桁数が奇数であることです。 入力用```
1
```有効な数字は次のとおりです`0`、`2`、`5`、 そして`8`、したがって、正しい答えは次のとおりです。`4`。 不用意に実装すると、`6`または`9`、回転後にそれぞれがもう一方に変化しますが。 

3 番目の特殊なケースは、先行ゼロです。 入力用```
2
```文字列`00`は完全に有効であり、カウントする必要があります。 先頭のゼロを拒否すると、間違った答えが生成されます。 

## アプローチ

 最も直接的な解決策は、考えられるすべての長さを列挙することです`n`使用可能な 6 桁の文字列を回転し、結果を元の文字列と比較します。 すべての候補が明示的にチェックされるため、これは正しいです。 残念ながら、あります`6^n`候補者、それは完全に不可能です。 平`n = 30`すでに以上のものが必要になります`2 × 10^23`小切手。 

重要な観察は、すべての位置がそのミラーリングされた位置とのみ相互作用するということです。 位置の場合`i`数字が含まれています`x`、次に位置を決めます`n - 1 - i`の回転形式を強制的に含める`x`。 

ミラーリングされたペアごとに、正確に 6 つの有効な割り当てがあります。`(0,0)`、`(2,2)`、`(5,5)`、`(8,8)`、`(6,9)`、`(9,6)`。 

各ペアは他のすべてのペアから独立しているため、`⌊n/2⌋`ペア、彼らは貢献します`6^(⌊n/2⌋)`可能性。 

もし`n`が奇数の場合、中央に 1 桁が残ります。 反転しても動かないので、それ自体を回転させる必要があります。 のみ`0`、`2`、`5`、 そして`8`この条件を満たすと、4 つの選択肢が得られます。 

答えは単純です`6^(n/2)`いつ`n`均等です、

 そして`6^(n/2) × 4`いつ`n`奇数です。 

以来`n`非常に大きい場合、指数は 2 進累乗モジュロで計算されます`998244353`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(6^n)$|$O(n)$| 遅すぎる |
 | 最適 |$O(\log n)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 整数を読み取る`n`。 
2. コンピューティング`pairs = n // 2`。 すべてのミラーリングされたペアは個別に選択できます。 
3. コンピューティング`ans = 6^pairs mod 998244353`高速べき乗剰余演算を使用します。 
4. もし`n`奇数です、乗算します`ans`による`4`モジュロ`998244353`、中央の数字は次のいずれかである必要があるため、`0`、`2`、`5`、 または`8`。 
5. 出力`ans`。 

### なぜ効果があるのか

 すべてのミラーリングされたペアについて、左の数字を選択すると、回転マッピングを通じて右の数字が一意に決定されます。 1 つのペアの選択は他のペアに影響を与えないため、有効な文字列の総数は各ペアの選択肢の数の積になります。 長さが奇数の場合、中央の位置がそれ自体にマッピングされるため、自己回転する数字のみが許可されます。 これらが唯一の制約であるため、カウント式は正確です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

n = int(input())

ans = pow(6, n // 2, MOD)
if n % 2:
    ans = ans * 4 % MOD

print(ans)
```プログラムはまず、ミラーリングされたペアがいくつ存在するかを数えます。 Pythonの組み込み`pow(base, exp, mod)`でバイナリべき乗を実行します`O(log exp)`時間は不可欠であるため、`n`非常に大きい場合があります。 

残る唯一のケースは、奇数長のディスプレイです。 中心位置は反転後にその位置を変更しないため、自動回転する数字が含まれている必要があります。 4 を掛けると、これらの可能性が考慮されます。 

カウント引数にはすでに先行ゼロが自然に含まれているため、先行ゼロに対する特別な処理は必要ありません。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

MOD = 998244353

def solve():
    input = sys.stdin.readline
    n = int(input())
    ans = pow(6, n // 2, MOD)
    if n % 2:
        ans = ans * 4 % MOD
    print(ans)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout
    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()
    solve()
    out = sys.stdout.getvalue()
    sys.stdin = backup_stdin
    sys.stdout = backup_stdout
    return out

# basic cases
assert run("1\n") == "4\n", "length 1"
assert run("2\n") == "6\n", "length 2"

# custom cases
assert run("3\n") == "24\n", "odd length"
assert run("4\n") == "36\n", "two mirrored pairs"
assert run("5\n") == "144\n", "odd with two pairs"
assert run("10000000000\n") == str(pow(6, 5000000000, MOD)) + "\n", "very large n"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`3`|`24`| センターディジットの処理。 |
 |`4`|`36`| 複数の独立したミラーリングされたペア。 |
 |`5`|`144`| 中央の数字と組み合わせたペアカウント。 |
 |`10000000000`|`6^5000000000 mod 998244353`| 非常に大きな指数が効率的に処理されます。 |
