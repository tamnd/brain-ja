 ## 解決策
 ## 問題の理解

 二部グラフが与えられました\(K_{n,m}\)最初はどこで\(n\)頂点が 1 つの辺と次の辺を形成します\(m\)頂点が反対側を形成します。 左側のすべての頂点は右側のすべての頂点に接続されており、どちらの側にもエッジはありません。 

このグラフに対してランダム ウォークが実行されます。 まず、開始頂点がすべての頂点から一様にランダムに選択されます。\(n+m\)頂点。 次に、各ステップで、現在の頂点から一様にランダムな近傍に移動します。 初めてプロセスを停止します\(T\)グラフ内のすべての頂点が少なくとも 1 回訪問されたとき。 タスクは、次の期待値を計算することです。\(T\)、モジュロ\(998244353\)、つまりモジュラー分数として。 

制約により許可されるのは、\(n, m \le 1000\)なので、グラフのサイズは最大 2000 頂点になります。 訪問ノードのサブセットにわたる単純なマルコフ連鎖は、状態空間が次のようになるため不可能です。\(2^{2000}\)。 状態ごとに確率を保存することすら不可能です。 

微妙な点は、ウォークが自明な点で対称ではないということです。同じ側の頂点は同じように動作しますが、遷移構造は左側にいるか右側にいるかに大きく依存します。 停止条件は、両方のパーティションを完全にカバーするかどうかによって異なります。 

いくつかの特殊なケースでは、単純な推論の問題が明らかになります。 もし\(n=1, m=1\)、開始に関係なく、両方の頂点が 1 つのステップですぐにアクセスされます。 期待値はちょうど 1 です。\(n=1, m>1\)、右側から開始すると、左側の頂点は常にすぐに訪問されますが、すべての右側の頂点に到達するには、中心が唯一の橋である星型の構造に依存します。 すべてのノードにわたって独立したクーポン収集を前提とするアプローチは失敗します。これは、訪問が交互のサイドを通じて強く相関しているためです。 

## アプローチ

 ブルートフォースの試みでは、\((u, S)\) で定義される状態にわたるマルコフ連鎖としてプロセスがモデル化されます。\(u\)は現在のノードであり、\(S\)訪問したノードのセットです。 各状態から隣接する状態に移行し、訪問セットを更新し、吸収状態までの予測ヒット時間を累積します。\(S\)すべての頂点が含まれます。 これは原理的には正しいです。完全な状態が判明するとプロセスはメモリレスになるからです。 

しかし、状態の数は \((n+m)\cdot 2^{n+m}\) と天文学的に多くなります。 たとえ\(n=m=20\)、これはすでに実行不可能になります。 

重要な観察は、グラフには頂点の対称クラスが 2 つしかないことです。 左側の頂点はすべて同一であり、右側の頂点もすべて同一です。 個々の訪問セットを追跡する代わりに、これまでに各側の頂点の数と、現在どの側にいるかを追跡するだけで済みます。 このプロセスは、サブセットではなくカウントを超える小さなマルコフ連鎖になります。 

左側にいる状態から、次のステップは常に均一に選択された右側の頂点に進みます。 右側の状態から、常に左側のどこかの頂点に進みます。 重要なのは、次の頂点が新しいか、それともすでに表示されているかということだけです。 これにより、訪問回数 \((i, j)\) を追跡するプロセスが簡略化されます。\(i\)左側の頂点と\(j\)現在の辺とともに右側の頂点が発見されました。 

これにより、問題は、サイズ \(O(nm)\) のグリッドにわたる 2 層の動的計画法に変わります。遷移は、反対側に残っている見えない頂点の数にのみ依存するクーポン コレクター スタイルの確率によって駆動されます。

 ## アルゴリズムのチュートリアル

 2 つの DP テーブルを定義します。 させて\(E_L[i][j]\)すでに見たので、現在左側の頂点にいるときに終了することが予想される残りのステップです。\(i\)左側の頂点と\(j\)右の頂点。 同様に、\(E_R[i][j]\)は、右側の頂点にいるときに定義されます。 

吸収条件は、\(i=n\)そして\(j=m\)、どちらの側に関係なく期待値がゼロになる場合。 

左側の状態から、次の移動は常に均一に選択された右側の状態に進みます。 がある\(m\)右側の頂点、そのうち\(m-j\)新しくて、\(j\)はすでに見られています。 したがって、新しい正しい頂点を発見したかどうかに応じて、新しい状態に遷移します。 

右側の状態からは、対称ロジックが役割を逆転して適用されます。 

期待値を降順に逆算します。\(i+j\)なぜなら、トランジションのたびに、訪問する頂点の数が増加するか、同じ数を維持しながら側が変わるからです。 循環を避けるために、方程式を線形形式に再編成します。 

核となる反復は、期待方程式を直接書くことから生まれます。 左側の状態から:

 1. 常に 1 ステップをすぐに消費するため、1 を追加します。 
2. 均等に右の頂点に移動します。 
3. 確率で\(\frac{m-j}{m}\)、増やします\(j\)1までに。 
4. 確率で\(\frac{j}{m}\)、\(j\)同じままです。 
5. どちらの場合も、右側の状態に切り替えます。 

したがって、次のような一次方程式が得られます。\[
E_L[i][j] = 1 + \frac{m-j}{m} E_R[i][j+1] + \frac{j}{m} E_R[i][j]
\]同様に:\[
E_R[i][j] = 1 + \frac{n-i}{n} E_L[i+1][j] + \frac{i}{n} E_L[i][j]
\]これらの方程式は直接の DP 遷移ではありません。\(E_L[i][j]\)を通じて間接的に両側に現れます。\(E_R[i][j]\)学期。 \((n-i)+(m-j)\) の降順で状態を反復することで問題を解決し、右辺の未知数がすでに計算されていることを確認します。 

### なぜ効果があるのか

 すべての状態 \((i,j)\) で、プロセスは次の移動で反対側のパーティションに新しい頂点が発見されるかどうかのみに依存します。 パーティション内のすべての頂点は対称であり、遷移ダイナミクスの下では区別できません。 この対称性により、サブセットの指数関数状態空間がカウントの多項式状態空間に崩壊します。 

順序付けにより、状態を評価するたびに、厳密により多くの訪問頂点を持つすべての状態がすでに解決されることが保証されます。 自己依存性は線形であり、期待方程式の再配置によって解決されるため、評価順序に循環依存性は残りません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def inv(x):
    return pow(x, MOD - 2, MOD)

def solve():
    n, m = map(int, input().split())

    inv_n = inv(n)
    inv_m = inv(m)

    E_L = [[0] * (m + 1) for _ in range(n + 1)]
    E_R = [[0] * (m + 1) for _ in range(n + 1)]

    for i in range(n, -1, -1):
        for j in range(m, -1, -1):
            if i == n and j == m:
                continue

            # compute E_L[i][j]
            if j < m:
                p_new = (m - j) * inv_m % MOD
                p_old = j * inv_m % MOD
                val_L = (1 + p_new * E_R[i][j + 1] + p_old * E_R[i][j]) % MOD
            else:
                val_L = (1 + E_R[i][j]) % MOD

            E_L[i][j] = val_L

            # compute E_R[i][j]
            if i < n:
                p_new = (n - i) * inv_n % MOD
                p_old = i * inv_n % MOD
                val_R = (1 + p_new * E_L[i + 1][j] + p_old * E_L[i][j]) % MOD
            else:
                val_R = (1 + E_L[i][j]) % MOD

            E_R[i][j] = val_R

    # initial expectation averages over starting point
    total = (E_L[1][0] * n + E_R[0][1] * m) % MOD
    total = total * inv(n + m) % MOD
    print(total)

if __name__ == "__main__":
    solve()
```DP テーブルには、両側で条件付けされた期待値と訪問数が保存されます。 トランジションは、新しい頂点を発見する確率と、すでに知られている頂点を再訪する確率をエンコードします。 

\((i,j)\) を計算するとき、すべての状態がより高い値をもつため、ボトムアップ反復は機能します。\(i\)または\(j\)すでに埋まっています。 境界線\(i=n, j=m\)これ以上の手順は必要ないため、ゼロになります。 

最終的な答えは開始点の平均になります。 左から始めると貢献する\(E_L[1][0]\)そして右側から始めることが貢献します\(E_R[0][1]\)、選択確率によって重み付けされます。 

## 実用的な例

 ### 例 1:\(n=1, m=1\)どちらかの頂点から開始して、1 ステップですぐにもう一方の頂点に到達します。 

| 状態 | L | からの値 R からの値 |
 |---|---|---|
 | (1,1) | 0 | 0 |
 | イニシャル | E_L[1][0]=1 | E_R[0][1]=1 |

 最終的な期待値は 1 で、1 つの移動で常にカバレッジが完了するという直接的な推論と一致します。 

これにより、境界条件と平均化ステップが自明なグラフと一致していることが確認されます。 

### 例 2:\(n=2, m=1\)ここで、グラフは 1 つの右側のノードを中心とする星形です。 

| 状態 | E_L[i][j] | E_R[i][j] |
 |---|---|---|
 | (2,1) | 0 | 0 |
 | (1,1) | 1 | 1 |
 | (0,1) | 2 | - |

 左側のノードから開始して中央に進み、場合によってはもう一方の左側のノードに進みます。 中心に再訪問する DP キャプチャは新しい発見に寄与せず、左から 2 番目のノードが見つかるまで試行を繰り返す必要があります。 

これは、繰り返しが進行状況を二重にカウントすることなく、繰り返しの訪問を正しく処理していることを示しています。

 ## 特殊なケース

 のために\(n=1, m=1\)の場合、\((1,1)\) はすでに終端状態であるため、DP はすぐに崩壊します。 アルゴリズムセット\(E_L[1][1]=E_R[1][1]=0\)、両方の初期状態は 1 ステップで終了に直接遷移し、平均化後の期待値は 1 になります。 

のために\(n=1, m=1000\)、プロセスは、すべてが表示されるまで右側の頂点を繰り返しサンプリングするように動作しますが、常に 1 つの左側の頂点を経由して戻ります。 DP は、左側が決定論的なブリッジとして機能し、新しい右側の頂点が検出された場合にのみ進行することを正しくエンコードします。 

のために\(n=1000, m=1000\)、すべての状態は完全に対称であり、DP はグリッド上で滑らかな勾配に減少します。 すべての遷移でカバレッジが増加するか、より高いカバレッジ レベルのすでに計算された状態が使用されるため、繰り返しにより循環依存関係が発生しないことが保証されます。
