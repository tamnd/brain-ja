 ## 解決策
 ## 問題の理解

 空のセル、壁、1 人の人物、正確に 2 つのボックス、正確に 2 つのターゲット セルを含む、最大 15 × 15 の小さなグリッドが与えられます。 人は一度に 4 方向に一歩ずつ移動できます。 次のセルが空の場合、人はそこに歩くだけです。 次のセルにボックスが含まれている場合、人はそれを押そうとします。これにより、移動先のセルがグリッド内にあり、壁や別のボックスでブロックされていない限り、ボックスが同じ方向に 1 セル前に移動します。 

目標は、最小限の人の移動で両方のボックスをターゲット セルに押し込むことです。 ボックスはターゲット上に残り、後で移動することもできます。 最小移動数を計算するか、それが不可能であることを報告する必要があります。 

重要な制約はグリッド サイズです。 n,m が 15 までなので、セルの総数は最大でも 225 個になります。ただし、状態には 2 つのボックスの位置だけでなく人の位置も含まれるため、状態空間が大幅に増加します。 これは、状態を慎重に圧縮しない限り、考えられるすべての動作シーケンスに対する単純な検索が実行不可能であることをすでに示しています。 

典型的な隠れた難しさは、ボックスを通過せずにボックスの後ろの位置に到達できるかどうかがプッシュを左右します。 たとえば、ボックスが (2,2) にある場合、ボックスを左に押すと (2,3) に到達する必要がありますが、そのパスはボックス自体または壁によってブロックされている可能性があります。 この制約を無視した単純なグリッド上の最短パスでは、プッシュが常に利用可能であると誤って想定されてしまいます。 

もう 1 つの微妙なケースは、構成の再検討です。将来のプッシュの到達可能性が変化するため、人の位置が異なる同じボックス構成は同等ではありません。 たとえば、人が箱の片側に閉じ込められている場合、たとえ箱が同じであっても、一部の押しは一時的に不可能になります。 

最後に、ボックスはターゲット上で消えないため、ターゲット上にあるボックスは依然としてスペースを占有し、動きに影響を与えます。 不注意なソルバーは、ターゲット セルを「ボックスに占有されている場合は空き」として扱う可能性がありますが、これは正しくありません。 

## アプローチ

 強引なアイデアは、プロセス全体を巨大な状態グラフの最短パスとして扱うことです。 状態には、人物と両方のボックスの位置が含まれます。 各状態から、考えられるすべての人の移動を試み、それに応じて位置を更新します。 これはルールを直接シミュレートしているため正しいですが、分岐要素が大きく、多くの状態では人の無関係な動きだけが異なります。 

考えられる状態の数は、人にとっておよそ 225 の選択肢であり、2 つのボックスを配置する方法は約 225² で、約 10⁷ の状態が得られます。 各状態の拡張では最大 4 つの移動が考慮されるため、生の BFS はすでに境界線に達しており、さらに悪いことに、多くの遷移にはボックスの構成を意味的に変更しない人の冗長な歩行ステップが含まれます。 

重要な洞察は、「ボックスの構成」と「人が押す位置に到達する方法」を分離することです。 すべての歩行ステップを明示的にシミュレートする代わりに、遷移が有効なプッシュにのみ対応するグラフとしてシステムを扱います。 押す間は、ボックスと壁の現在の静的なレイアウトで、人が必要な押すセルに到達できるかどうかだけを考慮します。 これにより、問題は結合された状態にわたる最短パスになりますが、ボックスが障害物として扱われるグリッド上の BFS を介して到達可能性チェックが行われます。 

次に、各状態が 2 つのボックスと人物の位置によって定義される状態に対して、0-1 スタイルの BFS またはダイクストラのような BFS を実行します。 コストは移動ごとに累積されますが、トランジションは、両方のボックスの 4 方向のすべての押しをチェックし、人が必要な押し前の位置に到達できるかどうかを確認することによって生成されます。 

これにより、実際にボックスを移動する意味のあるトランジションのみが拡張されるため、有効な検索スペースが減少します。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 |---|---|---|---|
 | ステップシミュレーションによる人物 + ボックス上のフルグリッド BFS | O(225 * 225² * 4) 最悪の場合 | O(225 * 225²) | 遅すぎる |
 | プッシュの到達可能性チェックを備えた最適化された状態 BFS | O(州 × 州ごとの BFS) ≈ O(10⁶ × 225) 最悪のケースだが、実際には刈り取られる | O(状態) | 承認済み |

 ## アルゴリズムのチュートリアル

 状態を人の位置と 2 つのボックスの位置で構成されるタプルとして定義します。 これらの州では最短距離を維持します。 

グリッドから読み取られた開始設定を使用して BFS キューを初期化します。 

次のように進めます。 

1. グリッドをエンコードし、人、ボックス、ターゲットの位置を特定します。 重複を避けるために 2 つのボックスの順序を修正します。 これは重要です。なぜなら、同一のボックスを交換すると、問題が変わることなく状態空間が 2 倍になるからです。 

2. 州に対して BFS またはダイクストラ形式の検索を使用します。 各状態は、すべての移動可能なエンティティのスナップショットを表します。 初期状態から現在の状態までの距離マップを維持します。 

3. 特定の状態に対して、壁とボックスの位置がブロックされているものとして扱われる一時的なグリッドを再構築します。 このグリッドは、その人が自由に歩行できるかどうかを判断するために使用されます。 

4. 各ボックスについて、4 方向のそれぞれに押してみます。 これにより、ボックスの前のセルが空で有効な場合にのみ、候補の手が生成されます。 

5. 押し候補の場合、その人が壁や箱を通過せずに必要な押し位置に到達できるかどうかを計算します。 これは、一時グリッド上の人の現在位置から開始する BFS を介して行われます。 

6. 到達可能な場合、人から押す位置までの距離に、押すこと自体の 1 ステップを加えたものとしてコストの増加を計算します。 

7. 結果の状態を更新します。ボックスは前方に移動し、人はボックスの前の位置で終了し、その新しい状態の距離を緩和します。 

8. すべての状態が処理されるまで続行します。 いずれかの州のターゲット セルに両方のボックスがある場合、回答を更新します。 

### なぜ効果があるのか

 重要な不変条件は、状態間を遷移するたびに、箱を押すという 1 つの意味のあるアクションで終わる人の動きのシーケンスのみを考慮するということです。 一連の中間歩行ステップは、固定障害物グリッド上の最短経路の計算に圧縮されます。 グリッド上の BFS は、プッシュ位置への最短到達性を保証するため、各移行コストは、そのプッシュを実行するために必要な最小限のステップと正確に一致します。 したがって、状態グラフのエッジは最適なローカル決定を表し、このグラフに対する BFS によりグローバル最小値が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

dirs = [(1,0),(-1,0),(0,1),(0,-1)]

def inb(x,y,n,m):
    return 0 <= x < n and 0 <= y < m

def reach(sr, sc, tr, tc, grid, n, m):
    if (sr, sc) == (tr, tc):
        return 0
    q = deque([(sr, sc)])
    dist = [[-1]*m for _ in range(n)]
    dist[sr][sc] = 0
    while q:
        x,y = q.popleft()
        for dx,dy in dirs:
            nx,ny = x+dx,y+dy
            if not inb(nx,ny,n,m):
                continue
            if grid[nx][ny] != 0:
                continue
            if dist[nx][ny] != -1:
                continue
            dist[nx][ny] = dist[x][y] + 1
            if (nx,ny) == (tr,tc):
                return dist[nx][ny]
            q.append((nx,ny))
    return -1

def solve():
    n,m = map(int,input().split())
    g = [list(input().strip()) for _ in range(n)]

    boxes = []
    targets = []
    for i in range(n):
        for j in range(m):
            if g[i][j] == 's':
                sr, sc = i, j
                g[i][j] = '.'
            elif g[i][j] == '#':
                boxes.append((i,j))
                g[i][j] = '.'
            elif g[i][j] == '@':
                targets.append((i,j))
                g[i][j] = '.'

    boxes.sort()
    targets.sort()

    def encode(b1, b2, pr, pc):
        return (b1, b2, pr, pc)

    start = encode(boxes[0], boxes[1], sr, sc)
    dist = {start: 0}
    q = deque([start])

    def build_grid(b1, b2):
        blocked = [[0]*m for _ in range(n)]
        for i in range(n):
            for j in range(m):
                if g[i][j] == '*':
                    blocked[i][j] = 1
        blocked[b1[0]][b1[1]] = 1
        blocked[b2[0]][b2[1]] = 1
        return blocked

    ans = -1

    while q:
        b1, b2, pr, pc = q.popleft()
        curd = dist[(b1,b2,pr,pc)]

        if (b1 in targets) and (b2 in targets):
            ans = curd
            break

        grid = build_grid(b1, b2)

        for i, (bx, by) in enumerate([b1, b2]):
            for dx, dy in dirs:
                nbx, nby = bx + dx, by + dy
                px, py = bx - dx, by - dy
                if not inb(nbx, nby, n, m):
                    continue
                if grid[nbx][nby]:
                    continue
                if grid[px][py]:
                    continue

                need = reach(pr, pc, px, py, grid, n, m)
                if need == -1:
                    continue

                if i == 0:
                    nb = (nbx, nby)
                    state = (nb, b2, bx, by)
                else:
                    nb = (nbx, nby)
                    state = (b1, nb, bx, by)

                nd = curd + need + 1
                if state not in dist or nd < dist[state]:
                    dist[state] = nd
                    q.append(state)

    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、まずグリッドから動的エンティティを抽出し、壁を静的な障害物マップに変換します。 ボックスの順序は並べ替えによって固定されるため、並べ替えによって同じ状態が重複することはありません。 

の`reach`関数は、固定された障害物レイアウトにおける人の最短歩行距離を計算します。ボックスの位置によってブロック構造が変化するため、この距離は状態ごとに再計算されます。 

BFS 中に、各状態展開では両方のボックスの 4 つの方向すべてが考慮されます。 プッシュは、宛先セルが空いており、反対側のセルを人が占有できる場合にのみ有効です。 人からその必要な位置までの BFS 距離は、プッシュに到達するコストとして追加されます。 

微妙な点は、人を押した後、ボックスの前の位置に配置されることです。 これは、人が箱を押すには箱の近くに立たなければならず、押した後は空いたセルを占有するという事実をモデル化しています。

 ## 特殊なケース

 エッジケースの 1 つは、幾何学的な隣接性はまだ残っているものの、到達可能な経路がない壁状の構造物によって人が箱から隔てられている場合です。 アルゴリズムはこれを処理します。`reach`BFS はボックスを含む静的な障害物を考慮します。 

もう 1 つのケースは、箱を押すときに人が箱自体を「通過」する必要がある場合です。 ボックスはグリッドにブロックとして含まれているため、`reach`、BFS はそのような動きを正しく禁止し、無効なプッシュの仮定を防ぎます。 

最後のケースは、ボックスがターゲット上で開始されるが、両方のボックスを正しく配置できる構成に到達するために離れたところに移動する必要がある場合です。 このアルゴリズムはターゲット セルを吸収状態として扱わないため、ボックスはすべての到達可能性とプッシュの計算でアクティブなままとなり、正しい遷移が保証されます。
