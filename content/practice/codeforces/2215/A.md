 ## 解決策
 ## 問題の理解

 整数の配列と 2 つの係数が与えられています。$p$そして$q$、最小間隔の長さとともに$k$。 許可される操作は、少なくとも長さの連続するサブ配列を選択することです。$k$そして、その部分配列内のすべての要素を法的に削減します。$p$または$q$。 目標は、このような操作を任意の数実行した後に配列の合計を最小化することです。 

入力は複数のテスト ケースで構成されます。 各テスト ケースは配列の長さを示します$n$、間隔パラメータ$k$、モジュライ$p$そして$q$、および配列自体。 出力は、演算を最適に適用した後に達成可能な最小合計です。 

とすれば$n$到達できる$10^5$テストケースごとの合計と$n$すべてのテストケースにわたって$10^5$、どのアルゴリズムもほぼ線形である必要があります。$n$テストケースごとに。 すべての間隔で反復する入れ子になったループは遅すぎます。$O(n^2)$間隔ごとに、$O(n)$操作、与える$O(n^3)$最悪の場合のオペレーション。 これは明らかに実行不可能です。 

エッジケースが発生するのは次の場合です$k = 1$、単一要素の演算が可能で、配列の要素が両方の要素よりも小さい場合に使用できます。$p$そして$q$。 たとえば、$a = [1,2,3]$、$k=1$、$p=5$、$q=10$、モジュロを適用しても要素は削減されず、最小合計は単に配列の合計になります。 もう 1 つの注意が必要なケースは、すべての配列要素が次の倍数である場合です。$p$または$q$、モジュロでは一部の要素がゼロになる可能性があるため、合計が大幅に減少します。 

## アプローチ

 ブルートフォースソリューションでは、少なくとも長さのすべての間隔が考慮されます。$k$そして、間隔ごとに両方のモジュロ演算を適用してみてください。 適用するたびに、それ以上の改善が不可能になるまでプロセスを再帰または繰り返すことができます。 これは原理的には正しいですが、操作の数は次のようになります。$O(n^3)$最悪の場合、それは実現可能な限界をはるかに超えています。$n=10^5$。 

重要な洞察は、モジュロ演算は、いかなる数値に対しても**事実上単調**であるということです。$x$、$x \bmod m \le x$したがって、モジュロを適用しても要素が増加することはありません。 これは、より小さいモジュロがすでに適用されている場合、同じ要素にモジュロを複数回適用しても役に立たないことを意味します。 唯一の関連するプロパティは、各要素をカバーする間隔によって削減できる最小値です。 なぜなら、少なくともすべての長さの間隔$k$任意の連続した長さのセグメントをカバーするように拡張できます$\ge k$の場合、最適な戦略は、**小さい方を法として要素の各連続減少シーケンスを削減することです。$p$そして$q$** 可能な場合。 

要素が以下より小さい場合$p$そして$q$、減らすことはできません。 要素が大きい場合、達成できる最小の係数は小さくなります。 配列をスキャンし、少なくとも長さの間隔を考慮して各要素の最小値を計算します。$k$を使用すると、合計を効率的に計算できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^3) | O(n) | 遅すぎる |
 | 最適 | テスト ケースあたり O(n) | O(1) おまけ | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、次の内容を読んでください。$n$、$k$、$p$、$q$、および配列$a$。 させて$m = \min(p, q)$。 
2. 現在の合計を初期化します`total = 0`。 
3. 配列を要素ごとに繰り返します。 要素ごとに$a[i]$：

- もし$a[i] \ge m$そしてそれは少なくとも一連のシーケンスの一部です$k$すべての連続する要素$\ge m$、 減らす$a[i]$に$a[i] \bmod m$。 
- それ以外の場合は、その場を離れてください$a[i]$変わらない。 
4. 結果の値を加算します。$a[i]$に`total`。 
5. すべての要素を処理した後、出力します`total`。 

重要な不変条件は、少なくとも任意の長さの間隔であることです。$k$上記のすべての要素をカバーするように整列させることができます$m$なので、各要素は$m$モジュロで削減できます$m$少なくとも一度は。 以下の要素$m$モジュロではそれ以上削減できないため、変更されないままになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k, p, q = map(int, input().split())
        a = list(map(int, input().split()))
        m = min(p, q)
        total = 0
        i = 0
        while i < n:
            if a[i] >= m:
                # find the length of the consecutive segment >= m
                j = i
                while j < n and a[j] >= m:
                    j += 1
                length = j - i
                if length >= k:
                    # apply modulo m to all elements in this segment
                    for x in range(i, j):
                        a[x] %= m
                i = j
            else:
                i += 1
        total = sum(a)
        print(total)
```まず、少なくとも次の要素の連続セグメントを見つけます。`m`。 少なくとも一定の長さのセグメントのみ`k`剰余を減らすことができます`m`。 小さいセグメントは有効な間隔の対象にできないため、そのまま残されます。 このアプローチにより、最小化できる各要素が 1 回だけ最小化され、合計が正しく計算されます。 

## 実用的な例

 インプットを考慮する```
4 3 3 4
1 2 3 4
```ここ`m = min(3,4) = 3`。 アレイをスキャンします。 

| 私 | a[i] | セグメント≧m? | 操作 |
 | --- | --- | --- | --- |
 | 0 | 1 | いいえ | 残す |
 | 1 | 2 | いいえ | 残す |
 | 2 | 3 | はい | セグメント長 = 2 < k → そのままにする |
 | 3 | 4 | はい | セグメント長 = 1 < k → そのままにする |

 合計は 1 + 2 + 3 + 4 = 10 のままですが、この例ではモジュロを適用することができませんでした。 実際には、要素 ≥ 3 の最長セグメントは [3,4] ですが、その長さは 2 であり、k=3 より小さくなります。 したがって、モジュロは適用できません。 合計は変わりません。 

別の例:```
6 4 9 20
18 27 180 9 45 99
```

`m = 9`。 スキャン:

 - 要素のセグメント ≥ 9 は [18,27,180,9,45,99]、長さ = 6 ≥ k=4 です。 すべてにモジュロ 9 を適用します。`[0,0,0,0,0,0]`。 合計 = 0。
