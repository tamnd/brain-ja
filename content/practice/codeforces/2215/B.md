 ## 解決策
 ## 問題の理解

 この問題では、与えられた正の整数の方法の数を数えるように求められます。$n$は、すべての基数にわたって「繰り返し」形式で表すことができます。 より正確に言うと、ベースの場合$b \ge 2$そして繰り返しの長さ$p \ge 2$、$n$考慮されています$(b, p)$-tidy がベースで表現されている場合$b$一定の長さのブロックに分割できる$p$ここで、各ブロックは同一の数字で構成されます。 例えば、$1111$は$(10, 2)$-次のように分割できるため整然としています$11 | 11$、またそれは$(10, 4)$-tidy は、整数が 4 つの同一の数字からなる 1 つのブロックを形成するためです。 入力は複数の整数で構成され、出力は各整数の数になります。$(b, p)$すっきりとまとめてくれるペア。 

制約は次のことを教えてくれます$n$まで行くことができます$10^{12}$最大 1000 のテスト ケースが存在する可能性がありますが、すべてのテスト ケースの合計は$n$を超えない$10^{12}$。 これは、おおよそ次のアルゴリズムを使用できることを意味します。$O(\sqrt{n})$またはテスト ケースごとにわずかに多くなります。 2 から 3 までのすべての塩基を反復する単純なアプローチ$n$実行不可能なので、$n$巨大になる可能性があります。 

明らかではないエッジ ケースには、小さな数値、または底のべき乗より 1 小さい数値が含まれます。 例えば、$1$または$2$有効なものがありません$(b, p)$ブロック長のためペア$p \ge 2$が必要です。 同様に、次のような数字も$1111$基地内で$10$複数人にとって整頓されている$p$他の拠点でも、より高い理由を説明できていない$p$整理整頓を過小評価する可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、すべてのベースに対して反復処理が行われます。$b$から$2$まで$n$、 変換する$n$基地へ$b$、可能なすべてのブロック長を確認します$p$各ブロックが同一の数字で構成されているかどうかを確認します。 これは原理的には機能しますが、変換コストがかかります。$n$すべての拠点まで$10^{12}$は禁止です。 のために$n \approx 10^{12}$、 がある$10^{12}-2$候補基地、および各基地について検査が必要になる場合があります$\log_b n$数字。 合計操作量は簡単に超えます$10^{12}$、これは数秒でできることをはるかに超えています。 

重要な観察は、数値が$(b, p)$-tidy、次の形式の項の合計として表現できます。$d \cdot \frac{b^{p \cdot k} - 1}{b^p - 1}$どこ$d$は繰り返される数字であり、$k$ブロックの数です。 この形に注目してみると、$n$多くの場合、次のように書くことができます$x^k + x^{k-1} + ... + 1$桁ごとにスケールされる$d$。 これにより、問題は次の約数を見つけることに帰着します。$n$次の形式の多項方程式を解きます。$b^p = something$。 ブロック長なので$p$超えることはできません$\log_2 n$、テストするだけで済みます$p$およそ40まで$n \le 10^{12}$。 それぞれについて$p$の解決を試みることができます。$b$整数 k 乗根テクニックを使用して、結果が以下であるかどうかを確認します。$b$有効です。 これにより、候補塩基が大幅に減少します。

 ## アルゴリズムのチュートリアル

 1. 整数を読み取る$n$テストケース用。 
2. 整理整頓のためにカウンタを初期化します。 
3. 反復する$p$2から$\lfloor \log_2 n \rfloor + 1$。 この境界で停止します。$2^p > n$基地が不可能になります。 
4. それぞれについて$p$、近似的な整数の底を計算します。$b$p 番目の整数根をとることにより、$n$。 丸め誤差が発生する可能性があるため、ルートの下限値と上限値の両方をチェックする必要があります。 
5. 各候補者について$b$、合計を計算します$1 + b + b^2 + ... + b^{p-1}$そして分割されるかどうかを確認してください$n$均等に。 存在する場合は、繰り返し数字構造が形成されていることを確認します。$n$その通り。 有効な場合は、整頓カウンタをインクリメントします。 
6. さらに、次のような自明なケースを確認します。$p = 1$繰り返しの長さは少なくとも 2 でなければならないため、カウントされません。 
7. 結局のところ$p$値が処理され、現在のカウンターを出力します。$n$。 

アルゴリズムが機能するのは、$(b, p)$-tidy 数値は、数字でスケールされた等比級数として表すことができます。 境界によって$p$に$\log_2 n$, we reduce the search space dramatically. 正確な除算をチェックすることで、有効なきちんとした表現のみをカウントすることが保証されます。 

## Python ソリューション```python
import sys
import math
input = sys.stdin.readline

def count_tidiness(n):
    if n == 1:
        return 0
    tidiness = 0
    max_p = int(math.log2(n)) + 1
    for p in range(2, max_p + 1):
        # approximate b = n^(1/p)
        low = 2
        high = int(n ** (1/p)) + 2
        for b in range(low, high):
            total = 0
            term = 1
            for _ in range(p):
                total = total * b + 1
            if total <= 0:
                continue
            if n % total == 0:
                d = n // total
                if 1 <= d < b:
                    tidiness += 1
    return tidiness

t = int(input())
for _ in range(t):
    n = int(input())
    print(count_tidiness(n))
```コードは意味のある最大値を計算します。$p$そしてすべてを反復します$p$。 それぞれについて$p$の p 乗根の周囲の候補塩基をチェックします。$n$等比級数展開を使用して、有効な繰り返し桁数が存在するかどうかをテストします。 p 根の周りの下限と上限のアプローチにより、丸め誤差が候補塩基を見逃さないことが保証されます。
