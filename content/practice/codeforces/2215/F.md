 ## 解決策
 ## 問題の理解

 私たちは、1 枚の特別なカードを除いてほとんど同じカードで構成されるデッキでプレイされる 2 人のプレイヤーの決定論的なゲームを検討しています。 特別なカードは最初は緑色で、上から既知の位置にあります。 各ターン、プレイヤーはデッキの一番上から固定枚数のカードを取り除き、オプションで引いたカードのうち最大 1 枚を捨てることができ、その後、並べ替えて残りを一番下に置くことができます。 重要な点は、緑のカードが静的ではないということです。アリスが緑のカードを引いて捨てないことを選択すると、その「価値」が増加し、再配置後の新しい位置が通知されます。 

アリスは、緑色のカードが捨てられる瞬間に、そのカードに書かれた最終値を最大化しようとしますが、ボブは、可能な限り自分でカードを捨てて、ゲームを強制的に値ゼロで終了させようとします。 

このインタラクションは、デッキ全体の状態に関するものではなく、グリーン カードが描かれるか埋められるかをどのくらいの速さで循環するかを制御するものです。 すべての動きは事実上、グリーン カードがサイズ k のウィンドウ内に公開されるかどうか、および対戦相手が最初にそれに到達できるかどうかを制御します。 

この制約により、私たちはプロセスを純粋に数学的に特徴付けることになります。 n と k が 10^9 までの場合、ターンやデッキの状態にわたるシミュレーションは不可能です。 唯一の実行可能なアプローチは、いつボブがグリーンカードを取得することが保証されるか、いつアリスが負けを無期限に回避できるか、そしていつアリスが増加するカウンター値で最終的にキャプチャを強制できるかを記述する小さな構造状態のセットにゲームを還元することです。 

最も危険なエッジケースは、グリーンカードがどちらかのプレイヤーがそれを破棄せざるを得なくなる状態に達しない場合です。 その状況では、アリスはそれを永遠に循環させ続けることができ、安全に扱うたびにその価値が高まります。 これは無限の結果をもたらします。 

ボブが最初のドローウィンドウでグリーンカードを確実に見ることができる場合、別の微妙なエッジケースが発生します。 アリスがそれを最適に後方に移動したとしても、初期位置 s はすでにボブの最初の k ウィンドウ内にある可能性があり、これはゲームがスコア 0 で即座に終了することを意味します。 

最後に、それほど明白ではない問題は、多くの素朴なアプローチが、グリーンカードの地位が決定論的に進化することを前提としていることです。 実際には、両方のプレイヤーが捨てられていないカードを任意に並べ替えることができるため、状態は正確な順序ではなく、各移動後にグリーン カードが現在の k ウィンドウの内側にあるか外側にあるかによってのみ決まります。 

## アプローチ

 ゲームを総当たり的に見ると、すべてのターンをシミュレートすることになります。 デッキの順序を明示的に維持し、上位 k 枚のカードを抽出し、どれを捨てるかを決定し、残りのカードの順序を変更し、緑のカードの位置を追跡します。 これはルールに正確に従っているため、原則として正しいです。 ただし、各ターンには O(k) 操作が必要であり、周期的な構成ではターン数が n またはそれ以上になると直線的に増加する可能性があります。 n が 10^9 までの場合、これは完全に不可能です。 

重要な観察は、サイズ k のスライディング ウィンドウ内でのグリーン カードの相対位置を超えて、デッキの順序は無関係であるということです。 各操作の後、プレイヤーは自由に順序を変更できるため、唯一意味のある問題は、プレイヤーが行動するときに緑色のカードが次の k 枚のカードの中にあるかどうか、およびどのプレイヤーがそれを取り除く優先権を持つかということです。 

これにより、ゲームは単一の状態変数、つまり上からグリーン カードまでの距離と、誰のターンであるかに関する到達可能性の問題に変わります。 各ターンは、コントロールを減らすか (ボブはそれを自分のウィンドウに持ち込んで捨てようとします)、またはサイクルを延長します (アリスはそれを見つけたときにそれを押し出してその値を増やそうとします)。 

このプロセスは、ボブによる即時キャプチャ、固定回数の増加後のアリスによる強制的な有限キャプチャ、またはアリスがスコアを増加し続けながら常に負けを回避できる永続ループの 3 つの体制のいずれかで安定します。

この構造に帰着すると、解は n、k、s に関する決定論的な算術条件になります。

 ## アルゴリズムのチュートリアル

 私たちは、グリーン カードが最初はボブのすぐ手の届く範囲内にあるかどうか、そしてアリスがそれを強制キャプチャ範囲外に再配置し続けることができるかどうかだけを使用してゲームをモデル化します。 

1. ボブが最初の動きですぐにグリーンカードを取得できるかどうかを確認します。 これは、初期位置 s が最初の k 枚のカード内にある場合に発生します。 その場合、ボブはすぐに引いて捨てるので、答えは0になります。 
2. それ以外の場合は、アリスの最初の動きを検討してください。 彼女は k 枚のカードを削除し、自由に並べ替えることができます。 彼女が緑のカードを引いた場合、彼女はそれを保持し、その価値を高め、それをデッキの奥深くに再挿入することを選択するかもしれません。 
3. 重要な量が、アリスが強制できる効果的な「安全な距離」になります。 彼女は各ドローの後に任意に順序を変更できるため、緑のカードを捨てないことを選択した場合はいつでも、引いたセグメントの一番下に押し込むことができます。 これは、位置が n − k を基準にしてリセットされることを意味します。 
4. アリスとボブが完全なサイクルで移動するたびに、グリーン カードが次のいずれかになるという意味で、ゲームは周期的になります。 

- ボブの強制ウィンドウに移動し、ゲームを終了します。または
 - 安全な領域に戻り、そこでアリスは再び捕獲を遅らせることができます。 
5. ボブが強制的にキャプチャを実行できないように安全領域が空ではない場合、アリスはこのサイクルを無限に繰り返すことができます。 その場合、アリスがグリーンカードを扱うたびにグリーンカードの価値が増加し、無制限のスコアが得られます。 
6. それ以外の場合、グリーンカードが必然的にボブの窓に落ちる前に、アリスが何回「救出」に成功できるかを計算します。 救助するたびに値が 1 ずつ増加するため、最終的な答えはそのカウントになります。 

### なぜ効果があるのか

 不変条件は、最適なプレイの各フル ラウンドの後で、唯一意味のある状態は、緑のカードがボブによって制御されている現在のデッキの方向の最初の k 番目の位置内にあるか、それともアリスの制御下でその外側にあるかということです。 両プレイヤーは特別でないカードをすべて任意に並べ替えることができるため、他の構造情報はターンを超えて保持されません。 これにより、ゲーム全体が二値安全状態に崩壊します。 アリスがボブのウィンドウの外にグリーン カードを無期限に維持できるようになると、プロセスが最終破棄状態に到達することはありません。そうでない場合、アリスがキャプチャを回避できる回数は有限であり、初期の間隔とウィンドウ サイズによって完全に決定されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k, s = map(int, input().split())

        # immediate capture by Bob
        if s <= k:
            print(0)
            continue

        # if k == 1, Bob always eventually reaches any position
        if k == 1:
            print(0)
            continue

        # main reduction:
        # Alice can indefinitely avoid only if she can always push green
        # beyond Bob's reach; this happens when k < n/2 structure allows
        # perpetual cycling. Otherwise finite increments until forced capture.
        if k * 2 <= n:
            print("Infinity")
        else:
            # finite phase: compute number of safe cycles
            # each cycle reduces distance effectively by (n-k)
            dist = s - k
            cycle = n - k

            # number of full safe pushes before entering Bob window
            ans = (dist + cycle - 1) // cycle
            print(ans)

if __name__ == "__main__":
    solve()
```実装は、些細な即時損失のケースを処理することから始まります。 初期位置がボブの最初の描画ウィンドウ内にある場合、アリスが何かに影響を与える前にゲームは終了します。 

k == 1 のケースは、各ターンに 1 枚のカードが取り除かれるため崩壊します。そのため、コントロールは失われ、再配置パワーに関係なく、ボブは最終的に緑のカードに到達します。 

核となる構造的分割は、デックが k に対して十分に大きく、アリスが各インタラクションの後に常にグリーン カードを「隠す」ことができるレジームと、ボブのウィンドウが最終的に支配できるほど十分に大きいレジームとの間で行われます。 条件 k * 2 <= n はこの分離をエンコードします。ボブのウィンドウがデッキ全体に対して大きすぎない場合、アリスはグリーン カードを手の届かないところにサイクルし続けることができます。 

それ以外の場合、プロセスは有限のカウントダウンになります。 サイクルが成功するたびに、ボブのウィンドウに向かうグリーン カードの有効距離が、ターンごとに消費されるデッキの量によって決まる固定量だけ減少します。 等差数列により、強制キャプチャ前の最終的な増分数が得られます。

 ## 特殊なケース

 グリーンカードが最初の k 位以内で始まる即時負けのケースは、アルゴリズムの最初で処理されます。 その状況では、ボブの最初のドローにはすでにグリーン カードが含まれているため、サイクルについてこれ以上推論する必要はありません。 

k が 1 の場合、移動するたびに一番上のカードが 1 枚だけ削除されるため、再配置の自由度は関係ありません。 ボブによる最適なプレイの下では、ある時点でグリーン カードが必然的にトップ カードになるため、この実装では結果がゼロになります。 

k * 2 <= n に基づくレジーム分割は、無限循環と強制収束の間の遷移を捉えます。 n = 10、k = 3 などの小さな例では、条件が成立し、アリスは各インタラクションの後に最初の 3 つの位置を超えてグリーン カードを配布することで、常にグリーン カードをボブの手の届かないところに置くことができます。 n = 10、k = 6 の場合、条件は失敗し、安全領域の縮小を繰り返すことで最終的なキャプチャが保証され、有限計算分岐に一致します。
