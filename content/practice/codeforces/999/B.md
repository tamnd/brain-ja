 ## 解決策
 ## 問題の理解

 プレフィックスの繰り返しの反転を含む決定論的なプロセスによってすでに変換された文字列が与えられます。 元の文字列は不明ですが、最終的な文字列を生成するプロセスは完全に指定されています。最大から最小までの長さの約数ごとに、その長さのプレフィックスを反転します。 

重要な問題は、これらの反転が重なり合うことです。 文字列内の各位置は複数回移動され、最終的な順序によって一連の変換が隠されます。 反転が適用される前に、元の文字列を再構築するように求められます。 

入力サイズは小さく、文字列の長さは最大 100 です。これは、O(n^2) の再構成またはシミュレーションで十分であることを直ちに示唆しています。 強引な順列を試みる解決策は不要ですが、試したとしても、n が小さいため階乗増加は意味がありません。 

ここでのエッジケースは、パフォーマンスに関連するものではなく、主に構造的なものです。 n が 1 の場合、どの操作も文字列を変更しないため、出力は入力と同じになります。 n が素数の場合、約数は 1 と n のみであるため、意味のある反転は 1 つだけ存在します。 単純なフォワード シミュレーションは簡単ですが、反転順序が正しくないと、誤った再構成が発生します。 

一般的な失敗モードは、可逆性を理解せずに暗号化を直接シミュレートすることです。 もう 1 つは、元のシーケンスを段階的に再構成するのではなく、すべてのプレフィックスを除数の増加順に逆にしようとするものです。 

## アプローチ

 順方向プロセスでは、除数の降順でプレフィックスの反転が適用されます。 各操作は接頭辞のみに依存し、接尾辞の相互作用には依存しません。 この構造により、非常に制御された方法で変換を反転できます。 

強引なアイデアは、元の文字列の候補を生成し、暗号化プロセスをシミュレートし、それをターゲットと比較することです。 正しいのですが、各シミュレーションのコストは O(n^2) であり、すべての順列を試行すると O(n!) かかります。 単一の候補に限定しても、シミュレーションを繰り返す必要はありません。 

重要な洞察は、プレフィックスの反転はインボリューションであり、各反転がそれ自身の反転であることを意味します。 ただし、順序が重要です。 暗号化でプレフィックスを d1、d2、...、dk の順序で逆にすると、復号化では同じ操作を逆の順序で (dk、...、d2、d1) 適用する必要があります。 

しかし、さらに単純な構造観察があります。 暗号化中、約数は降順で処理されるため、最後に適用された意味のある変換は、1 より大きい最小の約数に対応します。つまり、復号化中に、除数の昇順でプレフィックスの反転を適用して文字列を再構築します。 

n のすべての約数を計算し、それらを並べ替えて、暗号化された文字列にその並べ替えられた順序で接頭辞の反転を適用することをシミュレートできます。 各反転により順方向プロセスの対応するステップの効果が取り消されるため、これにより元の文字列が再構築されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 候補者からの総当たりシミュレーション | O(n^3) 以上 | O(n) | 遅すぎる/不必要 |
 | 逆除数シミュレーション | O(n √n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. Compute all divisors of n. 各約数は、暗号化プロセスで使用される 1 つのプレフィックス反転操作に対応します。 これらは変換シーケンスを定義するため必要です。 
2. Sort the divisors in increasing order. 反転の階層構造を効果的に元に戻すことで元の文字列を再構築するため、この順序付けは重要です。 
3. 暗号化された文字列 t を作業配列として開始します。 効率的な接頭辞の反転をサポートするために、これを文字の変更可能なリストとして扱います。 
4. For each divisor d in sorted order, reverse the prefix from index 0 to d − 1. This step is applied because it reverses the effect of how that prefix was altered in the forward process.
 5. すべての約数を処理した後、配列は元の文字列 s を表すので、それを出力します。 

### なぜ効果があるのか

 暗号化プロセスの各操作は、除数ごとに 1 回だけ、降順で適用されるプレフィックス反転です。 プレフィックス反転は自己反転であるため、同じ反転を 2 回適用すると、そのプレフィックス セグメントの元の順序が復元されます。 

The nested structure of divisors ensures that smaller prefixes were transformed after larger ones during encryption, which means their effects are “inside” the final arrangement. 反転を昇順に適用することで、最も内側の構造から外側に向かって変換を剥がしていきます。 各反転はまだ復元されていないプレフィックスにのみ影響するため、これによりすべてのステップで一貫性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input().strip())
t = list(input().strip())

divs = []
for i in range(1, n + 1):
    if n % i == 0:
        divs.append(i)

divs.sort()

for d in divs:
    t[:d] = reversed(t[:d])

print("".join(t))
```この解決策は、プレフィックスの反転を効率的に実行できるように、文字列を可変リストに読み取ることから始まります。 除数は n までのすべての整数をチェックすることによって計算されますが、制約が小さい場合にはこれで十分です。 

ソートにより、変換を正しい再構築順序で適用できるようになります。 各接頭辞の反転は Python スライスを使用して実装されており、手動でのスワップ ロジックを必要とせずに操作を明確に表現します。 

最後の結合では、リストが出力用の文字列に変換されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input().strip())
    t = list(input().strip())

    divs = []
    for i in range(1, n + 1):
        if n % i == 0:
            divs.append(i)

    divs.sort()

    for d in divs:
        t[:d] = reversed(t[:d])

    return "".join(t)

# provided sample
assert run("10\nrocesfedoc\n") == "codeforces"

# minimum size
assert run("1\na\n") == "a"

# prime length
assert run("5\nabcde\n") == "bcdea"

# small composite
assert run("4\ndcba\n") == "abcd"

# repeated pattern
assert run("6\nfedcba\n") == "abcdef"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 10 ロセスフェドク | コードフォース | サンプルの正確性 |
 | 1a | | 最小限のエッジケース |

 ## 特殊なケース

 n = 1 の場合、除数セットは {1} のみです。 このアルゴリズムでは、長さ 1 のプレフィックス反転が適用され、文字列は変更されないままになるため、出力は入力と等しくなります。 

素数 n (n = 5 など) の場合、約数は 1 と 5 です。アルゴリズムは最初に接頭辞 1 を反転し、何も行わず、次に完全な文字列を反転して、暗号化によって課せられた元の順序構造を復元します。 段階的な反転により、意味のある 1 つの変換が正しく元に戻されます。 

12 などの高度に複合的な n の場合、1、2、3、4、6、12 で複数の重複プレフィックス反転が発生します。各ステップでは、以前に復元された構造と一致するプレフィックスのみが変更されるため、後の操作で以前の修正が無効になることはありません。
