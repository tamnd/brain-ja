 ## 解決策
 ## 問題の理解

 左から右に固定順序で配置された問題のリストが与えられます。各問題には難易度の値が付いています。 ミシュカにはスキルレベルがあります`k`、つまり、彼はその難易度を超えない問題しか解決できないことを意味します。`k`。 

このプロセスは重要な方法で制限されています。どの時点でも、左端と右端の残りの問題のみが利用可能です。 ミシュカは、これら 2 つの目的のうちの 1 つを繰り返し選択し、その問題を取り除き、その困難さが彼の能力の範囲内である場合にのみそれを解決します。 どちらの端も解決できない場合は、すぐに停止し、それ以上の移動は不可能になります。 

目標は、行き詰まる前に、どれだけ多くの問題をうまく取り除き、解決できるかを判断することです。 

制約は小さいです。`n ≤ 100`すべての値は最大でも`100`。 これにより、二次シミュレーションや三次シミュレーションでも十分に高速であり、ポインタの移動を伴う貪欲なシミュレーションで十分であることがすぐにわかります。 高度なデータ構造や、ステップごとの一定時間のチェックを超える最適化は必要ありません。 

いくつかの危険な状況が重要になります。 

最初は両端が難しすぎる場合、Mishka は何も解決しません。 たとえば、入力`n = 3, k = 1, [5, 6, 7]`出力を生成します`0`なぜなら、最初は有効な手が存在しないからです。 

すべての値が範囲内にある場合`k`, 削除するたびに新しい有効なエンドポイントが公開され続けるため、Mishka は最終的には選択に関係なくすべてを削除できます。 

微妙なケースとしては、各ステップで片側のみが有効となり、決定的なシーケンスが強制される場合があります。 単純な誤解により、常に小さいまたは大きいエンドポイントを選択しようとする可能性がありますが、ブロックされるまで解決可能なエンドポイントを削除し続ける有効なシーケンスは、この貪欲な制約の下で同じ最大削除数につながるため、この問題は選択戦略の最適化を必要としません。 

## アプローチ

 これを直接考える方法は、プロセスを正確にシミュレートすることです。 2 つのポインターを維持します。1 つは配列の左端に、もう 1 つは配列の右端にあります。 各ステップで、左の値または右の値が解決可能かどうかを確認します。 

どちらも解決できない場合は、停止します。 それ以外の場合は、有効な端の 1 つを取得し、対応するポインタを内側に移動してカウントを増やします。 

両端は常に利用可能な選択肢であるため、自然な強引なアイデアは、考えられるすべての選択肢のシーケンスを試すことです。各ステップで、有効であれば左または右に分岐します。 これにより、状態の数が指数関数的に増加します。`n`ステップは 2 つの選択肢に分岐できます。 最悪の場合こうなります`O(2^n)`、決定が実際には検索を必要とするほど将来の結果に依存していないことを考えると、これは不要です。 

重要な観察は、決して後戻りする必要がないということです。 要素がどちらかの端から取得されると、その要素は永久に削除されます。唯一の制約は、要素が ≤ であるかどうかです。`k`。 将来の実現可能性の観点から、あるブランチが別のブランチよりも厳密に優れたものとなるような選択間に相互作用はありません。 有効な移動はいずれも答えに 1 つだけ寄与し、停止は両端が無効な場合にのみ発生します。 

これにより、問題は貪欲な 2 ポインター シミュレーションに縮小されます。つまり、どちらのエンドも条件を満たさないまで、有効なエンドポイントを繰り返し消費することになります。

 ## アルゴリズムのチュートリアル

 2 つのインデックスを保持します。`l = 0`そして`r = n - 1`、カウンター`ans = 0`。 

1. 現在のセグメントの両端をテストして、プロセスを続行できるかどうかを確認します。 
2. もし`a[l] <= k`、インクリメントして左側の要素を削除します`l`そして増加しています`ans`1つずつ。 
3. それ以外の場合`a[r] <= k`、デクリメントして右側の要素を削除します。`r`そして増加しています`ans`。 
4. どちらの条件も当てはまらない場合は、それ以上移動できないため、直ちに終了します。 

各ステップは 1 つの削除に正確に対応するため、セグメントが崩壊するか再生できなくなるまでループが継続します。 

最初に左を選択する理由は、この問題の正しさにとって重要ではありません。両端が有効な場合は常に、どちらの選択でもプロセスの一貫性が保たれるためです。両方の選択により、有効な要素が 1 つ消費され、問題のサイズが 1 つ減少します。 

### なぜ効果があるのか

 すべてのステップで重要な唯一の要素は、少なくとも 1 つのエンドポイントが解決可能かどうかです。 両方のエンドポイントが超過した場合`k`、最初にエンドポイントを削除しないと内部要素にアクセスできないため、今後のアクションでその状況を変えることはできません。 したがって、停止条件はローカルではなくグローバルに有効です。 有効な削除ごとに、残りのエンドポイントの正確性を維持しながら配列サイズが厳密に削減されるため、プロセスは解決可能な最大数の削除を正確にシミュレートします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    
    l, r = 0, n - 1
    ans = 0
    
    while l <= r:
        if a[l] <= k:
            ans += 1
            l += 1
        elif a[r] <= k:
            ans += 1
            r -= 1
        else:
            break
    
    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、古典的な 2 ポインター パターンが使用されます。 ループ条件`l <= r`残りの要素のみを処理するようにします。 内部では、最初に左側のエンドポイントをテストし、次に右側のエンドポイントをテストします。 どちらの選択も最終的なカウントへの寄与において同等であるため、この順序は任意ですが一貫しています。 

終了条件は、どちらのエンドポイントも有効でない場合にトリガーされます。これは、問題ステートメントの停止ルールに直接対応します。 追加の簿記は必要ありません。

 重要なエッジ ケースの 1 つは、最初と最後の要素が両方とも無効な場合です。 たとえば:

```開始時には、両方のエンドポイントは`5`を超える`k`。 アルゴリズムは両端をチェックし、どちらも有効ではないと判断し、出力を出してすぐに停止します。`0`。 

もう 1 つのケースは、片側のみが有効な場合です。 

入力:```

```段階的に、左端が無効になるまで常に最初に有効になり、その後、右側が使用されます。 ポインターは、有効なエンドポイントがなくなるまで一貫して縮小します。 貪欲ルールは、必要な場合にのみ正しく交互に実行され、有効な手をスキップすることはありません。 

最後のケースは完全に解決可能な配列です。

```すべてのステップで少なくとも 1 つのエンドポイントが有効であり、最終的には両方のポインターが一致するため、アルゴリズムはすべての要素を順番に削除します。
