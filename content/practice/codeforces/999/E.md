 ## 解決策
 ## 問題の理解

 都市がノード、道路が一方通行のエッジである有向グラフが与えられます。 1 つの都市が首都として指定されます。 目標は、首都から始まる指示された道路に従ってすべての都市に確実に到達できるようにすることです。 都市に到達できない場合は、新しい誘導道路を追加できますが、追加する道路の数は最小限に抑えたいと考えています。 

中心となるタスクは、到達可能性自体を計算することではなく、資本が最終的にグラフ内のすべてのノードに到達できるように、挿入する必要がある新しい有向辺の最小数を決定することです。 

この制約は、頂点とエッジの数が線形または線形に近いグラフ アルゴリズムには十分小さいものです。 n と m が両方とも 5000 までの場合、O(n²) または O(nm) の解は原則として許容されますが、3 次の解や到達可能性をゼロから繰り返し再計算するものはスケールできません。 

グラフに強く接続されたコンポーネントが含まれている場合、微妙な問題が発生します。 強く接続されたコンポーネント内では、すべてのノードが相互に到達可能であるため、ノードを個別に扱うと冗長な推論が発生します。 正しい抽象化は、強く接続されたコンポーネント間の構造のみが重要であるということです。 

素朴なアプローチでは、貪欲にエッジを追加し、到達可能性検索を繰り返し実行して首都を新しいノードに接続するシミュレーションを試みる可能性があります。 これは、複数の到達不能な領域が間接的に相互に依存している場合には失敗します。 たとえば、グラフに DAG 内に複数の SCC が配置されている場合、コンポーネント内の 1 つのノードを接続すると、他の多くのノードがロック解除される可能性があり、貪欲なローカル決定により、この構造を認識せずに過大評価または過小評価される可能性があります。 

## アプローチ

 直接的ではあるが非効率な戦略は、首都から BFS または DFS を繰り返し実行し、到達可能なすべてのノードをマークし、次に到達不可能なノードを選択して首都からそこへの道路を追加し、すべてが到達可能になるまで繰り返すことです。 追加するたびに到達可能性が変化するため、最初から再計算します。 最悪の場合、O(n) 個のエッジを追加する可能性があり、各到達可能性の計算に O(n + m) のコストがかかり、O(n(n + m)) 時間がかかり、上限では遅すぎます。 

重要な洞察は、強く接続されたコンポーネント内の到達可能性は個別には問題ではないということです。 強く接続された各コンポーネントを単一のノードに縮小すると、グラフは有向非巡回グラフ (DAG) になります。 DAG では、首都からの到達可能性は、首都コンポーネントからどのコンポーネントが到達可能であるかによってのみ決まります。 

さて、問題は次のとおりです。この DAG では、どのコンポーネントが首都コンポーネントから到達できませんか。また、すべてのコンポーネントが首都コンポーネントから到達できるようにするには、エッジをいくつ追加する必要がありますか? 追加された各エッジは、到達可能なコンポーネントから開始して、到達できないコンポーネントに進むことができるため、事実上、DAG の到達不能な部分を接続する必要があります。 

DAG のよく知られた特性がここで役に立ちます。 凝縮グラフを考慮すると、ソースから到達できない弱く接続されたすべての領域には、到達可能な側からの少なくとも 1 つの入力エッジが必要です。 必要なエッジの最小数は、到達可能な領域からの接続の観点から見た場合、到達不可能なコンポーネントのサブグラフ内のソース コンポーネントの数に等しくなります。 

実際には、強く接続されたコンポーネントを計算し、凝縮された DAG を構築し、どのコンポーネントが首都から到達可能であるかをマークし、次に、別の到達不能なコンポーネントからの入力エッジを持たない到達不能なコンポーネントの数をカウントすることで、これを解決します。 このような各コンポーネントは、少なくとも 1 つの新しいエッジを受け取る必要があります。 

これにより、問題は SCC 分解と圧縮されたグラフに対する線形スキャンに集約されます。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | エッジ追加による DFS/BFS の繰り返し | O(n(n + m)) | O(n + m) | 遅すぎる |
 | SCC+凝縮グラフ解析 | O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、Kosaraju のアルゴリズムまたは Tarjan のアルゴリズムを使用して、グラフを強接続コンポーネントに圧縮します。 このステップでは、相互に到達可能なノードを単一ユニットにグループ化します。これは、そのようなグループ内では到達可能性がすでに保証されており、新しいエッジを必要としないためです。 

次に、各 SCC がノードとなり、エッジがコンポーネント間の接続を表す凝縮グラフを構築します。 サイクルが短縮されているため、このグラフは DAG であることが保証されています。 

次に、資本を含む SCC を特定します。 このコンポーネントから、凝縮グラフに対して DFS または BFS を実行して、すでに到達可能なすべてのコンポーネントをマークします。 

その後、到達可能としてマークされていないコンポーネントのみに焦点を当てます。 これらの到達不可能なコンポーネントの中で、どのコンポーネントが到達可能なコンポーネントからの受信エッジを持たないかを計算します。 このような各コンポーネントは、間接的に到達できない領域を表すため、少なくとも 1 つの新しいエッジを接続する必要があります。 

最後に、これらの成分をカウントし、結果を出力します。 

### なぜ効果があるのか

 SCC に縮小すると、グラフは DAG になり、到達可能性は部分的な順序での走査のように動作します。 到達可能な SCC 内のすべてのノードは、そのコンポーネント内のすべてのノードおよび下流のすべての SCC に到達できます。 SCC に到達できない場合は、首都のコンポーネントからのパスがない別の DAG リージョンに存在する必要があります。 

到達不能な SCC に別の到達不能な SCC からの着信エッジがある場合、その上流の SCC が接続されると、その SCC に到達できるようになります。 したがって、到達不能なサブグラフ内からの入力エッジを持たない SCC のみが、明示的な接続を必要とする独立した「エントリ ポイント」になります。 このような各 SCC には少なくとも 1 つの新しいエッジが必要ですが、到達可能な SCC から接続できるため、1 つのエッジで十分です。 これにより、下限と構築の最適性の両方が確立されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def kosaraju(n, g, rg):
    visited = [False] * n
    order = []

    def dfs1(v):
        visited[v] = True
        for to in g[v]:
            if not visited[to]:
                dfs1(to)
        order.append(v)

    for i in range(n):
        if not visited[i]:
            dfs1(i)

    comp = [-1] * n
    cid = 0

    def dfs2(v, c):
        comp[v] = c
        for to in rg[v]:
            if comp[to] == -1:
                dfs2(to, c)

    for v in reversed(order):
        if comp[v] == -1:
            dfs2(v, cid)
            cid += 1

    return comp, cid

def solve():
    n, m, s = map(int, input().split())
    s -= 1

    g = [[] for _ in range(n)]
    rg = [[] for _ in range(n)]

    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        rg[v].append(u)

    comp, k = kosaraju(n, g, rg)

    cg = [[] for _ in range(k)]
    indeg = [0] * k

    for u in range(n):
        for v in g[u]:
            if comp[u] != comp[v]:
                cg[comp[u]].append(comp[v])

    cap = comp[s]

    reachable = [False] * k
    stack = [cap]
    reachable[cap] = True

    while stack:
        v = stack.pop()
        for to in cg[v]:
            if not reachable[to]:
                reachable[to] = True
                stack.append(to)

    indeg_unreach = [0] * k

    for u in range(n):
        cu = comp[u]
        if reachable[cu]:
            continue
        for v in g[u]:
            cv = comp[v]
            if not reachable[cv]:
                indeg_unreach[cv] += 1

    ans = 0
    for c in range(k):
        if not reachable[c] and indeg_unreach[c] == 0:
            ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションでは、まず、SCC 分解のために元のグラフと反転したグラフの両方を構築します。 コンポーネントのラベルを計算した後、暗黙的に凝縮グラフを構築し、資本コンポーネントからの到達可能性を調査します。 

重要な実装の詳細は、着信エッジをカウントする前に、到達可能な SCC と到達不可能な SCC を分離することです。 これにより、残りのグラフの接続には関係のない、すでに到達可能な領域から発生するエッジを過剰にカウントすることが防止されます。 

最後のカウント ステップでは、到達不能であり、他の到達不能 SCC からの入力エッジがゼロである SCC のみが考慮されます。これは、直接接続する必要がある独立したコンポーネントに正確に対応します。

| ステップ | アクション | 到達可能な SCC |

 ## 特殊なケース

 エッジ ケースの 1 つは、資本が凝縮グラフのシンク コンポーネントにある場合です。 この状況では、SCC からの発信エッジは存在しないため、SCC 内のノードのみに到達できます。 アルゴリズムはそのコンポーネントのみを到達可能としてマークし、受信到達可能性のない他のすべての SCC がカウントされます。 これにより、独立した到達不能領域ごとに 1 つの必要な接続が正しく生成されます。 

もう 1 つのケースは、グラフがすでに強く接続されている場合です。 SCC 圧縮後のコンポーネントは 1 つだけです。 到達可能性ステップでは、すぐに到達可能としてマークされ、最終カウントでは到達不可能なコンポーネントが検出されず、不要なカウントは実行されずにゼロが返されます。 

3 番目のケースは、エッジがまったくなく、切断された小さな SCC が複数ある場合です。 各 SCC には到達可能なコンポーネントからの着信エッジがゼロであるため、それぞれが 1 回カウントされます。 アルゴリズムは、それぞれを首都圏からの 1 つの直接接続が必要であると正しく解釈します。
