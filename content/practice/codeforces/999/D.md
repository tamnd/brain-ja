 ## 解決策

 ## 問題の理解

 整数の配列が与えられ、単一の要素を繰り返し 1 ずつ増やすことができます。 コストはそのような増分の数です。 実際の制約は値自体に関するものではなく、固定整数 m を法とするその剰余に関するものです。 

各要素を m で割ったときの余りだけで見ると、m の剰余クラスにわたる分布が得られます。 目標は、すべての剰余クラスが正確に n/m 回現れるように配列を調整することです。 

重要な詳細は、要素を 1 ずつインクリメントしてもそれが任意に変更されるわけではないということです。要素の剰余は 1 モジュロ m ずつ前方に移動し、0 から m−1 まで循環します。 したがって、各操作は 1 つの要素を次の残差クラスに事実上シフトします。 

したがって、このタスクは循環構造上の再分配問題であり、移動するたびに質量単位が 1 つの残留物バケットから次の残留物バケットに移動し、完全にバランスの取れた構成に到達する必要があります。 

制約は大きく、n は最大 2×10^5 です。 これにより、すべてのターゲットの割り当てを試行したり、要素ごとおよびステップごとに単純に動きをシミュレートしたりするアプローチは即座に除外されます。 すべての解は線形または n log n に近い必要があります。 

複数の要素が同じ剰余を共有する場合、微妙な問題が発生します。 グローバルな調整を行わずにそれらを個別に貪欲に調整すると、中間の剰余クラスを過剰に埋めてしまい、不必要なローテーションを実行してしまう可能性があります。 もう 1 つの失敗例は、循環依存関係を考慮せずに「欠損をローカルで修正」しようとすることから生じます。要素を残りの 1 つに移動すると、別の場所に欠損が生じ、後で修正するのにコストがかかる可能性があります。 

## アプローチ

 直接的なアイデアは、配列を繰り返しスキャンし、現在の剰余カウントを計算し、クラスに余剰がある場合は常に、不足クラスに分類されるまで要素をインクリメントすることです。 これは、すべての増分が有効であるため原理的には正しいですが、計算的には実行不可能です。各増分は 1 つの要素を 1 ステップずつシフトするだけであり、最悪の場合、要素は O(m) 残基を移動する必要があり、O(nm) の演算が必要になる可能性がありますが、これは大きすぎます。 

個々の増分という観点から考えるのをやめ、代わりに、ターゲットの剰余クラスに到達するために各要素が何ステップ進む必要があるかという観点から考えると、構造はより単純になります。 各要素はある剰余 r で始まり、最後の剰余 t に割り当てられなければなりません。 t ≥ r の場合、コストは t−r です。 t < r の場合、ラップアラウンドして m−(r−t) を支払います。 これは円周上を常に前進することに相当します。 

ここで問題は、合計円周距離が最小になるように、正確に n/m 個の要素を各剰余クラスに割り当てることになります。 これは、サイクル上の古典的な貪欲なバランス調整です。 残余クラスを昇順に処理し、前のクラスからの「過剰な」要素のキューを維持すると、各クラスが容量に達するまで貪欲に要素を前進させることができます。 これが機能するのは、要素をさらに前に送信する方が、前に配置するよりも常にコストが高くなるためです。そのため、常に可能な限り早い時点での不足を最初に満たす必要があります。 

残基のスイープをシミュレートし、前方に割り当てることができる利用可能な要素のリストを維持します。 残差クラスが不足している場合、以前のクラスから最も近い利用可能な要素を取得し、ここに到達するのに十分なだけ前方に移動します。 クラスがいっぱいになると、余った要素を将来のクラスのバッファーにプッシュします。

 ## アルゴリズムのチュートリアル

 各要素は、最初は剰余バケット r = a[i] % m に属しているものとして扱います。

1. 要素のインデックスを剰余 r でグループ化します。 これにより、各残基クラスで現在利用可能な要素を追跡できるようになります。 
2. 出現する残基クラスごとに順序付けされた「未使用インデックス」のグローバル キューを維持します。このキューは、最終ターゲット残基にまだ割り当てられていない要素を表します。 
3. 各剰余クラスのターゲット サイズを k = n / m として設定します。 
4. 剰余 t を 0 から m-1 まで昇順に繰り返します。 
5. 各剰余 t に対して、正確に k 個の要素を割り当てる必要があります。 まず、以前の残基に由来する要素をキューから取り出します。 元の剰余 r を持つ選択された各要素について、それを t に移動するコストを (t − r) mod m として計算します。 
6. 以前の残基から利用できる十分な要素がない場合は、現在の残基クラスの要素も含めます。これは、それらの要素を残したり、後で前方に移動したりできるためです。 
7. 剰余 t として k 個の要素を選択したら、増分を最小限に抑えながら、a[i] % m = t となるように各元の値 a[i] を十分に増加させることで、最終値を修正します。 これは、(t − a[i] % m) mod m を追加することによって行われます。 
8. これらの要素を使用済みとしてマークし、今後の検討から除外します。 
9. すべての残留物が処理されるまで続行します。 

### なぜ効果があるのか

 任意の剰余 t で、まだ割り当てられていない要素は、最終的に巡回順序で t より上の何らかの剰余に前方に移動する必要があります。 遅延は移動の全サイクルを追加するだけなので、後で割り当てる場合と比較して、早めに割り当ててもコストが増加することはありません。 したがって、t を処理するときは、前の残差と現在の残り物から最も近い利用可能な要素を使用して要件を満たすことが常に最適です。 これにより、サイクルに沿って単調な割り当てが維持され、ローカルで貪欲な決定を通じてグローバルな最適性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    
    k = n // m
    
    buckets = [[] for _ in range(m)]
    for i, v in enumerate(a):
        buckets[v % m].append(i)
    
    res = [0] * n
    ptr = [0] * m
    
    # list of available indices as (value, index)
    import heapq
    heap = []
    
    for r in range(m):
        for idx in buckets[r]:
            heapq.heappush(heap, (r, idx))
        
        need = k
        new_heap = []
        
        while need > 0:
            r0, i = heapq.heappop(heap)
            need -= 1
            cur = a[i]
            cur_r = cur % m
            add = (r - cur_r) % m
            res[i] = cur + add
            
        # remaining go forward
        while heap:
            new_heap.append(heapq.heappop(heap))
        heap = new_heap
    
    print(sum(res[i] - a[i] for i in range(n)))
    print(*res)

if __name__ == "__main__":
    solve()

ヒープ クリーンアップ ステップにより、現在の残差で使用されていない要素が将来の残差で使用できるようになります。 これにより、割り当てられていないすべての要素のグローバルな可用性が維持されるため、正確さが維持されます。

 ## 特殊なケース

 重要なエッジケースは、すべての要素が同じ残差クラスで始まる場合です。 このアルゴリズムは、k 要素を各剰余に順番に繰り返し割り当て、完全な巡回拡散を強制します。 すべての要素を移動する必要がありますが、割り当ては剰余の昇順で行われるため、割り当てられた剰余に到達するために必要な最小ステップ数だけ移動されます。 

もう 1 つのケースは、分布がすでに均一になっている場合です。 ヒープは各ステップで完全一致を即座に提供するため、`(r - cur_r) % m`選択されたすべての要素についてゼロになります。 このアルゴリズムは効果的な増分を実行せず、ゼロのコストを返します。 

3 番目のケースには、ラップアラウンド動作が含まれます。最適な割り当てには、高い剰余から低い剰余への移動が必要です。 モジュロ計算により、これらが負の移動ではなく順方向循環シフトとして扱われることが保証され、特別なケースを使用せずに正確さが維持されます。
