 ## 問題の理解

 この問題は、ユーザーの評価から Codeforces 部門を割り当てる新しい方法について説明しています。 評価について`r`、整数を選択します`k`、値を見てください$$f(r-k,r)=\frac{1+r+\frac{r^2}{2!}+\dots+\frac{r^{r-k}}{(r-k)!}}{e^r}$$そして計算します`floor(1 / f) - 1`。 最小のものが必要です`k`これにより、この除算は厳密に次よりも大きくなります`1`。 

の表現`f`パラメータを持つポアソン確率変数の累積確率です。`r`せいぜい`r-k`。 言い換えれば、ポアソン分布値が選択したカットオフを超えない確率です。 除算が 1 より大きくなる条件は次のとおりです。$$\lfloor 1/f \rfloor - 1 > 1$$つまり:$$\lfloor 1/f \rfloor \ge 3$$したがって、最小のものを見つけるだけで済みます`k`次のような:$$f(r-k,r) \le \frac13$$評価はせいぜい`4000`、そして最大でもあります`20`テストケース。 に比例した仕事をするソリューション`r`各チェックは簡単に十分に高速です。 ただし、できる限りのことを試してみると、`k`また、確率を最初から再計算しても、不必要な操作が無駄になります。 便利な構造は、次の場合に確率が単調減少するということです。`k`が増加し、二分探索が可能になります。 

数値上の主な課題は、ポアソン プレフィックス確率を正確に評価することです。 最初の項から合計を計算することは危険です。なぜなら、大規模な項では項が非常に小さくなるためです。`r`。 代わりに、最後に含まれた用語から開始して下に移動します。 近い条件`r-k`は必要な範囲内で最大のものであるため、この方向では中間値が安定します。 

エッジケースは主に境界に関するものです。

## アプローチ

 直接的なアプローチは、あらゆる可能性を試すことです`k`ゼロからのスタート。 各候補について、次の値を計算します。`f(r-k,r)`そして、それが最大になる最初のもので停止します`1/3`。 これは正しいです。`k`はポアソン分布のより小さいプレフィックスを意味するため、確率は減少するだけです。 

問題は反復確率の計算です。 全部試してみると`k`、周りにあるかもしれません`4000`候補者たち。 すべての確率計算を最大でスキャンすると、`4000`つまり、1 つのテスト ケースには約`16,000,000`浮動小数点演算。 これは、特に制限時間が短い場合には理想的ではありません。 

重要な観察は単調性です。 いつ`k`増加し、`r-k`減少し、ポアソン接頭辞の分子から項が削除されます。 の値`f`決して増えません。 つまり、答えは単調条件が true になる最初の位置、まさに二分探索が適用される状況であることを意味します。 

残りのタスクは、1 つの確率を効率的に評価することです。 対数を使用して最後に含まれる項を計算し、適切な比率で繰り返し除算して、より小さいべき乗に移動します。 これにより、巨大な階乗が回避され、計算が通常の浮動小数点範囲内に保たれます。

 ## アルゴリズムのチュートリアル

 1. 固定定格の場合`r`、二分探索で答えを出します`k`。 検索範囲は次から始まります`0`十分に大きな上限。 私たちがテストする述語は、確率が`f(r-k,r)`せいぜい`1/3`。 
2. 述語を評価するには、次のようにします。`n = r-k`。 もし`n`が負の場合、プレフィックスに有効な用語がないため、確率はゼロになります。 
3. 確率項を計算します。$$P(X=n)=e^{-r}\frac{r^n}{n!}$$対数を使用する:$$\log P(X=n)=-r+n\log r-\log(n!)$$これにより、大きな累乗や階乗によるオーバーフローが回避されます。 

1. 後方に移動して小さい項を追加します。$$P(X=n-1)=P(X=n)\frac{n}{r}$$期間が無視できるようになるまで続けます。 これらの項の合計が、まさに必要なプレフィックス確率となります。 

1. 確率がすでに最大である場合`1/3`、二分探索を左に移動します。`k`も機能するかもしれません。 それ以外の場合は、より大きなカットオフ削減が必要となるため、右に移動します。 
2. 最小のものを返します`k`二分探索で見つかりました。 

機能する理由: 計算された確率は、正確に次の値までの累積ポアソン確率です。`r-k`。 増加中`k`この累積和から項を削除するので、述語は最大 1 回だけ false から true に変わります。 二分探索では、最初の遷移、つまり正確に有効な最小値が見つかります。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

def poisson_prefix(r, n):
    if n < 0:
        return 0.0
    if n >= r:
        return 1.0

    log_term = -r + n * math.log(r) - math.lgamma(n + 1)
    term = math.exp(log_term)

    ans = term
    cur = n
    while cur > 0:
        term *= cur / r
        ans += term
        cur -= 1
        if term < 1e-16:
            break

    return ans

def solve_case(r):
    lo, hi = 0, r + 10
    while lo < hi:
        mid = (lo + hi) // 2
        if poisson_prefix(r, r - mid) <= 1.0 / 3.0:
            hi = mid
        else:
            lo = mid + 1
    return lo

def main():
    t = int(input())
    ans = []
    for _ in range(t):
        r = int(input())
        ans.append(str(solve_case(r)))
    print("\n".join(ans))

if __name__ == "__main__":
    main()
```の`poisson_prefix`関数は数値部分を処理します。 の使用`math.lgamma`与える`log(n!)`直接的に実行し、階乗オーバーフローを回避します。 隣接するポアソン確率間の反復は、累乗や階乗を明示的に計算する必要がないことを意味します。 

二分探索では、答えが整数であり、それより大きい値はすべて整数であるという事実を利用します。`k`後の回答も有効です。 上限`r + 10`一度あるので安全です`r-k`マイナスになると確率はゼロになります。 

合計の停止条件により、答えに影響を与えなくなる用語に時間を費やすことがなくなります。 しきい値は比較に必要な精度をはるかに下回っています。`1/3`。

## テストケース```python
import sys
import io
import math

def run(inp: str) -> str:
    old = sys.stdin
    sys.stdin = io.StringIO(inp)
    data = sys.stdin.read().strip().split()
    sys.stdin = old

    def poisson_prefix(r, n):
        if n < 0:
            return 0.0
        if n >= r:
            return 1.0
        term = math.exp(-r + n * math.log(r) - math.lgamma(n + 1))
        res = term
        cur = n
        while cur > 0:
            term *= cur / r
            res += term
            cur -= 1
            if term < 1e-16:
                break
        return res

    def solve(r):
        lo, hi = 0, r + 10
        while lo < hi:
            mid = (lo + hi) // 2
            if poisson_prefix(r, r - mid) <= 1 / 3:
                hi = mid
            else:
                lo = mid + 1
        return str(lo)

    t = int(data[0])
    return "\n".join(solve(int(x)) for x in data[1:t+1])

 ## 特殊なケース

 のために`r = 5`、アルゴリズムは到達します`k = 2`カットオフになるので`3`、最大でポアソン値を取得する確率`3`すでに下にあります`1/3`。 二分探索では遷移点を直接チェックするため、これを見逃すことはありません。 

のために`r = 100`、答えは、評価の一定の割合を取るだけでは決まりません。 アルゴリズムは実際の確率境界を評価し、次のことを発見します。`k = 5`が最初の有効な選択肢です。
