 ## 解決策
 ## 問題の理解

 同じサイズの文字列のグループが 2 つあります。 最初のグループには質問が含まれ、2 番目のグループには事前に用意された回答が含まれます。 すべての質問に 1 つの回答を割り当て、すべての回答に 1 つの質問を割り当てる必要があります。 

2 つの文字列のペアのスコアは、韻の長さによって決まります。 2 つの文字列を比較する前に、小文字の英字を除くすべての文字が削除されます。 スコアは、結果として得られる 2 つの文字列が共有する最長のサフィックスの長さです。 目標は、可能な限り最大の合計スコアを持つ完全なペアを見つけることです。 

重要な観察は、スコアの構造から得られます。 処理されたすべての文字列を逆にすると、共通の接尾辞が共通の接頭辞になります。 この変換の後、問題は、2 つの文字列の重みがそれらの最長の共通プレフィックスの長さになる、最大重みの完全一致を見つけることになります。 

文字列の数は最大 800 で、すべての文字列の合計長は最大 200000 です。ハンガリアン マッチングなどの一般的な割り当てアルゴリズムは、約 O(n^3) の演算が必要になるため、コストが高すぎます。 n = 800 の場合、これはすでに数億回の操作となり、文字列比較を個別に処理すると事態はさらに悪化します。 文字列の合計長は、意図したソリューションでは文字のペアごとに比較するのではなく、文字をまとめて処理する必要があることを示唆しています。 

いくつかのケースは見落とされやすいものです。 記号を削除した後に 2 つの文字列が空になった場合、それらの韻の長さはゼロになります。 たとえば、次のような質問です。`!?`そして答え`)`スコア 0 を生成します。フィルタリング手順を忘れたソリューションでは、記号が誤って文字として扱われる可能性があります。 

もう 1 つのケースは、ある文字列が別の文字列のサフィックスである場合です。 例えば、掃除をした後、`abc`そして`xabc`韻の長さは 1 ではなく 3 です。短い文字列が終わるまで最後の文字だけを比較する不用意な実装はまだ機能しますが、反転した文字列のすべての接頭辞ではなく完全な接尾辞のみを保存するソリューションはここで失敗する可能性があります。 

3 番目の重要なケースは、繰り返しのエンディングです。 2 つの質問と 2 つの回答がすべて次のように終わるとします。`ing`。 1 つの質問に対する最良の回答は、最初に見つかった一致する回答であるとは限りません。 アルゴリズムは、等しいサフィックスのすべてのグループ内で利用可能なすべての一致を保存する必要があります。 

## アプローチ

 強引なアプローチでは、すべての質問と回答のペアの韻の値を計算し、その結果として得られる重み付けされた 2 部マッチング問題を解決します。 重みの計算はペアに対して O(L) で実行できます。L は文字列の長さです。 マッチング自体は、ハンガリーアルゴリズムを使用して O(n^3) で解決できます。 これは数学的には正しいですが、マッチング ステップだけでも、n = 800 の場合に約 5 億 1,200 万回の操作に達し、この設定では遅すぎます。 

重要な特性は、重みが任意ではないということです。 これらは、文字列を反転した後のトライ内の共通の接頭辞から取得されます。 トライでは、すべてのノードは、何らかのプレフィックスを共有する文字列のグループを表します。 2 つの文字列が同じノードの異なる子を通過する場合、それらの最長の共通プレフィックスは正確にこのノードで終了します。 これは、異なるブランチの文字列がペアになると、それらの寄与はすでに固定されていることを意味します。 

最適な戦略は、トライ内で再帰的に問題を解決することです。 まず、各子サブツリー内に可能な限り最適なペアを作成します。 その後、異なる子サブツリーにある残りの不一致の質問と回答はすべて、現在の深さを正確に取得するため、現在のノードでペアにすることができます。 残りの不一致文字列は親に渡され、親はより短い共通プレフィックスを取得できます。 

ブルート フォースは、考えられるすべての割り当てを考慮するため機能しますが、多くのエッジが同じ値を持つことは無視されます。 トライはこれらの同一の関係を圧縮し、グループ全体を一度に決定できるようにします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^3 + n^2L) | O(n^2) | 遅すぎる |
 | 最適 | O(S) | O(S) | 承認済み |

 ここで、S は処理されるすべての文字列の合計長です。 

## アルゴリズムのチュートリアル

 1. すべての文字列から小文字以外の文字をすべて削除し、残りの文字を反転します。 すべての質問と回答を 1 つの共有トライに挿入します。 挿入時に、文字列が質問側に属するか回答側に属するかを格納します。 

逆変換とは、サフィックス比較をプレフィックス比較に変える変換です。 このトライは、考えられるすべての一般的な韻を表すことができます。 
2. ルートから深さ優先検索を実行します。 すべてのノードについて、まずそのすべての子を再帰的に解決します。 

子サブツリーには、共通のプレフィックスが現在の深さより長い、考えられるすべてのペアがすでに含まれています。 現在のプレフィックスのみを共有するペアを検討する前に、これらの一致を修正する必要があります。 
3. 子どもたちから返された一致しない質問と回答を収集します。 両方が存在する場合は、1 人の子供からの一致しない質問と、別の子供からの一致しない回答をペアにします。 

これらのペアは、現在のノードのすぐ下で分岐しているため、現在のノードを越えて追加の文字を取得することはできません。 ここでそれらをペアにすることで、このノードの深さで表される正確なスコアが得られます。 
4. ノードの処理の終了時に、最大でも片側の残りの不一致文字列を上方に戻します。 すべての子はすでに可能な限り相互に照合されているため、残りの文字列はこのサブツリーの外側の文字列とのみ照合できます。 
5. 作成されたすべてのペアを記録し、ペアが形成されるたびに現在の深さを答えに追加します。 

### なぜ効果があるのか

 不変条件は、トライ ノードの処理後、そのノードのサブツリー内に完全に含まれるすべての可能なペアがすでに最適化されていることです。 唯一の不一致の文字列は、トライの上位でより適切に一致する可能性を失うことなくサブツリー内でペアにできない文字列です。

2 つの文字列がノードの異なる子から取得される場合、それらの最長の共通プレフィックスは、正確に現在のノードの深さになります。 今後操作を行っても値が増加することはないため、すぐに一致させるのが常に安全です。 2 つの文字列が同じ子に残っている場合は常に、再帰呼び出しによって、それらのより長い可能性のある共通プレフィックスが処理されます。 この引数をリーフからルートまで適用すると、文字列に利用可能な最大の寄与を使用してすべてのペアが作成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Node:
    __slots__ = ("children", "q", "a", "depth")
    def __init__(self, depth):
        self.children = {}
        self.q = []
        self.a = []
        self.depth = depth

def solve():
    n_line = input().strip()
    if not n_line:
        return
    n = int(n_line)
    questions = [input().rstrip("\n") for _ in range(n)]
    answers = [input().rstrip("\n") for _ in range(n)]

    root = Node(0)

    def add(s, is_question, idx):
        cur = root
        clean = ''.join(c for c in s if 'a' <= c <= 'z')[::-1]
        for c in clean:
            if c not in cur.children:
                cur.children[c] = Node(cur.depth + 1)
            cur = cur.children[c]
        if is_question:
            cur.q.append(idx)
        else:
            cur.a.append(idx)

    for i, s in enumerate(questions):
        add(s, True, i)
    for i, s in enumerate(answers):
        add(s, False, i)

    ans = 0
    pairs = [None] * n

    def dfs(v):
        nonlocal ans

        left_q = list(v.q)
        left_a = list(v.a)

        for child in v.children.values():
            q, a = dfs(child)
            left_q.extend(q)
            left_a.extend(a)

        if v.depth:
            while len(left_q) > 0 and len(left_a) > 0:
                q = left_q.pop()
                a = left_a.pop()
                pairs[q] = a
                ans += v.depth

        return left_q, left_a

    dfs(root)

    out = [str(ans)]
    for i in range(n):
        out.append(questions[i])
        out.append(answers[pairs[i]])
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```挿入フェーズでは、必要な正規化が 1 回実行されます。 トライは元の問題からの正確な接尾辞関係を表す必要があるため、フィルタリングと反転は挿入前に行われます。 

深さ優先検索はアルゴリズムの中核です。 各ノードは、完全に一致する行列を構築しようとするのではなく、一致しないインデックスを返します。 これにより、トライ ノードの数に比例したメモリが維持されます。 

ペアリング ループは、両側に一致しない文字列がある場合にのみ実行されます。 質問のみまたは回答のみを含む try ノードは有効なペアを作成できないため、これらの文字列は上方に渡されます。 深さは、ノードによって表される共通のプレフィックスの長さであるため、ペアの作成時に正確に追加されます。 

Python の整数はオーバーフローしないため、可能な最大スコアには特別な処理は必要ありません。 また、この実装では、文字列の合計長が 200000 であり、可能な限り最も深いトライ パスがその長さになる可能性があるため、再帰の深さの問題も回避されます。 Python では、このような場合に備えて再帰制限を増やす必要があります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(S) | すべての文字が 1 回挿入され、すべてのトライ ノードが 1 回アクセスされます。 
| スペース | O(S) | トライは、処理された個別のプレフィックスごとに 1 つのノードを格納します。 

処理される合計の長さは 200000 によって制限されるため、線形ソリューションは制限に簡単に適合します。 このアルゴリズムは、ペア スコアの O(n^2) 行列を決して構築しません。これが、アルゴリズムが効率的である主な理由です。

 ## 特殊なケース

 文字列に句読点のみが含まれている場合、文字列は空になります。 例えば：```

```トライ ルートは両方の文字列を直接受け取ります。 ゼロ以外の深さは存在しないため、アルゴリズムはスコア 0 のペアを作成します。

```反転された文字列は、以下に対応する最初の 3 つのトライ レベルを共有します。`abc`。 ペアは利用可能な最も深いノードで形成され、最終的な文字を比較するだけでなくスコア 3 が与えられます。 

多くの文字列が同じ韻を持っている場合、アルゴリズムは単一のお気に入りを貪欲に選択しません。 たとえば、いくつかの文字列が次のように終わる場合、`ing`、それらはすべて同じトライパスを通過します。 再帰的なプロセスでは、利用可能な最大スコアが割り当てられる最も深いノードまで、すべての不一致文字列が保持されます。
