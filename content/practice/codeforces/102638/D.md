 ## 解決策
 # 問題の理解

 システムは CPU の 3 次元グリッドです。 動作中の CPU は各軸の正の方向にのみ情報を送信できます。つまり、CPU は 1 つの座標を 1 増やして隣の CPU に移動できます。 壊れた CPU は通信グラフには存在しません。 

動作中の CPU のみを削除すると、他の 2 つの CPU 間の既存の通信関係が少なくとも 1 つ破壊される場合、その CPU はクリティカルと呼ばれます。 言い換えれば、削除前にパスが存在していた、動作している CPU のペアが存在する必要がありますが、考えられるすべてのパスで削除された CPU が使用されていました。 タスクは、このプロパティを持つ CPU の数をカウントすることです。 

グリッドの次元はそれぞれ 100 に達する可能性があるため、セルの総数は 100 万に達する可能性があります。 これにより、すべての CPU を削除した後に完全なグラフ検索を実行する試みが除外されます。 グリッド全体にわたる 1 つの幅の最初の検索では、すでに約 100 万回の操作が必要であり、すべてのセルに対してそれを繰り返すと約 1 兆回の操作になります。 このソリューションでは、各 CPU を一定の回数だけ検査する必要があります。 

主なエッジ ケースは、CPU の周りに複数のルートがあるように見えても、グリッドの方向や CPU の故障によりそれらのルートが存在しない可能性があるという事実から生じます。 例えば：```
1 1 3
111
```中央の CPU が重要です。 これを削除すると、最初の CPU は 3 番目の CPU を制御できなくなります。 正しい出力は次のとおりです。```
1
```CPU に隣接する CPU が 2 つあるかどうかだけをチェックする不用意なソリューションでは、2 次元の迂回がないため、これを見逃す可能性があります。 

別のケースは次のとおりです。```
1 2 2
11
11
```右上の CPU は重要ではありません。 方向を検討する前に、左下の CPU から右上の CPU に移動する方法は 2 つありますが、許可された方向の場合、意味のある唯一の質問は、別の単調なルートが存在するかどうかです。 正しい出力は次のとおりです。```
0
```実装では、グリッドを無向グラフとして扱うのではなく、動きの有向性を尊重する必要があります。 

# アプローチ

 直接的なアプローチでは、動作中のすべての CPU を一度に 1 つずつ削除し、到達可能性検索を実行して通信ペアが消失していないかどうかを確認します。 これは重要な CPU の定義を正確にシミュレートしているため、これは正しいです。 ただし、最大のグリッドには 100 万個の CPU があります。 それぞれのノードに対して 100 万個のノードに対して検索を実行すると、次の結果が得られます。$10^{12}$限界をはるかに超えた仕事。 

重要な観察は、CPU に入るすべてのパスは、その 3 つの可能な先行パスの 1 つを経由する必要があり、CPU から出るすべてのパスは、3 つの可能な後続パスの 1 つを経由する必要があるということです。 CPU がクリティカルな場合は、それらの間のすべてのパスが CPU を通過する、先行および後続のペアが存在する必要があります。 

このような先任者と後継者との間の距離は非常に近いです。 前任者は CPU より一歩遅れており、後任者は CPU より一歩進んでいます。 それらが同じ軸上にある場合、CPU が唯一の中央セルとなります。 異なる軸を使用する場合、考えられる代替の中央セルは 1 つだけ、つまり 2 x 2 x 1 の小さな長方形の角になります。 そのコーナーが存在するかどうかを確認するだけで十分です。 

これにより、問題全体が CPU ごとに最大 9 つのローカル構成をチェックするだけで済みます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | ブルートフォース | O(nmk・nmk) | O(nmk) | 遅すぎる |
 | 最適 | O(nmk) | O(nmk) | 承認済み |

 # アルゴリズムのチュートリアル

 1. 動作している CPU と壊れた CPU のグリッドを保存します。 動作中のすべての CPU にとって、通信はこれらの隣接セルを経由して出入りできるため、6 つの隣接する位置のみが重要になります。 
2. 動作中の CPU ごとに、動作している先行CPU と動作中の後続 CPU の指示を収集します。 先行者は軸の負の方向に 1 ステップ行った形式を持ち、後続は軸の正の方向に 1 ステップ行った形式を持ちます。 
3. すべての先行者と後続者のペアを試します。 両方が同じ軸を使用する場合、先行者は現在の CPU を介してのみ後続者に到達できるため、CPU が重要になります。 
4. 先行者と後続者が異なる軸を使用する場合、唯一可能な迂回セルを計算します。 そのセルが壊れているか、グリッドの外側にある場合、現在の CPU が重要になります。 そうでない場合、迂回路は別の経路を提供し、このペアは重要性を証明しません。 
5. 少なくとも 1 つの先行および後続ペアが、それらの間のすべてのパスで CPU を使用していることを証明する場合、CPU をカウントします。 

これが機能する理由は、単一の CPU に出入りするパスがローカル構造を持っているためです。 CPU を使用する通信パスは、隣接する 1 つの先行者から入り、隣接する 1 つの後続者から出る必要があります。 唯一可能なバイパスは、これら 2 つのセルを接続する最小の長方形の内側に収まる必要があり、その長方形には他の中間セルが最大 1 つあります。 セルが考えられるすべての代替パスをカバーしていることを確認します。 

# Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    grid = []
    for i in range(n):
        while True:
            line = input().strip()
            if line:
                break
        grid.append([list(line)])
        for _ in range(m - 1):
            grid[i].append(list(input().strip()))

    def inside(x, y, z):
        return 0 <= x < n and 0 <= y < m and 0 <= z < k

    ans = 0

    dirs = [(1, 0, 0), (0, 1, 0), (0, 0, 1)]

    for x in range(n):
        for y in range(m):
            for z in range(k):
                if grid[x][y][z] != '1':
                    continue

                prevs = []
                nexts = []

                for idx, (dx, dy, dz) in enumerate(dirs):
                    px, py, pz = x - dx, y - dy, z - dz
                    nx, ny, nz = x + dx, y + dy, z + dz

                    if inside(px, py, pz) and grid[px][py][pz] == '1':
                        prevs.append(idx)
                    if inside(nx, ny, nz) and grid[nx][ny][nz] == '1':
                        nexts.append(idx)

                critical = False

                for a in prevs:
                    if critical:
                        break
                    for b in nexts:
                        if a == b:
                            critical = True
                            break

                        dx1, dy1, dz1 = dirs[b]
                        dx2, dy2, dz2 = dirs[a]

                        cx = x - dx2 + dx1
                        cy = y - dy2 + dy1
                        cz = z - dz2 + dz1

                        if not inside(cx, cy, cz) or grid[cx][cy][cz] == '0':
                            critical = True
                            break

                if critical:
                    ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```入力パーサーは、レイヤーを区切る空の行をスキップします。 グリッドは直接保存されるため、すべての近隣ルックアップは一定時間になります。 

各細胞について、`prevs`そして`nexts`セルを介した通信パスに参加できる動作中の近隣ノードのみが含まれます。 それぞれが 3 つを超えることはないため、ネストされたチェックは最大 9 回の反復を実行します。 

迂回計算が微妙な部分です。 先行する方向が x 軸であり、後続する方向が y 軸であると仮定します。 唯一の代替ルートは、最初に y に移動し、次に x に移動して、反対側のコーナーを通過する必要があります。 数式はそのコーナーを正確に計算します。 先行者と後続者の座標の差は 2 ユニット移動だけであるため、検索の必要はありません。 

# 実用的な例

 3 x 3 x 3 の立方体全体については、中央の CPU を検討してください。 

| 現在の CPU | 先代の方向性 | 後継者の方向性 | 代替セル | 結果 |
 | --- | --- | --- | --- | --- |
 | (2,2,2) | × | × | なし | クリティカル |
 | (2,2,2) | × | y | (2,1,2) | 重要であることを証明するには不十分 |

 CPU は、x 方向に沿って前の CPU と後の CPU など、同じ軸上にペアがあります。 それを削除すると、その直線的な通信パスがブロックされます。 この推論を繰り返すと、コーナー以外のすべての CPU がクリティカルとしてマークされます。 

3 つの CPU のラインの場合:```
1 1 1
```トレースは次のとおりです。 

| 現在の CPU | 先人 | 後継者 | 決定 |
 | --- | --- | --- | --- |
 | 最初 | なし | 真ん中 | 重要ではない |
 | 中央 | 最初 | 最後 | クリティカル |
 | 最後 | 真ん中 | なし | 重要ではない |

 この例は、エンドポイントをカウントできない理由を示しています。 重要な CPU には、通信を失うソース側と宛先側の両方が必要です。 

# 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(nmk) | すべての CPU は、一定数の近隣およびペアをチェックします。 |
 | スペース | O(nmk) | グリッド自体は保存されます。 |

 可能な最大のグリッドには 100 万個のセルが含まれます。 このアルゴリズムはセルごとに少量の固定量の作業のみを実行するため、意図した制限に適合します。 

# テストケース```python
import sys
import io

def run(inp: str) -> str:
    old = sys.stdin
    sys.stdin = io.StringIO(inp)
    data = sys.stdin.read().splitlines()
    sys.stdin = old

    it = iter(data)
    n, m, k = map(int, next(it).split())
    grid = []
    for _ in range(n):
        while True:
            s = next(it)
            if s:
                break
        grid.append([list(s)])
        for _ in range(m - 1):
            grid[-1].append(list(next(it)))

    def inside(x, y, z):
        return 0 <= x < n and 0 <= y < m and 0 <= z < k

    dirs = [(1,0,0),(0,1,0),(0,0,1)]
    ans = 0

    for x in range(n):
        for y in range(m):
            for z in range(k):
                if grid[x][y][z] != '1':
                    continue
                p = []
                q = []
                for i, (dx,dy,dz) in enumerate(dirs):
                    if inside(x-dx,y-dy,z-dz) and grid[x-dx][y-dy][z-dz]=='1':
                        p.append(i)
                    if inside(x+dx,y+dy,z+dz) and grid[x+dx][y+dy][z+dz]=='1':
                        q.append(i)
                ok = False
                for a in p:
                    for b in q:
                        if a == b:
                            ok = True
                        else:
                            dx1,dy1,dz1 = dirs[b]
                            dx2,dy2,dz2 = dirs[a]
                            cx,cy,cz = x-dx2+dx1, y-dy2+dy1, z-dz2+dz1
                            if not inside(cx,cy,cz) or grid[cx][cy][cz]=='0':
                                ok = True
                        if ok:
                            break
                    if ok:
                        break
                ans += ok
    return str(ans) + "\n"

 # エッジケース

 直線の場合:```
1 1 3
111
```中央の CPU には、同じ軸上に 1 つの先行 CPU と 1 つの後続 CPU があります。 アルゴリズムは、迂回セルの可能性がないことを確認し、それをカウントします。 

単一の分離された動作中の CPU の場合:```
1 1 1
1
```前任者も後継者もいません。 通信関係を壊すことはできないため、アルゴリズムは答えを変更しないままにします。 

交互セルの場合:```
1 1 10
0101010101
```動作中のすべての CPU には、必要な隣接ペアがありません。 このアルゴリズムでは先行と後続の組み合わせが見つからないため、出力はゼロのままになります。 

密なキューブの場合、すべての内部 CPU には少なくとも 1 つの直接先行後続ペアがあります。 局所的な直線パスはすでに臨界性を証明するのに十分であるため、アルゴリズムはグラフ全体を検査する必要はありません。
