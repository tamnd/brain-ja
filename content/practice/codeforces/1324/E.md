 ## 問題の理解

 私たちは、一連の決定を通じて段階的に進化するプロセスを追跡しています。 がある`n`睡眠イベント。 初めの頃の時間は、`0`、各イベントの後に、現在の時間を次のいずれかだけ進めます。`a_i`または`a_i - 1`。 これにより累積時間のチェーンが作成され、各ステップで前進する距離がわずかに調整されます。 

各ステップの後、現在時刻が日の長さで割られたかどうかを確認します。`h`「良い」間隔に入る`[l, r]`。 時間が経つたびに`h`時間、値のみ`time % h`睡眠が良いかどうかを決める重要な要素です。 

目標は、各ステップで 1 を減算するかどうかを独立して選択し、結果として得られるモジュロ位置が`[l, r]`最大化されます。 

制約`n ≤ 2000`そして`h ≤ 2000`いかなる解もおおよそ二次関数以上である必要があることを直ちに示唆してください。 状態と遷移に対する三次解はまだ問題ありませんが、すべてを列挙することを伴うものはすべて`2^n`それは指数関数的であるため、選択は不可能です。 同様に、剰余モジュロのみを格納するため、すべてのフルタイム値を格納する必要はありません。`h`重要です。 

各ステップで 1 を減算することがオプションであるという事実から、微妙なエッジ ケースが発生します。 常に内側に着地しようとする貪欲なアプローチ`[l, r]`現在のステップでは失敗します。残余を悪い方向にシフトすることで将来の機会を破壊する可能性があるためです。 もう一つの微妙なケースは次のような場合です。`l = 0`そして`r = h - 1`、どの状態も良好であり、答えは自明です`n`、これは正確さを検証するのに役立ちます。 

2 番目のエッジ ケースは、間隔が空であるか非常に小さい場合です。たとえば、`l = r`。 次に、DP は到達可能性を注意深く伝播する必要があります。これは、正確な残基を一度でも欠落すると、潜在的な最適なパスが壊れるためです。 

## アプローチ

 ブルートフォース ソリューションでは、一連の決定をすべて試行し、選択するものを選択します。`a_i`または`a_i - 1`各ステップごとに。 これは次のことにつながります`2^n`それぞれの可能性について、累計をシミュレートし、モジュロが適切な区間に到達した回数を数えます。 たとえ`n = 2000`、状態空間が指数関数的に爆発するため、これは完全に実行不可能です。 

重要な観察は、絶対時間が増加しても、重要なのはモジュロの剰余だけであるということです。`h`。 これにより、状態空間が最大で圧縮されます。`h`可能な値。 各ステップで、与えられた余りから`t`、次の 2 つの可能な剰余に移行できます。`(t + a_i) % h`または`(t + a_i - 1) % h`。 

これにより、ステップと剰余に関する動的プログラミングが自然に行われます。 すべてのパスを記憶するのではなく、ステップのプレフィックスを処理した後、残りの部分ごとに達成可能な最良の結果のみを保存します。 各遷移は、新しい残りが次の場合に「良い」報酬を追加します。`[l, r]`か否か。 

これにより、問題は指数関数的分岐から階層化されたグラフの最短パス スタイル DP に軽減されます。`n * h`州。

 | ブルートフォース | O(2^n · n) | O(n) | 遅すぎる |

 ## アルゴリズムのチュートリアル

 私たちは定義します`dp[t]`イベントの現在のプレフィックスを処理した後に達成可能なグッド スリープの最大数として、残り時間で終了します。`t`。 

1. を除くすべての状態を到達不能として初期化します。`dp[0] = 0`、時間 0 で良好な睡眠がゼロで開始されるためです。 
2. イベントごとに`i`1から`n`、新しい DP 配列を作成します`ndp`到達不可能な状態を表すために非常に負の値で埋められます。 
3. 残りごとに`t`で`[0, h-1]`で到達可能です`dp`、両方の選択肢を考慮します。 

最初のものはに移動します`(t + a_i) % h`、そして2番目は`(t + a_i - 1) % h`。 これにより、許容される 2 つのスリープ タイミングがキャプチャされます。 
4. 結果の各剰余について`nt`、次のことを確認して、良い時期かどうかを計算します。`l ≤ nt ≤ r`。 そうであれば、スコアに 1 を追加します。 それ以外の場合は 0 を追加します。 
5.アップデートする`ndp[nt]`に至るすべての遷移から達成可能な最大値`nt`。 
6. 現在のすべての状態を処理した後、`i`、交換します`dp`と`ndp`。 
7. すべてのイベントが処理された後、答えは、すべての最終剰余の最大値になります。`dp`。 

重要なアイデアは、各ステップで各残基クラスに対して可能な限り最良の結果を独立して伝播するということです。 

### なぜ効果があるのか

 あらゆる段階で`i`、`dp[t]`残りで終わるすべての選択シーケンスの中で、達成可能な最良の良好な睡眠の数を表します。`t`。 考えられるすべての決定シーケンスは、これらの状態を通過する 1 つのパスに正確に対応し、すべての遷移は増分の有効な選択の両方を考慮しているため、正確さを維持します。 状態に到達するすべての方法で常に最大値を取得するため、最適なパスが破棄されることはありません。 したがって、DP はモジュロ等価性によって状態を圧縮しながら、完全な決定木を暗黙的に探索します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, h, l, r = map(int, input().split())
    a = list(map(int, input().split()))

    NEG = -10**9
    dp = [NEG] * h
    dp[0] = 0

    for x in a:
        ndp = [NEG] * h

        for t in range(h):
            if dp[t] == NEG:
                continue

            for add in (x, x - 1):
                nt = (t + add) % h
                val = dp[t] + (1 if l <= nt <= r else 0)
                if val > ndp[nt]:
                    ndp[nt] = val

        dp = ndp

    print(max(dp))

if __name__ == "__main__":
    solve()
```実装は DP 定義に直接準拠します。 の`NEG`Sentinel は、到達不能な状態が伝播しないことを保証します。 ネストされたループオーバー`h`状態と状態ごとに 2 つの遷移により、期待される結果が得られます。`O(nh)`複雑。 

よくある間違いは、各遷移の後にモジュロを取るのを忘れることです。 もう一人は更新中です`dp`これにより、さまざまなステップの状態が混在し、正確さが失われます。 別のものを使用する`ndp`アレイはこの汚染を防ぎます。

 | 0 | dp[0]=0 | 開始 | - |
 | 1 | dp[0]=0 | +2→2、+1→1 | dp[2]=1、dp[1]=1 |

 ## 特殊なケース

 などの1時間ごとが良いケース`l = 0, r = h - 1`、すべてのトランジションに 1 が加算されます。DP は引き続き機能しますが、実質的にはステップ数になります。 たとえば:

 入力:```
n=3, h=5, l=0, r=4, a=[1,2,3]
```それぞれのステップで、すべての`nt`条件を満たすため、トランジションごとにスコアが増加します。 DP は正しく生成します。`3`パス関係なく。 

間隔が狭い場合など`l = r = 0`DP に正確な残基を追跡するよう強制します。 たとえば:

 入力:```
n=2, h=4, l=0, r=0, a=[1,1]
```正確に残基 0 に到達するパスのみが寄与します。 DP は各ステップで複数の候補残基を正しく保存し、制約が満たされた場合にのみカウントします。 

到達不能な状態が多数あるケースは、その理由を示しています。`NEG`センチネルは必要だ。 これがないと、無効な遷移が誤って伝播し、結果が膨張してしまいます。
