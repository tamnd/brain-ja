 ## 解決策
 ## 問題の理解

 垂直地形を表す一連の柱の高さが与えられます。 各列には、初期の数のブロックが積み重ねられています。 利用可能な唯一の操作は、列を繰り返し選択し、その列の高さを 2 増やす固定垂直ピースを配置することです。配置するたびに、自動グローバル「重力ステップ」があり、少なくとも 1 つの列がゼロになるまで、すべての正の列を繰り返し 1 ずつ減らします。その時点で、その配置サイクルのプロセスは停止します。 

したがって、各サイクルは次のように動作します。つまり、選択した 1 つの位置を 2 だけブーストし、その後、最小の高さがゼロになるまで構成全体が均一に減少します。 

問題は、あるサイクル数の後、最終的にすべての列が同時にゼロになるような一連の列選択が存在するかどうかです。 

制約は小さく、テスト ケースの数は最大 100、テスト ケースあたりの列数は最大 100 であるため、O(n^2) または O(n^3) の推論アプローチも許容されますが、操作の構造は、実現可能性を決定する直接算術不変条件があることを示唆しています。 

微妙な点は、プロセスが列ごとに独立していないことです。 すべての操作は均一な減算ステップを通じてグローバルに相互作用するため、貪欲なシミュレーションは誤解を招きます。 

各列を独立して処理できると仮定すると、単純な間違いが発生します。 たとえば、問題を「すべての高さを均等にする」または「ブロックをローカルでペアにする」として扱うと失敗します。 もう 1 つの間違った直感は、常に最小または最大の列を固定することでサイクルを貪欲にシミュレートすることですが、グローバルな減算によりすべての値がロックステップで変更され、局所性が破壊されます。 

## アプローチ

 ブルートフォースアプローチでは、各ステップで 2 ブロックのピースをどこに配置するかについて、考えられるすべての選択肢をシミュレートしようとします。 各配置の後、すべての肯定的なエントリから 1 を繰り返し減算し、続行します。 各ステップの分岐係数は n で、深さは全体の高さの減少に比例し、列ごとに 100 に達することがあります。 これは可能なシーケンスで指数関数的な爆発を引き起こすため、実行不可能です。 

重要な洞察は、動的シミュレーションの観点から考えるのをやめ、代わりにプロセスをパリティと総質量の変換として解釈することです。 

1 つの完全なサイクルに集中します。 配列内の最小の高さが m であるとします。 列 i にピースを配置した後、その列は 2 増加し、次に m+2 倍の 1 単位を減算します (加算後の最小値は選択に応じて m または m+2 になりますが、システムは常にゼロが表示されるまで消耗します)。 重要な観察は、このシステムはすべての正の要素から繰り返し 1 を取り除くことと同等であるため、重要なのは絶対的な高さではなく、最小値との相対的な差であるということです。 

それをより構造的に見る方法は、プロセスを逆に見ることです。 2 を加算してからグローバルに減算することを考える代わりに、逆演算を繰り返し適用してゼロ ベクトルに到達したいと想像してください。つまり、すべての正の要素を 1 ずつ増やし、場合によっては、選択した 1 つの要素を 2 ずつ減らすことになります。これにより、問題はパリティ制約のバランスをとることに変わります。 

各列は独立してモジュロ 2 に寄与しますが、グローバル演算は、各サイクルがすべての正のエントリを均等に削減するという事実を通じてそれらを結合します。 これは古典的な不変式につながります。つまり、奇数の高さの列の数のパリティによって、システムを完全に削除できるかどうかが決まります。 

特に、パリティがどのように進化するかを調べると、+2 を加算してもパリティは変化しませんが、グローバルな減算では、各フェーズでアクティブな列の数が奇数か偶数かに応じてパリティが反転します。 最終的に完全なキャンセルを可能にする唯一の安定した条件は、高さの合計が偶数でなければならないことです。

これは、各サイクルがアクティブな各列から正確に k 個のユニットを削除することを考慮することで検証できます。ここで、k は最小値に依存し、プロセスでは合計のモジュロ 2 が保存されます。各操作では 2 が加算され、グローバルな減算によってすべての列にわたって偶数が削除されるため、合計のパリティは不変です。 したがって、すべてのゼロ (合計ゼロ) に達することは、最初の合計が偶数である場合にのみ可能です。 

この条件も十分です。合計が偶数であれば、許可された操作による再分配を繰り返して、すべての単位の高さをペアにすることができます。

 ## アルゴリズムのチュートリアル

 1. すべての列の高さの合計を計算します。 これにより、最終的に除去する必要がある合計の「質量」が取得されます。 ターゲット状態の合計はゼロであるため、合計のパリティが追跡する重要な量になります。 
2. この合計が偶数であるかどうかを確認します。 それが奇妙であれば、すぐに不可能であると結論付けます。 これは、許可されたすべての操作が合計のパリティを維持するという事実からわかります。 
3. 合計が偶数の場合、有効な一連の操作が存在すると結論付けられます。 構築は必須ではなく、存在とパリティのみが完全な特徴付けとして十分です。 

### なぜ効果があるのか

 不変式は、すべての高さの合計のパリティです。 各演算は、1 つの列に 2 を加算し、すべてのアクティブな列から同じ量を減算することで構成され、合計が偶数に変化します。 したがって、合計のパリティはプロセス全体を通じて決して変化しません。 最終状態の和は偶数であるゼロであるため、初期和も偶数でなければなりません。 逆に、パリティ条件が成立する場合、演算の構造によりユニット寄与のペアが許可されるため、すべての高さ寄与を一貫して除去でき、ゼロ構成への到達可能性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        s = sum(a)
        if s % 2 == 0:
            print("YES")
        else:
            print("NO")

if __name__ == "__main__":
    solve()
```実装はテスト ケースごとに合計を直接計算し、そのパリティをチェックします。 インバリアントはシステム全体を単一の整数プロパティに還元するため、プロセスをシミュレートしたり、中間状態を追跡したりする必要はありません。 

唯一の微妙な実装の詳細は、合計に 64 ビットの安全なアキュムレータを使用することですが、Python では整数のオーバーフローは問題になりません。 残りは、テスト ケースを単純に反復することです。

正しい解釈は、貪欲なペアリングの観点につながります。つまり、一様な崩壊によって作成された隣接する欠損を効果的に一致させます。これにより、システムは常に構造化された方法でサイズ 2 のブロックに縮小されます。 この正しい解釈の下では、最初のサンプルは有効なシーケンスを許可します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        out.append("YES" if sum(a) % 2 == 0 else "NO")
    return "\n".join(out)

 ## 特殊なケース

 次のような最小限の単一列のケース`[1]`システムにはグローバル削減ルールに基づいて奇数の単一ユニットを削除する方法がないため、すぐに失敗します。 アルゴリズムはパリティによってそれを正しく拒否します。 

次のような単一列の偶数の場合`[2]`単一の 2 ブロックの配置が折りたたみステップの後に直接ゼロに解決され、受け入れ条件と一致するため、成功します。 

以下のような均一性の高い配列`[2,2,2]`構造が順序付けに依存せず、集合的な実現可能性のみに依存し、アルゴリズムがそれらを一貫して受け入れることを示しています。 

混合シーケンスのような`[1,2,3,4,5]`ローカル構造は無関係であり、アルゴリズムが単一の集約条件を通じて正しく捕捉するグローバル不変条件のみが重要であることを確認します。
