 ## 解決策
 ## 問題の理解

 トピックのリストが与えられ、各トピックには 2 つの異なるスコアが含まれます。 1 つのスコアは、そのトピックが教師にとってどれだけ興味深いかを測定し、もう 1 つのスコアは、そのトピックが生徒にとってどれだけ興味深いかを測定します。 2 つの異なるトピックについて$i$そして$j$、私たちは、それらの組み合わせが「教師に有利」であるかどうか、つまり、教師の関心の合計が生徒の関心の合計を超えるかどうかを知りたいと考えています。$$a_i + a_j > b_i + b_j.$$タスクはペアの数を数える事です$(i, j)$と$i < j$この条件を満たします。 

これを再解釈する便利な方法は、両方の配列をトピックごとの単一の派生値に折りたたむことです。$$d_i = a_i - b_i.$$すると条件は次のようになります。$$d_i + d_j > 0.$$したがって、変換された値の合計が正の数になるペアを数えています。 

制約により、最大で$2 \cdot 10^5$トピックス。 すべてのペアにわたる二次スキャンには約$2 \cdot 10^{10}$最悪の場合の比較は、Python で処理できる 2 秒の制限をはるかに超えています。 これにより、ブルートフォース列挙が即座に排除されます。 

よくある微妙な落とし穴は、符号の対称性の取り扱いを誤ることです。 たとえば、多くの値が負の場合、混合ペアが重要であるため、「正の値を数えて乗算する」などの単純な考えは失敗します。 もう 1 つの問題は、他の言語からの直感のオーバーフローですが、ここでは Python がそれを回避します。 本当の課題は効率的に注文することです。 

エッジ ケースには、すべての差が正である場合 (すべてのペアが有効)、および差がすべて負である場合 (どのペアも有効ではない) が含まれます。 ソートされた構造を適切に分離しない不注意な実装では、そのような極端な場合でも不正確な部分カウントが生成される可能性があります。 

## アプローチ

 ブルートフォースソリューションはすべてのペアをチェックします$(i, j)$、計算します$a_i + a_j$、と比較します$b_i + b_j$、条件が成立した場合にカウンターをインクリメントします。 これは、適切なペアの定義を直接実装しているため、正しいです。 ただし大まかに評価する必要がある$n(n-1)/2$ペア、つまり約$2 \cdot 10^{10}$操作時の操作$n = 2 \cdot 10^5$、実行不可能になります。 

重要な単純化は、差異を使用して不等式を書き直すことによって実現されます。$d_i = a_i - b_i$。 今の条件は$d_i + d_j > 0$、または同等の$d_i > -d_j$。 これにより、問題はソートされた配列に対する古典的なカウント タスクに変換されます。要素ごとに、その右側にその否定よりも大きい要素がいくつあるかを知りたいと考えます。 

並べ替えにより、二分検索または 2 ポインター スイープが可能になります。 並べ替えたら、それぞれ$d_i$、最初の位置を見つけることができます$j$そのような$d_j > -d_i$、およびそれ以降のすべての要素は有効なペアに寄与します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^2)$|$O(1)$| 遅すぎる |
 | ソート + 二分探索 / 2 つのポインタ |$O(n \log n)$|$O(1)$追加（または$O(n)$) | 承認済み |

 ## アルゴリズムのチュートリアル

 変換された配列を使用して問題を解決します$d$。 

1. コンピューティング$d_i = a_i - b_i$トピックごとに。 

これにより、各トピックの不等式への寄与が分離され、ペアリングが単純な合計条件になります。 
2. 配列をソートする$d$降順ではない順に。 

並べ替えると単調な構造が得られます。これは、しきい値を超える要素の数を効率的にカウントするために不可欠です。 
3. インデックスごとに$i$、しきい値を定義します$-d_i$。 

何個か数えたい$j > i$満足する$d_j > -d_i$。 これにより、ペア条件が範囲カウント問題に変換されます。 
4. 二分探索 (または 2 つのポインター) を使用して、最初のインデックスを見つけます。$pos$どこ$d[pos] > -d_i$。 

からのすべてのインデックス$pos$に$n-1$～と有効なパートナーを形成する$i$、不等式を満たすためです。 
5.追加$n - \max(pos, i+1)$答えに。 

次のペアのみをカウントするようにします。$j > i$重複を避けるため。 
6.全体の貢献度を合計する$i$。 

有効な各ペアは、ソートされた順序で小さいインデックスを処理するときに 1 回だけカウントされます。 

### なぜ効果があるのか

 正しさは 2 つの特性に基づいています。 まず、不等式を次のように書き換えます。$d_i + d_j > 0$解空間を変更せずに等価性を維持します。 第 2 に、ソートにより、固定の$i$、有効なセット$j$インデックスは配列のサフィックスを形成します。$d_j > -d_i$単調な条件を定義します。 この単調性により、二分探索または 2 つのポインターがペアを欠落したり二重にカウントしたりすることなく、すべての有効なパートナーを捕捉することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))
b = list(map(int, input().split()))

d = [a[i] - b[i] for i in range(n)]
d.sort()

ans = 0

import bisect

for i in range(n):
    # we need d[j] > -d[i] with j > i
    target = -d[i]
    pos = bisect.bisect_right(d, target)
    if pos <= i:
        pos = i + 1
    ans += n - pos

print(ans)
```コードは最初に差分配列を構築します。これは、トピックが教師に好まれるのか、学生に好まれるのかをエンコードします。 並べ替えによりこれらの値が編成され、すべての比較が範囲クエリに集約されます。 

ポジションごとに、有効なパートナーが使用を開始できる最小のインデックスを計算します。`bisect_right`。 次に、現在のインデックスより厳密に大きいインデックスのみをカウントするようにします。 最後の引き算`n - pos`すべての有効なパートナーを効率的にカウントします。 

細かい部分の調整です`if pos <= i`、2 番目のインデックスが満たさないペアをカウントするのを防ぎます。$j > i$。 この修正がないと、セルフペアリングまたは逆順序が誤って含まれてしまいます。 

## 実用的な例

 ### 例 1

 入力:```
n = 5
a = [4, 8, 2, 6, 2]
b = [4, 5, 4, 1, 3]
```私たちは計算します$d = a - b = [0, 3, -2, 5, -1]$、次に並べ替えます:$$d = [-2, -1, 0, 3, 5]$$次に、各インデックスを評価します。 

| 私 | d[i] | -d[i] | pos (最初の d[j] > -d[i]) | ペアが貢献しました |
 | --- | --- | --- | --- | --- |
 | 0 | -2 | 2 | 3 | 2 |
 | 1 | -1 | 1 | 3 | 2 |
 | 2 | 0 | 0 | 3 | 2 |
 | 3 | 3 | -3 | 0 (4に調整) | 1 |
 | 4 | 5 | -5 | 0 (5に調整) | 0 |

 合計は7です。 

このトレースは、負の値が多くの有効なペアに寄与する一方、大きな正の値は、すでに以前の要素のほとんどを支配しているため、ほとんど寄与しないか、まったく寄与しないかを示しています。 

### 例 2

 入力:```
n = 4
a = [5, 1, 4, 2]
b = [1, 2, 3, 4]
```それから$d = [4, -1, 1, -2]$、並べ替え:$$d = [-2, -1, 1, 4]$$| 私 | d[i] | -d[i] | 位置 | ペア |
 | --- | --- | --- | --- | --- |
 | 0 | -2 | 2 | 3 | 1 |
 | 1 | -1 | 1 | 3 | 1 |
 | 2 | 1 | -1 | 3 | 1 |
 | 3 | 4 | -4 | 4 | 0 |

 合計は 3 です。 

これは、十分に大きなプラスの差だけが初期のマイナスの差とペアになり得ることを示しています。

## テストケース```python
import sys, io

def solve():
    input = sys.stdin.readline
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    d = sorted(a[i] - b[i] for i in range(n))

    import bisect
    ans = 0
    for i in range(n):
        pos = bisect.bisect_right(d, -d[i])
        if pos <= i:
            pos = i + 1
        ans += n - pos
    print(ans)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    from io import StringIO
    old_stdout = sys.stdout
    sys.stdout = StringIO()
    solve()
    out = sys.stdout.getvalue()
    sys.stdin = old_stdin
    sys.stdout = old_stdout
    return out.strip()

# provided sample
assert run("""5
4 8 2 6 2
4 5 4 1 3
""") == "7"

# all equal differences
assert run("""3
1 1 1
1 1 1
""") == "0"

# strictly increasing advantage
assert run("""4
1 2 3 4
0 0 0 0
""") == "6"

# strictly negative differences
assert run("""4
1 1 1 1
2 2 2 2
""") == "0"

# mixed case
assert run("""5
5 1 4 2 3

""") >= "0"

 ## 特殊なケース

 いつすべて$a_i = b_i$、 毎$d_i = 0$, したがって、厳密な不等式を満たすペアはありません。 このアルゴリズムはゼロをソートし、正の合計を持つインデックスを見つけず、ゼロを正しく生成します。 

いつすべて$a_i$よりもはるかに大きい$b_i$、 毎$d_i$は正であるため、すべてのペアが寄与します。 ソート後の各閾値$-d_i$は負であるため、すべての接尾辞は有効であり、アルゴリズムの合計は次のようになります。$n(n-1)/2$。 

いつすべて$a_i$よりも小さい$b_i$、 毎$d_i$はマイナスです。 並べ替えた後でも、どのペアの合計も正の値にならないため、すべてのバイナリ検索では有効範囲を超える位置が返され、予想どおりゼロが返されます。
