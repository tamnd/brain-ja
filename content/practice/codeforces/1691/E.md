 ## 解決策
 ## 問題の理解

 数直線上に、それぞれが赤または青に色付けされた一連のセグメントが与えられます。 各セグメントは、からの連続した間隔を占めます。`l_i`に`r_i`、包括的。 このタスクは、2 つのセグメントの色が異なり、間隔が重なっている場合に、2 つのセグメントが接続されているとみなされるセグメントのグループを見つけることです。 セグメントは、交互の色のチェーンを通じて間接的に接続できます。 出力は、各テスト ケースのそのような接続されたグループの合計数です。 

この制約により、すべてのテスト ケースにわたるセグメントの合計数が次を超えないことがわかります。`10^5`。 これは、あらゆるアルゴリズムを意味します。`O(n^2)`テストケースごとに実行すると遅すぎます。 理想的には、テスト ケースごとにほぼ線形または線形的なソリューションが必要です。`O(n log n)`。 

素朴なアプローチに引っかかる可能性のあるエッジ ケースには、端点を共有しているがそれ以上は重なり合わないセグメント、同じ色の複数のセグメントが互いに完全に重なり合っている、または色が交互になっているが接続を破壊するギャップがあるセグメントなどが含まれます。 たとえば、3 つのセグメント`(0, 0, 1)`、`(1, 1, 2)`、`(0, 3, 4)`最後の赤いセグメントは、青いセグメントに順番に続いているにもかかわらず、青いセグメントと重ならないため、3 つの別々のグループが形成されます。 

## アプローチ

 ブルートフォース手法では、セグメントのすべてのペアを反復処理し、セグメントが重なっていないか、異なる色を持っているかどうかを確認します。 それらが存在する場合は、DSU (disjoint set Union) のようなデータ構造を使用して、それらをグループに結合します。 これは正しいですが、確認が必要です`O(n^2)`到達できるペア`10^10`制限時間を大幅に超える最大の入力に対する操作。 

重要な洞察は、反対色のセグメントが現在のグループに接続されているかどうかを判断するには、色ごとに、これまでに到達した最も右の点を追跡するだけでよいということです。 セグメントを開始点で並べ替え、左から右にスイープすることで、セグメントを効率的にグループにマージできます。 これにより、問題は 2 つの並べ替えられたリスト (赤用と青用に 1 つ) をスキャンし、最大リーチを維持し、反対色の最も遠い点の後にセグメントが開始されるたびにグループ カウントを増分するという問題に軽減されます。 

この観察は素朴な考えを変えます`O(n^2)`管理可能な状態へのアプローチ`O(n log n)`ソリューションはソート操作によって支配されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | スイープ + 最大リーチ | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. セグメントを色別に赤と青の 2 つのリストに分けます。 各リストを左のエンドポイントで並べ替えます`l_i`。 
2. 2 つの変数を初期化する`max_red`そして`max_blue`各色の現在のアクティブなグループ内のセグメントの右端の端点を追跡します。 
3. グループカウンターの初期化`groups`これにより、接続されたグループがカウントされます。 
4. ソートされた 2 つのリストを左から右の順序で結合します。 各セグメントについて、反対色の現在の最大リーチと重複するかどうかを確認します。 
5. セグメントが反対色の最大エンドポイントと重なっている場合は、そのセグメントを現在のグループにマージし、その色の最大エンドポイントを更新します。 
6. 反対色の最大到達後にセグメントが開始する場合、このセグメントは切断された新しいグループを開始するため、グループ カウンタをインクリメントします。 リセット`max_red`そして`max_blue`それに応じて。 
7. すべてのセグメントが処理されるまで続行します。 最終的な値は、`groups`接続されているグループの数です。 

機能する理由: 赤と青のセグメントの最大右端点を常に追跡することにより、反対色の最大値より前または最大値で始まるセグメントはすべて同じグループに属している必要があります。 この時点を超えて開始されるセグメントは前のセグメントに接続できないため、新しいグループが開始されます。 並べ替えにより、セグメントが正しい順序で処理され、重複が正しく処理されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        red, blue = [], []
        for _ in range(n):
            c, l, r = map(int, input().split())
            if c == 0:
                red.append((l, r))
            else:
                blue.append((l, r))
        red.sort()
        blue.sort()
        
        i, j = 0, 0
        max_red, max_blue = -1, -1
        groups = 0
        
        events = []
        for l, r in red:
            events.append((l, r, 0))
        for l, r in blue:
            events.append((l, r, 1))
        events.sort()
        
        for l, r, color in events:
            if color == 0:
                if l > max_blue:
                    groups += 1
                    max_red, max_blue = r, -1
                else:
                    max_red = max(max_red, r)
            else:
                if l > max_red:
                    groups += 1
                    max_blue, max_red = r, -1
                else:
                    max_blue = max(max_blue, r)
        
        print(groups)

if __name__ == "__main__":
    solve()
```このコードは、まずセグメントを色ごとに分離して並べ替えます。 すべてのセグメントを開始点の順にマージし、各色が到達する最大の終了点を維持します。 セグメントが反対色の最大値の後に開始すると、新しいグループが開始されます。 新しいグループの最大リーチを正しくリセットするように注意してください。そうしないと、離れたセグメントが誤ってマージされる可能性があります。

 次のようなエンドポイントで接触するだけのセグメント`(0,0,2)`そして`(1,2,4)`範囲が含まれるため、接続されているとみなされます。 アルゴリズムは次のように比較するため、これを正しく処理します。`l > max_opposite`新しいグループを検出します。 開始値が反対色の最大値と等しい場合でも、それらはマージされます。 遠く離れたセグメント、たとえば`(0, 10, 12)`前回の max_blue が 4 になった後、期待どおりに新しいグループが開始されます。 この処理により、グループのカウントで 1 つずつの間違いが発生しないことが保証されます。
