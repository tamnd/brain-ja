 ## 解決策
 ## 問題の理解

 整数のシーケンスが与えられているので、残りのシーケンス内の連続する数値の各ペアの合計が偶数になるように、できるだけ少ない数値を削除する必要があります。 2 つの数値の合計は、両方の数値が偶数であるか、両方の数値が奇数の場合でも偶数です。 したがって、この条件は、残りのシーケンスが連続した位置にあるすべての偶数またはすべての奇数で構成されている必要があるという要件に変換されます。 元の数値の順序に制約されることはありませんが、維持する順序は維持する必要があります。 要素を並べ替えることはできません。 

入力は複数のテスト ケースで構成されます。 各テスト ケースは、シーケンスの長さとシーケンス自体を提供します。 すべてのテスト ケースにわたる要素の合計数は 100,000 を超えません。 この限界は、シーケンスの長さに比べて線形複雑度より悪い解は遅すぎる可能性があることを意味します。 O(n^2) 動作のアルゴリズムは、最悪の場合、約 100 億回の演算を実行するため、除外されます。 線形または線形算術的アプローチが実現可能です。 

微妙なエッジ ケースは、シーケンスがすでに有効である場合です。たとえば、`[3, 5, 9, 7]`。 ここでは、連続するペアはすべて偶数であるため、削除する必要はありません。 もう 1 つの注意が必要なケースは、シーケンスで次のようにパリティが交互に切り替わる場合です。`[2, 3, 4, 5]`。 最初の違反だけを調べる単純なアプローチでは、間違った要素が削除され、必要以上の削除が必要になる可能性があります。 正しいアプローチでは、奇数と偶数の合計数を理解し、最小限の削除を決定する必要があります。 

## アプローチ

 ブルートフォース手法では、シーケンスを反復処理し、連続するペアの合計が奇数になるたびに要素を貪欲に削除しようとします。 違反しているペアの最初または 2 番目の要素を削除して、シーケンスのチェックを再帰的に続行することもできます。 この方法は、番号を削除すると違反が解消されるため機能しますが、すぐに非効率になります。 それぞれの削除により、残りのシーケンスのほぼ全体が検査される再帰呼び出しが行われる可能性があり、最悪の場合の複雑さは O(n^2) になります。 n が 100,000 までの場合、これは遅すぎます。 

重要な洞察は、両方の数値が同じパリティを共有する場合にのみ、連続するペアの合計が偶数になるということです。 これは、最終シーケンスにはすべて同じパリティの数値が含まれている必要があることを意味します。 したがって、最適な解決策は、すべての偶数を保持するか、すべての奇数を保持するかを単純に決定することです。 最小除去数は、偶数と奇数のカウントの小さい方です。 パリティは位置に依存しないため、個々の要素の削除をシミュレートしたり、各ペアをチェックしたりする必要はありません。 この観察により、問題はパリティをカウントするための線形スキャンに帰着し、テスト ケースごとに O(n) 時間が与えられます。

 ## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取ります。 各テスト ケースは個別に処理されます。 
2. 各テスト ケースについて、シーケンスの長さとシーケンス自体を読み取ります。 
3. 2 つのカウンタを初期化します。1 つは偶数用、もう 1 つは奇数用です。 
4. シーケンスを繰り返します。 各要素について、2 で割り切れる場合は偶数カウンタをインクリメントし、2 で割り切れない場合は奇数カウンタをインクリメントします。 
5. 偶数の数と奇数の数の間の最小値を計算します。 より大きなグループを維持すると、連続合計条件を満たしながら要素の最大数が維持されるため、これは必要な削除の最小数です。 
6. テスト ケースのこの最小数を出力します。 

機能する理由: すべての数値のパリティを数えると、残りのすべての数値が同じパリティを共有するために削除する必要がある要素の数が正確にわかります。 これにより、連続するすべてのペアの合計が偶数になることが保証されます。 他の構成では、奇数と偶数が混在すると、少なくとも小さいグループのサイズと同じ数の違反が必然的に発生するため、削除を少なくすることはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    even_count = sum(1 for x in a if x % 2 == 0)
    odd_count = n - even_count
    print(min(even_count, odd_count))
```このコードは、高速 I/O を使用してすべての入力を効率的に読み取ります。 1 回のパスで偶数と奇数の数をカウントし、2 つのカウントの最小値を出力します。 使用する`n - even_count`奇数のカウントを計算することで 2 番目のループが回避され、コードがよりクリーンになり、わずかに高速になります。 エッジケースは自然に処理されます。すべての数値が偶数の場合、`odd_count`はゼロであるため、最小値はゼロであり、削除の必要がないことを正しく示しています。

 最小限の`even_count`そして`odd_count`は 1 です。単一の奇数 3 を削除すると、次のようになります。`[2,4,6,8]`、条件を満たします。

 入力シーケンス:`[3, 5, 9, 7, 1, 3]`| 要素 | パリティ | 偶数カウント | 奇数数 |

 | 7 | 奇数 | 0 | 4 |
 | 1 | 奇数 | 0 | 5 |
 | 3 | 奇数 | 0 | 6 |

 最小限の`even_count`そして`odd_count`は 0 です。すべての数値が奇数であるため、削除する必要はなく、連続する合計は偶数になります。

 ## 特殊なケース

 シーケンスに同じパリティの要素がすべて含まれている場合、アルゴリズムは正しく 0 を出力します。たとえば、次のようになります。`[2,4,6]`結果として`even_count=3`、`odd_count=0`、`min(even_count, odd_count)=0`。 シーケンスが交互パリティである場合、次のようになります。`[2,3,4,5]`、カウントは`even_count=2`、`odd_count=2`これにより、アルゴリズムが除去を過小評価することがなくなります。 単一要素シーケンスは自然に処理されます。`even_count`または`odd_count`は 1、もう一方は 0 であるため、最小値は 0 です。この解は、すべての有効な入力にわたってロバストです。
