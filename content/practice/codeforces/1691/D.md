 ## 解決策
 ## 問題の理解

 与えられた整数配列について、隣接する部分配列の最大値が少なくともその部分配列の合計と同じくらい大きいかどうかを判断するように求められます。 簡単に言うと、配列の考えられるすべてのセグメントについて、単一の最大の数値がそのセグメント内のすべての数値の合計より小さくてはなりません。 合計が最大要素を超える部分配列が 1 つでも存在する場合、答えは「いいえ」です。 それ以外の場合は「YES」です。 

入力は複数のテスト ケースを提供し、それぞれの長さは最大 200,000 の配列を持ち、すべてのテスト ケースの要素の合計数は 200,000 に制限されます。 各要素の範囲は -10^9 から 10^9 までです。 n が最大 2・10^5 で、制限時間が 2 秒であることを考えると、テスト ケースごとに O(n) よりも複雑なアルゴリズムは遅すぎる可能性があります。 これにより、すべての部分配列を明示的に検査しようとするアプローチは除外されます。これは、配列ごとに O(n²) の演算が必要となり、最悪の場合 4·10¹⁰ に達する可能性があるためです。 

明らかではないエッジ ケースは、配列に負の値が隣接する大きな正の数が含まれる場合に発生します。 たとえば、配列 [-1, 5, -1] では、すべての部分配列の合計は最大 5 で、最大要素は 5 です。単純なアプローチでは、長さ 2 または 3 の部分配列を考慮しない場合、または合計を減らす負の値を考慮せずに隣接する合計のみを調べる場合は失敗する可能性があります。 もう 1 つのエッジ ケースは、[1, 2, 3] のような厳密に増加する正の数のシーケンスです。この場合、最初の 2 つの要素の合計は 3 で、これはその部分配列の最大値に等しいですが、次の要素を追加すると、これまでの最大の要素よりも大きな合計が生成され、条件に違反します。 

## アプローチ

 ブルートフォース手法では、考えられるすべての部分配列を調べ、それらの合計と最大値の両方を計算し、それぞれの条件を検証します。 サイズ n の配列の場合、およそ n(n+1)/2 個のサブ配列があり、それぞれの合計または最大値を個別に計算するには O(n) 時間がかかり、合計の複雑さは O(n³) になります。 データ構造を使用してプレフィックスの合計とセグメントの最大値を使用した場合でも、サブ配列の数だけでは、このアプローチは n = 2·10^5 では実行不可能になります。 

重要な観察は、条件が失敗する場合、ある意味で合計が局所的に最大になる部分配列で条件が失敗する必要があるということです。 負の要素は合計を減らすだけであるため、最も危険な部分配列は、最初の要素から始まるか、最後の要素で終わる連続したセグメントです。 言い換えれば、すべての適切なサブ配列 (配列全体を含まないサブ配列) のプレフィックスの合計とサフィックスの合計をチェックするだけで済みます。 すべての適切なプレフィックスとサフィックスの合計が、その部分配列内の最大要素を超えない場合、条件は成立します。 

これにより、最大プレフィックス合計と最大サフィックス合計を効率的に計算し、それらを隣接する要素と比較するという問題が軽減されます。 実際には、配列を反復処理して、適切なサブ配列のプレフィックスまたはサフィックスの合計が配列全体の最大値より厳密に大きくなるかどうかを確認するだけで十分です。 そのような部分配列が存在する場合、答えは「いいえ」です。 それ以外の場合は「YES」です。 このアプローチは、テスト ケースごとに O(n) です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n3) | お(1) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

1. テスト ケースごとに、配列を読み取り、その最大要素を特定します。 合計がこの最大値を超えてはいけないため、これが不等式を満たす候補となります。 
2. アレイの適切なプレフィックスをすべて確認します。 累計をゼロに初期化します。 最初の要素から最後から 2 番目の要素までを繰り返し、各要素を累計に加算します。 いずれかの時点で累計が配列の最大値を超えた場合は、条件に違反しているため、すぐに「NO」を返します。 
3. 配列の適切なサフィックスをすべて確認します。 累計をゼロにリセットし、最後の要素から 2 番目の要素まで繰り返して、各要素を累計に加算します。 繰り返しますが、合計が最大要素を超える場合は、「NO」を返します。 
4. 違反しているサブ配列が見つからずに両方のチェックが完了した場合は、条件がその配列に当てはまるため、「YES」を返します。 

直観的には、この不等式が厳密であるのは、配列の一部の接頭辞または接尾辞である部分配列についてのみです。 内部に完全に含まれるサブ配列はプレフィックスとサフィックスに分解できます。負の数は合計を減らすだけなので、条件がすべてのプレフィックスとサフィックスに当てはまる場合は、すべてのサブ配列にも当てはまります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        max_val = max(a)

        # check prefixes
        prefix_sum = 0
        valid = True
        for i in range(n - 1):
            prefix_sum += a[i]
            if prefix_sum > max_val:
                valid = False
                break

        # check suffixes
        if valid:
            suffix_sum = 0
            for i in range(n - 1, 0, -1):
                suffix_sum += a[i]
                if suffix_sum > max_val:
                    valid = False
                    break

        print("YES" if valid else "NO")

if __name__ == "__main__":
    solve()
```コードは最初に最大要素を特定します。 次に、最初の要素から最後から 2 番目までのプレフィックスの合計をチェックします。これは、最後の要素を含める必要がないためです。配列全体の合計が最大値を超えると、配列自体が禁止されている条件に違反することになります。 同様に、接尾辞のチェックは最後の要素から 2 番目の要素まで実行されます。 条件に違反すると各ループが直ちに中断され、速度が最適化されます。

## 特殊なケース

 [100] のような単一要素配列の場合、アルゴリズムは最大値を 100 として計算します。n-1 がゼロであるため、プレフィックス ループとサフィックス ループは両方ともスキップされ、条件は自動的に合格し、YES が出力されます。 

[-5, -3, -2] など、すべて負の数値を含む配列の場合、プレフィックスの合計は負から始まり、最大値の -2 を超えることはありません。 接尾辞の合計も同様に -2 未満のままです。 アルゴリズムは正しく YES を返します。
