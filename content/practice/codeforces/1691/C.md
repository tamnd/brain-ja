 ## 解決策
 ## 問題の理解

 長さのバイナリ文字列が与えられます$n$そして、すべての連続する数字のペアから計算される合計を最小化したいと考えています。 各数字のペア$s_i s_{i+1}$は 10 進数として扱われるため、「10」は 10 としてカウントされ、「01」は 1 としてカウントされます。 目標は、文字列を最大で再配置することです。$k$この合計をできるだけ小さくするために、隣接する要素を交換します。 

文字列は最大までなので、$10^5$文字を含めることができます$10^5$合計を含むテストケース$n$すべてのテストで以下を超えない$10^5$, our solution must process each test case in linear time. Any algorithm that examines all permutations of the string or even attempts to simulate all adjacent swaps would be too slow.

 The non-obvious edge cases involve strings where moving a '1' to either end reduces the sum efficiently. たとえば、文字列が「1000」の場合、$k = 1$、「1」を最後に向かって 1 つ移動して、最大の寄与を最小限に抑えることができます。 別のエッジ ケースは、文字列がすでに「0」で始まるか終わる場合に発生します。その場合、「1」を移動する必要がない場合があります。 不注意なアプローチでは、無差別に「1」を交換しようとして、次の値を超える可能性があります。$k$操作を失敗したり、右側の「1」を文字列境界に移動する優先順位を付けなかったりします。 

## アプローチ

 ブルート フォース ソリューションでは、考えられるすべてのシーケンスが試行されます。$k$隣接するスワップを計算し、各構成の合計を計算します。 各スワップは 2 つの隣接する位置にのみ影響するため、$n$キャラクターと$k$スワップにより、到達可能な状態の数は指数関数的に増加します。$n$そして$k$。 のために$n \sim 10^5$、これは不可能です。 

重要な洞察は、合計への最大の寄与は、「1」が文字列の末尾または先頭にあるペアから来ているということです。 中央の「1」は 2 つのペア、つまり、それで終わるペアとそれで始まるペアに寄与します。 最大の削減は、最大で 2 つの「1」を移動することで得られます (1 つは先頭に、もう 1 つは末尾に)。 残りの「1」は、移動しても合計がそれほど効率的に減らず、不必要なスワップを消費するため、所定の位置に残しておくことができます。 したがって、移動候補である左端と右端の「1」を追跡し、それらを文字列の終端に移動するためのスワップのコストを計算し、与えられた値に余裕があるかどうかを判断するだけで済みます。$k$。 

この貪欲なアプローチは、合計に対する各「1」の寄与が線形であり、文字列境界に移動すると独立しているため機能します。 他のすべての「1」の影響は小さいか同等であるため、極端な点に焦点を当てることで最適性が保証されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n! × k) | O(n) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る$t$。 テスト ケースごとに、次の内容を読んでください。$n$、$k$、および文字列$s$。 
2. 2 つのポインターを初期化します。`left_one`左から最初に出現する「1」まで、および`right_one`右から最初に出現する「1」まで。 
3. 初期合計を計算する$f(s)$連続するすべてのペアを反復処理します。 各ペア「00」は 0、「01」は 1、「10」は 10、「11」は 11 を割り当てます。 
4. 「1」を最後に移動してみます。 スワップのコストは、`right_one`最後の位置まで。 費用が範囲内であれば$k$、この「1」を最後に移動すると、最後のペアへの寄与が「1x」から「0x」に削除されるか、「10」の寄与が減少するため、合計を 10 減らします。 使用したスワップを差し引く$k$。 
5. 「1」を先頭に移動してみます。 コストは距離です`left_one`最初の位置へ。 費用が残りの範囲内であれば$k$、「1」を先頭に移動すると、最初のペア「x1」が「x0」に置き換えられるため、合計が 1 減ります。 
6. 同じ「1」を両端に移動する場合、移動できるのは 1 つだけです。大きい方の 10 の寄与が減少するため、最初にそれを最後に移動することを優先します。 
7. 各テスト ケースの結果の合計を出力します。 

不変条件は、潜在的な各移動の後、文字列の合計が許容されるスワップ数以下で最小化されるということです。 極端な「1」のみを移動すると、次の値を超えない限りそれ以上の削減は不可能になります。$k$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, k = map(int, input().split())
    s = input().strip()
    
    first_one = -1
    last_one = -1
    for i in range(n):
        if s[i] == '1':
            if first_one == -1:
                first_one = i
            last_one = i

    total = 0
    for i in range(n-1):
        total += int(s[i])*10 + int(s[i+1])

    if last_one != -1:
        cost_to_end = n-1 - last_one
        if cost_to_end <= k:
            total -= 10
            k -= cost_to_end
            if first_one == last_one:
                first_one = -1

    if first_one != -1:
        cost_to_start = first_one
        if cost_to_start <= k:
            total -= 1

    print(total)
```このソリューションは、左端と右端の「1」へのポインターを初期化し、文字列から直接合計を計算します。 2 つの潜在的な手が、合計に最も大きな影響を与える手から始めて、貪欲に評価されます。 場合の対処方法`first_one == last_one`二重カウントを防ぎます。 すでに末尾にある「1」を移動するにはゼロスワップが必要なため、境界条件に対処します。 

## 実用的な例

 トレースサンプル 1:「1010」、k = 0

 | 私 | ペア | 貢献 | 合計 |
 | --- | --- | --- | --- |
 | 0 | 10 | 10 | 10 |
 | 1 | 01 | 1 | 11 |
 | 2 | 10 | 10 | 21 |

 スワップは許可されず、合計 = 21、予想される出力と一致します。 

トレースサンプル 3: "00110"、k = 2

 初期合計:

 | 私 | ペア | 貢献 | 合計 |
 | --- | --- | --- | --- |
 | 0 | 00 | 0 | 0 |
 | 1 | 01 | 1 | 1 |
 | 2 | 11 | 11 | 12 |
 | 3 | 10 | 10 | 22 |

 インデックス 3 の「1」を最後に移動します (コスト = 1 ≤ 2)、合計 -= 10 → 12、k = 1。 

インデックス 2 の '1' を移動して開始します (コスト = 2 > 1)。移動できません。 最終的な合計 = 12。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | テスト ケースあたり O(n) | 合計を計算し、最初/最後の '1' を見つけるための 1 回のパス |

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = []
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        s = input().strip()
        first_one = -1
        last_one = -1
        for i in range(n):
            if s[i] == '1':
                if first_one == -1:
                    first_one = i
                last_one = i
        total = sum(int(s[i])*10 + int(s[i+1]) for i in range(n-1))
        if last_one != -1:
            cost_to_end = n-1 - last_one
            if cost_to_end <= k:
                total -= 10
                k -= cost_to_end
                if first_one == last_one:
                    first_one = -1
        if first_one != -1:
            cost_to_start = first_one
            if cost_to_start <= k:
                total -= 1
        output.append(str(total))
    return "\n".join(output)

# custom
assert run("1\n2 1\n10\n") == "1"
assert run("1\n3 2\n111\n") == "21"
assert run("1\n5 10\n00000\n") == "0"
assert run("1\n4 3\n1001\n") == "11"
