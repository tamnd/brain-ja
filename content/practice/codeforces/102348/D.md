 ## 解決策
 ## 問題の理解

 均等な長さのチケットを 2 つの等しい半分に分割しました。 すべての位置にすでに数字が含まれているか、`?`、その数字が消去されたことを意味します。 2人のプレイヤーは交互に残りの1人を選択します`?`からの任意の数字に置き換えます。`0`を通して`9`。 Monocarp が最初に動き、2 つの半分の最終的な合計が異なることを望みます。 Bicarp はこれらの合計が等しいことを望んでいます。 

チケットを表す便利な方法は、個々のポジションの文字列としてではなく、4 つの数量を使用することです。 させて`L`そして`R`左半分と右半分の既知の数字の合計とし、`qL`そして`qR`は、それらの半分の消去された位置の数になります。 ゲーム全体はこれら 4 つの値によって特徴づけられます。 

長さは次のように大きくすることができます`200000`、制限時間はわずか1秒です。 したがって、ソリューションはチケットの長さが線形であるか、線形に近いものである必要があります。 可能な割り当ての大部分を調査するアプローチは不可能です。`10^20`割り当てはすでに処理できる量をはるかに超えています。 メモリ制限は、`O(n)`ただし、入力文字列といくつかのカウンター以外のものを保存する理由はありません。 

単純なソリューションを簡単に壊してしまういくつかのエッジケースがあります。 まず、消去位置のないチケットはすでに決まっています。 例えば、`n = 4`そして`0523`金額が残っています`0 + 5 = 5`そして正しい合計`2 + 3 = 5`、したがって、答えは次のとおりです`Bicarp`。 少なくとも 1 つを想定した実装`?`この事件の扱いを誤る可能性があります。 

第二に、同じ数の疑問符だけでは Bicarp の勝利を保証するものではありません。 例えば：```
4
?123
```ここ`qL = 1`、`qR = 0`, したがって、Monocarp が勝ちます。 初期の固定合計が等しいかどうかのみをチェックする不注意な実装では、誤った出力が発生します。`Bicarp`。 

第三に、固定合計の差が正確に適切なサイズである場合、疑問符の数が等しくない場合でも、Bicarp が勝利する可能性があります。 例えば：```
8
?054??0?
```左側の固定額は`9`、正しい固定額は`0`、 その間`qL = 1`そして`qR = 3`。 疑問符の数の違いは次のとおりです。`2`、 そして`9 * 2 / 2 = 9`、固定合計差額に正確に一致します。 ビカープが勝ちます。 したがって、「疑問符の数が等しくない場合は、Monocarp が勝つことを意味する」などのルールは正しくありません。 

最後に、要因は、`9`すべての疑問符は次のような原因となる可能性があるため、重要です。`0`に`9`。 例えば：```
6
???00?
```定額額は、`0`そして`0`ですが、疑問符の数は`3`そして`1`。 Bicarp が左側の 2 つの余分なポジションを補うことができないため、Monocarp が勝ちます。 疑問符をその全範囲を考慮せずに単に不特定の値として扱うと、実際のゲーム構造を見逃してしまいます。 

## アプローチ

 直接的な総当たりの解決策では、疑問符を置き換えるあらゆる可能な方法が検討されます。 あれば`q`消去された位置にはそれぞれ 10 桁の可能な数字があり、`10^q`完全なチケット。 各位置の数字を再帰的に選択し、最後の 2 つの合計をチェックすることができます。 これは正しいです。考えられるすべてのゲーム結果は検索ツリーの 1 つの葉で表されますが、最悪の場合は`q = 200000`、生産`10^200000`端末の割り当て。 割り当てごとに一定の少量の作業を行う場合でも、これは完全に不可能です。 

このゲームには、任意のミニマックスよりもはるかに多くの構造があります。 最終結果は、2 つの半値和の差にのみ依存します。 まず、すでに固定されているポジションについて考えてみましょう。 定義する

 [
 D = L-R。 
】

 疑問符は、この違いに追加の値を与えます。 両方の半分に同じ数の疑問符がある場合、`D = 0`, Bicarp は、反対側の半分の同じ数字を選択することで、すべての手を答えることができます。 新しく追加された 2 つの貢献はキャンセルされるため、各ペアの移動の後、差はゼロのままになります。 これは直接ペアリング戦略です。 

もし`D = 0`しかし、疑問符の数が異なる場合、ペアリングは不可能です。 Monocarp が最初に移動するため、最終的には一致しない疑問符のある側に移動し、最終的な差がゼロ以外になる可能性があります。 

さて、仮定してください`D != 0`。 概念的に 2 つの半分を入れ替えることができます。`D > 0`、つまり、固定桁によってすでに左半分が大きくなっているということです。 問題は、右半分にそれを補うだけの余分な疑問符があるかどうかです。 

もし`qL >= qR`, Monocarp には、すでに大きい側と少なくとも同じくらい多くの利用可能な手があります。 彼はアドバンテージが修復されるのを防ぐことができるので、Bicarpは平等を強制することができません。 

興味深いケースは、`qL < qR`。 右側には、`qR - qL`余分な疑問符。 疑問符の総数は偶数であるため、この差も偶数になります。 ゲームのペア部分では、プレーヤーは両側から同数の疑問符を効果的にキャンセルできます。 最終的には、右側の余分な疑問符だけが残ります。 

あると仮定します`k = qR - qL`そういったポジション。 以来`k`が偶数である場合、Bicarp はペアで最終的なバランス効果を制御できます。 追加の右側の疑問符の各ペアは、最大でも貢献できます。`9`関連する最適戦略における左側の利点を減らすことに向けて。 したがって、最大補償額は、

 [
 9\frac{k}{2}。 
】

 この金額が固定差に等しい場合、Bicarp が勝ちます。 

[
 D = 9\frac{qR-qL}{2}。 
】

 差が小さい場合、Bicarp は初期のアドバンテージを十分に取り出すことができません。 それが大きい場合でも、残りの利点は依然としてゼロではありません。 平等は、完全なバランスを強制できる唯一の状況です。 

これにより、チケットを 1 回スキャンした後、一定のサイズの決定が得られます。

 ## アルゴリズムのチュートリアル

 1. チケットを概念的に左半分と右半分に分割します。 文字列をスキャンしながら計算します`left_sum`そして`right_sum`固定数字とカウントのみを使用する`left_q`そして`right_q`、各半分に疑問符が表示されます。 これら 4 つの値には、ゲームに必要なすべての情報が含まれています。 
2. 固定合計差額を次のように計算します。`left_sum - right_sum`。 負の場合は、概念的に 2 つの辺を入れ替えます。`left_sum >= right_sum`。 同時に、疑問符の数を交換します。 この正規化の後、固定差は非負となり、左側の利点を表します。 
3. 固定差がゼロの場合、Bicarp は正確に次の時点で勝ちます。`left_q == right_q`。 カウントが等しい場合、Monocarp によるすべての動きは、同じ桁を使用して他の半分の応答と組み合わせることができ、同等性が保たれます。 カウントが等しくない場合、最初のプレイヤーは最終的に比類のない手を取得し、平等を破壊する可能性があります。 
4. 固定差分が正の場合、`left_q >= right_q`、出力`Monocarp`。 すでに先行している側には少なくとも同じ数の疑問符があるため、Monocarp は自分の動きを利用してゼロ以外のアドバンテージを維持できます。 Bicarp は、相手チームにそれを補うほどの比類のないポジションを持っていません。 
5. 固定差分が正の場合、`left_q < right_q`、計算します`extra = right_q - left_q`。 Bicarp は最初の差が正確に一致した場合にのみ勝つことができます`9 * extra / 2`。 疑問符の総数は偶数なので、`extra`は偶数であるため、この値は整数です。 等価が成立する場合、出力`Bicarp`; それ以外の場合は出力`Monocarp`。 

### なぜ効果があるのか

 不変量は、2 つの半和間の現在の差と各辺の未使用の疑問符の数です。 Monocarp が一方の側で値を選択した後、Bicarp はもう一方の側で同じ値を使用できるため、同数の残りの疑問符をペアで無効にすることができます。 これらのペアの位置が削除されると、一致しない疑問符のみが問題になります。 最初に大きい固定合計に少なくとも同数の疑問符がある場合、Monocarp は優位性を維持できます。 それ以外の場合、相手側は正確に`qR - qL`余分なポジションがあり、固定された差を補償する唯一の方法は、それらのポジションが正確に提供することです。`9(qR-qL)/2`調整のこと。 したがって、記載された条件は必要かつ十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    s = input().strip()

    half = n // 2

    left_sum = 0
    right_sum = 0
    left_q = 0
    right_q = 0

    for i in range(half):
        if s[i] == '?':
            left_q += 1
        else:
            left_sum += ord(s[i]) - ord('0')

    for i in range(half, n):
        if s[i] == '?':
            right_q += 1
        else:
            right_sum += ord(s[i]) - ord('0')

    if left_sum < right_sum:
        left_sum, right_sum = right_sum, left_sum
        left_q, right_q = right_q, left_q

    diff = left_sum - right_sum

    if diff == 0:
        if left_q == right_q:
            print("Bicarp")
        else:
            print("Monocarp")
        return

    if left_q >= right_q:
        print("Monocarp")
        return

    extra = right_q - left_q

    if diff * 2 == extra * 9:
        print("Bicarp")
    else:
        print("Monocarp")

if __name__ == "__main__":
    solve()
```最初のループは最初のものを正確に処理します。`n // 2`位置、2 番目の位置は次から始まります`n // 2`、これは、Python のゼロベースのインデックス付けにおける右半分の最初のインデックスです。 固定数字はそれぞれの合計に影響しますが、疑問符は 2 つのカウンタにのみ影響します。 

スキャン後の交換は便利な簡略化です。 個別のケースを書く代わりに、`left_sum > right_sum`そして`right_sum > left_sum`の場合、コードは常に、より大きい固定合計を持つ側を左側として扱います。 ゲームでは大きい側の識別が重要であるため、疑問符の数は合計とともに交換する必要があります。 

等価性テストでは次のように使用されます。`diff * 2 == extra * 9`分けるのではなく`extra`2つまでに。 これにより、不必要な除算が回避され、数学的条件がコード内で直接表示されるようになります。 Python の整数にはオーバーフローの懸念はなく、ここでの最大値は次のオーダーにすぎません。`10^6`。 

実装ではチケット自体を変更する必要はありません。 4 つの合計量が計算されると、疑問符の正確な位置は重要ではなくなります。 これにより、ゲームが指数関数的な検索から単一の線形スキャンに減ります。

 ## 特殊なケース

 最初のエッジ ケースは、消去された位置のないチケットです。 のために`4 / 0523`、スキャンにより得られる`left_sum = 5`、`right_sum = 5`、`left_q = right_q = 0`。 アルゴリズムはゼロ差分分岐に入り、戻ります。`Bicarp`。 移動がないため、初期状態が結果を直接決定します。 

2 番目のエッジ ケースは、固定合計は等しいが、疑問符の数が等しくない場合です。 のために`4 / ?123`、固定左和は`0`、固定権利合計は`2 + 3 = 5`なので、正規化後は右側の方が大きくなります。 カウントは次のようになります`qL = 0`そして`qR = 1`、プラスの固定差があります。 大きい側にはより多くの疑問符が含まれるため、アルゴリズムは次の値を返します。`Monocarp`。 より一般的には、固定差がゼロでカウントが異なる場合、最初の手を持ったプレーヤーは不一致のポジションを持ち、永続的なペア戦略を妨げます。
