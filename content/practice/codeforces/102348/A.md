 ## 問題の理解

 (a_1) と (a_2) の選手がいる 2 つのサッカー チームがあります。 最初のチームのプレーヤーは (k_1) 枚のイエローカードを受け取った後に除外され、第 2 チームのプレーヤーは (k_2) 枚のカードを受け取った後に除外されます。 私たちが知っているのは提示されたイエローカードの総数 (n) だけであり、どの選手がイエローカードを受け取ったかはわかりません。 

課題は 2 つの極端な値を見つけることです。 最初の数字は、(n) 枚のカードを配布するすべての有効な方法で削除されたプレイヤーの最小数です。 2 番目の数字は、削除されたプレイヤーの最大数です。 この問題は Codeforces 1215A としても知られており、同じステートメントと制約があります。 

プレイヤー数とカードのしきい値は最大 (1000) であるため、カードの総数は最大でも

 [
 1000\cdot1000+1000\cdot1000=2\cdot10^6。 
】

 これにより、(n) 個の可能なカード カウントにわたる線形スキャンが低レベル言語で実行可能になりますが、その必要はありません。 2 つのチームの構造により、両方の答えを一定数の算術演算に減らすことができます。 さらに重要なのは、最大 (2\cdot10^6) 個のカードごとに最大 (2000) 個の受信者が存在する可能性があるため、実際のカード割り当てを列挙することは完全に不可能です。 

最初の難しい境界は、すべてのプレイヤーが退場せずに (k_i-1) 枚のカードを受け取ることができるときです。 例えば、```
1
1
2
3
3
```最初のプレーヤーは安全に 1 枚のカードを受け取ることができ、2 番目のプレーヤーは安全に 2 枚のカードを受け取ることができるため、誰も退場することなく 3 枚のカードすべてを割り当てることができます。 答えは、`0 1`。 (a_1k_1+a_2k_2) を安全容量として使用する不用意な最小計算も、ここで偶然ゼロを返しますが、(n) がその誤って定義された安全容量を超えるとすぐに失敗します。 関連する安全限界は、常に除去しきい値より 1 小さい値です。 

しきい値が (1) の場合、別のエッジ ケースが発生します。 例えば、```
1
1

5
1
```最初のチームの選手は唯一のイエローカードで退場となるため、答えは次のようになります。`1 1`。 (k_1-1=0) を正しく使用すると、最初のプレイヤーが安全なカードをまったく持っていないことを意味します。

## アプローチ

 完全に総当たりのソリューションでは、すべてのイエロー カードの受信者をすべて考慮することができます。 (a_1+a_2) 人のプレイヤーと (n) 枚のカードを使用すると、((a_1+a_2)^n) 個の可能な割り当てが生成されます。 最大の制限では、(2000^{2,000,000}) ほどの大きさになりますが、これは遠隔的には実現可能ではありません。 このアプローチは、考えられるすべての分布が考慮されるため正しいですが、その検索スペースはカードの数に応じて指数関数的に増加します。 

もう少し実用的な総当たりアプローチは、(n) 枚のカードのうち何枚が最初のチームに属するかを列挙することです。 選択した値 (x) の場合、削除されるプレーヤーの最大数は次のとおりです。 

[

 +
 \min(a_2,\lfloor(n-x)/k_2\rfloor)。 
】

 すべての (x) を試行するには (O(n)) 時間がかかりますが、これらの制約の下では最大でも約 200 万回の反復であり、機能します。 ただし、この問題にはより強力な貪欲構造があるため、この列挙を実行する理由はありません。 

最低限のこととして、まずカードをできるだけ安全に配布することを想像してください。 すべてのファースト チーム プレーヤーは除去されることなく (k_1-1) 枚のカードを受け取ることができ、すべてのセカンド チーム プレーヤーは (k_2-1) のカードを受け取ることができます。 したがって、除去せずに吸収できるカードの枚数は

 [
 S=a_1(k_1-1)+a_2(k_2-1)。 
】

 (n\le S) の場合、誰も去る必要はありません。 (n>S) の場合、カードが追加されるたびに、さらに 1 人のプレイヤーが除去しきい値に到達することになります。 したがって、最小値は

 [
 \max(0,n-S)。 
】

 最大値に対する重要な観察は異なります。 除外されたプレイヤーはちょうど (k_i) 枚のカードを消費します。 できるだけ多くのプレイヤーを削除するには、最初に必要なカードの少ないプレイヤーにカードを費やす必要があります。 (k_1<k_2) の場合、第 1 チームのプレイヤーを除去する方が第 2 チームのプレイヤーを除去するよりもカードのコストが少なくて済むため、第 2 チームの除去にカードを使用する前に、手頃な価格の第 1 チームの除去をすべてとるべきです。 (k_2<k_1) の場合、役割は逆になります。 しきい値が等しい場合、どちらの順序も同等です。 

小さい方のしきい値が (k_s) で、(a_s) 人のプレーヤーが対応し、もう一方のしきい値が (k_l) で、(a_l) 人のプレーヤーがいるとします。 削除できます

 [
 x=\min(a_s,\lfloor n/k_s\rfloor)
 】

 安いチームの選手。 残りのカードは (n-xk_s) なので、削除できます。 

[
 \min(a_l,\lfloor(n-xk_s)/k_l\rfloor)
 】

 他のチームの選手たち。 

安い除去を高価な除去に置き換えても、固定枚数のカードから得られる除去の数は決して増加しないため、この貪欲な選択は最適です。

 ## アルゴリズムのチュートリアル

 1. 誰も削除せずに、すべてのプレイヤーに与えることができるカードの数を計算します。 

[
 安全=a_1(k_1-1)+a_2(k_2-1)。 
】

 最小削除数は次のとおりです。`max(0, n - safe)`。 その先の各カード`safe`以前に安全だったプレーヤーのしきい値を完了する必要があり、しきい値を 1 つ完了すると、プレーヤーが 1 人だけ削除されます。 
2. (k_1) と (k_2) を比較し、しきい値が小さいチームを最大計算の最初のチームとして扱います。 

このチームからの除去はカードの消費が少ないため、最初に使用すると可能な限り多くの除去を獲得できます。 
3. 閾値の小さいチームからできるだけ多くのプレーヤーを削除します。 

[
 x=\min(a_s,n//k_s)。 
】

 の`min`そのチームには (a_s) 人のプレーヤーしかいないため、これが必要です。 
4. 除外されたプレイヤーが使用した (xk_s) カードを減算します。 

残りのカードは、他のチームからプレーヤーを削除するために使用できます。 しきい値を下回る残りの金額は、プレーヤーを削除することなく、単純にそのプレーヤーに割り当てることができます。 
5. 他のチームからできるだけ多くのプレーヤーを削除します。 

[
 y=\min(a_l,(n-xk_s)//k_l)。 
】

 最大の答えは (x+y) です。 

### なぜ効果があるのか

 少なくとも、すべてのプレイヤーはゲームに留まりながら正確に (k_i-1) 枚のカードを吸収できます。 これにより、合計安全容量は (安全) になります。 これらのカードが使用されると、追加のすべてのカードはいずれかのプレイヤーの (k_i) 番目のカードでなければならず、その結果除去が作成されます。 入力により、(n) が総容量 (a_1k_1+a_2k_2) を超えないことが保証されるため、すべての超過カードを吸収するのに十分なプレイヤーが常に存在します。 

最大値については、削除されたプレイヤーのセットを考慮します。 最初のチームの各除去は (k_1) 枚のカードのコストがかかり、二番目のチームの各除去は (k_2) 枚のカードのコストがかかります。 (k_1<k_2) の場合、後続チームの除去 1 枚を第一チームの除去 1 枚で置き換えても、それ以上のカードは必要なく、さらなる除去に使用できるカードは少なくとも同じ枚数だけ残すことができます。 したがって、最適な配置は、より大きなしきい値の除去の前に、できるだけ多くのより小さなしきい値の除去を使用する配置に常に変換できます。 (k_2<k_1) の場合、チームが逆転する場合にも同じ議論が当てはまります。 選択されたすべての除去が支払われた後、未使用のカードはしきい値に達していないプレイヤーに配置できるため、貪欲なカウントを達成できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    a1 = int(input())
    a2 = int(input())
    k1 = int(input())
    k2 = int(input())
    n = int(input())

    safe = a1 * (k1 - 1) + a2 * (k2 - 1)
    minimum = max(0, n - safe)

    if k1 <= k2:
        small_count, small_k = a1, k1
        large_count, large_k = a2, k2
    else:
        small_count, small_k = a2, k2
        large_count, large_k = a1, k1

    removed_small = min(small_count, n // small_k)
    remaining = n - removed_small * small_k

    removed_large = min(large_count, remaining // large_k)
    maximum = removed_small + removed_large

    print(minimum, maximum)

if __name__ == "__main__":
    solve()
```最初の 5 つの入力呼び出しでは、2 つのチームのサイズ、それぞれの除去しきい値、およびイエロー カードの総数が読み取られます。 この問題には複数のテスト ケースがないため、1 回の呼び出しで`solve()`で十分です。 

の`safe`式の使用法`k_i - 1`、 ない`k_i`。 正確に (k_i) 枚のカードに達するとプレーヤーが削除されるため、誰も削除しないようにする必要がある場合は、(k_i-1) 枚のカードのみが使用可能になります。 

最大値を得るために、コードは入力値を物理的に変更するのではなく、チームの概念的な役割を交換します。 比較した後、`small_k`以下の大きさであることが保証されています`large_k`。 これらのしきい値で整数を割ると、除去を生み出すことができるカードの完全なグループの数が求められます。 

の`min`チームの規模に応じて、プレイヤーの数よりも多くの除去をカウントすることを防ぎます。 これらの除去の支払い後、残りのカードを大きい方のしきい値で割って、さらに何人のプレイヤーが抜けることができるかを調べます。 

Python の整数には任意の精度があるため、オーバーフローの問題はありません。 最大の積はチームごとに (10^6) のみであるため、ここでは固定幅の 32 ビット整数でも十分ですが、Python 整数を使用するとその懸念が完全に解消されます。
