 ## 解決策
 ## 問題の理解

 文字列が 2 つあります`s`そして`t`同じ長さの。 すべての位置に次のいずれかが含まれます`a`または`b`。 1 回の操作で任意の位置を選択`s`そしてどの位置でも`t`、次に 2 つの文字を交換します。 目標は、できるだけ少ない操作を使用して 2 つの文字列全体を同一にし、同時に 1 つの最適なスワップ シーケンスを出力することです。 

位置を確認する便利な方法は、その位置を占めている 2 つの文字を比較することです。 彼らがすでに同意しているのであれば、その立場に注意を払う必要はありません。 一致しない場合、その位置は次のいずれかのタイプになります。`ab`、 意味`s[i] = a`そして`t[i] = b`、または入力します`ba`、 意味`s[i] = b`そして`t[i] = a`。 

届く長さは`2 * 10^5`したがって、二次作業を行うアルゴリズムは次のように実行できます。`4 * 10^10`最悪の場合、2 秒のコンテスト制限で許容される反復回数をはるかに超えます。 本質的に直線的な動作をするソリューションが必要です。`n`、ポジションごとの簿記の量はわずかです。 アルファベットには 2 文字しか含まれていないため、不一致タイプによって、それを実現するために必要な構造が正確に得られます。 

一見合理的と思われる実装が失敗する可能性があるいくつかのエッジケースがあります。 まず、奇数の不一致はあり得ません。 例えば、```
1
a
b
```1つあります`ab`ミスマッチ。 1つだけあります`a`2 つの文字の間にあり、最後の等しいペアにはすべて 0 または 2 のいずれかが含まれます。`a`文字。 一連のスワップによって総数が変わることはありません。`a`文字なので、正しい出力は次のようになります。`-1`。 パリティをチェックせずに単に不一致をペアにする不注意な実装では、1 つの位置が未解決のままになる可能性があります。 

2 番目のエッジ ケースは、両方の不一致タイプのカウントが奇数である場合に発生します。 例えば、```
2
ab
ba
```1つあります`ab`位置と1`ba`位置。 方向が反対であるため、直接のワンスワップペアリングでは修正できません。 ただし、交換は2回で十分です。 スワップ`s[1]`と`t[1]`、最初の不一致を から変える`ab`の中へ`ba`、交換します`s[1]`と`t[2]`。 両者の立場は等しくなります。 等しい不一致タイプのみをペアにするソリューションでは、このケースは不可能であると誤って結論付けられてしまいます。 

3 番目のエッジケースは、不一致がまったくない場合です。```
3
aba
aba
```正しい答えは、`0`、操作線はありません。 少なくとも 1 つの不一致があることを前提とした実装では、誤って空のリストにアクセスしたり、不要な操作を出力したりする可能性があります。 

## アプローチ

 直接的なアプローチは、不一致を繰り返し見つけ、それを修正できる別の位置を探すことです。 たとえば、`ab`位置が決まったら、残りの位置をスキャンして別の位置を探します`ab`位置を変更し、1 回の文字列間スワップを使用して両方を解決します。 そのようなポジションが存在しない場合は、次のような特別なケースを処理できます。`ba`2回のスワップによるポジション。 

すべての検索が有効なパートナーを探しており、操作が成功するたびに不一致の数が減少するため、この戦略は論理的に適切です。 問題は繰り返しスキャンすることです。 最悪の場合、こんなことも考えられます`Θ(n)`不一致があり、各パートナーを見つけると検査される可能性があります`Θ(n)`ポジション。 文字比較の合計数は次のとおりです`Θ(n²)`、それは約です`4 * 10^10`のために`n = 2 * 10^5`。 それは制限時間を超えすぎます。 

重要な点は、パートナーを動的に検索する必要がないということです。 間違った位置に関連する唯一の情報は、その位置が正しいかどうかです。`ab`または`ba`。 1 回のパスで各タイプのすべてのポジションを収集できます。 

二`ab`いつでも一度の操作で位置をまとめて固定できます。 位置を仮定する`x`そして`y`両方です`ab`。 スワッピング`s[x]`と`t[y]`交換`a`そして`b`。 で`x`、`s[x]`からの変更`a`に`b`、一致する`t[x]`。 で`y`、`t[y]`からの変更`b`に`a`、一致する`s[y]`。 同じ議論が 2 つの場合に機能します`ba`ポジション。 

これにより、等しい不一致タイプのすべてのペアが即座に処理されます。 残る唯一の状況は、両方の不一致リストに 1 つのペアになっていない位置が含まれている場合です。 不一致の合計数は偶数である必要があるため、これら 2 つのリストは両方とも偶数サイズであるか、両方とも奇数サイズです。 奇妙なケースでは、`x`残ります`ab`位置と`y`残り`ba`位置。 最初の交換`s[x]`と`t[x]`。 これで位置が変わります`x`から`ab`の中へ`ba`。 今では両方とも`x`そして`y`は`ba`、つまり、次の間の 2 番目の交換`s[x]`そして`t[y]`両方を修正します。 

操作数の下限も単純です。 1 回の操作で現在不一致である最大 2 つの位置を修正できるため、2 つの等しい不一致をペアにするには少なくとも 1 回の操作が必要であり、最適です。 いつ`ab`そして1つ`ba`残りの場合、それらの方向は反対であるため、1 つの操作で両方を解決することはできません。 したがって、上記の 2 つの操作の構成が最適です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | パートナーを繰り返し検索 |`O(n²)`|`O(n)`| 遅すぎる |
 | 不一致の位置を保存し、それらをペアにします。`O(n)`|`O(n)`| 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての位置を左から右にスキャンします。 もし`s[i] == t[i]`、無視してください。 もし`s[i] == 'a'`そして`t[i] == 'b'`、追加`i`に`ab`リスト。 それ以外の場合は追加`i`に`ba`リスト。 これにより、問題のあるすべての位置が、2 つのみ考えられる不一致方向に従って分離されます。 
2. 2 つのリストのパリティをチェックします。 の合計数`a`両方の文字列の文字は交換のたびに保持され、最終的な等しいペアには 0 または 2 のいずれかが含まれます。`a`文字。 したがって、合計数は、`a`文字は偶数である必要があります。 同様に、不一致の総数は偶数でなければなりません。 2 つの不一致カウントは、その合計が偶数である場合は常に同じパリティを持つため、次の場合には拒否するだけで十分です。`len(ab) + len(ba)`奇数です。 
3. 連続するポジションをペアにする`ab`。 すべてのペアについて`ab[2j]`そして`ab[2j + 1]`、間のスワップを出力します。`s[ab[2j]]`そして`t[ab[2j + 1]]`。 1 回の操作で両方の位置が固定されるため、これはそのペアにとって最適です。 
4. 連続するポジションをペアにする`ba`全く同じ方法で。 ポジションについて`x = ba[2j]`そして`y = ba[2j + 1]`、交換`s[x]`と`t[y]`。 操作後、両方の不一致は同じ位置になります。 
5. 両方の不一致リストの長さが奇数の場合、各リストに 1 つの位置が残ります。 それらの立場を`x = ab[-1]`そして`y = ba[-1]`。 最初の出力`(x, x)`、 2 つの文字の位置を交換します。`x`そしてそのタイプを次から変更します`ab`に`ba`。 次に出力します`(x, y)`。 残った二人`ba`不一致がペアになり、等しくなります。 
6. 保存されているすべての 0 から始まるインデックスを、印刷時に 1 から始まるインデックスに変換します。 出力カウントは、単に生成された操作リストの長さです。 

### なぜ効果があるのか

 最初のスキャンの後、すべての不一致は 2 つのリストのいずれかに正確に属します。 同じ不一致タイプの 2 つの位置を交換すると、すでに固定されている位置に影響を与えることなく、両方が固定されます。 したがって、2 つのリストのすべての偶数サイズの部分をペアで最適に削除できます。 

両方のリストが奇数の場合、それぞれに 1 つの位置が残ります。 最初の追加スワップにより、残りのスワップが変更されます`ab`不一致`ba`その後、残りの 2 つの不一致は同じタイプになり、もう 1 回スワップすることで修正できます。 不一致の合計数が奇数の場合、すべての操作で 2 つの文字列が同一になるために必要なパリティ条件が保持されるため、解決策は存在しません。 

2 つの等しい不一致タイプに対して使用されるすべての操作は、可能な最大値である 2 つの不一致を修正します。 唯一の避けられない例外は、最後の反対のペアであり、2 つの操作が必要です。 したがって、構築されたシーケンスは可能な限り最小限の長さになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    s = input().strip()
    t = input().strip()

    ab = []
    ba = []

    for i in range(n):
        if s[i] == t[i]:
            continue
        if s[i] == 'a':
            ab.append(i)
        else:
            ba.append(i)

    if (len(ab) + len(ba)) % 2:
        print(-1)
        return

    operations = []

    for i in range(0, len(ab) - 1, 2):
        operations.append((ab[i] + 1, ab[i + 1] + 1))

    for i in range(0, len(ba) - 1, 2):
        operations.append((ba[i] + 1, ba[i + 1] + 1))

    if len(ab) % 2 == 1:
        x = ab[-1] + 1
        y = ba[-1] + 1
        operations.append((x, x))
        operations.append((x, y))

    out = [str(len(operations))]
    out.extend(f"{x} {y}" for x, y in operations)
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```最初のループでは不一致のみが記録されるため、等しい位置が後のロジックに入力されることはありません。 これは、後で生成されるすべての操作を完全に不一致リストの観点から推論できるため便利です。 

パリティ チェックは、操作を構築する前に実行されます。 各操作は既存の文字を交換するだけなので、総数を変更することはできません。`a`2 つの文字列内の文字。 等しい文字列を含む最終状態では、必ず偶数の合計数が含まれます。`a`したがって、奇数の不一致数は不可能であることを証明します。 

2 つのペアリング ループでは、`range(0, len(list) - 1, 2)`。 リストの長さが奇数の場合、上限は最終要素の手前で意図的に停止します。 最後の要素は、特別な 2 つの操作を行う構造のために予約されています。 

特殊なケースでは、最初の操作で同じインデックスを 2 回使用します。たとえば、`(x, x)`。 最初のインデックスは次のものに属しているため、これは正当です。`s`そして2番目のものは`t`、つまり操作が入れ替わります`s[x]`そして`t[x]`。 それは何もしないわけではありません。 のために`ab`不一致の場合、位置が次のように変更されます。`ba`。 

Python 文字列はゼロベースのインデックスを使用するため、すべての内部インデックスはゼロベースです。 これらは出力に格納される場合にのみ 1 ずつ増加し、問題で必要な 1 から始まる位置と一致します。 

変異なし`s`または`t`必要です。 操作は元の不一致分類から派生し、生成された各操作は意図された位置を修正することが数学的に知られています。 これにより、後の分類決定に対する偶発的な変更も回避されます。

## テストケース

 最適な操作シーケンスは一意ではないため、堅牢なテスト ハーネスでは、成功した出力を文字ごとにサンプル出力と比較する必要はありません。 代わりに、出力に正しい最小数の操作が含まれていること、およびそれらの操作を適用すると実際に等しい文字列が生成されることを検証する必要があります。```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    n = int(input())
    s = input().strip()
    t = input().strip()

    ab = []
    ba = []

    for i in range(n):
        if s[i] == t[i]:
            continue
        if s[i] == 'a':
            ab.append(i)
        else:
            ba.append(i)

    if (len(ab) + len(ba)) % 2:
        print(-1)
        return

    operations = []

    for i in range(0, len(ab) - 1, 2):
        operations.append((ab[i] + 1, ab[i + 1] + 1))

    for i in range(0, len(ba) - 1, 2):
        operations.append((ba[i] + 1, ba[i + 1] + 1))

    if len(ab) % 2 == 1:
        x = ab[-1] + 1
        y = ba[-1] + 1
        operations.append((x, x))
        operations.append((x, y))

    print(len(operations))
    for x, y in operations:
        print(x, y)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

def validate(inp: str, out: str):
    data = inp.strip().splitlines()
    n = int(data[0])
    original_s = data[1]
    original_t = data[2]

    lines = out.strip().splitlines()

    if not lines:
        raise AssertionError("empty output")

    if lines[0].strip() == "-1":
        mismatches = sum(a != b for a, b in zip(original_s, original_t))
        assert mismatches % 2 == 1, "reported impossible for a solvable case"
        return

    k = int(lines[0])
    assert len(lines) == k + 1, "wrong number of operation lines"

    ab = []
    ba = []

    for i in range(n):
        if original_s[i] == original_t[i]:
            continue
        if original_s[i] == 'a':
            ab.append(i)
        else:
            ba.append(i)

    expected = len(ab) // 2 + len(ba) // 2
    if len(ab) % 2:
        expected += 2

    assert k == expected, f"not minimum: got {k}, expected {expected}"

    s = list(original_s)
    t = list(original_t)

    for line in lines[1:]:
        x, y = map(int, line.split())
        assert 1 <= x <= n
        assert 1 <= y <= n
        x -= 1
        y -= 1
        s[x], t[y] = t[y], s[x]

    assert s == t, "operations did not make strings equal"

# Provided samples.
sample1 = """4
abab
aabb
"""
validate(sample1, run(sample1))

sample2 = """1
a
b
"""
validate(sample2, run(sample2))

sample3 = """8
babbaabb
abababaa
"""
validate(sample3, run(sample3))

# Minimum-size solvable case: already equal.
case1 = """1
a
a
"""
validate(case1, run(case1))
assert run(case1).strip() == "0"

# Minimum-size impossible case: one mismatch.
case2 = """1
a
b
"""
assert run(case2).strip() == "-1"

# Opposite mismatch types. This catches the special two-operation case.
case3 = """2
ab

"""
validate(case3, run(case3))

# Maximum-size input, with all positions equal.
case4 = "200000\n" + "a" * 200000 + "\n" + "a" * 200000 + "\n"
assert run(case4).strip() == "0"

# Boundary case with two equal mismatch types.
case5 = """4
aabb
bbaa
"""
validate(case5, run(case5))
