 ## 解決策
 ## 問題の理解

 2 つのバイナリ文字列があります`s`そして`t`同じ長さの。 1 回の操作で、任意の位置を選択できます。`s`そしてどの位置でも`t`, 次に、これら 2 つの文字を交換します。 2 つの位置が等しい必要はないため、操作により 2 つの異なる不一致を一度に修正できます。 

目標は、文字列間の交換をできるだけ少なくして、文字列全体を同一にすることです。 最小スワップ数を 1 つの最適なシーケンスとともに出力するか、または出力する必要があります。`-1`どのシーケンスも機能しない場合。 

位置を確認する便利な方法は、その 2 つの文字を比較することです。 可能性は4つしかありません。 を含むポジション`aa`または`bb`はすでに正しいです。 を含むポジション`ab`手段`s[i] = a`そして`t[i] = b`、 その間`ba`は逆の意味です。 適切な位置を交換すると、2 つの不一致を同時に解消できます。 

届く長さは`2 * 10^5`したがって、位置のすべてのペアをスキャンするアルゴリズムはすでに遅すぎます。 二次アルゴリズムは大まかに実行できます`4 * 10^10`最悪の場合、ペアチェックは 2 秒の制限をはるかに超えます。 実際に出力する操作の数とは別に、文字列の長さに応じて作業量が直線的に増加するソリューションが必要です。 

世界的な実現可能性条件もあります。 すべての操作は 2 つの文字列間で文字を交換するだけなので、`a`両方の文字列の文字が変更されることはありません。 最終的な文字列が等しくなるには、2 つの文字列全体ですべての文字が偶数回出現する必要があります。 したがって、合計数が`a`文字が変なので答えられません。 同じ条件は、不一致の数を使用してより直接的に表現できます。`ab`ポジションと数の合計`ba`位置は偶数である必要があります。 

最初のエッジ ケースは、単一の不一致です。 入力用```
1
a
b
```唯一の立場は`ab`なので、不一致の総数は奇数になります。 正しい出力は次のとおりです`-1`。 単に不一致を記録し、利用可能なものをすべてペアにする不注意な実装では、1 つの不一致の位置が残り、シーケンスが誤って出力される可能性があります。 

2 番目のエッジ ケースは、エッジ ケースが 1 つある場合に発生します。`ab`不一致と 1`ba`ミスマッチ。 例えば、```
2
ab
ba
```2 つの操作が必要です。 最初の交換により、`ab`に位置する`ba`, しかし、それで問題は解決しません。 結果のペアを解決するには、2 回目のスワップが必要です。 すべての不一致のペアを 1 回の操作で解決できるものとして扱うと、1 回の操作で十分であると誤って主張することになります。 

3 番目の特殊なケースは、すべての位置がすでに一致している可能性があることです。 例えば、```
3
aba
aba
```操作は不要です。 少なくとも 1 つの不一致が存在することを前提とした実装では、誤って空の不一致リストにアクセスしたり、不要な操作を出力したりする可能性があります。 

## アプローチ

 簡単なアプローチは、不一致の位置を検査し、文字を交換して進行できる 2 つの位置を繰り返し検索することです。 不一致には 2 種類あるため、考えられるすべてのインデックスのペアを試し、対応する文字を交換することで不一致の数が減るかどうかをテストできます。 徹底的な検索ではすべての法的スワップが考慮されるため、これは正しいですが、費用がかかりすぎます。 と`n`ポジション、あります`n²`文字列間の交換が可能であり、それらを繰り返し検索するには次のオーダーが必要になる場合があります。`n²`小切手。 で`n = 2 * 10^5`、それは約です`4 * 10^10`候補者交換。 

重要な観察は、実際の文字はタイプの不一致によってのみ重要であるということです。 位置を仮定する`i`そして`j`どちらもタイプです`ab`。 どちらの立場でも、`s = a`そして`t = b`。 スワッピング`s[i]`と`t[j]`交換`a`そして`b`、したがって、両方の位置は次のようになります`bb`そして`aa`。 したがって、2`ab`不一致は 1 回の操作で修正できます。 同じ議論が 2 つの場合に機能します`ba`不一致。 

これは、2 つの不一致タイプのインデックスを別々に保存することを直ちに示唆しています。 同じ型内のすべてのペアには 1 回の操作が必要です。2 つの不一致を修正するには 1 回の操作が理論上の最小値であるため、より良い配置を探す必要はありません。 

唯一興味深いケースは、両方の不一致リストのサイズが奇数である場合です。 できるだけ多くのポジションをペアリングした後、1 つのポジションを`ab`そして1つ`ba`残る。 文字の向きが逆のため一度の操作では修正できません。 ただし、操作は 2 回で十分です。 もし`i`残りは`ab`位置と`j`残りは`ba`ポジション、最初の交換`s[i]`と`t[i]`。 位置`i`からの変更`ab`に`ba`。 現在のポジション`i`そして`j`両方です`ba`、交換します`s[i]`と`t[j]`両方を修正します。 

最小値も同じ構造から得られます。 すべての操作で最大 2 つの不一致位置を修正できるため、1 回の操作で 2 つの等しい不一致タイプをペアにすることが最適です。 各タイプの不一致が 1 つだけ残っている場合、1 つの操作では両方を修正できませんが、上記の構成ではそれらを 2 つだけ修正します。 したがって、結果として生じる操作の数は最小限になります。

 ## アルゴリズムのチュートリアル

 1.すべての位置をスキャンします`i`から`0`に`n - 1`。 もし`s[i] = t[i]`、そこでは何もする必要はありません。 もし`s[i] = a`そして`t[i] = b`、 店`i`で`ab`リスト。 もし`s[i] = b`そして`t[i] = a`、 店`i`で`ba`リスト。 これら 2 つのリストには、依然として注意が必要なポジションが正確に含まれています。 
2. 2 つの不一致リストのパリティをチェックします。 もし`len(ab) + len(ba)`奇数です、印刷してください`-1`。 両方の文字列にわたる各文字の合計数が保持されるため、不一致の数によってすべての位置が等しくなるようにパリティを変更することはできません。 
3. 連続するポジションをペアにする`ab`。 すべてのペアについて`ab[i]`そして`ab[i + 1]`、操作を追加します`(ab[i], ab[i + 1])`。 両方のポジションの形式は次のとおりです`ab`、つまり、`a`の最初の位置から`s`と`b`の2番目の位置から`t`両方の位置を等しいペアに変更します。 
4. 連続するポジションをペアにする`ba`同じように。 すべてのペアについて`ba[i]`そして`ba[i + 1]`、 追加`(ba[i], ba[i + 1])`。 どちらのポジションにも次のような形式があるため、`ba`、同じ理由で 1 回の操作で両方が修正されます。 
5. 両方のリストの長さが奇数の場合、1 つの位置`i`に残っている`ab`そして1つのポジション`j`に残っている`ba`。 操作を追加する`(i, i)`。 以来の地位`i`は`ab`、それ自体の 2 文字を交換すると、次のように変更されます。`ba`。 
6. 2 番目の操作を追加します`(i, j)`。 位置`i`今です`ba`、および位置`j`すでにあった`ba`、交換します`s[i]`と`t[j]`両方の位置を等しいペアに変更します。 
7. 保存されているすべての 0 から始まるインデックスを、印刷時に 1 から始まるインデックスに変換します。 操作のペアに続く操作の数を出力します。 

### なぜ効果があるのか

 不変条件は、保存されていないすべての位置です。`ab`または`ba`はすでに等しいですが、格納されているすべての位置は 1 つの不一致タイプによって表されます。 同じタイプのペアは常に 1 回の操作で削除できるため、そのようなペアはすべて個別に削除できます。 奇数サイズの不一致リストが 2 つ残っている場合、最初の操作で残りの 1 つが変更されます。`ab`の中へ`ba`、その後、2 つの残りは同じタイプになり、2 番目の操作でそれらが削除されます。 合計の不一致数が奇数の場合、各文字の保存された合計数により、ターゲット状態に到達できなくなります。 すべての操作では最大 2 つの不一致が修正され、アルゴリズムは 2 つの不一致を一緒に修正できる場合は常に 1 つの操作を使用し、避けられない反対タイプの残り物については正確に 2 つの操作を使用します。 したがって、生成されたシーケンスは有効かつ最小です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    s = input().strip()
    t = input().strip()

    ab = []
    ba = []

    for i in range(n):
        if s[i] == t[i]:
            continue
        if s[i] == 'a':
            ab.append(i)
        else:
            ba.append(i)

    if (len(ab) + len(ba)) % 2:
        print(-1)
        return

    ans = []

    for i in range(0, len(ab) - 1, 2):
        ans.append((ab[i], ab[i + 1]))

    for i in range(0, len(ba) - 1, 2):
        ans.append((ba[i], ba[i + 1]))

    if len(ab) % 2 == 1:
        i = ab[-1]
        j = ba[-1]
        ans.append((i, i))
        ans.append((i, j))

    out = [str(len(ans))]
    for x, y in ans:
        out.append(f"{x + 1} {y + 1}")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```最初のループでは、すべての位置を 1 回だけ分類します。 等しい位置は無視されますが、不一致の可能性がある 2 つの方向は別々に保存されます。 アルファベットには以下しか入っていないので、`a`そして`b`、処理できる 3 番目の不一致タイプはありません。 

2 つのペアリング ループは 2 つ進みます。 このため、上限は`len(ab) - 1`それよりも`len(ab)`: ペアになっていない最後の要素は、特殊な 2 つの操作のケースが処理されるまでそのままにしておく必要があります。 同じことが当てはまります`ba`。 

特殊な場合のみチェックします`len(ab) % 2`。 不一致の総数が偶数であることがわかったら、`ab`そして`ba`必ず同じパリティを持ちます。 したがって、もし`ab`奇妙です、`ba`も奇数で、両方ともペアリング後にちょうど 1 つの要素が残ります。 

Python 文字列ではゼロベースのインデックスが使用されるため、操作インデックスはゼロベースの値として内部的に保存されます。 出力には 1 から始まる位置が必要なので、`x + 1`そして`y + 1`が印刷されています。 スワップのシミュレーションは必要ありません。 ペアの分類により、その操作が何を行うのかが証明され、シミュレーションを回避することで実装が単純になります。 

Python では整数オーバーフローの懸念はありません。 操作の最大数は次のとおりです`n + 1`、直接保存して印刷できるほど小さいです。 出力自体には以下を含めることができます`O(n)`したがって、文字列のリストとして作成して一度記述する方が、個別に何度も実行するより効率的です。`print`呼び出します。

## テストケース

    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        solve_io()
        return sys.stdout.getvalue()
    finally:

    data = inp.strip().splitlines()
    n = int(data[0])
    s = data[1]
    t = data[2]

    out = run(inp).strip().splitlines()

    possible = (sum(c == 'a' for c in s) +
                sum(c == 'a' for c in t)) % 2 == 0

    if not possible:
        assert out == ["-1"]
        return

    k = int(out[0])
    assert len(out) == k + 1

    # The theoretical minimum.
    ab = []
    ba = []
    for i in range(n):
        if s[i] == t[i]:

        if s[i] == 'a':
            ab.append(i)
        else:
            ba.append(i)

        assert 1 <= x <= n
        assert 1 <= y <= n

        y -= 1
        ss[x], tt[y] = tt[y], ss[x]

    assert ss == tt

aba
```両方の不一致リストは空のままです。 合計の不一致数はゼロで、ペアリング ループは何も行わず、特殊なケースも何も行わず、プログラムは次のように出力します。`0`。 スワップが必要ないため、これは正しい最小値です。 

同じタイプの 2 つの不一致については、次のように考えます。```
2
aa
bb
```どちらの立場も、`ab`、 それで`ab = [0, 1]`。 最初のペアリング ループでは、`(0, 1)`。 スワッピング`s[0] = a`と`t[1] = b`生成する`bb`最初の位置にあり、`aa`2 番目では、ちょうど 1 回の操作後に文字列が等しくなります。 アルゴリズムが 1 回の操作の下限に到達しました。 

最後に、最大サイズのケース```
200000
aaaaaaaaaa...aaaaaaaaaa
bbbbbbbbbb...bbbbbbbbbb
```もっている`200000` `ab`不一致。 それらは次のようにグループ化できます。`100000`ペアごとに 1 つのスワップが必要です。 アルゴリズムは 1 回の線形スキャンを実行し、正確に`100000`操作。 大まかに検査することはありません`4 * 10^10`これが、十分な速度を維持できる主な理由です。
