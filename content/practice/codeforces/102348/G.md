 ## 解決策
 ## 問題の理解

 文字列が 2 つあります`s`そして`t`同じ長さで、すべての文字は次のいずれかです`a`または`b`。 1 回の操作で、任意の位置を選択できます。`s`そしてどの位置でも`t`、次に 2 つの文字を交換します。 目標は、このような文字列間の交換をできるだけ少なくして、2 つの文字列を同一にすることです。 

出力には、最小数のスワップと、それを達成するインデックス ペアの 1 つのシーケンスが含まれている必要があります。 文字列を等しくできるシーケンスがない場合は、次のように出力します。`-1`。 

最初の有益な観察は文字数に関するものです。 スワップによって合計数が変わることはありません。`a`両方の文字列にわたる文字。 最終的な文字列が等しい場合、各位置は両方の文字列に同じ文字を提供するため、文字列の合計数は`a`文字は偶数である必要があります。 同様に、次の位置の数は、`s[i] != t[i]`均等でなければなりません。 奇数の場合、一連のスワップは機能しません。 

と`n`と同じくらい大きい`2 * 10^5`、二次または指数関数的な動作をするアルゴリズムは適していません。 2 秒の制限は、入力サイズにほぼ比例する、線形または線形に近い作業を目指す必要があることを意味します。 不一致の位置の保存も、最大でも`n`彼らのうち。 

不一致タイプは 2 つあります。 という位置で、`s[i] = a`そして`t[i] = b`、それを「」と呼びます`ab`ミスマッチ。 という位置で、`s[i] = b`そして`t[i] = a`、それを`ba`ミスマッチ。 これらのタイプはペアになると異なる動作をするため、その区別を見落とすことが誤った解決策の主な原因となります。 

考慮する`n = 1`、`s = "a"`、`t = "b"`。 不一致が 1 つあるため、不一致の合計数は奇数になります。 不注意な解決策は、インデックスの 2 つの文字を交換しようとする可能性があります。`1`、しかしその操作は交換します`a`そして`b`文字列の間に文字列を挿入し、単に文字列をそのままにしておきます。`"b"`そして`"a"`。 正しい答えは、`-1`。 

もう 1 つの重要なケースは、各タイプの 1 つの不一致です。 たとえば、`s = "ab"`そして`t = "ba"`、不一致は`ab`位置にある`1`そして`ba`位置にある`2`。 これら 2 つの異なる位置を 1 回交換するだけでは修正できません。 2 つの操作が必要です: swap`s[1]`と`t[1]`、交換します`s[1]`と`t[2]`。 答えは`2`。 常に 1 つをペアにするソリューション`ab`1つで`ba`1 回の操作で十分であると仮定すると、ここでは失敗します。 

最後に、同じタイプの不一致が 2 つある場合は、1 回の操作で十分です。 のために`s = "aabb"`そして`t = "bbaa"`、ポジション`1`そして`2`両方です`ab`不一致。 スワッピング`s[1]`と`t[2]`両方の位置を同時に固定します。 不一致の位置をすべて個別に処理するソリューションでは、使用する操作が多すぎます。 

## アプローチ

 直接的な総当たりアプローチにより、あらゆる可能な配置をモデル化できます。`2n`2 つの文字列内の文字を状態として表示します。 ある州からは、`n^2`文字列間のスワップが発生する可能性があるため、幅優先検索では操作数が増加する中で状態を探索し、2 つの文字列が等しくなったときに停止する可能性があります。 BFS は重み付けされていない状態グラフで最短パスを見つけるため、これは正しいです。 

問題はそのグラフのサイズです。 の合計数`a`文字は保持されるので、`k`それらの中には、`C(2n, k)`異なる州。 これは最大化されます`k = n`、大まかに言うと`C(2n, n)`として成長します。`4^n / sqrt(n)`。 まで探索中`n^2`各状態からの遷移は、最悪の場合のスケールを与えます。`Theta(n^2 C(2n, n))`、数十のポジションであっても完全に実行不可能です。 

より焦点を絞った貪欲なアプローチでは、不一致を検査し、それらを 1 つずつ修正しようとすることができます。 重要な洞察は、不一致がペアになる可能性があるということです。 2 つの位置が同じ不一致タイプを持つ場合、1 回の文字列間スワップで両方が修正されます。 たとえば、2 つの`ab`位置を交換することでペアにすることができます`a`最初の位置から`b`2番目から。 同じ議論が 2 つの場合に機能します`ba`ポジション。 

同じタイプを繰り返しペアリングした後、最大で 1 つのタイプをペアにすることができます。`ab`不一致、最大 1 つ`ba`不一致が残っています。 どちらも残っていない場合は終了です。 1 つだけが残っている場合、不一致の総数は奇数になるため、インスタンスは不可能になります。 両方が残っている場合は、2 つの操作が必要です。 最初の操作では、残りの位置の 1 つにある 2 文字を文字列全体でそれ自体と交換し、そこでの不一致タイプを変更します。 残りの 2 つの不一致は同じタイプになり、2 回目のスワップで解決できます。 

したがって、問題全体は、不一致の位置を収集し、等しいタイプをペアにし、考えられる 2 つの残りを個別に処理することに帰着します。

 ## アルゴリズムのチュートリアル

 1. すべての位置を左から右にスキャンします。 もし`s[i] == t[i]`、その位置はすでに一致しており、操作は必要ありません。 それ以外の場合は、1 から始まるインデックスを次のいずれかに追加します。`ab`または`ba`、ペアであるかどうかに応じて、`(a, b)`または`(b, a)`。 

2 つの不一致タイプを分離しておくことにより、1 つの操作で 2 つの位置を解決できることを認識できるようになります。 
2. 不一致の合計数が多ければ、`len(ab) + len(ba)`、奇数です、印刷します`-1`。 

すべての操作で、合計数が保存されます。`a`文字が等しい一方、等しい最終文字列には偶数の文字が含まれます。`a`合計文字数。 したがって、パリティ条件が必要です。 バイナリ文字列の場合もこれで十分です。 
3. 連続したペア`ab`不一致。 すべてのペアについて`ab[i]`そして`ab[i + 1]`、操作を追加します`(ab[i], ab[i + 1])`。 

最初の位置では、`s`含まれています`a`そして`t`含まれています`b`。 2番目の位置では、`s`含まれています`a`そして`t`含まれています`b`。 スワッピング`s[ab[i]]`と`t[ab[i + 1]]`両方の位置を次のように変更します`(b, b)`または、ペアの方向に応じて、両方の不一致を同時に修正します。 同じ理由が 2 つにも当てはまります`ba`不一致。 
4. 連続したペア`ba`まったく同じように不一致になります。 すべてのペアについて`ba[i]`そして`ba[i + 1]`、 追加`(ba[i], ba[i + 1])`。 

このような操作ごとに 2 つの不一致が削除されるため、このステップの後では、各タイプの不一致が最大 1 つ存在する可能性があります。 
5. 両方の場合`ab`そして`ba`ペアになっていないポジションが 1 つあるとします。`x`そして`y`、 実行する`(x, x)`初め。 

位置で`x`、登場人物は`a`で`s`そして`b`で`t`。 これら 2 つの文字を交換すると、不一致が変わります。`ab`に`ba`。 これで、残りの両方の位置が同じ不一致タイプになります。 
6. 実行する`(x, y)`2回目の手術として。 

残りの 2 つの等しい型の不一致は、以前に使用したのと同じペアリング引数によって修正されます。 
7. 前の手順で収集した操作を出力します。 

すべての操作は 2 つの不一致を削除します。ただし、残ったケースの最初の操作は、2 番目の操作で最後の 2 つを削除できるように配置を変更します。 各操作は可能な限りの削減を目的として使用されるため、結果として得られるカウントは最小限になります。 

### なぜ効果があるのか

 不変条件は、収集された不一致の位置が、2 つの文字列がまだ一致しない場所を正確に記述していることです。 同じタイプの 2 つの不一致は常に 1 回の操作で削除できるため、1 回の操作では 3 つ以上の不一致位置を修正できないため、それらをペアにすることが最適です。 

このようなペアがすべて削除された後、各タイプの不一致は最大 1 つだけ残ります。 1 つだけが残っている場合、不一致の数は奇数となり、等価性は不可能になります。 2 つ残った場合、必ず反対のタイプになります。 1 回の自己インデックス スワップによって一方のタイプがもう一方のタイプに変更され、最後のクロスインデックス スワップによって両方が修正されます。 したがって、可能なすべての解決可能な構成が処理され、すべての操作が可能な最小数を達成する方法で使用されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    s = input().strip()
    t = input().strip()

    ab = []
    ba = []

    for i in range(n):
        if s[i] == t[i]:
            continue
        if s[i] == 'a':
            ab.append(i + 1)
        else:
            ba.append(i + 1)

    if (len(ab) + len(ba)) % 2:
        print(-1)
        return

    ans = []

    for i in range(0, len(ab) - 1, 2):
        ans.append((ab[i], ab[i + 1]))

    for i in range(0, len(ba) - 1, 2):
        ans.append((ba[i], ba[i + 1]))

    if len(ab) % 2 == 1:
        x = ab[-1]
        y = ba[-1]

        ans.append((x, x))
        ans.append((x, y))

    print(len(ans))
    for x, y in ans:
        print(x, y)

if __name__ == "__main__":
    solve()
```最初のスキャンでは、すべての不一致が 2 つの不一致配列のいずれかに分類されます。 の`i + 1`この問題では から始まる位置が必要であるのに対し、アルゴリズムは内部で Python のゼロベースのインデックスを使用するため、変換は意図的に行われます。`1`。 

ペアリング ループは 2 つ進みます。 たとえば、次の場合`ab = [2, 5, 7, 9]`、操作は次のとおりです。`(2, 5)`そして`(7, 9)`。 ループバウンド`len(ab) - 1`配列の長さが奇数である場合に、存在しない 2 番目の要素にアクセスすることを防ぎます。 

残ったケースは微妙な部分です。 いつ`ab`ペアになっていないポジションが 1 つあり、`ba`合計の不一致数が偶数であるため、1 つも必要です。 操作`(x, x)`選択された 2 つの位置が同じ数値インデックスを持つ可能性があるため、これは正当です。`s`そしてもう一つは`t`。 不一致を反転します`x`、その後`(x, y)`両方の位置を固定します。 

文字列のシミュレーションは必要ありません。 構築された演算はすでに代数的に推論されているため、元の文字列からの不一致分類のみが必要です。 Python の整数にもオーバーフローの心配はありません。`n`操作が生成されます。
