 ## 解決策
 ## 問題の理解

 (n) 個のフェンス板と (m) 色の色の列があります。 色 (i) は正確に (a_i) 枚の板で使用でき、値の合計は (n) になるため、ペイントのすべての単位を使用する必要があります。 1 つの色の最大連続ランの長さが (k) を超えることがないように、フェンスに沿ってこれらの色の出現を並べ替える必要があります。 

出力は、すべての色を正確に (a_i) 回使用する長さ (n) の色配列、または有効な配置が存在しない場合は (-1) のいずれかになります。 

制約 (n \le 2\cdot 10^5) は、可能な順列の大部分を探索するものをすべて除外します。 (O(n^2)) であっても、最悪の場合、すでに (4\cdot10^{10}) 程度の演算を意味します。 本質的に線形の解、つまり (O(n\log n)) の解が必要です。 プライオリティキューは、ランリミットに達した色を一時的に除外し、残量が最も多い色を採用することですべての位置を決定できるため、適切です。 

不注意な実装が失敗する可能性のあるエッジケースがいくつかあります。 まず、色は正確に実現可能性の境界にある可能性があります。 例えば、```
6 2 3
5 1
```可能です、`1 1 1 2 1 1`。 色 1 のランの長さは正確に (3) であるため、(k) を超えるランではなく長さ (k) のランを拒否すると、誤って (-1) が表示されます。 

2 番目のケースは、他の色がいくつか存在するにもかかわらず、最大の色が大きすぎる場合です。 例えば、```
8 2 3
7 1
```不可能です。 カラー 1 の 7 つのコピーには少なくとも 3 回の別々の実行が必要ですが、カラー 2 の 1 つの板では 2 つの境界しか分離できません。 実現可能性をチェックせずに単に最大の色の配置を開始する貪欲な実装は、最終的に行き詰まる可能性があるため、その状況を正しく処理する必要があります。 

可能な最小の入力も特殊です。```
1 1 1
1
```唯一の有効な答えは、`1`。 前の色はなく、実行違反の可能性もないため、初期化では、答えにすでに前のプランクが含まれていると想定してはなりません。 

最後に、(k) はすべての有用な実行よりも大きくなる可能性があります。 例えば、```
5 2 5
4 1
```として有効です`1 1 1 1 2`。 (k\ge n) の場合、実行制限は事実上無関係であるため、アルゴリズムは不必要な色の変更を強制してはなりません。 

## アプローチ

 直接的な総当たりアプローチでは、フェンスを順列問題として扱います。 すべてのプランクで、残りの量が正であるすべての色を試し、再帰的に続行し、現在の実行が (k) を超えるとすぐに分岐を拒否します。 これは正しいです。なぜなら、考えられるすべてのカラーリングが最終的に考慮され、有効なカラーリングが受け入れられるからです。 

問題は、可能な色の数です。 固定多重度を無視しても、(n) 色の (m^n) 個のシーケンスが存在します。 1 つの完全なシーケンスをチェックするには (O(n)) かかるため、単純な徹底的な検索には (O(nm^n)) 時間がかかる可能性があります。 (m=n=2\cdot10^5) の場合、この最悪の場合の限界はおよそ (O(n^{n+1})) となり、これは完全に実行不可能です。 

有益な観察は、私たちはまだ埋まっていないポジションの身元を決して気にしないということです。 各ステップで重要なのは、各色のコピーが何枚残っているか、最後に使用された色は何か、現在の実行時間がどれくらいかということです。 使用可能な色の中で、残りの数が最も多い色が最も危険です。 小さい色を消費しながら未使用のままにしておくと、残りのコピーが後で配置されにくくなります。 

それが優先キューにつながります。 私たちは常に、残りの数が最大の色を採用します。 その色が前の色と異なる場合は、すぐに使用できます。 それが同じ色で、現在の実行がすでに (k) に達している場合は、代わりに 2 番目に大きい色を一時的に採用します。 カラーを一度使用すると、残りの数が減り、コピーが残っている場合はヒープに戻されます。 

簡単な実現可能条件もあります。 色 (c) が (A) 回発生するとします。 (c) の各実行には最大で (k) 個のコピーが含まれるため、少なくとも (\lceil A/k\rceil) 個の (c) の個別の実行が必要になります。 これらの実行の間には、少なくとも (\lceil A/k\rceil-1) 個の色の板がなければなりません。 したがって、

 [
 \left\lceil\frac{A}{k}\right\rceil \le n-A+1,
 】

 これは以下と同等です

 [
 \le k(n-A+1)。 
】

 最も難しい色は最大 (A) を持つ色であるため、最大値 (a_i) を確認するだけで十分です。 これにより、答えを構築する前に即時不可能性テストが行​​われます。 

ブルート フォースは、考えられるすべての順序を探索するため機能しますが、順序が指数関数的に多いため失敗します。 残っている最大の色だけが配置できなくなる恐れがあるという観察により、最大ヒープを使用して貪欲に各決定を下すことができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(nm^n)) | (O(n+m)) | 遅すぎる |
 | 最適 | (O(n\log m)) | (O(n+m)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 色のカウントを読み取り、最大のカウント (A) を見つけます。 (A>k(n-A+1)) の場合、(-1) を出力します。 最大の色だけでも、他の板で提供できるよりも多くの分離されたランがすでに必要です。 
2. すべての色とその残りの数を最大ヒープに置きます。 パイソンの`heapq`は最小ヒープであるため、負の数を保存します。 
3.キープ`last`、前の板で使用された色、および`run`、現在の連続実行の長さ。 最初は前のカラーが無いので、`last = -1`そして`run = 0`。 
4. すべての位置で、残りのカウントが最大の色をヒープから削除します。 
5.その色が違う場合`last`、使ってください。 新しいランレングスは (1) になります。 
6. 等しい場合`last`そして`run < k`、再度使用します。 同じ色を継続することは、残りの数が最も多く、現在の実行にはまだ余裕があるため、好ましいです。 
7. 等しい場合`last`そして`run = k`、現在は使用できません。 次に大きい色をヒープから削除し、代わりにその色を使用します。 ブロックされた色を変更せずにヒープに返します。 2 番目の色が存在しない場合、構築を続行できません。 
8. 選択した色の残りの数を減らします。 まだコピーが残っている場合は、それをヒープに挿入し直します。 
9. すべて (n) の板が割り当てられるまで繰り返します。 

### なぜ効果があるのか

 不変条件は、プレフィックスがすでにランレングス制限を満たしている一方で、プレフィックスが構築されるたびに、ヒープにはすべての色の未使用のコピーが正確に含まれるということです。 最も頻繁に残っている色を継続できる場合は、残り数が少ない色を延期しても、その小さい色を配置するのが難しくなることはないので、その色を使用するのが安全です。 現在の実行が (k) に達すると、継続は禁止されるため、有効な継続は別の色を選択する必要があります。 利用可能な最大の代替を選択すると、最も制限された残りのリソースが保存されます。 

実現可能性の不等式により、最大の色には、必要なすべてのランを分離するのに十分な不一致の板が利用できることが保証されます。 貪欲な選択では、現在の色が合法的に継続できる間にそれらの色を無駄にするのではなく、切り替えが強制された場合にのみそれらの分離色を常に費やします。 したがって、最初の実現可能条件が満たされていれば、ヒープ構築はスタックすることなくすべてのコピーを消費できます。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    a = list(map(int, input().split()))

    mx = max(a)

    if mx > k * (n - mx + 1):
        print(-1)
        return

    heap = []
    for color, count in enumerate(a, 1):
        heapq.heappush(heap, (-count, color))

    ans = []
    last = -1
    run = 0

    for _ in range(n):
        neg_count, color = heapq.heappop(heap)
        count = -neg_count

        if color == last and run == k:
            if not heap:
                print(-1)
                return

            neg_count2, color2 = heapq.heappop(heap)
            count2 = -neg_count2

            heapq.heappush(heap, (-count, color))

            color = color2
            count = count2
            run = 1
        else:
            if color == last:
                run += 1
            else:
                run = 1

        ans.append(color)
        count -= 1

        if count > 0:
            heapq.heappush(heap, (-count, color))

        last = color

    print(*ans)

if __name__ == "__main__":
    solve()
```実現可能性チェックでは最大数のみが使用されます。 (A) 個のコピーを持つカラーの場合、少なくとも (\lceil A/k\rceil) 個のランが必要であり、(n-A) 個の他の板は最大で (n-A+1) 個の可能なラン スロットを提供します。 (A) が大きくなるにつれて不等式は難しくなるため、最大数をチェックすることですべての色がカバーされます。 

ヒープにはペアが格納されます`(-count, color)`そのため、最小のヒープ値が最大の残りカウントに対応します。 2 つの色は同じ数を持つ可能性があり、それでも区別できる必要があるため、カラー インデックスは明示的に保存されます。 

特別な支店は、`color == last and run == k`が重要な境界条件です。 現在の色はすでにちょうど (k) 個の連続した位置を占めているため、それをもう一度使用すると、長さ (k+1) のランが作成されます。 それを一時的に削除し、次に最適な色を選択し、ブロックされた色を変更せずに戻します。 

選択した色のコピーが 1 つ残っている場合、その数を減分するとゼロが生成され、単純に押し戻されません。 入力ではすべてのカウントの合計が (n) であることが保証されるため、正確に (n) 回の成功した選択が必要です。 

Python の整数はオーバーフローせず、実現可能性テストでの最大の積は最大 (n^2)、約 (4\cdot10^{10}) であり、Python はこれを直接処理します。

## テストケース

def run(inp: str) -> str:
    global input

    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()
    input = sys.stdin.readline

    try:
        solve()
        return sys.stdout.getvalue().strip()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout
        input = sys.stdin.readline

def validate(inp: str, out: str):
    data = list(map(int, inp.split()))
    n, m, k = data[0], data[1], data[2]
    a = data[3:3 + m]

    assert out != "-1"

    ans = list(map(int, out.split()))
    assert len(ans) == n

    cnt = [0] * (m + 1)

    last = -1
    run = 0

    for color in ans:
        assert 1 <= color <= m
        cnt[color] += 1

        if color == last:
            run += 1
        else:
            last = color
            run = 1

        assert run <= k

    for color in range(1, m + 1):
        assert cnt[color] == a[color - 1]

 ## 特殊なケース

 最低限の入力に関しては```
1 1 1
1
```最大数は (1) で、実現可能性テストでは (1\le1(1-1+1)) が得られます。 ヒープには、一度選択されたカラー 1 のみが含まれています。 前の色がないため、実行は (1) から始まり、出力は正確に次のようになります。`1`。 

正確な境界の場合```
6 2 3
5 1
```ドミナントカラーには 5 つのコピーがあります。 (\lceil5/3\rceil=2) なので 2 回の実行が必要ですが、色 2 の 1 つのコピーでそれらを分離するのに十分です。 貪欲な構築では、カラー 1 を 3 回取得し、実行が (3) に達するとカラー 2 に切り替わり、その後カラー 1 を 2 回取得します。 結果は`1 1 1 2 1 1`、その最長ランの長さは正確に (3) です。 

周波数が等しい場合、```
12 3 4
4 4 4
```すべての色はヒープ内で同じ優先度を持ちます。 ヒープのカラー インデックスは一貫して関係を解消するため、この構造では 1 つの色のコピーを 4 つ生成し、続いて別の色のコピーを 4 つ、3 番目の色のコピーを 4 つ生成できます。 各ランの長さは (4)、まさに許容される最大値です。 

不可能な境界線に対して、```
8 2 3
7 1
```支配的な色は少なくとも 3 回のランを必要としますが、他の 1 つの板はそのようなランを最大 2 回分離できます。 不等式は (7\le6) となり、これは false となるため、アルゴリズムは次のように出力します。`-1`すぐに。 部分的な構築は必要なく、完了できないプレフィックスを報告するリスクもありません。 

ケース (k=1) も同じロジックで処理されます。 前の色がヒープの一番上にあるたびに、`run == k`はすでに true であるため、アルゴリズムは別の色を選択する必要があります。 実現可能条件は (A\le n-A+1) に帰着します。これは、最も頻繁に使用される色には、そのコピーをすべて分離するのに十分な他の要素がなければならないというよく知られた要件です。
