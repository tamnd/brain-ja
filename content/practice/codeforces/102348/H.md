 ## 解決策
 ## 問題の理解

 私たちは持っています`n`ランタンは厳密に増加する整数座標に配置されます`x[0], x[1], ..., x[n-1]`。 それらのサブセットをオンにすることもできます。 選択された座標は等差数列を形成する必要があります。つまり、連続して選択されたすべての座標には同じ差があります。 1 つまたは 2 つのランタンのセットは自動的に有効になるため、実際のタスクは、ソートされた座標配列の最長の算術進行サブシーケンスを見つけることです。 

元の制約により、`n <= 3000`までのコーディネート`10^18`。 大きな座標範囲により、小さな座標範囲に依存する手法が除外されますが、Python の整数はこれらの値を正確に処理するため、算術自体に悪影響を与えることはありません。 サイズ`3000`が重要な制約です。 アン`O(n^2)`このアルゴリズムは約 450 万回のペア遷移を実行しますが、これは慎重に実装すれば 2 秒の制限に適切です。 アン`O(n^3)`このアルゴリズムは、緩い最悪の場合の境界ですでに約 270 億回の反復を行っており、制限をはるかに超えています。 公式声明では、これらの制限と座標の厳密な増加順序が確認されています。 

実装が静かに失敗する可能性があるケースがいくつかあります。 まず、3 つの任意のランタンが必ずしも有効な進行を形成するとは限りません。 例えば、`3 5 9`等しい自由ギャップが 2 つだけあり、`2`そして`4`、したがって、答えは次のとおりです`2`、 ない`3`。 すべてのペア拡張を自動的に有効なものとして扱う不用意な実装は、カウントを過剰にカウントする可能性があります。 

第二に、最良の進行では多くのランタンをスキップできます。 のために`1 2 4 6 7`、答えは`3`を使用して`1, 4, 7`。 連続したランタンだけを見ていると、元のギャップが開いているため、この進行を見逃してしまいます。`1, 2, 2, 1`。 

第三に、入力座標は次の値に近づく可能性があります。`10^18`。 例えば、`0 500000000000000000 1000000000000000000`答えがあります`3`。 固定幅の実装では、次のような式に十分な幅の型を使用する必要があります。`2*x[i]`ただし、Python の任意精度の整数を使用すると、この問題が簡単になります。 

最後に、「すべて等しい値」というフレーズは、座標が厳密に増加しているため、この問題の入力制約の下では文字通り有効なテストを生成できません。 そのストレス ケースの意味のあるバージョンは、次のようなすべてのギャップが等しい配列です。`0 1 2 3 4`、すべての座標は 1 つの等差数列に属します。 

## アプローチ

 直接的な総当たりアプローチでは、最初と 2 番目のランタンを選択し、それらの違いを判断し、同じ進行を続ける後続のすべての座標を検索できます。 考えられるすべての次の位置を素朴にスキャンすると、次のようになります。`O(n^2)`最初の 2 つのランタンと最大のランタンの選択`O(n)`それぞれのために働き、与える`O(n^3)`時間。 同様に、すべてのトリプルをチェックすることは、すでに検査することを意味します。`C(3000, 3) = 4,495,501,000`最悪の場合は3倍になります。 すべての等差数列には最初のペアがあるため、すべてのペアを試行すると、最終的にその正確な共通差分が考慮されるため、強引な方法は正しいです。 単に作業の繰り返しが多すぎるだけです。 

有益な観察は、最後に選択した 2 つの座標がわかれば、次の座標が完全に決定されるということです。 現在、等差数列が座標で終了していると仮定します。`x[h], x[i]`。 次の座標は次のようにする必要があります。`x[j] = x[i] + (x[i] - x[h]) = 2*x[i] - x[h]`。 

これにより、問題はエンドポイントのペアにおける動的プログラムに変わります。 させて`dp[i][j]`最後の 2 つの座標が次の等差数列の最大長になります。`x[i]`そして`x[j]`、 と`i < j`。 必要な先行座標の場合`2*x[i] - x[j]`インデックスに存在します`h`、その後、進行状況は で終了する状態から拡張できます。`(h, i)`:`dp[i][j] = dp[h][i] + 1`。 

その先行者が存在しない場合、ペアは`(i, j)`それ自体は有効な長さの進行です`2`、 それで`dp[i][j] = 2`。 

並べ替え順序により、追加の便利なプロパティが得られます。 なぜなら`j > i`、必要な前任者`2*x[i] - x[j]`より厳密に小さいです`x[i]`、そのインデックス`h`満たさなければなりません`h < i`。 遷移に必要なすべての情報は、処理時にすでに計算されています。`i`。 

見つけることができます`h`ハッシュテーブルなし。 固定の場合`i`、 として`j`増加し、`x[j]`増えるので、`2*x[i] - x[j]`減少します。 したがって、座標を逆方向にスキャンするポインタは、内側のループ全体で逆方向にのみ移動します。 固定を越えて`i`、ポインターは最大で移動します`i`回なので、全体にわたるポインタの移動の合計は`i`は`O(n^2)`。 

DP には次の内容が含まれます`n(n-1)/2`ペアの状態。 Python では、ネストされたリスト内に各状態を通常の整数として保存すると、大量のメモリが消費される可能性があります。 最大DP値は最大です。`3000`したがって、符号なし 16 ビット整数で十分です。 パイソンの`array('H')`は各状態を 2 バイトに格納し、約 450 万の状態を小さなメモリ フットプリント内に収めます。

 ## アルゴリズムのチュートリアル

 1. ソートされた座標を読み取り、答えを初期化します。`2`。 異なるランタンのどのペアも有効な選択であるため、答えは常に少なくとも次のとおりです。`2`。 
2. インデックスごとに`i`、州を含む DP 行を作成します。`dp[i][j]`みんなのために`j > i`。 すべての状態を次のように初期化します`2`なぜなら、ランタンのペアは長さ 2 の等差数列を形成するからです。 
3. 中間のエンドポイントを修正します`i`そして先行ポインタを開始します`k = i - 1`。 あらゆる人にとって`j > i`、直前に必要な座標`x[i]`は`target = 2*x[i] - x[j]`。 
4. 移動`k`その間に立ち去った`x[k] > target`。 以来`target`として減少するだけです`j`増加し、`k`二度と右に動く必要はありません。 もし`x[k] == target`、 索引`k`まさに必要な前任者です。 
5. 先行処理が存在する場合、次で終わる計算済みの状態を読み取ります。`(k, i)`そしてセット`dp[i][j] = dp[k][i] + 1`。 前の状態の要素は 1 つ少なく、追加されています。`x[j]`共通の違いが保たれるのは、`x[i] - x[k] = x[j] - x[i]`。 
6. グローバル回答を新しい状態で更新します。 先行者が存在しない場合、初期化された値`2`正しいままです。 
7. 可能な限りの処理を行う`i`。 最終的に、最大の DP 値が最長の算術進行サブシーケンスとなり、必要な答えとなります。 

### なぜ効果があるのか

 次で終わる等差数列を考えてみましょう。`x[i], x[j]`。 以前の座標がある場合、それは正確に一致している必要があります`2*x[i] - x[j]`。 座標がソートされているため、`j > i`、その前任者はその前にあります`i`。 したがって、少なくとも 3 の長さのすべての進行には、拡張できる固有の初期の DP 状態があります。 反復では、先行するものが存在する場合はそれを正確に考慮し、それ以外の場合はペアを長さ 2 のままにします。 最終エンドポイントの位置に関する帰納法により、すべての DP 状態は、そのペアで終了する最大の有効な進行を保存します。 したがって、すべてのペアの最大値を取ると、全体的な最適値が得られます。 

## Python ソリューション```python
import sys
from array import array

input = sys.stdin.readline

def solve():
    n = int(input())
    x = list(map(int, input().split()))

    if n <= 2:
        print(n)
        return

    # rows[i][j - i - 1] stores dp[i][j] for j > i.
    # Every state starts at 2 because every pair is valid.
    rows = [None] * n
    answer = 2

    for i in range(n - 1):
        length = n - i - 1
        row = array('H', [2]) * length

        # For fixed i, target = 2*x[i] - x[j] decreases as j grows.
        # Hence k only moves to the left.
        k = i - 1
        xi = x[i]

        for j in range(i + 1, n):
            target = 2 * xi - x[j]

            while k >= 0 and x[k] > target:
                k -= 1

            if k >= 0 and x[k] == target:
                value = rows[k][i - k - 1] + 1
                row[j - i - 1] = value

                if value > answer:
                    answer = value

        rows[i] = row

    print(answer)

if __name__ == "__main__":
    solve()

表現`rows[k][i-k-1]`取得します`dp[k][i]`。 各行はそれ自身の最初の有効な 2 番目のエンドポイントから始まるため、オフセットは間違えやすいです。 たとえば、列で`k`、2 番目のインデックスが次の状態`i`です`(i-k-1)`- 番目の要素。 

先行ポインタは次から始まります`i-1`、可能な最大の先行インデックス。 新しいものごとに`j`、必要な座標が減少します。 の`while`ループは、正確な座標が見つかるか、すべての可能な先行処理が大きくなりすぎるまで、ポインタを移動します。 から再起動する必要はありません`i-1`これにより、検索が 3 次ではなく 2 次に保たれます。 

の`array('H')`どの進行にもそれ以上のものを含めることはできないため、type だけで十分です。`n <= 3000`提灯。 16 ビットの符号なし整数は、次のように値を表すことができます。`65535`したがって、すべての DP 状態が快適に適合します。 これにより、Python の完全な整数オブジェクトと比較して、大量のメモリが節約されます。 

Python の整数も安全に評価されます`2 * x[i]`たとえいつでも`x[i]`近いです`10^18`なので、オーバーフローの問題はありません。 

入力にはテスト ケースが 1 つだけあるため、外部のテスト ケース ループはありません。
