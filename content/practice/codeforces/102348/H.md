 ## 解決策
 ## 問題の理解

 ランタンは厳密に増加する座標として与えられるため、入力順序はすでに通りに沿った順序になっています。 等差数列を形成するこれらの座標の最大の部分列を選択する必要があります。 座標 (a_1,a_2,\ldots,a_k) を選択した場合、連続するギャップはすべて同一でなければなりません。 1 つまたは 2 つのランタンの選択は自動的に有効になるため、興味深い部分は長さ 3 から始まります。 

座標は (10^{18}) まで大きくすることができるため、座標範囲に依存するアプローチは除外されます。 ただし、ランタンは最大 (n=3000) 個しかないため、(O(n^2)) アルゴリズムが現実的です。 (n=3000) の場合、約 (n^2/2=4.5) 百万のペアが存在します。これは、二次動的プログラムに適した作業量です。 (O(n^3)) アルゴリズムは、自然な実装では (3000^3/6=4.5) 億回程度の内部反復で実行され、2 秒の制限をはるかに超えています。 

座標の厳密な増加により、便利な順序付けプロパティも得られます。 (i<j) の場合、(x_i,x_j) で終わる等差数列の公差は (x_j-x_i>0) です。 以前の座標が存在する場合、それは次のとおりである必要があります。 

[
 x_i-(x_j-x_i)=2x_i-x_j。 
】

 (2x_i-x_j<x_i) であるため、その前の座標のインデックスは小さい必要があります。 これにより、すべての状態がすでに計算された状態のみに依存するようになります。 

不適切な実装が露呈する可能性のあるエッジケースがいくつかあります。 次のような 3 つの連続した座標を使用すると、```
3
1 2 3
```配列全体に等しいギャップがあるため、答えは 3 です。 すべての進行を長さ 2 に初期化するが、中間点が存在するときにそれを拡張するのを忘れる実装は、誤って 2 を返します。 

2つ目のケースは、```
5
1 2 4 6 7
```答えは 3 です。座標 (1,4,7) は、入力内で連続していなくても、等差数列を形成します。 連続するランタンのみを検査するソリューションでは、これが見逃され、2 が返されます。 

3 番目の問題は、前任者が存在しない進行状況です。 例えば、```
3
1 2 4
```答えは 2 です。ペア (2,4) の場合、必要な以前の座標は (0) になりますが、これは存在しません。 このペアは依然として長さ 2 の有効な進行であるため、実装では欠落している先行データをエラーとして扱ってはなりません。 

最後に、座標は非常に大きくなる可能性があります。 (2x_i-x_j) のような式は一時的に間隔 ([0,10^{18}]) から離れる可能性があるため、座標による配列のインデックス付けに依存するのではなく、整数として処理する必要があります。 Python の整数には任意の精度があるため、これが簡単になります。 

## アプローチ

 直接的なアプローチは、進行の最初の 2 つのランタンを選択し、それらの違いを判断し、同じ違いを持つ次の座標を繰り返し検索することです。 (O(n^2)) 個の開始ペアが考えられます。 各ペアが残りの座標をスキャンする場合、最悪の場合の反復回数は次のようになります。 

[
 \sum_{i=0}^{n-1}\sum_{j=i+1}^{n-1}(n-j-1)=O(n^3),
 】

 (n=3000) でおよそ (n^3/6)、つまり 45 億回の反復。 ハッシュ セットを使用すると、個々の検索を一定時間にすることができますが、すべての開始ペアで長いスキャンが生成される可能性があるため、3 番目の要素は削除されません。 

最初の 2 つの座標が固定されると、算術数列全体が決定されるため、総当たりアプローチが機能します。 問題は、同じサフィックスが繰り返し検出されることです。 たとえば、いくつかの異なる開始ペアが最終的に同じ座標ペア (x_k,x_i) に到達した場合、それらはすべて、そのペアを拡張するために必要な作業を独立してやり直すことになります。 

重要な観察は、連続して選択された 1 組の座標が、将来の拡張に必要な状態を完全に記述しているということです。 (i<j) の場合、(dp[i][j]) を、選択された最後の 2 つの座標が (x_i,x_j) である等差数列の最大長として定義します。 この進行を後方に拡張したい場合、その前の座標は (2x_i-x_j) でなければなりません。 すべての座標は個別であるため、そのようなランタンは最大でも 1 つしかありません。 

インデックス (k<i) に座標が存在するとします。 次に、(x_i,x_j) で終了する進行は、(x_k,x_i) で終了する進行を取得し、(x_j) を追加することによって取得されます。 したがって、

 [
 dp[i][j]=dp[k][i]+1。 
】

 (2x_i-x_j) が存在しない場合でも、ペア (x_i,x_j) は有効な進行を開始できるため、(dp[i][j]=2) となります。 

座標がインデックスにマップされると、反復により (O(n^2)) 状態と状態ごとの一定の仕事量が得られます。 通常の 2 次元の Python リストでは、何百万もの Python 整数オブジェクトとリスト参照が高価であるため、大量のメモリが浪費されます。 答えは最大 3000 であるため、すべての DP 値は符号なし 16 ビット整数に収まります。 すべての三角形 DP 状態を`array('H')`により、DP ストレージが約 9 MB に削減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(n^3)) | (O(n)) | 遅すぎる |
 | 最適 | (O(n^2)) | (O(n^2)) を 16 ビット値にパック | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 指定されたソート順で座標を保存し、すべての座標をそのインデックスにマッピングする辞書を構築します。 ディクショナリを使用すると、必要な先行処理 (2x_i-x_j) が一定の予想時間内に存在するかどうかを判断できます。 
2. 各ペア (i<j) に 1 つのパックされた DP エントリを割り当てます。 (i\ge j) の状態は無意味であり、各値は最大でも (n\le3000) なので、符号なし 16 ビット整数で十分であるため、三角ストレージのみが必要です。 
3. 最初のインデックス (i) を左から右に処理し、すべての (j>i) についてペア (x_i,x_j) を検討します。 このペアのすべての先行関数は (i) より小さいインデックスを持っている必要があるため、再帰に必要な状態はすでに計算されています。 
4. 必要な先行座標を (p=2x_i-x_j) として計算します。 (p) がインデックス (k) に存在する場合、すでに計算された状態 (dp[k][i]) を読み取り、設定します

 [
 dp[i][j]=dp[k][i]+1。 
】

 このステップの背後にある算術恒等式は、まさに等ギャップ条件です。 (x_k) から (x_i) までのギャップが (x_i) から (x_j) までのギャップと等しい場合、(x_k=2x_i-x_j) になります。 

1. (p) が存在しない場合は、(dp[i][j]=2) を設定します。 ランタンのどのペアも距離に関係なく有効であるため、すべてのペアは少なくとも 2 つの長さの進行を提供します。 
2. 確認された最大の DP 値でグローバル応答を更新します。 (n\ge3) であるため、答えは常に少なくとも 2 であり、有効な 3 つ以上の進行が存在する場合、反復ではその全長が記録されます。 

これが機能する理由: 不変条件は、ペア (i,j) を処理した後、`dp[i,j]`はまさに、最後の 2 つの座標が (x_i,x_j) である最長の等差数列です。 必要な先行処理 (2x_i-x_j) が存在する場合、(i,j) で終了するすべての進行はその一意の先行処理を使用する必要があるため、(k,i) で終了する最適な進行を拡張すると最適な値が得られます。 先行演算子が存在しない場合、少なくとも 3 の長さの数列は (i,j) で終了できず、ペア自体は最適な長さ 2 のままになります。考えられるすべての等差数列には最終的なペアがあるため、すべてのペアの最大値を取ると、グローバル最適値が得られます。 

## Python ソリューション```python
import sys
from array import array

input = sys.stdin.readline

def solve():
    n = int(input())
    x = list(map(int, input().split()))

    pos = {value: i for i, value in enumerate(x)}

    # For row i, store dp[i][i+1], dp[i][i+2], ..., dp[i][n-1].
    # Number of stored pairs is n * (n - 1) // 2.
    total = n * (n - 1) // 2
    dp = array('H', [0]) * total

    # base[i] is the first position belonging to row i.
    base = [0] * n
    for i in range(1, n):
        base[i] = base[i - 1] + (n - i)

    def index(i, j):
        return base[i] + (j - i - 1)

    ans = 2

    for i in range(n - 1):
        xi = x[i]

        for j in range(i + 1, n):
            previous = 2 * xi - x[j]
            k = pos.get(previous)

            if k is not None:
                length = dp[index(k, i)] + 1
            else:
                length = 2

            dp[index(i, j)] = length

            if length > ans:
                ans = length

    print(ans)

if __name__ == "__main__":
    solve()
```座標辞書が最初に構築されるため、先行するルックアップではすべてのペアに対する二分探索は必要ありません。 座標が違うので、`pos.get(previous)`一意の先行インデックスを返すか、`None`。 

三角形の DP レイアウトは注目に値します。 行`i`ペアのみが含まれます`(i, i+1)`を通して`(i, n-1)`。 その開始位置は、

 [
 \text{base}[i]=\sum_{r=0}^{i-1}(n-r-1)。 
】

 繰り返しがマッピングされます`(i,j)`に`base[i] + (j-i-1)`。 行に最初に保存されているペアであるため、1 による減算が必要です。`i`は`(i,i+1)`。 

繰り返しは次のようになります`dp[index(k, i)]`、 ない`dp[index(i, k)]`、進行は座標と (k<i) によって順序付けされるためです。 先行計算により、先行が存在する場合は必ずこの順序が自動的に保証されます。 

DP 値は、符号なし 16 ビット配列に格納されます。 可能な最大進行長は 3000 で、65535 を余裕で下回ります。これにより、数百万の Python 整数によるメモリ オーバーヘッドが回避されます。 Python の整数演算では、(10^{18}) 付近の座標もオーバーフローすることなく処理されます。 

提灯3個用の専用ケースはございません。 必要な先行関数が存在する場合、ペアの再帰は長さ 2 の状態を長さ 3 に自然に変更します。そのため、サンプルは`1 2 3`別個のロジックなしで 3 を生成します。

## 特殊なケース

 最初のエッジ ケースは、可能な最小の入力です。 と```
3
1 2 3
```ペア`(1,2)`は長さ 2 に初期化されます。アルゴリズムが次の値に達すると、`(2,3)`、(2\cdot2-3=1) を計算し、座標 1 を見つけて、長さ 2 の状態を読み取ります。`(1,2)`。 (2+1=3) が生成されるため、最終的な答えは 3 になります。特別な処理はありません。`n=3`が必要です。 

2 番目のエッジ ケースは、先行するもののないペアです。 のために```
3
1 2 4
```ペア`(2,4)`座標 (2\cdot2-4=0) が必要です。 0 が存在しないため、アルゴリズムはそのペアに長さ 2 を割り当てます。 ペア`(1,2)`これも長さ 2 であり、長さ 3 に達する状態はありません。出力は 2 です。 

3 番目のエッジ ケースは、無関係な座標の間に隠された数列です。 のために```
7
1 2 4 7 10 13 20
```座標`1, 4, 7, 10`差分数列を形成する 3. 処理時`(7,10)`、先行値は 4 であるため、状態は拡張されます。`1,4,7`に`1,4,7,10`。 答えは 4 になります。これにより、隣接する入力要素のみを検査する実装が捕捉されます。 

4 番目のエッジ ケースでは、最大の有効な座標値が使用されます。```
5
0 250000000000000000 500000000000000000 750000000000000000 1000000000000000000
```すべてのギャップは (250000000000000000) であるため、答えは 5 です。先行計算では (10^{18}) と同じくらい大きな値が繰り返し生成され、Python はそれらを正確に処理します。 

要求されたすべてが等しいケース、たとえば、```
3
5 5 5
```この問題では座標が厳密に増加することが保証されているため、有効なテストでは発生しません。 辞書と DP はその保証を中心に設計されているため、この不正な入力は法的なテストであるかのように振る舞うのではなく、実行可能なアサーションから意図的に除外されています。
