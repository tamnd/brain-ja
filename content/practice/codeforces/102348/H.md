 ## 解決策
 ## 問題の理解

 私たちは持っています`n`ランタンは厳密に増加する整数座標に配置されます`x[0], x[1], ..., x[n-1]`。 それらのサブセットを選択してオンのままにすることもできます。 少なくとも 3 つのランタンを選択した場合、それらの座標は等差数列を形成する必要があります。これは、連続して選択されたすべてのペアが同じ距離を持つことを意味します。 ランタンを 0 つ、1 つ、または 2 つ選択しても、制限はありません。 

課題は、そのような等差数列を形成する座標を持つランタンを可能な限り多く見つけることです。 

提灯の数は最大でも`3000`。 二次アルゴリズムは次のように実行します。`9,000,000`状態遷移。これはコンパイルされた実装にとって合理的であり、コンパクトなストレージと定数時間の座標ルックアップを備えた Python でも実用的にすることができます。 三次アルゴリズムは次のように実行されます。`27,000,000,000`最悪の場合、基本的な遷移が発生しますが、これは 2 秒の制限をはるかに超えています。 座標は次のように大きくできます。`10^18`したがって、ソリューションは小さな座標の配列に依存してはなりませんが、Python の整数は算術演算を直接処理します。 

不用意に実装すると失敗するケースがいくつかあります。 たとえば、ランタンがちょうど 3 つある場合、入力は次のようになります。```
3
1 2 4
```答えがあります`2`、 なぜなら`1, 2, 4`は等差数列ではないため、任意の 2 つのランタンを使用できます。 3 つのランタンが常に進行を形成する必要があると仮定したソリューションでは、誤って印刷されます。`3`。 

進行では、入力からの連続したランタンを使用する必要はありません。 のために```
5
1 2 4 6 7
```答えは`3`、座標を使用して`1, 4, 7`。 隣接する入力座標のみを検査するメソッドではギャップが検出されます`1, 2, 2, 1`そして、有益な進歩はないと誤って結論付ける可能性があります。 

必要な先行データが座標範囲外にある場合もあります。 のために```
3
0 10 20
```答えは`3`、その間、```
3
0 10 21
```答えは`2`。 ペアを拡張できるかどうかを確認するときに、計算された先行データ`2*x[i] - x[j]`マイナスになることもあるし、超えることもある`10^18`。 このような値は単に座標マップに存在しないため、検索では座標が有効であると仮定するのではなく、存在しないことを処理する必要があります。 

座標の上部境界も無害です。 のために```
3
0 500000000000000000 1000000000000000000
```答えは`3`。 算術演算では周囲の値が使用されます。`10^18`ただし、座標インデックス付きのストレージは必要ありません。 

## アプローチ

 直接的なアプローチは、希望する進行の最初の 2 つのランタンを選択することです。 座標が取得されたら、`a`そして`b`、共通の違いは次のように固定されます。`d = b - a`したがって、以降の座標はすべて強制されます。`b + d`、 それから`b + 2d`、 等々。 強制された次の座標をすべて配列全体で検索すると、すべてを試すことができます。`O(n^2)`ペアの開始と支出`O(n)`それぞれを拡張する作業。 これにより、`O(n^3)`おおよその時間`3000^3 = 27 billion`最悪の場合のチェック。 

動的プログラムを作成しても、以前のすべてのランタンをスキャンして先行プログラムを検索すると、同じ三次ボトルネックが発生します。 すべてのペアについて`(i, j)`、インデックスを見つける必要があります`k`満足のいく`x[k] = 2*x[i] - x[j]`。 

方程式の構造によって重要な最適化が行われます。 前の座標は、2 つの現在の座標によって一意に決定されます。 すべての座標は別個であるため、座標からそのインデックスまで辞書を構築し、`k`予想通り`O(1)`時間。 

定義する`dp[i][j]`のために`i < j`最後の 2 つのランタンが次のような最も長い等差数列の長さとして`i`そして`j`。 進行状況に前のランタンがある場合`k`、 それから`x[i] - x[k] = x[j] - x[i]`。 

並べ替えると`x[k] = 2*x[i] - x[j]`。 

なぜなら`x[k] < x[i]`、そのようなもの`k`は自動的に次よりも前になります`i`。 したがって、計算するとき、`dp[i][j]`、必要な状態`dp[k][i]`はすでに計算されています。 

先行ペアが存在しない場合、ペアは`(i, j)`それ自体は長さの等差数列です`2`、つまりその状態は`2`。 先行者が存在する場合は、次で終了する最適な進行を拡張します。`(k, i)`ランタンひとつで。 

これにより問題は次のようになります`O(n^2)`動的プログラミング。 唯一の Python 固有の問題はメモリです。 通常の整数からなる完全な Python 行列は不必要に大きいため、実装では DP 値をコンパクトな unsigned-short 配列に格納します。 答えは超えられないから`3000`、すべての状態は 16 ビットに快適に収まります。

 | --- | --- | --- | --- |
 | ブルートフォース |`O(n^3)`|`O(n)`| 遅すぎる |
 | 最適なDP |`O(n^2)`|`O(n^2)`| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 座標を読み取って辞書を作成する`pos`すべての座標をそのインデックスにマッピングします。 座標は一意であるため、すべての検索では可能なインデックスが 1 つだけ存在します。 
2.割り当て`dp[i][j]`すべてのペアに`i < j`。 最初は、すべてのペアが長さの等差数列を表します。`2`したがって、その値は次のようになります。`2`。 
3. 可能な中間インデックスを処理する`i`左から右へ。 あらゆる人にとって`j > i`、先行する必要がある座標を計算します。`x[i]`もし`(x[i], x[j])`は等差数列の最後の 2 つの項でした。 そのコーディネートは`target = 2*x[i] - x[j]`。 
4. 上を向いて`target`で`pos`。 これが存在しない場合、ペアを拡張する方法はありません。`(i, j)`、 それで`dp[i][j]`残る`2`。 
5. もし`target`インデックスに存在します`k`、 それから`k < i`なぜなら`x[j] > x[i]`暗示する`2*x[i] - x[j] < x[i]`。 進行状況は次で終了します`k, i`すでに正しい共通差異があるため、設定します`dp[i][j] = dp[k][i] + 1`。 
6. 最大 DP 値を維持します。 この値は、点灯できるランタンの最大数です。 

### なぜ効果があるのか

 不変条件は次のとおりです`dp[i][j]`が計算されると、それはまさに提灯で終わる最長の等差数列です`i`そして`j`。 そこで終了する進行は、以前の座標が次の値に等しい必要があります。`2*x[i] - x[j]`したがって、可能な先行者は最大 1 つです。 その座標が存在する場合、すべての有効な進行は次の位置で終了します。`(i, j)`で終わる有効な進行を拡張することによって取得されます。`(k, i)`。 これが存在しない場合、少なくとも 3 つの長さの進行は次の時点で終了できません。`(i, j)`、基本の長さを残します`2`。 以来`k < i`、必要な状態はすでに計算されています。 したがって、すべてのペアの最大値を取得すると、考えられるすべての等差数列が考慮されます。 

## Python ソリューション```python
import sys
from array import array

input = sys.stdin.readline

def solve():
    n = int(input())
    x = list(map(int, input().split()))

    pos = {value: i for i, value in enumerate(x)}

    # Every pair initially represents a progression of length 2.
    # n <= 3000, so every answer fits into an unsigned short.
    dp = array('H', [2]) * (n * n)

    ans = 2

    for i in range(n):
        xi = x[i]
        row = i * n

        for j in range(i + 1, n):
            target = 2 * xi - x[j]
            k = pos.get(target)

            if k is not None:
                length = dp[k * n + i] + 1
                dp[row + j] = length
                if length > ans:
                    ans = length

    print(ans)

if __name__ == "__main__":
    solve()
```辞書`pos`アルゴリズムからの定数時間ルックアップ構造です。 表現`2 * xi - x[j]`は、算術進行条件によって強制される正確な先行座標です。 

DP は 1 次元に平坦化されます。`array('H')`。 に対応する状態`(i, j)`に保存されています`i * n + j`。 フラット配列は、数百万の Python 整数の Python リストによって引き起こされるオブジェクトごとの大きなオーバーヘッドを回避します。 

すべての状態は次から始まります`2`異なる座標の任意のペアが有効な選択セットであるためです。 前の状態が存在する場合、状態は前の状態に 1 を加えたもので上書きされます。 

ループの順序は重要です。 国家にとって`(i, j)`、前任者は`k < i`、 それで`dp[k][i]`前の行に属しており、すでに計算されています。 コードを検索する必要はありません`k`手動で`pos`直接供給します。 

Python には整数オーバーフローの問題はありません。 最大の中間座標は約`2 * 10^18`、Python の整数は正確に表します。 

答えは次のように初期化されます`2`。 以来`n >= 3`、有効なペアが常に存在し、長さの進行`2`常に許可されます。
