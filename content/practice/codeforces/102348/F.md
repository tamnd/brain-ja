 ## 問題の理解

 整数の配列があり、すべての連続する部分配列には負、ゼロ、または正のいずれかの積があります。 タスクは、これら 3 つのカテゴリのそれぞれに属するサブ配列の数を数え、その数を負、ゼロ、正の順に出力することです。 

実際の値の大きさは (10^9) ほど大きくなる可能性がありますが、その大きさは積の符号には関係ありません。 非ゼロ要素の場合、それが正であるか負であるかだけが問題になります。 単一のゼロは、そのゼロを含むすべての部分配列に積ゼロがあるため、異なります。 

(n) が (2\cdot10^5) までの場合、(O(n^2)) のソリューションはすでに約について検査する必要があります。 

[
 \frac{n(n+1)}2 \約 2\cdot10^{10}
 】

 最悪の場合はサブアレイ。 これは 2 秒の制限時間で処理できる範囲をはるかに超えています。 線形または線形に近い解決策が必要です。 また、メモリ制限が 256 MB であるため、すべてのサブアレイに関する情報を保存するのではなく、少量の状態のみを保持することが有利になります。 

素朴なソリューションを静かに破壊する可能性のあるエッジケースがいくつかあります。 ゼロは個別に処理する必要があります。 たとえば、```
3
1 0 -1
```正しい答えは`0 3 2`。 3 つのゼロ積部分配列は次のとおりです。`[1,0]`、`[0]`、 そして`[0,-1]`。 負の値のパリティのみを追跡し、ゼロを無視するソリューションでは、これらのサブ配列の一部が正または負として誤って分類されてしまいます。 

サブ配列の長さは 1 であることが許可されているため、単一要素の配列も重要です。 のために```
1
-7
```答えは`1 0 0`。 誤って異なるインデックスのペアのみを考慮するソリューションでは、唯一の有効な部分配列が失われます。 

ゼロのみを含むシーケンスは、別の有用な境界ケースを提供します。```
3
0 0 0
```6 つの部分配列のすべてに 0 が含まれるため、答えは次のようになります。`0 6 0`。 ゼロにより配列が独立した非ゼロ領域に分割されるため、ゼロの後に符号状態をリセットする必要があります。 

最後に、カウント自体が 32 ビット整数の範囲を超える可能性があります。 (n=2\cdot10^5) の場合、合計サブ配列は (20,000,100,000) 個になります。 32 ビットの符号付き整数はその値を表すことができません。 Python の整数はこれを自動的に処理しますが、C++ の同じアルゴリズムでは次の処理が必要になります。`long long`。 

## アプローチ

 直接的なアプローチは、エンドポイントのすべてのペア ((l,r)) を列挙し、その部分配列の積を計算し、その符号を分類することです。 すべてのペアに対して積を最初から再計算する場合、(O(n^2)) 個の部分配列があり、各積には (O(n)) 個の要素を含めることができるため、アルゴリズムには (O(n^3)) 時間がかかります。 (n=2\cdot10^5) の場合、これは完全に不可能です。 

左のエンドポイントを固定し、右のエンドポイントを一度に 1 位置ずつ拡張することで、ブルート フォースを改善できます。 積を再計算する代わりに、新しい要素が追加されたときにのみその符号を更新します。 これによりメソッド (O(n^2)) が作成され、これは大きな改善ですが、まだ約 (2\cdot10^{10}) 個の部分配列を処理する必要があります。 2 秒の制限により、これは排除されます。 

重要な観察は、非ゼロ積の符号は負の要素の数のパリティのみに依存するということです。 負の係数が偶数であれば正の積が生成され、奇数であれば負の積が生成されます。 実際の製品はまったく必要ありません。 

配列のゼロのない部分を考えてみましょう。 プレフィックスのパリティを、プレフィックスに偶数の負の値が含まれる場合は (0)、奇数が含まれる場合は (1) として定義します。 (l) から (r) までのサブ配列の場合、2 を法とする負の要素の数は、サブ配列の直前と最後にある 2 つのプレフィックス パリティの XOR です。 その結果、2 つの等しいプレフィックス パリティは正のサブ配列を与え、2 つの異なるプレフィックス パリティは負のサブ配列を与えます。 

これにより、2 つのカウンターのみを使用して、すべての位置で終わるサブ配列をカウントできるようになります。 現在のプレフィックス パリティが (p) の場合、パリティ (p) を持つすべての以前のプレフィックスはここで終わる正のサブ配列を作成し、パリティ (1-p) を持つすべての以前のプレフィックスは負のサブ配列を作成します。 

ゼロには追加のアイデアが 1 つ必要です。 ゼロを含むサブ配列には積ゼロが含まれるため、そのようなサブ配列は正または負のパリティ カウントに決して参加すべきではありません。 ゼロごとにプレフィックス パリティ カウンタをリセットするだけです。 最大のゼロフリー セグメントはそれぞれ独立して処理できます。 

ブルートフォース手法は、すべての部分配列を明示的に考慮するため機能します。 数が多すぎるため失敗します。 符号パリティのみが重要であるという観察により、これらすべてのサブ配列を 2 つのプレフィックス状態のカウントに置き換えることができ、配列を 1 回通過することができます。

 ## アルゴリズムのチュートリアル

 1.キープ`cnt[0]`そして`cnt[1]`、現在偶数および奇数の負のカウント パリティを持つ関連するプレフィックス位置の数を表します。 最初は、空のプレフィックスは偶数パリティを持っているため、`cnt[0] = 1`そして`cnt[1] = 0`。 
2. メンテナンス`parity`、これは、現在のゼロのないセグメント内の負の値の数のパリティです。 正の値を指定すると変更されず、負の値を指定すると反転します。 
3. 現在値がゼロ以外の場合、更新します。`parity`値が負の場合。 結果のパリティが次の場合`p`、パリティ付きの以前のすべてのプレフィックス`p`偶数の負の値を含む部分配列を形成するため、次の値を追加します。`cnt[p]`肯定的な答えに。 パリティ付きの以前のすべてのプレフィックス`1-p`奇数の負の値を含む部分配列を形成するため、次の値を追加します。`cnt[1-p]`否定的な答えに対して。 
4. インクリメント`cnt[p]`現在の位置で終わる接頭辞は将来の部分配列で使用できるためです。 
5. 現在の値がゼロの場合、この位置で終わるすべてのサブ配列にはこのゼロが含まれるため、積はゼロになります。 まさにあります`i+1`ゼロから始まるインデックスで終わる部分配列`i`ので、追加します`i+1`ゼロの答えへ。 
6.リセット`parity`ゼロにして復元する`cnt[0] = 1`、`cnt[1] = 0`ゼロの後。 次の非ゼロ部分配列は、非ゼロのままでゼロを越えることはできないため、ゼロの前のプレフィックス パリティをその後のプレフィックス パリティと混合してはなりません。 
7. 負の数、ゼロの数、正の数をこの順序で出力します。 

### なぜ効果があるのか

 ゼロフリー セグメント内で、エンドポイントが 2 つのプレフィックス状態に対応するサブ配列を考えます。 2 を法とする負の要素の数は、プレフィックス パリティの XOR です。 等しいパリティでは偶数の負の値が生成されるため、正の積が生成されます。 パリティが異なると奇数の負の数が生成されるため、負の積が生成されます。 カウンタには、各パリティを持つ以前のプレフィックスの数が正確に保存されるため、ゼロ以外のすべてのサブ配列は、その右のエンドポイントが処理されるときに正確に 1 回カウントされます。 

このパリティ引数にゼロが含まれることはありません。 ゼロと交差するすべてのサブ配列は積ゼロを持ちますが、ゼロ以外のすべてのサブ配列は完全に 2 つのゼロの間にあります。 各ゼロの後でカウンタをリセットすると、これら 2 つのケースが完全に分離されます。 したがって、すべてのサブ配列は、負、ゼロ、または正に 1 回だけ分類されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    negative = 0
    zero = 0
    positive = 0

    parity = 0
    cnt = [1, 0]

    for i, x in enumerate(a):
        if x == 0:
            zero += i + 1

            parity = 0
            cnt[0] = 1
            cnt[1] = 0
            continue

        if x < 0:
            parity ^= 1

        positive += cnt[parity]
        negative += cnt[parity ^ 1]

        cnt[parity] += 1

    print(negative, zero, positive)

if __name__ == "__main__":
    solve()
```3 つの回答変数には最終的なカウントが保存されます。 それらはおよそ (n(n+1)/2) まで増加する可能性があるため、ここでは Python の任意精度の整数が便利です。`parity`現在のゼロフリープレフィックス内のすべての非ゼロ要素の積の符号を表します。 負の要素はパリティを反転しますが、正の要素は何も行いません。 

初期化`cnt = [1, 0]`は空のプレフィックスを表します。 これにより、最初の要素から始まるサブ配列をカウントできるようになります。 たとえば、最初の要素が負の場合、現在のパリティは 1 になり、最初の偶数プレフィックスによって 1 つの負のサブ配列が作成されます。 

ゼロ以外の要素の場合、`cnt[parity]`に追加されます`positive`等しいプレフィックスパリティはモジュロ 2 をキャンセルするためです。`cnt[parity ^ 1]`に追加されます`negative`異なるパリティでは、一致しない負のパリティが 1 つ残るためです。 

ゼロ処理では、`i + 1`ゼロそのものを数えるだけではなく。 位置で`i`、まさにあります`i + 1`左の端点の選択肢があり、それらの部分配列はすべて 0 で終わるため、積は 0 になります。 

ゼロ後のリセットは必須です。 これがないと、ゼロの前のプレフィックスがゼロの後のプレフィックスとペアになり、実際にはゼロを含む部分配列に対して正または負のカウントが誤って生成される可能性があります。 

このアルゴリズムには乗算演算がないため、潜在的に膨大な中間積を表現する必要はありません。 重要な最大値は回答数であり、Python はそのサイズを安全に処理します。
