 ## 解決策
 ## 問題の理解

 (n) 個の整数の配列があり、すべての連続する部分配列はその積の符号に従って寄与します。 エンドポイントの各ペア (l \le r) について、(a_​​l,a_{l+1},\ldots,a_r) の積は、負、ゼロ、または正のいずれかになります。 各カテゴリに属する​​サブ配列の数を数え、3 つのカウントをその順序で出力する必要があります。 

ゼロ以外の積の実際の値は無関係です。 その符号のみが重要です。 部分配列に奇数の負の要素が含まれる場合、積はまさに負となり、偶数の負の要素が含まれる場合、積は正となります。 少なくとも 1 つのゼロを含む部分配列には積ゼロがあります。 

配列には最大 (2\cdot10^5) 個の要素を含めることができます。 二次アルゴリズムは、おおよそ (n(n+1)/2) 個の部分配列を検査します。これは、(n=2\cdot10^5) の場合、約 (2\cdot10^{10}) になります。 これは 2 秒の制限が処理できる範囲をはるかに超えています。 (O(n)) または (O(n\log n)) の解が必要です。 答え自体も (n(n+1)/2) 程度になる可能性があるため、固定幅の整数型を使用する言語では 64 ビット整数が必要です。 Python の整数はすでにこれらの値を安全に処理します。 

ゼロは符号情報を破壊するため、ゼロは別個に処理する必要があります。 たとえば、入力の場合```
1
0
```正しい答えは```
0 1 0
```ゼロを正でも負でもないとして扱うが、以前のプレフィックス状態を継続する符号パリティ アルゴリズムでは、サブ配列がゼロを横切り、古い符号によって分類されることを誤って許可してしまいます。 ゼロは、配列を独立した非ゼロのセグメントに分割する必要があります。 

誤って処理しやすいもう 1 つのケースは、正の値のみを含む配列です。 のために```
3
1 1 1
```(6) 個のサブ配列のすべてに正の積があるため、答えは次のようになります。```
0 0 6
```符号が変化する積のみをカウントする方法では、単一要素および正の要素の偶数長の組み合わせをカウントすることを忘れる可能性があります。 

負の値の場合は、空のプレフィックスを正確にカウントする必要もあります。 のために```
3
-1 -1 -1
```正しい答えは```
4 0 2
```負の積のサブ配列は奇数の長さを持ち、(3+1=4) になりますが、2 つの偶数の長さのサブ配列は正の積を持ちます。 最初の要素の前の接頭辞を忘れると、インデックス (1) から始まる部分配列が失われます。 

Finally, zeros can occur at the boundaries. のために```
3
0 1 0
```正しい答えは```
0 5 1
```合計 6 つの部分配列があり、([2,2]) のみがゼロ以外の正の積を持ちます。 他の 5 つはゼロを含みます。 ゼロに遭遇した場合にのみゼロを含む部分配列をカウントするソリューションでは、そのゼロを超えて続く部分配列を見逃す可能性があります。 

## アプローチ

 直接的なアプローチは、エンドポイントのすべてのペア ((l,r)) を列挙することです。 左の端点が固定されている場合、右の端点を一度に 1 位置ずつ拡張して、現在の積符号を維持できます。 負の要素の数が奇数であるか偶数であるかのみが重要であり、ゼロはすぐに検出できるため、実際の値を乗算する必要はありません。 

すべての連続する部分配列が 1 回だけ考慮されるため、この強引な方法は正しいです。 問題は部分配列の数です。 それらは (n(n+1)/2) 個あり、(n=200,000) に対して (20,000,100,000) に達します。 サブ配列ごとの定数処理でも多すぎるため、2 次アプローチは除外されます。 

重要な観察は、非ゼロ部分配列の符号は、その内部の負の要素の数のパリティのみに依存するということです。 このパリティは、偶数の負数の場合は (0)、奇数の場合は (1) としてエンコードできます。 

プレフィックスパリティを考慮してください。 (p_i) を、位置 (i) までの現在の非ゼロ セグメント間の負の要素の数のパリティとします。 (l) から (r) までの部分配列の場合、(2) を法とする負の要素の数は次のようになります。 

[
 p_r \oplus p_{l-1}。 
】

 したがって、2 つのプレフィックス パリティが等しい場合、サブ配列の積は正になります。 それらが異なる場合、サブ配列には負の積が生じます。 

左から右にスキャンするとき、偶数パリティと奇数パリティを持つ以前のプレフィックスがいくつあるかを知る必要があるだけです。 現在のプレフィックス パリティが偶数の場合、前のすべての偶数プレフィックスはここで終わる正積サブ配列を形成し、以前のすべての奇数プレフィックスは負積サブ配列を形成します。 現在のパリティが奇数の場合、状況は逆になります。 

ゼロは単に独立したセグメントを区切るだけです。 ゼロが現れると、有効なゼロ以外の部分配列はそれを横切ることができないため、プレフィックス パリティ カウントは初期状態にリセットされます。 

すべての非ゼロ積がカウントされると、残りのすべてのサブ配列の積がゼロになる必要があります。 合計 (n(n+1)/2) 個の部分配列があるため、

 [
 \text{ゼロ} =
 \frac{n(n+1)}2-\text{ネガティブ}-\text{ポジティブ}。 
】

 これにより、ゼロを含む部分配列を直接カウントする必要がなくなります。

 ## アルゴリズムのチュートリアル

 1. 偶数プレフィックス 1 つと奇数プレフィックス 0 から始めます。 最初のプレフィックスは、最初の要素の前の空のシーケンスを表し、その負の値の数は 0 です。 
2. メンテナンス`even`そして`odd`、偶数および奇数の負のカウントパリティを持つ以前のプレフィックス状態の数。 また、現在のパリティも維持します。`0`偶数を意味し、`1`奇数という意味です。 
3. すべての配列要素について、最初にそれがゼロであるかどうかを確認します。 ゼロの場合はリセットする`even`(1)に、`odd`を (0) に、現在のパリティを偶数にします。 配列のゼロ以外の部分はゼロで区切られるため、その前のプレフィックスをその後のプレフィックスと組み合わせてはなりません。 
4. 要素が負の場合、現在のパリティを反転します。 要素が正の場合、パリティを変更しないままにします。 符号のみが重要であるため、要素の大きさが計算に含まれることはありません。 
5. 現在のパリティが偶数の場合、次の値を追加します。`even`プラスのカウントと`odd`マイナスカウントにします。 前のすべての偶数プレフィックスは 2 つのプレフィックス間の偶数の負数を生成し、前のすべての奇数プレフィックスは奇数を生成します。 
6. 現在のパリティが奇数の場合は、次の値を追加します。`odd`プラスのカウントと`even`マイナスカウントにします。 等しいプレフィックス パリティは依然として偶数の差に相殺されるため、2 つのケースは逆になります。 
7. 現在のプレフィックスを適切なカウンターに追加します。 現在のプレフィックスは同じ位置で終わるサブ配列の左境界として使用できないため、これは、現在の位置で終わるサブ配列を数えた後に行われなければなりません。 
8. 配列全体を処理した後、サブ配列の総数を (n(n+1)/2) として計算します。 正のカウントと負のカウントを減算して、積が 0 になる数値を取得します。 

### なぜ効果があるのか

 ゼロ以外のすべての部分配列の符号は、負の要素の数のパリティによって決まります。 ([l,r]) 内の負のカウントのパリティは、(r) の直後と (l) の直前のプレフィックス パリティの XOR です。 したがって、等しいプレフィックス パリティは正の積を表し、異なるプレフィックス パリティは負の積を表します。 カウンター`even`そして`odd`必要な以前のプレフィックスが正確に含まれているため、ゼロ以外のすべてのサブ配列は、その右のエンドポイントが処理されるときに 1 回カウントされます。 ゼロの後にリセットすると、ゼロを含むサブ配列がこれらのカウントに入ることがなくなります。 すべての部分配列は正、負、またはゼロのいずれかであるため、合計から 2 つの非ゼロのカウントを減算すると、正確にゼロのカウントが得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def count_products(a):
    n = len(a)

    # Number of previous prefix parities in the current nonzero segment.
    even = 1
    odd = 0

    parity = 0

    negative = 0
    positive = 0

    for x in a:
        if x == 0:
            # No nonzero subarray can cross a zero.
            even = 1
            odd = 0
            parity = 0
            continue

        if x < 0:
            parity ^= 1

        if parity == 0:
            positive += even
            negative += odd
            even += 1
        else:
            positive += odd
            negative += even
            odd += 1

    total = n * (n + 1) // 2
    zero = total - positive - negative

    return negative, zero, positive

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    negative, zero, positive = count_products(a)
    print(negative, zero, positive)

if __name__ == "__main__":
    solve()
```機能`count_products`リニアスキャン全体が含まれます。`even = 1`最初の要素の前のプレフィックスを表します。 この初期化により、最初の配列位置から始まるサブ配列をカウントできるようになります。 

負の値の場合、`parity ^= 1`もう 1 つの負の要素に遭遇したため、パリティを反転します。 正の値の場合、パリティは変更されません。 ゼロ以外の値の実際の大きさは決して使用されません。 

への追加`positive`そして`negative`増加する前に発生する`even`または`odd`。 現時点では、これらのカウンターは厳密に現在の要素の前にあるプレフィックスのみを記述します。これはまさにエンドポイント式が必要とするものです。 最初にそれらを更新すると、無効な空の長さの貢献が導入されます。 

いつ`x == 0`、現在の非ゼロセグメントが終了します。 にリセットする`even = 1`、`odd = 0`、 そして`parity = 0`ゼロの直後に新しいプレフィックス シーケンスを開始します。 ゼロを含むサブ配列は、正および負のカウントから意図的に除外されます。 

表現`n * (n + 1) // 2`考えられるすべてのエンドポイントのペアをカウントします。 Python の任意精度の整数により、特別な処理を行わなくても、潜在的に大きな答えが安全になります。
