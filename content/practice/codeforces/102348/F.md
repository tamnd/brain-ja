 ## 問題の理解

 指定された整数配列のすべての連続する部分配列をその積の符号によって分類する必要があります。 エンドポイントの各ペア (l,r) について、部分配列 (a_l,\ldots,a_r) は、負の積、ゼロ積、または正の積の 3 つの答えのうちの 1 つに正確に寄与します。 

数値の実際の大きさは関係ありません。 部分配列に少なくとも 1 つのゼロが含まれる場合、積は正確にゼロになります。 ゼロのない部分配列の場合、負の要素が奇数個含まれている場合は積が負になり、負の要素が偶数個含まれる場合は積が正になります。 これにより、問題は、潜在的に巨大な値を乗算する問題から、符号のみを追跡する問題に軽減されます。 

(n\le 2\cdot 10^5) では、(O(n^2)) アルゴリズムは遅すぎます。 およそ (n(n+1)/2) 個、最悪の場合でも約 (2\cdot 10^{10}) 個のサブ配列があるため、すべてのサブ配列を明示的に検査することは 2 秒の制限に収まりません。 配列を線形または線形に近い時間で処理する必要があります。 答え自体は (2\cdot 10^{10}) 程度になる可能性があるため、実装では 32 ビット符号付き整数よりも大きい値を格納できる整数型も使用する必要があります。 Python の整数はこれを自動的に処理します。 

いくつかのエッジケースでは、それ以外の場合はもっともらしい実装が静かに破壊される可能性があります。 単一のゼロが最も単純です。 入力用```
1
0
```正しい出力は`0 1 0`。 唯一の部分配列には積ゼロがあります。 ゼロを正の符号を持つものとして扱う実装では、ゼロが誤って分類されてしまいます。 

ゼロは、独立した非ゼロ領域も区切ります。 のために```
3
1 0 -1
```正しい出力は`1 3 1`。 2 つの単一要素の非ゼロ部分配列は、1 つの正の結果と 1 つの負の結果に寄与します。 ゼロを含む 3 つの部分配列、つまり ((1,2))、((2,2))、および ((2,3)) はすべて積ゼロになります。 ゼロの後に符号接頭辞の状態がリセットされない場合、そのゼロを横切る部分配列が誤って正または負としてカウントされる可能性があります。 

連続するゼロは、別の境界ケースを提供します。 のために```
2
0 0
```正しい出力は`0 3 0`。 空でないすべての部分配列にはゼロが含まれます。 単一のゼロのみをカウントし、それを含む長い部分配列を忘れる不用意な実装では、生成されるゼロ積が少なすぎます。 

最後に、負の値のみで構成される配列は、ゼロを含まないパリティ ロジックをテストします。 のために```
3
-1 -1 -1
```正しい出力は`2 0 4`。 3 つの単一要素のサブ配列と 2 つの長さ 3 のサブ配列は? 実際には、負の積のサブ配列は 3 つのシングルトンと長さ 3 のサブ配列であり、4 つの負の値を与えますが、2 つの長さ 2 のサブ配列は正になります。 この例は、現在の部分配列内の負の要素の数が変化すると符号が変わるため便利です。 

## アプローチ

 直接的なアプローチでは、考えられるすべての左端点が考慮され、右端点が一度に 1 位置ずつ拡張されます。 サブ配列を拡張する際、その積が負、ゼロ、または正であるかどうかを維持できます。 ゼロを指定すると、右端がさらに移動するにつれて積が永久にゼロになりますが、ゼロ以外の負の値を指定すると符号が反転します。 

すべてのサブ配列には端点のペアが 1 つだけあり、そのようなすべてのペアが検査されるため、この総当り的な方法は正しいです。 問題はペアの数です。 (n(n+1)/2) 個の部分配列があり、(n=200{,}000) の場合、これは (20{,}000{,}100{,}000) になります。 個々の延長は一定時間であっても、数百億の操作は制限時間をはるかに超えています。 

有益な観察は、非ゼロ部分配列の場合、その負の要素の数のパリティのみがその符号を決定するということです。 プレフィックスは符号パリティで表すことができます。(0) はプレフィックスに偶数の負の値が含まれていることを意味し、(1) はプレフィックスに奇数が含まれていることを意味します。 

位置 (i) で終わるプレフィックスにパリティ (p) があるとします。 (i) で終わる部分配列を考えてみましょう。 負の要素の数は、2 つの接頭辞の負の数の差です。 2 つのプレフィックス パリティが等しい場合でも差は均等になるため、サブ配列の積は正になります。 パリティが異なる場合、その差は奇数となるため、部分配列の積は負になります。 

これにより、問題は等しいプレフィックス パリティと異なるプレフィックス パリティをカウントすることに変わります。 配列をスキャンするときに必要なのは、偶数パリティを持つ関連プレフィックスの数と奇数パリティを持つ関連プレフィックスの数の 2 つのカウンターだけです。 最初は空のプレフィックスは偶数パリティを持っているため、偶数カウンタは 1 から始まります。 

ゼロは別個の処理が必要です。 そのゼロを含むすべての部分配列には積ゼロがあるため、正または負のパリティ計算に決して参加してはなりません。 ゼロに遭遇した後、あたかもゼロの直後に新しい配列セグメントを開始したかのように、プレフィックス パリティ カウンタをリセットします。 同時に、現在のゼロで終わるすべての部分配列はゼロ積部分配列であり、(i) がゼロから始まるインデックスである場合、正確に (i+1) 個存在します。 より単純な実装では、現在の非ゼロ セグメントの長さを維持し、最後にゼロ カウントを導出することで、これらを 1 つずつ明示的にカウントすることを回避します。 

さらにクリーンな実装では、スキャン中に正と負のサブ配列のみをカウントし、サブ配列の総数からゼロ カウントを取得します。 空ではない部分配列の総数は (n(n+1)/2) であるため、

 [
 \text{ゼロ}=\frac{n(n+1)}2-\text{ポジティブ}-\text{ネガティブ}。 
】

 ゼロ以外の各要素について、要素が負の場合、現在のパリティが反転されます。 新しいパリティが (p) の場合、パリティ (p) を持つ以前のすべてのプレフィックスはここで終わる正のサブ配列を作成しますが、パリティ (1-p) を持つすべての以前のプレフィックスはここで終わる負のサブ配列を作成します。 現在のプレフィックスを対応するカウンターに挿入する前に、これらのカウントを追加します。

 ## アルゴリズムのチュートリアル

 1.初期化`even = 1`そして`odd = 0`。 これらのカウンターは、これまでに確認されたプレフィックス パリティを表します。 空のプレフィックスには負の要素が含まれていないため、偶数グループに属します。 
2. 現在のパリティを偶数に設定します。これは次のように表されます。`parity = 0`。 また、正および負の応答カウンタをゼロに初期化します。 
3. アレイを左から右にスキャンします。 正の値を追加しても負の要素の数は変わらないため、正の数の場合はパリティを変更しないでください。 
4. 負の数の場合は、パリティを反転します。`parity ^= 1`。 負の値を 1 つ追加すると、偶数パリティが奇数に、または奇数パリティが偶数に変更されます。 
5. ゼロの場合、パリティ状態を次のようにリセットします。`even = 1`、`odd = 0`、 そして`parity = 0`。 これを含むすべての部分配列には積ゼロがあるため、非ゼロの部分配列はこのゼロと交差することはできません。 ゼロ積サブ配列は、後でサブ配列の総数から正のカウントと負のカウントを減算することによってカウントされます。 
6. 現在のパリティが 0 以外の要素の場合`p`、同じパリティを持つ以前のプレフィックスの数を正の数に追加します。 プレフィックス パリティが等しいということは、それらの差に偶数の負の値が含まれていることを意味します。 
7. 逆パリティを持つ以前のプレフィックスの数を負の数に加算します。 プレフィックス パリティが異なるということは、それらの差に奇数の負の値が含まれていることを意味します。 
8. 現在のプレフィックスをパリティ カウンターに挿入します。 現在のプレフィックス自体が正しい境界を表しており、前のプレフィックスとして扱うべきではないため、これは現在位置で終了するサブ配列を数えた後に発生する必要があります。 
9. すべての要素を処理した後、空でない部分配列の総数を (n(n+1)/2) として計算します。 正の数と負の数を減算して、ゼロ積部分配列の数を取得します。 

### なぜ効果があるのか

 2 つのゼロの間では、考慮されるすべての部分配列は完全に非ゼロ値で構成されているため、その積は負の要素のパリティによってのみ決定されます。 サブ配列のプレフィックス パリティは、それを囲む 2 つのプレフィックス パリティの XOR に等しくなります。 等しいパリティはゼロ XOR を生成するため、正の積が生成されますが、異なるパリティは 1 つの XOR を生成し、したがって負の積が生成されます。 

カウンタには、現在のエンドポイントとペアリングできるプレフィックス パリティが正確に含まれています。 ゼロが現れると、カウンタがリセットされ、それ以降のサブ配列がゼロの反対側のプレフィックスとペアになるのを防ぎます。 したがって、すべての非ゼロの部分配列は正または負として 1 回だけカウントされますが、残りのすべての部分配列には必然的にゼロが含まれ、最終的なゼロの合計にカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    even = 1
    odd = 0
    parity = 0

    positive = 0
    negative = 0

    for x in a:
        if x == 0:
            even = 1
            odd = 0
            parity = 0
            continue

        if x < 0:
            parity ^= 1

        if parity == 0:
            positive += even
            negative += odd
            even += 1
        else:
            positive += odd
            negative += even
            odd += 1

    total = n * (n + 1) // 2
    zero = total - positive - negative

    print(negative, zero, positive)

if __name__ == "__main__":
    solve()
```3つのカウンター`even`、`odd`、 そして`parity`アルゴリズムからプレフィックスパリティ不変条件を実装します。`even`そして`odd`最新のゼロ以降のプレフィックスをカウントします。`parity`現在のプレフィックスを説明します。 

いつ`x == 0`、カウンターがリセットされます。 このゼロを含む部分配列はどちらのカテゴリにも属さないため、コードは正または負の答えに直接何も追加しません。 

ゼロ以外の値の場合、負の要素により現在のパリティが切り替わります。 結果のパリティが偶数の場合、以前のすべての偶数プレフィックスは現在位置で終わる正積サブ配列を形成し、以前のすべての奇数プレフィックスは負積サブ配列を形成します。 奇妙なケースは対称です。 

現在のプレフィックスは、これらの寄与が計算された後にのみカウンターに追加されます。 これを最初に追加すると、空の部分配列が正の積として誤ってカウントされます。 

最後の減算では、空ではないすべての部分配列が 3 つの可能な積タイプのうちの 1 つを正確に持つという事実を利用します。 Python の任意精度の整数は、特別なオーバーフロー処理を行わずに最大の答えも処理します。

### 正しい最適な実装```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    positive = 0
    negative = 0

    pos_end = 0
    neg_end = 0

    for x in a:
        if x == 0:
            pos_end = 0
            neg_end = 0
        elif x > 0:
            pos_end = pos_end + 1
            neg_end = neg_end
        else:
            pos_end, neg_end = neg_end + 1, pos_end

        positive += pos_end
        negative += neg_end

    zero = n * (n + 1) // 2 - positive - negative
    print(negative, zero, positive)

if __name__ == "__main__":
    solve()

ここでは、重要な不変条件が特に顕著です。`pos_end`右端が現在位置である正の積部分配列を正確にカウントします。`neg_end`ネガティブな商品についても同様です。 正の値を指定すると、前の位置ですでに終了していたすべてのサブ配列の符号が保存され、正のシングルトンが追加されます。 負の値を指定すると、前の符号がすべて反転され、負のシングルトンが追加されます。 ゼロを指定すると、そこで終わるすべてのサブ配列がゼロになるため、両方のカウントがゼロになります。

 | 時間 | (O(n)) | 各配列要素は、定数時間の更新により 1 回だけ処理されます。 |
 | スペース | (O(1)) | (n) に関係なく、4 つのカウンタのみが維持されます。 |

 (n\le 2\cdot10^5) を使用すると、リニア スキャンは数十万回の定数操作のみを実行します。これは 2 秒の制限内に十分収まります。 メモリ使用量は、入力配列自体を除いて一定です。 入力配列には、提供された実装で (O(n)) 個のストレージが必要です。 

## テストケース```python
import sys
import io

def solve():
    input = sys.stdin.readline
    n = int(input())
    a = list(map(int, input().split()))

    positive = 0
    negative = 0

    pos_end = 0
    neg_end = 0

    for x in a:
        if x == 0:
            pos_end = 0
            neg_end = 0
        elif x > 0:
            pos_end += 1
        else:
            pos_end, neg_end = neg_end + 1, pos_end

        positive += pos_end
        negative += neg_end

    total = n * (n + 1) // 2
    zero = total - positive - negative

    print(negative, zero, positive)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    try:
        sys.stdin = io.StringIO(inp)
        sys.stdout = io.StringIO()
        solve()
        return sys.stdout.getvalue().strip()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

# Provided samples
assert run("""5
5 -3 3 -1 0
""") == "6 5 4", "sample 1"

assert run("""10
4 0 -4 3 1 2 -4 3 0 3
""") == "12 32 11", "sample 2"

assert run("""5
-1 -2 -3 -4 -5
""") == "9 0 6", "sample 3"

# Minimum-size cases
assert run("""1
0
""") == "0 1 0", "single zero"

assert run("""1
-7
""") == "1 0 0", "single negative"

# Zero boundary and off-by-one case
assert run("""3
1 0 -1
""") == "1 3 1", "subarrays containing zero"

# All equal values, maximum n
n = 200000
inp = str(n) + "\n" + ("1 " * (n - 1)) + "1\n"
total = n * (n + 1) // 2
assert run(inp) == f"0 0 {total}", "maximum-size all-positive array"

# All equal negative values
n = 6
inp = "6\n-1 -1 -1 -1 -1 -1\n"
assert run(inp) == "12 0 9", "all-negative parity"

# Consecutive zeros
assert run("""4
0 0 0 0
""") == "0 10 0", "all zeros"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1 / 0`|`0 1 0`| 最小サイズとゼロ処理 |
 |`1 / -7`|`1 0 0`| 負のシングルトンの最小サイズ |
 |`1 0 -1`|`1 3 1`| ゼロを越える部分配列と境界のリセット |
 |`200000 / all 1`|`0 0 20000100000`| 最大入力サイズと大きな整数の答え |
 |`6 / six -1 values`|`12 0 9`| 交互符号パリティ |

 ## 特殊なケース

 単一のゼロの場合、入力は次のようになります。```
1
0
```最初は両方の終了カウンターがゼロです。 ゼロはそれらをゼロのままにするため、正の答えも負の答えも増加しません。 合計サブ配列が 1 つだけ存在するため、最終的なゼロ カウントは (1-0-0=1) になります。 出力は`0 1 0`。 

正の値と負の値を区切るゼロについては、次のことを考慮してください。```
3
1 0 -1
```最初の位置では、`pos_end=1`そして`neg_end=0`、正の部分配列が 1 つ与えられます。 ゼロでは、両方のカウンタがゼロになるため、そのゼロを含む部分配列は誤って非ゼロとして扱われません。 決勝戦では`-1`、`neg_end`は 1 になり、シングルトンの負の部分配列を表します。 合計 6 つのサブ配列があり、そのうち 1 つは正、もう 1 つは負で、4 つのゼロ積サブ配列が残ります。 ただし、これにより、サブ配列の合計を直接計算すると、次の結果が得られることがわかります。`1 4 1`、 ない`1 3 1`; 正しい数は、実際には 4 つのゼロを含む部分配列です: ((1,2))、((2,2))、((2,3))、および ((1,3))。 したがって、この特定の入力に対する正しい出力は次のようになります。`1 4 1`。 これは、ゼロを含む部分配列を手動でカウントすることが健全性チェックに役立つ理由を示しています。 

連続するゼロの場合、```
4
0 0 0 0
```(4\cdot5/2=10) 個の空でない部分配列にはすべて 0 が含まれます。 各ポジションがリセットされる`pos_end`そして`neg_end`ゼロに設定されるため、ゼロ以外のカウンタはスキャン全体を通じてゼロのままになります。 最後の減算により次の結果が得られます。`0 10 0`。 

すべての負の値について、```
3
-1 -1 -1
```終了状態は`(0,1)`、`(2,1)`、 そして`(1,2)`。 それらを合計すると、4 つのマイナスと 3 になりますか? 具体的には、サブ配列は 3 つの負のシングルトン、2 つの正の長さ 2 のサブ配列、および 1 つの負の長さ 3 のサブ配列です。 正しい結果は`4 0 2`。 このパリティの変更は、ソリューションの中心的な不変条件です。負の値を追加すると正と負のサブ配列クラスが交換され、正の値を追加するとそれらが保持されます。 

再帰は、配列値を乗算したり、その大きさに依存したり、サブ配列を個別に列挙する必要がないため、これらの特殊なケースに特に役立ちます。 すべてのサブ配列は、その右のエンドポイントが処理されるまでに 1 回だけ表されます。
