 ## 解決策
 ## 問題の理解

 (n) 個のビー玉の列があり、各ビー玉には最大 20 色のいずれかが含まれています。 隣接するビー玉を交換することができ、目標は、すべての色が 1 つの連続したブロックを占めるようにすることです。 ブロック自体は任意の順序で表示できます。 

重要な難点は、色の最終的な順序が指定されていないことです。 この順序が修正されると、問題は標準的な最小隣接スワップ問題になります。 本当の仕事は、異なる色の最適な組み合わせを選択することです。 

個別の色を (k) 色とする。 すべての色は 1 から 20 (k\leq20) の間であるため、(n) が (4\cdot10^5) ほど大きくなる場合もあります。 色数のこの小さな限界が、サブセット動的プログラミング ソリューションが可能な理由です。 (n) の解多項式と (k) のみの指数関数は実用的ですが、(n) の指数関数は完全に不可能です。 

境界 (n\leq4\cdot10^5) により、スワップの繰り返しシミュレーションも除外されます。 1 つの変換には (\frac{n(n-1)}2) 個の隣接するスワップが必要になる可能性があり、最大 (n) 個は次のようになります。 

[
 \frac{400000\cdot399999}{2}=79,999,800,000。 
】

 したがって、明示的なスワップによって特に悪いターゲット配置を 1 つ処理するだけでも、制限時間をはるかに超えています。 

誤って対処しやすい特殊なケースがいくつかあります。 すべてのビー玉がすでにブロックを形成している場合、色が数値的に並べ替えられていない場合でも、答えはゼロになります。 例えば、```
4
2 2 1 1
```答えは(0)です。 ブロックが色の値によって順序付けされなければならないと仮定する解決策では、(2,1) を (1,2) に変更するという不正確な代償が発生します。 

1 色のみが発生する場合は、(n) に関係なく、操作は必要ありません。 例えば、```
4
20 20 20 20
```答えは(0)です。 考えられる 20 色すべてに状態を盲目的に割り当てるソリューションはかなりの時間を無駄にする可能性がありますが、正しい実装では実際に発生する色を圧縮する必要があります。 

繰り返される色も重要です。 のために```
4
1 2 1 2
```中央の 2 つのビー玉を交換すると (1,1,2,2) が得られるため、答えは (1) です。 個々のビー玉を独立して順序付けられたオブジェクトとして扱うと、同じ色のビー玉間の不必要な交換がカウントされる可能性があります。 

最後に、色の値は (1,\dots,k) などの小さな連続範囲に限定されません。 のために```
4
20 1 20 1
```答えは再び (1) です。 実装では、数値を DP インデックスとして使用するのではなく、実際に発生する色を圧縮する必要があります。 

## アプローチ

 直接的な総当たりアプローチは、最終的な有効な配置がカラー ブロックの順序によって完全に決定されることを観察することから始まります。 個別の色が (c_1,c_2,\ldots,c_k) である場合、考えられる順序は (k!) あります。 

1 つの固定順序については、すべての色に希望のブロック ランクを割り当て、元の配列をスキャンできます。 相対順序が目的のブロック順序と異なるビー玉の各ペアは、正確に 1 つの隣接スワップに寄与します。 これは、隣接スワップの通常の反転解釈です。 したがって、固定順序は (O(n)) で評価でき、すべての可能な順序に対して (O(k!,n)) 時間を与えます。 

(k=20) では、これは絶望的です。 あります

 [
 20！ = 2,432,902,008,176,640,000
 】

 可能な注文。 注文ごとに (4\cdot10^5) 個のビー玉を 1 回スキャンするだけでも、おおよその時間がかかります

 [
 20!\cdot4\cdot10^5 \約 9.73\cdot10^{23}
 】

 要素の訪問。 

有益な観察は、注文のコストをペアごとに分解できることです。 最終シーケンスでは色 (x) が色 (y) の前に配置されているとします。 (x) が出現する前に最初に出現した (y) はすべて、順序を逆にする必要があるペアを形成します。 このような各ペアには、ちょうど 1 つの隣接するスワップがかかります。 

定義する

 [
 コスト[x][y]
 】

 元の配列で (x) が (y) の前に出現するペアの数として表されます。 

ここで、最終的な色の順序を左から右に構築することを想像してください。 すでに選択されている色のセット (S) の後に色 (c) を追加する場合、すべての色 (x\in S) が (c) の前に現れる必要があります。 すべての後に (c) を配置することによって導入されたスワップは、正確に次のようになります。 

[
 \sum_{x\in S} コスト[c][x]。 
】

 重要な部分は、これは (S) と (c) のみに依存し、(S) の色が以前に配置された順序には依存しないということです。 これにより、サブセット DP に必要な最適な部分構造が得られます。 

ビットマスクを使用して、すでに配置されている色のセットを表します。 DP 状態は、そのセットをプレフィックスとして正確に配置するための最小コストを記録します。 新しい色を 1 つ追加すると、トランジションが得られます。 

比較は次のとおりです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(k!,n)) | (O(k+n)) | 遅すぎる |
 | 最適 | (O(nk+k2^k)) | (O(k2^k)) | 承認済み |

 ここでは (k\leq20) なので、指数部分はおおよそ (20\cdot2^{20}) で区切られ、管理可能です。 

## アルゴリズムのチュートリアル

 1. 配列内に実際に存在する色をインデックス (0,1,\ldots,k-1) に圧縮します。 これらの色のみが最終ブロックとして表示されます (k\leq20)。 
2. ペアごとのコスト マトリックスを構築します。 すべての色のペア (x,y) について、(a_​​i=x) および (a_j=y) となる位置のペア (i<j) の数を (cost[x][y]) とします。 左から右へのスキャン中、現在の色が (y) の場合、以前に表示されたすべての (x) が (cost[x][y]) に 1 を与えます。 色は最大 20 色なので、この前処理には (O(nk)) のコストがかかります。 
3. 色の最終的な順序を検討し、最後の色 (c) が追加される瞬間に注目します。 他のすべての色はセット (S)、および (c\notin S) を形成します。 (c) を追加することによって発生する追加コストは次のとおりです。 

[
 add(c,S)=\sum_{x\in S}コスト[c][x]。 
】

 この式は、(c) が (S) のすべての色の後に来る必要がある場合に、間違った相対順序にあるペアを正確にカウントします。 

1. (dp[mask]) を、次の式で表される色を正確に配置するために必要な隣接するスワップの最小数として定義します。`mask`最終行の 1 つの有効なプレフィックスに変換されます。 マスク内の色は、コストが最小になる順序で表示されます。 
2. 空ではないマスクごとに、マスクに含まれる各色 (c) をその接頭辞の最後の色として試します。 もし`prev = mask`(c) がない場合、遷移は次のようになります。 

\min_{c\in マスク}
 \左(
 dp[前へ]
 +
 \sum_{x\in prev}コスト[c][x]
 \右）。 
】

 先行するものは DP の定義によってすでに最適であり、追加された項は、新しく追加された色を含むすべてのペアを説明します。 

1. Python 実装の高速性を維持するには、サブセットの合計を事前計算します。 

[
 sum_c[S]=\sum_{x\in S}コスト[c][x]
 】

 すべての色 (c) と (c) を含まないすべてのサブセット (S) に対して。 このような各テーブルには (2^{k-1}) 個のエントリがあるため、すべてのテーブルに (k2^{k-1}) 個の値が含まれます。 サブセットの合計自体は、1 つの設定ビットを削除することで計算されます。 

[
 sum_c[S]=sum_c[S\setminus{x}]+コスト[c][x]。 
】

 実装では、これらの値をコンパクトな 64 ビット配列に格納します。 

1. すべてのマスクを反復処理し、可能なすべての最後の色にトランジションを適用します。 答えは`dp[(1 << k) - 1]`なぜなら、そのマスクにはあらゆる異なる色が含まれているからです。 

機能する理由: 最終的な色の順序を修正します。 異なる色のビー玉の各ペアは、相対的な順序を維持するか、またはその順序を逆転させます。 元の順序が最終的なブロックの順序と一致しないペアは、正確に 1 回交差する必要があり、隣接するスワップでは、スワップされた 2 つのビー玉の相対順序のみが変更されます。 したがって、そのような反転ペアの数は、まさに最終的な順序付けの隣接するスワップの最小数になります。 

DP は、考えられるすべての最終的な順序を暗黙的に考慮します。 色 (c) が追加される場合、その寄与は内部順序ではなく、その前に既に存在する色のみに依存します。 したがって、すべての順序は DP 遷移のシーケンスによって表され、すべての遷移は新しく追加されたブロックに関係するスワップを正確に追加します。 可能なすべての最後の色で最小値を取ると、すべての有効なブロック順序での最小コストが得られます。 

## Python ソリューション```python
import sys
from array import array

input = sys.stdin.readline

def solve_case(a):
    # Compress the colors that actually occur.
    colors = sorted(set(a))
    k = len(colors)
    index = {x: i for i, x in enumerate(colors)}
    b = [index[x] for x in a]

    # cost[x][y] = number of pairs (x before y) in the original array.
    cost = [[0] * k for _ in range(k)]
    seen = [0] * k

    for y in b:
        for x in range(k):
            cost[x][y] += seen[x]
        seen[y] += 1

    if k == 1:
        return 0

    # For every color c, store subset sums for subsets not containing c.
    # Such a subset has k-1 bits, hence 2^(k-1) entries.
    half = 1 << (k - 1)
    total_sum_entries = k * half
    subset_sum = array('q', [0]) * total_sum_entries

    for c in range(k):
        base = c * half

        others = []
        for x in range(k):
            if x != c:
                others.append(x)

        row = cost[c]

        for mask in range(1, half):
            lb = mask & -mask
            bit = lb.bit_length() - 1
            prev = mask ^ lb
            subset_sum[base + mask] = (
                subset_sum[base + prev] + row[others[bit]]
            )

    size = 1 << k
    inf = 10**30
    dp = [inf] * size
    dp[0] = 0

    lower_mask = [(1 << c) - 1 for c in range(k)]

    for mask in range(1, size):
        bits = mask
        best = inf

        while bits:
            lb = bits & -bits
            c = lb.bit_length() - 1
            prev = mask ^ lb

            # Remove bit c from prev to obtain its compressed
            # (k-1)-bit representation.
            compressed = (
                (prev & lower_mask[c])
                | ((prev >> (c + 1)) << c)
            )

            value = dp[prev] + subset_sum[c * half + compressed]

            if value < best:
                best = value

            bits ^= lb

        dp[mask] = best

    return dp[-1]

def main():
    n = int(input())
    a = list(map(int, input().split()))
    print(solve_case(a))

if __name__ == "__main__":
    main()
```の最初の部分`solve_case`色を圧縮します。 これにより、決して発生しない色に DP 状態を割り当てることが回避され、20 などの値も特別に扱わずに処理されます。 

の`cost`行列には方向ペアの数が格納されます。 現在の色が`y`、以前に見たすべての色`x`とのペアを1つ与えます`x`前に`y`、 それで`cost[x][y]`によって増分されます`seen[x]`。 この方向性が重要です。 いつ`y`の後に追加されます`x`、問題のあるペアは次のようなものです。`y`元々は前に登場した`x`として保存されます。`cost[y][x]`。 

サブセット合計テーブルには、考えられる最後の色ごとに個別にインデックスが付けられます。 最後の色 (c) はその前のマスクに存在できないため、(k-1) ビットのみが必要になります。 これにより、ストレージが (k2^k) エントリから (k2^{k-1}) エントリに削減されます。 

圧縮されたマスクはビットを削除します`c`。 下位ビットはそのまま維持できますが、上位ビットはすべて`c`1つ下にシフトされます。 表現```
(prev & lower_mask[c]) | ((prev >> (c + 1)) << c)
```まさにその変換を実行します。 

DP は次から始まります`dp[0] = 0`空のプレフィックスはスワップを必要としないためです。 空ではないマスクごとに、設定された各ビットが最後のブロックの色とみなされます。 前任者は次のように取得されます。`mask ^ lb`、事前に計算されたサブセットの合計は、選択した色をすべての先行色の後に置くコストを提供します。 

Python の整数には任意の精度があるため、答えが (2^{31}) よりもはるかに大きくなる場合でも、オーバーフローの心配はありません。 コンパクト`array('q')`Python の通常の整数はオブジェクトごとにかなりのメモリ オーバーヘッドを伴うため、サブセットの合計に使用されます。 

## 実用的な例

 ### サンプル 1

 入力は```
7
3 4 2 3 4 2 2
```個別の色は (3,4,2) です。 圧縮後、それらをそれぞれ (0,1,2) と呼びます。 

関連するペアのコストの一部は次のとおりです。 

[
 コスト[4][3]=1、
 \qquad
 コスト[2][3]=1、
 \qquad
 コスト[2][4]=1。 
】

 最終順序が (3,4,2) の場合、これらはまさに交差する必要がある 3 つのペアです。 

最適な DP パスは次のように示すことができます。 

| マスク | 最後の色 | 前のマスク | 追加コスト | DP値 |
 | --- | --- | --- | --- | --- |
 |`001`| 3 |`000`| 0 | 0 |
 |`011`| 4 |`001`| (コスト[4][3]=1) | 1 |
 |`111`| 2 |`011`| (コスト[2][3]+コスト[2][4]=2) | 3 |

 結果のブロック順序は (3,4,2) となり、最終的な配置が得られます。```
3 3 4 4 2 2 2
```最小値は (3) です。 

このトレースは、追加される色にコストが付加される理由を示しています。 4 が 3 の後に追加される場合、元々 4 が 3 より前にあるペアのみが問題になります。 2 を追加する場合、それらのペアが間違った順序で発生する場所で、前の 3 と 4 を正確に交差する必要があります。 

### サンプル 2

 入力は```
5
20 1 14 10 2
```すべての色は 1 回だけ発生します。 各色はすでに長さ 1 のセグメントを形成しているため、5 つのシングルトン ブロックのどの順序も有効であり、元の配置ではスワップは必要ありません。 

元のシーケンス自体がすでに有効なブロック順序付けであるため、すべてのペアのコストは最適化とは無関係です。 

| マスク | 最後の色 | 前のマスク | 追加コスト | DP値 |
 | --- | --- | --- | --- | --- |
 |`00001`| 20 |`00000`| 0 | 0 |
 |`00011`| 1 |`00001`| 0 | 0 |
 |`00111`| 14 |`00011`| 0 | 0 |

 |`11111`| 2 |`01111`| 0 | 0 |

 すべての DP 状態は 0 のままであるため、最終的な答えは (0) になります。 

これは、すべての色が 1 回出現する場合を例にしています。 正しい解決策では、シングルトン カラーがすでに連続していることを認識する必要があります。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(nk+k2^k)) | ペアの構築コストは (O(nk)) かかり、サブセットの合計と DP は (O(k2^k)) かかります。 
| スペース | (O(k2^k)) | DP には (2^k) 個の状態があり、コンパクトなサブセット合計テーブルには (k2^{k-1}) 個のエントリがあります。 

(k\leq20) の場合、DP には最大でも (2^{20}=1,048,576) 個の状態が含まれます。 遷移では、状態ごとに最大 20 個の最後の可能な色が検査されます。 前処理では、(4\cdot10^5) 個のビー玉ごとに最大 20 個のカラー カウンターをスキャンします。 これらの境界は小さな色のアルファベットを中心に設計されているため、アルゴリズムは最大 (n) であっても実行可能です。

from array import array

def solve(inp: str) -> str:

    n = int(reader())
    a = list(map(int, reader().split()))

    colors = sorted(set(a))
    k = len(colors)
    index = {x: i for i, x in enumerate(colors)}

    cost = [[0] * k for _ in range(k)]
    seen = [0] * k

    for y in b:
        for x in range(k):
            cost[x][y] += seen[x]
        seen[y] += 1

    if k == 1:
        return "0"

    half = 1 << (k - 1)
    subset_sum = array('q', [0]) * (k * half)

    for c in range(k):
        base = c * half
        others = [x for x in range(k) if x != c]
        row = cost[c]

        for mask in range(1, half):
            lb = mask & -mask
            bit = lb.bit_length() - 1
            prev = mask ^ lb
            subset_sum[base + mask] = (
                subset_sum[base + prev] + row[others[bit]]
            )

    size = 1 << k
    inf = 10**30
    dp = [inf] * size
    dp[0] = 0

    lower_mask = [(1 << c) - 1 for c in range(k)]

    for mask in range(1, size):
        bits = mask
        best = inf

        while bits:
            lb = bits & -bits
            c = lb.bit_length() - 1
            prev = mask ^ lb

            compressed = (
                (prev & lower_mask[c])
                | ((prev >> (c + 1)) << c)
            )

            value = dp[prev] + subset_sum[c * half + compressed]

            if value < best:
                best = value

            bits ^= lb

        dp[mask] = best

    return str(dp[-1])

 ## 特殊なケース

 すべての大理石が同じ色である場合、すでに連続したセグメントが 1 つだけ存在します。 のために```
4
20 20 20 20
```圧縮により (k=1) が生成されます。 アルゴリズムは、大きな DP を構築する代わりに、ただちにゼロを返します。 これにより、不必要な作業と、少なくとも 2 つの色が存在すると仮定するというよくある間違いの両方を回避できます。 

すべての色が 1 回出現すると、すべてのビー玉はすでに独自の連続したブロックになります。 のために```
5
20 1 14 10 2
```シングルトン ブロックが 5 つあるため、元の行はすでに有効であり、答えは 0 です。 元の注文自体が許可された最終注文の 1 つであるため、ペアのコストは特定の注文を強制しません。 

カラーがインターリーブされている場合、ペア数の定式化により、必要なスワップが正確にキャプチャされます。 のために```
4
1 2 1 2
```最後の順序 (1,2) では、2 番目のビー玉と 3 番目のビー玉が交差する必要があります。 後の 1 の前に 2 が出現するペアが 1 つだけ存在するため、DP はコスト (1) を順序 (1,2) に割り当てます。 ブロック順序を逆にするとコストが高くなります。答えは (1) です。 

カラー値がまばらであるか、その境界にある場合、圧縮によって配列インデックスのエラーが防止されます。 のために```
4
20 1 20 1
```元の値が 20 と 1 であっても、色は 2 つの DP インデックスに圧縮されます。1 つの交差が必要なので、答えは (1) です。 

既存のブロックが任意の順序になっている場合は、その順序を受け入れる必要があります。 のために```
6
3 3 1 1 2 2
```各色はすでに連続しているため、交換する必要はありません。 DP は数値的な色の順序に関連付けられません。 最終ブロック順序として (3,1,2) を自由に選択でき、ゼロが得られます。 

1 つの色が優勢な場合は、最大の入力サイズも安全です。 カラー 20 の (400,000) コピーでは、異なる色は 1 つだけであるため、アルゴリズムは圧縮後に終了します。 このケースは、実際のインスタンスの状態が 1 つだけであるにもかかわらず、常に (2^{20}) 状態の DP を構築する実装では不要な作業が実行されるため、便利です。
