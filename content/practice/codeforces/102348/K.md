 ## 解決策
 ## 問題の理解

 (n \times n) チェッカーボードを構築する必要があります。ここで、(i+j) が偶数の場合はセル ((i,j)) に石が含まれ、そうでない場合は砂が含まれている必要があります。 値 (n) は偶数で、最大 (50) です。 

難しいのは、最終的な色を選ぶことではありません。 難しいのは、セルに到達できる順序です。 空のセルは、境界線上にある場合、またはすでに入力されているセルに触れている場合にのみ、個別に入力できます。 (2 \times 2) 演算はより強力ですが、その正方形内の現在空のすべてのセルは同じ色を受け取ります。 すべての (2 \times 2) チェッカーボードには 2 つの石のセルと 2 つの砂のセルが含まれるため、正方形の演算は、その正方形内の 1 色のセルがすでに埋められた後にのみ使用できます。 

出力は、一連の有効な操作です。 すべての操作は正しい色のみを配置する必要があり、選択されたすべての位置は必要なアクセシビリティ条件を満たしている必要があり、操作の合計数は (3n^2/4) を超えてはなりません。 

制約 (n \le 50) は、セルの数が最大 (2500) であるため、直接 (O(n^2)) の構築であっても計算的には小さいことを意味します。 実際の制限はマニピュレータの使用数です。 すべてのセルを個別に埋めるには (n^2) 回の操作が必要ですが、これは常に許容される (3n^2/4) よりも大きくなります。 したがって、単にすべてのセルの有効な走査を見つけるのではなく、(2 \times 2) 演算を利用する必要があります。 

(n) が偶数であるという事実は、まさに壁全体を互いに素な (2 \times 2) 正方形に分割することを可能にします。 このような正方形は (n^2/4) 個あり、各正方形が 3 回の操作で完了できる場合、合計は正確に (3n^2/4) となり、制限に一致します。 

一般的に不注意な建築物を破壊する小さなケースが 2 つあります。 (n=2) の場合、壁全体は 1 (2 \times 2) の正方形になります。 直接 (2 \times 2) 操作を最初の操作にすることはできません。4 つのセルがすべて空であり、それらを 1 つの色で塗りつぶすことになり、間違ったセルが作成されてしまうからです。 たとえば、入力の場合`2`、有効な構成は 3 つの操作です。1 つの対角線の 2 つのセルを個別に塗りつぶし、もう 1 つの対角線に対して 1 つの平方演算を使用します。 

内側の (2 \times 2) 正方形の場合、単純に 1 つのセルを塗りつぶしてから、その同じ色の対角の相手を塗りつぶそうとすることも失敗します。 これら 2 つのセルは斜めに隣接しているため、2 番目のセルは最初の操作では解放されません。 構築では、それぞれがすでに構築された領域の境界上にあるように 2 つのシード セルを選択する必要があります。 

## アプローチ

 最も直接的な構築は、すべてのセルを独立して埋めることです。 セルに到達するとセルを選択でき、その境界から内部に向かって壁を処理することで有効な順序が与えられます。 すべての操作で必要な色が選択されるため、最終的な色付けは明らかに正しいです。 ただし、これは最悪の場合に正確に (n^2) の演算を使用しますが、問題では (3n^2/4) のみが許可されます。 (n=50) の場合、許可される最大数 (1875 回) ではなく、(2500 回) の操作になります。 問題は、計算実行時間ではなく、運用予算です。 

重要な観察は、壁を (n^2/4) 個の互いに素な (2 \times 2) 正方形に分割できることです。 左上隅 ((x,y)) を持つそのような正方形の 1 つを考えてみましょう。(x) と (y) は両方とも奇数です。 その細胞は、

 [
 (x,y)、\quad (x,y+1)、\quad (x+1,y)、\quad (x+1,y+1)。 
】

 セル ((x,y+1)) と ((x+1,y)) は同じ色です。 さらに重要なのは、(2 \times 2) の正方形が上から下、左から右に処理される場合、正方形を処理する前にこれらのセルの両方に到達できることです。 1 つ目は、上の境界線上にあるか、上に完全に構​​築された正方形に触れています。 2 つ目は、左側の境界上にあるか、左側の完全に構築された正方形に触れています。 

これら 2 つの同じ色のセルを 2 つのシングルトン操作で埋めることができます。 その時点で、正方形の残りの 2 つのセルは反対の色を持つため、その反対の色を使用した 1 回の (2 \times 2) 操作で、これら 2 つの空のセルが正確に塗りつぶされます。 間違ったセルが描画されることはありません。 

したがって、(2 \times 2) 正方形ごとにちょうど 3 回の演算が必要になります。 (n^2/4) 個の正方形があるので、合計は次のようになります。 

[
 3 \cdot \frac{n^2}{4}=\frac{3n^2}{4}、
 】

 これはまさに許容最大値です。 

ブルートフォース構造は、個々の操作ですべてのセルを完全に制御できるため機能しますが、セルごとに 1 つの操作が必要になります。 すべてのチェッカーボード (2 \times 2) の正方形が 2 つの同じ色の対角線で構成されているという観察により、4 つのシングルトン演算を 2 つのシングルトン シードと 1 つの平方演算に置き換えることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべてのセルを個別に入力する | (O(n^2)) | (O(n^2)) | 有効ですが、操作制限を超えています |
 | (2 \times 2) 個の正方形に分割する | (O(n^2)) | (O(n^2)) ストアド操作の場合 | 承認済み |

 ## アルゴリズムのチュートリアル

1. 壁を、左上隅が ((x,y)) となる互いに素な (2 \times 2) の正方形に分割します。ここで、(x) と (y) は奇数の値 (1,3,5,\ldots,n-1) をとります。 すべての壁セルは、まさに 1 つのそのような正方形に属します。 
2. これらの正方形を行の昇順で処理し、各行内で列の昇順で処理します。 この順序により、外側の境界線に接する四角形を除くすべての四角形が、その真上または真左にすでに完成した四角形を持つことが保証されます。 
3. 現在の正方形について、まず ((x,y+1)) を個別に塗りつぶします。 (x+y+1) が奇数であるため、必要な色は砂です。 (x=1) ではセルが上の境界線に配置されるため、セルは空きですが、(x>1) では上に塗りつぶされた隣接セルが与えられます。 
4. ((x+1,y)) にも個別に砂を入れます。 (y=1) の場合、左端にあります。 それ以外の場合、すぐ左側の正方形はすでに完成しているため、((x+1,y)) には塗りつぶされた近傍があります。 
5. stone を使用して ((x,y)) で (2 \times 2) 演算を使用します。 前の操作で配置された 2 つの砂のセルはすでに占有されていますが、他の 2 つのセル ((x,y)) と ((x+1,y+1)) は、まさにこの市松模様の正方形の 2 つの石のセルです。 したがって、この操作では正しいセルのみが入力されます。 
6. (2 \times 2) 個の正方形がすべて処理されるまで続行します。 (x) には (n/2) 個の選択肢があり、(y) には (n/2) 個の選択肢があるため、(n^2/4) 個の正方形があり、正方形ごとにちょうど 3 つの演算が行われます。 

### なぜ効果があるのか

 不変条件は、正方形を処理する前に、以前に処理されたすべての正方形が完全に正しく、現在の正方形がまだ空であることです。 最初のシード ((x,y+1)) は、上の境界線上にあるか、上の完成した正方形に触れているため、常に空きです。 2 番目のシード ((x+1,y)) は、左側の境界上にあるか、左側の完成した正方形に接しているため、常に空きです。 どちらの種子も砂細胞です。 石を配置した後、正方形内の空のセルは 2 つの石のセルだけになるため、最後の (2 \times 2) 操作で石を安全に使用できます。 したがって、すべての操作は有効であり、占有されているすべてのセルは必要な色を持ちます。 正方形はばらばらで壁全体を覆うため、最終的な壁はまさに必要なチェッカーボードになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    ans = []

    for x in range(1, n, 2):
        for y in range(1, n, 2):
            # (x, y + 1) and (x + 1, y) are both sand cells.
            ans.append((1, x, y + 1, 2))
            ans.append((1, x + 1, y, 2))

            # The remaining two cells of this 2x2 square are stone.
            ans.append((2, x, y, 1))

    print(len(ans))
    for t, x, y, b in ans:
        print(t, x, y, b)

if __name__ == "__main__":
    solve()
```外側のループは、各 (2 \times 2) ブロックの一番上の行を選択します。 2 ずつ増加するため、行 (1,3,\ldots,n-1) を正確に参照します。 内側のループは列に対して同じことを行います。 

最初のシングルトン操作は ((x,y+1)) をターゲットとします。 パリティが奇数なので砂に違いない。 2 番目のターゲットは ((x+1,y)) で、同じパリティを持つため、砂も必要です。 

二乗演算は ((x,y)) から始まります。 (x,y \le n-1) であるため、その 4 つのセルは壁の内側にあります。 2 つの砂のセルはすでに占有されているため、この操作では空の 2 つの石のセルのみが埋められます。 四角い色に石を選ぶと安全に作業ができます。 

壁のシミュレーションは必要ありません。 建設命令自体が、必要なセルが無料であることを証明しています。 Python の整数も、すべての座標と演算数が最大でも数千であるため、特別な処理は必要ありません。 

## 実用的な例

 ### 例 1

 指定された入力 (n=2) の場合、正方形は 1 つだけ (2 \times 2) です。 

| 正方形 ((x,y)) | 最初のシード | 2番目のシード | 二乗演算 | 使用される操作 |
 | --- | --- | --- | --- | --- |
 | ((1,1)) | ((1,2))、砂 | ((2,1))、砂 | ((1,1))、石 | 3 |

 出来上がった壁は、

 | ポジション | ((1,1)) | ((1,2)) |
 | --- | --- | --- |
 | 行 1 | 石 | 砂 |
 | 行 2 | 砂 | 石 |

 このサンプルでは、​​異なるが同様に有効な順序付け、つまり 2 つの石のシングルトン操作とそれに続く 1 つの砂の四角形操作が使用されています。 この問題は、操作制限内で有効な構成を受け入れます。 この構築では、正確に (3=3\cdot2^2/4) の演算も使用します。 

### 例 2

 (n=4) の場合、互いに素な (2 \times 2) 個の正方形が 4 つあります。 

| 正方形 ((x,y)) | 最初のシード | 2番目のシード | 最終二乗演算 | 総オペレーション |
 | --- | --- | --- | --- | --- |
 | ((1,1)) | ((1,2))、砂 | ((2,1))、砂 | 石 | 3 |
 | ((1,3)) | ((1,4))、砂 | ((2,3))、砂 | 石 | 3 |
 | ((3,1)) | ((3,2))、砂 | ((4,1))、砂 | 石 | 3 |
 | ((3,3)) | ((3,4))、砂 | ((4,3))、砂 | 石 | 3 |

 最初の正方形が完成すると、2 番目の正方形のセル ((2,3)) が、完成した正方形の左側に隣接します。 3 番目の正方形のセル ((3,2)) も同様に、上の完成した正方形に隣接しています。 これがまさに、行優先処理が内部正方形に対して機能する理由です。 

最終的なカウントは (4\cdot3=12) ですが、

 [
 \frac{3n^2}{4}=\frac{3\cdot16}{4}=12。 
】

 したがって、この例では、動作限界を超えることなく、正確に動作限界に到達します。

## テストケース

 出力は一意ではないため、テストでは、生成された操作シーケンスを 1 つの特定の有効な出力と文字ごとに比較するのではなく、検証する必要があります。```python
# This test harness validates the construction itself.
# It can be used with the solve() implementation above.

import sys
import io

def build(n):
    ans = []

    for x in range(1, n, 2):
        for y in range(1, n, 2):
            ans.append((1, x, y + 1, 2))
            ans.append((1, x + 1, y, 2))
            ans.append((2, x, y, 1))

    out = [str(len(ans))]
    out.extend(f"{t} {x} {y} {b}" for t, x, y, b in ans)
    return "\n".join(out) + "\n"

def validate(inp: str) -> str:
    n = int(inp.strip())
    output = build(n)

    data = list(map(int, output.split()))
    k = data[0]
    assert 1 <= k <= 3 * n * n // 4

    board = [[0] * n for _ in range(n)]
    p = 1

    def wanted(i, j):
        # i and j are zero-based here.
        return 1 if (i + j) % 2 == 0 else 2

    def free(i, j):
        if board[i][j] != 0:
            return False

        if i == 0 or i == n - 1 or j == 0 or j == n - 1:
            return True

        return (
            board[i - 1][j] != 0
            or board[i + 1][j] != 0
            or board[i][j - 1] != 0
            or board[i][j + 1] != 0
        )

    for _ in range(k):
        t, x, y, b = data[p:p + 4]
        p += 4

        x -= 1
        y -= 1

        if t == 1:
            assert 0 <= x < n
            assert 0 <= y < n
            assert free(x, y)
            assert wanted(x, y) == b
            board[x][y] = b

        else:
            assert t == 2
            assert 0 <= x < n - 1
            assert 0 <= y < n - 1

            cells = [
                (x, y),
                (x, y + 1),
                (x + 1, y),
                (x + 1, y + 1),
            ]

            assert any(free(i, j) for i, j in cells)

            for i, j in cells:
                if board[i][j] == 0:
                    assert wanted(i, j) == b

            for i, j in cells:
                if board[i][j] == 0:
                    board[i][j] = b

    for i in range(n):
        for j in range(n):
            assert board[i][j] == wanted(i, j)

    return output

# Provided sample.
sample1 = validate("2")
assert sample1.startswith("3\n"), "sample 1"

# Minimum size, exercising the single 2x2 square.
case2 = validate("2")
assert case2.splitlines()[0] == "3"

# A small interior case, where reachability depends on previously

case3 = validate("4")
assert case3.splitlines()[0] == "12"

# Another even size, catching row and column progression errors.
case4 = validate("6")
assert case4.splitlines()[0] == "27"

# Maximum allowed n.
case5 = validate("50")
assert case5.splitlines()[0] == str(3 * 50 * 50 // 4)

 ## 特殊なケース

 (n=2) の場合、入力は次のようになります。```
2
```唯一の正方形は ((1,1)) です。 アルゴリズムは、まず ((1,2)) を砂で埋め、次に ((2,1)) を砂で埋めます。 どちらも境界セルであるため、両方のシングルトン操作が有効です。 最後の (2 \times 2) 操作では、((1,1)) と ((2,2)) を石で満たします。 出力では、正確に 3 つの演算が使用されます。 

内部正方形の場合、(n=4) と ((3,3)) から始まる正方形を考えます。 そこに到達する前に、((1,1))、((1,3))、((3,1)) から始まるマス目がすでに完成しています。 セル ((3,4)) は上の完成した正方形に隣接しているため空きですが、((4,3)) は左側の完成した正方形に隣接しているため空きです。 どちらも砂のセルなので、個別に配置できます。 残りのセル ((3,3)) と ((4,4)) はどちらも石であり、最後の平方演算によりこれらのセルが正確に埋められます。 

(x=1) または (y=1) の境界ケースは、特別なコードなしで処理されます。 (x=1) の場合、最初のシードは上の境界線にあります。 (y=1) の場合、2 番目のシードは左側の境界にあります。 建設がさらに内側に進むと、対応する以前に完成した正方形が必要な隣接ブロックを提供します。 

最大の場合 (n=50) には、(25) ブロック行と (25) ブロック列が含まれ、(625) 個の互いに素な (2 \times 2) 正方形が得られます。 各正方形には 3 回の演算が必要なため、この構築では (625\cdot3=1875) 演算が生成され、これは (3n^2/4) とまったく同じになります。 指定された制限を超える操作数や座標はありません。
