 ## 解決策
 ## 問題の理解

 2列あります`n`テーブル、各フロアに 1 列。 あ`1`位置にある`i`チームがそのテーブルを占有することを意味しますが、`0`テーブルが空いていることを意味します。 プリンターは、占有されているテーブルを含め、どのテーブルにも設置できます。 

プリンターが所定の位置にあるとします`p`選択した 1 つのフロアで。 同じフロアのチームは横歩きしかできないので不便です`|i - p|`。 他の階のチームは、まず自分のテーブルから階段まで歩いて行き、`k`フロアを変えてからプリンターまで歩いていく必要があり、不便を感じます`i + k + p`。 

タスクは、参加チームの最大の不便が可能な限り小さくなるように、プリンター用の床とテーブルの両方を選択することです。 その最小値と、それを達成する 1 つのプリンター位置を出力します。 

値`n`せいぜい`1000`したがって、二次アルゴリズムでさえ、フロアごとに約 100 万回の反復しか実行されません。 可能な 2 つのプリンターフロアにより、すべてのプリンターの位置とすべてのチームのパフォーマンスを完全に直接列挙します。`4n² = 4,000,000`チームポジションの評価。 不必要な作業ではありますが、これはこれらの制約を考慮するとすでに十分小さいものです。 不便さの公式の構造により、計算を線形時間に短縮できます。 

最も一般的な実装エラーは、空のフロアや入力順序とフロア番号の混同によって発生します。 2 番目の入力文字列はフロア 2 を説明し、3 番目の入力文字列はフロア 1 を説明します。たとえば、```
1 1
1
0
```唯一のチームは 2 階にいるため、プリンターを 2 階に配置すると、テーブル 1 が答えを返します。`0`、 ない`3`。 両方のフロアにチームが含まれていると想定する不注意な実装では、フロア間のコストが誤って追加される可能性があります。 

もう 1 つの境界ケースは、最後のテーブルにいるチームです。 のために```
4 2
0001
0001
```プリンターをフロア 1 のテーブル 1 に置くと、非常に不便になります`4 + 2 + 1 = 7`、これが最適です。 他のフロアの用語では、最小の占有インデックスではなく、最大の占有インデックスが使用されます。`i + k + p`と増加します`i`。 間違った極端値を使用すると、答えが過小評価されてしまいます。 

3 番目のケースは、選択したフロアのすべてのテーブルが占有されている場合です。 のために```
5 3
11111
11111
```プリンターがテーブル 1 のフロア 1 にある場合、反対側のフロアが寄与します`5 + 3 + 1 = 9`。 選択したフロアにもチームが存在するという事実は、フロア間の表現を変更しません。 同じ式内で 2 つのフロアを対称的に扱うと、不正確な結果が得られます。 

最後に、空いているテーブルにプリンターを置くことが許可されます。 のために```
5 7
00000
10001
```最適なプリンタの位置はフロア 1、テーブル 3 であり、同じフロアの最大距離が得られます。`2`。 プリンターを占有テーブルに制限すると、最適な結果が得られなくなります。 

## アプローチ

 最も直接的な解決策は、考えられるすべてのプリンターの位置を試します。 がある`2n`プリンターはどちらのフロアのどのテーブルにも置くことができるため、選択肢が豊富です。 選択ごとに、占有されているすべてのテーブルを検査し、同じフロアまたはクロスフロアの式を使用してその不便さを計算し、最大値を維持します。 これは正しいです。すべての合法的なプリンタの配置が明示的に考慮され、すべてのチームの貢献が正確に評価されるからです。 

費用は`O(n²)`。 最悪の場合には、`2n`プリンターの位置と最大`2n`占領されたチーム、与える`4n²`評価。 で`n = 1000`つまり、最大 400 万回の評価であるため、この強引な方法は、特に C++ では、指定された制約の下で実際に実行可能です。 それでも、テーブルの数が増加した場合には同じ推論が必要になるため、線形解を導き出すことは有用です。 

重要な観察は、プリンターフロアが固定されれば、すべてのチームのポジションは必要ないということです。 印刷フロアのチームの場合、最大値は`|i - p|`は、占有されているテーブルの左端と右端によって完全に決定されます。 それらのポジションが`L`そして`R`、同じ階の寄付は`max(p - L, R - p)`。 

反対側のフロアのチームの場合、次の式になります。`i + k + p`として成長します。`i`成長します。 したがって、反対側の階の最も右側にある占有テーブルのみが問題となります。 その立場なら`M`、反対側のフロア全体が貢献します`M + k + p`。 

したがって、プリンターの床と位置が固定されている場合`p`、チームのセット全体は、選択したフロアの左端と右端の占有位置、および他のフロアの右端の占有位置という最大 3 つの番号に折りたたまれます。 

これらの極値は、各入力文字列を 1 回スキャンすることで取得できます。 その後、すべての可能なプリンター位置を一定時間で評価できます。 あるのは`2n`位置なので、合計実行時間は次のようになります。`O(n)`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | 受け入れられました`n <= 1000`、しかし不必要に高価です |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 2 つのフロアの説明を読み、2 番目の入力文字列がフロア 2 を表し、3 番目の入力文字列がフロア 1 を表すことを覚えておいてください。このマッピングは、回答を印刷するときに保存する必要があります。 
2. 各フロアについて、一般に、その左端の占有テーブル、右端の占有テーブル、および右端の占有テーブルを見つけます。 最初の 2 つは、プリンターがそのフロアにある場合に必要になります。 そのフロアが反対側のフロアの場合は、一番右の位置が必要です。 
3. プリンターを 1 階のテーブルに置くことを検討してください。`p`。 フロア 1 にチームがいる場合、最大の不便さは次のとおりです。`max(p - L1, R1 - p)`。 フロア 1 が空の場合、考慮すべきチームがないため、この寄与はゼロになります。 
4. 2 階のチームはすべて階段を通って到達します。 彼らの不便さは、`i + k + p`、これは 2 階の右端のチームで最大です。したがって、彼らの貢献度は次のようになります。`R2 + k + p`フロア 2 が空でない場合はゼロ、そうでない場合はゼロ。 
5. これら 2 つの寄与の最大値を取得します。 これにより、プリンタの位置が最大限に不便になります。`(1, p)`。 
6. それぞれについて同じ計算を繰り返します。`p`から`1`を通して`n`プリンターが 2 階にある場合、同じフロアの用語では 2 階の極値が使用され、クロスフロアの用語では 1 階の右端のチームが使用されます。 
7. これまでに見られた最高の不便さを最大限に維持します。 新しい値が厳密に小さい場合にのみ、保存された回答を更新します。 最適な配置は任意であるため、最小値に達する最初の配置を維持するだけで十分です。 
8. 最も不便な点を出力し、その後にフロアとテーブルの番号を出力します。 すべての位置は、問題の番号付けと一致する、1 から始まるインデックスとして維持されます。 

### なぜ効果があるのか

 固定のプリンターフロアの場合、同じフロアのすべてのチームが距離に貢献します。`p`。 このようなすべてのチームの中で、最大距離は 2 つの極端に占有されたテーブルのいずれかから得られる必要があるため、同じフロアのセット全体がその最小位置と最大位置によって正確に表されます。 反対側のフロアのすべてのチームが貢献する`i + k + p`、これは厳密に増加しています`i`, そのため、反対側のフロアの右端のチームのみが最大値を決定できます。 したがって、各候補プリンタ位置に対して評価される式は、まさにその真の最大の不便さを表します。 アルゴリズムはすべての可能なフロアとすべてのテーブルを評価するため、記録される最小値が全体的な最適値になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    floor2 = input().strip()
    floor1 = input().strip()

    floors = [floor1, floor2]

    # For each floor:
    # left[i]  = leftmost occupied table, or 0 if empty
    # right[i] = rightmost occupied table, or 0 if empty
    left = [0, 0]
    right = [0, 0]

    for f in range(2):
        for pos, ch in enumerate(floors[f], 1):
            if ch == '1':
                if left[f] == 0:
                    left[f] = pos
                right[f] = pos

    best_value = 10**18
    best_floor = 1
    best_pos = 1

    for f in range(2):
        other = 1 - f

        for p in range(1, n + 1):
            same = 0
            if right[f] != 0:
                same = max(p - left[f], right[f] - p)

            other_floor = 0
            if right[other] != 0:
                other_floor = right[other] + k + p

            cur = max(same, other_floor)

            if cur < best_value:
                best_value = cur
                best_floor = f + 1
                best_pos = p

    print(best_value)
    print(best_floor, best_pos)

if __name__ == "__main__":
    solve()
```2 つの入力文字列は次のように並べ替えられます。`floors = [floor1, floor2]`そのインデックス`0`出力フロア 1 とインデックスに対応`1`これにより、入力自体が最初にフロア 2 をリストしていることを繰り返し思い出すことがなくなります。 

最初のスキャンでは、占有されているテーブルの左端と右端が記録されます。 とき`1`初めて遭遇すると、`left[f]`; 占領されているすべての位置が割り当てられます`right[f]`ので、スキャン後`right[f]`は自動的に最後に占有されたテーブルになります。 

値`0`空のフロアを表すために使用されます。 すべての実テーブルインデックスは少なくとも`1`、有効な占有位置と混同することはできません。 ゼロに対するチェックにより、空のフロアが誤ってテーブル 0 に偽のチームを生成することを防ぎます。 

プリンターの候補位置について`p`、`same`はゼロに初期化されます。 選択したフロアにチームが含まれている場合、2 つの極端な距離が計算されます。 この 2 つの最大値は、まさにそのフロアで最悪の不便さです。 

反対側の階の寄与分もゼロに初期化されます。 反対側のフロアに少なくとも 1 つのチームが含まれている場合、その右端の位置が使用されます。`right[other] + k + p`。 テーブルインデックスが小さくなるたびにクロスフロアの不都合が小さくなるため、他のチームを検査する必要はありません。 

ループは使用します`range(1, n + 1)`、 それで`p`問題の 1 から始まるテーブル インデックスを直接表します。 これにより、回答を出力する際の off-by-one 変換が回避されます。 Python の整数は、可能な最大の値も快適に処理できますが、ここでの最大の答えは次のオーダーにすぎません。`2n + k`。 

厳密な比較`cur < best_value`最初に見つかった最適な位置を意図的に維持します。 これにより、出力が確定的になり、最初のサンプルのプリンターの位置がフロア 1、テーブル 1 に自然に生成されます。
