 ## 解決策
 ## 問題の理解

 従業員は会社のオーナーを根とする根の生えた木を形成します。 各従業員の年齢はマネージャーの年齢以下であるため、階層が下に移動しても年齢が上がることはありません。 

パーティは、その所有者と許可される年齢間隔によって説明されます。 所有者は常に自分のパーティーに対して有効です。 別の従業員が出席するには、すでに出席している従業員と直接のつながりがあり、年齢が範囲内である必要があります。 これは、招待された従業員は、年齢が範囲外の従業員を削除した後のツリー内の所有者の接続コンポーネントとまったく同じであることを意味します。 

すべての従業員について、その従業員を含む連結コンポーネントが生成されるパーティー間隔の数をカウントする必要があります。 

制限は大きく、従業員と関係者の数は両方とも 100,000 に達する可能性があります。関係者ごとにツリーを探索するソリューションでは、最悪の場合でも約 10^10 の操作を実行できますが、これは可能性をはるかに超えています。 O((N + M) log N) に近い解が必要です。 

年齢の順序によってキーの構造が決まります。 パーティにオーナーがいる場合`o`そして最大年齢も`R`から上に移動できます。`o`マネージャーの年齢がまだ高いうちに`R`。 最も連絡可能な従業員を次のようにします。`h`。 パーティーに招待されたすべての従業員は、次のサブツリー内に入ります。`h`なぜなら、すべての祖先は`o`まで`h`は有効であり、それらの祖先からのすべての側枝も接続されたままになります。 そのサブツリー内で残る唯一の制限は最低年齢です。`L`。 

実装が失敗する可能性があるケースがいくつかあります。 

会社のルートである所有者について考えてみましょう。```
1 1
5 1
1 1 5
```答えは次のとおりです。```
1
```すべての従業員が自分とは異なる親を持つことを前提としたソリューションは、祖先を登るときに壊れる可能性があります。 

もう 1 つのケースは、従業員に正確な境界年齢がある場合です。```
3 1
10 1
5 1
5 2
2 5 5
```出力は次のとおりです。```
0 1 1
```正確な年齢の従業員`L`または正確に`R`を含める必要があります。 厳密な比較を使用すると、それらが誤って削除されます。 

最後のトリッキーなケースは、最大年齢が根の手前で登りを止めるパーティです。```
4 1
10 1
7 1
4 2
3 3
3 3 7
```所有者は従業員 4 です。年齢 7 で許可される最上位の祖先は、従業員 1 ではなく、従業員 2 です。招待されたセットは、年齢が少なくとも 3 である従業員 2 のサブツリーであり、次のようになります。```
0 1 1 1
```常にルートから開始する不注意な実装では、従業員 1 が誤ってカウントされます。 

## アプローチ

 直接的なアプローチは、すべての関係者を個別に処理することです。 所有者から始めて、パーティー間隔内の年齢の従業員のみを入力する DFS を実行できます。 訪問した従業員全員にもう 1 回招待状が届きます。 これは正しいです。DFS は、招待されたすべての従業員は有効な従業員を介して接続する必要があるというルールに正確に従っているからです。 

この問題は、多くのパーティが重なった場合に発生します。 最悪の場合、すべての関係者がすべての従業員を訪問し、O(NM) に仕事を与える可能性があります。 両方の値が 100000 に達すると、これは約 100 億のツリー アクセスになります。 

有益な観察は、パーティを幾何学的更新に変換できるということです。 有効な最上位の祖先を見つけた後`h`、パーティーはすべての従業員に影響を与えます`v`2 つの条件を満たす:`v`のサブツリー内にあります`h`、 そして`age[v] >= L`。 

ツリーに対して DFS 注文を実行すると、すべてのサブツリーが連続した間隔になります。 従業員`v`点で表されます`(tin[v], age[v])`。 パーティが長方形の更新になります:`tin[h] <= tin[v] <= tout[h]`そして`age[v] >= L`。 

このような更新を多数適用し、従業員のあらゆる時点で価値を問う必要があります。 この問題は、従業員を年齢別に分類することでオフラインで解決できます。 従業員を若い人から年長者に処理する際に、すでに最低年齢に達しているすべてのパーティをアクティブ化します。 アクティブなパーティはオイラー区間に 1 を追加するだけでよく、これはフェンウィック ツリーで処理できます。 

最終的な変換は次のとおりです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(NM) | O(N) | 遅すぎる |
 | 最適 | O((N + M) log N) | O(N log N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 従業員ツリーを構築し、オイラー ツアーの位置を計算します。 すべての従業員にとって、店舗`tin`そして`tout`, したがって、すべてのサブツリーはオイラー順序で 1 つの区間になります。 
2. 祖先用のバイナリリフティングテーブルを構築します。 ルートへのパスでは年齢条件は単調であるため、2 の累乗で上にジャンプして、年齢がパーティの最大年齢を超えない最上位の祖先を見つけることができます。 
3. すべてのパーティについて、その所有者から開始して、バイナリ リフティングを使用して上に向かって登ります。 祖先候補の年齢が最大の場合`R`、そこに移動します。 最後の従業員が有効な最上位の祖先です`h`。 
4. パーティをオイラー間隔でオフライン更新に変換します`[tin[h], tout[h]]`そして最低年齢`L`。 
5. 従業員を年齢順に並べ替え、パーティーの最新情報を最低年齢順に並べ替えます。 従業員の年齢に答える前に`A`、すべてのパーティーを追加します`L <= A`オイラー区間の範囲増分としてフェンウィック ツリーに変換します。 
6. 従業員のオイラー位置でフェンウィック ツリーをクエリします。 値は、その従業員をカバーするアクティブなパーティの四角形の数であり、これはまさにその従業員を招待するパーティの数です。 

なぜ効果があるのか:

 パーティーにとっては最高の祖先`h`せいぜい年齢とともに`R`所有者とのつながりを維持できる最上部のポイントです。 外のすべて`h`のサブツリーでは、年齢がすでに大きすぎる親エッジを通過する必要があります。 内部`h`のサブツリー、すべての年齢は自動的に最大で`R`なぜなら、子孫は祖先よりも年をとることはできないからです。 残りの要件は少なくとも年齢です`L`、これはオフライン スイープによって処理されます。 すべての従業員は、長方形に自分の担当者が含まれる関係者に対して 1 つの増分を受け取ります。`(tin, age)`したがって、最後の Fenwick クエリは必要なカウントを生成します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    age = [0] * (n + 1)
    graph = [[] for _ in range(n + 1)]

    for i in range(1, n + 1):
        a, b = map(int, input().split())
        age[i] = a
        if i != b:
            graph[b].append(i)

    LOG = (n + 1).bit_length()
    up = [[1] * (n + 1) for _ in range(LOG)]

    stack = [1]
    order = [1]
    parent = [1] * (n + 1)

    while stack:
        u = stack.pop()
        for v in graph[u]:
            parent[v] = u
            order.append(v)
            stack.append(v)

    for i in range(1, n + 1):
        up[0][i] = parent[i]

    for k in range(1, LOG):
        prev = up[k - 1]
        cur = up[k]
        for i in range(1, n + 1):
            cur[i] = prev[prev[i]]

    tin = [0] * (n + 1)
    tout = [0] * (n + 1)
    timer = 0

    stack = [(1, 0)]
    while stack:
        u, state = stack.pop()
        if state == 0:
            timer += 1
            tin[u] = timer
            stack.append((u, 1))
            for v in reversed(graph[u]):
                stack.append((v, 0))
        else:
            tout[u] = timer

    def highest(o, r):
        u = o
        for k in range(LOG - 1, -1, -1):
            if age[up[k][u]] <= r:
                u = up[k][u]
        return u

    updates = []
    for _ in range(m):
        o, l, r = map(int, input().split())
        h = highest(o, r)
        updates.append((l, tin[h], tout[h]))

    updates.sort()
    employees = sorted((age[i], tin[i], i) for i in range(1, n + 1))

    bit = [0] * (n + 2)

    def add(idx, val):
        while idx <= n:
            bit[idx] += val
            idx += idx & -idx

    def range_add(l, r, val):
        add(l, val)
        add(r + 1, -val)

    def query(idx):
        res = 0
        while idx:
            res += bit[idx]
            idx -= idx & -idx
        return res

    ans = [0] * (n + 1)
    p = 0

    for a, pos, idx in employees:
        while p < m and updates[p][0] <= a:
            _, l, r = updates[p]
            range_add(l, r, 1)
            p += 1
        ans[idx] = query(pos)

    print(*ans[1:])

if __name__ == "__main__":
    solve()
```コードの最初の部分では、ルート ツリーとバイナリ リフティング テーブルを構築します。 ルートは祖先テーブル内でそれ自体を指します。これにより、企業階層の最上位に到達する際の特別な処理が回避されます。 

オイラー ツアーは、Python の再帰制限を回避するために反復的に計算されます。 重要な特性は、1 つのサブツリー内のすべての従業員が、次のサブツリー間のオイラー位置を持っていることです。`tin[u]`そして`tout[u]`。 

の`highest`関数は、大きなジャンプから小さなジャンプへのバイナリ リフティングを使用します。 年齢はツリーの下に移動する間にのみ減少するため、ジャンプ ターゲットがまだ許可されている最大年齢以内であれば、現在のポジションとそのジャンプ ターゲットの間にあるすべての従業員も有効です。 

フェンウィック ツリーは、オイラー位置の差分配列を保存します。 パーティ更新では、2 つのポイント更新を使用してサブツリー間隔全体に 1 を追加します。 年齢スイープにより、現在の従業員の年齢が許容される最低年齢に達したときに正確にパーティーが挿入されることが保証されます。 

大きな値の乗算は必要ないため、Python 整数のオーバーフローは問題になりません。 間隔更新では、`r + 1`; フェンウィックツリーにはサイズがあるため、この余分な位置は無害です`n + 1`、サブツリーの最後での off-by-one エラーを防ぎます。

 ## 特殊なケース

 ルートのみの場合は、バイナリ リフティング テーブルがルートを自身の祖先として保存するため機能します。 の`highest`関数は有効な範囲を離れることはなく、ルートを可能な限り最上位の従業員として正しく維持します。 

境界年齢の場合:```
3 1
5 1
5 1
5 2
2 5 5
```パーティーにはオーナー 2 と射程があります`[5,5]`。 所有者と従業員 3 は正確に許可されている年齢を持っているため、両方ともカウントされます。 スイープ中に、5 歳の従業員を処理する前にパーティーが挿入されます。`L <= age`、オイラー区間には両方の従業員が含まれます。 

停止した上昇の場合:```
4 1
10 1
7 1
4 2
3 3
3 3 7
```所有者は従業員 4 です。バイナリ リフティングは上方に移動しようとしますが、従業員 1 の年齢は 10 で、最大年齢 7 の範囲外です。有効な最上位の祖先は従業員 2 のままです。更新は従業員 2 のサブツリーのみをカバーするため、従業員 1 がパーティの増分を受け取ることはありません。 

オフライン スイープでは、すべての当事者がサブツリー条件と最低年齢条件の両方を満たす従業員によって代表されるため、このようなケースはすべて一律に処理されます。
