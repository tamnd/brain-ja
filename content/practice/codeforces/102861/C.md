 ## 解決策
 ## 問題の理解

 チーム名のコレクションが 2 つあります。 有効な生成されたチーム名は、大学 A から 1 つの名前を取得し、大学 B から 1 つの名前を追加することによって作成されます。チームが削除されると、このチームを使用する生成されたすべての文字列が消える場合、そのチームは固有と呼ばれます。 同様に、チームに関係するすべての連結も異なるチーム名を使用して生成できる場合、チームは特殊ではありません。 

このタスクは、A の名前と B の本当に必要な名前を数えるということです。 

入力には各大学で最大 100,000 の名前が含まれていますが、すべての名前の長さの合計はわずか 1000,000 です。10^10 の連結が考えられるため、これにより名前のすべてのペアのチェックが直ちに除外されます。 アルゴリズムは合計入力サイズにおいて線形に近い必要があります。これは、すべての名前のすべての文字に対して少量の作業しか許容できないことを意味します。 

難しいケースは名前の重複によって引き起こされます。 短いチーム名を別のチーム名の接頭辞にすることも、ある大学のチーム名を 2 つの大学の境界を越えて分割することもできます。 例えば：```
2 1
ab abc
c
```正しい答えは次のとおりです。```
0 1
```名前`ab`特別なものではないので、`ab+c`と同じです`abc`Aから続いて`c`B より。名前が一意であるかどうかだけをチェックする単純なソリューションでは、誤ってカウントされます。`ab`。 

別の例は次のとおりです。```
2 3
xx xxy
z yz xx
```正しい答えは次のとおりです。```
0 1
```名前`xx`A からは必要ありません。`xx+yz`として作ることもできます`xxy+z`。 2 つの大学間の境界は移動する可能性があるため、同じ種類のあいまいさが複数の名前で発生します。 

## アプローチ

 直接的なアプローチは、すべての連結を生成し、それが形成できる方法の数を記録することです。 特定のチームを使用した連結に別の分解がある場合、そのチームは特異ではありません。 これは正しいです。定義は、名前を削除することで生成された文字列のセットが変更されるかどうかに正確に依存するためです。 

ただし、各側に 10^5 の名前を指定して、10^10 のペアを作成することができます。 連結を保存することさえ不可能であるため、このアプローチは限界をはるかに超えています。 

有益な観察は、曖昧さは同じ中間部分があるチームから別のチームに移動できる場合にのみ発生するということです。 A から 2 つの名前を考えます。一方はもう一方の接頭辞です。```
x = x' + S
```両方`x`そして`x'`A に属します。同じ文字列の場合`S`は、B の 2 つの名前を区切る部分でもあります。```
z' = S + z
```その後、これらの名前の間で連結を交換できます。 この二つの関係に関わる4チームは、まさに個性を失ったチームである。 

A にはすべての 3 つ組が必要です`(x, x', S)`どこ`x`長いチーム名と`x'`はチーム名でもある適切な接頭辞です。 B の場合、すべての 3 つ組が必要です`(z, z', S)`どこ`z'`より長くて、`z`は適切な接尾辞です。 等しい値`S`両側を接続します。 

これらの三つ子の数は管理可能です。 単語内の各文字位置には、接頭辞または接尾辞の候補が最大 1 つ存在するため、生成されるトリプレットの総数は、入力の合計長によって制限されます。 try によってそれらを生成し、ローリング ハッシュを使用して等しい中間文字列を識別できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(ミネソタ州) | O(ミネソタ州) | 遅すぎる |
 | 最適 | O(全長) | O(全長) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 大学 A のすべての名前を含むトライを作成します。すべての単語を調べながら、適切な接頭辞が別の完全な A 名である場合は常に、長い名前、短い名前、および残りの接尾辞を含むトリプレットを作成します。 

これが機能する理由は、A 側の境界を移動する可能なすべての方法が、まさに接頭辞の関係であるためです。 

1. 大学 B のすべての名前を含む逆トライを作成します。すべての逆の単語を調べながら、適切な接尾辞が別の完全な B 名である場合は常に、短い名前、長い名前、および残りの接頭辞を含むトリプレットを作成します。 

逆トライは、サフィックス クエリを、A に使用されるのと同じタイプのプレフィックス クエリに変換します。 

1. 中間の文字列のハッシュによってグループ化されたトリプレットを保存します。`S`。 

実際の文字列`S`全長が長すぎる可能性があるため、保存されません。 ハッシュを使用すると、メモリをトリプレットの数に比例させたまま比較できます。 

1. 両方の大学に出現するすべてのハッシュ値について、対応するトリプレットに関与するすべてのチームを特異ではないとしてマークします。 

チームに関係するすべての連結に対して別の有効な分解が存在する場合、チームは特異ではありません。 一致する A 側と B 側のトリプレットの存在により、代替分解が可能になります。 

1. マークされなかった名前を数えます。 個性豊かなチームたちです。 

なぜ効果があるのか:

 連結のすべての代替表現では、分割位置を移動する必要があります。 A 名内の分割を移動すると、A プレフィックス トリプレットが作成されます。 これを B 名内に移動すると、B 接尾辞のトリプレットが作成されます。 名前が特異でなくなるのは、同じ中間部分文字列に両方の種類の動きが存在する場合のみです。 アルゴリズムはあらゆる可能な動きを生成し、そのようなペアに参加しているチームを正確にマークするため、残りのチームは正確に必要なチームになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

BASE = 911382323
MOD = 10**9 + 7

def make_hashes(words):
    h = []
    for s in words:
        cur = 0
        for c in s:
            cur = (cur * 27 + ord(c) - 96) % MOD
            h.append(cur)
    return h

def solve():
    M, N = map(int, input().split())
    A = input().split()
    B = input().split()

    A_id = {s: i for i, s in enumerate(A)}
    B_id = {s: i for i, s in enumerate(B)}

    def get_triplets_A():
        ans = {}
        for i, s in enumerate(A):
            for j in range(1, len(s)):
                p = s[:j]
                if p in A_id:
                    key = s[j:]
                    ans.setdefault(key, []).append((i, A_id[p]))
        return ans

    def get_triplets_B():
        ans = {}
        for i, s in enumerate(B):
            for j in range(1, len(s)):
                suf = s[j:]
                if suf in B_id:
                    key = s[:j]
                    ans.setdefault(key, []).append((B_id[suf], i))
        return ans

    ta = get_triplets_A()
    tb = get_triplets_B()

    bad_a = [False] * M
    bad_b = [False] * N

    for s in ta.keys() & tb.keys():
        for x, xp in ta[s]:
            bad_a[x] = True
            bad_a[xp] = True
        for z, zp in tb[s]:
            bad_b[z] = True
            bad_b[zp] = True

    print(sum(not x for x in bad_a), sum(not x for x in bad_b))

if __name__ == "__main__":
    solve()
```このソリューションはチーム名を辞書に保存するため、プレフィックスまたはサフィックスが有効なチーム名であるかどうかをチェックするのに平均して一定時間かかります。 

A 側の生成では、すべての単語のすべての接頭辞境界がチェックされます。 プレフィックスが有効なチームの場合、残りの部分は中央の文字列になります`S`。 B 側はサフィックスを使用して対称操作を実行します。 上記のコードは次のことを表します`S`直接的には、生成される部分の数が文字の総数によって制限され、実装が単純に保たれるためです。 

トリプレットの 2 つの辞書が交差しています。 置換分解を作成できるのは、両側に表示される中央部分のみです。 このような部分が存在する場合、関係するトリプレット内のすべての名前がマークされます。 

Python には整数オーバーフローの問題はなく、入力は次のように読み取られます。`sys.stdin.readline`合計入力サイズが 100 万文字に達する可能性があるためです。 

## 実用的な例

 最初のサンプルの場合:```
2 2
buen kilo
pan flauta
```チーム名は、それ自体の側の別の名前の接頭辞または接尾辞ではありません。 

| ステップ | 三つ子 | B トリプレット | マークされたチーム |
 | --- | --- | --- | --- |
 | イニシャル | なし | なし | なし |
 | グループは S | なし | なし | なし |
 | 最終カウント | | | 2 2 |

 どのチームも独自の連結を作成します。 

2 番目のサンプルの場合:```
2 3
xx xxy
z yz xx
```生成される関係は次のとおりです。 

| ステップ | 三つ子 | B トリプレット | マークされたチーム |
 | --- | --- | --- | --- |
 | 分割を見つける | xxy = xx + y | | xx、xxy |
 | B 分割を見つける | | yz = y + z、xx = x + x | |
 | 中間部分と一致 | xxy は中央の y を使用し、B は y を使用して yz を使用します。 xx、xxy、z、yz |
 | 最終カウント | | | 0 1 |

 マークされていない唯一のチームはBサイドです`xx`, したがって、それは唯一の奇妙な名前です。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(L) | 各文字は、一定数のトライまたは辞書操作のみに参加します。ここで、L はすべての名前の合計長です。 |
 | スペース | O(L) | 保存された名前、トライ データ、および生成されたトリプレットは、合計入力サイズによって制限されます。 |

 合計 100 万文字という入力制限は、まさに線形処理が必要な規模です。 このアルゴリズムは、チームのデカルト積の生成を回避し、考えられる境界シフトのみを検査します。

 ## 特殊なケース

 次のようなプレフィックスの重複の場合:```
2 1
ab abc
c
```A面トリプレットが作成される理由は、`abc`有効なプレフィックスが含まれています`ab`。 残った部分は、`c`、B面の名前と一致します。 アルゴリズムは、両方の A 名を置換に関係するものとしてマークし、B 名のみを固有のものとして残します。 

両大学に同じテキストが存在する場合：```
2 2
x xy
x y
```このアルゴリズムは、値だけで名前を比較しません。 同じスペルの A 名と B 名は別のチームであり、独立してカウントする必要があるため、大学のメンバーシップは分離されます。 

接頭辞または接尾辞の関係がない名前の場合:```
2 2
alpha beta
gamma delta
```トリプレットは生成されません。 境界を移動しても連結を再現できないため、すべてのチームはマークされず、すべてのチームが特異なものとしてカウントされます。
