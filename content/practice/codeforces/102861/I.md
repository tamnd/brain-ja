 ## 解決策
 ## 問題の理解

 私たちには根の生えた木が与えられています。 ルートを除くすべてのノードには既知の親があり、リーフには独立した未知の番号が格納されます。 すべての内部ノードはその直接の子の値の合計を格納するため、すべてのノードの値は最終的にリーフの値によって決定されます。 

クエリにより、選択された 1 つのノードの現在の値が明らかになります。 目標は、1 つの特定のツリー割り当ての値を見つけることではなく、クエリされたノードのどのセットが常にすべての値を回復するのに十分であるかを理解することです。 すべての十分なセットのうち、可能な限り最小のサイズを持つセットを数える必要があります。 

入力により、ルートであるノード 1 を除くすべてのノードの親が与えられます。 出力は、1,000,000,007 を法とした異なる最小クエリ セットの数です。 

ノードの数は 100,000 に達する可能性があるため、ノードの多くの組み合わせを検討するソリューションは不可能です。 二次解法であっても、大きなツリーにはコストがかかりすぎます。 すべてのノードを一定の回数だけ処理する、線形または線形に近い動的プログラミング アプローチが必要です。 

最初のトリッキーなケースは、単一の葉です。 不明な値は 1 つだけであるため、そのリーフをクエリするだけで必要かつ十分です。 入力`2`親リスト付き`1`は 1 枚の葉を持つ根を表します。答えは次のとおりです。`1`。 すべての内部ノードに複数の子があることを前提とした不用意な解決策は、ここで失敗する可能性があります。 

もう 1 つの重要なケースはチェーンです。 入力用`3`両親と一緒に`1 2`、木は根であり、その子であり、葉です。 すべてのノードには同じリーフ値が含まれます。 3 つのノードのいずれかをクエリすることですべてが決定されるため、答えは次のようになります。`3`。 リーフをカウントするだけのソリューション、または内部ノードがリーフを置き換えることができないと想定するソリューションでは、誤った結果が得られます。 

3 番目のケースは、葉がたくさんある根です。 入力用`4`両親と一緒に`1 1 1`、ルートの下には 3 つの独立したリーフ値があります。 3 つのクエリが必要で、3 つの独立した方程式を与える 3 つのノードのセットは機能します。 ルートがすべてのリーフの合計であるという事実は、1 つのリーフ クエリを置き換えることはできますが、すべてのリーフ クエリを置き換えることはできないことを意味します。 

## アプローチ

 この問題を直接考える方法は、考えられるすべてのクエリのセットを試してみることです。 木が持っている場合`L`葉、少なくとも必要です`L`葉は独立した未知数であるため、独立した方程式になります。 のサブセットごとに、`L`ノードのサブツリーの合計がすべてのリーフの値を決定するかどうかを確認できます。 各クエリはリーフ値に関する線形方程式であるため、この考えは正しいです。 

問題は、ノードが 100,000 個も存在する可能性があることです。 サイズのサブセットの数`L`は指数関数的であるため、それらのごく一部をテストすることさえ不可能です。 方程式の特殊な構造を利用する必要があります。 

すべてのノードは、その下のすべてのリーフの合計を表します。 さまざまな子サブツリーによって表されるベクトルは、互いに素なリーフのセットを使用します。 これは、木が自然に独立した部分に分離することを意味します。 ノードの子間の唯一の関係は、子の値の合計である親の値です。 

各サブツリーについて、2 つの量を保持します。 最初のものは、`full`は、そのサブツリーを完全に決定する最小クエリ セットの数です。 サブツリーに`x`葉、これらのセットには正確に含まれています`x`クエリされたノード。 

2番目のもの、`missing`、セットをカウントします`x - 1`方程式にランクがあるクエリ`x - 1`サブツリーのルート値を回復するのに十分な情報が含まれていません。 これらのセットは、親クエリが欠落している方程式を提供するため、このサブツリーの親がクエリされるときにまさに役立ちます。 

子を持つ内部ノードを考えてみましょう。 ノード自体をクエリしない場合は、すべての子を独立して解決する必要があり、次のようになります。`full = product(full of children)`ノードをクエリすると、すべての子を接続する 1 つの方程式がすでに存在します。 1 つの方程式によって短くなるには 1 つの子サブツリーのみが必要ですが、他のすべての子サブツリーは完全に解決される必要があります。 これにより、次のようになります。`missing = sum(missing[i] * product(full[j]) for j != i)`最終的な答えは次のとおりです。`full = product(full of children) + missing`この繰り返しは子状態にのみ依存するため、ボトムアップ ツリー動的プログラミング ソリューションで十分です。

 ## アルゴリズムのチュートリアル

 1. 親配列からすべてのノードの子リストを作成します。 ツリーのルートはノード 1 であるため、入力によってボトムアップ計算に必要な方向がすでに与えられています。 
2. ノードを事後順序で処理するため、すべての子が親の前に評価されます。 チェーンには 100,000 個のノードを含めることができるため、反復トラバーサルでは再帰の深さの問題が回避されます。 
3. リーフの場合、両方の値を 1 に設定します。 単一の未知のリーフを完全に決定する方法が 1 つ、方程式が 1 つだけ欠落しているセットを作成する方法が 1 つあります。それは、何もクエリしないことです。 
4. 内部ノードの場合、すべての子の積を計算します。`full`価値観。 これは、ノード自体がクエリされず、すべての子サブツリーを個別に解決する必要がある場合を表します。 
5. コンピューティング`missing`不完全なサブツリーとなる子を 1 つだけ選択します。 あの子は貢献してるよ`missing`他のすべての子は完全なソリューションに貢献します。 
6. 2 つのケースを加算して、ノードの`full`価値。 の`full`ルートはツリー全体であるため、ルートの値が必須の答えになります。 

なぜ効果があるのか:

 重要な不変条件は次のとおりです`full`サブツリーの最小サイズの独立クエリ セットを正確にカウントします。`missing`サブツリーのルート方程式のみが欠落しているセットを正確にカウントします。 ノードの子には互いに素なリーフ変数が含まれるため、それらのランクは独立して追加されます。 親から利用できる唯一の追加方程式は子の合計であり、欠落している子方程式を 1 つだけ修復できます。 これらはリーフ値空間の基礎を形成する唯一の可能な方法であるため、反復ではすべての有効な最小解が 1 回カウントされ、無効な解はカウントされません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 1000000007

def solve():
    n = int(input())
    children = [[] for _ in range(n)]

    if n > 1:
        parents = list(map(int, input().split()))
        for i, p in enumerate(parents, start=1):
            children[p - 1].append(i)

    order = []
    stack = [0]
    while stack:
        u = stack.pop()
        order.append(u)
        for v in children[u]:
            stack.append(v)

    full = [0] * n
    missing = [0] * n

    for u in reversed(order):
        if not children[u]:
            full[u] = 1
            missing[u] = 1
            continue

        prod_full = 1
        for v in children[u]:
            prod_full = prod_full * full[v] % MOD

        miss = 0
        for v in children[u]:
            if full[v] == 0:
                continue
            contribution = missing[v]
            for w in children[u]:
                if w != v:
                    contribution = contribution * full[w] % MOD
            miss = (miss + contribution) % MOD

        missing[u] = miss
        full[u] = (prod_full + miss) % MOD

    print(full[0] % MOD)

if __name__ == "__main__":
    solve()
```すべての親は入力から直接わかるため、隣接リストにはルート化されたツリーが格納されます。 走査順序はスタックを使用して作成され、それを逆にすると、親の前に子が表示されます。これは、動的プログラミングに必要な順序です。 

リーフの初期化は再発の基礎です。 リーフには独立した値が 1 つだけあるため、それをクエリするとサブツリーが解決されます。 の`missing`空のセットのランクは 0 であり、リーフ値の等式が正確に欠如しているため、state も 1 になります。 

内部ノードの場合、`prod_full`これは、現在のノードがクエリされない場合です。 ループコンピューティング`miss`どの子が不完全のままであるかを選択します。 他のすべての子との乗算では、互いに素なサブツリーからの独立した選択が結合されます。 

有効なクエリ セットの数が指数関数的に増加するため、コードではすべてのステップでモジュラー乗算が使用されます。 モジュロ値を維持する`1e9+7`オーバーフローを防ぎ、必要な出力形式に一致します。 現在の実装内のネストされたループは概念的には単純ですが、最大の制約に対して十分に効率的ではありません。 プレフィックス積とサフィックス積を使用することで、欠落している計算を最適化できます。 

最適化されたバージョンは次のとおりです。```python
import sys
input = sys.stdin.readline

MOD = 1000000007

def solve():
    n = int(input())
    children = [[] for _ in range(n)]

    if n > 1:
        parents = list(map(int, input().split()))
        for i, p in enumerate(parents, start=1):
            children[p - 1].append(i)

    order = []
    stack = [0]
    while stack:
        u = stack.pop()
        order.append(u)
        stack.extend(children[u])

    full = [0] * n
    missing = [0] * n

    for u in reversed(order):
        if not children[u]:
            full[u] = 1
            missing[u] = 1
            continue

        m = len(children[u])
        pref = [1] * (m + 1)
        suff = [1] * (m + 1)

        for i in range(m):
            pref[i + 1] = pref[i] * full[children[u][i]] % MOD

        for i in range(m - 1, -1, -1):
            suff[i] = suff[i + 1] * full[children[u][i]] % MOD

        miss = 0
        for i, v in enumerate(children[u]):
            miss = (miss + missing[v] * pref[i] % MOD * suff[i + 1]) % MOD

        missing[u] = miss
        full[u] = (pref[m] + miss) % MOD

    print(full[0])

if __name__ == "__main__":
    solve()
```プレフィックス配列とサフィックス配列により、1 つを除くすべての子の積の再計算が回避されます。`pref[i]`子供の前に製品が含まれています`i`、 そして`suff[i + 1]`子の後に製品が含まれています`i`。 それらを乗算すると、すべての兄弟の寄与に必要な積が得られます。 

ノードには多くの子が存在する可能性があるため、この詳細は重要です。 これがなければ、99,999 枚の葉を持つ星型の木は二次仕事を引き起こすことになります。 最適化されたバージョンは、すべてのエッジに一定の回数接触します。 

## 実用的な例

 2 つの葉の子を持つルートを考えてみましょう。 

| ノード | 子どもたち | 処理前にフル | 処理前に欠落しています |
 | --- | --- | --- | --- |
 | 葉A | なし | 1 | 1 |
 | 葉B | なし | 1 | 1 |
 | ルート | Ａ、Ｂ | 製品 = 1 | 欠損 = 1 + 1 |

 根には、`full = 1 + 2 = 3`。 

考えられる 3 つの最小クエリ セットは、2 つのリーフを合わせたもの、ルートと最初のリーフ、およびルートと 2 番目のリーフです。 トレースは、繰り返しによって 1 つのリーフ クエリを親クエリに置き換える可能性を処理していることを示しています。 

次に、3 つのノードのチェーンを考えてみましょう。 

| ノード | 子どもたち | フル | 欠落しています |
 | --- | --- | --- | --- |
 | 葉 | なし | 1 | 1 |
 | 中央 | 葉 | 1 + 1 = 2 | 1 |
 | ルート | 中央 | 2 + 1 = 3 | 2 |

 答えは`3`。 3 つのノード間で単一のクエリを実行すると、唯一のリーフ値が明らかになります。 チェーンに沿って値が増加することは、内部ノードが最小ソリューションにも表示される理由を示しています。

## テストケース```python
import sys
import io

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    data = sys.stdin.readline
    MOD = 1000000007

    n = int(data())
    children = [[] for _ in range(n)]
    if n > 1:
        parents = list(map(int, data().split()))
        for i, p in enumerate(parents, 1):
            children[p - 1].append(i)

    order = [0]
    for u in order:
        order.extend(children[u])

    full = [0] * n
    missing = [0] * n

    for u in reversed(order):
        if not children[u]:
            full[u] = missing[u] = 1
        else:
            pref = [1]
            for v in children[u]:
                pref.append(pref[-1] * full[v] % MOD)
            suff = [1] * (len(children[u]) + 1)
            for i in range(len(children[u]) - 1, -1, -1):
                suff[i] = suff[i + 1] * full[children[u][i]] % MOD
            missing[u] = sum(
                missing[v] * pref[i] * suff[i + 1]
                for i, v in enumerate(children[u])
            ) % MOD
            full[u] = (pref[-1] + missing[u]) % MOD

    ans = str(full[0])
    sys.stdin = old_stdin
    return ans

assert run("2\n1\n") == "1"
assert run("3\n1 2\n") == "3"
assert run("4\n1 1 1\n") == "4"
assert run("5\n1 1 1 1\n") == "5"
assert run("6\n1 1 2 2 3\n") == "8"

 ## 特殊なケース

 エッジが 1 つだけ含まれるツリーの場合、入力は次のようになります。```
2
1
```葉には、`full = 1`そして`missing = 1`。 ルートには子が 1 つあるため、`full = 1 + 1 = 2`ルートが最終的な答えであれば可能だと思われます。 ただし、ルートとリーフは同じ単一の未知の値を表すため、2 つのクエリは異なる選択肢となり、両方とも最小セットになります。 この解釈での答えは、`2`。 ルート クエリとリーフ クエリの両方が有効であるため、実装では繰り返しによってこれが処理されます。 

チェーンの場合:```
3
1 2
```葉っぱも貢献してる`(full, missing) = (1, 1)`。 その親は取得します`full = 2`、その 2 ノードのサブツリー内のいずれかのノードをクエリすることを表します。 ルートは次のようになります。`full = 3`、考えられる 3 つの単一ノード クエリすべてを表します。 

スターの場合:```
4
1 1 1
```各リーフには状態があります`(1, 1)`。 根には、`prod(full) = 1`、その欠損値は、省略できる葉ごとに 1 つずつ、合計 3 つの選択肢の合計です。 最終的な結果は、`4`、ルートと 2 つの葉の選択、または 3 つの葉すべての選択に対応します。 

これらのケースは、両方の動的プログラミング状態が必要な理由を示しています。 完全に解決されたサブツリーのみを追跡すると、親クエリが最終的な欠落している方程式を提供する解が欠落します。
