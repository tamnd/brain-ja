 ## 解決策
 ## 問題の理解

 私たちには無向の友情グラフが与えられています。 すべての頂点はプレイヤーを表し、すべてのエッジは友情関係を表します。 すべてのプレーヤーについて、同じグループに属する友達の数が奇数になるように、プレーヤーを最大 2 つのグループに分割する必要があります。 2 つのグループの実際の名前は重要ではなく、2 人のプレーヤーが一緒に配置されるかどうかのみが重要です。 

入力により、最大 100 人のプレイヤーとその友情エッジが得られます。 答えは`Y`可能な 2 つのグループへのプレイヤーの割り当てが、すべてのプレイヤーの奇数フレンド条件を満たす場合、および`N`さもないと。 

プレイヤー数の制限が小さいことが、意図された複雑さに関する重要な観察点です。 100 個の変数を使用すると、線形代数に基づくアルゴリズムが実用的になります。 ブルート フォース割り当てでは、考えられるすべての分割が試行されます。これは、プログラムが処理できる範囲をはるかに超えて、最大 (2^{100}) 個の可能性をチェックすることを意味します。 グラフの条件を、最大 100 個の未知数を含むシステムに変換する必要があります。ガウス消去法は簡単に十分に高速です。 

直感的なアプローチが失敗するケースがいくつかあります。 よくある間違いは、すべての次数が奇数であれば、すべてのプレーヤーを 1 つのグループに配置することが常に機能するはずだと考えることです。 一部の頂点の次数が偶数の場合、これは false になります。 例えば：```
3 2
1 2
2 3
```中央のプレーヤーには 2 人の友達がいます。したがって、全員が同じグループに属している場合、そのプレーヤーには 2 人の友達が表示され、これは均等になります。 正しい出力は次のとおりです`N`。 グラフの次数の合計をチェックするだけの方法では、各頂点に独自の条件があるという事実が見落とされます。 

もう 1 つの注意が必要なケースは、2 つのグループが両方とも空でない必要はないということです。 例えば：```
2 1
1 2
```両方のプレイヤーを同じグループに入れると、各プレイヤーにグループ内の友達が 1 人ずつ追加されます。 正しい出力は次のとおりです`Y`。 空ではない 2 番目のグループを強制するソリューションは、このケースを誤って拒否します。 

3 番目のケースは、複数の有効なパーティションが存在する場合です。 例えば：```
4 4
1 2
2 3
3 4
4 1
```サイクルは複数の方法に分割でき、アルゴリズムは有効な割り当てを 1 つ見つけるだけで済みます。 一意のパーティションが存在することを想定すべきではありません。 

## アプローチ

 直接的な総当たりアプローチは、各プレイヤーのグループを独立して決定することです。 (2^P) 個の可能な割り当てのそれぞれについて、プレイヤーごとに、同じ割り当てグループを持つ隣接する頂点の数を数えます。 すべてのカウントが奇数の場合、パーティションは存在します。 

このアプローチは、考えられるすべてのパーティションを検査するため、正しいです。 ただし、(P=100) の場合、割り当ての数は (2^{100}) となり、約 (1.27 \times 10^{30}) になります。 たとえ 1 つの割り当てを確認するのに数回の操作しかかからなかったとしても、これは不可能です。 

この問題の重要な構造は、条件がパリティのみに依存するということです。 同じグループ内の友達の正確な数は必要ありません。その数が奇数か偶数かだけが必要です。 パリティは当然、すべての値が 0 または 1 になる、算術モジュロ 2 になります。 

(x_i) がプレーヤー (i) のグループを表すものとします。 2 つのグループには (0) と (1) を使用します。 近隣 (j) の場合、(j) が (i) と同じグループにあるかどうかを示す値は次のように記述できます。 

[
 1 + x_i + x_j
 ]

 計算がモジュロ 2 で実行されるとき。2 人のプレーヤーのグループ値が等しい場合、式は 1 になり、それ以外の場合は 0 になります。 

プレイヤー (i) の場合、すべての友人にこの式を追加すると、同じグループの友人の数が同等になります。 

[
 deg_i + \sum_{j \in N(i)} x_j + deg_i \cdot x_i
 ]

 すべての演算はモジュロ 2 です。同じグループの友人の数は奇数でなければならないため、この値は 1 に等しくなければなりません。 

並べ替えると次のような一次方程式が得られます。 

[
 \sum_{j \in N(i)} x_j + (deg_i \bmod 2)x_i = 1 + (deg_i \bmod 2)
 ]

 すべてのプレイヤーが 1 つの方程式に貢献し、すべてのプレイヤーが 1 つの変数になります。 問題は、GF(2) 上の最大 100 個の線形方程式の系に解があるかどうかを確認することになります。 ガウス消去法はこれに直接作用します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^P · P²) | O(P²) | 遅すぎる |
 | 最適 | O(P3) | O(P²) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 線形システムを表すバイナリ行列を構築します。 各行は 1 人のプレーヤーに対応し、各列は 1 人のプレーヤーのグループ変数に対応します。 最後の列には、方程式の右側に必要な値が格納されます。 

変数 (x_j) の係数は、プレイヤー (j) がプレイヤー (i) の友人である場合、1 になります。 さらに、プレイヤー (i) の次数が奇数の場合、(deg_i \cdot x_i) 項により (x_i) の係数が切り替わります。 
2. モジュロ 2 に対してガウス消去法を適用します。現在の列で 1 を持つ行を見つけ、それを現在のピボット位置に交換します。 

ピボットが現在の行の下に表示される可能性があり、ピボットを上に移動しないと列を正しく削除できないため、スワップが必要です。 
3. ピボット行を使用して、現在の変数を 1 行おきの行から削除します。 

すべての演算はモジュロ 2 であるため、変数の削除はピボット行と別の行の XOR 演算を行うだけです。 これにより、行列の値がバイナリに保たれます。 
4. 消去後、すべての行を検査します。 すべての変数係数がゼロでも最終値が 1 の場合、方程式は不可能であるため、有効な分割は存在しません。 

このような行は (0 = 1) のような矛盾を表します。 
5. 矛盾が存在しない場合、システムには少なくとも 1 つのグループ値の割り当てがあるため、答えは次のようになります。`Y`。 

なぜ効果があるのか:

 グラフ問題から方程式への変換により、必要な正確な条件が保存されます。 有効なパーティションはすべての方程式を満たす変数の値を生成し、方程式の解はすべてのプレイヤーが同じグループに奇数の友達を持つグループ値を与えます。 GF(2) に対するガウス消去法は解のセットを変更せず、方程式をより簡単な形式に変換するだけです。 最後の矛盾チェックでは、分割の可能性がないシステムと、少なくとも 1 つあるシステムが区別されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    P, F = map(int, input().split())
    adj = [[0] * P for _ in range(P)]
    deg = [0] * P

    for _ in range(F):
        a, b = map(int, input().split())
        a -= 1
        b -= 1
        adj[a][b] = 1
        adj[b][a] = 1
        deg[a] += 1
        deg[b] += 1

    mat = [[0] * (P + 1) for _ in range(P)]

    for i in range(P):
        for j in range(P):
            mat[i][j] = adj[i][j]
        if deg[i] % 2 == 1:
            mat[i][i] ^= 1
        mat[i][P] = 1 ^ (deg[i] % 2)

    row = 0
    for col in range(P):
        pivot = row
        while pivot < P and mat[pivot][col] == 0:
            pivot += 1

        if pivot == P:
            continue

        mat[row], mat[pivot] = mat[pivot], mat[row]

        for i in range(P):
            if i != row and mat[i][col]:
                for j in range(col, P + 1):
                    mat[i][j] ^= mat[row][j]

        row += 1

    for i in range(P):
        all_zero = True
        for j in range(P):
            if mat[i][j]:
                all_zero = False
                break
        if all_zero and mat[i][P]:
            print("N")
            return

    print("Y")

if __name__ == "__main__":
    solve()
```隣接行列には、2 人のプレイヤーが友達であるかどうかのみが保存されます。 制約が小さいため、(P \times P) 行列を使用すると、方程式の構築が単純になり、余分なグラフ走査ロジックの必要性が回避されます。 

行列の構築は、導出された方程式に直接続きます。 すべての友情は、友人の変数の係数に寄与します。 奇数次数のプレイヤーの場合、プレイヤー自身の変数は追加の係数を受け取ります。 右側は (1 + deg_i) モジュロ 2 として計算されます。 

加算と減算はモジュロ 2 の演算では同一であるため、消去では XOR が使用されます。 ピボット検索では、現在ピボットとして使用できない列をスキップします。これは、一部の変数が自由変数である可能性があるため必要です。 

最終スキャンでは、不可能な行のみがチェックされます。 変数が含まれていないが結果がゼロ以外の行は、システムが虚偽のステートメントを要求していることを意味します。 他の最終フォームには、少なくとも 1 つの割り当てが残っています。
