 # 問題の理解

 ボードは大文字の長方形のグリッドです。 コレクションの単語は、元の順序で表示される必要はありません。 代わりに、文字を再配置して指定された単語の 1 つを形成できる、行、列、または対角線の連続したセグメントに興味があります。 

セルが少なくとも 1 つのそのようなセグメントに属している場合、そのセルは特別と呼ばれます。 タスクは、すべての有効なアナグラム セグメントによってカバーされる異なるセルの数を数えることです。 

グリッドの寸法は最大 40 x 40 であるため、ボードには最大 1600 個のセルが含まれます。 コレクションには最大 20 個の単語が含まれ、各単語の長さは最大 15 です。これらの制限は、考えられる多くのセグメントを検査する余裕があるほど十分に小さいですが、各単語に対してボード全体でコストのかかる検索を繰り返し実行するソリューションは除外されます。 重要な制約は最大語長です。 有効なセグメントは短いため、候補セグメントを 1 文字ずつチェックするのはコストがかかりません。 

いくつかの詳細により、単純な実装は簡単に壊れる可能性があります。 文字の順序がまったく異なる場合でも、セグメントは単語と一致する場合があります。 例えば：```
2 3
BCA
XXX
1
ABC
```答えは`3`、最初の行には次のものが含まれているため、`BCA`のアナグラムです。`ABC`。 単語の正確な順序のみを検索するソリューションでは、誤ってゼロが返されます。 

セルは複数の一致するセグメントに属する場合がありますが、カウントされるのは 1 回のみです。 例えば：```
2 2
AA
AA
1
AA
```4 つのセルはそれぞれ、複数の一致するセグメントに属していますが、正解は次のとおりです。`4`。 一致が見つかるたびに回答をインクリメントするような不用意な実装は、過剰にカウントしてしまいます。 

同じ単語長がボードの方向に何度も出現する可能性があり、単語は行と列だけでなく対角線に沿って一致することもあります。 例えば：```
3 3
ABC
XXX
XXX
1
ACB
```文字を再配置する必要があるため、ここでは一番上の行だけでは十分ではありません。 正しい解決策は、セグメント全体をチェックし、文字の頻度を比較します。 

# アプローチ

 直接的なアプローチは、ボードの可能なすべてのセグメントを試すことです。 各開始位置、4 つの有用な方向のそれぞれ、および考えられるすべての単語の長さについて、セグメント内の文字を収集し、その出現頻度数を指定された単語と比較できます。 これが機能するのは、アナグラムが各文字の出現回数によって完全に決定されるためです。 

総当たり法は、単語ごとに作業を繰り返すと非効率になります。 最大のケースでは、約 1600 の開始位置、4 つの方向、多くの可能な長さ、および比較する最大 20 の単語があります。 単語ごとに頻度配列を個別に構築して比較するバージョンでは、何百万もの不必要な操作が実行される可能性があります。 

重要な観察は、単語の長さが短く、入力された 2 つの単語が互いにアナグラムになることはないということです。 セグメントの周波数ベクトルがターゲット周波数ベクトルのセットに属しているかどうかだけを知る必要があります。 すべてのターゲット ベクトルをハッシュ セットに保存し、すべての単語からの検索を 1 回の操作に減らすことができます。 

最大長はわずか 15 であるため、すべての候補セグメントの頻度カウントを再構築するだけでも十分に高速です。 関連するすべての長さと方向にわたって候補セグメントは数万しかありません。 これにより、制限内に収まりながら、複雑なスライディング ウィンドウを維持するよりもはるかに簡単なソリューションが得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(D * L * C * K * P) | O(N) | すべての単語を個別に比較すると遅すぎます。 
| 周波数ハッシュ | O(D * L * C * K * P) | O(N + L * C) | 承認済み |

 ここ、`D`四方向です、`K`は個別の語長の数であり、`P`は最大語長です。 指定された境界では、実際の文字操作の数は少ないままです。 

# アルゴリズムのチュートリアル

 1. すべてのターゲット単語を読み取り、26 文字のそれぞれの数を含む頻度ベクトルに変換します。 これらのベクトルをセットに格納します。 2 つのターゲット単語がアナグラムになることは決してないため、保存された各ベクトルは正確に 1 つのターゲット単語を識別します。 
2. ターゲット単語の明確な長さを記録します。 セグメントは、長さがこれらの値のいずれかである場合にのみ単語と一致できるため、他の長さをチェックしても不必要な作業が発生するだけです。 
3. 考えられるすべての語長と 4 つの方向のそれぞれについて、完全なセグメントを含むことができるすべての開始セルを調べます。 4 つの方向は、水平、垂直、斜め右下、および斜め左下です。 同じセルを逆の順序で記述するため、逆の方向は不要です。 
4. 各候補セグメントの周波数ベクトルを構築し、それが保存されたターゲット セットに存在するかどうかを確認します。 存在する場合は、このセグメントのすべてのセルを特別としてマークします。 
5. すべてのセグメントの処理が完了したら、マークされたセルを数えます。 マーキングは一致の数ではなくブール状態として保存されるため、各セルは 1 回カウントされます。 

なぜ効果があるのか:

 考えられるすべての有効なアナグラム セグメントは、ターゲットの長さの 1 つを持ち、選択された 4 つの方向のいずれかになければなりません。 アルゴリズムはそのようなすべてのセグメントをチェックします。 セグメントは、その文字頻度ベクトルがターゲット単語の 1 つと一致する場合に正確に受け入れられます。これはまさにアナグラムであるという定義です。 受け入れられたすべてのセグメントはそのすべてのセルをマークするため、すべての特別なセルがマークされます。 最終的な回答では一致ではなくマークされたセルがカウントされるため、重複するセグメントによって過剰カウントが発生することはありません。 

# Python ソリューション```python
import sys

input = sys.stdin.readline

def solve():
    L, C = map(int, input().split())
    grid = [input().strip() for _ in range(L)]

    N = int(input())

    target = set()
    lengths = set()

    for _ in range(N):
        word = input().strip()
        cnt = [0] * 26
        for ch in word:
            cnt[ord(ch) - ord('A')] += 1
        target.add(tuple(cnt))
        lengths.add(len(word))

    marked = [[False] * C for _ in range(L)]

    directions = [(0, 1), (1, 0), (1, 1), (1, -1)]

    for length in lengths:
        for dr, dc in directions:
            for r in range(L):
                for c in range(C):
                    end_r = r + dr * (length - 1)
                    end_c = c + dc * (length - 1)

                    if not (0 <= end_r < L and 0 <= end_c < C):
                        continue

                    cnt = [0] * 26
                    cells = []

                    rr, cc = r, c
                    for _ in range(length):
                        cnt[ord(grid[rr][cc]) - ord('A')] += 1
                        cells.append((rr, cc))
                        rr += dr
                        cc += dc

                    if tuple(cnt) in target:
                        for x, y in cells:
                            marked[x][y] = True

    ans = 0
    for row in marked:
        ans += sum(row)

    print(ans)

if __name__ == "__main__":
    solve()
```入力は一度読み取られ、ターゲット単語はすぐに周波数ベクトルに変換されます。 タプルを使用すると、ベクトルを Python セットに保存できるため、一定の平均時間でメンバーシップ チェックが行われます。 

アナグラムは読む順序に依存しないため、4 方向で十分です。 左から右のセグメントとその逆のセグメントには同じセルと同じ文字が含まれるため、両方をチェックすると重複した作業が発生します。 

すべての候補セグメントについて、コードは最初にエンドポイントがボード内に残っているかどうかを検証します。 これにより、境界外へのアクセスが回避され、斜め方向が間違いを引き起こす主な場所となります。 セグメントが収集された後、コードは、周波数ベクトルがターゲットと一致する場合にのみ、そのセルにマークを付けます。 

の`marked`配列はマッチングプロセスとは別のものです。 これが必要なのは、多くの異なるアナグラム セグメントがセルを共有する可能性があり、問題では出現数ではなくセルの数が求められるためです。
