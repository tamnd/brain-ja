 ## 解決策
 ## 問題の理解

 アルバムには、`N`空のスロットがあり、すべてのパケットがランダムな数のステッカーを提供します。 パケットには、次の範囲の任意の整数を含めることができます。`A`そして`B`、すべての値が同じ確率を持ちます。 目標は、1 つの収集プロセスをシミュレートすることではなく、累積されたステッカーが少なくとも一定の数に達するまでに必要な平均パケット数を計算することです。`N`。 

入力値は、ステッカーの目標数と可能な最小および最大のパケット サイズを表します。 出力は、必要なパケットの予想数を表す浮動小数点値です。 

制約`N <= 10^6`が主な難点です。 履歴の数は指数関数的に増加するため、考えられるすべての収集履歴を試すソリューションは不可能です。 すべての状態に対して可能なすべてのパケット サイズにわたって遷移を実行する動的プログラミング ソリューションであっても、次のようなものが必要になります。`N * (B - A + 1)`到達できる操作`10^12`両方の値が大きい場合。 ソリューションは各状態をほぼ一定の時間で処理する必要があります。 

直接式が失敗するケースがいくつかあります。 1 つ目は、パケットにステッカーが含まれていない場合です。 たとえば、入力の場合`1 0 1`、パケットには 0 または 1 つのステッカーが付与されます。 予想される答えは`2.0`なぜなら、最初のパケットは半分の確率で成功し、試行回数は幾何分布に従うからです。 進捗がゼロになる可能性がある場合、平均値は十分な情報ではないため、平均パケット サイズで割る式は失敗します。 

もう 1 つのエッジ ケースは、すべてのパケットのサイズが同じである場合です。 入力用`30 3 3`、各パケットにはちょうど 3 枚のステッカーが含まれているため、答えは次のようになります。`10.0`。 範囲を、同じ可能性の複数の値が含まれているかのように扱うと、範囲の長さによる不正確な除算が発生します。 

最後の境界ケースは、最小パケット サイズがすでに小さい状態を終了しているときに現れます。 入力用`5 5 10`、1 つのパケットで常にアルバムが完成するため、答えは次のようになります。`1.0`。 あり得ない以前の状態が偶然含まれる繰り返しにより、1 より大きな値が生成される可能性があります。 

## アプローチ

 単純な動的プログラミング ソリューションでは、次のことが定義されます。`dp[x]`必要なパケットの予想数として`x`ステッカーはまだありません。 パケットに次の内容が含まれている場合`k`ステッカーの残量は`max(0, x-k)`。 再発というのは、`dp[x] = 1 + average(dp[max(0, x-k)])`考えられるすべてのパケット サイズにわたって。 

すべての状態はより少ない残量のみに依存するため、このアプローチは正しいです。 問題は移行です。 あらゆる人にとって`x`からのすべての値をチェックします`A`に`B`最大 100 万回の操作が必要になる場合があります。 100 万の州の場合、これは約`10^12`限界をはるかに超えた最悪の場合の操作。 

重要な観察点は、遷移では以前の状態の連続した範囲が使用されるということです。 いつ`A > 0`、値`dp[x-B]`を通して`dp[x-A]`ゼロ以外の貢献はこれらだけです。 いつ`A = 0`、トランジションには以下も含まれます`dp[x]`ゼロ ステッカー パケットは状態を変更しないままにするため、それ自体が削除されます。 その場合、反復を代数的に再配置して、現在の値が一定時間内に計算されるようにすることができます。 

動的プログラミング値のプレフィックス合計を維持すると、一定時間で連続した範囲の合計を取得できます。 元の二次遷移は、次の線形スキャンになります。`1`に`N`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N(B - A + 1)) | O(N) | 遅すぎる |
 | 最適 | O(N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を作成する`dp`どこ`dp[x]`収集に必要なパケットの予想数を保存します`x`もっとステッカーを。 メンテナンスも行います`pref[x]`、すべてのプレフィックスの合計`dp`までの値`x`。 
2. からの状態を処理します。`1`に`N`。 常に小さい欠損量を最初に解決します。これは、再帰的に必要なすべての値がすでにわかっていることを意味します。 
3. もし`A > 0`、通常の再発を処理します。 考えられる以前の状態は、次の間隔を形成します。`max(0, x-B)`に`x-A`。 プレフィックスの合計を使用してこの間隔の合計を取得し、次のように計算します。`dp[x] = 1 + interval_sum / (B-A+1)`の`1`は次のパケットの購入を表し、平均はそのパケットの後に予想される残りの作業を表します。 
4. もし`A = 0`、現在の状態を再発から分離します。 ゼロステッカーパケットは貢献します`dp[x]`それ自体なので、方程式は次のようになります。`dp[x] = (B+1 + sum(dp[j]) for j in [max(0,x-B), x-1]) / B`これにより、循環依存関係が回避され、同じ順方向の反復が可能になります。 
5. それぞれを計算した後`dp[x]`、将来の州がすぐに範囲をクエリできるように、プレフィックスの合計を更新します。 

機能する理由: 動的プログラミングの状態は、ステッカーの欠落の可能性がある量ごとに予想される残りのパケット数を正確に表します。 再発は、購入した最初のパケットの条件付けから直接続きます。 プレフィックス合計は、必要な平均の計算方法を変更するだけであり、反復の数学的値は変更しません。 特別な取り扱いは、`A = 0`現在の状態がそれ自体に依存する唯一のケースが削除されるため、すべての状態はすでに確定された値から計算されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    N, A, B = map(int, input().split())

    dp = [0.0] * (N + 1)
    pref = [0.0] * (N + 1)

    count = B - A + 1

    for x in range(1, N + 1):
        if A == 0:
            left = max(0, x - B)
            if left == 0:
                previous_sum = pref[x - 1]
            else:
                previous_sum = pref[x - 1] - pref[left - 1]
            dp[x] = (B + 1 + previous_sum) / B
        else:
            left = max(0, x - B)
            right = x - A
            if right >= left:
                interval_sum = pref[right]
                if left > 0:
                    interval_sum -= pref[left - 1]
            else:
                interval_sum = 0.0
            dp[x] = 1.0 + interval_sum / count

        pref[x] = pref[x - 1] + dp[x]

    print("{:.10f}".format(dp[N]))

if __name__ == "__main__":
    solve()
```配列`dp`小さなターゲットごとに答えを保存しますが、`pref`累積合計を保存するので、ループせずに状態の範囲を取得できます。 後の状態は以前のすべての値に依存するため、プレフィックス合計の更新は状態を計算した直後に行われます。 

の支店`A == 0`通常の漸化式には未知の値が含まれるため、これが必要です`dp[x]`。 その項を左辺に移動すると、分母は次のようになります。`B`、 ない`B+1`。 この代数的調整が欠けていることは、最も一般的な実装エラーです。 

のために`A > 0`、`right = x - A`最小のパケットを受信した後に残ることができる最大の前の状態です。 下限は使用します`max(0, x-B)`大きなパケットを受信するとアルバムが完全に終了する可能性があるため、これは`dp[0] = 0`。 

必要な誤差許容度は次のとおりであるため、Python 浮動小数点値で十分です。`10^-5`。 

## 実用的な例

 入力用`40 0 2`、ゼロパケットケースが使用されます。 

| × | 以前に使用された合計 | dp[x] |
 | --- | --- | --- |
 | 1 | dp[0] = 0 | 1.50000 |
 | 2 | dp[0] + dp[1] = 1.50000 | 2.25000 |
 | 3 | dp[1] + dp[2] = 3.75000 | 3.37500 |
 | 40 | dp[38] + dp[39] | 40.33333 |

 トレースは、ステッカー パケットがゼロであると期待値がどのように増加するかを示しています。 失敗したパケットでも試行が消費されるため、反復では単純に平均パケット サイズを使用することはできません。 

入力用`100 1 10`、すべてのパケットが前向きに進行するため、通常の遷移が使用されます。 

| × | 以前の状態の範囲 | dp[x] |
 | --- | --- | --- |
 | 1 | 空 | 1.00000 |
 | 2 | dp[1] | 1.10000 |
 | 3 | dp[1] から dp[2] | 1.21000 |
 | 100 | dp[90] から dp[99] | 18.72727 |

 トレースは、前の値のスライド間隔のみが必要であることを示しています。 プレフィックス合計を使用すると、その間隔を即座に照会できます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N) | 各ステッカー カウントは 1 回処理され、すべての遷移でプレフィックスの合計が使用されます。 |
 | スペース | O(N) | このアルゴリズムは、考えられる残りのステッカー数ごとに 1 つの値と 1 つのプレフィックスの合計を保存します。 |

 線形アルゴリズムでは最大 100 万状態が実用的です。 浮動小数点値の配列が 2 つだけ保存されるため、メモリ使用量も線形で快適にフィットします。 

## テストケース```python
import sys
import io

def solve_data(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)

    N, A, B = map(int, sys.stdin.readline().split())

    dp = [0.0] * (N + 1)
    pref = [0.0] * (N + 1)

    for x in range(1, N + 1):
        if A == 0:
            left = max(0, x - B)
            s = pref[x - 1]
            if left > 0:
                s -= pref[left - 1]
            dp[x] = (B + 1 + s) / B
        else:
            left = max(0, x - B)
            right = x - A
            s = 0.0
            if right >= left:
                s = pref[right]
                if left > 0:
                    s -= pref[left - 1]
            dp[x] = 1 + s / (B - A + 1)
        pref[x] = pref[x - 1] + dp[x]

    sys.stdin = old_stdin
    return "{:.5f}".format(dp[N])

assert abs(float(solve_data("40 0 2")) - 40.33333) < 1e-5
assert abs(float(solve_data("100 1 10")) - 18.72727) < 1e-5
assert abs(float(solve_data("30 3 3")) - 10.0) < 1e-5
assert abs(float(solve_data("314 5 8")) - 48.74556) < 1e-5

assert abs(float(solve_data("1 1 1")) - 1.0) < 1e-5
assert abs(float(solve_data("1 0 1")) - 2.0) < 1e-5
assert abs(float(solve_data("5 5 10")) - 1.0) < 1e-5
assert abs(float(solve_data("1000000 1000000 1000000")) - 1.0) < 1e-5

 ## 特殊なケース

 のために`1 0 1`、アルゴリズムはゼロ最小分岐に入ります。 前回の合計はただ`dp[0]`、これはゼロなので、`dp[1] = (1 + 1 + 0) / 1 = 2`。 これは、最初に 1 ステッカー パケットが成功するまでの予想される試行回数と一致します。 

のために`30 3 3`、すべての遷移には、可能なパケット サイズが 1 つだけあります。 この間隔には、現在の状態から 3 位置後の状態が正確に含まれるため、値は次のようになります。`dp[3] = 1`、`dp[6] = 2`、そして最後に`dp[30] = 10`。 決定的な動作は維持されます。 

のために`5 5 10`、すべてのパケット サイズはすぐに終了するのに十分です。 すべての州について`1`に`5`、遷移範囲は空であり、そのままになります。`dp[x] = 1`。 最終的な答えは正しく 1 パケットです。 

のために`1000000 1000000 1000000`、アルゴリズムは、遷移テーブルを割り当てたり、パケット サイズをループしたりしようとしません。 100 万回の定時更新を実行し、結果を返します。`1.0`これは、線形アプローチが必要な理由を示しています。
