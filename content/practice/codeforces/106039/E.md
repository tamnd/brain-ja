 ## 解決策
 ## 問題の理解

 一連の個別の整数と、非常に特殊な方法で動作するクイックソートの特定のバージョンが与えられます。 ピボットは、値ではなく位置によって、常に現在のセグメントの中間インデックスとして選択されます。 ピボット値を選択すると、`pivot`プロシージャはセグメント全体をスキャンし、すべての要素をこのピボットと比較します。 比較するたびにグローバル カウンターが増加します。 

パーティショニングは、標準のインプレース Lomuto スキームまたは Hoare スキームではありません。 代わりに、ピボットより小さい要素は相対的な順序を維持しながら左側に圧縮され、ピボットより大きい要素は右側に圧縮されますが、相対的な順序は逆になります。 分割後、ピボットは最終位置に配置され、左右のセグメントで再帰が続行されます。 

タスクは並べ替えをシミュレートすることではなく、このクイックソートの実行全体で配列要素とピボット値の間の比較が何回発生するかを正確に計算することです。 

入力サイズは最大 200,000 要素です。 明示的なパーティショニングを使用したクイックソートの直接シミュレーションでも、パーティション レベルごとに線形の作業が行われますが、再帰ツリーは二次的な動作につながる形で縮退する可能性があります。 したがって、単純なシミュレーションでは制限時間を超える危険があります。 

主な微妙な点は、比較がパーティション呼び出しごとにカウントされ、セグメント内のすべての要素がセグメントの処理ごとに 1 回だけ比較されることです。 これは、総コストが、最終的な並べ替え順序だけではなく、メディアン インデックス ピボットによって引き起こされる再帰ツリーの構造によって完全に決定されることを意味します。 

実際に配列の再配置を実行する単純な実装も危険です。パーティション ロジックが非標準であり、要素を繰り返しシフトする必要があり、余分な線形係数が黙って追加される可能性があるためです。 

値の順列に応じて、ピボット インデックスが非常に不均衡なセグメントを繰り返し分割する場合、エッジ ケースが発生します。 たとえば、配列がすでにソートまたは逆ソートされている場合でも、中央値インデックスによって分割が生成されますが、サブセグメント内の値分布の構造によって、要素が将来のパーティションにどの程度深く関与するかが決まります。 

## アプローチ

 直接シミュレーションは、指定された疑似コードに従います。中央のインデックスを選択し、比較をカウントしながらセグメントを分割し、その後再帰します。 これはプロセスと正確に一致するため、概念的には正しいです。 ただし、各パーティションはセグメント全体を 1 回スキャンし、再帰は 2 つのサブ問題に分割され、そのサイズはピボット値がどこに到達するかによって異なります。 

ピボット インデックスが固定されている場合でも、再帰呼び出しで各要素が何回再検出されるかは、値の分布によって決まります。 最悪の場合、これは非常に不均衡なパーティションによるクイックソートのように動作し、二次時間につながります。 

重要な点は、実際にはパーティショニングをシミュレートする必要がないということです。 コストにとって重要なのは、現在の間隔の中間インデックスでピボットを繰り返し選択することによって形成されたセグメントの一部として各要素が何回比較されるかということだけです。 

純粋にインデックスに基づいて再帰を観察すると、各呼び出しでセグメントが処理されます。`[l, r]`そして貢献する`(r - l + 1)`比較。 ピボットは、セグメントを 2 つの互いに素なインデックス間隔に分割します。 したがって、比較の合計数は、再帰ツリー内のすべてのセグメントの長さの正確な合計になります。 

これにより、問題は、常に中間点インデックスによって分割することによって定義される決定論的な分割統治ツリーにわたるサイズ合計の計算に変換されます。 値の置換は、発生する比較の数には影響せず、どの値がどのサブツリーに配置されるかのみに影響しますが、再帰ツリー内のすべてのノードは常にそのセグメント長に等しいコストに寄与します。 

したがって、答えはインデックスの再帰構造のみに依存します。この再帰構造は、インデックス範囲の分割統治を使用してセグメント サイズを合計することで効率的に計算できます。

 | --- | --- | --- | --- |
 | パーティションの完全なシミュレーション | O(n^2) | O(n) | 遅すぎる |
 | インデックスに対する分割統治 | O(n) | O(log n) | 承認済み |

 ## アルゴリズムのチュートリアル

 このプロセスをインデックス間隔のみで動作するものとして再構築します。 

### 1. 再帰構造を定義する

 ある区間にわたる関数を考えます`[l, r]`これは、そのセグメントに対するクイックソートへの 1 回の呼び出しを表します。 ピボットインデックスは次のように固定されます。`m = (l + r) // 2`。 

この分割は値に依存しないため、再帰ツリーはインデックスに対して決定的です。 

### 2. 1 つのセグメントが寄与するコンピューティング コスト

 セグメントの場合`[l, r]`、ピボット ルーチンはセグメント内のすべての要素を 1 回比較するため、正確に寄与します。`r - l + 1`比較。 

これは、再帰ツリー内の各ノードがそのセグメント サイズに等しい重みを与えることを意味します。 

### 3. 左半分と右半分を再帰する

 選択した後`m`、アルゴリズムは続行します`[l, m - 1]`そして`[m + 1, r]`。 

これら 2 つの間隔は互いに素であり、すべての非ピボット要素をカバーし、パーティション構造と一致します。 

### 4. 貢献度の集計

 以下を再帰的に合計して総コストを計算します。 

現在のセグメントのコストに、左右のサブセグメントのコストを加えたものです。 

これは標準的な分割統治の蓄積です。 

### 5. 基本ケース

 いつ`l > r`、仕事がないので貢献度はゼロです。 

### なぜ効果があるのか

 インデックスに対する再帰ツリーは入力値に関係なく固定されており、すべてのノードは 1 回の呼び出しに正確に対応します。`pivot`。 このような各呼び出しでは、そのセグメント内の要素ごとに 1 つの比較が正確に実行されるため、すべてのノードのセグメント サイズをカウントすると、実行された比較の合計数が正確に一致します。 要素が関与するセグメントの外で要素がカウントされることはなく、すべての要素は元のコードでの実際の比較に対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    n = int(input())
    arr = list(map(int, input().split()))
    
    def dfs(l, r):
        if l > r:
            return 0
        m = (l + r) // 2
        # cost of this partition: every element is compared once
        return (r - l + 1) + dfs(l, m - 1) + dfs(m + 1, r)
    
    print(dfs(0, n - 1))

if __name__ == "__main__":
    solve()
```この実装は再帰構造を直接反映しています。 機能`dfs(l, r)`はセグメントに対する 1 つのクイックソート呼び出しを表し、その戻り値はそのサブツリー内で行われた比較の数です。 

中点の計算は整数の除算であり、前述のピボット選択と一致します。 基本ケースは無効な範囲を防ぎます。 重要なモデリング手順は、各セグメントをその全長に一度だけ寄与するものとして扱うことです。これにより、配列の再配置のシミュレーションが回避されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各セグメントは 1 回処理され、再帰は各インデックス範囲を 1 回だけ訪問します。 
| スペース | O(log n) | 再帰の深さはインデックス間隔のバイナリ分割に従います。 

このソリューションは、次の制約内に快適に適合します。`n ≤ 2 × 10^5`、各要素は再帰ツリーのレベルごとに 1 つのノードに正確に寄与するためです。

 ## 特殊なケース

 単一要素の配列は基本ケースのみをトリガーします`[0,0]`、ゼロの比較に貢献します。 再帰はピボット ロジックに入らずにすぐに戻り、比較が行われないという事実と一致します。 

2 要素の配列`[l, r]`サイズ 2 のルート セグメントを生成し、2 つの比較を行った後、2 つの単一要素セグメントに分割します。 これらのそれぞれは、それ以上の比較に寄与しないため、セグメント合計の解釈と一致して、合計コストはちょうど 2 になります。 

逆ソートまたはソートされた配列は、ピボットがインデックスのみに依存するため、再帰構造をまったく変更しません。 同じ一連のセグメント サイズが生成されるため、どちらも同じ合計比較カウントを生成します。
