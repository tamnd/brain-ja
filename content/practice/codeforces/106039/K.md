 ## 解決策
 ## 問題の理解

 私たちは、アントニオが使用を拒否した一連の材料と材料のリストを渡されました。 レシピはいくつかのステージに分割されており、各ステージではそのステップに必要な材料のサブセットが指定されています。 

アントニオは舞台を準備するとき、嫌いな材料をすべて省きます。 これにより、その段階で実際に使用される材料の数が減る可能性があります。 不足している成分の割合がそのステージの元の成分数の 3 分の 1 を超える場合、そのステージは受け入れられなくなります。 

タスクは、この状態が発生する最も初期のステージ、つまり、欠落している成分の数が厳密にステージ サイズの 3 分の 1 を超える最初のステージを見つけることです。 この条件に違反するステージがない場合は、マイナス 1 を出力します。 

この制約は、すべての段階にわたる成分言及の総数が最大 300,000 であることを意味します。 これにより、ステージごとに大きな構造を二次形式で繰り返しスキャンするソリューションは即座に除外されます。 各成分はステージごとに 1 回だけ表示され、ステージ全体の合計サイズは制限されているため、それ自体の成分に対するステージごとの線形スキャンは許容されます。 

ステージサイズが小さい場合、微妙なエッジケースが現れます。 ステージのサイズが 1 の場合、1 は 1/3 より大きいため、成分が 1 つ欠けているとすでにステージが無効になります。 同様に、サイズ 2 の場合、1 > 2/3 は偽ですが、2 > 2/3 は成り立つため、少なくとも 1 つの成分が欠けていれば十分です。 したがって、実際には、しきい値は整数の除算に敏感であり、四捨五入ではなく厳密な不等式を使用して処理する必要があります。 

もう 1 つのエッジケースは、どの段階でも嫌いな材料が出現しない場合です。 正しい出力はマイナス 1 であり、答えを誤って初期化したり、すべての段階のチェックを忘れたりする単純な実装では、誤ってゼロまたは初期化されていない値が返される可能性があります。 

## アプローチ

 問題を解決する直接的な方法は、各段階を個別にシミュレーションすることです。 特定のステージについて、そのすべての要素をスキャンし、アントニオの嫌いなセットに属するものがいくつあるかを数えます。 その後、このカウントをステージ サイズの 3 分の 1 と比較します。 厳密にそれより大きい場合、そのステージは無効です。 

各成分はステージごとに 1 回処理され、すべてのステージ サイズの合計が最大 300,000 であるため、この総当り手法はすでに最適に非常に近づいています。 唯一の懸念は、その成分が嫌われているかどうかをどのように確認するかということです。 嫌いな成分をハッシュ セットに保存すると、メンバーシップ チェックは平均 O(1) になり、ソリューション全体が合計入力サイズに対して線形になります。 

重要な観察は、ステージ間に相互依存性がないということです。 各ステージは、嫌いなセットとの重複の数のみを使用して独立して評価できます。 これにより、セットの構築以外にプレフィックス構造、ソート、または前処理が必要なくなります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ステージごとのブルート フォース スキャン | O(全成分) | O(B) | 承認済み |
 | ハッシュ セット メンバーシップのカウント | O(全成分) | O(B) | 承認済み |

 実際には、入力の構造によって全体の作業がすでに制限されているため、両方の記述は同じ実装に折りたたまれます。 

## アルゴリズムのチュートリアル

 ### 最適なアルゴリズム

 1. 嫌いな成分のセットを読み取り、ハッシュ セットに保存します。 これにより、Antonio によって無視された成分がないかどうかを定期的にチェックすることができます。 
2. 各ステージを順番に繰り返します。 各段階の成分リストをお読みください。 
3. 現在のステージについて、嫌いなセットにその要素がいくつ登場するかを数えます。 この数は、実際に不足している成分の数を表します。 
4. このカウントが厳密にステージ サイズの 3 分の 1 を超えているかどうかを確認します。 浮動小数点除算を使用する代わりに、比較します。`3 * missing > M`これにより、精度の問題が回避され、すべてが整数に保たれます。 
5. 条件が成立する場合は、現在のステージ インデックスを直ちに応答として返します。 
6. すべての処理を行った後、条件を満たすステージが存在しなかった場合は、マイナス 1 を返します。 

### なぜ効果があるのか

 各ステージは、ステージの材料セットと嫌いなセットの間の交差サイズのみに基づいて独立して評価されます。 状態は、欠けている成分の数のみに依存し、その正体や位置には依存しません。 このカウントをステージごとに正確に計算し、近似を行わずに不等式をチェックするため、最初の違反ステージが正しい順序で見つかります。 どの段階もスキップされたり、他の段階の影響を受けたりすることはないため、最も早い段階の障害が常に正しく検出されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    N, A, B = map(int, input().split())
    disliked = set(map(int, input().split()))

    for i in range(1, N + 1):
        data = list(map(int, input().split()))
        M = data[0]
        arr = data[1:]

        missing = 0
        for x in arr:
            if x in disliked:
                missing += 1

        if 3 * missing > M:
            print(i)
            return

    print(-1)

if __name__ == "__main__":
    solve()
```この解決策は、嫌いな要素をすべてハッシュ セットにロードすることから始まります。これが必要な唯一の前処理です。 その後、各ステージが順番に処理されます。 ライン`3 * missing > M`は、浮動小数点演算を行わずに「3 分の 1 以上」をエンコードする重要な比較です。 

すべてのステージにわたる成分エントリの合計数は 300,000 で制限されているため、成分のループは安全です。そのため、最悪の場合でも内部ループは合計 300,000 回の反復を実行します。

 ## 特殊なケース

 ステージ サイズが小さいと、条件がすぐにトリガーされる可能性があります。 たとえば、ステージに 1 つの要素があり、それが嫌われている場合、`missing = 1`そして`3 * 1 > 1`はすぐに成り立ち、最初の段階で拒否が発生します。 サイズに関係なく同じ整数不等式が使用されるため、アルゴリズムはこれを自然に処理します。 

不足している材料がステージのちょうど 3 分の 1 に等しい場合でも、ステージは受け入れられる必要があります。 たとえば、サイズ 3 のステージに 1 つの成分が欠けている場合、次のようになります。`3 * 1 = 3`厳密には 3 を超えることはありません。実装では、厳密な不等式を使用することにより、この境界条件が正しく保存されます。 

どのステージにも嫌いな成分が含まれていない場合、すべてのステージに`missing`はゼロであるため、不等式は成立せず、アルゴリズムはすべてのステージの処理後にマイナス 1 を正しく出力します。
