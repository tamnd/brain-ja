 ## 解決策
 ## 問題の理解

 固定の夜数 D と、人が眠ることができる N 個の場所の集合が与えられます。 各場所には、その場所で連続して何泊できるかを制限する制約があります。 その人が連続して 2 日以上同じ場所に留まると、すぐに強制退去されるため、有効な計画は制限を超える前に長い連続記録を破る必要があります。 

タスクは、長さ D の任意のシーケンスを構築することです。ここで、各要素は 1 から N までのインデックスであり、人が毎晩どこで寝るかを記述します。 シーケンスは、インデックス i が di より長い連続ブロックに出現しないという規則を尊重する必要があります。 di が 0 の場合、一晩でもすでに制約に違反しているため、その場所はまったく使用できません。 

N、D ≤ 100000 という制約は、どの解も最大でも O(D log D) または O(D) でなければならないことを意味します。 D の二次関数や、位置ごとにフル スキャンを繰り返すものはすべて失敗します。 違反が発生した後にそれを修復しようとする単純なバックトラッキングや貪欲なシミュレーションは、D が大きく有効な構成が厳しい最悪の場合には遅すぎます。 

使用可能な di 値がすべて小さいのに D が大きい場合、微妙な失敗のケースが発生します。 たとえば、すべての di が 1 の場合、どの場所も 2 回連続して使用できないため、完全に交互に使用する必要があります。 N = 1 および D = 2、d1 = 1 の場合は不可能ですが、N = 2 の場合は解決策が存在します。 これは、実現可能性は総容量だけではなく、限界に達する前に常に「切り替える」ことができるかどうかにも依存することを示しています。 

すべての di がゼロの場合、別の特殊なケースが発生します。 その場合、あらゆる場所が禁止され、D = 1 さえ不可能になります。 di = 0 を無視する貪欲なアプローチでは、これらのインデックスを誤って使用しようとします。 

## アプローチ

 強引なアイデアは、毎日シーケンスを構築し、毎日すべての可能な場所を試し、その場所の追加が連続制約に違反するかどうかを確認することです。 その場合は、別の場所を試します。 現在の場所の現在のストリークの長さを維持し、シーケンスを拡張するときに更新します。 

制約を尊重するシーケンスのみを受け入れるため、これは論理的に機能しますが、問題は、最悪の場合、1 日に多くの代替案を試行する可能性があることです。 現在の場所が枯渇し、切り替える必要がある状況に遭遇した場合、N 個の候補すべてを繰り返しスキャンして、O(DN) 動作 (最悪の場合は 10^10 の操作) が発生する可能性があります。 

重要な点は、制約が連続使用にのみ依存するということです。 一度場所を決めたら、最長でも連続して 2 日間そこに滞在することができますが、それより早く出発することを強制するものは何もありません。 これは、常に最大の安全ストリークが得られる場所を使用し、その後切り替える必要があることを示唆しています。 

それぞれの場所を、最大 di までの長さのブロックを放出できる「リソース」として扱うことができます。 これらのブロックを合計長 D のシーケンスにつなぎ合わせたいと考えています。唯一の困難は、現在のブロックが終了したときに有効な次のブロックを常に確保できるようにすることです。 

自然な貪欲な戦略は、セグメントを開始または再開する必要があるときに、常に最大の許容ストリークが残っている場所を選択することです。 常に現在最も強い選択肢を選択すると、残りの日数を埋めることができない弱い選択肢だけで行き詰まるのを避けることができます。 

これを効率的にサポートするために、di をキーとする最大ヒープを維持します。 利用可能な最適な場所を繰り返し取得し、それを min(di, Remaining_days) まで使用し、まだ容量が残っている場合はプッシュして戻します (または、di はグローバルに減少せず、連続した使用のみが問題となるため、単純に再利用します。代わりに、同じプールを再利用することでストリークを明示的に管理します)。

重要な構造は、あまりにも長い連続実行を防ぐことだけを考慮しているため、ある場所から切り替えると、その適格性がすぐにリセットされるということです。 これにより、許容されるストリークの長さを最大化しながら、最後に使用した場所とは異なる場所を繰り返し選択するという問題が発生します。

 | --- | --- | --- | --- |
 | ブルートフォース | O(DN) | O(N) | 遅すぎる |
 | 最適 (貪欲 + ヒープ) | O(D log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは、利用可能な場所の優先キューを di の降順で維持します。 また、最後に選択した場所と、それを連続して何回使用したかも追跡します。 

1. di > 0 となるすべてのインデックス i を、di をキーとする最大ヒープに挿入します。 これらは使用可能な場所を表します。 di = 0 エントリは、有効なシーケンス内に決して出現できないため、完全に無視されます。 
2. 空の結果リストと変数 last_place = -1 および streak = 0 を初期化します。 
3. 1 から D までの毎日、次に寝る場所を選択します。 まず、ヒープの中から利用可能な最適な場所を選択しようとします。 その場所が last_place と同じであり、それを使用すると許可される連続制限を超える場合は、一時的にその場所をスキップし、次善の候補を採用します。 

スキップする理由は、ヒープが「現在のストリーク状態」をエンコードしないため、その制約を手動で強制する必要があるためです。 

1. 候補地 x を選択したら、それを回答に追加し、last_place を更新します。 x が last_place に等しい場合は、ストリークをインクリメントします。そうでない場合は、ストリークを 1 にリセットします。 
2. x を使用した後、将来の選択にまだ役立つ場合にのみ、x をヒープに再挿入します。 di は消費可能なリソースではなく最大連続許容値であるため、変更されずにヒープ内に残りますが、ストリーク追跡によって過剰使用をブロックするだけで正確性が保証されます。 
3. ストリークがすでに d[last_place] に達しているときに、いずれかの時点で last_place とは異なる有効な候補が見つからない場合、構築は不可能であると結論付けます。 

この選択戦略が正しい理由は、切り替えを余儀なくされるたびに、有効なソリューションもその時点で切り替える必要があるという事実に関係しています。 利用可能な最大の di を選択すると、将来のセグメントに対する柔軟性が最大化されます。 

### なぜ効果があるのか

 毎日の境界において、実行可能性を損なう可能性がある唯一の制約は、実行を di 制限を超えて延長することを強制されることです。 このアルゴリズムは、現在のランレングスがその場所の di を決して超えないという不変条件を維持し、切り替えが必要な場合は常に、有効なソリューションはその時点またはその前に切り替えを実行する必要があります。 私たちは常に最も寛容な利用可能な次のブロックを選択するため、将来の実現可能性を必要以上に下げることはなく、必要な時期よりも早く使用できなくなるような方法で場所を消費することもありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import heapq

def solve():
    n, d = map(int, input().split())
    arr = list(map(int, input().split()))
    
    heap = []
    for i, v in enumerate(arr):
        if v > 0:
            heapq.heappush(heap, (-v, i + 1))
    
    if not heap:
        print(-1)
        return
    
    res = []
    last = -1
    streak = 0
    last_limit = 0
    
    for _ in range(d):
        if not heap:
            print(-1)
            return
        
        v1, i1 = heapq.heappop(heap)
        v1 = -v1
        
        if i1 == last and streak == v1:
            if not heap:
                print(-1)
                return
            v2, i2 = heapq.heappop(heap)
            v2 = -v2
            heapq.heappush(heap, (-v1, i1))
            
            chosen = i2
            if i2 == last:
                streak += 1
            else:
                streak = 1
            last = i2
            res.append(chosen)
        else:
            chosen = i1
            heapq.heappush(heap, (-v1, i1))
            
            if i1 == last:
                streak += 1
            else:
                streak = 1
            last = i1
            res.append(chosen)
    
    print(*res)

if __name__ == "__main__":
    solve()
```実装では、di によって場所の最大ヒープが保持されます。 毎日、利用可能な最も強力な場所を使用しようとします。 現在の連勝によりその場所が連続制限に違反する場合は、一時的にその場所をスキップし、次善の候補を使用します。 

重要な点は、要素をヒープから永久に削除しないことです。 各場所は利用可能なままですが、正確性はストリーク ロジックによって強制されます。 スワップ メカニズムにより、最適な候補が最後に使用された場所と同じであるがすでに飽和している場合に、時期尚早にスタックすることがなくなります。 

ストリークを正確に追跡するには注意が必要です。 連続数は当日を含む現在の実行をカウントするため、off-by-one エラーがよく発生します。

 ## 特殊なケース

 すべての di が 0 である場合は、空ヒープ チェックによって直ちに処理されます。 場所が挿入されていないため、アルゴリズムは構築を試みる前に -1 を出力します。 

di = 1 で D > 1 の有効な場所が 1 つだけある場合、ヒープは常に同じ要素を返し、ストリーク条件によりそれ以降の使用は直ちにブロックされます。 2 番目のヒープ フォールバックは存在しないため、アルゴリズムは -1 で正しく終了します。 

複数の場所が di = 1 に等しい場合、ヒープは常に代替候補を提供します。 ストリーク ロジックにより、ヒープの順序付けにより同じインデックスが再び先頭に表示された場合でも、使用可能な別のインデックスが優先されてスキップされ、有効な交互シーケンスが生成されます。
