 ## 解決策
 ## 問題の理解

 長さのシーケンスが与えられます$2N$, ここで、各値は$1$に$N$正確に 2 回表示されます。 これは、線に沿って配置された同一のシンボルのペアと考えることができます。 

タスクは、厳密な移動ルールの下で等しいシンボルのペアを選択することです。 位置でオカレンスをペアにすることにした場合$i$、ある位置で一致するものと直ちにペアにする必要があります。$j > i$。 これを実行すると、その時点から前方にスキャンし続け、後戻りすることはできません。 選択された各ペアは、そのエンドポイント間の距離に等しいコストをもたらします。$j - i$。 

目標には 2 つのレベルがあります。 まず、順方向のみのプロセスを尊重しながら、形成できるそのようなペアの数を最大化したいと考えます。 次に、この最大ペア数を達成するすべての戦略の中で、総コストを最小限に抑えたいと考えます。 

制約の重要な意味は次のとおりです。$N \le 10^5$、したがって配列の長さは最大です$2 \cdot 10^5$。 選択肢をシミュレートしたり、組み合わせを検索しようとするソリューションは失敗します。 平$O(N^2)$推論はすでに大きすぎて、$O(N \log N)$ソリューションは注意深く構成する必要があります。 

微妙な問題は、貪欲なペアリングは自明のことながら安全ではないということです。 シンボルを最初に一致する可能性のあるものと組み合わせると、より適切なグローバル構造がブロックされる可能性があります。 たとえば、次のようなシーケンスでは、$1, 2, 1, 2$、最初のペアリング$1$2番目と$1$は不可能なので、相互作用を強いられ、順序付けの制約が重要になります。 もう 1 つの微妙なケースは、将来の接続が長くなるために、最適なペアリングを行うために以前の機会をスキップする必要がある場合です。 

さらに深刻な問題は、単に間隔を独立して一致させているわけではないということです。 すべてのペアは配列のセグメントを消費し、1 つのペアの選択は、順方向スキャンでどのシンボルが引き続き照合できるかに影響します。 

## アプローチ

 ブルートフォース解釈は、重複しない前方ペアを形成するすべての有効な方法を探索するプロセスをシミュレートすることです。 各位置で、それをスキップするか、右側のどこかで一致する出現と組み合わせて、そこから再帰的に試みます。 これにより、すべての有効なシーケンスが正しく調査され、コストを累積しながら、可能なペアの数をカウントできます。 

問題は分岐係数が大きいことです。 位置ごとに複数の有効な一致パートナーが存在する可能性があり、すべてのペアの組み合わせに対する再帰はすぐに爆発的に増加します。 最悪の場合、これは指数関数的に増加します$N$なぜなら、すべてのペアの決定は、非局所的な方法で将来の可能性を制約するからです。 

構造的な洞察は、実際には任意の組み合わせの中から選択する必要がないということです。 各値は正確に 2 回出現するため、各要素は 2 回出現するまでの固定間隔を定義します。 唯一の実際の決定は、前の選択によって暗示される順序付けの制約に違反することなく、指定された間隔を有効な前方チェーンの一部として取得できるかどうかです。 

各数値を間隔として表示すると、$(l_i, r_i)$の場合、問題は単調スキャン プロセスの下で間隔の最大数を選択することになります。ここで、左端点の昇順で間隔を処理し、選択された間隔が非減少境界を尊重するようにする必要があります。 

2 番目の重要なアイデアは、ペアの数を最大化することはコストに依存しないということです。 有効なフォワード構築ではすべての数値がペアになるかペアにならないかのどちらかである必要があるため、ペアの最大数は、貪欲なフォワード スイープで重複せずにチェーンできる間隔の数によって決まります。 最大セットが固定されると、総距離を最小化する方法で、可能な限り最も近い有効な一致を常に使用するようになり、コストを最小限に抑えることができます。 

これは当然、スタックベースの解釈につながります。配列をスキャンするときは可能な限り一致しますが、ペアリングを遅らせると距離が増加するだけであるため、常に最も近い利用可能なオープン オカレンスとペアリングするようにします。

 ## アルゴリズムのチュートリアル

 シーケンスをストリームとして扱い、スタックを使用して現在一致しないオカレンスのセットを維持します。 シンボルを見るたびに、それが以前に開いたシンボルを閉じるかどうかを決定します。 

1. 空のスタックと、ペアの数と合計コストのカウンターを初期化します。 
2. 配列を左から右に繰り返します。 

価値観に出会ったとき$x$かどうかを確認します。$x$はすでにスタックの一番上にあります。 そうでない場合は、この発生を開始点として扱い、スタックにプッシュします。 

これが機能するのは、この時点では、この発生に最適なペアリングがどこになるかまだ分からず、時期尚早なペアリングの決定は順方向制約に違反するためです。 
3. 現在の値がスタックの最上位と一致する場合、同じシンボルの最新の不一致オープニングに対する正しいクローズが見つかりました。 

それをポップしてペアを形成します。 距離の寄与は、現在のインデックスから開始箇所の保存されたインデックスを引いたものです。 
4. ペアが形成されるたびに、ペア数を増加させ、総コストに距離を加算します。 

この貪欲なクロージャは正しいです。なぜなら、利用可能な最も近い一致ではない後続の要素と要素をペアにすることは、クロージャを遅らせるだけであり、実現可能性を向上させることなくコストを厳密に増加させることになるからです。 
5. 配列全体を処理した後、形成されたペアの数と累積コストを出力します。 

### なぜ効果があるのか

 スタックは常に、アクティブで一致しないシンボルのセットを、開かれた順序で表します。 このアルゴリズムでは、常に最後に開いた互換性のあるシンボルを最初に閉じることが強制されます。 これにより、後で接続を長くすることになるインターリーブが防止されます。 

不変条件は、現在スタック内にあるすべてのシンボルについて、その一致するパートナーが、順序に違反することなくより緊密なペアリングを可能にする方法でまだ渡されていないことです。 各シンボルは正確に 2 回表示されるため、最初に表示されたときに間隔が開き、2 回目に表示されたときに間隔が閉じる必要があります。 スタックは、ネストされた構造が後入れ先出し方式で解決されることを保証します。これはまさに、前方のみのトラバーサルで依存関係の交差を回避する唯一の方法です。 

このポリシーから逸脱すると、有効な即時一致がスキップされるか、より遠くで後の一致が強制されるため、ペアの数は増加せずにコストが増加します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    stack = []
    pos = {}
    pairs = 0
    cost = 0

    for i, x in enumerate(a):
        if stack and stack[-1] == x:
            j = stack.pop()
            cost += i - j
            pairs += 1
        else:
            stack.append(i)

    print(pairs, cost)

if __name__ == "__main__":
    solve()
```この実装では、配列を 1 回スキャンし、一致しない開口部のインデックスをスタックに保持します。 コストは位置に依存するため、重要な設計上の選択は、値ではなくインデックスを保存することです。 一致するたびに正確な距離がすぐに計算され、後で変更する必要がないことが保証されます。 

条件`stack[-1] == x`最適なペアリングに必要なネストされた構造を維持しながら、シンボルが最新の不一致の出現に一致した場合にのみシンボルを閉じることが保証されます。

 ## 特殊なケース

 のような最小限のケース$1, 1$アルゴリズムが即時クローズを正しく処理することを確認します。 スタックは最初の要素を受け取り、2 番目の要素がすぐにそれに一致し、コスト 1 のペアが 1 つ生成されます。 

次のような完全にネストされたシーケンス$1, 2, 3, 3, 2, 1$LIFO 動作の重要性を示しています。 新しいシンボルを開いて逆順に解決するとスタックが増大し、以前に開いたシンボルが独立したペアリングをブロックするため、有効なペアが 1 つだけ生成されます。 

のような交差パターン$1, 2, 1, 2$すべての出現が独立した間隔を形成するわけではないことを示しています。 スタックにより、ペアリングが 1 つだけ形成されることが保証され、コストには強制的な長い接続が反映され、時期尚早なペアリングの試行が順序付けの制約に違反することが確認されます。
