 ## 解決策
 ## 問題の理解

 のみを含む配列が与えられます。`1`そして`-1`。 あらゆるクエリに対して`[l, r]`、インデックスから部分配列を調べます`l`に`r`。 その部分配列内の要素を任意の順序で並べ替えることができますが、部分配列の合計がゼロになることが可能かどうかを判断する必要があります。 

実際には、数字の順序は合計には関係ありません。 再配置では位置のみが変更され、数は変更されません`1`と`-1`性差別主義者。 本当の問題は、選択したセグメントに同じ数のセグメントが含まれているかどうかです。`1`と`-1`s.

 部分配列に長さがある場合`k`、合計が得られます`0`ちょうど要素の半分が`1`そして残りの半分は`-1`。 これにより、すぐに 2 つのことが分かります。 まず、セグメントの長さが偶数である必要があります。 第二に、その数`1`s は次の数と等しくなければなりません`-1`s.

 制約が大きいため、すべてのクエリを要素ごとに検査することはできません。 両方`n`そして`m`到達できる`2 * 10^5`。 各クエリの単純なスキャンには時間がかかります`O(length of segment)`おおよその時間になります`4 * 10^10`最悪の場合の運用。 これは1秒の制限時間をはるかに超えています。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

奇数の長さのセグメントを考えてみましょう。```
3 1
1 -1 1
1 3
```正しい答えは次のとおりです。```
0
```カウントが近い場合でも、奇数長のセグメントを同じ数のセグメントに均等に分割することはできません。`1`そして`-1`。 

もう 1 つの微妙なケースは、長さは均一だがカウントがアンバランスなセグメントです。```
4 1
1 1 -1 -1
1 2
```セグメント`[1, 2]`2つ含まれています`1`といいえ`-1`s. 並べ替えても何も変わらないので、答えは変わりません`0`。 

不用意に実装すると、再配置をシミュレートしようとして問題が複雑になりすぎる可能性があります。 例えば：```
4 1
1 -1 1 -1
1 4
```合計はすでに`0`、したがって、答えは次のとおりです`1`。 実際の再配置ロジックは必要ありません。 

## アプローチ

 ブルート フォース アプローチでは、すべてのクエリが個別に処理されます。 各セグメントごとに`[l, r]`、何個数えますか`1`と`-1`が表示されます。 カウントが一致する場合は印刷します`1`; それ以外の場合は印刷します`0`。 

これが機能するのは、合計を達成するための条件が次のとおりであるためです。`0`は、正の数と負の数が正確に等しいことを意味します。 問題はスピードです。 最悪の場合、各クエリは配列のほぼ全体をスキャンする可能性があります。 と`2 * 10^5`クエリと`2 * 10^5`要素を追加すると、合計作業量は 2 次になります。 

重要な観察点は、実際の値は次のとおりであるということです。`1`そして`-1`。 セグメントには合計を含めることができます`0`その長さが偶数で、その数が偶数である場合に限り、`1`s は次の数に等しい`-1`s. 両方を毎回別々にカウントする代わりに、グローバルに 1 つのカテゴリのみをカウントできます。 

の総数を事前に計算するとします。`1`配列全体の s。 させて：```
ones = number of elements equal to 1
minus = number of elements equal to -1
```ある長さのクエリセグメントの場合`len`:```
len = r - l + 1
```合計をゼロにするには、次のものが必要です。```
len / 2 <= ones
len / 2 <= minus
```なぜ？ セグメントには正確に含まれている必要があるため、`len / 2`各値のコピー。 再配置には制限がないため、重要なのは可用性だけです。 

これにより、すべてのクエリが一定時間のチェックに減ります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nm) | お(1) | 遅すぎる |
 | 最適 | O(n + m) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を読み取り、等しい要素の数を数えます。`1`。 
2. 等しい要素の数を計算します。`-1`。 
3. 各クエリについて、セグメントの長さを計算します。```
len = r - l + 1
```4. 長さが奇数の場合は、印刷します`0`。 

ゼロサムには等しい数のものが必要です`1`そして`-1`、要素の数が奇数の場合は不可能です。 
5. それ以外の場合は、次のように計算します。```
need = len // 2
```これは何個ですか`1`と`-1`■ セグメントには次のものが含まれている必要があります。 
6. 両方のグローバル カウントが満たされる場合:```
ones >= need
minus >= need
```印刷する`1`。 それ以外の場合は印刷します`0`。 

これが機能する理由は、再配置により位置の制約がすべて削除されるためです。 必要なサイズのセグメントを満たすのに十分な各値のコピーが存在するかどうかだけを考慮します。 

### なぜ効果があるのか

 長さのセグメント`len`合計があります`0`まさに同じ数が含まれているとき`1`と`-1`s. すべての要素はいずれかであるため、`1`または`-1`、カウントが等しいということは、次のことを意味します。```
count(1) = count(-1) = len / 2
```もし`len`奇妙です、これはすぐには不可能です。 

もし`len`が偶数の場合、残る唯一の問題は、配列に少なくとも`len / 2`各値のコピー。 並び替えは自由ですので、位置は一切問いません。 アルゴリズムはこれらの必要十分条件を正確にチェックするため、すべての答えは正しいものになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    arr = list(map(int, input().split()))

    ones = arr.count(1)
    minus = n - ones

    ans = []

    for _ in range(m):
        l, r = map(int, input().split())

        length = r - l + 1

        if length % 2 == 1:
            ans.append("0")
            continue

        need = length // 2

        if ones >= need and minus >= need:
            ans.append("1")
        else:
            ans.append("0")

    print("\n".join(ans))

solve()
```最初の部分は何個数えますか`1`はグローバルに存在します。 他のすべての値は次のようにする必要があるため、`-1`、負の数は単純に次のようになります。`n - ones`。 

各クエリはセグメントの長さにのみ依存します。 実際のポジション`l`そして`r`その長さを決定すること以外には無関係です。 それが問題の中心的な単純化です。 

奇数長チェックは、不可能なケースを即座に拒否するため、最初に行われます。 その後、`need = length // 2`は各値の必要な数を表します。 

よくある間違いは、サブ配列の内容を正確に分析しようとすることです。 このステートメントでは、選択した範囲内の要素を再配置できるため、カウントのみが重要になります。 

もう 1 つの簡単な間違いは、長さを間違って計算することです。 両方のエンドポイントが含まれるため、正しい式は次のようになります。```
r - l + 1

def solve():

    minus = n - ones

    ans = []

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()
