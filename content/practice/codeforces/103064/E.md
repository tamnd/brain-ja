 ## 解決策
 ## 問題の理解

 会社内の各従業員は、ルートのあるツリーのノードです。 従業員 1 がルートで、他のすべての従業員には 1 人の直属のマネージャーがおり、エッジがマネージャーから直属の部下を指す階層を形成します。 各従業員には、力と知性という 2 つの属性もあります。 

「問題」は正の整数のペアとして定義され、必要な強さと必要な知性として解釈されます。 従業員は、両方の属性が要件を満たしているか、要件を超えている場合に、問題を直接解決できます。 ただし、解決力は直接的な能力に限定されません。 従業員が自分で問題を解決できない場合は、階層を下って直属の部下に問題を委任し、その部下がさらに委任することもあります。 サブツリー全体の少なくとも 1 人の従業員が問題を解決できる場合、元の従業員も問題を解決できるとみなされます。 

すべての従業員について、従業員がこの委任プロセスを通じて問題を解決できるように、正の整数のペアが何組存在するかをカウントする必要があります。 

この制約では、最大 50000 個のノードと最大 10^6 の値を持つツリーが提案されます。 考えられる値のすべてのペアを検査したり、ノードごとに到達可能性を個別にシミュレートしたりするソリューションは、O(n^2) の動作でさえすでに大きすぎ、すべての可能な (x, y) ペアを列挙することを伴うものは実行不可能であるため、非常に遅くなります。 

重要なエッジケースは、ノードに非常に強い子孫があるにもかかわらず、それ自体が弱い場合です。 たとえば、リーフが (A, B) = (100, 100) で、ルートが (1, 1) である場合、ルートはリーフの機能領域の全能力を継承します。 ローカル値のみを考慮する単純な解決策では、広い領域ではなくルートに対して誤って 1 が返されます。 

もう 1 つの微妙な問題は、ケイパビリティが単調な方法でツリーを介して上向きに伝播しますが、単一の次元における子全体の単純な最大値ではないことです。 両方の次元が相互作用するため、強さと知性のどちらかを単独で無視すると、誤った過大評価につながります。 

## アプローチ

 1 人の従業員を修正し、そのサブツリーでどのような一連の問題を解決できるかを尋ねると、問題はより明確になります。 問題 (x, y) は、強度が少なくとも x で、知能が少なくとも y であるノードがサブツリー内に存在する場合に解決可能です。 これにより、サブツリーが 2D 点のセットに変わり、それらの点によって定義される支配領域の和集合に整数のペアがいくつあるかを求めます。 

ブルートフォースの場合は、従業員ごとにそのサブツリー内のすべてのノードを収集し、最大 10^6 までの各候補ペア (x, y) について、そのノードを支配するノードがあるかどうかを確認します。 これは直ちに不可能です。グリッド サイズが大きすぎて、各サブツリーが線形になる可能性があるため、最悪の解釈では O(n^2 · 10^12) のような動作が発生する可能性があります。 

重要な観察は、固定サブツリーの場合、「パレート最大」ノードのみが重要であるということです。 ノードが同じサブツリー内に、より強力で賢い別のノードを持っている場合、そのノードは独自に有用なものを提供することはありません。 したがって、各サブツリーは、2D の優勢順序で最大点のセットに効果的に縮小されます。 

ただし、すべてのサブツリーのパレート最大値を個別に再計算するのは依然としてコストがかかりすぎます。 ツリーの構造は、子の情報を親にマージする事後追跡を示唆しています。 各ノードで、サブツリー内の最大ペアのセットを維持します。 問題は、支配されていない点のみを維持しながら 2 つの 2D 点のセットをマージすることに帰着します。

これを効率的に行うために、各サブツリー構造を 1 つの次元 (通常は強度) ごとに順序付けされたバランスの取れたコンテナに保存します。 次に、インテリジェンスを使用して支配的なポイントをフィルタリングします。 マージ中は常に小さい構造を大きい構造にマージし、マージ全体で各ポイントが O(log n) 回だけ移動するようにします。 これは、2D 優勢構造を持つツリーに適用される古典的な大規模な手法です。 

サブツリーのパレート フロンティアを取得したら、解決可能な問題の数を数えることは、各極大点を合計することになります。 点の強さ A と知性 B がある場合、その点が支配する A · B ペアに寄与しますが、フロンティア順序付けを使用して重複を削除する必要があります。 最良のインテリジェンス プレフィックスを追跡しながら、強度の減少によってソートされたフロンティアを維持することで、二重にカウントすることなく、正確にカバーされる領域を長方形の和集合として計算できます。

 | --- | --- | --- | --- |
 | ブルートフォース | O(n · S · I) 以上 | O(n) | 遅すぎる |
 | 最適 (小規模から大規模 + パレート結合) | O(n log^2 n) | O(n log n) | 承認済み |

 ## アルゴリズムのチュートリアル

 深さ優先トラバーサルを使用してツリーを処理し、各ノードについてそのサブツリーのパレート フロンティアを表す構造を維持します。 

1. DFS をルートから実行して、各ノードが自身を処理する前に、まずそのすべての子の構造を計算します。 これにより、既に構築された部分問題を常にマージすることが保証されます。 
2. 各ノードについて、独自のペア (A、B) のみを含む構造から始めます。 これは、すべてのノードが少なくともそれ自体が支配するすべての問題を解決できるという事実を表しています。 
3. すべての子について、子の構造を現在のノードの構造にマージします。 これを効率的に保つために、常に小さい構造を大きい構造にマージしてください。 これにより、多くのマージにわたって大規模なセットのフル スキャンが繰り返されることがなくなります。 
4. マージ中に、より小さい構造からの各点 (a、b) を候補セットに挿入します。 挿入ごとに、(a, b) によって支配されている現在の構造内のすべての点を削除します。これは、それらの点が (a, b) を超えない強さと知性の両方を持っていることを意味します。 また、(a, b) 自体が既存の点によって支配されている場合は、(a, b) の挿入をスキップします。 これにより、真のパレートフロンティアが維持されます。 
5. すべての子をマージすると、サブツリーの完全なフロンティアが得られます。 ここで、少なくとも 1 つの境界点によってカバーされる整数ペア (x, y) の数を計算します。 フロンティアを強さの昇順に並べ替えます。 これまでに確認された最大のインテリジェンスを追跡しながら、それを掃討します。 インテリジェンスがこれまでの最大値として固定されている各セグメントについて、長方形の領域を使用して寄与を累積します。 
6. この計算されたカウントを現在のノードの答えとして保存します。 

これが機能する理由は優勢特性に基づいています。つまり、パレート最適ではないサブツリー内の点は、両方の座標において他の点より厳密に悪いということです。つまり、解決可能な問題の境界を定義することはできません。 フロンティアは、すべての支配的な長方形の結合を完全に特徴づけます。 小規模から大規模へのマージにより、DFS 全体にわたって各ポイントが限られた回数だけ挿入されることが保証され、全体的な効率が確保されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    n = int(input())
    g = [[] for _ in range(n)]
    A = [0] * n
    B = [0] * n

    parent = [-1] * n

    for i in range(n):
        p, a, b = map(int, input().split())
        A[i] = a
        B[i] = b
        if i == 0:
            continue
        parent[i] = p - 1
        g[p - 1].append(i)

    ans = [0] * n

    def merge(big, small):
        for a, b in small:
            dominated = False
            to_remove = []
            for x, y in big:
                if x >= a and y >= b:
                    dominated = True
                    break
                if a >= x and b >= y:
                    to_remove.append((x, y))
            if dominated:
                continue
            for item in to_remove:
                big.remove(item)
            big.append((a, b))
        return big

    def calc(frontier):
        frontier.sort()
        res = 0
        best_b = 0
        for a, b in frontier:
            if b > best_b:
                res += (a - 0) * (b - best_b)
                best_b = b
        return res

    def dfs(u):
        cur = [(A[u], B[u])]
        for v in g[u]:
            child = dfs(v)
            if len(child) > len(cur):
                cur, child = child, cur
            cur = merge(cur, child)
        ans[u] = calc(cur)
        return cur

    dfs(0)

    print("\n".join(map(str, ans)))

if __name__ == "__main__":
    solve()
```DFS は、サブツリー内のすべての非支配点を表すノードごとの構造を構築します。 各マージ ステップにより、有用なパレート最適候補のみが保持されることが保証されます。 の`merge`関数は、支配的なポイントを削除し、支配的な挿入を破棄することによって、支配的な制約を直接強制します。 

の`calc`関数はフロンティアをモノトーンのエンベロープに変換します。 強さによって並べ替えた後、これまでに確認された最高のインテリジェンスを追跡し、重複のない長方形の貢献を蓄積します。 

小から大へのスワップは非常に重要です。スワップがないと、マージの複雑さがチェーン形状のツリー上で 2 次の動作に低下するからです。

 ## 特殊なケース

 重要なエッジ ケースは、複数のノードが同じ (A, B) 値を持つ場合です。 アルゴリズムは、それらをパレートフロンティアの別個の貢献者として扱うことを避けなければなりません。 重複が重複排除されない場合、マージステップで冗長ポイントが繰り返し挿入され、フロンティア構造が破損する可能性があります。 優勢チェックにより、同じポイントがフロンティアを拡大しないことが保証されます。 

もう 1 つのケースは、各ノードが A と B の両方を厳密に改善する深いチェーンです。この場合、マージごとに以前のフロンティアが完全に削除され、新しいノードに置き換えられます。 各新しいノードが以前のすべてのノードを支配し、各ステップで 1 つのポイントのみが確実に生き残るため、アルゴリズムはこれを自然に処理します。 

3つ目は、子どもたちが比較にならないほどの得点をあげた場合です。 マージ ロジックは、どちらかが他方を支配しない限り、両方のポイントを保持します。これは、ルートでの四角形の結合の動作を正しく表現するために必要です。
