 ## 解決策
 ## 問題の理解

 整数のフロア除算から構築された関数を 2 回適用して作業しています。 固定番号の場合$N$、すべての候補値$X$範囲内で$[1, N]$最初のコンピューティングによってテストされます$\lfloor N / X \rfloor$、その結果を除数として使用して同じ演算を再度適用します。 値$X$この 2 段階のプロセスが正確に返される場合、有効であるとみなされます。$X$また。 

したがって、構造は対称です。$X$、それを商にマップし、その商を使用してマップを戻し、元の値に戻るかどうかを確認します。 タスクは、次の整数がいくつあるかを数えることです。$[1, N]$指定されたそれぞれについてこの固定小数点条件を満たす$N$、最大 10 個のクエリと値$N$と同じくらい大きい$10^{18}$。 

ブルートフォースアプローチでは、あらゆるものをテストすることになります。$X$、2 つのフロア分割を計算し、結果を比較します。 つまり$O(N)$クエリごとに、これは不可能です$N$到達する$10^{18}$。 平$N = 10^9$すでに実現可能な限界をはるかに超えているだろう。 

主なエッジ ケースは、フロア分割により一定値の大きな間隔が作成されるという事実から生じます。 たとえば、次の場合$N = 10$、 それから$\lfloor 10 / X \rfloor$のような範囲では定数です$X = 1$10を与えると、$X = 2$に$3$5 を与えるなどです。 単純な値ごとのチェックでは、同じ商を何度も再計算することになり、この構造が欠落します。 

問題を解決する鍵は、個人の観点から考えるのをやめる事です$X$代わりに、商が一定のままの範囲で動作します。 

## アプローチ

 ブルートフォースメソッドはすべての整数を直接チェックします$X$、計算します$k = \lfloor N / X \rfloor$、次に計算します$\lfloor N / k \rfloor$そしてそれを比較します$X$。 これは定義上は正しいですが、クエリごとに直線的な作業が必要であり、全体としては完全に失敗します。$N$。 

構造上の観察によると、その機能は$\lfloor N / X \rfloor$は区分的に一定です。 のすべての値$X$同じ商を生成するものは連続セグメントを形成します。 個々の値を反復する代わりに、これらのセグメントを反復できます。 

セグメント内で、$k = \lfloor N / X \rfloor$固定されています、毎回$X$同じ最初の変換を共有します。 2 番目の変換は次のようになります$\lfloor N / k \rfloor$、これもそのセグメントでは一定です。 これは、セグメントごとに 1 つの候補値のみをテストする必要があることを意味します。$X' = \lfloor N / k \rfloor$。 この候補が生成されたセグメント内にある場合$k$であれば、それは有効な解決策です。 

これにより、すべての整数を反復処理する問題が軽減されます。$N$を反復する$O(\sqrt{N})$商セグメント。

 ## アルゴリズムのチュートリアル

 の各値を処理します。$N$独立して。 

1. から始める$X = 1$、標準的なフロア分割グループ化手法を使用して、フロアの最大間隔を特定します。$X$どこ$k = \lfloor N / X \rfloor$一定のままです。 これは、次の場合にのみ商が変化するため機能します。$X$の約数の境界を越える$N$。 
2. で始まるセグメントの場合$X = l$、計算する$k = \lfloor N / l \rfloor$。 これは、すべての最初の変換の値です。$X$このセグメントでは。 
3. 適切な境界を決定する$r$このセグメントの最大値として、すべての$X \in [l, r]$満足する$\lfloor N / X \rfloor = k$。 
4. これを修正するには$k$、2 番目の変換値を計算します。$X' = \lfloor N / k \rfloor$。 
5. かどうかを確認します。$X'$現在のセグメント内にあります$[l, r]$。 そうなったら、これ$X'$は有効であり、答えに 1 つだけ貢献します。 
6. 設定により次のセグメントに移動します$l = r + 1$そしてそれを繰り返す$l > N$。 

### なぜ効果があるのか

 どのセグメント内でも$[l, r]$、の値$\lfloor N / X \rfloor$すべての人にとって同一である$X$。 つまり、最初の変換はセグメント インデックスによって完全に決定されます。 修正したら$k$、2 番目の変換は独立したものになります。$X$単一の候補値を生成します$X'$。 2 段階マッピングが元の値に戻る唯一の方法は、この候補が同じ領域に存在し、同じ領域に存在する場合です。$k$、両方のフロア分割方向の一貫性を確保します。 それぞれ有効なので、$X$はセグメントと候補チェックによって一意に決定され、重複はカウントされません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_one(n: int) -> int:
    ans = 0
    x = 1

    while x <= n:
        k = n // x
        r = n // k

        x_candidate = n // k
        if x <= x_candidate <= r:
            ans += 1

        x = r + 1

    return ans

def main():
    q = int(input())
    for _ in range(q):
        n = int(input())
        print(solve_one(n))

if __name__ == "__main__":
    main()
```この実装は、セグメントベースの推論を直接反映しています。 ループ変数`x`は各商セグメントの左境界を表します。 値`k = n // x`セグメント全体の定数商を定義し、`r = n // k`そのセグメントの全範囲を計算します。 

重要な点は、個別に反復処理を行わないことです。$X$、セグメント境界を越えた場合のみ。 各セグメントに対して、正確に 1 つの候補を計算します。$X = \lfloor N / k \rfloor$、セグメント内にあるかどうかを確認します。 これにより、冗長な作業を回避しながら正確性が保証されます。

 ## 特殊なケース

 のために$N = 1$、唯一の値は$X = 1$、両方の除算がすぐに 1 を返すため、答えは 1 になります。最初のセグメントは次のとおりであるため、アルゴリズムはこれを処理します。$[1,1]$と$k = 1$、候補も 1 であり、セグメントの内側にあります。 

小型用$N$2 や 3 のように、セグメントは短く、ほとんどがシングルトンです。 各セグメントは、候補が 1 つだけの有効な値を正確に提供します。$X = \lfloor N / k \rfloor$常にセグメント境界と一致します。 

大型用$N$の値が小さいため、セグメントの数は少なくなります。$\lfloor N / X \rfloor$すぐに減ります。 アルゴリズムは個別に反復することはありません$X$、だからさえ$N = 10^{18}$管理可能なままです。 

すべての場合において、正確さは各セグメントが一意の商を持つという事実から導き出されます。$k$、および有効な任意の$X$は、その商によって引き起こされる一意の固定点でなければなりません。
