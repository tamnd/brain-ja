 ## 解決策
 ## 問題の理解

 各プログラミング タスクを最初から最後まで変換する繰り返しのワークフローが与えられます。 すべてのタスクは 4 つの段階を順番に通過します。 第 1 段階はコードの作成であり、第 3 段階はテスト結果後のコードの修正であり、どちらも Pasha の存在が必要であり、それぞれに時間 A がかかります。第 2 段階は自動テストであり、第 4 段階はコードレビューであり、どちらも時間 B がかかり、Pasha の積極的な参加は必要ありませんが、完了までに時間がかかります。 

重要な制約は、パイプライン全体が継続的に実行されなければならないということです。 タスクがプロセスに入ると、ステージ間にアイドル時間がなくなり、単一のフローでタスクが次々に処理されます。 N 個のタスクを完了するための最小合計時間を決定する必要があります。 

重要な点は、各タスクが固定の内部構造を持っているということです。つまり、長さ A の 2 つの「アクティブ」セグメントが分離され、その後に長さ B の 2 つの「非アクティブ」セグメントが続きます。ただし、タスクはパイプラインで処理されるため、依存関係が尊重されている限り、異なるタスクの異なるステージが時間的に重複する可能性があります。 

入力制約により、タスクごとのスケジューリングをシミュレートすることができなくなります。 N は 10^9 に達する可能性があるため、線形シミュレーションやタスクごとのシミュレーションはすぐに遅すぎます。 解決策は、問題をパイプラインの構造から派生した閉じた形式の式に還元する必要があります。 

B が A よりも大幅に大きい場合、またはその逆の場合、微妙なエッジ ケースが発生します。 たとえば、A が B よりもはるかに小さい場合、素朴な解釈ではアイドル待機が優勢であると想定される可能性がありますが、重複ステージにより B の大部分が隠蔽される可能性があります。逆に、A が優勢な場合、パイプラインはほぼ順次に動作します。 

## アプローチ

 この問題を考える簡単な方法は、タスクごとに 4 ステージのパイプラインをシミュレートすることです。 各タスクはステージ 1 に入り、その後ステージ 2 ～ 4 を通過し、その後のタスクはその後ろのキューに入れられます。 これは当然、各ステージがいつ空くかを追跡するスケジュール シミュレーションにつながります。 

このシミュレーションはすべての制約を直接尊重しているため正しいですが、すぐに実行不可能になります。 各タスクは一定の作業に寄与するため、合計の複雑さは O(N) になります。 Nが10^9までなので制限時間内では無理です。 

重要な観察点は、これは一般的なスケジュールの問題ではなく、ステージ期間が決定的な厳格なパイプラインであるということです。 各タスクは同じ作業パターンに寄与し、システムはベルトコンベアのように動作します。 十分なタスクが実行されると、パイプラインは定常状態に達し、完了時間が直線的に増加します。 

個々のステージを追跡する代わりに、新しいタスクをパイプラインに「挿入」するのにかかる時間と、完了したタスクがどのくらい早く終了するかに焦点を当てます。 最初のタスクでは、4 つのステージすべてのコストを全額支払います。 その後、重複が発生します。つまり、1 つのタスクがテストまたはレビュー中である間に、別のタスクがすでにコーディングまたは修正中である可能性があります。 アクティブ ステージ (A) とパッシブ ステージ (B) は交互の依存関係を形成するため、実効スループットはそれらの間のボトルネックによって決まります。 

主要な削減点は、システムが線形チェーンのように動作し、各タスクが初期ウォームアップ後に固定増分を効果的に追加することです。 この増分は、A と B の間の最大オーバーラップ制約によって制御されることが判明し、パイプラインがいっぱいになった後、タスクごとの一定の寄与が得られます。

 ## アルゴリズムのチュートリアル

1. 各タスクは、期間 A、B、B、A の 4 つの連続ステージの固定内部構造を持っていることに注目してください。順序は変更できませんが、依存関係が満たされている限り、異なるタスクのステージは重複する可能性があります。 
2. 最初のタスクだけを考えてみましょう。 4 つのステージすべてを順番に完了する必要があるため、合計時間は 2A + 2B かかります。 これにより、初期の「パイプライン充填」コストが確立されます。 
3. 最初のタスクがテストに入った後、最初のタスクがコーディング ステージを解放するとすぐに、2 番目のタスクはコーディングを開始できます。 これにより、タスク間に重複が生じます。つまり、後のタスクでは 2A + 2B のコスト全体が独立して発生することはありません。 
4. ステージ間の依存関係チェーンを追跡します。 2 番目の A ステージ (修正) はテストが終了するまで開始できず、レビューは修正に依存します。 これは、A ステージが重要なシリアル依存関係を形成する一方、B ステージはタスク間で部分的に重複する可能性があることを意味します。 
5. 実質的な制限要因は、B ステージによって強制される間隔を尊重しながら、新しいタスクが両方の A ステージをどれだけ早く完全に「進める」ことができるかになります。 これは、能動的作業 (A) と受動的作業 (B) のどちらが連続するタスクの完了間隔を支配しているかを比較することに帰着します。 
6. 定常状態の動作では、最初のタスク以降、タスクごとに一定のスループットが得られます。これは max(A, B) によって決まります。 アクティブ ステージまたはパッシブ ステージのいずれかがボトルネックを形成し、より緊密なパッキングを妨げるため、タスクを追加するたびに合計時間が 2 * max(A, B) だけ実質的に増加します。 
7. ウォームアップ コストと定常状態の増加を組み合わせます。合計時間は、初期値 2A + 2B と (N − 1) にタスクごとの増分 2 * max(A, B) を掛けたものです。 

### なぜ効果があるのか

 このシステムは、交互の依存関係を持つ 2 フェーズのパイプラインです。 A ステージは必須のユーザー依存作業のシリアル チェーンを形成し、B ステージは重複する可能性があるが間隔を強制する遅延として機能します。 パイプラインがいっぱいになると、新しいタスクはすべて、2 つのリソース制約のうち遅い方のリソース制約が容量を解放するまで待機する必要があります。 これにより、完了時間に一定の繰り返しが発生し、一定の傾きで直線的に成長することが保証されます。 すべてのタスクが同一であるため、並べ替えやローカル最適化によってこの傾きが変化することはなく、式は正確になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    N = int(input().strip())
    A = int(input().strip())
    B = int(input().strip())

    if N == 1:
        print(2 * A + 2 * B)
        return

    print(2 * A + 2 * B + (N - 1) * 2 * max(A, B))

if __name__ == "__main__":
    solve()
```このソリューションは、派生した閉じた形式を直接適用します。 最初のタスクは、4 つのステージすべてのパイプライン コスト全体 (2A + 2B) に寄与します。 タスクが完全に完了するには、パイプラインの両方の半分が進行する必要があるため、追加の各タスクは、A と B の間のボトルネックによって決定される一定の増分に寄与します。これは、max(A, B) で捕捉され、2 を乗算したものです。 

特殊なケース N = 1 では、(N − 1) の乗算が回避されます。そうしないと、タスクが 1 つしかない場合でも重複が存在すると誤って想定されてしまいます。 

## 実用的な例

 ### 例 1

 N = 2、A = 3、B = 5 とします。 

次の式を使用して計算します。 

| ステップ | 値 |
 | --- | --- |
 | 最初のタスク | 2A + 2B = 6 + 10 = 16 |
 | タスクごとの増分 | 2 * 最大(A, B) = 10 |
 | 合計 | 16 + 1 * 10 = 26 |

 これは、B が優勢な場合、パイプラインの間隔がテストおよびレビューの段階によって制御されることを示しています。 

### 例 2

 N = 3、A = 7、B = 4 とします。 

| ステップ | 値 |
 | --- | --- |
 | 最初のタスク | 2A + 2B = 14 + 8 = 22 |
 | タスクごとの増分 | 2 * 最大(A, B) = 14 |
 | 合計 | 22 + 2 * 14 = 50 |

 ここでは A が優勢であるため、コーディングと修正の段階でスループットが決まります。 

これらのトレースは、最初のタスクの後、追加の各タスクが A と B の大きい方のみによって決定される一定量を寄与することを確認します。

 ## 特殊なケース

 N = 1 の場合、パイプラインは定常状態に到達しません。 重複する可能性がないため、アルゴリズムは 2A + 2B を正しく返します。 

A = B の場合、アクティブ ステージとパッシブ ステージの両方が同等に制約されます。 この式は 2A + 2A + (N − 1) * 2A = 2AN に明確に減算されます。これは、パイプラインが完全に逐次プロセスのように動作することを意味します。 これにより、対称性の下での一貫性が確認されます。 

A ≫ B などの極端な不均衡の場合、増分は 2A になります。これは、テストとレビューが完全に隠蔽されている一方で、コーディングと修正がスループットを支配していることを意味します。 B ステージがボトルネックになることがないため、計算されたスケジュールは正しいままです。 

B ≫ A の場合は、その逆が起こります。テストとレビューが優勢となり、A ステージは重複部分に完全に隠れます。 この式は、常に max(A, B) を通じて真のボトルネックを選択するため、正しい線形成長を生成します。
