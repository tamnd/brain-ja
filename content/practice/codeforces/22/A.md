 ## 解決策
 ## 問題の理解

 小さな整数の配列が与えられているので、配列内の最小要素より厳密に大きい最小値を見つける必要があります。 

別の考え方としては、重複する値を削除し、残りの数値を並べ替えて 2 番目の要素を確認すると、その値が答えになります。 そのような値が存在しない場合は、次のように出力します。`NO`。 

たとえば、配列では次のようになります。```
1 2 2 -4
```最小値は`-4`。 より大きい最小の数`-4`は`1`、したがって、答えは次のとおりです`1`。 

制約はわずかです。 配列の長さは最大 100 であるため、二次解であっても完全に安全です。 アン`O(n^2)`アルゴリズムは最大 10,000 回の比較を実行しますが、これは 2 秒の制限時間では無視できる程度です。 入力が非常に小さいため、メモリ使用量もここでは関係ありません。 

難しいのはパフォーマンスではなく、重複を正しく処理することです。 この問題では、配列全体を並べ替えた後の 2 番目の要素ではなく、最小値より厳密に大きい最小の数値が求められます。 

次の入力を考えてみましょう。```
5
1 1 1 2 3
```正しい答えは次のとおりです。```
2
```単純に配列をソートしてインデックス 1 の要素を取得すると、次のようになります。`1`、最小値の重複はカウントされないため、これは間違っています。 

もう 1 つの重要なエッジ ケースは、すべての値が等しい場合に発生します。```
4
7 7 7 7
```最小値より大きい数値はないため、正しい出力は次のようになります。```
NO
```不注意な実装では、重複を削除した後も 2 番目の要素にアクセスしようとしてクラッシュしたり、誤って出力されたりする可能性があります。`7`。 

負の値も重要です。```
5
-10 -5 -10 -3
```最小値は`-10`、それより大きい最小値`-5`。 並べ替えロジックは、負の数に対しても正しく機能する必要があります。 

## アプローチ

 最も直接的な総当たりのアイデアは、すべての要素を他のすべての要素と比較することです。 まず最小値を見つけてから、配列を再度スキャンして、その最小値より大きい最小の数値を検索します。 This already works in linear time.

 より文字通りの総当たりバージョンでは、すべての個別の値が生成され、それらが並べ替えられ、2 番目の値が取得されます。 配列には最大 100 個の要素が含まれるため、並べ替えでもまったく問題ありません。 Sorting 100 numbers costs roughly`100 log 100`, which is tiny.

 この問題の興味深い部分は、ここで「二次統計」が実際に何を意味するのかを理解することです。 これは、ソートされた元の配列の 2 番目の位置を意味するものではありません。 これは、並べ替え後の 2 番目の個別の値を意味します。 

この観察は、すぐにクリーンな解決策を示唆しています。 

1. Remove duplicates.
 2. 残りの値を並べ替えます。 
3. 存在する個別の値が 2 つ未満の場合は、次のように出力します。`NO`。 
4. それ以外の場合は、2 番目の値を出力します。 

入力が小さいため総当り攻撃は機能しますが、個別の値を観察することで実装がよりクリーンになり、エラーが発生しにくくなります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | 承認済み |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 整数を読み取る`n`そして配列の値。 
2. 配列をセットに変換して重複を削除します。 

最小値が繰り返し出現しても答えに影響を与えてはならないため、このステップは不可欠です。 
3. セットをリストに変換し直し、昇順に並べ替えます。 

並べ替え後、最初の要素は最小の個別値であり、2 番目の要素が存在する場合、それが必要な答えになります。 
4. 個別の値がいくつ存在するかを確認します。 

サイズが 2 より小さい場合、有効な 2 次統計はありません。 
5. 少なくとも 2 つの異なる値がある場合は、インデックスの要素を出力します。`1`。 

配列はソートされているため、これは最小値よりも厳密に大きい最小値になります。 

### なぜ効果があるのか

 重複を削除した後、残りのすべての数値は、元の配列からの 1 つの異なる値を表します。 これらの値を並べ替えると、昇順に配置されます。 最初の値は最小の個別要素であり、次の値は正確にそれより大きい最小の個別要素です。 問題定義はこの特性に直接一致するため、アルゴリズムは常に正しい答えを生成します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
arr = list(map(int, input().split()))

distinct = sorted(set(arr))

if len(distinct) < 2:
    print("NO")
else:
    print(distinct[1])
```この解決策は、通常、高速入力を使用して配列を読み取ることから始まります。 高速 I/O はこれらの制約のために実際には必要ありませんが、競技プログラミングでは標準的な方法です。 

重要な行は次のとおりです。```
distinct = sorted(set(arr))
```の`set`重複した値を自動的に削除します。 これにより、最小値が繰り返されて誤って答えになることが防止されます。 その後、`sorted`残りの数値を昇順に並べます。 

配列は次のようなものであるため、長さのチェックは重要です。```
5 5 5 5
```重複を削除した後は、異なる値が 1 つだけ生成されます。 インデックスへのアクセス`1`チェックしないとエラーが発生します。 

最後に、少なくとも 2 つの個別の値が存在する場合、2 番目に小さい個別の数値は正確に次のようになります。`distinct[1]`。 

## 実用的な例

 ### 例 1

 入力:```
4
1 2 2 -4
```| ステップ | 値 |
 | --- | --- |
 | 元の配列 |`[1, 2, 2, -4]`|
 | After removing duplicates |`{1, 2, -4}`|
 | 並べ替え後 |`[-4, 1, 2]`|
 | 2 番目の個別の値 |`1`|

 最小の個別値は次のとおりです。`-4`。 次に大きな個別の値は次のとおりです。`1`、これは必要な定義と一致します。 

### 例 2

 入力:```
5
7 7 7 7 7
```| ステップ | 値 |
 | --- | --- |
 | 元の配列 |`[7, 7, 7, 7, 7]`|
 | 重複を削除した後 |`{7}`|
 | 並べ替え後 |`[7]`|
 | Number of distinct values |`1`|
 | 出力 |`NO`|

 この例は、2 番目の個別の値が存在しないという重要なエッジ ケースを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | 個別の値の並べ替えが実行時間を支配します。 
| スペース | O(n) | 設定および並べ替えられたリストには、個別の要素が格納されます。 

と`n ≤ 100`、このソリューションは簡単に制限内に収まります。 かなり遅いアプローチでも快適に通過できます。 

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    n = int(input())
    arr = list(map(int, input().split()))

    distinct = sorted(set(arr))

    if len(distinct) < 2:
        print("NO")
    else:
        print(distinct[1])

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    output = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return output.strip()

# provided sample
assert run("4\n1 2 2 -4\n") == "1", "sample 1"

# minimum size input
assert run("1\n5\n") == "NO", "single element"

# all values equal
assert run("5\n7 7 7 7 7\n") == "NO", "all equal"

# negative numbers
assert run("5\n-10 -5 -10 -3 -5\n") == "-5", "negative values"

# already sorted distinct values
assert run("4\n1 2 3 4\n") == "2", "simple increasing"

# duplicates of minimum
assert run("6\n1 1 1 2 3 4\n") == "2", "duplicate minimum"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1 / 5`|`NO`| 可能な最小配列サイズ |
 |`5 / 7 7 7 7 7`|`NO`| すべての値が同一 |
 |`5 / -10 -5 -10 -3 -5`|`-5`| 負の数の正しい処理 |
 |`4 / 1 2 3 4`|`2`| 基本的な個別増加ケース |
 |`6 / 1 1 1 2 3 4`|`2`| 最小値の重複は無視されます。 

## 特殊なケース

 すべての値が等しい場合を考えてみましょう。```
4
7 7 7 7
```アルゴリズムは配列をセットに変換します。```
{7}
```並べ替え後:```
[7]
```個別の値の数は 1 つだけであるため、アルゴリズムは次のように出力します。```
NO
```厳密に最小値を超える値はないため、これは正しいです。 

ここで、繰り返される最小値を考えてみましょう。```
6
1 1 1 2 3 4
```最小値が複数回表示されます。 重複を削除した後:```
{1, 2, 3, 4}
```並べ替えると次のようになります。```
[1, 2, 3, 4]
```アルゴリズムの出力`2`、これは厳密に次より大きい最小値です。`1`。 元の配列を単純にソートして 2 番目の要素を取得する単純なアプローチでは、誤った結果が返されます。`1`。 

最後に、負の数について考えてみましょう。```
5
-10 -5 -10 -3
```重複を削除して並べ替えた後:```
[-10, -5, -3]
```2 番目の個別の値は次のとおりです。`-5`。 整数の並べ替えは負の値を自然に処理するため、アルゴリズムは正しく機能します。
