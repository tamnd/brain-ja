 ## 解決策
 ## 問題の理解

 各人は正確に他の 1 人を指します。 誰かがニュースを知ったら、その人が指した人に電話し、その人が次の人に電話する、という具合です。 フォームに有向エッジを追加する場合があります`x -> y`、人を意味する`x`も電話しなければなりません`y`。 

この目標は、単に 1 つの開始ノードから接続されたグラフを作成するよりも強力です。 誰が最初にニュースを知ったかに関係なく、成功するためのプロセスが必要です。 つまり、すべてのノードから、最終的には有向パスを介して他のすべてのノードに到達できなければなりません。 

元のグラフは非常に特殊な構造を持っています。すべてのノードの出次数が 1 つだけです。 このようなグラフは関数グラフと呼ばれます。 関数グラフ内のすべての接続コンポーネントには、ちょうど 1 つの有向サイクルが含まれており、ツリーがそのサイクルにフィードされます。 

グラフ全体が強くつながるように、最小限の数の余分なエッジを追加する必要があります。 

バウンド`n ≤ 10^5`二次関数はすぐに除外されます。 たとえ`O(n^2)`すべてのペアにわたる走査は周囲で実行されます`10^10`最悪の場合、制限時間を大幅に超えて操作が行われる可能性があります。 線形または線形に近いアルゴリズムが必要です。 グラフにはすでに正確な値が含まれているため、`n`エッジ、`O(n)`DFS ベースのソリューションが自然なターゲットです。 

素朴な推論を打ち破る可能性のある微妙なケースがいくつかあります。 

次のグラフを考えてみましょう。```
1 -> 2
2 -> 1
3 -> 4
4 -> 3
```入力：```
4
2 1 4 3
```2 つの別々のサイクルがあります。 エッジを 1 つだけ追加すると、次のようになります。`2 -> 3`、十分ではありません。 ノードから開始`4`、ノードに到達することはできません`1`または`2`。 正解するには、サイクルを両方向に接続するために 2 つの追加エッジが必要です。 

もう 1 つの注意が必要な状況は、複数のツリーが同じサイクルにフィードされる場合です。```
1 -> 2
2 -> 3
3 -> 2
4 -> 3
5 -> 3
```入力：```
5
2 3 2 3 3
```不注意な解決策により、リーフ ノードを接続しようとする可能性があります。 これは失敗します。葉は無関係であり、サイクル構造が障害になっているためです。 すべてのパスは最終的に同じサイクルに入ります`{2,3}`したがって、サイクルから木の根に向かって戻るときに必要な追加のエッジは 1 つだけです。 

最も危険なエッジケースは、グラフがすでに 1 つのサイクルを形成している場合です。```
4
2 3 4 1
```グラフはすでに強く結びついています。 正解はゼロです。 多くの実装では、すでに単一の SCC が存在するかどうかを確認するのではなく、コンポーネントをカウントするだけなので、誤って少なくとも 1 つのエッジを追加してしまいます。 

## アプローチ

 強引なアプローチは、任意の強く接続された拡張の観点から考えることです。 すべての強く接続されたコンポーネントを計算し、それらの間にエッジを追加して、グラフ全体が強く接続されるかどうかをテストすることができます。 

すべての変更後にプロパティを直接検証するため、正確性は簡単です。 問題はコストです。 強力な接続テスト自体には時間がかかります`O(n)`、多くの候補エッジが存在する可能性があります。 SCC のすべてのペアを試してみても、すぐに 2 次式になります。 

グラフ構造により、利用できるはるかに強力な特性が得られます。 

すべてのノードの出次数が 1 つだけであるため、すべての連結成分には 1 つの有向サイクルが含まれます。 サイクルの外側にあるノードは、最終的にサイクルに流れ込みます。 各ノードには出力エッジが 1 つしかないため、一度サイクルに入るとそこから出ることはできません。 

この観察により、問題全体が変わります。 

唯一の本当の障害はサイクルそのものです。 1 つのコンポーネント内では、すべてのパスが最終的にそのコンポーネントのサイクルに閉じ込められてしまいます。 あれば`k`異なるサイクルの場合、グラフは次のように分割されます。`k`互いに到達できないシンク領域。 

グラフを強く結び付けるには、これらのサイクルを互いに接続する必要があります。 サイクルは、順方向ではなく逆方向でのみ、サイクルに供給するすべてのツリーにすでに到達できます。 重要なノードは、入力ツリーのルート、特に関数グラフ内の次数 0 のノードです。 それらは他の場所からは到達できない場所です。 

重要な定理は次のとおりです。 

あれば`k`サイクルの場合、追加されるエッジの最小数は次のとおりです。 

-`0`いつ`k = 1`また、indegree-zero ノードはありません。 
- さもないと`max(number_of_cycles, number_of_zero_indegree_nodes)`。 

関数グラフの場合、ゼロ入次ノードの数は常に、アクセスできないすべての領域を接続するために必要な追加エッジの数以下になります。 

標準的な構造はエレガントです:

 - 各サイクルから代表者を 1 名集めます。 
- 次数 0 のすべてのノードを収集します。 
- 循環的に接続します。 

これにより、正確に最小数のエッジが生成されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) 以上 | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 有向グラフを構築し、すべてのノードの入次数を計算します。 

各ノードには出力エッジが 1 つだけあるため、ターゲット配列を保存するだけで十分です。 
2. すべての有向サイクルを検索します。 

DFS を次の 3 つの状態で実行します。 

-`0`訪問されていないことを意味し、
 -`1`現在再帰スタック内にあることを意味します。 
-`2`完全に処理されたことを意味します。 

DFS がすでにマークされているノードに到達したとき`1`、サイクルを見つけました。 そのノードはそのサイクルの代表になります。 
3. 次数 0 のすべてのノードを収集します。 

これらのノードには、独自のツリーの外部からは決してアクセスできません。 強く接続されたグラフでは、すべてのノードが他のすべてのノードから到達可能である必要があるため、そのようなすべてのルートには少なくとも 1 つの入力追加エッジが必要です。 
4. すでに強く接続されているケースを処理します。 

ちょうど 1 つのサイクルがあり、次数ゼロのノードがない場合、グラフはすでに 1 つの有向サイクルです。 出力`0`。 
5. ゼロ度ノードをサイクルに一致させます。 

させて：

-`roots`は次数ゼロのノードであり、
 -`cycles`サイクルの代表者になります。 

エッジを作成することで、すべてのルートが別のコンポーネントから接続を受け取り、すべてのサイクルが発信エスケープ パスを取得します。 
6. 循環接続パターンを構築します。 

次のものがあるとします。```
roots = [r1, r2, ..., rm]
cycles = [c1, c2, ..., ck]
```私たちは接続します:```
c1 -> r2
c2 -> r3
...
ck -> r1
```大きいサイズを法としてインデックスを慎重にラッピングします。 
7. 構築されたすべてのエッジを出力します。 

追加されるエッジの数は次のとおりです`max(k, m)`。 

### なぜ効果があるのか

 関数グラフ内のすべてのパスは最終的にサイクルに入ります。 拡張前は、異なるサイクルは分離されたシンク領域です。 強力な接続には、すべてのサイクルが他のすべてのサイクルから到達可能になることが必要です。 

この構造では、すべてのサイクルが 1 つの有向リングにリンクされます。 パスがいずれかのサイクルに到達すると、追加されたエッジを通って他のすべてのコンポーネントに到達できます。 

Indegree-zero ノードは、正確には、もともと入力パスを持たなかったノードです。 このような各ノードに 1 つの入力追加エッジを与えると、到達不能なエントリ ポイントがすべて削除されます。 

循環構築により次のことが保証されます。 

- すべてのコンポーネントは他のすべてのコンポーネントに到達できます。 
- すべてのルートが受信パスを受け取ります。 
- 不要なエッジは追加されません。 

サイクルごと、および次数ゼロのルートごとに少なくとも 1 つのエッジが必要であるため、下限は次のようになります。`max(k, m)`、そしてその構造はまさにそれを達成しています。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(1 << 25)

n = int(input())
to = [0] + list(map(int, input().split()))

indeg = [0] * (n + 1)

for i in range(1, n + 1):
    indeg[to[i]] += 1

state = [0] * (n + 1)
cycles = []

def dfs(u):
    state[u] = 1

    v = to[u]

    if state[v] == 0:
        dfs(v)
    elif state[v] == 1:
        cycles.append(v)

    state[u] = 2

for i in range(1, n + 1):
    if state[i] == 0:
        dfs(i)

roots = []

for i in range(1, n + 1):
    if indeg[i] == 0:
        roots.append(i)

if len(cycles) == 1 and len(roots) == 0:
    print(0)
    sys.exit()

m = len(roots)
k = len(cycles)

ans = []

t = max(m, k)

for i in range(t):
    a = cycles[i % k]
    b = roots[(i + 1) % m] if m > 0 else cycles[(i + 1) % k]
    ans.append((a, b))

print(len(ans))
for x, y in ans:
    print(x, y)
```DFS は、古典的な再帰スタック方式を使用してサイクルを検出します。 すべてのノードには発信エッジが 1 つだけあるため、各 DFS パスは基本的に線形であり、合計作業量は線形のままです。 

行:```
elif state[v] == 1:
    cycles.append(v)
```重要な瞬間です。 現在の再帰スタック内にすでにノードが存在するということは、有向サイクルが見つかったことを意味します。 構築に必要なのはそれだけであるため、サイクルごとに代表ノードを 1 つだけ保存します。 

indegree 配列は、入力ツリーのルートを識別します。 これらは、現在他の場所からアクセスできないノードです。 

特殊な場合:```
if len(cycles) == 1 and len(roots) == 0:
```とても重要です。 1 つのサイクルを持ち、次数ゼロのノードを持たない関数グラフは、それ自体が 1 つの有向サイクルでなければならず、すでに強く結合されています。 

循環構築ではモジュロ インデックスを使用するため、リストが自然にラップされます。 ルートがない場合は、サイクルを互いに直接接続します。 

よくある間違いは、ルートとルートを接続しようとすることです。 それはサイクルから逃れるのに役立ちません。 永久に到達できることが保証されているのはサイクルのみであるため、エッジはサイクル代表から生じている必要があります。 

## 実用的な例

 ### 例 1

 入力:```
3
3 3 2
```グラフ：```
1 -> 3
2 -> 3
3 -> 2
```サイクルは`{2,3}`。 

| ステップ | サイクル | ルーツ | 追加されたエッジ |
 | --- | --- | --- | --- |
 | DFS後 | [2] | [] | [] |
 | 角度スキャン後 | [2] | [1] | [] |
 | 建設 | [2] | [1] | (2,1) |

 最終出力:```
1
2 1
```今：```
1 -> 3 -> 2 -> 1
```すべてのノードが相互に到達可能になります。 

この例は、indegree-zero ノードが重要である理由を示しています。 ノード`1`サイクルからは到達できないため、入力エッジが必要でした。

 入力:```

```グラフ：```

このトレースは下限を示しています。 2 つの独立したサイクルでは、到達可能性を両方向に機能させるために、少なくとも 2 つの有向エッジが必要です。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各ノードは DFS で 1 回処理され、次数スキャンで 1 回処理されます。 
| スペース | O(n) | グラフ、度数、DFS 状態、および回答ストレージの配列 |

 グラフには正確に次の内容が含まれています`n`エッジがあるため、線形トラバースが最適です。 と`10^5`ノード、`O(n)`ソリューションは時間制限とメモリ制限内に簡単に収まります。 

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    sys.setrecursionlimit(1 << 25)

    n = int(input())
    to = [0] + list(map(int, input().split()))

    indeg = [0] * (n + 1)

    for i in range(1, n + 1):
        indeg[to[i]] += 1

    state = [0] * (n + 1)
    cycles = []

    def dfs(u):
        state[u] = 1

        v = to[u]

        if state[v] == 0:
            dfs(v)
        elif state[v] == 1:
            cycles.append(v)

        state[u] = 2

    for i in range(1, n + 1):
        if state[i] == 0:
            dfs(i)

    roots = []

    for i in range(1, n + 1):
        if indeg[i] == 0:
            roots.append(i)

    if len(cycles) == 1 and len(roots) == 0:
        print(0)
        return

    m = len(roots)
    k = len(cycles)

    ans = []

    t = max(m, k)

    for i in range(t):
        a = cycles[i % k]

        if m > 0:
            b = roots[(i + 1) % m]
        else:
            b = cycles[(i + 1) % k]

        ans.append((a, b))

    print(len(ans))
    for x, y in ans:
        print(x, y)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out

    solve()

    sys.stdout = sys.__stdout__
    return out.getvalue()

# provided sample
assert run("3\n3 3 2\n").startswith("1"), "sample 1"

# already strongly connected cycle
assert run("4\n2 3 4 1\n") == "0\n", "single cycle"

# two disjoint cycles
res = run("4\n2 1 4 3\n")
assert res.startswith("2"), "two cycles"

# tree feeding into cycle
res = run("5\n2 3 2 3 3\n")
assert res.startswith("1"), "one root"

# minimum size
res = run("2\n2 1\n")
assert res == "0\n", "minimum strongly connected"

 |`4 / 2 3 4 1`|`0`| すでに強くつながっています |

 ## 特殊なケース

 2 つの切断されたサイクルを含むグラフをもう一度考えてみましょう。```
4
2 1 4 3
```DFS は 2 つのサイクル代表を検出します。たとえば、`[1,3]`。 すべてのノードにはすでに 1 つの入力エッジがあるため、indegree-zero ノードは存在しません。 

アルゴリズムは`m == 0`サイクルを分岐して直接接続します。```
1 -> 3
3 -> 1
```これで、パスは 2 つの元の SCC 間を両方向に移動できるようになります。 

次に、1 サイクルだが到達できないツリー ルートを持つグラフを考えてみましょう。```
5
2 3 2 3 3
```度数は次のとおりです。```
1: 0
2: 2
3: 3
4: 0
5: 0
```ルーツは`[1,4,5]`。 たとえば、サイクルの代表者は 1 人だけです。`[2]`。 

アルゴリズムは以下を追加します。```
2 -> 4
2 -> 5
2 -> 1
```すべてのルートにはサイクルからの入力パスがあり、すべてのノードは最終的に元のエッジを通ってサイクルに戻ることができます。 

最後に、すでに正しいケースを考えてみましょう。```
4
2 3 4 1
```サイクルは 1 つあり、次数ゼロのノードはありません。 アルゴリズムはすぐにゼロを出力します。 

このチェックを行わないと、多くの実装では誤って冗長エッジが追加され、最小性が損なわれてしまいます。
