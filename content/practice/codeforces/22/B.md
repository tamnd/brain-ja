 ## 解決策
 ## 問題の理解

 オフィスフロアは次のように表されます。`n × m`グリッド。 各セルは自由であるか、次のように記述されます。`0`、または家具でブロックされている、と書かれています。`1`。 側面がグリッドに沿った位置にある長方形のテーブルを 1 つ配置したいと考えています。 長方形で覆われたすべてのセルは空いている必要があります。 

目標は面積を最大化することではありません。 周囲長が最大の長方形が必要です。 高さのある長方形の場合`h`と幅`w`、周長は次のとおりです。$$2(h + w)$$出力は、すべて有効な長方形の中で可能な最大の周囲長です。 

この制約は、いくつかのアプローチが実行可能なほど十分に小さいですが、それでも不注意な強引な行為を罰するのに十分な大きさです。 両方なので`n`そして`m`せいぜい`25`、グリッドには最大でも次のものが含まれます`625`細胞。 考えられるすべての長方形を列挙するには、すでに大まかに次の作業が必要です。$$25^2 \times 25^2 = 390625$$候補となる四角形は管理可能です。 この問題は、各四角形内のすべてのセルをスキャンして、ゼロのみが含まれていることを確認すると発生します。 最悪の場合、各四角形には最大で次のものが含まれる可能性があります。`625`セル、おおよそ次のような結果になります。$$390625 \times 625 \approx 2.4 \times 10^8$$Python では操作が不必要に重くなります。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

単一の空きセルでも有効な答えが得られるはずです。 例えば：```
1 1
0
```寸法を持つ唯一の長方形`1 × 1`したがって、周長は次のようになります。`4`。 

不用意に実装すると、誤って返される可能性があります`0`これは、長方形の幅と高さが 1 つのセルを超える正の値を持つ必要があると想定しているためです。 

もう 1 つの注意が必要な状況は、空きセルは存在するが、より大きな四角形を形成できない場合です。```
2 2
01
11
```答えはまだです`4`左上のセルだけで有効なテーブルが形成されるためです。 

グリッドの境界線に接触する長方形も、一般的に 1 つずつずれたミスを引き起こします。 考慮する：```
2 3
000
000
```最適な長方形は、周囲を含めてグリッド全体に広がります。$$2(2 + 3) = 10$$プレフィックス合計または境界配列を使用した実装では、誤って最後の行または列が除外されることがよくあります。 

より微妙なケースは、大きな四角形にブロックされたセルが 1 つだけ含まれる場合です。```
3 3
000
010
000
```中央に障害物があるため、グリッド全体が無効になります。 最も有効な長方形は次のとおりです`2 × 2`長方形、周囲あり`8`。 内部全体ではなく境界線のみをチェックするアルゴリズムは、誤った結果を返します。`12`。 

## アプローチ

 最も直接的な解決策は、考えられるすべての長方形を列挙することです。 長方形は、上行、下行、左列、右列によって決まります。 各候補について、その内部のすべてのセルをスキャンし、すべてのセルが空いていることを確認します。 

すべての有効な四角形が明示的にチェックされるため、この強引な方法は正しいです。 何も見逃されることはなく、有効な長方形が表示されるたびに最適な周囲長が更新されます。 

ボトルネックはスキャンの繰り返しによって発生します。 くらいあります`O(n^2 m^2)`長方形、および 1 つの長方形の検証にはコストがかかる場合があります`O(nm)`時間。 完全な複雑さは次のようになります。$$O(n^3 m^3)$$最大のグリッドでは、数億の操作に達します。 

重要な点は、四角形の列挙自体ではなく、四角形の検証が高価な部分であるということです。 長方形にブロックされたセルが含まれているかどうかを一定時間内にテストできれば、ソリューションはすぐに十分な速度になります。 

これはまさに 2D プレフィックス合計が提供するものです。 

各セルがサブ四角形内に表示されるブロックされたセルの数を格納する行列を構築します。`(0,0)`に`(i,j)`。 この前処理が完了すると、四角形内のブロックされたセルの数を次のコマンドでクエリできるようになります。`O(1)`包含/除外を使用する時間。 

アルゴリズムは次のようになります。 

1. すべての長方形を列挙します。 
2. 含まれるブロックされたセルの数をクエリします。 
3. カウントがゼロの場合は、長方形の周囲を使用して答えを更新します。 

列挙には依然としてコストがかかります`O(n^2 m^2)`ですが、四角形の検証は定数時間になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n3m3) | お(1) | 遅すぎる |
 | 最適 | O(n²m²) | O(nm) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. グリッドを読み取り、空きセルが次のようになる数値行列に変換します。`0`そしてブロックされた細胞は`1`。 

セルが四角形をブロックするかどうかのみを考慮するため、整数を格納すると後の計算が簡素化されます。 
2. Build a 2D prefix sum array.

 させて`pref[i][j]`長方形内のブロックされたセルの数を表します。`(1,1)`に`(i,j)`1 から始まるインデックスを使用します。 

移行は次のとおりです。$$pref[i][j] = pref[i-1][j] + pref[i][j-1] - pref[i-1][j-1] + grid[i][j]$$これにより、一定時間内でサブレクタングルの合計クエリが可能になります。 
3. 考えられる最上位行と最下位行をすべて列挙します。 

すべての長方形は、最初にその垂直境界を選択する必要があります。 
4. 行のペアごとに、考えられる左右の列をすべて列挙します。 

この時点で、正確に 1 つの長方形が固定されます。 
5. プレフィックスの合計を使用して、四角形内のブロックされたセルの数をクエリします。 

長方形の場合`(r1,c1)`に`(r2,c2)`:$$blocked = pref[r2][c2] - pref[r1-1][c2] - pref[r2][c1-1] + pref[r1-1][c1-1]$$6. 長方形にブロックされたセルが含まれていない場合は、その周囲長を計算します。 

寸法は次のとおりです。$$h = r2 - r1 + 1$$

$$w = c2 - c1 + 1$$したがって、周囲は次のようになります。$$2(h+w)$$7. すべての有効な長方形の最大周囲長を追跡します。 

### なぜ効果があるのか

 プレフィックス合計行列により、すべての四角形クエリがその領域内のブロックされたセルの正確な数を返すことが保証されます。 長方形は、この値がゼロに等しい場合にのみ有効です。 

このアルゴリズムでは、考えられるすべての四角形が 1 回だけ列挙されるため、すべての有効なテーブル配置が考慮されます。 答えはすべての有効な長方形の中で最大の周囲長で更新されるため、最終結果は最適になる必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    grid = [input().strip() for _ in range(n)]

    pref = [[0] * (m + 1) for _ in range(n + 1)]

    for i in range(1, n + 1):
        for j in range(1, m + 1):
            val = 1 if grid[i - 1][j - 1] == '1' else 0

            pref[i][j] = (
                pref[i - 1][j]
                + pref[i][j - 1]
                - pref[i - 1][j - 1]
                + val
            )

    ans = 0

    for r1 in range(1, n + 1):
        for r2 in range(r1, n + 1):
            for c1 in range(1, m + 1):
                for c2 in range(c1, m + 1):

                    blocked = (
                        pref[r2][c2]
                        - pref[r1 - 1][c2]
                        - pref[r2][c1 - 1]
                        + pref[r1 - 1][c1 - 1]
                    )

                    if blocked == 0:
                        h = r2 - r1 + 1
                        w = c2 - c1 + 1
                        ans = max(ans, 2 * (h + w))

    print(ans)

solve()
```最初のセクションではグリッドを読み取り、プレフィックス合計行列を構築します。 1 から始まるインデックスの使用`pref`ほぼすべての境界の特殊なケースを削除します。 このトリックがなければ、上または左の境界線に触れるクエリには条件付きロジックが必要になります。 

四角形の列挙では 4 つのネストされたループが使用されます。 制約はあくまで`25 × 25`、これは完全に安全です。 高価な部分は列挙自体ではなく、四角形を効率的に検証することです。 

包含/除外式は、実装の中で最もデリケートな部分です。 減算の順序は重要です。```
A - B - C + D
```どこ`D`2 回減算されたオーバーラップを復元します。 

高さと幅の計算には両方とも次の値が使用されます。`+1`長方形の境界が含まれるためです。 これを忘れると、単一行または単一列の長方形の周囲が不正確になります。 

答えは次から始まります`0`ただし、この問題では少なくとも 1 つの空きセルが保証されているため、有効な四角形が常に存在し、最終的な答えは少なくとも次のようになります。`4`。
