 ## 問題の理解

 私たちは、各サーバーがノードであり、2 つのサーバー間の各接続が無向エッジであるサーバーのネットワークを設計するように求められています。 がある`n`サーバーと私たちは正確に許可されています`m`接続。 インデックス付きの 1 つの特定のサーバー`v`、ネットワークにとって重要である必要があります。失敗するか削除された場合、ネットワークは切断される必要があります。 出力では、有効なセットを記述する必要があります。`m`これらの条件を満たす接続、または`-1`それが不可能な場合。 

制約が私たちに与えるのは、`n`最大 10^5 および`m`最大 10^5。 これは、n または m の二次関数は制限時間を超えるため、どのような解もおよそ O(n + m) または O(m log n) 時間で実行する必要があることを意味します。 メモリ使用量も n または m において線形のままでなければならないため、最大の入力に対して密な隣接行列を保存することはできません。 

エッジケースは制約から自然に発生します。 たとえば、次の場合`m`よりも小さいです`n-1`、すべてのサーバーに接続することは不可能です。`n`ノードには少なくとも必要です`n-1`エッジ。 次の場合には、別の厄介なシナリオが発生します。`m`まさに`n-1`: ネットワークはツリーを形成するため、サーバーが`v`葉ではありません。 それ以外の場合、削除してもネットワークは切断されません。 もし`m`非常に大きく、最大で`n*(n-1)/2`、課題は接続を選択することになります。`v`を超えない範囲で切断頂点を維持します`m`エッジ。 

## アプローチ

 ブルートフォースアプローチを説明するのは簡単です。 可能なすべてのセットを生成します`m`間の接続`n`ノードを削除するかどうかをそれぞれ確認します。`v`ネットワークを切断します。 チェック自体は、BFS または DFS を使用して、他のノードから実行できます。`v`他のすべてのノードが到達可能であることを確認します。 これは正しいですが、可能なエッジ セットの数は組み合わせによって決まります。`C(n*(n-1)/2, m)`これは、n = 10^5 の場合、天文学的に大きくなります。 このアプローチはすぐに失敗します。 

重要な洞察は、グラフ理論を理解することから得られます。 サーバーが必要です`v`**関節点**、つまり頂点を削除すると接続されたコンポーネントの数が増加します。 これを保証する最も単純な構造は次のとおりです。`v`「星のような」構造の中心: 接続`v`他の一部またはすべてのノードに接続し、必要に応じて残りのノード間に接続を追加します。`m`エッジ。 確認する条件は次のとおりです。 

1.`m >= n-1`接続を保証します。 
2.`m <= (n-1) + ((n-1)*(n-2)/2)`せいぜい`(n-1)*(n-2)/2`ノード間のエッジを除く`v`、プラス`n-1`接続するエッジ`v`他のすべてのノードに送信します。 

この観察により、問題は建設的なものに帰着します。 すべてのグラフをチェックする代わりに、**有効なグラフを直接構築**して、`v`はカット頂点であり、エッジの数が一致します`m`。

 ## アルゴリズムのチュートリアル

 1.次のことを確認します`m`よりも小さいです`n-1`または指定された最大可能エッジよりも大きい`v`カット頂点として。 どちらかが true の場合、出力`-1`。 
2. サーバーに接続する`v`1 つのサーバー (それを呼び出します)`u1`) 残りをすべて接続します`n-2`サーバーから`u1`直接ではなく`v`。 これにより、`v`接続するために必要です`u1`残りへ。 これは微妙な点です。`v`はすべてのノードに直接接続されているため、後でアーティキュレーション プロパティを失うことなく追加のエッジを安全に追加できます。 
3. 間にエッジを追加します`v`まで、必要なだけ他のノードを追加します。`v`に接続されています`n-1`ノード。 これにより、削除が保証されます。`v`少なくとも 1 つのノードを残りのノードから切断します。 
4. もし`m`これまでに追加したエッジよりもまだ大きいため、他のエッジの間にエッジを追加してください`n-1`まで任意にノードを追加`m`端に達しました。 すべてのペアを反復処理できます`(i, j)`どこ`i != v`そして`j != v`カウントが満たされるまでエッジを追加します。 
5. エッジのリストを出力します。 

機能する理由: 接続することで`v`少なくとも 1 つのノードに接続し、すべてのノードが経由で接続されていることを確認します。`v`最初は、`v`がアーティキュレーションポイントになります。 他のノード間の余分なエッジは、次の条件を満たす限り、このプロパティを削除しません。`v`ネットワークの一部への唯一の接続が経由であるネイバーが少なくとも 1 つあります。`v`。 エッジ数は一致することが保証されています`m`問題の制約を尊重しながら構築します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m, v = map(int, input().split())

min_edges = n - 1
max_edges = (n - 1) + (n - 2) * (n - 1) // 2

if m < min_edges or m > max_edges:
    print(-1)
    sys.exit()

edges = []

# connect v to one node
v_node = v
other_nodes = [i for i in range(1, n + 1) if i != v_node]

# Step 1: ensure v is connected to at least one node
edges.append((v_node, other_nodes[0]))
added_edges = 1

# Step 2: connect the rest to v to satisfy articulation
for node in other_nodes[1:]:
    if added_edges < m and len(edges) < n-1:
        edges.append((v_node, node))
        added_edges += 1

# Step 3: add edges among remaining nodes until reaching m
for i in range(len(other_nodes)):
    for j in range(i + 1, len(other_nodes)):
        if added_edges >= m:
            break
        edges.append((other_nodes[i], other_nodes[j]))
        added_edges += 1
    if added_edges >= m:
        break

for a, b in edges:
    print(a, b)
```このソリューションでは、まず次のことが保証されます。`v`プライマリ ノードに直接接続することで頂点をカットします。 次に、残りのエッジを徐々に構築します。`m`。 接続しないように注意する`v`残りのノードが間接的に接続され、アーティキュレーション プロパティが維持されるまで、必要以上のノードに接続します。
