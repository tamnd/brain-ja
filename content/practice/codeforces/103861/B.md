 ## 解決策
 ## 問題の理解

 数字列が与えられ、そのすべての部分文字列を考慮するように求められます。 各部分文字列について、正確に 6 つの連続する空でない部分に分割する方法を検討します。 最初、2 番目、および 5 番目の部分が同一の文字列であり、3 番目と 6 番目の部分も同一の文字列であり、4 番目の部分が制限されていない場合、分割は有効であると見なされます。 

各部分文字列について、このような有効な 6 つの部分に分割された部分がいくつ存在するかを数えます。この数は、その部分文字列の「美しさ」と呼ばれます。 最後のタスクは、入力文字列のすべての部分文字列にわたってこの美しさの値を合計することです。 

したがって、問題は 1 つの文字列内のパターンをカウントするだけではなく、すべての部分文字列間隔にわたるカウントを集計することであり、各間隔自体で複数の内部パーティション構成が可能になります。 

この制約により、テスト ケースごとに最大 5000 文字、合計の長さは最大 30000 文字が許可されます。これにより、部分文字列を列挙し、すべてのパーティションを個別に再チェックしようとするソリューションは即座に除外されます。 すべての部分文字列を調べてから各部分文字列内のすべての分割点を試す単純なアプローチでは、三次またはさらに悪い動作が発生し、非常に遅すぎます。 

さらに微妙な問題は、パーティションが部分文字列間で重なり合うことです。 繰り返されるセグメントの固定一致は、一度に多くの部分文字列に寄与する可能性があります。 正しいソリューションでは、部分文字列ごとにパターン一致を最初から再計算するのではなく、計算を再利用する必要があります。 

強調する価値のある小さなエッジケースは、すべての文字が区別できる場合です。 この場合、反復セグメントの等価性は発生しないため、答えはゼロになります。 もう 1 つは、文字列が一定の場合です。この場合、繰り返されるセグメントの等価性が多くなり、単純なカウントでは、異なる部分文字列間で寄与が重複するため、簡単にカウントを超えてしまう可能性があります。 

## アプローチ

 ブルートフォース解釈は簡単です。 すべての部分文字列について$t[l..r]$、5 つのカット位置を選択し、6 つのパーツを形成するためにあらゆる方法を試します。 このような分割ごとに、次のことを確認します。$s_1 = s_2 = s_5$そして$s_3 = s_6$。 各チェックには部分文字列の比較が含まれるため、セグメントの長さに対して直線的な時間がかかる場合があります。 

ハッシュを使用して部分文字列の比較が最適化されている場合でも、ある長さの部分文字列内の 5 つのカット位置を選択する方法の数は$m$は$O(m^5)$、そして、あります$O(n^2)$部分文字列。 これにより、ブルートフォースはすでに実行不可能になります。$n = 5000$。 

重要な観察は、有効なパーティションの構造が、繰り返されるブロックのエンドポイントを選択することによってほぼ完全に決定されるということです。 最初に出現する位置を修正したら、$s_1$そして2ブロック目$s_3$、パーティションの残りの部分は等式によって強制されます。 言い換えれば、6 つのセグメントの観点から考える代わりに、2 つのパターン ブロックの観点から考えることができます。1 つは 3 回繰り返され、もう 1 つは 2 回繰り返され、間に自由な区切り文字が入ります。 

これにより、問題は、固定オフセットを持つ一致する部分文字列のペアの出現をカウントし、考えられるすべての部分文字列境界にわたるそれらの寄与を集計することに変換されます。 これは、部分文字列の同等性を事前に計算し、考えられるセグメントの長さと開始位置をスイープすることによって自然に処理されます。 

これを効率的に行う標準的な方法は、繰り返されるブロックの長さを固定することです。 繰り返されるブロックの長さを仮定します$a = |s_1| = |s_2| = |s_5|$そして 2 番目に繰り返されるブロック$b = |s_3| = |s_6|$。 次に、有効な各構造は開始インデックスの選択に対応します。$i$そして、部分文字列にパターンがあることを確認します。$a, a, b, x, a, b$、

 これは、固定オフセットで部分文字列の等価性をチェックすることになります。$i$。 

次に、ペアごとにカウントします$(a, b)$、いくつのポジション$i$満足する：$t[i:i+a] = t[i+a:i+2a] = t[i+3a+b:i+3a+b+a]$そして$t[i+2a:i+2a+b] = t[i+3a:i+3a+b]$。 

これは部分文字列等価クエリの問題になります。ローリング ハッシュを使用して定数時間で応答し、有効なすべてのクエリを合計することができます。$(a, b, i)$。 

最後の最適化は、列挙を制限することです。開始インデックスごとに、次のことだけを考慮します。$a$そして$b$完全な構造が文字列に収まるようにします。 これにより、$O(n^2)$定数時間チェックを伴う列挙。

 ## アルゴリズムのチュートリアル

 ローリング ハッシュ前処理を使用して、高速な部分文字列の等価性チェックを可能にします。 

1. 文字列全体のプレフィックス ハッシュと基数の累乗を事前計算します。 これにより、任意の 2 つの部分文字列を定数時間で比較できるようになります。 これが不可欠な理由は、すべての有効な構成は複数の部分文字列の同等性のみに依存しており、直接比較を繰り返すと実行時間が大きく左右されるためです。 
2. 開始インデックスを修正する$i$最初のセグメントの始まりとして機能します$s_1$。 すべての有効なパーティションはそのような位置に固定されているため、すべてのパーティションを反復処理します。$i$完全性を保証します。 
3. それぞれについて$i$、可能な長さにわたって反復します$a$繰り返されるブロックの$s_1, s_2, s_5$。 制約というのは、$i + 2a$2 番目のブロックが始まる前に、このブロック構造のコピーが少なくとも 3 つ必要なので、まだ境界内にある必要があります。 
4. 選択したそれぞれについて$a$、可能な長さにわたって反復します$b$2 番目に繰り返されるブロックの場合$s_3, s_6$。 構造全体の長さを確保します。$3a + 2b + 1$（無料区間を含む）$s_4$) は文字列内に収まります。 
5. 各トリプルについて$(i, a, b)$、ハッシュ比較を使用して等価条件を検証します。まず、3 つの条件が一致していることを確認します。$a$-length セグメントが等しい場合は、2 つのセグメントが等しいことを確認します。$b$-長さのセグメントは等しい。 各チェックは前処理により一定時間になります。 
6. 両方の条件が当てはまる場合、グローバル応答を 1 ずつ増分します。各有効な構成は、正確に 1 つの部分文字列の 1 つの有効なパーティションに正確に対応するため、それ以上の調整は必要ありません。 

### なぜ効果があるのか

 このアルゴリズムは、開始点とブロック長の可能な選択肢をすべて列挙し、それぞれの選択肢について、有効なパーティションを定義する制約を正確にチェックします。 すべての有効なパーティションは開始インデックスとブロック サイズによって一意に決定されるため、$a$そして$b$、有効なパーティションとカウントされる構成の間には 1 対 1 のマッピングがあります。 ハッシュ ステップにより、曖昧さのない等価性チェックの正確性が保証され、境界ループにより、すべての実行可能な構成が 1 回だけアクセスされることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)
    if n < 6:
        print(0)
        return

    base = 91138233
    mod = (1 << 61) - 1

    pref = [0] * (n + 1)
    power = [1] * (n + 1)

    for i in range(n):
        pref[i + 1] = (pref[i] * base + (ord(s[i]) - 48)) & mod
        power[i + 1] = (power[i] * base) & mod

    def get_hash(l, r):
        return (pref[r] - (pref[l] * power[r - l]) & mod) & mod

    ans = 0

    for i in range(n):
        max_a = (n - i) // 3
        for a in range(1, max_a + 1):
            # need space for 3a + at least 2b + 1
            max_b = (n - i - 3 * a) // 2
            if max_b <= 0:
                break
            h1 = get_hash(i, i + a)
            h2 = get_hash(i + a, i + 2 * a)
            h3 = get_hash(i + 3 * a, i + 3 * a + a)
            if not (h1 == h2 == h3):
                continue

            for b in range(1, max_b + 1):
                h4 = get_hash(i + 2 * a, i + 2 * a + b)
                h5 = get_hash(i + 3 * a, i + 3 * a + b)
                if h4 == h5:
                    ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```この実装はプレフィックス ハッシュに依存して、部分文字列の比較を定数時間に短縮します。 外側のループは開始インデックスを修正し、最初の内側のループは繰り返されるブロックの長さを修正します。$a$。 3人になったら$a$- セグメントは等しいことが検証され、スキャンのみが行われます$b$2 つの等しいことを確認しながら$b$-セグメント。 

微妙な詳細はチェックの順序です。最初に 3 つの条件を含む、より制限的な条件を検証します。$a$-反復前のセグメント$b$。 これにより、構造がすでに無効になっている場合に、不必要な内部ループの作業が回避されます。 もう 1 つの重要な点は、慎重な境界管理です。$3a$そして$3a + 2b$文字列の範囲内にとどまる必要があります。

 ## 特殊なケース

 重要なエッジ ケースは、文字列の長さがちょうど 6 の場合です。この場合、有効な構成ごとに可能なパーティション構造は 1 つだけです。 すべてのループが制限しているため、アルゴリズムはこれを正しく処理します。$a \ge 1$、$b \ge 1$、文字列境界を越えるオーバーフローを自動的に防ぎます。 

もう 1 つの特殊なケースは、同一の文字が長く続く文字列です。 ここでは、隣接するインデックスから始まる多くの重複するパーティションが存在しますが、アルゴリズムはすべての有効な開始位置に固定され、構成をマージしないため、それぞれは独立してカウントされます。 

最後のエッジケースは、有効な 3 つの等価性が存在しない場合です。$s_1, s_2, s_5$存在します。 そのような状況では、アルゴリズムは早い段階で枝刈りを行います。$a$-レベルを上げて不要なものを避ける$b$-完全に反復し、正確性と効率性を同時に確保します。
