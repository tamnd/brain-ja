 ## 解決策
 ## 問題の理解

 ノード 1 をルートとするルート付きツリーが与えられます。 このツリーに対して深さ優先検索が実行されます。唯一の制約は、各ノードが任意の順序でその子にアクセスできることです。 DFS は常に事前順序形式で動作します。つまり、ノードが入力されると最初に記録され、次にその子が再帰的に探索されます。 

子の順序はすべてのノードで自由に変更できるため、すべてのノードの最終的な訪問順序は一意ではありません。 代わりに、子をローカルに配置する方法の選択に応じて、多くの可能な DFS 事前注文シーケンスが存在します。 

すべてのノードについて、ツリー全体の有効な DFS 事前順序にそのノードが現れる可能性のある最も早い位置と最も遅い位置を知りたいと考えています。 

したがって、各ノードの出力は、グローバルな訪問順序で占有することができる最小インデックスと最大インデックスを表す整数のペアになります。 

制約は大きく、すべてのテスト ケースにわたるノードの合計数は 100 万に達する可能性があります。 これにより、多くの順列に対して DFS を明示的にシミュレートしたり、ノードごとにサブツリーの順序を再計算したりするアプローチは除外されます。 どのソリューションも、テスト ケースごとのツリーのサイズが線形である必要があります。 

よくある失敗例は、固定の DFS 順序を想定している場合です。 たとえば、ノード 1 に子 2 と 3 がある場合、ノード 3 は 1 の直後、またはサブツリー 2 を完全に探索した後にのみ表示される可能性があります。どちらも有効であり、この変動性はツリーの下方に伝播します。 

もう 1 つの微妙な問題は、サブツリー間隔が固定されていると仮定していることです。 順序が固定された標準の DFS では、各サブツリーは連続したセグメントに対応します。 ここでは、セグメントは存在しますが、他のサブツリーに対する相対的な位置は変化するため、兄弟サブツリー間の相対的な順序のみが柔軟です。 

## アプローチ

 単純なアイデアは、すべてのノードで子のすべての順列を試し、生成されたすべての走査にわたって各ノードの位置を記録することによって、考えられるすべての DFS 順序を生成することです。 これは、有効な DFS 順序をすべて調査するため、概念的には正しいです。 ただし、これは組み合わせ的に爆発します。ノードの次数が d の場合、ノードは d! に寄与します。 局所的に順列が変化し、これらの選択肢はツリー全体で増殖します。 バランスの取れたバイナリ ツリーであっても、すでに指数関数的な数のグローバル DFS オーダーが生成されており、列挙が不可能になっています。 

重要な観察は、完全な順序は必要なく、位置の境界だけが必要であるということです。 プリオーダー DFS では、ノードの位置は、その前に表示されるノードの数によって完全に決まります。 これらのノードは、ルート パス上の祖先と、ノード自体のブランチの前にアクセスされる兄弟のサブツリーという 2 つのソースから取得されます。 

重要な構造上の事実は、各サブツリーのサイズが固定されており、唯一の自由は兄弟サブツリーをノードに至るパスの前または後に配置することだけであるということです。 これは、すべての祖先について、ノードの位置への寄与は、パス上のどの子が選択されるか、およびその周りに残りの子をどのように順序付けるかによってのみ依存することを意味します。 

これから、1 つの DFS でサブツリーのサイズを計算できます。 次に、2 回目のトラバーサルを使用して最小位置と最大位置を計算します。 親 p を持つノード v の場合、p から v への遷移はローカルです。考慮する必要があるのは、p の他のサブツリー内のノードの数を v の前に配置できるかだけです。 

これにより、ツリー上の単純な DP が得られます。 最小位置は、すべての祖先がパスの子を最初に配置するときに発生するため、ノードに到達する前に兄弟サブツリーを訪問することはありません。 最大の位置は、すべての祖先がパスの子を最後に配置するときに発生するため、すべての兄弟サブツリーは下降する前に使い果たされます。

 ## アルゴリズムのチュートリアル

ツリーをノード 1 にルートし、サブツリーのサイズと親の関係という 2 つの標準的な情報を計算します。 次に、最小および最大の DFS 位置をルートから下に伝播します。 

1. ルートから DFS を計算して決定します。`parent[v]`、`depth[v]`、 そして`subtree_size[v]`。 すべての位置効果はサブツリーのサイズに依存するため、この手順が必要です。 
2. ノードの最小可能位置をツリー内の深さとして定義し、ルートを深さ 1 にします。その理由は、DFS が各ステップでターゲット パスをすぐにたどることができ、最初にサイド サブツリーを探索することがないように常に子を配置できるためです。 
3. ルートは常に最初にアクセスされるため、ルートの最大位置を 1 として初期化します。 
4. ツリーを根元から横断します。 親からの各エッジに対して`p`子供に`v`のサブツリーを配置するときに、どの程度の追加寄与が得られるかを計算します。`v`～の子供たちの中で最後に`p`。 入力する前に表示される追加のノード`v`正確に、他の子サブツリー内のすべてのノードです。`p`に等しい`subtree_size[p] - 1 - subtree_size[v]`。 
5.セット`max[v] = max[p] + (subtree_size[p] - 1 - subtree_size[v])`。 

これにより、すべての祖先からの貢献が蓄積されます。`max[p]`すでに上記のすべてが含まれています`p`。 
6. 出力`(min[v], max[v])`各ノードごとに。 

### なぜ効果があるのか

 重要な不変条件は次のとおりです`max[v]`訪問する前に表示できるノードの最大数を表します`v`すべての DFS 予約注文で。 親から子に移動する場合、強制的に実行できるのは新しいノードのみです。`v`は、親の兄弟サブツリー内のノードです。 これらのサブツリーは互いに素であり、サブツリーのサイズによって完全に考慮されるため、それらの寄与はルートからノードへのパスに沿って独立して追加されます。 各ステップはローカルのサブツリー構造と親の累積最大値のみに依存するため、再帰により二重にカウントすることなくグローバル最大値が正しく構築されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    n = int(input())
    g = [[] for _ in range(n + 1)]
    
    for _ in range(n - 1):
        x, y = map(int, input().split())
        g[x].append(y)
        g[y].append(x)

    parent = [0] * (n + 1)
    depth = [0] * (n + 1)
    sz = [0] * (n + 1)

    order = []

    def dfs(u, p):
        parent[u] = p
        sz[u] = 1
        for v in g[u]:
            if v == p:
                continue
            depth[v] = depth[u] + 1
            dfs(v, u)
            sz[u] += sz[v]

    dfs(1, 0)

    max_pos = [0] * (n + 1)
    max_pos[1] = 1

    from collections import deque
    q = deque([1])

    while q:
        u = q.popleft()
        for v in g[u]:
            if v == parent[u]:
                continue
            max_pos[v] = max_pos[u] + (sz[u] - 1 - sz[v])
            q.append(v)

    for i in range(1, n + 1):
        print(depth[i] + 1, max_pos[i])

def main():
    t = int(input())
    for _ in range(t):
        solve()

if __name__ == "__main__":
    main()
```このソリューションでは、計算をサブツリー サイズに関する最初の DFS と、最大位置を伝播するための 2 番目の走査に分割します。 ルート パス上の各エッジは 1 回の避けられない訪問に寄与するため、深さ配列は可能な最小位置を直接エンコードします。 

BFS スタイルの最大値の伝播は親子反復に依存しており、各ノードが 1 回処理されることが保証され、複雑さが線形に保たれます。 

## 実用的な例

 ### 例 1

 1 が 2 に接続され、3 に接続されたという単純なチェーンを考えてみましょう。 

| ノード | 親 | サブツリーのサイズ | 深さ | 分 | マックス |
 | --- | --- | --- | --- | --- | --- |
 | 1 | - | 3 | 0 | 1 | 1 |
 | 2 | 1 | 2 | 1 | 2 | 2 |
 | 3 | 2 | 1 | 2 | 3 | 3 |

 分岐が存在しないため、トラバースは固定され、すべての順序が一致します。 兄弟サブツリーがないため、最大の式では各ステップでゼロが加算されます。 

### 例 2

 ツリー: 1 には子 2 と 3 があり、ノード 2 には子 4 があります。 

サブツリーのサイズは次のとおりです。`sz(4)=1`、`sz(2)=2`、`sz(3)=1`、`sz(1)=4`。 

| ノード | 深さ | 分 | マックス |
 | --- | --- | --- | --- |
 | 1 | 0 | 1 | 1 |
 | 2 | 1 | 2 | 3 |
 | 3 | 1 | 2 | 4 |
 | 4 | 2 | 3 | 3 |

 ノード 3 の場合、サブツリー 2 を 3 の前に配置するとノード {2,4} が最初に表示され、その位置が大幅に増加するため、最大値は大きくなります。 

これらの例では、min は深さのみに依存し、max はノードのパスの前にスケジュールできる兄弟サブツリーの数に依存することが確認できます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque

    def solve():
        n = int(input())
        g = [[] for _ in range(n + 1)]
        for _ in range(n - 1):
            x, y = map(int, input().split())
            g[x].append(y)
            g[y].append(x)

        parent = [0] * (n + 1)
        depth = [0] * (n + 1)
        sz = [0] * (n + 1)

        sys.setrecursionlimit(10**7)

        def dfs(u, p):
            parent[u] = p
            sz[u] = 1
            for v in g[u]:
                if v == p:
                    continue
                depth[v] = depth[u] + 1
                dfs(v, u)
                sz[u] += sz[v]

        dfs(1, 0)

        max_pos = [0] * (n + 1)
        max_pos[1] = 1
        q = deque([1])

        while q:
            u = q.popleft()
            for v in g[u]:
                if v == parent[u]:
                    continue
                max_pos[v] = max_pos[u] + (sz[u] - 1 - sz[v])
                q.append(v)

        out = []
        for i in range(1, n + 1):
            out.append(f"{depth[i] + 1} {max_pos[i]}")
        return "\n".join(out)

    return solve()

 ## 特殊なケース

 最初のエッジ ケースは、完全に線形のツリーです。 この状況では、兄弟サブツリーがまったく存在しないため、再帰によって余分な寄与が追加されることはありません。 アルゴリズムはこれを自然に処理します。`subtree_size[u] - 1 - subtree_size[v]`は常にゼロです。 

2 番目のエッジ ケースは、ルートに多くの子がある星形のツリーです。 ここでは、他のすべてのサブツリーをその前に配置できるため、各子の最大位置が大きくなります。 この式は兄弟の完全なサブツリー サイズを正しく累積し、最小位置と最大位置の間に大きな分離を生成します。 

3 番目のエッジ ケースは、底部付近に 1 つの分岐ノードがある深いチェーンです。 その分岐ノードのみが非ゼロの兄弟合計に寄与し、伝播により、この効果が重複することなく子孫に正しくカスケードされることが保証されます。
