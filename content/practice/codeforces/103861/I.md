 ## 解決策
 ## 問題の理解

 いくつかの独立したテスト ケースが与えられています。 各テスト ケースには整数の配列があり、位置のペアが何組あるかを数える必要があります。$(i, j)$と$i < j$選択した要素の乗算と加算を含む特定の不等式を満たします。 

値のペアの場合$x = a_i$そして$y = a_j$、条件は次のとおりです。$$x \cdot y < x + y$$配列ごとに、この不等式が成り立つ順序のない要素のペアがいくつあるかを数えることを実質的に求められます。 

条件を書き換えることは、最初の有用なステップです。 すべてを片側に移動します。$$xy - x - y < 0$$1を追加:$$(x - 1)(y - 1) < 1$$この形式は元の表現よりもはるかに構造化されており、以降のすべての鍵となります。 

入力サイズは合計で大きくなり、$n$テストケース全体で最大$10^6$。 それはあらゆることを排除します$O(n^2)$サイズが単一の密なテスト ケースであっても、テスト ケースごとにすぐにアプローチできるため、$10^5$すでに暗示しているだろう$10^{10}$ペアチェック。 

テスト ケースごとに線形または線形のソリューションが必要です。 総入力サイズが大きいため、$O(n \log n)$慎重に実装され、要素ごとに過度に繰り返されない場合にのみ許容されます。 

素朴な推論を打ち破るようなエッジな状況がいくつかあります。 

すべての数値が正で大きい場合、次のようにします。$a_i \ge 2$、 それから$x+y \le xy$常に成り立つので、答えはゼロになるはずです。 単純なプログラマは、ヒューリスティックやオーバーカウントによってペアをカウントしようとする可能性があります。 

配列に多くの負の値が含まれている場合、不等式により非直感的な方法で動作が反転する可能性があります。 たとえば、$x = -1$そして$y = 2$、私たちは得ます$-2 < 1$これは、一方の値が負であり、もう一方の値が正である場合でも当てはまります。 

両方の値がゼロの場合、$0 \cdot 0 = 0$そして$0 + 0 = 0$、つまり、不等式は厳密であるため失敗します。 

これらのコーナー相互作用はまさに、カウント戦略を試みる前に不等式の変換が必要な理由です。 

## アプローチ

 ブルートフォースのアイデアは単純です。 すべてのペアをチェックします$(i, j)$、計算する$a_i a_j$そして$a_i + a_j$、不等式が成立する場合は答えをインクリメントします。 これは、ペアを欠落させることなく、記載されているとおりに条件を直接評価するため、正しいです。 

ただし、これには次のことが必要です$\frac{n(n-1)}{2}$テストケースごとの操作。 と$n = 10^5$、これについてです$5 \cdot 10^9$比較は実現可能な限界をはるかに超えています。 

重要な観察は、不等式を書き換えることから得られます。$$(x - 1)(y - 1) < 1$$今、構造はどれだけ近いかによってのみ決まります$x$そして$y$は絶対的な大きさではなく、1 になります。 これは、実線上の相対位置についての分類と推論を示唆しています。 

の符号に基づいて数値を分割します。$x - 1$。 価値観$x \le 1$作る$x - 1 \le 0$、一方の値$x \ge 2$作る$x - 1 \ge 1$。 これにより、配列が非正の変換値と正の変換値に分割されます。 

次にケースを考えてみましょう。 

両方の場合$x - 1$そして$y - 1$が正の場合、その積は少なくとも 1 であるため、不等式は成立しません。 したがって、両方の値が 1 より大きいペアは寄与しません。 

一方が正でもう一方が正でない場合、積は常に正ではないため、常に 1 より小さいため、そのようなクロスペアはすべて有効です。 

両方が正でない場合、つまり元の値が両方とも正でないことを意味します。$\le 1$、 それから$(x - 1)(y - 1) \ge 0$。 このようなペアは、積が正確に 0 である場合、つまり少なくとも 1 つが 1 に等しい場合にのみ有効です。 

したがって、問題全体は数えることに帰着します。 

少なくとも 1 つの要素を含むペア$\le 1$別の要素で$> 1$、さらに、値 1 を含むペアは重複を慎重に処理します。 

この構造により、ペアの列挙ではなく頻度によるカウントが行われます。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. 配列を 3 つの概念グループ (1 に等しい値、1 未満の値、1 より大きい値) に分割します。この分類は、次の符号に直接対応します。$x - 1$、不平等を制御します。 
2. 1 に等しい要素がいくつあるかを数えます。これらの要素は特別です。$(x - 1) = 0$、別の 1 と組み合わせると、製品の状態が正確に 0 になります。 
3. 1 未満の要素がいくつあるかを数えます。変換された値はそれぞれ非正と正であるため、これらは 1 より大きい要素と自由に相互作用し、積 < 1 が保証されます。 
4. 1 より大きい要素の数を数えます。変換された両方の値が少なくとも 1 であり、少なくとも 1 の積が生成されるため、これらは相互にペアにすることができません。 
5. 寄与を計算します。 

- 1 つの要素を含む任意のペア$\le 1$そして一つの要素$> 1$有効です。 
- 少なくとも 1 つの要素が 1 で、もう一方の要素も 1 である任意のペア$\le 1$は制限された場合にのみ有効ですが、1 と非正の値を含む組み合わせに限定されます。 
6. 最終的な答えは、反復ではなく組み合わせカウントを使用して、有効なグループ間の寄与を合計することによって得られます。 

なぜ効果があるのか:

 条件を次のように書き換えた後、$(x - 1)(y - 1) < 1$の場合、問題は完全に、シフトされた 2 つの値が 1 未満の積を生成するかどうかになります。すべての整数は、1 より小さいか、1 に等しいか、1 より大きいかによって分けられるため、各カテゴリには他のカテゴリとの固定の交互作用ルールがあります。 これらの相互作用ルールは決定論的で順序とは独立しています。つまり、周波数を介してペアをカウントすると、有効なペアを欠落したり二重にカウントしたりすることなく正確な正確さが保たれます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    
    for _ in range(t):
        n = int(input())
        arr = list(map(int, input().split()))
        
        cnt1 = 0
        cnt_le1 = 0
        cnt_gt1 = 0
        
        for x in arr:
            if x == 1:
                cnt1 += 1
                cnt_le1 += 1
            elif x < 1:
                cnt_le1 += 1
            else:
                cnt_gt1 += 1
        
        ans = 0
        
        ans += cnt1 * (cnt1 - 1) // 2
        
        ans += cnt1 * (cnt_le1 - cnt1)
        
        ans += cnt_le1 * cnt_gt1
        
        out.append(str(ans))
    
    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```このコードは、以前に導出されたグループ化ロジックに正確に従っています。 重要な実装の詳細は、1 の数と要素の合計数の両方を維持することです。$\le 1$1 を含むペアは両方の量に依存するためです。 最終的な式は完全に組み合わせペアリングから構築され、明示的なペアの反復は回避されます。 

間の誤分類があるため、すべての要素が 1 回だけ分類されるように注意する必要があります。$=1$、$<1$、 そして$>1$派生したアイデンティティを直接破壊します。 

## 実用的な例

 配列を考慮してください$[2, 3, 0, 1]$。 

カウントを計算します。$cnt1 = 1$、$cnt\_le1 = 2$(0 と 1)、$cnt\_gt1 = 2$(2と3)。 

| ステップ | cnt1 | cnt_le1 | cnt_gt1 | 部分的な回答 |
 | --- | --- | --- | --- | --- |
 | 初期化 | 0 | 0 | 0 | 0 |
 | スキャン後 | 1 | 2 | 2 | 0 |
 | 1ペア | 1 | 2 | 2 | 0 |
 | 1 le1 付き | 1 | 2 | 2 | 1 |
 | le1 と gt1 | 1 | 2 | 2 | 5 |

 最終的な答えは 5 です。 

ここで考えてみましょう$[2, 2, 3]$。 

ここ$cnt1 = 0$、$cnt\_le1 = 0$、$cnt\_gt1 = 3$。 両方の値が 1 より大きいため、すべてのペアは無効です。 

答えは 0 であり、次の事実と一致します。$xy \ge x + y$この範囲内のすべてのペアに当てはまります。 

これらの例は、地域間の相互作用のみが寄与していることを確認しています。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        arr = list(map(int, input().split()))
        cnt1 = cnt_le1 = cnt_gt1 = 0
        for x in arr:
            if x == 1:
                cnt1 += 1
                cnt_le1 += 1
            elif x < 1:
                cnt_le1 += 1
            else:
                cnt_gt1 += 1
        ans = cnt1 * (cnt1 - 1) // 2 + cnt1 * (cnt_le1 - cnt1) + cnt_le1 * cnt_gt1
        out.append(str(ans))
    return "\n".join(out)

 ## 特殊なケース

 微妙なケースの 1 つは、すべての要素が 1 に等しい場合です。不等式は次のようになります。$1 \cdot 1 < 2$これは常に true であるため、すべてのペアがカウントされる必要があります。 アルゴリズムは計算します$cnt1 = n$、$cnt\_le1 = n$、$cnt\_gt1 = 0$、与える：$$\frac{n(n-1)}{2}$$これは完全なペアセットと正確に一致します。 

もう 1 つのケースは、すべての要素が 2 に等しい場合です。この場合、すべての積は少なくとも 4 ですが、合計は最大 4 になるため、厳密な不等式は成立しません。 アルゴリズムはすべての要素を次のように分類します。$cnt\_gt1$、貢献度はゼロになります。 

混合エッジケースのような$[1, 0, 2]$は、期間をまたいだロジックを示しています。 唯一の有効なペアは、$(1,0)$そして$(1,2)$、評価に応じて、カウント式は両方を介してキャプチャします。$cnt1$二重カウントなしの - ベースの用語とクロスグループ用語。
