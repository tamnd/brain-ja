 ## 問題の理解

 私たちには長い一連の日が与えられており、毎日、正、ゼロ、または負の幸福度の数値が与えられます。 2 種類の操作が許可されています。1 日の幸福度の値を更新することも、日のセグメントをクエリして、そのセグメント内で可能な限り最良の休暇計画を求めることもできます。 

休暇計画は、クエリ間隔内の連続する部分配列を選択することによって選択されます。 ただし、制限があります。選択したサブ配列の長さは最大でも次のとおりです。`c`、教授はそれしか持っていないので、`c`連続日数の休暇。 クエリの目的は、範囲内のすべての部分配列の最大合計を計算することです。`[l, r]`その長さが超えないもの`c`。 空の選択肢は暗黙的に許可されており、答えは少なくともゼロであることを意味します。 

したがって、各クエリは、点の更新を伴う動的配列に対する制約付きの最大サブ配列合計を要求します。 

制約は大きく、最大で`2 × 10^5`日々と`5 × 10^5`操作。 クエリごとに回答を最初から再計算する単純なアプローチでは、最大で次のスキャンが必要になります。`O(n)`クエリごとに、おおよそ`10^11`実行可能な限界をはるかに超えた最悪の場合の操作。 これにより、再利用せずにクエリごとにサブ配列情報を再計算するソリューションは即座に除外されます。 

主な困難は、最大サブアレイ構造とスライディング長さの制約という 2 つの機能の組み合わせにあります。`c`、どちらもポイント更新中です。 

微妙なエッジ ケースは、負の値と空のサブ配列が選択される可能性から発生します。 たとえば、セグメントが`[1, -100, 1]`そして`c = 2`、最良の答えは`1`、 ない`-98`または`-100`。 すべての値が負の場合、別の特殊なケースが発生します。 その場合、正しい答えは常に`0`空いている休暇を選ぶことができるからです。

 ## アルゴリズムのチュートリアル

 配列上にセグメント ツリーを構築します。 各ノードはセグメントを表し、次の 2 つの配列を保存します。各長さの最適なプレフィックスの合計は次のとおりです。`c`、および最大の各長さの最適な接尾語の合計`c`、セグメントの合計額も合わせて表示されます。 

1. 単一要素に対応するリーフノードの場合`a[i]`、プレフィックスとサフィックスの配列は簡単です。 長さ 1 の最適なプレフィックスは次のとおりです。`a[i]`、空のプレフィックスは 0 です。サフィックスにも同じことが当てはまります。 これにより、マージ用の基本構造が初期化されます。 
2. 2つの子ノードを結合する場合`L`そして`R`、合計を次のように計算します。`L.sum + R.sum`。 この値は、両側にまたがるサフィックスとプレフィックスの組み合わせを計算するために必要です。 
3. 最初にすべてのプレフィックスを取得して、マージされたノードのプレフィックス配列を計算します。`L`それらは左側のセグメント内で完全に有効なままであるためです。 次に、次のように拡張します。`R`フルを組み合わせることで`L`の接頭辞が付く`R`、長さ制限を考慮して`c`。 これにより、左側の境界から始まるすべてのサブ配列が確実にキャプチャされます。 
4. 同様に、サフィックスを完全に取得してサフィックス値を計算します。`R`、そして以下に拡張します`L`必要なときに。 この対称性により、正しい境界で終わるサブ配列の正確さが保証されます。 
5. 境界を越える最適な部分配列を計算するために、可能な分割長を反復処理します。`i`の接尾辞から取られています`L`そして`j`の接頭辞から`R`、 と`i + j ≤ c`。 分割ごとに、次のように計算します。`suffix_L[i] + prefix_R[j]`そして最大値を取る。 これにより、制約が明示的に強制されます。 
6. 更新ごとにリーフ ノードが変更され、同じマージ ロジックを使用してすべての祖先が再計算され、ツリー全体の一貫性が維持されます。 
7. すべての制約付きサブ配列がその構造内ですでにエンコードされているため、各クエリはセグメント ツリーを使用してセグメント ノードを抽出し、格納されている最良の値を直接読み取ります。 

これが機能する理由は、すべてのノードがすべての有効なサブ配列をそのセグメント内で完全に最大長で完全にエンコードするという不変条件から来ています。`c`、完全に左の子、完全に右の子、または中間点を横切るという 3 つのカテゴリに分割されます。 マージ ステップは 3 つのカテゴリすべてを徹底的にカバーするため、有効な候補が省略されることはなく、すべてのプレフィックスとサフィックスの組み合わせが明示的に制限されるため、無効な候補が長さの制約を超えることはありません。`c`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Node:
    __slots__ = ("sum", "pref", "suff", "best")
    def __init__(self, c):
        self.sum = 0
        self.pref = [0] * (c + 1)
        self.suff = [0] * (c + 1)
        self.best = 0

def merge(left, right, c):
    res = Node(c)
    res.sum = left.sum + right.sum

    res.best = max(left.best, right.best)

    for i in range(1, c + 1):
        res.pref[i] = max(left.pref[i], left.sum + right.pref[i])
        res.best = max(res.best, res.pref[i])

    for i in range(1, c + 1):
        res.suff[i] = max(right.suff[i], right.sum + left.suff[i])
        res.best = max(res.best, res.suff[i])

    for i in range(1, c + 1):
        li = min(i, c)
        for j in range(1, c - i + 1):
            res.best = max(res.best, left.suff[i] + right.pref[j])

    return res

class SegTree:
    def __init__(self, arr, c):
        self.n = len(arr)
        self.c = c
        self.size = 4 * self.n
        self.tree = [Node(c) for _ in range(self.size)]
        self.arr = arr
        self.build(1, 0, self.n - 1)

    def build(self, idx, l, r):
        if l == r:
            val = self.arr[l]
            node = self.tree[idx]
            node.sum = val
            node.pref[1] = max(0, val)
            node.suff[1] = max(0, val)
            node.best = max(0, val)
            return
        mid = (l + r) // 2
        self.build(idx * 2, l, mid)
        self.build(idx * 2 + 1, mid + 1, r)
        self.tree[idx] = merge(self.tree[idx * 2], self.tree[idx * 2 + 1], self.c)

    def update(self, idx, l, r, pos, val):
        if l == r:
            node = self.tree[idx]
            node.sum = val
            node.pref[1] = max(0, val)
            node.suff[1] = max(0, val)
            node.best = max(0, val)
            return
        mid = (l + r) // 2
        if pos <= mid:
            self.update(idx * 2, l, mid, pos, val)
        else:
            self.update(idx * 2 + 1, mid + 1, r, pos, val)
        self.tree[idx] = merge(self.tree[idx * 2], self.tree[idx * 2 + 1], self.c)

    def query_node(self, idx, l, r, ql, qr):
        if ql <= l and r <= qr:
            return self.tree[idx]
        mid = (l + r) // 2
        if qr <= mid:
            return self.query_node(idx * 2, l, mid, ql, qr)
        if ql > mid:
            return self.query_node(idx * 2 + 1, mid + 1, r, ql, qr)
        left = self.query_node(idx * 2, l, mid, ql, qr)
        right = self.query_node(idx * 2 + 1, mid + 1, r, ql, qr)
        return merge(left, right, self.c)

def solve():
    n, m, c = map(int, input().split())
    arr = list(map(int, input().split()))
    st = SegTree(arr, c)

    for _ in range(m):
        op = input().split()
        if op[0] == '1':
            x = int(op[1]) - 1
            y = int(op[2])
            st.update(1, 0, n - 1, x, y)
        else:
            l = int(op[1]) - 1
            r = int(op[2]) - 1
            node = st.query_node(1, 0, n - 1, l, r)
            print(node.best)

if __name__ == "__main__":
    solve()

微妙な点の 1 つは、各ノードがサイズの配列を通じて上限付きのプレフィックスとサフィックスの情報を暗黙的に格納することです。`c`。 これにより、各クエリ中にセグメント全体の完全な DP を再計算することなく、制限された再結合が可能になります。
