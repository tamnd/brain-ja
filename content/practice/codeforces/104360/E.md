 ## 解決策
 ## 問題の理解

 私たちには一連の動きが与えられています。 開始時に、ボブは 2 つの整数を左手に 1 つ、右手に 1 つずつ保持しており、どちらもゼロに等しいです。 移動 i ごとに、アリスは新しい数字 ki を提示します。 ボブは、左手にある値を ki に置き換えるか、右手にある値を ki に置き換えるかを選択する必要があります。 もう一方の手は変化しません。 

置換のたびに、結果の値のペアは長方形制約内に収まる必要があります。左側の値 x は ai ≤ x ≤ bi を満たす必要があり、右側の値 y は ci ≤ y ≤ di を満たす必要があります。 どこかの時点でこの条件に違反すると、プロセスは直ちに停止します。 ボブはすべての手を事前に確認し、すべてのプレフィックスに対してすべての制約が満たされるように、ステップごとにどの手を交換するかを決定する必要があります。 

出力は、新しい数字が左手に行くのか右手に行くのかを示す、または有効なシーケンスが存在しないというステートメントを示す一連の決定 (手ごとに 1 つ) です。 

n が 100000 までの制約は、すべての解が線形または線形演算に近くなければならないことを意味します。 選択肢によって指数関数的に分岐する方法は、直ちに不可能になります。 すべてのプレフィックスにわたる二次 DP であっても、大幅に圧縮しない限り遅すぎます。 

微妙な問題は、両方の手が非対称に進化することです。各決定は、複合的に将来の実現可能性に影響を与えます。 素朴な考えは、各ステップの後に、考えられるすべての値のペアを維持しようとすることです。 値は小さな領域に制限されていないため、これは不可能です。 ki は最大 10^9 まで大きくすることができます。 

もう 1 つの失敗モードは、将来の制約を考慮せずに、現在のステップを有効に保つハンドを貪欲に選択することです。 現在の割り当てでは、現時点では実行可能性が保たれても、将来のすべての間隔がブロックされる可能性があるため、ローカルでの決定は信頼できません。 

## アプローチ

 直接的な総当りのアプローチでは、各 ki のすべての割り当てが左または右に試行されます。 このような割り当ては 2^n 個あり、それぞれについて O(n) でプロセスをシミュレートし、O(n・2^n) を与えます。 これは、n = 100000 では明らかに実行不可能です。 

重要な構造上の観察は、どの時点においても重要なのは、それぞれの手に最後に書き込まれた値だけであるということです。 各移動は 1 つの座標のみを上書きし、制約はこれら 2 つの現在の値にのみ依存します。 したがって、状態はペア (x, y) ですが、これらの値は制限されたセット、つまり 0 またはそのハンドに選択されたいくつかの ki から取得されます。 

問題は、状態空間の値の範囲が大きく、ステップ数が多い一方で、決定が 2 値であることです。 これは、状態を超えて圧縮を伴う時間の経過に伴う DP を示唆しています。 

dp[i][0/1] を、最初の i 番目の移動を処理し、それぞれ左または右に割り当てられた i 番目の値で終了できるかどうかとして定義します。 ただし、これではまだ実際の値の制約が満たされていません。 

代わりに、視点を逆転させます。各ステップで、正確な値を追跡するのではなく、サフィックスの完成を可能にしつつ、各手が保持できる値の可能な間隔を追跡します。 これにより、問題は逆方向に伝播する実現可能範囲の維持に変わります。 

より効果的なアプローチは、状態枝刈りを使用したフォワード DP です。 ステップごとに、左右の値の候補状態のセットを保持します。 ただし、すべての値を保存するのではなく、固定割り当てパターンの場合、値はそれぞれの手に割り当てられた ki のサブシーケンスであることがわかります。 したがって、左手は、それに割り当てられた選択されたインデックスのサブシーケンスによって決定されます。 

これは古典的な削減につながります。各ステップで、最後の割り当てが左または右であった状態に到達できるかどうか、および親ポインターを使用して逆方向に再構成することによって現在の値が暗黙的に決定されることを追跡するだけで済みます。 各ステップでの実現可能性チェックはローカルです。左側に ki を割り当てる場合は、それが [ai​​, bi] 内にあることを確認する必要があり、右側についても同様です。

したがって、2 つの DP 層を維持します。dp[i][0] は i 番目のカードを左側に割り当てることを意味し、dp[i][1] は右側に割り当てることを意味します。 遷移は、以前の割り当てが有効であり、その結果の値が間隔制約を満たすかどうかにのみ依存します。 

これにより、バックトラッキングを伴う O(n) DP が得られます。

 | ブルートフォース | O(2^n · n) | O(n) | 遅すぎる |
 | ステップごとに 2 つの状態を持つ DP | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは、各状態がどのハンドが現在のカードを受け取ったのか、そしてその選択が両方のハンドを有効に保つかどうかをエンコードするプレフィックス上に動的なプログラムを構築します。 

1. システムを left = 0 および right = 0 で初期化します。これは、ステップ 0 の後の最初の制約を暗黙的に満たしている必要があります。 
2. 各ステップ i で、左手に ki を置くことを検討します。 こうすると、新しい左が「気」になり、右は変化しません。 この移動は、ki が [ai​​, bi] 内にあり、変更されていない正しい値が [ci, di] 内にある場合にのみ有効です。 
3. 同様に、右手に ki を置き、右手を ki に更新し、左手の値がその区間内に収まっていることを確認することを考えます。 
4. dp[i][0] と dp[i][1] を到達可能な状態として保存します。これは、ステップ i での対応する選択肢を使用して i までの処理が可能であることを意味します。 
5. 答えを再構築するために、親ポインターを維持します。各 dp 状態から、それが dp[i−1][0] から来たのか dp[i−1][1] から来たのかを記憶します。 
6. すべてのステップを処理した後、dp[n][0] にも dp[n][1] にも到達できない場合、有効なシーケンスは存在しません。 
7. それ以外の場合は、有効な終了状態からバックトラックし、一連の選択肢を再構築します。 

重要な微妙な点は、状態は局所的にハンドを選択することの実行可能性だけでなく、各割り当て後に両方の制約を同時に維持することの実行可能性であるということです。 ステップごとに変更される値は 1 つだけであるため、有効性のチェックは、変更されていないハンドが前のステップでその間隔をすでに満たしていることを確認しながら、更新されたハンドをその間隔に対してチェックすることになります。 

### なぜ効果があるのか

 不変条件は、ステップ i の後に有効な構成を生成する最初の i ステップの選択シーケンスが存在し、その i 番目の手が ki をハンド t に割り当てる場合に、dp[i][t] が真であるということです。 各遷移は 1 つの座標のみを変更し、制約は現在の座標のみに依存するため、以前の有効な状態を超える隠された履歴は問題になりません。 ステップ i のすべての有効な構成は、2 つのハンドのいずれかに ki を割り当てることにより、ステップ i-1 での 1 つの有効な構成から得られる必要があるため、DP はすべての有効なシーケンスのみをキャプチャします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    
    k = [0] * (n + 1)
    a = [0] * (n + 1)
    b = [0] * (n + 1)
    c = [0] * (n + 1)
    d = [0] * (n + 1)

    for i in range(1, n + 1):
        k[i] = int(input())
        a[i], b[i] = map(int, input().split())
        c[i], d[i] = map(int, input().split())

    # dp[i][0] = last move to left, dp[i][1] = last move to right
    dp = [[False, False] for _ in range(n + 1)]
    parent = [[-1, -1] for _ in range(n + 1)]

    # initial state: both 0 are in range after step 0 implicitly
    dp[0][0] = dp[0][1] = True

    left_val = [0] * (n + 1)
    right_val = [0] * (n + 1)

    for i in range(1, n + 1):
        for prev in [0, 1]:
            if not dp[i - 1][prev]:
                continue

            l = left_val[i - 1]
            r = right_val[i - 1]

            # put in left
            if a[i] <= k[i] <= b[i] and c[i] <= r <= d[i]:
                if not dp[i][0]:
                    dp[i][0] = True
                    parent[i][0] = prev
                    left_val[i] = k[i]
                    right_val[i] = r

            # put in right
            if a[i] <= l <= b[i] and c[i] <= k[i] <= d[i]:
                if not dp[i][1]:
                    dp[i][1] = True
                    parent[i][1] = prev
                    left_val[i] = l
                    right_val[i] = k[i]

    end = -1
    if dp[n][0]:
        end = 0
    elif dp[n][1]:
        end = 1
    else:
        print("No")
        return

    ans = [0] * (n + 1)
    cur = end

    for i in range(n, 0, -1):
        ans[i] = cur
        cur = parent[i][cur]

    print("Yes")
    print(*ans[1:])

if __name__ == "__main__":
    solve()
```この実装では 2 つの DP 層が維持され、親ポインターを使用してパスが再構築されます。 配列 left_val と right_val は、ステート作成時の各ハンドの値を表します。 各状態はレイヤーごとに 1 回だけ記録されるため、これらの保存された値は選択された遷移と一致したままになります。 

よくある落とし穴は、関連付けられた値の正確さを維持せずに dp 状態を上書きすることです。 コードでは、dp 状態を 1 回だけ設定し、その時点で結果の構成をバインドすることでこれを回避します。

 ## 特殊なケース

 両方の選択肢が局所的に有効であるにもかかわらず、どちらか 1 つだけが将来の実現可能性を維持する場合、重大なエッジ ケースが発生します。 DP は、代替の到達可能な状態を途中で破棄しないため、これを処理します。 可能な場合は、dp[i][0] と dp[i][1] の両方を保持します。 

もう 1 つの微妙なケースは、最初の手がすでに 1 つの手がゼロから離れることを強制している場合です。 両方の手が 0 から始まるため、最初の ki が一方の間隔の外側にあり、もう一方の間隔の内側にある場合、1 つの DP 状態のみが残ります。これは、代替構成が存在しないため、正しいです。 

最後のケースは、拘束が非常に厳しく、中間のステップで両手の間で振動が強制される場合です。 再構築により、各ステップが貪欲に再計算するのではなく、保存された親ポインタを使用するようになり、強制切り替えシーケンスでも一貫性が維持されます。
