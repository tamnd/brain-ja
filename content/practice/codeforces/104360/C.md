 ## 解決策
 ## 問題の理解

 学生のスキル レベルのコレクションが与えられ、それらを並行クラスと呼ばれるいくつかのグループに分割したいと考えています。 各クラス内で学生をスキル別に並べ替える場合、隣接するすべてのペアの違いは最大でも固定値 x でなければなりません。 この条件により、各クラスには、大きなギャップがなく、並べ替えられた順序で小さなジャンプを通じて「接続」できる生徒が含まれるよう効果的に強制されます。 

任意のスキル値を持つ最大 k 人の追加生徒を挿入することができます。 これらの挿入された学生は、元のディストリビューションに属する必要はなく、必要なクラスの数を減らすために戦略的に選択できます。 

目標は、最大 k 個の追加値を最適に挿入した後、必要な安定したクラスの数を最小限に抑えることです。 

入力サイズは最大 200,000 人の生徒と大きく、k と x は両方とも最大 10^18 と非常に大きくなる可能性があります。 これにより、挿入を直接シミュレートしようとしたり、追加の生徒のすべての配置を試行したりするソリューションは即座に除外されます。 ギャップごとに推論し、並べ替えられたデータに対して線形または線形に近い時間で実行するアプローチは許容されますが、k を超える二次関数や組み合わせは不可能です。 

重要な点は、挿入された生徒の価値が完全に自由であることです。 それらは既存のギャップや位置から生じるという制約はありません。 つまり、大きなギャップの間の「橋」として使用でき、大きなジャンプを複数の小さなジャンプに効果的に分割できます。 

隣接する差分が x を超えるたびに配列を貪欲にセグメントに分割すればよいと考えると、単純な間違いが発生します。 これは、k = 0 の場合は正しいですが、値を挿入できる場合は完全に失敗します。 たとえば、[1, 100] で x = 10 がある場合、単純な解決策では 2 つのクラスが必要になると考えられます。 しかし、k = 1 の場合、50 を挿入して [1, 50, 100] を形成でき、安定します。 

もう 1 つの微妙なエッジ ケースは、大きなギャップを部分的に埋めることができる場合です。 ギャップのサイズが d の場合、単純な意味では常に d / x の挿入が必要というわけではありません。 正しいカウントは、各ジャンプを最大 x まで減らすために必要な中間点の数に基づきます。 

## アプローチ

 学生を挿入する可能性を無視すると、問題は単純になります。 配列をソートし、隣接する差が最大で x である最大のセグメントに分割します。 x より大きいギャップが見つかるたびに、新しいクラスを開始します。 これにより基本的な答えが得られます。 

難しいのは、最大 k 個の値を挿入できることにあります。 挿入するたびに大きな隙間を減らすことができます。 差が d である 2 つの連続したソート値 a[i] と a[i+1] があるとします。 挿入がない場合、これは d ≤ x かどうかに応じて 0 または 1 つのブレークに寄与します。 挿入を使用すると、ギャップがより小さなステップに分解されるように中間値を配置できます。 それらの間に t 個の数値を挿入すると、ギャップを最大 x のサイズの t+1 個のセグメントに分割できます。 したがって、t は (t + 1) * x ≥ d、つまり t ≥ ceil(d / x) - 1 を満たす必要があります。 

これにより、問題は「すべてを接続できるか」という問題から、「修復する必要があるギャップの数と修復にかかるコストはいくらか」という問題に変わります。 

まず配列をソートします。 次に、x より大きい隣接するすべてのギャップを調べます。 このような各ギャップは、ceil(d / x) - 1 に等しい必要な挿入数に寄与します。十分な k がある場合は、ギャップを埋めるために「支払う」ことで、結果として得られるクラスの数を減らすことができます。 ブリッジされた各ギャップは、以前は別々だった 2 つのセグメントをマージします。 

ここで構造を再解釈します。挿入がなければ、大きなギャップによってコンポーネント間に分離が生じます。 挿入を使用してギャップを修正すると、2 つのコンポーネントが 1 つにマージされます。 マージされたギャップごとにコンポーネントの数が 1 つ減るため、k を費やしてできるだけ多くのギャップを修正し、必要な挿入の観点からコストが最小のものを優先したいと考えています。

したがって、x を超えるすべてのギャップを計算し、必要な挿入コストを計算し、これらのコストを並べ替えます。 最初は、クラスの数は 1 にそのようなギャップの数を加えたものに等しくなります。 次に、予算 k があるうちに最も安価なギャップを貪欲に修正し、修正するたびにクラスの数が 1 つずつ減ります。 

重要な考え方は、隣接するソートされたギャップのみが分離を定義するため、隣接しない要素間の相互作用を考慮する必要がないということです。

 ## アルゴリズムのチュートリアル

 1. 学生のスキルの配列を降順でない順に並べ替えます。 安定性は順序付け後の隣接する差分によって定義されるため、ソートが必要です。 
2. ソートされた配列を走査し、隣接するすべての差分を計算します。 差 d が x を超えるたびに、それを「ブレーク ギャップ」として記録し、それを有効にするために必要な挿入の回数を計算します: t = ceil(d / x) - 1。この値は、両側が同じクラスに属することができるように、そのギャップを修復するコストを表します。 
3. 初期クラスの数を 1 に d > x のギャップの数を加えたものとして数えます。 このような各ギャップは、挿入前にソートされた配列を個別の安定したセグメントに分割します。 
4. これらのギャップについて計算されたすべての修理コストをリストに収集します。 各コストは、2 つの隣接するコンポーネントをマージするのにかかるコストを表します。 
5. コストのリストを昇順に並べ替えます。 これにより、接続するのに最も安価なセグメントを優先的に結合することができます。 
6. 最小コストから開始して、利用可能な k を繰り返し使用して、ギャップを修復するための「支払い」を行います。 コストに余裕があるたびに、k を減らし、クラスの数を 1 つ減らします。 
7. k が不足するか、修復するギャップがなくなったら停止します。 残りのコンポーネントの数が答えになります。 

### なぜ効果があるのか

 ソート後の構造は線形であり、すべてのクラス境界は x を超えるギャップによってのみ決定されます。 このような各境界は、境界をブリッジすることがその特定の間隔に十分な中間値を挿入することだけに依存するという意味で独立しています。 有効な解決策はすべて、修復するギャップのサブセットを選択することに対応し、修復ごとに固定コストを消費しながらクラス数をちょうど 1 つ減らします。 コストは独立していて加算的なものであるため、固定予算の下では最小のコストを最初に選択することが最適であり、これは直接的な貪欲な交換の議論です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k, x = map(int, input().split())
    a = list(map(int, input().split()))
    a.sort()

    gaps = []

    for i in range(n - 1):
        d = a[i + 1] - a[i]
        if d > x:
            t = (d + x - 1) // x - 1
            gaps.append(t)

    components = 1 + len(gaps)

    gaps.sort()

    for cost in gaps:
        if cost <= k:
            k -= cost
            components -= 1
        else:
            break

    print(components)

if __name__ == "__main__":
    solve()
```この解決策は、すべての安定性制約が隣接する差異に帰着するように生徒を分類することから始まります。 ギャップに対するループでは、しきい値 x に違反する間隔のみが抽出されます。 式`(d + x - 1) // x - 1`大きなギャップを最大 x サイズの有効なステップに分割するために必要な挿入値の数を計算します。 

コンポーネントの初期数は、挿入が使用されない場合の避けられないセグメントの数です。 各ギャップは潜在的なマージ操作に対応しており、各マージには必要な挿入という点でコストがかかります。 これらのコストを分類すると、常に最初に最も安価なマージに k が費やされ、コンポーネント数の削減が最大化されます。 

最終的な答えは、単純に、できるだけ多くのマージ操作を実行した後に残るセグメントの数です。 

## 実用的な例

 ### 例 1

 入力:

 n = 8、k = 2、x = 3

 a = [1、1、5、8、12、13、20、22]

 ソートされた配列はすでに与えられています。 

ギャップを計算します。 

| 私 | a[i] | a[i+1] | 差分 | d > x | コスト |
 | --- | --- | --- | --- | --- | --- |
 | 0 | 1 | 1 | 0 | いいえ | - |
 | 1 | 1 | 5 | 4 | はい | ceil(4/3)-1 = 1 |
 | 2 | 5 | 8 | 3 | いいえ | - |
 | 3 | 8 | 12 | 4 | はい | 1 |
 | 4 | 12 | 13 | 1 | いいえ | - |
 | 5 | 13 | 20 | 7 | はい | ceil(7/3)-1 = 2 |
 | 6 | 20 | 22 | 2 | いいえ | - |

 初期コンポーネント = 4 (3 つの違反ギャップと 1 つ)。 

コストを [1、1、2] に並べ替えます。 

k = 2 です。 

コスト 1 → k = 1、コンポーネント = 3 とします。 

コスト 1 → k = 0、コンポーネント = 2 とします。 

コスト2は取れません。 

最終的な答えは 2 つのコンポーネントです。 

このトレースは、複数のギャップを個別に部分的に修復できること、最小の修復コストを貪欲に選択することで、許容できるマージの数を直接最大化できることを示しています。

 ## 特殊なケース

 すべての値が等しい場合、並べ替えではギャップがゼロになるため、クラス境界は存在しません。 ギャップ リストが空で修復の必要がないため、アルゴリズムは 1 つのコンポーネントを正しく返します。 

k が 0 の場合、アルゴリズムは、隣接する差分が x を超えるギャップをカウントするように退化します。 このようなギャップは構造を永続的に分割し、マージが不可能なため、貪欲ループがトリガーされることはありません。 

k が非常に大きい場合、すべてのギャップを修復できます。 各修復では、隣接する 2 つのコンポーネントが 1 つだけ残るまでマージされます。 すべてのコストが昇順に処理され、すべてが手頃な価格であるため、アルゴリズムは自然にこの状態に到達します。 

ギャップに複数の挿入が必要な場合、コスト計算式により正確な計算が保証されます。 x = 3 のサイズ 10 のギャップには ceil(10/3)-1 = 3 回の挿入が必要です。これは、すべてのステップを範囲内に保つために 3 つの中間点が必要であることを反映しています。
