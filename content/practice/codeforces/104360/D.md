 ## 解決策
 ## 問題の理解

 いくつかの製品タイプがあり、それぞれに固定数の購入が必要です。 通常、購入には 2 単位のお金がかかります。 種類に関係なく、アイテムを購入するたびに増加するグローバルカウンターがあります。 各製品タイプについて、購入されたアイテムの総数がそのタイプに固有のしきい値に達すると、そのタイプの今後の購入は安くなり、コストは 2 ではなく 1 のみになります。 

私たちに与えられる唯一の自由は、すべての種類の個々のアイテムを購入する順序です。 目標は、割引が解除される前にできるだけ多くの高価な購入が行われ、割引が有効になった後にできるだけ多くの安価な購入が行われるように、これらの購入をスケジュールすることです。 

入力サイズは大きく、製品タイプは最大 10 万、必須項目の合計は最大 1 兆に達します。 これにより、各購入を明示的に追跡することに依存する個々のアイテムまたは状態に関するシミュレーションが即座に除外されます。 実行可能なソリューションは、各タイプを集約推論に圧縮し、ほぼ線形または線形時間で動作する必要があります。 

素朴な解釈では、次にどの商品を購入するかを常に選択しながら、プロセスを段階的にシミュレートしようとします。 個別の購入は合計で最大 10^14 まで存在する可能性があり、貪欲なシミュレーションさえ不可能であるため、これは失敗します。 

すべてのしきい値がアイテムの総数に比べて極端に大きい場合、微妙なエッジ ケースが発生します。 この場合、割引は有効になりません。答えは単純にすべての数量の合計の 2 倍になります。 不注意な解決策でも、順序を不必要に最適化しようとする可能性がありますが、何も改善することはできません。 

もう 1 つのエッジ ケースは、1 つのタイプのしきい値が非常に小さく、数量が膨大な場合です。 したがって、最良の戦略は、できるだけ早く割引を発動することに大きく依存します。なぜなら、それにより、高価な購入の多くのサフィックスが安価な購入に変換されるからです。 これは、順序がタイプごとではなくグローバルに重要であることを示しています。 

## アプローチ

 ブルートフォース戦略では、各購入を明示的にシミュレートし、各ステップで購入された品目の数を維持し、各種類の割引が有効になっているかどうかを確認します。 各ステップで、おそらく残りのすべてのタイプを試して、次の項目を最適に選択します。 これにより、項目の合計とタイプの数のオーダーで複雑さが生じますが、項目の合計が 10^14 に達すると、これは完全に実行不可能になります。 

重要な観察点は、割引条件は購入された商品の世界的な数のみに依存し、購入された種類には依存しないということです。 各タイプ i は、グローバルでの購入後に割引されます。 これは、問題全体が、アイテムごとに、グローバルな順序付けにおけるしきい値の位置の前に配置されるか後ろに配置されるかを決定することに帰着することを意味します。 

このプロセスを、すべての個別項目の順列を選択するものとして再解釈できます。 各アイテムは、そのタイプがロック解除される前に配置された場合はコスト 2、それ以外の場合はコスト 1 になります。 課題は、全体的に最適な方法で割引の開始を遅らせたり加速したりするために、各タイプのアイテムをいくつ早期に配置するかを決定することです。 

重要なのは「投資」という観点から考えることです。 アイテムを早期に購入するとコストが 2 になりますが、将来のすべてのアイテムをそのタイプの割引に近づけるのに役立ちます。 ただし、どのアイテムでも早めに購入すると、他のすべてのタイプがより早く閾値に達するのにも役立ちます。 したがって、早期購入は、割引を遅らせても害が少ない商品に割り当てる必要があります。 

これを解決する標準的な方法は、しきい値 bi で取得した早期購入の緊急度によってタイプを並べ替えることです。 bi が小さいタイプは、割引がすぐに有効になるため、早期の操作による恩恵が少ないため、「遅延」されることが優先されます。 

これにより、bi に基づいた貪欲な順序付けが行われ、より小さい bi がより敏感なものとして効果的に扱われ、より早くスケジュールされます。

 ## アルゴリズムのチュートリアル

 ## 1. 各型をペア (ai、bi) に圧縮します。 

まず、各製品タイプを個別に処理し、購入する必要があるアイテムの数と、そのアイテムが安くなるしきい値を保存します。 

## 2. bi を増加させて製品タイプを並べ替えます

 しきい値が小さいタイプは、割引がすぐに解除されるため、早期のグローバル購入に対してより敏感です。 並べ替えにより、最も「ロック解除が簡単な」タイプが最初に処理されるようになります。 

## 3. 購入したアイテムのグローバルカウンターを維持する

 このカウンターは、グローバル シーケンスでどこまで進んだかを表します。 これにより、新しく購入した商品がまだ高価であるか、すでに割引されているかが決まります。 

## 4. ソートされた型を反復処理し、寄与を決定する

 タイプごとに、スケジュールによって引き起こされるグローバルな順序付けでしきい値 bi に達する前に、その AI アイテムをいくつ購入するかを概念的に決定します。 このような各アイテムはコスト 2 を寄与し、残りのアイテムはコスト 1 を寄与します。 

主な理由は、タイプの順序を修正すると、以前のタイプのすべてのアイテムがグローバル カウンタを増やすのに役立ち、後のタイプの割引の有効化が加速されるということです。 

## 5. 総コストを累計する

 タイプごとに、構築された注文に基づいて割引が有効になる前に、その商品が何個購入されるかを計算します。 それらの場合は 2 を追加し、残りの場合は 1 を追加します。 

## なぜ機能するのか

 正確さは、しきい値の単調性特性に依存します。 bi が小さいタイプがより早く処理されると、最適な配置でより早く割引条件に達します。これを延期しても、購入済みのアイテムの数が増えるだけであり、それが役立つだけであるためです。 したがって、最適な順序付けでは、最適性を損なうことなく、型を bi の非減少順に配置できます。 

このように並べ替えると、グローバル プロセスに一貫性が生まれます。各タイプでは、割引が開始される前に予測可能な数の早期購入が発生し、その後の並べ替えでは、しきい値の順序制約に違反することなく総コストを改善できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    items = []
    total_a = 0

    for _ in range(n):
        a, b = map(int, input().split())
        items.append((b, a))
        total_a += a

    items.sort()

    taken = 0
    ans = 0

    for b, a in items:
        if taken >= b:
            ans += a
        else:
            need = min(a, b - taken)
            ans += need * 2
            ans += (a - need)
            taken += a

    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションでは、まず、割引が有効化されたタイプが最初に処理されるように、しきい値 bi によって項目を並べ替えます。 取得された変数は、これまでに世界中で購入されたアイテムの数を追跡します。 タイプごとに、現在の世界的な数を考慮して、まだ「割引前」の商品がいくつあるかを確認します。 これらはコスト 2 に寄与し、残りはコスト 1 に寄与します。また、このタイプのすべての品目は購入シーケンスの一部とみなされるため、グローバル カウンタを ai の全額だけ進めます。 

微妙な点は、個別のアイテムをシミュレーションすることは決してないことです。 代わりに、しきい値境界の前後に該当するアイテムの数を一括で計算します。 ai の合計は最大 10^14 になる可能性があるため、これは不可欠です。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | しきい値による並べ替えが優先されます。 他のすべての操作は線形です。 
| スペース | O(n) | (bi, ai) のペアの保存 |

 ## 特殊なケース

 重大なエッジ ケースは、すべての bi 値が項目の合計数を超える場合です。 その場合、グローバル カウンタはしきい値に到達しません。 アルゴリズムはすべてのタイプを任意の順序で処理しますが、取得された値がどの bi とも交差しないため、すべてのアイテムの価格は 2 になります。ループ内の数式が割引分岐をトリガーすることはないため、正確性は保たれます。 

もう 1 つのエッジ ケースは、あるタイプの bi が 1 で、ai が非常に大きい場合です。 最初のアイテムをグローバルに処理した後、このタイプはすぐに割引されます。 このアルゴリズムでは、そのタイプの最初の品目のみが残りのギャップ ロジックに基づいてコスト 2 に寄与し、後続のすべての品目はコスト 1 としてカウントされ、できるだけ早く割引をトリガーするという意図された最適戦略と一致します。
