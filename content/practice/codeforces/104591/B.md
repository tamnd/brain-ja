 ## 解決策
 ## 問題の理解

 入力は、頂点がフレンドであり、エッジが通信リンクである有向グラフを記述します。 順序付けされた各ペアは、1 人の友人が 1 つのニュースを別の友人に送信できることを示します。 すべてのエッジに対して、大きさが制限された、正または負のゼロ以外の整数値を割り当てる必要があります。 重要な制約は保存ルールです。すべての友人について、発信エッジの合計値は着信エッジの合計値と等しくなければなりません。 

これはエッジごとのローカル制約ではなく、頂点に付随するすべてのエッジを結合します。 各頂点は、符号付きフローが保存されるフロージャンクションのように動作します。 そのような割り当てが存在するかどうかを判断し、存在する場合は有効な割り当てを構築するように求められます。 

F² によって制限される値の制約は十分に寛大であるため、有効なフローが存在すれば、スケーリングや小さな調整はいつでも可能です。そのため、主な問題は大きさの制御ではなく、純粋に構造的な実現可能性です。 

単純なアプローチでは、任意の値を割り当てて、貪欲に頂点を固定しようとします。 1 つのエッジの調整が 2 つの頂点に同時に影響するため、これは失敗します。そのため、ローカル修正によって修正サイクルが伝播されます。 有向三角形のような小さな例であっても、1 つのエッジ値を選択すると他の値が強制され、矛盾があればすぐに広がります。 

2 番目の微妙なエッジ ケースは、頂点が入次数 0 または出力次数 0 を持ち、両方ではない場合に発生します。 たとえば、ノードに出力エッジのみがある場合、その出力合計はゼロでなければなりませんが、すべてのエッジがゼロ以外でなければならないため、これは不可能です。 これによりインスタンスは即座に不可能になり、「後でバランスをとろう」と試みるメソッドはこの障害を見逃すことになります。 

## アプローチ

 各頂点での保存条件は、各有向辺が流れを運ぶと解釈する場合、すべての頂点の正味流れがゼロでなければならないと言うのと同じです。 これはまさに有向グラフにおける循環の定義です。 

強引な解釈では、エッジに 1 つずつ値を割り当て、すべての頂点のバランスを維持します。 各割り当てでは 2 つの線形制約が導入され、それらを解決するには、不等号境界を持つ整数に対するグローバル方程式系を解く必要があります。 これはコストが高く、概念的に不安定になります。システムが不十分に決定されており、素朴なソルバーは代入を探索する順序で指数関数的な探索空間をバックトラッキングすることになるからです。$[-F^2, F^2]^P$。 

重要な構造的観察は、グラフのすべての接続コンポーネントは内部循環のみを必要とするということです。 エッジを単純なサイクルに分解できれば、各サイクルに沿って +1 と -1 を交互に割り当てると、そのサイクル内のすべての頂点で保存則が自動的に満たされます。 有向サイクル上のすべての頂点には、そのサイクルからの入力寄与と出力寄与が 1 つずつだけ含まれるため、正味の寄与はゼロになります。 

これにより、問題全体が、方向を考慮したエッジのサイクルへの分解を見つけることに帰着します。 このような分解が存在する場合は、ウォーキング サイクルとフローの分散によって値を割り当てます。 グラフに有向サイクルに参加していないエッジが含まれている場合、それらのエッジは流れをソースに戻すことができないため、バランスを取ることができません。 

したがって、問題は、すべてのエッジが何らかの有向サイクル構造内にあるかどうかを識別し、次に、強く接続された各構造についてオイラー形式の分解を介してサイクル基底を明示的に構築することになります。

 ## アルゴリズムのチュートリアル

 有向グラフの接続構造ごとにサイクル分解を使用して、建設的な解決策を構築します。 

1. まずグラフを隣接リストとして解釈します。 入力エッジごとに値を出力する必要があるため、各エッジはインデックスとともに保存されます。 
2. 各頂点について、循環をサポートできる構造に関与しているかどうかを計算します。 正しい条件は、基礎となる有向グラフの各接続コンポーネント (接続性に関して無向として扱われる) で、すべての頂点がコンポーネント内に少なくとも 1 つの入力エッジと 1 つの出力エッジを持つ必要があることです。 頂点がこれに違反すると、流れのバランスが取れなくなるため、循環は不可能になります。 
3. 接続されたコンポーネントごとに、未使用のエッジを追跡する DFS ベースのトラバーサルを使用して、そのエッジをサイクルに分解しようとします。 未使用の外向きエッジを持つ頂点から繰り返し開始し、未使用のエッジに沿って貪欲に前進し、それらに使用済みのマークを付けます。 
4. 現在の歩行で以前に訪れた頂点に遭遇すると、サイクルが発見されたことになります。 このサイクルを抽出し、サイクルのエッジに沿って +1 と -1 の値を交互に割り当てます。 トラバースの方向によって、符号の一貫性が決まります。 
5. コンポーネント内のすべてのエッジが使用されるまで続行します。 各エッジは 1 サイクルに 1 回だけ割り当てられるため、すべてのエッジが値を受け取ります。 
6. 最後に、すべてのエッジが割り当てられたことを確認します。 未使用のものが残っている場合、グラフには非循環の残りの構造が含まれるため、答えは不可能です。 

サイクルに沿った割り当てにより、すべてのサイクルにわたるフロー寄与の出入りに関して、各頂点が -1 寄与と同数の +1 寄与を認識することが保証されます。 

### なぜ効果があるのか

 すべてのエッジは、正確に 1 つの有向サイクル分解に配置されます。 どのサイクルでも、各頂点は 1 つの入力エッジと 1 つの出力エッジに正確に寄与するため、その頂点におけるそのサイクルの正味の寄与はゼロになります。 すべてのサイクルを合計すると、すべての頂点で正味フローがゼロになります。 すべてのエッジは何らかのサイクルに属しているため、すべての頂点はすべての入射エッジにわたってバランスの取れた入力および出力の合計を持ちます。 これにより、保存制約がグローバルに満たされることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    T = int(input())
    for tc in range(1, T + 1):
        F, P = map(int, input().split())
        adj = [[] for _ in range(F)]
        edges = []

        for i in range(P):
            a, b = map(int, input().split())
            a -= 1
            b -= 1
            adj[a].append((b, i))
            edges.append((a, b))

        used = [False] * P
        ans = [0] * P

        # build undirected connectivity for component grouping
        und = [[] for _ in range(F)]
        for i, (a, b) in enumerate(edges):
            und[a].append(b)
            und[b].append(a)

        visited = [False] * F

        def dfs(u, comp):
            visited[u] = True
            comp.append(u)
            for v in und[u]:
                if not visited[v]:
                    dfs(v, comp)

        for i in range(F):
            if not visited[i]:
                comp = []
                dfs(i, comp)

                # collect edges in component
                comp_edges = []
                for u in comp:
                    for v, idx in adj[u]:
                        if not used[idx]:
                            comp_edges.append(idx)

                # attempt cycle decomposition using stack
                stack = []
                ptr = {u: 0 for u in comp}
                local_adj = {u: [] for u in comp}
                for u in comp:
                    for v, idx in adj[u]:
                        if not used[idx]:
                            local_adj[u].append((v, idx))

                for start in comp:
                    while ptr[start] < len(local_adj[start]):
                        stack = [(start, 0)]
                        path = []
                        seen_edge = {}

                        while stack:
                            u, it = stack.pop()
                            if it == len(local_adj[u]):
                                continue
                            v, idx = local_adj[u][it]
                            local_adj[u][it] = local_adj[u][it]  # placeholder
                            stack.append((u, it + 1))
                            if used[idx]:
                                continue
                            used[idx] = True
                            path.append((u, v, idx))
                            stack.append((v, 0))

                        if path:
                            k = len(path)
                            for i, (_, _, idx) in enumerate(path):
                                ans[idx] = 1 if i % 2 == 0 else -1

        if any(v == 0 for v in ans):
            print(f"Case #{tc}: IMPOSSIBLE")
        else:
            print("Case #{}: {}".format(tc, " ".join(map(str, ans))))

if __name__ == "__main__":
    solve()
```この解決策は、有向グラフを読み取り、インデックス付きのエッジを保存することから始まり、後で出力を割り当てることができるようになります。 また、切断された部分間の循環は不可能であるため、接続されているコンポーネントを識別するための無向隣接リストも構築します。 

各コンポーネント内で、トラバーサルを介してすべてのエッジを消費し、それらをサイクル パスに割り当てようとします。 未使用の有向エッジのシーケンスを横断するたびに、サイクルに近づく必要があるパスを形成します。 そうしないと、残ったエッジが未使用のままになり、不可能であることがわかります。 

検出された各サイクルに沿った交互の割り当てにより、頂点のバランスが暗黙的に強制されます。 実装の微妙な点は、すべてのエッジが 1 回だけ使用されるとマークする必要があることです。 これが欠けていると、重複した割り当てまたは未割り当てのエッジが発生し、どちらも無効になります。 

## 実用的な例

 3 つの頂点の単純なサイクルを考えてみましょう。 

入力エッジ: 1→2、2→3、3→1。 

トラバースを 1 から開始します。 

| ステップ | 現在のノード | 使用エッジ | パス |
 | --- | --- | --- | --- |
 | 1 | 1 | 1→2 | 1→2 |
 | 2 | 2 | 2→3 | 1→2→3 |
 | 3 | 3 | 3→1 | 1→2→3→1 |

 サイクルが完了したので、サイクルに沿って値 +1、-1、+1 を割り当てます。 各頂点は 1 つの入力寄与と 1 つの出力寄与を受け取るため、バランスが保たれます。 

次に、切れたチェーン 1→2、2→3 とエッジのない 3→1 を考えます。 

トラバースの結果:

 | ステップ | 現在のノード | 使用エッジ | パス |
 | --- | --- | --- | --- |
 | 1 | 1 | 1→2 | 1→2 |
 | 2 | 2 | 2→3 | 1→2→3 |

 パスはサイクルに閉じず、頂点 3 には外への継続がないままになります。 これは、頂点 3 が保存を満たすことができないため、不可能であることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(F + P) | 各エッジは、トラバース中に 1 回だけ訪問され、割り当てられます。 
| スペース | O(F + P) | エッジの隣接リストとブックキーピング |

 この制約では最大数千のエッジが許可されるため、線形トラバースは問題なく制限内に収まります。

 ## 特殊なケース

 単一の有向エッジは、そのソースの出力合計が正で入力合計が 0 であるのに対し、宛先は逆の不均衡を持っているため、すでに制約に違反しています。 サイクルを形成できず、エッジが未使用のままになるため、アルゴリズムはこれを検出します。 

純粋なサイクルは常に有効であり、トラバーサルがコンポーネントごとに 1 回だけ終了し、バランスのとれた割り当てが生成されるため、クリーンに処理されます。 

トラバースが原点に戻れず、残りのエッジが未使用のままになるため、チェーン構造は失敗します。 これは、循環ではすべてのエッジが閉ループの一部である必要があるため、サイクル分解ステップでの不可能性を直接明らかにします。
