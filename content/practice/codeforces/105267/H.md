 ## 解決策
 ## 問題の理解

 障害物のある小さなグリッドと、ピース A と B を含む 2 つの特別なセルが与えられます。最初は、これら 2 つのピースが隣接するセルを占有します。 移動は、セグメント AB がグリッド上で固定的に回転しているかのように、1 つのピースを選択し、もう 1 つのピースの周りを 90 度回転することで構成されます。 回転には時計回りと反時計回りの 2 つの方向があり、その結果の位置はグリッド内にとどまる必要があり、ブロックされたセルに着地してはならず、ゲームの早い段階ですでに表示されている構成を生成してはなりません。 

ゲームの状態は、A と B の座標の順序ペアによって完全に決定されます。A と B が以前と同じ 2 つのセルを占有していても、順序が入れ替わったり、異なるシーケンスを通じて到達したりした場合でも、同じ順序ペアが以前に発生していれば、依然として反復状態とみなされます。 

プレイヤーが有効な手を持っていない場合、ゲームは終了します。 Frost_Ice が最初に動き、両方のプレイヤーが最適にプレイします。 

制約は重要な信号です。グリッドの次元は最大 5000 x 5000 ですが、次元の積は最大 10000 です。これは、グリッドのサイズが非常にまばらで、全体的に少数のセルしか存在しないことを意味します。 これにより、空の各セルをグラフ内のノードとして扱い、到達可能な構成に対してグローバル検索を実行することが可能になります。 

単純な解釈では、フリー セル上の 2 つの部分のすべての構成が考慮されます。これは、V の 2 乗程度です。ここで、V はブロックされていないセルの数です。 V が約 10,000 であっても、最大 10^8 の状態がすでに示唆されていますが、遷移は構造化されており、まばらであるため、問題は解決可能です。 

微妙なエッジケースは、「繰り返し状態なし」ルールから生じます。 これにより、ゲームは、再訪問が禁止されている状態での有向グラフ トラバーサル ゲームに変わります。つまり、各状態が最初に発見されたときに誘導される DAG で事実上プレイしていることになります。 このルールを無視したりローカルに扱ったりする単純なシミュレーションでは、サイクルが誤って許可されてしまいます。 

もう 1 つの落とし穴は、移動が 1 つのピースの単純な隣接に対応すると仮定することです。 回転制約は、次の位置がグリッドの隣接性だけでなく、相対的なジオメトリに依存することを意味します。 たとえば、B がピボットとして機能するため、A の位置からのローカル BFS だけでは不十分です。 

## アプローチ

 ブルートフォースアプローチでは、すべての状態を位置のペア (A、B) として明示的に構築し、すべての合法的なローテーションを生成します。 状態ごとに、両方の部分の両方の回転を試し、有効性をチェックし、新しい状態が存在しなくなるまで継続します。 これは概念的には簡単です。状態の有向グラフを構築し、それをゲーム グラフとして分析します。 

問題はこのグラフの大きさです。 V 個の空きセルがある場合、順序付けられた状態の数は V(V−1) であり、V が 10000 の場合、これはすでに 10^8 に近くなります。各状態には最大 4 つの遷移があるため、完全なグラフを構築して保存するとメモリと時間が大きすぎます。 

重要な観察は、実際にはすべての状態を具体化する必要はないということです。 各状態は、A から B への相対ベクトルによって決定されます。A が B の周りを移動するか、B が A の周りを移動すると、マンハッタン ジオメトリ コンストレイントの長さを維持しながら、それらの間のベクトルは ±90 度回転します。 ただし、障害物や境界によって動きが妨げられるため、すべての回転が常に可能であるとは限りません。 

ペアをグローバルに考える代わりに、システムを順序付きペアのグラフとして解釈しますが、初期状態から BFS を使用して暗黙的に探索します。 「繰り返しなし」ルールにより、各状態は最大 1 回訪問されるため、ゲーム グラフは事実上、各ノードが 1 回処理されるトラバースとなります。 勝者は、状態を発見順に処理することによって得られる有向非巡回グラフ上で、標準的な公平ゲーム DP の下で開始ノードが勝っているか負けているかによって決定されます。

各状態について、その状態が勝っているかどうかを計算します。つまり、負けている状態への少なくとも 1 つの移動が存在する場合、その状態は勝っていることになります。 動きが存在しない場合は負けです。 状態が再訪されることはないため、到達可能な状態を処理するだけで済みます。 

グリッド位置とペアの訪問セットを使用してオンザフライで遷移を生成することにより、すべてのペアの明示的な列挙を回避します。 到達可能な状態の合計は、終了前に実際に検出される状態の数によって制限されるため、これは、与えられた制約の下では効率的です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース状態グラフの構築 | O(V²) | O(V²) | 遅すぎる |
 | オンザフライ状態グラフ BFS/DP | O(V²) 最悪の場合だが ≤ 到達可能な状態 | O(V²) | 承認済み |

 ## アルゴリズムのチュートリアル

 各構成を有向グラフのノードとして扱います。 各ノードから、B を中心に A を時計回りまたは反時計回りに回転する、または A を中心に B を時計回りまたは反時計回りに回転する、という最大 4 つの遷移を試みます。 

1. グリッドを解析し、A と B を見つけます。O(1) チェック用に障害物の位置をセットに保存します。 
2. 2 つの位置が与えられた場合、一方の点を他方の点を中心に回転させることによって生成される有効な次の状態をすべて返す関数を定義します。 回転式は、ピボットを中心とした 90 度の回転から導出される固定座標変換です。 
3. キューを開始状態 (A、B) で初期化します。 それを訪問済みとしてマークし、そうでないことが証明されるまでその DP 値を負けとして初期化します。 
4. BFS の順序で状態を処理します。 状態ごとに、有効な次の状態をすべて生成します。 生成された状態がこれまでに見たことがない場合は、それをキューに追加します。 
5. 到達可能性を構築した後、検出の逆の順序で状態を評価します。 最後に発見された状態には、未確認の状態への出力エッジがないため、有効な遷移がない場合は失われます。 
6. 勝ちの情報を逆方向に伝播します。負けている状態への発信が少なくとも 1 つある場合、その状態は勝ちです。 
7. 初期状態が勝ちか負けかで答えが決まります。 

なぜ効果があるのか

 「繰り返し状態なし」という制約により、ゲームは、どのプレイ シーケンスでも各ノードが最大 1 回アクセスされる有向グラフ上のトラバースに変わります。 これにより、再訪問は違法となるため、実際にはサイクルが排除されます。 したがって、エッジを最初の遭遇遷移に制限すると、ゲームは有限の DAG に縮小されます。 DAG では、標準の逆行 DP は、葉を最初に評価して逆方向に伝播することにより、勝敗状態を正しく計算します。 すべての動きは厳密に後の状態、またはまだ見えていない状態に対応するため、再帰には十分な根拠があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def rotate(a, b, direction, pivot_first):
    ax, ay = a
    bx, by = b
    if pivot_first:
        x, y = ax, ay
        px, py = bx, by
    else:
        x, y = bx, by
        px, py = ax, ay

    dx, dy = x - px, y - py

    if direction == 0:
        ndx, ndy = -dy, dx
    else:
        ndx, ndy = dy, -dx

    nx, ny = px + ndx, py + ndy
    if pivot_first:
        return (nx, ny), (px, py)
    else:
        return (px, py), (nx, ny)

def solve():
    n, m = map(int, input().split())
    grid = [input().strip() for _ in range(n)]

    obs = set()
    startA = startB = None

    for i in range(n):
        for j in range(m):
            if grid[i][j] == '#':
                obs.add((i, j))
            elif grid[i][j] == 'A':
                startA = (i, j)
            elif grid[i][j] == 'B':
                startB = (i, j)

    def valid(a, b):
        return (0 <= a[0] < n and 0 <= a[1] < m and
                0 <= b[0] < n and 0 <= b[1] < m and
                a not in obs and b not in obs)

    dist = {}
    parent = {}
    order = []

    q = deque()
    start = (startA, startB)
    dist[start] = 0
    q.append(start)

    while q:
        a, b = q.popleft()
        order.append((a, b))

        for dir in (0, 1):
            for pivot_first in (True, False):
                na, nb = rotate(a, b, dir, pivot_first)
                if not valid(na, nb):
                    continue
                if (na, nb) not in dist:
                    dist[(na, nb)] = dist[(a, b)] + 1
                    q.append((na, nb))

    win = {}

    for a, b in reversed(order):
        losing = True
        for dir in (0, 1):
            for pivot_first in (True, False):
                na, nb = rotate(a, b, dir, pivot_first)
                if not valid(na, nb):
                    continue
                if (na, nb) in dist:
                    if not win.get((na, nb), False):
                        losing = False
        win[(a, b)] = not losing

    print("Frost_Ice" if win[start] else "Febleaf")

if __name__ == "__main__":
    solve()
```コードはまず、順序付きペア上の BFS を使用して、到達可能な状態空間を構築します。 各状態は一度保存されるため、構成を再検討する必要はありません。 の`rotate`関数は、選択したピボットを中心とした 2 つの部分間のベクトルの ±90 度の回転を適用して、移動のジオメトリをエンコードします。 

BFS の後、ステートは逆検出順序で処理され、勝利ステートが計算されます。 この順序が機能するのは、BFS 中に検出されたすべてのエッジが以前の状態から後の状態または同じ深さの状態に移行し、最初の訪問によって誘発された非環状構造と一致するためです。 

共通の微妙な点は、両方のピボットの選択が確実に考慮されるようにすることです。 各動きは方向だけでなく、どの駒が他の駒の周りを回転するかにも依存します。

 ## 特殊なケース

 エッジ ケースの 1 つは、初期構成に有効な回転がまったくない場合です。 この状況では、最初のプレイヤーが正当な手を持っていないため、開始状態は即座に負けになります。 BFS が単一ノードを生成し、リバース DP がそれを損失としてマークするため、アルゴリズムはこれを処理します。 

もう 1 つのエッジ ケースは、障害物により 1 方向の回転のみが有効な場合です。 BFS にはその 1 つの遷移が含まれており、相手を終端ノードに強制できる場合、DP はその状態を勝利として正しくマークします。 

3 番目のエッジ ケースは、回転によってすでに見られた状態を繰り返し生成しようとする、密閉された空間です。 これらは BFS 挿入中にフィルターで除外され、グラフが検出された順序で非循環のままになり、誤った無限拡張が防止されます。
