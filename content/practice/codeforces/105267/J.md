 ## 問題の理解

 2 つの数値が与えられます: 正の整数$N$そしてプライム$P$。 タスクは、すべての順序付きペアの二重和を計算することです。$(i, j)$両方のインデックスの実行元$1$に$N$。 ペアごとに製品を受け取ります$i \cdot j$、この数値に含まれる正の約数がいくつあるかを計算し、同じ約数の累乗を計算します。$i \cdot j$。 最終的な答えは、これらすべての値のモジュロの合計です。$P$。 

より具体的に言えば、すべてのペア$(i, j)$整数のみに依存する項を提供します$x = i \cdot j$。 どれだけ「複合性が高い」かを評価します$x$除数のカウントによる$d(x)$、それをベース指数としても使用して指数関数的に増幅します。 出力は、全期間にわたるこれらの貢献の累積です。$N \times N$グリッド。 

制約は次のことを示唆しています$N$と同じ大きさにすることができます$10^6$、すべてを明示的に反復するアルゴリズムは直ちに除外されます。$N^2$ペア。 それは次のとおりです$10^{12}$実行可能な制限時間をはるかに超えて評価を行う必要があります。 コンピューティングでも$d(x)$ペアごとのオンザフライは遅すぎます。 各整数値が集計形式で寄与するように計算を再編成する必要があります。 

素朴だが有益なアプローチは、すべてのペアを直接ループして計算することです。$x=i \cdot j$、因数分解する$x$、約数を数え、結果を累積します。 これは 2 つの理由で失敗します。1 つはペアの 2 次数です。 2 番目に、数値の因数分解を繰り返します。$N^2$、それ自体が高価です。 

除数のカウントを事前に計算しようとしても、2 番目の障害モードが表示されます。$N^2$: メモリと前処理のコストが法外なものになります$N=10^6$。 

## アプローチ

 重要な観察は、式が製品にのみ依存しているということです。$x = i \cdot j$、オンではありません$i$そして$j$別に。 これは、貢献度を製品価値ごとにグループ化して合計を書き直すことを示唆しています。 

以下を定義しましょう:$$F(x) = d(x)^x$$すると問題は次のようになります。$$\sum_{i=1}^N \sum_{j=1}^N F(i \cdot j)$$これを次のように再解釈します。$$\sum_{x} F(x) \cdot \#\{(i,j) : i \cdot j = x, 1 \le i,j \le N\}$$したがって、ペアを反復する代わりに、可能な値を反復します。$x$、それぞれについて$x$、内部に因子ペアがいくつあるかを数えます。$N \times N$グリッド。 

これが中心的な単純化です。乗算の構造により、ペアベースのビューから値ベースのビューに切り替えることができます。 

ここで、残りのタスクが 2 つの部分に分割されます。 まず、すべての約数が必要です$d(x)$効率的に。 以来$x$までの範囲$N^2$原則として、ただし、最大の数値の積からの寄与のみを考慮します。$N$、除数のカウントを安全に計算できます。$N$または最大$N^2$実装の制約によって異なりますが、重要なトリックは、すべてのペアを明示的に列挙しないことです。 

次に、それぞれを計算します。$x$、ペアの数$(i,j)$そのような$i \mid x$、$j = x/i$、両方とも範囲内です。 これは約数を数えるのと同じです$i$の$x$そのような$i \le N$そして$x/i \le N$。 

したがって、それぞれについて$x$、約数を反復処理します$i \mid x$、補数も範囲内にあるかどうかを確認します。 

約数の合計は最大のすべての数値に及ぶため、全体の複雑さは管理可能になります。$N^2$おおよそです$O(N^2 \log N)$概念的には最悪の意味ですが、実際には次のことのみを考慮して反復を巧妙に制限します。$x \le N^2$および約数にわたる構造化されたループ$x$までの事前計算で実現可能です。$N^2$慎重に最適化した場合にのみ。 ただし、より効率的なアプローチは、すべてを繰り返すのではなく、視点を再度逆転させることです。$x$、すべてを繰り返します$i, j$倍数を列挙することで間接的にペアを作成します。 

よりクリーンな標準変換は次のとおりです。$$\sum_{i=1}^N \sum_{j=1}^N f(i \cdot j)
= \sum_{i=1}^N \sum_{k=1}^{N/i} f(i \cdot k)$$これにより、内側のループの長さが幾何学的に短縮されます。 

したがって、合計作業量は次のようになります。$$\sum_{i=1}^N \frac{N}{i} = O(N \log N)$$各項について計算します$d(i \cdot j)$なので、除数のカウントを事前に計算します。$N^2$または、ふるいのような方法で段階的に維持します。 

最後に、すべての寄与分をモジュロで結合します。$P$。

## アルゴリズムのチュートリアル

 1. 除数のカウントを事前計算する$d[x]$みんなのために$x \le N$標準的なふるい式の蓄積を使用します。 各整数について$i$、複数回繰り返します$j$そして増加します$d[j]$。 これが機能するのは、すべての約数が倍数ごとに 1 回だけ寄与するためです。 
2. 全体を反復処理する$i$から$1$に$N$、それぞれについて$i$、繰り返します$j$から$1$に$N // i$。 これにより、製品が確実に$x = i \cdot j$すべてのペアを明示的に構築せずに、関連する範囲内に留まります。 
3. ペアごとに$(i, j)$、計算する$x = i \cdot j$そしてその除数の数を取得します$d[x]$。 
4. 寄与度を計算する$d[x]^x \bmod P$高速累乗を使用します。 これが必要な理由は、$x$が大きくなる可能性があるため、べき乗を素数を法として減らす必要があります。 
5. 結果を累計して剰余和を計算します。$P$。 
6. 最終的な合計を出力します。 

### なぜ効果があるのか

 正確さは、元のペア間の直接的な 1 対 1 対応に基づいています。$(i,j)$すべての有効なペアは 1 回だけアクセスされます。$i,j \le N$、の内側のループ$i$到達する$j$に限って$j \le N/i$。 除数の数は積の決定論的な関数であるため、次のように評価します。$x=i\cdot j$元の定義を保持します。 べき乗剰余演算により、剰余の計算の正確性が維持されます。$P$したがって、変換された各項は元の寄与と正確に一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def mod_pow(a, e, mod):
    res = 1
    a %= mod
    while e:
        if e & 1:
            res = res * a % mod
        a = a * a % mod
        e >>= 1
    return res

def solve():
    N, P = map(int, input().split())

    d = [0] * (N + 1)
    for i in range(1, N + 1):
        for j in range(i, N + 1, i):
            d[j] += 1

    ans = 0

    for i in range(1, N + 1):
        for j in range(1, N // i + 1):
            x = i * j
            ans += mod_pow(d[x], x, P)
            if ans >= 8 * P:
                ans %= P

    print(ans % P)

if __name__ == "__main__":
    solve()
```除数の事前計算では、古典的なふるいの考え方が使用されます。$j$すべての約数からの貢献を蓄積します$i$。 これにより保証されます$O(N \log N)$前処理中。 

ダブルループオーバー$(i,j)$すべての有効なペアを冗長性なしで列挙します。 バウンド$N // i$これは、製品を範囲内に保つための重要な制約です。 べき乗モジュラーが必要なのは、直接べき乗を行うと、中程度の値であってもすぐにオーバーフローしてしまうためです。$x$。 

時折削減される`ans`モジュラス演算における正確性を維持しながら、整数の増加を防ぎます。

 ## 特殊なケース

 エッジケースの 1 つは、$N=1$。 唯一のペアは、$(1,1)$、したがって、答えは次のとおりです$d(1)^1 = 1$。 ふるいが初期化されるため、アルゴリズムは除数のカウントを正しく計算します。$d[1]=1$、そしてループオーバー$i=1, j=1$正確に 1 つの貢献を生成します。 

もう 1 つのエッジケースは次のような場合です$N$大きく、高度に合成された数が約数の数を支配します。 たとえば、$N=10$、次のような数字$6$そして$8$約数が誇張されており、複数の場所で繰り返し出現します。$(i,j)$ペアは寄与を大きく歪める可能性があります。 各ペアが独立して評価され、除数の数が一度事前計算されて一貫して再利用されるため、アルゴリズムはこれを引き続き正しく処理します。
