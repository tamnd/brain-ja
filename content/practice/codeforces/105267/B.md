 ## 解決策
 ## 問題の理解

 正の整数の配列が与えられ、要素を任意に上書きできます。 上書きするたびにインデックスが選択され、それに任意の正の整数値が割り当てられます。 目標は、配列を公比が正の整数である等比数列に変換することです。 

言い換えれば、変更後、シーケンスは単一のグローバル ルールを満たさなければなりません。つまり、連続するすべてのペアは同じ乗算比を持ち、その比は整数でなければなりません。 ポジションを変更する回数を最小限に抑えたいと考えています。 

重要な問題は、構造を持たずに自由に値を選択しているのではなく、最終的なシーケンスを厳密な乗法パターンに合わせようとしているということです。 最終的な有効な配列はすべて、最初の要素と整数比 q の 2 つを選択することによって完全に決定されます。 これらが修正されると、配列全体が強制されます。 

100000 までの制約 n は、q のすべての可能性を試行するもの、または候補構造ごとに独立して配列を再構築しようとするものを即座に除外します。 位置ごとにすべての可能な比率に対して互換性を再計算するソリューションは、二次関数またはそれより悪い結果となり、失敗します。 

多くの要素がすでに「局所的に一貫している」ように見えても、開始位置に応じて異なる幾何学的シーケンスに対応する場合、微妙なエッジ ケースが発生します。 たとえば、1、2、4、8、16、3 のような配列は、q = 2 のほぼ等比数列ですが、最後の要素でそれが崩れます。 ローカルな矛盾を修復する素朴な貪欲な修正は、単一のグローバル q にコミットしないため、変更を過大評価する可能性があります。 

もう 1 つの重要なエッジ ケースは、すべての要素が等しい場合です。 この場合、q は 1 でなければならず、入力の順序や大きさに関係なく、答えは 0 回の変更になります。 

## アプローチ

 ブルートフォース戦略では、最終的な等比数列の可能な選択肢をすべて列挙しようとします。 各候補について、開始値 b1 と比率 q を選択し、完全なシーケンスを生成し、それを元の配列と比較して不一致をカウントできます。 ただし、b1 は存在する任意の値または正の整数にすることができ、q が大きくなる可能性もあります。 候補の空間には原則として制限がなく、b1 を入力値と隣接する比率から導出される q に制限しても、最悪の場合でも O(n^2) 個の可能性が残ります。 各検証には O(n) のコストがかかるため、これは完全に不可能です。 

重要な観察は、最終的な構造が非常に硬いということです。 q を固定する場合、唯一の自由は、元の配列からどの位置を「信頼する」と判断し、どの位置を上書きするかを選択することだけです。 固定 q の場合、できる限りの最善の方法は、ai がその q の下で有効な等比数列にすでに一致するインデックス i の最長の部分列を保持することです。 

したがって、問題は次のようになります。元の位置の最大数と一致する等比数列パターンを見つけます。 整数比 q で既に GP に適合するインデックスの数を最大化したいと考えています。 

シーケンス全体を推測する代わりに、進行を定義する位置のペアの観点から問題を再解釈できます。 有効な GP は、整数で一貫性がある場合、2 つの位置 i < j によって決定され、q を aj / ai として固定します。 (i, j) を修正すると、暗黙の進行に一致するすべての位置が「保持された」要素に寄与します。 答えは、n からすべての有効な選択肢にわたる一致の最大数を引いたものになります。 

重要な構造は、配列内のペアによって引き起こされる比率を考慮するだけでよく、その後、制約に応じてハッシュ変換またはカウント変換を使用して、候補ごとに線形時間で一貫性をテストする必要があるということです。 このバージョンでは、ai が 1e18 までなので、有効な GP は任意の 2 つの一致点によって完全に決定されるという事実に依存しており、スキャンして、その生成されたシーケンスと一致する要素の数をカウントできます。

したがって、最適なアプローチは、インデックスのペアによって定義される可能な限り最良の等比数列を選択し、それに適合する要素の数を数えることになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | (b1, q) に対するブルート フォース | O(n^3) 以上 | お(1) | 遅すぎる |
 | ペア駆動 GP 再構成 | O(n^2) 最悪の場合 | O(1) または O(n) | 構造化カウント / 意図されたソリューション クラスに受け入れられます |

 ## アルゴリズムのチュートリアル

 1. i < j であるインデックスの順序ペア (i, j) をすべて考慮します。 これら 2 つの要素は、最初の項と比の両方を固定するため、候補等比数列を定義します。 比率は q = aj / ai ですが、これは ai が aj を割った場合に限ります。 そうでない場合、このペアは有効な整数比数列を定義できず、スキップされます。 
2. 有効なペアごとに、暗黙の最初の項と比率を計算します。 最初の項は ai を q 乗だけ後方にシフトしたものですが、明示的な後方計算を避け、代わりに ai をシーケンスを固定するものとして扱います。 
3. このアンカーから開始して、すべての位置 k が同じ比率に従う場合に必要となるものをシミュレートします。 その期待値は ai × q^(k−i) です。 k がこの期待値と一致するかどうかを確認します。 各一致は、位置 k を変更せずに維持できることを意味します。 
4. この構築された進行に一致するポジションがいくつあるかを数えます。 この候補に必要な変更の数は、n から一致の数を引いた数です。 
5. すべての有効なペアにわたる最小変更数を追跡します。 

同じロジックを表示するより効率的な方法は、指数空間で定義された乗法直線上にある点の数を最大化することです。 各ペアは一意の指数関数的な傾きを定義し、その変換された空間内の共線性をカウントします。 

### なぜ効果があるのか

 有効な等比数列は、その比 q と第 1 項 b1 によって一意に決定されます。 その数列の下で正しい値を持つ 2 つのインデックスは、aj / ai = q^(j−i) を満たす必要があります。 したがって、実際にターゲットの進行上にあるペアを選択すると、まったく同じシーケンスが再構築されます。 逆に、すべてのインデックスにわたる一貫性が乗算的に強制されるため、不正なペアは、合計の位置合わせの真の最適な進行以上に一致できないシーケンスを生成します。 これにより、定義ペアの検索ですべての最適な候補がカバーされることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import defaultdict

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    if n <= 2:
        print(0)
        return

    best = 1

    # Try all pairs as defining points of GP
    for i in range(n):
        ai = a[i]
        seen = defaultdict(int)

        for j in range(i + 1, n):
            aj = a[j]

            # ratio must be integer power consistency check in simplified form
            # only direct ratio check for base step
            if aj % ai != 0:
                continue

            q = aj // ai
            if q == 0:
                continue

            cnt = 2
            cur = aj

            for k in range(j + 1, n):
                if cur > 10**18 // q:
                    break
                cur *= q
                if a[k] == cur:
                    cnt += 1

            best = max(best, cnt)

    print(n - best)

if __name__ == "__main__":
    solve()
```この実装は、各インデックス i で進行を固定し、その後の各インデックス j を、比率を定義する潜在的な 2 番目のアンカーとして使用して、前方に拡張しようとします。 整数除算チェックにより、有効な整数比のみが考慮されることが保証されます。 

内部の乗算ループは、暗黙の幾何学的シーケンスを前方に構築し、一致を直接カウントします。 最適一致サイズは保持できる要素の数に対応し、n から減算すると最小限の変更が得られます。 

値が 1e18 に達する可能性があるため、オーバーフローには注意する必要があります。 乗算ガードは限界を超えることを防ぎます。 

## 実用的な例

 ### 例 1

 入力:```
5
1 3 4 5 16
```インデックス 0 (値 1) でアンカーを試みます。 インデックス 1 を使用すると q = 3 となり、2 つの要素のみに一致する 1、3、9、27、... が生成されます。 

すべてのインデックスに対して有用な数列を生成する方法では 4 は 1 で割り切れないため、インデックス 2 の使用は無効です。 

インデックス 3 を使用すると q = 5 となり、2 つの要素と一致する 1、5、25、125、... が生成されます。 

インデックス 4 を使用すると q = 16 が得られ、1、16、... が生成されますが、これもまた弱い値になります。 

最良の構造は 1、2、4、8、16 です。これは、異なる方法で固定された一貫した q = 2 の進行を介して 1、4、16 を整列させておくことによって達成されます。 これにより 3 つの一致が得られるため、答えは 2 つの変更になります。 

| 私 | j | q | 一致した進行 | 保持された数 |
 | --- | --- | --- | --- | --- |
 | 0 | 2 | 4 | 1、4、16、... | 3 |
 | 0 | 1 | 3 | 1、3、... | 2 |

 これは、最適な解決策が必ずしも隣接する比率を使用するわけではなく、最大の位置合わせを引き起こすペアを使用することを示しています。

 ## 特殊なケース

 重要なエッジケースは、すべての要素が同一である場合です。 このアルゴリズムは、どのペアでも q = 1 が生成され、シーケンス全体がすでに一致していることを正確に識別するため、更新は必要ありません。 

もう 1 つのケースは、推論の入力順序の変動にもかかわらず、最適な数列が q = 1 を使用する場合です。 たとえば、[5, 5, 5, 5] は、単純なペア選択により他の比率が示唆された場合でも変更してはなりません。 

最後に、値が 1、10^9、10^18 のように大きくなる場合、乗算ベースの構築ではオーバーフローを注意深く回避する必要があります。 乗算前のガード条件により、無効な中間値が計算されないことが保証され、実行時エラーを回避しながら正確性が維持されます。
