 ## 問題の理解

 固定数のグローバル変換を通じて進化する、長さ n の配列の小さなシステムが与えられています。 配列から始めます`a`を繰り返し正確に適用します`u`操作。 各操作は、固定配列と組み合わせることにより、配列のすべての要素を一度に変更します。`b`ビットごとの XOR を使用するか、指定された置換に従って配列を置換することによって`p`そして定数を追加します`r`。 

すべての操作を実行した後、結果の配列と 2 つの追加の配列に応じて最終スコアを計算します。`k`そして`b`。 スコアはポジションに対して加算されるため、最終的な値が決まると、各インデックスは独立して寄与します。`a`知られています。 

重要な構造上の困難は、操作がグローバルかつ構成的であることです。操作を順番に適用すると、XOR 変換、置換、および加算シフトが複雑に混在することになります。 以来`n ≤ 30`そして`u ≤ 30`、大規模なデータを扱っているわけではありませんが、すべての可能性を明示的に追跡しようとすると、指数関数的な状態空間を扱っていることになります。 この問題は本質的に、有限領域上で少数の線形のような変換を構成し、最適な結果を評価することに関するものです。 

順列と加算の間の相互作用から微妙な問題が発生します。 単純な実装では、xor と順列を独立して扱う可能性がありますが、順列は将来の追加が到着する場所で変化するため、順序は非可換的に重要になります。 もう 1 つのよくある落とし穴は、すべての操作シーケンスをインデックスごとに独立したものとしてシミュレートしようとすることです。 これは、インデックスが順列で混在するため、各ポジションの履歴が他のポジションに依存するため失敗します。 

素朴な推論による具体的な失敗例は、各インデックスが独立して進化すると仮定することです。 もし`p`のようなサイクルです`1 → 2 → 3 → 1`の場合、単一のシフト操作でも値が回転します。これは、インデックスの寄与を意味します。`i`ローカル更新だけでなく、サイクル履歴全体に依存します。 

## アプローチ

 ブルートフォースのアイデアは、考えられるすべての操作シーケンスを段階的にシミュレートし、結果の配列を計算することです。 ただし、問題は操作を選択することではなく、順序は固定されています。 本当の難しさは、各操作が状態全体を変換するため、ブルート フォースは各ステップの後に配列の完全な状態を追跡する必要があることです。 

簡単なシミュレーションが実行可能である理由は、`n ≤ 30`そして`u ≤ 30`。 各操作を配列全体に明示的に適用できます。 課題は、最終的なスコアも評価する必要があることです。このスコアは、最終的な値だけではなく、配列間のペアの関係に依存します。 これは、単に追跡するのではなく、`a`、各初期基礎要素が最終結果にどのように寄与するかを追跡する必要があります。 

重要な観察は、xor と加算によって引き起こされる有限体構造にわたる線形性です。 各演算は、2 種類の線形アクションによる整数上のベクトル空間上の変換です。xor は GF(2^k) の加算のように機能し、順列は線形の再インデックス付けであり、次の加算です。`r`個別に追跡できる一定のシフトが導入されます。 なぜなら`u`が小さい場合、各初期位置の基底寄与に適用される一連の変換としてシステムをモデル化できます。 

すべての可能な値を直接シミュレートする代わりに、元の各要素がどのように変化するかを追跡します。`a`最終的な配列に寄与し、重み付けされた寄与を集計します。`k`そして`b`。 これにより、問題は 2 つの演算の下で基底ベクトルの変換を維持し、最終的な重み付けされた合計を計算することになります。

 ## アルゴリズムのチュートリアル

 このプロセスは、各初期インデックスが各最終インデックスにどのように寄与するかを維持するものであると解釈します。 

1. 現在の状態を、元のインデックスから現在の値へのマッピングとして表します。 最初は、各ポジションはそれ自体にのみ貢献します。 

これにより、構造を値から分離することができます。 
2. 演算タイプ 1 の場合、固定配列を使用してビットごとの XOR を適用します。 これは、各現在の値が定数項と組み合わせることで独立して変更されることを意味するため、インデックス構造を変更せずに各マッピングの値部分を更新します。 
3. 演算タイプ 2 の場合、順列を適用して加算します。`r`。 順列ステップでは、コントリビューション (位置にあったすべてのコントリビューション) を再配置します。`i`位置に移動します`p[i]`。 加算ステップでは、すべての値が次のように増加します。`r`置換後は一様に。 
4. 繰り返します`u`構造マッピングと蓄積された一定のシフトの両方を維持する操作。 
5. すべての操作の後、貢献度を集計して最終スコアを計算します。ポジションごとに、その最終値を次の値と組み合わせます。`k[i]`そして、指定されたスコアリングルールを使用して回答に累積します。 

重要な考え方は、順列は構造に影響を与え、xor と加算は値に影響を与えるということです。 これらを分離しておくと、完全な履歴の再計算が回避されます。 

### なぜ効果があるのか

 すべての演算は状態空間上でアフィンです。順列は全単射の再ラベル付け、xor は可逆線形演算、加算は一様な変換です。 これらの操作は独立した基底寄与間の相互作用なしで構成されるため、各初期インデックスがどのように伝播するかを追跡するだけで十分です。 すべての変換はインデックス構造上で元に戻せるため、情報が失われることはなく、マッピングによって最終値が完全に決定されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, u, r = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    k = list(map(int, input().split()))
    p = list(map(int, input().split()))
    p = [x - 1 for x in p]

    # current value array
    cur = a[:]

    for _ in range(u):
        op = input().strip()
        if op == "1":
            for i in range(n):
                cur[i] ^= b[i]
        else:
            nxt = [0] * n
            for i in range(n):
                nxt[p[i]] = cur[i]
            for i in range(n):
                nxt[i] += r
            cur = nxt

    ans = 0
    for i in range(n):
        ans += cur[i] * k[i]

    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションはプロセスを直接シミュレートします。`n`そして`u`小さいです。 xor 演算は要素ごとに適用され、並べ替え演算は、各要素が以下に従って移動する新しい配列を構築することによって処理されます。`p`。 の追加`r`同時更新要件を尊重して、置換後に適用されます。 

最終スコアは、次を使用して加重合計として計算されます。`k`。 制約は完全なシミュレーションに十分に厳しいため、中間の最適化は必要ありません。

 ## 特殊なケース

 エッジ ケースの 1 つは、すべての要素が等しい場合です。 この状況では、順列には目に見える効果はありませんが、XOR と加算は引き続き適用されます。 両方の演算が並べ替えの前後で要素ごとに動作し、同一のベクトルが変更されないため、アルゴリズムは均一性を正しく維持します。 

もう 1 つの特殊なケースは、単一要素の配列です。 順列は簡単になるため、効果は xor と加算を繰り返し適用することだけになります。 インデックス付けは単一の位置に縮退するため、シミュレーションではこれを自然に処理します。 

最後のケースは、操作がゼロの場合です。 最終的な答えは、変換を行わずに初期配列から直接計算する必要があります。 ループオーバー操作が完全にスキップされ、最終的な集計では元の集計が使用されるため、実装はこれを処理します。`cur`。
