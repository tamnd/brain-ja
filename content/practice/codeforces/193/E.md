 ## 問題の理解

 私たちには単一の番号が与えられています$f$そして、フィボナッチ ルールによって生成された無限シーケンスを検討しますが、モジュロ 1013 を使用します。シーケンスは 0 と 1 で始まり、次のすべての値は前の 2 つの値の合計で、モジュロ 1013 を減じたものになります。したがって、可能な残基は 1013 個しかないため、シーケンスは完全に決定され、時間の経過とともに値を繰り返します。 

タスクは、シーケンス自体を完全に計算することではなく、値が含まれる最も古いインデックスを見つけることです。$f$が表示されます。 値がシーケンス内に出現しない場合は、-1 を出力します。 

インデックス付けはゼロベースであるため、位置 0 は 0、位置 1 は 1、位置 2 は 1 などとなります。 

重要な制約は、モジュラスが 1013 であるということです。これは、ペアのシーケンスが$(F_i, F_{i+1})$最終的には繰り返す必要があり、周期的な動作を意味します。 ただし、ピリオドは尋ねられません。 最初の出現が求められるため、簡単なフォワード シミュレーションが可能になります。 

隠れた主な詳細は、フィボナッチ モジュロ数値は周期的ですが、周期の長さが十分に長くなる可能性があるため、すべてのペアを完全に列挙するという単純な考え方を慎重に制御する必要があるということです。 それでも、1013 は十分小さいため、訪問した状態を保存したり、境界付きプレフィックスをシミュレートしたりすることは可能です。 

微妙なエッジケースが現れるのは、$f = 0$。 最初の要素はすでに 0 に等しいため、答えはすぐに 0 になります。もう 1 つは次のとおりです。$f = 1$これはインデックス 1 に出現し、再びインデックス 2 に出現するため、最初に出現したもののみを返すようにする必要があります。 

それほど明白ではないエッジ ケースは、すべての値が次のとおりであるとは限らないことです。$[0, 1012]$ピリオドが繰り返される前に、1013 を法とするフィボナッチ数列に必ず出現します。 すべての残基が出現するという単純な仮定は、不正確な無条件の答えにつながります。 

## アプローチ

 最も直接的なアプローチは、インデックス 0 から開始して 1013 を法とするフィボナッチ数を 1 つずつ生成し、各ステップで現在の値が以下に等しいかどうかを確認することです。$f$。 シーケンスは決定的であるため、最終的には次のいずれかが見つかります。$f$またはサイクルに入ります。 

これが機能するのは、各項が前の 2 つの値のみに依存するためです。そのため、ローリング ペアを維持して前方に反復できます。 正確さは即座にわかります。ターゲットを見つけるか、繰り返しを終了するのに十分な状態を確認したと判断するまで、すべての位置を昇順にチェックします。 

無制限シミュレーションの問題は、フィボナッチ モジュロ 1013 がサイズの有限状態空間に存在することです。$1013 \times 1013$順序ペアを考慮した場合。 これにより、最終的な繰り返しが保証されますが、最悪の場合、繰り返されるペアが表示される前に長いプレフィックスをたどってしまう可能性があります。 それでも、この境界は約 100 万州にすぎず、安全です。 

より構造化されたビューは、状態をペアとして扱うことです。$(F_i, F_{i+1})$。 ペアが繰り返されると、その時点からのシーケンスが正確に繰り返されます。 したがって、ペアが繰り返され、まだ表示されていない場合はシミュレーションを停止できます。$f$、後で表示されることはありません。 

これにより、問題は 1,013 平方の状態を含む関数グラフにわたるグラフ走査に変換され、各状態には 1 つの後続状態が正確に存在します。 繰り返しが行われるまで、基本的に自転車道に沿って歩きます。

 ## アルゴリズムのチュートリアル

 インデックスを追跡している間、1013 を法とするフィボナッチ数列を維持します。 

1. 連続するフィボナッチ値を表す 2 つの変数を初期化します。$a = 0$、$b = 1$、インデックス$i = 0$。 これは、最初の 2 つの項がすでにわかっているシーケンスの開始に対応します。 
2. もし$a == f$、インデックス 0 が最初に出現するため、すぐに 0 を返します。 
3. 安全限界を超えていない間に繰り返します。$1013^2 + 5$ステップ、またはサイクル検出が停止するまで。 
4. 反復ごとに、比較します。$a$と$f$。 一致する場合は返します$i$。 これにより、インデックスの昇順でスキャンが行われるため、常に最も早い発生を報告することが保証されます。 
5. フィボナッチ数列を前方に進める: 次の値を計算します。$c = (a + b) \bmod 1013$。 
6. ペアを更新します: set$a = b$、$b = c$、インデックスをインクリメントします$i$。 これにより、次の不変条件が保存されます。$(a, b)$常に表します$(F_i, F_{i+1})$。 
7. オプションで訪問ペアを追跡する$(a, b)$。 ペアが繰り返される場合は、停止して -1 を返します。$f$見つかりませんでした。 これにより、サイクルに入った後に無限にループすることがなくなります。 

### なぜ効果があるのか

 すべてのステップで、アルゴリズムは次の不変条件を維持します。$a = F_i \bmod 1013$そして$b = F_{i+1} \bmod 1013$。 フィボナッチ進化は決定論的であるため、遷移ルール​​はこの不変式を維持します。 ペアのシーケンスは有限集合内に存在するため、ペアの繰り返しは、その時点以降シーケンスが周期的になることを意味します。 したがって、もし$f$は、繰り返される状態の前に現れず、後に現れることもできないため、早期終了の正確性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 1013

def solve():
    f = int(input().strip())

    a, b = 0, 1
    if a == f:
        print(0)
        return

    # We store visited states of pairs (a, b)
    visited = set()
    visited.add((a, b))

    idx = 1

    # Safe upper bound: at most MOD^2 states
    limit = MOD * MOD + 5

    while idx <= limit:
        a, b = b, (a + b) % MOD

        if a == f:
            print(idx)
            return

        if (a, b) in visited:
            break
        visited.add((a, b))

        idx += 1

    print(-1)

if __name__ == "__main__":
    solve()
```このコードは、2 つの変数を使用してフィボナッチ遷移を明示的に維持し、完全な配列ストレージを回避します。 インデックス`idx`の位置に正確に対応します`a`シーケンス内なので比較すると`a == f`、正しいシーケンス位置を確認しています。 

訪問セットは、サイクルに入った後の無限ループを防ぎます。 これがなければ、ループは限界があるため実際には安全ですが、サイクル検出により理論上の明確なカットオフが得られます。 

初期化チェック`a == f`ゼロ インデックスを直接処理します。これは、フィボナッチ実装における一般的なオフバイワン トラップです。

 ## 特殊なケース

 のために$f = 0$、アルゴリズムはループに入る前に初期値をチェックします。 以来$a = 0$インデックス 0 では、すぐに 0 が返され、必要な最初の出現に一致します。 

次のように複数回出現する値の場合、$f = 1$、スキャン順序により正確さが保証されます。 最初の一致はインデックス 1 で発生し、その後に一致が存在する場合でも、インデックスの走査が増加するため、アルゴリズムはすぐに停止します。 

1013 を法とする特定の残基など、決して出現しない可能性のある値の場合、訪問状態メカニズムにより終了が保証されます。 フィボナッチ ペアが繰り返されると、シーケンスは前のセグメントと同じサイクルに入ります。 もし$f$この繰り返しの前に は検出されなかったので、今後の繰り返しではこれを導入できないため、-1 を返すのが正しいです。
