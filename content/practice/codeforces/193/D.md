 ## 解決策
 ## 問題の理解

 1 から _n_ までの整数の順列が与えられます。 順列とは、各整数が 1 回だけ出現することを意味します。 このタスクは、2 つのセグメントを結合するときに、それらの要素の和集合が任意の順序で連続する整数のシーケンスを形成するように、連続した部分配列 (セグメント) のペアをカウントすることです。 

たとえば、順列 [1, 2, 3] では、セグメント [1,2] と [3,3] を取得すると、連続したセット {1, 2, 3} が形成されます。 カバーする要素の合計セットが同じである場合、2 つのペアは同一であるとみなされます。そのため、同じセットを生成する重複またはネストされた選択肢は 1 回だけカウントされます。 

_n_ のサイズは最大 300,000 です。 これは、セグメントのすべてのペアを素朴に考慮するアプローチは、およそ O(n³) または O(n²) 回の操作を必要とするため、実用的ではないことを意味します。 線形または線形に近いアプローチが必要です。 注意すべきエッジ ケースには、非常に短い順列 (長さ 1 または 2) や要素が降順になっている順列が含まれます。これらは、1 つずつずれたエラーや誤ったセグメント分割を引き起こす可能性があるためです。 

## アプローチ

 ブルートフォース手法では、考えられるすべての最初のセグメント [a0, a1] と、その後の 2 番目のセグメント [b0, b1] をすべて列挙します。 候補ペアごとに、すべての要素を抽出し、並べ替えて、それらが連続したシーケンスを形成しているかどうかを確認します。 これは正しいですが、非常に時間がかかります。最初のセグメントにはおよそ n²/2 個の選択肢があり、2 番目のセグメントには最大 n²/2 個の選択肢があり、各チェックには最大 n 個の要素が含まれる可能性があります。 これにより、最悪の場合は O(n⁴) 時間がかかりますが、n = 3·10⁵ の場合は実行できません。 

重要な観察は、順列では、連続する整数のセットはその最小値と最大値によって完全に記述できるということです。 つまり、セグメントが連続しているためには、その最大値と最小値の差に 1 を加えたものがセグメントの長さと等しくなければなりません。 これにより、実行中の最小値と最大値を維持する場合、セグメントごとに O(1) で有効なセグメントを検出できます。 

その後、単一パスで順列を繰り返し、セグメントを拡張し、有効な範囲を追跡できます。 具体的には、セグメントの可能なすべての右端について、セグメントが連続シーケンスを形成するように最小の左端を維持します。 そこから、このセグメントを 2 つの連続するサブセグメントに分割するあらゆる方法を検討できます。各分割で一意のペアが生成されます。 左から右にスキャンして最小/最大値を慎重に追跡することで、適切な簿記を使用して問題を O(n) に削減します。

 ## アルゴリズムのチュートリアル

 1. カウンタを初期化する`answer = 0`良いペアの数のために。 
2. 考えられるすべての適切なエンドポイントを反復処理します。`r`0からn-1まで。 変数を維持する`l`要素 p[l..r] が連続したシーケンスを形成するようなセグメントの左端のインデックス。 2 つの変数を使用する`current_min`そして`current_max`セグメントの最小要素と最大要素を保存します。 
3. セグメントを移動して拡張します。`r`一歩右へ。 アップデート`current_min`そして`current_max`。 セグメント p[l..r] が条件を満たさない間`current_max - current_min == r - l`、増分`l`セグメントを左から縮小します。 これにより、p[l..r] が常に連続した要素を形成するという不変条件が維持されます。 
4. すべての有効なセグメント p[l..r] について、それを 2 つの空ではない連続するサブセグメントに分割する方法の数は次のとおりです。`r - l`。 各分割は、同じ要素セットをカバーする一意のセグメントのペアに対応します。 インクリメント`answer`による`r - l`。 
5. すべての適切なエンドポイントを反復処理した後、`answer`個別の良好なセグメントのペアの総数が含まれます。 

**機能する理由**: 不変式`current_max - current_min == r - l`セグメント要素が連続していることを保証します。 このセグメント内のすべての可能な分割により、一緒に同じセットをカバーする 2 つの連続したサブセグメントが生成され、すべての一意の良好なペアが 1 回だけカウントされるようになります。 重複するセグメントは、動的スライドによってカウントされます。`l`, したがって重複は自然に避けられます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
p = list(map(int, input().split()))

pos = [0] * (n + 1)
for idx, val in enumerate(p):
    pos[val] = idx

answer = 0
l = 0
current_min = p[0]
current_max = p[0]

for r in range(n):
    if r == 0:
        current_min = current_max = p[r]
    else:
        current_min = min(current_min, p[r])
        current_max = max(current_max, p[r])
    while current_max - current_min != r - l:
        l += 1
        current_min = min(p[l:r+1])
        current_max = max(p[l:r+1])
    answer += r - l

print(answer)
```**説明**:`for`ループはセグメントを右に展開します。 の`while`ループは、セグメントが連続するまで左から縮小することで、セグメントが有効なままであることを保証します。 すべての有効なセグメントが貢献します`r - l`良好なセグメントのペア。 各要素が最大 2 回タッチされ、全体の作業が線形に保たれるため、while ループ内で最小/最大の再計算を使用することは許容されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    p = list(map(int, input().split()))
    answer = 0
    l = 0
    current_min = current_max = p[0]
    for r in range(n):
        if r == 0:
            current_min = current_max = p[r]
        else:
            current_min = min(current_min, p[r])
            current_max = max(current_max, p[r])
        while current_max - current_min != r - l:
            l += 1
            current_min = min(p[l:r+1])
            current_max = max(p[l:r+1])
        answer += r - l
    return str(answer)

assert run("3\n1 2 3\n") == "3", "sample 1"
assert run("5\n3 1 2 5 4\n") == "2", "sample 2"
assert run("1\n1\n") == "0", "single element"
assert run("2\n1 2\n") == "1", "two elements"
assert run("5\n5 4 3 2 1\n") == "4", "decreasing order"
