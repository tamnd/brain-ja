 ## 解決策
 ## 問題の理解

 迷路はちょうど 3 列の通路で、`n`列。 各セルは開いているかブロックされています。 アリスは、最初の列の任意の開いたセルから開始し、開いたセルを上下左右に移動できます。 目標は、少なくとも 1 つの可能なパスが最後の列の開いたセルに到達するかどうかを判断することです。 入力には、コリドーの幅と行を説明する 3 つのバイナリ文字列が含まれています。`0`歩きやすい位置を表し、`1`壁を表します。 出力は`Solvable!`最後の列に到達できれば、`Unsolvable!`さもないと。 

届く幅は`10^4`、したがって、迷路には約`3 * 10^4`細胞。 すべてのセルを一定の回数だけ検査するソリューションは、十分に高速です。 迷路が大きくなるにつれて、可能な歩行の数が指数関数的に増加するため、可能な経路を総当たりで検索することは不可能です。 この制約は、各セルが 1 回処理されるグラフ トラバーサルを強く指しています。 

厄介なケースは、開始点が固定されていないという事実から発生します。 よくある間違いは、左上のセルからのみ開始することですが、アリスは最初の列の任意の行を選択できます。 例えば：```
2
10
00
10
```正しい出力は次のとおりです。```
Solvable!
```行 0 のみから開始する検索は、左中央のセルが 2 列目に到達できる場合でも、左上のセルがブロックされているため、すぐに失敗します。 

もう 1 つのエッジ ケースは、宛先付近のセルは開いているが、左側からは接続されていない場合です。 例えば：```
3
011
010
010
```正しい出力は次のとおりです。```
Unsolvable!
```最後の列には開いたセルが含まれていますが、最初の列からそれらのセルへのパスはありません。 最後の列に`0`間違った答えが生まれてしまいます。 

最後の境界ケースは完全に開いた迷路です。```
2
00
00
00
```正しい出力は次のとおりです。```
Solvable!
```パスは任意の行を横切って直線的に移動するだけです。 誤って 3 行すべてを移動する必要がある実装や、一意のパスを見つけようとする実装は、ここで失敗します。 

## アプローチ

 直接的なアプローチは、すべての開いたセルをグラフの頂点として扱うことです。 2 つの頂点のセルが 1 つの辺を共有する場合、接続されます。 ブルートフォース ソリューションでは、最初の列から可能なパスを列挙し、最後の列に到達したときに停止する可能性があります。 すべての有効な動作シーケンスがグラフ内のパスに対応するため、これは正しいです。 問題は、可能なパスの数です。 多くの分岐点がある迷路では、選択肢の数が膨大になる可能性があるため、経路を個別に探索することはすぐに不可能になります。 

有益な観察は、質問はパスが存在するかどうかだけを尋ねているということです。 パス自体、その長さ、パスの数は必要ありません。 セルに到達できるようになると、そのセルに到達した正確な方法は重要ではなくなります。 これは、セルを訪問済みとしてマークし、すべての可能な開始位置から一度に外側に拡張できることを意味します。 

すべてのオープンセルが最大 1 回考慮されるため、幅優先検索または深さ優先検索で十分です。 3 列の形状には特別な迷路アルゴリズムは必要ありません。 各セルが持つことができる隣接セルの数が減少するだけです。 グラフには線形の数の頂点とエッジがあるため、標準の走査は制限内で終了します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 分岐数の指数関数 | O(n) | 遅すぎる |
 | グラフトラバーサル | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 最初の列のすべての開いたセルを含むキューを作成します。 アリスは任意の行を選択できるため、これらはすべて有効な開始位置です。 
2. キューからセルを繰り返し削除し、そのセルに隣接する可能性のある 4 つを検査します。 隣人が迷路内にいて、開いていて、まだ訪問していない場合は、訪問者としてマークを付けてキューに追加します。 訪問された配列により、繰り返しの作業や無限の移動サイクルが防止されます。 
3. セルの処理中に、訪問したセルが最後の列に属しているかどうかを確認します。 その列のいずれかの行に到達すると、迷路に解決策があることを意味します。 
4. 最後の列に到達せずにキューが空になった場合は、レポートを送信します。`Unsolvable!`。 到達可能なすべての位置はすでに探索されているため、失われたパスは存在しません。 

機能する理由: トラバーサルでは、訪問済みとマークされたすべてのセルが最初の列の開始セルから到達可能であるという不変条件が維持されます。 有効な開始セルのみが挿入されるため、最初はこれが当てはまります。 新しいセルが追加されるたびに、すでに到達可能なセルからの有効な移動によってそのセルに到達するため、不変条件は true のままです。 検索は、到達可能なセルがすべてなくなるまで続けられます。 最後の列に到達すると、記録された経路によって迷路が解けることが証明されます。 一度も訪問されなかった場合は、到達可能なすべての位置がチェックされ、有効なパスが存在しないことが証明されます。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    n = int(input())
    maze = [input().strip() for _ in range(3)]

    visited = [[False] * n for _ in range(3)]
    q = deque()

    for r in range(3):
        if maze[r][0] == '0':
            visited[r][0] = True
            q.append((r, 0))

    directions = [(1, 0), (-1, 0), (0, 1), (0, -1)]

    while q:
        r, c = q.popleft()

        if c == n - 1:
            print("Solvable!")
            return

        for dr, dc in directions:
            nr = r + dr
            nc = c + dc

            if 0 <= nr < 3 and 0 <= nc < n:
                if not visited[nr][nc] and maze[nr][nc] == '0':
                    visited[nr][nc] = True
                    q.append((nr, nc))

    print("Unsolvable!")

if __name__ == "__main__":
    solve()
```迷路の高さは固定されているため、入力は 3 つの文字列として読み取られます。 訪問された配列は迷路と同じ寸法を持ち、位置がすでに発見されているかどうかを記録します。 

初期化ステップでは、考えられる 3 つのセルすべてを最初の列に挿入します。 これは、開始位置を 1 つだけ想定すると問題が変わるため、この問題で最も一般的な実装ミスです。 

キューには行と列のペアが格納されます。 セルが削除されるたびに、コードは隣接するセルを探索する前に、そのセルが最後の列にあるかどうかを確認します。 境界チェックにより、3 行または`n`列。 

有効な各隣接要素は、削除後ではなく挿入前にマークされます。 これにより、2 つの異なるパスが到達したときに同じセルを複数回追加することが回避されます。
