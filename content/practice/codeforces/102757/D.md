 ## 解決策
 ## 問題の理解

 この問題は、歴史的な発明のコレクションについて説明します。 それぞれの発明にはタイトル、発明日、そしてスライスされたパンの素晴らしさにどれだけ近づいているかを表すスコアが付いています。 目的は、スライスパンが発明された後に起こった最大の発明を見つけることであり、スライスパンは 1928 年 7 月 7 日に登場したと考えられています。 

入力にはいくつかの発明レコードが含まれています。 各レコードは、名前、3 文字の月の省略形を使用して書かれた日付とそれに続く日と年、および 0 から 1 までの 10 進数のスコアで構成されます。出力は、単純に最大スコアを持つ有効な発明の名前です。 

発明の数は10,000に達することもあります。 これは十分に小さいので、すべての発明を 1 回検査できるほどです。 発明のすべてのペアを比較するアプローチでは、最悪の場合でも約 1 億回の比較が実行されますが、これは単純な最大検索には不要です。 

実装上の主な困難は、検索自体ではなく、日付を正しく解釈することです。 不注意な解決法では、日付を文字列として比較したり、年が常に 4 桁であるとは限らないことを忘れたりする可能性があります。 日付は、時系列順が維持される表現に変換する必要があります。 

たとえば、次のような入力です。```
3
Old Machine
Jan 1, 3000
0.9
New Machine
Jan 1, 2000
0.8
Ancient Tool
Jan 1, 100
0.99
```他の 2 つはスライスされたパンの前に作成されたため、有効な発明は Old Machine の 1 つだけです。 正しい出力は次のとおりです。```
Old Machine
```最大のスコアのみを選択するソリューションでは、誤って古代ツールが出力されます。 

もう 1 つのエッジ ケースは、1928 年 7 月 7 日に作成された発明です。文言上、スライスしたパンの後に作成された発明であることが求められているため、これはカウントされません。 例えば：```
2
Exact Date
Jul 7, 1928
1.0
Later
Jul 8, 1928
0.5
```正しい出力は次のとおりです。```
Later
```以上を使用して比較すると、正確な日付が誤って選択されます。 

## アプローチ

 簡単なアプローチは、すべての発明を保存し、考えられるすべての選択肢を検討することです。 各発明について、1928 年 7 月 7 日以降に作成されたかどうかを確認し、そのスコアを他のすべての有効な発明と比較します。 これは正しいです。なぜなら、すべての有効な候補の中で最大のスコアもそれらの比較の中で見つける必要があるからです。 ただし、10,000 個の発明がある場合、約 1 億回の比較が実行されますが、問題の解決には発明間の相互作用は必要ありません。 

有益な観察は、これはフィルタリングされたレコードの最大値のみを求めているということです。 他の発明を処理してしまえば、それについて何も知る必要はありません。 入力を 1 回スキャンし、スライスされたパンの日付以前または当日に発明を破棄し、これまでに確認された最高のスコアを維持できます。 

ブルートフォース ソリューションは、最終的にすべての勝者を検査するため機能しますが、不必要な比較を繰り返すため失敗します。 最大値を段階的に維持できることが観察されると、問題は単一パスに縮小されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N²) | O(N) | 概念的には遅すぎる |
 | 最適 | O(N) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 発明の数を読み取ります。 答えはこれまでに見つかった最も有効な候補にのみ依存するため、各発明記録を個別に処理します。 
2. 発明日を比較可能な数値形式に変換します。 便利な表現は、年、月、日をタプルとして保存することです。 タプルは、最大単位から最小単位の順序で時系列に比較されます。 
3. 発明の日付が厳密に 1928 年 7 月 7 日以降であるかどうかを確認します。発明はスライスされたパンより新しいはずであるため、同じ日付は拒否されます。 
4. 有効な発明ごとに、そのスコアを現在の最高スコアと比較します。 この発明のスコアが大きい場合は、保存されている回答を置き換えます。 
5. すべてのレコードが処理された後、保存されているタイトルを印刷します。 

機能する理由: スキャン中、保存された発明は、これまでに処理されたすべてのレコードの中で常に最もスコアの高い有効な発明です。 別の有効な発明が検査されると、その発明のスコアが小さくて不変式が真のままであるか、またはその発明のスコアが大きくて、保存されている回答を置き換えると不変式が復元されます。 最終記録の後、保存された回答は最も有効な発明である必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

months = {
    "Jan": 1,
    "Feb": 2,
    "Mar": 3,
    "Apr": 4,
    "May": 5,
    "Jun": 6,
    "Jul": 7,
    "Aug": 8,
    "Sep": 9,
    "Oct": 10,
    "Nov": 11,
    "Dec": 12,
}

def parse_date(s):
    month, day, year = s.replace(",", "").split()
    return (int(year), months[month], int(day))

def solve(data=None):
    global input
    if data is not None:
        import io
        input = io.StringIO(data).readline

    n = int(input())

    cutoff = (1928, 7, 7)
    best_score = -1.0
    answer = ""

    for _ in range(n):
        title = input().rstrip("\n")
        date = parse_date(input().rstrip("\n"))
        score = float(input().rstrip("\n"))

        if date > cutoff and score > best_score:
            best_score = score
            answer = title

    return answer

if __name__ == "__main__":
    print(solve())
