 ## 解決策
 # 問題の理解

 この問題は、すべての顧客が 1 つの商品を 1 つの銅貨で購入する店をシミュレートします。 顧客は必ずしも銅貨で支払うとは限らず、銀貨や金貨を渡す場合もあります。 アルフォンソは、次の顧客にサービスを提供する前に、すぐに正しいおつりを返さなければなりません。 

コイン システムは 2 進法です。1 枚の銀貨は 2 枚の銅貨と同じ価値を持ち、1 枚の金貨は 2 枚の銀貨と同じ価値を持ちます。 同等の値は、ブロンズ = 1、シルバー = 2、およびゴールド = 4 です。アルフォンソはコインなしで開始するため、最初の数人の顧客は、継続するのに十分な小さなコインがあるかどうかを判断できます。 目標は、キュー全体を処理できるかどうかを判断することです。 

顧客の数は 100,000 に達する可能性があるため、履歴全体を繰り返し検索したり、可能な選択肢を試したりするアルゴリズムでは遅すぎます。 顧客ごとに一定の作業のみを行い、O(n) ソリューションを提供する、顧客間の単一パスが必要です。 

厄介なケースは、十分な総額があ​​るだけでは十分ではないという事実から生じます。 アルフォンソには十分な価値があるかもしれないが、変化に適した宗派ではない。 例えば：```
3
gold
gold
gold
```正しい出力は次のとおりです。```
NO
```最初の金貨の後、アルフォンソは金貨を所有していますが、3 枚の銅貨を返す必要があります。 彼は小さいコインを持っていないので、すぐに失敗します。 総額のみを追跡する不注意な解決策では、十分なお金があると思い込み、間違った答えを与える可能性があります。 

もう 1 つのエッジ ケースは、いくつかの小さなコインの後に高額な額面が表示される場合です。```
4
bronze
bronze
silver
gold
```正しい出力は次のとおりです。```
YES
```最初の 2 人の顧客はアルフォンソに銅貨 2 枚を与えます。 シルバーの支払いはブロンズを 1 つ返却することで処理できます。 最後のゴールドの支払いは、シルバー 1 つとブロンズ 1 つを返却することで処理できます。 すべてのコインの価値が十分な回数出現するかどうかだけをチェックするソリューションでは、順序付けの要件を満たさない可能性があります。 

最終的な境界ケースは次のとおりです。```
3
bronze
silver
gold
```正しい出力は次のとおりです。```
NO
```ブロンズの支払い後、アルフォンソはブロンズを 1 つ獲得します。 銀の支払いは成功し、銀貨が 1 枚残ります。 金の支払いには銅貨3枚分の小銭が必要だが、アルフォンソが持っているのは銀貨1枚だけ。 銀貨は 3 枚ではなく 2 枚の価値があるため、おつりとして返すことはできません。 

# アプローチ

 簡単なアプローチは、アルフォンソが変化を起こす可能性のあるあらゆる方法をシミュレーションすることです。 プログラムは、顧客ごとに、合計が必要な変更となるコインのさまざまな組み合わせを試行し、再帰的に続行することができます。 考えられるすべての決定順序が考慮されるため、これは正しいですが、すぐに不可能になってしまいます。 最悪の場合、すべてのゴールド顧客は、ブロンズ コイン 3 枚相当の小銭を作成するいくつかの可能な方法を導入し、それらの分岐を探索すると、指数関数的な動作につながります。 

コイン システムの構造により、ルートは非常に単純になります。 各額面は前の額面のちょうど 2 倍であるため、大きいコインは常に小さいコインよりも価値があり、柔軟性が低くなります。 将来の顧客にとって重要なのは、アルフォンソが現在銅貨と銀貨を何枚持っているかということだけです。なぜなら、小銭を作るのに金貨は必要ないからです。 取引後も金貨は常に彼のコレクションに残ります。 

重要な観察は、変化は貪欲に加えられるということです。 シルバーの顧客には、ブロンズ コインが 1 枚必要です。 ゴールドの顧客には価値のあるブロンズ コインが 3 枚必要です。 ブロンズ コイン 3 枚相当の小銭を提供する最善の方法は、可能な限りシルバー コインとブロンズ コインを 1 枚ずつ使用することです。そうすることで、将来のシルバー コインの顧客のためにより多くのブロンズ コインを保存できるからです。 それが無理なら銅貨3枚しか残らない。 

ブルート フォースは、変更を加えるための有効な方法をすべて探索するため機能しますが、選択肢の数が急速に増加するため失敗します。 コイン値のバイナリの性質により、その曖昧さが取り除かれ、ラインを 1 回処理する間に必要なコイン数のみを維持できるようになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 顧客数の指数関数的増加 | O(n) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 # アルゴリズムのチュートリアル

 1. アルフォンソが所有する銅貨、銀貨、金貨の数のカウンターを維持します。 最初は 3 つのカウンタはすべてゼロです。 
2. 列の先頭から 1 人ずつ顧客を読み取り、受け取ったコインをアルフォンソのコレクションに追加します。 受け取ったコインは、取引がすでに行われているため、アイテムの支払いには使用できません。そのため、コインは利用可能なコインの一部になります。 
3. 顧客がブロンズで支払った場合、支払いは価格と正確に一致するため、お釣りは必要ありません。 
4. 顧客が銀貨で支払った場合、おつりとして銅貨 1 枚を取り出します。 銅貨がなければ接客は不可能です。 
5. 顧客が金で支払った場合は、銅貨 3 枚分の小銭を取り出します。 銀貨 1 枚と銅貨 1 枚を使用することをお勧めします。これにより、残りの銅貨を後で銀貨の支払いに利用できるようになります。 それが不可能な場合は、銅貨を 3 枚使用します。 どちらのオプションも存在しない場合、プロセスは失敗します。 
6. すべての顧客が正常に処理された場合、出力`YES`。 それ以外の場合は出力`NO`変化を生み出すことができない最初の時点で。 

なぜ効果があるのか:

 不変条件は、すべての顧客に正常にサービスを提供した後、保存されているコインの数が、これまでのすべての取引を完了した後にアルフォンソが持っているコインを正確に表すということです。 銀の支払いの場合、必要な小銭は銅貨 1 枚のみです。 金の支払いの場合、3 枚の銅貨を返す有効な方法はすべて、銀貨 1 枚と銅貨 1 枚、または銅貨 3 枚のいずれかです。 銀貨 1 枚を銅貨 2 枚に置き換えても、アルフォンソの柔軟性が低下するだけなので、欲張った選択が安全です。 より小さな価値を最初に費やしながらより大きなコインを保持することで、将来のすべての顧客に少なくとも同等のサービスを提供する能力が得られます。 すべての顧客は、この不変条件を維持する有効なトランザクションを使用して処理されるため、最終的な答えは正しいです。 

# Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    bronze = 0
    silver = 0
    gold = 0

    for _ in range(n):
        coin = input().strip()

        if coin == "bronze":
            bronze += 1
        elif coin == "silver":
            silver += 1
            if bronze == 0:
                print("NO")
                return
            bronze -= 1
        else:
            gold += 1
            if silver > 0 and bronze > 0:
                silver -= 1
                bronze -= 1
            elif bronze >= 3:
                bronze -= 3
            else:
                print("NO")
                return

    print("YES")

if __name__ == "__main__":
    solve()
```3 つの変数には、将来の顧客に必要な情報のみが保存されます。 金貨は受け取った後はアルフォンソのものであるため数えられますが、小銭の支払いには決して関与しません。 

銀の支払いの場合、コードは最初に銀のコインを追加し、次に 1 つの銅のコインを削除します。 アルフォンソがお釣りを返す前に顧客がコインを渡したため、注文は正しいです。 

ゴールドの支払いの場合、コードは最初にゴールド コインを保持し、次に 3 枚のブロンズ コインを作成するための 2 つの有効な方法をチェックします。 推奨されるブランチでは、銀貨と銅貨が使用されます。 フォールバック ブランチは 3 つのブロンズ コインを使用します。 チェックは減算の前に書き込まれるため、カウンタが負になることはありません。 

Python の整数はオーバーフローせず、アルゴリズムは少数の変数のみを使用するため、最大数の顧客に対しても効率を維持します。

        coin = sys.stdin.readline().strip()

                silver -= 1
                bronze -= 1
            elif bronze >= 3:
                bronze -= 3
            else:
                print("NO")
                break
    else:
        print("YES")

    sys.stdin = old_stdin
    sys.stdout = old_stdout
    return out.getvalue()

```アルゴリズムはコインゼロから始まります。 最初の金の顧客はアルフォンソに金貨を渡しますが、アルゴリズムは小銭に相当する銅貨 3 枚が存在するかどうかをチェックします。 銀貨 1 枚と銅貨 1 枚、または銅貨 3 枚は利用できないため、すぐに印刷されます。`NO`。 金貨は小さなコインに分割できないため、これは実際のプロセスと一致します。
