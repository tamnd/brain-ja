 ## 解決策
 ## 問題の理解

 いくつかの等しい長さの数字列が与えられます。 すべての文字列内の数字は間違った位置にありますが、同じ未知の再配置がすべての文字列に適用されています。 私たちの仕事は、すべての文字列の数字を移動した後、結果の最大の数値と結果の最小の数値の差ができるだけ小さくなるように、位置の再配置を自分で選択することです。 

出力は、この可能な最小の差です。 

入力の重要な部分は、桁数が少ないことです。 長さは最大 9 です。これは、可能な位置再配置の総数が最大 9!、つまり 362880 であることを意味します。これは、すべての配置を試す必要があるほど十分に大きいですが、すべての配置を完全に検索するのが実用的であるほど十分に小さいです。 コードの数は最大 100 個なので、1 つの配列をすべてのコードに対してチェックすることも安価です。 探索空間は階乗限界によって制限されるため、考えられるすべての桁の順序に対してすべての考えられる変換値を試した解決策でも適合します。 

危険なケースは、見落としがちな細部から発生します。 コードの長さは常に正確に k 桁であるため、先頭のゼロは意味のあるものでなければなりません。 たとえば、入力が次の場合:```
2 2
01
10
```正しい答えは`9`。 考えられる 2 つの配置は次のとおりです`01,10`差分9と`10,01`同じ違いです。 治療中`01`再配置前の整数 1 は、この特定のケースを壊すものではありませんが、一般に、位置情報が失われ、不正確な変換が発生する可能性があります。 

数字の繰り返しも間違いの原因です。 考慮する：```
3 3
111
121
131
```正しい答えは、`20`。 Swapping two equal digit positions changes nothing, but an implementation that assumes every permutation creates a unique result may waste time or accidentally remove valid arrangements incorrectly.

 最後のエッジケースは、すべてのコードが同一である場合です。```
3 2
55
55
55
```答えは`0`。 どの順列でもすべての値が等しくなるため、最大値と最小値は同じままになります。 

## アプローチ

 直接的なアプローチは、k 桁の位置の可能な順序をすべて試してみることです。 順序ごとに、その順序を使用してすべてのリカバリ コードを変換し、変換された最小値と最大値を追跡し、それらの差で答えを更新します。 

考えられる一般的な再配置はすべて明示的にテストされるため、この強引な方法は正しいです。 最適な再配置が存在する場合、それは生成された順列の中に表示されます。 

k が小さいため、総当り攻撃が実用的になります。 k = 9 の場合、順列は 362880 個しかありません。 1 つの順列をチェックするには、最大 100 個の数値を調べる必要があります。 変換されたすべての数値を 1 桁ずつ再構築する単純な実装では、およそ 362,880 × 100 × 9 の演算が実行され、これは約 3 億 2,600 万の小さな演算に相当します。 

主な改善点は、アルゴリズムのアイデアが変わったことではなく、表現が慎重になったことです。 文字列を繰り返し変換する代わりに、すべての数値の元のすべての桁位置の寄与を事前計算します。 順列によってポジションが特定の小数重みに配置される場合、保存されている寄与のみを追加します。 これにより階乗列挙が維持されますが、各チェックが大幅に高速化されます。 

可能な桁数が少ないため、総当たりが機能します。 桁の長さが大幅に大きくなり、階乗増加が不可能になる場合にのみ失敗します。 k が 9 を超えることは決してないという観察により、問題をすべての位置の置換に対する網羅的な検索に縮小できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(k! · n · k) | O(n · k) | 最適化により受け入れられます |
 | 最適 | O(k! · n · k) | O(n · k) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのコードを読み取り、各コードの桁を個別に保存します。 すべてをすぐに整数に変換するのではなく、数字を保持すると、元の k 桁の構造が保持されます。 
2. すべてのコードの各桁位置の寄与を事前計算します。 コード位置と小数点以下の桁ごとに、この数字がそこに配置された場合に加算される値を保存します。 これにより、順列検索中に文字列操作が繰り返されることがなくなります。 
3. k 個の元の位置のすべての順列を生成します。 順列は、最上位桁から最下位桁までの位置の最終的な順序を表します。 
4. 現在の順列については、選択した位置の事前計算された寄与を組み合わせて、変換されたすべての数値を計算します。 変換された最大値と最小値によって、この配置によって生じる差が決まります。 
5. 現在の取り決めとの差を使用してグローバル最小の答えを更新します。 すべての順列がチェックされた後、この値が必要な結果になります。 

これが機能する理由は、すべての有効な解が数字の位置の 1 つの並べ替えであるためです。 検索では、そのようなすべての順列を参照し、それぞれの順列について、その再配置によって生成される正確な最大値と最小値を計算します。 アルゴリズムは考えられるすべての再配置を比較するため、より適切な答えを見逃すことはありません。 

## Python ソリューション```python
import sys
from itertools import permutations

input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    codes = [input().strip() for _ in range(n)]

    digits = [[ord(c) - 48 for c in s] for s in codes]

    weights = [10 ** i for i in range(k - 1, -1, -1)]

    contrib = []
    for row in digits:
        contrib.append([row[j] * weights[i] for j in range(k) for i in range(k)])

    pre = []
    for row in digits:
        cur = []
        for pos in range(k):
            for place in range(k):
                cur.append(row[pos] * weights[place])
        pre.append(cur)

    ans = 10 ** k

    for perm in permutations(range(k)):
        best = -1
        worst = 10 ** k

        for row in pre:
            value = 0
            base = 0
            for pos in perm:
                value += row[pos * k + base]
                base += 1

            if value > best:
                best = value
            if value < worst:
                worst = value

        diff = best - worst
        if diff < ans:
            ans = diff

    print(ans)

if __name__ == "__main__":
    solve()
```コードは、元の各桁位置の考えられる重み付けされた寄与を格納します。 置換ループは元の位置を出力位置に割り当てるため、内部計算は加算のみを実行します。 

置換における桁の順序は重要です。 順列の最初の要素は最も重要な位置に配置されます。そのため、重みは 10 の最大乗から下方に生成されます。 

変数`best`そして`worst`は、現在の配置によって生成される最大数と最小数を表します。 それぞれの配置が異なる可能性のあるパスワードの再構築を記述するため、これらは順列ごとにリセットされます。 

Python の整数は、最大の数値が 9 桁しかないため、この問題ではオーバーフローしませんが、実行時間を短くするために、実装では不必要な変換や累乗の繰り返しが回避されています。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(k! · n · k) | すべての桁の順序がチェックされ、それぞれの順序ですべてのコードが評価されます。 
| スペース | O(n · k) | 保存された数値と重み付けされた寄与は入力サイズに比例します。 

k が最大 9 の場合、階乗項は 362880 によって制限されます。最大 100 個のコードと組み合わせると、これは意図した制限内に快適に収まります。 

## テストケース```python
import sys
import io
from itertools import permutations

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n, k = map(int, input().split())
    codes = [input().strip() for _ in range(n)]

    ans = 10 ** k

    for perm in permutations(range(k)):
        mn = 10 ** k
        mx = -1
        for s in codes:
            value = int(''.join(s[i] for i in perm))
            mn = min(mn, value)
            mx = max(mx, value)
        ans = min(ans, mx - mn)

    return str(ans)

assert run("""2 2
12
32
""") == "2", "sample 1"

assert run("""4 4
1842
0141
5581
1581
""") == "1017", "sample 2"

assert run("""2 1
0
9
""") == "9", "single digit boundary"

assert run("""3 2
55
55
55
""") == "0", "all equal values"

assert run("""3 3
001
100
010
""") == "99", "leading zero handling"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`2 1 / 0 / 9`|`9`| 最小桁長 |
 |`3 2 / 55 / 55 / 55`|`0`| 同じ番号 |
 |`3 3 / 001 / 100 / 010`|`99`| 先頭のゼロと位置の変更 |

 ## 特殊なケース

 先行ゼロの場合:```
3 3
001
100
010
```このアルゴリズムは、すべてのコードを 3 つの個別の桁位置として扱います。 順列ではゼロを移動できますが、削除することはできません。 すべての配置は 3 桁の数値として評価されるため、出力は正しいままになります。 

数字が繰り返される場合:```
3 2
55
55
55
```すべての置換により、まったく同じ変換値が作成されます。 最大値と最小値はすべての反復で等しいため、答えはゼロのままです。 

より長い長さを持つ同一のコードの場合:```
3 4
1234
1234
1234
```可能な限り並べ替えると、3 つの同じ数字が作成されます。 検索では引き続きすべての順列が検査されますが、最大値と最小値を見つけた直後には、それぞれの順列の差が 0 になります。 

コードの数を可能な限り少なくするには:```

3
8
```可能な桁位置の順序は 1 つだけです。 このアルゴリズムは、変換された 2 つの値を直接評価し、その差である 5 を返します。
