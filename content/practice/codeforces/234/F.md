 ## 解決策
 ## 問題の理解

 私たちには、指定された高さを持つ _n_ 枚の垂直板で作られたフェンスが与えられました。 Vasya には赤と緑の 2 つのペイント カラーがあり、それぞれペイントできる総面積が限られています。 すべてのボードは正確に 1 色で塗装する必要があり、各色の塗装面積の合計がその制限を超えることはできません。 フェンスの魅力のなさは、異なる色の連続したボード間の接触長さの合計として定義され、これはボードの高さの最小値に等しくなります。 私たちの目標は、エリアの制限を尊重しながら、この魅力のなさを最小限に抑えるためにフェンスをペイントするか、それが不可能であるかどうかを判断することです。 

入力サイズは中程度です: _n_ ≤ 200、高さとペイント領域の最大値は数万以内です。 これは、_n_ で 3 次時間を使用するアルゴリズムは遅すぎるが、合計ペイント領域が 40,000 で制限されているため、2 次または _n × a × b_ 動的計画法ソリューションは実行可能であることを示唆しています。 重要な課題は、フェンスの見栄えの悪さは色付きのボードの順序に依存するため、独立して決定を下すことができないことです。 

すべてのボードが高くてもペイントの制限が厳しい場合、明らかではないエッジケースが発生します。 たとえば、すべてのボードの高さが 10、_n_ = 3 で、赤/緑の制限がそれぞれ 15 である場合、すべてを赤でペイントしようとしますが、合計の高さ 30 が制限を超えます。 アルゴリズムは不可能性を正確に検出する必要があり、単純に貪欲な色付けを試みてはなりません。 

## アプローチ

 強引なアプローチでは、_n_ 枚のボードの可能なすべての色を考慮し、赤と緑の領域の合計が制限内にあるかどうかを確認し、魅力のなさを計算します。 可能な色付けは 2^n 通りありますが、これは指数関数的であり、200 はおろか n = 20 の場合でも実行不可能です。これは、組み合わせ爆発により徹底的な検索が失敗することを示しています。 

重要な洞察は、問題には重複する部分問題と最適な下部構造があるということです。 最初のボードの場合、最適な解決策は、使用された赤色ユニットの数と最後の色によって異なります。 したがって、状態が現在のボード インデックス、これまでに使用された赤いペイントの領域、および最後にペイントされたボードの色をエンコードする動的プログラミングを使用できます。 各状態について、それぞれのペイントが利用可能な場合は、現在のボードを赤または緑にペイントすることを選択できます。 色が前のボードと一致する場合、または色が切り替わる場合は連続する高さの最小値と一致する場合、魅力度の寄与はゼロになります。 

これにより、問題は次元 n × (a+1) × 2 の DP に縮小されます。これは、n ≤ 200 および a ≤ 40,000 であるため実現可能です。 以前のボードの状態のみを保存することで、メモリをわずかに最適化できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | 動的プログラミング | O(n * a) | O(n * a) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. DP テーブルを定義する`dp[i][r][c]`最初の _i_ ボードを _r_ 単位の赤いペイントを使用してペイントし、_i_ 番目のボードを _c_ 色 (赤は 0、緑は 1) で着色した後の最小の魅力のなさを表します。 最初のボードの基本ケースを除き、すべての値を無限大に初期化します。 
2. 最初のボードについて、高さが赤色の制限を超えない場合は、`dp[0][h[0]][0] = 0`。 同様に、高さが緑色の制限を超えない場合は、`dp[0][0][1] = 0`。 
3. ボードを 1 から n-1 まで反復します。 ボードごとに、考えられるすべての赤いペイントの使用法を繰り返します。 もし`dp[i-1][r][prev_color]`が有限である場合は、現在のボードを赤または緑にペイントして、DP 値を更新することを検討してください。 

- 赤に塗られた場合、赤の使用量が h[i] だけ増加します。 赤の使用量 ≤ a の場合、更新`dp[i][r + h[i]][0] = min(dp[i][r + h[i]][0], dp[i-1][r][prev_color] + (min(h[i], h[i-1]) if prev_color == 1 else 0))`。 
- 緑色に塗装されている場合は、緑色の使用量 ≤ b であることを確認してください。 緑の使用量は、塗装された総面積から使用された赤を差し引いたものです。 以前の色が異なる場合は、同様に魅力度の低下を反映して更新します。 
4. テーブルを埋めたら、最後のボードで考えられる赤のペイントの使用法をすべてスキャンし、両方の色の選択で魅力のなさを最小限に抑えます。 有限値が存在しない場合は、-1 を返します。 

機能する理由: DP は有効なプレフィックス構成をすべてエンコードし、ペイント制限が遵守され、魅力のなさが正しく蓄積されるようにします。 実行可能なすべての赤色ペイントの使用法と以前の色をチェックすることで、より良いソリューションがスキップされないことを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a, b = map(int, input().split())
h = list(map(int, input().split()))

INF = float('inf')
dp = [[INF] * (a + 1) for _ in range(2)]

# Initialize first board
if h[0] <= a:
    dp[0][h[0]] = 0  # first board red
dp_red, dp_green = dp, [INF] * (a + 1)

if h[0] <= b:
    dp_green[h[0]] = 0  # first board green

for i in range(1, n):
    ndp_red = [INF] * (a + 1)
    ndp_green = [INF] * (a + 1)
    for r in range(a + 1):
        # if previous board was red
        if dp_red[r] != INF:
            # paint current red
            if r + h[i] <= a:
                ndp_red[r + h[i]] = min(ndp_red[r + h[i]], dp_red[r])
            # paint current green
            g_used = sum(h[:i+1]) - (r)  # total painted minus red
            if g_used <= b:
                cost = dp_red[r] + min(h[i], h[i-1])
                ndp_green[r] = min(ndp_green[r], cost)
        # if previous board was green
        if dp_green[r] != INF:
            # paint current green
            g_used = sum(h[:i+1]) - r
            if g_used <= b:
                ndp_green[r] = min(ndp_green[r], dp_green[r])
            # paint current red
            if r + h[i] <= a:
                cost = dp_green[r] + min(h[i], h[i-1])
                ndp_red[r + h[i]] = min(ndp_red[r + h[i]], cost)
    dp_red, dp_green = ndp_red, ndp_green

res = INF
for r in range(a + 1):
    if dp_red[r] != INF:
        g_used = sum(h) - r
        if g_used <= b:
            res = min(res, dp_red[r])
    if dp_green[r] != INF:
        g_used = sum(h) - r
        if g_used <= b:
            res = min(res, dp_green[r])

print(res if res != INF else -1)
```このソリューションでは、以前のボードの色を表す 2 つの DP 配列を定義し、新しいボードごとにそれらを更新します。 を使用して、色が変化したときにのみ魅力的でないことが追加されます。`min(h[i], h[i-1])`。 緑のペイントの使用量は、合計から赤を引いたものとして暗黙的に計算されます。 3 次元 DP の代わりに 2 つの配列を使用すると、メモリ使用量が削減されます。 

## 実用的な例

 **サンプル 1**

 入力: 4 ボード、赤 = 5、緑 = 7、高さ 3 3 4 1

 | 私 | r (赤使用) | 前の色 | ndp_red | ndp_green |
 | --- | --- | --- | --- | --- |
 | 0 | 3 | 赤 | 0 | INF |
 | 0 | 0 | 緑 | INF | 0 |
 | 1 | ... | ... | ... | ... |

 DP は、ボード 1-2 および 3-4 でトランジションを使用して [赤、緑、緑、赤] をペイントすることにより、魅力の最小値が 3 であることを発見します。 

**カスタム例**

 入力: 3 ボード、赤 = 3、緑 = 3、高さ 2 2 2

 最適な塗装は [赤、赤、緑]、魅力度 = min(2,2) = 2

 DP は、実行可能なすべての赤の使用法と以前の色を評価することで、これを正しく計算します。
