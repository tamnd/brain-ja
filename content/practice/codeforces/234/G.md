 ## 解決策
 ## 問題の理解

 私たちは持っています`n`サッカー選手の番号は`1`に`n`。 

各練習は、すべてのプレーヤーを空ではない 2 つのチームに分割することで構成されます。 数回の練習の後、すべてのプレーヤーのペアを少なくとも 1 回は分離する必要があります。これは、2 人のプレーヤーが反対のチームに配置された練習が存在することを意味します。 

課題は、そのようなスケジュールを立てるだけではなく、可能な限り最小限の練習を行うことです。 

入力には整数が 1 つだけ含まれています`n`。 出力では、最初に最小数の練習を出力し、次に 2 つのチームのうちの 1 つをリストして各練習を説明する必要があります。 あらゆる最適な施工を承ります。 

制約`n ≤ 1000`は十分小さいので、すべてのチームを明示的に出力できます。 課題は計算の複雑さではなく、最小限のプラクティスを見つけて構築することです。 

この問題を考えるのに役立つ方法は、各プレーヤーにバイナリ コードを割り当てることです。 すべてのプラクティスは 1 つのビット位置に対応します。 練習中、ハミを持った選手たち`0`ビットを持った 1 つのチームと選手に行く`1`他のチームに行ってください。 2 人のプレーヤーのコードが少しでも異なる場合は、必ず引き離されます。 

プレーヤーの数は最大 1000 であるため、最大 10 ビットのバイナリ表現で十分です。`2^10 = 1024`。 

微妙な特殊なケースがいくつかあります。 

のために`n = 2`、ペアは 1 つだけ存在します。 プレーヤー 1 をプレーヤー 2 に対して配置する練習を 1 回行うだけで十分です。 

入力：```
2
```有効な出力の 1 つは次のとおりです。```
1
1 1
```常に出力する不用意な実装`⌈log2 n⌉`小さな値を考慮せずに練習すると、練習によっては誤って空のチームが作成される可能性があります。 

別のエッジケースが発生するのは次の場合です。`n`は 2 の累乗ではありません。 

入力：```
5
```3 つの実践が必要です。`2^2 = 4 < 5 ≤ 8 = 2^3`。 一部のビット位置には非常に不均等なスプリットが含まれる場合がありますが、すべての練習では両チームが空でないことが必要です。 既存のプレーヤーのビット位置にゼロのみが含まれている場合、チェックせずにすべてのビット位置を盲目的に出力する実装は正しくありません。 

最後の微妙な点は、プレイヤーの番号が 1 から始まることです。 数字の使用`1..n`バイナリコードとして直接使用すると、必要なビット数を 1 つ増やすことができます。 コードを使用したクリーンな構造`0..n-1`。 

## アプローチ

 強引な視点は、プレーヤーのペアについて直接考えることです。 がある`n(n-1)/2`ペア。 プラクティスを繰り返し設計し、どのペアがすでに分離されているかを確認できます。 すべての練習はプレーヤーを 2 つの空ではないグループに分割するため、このような検索はすぐに組み合わせになります。 中程度の場合でも`n`、可能なパーティションの数は膨大です。 

実践がどのような情報を提供するのかを尋ねると、本当の構造が見えてきます。 練習では、各プレーヤーがパーティションのどちら側に位置するかがわかるだけです。 私たちが演奏したら`m`練習では、すべてのプレーヤーが`m`-すべての実践にわたるチームの割り当てを説明するビット署名。 

2 人のプレーヤーは、サインが異なる場合に少なくとも 1 回は分離されます。 2 人のプレーヤーが同じサインを持っている場合、それらは常に同じ側に表示され、分離されることはありません。 

これにより、問題はコーディングの問題に変換されます。 必要です`n`独特のサイン。 と`m`ビット、最大でもあります`2^m`署名が異なるため、次のようになります。$$2^m \ge n$$したがって、次のようになります。$$m \ge \lceil \log_2 n \rceil$$これにより、答えの下限が決まります。 

同じ観察はすぐに構造を与えます。 選手を割り当てる`i`のバイナリ表現`i-1`。 価値観以来、`0,1,\dots,n-1`すべての署名は区別されます。 ビット位置ごとに、そのビットに従ってプレーヤーを分けるプラクティスを 1 つ作成します。 

プレーヤーの各ペアは異なるバイナリ表現を持っているため、多少の違いがあります。 対応する練習中に、彼らは反対チームに配置され、要件を満たします。 

下限と構造は一致しており、最適性が証明されています。

 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | 指数 | 遅すぎる |
 | 最適 | O(n log n) | O(n log n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 最小の整数を計算する`m`そのような`2^m ≥ n`。 
2. プレイヤーに番号を付けます`0`に`n-1`内部的に。 These values serve as unique binary codes.
 3. 各ビット位置について`b`から`0`に`m-1`、練習を 1 つ作成します。 
4. 実際に`b`、コードにビットがあるすべてのプレーヤーを配置します`b`に等しい`1`最初のチームに入る。 
5. 残りのプレイヤーはすべて自動的に第 2 チームに所属します。 
6. 各練習の最初のチームの選手を出力します。 

bit を持つプレーヤーのみを出力するのが安全な理由`1`? 以来`2^m ≥ n`、使用される最上位ビット位置が必要です。 ビット位置ごとに`b < m`、ビットを持つコードが少なくとも 1 つ存在します。`b = 1`少なくとも 1 つのビット付きコード`b = 0`の間で`0..n-1`。 したがって、両チームは空ではありません。 

### なぜ効果があるのか

 各プレーヤーは、一意の整数のバイナリ表現を次から受け取ります。`0`に`n-1`。 

2 人の異なるプレーヤーについて考えてみましょう。 割り当てられた整数が異なるため、バイナリ表現は少なくとも 1 つのビット位置が異なります。 そのビットに対応する練習中、1人の選手はファーストチームに所属し、もう1人の選手はセカンドチームに所属します。 したがって、すべてのペアは少なくとも 1 回は分離されます。 

次に、最小練習数を考えてみましょう。 後`m`練習では、すべてのプレーヤーは、`m`-ビット署名。 多くてもあります`2^m`独特のサイン。 ずっと`n`プレーヤーは異なる署名を持っている必要があります。`2^m ≥ n`。 したがって、少なくとも`⌈log₂ n⌉`実践が必要です。 

私たちの建設は正確に使用します`⌈log₂ n⌉`練習するので最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    m = 0
    while (1 << m) < n:
        m += 1

    print(m)

    for b in range(m):
        team = []
        for i in range(n):
            if (i >> b) & 1:
                team.append(str(i + 1))

        print(len(team), *team)

solve()
```最初のループは、表現するために必要な最小ビット数を計算します。`n`明確なコード。 

番号を持った選手`i + 1`内部コードを受け取る`i`。 使用する`0..n-1`それは重要です、なぜならまさに`n`個別のコードが必要であり、これにより 1 つのコード値の無駄が回避されます。 

ソリューションは、ビット位置ごとに、コードに`1`その部分で。 それらの選手がトップチームを形成します。 他の全員は暗黙のうちに 2 番目のチームに属します。 

微妙な点の 1 つは、出力形式ではリストに含めるチームが 1 つのみであることです。 残りのプレイヤーは自動的に他のチームを形成します。 

もう 1 つの微妙な点は、リストされているチームが決して空ではないことを証明することです。 以来`m`の最小値です`2^m ≥ n`、以下の各ビット位置`m`として表示されます`1`少なくとも 1 つの数字について`0..n-1`。 したがって、印刷されたすべての練習には少なくとも 1 人のプレーヤーが含まれます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | すべてのプレーヤーのすべてのビット位置を検査します。 
| スペース | O(n) | 一度に 1 つのチーム リストが保存されます。 

以来`n ≤ 1000`、私たちはせいぜい`⌈log₂ 1000⌉ = 10`実践。 アルゴリズムは大まかに実行します`1000 × 10 = 10000`チェックですが、制限内では些細なことです。 

## テストケース```python
import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    n = int(input())

    m = 0
    while (1 << m) < n:
        m += 1

    out = [str(m)]

    for b in range(m):
        team = []
        for i in range(n):
            if (i >> b) & 1:
                team.append(str(i + 1))
        out.append(f"{len(team)}" + ("" if not team else " " + " ".join(team)))

    return "\n".join(out)

# provided sample
assert run("2\n") == "1\n1 2"

# minimum size
assert run("2\n").splitlines()[0] == "1"

# first non-power of two
assert run("3\n").splitlines()[0] == "2"

# power of two
assert run("8\n").splitlines()[0] == "3"

# maximum size
assert run("1000\n").splitlines()[0] == "10"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`2`| 一つの練習 | 最小の有効なインスタンス |
 |`3`| 2つの実践 | 2 のべき乗以外の遷移 |
 |`8`| 3つの実践 | 2 の正確な累乗 |
 |`1000`| 10の実践 | 最大制約 |

 ## 特殊なケース

 次のことを考慮してください。```
2
```アルゴリズムは計算します`m = 1`。 プレーヤー 1 がコードを受信します`0`、プレーヤー 2 がコードを受け取ります`1`。 シングル プラクティスでは、プレーヤー 2 がリストされているチームに配置され、プレーヤー 1 が他のチームに配置されます。 唯一のペアはすぐに分離されます。 

考慮する：```
5
```アルゴリズムは計算します`m = 3`。 3 番目の練習には、コードのみであるため、プレーヤー 5 のみが含まれています。`100`最上位ビットが設定されています。 両方のチームが空ではないため、これは依然として有効です。 不用意に実装すると、このような非常に不均衡なパーティションが誤って拒否される可能性があります。 

考慮する：```
8
```ここ`m = 3`その通り。 すべてのプレーヤーは、次から個別の 3 ビット コードを受け取ります。`000`に`111`。 この構造は下限を正確に達成しており、4 番目の練習が必要ないことがわかります。 ペアごとの分離特性は、バイナリ表現の一意性から直接得られます。
