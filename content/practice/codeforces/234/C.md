 ## 解決策
 ## 問題の理解

 私たちは毎日の一連の気温を与えられています。 任意の温度を他の値に変更することができ、変更された位置ごとに 1 回の変更がかかります。 

目標は、シーケンスが非常に特殊なパターンに従うようにすることです。 分割前は毎日厳密に負の温度となり、分割後は毎日厳密に正の温度になるような分割位置が必要です。 両方の部分が空であってはなりません。 最終シーケンスでは温度がゼロになることは決して許可されません。 

変更する必要がある位置の最小数が必要です。 

日数は次のように大きくすることができます$10^5$。 これにより、考えられるすべての分割を調べてから配列全体を再度スキャンするアルゴリズムが即座に除外されます。$O(n^2)$仕事、大まかに$10^{10}$最悪の場合の運用。 線形または線形に近いものが必要です。 

難しいのは、ゼロを正しく処理することです。 温度ゼロは、分割のどちらの側でも無効です。 日が負のセグメントに属する場合は、ゼロを変更する必要があります。 正のセグメントに属する場合は、ゼロも変更する必要があります。 

もう 1 つの簡単な間違いは、両方のセグメントに少なくとも 1 つの要素が含まれている必要があることを忘れることです。 例えば：```
2
-5 -3
```答えは`1`、 ない`0`。 正のサフィックスを作成する必要があるため、少なくとも 1 つの値を変更する必要があります。 

同様に:```
2
4 7
```答えは`1`空ではない負の接頭辞が必要なためです。 

考慮する：```
3
0 0 0
```あらゆる立場を変えなければなりません。 有効な結果の 1 つは、`-1 -1 1`、したがって、答えは次のとおりです`3`。 ゼロをすでに許容できるものとして扱うアプローチは、ここでは失敗します。 

別の微妙な例は次のとおりです。```
4
-1 1 -2 1
```最適な分割は 3 番目の要素の後にあります。 のみ`-2`ポジティブになる必要があるので、答えは`1`。 

## アプローチ

 ブルートフォースソリューションでは、考えられるすべての分割位置を試します。 

スプリットがポジションの後にあると仮定します$k$。 次に位置$1 \ldots k$負の値である必要があり、位置は$k+1 \ldots n$ポジティブである必要があります。 これらの要件に違反する要素の数を数えて、すべての分割の最小値を取得できます。 

これは、すべての有効な最終構造を明示的に評価するため、正しいです。 問題はスピードです。 がある$n-1$1 つの分割を単純にチェックするには、配列全体をスキャンする必要があります。 複雑さは次のようになります$O(n^2)$が遅すぎます。$n=10^5$。 

重要な観察は、分割のコストは 2 種類の違反のみに依存するということです。 

負の接頭辞の場合、要素が厳密に負である場合、その要素はすでに正しいです。 それ以外の場合は変更する必要があります。 

正の接尾辞の場合、要素が厳密に正であれば、その要素はすでに正しいことになります。 それ以外の場合は変更する必要があります。 

これは、プレフィックスとサフィックスの情報を前処理することを示唆しています。 

させて：`prefix[i]`= 最初の要素間の要素の数`i`マイナスではない位置。 

これらはまさに、最初の場合に修正が必要となる位置です。`i`要素が負のセグメントを形成しました。 

同様に、次のようにしましょう。`suffix[i]`= 位置からの要素の数`i`に`n`それはポジティブではありません。 

これらはまさに、位置が次の場合に変更が必要となる位置です。`i...n`プラスセグメントを形成した。 

次に、ポジション後のスプリットについて`k`、コストは次のようになります。```
prefix[k] + suffix[k+1]
```線形前処理の後、すべての分割を一定時間で評価できるようになりました。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 温度配列を読み取ります。 
2. プレフィックス配列を構築します。`prefix[i]`位置間の要素の数を保存します`1...i`厳密には否定的ではありません。 

要素がゼロまたは正の場合、負のセグメント内でどちらの値も変更する必要があるため、要素はこのカウントに寄与します。 
3. サフィックス配列を構築します。`suffix[i]`位置間の要素の数を保存します`i...n`厳密にはポジティブではありません。 

要素がゼロまたは負の場合、正のセグメント内でいずれの値も変更する必要があるため、要素はこのカウントに寄与します。 
4. すべての有効な分割位置を反復処理します。`k`から`1`に`n-1`。 
5. 以下を計算します。```
cost = prefix[k] + suffix[k+1]
```最初の項は、負の接頭辞で必要な変更をカウントします。 2 番目の項は、正の接尾辞で必要な変更をカウントします。 
6. すべての分割にわたって最小コストを維持します。 
7. 見つかった最小値を出力します。 

### なぜ効果があるのか

 分割位置が固定されている場合、すべての要素はちょうど一方の側に属します。 

要素が負のプレフィックスにある場合、厳密には負ではない場合にのみ変更が必要になります。 プレフィックス配列は、これらの違反を正確にカウントします。 

要素が正の接尾辞にある場合、それが厳密に正でない場合にのみ変更が必要になります。 サフィックス配列は、これらの違反を正確にカウントします。 

2 つのセグメントは互いに素であるため、変更カウントは直接加算されます。 すべての有効な最終配置は 1 つの分割位置に正確に対応するため、すべての分割を評価して最小値を取得すると、全体的に最適な答えが得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    t = list(map(int, input().split()))

    prefix = [0] * (n + 1)
    for i in range(1, n + 1):
        prefix[i] = prefix[i - 1] + (1 if t[i - 1] >= 0 else 0)

    suffix = [0] * (n + 2)
    for i in range(n, 0, -1):
        suffix[i] = suffix[i + 1] + (1 if t[i - 1] <= 0 else 0)

    ans = n
    for k in range(1, n):
        ans = min(ans, prefix[k] + suffix[k + 1])

    print(ans)

if __name__ == "__main__":
    solve()
```プレフィックスの構築は定義に直接続きます。 ゼロ以上のすべての値は負のセグメントの違反となるため、次の場合に 1 を追加します。`t[i-1] >= 0`。 

接尾辞の構造は対称です。 ゼロ以下のすべての値は正のセグメントの違反となるため、次の場合に 1 を追加します。`t[i-1] <= 0`。 

最も一般的な実装上の間違いは、ゼロを正しく処理しないことです。 ゼロは両側で無効であるため、ゼロが配置される場所に応じて両方の違反カウントに影響します。 

もう 1 つの簡単な off-by-one エラーが分割ループで発生します。 分割では両方の部分を空にしない必要があるため、有効な値は次のとおりです。`1`を通して`n-1`。 許可する`0`または`n`空のセグメントが作成され、不正確な回答が生成されます。 

すべてのカウントが最大値であるため、整数オーバーフローの問題は存在しません。`n`。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    n = int(input())
    t = list(map(int, input().split()))

    prefix = [0] * (n + 1)
    for i in range(1, n + 1):
        prefix[i] = prefix[i - 1] + (t[i - 1] >= 0)

    suffix = [0] * (n + 2)
    for i in range(n, 0, -1):
        suffix[i] = suffix[i + 1] + (t[i - 1] <= 0)

    ans = n
    for k in range(1, n):
        ans = min(ans, prefix[k] + suffix[k + 1])

    print(ans)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out

    solve()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out.getvalue().strip()

# provided sample
assert run("4\n-1 1 -2 1\n") == "1", "sample 1"

# minimum size, already valid
assert run("2\n-1 1\n") == "0"

# minimum size, all negative
assert run("2\n-5 -3\n") == "1"

# minimum size, all positive
assert run("2\n4 7\n") == "1"

# all zeros
assert run("3\n0 0 0\n") == "3"

# split near the end
assert run("5\n-1 -2 -3 -4 5\n") == "0"

# catches zero handling
assert run("4\n-1 0 0 1\n") == "2"

 ## 特殊なケース

 次のことを考慮してください。```
2
-5 -3
```プレフィックス配列は次のようになります。```
0 0
```最後の位置のサフィックス違反数は次のとおりです。```
1
```最初の要素の後に、有効な分割は 1 つだけあります。 費用は次のとおりです。```
0 + 1 = 1
```1 つの温度がプラスになる必要があります。 アルゴリズムは正しく出力します`1`。 

次に、次のことを考えてみましょう。```
2
4 7
```唯一の有効な分割は、やはり最初の要素の後です。 

最初の要素は負のセグメントに属し、正であるため、1 つの違反を引き起こします。 2 番目の要素はすでに正です。 

計算されたコストは、`1`、これが最適です。 

最後に次のことを考慮してください。```
3
0 0 0
```どちらの側に属するかに関係なく、すべてのゼロは違反として寄与します。 アルゴリズムは位置ごとに 1 つの変更をカウントし、値を返します。`3`。 

これはまさに正しいです。なぜなら、すべての温度は厳密に負か正のいずれかになる必要があり、ゼロのままであることはできないからです。
