 ## 解決策
 ## 問題の理解

 いくつかのテストケースが与えられています。 各テスト ケースでは、数直線上に配置された点のリストから開始します。 ポイントごとに特別な位置を 1 つ選択します`s`、そして私たちはつながります`s`あらゆる点に`x_i`整数線上のセグメントによって。 したがって、各元の点は、その座標とその座標の間に伸びる間隔になります。`s`。 

任意の固定整数位置の場合`p`数直線上で、その位置をカバーするこれらのセグメントの数としてその「パワー」を定義します。 多くのセグメントが重なっている場合、`p`、その威力は高い。 与えられた選択に対して、`s`、単一の位置でのパワーは求められませんが、次のすべての整数位置を合計した合計パワーが求められます。`1`に`10^9`。 この合計は、すべてのセグメントにわたって、それらがカバーする整数ポイントの数を合計することに相当します。 

タスクは次のとおりです。テスト ケースごとに、考えられるすべての選択肢についてこの合計を計算する必要があります。`s`、 どこ`s`は入力座標の 1 つに制限されます。 

制約は厳しく、すべてのテスト ケースにわたるポイントの総数は最大です。`2·10^5`、最大で`10^4`テストケース。 各候補者に対して独立して回答を再計算するソリューション`s`線形時間では約に劣化します`O(n^2)`全体的に遅すぎます。 

素朴なアプローチでは、それぞれの場合、`s`、すべてのセグメントを構築し、カバレッジの長さを明示的に計算します。 それはすでにコストがかかります`O(n)`あたり`s`、があるので、`n`選択肢、こうなる`O(n^2)`テストケースごとに。 と`n`まで`2·10^5`、これは許容範囲をはるかに超えています。 

主な微妙な点は、重複するセグメントが構造化された方法で相加的に寄与することです。 各セグメントは独自の長さに寄与し、オーバーラップは、明示的なポイントごとのシミュレーションではなく、これらの長さがどのように集約されるかによってのみ問題となります。 

素朴な考えを打ち破るエッジケースには、多くの点が同じ座標を共有する状況や、すべての点が座標の片側にある状況が含まれます。`s`、すべてのセグメントが同じ方向を向くようにします。 もう一つの微妙なケースは次のような場合です。`s`が極端 (最小または最大) であるため、すべてのセグメントが整列し、オーバーラップ構造が最大化されます。 

## アプローチ

 強引なアイデアは単純明快です: 各候補者に対して`s`、間隔ごとに計算します`[min(x_i, s), max(x_i, s)]`次に、範囲内の各整数点について、カバレッジをカウントします。 これは、パワーの合計が間隔の長さからオーバーラップを差し引いた合計に等しいことを観察することでわずかに最適化できますが、合計カバレッジを計算する場合でも、最大の広い座標範囲をスイープする必要があることが明示的に必要になります。`10^9`、それは不可能です。 

重要な観察は、個々のポイントでカバレッジをシミュレートする必要がないということです。 すべての位置の累乗の合計は、すべてのセグメントの長さの正確な合計です。 各セグメント`[a, b]`貢献する`b - a + 1`重複に関係なく、合計に加算されます。 したがって、与えられた答えは`s`単に全体の合計です`i`の`|x_i - s| + 1`。 

これにより、問題はそれぞれの評価に変換されます。`s`、式:$$\sum |x_i - s| + n$$定数`n`は最適化には無関係であるため、中心となるタスクは、多くの候補中心について効率的に絶対差の合計を計算することです。 これは古典的なソート + プレフィックス合計の問題です。配列がソートされると、寄与を左側の要素に分割できます。`s`と右側のものを組み合わせて、O(1) の各部分を計算します。 

ブルート フォースは距離を直接評価するため機能しますが、絶対差の繰り返しの再計算は二次関数であるため失敗します。 絶対値が 2 つの線形成分に分割されるという観察により、プレフィックス合計により、前処理後に各クエリを定数時間に圧縮できます。

 ## アルゴリズムのチュートリアル

 ソート後の絶対距離の構造を利用して作業を進めます。 

1. 座標の配列を並べ替えます。 これにより、選択したものに対して、`s`、その左右のすべての要素は連続したグループを形成します。 
2. ソートされた配列のプレフィックスの合計を作成します。これにより、任意のプレフィックスまたはサフィックスの合計を定数時間で計算できます。 
3. インデックスごとに`i`、 扱う`x[i]`中心として`s`。 配列を左側の要素に分割します。`i`そしてその右側`i`。 
4. 左辺の寄与を次のように計算します。`s * i - sum(left)`。 これはからの合計距離を表します`s`すべての小さな要素に。 
5. 右辺の寄与を次のように計算します。`sum(right) - s * (n - i - 1)`。 これは、より大きな要素までの合計距離を表します。 
6.追加`n`を説明するために`+1`各セグメントの長さ。 
7. 各位置の結果を出力します。 

各ステップでは、プレフィックス合計を利用することで、線形スキャンの可能性を定数時間演算に変換します。 

### なぜ効果があるのか

 正確さは、絶対値を方向性の寄与に分解することで得られます。 並べ替えると、すべての要素が貢献します。`s - x_i`または`x_i - s`、位置に応じて。 プレフィックス合計は両方のグループの正確な合計を保持するため、各クエリは再計算せずに完全な合計を正確に再構築します。 セグメントのオーバーラップはすでに加算長さの解釈に吸収されているため、オーバーラップ構造を追跡する必要はありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        x = list(map(int, input().split()))
        
        x.sort()
        
        pref = [0] * (n + 1)
        for i in range(n):
            pref[i + 1] = pref[i] + x[i]
        
        total = pref[n]
        res = []
        
        for i in range(n):
            s = x[i]
            
            left_sum = s * i - pref[i]
            right_sum = (total - pref[i + 1]) - s * (n - i - 1)
            
            res.append(left_sum + right_sum + n)
        
        print(*res)

if __name__ == "__main__":
    solve()
```コードは最初に配列を並べ替えて、すべての距離をプレフィックスの合計で処理できるようにします。 プレフィックス配列には累積合計が保存され、各候補の両側の合計を直接計算できます。`s`。 各位置について、左側の寄与は、次の間のギャップとして計算されます。`s`とすべての小さな要素が含まれており、右側の寄与は対称的です。 

決勝戦`+ n`これは、各セグメントがそのエンドポイントの包含に寄与しているという事実を説明しています (`+1`間隔あたりの長さ)。 これは、幾何学的範囲から絶対的な差分への変換によって隠蔽されるため、忘れられがちです。 

微妙な点はインデックス付けです。正しい寄与を計算する際には、`x[i]`それ自体を使用して`pref[i + 1]`、センターを二重にカウントしないようにします。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        x = list(map(int, input().split()))
        x.sort()
        pref = [0]
        for v in x:
            pref.append(pref[-1] + v)
        total = pref[-1]
        res = []
        for i, s in enumerate(x):
            left = s * i - pref[i]
            right = (total - pref[i+1]) - s * (n - i - 1)
            res.append(left + right + n)
        out.append(" ".join(map(str, res)))
    return "\n".join(out)

 ## 特殊なケース

 すべての点が同一である場合、すべてのセグメントは、次の点に関係なく同一になります。`s`となり、式は要素ごとの一定の寄与に折りたたまれます。 プレフィックスの合計により左右の寄与が両方ともゼロになり、定数のみが残るため、アルゴリズムはこれを処理します。`+n`。 

点が 1 つだけの場合、左右の分割は存在しないため、両方の寄与はゼロとなり、答えは正確に次のようになります。`1`、単一の単位長セグメントと一致します。 

値が極端に分散している場合でも、接頭辞の合計の定式化は座標密度には依存せず、合計の合計のみに依存するため、機能します。そのため、Python 整数ではオーバーフローや精度の問題は発生しません。
