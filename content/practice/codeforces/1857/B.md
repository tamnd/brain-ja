 ## 解決策
 ## 問題の理解

 数字の文字列として書かれた数値が与えられ、選択した位置の数字を変更し、非標準的な方法で桁上げをより高い位置に伝播する特定の丸め演算を繰り返し適用することができます。 各演算の後、選択した位置の厳密に右にあるすべての桁がゼロになり、その位置の桁は、四捨五入前のすぐ右の桁に応じて増加する可能性があり、桁が 10 になるとキャリーがさらに左に移動する可能性があります。 

目標は、この操作を選択した順序で何度でも適用して、可能な限り最大の最終数値を取得することです。 

重要な問題は、各丸めステップが独立して機能しないことです。 1 回の操作で数値のサフィックス全体が消去され、キャリーが左方向にカスケードされ、上位の桁が変更される可能性があります。 このため、最初の操作の選択は、後の決定のためにどの情報を保存するかを決定するため、非常に影響力があります。 

制約により、最大で次のことが許可されます。$10^4$テスト ケース、およびすべての入力の合計桁数は最大で$2 \cdot 10^5$。 これにより、テスト ケースごとの二次シミュレーションが即座に除外されます。 どのソリューションでも、各桁を平均して一定回数、通常は文字列ごとに線形時間で処理する必要があります。 

複数の丸め操作を異なる位置に適用できる場合、微妙なエッジ ケースが発生しますが、「小さな」丸めを早期に適用すると、キャリー チェーンの向上に寄与する桁が破壊されます。 たとえば、199999 や 10999 のような数値では、桁上げがどこまで伝播するかについて注意を払わないと、ローカルでの貪欲な丸め決定により最適とは言えないグローバルな結果が生じる可能性があります。 

## アプローチ

 ブルートフォース戦略では、考えられるすべての丸め操作シーケンスをシミュレートします。 各操作は任意の位置に適用でき、各操作の後に数値が変化するため、状態空間は大きく分岐します。 有効な演算に限定したとしても、可能なシーケンスの数は桁数とともに指数関数的に増加します。 各操作はキャリーを介して上位のすべての桁に影響を与える可能性があるため、プロセスを独立したローカルな選択に分解することはできません。 これにより、非常に小さな入力を超えるとブルート フォースが実行できなくなります。 

重要な観察は、この操作には常に同じ構造的効果があるということです。つまり、位置が選択されます。$k$、右側の数字に基づいてキャリーがトリガーされるかどうかを決定し、それより下のすべてをゼロにします。$k$。 位置で操作を実行したら$k$、以下のすべてのポジション$k$永久に失われます。 これは、初期の操作は桁上げを押し上げて接尾語を削除するだけであるため、最終的な答えは、丸めによって最終的に数値が安定する単一の「最も効果的な位置」を選択することによって決定されることを意味します。 

すべてのシーケンスをシミュレートする代わりに、逆に考えることができます。つまり、丸めによって最上位桁が最大化されるカスケードが発生する位置を見つけたいと考えます。 数字は、9 の連続を通じてキャリー チェーンをトリガーする場合にのみ影響力を持ちます。 これは、右から左にスキャンして、丸めが意味のある増加を引き起こす箇所を追跡することを示唆しています。 

最も左の位置を特定することによって、可能な限り最良のキャリー伝播をシミュレートします。その位置に丸めるには桁を増やし、連続する 9 までキャリーを伝播する必要があります。 そのような位置が特定されると、その右側はすべてゼロになり、キャリー調整を除いて左側はすべて変更されません。 

これにより、問題は、最適な丸めの決定によって影響を受ける最も遠い位置を計算する単一の線形スキャンに縮小されます。

 ## アルゴリズムのチュートリアル

 数値を変更可能な数字のリストとして処理します。 

1. 入力数値を整数のリストに変換して、数字を直接変更できるようにします。 
2. 右端の桁から始めて左にスキャンして、丸めが有効な位置を検出します。 具体的には、次の位置からの四捨五入の「トリガー」として見たときに、少なくとも 5 である桁を探します。 これは、その境界での丸めにより次の桁が増加する状況に対応します。 
3. そのような位置が見つかったら、そのすぐ左の桁から始まるキャリーをシミュレートします。 その桁が 10 になると、それを 0 に設定し、桁上げがなくなるか、最上位桁に到達するまで、左方向に桁上げを続けます。 
4. 桁上げの伝播が完了したら、影響を受ける位置の右側にあるすべての桁を 0 に設定します。 これは、位置での丸めが行われるという事実を反映しています。$k$サフィックスをクリアします。 
5. 初期の丸めにより左側の結果がさらに改善される可能性があるため、スキャンを続けますが、一度削除された非ゼロの数字が右側に再導入されることはありません。 
6. 最後に、数値を再構築し、先頭のゼロを削除します。 

重要な考え方は、意味のあるキャリー チェーンのみをシミュレートするということです。 5 未満の桁は丸めをトリガーしないため、有益な伝播を開始できません。 このプロセスでは、複数の丸め操作が数字配列の 1 つの貪欲な変換に効果的に圧縮されます。 

### なぜ効果があるのか

 不変条件は、各ステップにおいて、現在処理されている位置の右側の接尾辞が、それらの位置にのみ影響を与える一連の操作の下で達成可能な最良の構成を表すということです。 特定の境界で丸めることを決定すると、右側のすべての情報は無関係になります。これは、以降の操作ではゼロがさらに消去または保存されるだけで、有用な数字が再構築されることはないためです。 貪欲な選択により、すべてのキャリーが可能な限り左端に伝播されることが保証され、早期の切り捨てによって正確さを失うことなく最上位桁が最大化されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = list(map(int, input().strip()))
    
    n = len(s)
    # We try to find the rightmost position where rounding causes change
    mark = -1
    
    for i in range(n - 1, 0, -1):
        if s[i] >= 5:
            mark = i

    if mark == -1:
        print("".join(map(str, s)))
        return

    # perform rounding at position mark
    s[mark] = 0
    carry = 1
    i = mark - 1

    while i >= 0 and carry:
        s[i] += carry
        if s[i] == 10:
            s[i] = 0
            carry = 1
        else:
            carry = 0
        i -= 1

    # zero out suffix
    for j in range(mark + 1, n):
        s[j] = 0

    print("".join(map(str, s)))

t = int(input())
for _ in range(t):
    solve()
```コードはまず、キャリーをトリガーする可能性のある桁をスキャンすることで、丸めが問題となる可能性のある最も深い位置を特定します。 次に、左側への単一キャリー シミュレーションを実行し、オーバーフローが正しく伝播することを確認します。 最後に、サフィックスを消去します。これは、この丸めを使用する最適な戦略では、選択したピボットの右側にあるものをすべて削除する必要があるためです。 

微妙な点は、単調接尾辞の破壊により、一連の操作が単一の最も影響の大きい丸めにまとめられる可能性があるため、有効な丸めを 1 つだけ適用することです。 

## 実用的な例

 ### 例 1: 1980 年

 数字 [1、9、8、0] を処理します。 

| ステップ | スキャン位置 | マーク | キャリースタート | キャリー後の状態 | 最後のサフィックス |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 3→1 | 2 | インデックス 1 から | 2 0 0 0 | 0 0 |

 位置 2 で数字 8 が検出され、丸めがトリガーされます。 キャリーは 9 から伝播し、先頭の桁が増加するカスケードを生成します。 

結果は 2000 となり、最後の桁で局所的に丸めるのではなく、正しい境界で丸めるという最適な戦略と一致します。 

### 例 2: 20445

 数字: [2、0、4、4、5]

 | ステップ | スキャン位置 | マーク | キャリースタート | キャリー後の状態 | 最後のサフィックス |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 右スキャン | 4 | インデックス 3 から | 2 1 0 0 0 | 0 0 |

 ここでは、後続の 5 が丸めをトリガーしますが、キャリーは 4 に伝播し、それ以上カスケードすることなく停止します。 正しい結果は 21000 になります。 

これは、境界での 1 つのローカル丸めでもキャリー伝播を介して複数の桁を再形成できることを示しています。

 ## 特殊なケース

 主なエッジ ケースは、9 という長いサフィックスが最上位桁までのカスケード キャリーをトリガーする場合です。 入力 199999 の場合、正しい動作は、すべての桁にキャリーを伝播して 200000 を生成することです。キャリーが消えるか、すべての桁を使い果たすまでキャリー ループが継続し、完全な伝播が保証されるため、アルゴリズムはこれを自然に処理します。 

もう 1 つのエッジ ケースは、丸めをトリガーするのに十分な大きさの桁がない場合です。 入力 44444 の場合、マークが見つからないため、数値が変更されずに返されます。 これは正しいです。なぜなら、どのような演算も、有益なキャリーを生成せずにサフィックスをゼロにすることによって重要性を低下させるだけだからです。 

3 番目のエッジケースは、潜在的な丸めポイントが複数存在する場合に発生します。 スキャンでは右端の有効なトリガーが選択されます。これは、有効なサフィックス構造の早期破壊を回避しながら、丸めによって数値の最も重要な部分が改善される最も早い時点に対応します。
