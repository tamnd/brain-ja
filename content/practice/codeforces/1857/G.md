 ## 解決策
 ## 問題の理解

 私たちには木が与えられています$n$頂点。各エッジは整数の重みを持ちます。 このタスクは、指定されたツリーが一意の最小スパニング ツリー (MST) であり、グラフ内のすべてのエッジの重みが次を超えない整数になるように、重み付けされた単純なグラフの数をカウントすることです。$S$。 グラフにはツリーを超えた追加のエッジが含まれる場合がありますが、エッジを追加しても代替 MST が作成されることはありません。 

入力により複数のテスト ケースが提供されます。 各テスト ケースは頂点の数を指定します。$n$、最大エッジの重み$S$、 その後$n-1$重みを使用してツリーを記述するエッジ。 各テスト ケースの出力は単一の数値、つまり有効なグラフの数を法的に表したものです。$998244353$。 

制約は重要です。$n$到達できる$2 \cdot 10^5$、 そして$t$できる$10^4$、ただし、合計は$n$すべてのテスト ケースにわたって、次のように制限されます$2 \cdot 10^5$。 これは、各テスト ケースについて、どの解もほぼ線形である必要があることを意味します。$n$。 完全なグラフ内の潜在的なエッジの数は$O(n^2)$までです$4 \cdot 10^{10}$のために$n \sim 2 \cdot 10^5$。 

エッジ ケースには、頂点が 2 つだけのツリー、すべてのエッジの重みが等しいツリー、および次のような状況が含まれます。$S$は、最大のエッジの重みに比べて小さいです。 たとえば、ツリーが重み 5 の単一エッジの場合、$S = 5$、唯一のグラフはツリー自体です。 までの重みを持つ任意のエッジを追加できると仮定した単純なアプローチ$S$MST の一意性をチェックしないと、ここで失敗します。 

## アプローチ

 単純なアプローチでは、ツリー内にないすべての追加エッジを反復処理し、可能なすべての重みを最大で割り当てようとします。$S$を選択し、結果のグラフの MST が元のツリーであるかどうかを確認します。 これは組み合わせ爆発です:$n = 10^5$、おおよそあります$5 \cdot 10^9$非木端。 マイクロ秒ごとに 1 つの組み合わせをチェックするだけでも何年もかかります。 MST の一意性はクラスカルのアルゴリズムで検証できるため、ブルート フォースは概念的には機能しますが、大規模な場合は完全に失敗します。$n$。 

重要な洞察は、特定のツリーが固有の MST である理由を考慮することです。 ツリーにないエッジは、その重みがツリー内の端点を接続するパス上の最大エッジ重みよりも厳密に大きい場合にのみ追加できます。 追加されたエッジの重みがそれより小さいか等しい場合は、一部の MST 内の木のエッジを置き換えるか、同じ総重みを持つ別の MST を作成します。 

したがって、潜在的な追加エッジごとに、$(u,v)$ツリー内にない場合、許可される重みの数は$S - \text{maxWeight}(u,v)$ただし、これがポジティブな場合に限ります。 木のエッジ自体は、(指定された) 可能な重みを 1 つだけ持ちます。 有効なグラフをカウントすると、ツリー以外のすべてのエッジについてこれらのカウントの積を計算することになります。 

ツリー内の任意の 2 つのノード間のパス上の最大エッジを効率的に計算するには、深さ優先検索 (DFS) とスパース テーブルでのバイナリ リフティングを使用できます。 これにより、$O(\log n)$前処理されたツリーのエッジごとのクエリ。 DSU または賢い組み合わせカウントを使用すると、エッジを明示的に列挙することなく最終的なカウントを蓄積できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(S * 2^(n^2)) | O(n^2) | 遅すぎる |
 | 最適 (パス最大値 + 組み合わせカウント) | O(n log n + m log n) | O(n log n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力を解析し、重みを付けてツリー隣接リストを構築します。 

各ノードは、その子とその子に対する重みを保存します。 この表現により、DFS が簡単になります。 
2. パス上の高速最大エッジ クエリのためにツリーを前処理します。 

バイナリ リフティングを使用します。ノードごとに、その 2^k 番目の祖先と、その祖先へのパスに沿った最大エッジ重みを保存します。 DFS は深さと直接の親/エッジを埋めてから、以下を使用して上位の祖先を計算します。$$up[node][k] = up[up[node][k-1]][k-1], \quad \text{maxEdge[node][k]} = \max(\text{maxEdge[node][k-1]}, \text{maxEdge[up[node][k-1]][k-1]})$$3. 頂点の各ペアについて$u,v$ツリー エッジによって接続されていない場合は、バイナリ リフティングを使用してツリー内の固有のパスに沿った最大エッジの重みを計算します。 これに電話してください$w_{\max}$。 
4. このエッジの有効な重みの数は次のとおりです。$\max(0, S - w_{\max})$。 これらのカウントをモジュロで乗算します$998244353$。 
5. 木のエッジごとに 1 を掛けます (重みは固定です)。 
6. 最終製品を返却します。 

機能する理由: 非ツリー エッジはツリー パス上の最大エッジ以下の重みを持つことができないため、MST の一意性が保証されます。 これにより、Kruskal のアルゴリズムが常に最初にツリーのエッジを選択し、元のツリーを MST として生成することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(1 << 25)

MOD = 998244353

def solve():
    t = int(input())
    for _ in range(t):
        n, S = map(int, input().split())
        adj = [[] for _ in range(n)]
        edges = []
        for _ in range(n-1):
            u,v,w = map(int, input().split())
            u -= 1
            v -= 1
            adj[u].append((v,w))
            adj[v].append((u,w))
            edges.append((u,v,w))

        LOG = 20
        up = [[-1]*LOG for _ in range(n)]
        maxEdge = [[0]*LOG for _ in range(n)]
        depth = [0]*n

        def dfs(u, p):
            for v,w in adj[u]:
                if v == p:
                    continue
                depth[v] = depth[u]+1
                up[v][0] = u
                maxEdge[v][0] = w
                dfs(v,u)
        dfs(0,-1)

        for k in range(1,LOG):
            for v in range(n):
                if up[v][k-1] != -1:
                    up[v][k] = up[up[v][k-1]][k-1]
                    maxEdge[v][k] = max(maxEdge[v][k-1], maxEdge[up[v][k-1]][k-1])

        def path_max(u,v):
            if depth[u] < depth[v]:
                u,v = v,u
            res = 0
            for k in reversed(range(LOG)):
                if up[u][k] != -1 and depth[up[u][k]] >= depth[v]:
                    res = max(res, maxEdge[u][k])
                    u = up[u][k]
            if u == v:
                return res
            for k in reversed(range(LOG)):
                if up[u][k] != -1 and up[u][k] != up[v][k]:
                    res = max(res, maxEdge[u][k], maxEdge[v][k])
                    u = up[u][k]
                    v = up[v][k]
            res = max(res, maxEdge[u][0], maxEdge[v][0])
            return res

        # Count extra edges
        ans = 1
        for u in range(n):
            for v in range(u+1,n):
                if any((x==v) for x,_ in adj[u]):
                    continue
                m = path_max(u,v)
                ways = max(0, S - m)
                ans = ans * ways % MOD
        print(ans)
        
if __name__ == "__main__":
    solve()
```このコードは、まずバイナリ リフティング用にツリーを前処理して、パスに沿った最大エッジをすばやく見つけます。 次に、すべての潜在的な非ツリー エッジに対して反復処理を行い、有効な重みカウントを乗算します。 DFS とバイナリ リフティングにより、最大のエッジ クエリの高速化が保証されます。 小切手`if any((x==v) for x,_ in adj[u])`木の端をスキップします。 モジュラー乗算により、範囲内に確実に収まります。 

## 実用的な例

 **サンプル入力 1:**```
2 5
1 2 4
```- 頂点は 2 つ、エッジは 1 つだけです。 余分なエッジはできません。 カウント = 1。 

**サンプル入力 2:**```
4 5
1 2 2
2 3 4
3 4 3
```- 非ツリー エッジ: (1,3)、(1,4)、(2,4)
 - それぞれの path_max を計算します: (1,3)=2、(1,4)=4、(2,4)=4
 - 有効な重み: (1,3)=3,4,5 → 3 通り。 (1,4)=5 → 1 方向; (2,4)=5 → 片道
 - 合計 = 3_1_1 = 3、木の端に 1 を掛ける → 最終的な答え = 3 (モジュロ 998244353)

 以下を示すテーブルを構築できます。`u,v,m,max_weight,S-m`、すべての余分なエッジが最大パスの重みを超えるという不変式が確認されます。
