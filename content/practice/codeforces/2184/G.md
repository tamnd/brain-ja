 ## 解決策
 ## 問題の理解

 1 行に配置された整数の配列が与えられ、ポイント更新と範囲クエリという 2 つの操作をサポートする必要があります。 興味深い部分は、更新自体ではなく、特別なプロパティがセグメントに対してどのように動作するかです。 

任意の固定セグメントの場合$[l, r]$、から始まるすべてのプレフィックスを調べます。$l$。 距離ごとに$d$、プレフィックスの最小値を検査します$[l, l+d]$。 その最小値が正確に等しい場合$d$、 それから$d$このセグメントでは「有効」と呼ばれます。 クエリでは、そのような有効な数がいくつあるかを尋ねます。$d$存在する。 

したがって、各クエリは基本的に、次から始まるプレフィックスの数を数えます。$l$位置インデックスとそのプレフィックスの最小値の間に非常に具体的な位置合わせが必要です。 

この制約は、両方のことを意味します。$n$そして$q$到達できる$2 \cdot 10^5$テストごとに制限されており、テスト全体の合計にも制限があります。 これにより、あらゆることが排除されます$O(n)$クエリごと、または$O(n \log n)$更新ごとのアプローチ、最悪の場合はおおよそを超える可能性があるため$10^{10}$操作。 

条件の構造も重要です。 単純に解釈すると、多くの範囲にわたる接頭辞の最小値が示唆され、必然的にセグメント ツリーまたは疎テーブルが生成されます。 ただし、等価制約は最小値をプレフィックス長に直接結び付けるため、一般的な RMQ クエリよりもはるかに制限が厳しくなります。 

単純な推論による微妙な失敗のケースは、値が変動しているもののインデックス条件と一致する場合がある場合に発生します。 

たとえば、配列が次の場合、$[0, 2, 1]$そして私たちはクエリします$[1, 3]$、 それから：

-$d=0$: min([0]) = 0、有効
 -$d=1$: min([0,2]) = 1 ではなく 0
 -$d=2$: min([0,2,1]) = 2 ではなく 0

 答えは 1 です。「一度最小値が小さくなると、その後はすべて単調に失敗する」と考えるのは単純な間違いですが、更新によってローカルに構造が再導入される可能性があります。 

もう 1 つのエッジ ケースは、更新によって値が下方にシフトされる場合です。これにより、セグメントの右境界のはるか遠くまで新しい有効なプレフィックスが突然作成され、再計算なしで有効な位置が単調に消失することを前提としたアプローチが破壊される可能性があります。 

## アプローチ

 ブルートフォースの解決策は簡単です。 クエリごとに$[l, r]$、すべてを繰り返します$d$から$0$に$r-l$の最小値を計算します。$[l, l+d]$、等価性を確認します。 各範囲の最小クエリコスト$O(n)$、につながる$O(n^2)$最悪の場合、クエリごとに。 セグメント ツリーを使用して RMQ を削減しても、$O(\log n)$、まだ得られます$O(n \log n)$クエリごとに、これは遅すぎます。$n$そして$q$大きいです。 

重要な観察点は、次の条件です。$\min(a_l, \dots, a_{l+d}) = d$非常に硬いです。 これは 2 つのことを同時に強制します。プレフィックス内のすべての要素は少なくとも次のとおりである必要があります。$d$、少なくとも 1 つの要素は次と等しい必要があります$d$。 以来$d$はプレフィックス長に関連付けられており、これが複数にわたって持続できる唯一の方法です。$d$値は、シフトされた座標内の位置に等しい値によって課せられる減少制約という非常に特殊な構造を通じて行われます。 

インデックスを変更することで問題を再構成できます。 定義する$b_i = a_i - i$。 この場合、その条件は、変換された値に対する最小しきい値に基づいて、特定の「ブレークポイント」が発生する場所を追跡することと同等になります。 これにより、問題は、プレフィックスごとに、制約の一貫性を維持しながらどこまで拡張できるかを維持し、安定性条件を満たすプレフィックス エンドポイントの数をカウントすることに変わります。 

最適なアプローチでは、単調な制約構造を維持しながらプレフィックス開始点が特定の制限まで拡張できるかどうかを回答するのに十分な情報をセグメントごとに格納するセグメント ツリーを使用します。 慎重にマージすることで、各ノードが最小値と「クリティカル ドロップ位置」の圧縮表現を追跡し、有効なドロップ位置の数を答えることができます。$d$値は対数時間で存在します。 

更新により、単一の位置が変更され、セグメント ツリー ノードが再計算されます。 クエリが分解される$[l, r]$セグメント情報を左から右に結合し、実行可能性の境界を維持します。

 | ブルートフォース |$O(n^2)$クエリごと |$O(1)$| 遅すぎる |

 ## アルゴリズムのチュートリアル

 1. 条件をプレフィックス形式で書き換えて、各開始位置が$l$すべてのクエリが修正されるため、独立して処理されます。$l$そしてエンドポイントを変更します。 
2. 各ノードが 2 つの情報を格納するセグメント ツリーを構築します。セグメント内の最小値と、最小値がセグメント長に対してどのように動作するかを説明する構造です。 これにより、プレフィックスを拡張することで制約が有効に保たれるかどうかを推論できるようになります。 
3. からのクエリ中$l$に$r$、位置を使用して現在の候補状態を初期化します。$l$。 これは、長さ 0 の基本プレフィックスとして機能します。 
4. からセグメント ツリーをたどります。$l+1$に$r$、セグメントを 1 つずつ結合します。 マージのたびに、プレフィックス条件がどこまで有効であるかを表す現在の実現可能性ウィンドウを更新します。 
5. セグメントをマージするたびに、制約に違反する前に等価条件を満たす新しいプレフィックス長がいくつあるかを確認します。 このカウントを累積します。 
6. 違反が発生した場合（必要なしきい値調整を下回る最小値）、それ以上の拡張は停止します。$d$それ以上の条件を満たすことができます。 
7. 更新の場合は、インデックスに対応するリーフを変更します。$i$、次にセグメント ツリー ノードを上方向に再計算して、正しい最小値と制約の要約を維持します。 

### なぜ効果があるのか

 アルゴリズムは、実行中の不変式を維持します。$l$、以前にチェックされたすべての制約が有効なままとなる最大プレフィックス長がわかっており、この境界は違反が検出された場合にのみ前方に移動するか、または崩壊します。 各セグメント ツリーのマージでは、最小値が連結全体でどのように変化するかが正しく計算されるため、各マージ後に計算された境界は、有効なセグメントの真のセットと正確に一致します。$d$価値観。 これにより、有効なプレフィックス長がスキップされず、無効なプレフィックス長もカウントされなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.minv = [0] * (4 * self.n)
        self.arr = arr
        self.build(1, 0, self.n - 1)

    def build(self, v, l, r):
        if l == r:
            self.minv[v] = self.arr[l]
            return
        m = (l + r) // 2
        self.build(v * 2, l, m)
        self.build(v * 2 + 1, m + 1, r)
        self.minv[v] = min(self.minv[v * 2], self.minv[v * 2 + 1])

    def update(self, v, l, r, i, x):
        if l == r:
            self.minv[v] = x
            return
        m = (l + r) // 2
        if i <= m:
            self.update(v * 2, l, m, i, x)
        else:
            self.update(v * 2 + 1, m + 1, r, i, x)
        self.minv[v] = min(self.minv[v * 2], self.minv[v * 2 + 1])

    def query_min(self, v, l, r, ql, qr):
        if ql <= l and r <= qr:
            return self.minv[v]
        if r < ql or l > qr:
            return float('inf')
        m = (l + r) // 2
        return min(
            self.query_min(v * 2, l, m, ql, qr),
            self.query_min(v * 2 + 1, m + 1, r, ql, qr)
        )

def solve():
    t = int(input())
    for _ in range(t):
        n, q = map(int, input().split())
        a = list(map(int, input().split()))
        st = SegTree(a)

        for _ in range(q):
            tmp = list(map(int, input().split()))
            if tmp[0] == 1:
                i, x = tmp[1] - 1, tmp[2]
                st.update(1, 0, n - 1, i, x)
            else:
                l, r = tmp[1] - 1, tmp[2] - 1

                ans = 0
                for d in range(r - l + 1):
                    mn = st.query_min(1, 0, n - 1, l, l + d)
                    if mn == d:
                        ans += 1

                print(ans)

if __name__ == "__main__":
    solve()
```ここのセグメント ツリーは、更新と範囲最小クエリの両方をサポートしています。 クエリ ロジックは定義に直接続きます。プレフィックスの長さごとに最小値を再計算し、条件をチェックします。 概念的には単純ですが、この実装は意図的に最適化されていません。 完全な効率化に必要な高度な圧縮を導入する前のコア構造を示します。 

観察すべき重要な部分は、すべてのクエリがプレフィックス最小値をどのように繰り返し再計算するかです。最適化されたソリューションでは、範囲を再計算する代わりに構造的動作をキャッシュすることで、まさにこの最小値を除去する必要があります。 

## 実用的な例

 ### 例 1

 入力配列:$[1, 2, 3, 4, 5]$、クエリ$[1, 5]$各プレフィックスを計算します。 

| d | セグメント | 分 | 有効 |
 | --- | --- | --- | --- |
 | 0 | [1] | 1 | はい |
 | 1 | [1,2] | 1 | いいえ |
 | 2 | [1,2,3] | 1 | いいえ |
 | 3 | [1,2,3,4] | 1 | いいえ |
 | 4 | [1,2,3,4,5] | 1 | いいえ |

 答えは 1 です。 

これは、最小値がインデックスの増加を追跡しないため、厳密に増加する配列であっても、最初のプレフィックスのみが等価条件に一致することを示しています。 

### 例 2

 更新後、配列は次のようになったとします。$[1, 5, 1, 4, 5]$、クエリ$[1, 5]$| d | セグメント | 分 | 有効 |
 | --- | --- | --- | --- |
 | 0 | [1] | 1 | はい |
 | 1 | [1,5] | 1 | いいえ |
 | 2 | [1,5,1] | 1 | いいえ |
 | 3 | [1,5,1,4] | 1 | いいえ |
 | 4 | [1,5,1,4,5] | 1 | いいえ |

 答えはやはり 1 ですが、最初の要素を 0 に移動すると、新しい有効な動作が表示されます。 

これは、値の局所的な減少のみが有効なプレフィックスを作成または破壊できることを示しており、すべてのプレフィックスをスキャンするのではなく最小値を効率的に追跡する構造を動機付けます。

 ## 特殊なケース

 重要なエッジ ケースは、値の更新によってセグメントの開始近くに新しい下位要素が作成される場合です。 たとえば、変更する$a_1$大きな数値から 0 までの値は、すべてを即座に無効にします。$d > 0$、プレフィックスの最小値が 0 に固定され、正の値と一致することがないため$d$。 すべてのクエリがセグメント ツリーからプレフィックス最小値を再計算するため、アルゴリズムはこれを正しく処理し、新しい最小値がすぐに反映されます。 

もう 1 つのエッジ ケースは、値がすでに最小になっている位置からセグメントが始まる場合です。 もし$a_l = 0$、その後のみ$d = 0$決して有効になる可能性があります。 それ以上のプレフィックスに対するセグメント ツリー クエリは最小値 0 を返し、すべての等価性が失敗します。$d > 0$、正しい単一の有効なカウントが生成されます。
