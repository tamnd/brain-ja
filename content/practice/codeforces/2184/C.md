 ## 解決策
 ## 問題の理解

 アンドレイは、以下を含む単一の山から始めます。$n$リンゴ。 彼はどんな大きさの山でも分割できる$x$ちょうど 1 分で 2 つの小さな山に分割され、1 つの山が作成されます。$\lfloor x/2 \rfloor$リンゴともう一つ$\lceil x/2 \rceil$リンゴ。 彼の目標は、正確にパイルを取得することです$k$リンゴの数を手動で数えることはありません。 タスクは、分割を繰り返してもそのような山が得られるかどうかを判断し、得られる場合はその山を生成するのに必要な最小時間を計算することです。 

各テスト ケースはリンゴの合計数を提供します。$n$希望のパイルサイズ$k$。 出力は次のようになります。$-1$もし$k$正確に取得することはできません。 それ以外の場合は、必要な最小分割数を返す必要があります。 

制約により、最大で次のことが許可されます。$10^4$テストケースとパイルは同じくらいの大きさ$10^9$。 山を再帰的に分割し、考えられるすべての分割を探索する単純なアプローチでは、分割の数はビット数に比例する可能性があるため、非常に時間がかかりすぎます。$n$そして州の数は指数関数的に増加します。 したがって、効率的な方法は、総当りの探索ではなく、半分にする演算の数学的構造に依存する必要があります。 

次の場合、微妙なエッジケースが発生します。$k$よりも大きいです$n$、それは直ちに不可能です。 別の厄介なシナリオが発生するのは、$k$は、次から得られる 2 のべき乗の和ではありません。$n$半減を繰り返すことで。 たとえば、$n = 21$そして$k = 4$、取得可能な杭のサイズは、繰り返し半分にすることによって定義された順序に従います。$21$、サイズの山を生成します$21, 10, 11, 5, 6, 2, 3, 1$。 以来$4$決して表示されない場合、アルゴリズムはこれを検出する必要があります。 

## アプローチ

 ブルートフォース手法では、サイズの山が見つかるまで、あらゆる方法ですべての山を分割することを再帰的にシミュレートします。$k$またはすべてのオプションを使い果たします。 各分割について、分数と結果として得られるすべてのパイル サイズを追跡します。 原理的には正しいですが、州の指数関数的な成長により、それは不可能になります。$n$まで$10^9$。 

重要な洞察は、各分割によって山が半分になり、結果として得られる山が元の数値の 2 進数表現に対応することを観察することで得られます。 各パイル サイズは基本的に、構成する 2 の累乗のサブセットの合計です。$n$。 したがって、サイズの山を取得するには$k$と表現するのと同じです$k$で利用可能な 2 のべき乗の合計として$n$。 最小時間は、目的のサイズの山を分離するために必要な分割の最小数に対応します。これは、貪欲に分解することで決定できます。$k$の最大の 2 の累乗を使用する$n$。 

したがって、問題は、合計が$k$。 これは、優先キューまたはビット操作を使用して効率的に実装でき、ターゲットが形成されるまで各分割で利用可能な最大のパイルが確実に減少します。

 ## アルゴリズムのチュートリアル

 1. 最初の山から始めます$n$リンゴをチェックしてください$k > n$。 trueの場合、出力$-1$すぐに。 
2. パイル サイズを 2 の累乗として表します。$n$。 例えば、$n = 10$さまざまなサイズの山に対応$8, 2$2 の最大累乗を使用して分解した後に最初に利用可能になります。 
3. 最大ヒープまたは優先キューを使用して、利用可能な最大のパイルを常に分割します。 発生した分割数 (分) のカウンターを保持します。 
4. 最大の杭は、到達するために必要な最小のコンポーネントよりも大きいですが、$k$、それを 2 つの半分に分割し、両方の半分をヒープに戻し、分割カウンタをインクリメントします。 
5. 選択した山の合計を追跡します。 組み合わせの合計が正確に一致すると、$k$、停止し、現在の分割カウンタを最小分数として返します。 
6. ヒープが使い果たされた場合、$k$形成できません、戻る$-1$。 

このアルゴリズムが機能するのは、分割するたびに山が 2 つの小さなコンポーネントに減らされ、すべての 2 の累乗が保証されるためです。$n$いくつかの山に残っています。 ヒープは、分割数を最小限に抑え、最小限の時間を達成するために常に最大のパイルが選択されることを保証します。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        if k > n:
            print(-1)
            continue
        # Count how many ones in binary representation of n
        ones = bin(n).count('1')
        if k < ones:
            print(-1)
            continue
        
        # Min-heap for split counts (we use negative for max-heap)
        heap = [-n]
        splits = 0
        total_piles = 1
        
        while total_piles < k:
            largest = -heapq.heappop(heap)
            if largest == 1:
                break
            a = largest // 2
            b = largest - a
            heapq.heappush(heap, -a)
            heapq.heappush(heap, -b)
            splits += 1
            total_piles += 1
        
        if total_piles == k:
            print(splits)
        else:
            print(-1)

if __name__ == "__main__":
    solve()
```解決策は、些細な不可能なケースに対処することから始まります。 のバイナリ分解$n$分割せずに取得できる杭の最小数を設定します。 ヒープにより、常に最大のパイルを分割してアプローチすることができます$k$効率的に。 の`total_piles`カウンターは、個々の杭がいくつ存在するかを追跡し、到達したときに確実に$k$パイルの場合、分割カウンターは最小限の操作数を反映します。 

## 実用的な例

 | ステップ | ヒープ (最大が最初) | 合計の山 | 分割 |

 選択された山の合計には 3 つの山が 1 つ含まれており、$k = 3$2分割で。 

**例 2:$n = 11, k = 5$**

 1回の分割直後にはサイズ5の山が存在するため、最小時間は1となります。
