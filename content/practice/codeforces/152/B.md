 ## 解決策
 ## 問題の理解

 長方形のグリッドがあります。`n`行と`m`列。 Vasya はこのポジションからスタート`(xc, yc)`。 それから彼は処理します`k`動きベクトルを 1 つずつ設定します。 

ベクトルの場合`(dx, dy)`、彼は繰り返し動きます：```
(x, y) -> (x + dx, y + dy)
```彼は次の動きがグリッドを離れるまでその方向に動き続けます。 1 つのベクトルを終了すると、現在の位置から次のベクトルを開始します。 

タスクは、すべてのベクトルにわたる有効な手の合計数を計算することです。 

グリッドの寸法は次のように大きくできます。`10^9`これにより、グリッド自体のセルに対するシミュレーションが即座に除外されます。 単一のベクトルでも Vasya をおおよそ最大まで動かすことができます`10^9`そのため、ステップバイステップのシミュレーションは不可能です。 それでも`k`だけです`10^4`、実行される移動の総数は膨大になる可能性があります。 

中心的な観察は、各ベクトルについて実際に動きをシミュレートする必要がないということです。 必要なのは、1 つの座標が有効範囲から外れるまでにベクトルを何回適用できるかを決定することだけです。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

動きが純粋に垂直方向であると仮定します。 

入力：```
5 5
3 3
1
-2 0
```正しい答えは次のとおりです。```
1
```ヴァシャが 1 回移動した後、`(1, 3)`。 別の動きは到達するだろう`(-1, 3)`、グリッドの外側。 両方で割る不注意な解決策`dx`そして`dy`ゼロを個別に処理しないとクラッシュするか、ガベージが生成されます。 

マイナス方向も間違いのよくある原因です。 

入力：```
5 5
4 4
1
-1 -2
```正しい答えは次のとおりです。```
1
```ヴァシャが 1 回移動した後、`(3, 2)`。 別の動きは到達するだろう`(2, 0)`、列が次の理由で無効です。`0`存在しません。 数式がすべての方向が正であると仮定している場合、計算された歩数は不正確になります。 

全く移動できない場合もあります。 

入力：```
3 3
1 1
1
-1 0
```正しい答えは次のとおりです。```
0
```最初の動きはすでにボードから離れています。 一部の実装では、誤って負のステップ数が生成され、それが答えに追加されます。 

最後に、答え自体が非常に大きくなる可能性があります。 最大寸法`10^9`そして最大まで`10^4`ベクトルの場合、移動の合計数が 32 ビット整数の範囲を超える可能性があります。 Python はこれを自動的に処理しますが、C++ ソリューションでは次を使用する必要があります。`long long`。 

## アプローチ

 最も直接的な解決策は、すべての動きを文字通りシミュレートすることです。 ベクトルごとに`(dx, dy)`かどうかを繰り返し確認します。`(x + dx, y + dy)`ボード内に残ります。 そうであれば、そこに移動して答えを増やします。 

この強引なアプローチは、ゲームのルールに正確に従っているため、正しいものです。 問題は走行時間です。 単一のベクトルでほぼ次のような結果が得られる可能性があります。`10^9`動く。 と`10^4`ベクトル、総作業量は約`10^13`2 秒に収まる操作をはるかに超えています。 

重要な観察は、1 つのベクトルに沿った動きは完全に予測可能であるということです。 Vasya がいる場合`(x, y)`ベクトルを使用します`(dx, dy)`、 後`t`彼は次のような動きをします:```
(x + t * dx, y + t * dy)
```最大の非負の整数が必要です`t`両方の座標がグリッド内に留まるようにします。 

つまり:```
1 <= x + t * dx <= n
1 <= y + t * dy <= m
```各座標は独立して上限を課します。`t`。 有効な最大ステップ数は、単にこれらの制限の最小値です。 

たとえば、次の場合`dx > 0`、 それから：```
x + t * dx <= n
t <= (n - x) / dx
```もし`dx < 0`、 それから：```
x + t * dx >= 1
t <= (x - 1) / (-dx)
```私たちも同じことをします`dy`、次に許容される最小値を取得します。 

これにより、潜在的に数十億のシミュレートされた動きから各ベクトルが一定量の演算に削減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(総ステップ数) | お(1) | 遅すぎる |
 | 最適 | O(k) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. グリッドの寸法を読み取る`n`そして`m`。 
2. 開始位置を読み取る`(x, y)`。 
3.初期化`answer = 0`。 
4. 各ベクトルを処理する`(dx, dy)`独立して。 
5. 行座標によって許可される移動数を計算します。 

もし`dx > 0`、境界境界は下端です。```
(n - x) // dx
```もし`dx < 0`、境界境界は上端です。```
(x - 1) // (-dx)
```もし`dx == 0`、移動によって行が変更されることはないため、行の座標には制限がありません。 
6. 同じロジックを使用して、列座標によって許可される移動数を計算します。 
7. このベクトルの実際の移動数は、両方の座標からの最小制限です。 

両方の座標が同時に有効である必要があるため、より厳しい制限によって移動が制御されます。 
8. この値を`answer`。 
9. 現在の位置を更新します。```
x += steps * dx
y += steps * dy
```10. すべてのベクトルが処理されたら、印刷します。`answer`。 

### なぜ効果があるのか

 固定ベクトルの場合`(dx, dy)`、すべての動きは同じ量だけ位置を変更します。 後`t`移動すると、位置は正確に次のようになります。```
(x + t * dx, y + t * dy)
```アルゴリズムは最大値を計算します`t`両方の座標が有効範囲内に留まります。 これより大きな値を指定すると、少なくとも 1 つの境界に違反することになるため、それ以上の移動は不可能になります。 より小さい値は明らかに有効です。 

各ベクトルはこれらの最大有効手に従って正確に処理されるため、アルゴリズムはゲームのルールを完全に再現します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
x, y = map(int, input().split())

k = int(input())

answer = 0

INF = 10**30

for _ in range(k):
    dx, dy = map(int, input().split())

    steps_x = INF
    steps_y = INF

    if dx > 0:
        steps_x = (n - x) // dx
    elif dx < 0:
        steps_x = (x - 1) // (-dx)

    if dy > 0:
        steps_y = (m - y) // dy
    elif dy < 0:
        steps_y = (y - 1) // (-dy)

    steps = min(steps_x, steps_y)

    answer += steps

    x += steps * dx
    y += steps * dy

print(answer)
```実装は数学的導出に直接従います。 

各ベクトルについて、行と列に沿った最大有効移動を個別に計算します。 値`INF`決して変化しない座標に対する「無制限」の移動を表します。 たとえば、次の場合`dx == 0`の場合、行座標はグリッドから離れることはないため、列の制約のみが問題になります。 

方向の符号により計算式が異なります。 プラスで下に移動する場合`dx`、下の境界`n`が制限要因となります。 マイナスで上方向に移動する場合`dx`、上部の境界`1`が制限要因となります。 

更新手順:```
x += steps * dx
y += steps * dy
```重要です。 次のベクトルは、現在のベクトルが終了した後の最終位置から開始します。 

Python の整数は、非常に大きな答えを自動的に安全に処理します。 固定幅の整数を使用する言語では、答えは 64 ビット ストレージを使用する必要があります。

# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    n, m = map(int, input().split())
    x, y = map(int, input().split())

    k = int(input())

    ans = 0
    INF = 10**30

    for _ in range(k):
        dx, dy = map(int, input().split())

        sx = INF
        sy = INF

        if dx > 0:
            sx = (n - x) // dx
        elif dx < 0:
            sx = (x - 1) // (-dx)

        if dy > 0:
            sy = (m - y) // dy
        elif dy < 0:
            sy = (y - 1) // (-dy)

        steps = min(sx, sy)

        ans += steps

        x += steps * dx
        y += steps * dy

    print(ans)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()

    backup = sys.stdout
    sys.stdout = out

    solve()

    sys.stdout = backup

    return out.getvalue().strip()
