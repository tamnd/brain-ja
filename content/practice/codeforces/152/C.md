 ## 解決策
 ## 問題の理解

 のリストがあります`n`すべての文字列は同じ長さです`m`。 操作では 2 つの文字列とプレフィックス長を選択します`k`、最初のを交換します`k`これら 2 つの文字列の間にある文字。 

最終的にその位置に表示される文字列のみを考慮します`1`。 任意の数の操作を実行した後、最終的にはいくつの異なる文字列が得られるでしょうか?

 重要な部分は、操作で実際に何が許可されるかを理解することです。 接頭辞を入れ替えても、文字が恣意的に並べ替えられるわけではありません。 位置の後のサフィックスを保持します`k`、その前にすべてを交換しながら。 問題は、実際には、最初の文字列の各位置にどの文字を独立して出現できるかを尋ねることです。 

どちらの制限も非常に小さいです`n`そして`m`せいぜい`100`。 ここでは、指数関数的に見えるアイデアでも魅力的です。入力の合計サイズはわずかです。`10^4`文字。 それでも、到達可能なすべての文字列を明示的に生成するのは危険です。 すべての位置が多くの文字の中から独立して選択できる場合、到達可能な文字列の数は指数関数的に増加します。`m`。 たとえば、`m = 100`そしてそれだけでも`2`ポジションごとの選択肢はすでにあります`2^100`可能性。 

これにより、文字列に対する状態空間検索が即座に除外されます。 私たちは可能性を構築することなく数え上げる必要があります。 

複数の文字列の列に同じ文字が含まれている場合、微妙なエッジ ケースが発生します。 考慮する：```
3 2
AA
AB
AC
```2 番目の位置で使用できる文字は次のとおりです。`{A, B, C}`、ただし最初の位置には`{A}`。 答えは、`1 * 3 = 3`、 ない`3^2 = 9`。 列ではなく行を処理するソリューションでは、オーバーカウントが発生します。 

もう 1 つの簡単な間違いは、異なる列の文字がリンクされていると想定することです。 考慮する：```
2 3
ABC
DEF
```到達可能な文字列は次のとおりです。```
ABC
ABF
AEC
AEF
DBC
DBF
DEC
DEF
```がある`2^3 = 8`各列は、その列に表示される文字とは独立して選択できるため、さまざまな可能性があります。 単純なシミュレーションでは、この独立性が欠けていることがよくあります。 

もう 1 つの罠は文字列の重複です。 例えば：```
3 3
AAA
AAA
AAA
```答えは、`1`、 ない`3^3`。 行数ではなく、列ごとの個別の文字をカウントします。 

## アプローチ

 ブルートフォース手法では、到達可能なすべての文字列を状態として扱い、可能なすべての操作を繰り返し適用します。 文字列のすべてのペアとすべてのプレフィックス長について、新しい状態を生成し、未確認の文字列が表示されなくなるまで続行します。 

操作空間が有限であり、生成されたすべての文字列が真に到達可能であるため、これは概念的に機能します。 問題は州の数が爆発的に増加していることだ。 それぞれの場合、`m`ポジションは独立して均等に取ることができます`2`値を指定すると、到達可能な文字列の総数は次のようになります。`2^m`。 と`m = 100`、これはまったく不可能です。 

ターニングポイントは、プレフィックスの交換によって実際に何が変わるのかを理解することから始まります。 

1 つのポジションに注目するとします`p`。 少なくとも長さのプレフィックスを交換すると`p + 1`、次に位置の文字`p`プレフィックスと一緒に移動します。 プレフィックス長が短い場合は、`p`は手付かずです。 

これは、列にすでに存在する任意の文字を個別にインポートできることを意味します`p`最初の文字列に。 さらに重要なのは、後の列に対する操作によって、以前の列に対してすでに行われた選択が破壊されないことです。 各列は独立して動作します。 

したがって、問題は単純なカウントの観察に帰着します。 

すべての列について、すべての文字列の中で異なる文字が何個出現するかを数えます。 最終的な答えは、これらのカウントの積です。 

なぜ乗算なのでしょうか？ すべての列について、他の列の選択とは関係なく、その列に表示される任意の文字を選択できるからです。 

例えば：```
ABC
DEF
```カラム`0`もっている`{A, D}`、 カラム`1`もっている`{B, E}`、 カラム`2`もっている`{C, F}`。 

到達可能な文字列の数は次のとおりです。```
2 * 2 * 2 = 8
```これにより、シミュレーションが完全に回避されます。 入力を 1 回だけスキャンし、列ごとに個別の文字をカウントします。

 ## アルゴリズムのチュートリアル

 1. 整数を読み取る`n`そして`m`、すべての文字列を保存します。 
2. 答えを次のように初期化します。`1`。 
3. すべての列について`j`から`0`に`m - 1`、すべての文字列にわたってその位置に出現するすべての文字を収集します。 

複数の行から同じ文字を選択しても新しい文字列は作成されないため、個別の文字のみを考慮します。 
4.列内の個別の文字の数を設定します`j`なれ`cnt`。 
5. 答えを乗算します`cnt`、モジュロを取る`10^9 + 7`。 

この乗算は、さまざまな列の選択が独立しているため機能します。 
6. すべての列を処理した後、最終的な回答を出力します。 

### なぜ効果があるのか

 どの列でも`j`、少なくとも長さのプレフィックスを交換します`j + 1`キャラクターをその位置に移動できます`j`ある文字列から別の文字列へ。 したがって、その列にすでに存在するすべての文字は、最終的には最初の文字列に現れる可能性があります。 

同時に、列に影響を与える操作`j`後で他の列に選択できる文字を制限しないでください。 構築は位置ごとに独立して動作します。 

すべての列が独立した選択肢のセットを提供するため、到達可能な文字列の総数は、各列内の個別の文字数の積に等しくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

n, m = map(int, input().split())
names = [input().strip() for _ in range(n)]

answer = 1

for col in range(m):
    chars = set()

    for row in range(n):
        chars.add(names[row][col])

    answer = (answer * len(chars)) % MOD

print(answer)
```プログラムは列非依存観測を直接実装します。 

まず、すべての文字列をリストに読み込みます。 次に、列ごとに、そこに表示されるすべての個別の文字を含むセットを構築します。 Python セットは重複を自動的に削除するため、数学的要件に正確に一致します。 

答えはこのセットのサイズで乗算されます。 可能な文字列の数が非常に多くなる可能性があるため、すべての乗算は剰余で実行されます。`10^9 + 7`。 

よくある実装上の間違いは、個別の文字ではなく出現総数をカウントすることです。 たとえば、列に次の内容が含まれている場合、`A A A`、貢献度は`1`、 ない`3`。 

もう 1 つの微妙な点はインデックスです。 Python はゼロベースのインデックスを使用するため、列`0`最初の文字に対応します。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    MOD = 10**9 + 7

    n, m = map(int, input().split())
    names = [input().strip() for _ in range(n)]

    ans = 1

    for col in range(m):
        chars = set()

        for row in range(n):
            chars.add(names[row][col])

        ans = (ans * len(chars)) % MOD

    print(ans)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    output = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return output.strip()

# provided sample
assert run(
"""2 3
AAB
BAA
"""
) == "4", "sample 1"

# minimum size
assert run(
"""1 1
A
"""
) == "1", "minimum case"

# all strings equal
assert run(
"""3 3
AAA
AAA
AAA
"""
) == "1", "all equal"

# every column has two choices
assert run(
"""2 3
ABC
DEF
"""
) == "8", "independent columns"

# mixed duplicates
assert run(
"""3 2
AA
AB
AC
"""
) == "3", "duplicate handling"

# boundary style case
assert run(
"""4 4
ABCD
BBCD
CBAD
DBCD
"""
) == "12", "multiple distinct counts"

 ## 特殊なケース

 すべての文字列が同一である場合を考えてみましょう。```
3 3
AAA
AAA
AAA
```すべての列について、個別のセットは次のようになります。`{A}`。 アルゴリズムは以下を計算します。```
1 * 1 * 1 = 1
```どの列にも新しい文字が存在しないため、どの操作でも新しい文字を導入できません。 個別の文字ではなく行をカウントする不注意な実装では、誤って返される可能性があります。`27`。 

次に、列全体で独立した選択を検討します。```
2 3
ABC
DEF
```列セットは次のとおりです。```
{A, D}
{B, E}
{C, F}
```アルゴリズムは次のように乗算します。```
2 * 2 * 2 = 8
```これは正しいです。なぜなら、各列は使用可能な文字の 1 つを独立して選択できるからです。 行全体の構造を保持しようとするアプローチでは、過小評価されます。 

最後に、不均一な多様性について考えてみましょう。```
3 2
AA
AB
AC
```最初の列は 1 つのオプションのみを提供します。```
{A}
```2 番目の列は次の 3 つを提供します。```

```答えは次のようになります。```
1 * 3 = 3
```これにより、すべての列を個別に処理する必要があり、列内の重複は無視する必要があることが確認されます。
