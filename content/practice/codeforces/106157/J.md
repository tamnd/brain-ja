 ## 解決策
 ## 問題の理解

 小文字の間には一連の順序規則が与えられています。 次のようなルール`a < b`あらゆる出来事を意味します`a`が出現するたびに前に出現する必要があります`b`最後に並べ替えた言葉で。 ルール`a > b`と同じ意味です`b < a`。 

入力には単語も含まれています。 文字を好きなように並べ替えることができますが、最終的な配置はすべての順序規則を同時に満たさなければなりません。 

タスクは、単語の有効な再配置を出力することです。 ルールが互いに矛盾し、一度にすべてを満たすことが不可能な場合は、次のように出力する必要があります。`IMPOSSIBLE`。 

有益な観察は、可能な文字が 26 個しかないということです。 ルールの数は 700 に達し、ワード長は 100,000 に達する可能性がありますが、実際の依存関係グラフは 26 頂点のみで構築されます。 

単語の長さが長いことから、個々の文字を繰り返し比較したり移動したりするのは無駄であることがわかります。 代わりに、制約は問題を 2 つの部分に分割することを提案します。 まず、文字の有効なグローバル順序を決定します。 次に、各文字の出現頻度を利用して効率的に答えを作成します。 

よくある間違いの原因は、間接的な矛盾を処理することです。 

考慮する：```
3
a < b
b < c
c < a
abc
```ルールはサイクルを形成します。 配置できない配置`a`前に`b`、`b`前に`c`、 そして`c`前に`a`同時に。 正しい出力は次のとおりです。```
IMPOSSIBLE
```もう 1 つの微妙なケースは、2 つの文字に関連性がない場合です。```
1
b < n
banana
```ルールのみの制約`b`そして`n`。 手紙`a`どちらとも無関係です。 すべてが満たされるあらゆるアレンジメント`b`文字がすべての前に来る`n`文字は有効です。 複数の答えが存在します。 

3 番目のエッジ ケースは、単語に制約された文字が含まれていない場合に発生します。```
2
x < y
y < z
banana
```制約は依然としてサイクル検出に関与しますが、欠落している文字は出力にゼロのコピーをもたらします。 有効なトポロジー順序が依然として必要です。 

## アプローチ

 ブルートフォースアプローチでは、単語に出現する文字のさまざまな順列を試し、すべてのルールが満たされているかどうかを確認します。 これは直ちに実行不可能です。 たとえ 10 個の異なる文字しか現れなかったとしても、`10! = 3,628,800`可能な注文。 

この問題の構造は、一般的な並べ替え問題よりもはるかに制限的です。 すべてのルールは、文字タイプ間の相対的な順序を記述するだけです。 個々のコピーの正確な位置は関係ありません。 

これは、各文字を有向グラフの頂点として表すことを示唆しています。 ルールとしては`a < b`、エッジを追加します`a → b`。 有効な最終取り決めには手紙を提出する必要があります`a`手紙の前に`b`したがって、すべての有効な解は、このグラフのトポロジカルな順序に対応します。 

グラフにサイクルが含まれる場合、位相的順序は存在せず、答えは不可能です。 

グラフが非巡回の場合、トポロジカル順序により、26 文字すべての有効なグローバル順序が与えられます。 その順序がわかれば、単語を構築するのは簡単です。 元の単語に各文字が何回出現するかを数え、位相順序に従って各文字のコピーをすべて出力します。 

グラフは小さく、頂点が 26 個しかないため、トポロジカル ソートは基本的に定数時間です。 主な作業は、文字のカウントと出力文字列の書き込みになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(k!) | O(k) | 遅すぎる |
 | 最適 | O(n + \|s\|) | O(n + 26) | 承認済み |

 ここ`n`は順序付けルールの数であり、`|s|`単語の長さです。 

## アルゴリズムのチュートリアル

 1. 小文字ごとに 1 つずつ、合計 26 個の頂点を持つ有向グラフを作成します。 
2. すべてのルールについて:

 - ルールが次の場合`a < b`、エッジを追加します`a → b`。 
- ルールが次の場合`a > b`、エッジを追加します`b → a`。 

これにより、必要な優先関係がエンコードされます。 
3. すべての頂点の次数を計算します。 
4. カーンのトポロジカルソートを実行します。 

- 次数が 0 のすべての頂点から開始します。 
- そのような頂点を繰り返し削除し、トポロジカル順序に追加します。 
- 出ていく近傍の入次数を減らします。 
- 近傍が次数 0 に達するたびに、それをキューに追加します。 
5. 処理される頂点の数が 26 未満の場合、グラフにはサイクルが含まれます。 出力`IMPOSSIBLE`。 
6. 指定された単語内のすべての文字の頻度を数えます。 
7. 計算されたトポロジー順序をたどります。 各文字について、単語内に出現する回数だけその文字を追加します。 
8. 結果の文字列を出力します。 

### なぜ効果があるのか

 グラフ内のすべてのエッジは、必須の順序付け制約を表します。 カーンのアルゴリズムは、すべての有向エッジが前の文字から後の文字に向かう順序を生成します。 

この位相順序に従って文字のすべてのコピーをまとめて出力すると、ソース文字のすべての出現は、すべてのエッジで宛先文字のすべての出現より前に表示されます。 トポロジー的順序はすべてのエッジを満たすため、すべての順序付け規則も満たします。 

サイクルが存在する場合、ある文字セットはそれぞれ同じサイクル内の別の文字の前に来なければなりません。 直線的な配置ではその要件を満たすことはできません。`IMPOSSIBLE`が正解です。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

n = int(input())

adj = [[] for _ in range(26)]
indeg = [0] * 26
seen = set()

for _ in range(n):
    a, op, b = input().split()

    if op == "<":
        u = ord(a) - ord('a')
        v = ord(b) - ord('a')
    else:
        u = ord(b) - ord('a')
        v = ord(a) - ord('a')

    if (u, v) not in seen:
        seen.add((u, v))
        adj[u].append(v)
        indeg[v] += 1

s = input().strip()

q = deque(i for i in range(26) if indeg[i] == 0)

topo = []

while q:
    u = q.popleft()
    topo.append(u)

    for v in adj[u]:
        indeg[v] -= 1
        if indeg[v] == 0:
            q.append(v)

if len(topo) != 26:
    print("IMPOSSIBLE")
    sys.exit()

cnt = [0] * 26
for ch in s:
    cnt[ord(ch) - ord('a')] += 1

ans = []

for x in topo:
    ans.append(chr(x + ord('a')) * cnt[x])

print("".join(ans))
```グラフの構築により、すべての比較が、必要な順序と方向が一致する有向エッジに変換されます。 

の`seen`set は、重複したエッジが人為的に度数を増加させることを防ぎます。 入力が明確なルールを保証する場合でも、これにより実装が堅牢になります。 

カーンのアルゴリズムは、有効なトポロジー順序付けが存在する場合は常に、それを生成します。 サイクル チェックは、26 文字すべてが処理されたことを確認することによって実行されます。 

最後の構築ステップでは、文字列全体をソートするのではなく、頻度を使用します。 単語には最大 100,000 文字が含まれる可能性があるため、これは重要です。 Appending`count(letter)`各文字を直接コピーすると、語長が線形になります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + \|s\|) | ルールに基づいてグラフを構築し、単語を数えて出力する |
 | スペース | O(n + 26) | グラフのエッジと周波数配列 |

 グラフには 26 個の頂点しか含まれていないため、トポロジカル ソートは実質的に定数時間になります。 実行時間の大部分は、制限内に簡単に収まる入力ルールと単語の文字の処理に費やされます。 

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io
from collections import deque

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n = int(input())

    adj = [[] for _ in range(26)]
    indeg = [0] * 26
    seen = set()

    for _ in range(n):
        a, op, b = input().split()

        if op == "<":
            u = ord(a) - 97
            v = ord(b) - 97
        else:
            u = ord(b) - 97
            v = ord(a) - 97

        if (u, v) not in seen:
            seen.add((u, v))
            adj[u].append(v)
            indeg[v] += 1

    s = input().strip()

    q = deque(i for i in range(26) if indeg[i] == 0)
    topo = []

    while q:
        u = q.popleft()
        topo.append(u)

        for v in adj[u]:
            indeg[v] -= 1
            if indeg[v] == 0:
                q.append(v)

    if len(topo) != 26:
        return "IMPOSSIBLE\n"

    cnt = [0] * 26
    for ch in s:
        cnt[ord(ch) - 97] += 1

    ans = []
    for x in topo:
        ans.append(chr(x + 97) * cnt[x])

    return "".join(ans) + "\n"

# custom cases

out = run("""0
a
""")
assert sorted(out.strip()) == ['a']

assert run("""3
a < b
b < c
c < a
abc
""") == "IMPOSSIBLE\n"

out = run("""1
b < n

""")
assert out.strip().count('a') == 3
assert out.strip().index('b') < out.strip().rindex('n')

out = run("""2
x < y
y < z
banana
""")
assert sorted(out.strip()) == sorted("banana")

out = run("""1
a > b
abba
""")
s = out.strip()
assert s.rfind('b') < s.find('a')
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 単一文字の単語 | 有効な 1 文字の回答 | 最小サイズ |
 | サイクル`a<b<b<c<c<a`|`IMPOSSIBLE`| サイクル検出 |
 |`b<n`と`banana`| 有効な取り決め | 半オーダー対応 |
 | 不在文字の制約 | 有効な再配置 | Word で文字が見つからない |

 循環入力を考えてみましょう。```
3
a < b
b < c
c < a
abc
```グラフにはエッジが含まれています`a → b`、`b → c`、 そして`c → a`。 すべての頂点は正の次数を持ちます。 カーンのアルゴリズムは 26 文字すべてを処理できないため、位相順序は不完全です。 アルゴリズムは次を出力します。```
IMPOSSIBLE
```有効な順序が存在しないため、これは正しいです。

1

banana
```グラフにはエッジが 1 つだけ含まれています。 トポロジカルソートにより、`a`～に対して相対的な任意の場所`b`そして`n`。 生成される文字列は次のとおりです`aaabnn`、`baaann`、またはその他多くの。 すべての有効な回答はすべてを保持します`b`何よりもまず文字`n`文字。
