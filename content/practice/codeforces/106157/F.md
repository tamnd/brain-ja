 ## 解決策
 ## 問題の理解

 丘の方向性のない地図が接続されています。 それぞれの丘には高さがあり、丘の間のパスがグラフを形成します。 訪問した最も高い丘と最も低い丘の差をできるだけ小さくしながら、丘 1 から丘 2 まで移動する必要があります。 

選択したルートの場合、重要なのは、そのルート上に表示される最小の高さと最大の高さだけです。 ルートが高さ 10、14、13、12 を訪問する場合、その費用は次のようになります。`14 - 10 = 4`。 

入力により、丘の数、トレイルの数、すべての丘の高さ、およびトレイルで接続された丘のペアが得られます。 出力は、丘 1 から丘 2 までのすべてのルートの中で可能な最小の高低差です。 

丘の数は最大 5000、トレイルの数は最大 25000 です。グラフには膨大な数の異なるルートが含まれる可能性があるため、考えられるすべてのパスを試すソリューションは不可能です。 すべての道を探索するだけでも指数関数的に増加するでしょう。 問題を高さ制限下での接続性のチェックに減らす必要があります。 丘は 5000 個しかないため、アルゴリズムは次のようになります。`O(n(n+m))`これは現実的ですが、すべての丘のペアやすべての可能なパスを含むものはコストがかかりすぎます。 

最初のエッジ ケースは、丘 1 と丘 2 が同じ高さである場合です。 これら 2 つの丘のみで構成されるルートは、それらが直接接続されている場合、答えは 0 になります。 例えば：```
Input
2 1
5 5
1 2

Output
0
```答えが常に肯定的であると仮定する不注意な解決策は、ここでは失敗します。 

もう 1 つのエッジ ケースは、最適なルートが最短のグラフ パスを使用しない場合です。 例えば：```
Input
5 5
1 100 50 51 2
1 2
1 3
3 4
4 5
5 2

Output
49
```ダイレクトパスには高さの範囲があります`99`、しかし、より長い道のり`1 -> 3 -> 4 -> 5 -> 2`範囲がある`50 - 1 = 49`。 高さの範囲ではなくエッジの数を最小限に抑えるソリューションでは、誤った結果が得られます。 

3 番目のエッジ ケースは、複数の丘が同じ高さを共有する場合に発生します。 許可される高さのウィンドウは、丘のインデックスではなく、高さの値に基づく必要があります。 例えば：```
Input
3 2
7 7 10
1 2
2 3

Output
3
```高さ 7 の 2 つの丘は一緒に扱う必要があります。 同じ高さを別々の範囲に分割すると、有効な回答が失われる可能性があります。 

## アプローチ

 直接的なアプローチでは、丘 1 から丘 2 までの可能なすべてのルートを列挙し、各ルートの最小高さと最大高さを計算し、最小の差を維持します。 考えられるすべての候補ルートが考慮されるため、これは正しいです。 問題は路線数です。 疎なグラフであっても、指数関数的に多くの異なるパスが含まれる可能性があるため、このアプローチはすぐに使用できなくなります。 

重要な観察は、正確なルートは気にせず、高さの範囲内に何らかのルートが存在するかどうかだけを気にするということです。 

2 つの高さを選択するとします`low`そして`high`。 丘 1 と丘 2 が、その間の高さの丘のみを使用して接続されているかどうかを尋ねています。`low`そして`high`。 それらが接続されている場合、この間隔は有効な回答候補になります。 

有効な間隔には単調な特性があります。 もし`[low, high]`機能し、その後増加します`high`それを機能させ続けます。 もし`[low, high]`機能しない、減少する`high`助けることはできません。 これにより、ソートされた一意の高さに対する 2 ポインターのスキャンが可能になります。 

左側の境界ごとに、間隔が有効になるまで右側の境界を前方にのみ移動します。 次に、現在の最小の高さを削除して続行しようとします。 右ポインタが後方に移動することはないため、接続性チェックの数は個別の高さの数に比例します。 

ブルート フォースは、考えられるすべてのルートをチェックするため機能しますが、ルートの数が膨大であるため失敗します。 許容される高さの間隔のみが重要であるという観察により、パスの列挙をグラフの接続性チェックの繰り返しに置き換えることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | O(n) | 遅すぎる |
 | 最適 | O(k(n+m)) | O(n+m) | 承認済み |

 ここ`k`は個別の高さの数であり、`k <= n`。 

## アルゴリズムのチュートリアル

 1. すべての個別の丘の高さを並べ替えます。 既存の 2 つの高さの間の境界を移動しても、利用可能な丘を変更できないため、これらの値は有用な間隔の唯一の可能な境界です。 
2. 2 つのポインターを維持する`left`そして`right`並べ替えられた高さリストの上に表示されます。 現在の候補間隔は次のとおりです。`heights[left]`に`heights[right]`。 
3. 現在の間隔で、丘 1 から開始する BFS を実行します。検索中は、高さが間隔内にある丘のみを訪問します。 丘 2 に到達すると、その区間には有効なルートが含まれます。 
4. 間隔が無効な場合は、間隔を大きくします。`right`。 最大高さを大きくすると、利用可能な丘が増えるだけなので、ルートが表示される可能性があります。 
5. 間隔が有効な場合は、現在の範囲で回答を更新し、値を増やします。`left`。 許容される最小の高さを削除すると、有効な間隔がさらに小さくなる可能性があります。 
6. 右ポインタが高さリストの最後に到達するまで続けます。 

2 ポインタの移動が安全である理由は、間隔が広がると接続が容易になるためです。 特定の最大高さが特定の最小高さに対して十分であると、それより小さい最大高さを検索しても役に立ちません。 

なぜ効果があるのか:

 すべての有効なルートの高さは最小です`L`そして最大の高さ`R`、したがって、これは 2 ポインター プロセスで考慮される間隔の 1 つに対応します。 BFS チェックは、その区間内の丘によって形成されるサブグラフを正確に探索するため、区間に丘 1 から丘 2 へのルートが含まれているかどうかを正確に判断します。 このアルゴリズムは、考えられるすべての最小左境界をテストし、それに適した最小の右境界を見つけます。そのため、それより小さい有効な間隔はスキップされません。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    h = list(map(int, input().split()))

    graph = [[] for _ in range(n)]
    for _ in range(m):
        a, b = map(int, input().split())
        a -= 1
        b -= 1
        graph[a].append(b)
        graph[b].append(a)

    values = sorted(set(h))

    def connected(low, high):
        if not (low <= h[0] <= high and low <= h[1] <= high):
            return False

        seen = [False] * n
        q = deque([0])
        seen[0] = True

        while q:
            u = q.popleft()
            if u == 1:
                return True
            for v in graph[u]:
                if not seen[v] and low <= h[v] <= high:
                    seen[v] = True
                    q.append(v)

        return False

    ans = values[-1] - values[0]
    right = 0

    for left in range(len(values)):
        if right < left:
            right = left

        while right < len(values) and not connected(values[left], values[right]):
            right += 1

        if right == len(values):
            break

        ans = min(ans, values[right] - values[left])

    print(ans)

if __name__ == "__main__":
    solve()
```グラフが十分に疎であるため、すべてのエッジを明示的に保存する必要がないため、入力解析によって隣接リストが構築されます。 の`connected`関数はウォークスルーの中核となる操作です。 現在の高さの間隔で頂点をフィルタリングしながら BFS を実行します。 

2 つのポインター ループは、インデックスのみをソートされた高さリストに格納します。 右ポインタは決して後方には移動しないため、BFS 呼び出しの数が制限されます。 回答の更新は、有効な間隔が見つかった後にのみ行われます。 

開始時の境界確認`connected`いずれかのエンドポイントが現在の高さの範囲外にある場合を処理します。 これがないと、開始丘または終了丘が利用できない場合でも、BFS はルートが存在すると誤って主張する可能性があります。 

Python の整数はオーバーフローしないため、高さが 100 万に達する場合でも高さの計算は安全です。

 最適な間隔は高さ 1 ～ 3 で、答え 2 が得られます。トレースは、動作する間隔を見つけた後、アルゴリズムがそれを改善するために最小の高さを削除しようとすることを示しています。

 アルゴリズムは一意の高さの値に対して機能するため、2 つの等しい高さの値は一緒に処理されます。

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |

 ## 特殊なケース

 高さが等しい場合:```
2 1
5 5
1 2
```ソートされた高さリストには、`[5]`。 チェックされる唯一の間隔は、`[5,5]`。 両方のエンドポイントがその内部にあり、BFS はすぐに丘 2 に到達し、答えは次のようになります。`5 - 5 = 0`。 

より長いルートの場合:```
5 5
1 100 50 51 2
1 2
1 3
3 4
4 5
5 2
```間隔`[1,2]`代替ルートに必要な中間の丘が利用できないため、丘 2 に到達できません。 まで拡張`[1,50]`まだ失敗しますが、`[1,51]`高さのある丘を乗り越えて成功する`1,50,51,2`。 アルゴリズムの記録`51 - 1 = 50`検索を続ける前に。 最終的な有効な最小値は次のとおりです。`49`間隔を使って`[2,51]`左ポインタが移動した後。 

重複する高さの場合:```
3 2
7 7 10
1 2
2 3
```ソートされた一意の高さは次のとおりです。`[7,10]`。 アルゴリズムは高さ 7 の 2 つの丘を決して分離しないため、間隔は`[7,10]`両方を正しく含み、範囲内のルートを検索します`3`。 

すべての場合において、不変条件は、間隔がテストされるたびに、BFS がその高さ制限の下で利用可能なグラフを正確に表すということです。 2 つのポインタは、解答を改善できない区間のみを破棄するため、最終的な最小範囲は保持されます。
