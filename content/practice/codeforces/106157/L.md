 ## 解決策
 ## 問題の理解

 道路網の交差点ごとにパブが 1 軒ずつある町があります。 道路沿いの移動には時間がかかり、どのパブにも閉店時間があります。 時間 0 にパブ 1 から開始します。 

飲み会の時間はあらかじめ決まっています。 最初のパイントはかかります$t_1$秒、2 秒かかります$t_2$、などまで$t_r$。 期間は必ずしも増加するわけではありません。 

パイントは、それが飲まれているパブが閉店する前に完全に飲み終えた場合にのみカウントされます。 道路網を好きなように移動したり、パブを何度も訪れたり、お酒を飲まずにパブを通り過ぎたりすることもあります。 唯一の制限は、同じパブで 2 パイントを連続して飲むことはできないということです。 目標は、消費されるパイント数を最大化することです。 

パイント数の制限は少ないですが、$r \le 100$パブの数も中程度で、$k \le 300$。 グラフは、最大 90,000 本の道路が含まれる非常に密集したものになる可能性があります。 

考えられるすべてのパブシーケンスを総当りで検索するのは絶望的です。 パイントごとにパブを選ぶだけでも、すでにおおよその情報が得られます$k^r$可能性。 と$k=300$そして$r=100$、それは天文学的な大きさです。 

グラフのサイズは、パブのすべてのペア間の最短移動時間を計算することが実現可能であることを示唆しています。 これらの最短経路がわかれば、実際の道路構造はもはや重要ではなくなり、パブ間の最小移動時間のみが重要になります。 

パブを再訪問すると、微妙なエッジケースが現れます。 再訪は許可されていますが、途中で別の場所で飲んだ後に限ります。 

例：```
2
5 5
2
20 20
1
1 2 1
```同じパブが連続するパイントに使用されるため、パブ 1 → パブ 1 というシーケンスは無効です。 閉店時間をチェックするだけのソリューションでは、誤って 2 パイントを数えることになります。 

もう 1 つのエッジ ケースは、パブ 1 で最初の 1 パイントを飲む必要がないことです。 

例:```
1
10
2
100 15
1
1 2 1
```パブ 2 への移動には 1 秒かかるため、最初のパイントは時刻 11 に終了し、有効になります。 パブ 1 で最初のパイントを強制的に消費するような解決策は、この可能性を逃すことになります。 

3 番目のエッジ ケースは、グラフに同じジャンクションのペアの間に複数の道路が含まれる可能性があることです。 最短の移動時間だけが重要です。 最適な道路ではなく任意の道路を使用すると、実現可能なスケジュールが不可能に見える可能性があります。 

## アプローチ

 最も直接的なアイデアは、すべてのパイントに対して可能な限りすべてのパブの選択肢を試してみることです。 パブで今のパイントを飲んだ場合$u$、パブを選びます$v \ne u$次の場合は、移動時間と飲酒時間を追加し、閉店時間が守られているかどうかを確認します。 

このアプローチは、有効なスケジュールをすべて明示的に列挙するため、正しいです。 問題は可能性の数です。 旅行の詳細を無視しても、大まかに$k$パイントあたりの選択肢、生産$k^r$州。 と$k=300$そして$r=100$、これはまったく不可能です。 

重要な観察は、可能な限り早い終了時間のみが重要であるということです。 

私たちはすでに飲んでしまったとします$j$パイントで最後の一杯はパブで終わった$u$。 2 つの異なるスケジュールが同じ状態に達した場合$(j,u)$、終了時間が短いスケジュールは常に他のスケジュールと少なくとも同じくらい優れています。 すべての制約には時間の上限があるため、早く到着しても将来の選択肢が減ることはありません。 

これにより、動的計画法が定式化されます。 

DP の前に、すべてのペアの最短パスを計算します。 早めに到着する方が常に良いため、2 つのパブ間のルートは最短ルートに置き換えることができます。 

定義する：$$dp[j][u]$$可能な最小の絶対時間として、$j$- 塗装はパブで終了します$u$。 

このような状態から、どのパブでも次のパイントを飲むことができます$v \ne u$。 終了時間は次のようになります。$$dp[j][u] + dist[u][v] + t_{j+1}$$トランジションは終了時間を超えない場合にのみ有効です。$c_v$。 

州の数はたったの$r \times k$、そして各州は次のパブをすべて試してみます。$O(rk^2)$トランジション。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(k^r)$|$O(r)$| 遅すぎる |
 | 最適 |$O(k^3 + rk^2)$|$O(rk)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 飲酒時間、パブの閉店時間、道路網を読んでください。 
2. 無限大に初期化された距離行列を構築します。 
3. すべてのパブからそれ自体までの距離を 0 に設定します。 
4. すべての道路について、端点間の最小重量を維持します。 複数の道路が同じペアのパブを接続している場合があります。 
5. Floyd-Warshall を実行して、すべてのパブ間の最短移動時間を計算します。 
6. DP テーブルを作成します。`dp[j][u]`飲んだ後の可能な限り最も早い終了時刻を正確に保存します`j`パイントとパブで終わる`u`。 
7. 最初のパイントを初期化します。 あらゆるパブに`u`、最初のパイントはそこで飲むことができます。$$dist[1][u] + t_1 \le c_u$$これが成立したら、その終了時刻を次の場所に保存します。`dp[1][u]`。 

1. 消費されたパイント数ごとに`j`1から`r-1`、到達可能なすべての終了パブを処理します`u`。 
2. あらゆる目的地のパブに`v`とは違う`u`、計算する$$finish = dp[j][u] + dist[u][v] + t_{j+1}$$もし`finish <= c[v]`、 アップデート$$dp[j+1][v]$$これまでに確認された最小終了時間で。 

1. 答えは最大です`j`ある州のために`dp[j][u]`到達可能です。 

### なぜ効果があるのか

 DP 州は、消費したパイント数と最後のパイントを飲んだパブで構成される固定ペアについて、達成可能な最も早い終了時刻を記録します。 

今後の決定はこれら 2 つの情報のみに依存します。 すべての制約には期限があるため、より早い完了は常に、より遅い完了と少なくとも同じくらい優れています。 スケジュールを、以前に同じ状態に達した別のスケジュールで置き換えても、その後の一連の移動を無効にすることはできません。 

フロイド・ウォーシャルは次のことを保証します。`dist[u][v]`パブ間の移動時間は最短です。 より長いルートを使用するスケジュールは、完了が遅くなる可能性があるため、最短経路を考慮するだけで十分です。 

パブのすべての有効なシーケンスは DP 遷移のシーケンスに対応し、すべての DP 遷移は有効なアクション シーケンスを表すため、DP は実行可能なすべてのスケジュールを正確に探索します。 到達可能な最大のパイント数が最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**18

r = int(input())
t = list(map(int, input().split()))

k = int(input())
c = list(map(int, input().split()))

m = int(input())

dist = [[INF] * k for _ in range(k)]

for i in range(k):
    dist[i][i] = 0

for _ in range(m):
    a, b, d = map(int, input().split())
    a -= 1
    b -= 1
    if d < dist[a][b]:
        dist[a][b] = d
        dist[b][a] = d

for mid in range(k):
    dm = dist[mid]
    for i in range(k):
        if dist[i][mid] == INF:
            continue
        via = dist[i][mid]
        di = dist[i]
        for j in range(k):
            nd = via + dm[j]
            if nd < di[j]:
                di[j] = nd

dp = [[INF] * k for _ in range(r + 1)]

start = 0

for u in range(k):
    if dist[start][u] == INF:
        continue
    finish = dist[start][u] + t[0]
    if finish <= c[u]:
        dp[1][u] = finish

answer = 0

for u in range(k):
    if dp[1][u] < INF:
        answer = 1

for drank in range(1, r):
    for u in range(k):
        cur = dp[drank][u]
        if cur == INF:
            continue

        for v in range(k):
            if v == u:
                continue
            if dist[u][v] == INF:
                continue

            finish = cur + dist[u][v] + t[drank]

            if finish <= c[v] and finish < dp[drank + 1][v]:
                dp[drank + 1][v] = finish
                answer = max(answer, drank + 1)

print(answer)
```最初の部分では、最短パス行列を構築します。 同じペアのパブ間の複数の道路は、最小エッジの重みのみを維持することによって処理されます。 

Floyd-Warshall 実装では、マトリックスが適切に更新されます。 以来$k \le 300$、$O(k^3)$複雑さは許容されます。 

DP テーブルには、ブール値の到達可能性ではなく、最も早い終了時刻が格納されます。 これが重要な最適化です。 同じパブで同じ数のパイントを飲んだ後、2 つのスケジュールが終了する場合は、早い方のスケジュールのみが問題になります。 

最初のパイントは前のパブがないため特別な処理が必要です。 パブ 1 から選択したパブまで移動して過ごすだけです。$t_1$そこで飲んでいる数秒。 

トランジションがスキップされる`v == u`、同じパブで連続してパイントを消費することはできないというルールを強制します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(k^3 + rk^2)$| フロイド-ウォーシャルとDPの移行 |
 | スペース |$O(rk + k^2)$| DP テーブルと距離行列 |

 と$k \le 300$そして$r \le 100$、フロイド-ウォーシャルフェーズは約 2,700 万回の更新を実行し、DP は約 900 万回のトランジションを実行しますが、どちらも一般的なコンテストの制限内で問題なく収まります。 

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline
    INF = 10**18

    r = int(input())
    t = list(map(int, input().split()))

    k = int(input())
    c = list(map(int, input().split()))

    m = int(input())

    dist = [[INF] * k for _ in range(k)]
    for i in range(k):
        dist[i][i] = 0

    for _ in range(m):
        a, b, d = map(int, input().split())
        a -= 1
        b -= 1
        dist[a][b] = min(dist[a][b], d)
        dist[b][a] = min(dist[b][a], d)

    for mid in range(k):
        for i in range(k):
            for j in range(k):
                dist[i][j] = min(
                    dist[i][j],
                    dist[i][mid] + dist[mid][j]
                )

    dp = [[INF] * k for _ in range(r + 1)]

    for u in range(k):
        finish = dist[0][u] + t[0]
        if finish <= c[u]:
            dp[1][u] = finish

    ans = 0
    for u in range(k):
        if dp[1][u] < INF:
            ans = 1

    for drank in range(1, r):
        for u in range(k):
            if dp[drank][u] == INF:
                continue
            for v in range(k):
                if v == u:
                    continue
                finish = dp[drank][u] + dist[u][v] + t[drank]
                if finish <= c[v]:
                    dp[drank + 1][v] = min(
                        dp[drank + 1][v],
                        finish
                    )
                    ans = max(ans, drank + 1)

    return str(ans) + "\n"

# minimum size

""") == "1\n"

# cannot drink any pint

""") == "0\n"

""") == "2\n"

""") == "3\n"
