 ## 解決策
 ## 問題の理解

 ルートに沿った高速道路の停留所の位置が与えられ、厳密に増加する累積距離として保存されます。 

連続する各停留所の間には運転セグメントがあります。 位置停止の場合`i`が削除されます。`i`が始点でも終点でもない場合、その停留所に隣接する 2 つのセグメントが 1 つの長いセグメントになります。 

タスクは、残っている最長の駆動セグメントをできるだけ小さくするために、内部ストップを 1 つだけ削除することです。 その最小可能な最長距離を出力する必要があります。 

させて`g[j] = s[j+1] - s[j]`連続するストップ間の距離になります。 

ストップを外したら`i`、次にギャップ`g[i-1]`そして`g[i]`消えて、長さの 1 つのギャップに置き換えられます`g[i-1] + g[i]`。 

他のすべてのギャップは変更されません。 

ストップ数は 200,000 にも達するため、ほぼ 200,000 のギャップが存在します。 削除されたストップごとに最大ギャップを最初から再計算するアルゴリズムには、大まかに次のものが必要になります。`O(n²)`あまりにも大きすぎる仕事。 と`n = 200,000`、それは数百億回の操作を意味します。 

いくつかの特殊なケースは注目に値します。 

ギャップがあるとします。`10 20 30`。 

中間停止マージの削除`10`そして`20`、ギャップを生み出す`30 30`。 答えは`30`、 ない`20`。 既存のギャップのみを確認し、マージされたセグメントを無視するソリューションは失敗します。 

考慮する：```
4
0 100 101 200
```ギャップは`100 1 99`。 

2 番目のストップを削除すると、`101`、最大値を与える`101`。 

3 番目のストップを削除すると、`100`、最大値を与える`100`。 

正しい答えは、`100`。 「最小のギャップの隣のストップを削除する」などの貪欲なルールは信頼できません。 

もう 1 つの境界ケースは、最初または最後の取り外し可能なストップの隣で最適な取り外しが行われる場合です。```
3
0 5 12
```削除できるストップは 1 つだけです。 結果のセグメント長は次のようになります。`12`、したがって、答えは次のとおりです`12`。 ここでプレフィックスやサフィックスを不注意に処理すると、無効なインデックスに簡単にアクセスしてしまう可能性があります。 

## アプローチ

 最も直接的な解決策は、取り外し可能なすべてのストップを試してみることです。 

選択したストップについて、その 2 つの隣接するギャップをマージし、残りのすべてのギャップをスキャンして最大のギャップを見つけます。 これは、考えられるすべての削除の結果を明示的に評価するため、正しいです。 

問題は走行時間です。 がある`O(n)`候補者は立ち止まり、それぞれの評価がかかります`O(n)`最大ギャップを再計算する時間がかかります。 全体の複雑さは次のようになります。`O(n²)`、それは不可能です`n = 200,000`。 

重要な観察は、ストップを削除した後、ギャップが 2 つだけ変化するということです。 

隙間の除去に`g[i-1]`そして`g[i]`:

 結合されたギャップは次のようになります。`g[i-1] + g[i]`。 

他のすべてのギャップはまったく同じままです。 

したがって、この削除後の最大ギャップは、単に次の大きい方になります。 

1. マージされたギャップ。 
2. を除くすべてのギャップのうちの最大のギャップ`g[i-1]`そして`g[i]`。 

これは、ギャップ配列のプレフィックスとサフィックスの最大値を事前に計算することを示唆しています。 

させて：`pref[j]`= 間の最大ギャップ`g[0..j]`

`suff[j]`= 間の最大ギャップ`g[j..m-1]`どこ`m = n - 1`。 

次に隙間を含む除去について`g[i-1]`そして`g[i]`、影響を受けない最大ギャップは、前のプレフィックスから一定時間で取得できます。`g[i-1]`そしてその後の接尾辞`g[i]`。 

各削除候補は次のように評価されます。`O(1)`全体的な時間を与える`O(n)`解決。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 停止位置を読み取ります。 
2. ギャップアレイを構築する`g`、 どこ`g[i] = s[i+1] - s[i]`。 
3. プレフィックス最大配列を構築する`pref`。`pref[i]`最初からインデックスまでに見られる最大のギャップを保存します`i`。 
4. サフィックス最大配列を構築する`suff`。`suff[i]`インデックスとの最大ギャップを保存します`i`最後まで。 
5. 取り外し可能なすべてのストップを繰り返します。 

取り外したストップが隙間の間にある場合`g[i-1]`そして`g[i]`の場合、新しくマージされたギャップは次のようになります。`merged = g[i-1] + g[i]`。 
6. 影響を受けない最大のギャップを計算します。 

以前のギャップ`g[i-1]`貢献する`pref[i-2]`そのようなインデックスが存在する場合。 

その後のギャップ`g[i]`貢献する`suff[i+1]`そのようなインデックスが存在する場合。 

これら 2 つの値のうち大きい方が、影響を受けない最大ギャップとなります。 
7. この削除後の最大のセグメントは次のとおりです。`max(merged, unaffected_max)`。 
8. すべての削除候補の中から最小値を取得します。 
9. その最小値を出力します。 

### なぜ効果があるのか

 選択したストップについては、正確に 2 つの隣接するギャップが変更されます。 他のすべてのギャップは変更されません。 

そのストップを削除した後の最長セグメントは、新しくマージされたギャップか、変更されていないギャップのいずれかである必要があります。 プレフィックスとサフィックスの最大配列は、一定時間内でマージされたペアの外側の最大の不変ギャップを与えます。 

このアルゴリズムは、有効な削除ごとに正確な最長セグメントを評価し、その中で最小のものを返すため、常に削除に最適な停止を見つけます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
s = list(map(int, input().split()))

gaps = [s[i + 1] - s[i] for i in range(n - 1)]
m = n - 1

pref = [0] * m
pref[0] = gaps[0]
for i in range(1, m):
    pref[i] = max(pref[i - 1], gaps[i])

suff = [0] * m
suff[m - 1] = gaps[m - 1]
for i in range(m - 2, -1, -1):
    suff[i] = max(suff[i + 1], gaps[i])

ans = 10**18

for i in range(1, m):
    merged = gaps[i - 1] + gaps[i]

    other = 0
    if i - 2 >= 0:
        other = max(other, pref[i - 2])
    if i + 1 < m:
        other = max(other, suff[i + 1])

    ans = min(ans, max(merged, other))

print(ans)
```最初の部分では、停止位置をギャップ長に変換します。 ストップの削除は 2 つの隣接するギャップにのみ影響するため、ギャップの操作は非常に簡単です。 

プレフィックス配列とサフィックス配列を使用すると、影響を受けない最大のギャップを一定時間でクエリできます。 これらがなければ、候補を削除するたびにアレイ全体を再スキャンする必要があります。 

インデックスの扱いは微妙な部分です。 

間のストップを外すとき`g[i-1]`そして`g[i]`、影響を受けないギャップは以前のすべてです`g[i-1]`そしてその後のすべて`g[i]`。 

そのため、左の投稿では次のものが使用されます。`pref[i-2]`そして適切な貢献の用途`suff[i+1]`。 

使用する`0`一方の側が存在しない場合、ルートの終端付近の削除が正しく処理されます。 

Python の整数は、座標が最大でも次の値であるため、可能な最大距離値を簡単に処理できます。`10^9`。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    n = int(input())
    s = list(map(int, input().split()))

    gaps = [s[i + 1] - s[i] for i in range(n - 1)]
    m = n - 1

    pref = [0] * m
    pref[0] = gaps[0]
    for i in range(1, m):
        pref[i] = max(pref[i - 1], gaps[i])

    suff = [0] * m
    suff[m - 1] = gaps[m - 1]
    for i in range(m - 2, -1, -1):
        suff[i] = max(suff[i + 1], gaps[i])

    ans = 10**18

    for i in range(1, m):
        merged = gaps[i - 1] + gaps[i]

        other = 0
        if i - 2 >= 0:
            other = max(other, pref[i - 2])
        if i + 1 < m:
            other = max(other, suff[i + 1])

        ans = min(ans, max(merged, other))

    return str(ans) + "\n"

 ## 特殊なケース

 次のことを考慮してください。```
3
0 5 12
```取り外し可能なストッパーは 1 つだけです。 ギャップアレイは`[5, 7]`。 中間のストップを削除すると、それらがマージされます。`12`。 アルゴリズムは単一の候補を評価し、`merged = 12`、影響を受けないギャップを見つけず、出力します。`12`。 

考慮する：```
4
0 100 101 200
```ギャップは`[100, 1, 99]`。 

2 番目のストップを削除すると、マージされたギャップは次のようになります。`101`そしてもう一つのギャップ`99`、したがって最大値は次のようになります`101`。 

3 番目のストップを削除すると、結合されたギャップは次のようになります。`100`そしてもう一つのギャップ`100`、したがって最大値は次のようになります`100`。 

アルゴリズムは両方の可能性をチェックし、正しく返します。`100`。 

考慮する：```
5
0 1 100 101 102
```ギャップは`[1, 99, 1, 1]`。 

位置停止の解除`1`最初の 2 つのギャップをマージします`100`。 残りのギャップは、`1`そして`1`したがって、最大値は`100`。 

プレフィックスおよびサフィックスのクエリは、削除されたペアの片側にギャップが残っていないという事実を正しく処理します。 これはまさに、オフバイワンの間違いがよく発生する場所であり、インデックス チェックによってそれらの間違いが防止されます。
