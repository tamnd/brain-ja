 ## 解決策
 ## 問題の理解

 タスクは、単一の符号なし整数のストレージ ユニットのサイズを選択することです。 システムは、これまでに格納される最大値を知っており、ハードウェアの規則に従ってビット数を予約したいと考えています。つまり、ビット数自体は 2 の累乗でなければなりません。 したがって、有効なストレージ サイズは 1、2、4、8、16、32、64 などになります。 

入力は、メモリに収まる必要がある最大値を表す 1 つの整数です。 出力は、その値を格納できる最小有効ビット サイズと、その後に正しい単数形または複数形の表現が続きます。 

収納ユニット付き`b`ビットは次の値を表すことができます。`0`に`2^b - 1`。 入力は次のように大きくできるため、`10^18`、入力までのすべての可能な値を反復せずに答えを見つける必要があります。 仕事が比例するあらゆるアプローチ`n`最悪の場合、約 1 京の操作が必要になりますが、これは通常のコンテストの制限時間の許容範囲をはるかに超えています。 可能なビット サイズの小さなセットを検査するだけで済みます。 

エッジ ケースは、2 つのストレージ サイズ間の境界から生じます。 たとえば、入力`1`生産しなければならない`1 bit`、1 ビットで値を保存できるため`0`そして`1`。 2 ビットからチェックを開始するソリューションでは、誤って出力されます。`2 bits`。 

もう 1 つの境界ケースは、ストレージ容量から 1 を引いた値に正確に等しい値です。 入力用`255`、正しい出力は次のとおりです。`8 bits`、8 ビットには次の値が格納されるためです。`0`を通して`255`。 かどうかを確認する不注意な解決策`n < 255`の代わりに`n <= 255`誤って移動してしまう`16 bits`。 

もう 1 つの重要なケースは、値が 2 のべき乗の境界を 1 だけ超えている場合です。 入力用`256`、その最大値は次のとおりであるため、8 ビットではもはや十分ではありません。`255`。 答えは次のようになります`16 bits`。 

## アプローチ

 直接的なアプローチでは、可能なビット数を 1 から始めてすべて試し、そのビット数で指定された値を格納できるかどうかをテストします。 候補サイズの確認`b`単に、`2^b - 1`少なくとも必要な最大値です。 このメソッドは、サイズを昇順に調べ、最初の有効なサイズで停止するため、正しいです。 

このアプローチの問題は、候補がどのように生成されるかによって異なります。 考えられるすべてのビット数をチェックすることを想像すると、`1`入力値まで、最悪の場合の入力値に近い`10^18`約必要になる`10^18`チェック、それは不可能です。 有益な観察は、2 のべき乗のみが答えとして許可されるということです。 可能な最大入力を超える前に、そのような値はほんの少数しか存在しません。 容量が十分に大きくなるまで、現在の答えを 2 倍にすることを繰り返します。 

答えは最初の有効なサイズであるため、総当たりのアイデアは機能します。 有効なサイズが小さな幾何学的シーケンスを形成するという観察により、それらの間の無効なサイズをすべてスキップできます。

 ## アルゴリズムのチュートリアル

 1. ストレージ サイズから開始します。`1`少し。 これは可能な最小の割り当てであり、非常に小さな数がそこに収まる可能性があるため、考慮する必要があります。 
2. このビット数が必要な最大値を格納できるかどうかを確認します。 サイズ`bits`いつ動作しますか`2^bits - 1`少なくとも入力値です。 
3. 現在のサイズが小さすぎる場合は、2 倍にします。 許可されるサイズはすべて 2 の累乗であるため、次の有効なストレージ サイズに移動します。 
4. 容量が十分に大きくなるまで続行します。 機能する最初のサイズが必要な答えです。 
5. 正しい接尾辞を付けてサイズを出力します。 唯一の特異なケースは、`1`、出力には次のものが含まれます。`bit`; 他のサイズはすべて使用します`bits`。 

機能する理由: このアルゴリズムは有効なストレージ サイズのみを考慮し、昇順にチェックします。 答えは最小の有効なサイズとして定義されるため、容量が必要な値に達する最初のサイズが最適な選択である必要があります。 すべてのスキップされた値は許容されるストレージ サイズではないため、「スキップされた値なし」という方が良い答えになる可能性があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    bits = 1
    while (1 << bits) - 1 < n:
        bits *= 2

    if bits == 1:
        print("1 bit")
    else:
        print(f"{bits} bits")

if __name__ == "__main__":
    solve()
```変数`bits`現在割り当てられているビット数を格納します。 から始まります`1`なぜなら、1 ビットのストレージが有効な可能性があるからです。 

ループ条件は、現在のストレージ サイズで表現できる最大値をチェックします。 表現`(1 << bits) - 1`まさに`2^bits - 1`これにより、浮動小数点計算が回避され、すべての演算が整数演算として維持されます。 

乗算する`bits`2 倍にすることが重要なステップです。 答えを次のような任意の数字にすることはできません。`5`または`12`, そのため、1 ずつ増やすと、無効な候補をチェックする時間が無駄になります。 2 倍にすると、有効なストレージ サイズ間で直接ジャンプします。 

最後の条件は、唯一の文法上の例外を処理します。 収納サイズ`1`は単数形を使用しますが、それより大きいサイズではすべて複数形を使用します。

import sys
import io

def solve_case(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    bits = 1
    while (1 << bits) - 1 < n:
        bits *= 2

    return f"{bits} {'bit' if bits == 1 else 'bits'}"

 ## 特殊なケース

 入力の場合:```
1
```アルゴリズムは次から始まります`bits = 1`。 容量の計算により、`2^1 - 1 = 1`これで十分なので、ループはスキップされます。 出力は`1 bit`、単数形を正しく処理します。 

入力の場合:```
255
```アルゴリズムのテスト`8`噛んで見つけた`2^8 - 1 = 255`。 包括的な比較であるため、値は正確に一致し、答えは残ります。`8 bits`。 

入力の場合:```
256
```アルゴリズムは次のことを発見しました`8`ビットは容量を提供します`255`、不十分です。 サイズが2倍になります`16`、容量は`65535`、および出力`16 bits`。 

入力の場合:```
1100586419201
```アルゴリズムは、許容されるストレージ サイズを超えて倍増を続けます。 からの値`1`を通して`32`ビットは入力を表すことができませんが、`64`ビットはできます。 小さい有効なサイズはすべて最初に拒否されるため、結果は最小になることが保証されます。
