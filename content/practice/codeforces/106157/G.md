 ## 解決策
 ## 問題の理解

 チャーリーは`n`コンテストの数日前。 

彼が新鮮なとき、彼は利益を得る`a`1日あたりのスキルポイント、ただし最初のみ`x`リセット後の連続営業日。 彼がそれを超えて働き続けるなら`x`何日もかけて彼は疲れて、得るものだけが増えていく`b`1 日あたりのスキル ポイント、ここで`a ≥ b`。 

いつでも彼は休憩を始めるかもしれない。 休憩はきっちり続く`y`連続した日数ではスキルポイントは与えられません。 休憩が終わると、チャーリーは再び新鮮になって、再び楽しむことができます`x`利益を得た日々`a`。 目標は、利用可能なスキル ポイントの合計を最大化することです。`n`日々。 

制約は問題の重要な部分です。 両方`n`他のパラメータは次のように大きくできます。`10^9`、まであるかもしれません`10^4`テストケース。 毎日のシミュレーションは不可能です。 ソリューションは、テスト ケースごとに一定時間で実行されるクローズドフォームの最適化に基づいている必要があります。 

微妙な点は、休憩が常に役立つとは限らないということです。 休憩をとることで回復するスキルよりも多くのスキルが必要になる場合、最適な戦略はまったく休まないことかもしれません。 

もう 1 つの簡単な間違いは、すべての新しい期間を常に完全に使用する必要があると想定していることです。 スケジュールの終わり近くになると、すべてを消費するのに十分な日数が残らない可能性があります。`x`新鮮な日なので、最後のセグメントは慎重に扱う必要があります。 

考慮する：```
n = 5, a = 4, b = 1, x = 3, y = 1
```5 日間すべて働くと次のことが得られます。```
4 + 4 + 4 + 1 + 1 = 14
```3 日目の後に休憩をとると、次のことが得られます。```
4 + 4 + 4 + 0 + 4 = 16
```疲れた一日を別の新鮮な一日に変えることができるので、休憩は価値があります。 

次に、次のことを考えてみましょう。```
n = 10, a = 6, b = 5, x = 1, y = 5
```休憩は、価値の高い 1 日を回復するだけで 5 日かかります。 仕事を続けることはずっと良いことです。 

## アプローチ

 ブルートフォース ビューでは、考えられるすべてのブレークの配置を試します。 各スケジュールは、休憩で区切られた作業セグメントで構成されます。 セグメントの長さの増加`L`は```
a * min(L, x) + b * max(0, L - x)
```この定式化は正しいですが、可能なブレーク配置の数は指数関数的に増加し、中程度の値であっても絶望的になります。`n`。 

重要な点は、休憩の数のみが重要であるということです。 

正確に取るとします`m`休憩します。 

それらの休憩は消耗します`m * y`数日、出発```
W = n - m * y
```勤務日。 

疲労率を上回る合計ボーナスは、新鮮な日々から得られます。 すべての労働日には少なくとも価値がある`b`。 新鮮な一日はさらなる貢献をします```
a - b
```ボーナス。 

と`m`休憩、あります`m + 1`作業セグメント。 各セグメントが貢献できるのは最大でも`x`新鮮な日数であるため、新鮮な日数の合計が超えることはできません```
(m + 1) * x
```また、営業日数を超えることはできません`W`。 

したがって、次のようになります。```
fresh_days = min(W, (m + 1) * x)
```合計ゲインは次のようになります。```
b * W + (a - b) * fresh_days
```または```
G(m) = b * (n - m y)
     + (a - b) * min(n - m y, (m + 1) x)
```現在、問題は 1 次元の最適化になっています。 

2 つの地域があります。 

いつ```
n - m y > (m + 1) x
```新しいスロットはすべて完全に使用されます。 それから```
G(m)
= b n + (a - b) x + m((a - b)x - by)
```これは線形です`m`。 

いつ```
n - m y ≤ (m + 1) x
```毎日の勤務は新鮮なので、```
G(m) = a(n - m y)
```これは次のように減少します`m`が増加します。 

線形関数の後に減少関数が続く場合は、最適値が境界点の 1 つでのみ発生する可能性があることを意味します。 それらを一定時間で直接計算できます。

 ## アルゴリズムのチュートリアル

 1. もし`n ≤ x`、利用可能なすべての日を最初のフレッシュ期間に費やすことができます。 答えは簡単です:```
a * n
```2. コンピューティング```
m0 = ceil((n - x) / (x + y))
```これは、残りの勤務日ごとに更新できる休憩の最小数です。 
3. 最初の候補を評価します。```
G2 = a * (n - m0 * y)
```これは、すべての営業日が新鮮である 2 番目の領域に対応します。 
4. コンピューティング```
c = (a - b) * x - b * y
```これは、次の完全なサイクルをもう 1 つ追加することによって得られる利益です。`x`新鮮な日々と`y`休みの日。 
5. もし`c ≤ 0`、線形領域は減少しているため、その最良の点は`m = 0`。 
6. もし`c > 0`、線形領域は増加しているため、その最良点は有効な最大値になります。`m`2 番目の領域に入る前に:```
m1 = m0 - 1
```7. 評価する```
G1 = G(m1)
```または`G(0)`いつ`c ≤ 0`。 
8. 答えは次のとおりです。```
max(G1, G2)
```### なぜ効果があるのか

 休憩の数が固定されている場合、最適な配置は、存在する作業セグメントの数によって完全に決まります。 各セグメントの貢献度は最大でも`x`fresh days なので、fresh days の合計は正確に次のようになります。`min(W, (m + 1)x)`。 

これにより、問題全体が単一の整数の関数に還元されます。`m`。 この関数は、新鮮な生産能力が完全に飽和している間は線形であり、その後、毎営業日がすでに新鮮になると減少する線になります。 関数には遷移点が 1 つだけあるため、最大値は最初の線の最良点か 2 番目の線の最初の点で発生する必要があります。 それらの候補者を評価するだけで十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n, a, b, x, y = map(int, input().split())

        if n <= x:
            print(a * n)
            continue

        m0 = (n - x + (x + y) - 1) // (x + y)

        ans = a * (n - m0 * y)

        c = (a - b) * x - b * y

        if c <= 0:
            m = 0
        else:
            m = m0 - 1

        w = n - m * y
        g = b * w + (a - b) * min(w, (m + 1) * x)

        ans = max(ans, g)

        print(ans)

solve()
```最初のブランチは、最初の新規期間が利用可能なすべての日をすでにカバーしているという簡単な状況を処理します。`m0`これは、新しい総容量がすべての営業日をカバーするのに十分な大きさになる最初の休憩カウントです。 天井分割による計算は、実装の中で最もデリケートな部分です。 

変数`c`完全な新しいサイクルをさらに追加することが有益かどうかを測定します。 利益が得られない場合、線形領域の最良のポイントはすぐにあります。`m = 0`。 それ以外の場合、線形領域は境界まで増加するため、遷移前の最後の有効な点を評価します。 

すべての算術演算は 64 ビット整数に快適に収まりますが、Python の任意精度の整数を使用すると、その懸念さえ解消されます。

 ## 特殊なケース

 次のことを考慮してください。```
1
1 10 5 7 3
```以来`n ≤ x`, チャーリーは決して疲れません。 アルゴリズムはすぐに次の値を返します。```
10 × 1 = 10
```ブレーク関連のロジックは必要ありません。 

考慮する：```
1
10 5 5 3 2
```新鮮な日も疲れた日も同じ価値があります。 休憩は時間を無駄にするだけなので、サイクル利益はマイナスです。 アルゴリズムが選択するのは、`m = 0`、生産:```
10 × 5 = 50
```これが最適です。 

考慮する：```
1
5 4 1 3 1
```遷移点はちょうど 1 つのブレークで発生します。 アルゴリズムは境界の両側を評価します。```
G(0) = 14
G(1) = 16
```そして選択します`16`、最適な戦略が継続的な作業からリセットの使用に変わるポイントを正しく処理します。
