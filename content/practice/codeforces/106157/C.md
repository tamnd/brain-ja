 ## 解決策
 ## 問題の理解

 私たちは2つの異なる虹色の名前を与えられています。 

最初のカラーは、`C1`、単純化された「人間の視覚」システムが ASCII アートから認識しなければならない単語です。 ２色目は、`C2`、画像を通常の文字列として読み取る言語モデルがその色を認識し、他の虹色を認識しないようにするため、生のテキストに表示される単語です。 

認識モデルは非常に弱いです。 文字の実際の形状は関係ありません。 大文字の 4 つの接続されたコンポーネントはすべて 1 つの大きな文字として扱われ、使用される唯一の特徴はそのコンポーネント内の穴の数です。 

2 つの穴を持つコンポーネントは次のように解釈されます。`B`。 

穴が 1 つあるコンポーネントは、次のいずれかとして解釈されます。`A`、`D`、`O`、`P`、`Q`、`R`。 

穴がゼロのコンポーネントは、他の文字として解釈されます。 

6 つの虹の色の名前は異なる穴数の順序を持​​っているため、色を認識することは穴数の順序を認識することになります。 

これは純粋に建設的な問題です。 入力サイズは小さく、色の名前のペアは 1 つだけあり、出力は一連の幾何学的制約を満たすだけで済みます。 課題は効率ではなく、常に機能する構造を見つけることです。 

主な落とし穴は、印刷された文字列内に別の色の名前が偶然出現すると、直ちにステートメントに違反することです。 もう 1 つの簡単な間違いは、2 つの隣接するコンポーネントが接触することを許可することです。これにより、それらのコンポーネントが 1 つの大きなコンポーネントにマージされ、認識エンジンが認識するホール カウントのシーケンスが完全に変化してしまいます。 

## アプローチ

 強引な考え方では、すべての色に対して実際の楷書体を描画し、言語モデルの色を何らかの方法で画像内に隠そうとします。 これは概念的には機能しますが、多数の幾何学的ケースが作成され、正しさを推論することが困難になります。 

重要な観察は、認識装置がホールをカウントするだけであるということです。 コンポーネントが実際のアルファベットに似ているかどうかは決してチェックされません。 

それに気づくと、どのキャラクターも、`C1`正確に 0、1、または 2 個の穴を持つコンポーネントを作成することだけを目的とした小さなテンプレートで置き換えることができます。 

虹色に表示されるすべての文字に関連付けられた穴の数を事前に計算できます。 

次に、文字ごとに 1 つの接続コンポーネントを構築します。`C1`、隣接するコンポーネントを少なくとも 1 列のドットで分離します。 レコグナイザーは、意図したホールカウントシーケンスを正確に読み取ります。 

言語モデル部分については、単純に次のように配置します。`C2`最終行の通常のテキストとして。 1 行おきに無害なフィラー文字のみが使用されているため、他の虹色の名前を部分文字列として使用することはできません。

### なぜ効果があるのか

 各テンプレートは、4 つの接続された単一のコンポーネントを形成します。 最初のテンプレートには囲まれた領域が含まれておらず、2 番目のテンプレートには 1 つの囲まれた領域が含まれ、3 番目のテンプレートには 2 つの囲まれた領域が含まれています。 

隣接するテンプレートはドットの列全体で区切られているため、コンポーネントが接触することはありません。 したがって、認識装置は文字ごとに 1 つのコンポーネントを認識します。 

認識装置によって認識されるホール カウントのシーケンスは、正確に次の文字に対応するシーケンスです。`C1`、したがって、画像は次のように解釈されます`C1`。 

最後の行には明示的に以下が含まれています`C2`スタンドアロンの部分文字列として、言語モデルの要件を満たします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

c1 = input().strip()
c2 = input().strip()

holes = {
    'A': 1, 'B': 2, 'C': 0, 'D': 1, 'E': 0, 'F': 0, 'G': 0,
    'H': 0, 'I': 0, 'J': 0, 'K': 0, 'L': 0, 'M': 0, 'N': 0,
    'O': 1, 'P': 1, 'Q': 1, 'R': 1, 'S': 0, 'T': 0, 'U': 0,
    'V': 0, 'W': 0, 'X': 0, 'Y': 0, 'Z': 0
}

templates = {
    0: [
        "XXX",
        "X..",
        "X..",
        "X..",
        "XXX",
    ],
    1: [
        "XXX",
        "X.X",
        "X.X",
        "X.X",
        "XXX",
    ],
    2: [
        "XXX",
        "X.X",
        "XXX",
        "X.X",
        "XXX",
    ]
}

rows = [""] * 5

for i, ch in enumerate(c1):
    pat = templates[holes[ch]]
    for r in range(5):
        rows[r] += pat[r]
        if i + 1 != len(c1):
            rows[r] += "."

width = max(len(rows[0]), len(c2))

for i in range(5):
    rows[i] += "." * (width - len(rows[i]))

rows.append(c2 + "." * (width - len(c2)))

print("\n".join(rows))
```最初の部分では、穴数のマッピングを構築します。 重要な値は 0、1、2 の 3 つだけです。 

3 つのテンプレートは、それぞれが接続され、必要な数の穴ができるように慎重に選択されています。 

構築ループは、次のすべての文字を変換します。`C1`をテンプレートに挿入し、隣接するコンポーネントの間にドットの区切り列を挿入します。 このセパレータがないと、2 つのコンポーネントが 1 つのより大きな接続された領域にマージされる可能性があります。 

5 つの描画行が終了したら、必要な長方形の幅を計算します。 すべての行は同じ長さである必要があるため、短い行にはドットが埋め込まれます。 

最後に、最後の行には次の内容が含まれます`C2`同じ幅にパディングされます。

 ## 特殊なケース

 のような色`BLUE`すべての虹色の中で唯一の 2 穴の文字から始まります。 この構造では、専用の 2 穴テンプレートを選択することでこれに対応します。 認識機能は、ちょうど 2 つの囲まれた領域を持つコンポーネントを認識し、それを次のように正しく解釈します。`B`。 

のような色`ORANGE`いくつかの連続した一穴文字で始まります。 すべてのコンポーネントはドット列で区切られているため、これらの 1 穴コンポーネントがマージされることはありません。 認識機能では、依然として 1 つの大きなコンポーネントではなく、3 つの異なる文字が認識されます。 

のような色`GREEN`ゼロホール文字とワンホール文字の両方が含まれています。 ホール数はコンポーネントごとに個別にエンコードされるため、混合シーケンスは特別なロジックを必要とせずに自動的に処理されます。
