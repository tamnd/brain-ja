 ## 解決策
 ## 問題の理解

 各入力値は、整数のラベルが付いたボックスとして見ることができ、ボックスごとに、その数値の自明ではない約数を 2 つ選択する必要があります。 選択した約数は両方とも 1 より大きく、数値を正確に除算する必要があり、元の数値の素因数で和を除算することはできないという意味で、その合計は元の数値と「互換性がない」必要があります。 

出力では、すべての数値に対してそのような約数のペアが表示されるか、-1 -1 で失敗が宣言されます。 重要な問題は、制約が、選択した約数自体の割り切りに関するものではなく、その和とその数の完全な素数構造との関係に関するものであることです。 

制約は大きく、最大 5×10^5 の数値 (それぞれの数値は 10^7 まで) です。 これにより、試行除算による数値ごとの因数分解が除外されます。 O(n√a_i) のアプローチであっても、最悪の場合は約 10^10 の操作が必要となり、これは制限時間を大幅に超えます。 この構造は、値の範囲全体にわたる前処理ステップを強く示唆しています。最も自然なのは、数値ごとに定数または定数に近い係数クエリを許可するふるいのようなものです。 

数値が素数の場合、微妙な特殊なケースが発生します。 たとえば、8 の場合、1 より大きいすべての約数は依然として同じ素数のみで構成されているため、そのような 2 つの約数の和はその素数で割り切れたままとなり、直ちに gcd 条件に違反します。 このような場合、有効なペアは存在しません。 

もう 1 つのエッジ ケースは、数値に複数の異なる素数があるが、そのうちの 1 つが特定の因数分解の選択肢に 1 回しか現れない場合です。 任意の約数を選択する不用意なアプローチは失敗する可能性があります。両方の約数が個別に有効であっても、和が誤って元の数値を持つ共有素因数を継承する可能性があるためです。 

## アプローチ

 ブルートフォース戦略では、各数値のすべての約数のペアを調べます。 単一の値 a_i の場合、すべての約数を列挙し、すべてのペアをテストして、gcd(d1 + d2, a_i) が 1 に等しいかどうかを確認できます。 最悪の場合、10^7 のような数値には数千の約数が含まれる可能性があり、5×10^5 クエリ全体でこれは計算上実行不可能になります。 約数を列挙すること自体でも因数分解が必要ですが、それがすでに複雑さを占めています。 

重要な点は、任意の約数が必要ないということです。 数値の素因数分解から得られる非常に特殊な構造を持つペアを構築するだけで十分です。 a_i を p^k · b と書きます。ここで、p は a_i の最小の素因数であり、p は b を割りません。 b が 1 に等しい場合、その数は純粋な素数累乗であり、解は存在しません。 それ以外の場合、 d1 = p^k および d2 = b を選択すると、両方が 1 より大きい有効な約数であることが保証され、共有素因数に関する構造矛盾の議論により gcd 条件が成立します。 

これにより、問題は高速因数分解クエリに縮小され、事前に計算された最小の素因数ふるいを使用して答えることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n · d^2 + 因数分解コスト) | O(1) おまけ | 遅すぎる |
 | 最適 | O(N log log N + n log a_i) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### 前処理と構築ロジック

1. 10^7 までのすべての整数の最小素因数の配列を作成します。 これにより、最小の素数で繰り返し除算することで、任意の数値をすばやく素因数分解することができます。 
2. 各数値 a_i について、その最小の素因数 p を取得します。 これにより、p が因数分解の最初の素数であることが保証され、きれいに分離できるようになります。 
3. 割り切れる間に繰り返し割り算を行うことで、a_i から p の全累乗を抽出します。 これにより、p^k と、p で割り切れない残りの値 b が生成されます。 
4. b が 1 に等しい場合、その数値は素数べき乗であり、有効な分解が存在しないため、-1 -1 を出力します。 
5. それ以外の場合は、d1 = p^k および d2 = b を設定します。 どちらも 1 より大きいことが保証されており、両方とも a_i を除算します。 
6. 構築されたペアを出力します。 

### なぜ効果があるのか

 a_i = p^k · b とします。ここで、p は b を除算しません。 ある素数 q が d1 + d2 と a_i の両方を除算するとします。 次に、因数分解における素数の唯一のソースが p または b であるため、q は p または b のいずれかを除算する必要があります。 q = p の場合、p は p^k + b を除算します。これは、p が b を除算することを意味し、構造に矛盾します。 q が b を除算する場合、q は b と p^k + b の両方を除算します。これは、q が p^k を除算することを意味しますが、p は q で割り切れないため、これは不可能です。 これにより、考えられるすべての共有素数が排除されるため、gcd は 1 でなければなりません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXA = 10**7

spf = list(range(MAXA + 1))
for i in range(2, int(MAXA ** 0.5) + 1):
    if spf[i] == i:
        step = i
        start = i * i
        for j in range(start, MAXA + 1, step):
            if spf[j] == j:
                spf[j] = i

def solve():
    n = int(input())
    arr = list(map(int, input().split()))

    out1 = []
    out2 = []

    for x in arr:
        p = spf[x]

        d1 = 1
        while x % p == 0:
            x //= p
            d1 *= p

        d2 = x

        if d2 == 1:
            out1.append("-1")
            out2.append("-1")
        else:
            out1.append(str(d1))
            out2.append(str(d2))

    print(" ".join(out1))
    print(" ".join(out2))

if __name__ == "__main__":
    solve()
```ふるいは最小の素因数を事前に計算するので、各数値をそのサイズに関して対数時間で分解できます。 内側のループは最小の素数の全累乗を抽出し、d1 がクリーンな素数べき約数であり、d2 に残りの構造が含まれることを保証します。 

重要な実装の詳細は、d1 の構築中に x が破壊的に削減されることです。 これにより、追加の乗算や因子の追跡を必要とせずに、d2 が正確に相補的な因子であることが保証されます。 

## 実用的な例

 次のサンプル入力を考えてみましょう。```
10
2 3 4 5 6 7 8 9 10 24
```いくつかの代表的な値を追跡します。 

| あ_い | p = spf | d1工事 | 残り d2 | 結果 |
 | --- | --- | --- | --- | --- |
 | 4 | 2 | 2^2 = 4 | 1 | -1 -1 |
 | 6 | 2 | 2 | 3 | (2, 3) |
 | 8 | 2 | 2^3 = 8 | 1 | -1 -1 |
 | 24 | 2 | 2^3 = 8 | 3 | (8, 3) |

 6 の場合、2 と 3 は別個の素因数から導出されるため、2 と 3 への分割は機能します。 24 の場合、2 の全累乗を分離すると 3 が残り、それらの合計により 24 との共通素因数が回避されます。 

これは、この構造が常に最小素数の寄与を残りの因数分解からきれいに分離していることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(MAXA log log MAXA + n log a_i) | ふるいは最小の素因数を構築し、各数値は繰り返し除算によって分解されます。 
| スペース | O(MAXA) | SPF アレイのストレージは最大 10^7 |

 前処理が 1 回だけ優先され、各クエリは抽出された素因数の数に比例した時間内に処理されますが、実際にはその数は少ないです。 これは、時間とメモリの制限内に問題なく収まります。 

## テストケース```python
import sys, io

def solve():
    input = sys.stdin.readline
    MAXA = 10**7

    spf = list(range(MAXA + 1))
    for i in range(2, int(MAXA ** 0.5) + 1):
        if spf[i] == i:
            for j in range(i * i, MAXA + 1, i):
                if spf[j] == j:
                    spf[j] = i

    n = int(input())
    arr = list(map(int, input().split()))

    res1 = []
    res2 = []

    for x in arr:
        p = spf[x]
        d1 = 1
        while x % p == 0:
            x //= p
            d1 *= p
        d2 = x
        if d2 == 1:
            res1.append("-1")
            res2.append("-1")
        else:
            res1.append(str(d1))
            res2.append(str(d2))

    print(" ".join(res1))
    print(" ".join(res2))

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    old_stdout = sys.stdout
    sys.stdout = io.StringIO()
    solve()
    out = sys.stdout.getvalue()
    sys.stdout = old_stdout
    return out.strip()

assert run("1\n2\n") == "-1\n-1"
assert run("3\n4 6 8\n") in ["-1 -1\n2 3\n-1 -1", "-1 -1\n3 2\n-1 -1"]
assert run("1\n6\n") in ["2\n3", "3\n2"]
assert run("1\n24\n") in ["8\n3", "3\n8"]
assert run("2\n6 10\n") in ["2 2\n3 5", "2 2\n5 3"]
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 2 | -1 -1 | プライム処理 |
 | 3 4 6 8 | 混合 | 複合パワーとプライムパワー |
 | 1 6 | 2 3 | 基本的な因子分割 |
 | 1 24 | 8 3 | より高いプライムパワー |
 | 2 6 10 | 有効な分割 | 複数のクエリの一貫性 |

 ## 特殊なケース

 16 のような素数の場合、アルゴリズムは d1 が 16 になり、d2 が 1 になるまで p = 2 を繰り返し抽出します。これにより、失敗条件が即座にトリガーされ、すべての約数が 1 つの素数に限定されるため、入力が正しく拒否されます。 

10 のような数値の場合、分解により p = 2、d1 = 2、d2 = 5 が得られます。合計は 7 で、10 と素因数を共有せず、両方の約数が個別に素数であっても、正確であることが確認されます。 

12 などの複数の因数を含む数値の場合、2 の全累乗を抽出すると、d1 = 4 および d2 = 3 が生成されます。他の有効な分解が存在する場合でも、この構築では、因数分解の残りの部分から最小の素数成分を分離することにより、合計内の素数の共有を一貫して回避します。
