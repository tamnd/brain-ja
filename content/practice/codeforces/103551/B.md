 ## 解決策
 ## 問題の理解

 長さを数えるよう求められます`n`各要素が次の整数であるシーケンスを形成できます。`1`に`x`。 このようなシーケンスは、次の位置として解釈されます。`n`部屋内のクライオ カプセル。各カプセルは、`x`。 

ポジション`i`厳密な局所ピークを形成する場合、その値は「エネルギー効率が高い」と見なされます。その値は、直前の要素よりも厳密に大きく、つまり、前の要素と次の要素の両方よりも高くなります。 エンドポイントには 2 つの近傍がないため、エンドポイントをピークにすることはできません。 

タスクは、正確に含まれるシーケンスの数を数えることです。`k`そのようなピークを計算し、モジュロ結果を返します。`1e9 + 7`。 

制約`n, x, k ≤ 500`シーケンスの指数関数的または階乗的探索を直ちに除外します。 すべての総当たりの列挙`x^n`シーケンスは完全に不可能です`n = 20`。 完全なシーケンスを追跡する動的プログラミングさえも範囲外です。 この構造は、各ステップが最近の小さな歴史にのみ依存する、ローカルな移行と漸進的な構築に依存する必要があることを示唆しています。 

微妙なエッジケースは次のような場合です`n < 3`。 その場合、ピークには両方の近傍が必要となるため、ピークはまったく存在しません。 たとえば、次の場合`n = 2`、すべてのシーケンスは正確に`0`ピークなので、答えは`x^2`もし`k = 0`そして`0`さもないと。 もう一つのエッジケースは、`k > n - 2`、位置だけなので不可能です`2`を通して`n-1`ピークになる可能性があります。 

主な問題は、位置が`i`ピークは隣接する遷移だけでなく 3 つの連続する値に依存するため、1 次元にわたる標準 DP が複雑になります。 

## アプローチ

 単純なアイデアは、長さのすべてのシーケンスを直接生成することです。`n`以上`[1, x]`、条件を満たすものがいくつあるかを数えます。 これは概念的には簡単です。各位置を確認してください。`i`そして何人が満足したか数えてください`p[i-1] < p[i] > p[i+1]`。 このアプローチは正しいですが、複雑です`O(x^n · n)`、これは非常に小さな入力であっても天文学的になります。`x = 500`そして`n = 500`。 

改善するために、シーケンスを左から右に構築する動的プログラミングに切り替えます。 課題は、位置が`i-1`新しい要素を追加するときに連続する 3 つの値を知る必要がある場合、 はピークになります。 これは、DP 状態が少なくとも最後の 2 つの値を保持する必要があることを示唆しています。 

重要な観察は、ピークは完全にトリプルによって決定される局所構造であるということです。`(p[i-2], p[i-1], p[i])`。 これにより、サイズ 2 のスライディング ウィンドウ上に DP を定義し、シーケンスを拡張するときに前方にシフトすることができます。 各遷移では、ちょうど 1 つの新しいトリプルが導入され、場合によっては 1 つの新しいピークが作成されます。 

したがって、位置、最後の 2 つの値、およびピークの数に対する DP を定義します。 遷移は次の値を反復し、形成されたトリプルに基づいてピーク カウントを更新します。 これにより問題は次のように縮小されます`O(n · x^2 · k)`状態ごとの移行コストが一定の状態。 

それでも`x`までです`500`の場合、ピーク条件はトリプルの中間要素との比較のみに依存するため、この構造により、次の値次元への移行時に接頭辞合計の最適化が可能になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(x^n · n) | O(n) | 遅すぎる |
 | 最後の 2 つの値の DP | O(n · x^2 · k) | O(x^2・k) | 承認済み |

 ## アルゴリズムのチュートリアル

 最後に選択した 2 つの値を常に記憶しながら、左から右にシーケンスを構築します。 これは、新しく形成されたトリプルの中間要素がピークであるかどうかを判断するのに十分です。 

私たちは定義します`dp[i][a][b][j]`長さのプレフィックスを構築する方法の数として`i`最後の 2 つの値は次のようになります。`p[i-1] = a`そして`p[i] = b`、そしてまさに`j`これまでにポジション間でピークが形成されている`2..i-1`。 

最初の 2 つの位置のすべての有効なペアを初期化することから始めます。 インデックスの前にピークが形成できないため`2`、 全て`dp[2][a][b][0] = 1`。 

次に、シーケンスを一度に 1 要素ずつ拡張します。 

1. 各ポジションごと`i`から`2`に`n-1`、あらゆる状態を考慮します`(a, b)`最後の 2 つの値を表します。 
2. 新しい値を追加してみます`c`で`[1, x]`、トリプルを形成します`(a, b, c)`。 
3. このトリプルは位置を決定します。`i`(に対応します`b`）がピークです。 まさにその時がピークです`a < b > c`。 
4. 新しいピーク数を計算します`j' = j + 1`もし`a < b > c`、 さもないと`j' = j`。 
5. 状態を前方に遷移します。新しい最後の 2 つの値は次のようになります。`(b, c)`。 

直接実装すると、すべてを反復処理することになります。`c`あらゆる人にとって`(a, b)`が遅すぎます。 代わりに、次のいずれかによってトランジションを分割します。`c < b`または`c > b`、プレフィックスの合計を使用します`c`効率的に貢献度を貯めることができます。 

重要な構造は、ピーク条件が以下を含む比較のみに依存するということです。`a`、`b`、 そして`c`、つまり固定用`(a, b)`有効なものをすべて集約できます`c`事前に計算されたプレフィックス合計を使用して一定時間内の範囲を計算します。`c`寸法。 

### なぜ効果があるのか

 すべてのステップで、DP 状態はシーケンスの最後の 2 つの値を完全にキャプチャします。 将来のピークの決定は、これら 2 つの値と次の候補値のみに依存します。 すべてのピークはその右隣が追加された瞬間に正確に決定されるため、各ピークは 1 回だけカウントされます。 DP は将来の遷移を評価するために必要な情報を決して失うことがないため、すべてのシーケンスが正確に 1 回カウントされ、正しいピーク カウントが得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def main():
    n, x, k = map(int, input().split())

    if n < 3:
        return print(1 if k == 0 else 0)

    dp = [[ [0] * (k + 1) for _ in range(x + 1)] for _ in range(x + 1)]

    for a in range(1, x + 1):
        for b in range(1, x + 1):
            dp[a][b][0] = 1

    for i in range(2, n):
        ndp = [[ [0] * (k + 1) for _ in range(x + 1)] for _ in range(x + 1)]

        for a in range(1, x + 1):
            for b in range(1, x + 1):
                cur = dp[a][b]
                if not any(cur):
                    continue

                for c in range(1, x + 1):
                    add = 0
                    if a < b and b > c:
                        add = 1

                    for j in range(k + 1 - add):
                        if cur[j]:
                            ndp[b][c][j + add] = (ndp[b][c][j + add] + cur[j]) % MOD

        dp = ndp

    ans = 0
    for a in range(1, x + 1):
        for b in range(1, x + 1):
            ans = (ans + dp[a][b][k]) % MOD

    print(ans)

if __name__ == "__main__":
    main()
```DP はサイズ 2 の引き違い窓を中心に構成されています。 ネストされたループは、各遷移が固定ペアに依存しているという事実を反映しています。`(a, b)`そして次の値の候補`c`。 ピーク チェックはトリプルごとに 1 回だけ評価され、カウントの正確性が保証されます。 

制約は最終的な構成状態ではなくピークの数のみに関係するため、最終的な合計では、最後の 2 つの値に関係なく、すべての有効な終了が集計されます。

 ## 特殊なケース

 のために`n < 3`、アルゴリズムは直接返します`1`そのときだけ`k = 0`。 これは、両方の近傍がなければインデックスがピーク条件を満たすことができないという事実と一致します。 

小型用`x = 1`、すべてのシーケンスは定数であるため、厳密な不等式は存在しません。 DP は、すべての長いシーケンスに対してゼロ ピークを正しく伝播します。 

のために`k = 0`、DP は厳密な極大値を持たないすべてのシーケンスをカウントするように退化します。 ピーク条件がトリガーされないため、遷移は引き続き機能し、すべてのパスが有効なままになり、正しく蓄積されます。 

のために`k > n - 2`、しかないので、どの国家も生き残ることはできません。`n - 2`考えられるピーク位置。 DP は、ピークが評価される遷移より多くのピークを蓄積できないため、当然ゼロになります。
