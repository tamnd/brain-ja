 ## 解決策

 ## 問題の理解

 すべてのエッジが 1 から n − 1 までの固定順序を持つツリーが与えられます。最初は、すべての頂点がトークンとして独自のラベルを保持します。 エッジは厳密にインデックスの昇順で処理され、各エッジで 1 つのエンドポイントから 1 つのトークンだけを削除することがありますが、これはその時点で両方のエンドポイントにトークンがまだある場合に限ります。 削除されたトークンの値は、グローバル出力シーケンスに追加されます。 

重要な点は、選択がローカルであるということです。エッジが処理されるときに、どのエンドポイントを「犠牲」にするかを選択しますが、トークンは永久に消えるため、その選択はその後のすべてのエッジに影響します。 エッジ全体で異なる選択をすると、最終的なシーケンスが異なる可能性があるため、異なるシーケンスがいくつ生成されるかを数えなければなりません。 

制約では最大 200,000 個の頂点が許可されるため、構成を列挙したり、すべての選択肢をシミュレートしたりするソリューションは不可能です。 エッジを越えた単純なバックトラッキングでも、各エッジで最大 2 ずつ分岐し、最悪の場合は指数関数的な増加につながります。 これにより、エッジ順序付けによって引き起こされるツリー構造に対して動的プログラミングを使用して選択肢を集約するソリューションが直ちに強制されます。 

すでにトークンを「失った」パーツをエッジが接続する場合、微妙な問題が発生します。 このような場合、エッジは非アクティブになり、何も貢献しません。つまり、早期の決定により、サブツリー全体がそれ以降の相互作用から「消去」される可能性があります。 もう 1 つの特殊なケースは、頂点に付随する複数のエッジが後の順序で出現する場合であり、早期の削除が重要になります。間違ったエンドポイントを早期に削除すると、将来のコントリビューション パスが完全に切断され、シーケンスだけでなくその実現可能性も変化する可能性があります。 

これはツリー上の貪欲な枝刈りの問題であると考えるのが単純な誤解を招く直観ですが、決定は純粋に構造的な隣接関係ではなくエッジ順序を通じて前方に伝播するため、貪欲な選択は失敗します。 

## アプローチ

 ブルートフォース手法でプロセスをシミュレートします。エッジごとに、両方が生きている場合にどちらのエンドポイントを削除するかを分岐します。 アクティブな頂点のセットを維持し、考えられるすべてのシーケンスを生成します。 これによりプロセスが正しくモデル化されますが、エッジごとにバイナリ分岐が作成され、最大 2^(n−1) 状態が生成されます。 トークンの構成は将来のエッジ インタラクションに影響を与える点で異なるため、同一の状態を枝刈りしても効果はありません。 

重要な観察は、エッジが固定された順序で処理されるため、依存関係の構造は時間的には線形ですが、空間的にはツリー状であるということです。 各エッジは、以前の削除に応じてアクティブになるか非アクティブになり、アクティブになると、ちょうど 1 つのエンドポイントが消費されます。 これにより、削除されたエンドポイントにエッジを向けると解釈できる依存構造が作成されます。 

プロセスを再解釈できます。各エッジがアクティブな場合、1 つのエンドポイントを「削除された側」として選択します。そのエンドポイントは、前のエッジによって以前に削除されていることはありません。 これにより問題は、エッジの有効な方向をカウントすることに変わり、インシデントに処理されたエッジの 1 つがそれを「要求」したときにすべての頂点が正確に削除されるようになります。 

重要な簡素化は、エッジを順番に処理し、すでに処理されたエッジによって形成された接続コンポーネント上の DP を維持することです。 エッジを処理するたびに、2 つのコンポーネントをマージし、それらの間で削除責任を一貫して割り当てる方法が何通りあるかを数えます。 これにより、問題はエッジインデックス付きユニオン検索構造上のツリー DP に縮小されます。

 ## アルゴリズムのチュートリアル

1. 各頂点が独自のコンポーネントである素集合結合 (DSU) 構造を初期化します。 各コンポーネントは処理されたエッジのサブツリーを表し、有効な内部構成の数を表す DP 値を維持します。 
2. 最初にすべての頂点に対して dp[v] = 1 を設定します。 まだエッジが処理されていないため、単一の孤立した頂点には単純な構成が 1 つだけあります。 
3. エッジを昇順に処理します。 エッジ (u, v) の場合、Cu と Cv を u と v を含むコンポーネントとします。 
4. Cu が Cv に等しい場合、エッジは同じ処理済みコンポーネント内にすでにあるノードを接続しているため、両方のエンドポイントはすでに内部拘束されています。 この場合、現時点では両方のエンドポイントが同時にアクティブなトークンを持つことができないため、エッジは何も寄与しません。 ただ続けるだけです。 
5. それ以外の場合は、2 つの独立したコンポーネントをマージする必要があります。 この時点で、エッジは、以前は独立していた 2 つの DP 状態間に相互作用を導入します。 
6. このエッジを解決できる方法の数は、どちらの側がトークンを「失う」かの選択によって異なります。 DP の累積に関して Cu がサイズ a に寄与し、Cv がサイズ b に寄与する場合、新しく結合された DP は dp[new] = dp[Cu] * dp[Cv] * (a + b) になります。 この用語は、削除されたトークンが 2 つのコンポーネントのいずれかから取得される必要があり、各コンポーネントがすべての内部ウェイに独立して寄与することを反映しています。 
7. 新しい DP 値を計算した後、DSU で Cu と Cv を結合し、結果として得られるルートの dp を保存します。 
8. すべてのエッジが処理されるまで続行します。 答えは dp[find(任意の頂点)] です。 

### なぜ効果があるのか

 いつでも、各 DSU コンポーネントは、すべての内部エッジ決定が修正された、完全に処理されたサブグラフを表します。 DP 値は、その構造内で除去を割り当てる有効な方法の数をエンコードします。 2 つのコンポーネントが新しいエッジによってマージされる場合、新しい自由度は、この接続エッジによってトリガーされるトークンの削除にどちらの側が寄与するかだけです。 以前のエッジはこの選択に影響を与えることができないため、乗算構造は有効であり、コンポーネント間の独立性は維持されます。 

不変条件は、dp[C] がコンポーネント C に限定された処理済みエッジと一致するすべての有効な内部シーケンスをカウントし、接続エッジによって結果が以前の内部割り当てに干渉しない新しいバイナリ選択肢が 1 つだけ導入されるため、2 つのコンポーネントをマージすると正確さが保たれるということです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

class DSU:
    def __init__(self, n):
        self.p = list(range(n))
        self.sz = [1] * n
        self.dp = [1] * n

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return

        if self.sz[a] < self.sz[b]:
            a, b = b, a

        # merge b into a
        self.p[b] = a
        self.dp[a] = self.dp[a] * self.dp[b] % MOD

        # new edge introduces choice: pick endpoint side
        self.dp[a] = self.dp[a] * (self.sz[a] + self.sz[b]) % MOD

        self.sz[a] += self.sz[b]

n = int(input())
dsu = DSU(n)

for _ in range(n - 1):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    dsu.union(u, v)

print(dsu.dp[dsu.find(0)])
```DSU は接続と DP アグリゲーションの両方を維持します。 サイズ配列は、各コンポーネントにある頂点の数を追跡します。これは、2 つのコンポーネントをマージするときに組み合わせ係数を計算するために使用されます。 dp 配列には、各コンポーネント内の有効な構成の数が格納されます。 

結合ステップは、組み合わせ分岐が導入される唯一の場所です。 dp 値を乗算すると独立した部分問題が結合され、サイズの合計によって新しい接続エッジによって導入された有効な選択肢の数が取得されます。 

パス圧縮により、ほぼ一定の時間で償却された操作が保証され、最大の制約に対してソリューションの効率が維持されます。

 ## 特殊なケース

 2 つの頂点を持つ最小ツリーは 1 つのエッジを処理します。 最初は両方のエンドポイントがアクティブであるため、正確に 1 つの削除が発生し、どちらのエンドポイントが選択されたかに応じて 2 つの異なる結果が存在します。 DSU は 2 つのシングルトン コンポーネントをマージし、dp = 2 を与え、2 つの可能なシーケンスと一致させます。 

パス形状のツリーでは、順次依存関係が強制されます。 各エッジは新たに拡張されたコンポーネントを接続し、DSU は干渉することなく乗法的な選択肢を蓄積します。 すべてのマージは、前の制約に違反することなく 1 つのエンドポイントだけを削除できる一意の決定ポイントに対応するため、アルゴリズムは有効な構成のみを正しくカウントします。 

星型ツリーは、すべての選択肢を中心ノードの周りに集中させます。 各リーフ エッジは処理される時点では独立しており、DP の乗算は、各リーフが接続時に削除方向の新しい独立した選択に寄与することを正しく反映しています。
