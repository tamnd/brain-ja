 ## 解決策
 ## 問題の理解

 小文字で構成される文字列が与えられます。 特定の長さ 3 のパターンは「悪い」とみなされます。具体的には、部分文字列です。`"one"`そして`"two"`。 このような不正なトリプルが文字列内のどこかに出現すると、その文字列は受け入れられなくなります。 

私たちの操作は、文字列内のいくつかの位置を選択し、それらの文字を同時に削除するというものです。 削除後、残りの文字は元の順序を維持します。 目標は、結果の文字列に次の文字列が含まれないように、できるだけ少ない位置を削除することです。`"one"`または`"two"`。 

タスクは、最小削除数を計算するだけでなく、その最小値を達成する有効なインデックスのセットを出力することも行います。 

制約構造は重要です。 すべてのテスト ケースの合計の長さは最大 150 万であるため、すべてのソリューションは合計入力サイズにおいて線形である必要があります。 部分文字列に対する 3 次または 2 次スキャンはすぐにタイムアウトになります。 シングルパスまたはそれに近いパスで除去を決定する貪欲または線形の動的プロセスが必要です。 

微妙な難しさはパターンの重なりです。 1 つの文字が複数の禁止された部分文字列に属することができます。 たとえば、`"twone"`、部分文字列`"two"`と重なる`"one"`キャラクターのところに`'o'`。 1 つのパターンを個別に修正する単純なアプローチでは、1 つの削除で複数の不正な部分文字列が壊れる可能性があることを見落とす可能性があります。 

もう 1 つのエッジ ケースは、次のような連続パターンです。`"oneoneone"`ここで、削除しすぎずにすべての出現を破壊するために、最適な削除の間隔を慎重に配置する必要があります。 

## アプローチ

 ブルートフォースのアイデアは、文字列を繰り返しスキャンし、次のような文字列の出現を検出することです。`"one"`または`"two"`、出現するたびに 1 文字を削除し、不良な部分文字列がなくなるまで繰り返します。 すべてのステップで違反の数が減少するため、これは原理的には正しいですが、コストが高すぎます。 各パスは O(n) であり、削除が最小限である敵対的なケースでは、O(n) パスが必要になる可能性があり、長い文字列に対して O(n²) 動作が発生します。 

重要な観察は、すべての不良部分文字列が固定長 3 であり、アルファベットの構造がパターン マッチングによってのみ小さいことです。 違反を繰り返し修正する代わりに、左から右に貪欲に削除を決定できます。 不正なトリプルを検出したら、将来の競合を防ぎ、以前の決定を再度検討しないように、1 文字だけを削除できます。 

重要な洞察は、左から右にスキャンすることで「クリーンなプレフィックス」の不変条件を維持できるということです。つまり、現在位置より前のすべてのものには、削除が適用された後に不良な部分文字列が含まれていないことがすでに保証されています。 位置 i で不正なトリプルエンドが発生した場合は、3 つの文字のうち 1 つを削除する必要があります。 適切なキャラクターを選択することで、新たな重複する問題が発生することを防ぎます。 最適な貪欲な選択は、可能であれば常にパターンの中間文字を削除することです。これは、将来のチェックのために最大限のコンテキストを保持しながら部分文字列を分割するためです。 

これにより、問題は 1 つのパスに変換され、進化する有効な文字列が暗黙的に維持されます。

 ## アルゴリズムのチュートリアル

 削除後に残る文字のリストを維持しながら、文字列を左から右に処理します。 同時に、元の指標を追跡して答えを報告します。 

1. のペアを格納する空のスタックを初期化します。`(character, index)`。 
2. 文字列を 1 文字ずつ繰り返します。 
3. 現在の文字とそのインデックスをスタックにプッシュします。 
4. プッシュするたびに、スタック内の最後の 3 文字を確認します。 
5. 形成された場合`"one"`または`"two"`、このトリプルの中央の文字 (最新の 3 つの要素のうちの 2 番目) を削除します。 
6. 後戻りせずに処理を続行します。 スタックには削除後の文字列が反映されるようになりました。 
7. すべての文字を処理した後、スタック内の残りのインデックスが有効なソリューションを形成します。 

重要な設計上の選択は、検出された各禁止トリプルの中央の文字を削除することです。 これが機能するのは、最初または 3 番目の文字を削除すると、重複するパターンが存続したり、隣接する文字を含む別の禁止された部分文字列が再作成されたりする可能性があるためです。 中間の削除により、以前の構造に必要以上に干渉することなく、特定のオカレンスがきれいに破壊されます。 

### なぜ効果があるのか

 このアルゴリズムは、現在のスタックには完全な禁止部分文字列が含まれないという不変条件を維持します。 違反が出現する場合は常に、その違反は最後の 3 文字内に完全に特定されます。 中間の要素を削除すると、その正確な出現が削除され、以前の部分がすでに有効で変更されていないため、現在の位置より前で終わる新しい禁止された部分文字列を導入することはできません。 これにより、ポジションが処理されて保持または削除されると、再検討する必要がなくなることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    st = []  # (char, index)

    for i, ch in enumerate(s, 1):
        st.append((ch, i))

        if len(st) >= 3:
            a, b, c = st[-3][0], st[-2][0], st[-1][0]
            if (a == 'o' and b == 'n' and c == 'e') or (a == 't' and b == 'w' and c == 'o'):
                # remove middle character of the bad triple
                st.pop(-2)

    print(len(st))
    if st:
        print(*[idx for _, idx in st])

if __name__ == "__main__":
    t = int(input())
    for _ in range(t):
        solve()
```この実装は、貪欲なスタック プロセスを直接反映しています。 スタックには文字と元のインデックスの両方が保存されるため、削除が正しく報告されます。 唯一の重要な操作は、各挿入後の最後の 3 つの要素をチェックすることです。これにより、文字ごとに O(1) の作業が保証されます。 

よくある落とし穴は、即時の整合性を強制せずに、文字列を繰り返しスキャンしようとしたり、別の配列で削除をマークしようとしたりすることです。 これにより、重複するパターンが存在する場合に連鎖的なエラーが発生します。

このトレースは、各違反が発生したときに直ちに処理され、伝播を防ぐ方法を示しています。

 ## 特殊なケース

 重要なエッジケースは、次のようなパターンが重なっています。`"twone"`、単一の文字が両方に属します。`"two"`そして`"one"`構造物。 最初の違反はすぐに処理され、結果の構成がスタックを通じてローカルで再チェックされるため、アルゴリズムはこれを正しく解決します。 

もう 1 つのエッジ ケースは、次のような連続パターンです。`"oneone"`。 スタックは、最初のスタックの中央を削除した後、`"one"`の場合でも、残りの文字は境界を越えて形成された新しいトリプルがないかどうか引き続きチェックされるため、2 番目の出現が見逃されることはありません。 

3 番目のケースは、有効な削除が必要ない文字列です。たとえば、`"testme"`。 トリプルが形成されることはないため、スタックは除去をトリガーすることなく単純に増加し、出力は完全なインデックス セットになります。
