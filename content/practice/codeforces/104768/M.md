 ## 解決策
 ## 問題の理解

 私たちには一連のカードが与えられ、各カードには 2 つの数字が書かれています。 各位置について、最初は 1 つの数字が上を向き、もう 1 つの数字が下を向きます。 初期設定は固定されています。カード i に表示される値は次のとおりです。$a_i$、 その間$b_i$下に隠れています。 

実行できる操作は 1 つだけです。カードの連続したセグメントを選択し、そのセグメント内のすべてのカードを裏返し、その中にあるすべてのカードの表示されている数字と隠れている数字を交換します。 これを行った後も、各位置には、選択したセグメント内にあるかどうかに応じて、元の上側または反転した下側からの 1 つの数値が表示されます。 

最終的に表示される配列が形成されたら、その中央値を計算します。$(n+1)/2$-すべての表示される数値の中で 2 番目に大きい値。 以来$n$は奇妙ですが、これは明確に定義された中位の統計量です。 

目標は、この中央値ができるだけ大きくなるようにセグメントを最適に選択する (またはまったく反転しないことを選択する) ことです。 

制約は次のとおりです$3 \cdot 10^5$これにより、すべての間隔にわたって 2 次またはセグメント ブルートフォース アプローチが即座に除外されます。 平$O(n^2)$考えられるすべてのフリップのスキャンは遅すぎます。$O(n^2)$セグメント。 これにより、明示的に間隔を試行することを回避し、代わりに問題を、おそらく答えに対する二分探索内で線形時間で評価できる単調な実現可能性チェックに減らすという解決策に向かうことになります。 

微妙な点は、操作が要素ごとに独立していないことです。カードごとに、取得するかどうかを自由に選択できません。$a_i$または$b_i$。 選択は単一の連続した反転セグメントから行われる必要があり、これによりグローバル構造制約が導入されます。 インデックスごとに独立して決定する単純な貪欲なやり方は失敗します。 

トラップの例として、より良い方を独立して選択できると仮定します。$a_i$そして$b_i$。 これでは、「単一セグメント」の制限が無視されるため、答えが過大評価されてしまいます。 

別の失敗例は、チェックを最適化せずに、各候補中央値に対して最善のセグメントをブルートフォースで抽出しようとすることです。 単純なシミュレーションでは、間隔ごとにカウントを繰り返し再計算します。$O(n^2)$テストのアイデアごとであり、すぐには実行不可能です。 

## アプローチ

 直接的な総当たりアプローチでは、考えられるすべてのセグメントが列挙されます。$[l, r]$、反転をシミュレートし、結果の配列の中央値を計算します。 中央値を毎回計算するには、並べ替えまたは選択手順が必要です。$O(n)$慎重に行えば間隔ごとに。 あるので$O(n^2)$間隔、これはおおよその結果となります$O(n^3)$総作業量は、はるかに小さい制約であっても制限をはるかに超えています。 

重要な構造的変化は、最終的な配列を明示的に構築するという観点から考えるのをやめ、代わりに、候補の中央値が適切かどうかという観点から考えることです。$x$達成可能です。 閾値を固定すると$x$、問題は次のようになります：少なくとも作ることができますか？$k = (n+1)/2$最終配列内の要素が以上である$x$?

 このように再構成すると、各カードは、目に見える価値が少なくとも$x$。 唯一の複雑な点は、セグメントを反転すると表示される値が変わるため、各位置には 2 つの可能な状態があり、良好な要素の数に異なる影響を与えることです。 

これにより、クリーンな変換が行われます。ベースライン構成 (反転なし) から開始し、すでに満たしている位置の数を計算します。$a_i \ge x$、そしてフリップオンを解釈します$[l, r]$そのセグメントの貢献を変更するなど。 セグメント内の各インデックスは、カウントを改善するか悪化させるか、または、$a_i$に$b_i$閾値を超えます。 

これにより、問題は +1、-1、および 0 の値の配列にわたる最大部分配列の合計を見つけることになり、Kadane のアルゴリズムを使用して線形時間で解決できます。 次に、可能な限り最善の改善を行っても少なくとも次の目標に到達できるかどうかを確認します。$k$良い要素。 

実現可能性は単調なので、$x$では、入力に現れるすべての値に対して答えを二分検索します。

 ## アルゴリズムのチュートリアル

 タスクを固定値かどうかのチェックに集約します。$x$中央値として機能できます。 

## アルゴリズムのチュートリアル

 1. 候補値を確定する$x$そして、「良い」ポジションの概念を、目に見える数字が少なくとも$x$。 私たちの目標は、少なくとも達成できるかどうかを確認することです$k = (n+1)/2$良いポジション。 
2. 何も反転しなかった場合の良好なポジションのベースライン数を計算します。 これは単にインデックスの数です。$a_i \ge x$。 
3. 各インデックスについて、フリッピングがその寄与にどのような影響を与えるかを判断します。 i で反転しないままであれば、貢献度は以下に依存します。$a_i$。 反転した場合、それは以下に依存します$b_i$。 反転されたセグメントに i を含めることによって生じる変化は、次の 3 つのケースのいずれかです。$a_i < x \le b_i$、次の場合は減少します$a_i \ge x > b_i$、またはそれ以外は何もしません。 
4. 各位置を値としてエンコードする$w_i$、 どこ$w_i = +1$利益のために、$w_i = -1$損失のために、そして$w_i = 0$さもないと。 選択された反転されたセグメントは、次の合計に寄与します。$w_i$その間隔にわたって。 
5. 部分配列の最大合計を計算します。$w$。 これは、最適なフリップ セグメントを選択することで達成できる可能な限り最高の改善を表します。 セグメントを選択しないこともできるので、改善は少なくとも 0 になります。 
6. この目的で達成可能な最良の良好な要素の数$x$ベースラインに最大の改善を加えたものです。 この値が少なくとも$k$、 それから$x$実現可能です。 
7. すべての可能な値に対する二分探索$x$実行可能性チェックを述語として使用して、入力に表示されます。 

### なぜ効果があるのか

 固定閾値の場合$x$, すべてのカードは、反転されたセグメント内にあるかどうかを決定すると、「良い」要素のカウントに役立つか悪影響を与えるかに独立して寄与します。 唯一のグローバル制約は、反転されたインデックスが単一の連続ブロックを形成する必要があることです。 この制約は、まさに最大部分配列合計が捉えるものです。有効な反転は連続する区間に対応し、区間は有効な反転に対応します。 したがって、中央値を最適化するとは、しきい値を超える要素数の純ゲインを最大化する間隔を選択することになります。 次に、少なくとも中央値を達成できれば、二分探索は単調性を利用します。$x$、さらに小さな値でもそれを達成できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can(x, a, b, k):
    n = len(a)
    base = 0

    w = [0] * n
    for i in range(n):
        ai, bi = a[i], b[i]

        if ai >= x:
            base += 1

        if ai < x and bi >= x:
            w[i] = 1
        elif ai >= x and bi < x:
            w[i] = -1
        else:
            w[i] = 0

    best = 0
    cur = 0
    for v in w:
        cur = max(0, cur + v)
        best = max(best, cur)

    return base + best >= k

def solve():
    n = int(input())
    a = []
    b = []

    for _ in range(n):
        x, y = map(int, input().split())
        a.append(x)
        b.append(y)

    k = (n + 1) // 2

    vals = list(set(a + b))
    vals.sort()

    lo, hi = 0, len(vals) - 1
    ans = vals[0]

    while lo <= hi:
        mid = (lo + hi) // 2
        x = vals[mid]

        if can(x, a, b, k):
            ans = x
            lo = mid + 1
        else:
            hi = mid - 1

    print(ans)

if __name__ == "__main__":
    solve()
```このコードは、実現可能性のチェックと回答の検索を分離します。 の`can`関数は、すでに良好なカードのベースライン数を計算し、セグメントを反転した場合の効果を表すゲイン/ロス配列を構築します。 Kadane のアルゴリズムは最も単純な形式で表示されます。つまり、ゼロへのリセットを許可しながら実行中の最良の部分配列合計を維持します。これにより、「反転を選択しない」オプションが暗黙的に処理されます。 

二分探索は、カードの両側からのすべての個別の値に対して実行されます。 閾値がこれらの値のいずれかを超えた場合にのみ答えが変化する可能性があるため、これで十分です。 

実装の微妙な詳細は、実現可能性が単調減少するため、答えを最小値で初期化することです。$x$。 中間の値が機能する場合は、上向きに押し上げます。 それ以外の場合は下に進みます。

 ベースライン = 2。 

カダネよりｗ：

 最良の部分配列は [2] で +1 になります。 

したがって、合計良好 = 3 で十分です。 

これは、単一の不良要素を良好な要素に変換するため、中央のセグメントを反転することが有益であることを示しています。 

次に、より厳しいしきい値を検討します$x = 6$。 

| 私 | a_i | b_i | ベースライン | w_i |

 ベースライン = 1。 

ベストゲインは依然として指数 2 から +1 です。 

合計 = 2、これは満たします$k=2$。 

このトレースは、アルゴリズムが、あるポジションで高い値を失いながら別のポジションで利益を得る方法を正しくバランスさせていることを示しています。

 ## 特殊なケース

 重要なエッジケースは、反転があらゆる場所で有害な場合です。 あの状況ではみんな$w_i \le 0$したがって、Kadane は当然ゼロを返し、アルゴリズムは反転されていない構成に戻ります。 たとえば、すべての場合、$a_i$すでに大きくなり、$b_i$が小さい場合、最善の戦略は反転を完全に回避することであり、実行可能性チェックではプラスのゲインが生成されないことがそれを反映します。 

もう 1 つの微妙なケースは、利益と損失が交互に配置される場合です。 Kadane は累積ゲインが正である連続領域のみを選択するため、アルゴリズムはこれを処理します。 有益なインデックスが分散している場合でも、それらの間に有害なポジションを強制的に含めることはありません。 

最後の特殊なケースは、最適な間隔が配列全体である場合です。 これは、ほぼすべてのインデックスがスワップの恩恵を受ける場合に発生します。 サブ配列の合計は自然に全範囲にわたって増加し、Kadane は特別な処理を行わずに全間隔を最適なものとして正確に識別します。
