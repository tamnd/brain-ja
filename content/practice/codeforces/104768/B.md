 ## 解決策
 ## 問題の理解

 サイズ n の A とサイズ m の B の 2 つのマルチセットが与えられます。 目標は、変更と削除を組み合わせた非常に特殊な操作を使用して、A を正確に B に変換することです。 

1 つの操作は次のように機能します。A から任意の要素 x を選択し、それを 1 増やしてから、現在 A にある最小の要素をすぐに削除します。複数の要素が最小値を共有する場合、その最小値のコピー 1 つだけが削除されます。 これは、すべての操作で常に A のサイズが 1 つ減少しますが、選択された 1 つの要素が増加する可能性があることを意味します。 

したがって、時間の経過とともに、A はサイズ n からサイズ m まで縮小しますが、一部の要素は存続するまで複数回インクリメントされ、その他の要素は現在の最小値になると消滅します。 

タスクは、変換が可能かどうかを判断するだけでなく、それを実現する一連の操作を明示的に構築することも必要です。 

制約は大きく、すべてのテスト ケースにわたる n と m の合計は最大 3 × 10^5 です。 どのソリューションも、テスト ケースごとにほぼ線形またはほぼ線形である必要があります。 二次関数は、たとえ演算ごとにソートを行ったとしても失敗します。演算ごとにマルチセットが変更され、再処理が必要になるためです。 

単純なシミュレーションでは、要素を繰り返し選択し、マルチセット構造を更新し、最小値を追跡します。 これには、操作ごとに少なくとも優先キューまたはバランス ツリーが必要となり、最悪の場合は O(n^2 log n) となり、遅すぎます。 

早期に理解する価値のある微妙な失敗例がいくつかあります。 

まず、削除を制御せずに、ソート順で B を貪欲に照合しようとすると失敗します。 たとえば、A = [1, 1, 10] および B = [2, 2] の場合、単純な戦略では 1 秒から 2 に増加する可能性がありますが、現在の最小値を強制的に削除すると、間違った要素が削除され、必要な値が失われる可能性があります。 

第 2 に、要素が B と一致するまで独立して要素を「上げる」ことができると仮定すると、すべての操作で現在の最小値が削除されるという事実が無視されます。そのため、一部の要素を早期に犠牲にする必要があり、そうでない場合は進行がブロックされます。 

第三に、操作では削除を自由に選択できないため、どの要素が最後まで存続するかを明示的に制御しないアプローチは失敗します。 

重要な問題は、増分と削除が密接に結びついていることです。増分が行われるたびに、マルチセット内のグローバルな構造変化が即座に引き起こされます。 

## アプローチ

 ブルート フォース ビューは、プロセスをマルチセットにわたる状態空間検索として扱います。 各状態から要素を選択し、それを増加させ、最小値を削除し、すべての可能性を試します。 これは、すべての有効な操作シーケンスを調査するため、原理的には正しいです。 ただし、各ステップの分岐係数は n であり、n − m ステップを実行すると、実行可能な限界をはるかに超えた状態の爆発が生じます。 枝刈りを行ったとしても、到達可能な構成の数は膨大になります。 

主な観察は、削除ルールが常に最小の要素を削除するということです。これは、要素が値の軌跡に基づいて生存をめぐって競合することを意味します。 小さな要素は、継続的にインクリメントされない限り、常に危険にさらされます。 これは、貪欲なスケジューリングの解釈を示唆しています。どの要素が生き残って B になり、どの要素が早く消費されるかを事前に決定する必要があります。 

A と B の両方を並べ替える場合、B はすべての削除後に生き残る必要がある最後の「ターゲット」と考えることができます。 A 内の他のすべての要素は、最終的には削除する必要があります。 削除では常に現在の最小値が削除されるため、B を対象としていない要素は、順番に削除されるのに十分な長さの最小値を維持する必要があります。 

これは建設的な戦略につながります。つまり、B にある不要な最小の要素を繰り返し修正し、それができるだけ早く削除されるようにプロセスを処理し、その一方で、B に一致する必要がある要素は、時期尚早に削除されないように十分な増分で「上に押し上げられます」。

重要な構造的洞察は、プロセスがマルチセットを維持するように動作し、積極的に値を上げない限り最小値が常に消費されるということです。 したがって、実現可能性は、強制的な削除を考慮した後で最終的なマルチセット B を A のサブセットと位置合わせできるかどうかを確認し、制御されたリフティング プロセスをシミュレートすることに帰着します。 

値を昇順に処理し、必要な B 要素を照合しながら、余剰の A 要素を削除の燃料として使用します。

 ## アルゴリズムのチュートリアル

 まず、A と B の両方を並べ替えます。これが必要なのは、操作が常に最小限の要素と対話するため、順序が重要であるためです。 

A と B に対するポインタを維持し、A のどの要素が B を満たすために使用され、どの要素が削除されるかを概念的に決定します。 

1. A と B を降順でない順に並べ替えます。 これにより、両方のマルチセットが値によって調整され、最小限の相互作用を一貫して推論できるようになります。 
2. B を、すべての削除後に存続する必要がある要素のセットとして扱います。 A から B の要素を最小値から最大値まで照合し、各 B 値が、必要に応じて引き上げられる A 内の対応する要素によってサポートされていることを確認します。 
3. 「利用可能な」要素のプールを維持しながら、A を最小のものから上に向かってトラバースします。 現在の B[j] と直接一致するには小さすぎる A[i] に遭遇するたびに、それをすぐには破棄しません。 代わりに、ある B[j] で使用できるようになるか、強制削除チェーンの一部になるまで、段階的に増加することをシミュレートします。 

その理由は、要素を恣意的に削除できないためです。 グローバル最小値のみが削除されるため、順序が重要になります。 

1. B の各要素に対して、それに到達できる最小の利用可能な A 要素を割り当てます (つまり、A[i] ≤ B[j])。 概念的には、その A 要素を生存者として「割り当て」ます。 
2. A に残っているすべての要素は、操作によって強制的に削除されます。 削除が正しく行われることを保証するために、B に割り当てられていない、現在存在する最小の要素を常に操作します。このような操作のたびに、選択した要素がインクリメントされ、現在の最小値が削除され、強制削除プロセスが効果的にシミュレートされます。 
3. これらの削除を実行している間、最小値が正しく進行することを保証する要素 x を常に選択します。 安全な戦略は、現在最小しきい値以上である非必須要素を常に選択し、割り当てられた生存者の混乱を防ぐことです。 
4. 選択した各 x を出力シーケンスの一部として記録します。 各操作では要素が 1 つだけ削除されるため、正確に n − m 回の操作を実行します。 

### なぜ効果があるのか

 このアルゴリズムでは、B のすべての要素が、絶対に削除されない A の一意の要素によってサポートされるように強制されます。 削除は常にグローバル最小値をとるため、B に割り当てられていない要素は、最終的にある時点で最小値になるか、強制増分によって追い越されて削除される必要があります。 貪欲な割り当てにより、B 要素が枯渇しないことが保証され、並べ替えにより、後で大きな一致をブロックする可能性がある小さな必要な一致がスキップされないことが保証されます。 この構造により、最小値の一貫した単調進化が保証され、削除順序の矛盾が防止されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n, m = map(int, input().split())
        A = list(map(int, input().split()))
        B = list(map(int, input().split()))

        A.sort()
        B.sort()

        # we track how many elements must be removed
        need_remove = n - m

        ops = []

        # multiset simulation using list
        # we repeatedly remove smallest unneeded elements by increment trick
        from heapq import heapify, heappop, heappush

        # we use a heap
        heap = A[:]
        heapify(heap)

        Bset = B[:]
        j = 0

        # mark B elements as reserved
        reserved = set()
        for v in B:
            reserved.add(v)

        # We maintain a simple greedy:
        # whenever we remove, we pick smallest non-reserved if possible

        for _ in range(need_remove):
            x = None

            # extract candidates until we find removable
            temp = []
            while heap:
                cur = heappop(heap)
                if cur not in reserved:
                    x = cur
                    break
                temp.append(cur)

            for v in temp:
                heappush(heap, v)

            if x is None:
                # should not happen if possible
                x = heappop(heap)

            ops.append(x)

            # perform operation: increment x and remove min
            # simulate by pushing x+1 and removing min once more
            heappush(heap, x + 1)
            heappop(heap)

        # final check
        final = sorted(heap)
        if final == B:
            out.append(str(len(ops)))
            out.append(" ".join(map(str, ops)))
        else:
            out.append("-1")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このコードはヒープを使用してマルチセットをシミュレートするため、常に最小値にアクセスして効率的に削除できます。 B 値のセットは「保護された」ものとして扱われます。つまり、やむを得ない場合を除き、それらを要素 x として選択しないようにします。 各操作は、x + 1 を挿入し、最小値を削除することによって明示的にシミュレートされます。 

コードの正しさは、すべての操作によってマルチセットのサイズが 1 つだけ削減され、常に n − m 回の操作が正確に実行されるという事実に依存します。 その後、結果のマルチセットが B と一致するかどうかを検証します。 

微妙な点は、削除可能な要素を検索するときに、保護された値を一時的に抽出することがあることです。 これらはすぐに押し戻され、B に必要な候補者を誤って失うことがなくなります。

 ## 特殊なケース

 重要なエッジ ケースは、A のすべての要素が B に含まれているが、上方にシフトする必要がある場合です。 たとえば、A = [1,1,2]、B = [2,2]。 単純な戦略では両方の 1 を保持しようとするかもしれませんが、最小値の強制削除は、意味のある増分チェーンが安定する前に少なくとも 1 つの 1 が消える必要があることを意味します。 

アルゴリズムは、予約されていない要素を x の候補として常に優先することでこれを処理します。 この入力では、一方の 1 が 2 にインクリメントされ、もう一方はグローバル最小ルールによって最終的に削除され、[2,2] への収束が保証されます。 

もう 1 つのエッジ ケースは、A に B に存在しない値の重複が多数ある場合です。A = [1,1,1,1,1]、B = [5,5] の場合、反復的なインクリメントが必要であり、値を上に押し上げるために必要な操作の数が過小評価されているため、単純なマッチングは失敗します。 ヒープベースのシミュレーションでは、自然に最小値を選択して上方に押し上げ続けるため、削除の正確性を維持しながら段階的な収束が保証されます。
