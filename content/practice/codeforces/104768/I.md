 ## 解決策
 ## 問題の理解

 いくつかのテストケースが与えられています。 各テスト ケースは生徒の行を記述しており、各生徒は 1 から m までの単一の整数値に関連付けられています。 この値は、学生がどのアルゴリズムを (難易度ランク別に) 知っているかを表します。 

生徒の連続したセグメントを選択する必要があります。つまり、l から r までの範囲のインデックスを選択し、それらの生徒のみを考慮します。 そのセグメントについては、2 つの量が計算されます。 1 つ目は、セグメント内に出現する個別のアルゴリズム インデックスの数です。 2 番目は、セグメントに現れない 1 から始まる最小のアルゴリズム インデックスです。 1 から m までのすべてのアルゴリズムが少なくとも 1 回出現する場合、この値は m + 1 として定義されます。 

セグメントのスコアは、存在する個別のアルゴリズムの数からこの最小の欠落インデックスを引いたものとして定義されます。 目標は、可能なすべての連続セグメントにわたってこのスコアを最大化することです。 

入力サイズは大きく、すべてのテスト ケースにわたる生徒の総数は最大 500,000、m も最大 500,000 です。これにより、すべての O(n^2) セグメントをチェックするソリューションは直ちに除外されます。 O(n sqrt n) のアプローチであっても、慎重に最適化しない限り危険であるため、目的のソリューションはテスト ケースごとに線形または線形に近いものでなければなりません。 

微妙な問題は、スコアの両方のコンポーネントが同じセグメントに依存しているにもかかわらず、拡張下では異なる動作をするという事実から生じます。 個別の数はセグメントを拡大するにつれて増加する傾向がありますが、mex 値はしばらく安定していても、重要な値を含めたり除外したりすると突然低下することがあります。 この非単調な動作により、単純なスライディング ウィンドウ戦略の信頼性が低くなります。 

いくつかの特殊なケースで構造を説明します。 

すべての生徒が同じ値 (たとえば、a = [5, 5, 5]) を持っている場合、どのセグメントも個別のカウント 1 を持ち、mex は 1 であるため、答えは 0 になります。単純なアプローチでは、セグメントが長いほどスコアが向上すると誤って考える可能性がありますが、実際はそうではありません。 

値がすでに一部のセグメントのアルゴリズム 1 から m までをすべてカバーしている場合、mex は m + 1 になり、スコアは個別の - (m + 1) になり、負になる可能性があります。 これは、最適な答えが必ずしも「広い範囲」のセグメントから得られるわけではないことを意味します。 場合によっては、小さな欠落インデックスを避けることの方が重要です。 

もう 1 つの注意が必要なケースは、小さな値が早い段階で欠落している場合です。 たとえば、セグメント内で 1 が欠落している場合、mex は 1 となり、より高い値に関係なくスコアは個別の - 1 になるため、より大きな個別の要素を導入してもペナルティはまったく変わりません。 

これらの相互作用は、含める個別の要素の数を制御しながら、mex を明示的に追跡する必要があることを示唆しています。 

## アプローチ

 ブルートフォースソリューションでは、すべてのサブ配列を列挙し、個別のカウントと mex の両方を最初から計算します。 n が 5e5 までの場合、単純に再計算すると O(n^3)、周波数構造では O(n^2) が必要になります。 O(n^2) でも大きすぎます。 

周波数配列を維持し、2 つのポインターを使用して O(n) のスライディング ウィンドウを維持することで改善できますが、主な障害は、目的関数がどちらの方向でも単調ではないことです。 ウィンドウを拡大すると、個別のカウントが増加する可能性がありますが、mex が予期せず変化する可能性もあり、ウィンドウを縮小すると、削除される値に応じてスコアが改善または悪化する可能性があります。 これにより、標準の 2 ポインター引数が壊れます。 

重要な構造観察は、mex に注目することです。 どのセグメントでも、その mex が k の場合、1 から k − 1 までのすべての値がセグメント内に出現する必要があり、値 k は存在してはならない。 これは、特定の mex を持つすべてのセグメントを特徴付けます。 

mex が k に固定されると、スコアは次のようになります。 

個別カウント − k

 ただし、セグメントには 1 ～ k − 1 のすべての値が少なくとも 1 回含まれなければならず、k が含まれていてはなりません。 

これは、問題を制約付きの最大化に再構成します。つまり、考えられる k ごとに、それらの制約を満たす最適なセグメントが必要になります。

これを効率的に評価するために、スライディング ウィンドウと動的周波数構造を維持し、同時に周波数カウントに対してセグメント ツリーを使用して現在の mex を維持します。 mex は周波数がゼロの最小のインデックスであるため、周波数が変化すると対数時間で更新できます。 

また、ウィンドウ内の個別の要素の数も維持します。 右ポインターを移動すると、周波数が更新され、mex と個別のカウントの両方が調整されます。 次に、左ポインタを調整して、mex 追跡の正確さを常に維持しながら、スコアを悪化させる要素を保持しないようにします。 

重要な考え方は、固定された右エンドポイントの場合、現在の mex によって課された構造に違反せずにさらに移動できないエンドポイントの中に最適な左エンドポイントが常に存在するということです。 これにより、左側のすべての位置を試すのではなく、常に現在の状態の最良の候補を表す小さなアクティブ ウィンドウを維持することができます。

 ## アルゴリズムのチュートリアル

 値 1 ～ m にわたる頻度配列、頻度 0 (mex) の最小インデックスを追跡するセグメント ツリー、および現在ウィンドウ内にある個別の値の数を示すカウンターを維持します。 

また、継続的に調整する現在のウィンドウ [l, r] も維持します。 

1. l = 1、r = 0、空のウィンドウ、すべての周波数 0、mex = 1、および個別 = 0 から開始します。これにより、ベースライン状態が得られます。 
2. 配列内で r を段階的に展開します。 新しい値 a[r] ごとに、その頻度を増やします。 この値が以前に存在しなかった場合は、個別のカウントを増加させます。 頻度がゼロ以外になった場合、この値が現在存在していることを反映するようにセグメント ツリーを更新します。 
3. 挿入するたびに、セグメント ツリーを使用して mex を再計算します。 これにより、現在ウィンドウに存在しない最小値が得られます。 
4. 現在のスコアを個別の - mex として計算し、グローバルな答えを更新します。 
5. 回答を更新した後、l を前に進めてウィンドウの改善を試みます。 l を移動するかどうかの決定は、a[l] を削除することでウィンドウを有効に保ちながら、スコアを向上させる可能性があるかどうかに基づいて決定されます。 周波数への影響を一時的にチェックすることで削除をシミュレートします。a[l] を削除しても、現在の構造を維持するために必要な小さな値の必要なカバレッジが破壊されない場合は、l を縮小します。 
6. l を縮小する場合、a[l] の頻度をデクリメントし、その値がゼロになった場合は個別のカウントを更新し、それに応じてセグメント ツリーを更新します。 mex は縮小するたびに再計算されます。 
7. これ以上縮小しても改善されなくなるまで、または有効性が維持されなくなるまでこのプロセスを繰り返し、r の拡張を続けます。 

重要な点は、更新のたびに mex が常に再計算されるため、「1 から mex-1 までのすべての値が存在する」という構造がセグメント ツリー状態の構築によって継続的に強制されることです。 これにより、ウィンドウが常に現在の mex と内部的に一貫していることが保証されます。 

### なぜ効果があるのか

 セグメント ツリーはいつでも、現在のウィンドウの mex が正しく識別されることを保証します。 ウィンドウ メンテナンスにより、mex を有益な方法で変更することなくスコアを低下させる冗長な左境界位置が保持されないようになります。 

すべての有効なセグメントは、このプロセス中に到達可能なウィンドウ状態に対応します。これは、セグメントが正確に形成されるまで r をその終点まで拡張し、次に l を縮小することによってセグメントを構築できるためです。 到達可能なすべての状態でスコアを評価するため、最適なセグメントが常に見つかります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SegTree:
    def __init__(self, n):
        self.n = n
        self.size = 1
        while self.size < n:
            self.size <<= 1
        self.seg = [0] * (2 * self.size)

    def update(self, i, val):
        i += self.size
        self.seg[i] = val
        i >>= 1
        while i:
            self.seg[i] = self.seg[i << 1] & self.seg[i << 1 | 1]
            i >>= 1

    def find_mex(self):
        if self.seg[1] == 1:
            return self.n + 1
        i = 1
        while i < self.size:
            if self.seg[i << 1] == 0:
                i = i << 1
            else:
                i = i << 1 | 1
        return i - self.size + 1

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))

        freq = [0] * (m + 2)
        st = SegTree(m + 2)

        # initially all values missing -> segtree all zeros
        for i in range(1, m + 2):
            st.update(i, 0)

        l = 0
        distinct = 0
        ans = -10**18

        for r in range(n):
            x = a[r]
            if freq[x] == 0:
                distinct += 1
            freq[x] += 1
            st.update(x, 1)

            mex = st.find_mex()
            ans = max(ans, distinct - mex)

            while l <= r:
                y = a[l]
                if freq[y] == 1:
                    # try removing
                    freq[y] -= 1
                    st.update(y, 0)
                    new_mex = st.find_mex()
                    new_distinct = distinct - 1

                    if new_distinct - new_mex >= distinct - mex:
                        distinct = new_distinct
                        mex = new_mex
                        l += 1
                    else:
                        freq[y] += 1
                        st.update(y, 1)
                        break
                else:
                    freq[y] -= 1
                    l += 1

        print(ans)

if __name__ == "__main__":
    solve()
```このコードは、高速な mex クエリを可能にする、値 1 ～ m にわたる頻度配列とセグメント ツリーを維持します。 値が現在のウィンドウに出入りするたびに、セグメント ツリーは対数時間で更新されます。 

要素を削除しても現在のスコアが減少しない場合にのみ、左ポインタが移動します。 これにより、mex の動作を改善せずに個別のカウントを増大させる不要な要素をウィンドウ内に保持しないことが保証されます。 

実装でよくある落とし穴は、mex は存在ではなく不在を反映する必要があることを忘れることです。 セグメント ツリーには存在フラグが格納されるため、存在する場合は値が 1、存在しない場合は 0 とマークされます。 もう 1 つの微妙な問題は、変更のたびに mex を再計算することです。 これをスキップすると、候補州間の比較が矛盾することになります。

 ## 特殊なケース

 重要なエッジ ケースは、値 1 が配列内にまったく出現しない場合です。 その場合、どのセグメントでも mex は常に 1 であるため、問題は個別の要素を最大化することに帰着します。 セグメント ツリーは 1 を存在としてマークすることがないため、アルゴリズムはこれを自然に処理します。そのため、すべてのウィンドウ状態を通じて mex は 1 のままになります。 

もう 1 つのエッジ ケースは、配列に 1 から m までのすべての値が少なくとも 1 回含まれる場合です。 この状況では、すべての値をカバーするウィンドウに対してのみ mex は m + 1 になります。 スコアが負になる可能性がありますが、アルゴリズムは引き続き mex が小さい中間ウィンドウを評価し、グローバル最大値が確実に取得されるようにします。 

最後のエッジ ケースは、多くの値が繰り返されるが、少数の個別の値しか存在しない、大量に重複した配列です。 ここで、ポインタの移動により周波数は変更されますが、明確なカウントは頻繁に変更されるわけではありません。mex は想定された構造ではなく実際の存在から再計算されるため、アルゴリズムは改善の過大評価を正しく回避します。
