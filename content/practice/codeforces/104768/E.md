 ## 解決策
 ## 問題の理解

 整数のシーケンスが 1 つずつ明らかにされます。 新しい要素が追加されるたびに、プレフィックス全体が単純化されたルールの下で有効な麻雀役として解釈できるかどうかを判断する必要があります。 

有効なハンドとは、1 つの特別なペアを繰り返し削除し、他のすべてを 3 つのグループに分割することで、すべての数字を削除できることを意味します。 3 つの各グループは、3 つの同一の値または 3 つの連続する整数のいずれかである必要があります。 このペアは、2 つの等しい数値が 1 回だけ出現するものです。 

したがって、すべてのプレフィックスについて、マルチセットの構造分解問題をチェックしています。ペアを形成する値の選択肢が 1 つだけ存在するかどうか、また、それを削除した後、残りのマルチセットが等しい要素または連続するトリプルのトリプルで完全にタイル化できるかどうかです。 

この制約により、すべてのテスト ケースにわたって合計最大 100,000 個の要素が許可されます。 これにより、指数関数的な検索や完全なシミュレーションの繰り返しを使用して、プレフィックスごとに独立して完全な分解を再計算しようとするソリューションは即座に除外されます。 テスト ケースごとに O(n^2) の解でも、およそ 10^10 の演算を意味するため、最悪の場合には大きすぎます。 

ここで最も危険なエッジケースは、値の間隔が広い場合です。 たとえば、次のようなプレフィックス`[1, 100, 200, 300, ...]`はシーケンスを形成する可能性がないため、重要なのはトリプルだけです。 もう 1 つのエッジ ケースは、値が長い連続ランを形成する場合です。この場合、シーケンスの形成があいまいになり、貪欲なペアリングの決定により将来の実現可能性が簡単に損なわれる可能性があります。 ペアの配置を考慮せずに貪欲にトリプルを削除する単純なアプローチは、次のような入力で失敗する可能性があります。`[1,1,2,3,4,5,6]`ここで、正しい答えは、正しいペアを早めに予約するかどうかに依存します。 

## アプローチ

 プレフィックスを検証するブルート フォースの方法は簡単です。ペアの可能な選択肢をすべて試して、それを削除し、残りのマルチセットを有効なトリプルに貪欲に分割しようとします。 分割ステップ自体は、常に最初に同一のトリプルを使用し、次に連続したトリプルの形成を試みることによって実行できます。 これが機能するのは、ペアが固定されるとルールがローカルで決定的になるためです。 

ただし、このアプローチは、すべての候補ペア値およびすべてのプレフィックスに対して完全な分解の試行を繰り返すため、コストが高くなります。 最悪の場合、すべての値が異なる、またはほぼ異なる場合でも、プレフィックスごとに周波数構造全体を複数回スキャンすることになり、全体的に 3 次的な動作が発生します。 

重要な観察は、有効な手の構造は一度分類されると非常に厳格になるということです。 ペアを修正した後、残りのマルチセットの自由度はほとんどありません。トリプルを遅延させると、シーケンスを形成する将来の可能性が常に減少するため、各値で貪欲にトリプルを消費する必要があります。 これにより、固定ペアの実現可能性を確認するには単一の決定論的削減プロセスで十分になります。 

したがって、すべてのパーティションを探索する代わりに、妥当なペアの候補のみを試し、ソートされた順序で値を処理する貪欲なリダクションを適用し、トリプルを消費して、可能な場合はシーケンスの拡張を試みます。 これにより、問題は組み合わせ検索から順序付けされた周波数にわたる制御されたシミュレーションに軽減されます。

 ## アルゴリズムのチュートリアル

 私たちはこれまでに確認されたすべての数値の頻度マップを維持しています。 各接頭辞を処理した後、それが有効な麻雀分解を形成できるかどうかを確認します。 

1. 現在のプレフィックスの長さが 2 モジュロ 3 に一致しない場合、有効なハンドを形成できないことがすぐにわかります。 これは、1 つのペアが 2 つの要素に寄与し、他のすべては 3 つのグループである必要があるという事実から来ています。 
2. 現在少なくとも 2 の頻度で出現するすべての値を収集します。そのような各値はペアの候補となります。 
3. 各候補ペア値について、その頻度を一時的に 2 減らして、残りのマルチセットの検証を試みます。 
4. ペアのない固定マルチセットを検証するには、値を昇順に処理します。 各値 x について、まず (x, x, x) の形式のトリプルをできるだけ多く削除します。 その後、利用可能な数を確認しながら、貪欲に連続するグループ (x、x+1、x+2) を形成しようとします。 
5. トリプル制約とシーケンス制約を尊重しながら、いずれかの時点で値の出現をすべて削除できない場合、この候補ペアは無効となり、頻度が復元されます。 
6. いずれかの候補ペアが完全に成功した削減につながる場合、プレフィックスは有効です。 

中心的なアイデアは、ペアを修正すると、残りの構造が強制的に強制され、貪欲な左から右への消費で有効性を検出するのに十分であるということです。 

### なぜ効果があるのか

 分解問題には強い単調性の性質があります。 値 x を処理すると、トリプル内またはシーケンスの一部として使用されなかった x の残りの出現は繰り越される必要がありますが、シーケンスには正確な隣接性が必要であるため、繰り越しは将来の柔軟性を低下させるだけです。 したがって、常にソートされた順序でできるだけ早くトリプルとシーケンスを消費するように、最適な分解を再配置することができます。 これにより、検証ステップ内での後戻りがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import defaultdict

def can_finish(freq):
    # work on a copy
    keys = sorted(freq.keys())
    f = dict(freq)

    for x in keys:
        c = f.get(x, 0)
        if c < 0:
            return False
        if c == 0:
            continue

        # use triples first
        t = c % 3
        use3 = c // 3
        f[x] -= use3 * 3

        # remaining must be handled by sequences greedily
        while f.get(x, 0) > 0:
            if f.get(x+1, 0) > 0 and f.get(x+2, 0) > 0:
                f[x] -= 1
                f[x+1] -= 1
                f[x+2] -= 1
            else:
                return False

    return True

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        freq = defaultdict(int)
        res = []

        for i, x in enumerate(a, 1):
            freq[x] += 1

            if i % 3 != 2:
                res.append('0')
                continue

            ok = False
            for v in list(freq.keys()):
                if freq[v] >= 2:
                    freq[v] -= 2
                    if can_finish(freq):
                        ok = True
                    freq[v] += 2
                    if ok:
                        break

            res.append('1' if ok else '0')

        print(''.join(res))

if __name__ == "__main__":
    solve()
```このソリューションは、頻度テーブルを増分的に維持します。 各プレフィックスについて、考えられるペアの候補にのみ分岐し、一時的に 2 つの出現を減算し、決定論的チェッカーを呼び出します。 

いかなる変更も他のペアのトライアルに影響を与えてはいけないため、チェッカーはコピーに対して機能します。 その内部では、並べ替えられた順序で値をスイープするため、シーケンスの形成では常に最も早い位置が使用され、将来のブロックが防止されます。 

実装の微妙な点は、各試行後に周波数を復元することです。 復元を忘れたり、トライアル間で変更可能な状態を誤って共有したりすると、後のチェックが破損する可能性があります。 

## 実用的な例

 プレフィックスシーケンスを考慮する`[1, 1, 1, 2, 3, 4]`。 

長さ 2 では、次のようになります。`[1,1]`これはすぐに有効なペアとなり、トリプルは必要ありません。したがって、答えは次のようになります。`1`。 

長さ 3 では、`[1,1,1]`はシングルポンですが、まだ有効です。 

長さ 4 では、`[1,1,1,2]`ペアを選択した後なので、1 ペアとトリプルを形成することはできません`1,1`、私たちに残されたのは`[1,2]`トリプルまたはシーケンスを形成することはできません。 

| ステップ | プレフィックス | 長さ mod 3 チェック | 試したペア | 有効？ |
 | --- | --- | --- | --- | --- |
 | 1 | [1,1] | 有効 | 1 | はい |
 | 2 | [1,1,1] | 無効 (3≠2 mod 3) | - | いいえ |
 | 3 | [1,1,1,2] | 無効 | - | いいえ |

 これは、構造チェックの前にモジュロ条件が必要であることを示しています。 

ここで考えてみましょう`[1,2,3,1,2,3,4,4]`。 

最後のプレフィックスで、`4,4`ペアが去るとき`[1,2,3,1,2,3]`、2つの食事に分割できます`(1,2,3)`そして`(1,2,3)`。 

貪欲チェッカーは、残余なく左から右にシーケンスを正常に消費し、有効性を確認します。

 ## 特殊なケース

 重要なエッジ ケースは、多くの値の頻度が少なくとも 2 である場合です。 例えば`[1,1,2,2,3,3,4,4]`。 アルゴリズムはそれぞれを可能なペアとして試行しますが、分解が成功するのは 1 つだけです。 各試行は独立しているため、各試行後の周波数の復元によって正確さが保証されます。 

もう 1 つのエッジ ケースは、次のようなシーケンスを厳密に増加させることです。`[1,2,3,4,5,6]`。 ここでは、ペアと完全なシーケンス構造の両方を形成するのに十分な要素が存在するまで、有効なプレフィックスは表示されません。 モジュロ チェックは多くのプレフィックスを早期に削除し、不必要なシミュレーションを防ぎます。 

3 番目のエッジケースは、次のような頻繁な繰り返しです。`[5,5,5,5,5,5]`。 この場合、貪欲チェッカーはトリプルを即座に削減し、正しいプレフィックス長に達するとペアの選択は無関係になります。
