 ## 解決策
 ## 問題の理解

 整数の配列が与えられ、選択された要素に対する 2 つの演算 (選択されたすべての値のビットごとの XOR と整数の割り算) を結び付ける制約を満たす、この配列の空でないサブシーケンスがいくつあるかを数えるように求められます。 

選択したサブシーケンスについて、そのすべての要素の XOR を計算します。 次に、そのサブシーケンス内のすべての要素がこの XOR 値を除算する必要があります。 つまり、サブシーケンスに値が含まれている場合、$v_1, v_2, \dots, v_k$そしてそれらの XOR は$X$、その後、それぞれ$v_i$満たさなければなりません$X \bmod v_i = 0$。 

入力サイズが十分に大きいため、すべてのサブシーケンスを試行するソリューションは直ちに不可能になります。 と$n$まで$2 \cdot 10^5$テスト ケース全体で、サイズ 40 の単一配列のすべてのサブセットを検査するだけでもすでに制限を超えているため、値ごとに独立して、またはほぼ独立して寄与をカウントするように問題を軽減する構造が必要です。 

微妙な困難は、XOR と割り算の相互作用から生じます。 XOR は単調ではなく、算術構造を保持しないため、XOR を sum や gcd に置き換えるような単純な推論は完全に失敗します。 

有用な健全性チェックは、小さな病理学的ケースを調べることです。 配列に混合値が含まれている場合は、次のようにします。$[2, 3]$、XOR は$1$。 どちらでもない$2$または$3$分割する$1$したがって、このサブシーケンスは無効です。 試してみると$[1, 2]$、XOR は$3$、そしてその間$1$すべてを分割し、$2$分けない$3$, したがって、これも無効です。 これは、異なる値の混合が高度に制限されていることを示唆しています。 

もう 1 つのエッジ状況は、選択された値がすべて同一である場合です。 値だけを選択すると$v$, XOR は非常に単純に動作します。偶数の要素の場合、次のようになります。$0$、奇数の場合は次のようになります$v$。 両方$0$そして$v$で割り切れます$v$したがって、同一の値の空でないサブセットはすべて有効です。 これは構造的に安定した唯一のケースであることが判明しました。 

## アプローチ

 ブルートフォース手法では、配列のすべてのサブシーケンスを列挙し、その XOR を計算して、すべての要素の割り切り可能性を検証します。 これは正しいですが、それには次のことが必要です$O(2^n \cdot n)$各サブセットは XOR 計算とスキャンを必要とするため、最悪の場合、テスト ケースごとに時間がかかります。 と$n$まで$2 \cdot 10^5$、これは実現不可能です。 

重要な観察は、割り算の制約により、有効なサブセットに極端な均一性が強制されるということです。 サブセットに 2 つの異なる値が含まれる場合$a$そして$b$、両方とも分割する必要があります$a \oplus b \oplus \cdots$。 これにより、すべての値が同一でない限り、ほとんど適用されない強力な算術制限が作成されます。 実際、異なる値を混合しようとすると、少なくとも 1 つの要素の割り切れる可能性がすぐに失われます。これは、XOR では独立した整数間の割り切れる関係が保持されないためです。 

単一の個別の値で構成されるサブセットのみが存続できることを受け入れると、問題は値によって完全に分解されます。 個別の値ごとに$v$、その出現の空でないサブセットを選択できる方法が何通りあるかを数えるだけです。 表示されたら$c_v$時々、あります$2^{c_v} - 1$のみで構成される有効なサブシーケンス$v$。

 ## アルゴリズムのチュートリアル

 1. 配列内に各値が何回出現するかを数えます。 これが必要なのは、有効なサブシーケンスの構造が位置ではなく多重度のみに依存するためです。 
2. 個別の値ごとに$v$、の出現のみから形成されたすべての部分列を考慮します。$v$。 あれば$c_v$このような場合、空でない選択肢の数は$2^{c_v} - 1$。 これは、値を同一に保ちながら少なくとも 1 つのインデックスを選択するためのあらゆる可能な方法をカウントします。 
3. すべての個別の値に対するこれらの寄与を合計します。 制約の下では、異なる値を有効なサブシーケンスに組み合わせることができないため、これらのグループは互いに素で独立しています。 
4. 合計モジュロを返します$998244353$。 

ステップ 3 が有効である理由は、2 つの異なる値を含むサブシーケンスが条件を満たすことができないため、重複または欠落している交互作用項がないためです。 

### なぜ効果があるのか

 有効なサブシーケンスはすべて、すべての要素がサブシーケンス全体の XOR を除算することを満たさなければなりません。 2 つの異なる値の場合$a$そして$b$両方が一緒に出現する場合、両方とも同じ XOR 値を除算する必要があります。これは両方に依存します。$a$そして$b$非線形的な方法で。 XOR によって互換性のない割り算制約が導入されない唯一の安定した構成は、すべての要素が等しい場合です。 その場合、XOR は次のいずれかに崩壊します。$v$または$0$、両方とも割り切れます$v$、有効性を保証します。 したがって、ソリューション空間は値によって正確に分割されます。 

## Python ソリューション```python
import sys
from collections import Counter

input = sys.stdin.readline
MOD = 998244353

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        arr = list(map(int, input().split()))
        
        freq = Counter(arr)
        ans = 0
        
        for v, c in freq.items():
            ans = (ans + pow(2, c, MOD) - 1) % MOD
        
        print(ans)

if __name__ == "__main__":
    solve()
```実装は削減の直後に行われます。 の`Counter`配列を周波数バケットに圧縮します。これにより、位置について推論する必要がなくなります。 べき乗モジュラーの計算$2^{c_v}$対数時間で効率的に。 

微妙な点は、係数の下で減算を処理することです。 以来$2^{c_v} - 1$減算後に負になる可能性があるため、最後の加算後の Python のモジュロ動作に依存して、結果が範囲内に収まるようにします。

## テストケース```python
import sys, io

MOD = 998244353

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    
    from collections import Counter
    
    def solve():
        t = int(input())
        out = []
        for _ in range(t):
            n = int(input())
            arr = list(map(int, input().split()))
            freq = Counter(arr)
            ans = 0
            for v, c in freq.items():
                ans = (ans + pow(2, c, MOD) - 1) % MOD
            out.append(str(ans))
        print("\n".join(out))
    
    solve()
    return sys.stdout.getvalue().strip()

# minimum size
assert run("1\n1\n7\n") == "1"

# all equal
assert run("1\n3\n4 4 4\n") == str((2**3 - 1) % MOD)

# mixed values
assert run("1\n3\n1 2 3\n") == str((1 + 1 + 1) % MOD)

# duplicates + single
assert run("1\n4\n2 2 2 5\n") == str((2**3 - 1 + 1) % MOD)

 ## 特殊なケース

 すべての要素が同一の場合、XOR はパリティに応じて値自体とゼロの間で交互に実行されます。 どちらの場合も、割り算は自動的に成立するため、空でないすべてのサブセットが有効になります。 このアルゴリズムは、単一の周波数バケット内のすべてのサブセットをカウントすることでこれを処理します。 

すべての要素が個別である場合、アルゴリズムは要素ごとに 1 つの寄与を生成し、シングルトンにのみ対応します。 より大きなサブセットでは、XOR の可分性の下で異なる値間の互換性が必要になりますが、これは失敗するため、グループ化ロジックは過大なカウントを正しく回避します。 

1 つの値が他の値と一緒に何度も出現する場合、繰り返されるブロックのみが指数関数的に寄与します。 たとえば、`[3, 3, 3, 1]`、値`3`貢献する$2^3 - 1$、 その間`1`貢献するだけ$1$。 混合サブセットはグループ化構造には決して現れないため、暗黙的に除外されます。
