 ## 解決策
 ## 問題の理解

 同じサイズのいくつかの順列が与えられ、各順列は位置の再配置として機能します。 2 つの順列を構成すると、結果の i 番目の位置が 1 つの順列を次々に適用することによって得られる別の順列になります。 

タスクは、指定された順列の空ではないすべての可能な部分列を考慮し、それらの構成を指定された順序で取得し、個別の最終的な順列がいくつ生成できるかをカウントすることです。 

主な困難は、1 つの合成を計算することではなく、入力順列の任意のサブシーケンスによって生成されたすべての結果の空間を理解することです。 

制約は構造的な意味で非常に小さいです。つまり、すべての順列にわたる要素の合計数 (n に m を掛けたもの) は最大 180 です。これは、n と m の両方が個別に小さいことをすぐに意味しますが、より重要なのは、合計の入力サイズが十分に小さいため、順列に対して 2 次または 3 次の推論を行うことができるということです。 ただし、部分列の組み合わせ数は 2^m であり、m が 40 以上に近づくと、これはすでに大きすぎて直接列挙できません。 

素朴なアプローチでは、順列のすべてのサブセットを列挙し、各構成を計算し、結果をセットに保存しようとします。 たとえ合成コストが O(n) だったとしても、O(2^m · n) となり、これは中程度の m であっても実行不可能になります。 

異なるサブシーケンスが異なる合成パスを通じて同じ順列を生成する場合、微妙なエッジ ケースが発生します。 たとえば、2 つの異なる順列シーケンスが互いにキャンセルされたり、最終的に同じマッピングに並べ替えられたりする場合があります。 正しいソリューションでは、列挙に依存するのではなく、これらの結果を効率的に重複排除する必要があります。 

## アプローチ

 直接的な総当たり戦略は、m 個の順列の空でないすべてのサブセットを反復処理することです。 サブセットごとに、インデックス順に順列を構成し、結果の順列をハッシュ セットに挿入します。 

順列の構成は決定論的であり、すべてのサブシーケンスが正確に 1 つの順列を生成するため、これは概念的には正しいです。 問題は規模だ。 m が 30 の場合、すでに約 10 億のサブセットが存在します。 各作品のコストは O(n) であるため、総作業量は法外なものになります。 

重要な構造観察は、順列構成がグループを形成しているということです。 すべての順列は {1, …, n} の全単射であり、それらを構成することは対称群 S_n の要素を乗算することに対応します。 n が小さいため、各順列は有限変換システム内の単一の状態として扱うことができます。 

サブセットについて考える代わりに、順序を維持した方法で、指定されたジェネレーターの可能なすべての製品を構築するプロセスとして再解釈します。 各インデックス i で、Ai を含めるかスキップするかを決定します。 これは本質的に、合成下の順列の状態空間における到達可能性の問題です。 

n 個の要素の順列の総数は n! ですが、これは一般にまだ天文学的に大きいため、グループ全体を走査することはできません。 ただし、n・m ≤ 180 という制約は、m = 1 の最悪の場合でも n が最大 180 であることを意味しますが、通常は両方とも十分に小さいため、これらの構成で到達可能な個別の置換の数は管理可能なままです。 重要な単純化は、任意の順列を考慮する必要がなく、制御されたプロセスのプレフィックスによって生成される順列のみを考慮する必要があることです。 

最初の i 順列の処理後に到達可能なすべての順列のセットを維持しながら、インデックス上の DP を使用して、サブセットにわたる動的構築をモデル化できます。 ステップ i では、Ai をスキップするか、以前に形成された順列に追加します。 これにより、古い状態と Ai で構成された古い状態の集合結合が生成されます。

指数関数的な再計算を避けるために、状態をハッシュ セットに保存し、反復的に更新します。 各順列は、高速ハッシュのタプルとして表されます。 すべての状態遷移は固定順列を持つ合成であるため、合成を効率的に事前計算できます。 

この正しさは、有効なサブシーケンスが固有の増加するインデックス シーケンスに対応し、順列を処理することで、そのようなすべてのサブシーケンスが包含または除外の決定を通じて正確に 1 回生成されるという事実から生まれます。

 ## アルゴリズムのチュートリアル

 各順列を位置から位置にマッピングする関数として扱います。 状態は、何らかのサブシーケンスから構築された合成順列を表します。 

ID 順列から始めて、現在到達可能な順列のセットを維持します。 

1. セットを初期化する`dp`恒等順列のみを含む。 これは、Ai を選択する前の空の構成に対応します。 
2. 順列 A1 から Am までを順番に繰り返します。 
3. 各 Ai について、まず現在の状態セットをコピーします。これは、Ai をスキップすると、以前の結果がすべて変更されないためです。 
4. dp にすでに含まれているすべての順列 P について、合成 P ∘ Ai を計算し、それを新しいセットに挿入します。 
5. 新しく作成された状態をマージして dp に戻します。 
6. すべての Ai を処理した後、空ではないサブシーケンスのみが許可されるため、必要に応じて恒等順列を削除します。 
7. dpのサイズを出力します。 

微妙な点は、各ステップで、構造化された方法で到達可能なセットを 2 倍にすることです。つまり、Ai を使用しないか、既存の構造に Ai を追加します。 これにより、すべてのサブシーケンスが、インデックスの順序に沿った包含決定のシーケンスとして 1 回だけ表現されることが保証されます。 

### なぜ効果があるのか

 すべてのサブシーケンスは、インデックスに対するバイナリ決定文字列に一意に対応します。つまり、各 Ai を含めるか除外します。 順列を順番に処理することで、Ai を含めると、順序を維持しながら、以前に形成された有効な構成すべてに Ai が追加されることが保証されます。 順列の構成は結合的であるため、最終的な順列はグループ化ではなく、選択したサブシーケンスのみに依存します。 したがって、すべてのサブシーケンスは dp に 1 つの状態を正確に生成し、欠落する状態はありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def compose(a, b):
    # return a ∘ b, meaning a[b[i]]
    return tuple(a[b[i] - 1] for i in range(len(a)))

def solve():
    n, m = map(int, input().split())
    perms = [tuple(map(int, input().split())) for _ in range(m)]
    
    identity = tuple(range(1, n + 1))
    dp = {identity}
    
    for p in perms:
        new_states = set(dp)
        for cur in dp:
            new_states.add(compose(cur, p))
        dp = new_states
    
    dp.discard(identity)
    print(len(dp))

if __name__ == "__main__":
    solve()
```コア実装は、順列を Python セット内で使用できるようにタプルとして表現することを中心に展開します。 の`compose`関数は、インデックスを作成することによって順列を次々と適用します。 Python では 0 ベースのインデックスが使用されますが、順列は 1 ベースであるため、1 による減算が必要です。 

DP の更新はスナップショットを使用して慎重に行われます`new_states`これにより、同じ反復で新しく作成された状態がさらなる拡張を再帰的にトリガーすることはなくなり、同じ Ai の複数の使用が誤ってシミュレートされます。 

恒等順列を削除すると、許可されていない空のサブシーケンスがカウントされなくなります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(S・m・n) | 各状態は、ステップごとに 1 回、各順列で構成されます。 
| スペース | O(S・n) | それぞれの個別の順列はハッシュ セットに保存されます。 

n・m ≤ 180 の場合、n と m は両方とも小さく、グループ構造により多くのサブシーケンスが同一の結果に崩壊するため、実際には到達可能な個別の置換の数 S は制限されたままになります。 これにより、制限時間内で DP を管理できるようになります。

 ## 特殊なケース

 重要なエッジケースは、すべての順列が同一である場合です。 この場合、すべてのサブシーケンスは同一性を生成しますが、空のサブシーケンスはカウントしてはなりません。 アルゴリズムはアイデンティティから開始し、空ではない構成のみを追加するため、dp は {identity} で終わり、アイデンティティを破棄するとゼロが生成されます。 

もう 1 つのエッジ ケースは、合成時に順列により重複が生成される場合です。 たとえば、A ∘ A が恒等式に等しい場合、インデックスは一意であるため、{A} や {A, A, A} のようなサブセットは存在しませんが、他の順列の異なる組み合わせは同一の結果に陥る可能性があります。 セットベースの DP はこれらの状態を自然にマージし、明示的なチェックを行わずに正確性を保証します。
