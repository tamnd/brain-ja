 ## 解決策
 ## 問題の理解

 文字列の 2 つのコレクションが与えられます。各コレクションには同じ数の文字列が含まれており、すべての文字列は同じ固定長です。 タスクは、各コレクション内の文字列を個別に並べ替えてから、並べ替えられた各コレクションを 1 つの長い文字列に連結することです。 その後、結果として得られる 2 つの長い文字列を比較します。ただし、ひねりが加えられています。1 つは周期的に回転できます。つまり、任意の位置で切断して接頭辞を最後に移動できます。 

したがって、本当の問題は、文字を循環シフトした後に 2 つの連結された文字列が同一になるように、両方のコレクション内の文字列を並べ替えることができるかどうかです。 

各テスト ケースは独立しています。 有効な並べ替えを記述するインデックスの 2 つの順列を出力するか、それが不可能であると報告する必要があります。 

制約はテストごとではなく合計サイズで厳しくなります。 すべてのテスト ケースのすべての文字の合計は最大 100 万文字であるため、どのソリューションもテスト ケースごとに基本的に直線的な時間で実行する必要があります。 文字列間のネストされた比較や、すべての並べ替えを試行することは、直ちに実行不可能になります。 

すべての文字列が非常に類似しているように見えても、マルチセットとしては同一ではない場合、微妙なエッジ ケースが発生します。 たとえば、A に {"aa", "ab"} が含まれ、B に {"aa", "ac"} が含まれている場合、一方のコレクションには文字パターンが含まれており、もう一方のコレクションには含まれていないため、再配置を行っても、回転後であっても連結された文字列が一致することはありません。 単純な考えでは、マルチセットの等価性をチェックせずに最終的な連結の回転を整列させようとする可能性があります。これは、不一致を修正するには再配置だけで常に十分であると誤って仮定することになります。 

## アプローチ

 強引な解釈は、順列の観点から直接考えることから始まります。 A のすべての順序と B のすべての順序を試し、2 つの連結された文字列を構築し、一方が他方の循環回転であるかどうかを確認できます。 これは定義と明示的に一致するため、概念的には単純で正しいものです。 ただし、これは n の階乗であり、文字列を構築して比較する場合でも、試行ごとに O(nm) のコストがかかり、実現可能な制限をはるかに超えています。 

重要な観察は、循環回転が個々のブロックではなく、最終的に連結された文字列に作用するということです。 2 つの連結が相互に巡回シフトである場合、それらには、まったく同じ多重度でまったく同じ文字が含まれている必要があり、さらに重要なことに、長さ m のブロックの同じマルチセットが構造全体にわたって保存されなければなりません。 各シーケンス内で任意に並べ替えることができるため、残る唯一の構造要件は、両方のシーケンスがまったく同じ文字列のマルチセットで構成されているということです。 

これが理解されると、周期的条件はより深い意味で無関係になります。 2 つの文字列のマルチセットが同一の場合は、両方のシーケンスに対して同じ順序を選択するだけで済みます。 この場合、連結された文字列は文字通り等しくなります。これは、シフト 0 を伴う巡回同型性の特殊なケースです。 マルチセットが異なる場合、並べ替えでは文字列が作成または破壊されないため、順序を変更してもその不一致を修正できません。 

これにより、問題は複雑なグローバル アラインメントの問題から単純なマルチセット比較の問題に縮小されます。

 | --- | --- | --- | --- |
 | ブルートフォース順列 | O(n! · n · m) | O(nm) | 遅すぎる |
 | マルチセットマッチング | O(nm log n) または O(nm) | O(nm) | 承認済み |

 ## アルゴリズムのチュートリアル

 次に、観察を建設的な手順に変換します。

1. テスト ケースの 2 つの文字列リストを読み取り、各文字列を入力内の元のインデックスに関連付けます。 
2. 文字列の内容に基づいて両方のリストを辞書順に並べ替えます。 これにより、同じ文字列を自然に順番に並べることができます。 
3. ソート後、2 つの文字列シーケンスを位置ごとに比較します。 不一致が現れた場合は、マルチセットが同一ではなく、有効な順列が存在しないことを意味するため、-1 を出力します。 
4. それらが一致する場合、ソートされた順序でインデックスを取得して両方の順列を構築します。 A の順列はソート後の A の順序であり、B についても同様です。 
5. これら 2 つの順列を出力します。 

ソートで十分な主な理由は、ソートがマルチセットの正規表現を提供するためです。 2 つのマルチセットが等しい場合、それらの並べ替えられた表現は同一であり、同一の要素間の組み合わせは有効です。 

### なぜ効果があるのか

 連結された文字列間の循環同型性は、文字列が内部的にどのようにブロックにグループ化されるかには依存せず、最終的な文字列の内容にのみ依存します。 どちらのシーケンスでもブロックを自由に並べ替えることができるため、基礎となるマルチセットが一致するときはいつでも、常に同じ文字列を同じ順序で整列させることができます。 これにより、同一の連結文字列が生成され、循環等価性が自明に満たされます。 マルチセットが異なる場合、少なくとも 1 つの文字列の頻度が異なり、並べ替えや回転によってその不一致を調整することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    
    for _ in range(t):
        n, m = map(int, input().split())
        
        A = []
        B = []
        
        for i in range(n):
            A.append((input().strip(), i + 1))
        for i in range(n):
            B.append((input().strip(), i + 1))
        
        A.sort()
        B.sort()
        
        ok = True
        for i in range(n):
            if A[i][0] != B[i][0]:
                ok = False
                break
        
        if not ok:
            out.append("-1")
            continue
        
        p = [str(x[1]) for x in A]
        q = [str(x[1]) for x in B]
        
        out.append(" ".join(p))
        out.append(" ".join(q))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このソリューションでは、並べ替えによって元の位置が失われないように、まず文字列をインデックスでグループ化します。 並べ替えは純粋に文字列の内容に基づいて行われ、同一の文字列は交換可能であるため安全です。 ソート後、2 つのシーケンスの等しいかどうかが直接チェックされます。 それらが一致する場合、対応するインデックス順序を出力します。 それ以外の場合は不可能であると報告します。 

一般的な実装の落とし穴は、ソート中に元のインデックスを保持することを忘れることです。これにより、必要な順列を再構築できなくなります。 もう 1 つの微妙な問題は、グローバル状態を誤って再初期化することなく、複数のテスト ケースを効率的に処理することです。 

## 実用的な例

 両方のセットが一致する場合を考えてみましょう。 

入力:

 A = ["abc", "def", "ghi"]

 B = ["bcd", "efg", "hia"]

 ソート後、同一の文字列を整列させます。 それらが同一のマルチセットである場合、ソートされた順序は正確に一致し、両方に対して同じ順列構造が出力されます。 

次に、不一致の場合を考えてみましょう。 

A = ["abc"]

 B = ["デフォルト"]

 | ステップ | 並べ替えられた | B 並べ替え | 一致 |
 | --- | --- | --- | --- |
 | 並べ替え後 | ABC | デフ | いいえ |

 要素のみが異なるため、アルゴリズムはすぐに -1 を返し、どの並べ替えもギャップを埋めることができないことを反映します。 

これは、アルゴリズムが問題を純粋なマルチセットの等価性チェックに帰着させることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n m log n) | 長さ m の n 個の文字列を並べ替えることが優先されます。 
| スペース | O(nm) | すべての文字列とインデックスの保存 |

 すべてのテスト ケースの合計サイズは最大 10^6 文字であるため、並べ替えとスキャンは制限内で快適に行えます。 各文字は最大 1 つの並べ替え操作に参加するため、ソリューションの効率が維持されます。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    t = int(input())
    out = []
    
    for _ in range(t):
        n, m = map(int, input().split())
        A = [(input().strip(), i+1) for i in range(n)]
        B = [(input().strip(), i+1) for i in range(n)]
        
        A.sort()
        B.sort()
        
        if any(A[i][0] != B[i][0] for i in range(n)):
            out.append("-1")
        else:
            out.append(" ".join(str(x[1]) for x in A))
            out.append(" ".join(str(x[1]) for x in B))
    
    return "\n".join(out)

# minimal case
assert run("1 1\na\n a\n") != ""

# identical single element
assert run("1 1\na\na\n") == "1\n1"

# simple valid swap
assert run("2 1\na\nb\na\nb\n") != "-1"

# multiset mismatch
assert run("2 1\na\nb\na\nc\n") == "-1"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | n=1 の場合 | 同一のインデックス | 基本的な正確性 |
 | 等しいマルチセット | 有効な順列 | 建設 |
 | 不一致の場合 | -1 | 不可能の検出 |
 | 小さなスワップケース | -1 以外 | 注文の柔軟性 |

 ## 特殊なケース

 すべての文字列が同一の場合、ソートされた両方の配列は自明に一致します。 このアルゴリズムは同一の順序を出力し、連結された両方の文字列が同じであるため、巡回シフトは直ちに満たされます。 

多数の重複文字列など、重複が大量に存在する場合でも、並べ替えによってそれらは正しくグループ化されます。 アルゴリズムは一意性に依存せず、同一のブロックは交換可能であるため、安定した配置は有効です。 

2 つのマルチセット間で 1 つの文字列のみが異なる場合、並べ替えにより 1 つの位置での不一致が明らかになります。 このアルゴリズムは、回転推論を試行することなくケースを正しく拒否しますが、回転では欠落しているブロックや余分なブロックを修正できないため、これは無関係です。
