 ## 解決策
 ## 問題の理解

 いくつかの位置が最初に感染している家の円形の配置が与えられています。 毎日は 2 つのフェーズで構成されます。まず、現在安全な 1 つの家を永久に保護します。次に、感染したすべての家から、隣接するすべての保護されていない未感染の家に感染が広がります。 

目標は、感染が拡大しなくなった後、感染した住宅の総数が可能な限り少なくなるように保護命令を選択することです。 

このプロセスを理解するのに役立つ方法は、感染した家屋を円に沿って外側に拡大する「感染源」として想像し、一方で私たちの保護がこの拡大を阻止する障壁として機能することを想像することです。 家が保護されると、それは永久的な壁となり、感染したり、さらなる拡散に使用されることはありません。 

入力サイズにより、ソリューションの構造が重要になります。 住宅の数 n は最大 10^9 まで非常に大きくなる可能性がありますが、感染した住宅の数はすべてのテスト ケース全体で合計すると少なくなります。 これは、プロセスを完全な円でシミュレートできないことを直ちに示唆しています。 個々の家を追跡したり、日々の拡張をシミュレートしたりするアプローチは、あまりにも遅すぎます。 

重要な隠された構造は、感染した位置間のギャップのみが重要であるということです。 円は、感染した家の間で健全な家のセグメントに効果的に分割され、これらのセグメントだけが感染がどのように伝播するか、および保護を配置することがどれほど役立つかを決定します。 

感染した家が 1 軒だけの場合、微妙なエッジケースが発生します。 その状況では、感染は円に沿って両方向に対称的に広がります。その答えは、その単一の感染源からの拡大をいかに早く阻止できるかに完全にかかっています。 感染間に内部境界がないため、感染を複数のセグメントのように扱う単純な貪欲な戦略は失敗します。 

もう 1 つの注意が必要なケースは、感染した位置が等間隔に配置されている場合です。 ここでは、すべてのギャップは等しく、局所的にはすべてが対称に見えても、貪欲な選択では、より大きな実効スプレッドを破ることを最初に正しく優先する必要があります。 

## アプローチ

 ブルートフォースシミュレーションでは、プロセスを毎日モデル化しようとします。 毎日、安全な場所を選択し、そこに保護済みとしてマークを付け、現在感染しているすべてのセルから感染を拡大します。 各拡張は潜在的に多くの新しい家に影響を与える可能性があるため、最悪の場合は円の大部分を繰り返しスキャンすることになります。 n が 10^9 までの場合、状態を保存することさえ不可能であり、状態を圧縮したとしても、セグメント間で繰り返される伝播は、影響を受ける 1 日あたりの間隔のサイズが依然として線形であり、最大 m ステップにわたる爆発につながります。 

重要な観察は、円上の最初に感染した家の間のそれぞれの隙間内で感染が独立して広がるということです。 感染した位置を分類すると、円は隙間の連続になります。 各ギャップは、感染した 2 つのエンドポイント (ラップアラウンドの場合は 1 つのエンドポイント) で囲まれた線形セグメントのように動作します。 感染は両側から内側に拡大し、私たちの保護は日数を費やすことでこの拡大を阻止できます。 

この貪欲な戦略は、各ギャップが感染によって「蝕まれる」速度と、保護ブロックを配置できる速度を比較することから生まれます。 毎日 1 単位の拡張を効果的に遅らせることができるため、最善の戦略は、健全な住宅の残りの最大部分を保存することを常に優先することです。 

形式的には、サイズ x の隙間ごとに、感染が両側から隙間を食い尽くします。保存できる家の数は、どれだけ早く遮断を開始するかによって決まります。 これらのギャップを並べ替えて降順に処理すると、保護日数の最適な割り当てが得られます。 

直感的には、大きな隙間は、完全に感染するまでに時間がかかるため貴重であるため、隙間の中に防護壁を設置する機会が多くなります。

 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(n · m) 以上 | O(n) | 遅すぎる |
 | ギャップ + 貪欲な並べ替え | O(m log m) | O(m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 円に沿って感染位置を並べ替えます。 これは、連続する感染した家の間のギャップを正確に計算するために必要です。 
2. 循環順序で隣接する感染位置間のすべてのギャップを計算します。 連続する 2 つの感染した家 a と b の場合、ギャップは b - a - 1 であり、ラップアラウンド ギャップの場合、n - 最後 + 最初 - 1 です。これらのギャップは、当初は安全だった家の独立した範囲を表します。 
3. ギャップを降順に並べ替えます。 この順序は、感染圧力が最も高い地域、または介入によって最も多くの住宅が救われる地域を優先することを反映しています。 
4. 経過日数を表す変数を初期化します。 これは、保護によって効果的にブロックされた感染層の数を追跡します。 
5. ソートされたギャップを反復処理します。 感染は保護に時間がかかる間に両端から内側に進行するため、各ギャップについて、そのサイズからすでに使用された日数の 2 倍を差し引きます。 結果の値が正の場合は、それを答えに追加し、日カウンターを適切に増やします。 
6. 感染した家の総数を、ギャップ内に保存されたすべてのセグメントの補数として累積します。 

### なぜ効果があるのか

 感染は最初に感染した家を飛び越えることができないため、各ギャップは独立して動作します。 隙間内では感染が両端から対称的に進行し、塞がれない限り有効に使用できる空間が 1 日あたり 2 ユニット減少します。 各保護は 1 日の成長を効率的に消費することで拡張を遅らせるため、より大きなギャップに早い日を割り当てると、セルを遅らせるよりも常に多くのセルが保存されます。 これにより、ギャップ サイズによる貪欲な順序付けが最適な単調な利益構造が作成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    
    if m == n:
        print(n)
        continue
    
    a.sort()
    
    gaps = []
    for i in range(m - 1):
        gaps.append(a[i + 1] - a[i] - 1)
    gaps.append(n - a[-1] + a[0] - 1)
    
    gaps.sort(reverse=True)
    
    saved = 0
    days = 0
    
    for g in gaps:
        effective = g - 2 * days
        if effective <= 0:
            continue
        effective -= 1
        if effective > 0:
            saved += effective
            days += 2
    
    print(n - saved)
```コードはまず感染位置を正規化し、すべての円形ギャップを構築します。 並べ替えにより、常に最も価値のある領域が最初に処理されるようになります。 

変数`days`感染圧力がどれだけ蓄積されているかをモデル化し、以前の保護によって両側の何層がすでに無力化されているかを表します。 それに応じて各ギャップは減少します。 による引き算`2 * days`両端から広がる感染の対称的な性質を捉えています。 

最終的な答えは、総住宅数から感染から救われる住宅を差し引いたものとして計算されます。 

## 実用的な例

 ### 例 1

 入力:

 n = 10、感染者 = [3、6、8]

 分類された感染者: [3、6、8]

 ギャップは次のとおりです。 

| ステップ | 計算されたギャップ |
 | --- | --- |
 | 3→6 | 2 |
 | 6→8 | 1 |
 | 8 → 3 (ラップ) | 4 |

 ソートされたギャップ: [4, 2, 1]

 最大のギャップを最初に処理します。 

| ギャップ | 日々 | 効果的 | 保存済み |
 | --- | --- | --- | --- |
 | 4 | 0 | 4 | 3 |
 | 2 | 2 | 0 | 0 |
 | 1 | 2 | 0 | 0 |

 合計保存数 = 3、つまり感染 = 10 - 3 = 7。 

これは、小さいセグメントは事前の拡散圧力によって圧倒されるため、最大のセグメントのみが意味のある貢献をしていることを示しています。 

### 例 2

 入力:

 n = 10、感染者 = [2, 5]

 分類された感染者: [2、5]

 ギャップ:

 | ステップ | ギャップ |
 | --- | --- |
 | 2→5 | 2 |
 | 5→2 | 5 |

 ソート済み: [5, 2]

 | ギャップ | 日々 | 効果的 | 保存済み |
 | --- | --- | --- | --- |
 | 5 | 0 | 5 | 4 |
 | 2 | 2 | 0 | 0 |

 合計保存数 = 4、感染者 = 6。 

これは、ラップアラウンド セグメントが同等に扱われ、大きい場合にはプロセスを支配することを確認します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(m log m) | 線形ギャップ処理による感染位置とギャップのソートが優先 |
 | スペース | O(m) | 感染した位置とギャップ配列のみを保存します |

 この制約により、テスト ケース全体で最大 10^5 の合計感染位置が許可されるため、テスト ケースごとの並べ替えで十分です。 すべての演算は m 単位で線形またはほぼ線形であるため、解は容易に制限内に収まります。

import sys, io

def run(inp: str) -> str:

    input = sys.stdin.readline

    out = []
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        
        if m == n:
            out.append(str(n))
            continue

            gaps.append(a[i+1] - a[i] - 1)
        gaps.append(n - a[-1] + a[0] - 1)
        
        gaps.sort(reverse=True)

        days = 0
        
        for g in gaps:
            eff = g - 2 * days
            if eff <= 0:
                continue
            eff -= 1
            if eff > 0:
                saved += eff
                days += 2
        
        out.append(str(n - saved))
    
    return "\n".join(out)

 ## 特殊なケース

 感染した家が 1 つあれば、問題は 1 つの円形の拡大領域に縮小されます。 このアルゴリズムは、1 つの大きなラップアラウンド ギャップを作成し、複数の感染ポイント間の隣接構造に依存せずにそれを正しく評価します。 

すべての家が感染すると、ギャップ構築ではどこでもゼロが生成され、保存するスペースがないため、アルゴリズムはすぐに n を返します。 

感染した家が等間隔に配置されている場合、すべての隙間は等しく、並べ替えによって任意の順序が維持されます。 各ギャップが同じ感染圧力用語によって均一に削減され、ギャップが誤って優先順位付けされることがないことが保証されるため、貪欲は依然として機能します。 

すべての場合において、挙動は相対的なギャップ サイズと日の経過によって引き起こされる線形減衰のみに依存し、これはプロセスの実際の対称拡散ダイナミクスと一致します。
