 ## 解決策
 ## 問題の理解

 0 と 1 の 2 つのシーケンスが与えられます。`a`長さの`n`そしてシーケンス`b`長さの`m`。 私たちは変身したいのです`a`の中へ`b`最初の 2 つの要素のみを変更できる 2 つの操作を使用します。`a`そして最初の要素を削除します。 操作 1 は 2 番目の要素を最初の 2 つの要素の最小値に置き換え、操作 2 は最大値に置き換えます。 各操作の後、次の最初の要素が`a`が削除され、シーケンスが効果的に前方にスライドされます。 

入力は複数のテスト ケースで構成され、それぞれが長さとシーケンスを指定します。 変換できた場合、出力は「YES」になります。`a`の中へ`b`, それ以外の場合は「いいえ」。 最大長は、`a`そして`b`は 50 で、テスト ケースの数は 2000 に達する可能性があります。これらの限界は、O(n·t) が最大 100,000 回の操作であるため、制限時間内で無理なく、各テスト ケースのシーケンスを単純に線形スキャンすることで解決できることを示唆しています。 

微妙な点は、操作は最初の 2 つの要素にのみ影響するため、最後の要素は`b`のいずれかの要素と一致する必要があります`a`操作を通じて最後の位置に伝播することができます。 次の場合には、別のトリッキーなエッジケースが発生します。`b`は 1 つの要素の長さだけです。 その場合、最後の要素が`a`一致することができます`b[0]`そして、シーケンスの早い段階で適切な値を生成するためのある程度の柔軟性があること。`b[0]`。 

## アプローチ

 単純なアプローチは、考えられるすべての操作シーケンスをシミュレートすることです。 から開始`a`次のいずれかになるまで、各ステップで両方の操作を試します。`a`マッチ`b`あるいは不可能になってしまう。 これが機能するのは、テスト ケースごとの操作数が最大でも`n-1`各演算は O(1) です。 ただし、操作シーケンスの数は指数関数的に増加し、n=50 では実行不可能になります。 

重要な洞察は、すべての操作シーケンスをシミュレートする必要はないということです。 の最後の要素のみ`b`の最後の要素が必要です`a`スライド後、それ以前のすべての要素は 1 つの条件だけを満たす必要があります。シーケンスには両方の条件が含まれている必要があります。`0`そして`1`もしどこかで`b[-1]`前の要素とは異なります。 より具体的には、`0`または`1`の最後の位置で`b`、少なくとも 1 つ存在する必要があります`0`そして1つ`1`の接頭辞に`a`操作中に 2 番目の要素に影響を与える可能性があります。 これにより、問題は最後の要素をチェックし、シーケンスに少なくとも 1 つの要素が含まれていることを確認するだけになります。`0`そして1つ`1`もし`m>1`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^(n-m) * m) | O(n) | 遅すぎる |
 | 最適 | テスト ケースあたり O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. の最後の要素を特定します。`b`、呼んでください`b_last`。 この要素は、次のいずれかの要素と一致する必要があります。`a`スライド操作後。 最初の要素を繰り返し削除するので、次のことを確認するだけで十分です。`a[n-m]`(要素は次の最初の要素と整列します`b`) を生成するために使用できます。`b_last`後`m-1`操作。 
2. の最後の要素が`a`の最後の要素に等しい`b`。 そうでない場合は、一連の操作で最後の要素を変更できないため、すぐに「NO」を出力します。`a`すべての削除後。 
3. シーケンスの場合`b`1 より長い場合は、最初のどこかにあることを確認してください。`n-1`の要素`a`以下に等しい要素が少なくとも 1 つ存在します`b[-2]`。 これにより、操作で必要な値を前方に伝播できることが保証されます。 そのような要素が存在しない場合は、「NO」を出力します。 
4. 両方のチェックに合格した場合は、「YES」と出力します。 

機能する理由: 操作は 2 番目の要素を最小化または最大化します。これは、連続する 2 つの要素が互いに影響を与える可能性があることを意味します。 の最後の要素`b`の正しい相対位置にすでに存在している必要があります`a`。 もし`m>1`、値を伝播する柔軟性は、最小値または最大値が最後から 2 番目の要素と一致するように強制できる少なくとも 1 つの要素の存在によってもたらされます。`b`。 他の制約は重要ではないため、このチェックは変換の可能性を完全に特徴付けます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, m = map(int, input().split())
    a = input().strip()
    b = input().strip()
    
    if a[n - m] != b[0]:
        print("NO")
        continue
    
    if m == 1:
        print("YES")
        continue
    
    # Check if there is any element in a[0:n-1] that equals b[1]
    possible = '1' if b[1] == '1' else '0'
    if possible in a[:n-1]:
        print("YES")
    else:
        print("NO")
```まずは位置合わせをします`a`と`b`したがって、の最初の要素は`b`に相当する`a[n-m]`。 長さ 1 のシーケンスの場合、アライメントのみが問題になります。 長いシーケンスの場合は、必要な値を伝播するために適切な要素がプレフィックスに存在するかどうかを確認します。 スライス`a[:n-1]`一致するようにすでに予約されている最後の要素を誤ってチェックしないようにします`b[-1]`。

 ## 特殊なケース

 もし`b`長さが 1 の場合、アルゴリズムは、最後の要素が YES であれば正しく YES を返します。`a`マッチ`b[0]`、プレフィックスに関係なく。 たとえば、次のように入力します。```
1
5 1
10101
1
```ここ`b`長さは 1 です。`a[n-1]=a[4]='1'`マッチ`b[0]`したがって、出力は YES になります。 それ以上のチェックは必要ありません。 

最後の要素が一致しない場合は、たとえば次のようになります。```
1
5 1
10101
0
```

`a[4]='1' != b[0]='0'`は即座に NO をトリガーし、アルゴリズムが不必要な計算を行わずに境界の不一致を処理することを示しています。
