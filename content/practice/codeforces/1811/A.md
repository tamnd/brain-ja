 ## 解決策
 ## 問題の理解

 文字列として書かれた 10 進数と 1 つの追加の数字が与えられます。 この数字は、最初の数字の前や最後の数字の後など、数字の任意の位置に挿入できます。 目標は、特殊な場合の先行ゼロなしで通常 10 進数で解釈された結果の数値ができるだけ大きくなるように、挿入位置を選択することです。 

重要なメンタル モデルは、文字列に 1 文字を挿入し、辞書編集上可能な最大の結果文字列が必要であるということです。これは、2 つの同じ長さの 10 進数文字列を桁ごとに比較することは、負でない整数の数値比較と一致するためです。 

入力サイズはテスト ケース全体で大きく、すべての数値の合計の長さは最大で 200,000 になります。 これは、すべての挿入位置を個別に試行し、完全な文字列を繰り返し再構築するソリューションは、テスト ケースごとに線形である場合にのみ、全体としては依然として問題がないことをすぐに示唆しています。 テスト ケースごとの二次関数は、最悪の入力では崩壊します。 

単純なアプローチでは、n+1 個の位置のそれぞれに数字を挿入し、毎回結果の文字列を構築し、すべての結果を比較することを試みる可能性があります。 文字列の構築と比較が繰り返されるため、最悪の場合、テスト ケースごとにすでに O(n^2) のコストがかかります。 テスト全体の合計 n が最大 2e5 であるため、これでは遅すぎます。 

不注意で貪欲な直感を打ち破るようなエッジケースがいくつかあります。 1 つは、98765 のような降順の数値に 1 を挿入するなど、余分な桁が小さい場合です。常に追加するのは間違っています。早めに挿入するとより大きな数値が生成されるためです。 もう 1 つは、数字が挿入された数字と等しい場合です。たとえば、5555 に 5 を挿入します。この場合、配置は重要ではありませんが、条件が厳密である場合、off-by-one 挿入ルールによって正確性が簡単にずれてしまう可能性があります。 最後のエッジケースは 0 の挿入です。先頭のゼロはオリジナルでは許可されていませんが、中間構造の一部として許可されているため、配置が依然として重要です。 正確さは純粋に辞書編集上の順序を最大化することに依存します。 

## アプローチ

 ブルート フォース方式では、考えられるすべての挿入ポイントが試行されます。 0 から n までの各位置 i に対して、数字を挿入して新しい文字列を構築し、これまでに確認された最良の文字列と比較します。 これは、すべての有効な構成を明示的に評価するため、正しいです。 失敗点はパフォーマンスです。 各挿入には構築に O(n)、比較に O(n) のコストがかかり、テスト ケースごとに O(n^2) が得られます。 合計文字数が 2e5 を超えると、これでは非常に遅くなります。 

問題の構造により、より簡単に観察できるようになります。 固定文字列に 1 桁の数字を挿入しており、結果として得られる文字列を辞書順でできるだけ大きくしたいと考えています。 これは、最大の順序を維持しながら、挿入された数字をできるだけ左に配置したいことを意味します。 数値を左から右に移動する場合、挿入された数字以上である限り、既存の数字を保持する必要があります。これは、数字の後に数字を配置すると、より大きなプレフィックスが保持されるためです。 現在の数字が挿入された数字よりも厳密に小さい最初の位置が、それを挿入する場所です。 

そのような位置が見つからない場合は、すべての数字が挿入された数字以上であることを意味するため、最適な位置は末尾になります。 

これにより、問題は 1 回のリニア スキャンに軽減されます。

 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。

1. 文字に変換された文字列番号と数字 d を読み取ります。 文字を操作すると、整数変換の繰り返しが回避され、辞書編集的な比較と直接調整されます。 
2. 空の結果リストと、数字を挿入したかどうかを示すフラグを初期化します。 
3. 元の番号を左から右にスキャンします。 各位置で、現在の桁を d と比較します。 
4. 現在の数字が d 以上である間、それを結果に追加します。 このようにするのは、d を前に置くと接頭辞が辞書順で小さくなるからです。 
5. d よりも厳密に小さい数字が見つかるとすぐに、その位置に d を挿入し、それを結果に追加し、元の数値の残りを追加します。 
6. d を挿入せずに最後まで到達した場合は、最後に追加します。 

重要な決定点は、厳密な不平等です。 現在の数字が d に等しい場合でも、挿入は延期されます。これは、後で d を配置するとプレフィックスが保持され、結果の数値が減らないためです。 

機能する理由: スキャンのどの時点でも、結果にすでに追加されているすべての数字の位置が最適であることが保証されます。 d を配置するとプレフィックスが改善される最初の位置は、まさに既存の数字が d より小さい場所です。 後で挿入すると、必要よりも早くプレフィックスが減らされ、それより早く挿入すると、それより大きいか等しい数字が置き換えられるため、最終的な辞書編集値を増やすことはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n, d = input().split()
        s = input().strip()

        inserted = False
        res = []

        for ch in s:
            if not inserted and ch < d:
                res.append(d)
                inserted = True
            res.append(ch)

        if not inserted:
            res.append(d)

        out.append("".join(res))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装は、前述した貪欲スキャンの直後に続きます。 文字列の連結を繰り返すとパフォーマンスが 2 次の動作にまで低下するため、効率を高めるために結果はリストを使用して構築されます。 挿入チェックは文字ごとに 1 回行われるため、直線的な複雑さが保証されます。 

微妙な点は、ch < d を検出した場合、現在の文字を追加する前に挿入が行われることです。 この数字は厳密に最初の小さい数字の前に出現する必要があるため、これにより正確さが保たれます。 代わりに、最初に追加してから挿入すると、位置が誤って 1 つずれてしまいます。

 ## 特殊なケース

 主なエッジ ケースは、すべての数字が挿入された数字と等しい場合です。 入力用`44444`と`d = 4`、スキャンでは厳密に 4 より小さい数字は検出されないため、挿入は最後に行われます。 アルゴリズムは最初にすべての数字を追加し、次に 4 を追加して、`444444`これは正しいです。以前に挿入すると、同じ複数セットの数字が同じ順序で生成され、ルールによって一貫して最後の有効な位置に数字が配置されるためです。 

もう 1 つのエッジ ケースは、挿入された数字が 0 の場合です。たとえば、`7058959`の場合、アルゴリズムは 0 より小さい最初の桁に 0 を配置しますが、このようなことは決して起こらないため、最後に追加されます。 0 が最小の桁であるため、先頭位置に挿入しても辞書編集値が減少するだけであるため、これは正しいです。 

最後のエッジケースは、挿入された数字が可能な最大の 9 である場合です。`12345`、最初の数字 1 は 9 より小さいため、先頭にすぐに挿入します。`912345`。 これにより、貪欲ルールが最上位桁位置の最大化を正しく優先していることが確認されます。
