 ## 解決策
 ## 問題の理解

 それぞれ色と整数を持つタイルの行が与えられます。$k$。 パスは右側のタイルにジャンプすることで形成され、パスの長さが次の値で割り切れる場合、そのパスは「ナイス」と呼ばれます。$k$色は、サイズの連続したブロック内で一定です。$k$。 タスクは、可能な最大長の素敵なパスの数を数えることです (剰余)$10^9 + 7$。 

入力は複数のテスト ケースで構成されます。 テストケースごとに、タイルの数が与えられます。$n$、ブロックサイズ$k$、色の順序。 ケースごとに、最長のナイス パスの数を計算する必要があります。 

制約は次のことを教えてくれます$n \le 100$そして$k \le n$、との合計$n^3$すべてのテスト ケースは制限されています。 これは、$O(n^3)$テストケースごとのソリューションは実現可能です。 考えられるすべてのパスを生成する単純な解決策は指数関数的であり、明らかに実行不可能です。 小さいもの$n$動的計画法または組み合わせ計数が快適に適合することを示唆しています。 

エッジケースには、すべてのタイルが同じ色であるシナリオが含まれます。$k = 1$、連続する 2 つのタイルが同じ色を持たない場合、および$k$等しい$n$。 たとえば、次の場合$n = 3$そして$k = 2$色付き`[1, 2, 3]`、最大ナイス パス長は次のとおりです。$k = 2$, しかし、単一のブロックのみが存在し、生成されるパスはほとんどありません。 不注意な実装では、長さのパスを識別できない可能性があります$k$有効な最大長のパスとして。 

## アプローチ

 ブルートフォース手法では、タイルのすべてのシーケンスを列挙し、各シーケンスが次の値で割り切れるかどうかを確認しようとします。$k$、各ブロックの色が同じであることを確認します。 このようなシーケンスの数は、次のように指数関数的に増加します。$n$、それは実現不可能です$n = 100$。 

重要な洞察は、パスの長さが$m$は、各ブロックの開始タイルのインデックスで表すことができます。 ナイス パスの最大長は、タイルをあるサイズのブロックにグループ化できる最長のサブシーケンスによって決まります。$k$同じ色で。 これにより、問題はタイルごとの組み合わせ動的計画問題に帰着します。$i$で終わるブロックの最大数を計算します。$i$そして、これが起こる可能性が何通りあるか数えてください。 

具体的には、次のように定義できます。`dp[i]`タイルで終わるナイス パス内のブロックの最大数として`i`、 そして`cnt[i]`で終わるその長さのパスの数として`i`。 以前のすべてのタイルを反復処理します`j < i`サイズのブロックかどうかを確認します`k`から拡張できます`j`に`i`。 その場合は更新します`dp[i]`そして`cnt[i]`それに応じて。 このアプローチが実現可能な理由は、$n \le 100$、につながる$O(n^3)$テストケースごとのソリューション。

 ## アルゴリズムのチュートリアル

 1. 2 つの配列を初期化します。`dp`そして`cnt`、それぞれの長さ$n$、 と`dp[i] = 0`そして`cnt[i] = 1`。`dp[i]`タイルで終わるブロックの最大数を保存します`i`、 そして`cnt[i]`それを達成するための方法の数を保存します。 
2. すべてのタイルを反復処理します。`i`左から右へ。 タイルごとに、前のすべてのタイルを反復処理します。`j`長さのブロックかどうかを確認するには`k`同じ色のものを次から形成できます。`j+1`そして終わる`i`。 これを確認するには、ブロック内のすべての色が同じであることを確認します。 
3. 有効なブロックが存在する場合`j+1`に`i`で終わるパスを延長するかどうかを確認します。`j`より多くのブロックを生成します`dp[i]`。 その場合はアップデートしてください`dp[i] = dp[j] + 1`そしてセット`cnt[i] = cnt[j]`。 同じ数のブロックが生成される場合は、増分します。`cnt[i] += cnt[j]`。 
4.充填後`dp`そして`cnt`の最大値を求めます。`dp`。 の合計`cnt[i]`みんなのために`i`どこ`dp[i]`最大値は、最大長のナイス パスの数と同じです。 
5. このカウントのモジュロを返します$10^9 + 7$。 

なぜ効果があるのか​​:`dp[i]`で終了するパスの最適な数のブロックを保存します。`i`。 以前のすべてのタイルを拡張対象として考慮することで、考えられるすべてのパスが確実にカウントされます。 数える`cnt[i]`同じ最大ブロック数に到達するための複数の方法が正しく累積されるようにします。 モジュロ演算により、整数のオーバーフローが防止されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

for _ in range(int(input())):
    n, k = map(int, input().split())
    c = list(map(int, input().split()))
    
    dp = [0] * n
    cnt = [1] * n
    
    for i in range(n):
        for j in range(i):
            # Check if a block of length k ending at i can extend path ending at j
            if i - j >= k:
                block_color = c[i]
                valid = True
                for x in range(i - k + 1, i + 1):
                    if c[x] != block_color:
                        valid = False
                        break
                if valid:
                    if dp[j] + 1 > dp[i]:
                        dp[i] = dp[j] + 1
                        cnt[i] = cnt[j]
                    elif dp[j] + 1 == dp[i]:
                        cnt[i] = (cnt[i] + cnt[j]) % MOD
        # Check if the first block can start at the beginning
        if i + 1 >= k:
            block_color = c[i]
            valid = True
            for x in range(i - k + 1, i + 1):
                if c[x] != block_color:
                    valid = False
                    break
            if valid:
                dp[i] = max(dp[i], 1)
                # cnt[i] remains at least 1
    
    max_blocks = max(dp)
    ans = sum(cnt[i] for i in range(n) if dp[i] == max_blocks) % MOD
    print(ans)
```コードでは、`dp[i]`タイルで終わるブロックの最大数を格納します`i`。 内側のループは、有効なサイズのブロックかどうかをチェックします。`k`で終わるように形成できます`i`最後を調べてみると`k`タイル。 初期化により、先頭から始まる単一ブロックが確実にカウントされます。 モジュロ演算により、累積中のオーバーフローが防止されます。 

## 実用的な例

 ### 例 1

 入力:`5 2`そして色`[1, 2, 3, 4, 5]`。 

タイルはすべて異なります。 長さ 2 の連続するブロックは同じ色を持ちません。`dp`に滞在します`[0, 0, 0, 0, 0]`。 最大ブロック数は 0 で、空のパスは 1 つだけカウントされます。 出力は`1`。 

### 例 2

 入力:`7 2`そして色`[1, 3, 1, 3, 3, 1, 3]`。 

長さ 4 のナイス パスは、それぞれサイズ 2 の 2 つのブロックに対応します。`[1,3,4,5]`、`[2,4,5,7]`、`[1,3,5,7]`、`[1,3,4,7]`。`dp`複数の位置で最大ブロック 2 で終了し、`cnt`に蓄積する`4`。 出力は`4`。 

| 私 | dp[i] | cnt[i] |

 | 0 | 0 | 1 |

 | 2 | 1 | 1 |
 | 3 | 1 | 1 |

 | 5 | 2 | 1 |
 | 6 | 2 | 4 |

 これにより、アルゴリズムがブロック数とパスの組み合わせを正しく追跡していることが確認されます。
