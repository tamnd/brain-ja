 ## 問題の理解

 派生配列が与えられます$b$、そしてそれは何らかの隠し配列から来ていると言われています$a$。 それぞれの値$b_i$内の 2 つの隣接する値の最大値です。$a$、 具体的には$a_i$そして$a_{i+1}$。 私たちの仕事は、元の配列を一意に再構築することではなく、有効な配列を構築することです。$a$それは与えられたものを生み出すことができたでしょう$b$。 

問題の構造はローカルです。 すべての制約は、次の 2 つの隣接する位置のみを結び付けます。$a$したがって、システム全体は重複する最大制約の連鎖です。 出力は、これらの極大関係をすべて満たす非負の整数配列です。 

制約により、最大で$2 \cdot 10^5$テスト ケース全体の要素の合計を計算するため、二次関数やシミュレーションを多用した再構築は即座に除外されます。 各ポジションの候補者を個別に強引に選ぼうとするものは、少なくとも次のような結果につながるでしょう。$O(n^2)$最悪の場合の動作は限界をはるかに超えています。 ソリューションはテスト ケースごとに線形である必要があります。 

次の場合、微妙なエッジケースが発生します。$b$繰り返しの値または長い平らなセグメントが含まれています。 素朴な考えとしては、各制約の両方のエンドポイントを直接次のように設定することかもしれません。$b_i$ただし、これは隣接する制約に違反する可能性があります。$a$2 つの異なる極大値に参加します。 ゼロが明示的に割り当てられていなくても制約が伝播される可能性があり、不注意に入力すると誤って不要な正の値が導入される可能性があるため、ゼロが出現すると別の失敗ケースが発生します。 

## アプローチ

 ブルートフォース試行では、考えられるすべての配列を構築しようとします。$a$と一致する$b$、各候補がすべての最大制約を満たすかどうかを確認します。 値を$b$、各位置には依然として複数の選択肢があり、状態空間は指数関数的に増加します。 のために$n = 2 \cdot 10^5$、要素ごとの二者決定であっても、$2^n$可能性はありますが、それは明らかに実現不可能です。 

重要な観察点は、それぞれが$b_i$少なくとも 1 つを強制するだけです$a_i$または$a_{i+1}$等しい$b_i$、両方ともそれを超えてはなりません。 これはそれぞれのポジションを意味します$a_i$は 2 つの近傍によって制約されます。$b_{i-1}$そして$b_i$。 現地で考えてみると、$a_i$隣接する最大値のいずれにも違反しないように十分に小さくなければなりませんが、もう一方のエンドポイントを適切に選択することで両方の制約を満たせるように十分に大きくする必要があります。 

これは、建設的な貪欲な戦略につながります。各位置に、両方の隣接する制約と互換性のある最小値を割り当て、同時に各ペアの少なくとも 1 つのエンドポイントが必要な最大値を実現できるようにします。 これを達成する直接的かつクリーンな方法は、すべてを初期化することです。$a_i$ゼロとして、必要な最大値を必要な位置に選択的に「注入」し、すべての値を保証します。$b_i$少なくとも 1 つのエンドポイントによって実現されます。 

より体系的な構築は、それぞれを処理することです。$b_i$どちらの立場でも現れなければならない要求として$i$または$i+1$, そしてまだ柔軟なポジションに貪欲に割り当てます。 各ポジションは最大 2 つの制約に関与するため、一貫性を保証するには左から右へのパスで十分です。

 ## アルゴリズムのチュートリアル

 1. 配列を初期化する$a$長さの$n$すべてゼロで。 これにより、最大制約に決して違反しない中立的なベースラインが得られます。 
2. インデックスごとに$i$、制約を考慮します$b_i = \max(a_i, a_{i+1})$。 2 つの位置のうち少なくとも 1 つが値を取得することを確認する必要があります$b_i$。 
3. 両方の場合$a_i$そして$a_{i+1}$現在は以下です$b_i$、割り当てます$a_{i+1} = b_i$。 この選択により、制約が満たされることが保証されながら、左側の将来の柔軟性が維持されます。 
4. エンドポイントの 1 つがすでに等しい場合$b_i$、制約はすでに満たされているため、何もしません。 
5.すべての処理が完了したら$b_i$、配列を返します$a$。 

重要な設計上の選択は、必要に応じて値を常に右に押し出すことです。 これにより、以前の制約を満たすためにまだ必要な左側の位置を時期尚早に固定することが回避されます。 

### なぜ効果があるのか

 それぞれの制約$b_i$は 1 回だけ処理され、処理されると、少なくとも 1 つのエンドポイントが一致することが保証されます。$b_i$。 それを超えて値を増やすことは決してないので、$b_i$、制約が満たされた後は、制約に違反することはありません。 貪欲な方向により、今後の制約では、必要に応じて右側で調整できる有効なプレフィックスが常に参照されるようになります。 これにより、以前の決定を破ることなく、すべての最大要件がローカルで満たされる一貫したチェーンが作成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    b = list(map(int, input().split()))
    
    a = [0] * n
    
    for i in range(n - 1):
        if a[i] < b[i] and a[i + 1] < b[i]:
            a[i + 1] = b[i]
    
    print(*a)
```このソリューションはゼロで初期化された配列から始まり、偶発的な制約違反が発生しないようにします。 次に、各制約を左から右に処理し、それぞれの制約を適用します。$b_i$必要に応じて、その値を適切なエンドポイントに配置します。 この方向性は、以前に適用された制約の上書きを防ぐため、非常に重要です。 

よくある間違いは、両側を対称的に割り当てたり、更新をバックトラックしようとしたりすることです。 これにより、重複する制約間に矛盾が生じます。 貪欲なワンパスアプローチは、それを完全に回避します。

 ## 特殊なケース

 重要なエッジケースは、すべての値が$b$はゼロです。 この状況では、正しい出力はすべてゼロの配列です。 このアルゴリズムはゼロから始まり、割り当てをトリガーしないため、この構造が正しく保存されます。 

もう一つのケースは次のような場合です。$b$厳密に増加しています。 新しい値が追加されるたびに、新しい値が右側に強制的に割り当てられ、以前の値は変更されません。 貪欲な戦略により、各増加が競合することなく独立して処理されることが保証されます。 

3 番目のケースは単一要素です$b$、等しい値の任意のペアが有効です。 このアルゴリズムは必要な場合にのみ割り当てを行うため、特別な処理を行わなくても有効なペアが自然に生成されます。
