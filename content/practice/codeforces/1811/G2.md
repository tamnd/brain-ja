 ## 解決策
 ## 問題の理解

 タイルが並んでいて、それぞれが色で塗られています。 Vlad は、パスが一定の長さの連続したブロックに分割できるように、この行に沿ってパスを作成したいと考えています。`k`、各ブロックは同じ色で構成されます。 可能な限り最大の長さの「適切なパス」をすべて見つけるように求められます。 

各テスト ケースはタイルの数を示します`n`、ブロックサイズ`k`、色の配列。 出力は、最大長の Nice パスの数を法的に表したものです。`10^9 + 7`。 

制約とは、次のことを意味します。`n`最大 5000 まで可能で、合計は`n^2`すべてのテストケースにわたって`≤ 25·10^6`。 これは、タイル上にネストされたループを持つアルゴリズム (`O(n^2)`）実現可能ですが、それより悪いことは、次のようになります。`O(n^3)`, 制限時間を超えてしまいます。 

明らかではないエッジ ケースは、最大長のパスが短い場合に発生します。 たとえば、次の場合`n=5`そして`k=2`色付き`[1,2,3,4,5]`、長さ 2 のブロックは同じ色を持たないため、実質的に長さ 0 の唯一の最大ナイス パスとなり、出力は次のようになります。`1`。 もう 1 つの注意が必要なケースは、すべてのタイルが同じ色である場合です。 その場合、複数のパスが形成される可能性があるため、タイル選択の組み合わせを慎重にカウントする必要があります。 

## アプローチ

 ブルート フォースのアプローチは簡単です。すべてのタイルでパスを開始してから、ブロックの制約に従ってパスを継続できる次のすべてのタイルを再帰的または反復的に試行します。 考えられるすべてのパスの長さを確認し、最長のものを保持します。 これは正しいですが、すぐに実行不可能になります。`n`が 5000 であれば、大まかに実行します`n^2`テスト ケースごとの操作は開始位置のみであり、すべてのジャンプを考慮するとコストがさらに倍増するため、`O(n^3)`最悪の場合、遅すぎます。 

最適化のための重要な洞察は、あるブロックから色が一致する次のブロックにジャンプするパスのみを考慮すればよいということです。 開始インデックスごとに、同じ長さの連続ブロックの最大数を事前計算できます。`k`同じ色を持つもの。 次に、動的プログラミングを使用して、各位置で終了するパスをカウントできます。有効なブロック内の各位置は、同じ色の前のブロックからカウントを継承できます。 パスは加算的であり、ブロックは連続しているため、問題は、ブロック全体で増加するサブシーケンスをカウントするという変形に帰着します。 

単純な O(n^3) アプローチから動的プログラミング O(n^2) ソリューションへの削減は、適切なパスが各ブロックの開始インデックスによって完全に決定されるという観察によって推進されます。 ブロックの境界と色がわかれば、パスのカウントはすべてのジャンプにわたって再帰的ではなく、組み合わせ的に行われるようになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^3) | O(n^2) | 遅すぎる |
 | 最適 (ブロック全体の DP) | O(n^2) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、次の内容を読んでください。`n`、`k`、および配列`c`色の。 
2. 事前計算`cnt[i]`ポジションごとに`i`。`cnt[i]`は、同じ長さの連続するブロックの最大数です。`k`から始まる`i`各ブロックは同じ色です。 の倍数ごとにチェックします`k`ブロックが均一かどうかを確認してください。 これにより、インデックスから始まる素敵なパスの最大長を知ることができます。`i`。 
3. 動的プログラミング配列を初期化する`dp[i]`位置で終了する最大長のナイス パスの数を表す`i`。 
4. 各ブロックの開始位置を逆方向に繰り返します。 それぞれについて`i`、将来の位置を調べてパスを延長する方法の合計数を計算します。`j`どこ`c[j]`次のブロックの色と一致します。 アップデート`dp[i]`合計することで`dp[j]`モジュロ値`10^9 + 7`。 
5. 充填中に全体の最大パス長を追跡します。`dp`。 この最大長に達するパスのみをカウントします。 
6. すべてを合計する`dp[i]`テスト ケースの最終的な答えを得るために、最大長に達する可能性のある開始位置を指定します。 

**それが機能する理由:** それぞれ`dp[i]`で始まるすべてのナイス パスの数を累積します。`i`同じ色の長さのブロックのみを使用します`k`。 不変条件は、各ステップで、DP はブロックカラー条件が成立するパスのみを拡張するということです。 逆に反復することで、将来の長いパスからのカウントが以前の位置に正しく伝播されるようになり、すべての最大長のパスが含まれることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
MOD = 10**9 + 7

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        c = list(map(int, input().split()))
        dp = [0] * n
        max_len = 0

        # Compute maximum number of blocks starting at i
        blocks = [0] * n
        i = 0
        while i <= n - k:
            same = True
            for j in range(1, k):
                if c[i+j] != c[i]:
                    same = False
                    break
            if same:
                blocks[i] = 1
            i += 1

        # DP over blocks
        for i in reversed(range(n)):
            if blocks[i]:
                dp[i] = 1
                next_pos = i + k
                while next_pos < n:
                    if c[next_pos] == c[i] and blocks[next_pos]:
                        dp[i] += dp[next_pos]
                        dp[i] %= MOD
                    next_pos += k
                max_len = max(max_len, dp[i])

        # Count paths achieving max length
        ans = 0
        for i in range(n):
            if dp[i] == max_len:
                ans += 1
                ans %= MOD
        print(ans)

if __name__ == "__main__":
    solve()
```**説明:** まず、有効な長さのブロックをマークします。`k`すべての色が同じ場合。 次に、そのようなブロックごとに、次のステップで先を見据えます。`k`色の均一性を維持しながらパスを延長します。 各ブロックで終わるパスの数を次のように保存します。`dp`。 最後に、最大長のパスを開始するブロックの数を数えます。 微妙な点には、インデックスの正しい処理が含まれます (`i + k`) とモジュラー演算を使用してオーバーフローを回避します。
