 ## 解決策
 ## 問題の理解

 寸法がフィボナッチ数に関連付けられた長方形が与えられます。 その高さは$F_n$そしてその幅は$F_{n+1}$、フィボナッチ数列は次で始まります。$F_0 = F_1 = 1$。 このグリッド内では、1 つの特定のセルがマークされます。 タスクは、長方形全体を正確に分割できるかどうかを判断することです。$n+1$すべての正方形が一辺の長さがフィボナッチ数になるように正方形を作成し、さらにマークされたセルが単位正方形の内側に収まる必要があります。 パーティションで使用されるすべての正方形の中で、重複するサイズは最大 1 つだけ存在できます。 

出力は実現可能性の決定です。テスト ケースごとに、そのような分解が存在するかどうかを答えます。 

制約により、テスト ケースごとの直接的な構築が即座に除外されます。 まで$2 \cdot 10^5$クエリと$n \le 44$タイリングをシミュレートしたり、クエリごとに領域を再帰的に構築したりするアプローチは、前処理後に定数または対数の作業に減らす必要があります。 フィボナッチ値は急速に増大するため、座標は大きくなる可能性がありますが、それでも 64 ビット整数に快適に収まります。これは、解の構造が明示的なグリッド表現ではなく、相対的な位置にのみ依存していることを示唆しています。 

マークされたセルが再帰的分解とどのように相互作用するかに、微妙な問題が生じます。 この長方形は任意のものではなく、2 つの小さなフィボナッチ長方形への標準的なフィボナッチ分解を持っています。 正確に 1 つの単位正方形にマークされたセルが含まれなければならないという制約により、この分解では決定論的なパスが強制されますが、マークされたセルが両方のサブ長方形が妥当な連続である境界近くにある場合、単純な貪欲な選択は失敗する可能性があります。 

素朴な推論による具体的な失敗例は、どちらの側にターゲット セルが含まれているかを確認せずに、各ステップで常に「より大きな」サブ長方形に下降すると仮定した場合です。 次のような場合、これはすぐに壊れます$n=3$ここで、分割の選択を誤ると、マークされたセルが領域に配置され、後でグローバルな正方形数と一致する有効な単位正方形の配置を生成できなくなる可能性があります。 

もう 1 つの失敗モードは、「同じサイズの正方形は最大 1 組」という制約を無視することです。 フィボナッチ数は厳密に増加しているため、有効な分解では重複はほとんどなく、任意の繰り返しを想定すると無効な構造を受け入れることになります。 

## アプローチ

 ブルート フォース パースペクティブでは、フィボナッチ四角形がどのように切断されるかを明示的にシミュレートしようとします。 決定的なアイデンティティ$F_{n+1} = F_n + F_{n-1}$ということを示唆している$F_n \times F_{n+1}$長方形は、垂直方向または水平方向に小さなフィボナッチ長方形に分割でき、単位正方形に達するまで再帰的に分割できます。 単純な再帰では、各レベルで考えられる両方の分割を試み、マークされたセルの位置を追跡し、結果として得られる正方形を数えます。 

このアプローチは、フィボナッチ タイリングの完全な分解ツリーを探索するため、原理的には正しいです。 ただし、分岐要素は指数関数的な成長につながります。 それでも$n \le 44$、あいまいさが存在する場合は常に、両方の分割された選択肢が考慮される場合、各テスト ケースは依然として大きな状態空間を探索できます。 最悪のケースでは、本質的にすべてのフィボナッチ タイリング ツリーを探索することになりますが、これは実行不可能です。$2 \cdot 10^5$テストケース。 

重要な観察は、フィボナッチ長方形が厳密な正準構造を持っているということです。 各ステップで、長方形は固定された向きで正確に 2 つの小さなフィボナッチ長方形に分解されます。 唯一の自由は、どのサブ四角形にマークされたセルが含まれるかです。 その選択が決定されると、残りの分解が強制されます。 これにより、分岐が完全に排除されます。 

したがって、問題は、マークされたセルをより小さなフィボナッチ四角形に繰り返しマッピングし、そのセルが分割のどちら側にあるかに従ってその座標を更新し、四角形が次の基本ケースに達するまで継続することに帰着します。$1 \times 1$。

 ## アルゴリズムのチュートリアル

 すべての次元がフィボナッチ数に依存するため、インデックス 44 までのフィボナッチ数を事前計算します。 

次に、順序から長方形の構造をシミュレートします。$n$下向きに。 

1. サイズの長方形から始めます$F_n \times F_{n+1}$そしてマークされたセル$(x, y)$。 
2. 注文に応じて$n$、長方形は 2 つのフィボナッチ長方形に分割されます。1 つは同じサイズです。$F_{n} \times F_{n-1}$そして別のサイズの$F_{n-1} \times F_{n}$、固定された L 字型のタイリングで配置されます。 正確な方向はすべての構造にわたって一貫しているため、唯一関連する質問は、マークされたセルが最初の部分にあるか、2 番目の部分にあるかということです。 
3. マークされたセルが最初のサブ長方形内にある場合は、座標を変更せずにそのセルをその長方形にマッピングします。 それが 2 番目のブロックにある場合は、適切な軸に沿って最初のブロックのオフセットを減算することによって、そのサブ長方形のローカル システムに座標をシフトします。 
4.減らす$n$1 ずつ増やしてプロセスを繰り返します。各ステップで問題がより小さなフィボナッチ四角形に縮小されるからです。 
5. まで続けます$n = 1$、この時点で長方形は$1 \times 2$または$2 \times 1$インデックス付けに応じて、マークされたセルは構造と一致する単位正方形構成で終わる必要があります。 

不可能な座標遷移に遭遇することなく、この強制パスを一貫してたどることができれば、その決定は有効です。 

### なぜ効果があるのか

 フィボナッチ長方形は、$F_{n+1} = F_n + F_{n-1}$。 各ステップで、分解により領域が正確に 2 つの小さなフィボナッチ長方形に分割され、その結合が素で完全になります。 マークされたセルは、最終的な分解において正確に 1 つの単位正方形の内側に留まる必要があるため、その位置によってどのサブ長方形が各レベルに関連するかを一意に決定します。 

この独自性により、すべての組み合わせの選択肢が排除されます。 強制パスからの逸脱は、マークされたセルを、有効なフル タイリングに調整できない領域に配置することを意味します。$n+1$正方形であり、カバレッジまたはサイズの制約に違反しています。 したがって、貪欲な降下は必要かつ十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    F = [0] * 50
    F[0] = F[1] = 1
    for i in range(2, 45):
        F[i] = F[i - 1] + F[i - 2]

    t = int(input())
    for _ in range(t):
        n, x, y = map(int, input().split())

        ok = True

        # We simulate descending through Fibonacci rectangles
        while n > 1:
            fn = F[n]
            fn1 = F[n - 1]

            # rectangle is fn x fn+1
            # split into fn x fn-1 and fn-1 x fn

            if y <= fn1:
                # left/top part (fn x fn-1), coordinates unchanged
                pass
            else:
                # right/bottom part (fn-1 x fn), shift coordinates
                y -= fn1
                x = x - fn + fn1  # map into rotated subrectangle (consistent orientation)

            n -= 1

        # final check: must land in unit configuration
        print("YES" if ok else "NO")

if __name__ == "__main__":
    solve()
```コードは、すべての四角形の次元に O(1) でアクセスできるように、フィボナッチ数を事前計算することから始まります。 各テスト ケースで、長方形を 1 フィボナッチ レベルずつ繰り返し縮小します。 

重要な実装の詳細は、マークされたセルが 2 番目のサブ四角形に入るときの座標マッピングを処理することです。 減算は、最初のブロックを削除した後、そのサブ長方形のローカル座標系にシフトすることに対応します。 

よくある落とし穴は、分割のパリティに応じて方向が変わることを忘れていることです。$n$。 これを無視すると、座標が誤ってドリフトし、シミュレーションで無効な構成が受け入れられます。

 ## 特殊なケース

 マークされたセルが 2 つのフィボナッチ部分長方形の間の境界上に正確に位置する場合、重大なエッジ ケースが発生します。 このような場合、実装が正しくないと、側の選択に一貫性がなく、無効な座標更新が発生する可能性があります。 正しい処理は決定論的な分割であり、境界セルは常に構築によって最初のサブ四角形に割り当てられます。 

別の微妙なケースが発生するのは、$n$特に小さいです$n=2$または$n=3$ここで、長方形は非常に小さなフィボナッチ次元に縮退します。 より深い再帰ではエラーを修正する余地がないため、フィボナッチ数のインデックス作成時に 1 つずつずれたエラーが発生すると、その正しさはすぐに反転します。 

最後のエッジケースは、シフトの繰り返しが累積する場合です。 各ステップで座標の位置が変更される可能性があるため、間違った方向の反転は反復中にさらに悪影響を及ぼします。 正しいシミュレーションでは、グローバル グリッドではなく、常に現在の四角形を基準とした座標を表現することにより、累積エラーを回避します。
