 ## 解決策
 ## 問題の理解

 私たちには複数の「イベント」が与えられており、各イベントはもともと特定の日に属しています。 配列はソートされており、各値によってコミットが発生した日がわかります。 

各コミットは柔軟です。コミットを元の日に保持することも、正確に 1 日だけ進めることもできます。 他の移動は許可されず、各コミットは個別に移動されます。 

すべてのコミットの送信先を選択した後、結果として得られるコミットの数日にわたる分布を確認します。 少なくとも 1 つのコミットがその日に到達した場合、その日は「アクティブ」であるとみなされます。 私たちの目標は、アクティブな日を可能な限り長く連続するセグメントにすることです。 

したがって、問題は、アクティブな日数をグローバルに最大化することではなく、毎日少なくとも 1 つのコミットが割り当てられる、最長で中断のない 1 つのブロックを形成することです。 

制約は小さく、テストごとのコミット数は最大 50 で、値は最大 100 です。これにより、テストごとに O(n^3) または O(n^4) 程度のソリューションであれば問題ないことがすぐにわかりますが、すべての割り当てを総当りで実行するのではなく、よりクリーンな組み合わせまたは貪欲な構築を目指す必要があります。 テストは最大 100 個あるため、テスト ソリューションあたり O(n^2) または O(n^3) が安全な目標です。 

微妙な難しさは、コミットが相互作用するという事実から生じます。あるコミットを前に進めると、別の日と衝突したり、ギャップを埋めるのに役立つ可能性があります。 日々を独立して処理する単純な貪欲な人は失敗する可能性があります。 

甘い考えが露呈するエッジケースの 1 つは、すべてのコミットが 1 日に集中する場合です。`[10, 10, 10]`。 すべてが 1 つの場所から始まるため、答えは常に 1 であると思うかもしれませんが、一部を翌日に移動すると、長さ 2 の連続したブロックが作成されます。 

もう 1 つの注意が必要なケースは、ギャップがある場合です。たとえば、`[1, 3, 5]`。 +1 シフトする機能により、一部のギャップを埋めることができますが、すべてを埋める必要はなく、意思決定を調整する必要があります。 

## アプローチ

 強引なアイデアは、各コミットを 2 つの選択肢があるものとして扱うことです。`a[i]`またはに移動します`a[i] + 1`。 これにより、`2^n`課題。 割り当てごとに、数日間の頻度マップを構築し、すべての日が空ではない最長の連続セグメントを計算します。 

これは、考えられるすべての有効な構成を列挙するため正しいですが、非常に遅すぎます。 と`n = 50`、私たちは約を得ます`2^50`可能性はありますが、それは完全に不可能です。 

重要な観察は、私たちは実際には個々の割り当てを気にしていないということです。 私たちが気にしているのは、毎日を一定の間隔でカバーできるかどうかだけです。 これにより、問題はサブセット列挙問題ではなく、カバレッジ構築問題に変わります。 

各コミットを個別に決定する代わりに、毎日の境界付近で「利用可能な」コミットの数という観点から考えることができます。 各コミットは隣接する 2 日間にのみかかるため、短い間隔のように動作します。`[a[i], a[i]+1]`。 整数ポイントの間隔全体がカバーされるように配置を選択したいと考えています。 

問題を再解釈する有効な方法は、ギャップを埋めるためにコミットを前方に「流す」ことを考えることです。 コミットが欠けている日がある場合は、前方にシフトできる前日のコミットから借用しようとします。 

これにより、可能な開始点を貪欲にスキャンすることになります。毎日開始して最長の有効なセグメントを構築しようとし、利用可能なコミットを使用して翌日も埋め続けることができるかどうかをシミュレートします。 

各コミットは 1 ステップしか移動できないため、構造はローカルであり、どれだけの「残りの」コミットを前に進めることができるかを追跡するだけで済みます。

 | --- | --- | --- | --- |
 | ブルート フォース (すべての割り当て) | O(2^n · n) | O(n) | 遅すぎる |
 | 数日間にわたる貪欲なシミュレーション | O(n^2) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各テストを個別に扱います。 

1. 周波数配列を構築する`cnt[d]`1日に最初に発生したコミットの数を表します`d`。 以来`a_i ≤ 100`101 または 102 までの配列に安全に圧縮できます。 
2. 可能な開始日ごとに`L`、最長の有効なセグメントを構築しようとします`[L, R]`。 
3. 変数を維持します`carry`、次の日に前方にシフトできるコミットの数を表します。 最初は`carry = 0`。 
4. 毎日次のことを繰り返します。`L`上向きに。 毎日`d`、追加します`cnt[d]`の中へ`carry`、日からコミットするため`d`滞在することも、移動することもできます`d+1`。 
5. 日を確保しなければなりません`d`満たされています。 もし`carry == 0`、その日`d`をアクティブにすることはできないため、このセグメントの拡張を停止します。 
6. もし`carry > 0`、1 日をカバーするために 1 つのコミットを「使用」します`d`, したがって、デクリメントします`carry`1. 残り`carry`将来の日々を埋める可能性を秘めて前進し続けます。 
7. 1 日でカバーしきれないまで延長を続け、すべての開始点の最大長を追跡します。 

直感的には、毎日 1 つのコミットが消費され、同時にその日から新しいコミットも収集されることになります。 各コミットは 1 ステップしか移動できないため、1 日に入力される供給単位のように動作します。`a[i]`で使用できます`a[i]`または`a[i]+1`。 

### なぜ効果があるのか

 重要な不変条件は次のとおりです`carry`は常に、その日にまだ割り当てられていないが、現在または翌日にはまだ使用できるコミットの数を表します。 すべてのコミットは最大 1 回使用され、遅延できるのは 1 ステップだけなので、最大 1 回だけ繰り越すことができます。 

毎日、1 つのコミットの「コスト」を支払うことができない場合、この時点に到達する可能性のあるすべての利用可能なコミットがすでに使い果たされているため、どの割り当てもその日をアクティブにすることはできません。 逆に、支払いができるのであれば、1 つのユニットを使用するのが常に安全です。使用を遅らせても、将来の柔軟性が高まるだけだからです。 

この貪欲なシミュレーションは、継続するたびに有効な割り当てを暗黙的に構築するため、生成されるどのセグメントも実行可能であり、すべての開始を試すため、最大値が見つかります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        if n == 0:
            print(0)
            continue

        max_day = max(a) + 2
        cnt = [0] * (max_day + 5)

        for x in a:
            cnt[x] += 1

        ans = 0

        for L in range(1, max_day + 1):
            carry = 0
            length = 0

            for d in range(L, max_day + 1):
                carry += cnt[d]

                if carry == 0:
                    break

                carry -= 1
                length += 1

            ans = max(ans, length)

        print(ans)

if __name__ == "__main__":
    solve()
```実装は貪欲な構築に直接続きます。 頻度配列には、毎日発生するコミットの数が格納されます。 

それぞれの開始日ごとに`L`、リセットします`carry`各セグメントが独立しているためです。 次に、利用可能なコミットを毎日追加し、現在の日をアクティブに保つために 1 つを費やして、順方向のシミュレーションを行います。 1 つを費やすことができなくなった時点で、セグメントは終了します。 

まで反復するかどうかの選択`max_day + 1`元の最終日からシフトされたコミットを確実に考慮します。

 ## 特殊なケース

 すべてのコミットが 1 日に該当する場合、アルゴリズムはシフトされたコミットを使用して翌日に延長することを正しく許可します。 キャリーは開始点で蓄積され、正確に 1 日追加できますが、その後新しい供給が到着しないため、それ以上はできません。 

コミットが厳密に 1 つずつ増加する場合、毎日 1 ユニットが正確に供給されるため、キャリーは安定したままとなり、セグメントは自然に全日に拡張されます。 アルゴリズムはキャリーをゼロにしないことでこれを反映しています。 

隙間がある場合など`[1, 3, 5]`、事前に十分なキャリーが蓄積されていない限り、シミュレーションは欠落日をまたいで拡張できません。 ブレーク条件は、最初の避けられない空の日に正確にトリガーされ、そこにカバレッジを生成できる割り当てがないという事実と一致します。
