 ## 解決策
 ## 問題の理解

 目的地までの最初の距離によってソートされたスクーターの列が与えられます。 スクーター$1$一番近くからスタート、スクーター$n$一番遠い。 各スクーターにはその指数に等しい固定公称速度があるため、より高い指数のスクーターはより速く移動しようとします。 

道路には制約があり、スクーター同士のすれ違いはできず、少なくとも 1 メートルの車間距離を保つ必要があります。 より速いスクーターがより遅いスクーターに追いつくと、距離の制約が維持されるように強制的に速度が低下し、接触を通じて速度が後方に伝播する移動チェーンが効果的に形成されます。 

タスクは、これらのルールに従って正確に 1 秒間動作した後のすべてのスクーターの位置を決定することです。 

制約は小さいです。$n \le 100$。 これにより、パフォーマンスを懸念することなく、短期間での直接シミュレーションや貪欲な伝播プロセスが可能になります。 

一般的な故障モードは、スクーターを独立して扱い、その位置から速度を減算することです。 それは、より速いスクーターがより遅いスクーターを追い越すとすぐに壊れます。 もう 1 つの間違いは、速度低下がプレフィックス全体に逆方向に伝播することに気づかず、制約を 1 回だけ強制することです。 

## アプローチ

 単純なアプローチでは、小さなタイムステップで動きをシミュレートし、すべての位置を更新し、スクーターを押し離して違反を修正します。 これは概念的には機能しますが、不必要に重く、すべてのステップで順序付け制約を慎重に処理する必要があります。 

重要な単純化は、1 秒後の各スクーターの位置が、そのスクーター自体の速度または前方のスクーターのいずれかによって決定されることに注意することです。 スクーターが前のスクーターに対して 1 メートルの間隔を違反した場合は、代わりにちょうど 1 メートル後方で停止しなければなりません。 これは、制約を段階的に適用しながら、最終的な位置を左から右に計算できることを意味します。 

ブルートフォースは、時間の経過とともに繰り返し物理を適用するため機能しますが、直接の閉じた形式の計算が必要な場合は失敗します。 相対的な順序付けと単一パスの制約のみが重要であるという観察により、問題は線形スキャンに帰着します。

 | ステップシミュレーション |$O(n \cdot T)$|$O(n)$| 遅すぎる/不必要 |
 | シングルパスの貪欲な伝播 |$O(n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 開始位置から速度を減算して、1 秒後の各スクーターの単純位置を計算します。 これにより、制約を無視したベースラインが得られます。 
2. スクーターを最初から最後まで順番に横切ります。 最初のスクーターの前には拘束がないため、その位置は計算されたままになります。 
3. スクーターごとに$i > 1$、仮の位置とスクーターの位置を比較します。$i-1$。 少なくとも1メートル後ろにいる場合は、そのままにしておきます。 
4.スクーターの場合$i$1 メートルの隙間に違反している場合は、スクーターのちょうど 1 メートル後方に位置を設定してください$i-1$。 これにより、制約がローカルに適用されます。 
5. すべてのスクーターでこのプロセスを継続し、各位置が既に固定されている以前の位置のみに依存するようにします。 

### なぜ効果があるのか

 1 秒後、各スクーターは自由に動くか、その前にある最も近い低速の構成によって制限されます。 制約はソート順の直前の制約にのみ依存するため、必要なすべての調整を反映するには単一の左から右へのパスで十分です。 スクーターが修正されると、それが後続のすべてのスクーターの新しい境界条件になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = [int(input()) for _ in range(n)]
    
    # naive move after 1 second: speed = index (1-based)
    pos = [a[i] - (i + 1) for i in range(n)]
    
    res = [0] * n
    res[0] = pos[0]
    
    for i in range(1, n):
        if pos[i] < res[i - 1] + 1:
            res[i] = res[i - 1] + 1
        else:
            res[i] = pos[i]
    
    print(*res)

if __name__ == "__main__":
    solve()
```このソリューションでは、最初に各位置から速度を減算して、制約のない動きを計算します。 次に、前方スイープを使用して違反を修正します。 重要な詳細は、制約が厳密にローカルであるということです。各スクーターは、そのスクーターがすでに修正された後、すぐ前のスクーターのみを尊重する必要があります。 

微妙な点は、修正によりスクーターの位置が単純な値を超えて増加する可能性があることです。 これは、単独で移動しているのではなく、前方の渋滞に押されて前進しているために必要です。

 ## 特殊なケース

 スクーター同士が非常に接近して発進すると、単純な独立した動きによってスクーターが同じ位置に崩れてしまいます。 代わりに、アルゴリズムは後続のスクーターを前方に押し出して間隔を維持します。 これにより、すべてのナイーブ位置が一致する場合でも、最終結果は、システムの物理的制約に一致する、最小限のギャップを持つ厳密に増加するシーケンスを形成することが保証されます。
