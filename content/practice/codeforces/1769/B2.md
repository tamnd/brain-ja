 ## 解決策
 ## 問題の理解

 複数のファイルをあるサーバーから別のサーバーに順番にコピーし、ファイルごとと全体の 2 つの方法で進行状況を追跡するモデルを作成するように求められます。 各ファイルにはバイト単位のサイズがあり、バイトごとのコピーをシミュレートします。 あらゆる瞬間に、完了した現在のファイルの整数の割合と、完了したすべてのファイルの整数の割合を計算できます。 私たちのタスクは、ある瞬間に両方の進行状況バーに同時に表示される 0 から 100 までのすべてのパーセンテージを見つけることです。 

入力により、ファイルの数とそのサイズのリストが得られます。 出力はすべて整数です`p`そのような`p%`両方のバーで同時に発生します。 ファイル サイズは最大 10^10 バイトと非常に大きくなる可能性があるため、すべてのバイトをシミュレートすることは現実的ではありません。 各バイトを反復処理せずに、可能な同時パーセンテージを計算する方法が必要です。 

主な制約は、ファイル サイズが大きいことと、パーセンテージの切り捨てを考慮する必要があることです。 たとえば、1 つのファイルで 6 バイトをコピーすると、ファイルごとのパーセンテージは 0、16、33、50、66、83、100 になります。ファイル サイズが異なるため、ファイルごとのパーセンテージは合計の進行状況のパーセンテージと必ずしも一致せず、キャプチャする必要があるギャップや重複が生じます。 単純なシミュレーションでは最大 10^12 ステップを実行しますが、これは不可能であるため、数学的アプローチが必要です。 

明らかではないエッジ ケースには、単一のファイル (すべてのパーセンテージが合計進行状況と一致する)、非常に小さいファイル、またはサイズが 100 の倍数ではないファイルが含まれます。たとえば、単一の 6 バイト ファイルには上記のパーセンテージがあり、アルゴリズムは均一な 1% ステップを想定するのではなく、それぞれの同時パーセンテージを正しく検出する必要があります。 

## アプローチ

 ブルートフォース手法では、すべてのファイルの各バイトを反復処理し、両方の進行状況バーを計算し、それらが一致した場合にパーセンテージを収集します。 これは入力が小さい場合には正しいですが、サイズ 10^10 の単一ファイルには 10^10 の反復が必要になるため、すぐに実行不可能になります。 

重要な洞察は、どちらかのプログレスバーが変化する瞬間のみを考慮しているということです。これは、次の倍数で発生します。`a_i / 100`ファイルごとのパーセンテージについては、`total_size / 100`全体の割合については。 切り捨てが使用されるため、特定のパーセンテージにマップされるバイト範囲は連続した間隔を形成します。 ファイルごとに、ファイルごとのパーセンテージに対応するバイト範囲を計算できます。 同様に、全体のパーセンテージごとにバイト範囲を計算できます。 これらの範囲の交差により、同時に表示されるパーセンテージのセットが得られます。 

数学的には、ファイルの場合`i`サイズの`a_i`バイトオフセットから始まる`offset`、ファイルごとのパーセンテージ`p`からのバイトに対して発生します`ceil(p * a_i / 100)`に`floor((p + 1) * a_i / 100) - 1`。 全体の割合`p`からのバイトに対して発生します`ceil(p * total_size / 100)`に`floor((p + 1) * total_size / 100) - 1`。 この間隔が重なると、`p`は有効な同時パーセンテージです。 これにより、問題はすべてのバイトのシミュレーションから、各ファイルの最大 101 パーセント値の処理へと軽減され、実現可能になります。

 | 最適 | O(n * 101) | お(101) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのファイルの合計サイズを計算します。 これにより、全体的な進捗率のスケールが定義されます。 
2. 同時に表示されるパーセンテージを格納するために空のセットを初期化します。 
3. 変数を初期化する`offset = 0`合計内の各ファイルの開始バイト インデックスを追跡します。 
4. 各ファイルを反復処理します。`i`サイズ付き`a_i`。 
5. ファイルごとの可能なパーセンテージごとに`p`0 から 100 まで、このパーセンテージが表示されるファイルの最初と最後のバイトを計算します。 最初のバイトは`ceil(p * a_i / 100)`そして最後のバイトは`floor((p + 1) * a_i / 100) - 1`。 このファイル内のどのバイトにも対応しない割合をスキップします。 
6. 同じように`p`、パーセンテージを示す合計進行状況バーのバイト間隔を計算します。`p`。 最初のバイトは`ceil(p * total_size / 100)`そして最後のバイトは`floor((p + 1) * total_size / 100) - 1`。 
7. ファイルごとのバイト間隔と全体のバイト間隔が重なる場合、`p`同時に達成可能です。 追加`p`セットへ。 
8. アップデート`offset += a_i`次のファイルの開始位置に移動します。 
9. すべてのファイルを処理した後、パーセンテージのセットを並べ替えて出力します。 

機能する理由: ファイルごとの進行状況と全体的な進行状況のパーセンテージは、個別のバイト境界で変化します。 各整数パーセンテージの間隔を計算し、重複をチェックすることにより、丸めによる欠落なしに、可能なすべての同時表示をキャプチャします。 すべての有効なパーセンテージが考慮され、丸めにより整数の計算が十分であることが保証されます。 

## Python ソリューション```python
import sys, math
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

total = sum(a)
ans = set()
offset = 0

for size in a:
    for p in range(101):
        # per-file interval
        file_l = (p * size + 99) // 100  # ceil division
        file_r = ((p + 1) * size) // 100 - 1
        if file_l > file_r:
            continue
        # overall interval
        total_l = (p * total + 99) // 100
        total_r = ((p + 1) * total) // 100 - 1
        # shift per-file interval to global bytes
        file_l_global = offset + file_l
        file_r_global = offset + file_r
        if file_r_global < total_l or file_l_global > total_r:
            continue
        ans.add(p)
    offset += size

for p in sorted(ans):
    print(p)
```このソリューションでは、整数演算を慎重に使用して、浮動小数点エラーを回避します。`(p * size + 99) // 100`安全に実装する方法です`ceil(p * size / 100)`。 ファイルごとの間隔をシフトする`offset`それらを合計進行状況バーと揃えます。 間隔の重複チェックにより、同時に発生する可能性のあるパーセンテージのみが追加されることが保証されます。
