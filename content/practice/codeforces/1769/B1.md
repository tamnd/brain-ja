 ## 解決策
 ## 問題の理解

 あるサーバーから別のサーバーに複数のファイルをコピーする進行状況をシミュレートするように求められます。 各ファイルにはバイト単位のサイズがあり、コピーは一度に 1 バイトずつ順次行われます。 進行状況インジケーターは 2 つあります。1 つ目はコピーされた現在のファイルの割合を示し、2 つ目はコピーされたすべてのファイルの全体の割合を示します。 どちらのパーセンテージも、各バイトの後に最も近い整数に切り下げられます。 

入力はファイルの数を示します`n`そしてそれらのサイズの配列。 出力は、両方の進行状況バーに同時に表示される 0 から 100 までのすべての整数です。 つまり、コピー プロセスのある時点で、現在のファイルの進行状況と合計の進行状況は両方とも同じ整数に切り捨てられます。 

制約は小さく、各ファイルのサイズは最大 1000 バイト、ファイル数は最大 100 です。 これは、最悪の場合にコピーされる合計バイト数が 100,000 であることを意味し、バイトごとにシミュレーションすることが可能です。 

ファイル サイズが 100 を均等に分割しない場合、明らかではないエッジ ケースが発生します。 たとえば、サイズ 6 のファイルの進行状況の値は 0、16、33、50、66、83、100 になります。`100/a_i`中間値が失われる可能性があります。 もう 1 つのエッジ ケースは、サイズ 1 の複数のファイルです。どちらのプログレス バーも中間ステップなしで 0 から 100 に直接ジャンプしますが、アルゴリズムには 0 と 100 が含まれている必要があります。 

## アプローチ

 最も簡単なアプローチは総当たりです。各ファイルの各バイトのコピーをシミュレートし、現在のファイルのパーセンテージと合計パーセンテージを計算し、両方のバーに表示されるすべての整数を保存します。 進行状況バーが確定的に更新され、合計バイト数が少ないため、これは正しいです。 ただし、このアプローチでは各バイトを個別に反復処理します。 最悪の場合、それぞれ 1000 バイトのファイルが 100 個ある場合、100,000 ステップをシミュレートします。 これは特定の制約では実現可能ですが、その必要はありません。 

重要な洞察は、各バイトをシミュレートする必要がないということです。 ファイルごとに、現在のファイルの進行状況は次の場合にのみ変更されます。`floor(100*x/a_i)`合計の進行状況も同様に増加します。 したがって、各整数のパーセンテージが表示されるバイト範囲を計算できます。 各整数について`p`0 から 100 まで、存在するかどうかを確認できます。`x`そのようなファイルに`floor(100*x/a_i) == p`そして`floor(100*(sum_previous + x)/total) == p`。 ファイル サイズが小さいため、すべてのファイルについて 0 から 100 までのすべての整数をチェックすることが効率的です。 これにより、問題はバイトごとのシミュレーションからファイルごとのパーセンテージごとの範囲チェックに軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(合計(a_i)) | お(101) | 小さいサイズも承ります |
 | 最適化されたパーセンテージチェック | O(n * 101) | お(101) | 受け入れられ、クリーンです |

 ## アルゴリズムのチュートリアル

 1. すべてのファイルの合計サイズを計算します。 これは全体的な進行状況の計算に必要です。 
2. 両方の進行状況バーに表示されるすべてのパーセンテージを保存するセットを初期化します。 
3. 各ファイルを繰り返し処理します。 このファイルの前にコピーされた合計バイト数を追跡​​します。`copied_so_far`。 
4. For each integer percentage`p`0 から 100 まで、バイト範囲を計算します`x`現在のファイルの進行状況はどこですか`p`。 これは不等式を解くことで達成されます`p <= 100 * x / a_i < p + 1`。 Convert these inequalities into integer bounds for`x`。 
5. 対応するバイト範囲を計算します。`x`合計の進捗状況も`p`、同じ方法を使用します。`p <= 100 * (copied_so_far + x) / total < p + 1`。 
6. 現在のファイルの進行状況と合計の進行状況の範囲が交差しているかどうかを確認します。 存在する場合は、追加します`p`結果セットに。 
7. すべてのファイルを処理した後、すべてのパーセンテージを順番に出力します。 

これが機能する理由は、整数のパーセンテージごとに、両方のプログレス バーに表示されるバイトが少なくとも 1 バイト存在するかどうかを明示的にチェックしているためです。 個々のバイトではなく整数の範囲を扱うことで、正確性を保証しながら不必要なシミュレーションを回避します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

total = sum(a)
result = set()
copied_so_far = 0

for size in a:
    for p in range(101):
        # current file: p <= 100 * x / size < p + 1
        l1 = (p * size + 99) // 100  # ceil(p*size/100)
        r1 = ((p + 1) * size - 1) // 100  # floor((p+1)*size/100) - 1
        
        # total: p <= 100 * (copied_so_far + x) / total < p + 1
        l2 = (p * total + 99 - copied_so_far * 100) // 100
        r2 = ((p + 1) * total - 1 - copied_so_far * 100) // 100
        
        if l1 <= r1 and l2 <= r2 and max(l1, l2) <= min(r1, r2):
            result.add(p)
    copied_so_far += size

for x in sorted(result):
    print(x)
```このコードは、整数の除算を使用して範囲を慎重に計算します。`l1`そして`r1`進行状況を生成する現在のファイル内の最小および最大のバイト インデックスを表します。`p`。`l2`そして`r2`合計の進捗状況についても同じことを行います。 小切手`max(l1, l2) <= min(r1, r2)`両方の条件を満たすバイトが少なくとも 1 バイトあるかどうかを確認します。

 ## 特殊なケース

 サイズ 1 のファイルの場合、可能な進行状況パーセンテージは、コピー前は 0、コピー後は 100 のみです。 バイト範囲は次のとおりであるため、アルゴリズムはこれを正しく識別します。`floor(100 * x / size)`単一の値に折りたたまれます。 サイズ 6 のファイルのような不均一な分布の場合、整数の丸めは上限と下限の式によって明示的に処理されるため、16 や 83 などのパーセンテージが正しく含まれます。 複数のファイルの場合、合計進行状況の計算には `copyed_so が考慮されます。
