 ## 解決策
 ## 問題の理解

 の根付きツリーを構築するように求められています。`n`特別なプロパティを持つノード: 各ノードには **神性** があり、これはルートからそのノードまでのパス上の最小のノード ラベルです。 数値を与える`m`、すべてのノードの神性値の合計が正確に等しくなるようなツリーが必要です。`m`。 そのようなツリーが存在しない場合は、報告する必要があります`-1`。 

入力は複数のテスト ケースで構成されます。 各テスト ケースが提供するのは、`n`そして`m`。 出力ではルート ノードを指定する必要があります。`n-1`木の端。 ノードにはラベルが付けられます`1`を通して`n`、合計条件を満たす任意の有効なエッジ セットが受け入れられます。 

制約により許可されるのは、`n`まで`10^6`テストケースごと、そして`m`まで`10^{12}`、ただし、合計は`n`すべてのテスト ケースにわたって、次のように制限されます`10^6`。 これは、次の線形解が必要であることを示しています。`n`テストケースごとに。 すべてのツリーを列挙しようとするソリューションは、非常に遅すぎます。 高い`m`価値観はまた、神性の合計を素朴にシミュレートできないことを意味します。 数学的なアプローチが必要です。 

エッジケースは次の場合に発生します。`n`非常に小さい、たとえば`n = 1`そして`m = 2`。 単一のノードは、それ自身のラベルと同等の神性のみを持つことができます。`1`、 それで`m = 2`不可能です。 のために`n > 1`別の特殊なケースは次のような場合です。`m`たとえば、どの木でも形成するには小さすぎるか大きすぎます。`n = 4`そして`m = 3`(最小合計は次のとおりであるため、合計が小さすぎます`1+1+1+1 = 4`） または`m`ルートを持つスターツリーで可能な最大合計を超えています`1`。 

## アプローチ

 ブルートフォースアプローチは、考えられるすべてのルートツリーを生成し、それらの神性の合計を計算し、等しいものがあるかどうかを確認することです。`m`。 これはすべてのツリーをチェックするので論理的には正しいですが、組み合わせ爆発がすぐに発生します。`n`ラベル付きノードは`n^{n-2}`。 たとえ`n = 20`、これは天文学的な数字です。 したがって、ブルートフォースは完全に非現実的です。`n`まで`10^6`。 

重要な観察は、ノードの神聖さは、**ルートからそのノードまでのパスに沿った最小のラベル**にのみ依存するということです。 合計を最小化するには、最小のラベルをルートとして配置し、他のすべてのノードを子 (スター ツリー) として直接接続します。 これにより合計が得られます`n`根が貢献しているから`1`、および他のすべてのノードが貢献します`1`それぞれ。 合計を最大化するには、最大のラベルからルートまでツリーを**チェーン**に配置します。 これにより合計が得られます`1 + 2 + 3 + ... + n`根があれば`1`、 または`n*(n+1)/2`。 

したがって、貪欲な構築が可能である。 合計を最小にするツリーから開始し、ターゲットに到達するまでノードをツリーの奥深くに移動することで**神聖さを徐々に高めます**`m`。 すべてのステップで、パスに沿った最小のラベルは、何らかの祖先のラベルのままになります。 どのノードをどの親に接続するかを慎重に選択することで、最小値と最大値の範囲内で可能な合計を達成できます。 

最適なソリューションでは、**レベルごとの構造**が使用されます。 根を摘みます`k`そしてその合計が達成できるように神性の値を割り当てます`m`。 合計が等しくなるまで、深さごとの神性の増分を最大化する方法でノードを分散します。`m`。 最小値と最大値の合計を分析的に計算し、実現可能性をチェックして、貪欲なアルゴリズムを使用してエッジを割り当て、現在の合計と深さを追跡できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^n) | O(n) | 遅すぎる |
 | 貪欲 / 建設的 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ツリーの最小および最大の可能な神性の合計を次のように計算します。`n`ノード。 最小和はルートを持つスターツリーで発生します`1`、合計 =`n`。 最大合計はノード ラベルが増加するパス/ツリーで発生します。合計 =`1+2+...+n`=`n*(n+1)/2`。 
2. もし`m`この範囲外の場合、出力`-1`。 
3. ルートラベルを選択します。 自然な選択は、`1`それは最小額を許可するからです。 
4. 2 つの配列を維持しながら、レベルごとにノードの接続を開始します。`parents`各ノードの親に対して、`depths`神性の追跡のため。 最初、ツリーは単一のルートです。 
5. 変数を維持する`current_sum`最小額から開始 (`n`）。 配置されていないノードごとに、ツリーのより深いノードにノードを接続することで、神性の最大の増加を計算します。 
6. を超えない範囲で、最大の増分を与える親にノードを貪欲に接続します。`m`。 アップデート`current_sum`。 
7. すべてのノードが配置されるまで繰り返します。 もし`current_sum`等しい`m`、エッジを出力します。 
8. 最後に`current_sum`!=`m`、出力`-1`。 

機能する理由: アルゴリズムは常に次の不変条件を維持します。`current_sum`すでに配置されているノードの神性の合計を反映します。 神性増加を超えずに最大化するノードアタッチメントを選択することで、`m`、正確に到達することを保証します`m`それが実現可能であれば。 深さの割り当てにより、神聖さが決して減少しないことが保証されるため、無効な合計は生成されません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        min_sum = n
        max_sum = n * (n + 1) // 2
        if m < min_sum or m > max_sum:
            print(-1)
            continue

        # choose root = 1
        root = 1
        res = []
        current_sum = min_sum
        nodes = [1]
        next_label = 2
        # assign nodes greedily
        from collections import deque
        queue = deque([1])
        parent = {1: 0}
        while next_label <= n:
            u = queue.popleft()
            res.append((u, next_label))
            parent[next_label] = u
            current_sum += (next_label - 1)  # increase divineness
            queue.append(next_label)
            next_label += 1
            if current_sum >= m:
                break

        # fill remaining nodes as children of root
        for i in range(next_label, n+1):
            res.append((1, i))

        print(root)
        for u, v in res:
            print(u, v)

if __name__ == "__main__":
    solve()
```このソリューションでは、まず最小値と最大値の合計の境界を使用して実現可能性をチェックします。 根を摘みます`1`神性増加を最大限に高めるために貪欲にノードを取り付けます。 残りのノードはルートに接続されます。 の`current_sum`完全な神性を説明し、正確さを保証します。
