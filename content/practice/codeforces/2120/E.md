 ## 解決策
 ## 問題の理解

 各レーンには最初に次のものが含まれます`a_i`車。 誰も動かない場合、車線内の車は 1 秒に 1 台出発するため、車線の大きさは`x`貢献する$$1+2+\dots+x=\frac{x(x+1)}2$$完全な怒りに。 

車が車線変更する場合があります。 移動された車は別の車線の後ろに追加され、追加のペナルティを受けます。`k`。 車線変更は瞬時に行われ、いつでも発生する可能性があるため、重要なのは各車線の最終的な車両数だけです。 

最終的なレーン サイズが次のようになったとします。`b_1, b_2, ..., b_n`車の総数が同じ場合:$$\sum b_i = \sum a_i = S.$$待ち時間負担金は、$$\sum \frac{b_i(b_i+1)}2.$$残りの問題は、実際に何台の車両が移動する必要があるかです。 

レーンの場合`i`で終わる`b_i`せいぜい車`min(a_i,b_i)`オリジナルの車両はそこに留まることができます。 残りは出発するか、他の場所から到着する必要があります。 移動する車両の最小台数は、$$\sum \max(0,a_i-b_i).$$したがって、最適化問題は次のようになります。$$\min \sum \left( \frac{b_i(b_i+1)}2 + k\max(0,a_i-b_i) \right).$$制約こそが本当の課題なのです。 まであります`10^4`テストケースと合計`n`すべてのテストケースにわたって`2·10^5`。 個々のレーンのサイズが到達する`10^6`, したがって、車の総数は次のようになります。`2·10^{11}`。 車を個別に推論するアルゴリズムは不可能です。 複雑さが依存するソリューションが必要です。`n`、車両の総数ではありません。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

考慮する：```

5
```車線は1つしかありません。 車を便利な場所に移動させることはできません。 答えは単純です$$1+2+3+4+5=15.$$バランスをとることが常に役立つと仮定したソリューションは、間違った結果を生み出すことになります。 

別の微妙なケースは次のとおりです。```
1
2 1
1 1
```車の引っ越しにはほとんど費用はかかりませんが、それでも引っ越しは役に立ちません。 設定を維持すると完全に怒られる`1+1=2`。 あらゆる動きによってレーンのサイズが作成される`(0,2)`そしてコスト`3+1=4`。 

もう一方の極端な場合:```
1
2 100
10 0
```待機時間の用語はバランスをとることを優先しますが、移動のペナルティは膨大です。 最適な設定により、ほとんどの車が所定の位置に固定されます。 二次レーンサイズ項を最小化するだけの解決策は失敗します。 

## アプローチ

 強引な観点は、最終的なレーン サイズを選択することです`b_i`そして評価する$$\sum \frac{b_i(b_i+1)}2 + k\sum \max(0,a_i-b_i).$$問題は、可能なベクトルの数が限られていることです。`(b_1,\dots,b_n)`定額で`S`天文学的です。 控えめな値であっても、検索スペースには手が届きません。 

重要な観察は、目的が分離可能であるということです。 定義する$$g_i(b) = \frac{b(b+1)}2 + k\max(0,a_i-b).$$それなら私たちが欲しいのは$$\min \sum g_i(b_i)$$の対象となる$$\sum b_i=S.$$これは古典的な凸型リソース割り当て問題です。 

建物のレーンを想像してみてください`i`車は一度に一台ずつ。 サイズを増やすコストを`t-1`に`t`限界費用になる$$\Delta_i(t)=g_i(t)-g_i(t-1).$$簡単に計算すると、$$\Delta_i(t)= \begin{cases} t-k,& t\le a_i,\\ t,& t>a_i. \end{cases}$$レーンごとに、増加する一連の限界費用を取得します。$$1-k,\;2-k,\;\dots,\;a_i-k,\;a_i+1,\;a_i+2,\dots$$最終的なサイズを選択することは、正確に選択することと同じです`S`これらすべてのシーケンスの和集合から得られる限界費用項目。 最小総コストは次のように求められます。`S`最小の限界費用。 

ここで、問題は次のようになります。無限に多くの限界値の中で、最小の値の合計を見つけます。`S`彼らのうち。 

周辺値は単調なので、しきい値を二分探索することができます。`m`。 どれについても`m`、限界が何個あるか数えることができます`≤ m`すべての限界の合計を計算します`< m`。 これにより、問題は標準的な数えて合計する二分探索に変わります。

## アルゴリズムのチュートリアル

 1. しましょう`S = sum(a)`。 
2. それを観察してください$$g_i(b) = \frac{b(b+1)}2 + k\max(0,a_i-b).$$合計の目標は、これらの独立したレーンのコストの合計です。 
3. 各レーンの周辺シーケンスを計算します。$$\Delta_i(t)= \begin{cases} t-k,& t\le a_i,\\ t,& t>a_i. \end{cases}$$選択する`b_i`最初を取ることを意味します`b_i`レーンからの限界値`i`。 
4. 問題を正確に選択するように再解釈する`S`すべてのレーン シーケンスの和集合からの限界値。 

最適解は次の合計です。`S`最小の限界値。 
5. 整数のしきい値による二分探索`m`。 

サイズのあるレーンの場合`a_i`:

 満足する限界の数`Δ ≤ m`は$$\min(a_i,m+k)+\max(0,m-a_i),$$負の量はゼロにクリップされます。 
6. しましょう`C(m)`限界の合計数になります`≤ m`。 

を満たす最小のしきい値を見つける$$C(m)\ge S.$$同様に、$$C(m-1)<S\le C(m).$$7. より厳密に小さいすべての限界の数と合計を計算します。`m`。 

レーン用`i`:

 最初のセグメントが貢献します$$c_1=\min(a_i,m+k-1),$$限界、その和は$$\frac{c_1(c_1+1)}2-kc_1.$$2番目のセグメントが貢献します$$c_2=\max(0,m-1-a_i)$$限界、その和は$$\sum_{t=a_i+1}^{a_i+c_2} t = \frac{c_2(2a_i+c_2+1)}2.$$8. しましょう`cnt_less`辺縁の合計数になります`< m`そして`sum_less`それらの合計。 

まだ必要です$$S-cnt\_less$$限界、すべて正確に値を持つ`m`。 
9. 最小値の合計`S`限界は$$sum\_less + (S-cnt\_less)\cdot m.$$10. 定数項を追加します$$kS.$$This recovers the original objective value.

 ### なぜ効果があるのか

 各レーンの限界コストは、減少しない系列を形成します。 実現可能な最終サイズのベクトルは、各シーケンスのプレフィックスを取得することに対応し、選択されたマージナルの合計数は正確に次のようになります。`S`。 

あらゆる選択方法の中で`S`限界の場合、最小合計はグローバル最小値を取ることによって取得されます。`S`価値観。 二分探索により境界値を特定します`m`選択された余白と選択されていない余白を分離します。 カウント式は、その境界の下にある値の数と、それらの合計寄与度を正確に決定します。 残りのポジションを値で埋める`m`の合計を再構築します`S`最小のマージン、これがまさに最適な目的です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))

        S = sum(a)
        mx = max(a)

        def count_le(m):
            total = 0
            for x in a:
                c1 = min(x, max(0, m + k))
                c2 = max(0, m - x)
                total += c1 + c2
            return total

        lo = -k
        hi = max(mx, (S + n - 1) // n) + 2

        while lo < hi:
            mid = (lo + hi) // 2
            if count_le(mid) >= S:
                hi = mid
            else:
                lo = mid + 1

        m = lo

        cnt_less = 0
        sum_less = 0

        for x in a:
            c1 = min(x, max(0, m + k - 1))
            cnt_less += c1
            sum_less += c1 * (c1 + 1) // 2 - k * c1

            c2 = max(0, m - 1 - x)
            cnt_less += c2
            sum_less += c2 * (2 * x + c2 + 1) // 2

        marginal_sum = sum_less + (S - cnt_less) * m
        answer = k * S + marginal_sum

        ans.append(str(answer))

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```二分探索により、限界限界値が求められます。 機能`count_le(m)`限界費用が最大でいくらになるかを計算します`m`。 

下限は`-k`、これは可能な最小の限界値 (`1-k`）。 上限は最終しきい値を超えるだけで済みます。 一度`m`到達する`max(a_i)`、各レーンは大まかに寄与します`m`限界に近いので、限界が近い`max(a_i)`で十分です。 

2 番目のパスでは、厳密に以下のすべての限界値の正確な寄与を計算します。`m`。 残りの必要な限界はすべて等しくなければなりません`m`、定義的なプロパティのため$$C(m-1)<S\le C(m).$$Python の整数は、おおよその値まで自動的に処理します。`10^{17}`したがって、オーバーフローの問題は発生しません。
