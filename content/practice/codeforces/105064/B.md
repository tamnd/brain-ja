 ## 問題の理解

 ボブの有効なマークのセットを構築するように求められます。$n$各マークは 0 ～ 2047 の整数ですが、追加の制約が 1 つあります。すべてのマークのビットごとの XOR が指定された値に等しくなければなりません。$x$。 このようなすべての有効な割り当ての中で、マークの平均を最大化したいと考えています。 以来$n$が固定されている場合、平均を最大化することは、すべてのマークの合計を最大化することとまったく同じです。 

したがって、実際のタスクは純粋に組み合わせです。$n$制限された範囲内の数値の場合、XOR が強制的に計算されます。$x$、それらの合計をできるだけ大きくします。 

上限の 2047 は重要です。 これは、すべての数値が 11 ビットの整数であることを意味するため、ビット操作の観点から考えるのが自然です。 また、以来、$n \le 1000$最大 500 のテスト ケースがあり、どのソリューションも$O(t)$あるいは最悪の場合$O(t \log n)$。 全体の検索に関するもの$n$-タプルや大きな状態に対する動的プログラミングは遅すぎます。 

XOR 制約をグローバルに尊重せずに貪欲な構築を試みると、微妙な失敗例が発生します。 たとえば、単純にすべての値を 2047 に設定しようとすると、ローカルで合計が最大化されますが、XOR が固定され、一致しない可能性があります。$x$。 複数の要素を個別に調整する単純な修正では、誤って合計が必要以上に減少する可能性があります。 

もう 1 つのエッジケースは次のような場合です$x = 0$。 その場合、最適解は単にすべての値が 2047 に等しいという可能性があります。$n$均一であるか、わずかに調整されている場合$n$XOR のパリティ効果に応じて奇数になります。 

## アプローチ

 強引な解釈は単純ですが、絶望的です。 全部試してみるのもいいかもしれない$n$-length の値の配列$[0, 2047]$、それらの XOR が等しいかどうかを確認します$x$、最大合計を計算します。 これは探索します$2048^n$可能性は天文学的に大きい$n = 2$, したがって、それは直ちに実行不可能です。 

重要な観察は、各要素ができるだけ大きくなると、つまり 2047 に近づくと合計が最大になるということです。したがって、すべてのコースが 2047 になる構成から開始し、XOR 制約を修正するのに十分な値を最小限に変更します。 

初期配列をすべて 2047 とします。その XOR はパリティによって固定されます。$n$偶数の場合、XOR は 0、それ以外の場合は 2047 です。これを必要な XOR と比較します。$x$。 それらの不一致は価値観です$\Delta$、XOR を「修正」する必要がある量を表します。 

ここで問題は次のとおりです。XOR 補正が正確になるように、いくつかの要素を 2047 年から遠ざけて調整したいと考えています。$\Delta$合計の損失を最小限に抑えながら。 2047 年の値をある値に変更すると、$a$、合計の減少は$2047 - a$。 2047 との XOR は 11 ビットのビット単位の補数のように動作するため、明確な同一性が得られます。値を変更するコストは、まさにその要素に適用される XOR の差です。 

そこで問題を表現することに還元します$\Delta$選択されたいくつかの「差分値」の XOR として、それらの合計を最小化します。 重要な単純化は、複数の補正を使用しても、値の 1 つの補正を使用した場合よりもコストを削減することはできないということです。$\Delta$自体。 複数の XOR コンポーネントへの分解は、総和コストにおいてその直接表現を上回ることはできません。 

したがって、最適な戦略は、サイズの単一補正を適用することです。$\Delta$、または次の場合は何もしません$\Delta = 0$。

 ## アルゴリズムのチュートリアル

 1. すべて 2047 の配列の基本 XOR を計算します。 もし$n$偶数の場合は 0、それ以外の場合は 2047 です。これは、調整前の最適な開始構成を表します。 
2. 不一致値を計算する$\Delta = \text{base\_xor} \oplus x$。 これは、ターゲットに到達するために必要な正確な XOR 補正です。 
3. 調整前の最大可能合計を計算します。$2047 \cdot n$。 これは、すべてのコースに 2047 を割り当てることに相当します。 
4. もし$\Delta = 0$、 戻る$2047 \cdot n$。 調整は必要ないので、これはすでに最適です。 
5. それ以外の場合は減算します$\Delta$合計から計算して結果を返します。 これは、XOR を修正する単一の最小コストの修正を実行することに対応します。 

### なぜ効果があるのか

 この構築が機能するのは、各要素が 2047 年からどれだけ逸脱しているかを記録することで、有効な解をすべて 2047 年のベースラインに変換できるためです。これらの逸脱は、必要な修正を正確に組み合わせる XOR コンポーネントのように動作します。$\Delta$。 値によって要素を変更するので、$d$合計を正確に減算します$d$の場合、最適化は XOR が固定された偏差値の合計を最小化することになります。 可能な限り最良の方法は、次の値に等しい単一の偏差を使用することです。$\Delta$, 複数に分割しても合計額を減らすことができないためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, x = map(int, input().split())
        
        base_xor = 2047 if n % 2 else 0
        delta = base_xor ^ x
        
        ans = 2047 * n - delta
        print(ans)

if __name__ == "__main__":
    solve()
```この実装は、単一の補正値への削減の直後に行われます。 唯一の微妙な部分は、次のパリティを使用してベースラインの XOR を正しく計算することです。$n$, 繰り返される同じ数値の XOR は、カウントが奇数か偶数かによってのみ決まるためです。 

配列を明示的に構築することはありません。 すべてがテスト ケースごとの定数時間演算に還元されます。

 ## 特殊なケース

 いつ$n$均等であり、$x = 0$、ベースライン XOR はすでにゼロであるため、修正は必要ありません。 アルゴリズムは計算します$\Delta = 0$そして戻ってきます$2047 \cdot n$, これは、すべてのコースに最高点を割り当てることに相当します。 

いつ$n$奇妙であり、$x = 2047$、ベースライン XOR はすでに 2047 年です。繰り返しになります。$\Delta = 0$したがって、調整は適用されず、ソリューションは最適なままになります。 

いつ$n = 2$、構造は最小限であり、修正は XOR 制約と合計制約の両方に直ちに影響します。 この式は、単一の補正が必要かどうかを引き続き正確に計算し、特別な場合を使用せずに一定時間内にそれを適用します。 

いつ$x$が大きく、2047 に近い場合でも、XOR 補正は依然として 11 ビット以内に制限されるため、最大合計からの減算がオーバーフローしたり、特別な処理が必要になったりすることはありません。
