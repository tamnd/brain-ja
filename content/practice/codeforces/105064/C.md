 ## 解決策
 ## 問題の理解

 各コースには多数の割り当てがあり、インデックスに応じた特別な操作を使用して、単一のコースの値を繰り返し変換できます。 目標は、これらの操作を何度でも適用した後、すべてのコース値の合計を最小化することです。 

この操作は、インデックスに依存するベースに基づいた桁の再編成として最もよく理解されます。 i 番目のコースでは、基数 m = i + 2 を定義します。この演算を値 a に適用するときは、a 内に収まるべき乗 m^k を選択し、除算と m による法を使用して a を 2 つの部分に分割し、位置を入れ替えてそれらの部分を再結合します。 この操作を繰り返すと、数値のさまざまな巡回シフトで基数 m の a の表現を変更できます。 

したがって、問題は、インデックス i ごとに、この桁シフト操作を繰り返し適用した後に a_i から取得できる最小値が何かを決定することになります。 

制約は大きく、すべてのテスト ケースの合計 n は最大 10^5、a_i の値は最大 10^9 です。 これにより、操作ごとのシミュレーションや要素ごとの貪欲な変換の繰り返しが排除されます。 二次関数や要素ごとの対数二乗関数は許容されますが、数値を繰り返し再構築したり状態を調査したりするものは許容されません。 

微妙なエッジ ケースは、a_i が m に比べて小さい場合です。 その場合、モジュロ部分は a_i 自体であり、除算はゼロであるため、演算は何も役に立たない純粋な数字の回転のように動作する可能性があります。 もう 1 つのエッジ ケースは、a_i が正確に m のべき乗である場合です。この場合、k の選択が縮退し、式の単純な解釈が誤った分割につながる可能性があります。 

主な問題点は、この操作が局所的で代数的であるように見えますが、実際には数値の基数 m の桁表現構造の変更に相当することです。 

## アプローチ

 直接的な総当たりアプローチでは、改善が不可能になるまで各インデックスに対して繰り返し操作を適用しようとします。 固定値の場合、各アプリケーションはその構造を変更できるため、到達可能なすべての状態を調査する必要があります。 各状態は桁の分解と k の選択に依存するため、分岐要素は自明ではありません。 最悪の場合、最大 10^9 のサイズの数値が何度も変換される可能性があり、少ないステップ数で収束するという保証はありません。 すべてのテスト ケースで、これは制限時間を簡単に超えてしまいます。 

重要な観察は、変換によって任意の数値が作成されるわけではないということです。 これは、数値の基数 m の桁のマルチセットを保持し、循環アラインメントのみを変更します。 表現

 m^k × (a mod m) + Floor(a / m)

 は、まさに a の基数 m 表現の回転です。ここで、k は最下位桁がどれだけ上にシフトされるかを決定します。 

したがって、各インデックス i について、問題は次のようになります。数値 a_i が与えられた場合、それを基数 m = i + 2 で書き込み、その数字表現のすべての循環回転を考慮し、それらの最小値を取得します。 

これにより、各要素が最大 O(log_m a_i) 個の状態の有限セットに削減されます。 基数 m の桁を 1 回計算し、すべての回転を生成し、それらの数値を評価して、最小値を取得できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース シミュレーション | O(大きい / 予測不可能) | お(1) | 遅すぎる |
 | 基数 m の桁回転列挙 | O(n log a_i) | O(log a_i) | 承認済み |

 ## アルゴリズムのチュートリアル

 異なる位置での操作は相互作用しないため、テスト ケースごとにすべてのインデックスを個別に処理します。

1. n と配列 a を読み取ります。 各位置 i に対して、基数 m = i + 2 を定義します。この基数はインデックスごとに固定されているため、各要素には独自の数値体系があります。 
2. 剰余と m による除算を繰り返して、a_i を基数 m の表現に変換します。 数字は最下位から最上位まで格納されます。 演算はこれらの数字に直接作用するため、この手順は不可欠です。 
3. 数値の基数 m が 1 桁のみの場合、変換によって数値は変更されません。 その場合、この要素の答えは a_i そのものになります。 これは、a_i < m の場合に発生します。 
4. 桁リストのすべての循環ローテーションを生成します。 各回転は、元の操作で異なる k を選択することに対応し、高部と低部の分割が発生する場所をシフトします。 
5. 回転ごとに、基数 m の数値を評価して数値を再構築します。 これらの値の最小値を計算します。 
6. すべてのインデックスの達成可能な最小値を合計します。 

なぜこれが機能するかというと、この演算では数字自体が変更されるのではなく、基数 m での循環配置のみが変更されるからです。 一連の操作は何らかの回転に相当し、すべての回転が達成可能です。 したがって、検索空間はまさに数字ベクトルの巡回置換のセットです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def to_base(x, base):
    digits = []
    while x > 0:
        digits.append(x % base)
        x //= base
    return digits

def value_of(digits, base):
    res = 0
    for d in reversed(digits):
        res = res * base + d
    return res

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        total = 0
        for i in range(n):
            m = i + 2
            x = a[i]
            
            digits = to_base(x, m)
            
            if len(digits) == 1:
                total += x
                continue
            
            best = float('inf')
            k = len(digits)
            
            for shift in range(k):
                rotated = digits[shift:] + digits[:shift]
                val = value_of(rotated, m)
                if val < best:
                    best = val
            
            total += best
        
        out.append(str(total))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```変換関数は、基数 m の桁リストを最下位順序で構築します。これは、モジュロ演算を繰り返した場合の自然な結果と一致します。 回転ステップは、演算定義内のすべての有効な k の選択に対応する、桁サイクルのすべての可能なカット ポイントをシミュレートします。 再構成関数は、回転された各表現を評価して整数形式に戻します。 

よくある落とし穴は、値を再構築するときに数字を正しい順序で解釈する必要があることを忘れることです。 もう 1 つは、実際にはすべての循環シフトが到達可能であるにもかかわらず、1 つの回転のみが重要であると仮定することです。 

## 実用的な例

 n = 3、a = [5, 7, 4] の小さな例を考えてみましょう。 

各インデックスをそれぞれ基底 m = 2、3、4 で処理します。 

i = 1、m = 2、a = 5 の場合、基数 2 では、5 は [1, 0, 1] として表されます。 回転は [1,0,1]、[0,1,1]、[1,1,0] です。 

| 回転 | 基数 2 の値 |
 | --- | --- |
 | 101 | 5 |
 | 011 | 3 |
 | 110 | 6 |

 ベストは3です。 

i = 2、m = 3、a = 7 の場合、基数 3 の表現は [1, 2] です。 回転は[1,2]と[2,1]です。 

| 回転 | 基数 3 の値 |
 | --- | --- |
 | 12 | 5 |
 | 21 | 7 |

 ベストは5です。 

i = 3、m = 4、a = 4 の場合、基数 4 の表現は [0,1] です。 回転は [0,1] と [1,0] です。 

| 回転 | 基数 4 の値 |
 | --- | --- |
 | 01 | 1 |
 | 10 | 4 |

 ベストは1です。 

合計は3+5+1=9となります。 

このトレースは、元の値が異なっていても、各インデックスが桁の回転を通じて個別に最小化され、合計が最終的な答えになることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log_{m} a_i) | 各数値は基数 m に変換され、すべての桁の回転が評価されます。 
| スペース | O(log a_i) | 要素ごとに数字表現を格納します |

 すべての数値の合計桁数は、対数の合計によって制限されます。これは、n が 10^5 まで、a_i が 10^9 までの制限内に十分に収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    def to_base(x, base):
        digits = []
        while x > 0:
            digits.append(x % base)
            x //= base
        return digits

    def value_of(digits, base):
        res = 0
        for d in reversed(digits):
            res = res * base + d
        return res

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        total = 0
        for i in range(n):
            m = i + 2
            x = a[i]
            digits = to_base(x, m)
            if len(digits) == 1:
                total += x
                continue
            best = min(value_of(digits[j:] + digits[:j], m) for j in range(len(digits)))
            total += best
        out.append(str(total))
    return "\n".join(out)

 ## 特殊なケース

 a_i がその基数 m より小さい場合、基数 m の表現は 1 桁になります。 この場合、すべての回転は同一であるため、アルゴリズムは値を変更しないまま正確に保ちます。 たとえば、n = 1、a = [3]、m = 2 の場合、数字は [1,1] となり、回転は可能ですが、改善はありません。 

a_i が正確に m のべき乗である場合 (a_i = 8、m = 2 など)、表現は先頭に 1 が 1 つとその後にゼロが続きます。 回転により、位置に応じて 1、2、4、8 などの値が生成されます。 このアルゴリズムはすべての回転を列挙するため、最小値 (この場合は 1) を正確に取得します。 

数字に多くのゼロが含まれる場合、ゼロを前に移動する回転により、より小さな値が生成されます。 アルゴリズムはすべての回転を明示的に評価するため、これらのケースは特別なケースなしで処理されます。
