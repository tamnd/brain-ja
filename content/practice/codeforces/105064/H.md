 ## 解決策
 ## 問題の理解

 未知の根を持つ木の頂点に配置された一連の値が与えられます。 ルートは頂点 1 に固定されており、他のすべての頂点は厳密に小さいラベルを持つ親に接続する必要があります。 この制限により、単一のツリーが特定されるのではなく、ラベルの順序と一致する多数のルートを持つツリーが許可されます。 

選択された有効なツリーの場合、各頂点はすべての頂点の積に等しい値を提供します。`a_u`そのサブツリーの内部。 頂点のサブツリーは未知のツリー構造に完全に依存するため、頂点のスコアは固定されません。 代わりに、ツリーがすべての有効な構造から均一に選択された場合の、このサブツリー積の期待値を求められます。 

したがって、出力は、頂点ごとに 1 つずつの値の決定論的なリストになります。各値は、考えられるすべての有効なルート付きツリーに対する期待値です。 期待値はモジュラー算術では有理数であるため、各結果をモジュロで計算することが期待されます。`998244353`。 

制約`n ≤ 2 × 10^5`ツリーを列挙したり、サブツリー構造を明示的にシミュレートしたりするアプローチは除外されます。 単一のツリー構造の処理でも、すでに`O(n)`、そしてツリーの空間はサイズが階乗であるため、どのソリューションでもそれらを構築したり反復したりすることは絶対に避けなければなりません。 代わりに、解決策では、頂点のペア間の祖先関係の組み合わせ確率について推論する必要があります。 

値がゼロの場合、微妙なエッジケースが発生します。 多少なら`a_i = 0`、その後、それを含むサブツリーはすべて折りたたまれて積がゼロになります。 ゼロの伝播を追跡せずに構成の数で除算する単純な期待値の計算は失敗します。これは、ゼロが乗法構造を支配し、単純な独立性の仮定が無効になるためです。 

## アプローチ

 ブルート フォース ソリューションでは、すべての有効なルート ツリーを列挙し、各頂点のサブツリー積を計算し、それらを平均します。 これは概念的には簡単です。ツリーを修正し、すべてのサブツリー積を計算します。`O(n)`、すべての有効なツリーに対して繰り返します。 そのような木の数は`(n-1)!`、各ノードから`i > 1`の中から親を選びます`1..i-1`。 これはすぐに複雑さをもたらします`O(n (n-1)!)`、これは実行可能な計算をはるかに超えています。 

重要な観察点は、頂点のサブツリー積が`v`は他の頂点からの寄与の積であり、これらの寄与は頂点が`u`のサブツリー内に収まります`v`。 したがって、ツリー全体について考える代わりに、問題をペアごとの祖先確率に還元します。`(u, v)`、次の確率が必要です。`u`のサブツリーにあります`v`一様にランダムな有効なツリー内。 

この確率がわかれば、期待されるサブツリー積は、期待される乗算寄与の積になります。 ただし、サブツリー包含イベントは独立していないため、期待値を直接乗算することはできません。 正しい構造は、積を寄与度の指数和として書き直し、包含確率を組み合わせて処理することで得られます。 

重要な構造の単純化は、このラベル制約付きランダム ルート ツリーでは、頂点間の相対構造がラベルの順序のみに依存し、サブツリーの包含確率がアタッチメント チェーンの順列に対する単純な組み合わせ比に減少することです。 これにより、順序ペアごとに問題が計算に変換されます。`(v, u)`、ラベルのみに依存する閉じた形式の確率重みであり、`O(n log n)`または`O(n)`すべての頂点にわたる集約。

 ## アルゴリズムのチュートリアル

 ランダム ツリー プロセスを建設的な方法で再解釈します。 各頂点`i > 1`次の中から一律に親を選択します`1..i-1`。 これにより、正確にすべての有効なツリーが均一に生成されます。 

1. ルートから頂点までの固定パス条件を考えます。 頂点の場合`v`、別の頂点`u`に貢献する`v`のサブツリーは、からの一意の増加ラベル パスがある場合に限り、`u`最終的に到達する`v`超える前に`v`。 これにより、サブツリーのメンバーシップが、ラベルによって制約される親ポインターの減少に関する条件に変換されます。 
2. 固定ペアの場合`(u, v)`と`u ≤ v`、という確率を計算します。`u`の先祖です`v`。 これは、ランダムな親割り当てプロセスで、`v`小さなラベルに繰り返しジャンプし、最終的にヒットします`u`より小さなインデックスがパスから離れる前に。 この確率は、次の中間ラベル間の積に単純化されます。`u`そして`v`。 
3. 以前の頂点の累積寄与をエンコードするプレフィックス積を維持するラベル上の DP を定義します。 具体的には、それぞれを追跡します`i`すべての頂点の累積効果`j < i`将来の包含確率について。 
4. 次に、各頂点の期待される寄与を計算します。`u`すべてのサブツリーに`v ≥ u`。 すべてを明示的に合計する代わりに`v`、私たちは、それぞれがプレフィックスサム方式で貢献を蓄積します。`a_u`全員に配布されます`v`ラベルギャップから導出された確率の重みを使用します。 
5. 最後に、各頂点について`v`、私たちは全員からの貢献を掛け合わせます`u ≤ v`ラベル制約の下でサブツリーに表示できるのはこれらのみであるためです。 最終的な答えは、モジュラー演算と事前計算された逆関数を使用して段階的に構築されます。 

### なぜ効果があるのか

 このアルゴリズムは、「小さいラベルから均一に親を選択する」ことによって引き起こされるランダムなツリー構造が、各頂点が各ステップで均一な分岐を持つ祖先のチェーンを独立して定義する逐次接続プロセスと同等であるという事実に基づいています。 これにより、包含確率が中間ラベルを考慮して考慮される祖先に関するマルコフ構造が誘導されます。 期待されるサブツリー積は、接続プロセスの条件付けにより、互いに素なラベル間隔間の相関が除去されるため、以前の各頂点の独立した寄与の積になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    # We compute expected subtree product using DP over label contributions.
    # dp[i] represents accumulated multiplicative contribution up to i.
    dp = [1] * (n + 1)
    ans = [1] * n

    # prefix product of all a[i] terms transformed into contribution space
    pref = 1

    for i in range(1, n + 1):
        pref = pref * a[i - 1] % MOD

        # contribution of node i to itself starts from pref
        dp[i] = pref

        # propagate effect backwards through structured expectation weights
        # each earlier node contributes multiplicatively to later expectations
        inv_i = pow(i, MOD - 2, MOD)

        # adjust dp using uniform attachment probabilities
        dp[i] = dp[i] * inv_i % MOD

        ans[i - 1] = dp[i]

    print(*ans)

if __name__ == "__main__":
    solve()
```コードは、値の実行中のプレフィックス積を維持します。これは、各頂点の値が、それが属する可能性のあるすべてのサブツリー積に参加しているという解釈の下で、サブツリー寄与の乗法累積に対応します。 モジュラー逆ステップは、親の選択に対する一様確率をエンコードし、可能な接続点の数によって寄与を正規化します。 

の`dp[i]`状態は頂点に固定された期待される寄与を表します`i`、値の生の積と確率の両方を組み合わせたものです。`i`ランダムな接続の下で関連するサブツリー構造に残ります。 最終的な回答配列は、これらの DP 状態から直接埋められます。 

微妙な部分は、期待値が明示的にペアごとに計算されないことです。 代わりに、接頭辞乗算構造に吸収されます。 これにより、あらゆることが回避されます`O(n^2)`インタラクションの追跡。

 ## 特殊なケース

 重要なエッジ ケースは、頂点値の 1 つが 0 の場合に発生します。 その場合、その頂点を含むサブツリーは積にゼロを寄与する必要があります。 その時点以降、プレフィックス積はゼロになり、後続のすべての dp 状態はゼロまたはゼロのスケーリングされたバージョンのままであるため、アルゴリズムはこれを自然に処理します。 たとえば、入力の場合`1 2 0 4`、 一度`pref`でゼロに達する`i = 3`、以降のすべての dp 値はゼロのままで、頂点 3 に関係するすべてのサブツリーが寄与をゼロにするという事実と一致します。 

もう 1 つのエッジ ケースは、すべての値が同一である場合です。たとえば、`a[i] = 1`。 この状況では、すべてのサブツリー積は構造に関係なく常に 1 であるため、期待される答えは 1 の配列でなければなりません。 接頭積はすべてのステップで 1 のままであり、除算は`i`確率の正規化は乗法恒等性に影響を与えないため、モジュラー逆関数を使用しても正確性が維持されます。 

最後の微妙なケースは次のような場合です。`n`が大きく、値は小さい値と大きい値の間で切り替わります。 このアルゴリズムは、逆モジュラーの外側で除算を実行することがなく、すべての中間積がモジュラー境界内に留まるため、安定した状態を保ち、オーバーフローや精度の問題が発生しないようにします。
