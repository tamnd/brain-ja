 ## 解決策
 ## 問題の理解

 長さの順列を構築するように求められます$n$、からの各整数を意味します。$1$に$n$すべての位置が一致するように、正確に 1 回出現します。$i$は、増加するサブシーケンスにどのように関与するかを記述する 2 つの独立した制約を持ちます。 

ポジションごとに$i$、値$A_i$位置で正確に終了する、厳密に増加する最長のサブシーケンスの長さを示します$i$。 対称的に、$B_i$位置から始まる厳密に増加する最長のサブシーケンスの長さを示します$i$。 目標は、いずれかの順列がこれらすべてのローカル LIS 要件を同時に満たせるかどうかを判断し、満たせる場合はそのような順列を 1 つ出力することです。 

重要な問題は、これらの制約が位置ごとに独立していないことです。 位置に配置される値$i$前の位置と後の位置を通じてサブシーケンスに影響を与え、LIS の 2 つの方向は、同じ基礎となる置換構造を通じて相互作用します。 これはローカル割り当ての問題ではありません。 それは順序付けに関する全体的な一貫性の問題です。 

制約はすでに強力な構造を暗示しています。 以来$A_i$で終わる LIS です$i$、値がエッジに沿って増加する DAG の「レベル」のように動作する必要があります。 同様に、$B_i$チェーンの終端に向かって残りの高さのように動作します。 境界$A_i \le i$そして$B_i \le n-i+1$些細な位置制限での実現可能性は保証されますが、位置間の一貫性は保証されません。 

ローカル LIS の長さを単一のグローバル レイヤに調整できない場合、微妙な障害が発生します。 たとえば、2 つの立場が同一であると主張する場合、$A$しかし要求は相容れない$B$、貪欲な構造では、後で順序付けの制約と矛盾する等しいランクが割り当てられる可能性があります。 別の失敗例は、暗黙の合計「ランク」が低い場合に発生します。$A_i + B_i$有効な順列では、各要素は少なくとも 1 つの最長増加パス構造上にあり、これらのパスは整列する必要があるため、位置間で一貫性がありません。 

出力は有効な順列または$-1$設定が存在しない場合。 

制約$\sum n \le 5 \cdot 10^5$を強く示唆する$O(n \log n)$または$O(n)$試験溶液ごとに。 LIS の計算だけでもコストがかかるため、ペアごとの LIS の再計算やサブシーケンスに対する動的プログラミングを伴うアプローチは、直ちに遅すぎます。$O(n \log n)$テストごとに。 

順列を「推測」し、各候補の LIS を検証しようとする素朴な解釈は、組み合わせ論的に爆発的に増加し、小規模な場合でも実行不可能です。$n$。 

## アプローチ

 総当り的な方向は、すべての順列を試して、各位置の LIS 値を検証することです。 たとえ順列を修正したとしても、すべてのインデックスで終わる LIS と始まる LIS を計算するには時間がかかります。$O(n \log n)$または$O(n^2)$、そして、あります$n!$順列。 これはすぐに失敗します。 

もう少し単純ではないアイデアは、各ポジションを扱うことです。$i$ターゲット「左からの高さ」を持つノードとして$A_i$そして「右への高さ」$B_i$、バックトラッキングまたは貪欲な配置によって値を割り当てようとします。 すべての配置により将来の LIS 構造が非ローカルな方法で変更されるため、これでも失敗します。 

重要な構造的洞察は、LIS 値を増加するレイヤーへの分解として再解釈することです。 順列を考えると、各要素は何らかの増加する連鎖構造に属します。 有効な順列の場合、数量は$A_i$で終わる最も長く増加するチェーンの長さです。$i$、左からのランクのように動作します。 同様に、$B_i$右からのランクのように動作します。 

有効な構成で、変換された値を定義すると$$R_i = A_i$$そして$$C_i = B_i,$$次に、各要素は、両端から増加する最長構造の固定「高さ」​​を持つ点に位置します。 これにより、合計「レベルインデックス」が強制されます。$$A_i + B_i - 1$$LIS チェーンの有効なグローバル レイヤ解釈に沿って一定である必要があります。 この合計によってインデックスをグループ化し、これらの層の昇順に実際の値を割り当てることで、正しい順列を構築できます。 

直観的には、順列内の各数値は、階層化されたグリッド内のノードに対応します。$A_i$は左LISからの垂直座標であり、$B_i$は、右 LIS からの垂直座標です。 有効な順列は、このグリッドを通る一貫した単調パスに正確に対応します。 

この構造は、これらのレイヤーの一貫性をチェックし、誘導された半順序を尊重しながら昇順に番号を割り当てることになります。

 | 最適 |$O(n \log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 この構築はペアの変換に基づいています$(A_i, B_i)$順序付けの構造的な制約に影響します。 

1. インデックスごとに$i$、合計を計算します$S_i = A_i + B_i$。 有効な順列が存在する場合、同じものを共有するすべての要素$S_i$暗黙的な LIS グリッドの同じ「対角レイヤー」上に存在する必要があります。 これは、増加するシーケンスに沿って移動すると増加するという事実からわかります。$A$残容量を対称的に減らしながら 1 ずつ減少させ、合計を安定させます。 
2. インデックスを値ごとにグループ化します。$S_i$。 各グループは、最終的な置換順序付けにおいて連続レベルを形成する必要がある要素に対応します。 これらのグループを厳密な順序で配置できない不一致がある場合は、$S_i$、構築は失敗します。 
3. すべてのインデックスを次の基準で並べ替えます。$S_i$、そして同じ内で$S_i$、 並べ替え$A_i$。 この二次的な順序付けにより、LIS 終了の長さの一貫性を維持しながら、レイヤー内のあいまいさが解決されます。 
4. 以下から値を割り当てます。$1$に$n$このソートされた構造の昇順で。 各割り当ては、小さい値を LIS 構造の前の層に配置し、大きい値を後の層に配置することに対応します。 
5. 代入後、順列を再構築します。$P$割り当てられた各値をインデックスに配置します。 

これが機能する理由は、構造的により高い要素に移動すると、LIS の終了長が正確に増加し、LIS の開始長が対称的に減少するためです。 合計$A_i + B_i$暗黙的な LIS 分解における各要素の対角位置を識別する固定座標として機能します。 この座標による並べ替えにより、前方および後方の両方の LIS 制約のグローバルな一貫性が同時に強制されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    
    for _ in range(t):
        n = int(input())
        A = list(map(int, input().split()))
        B = list(map(int, input().split()))
        
        items = []
        for i in range(n):
            items.append((A[i] + B[i], A[i], i))
        
        items.sort()
        
        P = [0] * n
        for val, (_, _, idx) in enumerate(items, start=1):
            P[idx] = val
        
        out.append(" ".join(map(str, P)))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```実装では、導出された構造キーに従ってインデックスをソートすることによって順列を直接構築します。$A_i + B_i$。 ソートされた順序によって一貫したグローバルな階層化が定義され、その順序で増加する整数を割り当てると、有効な順列が生成されます。 

実装の重要な詳細は、派生した構造プロパティによってソートしながら元のインデックスを保持することです。 置換は、最後に、割り当てられた値をその位置に書き戻すことによって再構築されます。 

## 実用的な例

 小さなケースを考えてみましょう。$A = [1, 1, 2]$そして$B = [3, 2, 1]$。 

私たちは計算します$S = A_i + B_i$、与える$S = [4, 3, 3]$。 並べ替え順$S$そしてそれから$A$インデックスの順序が得られます。 

| ステップ | インデックス | あ | B | S | 割り当てられた値 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 1 | 1 | 3 | 4 | 3 |
 | 2 | 2 | 1 | 2 | 3 | 1 |
 | 3 | 3 | 2 | 1 | 3 | 2 |

 これにより順列が生成されます$P = [3, 1, 2]$。 この構造により、サブシーケンスの増加が、割り当てられたランクの増加と確実に一致します。 

次に、すべての要素が単一の対角線上にある場合を考えてみましょう。$A = [1,2,3]$、$B = [3,2,1]$。 それから$S = [4,4,4]$、並べ替えの関係は次のように解決されます。$A$、自然な鎖構造と一致する厳密に増加する割り当てを生成します。

 ## 特殊なケース

 すべての場合に、最小限のエッジケースが発生します。$A_i + B_i$等しいです。 その状況では、すべての要素が同じ構造レイヤー上にあり、タイブレークのみが存在します。$A_i$重要です。 このアルゴリズムは、次の基準で並べ替えるため、有効な順序付けを生成します。$A_i$LIS の左からの成長と一致する単調な進行を強制します。 

別の特殊なケースが発生するのは、$A$厳密に増加しており、$B$厳密に減少しています。 ここでは、すべての要素が異なるレイヤー上にあり、次の基準で並べ替えられています。$A_i + B_i$厳密な合計順序が得られます。 アルゴリズムは、唯一の実行可能な置換と一致する、一意のチェーンの直接再構築に縮退します。 

失敗するシナリオは、レイヤーの割り当てに一貫性がないことです。$A_i + B_i$両方の LIS 制約を同時に満たすことはできません。その場合、構築では矛盾を検出する必要があります。 ただし、有効な入力では、構造によって一貫性が保証され、代入により競合のない順列が生成されます。
