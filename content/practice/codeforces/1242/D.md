 ## アルゴリズムのチュートリアル

 このプロセスは、連続するサイズのグループ内の整数を消費するものとして解釈されます。$k$、各グループの後に 1 つの追加要素が挿入されます。 

数字がどのように配置されるかを追跡してみましょう。 

1. 各ラウンドは次のラウンドを消費します$k$未使用の整数。貪欲な「最小欠損」ルールにより常に連続しています。 したがって、ラウンド 1 では、$1 \dots k$、ラウンド 2 の使用$k+1 \dots 2k$、 等々。 

これは重要な構造の単純化です。合計が挿入される前に、欠落しているセットによってブロック内にギャップが生じることはありません。 
2. から始まるブロックを消費した後$(r-1)k + 1$そして終わる$rk$、シーケンスはそれらを追加します$k$数値を順番に並べ、その後にその合計を表示します。 したがって、各ラウンドが貢献します$k+1$シーケンスに位置を合わせます。 
3. 与えられた数値に対して$n$、そのブロックインデックスを決定します。$$r = \left\lceil \frac{n}{k} \right\rceil$$これは、サイズの完全なブロックが何個あるかを示します。$k$前に来るか含める$n$。 
4. そのブロック内で、そのオフセットを計算します。$$p = (n-1) \bmod k$$これがその中での位置です。$k$ブロックの要素。 
5. ブロックの前の各フルブロック$r$貢献する$k+1$要素をシーケンスに追加します。 したがって、ブロックの前のすべての数字$r$貢献する：$$(r-1)(k+1)$$6. インサイドブロック$r$、番号$n$オフセットで表示されます$p$, そこで追加します$p+1$インデックスに。 
7. 各ブロックの sum 要素は常にブロックの後に現れるため、個々の整数の位置には影響しません。$k$そのブロックの整数。 後の要素を均一にシフトするだけであり、すでに$(k+1)$ブロック構造ごとに。 

### なぜ効果があるのか

 不変条件は、各ラウンドの開始時に、未使用の数値が正の整数の連続した接尾辞を形成することです。 これは、次に進む前に常に利用可能な最小の数値を完全に消費するため当てはまります。 その結果、各ラウンドは正確に次のラウンドを取ることを強制されます。$k$連続した整数。 sum 要素は常にこれらの後に追加されるため、$k$値の場合、将来未使用の整数の順序が乱されることはありません。 これにより、厳密なブロック構造が保証され、シミュレーションなしで直接インデックスを作成できるようになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n, k = map(int, input().split())

        # block index (1-based)
        r = (n - 1) // k + 1

        # position inside block
        p = (n - 1) % k

        # each previous block contributes k + 1 elements
        ans = (r - 1) * (k + 1) + (p + 1)

        out.append(str(ans))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この解決策は、ブロック構造を直接計算することに依存しています。 整数の除算`(n - 1) // k`どのサイズのグループを識別するか$k$その番号が属するのに対し、`(n - 1) % k`そのグループ内での位置を決定します。 最終的なインデックスは、以前の完全なグループの数に次の値を乗算して取得されます。$k+1$、各グループが貢献するため、$k$要素に 1 つの合計要素を加えてから、グループ内のオフセットを追加します。 

唯一の微妙な点は、オフバイワンの処理です。 使用する`(n - 1)`の代わりに`n`正確に割り切れる数値を正しくグループ化します。$k$そうしないと、誤って次のブロックにこぼれてしまいます。

 ## 特殊なケース

 重要なエッジケースの 1 つは次のような場合です。$n$は正確に割り切れます$k$、 のような$n = k, 2k, 3k$。 このような場合、使用すると、$n // k$調整を行わないと、ブロックが誤って分類されます。 表現$(n - 1) // k$正しく配置する$n = k$間違って新しいブロックを開始するのではなく、最初のブロックに挿入します。 

もう一つのケースは次のような場合です。$k$よりも大きいです$n$。 その場合、推論全体が 1 つのブロックに崩壊し、答えは単純にそれを反映する必要があります。$n$最初に登場する$k$sum 要素が関連する前のシーケンスの位置。 この式は自然にこれを処理します。$r = 1$そして以前のブロックは貢献しません。 

最後に、非常に大きな値$n$すべての計算は 64 ビット整数の範囲内にとどまるため、数値の不安定性は生じません。 必要な唯一の注意は、中間乗算でのオーバーフローを避けることです。これは Python では安全ですが、低レベル言語では 128 ビットの算術演算が必要になります。
