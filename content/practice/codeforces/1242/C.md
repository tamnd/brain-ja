 ## 解決策
 ## 問題の理解

 いくつかのコンテナーが与えられ、それぞれのコンテナーには個別の整数のマルチセットが保持されます。 1 つの操作は 1 回だけ実行されます。すべてのコンテナーから値を 1 つだけ選択し、それらの選択した値をコンテナーに再分配して、最終的に各コンテナーの要素数が最初と同じになるようにする必要があります。 選択した値は、元のコンテナまたは別のコンテナに戻すことができます。 

目的は、再配布後にすべてのコンテナの要素の合計がまったく同じになるように、これらの値を選択して再割り当てする方法があるかどうかを判断することです。 

主な難点は、この操作ですべてのコンテナが結合されることです。 選択された各値は、元のコンテナから寄与を削除し、ターゲット コンテナに追加するため、最終的な効果は、グローバルにバランスを取る必要がある合計調整のシステムになります。 

コンテナーの数という点では制約は小さく、k は最大 15 ですが、コンテナーあたりの合計要素数という点では潜在的に大きくなり、ボックスあたり 5000 に達します。 これにより、要素の完全な割り当てを列挙したり、個々の数値に対するすべての可能性をシミュレートしようとするアプローチは即座に除外されます。 有効なアプローチでは、要素ごとではなくボックスごとに状態を圧縮する必要があります。 

素朴だが重要なエッジケースは、わずかに異なる 1 つのボックスを除いてすべての数値がすでにバランスが取れている場合に発生します。 不注意な解決策では、すべてのボックスで同じインデックスを選択するか、極端に一致させることが機能すると想定する可能性がありますが、再配布制約がグローバルであり、循環依存関係が重要であるため、それは失敗します。 

## アプローチ

 ブルートフォース解釈では、ボックスごとに 1 つの選択された要素と 1 つの宛先ボックスを割り当て、再分配をシミュレートして、結果として得られるすべての合計が一致するかどうかを確認します。 これにより、おおよそ n₁ × n₂ × ... × n_k 通りの選択が可能になりますが、組み合わせの数が k と要素数の両方で指数関数的に増加するため、中程度の k の場合でも実行不可能です。 

最初にボックスごとに 1 つの要素を選択することに注意を限定したとしても、依然としてボックスごとに k 個の選択肢があるため、最悪の場合でも約 (5000)^15 個の可能性があり、これは天文学的に大きくなります。 

重要な洞察は、視点を逆転させることです。ボックスごとに要素を個別に選択することを考えるのではなく、最終的な合計をすべて等しくするために、選択された各要素が「何を望んでいる」かを追跡します。 ターゲット合計が S であるとします。ボックス i から要素 x を選択すると、ボックス i は x をグローバルな再分配に寄与しており、最終的な合計が S になるように他の要素 y を受け取ることで補償する必要があると事実上言えます。 

これにより、有向構造が作成されます。選択された各要素は、元のボックスから、そこで必要な値によって決定される宛先ボックスへの移動を定義します。 各ボックスは出力要素を 1 つだけ選択する必要があるため、構造はボックス上の関数グラフになります。 問題は、すべてのサイクルが有効で、すべてのボックスをカバーする一貫した割り当てを見つけることに帰着します。 

k が小さい (≤ 15) ため、ビットマスクを使用してボックスのサブセットを表し、有効なサイクルの構築を試みることができます。 開始要素ごとに、「必要な値」→「その値を含むボックス」を繰り返しマッピングすることでサイクルを構築しようとします。 開始ボックスに戻り、競合することなく一連のボックスをカバーできれば、有効なサイクル コンポーネントが得られます。 次に、サブセット上の DP を使用してすべてのボックスをカバーするサイクルを結合します。 

これにより、値の制約によって引き起こされる有効なサイクルへのボックスの分割を検出するという問題が発生しますが、これは 2^k 状態で管理可能です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | n と k の指数 | O(1)-O(n^k) | 遅すぎる |
 | サイクル + ビットマスク DP | O(k · 2^k) | O(2^k) | 承認済み |

 ## アルゴリズムのチュートリアル

私たちは 3 つの概念フェーズでソリューションを構築します。各値の遷移の実現可能性を計算し、すべての有効なサイクルを構築し、サブセット DP を使用してそれらを結合します。 

1. すべての数値の合計とボックスの総数を計算します。 解が存在する場合、すべての最終的なボックスの合計は単一の値 S (total_sum / k) に等しくなければなりません。 total_sum が k で割り切れない場合、解が存在しないことがすぐにわかります。 このステップにより、後で不必要な構築が回避されます。 
2. すべてのボックス i のすべての値 x について、x が選択された場合にどの値 y をボックス i に入れる必要があるかを計算します。 必要な値は y = S - (sum[i] - x) です。 この方程式は、x を削除して y を挿入した後、ボックス i の合計が S になることを強制することで得られます。 
3. すべての値からその場所 (どのボックスに属するか) へのマッピングを構築します。 すべての値は異なるため、この検索は一意で効率的です。 
4. 開始ペア (i、x) ごとに、チェーンの構築を試みます。 ボックス i を訪問済みとしてマークし、必要な値 x から開始します。 どのボックスに x が含まれているか (ボックス j など) を特定し、バランス方程式を満たすためにボックス j からどの値を取得する必要があるかを決定します。 このプロセスを継続して、ボックス上に有向パスを形成します。 
5. このトラバーサル中に、開始ボックスではないボックスに再度アクセスしたり、どのボックスにも存在しない値に遭遇した場合、チェーンは無効になります。 開始ボックスに正確に戻り、訪問したセットがサイクルを形成する場合、これを (値, 宛先ボックス) の選択されたマッピングとともに、ボックスのサブセットをカバーする有効なサイクルとして記録します。 
6. 参加しているボックスのビットマスクによってインデックス付けされたすべての有効なサイクルを保存します。 
7. ボックスのサブセットに対して動的プログラミングを使用します。 dp[mask] は、マスクを有効なサイクルに分割できるかどうかを示します。 マスクを反復処理し、ビットマスクが素であるサイクルを使用してマスクを拡張しようとします。 親ポインタは再構築の選択肢を保存します。 
8. dp[(1 << k) - 1] が false の場合は、No を出力します。そうでない場合は、選択されたサイクルを再構築し、ボックスごとに、選択された値とその宛先ボックスを出力します。 

なぜ効果があるのか

 有効な各サイクルは、サイクル内のすべてのボックスがバランス方程式を 1 回だけ満たす合計転送の閉じたシステムをエンコードします。 各ボックスは厳密に 1 つの値を提供および受信するため、ボックスあたりの正味の変化は S に対してゼロになります。DP はサイクルが互いに素であり、集合的にすべてのボックスをカバーすることを保証するため、すべてのボックスには 1 つの出力選択肢が割り当てられ、元の制約が満たされます。 矛盾があるとマッピングまたはクロージャー条件が壊れるため、無効な構成はサイクル検証ステップを通過できません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    k = int(input())
    boxes = []
    total_sum = 0

    value_to_box = {}

    for i in range(k):
        arr = list(map(int, input().split()))
        n = arr[0]
        vals = arr[1:]
        s = sum(vals)
        boxes.append(vals)
        total_sum += s
        for v in vals:
            value_to_box[v] = i

    if total_sum % k != 0:
        print("No")
        return

    target = total_sum // k

    need = {}
    for i in range(k):
        s = sum(boxes[i])
        for x in boxes[i]:
            need[(i, x)] = target - (s - x)

    from collections import defaultdict

    cycles = defaultdict(list)

    # try to build cycles starting from each (i, x)
    for i in range(k):
        for x in boxes[i]:
            start = (i, x)
            used_mask = 0
            assignment = {}
            cur_i = i
            cur_val = x

            visited = {}

            ok = True
            while True:
                if cur_i in visited:
                    if cur_i == i:
                        break
                    ok = False
                    break

                visited[cur_i] = cur_val
                used_mask |= (1 << cur_i)

                nxt_val = need[(cur_i, cur_val)]
                if nxt_val not in value_to_box:
                    ok = False
                    break

                nxt_i = value_to_box[nxt_val]

                assignment[cur_i] = (cur_val, nxt_i)

                cur_i, cur_val = nxt_i, nxt_val

            if ok and cur_i == i:
                cycles[used_mask].append(assignment)

    dp = [False] * (1 << k)
    parent = [None] * (1 << k)
    dp[0] = True

    for mask in range(1 << k):
        if not dp[mask]:
            continue
        for cmask, lst in cycles.items():
            if mask & cmask:
                continue
            new_mask = mask | cmask
            if not dp[new_mask]:
                dp[new_mask] = True
                parent[new_mask] = (mask, cmask, lst[0])

    if not dp[(1 << k) - 1]:
        print("No")
        return

    res = {}

    mask = (1 << k) - 1
    while mask:
        prev_mask, cmask, assign = parent[mask]
        for i, (val, dst) in assign.items():
            res[i] = (val, dst + 1)
        mask = prev_mask

    print("Yes")
    for i in range(k):
        v, p = res[i]
        print(v, p)

if __name__ == "__main__":
    solve()
```この実装では、最初にグローバル ターゲットの合計を計算し、値からその所有ボックスまでの高速ルックアップを構築します。 次に、開始要素候補ごとに、ボックスごとの目標合計条件を強制することによって引き起こされる必要な値の遷移を定義します。 

サイクル構築ループは最もデリケートな部分です。 「必要な値→それを含む実際のボックス」に従ってボックスからボックスへの移動をシミュレートし、訪問した各ボックスの出力選択を記録します。 訪問された構造により、最初に戻るときにのみクロージャーを検出することが保証され、偶発的な複数サイクルのマージが防止されます。 

マスク上の DP により、すべてのボックスを正確に 1 回カバーする、一貫した素のサイクルのセットが確実に選択されます。 再構築では、保存されている親ポインタを使用して、1 つの有効な割り当てを回復します。

 ## 特殊なケース

 重大なエッジケースは、合計が k で割り切れない場合です。 このような状況では、統一されたターゲットが存在しないため、サイクルを構築しようとする試みは無意味になります。 アルゴリズムは、構造計算の前に割り算をチェックすることにより、これを即座に処理します。 

もう 1 つの微妙なケースは、値がどのボックスにも存在しない必要な値を指している場合に発生します。 サイクル シミュレーション中に、これによりマッピング ステップが中断され、アルゴリズムは継続を強制するのではなく候補サイクルを正しく拒否します。 

最後の重要なケースは、部分的なサイクルが存在するが、すべてのボックスをカバーしていない場合です。 DP は、ビットマスク 2^k - 1 の完全なカバレッジのみが有効であるとみなされるため、そのような部分構造が誤って受け入れられないことを保証します。
