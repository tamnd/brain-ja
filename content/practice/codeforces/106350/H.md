 ## 解決策
 ## 問題の理解

 私たちには一列の敵が与えられており、それぞれがプラスの強さを持っています。 それぞれのクエリに対して、ザグロルは初期パワーの剣から始めて、できるだけ多くの敵を倒そうとします。 ルールはシンプルですが少し変わったもので、敵と戦う順番は自由ですが、敵を倒すには現在の剣の力がその敵の強さ以上でなければならず、倒した後はその強さだけ剣の力が永久に減少します。 

各クエリは独立しています。つまり、同じ敵のリストと新しい初期剣のパワーで常に新たにスタートします。 タスクは、クエリごとに、最適な順序を選択して倒すことができる敵の最大数を計算することです。 

ルールに隠された重要な構造は、力のある敵を倒すたびに、$a_i$、私たちは永久に予算を削減します$a_i$。 これにより、問題は、選択された各項目が初期電力の一部を消費する予算編成プロセスに変わります。 

制約 (最大$10^5$敵と$10^5$クエリ、最大値$10^9$) 順列またはサブセットに対するクエリごとのシミュレーションを直ちに除外します。 クエリごとに 2 次であっても大きすぎ、$O(n \log n)$クエリごとに境界線に達する可能性があります。 各クエリに対数時間で応答できるようにする前処理のアイデアが必要です。 

いくつかの特殊なケースに注目する価値があります。 

すべての敵の戦力が初期戦力よりも大きい場合、答えはゼロになります。 例えば敵に対して$[5, 6, 7]$そして$x = 3$、戦闘は不可能です。 

すべての敵が小さいにもかかわらず、その数が多い場合、欲張った戦略が順序に依存しているように見える可能性があります。 たとえば、$[4, 1, 3]$そして$x = 5$、順序が異なると結果が変わるように見えるかもしれませんが、実際には、構造を正しく解釈すると、一貫した最適な選択が強制されます。 

より微妙なケースは、大きな敵を早い段階で選択し、後で複数の小さな敵をブロックする場合です。 例えば、$[6, 1, 1, 1]$と$x = 7$: 最初に 6 個を選択すると、柔軟性があまりにも低くなりますが、最初に小さいものを選択すると、より多くの合計キルが可能になります。 これは、順序が重要であることを示唆していますが、それは非常に制御された方法で行われます。 

## アプローチ

 ブルートフォース解釈では、敵のすべてのサブセットと各サブセットのすべての可能な順序を試し、所定の順序がべき乗則の下で有効かどうかをシミュレートします。 順列を無視してサブセットのみをチェックしたとしても、依然として次のような問題に直面します。$2^n$可能性があり、各シミュレーションには直線的な時間がかかります。 これはまったく実現不可能です。 

重要な観察は、注文が実際には私たちの管理下にあり、減少する予算にどれだけ多くのアイテムを「適合」できるかを最大化したいということです。 選択された各敵は、利用可能な合計パワーから正確に独自のパワーを消費します。各ステップの制約は、残りの予算を決して超えないようにすることと同じです。 

敵のサブセットを決めた場合、最善の戦略は、強さの増加順に戦うことです。 これにより、大きな値の初期段階で電力を浪費することがなくなり、実現可能性が中間の変動ではなく合計にのみ依存することが保証されます。 この順序では、条件は単純になります。$k$敵の合計は以下を超えてはなりません$x$。 

したがって、問題は、要素の合計が最大で以下になるように、できるだけ多くの要素を選択することになります。$x$。 カウントを最大化するには、常に小さい要素を最初に取得する必要があります。これは、小さい要素のほうがコストが少なく、より多くの要素を適合できるためです。 これにより、問題はソートとプレフィックス合計配列の構築に変換されます。 

各クエリは次のようになります: 累積合計が超過する前に最小の要素をいくつ取得できるか$x$、プレフィックスの合計に対する二分探索を使用して答えることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | サブセットと順序に対するブルート フォース |$O(n! \cdot n)$それより悪い |$O(n)$| 遅すぎる |
 | ソート + プレフィックス合計 + 二分探索 |$O(n \log n + q \log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 敵の強さの配列を降順でない順に並べ替えます。 これにより、常に最も安価な敵を最初に考慮することが保証され、これはカウントを最大化するために不可欠です。 
2. 各位置がそのインデックスまでのすべての敵の合計強さを格納するプレフィックス合計配列を構築します。 これにより、最も弱い敵を何体でも倒す場合のコストをすばやく計算できます。 
3. 初期検出力を持つ各クエリについて$x$、プレフィックス合計配列に対して二分検索を実行して、最大のインデックスを見つけます。$k$最初の合計が$k$敵はせいぜい$x$。 
4. 出力$k$これは、利用可能なパワーを超えずに倒すことができる敵の最大数を表すため、そのクエリの答えとして使用されます。 

ここで二分探索が機能する理由は、プレフィックスの合計が厳密に増加しているため、実行可能性は true から false に 1 回だけ遷移するためです。 

### なぜ効果があるのか

 受け入れたい敵の数を決めたら、有効な命令は、残りのパワーが次に選択した敵を下回らないという制約を尊重する必要があります。 昇順に並べ替えると、各ステップでその段階で可能な限り最小の利用可能なコストが消費されるため、最も厳しい制約が常に最後に満たされることが保証されます。 これにより、シーケンシャル条件が 1 つのグローバル条件に折りたたまれます。つまり、選択された要素の合計が開始べき乗を超えてはなりません。 すべての値が正であるため、使用可能な最小の要素を最初に選択することから逸脱すると、適合できる項目の数が減少するだけであり、増加することはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))
a.sort()

# prefix sums
pref = [0] * n
pref[0] = a[0]
for i in range(1, n):
    pref[i] = pref[i - 1] + a[i]

q = int(input())
out = []

def upper_bound(x):
    lo, hi = 0, n - 1
    ans = -1
    while lo <= hi:
        mid = (lo + hi) // 2
        if pref[mid] <= x:
            ans = mid
            lo = mid + 1
        else:
            hi = mid - 1
    return ans + 1

for _ in range(q):
    x = int(input())
    out.append(str(upper_bound(x)))

print("\n".join(out))
```コードはまず配列を並べ替えて、より弱い敵がより強い敵の前に考慮されるようにします。 プレフィックス合計配列は「k 人の敵を連れて行けるか?」を変換します。 との単一の比較にまとめる$x$。 二分検索では最大の有効なプレフィックスが検索され、インデックスに 1 を加えた値がカウントに変換されて返されます。 

実装でよくある落とし穴は、答えはインデックスではなくカウントであることを忘れることです。 もう 1 つは、最小の要素でさえ大きすぎる場合の処理​​を誤っていることです。この場合、関数は、$-1 + 1$調整。

## 複雑さの分析

| スペース |$O(n)$| プレフィックス合計配列には、敵ごとに 1 つの値が格納されます。

                lo = mid + 1

        x = int(input())

 ## 特殊なケース

 すべての要素がクエリ能力を超えると、プレフィックス合計配列は上から始まります。$x$、バイナリ検索は正しく返します$-1$、これはゼロに変換されます。 たとえば、$[10, 20]$そして$x = 5$、検索では有効なプレフィックスが見つかりません。 

配列に多数の小さな要素が含まれ、その後に大きな外れ値が続く場合。$[1, 1, 1, 1, 100]$、アルゴリズムは、小さいクエリの大きな要素を当然無視します。これは、大きな要素が並べ替えの後に最後に配置され、十分に大きな要素に対してのみ関連するためです。$x$。 

いつ$x$非常に大きい場合、二分検索では常に返されます$n$また、プレフィックスの合計には Python 整数が使用されるため、アルゴリズムはオーバーフローの問題なくすべての要素を正しくカウントします。
