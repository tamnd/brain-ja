 ## 解決策
 # 問題の理解

 この問題では、ボックスの列について説明します。 いくつかのボックスにはモハメドが含まれており、次のように表されます。`1`、空のボックスは次のように表されます。`0`。 モハメッドは、最終的な集合場所として 1 つのボックスを選択し、現在別のボックスにいるすべてのモハメッドをその選択したボックスに移動したいと考えています。 モハメドをあるボックスから隣接するボックスに移動するには 1 回のスワップが必要となるため、移動距離は`d`箱のコスト`d`操作。 タスクは、考えられるすべての宛先ボックスに対して必要なスワップの最小数を見つけることです。 

入力には、ボックスの数と、ボックスの現在の状態を説明するバイナリ文字列が含まれます。 出力は可能な限り最小の総移動コストです。 

制約は、すべての目的地をチェックしたり、移動を繰り返しシミュレートしたりすることを排除するように設計されています。 あれば`n`ボックスと`n`サイズが大きくなる可能性があるため、すべての宛先を試して文字列全体をスキャンするソリューションには時間がかかります`O(n^2)`動作が遅すぎます。 各ボックスが一定の回数だけ処理される方法が必要です。 

主なエッジケースは、モハメドがいないポジションや、モハメド全員がすでに揃っている列から発生します。 不注意な実装では、宛先にはモハメッドが含まれている必要があると想定される可能性がありますが、最適な宛先は空のボックスである可能性があります。 

例えば：```
5
00100
```正しい出力は次のとおりです。```
0
```すでにモハメドが含まれている中央のボックスを選択する場合は、移動する必要はありません。 空いている位置だけをチェックしたり、端への移動だけを考慮したりする方法は失敗します。 

別の例:```
6
100001
```正しい出力は次のとおりです。```
5
```中央のボックスを選択するとコストが大きくなりますが、どちらかのエンドポイントを選択すると、1 つの Mohamed ボックスが 5 つ移動し、もう 1 つはすでに存在したままになります。 距離ではなくモハメッドの数だけをカウントする単純なアプローチでは、実際のコストを見逃してしまいます。 

## アプローチ

 簡単な解決策は、考えられるすべての宛先ボックスを試してみることです。 選んだ目的地に向けて`i`、文字列全体をスキャンし、ボックスに Mohamed が含まれるたびに、そのボックスと`i`。 これは正しいです。目的地に必要な総作業量は、すべての個々の動作の合計であるからです。 

ただし、これを宛先ごとに行うと、ほぼ同じ計算を何度も繰り返すことになります。 と`n`考えられる目的地と`n`ボックスごとにスキャンする必要がありますが、最悪の場合は`O(n^2)`操作。 行が大きい場合、これはすぐに不可能になります。 

重要な観察は、隣接する目的地が関連しているということです。 全員をボックスに配置するための合計コストがわかっている場合`i`、箱のコストを導き出すことができます`i + 1`行全体を再度スキャンする必要はありません。 

目的地を右に 1 歩移動すると、左側のすべてのモハメッドは 1 歩遠ざかり、右側のすべてのモハメッドは 1 歩近づきます。 両側のモハメッドの数を維持すると、単純な差分だけコストが変わります。 これにより、すべての目的地を線形時間で計算できるようになります。 

ブルートフォース手法は、考えられるすべての目的地が正確に評価されるため機能しますが、重複する距離を再計算するのに時間がかかります。 隣接する宛先間でコストがどのように変化するかについての観察により、問題はプレフィックスとサフィックスのカウントに限定されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 目的地が最初のボックスの場合、すべてのモハメッドの貢献をカウントします。 

ポジションにあるすべてのモハメッドに対して`i`、そのコストは`i`動かなければならないから`i`ボックスを押して最初の位置に到達します。 これらの値を合計すると、最初の目的地の最初の答えが得られます。 
2. この初期コストを保存し、目的地を左から右に移動する準備をします。 

目的地を移動する際に必要なのは、現在左側と右側に何人のモハメッドがいるかを知ることだけです。 
3. 目的地を 1 つずつ右に移動します。 

目的地が位置から移動すると仮定します`i`に`i + 1`。 ポジションにあるすべてのモハメッド`0`を通して`i`は一歩遠ざかり、左側のモハメッドの数だけコストが増加します。 モハメッドのその後は`i`は一歩近づき、右側のモハメッドの数だけコストが減少します。 
4. この差を使用して現在のコストを更新し、表示される最小値を維持します。 

考えられるすべての目的地には 1 回だけ到達するため、記録された最小値が最適な答えになります。 

なぜ効果があるのか:

 不変条件は、目的地を処理する前に保存されるコストが、すべての Mohamed をその位置に移動するのに必要なスワップの数と正確であるということです。 目的地を 1 位置移動すると、個々の距離がちょうど 1 だけ変化し、モハメドがどちら側にいるかに応じて増加または減少します。 すべての寄与はそのカウントを使用して一緒に更新されるため、計算されたすべての宛先コストは正しく、見つかった最小値が真の最適値となります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    s = input().strip()

    total = 0
    ones = 0

    for i, c in enumerate(s):
        if c == '1':
            total += i
            ones += 1

    ans = total

    left = 0
    right = ones

    current = total

    for i in range(n - 1):
        if s[i] == '1':
            left += 1
        right = ones - left

        current += left - right
        ans = min(ans, current)

    print(ans)

if __name__ == "__main__":
    solve()
```最初のループは、選択された宛先が最初のボックスである場合のコストを計算します。 インデックスのモハメッド`i`まさに貢献する`i`この状況で交換します。 

変数`left`そして`right`左から右にスキャンしながら、現在の目的地の前後に何人のモハメッドがいるかを維持します。 目的地が 1 つ移動すると、`left`グループは一人ずつ遠ざかり、`right`グループが 1 つ近づいたので、更新は`left - right`。 

ループは次で停止します`n - 1`なぜなら、最後の移動の後は評価すべき次の目的地がないからです。 すべての算術演算では Python 整数が使用されるため、大きな移動の合計がオーバーフローすることはありません。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)

    data = sys.stdin.readline
    n = int(data())
    s = data().strip()

    total = 0
    ones = 0

    for i, c in enumerate(s):
        if c == '1':
            total += i
            ones += 1

    ans = total
    left = 0
    current = total

    for i in range(n - 1):
        if s[i] == '1':
            left += 1
        right = ones - left
        current += left - right
        ans = min(ans, current)

    sys.stdin = old_stdin
    return str(ans) + "\n"

assert run("6\n100001\n") == "5\n", "symmetric endpoints"
assert run("1\n1\n") == "0\n", "minimum size"
assert run("8\n11111111\n") == "16\n", "all boxes occupied"
assert run("7\n0001000\n") == "0\n", "single Mohamed with many empty boxes"

 ## 特殊なケース

 のために`00100`、アルゴリズムは初期コストで開始されます。`2`, なぜなら、モハメドは最初のボックスから2つ離れた位置にあるからです。 目的地が右に移動するにつれて、左右のモハメドの差によってコストが変更されるアップデートです。 目的地が中心地に到着すると、料金は`0`、これは回答として記録されます。 

のために`100001`、初期費用は`5`。 目的地を中央に移動すると、一方のモハメッドは同じ量だけ近くなり、もう一方は遠ざかるため、合計は変わりません。`5`。 このアルゴリズムは、中央が常に優れているとは想定しておらず、最小値を正確に返します。 

のために`11111111`、すべてのボックスにはモハメドが含まれています。 アルゴリズムは、特別なケースを使用せずにこれを処理します。 各シフトは両側のモハメッドのバランスに応じてコストを変更し、中央付近で最小値が発生し、正しい全体の動きが生成されます。 

単一ボックスの場合、次のようになります。`1`の場合、隣接する宛先がないため、ループは遷移を実行しません。 初期コストはすでに最終的な答えであり、1 つずつの間違いを避けることができます。
