 ## 解決策
 ## 問題の理解

 エレベーターには常に2桁の階数が表示されます。`00`に`99`。 各桁は 7 セグメント ディスプレイを使用して描画されます。 

セグメントが壊れる可能性があります。 セグメントが破損すると、点灯するはずの部分が点灯しなくなります。 重要な観察は、壊れたセグメントは意図した点灯セグメントを消灯セグメントに変えることしかできないということです。 余分な光を作り出すことはできません。 

現在ディスプレイに表示されている 2 桁が与えられます。 元の階数を数えなければなりません`x`から`00`に`99`セグメントの一部が壊れた後に、この目に見える数値が生成された可能性があります。 

表示には常に正確に 2 桁が含まれるため、10 の位と 1 の位は独立しています。 のようなフロア`03`2 桁として扱う必要があります`0`そして`3`、整数としてではなく`3`。 

制約はわずかです。 元のフロア番号は 100 個しかありません。 すべての候補を表示された数値と桁ごと、セグメントごとに比較したとしても、総作業量は無視できるほどです。 数千回の操作で十分です。 

間違いの主な原因は、壊れたセグメントがどのように動作するかを誤解することです。 

入力を考慮してください:```
88
```表示される桁`8`7 つのセグメントすべてを使用します。 破損により追加のセグメントが表示されないため、元の数字も表示されなければなりません。`8`。 したがって、のみ`88`そして`89`生産できる`89`、 なぜなら`9`とは異なります`8`ちょうど 1 つのセグメントが壊れる可能性があります。 

もう 1 つの簡単な間違いは、先頭のゼロを忘れることです。 

入力の場合:```
00
```候補者`08`有効です。 右の数字`8`必要なセグメントを除くすべてのセグメントが失われる可能性があります`0`。 もしフロアを通常の整数として保存し、先頭のゼロを無視すると、そのような可能性を見逃してしまいます。 

3 番目の微妙なケースは、表示されたセグメントが元のセグメントのサブセットである場合、候補はグローバルに有効であると仮定する場合です。 チェックは両方の桁位置に対して個別に実行する必要があります。 たとえば、一の位は互換性があっても、十の位は互換性がない場合があります。 

## アプローチ

 最も直接的な解決策は、考えられるすべての元の階数をテストすることです。`00`に`99`。 

候補番号については、その 2 桁のそれぞれを、対応する表示された桁と比較します。 表示された桁で点灯しているすべてのセグメントが元の桁でも点灯していれば、表示された桁は元の桁から得られます。 

ディスプレイではセグメントが点灯しているが、元の数字では点灯していないものとします。 そのためには、光を作り出すために壊れたセグメントが必要になりますが、それは不可能です。 そのような候補者は拒否されなければなりません。 

この強引な方法はすでに十分に高速です。 候補者はわずか100人です。 各候補は 2 桁をチェックする必要があり、各桁には 7 つのセグメントが含まれます。 総作業量は約`100 × 2 × 7 = 1400`セグメントの比較。 

重要な点は、セグメントの障害では点灯しているセグメントのみが削除されるということです。 各桁をオンにするセグメントのセットで表すと、表示される桁は`d`元の数字から取得できる`o`まさに次のとき:`segments(d)`のサブセットです`segments(o)`。 

これにより、問題は数字間の単純な互換性テストに変わります。 表示されているすべての数字について、それを生成できる元の数字の数を事前に計算できます。 

この番号は 2 つの独立した位置で構成されているため、有効なフロア番号の合計数は次のようになります。`compatible[tens] × compatible[ones]`。 

これにより、100 階すべての番号を列挙する必要がなくなり、実装がさらに簡単になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | ブルートフォース | O(100×14) | お(1) | 承認済み |
 | 最適 | O(10²) 前処理 + O(1) クエリ | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### セグメント表現

 10 進数の各桁を、その桁で点灯する 7 つのセグメントによってエンコードします。 

例えば：`0 = "1111110"`

`1 = "0110000"`等々。 

文字列内の各位置は、表示の 1 つのセグメントに対応します。 

### 互換性のあるオリジナルの桁数

 1. 表示桁ごとに`d`から`0`に`9`、カウンターを初期化します。 
2. 考えられるすべての元の数字について`o`から`0`に`9`、どうかを確認してください`d`から入手できます`o`。 
3. 互換性を確認するには、7 つのセグメントすべてを検査します。 
4. 一部のセグメントが点灯している場合`d`しかし点灯していない`o`、壊れたセグメントは光を生成できないため、ペアを拒否します。 
5. それ以外の場合、ペアは有効であるため、カウンタをインクリメントします。`d`。 

互換性条件は、点灯しているセグメントのサブセット条件とまったく同じです。 

### 入力された数値を処理する

 1. 表示された 2 桁の数字を読み取ります。 
2. 最初の桁を次のようにします`a`そして2桁目は`b`。 
3. 2 つの位置は独立しているため、有効な元のフロア番号の合計数は次のようになります。`count[a] × count[b]`。 
4. 結果を出力します。 

### なぜ効果があるのか

 どの桁の位置でも、表示されたセグメントは、最初に点灯していた場合にのみ点灯したままになります。 壊れたセグメントは点灯しているセグメントをオフにすることはできますが、新しい光を作成する方法でセグメントを選択的にオフにすることはできません。 したがって、表示された数字は、その点灯しているセグメントのすべてがすでに元の数字に属している場合に正確に達成できます。 

10 の位と 1 の位は別々の表示を使用するため、1 つの位置での障害が他の位置に影響することはありません。 すべての有効な元の 10 の桁は、すべての有効な元の 1 の桁と組み合わせることができます。 したがって、カウントを乗算すると、有効な 2 桁のフロア番号の正確な数が生成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

SEG = [
    "1111110",  # 0
    "0110000",  # 1
    "1101101",  # 2
    "1111001",  # 3
    "0110011",  # 4
    "1011011",  # 5
    "1011111",  # 6
    "1110000",  # 7
    "1111111",  # 8
    "1111011",  # 9
]

count = [0] * 10

for shown in range(10):
    for original in range(10):
        ok = True
        for k in range(7):
            if SEG[shown][k] == '1' and SEG[original][k] == '0':
                ok = False
                break
        if ok:
            count[shown] += 1

s = input().strip()

a = int(s[0])
b = int(s[1])

print(count[a] * count[b])
```最初の部分には、各桁の 7 セグメント パターンが保存されます。 あ`'1'`セグメントが点灯していることを意味します。 

前処理ループは、表示されている各桁を生成できる元の桁の数を計算します。 条件```
SEG[shown][k] == '1' and SEG[original][k] == '0'
```元の数字には存在しなかった点灯セグメントがディスプレイに表示されるというあり得ない状況を検出します。 

前処理後、実際の入力はすぐに解決されます。 表示された2桁を読み取り、位置ごとに対応する原稿の枚数を調べ、それらを掛け合わせます。 

よくある間違いは、互換性チェックを元に戻すことです。 表示された数字のすべての点灯セグメントが元の数字にも存在することを確認する必要があります。その逆ではありません。 

もう 1 つのよくある間違いは、入力全体を整数に変換することです。 入力`"03"`先頭のゼロが保持されるように、2 文字の文字列のままにする必要があります。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

SEG = [
    "1111110",
    "0110000",
    "1101101",
    "1111001",
    "0110011",
    "1011011",
    "1011111",
    "1110000",
    "1111111",
    "1111011",
]

def solve():
    count = [0] * 10

    for shown in range(10):
        for original in range(10):
            ok = True
            for k in range(7):
                if SEG[shown][k] == '1' and SEG[original][k] == '0':
                    ok = False
                    break
            if ok:
                count[shown] += 1

    s = input().strip()
    print(count[int(s[0])] * count[int(s[1])])

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    global input
    input = sys.stdin.readline

    solve()

    out = sys.stdout.getvalue().strip()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out

# provided sample
assert run("89\n") == "2", "sample 1"

# custom cases
assert run("00\n") == "4", "leading zeros"
assert run("88\n") == "1", "all segments lit"
assert run("11\n") == "25", "many compatible digits"
assert run("99\n") == "4", "boundary near maximum value"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 00 | 4 | 先頭ゼロの処理 |
 | 88 | 1 | 完全に点灯している数字にはソースが 1 つだけあります |
 | 11 | 25 | カウントの独立した乗算 |
 | 99 | 4 | 高桁互換性チェック |

 ## 特殊なケース

 入力を考慮してください:```
00
```各位置で表示される桁は次のとおりです。`0`。 元の数字のみ`0`そして`8`に必要なすべてのセグメントが含まれています`0`。 アルゴリズムは次の数を計算します。`2`各ポジションとリターンについて`2 × 2 = 4`。 入力を整数として扱う`0`文字列の代わりに`"00"`1 桁が失われ、不正確な答えが生成されます。
