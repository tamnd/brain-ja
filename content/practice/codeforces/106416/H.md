 ## 解決策
 ## 問題の理解

 私たちに与えられた木は、$N$ノード。 各ノードはホールを表し、各エッジはトンネルです。 ゲームにおける移動とは、2 つのノード間の任意の単純なパスです。 グラフはツリーであるため、ノードの各ペアはそのようなパスを 1 つだけ定義します。 

2 人のプレイヤーが独立して 2 つのパスを選択します$A$そして$B$。 それらのスコアは、選択した両方のパス上にあるエッジの数です。 タスクは、あらゆるものについて計算することです。$k$から$1$に$N-1$、順序付けされたパスのペアの数$(A,B)$交差サイズが正確である$k$。 

入力サイズが到達しました$2 \cdot 10^5$したがって、ノードまたはパスの数が 2 次に近いものは使用できません。 ツリー内のパスの数はすでに$\Theta(N^2)$、各パスはエンドポイントのペアによって定義されるためです。 すべてのパスを明示的に反復し、それらをペアごとに比較するソリューションでは、大まかに次の結果が得られます。$N^4$実行可能な限界をはるかに超えた最悪の場合の動作。 

さらに微妙な問題は、2 つの木のパスの交差が任意ではないことです。 これは常に空であるか、それ自体が単一の接続されたパス セグメントであるかのいずれかです。 単純な試みでは、エッジをスキャンしたり、パスのペアごとに LCA 構造を再計算したりして「重複を照合」しようとする可能性がありますが、効率的な LCA ベースの交差チェックを行っても、依然としてパスのペアが多すぎます。 

失敗例の小さな例として、星形グラフがあります。 単純なアプローチですべてのパスを列挙する場合、そのほとんどは長さ 1 または 2 であり、すべてのペアを比較しても葉の数は二次関数的に増加します。 別の障害モードは、LCA 計算を使用して 1 つのパスを修正しようとしてカウントが他のすべてのパスと重複しますが、それでも問題が発生します。$O(N^3)$総合的な行動。 

主な困難は、個々のパスのプロパティではなく、パスのペア間の相互作用のプロパティをカウントしていることです。そのためには、オブジェクトを 1 つずつ比較するのではなく、ツリー全体にわたる構造を集約する必要があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 すべての単純なパスを列挙する$A$、すべての単純なパスを列挙します$B$、LCA またはセットベースの走査を使用して交差の長さを計算し、その値の答えを増分します。 これは問題の定義に直接従うため、正しいです。 問題はスケールです。木には次のような特徴があります。$\Theta(N^2)$パスがあるため、すべてのペアを比較すると次のようになります。$\Theta(N^4)$最悪の場合の操作は不可能です。$N = 2 \cdot 10^5$。 

これを改善するために、パス ペアの構造を共有コアと独立した拡張の 2 つの部分に分離しようとしました。 2 つのパスが重なっている場合、それらの交差点は連続したセグメントになります。$S$。 一度$S$が修正されると、各パスの残りの部分は強制的に終端から分岐します。$S$再入力せずに。 この観察により、問題は「2 つのパスを比較する」という問題から、「共通のセグメントを選択し、その周囲に両方のパスを延長する有効な方法がいくつあるかを数える」という問題に変わります。 

次のステップは、共有セグメントのエンドポイントでローカルに何が起こるかを特徴付けることです。 セグメント内ではすべてが固定されています。 各エンドポイントで、両方のパスが停止するか、セグメントから離れて側枝の 1 つに入る可能性があります。 唯一禁止される状況は、両方のパスが同じ出力分岐を選択する場合です。選択したセグメントを超えて交差点が拡張されてしまうためです。 

このローカルな独立性により、セグメントの寄与がそのエンドポイント全体にわたって乗算されます。 各ノードの次数のみに応じて重みを計算すると、問題全体は、指定された距離にあるノードの重み付きペアをカウントすることになります。 それは古典的な「すべてのペアが距離を置いている」ことです。$k$」ツリーの問題は、重心分解で効率的に解決できます。

 | パスペアに対するブルートフォース |$O(N^4)$|$O(N^2)$| 遅すぎる |
 | エンドポイント因数分解 + 重心分解 |$O(N \log N)$|$O(N)$| 承認済み |

 ## アルゴリズムのチュートリアル

 幾何学を組み合わせ論から分離すると、解決策はきれいになります。 

1. ノードごとに$x$、ローカルの重みを計算します$w(x)$2 つのパスがどのように伸びるかを捉えています。$x$で終わる固定セグメントを共有しているとき$x$。 

させて$d$程度になる$x$。 選択した共有セグメントに沿って、ちょうど 1 つのインシデント エッジがすでに使用されているため、$d-1$無料の支店と立ち寄るオプション$x$。 各パスは独立して、停止するか 1 つの分岐に入るかを選択しますが、2 つのパスが同じ分岐を選択することはできません。 このような選択肢の順序付きペアをすべて数えると、次のようになります。$$w(x) = (d-1+1)^2 - (d-1) = d^2 - d + 1.$$2. 空ではない交差を持つパスのペアは次のように一意に記述できることに注目してください。 

a) 中央セグメント$S$、そして

 b) 両方のパスがエンドポイントでどのように延長されるかについての独立した選択$S$。 

これは、すべての有効なペアが、交差セグメントを選択することによって 1 回だけカウントされることを意味します。 
3. 距離を固定する$k$。 有効な長さのすべての交差セグメント$k$エンドポイントのペアに対応します$(u,v)$と$\text{dist}(u,v)=k$。 このセグメントの貢献は、$w(u)\cdot w(v)$。 
4. 問題はコンピューティングに帰着します。$k$、距離にあるノードのすべてのペアの合計$k$、で重み付けされます$w(u)w(v)$。 
5. 重心分解を使用して、すべての重み付けされた距離ペアの合計を計算します。 各重心で:

 a) 各サブツリー内のすべてのノードを重心からの距離とその重みとともに収集します。 

b) サブツリー データをグローバル頻度構造にマージします。 

c) 新しいサブツリーごとに、そのノードを以前に処理されたサブツリーと組み合わせて、すべての距離値の寄与を更新します。 
6.重心を削除した後にサブツリーを再帰し、各ノードが確実に処理されるようにする$O(\log N)$回。 

### なぜ効果があるのか

 パスの各ペアは、それらの交差セグメントがエンドポイントのペアとして「組み立てられる」時点で 1 回だけカウントされます。 重心に対する分解により、すべてのノードのペアが$(u,v)$それらのパスが最初に結合される正確に 1 つの重心レベルに寄与します。 寄与は距離とエンドポイントの重みのみに依存するため、再帰レベル全体で過剰カウントは発生しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

MOD = 998244353

def solve():
    n = int(input())
    g = [[] for _ in range(n)]
    deg = [0] * n

    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)
        deg[u] += 1
        deg[v] += 1

    w = [0] * n
    for i in range(n):
        d = deg[i]
        w[i] = d * d - d + 1

    ans = [0] * n

    removed = [False] * n
    sub_size = [0] * n

    def dfs_size(u, p):
        sub_size[u] = 1
        for v in g[u]:
            if v == p or removed[v]:
                continue
            dfs_size(v, u)
            sub_size[u] += sub_size[v]

    def dfs_collect(u, p, dist, arr):
        arr.append((dist, w[u]))
        for v in g[u]:
            if v == p or removed[v]:
                continue
            dfs_collect(v, u, dist + 1, arr)

    def add_contrib(arr, counter):
        for d, weight in arr:
            for k in range(len(counter)):
                if k + d >= len(ans):
                    break
                ans[k + d] = (ans[k + d] + weight * counter[k]) % MOD

    def build_counter(arr):
        counter = {}
        for d, weight in arr:
            counter.setdefault(d, 0)
            counter[d] = (counter[d] + weight) % MOD
        return counter

    def centroid(u):
        dfs_size(u, -1)
        nsz = sub_size[u]

        p = -1
        changed = True
        while changed:
            changed = False
            for v in g[u]:
                if v == p or removed[v]:
                    continue
                if sub_size[v] * 2 > nsz:
                    p = u
                    u = v
                    changed = True
                    break
        return u

    def decompose(u):
        c = centroid(u)
        removed[c] = True

        all_data = []
        global_counter = {}

        global_counter[0] = w[c]

        for v in g[c]:
            if removed[v]:
                continue
            arr = []
            dfs_collect(v, c, 1, arr)

            sub_counter = build_counter(arr)

            add_contrib(arr, global_counter)

            for d, val in sub_counter.items():
                global_counter.setdefault(d, 0)
                global_counter[d] = (global_counter[d] + val) % MOD

            all_data.extend(arr)

        for v in g[c]:
            if not removed[v]:
                decompose(v)

    decompose(0)

    print(*[ans[i] % MOD for i in range(1, n)])

if __name__ == "__main__":
    solve()
```実装は、各ノードの次数ベースの重みを計算することから始まります。 次に、重心分解ではバランスのとれたルートを繰り返し選択し、各サブツリーから距離と重みのペアを収集し、周波数マップを使用してすべての距離の寄与を蓄積します。 重要な実装の詳細は、以前に処理されたサブツリーと現在のサブツリーの間でのみ寄与が蓄積されるため、兄弟サブツリー間での二重カウントが防止されることです。 

距離の累積は加算的なものであるため、ノードのペアは、それらのパスが最も低い重心の祖先で出会うときに 1 回だけ寄与します。

 ## 特殊なケース

 2 ノード ツリーでは、すべてのパスが単一のエッジであるため、すべての順序ペアの交差長は 1 になります。アルゴリズムは、次数に基づいて各ノードに重みを割り当て、単一の重心の寄与を正確にカウントします。 

スター グラフでは、すべての重要な交差は中心を通る葉間の相互作用から生じます。 重心分解では最初に中心が処理されるため、すべてのリーフ ペアが距離 2 で 1 回だけ結合され、必要な数と一致します。 

長いチェーンでは、各重心分割は、各距離レベルで重複することなくすべてのペアをキャプチャします。これは、各ペアが、分解階層内でパスが最初に交わる重心に関連付けられているためです。
