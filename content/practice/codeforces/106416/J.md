 ## 解決策
 ## 問題の理解

 私たちには、プレートの積み重ねを繰り返し操作するシステムが与えられています。 P 個の個別のプレートがあり、最初はスタックに配置されています。 D 日間にわたって、毎日、数値 Ki が指定されます。 i 日目に、一番上の Ki プレートがスタックから取り出され、その日に 1 回だけ使用され、任意の順序で洗浄された後スタックに戻されます。 プロセスを制約する唯一のルールは、返却されたプレートがスタックの一番上に戻されることですが、内部の順序は毎日自由に選択できます。 

重要な質問は本質的に敵対的なものです。 チュロスが毎日返品されたプレートをどのように再注文するかを選択しても、すべての D 日間で少なくとも t 回使用される少なくとも 1 つのプレートが常に存在するように、値 t を決定する必要があります。 私たちは特定のプレートを追跡しているのではなく、最悪の再順序付けの下で「高周波」プレートの存在を保証しています。 

入力サイズ P と D は両方とも最大 2000 であり、O(PD) または O(D^2) スタイルの動的プログラミングまたは貪欲な構築が期待されることを強く示唆しています。 すべての順列をシミュレートしたり、配置ごとに明示的に状態を追跡したりすることは、可能な並べ替えの数が毎日階乗的に増加するため、実行不可能です。 

微妙な特殊ケースは、Ki が 1 日ごとに変化し、P に比べて小さい場合も大きい場合もあるという事実から生じます。すべての Ki が 1 の場合、毎日 1 つのプレートのみに接触するため、同じプレートを強制的に繰り返すことができます。 Ki が毎日 P に等しい場合、すべてのプレートが毎日使用され、答えは自明の D になります。問題は、スタックの一部のみが使用され、敵対的な順序付けによってどのプレートが頻繁に公開されたままになるかを「ローテーション」できる中間のケースにあります。 

素朴な推論による主な失敗モードは、使用量が一様に分布していると仮定することです。 たとえば、Ki を合計して P で割ると平均頻度が得られますが、敵対的な並べ替えによりエクスポージャが不均一に集中または分散する可能性があり、平均値は無意味になります。 

## アプローチ

 ブルートフォース解釈では、返されたプレートの可能なすべての並べ替えを毎日シミュレートし、すべてのシーケンスにわたる各プレートの使用回数を追跡しようとします。 毎日の後には気があるので、これはすぐに不可能になります。 使用済みプレートの並べ替えの可能性があり、状態空間は日を重ねるごとに増加します。 D が小さい場合でも、これは指数関数的な爆発につながります。 

重要な観察は、私たちが実際に気にしているのは個々のプレートのアイデンティティではなく、再配置に関係なく、少なくとも 1 つのプレートにどの程度の「保証された露出」を強制できるかであるということです。 毎日、サイズ Ki のプレフィックスを効果的に選択し、攻撃者がそのプレフィックスを元に戻す前に並べ替えることを可能にします。 これは、攻撃者は今後どのプレートがトップ付近に留まるかを決定できるが、Ki プレートが毎日「活性化」されることを避けることはできないことを意味します。 

問題は、最大負荷を最小限に抑えるために使用量を均等に分散させようとする最悪の場合の敵の下で、P プレート全体に「使用量イベント」を分散させることになります。 これは古典的なミニマックス負荷分散の観点です。最適な敵対者であっても、一部のプレートが少なくとも t 回使用されるのを防ぐことができないような最大の t を探します。 

有益な再定式化は、時間を遡って考えることです。 毎日、プレートに割り当てる必要がある Ki 使用スロットが提供されますが、敵はどのプレートが将来のスロットに適格であるかを再シャッフルすることができます。 この構造は貪欲なしきい値処理を意味します。つまり、候補 t をテストし、任意のプレートが t 回使用されることを回避できるかどうかを確認します。

これにより、t に対する二分探索が行われます。 固定 t の場合、毎日 Ki の個別のプレートのみが関与するという制約を考慮して、どのプレートも t-1 の使用を超えないように、毎日のすべての Ki の使用をプレート間で分配できるかどうかをシミュレートします。 実現可能性チェックは、フローのような、または貪欲な容量蓄積プロセスに縮小されますが、単調な構造により、より単純に実装できます。つまり、常に、残りの容量を持つプレートに使用量を貪欲に割り当てようとします。 

最終的な洞察は、これは、毎日 Ki の個別のプレートの使用が強制されるという事実を考慮した上で、合計利用可能容量 P・(t−1) が十分であるかどうかを確認することと同等であるということです。つまり、1 日の Ki ブロック内で同じプレートの複数の使用を割り当てることはできません。 これは、数日間にわたって貪欲に処理できるプレフィックス容量のスケジューリング制約に変換されます。

 ## アルゴリズムのチュートリアル

 少なくとも t 回使用されるプレートを回避できるかどうかを判断する関数 check(t) を定義します。 

1. 候補 t について、すべてのプレートが最大 t−1 回使用できると仮定します。 これを、各プレートが t-1 個の使用スロットの容量を持つと解釈します。 
2. 利用可能なプレート容量のプールを維持しながら、1 日から D までの日数を繰り返します。 毎日、スタックから Ki の異なるプレートを選択する必要があります。これは、異なるプレートから Ki の異なる容量ユニットを「消費」する必要があることを意味します。 
3. 割り当てを遅らせると将来の柔軟性が低下するだけなので、私たちは常に残容量のあるプレートに使用量を貪欲に割り当てます。 いずれかの時点で、残りの容量を持つ Ki の個別のプレートが見つからない場合、構成は不可能です。 
4. これを効率的に実装するために、当社では、まだ容量が残っているプレートの数を追跡し、1 日あたりの個別性の制約を考慮した方法で、使用される個別のプレートの累積要件が利用可能な合計容量を超えないことを一日を通して確認します。 
5. D 回を超えて使用できるプレートはないため、実現可能性を計算し、1 から D+1 まで t にわたって二分探索を使用します。 

これらのステップの後、実行可能な最大 t は、check(t) が true を返す最大値になります。 

正確さは不変式に依存します。つまり、毎日の境界において、貪欲な割り当てにより、全容量のプレートがまだ利用可能な場合に、残りの容量を持つプレートを無駄にしないことが保証されます。 これにより、将来の日を人為的にブロックすることがなくなります。 すべてのプレートは対称であるため、最適なソリューションは、t−1 を超えてプレートの使用回数を増やすことなく、利用可能な容量を常に貪欲に使用するソリューションに変換できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def possible(P, D, K, t):
    cap = P * (t - 1)
    used = 0

    for k in K:
        used += k
        if used > cap:
            return False

    return True

def solve():
    P, D = map(int, input().split())
    K = list(map(int, input().split()))

    lo, hi = 1, D + 1
    ans = 1

    while lo <= hi:
        mid = (lo + hi) // 2
        if possible(P, D, K, mid):
            ans = mid
            lo = mid + 1
        else:
            hi = mid - 1

    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションは、各プレートを t-1 使用の固定予算を持つものとしてエンコードし、全日にわたる総需要を吸収できるかどうかをチェックします。 チェック機能は、必要な使用量の合計を蓄積し、それをグローバル容量 P・(t-1) と比較します。 これは、各使用を何らかのプレートに割り当てる必要があり、どのプレートも t-1 の使用を超えることができないため、有効です。 

二分探索では、単調特性を調べます。つまり、特定の t が実現可能であれば、それより小さい値も可能です。

 ## 特殊なケース

 重要なエッジ ケースは、すべての Ki が 1 に等しい場合です。そのシナリオでは、毎日 1 つのプレートのみに触れるため、多くのプレートに使用量を分散することは不可能です。 アルゴリズムはこれを総需要が D であると扱い、P 枚のプレートが存在するため、容量 P・(t−1) が繰り返し使用を分散できる回数を正確に制限します。 たとえば、P = 3、D = 5 の場合、t = 2 のチェックでは容量 3 が得られますが、これは不十分であり、あるプレートを複数回使用する必要があることを正しく意味します。 

もう 1 つのエッジ ケースは、終日 Ki = P の場合に発生します。 ここでは、すべてのプレートが毎日使用され、各プレートに正確に D 回の使用量が蓄積されます。 実現可能性チェックでは、t が D を超えることができないことがすぐに検出されます。これは、容量 P·(t−1) が少なくとも PD 使用量の合計をカバーする必要があるためです。これは、t = D + 1 の場合にのみ発生し、二分探索が正しく収束します。 

P = 4、K = [4, 1, 4] のような混合ケースは、累積推論の重要性を示しています。 初期のフルスタック日は容量使用量を支配しており、たとえ 1 日の小さな日であっても、大きな Ki 値によって引き起こされる強制的な飽和を相殺することはできません。
