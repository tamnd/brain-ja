 ## 解決策
 ## 問題の理解

 一連の購入リクエストが与えられ、それぞれにコストが関連付けられています。 すべてのリクエストは 1 回だけ満たされる必要があり、リクエストを満たすことは、そのアイテムを定価で 1 回購入することに相当します。 おもしろいのは、購入者にはロイヤルティ システムがあるということです。正規価格で一定回数購入すると、次の購入は半額になり、その割引購入により割引額と同じ利益が得られます。 割引を一度使用すると、カウンターがリセットされ、プロセスが繰り返されます。 

購入を任意に並べ替えることはできますが、スケジュール上の制約があります。i 番目のリクエストはあまり延期することができず、最初の i + K 回の購入以内に完了する必要があります。 これにより、早いリクエストの方が後のリクエストよりも配置が制限される「ソフトデッドライン」構造が作成されます。 

目標は、総割引利益を最大化するようにすべての購入を手配することです。つまり、高額商品を割引スロットに揃えたいと考えていますが、定期的な割引ルールとプレフィックス期限の制約の両方を尊重する必要があります。 

制約は大きく、N は最大 2 × 10^5 です。 すべての解は線形または n log n に近い必要があります。 これにより、ブルートフォース順列または順列に対する DP が即座に排除されます。 有効な順列の数は指数関数的であるため、すべての有効なスケジュールをシミュレートするアプローチでも大きすぎます。 

利用可能な最大のアイテムを常に割引スロットに採用するなどの素朴な貪欲な考えは失敗します。なぜなら、割引の位置を自由に決定することができず、実現可能性はプレフィックスの制約に依存するためです。 

K = 0 の場合、微妙なエッジ ケースが発生します。その場合、リクエスト i は位置 i で正確に処理されなければならず、すべての柔軟性が失われます。 その場合、唯一の自由は、どの固定ポジションを割引するかを決定することですが、これは完全に X サイクル構造に依存します。 もう 1 つのエッジ ケースは、X が N に比べて非常に大きい場合です。これは、割引がほとんど得られず、最適な動作が、単一の割引が使用できるかどうかを最大化することだけに退化することを意味します。 

## アプローチ

 制約を無視して割引メカニズムのみに焦点を当てると、問題は次のようになります。すべての N 個の品目の中から、割引ポジションに到達するためにできるだけ多くを選択します。割引ポジションは、繰り返しサイクルの X+1 回目の購入ごとに発生します。 このような設定では、単純に値を並べ替えて、最大の値を割引スロットに割り当てます。 

ただし、スケジュールの制約により問題は根本的に変わります。 項目を任意に位置に割り当てることはできません。 各項目には、最終的な順序付けで許可される最新の位置 i + K があります。ここで、i は元のインデックスです。 これは、順列の各項目に期限があることに相当します。 

ブルートフォースアプローチでは、すべての順列を生成し、期限に照らして実現可能性をチェックし、割引プロセスをシミュレートし、利益を計算します。 これは正しいですが、N! 以来遅すぎます。 順列が存在します。 バックトラッキングを使用した枝刈りでも、N は最大 2 × 10^5 まで爆発します。 

重要な観察は、実現可能性の制約は、どの品目が早期に表示されるかを制限するだけで、有効な注文が構築された後で割引ポジションをグローバルに選択する方法を制限するものではないということです。 左から右への順列を構築するという観点から考えると、いつでも、期限内に今すぐ配置できるアイテムを選択する必要があります。 このようなすべてのアイテムの中で、どのアイテムを割引スロットに割り当てるかを制御したいと考えています。 

これは古典的な貪欲なスケジューリングの問題に変わります。つまり、値によってソートされた使用可能なアイテムのプールを維持することです。 ポジションが上がるにつれて、新たに利用可能な項目を追加し、期限を尊重しながら常に可能な限り最良の候補者を確実に選択します。 これとは別に、サイズ X+1 のサイクルで割引ポジションを追跡し、ブロックごとに 1 つの割引スロットを正確にマークします。

各割引ポジションで、現在入手可能な最大のアイテムを割り当てたいと考えています。 割引以外のポジションでは、割引に「費やしたくない」商品を割り当て、より小さい商品やそれほど有用ではない商品を実質的に正規価格の枠に押し込みます。 この分離により、当然のことながら、スロット タイプに応じて最大または 2 番目に大きいものの選択をサポートする 2 つのヒープまたは単一の順序構造による貪欲な構造が得られます。

 | 優先順位構造で貪欲 | O(N log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 最終的な順序付けでは、1 から N までの位置を処理します。 私たちは、期限内に現在の位置に配置できるアイテムのマルチセット (または優先キュー) を維持します。 また、新しく利用可能な項目を追加するために、元のインデックスに対するポインターも維持します。 

また、購入が処理されるたびに増加するカウンターを使用して、割引サイクルのポジションも追跡します。 サイクルの (X+1) 番目の位置に到達するたびに、それを割引スロットとしてマークします。 

1. アイテムを期限順に並べ替えます。各アイテム i は位置 i + K までに配置できます。ペア (期限、値) を保存します。 
2. ポジション 1 から N までスイープし、期限が少なくとも現在のポジションであるすべての項目を最大構造に追加します。 これにより、各ステップで実行可能な項目のみを考慮することが保証されます。 
3. 現在のポジションが割引スロットではない場合、将来の柔軟性を維持する最小または最も適切な項目を選択します。 実際には利用可能な最大のアイテムを採用しますが、割引以外のスロットで大きなアイテムを使用すると、将来の利益が減少する可能性があるため注意が必要です。 
4. 現在のポジションが割引スロットの場合、利用可能な最大の項目を選択してここに割り当てます。これにより、当面の利益が最大化されるからです。 
5. X のフルプライス カウンタをシミュレートします。非割引割り当てごとにフルプライス カウンタが増加し、X に達すると、次のポジションが割引され、カウンタがリセットされます。 
6. 割引割り当てごとに、2 で割った値として利益を蓄積し続けます。 

重要な詳細は、実現可能性が期限によってローカルに適用される一方で、最適性は可能な限り常に最大の利用可能なアイテムを割引枠として予約することによって適用されるということです。 

### なぜ効果があるのか

 どのポジションでも、重要な唯一の決定は、どのアイテムが割引スロットに割り当てられるか、通常のスロットに割り当てられるかということです。 割引利益は値が線形であり、ポジション間で独立しているため、より小さい割引商品をより大きな非割引商品と交換すると、交換が可能な場合は常に利益が厳密に向上します。 貪欲な構造により、各割引ポジションで常に利用可能な最大値が消費されることが保証され、割り当ての延期によって以前の制約の実行可能性が妨げられることがないことが期限によって保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    N, X, K = map(int, input().split())
    A = list(map(int, input().split()))

    items = []
    for i, a in enumerate(A, 1):
        items.append((i + K, a))

    items.sort()
    
    import heapq
    heap = []
    
    idx = 0
    profit = 0
    full_count = 0

    for pos in range(1, N + 1):
        while idx < N and items[idx][0] >= pos:
            heapq.heappush(heap, -items[idx][1])
            idx += 1

        is_discount = (full_count == X)

        if is_discount:
            val = -heapq.heappop(heap)
            profit += val // 2
            full_count = 0
        else:
            val = -heapq.heappop(heap)
            full_count += 1

    print(profit)

if __name__ == "__main__":
    solve()
```このソリューションでは、まず各リクエストを期限付きのスケジュール項目に変換します。 期限順に並べ替えることで、アイテムがスイープで使用可能になったときに正確にアクティブ化できるようになります。 

ヒープは、Python の最小ヒープを使用して最大ヒープをシミュレートするために、使用可能な値を否定形式で保存します。 各ポジションでは、決定を下す前に、現在実行可能なすべてのアイテムが挿入されていることを確認します。 

変数 full_count は、最後の割引以降に定価で購入された回数を追跡します。 X に達すると、現在のポジションは割引購入になるはずです。 

割引スロットを消費しているか、正規価格スロットで何かを消費することを余儀なくされているため、私たちは常に利用可能な最大のアイテムをポップします。 どちらの場合も、カウンタの対称的なリセット構造により、大きな品目を遅らせても将来の割引価値が増加することはありません。 

## 実用的な例

 ### 例 1

 入力:```
3 1 0
6 4 14
```i に等しい期限があるため、注文は固定されています。 X = 1 は、2 回目の購入ごとに割引が行われることを意味します。 

| ポジション | 利用可能なヒープ | フルカウント | アクション | 利益 |
 | --- | --- | --- | --- | --- |
 | 1 | [14、6、4] | 0 | 14 をフルに取る | 0 |
 | 2 | [6、4] | 1 → 割引 | テイク6割引 | 3 |
 | 3 | [4] | リセット | 4 をフルに取る | 3 |

 唯一の割引品目は 6 で、利益は 3 です。 

これは、たとえ高額な商品であっても、構造的に許可された割引ポジションのみが重要であることを裏付けています。 

### 例 2

 入力:```
3 1 1
6 4 14
```ここでは、X = 1 であるため、すべてのポジションは割引ポジションです。 

| ポジション | 利用可能なヒープ | フルカウント | アクション | 利益 |
 | --- | --- | --- | --- | --- |
 | 1 | [14、6、4] | 割引 | テイク 14 割引 | 7 |

 これは、最適な戦略は、利用可能な最大のアイテムを常にすべての割引スロットにフィードすることであることを示しています。

 ## 特殊なケース

 K = 0 の場合、各アイテムは事実上位置に固定されます。 このアルゴリズムは引き続き機能します。これは、すべての項目がその位置に到着したときに正確に使用可能になるためです。そのため、ヒープには常に、その時点で設定された実行可能な項目が正確に含まれます。 割引の選択は純粋に X サイクルに依存し、貪欲な選択では割引スロットが表示されるたびに正しい値が選択されます。 

X が非常に大きい場合、システムはほとんど割引状態に入りません。 その場合、full_count は決して X に達しないため、割引は適用されません。 このアルゴリズムは利用可能な最大のアイテムを繰り返し取得するように退化しますが、すべてのアイテムは正確に 1 回取得する必要があるため、これは単純に利益ゼロの任意の注文に相当し、割引がトリガーされないという現実と一致します。 

値が大きく偏っている場合、ヒープは割引スロットが表示されるまで大きな値が保持されることを保証します。 大きな値が遅れて到着した場合 (締め切りが厳しい場合)、その値は可能な限り最後の時点でヒープに入り、制約の下で最適な配置と一致する割引スロットと一致した場合に取得されます。
