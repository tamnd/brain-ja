 ## 解決策
 ## 問題の理解

 各テスト ケースは、ボード ゲーム セッション中に収集されたリソース タイプのコレクションを記述します。 タイプごとに、そのリソースが収集されたユニットの数と、1 つのユニットが何ポイントの価値があるかが示されます。 このタスクは、すべてのリソース タイプからの貢献を集計して合計スコアを計算することです。 

より具体的に言うと、各行に 1 組の数字が表示されます。 最初の数値は特定の種類の項目の数であり、2 番目の数値はそのような項目 1 つの値です。 最終スコアに対するそのタイプの貢献度は単にその積であり、答えはすべてのタイプに対するこれらの貢献度の合計です。 

制約では最大 100,000 のリソース タイプが許可され、各値は 100,000 までの大きさになります。これにより、入力に対する単一の線形パスを超えるものを試行するソリューションは即座に排除されます。 直接集計以外に利用できる構造がないため、O(n log n) アプローチさえも不要です。 唯一の実行可能なアプローチは、入力を読み取るときに合計を累積することです。 

不注意な実装で発生する可能性のある微妙な問題は、固定幅整数を使用する言語での整数オーバーフローです。 たとえば、すべての入力が最大値の場合、単一の積は 10^10 に達し、そのような値を 10^5 まで合計すると 10^15 に達する可能性があります。 Python ではこれは安全ですが、他の言語では 64 ビット整数が必要です。 

もう 1 つの潜在的な間違いは、累算を 2 つの配列に分割し、それらを後で不必要に処理しようとすることです。これにより、オーバーヘッドが追加されますが、正確さは変わりません。 各ラインは独立しているため、計算を遅らせてもメリットはありません。 

## アプローチ

 強引な解釈では、すべてのリソース単位を個別に展開し、値を 1 つずつ割り当てます。 つまり、概念的には、型ごとにサイズ a_i のリストを作成し、各要素に b_i を割り当てます。 これは正しいですが、a_i が大きい場合は、展開された要素の総数が最悪の場合 10^10 に達する可能性があるため、すぐに実行不可能になります。 

重要な観察は、同じタイプのすべてのユニットの価値寄与が同一であるということです。 リソースタイプ間に相互作用はなく、リソースタイプ間の順序や制約もありません。 これにより、問題は、各重みが単に a_i であり、各値が b_i である重み付き合計の計算に分解されます。 拡大するのではなく、直接乗算して累積します。 

これにより、タスク全体が入力の 1 回のパスに減ります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース拡張 | O(∑a_i) | O(∑a_i) | 遅すぎる |
 | 直接加算 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 変数を初期化する`total`ゼロに。 これにより、すべての寄付金の累計が保存されます。 
2. リソースタイプの数を読み取ります`n`。 
3. 次のそれぞれについて`n`行、ペアを読み取ります`(a_i, b_i)`。 
4. このタイプの寄与を次のように計算します。`a_i * b_i`。 これは、その種類のすべての項目を組み合わせた合計値を表します。 
5. この投稿を`total`。 
6. 全行処理後、出力`total`。 

重要な設計上の選択は、値を保存するのではなく、読み取り時に乗算を実行することです。 これにより、不必要なメモリ使用が回避され、計算が入力ライン数に対して厳密に線形になることが保証されます。 

### なぜ効果があるのか

 各リソース タイプは他のリソース タイプから独立しており、タイプ内のすべてのユニットは同じ値を持ちます。 したがって、合計スコアは、各グループが正確に貢献している、互いに素なグループの合計になります。`a_i * b_i`。 加算は結合的かつ可換的であるため、入力順序に関係なく、寄与を累積すると正確さが増分的に維持されます。 相互作用項は存在しないため、累計を超える追加の状態は必要ありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    total = 0
    for _ in range(n):
        a, b = map(int, input().split())
        total += a * b
    print(total)

if __name__ == "__main__":
    solve()
```ソリューションは各ペアを 1 回読み取り、すぐに答えに組み込みます。 乗算は加算の前に行われるため、中間の拡張表現を保存する必要がありません。 Python の任意精度の整数を使用すると、合計が 64 ビットの制限を超えた場合でも正確さが保証されます。

 ## 特殊なケース

 エッジケースの 1 つは、すべてのリソース数がゼロの場合です。 入力の場合:```
3
0 10
0 20
0 30
```各寄与はゼロであるため、実行中の合計は実行中ゼロのままです。 このアルゴリズムは 3 つの乗算を実行しますが、結果はすべて 0 であり、特別な分岐がなければ最終出力は 0 のままです。 

もう 1 つのケースは、タイプが 1 つだけ存在する場合です。```
1
12345 67890
```このアルゴリズムは 1 回の乗算を実行し、結果を直接出力します。 アキュムレータはゼロから開始され、単一の更新で完全な答えが正しく取得されるため、初期化の問題は発生しません。 

3 番目のケースは、値が最大の大きさである場合です。 中間積は大きくなる可能性がありますが、Python は任意の精度を自然に処理するため、累積を繰り返してもオーバーフローしたり精度が失われることはありません。
