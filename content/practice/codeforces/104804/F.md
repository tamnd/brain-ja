 ## 解決策
 ## 問題の理解

 ラテン語の大文字で構成される文字列とパラメータが与えられます。$k$。 部分文字列に次の文字列が含まれない場合、その部分文字列は有効であるとみなされます。$k$母音は連続しており、連続した母音が含まれることはありません。$k$子音が並んでいます。 母音は次のように固定されます$a, e, i, o, u$, したがって、すべての文字は母音または子音のいずれかに決定論的に分類できます。 

タスクは、この制約を満たす最長の連続する部分文字列の長さを計算することです。 

文字列の長さは次のとおりです。$10^5$これにより、すべての部分文字列を明示的にチェックするアプローチは即座に除外されます。 すべての部分文字列を列挙することは、$O(n^2)$、そして線形時間でそれぞれを検証することさえも$O(n^3)$、実現可能な限界をはるかに超えています。 これにより、一定時間の状態維持を伴う線形または線形に近いスキャンが実現されます。 

重要な微妙な点は、無効性が絶対数ではなく、同じタイプの連続実行に依存することです。 これにより問題は本質的に局所的になりますが、実行が中断されるとリセットされるスライディング グローバル制約が伴います。 

ランが長さに近い場合、エッジケースが発生します$k$、特に境界付近。 

たとえば、次の場合$k = 2$そして文字列は`"aaabbb"`、すべての文字は少なくとも 3 の長さのランの一部であるため、長さが 2 を超える部分文字列には、禁止された連続する母音または子音のペアが含まれることを避けることができません。 単一文字または交互の単一文字は安全であるため、答えは 2 になります。 

もう 1 つのエッジケースは次のような場合です$k = 1$。 母音または子音だけでもすでに長さ 1 の禁止されたランを形成しているため、空でない部分文字列はすべて無効になり、答えは強制的に 0 になります。$k > 1$、この境界を理解すると、仕組みが明確になります。 

3 番目の微妙なケースは、長い有効領域が、タイプを反転する単一の文字によって中断される場合です。 母音/子音の合計数を追跡するだけの単純なアプローチでは、そのようなセグメントが誤って受け入れられてしまいます。 

## アプローチ

 ブルートフォース戦略では、すべての開始インデックスを試します。$l$、 伸ばす$r$右側に移動し、連続する母音と子音の数を維持します。 各拡張子は、長さが連続しているかどうかをチェックします。$k$が形成されました。 これは制約を直接シミュレートするため、これは正しいです。 

ただし、それぞれの$O(n^2)$部分文字列には最大で$O(n)$単純に実装すると最悪の場合スキャンが行われ、$O(n^3)$。 注意深く増分チェックを行ったとしても、拡張機能の数だけでも二次関数となり、これでは遅すぎます。$10^5$。 

重要な観察は、無効は同一の文字タイプの実行によってのみ引き起こされるということです。 すべての最大連続母音セグメントと子音セグメントの長さがわかったら、部分文字列は少なくともその長さのセグメントが完全に含まれていない場合にのみ有効になります。$k$中断することなく。 

部分文字列を開始する代わりに、視点を逆転させます。 すべての「悪い境界」、つまりランの長さに達する位置を見つけることができます。$k$。 有効な部分文字列はすべて、長さが連続しない領域内に完全に存在する必要があります。$k$完全に含まれています。 

したがって、左から右にスキャンしている間、現在の連続ランレングスを維持します。 ランニングが長くなるとき$k$、現在のインデックスまでの最初の文字を含む部分文字列は無効になるため、左の境界を前方に移動します。 これは当然、スライディング ウィンドウにつながります。現在のウィンドウに禁止された実行が含まれないように、最小の左エンドポイントを維持します。

 ## アルゴリズムのチュートリアル

 母音/子音タイプの現在のランレングス、最後に表示された文字タイプ、および現在のウィンドウの最も古い有効な開始インデックスという 3 つの情報を維持しながら、文字列を左から右に処理します。 

1. 各文字を母音または子音を示すブール値に変換します。 これにより、以降のすべてのロジックがアルファベット処理ではなくバイナリ遷移に簡素化されます。 
2. 変数を維持する`run_len`これは、現在の位置で終わる同じタイプの連続した文字の数をカウントします。 メンテナンスも行います`last_type`比較用に。 
3. ポインタを維持する`left`現在の位置で終わる有効な部分文字列の最小の開始インデックスを表します。 
4. ポジションごとに`r`、実行を更新します: 現在のタイプが一致する場合`last_type`、増分`run_len`、それ以外の場合はリセット`run_len`1 に更新してください`last_type`。 
5. もし`run_len`と等しくなる$k$、で始まる部分文字列`r - k + 1`そしてで終わります`r`は禁止されています。 次で終わる有効なウィンドウ`r`そのセグメント全体を含めることはできないため、移動します`left`に`r - k + 2`。 
6. 回答を次のように更新します`max(ans, r - left + 1)`。 

ステップ 5 の背後にある理由は、ウィンドウが無効になる唯一の方法は、禁止された実行を完全に封じ込めることであるということです。 ランが長さに達したら$k$の場合、その実行の前または開始時に始まり、その終了時以降に終了するすべてのウィンドウを除外する必要があります。 

### なぜ効果があるのか

 あらゆるポジションで$r$、アルゴリズムにより、現在のウィンドウが$[left, r]$～のセグメントが含まれていない$k$連続した母音または子音。 違反はすべて、同じタイプの長さの連続した実行として現れる必要があります。$k$そして、そのような実行が検出されると、無効なウィンドウはすべて次のステップに進むことで削除されます。`left`フルランを含む可能な限り最も早い開始点を少し超えたところにあります。 これにより、維持されているすべてのウィンドウが有効であることが保証され、すべての有効なウィンドウが最終的には`r`拡大します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def is_vowel(c):
    return c in "aeiou"

def solve():
    s = input().strip()
    k = int(input())

    n = len(s)
    if n == 0:
        print(0)
        return

    ans = 0
    left = 0

    last_type = None
    run_len = 0

    for r, ch in enumerate(s):
        t = is_vowel(ch)

        if t == last_type:
            run_len += 1
        else:
            last_type = t
            run_len = 1

        if run_len >= k:
            left = max(left, r - k + 2)

        ans = max(ans, r - left + 1)

    print(ans)

if __name__ == "__main__":
    solve()
```この実装は、上で説明したスライディング ウィンドウに従います。 重要な詳細はアップデートです`left = max(left, r - k + 2)`。 この式は、次で終わる完全な禁止された実行を含む最小限のプレフィックスを正しく削除します。`r`。 使用する`max`重複する複数の実行がすでに強制されている可能性があるため、これが必要です。`left`先に進みます。 

答えの更新`r - left + 1`現在の有効なウィンドウのサイズを直接測定します。

 ## 特殊なケース

 厄介なケースは、ランがちょうどしきい値を横切る場合です。$k$。 例えば、`aaaa`と$k=3$。 で$r=2$、実行は 3 に達し、左シフトが強制されます。 アルゴリズムセット`left = r - k + 2 = 1`、つまりウィンドウは次のようになります`[1,2]`。 0 で始まるウィンドウには完全な禁止された実行が含まれるため、これにより正確さが保たれます。`"aaa"`インデックス 2 で終わります。 

もう 1 つのケースは、ランの成長を伴わない交互のキャラクターです。 アルゴリズムが更新されない`left`したがって、文字列全体は有効なままであり、禁止されたシーケンスが形成されないため、定義と一致します。 

最後の微妙なケースは、タイプの切り替えによって引き起こされる重複した実行です。 ランレングスはタイプが変わるとリセットされるため、移動をトリガーする唯一の方法は、同じタイプの単一の連続ブロックです。 これにより、二重にカウントしたり、短い無効ウィンドウを見逃したりすることなく、各違反が個別に処理されることが保証されます。
