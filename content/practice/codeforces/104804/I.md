 ## 解決策
 ## 問題の理解

 配列が与えられ、最初にその配列のすべてのプレフィックスの合計を形成します。 配列が`a`次に、新しいシーケンスを構築します`s`どこ`s[i]`最初の合計です`i`要素。 その後、このプレフィックス合計シーケンス内の個別の要素のすべてのペアを考慮し、それらを乗算します。 タスクは、そのようなすべてのペア積の合計を計算し、その結果を剰余演算することです。`M`、 どこ`M`は 2 の累乗であることが保証されます。 

したがって、入力は整数配列と係数です。 出力は、全体の合計を表す単一の数値です。`i < j`の`s[i] * s[j]`、縮小モジュロ`M`。 

制約により許可されるのは、`N`プレフィックス合計に対する 2 次スキャンは大きすぎます。最悪の場合、約 4 億 5,000 万回の乗算が必要になるからです。 これは、最適化された C++ ではすでに限界に達しており、Python では明らかに受け入れられません。 これにより、式の線形または線形に近い変換がすぐに実行されます。 

係数が 2 の累乗であることも、構造上の強力なヒントとなります。 これは、オーバーフロー動作がビット マスキングに対応する、固定幅の整数演算を効果的に行っていることを意味します。 これにより、多くの場合、除算や逆モジュラを気にせずに、整数に対する単位を使用した単純化が可能になります。 

いくつかのエッジ動作には注意が必要です。 

もし`N = 1`、プレフィックスの合計のペアは存在しないため、答えはゼロでなければなりません。 アキュムレータを誤って初期化するか、少なくとも 1 つのペアが存在すると仮定する単純な実装では、簡単にガベージが生成される可能性があります。 

すべての要素がゼロの場合、すべてのプレフィックスの合計もゼロになるため、答えはゼロになる必要があります。 これにより、ゼロチェックを行わずに誤って部分積を使用する実装が捕捉されます。 

接頭辞の合計が大きくなると (最大 3e8)、中間積が 32 ビットの範囲を超える可能性があるため、適切な注意を払わずに固定幅の整数に依存するアプローチは、大きな整数を持たない言語ではオーバーフローしてしまいます。 ここでは Python は安全ですが、式の導出は依然として重要です。 

## アプローチ

 ブルートフォースのアイデアは単純です。 すべてのプレフィックスの合計を計算します`s[i]`次に、すべてのペアを反復処理します。`(i, j)`と`i < j`、乗算と累積`s[i] * s[j]`。 これは定義と正確に一致するため、正しいです。 ただし、すべてのプレフィックスの合計を保存し、大まかに実行する必要があります。`N^2 / 2`掛け算。 と`N = 30000`、これでは遅すぎます。 

重要な点は、実際にはペアを列挙する必要がないということです。 私たちが求める表現は、$$\sum_{i < j} s_i s_j$$は、シーケンスにわたる標準の対称合計です。 ID を使用して書き換えることができます$$\left(\sum s_i\right)^2 = \sum s_i^2 + 2 \sum_{i < j} s_i s_j.$$これにより、プレフィックスの合計の合計とそれらの二乗の合計の両方を計算できれば、ペアごとの合計が線形時間で計算できるものに変換されます。 

問題は、プレフィックスの合計をオンラインで維持することに帰着します。 プレフィックス配列全体を明示的に保存する必要さえありません。 計算できる`s[i]`オンザフライで、すべてのプレフィックス合計の累計とその二乗の累計を保持します。 

これら 2 つのアキュムレータを取得したら、上記の恒等式を使用して答えを再構築できます。 モジュラスは 2 のべき乗であるため、2 による除算は安全であり、このシステムでは 2 の逆モジュラがビット シフトとして存在します。

 ## アルゴリズムのチュートリアル

 現在のプレフィックスの合計を維持しながら、配列を左から右に処理します。 

1. から始める`pref = 0`、`sum_pref = 0`、 そして`sum_sq = 0`。 これらは、現在のプレフィックス合計、これまでに確認されたすべてのプレフィックス合計の合計、およびそれらの二乗の合計を表します。 
2. 各要素について`a[i]`、 アップデート`pref += a[i]`。 これにより、位置で終わるプレフィックスの合計が生成されます。`i`。 
3. この新しいプレフィックス合計を`sum_pref`。 これにより追跡が行われます$\sum s_i$。 
4. プレフィックスの合計の 2 乗を加算します。`sum_sq`。 これにより維持されます$\sum s_i^2$。 
5. すべての要素を処理した後、計算します`total = sum_pref * sum_pref`。 これは等しい$(\sum s_i)^2$。 
6. 次を使用してペアごとの寄与を抽出します。`pair_sum = (total - sum_sq) // 2`。 
7. 最後に減らす`pair_sum`モジュロ`M`一貫してマスクまたは削減するように注意してください。`M`は 2 の累乗です。 

各ステップが有効である理由は、正確なプレフィックス合計を増分的に維持することからわかります。 完全な配列が必要になることはありません`s`、実行中の集計のみ。 

### なぜ効果があるのか

 正しさは、和の二乗の代数的分解に基づいています。 拡大中$(\sum s_i)^2$すべての対角項を生成します$s_i^2$そして、対角外の各ペアを 2 回ずつ実行します。 対角項を減算すると、目的の量のちょうど 2 倍が分離されます。 すべてのペアが 1 回だけ出現するため、`i < j`を 2 で割ると、必要な合計が得られます。 すべてのプレフィックス合計は実行中のアキュムレータで 1 回だけ計算されるため、用語の欠落や重複はありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))

    pref = 0
    sum_pref = 0
    sum_sq = 0

    for x in a:
        pref += x
        sum_pref += pref
        sum_sq += pref * pref

    total = sum_pref * sum_pref
    pair_sum = (total - sum_sq) // 2

    print(pair_sum % m)

if __name__ == "__main__":
    solve()
```実装は派生 ID に直接に従います。 プレフィックス合計は、プレフィックス配列全体の保存を避けるために段階的に更新されます。 2 つのアキュムレータは、必要な対称統計を追跡します。 最後の減算では交差項が分離され、整数の 2 による除算は除算前に式が偶数であることが保証されているため安全です。 

微妙な点は、すべての算術演算が Python 整数で行われるため、オーバーフローが問題にならないことです。 アイデンティティの正確さを維持するには中間値が完全な精度で必要とされるため、係数は最後にのみ適用されます。

 ## 特殊なケース

 のために`N = 1`、アルゴリズムセット`pref`単一の要素に追加されますが、プレフィックスの合計は 1 つしかないため、`sum_sq`等しい`sum_pref^2`、作る`(total - sum_sq)`ゼロと除算後の出力ゼロ。 これは、ペアが存在しないことと正確に一致します。 

のような配列の場合`0 0 0`、すべてのプレフィックスの合計はゼロのままです。 両方`sum_pref`そして`sum_sq`全体を通してゼロのままであるため、最終的な式は特別な処理を行わなくてもゼロと評価されます。 

より大きな値の場合、`a = [1, 2, 3, 4]`、プレフィックスの合計は次のように増加します`1, 3, 6, 10`。 アルゴリズムはそれらの二乗と和をそれぞれ 1 回だけ正確に累積し、恒等式により、これら 4 つの値のすべてのペアの積が再構築された式で正確に 1 回カウントされることが保証され、順序付けやインデックス付けの問題が正確さに影響を与えないことが確認されます。
