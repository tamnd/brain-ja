 ## 解決策
 ## 問題の理解

 私たちは、用紙の長さを一連の連続したセグメントに分割する印刷所を与えられています。 各セグメントはページ数の範囲を表し、すべての範囲にはページあたりの固定コストがかかります。 ジョブが範囲内に収まる場合は、そのページあたりのコストで印刷できますが、落とし穴があります。顧客は、合計ページ数が元の長さ以上の任意の値になるようにドキュメントに追加の空白ページを埋め込み、その埋め込まれたサイズをカバーする範囲を選択することができます。 

目標は、正確なドキュメントから始めることです。$k$ページ数を増やし、必要に応じてそれをさらに大きな数に増やしてから、最終ページ数が完全に含まれる間隔を持つ 1 つのセグメントを選択します。 コストはページごとであるため、コストはセグメントのコストに選択したページ数を乗算したものになります。 タスクは、この合計支払額を最小限に抑えるか、実現可能なパディング長に対応できるセグメントが存在しないことを判断することです。 

入力の構造は重要です。セグメントは昇順で与えられ、ギャップや重複がなく、1 から始まる数直線を完全に分割します。 これは、すべての正の整数のページ数が 1 つのセグメントに属することを意味します。 

この制約により、線形または線形に近い解決策が求められます。 と$n \le 10^5$、 どれでも$O(n^2)$すべての選択肢を試したり、セグメントごとにパディングの決定をシミュレートしたりする戦略は、すぐに遅すぎます。 重要な隠れた制約は次のとおりです。$k \le 10^9$これにより、明示的な配列またはページ上の DP を構築できなくなります。 

最良のセグメントが単に次のものを含むセグメントであると仮定すると、単純な間違いが発生します。$k$。 パディングを使用すると、ページあたりのコストがはるかに小さくなる可能性がある後のセグメントに移動できるため、これは不正確です。 

別の微妙な失敗例は、直後にセグメントが開始されるときに発生します。$k$、さらに右側には安価なセグメントが存在します。 たとえば、後でセグメントのコストが大幅に減少する場合、最適な戦略はページ数をこれまで以上に増やすことです。$k$その安価なセグメントに到達するまで。 

最後に、パディング後にセグメントを混合するのではなく、単一のセグメントを選択していることを忘れがちです。 

## アプローチ

 ブルートフォースアプローチでは、最終的な選択としてすべてのセグメントが試行されます。 各セグメントごとに$[a_i, b_i]$、パディングによって到達できるかどうかを確認します。つまり、必要があることを意味します$b_i \ge k$。 もしそうなら、どれでも選ぶことができます$x \in [\max(k, a_i), b_i]$、コストは$x \cdot c_i$。 セグメント内の最良の選択は常に実行可能な最小値です$x$コストはページ数に応じて直線的に増加するためです。 したがって、セグメントごとに次のように計算します。$$x_i = \max(k, a_i), \quad \text{cost}_i = x_i \cdot c_i$$すべての有効なセグメントの最小値を取得します。 

これは正しいですが、すでに$O(n)$、それは問題ありません。 ただし、この構造にはさらに重要な観察結果が隠されています。セグメントは連続していて並べ替えられているため、最良の答えを維持しながら 1 回のパスで処理できます。 重要な考え方は、以前のセグメントを再検討する必要はなく、特定の範囲について現在のセグメント以上のことを考慮する必要はないということです。$k$。 

本当に微妙なのは、パディングが許可されているため、効果的な決定がどこに行われるかに関連付けられていないことです。$k$最初は嘘をつきます。 基本的にブレークポイントを選択しています$x \ge k$、その後支払い$x \cdot c(x)$、 どこ$c(x)$区間にわたるセグメントコスト関数です。 

この関数はセグメント全体では区分的に一定であり、各セグメント内では線形であるため、各セグメントを 1 回チェックするだけで十分です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n) | お(1) | 承認済み |
 | 最適 | O(n) | お(1) | 承認済み |

 実際、「最適な」ソリューションは、正しく定式化されればクリーン総当たりと同じですが、間隔ロジックを使用して慎重に実装されます。 

## アルゴリズムのチュートリアル

 1. 変数を初期化する`answer`無限のように。 これにより、すべての有効な選択肢にわたって可能な最小コストが追跡されます。 
2. 各セグメントを反復処理します。$[a_i, b_i]$費用がかかる$c_i$。 セグメントは互いに素であり、すべての整数をカバーするため、考えられる最終ページ数はそれぞれ 1 つのセグメントに属し、各セグメントは 1 回だけ考慮される必要があります。 
3. セグメントが実際に使用できるかどうかを確認します。 ページを増やすことしかできないため、最終的なページ数は少なくとも$k$。 もし$b_i < k$の場合、セグメントには実現可能な最終サイズを含めることができないため、無視されます。 
4. セグメントが使用可能な場合は、そのセグメント内の最適なページ数を決定します。 実現可能な最小ページ数は次のとおりです。$\max(k, a_i)$、下には行けないので$k$パディングのため、セグメント開始より下に進むことはできません。 
5. コストを次のように計算します。$\text{pages} \times c_i$。 ページの増加はコストを直線的に増加させるだけであるため、これはセグメント内で最適です。 
6. 全体的な最小の答えを更新します。 
7. すべてのセグメントを処理した後、回答が更新されなかった場合は、出力$-1$。 それ以外の場合は、計算された最小値を出力します。 

### なぜ効果があるのか

 重要な不変条件は、実現可能なすべての最終ページ数が正確に 1 つのセグメントに属し、セグメント内ではコスト関数がページ数において単調であることです。 これにより、セグメント内の最適な選択は常にその左端の実行可能な点になります。 すべての有効な最終状態は、正確に 1 つのセグメントとその中の 1 つの選択肢によって表されるため、すべてのセグメントをスキャンして最良の局所最適を取得することで、グローバル最適が保証されます。 実現可能条件を超えるとセグメント間の相互作用は存在しない$b_i \ge k$なぜなら、パディングはページ数を増やすだけであり、それを考慮せずにセグメントを強制的にスキップすることは決してないからです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    ans = 10**30

    for _ in range(n):
        a, b, c = map(int, input().split())

        if b < k:
            continue

        x = max(a, k)
        if x <= b:
            ans = min(ans, x * c)

    print(-1 if ans == 10**30 else ans)

if __name__ == "__main__":
    solve()
```このソリューションはセグメントを単一パスで処理し、これまでのところ最良の答えのみを維持します。 重要な詳細は次の計算です。`x = max(a, k)`、これは両方の制約を正しくモデル化しています: パディングは以下に減らすことはできません$k$、セグメントの境界内に留まらなければなりません。 

小切手`b < k`有効な最終サイズを含めることができないセグメントをフィルターします。 2番目の条件`x <= b`パディング後もセグメント内に留まるようにします。

 ## 特殊なケース

 主なエッジケースは次のような場合です$k$セグメントのはるか内側にありますが、最適な動きは前方にスキップすることです。 たとえば、後のセグメントのコストがはるかに低い場合、パディングは中間の高価なセグメントを飛び越える必要があります。 アルゴリズムは、選択肢を以下を含むセグメントに制限することがないため、これを処理します。$k$、すべてのセグメントを独立して評価します。 

別のエッジケースが発生するのは次の場合です。$k$すべてよりも大きいです$b_i$最後のセグメントを除いて。 この場合、最後のセグメントのみが候補に寄与し、アルゴリズムはそこからの値または$-1$それでも対応できない場合$k$。 

3 番目のケースは、最適値が正確に達成される場合です。$a_i$それよりも$k$。 式`max(a, k)`どちらかの制約を下回る値が誤って選択されることがないため、左境界ロジックは、次のような場合でも正しいままになります。$k$小さいです。
