 ## 解決策
 ## 問題の理解

 有限のマルチセットのトークンが入ったバッグが与えられます。 これらのトークンの中には特別な「ナイト」トークンもあり、残りは通常のトークンです。 プレイヤーはこのバッグから、交換することなく一定数のトークンを均一にランダムに引き出します。 

このタスクは、引かれたトークンの少なくとも 1 つがナイトである確率を計算することです。 

より具体的に言うと、サイズのサブセットをサンプリングしています。$m$大きな宇宙から$n$、正確にはどこに$k$要素は成功 (ナイト) としてマークされます。 サイズのすべてのサブセット$m$同様の可能性があります。 選択したサブセットがナイトのセットと交差する確率が必要です。 

制約は非常に小さいです。$n \le 20$そして$m \le 20$。 これは、組み合わせ列挙または二項係数を使用した直接計算で十分であることを直ちに示します。 近似、シミュレーション、または漸近的に最適化された組み合わせ論は必要ありません。 

微妙なエッジケースが現れるのは、$m \ge n$。 その状況では、すべてのトークンが引かれるため、確率は次のいずれかになります。$k > 0$、または 0 の場合$k = 0$。 もう一つのコーナーケースは、$k = 0$、騎士が存在しない場合、確率は当然のことながら 0 になります。$m$。 逆に、もし$k \ge 1$そして$m = n$、答えはまさに 1 です。 

単純なモンテカルロ シミュレーションでは収束が遅すぎて、精度の問題が発生します。 もう 1 つのよくある間違いは、抽出が独立であると仮定することです。これは、サンプリングには置換がないため、正しくありません。 

## アプローチ

 ブルートフォースアプローチは、サイズのすべてのサブセットを列挙することです。$m$から$n$要素を調べて、各サブセットに少なくとも 1 つのナイトが含まれているかどうかを確認し、有効なナイトの数を数えます。 サブセットの総数は$\binom{n}{m}$、最悪の場合、これは近くで最大化されます。$n = 20, m = 10$、与える$\binom{20}{10} = 184,756$。 これは、ブルートフォースを直接実行できるほど小さいため、正しさはすぐにわかります。 

しかし、強引な方法では問題の本当の構造が隠蔽されてしまいます。 重要な点は、個々の配置を考慮する必要はなく、抽選に含まれる騎士の数だけを考慮する必要があるということです。 有利なサブセットを直接カウントする代わりに、補数イベントを計算する方が簡単です。つまり、ゼロのナイトを描画します。 そのイベントはすべてを選択することに対応します$m$からのトークン$n-k$非騎士トークン。 これにより、問題は 1 つの組み合わせ比に限定されます。 

確率は次のようになります。$$P(\text{at least one knight}) = 1 - \frac{\binom{n-k}{m}}{\binom{n}{m}}$$という慣例で$\binom{a}{b} = 0$いつ$b > a$。 

この変換により、サブセットの列挙が完全に回避され、問題がいくつかの二項係数の評価に置き換えられます。

 | 補数 + 組み合わせ論 |$O(1)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 ### 段階的な計算

 1. 整数の読み取り$n$、$k$、 そして$m$。 これらはそれぞれ、合計プール、成功数、サンプル サイズを定義します。 
2. 些細なケースを最初に処理します。 もし$k = 0$、成功要素が存在しないため、すぐに 0 を返します。 もし$m \ge n$、場合は 1 を返します$k > 0$これにより、後で無効な組み合わせ式が回避されます。 
3. ナイト以外のトークンの数を計算します。$n - k$。 これは「安全専用」プールを表します。 
4. 非ナイトのみを引く確率を計算します。これは次のとおりです。$$\frac{\binom{n-k}{m}}{\binom{n}{m}}$$この比率は、すべてを選択したことを反映しています。$m$騎士以外からの限定アイテム。 
5. この値を 1 から減算して、少なくとも 1 人の騎士が存在する確率を求めます。 
6. 結果を十分な精度で出力します。通常は 1e-4 の精度要件を満たすために少なくとも小数点以下 8 桁です。 

### なぜ効果があるのか

 アルゴリズムは可能な限りすべてを分割します$m$のサイズのサブセットを、少なくとも 1 人のナイトを含むものとまったく含まないものという 2 つの独立したカテゴリに分類します。 これら 2 つのイベントは、重複することなくサンプル空間全体をカバーします。 補完イベント「騎士が選ばれていない」は、選択がサイズの縮小されたサブセットに完全に制限されるため、数えやすくなります。$n-k$。 サイズのすべてのサブセット$m$可能性が等しい場合、確率は正確に有利なサブセット数の比率となり、正確性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from math import comb

def solve():
    n, k, m = map(int, input().split())

    if k == 0:
        print("0.0")
        return

    if m >= n:
        print("1.0")
        return

    total = comb(n, m)
    if n - k < m:
        no_knight = 0
    else:
        no_knight = comb(n - k, m)

    ans = 1.0 - no_knight / total
    print(f"{ans:.10f}")

if __name__ == "__main__":
    solve()
```この実装は、これらの制約に対して安定していて正確な Python の組み込みの組み合わせ関数に直接依存しています。 初期の出口は、二項係数が素朴な意味でゼロまたは未定義になるような退化したケースを処理します。 

唯一の微妙な点は、ケースを正しく処理することです$n-k < m$、選択することが不可能な場合$m$非ナイトの場合、「ナイトなし」の確率はゼロになります。

## テストケース```python
import sys, io
from math import comb

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, k, m = map(int, input().split())

    if k == 0:
        return "0.0000000000"
    if m >= n:
        return "1.0000000000"

    total = comb(n, m)
    no_knight = comb(n - k, m) if n - k >= m else 0
    ans = 1.0 - no_knight / total
    return f"{ans:.10f}"

# provided samples

# custom cases
assert run("5 0 3") == "0.0000000000"
assert run("5 5 2") == "1.0000000000"
assert run("5 1 5") == "1.0000000000"
assert run("6 3 1") == "0.5000000000"

 ## 特殊なケース

 重要なエッジケースの 1 つは、ナイトがいない場合です。 入力用`5 0 3`の場合、アルゴリズムは組み合わせ論の前にすぐに 0 を返します。 これを忘れた数式ベースの実装でも比率を計算できますが、除算アーティファクトや不必要な計算が発生する危険があります。 

もう 1 つのケースは、ドロー サイズがバッグ サイズと等しい場合です。次のような場合です。`5 2 5`。 ナイトが少なくとも 1 つ存在する場合、ナイトの選択を避ける方法がないため、補完確率はゼロになります。 アルゴリズムは正しくトリガーします`m >= n`分岐して 1 を返します。 

3 番目のケースは、非ナイトが少なすぎて描画サイズを満たすことができない場合に発生します。 例えば、`6 4 4`残るは騎士以外の2人のみ。 計算`comb(2,4)`はゼロとして扱われ、すべての有効なドローにはナイトが含まれている必要があることを正しく意味し、確率は 1 になります。
