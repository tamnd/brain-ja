 ## 解決策
 ## 問題の理解

 正確に接続された無向グラフが与えられます。$N$頂点と$N$エッジ。 各エッジは、2 つの島間の双方向のフェリー ルートを表します。 エッジの数が頂点の数と同じであっても、グラフは接続されたままであることが保証されます。 

タスクは、グラフの接続を維持しながら、どのフェリー ルートを削除しても安全かを判断することです。 ルートを削除した後も、残りのルートを介してすべての島が他のすべての島に到達できる場合、そのルートは安全であるとみなされます。 

グラフの用語では、ブリッジではないすべてのエッジを見つけるように求められます。 ブリッジは、削除するとグラフが切断されるエッジです。 選択したエッジを削除した後も接続を維持したいので、ブリッジではないエッジがまさに有効な答えになります。 

制約は大きく、$N \le 10^5$。 これにより、コストがかかるため、各エッジを削除し、DFS または BFS を使用して完全な接続チェックを実行しようとするアプローチが即座に除外されます。$O(N^2)$最悪の場合、許容範囲をはるかに超えます。 ソリューションは線形または線形に近いものでなければなりません。通常、$O(N)$または$O(N \log N)$。 

微妙なエッジ ケースは、サイクルおよびマルチサイクル構造の存在によって発生します。 グラフには正確に$N$エッジが接続されている場合、少なくとも 1 つのサイクルが含まれている必要があります。 グラフが単一サイクルの場合、エッジを削除してもすべてのノードを接続するパスが残ります。 その場合、すべてのエッジが有効になります。 グラフにブリッジが含まれている場合、サイクル内のエッジのみが有効のままになります。 

単純な落とし穴は、そのサイクルがそのエッジに接続性を依存するより大きな構造の一部であるかどうかを検証せずに、サイクル内のエッジを削除することが常に安全であると仮定することです。 たとえば、単一のエッジで接続された 2 つのサイクルのような形状のグラフでは、その接続エッジは、循環コンポーネントの間にある場合でもブリッジになります。 

## アプローチ

 直接的な総当たりアプローチは、すべてのエッジを個別にテストすることです。 各エッジについて、エッジを削除し、任意のノードから DFS または BFS を実行して、すべてのノードがまだ到達可能かどうかを確認します。 これにより、削除後の接続がそのプロパティを直接エンコードするため、エッジがブリッジであるかどうかが正しく識別されます。 

ただし、接続チェックにはそれぞれ費用がかかります$O(N)$、そして私たちはそれを実行します$N$エッジ、与える$O(N^2)$合計時間。 と$N = 10^5$、これは次のようになります$10^{10}$実行不可能な操作。 

重要な観察は、問題が無向グラフ内のブリッジの識別に帰着するということです。 これは、検出時間と低リンク値を備えた DFS を使用して線形時間で計算できる古典的な構造プロパティです。 このアイデアは、DFS トラバーサル中に、バック エッジを使用して各ノードの最も早く到達可能な祖先を追跡することです。 エッジがその親サブツリーのどの祖先にも到達できない場合、それはブリッジです。 

これは、グラフが確実に接続されており、正確に一致しているため、ここでは特にうまく機能します。$N$しかし、ブリッジ検出アルゴリズムはその事実に依存しません。 これは、以下の任意の無向グラフに対して機能します。$O(N + M)$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (エッジの削除 + BFS) |$O(N^2)$|$O(N)$| 遅すぎる |
 | DFS ローリンク ブリッジの検出 |$O(N)$|$O(N)$| 承認済み |

 ## アルゴリズムのチュートリアル

 タイムスタンプを使用した DFS トラバーサルを使用してすべてのブリッジを検索することで、この問題を解決します。 

1. グラフの隣接リストを構築し、各エッジの識別子 (インデックス) を保存します。 頂点が繰り返される場合でも、複数のエッジを区別する必要があるため、エッジ ID が必要です。 
2. 配列を維持する`tin`そして`low`、 どこ`tin[v]`ノードの時刻です$v$最初に DFS にアクセスし、`low[v]`最小です`tin`から到達可能$v$0 個以上のツリー エッジと、それに続く最大 1 つのバック エッジを使用します。 これを追跡する理由は、サブツリーが特定のエッジを使用せずに上方に「逃げる」ことができるかどうかを検出するためです。 
3. グラフが接続されているため、任意のノードから DFS を実行します。 ノードにアクセスするたびに増加するタイムスタンプを割り当てます。 
4. ノードからの DFS 時$v$、それぞれの隣人を探索します$to$。 もし`to`は DFS の親であるため、些細な後戻りを避けるためにスキップします。 
5. もし`to`未訪問の場合、再帰的に DFS でアクセスし、更新します`low[v] = min(low[v], low[to])`。 返却後、確認してください`low[to] > tin[v]`。 これが当てはまれば、エッジは$(v, to)$サブツリーのルートがブリッジであるため、 はブリッジです。`to`の祖先には到達できません$v$このエッジを使用せずに。 
6. もし`to`はすでに訪問されており、親エッジではないため、更新します`low[v] = min(low[v], tin[to])`。 これによりバックエッジが記録され、到達可能性が向上します。 
7. DFS が完了すると、ブリッジとしてマークされなかったすべてのエッジは、まさにその削除によってグラフの接続が維持されるエッジとなるため、これらを出力します。 

### なぜ効果があるのか

 DFS ツリーは、エッジをツリー エッジとバック エッジに分割します。 をルートとするサブツリー$to$エッジを削除した後もグラフの残りの部分と接続されたままになります$(v, to)$それが何らかの祖先に到達するバックエッジを持っている場合に限り、$v$。 の`low`value は、到達可能なそのような上位の祖先を取得します。 もし`low[to]`厳密には次より大きいです`tin[v]`の場合、サブツリーからのバック エッジは到達しません。$v$以上。グラフの残りの部分との唯一の接続がエッジであることを意味します。$(v, to)$。 これはまさに橋の定義であり、必要条件であり十分条件でもあります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

n = int(input())
adj = [[] for _ in range(n)]

edges = []

for i in range(n):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    adj[u].append((v, i))
    adj[v].append((u, i))
    edges.append((u, v))

tin = [-1] * n
low = [0] * n
vis = [False] * n
is_bridge = [False] * n
timer = 0

def dfs(v, pe):
    global timer
    vis[v] = True
    tin[v] = low[v] = timer
    timer += 1

    for to, eid in adj[v]:
        if eid == pe:
            continue
        if tin[to] == -1:
            dfs(to, eid)
            low[v] = min(low[v], low[to])
            if low[to] > tin[v]:
                is_bridge[eid] = True
        else:
            low[v] = min(low[v], tin[to])

dfs(0, -1)

res = []
for i in range(n):
    if not is_bridge[i]:
        u, v = edges[i]
        res.append((u + 1, v + 1))

print(len(res))
for u, v in res:
    print(u, v)
```この実装では、グローバル タイマーを備えた標準の再帰的 DFS を使用して、検出時間を割り当てます。 各エッジはインデックスによって追跡されるため、後でエッジをブリッジとしてマークするかどうかを指定できます。 配列`is_bridge`どのエッジを出力セットから削除する必要があるかを格納します。 

微妙な点の 1 つは、DFS でのエッジ ID を使用した親エッジの処理です。`pe`。 これにより、DFS ツリーの直接のエッジがバック エッジとして誤って扱われるのを防ぎます。 もう 1 つの重要な詳細は再帰の深さです。$10^5$ノードでは再帰制限を増やす必要があります。 

最後に、グラフは接続されていることが保証されているため、ノード 0 からの 1 回の DFS 呼び出しで十分です。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline
    sys.setrecursionlimit(10**7)

    n = int(input())
    adj = [[] for _ in range(n)]
    edges = []

    for i in range(n):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        adj[u].append((v, i))
        adj[v].append((u, i))
        edges.append((u, v))

    tin = [-1] * n
    low = [0] * n
    is_bridge = [False] * n
    timer = 0

    def dfs(v, pe):
        nonlocal timer
        tin[v] = low[v] = timer
        timer += 1
        for to, eid in adj[v]:
            if eid == pe:
                continue
            if tin[to] == -1:
                dfs(to, eid)
                low[v] = min(low[v], low[to])
                if low[to] > tin[v]:
                    is_bridge[eid] = True
            else:
                low[v] = min(low[v], tin[to])

    dfs(0, -1)

    out = []
    for i in range(n):
        if not is_bridge[i]:
            u, v = edges[i]
            out.append((u+1, v+1))

    return str(len(out)) + "\n" + "\n".join(f"{u} {v}" for u, v in out)

 ## 特殊なケース

 純粋なサイクルは最も単純なエッジケースです。 このようなグラフでは、すべてのノードに、単一のエッジを回避する他のすべてのノードへの代替ルートがあります。 DFS 中に、すべてのノードは以前の祖先へのバック エッジを見つけます。`low`値は可能な限り最小値に折りたたまれ、ブリッジ条件がトリガーされるのを防ぎます。 アルゴリズムはすべてのエッジを安全であると正しくマークします。 

追加のエッジが 1 つだけあるツリー状構造も、重要なケースです。 線を考えてみる$1-2-3-4-5$追加のエッジをプラス$2-4$。 ライン上のエッジはほとんどがブリッジですが、弦はノード 2、3、4 の周囲にサイクルを作成します。DFS は、このサイクル内のエッジがブリッジ条件を満たさないことを検出しますが、外側のエッジは依然としてブリッジ条件を満たしています。 出力には、非ブリッジ エッジのみが正しく含まれています。 

最後の微妙なケースは、頂点に重複するサイクルを形成する複数の接続がある場合です。 アルゴリズムはこれを自然に処理します。`low`値は到達可能な最小の祖先を伝播し、サブツリー内の任意の場所にある代替パスがそのパスに沿ったすべてのエッジのブリッジ分類を確実に防止します。
