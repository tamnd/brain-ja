 ## 解決策
 ## 問題の理解

 1 から 1 までの番号が付けられた頂点を持つ根付きツリーが与えられます。$n$、ここで頂点 1 はルートです。 各頂点は 0 個以上の子を持つことができ、入力は頂点を接続するエッジを指定します。 タスクは、ツリーが対称かどうかを判断することです。 各ノードの子の順序を変更した後、左端と右端のサブツリーが鏡像、左から 2 番目と右から 2 番目のサブツリーが鏡像などになる場合、ツリーは対称です。 ノードに奇数の子がある場合、中央の子のサブツリー自体が対称でなければなりません。 

入力は複数のテスト ケースで構成されます。 各テスト ケースは、最大で次のツリーを記述します。$2 \cdot 10^5$頂点。 テスト ケース全体のすべての頂点の合計は次のように制限されるため、$2 \cdot 10^5$、どのソリューションも、テスト ケースごとのノード数が線形である必要があります。 アルゴリズムを使用$O(n^2)$複雑さは遅すぎます。 単純にサブツリーをスキャンして繰り返し比較することを避けなければなりません。 メモリ使用量も妥当な範囲内に抑える必要があります。$O(n)$テストケースごとに。 

明白でないエッジ ケースには、単一ノードのツリー、完全に線形のチェーン、または子の順序を変更した後にのみ対称性が達成されるツリーが含まれます。 たとえば、ルートに回文形の子があるが、サブツリー自体が異なるツリーは、NO を返さなければなりません。 不注意な実装では、サブツリー構造ではなく子の数だけをチェックする可能性があります。 

## アプローチ

 ブルートフォースアプローチは、すべてのノードで子の可能な順列をすべて試し、対称的な順序が存在するかどうかを確認することです。 各ノードについて、サブツリーのすべてのペアを再帰的にチェックし、一方が他方のミラー イメージであるかどうかを計算します。 これは原理的には正しいですが、すべての順列を生成すると子の数が階乗的に複雑になるため、多くの子を持つノードでは実行できません。 順列なしで再帰的な比較を試みたとしても、サブツリー構造を単純に比較すると、同じ結果が繰り返される可能性があります。$O(n)$ノードごとの走査数、結果として$O(n^2)$時間。 

重要な観察は、サブツリーの対称性がハッシュ問題に帰着できるということです。 子の順序とは無関係で、ミラー構造をキャプチャする各サブツリーの構造署名またはハッシュを計算できれば、対称性のチェックはハッシュの単純な比較になります。 ノードの場合、すべての子のハッシュを再帰的に計算し、これらのハッシュを並べ替え (またはミラー順で比較)、サブツリーを表す単一のハッシュに結合できます。 2 つのサブツリーは、子のハッシュ リストが互いに逆の場合、鏡像になります。 

決定論的ハッシュ関数 (たとえば、ソートされた子ハッシュのタプル) を使用できます。 これらのハッシュをリーフからルートまで再帰的に伝播することで、問題を次のように軽減します。$O(n)$木ごとに。 このアプローチは、反復的な走査を回避し、任意の子の順序付けを処理します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース順列 | ノードあたり O(n!) | O(n) | 遅すぎる |
 | 再帰的サブツリー ハッシュ | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ツリーを頂点 1 をルートとする隣接リストとして表します。これにより、子の効率的な走査が可能になります。 
2. 再帰関数を定義する`hash_tree(node)`をルートとするサブツリーの構造ハッシュを返します。`node`。 リーフの場合、ハッシュは次のような固定値になります。`()`。 
3. 非リーフ ノードの場合、各子のハッシュを再帰的に計算します。 子ハッシュのリストを保存します。 
4. 子ハッシュをソートし、逆になった子ハッシュも考慮します。 ソートされたリストがその逆のリストと等しい場合、サブツリーは対称になります。 それ以外の場合はそうではありません。 
5. 多数の子を効率的に処理するには、子のハッシュをタプルまたは文字列に変換し、ハッシュ可能な構造で使用します。 
6. 現在のノードの構造と子の対称性をエンコードするハッシュを返します。 簡単なアプローチは、子ハッシュのリストをタプルに変換することです。`tuple(child_hashes)`。 これにより、同一のサブツリー構造を持つノードが同一のハッシュを生成することが保証されます。 
7. ルートで、計算されたハッシュに基づいてサブツリーが対称かどうかを確認します。 そうであれば YES を出力し、そうでない場合は NO を出力します。 

機能する理由: 再帰的ハッシュにより、各サブツリーがその構造によって確実に一意に表現されます。 対称性チェックは、ミラー化された順序で子ハッシュを比較することに帰着します。 再帰はすべてのノードをカバーし、その子ハッシュを決定的に結合するため、非対称性はミラーリングされたハッシュが異なる最初のレベルで検出されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(1 << 20)

def solve():
    t = int(input())
    results = []
    
    for _ in range(t):
        n = int(input())
        tree = [[] for _ in range(n + 1)]
        for _ in range(n - 1):
            u, v = map(int, input().split())
            tree[u].append(v)
            tree[v].append(u)
        
        def dfs(node, parent):
            child_hashes = []
            for child in tree[node]:
                if child == parent:
                    continue
                child_hashes.append(dfs(child, node))
            
            # Check symmetry
            left = 0
            right = len(child_hashes) - 1
            while left < right:
                if child_hashes[left] != child_hashes[right]:
                    return None  # Asymmetrical subtree
                left += 1
                right -= 1
            
            # Hash for this node: tuple of sorted children
            return tuple(sorted(child_hashes))
        
        result = dfs(1, 0)
        results.append("YES" if result is not None else "NO")
    
    print("\n".join(results))

solve()
```隣接リストにより、各ツリーを線形時間で走査できることが保証されます。 の`dfs`この関数は、ミラー化された子の同等性をチェックしながらサブツリー ハッシュを再帰的に計算します。 子のペアがミラーリングされていない場合、関数は戻り値を返します。`None`、上に伝播し、非対称性を示します。 子ハッシュをソートすると、さまざまな子の順序間で一貫性が保証されます。 再帰的な深さは次のように制限されます。`sys.setrecursionlimit`深い木を扱うため。 

## 実用的な例

 最初のサンプル入力の場合:```
6
1 5
1 6
1 2
2 3
2 4
```

`dfs(1)`子供たちを見る`[5, 6, 2]`。 ノード 5 と 6 はリーフなので、ハッシュは次のようになります。`()`。 ノード 2 には子があります`[3,4]`、葉であり、ハッシュを与えます`(() , ())`。 ミラーリングされたチェックは 5 と 2 を比較します。ハッシュをソートした後、ノードは対称性を通過するため、出力は YES になります。 

2 番目のサンプルの場合:```
7
1 5
1 3
3 6
1 4
4 7
4 2
```

`dfs(1)`子供たちを見る`[5,3,4]`。 子ハッシュが異なり、ミラーリングされた比較は失敗するため、出力は NO になります。 

| ノード | 子ハッシュ | 対称性チェック | 返されたハッシュ |
 | --- | --- | --- | --- |
 | 3 | [6] -> [()] | 一人っ子 | ((),) |
 | 4 | [7,2] -> [(),()] | ミラー OK | ((),()) |
 | 1 | [5,3,4] -> [(),((),),((),())] | 左と右は異なります | なし |

 ## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各ノードは 1 回訪問され、子ハッシュはノードごとに線形的に比較されます。 
| スペース | O(n) | n に比例する隣接リストと再帰スタック |

 すべてのテスト ケースで n ≤ 2 × 10^5 を指定すると、アルゴリズムは 2 秒以内、メモリ制限 256 MB 以内で簡単に実行されます。
