 ## 解決策
 ## 問題の理解

 同じ長さの 2 つの文字列があります。`s`そして`t`。 から始まる`s`、位置が正確に異なる文字を繰り返し交換する場合があります。`k`または正確に`k + 1`。 問題は、これらの許可されたスワップが変革を起こすほど強力であるかどうかです。`s`の中へ`t`。 

任意の位置を交換することはできないため、この操作は異例です。 許可されるスワップは、文字列の位置に関するグラフを定義します。 位置`i`ポジションにつながっている`j`もし`|i - j| = k`または`|i - j| = k + 1`。 すべてのスワップは、このグラフの 1 つのエッジに沿って発生します。 

文字列の長さは次のとおりです`2 · 10^5`、すべてのテスト ケースの合計の長さも`2 · 10^5`。 すべてのポジションのペアを検査するアルゴリズムは直ちに除外されます。 テスト ケースごとに線形に近い時間が必要です。 

いくつかの特殊なケースは見落とされがちです。 

考慮する：```
n = 5, k = 4
s = "abcde"
t = "ebcda"
```文字列にはまったく同じ文字が含まれています。 頻度チェックだけでは「YES」と言えます。 しかし、位置`0`位置でのみ交換できます`4`、位置を維持しながら`1`、`2`、 そして`3`孤立している。 中間位置は移動できないため、文字数が一致していても答えは「NO」になる可能性があります。 

もう 1 つの重要なケースは、グラフが接続されるときに発生します。```
n = 7, k = 1
```許容される距離は次のとおりです`1`そして`2`。 距離`1`すでに隣接する位置を接続しているため、すべての順列が到達可能になります。 この状況では、複数の文字セットのみが問題になります。 

3 番目のトラップは、エッジで接続されていない位置は移動できないと仮定することです。 直接的なエッジではなく、接続性が重要です。```
n = 5, k = 3
```ポジション`0`そして`4`は直接接続されていませんが、両方とも中間頂点を介して同じ接続コンポーネントに属しています。 キャラクターは一連の交換を経て移動できます。 

## アプローチ

 ブルートフォースソリューションでは、到達可能なすべての文字列を明示的に構築します。`s`順列の状態空間に対して BFS を使用します。 すべての有効な変換は一連のスワップに対応するため、これは正しいです。 残念ながら、中程度の場合でも、`n`、到達可能な状態の数は階乗的に増加します。 長さ 20 の文字列には、どのプログラムでも探索できるよりもはるかに多くの状態がすでに含まれています。 

重要な観察は、操作がポジションにのみ作用するということです。 実際の文字は、どのスワップが合法であるかには影響しません。 

位置をグラフの頂点と考えてください。 間にエッジを追加します`i`そして`j`いつでも`|i-j| = k`または`|i-j| = k+1`。 許可されたスワップでは、一方のエッジを越えて文字が交換されます。 

このグラフの連結成分内では、任意の並べ替えが可能です。 エッジの交換が可能な接続されたグラフでは、頂点のすべての順列が生成されます。 キャラクターはパスに沿ってルーティングできるため、コンポーネント内のあらゆる再配置を実現できます。 

これにより問題は完全に変わります。 文字列を検索する代わりに、位置グラフの接続コンポーネントを決定するだけで済みます。 

各連結成分について、由来する文字のマルチセット`s`が要求する複数の文字セットと一致する必要があります`t`。 すべてのコンポーネントがこの条件を満たしていれば、変換は可能です。 そうでなければそうではありません。 

グラフに含まれるのは次のとおりです`O(n)`各頂点には最大 4 つの隣接頂点があるため、エッジに対応します。`±k`そして`±(k+1)`。 これにより、線形時間の DFS または DSU ソリューションが可能になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 到達可能な文字列に対するブルート フォース | 指数 | 指数 | 遅すぎる |
 | 接続コンポーネント + 周波数チェック | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 位置に基づいてグラフを構築する`0 ... n-1`。 
2. ポジションごとに`i`と接続してみます。`i+k`、`i-k`、`i+k+1`、 そして`i-k-1`それらのポジションが存在するときはいつでも。 
3. DFS、BFS、または DSU を使用して、接続されているすべてのコンポーネントを検索します。 
4. コンポーネントごとに、`s`そのコンポーネント内にあります。 
5.のキャラクターを集めてください`t`同じコンポーネント内にあります。 
6. 両方のコレクションを並べ替えて比較します。 
7. いずれかのコンポーネントが異なるマルチセットを生成する場合、出力`"NO"`。 
8. すべてのコンポーネントが一致する場合、出力`"YES"`。 

ステップ 6 が機能する理由は、1 つの接続コンポーネント内で文字を任意に並べ替えることができるためです。 唯一不変なのは、そのコンポーネント内に各文字のコピーが何個存在するかです。 

### なぜ効果があるのか

 すべてのスワップでは、各位置を含む連結成分が保持されます。 許可された移動はすべてそのコンポーネント内のエッジに沿って行われるため、キャラクターはそのコンポーネントから離れることはできません。 

したがって、すべてのコンポーネントについて、そこに含まれる複数の文字セットはプロセスの不変条件となります。 

逆もまた真です。 接続されたグラフのエッジに沿った隣接するスワップにより、そのグラフ内の頂点のあらゆる置換が生成されるため、コンポーネントの文字の任意の配置を実現できます。 マルチセットがコンポーネントごとに一致すると、ターゲット文字列に一致するように各コンポーネントを個別に再配置できます。 

コンポーネントのマルチセット条件は必要かつ十分であり、正確さを証明します。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n, k = map(int, input().split())
        s = input().strip()
        target = input().strip()

        adj = [[] for _ in range(n)]

        for i in range(n):
            for d in (k, k + 1):
                j = i + d
                if j < n:
                    adj[i].append(j)
                    adj[j].append(i)

        vis = [False] * n
        ok = True

        for start in range(n):
            if vis[start]:
                continue

            q = deque([start])
            vis[start] = True
            comp = []

            while q:
                v = q.popleft()
                comp.append(v)

                for to in adj[v]:
                    if not vis[to]:
                        vis[to] = True
                        q.append(to)

            a = sorted(s[i] for i in comp)
            b = sorted(target[i] for i in comp)

            if a != b:
                ok = False
                break

        ans.append("YES" if ok else "NO")

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```グラフの構築では前方エッジのみが追加されます。 すべてのエッジが両方向に挿入されるため、グラフは無向のままであり、接続コンポーネントの検索は正常に機能します。 

よくある間違いは、グローバル文字頻度のみをチェックすることです。 ハード バージョンが存在するのは、全体の周波数が等しいだけでは十分ではないためです。 各接続コンポーネントは個別にチェックする必要があります。 

もう 1 つのよくあるバグは、すべてをビルドしようとすることです。`O(n²)`距離が次のペア`k`または`k+1`。 すべての頂点には一定数の有効な近傍のみがあるため、線形時間でグラフを構築できます。

## 特殊なケース

 いつ`k = 1`、すべての位置が隣接する位置に接続されます。 グラフがつながっていきます。 例えば：```
n = 5
s = abcde
t = edcba
```すべての位置は 1 つのコンポーネントに属します。 文字のマルチセットが一致するため、答えは次のようになります。`"YES"`。 

いつ`k`非常に大きいため、多くの位置が孤立します。```
n = 5
k = 4
s = abcde
t = aecdb
```位置`1`含まれています`b`で`s`しかし`e`で`t`。 以来の地位`1`は孤立したコンポーネントであるため、その性質は変更できません。 コンポーネント チェックでは、変換が即座に拒否されます。 

コンポーネントに複数の頂点が含まれる場合、直接エッジがなくても文字が中間位置を通過することがあります。```
n = 5
k = 3
```グラフはパスを介して接続されます。 キャラクターは、複数のスワップを使用して一方の端からもう一方の端に移動できます。 このアルゴリズムは、グラフ全体を 1 つのコンポーネントとして正しく処理し、コンポーネント全体のマルチセットのみを比較します。
