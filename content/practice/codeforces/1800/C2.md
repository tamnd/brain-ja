 ## 解決策
 ## 問題の理解

 一定の順序で配置された一連のカードが与えられ、それらを上から下に処理します。 各カードはヒーローまたはボーナスのいずれかです。 ヒーロー カードの価値はゼロで、我が軍に 1 人のヒーローを最終決定する機会を表します。 ボーナス カードはプラスの値を持ち、別の構造に一時的に保管できますが、後でヒーローに影響を与える方法でのみ保管されます。 

ヒーローカードが出現すると、すぐに軍隊のヒーローが形成されます。 その時点でボーナス カードを保存している場合は、保存されているボーナスの 1 つをこのヒーローに割り当てることができます。具体的には、最後に保存した、まだ保持することを選択したボーナスを割り当てます。 その後、そのボーナスは消費され、ストレージから削除されます。 ボーナスが保存されていない場合、ヒーローの貢献はゼロになります。 

目標は、ヒーロー カードが出現したときに、すべてのヒーローに割り当てられた合計ボーナス値が最大になるように、どのボーナス カードを保持するか破棄するかを選択することです。 

入力サイズはすべてのテスト ケースで合計 200,000 カードに達するため、ボーナスの保持または破棄のすべてのサブセットをシミュレートしようとするソリューションはすぐに失敗します。 テスト ケースごとの二次関数でさえ遅すぎるため、解は線形または線形に近いものでなければなりません。 

ボーナスは豊富だがヒーローがまばらだったり遅れたりする場合、微妙な問題が発生します。 たとえば、すべてのヒーローが早く出現し、ボーナスが後から来る場合、多くのヒーローが利用可能であっても、ボーナスは使用できません。 逆に、ヒーローが早く来て、初期のボーナスをあまりにも多く破棄した場合、後のヒーローは価値の高い割り当てを逃す可能性があります。 

常にすべてのボーナスを保持する単純な欲張りは、限られた数のヒーローのみがボーナスを使用できるため、多すぎると失敗します。 たとえば、ヒーローよりもボーナスが多い場合は、一部を破棄する必要がありますが、順序が重要であるため、どれを選択するかは簡単ではありません。 

## アプローチ

 強引なアイデアでは、すべてのボーナスについてそれを維持するかどうかを決定し、ヒーローに順番にボーナスを割り当てるシミュレーションを試みます。 各ボーナスは保持または破棄でき、各ヒーローは利用可能な保存されたボーナスを消費できるため、これにより選択肢が飛躍的に増加します。 枝刈りを行ったとしても、順序付けと選択の間の相互作用によって多くの有効な構成が作成されるため、状態空間は爆発的に増加します。 

重要な観察は、ヒーロー カードが「消費者」のように動作し、それぞれがすでに表示されているボーナスのプールから 1 つのボーナスだけを取得し、可能であれば利用可能な最高のものだけを使用する必要があるということです。 ボーナスはプラスなので、利用可能性を正しく管理すれば、より大きなボーナスを早期に使用しても、将来のヒーローに害を及ぼすことはありません。 難しいのは、一度に得られるボーナスが多すぎる可能性があるため、どれを保持するかを決定する必要があることです。 

これは古典的な「時間の経過とともに開く限られたスロットで選択したアイテムの合計を最大化する」問題になります。 各ヒーローは、以前に確認されたすべてのボーナスから選択された最大 1 つのボーナスを付加できるスロットを効果的に作成します。 逆に考えると、すべてのヒーローは、自分のポジションの前に利用できる可能な限り最高のボーナスを望んでいます。 

スタックを直接シミュレートする代わりに、候補ボーナスのプールを維持し、将来実際にヒーローに割り当てることができるボーナスのみを保持するようにします。 自然な構造は、ボーナスの最大構造を維持しながら配列を処理し、必要に応じて可能な限り最大のボーナスを各ヒーローに貪欲に割り当てることです。 

最も重要な洞察は、これまでにある程度の数のヒーローを見てきた場合、いかなる時点でも、その数を超えるボーナスを決して保持すべきではないということです。追加のボーナスは以前のヒーローによって使用されることはなく、将来のヒーローを獲得するためにのみ競合するためです。 これにより、問題は可能な限り最大のボーナスを選択し、それらを貪欲にヒーローに一致させることに減ります。

これを実装するには、ボーナスをヒープに収集し、ヒーローに遭遇したときに、これまでに利用可能な最高のボーナス (存在する場合) を確実に割り当てることができます。 これまでに見られたヒーローよりも多くのボーナスを蓄積した場合は、最も役に立たないため、最小のボーナスを破棄します。

 ## アルゴリズムのチュートリアル

 1. これまでに発生したすべてのボーナス値の最大ヒープ (または同等の構造) を維持しながら、カード シーケンスを左から右にトラバースします。 これは、現在割り当て可能なすべてのボーナスを表します。 
2. これまでに登場したヒーローの数を記録します。 各ヒーローは、将来の 1 つの任務の機会を表します。 
3. ボーナス カードを見つけたら、その値をヒープに挿入します。 これは、将来のヒーローが利用できるようになるということを意味します。 
4. 保存されているボーナスの数がそれまでに確認されたヒーローの数を超えた場合は、ヒープから最小のボーナスを削除します。 このステップにより、後でヒーローと一致させることができないボーナスが保存されることがなくなります。 どの割り当てにおいても、ボーナスが高いほど価値が高いため、削除されたボーナスは最終的な合計に寄与する可能性が最も低いものです。 
5. ヒーローカードに遭遇したら、ヒーローカウンターをインクリメントします。 次に、ヒープが空でない場合は、そこから最大のボーナスを取り出してこのヒーローに割り当て、合計スコアに追加します。 ボーナスは消費されているため、ヒープから削除します。 
6. シーケンスが終了するまでこのプロセスを続けます。 

余分な小さなボーナスを削除する背後にある理由は、使用できるボーナスはヒーローの数だけであり、可能な割り当てのセットの中で、より大きなボーナスを維持することが、より小さなボーナスを維持することよりも優先されるためです。 

### なぜ効果があるのか

 配列の任意の接頭辞で、h 人のヒーローと b 人のボーナスが確認されたとします。 最適な戦略において、最初の h 個のヒーローの間で最大 h 個のボーナスを使用できます。 b が h を超える場合、最適解は少なくとも b から h を引いたボーナスを破棄する必要があります。 ボーナスは値によってのみ異なり、順序以外の位置の制約がないため、保持されているボーナスをより大きなボーナスに置き換えることで合計を改善または維持することしかできないため、最小のものを破棄するのが最適です。 これにより、交換の議論が生じます。小さいボーナスを保持し、より大きいボーナスを破棄する解決策は、実現可能性を侵害することなく、それらを交換することで改善できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import heapq

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        # we store bonuses as negative values for max-heap behavior
        heap = []
        hero_count = 0
        total = 0
        
        for x in a:
            if x == 0:
                hero_count += 1
                if heap:
                    total += -heapq.heappop(heap)
            else:
                heapq.heappush(heap, -x)
                # discard excess small bonuses: keep at most hero_count items
                if len(heap) > hero_count:
                    heapq.heappop(heap)
        
        print(total)

if __name__ == "__main__":
    solve()
```この実装では、負の値のヒープを使用して、Python の最大ヒープをシミュレートします。 各ボーナスは見たらすぐに挿入されます。 重要なバランス調整ステップは挿入後に行われます。これまでのヒーローよりも多くのボーナスがある場合は、最小のボーナスを削除します。これは、最大の負の値をポップすることに対応します。 

ヒーローはカウントをインクリメントし、利用可能な最高のボーナスが存在する場合はすぐにそれを消費します。 これは、各ヒーローが出現した瞬間に可能な限り最強の保存ボーナスを割り当てられるべきであるという考えと一致します。 

よくある間違いは、ボーナスの割り当てを遅らせたり、完全な入力処理後にボーナスをペアリングしようとしたりすることです。 ヒーローの後に表示されるボーナスはヒーローに使用できないため、これにより順序の制約が破られます。

 | 測定 | 複雑さ | 説明 |

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import heapq

    def solve():
        t = int(sys.stdin.readline())
        out = []
        for _ in range(t):
            n = int(sys.stdin.readline())
            a = list(map(int, sys.stdin.readline().split()))

            heroes = 0
            total = 0

                if x == 0:

                    if len(heap) > heroes:
                        heapq.heappop(heap)
            out.append(str(total))
        return "\n".join(out)

    return solve()

 ## 特殊なケース

 すべてのヒーローがボーナスの前に出現すると、ヒーローの処理中にヒープが使用されることはありません。 入力用`0 0 0 5 6`、すべてのヒーローは空のヒープを見つけるため、合計はゼロのままです。 割り当てはヒープが空でない場合にのみ発生するため、アルゴリズムはこれを自然に処理します。 

たとえば、すべてのボーナスがヒーローの前に表示される場合`5 4 3 0 0`、すべてのボーナスが最初に収集され、次に最初の 2 人のヒーローが 2 つの最大値を消費します。 ヒープ トリミング ルールにより、ヒーロー数を超える不必要なストレージが確保されず、結果は利用可能な最良の一致の合計となり、最適になります。 

ヒーローとボーナスが緊密に交互に配置される場合、ヒープにより、たとえ複数の小さいボーナスが以前に破棄されたとしても、ヒーローの各ステップで以前の最高のボーナスに引き続きアクセスできることが保証されます。 これにより、初期の小さな値に対する局所的な貪欲な決定に囚われることが回避されます。
