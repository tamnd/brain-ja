 ## 解決策
 ## 問題の理解

 トランプのデッキを上から下に処理します。 正の値はボーナス カードを表し、`0`ヒーローカードを表します。 

ボーナスカードに出会ったとき、私たちはそれを後で使うために取っておくか、捨ててしまうかもしれません。 ヒーロー カードに遭遇するたびに、そのヒーローに利用可能な最強のストアド ボーナスを与えることができます。 そのボーナスは消費され、総軍力に追加されます。 ボーナスが利用できない場合、ヒーローは何も貢献しません。 

目標は、すべてのヒーローが獲得する合計パワーを最大化することです。 

入力には複数のテスト ケースが含まれています。 テスト ケースごとにデッキの順序が与えられ、可能な限り最大の総パワーを計算する必要があります。 

この簡単なバージョンでは制約が少ないです。 すべてのテスト ケースにわたるカードの合計数は最大 5000 です。$O(n^2)$ソリューションは快適にフィットしますが、よりクリーンで貪欲なソリューションがあります。$O(n \log n)$。 

問題の微妙な点は、ボーナスはデッキ内でそれらのボーナスの後に登場するヒーローによってのみ使用できることです。 ヒーローとボーナスを任意に一致させることはできません。 

デッキを考えてみましょう:```
0 100
```答えは`0`、 ない`100`。 ボーナス前に主人公が登場するため、ボーナスは使用できません。 

もう 1 つの重要なケースは次のとおりです。```
5 1 0
```答えは`5`、 ない`6`。 ヒーローはボーナス カードを 1 枚だけ受け取ることができます。 両方のボーナスを受け取ることは不可能です。 

3 番目のケースは次のとおりです。```
1 2 3 0 0
```答えは`5`。 最初のヒーローが受け取る必要があります`3`、2番目は受け取る必要があります`2`。 贈る`1`最初は価値を無駄にして生産だけをするだろう`4`。 

これらの例は、ヒーローが登場するときは常に、利用可能な最大のボーナスを使用する必要があることを示しています。 

## アプローチ

 ブルートフォースソリューションでは、各ボーナスカードを保持するか破棄するかについてのあらゆる可能な決定と、保存されているボーナスのヒーローへの可能なすべての割り当てが試行されます。 各ボーナスには複数の選択肢が導入されるため、これにより、指数関数的に多くの状態が探索されます。 たとえ数十枚のカードであっても、これは不可能になります。 

重要な点は、ボーナス カードを保持しておくことは決して悪いことではないということです。 ボーナスが後で役に立たない場合は、単純に無視できます。 唯一意味のある決定が下されるのは、ヒーローが現れたときです。 

現在、いくつかのボーナス カードが利用可能であるとします。 最大のボーナス以外の何かを主人公に与える場合、その選択肢を最大のボーナスと交換することができ、最終的な答えを減らすことはありません。 現在のヒーローはより多くの力を獲得しますが、将来のヒーローはより小さなボーナスを利用できます。 

この交換議論は貪欲な戦略に直結します。 利用可能なすべてのボーナスを最大ヒープに維持します。 ヒーローが現れたら、ヒープから最大のボーナスを削除し、それを答えに追加します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | 指数 | 遅すぎる |
 | 貪欲な最適ヒープ |$O(n \log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 空の最大ヒープを初期化し、答えをゼロに設定します。 
2. デッキを左から右に処理します。 
3. 現在のカードが正の数の場合、このボーナスは将来のヒーローに利用可能となるため、その値をヒープに挿入します。 
4. 現在のカードがヒーローカードの場合 (`0`)、ヒープが空でないかどうかを確認します。 
5. 少なくとも 1 つのボーナスが利用可能な場合は、ヒープから最大のボーナスを抽出し、それを答えに追加します。 
6. すべてのカードが処理されるまで続行します。 
7. 蓄積された回答を出力します。 

### なぜ効果があるのか

 どのヒーロー カードでも、以前に表示されたボーナスのみを使用できます。 これらのボーナスの中で、利用可能な最大の値を選択することが常に最適です。 

ヒーローがボーナスを受け取ると仮定します$x$より大きなボーナスを利用できる一方で、$y$存在します。 現在のヒーローが受け取るように割り当てを交換する$y$現在の貢献度が増加します$y-x$。 少ない方のボーナス$x$後のヒーローも引き続き利用できるため、将来の選択が悪化することはありません。 この議論を繰り返すと、貪欲でないあらゆる選択肢が排除され、あらゆる最適解が、常に最大の利用可能なボーナスを獲得するものに変換されます。 

ヒープには常に割り当て可能なボーナスが正確に保存されるため、各ヒーロー カードで最大値を抽出することで最適な結果が得られます。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    t = int(input())
    answers = []

    for _ in range(t):
        n = int(input())
        cards = list(map(int, input().split()))

        heap = []
        total = 0

        for x in cards:
            if x > 0:
                heapq.heappush(heap, -x)  # max-heap
            else:
                if heap:
                    total += -heapq.heappop(heap)

        answers.append(str(total))

    sys.stdout.write("\n".join(answers))

if __name__ == "__main__":
    solve()
```ヒープには負の値が格納されます。`heapq`最小ヒープを実装します。 押す`-x`最小の保存値を最大の元のボーナスに対応させることができます。 

すべてのポジティブ カードは、利用可能になるとすぐに挿入されます。 すべてのヒーロー カードは、ルールに正確に一致して、最大 1 つのボーナスを消費します。 

小切手`if heap:`ヒーローはボーナス カードの前に登場する可能性があるため、これは重要です。 その状況では、ヒーローはパワーをゼロに貢献します。 

カードパワーが次の範囲に達するため、答えは大きくなる可能性があります$10^9$, そのため、Python の整数を使用して結果を累積します。

 ## 特殊なケース

 デッキを考えてみましょう:```
0 7
```ヒーローはボーナス カードの前に表示されます。 ヒーローが処理されるときヒープは空であるため、答えには何も追加されません。 後のボーナスは時間を遡ることはできません。 アルゴリズムは正しく返します`0`。 

考慮する：```
10 1 0
```ヒーローが登場すると、両方のボーナスが利用可能になります。 ヒープには以下が含まれます`{10,1}`そしてアルゴリズムは以下を削除します`10`。 答えは次のようになります`10`。 取る`1`代わりに、9単位の電力が永久に失われることになります。 

考慮する：```
5 4 3 0 0 0
```最初のヒーローが受け取る`5`、2番目は受け取ります`4`、3番目は受け取ります`3`。 答えは次のようになります`12`。 ヒープは自然に、最も強力な残りのボーナスを後続の各ヒーローに一致させます。これはまさに最適な割り当てです。
