 ## 解決策
 ## 問題の理解

 単語のリストが与えられ、その連結がいくつかの厳密な特性を満たす単語のペアを数えるように求められます。 具体的には、「悪夢」は 2 つの単語を連結することによって形成され、正確に 25 個の異なる文字を含み、各文字が奇数回出現する奇数長の文字列になります。 このような悪夢を生み出す異なる単語のペアの数を数える必要があります。 

入力には最大 200,000 語が含まれ、すべての単語の合計長は最大 500 万文字です。 これは、単語を連結して文字を数えることで、考えられるすべての単語のペアを直接チェックするアルゴリズムでは、遅すぎることがわかります。 素朴なアプローチでは O(n²) 回の操作が必要となり、上限は 4・10¹⁰ に達する可能性があり、4 秒の時間制限をはるかに超えています。 したがって、すべての連結を明示的に形成することなく、各単語を迅速に検査するソリューションが必要です。 

ここでのエッジケースは微妙です。 単語にすでに文字が欠落している場合は、どの文字が欠落しているかを追跡する必要があります。欠落している文字を提供する別の単語と組み合わせると、正当な悪夢が形成される可能性があるためです。 同様に、偶数回出現する繰り返し文字を含む単語は、パリティを奇数に反転する単語と組み合わせない限り、悪夢に直接寄与することはできません。 文字をグローバルにカウントするだけ、または個別の文字の数を追跡するだけの不注意な実装では、これらのケースは失敗します。 たとえば、「aabbcc」と「defghijklmnopqrstuvwxyz」を組み合わせたような単語は、最終的に 25 文字を含むという理由だけでなく、パリティが一致する場合にのみ悪夢になります。 

## アプローチ

 ブルートフォースの解決策は簡単です。 単語のペア (i、j) ごとに 2 つの単語を連結し、異なる文字が何個あるかを数え、各文字のパリティをチェックします。 これは問題ステートメントを直接実装しているため機能します。 ただし、n が大きい場合は失敗します。n = 2・10⁵ の場合、およそ 2・10¹⁰ のペアがあり、文字を数えるのに各ペアで最大 50 回の演算が必要になります。 これは、4 秒の制限に対して操作が多すぎます。 

重要な洞察は、文字数と個別の文字に関するすべての条件がビットマスクを使用して効率的にエンコードできることを認識することです。 各単語を 26 ビット整数で表します。各ビットは文字に対応し、文字が奇数回出現する場合は 1 になります。 「連結内ですべての文字が奇数回出現する」という条件は、2 つの単語のビットマスク間のビットごとの XOR になります。 正確に 25 個の異なる文字を持つという要件は、XOR 結果に正確に 25 ビットが設定されている必要があることを意味します。 長さのパリティをチェックすることは簡単であり、文字とは独立しています。 

これにより、問題は、現在のワードのビットマスクと XOR 演算したときに 25 ビットを生成するビットマスクを持つ以前のワードがいくつあるかをワードごとに数えることになります。 O(n²) を回避するために、ビットマスク値からそのビットマスクを持つワード数までのハッシュ マップを維持します。 各ワードは、可能な単一ビットの反転を繰り返すことによって、互換性のある以前のワードと効率的にペアにすることができます (XOR で 25 ビットを設定することは、完全な 26 ビット マスクとちょうど 1 ビット異なることと同等であるため)。 これにより、二次問題が単語と少数の固定数の潜在的なマスクを反復する問題に変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²・L) | お(1) | 遅すぎる |
 | 最適 | O(n・26) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 各ワードの 26 ビット マスクを事前計算します。 マスクを 0 に初期化します。単語内の各文字について、XOR を使用して対応するビットを反転します。 最後に、マスクは単語内のすべての文字のパリティをエンコードします。 
2. 各マスクを持つ単語の数をカウントするハッシュ マップを維持します。 これにより、有効な悪夢を形成するために、現在の単語とペアになる前の単語が何個あるかをクエリできます。 
3. 各単語について、現在の単語と XOR 演算したときに 25 文字セットを生成するターゲット XOR マスクを計算します。 25 ビットが設定された 26 ビット マスクは、現在のマスクとちょうど 1 ビットだけ異なるため、現在のマスクの各ビットを反転して得られるすべてのマスクを生成します。 
4. これらの互換性のあるマスクのいずれかを使用した前の単語の数を答えに追加します。 現在の単語のマスクを含めるようにハッシュ マップを更新します。 
5. 奇数長の要件に対処するには、奇数長と偶数長のワードのカウントを別々に維持します。 長さの合計が奇数になる単語のみを組み合わせてください。 

機能する理由: 各単語は、その文字パリティをキャプチャするビットマスクによって表されます。 2 つのワードの XOR に正確に 25 ビットが設定されており、長さの合計が奇数になる場合、2 つのワードが悪夢を形成する可能性があります。 ハッシュ マップにより、互換性のあるすべての以前のワードが 1 回だけカウントされることが保証され、26 ビットのそれぞれを反転することで、XOR で設定された 25 ビットを達成するためのすべての可能性が生成されます。 これにより正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def count_nightmares():
    n = int(input())
    words = [input().strip() for _ in range(n)]
    
    from collections import defaultdict
    
    # maps length parity (0=even,1=odd) -> mask -> count
    counts = [defaultdict(int), defaultdict(int)]
    
    ans = 0
    for w in words:
        mask = 0
        for c in w:
            mask ^= 1 << (ord(c) - ord('a'))
        
        length_parity = len(w) % 2
        # we want to pair with words of opposite length parity
        target_parity = 1 - length_parity
        
        # flip each bit to get masks with 25 bits difference
        for i in range(26):
            target_mask = mask ^ (1 << i)
            ans += counts[target_parity].get(target_mask, 0)
        
        counts[length_parity][mask] += 1
    
    print(ans)

count_nightmares()
```コードはまず各単語を文字パリティのビットマスクに変換します。 奇数長の要件を強制するために、長さのパリティによってカウントを分割します。 次に、単語ごとに 26 回のシングル ビット フリップをすべて繰り返して、互換性のある前の単語を特定します。 最後に、現在の単語のマスクのカウントを更新します。 よくある落とし穴は、長さパリティを区切ることを忘れたり、XOR を誤って使用したりすることです。 

## 実用的な例

```| 単語 | マスク (ビン) | 長さパリティ | 互換性のあるマスク | 累積数 |

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n・26) | 各ワードは 1 回処理され、互換性のあるマスクを見つけるために 26 ビットにわたって反復されます。 |
 | スペース | O(n) | マスクとカウントのマップを保存します。 最悪の場合、各単語には固有のマスクが適用されます。 |

 n ≤ 2・10⁵ で、単語ごとに 26 回の反復を行うと、解は 4 秒未満で快適に完了します。 メモリは一意のマスクの数によって制限され、最大でも 2²⁶ ですが、総文字数制限により現実的にははるかに少なくなります。

 ## 特殊なケース

 単語のすべての文字が偶数カウントである場合、そのマスクはゼロになります。 これを、マスクに 1 ビット セットだけが設定されている別のワードと組み合わせると、XOR に 25 ビットがセットされ、長さが一致した場合に有効な悪夢が発生します。 アルゴリズムは正しく追跡します
