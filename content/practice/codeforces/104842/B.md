 ## 解決策
 ## 問題の理解

 このゲームは、2 つのチームがそれぞれ 5 人の現役選手と 5 人の交代選手で開始するバスケットボールの試合をシミュレートします。 時間の経過とともに、プレーヤーがコートとベンチの間で入れ替わり、得点イベントが発生するという 2 つのことが起こります。 おもしろいのは、得点はチームの合計だけではなく、現在コートにいる個々のプレーヤーに分配されることです。 

チームが x 点に相当するバスケットを獲得するたびに、現在コートでプレーしているそのチームのすべてのプレーヤーは、個人統計に x を獲得します。 同時に、現在コートにいる相手チームのすべてのプレーヤーは x を失います。 交代は累積スコアには影響しませんが、将来の得点イベントによって現在どの選手が影響を受けるかが変わります。 

タスクは、交代と得点イベントの完全なシーケンスを順番に処理し、コートに登場したすべての選手の最終的なプラスマイナスの値を計算することです。 出力は、入力宣言の順序ではなく、プレーヤーが最初にプレイに登場する順序に従う必要があります。 

制約は小さく、イベント数は最大 1000 です。 これにより、線形または線形に近いシミュレーションよりも複雑なものは即座に除外されます。 各チームの現在の 5 人のプレーヤーをイベントごとに更新するアプローチは、各イベントが最大 10 人のプレーヤーに接触するため、十分に高速です。 

微妙な詳細は、プレーヤーが最初の名簿にリストされているときではなく、最初にコートに足を踏み入れたときにのみ出力順序に表示される可能性があることです。 もう 1 つの詳細は、交代によってイベントで以前に言及されていない選手が登場する可能性があるため、システムは新しい名前を動的に登録する必要があることです。 

もう 1 つのエッジケースは、繰り返しの出場です。プレーヤーは何度もコートを離れ、再びコートに入ることができますが、スコアは活動期間全体にわたって累積されます。 

## アプローチ

 直接シミュレーションは問題ステートメントと正確に一致します。 セット内の各チームの現在の 5 人のプレーヤーを維持し、各プレーヤーの名前を累積スコアにマッピングする辞書を維持します。 また、出力順序を修正するために、プレーヤーが以前に見られたことがあるかどうかも追跡します。 

各得点イベントについて、得点チームの 5 人のアクティブ プレーヤーを反復して x を加算し、対戦相手の 5 人のアクティブ プレーヤーを反復して x を減算します。 交代イベントの場合、スコアを変更せずに、アクティブ セットから 1 人のプレーヤーを削除し、別のプレーヤーを挿入します。 

これが機能するのは、アクティブなプレイヤーの数が一定かつ少ないため、各イベントには一定の作業コストがかかるためです。 最大 1,000 のイベントを使用しても、総操作量はわずかです。 

ブルートフォースの亜種は、完全なタイムラインを再構築し、イベントごとにプレイヤーごとの貢献を再計算しようとしますが、すでに正確な状態を増分的に維持しているため、それは必要ありません。 再計算やロールバックは必要ありません。 システムは純粋に順加法です。 

重要な観察は、いつでも重要となる唯一の状態は、チームごとに現在の 5 人のプレーヤーであるということです。 あとはすべて帳簿を積み上げていくだけです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | イベントごとに完全な再計算をシミュレートする | O(q * n) | O(n) | 遅すぎる/不必要 |
 | アクティブ セットを使用した直接シミュレーション | O(q) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 最初のチーム名とスターティングラインナップを解析し、これらすべてのプレーヤーを「既知」としてマークして、後で順序を保存できるようにします。 また、スコアをゼロに初期化します。 
2. 各チームの現在のコート上の選手をセットまたは辞書のような構造に保存します。 これにより、置換中に O(1) のメンバーシップ更新が可能になります。 
3. 辞書を管理する`score[player]`試合全体でプラスマイナスの値を蓄積します。 
4. リストを管理する`order`これは、各プレーヤーがコート上のポジションに初めて登場した時間を記録します。 このリストは、最終的な出力の順序付けに使用されます。 
5. 各イベントを時系列に処理します。 
6. イベントが値 x を持つチーム T の得点イベントである場合、T の現在コートにいる 5 人のプレーヤーを反復処理し、それぞれのスコアに x を加算します。 次に、相手チームの 5 人のプレーヤーを反復処理し、各プレーヤーから x を減算します。 これは、スコアリングが個々の統計にどのような影響を与えるかを直接反映します。 
7. イベントが交代の場合は、出て行く選手をアクティブ セットから削除し、入ってくる選手を挿入します。 入ってくるプレイヤーがこれまでに登場したことがない場合は、スコアをゼロに初期化し、出力順序リストに追加します。 
8. すべてのイベントの後、記録された順序リストを反復処理し、各プレーヤーをチームと署名済みのスコアとともに印刷します。 

### なぜ効果があるのか

 いかなる時点においても、最終的な統計に対するプレーヤーの貢献は、各得点イベント中にそのプレーヤーがコート上にいるかどうかによってのみ決まります。 このアルゴリズムは各ステップでアクティブなプレーヤーの正確なセットを維持するため、各スコアの更新はプレーヤーの正しいサブセットに正確に適用されます。 置換はこのセットのメンバーシップを変更するだけで、過去のイベントには影響を与えないため、イベントの処理は、ロールバックや将来の知識を必要とせずに、正確さを順番に保持します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def fmt(x):
    if x > 0:
        return f"+{x}"
    return str(x)

first_team = input().strip()
first_players = [input().strip() for _ in range(5)]

second_team = input().strip()
second_players = [input().strip() for _ in range(5)]

score = {}
team_of = {}

on = {first_team: set(first_players),
      second_team: set(second_players)}

order = []
seen = set()

def register(p, team):
    if p not in seen:
        seen.add(p)
        order.append(p)
        score[p] = 0
        team_of[p] = team

for p in first_players:
    register(p, first_team)

for p in second_players:
    register(p, second_team)

q = int(input())
for _ in range(q):
    line = input().strip()

    if "scored" in line:
        parts = line.split()
        team = parts[1]
        val = int(parts[-1])

        for p in on[team]:
            score[p] += val
        other = first_team if team == second_team else second_team
        for p in on[other]:
            score[p] -= val

    else:
        parts = line.split()
        team = parts[1]
        y = parts[3]
        z = parts[5]

        on[team].remove(y)
        on[team].add(z)

        register(z, team)

for p in order:
    s = score[p]
    sign = "" if s == 0 else ("+" if s > 0 else "")
    print(f"{p} ({team_of[p]}) {fmt(s)}")
```コア実装は、チームごとに 1 つずつ、2 つのアクティブ セットを保持し、交代が発生したときにそれらを直接更新します。 得点ロジックは対称的です。得点チームの 5 人のプレーヤーをループしてポイントを追加し、相手の 5 人のプレーヤーをループして減点します。 の`register`この関数により、プレーヤーを出力オーダーに 1 回だけ追加し、最初にプレイに登場したときにメタデータを正確に初期化することが保証されます。 

微妙な点の 1 つは、イベント行の解析です。 厳密な書式設定ブランチに依存する代わりに、キーワードをチェックします。`"scored"`これにより、2 つのイベント タイプが明確に分離されるためです。 もう 1 つの微妙な点は、選手が最初のラインナップ順序に登場する前に交代によって導入される可能性があるため、登録は初期化時と交代時の両方で行われる必要があることです。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    first_team = input().strip()
    first_players = [input().strip() for _ in range(5)]

    second_team = input().strip()
    second_players = [input().strip() for _ in range(5)]

    score = {}
    team_of = {}

    on = {first_team: set(first_players),
          second_team: set(second_players)}

    order = []
    seen = set()

    def register(p, team):
        if p not in seen:
            seen.add(p)
            order.append(p)
            score[p] = 0
            team_of[p] = team

    for p in first_players:
        register(p, first_team)
    for p in second_players:
        register(p, second_team)

    q = int(input())
    for _ in range(q):
        line = input().strip()
        if "scored" in line:
            parts = line.split()
            team = parts[1]
            val = int(parts[-1])
            other = first_team if team == second_team else second_team
            for p in on[team]:
                score[p] += val
            for p in on[other]:
                score[p] -= val
        else:
            parts = line.split()
            team = parts[1]
            y = parts[3]
            z = parts[5]
            on[team].remove(y)
            on[team].add(z)
            register(z, team)

    out = []
    for p in order:
        s = score[p]
        if s > 0:
            out.append(f"{p} ({team_of[p]}) +{s}")
        elif s < 0:
            out.append(f"{p} ({team_of[p]}) {s}")
        else:
            out.append(f"{p} ({team_of[p]}) 0")

    return "\n".join(out)

 ## 特殊なケース

 微妙なケースの 1 つは、選手が交代で投入され、すぐに順位に影響を与える場合です。 たとえば、新しいプレーヤーがゲームの途中で参加し、その後得点に貢献する場合、そのプレーヤーは出力順序ですべての最初のプレーヤーの後に表示される必要があります。 の`register`関数は、最初の出現時にのみ追加することでこれを保証します。 

もう一つのケースは、同じ選手の交代が繰り返されることです。 セットを使用しているため、削除と再追加は安全かつ冪等です。 スコアはリセットされないため、復帰プレイヤーは過去の貢献度から蓄積され続けます。 

最後のケースは、初期名簿に登録されているものの、即時の交代によりコートに登場しない選手です。 これらは、スコアの更新を受け取っていない場合でも、最初はコート上にいたため、引き続き出力に表示されます。
