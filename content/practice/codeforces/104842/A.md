 ## 解決策
 ## 問題の理解

 整数グリッド上の 2 つの点が与えられます。 開始点と目的地の両方が座標軸から厳密に離れた場所にあります。これは、どちらの終点でも座標が 0 ではないことを意味します。 このようなポイントを無料ポイントといいます。 グリッドには「高価な」点も含まれています。これは、まさに X 座標または Y 座標のいずれかが 0 である軸上にある点です。 パスが任意の軸点を通過するたびに、コスト 1 が支払われます。 

タスクは、グリッド エッジや直線セグメントに限定されず、平面内の任意の連続パスを使用して開始点から目的地まで移動することです。 重要なのは、パスが少なくとも 1 回接触する軸ポイントの数だけです。 目標は、この数を最小限に抑えることです。 

重要な問題は、平面が連続しているため、パスが任意に曲げられる可能性があることです。 ただし、コスト構造は離散的であり、パスが x 軸または y 軸と交差するかどうか、および変形によって回避できない方法で交差する回数にのみ依存します。 

座標境界は十分に小さいため、テストごとに O(1) 推論で十分です。 値が最大 10,000 の大きさの場合、ジオメトリのシミュレーションや平面の離散化を試みるソリューションは不要であり、過剰になります。 正しい解決策は、トポロジー的にいくつの軸を交差させる必要があるかについての幾何学的な推論から導き出される必要があります。 

素朴な誤解は、パスが x = 0 または y = 0 を横切るたびに再び料金が発生すると仮定することです。 最適な構成では、適切に選択されたパスが各軸を横切るのは最大 1 回であるため、これは過剰カウントにつながります。 

2 番目のよくある間違いは、絶対座標の変化を合計したり、グリッドのステップを考慮したりするなど、マンハッタン スタイルの推論を想定していることです。 パスは連続しており、象限を自由に横切ることができるため、これは不正確です。 

素朴な考えを打ち破るエッジケースには、次のようなものがあります。 

同じ象限内の開始点と終了点。 たとえば、(2, 3) ～ (5, 7) です。 素朴な軸横断アプローチでは、やはり軸を横断しなければならないと考えるかもしれませんが、完全に同じ象限に留まり、費用はゼロになります。

 (1, 1) から (-1, -1) など、対角線上にある象限の開始点と終了点。 ここでは両方の座標の符号が変わり、両方の軸を横切るパスが強制されるため、少なくとも 2 コストが発生します。 

(1, 1) から (-1, 2) のような混合ケース。x 符号のみが変化するため、1 つの軸のみが交差することは避けられません。

 実際のタスクは、座標の符号の変更と、単一の象限を通る配線によって軸を完全に回避できるかどうか、または交差が構造的に強制されるかどうかについての推論に帰着します。 

## アプローチ

 ブルートフォースのアイデアでは、パスを明示的に考慮しようとします。 平面を細かいグリッドに離散化し、軸を横切る場合にコストが増加する最短経路検索を実行することを想像することもできます。 軸の交差部分ではコストが加算されるため、これにより問題が正しくモデル化されます。 ただし、グラフは無限かつ連続的であり、すべての有効な動作を捕捉するのに十分なほど細かく離散化すると、サイズが爆発的に増加します。 サイズを 20,000 × 20,000 の有界グリッドに制限した場合でも、数億のノードが発生するため、BFS やダイクストラは実行不可能になります。 

重要な観察は、この問題では平面が実際には複雑ではないということです。 唯一意味のある構造は、軸で区切られた 4 つの象限への分割です。 象限内では移動は自由です。 時間コストが発生するのは、x = 0 または y = 0 を横切るときだけです。さらに、軸を再度横切ることは、到達可能性を向上させることなく不必要なコストを追加するだけであるため、最適なパスで各軸を横切ることができるのは多くても 1 回だけです。

これにより、問題は、開始点と終了点が同じ象限内にあるか、1 つの座標記号パターンを共有しているか、または対角線上にあるかどうかに関する純粋に組み合わせの問題に帰着します。 両方の座標の両端点で同じ符号がある場合、軸を横切る必要がないため、コストはゼロになります。 座標記号が 1 つだけ異なる場合は、軸を 1 つだけ交差する必要があります。 両方が異なる場合は、両方の軸を交差する必要があり、コストが 2 になります。 

したがって、ジオメトリは符号比較に崩壊します。

 ## アルゴリズムのチュートリアル

 各点を、x 用と y 用の 1 組の符号に変換します。 各記号は、その点が対応する軸のどちら側にあるかを示します。 

1. 始点と終点の座標を読み取ります。 入力にゼロが現れることはないため、実際に必要な情報は各座標が正か負かということだけです。 
2. x1 と x2 の符号が同じかどうかを判断します。 それらが異なる場合は、開始点から終了点までの移動で少なくとも 1 回は y 軸を横切る必要があります。 これは、x の符号を変更するには x = 0 を通過する必要があるためです。 
3. y1 と y2 の符号が同じかどうかを判断します。 それらが異なる場合、y の符号を変更するには y = 0 を通過する必要があるため、開始点から終了点までの移動では少なくとも 1 回 x 軸を横切る必要があります。 
4. これら 2 つの符号の比較のうち、異なるものがいくつあるか数えます。 この数は、必要な軸交差の最小数です。 
5. カウントを答えとして出力します。 

各軸がトポロジー バリアに対応するため、ロジックは機能します。 座標全体での符号の変更は、対応する軸を通過することなく行うことはできず、各軸を通過するたびに 1 つのコストが発生します。 

### なぜ効果があるのか

 平面は軸によって 4 つの開いた象限に分割されます。 2 点間の連続したパスは、この分割された空間内でも連続したままでなければなりません。 象限間の移動は、軸の 1 つを横切ることに正確に対応します。 コストは軸点に触れた場合にのみ発生するため、最小コストは正確に開始象限と終了象限を分ける個別の軸の数になります。 軸の交差を回避すると、目的地を含まない接続された領域内にとどまることになるため、パスでこの数を減らすことはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def sign(x):
    return 1 if x > 0 else -1

def solve():
    x1, y1, x2, y2 = map(int, input().split())

    dx = sign(x1) != sign(x2)
    dy = sign(y1) != sign(y2)

    print(dx + dy)

if __name__ == "__main__":
    solve()
```このソリューションでは、ヘルパー関数を使用して各座標をその符号に換算します。 ゼロは出現しないことが保証されているため、正の値と負の値のみを区別します。 

次に、x 座標と y 座標の符号を個別に比較します。 それぞれの不一致により、避けられない軸の交差が 1 つ発生します。 最終的な答えは、これらの不一致の合計です。 

実装は定数時間であり、幾何学的なシミュレーションを回避します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    def sign(x):
        return 1 if x > 0 else -1

    x1, y1, x2, y2 = map(int, input().split())

    dy = sign(y1) != sign(y2)

# only y changes sign
assert run("1 2 3 -4\n") == "1"

 ## 特殊なケース

 微妙なケースは、両方の点が同じ象限にある場合です。 たとえば、(10, 5) ～ (3, 7) です。 アルゴリズムは両方の座標の同一の符号を計算し、ゼロクロッシングが発生します。 どちらの軸にも近づくことなく、その象限内にパス全体を描画できるため、コストは発生しません。 

もう 1 つのケースは、(5, 10) から (-2, 8) のように、1 つの座標だけが符号を変える場合です。 X 記号は異なりますが、Y 記号は一致します。 アルゴリズムは 1 を返します。これは、必要な 1 つの Y 軸交差に対応します。 x 記号を反転するには、連続パスがある時点で x = 0 を通過する必要があります。 

最後に、(2, 3) から (-4, -5) のように、両方の座標の符号が変わると、両方の不一致がカウントされます。 パスは両方の軸を何らかの順序で交差する必要がありますが、開始点と終了点が対角線上にある象限にあるため、変形によって両方の交差を回避することはできません。
