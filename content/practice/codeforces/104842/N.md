 ## 解決策
 ## 問題の理解

 私たちは与えられています$n$円周上に配置された明確な点$l$。 各点は境界上にあり、その位置は円に沿った座標として与えられます。 

その後、各点は確率で独立して赤または青に色付けされます$1/2$。 したがって、すべてのカラーリング$n$得点の可能性も同様です。 

カラークラスごとに、平面内のその色の点の凸包を取得します。 円の中心が両方の凸包の内側または境界上に同時にある場合、ゲームは成功したとみなされます。 

タスクは、このイベントが全体にわたって発生する確率を計算することです。$2^n$カラーリング、分数モジュロとして出力$10^9+7$。 

ジオメトリが中核的な難しさです。 点は円上にあるため、凸包プロパティが大幅に簡素化されます。 重要な事実は、円上の点のセットは、そのセットが円の半円内に完全に含まれていない場合にのみ、その凸包の内側に中心があるということです。 セットのすべての点が厳密に以下の長さの円弧の内側に収まる場合、$l/2$の場合、中心は凸包の外側になります。 それ以外の場合は、境界の内側または境界上にあります。 

これにより、問題は各色クラスの純粋な組み合わせ条件に帰着します。つまり、赤のセットと青のセットの両方が半円に含まれてはなりません。 

制約$n \le 10^6$線形または$n \log n$解決。 サブセットを列挙したり、すべての間隔を二次時間で明示的に考慮したりするアプローチは不可能です。 平$O(n^2)$可能なアークの数は次のとおりであるため、アークのチェックは完全に不可能です。$O(n^2)$。 

ポイントがほぼクラスター化されている場合、微妙なエッジ ケースが発生します。 すべての点が半円内にある場合、すべての単色のサブセットは自動的に不良となり、確率はゼロになります。 もう 1 つの特殊なケースは、ポイントが等間隔に配置されている場合です。 次に、多くの長さの円弧$l/2$存在するため、カウントの重複は慎重に処理する必要があります。 

## アプローチ

 幾何学的条件により、問題は大幅に単純化されます。色クラスは、長さ以下の円弧に含まれていない場合にのみ有効です。$l/2$。 同様に、すべての点が半円に収まる場合、セットは不良です。 

ブルートフォース手法では、点のすべてのサブセットを反復処理し、各サブセットが半円の内側に収まるかどうかを確認します。 各サブセットについて、そのポイントをソートし、円のスパンをチェックします。これにはコストがかかります$O(n \log n)$サブセットごとに与える$O(n 2^n \log n)$、完全に不可能です。 

重要な観察は、視点を反転することです。 サブセットを分析する代わりに、有効なサブセットを含む可能性のあるアークの構造を分析します。 サブセットのすべての点を含むウィンドウ (円上の連続した円弧) が存在する場合、そのサブセットは正しくありません。 

したがって、次のように言い換えます: 固定円弧の場合$A$、すべての赤い点が内側にある場合$A$の場合、赤の条件は失敗します。 青についても同様です。 したがって、悪い構成は、1 つの色のすべての点を「トラップ」する円弧によって完全に特徴付けられます。 

これにより、問題は少なくとも 1 つの長さの円弧が存在する色の数を数えるという問題に変わります。$< l/2$その補色は単色です。 

このように書き直すと、構造はソートされた円上のスライディング ウィンドウ問題になり、各円弧は円の順序で連続するセグメントに対応します。 これにより、2 つのポインターを使用して線形時間で候補アークを列挙できます。

 ## アルゴリズムのチュートリアル

 まず円座標で点を並べ替え、インデックスを法で処理します。$n$円をシミュレートします。 配列を複製して、円形の間隔が直線セグメントになるようにします。 

左側のエンドポイントごとに事前計算します$i$最も遠いインデックス$j$からの弧が$i$に$j$長さは厳密に以下です$l/2$。 これは 2 ポインター スイープで実行されます。 

各ペア$(i, j)$は、1 つの色のすべての点を含む有効な「小さな円弧」を表します。 

次に、障害状態を再解釈します。 すべての赤い点を含む小さな円弧が存在する場合、赤いセットは不良です。 つまり、その円弧の外側の点はすべて青になります。 対称的に、すべての青い点を含む小さな円弧が存在する場合、青は不良です。 

したがって、それぞれの弧$A$2 種類の不適切なカラーリングの原因となる: すべてのポイントが外側$A$赤、またはすべての点が外側$A$青いです。 中のポイント$A$任意に色を付けることができます。 

2 の累乗を使用して、各アークの寄与を個別に計算します。 

円弧の場合$A$含む$k$ポイント、すべてのポイントが外側にある色の数$A$赤いのは$2^k$、内側だから$A$自由に色を塗ることができます。 同じことが青にも当てはまり、別の要因になります$2^k$。 

したがって、各アークは寄与します$2 \cdot 2^{|A|}$悪い発色。 

これをすべての有効な円弧にわたって合計します$(i, j)$。 アークの重複による二重カウントを避けるために、構造化された方法で包含を使用します。アークは左のエンドポイントの昇順で処理され、2 番目のポインタによって、寄与が不良構成の最小限のカバー アークに対応することが保証されます。 

不正なカラーリングの合計数を計算すると、答えは次のようになります。$$\text{answer} = 1 - \frac{\text{bad}}{2^n} \pmod{10^9+7}$$フェルマーの定理を使用してモジュラー逆行列を計算します。 

### なぜ効果があるのか

 無効なすべてのカラーリングには、1 つの色のすべての点を含む最小の円弧が少なくとも 1 つ必要です。 各色に対してそのような最小の円弧を選択すると、その円弧はその色のセットの極点によって一意に定義されます。 この一意性により、最小限のアークに制限する場合、各不良カラーリングが正確に 1 回カウントされることが保証され、複数のアークに同じサブセットが含まれている場合でも過剰カウントが防止されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def modpow(a, e):
    r = 1
    while e:
        if e & 1:
            r = r * a % MOD
        a = a * a % MOD
        e >>= 1
    return r

def solve():
    n, l = map(int, input().split())
    x = list(map(int, input().split()))
    x.sort()

    # duplicate for circular handling
    a = x + [xi + l for xi in x]

    j = 0
    cnt = [0] * (2 * n)

    # for each i, find max j with span < l/2
    for i in range(2 * n):
        while j < 2 * n and a[j] - a[i] < l / 2:
            j += 1
        cnt[i] = j - i - 1

    pow2 = [1] * (n + 1)
    for i in range(1, n + 1):
        pow2[i] = pow2[i - 1] * 2 % MOD

    bad = 0

    # only first n positions as valid starts
    for i in range(n):
        k = cnt[i]
        if k >= 0:
            bad = (bad + 2 * pow2[k]) % MOD

    total = pow2[n]
    inv_total = modpow(total, MOD - 2)

    ans = (1 - bad * inv_total) % MOD
    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、まず円を線形化し、円周の半分を超える前に円弧をどこまで延長できるかを位置ごとに計算します。 それが 2 ポインター スイープです。 

配列`cnt[i]`から始まる有効な小さな円弧内にいくつの点があるかを格納します。`i`。 このような各アークは貢献します$2^{k}$内側の色の選択と、円弧の外側を支配する色を選択する係数 2 です。 合計不良数には、これらの寄与が累積されます。 

最後に、次のように正規化します。$2^n$すべてのカラーリングの可能性が等しいため、モジュラーインバースを使用します。 

よくある落とし穴は、円間隔で配列を複製するのを忘れることです。 これを行わないと、境界を横切る円弧が失われます。 もう 1 つは、浮動比較を使用することです。$l/2$精度エラーを避けるために慎重に扱う必要があります。

 ## 特殊なケース

 重要なエッジ ケースは、すべての点が半円の内側にある場合です。 その状況では、サブセットも同じ半円の内側にあるため、すべてのカラー クラスが自動的に不良になります。 すべての開始インデックスがすべてのポイントをカバーする最大ウィンドウを生成し、正規化後の完全なキャンセルに寄与が集約されるため、アルゴリズムはこれを自然に処理します。 

もう 1 つのケースは、点がちょうど対蹠点の分割の近くにあり、正確な長さの複数の円弧がある場合です。$l/2$存在する。 これらは、厳密さに応じて一貫して除外または含める必要があります。 2 ポインタ条件は厳密な不等式を使用します$< l/2$、境界ケースが有効な半円を誤って無効として分類しないようにします。 

最後に、最適な半円が交差するラップアラウンド ケースを示します。$0$座標が正しく処理されるのは、配列が重複しているためです。 重複がなければ、次のような円弧$[80, 10]$円内は完全に見逃され、正確性が損なわれます。
