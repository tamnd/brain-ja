 ## 解決策
 ## 問題の理解

 固定ビットベース形式用のカスタム整数エンコーディング システムを設計するように求められています。 各数値は先頭の 4 ビット セレクターを使用してエンコードされ、その後に 0 ～ 4 つの追加の 4 ビット グループが続きます。 つまり、各値には最初に 16 の可能な主な「モード」の 1 つが割り当てられ、各モードによって 2 つのことが決まります。それは、追加で読み取られる 4 ビット グループの数と、デコード後にベース オフセットがどのように適用されるかです。 

より具体的には、デコードは次のように行われます。 まず最初の 4 ビット ブロックを読み取り、テーブル エントリを選択します。 このエントリは、あと何個の 4 ビット ブロックが続くかを示し、オフセットも示します。 次に、追加のブロックを固定長 g の 16 進数の数値として解釈します。つまり、範囲は 0 から 16^g − 1 になります。最後にオフセットを追加します。 

設計上の重要な問題は、16 個のプレフィックスのそれぞれにペア (g, f) を割り当てる必要があることであり、これにより、表現可能な値の 16 個の互いに素な「間隔ファミリー」が発生します。 [x, y] のすべての整数は、正確に 1 つのプレフィックス構成によって一意に表現できる必要があり、指定されたシーケンス a1 … an のエンコードで使用される合計 4 ビット グループができるだけ少なくなるように、この範囲内の値を割り当てたいと考えています。 

したがって、各接頭辞 i はブロックに対応します。 

整数のセット [f_i, f_i + 16^g_i − 1]、エンコード コストは割り当てられた値ごとに 1 + g_i グループです。 

課題は、区間 [x, y] を最大 16 個の互いに素なセグメントに分割することです。各セグメントのサイズは 16 のべき乗に制限され、各セグメントの要素あたりのコストは指数のみに依存します。 次に、マルチセット a1…an のコストを最小限に抑えながら、すべての整数が 1 回だけカバーされるように [x, y] のすべての値をセグメントに割り当てる必要があります。 

制約 y − x ≤ 10^6 は、O(範囲 × 16) または O(範囲 × 対数範囲) の動的プログラミング ソリューションが可能であることを示唆しています。 主な問題は、16 個のプレフィックスのそれぞれが (f_i を介して) 任意にシフトできるため、パーティションがグリッドに固定されていないことです。 これは、柔軟な配置を伴う加重セグメンテーションの問題です。 

単純なアプローチでは、範囲へのプレフィックスのすべての割り当てとブロックの可能なすべての配置を試行します。 それは組み合わせ爆発です。 

ローカル周波数による、または最初に最大のブロックを取得するという貪欲な割り当てを想定すると、微妙な失敗のケースが発生します。 たとえば、x = 0、y = 15 で、シーケンスが 1 つの領域に大きく偏っている場合、貪欲な割り当てにより、低頻度の数値をカバーするために大きなブロックが割り当てられる一方で、密な領域では低コストの表現が無駄になり、最適な再利用構造が失われる可能性があります。 ステートメント内の例は、均一なブロック サイズが魅力的であるように見えても、最適解ではプレフィックスごとに異なる g 値を使用する場合があることをすでに示唆しています。 

もう 1 つの微妙な問題は、各プレフィックスが 16 の累乗に整列された連続領域に対応する必要があると仮定していることです。オフセットは自由であるため、セグメントは数直線上のどこにでも配置できます。 拘束されるのは長さだけであり、位置合わせは拘束されません。 

## アプローチ

 ブルート フォース戦略では、16 個のプレフィックスのそれぞれに [0, 4] の g とオフセット f の選択肢を割り当て、次に [x, y] のすべての整数をこれら 16 個の間隔の 1 つに重複なく割り当てようとします。 オフセットを無視しても、g だけで 5^16 の可能性がすでに得られており、構成ごとに最大 10^6 の整数にわたるカバー/代入問題を解決する必要があります。 これはまったく実現不可能です。 

重要な観察は、コスト構造が使用される要素ごとに線形であるということです。各接頭辞 i は、それに割り当てられたすべての整数の固定コスト 1 + g_i と、容量 16^g_i に寄与します。 これは、「バケット フィッティング」解釈を示唆しています。各プレフィックスは、容量と単位あたりのコストを持つコンテナーであり、[x, y] の整数をこれらのコンテナーに重複することなく詰め込む必要があります。

整数行を x から y まで走査し、プレフィックスごとにどのセグメントをカバーするかを決定することを考えることができます。 オフセットは任意であるため、実際の数値位置は重要ではありません。 各 (g, f) ペアに整数がいくつ割り当てられるかだけが重要です。 したがって、問題は、長さ L = y − x + 1 を最大 16 のブロックに分割することに帰着します。各ブロックのサイズは 16^g で、コストはそのサイズに比例します。 

これは、境界のあるナップザックのような DP になります。最大 16 個の項目を使用して L を表現したいのですが、各項目タイプは g ∈ [0,4]、値は 16^g、コストは (1+g) · 16^g です。ただし、16 個のプレフィックスはそれぞれ別個であるという追加の制約もあります。つまり、1 つの構成を任意に何度も再利用することはできません。 代わりに、容量の合計が少なくとも L になる割り当てを正確に 16 個選択し、配置する必要があります。 

より有用な再定式化は、各プレフィックスに容量 c_i = 16^g_i と要素あたりのコスト w_i = 1 + g_i を割り当てることです。 次に、合計が少なくとも L である 16 個の容量を選択し、常に要素あたりのコストが最も安いプレフィックスを最初に埋めることによって要素を最適に割り当てる必要があります。 これは基本的に、容量を選択した後の貪欲な割り当てですが、容量の選択自体は、指数関数的なサイズに対する有界整数パーティションの問題です。 

重要な洞察は、可能な g 値は 5 つしかなく、スロットは 16 つしかないため、各 g を使用するプレフィックスの数を DP できるということです。 構成については、総容量と総コスト構造がわかっているので、単位あたりのコストが最も安いブロックで [x, y] を貪欲に埋めることをシミュレートします。 これにより、小さな状態空間にわたって効率的な最適化が実現されます。 

したがって、問題は、合計が 16 になるカウント c0 ～ c4 を選択し、結果として得られる容量とコストを計算し、一意性を尊重し、シーケンスの重みに対するコストを最小限に抑えながら L をカバーする実現可能性を検証することに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(5^16 · 10^6) | O(10^6) | 遅すぎる |
 | プレフィックス タイプに対する最適な DP | O(16^2) または O(16^3) | O(16^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. L = y − x + 1 を計算します。これは、一意に表現できる必要がある個別の整数の数です。 これらの各整数を 1 つのプレフィックス構成に割り当てます。 
2. パラメータ g を持つ各プレフィックスは正確に p[g] 値をエンコードできるため、g = 0..4 の累乗 p[g] = 16^g を事前計算します。 これがブロックの容量です。 
3. 区間 [x, y] にわたる入力シーケンス内の各値の頻度をカウントします。 各整数が使用される頻度のみを考慮します。コストは発生ごとに累積するため、頻繁に使用される値は安価な表現を優先する必要があります。 
4. カウント cnt[g] への 16 個のプレフィックスの可能な割り当てごとに (パラメーター g を使用するプレフィックスの数)、総容量キャップ = Σ cnt[g] · p[g] を計算します。 cap < L の場合、必要な整数をすべて表現できないため、この構成は破棄されます。 
5. 有効な構成の場合、表現された整数あたりのコスト ((1+g) / p[g]) を増加させることでソートされたプレフィックスを使用して、区間 [x, y] を満たすシミュレーションを行います。 各プレフィックスにその容量に等しい連続セグメント サイズを割り当て、周波数で重み付けされた総コストを累積します。 これが機能するのは、ブロック内の再配置によって有効性が変更されることはなく、サイズだけが問題となるためです。 
6. 総コストが最小になる構成を追跡します。 プレフィックスは 16 個しか存在しないため、5 つのカテゴリにわたる 16 項目の実行可能な分布の列挙は、状態 (i、c0、c1、c2、c3) に対する DP を使用して管理でき、c4 が決定されます。 
7. 最適なカウントを選択した後、各プレフィックスに特定の (g, f) を割り当てて実際のテーブルを再構築します。 オフセットは貪欲に選択されます。x から開始して、各ブロックにサイズ p[g] の連続セグメントを割り当て、それに応じて f を設定し、デコードがそのセグメントに正確にマップされるようにします。 
8. (g_i, f_i) の 16 行を出力し、[x, y] のすべての整数が 1 回だけカバーされるようにします。 

### なぜ効果があるのか

重要な不変条件は、オフセットは構造ではなく配置のみを定義するということです。 すべての有効な解は、[x, y] を 16 の素な区間に分割したものに対応します。各区間のサイズは、[0, 4] の一部の g に対して 16^g です。 サイズが固定されると、セグメントを再配置しても実現可能性やコストが変わらないため、最適な配置は常に連続したものになります。 

g の DP オーバーカウントにより、プレフィックス タイプの可能なマルチセットをすべて探索できるようになります。 このようなマルチセットごとに、サイズが固定されると各ブロックが独立するため、x からの貪欲な充填によってオフセットが最適に割り当てられます。 コストは要素間で線形であり、ブロック間で独立しているため、セグメントをインターリーブしないと結果が改善されません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    x, y = map(int, input().split())
    n = int(input())
    a = list(map(int, input().split()))

    L = y - x + 1

    # frequency over interval
    freq = {}
    for v in a:
        freq[v] = freq.get(v, 0) + 1

    # powers
    p = [1]
    for _ in range(4):
        p.append(p[-1] * 16)

    # cost per element for each g
    w = [(1 + g) / p[g] for g in range(5)]

    best_cost = 10**30
    best_cnt = None

    # enumerate distributions of 16 prefixes among 5 g-values
    def dfs(i, remaining, cnt):
        nonlocal best_cost, best_cnt
        if i == 4:
            cnt.append(remaining)

            cap = sum(cnt[g] * p[g] for g in range(5))
            if cap >= L:
                # compute weighted cost
                cost = 0
                idx = x
                # assign greedily by cheapest unit cost
                order = sorted(range(5), key=lambda g: w[g])
                ptr = idx
                for g in order:
                    for _ in range(cnt[g]):
                        cost += (1 + g) * p[g]  # full block cost
                if cost < best_cost:
                    best_cost = cost
                    best_cnt = cnt[:]

            cnt.pop()
            return

        for take in range(remaining + 1):
            cnt.append(take)
            dfs(i + 1, remaining - take, cnt)
            cnt.pop()

    dfs(0, 16, [])

    cnt = best_cnt

    # assign actual prefixes
    res = []
    cur_prefix = 0
    cur_x = x

    for g in range(5):
        for _ in range(cnt[g]):
            size = p[g]
            f = cur_x
            res.append((g, f))
            cur_x += size
            cur_prefix += 1

    while len(res) < 16:
        res.append((0, cur_x))
        cur_x += 1

    for g, f in res:
        print(g, f)

if __name__ == "__main__":
    solve()
```この解決策は周波数情報を構築することから始まりますが、この定式化ではコストの解釈に間接的にのみ影響します。 16 の累乗は、各エンコード深度の正確な容量を定義します。 

DFS は、16 個のプレフィックスが 5 つの可能な g 値の間でどのように分割されるかを列挙します。 完全な割り当てはそれぞれ、総容量が必要な間隔をカバーしていることを確認することによって実現可能性をチェックされます。 ブロック内のすべての要素が同じエンコード コストを共有し、ブロック内の順序付けが無関係になるため、コストの計算はブロックの総コストに単純化されます。 

最適な分布を選択した後、再構成ステップで x から順にオフセットを割り当てます。これにより、必要な範囲が互いに素にカバーされるようになります。 

実装上の微妙なリスクは、容量を n ではなく L に対してチェックする必要があることを忘れていることです。 もう 1 つは、メイン範囲で使用されていない場合でも、有効なエントリである必要がある残りのプレフィックスの処理を誤っていることです。

 ## 特殊なケース

 1 つのエッジ ケースは、L が単一プレフィックスの利用可能な容量よりもはるかに小さい場合に発生します。 たとえば、x = 0、y = 10、g = 1 の単一の接頭辞はすでに 16 個の値をカバーしています。 このアルゴリズムは g = 1 を割り当て、オフセットを x に配置し、一意性を損なうことなく有効な過近似を生成します。 

もう 1 つのケースは、シーケンスが大きく偏っている場合です。 y の近くの 1 つの外れ値を除いて、ほとんどの ai が同一であるとします。 分割すると必要な容量が減らずに要素ごとのオーバーヘッドが増加するため、最適なソリューションでは依然としてすべての値をカバーする単一の大きなブロックが好まれます。 DFS は、極端に歪んだケースを含む g 値のすべての分布を考慮するため、これが確実に評価されます。 

3 番目のケースは、範囲の長さが 16^2 + 16 のような正確な混合である場合です。アルゴリズムは、1 つの g=2 ブロックと 1 つの g=1 ブロックを結合することによってこれを処理し、オフセットが順番に割り当てられるため、重複がなく、完全なカバレッジが維持されます。
