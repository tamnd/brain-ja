 ## 解決策
 ## 問題の理解

 n − 1 個の方向のない道路で接続された n 個の都市を含むツリーが与えられます。 通常、どの道路もどちらの方向に通過するにも 1 クレジットかかります。 

キングは変更を実行します。つまり、すべての都市が、その発生する道路の 1 つを正確に選択します (または、優先順位がなければ何も選択しないこともありますが、ツリーでは、孤立した些細なケースを除くすべてのノードに少なくとも 1 つの道路があります)。 都市で選択した道路については、その都市からその特定の道路を通って移動するのが無料になります。 この方向別の割引は個人的なものではなくグローバルなものです。つまり、都市 u がエッジ (u, v) を選択した場合、u から v に移動する旅行者はそのエッジの通過に対して 0 を支払いますが、v から u への逆方向の場合は、v も選択しない限り料金 1 がかかります。 

これらの割引が適用された後、2 つの都市間のすべてのパスには、ツリー内の固有の単純なパスに沿ったエッジ トラバース コストを合計することによって得られる、明確に定義された総コストが設定されます。 タスクは、都市のペア間の最大最短パス コストが最小になるように各ノードで選択したエッジを選択し、その最小可能最大距離と選択したエッジの有効な割り当ての両方を出力することです。 

この制約では最大 200,000 個のノードが許可されるため、ノードのすべてのペアを評価したり、構成ごとに距離を繰り返し再計算したりするソリューションは除外されます。 O(n²) の動作に依存するアプローチは直ちに不可能であり、O(n log n) であっても、線形または線形に近いツリー走査を中心に注意深く構成する必要があります。 

方向性から微妙な問題が発生します。元のグラフは無向ですが、変更によりエンドポイントの選択に応じてエッジごとに非対称コストが導入されます。 単純な試みでは、エッジを貪欲に割り当てた後に最短パスを動的に計算しようとする可能性がありますが、ツリーの一部で局所的に改善すると、他の場所で全体的な最悪の場合の距離が悪化する可能性があるため、これは失敗します。 

もう 1 つのよくある落とし穴は、各エッジを独立して処理できると想定していることです。 実際には、「各ノードは出力する自由エッジを 1 つだけ選択する」という制約により、ノードに付随するすべてのエッジが結合されます。これは、構造がグローバルに制約されることを意味します。 

## アプローチ

 ブルート フォース アプローチでは、ノードごとに 1 つの発信エッジの可能なすべての割り当てが試行されます。 ツリーでは、次数 d のノードには d 個の選択肢があるため、構成の総数は次数の積となり、最悪の場合、チェーン状構造の場合は 2^(n) のように動作し、スターの場合は組み合わせ的にさらに大きくなります。 構成ごとに、すべてのペアの最短パスを再計算するか、すべてのノードから BFS/DFS を実行して少なくとも直径を計算し、構成ごとに O(n²) のコストがかかります。 これは天文学的に大きくなり、完全に不可能になります。 

重要な構造的洞察は、ノードごとに 1 つの出力エッジを選択する操作が、ルートを選択し、親ポインター構造を通じてすべてのノードをそのルートに向け、選択したエッジをその親へのエッジとして使用することと同等であるということです。 これが分かると、コスト構造は劇的に単純化されます。ルートに向かって上方向に移動すると、選択したエッジに沿って自由に移動できますが、下方向に移動すると、その特定のエッジが下位のエンドポイントで選択されない限り、常にコストが発生します。 

これにより、問題は「高価な下方移動」がどこまで蓄積されるかを制御することに変わります。 最悪の場合のパス コストは、選択したルートに対するノードの深さに密接に関係します。 したがって、最適な戦略は、最大の深さを最小限に抑えるルートを選択することです。これはまさにツリーの中心の定義です。 答えは木の半径になります。 

最適なルートが特定されると、割り当ての構築は簡単になります。各ノードは、中心をルートとする BFS または DFS ツリー内の親に接続するエッジを選択します。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 割り当てに対するブルート フォース + 距離の再計算 | 指数 | O(n) | 遅すぎる |
 | 中心ベースの根張り (木の半径) | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 2 つの BFS パスを使用して木の直径を見つけます。 任意のノードから開始して最も遠いノード a を見つけ、次に a から BFS を実行して最も遠いノード b を見つけ、パス構造を記録します。 これにより、ツリー内の最長の単純なパスが特定されます。 
2. a から b までの直径パスを再構成します。 このパスはツリー構造の両端点を表しており、最適なルートはその中間付近に存在する必要があります。 
3. 直径パスの中心を選択します。 パス長が L の場合、最適なルートは、L が偶数の場合は中間ノード、L が奇数の場合は 2 つの中間ノードのいずれかです。 この選択により、すべてのノードまでの最大距離が最小限になります。 
4. 選択したセンターから BFS を実行して、ツリー内のすべてのノードの親関係を定義します。 これにより、各ノードがルートを除く一意の親を持つルート付きツリーが生成されます。 
5. ルートを除くすべてのノードについて、選択したフリー エッジを、BFS ツリー内のそのノードを親に接続するエッジとして割り当てます。 ルートには親エッジがないため、-1 が得られます。 
6. 答え d は、この BFS ツリーで到達する最大の深さであり、ツリーの半径と等しくなります。 

これが機能する理由は、2 つのノード間のパスはルートに向かう上向きの動きとルートから遠ざかる下向きの動きに分解できるためです。 各ノードがその親エッジを選択するため、上方への移動は常に自由に行うことができます。 下方への動きは避けられず、まさに最下位の共通祖先からの深さの差に寄与します。 したがって、最悪の場合のパスは最も深いノードによって支配され、その深さを最小限に抑えることがまさにツリーの中心の問題になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import deque

def bfs(start, adj):
    n = len(adj) - 1
    dist = [-1] * (n + 1)
    parent = [-1] * (n + 1)
    q = deque([start])
    dist[start] = 0

    while q:
        v = q.popleft()
        for to in adj[v]:
            if dist[to] == -1:
                dist[to] = dist[v] + 1
                parent[to] = v
                q.append(to)

    farthest = max(range(1, n + 1), key=lambda i: dist[i])
    return farthest, dist, parent

def solve():
    n = int(input())
    adj = [[] for _ in range(n + 1)]
    edges = []

    for i in range(n - 1):
        a, b = map(int, input().split())
        adj[a].append((b, i))
        adj[b].append((a, i))
        edges.append((a, b))

    def bfs_dist(start):
        dist = [-1] * (n + 1)
        par = [-1] * (n + 1)
        par_edge = [-1] * (n + 1)
        q = deque([start])
        dist[start] = 0

        while q:
            v = q.popleft()
            for to, eid in adj[v]:
                if dist[to] == -1:
                    dist[to] = dist[v] + 1
                    par[to] = v
                    par_edge[to] = eid
                    q.append(to)

        far = max(range(1, n + 1), key=lambda i: dist[i])
        return far, dist, par, par_edge

    a, _, _, _ = bfs_dist(1)
    b, dist, par, par_edge = bfs_dist(a)

    path = []
    cur = b
    while cur != -1:
        path.append(cur)
        cur = par[cur]
    path.reverse()

    center = path[len(path) // 2]

    dist2 = [-1] * (n + 1)
    par2 = [-1] * (n + 1)
    par_edge2 = [-1] * (n + 1)

    q = deque([center])
    dist2[center] = 0

    while q:
        v = q.popleft()
        for to, eid in adj[v]:
            if dist2[to] == -1:
                dist2[to] = dist2[v] + 1
                par2[to] = v
                par_edge2[to] = eid
                q.append(to)

    ans = [-1] * n
    for v in range(1, n + 1):
        if v != center:
            ans[v - 1] = par_edge2[v]

    d = max(dist2)

    print(d)
    print(*ans)

if __name__ == "__main__":
    solve()
```最初の BFS ペアは直径の端点を特定するためにのみ使用され、2 番目の再構成ステップによりその直径に沿った明示的なノード シーケンスが得られます。 偏心を最小限に抑えるために、中心はこのパスから選択されます。 

中心に根差した最後の BFS は建設段階です。 各ノードは、その親と、そのノードに到達するために使用されたエッジの両方を記録します。これにより、そのノードから解放されるエッジが直接決定されます。 

最大距離は、最も深い BFS レベルとして計算されます。これは、誘導コスト モデルにおける最悪の下向きトラバース コストに対応します。

 ## 特殊なケース

 2 ノード ツリーは、直径に真の「中間間隔」が存在しないことを実装が正しく処理しているかどうかを明らかにします。 BFS はエンドポイント 1 と 2 を返し、センター選択はそれらの 1 つを選択します。 唯一のエッジがルートまたはリーフによって選択され、最大深さ 1 が生成される必要があるため、結果の割り当ては依然として有効です。 

1-2-3-4-5 などのパス グラフは、中心の選択が正しいかどうかをテストします。 直径はチェーン全体であり、中間ノードにより対称的な深さの分布が保証されます。 ノード 3 から BFS を実行すると、最適な半径と一致する最大深さ 2 が生成されます。 

星型ツリーにより、直径の両端点が葉である場合に、アルゴリズムが誤って葉を中心として選択することがなくなります。 直径の中間点がハブであり、BFS はすべてのエッジをハブに向けて正しく割り当て、偏心を最小限に抑えます。
