 ## 解決策
 ## 問題の理解

 負ではない整数の配列が与えられます。 0 から k までの範囲で単一の整数 x を選択することができ、配列のすべての要素に x との XOR を適用します。 この変換後、結果として得られる配列が非減少であることが必要です。 

タスクは、区間 [0, k] 内でこの非減少順序を維持する x の異なる値がいくつあるかを数えることです。 

重要な問題は、XOR では単純な単調な方法では順序が維持されないことです。 x の 1 ビットの反転で多くの比較の順序が変更される可能性があり、n が 2 · 10^5 まで、T が 2 · 10^5 までという制約は、各 x を独立してテストできないことを意味します。 配列の合計サイズは 2 · 10^5 で制限されるため、解はテスト ケースごとにほぼ線形または線形でなければなりません。また、k は 10^18 に達する可能性があるため、k に直接依存することはできません。 

強引なアイデアでは、0 から k までのすべての x を試し、変換された配列がソートされているかどうかを確認します。 それには O(nk) の費用がかかりますが、これは不可能です。 1 つの x をチェックするだけでも O(n) のコストがかかるため、k への依存性を完全に減らす必要があります。 

微妙なエッジ ケースは、すべての要素が等しいか、XOR が非常に特定のビット位置でのみ順序を破ることができる方法ですでに並べ替えられている場合です。 たとえば、a がすでに定数である場合、すべての x が機能するため、答えは k + 1 になります。ビットを過度に制限する解決策はここで失敗します。 

もう 1 つのエッジ ケースは、順序付けが隣接する要素間の最大の差ビットのみに依存する場合です。 XOR は比較全体でビットを結合するため、ビットを独立して扱う単純なビット単位の推論は失敗します。 

## アプローチ

 ブルートフォースの観点から始めます。 固定 x の場合、変換された配列 b (bi = ai ⊕ x) を計算し、b が減少していないかどうかを確認します。 これは条件に直接一致するため、簡単で正しいです。 x あたりのコストは O(n) であるため、合計の複雑さは O(nk) になります。 k は 10^18 になる可能性があるため、反復処理さえ不可能であり、明らかに x の列挙を避ける必要があります。 

重要な観察は、制約「a[i] ⊕ x ≤ a[i+1] ⊕ x」は、x の接頭辞に対するトライのような推論を使用してビットごとに分析できることです。 x を値として考えるのではなく、最上位ビットから下位に構築されるものとして考えます。 各ビットで、それを 0 に設定するか 1 に設定することですべての隣接する制約を満たすことができるかどうかを尋ねます。 

任意のペア (u, v) について、u ⊕ x ≤ v ⊕ x が必要です。 これは、XOR の後に相違する最上位ビットを比較することに相当します。 この比較は、x のプレフィックスに対する制約としてエンコードできる方法で x に依存します。 x を高位から低位までビットごとに固定すると、隣接する各ペアによって、特定のビットで 0 を選択するか 1 を選択するかによって実現可能性が保たれるかどうかの制限が課せられます。 これにより、x がまだ k によって制限されているかどうか、および以前の制約によってすでに厳密な不等号マージンが強制されているかどうかを状態追跡することで、ビットに対する桁 DP が自然に得られます。 

ビットは上位 (約 60) から下位 (0) まで処理されます。 各ステップで、すべての隣接するペアによって引き起こされる実行可能な「制約状態」のセットを維持します。 すべてのペアを明示的に追跡する代わりに、各ペアが「最初の異なるビットで変換された順序が反転する範囲に x が入ってはいけない」という形式の条件を課していることがわかります。 これは、x の一連の許容間隔を維持することになり、DP 遷移中に表現できる少数の制約に統合されます。 

最終的な構造は、k の下でまだタイトであるかどうか、および順序付けの制約が一貫しているかどうかという 2 つの次元を持つ x 上のビット単位の DP です。 各ステップでは、ビット 0 または 1 を設定するための遷移をチェックし、接頭辞 x について違反が避けられないかどうかを示す事前計算された構造を使用して、隣接するすべての比較に対する一貫性を検証します。

核となる簡略化は、すべての x をチェックする代わりに、XOR 後のバイナリ表現の辞書編集順序の一貫性を維持するように条件を変換することです。これは、隣接制約を使用してビットごとに段階的にチェックできます。 

慎重に実装すると、テストあたり O(n log A) の前処理で問題が 60 ビット以上の桁 DP に削減されます。

 ## アルゴリズムのチュートリアル

 注文条件をローカルで書き換えます。 すべての隣接するペア i について、(a[i] ⊕ x) ≤ (a[i+1] ⊕ x) が必要です。 2 つの XOR された値の比較は、それらが異なる最上位ビットによって決定されるため、問題は x が各ペアの最初の異なるビットにどのように影響するかを制御することになります。 

x を最上位ビットから下方向に処理し、段階的に構築します。 x の各プレフィックスについて、このプレフィックスがすべての制約と互換性があるかどうかを追跡します。 

1. 隣接するペア (a[i]、a[i+1]) ごとに、それらが異なる最上位ビットを事前計算します。 このビットは、x が適用された後に順序がどこで決定されるかを決定します。 それらが等しい場合、そのペアは常に有効であり、無視できます。 
2. 各ペアについて、その重要なビットにおける x の条件を導出します。 そのビットで、XOR は、x に 0 があるか 1 があるかに応じて、順序を保持するか反転します。 これにより、各ペアが、x の上位ビットを条件とする単一ビット決定の制約に変換されます。 
3. ビットを上位から下位にスイープします。 これまでに構築された x のプレフィックスが依然として制限 k 内にあり、ペアによって引き起こされるすべての制約と依然として一致しているかどうかを表す DP 状態を維持します。 
4. 各ビットについて、0 または 1 に設定してみます。k の現在のビットが 0 の場合、1 をタイトな状態に置くことはできません。 各候補ビットについて、以前に固定された上位ビットを考慮してペア制約に違反していないことを確認します。 
5. それに応じて DP を移行し、有効な完了数を累積します。 

重要な技術的ステップは、各ペア制約が 1 つのビット位置でのみ「アクティブ化」されるため、重要なビットが処理された後にそのペアの下位ビットを再検討する必要がないことです。 

### なぜ効果があるのか

 隣接する各ペアは、ai ⊕ x と ai+1 ⊕ x の間の相対順序が決定される単一の決定ビットを定義します。 x の上位ビットは、一貫した状態でその比較に到達するかどうかを決定するだけであり、最初の異なるビットが修正されると、下位ビットは結果を変更できません。 これにより、重要なビットで制約を独立して適用できる、プレフィックス一貫性のあるシステムが作成されます。 DP over bits は、[0, k] 内のすべての x 値を正確に列挙し、ペアの決定的なビットで違反を引き起こすものを正確に拒否して、正確性を保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    MAXB = 60

    for _ in range(T):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))

        # precompute critical bits and relation sign
        crit = []
        rel = []
        for i in range(n - 1):
            x = a[i]
            y = a[i + 1]
            if x == y:
                crit.append(-1)
                rel.append(0)
                continue
            b = (x ^ y).bit_length() - 1
            crit.append(b)
            # whether x < y at that bit decides constraint direction
            if (x >> b) & 1 < (y >> b) & 1:
                rel.append(0)
            else:
                rel.append(1)

        dp = [[0] * 2 for _ in range(MAXB + 1)]
        dp[0][1] = 1

        for bit in range(MAXB - 1, -1, -1):
            ndp = [[0] * 2 for _ in range(MAXB + 1)]
            kbit = (k >> bit) & 1

            for tight in range(2):
                ways = dp[MAXB - bit][tight]
                if not ways:
                    continue

                for xb in (0, 1):
                    if tight and xb > kbit:
                        continue

                    ntight = tight and (xb == kbit)

                    valid = True

                    # verify all constraints
                    for i in range(n - 1):
                        b = crit[i]
                        if b == -1 or b < bit:
                            continue
                        if b == bit:
                            # decide constraint
                            if xb == rel[i]:
                                valid = False
                                break

                    if valid:
                        ndp[MAXB - bit + 1][ntight] += ways

            dp = ndp

        ans = dp[MAXB + 1][0] + dp[MAXB + 1][1]
        print(ans)

if __name__ == "__main__":
    solve()
```実装はビット上の数字 DP に従います。 DP 状態は、各ビット位置に x の有効なプレフィックスがいくつ存在するか、およびまだ k によって制限されているかどうかを追跡します。 遷移では、各ビットの設定を試行し、決定的なビットが現在の位置以上にあるすべての隣接制約に対して実行可能性をチェックします。 

微妙な点は、最も重要な異なるビットを使用して、隣接する各制約を単一の効果的な決定点に圧縮することです。 これにより、完全な数値不等式を繰り返し推論する必要がなくなります。 

もう 1 つの重要な詳細は、厳密なフラグ処理です。 上位ビットですでに k を超えている場合、その分岐は破棄されます。 それでもタイトな場合は、k の対応するビットより少し大きく設定しないようにする必要があります。 

## 実用的な例

 a = [1, 3] という小さなケースを考えてみましょう。 XOR シーケンスは非減少のままでなければなりません。 考えられる x を分析します。 

| ビット | kビット | Xビット | タイト | 制約チェック |
 | --- | --- | --- | --- | --- |
 | 1 | 0 | 0 | 1 | 有効 |
 | 0 | 1 | 0 | 1 | 有効 |

 これは、1 から 3 までの順序がいくつかの選択肢に対する XOR の下で安定しているため、複数の x 値が依然として実現可能であることを示しています。 

ここで、a = [2, 0, 1] の場合を考えてみましょう。 ここでは、順序付けの制約がより強く競合します。 

| ペア | クリティカルビット | 関係 |
 | --- | --- | --- |
 | (2,0) | MSB | 拘束を強制する |
 | (0,1) | LSB | 弱い制約 |

 x をビットごとに構築すると、特定の代入のみが最上位の異なるビットでの順序の反転を回避することがわかります。 

このトレースは、制約がグローバルに相互作用するのではなく、単一のビット位置にどのように局在化するかを示しています。

 ## 特殊なケース

 すべての要素が等しい配列の場合、[0, k] 内のすべての x が有効です。 すべての重要なビットが非アクティブとしてマークされるため、アルゴリズムはこれを処理します。そのため、DP 遷移中に制約が候補を拒否することはありません。 

単一要素の配列の場合、隣接する制約がないため、すべての x が有効になります。 DP は失敗する制約に遭遇することはなく、[0, k] の範囲内のすべての数値をカウントします。 

隣接する差分が下位ビットでのみ発生する場合、x の上位ビットは有効性に影響を与えることはありません。 DP は、クリティカル ビットが現在の処理ビットを下回る制約を正しくスキップし、選択肢が時期尚早に制限されないようにします。 

ジグザグ シーケンスなど、制約が競合する場合、各制約は異なるビットでアクティブになります。 このアルゴリズムは、最も古い関連制約に違反する x のプレフィックスのみを拒否し、グローバルに一貫した割り当てのみがカウントされるようにします。
