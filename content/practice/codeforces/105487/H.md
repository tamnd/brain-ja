 ## 解決策
 ## 問題の理解

 バイナリ文字列が与えられると、それをシーケンスとして解釈します。`1`キャラクターは重要です。 最大の連続ブロックごとに、`1`s はセグメントを形成しますが、`0`s は、文字列を独立したセグメントに分割する区切り文字として機能します。 

連続するセグメントごとに`1`s、長さがあるとします$L$、合計スコアへの寄与は長さの平方根として定義されます。 文字列の合計値は、すべてのセグメントにわたるこれらの平方根の合計です。 

元の文字列を取得して、その一部を反転することができます。`1`に入る`0`このスコアを評価する前に。 を回す`1`の中へ`0`セグメントを複数の小さなセグメントに分割することもできますが、セグメントの数も減ります。`1`はスコアに貢献できる状態のままです。 目標はどちらを選択するかです`1`s を削除して、再セグメント化後に、結果として得られるすべての平方根の合計が`1`-セグメントが最大化されます。 

重要な制約は、文字列の長さが次のとおりであることです。$10^6$したがって、どのような解決策も本質的に時間的に線形である必要があります。 削除のすべてのサブセットやセグメントのすべてのパーティションを考慮しようとすることは、ただちに実行不可能です。$L$飛躍的に多くの分割方法が認められるでしょう。 

微妙な点は、決定が各最大ブロックに対してローカルであることです。`1`元の文字列の s。 ゼロは異なるブロック間で相互作用することがないため、各ブロックを個別に最適化してから合計することができます。 

よくある落とし穴は、ブロックを分割することが常に有益であると想定していることです。$\sqrt{x} + \sqrt{y} > \sqrt{x+y}$。 それは事実ですが、分割には削除に費用がかかるため、総数が減少します。`1`答えに貢献しています。 たとえば、長さのブロックでは`4`、何も削除しなかった場合、取得されるものは$\sqrt{4} = 2$ただし、積極的に分割しようとすると、一部を削除する必要があります。`1`s を使用してセパレータを作成し、それらの削除により使用可能な総質量が減少します。 

文字列に何もない場合には、別の特殊なケースが発生します。`0`まったくです。 例えば、`111111`分割できるのは文字を削除することによってのみであり、削除するたびに利用可能な貢献の合計が減少するため、分割による利益と利用可能な要素の損失のバランスを取る必要があります。`1`s.

 ## アプローチ

 強引なアイデアは、ポジションを反転する位置のすべてのサブセットを考慮することです。`1`の中へ`0`。 このような選択ごとに、結果として得られるすべてのセグメントを再計算し、それらの平方根を合計します。 これは定義に直接従っているので正しいですが、絶望的に高価です。 長さの文字列$n$もっている$2^n$考えられる削除パターンがあり、1 つの構成を評価するだけでも直線的な時間がかかり、全体的な複雑さは実現可能な限界をはるかに超えています。 

重要な観察は、問題が最大の実行ごとに分解されるということです。`1`s. 一定の長さのランの内側$L$、私たちは効果的にいくつを選択していますか`1`を保持し、それらをセグメントに分割する方法。 構造はトレードオフになります: より多くのものを保持する`1`s は利用可能な総質量を増加させますが、分割すると平方根項の数が増加します。 

重要な単純化は、単一の実行の最適な形状を理解することです。 維持することに決めたとします。$k$ランニングからのもの。 平方根の合計を最大化するには、それぞれを維持する必要があります。`1`可能な限り独自のセグメントを形成するため、$\sqrt{1} = 1$ユニットあたりの効率が最も高くなります。 ただし、保管されているそれぞれを分離すると、`1`中間文字を削除する必要があり、削除は制限されています。 

維持すれば$k$それらすべてを隔離したい場合は、少なくとも必要です$k-1$削除してそれらを分離します。 私たちにはそれしかないので、$L-k$実行内で削除が可能、実現可能性が必要$$k - 1 \le L - k \quad \Rightarrow \quad k \le \frac{L+1}{2}.$$したがって、最適な完全に分割された構成では、最大で次の値が得られます。$\left\lfloor \frac{L+1}{2} \right\rfloor$。 

一方、何も削除しない場合、ブロック全体はそのままの状態で維持され、次の結果が得られます。$\sqrt{L}$。 

中間の不規則分割には利点がありません。非シングルトン セグメントでは、実現可能な最高の極限値を超えるほどユニットあたりの効率が向上することなく、平方根項の数が減少します。 したがって、各実行では、全体を保持するか、削除制約の下でできるだけ多くの分離されたものを抽出するかを選択することになります。

 | 削除に対するブルートフォース |$O(2^n)$|$O(n)$| 遅すぎる |
 | 実行ごとの最適化 |$O(n)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 文字列を 1 回スキャンし、最大の連続ブロックをすべて抽出することで文字列を処理します。`1`s. 長さのブロックごとに$L$、達成可能な最高の寄与を個別に計算します。 

1. 文字列をトラバースし、連続するものをカウントします。`1`まで`0`が発生するか、文字列が終了します。 これによりランレングスが得られます$L$。 
2. この実行について、2 つの答えの候補を計算します。実行をそのままの状態に保つことが貢献します。$\sqrt{L}$、分離されたものに完全に分割することは貢献しますが、$\left\lfloor \frac{L+1}{2} \right\rfloor$。 
3. これら 2 つの値のうち大きい方を全体的な答えに追加します。 
4. 文字列全体が処理されるまで続行します。 

部分的な分割パターンを考慮しない理由は、そのような構成は、いくつかの保持されたものを選択することに対応するためです。$k$、そしてその最高の達成可能な値はまさに$k$ただし、実現可能性の制約には上限があります$k$で$\lfloor (L+1)/2 \rfloor$。 サイズ 1 より大きいセグメントを形成しようとする試みは、保持されるセグメントの合計を増やすことなく厳密にセグメントの数を減らすため、優先されます。 

### なぜ効果があるのか

 ゼロはコントリビューションを永続的に分離するため、各実行は独立しています。 実行内で、保持する位置のサブセットを選択することにより、すべての有効な最終構成を記述することができます。`1`s および削除を区切り文字として扱います。 目標はシングルトン セグメントの数において線形であり、最適な配置により、実現できる分離セグメントの数を最大化することにすべてのメリットがもたらされます。 セパレータの要件から導出される実現可能性条件は、分離された寄与の最大数を完全に特徴づけるものであり、代替手段は実行をそのまま維持することです。 他のすべてのパーティションは、保持された質量と達成可能なセグメンテーションの両方においてこれらの極端の間にあるため、2 つの候補のうち最良のものを超えることはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    s = input().strip()
    n = len(s)
    
    ans = 0.0
    i = 0
    
    while i < n:
        if s[i] == '0':
            i += 1
            continue
        
        j = i
        while j < n and s[j] == '1':
            j += 1
        
        L = j - i
        
        # option 1: keep whole segment
        keep_whole = (L ** 0.5)
        
        # option 2: split into isolated ones (optimal feasible)
        split = (L + 1) // 2
        
        ans += max(keep_whole, split)
        
        i = j
    
    print(f"{ans:.10f}")

if __name__ == "__main__":
    main()
```この実装は、1 の実行を識別し、実行ごとに 2 つの導出候補を評価する単一の線形スキャンです。 平方根の場合は直接計算されますが、組み合わせ分割の場合は閉形式の実現可能範囲から取得されます。 最終的な答えには高い精度が必要なため、浮動小数点での累算には注意が必要です。 

実装の微妙な詳細は、整数分岐は正確なままである一方、平方根分岐ではすべての計算が浮動小数点演算のままでなければならないことです。 これらは代数的に結合されるのではなく、比較されるだけであるため、それらを混合しても安全です。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    
    s = input().strip()
    
    ans = 0.0
    i = 0
    n = len(s)
    
    while i < n:
        if s[i] == '0':
            i += 1
            continue
        j = i
        while j < n and s[j] == '1':

        ans += max(L ** 0.5, (L + 1) // 2)

 ## 特殊なケース

 完全に以下からなる実行`0`s は貢献を生成しないため、すぐにスキップされます。 アルゴリズムはこれを自然に処理します。`1`-セグメントが形成されるため、計算はトリガーされません。 

次のような単一のロングラン`111111...`主要な決定ルールを実行します。 このアルゴリズムは平方根形式と分割限界の両方を評価し、削除をシミュレートすることなく実行ごとに最大値が正しく取得されます。 

次のような文字が交互に並ぶ文字列`1010101`すべての実行を長さ 1 に削減します。それぞれが正確に 1 に寄与し、両方の候補式が一致するため、比較または浮動小数点評価で不安定性がなくなります。
