 ## 解決策
 ## 問題の理解

 大文字のみで構成される単一の長い文字列が与えられます。 文字を任意に並べ替えることができます。 並べ替えた後、結果の文字列内でパターン「CCPC」が連続部分文字列として出現する回数を確認します。 これらの発生は重複することが許可されます。 

タスクは、文字列のすべての順列にわたってそのような出現の最大可能数を計算することです。 

入力サイズは最大 100 万文字まで可能です。 これにより、すべての順列を明示的に構築したり、組み合わせ的な方法でパターンの配置をシミュレートしようとするアプローチは即座に除外されます。 二次関数でも、$O(n \log n)$文字列の大部分を複数回繰り返しスキャンする構造は、位置ごとに重い処理を行うと遅すぎます。 

自由に並べ替えることができるため、重要な情報は文字の頻度だけです。 したがって、問題の構造は元の配置に関するものではなく、使用可能な文字を使用してパターン「CCPC」の重複するコピーを何回パックできるかということになります。 

重なり合うと、微妙なエッジケースが発生します。 たとえば、十分な文字があれば、パターンで文字を共有できます。 素朴な解釈では、「CCPC」の互いに素なブロックを想定する可能性がありますが、「CCPCC」のような重複には、カウントが慎重に構築できる場合にのみ、位置 1 と 2 で始まる 2 つの出現が含まれます。 ただし、オーバーラップは、元の文字列の隣接性ではなく、文字の利用可能性とパターン構造によって依然として制限されます。 

もう 1 つの重要なエッジ状況は、カウントがかろうじて十分な場合です。 たとえば、すべての有効なパターンには 3 つの C と 1 つの P が必要であるため、C が 2 つ未満の場合、P がいくつ存在しても発生することはありません。 

## アプローチ

 強引なアイデアは、最終的な文字列を構築し、「CCPC」の出現を 1 つずつ配置しようとすることを考えることです。 各ステップで、パターンをある位置に挿入し、文字数を減らし、再帰的に続行することを試みることができます。 各配置の選択は将来のすべての配置に影響を与えるため、これはすぐに指数関数的になります。重複するパターンは複数の相互作用する方法で配置される可能性があるため、貪欲なローカル配置ですら信頼できません。 

もう 1 つの強引な解釈は、文字列のすべての順列を試し、それぞれの中で「CCPC」の出現をカウントすることです。 これは階乗時間であり、すぐには実行不可能です。$n = 10^6$。 

重要な観察は、問題はカウントするだけであり、パターン構造は単純であるということです。3 つの C と 1 つの P を使用します。しかし、本当の難しさは、C が連続した出現の間で共有される可能性があることであり、最適な配置は単に「できるだけ多くの互いに素な CCPC ブロックを取る」ということではありません。 

配置という観点から考えるのではなく、視点を逆転させて、出現回数を最大化する長い文字列がどのように見えるべきかを検討します。 最適な配置では、「CCPC」が出現するたびに複数の文字セットが消費されますが、重複することで中央の C を再利用できます。 各パターンには P が 1 つだけ含まれており、出現間で P を共有できないため、構造を「区切る」唯一の文字は P です。 

これは、「CCPC」の各出現が効果的に P の周囲に固定され、周囲の C によってサポートされていることを示唆しています。 最良の構築は、P をグループ化し、その周囲に C をできるだけ密に配置することです。 

コアの削減は次のようになります。各出現には 1 つの P が必要で、出現ごとに 3 つの C が必要ですが、C は隣接するパターン間で限定された方法でのみ再利用できます。 パターンの最大チェーンを構築することを想像する場合、制限要因は、共有 C を通じてパターンが重複することを考慮しながら、利用可能な C を 3 つのブロックで何回「消費」できるかということです。 

結果の構造はパッキング パターンのように動作し、新しい出現ごとに最初の重複境界を超えて 1 つの新しい P と 2 つの新しい C が消費され、カウントに基づいた単純な最大化が行われます。 

そこで、C と P の数を計算します。答えは、P の数と、連鎖したオーバーラップをサポートできる C のグループの数によって制限されます。 最終結果は、利用可能なリソースで k 個のオカレンスを形成できる最大 k です。

 ## アルゴリズムのチュートリアル

 まず、文字列内に各文字が何回出現するかを数えますが、実際には C と P の数のみを考慮します。 

次に、この問題は、重複する「CCPC」ブロックの最大数を構築することであると解釈します。 

1. 文字列内の C 文字と P 文字の数を数えます。 再配置により位置の制約がなくなるため、このステップでは使用可能な情報がすべて入力から抽出されます。 
2. 「CCPC」の有効な出現には少なくとも 1 つの P が必要であるため、出現の数が P の数を超えることはできないことに注意してください。 これにより、最初の上限が得られます。 
3. 各出現には 3 つの C も必要ですが、出現が重複する可能性があるため、C を独立してすぐに 3 で割ることはしません。 代わりに、チェーン内に k 個の出現を配置すると、必要な個別の C の総数は k + 2 になると考えます。これは、最適な配置では、連続するパターンが境界でちょうど 1 つの C を共有するという事実から来ています。 
4. 制約を結合します。最大限に重複する構造で k 個の出現を実現するには、少なくとも k 個の P と少なくとも k + 2 個の C が必要です。 
5. k ≤ P および k + 2 ≤ C となる最大の k を求めます。 
6. したがって、答えは min(P, C − 2) であり、その下限はゼロです。 

重要な推論ステップは、最適なオーバーラップにより C の消費量が 3k ではなく 3k から k + 2 に削減されることを認識することです。 

### なぜ効果があるのか

 k 個のオカレンスを実現する構成では、各オカレンスが 1 つの P に寄与するため、P は厳密なオカレンスごとの要件です。 C の場合、連続する出現をできるだけ整列させて書き留めると、最初の出現の後の各新しい出現では、2 つの新しい C のみが導入されます。これは、1 つの C が 1 つの出現の末尾部分および次の構造の先頭部分として共有されるためです。 これにより、緊密な線形充填構造が確立されます。 C の使用量をさらに削減しようとすると、必要な「CCPC」の部分文字列構造が壊れてしまいます。これは、各出現箇所に独自の内部「CCP」プレフィックスと終了 C アラインメントが含まれている必要があるためです。 したがって、導出された境界は必要であり、達成可能です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    c = s.count('C')
    p = s.count('P')
    # k <= p and k <= c - 2
    if c < 3:
        print(0)
        return
    print(min(p, c - 2))

if __name__ == "__main__":
    solve()
```この解決策は完全に頻度カウントに依存しているため、最終的な文字列の構築を回避します。 条件チェック`c < 3`の負の値を防ぐ`c - 2`そうしないと、有効な出現が誤って示唆されてしまいます。 

ロジック`min(p, c - 2)`アルゴリズムのウォークスルーで導出された 2 つの独立した制約を直接エンコードします。 

## 実用的な例

 インプットを考慮する`CCPCCPC`。 

文字数を数えます: C = 5、P = 2。 

制約を計算します。P は最大 2 回の出現に制限します。 C − 2 = 3、結合しません。 したがって、答えは 2 です。 

| ステップ | C カウント | P カウント | P | からバインド C − 2 からバインドされる | 答え |
 | --- | --- | --- | --- | --- | --- |
 | 初期化 | 5 | 2 | 2 | 3 | 2 |

 これは、Cが豊富であってもPがボトルネックであることを示しています。 

ここで考えてみましょう`CCCCP`。 

C = 4、P = 1。 

P = 1 であるため、形成できるオカレンスは 1 つだけです。C − 2 = 2 であるため、C で十分です。 

| ステップ | C カウント | P カウント | P | からバインド C − 2 からバインドされる | 答え |
 | --- | --- | --- | --- | --- | --- |
 | 初期化 | 4 | 1 | 1 | 2 | 1 |

 これは、余分な C があっても、P が構築を厳しく制限していることを裏付けています。

 ## 特殊なケース

 次のような非常に小さな文字列の場合`PP`または`CC`の場合、C が 3 未満であるか P が 0 であるため、アルゴリズムはすぐに 0 を返します。そのため、有効な部分文字列は存在できません。 

多くの C があり、P が 1 つだけある入力の場合、次のようになります。`CCCCCCCCCP`、アルゴリズムは 1 を返します。トレースは単純です: C = 9、P = 1、つまり min(1, 7) = 1。この構築では単一の P をアンカーとして使用し、必要な C のみを消費します。 

P が多くても C が不十分な入力の場合、次のようになります。`CCCPPPP`の場合、C = 3、P = 4 が得られるため、答えは min(4, 1) = 1 となります。P が豊富であっても、C 制約が優勢です。 

これらのケースは、数式が両方の制約を対称的に処理し、物理的に実現できない重複の過剰カウントを回避していることを確認します。
