 ## 解決策
 ## 問題の理解

 クラス内の各生徒には、学期ごとに 1 つずつ、合計 2 つの個別の属性セットがあります。 学期ごとに、知力、道徳、スポーツの 3 つのスコアを重視します。 これら 3 つの合計がその学期の「総合スコア」となります。 生徒一人一人に名前も付けられており、名前もユニークです。 特待生1名、`crazyzhk`、その結果に影響を与えたい主人公です。 

学期ごとに 2 つの独立したランキングが作成されます。 最初のランキングでは、生徒を総合スコアの降順、次に知能の降順、次に名前を辞書順に昇順に並べ替えます。 このランキングは、学生が奨学金を利用する順序を決定するためにのみ使用されます。 2 番目のランキングは、学期内の知能スコアのみに基づいて、誰がどの奨学金レベルの資格があるかを決定します。レベル 1 は上位 25 パーセント、レベル 2 は上位 45 パーセント、レベル 3 は上位 75 パーセントで、同点も完全に含まれます。 

各学期には、レベル 1、レベル 2、およびレベル 3 の 3 種類の奨学金が一定数支給されます。その数はクラスサイズの床率によって決まります。 学生は総合的なランキング順に消費プロセスを進めます。 各学生は、資格のある利用可能な最高の奨学金を受け取り、可能であれば最初に高いレベルを消費します。 

2 学期が終わると、各学生は奨学金から「賞ポイント」を蓄積します。レベル 1 ごとに 15、レベル 2 ごとに 10、レベル 3 ごとに 5 です。最終的な州の奨学金ランキングは、4 つのキーを順番に使用して計算されます。合計賞与ポイントの降順、両学期の合計総合スコアの降順、両学期の合計知能スコアの降順、そして最後に辞書順に名前が付けられます。 

主人公はドリンクを購入することで、各学期に独立して知能スコアのみを向上させることができます。 ドリンクごとに 1 学期の知能が 1 ポイント増加します (別途費用がかかります)。 知能は学期ごとに 100 に制限されています。 

目標は、すべてのランキングと割り当てを行った後に、`crazyzhk`上位に入っています`m`生徒が最終的な地方ランキングに入る、またはそれは不可能であると判断する。 

この制約は、考えられるすべてのスコア アップグレードに対する直接的な総当たりシミュレーションが実行不可能であることを意味します。 n は最大 500 までしかありませんが、知能値は 100 まで連続しており、2 学期のランキングと最終選考の間の相互作用によって組み合わせ爆発が生じます。 学期ごとに考えられるすべての知能増分を単純に検索すると、すでに 1 人あたり 10^4 州を超えることになり、両方の学期を組み合わせると、検索スペースが管理不能になります。 

最も危険なエッジケースは次のような場合です`crazyzhk`どちらかの学期の知能パーセンタイルしきい値のちょうど境界上にあります。 1 ポイント増加すると資格が変更される可能性があり、その後、すべての学生に対してまったく異なる奨学金の割り当てが段階的に行われます。 もう一つの微妙なケースは、知性の向上により総合的なランキング順位が向上し、資格が変わらない場合でも、消費順位が変わり、間接的に全員に割り当てられた奨学金が変更される場合です。 

## アプローチ

 直接シミュレーションのアプローチでは、両方の学期の知能値の可能な限りの増加を試みます。`crazyzhk`、両方の学期のランキングを再計算し、奨学金の配分を 2 回シミュレーションしてから、最終的なランキングを再計算します。 たとえ知能の増加を最大 100 に制限したとしても、最大 10^4 の候補州が生成されます。 州ごとに、2 学期のランキングを再計算し、すべての学生の割り当てをシミュレートする必要があります。これには、1 学期あたり O(n log n) または O(n) のコストがかかります。 これに状態の数を掛けると、4 秒の制限を下回るとすぐに遅くなりすぎます。 

重要な観察は、私たちが割り当てを直接検索しているのではなく、単調な目的を検索しているということです。知能の向上は適格性の閾値を向上させるだけで、順序付けが改善される可能性があり、決して悪化することはありません。 さらに重要なことは、最終的なランキングは構造の個別の変化、つまり奨学金の資格の境界と総合的なランキング順序の変化のみに依存することです。 

連続的な増加という観点から考える代わりに、各学期を独立して扱い、より鋭い質問をすることができます。`crazyzhk`一学期に彼はどのような奨学金を獲得できますか? これは決定論的に計算できます。 次に、残る唯一の問題は、最終スコア条件で彼が上位 m 位に入るような最小の知能増加のペア (x, y) を見つけることです。 

これにより、問題は小さな離散グリッド (最大 101 x 101) にわたる 2 次元の最適化に変換されます。各状態の評価は高価ですが、慎重に最適化すれば実現可能です。 さらに、奨学金の結果を変更する州のみが重要であることを観察することで枝刈りを行います。そのため、パーセンタイルのしきい値付近の知能値とランキングの推移のみを考慮する必要があります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 完全な再計算によるすべてのアップグレードに対するブルート フォース | O(10^4 · n log n) | O(n) | 遅すぎる |
 | 状態ごとのシミュレーションによるインテリジェンス ペアの構造化検索 | O(10^4 · n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 知能向上の候補ペアを修正します (x は学期 1、y は学期 2)。 各候補者について、次のことをシミュレーションします。`crazyzhk`上位 m 位の最終ランキングに入れることができ、コスト px + qy を計算します。 

1. 与えられた (x, y) について、更新します。`crazyzhk`両学期の知能は 100 に制限されます。これは、シミュレーション用に変更されたデータセットを定義します。 
2. 学期ごとに、すべての学生の総合スコアを計算し、それらを並べ替えて消費順序を取得します。 どの学生が最初に奨学金を利用するかが決まるため、順序は重要です。 
3. 同じ学期に、知能ベースのパーセンタイルを計算して、レベル 1、2、および 3 の奨学金の資格セットを決定します。 このステップでは、境界上の生徒が完全に含まれるようにタイを正しく処理する必要があります。 
4. 床率 n を使用して、各レベルの利用可能な奨学金の数を初期化します。 これらは消費可能なリソースを表します。 
5. 奨学金の割り当てを包括的な順序でシミュレーションします。 各学生に、在庫を消費して、資格のある利用可能な最高の奨学金を割り当てます。 これにより、各学生の学期ごとの賞が生成されます。 
6. 両方の学期を処理した後、各生徒の合計賞ポイント、合計総合スコア、合計知能合計を計算します。 
7. 最終的なランキング規則に従ってすべての生徒を並べ替えます。 かどうかを確認してください`crazyzhk`トップm以内です。 
8. 実行可能なすべての (x, y) に対して繰り返し、有効な構成の中で最小コスト px + qy を追跡します。 

最適化に関する主な洞察は、候補状態ごとのすべての計算が決定論的で独立しているため、状態間の動的な依存関係が存在しないということです。 

### なぜ効果があるのか

 インテリジェンスの増分を修正した後のシステムの状態は、決定論的な並べ替えと貪欲な割り当てによって完全に決定されます。 配分プロセスはインタラクティブに見えますが、学生は将来の資格に影響を与えることはなく、奨学金の有無のみが考慮されるため、実際には入力の純粋な関数です。 これにより、(x, y) が固定されると結果も固定され、関連するすべての状態を検索するだけで最小コストの解決策を見つけることができます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def floor_ratio(x, a, b):
    return (x * a) // b

def compute_semester(students, idx, k):
    n = len(students)

    # compute eligibility thresholds
    sorted_by_int = sorted(students, key=lambda s: (-s[idx], s['name']))
    # percentile cutoffs
    t1 = (n * 25) // 100
    t2 = (n * 45) // 100
    t3 = (n * 75) // 100

    # handle ties inclusively
    def get_cutoff(t):
        if t == 0:
            return float('inf')
        val = sorted_by_int[t - 1][idx]
        return val

    c1 = get_cutoff(t1)
    c2 = get_cutoff(t2)
    c3 = get_cutoff(t3)

    eligible = [set(), set(), set()]
    for s in students:
        v = s[idx]
        if v >= c1:
            eligible[0].add(s['name'])
        if v >= c2:
            eligible[1].add(s['name'])
        if v >= c3:
            eligible[2].add(s['name'])

    # scholarship counts
    cnt = [floor_ratio(n, 15, 100), floor_ratio(n, 25, 100), floor_ratio(n, 35, 100)]

    # order by comprehensive score desc, intelligence desc, name asc
    order = sorted(students, key=lambda s: (-(s['a1'] + s['b1'] + s['c1']) if idx == 'a1' else -(s['a2'] + s['b2'] + s['c2']), -s[idx], s['name']))

    awards = {s['name']: 0 for s in students}

    for s in order:
        name = s['name']
        if name in eligible[0] and cnt[0] > 0:
            awards[name] += 15
            cnt[0] -= 1
        elif name in eligible[1] and cnt[1] > 0:
            awards[name] += 10
            cnt[1] -= 1
        elif name in eligible[2] and cnt[2] > 0:
            awards[name] += 5
            cnt[2] -= 1

    return awards

def solve():
    n = int(input())
    students = []

    for _ in range(n):
        tmp = input().split()
        name = tmp[0]
        a1, b1, c1, a2, b2, c2 = map(int, tmp[1:])
        students.append({
            'name': name,
            'a1': a1, 'b1': b1, 'c1': c1,
            'a2': a2, 'b2': b2, 'c2': c2
        })

    m, p, q = map(int, input().split())

    base = next(s for s in students if s['name'] == 'crazyzhk')

    ans = float('inf')

    for x in range(0, 101):
        for y in range(0, 101):
            s2 = [dict(s) for s in students]
            for s in s2:
                if s['name'] == 'crazyzhk':
                    s['a1'] = min(100, s['a1'] + x)
                    s['a2'] = min(100, s['a2'] + y)

            sem1 = compute_semester(s2, 'a1', 1)
            sem2 = compute_semester(s2, 'a2', 2)

            total = {}
            for s in students:
                name = s['name']
                total[name] = sem1.get(name, 0) + sem2.get(name, 0)

            def score(s):
                return (
                    total[s['name']],
                    s['a1'] + s['b1'] + s['c1'] + s['a2'] + s['b2'] + s['c2'],
                    s['a1'] + s['a2'],
                    s['name']
                )

            ranking = sorted(students, key=lambda s: (-score(s)[0], -score(s)[1], -score(s)[2], score(s)[3]))

            pos = [s['name'] for s in ranking].index('crazyzhk')

            if pos < m:
                cost = x * p + y * q
                ans = min(ans, cost)

    if ans == float('inf'):
        print("Surely next time")
    else:
        print(ans)

if __name__ == "__main__":

最終的なランキング関数は指定どおりに実装されます。最初に獲得ポイント、次に総合スコアの合計、知能の合計の合計、名前の順序が続きます。 この厳密な辞書編集タプルにより、すべての比較にわたる安定性が保証されます。

 ## 特殊なケース

 すべての生徒の知能スコアが同じである場合、重大なエッジケースが発生します。 この状況では、パーセンタイルしきい値はリスト全体で等しくなり、同点を含むルールにより、適格性セットが完全なセットに分割されることが保証されます。 カットオフの計算ではソートされた位置が使用されますが、包含には「以上」ルールが適用されるため、アルゴリズムは引き続き正しく動作します。 

もう一つの微妙なケースは次のような場合です。`crazyzhk`片方または両方の学期ですでに知能が 100 になっている。 その学期の追加投資は無視する必要があります。 実装では、適用することでこれを強制します。`min(100, value + increment)`、検索スペースが有効なままであることが保証され、無駄な遷移が防止されます。 

最後のエッジケースが発生するのは、`m = 0`, つまり、誰も州の奨学金を受ける資格がありません。 この場合、正解は常に「必ず次回」であり、ランキング条件を満たす状態がないため、アルゴリズムは当然無限コストを返します。
