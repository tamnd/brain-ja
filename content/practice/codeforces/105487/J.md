 ## 解決策
 ## 問題の理解

 1 から n までの整数の 2 つの順列が与えられますが、それらは位置によってインデックス付けされた配列として格納されます。 各クエリは、最初の置換でインデックスの連続セグメントを選択し、2 番目の置換で別の連続セグメントを選択します。 これら 2 つのセグメントから、各セグメントから 1 つずつ値のすべてのペアを形成し、各ペアについて最大公約数の 2 乗を計算します。 クエリでは、これらの二乗 gcd 値の合計が求められます。 

言い換えれば、各クエリは 2 つの数値セットを定義します。1 つのセットは、次の部分配列に現れる値から取得されます。`a`、もう一方は部分配列に現れる値からのものです。`b`。 次に、これら 2 つのセット間の完全な 2 部ペアを考慮し、選択した 2 つの値の gcd のみに依存する関数を集計します。 

制約は大きく、最大 100,000 個の要素と 100,000 個のクエリです。 最悪の場合、1 つのクエリに最大 10^10 のペアが含まれる可能性があるため、クエリごとにすべてのペアを検査するソリューションは直ちに不可能です。 計算を大幅に圧縮しない限り、クエリごとに片側だけを反復処理するだけでも遅すぎます。 これにより、ペアの列挙を回避し、代わりに構造化されたペアのグループをカウントする解決策が求められます。 

素朴な考えは、クエリ内のすべてのペアの gcd を直接計算することです。 クエリごとの 2 次の複雑さのため、これはすでに失敗しています。 

もう少し素朴なアイデアは、gcd 値をグローバルに事前計算するか、プレフィックス構造を再利用することです。ただし、gcd は単純な方法では加法的ではなく、範囲にわたって分解できないため、標準的なプレフィックス トリックは適用されません。 

この問題をインデックス ドメインのみに対する独立した範囲クエリとして処理しようとすると、より微妙な障害モードが発生します。 難しいのは、値の分布が順列であることです。インデックスと値が絡み合っており、条件がインデックス空間ではなく値空間 (割り算) で定義されます。 

## アプローチ

 ブルートフォースアプローチは簡単です。 クエリごとに、次のすべてのインデックスを反復処理します。`[l, r]`そして`[L, R]`、計算する`gcd(a[i], b[j])`、それを二乗し、その結果を累積します。 これはクエリの定義に直接従うため、正解です。 ただし、クエリごとの操作数はセグメント長の積に比例し、最悪の場合は n² になります。 q 個のクエリにわたって、これは最悪のシナリオでは n³ になりますが、n = 10⁵ の場合はまったく実行不可能です。 

重要な観察は、gcd 構造が生の値ではなく約数によって支配されるということです。 ペアごとにグループ化する代わりに、貢献度を gcd 値ごとにグループ化します。 標準恒等式を使用すると、各セット内の要素が d で割り切れる数をカウントするという観点から、gcd が正確に d であるすべてのペアの寄与を書き直すことができます。 

固定クエリに対して次のように定義すると、`A_d`d で割り切れる最初のセグメントの要素の数として、`B_d`2 番目のセグメントについても同様に、両方の要素が d で割り切れるペアの数は次のようになります。`A_d * B_d`。 これには、gcd が正確には d ではなく、その倍数であるペアが含まれます。 これは、倍数に対する除数の包含/除外を使用して修正できます。 

したがって、構造は約数 DP になります。大きいものから小さいものまで、それぞれの d について、倍数のカウントを使用して、gcd が正確に d であるペアの数を計算します。 

課題は、各クエリに値が必要であることです。`A_d`そして`B_d`すべての d に対して、クエリごとにそれらを最初から再計算すると、やはり時間がかかりすぎます。 解決策は、値の位置マップを事前計算し、両方の順列で「d で割り切れる値」の高速範囲カウントを維持し、これらのカウントを効率的に取得して各クエリに答えることです。 

次のようにアプローチを比較できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | クエリあたり O(n²) | お(1) | 遅すぎる |
 | 除数のグループ化 + 範囲のカウント | O((n log n + q log n)) クエリ構造ごとの償却コスト | O(n log n) | 承認済み |

 重要な改善点は、ペアの列挙から除数ごとの集計に移行し、二次オブジェクトを対数除数構造に変換することです。 

## アルゴリズムのチュートリアル

 私たちは、gcd 構造は可算性の観点から表現すると扱いやすいという観察に基づいて作業します。 

1. 1 ～ n の各値 x について、配列内のその位置を計算します。`a`そして配列で`b`。 これにより 2 つの配列が得られます`posA[x]`そして`posB[x]`。 すべての値は 2D 平面内の点になります。 
2. クエリ`[l, r] × [L, R]`この 2D 平面では長方形になります。次のようなすべての値 x が必要です。`posA[x] ∈ [l, r]`そして`posB[x] ∈ [L, R]`。 
3. 固定クエリの場合、関数を定義します`cntA[d]`値が d で割り切れる四角形内の値の数として、および同様に`cntB[d]`。 
4. gcd を直接計算する代わりに、除数の寄与に切り替えます。 各 d について、両方の値が d で割り切れるペアの数は次のとおりです。`cntA[d] * cntB[d]`。 
5. d に対して減少する DP を使用して、正確な gcd 寄与を計算します。 

1. n から 1 までの d について、計算します。`f[d] = cntA[d] * cntB[d]`。 
2. すでに割り当てられている倍数の寄与を減算します。k ≥ 2 の倍数 k・d ごとに、`f[k·d]`から`f[d]`。 
6. 最後に、各 gcd クラスが貢献します。`d² * f[d]`答えに。 

重要な計算タスクは評価です`cntA[d]`そして`cntB[d]`クエリ内のすべての d に対して。 これは、両方の順列で d で割り切れる数値の位置のリストを d ごとに前処理することによって行われます。 可分性群は安定しているため、これらのリストは一度作成できます。 

クエリの場合、これらの並べ替えられたリスト内で二分検索を行い、d あたり O(log n) のカウントを取得します。 

### なぜ効果があるのか

 すべての値のペアは、一意の gcd クラスに 1 回だけ寄与します。 除数ベースのカウントでは、まず除数 d を共有するすべてのペアをカウントし、次に、より高い倍数に属するペアを減算します。 これにより、正確な gcd 値によってすべてのペアの素のパーティションが構築されます。 正確さは、すべての整数のペアが一意の最大公約数を持ち、倍数に対する包含/除外によって曖昧さなく正確に過剰カウントが除去されるという事実に基づいています。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

# Precompute divisors list
def build_div_lists(n, pos):
    div_lists = [[] for _ in range(n + 1)]
    for x in range(1, n + 1):
        px = pos[x]
        for d in range(1, int(x ** 0.5) + 1):
            if x % d == 0:
                div_lists[d].append(px)
                if d * d != x:
                    div_lists[x // d].append(px)
    for d in range(1, n + 1):
        div_lists[d].sort()
    return div_lists

def count_in_range(arr, l, r):
    # binary search
    import bisect
    return bisect.bisect_right(arr, r) - bisect.bisect_left(arr, l)

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    q = int(input())

    posA = [0] * (n + 1)
    posB = [0] * (n + 1)

    for i, x in enumerate(a, 1):
        posA[x] = i
    for i, x in enumerate(b, 1):
        posB[x] = i

    divA = build_div_lists(n, posA)
    divB = build_div_lists(n, posB)

    import bisect

    for _ in range(q):
        l, r, L, R = map(int, input().split())

        cntA = [0] * (n + 1)
        cntB = [0] * (n + 1)

        for d in range(1, n + 1):
            cntA[d] = count_in_range(divA[d], l, r)
            cntB[d] = count_in_range(divB[d], L, R)

        f = [0] * (n + 1)
        ans = 0

        for d in range(n, 0, -1):
            f[d] = cntA[d] * cntB[d]
            k = 2 * d
            while k <= n:
                f[d] -= f[k]
                k += d
            ans = (ans + (d * d) * f[d]) & 0xFFFFFFFF

        print(ans)

if __name__ == "__main__":
    solve()
```解決策は、各値を両方の順列の位置にマッピングすることから始まります。 これにより、インデックス範囲内の値の選択が、値インデックスに対する幾何学的四角形のクエリに変わります。 除数リストは、すべての除数 d について、どの値がその値に寄与しているのかを正確に把握できるように構築されており、高速な範囲カウントを可能にするためにその位置を保存します。 

クエリごとに、約数ごとに四角形に入る有効な値の数を計算します。 次に、倍数に対して古典的な包含-除外を適用して、正確な gcd 寄与を分離します。 最終的な累積では、ビット マスキングによる 32 ビット モジュロ動作が使用されます。 

微妙な点は、すべてのカウントがクエリごとに行われることです。これはコストがかかりますが、構造的には正しいです。 除数分解により、カウントの取得方法に関係なく正確さが保証されます。

 ## 特殊なケース

 次のような単一要素範囲の場合`l = r`そして`L = R`の場合、四角形には値が 1 つだけ含まれます。 アルゴリズムはコンピューティングに帰着します`gcd(x, y)^2`シングルペア用。 除数 DP は依然として機能します。これは、その単一値の除数だけがゼロ以外のカウントに寄与し、より大きな倍数は自然に消滅するためです。 

クエリが配列全体にわたる場合、すべての値が含まれます。 この場合、すべての約数リストがそのフル サイズに寄与し、包含/排他によって、各 gcd クラスが重複することなく完全なデカルト積を分割することが保証され、共有約数の過大なカウントが防止されます。 

値がセグメント間で互いに素である場合、すべてのセグメントが`cnt[d]`d > 1 の場合はゼロになり、d = 1 のみがアクティブになります。 アルゴリズムは、gcd 1 ですべてのペアをカウントするまで正しく崩壊し、除数構造が偽の寄与を導入しないことを示しています。
