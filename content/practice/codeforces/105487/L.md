 ## 解決策
 ## 問題の理解

 A、B、C、D とラベル付けされた 4 種類のパズルのピースが与えられますが、それぞれ数量に限りがあります。 各ピースは特別なエッジ形状を持ち、ピースの接触するエッジが相補的な方法で互換性がある場合にのみ互いに​​隣り合うことができます。つまり、一方の側がもう一方の側に「適合」する必要があります。 

これらのピースを使用して、正方形または非正方形の単一の長方形を組み立てたいと考えています。 最終形状の境界は完全に平らでなければならないため、外側の境界に凹みや突起は禁止されます。 長方形の内部では、2 つの隣接する部分間のすべての共有エッジも、同じ一致ルールに従って完全に互換性がなければなりません。 

目標は、面積を最小化したり、固定形状に一致させたりすることではなく、有効な長方形を組み立てながら、指定されたマルチセットから使用できる部分の数を最大化することです。 

この制約は、最大 10⁴ のテスト ケースがあり、各テスト ケースのカウントが最大 103 であることを意味します。 したがって、どのソリューションもテスト ケースごとに一定時間で実行する必要があります。 形状の列挙、グリッドの構築、または次元の検索を伴うものはすべて、すぐに遅すぎます。 

グローバル ペアリングを尊重せずにローカルで推論しようとすると、微妙な失敗例が発生します。 たとえば、A は豊富だが、その互換性のあるタイプ C が完全に欠落しているとします。 貪欲なアプローチでは、依然として A ピースを配置しようとする可能性がありますが、どのピースも長方形内で一貫してペアにすることができないため、正しい答えは、その方向からの使用可能な貢献がゼロであることです。 同様に、一致しない型を混合すると、部分的に「ほぼ有効な」アセンブリが長方形に近づくことができない可能性があります。 

## アプローチ

 自然な出発点は、実際に長方形を構築することを考えることです。 考えられる長方形の寸法を列挙し、エッジの互換性を考慮しながら利用可能な部分でそれらをタイル状に並べてみることもできます。 これには、幅と高さを決定し、ピースを位置に割り当ててすべての隣接性を検証する実現可能性チェックを実行することが含まれます。 

これは概念的には簡単ですが、あまりにも遅すぎます。 利用可能な部分の合計に基づいて寸法を制限したとしても、候補となる長方形の数は総数に比例し、検証ごとにグリッドをスキャンする必要があります。 最大 10⁴ のテスト ケースでは、これはすぐに実行不可能になります。 

重要な観察は、問題が実際には幾何学的配置に依存していないということです。 長方形制約は、より強力な構造要件を強制します。すべての露出したエッジは中立でなければならず、すべての内部隣接は有効な相補ペアを形成する必要があります。 これにより、構造が互換性のないタイプの独立したペアに分解されます。 

このように表示すると、ジオメトリが消え、マッチングの問題が残ります。 各 A ピースは、互換性のある C ピースとペアになった場合にのみ意味のある貢献をすることができ、各 B ピースは D とのみペアになります。ペアになっていないピースは、制約に違反せずに境界または内部に表示できないため、使用できません。 

したがって、問題全体は、2 つの独立したグループでできるだけ多くの有効なペアを形成することに帰着します。

 ## アルゴリズムのチュートリアル

 各テスト ケースを個別に処理し、問題を、形成できる相補的なペアの数を数えることに落とし込みます。 

1. ペア (A、C) について、素の一致がいくつできるかを計算します。 各試合では A と C が 1 つずつ消費されるため、使用可能なペアの数は次のようになります。`min(A, C)`。 これは、これら 2 つの互換性のないエッジ タイプ間で考えられるすべての有効な相互作用を表します。 
2. ペア (B, D) について、次の式を使用して同じ量を計算します。`min(B, D)`。 これらのペアは A-C ペアから独立しているため、互いに干渉しません。 
3. 有効な各ペアは、境界または隣接性の制約に違反することなく長方形内で安全に使用できる 2 つの部分に対応します。 
4. したがって、使用可能なピースの総数は、形成されたペアの数の 2 倍になります。`2 * (min(A, C) + min(B, D))`。 
5. 有効なペアが存在しない場合、有効なエッジを持つ四角形を形成できないため、結果はゼロになります。 

### なぜ効果があるのか

 長方形の制約により、すべてのエッジがグローバルにバランスをとるように強制されます。 有効な構成で配置されたピースは、すべての露出したエッジが互換性のある隣接要素によって中和されている必要があります。これは、相補的なタイプ間の正確なペアリングによってのみ可能です。 エッジの互換性以外に追加の構造上の制限がないため、最適な戦略では常に可能な限り多くの互いに素な有効なペアが使用され、再配置によってこの数が増加することはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        A, B, C, D = map(int, input().split())
        ans = 2 * (min(A, C) + min(B, D))
        print(ans)

if __name__ == "__main__":
    solve()
```この実装は、上記で導出されたペアリング ロジックを直接エンコードします。 各テスト ケースは独立して読み取られるため、補助的なデータ構造は必要ありません。 

唯一の微妙な点は、2 つの独立したペアのカウントを合計した後に 2 の乗算が確実に行われるようにすることです。 早めに実行しても正確さは変わりませんが、グループ化しておくとペアリング構造への依存関係が明確になります。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        A, B, C, D = map(int, input().split())
        out.append(str(2 * (min(A, C) + min(B, D))))
    return "\n".join(out)

 ## 特殊なケース

 すべてのカウントがゼロの場合、両方のペアリング グループは空であり、結果は当然ゼロになります。 アルゴリズムは両方を評価します`min(A, C)`そして`min(B, D)`ゼロとして出力されるため、特別な処理をしなくても出力は正しくゼロになります。 

A がプラス、C がゼロなど、ペアの片側のみが存在する場合、`min(A, C)`がゼロになり、一致しない部分の不正な使用が防止されます。 これにより、残った A ピースが依然として部分構造を形成する可能性があるという誤った直感が防止されます。 

1 つの型がその相手よりもはるかに大きいなど、すべてのカウントが非常に不均衡な場合、アルゴリズムは自動的に小さい方のカウントで使用量を制限し、過剰なカウントが発生しないようにし、有効な長方形内で余剰部分を使用することが不可能であることを正確に反映します。
