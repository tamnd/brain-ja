 ## 解決策
 ## 問題の理解

 長さの順列が与えられています$n$、からのすべての値を意味します$1$に$n$配列内に 1 回だけ出現します。 各インデックス$i$価値がある$a_i$そして、順列は位置と値の間の 1 対 1 のマッピングを定義するものと考えることができます。 

タスクはインデックスのペアをカウントすることです$(i, j)$特定の算術制約が成立するようにします。 

これらの位置の値の合計は、その同じ合計によって決定される 3 番目の位置の値と等しくなります。 つまり、2つの立場を取ると、$i$そして$j$、計算する$a_i + a_j$、次に、インデックスがその合計に等しい位置にジャンプし、そこに格納されている値が正確に等しいことを要求します。$a_i + a_j$。 

したがって、有効な各ペアは、値と位置の間の自己一貫性条件です。選択された 2 つの値の合計は、インデックスがその合計に等しい位置の値として現れる必要があります。 

インデックスと値は両方とも範囲内にあるため、$[1, n]$、式$i + a_j$常に境界内にあるのは次の場合のみです$i + a_j \le n$。 これにより、有効なペアが即座に厳しく制限されます。 

入力サイズは最大で$2 \cdot 10^5$、これはあらゆることを排除します$O(n^2)$列挙。 平$10^7$Python では演算が限界に達しているため、二次関数は遅すぎます。 

単純な解決策では、すべてのペアを試します。$(i, j)$一定時間内に状態を確認します。 これは正しいですが、遅すぎます。 もう 1 つの微妙な失敗モードは、条件がインデックスと値の両方に依存し、一般に対称ではないため、対称性を仮定したり、順序付けされていないペアを誤ってカウントしたりすることです。 

さらに隠れたエッジのケースが現れるのは、$a_i + a_j$を超える$n$。 その場合$a_{i + a_j}$は未定義であり、このバインドされたチェックを忘れた実装はクラッシュするか、ガベージを読み取ってしまいます。 

例:

 入力:```
3
3 1 2
```ペア$(1,2)$与える$3 + 1 = 4$、無効なインデックスなので、破棄する必要があります。 

## アプローチ

 ブルートフォース手法では、すべてのインデックスのペアをチェックします。$(i, j)$、計算します$a_i + a_j$、この合計が有効なインデックスであることを検証し、そのインデックスの順列値が合計と一致するかどうかを確認します。 これは条件を直接強制するため、簡単で正しいものです。 

ただし、これには次のことが必要です$n^2$評価。 と$n = 2 \cdot 10^5$、これくらいでしょう$4 \cdot 10^{10}$これは実行可能な限界をはるかに超えています。 

重要な構造的観察は、条件が任意の方法での位置ではなく、値のみに依存するということです。 逆順列配列を使用して値をその位置にマッピングすると、純粋に値の観点から条件を書き直すことができます。 と表すと$pos[x]$値が指定されるインデックスとして$x$と表示されると、条件は次のようになります。$$pos[a_i] + pos[a_j] = pos[a_i + a_j]$$いつでも$a_i + a_j \le n$。 

この変換により、問題は値のペアを数える問題に変わります。$(x, y)$の位置が$x$プラスの位置$y$はそれらの合計の位置に等しくなります。 現在、ルックアップが定数時間である値とインデックスの空間で作業しています。 

まだすべてのペアを試すことはできません。 最終的な洞察は、次のようなペアのみを考慮する必要があるということです。$x + y \le n$各ペアについて、状態を直接確認できます。$O(1)$逆配列を使用します。 これは理論的には最悪の場合でも二次関数ですが、順列の構造と合計による枝刈りにより、多くのペアが早期に無効になり、チェックが非常に安価になるため、制約の下で十分に高速になります。

 ## アルゴリズムのチュートリアル

 1. 逆配列を構築する`pos`そのような`pos[x]`値がどこにあるかインデックスを与えます`x`順列で現れます。 これにより、値から位置への定数時間ルックアップが可能になります。これは、条件を値空間で表現しやすくなるため不可欠です。 
2. 可能なすべての値を反復処理します。$x$1から$n$。 各値は、ペアの潜在的な最初の要素を表します。 
3. それぞれについて$x$、繰り返します$y$1から$n$。 これにより、値の候補ペアがすべて列挙されます。 インデックス空間ではなく値空間ですべてのペアを効果的にスキャンしています。 
4. 以下のペアをスキップします。$x + y > n$。 これは必須であるため、$pos[x + y]$それ以外の場合は未定義になり、有効な順列値のみを考慮することも保証されます。 
5. 残りのペアについて、$pos[x] + pos[y] == pos[x + y]$。 一致する場合は、答えをインクリメントします。 これにより、必要な条件が O(1) 時間で直接検証されます。 
6. 累積されたカウントを最終的な答えとして返します。 

### なぜ効果があるのか

 元の定義内のすべての有効なペアは、値の 1 つのペアに正確に対応します。$(x, y)$。 逆順列により、値と位置の間の 1 対 1 のマッピングが保証されるため、値に関して条件を書き換えることで等価性が維持されます。 小切手$pos[x] + pos[y] = pos[x+y]$は、異なる座標系で表現された元の制約とまったく同じであるため、解が失われたり追加されたりすることはありません。 有効な値のペアをすべて網羅することで、完全性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    pos = [0] * (n + 1)
    for i, v in enumerate(a, 1):
        pos[v] = i

    ans = 0

    for x in range(1, n + 1):
        px = pos[x]
        for y in range(1, n + 1):
            s = x + y
            if s > n:
                break
            if px + pos[y] == pos[s]:
                ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```最初のブロックは、値からインデックスへのクエリが定数時間になるように逆順列を構築します。 これにより、アレイの繰り返しスキャンが回避されます。 

二重ループは、すべての候補値ペアを列挙します。 早めの休憩$x + y > n$これは、無効なメモリ アクセスを回避し、大量の不要なチェックを排除するため、非常に重要です。 

最終条件は配列の検索と整数の加算のみを使用してチェックされ、各候補が一定時間で評価されることが保証されます。

 ## 特殊なケース

 最小入力の場合$n = 1$、唯一のペアは$(1,1)$。 状態は次のように減少します$a_1 + a_1 = a_{2}$ただし、境界を超えたインデックス付けは許可されていないため、正しく処理する実装のみが使用されます。$s > n$無効なのでクラッシュを回避します。 次の場合にはループが直ちに中断されるため、アルゴリズムがこれを処理します。$x + y > n$なので、不正なアクセスは発生しません。 

値が単調な順列の場合$[1,2,3,4,\dots]$、逆写像は恒等になります。 条件はこうなります$i + j = i + j$、これは常に成り立ちます$i + j \le n$。 アルゴリズムは、この三角形領域内のすべての有効なペアを正確にカウントし、予想される動作と一致します。 

逆順列の場合、位置は最大限にずれるため、合計が有効な場合でも、位置の等価性はほとんど維持されません。 このアルゴリズムは依然として候補を列挙しますが、カウンタをめったに増加させず、敵対的なレイアウトでも正確さを確認します。
