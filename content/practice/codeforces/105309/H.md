 ## 解決策
 ## 問題の理解

 長さのシーケンスが与えられます$n$, ここで、各位置は、その日に友人が解決した問題の数を表します。 一部の値はすでに既知ですが、一部は不明でマークされています。$-1$、つまり自由に選択できるということです。 

また、2 種類の制約も与えられます。 最初のタイプは、特定の位置での特定の値を禁止するため、位置$u$価値を受け取ることができない$val$。 2 番目のタイプでは、対称制約が導入されます: セグメントの場合$[l, r]$、シーケンスはその区間内で回文でなければなりません。つまり、区間の終わりから等しく離れた位置は同じ値を持つ必要があります。 

タスクは、値の割り当てが完了した回数を数えることです。$[0, m]$すべての固定値、禁止値、およびすべての回文制約と一致します。 

主な問題は、制約がローカルではないことです。 単一の位置は、重なり合う回文間隔を通じて他の多くの位置にリンクされ、同じ値を共有する必要があるインデックスの同値クラスを形成できます。 これらのクラスが判明すると、値制限の下でクラスごとに有効な割り当てをカウントすることが問題になります。 

この制約により、すべての配列に対するブルート フォースが不可能になります。 自由位置のみを考慮したとしても、探索空間は次のようになります。$(m+1)^n$、これは天文学的に大きいです$n \le 3000$。 

の$k$禁止制約は最大 200 万個と非常に大きくなる可能性があるため、制約ごとに償却された一定時間で処理する必要があります。 回文制約は最大数千ですが、それらは推移的に相互作用するため、その効果を効率的に集約する必要があります。 

制約が互いに矛盾する場合、微妙なエッジケースが発生します。 たとえば、位置 1 が 3 であることを強制されているが、3 であることも禁止されている場合、答えはすぐに 0 になるはずです。もう 1 つのケースは、回文制約によりサイクル全体での等価性が強制されているが、固定値が一致しない場合です。 

入力:```
3 5 1 1
1 -1 -1
1 2
1 3
```これにより、位置 1 が位置 3 と同じになりますが、位置 1 は 1 に固定され、位置 3 は 3 に固定され、矛盾します。 正解は 0 です。ローカル制約のみをチェックする単純なアプローチでは、この矛盾を見落としてしまいます。 

## アプローチ

 直接的な総当たりアプローチでは、すべての位置に値を割り当て、すべての制約をチェックします。 これは努力することを意味します$(m+1)^n$シーケンスを検証し、それぞれの回文制約と禁止値を検証します。 たとえ$n = 3000$、状態空間が指数関数的に増大するため、これは完全に実行不可能です。 

重要な観察は、回文制約が独立して機能しないということです。 各回文制約はインデックスの対称ペアを同等にし、これらの同等性は推移的に伝播します。 インデックス 1 が 10 に等しく、10 が 3 に等しい場合、1 は 3 に等しくなければなりません。これにより、インデックスに対して同値クラスが自然に形成されます。 

問題を等式制約の下で連結成分にインデックスをマージするものとみなすと、その構造は和集合検索または DSU 問題になります。 各コンポーネントは単一の値を取る必要があります。$[0, m]$。 次に、問題は、そのコンポーネント内のすべての制約と一致する値を割り当てることができるコンポーネントの数を数えることに帰着します。 

各コンポーネント内では、一連の禁止値と、場合によっては初期割り当てまたは制約から得られる固定値を維持します。 コンポーネントに 2 つの矛盾する固定値がある場合、答えはゼロになります。 それ以外の場合、値が固定されている場合、そのコンポーネントは 1 つの選択肢に寄与します。 修正されていない場合は貢献します$(m+1 - \text{forbidden count})$。 

残る唯一の困難は、多くのペアを接続する回文制約を効率的に処理することです。 標準的なトリックは、インデックスに対して DSU を使用し、間隔ごとに対称ペアを結合することです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O((m+1)^n \cdot n)$|$O(n)$| 遅すぎる |
 | 制約上の DSU |$O((n + k + q)\alpha(n) + n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 この問題は、インデックスに対して等価グループを構築し、グループごとに制約を検証することで解決します。 

1. インデックスを使用して DSU 構造を初期化します。$1$に$n$。 各インデックスは独自のコンポーネントで始まります。 この構造は、回文制約によりどの位置が同じ値を共有する必要があるかを表します。 
2. 各回文制約について$[l, r]$、ペアをマージします$(l, r), (l+1, r-1), \ldots$真ん中に到達するまで。 各マージでは、対称位置間の等価性が強制されます。 このステップでは、等しくなければならないすべてのインデックスを表す連結成分を構築します。 
3. 初期配列を処理します。 もし$a[i] \neq -1$を含むコンポーネントにこの値を制約として付加します。$i$。 同じコンポーネントに複数の値が表示され、一致しない場合は、有効な割り当てがないと即座に結論付けます。 
4. 禁止された制約を処理する$(u, val)$。 このような制約ごとに、次のコンポーネントが$u$価値を受け取ることができない$val$。 これらはコンポーネントごとに蓄積されます。 
5. すべての制約が処理された後、各 DSU ルートを反復処理します。 コンポーネントに固定値がある場合は、それが禁止されていないことを確認してください。 禁止されている場合、答えはゼロです。 それ以外の場合、このコンポーネントは 1 つの選択肢のみを提供します。 
6. コンポーネントに固定値がない場合は、コンポーネント内の値の数を数えます。$[0, m]$そのコンポーネントでは禁止されていません。 すべてのコンポーネントの寄与をモジュロで乗算します。$10^9+7$。 

### なぜ効果があるのか

 すべての回文制約により、ミラーリングされた位置間の等価性が強制され、これらの制約を繰り返し適用すると、等価性の推移閉包が作成されます。 DSU はこれらのクロージャを正確にキャプチャします。つまり、すべての有効なシーケンスがコンポーネントごとに 1 つの値を割り当てる必要があります。 

インデックスがマージされると、制約はコンポーネントに対して純粋にローカルになります。 コンポーネントは、そのコンポーネント内のすべての制限と一致する少なくとも 1 つの値を割り当てることができる場合にのみ有効です。 コンポーネントは独立しているため、それらの選択を乗算すると、重複することなくすべてのグローバル割り当てがカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

class DSU:
    def __init__(self, n):
        self.p = list(range(n))
        self.sz = [1] * n

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return
        if self.sz[a] < self.sz[b]:
            a, b = b, a
        self.p[b] = a
        self.sz[a] += self.sz[b]

def solve():
    n, m, k, q = map(int, input().split())
    a = list(map(int, input().split()))

    dsu = DSU(n)

    # palindrome constraints
    for _ in range(q):
        l, r = map(int, input().split())
        l -= 1
        r -= 1
        while l < r:
            dsu.union(l, r)
            l += 1
            r -= 1

    fixed = {}
    forbidden = {}

    for i in range(n):
        if a[i] != -1:
            root = dsu.find(i)
            if root not in fixed:
                fixed[root] = a[i]
            else:
                if fixed[root] != a[i]:
                    print(0)
                    return

    for _ in range(k):
        u, val = map(int, input().split())
        u -= 1
        root = dsu.find(u)
        if root not in forbidden:
            forbidden[root] = set()
        forbidden[root].add(val)

    # merge sets per root
    comp_forbidden = {}
    for i in range(n):
        r = dsu.find(i)
        if r not in comp_forbidden:
            comp_forbidden[r] = set()
        if r in forbidden:
            comp_forbidden[r] |= forbidden[r]

    comp_seen = set()
    ans = 1

    for i in range(n):
        r = dsu.find(i)
        if r in comp_seen:
            continue
        comp_seen.add(r)

        forb = comp_forbidden.get(r, set())
        if r in fixed:
            if fixed[r] in forb:
                print(0)
                return
            ans = ans * 1 % MOD
        else:
            ans = ans * (m + 1 - len(forb)) % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```DSU は、すべての対称制約を連結コンポーネントに折りたたむために使用されます。 各回文間隔は、ミラーリングされたペアを繰り返し結合することによって処理されます。 

の`fixed`辞書は、コンポーネントが元の配列からの所定の値を持つかどうかを記録します。 コンポーネント内の矛盾は即座に処理されるため、後で不必要な計算が行われることがなくなります。 

の`forbidden`構造はコンポーネントごとに制約を蓄積します。 制約は同じ DSU セットの異なるメンバーに適用される可能性があるため、それらは最後にマージされます。`comp_forbidden`。 

最後に、コンポーネントを 1 回反復し、有効な値の数を計算して乗算します。 

よくある落とし穴は、同じコンポーネント内の複数のインデックスによって重複した禁止セットが導入される可能性があるため、ルートごとの最終結合が必要であることを忘れていることです。

 ## 特殊なケース

 重要なエッジ ケースは、回文制約によってすべてのインデックスが 1 つのコンポーネントに接続される場合です。 その状況では、すべてのポジションが 1 つの値を共有する必要があるため、答えはグローバルに有効な値をカウントすることになります。 DSU は自然に 1 つのルートを生成し、最後の乗算ステップは 1 回適用されるため、過剰なカウントが回避されます。 

もう 1 つのケースは、同じコンポーネント内の固定値が競合している場合です。 例えば：```
3 5 0 1
1 2 3
1 2
1 3
```回文制約はすべてのインデックスをマージしますが、固定値は一致しません。 処理中に、`fixed`Dictionary は競合を即座に検出し、カウントが行われる前に 0 を返します。 

最後の微妙なケースは、後で修正されたことが判明したものを除いて、禁止値がコンポーネントの可能なすべての割り当てをカバーする場合です。 その固定値も禁止されている場合、コンポーネントは無効になります。 アルゴリズムは評価時にこれをチェックし、製品に無効な貢献が入って​​いないことを保証します。
