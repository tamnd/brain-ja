 ## 問題の理解

 を構築するように求められています。$n \times n$バイナリグリッドを正確に使用する$k$ものと$n^2 - k$ゼロ。 グリッドの唯一の要件は構造的なものです。すべての行をバイナリ文字列として、すべての列をバイナリ文字列として見る場合、個別の行の数と個別の列の数を合わせた値は最大 5 でなければなりません。 

したがって、制約は局所的なパターンや隣接性に関するものではなく、多様性の圧縮に関するものです。 グリッドに含まれる個別の行タイプと列タイプの組み合わせが非常に少ない限り、どこにでも配置できます。 

重要な難点は、$n$最大 1000 まで大きくできるため、どの構造も直線または直線に近いものでなければなりません。$n^2$。 ただし、出力自体はすでに$n^2$、 それで$O(n^2)$建設は避けられず、予想されるものです。 

主な微妙な点は、行の多様性と列の多様性の両方を同時に制御する必要があることです。 行を個別に構築する単純なアプローチでは、あまりにも多くの個別の列パターンが簡単に作成されてしまう可能性があります。 

いい加減な施工をするとすぐに失敗例がいくつか出てきます。 たとえば、使い果たすまで 1 行ずつ埋めていきます。$k$塗りつぶされた行と塗りつぶされていない行の境界によって「階段」パターンが作成されるため、多くの異なる列が生成される傾向があります。 

もう 1 つの問題のあるアイデアは、次のような行を交互に配置することです。$1010...$そして$0101...$。 行の多様性は小さくても、列の多様性は爆発的に増加します。$n$、ランク制限に違反します。 

課題は、行と列の両方が非常に繰り返し多く、それらを組み合わせた個別の数が制限されたままになるグリッドを設計することです。 

## アプローチ

 ブルートフォースの考え方は、これを制約充足問題として扱うことです。つまり、各セルに値を割り当て、一連の個別の行と列を維持し、数値が 5 を超えるたびにバックトラックしてみます。これは明らかに指数関数的です。$n^2$なぜなら、セルを選択するたびに行と列の署名が変更される可能性があり、早期終了を保証する枝刈り構造がないからです。 たとえ$n = 20$、これはすでに実行不可能です。 

重要な点は、何も最適化したり検索したりする必要がないということです。 非常に単純な構造の存在だけが必要です。 すべての行が最大でも少数の固定パターンの 1 つであり、すべての列も小さな固定セットからのものであることを確認できれば、条件は自動的に満たされます。 

行と列の多様性を強制的に一定にする最も簡単な方法は、グリッドをほぼ均一にし、すべてのバリエーションを 1 つの長方形に集中させることです。 1 つまたは 2 つの行を除くすべての行が同一であり、1 つまたは 2 つの列を除くすべての列が同一である場合、行の型と列の型は両方とも制限されたままになります。 

きれいな構造は、グリッドを 2 つの大きな均一なブロックに分割することです。1 つのブロックは 1 で埋められ、残りは 0 です。 これにより、最大 2 つの異なる行タイプと最大 2 つの異なる列タイプが生成され、合計スーパー ランクは最大 4 となり、要件を満たします。 

次に、すべて 1 の四角形のサイズを調整して、次の要素が正確に含まれるようにします。$k$もの。 

構造は次のようになります。 左上の長方形を形成する行と列のプレフィックスを選択し、その面積が一致するように正確またはわずかに調整されます。$k$。 1 の任意の配置が許可されているため、プレフィックス領域内の長方形のプレフィックスを行ごとに貪欲に埋めて、それ以外はすべて 0 のままにすることができます。 これでも、制限された数の個別の行と列のパターンが保持されます。

 ## アルゴリズムのチュートリアル

 すべての 1 が単一の連続した左上領域に配置されるグリッドを構築します。 

1. を初期化します。$n \times n$グリッドはゼロで埋められます。 これにより、変更前にすべての行と列に対して単一のベースライン パターンが保証されます。 
2. 行ごとに左から右にスキャンしながら、左上のセルから入力を開始します。 
3. 正確な位置まで配置します。$k$ものが書かれています。 これにより、複雑なバランス調整を必要とせずに、カウント制約が確実に満たされます。 
4. すぐに一旦停止する$k$ものが置かれています。 残りのセルはすべてゼロのままです。 
5. グリッドを出力します。 

このプロセスの重要な構造効果は、行のセットが最大 1 つの遷移点でのみ変更できることです。つまり、部分的に埋められた最後の行より上の行は、あるプレフィックスまで 1 で埋められ、その下の行はすべてすべて 0 になります。 同様に、列は対称的に動作します。部分的に塗りつぶされた最後の列より前の列には、塗りつぶされたすべての行に 1 が含まれ、その後の列にはすべて 0 が含まれます。 

### なぜ効果があるのか

 生成されるグリッドには最大で 2 つの行タイプがあります。完全にゼロの行と、場合によっては 1 の接頭辞を含む 1 行です。 充填は 1 回のリニア スキャンで進行するため、他の行パターンは表示されません。 同様に、列タイプは最大で 2 つあります。完全にゼロの列と、場合によっては部分的に 1 のプレフィックスを持つ列が 1 つあります。 したがって、個別の行と列の合計数は最大 4 であり、最大 5 という要件を満たします。この構造は次の要素に依存しません。$k$充填がどこまで進むかは別なので、すべての有効な入力に対して機能します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    
    grid = [["0"] * n for _ in range(n)]
    
    for i in range(n):
        for j in range(n):
            if k == 0:
                break
            grid[i][j] = "1"
            k -= 1
        if k == 0:
            break
    
    for row in grid:
        print("".join(row))

if __name__ == "__main__":
    solve()
```このソリューションでは、効率的な変更のために文字配列のリストとしてグリッドを構築します。 二重ループは単純な左上の塗りつぶしを実行します。 早期停止条件により、一度に過剰充填することがなくなります$k$ものが置かれています。 

重要な実装の詳細は、次の場合に両方のループを正しく中断することです。$k$ゼロに達します。 外側のループを中断しないと出力は正しくなりますが、時間が無駄になります。 内部ループを適切に中断しないと、一部のバリアントでは完了後にゼロが誤って上書きされる可能性があります。

 ## 特殊なケース

 主なエッジケースは次のような場合です$k = 0$。 このアルゴリズムは充填ループに入ることはなく、すべてゼロのグリッドを直接出力します。 これにより、正確に 1 つの行タイプと 1 つの列タイプが保持され、スーパー ランクが最小限に保たれます。 

いつ$k = n^2$、ループはグリッド全体を埋めます。 すべてのセルが 1 になり、単一行タイプと単一列タイプが生成されます。 これは可能な限り最も均一な構成であり、制約を自明に満たします。 

いつ$k$行境界で正確に停止すると、塗りつぶされた領域は完全な長方形を形成し、完全に 1 行と完全に 0 行という 2 つの行タイプが生成されます。 カラムの多様性も同様に制限されます。 

いつ$k$行の途中で停止すると、1 行だけが混合プレフィックス行になります。 これは 3 番目のパターン候補を導入する唯一の行ですが、依然として個別の行と列の合計が 5 未満に制限されています。
