 ## 解決策
 ## 問題の理解

 グリッドはバイナリ タイルのボードとして見ることができます。 各セルには 0 または 1 が含まれており、セルを反転して 0 を 1 に、または 1 を 0 に変えることができます。目的は、水平または垂直に隣接する 2 つのセルが同じ値を共有しないようにグリッドを変更することです。 つまり、隣接するセル間のすべてのエッジは、変換後に異なる値を接続する必要があります。 

有効な最終構成はまさに市松模様です。これは、隣接するすべてのペアが異なることを保証する唯一の構造だからです。 タスクは、元のグリッドに最も近い構成を選択し、反転されるセルの数を最小限に抑えることです。 

この制約により、すべてのグリッドにわたって合計 10^6 セルまでの、最大 10^4 のテスト ケースが許可されます。 これは、テスト ケースごとに 2 次または重い定因数の繰り返し処理を行うと遅すぎるため、ソリューションはテスト ケースごとのグリッド サイズが線形である必要があることを意味します。 ターゲットの構造を簡単な方法で表現できれば、各グリッドを 1 回通過するだけで十分です。 

グリッドが非常に小さい場合、微妙なエッジケースが発生します。 1 行 1 列のグリッドの場合、満たすべき隣接制約がないため、値に関係なく反転は必要ありません。 1 × m または n × 1 グリッドの場合、チェッカーボード条件は線に沿って交互に値が変化し、同じ 2 パターンのロジックが引き続き適用されます。 

もう 1 つの潜在的な落とし穴は、貪欲なフリップによって違反をローカルに修正しようとすることです。 たとえば、2 つの等しい隣接がある場合、1 つを反転すると、他の場所に新しい違反が作成される可能性があります。 これにより、ローカル戦略は信頼できなくなります。 

## アプローチ

 ブルート フォース戦略では、隣接制約を動的に適用しながら、各セルに値を割り当てようとします。 各セルに 0 と 1 の可能なすべての割り当てを試すことも想像できますが、それは 2^(n・m) 構成になり、たとえ小さなグリッドであっても完全に実行不可能です。 

もう少し構造化されたブルート フォース アプローチは、セルごとに決定し、隣接セルとの有効性を維持しながら反転するかどうかを分岐することです。 枝刈りを行ったとしても、それぞれの決定が将来の制約に影響を与えるため、状態の数は指数関数的に増加します。 操作数はおよそ 2^(n・m) まで増加しますが、これは制限をはるかに超えています。 

重要な観察は、有効な最終グリッドはチェス盤のように値を交互に配置する必要があるということです。 これが認識されると、問題は元のグリッドを 2 つの可能なターゲット グリッドのみと比較することになります。 1 つのパターンは、(i + j) が偶数であるすべてのセルに値 0 を割り当て、それ以外の場合は 1 を割り当てます。一方、もう 1 つのパターンはその補数です。 各パターンに一致するために必要なフリップの数を単純に計算し、最小値を取得します。 

これにより、すべてのグリッドにわたる指数関数的な検索の問題が、入力上の一定数のパスに軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^(n・m)) | O(n・m) | 遅すぎる |
 | 最適 | O(n・m) | O(1) おまけ | 承認済み |

 ## アルゴリズムのチュートリアル

 ### 最適な戦略

1. 有効な構成では、隣接するセル間で値を交互に配置する必要があるため、チェッカーボード パターンのみが可能であることに注意してください。 これにより、検索スペースが 2 つの候補に減ります。 
2. (i + j) が偶数の場合は位置 (i, j) のセルが 0、そうでない場合は 1 になると予想される最初の候補パターンを定義します。 これにより、固定された交互構造が作成されます。 
3. 2 番目の候補パターンを最初のパターンの正確な逆として定義します。偶数パリティ セルは 1、奇数パリティ セルは 0 です。これは、残りの唯一の有効なチェッカーボードをカバーします。 
4. グリッド内の各セルについて、その現在の値を両方の候補パターンと比較し、不一致を個別にカウントします。 不一致は、必要な反転に対応します。 
5. 各パターンに必要なフリップの数は、そのパターンの合計不一致数です。 
6. グリッドの答えは、2 つの不一致数の最小値です。 

### なぜ効果があるのか

 有効な構成では、隣接するセルに異なる値を割り当てる必要があり、グリッド グラフの厳密な 2 部カラーが強制されます。 グリッドは、座標のパリティに基づいた一意のパーティションを持つ 2 部構成であるため、すべての有効なソリューションは、1 つのパリティ クラスに割り当てられた値の選択によって完全に決定されます。 その選択が決定されると、他のすべてのセルが強制されます。 これが、有効なパターンが 2 つ存在する理由であり、両方を比較することでフリップの最小数が保証される理由です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n, m = map(int, input().split())
        grid = [input().strip() for _ in range(n)]
        
        cost0 = 0
        cost1 = 0
        
        for i in range(n):
            row = grid[i]
            for j in range(m):
                bit = row[j]
                
                expected0 = '0' if (i + j) % 2 == 0 else '1'
                expected1 = '1' if (i + j) % 2 == 0 else '0'
                
                if bit != expected0:
                    cost0 += 1
                if bit != expected1:
                    cost1 += 1
        
        out.append(str(min(cost0, cost1)))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装は、各テスト ケースを独立して読み取り、2 つのチェッカーボード パターンに対応する 2 つのカウンターを維持します。 すべてのセルについて、インデックスのパリティを使用して、各パターンでそのセルが持つべき値を計算します。 それぞれの不一致により、対応するコストが増加します。 

正しく実装するための一般的な詳細は、グリッド変換の再計算を回避することです。 このソリューションでは、完全な期待グリッドを構築するのではなく、パリティを使用してオンザフライで期待値を計算します。 これにより、メモリ使用量が最小限に抑えられ、直線的な時間処理が保証されます。 

もう 1 つの微妙な点は、両方のコスト カウンターが独立して維持されるようにすることです。 ロジックを混合したり、単一のカウンターを再利用しようとすると、2 つのパターンがセルごとに異なるため、不正確な結果が生じます。

 ## 特殊なケース

 1 行 1 列のグリッドには隣接性の制約がありません。 このアルゴリズムは両方のパターンを評価し、少なくとも 1 つのパターンで不一致がゼロであることを検出します。これは、両方のパターンが単一の期待値に減り、両方の選択肢が 2 つのパターンにわたる最小値の構築によって一致する可能性があるためです。 

2 x 2 ブロック内のすべてのゼロなどの均一なグリッドは、両方のチェッカーボードの方向を比較する必要性を強調します。 1 つのパターンはセルの半分を正しく配置し、正確に 2 つの不一致を引き起こしますが、もう 1 つのパターンは同様に機能し、最小値は最適な反転を正確にキャプチャします。 

すでにチェッカーボード パターンと一致している完全に交互のグリッドでは、2 つのパリティ割り当てのうちの 1 つについて不一致がゼロになります。 一致する構成では不一致カウンターがゼロのままであるため、アルゴリズムは特別なケースを使用せずにこれを正しく識別します。
