 ## 解決策
 ## 問題の理解

 整数のシーケンスが与えられ、目標は、選択した値を含まない連続セグメントを繰り返し削除することで、すべての要素を等しくすることです。$x$。 の選択$x$一度選択すると変更できないため、これは重要です。 操作には、削除されたセグメントには何も含まれていない必要があるという制約があります。$x$、そして各削除はシーケンスを崩壊させてギャップを埋めます。 各テスト ケースの出力は、完全に次のもので構成されるシーケンスを残すために必要な、このような削除操作の最小数です。$x$。 

The input constraints allow$n$まで$2 \cdot 10^5$そして$t$まで$2 \cdot 10^4$, の合計$n$すべてのテストケースの上限も$2 \cdot 10^5$。 これにより、すべてのサブセグメントを検査したり、可能なすべての操作シーケンスを明示的に試行したりするソリューションは除外されます。そのようなアプローチは 2 次時間または 3 次時間で実行されるためです。 ソリューションは、各シーケンスのサイズが線形またはほぼ線形である必要があります。 

明らかではないエッジケースが発生する場合$x$まばらに現れるか、すでに配列を支配しています。 たとえば、シーケンスが次の場合、`[1, 2, 1, 2, 1]`そして私たちは選択します$x = 1$、次に各セグメント`[2]`個別に削除でき、3 つの操作が可能です。 毎回最大のセグメントを削除する単純な貪欲な戦略では、以前の削除によって生じたギャップを慎重に考慮しないと、過大にカウントされたり、過少にカウントされたりする可能性があります。 同様に、すべての要素が等しい場合、必要な操作はゼロですが、アルゴリズムが少なくとも 1 つの削除を想定している場合は、この操作が見落とされる可能性があります。 

## アプローチ

 ブルートフォースアプローチでは各候補者を試すことになる$x$そして、すべての有効なセグメントを削除することをシミュレートします。$x$残っています。 左から右にスキャンして、含まれていない連続ブロックを繰り返し見つけます。$x$そしてそれらを削除します。 これは正しく機能しますが、場合によっては各ブロックを複数回調べる必要があります。 最悪の場合、シーケンスが交互に発生した場合、$x$および他の要素、各要素は別個の操作の一部である可能性があり、$O(n^2)$すべての候補者を数えるときの動作$x$。 と$n$まで$2 \cdot 10^5$、これでは遅すぎます。 

重要な観察は、固定された$x$を使用すると、シミュレーションを行わずに削除操作の数をカウントできます。 各操作では、非連続セグメントが削除されます。$x$値を削除するとシーケンスが崩壊するため、連続した非$x$で区切られた値$x$1回の操作で取り外し可能です。 したがって、演算の数は、連続する非演算の「ギャップ」の数です。$x$それぞれの操作の後、次の非値に到達するために少なくとも 1 つの位置をスキップする必要があります。$x$崩壊によるブロック。 これにより、サイズのギャップから始まる対数カウントが得られます。$k$で削除できます。`ceil(log2(k+1))`間の最大セグメントを常に削除する場合の操作$x$s. より簡単で十分な方法は、左から右にスキャンし、非連続ブロックに遭遇するたびに操作カウンタをインクリメントすることです。$x$値を設定し、ステップを 1 つ飛ばして崩壊をシミュレートします。 これを候補者ごとに繰り返します$x$そして選択してください$x$操作を最小限に抑えます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(n^2) | O(n) | 遅すぎる |
 | 貪欲に非 x ブロックを数える | O(n * 固有の要素) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、まずシーケンス内のすべての個別の値を特定します。 それぞれの個別の値が候補となります。$x$。 
2. 各候補者について$x$、操作カウンターをゼロに初期化します。 これを修正した場合に必要な除去の数を計算します。$x$。 
3. シーケンスを左から右にスキャンします。 等しくない値に遭遇するたびに、$x$、そのような値の連続したブロックのカウントを開始します。 このブロックのオペレーション カウンタを 1 つインクリメントします。 
4. 1 ブロックを数えたら、次の要素をスキップします。$x$(存在する場合) 除去による崩壊をシミュレートし、スキャンを続けて次のブロックを見つけます。 これにより、単一のセグメントで区切られたセグメントが二重にカウントされなくなります。$x$。 
5. すべての候補にわたる最小操作数を追跡します。$x$。 すべての候補が処理されると、最小数がテスト ケースの答えとなります。 

機能する理由: 各削除操作では、非連続セグメント全体を削除できます。$x$価値観。 セグメントに次の内容が含まれているため、$x$連続した非連続セグメントの各セグメントは削除できません。$x$で区切られた値$x$s には少なくとも 1 つの操作が必要です。 アルゴリズムは、これらの最小限のセグメントを正確にカウントし、同時に、セグメントをスキップすることで崩壊効果を尊重します。$x$各操作の後。 各候補をスキャンする$x$操作を最小限に抑えるものを確実に選択します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def min_operations(a):
    candidates = set(a)
    res = float('inf')
    for x in candidates:
        ops = 0
        i = 0
        n = len(a)
        while i < n:
            if a[i] != x:
                ops += 1
                while i < n and a[i] != x:
                    i += 1
            else:
                i += 1
        res = min(res, ops)
    return res

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    print(min_operations(a))
```機能`min_operations`各候補を反復処理します$x$シーケンスで。 候補ごとに 1 回シーケンスをスキャンし、非連続ブロックをカウントします。$x$値を取得し、ブロックが処理された後に要素をスキップすることで削除をシミュレートします。 外側のループは複数のテスト ケースを処理します。 を使用して`set`候補者向けに、重複した値を処理しないようにし、時間の複雑さを許容範囲内に保ちます。 内部の while ループは、各ループが無効であることを保証することで、off-by-one エラーを防ぎます。$x$セグメントは 1 回だけカウントされます。
