 ## 解決策
 ## 問題の理解

 配列が与えられており、それを 3 つの連続する空ではないセグメントに分割したいと考えています。 それらを左側の部分、中央の部分、右側の部分と呼びます。 この制約は、これらのセグメントを非常に厳密な方法で結び付けます。つまり、左側のセグメントの最大値は中央のセグメントの最小値と等しくなければならず、この同じ値は右側のセグメントの最大値とも等しくなければなりません。 

したがって、任意のパーティションを自由に選択することはできません。 We are searching for a value`v`配列を次の出現を中心に分割できるようにします。`v`左側が決して超えないように`v`、真ん中は決して下にも上にもなりません`v`、右辺が超えることはありません`v`、中央はすべての要素を正確に強制します`v`。 

入力は複数の独立した配列で構成され、それぞれに対して有効な長さの分割を出力します。`(x, y, z)`または不可能を報告します。 

この制約により、合計要素数は最大 200,000 個までとなります。 これにより、すべての分割点を試したり、セグメントの最小値と最大値を最初から再計算したりするアプローチは即座に除外されます。 すべてのソリューションはテスト ケースごとに線形に近く、理想的にはすべてのテストにわたって線形に償却される必要があります。 

素朴な推論による微妙な失敗例は、値を選択すると仮定することです。`v`最初と最後の出現のみをチェックするだけで十分です。 たとえば、次のような配列では、`[1, 3, 2, 3, 1]`、ピッキング`v = 3`3 は複数回存在しますが、周囲の構造により、中央のセグメントが強制的に有効になるきれいな 3 方向のパーティションが妨げられているため、誤解を招きます。 

もう 1 つのよくある落とし穴は、中間セグメントに次の値以外の値が含まれる可能性があると想定していることです。`v`。 それは条件を壊す`min(middle) = v`、中央のすべての要素が正確に強制されます。`v`。 

## アプローチ

 ブルートフォース ソリューションでは、すべてのカット ポイントのペアが試行されます。`(x, x+y)`3 つのセグメントが条件を満たすかどうかを確認します。 分割ごとにセグメントの最小値と最大値を計算しますが、単純に実行すると直線的な時間がかかります。 それは、`O(n^3)`近づくか、せいぜい`O(n^2)`前処理を使用すると、まだ遅すぎます`2e5`合計要素。 

重要な構造上の観察は、中間セグメントには非常に強い制約があるということです。つまり、その最小値は最大値に等しいということです。これは、中間のすべての要素が同一であることを意味します。 その値を`v`。 

修正したら`v`、問題は、連続したブロックを選択できるかどうかを確認することになります。`v`s を中間セグメントとして使用しながら、次のことを保証します。 

左側のセグメントを超えることはありません`v`、右のセグメントが超えることはありません`v`、両方に少なくとも 1 つの要素が含まれています。 

したがって、パーティションを直接検索する代わりに、値を検索します。`v`およびその発生の有効な間隔。 中央は連続したブロックでなければなりません`v`配列内の s。 左側の部分は完全にこのブロックの前にあり、少なくとも 1 つの要素が含まれている必要があり、右側の部分は完全にこのブロックの後にある必要があります。 

各値の位置を事前に計算できます。 候補者ごとに`v`、その出現を調べて、有効な中間ブロックの展開を試みます。 次に、プレフィックスとサフィックスのチェックを使用して、左右の制約を検証します。 

残りの課題は、中間の開始までのプレフィックスが最大値であることを確認することです。`v`、中間端からのサフィックスは最大です。`v`。 これは、選択した中央ブロックの外側にあるすべての要素が正しいかどうかをチェックすることになります。`<= v`、そして両側が空ではないこと。 

少なくとも 2 回出現する値を考慮するだけでよいため (そうでない場合は中間が存在できません)、出現箇所を効率的に反復処理できます。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に解決します。 

1. まず、すべての値のすべての位置を配列に保存します。 これにより、配列全体を繰り返しスキャンすることなく、同じ値の連続したブロックを推論することができます。 
2. 個別の値ごとに`v`、その位置のリストを検討します。 出現回数が 2 回未満の場合は、空ではない中間セグメントを形成できないため、スキップします。 
3. 中間のセグメントを、次の出現の連続した部分配列として選択しようとします。`v`。 最も単純な有効な候補は、最初の出現から最後の出現までの全範囲です。 これにより、中央が連続して完全に満たされることが保証されます。`v`。 
4. この候補中間セグメントを修正したら`[l, r]`、配列内のすべての要素が`<= v`。 いずれかの要素がより大きい場合`v`の場合、これに有効なパーティションは存在しません。`v`なぜなら、そのような要素は左、中央、または右のいずれかに配置する必要があり、最大/最小条件に違反するからです。 
5. また、左側の部分が空ではなく、右側の部分が空ではないことも確認します。`l > 0`そして`r < n-1`。 
6. すべての条件が満たされる場合、パーティションの長さを構築できます。`(x, y, z)`として`x = l`、`y = r - l + 1`、`z = n - r - 1`。 
7. 値がない場合`v`動作したら出力します`NO`。 

### なぜ効果があるのか

 重要な不変条件は、中間セグメントが完全に単一の値で構成されている必要があることです。`v`。 これが修正されると、制約により配列内の他のすべての要素が強制的に変更されます。`<= v`より大きな値は、右セグメントの最大値が等しいという要件に違反するためです。`v`。 同様に、中央より内側の値が小さいと、最小値が次の値に等しいという条件が破られます。`v`。 中央を等しい要素の連続ブロックに固定し、相対的なグローバル境界を検証することにより、`v`、構築されたパーティションの実現可能性と正確性の両方を保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        pos = {}
        for i, v in enumerate(a):
            pos.setdefault(v, []).append(i)

        total_max = max(a)

        ok = False
        ans = None

        for v, idxs in pos.items():
            if len(idxs) < 2:
                continue

            l = idxs[0]
            r = idxs[-1]

            # middle must be at least one element and contiguous block
            # we choose full span of v occurrences
            if l == 0 or r == n - 1:
                continue

            # check all elements <= v
            valid = True
            for x in a:
                if x > v:
                    valid = False
                    break

            if not valid:
                continue

            # ensure left and right non-empty
            if l <= 0 or r >= n - 1:
                continue

            ok = True
            ans = (l, r)

            break

        if not ok:
            print("NO")
        else:
            l, r = ans
            x = l
            y = r - l + 1
            z = n - r - 1
            print("YES")
            print(x, y, z)

if __name__ == "__main__":
    solve()
```この実装では、中間セグメントの候補を値ごとに一定の時間で形成できるように、等しい値のインデックスをグループ化します。 各候補について、最初と最後の出現を使用して最大の連続ブロックを定義します。これは、有効な解は等価制約を破ることなくこの区間に拡張できるためです。 

グローバルチェック`x > v`は、右辺最大条件の適用です。 境界チェックにより、両方の外側セグメントが存在することが確認されます。 

ここでの実装上の微妙なリスクは、中間が厳密に配列内に存在する必要があることを忘れていることです。 もし`l == 0`または`r == n-1`の場合、セグメントの 1 つが空になり、値の制約が満たされていても無効になります。

 ## 特殊なケース

 微妙なケースの 1 つは、唯一の候補値が配列の境界にのみ現れる場合です。 で`[3, 1, 2, 3]`、選択する`v = 3`中央のブロックを強制的にエンドポイントに接触させ、1 つのセグメントを空のままにします。 アルゴリズムはこれを拒否します。`l == 0`または`r == n-1`、有効性を保証します。 

もう 1 つのケースは、複数の値が存在するが、グローバル上限制約を満たすのは 1 つだけである場合です。 で`[2, 1, 3, 1, 2]`、 価値`3`すべてがそうでなければならないという要件に違反するため、すぐに失敗します。`<= v`実現可能な中間と比較して。 このアルゴリズムはパーティションの構築を試行する前にそれをフィルタリングして除外し、誤った分割を防ぎます。 

最後のケースは、有効な`v`複数のセグメントに分割されます。 たとえ`v`は何度も出現しますが、連続した内部ブロックのみが中間として機能し、アルゴリズムは常に境界安全な間隔を使用するため、正確さを維持しながら両側が空にならないようにします。
