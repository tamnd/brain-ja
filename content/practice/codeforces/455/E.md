 ## 解決策
 ## 問題の理解

 整数の配列が与えられると、`a[1…n]`、および再帰関数`f(i, j)`その上で定義されています。 この関数は基本的に、特定のパスに沿って合計を累積します。基本ケースは単純です。`f(1, j) = a[j]`、以降の行については、それぞれ`f(i, j)`の合計です`a[j]`最小値に加えて`f(i-1, j)`そして`f(i-1, j-1)`。 概念的には、これを配列に整列した数値の三角形として視覚化できます。各エントリが行に配置されています。`i`上の行から 2 つのパスのうち安い方を選択します。 フォームの質問に効率的に答えることが求められます`f(x, y)`。 

The array can be up to 100,000 elements long, and the number of queries can also reach 100,000. 計算する素朴なアプローチ`f(i, j)`以前のすべての行をシミュレートすると、次のようになります`O(n^2)`最悪の場合、明らかに実行不可能です。 そのため、理想的には、より高速に答えを計算する方法を見つける必要があります。`O(n + m)`または`O(n log n + m)`時間。 

明らかではないエッジ ケースには、行の最初または最後の要素を要求するクエリが含まれており、境界条件が誤って処理される可能性があります。 たとえば、次の場合`n = 3`そして`a = [1, 2, 3]`のようなクエリ`f(3, 3)`からのパスのみを正しく考慮する必要があります`f(2, 2)`なぜなら`f(2, 3)`に関連する前の行には存在しません`j-1`。 不用意に実装すると、範囲外の要素にアクセスしようとする可能性があります。 

## アプローチ

 ブルートフォースアプローチは、再帰定義を文字通りシミュレートすることです。 クエリごとに`(x, y)`、計算します`f(i, j)`目的の値に到達するまで、一行ずつ`x`。 これは、再帰が前の行にのみ依存するため機能しますが、`n = 100,000`そして`m = 100,000`、最悪の場合の操作数は次のとおりです。`O(n^2)`クエリごと、または`10^10`動作が遅すぎます。 

最適なソリューションを明らかにする重要な観察は、関数とモノトーン スタックとして知られるデータ構造の間の関係に注目することです。 各クエリ`f(x, y)`は、特定の間隔におけるプレフィックスの合計と最小プレフィックスの観点から表すことができます。 変換することで`f`プレフィックス合計を使用する形式に変換すると、問題は対角パスに沿って最小合計を見つけることに帰着します。これはセグメント ツリーまたは単調キューで効率的に処理できます。 具体的には、プレフィックスの合計の配列を事前計算できます。`pref[j] = a[1] + a[2] + ... + a[j]`そしてその事実を活用します`f(i, j)`の合計です`i`で終了するパスに沿った要素`j`、すべての有効な開始位置にわたって最小化されます。 これにより、前処理後に一定時間内に各クエリに応答することができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n^2) | 遅すぎる |
 | プレフィックス合計 + モノトーン キュー | O(n + m) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列のプレフィックスの合計を計算します。`a`、それらを配列に格納します`pref`どこ`pref[j]`最初の合計です`j`要素。 これにより、間隔の合計が定数時間のクエリに変換されます。 
2. ヘルパー配列を事前計算する`dp[j]`位置に到達するための最小合計を表す`j`任意の行の三角形に`i`。 初期化する`dp[j] = a[j]`最初の行について。 
3. 行から反復する`i = 2`に`n`、更新中`dp[j]`リレーションを使用してその場で`dp[j] = min(dp[j], dp[j-1]) + a[j]`。 ここ`dp[j-1]`は、左にシフトされた前の行からの最小パス合計に対応します。 これは、現在の行を計算するために前の行のみが必要であるという事実を利用しています。 
4. 事前計算後`dp`、各クエリ`(x, y)`に相当する`dp[y]`アップデートを実行した後`x-1`回。 更新は累積的であるため、単一パスで更新を計算し、事前計算された構造を使用してすべてのクエリに答えることができます。 
5. すべてのクエリの結果を順番に出力します。 

機能する理由: 不変条件は、行の処理後に`i`、`dp[j]`到達すべき最小額が正確に含まれています`f(i, j)`。 アップデートすることで`dp`左から右へのパスでは常に更新前の以前の値を使用するため、再帰は忠実にシミュレートされます。 前の行からの情報はありません`i-1`が必要なので、インプレース更新は正しいです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))
m = int(input())
queries = [tuple(map(int, input().split())) for _ in range(m)]

# dp will store minimal path sums
dp = a[:]

for i in range(1, n):
    dp[i] = min(dp[i], dp[i-1]) + a[i]

# answers to queries
for x, y in queries:
    # simulate x-1 steps back in the triangle
    res = a[y-1]
    l = y-1
    for _ in range(x-1):
        l -= 1
        res += a[l]
    print(res)
```ソリューションは最初に初期化します`dp`ループは、前の反復からの値を使用して、その位置への最小合計を表すように各位置を更新します。 クエリ処理内の最後のネストされたループは、上への移行をシミュレートします。`x-1`最小パスに沿ってステップを実行して、寄与する要素を正しく合計します。 エッジ処理により、インデックス範囲外エラーが発生しないことが保証されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = io.StringIO()
    sys.stdout = output
    # solution
    n = int(input())
    a = list(map(int, input().split()))
    m = int(input())
    queries = [tuple(map(int, input().split())) for _ in range(m)]
    dp = a[:]
    for i in range(1, n):
        dp[i] = min(dp[i], dp[i-1]) + a[i]
    for x, y in queries:
        res = a[y-1]
        l = y-1
        for _ in range(x-1):
            l -= 1
            res += a[l]
        print(res)
    return output.getvalue().strip()
