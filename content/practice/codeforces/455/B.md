 ## 解決策
 ## 問題の理解

 ゲームは、指定された文字列から構築されたトライを通じて進行するものとして見ることができます。 

空の文字列を表すルートから始めます。 各ターンで、プレイヤーはキャラクターの追加に対応する 1 つの出力エッジを選択します。 現在の文字列は常に少なくとも 1 つの辞書単語の接頭辞のままである必要があるため、すべての正当な手はトライのエッジに従うだけです。 

子のないトライ ノードに到達すると、それ以上キャラクターを追加できないため、プレイヤーは負けます。 

ひねりを加えれば、ゲームは正確にプレイされるということです`k`回。 あるゲームの敗者が次のゲームを開始します。重要なのは最後のゲームに誰が勝つかだけです。 両プレイヤーはどの試合でも最適なプレーをします。 

入力は次のようになります。`10^5`すべての文字列の長さの合計も最大です。`10^5`。 各トライ ノードを一定の回数だけ処理するソリューションであれば、十分に高速です。 トライには約`10^5`ノード。 

この問題の最も微妙な部分は、実際には重要な 2 つの異なるゲーム特性があるということです。 

次の入力を考えてみましょう。```
1 2
a
```トライはroot→aだけです。 最初のプレイヤーは次の場所に移動する必要があります`a`、その後、2番目のプレイヤーは何も動かずに負けます。 最初のプレイヤーが常に勝ちます。 敗者が次のゲームを開始するため、2 番目のプレーヤーが第 2 ゲームを開始し、再び負けます。 最初のプレイヤーが最後のゲームに勝ちます。 「先手がルートから勝てるか？」を計算するだけのソリューション。 複数のゲーム間の相互作用が失われる可能性があります。 

もう 1 つの重要なケースは次のとおりです。```
2 100
ab
ac
```先手が動けるのでルートの勝ちです。 ただし、すべてのパスの長さはちょうど 2 です。 ゲームのパリティ構造が重要になります。 最初のプレーヤーが勝利を強制できるかどうかだけでは十分ではありません。 また、戦略的に望ましい場合に損失を強制できるかどうかも知る必要があります。 

3 番目の注意が必要なケースは次のとおりです。```
1 1
abc
```道は一つしかありません。 結果はパス長のパリティによって完全に決まります。 終端位置を無視し、分岐要素のみに注目する解決策は失敗します。 

重要な観察は、すべてのトライ ノードについて 2 つの独立した情報が必要であるということです。 

## アプローチ

 ブルート フォース アプローチでは、考えられるすべてのゲーム状態と、考えられるすべてのゲーム シーケンスを明示的に分析します。 1 つのゲームであっても、トライの深さに応じて可能なプレイの数は指数関数的に増加します。 以来`k`と同じ大きさにすることができます`10^9`、ゲームを1つずつシミュレートすることは不可能です。 

公平なゲームの構造では、ゲーム DP の使用が推奨されています。 すべてのトライノードは状態です。 プレイヤーはノードから 1 人の子供を選択します。 ターミナルノードには正当な動きはありません。 

通常プレイのゲームの場合、負けている状態への移行があれば、その状態は勝ちです。 すべての手が勝ちの状態になると、その状態は負けになります。 

この通常の勝敗ステータスのみを計算すると、現在のプレーヤーが勝利を強制できるポジションのセットが得られます。 これでシングルゲーム版は解決しますが、この問題は解決しません。 反復ゲーム ルールでは、別の疑問が生じます。現在のプレーヤーは、残りのどちらかの同等の手でゲームを強制的に終了させることができますか?

 これにより、2 つの DFS 計算が行われます。 

最初の DFS は、ノードが勝利しているかどうかを計算します。これは、「勝利状態」と呼ばれることがよくあります。 

2 番目の DFS は、通常、社説で「負け状態」と呼ばれる、別の基準に基づいてノードが負けているかどうかを計算します。 現在のプレイヤーが希望に応じて最終的に敗北を許可する方法でゲームを強制終了できるかどうかを決定します。 

両方の特性が根本的に分かると、マルチゲームの問題全体がいくつかの単純なケースに分解されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | 指数 | 遅すぎる |
 | 最適なトライ + DFS ゲーム DP | O(文字列の合計長) | O(文字列の合計長) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての入力文字列からトライを構築します。 

すべてのノードは有効なプレフィックスを表します。 ゲーム内のすべての正当な動きは、1 つのトライ エッジを横切ることに対応します。 
2. コンピューティング`win[v]`すべてのノードに対して。 

ノードに子がない場合、`win[v] = False`現在のプレイヤーは移動できないためです。 

さもないと、`win[v] = True`少なくとも1人の子供がそうであれば`win = False`。 

これは公平なゲームにおける標準的な勝利状態の繰り返しです。 
3. コンピューティング`lose[v]`すべてのノードに対して。 

ノードに子がない場合は、次のように設定します。`lose[v] = True`。 

さもないと、`lose[v] = True`少なくとも1人の子供がそうであれば`lose = False`。 

この 2 番目の DP は、現在のプレイヤーが最終的に敗北を許すパリティでゲームを終了させることができるかどうかという別の質問に答えます。 
4. ルートをノードとする`0`。 

もし`win[root]`が false の場合、最初のプレイヤーは 1 つのゲームにも勝つことができません。 答えは`"Second"`。 
5. もし`win[root]`それは真実であり、`lose[root]`が true の場合、最初のプレイヤーはどちらかのタイプのエンディングを強制できます。 答えはいつも`"First"`。 
6. もし`win[root]`それは真実であり、`lose[root]`が false の場合、使用できるパリティ構造は 1 つだけです。 

この場合、答えは以下によって決まります`k`。 

もし`k`奇数です、出力`"First"`。 

もし`k`偶数、出力`"Second"`。 

### なぜ効果があるのか

 最初の DFS は、現在のプレーヤーが 1 つのゲームで勝利をもたらすことができるポジションを特定します。 

2 番目の DFS は、現在のプレーヤーが有利なパリティで終端ノードに強制的に到達できる位置を識別します。 ターミナルノードには、`lose = True`なぜなら、そこに移動する現在のプレイヤーはすぐに負けるからです。 

ルートは、意味のある 3 つのカテゴリのうちの 1 つに正確に分類されます。 

ルートが勝てない場合、最初のプレイヤーはすぐに負けます。 

ルートが勝っていて 2 番目のプロパティも持っている場合、最初のプレーヤーは、残りのゲーム数に関係なく、勝利を強制するのに十分なゲーム ツリーの制御権を持っています。 

ルートが勝っていても 2 番目のプロパティがない場合、ゲームの結果はパリティによって固定され、奇数のみになります。`k`最初のプレーヤーが最終ゲームに勝つことができます。 

これらはまさにこのゲームの公式分析で証明されたケースです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())

    trie = [[-1] * 26]

    for _ in range(n):
        s = input().strip()
        node = 0

        for ch in s:
            c = ord(ch) - ord('a')

            if trie[node][c] == -1:
                trie[node][c] = len(trie)
                trie.append([-1] * 26)

            node = trie[node][c]

    m = len(trie)

    win = [False] * m
    lose = [False] * m

    sys.setrecursionlimit(300000)

    def dfs(v):
        children = []

        for nxt in trie[v]:
            if nxt != -1:
                children.append(nxt)

        if not children:
            win[v] = False
            lose[v] = True
            return

        win[v] = False
        lose[v] = False

        for to in children:
            dfs(to)

        for to in children:
            if not win[to]:
                win[v] = True
            if not lose[to]:
                lose[v] = True

    dfs(0)

    if not win[0]:
        print("Second")
    elif lose[0]:
        print("First")
    else:
        print("First" if k % 2 == 1 else "Second")

if __name__ == "__main__":
    solve()
```トライ構造では、個別のプレフィックスごとに 1 つのノードが作成されます。 入力の合計長は最大でも`10^5`、トライノードの総数も`O(10^5)`。 

の`win`配列には標準的なゲーム理論の結果が格納されます。 負けた子への動きが存在する場合、ノードは勝利しています。 

の`lose`配列は別の繰り返しを使用します。 終端ノードは true とマークされます。 内部ノードの場合、少なくとも 1 つの子の値が false であれば、値は true になります。 これは、現在のプレーヤーが必要なパリティ構造でゲームを強制的に終了できるかどうかをキャプチャします。 

バグを引き起こすことが多い実装の詳細の 1 つは、次の基本ケースです。`lose`。 ターミナルノードは次のように初期化する必要があります`True`、 ない`False`。 間違った値を使用すると、2 番目の DFS の意味が完全に逆転します。 

もう 1 つのよくある間違いは、次のことを忘れることです`k`と同じ大きさにすることができます`10^9`。 ゲームをシミュレートしようとするアプローチは不可能です。 ルートの 2 つの DP 値のみが重要です。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    n, k = map(int, input().split())

    trie = [[-1] * 26]

    for _ in range(n):
        s = input().strip()
        node = 0

        for ch in s:
            c = ord(ch) - ord('a')

            if trie[node][c] == -1:
                trie[node][c] = len(trie)
                trie.append([-1] * 26)

            node = trie[node][c]

    m = len(trie)
    win = [False] * m
    lose = [False] * m

    sys.setrecursionlimit(300000)

    def dfs(v):
        children = [x for x in trie[v] if x != -1]

        if not children:
            lose[v] = True
            return

        for to in children:
            dfs(to)

        for to in children:
            if not win[to]:
                win[v] = True
            if not lose[to]:
                lose[v] = True

    dfs(0)

    if not win[0]:
        return "Second"

    if lose[0]:
        return "First"

    return "First" if k % 2 else "Second"

# provided sample
assert run("2 3\na\nb\n") == "First", "sample 1"

# minimum size
assert run("1 1\na\n") == "First", "single move"

# parity-dependent case
assert run("2 2\na\nb\n") == "Second", "even k"

# losing root
assert run("1 2\nab\n") == "Second", "forced loss"

# deeper branching
assert run("3 5\na\nab\nac\n") == "First", "mixed trie"

 ## 特殊なケース

 次のことを考慮してください。```
1 2
a
```トライには 1 つのエッジが含まれます。 根には、`win = True`そして`lose = False`。 以来`k`が偶数の場合、アルゴリズムは次のように出力します。`"Second"`。 これはまさにパリティに敏感な状況であり、通常の勝利状態のみをチェックするソリューションを破壊します。 

考慮する：```
1 1
abc
```トライは長さ 3 の単一パスです。 DFS は値をリーフから上に伝播します。 ルートが勝つので、答えは`"First"`。 このアルゴリズムは、明示的なパリティ カウントを必要とせずに、長いチェーンを正しく処理します。 

考慮する：```
2 1
ab
ac
```ルートからリーフへのパスはどちらも同じ深さです。 ルートは負ける子の構成に移行できるため、勝ちます。 DFS は、パスの長さに関係なく、正確なゲーム理論上のステータスを計算します。 答えはルートの 2 つの DP 値から直接得られます。 

これらのケースは、両方の DFS 状態が必要な理由を示しています。 1 つは勝利が可能かどうかをキャプチャし、もう 1 つはプレイヤーがゲームの終了構造を十分に制御して任意の値を処理できるかどうかをキャプチャします。`k`。
