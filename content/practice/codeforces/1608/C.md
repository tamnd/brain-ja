 ## 問題の理解

 私たちは、トーナメントの各プレーヤーが、トーナメントが最適に実施された場合に勝つ可能性があるかどうかを判断するように求められています。 マップは 2 つあり、各プレイヤーは両方のマップで強みを持っています。 選択したマップで 2 人のプレイヤーが戦う場合、そのマップでより強いプレイヤーが常に勝ちます。 同じマップ上で同じ強さのプレイヤーは 2 人いないため、すべての戦闘には明らかな勝者がいます。 

トーナメントは、残りの 2 人のプレイヤーを繰り返し選択し、任意のマップで戦わせ、1 人のプレイヤーが残るまで敗者を排除することで構成されます。 各プレイヤーについて、最終的な勝者になれる一連の戦いが存在するかどうかを判断する必要があります。 出力は長さの文字列です$n$、プレイヤーが勝つことができた場合は「1」、そうでない場合は「0」になります。 

制約が意味するのは、$n$到達できる$10^5$すべてのテスト ケースの合計。 これにより、考えられるすべての戦闘シーケンスをシミュレートするアプローチは除外されます。$n$。 代わりに、線形または線形に近いアルゴリズムが必要です。 

明らかではないエッジ ケースとしては、そのプレイヤーが簡単に勝つシングル プレイヤー トーナメントや、プレイヤーの強さによって両方のマップを支配できるプレイヤーが 1 人もいない状況が挙げられ、強力なマップでより強力な対戦相手との直接対決を避ければ、複数のプレイヤーにチャンスが与えられます。 たとえば、2 人のプレイヤーの場合: マップ A の強み$[2,1]$そしてマップB$[1,2]$、一致の順序によっては両方が勝つ可能性があるため、出力は「11」になるはずです。 

## アプローチ

 ブルートフォースアプローチは、考えられるあらゆる戦闘シーケンスをシミュレートすることです。 考えられるすべてのペアとマップを選択し、勝者を伝播し、プレイヤーが決勝に進出できるかどうかを確認します。 このアプローチは原理的には正しいですが、検討が必要です$O(n!)$のシーケンス$n$プレーヤーにとっては不可能です$n$まで$10^5$。 

重要な洞察は、トーナメントの結果が 2 つのマップの優位性によって制約されるということです。 両方のマップで他のプレイヤーよりも弱いプレイヤーは決して勝つことはできません。選択したマップに関係なく、最終的にはその強いプレイヤーと対戦して負けることになるからです。 逆に、両方のマップで他のプレイヤーに支配されていないプレイヤーは、最後まで強い敵を避けるように調整され、勝者になる可能性があります。 

これを具体的にするには、2 次元の強度を考慮します。$(a_i, b_i)$各プレイヤーの。 プレイヤーを 1 つのマップで分類し、これまでに確認された他のマップの最大強さを追跡することで、最小限の「支配フロンティア」を特定できます。 両方のマップでより強いプレイヤーが存在する場合、プレイヤーは排除される可能性があります。 この優勢なセット以外のプレイヤーは勝者になる可能性があります。 

これにより、プレーヤーの並べ替えとリニア スキャンの問題が軽減され、時間の複雑さが次のようになります。$O(n \log n)$階乗ではなくテストケースごとに。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | お(ん!) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、次の内容を読んでください。$n$そして強さの配列$a$そして$b$。 それらを組み合わせてペアにします$(a_i, b_i, i)$元のインデックスを保持します。 
2. ペアを昇順に並べ替えます。$a_i$。 2人のプレイヤーが同じものを持っている場合$a_i$、までに注文してください$b_i$降下中。 これにより、左から右にスキャンするときに、現在の最大値を追跡するだけで済みます。$b$。 
3. 変数を初期化する$max_b$に$-\infty$。 これは最高値を追跡します$b$これまでにソートされた順序で表示された値。 
4. 長さ 0 の結果配列を初期化します。$n$。 
5. ソートされたプレーヤー リストを繰り返し処理します。 プレイヤーごとに$(a, b, idx)$：

- もし$b \ge max_b$、両方のマップでこのプレイヤーを支配する以前にスキャンされたプレイヤーが存在しないため、result[idx] を 1 としてマークします。 
- アップデート$max_b$最大まで$max_b$そして$b$。 
6. すべてのプレーヤーをスキャンした後、結果を文字列として出力します。 

機能する理由: 並べ替え$a$最大値を追跡しながらスキャンします$b$両方のマップで優勢なプレイヤーを確実に特定します。 このチェックを生き残ったプレイヤーは、より強力なプレイヤーに支配されない少なくとも 1 つの側面を持っています。つまり、最後まで敗退を回避できる巧妙な一連の戦いが存在します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        players = [(a[i], b[i], i) for i in range(n)]
        players.sort()  # sort by a ascending

        res = [0] * n
        max_b = -1
        for pa, pb, idx in players:
            if pb >= max_b:
                res[idx] = 1
            max_b = max(max_b, pb)
        print("".join(map(str, res)))

if __name__ == "__main__":
    solve()
```このソリューションでは、まずすべての入力を効率的に読み取ります。 プレーヤーは元のインデックスを持つタプルに結合され、入力順序で出力が生成されます。 並べ替え順$a$私たちがチェックするときにそれを保証します$b$、プレーヤーが両方のマップで支配されているかどうかを判断するには、実行最大値を維持するだけで済みます。 これにより、1 人のプレイヤーや、2 つのマップで十字パターンを形成する強みを持つプレイヤーなど、境界や特殊なケースが自然に処理されます。
