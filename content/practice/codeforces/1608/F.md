 ## 問題の理解

 配列を左から右に段階的に構築し、各位置の後で、これまでに構築したプレフィックスを確認します。 そのプレフィックスから、その MEX を計算します。これは、プレフィックスに現れない最小の非負の整数です。 この進化する配列とともに、ターゲット配列が与えられます。 各ステップで、現在のプレフィックスの MEX は、対応するターゲット値から最大で 1 だけ逸脱することが許可されます。`k`。 タスクは、すべてのプレフィックスでこの条件を遵守する完全な配列をいくつ構築できるかをカウントすることです。 

重要な問題は、MEX がローカル統計ではないことです。 値を追加すると、不足しているギャップを埋めるかどうかに応じて、MEX が増加するか、変更されないままになります。 これは、システムの状態が現在の MEX だけでなく、どの値が反映されるかも意味することを意味します。`0`上向きはプレフィックスですでに「アクティブ化」されています。 

制約は厳しいです:`n`2000年までです`k`これにより、配列またはサブセットに対する指数列挙が除外されます。 使用される数値の任意のサブセットを追跡する単純な状態表現も不可能です。これは、おおよその係数を意味するためです。`2^n`行動。 前進する唯一の方法は、現在の MEX 範囲のみに依存するものに状態を圧縮し、次の事実を利用することです。`k`MEX をターゲットから強制的に遠ざけることができる距離を制限します。 

ターゲットが次の場合に微妙なエッジケースが発生します。`b_i`負であるか、それより大きい`n`。 MEXは常に入っているので、`[0, n]`、これらの値はソフト制約として機能します。たとえば、`b_i = -2`の状態になります。`MEX >= -2 - k`これは常に真であるため、上限のみが重要です。 同様に非常に大きい`b_i`値は下限を課すだけです。 これらの制約をクランプしない不用意な実装`[0, n]`遷移を過剰に制約または過少に制約すると、誤ったカウントが生成されます。 

もう 1 つの注意が必要な状況は、MEX がジャンプする場合です。 たとえば、あるプレフィックスにすべての番号がある場合、`0..4`現在、MEX は`5`。 別のものを追加する`5`MEX は変更されませんが、欠落しているものを追加します`3`または`1`重複は MEX に影響しないため、不可能な場合もあります。 多くの単純な DP 定式化では、新しい要素がそれぞれ単調にカバレッジを増加させると誤って仮定していますが、これは誤りです。 

## アプローチ

 ブルートフォースアプローチでは、すべての配列を構築しようとします。`a`そして、MEX 制約が適用されるかどうかをプレフィックスごとに確認します。 位置ごとに、プレフィックスに対して MEX を最初から再計算します。これにはコストがかかります`O(n)`ステップごとに、`n^n`合計で配列。 初期のプレフィックスでは MEX が安定する前に多くの選択肢が許可されるため、制約による枝刈りでも十分な効果はありません。 これは、実行可能な計算をはるかに超えて爆発します。 

重要な観察は、MEX がプレフィックス内でどの小さな数値が完全に「完成」したかにのみ依存するということです。 数値を 1 回`x`少なくとも 1 回出現すると、MEX の増加につながる可能性があります。 重要なのは完全な集合構造ではなく、最初に欠落している整数です。 

現在の MEX を追跡します`m`。 プレフィックスにはすべての数字が含まれます`0..m-1`、 そして`m`は不在です。 新しい要素は、以下の欠落している番号を埋めるか、`m`これは MEX を増加させる可能性があります。あるいは、無関係なノイズ (より大きな値) である可能性があります。`m`）。 この構造は、欠損値を導入するかどうかによって遷移が異なることを意味します。 

これをポジションと可能な MEX 値に対する DP に変換します。 制約`|MEX - b_i| <= k`各ステップの有効な MEX 値を周囲の小さなウィンドウに制限します`b_i`したがって、一定のサイズの範囲にわたってのみ DP を維持します。`O(k)`考えられる各 MEX の周囲にあります。 移行は、同じ MEX を維持するか、現在の不足している数値を埋めることによって MEX を増やすことによって行われます。 

「MEX を変更しない」方法と「MEX を増やす」方法が何通りあるかを効率的にカウントするために、組み合わせの選択肢を維持します。各ステップで、現在の MEX より大きい値を選択することは、以下と同等です。`n - m`オプションを選択する一方で、MEX を完成させる欠落番号を選択することは、まさに 1 つの特定の値です。 

これにより、線形遷移を伴う制御された DP over MEX 状態に問題が軽減されます。

 ## アルゴリズムのチュートリアル

 私たちは定義します`dp[i][m]`最初の構築方法の数として`i`プレフィックスの MEX が正確に一致するような要素`m`。 以来`m`常に間にあります`0`そして`n`、ただし、によって制約されます`b_i`、以下の状態のみを考慮します。`m`にある`[b_i - k, b_i + k]`。 

1.初期化`dp[0][0] = 1`。 開始時には要素は存在せず、MEX は`0`なぜなら`0`すぐになくなってしまいます。 
2. ポジションごとに`i`から`1`に`n`、新しい DP テーブルを構築します`ndp`。 
3. 考えられる各 MEX 値について`m`それはステップの制約の下で有効です`i`では、前の状態からの 2 種類の遷移を考えます。 
4. まず、MEX を変更しないことを検討します。 これは、欠落している整数を埋めない値を追加したときに発生します。`m`。 がある`m`すでに完全に「非アクティブ」な値の選択肢 (現在の MEX 以上であっても正確性は低下しません)、および`(n - m)`MEX に影響を与えない値の選択肢。 重要な考え方は、次の値より大きい値はすべて考慮されるということです。`m`MEX は変更されません。 
5. 次に、MEX の増加を検討します。 から移動するには`m`に`m+1`、値を配置する必要があります`m`プレフィックスで初めて。 これは値の選択肢の 1 つですが、前のプレフィックスに MEX が含まれている場合にのみ有効です。`m`そして今挿入します`m`。 
6. これらの寄与を合計し、結果をモジュロで保存します`998244353`。 
7. すべてのポジションを処理した後、すべてのポジションを合計します。`dp[n][m]`どこ`m`ステップで有効です`n`。 

### なぜ効果があるのか

 不変条件は、すべてのステップで、`dp[i][m]`現在の数値の集合が次のようになるプレフィックスを構築する方法の数を正確に数えます。`m`欠落している最小の整数。 MEX はプレフィックスによって一意に決定されるため、有効なプレフィックスはいずれもそのような状態の 1 つに該当する必要があります。 すべての配列拡張により欠落した MEX 要素が導入されるか (決定論的な増加が強制される)、またはそれが回避される (MEX が変更されないままになる) ため、トランジションによって正確さが維持されます。 他の操作は MEX 境界に影響を与えることができないため、すべての有効な配列は 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n, k = map(int, input().split())
    b = list(map(int, input().split()))

    # dp[m] = number of ways with current MEX = m
    dp = [0] * (n + 2)
    dp[0] = 1

    for i in range(1, n + 1):
        ndp = [0] * (n + 2)
        bi = b[i - 1]

        # valid mex range at step i
        L = max(0, bi - k)
        R = min(n, bi + k)

        for m in range(L, R + 1):
            val = dp[m]
            if not val:
                continue

            # case 1: choose value > m or from "irrelevant pool"
            # there are (n - m) choices that do not introduce m
            ndp[m] = (ndp[m] + val * (n - m)) % MOD

            # case 2: try to introduce m and increase mex
            if m + 1 <= n:
                ndp[m + 1] = (ndp[m + 1] + val) % MOD

        dp = ndp

    # sum all valid final mex states
    print(sum(dp) % MOD)

if __name__ == "__main__":
    solve()
```この実装では、単一の DP 配列が維持され、位置ごとにそれが更新されます。 重要な詳細は、境界トランジションです。`[b_i - k, b_i + k]`、不可能な MEX 状態を取り除き、複雑さを線形に保ちます。`n · k`。 

掛け算`(n - m)`現在の MEX より厳密に大きい値は、欠落しているプレフィックス構造に影響を与えないことを反映しています。 2 番目の遷移は、欠落している整数を配置することで MEX を進める独自の方法をエンコードします。 

実装上の微妙な懸念事項は、インデックス作成です。MEX は次のことを達成できます。`n`したがって、配列は安全に対応する必要があります`n + 1`。 もう 1 つは、ネガティブなことを確実にすることです。`b_i - k`MEX を負にすることはできないため、 はゼロにクランプされます。

 ## 特殊なケース

 重大なエッジケースが発生するのは次の場合です。`b_i - k < 0`。 その状況では、有効な MEX ウィンドウをゼロにクランプする必要があります。 これが行われない場合、DP は負の MEX 状態にアクセスしようとし、有効な構成が実質的に削除される可能性があります。 たとえば、`b_i = 0, k = 5`、正しい解釈は、MEX は常に 0 以上 5 まで許容されますが、負になることはありません。 

別の特殊なケースが発生します`m = n`、MEX を増加させようとする遷移が境界を超える場合があります。 DP は明示的に保護する必要があります`m + 1 <= n`、MEX を超えることはできないため、`n`。 これがないと、配列のインデックスが範囲外になったり、無効な状態が誤ってカウントされたりする可能性があります。 

最後に、いつ`b_i`など大きいです`b_i = n + k`、制約ウィンドウは実質的に次のようになります。`[n, n]`、MEX を強制的に`n`。 この場合、すべてのプレフィックスにすべての数字が含まれている必要があります`0..n-1`、そして DP は決定論的な組み合わせプロセスに崩壊します。 実装はこれを自然に処理します。`m = n`DP ウィンドウ内で存続します。
