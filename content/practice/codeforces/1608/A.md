 ## 解決策
 ## 問題の理解

 連続する要素に特定の制限を設けて、テスト ケースごとに増加する整数のシーケンスを構築するように求められます。 シーケンスは厳密に増加している必要があり、さらに次のすべての要素が前の要素で割り切れてはなりません。 両方の制約を尊重し、最大 10 億の範囲内に収まる限り、有効な構造を自由に選択できます。 

各テストの要素が最大 1000 個であり、テスト全体の合計が最大 10,000 個であるという意味で、入力サイズは小さくなります。 これは、高度なデータ構造や複雑な前処理が必要ないことを意味します。 テスト ケースごとに線形時間で実行されるソリューションは、簡単に十分に高速です。 

主な構造上の制約は、隣接する要素間の可分性条件です。 場合によっては、特に倍数を注意深くステップ実行する場合、すべての整数がその前の整数で割り切れるため、連続する整数のような単純な増加シーケンスはすぐに失敗します。 同様に、単純な等差数列は予測可能な割り算パターンを導入することが多いため、危険です。 

エッジケースは最小限ですが、概念的には重要です。 n が 1 の場合、許容範囲内の任意の値を受け入れます。 n が大きい場合、構築では、a_{i} = k * a_{i-1} のペアが誤って導入されることを避ける必要があります。 たとえば、1、2、4、8 のような 2 の累乗を選択した場合、すべての要素が次の要素を分割するため、条件は完全に失敗します。 これは、「増やす」だけでは十分ではなく、積極的に乗法構造を破壊する必要があることを示しています。 

## アプローチ

 ブルートフォースアプローチでは、一度に 1 要素ずつシーケンスを構築しようとします。 次の値の候補ごとに、前の値より大きいすべての整数を、その値で割り切れない値が見つかるまでテストします。 これは制約を明示的に強制するので正しいのですが、最悪の場合、すべての位置について数直線の大部分をスキャンする可能性があり、最悪の場合は二次関数の動作につながる可能性があるため、コストが高くなります。 

重要な観察は、単純な構造化された方法で連続する数値が互いに素であることを保証すると、割り算を避けるのが簡単になるということです。 動的に可分性を回避しようとする代わりに、構築によって強制的に可分性を回避することができます。 標準的なトリックは、制御された増加パターンでパリティを交互に配置することです。 基本値を選択し、前の値の倍数の要素がないことを保証するパターンで小さなオフセットを追加すると、チェックなしで正確さを保証できます。 

特に単純な構造は、大きな一定のギャップから開始し、可分性を破りながら厳密に増加するようにインデックスを追加することです。 クリーンなアイデアの 1 つは、シーケンスを出力することです。 

a_i = 1000 * i + 1

 これにより、連続する項間のギャップがちょうど 1000 であるため、厳密な増加が即座に保証されます。さらに重要なことは、連続する項は互いの倍数ではないため、a_i modulo a_{i-1} がゼロになることはありません。差は固定されていますが、+1 オフセットにより比率は整数ではありません。 a_i を a_{i-1} で除算しようとすると、a_{i-1} がオフセット 1 の線形数列に均等に適合しないため、失敗します。 

ブルート フォースはローカルで検索することで機能しますが、意図的なオフセットを使用して固定算術構造を埋め込むことができるという観察により、検索の必要性がすべてなくなりました。

 ## アルゴリズムのチュートリアル

 各テスト ケースに対して配列を直接構築します。 

1. 与えられた n に対して、i を 1 から n まで繰り返します。 
2. 各インデックス i について、値 a_i = 1000 * i + 1 を計算します。 
3. 計算された各値を出力シーケンスに追加します。 
4. シーケンスを印刷します。

1000 を選択した理由は純粋に利便性です。 n より大きい定数も機能しますが、n ≤ 1000 であるため、制約の下では 1000 が安全です。+1 シフトにより、シーケンス構造内で別の要素の正確な倍数にならない要素が保証されます。 

### なぜ効果があるのか

 各項が前の項からちょうど 1000 ずつ増加するため、構築されたシーケンスは厳密に増加しています。 連続するペアの比率が次のとおりであるため、割り算条件は失敗します。 

a_i / a_{i-1} = (1000i + 1) / (1000(i-1) + 1)

 整数は指定できません。 分子と分母は 1000 異なりますが、+1 オフセットにより、キャンセルによって整数の比率が生成されなくなります。 したがって、次の要素を分割する要素はなく、すべての制約が満たされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        res = []
        for i in range(1, n + 1):
            res.append(str(1000 * i + 1))
        print(" ".join(res))

if __name__ == "__main__":
    solve()
```このソリューションは完全に直接構築に依存しています。 ループは各項を一定時間で生成し、出力はテスト ケースごとに 1 回行われます。 

重要な実装の詳細は、印刷前に文字列の蓄積を使用することです。 ループ内での印刷でも指定された制約は通過しますが、出力をバッチ処理することで不要なオーバーヘッドが回避されます。 

定数 1000 は、1000 * 1000 + 1 が 1,000,001 に等しいため安全であるため、最大 n の場合でもすべての値が 10^9 の制限内に収まるように選択されています。

 n = 1

 シーケンスには要素が 1 つだけ含まれているため、すべての制約が簡単に満たされます。 可分性チェックは必要ありません。 

これは、構築によって依然として有効な単一要素配列が生成される境界ケースを確認します。 

### 例 2

 入力:

 n = 4

 | 私 | あ_い |
 | --- | --- |
 | 1 | 1001 |
 | 2 | 2001年 |
 | 3 | 3001 |
 | 4 | 4001 |

 各ステップは 1000 ずつ増加します。連続するペアをチェックします。 

2001 / 1001 は整数ではないため、1001 は 2001 を割りません。 

同様に、2001 は 3001 を除算しません。また、3001 は 4001 を除算しません。+1 オフセットが倍数との位置合わせを壊すため、各ペアは割り切れません。 

これは、この構造がシーケンス全体にわたって偶発的な倍数を一貫して回避していることを示しています。

 ## 特殊なケース

 n = 1 の場合、アルゴリズムは単一の値 1001 を生成します。隣接関係の制約がないため、正確性は範囲の有効性のみに依存します。1001 は 10^9 よりもはるかに小さいため、範囲の有効性は満たされます。 

n = 2 の場合、出力は 1001 と 2001 です。2001 を 1001 で割った値は整数ではないため、2 番目は最初の値で割り切れません。 この構造では、両方の数値が 1000 の倍数に対して +1 の固定オフセットを共有し、位置合わせが妨げられるため、これが保証されます。 

n = 1000 など、n が大きい場合、最後の値は 1,000,001 になります。 これは範囲内に留まり、連続するすべてのペアは同じ構造を保持するため、位置に関係なく隣接するペア間で可分性の関係が現れることはありません。
