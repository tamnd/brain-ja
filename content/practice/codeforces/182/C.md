 ## 解決策
 ## 問題の理解

 配列と固定ウィンドウ長があります`len`。 長さのすべての部分配列に対して`len`、その合計を計算し、絶対値を取得します。 配列全体の「最適な合計」は、その固定長のすべてのウィンドウの最大絶対サブ配列合計です。 

答えを評価する前に、配列要素の符号を反転することがあります。 1 回の操作でインデックスを選択し、その値を乗算します。`-1`。 せいぜいパフォーマンスするかもしれません`k`オペレーションの合計。 同じ位置を複数回反転することは許可されますが、2 つの反転は互いに打ち消し合うため、重要なのはパリティのみです。 

タスクは、サイズのすべてのウィンドウの最大絶対和を最大化することです。`len`。 

制約があるため、私たちは慎重に考える必要があります。 配列の長さが次の値に達しました`10^5`したがって、すべてのウィンドウとすべての反転の組み合わせを検査する解決策は不可能です。 平`O(n * k)`両方が大きい場合、すでに実用的な限界に近づいています。 周りに何かが必要です`O(n log n)`またはそれ以上です。 

微妙な点は、ウィンドウ合計の絶対値を最大化していることです。 つまり、ウィンドウを非常にポジティブにするか非常にネガティブにするかは自由です。 ウィンドウ内のすべての要素を反転すると合計の符号が変わるため、正の方向を最大化すると負の方向もカバーされます。 

もう 1 つの微妙な点は、操作はグローバルですが、目的は最終的に 1 つのウィンドウにのみ依存することです。 複数のウィンドウを同時に最適化する必要はありません。 私たちは、可能な限り最高の単一ウィンドウを構築することだけに関心があります。 

次の例を考えてみましょう。```
n = 3, len = 2
a = [5, -100, 5]
k = 1
```最善の動きは反転することです`-100`の中へ`100`、ウィンドウ合計を与える`105`そして`105`。 すべてのウィンドウを個別に改善しようとする貪欲な戦略は、他の場所でフリップを無駄にする可能性があります。 

もう 1 つの簡単な間違いは、パリティの処理を誤ることです。 仮定する：```
n = 2, len = 2
a = [4, 7]
k = 1
```どちらの数字もすでにプラスになっています。 1 つを反転すると合計が減ります`11`どちらかに`3`または`-3`。 _at most_ を使用する可能性があるため、`k`操作、正解はまだです`11`。 正確に想定した不注意な実装`k`反転すると間違った結果が生成されます。 

ウィンドウに含まれる内容が以下の場合、もう 1 つのトラップが表示されます。`k`負の数。```
n = 4, len = 4
a = [-5, 2, 3, 4]
k = 3
```反転します`-5`に`5`、合計を取得`14`。 追加の反転を使用すると、反転するたびに正の数値が負の数値に変化するため、問題が発生するだけです。 

正しい戦略では、ウィンドウ内での反転の最適な使用法は、常に一部の負の値を正に変えることであることを理解する必要があります。 

## アプローチ

 ブルートフォース ソリューションでは、長さのすべてのウィンドウを列挙します。`len`。 各ウィンドウについて、サイズに応じて、反転する位置の可能なすべてのサブセットを試みます。`k`を計算し、結果の最大絶対和を計算します。 

それは直ちには不可能です。 単一のウィンドウにはすでに`2^len`サブセット。 と`len = 10^5`、1 つのウィンドウでもこの方法では処理できません。 

総当たり力をわずかに改善できます。 固定ウィンドウ内で、正の方向を最大化しようとすると、正の値を反転すると常に絶対和が減少します。 したがって、1 つのウィンドウの場合、最適な戦略は明らかです。最も有用な負の数値を反転することです。 

ウィンドウ合計が次のようになると仮定します。```
S = a1 + a2 + ... + alen
```負の数を反転する`-x`合計を変更します`+2x`。 

したがって、ウィンドウ内のすべての負の値を収集し、最大で`k`それらのうち、最大の改善は絶対値が最大のマイナスから得られます。 

この観察によって問題は完全に変わります。 任意の反転サブセットを気にする必要はなくなりました。 各スライディング ウィンドウには次のものが必要です。```
window_sum + 2 * (sum of k largest absolute negative values)
```ここで、課題はスライディング ウィンドウ データ構造の問題になります。 

ウィンドウが移動すると、要素が出入りします。 私たちは次のことを維持する必要があります。 

1. 通常のウィンドウ合計。 
2. の合計`k`現在ウィンドウ内にある負の要素の中で最大の絶対値。 

単純な実装では、ウィンドウごとにネガをソートし、コストがかかります。`O(len log len)`ウィンドウごとに、`O(n * len log len)`全体。 

重要な洞察は、トップのみが必要であるということです`k`ダイナミックにネガティブ。 これは古典的な 2 マルチセット構造です。 

1. 1 つのセットには、現在答えに寄与している選択されたネガが含まれています。 
2. もう一方のセットには残りのネガが含まれます。 

選択されたセットには常に次のものが格納されるという不変条件を維持します。`k`最大の絶対値。 その場合、挿入または削除のたびにコストがかかります`O(log n)`。 

ブルートフォースのアイデアは概念的には残りますが、スライディング ウィンドウでは各ステップで開始要素と終了要素が 1 つだけ更新されるため、高価な再計算はなくなります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n · 2^len) | O(レン) | 遅すぎる |
 | すべてのウィンドウを再並べ替える | O(n · len log len) | O(レン) | 遅すぎる |
 | スライディングウィンドウ + バランスセット | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 現在のウィンドウの通常の合計を維持します。 

ウィンドウがスライドするとき、退出要素を減算し、進入要素を追加します。 
2. 負の値ごとに`x`、そのゲインを次のように定義します`-2x`。 

例: 反転`-7`ウィンドウの合計を変更します`+14`。 
3. 2 つのマルチセットを維持します。 

最初のセットは、`best`、反転用に現在選択されているゲインを保存します。 そのサイズは決して超えられません`k`。 

２セット目は、`rest`、他のすべてのゲインを保存します。 
4. メンテナンス`best_sum`、内部の値の合計`best`。 

現在のウィンドウで達成可能な最良の正の合計は次のようになります。```
current_window_sum + best_sum
```5. 負の要素がウィンドウに入ると、そのゲインを構造に挿入します。 

もし`best`以下より少ない`k`要素がある場合は、そこに直接配置します。 

それ以外の場合は、現在内部にある最小ゲインと比較します。`best`。 

新しいゲインの方が大きい場合は、それらを交換します。 それ以外の場合は、新しいゲインを`rest`。 
6. 負の要素がウィンドウから出ると、その要素が現在含まれているセットからそのゲインを削除します。 

取り外した後、`best`以下より少ない`k`要素と`rest`が空ではない場合、最大のゲインを次から移動します。`rest`の中へ`best`。 
7. ウィンドウが更新されるたびに、以下を計算します。```
abs(current_window_sum + best_sum)
```しかし、ポジティブな方向を最大化するだけですでに十分です。 そのウィンドウ内のすべての記号を概念的に反転することで、ネガティブなターゲットをポジティブなターゲットに変換できます。 したがって、単純に次のものを最大化します。```
current_window_sum + best_sum
```8. すべてのウィンドウの最大値を追跡します。 

### なぜ効果があるのか

 固定ウィンドウの場合、反転されたすべての負の値が独立して寄与します。 反転`-x`合計を増やす`2x`、正の値を反転すると減少します。 したがって、最適な戦略は常に以下を選択することです。`k`絶対値が最大の負の値。 

データ構造は、常に最適な候補を正確に維持します。 不変条件は次のとおりです。```
best contains the k largest gains among all negatives in the current window
```ウィンドウ合計は正確に維持されるため、`best_sum`が最適な反転による合計の改善に等しい場合、計算されたすべての候補はそのウィンドウに対する真の最適値になります。 すべてのウィンドウで最大値を取ると、グローバルな答えが得られます。 

## Python ソリューション```python
import sys
from sortedcontainers import SortedList

input = sys.stdin.readline

def solve():
    n, length = map(int, input().split())
    a = list(map(int, input().split()))
    k = int(input())

    best = SortedList()
    rest = SortedList()

    best_sum = 0

    def add_gain(v):
        nonlocal best_sum

        if k == 0:
            rest.add(v)
            return

        if len(best) < k:
            best.add(v)
            best_sum += v
        else:
            if v > best[0]:
                smallest = best.pop(0)
                best_sum -= smallest
                rest.add(smallest)

                best.add(v)
                best_sum += v
            else:
                rest.add(v)

    def remove_gain(v):
        nonlocal best_sum

        if v in best:
            best.remove(v)
            best_sum -= v

            if rest:
                largest = rest.pop()
                best.add(largest)
                best_sum += largest
        else:
            rest.remove(v)

    window_sum = 0

    for i in range(length):
        window_sum += a[i]
        if a[i] < 0:
            add_gain(-2 * a[i])

    ans = window_sum + best_sum

    for r in range(length, n):
        l = r - length

        window_sum -= a[l]
        if a[l] < 0:
            remove_gain(-2 * a[l])

        window_sum += a[r]
        if a[r] < 0:
            add_gain(-2 * a[r])

        ans = max(ans, window_sum + best_sum)

    print(ans)

solve()
```実装はスライディング ウィンドウ構造に直接に従います。`window_sum`現在の部分配列の通常の合計を追跡します。 それぞれの負の数は、以下に等しい利得をもたらします。`-2 * a[i]`。 その値は常に正です。`a[i] < 0`。 

の`best`multiset は現在選択されているゲインを保存します。 そのサイズは最大でも`k`, and it always contains the largest gains available inside the window.

 The tricky part is maintaining the invariant after deletions. から要素を削除するとき`best`、私たちはより少ない数を残すかもしれません`k`選ばれた利益。 利用可能な最大の利益は、`rest`次に移動する必要があります`best`。 

もう一つの微妙なディテールはハンドリングです`k = 0`。 その場合、`best`永久に空のままにしておく必要があります。 明示的なチェックを行わずにアクセスすると、`best[0]`失敗するだろう。 

Python の整数はすでに任意の精度をサポートしていますが、合計がおおよその値に達する可能性があるため、これは重要です。`10^14`。 

ソリューションでは、`SortedList`から`sortedcontainers`クリーンなバランスの取れたツリー動作を実現します。 すべての挿入、削除、境界検索にはコストがかかります`O(log n)`。

 ## 特殊なケース

 すべての値がすでに正である場合を考えてみましょう。```
2 2
4 7
1
```初期ウィンドウ合計は次のとおりです。`11`。 負のゲインはないため、両方のマルチセットは空のままです。 アルゴリズムの出力`11`。 

これにより、使用する量が以下であることが確認されます。`k`操作が許可されます。 たった 1 回のフリップを強制する間違った解法は、答えを減らすことになります。 

ここで、負の数よりも多くの反転が許可される場合を考えてみましょう。```
4 4
-5 2 3 4
3
```ウィンドウ合計は次から始まります`4`。 

唯一の負の値は、`-5`、利益を生み出す`10`。 

それで：```
candidate = 4 + 10 = 14
```正の数を反転すると合計が減少するため、残りの 2 つの演算は無視されます。 

最後に、構造に出入りする利得が等しいことを考えます。```
5 3
-4 -4 -4 1 1
2
```初期ゲインは`{8, 8, 8}`。 所属するのは2人だけ`best`。 

窓がスライドすると、1`8`葉ともう一つが残ります。 マルチセット構造では、重複が個別に保存されるため、1 つの出現のみが正しく削除されます。 

これにより、すべての等しい値が誤って一緒に消えるという微妙なバグが防止されます。
