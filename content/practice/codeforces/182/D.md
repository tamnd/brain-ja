 ## 解決策
 ## 問題の理解

 2 つの小文字の文字列が与えられます。 文字列`d`別の文字列の約数と呼ばれます`s`もし`s`連結することで形成できます`d`続けて数回。 

例えば、`"ab"`分割する`"ababab"`繰り返しているので`"ab"`3 回実行すると完全な文字列が得られます。 一方で、`"aba"`分けない`"ababab"`なぜなら、それを繰り返しても正確にターゲットを生成することは決してないからです。 

タスクは、両方の入力文字列を同時に分割する文字列の数をカウントすることです。 

文字列の長さは最大でも`10^5`これにより、再構成の繰り返しと組み合わせた高価な部分文字列の生成が即座に排除されます。 近いものなら何でも`O(n^2)`両方の文字列が大きい場合、文字の動作が遅くなりすぎる可能性があります。 数百億回の操作を実行するソリューションは制限時間内に完了しません。 線形に近いものが必要です。`O(n log n)`。 

難しいのは、プレフィックスを一致させるだけでは十分ではないということです。 除数の候補は文字列全体で完全に繰り返される必要があります。 

次の入力を考えてみましょう。```
ababab
abab
```公約数は`"ab"`、 ない`"abab"`。 不注意な実装では、両方の文字列が同じプレフィックスで始まり、誤ってカウントされるかどうかだけをチェックする可能性があります。`"abab"`タイル化できなくても`"ababab"`完全に。 

もう 1 つの簡単な間違いは、候補の長さが文字列全体の長さを分割していない場合に発生します。```
aaa
aa
```唯一の公約数は`"a"`。 

素朴なアプローチで治療できるかもしれない`"aa"`両方の文字列が次で始まるため、有効と見なされます`"aa"`、 しかし`"aa"`生成できません`"aaa"`繰り返しを通して。 

単一文字の文字列も重要です。```
a
a
```答えは`1`、 なぜなら`"a"`両方の文字列を分割します。 

同じ文字数の異なるパターンも、間違った解決策を壊す可能性があります。```
abab
abba
```答えは`0`。 

両方の文字列には同じ文字が含まれていますが、両方を正確に生成する反復ベース文字列はありません。 

## アプローチ

 最も直接的な解決策は、可能なすべての部分文字列を除数の候補として試してみることです。 候補ごとに、それを繰り返すことで両方の文字列が正確に再構築されるかどうかを確認します。 

最初の文字列に長さがあると仮定します`n`そして2番目は長さです`m`。 最悪の場合には、`O(min(n, m))`候補の長さ。 すべての候補について、文字列の再構築と比較にかかるコストは最大で`O(n + m)`。 

それは全体的に複雑になります`O(min(n, m) * (n + m))`。 

近い長さで`10^5`、これはあまりにも高価になります。 最悪の場合の入力には、約`10^10`キャラクター操作。 

重要な点は、有効な約数の長さが両方の文字列長を分割する必要があるということです。 

ある長さの文字列の場合`k`長さの文字列を生成します`n`、 それから`k`分けなければなりません`n`その通り。 したがって、考えられるすべての長さをチェックするのではなく、2 つの長さの公約数をチェックするだけで済みます。 

たとえば、文字列に長さがある場合、`8`そして`16`、可能な約数の長さは次の公約数のみです。`8`そして`16`、つまり`1`、`2`、`4`、 そして`8`。 

そうなると候補者の数は大幅に減ります。 整数の約数の数は少なく、通常、約数の値の場合はせいぜい数百です。`10^5`。 

有効な長さごとに`k`、長さの接頭辞を取得します`k`最初の文字列から抽出し、それを繰り返すことで両方の文字列が再構築されることを確認します。 

検証自体は、反復と等価比較を使用して効率的に行うことができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(min(n,m) × (n+m)) | O(n+m) | 遅すぎる |
 | 最適 | O((n+m) × d) | O(n+m) | 承認済み |

 ここ`d`は文字列の長さの公約数であり、実際には非常に小さくなります。 

## アルゴリズムのチュートリアル

 1. 2 つの入力文字列を読み取ります。 
2. それらの長さを計算します`n`そして`m`。 
3. すべての整数を反復処理します。`k`から`1`に`min(n, m)`。 
4. どれもスキップします`k`それは両方を分割しない`n`そして`m`。 

一定の長さの繰り返しブロック`k`長さが次の倍数である文字列のみを生成できます。`k`。 
5. 最初のものを取る`k`最初の文字列の文字を除数の候補として使用します。 
6. 候補を繰り返して最初の文字列を再構築します。`n // k`回。 
7. 候補を繰り返して 2 番目の文字列を再構築します。`m // k`回。 
8. 再構築された両方の文字列が元の文字列と正確に一致する場合、答えをインクリメントします。 
9. 最終的なカウントを出力します。 

### なぜ効果があるのか

 繰り返しは常に先頭から始まるため、有効な除数文字列はすべて両方の文字列の接頭辞として出現する必要があります。 また、その長さは両方の文字列の長さを正確に分割する必要があります。 

このアルゴリズムは、考えられるすべての公約数の長さをチェックし、対応するプレフィックスが繰り返しを通じて両方の文字列を本当に生成するかどうかを検証します。 すべての約数がこれらの特性を満たす必要があるため、有効な約数を見逃すことはできません。 再構築により両方の元の文字列との正確な等しいことが保証されるため、無効な約数は数えられません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s1 = input().strip()
    s2 = input().strip()

    n = len(s1)
    m = len(s2)

    ans = 0

    for k in range(1, min(n, m) + 1):
        if n % k != 0 or m % k != 0:
            continue

        candidate = s1[:k]

        if candidate * (n // k) == s1 and candidate * (m // k) == s2:
            ans += 1

    print(ans)

solve()
```ループは、考えられるすべての除数の長さをチェックします。 繰り返しブロックではブロック長の倍数でない長さの文字列を生成できないため、割り算条件は必須です。 

約数の候補は常に次の接頭辞から取得されます。`s1`。 有効な除数は文字列の先頭から始まる必要があるため、任意の部分文字列をチェックする必要はありません。 

再構築ステップでは、正確性が強制されます。 2 つの文字列が同じプレフィックスを共有している場合でも、文字列の後半で繰り返されるパターンが失敗する可能性があります。 繰り返される文字列を構築し、元の文字列と比較すると、これらのケースがきれいに検出されます。 

微妙なディテールが 1 つあります。`.strip()`入力を読み取るとき。 これがないと、改行文字が文字列の一部となり、すべての比較が中断されます。 

もう 1 つの簡単な間違いは、両方の文字列を個別にチェックすることを忘れることです。 候補者が分裂する可能性がある`s1`正しくても失敗する`s2`。
