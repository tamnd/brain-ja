 ## 解決策
 ## 問題の理解

 最大 1,000 個の整数の静的配列と複数の独立したクエリが与えられます。 各クエリは、インデックスの個別の 4 倍の数を要求します。$(i, j, k, l)$4 つの対応する値の合計がクエリのターゲットと等しくなるように、厳密に昇順で指定されます。 

構造は重要です。繰り返しによって値を自由に選択しているのではなく、インデックスの 4 倍を選択しています。 これは、異なる位置の同一の値が異なる選択肢として扱われ、合計が一致する場合、4 つの位置のすべての組み合わせが独立して寄与することを意味します。 

制約によってアプローチが決まります。 と$N \le 1000$、4回転の合計数は次のとおりです。$\binom{1000}{4}$、大まかに言うと$4 \times 10^{10}$。 クエリごとに直接列挙することは完全に不可能です。 すべての 4 倍数を一度に列挙するだけでもすでに大きすぎ、最大 4000 クエリを掛け合わせると総当たりは不可能になります。 

値自体は小さく、大きさが 1000 によって制限されているため、ペアの合計は管理可能な範囲内にあり、4 倍の合計はおおよその範囲内にあります。$[-4000, 4000]$。 この制限された出力範囲は、合計に対する事前計算が実行可能である可能性があることを示唆しています。 

すべての数値が同一である場合、微妙な特殊なケースが発生します。 このような場合、多くの 4 倍数は同じ合計を生成し、答えは値の多様性ではなく組み合わせのカウントに完全に依存します。 もう 1 つの特殊なケースは、負の値が存在する場合です。これは、適切なインデックス付けを行わずに素朴なバケット化を試みると、明らかに合計の対称性がゼロを中心にしないためです。 

## アプローチ

 素朴なアプローチは、インデックスの 4 つ組をすべて列挙し、それらの合計を計算し、合計をキーとする度数テーブルをインクリメントすることです。 これは、すべての有効な組み合わせを直接カウントするため、正しいです。 問題はコストです。4 倍の数は$\Theta(N^4)$、約 2,500 億回の操作$N=1000$、制限時間をはるかに超えています。 

実効指数を減らす必要があります。 重要な観察は、4 倍の合計が 2 つのペアの合計に分解できることです。$$A_i + A_j + A_k + A_l = (A_i + A_j) + (A_k + A_l)$$インデックスは個別であり、順序付けされているという制約があります。 すべてのペアの合計を事前に計算すると、問題を 2 つの独立したペアの結合に減らすことができます。 

ただし、注意が必要です。ペアはインデックスを再利用してはなりません。 過剰カウントを回避する標準的な方法は、順序境界を修正することです。つまり、すべてのペアを計算します。$(i, j)$と$i < j$、それらの合計のカウントを保存し、素のインデックス セットが保証される方法でペアを結合します。 これを行うためのきれいな方法は、ペアの合計の頻度マップを作成し、クエリで 2 つのペアの合計が何通りになるかを数えることです。ただし、これは慎重に構築しない限り、ペアがインデックスを共有するケースをカウントしすぎます。 

正しい改良は、最初のペアが終了した後に 2 番目のペアを修正することです。 2 番目のペアの開始インデックスを反復処理し、カウント ロジック内で配列を動的に 2 つの半分に分割することで素性を確保します。 この正確な制約サイズに対する最も標準的な競技プログラミングのトリックは、構築順序によって暗黙的にエンコードされたインデックス制約を使用してすべてのペアの合計を計算し、寄与分を段階的に蓄積することです。 

具体的には、特定のインデックスの前で終了するすべてのペアと、次のインデックスで終了する新しい各ペアのペア合計の実行頻度マップを維持します。$k$、ペアを形成します$(k, l)$そして、それらを補完する以前のペアがいくつあるかを即座にクエリします。 これにより複雑さが軽減され、$O(N^2 + Q)$。

 ## アルゴリズムのチュートリアル

 1. 配列を修正する`A`そして、可能なペアの合計によってインデックス付けされた周波数構造を準備します。 ペアの合計の範囲は -2000 から 2000 であるため、+4000 シフトされた辞書または配列を選択します。 この構造体は、これまでに各合計を生成した有効なインデックスを持つペアの数を格納します。 
2. ペアの 2 番目のインデックスを反復処理し、最初のペアの右エンドポイントとして扱います。 固定ごとに`j`、すべてを考慮します`i < j`そしてペアの合計を計算します`A[i] + A[j]`。 現時点では、厳密に前に終了する以前に確認されたペアと組み合わせたいと考えています。`i`。 
3. 素性を強制するために、2 番目のインデックスが現在のインデックスよりも小さいペアに対してのみ周波数マップを維持します。`i`。 これにより、結合するペアはすべて現在のペアの完全に左側に配置されるため、インデックスが重複することはありません。 
4. 右エンドポイントの昇順でペアを処理します。 新しい要素ごとに`j`、最初にそれを使用して投稿に回答します。`i < j`、合計が次と等しい以前のペアがいくつあるかを調べます。`q - (A[i] + A[j])`そして、クエリターゲットのグローバルマップを介して間接的に各クエリの回答に蓄積されます。 
5. 次のような貢献を処理した後`j`で終わるすべてのペアを挿入します。`j`周波数構造に組み込むことで、将来のペアで使用できるようになります。 この順序によって正確さが保証されます。 
6. クエリは独立していますが多数であるため、ターゲットの合計を 4 倍の数にマッピングする辞書を維持し、有効なペアのペアの組み合わせを生成するときに段階的に更新します。 

### なぜ効果があるのか

 4回転ごと$i < j < k < l$間の中間境界を取ることによって一意に分解されます。$j$そして$k$。 このアルゴリズムでは、次で終わるペアを処理するときに、$j$、以前のすべてのペアは、インデックスが厳密に小さいものを正確に表します。$j$。 これにより、4 つの素の 2 つのペアへの有効な分割がすべて正確に 1 回カウントされることが保証されます。これは、2 番目のペアが処理され、最初のペアが既に構造内に存在する瞬間が 1 回だけ存在するためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    q = int(input())
    queries = [int(input()) for _ in range(q)]

    # coordinate compress query targets into answer map
    ans = {x: 0 for x in queries}

    # frequency of pair sums for pairs with second index < current i
    freq = {}

    # we will build pairs incrementally
    # for each j, we form pairs (i, j) and query against freq
    for j in range(n):
        for i in range(j):
            s = a[i] + a[j]

            # count how many earlier pairs form complement
            for t in ans:
                ans[t] += freq.get(t - s, 0)

        # now insert all pairs ending at j into freq
        for i in range(j):
            s = a[i] + a[j]
            freq[s] = freq.get(s, 0) + 1

    for x in queries:
        print(ans[x])

if __name__ == "__main__":
    solve()
```コア構造は右エンドポイントごとに 2 つのフェーズに分割されます`j`。 まず、で終わるすべてのペアを使用します。`j`以前に保存されたペアの合計を使用して有効な 4 倍数をカウントします。 次に、それらのペアを周波数マップに挿入します。 この順序付けにより、クアドルプルを形成する 2 つのペア間のインデックスの厳密な分離が強制されます。 

クエリ上の内部ループは、より最適化された実装では意図的に回避されていますが、このバージョンではロジックが明示的に保たれています。新しい各ペアは、頻度マップ内の補数を介して関連するすべてのターゲットに寄与します。 

実装の微妙な詳細は、頻度マップには、2 番目のインデックスが新しいペアの最初のインデックスよりも厳密に小さいペアのみを含める必要があるということです。そうしないと、インデックスが再利用され、無効な 4 倍数が過剰にカウントされる危険があります。

 ## 特殊なケース

 すべての値が同一である配列の場合、すべての 4 倍が 1 つの合計に等しく寄与します。 すべてのペアの合計が同一であり、頻度マップはインデックスを誤って区別することなく組み合わせカウントを蓄積するため、アルゴリズムはこれを自然に処理します。 

正の値と負の値が混在する配列の場合、ペアの合計が異なるインデックス ペア間で重なり合う可能性があります。 このアルゴリズムは、合計の一意性には依存せず、頻度マップの構築順序によって強制される正しい素のインデックス付けのみに依存するため、引き続き機能します。
