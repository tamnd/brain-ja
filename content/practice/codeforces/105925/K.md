 ## 解決策
 ## 問題の理解

 位置間の順序制約を定義するシーケンスと、各位置に重みを割り当てる別のシーケンスが与えられます。 これから、インデックスの順序と最初のシーケンスの値の両方が厳密に増加しているインデックスのすべての可能なサブシーケンスを考慮します。 すべての有効なサブシーケンスは 2 番目の配列から重みを収集し、合計を生成します。 このような合計をすべて収集すると、非常に大きなマルチセットが形成され、そこから K 個の最大値を非増加順に出力するか、K 未満の場合は -1 を出力するように求められます。 

重要な構造は、サブシーケンスが 2 つの同時増加条件に従う場合にのみ有効であるということです。 1 つは配列内で左から右に移動することによって発生し、もう 1 つは順列で値を増加させることによって発生します。 これにより、有効なサブシーケンスは、まさに 2 次元の部分順序で増加するチェーンになります。 

この制約は、すべてのサブシーケンスを直接列挙することが不可能であることを意味します。 N が中程度の場合でも、有効な増加サブシーケンスの数は指数関数的に増加する可能性があります。 すべてを明示的にリストしたり、カウントしたりしようとするソリューションは、すぐに失敗します。 成功するアプローチは、代わりにサブシーケンスのセットの圧縮表現を使用し、上位 K 個の結果のみを抽出する必要があります。 

順列がすでに値でソートされている場合、微妙なエッジケースが発生します。 その場合、インデックスのすべてのサブシーケンスが有効になるため、問題は重み配列のすべてのサブセットの合計を計算することに縮退します。 これは 2^N の値を生成し、単純な列挙は明らかに不可能ですが、正しい解は最も単純な構造であっても指数関数的分岐を暗黙的に処理する必要があることを示しているため、これは重要です。 

もう 1 つの特殊なケースは、K が有効なサブシーケンスの数を超える場合です。 出力には -1 の値を埋め込む必要があるため、アルゴリズムは生成された合計の枯渇をカウントまたは検出する必要があります。 

## アプローチ

 最も直接的なアイデアは、サブセットに対する深さ優先検索または動的プログラミングを使用して、すべての有効な増加サブシーケンスを生成し、それらの合計を累積することです。 これは、すべてのチェーンを明示的に構築し、その重みの合計を計算するため、原理的には正しいです。 ただし、各要素は含めることも除外することもでき、有効性は順序付けの制約に依存するため、状態の数は指数関数的に増加します。 最悪の場合、順列がソートされると 2^N 個の部分列に縮退し、N が小さい場合でも列挙が不可能になります。 

重要な観察は、すべての有効なサブシーケンスが、各ノードがインデックスを表す有向非巡回グラフ内のパスとして見なすことができ、i < j および A[i] < A[j] の場合、i から j へのエッジが存在することです。 すべてのサブシーケンスの合計は、この DAG 内のパスに沿ったノードの重みの合計となります。 問題は、正のノード重みを持つ DAG 内で K 個の最大パス合計を見つけることになります。 

この構造により、各ノードについて、そのノードで終わる最適な部分列合計のリストを維持する動的プログラミングが可能になります。 ノード j で終了するサブシーケンスは、j に到達できる以前のノード i で終了するサブシーケンスを拡張することによって形成できます。 これは、すべての有効な先行者からの候補リストをマージすることを提案します。 課題は、各ノードに多数の先行ノードがあり、各ノードが最大 K 個の部分和のリストを保持することです。 

これを効率的にするために、順列の値次元にわたるデータ構造を使用して先行集計を圧縮します。 A は順列であるため、値を 2 番目の座標として扱い、ノードを昇順に処理して、より小さい A 値を持つ以前のすべての状態のクエリをサポートする構造を維持できます。 各構造エントリには最良の合計の制限されたリストが格納され、2 つのリストのマージは、要素と現在の重みを組み合わせた最大の K 個の結果を取得することによって行われます。

これにより、指数関数的な列挙が削減され、構造化されたプレフィックスを介した制御された K ウェイ マージが行われ、各状態は最も関連性の高い K 個の候補のみを保持します。

 ## アルゴリズムのチュートリアル

 サブシーケンスの有効性はインデックスと値の増加の両方に依存し、値の順序を固定することで有効なチェーンのみを拡張できるため、順列では値の昇順で要素を処理します。 

1. A の各値をその位置にマップします。これにより、元の配列のどこに出現するかを把握しながら、1 から N までの値を処理できます。 これにより、問題は値によって順序付けされたシーケンスに取り組むことになり、遷移では位置の増加も考慮する必要があります。 
2. ポジション全体にわたってフェンウィック ツリーまたはセグメント ツリーを維持します。 各位置には、その位置で終了する最大 K 個の最良のサブシーケンス和のリストが保存されます。 単一の要素は常に、それ自体のみで構成される基本サブシーケンスに寄与するため、すべての位置は独自の重みで始まります。 
3. 値 v ごとに昇順で、元の配列内のその位置 p を見つけます。 p まで拡張できるすべての部分列が必要です。これは、値が以前に処理された q < p のすべての位置に対応します。 プレフィックス範囲 [1, p−1] でフェンウィック ツリーをクエリし、候補合計のマージされたリストを取得します。 
4. このマージされたリストから、p での重みを各候補合計に加算することによって、p で終わる新しいサブシーケンスを構築します。 p のみからなる単一要素部分列も含めます。 
5. 生成されたすべての合計を位置 p の最終リストにマージし、K 個の最大値のみを保持します。 グローバルの上位 K の結果に寄与できるのは州ごとの上位 K のみであるため、この切り捨ては不可欠です。 
6. このリストをフェンウィック ツリーの位置 p に挿入し直し、後の要素でこれらのサブシーケンスを拡張できるようにします。 
7. すべての位置を処理した後、保存されているすべてのリストを収集し、全体で K 個の最大値を抽出します。 存在するエントリが K より少ない場合は、残りのエントリを -1 で埋めます。 

正確さは、位置を処理した後、構造体がその位置で終わる K 個の最大の有効なサブシーケンスの合計を正確に格納するという不変式に依存します。 グローバル上位 K の答えに寄与するサブシーケンスは、ある位置で終了する必要があり、その位置が処理されるとすぐにすべての拡張が形成されるため、その最良の拡張が保持されることが保証されます。 すべての遷移ではインデックスの増加と値の増加の両方が考慮されるため、有効なサブシーケンスが失われることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [[] for _ in range(n + 1)]

    def merge_lists(self, a, b, k):
        # merge two sorted descending lists, keep top k
        res = []
        i = j = 0
        while len(res) < k:
            va = a[i] if i < len(a) else None
            vb = b[j] if j < len(b) else None
            if va is None and vb is None:
                break
            if vb is None or (va is not None and va > vb):
                res.append(va)
                i += 1
            else:
                res.append(vb)
                j += 1
        return res

    def query(self, idx, k):
        res = []
        while idx > 0:
            res = self.merge_lists(res, self.bit[idx], k)
            idx -= idx & -idx
        return res

    def update(self, idx, values, k):
        while idx <= self.n:
            self.bit[idx] = self.merge_lists(self.bit[idx], values, k)
            idx += idx & -idx

def main():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    pos = [0] * (n + 1)
    for i, v in enumerate(a):
        pos[v] = i + 1

    fw = Fenwick(n)
    all_vals = []

    for v in range(1, n + 1):
        p = pos[v]
        best_prev = fw.query(p - 1, k)

        cur = [b[p - 1]]
        for x in best_prev:
            cur.append(x + b[p - 1])

        cur.sort(reverse=True)
        if len(cur) > k:
            cur = cur[:k]

        fw.update(p, cur, k)
        all_vals.extend(cur)

    all_vals.sort(reverse=True)
    for i in range(k):
        if i < len(all_vals):
            print(all_vals[i], end=" ")
        else:
            print(-1, end=" ")
    print()

if __name__ == "__main__":
    main()
```この実装では、まず順列を位置マップに変換して、値の順序が処理順序になるようにします。 フェンウィック ツリーは、各インデックスに、その領域で終わる最良のサブシーケンス合計の圧縮リストを格納します。 各クエリは以前の位置からすべての拡張可能なサブシーケンスを収集し、更新ごとに新しく形成されたサブシーケンスを前方に伝播します。 

実装の重要な詳細は、マージのたびにリストがサイズ K に切り詰められることです。 これがないと、中間リストが急激に増大し、パフォーマンスが破壊されてしまいます。 もう 1 つの微妙な点は、すべての拡張機能が現在のノードの重みを明示的に追加し、サブシーケンスが常に再計算ではなく累積によって構築されるようにすることです。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N · K log N) | N 個の位置のそれぞれがフェンウィックのクエリと更新を実行し、それぞれが最大 K サイズのリストにマージされます。 
| スペース | O(N・K) | 各 Fenwick ノードは最大 K 個の最良の部分和を保存します。

 ## 特殊なケース

 重要なエッジ ケースは、順列が値によって厳密に増加する場合です。 この場合、すべてのサブシーケンスは有効であり、アルゴリズムは効果的にすべてのサブセットの合計を生成します。 すべてのプレフィックス クエリが以前に確認されたすべての組み合わせを返し、すべての更新が拡張合計を前方に正しく伝播するため、Fenwick 構造は引き続き機能します。 

もう 1 つのエッジ ケースは、順列が値によって厳密に減少している場合です。 ここでは、値の制約を満たすことができないため、1 を超える長さのサブシーケンスは有効ではありません。 各位置はそのシングルトンの重みにのみ寄与し、出力は個々の B 値のソートされたリストになります。 

最後に、K が有効なサブシーケンスの総数を超えると、アルゴリズムは生成された合計をすべて使い果たし、残りを -1 で埋めます。 これは、存在する値が K 未満の場合、最終収集中に自然に処理されます。
