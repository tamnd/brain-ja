 ## 解決策
 ## 問題の理解

 各ノードがシステムの状態を表し、親から子への各エッジが小文字でラベル付けされているルート付きツリーが与えられます。 すべてのノードについて、ルートから開始してそのノードまでの一意のパスに沿ってエッジ ラベルを連結することで文字列を読み取ることができます。 

このようなルートからノードへの文字列ごとに、非常に特殊な意味でその最小周期性を計算する必要があります。 より小さい文字列を少なくとも 2 回繰り返すことによって文字列を構築できる場合、その文字列は周期的であるとみなされます。 ブロックの繰り返しコピーとして文字列を表現するすべての可能な方法の中で、可能な限り短いブロック長が必要です。 文字列をより小さい空でない文字列の繰り返しとして書き込むことができない場合、その周期はゼロとして定義されます。 ルートは空の文字列に対応し、これも周期性が 0 です。 

タスクは、すべてのノードに対してこの値を計算し、ツリー全体の最大周期を出力することです。 

重要な制約は、ツリーが最大約 100,000 ノードまで大きくなる可能性があることです。 これにより、各ノードの完全な文字列を再計算したり、すべてのノードの長さのすべての約数を試すような単純な周期性チェックを実行したりすることは直ちに除外されます。これは、最悪の場合、二次関数の動作につながるためです。 ノード間の合計パス長は 2 次になる可能性があるため、すべての文字列を明示的に格納することさえ不可能です。 

文字列に繰り返し構造がまったくない場合、微妙な特殊なケースが発生します。 たとえば、「b」のような単一文字の場合、有効な小さい反復ブロックは存在しないため、答えはゼロになります。 もう 1 つの特殊なケースは、繰り返しは存在するが正確ではない場合です。 たとえば、「baba」は「ba」が 2 回繰り返されるため有効ですが、「babaa」は、たとえ部分文字列の繰り返しが含まれていても周期的ではありません。 

もう 1 つの重要なコーナーはルートです。その文字列は空であり、周期性 0 として個別に処理する必要があります。 

## アプローチ

 直接的なアプローチは、ルートからたどってすべてのノードの文字列を構築し、プレフィックス関数や Z アルゴリズムなどの古典的な文字列メソッドを使用してその周期性をテストすることです。 これにより、各ノードの周期が正しく計算されますが、各文字列の構築には、ツリーの高さのノードごとに線形時間がかかります。 チェーン形状のツリーでは、文字列を構築するだけで O(n^2) になり、すべての周期性チェックではさらに O(n^2) になり、これでは遅すぎます。 

重要な観察は、周期性がプレフィックス構造に完全に依存しており、ツリーに沿って段階的に維持できることです。 ノードに完全な文字列がある場合、そのプレフィックス関数値 π[n−1] を計算でき、候補期間の長さは n − π[n−1] となります。 これにより、周期性検出の問題は、ツリー パスに沿ってプレフィックス関数値を動的に維持することに軽減されます。 

難しいのは、ツリーが分岐している間に接頭関数が線形シーケンスに対して定義されていることです。 ただし、ルートからノードへの各パスは独立しているため、現在のパスに沿ってプレフィックス機能の状態を維持しながら、ルートから DFS をシミュレートできます。 c というラベルの付いたエッジを下に行くと、親の以前の状態を使用して、KMP とまったく同じようにプレフィックス関数の状態を更新します。 バックトラックすると、前の状態が復元されます。 

これにより、ツリー問題は、各ノードが親のオートマトンの状態を継承し、文字あたり O(1) の償却時間で更新するトラバーサルに変わります。 ノードの π が得られると、その最小周期の計算は定数時間の算術チェックになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 文字列の再構築 + ノードごとの再計算 | O(n^2) | O(n^2) | 遅すぎる |
 | ローリング プレフィックス機能を備えた DFS | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 DFS を使用して、ルートからノードへのすべてのパスに沿った KMP プレフィックス関数の構築をシミュレートします。

1. ノード 1 でツリーをルートします。ルートには空の文字列があるため、プレフィックス関数の値は 0 で、周期性は 0 です。このノードから π 値 0 で DFS を開始します。 
2. DFS 中に、c というラベルの付いたエッジを介してノード u から子 v に移動するときに、u の KMP 状態を拡張することによって v のプレフィックス関数値を計算します。 文字一致条件が成立する位置が見つかるまで、保存されているプレフィックス値を使用してフォールバックを繰り返し、その後 1 つ拡張します。 これは古典的なプレフィックス関数の更新を反映していますが、開始点として親の状態を使用します。 
3. 深さ L の各ノード v について、そのプレフィックス関数値 π[v] が判明したら、最小の候補期間を L − π[v] として計算します。 これは、π[v] が文字列の最長の境界を与えるという標準的な解釈から導き出されます。 
4. この候補が実際に繰り返しを形成するかどうかを検証します。 L % (L − π[v]) がゼロに等しく、L − π[v] が厳密に L より小さい場合、文字列は長さ L − π[v] の繰り返しブロックで構成されます。 それ以外の場合、文字列には有効な繰り返しがなく、その周期は 0 になります。 
5. DFS トラバーサル中にすべてのノードにわたる最大周期性を追跡します。 

### なぜ効果があるのか

 各ノードのプレフィックス関数は、サフィックスでもあるパス文字列の最も長い適切なプレフィックスを取得します。 これは、文字列をそれ自体と位置合わせできる最小のシフトを直接定義します。 文字列が繰り返しブロックで構成されている場合、その構造により大きな境界が強制され、文字列の長さとこの境界の長さの差が繰り返し単位に正確に対応します。 DFS は、KMP が線形文字列に対して行うのとまったく同じようにプレフィックス関数の状態を保持するため、すべてのノードは文字列を再構築することなく正しい境界情報を受け取ります。 これにより、π から導出される周期性の計算がすべてのパスに対して正しいことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n = int(input())
p = list(map(int, input().split()))
s = input().strip()

children = [[] for _ in range(n)]
for i in range(n - 1):
    parent = p[i] - 1
    child = i + 1
    children[parent].append((child, s[i]))

depth = [0] * n
pi = [0] * n

ans = 0

def dfs(u, cur_pi, cur_depth, path_chars):
    global ans
    depth[u] = cur_depth
    pi[u] = cur_pi

    if cur_depth > 0:
        length = cur_depth
        period = length - cur_pi
        if period > 0 and length % period == 0 and period < length:
            ans = max(ans, period)

        j = cur_pi
        while j > 0 and path_chars[j] != c:
            j = path_chars[j - 1]

            new_pi = 0 if c == '' else 0

            while k > 0:
                # we don't have full string, so we emulate fallback via stored structure
                break

        # (we instead store actual characters along path)

```意図したソリューションは、DFS パスに沿ってプレフィックス機能の状態を維持することに依存しています。 主要な実装アイデアは、完全な文字列を保存する代わりに、現在の π 値を保持し、それを使用して、KMP 拡張と同じロジックを使用して償却定数時間で次の π を計算することです。 

実際には、クリーンな実装では、現在のパス文字列を表す別の配列と、そのパスのプレフィックス関数配列が保持されます。 さらに深く進むたびに、標準の KMP 遷移ルール​​を使用して新しいノードの π を計算し、それを追加します。 バックトラックするときは、両方の配列をポップします。 これにより、何も最初から再計算する必要がなくなり、正確さが保証されます。 

主な微妙な点は、グローバル ツリー構造ではなく、現在のパスからの情報のみを使用して π が計算されるようにすることです。 各 DFS ブランチは独立している必要があります。 

## 実用的な例

 単純なチェーン: root → a → b → a → b を考えてみましょう。 文字列は「」、「a」、「ab」、「aba」、「abab」です。 

| ノード | 文字列 | π値 | 長さ | 期間候補 | 有効？ | 答え |
 | --- | --- | --- | --- | --- | --- | --- |
 | 1 | "" | 0 | 0 | - | - | 0 |
 | 2 | "a" | 0 | 1 | 1 | いいえ | 0 |
 | 3 | "アブ" | 0 | 2 | 2 | いいえ | 0 |
 | 4 | 「アバ」 | 1 | 3 | 2 | いいえ | 0 |
 | 5 | 「アバブ」 | 2 | 4 | 2 | はい | 2 |

 これは、完全に繰り返される構造だけが答えにどのように寄与するかを示しています。 

ここで、ルートからのすべてのエッジが異なる文字である星形のツリーを考えてみましょう。 すべてのノードには 1 文字の文字列があります。 すべての π 値はゼロであり、すべての周期性もゼロであるため、答えはゼロです。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input())
    p = list(map(int, input().split()))
    s = input().strip()

    children = [[] for _ in range(n)]
    for i in range(n - 1):
        children[p[i] - 1].append((i + 1, s[i]))

    pi = [0] * n
    depth = [0] * n
    ans = 0

    sys.setrecursionlimit(10**7)

    def dfs(u, cur_pi, cur_depth, path):
        nonlocal ans
        depth[u] = cur_depth
        pi[u] = cur_pi

        if cur_depth > 0:
            period = cur_depth - cur_pi
            if period > 0 and cur_depth % period == 0 and period < cur_depth:
                ans = max(ans, period)

        for v, c in children[u]:
            k = cur_pi
            while k > 0 and path[k] != c:
                k = pi[k - 1]
            if k < len(path) and path[k] == c:
                new_pi = k + 1
            else:
                new_pi = 0

            path.append(c)
            dfs(v, new_pi, cur_depth + 1, path)
            path.pop()

    dfs(0, 0, 0, [])
    return str(ans)

## 特殊なケース

 唯一のノードがルートであり、「a」というラベルが付けられた 1 つの子を持つ単一のエッジ ツリーの場合、子の文字列は「a」になります。 DFS は π を 0 に初期化し、長さが 1 であるため、周期性チェックはすぐに失敗し、0 が生成されます。これにより、単一文字の文字列は周期としてカウントされないことが確認されます。 

チェーン「aaaaaa」の場合、拡張するたびに π が増加し続けます。 最後のノードでは、長さ 6 に対して π が 5 になり、周期 1 が得られます。6 は 1 で割り切れるので、答えは 1 になります。各ステップが最初から再計算するのではなく、前の KMP 状態を拡張するため、DFS はこれを正しく累積します。 

「abcabd」のような非反復的な交互文字列の場合、π は除数の一貫した期間を作成できるほど大きくなることはありません。そのため、おそらく中間のプレフィックスを除くすべてのノードの寄与はゼロになります。 これは、アルゴリズムが完全な周期構造に及ばない部分的な境界を過剰にカウントしていないことを示しています。
