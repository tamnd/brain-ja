 ## 解決策
 ## 問題の理解

 長さの時間間隔が与えられています$T$そして毎秒ちょうど 1 つのセンサーがアクティブでなければなりません。 各センサーはセンサーと時間の両方に依存する値を生成するため、センサーをアクティブにすると$i$時に$j$貢献する$c(i, j)$合計スコアに。 

ただし、センサーを任意に切り替えることはできません。 センサーがオンになると、次の期間の連続した時間ブロックの間アクティブな状態を維持する必要があります。$L$そして$U$、包括的。 そのブロックが終了した後、別のセンサーに切り替えて新しいブロックを開始し、間隔全体が終了するまで継続します。$[1, T]$正確にカバーされています。 

タスクは、タイムラインを連続したセグメントに分割することです。各セグメントの長さは$[L, U]$、各セグメントに正確に 1 つのセンサーを割り当て、すべてのタイム ステップにわたる寄与の合計を最大化します。 

入力サイズが時間的に小さい ($T \le 100$）しかしセンサーが大きい（$N \le 5000$）。 この非対称性が鍵です。つまり、二次関数や三次関数さえも処理できるのです。$T$ただし、構造を持たずに時間ごとの DP 内のすべてのセンサーを繰り返し反復するものは、慎重に最適化する必要があります。 特に、セグメントごとにすべてのセンサーを単純に試すソリューションは、次のようになります。$O(NT^2)$これは境界線にありますが、内部の各計算が単純で適切に構造化されている場合にはまだ実現可能です。 

よくある失敗例は、将来の実現可能性を考慮せず、セグメントごとに貪欲な選択を想定することです。 たとえば、最初のセグメントに最適なセンサーを選択すると、残りの長さの制約を満たすことができないセグメンテーションが強制される可能性があります。 

貪欲さが精神的に失敗するこの小さな例を考えてみましょう。 仮定する$T=5$、$L=2$、$U=3$。 1 つのセンサーが優れている場合$[1,2]$しかし、その後はひどいもので、もう1つは初期はわずかに悪化しましたが、その後は素晴らしかったです$[3,5]$、ローカルで最適な初期セグメントを選択すると、より適切なグローバル パーティションがブロックされる可能性があります。 セグメントの長さによって残りのタイムラインの分解方法が制限されるため、この構造は本質的にグローバルです。 

もう 1 つの微妙な問題は、各セグメントの最適なセンサーが正確な間隔に依存することです。$[l, r]$、長さだけではありません。 したがって、長さごとに単一の最適なセンサーを事前に計算することはできません。 時間依存のスコアを考慮する必要があります。 

## アプローチ

 ブルートフォース手法では、タイムラインを有効なセグメントに分割し、各セグメントにセンサーを割り当てるためにあらゆる方法が試行されます。 指数関数的に多くのパーティションが存在します$T$パーティションを修正したとしても、セグメントごとに最適なセンサーを割り当てるには、すべてのセンサーをチェックする必要があります。$N$セグメント範囲にわたるセンサー。 おおよそで$O(N)$セグメントごとに、そして指数関数的に多くのセグメンテーションを行うと、これでは遅すぎます。 

重要な観察は、構造が純粋に 1 次元でセグメントベースであるということです。 セグメントが決定されると、$[l, r]$、そのセグメントに最適なセンサーの選択は、他のすべてのセグメントから独立しています。 これにより、センサーの選択がセグメンテーションから切り離されます。間隔ごとに、達成可能な最良のスコアを事前に計算できます。 

これにより、問題は古典的な区間動的計画法の問題に変わります。 間隔ごとに最高のスコアを計算します$[l, r]$次に、各状態が変化する時間の経過とともに DP を実行します。$dp[t]$プレフィックスを正確にカバーする達成可能な最大スコアを表します$[1, t]$。 トランジションでは、すべての有効なセグメント長が試行されます。 

主な最適化は、センサーごとのプレフィックス合計を使用して間隔の最適値を事前計算することで、間隔のスコアリングが制約内に収まるほど高速になるようにします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | パーティションに対するブルート フォース | 指数 | お(1) | 遅すぎる |
 | 事前計算を使用した間隔 DP |$O(NT^2 + TU)$|$O(NT)$| 承認済み |

 ## アルゴリズムのチュートリアル

 ### ステップ 1: センサーごとのプレフィックス合計を事前計算する

 センサーごとに$i$、時間の経過とともにプレフィックス合計配列を構築して、次の合計を計算できるようにします。$c(i, l) + \dots + c(i, r)$一定時間内に。 これにより、区間評価がセグメント長の線形から次のように変換されます。$O(1)$。 

### ステップ 2: すべての間隔で最適なセンサーを計算する

 インターバルごとに$[l, r]$、最適なセンサーを選択することで達成可能な最大スコアを計算します。$$best[l][r] = \max_i \sum_{j=l}^{r} c(i, j)$$このステップは費用がかかりますが、実行可能です。$T \le 100$, したがって、間隔は最大 10,000 です。 間隔ごとにすべてをスキャンします$N$センサー。 

### ステップ 3: DP を初期化する

 私たちは定義します$dp[t]$最初の部分を正確にカバーする最大スコアとして$t$秒。 設定しました$dp[0] = 0$他のすべての状態は最初は到達できないため、負の無限大になります。 

### ステップ 4: セグメント末尾のトランジション

 各エンドポイントについて$t$、有効なセグメント長をすべて試します$len \in [L, U]$。 セグメントは次のように始まります$t-len+1$。 その開始が有効な場合は、以下を更新します。$$dp[t] = \max(dp[t], dp[t-len] + best[t-len+1][t])$$これにより、すべてのセグメントが継続時間の制約を遵守するようになります。 

### ステップ 5: 結果を出力する

 答えは$dp[T]$。 到達できないままの場合は、次のように出力します。$-1$。 

### なぜ効果があるのか

 DP 状態は、タイムラインを有効な独立したセグメントに分割します。 すべての有効な完全な割り当ては、正確に 1 つの DP 遷移シーケンスに対応し、すべての DP 遷移は、最適に選択されたセンサーを備えた有効なセグメントに対応します。 プレフィックス DP により、セグメントの重複やギャップがないことが保証され、一方、間隔の事前計算により、各セグメント内で他の選択肢とは関係なく常に最良のセンサーが選択されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

NEG = -10**18

N, T = map(int, input().split())
c = [list(map(int, input().split())) for _ in range(N)]
L, U = map(int, input().split())

# prefix sums per sensor
pref = [[0] * (T + 1) for _ in range(N)]
for i in range(N):
    for j in range(1, T + 1):
        pref[i][j] = pref[i][j - 1] + c[i][j - 1]

def get_sum(i, l, r):
    return pref[i][r] - pref[i][l - 1]

# best[l][r] = best sensor sum for interval
best = [[NEG] * (T + 1) for _ in range(T + 1)]

for l in range(1, T + 1):
    for r in range(l, T + 1):
        best_val = NEG
        for i in range(N):
            best_val = max(best_val, get_sum(i, l, r))
        best[l][r] = best_val

dp = [NEG] * (T + 1)
dp[0] = 0

for t in range(1, T + 1):
    for length in range(L, U + 1):
        if t - length < 0:
            continue
        l = t - length + 1
        if best[l][t] == NEG:
            continue
        dp[t] = max(dp[t], dp[t - length] + best[l][t])

print(dp[T] if dp[T] > NEG // 2 else -1)
```プレフィックスの合計がなければ、各間隔の評価にコストがかかるため、プレフィックスの合計は不可欠です。$O(T)$、完全な事前計算を行う$O(NT^3)$、これは不要です。 

DP ループはセグメント境界を注意深く尊重します。 条件$t - length \ge 0$無効なプレフィックスを防止し、$NEG$決して不可能な状態を拡張しないことを保証します。

```まず、間隔の最適値を暗黙的に計算します。 次に、DP は次のように続けます。 

| t | 選択したセグメント | 付加価値 | dp[t] |
 | --- | --- | --- | --- |
 | 0 | - | - | 0 |
 | 1 | [1,1] | 最適な単一センサー = 2 | 2 |
 | 2 | [1,2] | 最良の間隔 = 5 | 5 |
 | 3 | [1,3] | 最良の間隔 = 7 | 7 |
 | 4 | [1,4] | 最適な間隔 = 8 | 8 |
 | 5 | [1,5] | 最良の間隔 = 11 | 11 |

 これは制約のないケースを示しています$L=1, U=5$すべてをカバーする 1 つのセグメントに折りたたまれます。 

### 例 2

 入力:```
3 5
2 3 2 1 2
1 1 5 1 2
1 2 2 1 5
2 3
```各セグメントの長さは 2 または 3 でなければなりません。 

| t | セグメントの選択 | dp[t] |
 | --- | --- | --- |
 | 0 | - | 0 |
 | 2 | [1,2] | 最高 = 5 → 5 |
 | 3 | [1,3] | ベスト = 7 → 7 |
 | 4 | [2,4] または [1,2]+[3,4] のベストコンボ | 8 |
 | 5 | 有効な分割のみ | 10 |

 これは、DP がセグメントごとに最適なセンサーを選択しながら、有効なセグメント長を強制する方法を示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(NT^2 + TU)$|$O(NT^2)$すべての間隔の最適値を計算するには、$O(TU)$DP トランジション |
 | スペース |$O(NT + T^2)$| 各センサーのプレフィックス合計と間隔テーブルおよび DP 配列 |

 と$N \le 5000$そして$T \le 100$、間隔カウントは 10,000 のみなので、$N$スキャンは受け入れ可能です。 それに比べれば、DP 部分は無視できます。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    NEG = -10**18
    N, T = map(int, input().split())
    c = [list(map(int, input().split())) for _ in range(N)]
    L, U = map(int, input().split())

    pref = [[0] * (T + 1) for _ in range(N)]
    for i in range(N):
        for j in range(1, T + 1):
            pref[i][j] = pref[i][j - 1] + c[i][j - 1]

    def get_sum(i, l, r):
        return pref[i][r] - pref[i][l - 1]

    best = [[NEG] * (T + 1) for _ in range(T + 1)]
    for l in range(1, T + 1):
        for r in range(l, T + 1):
            best[l][r] = max(get_sum(i, l, r) for i in range(N))

    dp = [NEG] * (T + 1)
    dp[0] = 0

    for t in range(1, T + 1):
        for length in range(L, U + 1):
            if t - length >= 0:
                l = t - length + 1
                dp[t] = max(dp[t], dp[t - length] + best[l][t])

    return str(dp[T] if dp[T] > NEG // 2 else -1)

 ## 特殊なケース

 厳しい制約のエッジケースは、次のような場合に発生します。$L = U$、すべてのセグメントが同じ長さになるように強制します。 その状況では、DP には状態ごとに有効な遷移が 1 つだけ存在し、不正な間隔インデックス付けが行われると、直ちに実現可能性が損なわれます。 ループオーバーのため、アルゴリズムはまだ機能します。`length`単一の固定ステップに縮退し、曖昧さなしにすべての状態に到達できるか到達できないかのどちらかになります。 

別のエッジケースが発生するのは次の場合です。$T$有効なセグメント長に分解できません。 例えば、$T=5$、$L=2$、$U=4$。 2 ～ 4 の長さのセグメントの合計が 5 になることはありません。そのため、次を除くすべての DP 状態が維持されます。$dp[0]$到達できないままです。 アルゴリズムは正しく出力します$-1$到達可能な状態からのすべての遷移が正確にカバーできないため$T$。
