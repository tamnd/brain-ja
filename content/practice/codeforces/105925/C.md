 ## 解決策
 ## 問題の理解

 N 量子ビット システムで動作する一連の可逆論理ゲートとして記述される量子回路が与えられます。 各ゲートは CNOT または CCNOT のいずれかです。 この回路は、サイズのすべての基底状態に基づいて変換を定義します。$2^N$、この変換は次のように表すことができます。$2^N \times 2^N$バイナリ行列。 私たちのタスクは、すべてのゲートを順番に適用した後、この完全な行列を構築することです。 

基底状態は、N ビットの 2 進数に対応します。 回路が入力状態 j を出力状態 i にマップする場合、行 i と列 j の行列エントリは 1、それ以外の場合は 0 になります。 すべてのゲートは可逆であるため、行列の各列には 1 が 1 つだけ含まれ、各行にも 1 が 1 つだけ含まれます。量子ゲート用語で表現されていますが、これは順列行列です。 

各ゲートは、特定の制御条件が満たされた場合にターゲット ビットを反転することによって状態を変更します。 CNOT は、制御ビットが 1 の場合、1 つのターゲット ビットを反転します。CCNOT は、両方の制御ビットが 1 の場合、ターゲット ビットを反転します。重要な点は、ゲートがインデックスのビット表現に直接作用することです。 

制約は非常に小さいです。$N \le 8$、 それで$2^N \le 256$。 完全な行列を明示的に構築し、すべての遷移をシミュレートしたとしても、状態空間は非常に小さいです。 ゲートの数も適度であるため、すべての状態に各ゲートを適用するアプローチは十分に高速です。 これにより、漸近最適化に関する懸念がすぐに排除され、問題は慎重なシミュレーションに移行します。 

主な微妙な点は、ビット順序の解釈です。 このステートメントでは、量子ビット インデックスがビット位置に対応し、最下位ビットが例と一貫して扱われる (Qiskit スタイルのインデックス付けと同様) という規則が使用されています。 ビットの順序を誤って解釈する単純な実装では、構造的にはまだ有効であるが正しくない、並べ替えられた行列が生成されます。 

エッジケースは主にビット操作の正しさに関するものです。 

最初の失敗ケースは、ビットの重要度の交換です。 間違ったビット順序を仮定すると、単純な 1 ゲート回路はすでに壊れてしまいます。 

入力：```
2 1
1 0 1
```正しい動作は、状態 |01⟩ と |11⟩ を反転する順列です。 逆ビット解釈では、代わりに異なるペアを反転して、異なる行列を生成します。 

2 番目の失敗例は、CCNOT が 2 つのコントロールの XOR や OR ではなく AND を使用することを忘れていることです。 間違ったブール条件があると、一見有効に見える置換行列が生成されますが、それでも間違っています。 

状態空間は小さく決定論的であるため、問題全体は、回路によって誘発される順列を構築し、それを行列形式に拡張することに帰着します。 

## アプローチ

 この強引なアイデアは、各列を個別にシミュレートすることによって完全な行列を最初から構築することです。 考えられるすべての入力状態 j について、回路がそれを出力状態 i にどのように変換するかをシミュレートします。 次に、matrix[i][j] = 1 を設定します。$2^N$状態ごとに M 個のゲートをシミュレートし、各ゲートが順番に適用されるようにします。 これにより、総コストは次のようになります。$O(M \cdot 2^N)$、完全なマトリックスを構築するには追加のコストがかかります$O(2^{2N})$入力して出力します。 

ただし、行列の乗算を明示的に計算する必要がないことを認識すると、これをさらに単純化できます。 各基底状態からそのイメージへの最終的なマッピングのみが必要です。 各ゲートは決定論的なビット変換であるため、行列演算の代わりに整数にビット 反転を直接適用します。 

重要な観察は、すべてのゲートが 0 から 0 までの整数のセットの順列であるということです。$2^N - 1$。 したがって、配列を維持できます`perm[j]`状態 j の最終イメージを表します。 当初は、`perm[j] = j`。 各ゲートは、そのビット操作を適用することによってすべてのエントリを更新します。 すべてのゲートを処理した後、次の位置に 1 を配置して順列を行列に展開します。`(perm[j], j)`各 j について。 

これにより、最大 256 のサイズのドメインに対して M 回のビット単位の変換を適用するという問題が軽減されます。

 ## アルゴリズムのチュートリアル

 各基底状態を N ビットの整数マスクとして扱い、回路の下でその進化するイメージを維持します。 

1. 配列を初期化する`perm`サイズの$2^N$そのような`perm[x] = x`すべての状態 x に対して。 これは、ゲートが適用される前の恒等変換を表します。 
2. ゲートごとに、システム内のすべての状態 x を順番に更新します。 新しい配列を計算します`nxt`どこ`nxt[x]`ゲートを適用した結果です`perm[x]`。 各ゲートは元のインデックスではなく、現在の変換された状態に作用するため、この分離は重要です。 
3. ゲートがコントロール c とターゲット t を持つ CNOT の場合、x ごとにビット c を検査します。`perm[x]`。 1 の場合、ビット t を反転します。`perm[x]`。 Otherwise we keep it unchanged. This directly encodes the definition of the gate as a conditional bit flip.
 4. If the gate is a CCNOT with controls c1, c2 and target t, we check whether both control bits in`perm[x]`が設定されています。 「はい」の場合、ビット t を反転します。 Otherwise we leave the value unchanged. The AND condition ensures reversibility and matches the gate definition.
 5. After processing all gates,`perm[x]`すべての入力 x の最終的な出力状態を与えます。 
6. を初期化して行列を構築します。$2^N \times 2^N$「0」のグリッド。 各入力状態 x に対して、行に「1」を配置します。`perm[x]`そしてコラム`x`。 

なぜそれが機能するのかは、各ゲートが状態空間上の全単射であるという事実に帰着します。 すべてのステップは状態を状態に一意にマップするため、ゲートの合成は単に順列上の関数の合成になります。 配列`perm`この合成された関数を明示的に追跡します。 各更新では正しい関数変換が適用されるため、M ステップ後に`perm`は、合成された回路関数に等しい。 最後の行列は、単にこの関数の出現行列です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def flip(x, bit):
    return x ^ (1 << bit)

def get_bit(x, bit):
    return (x >> bit) & 1

def apply_gate(states, gate):
    t = gate[0]
    n = len(states)
    if t == 1:
        c, tt = gate[1], gate[2]
        for i in range(n):
            x = states[i]
            if get_bit(x, c):
                states[i] = flip(x, tt)
    else:
        c1, c2, tt = gate[1], gate[2], gate[3]
        for i in range(n):
            x = states[i]
            if get_bit(x, c1) and get_bit(x, c2):
                states[i] = flip(x, tt)

def main():
    N, M = map(int, input().split())
    size = 1 << N

    perm = list(range(size))

    gates = []
    for _ in range(M):
        parts = list(map(int, input().split()))
        gates.append(parts)

    for gate in gates:
        apply_gate(perm, gate)

    mat = [['0'] * size for _ in range(size)]
    for j in range(size):
        mat[perm[j]][j] = '1'

    sys.stdout.write("\n".join("".join(row) for row in mat))

if __name__ == "__main__":
    main()
```この実装では、中間ステップで行列を構築する代わりに、直接の置換配列を維持します。 各ゲートは、すべての状態をスキャンし、現在のマッピングの一時的な解釈を通じて適切に更新することによって適用されます。 

ビット操作はシフトと XOR を使用して明示的に処理され、状態ごとの定数時間の更新が保証されます。 マトリックスの最終的な構築は、すべての変換が適用された後に 1 回だけ実行されるため、不必要な繰り返し割り当てが回避されます。 

微妙な点は、常に現在のマップされた状態にゲートを適用することです。`perm[x]`、x 自体ではありません。 これにより、ゲートは実行順序で指定されますが、行列の乗算は右から左への変換を構成するため、正しい構成順序が保証されます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、ゲートがほとんどの状態に影響を与えないように見える場合です。 たとえば、制御ビットが両方とも設定されることはほとんどない CCNOT でも、影響を受けないすべての行を正確に保存する必要があります。 明示的に反転しない限り、各状態は常に前方にコピーされるため、アルゴリズムはこれを自然に処理します。 

もう 1 つのエッジ ケースは、複数のゲートが同じターゲット ビットに作用する場合です。 随時更新していきますので`perm[x]`順番に、後のゲートは前のエフェクトを正しく上書きし、真の合成順序を反映します。 

最後のエッジケースは、N が最大の場合です。 でさえ$N = 8$、処理する状態は 256 個だけであるため、ゲートごとにスキャンを繰り返しても簡単です。 実装には単純なビット演算以上の最適化は必要なく、正確さは変換ルールの一貫した適用のみに依存します。
