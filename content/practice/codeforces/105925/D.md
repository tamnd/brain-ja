 ## 問題の理解

 量子ビットのコレクションの状態を表す同じ長さの 2 つの文字列が与えられます。 最初の文字列は、一部の位置が安定ビットである「分離」構成を表します。`0`または`1`、いくつかのポジションは不確実であり、`*`、量子ビットが重ね合わせられていることを意味します。 2 番目の文字列は、デコヒーレンス後の現実世界の条件下で観察される内容を記述します。`*`最初の文字列はどちらかに折りたたまれています`0`または`1`。 

すでにあったすべてのポジション`0`または`1`最初の文字列の内容は、2 番目の文字列でも変更されないことが保証されます。 あったポジションのみ`*`変化する可能性があり、それらの位置で、崩壊によって状態が変化したかどうかを比較します。 

タスクは、次のように開始されたすべてのポジションの比率を計算することです。`*`、崩壊後に値が変更されたものの数を数え、合計数で割ります。`*`ポジション。 答えは、小数点以下 2 桁の 10 進数として出力する必要があります。 

この制約により、文字列の長さは最大約 100,000 になります。 これにより、単一のリニア スキャンを超えて位置ごとに大量の計算を実行するアプローチは即座に排除されます。 二次関数や文字列のネストされたループを含むものは遅すぎます。 

微妙だが重要なエッジケースは、何もない場合に発生します。`*`最初の文字列の文字。 このステートメントは、このようなことが起こらないことを保証しているため、ゼロによる除算は問題になりません。 もう 1 つの特殊なケースは、すべてが`*`位置は 1 つを除いて 2 番目の文字列と同じように折りたたまれます。1 つは次のような非常に小さな部分を生成します。`0.01`または`0.00`フォーマットに応じて。 

## アプローチ

 直接的な解釈は、すべてのインデックスを反復処理し、最初の文字列が存在するすべての位置に対して反復処理を実行します。`*`、2 つの文字列を比較します。 このような位置がいくつ存在するかを示すカウンタと、2 つの文字列間で異なる位置がいくつあるかを示す別のカウンタを維持します。 答えは単にこれら 2 つの値の比率です。 

各インデックスを少なくとも 1 回検査する必要があるため、この総当り手法は構造的にすでに最適化されています。 位置間の組み合わせの爆発や依存関係がないため、高度なデータ構造や前処理は必要ありません。 必要な操作は単一パスの比較のみです。 

重要な観察は、この問題はグローバルなものや相互依存的なものを求めていないということです。 各インデックスは最終的な比率に独立して寄与するため、計算はローカル イベントのカウントに減ります。 

ブルート フォースは、文字ごとに定数チェックを 1 回だけ実行するため、線形であり、制約内で機能します。 これ以上複雑なアプローチでは、不必要なオーバーヘッドが発生します。

 ## アルゴリズムのチュートリアル

 両方の文字列を並行して処理し、2 つのカウンタを維持します。1 つは合計の重ね合わせ位置を表すもの、もう 1 つはそれらの位置のうち実際に変更された数を表すものです。 

1. 2 つの整数を初期化します。`total_star`そして`changed`、両方ともゼロに設定されます。 これらは、必要な比率の分母と分子を累積します。 
2. すべてのインデックスを反復処理します。`i`から`0`に`N - 1`。 各インデックスで、最初の文字列の文字が`*`。 これは計算に寄与する唯一のケースです。 
3. もし`S[i] == '*'`、増分`total_star`1つずつ。 これにより、2 番目の文字列で何が起こったかに関係なく、その位置が分母の一部としてカウントされます。 
4. 同じ状態のまま比較してください`S[i]`そして`T[i]`。 異なる場合は増分します`changed`。 以来`S[i]`いつもです`*`ここでは、これは、折りたたまれた値が元の未知の状態と異なるかどうかを効果的にチェックします。 
5. ループが終了したら、比率を計算します。`changed / total_star`浮動小数点数として。 
6. 小数点以下 2 桁でフォーマットされた結果を出力します。 

これが機能する理由は、それぞれ`*`位置は、最終的な確率のような比率に独立して寄与します。 位置間には相互作用がないため、局所的な不一致を集計すると、グローバルな測定値が直接生成されます。 

### なぜ効果があるのか

 各インデックスの場所`S[i]`は`*`単一のベルヌーイのようなイベントを定義します。つまり、崩壊が観測値と一致するか、一致しないかのいずれかです。 この問題は、そのようなすべての独立したイベント間の不一致の割合を求めます。 このアルゴリズムは、合計イベント スペースと失敗したサブセットの両方の正確な数を維持します。 すべての有効なインデックスは 1 回だけカウントされ、1 回だけ分類されるため、最終的な比率はステートメント内の定義と数学的に同一になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n = int(input().strip())
    s = input().strip()
    t = input().strip()

    total_star = 0
    changed = 0

    for i in range(n):
        if s[i] == '*':
            total_star += 1
            if t[i] != s[i]:
                changed += 1

    ans = changed / total_star
    print(f"{ans:.2f}")

if __name__ == "__main__":
    main()
```実装はアルゴリズムにほぼ直接に従います。 ループはソリューションの中核であり、キャラクターごとに一定時間の作業を実行します。 フォーマット手順`f"{ans:.2f}"`手動の丸めロジックなしで必要な精度を保証します。 

微妙な点の 1 つは、私たちは決してその意味を解釈しようとしていないということです。`0`または`1`スター以外の位置では、ステートメント内の保証により無関係になるためです。 これにより、実装が最小限に抑えられ、不必要な条件が回避されます。
