 ## 解決策
 ## 問題の理解

 単一の整数が与えられます$X$。 最大の整数を見つける必要があります$Y$そのような$Y \le X$そして、のバイナリ表現$Y$回文です。 

2 進回文とは、先頭にゼロを付けずに 2 進数で数値を記述すると、ビット シーケンスが左から右、右から左に同​​じように読み取られることを意味します。 例えば、$9 = 1001_2$は有効ですが、$10 = 1010_2$そうではありません。 

入力サイズの制約$X \le 10^{18}$バイナリ表現が最大 60 ビットであることを意味します。 これにより、候補ごとにすべての整数をスキャンするブルート フォースが即座に排除されます。$X$, 最悪の場合は まで調べることになるからです。$10^{18}$値ごとに 1 つのバイナリ回文チェックを行うだけでも、遅すぎます。 

問題の構造は、有効な答えが全範囲に比べて稀であることを示唆していますが、バイナリ回文はビットの前半によって完全に決定されるため、依然として非常に規則的に分布しています。 

単純な間違いは、単にから減少できると仮定することです。$X$そして回文性をテストします。 たとえば、次の場合$X = 1000_2$、次のような多くの値をチェックします$111, 110, 101, 100$のような回文に到達する前に$111_2$。 これは、入力が大きい場合にひどく劣化します。 

もう 1 つの微妙な問題は、先頭ビットです。 のような数字$0110_2$先行ゼロは表現の一部ではないため、有効とは見なされません。 どの構築方法でも、最上位ビットが常に 1 であることを保証する必要があります。 

## アプローチ

 ブルートフォースアプローチは簡単です。 から始まる$X$、各数値がバイナリ回文であるかどうかを確認します。 チェック自体は、$O(\log X)$バイナリに変換して文字列の末尾を比較するためです。 最悪の場合、$X$が回文のまばらな領域のすぐ下にある場合、1 つの整数に到達する前に、多くの連続する整数をスキャンする可能性があります。 これにより、次の方向に劣化する可能性があります。$O(X \log X)$、制約上不可能です。 

重要な構造的観察は、バイナリ回文がビットの前半によって完全に決定されるということです。 プレフィックスを修正すると、ミラーリングによってサフィックスが強制されます。 したがって、すべての整数を検索する代わりに、可能な半接頭語を検索し、候補の回文を作成し、それらを比較します。$X$。 

これにより、問題は、次と同じビット長の周りで回文を生成することになります。$X$、その下は最大 1 ビット長です。 それぞれの長さに対して、次の接頭辞を取得することで最適な回文を構築できます。$X$をミラーリングし、超えた場合は下方調整します。$X$。 調整はローカルです。構築された回文が大きすぎる場合は、プレフィックスをデクリメントして再度ミラーリングします。 

これにより、問題は一定数の構築と比較に変わり、それぞれ最大 60 ビットになります。

 ## アルゴリズムのチュートリアル

 のバイナリ長を処理します$X$なぜなら、答えは同じ長さか 1 つ少ない長さでなければならないからです。 

1.変換$X$バイナリ表現に変換する$s$。 させて$n$その長さになります。 

答えを以下のものにすることはできません$n-1$長さの回文がない場合を除き、ビット$n$または$n-1$は当てはまりますが、下向き検索では決して起こりません。$1$は常に有効です。 
2. 長さの最大の回文を構築しようとします$n$それは以下です$X$。 

我々が最初を取る$\lceil n/2 \rceil$ビットをプレフィックス候補として使用します。 このプレフィックスは、ミラーリングによって回文全体を決定します。 
3. この接頭辞を中心の周りに反映させて回文を作成します。 

もし$n$が奇数の場合、中間ビットは共有されます。 それ以外の場合は、対称的にミラーリングされます。 
4. この構築された回文を次のものと比較してください。$X$。 

以下の場合$X$、長さの最有力候補です$n$。 
5.それより大きい場合$X$、プレフィックスを 2 進数としてデクリメントし、回文を再度再構築します。 

実際には 1 回の減分だけで十分であるため、このステップは非常に重要です。プレフィックスを減らすと、厳密に辞書編集順に回文が減り、固定長 2 進数の数値順序と一致します。 
6. 調整後も有効でない場合$n$-bit 回文も許容されます。長さに対して同じ構造を繰り返します。$n-1$。 

バイナリ回文はあらゆる長さに対して存在し、最大値は以下のとおりであるため、これにより正確さが保証されます。$X$これら 2 つの長さのいずれかになければなりません。 

### なぜ効果があるのか

 固定長の場合、2 進数は数値と同じように辞書順に並べられます。 プレフィックスをミラーリングして回文を構築すると、そのプレフィックス クラスの可能な最大の候補が確実に生成されます。 指定された回文よりも小さい数値は、より小さい接頭辞またはより短い長さから取得されなければなりません。 したがって、プレフィックスを下方に調整すると、ギャップのない降順ですべての候補が探索され、次のように切り替わります。$n-1$残りの検索スペースをカバーします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_pal(prefix, n):
    s = bin(prefix)[2:]
    # ensure prefix has enough bits for mirroring
    s = s.zfill((n + 1) // 2)
    if n % 2 == 0:
        return int(s + s[::-1], 2)
    else:
        return int(s + s[-2::-1], 2)

def solve():
    x = int(input().strip())
    s = bin(x)[2:]
    n = len(s)

    def best_for_length(n):
        prefix_len = (n + 1) // 2
        prefix = int(s[:prefix_len], 2)

        while True:
            cand = build_pal(prefix, n)
            if cand <= x:
                return cand
            prefix -= 1

    ans = best_for_length(n)
    if ans == 0:
        ans = best_for_length(n - 1)

    print(ans)

if __name__ == "__main__":
    solve()
```この解決策は、プレフィックス抽出が直接スライスになるように、数値をバイナリ文字列形式に変換することから始まります。 コア ルーチンは、指定されたプレフィックスをミラーリングすることによって回文を構築し、奇数と偶数の長さを別々に慎重に処理します。 

内側のループは、構築された回文が次の値を超えた場合にのみプレフィックスをデクリメントします。$X$。 プレフィックスを減らすと結果として生じる回文が厳密に減少するため、これは安全です。そのため、有効な候補に向かって単調に移動します。 

最後に、同じビット長の有効な回文が機能しない場合は、次のように切り替えます。$n-1$ビット。これは以下の残りの検索スペースを完全にカバーするためです。$X$。

 ## 特殊なケース

 のために$X = 1$の場合、アルゴリズムは 1 ビットの回文に対してすぐに機能します。 バイナリ表現は$1$すでに有効になっているため、構築する必要はありません。
