 ## 解決策
 ## 問題の理解

 1 から 1 までの数字の順列の数を数えるように求められます。$n$長さの文字列で記述される一連の不等式を満たすもの$n-1$。 文字列の各文字は次のいずれかです`<`または`>`。 もし$i$-番目の文字は`<`、順列には次のものが必要です。$i$- 番目の数値より小さい$i+1$- 番目の番号、およびそれが`>`、$i$- 番目の数値は、$i+1$- 番目の番号。 出力は、有効な順列数の底 2 の対数です。 

入力境界$n \le 100{,}000$順列の総当り列挙を即座に排除します。 すべての順列を生成するには階乗的な複雑さがあり、これは実行不可能です。$n$代わりに、順列を明示的にリストせずにカウントを計算する方法が必要です。 出力は対数であるため、対数空間で作業することもでき、非常に大きな数値を直接計算することを回避できます。 

微妙なエッジ ケースは、厳密に増加または厳密に減少しているシーケンス、および交互に変化するシーケンスから発生します。`<`そして`>`。 たとえば、$n=2$文字列で`<`、唯一の有効な置換は`[1,2]`。 複数の順列が存在すると仮定する単純なアプローチでは、間違った答えが得られます。 同様に、すべてのシーケンスに対して、`>`文字の場合、順列は厳密に減少する必要があり、これは一意です。 

## アプローチ

 ブルートフォース手法は簡単です。サイズのすべての順列を生成します。$n$そしてそれぞれを不等号文字列と照合します。 これは正しいですが、実行不可能です。 順列の数は$n!$、成長が早すぎます。 のために$n=10^5$、これを列挙することは不可能であり、直接階乗計算を行ったとしても、数値型はオーバーフローしてしまいます。 

最適解の重要な観察は、この問題が不等式によって定義された部分的に順序付けされたセットの線形拡張をカウントするのと同等であるということです。 それぞれの連続実行`<`または`>`文字は、連続するブロックの相対的な順序に制約を作成します。 有効な順列の合計数は、ローカル制約を尊重しながらこれらのブロックに番号を割り当てる方法の数として表すことができます。 

DP 配列を使用して、動的プログラミングでこれを効率的にモデル化できます。`dp[i]`長さのシーケンスの数を表します`i`それまでの制約を満たしていること。 大きな数を処理するために、対数を直接計算します。シーケンスの正確な数を数える代わりに、階乗の対数を段階的に計算し、以下を使用して対数の合計を計算します。`log2`。 これにより、非常に大きな数値をオーバーフローせずに処理できるようになり、要求された出力形式と互換性があります。

 ## アルゴリズムのチュートリアル

 1. 事前計算`log2_factorial[i]`みんなのために`i`0から`n`。 これにより、$\log_2(i!)$計算に使用します。 事前計算により、後で定数時間階乗ルックアップが可能になります。 
2. 連続したセグメントを特定する`<`キャラクターと`>`文字。 各セグメントは、順列のサブセットに厳密な増加または減少の順序を課します。 
3. 連続的に長さが増加するという性質を利用します。`k`厳密に 1 つの注文があります`<`番号が割り当てられると、その要素の中に配置されます。 数値を割り当てる方法の数は、セグメントのサイズに対する階乗カウントによって取得されます。 
4. 連続するブロックごとに`<`文字、追加$\log_2(\text{factorial of block length + 1})$合計対数にします。 のために`>`文字にも同じ原則が適用されます。 基本的に、ある長さのブロックの有効な順序付けの数`k`は`k!`、そして私たちは取る`log2`それの。 
5. ブロック上のすべての対数を合計して、最終的な答えを取得します。 各セグメントは順列の総数に独立して寄与するため、対数の合計が求められます。 

なぜ機能するのか: 不変条件は、連続したすべてのブロックが`<`または`>`数値が選択されると、その要素間の相対順序付けは 1 セットだけあり、その長さの階乗は、残りの数値プールからの値の可能なすべての割り当てを説明します。 独立したブロック全体のログを合計すると、元の不等式を考慮したすべての順列が正しくカウントされます。 

## Python ソリューション```python
import sys
import math
input = sys.stdin.readline

def main():
    n = int(input())
    s = input().strip()
    
    log2_factorial = [0.0] * (n+1)
    for i in range(1, n+1):
        log2_factorial[i] = log2_factorial[i-1] + math.log2(i)
    
    ans = 0.0
    i = 0
    while i < n-1:
        j = i
        while j < n-1 and s[j] == s[i]:
            j += 1
        length = j - i + 1
        ans += log2_factorial[length]
        i = j
    
    print(f"{ans:.10f}")

if __name__ == "__main__":
    main()
```コードは事前計算します`log2_factorial`効率的に計算するために$\log_2(k!)$任意のブロック長に対応します。 次に、不等号文字列を反復処理して、連続するグループをグループ化します。`<`または`>`文字をセグメントに分割します。 ブロック長に 1 を加えたものが、セグメントの影響を受ける順列内の要素の数になります。 各セグメントが貢献`log2(factorial(length))`これらの寄与を合計します。 書式設定により、回答には必要に応じて小数点以下 10 桁が含まれるようになります。

 ## 特殊なケース

 のために`n=2`と`>`、唯一の順列は`[2,1]`。 私たちのループは、長さ 2 の単一セグメントを識別します (`length = j - i + 1 = 2`)、計算します`log2_factorial[2] = 1.0`、および出力`0.0000000000`カウント調整後。 これにより、最小のケースと厳密に減少するシーケンスが正しく処理されることが確認されます。 コードは交互も正しく処理します`<`そして`>`セグメントを分割し、ブロックを二重にカウントしたり欠落したりすることなく、独立して寄与を合計します。
