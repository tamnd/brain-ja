 ## 解決策
 ## 問題の理解

 このタスクでは、メッセージのタイムラインを考慮して、裁判官が 1 日に少なくとも 2 回、飼い犬のボーイを散歩させた可能性があるかどうかを判断するよう求められます。 各散歩はちょうど 120 分かかり、他の散歩と重複することはできません。また、審査員は散歩中にメッセージを送信することはありません。 入力はいくつかのテスト ケースで構成されており、それぞれが午前 0 時からのメッセージ時間の厳密な増加リストを分単位で提供します。 各テスト ケースの出力は、メッセージの周囲に少なくとも 2 つの重複しない 120 分間のウォークを適合させることができる場合は「YES」、そうでない場合は「NO」になります。 

重要な観察は、1 日は 1440 分であるため、利用できる合計時間は有限であるということです。 1 回の散歩には 120 分かかるため、2 回の散歩には 240 分の空き時間が必要になります。 メッセージの時間は、1 日をウォーキングが可能な間隔に分割します。 連続するメッセージ間の間隔、または 1 日の開始/終了間の間隔が少なくとも 120 分ある場合、そこでウォークが発生する可能性があります。 このような間隔が重複せずに少なくとも 2 つ存在するかどうかを確認する必要があります。 

エッジケースには、メッセージが非常に少ない状況、メッセージが密に詰め込まれている状況、またはウォークが真夜中に始まったり一日の終わりの瞬間に終わる可能性がある状況が含まれます。 たとえば、メッセージが 0、1、2、3、4 分に発生した場合、5 から 1440 までの残り時間は 2 つのウォークをスケジュールするのに十分です。 逆に、メッセージが 0、120、240、…、1320 にある場合は、120 分の歩行を 1 回も収めることが不可能である可能性があります。 

問題の制約は非常に緩やかです。 各テスト ケースには最大 100 個のメッセージが含まれ、最大 100 個のテスト ケースが存在します。 これにより、テスト ケースごとに O(n) のソリューションを時間制限内で快適に実行できます。 パフォーマンスを心配することなく、メッセージ時間を反復処理してギャップを計算できます。 

## アプローチ

 ブルートフォース手法では、1 日のあらゆる時間に開始して 120 分間のウォークを実行し、それがメッセージと重複するかどうかを確認しようとします。 これには、テスト ケースごとに最大 1440 件の開始時間をチェックし、開始時間ごとにすべてのメッセージを反復して競合をチェックする必要があります。 最悪の場合、テスト ケースごとに約 1440 * 100 = 144,000 回の操作が必要となり、これは実行可能ですが、必要以上に非効率的です。 

最適なアプローチでは、関連する時間は連続するメッセージ間の間隔と 1 日の端だけであることが観察されます。 各メッセージは、1 日を午前 0 時から最初のメッセージまで、メッセージ間、最後のメッセージから 1 日の終わりまでの間隔に分割します。 これらのギャップを測定し、少なくとも 2 つのギャップの長さが 120 以上であるかどうかを確認するだけで済みます。 メッセージ リストを 1 回繰り返して間隔の長さをチェックすることで、各テスト ケースを O(n) 時間で解決できます。 この洞察は、メッセージがウォーク中に移動しないため、十分に大きなギャップ内の任意の場所にウォークを配置すると常に機能するということです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(1440 * n) | O(n) | 動作しますが、不必要に遅い |
 | インターバルチェック | O(n) | お(1) | 受け入れられ、シンプル |

 ## アルゴリズムのチュートリアル

 1. まずテスト ケースの数を読み取ります。`t`。 これにより、分析する必要がある個別のスケジュールの数がわかります。 
2. 各テスト ケースについて、メッセージの数を読み取ります。`n`メッセージ時間のリスト`a`。 リストは厳密に増加しています。 
3. カウンタの初期化`walkable_intervals`ゼロに。 これにより、メッセージ間に 120 分の間隔が何回存在するかを追跡します。 
4. 午前 0 時から最初のメッセージまでの最初の間隔を計算します。 この間隔が少なくとも 120 分の場合は、増加します。`walkable_intervals`。 
5. 連続するメッセージのペアを繰り返します。 各ペアごとに`(a[i], a[i+1])`、間隔を確認してください`a[i+1] - a[i]`。 このギャップが少なくとも 120 分である場合、増分します`walkable_intervals`。 
6. 最後のメッセージからその日の終わりまでの最終間隔を確認します。 もし`1440 - a[-1]`少なくとも 120、増分`walkable_intervals`。 
7. すべての間隔を数えた後、次の場合は`walkable_intervals`少なくとも 2 の場合、「YES」を出力します。 それ以外の場合は「NO」を出力します。 

機能する理由: このアルゴリズムは、メッセージのない最大の連続期間のみを考慮するため、正しいです。 120 分のウォーキングは、完全にこれらの期間のいずれかに収まる必要があります。 少なくとも 120 の長さの期間をカウントすることで、重複しない歩行が可能かどうかを直接カウントします。 このような期間が 2 つ以上あると、2 回のウォークが発生する可能性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    walkable = 0
    
    # Check interval before first message
    if a[0] >= 120:
        walkable += 1
    
    # Check intervals between messages
    for i in range(n - 1):
        if a[i+1] - a[i] >= 120:
            walkable += 1
    
    # Check interval after last message
    if 1440 - a[-1] >= 120:
        walkable += 1
    
    print("YES" if walkable >= 2 else "NO")
```コードはアルゴリズムを段階的に反映しています。 最初のメッセージの前、連続する各ペアの間、最後のメッセージの後の間隔を明示的にチェックします。 ウォーカブル カウンターは、有効な 120 分間隔がいくつ存在するかをキャプチャします。 しきい値の比較`>= 120`利用可能な時間を過小評価しないようにします。 最後の条件は、少なくとも 2 つの歩行をスケジュールできるかどうかを単純に検証します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | テスト ケースあたり O(n) | n 個のメッセージを 1 回繰り返し、間隔ごとに一定の作業を行う |
 | スペース | O(n) | メッセージ時刻をリストに保存する |

 と`t`テスト ケースでは、合計の複雑さは O(t*n) で、最大でも 100 * 100 = 10,000 操作であり、2 秒の制限時間に比べれば無視できます。 メモリ使用量は最小限であり、メッセージ リストのみが保存されます。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = io.StringIO()
    sys.stdout = output
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        walkable = 0
        if a[0] >= 120:
            walkable += 1
        for i in range(n - 1):
            if a[i+1] - a[i] >= 120:
                walkable += 1
        if 1440 - a[-1] >= 120:
            walkable += 1
        print("YES" if walkable >= 2 else "NO")
    return output.getvalue().strip()
