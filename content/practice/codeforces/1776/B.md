 ## 解決策
 ## 問題の理解

 一連の LEGO Duplo レンガを、X 軸に沿った 1D 線上に配置するように求められます。各レンガは地面上の 2×2 の正方形を占め、高さは 1 であるという制約があります。紫色のレンガは、指定された高さでなければなりません。`h`特定の X 座標に、さらに低い Z レベルに追加のサポート レンガを配置して、それらを保持することができます。 地面にないすべてのレンガは、そのベースのプラスの領域を覆うように、その下のレンガの上に置かれなければなりません。 目標は、必要な追加のレンガの数を最小限に抑えることです。 

入力により得られるのは、`n`、紫レンガの数、一般的な高さ`h`、およびそれらの x 座標のソートされたリスト。 出力は単一の整数、つまり必要な追加ブリックの最小数です。 もし`h`がゼロの場合、紫色のレンガがすでに地面にあるため、追加のレンガは必要ありません。 それ以外の場合は、紫レンガ間の隙間と、下位レベルのレンガが一度に複数の紫レンガをどのようにサポートできるかを考慮する必要があります。 

微妙な点は、各レンガの幅が 2 であるため、レンガは x 座標を中心とすることです。`x`スパン`[x-1, x+1]`X 軸上。 これは、中心にある 2 つのレンガを意味します。`x_i`そして`x_{i+1}`場合によっては部分的に重複する可能性があります`x_{i+1} - x_i < 2`。 入力保証なので`x_i + 1 < x_{i+1}`, すべての紫色のレンガは少なくとも距離 2 離れているため、重なり合うことはありません。 これは、レンガを最適にサポートするための鍵です。正しく配置されていれば、1 つのサポート レンガで連続する紫レンガをカバーできます。 

エッジケースには、すべての紫色のレンガが地面にある場合が含まれます (`h=0`)、高さに紫色のレンガが 1 つあります`h`、および距離 2 で正確に配置されたレンガ。不必要な支持レンガを数えないよう慎重に扱う必要があります。 

## アプローチ

 ブルートフォースアプローチでは、レンガを層ごとに積み重ねるシミュレーションを試み、各 Z レベルで可能なすべての位置の重なりをチェックします。 紫色のレンガごとに、地面に達するまでその下のすべての整数 x 座標に支持レンガを配置してみることができます。 これには、潜在的に巨大な x 範囲を反復処理する必要があります。`10^9`までの高さ`10^9`。 明らかにこれは実行不可能です。`n`は最大 300 までですが、座標範囲は膨大です。 位置を反復処理することはできません。 紫色のレンガの位置を直接操作する必要があります。 

重要な観察は、すべてのレンガの幅が 2 であり、各紫色のレンガは、その 2 単位のベースがそれ自体のベースと重なるレンガの下にあるレンガによって支えられている必要があるということです。 支持レンガの最小数は、下層ごとに 1 つの支持レンガで連続する紫レンガをどのように覆うことができるかによって決まります。 なぜなら`x_i + 1 < x_{i+1}`、リスト内で連続する紫色のレンガは少なくとも 2 ユニット離れているため、最適に配置された場合、1 つのレンガが隣接する 2 つの紫色のレンガをカバーできる場合があります。 

これは、貪欲プログラミング アプローチまたは動的プログラミング アプローチを使用して形式化できます。 セグメントを定義する`[x_i-1, x_i+1]`for each purple brick. 次に、各層で、ベースが 2 つのユニットにまたがる支持レンガで、できるだけ多くの連続した紫レンガを覆うことができます。 レンガの高さが均一であるため、各層を独立して積み重ねることができるため、サポートするレンガの最小数は、単一の 2 ユニットのレンガではカバーできない紫色のレンガ間の隙間の数を数えるだけになります。 For height`h`、このカウントを乗算します`h`それぞれの紫レンガの高さがあるので`h`必要`h`その下にはサポート層があります。 この洞察により、問題は連続する x 座標間のギャップに基づく単純な算術計算に帰着します。

 ## アルゴリズムのチュートリアル

 1. もし`h`がゼロの場合、支持レンガは必要ありません。 すぐに0を返します。 
2. 紫色のレンガの連続する x 座標間の差を計算します。`gaps[i] = x[i+1] - x[i]`。 
3. 2 より大きい各ギャップには、2 を超える距離単位ごとに少なくとも 1 つの追加の支持レンガが必要です。具体的には、ギャップの場合`g`、必要です`g-2`各層で橋を架けるようにレンガを支えます。 1 つの 2 ユニット レンガで両方の紫レンガをカバーできるため、正確に 2 のギャップは追加のレンガを必要としません。 
4. すべての隙間に必要な支持レンガを合計します。 この合計を`needed_per_layer`。 
5. 乗算`needed_per_layer`による`h`紫色のレンガの高さに達するために必要な層の数を考慮します。 
6. 追加のレンガの総数を出力します。 

機能する理由: レンガの X 投影に焦点を当て、固定幅 2 を活用することで、3D スタッキングの問題を 1D のギャップ カバレッジの問題に軽減します。 下のレンガが同じスパンをサポートしているため、各層は独立しており、層ごとに必要なレンガの数は完全に紫色のレンガ間の距離によって決まります。 乗算`h`垂直方向の積み重ねを考慮します。 これにより、サポートされるブリックの最小数が保証されます。これは、構成が小さいと一部の紫色のブリックがサポートされないままになるためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, h = map(int, input().split())
x = list(map(int, input().split()))

if h == 0:
    print(0)
    exit()

additional_bricks = 0
for i in range(n - 1):
    gap = x[i+1] - x[i]
    if gap > 2:
        additional_bricks += gap - 2

print(additional_bricks * h)
```コードはまず、紫色のレンガが地面にあるという些細なケースをチェックします。 次に、連続する紫色のレンガを繰り返し、ギャップを計算し、各ギャップに必要な支持レンガの数を数えます。 最後に、カウントを次のように乗算します。`h`垂直スタッキングの場合は、結果を印刷します。 の`gap - 2`この式により、レンガは紫レンガ間の覆われていないスペースのみを埋めることが保証されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, h = map(int, input().split())
    x = list(map(int, input().split()))
    if h == 0:
        return "0"
    additional_bricks = 0
    for i in range(n - 1):
        gap = x[i+1] - x[i]
        if gap > 2:
            additional_bricks += gap - 2
    return str(additional_bricks * h)

# provided samples
assert run("4 0\n2 7 11 13\n") == "0", "sample 1"
assert run("4 2\n2 7 11 13\n") == "10", "custom for h=2"

# custom cases
assert run("1 5\n10\n") == "0", "single brick needs no support"
assert run("2 3\n1 4\n") == "3", "two bricks spaced by 3 units, 3 layers"
assert run("3 1\n2 5 8\n") == "3", "three bricks spaced by 3 units each, 1 layer"
assert run("3 0\n1 2 3\n") == "0", "height zero, no additional bricks"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
