 ## 解決策
 ## 問題の理解

 SwerChat によって表示されるリストは、最新順に並べられています。 最後にオンラインだったメンバーが最初に表示され、2 番目に最近オンラインだったメンバーが 2 番目に表示されます。 

9:00、ベッパは注文を記録します`a`。 22:00 に別の注文を記録します`b`。 

この 2 つの瞬間の間に、順序を変更できる唯一のことは、メンバーがオンラインになることです。 同時にオンラインになる人はいないため、すべてのオンライン イベントは一度に 1 つずつ処理されます。 メンバーがオンラインになると、そのメンバーが最も最近見たメンバーとなり、リストの先頭に移動します。 

順序を変更するには、少なくとも一度はオンラインになっている必要がある個別のメンバーの最小数を決定する必要があります。`a`の中へ`b`。 

すべてのテスト ケースの合計サイズは最大でも`10^5`したがって、メンバーのすべてのペアを比較したり、大規模なリスト操作を繰り返しシミュレートしたりするソリューションは、遅すぎます。 アン`O(n)`または`O(n log n)`テスト ケースごとのソリューションは簡単に十分に高速です。 

微妙な点は、メンバーがオンラインに必ずしも接続していなくても、別の位置に表示される可能性があることです。 他の人がオンラインになると、後ろに押しやられる可能性があります。 立場が変わった人全員を数えるという単純なアプローチでは、答えが過大評価されてしまいます。 

考慮する：```
a = [1, 2, 3]
b = [2, 1, 3]
```会員のみ`2`オンラインにする必要があります。 メンバー`1`位置は変わりますが、オンラインである必要はありません。 

もう 1 つの簡単な間違いは、2 つの順列間のすべての反転がオンライン イベントに対応すると仮定することです。 

例えば：```
a = [1, 2, 3, 4]
b = [3, 4, 1, 2]
```メンバー`3`そして`4`オンラインになり、最終注文が生成されます。 答えは`2`、 ない`4`。 

リストがすでに同一である場合、別のエッジケースが発生します。```
a = [1, 2, 3, 4]
b = [1, 2, 3, 4]
```誰もオンラインに接続する必要がないので、正解は次のとおりです。`0`。 

## アプローチ

 ブルートフォースの観点は、どのメンバーがオンラインだったのかを推測し、一連の前方移動操作で結果が得られるかどうかを確認することです。`b`。 

その考えは原理的には正しいですが、まったく現実的ではありません。 がある`2^n`メンバーの考えられるサブセット、および 1 つの候補サブセットを検証する場合でも、リスト操作をシミュレートする必要があります。 と`n`まで`10^5`、これは不可能です。 

重要な観察は、**オンラインに一度も接続したことがない**メンバーを観察することで得られます。 

メンバーが一度もオンラインにならないと仮定します。 それらは決して前面に移動されることはありません。 彼らに起こり得る唯一のことは、他のメンバーが彼らより先に飛び出すことです。 

そのため、オンラインにならないすべてのメンバーは、元の順列からの相対的な順序を維持します。`a`。 

これは最終的なリストを意味します`b`は非常に特殊な構造を持っています。```
[ all members who were online ]
[ all members who were never online ]
```2 番目の部分は、次の場合とまったく同じ相対順序で現れる必要があります。`a`。 

オンライン メンバーの数を最小限に抑えるために、オンラインに一度もアクセスしないメンバーの数を最大化したいと考えています。 

させて`pos[x]`メンバーの立場になる`x`で`a`。 

のすべての要素を置き換えます`b`その位置によって`a`。 

例えば：```
a = [1, 4, 2, 5, 3]

pos:
1 -> 1
4 -> 2
2 -> 3
5 -> 4
3 -> 5

b = [4, 5, 1, 2, 3]

positions in a:
[2, 4, 1, 3, 5]
```決してオンラインにならないメンバーは、接尾辞を形成する必要があります。`b`、およびそれらの位置`a`厳密に増加している必要があります。 それはまさに、相対的な秩序を維持するための条件です。 

したがって、厳密に増加する、変換されたシーケンスの最長のサフィックスが必要になります。 

その接尾辞に長さがある場合`L`、 それから`L`メンバーは決してオンラインにならない可能性があります。その答えは次のとおりです。```
n - L
```### アプローチの比較

 | ブルートフォース | 指数 | 指数 | 遅すぎる |

 ## アルゴリズムのチュートリアル

 1. 順列を読み取る`a`。 
2. アレイを構築する`pos`どこ`pos[x]`メンバーの位置を保存します`x`で`a`。 
3.トラバース`b`右から左へ。 
4. 現在検査されている接尾辞が不変であることを維持します。`b`の位置の厳密に増加するシーケンスに対応します。`a`。 
5. 端から始めて、次の操作を行いながら左に移動し続けます。```
pos[b[i-1]] < pos[b[i]]
```これは、それらのメンバーの相対的な順序が、次の順序と一致することを意味します。`a`, したがって、それらはすべてオンラインにならない可能性があります。 
6. この条件が失敗する最初の場所は、オンライン プレフィックスと非オンライン サフィックスの間の境界です。 
7. 増加するサフィックスがインデックスから始まる場合`s`、その長さは`n - s`。 
8. 出力:```
s
```まさに最初だから`s`のメンバー`b`オンライン セットに属している必要があります。 

### なぜ効果があるのか

 オンラインに一度もアクセスしないメンバーは皆、相対的な秩序を維持します。`a`。 すべてのオンライン メンバーはすべての非オンライン メンバーよりも先に到達するため、非オンライン メンバーは接尾辞を形成する必要があります。`b`。 

の接尾辞`b`～からの相対的な順序を保持します`a`まさに、対応する位置が`a`厳密に増加しています。 これ以上のサフィックスはこの条件に違反するため、オンラインにならないメンバーだけで構成することはできません。 

逆に、サフィックスが増加している場合は、そのサフィックスの前のすべてのメンバーをオンラインとして宣言することで順列を実現できます。 これらのオンライン メンバーを、次の順序に従って右から左に処理します。`b`、それぞれを一度前に移動します。 これにより、サフィックスは元の相対順序のままで、必要なプレフィックスが正確に生成されます。 

したがって、サフィックスを最も長く増加させると、オンラインにならないメンバーの最大数が得られ、オンライン メンバーの数が最小限に抑えられます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    answers = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        pos = [0] * (n + 1)

        for i, x in enumerate(a):
            pos[x] = i

        s = n - 1

        while s > 0 and pos[b[s - 1]] < pos[b[s]]:
            s -= 1

        answers.append(str(s))

    sys.stdout.write("\n".join(answers))

if __name__ == "__main__":
    solve()
```の`pos`array は、相対順序の質問を単純な整数の比較に変換します。 内部のメンバーを繰り返し検索する代わりに`a`、一定時間で注文の保存を確認できます。 

変数`s`最長の有効なサフィックスの先頭を追跡します。 長さが 1 のすべての接尾辞は自動的に増加するため、最後から開始します。 

条件```
pos[b[s - 1]] < pos[b[s]]
```サフィックスを 1 つ左に拡張しても、最初からの順序が維持されるかどうかをチェックします。`a`。 

条件が失敗した場合、オンラインにならない最大の可能性のあるサフィックスが見つかりました。 答えは、その前の要素の数です。`s`。 

リストのシミュレーションは必要ありません。
