 ## 解決策
 ## 問題の理解

 3 人からなるチームをスケジュールして、簡単、中、難しいの 3 つの難易度で一連の問題を解決するように依頼されます。 各問題には、難易度に応じて所要時間が固定されています。簡単な場合は 2 単位、中程度の場合は 3 単位、難しい場合は 4 単位かかります。 各人は一度に 1 つの問題のみに取り組むことができ、各問題の最後の時間単位には共有コンピュータへの排他的アクセスが必要です。つまり、2 人が同時に問題を終了することはできません。 コンテストは次の期間続きます`l`目標は、解決される問題の数を最大化し、有効なスケジュールを提供することです。 

入力`a`、`b`、`c`簡単、中、難しい問題の数をそれぞれ最大 10^4 で表します。 コンテスト期間`l`最大でも 10^5 です。 これは、問題のすべての順列またはすべての可能な開始時間に対する総当たり検索は、10^4 のオーダーで検討する必要があるため、遅すぎることを意味します。 シーケンス。 個人および共有コンピューターの制約を尊重しながら、問題を効率的にスケジュールする戦略が必要です。 

単純なアプローチでは、共有コンピュータの制約を無視し、人の空き状況に応じて貪欲に問題を割り当てようとする可能性があります。 2 つの問題が同時に終了する場合、これは失敗しますが、これは禁止されています。 次の場合には、別の微妙なエッジケースが発生します。`l`は非常に小さいかゼロです。 たとえば、次の場合`l = 1`たとえ簡単な問題があっても、最小期間は 2 であるため、問題を解決することはできません。同様に、1 つの難易度タイプに問題がまったくない場合、それらをスケジュールしようとすることは避けなければなりません。 

## アプローチ

 ブルートフォース手法では、すべての問題のあらゆる順列が試行され、コンピューターの制約を考慮して、可能なすべての開始時間に問題が人々に割り当てられます。 これはすべてのスケジュールを明示的にチェックするため、原理的には正しいと考えられますが、複雑さは問題の数に比例し、時間ステップでは指数関数的に増加します。 最大 10^4 の問題があるため、これは完全に不可能です。 

重要な洞察は、問題の構造から得られます。共有コンピュータを必要とする最後の時間単位を除いて、各人は独立して作業できます。 しばらくコンピュータを無視すると、最初に対応可能な人に任意の順序で問題を割り当てることができます。 本当に難しいのは、最後の時間単位での衝突を避けることです。 人数が 3 人だけであることを観察すると、最終時間単位の競合の最大数は少なく、1 人あたりの利用可能な時間と占有された最終時間単位のスロットのセットの優先キューとしてスケジュールをモデル化できます。 これにより、最後の時間単位が空いていることを保証しながら、可能な限り早い終了時間までに貪欲にスケジュールを設定できます。 

問題の総数を最大化するために、最初に所要時間が短い順に問題を割り当てます。 問題が短いほど早く終了し、コンピューターが早く解放されます。 問題ごとに、最も早く開始できる人を選択し、最後の時間単位が利用可能かどうかを確認します。 そうでない場合は、そうなるまで開始時刻を繰り上げます。 各問題の長さは短い (2 ～ 4 単位) ため、`l`≤ 10^5 の場合、この貪欲なアプローチは問題の数に対して線形時間で実行されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O((a+b+c)! * l^3) | O(l) | 遅すぎる |
 | 貪欲なスケジューリング | O((a+b+c) * log 3 + l) | O(a+b+c+l) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各問題をタプルとして表現する`(duration, type)`すべての問題を 1 つのリストに収集します。 期間の昇順で並べ替えると、短い問題から順にスケジュールを設定するようになります。 
2. 各人の利用可能な時間を 0 から開始して最小ヒープを初期化します。これにより、各人がいつ次の問題を開始できるかを追跡します。 
3. サイズのブール配列を維持する`l`どの時間単位が問題の最後の単位としてすでに使用されているかを追跡します。 これは、共有コンピュータの占有率を表します。 
4. 各問題を期間の順に繰り返します。 現在の問題については、ヒープから最も早く対応可能な人を調べます。 その人の空き時間に問題を解決するようにスケジュールを設定してください。 
5. 問題の最後の時間単位がすでに使用されているコンピュータ スロットと重なっている場合は、空いている最後の時間単位が見つかるまで開始時刻を増やし、その人が空いていることも確認します。 調整された終了時間を超えた場合`l`、問題をスキップします。 
6. 有効なスロットが見つかったら、録音します。`(person_id, start_time, end_time)`、最後の時間単位を占有済みとしてマークし、ヒープ内のその人の利用可能な時間を更新します。 
7. 考えられるすべての問題をスケジュールした後、スケジュールされたリストを終了時刻でソートし、結果を出力します。 

維持される不変条件は、2 つの問題が同じ時間単位で終了することはなく、重複する間隔で作業する人はいないということです。 これにより、スケジュールが個別のコンピューターと共有コンピューターの両方の制約を尊重することが保証されます。 常に最も早い対応可能な人を割り当て、衝突を避けるために最小限のシフトを行うことで、アルゴリズムは範囲内に収まる問題の数を最大化します。`l`。 

## Python ソリューション```python
import sys
import heapq
input = sys.stdin.readline

a, b, c, l = map(int, input().split())
problems = [(2, 'E')] * a + [(3, 'M')] * b + [(4, 'H')] * c
problems.sort()  # prioritize shorter problems

person_heap = [(0, i+1) for i in range(3)]  # (available_time, person_id)
heapq.heapify(person_heap)
computer_used = [False] * (l+1)

schedule = []

for duration, _ in problems:
    avail_time, person = heapq.heappop(person_heap)
    start = avail_time
    while start + duration <= l and computer_used[start + duration - 1]:
        start += 1
    end = start + duration
    if end > l:
        heapq.heappush(person_heap, (avail_time, person))
        continue
    schedule.append((person, start, end))
    computer_used[end-1] = True
    heapq.heappush(person_heap, (end, person))

schedule.sort(key=lambda x: x[2])
print(len(schedule))
for person, start, end in schedule:
    print(person, start, end)
```このコードは、すべての問題の統合リストを作成し、最短の期間で貪欲に問題をスケジュールします。 最小ヒープは、次に利用可能な人を効率的に見つけます。 while ループにより、問題の最後のユニットがコンピューターと競合しないことが保証され、問題がコンテスト内に収まらない場合はスキップされます。 最後に並べ替えると、終了時間が長くなり、出力順序が保証されます。
