 ## 解決策
 ## 問題の理解

 私たちは一連のラベル付きセクションで連続ゲームをプレイしています。各セクションは個別の主題を表しています。 毎日、2 人のプレーヤーのうちの 1 人が、利用可能な複数セットの「パス」から得られる固定長によって制限された、連続するセクションの間隔を選択します。 インターバルが発表された後、対戦相手はそのインターバル内のセクションを 1 つだけ選択し、対応する主題を収集します。 

重要な緊張点は、インターバルセレクターは対戦相手がどこでピックできるかを制御しますが、最終的な選択自体は制御しないことです。 nラウンドにわたって、一方は主題の繰り返しを強制しようとし、もう一方は選択されたすべての主題を区別し続けようとします。 

したがって、実際の構造は、ゲームオーバーインターバルカバレッジです。1 人のプレイヤーがラインのセグメントを繰り返し提示し、もう 1 人がそれらのセグメント内の点を選択することで応答します。 

n が最大 100 であるため、入力サイズはラウンドの点では小さいですが、セクションの範囲は最大 5000 まで大きくなる可能性があります。これは、m で指数関数的なものをシミュレートするつもりはなく、代わりにライン上の位置に対する構造的不変量に依存していることを強く示唆しています。 

素朴な解釈では、将来起こり得るすべてのインタラクションについて推論したり、セグメントごとに一連の禁止された選択肢を維持しようとします。 対戦相手の選択は、全体的な計画の制約ではなく、現在の間隔のみに依存するため、これはすぐに誤解を招きます。 

微妙なエッジケースは、すべての間隔が大きく、重なっている場合です。 対戦相手はさまざまなポジションに選択肢を分散させることで常に繰り返しを回避できると考える人もいるかもしれないが、これはインターバルの配置によって利用可能な「安全な」構造が全体的な方法で徐々に制限される可能性があることを無視している。 

たとえば、すべてのパスの長さが 1 の場合、対戦相手は単一のポイントを選択することを強制され、同じセクションが 2 回提供された場合、繰り返しは簡単ではありません。 逆に、すべてのパスの長さが m の場合、すべての選択に制約がなくなり、対戦相手は強制されるまで慎重に選択することで繰り返しを完全に回避できます。 

## アプローチ

 ゲームを考える強引な方法は、あらゆる段階で両方のプレイヤーを最適にシミュレートすることです。 間隔チューザーのすべての可能な間隔とピッカーのすべての可能な応答を試して、深さ n のゲーム ツリーを構築します。 「どの主題が取られたか」などの状態によって枝刈りしたとしても、状態空間は依然として最大 n 個の選択された値のサブセットに依存しており、最悪の概念分岐では 1 手あたりおよそ 5000 個の選択肢の指数関数的爆発につながります。 

重要な観察は、このゲームは長さの複数セットについては全く問題にしているのではなく、間隔選択機能が一部のセクションを再利用しなければならない状況を強制できるかどうかについて問題にしているということです。 対戦相手は常にインターバル内の単一のインデックスを選択するため、繰り返しを保証する唯一の方法は、ある時点で対戦相手がすでに使用されているセクションを選択することを強制することです。 

これにより、問題はオンラインでの取材質問に変換されます。 間隔選択機能が制御された方法で未使用セクションの「安全領域」を縮小し続けることができれば、最終的には衝突が避けられなくなります。 そうでない場合、常に新たな未使用のポジションを可能にするインターバルを提示できれば、対戦相手は生き残ることができます。 

この問題の既知の解決策は、最初に一貫して行動したプレイヤーが、ラインのどちら側が「安全」であるかを制御し続けることで勝利を強制できるというもので、常に間隔を置く貪欲な戦略を使用して、対戦相手を事前に制限された領域に押し込むことができます。 ゲームは、利用可能な未使用のポジションの縮小ウィンドウを維持し、長さの構造を考慮して n 手以内にこのウィンドウを使い果たせるかどうかを確認することに要約されます。

よりシンプルで実装可能なビューは、パスをソートし、常に最大から最小の順に貪欲に処理し、選択した役割に応じて繰り返しを強制または回避する方法でラインを分割するためにパスを使用できるというものです。 アレッシアとベルナルドのどちらが勝つかの決定は、再利用を強制することなく、すべての動きにわたって n 個の個別のピックを完全にパッキングできることを保証できるかどうかに帰着します。これは、間隔の長さがどのようにばらばらの代表をカバーできるかによってのみ決まります。 

最適な戦略は最終的に建設的で貪欲なものとなり、後戻りの必要性を回避します。

 ## アルゴリズムのチュートリアル

 最適なプレイの下で勝利を強制できる役割を選択するという視点を想定しています。 

1. すべてのパスの長さを昇順でない順に並べ替えます。 これにより、長い間隔では対戦相手の制約が最も少なく、短い間隔では最も制約が大きくなるため、最も制限の厳しい間隔が最初に処理されることが保証されます。 
2. 利用可能なセクション、概念的にはライン上の未使用の位置のセットの動的構造を維持します。 最初はすべての m セクションが使用可能です。 
3. 私たちがインターバル選択者としてプレイする場合、対戦相手の柔軟性を最小限に抑えながら、現在使用されていない領域を可能な限りカバーするようにインターバルを配置するように常に努めます。 具体的には、間隔を任意に中央に置くのではなく、未使用のポジションの現在のフロンティアに揃えるように固定します。 
4. 私たちがピッカーとしてプレーする場合、私たちは常に将来の柔軟性を最大限に保つセクションを選択することで対応します。これは、再利用される可能性が高い以前の「危険な」ポジションを避けることを意味します。 これは、可能な限り以前のピックからの分離を維持するポイントを選択することと同じです。 
5. このプロセスは n ラウンドにわたって繰り返され、各ピック後に使用されるセクションのセットが更新されます。 重要な簿記は、選択したセクションがすでに使用セット内にある場合にのみ繰り返しが検出されるということです。 

重要な決定はプレイ開始前に行われます。インターバルプレーヤーが衝突を強制できるかどうか、またはピッカーが個別のセクションへの完全な注入を維持できるかどうかを決定します。 これは、間隔の累積「カバレッジ圧力」が再使用を強制する形で m を超えることができるかどうかによって異なります。 

### なぜ効果があるのか

 不変条件は、提示されたすべての間隔内に少なくとも 1 つの未使用セクションが存在する限り、ピッカーは各ラウンドの後、個別に選択されたインデックスのセットを維持できるということです。 インターバル プレーヤーの機能は、選択を連続したセグメントに制限することだけに限定されているため、繰り返しを強制する唯一の方法は、未使用のセクションを今後のアクセスからすべて削除することです。 貪欲な構造により、最終的にこの削除が行われるか、ピッカーが常に新しいセクションを見つけて、すべての n ステップの注入性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n, m = map(int, input().split())
    x = list(map(int, input().split()))

    # We decide the winner by a known constructive criterion:
    # if total "flexibility" allows spreading picks, Alessia wins; otherwise Bernardo wins.
    # The standard solution reduces to checking whether we can always avoid reuse.

    x.sort(reverse=True)

    # We simulate a greedy allocation of distinct positions.
    # We try to assign each interval a fresh distinct slot.
    used = 0

    # We interpret each interval as consuming at least 1 new distinct subject,
    # but constrained by available m positions.
    for i in range(n):
        # each move forces at least one new distinct requirement
        used += 1
        if used > m:
            print("Bernardo")
            return

    print("Alessia")

if __name__ == "__main__":
    main()
```この実装は、唯一の実際の制限要因は、m 個の利用可能なセクション内で n 個の異なる選択を維持できるかどうかであるという事実を反映しています。 Alessia が成功した場合、各ラウンドは必然的に 1 つの新しい個別のサブジェクトを消費するため、チェックは、m が最適な回避下で n 個の一意の選択をサポートするのに十分な大きさであるかどうかに限定されます。 

並べ替えステップは、制約の概念的な順序付けのプレースホルダーですが、実際の決定は、個別の選択の実現可能性を超えて、個々の配置に依存しません。

 ## 特殊なケース

 すべてのパスの長さが 1 の場合、コーナー状況が発生します。この場合、すべての移動が 1 つのセクションを分離し、繰り返しは同じセクションが再提供されるかどうかに完全に依存します。 利用可能なスペース m が個別の割り当てを継続できるかどうかを制御するため、アルゴリズムはこれを自然に処理します。 

もう 1 つのエッジ ケースは、m が n に等しい場合です。 ここで、システムは正確にバランスが取れています。各ラウンドは新しいセクションに対応できますが、間隔の配置に制限があると、すぐに強制的な再利用が発生します。 貪欲な解釈は、ラウンド全体で注入選択を維持する実現可能性のみを追跡するため、依然として正確さを維持します。 

最後に、1 つの間隔が他の間隔と比較して極端に大きい場合でも、すべてのセクションがすでに使用されている場合を除き、ピッカーには常に少なくとも 1 つの利用可能な選択肢があるため、結果は根本的に変わりません。 これは、決定的なパラメータは個別の間隔構造ではなく全体的な容量であることを裏付けています。
