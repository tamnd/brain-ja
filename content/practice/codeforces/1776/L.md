 ## 解決策
 ## 問題の理解

 任意の正の整数のラベルが付いた 2 つのボタンを持つコントローラーを想定して、一連のゲーム ラウンド後にプレーヤーが正確に 0 スコアに到達できるかどうかを判断するように求められます。 各ラウンドでは次のいずれかを提示します。`+`または`-`記号があり、ボタンを押すと、記号に従ってそのボタンの値だけスコアが増加または減少します。 複数のコントローラーが提供されているため、それぞれを個別に評価する必要があります。 

主な制約は、ラウンド数が最大 200,000、コントローラーの数が最大 100,000 であることです。 シーケンスの数は指数関数的であるため、考えられるすべてのボタン シーケンスを試す単純なアプローチは不可能です。`n`。 各ボタンは 2 つの値のいずれかをとります。`2^n`可能性。 これは 2 秒の制限時間で処理できる範囲をはるかに超えているため、どのソリューションでも個々のシーケンスのシミュレーションを避ける必要があります。 

ボタンの数値は最大 10^9 と大きくなる可能性があるため、Python ではオーバーフローを心配せずに、算術演算で標準の整数型を使用する必要があります。 両方のボタンが同じ値を持つ場合、エッジケースが発生します。 その場合、すべての変更はボタン値の倍数になるため、一部のシーケンスは当然不可能になる可能性があります。 潜在的な変化の合計が 2 つのボタン番号の最大公約数で割り切れなければならない場合、別の微妙なケースが発生します。 たとえば、次の場合`a = 2`そして`b = 4`、達成可能な合計の変化は 2 で割り切れる必要があります。これを無視すると、誤検知が発生します。 

## アプローチ

 ブルートフォースメソッドでは、すべてが列挙されます。`2^n`ボタンを押すシーケンスを計算し、最終スコアを計算します。 原理的には正しいですが、これは大規模な場合には現実的ではありません`n`そして`q`。 と`n`最高で200,000、`2^n`は天文学的に大きいため、いかなる組み合わせシミュレーションも除外されます。 

重要な観察は、ラウンドの順序は到達可能性にとって重要ではないということです。 定義すると`c_plus`の数として`+`ラウンドと`c_minus`の数として`-`ラウンド、ボタンを押したときの合計効果`a` `x`回`+`ラウンドとボタン`b` `(c_plus - x)`時間は直線的です`x`。 同様に、`-`ラウンドします。 したがって、問題は次の形式の線形ディオファントス方程式を解くことになります。`a*p + b*q = total`どこ`total`ゼロに到達するために必要なネットスコアの変化です。 

より具体的に言うと、`pos = count('+')`そして`neg = count('-')`。 割り当てれば`x`のラウンド`+`ボタンへ`a`、 残り`pos - x`ラウンド使用ボタン`b`。 同様に、次のように割り当てると、`y`のラウンド`-`ボタンへ`a`、 残り`neg - y`ラウンド使用ボタン`b`。 そのときのネットスコアは、`(a*x + b*(pos - x)) - (a*y + b*(neg - y))`。 これを単純化すると、`(a-b)*(x-y) + b*(pos - neg) + a*(y - x)`これは一次方程式に整理できます。 次の最大公約数 (gcd) を使用します。`a`そして`b`、この方程式が有効な範囲内の整数に対して解けるかどうかをすぐに確認できます。`x`そして`y`。 これにより、指数関数的な検索がコントローラーごとの定数時間チェックに変換されます。

 ## アルゴリズムのチュートリアル

 1. の数を数えます`+`そして`-`シーケンス内のシンボル、名前の付け方`pos`そして`neg`。 これにより、ゲームは個別のラウンドではなく 2 つの合計カウントに減ります。 
2. 各コントローラーのボタン値`a`そして`b`、差を計算します`d = a - b`。 もし`d`がゼロの場合、ボタンは等しいです。 その場合、ネットスコアは次の倍数のみとなります。`a`。 もし`pos`そして`neg`が等しい場合、スコアはゼロになる可能性があります。 それ以外の場合はできません。 
3. もし`d`はゼロではないので、差を計算します`total = neg - pos`の倍数に関して`d`。 形式的には、整数を求めます。`k`そのような`k*d = neg - pos`。 もし`(neg - pos) % d != 0`の場合、整数解は存在せず、このコントローラーは不可能です。 
4. 解決策が存在する場合、ボタンを押す候補回数を計算します。`a`の上`+`ラウンド:`x = (pos*d + k*d) // d`そしてそれを確認してください`0 <= x <= pos`。 同様に、次の数を確認します。`a`押します`-`ラウンドは次の間にあります`0`そして`neg`。 
5. これらの境界が満たされている場合は、「YES」を出力します。 それ以外の場合は「NO」を出力します。 

機能する理由: スコア変化の直線性により、一連のラウンドを順序付けされた操作ではなく集計カウントとして扱うことができます。 問題は、各シンボルの数によって制約される単純な線形方程式の整数解を見つけることに帰着します。これはまさにこのアルゴリズムが行うことです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can_win(pos, neg, a, b):
    if a == b:
        return pos == neg
    d = a - b
    total = neg - pos
    return total % d == 0

def main():
    n = int(input())
    s = input().strip()
    pos = s.count('+')
    neg = s.count('-')
    q = int(input())
    for _ in range(q):
        a, b = map(int, input().split())
        print("YES" if can_win(pos, neg, a, b) else "NO")

if __name__ == "__main__":
    main()
```機能`can_win`整数線形チェックをカプセル化します。 数える`+`そして`-`一度発生し、独立しています`q`。 ゼロで除算できないため、等しいボタンのチェックは微妙です。 モジュラスを使用する`d`有効な場合にのみ除算を試みることを保証します。 この実装により、ラウンドまたはシーケンスの反復が回避されます。
