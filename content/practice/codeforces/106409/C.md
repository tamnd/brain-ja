 ## 解決策
 # 問題の理解

 このタスクでは、位置を選択し、その位置から文字列の末尾までのすべての文字を反転するという 1 つの操作のみを使用して、ペンギンゴーファー タイルの 1 つの文字列を別の文字列に変換するように求められます。 選択した位置のシーケンスを出力するか、シーケンスが存在しないことを報告する必要があります。 元の問題の制約では、長さ 1000 までの文字列が許可され、最大 2000 回の操作が必要です。 

変換が失敗する唯一の理由は、位置を反転しても複数の文字セットが変更されないことです。 2 つの文字列に含まれる各文字の数が同じでない場合、一連の反転は役に立ちません。 長さがわずか 1000 であるため、二次アプローチも引き続き許容されますが、演算制限により、多くの不必要に長い構造が排除されます。 

よくある間違いは、すべてのターゲット文字がソース内のどこかに出現するかどうかだけをチェックすることです。 周波数が重要です。 たとえば、入力の場合```
3
abc
abb
```正しい出力は`-1`最初の文字列には 1 つがあるため、`c`ターゲットには何もありませんが、`c`。 すべてのターゲット文字が存在することを確認するだけの不注意なアプローチは、それを誤って受け入れてしまいます。 

もう 1 つの特殊なケースは、文字列がすでに等しい場合です。 例えば、```
1
m
m
```正しい出力は`0`。 無駄な反転を生成することは数学的には依然として有効ですが、操作が無駄になり、実装が複雑になる可能性があります。 

最後の微妙なケースは、文字の繰り返しです。 例えば、```
4
aabc
cbaa
```を含む位置には複数の選択肢があります`c`。 等しい文字は置き換え可能であるため、一致するものを選択すると機能します。 現在の位置ではなく値によって誤って文字を追跡する実装では、間違ったタイルが移動する可能性があります。 

## アプローチ

 この問題を考える強引な方法は、考えられるサフィックスの逆転を検索し、開始文字列からターゲット文字列までのパスを見つけようとすることです。 これは正しいです。すべての有効な操作シーケンスが検索空間内のどこかで表されるからです。 ただし、可能な状態の数は膨大です。 長さが 1000 の場合、すべての順列を保存することさえ不可能であり、一連の操作を試行することは指数関数的に増加します。 

有益な観察は、サフィックスを反転すると、選択した文字を現在のサフィックスの前に移動できるということです。 位置を固定しているとします`i`左から右へ。 前の位置`i`すでに正しいので、再度変更することはできません。 から始まる反転`i`前にプレフィックスを残すため、まさにそれが行われます`i`手付かずの。 

位置に文字が必要な場合`i`現在その位置にいます`p`未完成のサフィックス内では、2 つの操作で十分です。 まず、で始まるサフィックスを逆にします。`p`。 これにより、目的の文字が最後に移動します。 次に、次から始まるサフィックスを逆にします。`i`。 目的の文字は接尾辞の末尾からその接尾辞の最初の位置に移動します。これは正確に`i`。 

ブルートフォース手法が機能するのは、その操作が文字を再配置するのに十分強力であるためです。 パスを構築するのではなく検索するため、失敗します。 上記の観察により、問題全体は、各位置に最大 2 つの操作が必要な貪欲な配置プロセスに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | 指数 | 遅すぎる |
 | 貪欲な建設 | O(n²) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 両方の文字列内のすべての文字の出現数をカウントします。 カウントが異なると目的の配置に到達できないため、出力します。`-1`。 反転は位置を並べ替えるだけであり、文字を作成したり削除したりすることはありません。 
2. 位置を左から右に処理します。 ステップで`i`、前のすべての位置`i`にはすでに最後の文字が含まれているため、今後の操作では残りの接尾辞のみが操作されます。 
3. 任意の位置を検索`p`と`p >= i`現在の文字が位置のターゲット文字と等しい場合`i`。 
4. もし`p`すでに`i`、操作は必要ありません。 正しいタイルはすでに配置されています。 
5. それ以外の場合は、次から始まるサフィックスを逆にします。`p`で始まるサフィックスを逆にします。`i`。 最初の反転により必要なタイルが残りの部分の最後に移動し、2 番目の反転により前面に移動されます。 
6. すべての位置が固定されるまで続けます。 操作の数は各ポジションで最大 2 回であるため、2000 を超えることはありません。 

なぜ効果があるのか:

 不変条件は、位置を処理する前の条件です。`i`、前のすべての位置`i`すでにターゲットと一致しており、今後変更されることはありません。 で始まるサフィックスの反転`i`それらの以前の位置に影響を与えることはできません。 2 回の逆転の動きにより、必要な文字が次の位置に配置されます。`i`不変式を維持しながらプロセスを繰り返すと、文字数が許す限り最終的にターゲット文字列が生成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(input().strip())
    b = input().strip()

    if sorted(a) != sorted(b):
        print(-1)
        return

    ans = []

    for i in range(n):
        if a[i] == b[i]:
            continue

        pos = i
        while a[pos] != b[i]:
            pos += 1

        if pos != i:
            ans.append(pos + 1)
            a[i:pos + 1] = a[i:pos + 1][::-1]

            ans.append(i + 1)
            a[i:] = a[i:][::-1]

    print(len(ans))
    for x in ans:
        print(x)

if __name__ == "__main__":
    solve()
```最初の比較では、ソートされた文字列が使用されます。これは、唯一不可能な状況が異なる文字マルチセットであるためです。 このチェックに合格すると、必要な文字はすべて残りのサフィックスのどこかに存在します。 

メインループは一度に 1 つのインデックスを修正します。 の検索`pos`まだ確定されていない位置のみを参照するため、すでに正しい文字が乱されることはありません。 

Python の 2 つのスライス反転は、2 つの接尾辞操作を直接シミュレートします。 操作の説明では 1 から始まる位置が使用されるため、保存されるインデックスは 1 から始まります。保存される操作の最大数は次のとおりです。`2 * (n - 1)`、これは必要な制限に適合します。
