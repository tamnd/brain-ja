 ## 解決策
 ## 問題の理解

 長さのバイナリ文字列を構築するように求められます。$n$、正確に含む$k$1 つは、長さ 3 のサブシーケンスを含む追加の構造的制約を伴うものです。 インデックスのすべてのトリプルの中で$i < j < k$、パターン「101」を形成する数と「010」を形成する数を数えます。 目標は、これら 2 つのカウントが等しい文字列を生成することです。 

ここでのサブシーケンスとは、文字を自由にスキップできることを意味するため、重要なのは隣接性ではなく、相対的な順序です。 これにより、条件はローカル パターンではなく、0 と 1 のグローバルな配置に敏感になります。 

制約は小さいです。$n \le 100$そして$t \le 500$。 これにより、これを超えて漸近的にタイトなものは必要ないことがすぐにわかります。$O(n^2)$テスト ケースごとに、さらに三次推論でも理解できます。 ただし、構築の問題は、明示的にカウントするのではなく、貪欲なパターンまたは構造的なパターンを示唆しています。 

エッジケースは次の場合に発生します。$k = 0$、$k = n$、またはいつ$k = 1$または$k = n-1$。 このような場合、「101」または「010」の少なくとも 1 つは両方のシンボルが交互の位置に 2 回出現する必要があるため、パターンの 1 つは不可能です。 たとえば、すべての文字が同一の場合、両方のカウントはゼロになるため、均一な文字列はすべて有効になります。 不注意なアプローチでは、あまりにも積極的に交互にサブシーケンスを「バランス」させようとする可能性がありますが、それは不必要であり、必要な 1 の数に違反する可能性があります。 

もう 1 つの微妙なエッジ ケースは、非常にまばらな場合、または非常に密な場合です。 たとえば、次の場合$k = 1$、1 が 1 つ含まれる文字列には両方のパターンが出現しないため、どのような配置でも機能します。 同様に、$k = n-1$。 

## アプローチ

 ブルートフォースのアイデアは、次の長さのバイナリ文字列をすべて生成することです。$n$まさに$k$1 つずつ、すべてのインデックスのトリプルを反復処理して、「101」と「010」のサブシーケンスの数を計算します。 部分列を直接カウントするには$O(n^3)$、そして、あります$\binom{n}{k}$候補文字列。 たとえ$n = 100$、これは天文学的に大きいため、ブルートフォースは完全に実行不可能になります。 

重要な観察は、この問題では実際には 2 つのカウント間の正確な差を制御する必要がないということです。 必要なのはそれらが等しいことだけです。 強力な構造の単純化は、両方のカウントを強制的にゼロにできることです。 これは、長さ 3 の交互パターンをすべて完全に削除した場合に発生します。 

バイナリ文字列には、0 と 1 が順番に 2 回交互にならない場合に限り、「101」または「010」のサブシーケンスがありません。 これは、文字列がブロック内の単調である場合 (すべて 0 の後にすべて 1 が続くか、すべて 1 の後にすべて 0 が続く) に保証されます。 このような文字列では、トリプルにはシンボル タイプが 1 つだけ含まれるか、遷移が 1 つだけ含まれるため、どちらのパターンも出現できません。 

これにより、タスクは純粋な構築問題に縮小されます。$k$ものと$n-k$単一の連続したブロック構造内のゼロ。 「000…111…」と「111…000…」は両方とも機能し、両方のサブシーケンス数がゼロであるため、両方とも必要な等価性を満たします。 

これが重要な削減です。2 つの組み合わせのカウントのバランスをとる代わりに、両方を同時に回避します。

 ## アルゴリズムのチュートリアル

 1.読む$n$そして$k$。 これらは、最終的な文字列に出現する必要がある 1 の数とその全長を定義します。 
2. 以下から構成される文字列を構築します。$k$連続した「1」文字。 これにより、後で修正する必要がなく、カウント制約がすぐに満たされることが保証されます。 
3. 追加$n-k$連続した「0」文字。 これにより、シンボル間に単一の遷移境界が作成されます。 
4. 結果の文字列を出力します。 

すべてを最初に置くかどうかは任意です。 すべてのゼロを最初に置くことも同様に有効です。これは、条件が絶対的な順序ではなく、交互形式のサブシーケンスのみに依存するためです。 

### なぜ効果があるのか

 構築された文字列には、シンボル間の遷移が最大 1 つあります。 0 と 1 の間で切り替わる長さ 3 のサブシーケンスには、0→1→0 または 1→0→1 のいずれかの順序で少なくとも 2 つの遷移が必要です。 文字列全体で遷移が 1 つだけ存在するため、どちらのパターンも形成できません。 したがって、両方のカウントはゼロであり、等しくなります。 

また、再配置せずに明示的に 1 を配置するため、この構築では 1 の正確な数も簡単に強制されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, k = map(int, input().split())
    # place all 1s first, then 0s
    print("1" * k + "0" * (n - k))
```コードはモノトーン ブロック構造を直接実装しています。 唯一の微妙な点は、カウントが正確に一致することを確認することです。文字列の長さは固定されているため、一度$k$1 が配置されている場合、残りの位置は 0 でなければなりません。 

構造によってサブシーケンス条件が自動的に保証されるため、それ以上の検証や計算は必要ありません。 

## 実用的な例

 ### 例 1

 入力:$n = 4, k = 2$私たちは以下を構築します:

 | ステップ | 文字列の状態 |
 | --- | --- |
 | 開始 | "" |
 | 1 を配置 | 「11」 |
 | 0 を配置 | 「1100」 |

 結果の文字列にはちょうど 2 つの文字列が含まれ、1 から 0 への遷移が 1 つあるため、長さ 3 の交互のサブシーケンスは存在しません。 したがって、「101」と「010」のカウントは両方ともゼロです。 

### 例 2

 入力:$n = 5, k = 3$| ステップ | 文字列の状態 |

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    t = int(sys.stdin.readline())
    out = []
    for _ in range(t):
        n, k = map(int, sys.stdin.readline().split())
        out.append("1" * k + "0" * (n - k))
    return "\n".join(out) + "\n"

 ## 特殊なケース

 いつ$k = 0$、アルゴリズムの出力$n$ゼロ。 何もないので、「101」と「010」の両方の部分列は不可能です。 この構築では、ゼロが続く空の 1 ブロックが生成されますが、それでも最大 1 つの遷移の不変条件は満たされます。 

いつ$k = n$、出力は$n$もの。 繰り返しますが、ゼロは存在しないため、両方のサブシーケンス カウントはゼロになります。 構造は遷移のない単一のブロックに縮退します。 

いつ$k = 1$の場合、文字列は「1000…0」です。 長さ 3 のサブシーケンスは、1 が 1 つしか出現しないため、交互に配置することはできず、両方のパターンが存在しません。 同じ推論が対称的に当てはまります。$k = n-1$。
