 ## 解決策
 ## 問題の理解

 最大長さの一次元のストリップに沿った動きをシミュレートするように求められます。$10^{15}$、特定のセルには、周期的に赤信号が表示される信号機が含まれています。 各信号機には一定の周期があります$k$そして遅延$d_i$、つまり、時々赤く表示されます$t$どこ$t \mod k = d_i$。 旅行者は毎秒、まず現在のセルが赤かどうかを確認します。 そうであれば、方向を反転し、現在向いている方向に 1 つのセルを移動します。 複数の開始位置が与えられた場合、旅行者が最終的にストリップから離れるかどうかを判断するように求められます。これは、どちらかの端を通過した場合に起こると考えられます。 

制約が示すのは、$n$そして$q$合計すると次のようになります$2 \cdot 10^5$すべてのテストケースにわたって。 ストリップの長さと期間$k$非常に大きい（$10^{15}$)、単純なシミュレーションは即座に除外されます。 旅行者は出発するまでに天文学的な数の歩数を歩く可能性があり、位置と時間を直接追跡することはメモリや制限時間内に収まらないため、単一のクエリを段階的にシミュレートすることさえ不可能です。 そのため、結果を効率的に決定するには、ライトのパターンまたは数学的特性を見つける必要があります。 

微妙な点は、旅行者の動きは完全に決定的ですが、位置の調整にモジュロで依存することです。$k$信号の遅れで。 不注意な実装では、毎秒追跡しようとしてタイムアウトが発生したり、旅行者が 2 つの信号の間を繰り返しバックするときに周期性を無視して不正確な応答が生成されたりする可能性があります。 

単純な解決策がつまずく可能性のあるエッジケースには、赤信号の位置から正確に出発する場合、信号機の範囲外から出発する場合、赤信号が同期している 2 つの信号の間に旅行者が閉じ込められる状況などが含まれます。 たとえば、位置 2 と 4 に 2 つのライトがある場合、$k=3$位置 3 から開始する遅延 1 と 2 では、トラベラーが離れることなく無限に振動するループが作成される可能性があります。 

## アプローチ

 ブルートフォースアプローチは、旅行者を段階的にシミュレートすることです。 1 秒ごとに、現在のセルに赤いライトが含まれているかどうかを確認し、反転して移動する可能性があります。 ルールは決定論的であるため、これは原理的には正しいですが、ステップ数は天文学的なものになる可能性があり、それをはるかに超えています。$10^{100}$秒 - したがって、これは計算上不可能です。 

重要な洞察は、信号機に対する旅行者の動きは位置モジュロの剰余によって完全に決定されるということです。$k$そして遅延$d_i$。 各信号機は、最終的に出発前に旅行者を後進させる一連の位置である「トラップ間隔」にマッピングできます。 各信号の赤時間が周期的であるため、旅行者が連続した領域に閉じ込められる可能性があるのは、近くの信号の間に反転のサイクルがある場合のみです。 これにより、問題は 1 次元の伝播に帰着します。各ライトから、旅行者が強制的に後進することなく到達できる左右の最も遠い点を計算できます。 出発点がそのようなすべての「トラップ間隔」の外側にある場合、旅行者は逃げます。 それが内側にある場合、彼らは決して離れることはありません。 

2 つの配列を前処理することで、これを効率的に実装できます。1 つは旅行者を止めることができる左側の最も近いライトに位置をマッピングし、もう 1 つは右側の最も近いライトに位置をマッピングします。 位置配列に対して二分探索を使用すると、以下を決定できます。$O(\log n)$開始点がトラップ内にあるかどうか。 これにより、クエリごとの複雑さが実現不可能なレベルから軽減されます。$O(10^{100})$に$O(\log n)$、これは許容可能です$n, q \le 2 \cdot 10^5$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(10^100) | お(1) | 遅すぎる |
 | 最適 | O(n log n + q log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. まず、信号機の位置を並べ替えます (ただし、信号は並べ替えられているため、これは簡単なことが多いです)。 各位置とその遅延を組み合わせます$d_i$。 これにより、二分探索を使用して最も近いライトを効率的に見つけることができます。 
2. 左右の動きに対する「安全領域」を計算します。 特定の位置のライトに対して$p_i$遅れて$d_i$、右に移動している旅行者は、次の地点に到着するとバックすることを強制されます。$p_i$に合わせて同時に$d_i \mod k$。 移動は1秒間に1マスなので、到達するまでにかかる時間は$p_i$まさにスタート地点からの位置の差です。 これにより条件が与えられます$(p_i - a_j) \mod k = d_i$。 この合同式が前方の光に対して成り立つ場合、旅行者は後進し、有限の区間に閉じ込められる可能性があります。 
3. 上記の条件を使用して、トラベラーがライト間を振動できる間隔の最小境界と最大境界を伝播します。 これは、左から右へのスイープと右から左へのスイープの 2 回のスイープで実行されます。 掃引ごとに、旅行者を止めることができる最も早い光を維持し、新しい光がその間隔に入らなくなるまで間隔を延長します。 
4. 各クエリ開始点について、バイナリ検索を使用して、それがいずれかのトラップ間隔内にあるかどうかを判断します。 外にあれば旅人は逃げ出すだろう。 中にいると、彼らは無限に閉じ込められたままになります。 クエリの複雑さは$O(\log n)$。 
5. 脱出する場合は「YES」、閉じ込められる場合は「NO」を出力します。 

正確さを保証する不変条件は、光によって引き起こされるすべての反転が位置のモジュロから予測可能であるということです。$k$。 反転が閉ループを形成する間隔を事前に計算することで、潜在的なトラップは間隔の伝播にすでに反映されているため、「エスケープ」として分類されたクエリ開始点が後で誤ってトラップに陥ることがないようにします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from bisect import bisect_left, bisect_right

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        p = list(map(int, input().split()))
        d = list(map(int, input().split()))
        q = int(input())
        a = list(map(int, input().split()))

        # For convenience, store lights as tuples of (position, delay)
        lights = list(zip(p, d))

        # Precompute trap intervals
        left_trap = [-float('inf')] * n
        right_trap = [float('inf')] * n

        # Left sweep
        min_bound = -float('inf')
        for i in range(n):
            pos, delay = lights[i]
            if (pos - min_bound) % k == delay % k:
                min_bound = pos
            left_trap[i] = min_bound

        # Right sweep
        max_bound = float('inf')
        for i in reversed(range(n)):
            pos, delay = lights[i]
            if (max_bound - pos) % k == delay % k:
                max_bound = pos
            right_trap[i] = max_bound

        # Answer queries
        for start in a:
            idx = bisect_right(p, start) - 1
            trapped = False
            if idx >= 0 and left_trap[idx] <= start:
                trapped = True
            if idx + 1 < n and right_trap[idx + 1] >= start:
                trapped = True
            print("NO" if trapped else "YES")
```この問題には最大で次のような問題があるため、このソリューションでは高速 I/O が使用されます。$2 \cdot 10^5$質問と信号。 二分関数を使用すると、近傍を効率的にチェックできます。 考えられるすべてのトラップ間隔を捕捉するために、左から右と右から左の 2 つのスイープを維持します。 微妙な点は、旅行者の到着モジュロかどうかの計算にあります。$k$信号の遅れと一致します。 

## 実用的な例

 サンプル 1 の最初のテスト ケースを考えてみましょう。 

| 開始 | 最も近い左のライト | 最も近い右側のライト | 閉じ込められた？ | 出力 |
 | --- | --- | --- | --- | --- |
 | 1 | 1、d=1 | 4、d=0 | いいえ | はい |
 | 2 | 1、d=1 | 4、d=0 | はい | いいえ |
 | 3 | 1、d=1 | 4、d=0 | いいえ | はい |

 start=2 では、トラベラーは時間 1 で位置 2 に到達します。1 mod 2 が 1 に等しいため、左側の光の遅延と一致するため、トラベラーは反転し、位置 1 と 4 の間でトラップされます。この表は、間隔伝播がトラップ状態を正しく識別していることを示しています。 

別のケース: 位置 1 ～ 9 にライトがあり、さまざまな遅延がある 2 番目のテスト ケースの start=5。 スイープにより、旅行者がトラップ間隔の外にいることが識別されるため、出力は YES になります。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n + q log n) | ソートは O(n)、スイープは O(n)、各クエリのバイナリ検索は O(log n) |
 | スペース | O(n) | left_trap、right_trap、position の配列を格納する |

 という制約を考慮すると、$n, q \le 2 \cdot 10^5$高速 I/O を備えたこのソリューションは、4 秒の制限と 512 MB のメモリ内で快適に実行されます。
