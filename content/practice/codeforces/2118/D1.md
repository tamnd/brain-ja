 ## 解決策
 ## 問題の理解

 までの長さの一次元のストリップがあります。$10^{15}$、それに沿って特定のセルに信号機が含まれています。 それぞれの光には一定の周期があります$k$そして遅延$d_i < k$、時々赤くなります$l \cdot k + d_i$整数の場合$l \ge 0$。 それ以外の場合は、ライトは緑色です。 プレーヤーは特定のセルから開始し、現在向いている方向 (最初は正) に 1 秒あたり 1 歩ずつ移動します。 赤信号に遭遇すると、プレイヤーはすぐに向きを変え、反対方向に進み続けます。 

タスクは、複数の開始位置について、プレーヤーが最終的にストリップから期限内に離れるかどうかを判断することです。$10^{100}$秒。 開始位置が大きいにもかかわらず、信号とクエリの数が少ないため、ストリップは事実上境界がありません ($n, q \le 500$）。 

重要な課題は、ストリップの長さが膨大であるため、毎秒の単純なシミュレーションが不可能であることです。 また、プレイヤーが信号の間で跳ねて閉じ込められる可能性があるため、生の動きではなくサイクルと反転について推論する必要があります。 単純なシミュレーションでは簡単に超えてしまう可能性があります$10^{15}$プレーヤーが行き詰まった場合はステップを実行します。そのため、周期性と相対的なタイミングに基づいた、より抽象的なアプローチが必要です。 

プレイヤーが信号待ちでスタートする場合、エッジケースが発生します。 その瞬間に赤信号が発生すると、プレーヤーはすぐに引き返します。 そうでない場合、プレーヤーは前進します。 たとえば、次の位置から開始します。$d_i = 0$そして$k = 2$、開始時間が赤色のフェーズと一致した場合、不注意なシミュレーションにより前方への移動が想定され、誤って脱出が報告される可能性があります。 

## アプローチ

 ブルートフォース手法では、プレイヤーの動きを秒単位でシミュレートします。 各ステップで、現在のセルに赤いライトが付いているかどうかを確認し、必要に応じて方向を反転し、セルを 1 つ移動します。 このアプローチは問題のルールを直接実装しているため正しいですが、距離が長い場合は失敗します。 1 つのテスト ケースには最大で次のものが必要になります。$10^{15}$ステップが発生し、実行不可能になります。 

最適なアプローチは、信号機の周期性を利用します。 各ライトは毎回プレイヤーにのみ影響します。$k$によると秒$d_i$。 したがって、システム全体は周期的なモジュロです。$k$。 各セルを、プレーヤーが後戻りせずに移動できる「安全な時間間隔」で表すことができます。 プレーヤーは、すべてのセルではなく、信号間の遷移をシミュレートするだけで済みます。 ライトのあるセルである「クリティカル ポジション」の概念を定義します。 プレイヤーがその方向に移動するすべてのライトを超えた点に到達すると、逃げます。 逆に、プレイヤーが赤のタイミングで逆転を強制される 2 つのライトの間に閉じ込められた場合、ループに入り、決して脱出することはできません。 

赤の反転が起こる前に、光ごとに到達可能な最小および最大の位置を剰余で事前計算できます。$k$。 次に、クエリごとに、その位置から開始して最終的にストリップの終端を超えるかどうかを確認します。これは次のように実行できます。$O(n^2)$以来$n \le 500$。

 | ブルートフォース | O(までステップアップ$10^{15}$) | お(1) | 遅すぎる |
 | 最適 | O(n^2 + n q) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 信号機を位置ごとに並べ替えます。 これにより、左右の隣接物を効率的に見つけることができます。 
2. 各信号機について、その有効な「赤のモジュロ k 倍」を計算します。 遅延で赤信号$d_i$毎回繰り返す$k$秒なので追跡するだけで済みます$t \bmod k$逆転のために。 
3. 2 つの配列を定義します。`left_reachable`そして`right_reachable`、プレーヤーが赤信号に強制的に戻されることなく左または右に移動できる最も遠いセルを追跡します。 
4.初期化`left_reachable[i]`そして`right_reachable[i]`ライト自身の位置へ。 
5. 左から右にスイープします。信号ごとに、プレーヤーが不都合な段階で赤信号に当たらずに右に移動し続けることができるかどうかを確認します。 アップデート`right_reachable[i]`一番遠くに届く正しい光へ。 
6. 同様に右から左にスイープして計算します`left_reachable`。 
7. クエリごとに、最初の移動方向に最も近いライトを見つけます。 プレーヤーがその方向のすべてのライトを超えて開始した場合は、YES を返します。 2 つのライトの間に閉じ込められた場合、`left_reachable`そして`right_reachable`間隔には開始位置が含まれます。NO を返します。 
8. それ以外の場合、最終的にすべてのライトを越えて移動できる間隔であれば、YES を返します。 

機能する理由: このアルゴリズムは、信号機の赤サイクルによって定義される間隔に基づいてプレーヤーの動きをモデル化します。 赤い時間がピリオドで繰り返されるので$k$、間隔はすべての可能な反転を捕捉します。 スイープにより、隣接するライト間の反転の連鎖反応が確実に考慮されます。 開始位置は、これらの間隔の外側 (エスケープ) またはループの内側 (トラップ) のいずれかであり、すべての可能性を網羅します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        p = list(map(int, input().split()))
        d = list(map(int, input().split()))
        q = int(input())
        a = list(map(int, input().split()))

        left = [p[i] for i in range(n)]
        right = [p[i] for i in range(n)]

        # Right sweep
        for i in range(n-1):
            dist = p[i+1] - p[i]
            delta = (d[i] + dist) % k
            if delta != 0:
                right[i+1] = right[i+1]
            else:
                right[i+1] = max(right[i+1], right[i])

        # Left sweep
        for i in range(n-1, 0, -1):
            dist = p[i] - p[i-1]
            delta = (d[i] + dist) % k
            if delta != 0:
                left[i-1] = left[i-1]
            else:
                left[i-1] = min(left[i-1], left[i])

        for pos in a:
            if pos < p[0]:
                print("YES")
            elif pos > p[-1]:
                print("YES")
            else:
                idx = 0
                while idx < n and p[idx] < pos:
                    idx += 1
                if left[idx-1] <= pos <= right[idx]:
                    print("NO")
                else:
                    print("YES")

if __name__ == "__main__":
    solve()
```コードは、テスト ケースと信号機データを読み取ることから始まります。 次に、モジュロを使用して到達可能な間隔を事前計算します。$k$周期性。 左右のスイープにより、赤色光の効果が伝播されます。 各クエリは、開始位置がこれらの間隔の外側にあるか内側にあるかをチェックします。 境界チェックにより、最初の信号の前または最後の信号の後の位置が自動的に YES になることが保証されます。
