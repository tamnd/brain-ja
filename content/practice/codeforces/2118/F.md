 ## 解決策
 ## 問題の理解

 整数の配列が 1 つあるかどうかを尋ねられます。`a`、別の配列に変換できます。`b`、2種類の操作を使用します。 最初の操作は循環左シフトで、すべての要素を 1 つ左に移動し、最初の要素を最後にラップします。 2 番目の操作は、数値の差が 2 以上である場合、隣接する要素間の交換です。どちらの配列にも 1 から 1 までのすべての整数が含まれます。`m`少なくとも 1 回は入力されているため、番号が欠落していることはありません。 配列は次よりも長くなる可能性があります`m`、つまり、一部の数字は繰り返すことができます。 

タスクは、各テスト ケースについて、目標に到達できるかどうかを判断することです。`b`から`a`これらの操作を使用して。 と`n`すべてのテスト ケースで最大 500,000 要素、合計 500,000 要素の場合、考えられるすべてのスワップまたはシフト シーケンスを考慮したソリューションは実行不可能です。 考えられるすべてのスワップをシミュレートする素朴な総当たりでは、階乗または指数関数的な時間がかかり、許容される制限をはるかに超えます。 

繰り返しの数字が関係する場合、明らかではないエッジケースが発生します。 たとえば、次のように考えてみましょう`a = [1,1,2]`そして`b = [1,2,1]`。 不注意なアプローチでは、数値の繰り返しによって一部のスワップがブロックされることを考慮せずに、各ペアの相対的な順序をチェックしようとする可能性があります。 ここで、アルゴリズムは繰り返される数字とその位置を慎重に処理する必要があります。 もう 1 つの微妙な点は、数値が 1 だけ異なる場合に発生します。つまり、スワップが禁止されているため、マルチセットですべての数値が一致しても、一部の順列に到達できません。 のような小さな配列`a = [1,2]`、`b = [2,1]`と`m = 2`また、スワップでは 1 の差を埋めることができないことも明らかになります。 

## アプローチ

 ブルート フォース アプローチでは、考えられるすべての操作シーケンスをシミュレートします。 シフトごとに配列を回転し、可能な交換ごとに、許可されている場合は隣接する要素の交換を試みることができます。 このアプローチは、許可された操作によっていくつかの順列が生成される可能性があるため機能しますが、次の操作が行われるとすぐに失敗します。`n`一握りを超えています。 と`n = 500,000`、要素ごとに 1 つのスワップを考慮しても、`O(n)`操作ごとに、すべてのシーケンスを探索することは天文学的なものになります。 

重要な洞察は、スワップでは 2 以上異なる要素のみが位置を交換できるということです。 したがって、1 だけ異なる要素は互いに通過できません。 これは、同じ「値モジュロ隣接性」の数値の相対的な順序が維持されることを意味します。 具体的には、数値をクラスにグループ化し、同じクラスの要素間で自由に交換したり、より大きな差を付けて交換したりできますが、1 つだけ異なる要素は互いにブロックします。 実際には、現在残っている配列の最小の数値が次の場所に現れる必要があります。`b`許可されたスワップやシフトを介して到達可能な位置にあります。 数値ごとの頻度マップと単調スタックまたはキューを使用して、どの数値が「先頭」にあるかを追跡します。`a`これを効率的にします。 さらに、循環シフトを使用すると、先頭の任意の数値が最終的に最初の要素になるように配列を回転できるため、交換の柔軟性が得られます。 

この観察により、問題は数値を最小から最大の順に処理することになり、各数値が次のように処理されることが保証されます。`b`に対応する番号が存在します。`a`スワップ制限に違反することなくその位置に移動できます。

 ## アルゴリズムのチュートリアル

 1. テストケースごとに配列を読み取ります。`a`そして`b`および個別の要素の数`m`。 各数値の頻度カウントを維持します。`a`。 
2. 1 から 1 までの各番号のキューまたはリストを作成します。`m`その数値が出現するインデックスを含む`a`。 これにより、次に必要な数値がどこにあるかを効率的に見つけることができます。 
3. 変数を初期化する`cur_min`現在移動可能な最小の数値を追跡して一致させる`b`。 1 だけ異なる数値は交換できないため、これは重要です。そのため、常に利用可能な最小の数値を大きい数値の前に移動する必要があります。 
4. 反復処理する`b`左から右へ。 それぞれについて`b[i]`で、その番号のポジションのキューを確認してください。`a`。 フロントインデックスが現在の位置に対応している場合は、`a`または、以下の数字を交差させずに前に進めることができます。`b[i]`、キューから削除し、頻度を減らします。 
5. いつか次の瞬間に`b[i]`必要な番号がまだ配置されていない小さい番号によってブロックされているため、その位置に移動できない場合、このテスト ケースでは「NO」が出力されます。 
6. すべての要素が`b`位置と許可されたスワップを使用して正常に一致した場合は、「YES」が出力されます。 

これが機能する理由は、スワップが数値の差によって制限されるためです。 常に利用可能な最小の数値を最初に移動することで、ブロックされた移動が発生しないようにします。 すべての数値が最終的に先頭に到達する可能性があるため、循環シフトはインデックス キューによって暗黙的に処理されます。 

## Python ソリューション```python
import sys
from collections import deque, defaultdict
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    
    pos = defaultdict(deque)
    for idx, val in enumerate(a):
        pos[val].append(idx)
    
    import heapq
    available = []
    freq = [0]*(m+2)
    for val in a:
        freq[val] += 1
    
    possible = True
    cur_min = 1
    for val in b:
        while cur_min <= m and freq[cur_min] == 0:
            cur_min += 1
        if val < cur_min:
            possible = False
            break
        freq[val] -= 1
    
    print("YES" if possible else "NO")
```コードでは、すぐにアクセスできるように、まず各数値の位置を収集します。 の`freq`配列は各数値の残りのカウントを追跡します。`cur_min`は、未処理の最小の数値を保持し、不正となる、より大きな数値をより小さな数値を超えて移動しようとしないようにします。 内部の while ループはインクリメントします`cur_min`最小の数が使い果たされるたびに。 チェック中`val < cur_min`ブロックされた動きが発生しないようにします。
