 ## 解決策
 ## 問題の理解

 整数の配列が与えられます。 それぞれの整数には、その数として定義される「美しさ」があります。`1`s をバイナリ表現で表現します。 例えば、`5`バイナリでは`101`、2つあります`1`だから、その美しさは`2`。 配列の全体的な美しさは、そのすべての要素の美しさの合計です。 

配列の任意の要素を何度でもインクリメントできます。最大合計は`k`配列全体で増分します。 私たちの目標は、最大限のパフォーマンスを発揮した後、アレイの全体的な美しさを最大化することです。`k`操作。 

制約は、どのような戦略が実現可能かを理解するための鍵となります。 配列のサイズ`n`最大 5000、およびすべての合計`n`テスト ケース全体の数も最大 5000 です。つまり、おおよそのアルゴリズムを使用する余裕があることを意味します。`O(n * log(max(a_i)))`テストケースごと、または`O(n * log^2(max(a_i)))`、 しかし`O(n*k)`それは直ちに実行不可能であるため、`k`と同じ大きさにすることができます`10^18`。 操作が多すぎて個別にシミュレートできないため、ソリューションを増分にわたって 1 つずつ反復することはできません。 

明らかではないエッジケースには、すでに次のような番号にある要素が含まれます。`1, 3, 7, 15`- フォームの番号`2^m - 1`- なぜなら、値を増やすと、次の「2 の累乗マイナス 1」に到達するまでに 1 回の操作しかかからず、突然美しさが 1 以上増加する可能性があるからです。 もう一つのエッジケースは、`k = 0`、配列は変更せずに返される必要があります。 同様に、`k`が非常に大きい場合、すべての数値を次の大きな 2 のべき乗の境界まで押し上げることが最適な場合があります。 

## アプローチ

 素朴なアプローチは、増分ごとに美しさが最大に増加する要素を繰り返し選択し、操作を適用することです。 これは原理的には機能しますが、決定ごとにすべての数値を調べて次の「1 ビット」のしきい値を確認する必要があります。 大型用`k`、これは次のことにつながります`O(n*k)`複雑さ、それは不可能であるため、`k`到達できる`10^18`。 

重要な観察は、数値の美しさは 2 のべき乗でのみ変化するということです。 たとえば、から`a_i = 3`(`11`バイナリで、美しさ 2) に`a_i = 4`(`100`バイナリでは、美しさ 1)、美しさは実際にはいくつかの点で減少しますが、到達した後は`7`(`111`バイナリ、美しさ 3)、次の増加`8`(`1000`) を再度美しさ 1 に落とします。 したがって、美しさを高めることができる唯一のポイントは、フォームの数です。`2^m - 1`。 数字から`x`、美しさが増す次の番号は次です`2^m - 1`より大きい`x`。 

これを使用して、各要素の美しさを高める次のしきい値に到達するための「コスト」を事前計算します。 次に、コストを並べ替えて、最も安価なものから順に増分を適用します。 これにより、すべての増分をシミュレートすることなく、美しさを効率的に最大化することができます。 この問題は、古典的な貪欲な「単位コストあたりの最大の利益を最初に購入する」シナリオに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n*k) | O(n) | 遅すぎる |
 | 最適 (次のしきい値) | O(n * log(max(a_i))) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列の初期の美しさをカウントによって計算します。`1`s は各要素のバイナリ表現です。 
2. 各要素について`a_i`、次の数値より大きい値を見つけます。`a_i`それはその美しさを増すでしょう。 これはフォームの次の番号です`2^m - 1`ここでのカウントは`1`sは今の美しさよりも上です。 差を計算する`d = next - a_i`、これは、この増加を達成するために必要な操作の数です。 
3. これらすべてを保管します`(cost, gain)`配列のペア。 ここでかかる費用は、`d`、ゲインは常に`1`なぜなら、各ステップが美しさをちょうど1つ増やすからです。 
4. コストの配列を昇順に並べ替えます。 最小の要素への操作の適用を開始します。`cost`、 それまで`k`なくなります。 
5. 適用された操作ごとに、全体の美しさをゲインによって増加させます。 減らす`k`コストによって。 
6. 1回`k`すべての要素が使い尽くされるか、すべての要素が処理されると、その積み重ねが達成可能な最大の美しさになります。 

機能する理由: 美しさは予測可能なしきい値でのみ増加するため、操作を無駄にすることはありません。 すべての増加は等しい利益を持ち、コストは独立しているため、次に最も安価な増加を貪欲に選択すると、最大の美しさが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def beauty(x):
    return bin(x).count('1')

def next_threshold(x):
    # returns the next number > x that increases beauty by 1
    b = beauty(x)
    while True:
        x += 1
        if beauty(x) > b:
            return x

t = int(input())
for _ in range(t):
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    current_beauty = sum(beauty(ai) for ai in a)
    
    costs = []
    for ai in a:
        nt = next_threshold(ai)
        costs.append(nt - ai)
    
    costs.sort()
    remaining_ops = k
    extra_beauty = 0
    for c in costs:
        if remaining_ops >= c:
            remaining_ops -= c
            extra_beauty += 1
        else:
            break
    
    print(current_beauty + extra_beauty)
```各セクションはアルゴリズムに直接対応します。 初期の美しさを計算するのがステップ 1 です。`next_threshold`関数はステップ 2 を具体化します。コストを並べ替えて増分を適用することは、ステップ 4 と 5 に対応します。Python の使用`bin`手動によるビットカウントエラーを回避し、`while`次の有効なしきい値が確実に見つかるようにします。

 ## 特殊なケース
