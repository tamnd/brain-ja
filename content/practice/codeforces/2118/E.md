 ## 解決策
 ## 問題の理解

 奇数サイズの長方形グリッドがあります。 セルは一度に 1 つずつ色付けされます。 新しいセルに色が付けられるときは、このステップの前にすでに色が付けられていたセルのみが表示されます。 これらのセルのうち、新しく色の付いたセルから最も遠いすべてのセルが 1 つのペナルティを受けます。 

距離の比較は珍しいですね。 まずチェビシェフ距離を最大化し、複数のセルが同じチェビシェフ距離を持つ場合は、マンハッタン距離を使用して関係を解消します。 

私たちの任務は、罰金の総数を最小限に抑えることではありません。 必要なのは、どのセルも 3 つを超えるペナルティを累積しないような色の順序だけです。 

このステートメントの最も印象的な部分は、両方の次元が奇数であるということです。 これは見た目上の制限ではありません。 構造全体は、一意の中央行と一意の中央列を持つことに依存しています。 公式編集上のヒントでは、反対側に 1 つのレイヤーを追加することで、小さな奇数の長方形を繰り返し拡張することも示されています。 

すべてのテスト ケースにわたるセルの合計数は最大 5000 です。つまり、$O(nm)$テストケースごとの構築は完全に安全です。 高度なデータ構造は必要ありません。 この挑戦は純粋に建設的なものです。 

単純なアプローチでは、有効な次のセルを検索しながらペナルティをシミュレートしようとします。 たとえ$71 \times 71$グリッドでは、各ステップでペナルティ分布が変化するため、状態空間は巨大になります。 この問題は明らかに、検索ではなく幾何学的なパターンを発見することを中心に設計されています。 

見落としやすいコーナーケースの 1 つは、単一行です。 

入力：```
1
1 5
```最も古いセルが繰り返し最も遠いセルになるため、自然な左から右の順序は危険です。 正しい構築色は中心付近に配置されます。```
1 2
1 4
1 5
1 1
1 3
```もう 1 つの特殊なケースは単一セルです。 

入力：```
1
1 1
```答えは簡単です:```
1 1
```以前に色の付いたセルが存在しないため、ペナルティが割り当てられることはありません。 

3 番目の微妙なケースは、次のような非常に薄い長方形です。$3 \times 9$。 正方形にのみ機能する構築では十分ではありません。 拡張プロセスは、垂直方向と水平方向に独立して動作する必要があります。 

## アプローチ

 ブルートフォースの観点は、ペナルティが実際に何に依存しているのかを明らかにするので有益です。 

すでにいくつかのセルのセットに色を付けており、次のセルを選択したいとします。 色付けされていないすべてのセルを試し、以前に色付けされたどのセルが最も遠くになるかを計算し、ペナルティを更新して、検索を続けることができます。 このような戦略は、問題のルールに明示的に従うため、原則として正しいです。 

問題は、分岐要素が膨大であることです。 5000 個のセルを持つグリッドでは、天文学的な数の次数を探索する必要があります。 考えられる次の手をすべてチェックするだけでも、すでにコストがかかりすぎます。 

重要な幾何学的観察は、ペナルティが極端なセルによって作成されるということです。 中心付近に色を付け、徐々に外側に拡張すると、以前に色付けされた最も遠いセルは常に、現在構築されている長方形の境界上に位置します。 編集者の主なアイデアは、中心から開始して、新しく追加された境界セルを注意深く順序付けしながら、長方形を 2 行または 2 列ずつ繰り返し拡張することです。 

どちらの寸法も奇数であるため、すべての延長は一意の中心線を保持します。 新しい境界セルは、反対側が交互に色付けされます。 これにより、ペナルティが単一のセルに集中するのではなく、境界全体に分散されます。 公式のソリューションでは、実際にはより強力な結果が得られます。つまり、すべてのセルが最大 2 つのペナルティを受けますが、これは必要な制限である 3 つよりもさらに優れています。 

構築は再帰的に表示できます。 

些細なことから始めましょう$1 \times 1$矩形。 

それを次まで拡張します$3 \times 1$、 それから$5 \times 1$、など、反対の行を追加します。 

幅を増やす必要がある場合は、同様に反対側の列を追加します。 

拡張順序は、新しく追加されたセルが反対側の境界にのみペナルティを作成し、それらのペナルティが制限されたままになるように選択されます。

 ## アルゴリズムのチュートリアル

 1. グリッドの中央のセルから開始します。 
2. 現在構築されている奇数の長方形を維持します。 
3. 高さを増やす必要がある場合は、現在の長方形の上に 1 行、下に 1 行を追加します。 
4. 新たに導入したセルを中央の列から始めて、その中央を中心に左右交互に色を付けます。 
5. 同じ水平オフセットを処理するときは、常に上の行と下の行を交互に実行します。 
6. 必要な高さに達したら、柱を使用して同じタイプの拡張を実行します。 
7. 2 つの列を追加する場合は、中央の行から開始し、その中央を中心に上下に交互に追加します。 
8. 構築された長方形がいっぱいになるまで続けます。$n \times m$グリッド。 

### なぜ効果があるのか

 どの段階でも、以前に色付けされていた最も遠いセルが現在の四角形の境界に属します。 反対側の交互の順序により、ペナルティが同じ場所を繰り返しターゲットにするのを防ぎます。 

新しい行のペアが追加されると、上側と下側のセルがペナルティ ロードを共有します。 新しい列のペアが追加されると、同じバランス効果が水平方向に発生します。 

再帰的不変条件は、既に構築されたすべての四角形がペナルティ境界を満たし、拡張によって制御された境界セルのセットに対するペナルティのみが増加するということです。 公式分析によると、このプロセス中に 2 つのペナルティを超えるセルは存在しません。 2 は必要な制限である 3 を下回っているため、この構築は有効です。 

## Python ソリューション

 次の実装は、受け入れられているソリューションで使用されている建設的な拡張のアイデアに従っています。 中心から外側に向かって答えを構築します。```python
import sys
input = sys.stdin.readline

def build_line(k):
    mid = (k + 1) // 2
    res = [mid]

    for d in range(1, mid):
        res.append(mid - d)
        res.append(mid + d)

    return res

t = int(input())
out = []

for _ in range(t):
    n, m = map(int, input().split())

    rows = build_line(n)
    cols = build_line(m)

    for r in rows:
        for c in cols:
            out.append(f"{r} {c}")

sys.stdout.write("\n".join(out))
```ヘルパー関数は、単一の次元に沿った位置の順序を構築します。 中央から始まり、左右対称に交互に表示されます。 

どちらの次元も奇数であるため、各次元には一意の中心があります。 行の順序と列の順序のデカルト積により、グリッド全体の中心から外への拡張が自然に生成されます。 

最も一般的な実装上の間違いは、出力内でディメンションが 1 から始まるインデックスであることを忘れることです。 もう 1 つの簡単なエラーは、オフセットを間違った順序で生成することです。これにより、構築が依存する対称性が崩れます。

## テストケース```python

import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    def build_line(k):
        mid = (k + 1) // 2
        res = [mid]
        for d in range(1, mid):
            res.append(mid - d)
            res.append(mid + d)
        return res

    t = int(input())
    out = []

    for _ in range(t):
        n, m = map(int, input().split())
        rows = build_line(n)
        cols = build_line(m)

        for r in rows:
            for c in cols:
                out.append(f"{r} {c}")

    return "\n".join(out)

# square grid

 ## 特殊なケース

 のために$1 \times 1$グリッド：```
1
1 1
```アルゴリズムは中心位置を即座に生成します。 以前に色の付いたセルが存在しないため、ペナルティは発生しません。 

のために$1 \times 5$グリッド：```
1
1 5
```順序は列 3 を中心に展開されます。```
(1,3)
(1,2)
(1,4)
(1,1)
(1,5)
```構造は完全に対称を維持しており、これがまさに 1 つのエンドポイントに繰り返しペナルティが蓄積するのを防ぎます。 

のために$3 \times 9$グリッド：```
1
3 9
```行は次のように生成されます。```
2, 1, 3
```列は次のように生成されます。```
5, 4, 6, 3, 7, 2, 8, 1, 9
```デカルト積は、寸法が大幅に異なる場合でも、中心から外への成長パターンを維持します。 構造はグリッドが正方形であることに依存しません。
