 ## 問題の理解

 セルに分割された長方形の惑星があります。 一部のセルは建設に使用できますが、一部はブロックされています。 目標は、可能な限り最大の船を建造することです。 船は、中央に 1 つの正方形と、4 つの側面にそれぞれ 1 つの正方形が取り付けられた、5 つの等しい正方形で作られた十字の形をしています。 それぞれの正方形の一辺の長さを`k`、十字架全体が占める`3k × 3k`ただし、その領域の中央の行ブロックと中央の列ブロックのみが使用可能でなければなりません。 

入力により、グリッドの高さと幅が与えられ、その後にグリッド自体が続きます。 あ`#`セルは建設に使用できますが、`.`セルはできません。 出力は次の最大値です。`k`この十字架の配置が存在するためです。 この声明は、少なくとも次のサイズの船が存在することを保証しています。`1`いつでも構築できます。 

グリッドの寸法は次の範囲に達します`2000 × 2000`、最大400万個の細胞を与えます。 考えられるすべてのセンターを試し、クロスを一度に 1 レイヤーずつ拡張するソリューションでは、数十億の操作に達する可能性があり、これは一般的な 1 秒の制限には多すぎます。 セル数が線形に近い、または線形に近い方法が必要です。 答えはせいぜい`min(n, m) / 3`、二分探索からの対数因数が受け入れられます。 

扱いにくいケースは、ほとんどが十字の形状に関連しています。 それなりの大きさの船`k`ただの普通ではない`k × k`正方形なので、中央の正方形だけをチェックすると不正解になります。 例えば：```
3 9
...###...
...###...
#########
```正しい答えは、`1`、中央の列は使用できますが、垂直部分には高さを持たせないためです。`3`。 あるかどうかだけを確認するいい加減な解決策`3 × 3`どこかでブロックすると失敗します。 

もう 1 つのエッジケースは、クロスが境界線に触れた場合です。 例えば：```
5 5
..#..
.###.
#####
.###.
..#..
```正しい答えは、`1`。 中央の正方形は配置できますが、大きな十字架を置くのに十分なスペースがありません。 候補十字の中心を想定する実装では、次の条件が必要です。`k`周囲に空の行や列があると、有効な境界線の配置が誤ってスキップされる可能性があります。 

最後によくある間違いは、図形全体のサイズと 1 つの正方形のサイズを混同することです。 ある程度の大きさの船の場合`k`、境界ボックスの合計は次のようになります。`3k × 3k`、 ない`k × k`。 

## アプローチ

 直接的なアプローチは、可能なすべての値を試してみることです。`k`、考えられるすべての中心位置を確認し、十字の 5 つの正方形をすべてチェックします。 船の定義はまさにこれら 5 つの正方形の結合であるため、これは正しいです。 ただし、単一の候補クロスをチェックするとコストがかかります`O(k²)`、そしてそれがあるかもしれません`O(nm)`可能性のあるセンターと`O(min(n,m))`可能なサイズ。 最悪の場合、これは非常に大きくなります。 

重要な観察は、固定された`k`、すべての候補のすべてのセルを検査する必要はありません。 特定かどうかを答えるだけで済みます。`k × k`正方形は完全に構築可能です。 これは、2 次元のプレフィックス合計を使用して一定時間で実行できます。 

修正が確認できたら`k`、答えを二分探索できます。 サイズのクロスの場合`k`存在する場合は、その十字の中央部分を取ることで、より小さなサイズを構築することもできます。 この単調な性質は、考えられる答えのセットが次のようになることを意味します。`true, true, ..., true, false, false, ...`、これはまさに二分探索に必要なことです。 

ブルートフォースは定義を直接チェックするため機能しますが、ほぼ同じ領域のチェックを何度も繰り返すため失敗します。 プレフィックス合計により繰り返しの作業が不要になり、二分探索により可能なすべてのサイズをテストする必要がなくなります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 最悪の場合は O(nm · min(n,m)³) | お(1) | 遅すぎる |
 | 二分探索 + 接頭辞の合計 | O(nm log(min(n,m))) | O(nm) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 左上隅からその位置までの長方形内の使用可能なセルの数を各位置に格納する 2 次元のプレフィックス合計配列を構築します。 

プレフィックスの合計を使用すると、一定時間内に四角形内にブロックされたセルが何個あるかをクエリできます。 使用可能なセルの数がその面積と等しい場合、長方形は構築に有効です。 

1.辺の長さを二分探索する`k`十字の1つの正方形。 

下限は次から始まります`1`解決策が存在することが保証されているからです。 上限は`min(n, m) // 3`というのは、十字全体が両次元でそのような正方形を 3 つ占めるからです。 

1. 候補者の場合`k`、中央の可能なすべての位置をスキャンします。`k × k`四角。 

中央の正方形には隣接する 4 つの正方形が必要です`k × k`正方形: 上、下、左、右。 5 つの長方形すべてに使用可能なセルのみが含まれている場合、サイズの十字`k`存在します。 

1. チェックが成功した場合は、二分探索を上に移動します。 それ以外の場合は、下に移動します。 

より大きなクロスには、より小さなクロスの要件がすべて含まれているため、1 つのサイズで失敗すると、それより大きなサイズもすべて失敗することになります。 

1. 二分探索終了後、成功した最大値を出力します。 

### なぜ効果があるのか

 テストされたすべてのサイズについて`k`、チェック手順では、有効な船を定義する 5 つの正方形を正確に検査します。 プレフィックスの合計は、各正方形で使用可能なセルの正確な数を示すため、正方形は、その内部のすべてのセルが使用可能な場合にのみ受け入れられます。 

二分探索は述語が「サイズの交差」であるため正しいです。`k`「存在する」は単調です。サイズの十字の場合`k`内部を取得して存在します`k' × k'`小さい部品用`k'`より小さい有効なクロスが作成されます。 サイズが失敗した場合、より大きなクロスにはより小さな無効な要件が含まれるため、それより大きなサイズは適合しません。 したがって、二分探索により、可能な最大サイズが見つかります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    grid = [input().strip() for _ in range(n)]

    pref = [[0] * (m + 1) for _ in range(n + 1)]

    for i in range(n):
        row_sum = 0
        for j in range(m):
            if grid[i][j] == '#':
                row_sum += 1
            pref[i + 1][j + 1] = pref[i][j + 1] + row_sum

    def rect_sum(r1, c1, r2, c2):
        return pref[r2][c2] - pref[r1][c2] - pref[r2][c1] + pref[r1][c1]

    def good_square(r, c, k):
        return rect_sum(r, c, r + k, c + k) == k * k

    def check(k):
        for r in range(n - 3 * k + 1):
            for c in range(m - 3 * k + 1):
                if good_square(r, c + k, k):
                    if (good_square(r + k, c, k) and
                        good_square(r + k, c + k, k) and
                        good_square(r + k, c + 2 * k, k) and
                        good_square(r + 2 * k, c + k, k)):
                        return True
        return False

    lo, hi = 1, min(n, m) // 3
    ans = 1

    while lo <= hi:
        mid = (lo + hi) // 2
        if check(mid):
            ans = mid
            lo = mid + 1
        else:
            hi = mid - 1

    print(ans)

if __name__ == "__main__":
    solve()
```プレフィックス構築では、使用可能なセルのカウントのみが保存されます。 これにより、四角形クエリが四角形のサイズに依存しなくなります。これは、すべてのセルを繰り返しチェックすることに対する主な最適化です。 

の`good_square`関数は、候補正方形内の使用可能なセルの数をと比較します。`k * k`。 それらが等しい場合、その正方形内のすべてのセルが使用可能になります。 

の`check`関数は、完全な位置でのみ反復します。`3k × 3k`境界ボックスがフィットします。 5 つのコールは、十字架の 5 つのブロックに直接対応します。 中央の正方形を維持する`(r + k, c + k)`周囲のブロックが自然に正確にオフセットされるため、off-by-one エラーが回避されます。`k`。 

ここでは Python の整数はオーバーフローしませんが、乗算は`k * k`プレフィックス値はセル数を表すため、 は整数式として保持されます。
