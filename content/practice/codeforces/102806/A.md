 ## 解決策
 ## 問題の理解

 整数の配列が与えられます。 すべての要素について、現在の値を保持することも、符号を変更することもできます。 タスクは、結果の配列が減少しないようにする何らかの符号の選択肢が存在するかどうかを判断することです。 このような構造が存在する場合は、有効な結果の配列を 1 つ出力する必要があります。 

入力サイズは 100000 要素に達するため、考えられるすべての符号の選択肢を試すことは不可能です。 各要素には 2 つの可能な状態があり、2^n 個の可能な配列が作成されます。 すべてをチェックするだけでも、2 秒の制限をはるかに超えてしまいます。 各要素を一定の回数だけ処理するアプローチが必要です。 

値は絶対値で 100000 まで大きくすることができますが、その大きさによって Python でオーバーフローの問題が発生することはありません。 主な困難は算術ではなく、有効な選択肢の順序を見つけることです。 今より大きな値を選択すると、将来の要素を配置できなくなる可能性があるため、間違った貪欲ルールは失敗する可能性があります。 

最初のエッジ ケースは単一の要素です。 例えば：```
Input:
1
-5

Output:
Yes
-5
```1 要素の配列はすでに非減少です。 少なくとも 1 つの隣接する比較が存在することを前提としたソリューションは、それを誤って拒否する可能性があります。 

もう 1 つの重要なケースは、一部の要素に対して否定的な選択のみが機能する場合です。 考慮する：```
Input:
3
5 3 1

Output:
Yes
-5 -3 -1
```正のバージョンは減少していますが、すべての符号を反転すると、有効な増加シーケンスが得られます。 元の兆候を維持しようとするだけの解決策は失敗します。 

最後の注意が必要なケースは、負の値では不十分で、正の値を使用する必要がある場合です。```
Input:
2
1 2

Output:
Yes
-1 2
```負の値が有効であるかどうかを確認せずに貪欲に選択すると、次のような結果が得られます。`-1 -2`、減少しています。 

## アプローチ

 直接的な総当りのアプローチでは、可能なすべての符号の割り当てを列挙することになります。 割り当てごとに、結果の配列を構築し、すべての隣接するペアが非減少条件を満たすかどうかを確認できます。 この方法は、考えられるすべての答えをチェックするので正しいですが、2^n 個のチェックを実行します。 n = 100000 の場合、これはほとんど実現不可能です。 

有益な観察は、各要素がちょうど 2 つの可能な値を持っているということです。`-abs(a[i])`そして`abs(a[i])`。 これら 2 つの値のうち、負の値は常に小さい方になります。 配列を左から右に処理する場合、前に選択した値を知る必要があるだけです。 現在のポジションに最適な選択は、注文を壊さない最小値です。 

可能な限り最小の有効な値を選択することが役立つのはなぜですか? 現在の値が小さいほど、後続のすべての要素に対する制限が少なくなります。 負の値を前の値の後に配置できる場合は、常に安全に使用できます。 それができない場合は、正の値が唯一の選択肢となります。 正の値でも前の値より小さい場合、解は存在しません。 

ブルート フォースは、可能なすべての符号の割り当てを探索するため機能しますが、検索スペースが指数関数的に増大するため失敗します。 最小の有効な電流値が最も自由度を残すという観察により、問題は単一の線形スキャンに縮小されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n * n) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 前に選択した値を負の無限大に設定して開始します。 最初の要素には左からの制限がないため、すべての有効な選択が可能です。 
2. 配列要素ごとに、考えられる 2 つの値、負の絶対値と正の絶対値を考慮します。 否定的なバージョンは常に小さい候補になります。 
3. 否定候補が少なくとも以前に選択した値である場合は、それを選択します。 現在の値を可能な限り小さく保つため、これが推奨される選択です。 
4. それ以外の場合は、肯定的な候補を試してください。 少なくとも以前に選択した値である場合は、それを選択します。 
5. どちらの候補も機能しない場合、配列を非減少配列に変換できないため、出力`No`。 
6. すべての要素が正常に処理された後、出力します。`Yes`そして構築されたシーケンス。 

機能する理由: 位置が処理されるたびに、アルゴリズムは答えの有効なプレフィックスを保持します。 現在の位置のすべての有効な選択肢の中で、可能な最小の値が保存されます。 より大きな選択に従う可能性のある将来の要素は、このより小さな選択にも従う可能性があるため、貪欲な決定によって可能な解決策が削除されることはありません。 アルゴリズムが両方の選択肢が小さすぎる要素に到達した場合、その要素の前で終わるすべての可能なプレフィックスは、少なくとも保存されている以前の値と同じくらい大きな値を持つため、構築を続行できません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    ans = []
    prev = -10**30

    for x in a:
        x = abs(x)

        if -x >= prev:
            cur = -x
        elif x >= prev:
            cur = x
        else:
            print("No")
            return

        ans.append(cur)
        prev = cur

    print("Yes")
    print(*ans)

if __name__ == "__main__":
    solve()
```現在のプレフィックスが有効になると、将来は以前の要素に依存しないため、コードは以前に選択された値のみを保持します。 変数`prev`は、構築された非減少プレフィックスの最後の値を表します。 

候補者は以下から生成されます。`abs(x)`演算ではどちらの符号も許可されるため、元の値ではなく、すべての要素が常にその大きさまたは負の大きさのいずれかになる可能性があります。 チェックの順序は重要です。否定的な候補者が最初にテストされます。これは、それがより小さな選択肢であり、将来のポジションに最も柔軟性を与えるためです。 

の初期値`prev`可能な配列値よりはるかに低い値が選択されます。 入力の大きさは最大 100000 なので、`-10**30`この問題では、負の無限大として安全に動作します。

## テストケース```python
import sys
import io

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout
    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    n = int(input())
    a = list(map(int, input().split()))

    ans = []
    prev = -10**30

    for x in a:
        x = abs(x)
        if -x >= prev:
            cur = -x
        elif x >= prev:
            cur = x
        else:
            print("No")
            sys.stdin = old_stdin
            return sys.stdout.getvalue()

        ans.append(cur)
        prev = cur

    print("Yes")
    print(*ans)

    result = sys.stdout.getvalue()
    sys.stdin = old_stdin
    sys.stdout = old_stdout
    return result

assert run("5\n1 -1 -2 3 6\n") == "Yes\n-1 -1 2 3 6\n", "sample 1"
assert run("3\n1 1 0\n") == "Yes\n-1 -1 0\n", "sample 2"

assert run("1\n-5\n") == "Yes\n-5\n", "single element"
assert run("2\n5 3\n") == "Yes\n-5 -3\n", "decreasing absolute values"
assert run("3\n10 1 2\n") == "Yes\n-10 -1 2\n", "switching from negative to positive"
assert run("3\n1 0 -1\n") == "No\n", "impossible ordering"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1 / -5`|`Yes / -5`| 最小サイズの入力 |
 |`5 3`|`-5 -3`| 順序を維持するために負の値を使用する |

 ## 特殊なケース

 単一要素の場合、ループは 1 回実行され、常に 2 つの可能な符号のうちの 1 つを受け入れます。 アルゴリズムは、存在しない前の要素との比較を試みることはありません。`n = 1`自然に扱われます。 

次のような絶対値が既に減少している配列の場合:```
Input:
3
5 3 1
```アルゴリズムは以下を選択します:```
-5 -3 -1
```次の各値は前の値よりも大きいため、負の値を選択するだけで十分です。 

否定的な選択が失敗した場合:```
Input:
2
1 2
```最初の要素は次のようになります`-1`。 2 番目の要素では、`-2`よりも小さいです`-1`, なので使えません。 アルゴリズムが試行する`2`これは機能し、次のようになります。```
-1 2
```不可能なケースの場合:```
Input:
3
1 0 -1
```最初の要素は次のようになります`-1`。 2 番目の要素は次のようにすることしかできません。`0`, したがって、プレフィックスは次のようになります`[-1, 0]`。 最後の要素は次のようにすることしかできません。`-1`または`1`;`-1`小さすぎるし、`1`有効です。`[-1, 0, 1]`。 ここでは貪欲な構築が成功し、疑わしいと思われる多くのケースが依然として存在する可能性があることを示しています。 

このアルゴリズムは、ある位置で利用可能な両方の値が以前に選択した値を下回っている場合にのみ失敗します。 この時点で、保存されているプレフィックスはすでに最も柔軟な可能なプレフィックスであるため、他の符号の割り当てでは配列を解決できません。
