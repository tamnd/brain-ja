 ## 解決策
 ## 問題の理解

 次のシーケンスがあります`n`ひとつひとつ丁寧に作られた真珠。 2番目に生成される真珠の色`i`が与えられる。 有効なエンジン セットには、各色のパールが 1 つだけ含まれている必要があるため、常に含まれています。`k`真珠。 1 つのセット内の真珠の製造時期は近い必要があります。そのセット内の最初の真珠と最も新しい真珠の違いは最大でも 1 秒程度です。`m`秒。 どの真珠も一度しか使用できません。 タスクは、そのようなセットをできるだけ多く構築し、すべてのセットのパールのインデックスを出力することです。 

入力には、生産された真珠の数、最大許容時間差、色の数、そして生産順序での各真珠の色が含まれます。 出力は完全なセットの最大数で始まり、その後に各セットに対して選択されたインデックスが続きます。 

限界は大きい：両方とも`n`そして`k`到達できる`100000`。 すべての色またはすべての以前のパールをすべての位置で繰り返しスキャンするアルゴリズムは二次関数となり、終了しません。 すべての真珠を一定の回数だけ処理するソリューションが必要です。 

主なエッジ ケースは、色の利用可能性と時間枠の間の相互作用から生じます。 現在のウィンドウに色が欠けている場合、他の色が豊富であってもセットを形成することはできません。 例えば：```
6 2 3
1 2 2 1 3 3
```最初に考えられるセットは真珠で形成されます`4, 3, 5`、なぜならそれらの色は`1, 2, 3`そして時差は`5 - 3 = 2`。 各色が出現する回数だけをカウントする不用意な解決策では、すべての色が 2 回出現するため、セットが 2 つ期待されますが、時間制限によりそれが妨げられます。 

もう 1 つの注意が必要なケースは、ある色の最後のパールが現在のウィンドウの外側にあり、他の色の古い出現が残っている場合です。 例えば：```
5 2 3
1 2 2 2 3
```色のパールの合計が十分にあります`2`、しかし、色の真珠は1つだけです`1`そしてそれは早すぎるようです。 答えは`0`。 グローバルなカウントのみを追跡するソリューションでは、誤って肯定的な答えが生成されます。 

## アプローチ

 直接的なアプローチは、考えられるすべてのグループを試してみることです。`k`真珠を見つけて、すべての色が含まれているか、制限時間内に収まっているかを確認します。 これは正しいセットの定義を正確にテストするためです。 ただし、最大で`100000`そのため、多くの可能なウィンドウを見てすべての色をすぐに確認することさえ遅すぎます。 最悪の場合、すべての位置のすべての色をスキャンするとコストがかかります`O(nk)`操作。 

問題の構造により、より良い方向性が得られます。 有効なセットは、次の長さの移動ウィンドウ内に含まれている必要があります。`m + 1`ポジション。 真珠を左から右にスキャンしながら、現在そのウィンドウ内に各色のどの未使用の真珠があるかを知る必要があるだけです。 すべての色に少なくとも 1 つの利用可能なパールがある場合、各色の最も古い利用可能なパールを選択すると、すぐに有効なセットが作成されます。 

最も古いパールの動作を採用する理由は、現在のウィンドウによって、保存されているすべてのパールが現在の位置に十分近いことがすでに保証されているためです。 古いパールを使用しても、将来のセットが悪化することはありません。新しいパールを使用しておくと、後の期間でより柔軟な対応ができるからです。 セットを作成した後、それらのパールはカラーキューから削除され、スキャンが続行されます。 

ブルートフォースアプローチはすべての可能性をチェックするため機能しますが、同じ作業を何度も繰り返すことになります。 スライディング ウィンドウ キューにより、将来の回答に引き続き参加できる情報のみを維持するという問題が軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nk) | O(n) | 遅すぎる |
 | 最適 | O(n + k) | O(n + k) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各色に対して 1 つのキューを作成します。 各キューには、アクティブな時間枠内で現在利用可能なその色のパールのインデックスが格納されます。 また、現在空ではないキューが何色あるかのカウンターも保持します。 
2. パールを左から右に加工します。 パールのとき`i`が表示されたら、そのインデックスをその色のキューに追加します。 挿入前にこのカラー キューが空だった場合は、使用可能な色の数を増やしてください。 
3. 窓から外れたパールを取り外します。 インデックス処理時`i`、許可されている最も古いインデックスは次のとおりです。`i - m`、インデックス`i - m - 1`存在する場合は削除する必要があります。 これを削除するとカラー キューが空になる場合は、使用可能な色の数を減らします。 
4. もしすべてが`k`カラーキューは空ではなく、すべてのキューから最初の要素を取得します。 これら`k`真珠にはすべて異なる色があり、すべてが現在のウィンドウ内にあるため、有効なセットを形成します。 インデックスを保存し、キューから削除します。 
5. すべての真珠が処理されるまで続けます。 保存されるセットは、可能な最大セット数です。 

なぜ効果があるのか:

 常に、各キューには、現在の位置で終了するセットでまだ使用できる 1 つの色の未使用のパールが含まれています。 セットは、すべての色に少なくとも 1 つの候補がある場合にのみ作成できるため、その時点で有効な選択肢が存在する場合にのみ、アルゴリズムによってセットが作成されます。 キュー内のすべての候補が同じ時間制限を満たしており、最も早い利用可能なパールを削除すると、将来のウィンドウに最新のパールが残るため、各色の最も早い候補を選択するのが安全です。 したがって、作成されたすべてのセットには、より良い選択肢で置き換えることのできない真珠が使用されており、貪欲なプロセスにより、将来可能なセットの数が減ることはありません。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    colors = list(map(int, input().split()))

    queues = [deque() for _ in range(k)]
    non_empty = 0
    ans = []

    for i, c in enumerate(colors):
        c -= 1

        if not queues[c]:
            non_empty += 1
        queues[c].append(i + 1)

        old = i - m - 1
        if old > 0:
            oc = colors[old - 1] - 1
            queues[oc].popleft()
            if not queues[oc]:
                non_empty -= 1

        if non_empty == k:
            cur = []
            for q in queues:
                cur.append(q.popleft())
            ans.append(cur)

            non_empty = 0
            for q in queues:
                if q:
                    non_empty += 1

    out = [str(len(ans))]
    for group in ans:
        out.append(" ".join(map(str, group)))
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```queues 配列は、スライディング ウィンドウのアイデアを直接実装したものです。 列`c`現在使用可能な色のパールの位置が含まれています`c`。 

新しいパールが読み取られると、そのカラー キューに追加されます。 削除ステップでは次を使用します。`i - m - 1`インデックスは、保存された回答では 1 から始まりますが、ループでは 0 から始まるためです。 まさに真珠`m`離れた位置は引き続き有効ですが、1 つ離れた位置のパールは無効です。 

すべてのキューが空でない場合、すべてのキューの先頭が選択されます。 前面は、その色の入手可能な最も古い真珠を表しています。 これらの選択されたパールをすべてのキューから削除すると、次の独立したセットを見つけるための構造が準備されます。 

変数`non_empty`挿入するたびにすべての色をスキャンする必要がなくなります。 キューが空の状態と空でない状態の間で変化する場合にのみ更新され、アルゴリズム全体が線形に保たれます。

 ## 特殊なケース

 すべての色が十分な回数出現しても、出現が分離されている場合、全体的なカウントは誤解を招きます。 のために：```
6 2 3
1 2 2 1 3 3
```色数は 2 つの可能なセットを示唆しています。 スキャン中、アルゴリズムは真珠のみを距離内に保ちます`2`現在の位置の。 インデックス時`5`、利用可能なキューには色が含まれています`1`、`2`、 そして`3`、つまりセットを作成します`4, 3, 5`。 残った色は`3`別の完全なグループとペアにすることはできません。 

必要な色がウィンドウの外側の過去にのみ存在する場合、その色は破棄する必要があります。 のために：```
5 2 3
1 2 2 2 3
```インデックスのパール`1`色がある`1`。 色がつく頃には`3`パールがインデックスに到着`5`、有効なウィンドウはインデックスから始まります`3`、だから色は`1`キューが空です。 このアルゴリズムは、セットをチェックする前に古いパールを削除するため、無効なグループが作成されることはありません。 

すべての真珠が同じ色の場合、1 つの色しか存在しない限り、グループは完成しません。 のために：```
6 3 2
1 1 1 1 1 1
```2 番目のカラー キューが空ではなくなることはありません。 の`non_empty`カウンターは下に留まります`k`、アルゴリズムは正しく返します`0`。
