 ## 解決策
 ## 問題の理解

 いくつかの種類のアリがいます。 タイプ`i`もっている`a[i]`アリが利用可能です。 ダニは 1 回の移動で数匹のアリを追い払うことができますが、同時に 2 つの制限が適用されます。移動中のアリの総数は以下を超えることはできません。`m`、そして単一の種類から採取されるアリの数は以下を超えることはできません。`k`。 

目標は、少なくとも`p`アリが捨てられる。 

入力には複数のテスト ケースが含まれています。 それぞれのケースについて、配列には各種類のアリの量が記述され、その後に除去する必要があるアリの目標数が続きます。 出力は、その目標を達成できる最小の手数です。 

すべての合計`n`テスト ケースの値は最大でも`10^6`。 これにより、あらゆるタイプについて多くの可能性のある手数を処理するものは除外されます。 解決策`O(n log answer)`適しているので`log`考えられる答えは小さいですが、`O(n * answer)`アリの数が多い場合は不可能です。 

の値`a[i]`、`m`、`k`、 そして`p`32 ビット整数よりもはるかに大きくなる可能性があるため、実装では、それが重要な言語では Python 整数または 64 ビット算術演算を使用する必要があります。 

よくある間違いは、総移動容量のみを考慮することです。 例えば：```
1
2 10 1
100 100
150
```答えはそうではありません`15`、 それでも`15 * 10 = 150`総容量でアリを投げることができます。 各移動は、1 つのタイプから 1 つのアリのみを取ることができます。`15`各タイプの移動は最大で貢献します`15`アリ。 本当の最大値は`30`したがって、正しい出力は次のようになります。```
100
```もう 1 つのエッジ ケースは、1 つの型にほぼすべてのアリが含まれる場合です。```
1
3 5 100
1000 1 1
10
```答えは`2`, なぜなら総移動量制限が制限だからです。 タイプごとの制限のみを考慮するソリューションでは、移動数が過大評価される可能性があります。 

## アプローチ

 直接的なアプローチは、可能な限りすべての手を試して、何匹のアリを投げることができるかをシミュレートすることです。 一定の移動回数の場合`x`、どのタイプも最大で貢献できます`min(a[i], x * k)`タイプ制限はすべての動きに独立して適用されるため、アリです。 グローバル制限もあります`x * m`アリ。 可能なすべての値を確認する`x`1 つずつ増やすことは概念的には機能しますが、答えは非常に大きくなる可能性があります。 もし`p`周りにいる`10^18`、答えが見つかるまですべての値を試すのは遅すぎます。 

重要な観察は、次のような場合です。`x`移動数だけで十分な場合は、さらに多くの移動数でも十分です。 この単調な性質により、答えの二分探索が可能になります。 

固定の場合`x`、投げることができるアリの最大数は次のとおりです。```
min(x * m, sum(min(a[i], x * k)))
```最初の項は、すべての動きにわたるアリの総数を制限します。 2 番目の項では、各タイプを個別に制限します。 これら 2 つの制限は、可能な最大量を完全に表しています。供給または移動ごとの制限がなくなるまで、すべてのタイプを同じ移動セットに個別に分散できるためです。 

実現可能性チェックは次のように線形になります。`n`。 二分探索で最小のものを見つける`x`チェックが成功した場合。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * 答え) | お(1) | 遅すぎる |
 | 最適 | O(n 対数応答) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 間の答えを二分探索します。`1`十分に大きな上限。 検索値は、テストしている手の数を表します。 
2. 中間値の場合`x`、投入できるアリの最大数を計算します。`x`動きます。 アリの種類ごとに、`min(a[i], x * k)`それがこのタイプが貢献できる最大のことだからです。 現在の合計に達したら追加を停止します`p`より大きな値は決定に影響しないためです。 
3. 計算された合計を次のように制限します。`x * m`, たとえ種類から十分な数のアリが存在したとしても、移動能力を超えることはできないためです。 
4. 投げられるアリの最大数が少なくとも`p`、より小さな答えを探し続けてください。 それ以外の場合は、小さい値を破棄し、大きい半分を検索します。 
5. 実行可能性チェックに合格した最初の移動数を返します。 

機能する理由: 二分探索は単調な特性に依存しています。 もし`x`移動だけで十分なので、`x + 1`余分な動きを常に未使用のままにしておくことができるため、動きも十分です。 実現可能性関数は、可能なアリの最大数を正確に計算します。`x`は移動するため、最初の実現可能な値が最小の有効な答えになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case():
    n, m, k = map(int, input().split())
    a = list(map(int, input().split()))
    p = int(input())

    def can(x):
        total = 0
        limit = x * k
        for v in a:
            total += v if v < limit else limit
            if total >= p:
                return True
        return min(total, x * m) >= p

    lo, hi = 1, (p + m - 1) // m
    hi = max(hi, 1)

    while not can(hi):
        hi *= 2

    while lo < hi:
        mid = (lo + hi) // 2
        if can(mid):
            hi = mid
        else:
            lo = mid + 1

    return str(lo)

def main():
    t = int(input())
    ans = []
    for _ in range(t):
        ans.append(solve_case())
    print("\n".join(ans))

if __name__ == "__main__":
    main()
```実現可能性機能はソリューションの中核です。`x * k`どのタイプにも同じ移動ごとの制限があるため、 は 1 回計算されます。 各タイプの貢献度は、利用可能なアリとこの制限の両方によって制限されます。 

合計額に達した場合の早期返却`p`大規模なケースでの不必要な作業を回避します。 決勝戦`min(total, x * m)`総容量制限が適用されます。 これを最後まで遅らせても安全な理由は、タイプの寄与は、供給側の総制約が目標を満たせるかどうかを判断するためにのみ使用されるためです。 

初期の上限は、少なくとも次の事実から来ています。`ceil(p / m)`唯一の制限が総移動容量である場合、移動は常に必要です。 倍増ループは、タイプごとの制限によってより多くの手が必要な場合に対処します。 

Python の整数は、次のような大きな値を乗算するときにオーバーフローを回避します。`x * k`。

import sys
import io

def solution(data):
    input = io.StringIO(data).readline

    def solve_case():
        n, m, k = map(int, input().split())
        a = list(map(int, input().split()))
        p = int(input())

        def can(x):
            total = 0
            limit = x * k
            for v in a:
                total += min(v, limit)
                if total >= p:
                    return True

            hi *= 2

            mid = (lo + hi) // 2
            if can(mid):
                hi = mid
            else:
                lo = mid + 1
        return str(lo)

    t = int(input())
    return "\n".join(solve_case() for _ in range(t))
