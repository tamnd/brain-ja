 ## 解決策
 ## 問題の理解

 個別の問題の難しさの分類されたリストが与えられます。 このリストから、コンテストを形成するサブシーケンス (必ずしも連続している必要はない) を選択する必要があります。 唯一の制限はローカルです。選択した難易度を徐々に並べ替える場合、連続するすべてのペアは、次の難易度が前の難易度の最大 2 倍であることを満たさなければなりません。 

目標は、長さを最大化しながら、この乗法制約を満たすサブシーケンスを選択することです。 

入力サイズは最大 200,000 要素まで可能です。 これにより、サブセットを列挙しようとしたり、ネストされた探索ですべての開始点を試行したりするソリューションは即座に除外されます。$10^{10}$操作は 1 秒では実行できません。 線形か、最悪の場合は線形演算が必要です。 

最適なサブシーケンスが元の配列内で連続していない場合、微妙なエッジ ケースが発生します。 たとえば、2 つの値がインデックス内で大きく離れている場合でも、中間値がスキップされると、それらの値は依然として最適なチェーンに属する可能性があります。 配列内の隣接する要素を常に選択する単純な貪欲型は、次のような場合に失敗します。`1 2 4 8 9 10`、特定の要素をスキップすると、有効なチェーンが長くなります。 

もう 1 つの問題は、条件が非対称であることです。 すべてのペアではなく、選択したサブシーケンス内の隣接する要素のみを拘束します。 これは、構造が全体的な比率制約ではなく連鎖条件であることを意味します。 

## アプローチ

 ブルートフォースのアイデアは、すべての開始インデックスを試し、次の有効な要素を繰り返し選択することでチェーンを前方に貪欲に拡張することです。 固定スタートの場合、スキャンフォワードのコストがかかります$O(n)$開始するたびにこれを行うと、$O(n^2)$。 と$2 \cdot 10^5$、これはおおよそになります$4 \cdot 10^{10}$比較すると遅すぎます。 

重要な点は、出発点を決めてしまえば、以前の要素を再検討する必要がないということです。 制約は最後に選択された値のみに依存します。 これは貪欲なフォワード構築を示唆していますが、すべてのインデックスから貪欲に開始するのは冗長です。 

代わりに、スライディング ウィンドウ構造を維持します。各位置について、そこから始まる最長の有効なチェーンを拡張しようとしますが、チェーンが次の位置で始まる場合、という事実を再利用します。$i$がわかっている場合、からの最適な拡張子は$i+1$作品の一部を再利用できます。 これにより、問題は 2 ポインター スタイルの展開に変わり、有効なウィンドウを維持し、その最大サイズを追跡します。 

シーケンスはソートされているため、連続して選択された要素間のローカルな妥当性を確認するだけで済みます。 これにより、条件を維持しながらウィンドウを拡張できます。$a[j] \le 2 \cdot a[j-1]$、条件が壊れた場合にのみ縮小します。

 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 現在の位置で終わる最長の有効なチェーンを維持しながら、配列を左から右に処理します。 

1. 配列の先頭にポインターを置き、単一の要素が有効なコンテストであるため、答えを 1 に設定します。 これにより、ベースラインのチェーン長が確立されます。 
2. 配列を 2 番目の要素から順に走査します。 各要素について、以前に選択した要素の最大 2 倍であるかどうかを確認して、現在のチェーンを拡張できるかどうかを確認します。 
3. 条件が満たされる場合、現在のチェーンの長さを 1 だけ延長します。 これは、制約を破ることなく現在の要素を追加できることを反映しています。 
4. 条件が満たされない場合は、現在の要素から開始してチェーンの長さを 1 にリセットします。 これが必要なのは、現在のチェーン内の以前の要素が、指定された制約の下ではこの要素に接続できないためです。 
5. 各ステップの後に、現在のチェーン長でグローバル最大値を更新します。 

このアルゴリズムは、前のインデックスで終わる最長の有効なチェーンを常に延長するという事実に基づいています。 拡張が失敗した場合、それ以前の開始点は同じ境界でチェーン条件に違反するため、新たに開始することが最適です。 

### なぜ効果があるのか

 どの位置でも、アルゴリズムはその位置で終了する最長の有効なサブシーケンスを維持し、ローカルで条件を尊重します。 妥当性は隣接するペアにのみ依存するため、最適解は、条件が連続的に成立する最大のセグメントに分解できます。 最良のコンテストは、最適な開始リセット後の最長のセグメントに対応し、アルゴリズムはすべての可能なセグメントのエンドポイントを暗黙的に列挙します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    best = 1
    cur = 1
    
    for i in range(1, n):
        if a[i] <= 2 * a[i - 1]:
            cur += 1
        else:
            cur = 1
        if cur > best:
            best = cur
    
    print(best)

if __name__ == "__main__":
    solve()
```このソリューションは、現在の有効なチェーン長の継続的なカウントを保持します。 変数`cur`配列内を移動するときに、連続して選択された要素の数が 2 倍条件を満たすかを表します。 条件が崩れると、その境界を越えて拡張することはできないため、リセットされます。 

変数`best`配列内の任意の場所で見られる最大チェーン長を追跡します。 この変換された意味では、すべての有効なサブシーケンスが連続した有効なセグメントとして現れる必要があるため、これらのセグメントを追跡するだけで十分です。 

重要な実装の詳細は、正確にいつリセットされるかです。`a[i] > 2 * a[i-1]`。 この厳密な不等式を見逃したり、リセットを忘れたりすると、無効なチェーンが過大にカウントされてしまいます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))

    best = 1
    cur = 1

    for i in range(1, n):
        if a[i] <= 2 * a[i - 1]:
            cur += 1
        else:
            cur = 1
        best = max(best, cur)

    return str(best)

# provided sample
assert run("10\n1 2 5 6 7 10 21 23 24 49\n") == "4"

# minimum size
assert run("1\n100\n") == "1"

# all valid chain
assert run("4\n1 2 3 5\n") == "4"

# strict breaks every time
assert run("4\n1 3 7 15\n") == "1"

# alternating extend/reset pattern
assert run("6\n1 2 5 6 12 13\n") == "2"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 要素 | 1 | 最小境界 |
 | 1 2 3 5 | 4 | フルチェーンは常に有効 |
 | 1 3 7 15 | 1 | 定数リセット |

 ## 特殊なケース

 次のような単一要素入力の場合`1`、アルゴリズムが初期化されます`best = 1`そしてすぐに戻ります。 遷移が発生しないため、誤ったリセットや比較がトリガーされることはありません。 

次のような厳密に 2 倍以上増加するシーケンスの場合`1 3 7 15`、次の各要素が前の要素の 2 倍を超えるため、すべての比較は失敗します。 ループがリセットされる`cur`すべてのステップで 1 になり、`best`有効なコンテストでは 2 つの要素が共存できないため、終始 1 のままで正解と一致します。 

次のような完全に有効なシーケンスの場合、`1 2 3 5`、すべての隣接するペアが制約を満たすため、`cur`アルゴリズムは決してリセットされず、配列全体が有効なコンテストとして正しく識別されます。
