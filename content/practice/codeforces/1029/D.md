 ## 解決策
 ## 問題の理解

 正の整数のリストと係数が与えられます。$k$。 個別のインデックスの順序付きペアごとに$(i, j)$、次のように書くことで新しい数を形成します$a_i$直接続いて$a_j$10進数表現で。 このような順序付けされた連結が何個で割り切れるかを数える必要があります。$k$。 

重要な問題は、連結が剰余に対する単純な算術演算ではないことです。 の桁数で表すと$a_j$として$d_j$の場合、連結は次と等しくなります$a_i \cdot 10^{d_j} + a_j$。 これにより、桁の長さへの依存が導入されるため、各ペアは値と構造の両方に依存します。 

制約は大きく、最大で$2 \cdot 10^5$数字と$k$まで$10^9$。 ペア上の二次解は、次のものが必要となるため、直ちに実行不可能です。$4 \cdot 10^{10}$最悪の場合の運用。 

すべての数値が同じ値を共有する場合、微妙なエッジケースが発生します。 たとえば、すべてが$a_i = 1$そして$k = 1$、すべてのペアが有効です。 正しいソリューションでは、ペアを列挙せずにこれを効率的に処理する必要があります。 

もう 1 つの重要な特殊ケースは、数値の桁の長さが異なる場合です。 例えば、$a_i = 1$、$a_j = 99$、 そして$k = 100$。 連結は$199$とは大きく異なる動作をします$991$したがって、順序の入れ替えは数値的にもモジュラー演算においても重要です。 

## アプローチ

 ブルートフォースアプローチにより、順序付けられたすべてのペアがチェックされます$(i, j)$、の桁数を計算します。$a_j$、連結された値を構築し、次のように割り切れるかどうかをテストします。$k$。 これは簡単で正しいですが、実際には$O(n^2)$限界をはるかに超えた操作$n = 2 \cdot 10^5$。 

重要な観察は、実際には完全な連結された数値が必要ないということです。 必要なのはその値の剰余だけです$k$。 もし$len(x)$の桁数です$x$の場合、連結は次の条件を満たします。$$concat(x, y) \bmod k = (x \cdot 10^{len(y)} + y) \bmod k$$したがって、問題は次の場合のペアを数えることに帰着します。$$(a_i \cdot 10^{len(a_j)} + a_j) \equiv 0 \pmod{k}$$並べ替え:$$a_i \cdot 10^{len(a_j)} \equiv -a_j \pmod{k}$$これは、数値を桁の長さによってグループ化することを示唆しています。 各数値について、その剰余モジュロを事前に計算できます。$k$、また 10 のべき乗をモジュロで事前計算します$k$長さ 1 ～ 10 の場合 ($a_i \le 10^9$、桁の長さは最大 10)。 

固定の場合$a_j$、何個か数えたいです$a_i$満足する：$$a_i \equiv (-a_j) \cdot (10^{len(a_j)})^{-1} \pmod{k}$$ただし、モジュラー逆関数を直接使用するのは不要であり、場合によっては安全ではありません。$k$は素数ではない、または 10 と因数を共有します。代わりに、視点を逆にします。各数値について、考えられるすべての桁の長さを試し、事前に計算された度数表と照合します。 

以前に確認した数値の残りのカウントを桁の長さごとにグループ化して保持します。 それぞれの番号について$a_i$、それをペアの 2 番目の要素とみなし、可能な桁長ごとに、それとペアになる以前の数字の数を計算します。 次に、周波数構造を更新します。 

これにより問題は次のように縮小されます$O(n \cdot 10)$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^2)$|$O(1)$| 遅すぎる |
 | 最適 |$O(n \cdot 10)$|$O(k)$| 承認済み |

 ## アルゴリズムのチュートリアル

 ### 重要なアイデアの設定

 10 のべき乗をモジュロで事前計算します$k$数値を連結する場合、桁のシフトが唯一の構造変換であるためです。 

また、桁の長さによって数値をグループ化し、これまでに確認された残基の頻度を追跡します。 

### ステップ

 1. 事前計算`pow10[d] = 10^d mod k`これにより、数字を追加して数値を左にシフトすることをすばやくシミュレートできます。 
2. 辞書を管理する`cnt[len][rem]`、 どこ`len`は桁の長さであり、`rem`剰余モジュロです$k$。 これは、指定された桁長で、指定された剰余を持つ、以前に処理された数値の数を保存します。 
3. 配列を左から右に処理します。 それぞれの番号について$x$、次を計算します。 

- その残り`rx = x % k`- 桁の長さ`dx`4. ペアの 2 番目の要素としての現在の数値について、考えられるすべての桁の長さを試します$d$最初の要素の場合:

 - 必要です$(y * 10^{dx} + x) % k = 0$- それで$y * 10^{dx} \equiv -x \pmod{k}$- これは、保存された周波数を使用した直接チェックになります。$$y \equiv (-x) \cdot 10^{-dx} \pmod{k}$$逆数を計算する代わりに、保存されている可能性のあるすべての剰余をチェックすることによってシミュレートします。 
5. で終わるペアの貢献を数えた後$x$、 入れる$x$の中へ`cnt[dx][rx]`。 

### なぜ効果があるのか

 いつでも、`cnt`は、現在のインデックスを 2 番目の要素とするペアの最初の要素として表示できる数値のマルチセットを正確に表します。 すべての有効なペアは、その 2 番目の要素を処理するときに 1 回だけカウントされます。 桁の長さによってモジュラー シフトの動作が完全に決定されるため、長さによってグループ化すると正確さが保たれます。 すべての有効な桁長変換に対して以前のすべての要素が考慮されるため、ペアが失われることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    def digits(x):
        return len(str(x))

    pow10 = [1] * 11
    for i in range(1, 11):
        pow10[i] = (pow10[i - 1] * 10) % k

    cnt = [[0] * k for _ in range(11)]
    ans = 0

    for x in a:
        rx = x % k
        dx = digits(x)

        for d in range(1, 11):
            # we want y * 10^dx + x ≡ 0 mod k
            # => y * 10^dx ≡ -x mod k
            need = (-rx) * pow10[dx] % k

            ans += cnt[d][need]

        cnt[dx][rx] += 1

    print(ans)

if __name__ == "__main__":
    solve()
```実装はアルゴリズムを直接反映しています。 の`pow10`array は、モジュラー算術における桁シフトを処理します。 2D 配列`cnt`ハッシュのオーバーヘッドを回避し、高速アクセスを保証します。 各数値について、現在の数値を挿入する前に最初の要素のすべての可能な桁長をクエリします。これにより、自己ペアリングが防止され、順序付けが保証されます。$(i, j)$。 

唯一の微妙な点はコンピューティングです`need`。 最初の数値の剰余の要件をエンコードするので、シフト後に次のようになります。`10^dx`そして追加`x`、結果は次で割り切れます。`k`。

import sys, io

    import sys
    input = sys.stdin.readline

    a = list(map(int, input().split()))

        return len(str(x))

    pow10 = [1] * 11

 ## 特殊なケース

 すべての要素が同一である配列の場合、$k = 1$、順序付けられたすべてのペアが有効です。 すべての剰余がゼロであり、桁の長さに関係なく、すべての検索が以前のすべてのエントリと一致するため、アルゴリズムはこれを処理します。 

最大桁長 (10 桁) の数値の場合、正確さは次の点に依存します。`pow10`は 10 まで事前に計算されます。この境界が無視されると、桁シフトが暗黙のうちに不正確になります。 ここでも、各 10 桁の数値は同じ剰余ロジックを通じて同様に処理されるため、特別な処理は必要ありません。 

連結が割り切れない場合の場合$k$、シフト下で決して整列しない慎重に選択された剰余など、頻度表は単に一致することなく累積されます。`need`価値。 有効なペアはカウントされないため、答えはゼロのままです。
