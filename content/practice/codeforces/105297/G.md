 ## 解決策
 ## 問題の理解

 数直線上に一連の点が与えられており、これらの点を一定の順序で訪問する必要があります。 位置 0 から開始します。各ステップで、リスト内の次に必要な位置に移動しますが、2 つの移動モードから選択できます。 

通常の移動では、現在の位置から次のポイントまで移動し、それらの間の絶対距離が消費されます。 テレポート移動は現在の位置を無視し、代わりに保存された「テレポート アンカー」位置を使用します。そのコストは、そのアンカーと次のポイントの間の距離です。 テレポートを使用すると、アンカーがテレポート前にいた前の位置になるようにシステムが更新され、古いアンカーは破棄されます。 

したがって、プロセスは逐次的です。常に順番にポイントを訪問しますが、各トランジションは、現在いる場所から、または最後のテレポート アンカーからの 2 つの方法のいずれかで支払うことができます。 

目標は、最終点に到達するまでの総コストを最小限に抑えることです。 

制約は十分小さいので、$O(n^2)$または$O(n^2 \log n)$動的プログラミング ソリューションは受け入れられます。$n \le 1000$。 これは、素朴に実装された場合、状態ごとの遷移ごとの三次またはより複雑なものを即座に除外しますが、インデックスに対する 2 次元の DP を許可します。 

すべてのポイントが互いに接近している場合、微妙なエッジ ケースが現れますが、テレポートが繰り返し有益となるのは、特定の「ピボット」ポイントの後でのみです。 「ローカルで役立つときはいつでもテレポートする」などの貪欲な戦略は、アンカーの選択が次の移行だけでなく将来のすべてのテレポート コストに影響を与えるため、失敗します。 もう 1 つのエッジケースは、座標が 0、100、1、99 のように変動する場合です。この場合、最適なプレイは、最新の位置ではなく、過去の最高のアンカーを維持することに依存します。 

## アプローチ

 ブルートフォースアプローチでは、考えられるすべての決定シーケンスをシミュレートします。 各ステップで、通常に移動するかテレポートするかを決定し、テレポートする場合は、以前のどの位置が新しいアンカーになるかを暗黙的に決定します。 アンカーの進化は履歴全体に依存するため、これにより指数関数的な分岐が発生します。 枝刈りをしても状態空間が大きくなりすぎます。 

重要な観察は、どの時点においても重要な情報は、現在位置と現在のテレポート アンカーの 2 つの位置だけであるということです。 決定ごとにこれら 2 つの値のいずれかが更新され、将来のコストはそれらのみに依存します。 これにより、問題は、最後に訪問したポイントと最後のアンカー ポイントのインデックスに関する動的プログラミング状態に帰着します。 

現在の位置のインデックスと、以前に訪問した位置の中のアンカーポイントのインデックスに対して DP を定義します。 両方のインデックスの範囲が最大であるため、$n$、私たちは得ます$O(n^2)$州。 各状態から、通常の移動 (アンカーを変更しない) またはテレポート (アンカーを前の現在位置に更新) のいずれかによって次のポイントに移行します。 

この構造により、2 つのインデックスを超えた履歴の依存性が排除され、まさに問題が扱いやすくなります。

 | DP over (i, アンカー) | O(n^2) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 ポイントを順番に処理し、各状態が特定のインデックスまですでに訪問していることを表す DP テーブルを構築し、以前のどの位置が現在テレポート アンカーであるかを記憶します。 

1. ポイントを訪問する前に、開始状況で DP を初期化します。この状況では、位置 0 にいて、アンカーも事実上 0 になります。 
2. 最初の点について、最初からその点に到達するまでのコストを計算します。 以降のすべての状態は有効な最初の動きに基づいて構築されるため、これにより DP 状態の最初の層が初期化されます。 
3. 次の各ポイント インデックス i について、現在の位置 j とアンカー k によって定義される以前のすべての状態を考慮します。 これらは、テレポート アンカーが k であるときにポイント j に到達する可能性のあるすべての方法を表します。 
4. 状態 (j, k) から、i に移動するコストを 2 つの方法で計算します。 通常の移動コスト |a[i] - a[j]| そしてアンカー k を変更しないままにします。 これは、テレポート設定を変更せずに単に前に歩いていることを反映しています。 
5. テレポート移動のコストは |a[i] - a[k]| で、使用後は現在位置が k になり、新しいアンカーは j になります。 この交換は、テレポートで前のアンカーを消費し、前の位置に置き換えるというルールを反映しています。 
6. 結果として得られる各状態に到達するためのすべての方法の中で最小のコストを考慮して、それに応じて DP 遷移を更新します。 
7. すべてのポイントを処理した後、答えは、アンカーに関係なく、現在位置が最後のポイントであるすべての状態の中での最小コストになります。 

機能する理由: 許可されるコストは両方とも現在位置とアンカー位置のみに依存するため、すべての状態は将来の遷移を計算するために必要な情報を正確にエンコードします。 これら 2 つの値が固定されると、以前の履歴は将来の決定に影響を与えなくなります。 これにより、DP の最適な部分構造が有効になり、すべての有効な動きのシーケンスが DP 状態グラフ内の 1 つのパスに正確に対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    # dp[j][k] = minimum cost where:
    # j = current position index
    # k = teleport anchor index (0..n-1, plus 0 as virtual start)
    INF = 10**30

    dp = [[INF] * (n + 1) for _ in range(n + 1)]

    start = n  # use index n as virtual node for position 0
    dp[start][start] = 0

    # helper to get coordinate
    def coord(i):
        return 0 if i == n else a[i]

    for i in range(n):
        ndp = [[INF] * (n + 1) for _ in range(n + 1)]

        ci = a[i]

        for j in range(n + 1):
            for k in range(n + 1):
                cur = dp[j][k]
                if cur >= INF:
                    continue

                cj = coord(j)
                ck = coord(k)

                # normal move: j -> i
                cost1 = cur + abs(ci - cj)
                if cost1 < ndp[i][k]:
                    ndp[i][k] = cost1

                # teleport move: k -> i, update anchor
                cost2 = cur + abs(ci - ck)
                if cost2 < ndp[j][i]:
                    ndp[j][i] = cost2

        dp = ndp

    ans = min(dp[n][k] for k in range(n + 1))
    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、位置 0 の仮想インデックスを含むインデックスのペアに DP を明示的に格納します。ヘルパー関数`coord`は、その仮想インデックスを座標 0 にマップするため、距離の計算は均一に保たれます。 

遷移ロジックは、許可された 2 つの操作を直接反映しています。アンカーを保持しながら通常に移動するか、テレポートしてアンカーを現在の位置と交換します。 2 番目の遷移は、テレポートがそのアンカー状態を消費して置き換えるルールをエンコードしているため、唯一微妙な部分です。 

私たちはフルサイズを使用します$O(n^2)$レイヤーごとの DP テーブル。トランジション間で両方の次元が変化するため、これが必要です。

 ## 特殊なケース

 エッジケースの 1 つは次のような場合です$n = 1$。 このアルゴリズムは、0 から 0 までの単一の距離に縮小します。$a_1$利用できる以前の構造がないため、テレポートによって結果が改善されることはありません。 最初の遷移では |a[0] - 0| が直接計算されるため、DP は正しく初期化されます。 

もう 1 つのエッジ ケースは、1、2、3、4 のように座標を厳密に増加させることです。ここでは、将来のポイントではアンカーが常に現在の位置よりも遠いため、テレポートは役に立ちません。 DP は依然としてテレポート状態を調査していますが、それらが優勢になることはありません。そのため、最終的な答えは差の単純な合計と一致します。 

より微妙なケースは、0、100、1、99 のような大きい値と小さい値を交互に使用することで、最適なアンカーが極端な値の間で切り替わります。 DP は、すべてのアンカーと現在の組み合わせを評価するため、これを正しく捕捉し、貪欲でない決定が必要な場合でも最適なスワップ シーケンスが見逃されないようにします。
