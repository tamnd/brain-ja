 ## 解決策
 ## 問題の理解

 私たちには潜在顧客のリストが与えられ、各顧客が製品に対して支払ってもよい最高価格が示されています。 価格を設定する場合$P$、つまり、まさにこれらの顧客$p_i \ge P$製品を購入し、それぞれが貢献します$P$収入に。 したがって、総収入は次のようになります。$P \times \#\{i : p_i \ge P\}$。 

タスクは単一の価格を選択することです$P$この収益を最大化する可能な値の実際のセットから計算し、選択された価格とその結果得られる最大収益の両方を出力します。 複数の価格が同じ最大収益を達成する場合は、そのうちのいずれかを返すことができます。 

重要な制約は、$N$と同じ大きさにすることができます$10^6$、そしてそれぞれ$p_i$まで行くことができます$10^9$。 これにより、数値範囲内のあらゆる可能な価格を試すアプローチは直ちに排除されます。 価格ごとの単純なチェックでは二次関数の動作が発生するため、ソートせずにすべての候補価格を反復処理するだけでも時間がかかりすぎます。 

すべての値が等しい場合、微妙なエッジケースが発生します。 たとえば、すべての顧客が$p_i = 10$、その後は任意の価格$P \le 10$完全な収益が得られます$10 \cdot N$。 最適な価格がすべての要素よりも小さい可能性があることを考慮せず、入力からの価格のみをテストする不注意なアプローチは、ここでも機能しますが、それが繰り返しの候補を正しく評価する場合に限ります。 

最適な価格が必ずしも最高値の 1 つであるとは限らない場合、別の問題が発生します。 たとえば、価格が$[5, 5, 5, 100]$、設定$P = 5$収入が得られる$5 \cdot 4 = 20$、 その間$P = 100$収量$100 \cdot 1 = 100$。 価格の低下が常に収益の増加につながると想定するソリューションは、ここでは失敗します。 

この構造は、収益関数が配列内に存在する値でのみ変化することを示唆しています。これは、2 つの連続する個別の値の間では、価格が上昇する間購入者の数は一定のままであり、ブレークポイントまでは収益を線形に改善することしかできないためです。 

## アプローチ

 直接的な強引なアイデアは、次のすべての整数の中で可能なすべての価格を試してみることです。$1$に$\max(p_i)$。 候補ごとの価格$P$、何個数えますか$p_i \ge P$、収益を計算します。 これは、問題の正確な定義を評価するため、正しいです。 

ただし、このアプローチは実行不可能です。 到達できる価格帯$10^9$、各価格について、すべてをスキャンする場合があります$N$顧客。 これは次のことにつながります$O(N \cdot \max p)$、それは天文学的な大きさです。 

重要な観察は、価格が配列内のいずれかの値を超えた場合にのみ購入者の数が変化するということです。 2 つの連続する並べ替え値の間では、購入者の数は一定のままであるため、収益関数は次のように線形になります。$P$そして、これらの間隔の終点の 1 つで最大値に達します。 これは、一部の価格に等しい価格のみを考慮する必要があることを意味します。$p_i$。 

配列を並べ替えると、それぞれの値以上の要素がいくつあるかを効率的に計算できます。 ソートされた順序で値を処理すると、価格のしきい値を上げたときに残っている顧客の数を追跡できます。 

ソートされた配列をスキャンし、それぞれの個別の値を候補価格として扱うことで、ソート後に線形時間で収益を計算できます。

 ## アルゴリズムのチュートリアル

 最初に配列を並べ替えて、考えられる価格しきい値ごとにどれだけの顧客が残っているかを推論できるようにします。 ソートは問題をサフィックス数の処理に変換するため、必須です。 

次に、ソートされた配列を繰り返し処理しますが、すべての位置を個別に評価するのではなく、等しい値をグループ化します。 個別の価格候補ごとに$P = p_i$、以上の要素がいくつあるかを計算します。$P$。 配列が非降順でソートされていて、インデックスにある場合$i$の場合、購入者の数は$N - i$。 

収益を次のように計算します。$P \times (N - i)$、そのようなすべての候補の最大値を追跡します。 

アルゴリズムは次のように進みます。 

## アルゴリズムのチュートリアル

 1. 配列をソートする$p$降順ではない順に。 これにより、より高いしきい値を持つすべての顧客が自然にグループ化されるため、サフィックスの長さが購入者の数を直接表すようになります。 
2. これまでに見つかった最高の収益と対応する価格を追跡するために変数を初期化します。 収益ゼロ、任意の価格からスタートします。 
3. ソートされた配列を左から右に走査します。 インデックスごとに$i$、 扱う$p[i]$販売価格の候補として。 
4. 購入者の数を次のように計算します。$N - i$、からのすべての要素があるため、$i$最後まで少なくとも$p[i]$。 これが機能するのは、並べ替えによって単調性が保証されるためです。 
5. 収益を計算する$R = p[i] \times (N - i)$。 これまでの最高の収益と比較し、それが大きい場合は更新します。 等しい場合は、どちらの値も維持できます。 
6. すべてのインデックスに対してこのプロセスを継続し、重複する値によって問題が発生しないことを確認します。これは、値は同じですが、サフィックス数が異なる可能性があるためです。 どちらも安全な候補です。 

### なぜ効果があるのか

 正しさは、固定価格であれば、$P$、購入する一連の顧客はまさに次のような顧客です。$p_i \ge P$。 ソートされた配列内の 2 つの連続する個別の値の間では、このセットは変化しません。 増加中$P$このような間隔内では収益が線形に減少するだけであるため、最適値は 2 つの隣接する個別の値の間に厳密に存在することはできません。 したがって、配列要素に等しい価格のみをテストするだけで十分であり、ソート後にサフィックス数を計算すると、そのようなすべてのケースが正しく捕捉されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    a.sort()

    best_rev = 0
    best_p = a[0]

    i = 0
    while i < n:
        j = i
        while j < n and a[j] == a[i]:
            j += 1

        p = a[i]
        buyers = n - i
        rev = p * buyers

        if rev > best_rev:
            best_rev = rev
            best_p = p

        i = j

    print(best_p, best_rev)

if __name__ == "__main__":
    solve()
```並べ替えのステップはソリューションの基礎です。 これにより、インデックスにあるときに、$i$、接尾辞$i \ldots n-1$価格を許容できるすべての顧客に正確に対応します$a[i]$。 

グループ化ロジック$j$繰り返される値に対する冗長な再計算を回避します。 厳密には必須ではありませんが、明確な価格のみが重要であるという考えに沿った推論を維持します。 

Python では収益の計算に 64 ビットの安全な算術演算が暗黙的に使用されますが、固定整数型を使用する言語では、このステップには注意が必要です。$10^9 \cdot 10^6$64 ビットの符号付き範囲には適合しますが、32 ビットには適合しません。

 ## 特殊なケース

 次のような単一要素入力の場合$N=1$、アルゴリズムは自明にソートし、1 つの候補を検討します$P = p_1$、収益を生み出す$p_1$。 サフィックス数は 1 なので、結果は正しいです。 

すべての値が同一である場合、次のようにします。$[7,7,7,7,7]$、どのインデックスも同じ収益を生み出します$7 \cdot 5$。 グループ化ステップにより、評価は 1 回だけになりますが、グループ化を行わない場合でも、各重複は同一の結果を生成するため、正確性は保たれます。 

など、大きな値に小さな値が多数混在する場合$[1,1,1,100]$、アルゴリズムは両方を評価します$P=1$そして$P=100$。 で$P=1$、収益は$4$、$P=100$、収益は$100$。 ソートにより大きな値が最後に配置され、サフィックス サイズ 1 が与えられ、収益が直接得られるため、サフィックス ベースの計算はこのコントラストを正確に捕捉します。
