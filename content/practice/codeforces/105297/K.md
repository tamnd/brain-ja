 ## 解決策
 ## 問題の理解

 N 個のぬいぐるみの行が与えられ、それぞれが正または負の整数値を持ちます。 最大で M 回の操作を実行できます。 各操作は、正確に W 個のぬいぐるみのブロックを削除する特別な爪の使用に対応しますが、ブロックは、削除後に縮小する固定インデックス システムでは選択されません。 代わりに、爪は現在の物理的なレイアウトに基づいて機能します。動物は固定位置に留まり、削除後に隙間が生じます。爪を配置すると、削除が行われる前に右の突起が既存のぬいぐるみに当たるまで左にスライドできます。 

機械的な説明にもかかわらず、各操作の主な結果は単純です。1 つの操作で、現在残っているシーケンス内のぬいぐるみの連続セグメントが削除され、削除された値がスコアに寄与します。 目標は、最大 M 回のこのような操作を使用した後に、削除された値の合計を最大化することです。 

N ≤ 104 および M ≤ 5000 という制約は、二次動的計画法のソリューションが意図されていることを強く示唆しています。 セグメントのすべての選択肢に対する三次解では、操作ごとに O(N²) セグメントを試行する必要があり、これでは遅すぎます。 O(N²M)すら不可能です。 O(NM) または O(NM log N) に近い値を目指す必要があります。これは、各状態遷移を定数時間または償却定数時間で計算する必要があることを意味します。 

最も危険なエッジケースは、削除が将来のセグメントにどのような影響を与えるかを誤解することです。 素朴な解釈では、セグメントを削除するとインデックスが変化し、今後のすべての決定は残りのギャップの複雑な形状に依存することが示唆されるかもしれません。 たとえば、W = 2 の場合:

 入力:```
4 2 2
1 100 -100 1
```単純な貪欲な人は、1 つのブロックを削除すると、後で隣接するとみなされるものに影響を与えることに気づかずに、中間のペアまたは端のいずれかを削除する可能性があります。 ただし、正しく解釈すると、相対的な順序が保持され、一般性を失うことなく最適な戦略を元のインデックスにマップし直すことができるため、問題は元の配列で互いに素な固定ウィンドウを選択することになります。 

もう 1 つの微妙な失敗例は、ウィンドウが重なっていることです。 ソリューションが誤ってセグメントの重複を許可すると、同じ要素が複数回カウントされる可能性があります。```
5 2 3
5 5 5 5 5
```間違ったアプローチでは、ウィンドウ [1,3] と [2,4] が選択され、共有要素が過大にカウントされる可能性がありますが、これは有効な操作では物理的に不可能です。 

## アプローチ

 ブルートフォース戦略では、各削除後に展開する配列内で長さ W のセグメントを最大 M 個選択するためのあらゆる可能な方法を列挙します。 各操作の後、ギャップにより配列構造が変化するため、これを直接シミュレートするには、動的なシーケンスを維持し、すべてのステップで可能な配置をすべて試す必要があります。 実装の複雑さを無視しても、状態の数は組み合わせ的に増加します。 各ステップで O(N) 個の位置を選択でき、これを M 回実行すると、最悪の概念形式でおおよそ O(N^M) が得られ、セグメントに制限しようとするとせいぜい O(N^{2M}) が得られますが、どちらも完全に実行不可能です。 

重要な簡素化は、削除プロセスによって最適性が変わるような新しい相対的隣接関係が作成されるわけではないことを認識することです。 セグメントが削除されると、その中にあるものは後の操作に影響を与えず、残りの要素は順序を保持するため、一連の削除を元の配列内の重複しないセグメントの選択にマッピングできます。 これにより、総和を最大化するために元の配列内の固定長 W の最大 M 個の互いに素なセグメントを選択するという問題が生じます。 

この削減が行われると、構造は古典的な動的計画法の問題になります。 左から右にスキャンして、位置 i でセグメントを終了するかどうかを決定します。 セグメントを取得する場合、それは i − W + 1 から開始する必要があり、そのセグメントの前の最適解にその合計を加算します。 スキップすると、前の値が引き継がれます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (動的構造ですべての操作をシミュレート) | 指数 | O(N) | 遅すぎる |
 | エンドポイントを介した動的プログラミング | O(N・M) | O(N · M) または O(N) 最適化 | 承認済み |

 ## アルゴリズムのチュートリアル

 セグメントの合計を一定時間で迅速に計算するために、プレフィックス合計配列を定義します。 dp[i][j] を、最初の i 個のぬいぐるみを使用して正確に j 回の除去を実行して取得できる最大合計値を表すものとします。 

1. l から r までのセグメントの合計が prefix[r] − prefix[l − 1] として計算できるように、プレフィックスの合計を事前計算します。 これは、固定長ブロックを繰り返し評価するために必要です。 
2. 1 から N までの各位置 i、および 0 から M までの演算数 j ごとに、2 つの可能性を考慮します。i で削除を終了しないか、i で長さ W の削除を終了します。 
3. i で終わるセグメントを削除しない場合、dp[i][j] は dp[i − 1][j] を引き継ぎます。 これは、削除ブロック内で i 番目の要素を未使用のままにすることに相当します。 
4. i で終わるセグメントを削除する場合、そのセグメントは正確に [i − W + 1, i] でなければなりません。 これは、i ≥ W および j ≥ 1 の場合にのみ実行できます。遷移は dp[i][j] = max(dp[i][j], dp[i − W][j − 1] + sum(i − W + 1, i)) になります。 dp[i − W][・] は取得しているセグメントを完全に除外するため、これにより素性が保証されます。 
5. 各州の両方の選択肢の最大値を採用します。 
6. 最終的な答えは、すべての j ≤ M にわたる最大 dp[N][j] です。 

これがなぜ有効であるかは、選択されたセグメントが正しいエンドポイントの昇順に考慮されるように、最適なソリューションを再配置できるという事実に依存します。 最適な構成ではセグメントが重なり合うことはないため、セグメントの境界でアレイを切断すると、決定が完全に分離されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    N, M, W = map(int, input().split())
    a = list(map(int, input().split()))

    pref = [0] * (N + 1)
    for i in range(1, N + 1):
        pref[i] = pref[i - 1] + a[i - 1]

    def seg(l, r):
        return pref[r] - pref[l - 1]

    NEG = -10**18
    dp = [[NEG] * (M + 1) for _ in range(N + 1)]
    dp[0][0] = 0

    for i in range(1, N + 1):
        for j in range(0, M + 1):
            dp[i][j] = max(dp[i][j], dp[i - 1][j])

            if i >= W and j >= 1:
                val = seg(i - W + 1, i)
                dp[i][j] = max(dp[i][j], dp[i - W][j - 1] + val)

    ans = 0
    for j in range(M + 1):
        ans = max(ans, dp[N][j])

    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションでは、最初にプレフィックスの合計を構築して、すべての候補除去ウィンドウを一定時間で評価できるようにします。 DP テーブルは行ごとに埋められ、各状態は現在の位置を無視するか、その位置で終わる固定サイズの削除ブロックを完了します。 W 位置だけジャンプして戻るトランジションにより、削除されたセグメントが決して重ならないことが保証されます。 

微妙な点は初期化です。dp にはゼロではなく非常に負の数値が入ります。これは、到達不可能な状態と、たまたま負の合計を持つ有効な状態を区別する必要があるためです。 これがないと、無効な遷移が誤って優勢になってしまう可能性があります。 

## 実用的な例

 次の入力を考えてみましょう。```
4 2 3
1 8 -10 5
```プレフィックスの合計を計算します: [0, 1, 9, -1, 4]。 

dp をエンドポイントごとに評価します。 

| 私 | j | dp[i-1][j] をスキップ | ウィンドウを取る | 最高 |
 | --- | --- | --- | --- | --- |
 | 3 | 1 | dp[2][1] = 0 | 合計(1..3)= -1 | 0 |
 | 4 | 1 | dp[3][1] = 0 | 合計(2..4)= 3 | 3 |
 | 4 | 2 | dp[3][2] = 0 | sum(2..4)+dp[1][1] 無効 | 0 |

 最良の選択は、セグメント [2,4] を取得して 8 + (-10) + 5 = 3 を与えるか、2 番目のセグメントを取得しないことです。 

次に、一様なケースを考えてみましょう。```
5 2 2
5 5 5 5 5
```サイズ 2 のすべてのウィンドウの合計は 10 です。最適な戦略は、互いに素なウィンドウ [1,2] と [3,4] を取得することです。 

| 私 | j | スキップ | 取る | 最高 |
 | --- | --- | --- | --- | --- |
 | 2 | 1 | 5 | 10 | 10 |
 | 4 | 2 | 10 | 10 + 10 | 20 |
 | 5 | 2 | 20 | 無効 | 20 |

 これは、DP が自然に非重複を強制し、最適な互いに素なセグメントを蓄積することを確認します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N・M) | 各 dp 状態は、プレフィックス合計 | を使用して O(1) 遷移で計算されます。 
| スペース | O(N・M) | DP テーブルには、各プレフィックスと操作数の最適な値が格納されます。 

N ≤ 10⁴ および M ≤ 5000 の制約により、最大 5 × 10⁷ の状態更新が許可されます。これは境界線ですが、遷移が単純な算術演算と配列インデックスのみの場合、最適化された Python では許容されます。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    N, M, W = map(int, input().split())
    a = list(map(int, input().split()))

    pref = [0] * (N + 1)
    for i in range(1, N + 1):
        pref[i] = pref[i - 1] + a[i - 1]

    NEG = -10**18
    dp = [[NEG] * (M + 1) for _ in range(N + 1)]
    dp[0][0] = 0

    for i in range(1, N + 1):
        for j in range(M + 1):
            dp[i][j] = max(dp[i][j], dp[i - 1][j])
            if i >= W and j >= 1:
                val = pref[i] - pref[i - W]
                dp[i][j] = max(dp[i][j], dp[i - W][j - 1] + val)

    return str(max(dp[N]))

| W=1の場合 | 12 | 最適な M 要素を選択することになります |

 ## 特殊なケース

 重要なエッジケースは、すべての値が負の場合です。 dp[0][0] = 0 であり、スキップ操作が全体を通じて有効であるため、アルゴリズムはこれを正しく処理します。 例えば：```
5 2 2
-1 -2 -3 -4 -5
```すべてのウィンドウには負の合計があるため、「テイク」トランジションごとにスコアが減少します。 スキップ遷移が常に優先され、出力 0 になるため、DP はセグメントの取得を強制しません。 

もう 1 つのエッジ ケースは、W = 1 の場合で、すべての操作で 1 つの要素が削除されます。 各セグメントは独立しているため、DP は最大 M 個の最大値を選択することになります。 dp[i][j] はスキップと i の単一要素の取得を比較するため、遷移は引き続き機能します。 

境界ケースは、W = N の場合に発生します。有効なセグメントは 1 つだけ存在します。 DP は、dp[N][1] のみがテイクを含むことができることを保証し、すべてをスキップした場合と正しく比較し、max(0, total sum) を返します。
