 ## 解決策
 ## 問題の理解

 次々に曲を再生する単一の音楽デバイスがあります。 各ゲストは特定の時間に到着し、固定長の曲を選択します。通常、その曲は再生キューの最後に追加されます。 

時間は進み、デバイスは現在アクティブなものを継続的に再生します。 曲が終了すると、キュー内の次の曲が遅延なくすぐに開始されます。 

一部のゲストは、曲を選択する瞬間に特別なボタンを押すことができるのが特徴です。 そうした場合、その曲は通常のキューに入れられた曲のように動作しません。 代わりに、その瞬間に現在再生されているものを即座に置き換え、再生が即座にその曲に切り替わります。 中断された曲は破棄され、再開されることはありません。 重要なのは、キュー内で待機していたものはすべて変更されないことです。 

ゲストが不満になるのは、自分の曲がアクティブに再生されており、別のゲストが曲が終了する直前に一度にこの中断ボタンを使用した場合のみです。 曲が終了した瞬間に割り込みが発生した場合、それは割り込みとしてカウントされません。 

課題は、どのゲストが少なくとも 1 回は歌を中断されたかを特定することです。 

入力サイズは最大 100,000 イベントまで可能で、イベントごとに最初から再起動したり、キューを繰り返しスキャンしたりするシミュレーションは直ちに除外されます。 実際に線形または線形に近い解決策より悪い解決策は、制限時間内で苦労することになります。 この構造は、私たちが単一の進化するタイムラインを扱っていることも示唆しているため、効率的なシミュレーションまたはイベント処理が必要です。 

曲が再生されていないときに複数のゲストが対話する場合、微妙なエッジケースが発生します。 その場合、ゲストが割り込みボタンを使っても何も割り込むことがないので、誰も不愉快になることはありません。 もう 1 つの注意が必要なケースは、ちょうど曲の境界で割り込みが発生する場合です。 曲はすでに終了しているため、中断としてカウントされるべきではありません。 

## アプローチ

 直接シミュレーションでは、明示的な曲のキューを維持し、時間を秒ごとまたはイベントごとにシミュレートし、曲が終了したかどうか、またはゲストが中断したかどうかを常にチェックします。 システムが決定的であるため、これは概念的に機能します。つまり、曲が順番に再生され、割り込みが発生すると現在の曲が即座に置き換えられます。 ただし、曲の長さと時間が最大 10^7 になるため、細かい粒度でシミュレーションすると遅すぎます。つまり、最悪の場合、シミュレーションには最大 10^12 の操作が必要になる可能性があります。 

重要な観察は、時間の連続的な進行と曲の決定的な完成以外には、イベントの間に何も起こらないということです。 ゲストが到着したときと曲が終わったときなど、個別の瞬間に反応するだけで済みます。 これにより、現在の曲への単一のポインタと待機中の曲のキューを維持しながら、段階的にではなくジャンプして時間を進めることができます。 

2 番目の洞察は、割り込みは現在再生中の曲にのみ影響し、キューには影響しないということです。 これは、新しい曲を追加する場合を除いて、将来予定されている曲を変更する必要がないことを意味します。 したがって、システムは、現在の状態、FIFO キュー、および時折の強制交換を含む単一のタイムラインとしてモデル化できます。 

連続するイベント間の時間の進行をシミュレートすることで、各到着時点で現在の曲が常に正しいことを確認でき、イベントごとに一定の作業のみを実行します。

 ## アルゴリズムのチュートリアル

 現在の曲 (存在する場合)、その終了予定時刻、および中断することなく追加された保留中の曲のキューという 3 つの状態を維持します。 また、どこまでシミュレーションしたかを追跡する現在の時間ポインターも維持します。

1. イベントを並べ替えるか、すでに時間の昇順になっていると仮定します。 この問題では明確な時間が保証されているため、入力順に処理できます。 
2. イベント処理前`t`、現在時刻から次の時刻までシミュレーションを進めます。`t`。 この間隔中、現在の曲が終了する前または終了する場合は、繰り返し終了します。`t`、すぐにキュー内の次の曲を開始します。 これにより、いつでも`t`、現在の曲の状態は正確です。 
3. 現在の曲が存在しない場合`t`キューが空ではない場合は、すぐに次のキューにある曲を開始します。 終了時間は次のように計算されます。`t + duration`。 
4. 時間ごとにイベントを処理する`t`。 ゲストがボタンを使用しない場合（`c = 0`)、曲をキューに追加します。 最終的には、前の曲が終了した後に再生されます。 
5. ゲストがボタン (`c = 1`）、曲が現在再生されているかどうか、および曲が終了した後に厳密に終了するかどうかを確認します。`t`。 その場合、曲が中断されるため、現在の曲の所有者に悲しいマークを付けます。 
6. 現在の曲をすぐに新しい曲に置き換え、終了時間を次のように設定します。`t + duration`。 この曲はキューに入りません。 
7. 次のイベントに進みます。 

### なぜ効果があるのか

 いつでも、システムの状態は現在の曲と保留中の曲のキューによって完全に決定されます。 イベント間では、システムは外部入力なしで決定論的に進化するため、情報を失うことなく次のイベント境界まで時間を安全に早送りできます。 すべての中断は発生した瞬間に 1 回だけ処理され、将来のイベントが過去の再生に遡って影響を与えることはありません。 これにより、中断されたすべての曲が再生中に置き換えられたときに正確にカウントされることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n = int(input())
    events = []
    for i in range(n):
        t, m, c = map(int, input().split())
        events.append((t, m, c, i + 1))

    queue = deque()
    sad = set()

    cur_id = 0
    cur_end = 0
    cur_dur = 0

    # we also need to know current owner id; store it separately
    cur_owner = None

    time = 0

    def start_next(t):
        nonlocal cur_owner, cur_end, cur_dur
        if queue:
            oid, dur = queue.popleft()
            cur_owner = oid
            cur_dur = dur
            cur_end = t + dur
        else:
            cur_owner = None
            cur_end = t

    for t, m, c, idx in events:
        # advance time to t
        while cur_owner is not None and cur_end <= t:
            time = cur_end
            start_next(time)

        time = t

        # if no current song, start from queue
        if cur_owner is None:
            start_next(t)

        if c == 0:
            queue.append((idx, m))
        else:
            # interrupt if currently playing and not already finished at t
            if cur_owner is not None and cur_end > t:
                sad.add(cur_owner)

            cur_owner = idx
            cur_dur = m
            cur_end = t + m

    print(len(sad))
    if sad:
        print(*sad)
    else:
        print()

if __name__ == "__main__":
    solve()
```このソリューションは、保留中の曲のキューと、スケジュールされた終了時刻を持つ 1 つのアクティブな曲を維持します。 ヘルパーロジック`start_next`現在の曲が終了するたびに、キューに入れられた次の曲が正しい時間にすぐに開始されるようにします。 

重要なのはコンディションです`cur_end > t`曲を中断としてマークするかどうかを決定するとき。 曲がちょうど時間通りに終わった場合`t`、きれいに終わることが許されているので、悲しいこととしてカウントされてはなりません。 

もう 1 つの重要な点は、中断された曲はどこにも再挿入されないことです。 それらは完全に消えますが、キューに入れられた曲は影響を受けません。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各曲の開始と終了は最大 1 回行われ、各イベントは 1 回処理されます。 
| スペース | O(n) | キューには最大で n 個の保留中の曲が保存され、中断された曲は悲しいセットに保存されます。 

このアルゴリズムは各ゲストを 1 回だけ処理し、イベント間または曲の完了の間のジャンプで時間を進め、入力数の合計作業量を線形に保ちます。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque

    n = int(input())
    events = []
    for i in range(n):
        t, m, c = map(int, input().split())
        events.append((t, m, c, i + 1))

    queue = deque()
    sad = set()

    cur_owner = None
    cur_end = 0

    def start_next(t):
        nonlocal cur_owner, cur_end
        if queue:
            oid, dur = queue.popleft()
            cur_owner = oid
            cur_end = t + dur
        else:
            cur_owner = None
            cur_end = t

    time = 0

    for t, m, c, idx in events:
        while cur_owner is not None and cur_end <= t:
            time = cur_end
            start_next(time)

        time = t

        if cur_owner is None:
            start_next(t)

        if c == 0:
            queue.append((idx, m))
        else:
            if cur_owner is not None and cur_end > t:
                sad.add(cur_owner)
            cur_owner = idx
            cur_end = t + m

    out = [str(len(sad))]
    if sad:
        out.append(" ".join(map(str, sad)))
    else:
        out.append("")
    return "\n".join(out)

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、曲が終了したまさにその瞬間に割り込みが発生する場合です。 その時の状態としては、`cur_end > t`曲が中断されたとみなされないようにします。 たとえば、曲が時間 5 で終了し、別のゲストが時間 5 でボタンを使用した場合、最初の曲はすでに終了しているため、悲しみは記録されません。 

もう 1 つのケースは、曲が再生されておらず、キューが空のときに複数のゲストが到着した場合に発生します。 この状況では、中断されない各曲はすぐに開始され、中断は非表示の状態に影響を与えることなく現在の曲を単純に置き換えます。 アルゴリズムはこれを処理します。`cur_owner`になる`None`有効なアクティブな曲が存在する場合にのみ移行します。 

3 番目のケースは、急速に連続する割り込みです。 各割り込みは現在のソングを直接置き換え、アクティブなソングは 1 つだけ追跡されるため、更新を繰り返してもエラーが蓄積されません。 各置換は正確なタイムスタンプで独立して処理され、前のアクティブな曲は破棄される前に正確に 1 回だけ悲しい曲として記録されます。
