 ## 解決策
 ## 問題の理解

 このタスクは、各エッジが交通規制された通路のように動作するグラフ内の目的地ノードへの可能な限り最も早い到着時間を計算することです。 固定開始時間にノード 1 から開始し、すべてのエッジに基本的に移動時間はかかりませんが、特定の周期的な「オープン ウィンドウ」中にのみ通過できます。 各エッジは、一定期間開いた状態と一定期間閉じた状態を交互に繰り返します。このパターンは、開いたフェーズの時間 0 から無限に繰り返されます。 

ノードに到着すると、複数の発信エッジがそれぞれの信号で通過できるまで待たなければならない場合があります。 目的は、これらの周期的制約によって課せられるすべての待ち時間を考慮して、ノード N での最終到着時間を最小化するノード 1 からノード N へのルートを選択することです。 

グラフには最大 100,000 個のノードと 200,000 個のエッジを含めることができるため、時間を段階的にシミュレートしたり、考えられるすべてのパスの待機動作を再計算したりするソリューションは即座に除外されます。 最短パスのフレームワークが必要ですが、標準のグラフとは異なり、エッジ コストはノードへの到着時間に依存するため、トラバース コストが動的に変化します。 

貪欲な選択により待機サイクルが無視されると、微妙な失敗のケースが発生します。 たとえば、2 つのルートを考えてみましょう。1 つはエッジが少ないものの、開いているウィンドウが見つからないために待ち時間が長くなり、もう 1 つはエッジが多いものの、サイクルとの整合性が高く、より早い到着につながります。 タイミングを無視する単純な BFS または DFS では、エッジ コストが固定されていないため、不正確な結果が生成されます。 

もう 1 つのよくある落とし穴は、ノードで 1 回待機すれば十分であると想定していることです。 各エッジには独自のサイクルがあるため、同じノードでも、どの発信エッジが選択されるか、またそこに到着する時刻に応じて、非常に異なる遅延が発生する可能性があります。 

## アプローチ

 ブルートフォースのアイデアでは、時間をシミュレーションしながら、ノード 1 からノード N までの可能なすべてのパスを探索しようとします。 各ノードで、すべての発信エッジを試し、エッジのサイクルに基づいて次に考えられる出発時刻を計算します。 これは基本的に、ノードと時間にわたる完全な状態空間検索になります。時間は最大 10^9 まで増加する可能性があります。 時間遷移を離散化したとしても、ノードへの各到着時刻が将来の異なる動作につながる可能性があるため、状態の数は爆発的に増加します。そのため、同じノードを異なるタイムスタンプで何度も再訪する必要があります。 最悪の場合、これは、パスの数にサイクル アライメント チェックを乗じた指数関数的な動作となり、実現可能な制限をはるかに超えます。 

重要な観察は、これは依然として最短経路問題であるが、時間依存のエッジ緩和関数を伴うということです。 時刻にノードに到着したとき`t`、エッジを横断するコストは一定ではありませんが、そのサイクルでモジュラー演算を使用して O(1) で計算できます。 この構造により、各ノードまでの「距離」を既知の最も早い到着時刻として扱う場合、ダイクストラのアルゴリズムを使用することができます。 

移行ルールは次のようになります。時間通りであれば`t`ノードで、オープンタイムのあるエッジを考慮します`x`そして閉店時間`y`、次に、最初に長さのサイクルのどこにいるかを計算します。`x + y`。 オープンフェーズにある場合は、すぐに終了します。 それ以外の場合は、次のオープンフェーズが開始されるまで待機します。 これにより、そのエッジの次回の到着時間が決定的に決まります。 

これにより、この問題は、非負のエッジ重みを備えた標準的な単一ソース最短経路問題に変換されます。重みは動的に計算されますが、ダイクストラの貪欲な特性に対して常に有効です。

 | オプティマル (ダイクストラ) | O(M log N) | O(N + M) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各交差点をグラフ内のノードとしてモデル化し、各道路をパラメータを保持する無向エッジとしてモデル化します。`(x, y)`その開いたサイクルと閉じたサイクルを説明します。 これにより、動きを時間依存のコストを伴うグラフの走査として再解釈できるようになります。 
2. 配列を初期化する`dist[]`大きな値と設定`dist[1] = t`、ノード 1 から開始するので、`t`。 この配列は、各ノードでの既知の最も早い到着時刻を追跡します。 
3.プッシュ`(t, 1)`最小ヒープ優先キューに入れられます。 ヒープは常に、次に拡張するために現在わかっている最も早い到着状態を選択し、時間の増加順にノードを処理することを保証します。 
4. ノードの抽出を繰り返す`u`最短の到着時間で`cur`。 この値が以前と比較してすでに古い場合は、`dist[u]`、スキップしてください。 これにより、最適ではないパスの冗長な処理が防止されます。 
5. 隣人ごとに`v`の`u`サイクル付き`(x, y)`、次の出発時間を計算します。 

最初の計算`cycle = x + y`そして`pos = cur % cycle`。 もし`pos < x`、エッジは現在開いており、時間になったらすぐにトラバースできます`cur`。 それ以外の場合は、次のサイクルの開始フェーズまで待たなければならないため、出発は`cur + (cycle - pos)`。 
6. 到着時間`v`移動時間は無視できるため、 はこの計算された出発時刻に等しくなります。 この値が改善されれば`dist[v]`、更新してプッシュします`(dist[v], v)`山の中へ。 
7. 到達可能なすべてのノードが処理されるまで続行します。 答えは`dist[N]`。 

正確さは、ノードが優先キューから取り出されたときに、そのノードの可能な最小到着時間が判明したという事実に依存します。 それ以降の到着では厳密に長い時間が必要となり、エッジ遷移によって負の時間短縮が生じることはないため、将来の緩和によって最終的な状態を改善することはできません。 

## Python ソリューション```python
import sys
import heapq
input = sys.stdin.readline

def solve():
    n, m, t = map(int, input().split())
    g = [[] for _ in range(n + 1)]

    for _ in range(m):
        a, b, x, y = map(int, input().split())
        g[a].append((b, x, y))
        g[b].append((a, x, y))

    INF = 10**30
    dist = [INF] * (n + 1)
    dist[1] = t

    pq = [(t, 1)]

    while pq:
        cur, u = heapq.heappop(pq)
        if cur != dist[u]:
            continue

        for v, x, y in g[u]:
            cycle = x + y
            pos = cur % cycle

            if pos < x:
                nxt = cur
            else:
                nxt = cur + (cycle - pos)

            if nxt < dist[v]:
                dist[v] = nxt
                heapq.heappush(pq, (nxt, v))

    print(dist[n])

if __name__ == "__main__":
    solve()
```ダイクストラ緩和中にすべての外向きエッジを効率的にトラバースする必要があるため、グラフは隣接リストとして保存されます。 各緩和では、単一のモジュロ演算を使用して実行可能な最も早い通過時間を計算し、遷移 O(1) を維持します。 

優先キューにより、既知の到着時間の昇順でノードが処理されることが保証されます。 古い状態のチェック`if cur != dist[u]`古いエントリの拡張を回避します。これは、複雑さを 2 次ではなく対数に保つために不可欠です。 

よくある実装上の間違いは、サイクル条件を出発計画時ではなく到着時に評価する必要があることを忘れていることです。 もう 1 つは、閉じた間隔の遅延を誤って処理しており、待機は単に追加するのではなく、次の開いているフェーズの境界にジャンプする必要があります。`y`。

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import heapq

    def solve():

        g = [[] for _ in range(n + 1)]
        for _ in range(m):
            a, b, x, y = map(int, input().split())
            g[a].append((b, x, y))
            g[b].append((a, x, y))

        dist = [INF] * (n + 1)
        dist[1] = t

 ## 特殊なケース

 重大なエッジ ケースは、開始時間が既に開始間隔と終了間隔の間のちょうど移行点にある場合に発生します。 エッジ用`(x, y)`、 もし`cur % (x + y) == x`、エッジはまだ境界状態にあるように見えても、すぐには使用できません。 このアルゴリズムは、次のサイクル開始までの完全な待機を正しく強制します。`pos < x`が厳密に要求されます。 

もう 1 つの微妙なケースは、待機により複数のサイクルにわたって時間が長くなる場合です。 たとえば、次の場合`cur`閉じたセグメントのはるか内側にある、式`cycle - pos`サイクルごとに繰り返すのではなく、次の開いているフェーズに正しくジャンプします。 これにより、待機の線形時間シミュレーションが妨げられます。 

最後に、複数のエッジが異なるタイミングで同じノードにつながっている場合、優先キューにより、最も早い到着のみが生き残ることが保証されます。 それ以降の到着は古いチェックによって破棄され、次善のパスがグラフ内をさらに伝播しないことが保証されます。
