 ## 解決策
 ## 問題の理解

 私たちは、各点が上下左右に 4 つの隣接する動きを持つ非常に大きな整数グリッドに取り組んでいます。 一部のグリッド ポイントは工事が行われているためにブロックされており、これらのブロックされたポイントにはアクセスできません。 

各クエリは、開始点から終了点までの有効な最短パスの数を要求します。ここで、「最短」とはマンハッタンの最短距離を意味するため、各ステップは目的地までのマンハッタンの距離を厳密に短縮する必要があります。 この制限により、すべての放浪が解消されます。すべての動きは正しい水平方向または正しい垂直方向に行われ、決してターゲットから離れないようにする必要があります。 

ブロックされたセルがなかった場合、からのすべてのパスが$(x_1, y_1)$に$(x_2, y_2)$は、固定数の水平移動と垂直移動を任意の順序で行うことで構成されるため、答えは二項係数になります。 難しいのは、一部の格子点が禁止されており、それらを通過するパスを除外する必要があることです。 

グリッド座標は両方の次元で最大 500,000 になるため、グリッドが大きすぎて明示的に表現できません。 ブロックされたポイントの数は最大 10 ですが、これが重要な構造上の制約です。 

微妙ですが重要な点は、パスは単調な最短ルートに沿ってのみ移動できるということです。 これは、目的地が北東であれば、北または東に移動するだけであることを意味します。 したがって、有効なパスはすべて、開始点と終了点の間の軸に沿った長方形の内側にあります。 

エッジケースは、障害物がこの単調な構造とどのように相互作用するかによって発生します。 単純な最短パスの数では、遠くでブロックされているが長方形の内側にあるパスの数を簡単にカウントしすぎてしまう可能性があります。また、もう 1 つのよくある間違いは、長方形内の単一の障害物であっても、領域を分割することで組み合わせが完全に変化する可能性があることを忘れていることです。 

たとえば、start が$(0,0)$、最後は$(2,2)$、にブロックがあります$(1,1)$、次に通過するすべてのパス$(1,1)$は無効です。 正しい答えは、合計パスからその点を通過するパスを引いたものです。 

合計は 6、(1,1) までは$\binom{2}{1} \cdot \binom{2}{1} = 4$したがって、答えは 2 です。中間のブロック ポイントを無視する素朴なアプローチでは、6 が出力されます。 

この制約は、クエリごとにグリッド DP または BFS を実行できないことを意味します。 最大 10,000 のクエリでは、約より悪いソリューションはありません$O(1)$または$O(n^2)$クエリごとは次の場合にのみ受け入れられます$n$小さいです、それはそうです。 重要なのは、障害物が 10 個しか存在しないという事実を利用することです。 

## アプローチ

 障害がなければ、各クエリは組み合わせ論の問題に帰着します。 させて$\Delta x = |x_2 - x_1|$そして$\Delta y = |y_2 - y_1|$。 最短経路の数は$\binom{\Delta x + \Delta y}{\Delta x}$, すべての動きの中から水平方向の動きの位置を選択するためです。 

障害物がある場合、強引なアイデアは、各クエリを四角形に制限されたグリッド DP または BFS として扱うことです。 座標範囲が最大 500,000 であるため、クエリごとに 1 回の走査さえ不可能であるため、これはすぐに失敗します。 

より洗練された総当り攻撃は、ブロックされていない座標のみを使用して長方形に対して DP を実行することです。 しかし、長方形は依然として巨大になる可能性があるため、これはまだ実現不可能です。 

重要な観察は、障害物の数が少ないということです。 これは、障害物を特別な中間点として扱い、それらに対して包含/除外を使用することを示唆しています。 グリッドの状態という観点から考えるのではなく、小さな点のセット間のパスという観点から考えるようになります。 

開始と終了とともに障害物を分類します。 次に、障害物を無視して、任意の 2 点間の単調パスの数を計算します。 その後、少なくとも 1 つの障害物を通過するパスの寄与を構造化された方法で差し引きます。各ポイントについて、最初の障害物を通過するパスを除き、開始点からその点までの有効なパスの数を計算します。 

開始と終了に加えて最大 10 個の障害物が含まれるため、これはクエリごとに最大 12 ポイントにわたる古典的な DP になります。 

クエリごとに次のことを行います。 

始点からすべての点まで、そして各点から終点までの経路を計算します。同時に、2 点間を移動するときは、単調な実現可能な遷移のみを考慮します (座標が適切に増加している場合のみ)。 次に、ソートされた順序でポイントを処理し、中間のブロックされたポイントを通過するパスを減算することによって、障害物の上に包含を適用します。 

これにより、各クエリが次のように削減されます。$O(n^2)$どこ$n \le 12$これは、10,000 件のクエリを処理するのに十分な速度です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (クエリごとのグリッド DP/BFS) |$O(Q \cdot H \cdot W)$|$O(H \cdot W)$| 遅すぎる |
 | 最適 (障害物を越える DP) |$O(Q \cdot n^2)$|$O(n^2)$| 承認済み |

 ## アルゴリズムのチュートリアル

 まず 1 つのクエリを修正します。 関連するすべてのポイント (開始点、終了点、ブロックされたすべてのセル) を収集します。 

開始点と終了点で定義される単調な長方形の内側にある点のみを考慮します。 障害物がこの長方形の外側にある場合、その障害物は最短経路上には存在できないため、このクエリでは無視できます。 

次に、x を増加させ、x が等しい場合は y を増加させて、関連するすべての点を並べ替えます。 有効なパスは両方の次元で小さい座標から大きい座標に移動する必要があるため、この順序付けでは単調な移動の制約が考慮されます。 

各ポイントの DP 値を定義します。これは、以前に処理された障害物を回避しながら、開始点からそのポイントまでの単調なパスの数を表します。 

開始点のDPを1として初期化します。 

ソートされた順序で各ポイントについて、最初に障害物を無視して開始点からポイントまでのすべての単調パスをカウントすることによって、その DP 値を計算します。 これは組み合わせの値です。 次に、それに到達できる以前のポイントからの寄与分を差し引きます。 

したがって、次のような構造化された方法で進めます。 

1. 開始点、終了点、およびすべての障害物で構成されるポイントのリストを作成します。 

これにより、すべての潜在的な「ブロック相互作用」が小さな DAG 内のノードとして明示的に表現されるようになります。 
2. クエリの四角形内にないポイントをフィルタリングします。 

そのような点は最短の単調パス上に存在することはできないため、それを含めることは不必要な状態を追加するだけです。 
3. 点を x の順に並べ替え、次に y の順に並べ替えます。 

これにより、ポイントを処理するときに、有効なモノトーン パス内のすべての先行ポイントがすでに処理されていることが保証されます。 
4. 最大 1,000,000 までの二項係数または階乗を事前計算するか、事前計算された階乗および逆階乗を含む高速な組み合わせ関数を使用します。 

これが必要なのは、2 点間の各エッジの重みが二項係数であるためです。 
5. dp[i] を、これまでの障害物を無視した開始点から点 i までの有効なパスの数として定義します。 
6. 各点 i について、ソートされた順序で次のようにします。 

start から i までの基本ウェイを comb(dx + dy, dx) として計算します。 

次に、以前の点 j を通過するパスを減算します。 

j が単調に i に到達できる場合は、dp[j] * way(j → i) を減算します。 
7. 答えは dp[end] です。 

減算ステップは本質的に、DP 形式に組み込まれた包含-除外です。 各 dp[j] は、j より前の障害物を回避するパスをすでに表しているため、j から i までのパスを乗算すると、最初に j に到達してから継続するすべてのパスが計算されます。 

### なぜ効果があるのか

 最初から最後までのすべての単調なパスは、最初の障害物 (または障害物がないこと) によって一意に分解できます。 パスが障害物を通過しない場合、そのパスは終了の直接の組み合わせ項にカウントされます。 少なくとも 1 つの障害物を通過する場合、j をソート順で最初に通過した障害物とします。 start から j までのプレフィックスはすでに dp[j] に考慮されており、j から end までのサフィックスは独立してカウントされます。 DP 減算により、このような各分解が 1 回だけカウントされることが保証され、ソートされた順序で処理することで、循環依存性や二重カウントがないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def modinv(x):
    return pow(x, MOD - 2, MOD)

MAXN = 500000

fact = [1] * (MAXN + 1)
invfact = [1] * (MAXN + 1)

for i in range(1, MAXN + 1):
    fact[i] = fact[i - 1] * i % MOD

invfact[MAXN] = modinv(fact[MAXN])
for i in range(MAXN, 0, -1):
    invfact[i - 1] = invfact[i] * i % MOD

def comb(n, r):
    if r < 0 or r > n:
        return 0
    return fact[n] * invfact[r] % MOD * invfact[n - r] % MOD

def solve():
    n = int(input())
    obstacles = [tuple(map(int, input().split())) for _ in range(n)]
    t = int(input())

    for _ in range(t):
        x1, y1, x2, y2 = map(int, input().split())

        if x1 <= x2:
            xs, ys = x1, y1
            xt, yt = x2, y2
        else:
            xs, ys = x2, y2
            xt, yt = x1, y1

        pts = [(xs, ys), (xt, yt)]
        for x, y in obstacles:
            if xs <= x <= xt and ys <= y <= yt:
                pts.append((x, y))

        pts = list(set(pts))
        pts.sort()

        k = len(pts)
        dp = [0] * k
        dp[0] = 1

        for i in range(k):
            xi, yi = pts[i]
            ways = comb(xi - xs + yi - ys, xi - xs)
            dp[i] = ways

            for j in range(i):
                xj, yj = pts[j]
                if xj <= xi and yj <= yi:
                    dx = xi - xj
                    dy = yi - yj
                    dp[i] = (dp[i] - dp[j] * comb(dx + dy, dx)) % MOD

        end_index = pts.index((xt, yt))
        print(dp[end_index] % MOD)

solve()
```このコードは、階乗と逆階乗を最大座標まで事前計算することから始まり、定数時間の二項係数クエリを可能にします。 2 点間のすべての遷移が組み合わせで評価されるため、これは不可欠です。 

各クエリについて、常に左下から右上に移動するように方向を正規化し、単調性を確保します。 次に、境界四角形内のすべての障害物を収集し、それらを点セットに追加します。 

ソートにより、dp[i] を計算するときに、考えられるすべての先行処理がすでに計算されていることが保証されます。 dp 値は最初からの合計の組み合わせパスから始まり、以前の到達可能なすべてのポイントから寄与分を差し引いて、障害物を「通過」するパスを効果的に削除します。 

最終的な答えは、目的地の dp 値です。 

実装の微妙な詳細は、負の値を避けるために減算後にモジュロを取得することです。 もう 1 つは、単調な先行要素のみが考慮されるようにすることです。 そうしないと、無効な逆方向遷移によってカウントが破損する可能性があります。

 ## 特殊なケース

 重要なエッジ ケースは、障害物がクエリの境界四角形の外側にある場合です。 この状況では、単調な最短パスは到達できないため、完全に無視する必要があります。 アルゴリズムは、DP セットを構築する前に、座標境界を使用して障害物をフィルタリングすることでこれを処理します。 

もう 1 つのケースは、複数の障害物が同じ x または y の順序制約を共有しており、パスの順序が比較できない場合です。 x、次に y で並べ替えると、単調グラフの有効な位相順序が確保されるため、各点は以前に到達可能な点にのみ依存します。 

最後に、開始と終了が隣接している場合、DP は小さいサイズの単一の二項係数に縮退します。 セット内に中間点がないため、減算は行われず、基本の組み合わせカウントが直接返されるため、アルゴリズムは引き続き機能します。
