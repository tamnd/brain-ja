 ## 解決策
 ## 問題の理解

 私たちには、それぞれ異なる知識レベルを持つ学生のリストが与えられます。 目標は、知識レベルでソートした後、各グループが 2 つの制約を満たすように、それらを連続したグループに分割することです。つまり、最大知識から最小知識を引いたものとして定義されるグループ内の範囲が固定値 k を超えず、グループ サイズが s を超えないことです。 

グループが形成されると、ソートされた値に基づいて作業するため、知識の範囲が自動的に増加することによってグループが順序付けされます。 有効なパーティションとは、各セグメントが両方の制約に従うように、ソートされた配列を連続したセグメントに分割する方法です。 異なるセグメンテーションはすべて異なるソリューションとしてカウントされ、それらすべてを 1e9 + 7 を法としてカウントする必要があります。 

入力サイズ n は最大 10000 まで可能で、すべてのパーティションまたはすべてのサブセットにわたる指数列挙が除外されます。 O(n^2) でさえ、最適化されればかろうじて合格する可能性がありますが、3 次以上のものは直ちに実行不可能になります。 追加の制約 s ≤ 100 は、ソリューションを形成する重要な構造上の制限です。 

微妙な点は、グループ化はソート後の純粋に位置的なものであるため、任意のサブセットを選択するのではなく、ソートされた配列のパーティションのみを選択することです。 もう 1 つの微妙な点は、k が大きくても (最大 1e9)、影響するのはセグメントが有効かどうかのみで、組み合わせ構造には直接影響しないことです。 

これを「任意の場所のカットを独立して選択する」ものとして扱うのは単純な間違いです。 セグメントの有効性はサイズと最小/最大範囲の両方に依存するため、これは失敗します。そのため、カットが許可されるかどうかはその左側のウィンドウに依存します。 

具体的なエッジ ケースとして、値 [1、2、3] を持つ n = 3、s = 2、k = 0 を考えてみましょう。 どのペアの範囲も 1 > 0 であるため、サイズ 2 のグループは無効です。そのため、有効なパーティションは {1}、{2}、{3} のみです。 k を無視する単純なアプローチでは、{1,2}、{3} などのパーティションが誤ってカウントされる可能性があります。 

もう 1 つのエッジ ケースは、k が非常に大きい場合です。これは、サイズ制約のみが重要であることを意味します。 次に問題は、各セグメントの長さが最大 ​​s であるパー​​ティションをカウントすることになります。これは、スライディング ウィンドウ遷移を備えた標準 DP です。 

## アプローチ

 制約を無視すると、ソートされた配列の可能なすべてのパーティションを生成し、各グループの有効性をチェックしようとする可能性があります。 これには、2^(n-1) 個の可能性があるすべてのカット構成を探索することが含まれます。 n = 30 でもこれは大きくなり、n = 10000 ではまったく不可能になります。 

代わりに、動的プログラミングの観点から考えることができます。 dp[i] が、ソートされた配列内のインデックス i で終わるプレフィックスを分割する有効な方法の数を表すものとします。 最後のグループが j で始まり i で終わる場合、セグメント [j, i] が両方の制約を満たす必要があります。 そうであれば、dp[i] は dp[j-1] を追加できます。 

難しいのは、各 i に対して有効な j をすべて効率的に見つけることです。 単純なスキャンでは、前の位置 s までをチェックし、O(n * s) が得られます。これは境界線ですが、s ≤ 100 の場合には実際には実行可能です。ただし、妥当性が 2 つのスライディング条件によって支配されることに注意することで、概念的にはより適切に行うことができます。サイズ制約は、j ≥ i - s + 1 を即座に制限し、範囲制約は、a[i] - a[j] ≤ k となるように j を制限します。 配列はソートされているため、各 i について、2 ポインター手法を使用して左端の有効な j を見つけることができます。 

これにより、遷移が dp にわたる制限された範囲の合計に変換され、プレフィックスの合計で計算できます。 これにより、内側のループが完全に削除され、問題が O(n) に減ります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースパーティション | O(2^n) | O(n) | 遅すぎる |
 | ウィンドウスキャン付きDP | O(n · s) | O(n) | 許容範囲だがきつい |
 | 2 つのポインター + プレフィックスの合計を持つ DP | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

グループ化は知識レベルの相対的な順序のみに依存するため、最初に配列を並べ替えます。 有効なグループ化ではこの順序が尊重される必要があるため、並べ替えると問題が 1D 分割問題に変換されます。 

dp[i] を、ソート後に最初の i 個の生徒を分割する有効な方法の数として定義します。 

また、セグメント [L, i] が制約 a[i] - a[L] ≤ k を満たすように、最も古いインデックスを追跡するポインター L も維持します。 i は前にしか進めないので、L も前にしか進めません。 

さらに、セグメントが最大でもサイズ s であることを保証することで、サイズ制約を適用します。これは、左側の境界が少なくとも i - s + 1 でなければならないことを意味します。 

各 i について、最後のグループの開始位置 j の有効範囲を計算します。 その範囲は L から R で、R = i - 1 であり、L は両方の制約を満たすように調整されます。 次に、[L, R] 内のすべての j に対する dp[i] = dp[j] の合計が必要になります。 

この合計を効率的に計算するために、dp にわたるプレフィックス合計配列を維持します。 

### ステップ

 1. 一連の知識レベルを並べ替えます。 これにより、有効なグループがソートされた順序で連続したセグメントに対応することが保証されます。 並べ替えを行わないと、範囲制約は連続した間隔に変換されません。 
2. dp[0] = 1 を初期化します。これは、1 つの有効なパーティションを持つ空のプレフィックスを表します。 
3. 現在の終了位置の左端の有効な開始位置を追跡するポインタ L = 0 を維持します。 
4. 1 から n までの各位置 i について、a[i] - a[L] > k の間、L を前方に移動します。 これにより、L より前で始まるすべてのセグメントが範囲違反により無効になります。 
5. サイズ制限された境界を i - s + 1 として計算し、L = max(L, i - s + 1) を更新します。 これにより、最大グループ サイズの制約が適用されます。 
6. ここで、有効な以前のカット位置 j は、dp インデックス付けの用語では [L - 1, i - 1] にあります。 この変化は、dp がプレフィックスに基づいて 1 から始まることから生じます。 
7. プレフィックス合計を使用して、O(1) 時間でその範囲にわたる dp[j] の合計として dp[i] を計算します。 
8. 各 dp[i] の計算後にプレフィックスの合計を更新して、将来の状態を効率的にクエリできるようにします。 

### なぜ効果があるのか

 任意のインデックス i において、すべての有効な最後のグループは i で終了し、両方の制約を満たす j で開始する必要があります。 スライディング ポインタにより、無効な開始がすべて 1 回だけ除外され、有効な開始が時期尚早に削除されることはありません。 プレフィックス合計は、考えられるすべての最終カット位置を集計します。つまり、有効な各パーティションは、最終分割ポイントに従って 1 回だけカウントされます。 DP の不変条件は、dp[i] がプレフィックス [1..i] のすべての有効なパーティションをカウントし、そのようなすべてのパーティションが最後のカットの位置によって一意に決定されることです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

n, k, s = map(int, input().split())
a = list(map(int, input().split()))
a.sort()

dp = [0] * (n + 1)
pref = [0] * (n + 1)

dp[0] = 1
pref[0] = 1

L = 0

for i in range(1, n + 1):
    while L < i and a[i - 1] - a[L] > k:
        L += 1

    if i - L > s:
        L = i - s

    left = L
    right = i - 1

    if left <= right:
        dp[i] = (pref[right] - pref[left - 1]) % MOD
    else:
        dp[i] = 0

    pref[i] = (pref[i - 1] + dp[i]) % MOD

print(dp[n])
```このソリューションは DP over プレフィックスを中心に構築されており、各状態が特定のインデックスで終わるすべての有効なパーティションを集約します。 並べ替えられた配列により、間隔を使用して有効性がチェック可能であることが保証され、スライディング ポインターにより、実行可能な開始のみが考慮されることが保証されます。 

プレフィックス合計配列は、状態ごとに O(s) の遷移となるものを O(1) に変換するため、重要です。 減算処理では、負の値を避けるためにモジュラー演算を慎重に使用します。 

微妙な点の 1 つはインデックスの位置合わせです。dp はプレフィックス長に基づいて 1 から始まりますが、配列は 0 から始まります。そのため、それらの間の変換には注意が必要です。 

## 実用的な例

 ### 例 1

 入力:

 n = 5、k = 5、s = 3

 a = [5、6、9、10、12]

 ソートされた配列は変更されません。 

dp と L を追跡します。 

| 私 | a[i] | L (範囲制約) | サイズ制約 L | 最終L | dp[i] |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 5 | 0 | 0 | 0 | 1 |
 | 2 | 6 | 0 | 0 | 0 | 2 |
 | 3 | 9 | 0 | 0 | 0 | 4 |
 | 4 | 10 | 0 | 1 | 1 | 7 |
 | 5 | 12 | 1 | 2 | 2 | 13 |

 i = 4 で、サイズ制約が古い開始を制限し始め、L を前方にシフトします。 これは、両方の制約がどのように相互作用するかを示しています。範囲制約は非アクティブで、サイズ制約が後で優先されます。 

最終的な答えは dp[5] = 13 です。 

### 例 2

| 私 | 有効なL | dp[i] |

これにより、グループ化が可能なサイズであっても、アルゴリズムが範囲制約を正しく適用していることが確認できます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | ソートは O(n log n) で優勢であり、DP 遷移はプレフィックス合計と単調ポインターを使用してインデックスごとに O(1) です。 
| スペース | O(n) | dp 配列と prefix 配列はすべてのプレフィックスの値を格納します。 

n ≤ 10000 という制約により、O(n log n) のソートが簡単になり、線形 DP は時間制限内に問題なく収まります。 サイズ n の配列をいくつか保存するだけなので、メモリ使用量も少なくなります。 

## テストケース```python
import sys, io

MOD = 10**9 + 7

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, k, s = map(int, input().split())
    a = list(map(int, input().split()))
    a.sort()

    dp = [0] * (n + 1)
    pref = [0] * (n + 1)

    dp[0] = 1
    pref[0] = 1

    L = 0

    for i in range(1, n + 1):
        while L < i and a[i - 1] - a[L] > k:
            L += 1

        if i - L > s:
            L = i - s

        left = L
        right = i - 1

        if left <= right:
            dp[i] = (pref[right] - (pref[left - 1] if left > 0 else 0)) % MOD
        else:
            dp[i] = 0

        pref[i] = (pref[i - 1] + dp[i]) % MOD

    return str(dp[n])

# provided sample-like tests
assert run("5 5 3\n10 6 5 9 12\n") == "13"

# minimum size
assert run("1 10 1\n7\n") == "1"

# all equal-ish spacing but k tight
assert run("3 0 2\n1 2 3\n") == "1"

# large k, small s
assert run("5 1000 2\n1 2 3 4 5\n") == "8"

# s = 1 forces singleton partitions
assert run("4 10 1\n4 1 3 2\n") == "1"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 要素 | 1 | 基本ケースの正確性 |
 | k = 0 チェーン | 1 | strict range constraint |
 | 大きい k、s=2 | 複数のパーティション | sliding window behavior |
 | s = 1 | 1 | size constraint enforcement |

 ## 特殊なケース

 エッジ ケースの 1 つは、k が非常に小さい場合であり、事実上、すべてのグループがシングルトンになります。 L ポインタは常に前進して正の範囲を持つセグメントを除外し、直前のインデックスからのみ dp 遷移を残すため、アルゴリズムはこれを処理します。 

もう 1 つのエッジ ケースは、s = 1 の場合で、すべてのグループに 1 つの要素だけが含まれるように強制されます。 この場合、各 i の有効範囲は最初は i 自体のみに集約されるため、dp[i] = dp[i-1] 遷移は消え、dp ​​は定数 1 の進行になります。 

3 番目のケースは、k が非常に大きく、範囲制約が無関係になる場合です。 この場合、値の違いによって L が移動することはなく、サイズ制約 i - s + 1 のみが遷移を制限します。 このアルゴリズムは、制限されたブロック サイズを持つ合成をカウントすることに帰着し、プレフィックス合計はそれらの遷移を変更せずに正しく集計します。
