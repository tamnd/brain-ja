 ## 解決策
 ## 問題の理解

 少なくとも 1 つはゼロ以外の 1 桁の数字の開始ペアが与えられます。 このペアから、次の各値がフィボナッチとまったく同じように形成されるシーケンス (前の 2 つの値の合計) を生成します。 唯一の違いは、数値が 1 桁を超えることは決して許可されないため、合計が 10 以上に達した場合は常に、最後の桁のみが保持されることです。 

これにより、最初の順序付きペアから一連の順序付きペアに発展する決定論的なプロセスが作成されます。 すべてのステップで、システムの状態は最後の 2 つの数字によって完全に説明されます。 タスクは、連続した位置で元の開始ペアに再び遭遇するまで、つまりシステムが初期状態に戻るまで、シーケンスがどれくらいの時間実行されるかを決定することです。 

シーケンスは数値的に見えますが、実際の構造はペア (a, b) にわたる遷移システムであり、各ステップは (b, (a + b) mod 10) に移動します。 可能な状態は 100 しかないため、反復は非常に迅速に保証されます。 

制約は十分に小さいため、100 個の可能性の完全な状態空間まで状態を探索するメソッドは制限内で快適に実行できます。 訪問したすべての状態を追跡する単純なシミュレーションでも、実質的には一定時間です。 

微妙なエッジ ケースは、シーケンスが非常に短いループですぐに循環する場合です。 たとえば、(1, 0) から開始して、次の状態は (0, 1)、(1, 1)、(1, 2) などとなり、直感に比べて復帰が比較的遅くなる可能性があります。 もう 1 つのエッジ ケースは、(5, 5) のような対称的な開始であり、再発がすぐに安定して短いサイクルになります。 問題は明らかに元の状態と一致する連続したペアに関するものであるため、ペアではなく単一の値の繰り返しをチェックするだけの単純な試みは失敗します。 

## アプローチ

 プロセスを理解する直接的な方法は、定義どおりに正確にシミュレーションすることです。 指定されたペアから開始して、合計の最後の桁として次の値を繰り返し計算します。 各ステップでペアを前進させ、初期構成に戻ったかどうかを確認します。 

この総当りシミュレーションは、シーケンスの定義を変換せずに反映しているため、正確です。 ただし、シーケンスは個々の数値ではなく、州ごとに進化します。 各コンポーネントで取り得る値は 10 個だけであるため、合計で 100 個の状態しか存在しません。 これは、最大 100 回の遷移の後、一部の状態を繰り返す必要があることを意味します。 したがって、総当たり法では最大でも一定サイズのグラフが探索されます。 

重要な観察は、私たちが扱っているのは無制限のフィボナッチのような成長問題ではないということです。 代わりに、有限状態マシンを扱っています。 繰り返しが 10 を法とする最後の 2 つの値にのみ依存することが認識されると、問題は初期状態で始まるサイクルの長さを見つけることになります。

## アルゴリズムのチュートリアル

1. システムの初期状態を定義する開始ペア (a、b) を読み取ります。 連続した位置でこの状態に戻ったときに測定するため、この状態は重要です。 
2. 最初のペアを、再度検出するターゲット状態として保存します。 
3. カウンタを初期化して、これまでにシーケンス内に出現した数値の数を追跡します。 すでに存在する 2 つの数値から開始するため、初期カウントは 2 です。 
4. 次の値を (a + b) mod 10 として計算し、ペアを (b, next_value) に前方にシフトします。 このステップでは、1 桁の制約を適用しながら繰り返しルールをエンコードします。 
5. すべての新しい状態がシーケンスに 1 つの追加要素を与えるため、新しい数値を生成するたびにカウンターをインクリメントします。 
6. 現在のペアが元の開始ペアと一致するまで、遷移を繰り返し続けます。 これが起こった瞬間に、シーケンスは完全なサイクルを完了します。 
7. 最初のペアの最初の再出現までのシーケンスの長さを表すカウンターを出力します。 

### なぜ効果があるのか

 このプロセスは完全に順序付きペアの遷移を通じて進化し、各遷移は決定的です。 これは、システムが、各ノードが出ていくエッジを 1 つだけ持つ有向グラフを定義することを意味します。 このような有限グラフ内の任意のノードから開始すると、最終的な繰り返しが保証されます。 最初のノードが再表示された場合にのみ明示的に停止するため、プロセスはそのノードから始まる 1 つの完全なサイクル長を正確に測定します。 個々の値ではなく完全なペアを比較し、状態の整合性を維持するため、中間の繰り返しが早期に終了することはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    a, b = map(int, input().split())
    start = (a, b)

    count = 2
    while True:
        c = (a + b) % 10
        a, b = b, c
        count += 1
        if (a, b) == start:
            print(count)
            return

if __name__ == "__main__":
    solve()
```この実装では、現在のペアとカウンターのみが保持されます。 トランジションライン`(a + b) % 10`フィボルージ ルールを直接適用します。 ループは、状態が最初のペアと再び一致するまで続き、その時点でちょうど 1 つの完全なサイクルが完了します。 遷移が発生する前に入力がすでに 2 つの要素に寄与しているため、カウンターは 2 から始まります。 

ここでよくある間違いは、カウンタを 0 または 1 で開始することです。これにより、最終的な答えが初期状態のサイズだけ誤ってシフトされます。 もう 1 つの微妙な点は、サイクル条件が前の両方の数値に同時に依存するため、個々の値ではなくペアを比較する必要があることです。 

## 実用的な例

 ### 例 1: 入力 3 4

 ペア (3, 4) から開始して、トランジションを繰り返し適用します。 

| ステップ | 現在のペア | 次の値 | カウント |
 | --- | --- | --- | --- |
 | 0 | (3,4) | - | 2 |
 | 1 | (4, 7) | 7 | 3 |
 | 2 | (7, 1) | 1 | 4 |
 | 3 | (1, 8) | 8 | 5 |
 | 4 | (8,9) | 9 | 6 |
 | 5 | (9, 7) | 7 | 7 |
 | 6 | (7,6) | 6 | 8 |
 | ... | ... | ... | ... |
 | 最終 | (3,4) | - | 14 |

 このトレースは、システムが 14 要素後に最終的に元のペアに戻ることを示しています。 重要な観察は、中間値は以前のパターンを繰り返しますが、終了は両方のコンポーネントが初期状態と一致する場合にのみ発生するということです。 

### 例 2: 0 6 を入力

 (0, 6) から始まる進化は、シーケンスの早い段階でゼロが安定化装置として機能するという事実によって支配されますが、システムは依然として後で完全なサイクルに入ります。 同じステート マシン ロジックが適用され、シーケンスは最終的に (0, 6) に戻り、再発の周期的な性質が確認されます。

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    from contextlib import redirect_stdout
    import io as _io
    out = _io.StringIO()
    with redirect_stdout(out):
        solve()
    sys.stdin = old_stdin
    return out.getvalue().strip()

 ## 特殊なケース

 (0, 6) のような開始の場合、シーケンスは最初、初期の遷移に影響を与える多くのゼロを持つシフトされたフィボナッチ チェーンのように動作します。 アルゴリズムは引き続き完全なペアを追跡するため、個々の値が早期に繰り返された場合でも、正確なペア (0、6) が再び現れるまで終了は発生しません。 ループは、完全な状態が一致するまで正しく続行されます。 

(5, 5) のような対称開始の場合、次の状態は (5, 0) になり、すぐに対称性が崩れます。 両方の開始値が同一であっても、ステート マシンはすぐに発散し、そのサイクルの完全な走査が完了した後でのみ最初のペアに戻ります。 実装では値を独立して比較するのではなく、常に順序付きペアを比較するため、これは自然に処理されます。
