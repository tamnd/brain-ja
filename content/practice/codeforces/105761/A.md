 ## 解決策
 ## 問題の理解

 英小文字のみで構成される単一の文字列が与えられます。 タスクは、それぞれの異なる文字が出現する回数に基づいてこの文字列を分類することです。 

文字列内に出現するすべての文字が奇数回出現する場合、その文字列は奇数と呼ばれます。 文字列は、その中に出現するすべての文字が偶数回出現する場合でも呼び出されます。 文字列に異なる文字間で奇数と偶数の頻度が混在している場合、その文字列はどちらのカテゴリにも属しません。 

したがって、出力は 3 方向の分類になります。 文字列が奇数の場合は 1、偶数の場合は 0、混合の場合は 0/1 を出力します。 

文字列の長さは最大 60 です。これは、およそ O(n) または O(26・n) までの解は制限内で実行するのが簡単であることを直ちに意味します。 高度なデータ構造や単一パス周波数以上の最適化は必要ありません。 

エッジケースは解釈においてのみ微妙です。 単純な間違いは、「奇数の文字列」を「全体の長さが奇数」と解釈し、「偶数の文字列」を「全体の長さが偶数」と解釈することです。 この条件はグローバルではなく文字ごとに適用されるため、これは不正確です。 

たとえば、次の文字列を考えてみましょう。`aabb`。 合計の長さは 4 で偶数ですが、文字数は次のようになります。`a:2`、`b:2`、したがって、問題の意味においては均等であり、出力する必要があります`0`。 

別の例は`aab`。 全長は 3 ですが、カウントは`a:2`、`b:1`。 これは奇数でも偶数でもないため、出力は次のようになります。`0/1`。 ここでの間違いは、長さが奇数であるため奇数として分類することですが、偶数の周波数が存在すると条件が崩れてしまいます。 

最後に、次のような文字列`abc`すべてのカウントが 1 に等しいため、奇数であり、出力する必要があります。`1`。 

重要な観察は、文字ごとの周波数パリティを検査するだけで済み、その後、すべての文字が 2 つの均一条件のいずれかを通過するかどうかを集計する必要があるということです。 

## アプローチ

 問題を解決する直接的な方法は、各文字の出現を数えて、条件を明示的にチェックすることです。 アルファベットのサイズは小文字 26 文字に固定されているため、サイズ 26 の頻度配列を維持し、文字列を 1 回スキャンできます。 

ブルート フォース バージョンでは、個別の文字ごとに文字列全体をスキャンして、その出現数をカウントします。 これには O(26・n) のコストがかかりますが、ここではまだ小さいですが、概念的には不要です。 文字列の重複を繰り返し再スキャンする必要があるため、アルファベットが大きい場合には、非効率性がより顕著になります。 

この改善は、周波数計算が 1 回のパスで段階的に実行できることを認識することで実現しました。 すべてのカウントを取得したら、分類は簡単なチェックです。ゼロ以外のカウントがすべて奇数であるか、ゼロ以外のカウントがすべて偶数であるかをテストします。 また、ゼロカウントの文字は条件に影響を与えてはいけないため、混同しないようにする必要があります。 

これにより、問題は 26 個の値に対する定数時間の後処理に軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (キャラクターごとに再スキャン) | O(26・n) | お(1) | 受け入れられますが冗長です |
 | 最適 (シングルパス周波数) | O(n + 26) | お(26) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を初期化する`freq`サイズ 26 のゼロ付き。 各インデックスはからの文字に対応します。`a`に`z`。 この構造体は、入力文字列に各文字が何回出現するかを保存します。 
2. 文字列内の各文字を反復処理し、対応する頻度を増加させます。`freq`。 これにより、単一パスで完全なディストリビューションが構築されます。 
3. ゼロ以外の周波数がすべて奇数であるかどうかを確認します。 これには、周波数配列をスキャンし、すべての周波数配列が検証される必要があります。`freq[i] != 0`満足する`freq[i] % 2 == 1`。 
4. ステップ 3 が成功した場合、文字列は奇数として分類され、戻ります。`1`。 
5. それ以外の場合は、次のことを確認して、ゼロ以外の周波数がすべて偶数であるかどうかを確認します。`freq[i] % 2 == 0`みんなのために`freq[i] != 0`。 
6. ステップ 5 が成功した場合、文字列は偶数として分類され、戻ります。`0`。 
7. どちらの条件も当てはまらない場合は、リターンします。`0/1`、混合パリティ構成を示します。 

### なぜ効果があるのか

 このアルゴリズムは、問題の定義を周波数空間に明示的にエンコードします。 各文字は最終的な分類に独立して寄与するため、関連する唯一のプロパティは、個々のカウントがパリティ制約を満たすかどうかです。 頻度配列は正確なカウントを取得し、文字間でカウントを混合する操作はないため、すべてのエントリをチェックすることで正確さが保証されます。 単一の文字が均一パリティ条件に違反すると、文字列全体がそのカテゴリを満たすことができなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

s = input().strip()

freq = [0] * 26

for ch in s:
    freq[ord(ch) - 97] += 1

all_odd = True
all_even = True

for f in freq:
    if f == 0:
        continue
    if f % 2 == 1:
        all_even = False
    else:
        all_odd = False

if all_odd:
    print("1")
elif all_even:
    print("0")
else:
    print("0/1")
```このソリューションでは、まず線形時間で周波数テーブルを構築します。 次に、固定サイズのアルファベットに対して 1 回のスキャンを実行して、文字列が奇数の条件を満たすか偶数の条件を満たすかを判断します。 2 つのブール値フラグ`all_odd`そして`all_even`繰り返しのパスを避けるために、同時に維持されます。 存在しない文字は定義に影響を与えないため、ゼロの頻度は無視されます。 

よくある実装の落とし穴は、ゼロカウントを無視できないことです。 ゼロを偶数として扱うと、すべての文字列が誤って「偶数」になることになりますが、これは意図したものではありません。 この問題を回避するために、チェックではゼロのエントリが明示的にスキップされます。

## テストケース```python
import sys, io

def solve():
    import sys
    input = sys.stdin.readline
    s = input().strip()

    freq = [0] * 26
    for ch in s:
        freq[ord(ch) - 97] += 1

    all_odd = True
    all_even = True

    for f in freq:
        if f == 0:
            continue
        if f % 2 == 1:
            all_even = False
        else:
            all_odd = False

    if all_odd:
        return "1"
    elif all_even:
        return "0"
    else:
        return "0/1"

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    return solve()

# provided samples (interpreted)
assert run("geekkeeg\n") == "0/1"
assert run("funnyn\n") == "0/1"
assert run("zztop\n") == "0/1"

# custom cases
assert run("a\n") == "1", "single char is odd"
assert run("aa\n") == "0", "single char even count"
assert run("abcabc\n") == "0", "all even frequencies"
assert run("abc\n") == "1", "all odd frequencies"
assert run("aabbc\n") == "0/1", "mixed parity"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`a`|`1`| 最小サイズが奇数の場合 |
 |`aa`|`0`| 偶数の場合の最小サイズ |
 |`abcabc`|`0`| 均一な偶数周波数 |
 |`abc`|`1`| 均一な奇数周波数 |
 |`aabbc`|`0/1`| 混合パリティ検出 |

 ## 特殊なケース

 主なエッジケースは、一部の文字が欠落している場合です。 たとえば、`abc`、周波数配列のほとんどのエントリはゼロです。 アルゴリズムはチェック中にゼロを明示的に無視するため、文字列が誤って偶数カテゴリに強制されることはありません。 スキャンで見えるのは`a:1, b:1, c:1`、すべて奇数なので、結果は次のようになります`1`。 

もう 1 つのケースは、次のような単一文字列です。`z`。 周波数配列には 1 に等しいエントリが 1 つあり、残りは 0 です。 1は奇数なので、`all_odd`全体を通して true のままで、出力は次のようになります。`1`。 

最後に、次のような混合ケース`aab`両方のフラグを維持する必要性を示しています。 加工後`aab`、周波数は`a:2, b:1`。 偶数と奇数の両方のカウントが存在すると、両方が反転します`all_odd`そして`all_even`false に設定すると、正しく生成されます`0/1`。
