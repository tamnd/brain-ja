 ## 解決策
 ## 問題の理解

 一連の整数としきい値が与えられます。`k`。 シーケンスからサブシーケンスを選択します。つまり、順序を変更せずにいくつかの要素を保持し、それをできるだけ長くしようとします。 制約は連続して選択された要素にあります。サブシーケンス内で隣接する 2 つの要素を選択するときは常に、それらの絶対差は少なくとも次の値でなければなりません。`k`。 

したがって、値を選択すると`x1, x2, x3, ...`、その後、すべての`i`、私たちは持っている必要があります`|xi - x(i+1)| >= k`。 タスクは、そのようなサブシーケンスの可能な最大長を計算することです。 

入力サイズは最大 300,000 要素で、値は 10^9 まで大きくすることができます。 O(n^2) は、最悪の場合、約 9e10 回の演算となり、制限をはるかに超えているため、これによりインデックスに対する二次アプローチは即座に除外されます。 O(n sqrt n) でも遅すぎます。 O(n log n) または O(n) に近い値を期待する必要があります。 

この構造はインデックス空間内でローカルではなく、値の違いに依存します。これは、「k ギャップ条件を尊重しながらこの値で拡張できる最適なサブシーケンスは何か」などの高速なクエリを可能にする方法で、以前に確認された値のグローバルなビューを維持する必要があることを示唆しています。 

見落としがちないくつかの危険な状況:

 すべての値が同一である場合、`k > 0`の場合、隣接する 2 つの要素をペアとして選択することはできないため、配列が長くても答えは 1 になります。 たとえば、入力`5 10`配列あり`7 7 7 7 7`出力する必要があります`1`。 

もし`k = 0`、制約がなくなるので、答えは常に`n`。 依然として厳密な不等号を強制したり、誤った比較ロジックを使用したりする単純なソリューションは、ここで失敗する可能性があります。 

値の間隔がしきい値ぎりぎりの場合、貪欲な決定や局所的な決定は失敗する可能性があります。 たとえば、最初に小さい値を選択するとサブシーケンスが長くなったとしても、早い段階で大きな値を選択すると、その後の多くの選択がブロックされる可能性があります。 

## アプローチ

 ブルートフォースソリューションでは、各位置で終わる最長の有効なサブシーケンスを計算しようとします。 あらゆるインデックスに対して`i`、以前のすべてのインデックスをスキャンします`j < i`かどうかを確認してください`|a[i] - a[j]| >= k`、更新中`dp[i] = max(dp[j] + 1)`。 これは、すべての有効な先行処理を明示的にテストするため、正しいです。 ただし、これは O(n^2) であり、n = 300,000 の場合、およそ 9e10 の比較が行われることになり、これは現実的ではありません。 

ボトルネックは、値が「互換性がある」ものの中で最良の dp 値のみを気にするにもかかわらず、要素ごとに以前のすべての要素を繰り返しスキャンすることです。 遷移条件は値の差のみに依存し、インデックス構造には依存しません。 これは、情報を価値別に再編成する必要があることを示唆しています。 

重要な観察は、現在の値についてです。`x`、有効な前の要素は、最大でも値を持つ要素です。`x - k`または少なくとも`x + k`。 これら 2 つの値範囲内で、以前に処理されたすべての要素の中で最良の dp 値が必要です。 

これにより、問題は、プレフィックス最大クエリとサフィックス最大クエリをサポートする値に対する動的構造の維持に変わります。 値が大きいため (最大 1e9)、それらを圧縮し、ソートされた一意の値に対してセグメント ツリーまたはフェンウィック ツリーを使用します。 各位置には、その正確な値で達成された最大 dp 値が保存されます。 次に、新しい要素ごとに 2 つの範囲の最大値をクエリし、それらを結合して、その値の位置を更新します。 

これにより、インデックスのスキャンから要素あたり最大 2 つの範囲のクエリへの移行が削減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | インデックスに対するブルート フォース DP | O(n^2) | O(n) | 遅すぎる |
 | 圧縮された DP をセグメント ツリーで調整 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 配列を左から右に処理し、考えられる値ごとに、その値で終わる最適なサブシーケンス長を格納するデータ構造を維持します。 

1. まず、配列からすべての値を収集し、それらを一意に並べ替えます。 これにより、各値を圧縮座標系のインデックスにマッピングできるようになります。 元の値が直接インデックスを作成するには大きすぎるため、この手順が必要です。 
2. これらの圧縮インデックスに対してセグメント ツリーを構築します。各ノードには、その圧縮値でこれまでに出現した数値の最大 dp 値が格納されます。 最初はすべての値がゼロです。 
3. 各要素について`a[i]`、圧縮された位置を見つけます`p`。 
4. 拡張できる最適なサブシーケンスが必要です`a[i]`。 これは、2 つの互いに素なグループから来ています: 値 ≤`a[i] - k`、および値 ≥`a[i] + k`。 ソートされた一意の配列に対して二分検索を使用して、これらをインデックス範囲に変換します。 
5. 両方の範囲の最大 dp 値をセグメント ツリーに問い合わせます。 可能な限り最良の先行処理は、これら 2 つの結果の最大値です。 
6.セット`dp = best_prev + 1`。 これは、最も有効なサブシーケンスを取得し、現在の要素を追加することを表します。 
7. 位置でセグメントツリーを更新します。`p`と`dp`将来の要素はこの値から拡張できるためです。 
8. すべての要素の最大 dp を追跡します。 

最終的な答えは、表示される最大 dp 値です。 

これが機能する理由: すべてのステップで、セグメント ツリーには、処理された要素間の任意の値で終わる最適なサブシーケンス長が含まれます。 新しい値を処理するとき`x`、有効な先行要素はすべて、制約によって定義された 2 つの安全な値間隔のいずれかに完全に収まる必要があります。 dp は以前のすべてのプレフィックスに対する最適なソリューションをすでに保存しているため、これらの間隔の最大値を取ることで、次のような最適な拡張が得られます。`x`。 将来の要素はインデックスの順序に依存せず、値の実現可能性にのみ依存するため、構造は帰納的に正確さを維持します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SegTree:
    def __init__(self, n):
        self.n = n
        self.seg = [0] * (4 * n)

    def update(self, idx, val, node=1, nl=0, nr=None):
        if nr is None:
            nr = self.n - 1
        if nl == nr:
            if val > self.seg[node]:
                self.seg[node] = val
            return
        mid = (nl + nr) // 2
        if idx <= mid:
            self.update(idx, val, node * 2, nl, mid)
        else:
            self.update(idx, val, node * 2 + 1, mid + 1, nr)
        self.seg[node] = max(self.seg[node * 2], self.seg[node * 2 + 1])

    def query(self, l, r, node=1, nl=0, nr=None):
        if nr is None:
            nr = self.n - 1
        if r < nl or nr < l:
            return 0
        if l <= nl and nr <= r:
            return self.seg[node]
        mid = (nl + nr) // 2
        return max(
            self.query(l, r, node * 2, nl, mid),
            self.query(l, r, node * 2 + 1, mid + 1, nr)
        )

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    vals = sorted(set(a))
    mp = {v: i for i, v in enumerate(vals)}

    st = SegTree(len(vals))

    ans = 1

    for x in a:
        idx = mp[x]

        left_val = x - k
        right_val = x + k

        import bisect
        best = 0

        li = bisect.bisect_right(vals, left_val) - 1
        if li >= 0:
            best = max(best, st.query(0, li))

        ri = bisect.bisect_left(vals, right_val)
        if ri < len(vals):
            best = max(best, st.query(ri, len(vals) - 1))

        cur = best + 1
        st.update(idx, cur)
        if cur > ans:
            ans = cur

    print(ans)

if __name__ == "__main__":
    solve()
```セグメント ツリーは、圧縮値ごとの最大サブシーケンス長を維持します。 各更新は、長いサブシーケンスがそこで終了する場合にのみ位置を改善します。 有効な遷移には禁止された間隔の外にある必要があるため、クエリは 2 つの値範囲に分割されます。`(x - k, x + k)`。 

実装の微妙な点は、dp[i] をインデックスに直接使用することはなく、値にのみ使用することです。 これは、同じ値の複数の出現が同じ状態を共有するため有効であり、後の出現は可能な限り最良の以前のチェーンからのみ恩恵を受けるため、最大値をとるだけで十分です。 

もう 1 つの重要な詳細は、二等分結果によって無効な間隔が生成される可能性がある、空のクエリ範囲の処理です。 これらは安全に貢献ゼロとして扱われます。

 ## 特殊なケース

 のような入力の場合`5 10`と`7 7 7 7 7`、アルゴリズムはすべての値を単一の圧縮インデックスにマップします。 両方の有効な範囲が唯一の値を除外するため、すべてのクエリはゼロを返します。 各 dp は 1 になり、更新のたびにその状態が強化されるだけです。 最終的な答えは 1 で、k > 0 の場合、有効なサブシーケンス内で 2 つの等しい値が隣接できないという制約と一致します。 

のようなケースの場合`k = 0`、 のような`1 2 3 4`、両方の条件が満たされるため、左と右のクエリ範囲には常に以前のすべての値が含まれます。`x - k`そして`x + k`同じ地点まで崩れる。 すべてのステップでこれまでの最大 dp が検出され、厳密に増加する dp シーケンスが生成されます。`1,2,3,4`。 

k の周囲に密に配置された値の場合、たとえば`1 100 2 99 3 98`、構造は小さい値と大きい値を正しく交互に行います。 各ステップで、有効な先行処理が常に反対側の範囲で見つかり、セグメント ツリーはこれまでの最良のチェーンを保存し、すべての要素を最大限に活用します。
