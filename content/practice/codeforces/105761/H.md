 ## 解決策
 ## 問題の理解

 各チャネルがノードである有向グラフとしてシステムをモデル化できます。 各ボットは小さな転送ルールのように機能します。ボットは 1 つのソース チャネルをリッスンし、そのチャネルがメッセージを受信すると、そのメッセージを宛先チャネルの固定リストに転送します。 同じチャネル内に複数のボットが存在できるため、チャネルに入力されたメッセージは、そのチャネルからのすべての送信ボット ルールを通じて直ちにブロードキャストされます。 

したがって、すべてのボットに対して、リスニング チャネルから転送リスト内の各チャネルに有向エッジを追加するのが効果的です。 複数のボットが同じチャネルをリッスンする場合、それはそのノードに複数の発信エッジがあることを意味します。 

問題で説明されているプロセスは、この有向グラフでの単なる到達可能性です。 あるチャネルでメッセージを開始すると、メッセージは有向辺に沿って伝播し、最終的にグラフ内のすべてのノードに到達するかどうかを知りたいと考えます。 タスクは、すべてのノードに到達できる開始ノードの数をカウントすることです。 

制約は大きく、最大 100,000 チャネルと 100,000 ボット、合計エッジ数は最大 200,000 です。 これにより、BFS または DFS を使用してすべてのノードから個別に伝播をシミュレートしようとするアプローチは即座に除外されます。 ノードあたりの単純なマルチソース BFS はおよそ O(n(n + m)) になりますが、この規模では遅すぎます。 

重複と循環について考えると、微妙な問題が生じます。 複数のボットが並列エッジを作成することができ、サイクルとはメッセージが無限に循環する可能性があることを意味します。 また、チャネルには発信エッジがまったくない場合があり、そのチャネルが唯一のノードでない限り、直ちに不適格となります。 

いくつかの特殊なケースで動作が明確になります。 

あらゆる場所を指すチャネルを除いてすべてのチャネルが分離されている場合、そのチャネルのみが有効です。 グラフが強く接続されている場合、すべてのチャネルが有効です。 グラフが複数のコンポーネントに切断されている場合、特別な構造の外側にあるノードは他のすべてのノードに到達できません。 

## アプローチ

 ブルート フォース ソリューションでは、すべてのチャネルから DFS または BFS を開始し、すべてのノードが到達可能かどうかを確認します。 到達可能性は伝播プロセスを正確に定義するため、これは概念的には正しいです。 ただし、各検索には O(n + m) のコストがかかり、すべての n ノードに対してそれを実行すると O(n(n + m)) となり、最悪の場合、制限をはるかに超えて 10^10 の演算のオーダーになります。 

重要な洞察は、有向グラフの到達可能性が強く接続されたコンポーネントに崩壊するということです。 強く接続されたコンポーネントの内部では、すべてのノードが他のすべてのノードに到達できるため、同じ SCC 内のすべてのノードは内部伝播の開始点として同じように動作します。 

グラフを SCC に圧縮すると、有向非巡回グラフが得られます。 その DAG では、ノード (SCC) は、他のすべての SCC に到達できる場合に限り、元のグラフ内のすべてのノードに到達できます。 DAG では、すべてのノードへの到達可能性は、反転グラフの一意のソースであるノード、または同等に凝縮内の他のノードすべてを支配するノードからのみ可能です。 

より直接的な特性評価により、完全な到達可能性チェックが回避されます。 SCC の DAG では、ノードは、逆凝縮グラフで次数が 0 の唯一の SCC である場合に限り、他のノードすべてに到達できます。これは、逆到達可能性の意味で、そのノードが固有の「グローバル ソース」であることを意味します。 これにより、問題は SCC の計算と候補コンポーネントのカウントに軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 各ノードからのブルート フォース DFS/BFS | O(n(n + m)) | O(n + m) | 遅すぎる |

 ## アルゴリズムのチュートリアル

 強結合成分とグラフ圧縮を使用して問題を解決します。

1. 各ボットがリスニング チャネルからすべてのターゲット チャネルにエッジを提供する有向隣接リストを構築します。 これは、可能なすべてのワンステップ メッセージ転送を表します。 グラフは伝播を完全にエンコードします。 
2. Kosaraju または Tarjan のアルゴリズムを使用して、強結合コンポーネントを計算します。 重要な考え方は、各 SCC 内ではすべてのノードが相互に到達可能であるため、SCC 内の任意のノードから開始すると、SCC 外でも同じ到達可能動作が得られるということです。 
3. 各ノードにコンポーネント識別子を割り当てます。 これにより、グラフが各 SCC がノードとなる DAG に圧縮されます。 
4. 元のグラフに 2 つの異なる SCC を接続するエッジがある場合は常に、SCC 間にエッジを追加して凝縮グラフを作成します。 
5. この凝縮グラフ内の各 SCC の次数を計算します。 
6. 他のすべての SCC に到達できる SCC を特定します。 この問題構造では、これらは逆の意味で次数 0 の SCC に正確に対応します。これは、グローバルな開始点となることが他のコンポーネントによってブロックされていない SCC と同等です。 
7. この条件を満たす SCC に属する元のノードの数を数えます。 この数が答えです。 

これが機能する理由は、SCC 圧縮がコンポーネント間の到達可能性を維持しながら内部サイクルを削除するためです。 不適格な SCC 内のノードは、そこから到達できない少なくとも 1 つの他の SCC によってブロックされているため、汎用の開始点にはなりません。 

### なぜ効果があるのか

 SCC の凝縮グラフは、各ノードが相互に到達可能なチャネルの最大セットを表す DAG です。 元のグラフ内のパスはすべて、この DAG 内のパスに対応します。 チャネルは、その SCC がこの DAG 内の他のすべての SCC に到達できる場合に限り、他のすべての SCC に到達できます。 DAG では、他のすべてに到達できるノードはすべてのシンクに到達できなければなりません。これは、他の SCC が逆方向の伝播を妨げない場合にのみ可能です。これは、逆凝縮の次数構造によって捕捉されます。 SCC パーティショニングではすべての到達可能性関係が正確に保存されるため、これにより正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def kosaraju(n, adj, radj):
    visited = [False] * (n + 1)
    order = []

    def dfs1(v):
        visited[v] = True
        for to in adj[v]:
            if not visited[to]:
                dfs1(to)
        order.append(v)

    for i in range(1, n + 1):
        if not visited[i]:
            dfs1(i)

    comp = [-1] * (n + 1)

    def dfs2(v, c):
        comp[v] = c
        for to in radj[v]:
            if comp[to] == -1:
                dfs2(to, c)

    cid = 0
    for v in reversed(order):
        if comp[v] == -1:
            dfs2(v, cid)
            cid += 1

    return comp, cid

def solve():
    c, b = map(int, input().split())
    adj = [[] for _ in range(c + 1)]
    radj = [[] for _ in range(c + 1)]

    for _ in range(b):
        data = list(map(int, input().split()))
        l = data[0]
        m = data[1]
        targets = data[2:]
        for t in targets:
            adj[l].append(t)
            radj[t].append(l)

    comp, k = kosaraju(c, adj, radj)

    indeg = [0] * k
    used_edge = set()

    for v in range(1, c + 1):
        for to in adj[v]:
            if comp[v] != comp[to]:
                if (comp[v], comp[to]) not in used_edge:
                    used_edge.add((comp[v], comp[to]))
                    indeg[comp[to]] += 1

    # count SCCs with zero indegree in condensation graph
    zero_indeg = [i for i in range(k) if indeg[i] == 0]

    if len(zero_indeg) != 1:
        return 0

    good = zero_indeg[0]

    return sum(1 for v in range(1, c + 1) if comp[v] == good)

def main():
    print(solve())

if __name__ == "__main__":
    main()
```このソリューションでは、まず、Kosaraju のアルゴリズムに必要な順方向グラフと逆方向グラフの両方を構築します。 2 番目の DFS パスはコンポーネント ID を割り当てます。 

次に、コンポーネント間の角度を計算しながら、凝縮グラフが間接的に構築されます。 セットは、同じ SCC ペア間の重複エッジのカウントを避けるために使用されます。これは、複数のボットが平行エッジを誘発する可能性があるため重要です。 

最後に、アルゴリズムは、凝縮グラフ内に角度ゼロの SCC が 1 つだけ存在するかどうかをチェックします。 そうしないと、単一の開始領域が他のすべての開始領域に到達できなくなります。 「はい」の場合、その SCC 内のすべてのノードが有効な開始チャネルです。

 ## 特殊なケース

 重要なエッジ ケースは、凝縮グラフで複数の SCC の次数が 0 である場合です。 たとえば、2 つの切断された強く接続された領域などです。 このアルゴリズムは SCC を計算し、複数の候補ソース コンポーネントを見つけます。 その場合の条件としては、`len(zero_indeg) != 1`これは、単一の開始チャネルが両方の領域に到達できないことを正しく反映しています。 

もう 1 つのケースは、すでに単一の SCC であるグラフです。 ここで、凝縮グラフには 1 つのノードと 0 度があります。 アルゴリズムはその SCC 内のすべてのノードを返し、完全なカウントを正確に生成します。 

最後の微妙なケースは、ボットからの重複エッジです。 SCC エッジ カウンティングで重複排除を行わないと、度数が人為的に増大する可能性があります。 セット`used_edge`各 SCC 遷移が 1 回カウントされることを保証し、凝縮構造の正確さを維持します。
