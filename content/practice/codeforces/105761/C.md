 ## 解決策
 ## 問題の理解

 サッカー チームのシーズン統計を表す 5 つの整数が与えられていますが、これらの整数の順序は混乱しています。 それらがプレイされた試合、勝ち、引き分け、負け、合計ポイントに対応していることはわかっていますが、どの数字がどれであるかはわかりません。 

サッカーの得点ルールは固定されており、勝利は 3 点、引き分けは 1 点、負けは 0 点となります。 また、すべての試合の結果はこれらの結果のいずれか 1 つになるため、合計試合数は勝ち、引き分け、負けの合計となります。 合計ポイントは 3 回の勝利と引き分けとして計算されます。 

タスクは、未知の順序で 5 つの数値を取得し、固有の有効な解釈を再構築し、それらを正規の順序 (MP、W、D、L、Pts) で出力することです。 

すべての値は最大 300 と小さいですが、主な難点は、試合数からの線形制約と得点からの線形制約という 2 つの制約を同時に満たして役割を正しく割り当てる必要があることです。 役割を恣意的に割り当てる単純な試みは失敗します。複数の順列が存在しますが、両方の方程式を同時に満たすのは 1 つだけであるためです。 

エッジケースは主に、繰り返される値を中心に展開します。 たとえば、次のような入力`0 0 1 1 0`重複が含まれているため、単純な貪欲な割り当てが曖昧になります。 もう 1 つの微妙なケースは、引き分けと負け、または勝ちと引き分けが同じ値を持つ場合です。これは、有効な解決策が一意であるにもかかわらず、並べ替えベースのヒューリスティックを誤解させる可能性があります。 

数値が 5 つしかないため、すべての順列に対する総当り攻撃が一定時間内に実行可能です。 それが主な構造観察です。 

## アプローチ

 直接的なアイデアは、MP、W、D、L、および Pts の役割に対する 5 つの数字の可能なすべての割り当てを試してみることです。 各割り当てについて、2 つの条件を満たすかどうかを確認します。1 つ目は、MP が W + D + L に等しくなければならないこと、2 つ目に、Pts が 3W + D に等しくなければならないことです。両方が当てはまれば、正しい解釈が見つかったことになります。 

値が 5 つしかないため、順列の数は 5 階乗、つまり 120 になります。順列ごとに一定の作業が行われるため、このアプローチは非常に高速です。 

制約が小さいため、ここではより「思考に基づいた」最適化は必要ありません。 どの数値が最大か最小かを推論してさらに削減しようとしても、一貫性を検証する必要があり、順列チェックはすでに簡単で安全です。 

ブルートフォースアプローチが機能するのは、検索スペースが小さく、制約によって一意のマッピングが完全に決定されるためです。 たったの5という観察！ 割り当てが存在することで、推論の問題のように見える問題が単純な検証ループに短縮されます。

 ## アルゴリズムのチュートリアル

 5 つの入力数値をマルチセットとして扱い、5 つの役割への可能な限りの割り当てを試みます。 

1. 5 つの整数を配列に読み取ります。 これらは、MP、W、D、L、および Pts の未知の順列を表します。 
2. これら 5 つの値のすべての順列を生成します。 各順列は仮想の割り当てに対応します。最初の値は MP、2 番目の W、3 番目の D、4 番目の L、および 5 番目の Pts です。 入力にはヒントがないため、順序付けは想定されていません。 
3. 各順列について、それがサッカー統計の構造的制約を満たすかどうかを計算します。 2 つの方程式を確認します。MP は W + D + L に等しくなければならず、Pts は 3W + D に等しくなければなりません。このステップが唯一のフィルタリング条件であり、スコアリング システムのルールを強制します。 
4. この問題では、有効な割り当てが 1 つだけ存在することが保証されているため、両方の条件を満たす順列が見つかるとすぐに、必要な順序で出力して終了します。 

これで十分である理由は、制約によってシステムが完全に定義されるためです。 不正な割り当ては少なくとも 1 つの方程式に違反するため、チェックに合格できません。 

### なぜ効果があるのか

 有効なサッカー テーブルのすべての行は、MP = W + D + L および Pts = 3W + D という 2 つの方程式によって完全に決定されます。これらの役割への入力数値のすべての可能な割り当てをテストしているため、正しい構成が順列の中に現れる必要があります。 一意性の保証により、他の順列が両方の制約を同時に満たすことができないことが保証されるため、最初に見つかった有効な一致が唯一の答えとなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from itertools import permutations

nums = list(map(int, input().split()))

for mp, w, d, l, pts in permutations(nums):
    if mp == w + d + l and pts == 3 * w + d:
        print(mp, w, d, l, pts)
        break
```このソリューションは、徹底的な割り当てチェックのアイデアを直接エンコードしています。 私たちは Python に依存しています`itertools.permutations`考えられる役割の割り当てをすべて列挙します。 

重要な点は、選択順序の最適化や積極的なプルーニングを試みていないことです。 ケース数が 120 件のみなので、オーバーヘッドは無視できます。 早期ブレークにより、有効な構成が見つかったらすぐに停止することが保証され、一意性の保証と一致します。 

微妙な点の 1 つは、値が繰り返される場合でも、すべての順列を同等に扱うことです。 正確性はインデックスの同一性ではなく値の割り当てに依存するため、これは問題ありません。 重複した値により重複した順列が生成される可能性がありますが、正確性やパフォーマンスには意味のある影響を与えません。 

## 実用的な例

 ### 例 1

 入力:`19 11 2 4 5`有効なマッピングが見つかるまで順列をテストします。 

| 国会議員 | W | D | Ｌ | ポイント | MPチェック | ポイントチェック |
 | --- | --- | --- | --- | --- | --- | --- |
 | 11 | 5 | 4 | 2 | 19 | 11 ≠ 11 | 19 = 19 |

 ここでは、MP = 11、W = 5、D = 4、L = 2、Pts = 19 となります。 

MP = W + D + L → 11 = 5 + 4 + 2 = 11 および Pts = 3W + D → 19 = 15 + 4 = 19 を検証します。 

これにより、正しい割り当てが見つかったことが確認されます。 

### 例 2

 入力:`0 0 1 1 0`有効な置換の 1 つは次のとおりです。 

| 国会議員 | W | D | Ｌ | ポイント | MPチェック | ポイントチェック |
 | --- | --- | --- | --- | --- | --- | --- |
 | 1 | 0 | 0 | 1 | 0 | 1 = 1 | 0 = 0 |

 ここで、MP = 1、W = 0、D = 0、L = 1、Pts = 0 は両方の制約を正確に満たします。 

このケースは、重複する値が重要である理由を示しています。複数の順列が存在しますが、両方の方程式を同時に満たすのは 1 つだけです。

## テストケース```python
import sys, io
from itertools import permutations

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    nums = list(map(int, sys.stdin.readline().split()))
    for mp, w, d, l, pts in permutations(nums):
        if mp == w + d + l and pts == 3 * w + d:
            return f"{mp} {w} {d} {l} {pts}"
    return ""

# provided samples
assert run("19 11 2 4 5") == "11 5 4 2 19"
assert run("2 2 6 20 10") == "10 6 2 2 20"
assert run("0 0 1 1 0") == "1 0 0 1 0"

# custom cases
assert run("3 1 1 1 4") == "3 1 1 1 4", "simple valid case"
assert run("9 3 3 3 12") == "9 3 3 3 12", "balanced draws case"
assert run("6 2 1 3 7") == "6 2 1 3 7", "mixed ordering case"
assert run("1 0 1 0 1") == "1 0 1 0 1", "edge small values"
```| テスト入力 | 期待される出力 | 検証内容 |

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、複数の値が同一である場合であり、区別できない順列の数が増加します。 のような入力の場合`0 0 1 1 0`の場合でも、正しさは値の一意性ではなく制約を満たすことに結びついているため、アルゴリズムは依然として機能します。 順列ループは最終的に次のことを試みます`MP=1, W=0, D=0, L=1, Pts=0`、これは両方のチェックに合格しますが、他のすべての順列は MP の一貫性またはスコアの一貫性のいずれかに違反します。 

もう 1 つのエッジケースは、勝利がゼロの場合です。 のような入力の場合`1 0 0 1 0`、有効な解釈では、構造を除いて勝ちまたは引き分けによる得点寄与はありません。 MP = 0 + 0 + 1 および Pts = 0 が正確に一致するため、チェックは引き続き成功します。 

3 番目のエッジケースは引き分けがゼロの場合で、得点が純粋な勝利の倍数に崩壊します。 たとえば、入力が`6 2 0 4 6`、正しい順列のみが MP 方程式と Pts 方程式の両方を同時に満たします。 このアルゴリズムはゼロを特別に扱うのではなく、方程式を一律に検証するだけで、特殊な場合のバグを回避します。
