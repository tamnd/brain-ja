 ## 解決策
 ## 問題の理解

 位置 0 から位置 L までの直線パスが与えられています。この線に沿って、ブースト ステーションと呼ばれる特別なポイントがあります。 これらの駅のいずれかに到着すると、速度は固定の定数値 c だけ即座に増加します。この値は、乗車の開始時に一度選択し、その後はどこでも使用する必要があります。 

ブースト ステーション間では、動きは単純な線形減衰によって支配されます。つまり、速度 v でセグメントに入ると、t 秒後に速度は v − t になり、そのセグメント内で移動した距離は速度の時間積分になります。 次の駅の手前で速度が足りなくなると停止してしまい、乗車は失敗します。 

目標は、初速度 c で位置 0 から開始して (最初のブーストが 0 であるため)、すべてのブースト ステーションを順番に通過して最終位置 L に到達し、合計時間最大 T 以内に終了できるように、可能な限り最小のブースト値 c を選択することです。 

制約は、n (ブースト ステーションの数) が最大 100 になり、L と T が最大 10^9 になるように構成されています。 これにより、タイム ステップにわたるシミュレーションやきめの細かい離散化が即座に除外されます。 どのソリューションでも、各セグメントを一定時間内に独立して処理する必要があるため、チェックあたり O(n log Answer) または O(n) が唯一の実行可能な方向です。 

浮動小数点の精度によって微妙な問題が発生します。 距離の式には時間の二次式が含まれるため、不注意に比較すると誤差が生じる可能性があります。 もう 1 つの重要なエッジ ケースは、速度がゼロになった瞬間にステーションに到達するのに必要な速度がかろうじて十分である場合です。 その場合、セグメントは実行可能性の境界で正確に終了し、連続時間におけるオフバイワン形式の推論は、一貫して処理されないと誤った二分探索の決定につながります。 

たとえば、2 つのステーションが非常に近く、c がわずかに過小評価されている場合、浮動誤差により計算された移動時間はまだ十分であるように見えますが、物理的には速度がゼロに達するのが早すぎて、次のブーストに到達することはありません。 

## アプローチ

 ブルートフォースアプローチでは、c の候補値を試し、乗り心地全体をシミュレートします。 セグメントごとに二次方程式を解き、次のブーストまでの距離を移動するのにかかる時間を決定します。 時間を蓄積し、T 以内に終了できるかどうかを確認します。各セグメントは所定の進入速度に応じて独立しており、運動公式によって移動距離が正確に決定されるため、このシミュレーションは正しいです。 

ただし、c は実数値であり、制限がない可能性があるため、c の値を順番に試すことは不可能です。 c を小さなステップで離散化した場合でも、必要な精度は約 1e-6 であり、妥当な検索範囲内で約 10^7 ～ 10^8 の候補が必要となり、各候補のコストは O(n) になります。 それは非常に遅くなります。 

重要な観察は単調性です。 与えられたブースト値 c によって時間 T 以内に終了できる場合は、それより大きな値 c も機能します。 c を増加すると、すべての駅での速度が厳密に増加しますが、各セグメントで必要な移動時間が短縮されるだけです。 この単調な動作により、c での二分探索が可能になります。 

各実現可能性チェックは、すべてのセグメントにわたるフォワード シミュレーションです。 主な技術的課題は、初速度 v を持つ長さ d のセグメントについて、線形減衰下でそれをカバーするのにどれくらいの時間がかかるかを計算することです。 v t − t^2/2 = d を解くと二次方程式が得られ、小さい方の正の根を取ります。 

これにより、問題全体が標準的な「O(n) チェックによる回答の二分探索」に変わります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 離散化された c | に対するブルート フォース シミュレーション O(K・n) | お(1) | 遅すぎる |
 | O(n) シミュレーションによる c の二分探索 | O(n 対数精度) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 走行を可能にする最小のブースト値 c を二分探索します。

1. 固定ブースト値で時間 T 以内に終了できるかどうかを判断する関数 check(c) を定義します。この関数は、セグメントごとに乗車をシミュレートします。 
2. 開始時には、位置 0 でブーストをすぐに受け取るため、速度は c です。また、合計時間を 0 に初期化します。 
3. 連続するブースト位置間の各セグメントについて、必要な距離 d がわかります。 セグメントに入るときの現在の速度 v もわかります。 
4. 各セグメントについて、減速運動下で距離 d を移動するのに必要な最小時間 t を計算します。 方程式 v t − t^2 / 2 = d を解きます。 v^2 ≥ 2d と仮定すると、有効な根は t = v − sqrt(v^2 − 2d) です。 
5. v^2 < 2d の場合、次のステーションに到達する前に速度がゼロに達するため、セグメントは不可能です。 その場合、check(c) はすぐに失敗します。 
6. それ以外の場合は、合計時間に t を追加し、セグメントの終わりの速度を v − t (sqrt(v^2 − 2d) と等しくなります) として更新します。 
7. ブースト ステーションに到着したら、速度を c 増加させて、v が v + c になり、続行します。 
8. すべてのセグメントを処理した後、合計時間が ≤ T かどうかを確認します。そうであれば、c は実行可能です。 

次に、答えをカバーするのに十分な範囲 (通常は [0, 1e9] 以上) で c を二分探索し、実行可能な最小値を返します。 

### なぜ効果があるのか

 シミュレーションでは、厳密な物理的不変条件が維持されます。つまり、各セグメントの開始時に、速度は過去のすべての影響を完全に取り込み、二次距離関係によって移動時間を一意に決定します。 速度は c が大きくなるほど増加するだけであり、セグメントの移動時間は進入速度の減少関数であるため、c では実現可能性は単調です。 これにより、述語 check(c) が実数直線に沿って false から true に 1 回だけ遷移するため、バイナリ検索の正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import math

def check(c, L, n, tlim, b):
    v = c
    time = 0.0

    for i in range(1, n):
        d = b[i] - b[i - 1]

        if v * v < 2 * d:
            return False

        nv = math.sqrt(v * v - 2 * d)
        dt = v - nv

        time += dt
        v = nv + c

        if time > tlim:
            return False

    d = L - b[-1]
    if v * v < 2 * d:
        return False

    nv = math.sqrt(v * v - 2 * d)
    dt = v - nv

    time += dt

    return time <= tlim

def solve():
    L, n, tlim = map(int, input().split())
    b = list(map(int, input().split()))

    lo, hi = 0.0, 1.0
    while not check(hi, L, n, tlim, b):
        hi *= 2

    for _ in range(80):
        mid = (lo + hi) / 2
        if check(mid, L, n, tlim, b):
            hi = mid
        else:
            lo = mid

    print(hi)

if __name__ == "__main__":
    solve()
```実装の中核は、O(n) で実現可能性を計算するチェック関数です。 各セグメントは、秒ごとの速度減衰をシミュレートする代わりに、二次運動方程式の閉じた形式の解を使用します。 

式 sqrt(v^2 − 2d) は距離 d を走行した後の残りの速度、v − sqrt(v^2 − 2d) はそのセグメント内で費やした時間です。 これにより、数値積分が回避されます。 

二分探索では、実行可能な解が見つかるまで上限が指数関数的に拡張され、限界を推測する必要がなく正確さが保証されます。 

1e-6 の精度には double の浮動小数点精度で十分であるため、最後のループでは固定反復回数 (80) が使用されます。

## テストケース```python
import sys, io
import math

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    from math import sqrt

    L, n, tlim = map(int, input().split())
    b = list(map(int, input().split()))

    def check(c):
        v = c
        time = 0.0
        for i in range(1, n):
            d = b[i] - b[i - 1]
            if v * v < 2 * d:
                return False
            nv = math.sqrt(v * v - 2 * d)
            time += v - nv
            v = nv + c
            if time > tlim:
                return False

        d = L - b[-1]
        if v * v < 2 * d:
            return False
        nv = math.sqrt(v * v - 2 * d)
        time += v - nv
        return time <= tlim

    lo, hi = 0.0, 1.0
    while not check(hi):
        hi *= 2
    for _ in range(60):
        mid = (lo + hi) / 2
        if check(mid):
            hi = mid
        else:
            lo = mid
    return str(hi)

## 特殊なケース

 重要なエッジ ケースは、2 つのブースト ステーションが一致するか、非常に近い場合です。 この状況では、必要な距離はゼロに近いため、セグメントはほとんど時間に寄与せず、速度は基本的に c だけ増加するはずです。 d = 0 では v^2 ≥ 0 が常に true、nv = v、dt = 0 となり、ブースト更新のみが残るため、アルゴリズムはこれを正しく処理します。 

もう 1 つのケースは、速度が正確に十分である場合、つまり v^2 = 2d である場合です。 その後、nv はゼロになり、dt は v に等しくなります。シミュレーションはステーションで正確にゼロ速度で着陸し、すぐにブーストを適用して実現可能性を維持するため、引き続き機能します。 

よりデリケートなケースは、実行可能境界付近で精度が浮いている場合です。 チェックでは平方根と比較が使用されるため、小さな数値誤差により実現可能性が逆転する可能性があります。 二分探索では、1e-6 内の一貫性のみを要求することでこれを軽減し、十分に大きな固定反復回数を使用することで安定した収束を保証します。
