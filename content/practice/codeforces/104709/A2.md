 ## 解決策
 ## 問題の理解

 小文字で構成される文字列が与えられます。 この文字列内のすべての文字について、単一のコピーとして保持することも、同じ文字の 2 つの連続するコピーに展開することもできます。 これらの選択は位置ごとに独立して行われますが、文字の相対的な順序は決して変更されません。 

これらの選択をすべての文字に適用すると、最終的に展開された文字列が得られます。 可能なすべての展開文字列の中で、辞書編集的に最小の文字列が必要です。 

重要な問題は、ある位置での決定が、最終的な文字列を他の有効な構造と比較する方法に影響を与えることです。これは、重複するかしないかによって、文字の長さとローカルな順序の両方が変化するためです。 

制約が十分に大きいため、2 倍化の決定のすべての組み合わせを明示的に試行するアプローチは実行不可能です。 各文字には 2 つの選択肢があるため、単純な検索スペースは文字列の長さに応じて指数関数的に増加し、100,000 文字のような中程度のサイズであっても不可能になります。 これにより、ブルートフォース列挙やバックトラッキングが即座に排除されます。 

最も重要なエッジ ケースは、等しい文字の連続と、文字値の増加と減少の間の遷移から発生します。 

たとえば、次のような文字列を考えてみましょう。`abc`。 で`a`、方法がわからない限り、複製が役立つかどうかは不明です`b`振る舞います。 将来のキャラクターを考慮せずにローカルで決定すると、次のようなものが生成される可能性があります。`aabbcc`次のようなより小さな辞書編集結果が存在する場合`abcc`または`aabcc`下流の構造に応じて。 

もう 1 つの微妙なケースは、文字が繰り返される場合です。`aab`。 各ポジションで独立して決定すると、最初のポジションが重複する可能性があります。`a`しかし 2 番目の場合はそうではなく、グローバルに最適ではない、一貫性のないローカルな順序付けの決定が生成されます。 

これらの例は、ポジションでの決定が`i`単独で作ることはできません。 それはサフィックスがどのように動作するかによって異なります。 

## アプローチ

 ブルートフォースソリューションでは、各文字に 1 コピーまたは 2 コピーを割り当てるあらゆる方法を試し、結果の文字列を構築し、辞書編集的に最小値を取得します。 ある長さの文字列の場合`n`、これにより生成される`2^n`可能性と構築された各文字列のコスト`O(n)`構築して比較します。 これにより、全体的なランタイムが急激に増加し、すぐに実行不可能になります。 

重要な観察は、完全な構造を世界的に比較する必要は決してないということです。 代わりに、最終的な辞書編集上の比較において、各文字が次の文字とどのように相互作用するかを理解することだけが必要です。 辞書編集上の順序は、2 つの構造が異なる最初の位置で決定されるため、意味のある唯一の比較は、元の文字列順序での隣接する決定間の比較です。 

これにより、ローカルでありながら制御された方法で推論することができます。各位置について、実際に値が異なる次の文字との比較に基づいて、2 倍にすることが役立つかどうかを決定します。 等しい文字は、決定が一貫している必要があるブロックを形成します。これは、実行内で不一致があると、相対的な順序が変更されずに比較が遅れるだけであるためです。 

これは、右から左への動的ルールにつながります。つまり、各位置の決定は次の位置によって決定され、制約が文字列全体に逆方向に伝播されます。

 | ブルートフォース | O(n · 2^n) | O(n) | 遅すぎる |

 ## アルゴリズムのチュートリアル

 最終的な答えに各文字を 1 回または 2 回出現させるかを決定しながら、文字列を右から左に処理します。 

1. 最後の文字から開始し、その後に比較するものがないため、その決定が 1 回発生するように強制します。 
2. 前の文字に移動し、元の文字列の次の文字と比較します。 現在の文字が次の文字より小さい場合、それを複製すると辞書編集上の順序が改善されます。これは、小さい文字が最終文字列の前に押し出され、プレフィックスが小さくなるためです。 
3. 現在の文字が次の文字より大きい場合、それを複製すると最終文字列の前に大きな文字が挿入され、辞書編集上の順序が悪化するだけなので、単一のコピーとして保持します。 
4. 現在の文字が次の文字と等しい場合、次の位置から決定を継承します。 これは、等しい文字が依存関係チェーンを形成し、最適な構造が実行全体にわたって一貫性を保つ必要があるためです。 いかなる偏差も、プレフィックスの順序を改善することなく、比較をシフトするだけです。 
5. すべての位置の決定を計算した後、計算されたルールに従って各文字のコピーを 1 つまたは 2 つ追加して、最終的な文字列を構築します。 

微妙な部分は、同等の文字による伝播です。 これがないと、等価性により実際の比較点がさらに右側に隠蔽されるため、ローカル比較は失敗します。 

### なぜ効果があるのか

 あらゆるポジションで`i`、構築されたプレフィックスは、最初に異なるインデックスで別の有効な構築と比較された場合にのみ意味を持ちます。 での決定`i`重要なのはそのときだけ`s[i]`は、2 つの候補出力間の最初の分岐点です。 もし`s[i]`等しい`s[i+1]`の場合、どちらの選択も最初の分岐をさらに右に延期します。つまり、最適な決定は接尾辞によって完全に決定されます。 これにより、各位置が次の不等比較点から正確さを継承する安定した後方依存関係が作成され、ローカルな決定によってグローバルな辞書編集上の最小性が無効にならないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)
    if n == 0:
        return

    # decision[i] = 1 or 2 copies of s[i]
    dec = [1] * n
    dec[n - 1] = 1

    for i in range(n - 2, -1, -1):
        if s[i] < s[i + 1]:
            dec[i] = 2
        elif s[i] > s[i + 1]:
            dec[i] = 1
        else:
            dec[i] = dec[i + 1]

    res = []
    for i in range(n):
        res.append(s[i] * dec[i])

    sys.stdout.write("".join(res))

if __name__ == "__main__":
    solve()
```ソリューションはまず文字列を読み取り、配列を準備します。`dec`各文字が 1 回または 2 回出現するかどうかを保存します。 右から左へのループは依存関係ロジックをエンコードします。各決定は次の文字または次の計算済みの決定にのみ依存し、線形な時間動作が保証されます。 

構築フェーズでは、保存された決定に従って各文字を拡張するだけです。 最後の文字が常に正しく初期化され、等しい文字の伝播で`dec[i + 1]`比較を再計算するのではなく。

 ## 特殊なケース

 単一文字入力の場合、比較する接尾辞がないため、アルゴリズムはただちに 1 つの文字を割り当てます。 これにより、バックワード ループでの境界の問題が回避されます。 

次のようなすべて同一の文字の文字列の場合、`aaaa`、すべてのポジションは右端のキャラクターからの決定を継承します。 最後の文字が単一であるため、チェーン全体が単一の決定となり、結果として 2 倍化は行われません。これは、すべてのシンボルが同一である場合、2 倍化によって辞書編集上の順序が変更されないという事実と一致します。 

次のような減少する文字列の場合`cba`、すべての比較の結果は 1 つのコピーになります。 すべてのローカル比較により、展開すると辞書編集順序が悪化することが示されるため、アルゴリズムは重複を正確に回避します。 

次のような増加する文字列の場合`abc`、各文字は後続文字よりも小さいため、各位置が 2 倍になり、前方に大きくロードされた辞書編集上最小限の文字列が生成され、初期の小さな文字を最大化することが最適であることが確認されます。
