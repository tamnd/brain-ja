 ## 解決策
 ## 問題の理解

 いくつかの独立したテスト ケースが与えられています。 それぞれに正の整数のリストがあります。 このリストには追加の整数を 1 つだけ挿入できます。 目標は、挿入後のコレクション全体の最大公約数が正確に 1 になるように、この挿入値を選択することです。すべての有効な選択肢の中から、最小の非負の整数を選択する必要があります。ただし、挿入値を 1 にすることはできません。 

このタスクが本当に求めているのは、慎重に選択した 1 つの数値を使用して配列全体の gcd を「修正」し、その数値を最小化する方法で行う方法です。 

この制約により、すべてのテスト ケースにわたって合計 10^5 までの要素が許可され、最大値は 10^18 になります。 これにより、テスト ケースごとに多くの可能性があるすべての配列要素に対して候補の挿入をシミュレートしようとするソリューションが即座に除外されます。 配列に対する gcd の計算は安価ですが、構造を持たずに要素ごとに多数の候補を繰り返し試行すると、不注意に実行した場合にのみ遅すぎます。 ここでは、構造が問題を非常に小さな検索に分解していることがわかります。 

重要な微妙なエッジケースがいくつかあります。 

すべての数値が同一で 1 より大きい場合、gcd はその数値になります。 たとえば、[6, 6, 6] のような配列には gcd 6 があります。x = 0 を挿入しようとすると、gcd は gcd(6, 0) = 6 になり、役に立ちません。 x = 2、gcd(6, 2) = 2 を試してみると、やはり 1 にはなりません。6 と素の数値のみが機能し、そのような最小の数値を見つける必要があります。 

配列にすでに gcd 1 がある場合、gcd(1, 0) = 1 なので 0 の挿入は有効です。これにより、0 が可能な最小の答えとなり、1 のみが禁止されているため許可されます。 

不注意なアプローチでは、すべての候補 x に対して配列全体の gcd を独立して再計算しようとします。 x は原理的に大きくなる可能性があるため、これは時間を無駄にし、実際には元の配列の gcd のみが重要であるという事実を見逃してしまいます。 

## アプローチ

 ブルートフォースのアイデアは単純です。 テスト ケースごとに、配列の gcd を計算し、x の値を 0 から開始して 1 をスキップして増加させ、x を挿入することで全体の gcd が 1 に等しくなるかどうかを確認します。各チェックでは、gcd(g, x) を計算する必要があります。ここで、g は配列の gcd です。 これは、配列全体に x を加えた gcd が正確に gcd(g, x) であるため機能します。 

この強引なアプローチは正しいですが、洞察なしで拡張することを想像すると、x の多くの値をテストし、配列全体と繰り返し結合する必要があるように感じるかもしれません。 毎回 n 個の要素に対して gcd を再計算すると、コストが高くなります。 ただし、配列を 1 つの gcd 値に圧縮すると、各チェックは O(1) になり、ボトルネックはなくなります。 

重要な観察は、gcd 操作では配列全体が単一の数値 g と同等であるということです。 問題は、gcd(g, x) = 1 および x ≠ 1 のような最小の x を見つけることになります。x = 0 は g = 1 の場合にのみ有効であるため、残りの検索は 2 から始まる非常に小さな整数に対して行われます。 実際には、g にはその大きさに比べてせいぜい少数の小さな素因数があるため、最初の互いに素な数は非常に早く現れます。 

これにより、問題は、テスト ケースごとに 1 つの gcd を計算し、整数の小さなプレフィックスをスキャンすることに軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 候補 x ごとの配列に対するブルート フォース | O(n · X) | お(1) | 遅すぎる |
 | gcd に減らしてから、小さい x | を試してください。 O(n + K) | お(1) | 承認済み |

 ここで、K は互いに素な値を見つける前にチェックされる小さな整数の数であり、実際には非常に小さな定数によって制限されます。 

## アルゴリズムのチュートリアル

 まず配列を縮小し、次に最小の有効な挿入値を検索します。

1. 配列内のすべての要素の gcd を計算します。 gcd は結合的で可換であるため、これによりすべての構造が 1 つの数値 g に圧縮されます。 
2. g が 1 に等しい場合、配列には挿入なしですでに gcd 1 が含まれています。 1 以外で許容される最小の非負の整数は 0 で、0 を挿入すると gcd は 1 のままになります。 
3. g が 1 より大きい場合、gcd(g, x) が 1 に等しくなるように、1 を除いて 0 から始まる最小の整数 x を見つけなければなりません。 
4. この場合、gcd(g, 0) = g であり、g > 1 の場合は 1 ではないため、x = 0 を直ちにスキップします。 
5. x = 2 から上へチェックを開始します。 候補ごとに、gcd(g, x) を計算します。 この gcd が 1 になる最初の値が答えです。 
6. 昇順にスキャンしており、最小限のものが必要なため、そのような x が見つかったらすぐに停止します。 

### なぜ効果があるのか

 gcd(a1, a2, ..., an, x) は gcd(g, x) に単純化されるため、配列全体はその gcd g を通じてのみ寄与します。 したがって、結果を固定する x の選択は g と互いに素でなければなりません。 有効な最小の整数は、g がすでに 1 の場合は 0、または g と素因数を共有していない 2 から始まる最初の整数のいずれかです。 gcd 制約は素因数にのみ依存するため、g を除算しない新しい素数を導入する数値 x に達すると、その x の gcd は永続的に 1 になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import math

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        arr = list(map(int, input().split()))
        
        g = 0
        for v in arr:
            g = math.gcd(g, v)
        
        if g == 1:
            out.append("0")
            continue
        
        x = 2
        while True:
            if math.gcd(g, x) == 1:
                out.append(str(x))
                break
            x += 1
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この解決策では、まず配列を単一の gcd 値に折りたたみます。 これは、今後のすべての推論にとって重要な唯一の情報です。 g = 1 の分岐はゼロの特別な役割を処理します。これは gcd 1 を保持し、許容される最小数です。 

g > 1 の場合、2 から始まる単純な増加スキャンを実行します。gcd チェックは定数時間であり、個々の配列要素との相互作用を考慮する必要がなくなるため、安全です。 

コードではループは意図的に制限されていませんが、非常に小さな整数はほとんどの場合 g で gcd 構造を壊すため、数学的にはすぐに終了します。 

## 実用的な例

 ### 例 1

 入力配列: [2、1、4]

 配列の gcd を段階的に計算します。 

| ステップ | 値 | 現在の gcd |
 | --- | --- | --- |
 | 開始 | - | 0 |
 | 2 を読む | 2 | 2 |
 | 1 を読む | 1 | 1 |
 | 4 を読む | 4 | 1 |

 最終的な gcd は 1 なので、すぐに 0 を出力します。gcd(1, 0) = 1 であるため、0 を挿入しても gcd は変わりません。 

この例は、配列がすでに gcd 1 と「完全に互換性」があり、許容される最小の数値を挿入する以外に修正が必要ないブランチを示しています。

 入力配列: [9、33、3、11]

 | ステップ | 値 | 現在の gcd |
 | --- | --- | --- |
 | 開始 | - | 0 |
 | 9 を読む | 9 | 9 |
 | 33 を読む | 33 | 3 |
 | 3 を読む | 3 | 3 |
 | 11 を読む | 11 | 1 |

 待ってください。この場合、gcd は 1 になるため、ルールに従って 0 が出力されます。これは、意図した 2 番目のサンプルの動作と一致します。 

このトレースは、数値が高度に構造化されているように見える場合でも、単一の比較的素な要素によって gcd が 1 に崩壊し、即座にゼロケースがアクティブになる可能性があることを示しています。

 ## 特殊なケース

 配列 gcd がすでに 1 である場合、0 の挿入は有効であり、厳密に最適です。 たとえば、入力 [3, 5, 7] はすぐに gcd 1 に折りたたまれるため、アルゴリズムは正の候補を試行してはなりません。 

配列 gcd が 1 より大きく偶数の場合、小さい偶数の候補はすぐに失敗します。 たとえば、g = 8 の場合、x = 2、4、6、8 は係数 2 を共有するためすべて失敗します。アルゴリズムは、x が g と互いに素な 3 または 5 のような数値に達するまで x をインクリメントすることで、それらを正しくスキップします。 

[12, 12, 12] のように、すべての数値が同一の場合、gcd は 12 のままで、アルゴリズムは 12 と素因数を共有しない最初の整数が見つかるまで、2 から上方向に検索します。この場合、gcd(12, 5) = 1 であるため、x = 5 がすぐに機能し、スキャンは早期に終了します。
