 ## 解決策
 ## 問題の理解

 私たちには一連の手紙が与えられており、各手紙はすでに宛先の会社に割り当てられています。 同時に封筒もあり、各封筒には同じ順序構造に一致する固定の会社が書かれています。 アミールが持つ重要な自由は、すべての封筒に 1 つの手紙が正確に届く限り、封筒全体で手紙を任意に並べ替えることができることです。 

私たちが尊重しなければならない制約は、手紙を封筒に入れた後、その会社が手紙の宛先の会社と一致する封筒に入ってはいけないということです。 言い換えれば、手紙が会社に宛てられたものであれば、`x`と書かれた封筒には入れられません。`x`。 

したがって、問題は、すべての文字がそのラベルがそのターゲット値と異なる位置に配置されるような、指定された文字の複数セットの順列が存在するかどうかをチェックすることに帰着します。 

入力サイズは最大です`n = 100000`これにより、順列に対する階乗または指数推論が即座に除外されます。 明示的な構築や順列のチェックを伴うものはすべて不可能です。 ラベルの分布の数または構造的特性のみを使用して検証できる条件が必要です。 

すべての文字が同じ会社に属している場合、微妙な特殊ケースが表示されます。 その状況では、すべての封筒も同じ会社に属し (その会社は少なくとも 1 回は出現する必要がありますが、封筒は位置的に対応しているため)、すべての配置は必然的に禁止された意味で「正しい」ものになります。 例えば：```
3 1
1 1 1
```出力は次のようにする必要があります`NO`、すべての文字が同一であり、どの配置でも一致するためです。 

もう 1 つのエッジ ケースは、複数の企業が存在するが、1 つの企業が大きく支配している場合です。 たとえば、単一の企業がポジションの半分以上に表示されている場合、そのラベルのすべての出現に対応するのに十分な「外国」枠がないため、自己配置を完全に回避することは不可能になるのではないかと疑われるかもしれません。 

## アプローチ

 ブルートフォースアプローチでは、封筒に手紙を割り当て、割り当てのすべての順列をチェックしようとします。 概念的には、各手紙をアイテムとして、各封筒をスロットとして扱い、すべての全単射を試して、固定点を回避するものがあるかどうかを確認します。 これは、考えられるすべての配置を検討するため、正確性を保つために機能しますが、時間とともに増大します。`n!`、これは`n = 100000`全く実現不可能です。 

重要な洞察は、個々の順列について考えるのをやめ、代わりに各企業ラベルの数に焦点を当てることです。 特定の会社の各手紙は、別の会社に属する封筒に入れる必要があるため、ラベルが出現するたびにそれ自体のクラスを「回避」する必要があります。 制限要因は、残りのラベルがこれらの回避された配置をホストするのに十分な容量を提供するかどうかです。 

1 つの企業があまりにも多く出現する場合、具体的には全レターの半分以上の場合、配置を最適に分配しようとしても、すべての出現を分離するのに十分な不一致の封筒が利用できなくなります。 逆に、半分を超えるラベルがない場合は、`n`の場合、有効な混乱のような割り当ては、異なるラベル間で循環または貪欲なシフト方法で要素を再配置することによって常に構築できます。 

したがって、問題全体は、企業ラベルの最大頻度が最大かどうかを確認することに帰着します。`n - max_frequency`。 同様に、どのラベルもあまりにも強く支配しないようにする必要があるだけです。 この特定の構造では、条件は最大周波数が次の値であるかどうかをチェックすることを単純化します。`n - largest_frequency`、単一のラベルがすべての位置を占めるか、混乱のような順列に必要なバランスに違反しない限り、常に成り立ちます。

 | ブルートフォース | お(ん!) | O(n) | 遅すぎる |

 ## アルゴリズムのチュートリアル

 この問題を周波数制約チェックに落とし込むことで解決します。 

1. 各企業がリストに何回登場するかを数えます。 これにより、各宛先クラスに送信したい文字数がわかります。 
2. すべての会社の最大頻度を見つけます。 これにより、最も「要求の厳しい」グループ、つまり紛争を強制する可能性が最も高いグループが特定されます。 
3. この最大頻度を残りの文字と比較します。 最も頻度の高い企業がすべてのポジションを占めている場合、または同様に、その出現を他の企業のエンベロープに割り当てることができない場合、失敗と判断します。 
4. そうでなければ、残りの企業が文字を並べ替えるのに十分なスロットを提供し、その会社自体のクラスに文字が残らないようにするため、成功と結論付けます。 

このステップの背後にある理由は、単一のクラスが利用可能な代替スロットのシステムを圧倒しない場合に、有効な割り当てが存在するということです。 

### なぜ効果があるのか

 各企業のラベルを色として考えてください。 それぞれの色のアイテムを、それ自体の色ではない位置に配置したいと考えています。 これに対する唯一の障害は、ある色が頻繁に出現し、他の色が十分な「安全な」位置を提供できない場合です。 最大のグループが大きすぎる場合は、最適な再配置を行ったとしても、少なくとも 1 つの要素がそのグループ内に留まることを余儀なくされます。 それが大きすぎない場合は、いつでも支配的なグループの要素を他のグループに属する位置に分散し、残りの配置を同様に完了することができます。 正確かどうかは、最大周波数のみがボトルネックを生み出すという事実にかかっています。 他のすべてのディストリビューションは、固定割り当てを作成せずにシャッフルできます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
arr = list(map(int, input().split()))

freq = {}
for x in arr:
    freq[x] = freq.get(x, 0) + 1

mx = max(freq.values())

# if one company dominates too much, impossible
if mx > n - mx:
    print("NO")
else:
    print("YES")
```このソリューションでは、最初にすべての企業ラベルの頻度マップを構築します。 これが必要なのは、問題の構造が位置ではなく多重度に完全に依存しているためです。 最大周波数を計算した後、デレンジメント スタイルの制約から導出された実現可能性条件を直接適用します。 

実装の重要な詳細は、順列を構築しようとしないことです。 どのような建設的なアプローチでも、複雑さとエッジケースエラーの危険があります。 代わりに、純粋に組み合わせ限界に依存します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 周波数をカウントして最大値を計算するシングルパス |
 | スペース | O(m) | 最大 m 個のラベルにわたる頻度辞書 |

 制約により、最大で次のことが許可されます。`n = 100000`したがって、リニアスキャンとハッシュカウントは制限内に快適に収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    input = _sys.stdin.readline

    n, m = map(int, input().split())
    arr = list(map(int, input().split()))

    freq = {}
    for x in arr:
        freq[x] = freq.get(x, 0) + 1

    mx = max(freq.values())
    return "YES\n" if mx <= n - mx else "NO\n"

# provided samples
assert run("3 1\n1 1 1\n") == "NO\n"
assert run("4 4\n4 1 2 3\n") == "YES\n"

# custom cases
assert run("1 1\n1\n") == "NO\n", "single element must fail"
assert run("2 2\n1 2\n") == "YES\n", "swap works"
assert run("5 2\n1 1 1 2 2\n") == "YES\n", "balanced mix"
assert run("6 2\n1 1 1 1 2 2\n") == "NO\n", "dominant class"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1 1 / 1`| いいえ | 最小サイズ、強制自己一致 |
 |`2 2 / 1 2`| はい | 最も単純な有効なスワップ |
 |`5 2 / 1 1 1 2 2`| はい | 自明ではない実現可能な組み合わせ |
 |`6 2 / 1 1 1 1 2 2`| いいえ | 支配的な周波数ブロックのソリューション |

 ## 特殊なケース

 次のような単一文字のシナリオの場合`n = 1`、唯一の可能な配置が固定されているため、最大頻度が以下に等しいため、アルゴリズムは正しく NO を返します。`n`。 

次のような非常に偏った分布の場合`1 1 1 1 2 2`、の周波数`1`は 4 ですが、補数は 2 のみです。`mx > n - mx`トリガーが不十分であることを正しく特定し、`1`スロットを使用して自己配置を回避します。 

バランスの取れたケースの場合`1 2 3 4`、すべての周波数は 1 なので、`mx = 1`そして`n - mx = 3`、有効な置換が可能になります。 アルゴリズムは、明示的な割り当てを構築せずに、容量制約から導出される実現可能性条件のみに依存して、これらのケースを受け入れます。
