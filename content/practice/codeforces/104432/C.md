 ## 解決策
 ## 問題の理解

 整数配列が与えられ、特別な特性を持つ連続した部分配列がいくつあるかを数えるように求められます。部分配列内のすべての要素を乗算すると、結果の積の約数は奇数になります。 

この条件の背後にある重要な数学的事実は、数値が完全な平方である場合に限り、その数値には奇数の約数があるということです。 通常、約数はペアで表されますが、完全平方の場合、1 つの約数のペアが単一の反復因数に崩壊し、奇数のカウントが作成されます。 

したがって、タスクは積が完全な平方である部分配列を数えることに帰着します。 

配列要素は正で最大 300 であり、テスト ケース全体で最大 10^6 の合計要素が存在する可能性があります。 このサイズでは、すべての部分配列を明示的に検査するソリューションは即座に除外されます。 テスト ケースごとの 2 次列挙では、約 n^2 / 2 個の部分配列が試行され、最悪の場合には 10^10 回程度の演算が行われ、実行可能な制限をはるかに超えます。 

製品の成長の速さから、微妙なエッジケースが発生します。 たとえば、[2, 2, 2, 2] のような小さな配列でも、すでに多くの大きな部分配列積が生成されていますが、実際には積を直接計算しません。 単純な乗算ベースのチェックを繰り返し実行すると、オーバーフローしたり遅くなったりします。 

もう 1 つの重要なエッジ ケースは、すべての要素が 1 の場合です。その場合、すべての部分配列には積 1 (完全な平方) が含まれるため、答えは n(n+1)/2 になります。 適切なソリューションでは、特別なケースを使用せずにこれを自然に処理する必要があります。 

## アプローチ

 ブルートフォース ソリューションでは、すべての部分配列を試し、その積を計算し、その積が完全な二乗であるかどうかを確認します。 実行中の製品を拡張することで製品を最初から再計算することを避けたとしても、テスト ケースごとに O(n^2) の更新を実行します。 合計要素数が最大 10^6 の場合、最悪の場合、約 5×10^11 回の演算が必要となり、これは実行不可能です。 

重要な洞察は、製品の数値は決して必要ないということです。 製品が完全な正方形であるかどうかのみを考慮します。 数値は、因数分解におけるすべての素指数が偶数の場合に完全平方になります。 これにより、問題は乗算から素指数のパリティの追跡へと移ります。 

各 a[i] は最大 300 であるため、その素因数分解には 300 までの素数のみが含まれ、各数値はどの素数が奇数回出現するかによって表すことができます。 パリティのみを追跡するため、各要素は素数に対するビットマスクとしてエンコードできます。素数がプレフィックス積で奇数の指数に現れる場合、ビットは 1 になります。 

サブ配列の積は、サブ配列に対するこれらのビットマスクの XOR が 0 である場合にのみ完全二乗になります。 これにより、問題は、XOR が 0 に等しいサブ配列をカウントするようになります。これは、標準的なプレフィックス XOR 頻度の問題です。 

私たちはプレフィックス XOR マスクを維持し、各マスクが出現する頻度をカウントします。 等しいプレフィックス マスクの各ペアは、XOR が 0 である部分配列を定義します。したがって、その積は完全二乗になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2 log A) | お(1) | 遅すぎる |
 | プレフィックス XOR 頻度 | O(n log A + P) | O(P) | 承認済み |

 ここで P は、n で区切られた個別のプライムマスク状態の数です。 

## アルゴリズムのチュートリアル

 各数値を素数指数のパリティのみをキャプチャする表現に変換し、プレフィックス累積を使用します。

1. 最大 300 までの素数を事前計算し、各素数にインデックスを割り当てます。 これにより、因数分解用のコンパクトなビットマスクを構築できるようになります。 
2. 配列要素ごとに因数分解し、各ビットが因数分解で素数が奇数回出現するかどうかに対応するビットマスクを作成します。 パリティのみを考慮しているため、カウントをインクリメントするのではなく、繰り返し除算によってビットが切り替わります。 
3. ゼロに初期化された実行中のプレフィックス マスクを維持します。 これは、開始位置から現在位置までのすべてのエンコードされた値の XOR を表します。 
4. ハッシュ マップまたは辞書を使用して、各プレフィックス マスクが出現した回数を数えます。 周波数 1 の空のマスクで初期化します。 
5. 各要素を処理するときに、要素のマスクと XOR 演算してプレフィックス マスクを更新します。 プレフィックス マスク値に到達するたびに、その現在の周波数を答えに加算します。 これにより、同じマスクが発生した以前のすべての位置がカウントされ、現在のインデックスで終わる有効なサブ配列が形成されます。 
6. 現在のプレフィックス マスクの周波数を増やします。 

ステップ 5 が正しい理由は、2 つの等しいプレフィックス マスクが、それらの間のセグメントの XOR がゼロであることを暗示しているためです。これは、すべての素数指数が偶数にキャンセルされることを意味し、これがまさに完全二乗積の条件です。 

### なぜ効果があるのか

 このアルゴリズムは、位置 i のプレフィックス マスクが最初の i 要素の積の素指数のパリティを表すという不変条件を維持します。 XOR キャンセルによってすべての素数指数が偶数になるため、l から r までの部分配列の積は、l−1 と r のプレフィックス マスクが同一である場合に完全な平方になります。 したがって、同一のプレフィックス マスクをカウントすると、すべての有効なサブ配列が 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

# Precompute primes up to 300
MAXV = 300
is_prime = [True] * (MAXV + 1)
is_prime[0] = is_prime[1] = False
primes = []
for i in range(2, MAXV + 1):
    if is_prime[i]:
        primes.append(i)
        for j in range(i * i, MAXV + 1, i):
            is_prime[j] = False

prime_index = {p: i for i, p in enumerate(primes)}

def factor_mask(x):
    mask = 0
    for p in primes:
        if p * p > x:
            break
        if x % p == 0:
            cnt = 0
            while x % p == 0:
                x //= p
                cnt ^= 1
            if cnt:
                mask ^= (1 << prime_index[p])
    if x > 1:
        mask ^= (1 << prime_index[x])
    return mask

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        freq = {0: 1}
        pref = 0
        ans = 0

        for v in a:
            pref ^= factor_mask(v)
            ans += freq.get(pref, 0)
            freq[pref] = freq.get(pref, 0) + 1

        print(ans)

if __name__ == "__main__":
    solve()
```因数分解ステップでは、各数値のパリティ マスクを構築します。 プレフィックス変数はこれらのマスクの XOR を累積し、配列の現在のプレフィックスの積における素数指数のパリティを効果的に追跡します。 

頻度辞書には、各プレフィックス状態が何回出現したかが格納されます。 接頭辞が繰り返される場合、以前に出現したすべての部分が、現在の位置で終わる有効な部分配列を形成します。 

よくある実装の落とし穴は、インデックス 0 から始まるサブ配列をカウントするために必要な、ゼロ マスクの頻度を 1 に初期化するのを忘れることです。

 ## 特殊なケース

 のような入力の場合`[1]`、プレフィックス マスクは常に 0 であるため、周波数マップはすぐに 1 つのサブ配列をカウントします。 アルゴリズムは頻度から始まります`{0:1}`したがって、単一の要素を処理する場合、プレフィックスはゼロのままで、正解に一致する有効な部分配列を 1 つだけ提供します。 

のような入力の場合`[2, 2, 2, 2]`、すべての要素が同じプライムビットを切り替えます。 プレフィックス マスクは 2 つの状態を交互に切り替えます。 プレフィックス状態の各繰り返しは複数のサブ配列に寄与し、頻度テーブルは等しい状態のすべてのペアを正確にカウントします。 たとえば、プレフィックスが偶数の位置でゼロに戻る場合、2 の指数はそれらのセグメント全体で偶数であるため、積が完全な平方である部分配列をカウントします。
