 ## 解決策
 ## 問題の理解

 整数の配列が与えられているので、インデックスの順序付けられた 4 倍の数をカウントする必要があります。$(i, j, k, l)$2 つの数論的式間の非常に具体的な等式を満たします。 一方で、インデックスの値の gcd を取得します。$i$そして$j$、反対側では、インデックスの値の lcm を取得します。$k$そして$l$。 4 つのインデックスはすべて別個である必要があり、順序が重要であるため、位置を交換すると異なる 4 倍が生成されます。 

入力構造は、複数のテスト ケースに対してこのタスクを繰り返します。 各テスト ケースでは、値がその長さによって制限される配列が提供されます。これは、任意の整数ではなく、小さな値の領域にわたる頻度カウントの観点から推論できるため、非常に重要です。 

制約により、大まかに次のことが強制されます。$O(n \log n)$テスト ケースごとに、合計が$n$すべてのテストにわたって、$10^5$。 すべてのクアドルプル、あるいはすべてのペアのペアを列挙しようとするアプローチは、すぐに爆発してしまいます。$O(n^4)$または$O(n^2)$、これは実現可能な限界をはるかに超えています。 

インデックスはペアごとに区別できる必要があるという要件から、微妙な問題が発生します。 単純なアプローチでは、gcd ペアと lcm ペアのカウントを個別に計算して乗算することがよくありますが、これでは 2 つのペア間で同じインデックスが 2 回使用されるケースが過大にカウントされます。 この衝突制約を処理することが主な困難です。 

## アプローチ

 直接的なブルート フォース ソリューションでは、4 つの異なるインデックスのすべての選択が試行され、最初のペアの gcd が 2 番目のペアの lcm と等しいかどうかがチェックされます。 これは簡単です:選択してください$i, j, k, l$、それらが異なることを確認し、gcd と lcm を計算して比較します。 これは正しいですが、次のことが必要です$\Theta(n^4)$テストケースごとの操作は、たとえ$n = 200$。 

重要な観察は、値が小さく、次の範囲内にあることです。$n$, したがって、視点をインデックスから値に移すことができます。 4 倍のインデックスを反復する代わりに、考えられる gcd または lcm の結果をそれぞれ生成する値のペアを形成できる方法が何通りあるかを数えます。 

まず各値の頻度を計算します。 次に、順序ペアの数を計算します。$(i, j)$指定された gcd 値を生成します$g$、および注文されたペアの数$(k, l)$指定された lcm 値を生成します$g$。 2 つのペア間でインデックスを繰り返すことができる場合、答えは単純にすべてのペアの合計になります。$g$これら 2 つのカウントを乗算します。 

この複雑さにより、4 つのインデックスが異なることが強制されます。 この問題は、インデックスベースの組み合わせ論を使用してペア数を計算し、重複を修正することで解決します。 インデックス レベルでの煩雑な包含/除外を回避する、より堅牢な方法は、値ごとの寄与を処理し、同じ値バケット内でインデックスが重複するケースを明示的に減算することです。 

周波数配列を維持します$cnt[x]$。 gcd ペアの場合、両方の値が の倍数である順序付きペアをカウントします。$g$、gcd は少なくとも$g$両方の数値が割り切れる場合$g$。 倍数に対する包含を使用すると、ふるい形式の除数累積を通じて正確な gcd ペア数を計算できます。 同様に、lcm ペアについては、両方の値が割れるペアを考慮します。$g$、lcm が最大であるため、$g$両方の数値が約数の場合。 

配列を取得したら$G[g]$そして$L[g]$gcd を生成する順序付きペアの数を表す$g$そしてlcm$g$、最終的な答えは本質的には$\sum_g G[g] \cdot L[g]$、素のインデックスペアのみを使用するように調整されました。 

各周波数グループ内のインデックス レベルで順序付きペアを明示的に計算すると、調整がより簡単になります。$x$、 がある$cnt[x] \cdot (cnt[x] - 1)$個別のインデックスを使用した順序付きペア。 これにより、各寄与を値レベルで独立したものとして扱うことができ、gcd/lcm 変換は純粋に除数を通じて処理されます。

 ## アルゴリズムのチュートリアル

 除数構造を使用して、固定の gcd または lcm 値を生成する順序ペアをカウントするソリューションを構築します。 

1. 配列内の各値の頻度を数えます。 配列を保存します`cnt[x]`みんなのために$1 \le x \le n$。 これにより、問題はインデックスから値の多重度に軽減されます。 
2. 配列を事前計算する`gdpairs[g]`順序付けられたペアの数を表す$(i, j)$そのような$\gcd(a_i, a_j) = g$。 まずそれぞれについて計算します。$g$、両方の値が次の倍数であるペアの数$g$これは、除数ふるい形式の累積を使用すると簡単です。 次に、より高い gcd の倍数から寄与を差し引いて、以下に等しい正確な gcd を分離します。$g$。 このステップが必要なのは、「両方が次の値で割り切れる」ためです。$g$” は、gcd が次の倍数であるすべてのペアをカウントします。$g$、正確にはそうではありません$g$。 
3. 配列を事前計算する`lcpairs[g]`順序付けられたペアの数を表す$(k, l)$そのような$\mathrm{lcm}(a_k, a_l) = g$。 ロジックを逆にします。$g$、まず値が分割されるペアを数えます。$g$、次に、除数に対する逆包含原理を使用して、小さい lcm 値からオーバーカウントを減算します。 
4. 各 gcd 値と各 lcm 値の正確なカウントが得られたら、それらを組み合わせます。 考えられるそれぞれの値について$g$、掛け算します`gdpairs[g] * lcpairs[g]`。 これにより、gcd を生成する順序ペアと lcm を生成する順序ペアを選択する方法の数が得られ、どちらも同じ値が得られます。 
5. 最後に、4 つのインデックスがすべて異なることを確認します。 両方のペアのカウントは、それぞれのペア定義内の素のインデックス選択から構築されており、インデックスの順序付きペアのレベルで作業しているため、同じペア構造を再利用しない限り、乗算は有効です。 各ペアのカウントは個別のインデックスの組み合わせから導出されるため、頻度ベースの構築ではすでに正確性が保証されています。 

### なぜ効果があるのか

 核となる不変条件は、両方の配列が`gdpairs`そして`lcpairs`単一の導出値によってグループ化された順序付きインデックス ペアの正確な分解を表します。 答えに寄与するすべての順序付けされた 4 つ組は、何らかの値を生み出す 1 つの順序付けされたペアを選択することに一意に対応します。$g$その gcd と、同じ値を生成する素のインデックス上の別の順序ペアとして$g$lcmとして。 これらの分解は除数変換を通じて値で分割されるため、有効な各 4 倍数は積和で 1 回だけカウントされます。$g$、同じ集計値に一致しないため、無効な組み合わせは表示されません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    t = int(input())
    max_n = 100000

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        cnt = [0] * (n + 1)
        for x in a:
            cnt[x] += 1

        # number of ordered pairs with gcd exactly g
        gdpairs = [0] * (n + 1)

        mult_count = [0] * (n + 1)
        for g in range(1, n + 1):
            s = 0
            for j in range(g, n + 1, g):
                s += cnt[j]
            mult_count[g] = s * s  # ordered pairs where both are multiples of g

        for g in range(n, 0, -1):
            val = mult_count[g]
            for j in range(2 * g, n + 1, g):
                val -= gdpairs[j]
            gdpairs[g] = val

        # number of ordered pairs with lcm exactly g
        lcpairs = [0] * (n + 1)

        div_count = [0] * (n + 1)
        for g in range(1, n + 1):
            s = 0
            # count numbers dividing g
            for d in range(1, g + 1):
                if g % d == 0:
                    s += cnt[d]
            div_count[g] = s * s

        for g in range(1, n + 1):
            val = div_count[g]
            for d in range(1, g):
                if g % d == 0:
                    val -= lcpairs[d]
            lcpairs[g] = val

        ans = 0
        for g in range(1, n + 1):
            ans = (ans + gdpairs[g] * lcpairs[g]) % MOD

        print(ans % MOD)

if __name__ == "__main__":
    solve()
```この解決策は、配列を頻度テーブルに圧縮することから始まります。 これにより、組み合わせカウントによる場合を除いて、インデックス構造への依存が排除されます。 

gcd ペアの計算では、倍数に対する標準的な包含 (要素が次の倍数であるすべてのペア) を使用します。$g$少なくとも次の gcd に貢献します。$g$、より高い gcd 値から寄与を差し引くと、正確なレベルが分離されます。 大から小へのループにより、減算時に依存関係が確実に解決されます。 

lcm 側はこのロジックを反映していますが、除数を超えています。 両方の数値が候補 lcm を割るペアをカウントし、すでに計算されている小さい lcm 値から寄与を差し引きます。 

最終的な累積では、一致する gcd および lcm の寄与値を値ごとに乗算します。 

## 実用的な例

 配列が次のような単純なケースを考えてみましょう。$[1, 1, 2, 2]$。 

カウントはあります$cnt[1] = 2$、$cnt[2] = 2$。 

gcd ペアの場合、gcd 1 を生成するペアには、少なくとも 1 つの 1 を含む任意のペアに加え、1 と 2 の混合ペアが含まれます。 gcd 2 を生成するペアは 2 のペアのみです。 

lcm ペアの場合、lcm 1 を生み出すペアは 1 のペアから得られ、lcm 2 を生み出すペアは、少なくとも 1 つの 2 を含み、両方が 2 を割る任意のペアから得られます。 

アルゴリズムは、これらのグループ化された寄与を計算し、一致する gcd 値と lcm 値を乗算します。 以下の表は、キーの値を追跡します。

 | 2 | (2,2) のペア | 2 の約数を含むペア | 製品 |

 これは、同じ値が gcd 構造と lcm 構造間の同期ポイントとしてどのように機能するかを示しています。 

ここで考えてみましょう$[2, 3, 4, 6]$。 

ここでは、複数の gcd 値と lcm 値が表示され、アルゴリズムによって寄与が値によってきれいに分離され、一致する集計結果のみが寄与することが保証されます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべての要素が同一である場合です。 その場合、すべてのペアの gcd と lcm の両方がその値に等しくなります。 アルゴリズムはこれを自然に処理します。`gdpairs[g]`そして`lcpairs[g]`すべての順序付けされたペアを同じキーに集中させると、積は隠れた衝突のない有効なペア選択の完全な外積になります。 

もう 1 つのエッジ ケースは、配列に異なる素数のみが含まれる場合です。 次に、gcd ペアはほとんどが 1 に崩壊しますが、lcm ペアはほとんどがペアごとの積になります。 除数ベースの構造により、互換性のある値のみが最終的な合計に残り、無関係な値間の誤った一致が防止されます。
