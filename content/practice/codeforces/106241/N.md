 ## 問題の理解

 単一の整数が与えられます$x$、そしてそれを 3 つの正の整数の完全平方に分割できるかどうかを知りたいのです。 言い換えれば、整数を見つけようとしているのです$a, b, c \ge 1$それらの平方和が正確に一致するように、$x$という追加の制約があります。$a \le b \le c$同じトリプルを異なる順序でカウントすることを避けるためだけです。 

出力は、そのようなトリプルが少なくとも 1 つ存在するかどうかという単純な二者決定です。 

入力サイズが到達しました$10^8$これにより、実行可能なソリューションの構造について重要なことがすぐにわかります。 の平方根$10^8$は$10^4$したがって、すべての可能な値を含む直接推論は、$a, b, c$およそのサイズの検索空間に住んでいます$10^4$。 単純な 3 つのネストされたループ ソリューションでは、次の順序で試行します。$10^{12}$これは実際の限界をはるかに超えています。 Even a double loop of size$10^4 \times 10^4$与える$10^8$これは Python では限界に達していますが、厳密な実装と早期のプルーニングを行えば、依然として許容できる可能性があります。 

明らかではない問題は、サイズだけではなく、順序の制約にもあります$a \le b \le c$。 順序を無視する不用意なアプローチは過剰にカウントしますが、存在チェックとしては正しいものです。 むしろ、本当のリスクは、平方チェック ステップのパフォーマンスと正確さです。 

微妙なエッジケースが現れるのは、$x$小さいです。 例えば、$x = 2$。 2 を 3 つの正の平方の和として表す方法はないため、答えは NO でなければなりません。 ゼロを許可する単純な実装では、次のようなケースが誤って受け入れられます。$1^2 + 1^2 + 0^2 = 2$, しかし、問題ではゼロが明示的に禁止されているため、このショートカットは無効です。 

もう 1 つのエッジケースは次のような場合です$x < 3$。 可能な最小の合計は$1^2 + 1^2 + 1^2 = 3$、そのような入力はすべて直ちに NO を返さなければなりません。 明示的または暗黙的にポジティブ性を尊重しないアルゴリズムはここで失敗します。 

## アプローチ

 最も直接的なアイデアは、可能なすべてのトリプルを試すことです$(a, b, c)$。 各変数は最大で$10^4$、これは約につながります$10^{12}$組み合わせ。 を使って剪定しても$a \le b \le c$、大きさのオーダーは立方体のままです。$10^4$完全に不可能な範囲です。 

最初の改善は、2 つの変数を修正し、3 番目の変数を計算することです。 私たちが選ぶなら$a$そして$b$、 それから$c^2$次のように一意に決定されます$x - a^2 - b^2$。 これにより、問題は、この値が完全な二乗であるかどうか、および結果として次の値が得られるかどうかを確認するだけになります。$c$順序制約を尊重します$c \ge b$。 

重要な観察は、事前に計算された二乗または整数平方根検証を使用して、完全二乗のチェックを一定時間で実行できることです。 これにより、問題が 3 次元から 2 つのネストされたループに減り、複雑さが約$10^8$最悪の場合のオペレーション。 これは大きいですが、特に残りの合計が負になると多くの反復が早期に終了するため、厳密な制約の下で最適化された Python では許容されます。 

ブルート フォースはすべての有効な構成を直接探索するため機能しますが、トリプルの組み合わせの爆発が大きくなりすぎると失敗します。 2 つの値が固定されると、3 番目の値はもはや選択肢ではなく決定的な値となり、検索空間が崩壊するため、この改善は機能します。

 ## アルゴリズムのチュートリアル

 考えられる値を列挙することで作業します。$a$そして$b$、と推測します$c$残りの金額から。 

1. 反復処理によりすべての平方を暗黙的に計算します。$a$1から$\lfloor \sqrt{x} \rfloor$。 より大きい正方形であればこれで十分です。$x$合計の一部にすることはできません。 
2. 固定ごとに$a$、反復します$b$から$a$上向きにしながら$a^2 + b^2 \le x$。 この順序により強制されるのは、$a \le b \le c$この段階では追加のチェックは行われません。 
3. ペアごとに$(a, b)$、残りの値を計算します$r = x - a^2 - b^2$。 もし$r < 0$、増加が止まります$b$それ以上の値は合計を増加させるだけであるためです。 
4. かどうかを確認します。$r$は完全な正方形です。 私たちは計算します$c = \lfloor \sqrt{r} \rfloor$そして検証してください$c^2 = r$。 
5. もし$c$有効です。チェックして注文してください。$c \ge b$。 これが当てはまる場合、有効なトリプルが存在すると直ちに結論付けられます。 
6. 有効なペアが生成されない場合$c$の場合は「NO」を返します。 

重要な設計上の選択は、計算のみを行うということです。$c$方程式から計算するのではなく、決して列挙しないでください。 これにより、検索空間の 1 つの完全な次元が削除されます。 

### なぜ効果があるのか

 このアルゴリズムは、チェックされたすべての状態が、次のような固有の順序付きトリプル候補に対応するという不変条件を保持します。$a \le b \le c$。 すべての有効なソリューションは、ペアとして 1 回だけ出現する必要があります$(a, b)$なぜなら$c$は方程式によって一意に決まります。 ループの順序付けにより、有効なペアがスキップされないことが保証され、二乗チェックにより再構成の正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    x = int(input().strip())

    if x < 3:
        print("NO")
        return

    import math

    limit = int(math.isqrt(x))

    for a in range(1, limit + 1):
        a2 = a * a
        if a2 > x:
            break

        for b in range(a, limit + 1):
            s = a2 + b * b
            if s > x:
                break

            r = x - s
            c = int(math.isqrt(r))
            if c < b:
                continue
            if c * c == r:
                print("YES")
                return

    print("NO")

if __name__ == "__main__":
    main()
```コードはアルゴリズムの構造に正確に従っています。 外側のループは修正されます$a$、内側のループが修正されます$b$、部分和が超過した場合に早期停止します。$x$。 残りの値は、整数の平方根を使用して完全二乗としてテストされます。 

微妙な点は注文チェックです`c < b`。 これがなければ、アルゴリズムは正しい分解を見つけますが、制約に違反する可能性があります。$a \le b \le c$、特に計算された場合$c$よりも小さいです$b$。 この条件により、有効な順序付きトリプルのみを受け入れることが保証されます。 

使用する`math.isqrt`を使用した場合に発生する可能性のある浮動小数点精度の問題を回避します。`sqrt`浮動小数点演算から。
