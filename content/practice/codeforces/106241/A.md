 ## 解決策
 ## 問題の理解

 同じ長さの 2 つの配列が与えられます。 すべての位置で、最初の配列の値を、その値の gcd と 2 番目の配列の対応する値で置き換えることによって、オプションで「アップグレード」することができます。 これを位置 i で実行すると、i にのみ依存する固定コストがかかります。 

この置換を適用するかどうかをインデックスごとに個別に選択すると、新しい配列が作成されます。 目標は、選択した置換に対して可能な限り最小限の総コストを支払いながら、この最終的な配列内のすべての数値の gcd を 1 に等しくすることです。 

重要なのは、すべてのインデックスが常に最終配列に存在することですが、各インデックスは元の値、または gcd 操作を通じて取得される潜在的に小さい値のいずれかに寄与するということです。 タスクは、全体の gcd が 1 になるように、gcd 換算値を使用するためにどのインデックスを「アクティブ化」する必要があるかを決定することです。 

この制約では、最大 5000 のポジションと最大 10¹² の値が許可されます。 これにより、可能性が 2⁵⁰⁰⁰ あるため、インデックスのサブセットを直接列挙しようとするアプローチは即座に除外されます。 すべてのサブセットの二次検査さえ不可能です。 実行可能なソリューションでは、中間結果を再利用し、gcd 構造を最初から繰り返し再計算することを避ける必要があります。 

元の配列にすでに gcd 1 があるにもかかわらず、誰かが依然として不必要な操作を適用している場合、微妙な失敗のケースが発生します。 たとえば、 a にすでに gcd 1 がある場合、演算を適用すると gcd 1 は維持されるものの、コストが増加するだけであっても、答えは 0 になるはずです。 

もう 1 つの重要な例外ケースは、gcd 1 の達成が構造的に不可能な場合です。 これは、すべてのインデックスで到達可能なすべての値が共通の素因数を共有する場合に発生します。 たとえば、すべての i について a[i] と gcd(a[i], b[i]) の両方が偶数である場合、考えられるすべての最終構成は偶数のままであるため、gcd が 1 になることはあり得ません。そのような場合、答えは -1 でなければなりません。 

## アプローチ

 ブルートフォースの見方は簡単です。インデックスごとに、a[i] を保持するか、gcd(a[i], b[i]) に置き換えるかを決定します。 これにより、2 つの可能な構成が作成されます。 構成ごとに、選択されたすべての値の gcd を計算し、gcd が 1 に等しい値の中での最小コストを追跡します。これは有効な選択肢をすべて網羅するので正しいですが、指数関数的に拡大し、n = 30 の場合でも実行不可能になります。 

重要な観察は、問題の構造が完全に gcd 遷移によって駆動されるということです。 選択した値のプレフィックスの gcd がわかったら、新しい要素を追加すると、2 つの可能な値のうちの 1 つを gcd に取ることによって状態が変更されるだけです。 これは、サブセットを明示的に追跡する必要はなく、サブセットに到達するために必要な最小コストとともに発生する可能性のある gcd 値のみを追跡する必要があることを意味します。 

これにより、問題は位置に関する動的プログラミング プロセスに変わります。各状態は、処理されたプレフィックスの可能な gcd を表し、その gcd を達成するために必要な最小コストが維持されます。 各インデックスは、既存のすべての状態を 2 つの遷移に分岐します。1 つは a[i] を使用し、もう 1 つは gcd(a[i], b[i]) を使用します。 

gcd 値は急速に縮小し、多くの異なる状態が同じ gcd にマージされるため、理論上は定数によって厳密に制限されませんが、実際には個別の状態の数は管理可能なままです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | サブセットに対するブルート フォース | O(2ⁿ・n) | O(n) | 遅すぎる |
 | gcd ステート上の DP | O(n · S · log A) | O(S) | 承認済み |

 ここで、S は DP 中に現れる個別の gcd 状態の数です。 

## アルゴリズムのチュートリアル

 処理されたプレフィックスを使用して、gcd 値をその値を達成するために必要な最小コストにマップする辞書を維持しながら、インデックスを左から右に処理します。

1. 空の状態から開始します。 インデックス 1 では、2 つの可能性を直接初期化します。コスト 0 の a[1] を保持するか、コスト 1² + 1 を支払う gcd(a[1], b[1]) に置き換えます。これらのそれぞれで、長さ 1 のプレフィックスの gcd 状態が作成されます。 
2. 後続のインデックス i ごとに、新しい状態マップを構築します。 以前に到達可能なすべての gcd 値 g について、2 つの拡張を考慮します。 1 つの拡張機能は a[i] を保持し、追加コストなしで新しい gcd g₁ = gcd(g, a[i]) を生成します。 もう 1 つは演算を適用し、g₂ = gcd(g, gcd(a[i], b[i])) を生成し、i² + i をコストに加算します。 
3. 複数の方法で同じ結果の gcd が生成される場合、それらの中で最小のコストのみが維持されます。 多くの異なるパスが同じ gcd 値に集約されるため、このマージは不可欠です。 
4. すべてのインデックスを処理した後、gcd 値 1 が最終状態マップに存在するかどうかを確認します。 存在する場合、その保存コストが答えになります。 そうでない場合、gcd 1 への変換は不可能です。 

これが機能する理由は、DP 状態がすべてのステップで、gcd 値とそれを達成するための最小コストのみを使用して、関連するすべての決定履歴を完全に要約するためです。 次の遷移は gcd の演算のみに依存し、gcd がどのように形成されたかには依存しないため、同じ gcd をもたらす 2 つの異なる選択シーケンスは将来の決定のために交換可能です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    
    dp = {}  # gcd -> min cost
    
    for i in range(n):
        cost = i * i + i
        bi = b[i]
        ai = a[i]
        gbi = gcd(ai, bi)
        
        new_dp = {}
        
        if not dp:
            new_dp[ai] = 0
            new_dp[gbi] = min(new_dp.get(gbi, 10**30), cost)
        else:
            for g, c in dp.items():
                ng1 = gcd(g, ai)
                nc1 = c
                if ng1 not in new_dp or nc1 < new_dp[ng1]:
                    new_dp[ng1] = nc1
                
                ng2 = gcd(g, gbi)
                nc2 = c + cost
                if ng2 not in new_dp or nc2 < new_dp[ng2]:
                    new_dp[ng2] = nc2
        
        dp = new_dp
    
    if 1 in dp:
        print(dp[1])
    else:
        print(-1)

def gcd(x, y):
    while y:
        x, y = y, x % y
    return x

if __name__ == "__main__":
    solve()
```このコードは、到達可能な gcd 状態のローリング辞書を維持します。 各反復では、現在のプレフィックスの状態空間が再構築されます。 gcd 関数は、最大 10¹² の大きな値でのパフォーマンスと明確さのために手動で実装されます。 遷移では、a[i] の保持と演算の適用が慎重に区別され、後者ではインデックス ベースの 2 次コストが発生します。 

実装でよくある落とし穴は、状態を最小限のコストでマージする必要があることを忘れていることです。 これがないと、状態空間が爆発し、支配的な遷移が持続するため、不正確な結果が生成されます。 

## 実用的な例

 ### 例 1

 いくつかのインデックスがすでに gcd を削減するように調整されている小さな入力を考えてみましょう。 

| 私 | 前の dp | アクション | 新しいgcd | コスト |
 | --- | --- | --- | --- | --- |
 | 1 | ∅ | a[1]=6 を取る | 6 | 0 |
 | 1 | ∅ | gcd(6,10)=2 を取る | 2 | 2 |
 | 2 | {6:0,2:2} | から 6 キープ 7 | 1 | 0 |
 | 2 | {6:0,2:2} | 6 から gcd(7,30)=1 を取る | 1 | 6 |
 | 2 | {6:0,2:2} | 2から7をキープ | 1 | 2 |
 | 2 | {6:0,2:2} | 2 から gcd(7,30)=1 を取る | 1 | 8 |

 最終的な dp には、最小コスト 6 の gcd 1 が含まれます。 

このトレースは、さまざまなパスが同じ gcd 状態にどのように崩壊し、最も安価なパスのみが生き残るかを示しています。 

### 例 2

 新しい素因数を導入できる演算がない入力:

 | 私 | dp 状態 | 説明 |
 | --- | --- | --- |
 | 1 | {4:0、2:2} | 偶数の値のみが存在します |
 | 2 | {4:0,2:2} | どの選択をしても gcd は均等のままです。 

どの状態も 1 に到達しないため、答えは -1 になります。 これにより、明示的な因子分析を必要とせずに、DP が不可能性を正しく捉えていることが確認されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n · S · log A) | 各状態遷移はインデックスごとに 2 回行われ、各遷移で gcd | が計算されます。 
| スペース | O(S) | 現在と次の dp マップのみが保存されます。 

gcd 値は急速に収束し、結合するため、実際には状態 S の数は小さいままです。 n は最大 5000 なので、時間制限内に問題なく収まります。

 ## 特殊なケース

 エッジ ケースの 1 つは、初期配列にすでに gcd 1 がある場合です。DP には、演算を適用せずに gcd 1 に到達できる状態がすぐに含まれます。そのため、アルゴリズムが不必要な遷移を強制しないため、最小コストは自然に 0 になります。 

もう 1 つのエッジ ケースは、異なるインデックスで演算を適用すると同じ gcd が得られるが、コストが異なる場合です。 DP はこれらの状態をマージして最小限のコストのみを保持し、後の高価なパスが安価な同等の構成を上書きするのを防ぎます。 

最後のエッジケースは、到達可能なすべての値が共通の素数で割り切れる場合です。 その状況では、すべての dp 状態には常にその素因数があるため、gcd 1 がマップに現れることはありません。 許可された一連の変換が共有除数構造を壊すことができないため、アルゴリズムは正しく -1 を返します。
