 ## 解決策
 ## 問題の理解

 1 から n までの整数の順列を構築するように求められます。 この順列のすべての部分配列について、その内部の数値の広がりに応じた値を計算します。 具体的には、セグメント p[i..j] の場合、そのセグメントの最大値を取得し、最小値を減算し、セグメントの長さを減算します。 これにより生じるコストは、値が密に詰め込まれており、セグメントが短い場合には小さくなり、セグメントが長い場合や値のギャップが大きい場合には大きくなります。 

順列の合計スコアは、すべての可能なサブ配列にわたるこのコストの合計です。 タスクは、この合計スコアを最小化する順列を見つけることです。 可能な最小スコアを達成するすべての順列の中で、辞書編集的に最大のものを出力する必要があります。 

この制約により、n は最大 200,000 まで許可されるため、すべての部分配列を明示的に評価しようとする解決策は直ちに不可能になります。 サブ配列の数は 2 次であり、サブ配列ごとの最小値と最大値を計算しても 3 次の動作になります。 

微妙な点は、順列は常に 1 から n であるため、目的は値の絶対的な同一性ではなく、値の相対的な順序にのみ依存することです。 もう 1 つの重要な観察は、すべてのサブ配列が最大値と最小値の両方を含む項に寄与していることです。これは、多くのセグメントで極値となる要素がコストに大きな影響を与えることを示唆しています。 

単純なアプローチでは、すべての部分配列の寄与を追跡しながら、ローカルで推論したり、要素を貪欲に選択しようとしたりしますが、値を挿入すると、その位置を横切るすべてのセグメントが非常に非ローカルな方法で影響を受けるため、そのようなアプローチは通常失敗します。 

小さな例で感度を強調します。 n = 3 の場合、並べ替え 1 2 3 と 3 2 1 は、中央の要素によって小さい範囲を持つセグメントの数が決定されるため、動作が異なります。 グローバル パターンを持たずに常に小さい値または大きい値を端に配置する貪欲な場合、真の最適な構造を簡単に見逃してしまう可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、すべての順列が生成され、それぞれの合計コストが計算されます。 たとえ O(n^2) の単一の置換のコストを計算する効率的な方法があったとしても、置換の数は n! であり、これは完全に実行不可能です。 1 つの順列の評価に限定しても、すべての O(n^2) 個の部分配列を反復処理する必要があり、最小値と最大値を単純に計算すると、部分配列ごとに O(n) が得られ、合計作業量は O(n^3) になります。 

どのような順列構造が全体の寄与を減らすのかを理解する必要があります。 セグメントのコストは最大値と最小値によって決まります。 セグメントの順列に連続する整数がある場合、その範囲は狭くなり、コストが削減されます。 これは、連続したセグメント内での大きなジャンプを避け、代わりに制御された方法で極端な値が分離されるように値を配置する必要があることを示唆しています。 

重要な変換は、要素の各ペアが部分配列全体で最大値または最小値になる頻度にどの程度寄与するかという観点から問題を書き直すことです。 式 max マイナス min は、セグメント内で 1 つの要素が最大となり、もう 1 つの要素が最小となるペアの寄与として解釈できます。 負の長さの項により、セグメントが短くなり、全体的なペナルティが軽減されます。 

出現する構造は、最大の要素を最初または最後に配置し、順列を可能な限り「中心」に保つ方法で外側に向かって再帰的に埋めていくことによって、最適な順列が構築されるというものです。 ただし、最適解の中の辞書編集上の最大値も必要であるため、対称性が許す限り、より大きな要素をより早く配置することを好みます。

これは建設的なパターンにつながります。つまり、辞書編集上の最大性を満たすために、より前の位置に偏りながら、常に最大の残りの数値を選択し、最適なバランスを保つ位置にそれを配置して、両端から内側に順列を構築します。 

最適な構成は、寄与の対称性の下で分析すると、単純な減少シーケンスであることがわかります。これは、大きい値の前に小さい値を配置する偏差があると、最大値と最小値が大きくなる追加のサブ配列が作成される傾向があり、長さの短縮によって十分に補償されないためです。 

したがって、解決策は、n から 1 までの番号を順番に並べることになります。

 | --- | --- | --- | --- |
 | ブルートフォース | O(n! · n²) | O(n) | 遅すぎる |
 | 最適な施工 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 順列を直接構築します。 

1. サイズ n の空のリスト p を初期化します。 これにより、最終的な順列が保存されます。 
2. 最大値 n から開始して 1 まで下方向に移動します。 
3. n から 1 までの値 x ごとに、x を p に追加します。 

これにより、より大きな値が順列の前半に配置されます。これは、最適なソリューション間の辞書編集順序を最大化するために必要です。 
4. 作成したリストを出力します。 

この単純な構成で十分である理由は、別の配置では、範囲が不必要に拡大するサブアレイの数が増加する形で、小さい値が大きい値に先行するインデックスのペアが導入されるためです。 降順では、大きな値が前面に集中し、値が徐々に小さくなるにつれて可能な範囲が狭くなるだけであるため、両極端が大きく離れて見えるセグメントの作成が最小限に抑えられます。 

### なぜ効果があるのか

 重要な不変条件は、順列の最初の k 要素を n、n−1、…、n−k+1 として配置した後、この接頭辞内で始まるすべての部分配列の最大値が、その部分配列の最初の要素によって即座に決定されるということです。 これにより、多くのセグメントにわたる max の寄与が安定し、配列内の後の大きな要素の前に小さな要素が出現した場合に生じるさらなる変動を防ぎます。 

i < j であるが p[i] < p[j] の形式を反転すると、最大値が左境界で局所的に決定されない追加の部分配列が作成され、多くのセグメントにわたる最大値と最小値の変動が増加します。 降順配置では、このような反転が完全に排除され、すべてのプレフィックスベースの最大値が単調になり、全体的な拡散の寄与が最小限に抑えられます。 

この構造は、最適な構成における対称性までユニークであるため、辞書編集的にはすべての最適解の中で最大になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    res = list(range(n, 0, -1))
    print(*res)

if __name__ == "__main__":
    solve()
```実装では、逆の順序で順列を直接構築します。 唯一重要な詳細は、スペースを含む正しい書式設定を保証することと、ステップ -1 で Python の範囲を使用することにより、off-by-one エラーを回避することです。 

インクリメンタルな構造を構築するのではなく、すぐに印刷するという決定により、不必要なオーバーヘッドが回避されます。 順列は決定的であるため、追加のデータ構造は必要ありません。 

## 実用的な例

 ### 例 1: n = 3

 シーケンスを段階的に構築していきます。 

| ステップ | 現在の x | 順列 |
 | --- | --- | --- |
 | 1 | 3 | 3 |
 | 2 | 2 | 3 2 |
 | 3 | 1 | 3 2 1 |

 最終出力は 3 2 1 です。これは、この構造が一貫して最大の残りの要素を最初に追加することを確認します。 

この例は、順列が曖昧さのない厳密に減少する構造を構築し、候補間で辞書編集的に最大の順序付けを保証する方法を示しています。

トレースは、並べ替えの決定が必要ないことを強調しています。これは、構築に局所的なトレードオフがないことと一致しています。

 ## 特殊なケース

 主なエッジ ケースは n = 1 です。このアルゴリズムは単一要素の置換 [1] を生成しますが、これには当然のことながら 1 を超える長さの部分配列がないため、すべてのコスト項は 0 になります。 これは最適性と一致します。 

n = 2 の場合、アルゴリズムは 2 1 を生成します。部分配列は [2]、[1]、および [2,1] のみです。 降順により、長さ 2 のセグメントのみが最大値と最小値が 1 に等しいことが保証され、構造の不均衡を増大させることなく辞書編集上の順序を改善できる代替の並べ替えはありません。 

少し自明ではないケースは n = 3 です。このアルゴリズムは 3 2 1 を生成します。反転のない構造により、すべてのプレフィックスが安定した最大値を持つことが保証され、より大きな辞書編集上のペナルティを導入することなく代替の置換によって寄与を減らすことができず、最小の非対称複数要素のケースでも正確性が確認されます。
