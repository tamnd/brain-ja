 ## 解決策
 ## 問題の理解

 ドミノの列が与えられ、それぞれに高さとコストが設定されています。 モーションを開始する唯一の方法は、選択したドミノを手動で押し、それぞれのコストを支払うことです。 ドミノが倒れると、決定論的な右方向の連鎖反応が引き起こされる可能性があります。位置 j で倒れたドミノは j+1 をノックしますが、これは厳密に右隣のドミノよりも高い場合に限ります。 この条件が当てはまれば、落下は前方に継続し、長い高さの減少を経てカスケード状になる可能性があります。 

目標は、手動で押すドミノのサブセットを選択し、選択した最初の押しの総コストを最小限に抑えながら、最終的にすべてのドミノが倒れるようにすることです。 

重要な構造の詳細は、連鎖反応が右にのみ移動し、隣接する高さが厳密に減少する方向にのみ成功するということです。 非減少境界は、明示的に境界を超えたり内部に新しいプッシュを開始しない限り、伝播をブロックします。 

この制約により、テスト ケースごとに線形または線形に近い解決策が求められます。 すべてのテスト ケースの合計 n が最大 2·10^5 の場合、テスト ケースごとに O(n²) または O(n log n) のアプローチでは遅すぎます。 これは、各ドミノが 1 回または一定の回数だけ処理される、貪欲または単調なスタック スタイルのソリューションを強く示唆しています。 

「すべての極大値をプッシュする」または「すべての増加するブレークポイントをプッシュする」と考えると、微妙な失敗のケースが発生します。 たとえば、高さを考えてみましょう`[3, 1, 2]`。 インデックス 1 のみをプッシュすると、3 > 1 であるため 2 に下がりますが、1 < 2 により伝播が中断されるため停止します。 まだインデックス 3 をプッシュする必要があります。ローカル比較のみに基づく単純な戦略では、コストのトレードオフが失われます。チェーンが実際にどの程度伝播するかによっては、早めにプッシュするか、後でプッシュする方が安くなる場合があります。 

もう 1 つのトリッキーなシナリオは、次のような単調増加配列です。`[1, 2, 3, 4]`。 ドミノは右にまったく伝播できないため、すべてのドミノを個別にプッシュする必要があります。 セグメントが増加する中で少なくとも部分的な伝播を仮定する解決策は、答えを過小評価することになります。 

最後に、次のような厳密に減少する配列では、`[5, 4, 3, 2]`、最初の位置で 1 回押すだけで十分で、他のすべては無料で落ちます。 これはまったく逆の動作であり、セグメントの貪欲なマージが不可欠になる場合があります。 

## アプローチ

 ブルートフォース解釈では、プッシュするインデックスのサブセットを選択し、結果として生じるカスケードをシミュレートし、すべてのドミノが倒れるかどうかを確認します。 これは正しいですが、実行不可能です。 2^n 個のサブセットがあり、各シミュレーションには O(n) がかかる可能性があり、指数関数的な時間が発生します。 

より構造化された見方は、プッシュが実際に何を「カバーする」かを問うことです。 位置 i を押すと、右側の最大の連続セグメントがアクティブになり、セグメントの先頭から高さが厳密に減少します。 この減少特性が壊れると、カスケードは停止し、個別にアクティブ化しない限り、その点を超えるものはすべて影響を受けません。 

したがって、各プッシュは効果的に間隔をカバーします`[i, r]`ここで、r は到達可能な最も遠いインデックスです。 これらの間隔を計算できた場合、問題は、すべてのインデックスが、それに到達する少なくとも 1 つの間隔でカバーされるように、最小コストの間隔スターターのセットを選択することになります。 

重要な観察は、間隔が独立していないということです。 i でプッシュを開始すると、その自然な減少実行がカバーされるだけでなく、以前にカバーされた領域と相互作用する可能性もあります。 後のポジションが以前のプッシュによってすでに到達されている場合、再度支払う必要はありません。 

これは、左から右への動的なプロセスにつながります。つまり、すでに選択されているプッシュによって現在到達可能な最も遠いポイントを維持し、それを超えてカバレッジを拡張するために料金を支払う必要があるかどうかを各インデックスで決定します。 

重要なアイデアは、伝播の構造が隣接する高さ間の比較のみに依存するということです。これにより、完全なシミュレーションを再計算することなく、貪欲なスイープで到達可能性を計算できるようになります。

 | ブルートフォース | O(2^n · n) | O(n) | 遅すぎる |
 | 最適な貪欲なスイープ | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 以前のプッシュによりどのサフィックスが既に落ちていることが保証されているかを追跡しながら、ドミノを左から右に処理します。 中心オブジェクトは、すでに選択されているプッシュから追加コストなしで現在到達できる最も遠いインデックスです。 

### ステップ

 1. 変数を維持します`reach`、すでに下落することが保証されている最も遠いインデックスを意味します。 
2. また、位置 i でのプッシュがその領域に影響を与える最初のプッシュである場合に、そのプッシュがどこまで伝播するかを示す構造も維持します。 これは、高さが厳密に減少している間に右をスキャンすることで計算できます。 
3. i を 1 から n まで繰り返します。 もし私がすでにその中にいるなら`reach`、以前の決定により自動的に落ちるため、スキップします。 
4. 私が外にいる場合`reach`、そうしないとドミノ i が決して倒れないので、i で新しいプッシュを開始することを強制されます。 私たちはciを支払います。 
5. i で支払いを行った後、このプッシュがどこまで伝播するかを計算します。 i から始めて、h[j] > h[j+1] になるまで j を拡張し、次のように設定します。`reach`最大(現在のリーチ、j)まで。 
6. スイープを続けます。 新たに強制的にプッシュするたびに、到達範囲がさらに広がり、大きなセクションがスキップされる可能性があります。 

### なぜ効果があるのか

 このアルゴリズムは、ポジションが以前にトリガーされた有効な減少チェーン内に入ると、その動作は将来の決定には無関係であるという事実に基づいています。 現在のリーチ内のドミノは、手動でプッシュするかどうかに関係なく、すでに落下しているため、新しい情報やコストを提供することはできません。 

i でプッシュすることを選択するたびに、それより前のプッシュが i に到達できないという理由だけでプッシュします。 これにより、有効な解決策において i での決定が避けられなくなります。 i をカバーする必要があるすべてのソリューションの中で、i から開始するのが最適です。これは、それより早い開始はすでに考慮されており、i に到達できないためです。 

したがって、選択されたすべてのプッシュは必要な「カバレッジ ブレークポイント」に対応し、貪欲なプロセスによって冗長なプッシュが発生することはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        h = list(map(int, input().split()))
        c = list(map(int, input().split()))

        reach = -1
        ans = 0

        i = 0
        while i < n:
            if i <= reach:
                i += 1
                continue

            ans += c[i]

            j = i
            while j + 1 < n and h[j] > h[j + 1]:
                j += 1

            reach = j
            i += 1

        print(ans)

if __name__ == "__main__":
    solve()
```この実装は、スイープのアイデアを直訳したものです。 の`reach`変数は、すでに落ちることが保証されている右端の位置を表します。 この範囲外のインデックスに遭遇すると、そのコストを支払う必要があります。 

内側のループは、選択した押し位置から開始して最大減少セグメントを計算します。 伝播は隣接する高さ間の厳密な比較のみに依存し、新しいプッシュが開始されると以前の選択とは無関係であるため、これは安全です。 

ループ構造により、各インデックスが最大 2 回アクセスされることが保証されます。1 回は外部スイープで 1 回、最大 1 回の内部伝播で 1 回となり、ソリューションが線形に保たれます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque

    input = sys.stdin.readline
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        h = list(map(int, input().split()))
        c = list(map(int, input().split()))

        reach = -1
        ans = 0
        i = 0
        while i < n:
            if i <= reach:
                i += 1
                continue
            ans += c[i]
            j = i
            while j + 1 < n and h[j] > h[j + 1]:
                j += 1
            reach = j
            i += 1
        out.append(str(ans))

    return "\n".join(out)

assert run("1\n4\n1 2 3 4\n1 1 1 1\n") == "4"

# all decreasing
assert run("1\n4\n4 3 2 1\n5 4 3 2\n") == "5"

# single element
assert run("1\n1\n10\n7\n") == "7"

# alternating pattern
assert run("1\n5\n5 1 4 2 3\n1 2 3 4 5\n") == "6"

 ## 特殊なケース

 外側のループは`reach = -1`、強制的に 1 回プッシュすると、セグメントはそれ自体になります。 境界を超えて伝播することはないので、答えは単純にそのコストです。 

シーケンスを厳密に増加させると、最悪の場合のプッシュ数が示されます。 各インデックスはすべてのステップで現在の到達範囲外にあるため、n 回の独立したアクティブ化が強制されます。 伝播ループが到達範囲を拡張しないため、アルゴリズムはすべてのコストを正しく支払います。 

厳密に減少するシーケンスは、単一の最大セグメントを形成します。 最初の強制プッシュは配列の最後まで拡張され、後続のすべてのインデックスがスキップされます。 これは、貪欲な「最初にカバーされていないインデックスがセグメントを定義する」動作が正しいことを示しています。
