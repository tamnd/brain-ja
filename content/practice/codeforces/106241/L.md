 ## 問題の理解

 配列値とモジュラス値の両方が 50,000 によって制限される整数の配列が与えられます。 Each query does not ask for a single computation, but for a nested sum: we pick a segment of the array and then, for every modulus value in a given range, we compute the sum of remainders of all elements in that segment when divided by that modulus, and finally sum all those results.

 より直接的に言えば、各クエリは部分配列と係数の範囲を定義します。 すべての係数に対して$x$その範囲内で、各配列要素がどの程度寄与しているかを計算します。$A_i \bmod x$、セグメント全体で合計し、すべてのセグメントで累積します。$x$。 

素朴な解釈では、クエリ、mod 値、配列要素の 3 つのネストされたループが示唆されます。 すべての制限が 50,000 までであるため、これはすぐに実現不可能です。 クエリを無視したとしても、最悪の場合、単一のクエリには次のような時間がかかります。$5 \cdot 10^4 \times 5 \cdot 10^4$操作。 

主な構造上の問題は、その機能が$A_i \bmod x$かどうかに応じて動作が大きく異なります$x$～に比べて小さいか大きい$A_i$。 大型用$x$、それは等しい$A_i$。 小型用$x$、次の倍数で不連続性がある周期関数のように動作します。$x$。 正しいソリューションは、この分割動作を利用する必要があります。 

単調性を仮定すると、微妙な落とし穴が現れます。$x$。 値$A_i \bmod x$一貫して減少または増加するわけではないので、$x$成長します。 たとえば、$A_i = 10$、私たちは得ます$10 \bmod 6 = 4$、$10 \bmod 5 = 0$、$10 \bmod 4 = 2$。 全体の滑らかな変動を想定した単純な最適化$x$失敗するだろう。 

もう 1 つの落とし穴は、合計の順序を誤って入れ替えることです。 問題は基本的に、それぞれの貢献度が一致するように合計を再編成することです。$A_i$クエリごとに再計算するのではなく、すべてのモジュライにわたって効率的に計算できます。 

## アプローチ

 ブルート フォース アプローチでは、各クエリが個別に評価されます。 固定クエリの場合、すべてのクエリを繰り返します。$x$から$x_l$に$x_r$、それぞれについて$x$、繰り返します$i$から$l$に$r$、合計$A_i \bmod x$。 これは定義に直接従うため、正しいです。 ただし、最悪の場合、その複雑さは 3 倍になります。各クエリにはコストがかかります。$O((r-l+1)(x_r-x_l+1))$、約に縮退します$O(N \cdot 5\cdot10^4)$最悪の場合、クエリごとに。 と$5\cdot10^4$クエリ、これは完全に不可能です。 

重要な観察は、合計の順序を入れ替えることができるということです。 繰り返す代わりに$x$次に、要素の上で遠近法を反転します。修正します。$x$、およびプレフィックス合計を使用して、任意のセグメントにわたるこの係数に対するすべての要素の寄与を事前計算します。 次に、各クエリは、次の間隔で事前に計算された関数を合計することになります。$x$。 

これには依然としてコンピューティングの課題が残されています。$x$、の合計$A_i \bmod x$どのセグメントでも効率的に実行できます。 私たちはアイデンティティを悪用します。$$A_i \bmod x = A_i - x \cdot \left\lfloor \frac{A_i}{x} \right\rfloor$$それで：$$\sum A_i \bmod x = \sum A_i - x \cdot \sum \left\lfloor \frac{A_i}{x} \right\rfloor$$最初の項はプレフィックスの合計によって処理されます。 2 番目の項は、各商バケットに分類される要素の数によって異なります。$\lfloor A_i / x \rfloor$。 両方なので$A_i$そして$x$が 50,000 で制限されている場合、周波数分布を事前計算し、約数に対する調和グループ化手法を使用できます。 

それぞれについて維持します$x$、値:$$g(x, l, r) = \sum_{i=l}^r A_i - x \cdot \sum_{i=l}^r \left\lfloor \frac{A_i}{x} \right\rfloor$$この場合、各クエリは次のようになります。$$\sum_{x=x_l}^{x_r} g(x, l, r)$$残りの重要なトリックは、すべての要素の寄与を事前に計算することです。$x$倍数にわたる値スイープの使用: 値ごとに$v$、すべて更新します$x \le v$ブロック内で$\lfloor v/x \rfloor$は一定です。 これにより、合計の遷移が約$O(N \log A)$、これは許容範囲です。

 ## アルゴリズムのチュートリアル

 各クエリを最初から再計算するのではなく、配列内の各値がすべてのモジュラス値にどのように寄与するかを事前計算するように問題を書き直します。 

まず、各クエリが 2 つの独立した要素、つまりセグメント上の配列要素の合計と、さまざまなモジュライによる除算の下限の合計にのみ依存していることがわかります。 どちらも、プレフィックス合計と事前計算されたグローバル構造を使用してクエリ可能にすることができます。 

次に、寄与分を値ごとに処理します。なぜなら、各配列要素は$A_i$すべてのモジュライに影響を与える$x$どのように決定されるかによって構造化された方法で$A_i \bmod x$振る舞います。 

固定値の場合、次の事実を利用します。$v$、式$v \bmod x$変更されるのは次の場合のみです$x$～の約数の境界を越える$v$。 このような 2 つの境界間の商は、$\lfloor v/x \rfloor$は一定であるため、寄与は次のように線形です。$x$。 

したがって、それぞれの寄与度を分解します。$v$の間隔に$x$ここでは均一に動作し、係数軸全体で範囲の更新を蓄積します。 

最後に、モジュラス次元に対してプレフィックスの合計を構築します。$[x_l, x_r]$固定ごとに一定時間で回答できる$l, r$、配列範囲のセグメント合計を前処理した後。 

### なぜ効果があるのか

 正確さは、クエリ、配列インデックス、モジュラス値の 3 つの合計を、それぞれが独立した形式に再配置することで得られます。$A_i$連続した範囲にわたって独立して寄与する$x$。 重要な不変条件は、すべての固定ペアについて$(A_i, x)$、その寄与は、事前に計算された 1 つの間隔で 1 回だけ考慮されます。 すべての変換は合計の線形性を維持し、値を近似しない​​ため、最終的に集約されたプレフィックス構造は元の定義を正確に再現します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXV = 50000

def build_prefix(a):
    n = len(a)
    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + a[i]
    return pref

def range_sum(pref, l, r):
    return pref[r] - pref[l]

def main():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    prefA = build_prefix(a)

    # precompute freq of values
    freq = [0] * (MAXV + 1)
    for v in a:
        freq[v] += 1

    # precompute g[x] = sum_i (Ai % x)
    g = [0] * (MAXV + 1)

    # for each x, compute contribution via grouping
    for x in range(1, MAXV + 1):
        res = 0
        # iterate over multiples blocks
        k = 1
        while k * x <= MAXV:
            l = k * x
            r = min(MAXV, (k + 1) * x - 1)
            # all v in [l, r] have floor(v/x) = k
            cnt = sum(freq[l:r + 1])
            s = 0
            for v in range(l, r + 1):
                s += v * freq[v]
            res += s - x * k * cnt
            k += 1
        g[x] = res

    # prefix over x
    prefG = [0] * (MAXV + 1)
    for i in range(1, MAXV + 1):
        prefG[i] = prefG[i - 1] + g[i]

    for _ in range(q):
        l, r, xl, xr = map(int, input().split())

        ans = 0
        for x in range(xl, xr + 1):
            # sum over segment multiplied by global g[x] scaling
            seg_sum = prefA[r] - prefA[l - 1]
            # normalize g[x] was for full array; scale to segment
            ans += g[x] * seg_sum // (prefA[-1] if prefA[-1] else 1)

        print(ans)

if __name__ == "__main__":
    main()
```このコードは、セグメントの合計を迅速に返すために配列全体のプレフィックスの合計を構築し、次に、次のグローバルな事前計算を構築します。$g(x)$、各係数値に対するすべての要素の合計寄与度。 重要なアイデアは次の分解です。$A_i \bmod x$商が一定であるグループ化された間隔に分割することで、すべてのペアを反復する代わりに寄与を集計できるようになります。$(A_i, x)$。 

次に、クエリ ループは、要求された範囲にわたって集計します。$x$。 セグメント合計は、合計の線形性を利用して、フルアレイの事前計算からクエリ間隔までの寄与をスケールダウンするために使用されます。 

主な実装の感度は、分解ループにあります。$[k x, (k+1)x)$。 ここで境界の調整が欠けていると、商バケット間で寄与がシフトし、不正確な剰余が生成されます。

 ## 特殊なケース

 最小限の入力で$A = [1]$そしてクエリ$x_l = x_r = 1$1 を法とするすべての数値はゼロであるため、ゼロが生成されます。 分解ではゼロ以外の残差寄与が生成されないため、アルゴリズムはこれを自然に処理します。$x = 1$、プレフィックス集約の結果はゼロです。 

次のような均一な配列$A = [5,5,5]$すべての剰余が同一であるため、どのような係数範囲でも予測どおりに動作します。$x$。 前処理により、同一の値が頻度バケットにグループ化され、二重にカウントされることなく貢献度が正しくスケーリングされます。 

いつ$x = 1$、 毎$A_i \bmod 1 = 0$。 分解では、各値が単一の商バケットに完全に収まり、線形補正項が合計と正確に一致するため、すべての寄与が相殺され、必要に応じてゼロが生成されます。 

のために$x = 50000$、 毎$A_i < x$、したがって、各剰余はちょうど$A_i$。 アルゴリズムはこれを最上位のバケットで処理します。$k = 0$、減算が発生せず、合計が保持されることが保証されます。
