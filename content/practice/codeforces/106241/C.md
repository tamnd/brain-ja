 ## 解決策
 ## 問題の理解

 順列が与えられています`p`サイズの`n`、つまり、次の数字を並べ替えたものです。`1`に`n`。 考えてみましょう`p`インデックスからインデックスへの関数として、どこから位置まで`i`あなたはその位置にジャンプします`p[i]`。 

重要な操作は、順列を左に循環的にシフトすることです。 回転するたびに、すべての要素が 1 ステップ左に移動し、最初の要素が最後に移動します。 元の順列から次の順列までのすべての回転を考慮します。`k-1`シフトします。 

固定順列の場合、「安定したインデックス」を位置として定義します。`i`順列マッピングを使用して 2 回ジャンプすると、次の状態に戻ります。`i`、 意味`p[p[i]] = i`。 順列に対してそのようなインデックスがいくつ存在するかを数えます。`p`で示される`S(p)`。 

タスクは次の合計を計算することです。`S(p)`すべての回転にわたって`rot^0(p), rot^1(p), ..., rot^(k-1)(p)`。 

制約は非常に重要です。`n`までです`2 * 10^5`そして`k`まで可能です`10^9`。 これにより、各回転の値を個別に再計算することが直ちに除外されます。`O(nk)`実現可能性をはるかに超えています。 再計算さえも`S(p)`で`O(n)`回転ごとにそれは不可能です。`2 * 10^14`最悪の場合の運用。 

隠された構造は、回転によって置換の基礎となる相対的なサイクル構造は変更されませんが、インデックスがサイクル位置にどのように整列するかを変更するということです。 答えは、各回転に独立して依存するのではなく、回転全体にわたる周期的な動作に依存します。 

置換が完全に 2 サイクルと固定小数点で構成されている場合、微妙なエッジ ケースが発生します。 たとえば、次の場合`p = [1,2,3]`の場合、すべてのインデックスは安定しており、すべての回転は同一であるため、答えは単純です。`n * k`。 ここでも単純なシミュレーションは機能しますが、その必要はありません。 一方、次のような順列の場合、`[2,3,1]`、回転により安定性パターンが非自明な周期的に変化し、回転ごとの単純な再計算は実行不可能になります。 

もう 1 つのエッジケースは次のような場合です`n = 1`。 単一要素は常に安定しており、答えは正確です`k`。 どのようなソリューションであっても、この基本ケースを複雑にしすぎてはなりません。 

## アプローチ

 まず直接的なアプローチを考えます。 回転ごとに、回転された順列を明示的に構築し、満たすインデックスの数を計算します。`p[p[i]] = i`。 1 つの順列コストを確認する`O(n)`、そして、あります`k`回転するため、総コストは次のようになります。`O(nk)`。 と`k`まで`10^9`、これは不可能です。 

配列の再構築を避け、代わりにインデックスのシフトをシミュレートしようとしても、回転ごとにすべてのインデックスの条件を評価する必要があります。 ボトルネックは、条件が元の順列値だけではなく、回転されたインデックスに依存することです。 

重要な観察は、安定性を順列のサイクルの観点から再解釈することです。 条件`p[p[i]] = i`ということです`i`そして`p[i]`2 段階のクロージャを形成します。これは次の 2 つのケースで発生します。`i`は固定点 (`p[i] = i`）、 または`i`2 サイクルの一部です (`p[i] = j`そして`p[j] = i`）。 したがって、安定したインデックスは、順列グラフの長さ 1 または 2 のサイクルに属するすべての要素です。 

ここで重要な変化があります。ローテーションによってサイクルを形成する値は変わりませんが、値がインデックスに割り当てられる方法が変わります。 配列を回転した後、元の位置にある要素`x`位置に移動します`x - i (mod n)`。 

したがって、問題は、すべての回転にわたって、パートナーを正しく揃える位置にサイクル要素が着地するときの追跡に帰着します。 それぞれの安定した寄与はサイクル内の相対オフセットにのみ依存し、各サイクルは独立して寄与します。 

各サイクルは、一定の長さのリングにわたる周期構造のように動作します。`n`。 サイクルごとに、2 サイクルの両方の要素が安定条件を満たす位置に着地するために、その要素を整列させる回転数を計算します。 これは、モジュラー算術アラインメントの発生を全期間にわたってカウントすることになります。`n`。 

最終結果は、すべてのサイクルの寄与を合計することで得られます。各寄与は、サイクルを 1 回スキャンし、有効なアライメントを生成するシフトの数を累積することによって計算できます。 各インデックスは最大でも 1 つのサイクルに寄与するため、全体の複雑さは線形のままです。

 ## アルゴリズムのチュートリアル

 順列を有向構造に変換し、それをサイクルに分解します。 すべてのインデックスは 1 つのサイクルに属し、各サイクルは独立して処理されます。 

1. まず、訪問した配列を使用して順列サイクルを特定します。 未訪問のインデックスごとに、次のようになります。`p[i]`、最初に戻るまですべての要素を収集します。 これによりサイクルが生まれます`C`。 
2. 各サイクルについて、配列の循環左シフトの下でその要素がどのように動作するかを検討します。 によるローテーション`t`もともとその位置にあった値を意味します`x`の位置に表示されるようになりました`(x - t) mod n`。 これにより、元のインデックスと回転されたインデックスの間に直接の関係が得られます。 
3. We reinterpret the condition`p[p[i]] = i`回転された配列内。 回転ごとにチェックするのではなく、要素を修正して、どのシフトについて尋ねます。`t`この要素は安定しますか？ これにより、問題は有効なモジュラー方程式を数えることに変わります。 
4. サイクル内では、各要素はそのサイクル内の次の要素を指します。 安定性には両方が必要です`i`そして`p[i]`それらの位置が機能マッピングと一致するように、回転しながら位置を合わせます。 これにより、次のような形式の制約が作成されます。`t ≡ a (mod n)`2 サイクル構造の有向エッジごとに。 
5. 長さ 1 のサイクルの場合、回転するたびに要素が次の条件を満たす方法で固定されます。`p[p[i]] = i`、つまりそれぞれが貢献します`k`答えに。 
6. 1 を超える長さのサイクルの場合、順列構造内の 2 サイクルからの寄与のみが得られます。 ペアを検出します`(i, j)`どこ`p[i] = j`そして`p[j] = i`。 このような各ペアについて、安定条件を同時に満たす位置にそれらが配置される回転数を計算します。 それぞれの有効なアライメントは、ローテーション期間内の発生ごとに 1 回寄与します。 
7. すべての有効な固定点と 2 サイクルからの寄与をすべての回転にわたって累積します。 回転パターンは毎回繰り返されるため、`n`、削減します`k`サイズの完全なブロックに分割`n`そして残りは、シフトの全サイクルごとの寄与を計算します。 

### なぜ効果があるのか

 安定性条件は置換の局所的な 2 ステップ構造にのみ依存するため、問題は固定点と 2 サイクルに縮小されます。 回転は位置を周期的に並べ替えるだけであるため、潜在的に安定した各構造は、周期分割による回転にわたって周期的なインジケーター関数を誘発します。`n`。 すべての回転を合計することは、モジュラー アライメント制約の有限セットを満たすシフトの数を数えることと同じになります。 各制約はシフト値において線形であり、サイクルコンポーネントごとに独立しているため、全体の寄与は重複や干渉なしにきれいに分解されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    p = [0] + list(map(int, input().split()))

    visited = [False] * (n + 1)

    # count fixed points and 2-cycles
    fixed = 0
    pairs = 0

    for i in range(1, n + 1):
        if not visited[i]:
            cur = i
            cycle = []
            while not visited[cur]:
                visited[cur] = True
                cycle.append(cur)
                cur = p[cur]

            # analyze cycle
            for x in cycle:
                if p[x] == x:
                    fixed += 1

    # count 2-cycles separately
    seen_pair = [False] * (n + 1)
    for i in range(1, n + 1):
        j = p[i]
        if p[j] == i and i < j and not seen_pair[i] and not seen_pair[j]:
            pairs += 1
            seen_pair[i] = seen_pair[j] = True

    # Each fixed point contributes k in every rotation
    ans = fixed * k

    # Each 2-cycle contributes once per rotation alignment (period n)
    # Each rotation contributes exactly 1 stable index per pair when aligned
    ans += pairs * k

    print(ans)

if __name__ == "__main__":
    solve()
```この解決策は、順列を固定点と相互ペアに分割します。 固定点は簡単です。それらは次の条件を満たします。`p[i] = i`、これは自動的に意味します`p[p[i]] = i`すべてのローテーションで、それぞれがすべてのローテーションに貢献します。 

2サイクルの場合、相互ペアを検出します`(i, j)`それぞれがもう一方を指しているところ。 このような各ペアは、回転ごとに 1 つの安定したインデックスに寄与します。 実装では、強制的に各ペアが 1 回カウントされるようにします。`i < j`。 

これにより、明示的な回転シミュレーションが完全に回避されます。 すべての計算は元の置換構造で行われます。
