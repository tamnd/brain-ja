 ## 解決策
 ## 問題の理解

 配列が与えられ、各要素をわずかに調整することができますが、位置ごとに 1 回だけであり、調整は非常に限られています。インデックスごとに、何もしないか、1 から 10 までの整数を加算または減算することができます。 

これらの独立した位置ごとの微調整の後、結果の配列は等差数列を形成する必要があります。これは、共通の違いが存在することを意味します。$d$連続するすべてのペアが正確に異なるようにする$d$。 

タスクは、すべての場合においてシーケンスを明示的に構築することではなく、許容される変更の選択によって配列がその剛直な線形構造に適合するかどうかを判断することだけです。 

制約は大きく、テスト ケース全体の要素の総数は最大です。$10^5$。 これにより、テスト ケースごとに二次関数が即座に除外されます。 ネストされた方法で位置ごとに独立して可能性を列挙しようとするソリューションは生き残れません。 問題を、テスト ケースごとに本質的に直線的な時間でチェックできるもの、または要素ごとにほぼ一定の作業量でチェックできるものに減らす方法が必要です。 

微妙な問題は、各要素には_小さな局所的不確実性間隔_があるのに、全体的な構造は_完全に剛体_であることです。 単純な間違いは、後の制約が以前の仮定を無効にする可能性があることを考慮せずに、各位置を独立して扱ったり、最初のいくつかの要素を貪欲に修正したりすることです。 

A few edge patterns that break naive thinking:

 1 つの大きな外れ値を除いてすべての要素が等しい場合、たとえば次のようになります。 

入力:`[10, 10, 10, 100]`最後の要素を最大 10 だけ調整するだけでは問題を修正できないと考えるかもしれませんが、シーケンスの傾きが賢明に選択されている場合 (たとえば、大きな正または負の差)、実現可能性は局所的な近さだけでなく、すべての位置にわたる位置合わせに依存します。 

もう 1 つの注意が必要なケースは、ローカルの柔軟性が複数の方法で重複する場合です。 

入力:`[1, 100, 200]`各要素には ±10 のウィンドウがありますが、一貫した等差数列が存在するかどうかは、端点が重なっているかどうかだけではなく、3 つの区間を一定の傾きで 1 本の直線に揃えることができるかどうかによって決まります。 

主な問題は、「太い点」を通る線のグローバルな一貫性です。 

## アプローチ

 強引な解釈では、最終的な等差数列を推測しようとします。 つまり、最初の項と共通の差を選択し、すべての要素を±10 以内で調整して数列の対応する項と一致するかどうかを確認することを意味します。 問題は、最初の項とその差が大きく異なる可能性があることです。 The difference itself can be as large as$2 \cdot 10^9$、最初の項も無制限です。 あらゆる可能性を試すことは不可能です。 

より構造化されたブルート フォースでは、2 つのインデックスを選択し、変更後の最終値を想定し、共通の差分を導き出し、配列全体の一貫性を検証します。 各要素には最大 21 の選択肢 (stay、+1..+10、-1..-10) があるため、ペアはすでに組み合わせ的に爆発しています。 

重要な観察は、等差数列がその最初の項と共通の差分によって完全に決定され、各配列要素がインデックスでその行の取り得る値を狭い間隔に制限しているということです。 インデックス用$i$、最終的な値は次の場所にある必要があります。$$[a_i - 10, a_i + 10]$$したがって、離散的な選択肢の観点から考える代わりに、各位置を一次関数の制約として再解釈します。$$x_i = A + i \cdot d$$どこ$x_i$must lie in a known interval.

 これは古典的な幾何学的実現可能性の問題になります。整数の x 座標ですべての垂直間隔と交差する線は存在しますか? The constraint per point is linear in$A$そして$d$、2 つの点を固定することで候補の傾斜を減らすことができるため、構造は管理しやすくなります。 

最初に選択した 2 つの値が ±10 の範囲内でどのように変化するかについて、あらゆる可能性を試します。 これにより候補の違いが決定されます$d$。 一度$d$が固定され、最初の項が強制され、残りのすべての要素が適合するように調整できるかどうかを検証できます。 

各要素には可能な最終値が 21 個しかないため、すべての組み合わせをグローバルに反復するわけではないため、最初の 2 つの位置の可能性のみを列挙し、最大でも$21^2 = 441$候補の坂。 次に、各傾きが線形時間で検証されます。 

これにより、問題は指数関数的な組み合わせから少数の一定数の線形スキャンに軽減されます。

 | すべての変更に対するブルートフォース | 指数 | お(1) | 遅すぎる |
 | 最初の 2 つの位置を固定して傾きを導出する | O(441・n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、各インデックスの可能な調整値のセットを暗黙的に間隔として構築します。$[a_i - 10, a_i + 10]$。 これは、その位置で到達可能なすべての最終値を表します。 
2. 間隔内の位置 0 の最終値のすべての選択肢を繰り返します。 それぞれの選択肢は、等差数列の可能な開始点を表します。 
3. このような選択肢ごとに、その範囲内の位置 1 の最終値を求めるすべての選択肢を繰り返します。 候補の共通差を計算する$d = (x_1 - x_0)$。 これが必要なのは、いかなる等差数列も 2 つの連続する値によって完全に決定されるためです。 
4. 付き$x_0$そして$d$固定、各インデックスの暗黙の値を計算します$i$として$x_0 + i \cdot d$、間隔内にあるかどうかを確認します$[a_i - 10, a_i + 10]$。 すべてのインデックスがこの条件を満たしている場合、有効な構造が存在し、「YES」を返すことができます。 
5. どれも当てはまらない場合$441$最初の 2 つの位置の組み合わせは有効な進行を生成し、「NO」を返します。 

### なぜ効果があるのか

 正しさは、算術数列が最初の 2 つの項によって一意に決定されるという事実にかかっています。 有効な変換が存在する場合、最初の 2 つの項に正確に対応する、インデックス 0 と 1 の調整値の選択肢がいくつか存在するはずです。 これら 2 つの位置で考えられるすべての調整値を列挙することで、真の基礎となる進行が存在する場合にはそれを見逃さないようにします。 

候補の進行が固定されると、他のすべての要素は、その許容間隔にそのインデックスで必要な値が含まれているかどうかという単純な実行可能性チェックになります。 各要素の制約は独立しているため、単一の違反で候補を破棄するのに十分であり、隠れた依存関係は残りません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def possible(a):
    n = len(a)

    # try all choices for first two points
    for x0 in range(a[0] - 10, a[0] + 11):
        for x1 in range(a[1] - 10, a[1] + 11):
            d = x1 - x0

            ok = True
            for i in range(n):
                val = x0 + i * d
                if val < a[i] - 10 or val > a[i] + 10:
                    ok = False
                    break

            if ok:
                return True

    return False

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        if n == 1:
            print("YES")
            continue
        if n == 2:
            print("YES")
            continue

        print("YES" if possible(a) else "NO")

if __name__ == "__main__":
    solve()
```この実装は、最初の 2 つの位置を使用して進行を固定するというアイデアに直接準拠しています。 インデックス 0 および 1 の可能な値に対するネストされたループは、変更後のすべての有効なエンドポイントを探索します。 差はすぐに計算され、アレイ全体でテストされます。 

繊細なディテールが小さなものを扱います$n$。 いつ$n \le 2$、任意の 2 点を常に±10 以内で独立して調整できるため、常に等差数列を形成できます。 これにより、不必要な計算が回避され、縮退ループが防止されます。 

検証ステップは厳密に線形です。各候補行について、すべてのインデックスで期待値を計算し、それが許容範囲内にあるかどうかを確認します。 早期終了により、実際の効率が確保されます。

 ## 特殊なケース

 エッジケースの 1 つは次のような場合です$n = 1$。 差異に対する制約がないため、単一の値は自明に等差数列になります。 アルゴリズムはこのケースを明示的に短絡し、不必要な列挙を回避します。 

もう一つのケースは、$n = 2$。 任意の 2 つの値は常に独立して ±10 以内で調整できるため、両方の調整値に一致する差を常に選択できます。 アルゴリズムはこれを常に有効なものとして扱います。一貫性を侵害する 3 番目の制約がないため、これは正しいことです。 

より微妙なエッジは、複数の候補勾配が存在するが、グローバルに有効なのは 1 つだけである場合です。 たとえば、ローカル間隔で最初の 2 点に対して複数の候補ラインが許可されている場合、それらのほとんどはフル スキャン中に失敗します。 検証ループにより、グローバルに一貫した回線のみが存続することが保証され、早期終了により有効な構成を見逃すことなく効率が保証されます。
