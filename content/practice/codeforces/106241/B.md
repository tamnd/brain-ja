 ## 解決策
 ## 問題の理解

 サイズの長方形グリッド内で移動する 2 つの同一のビリヤード ボールをシミュレートしています。$n \times m$。 各セルには整数の座標があります$(i, j)$、両方のボールは境界線上ではなく、内側の位置からスタートします。 各ボールは、単位時間あたり 4 つの対角方向 (右上、左上、右下、または左下) のいずれかに 1 ステップ移動します。 

ステップごとに、各ボールは斜めに移動して位置を更新します。 グリッドから離れる場合は境界で反射します。水平境界に当たると動きの垂直成分が反転し、垂直境界に当たると水平成分が反転します。 これは、長方形の壁上の完全な弾性反射と同等です。 

さらに、両方のボールが同じタイム ステップで同じセルに着地すると、移動方向が即座に切り替わり、移動を続けます。 

後$k$ステップでは、両方のボールの最終位置を辞書順に印刷して報告する必要があります。 

この制約により、直接のシミュレーションが直ちに除外されます。 グリッドには最大で次のものを含めることができます$2 \cdot 10^5$細胞と$k$と同じ大きさにすることができます$10^{12}$。 したがって、段階的なシミュレーションは不可能です。$10^7$C++ ではすでにステップが境界線に達しており、Python でははるかに早い段階で失敗します。 

素朴な解釈には、微妙な罠も隠されています。衝突は、連続的な更新ではなく、同時の位置に依存します。 ボール 1 をボール 2 の前に完全に移動させようとしたり、同期せずにすぐに方向を更新したりすると、衝突動作が不正確になります。 

2 番目の微妙な問題は周期性です。 各ボールは有界状態空間内で決定論的に移動するため、その動きは最終的に繰り返される必要があります。 これを無視すると、計算が無駄になったり、長い軌道をシミュレートしようとする間違った試みが行われたりすることになります。 

## アプローチ

 ブルートフォース手法では、両方の位置を更新し、壁の反射を処理し、両方の位置が一致する場合は方向を交換するという各ステップをシミュレートします。 これはルールに正確に従っているため、これは正しいです。 ただし、それぞれのステップは、$O(1)$したがって、全体の複雑さは次のようになります。$O(k)$。 と$k = 10^{12}$、これは不可能です。 

重要な観察は、各ボールが反射を伴う決定論的なシステム内で独立して移動することです。これは、「展開されたグリッド」上の直線運動と同等です。 反射する代わりに、コピーをミラーリングすることでグリッドを無限に拡張することを想像できます。 この展開された空間では、各ボールは一定の速度で斜めの直線に移動します。 

Thus, each ball’s position after$k$ステップは、2 倍の軸でモジュラー演算を使用して独立して計算できます。長さの直線上の動きをシミュレートします。$2(n-1)$行と$2(m-1)$列用。 これにより、反射が単純なモジュロ演算に変換されます。 

残る唯一の困難は衝突処理です。 展開空間内で動きが線形化されると、各ボールの位置を時間の関数として扱うことができます。 両方の座標が同時に一致すると、衝突が発生します。 ただし、スワップを動的にシミュレートする代わりに、衝突時に方向をスワップすることは、ボールを相互に通過する区別できない粒子として扱うことと同等であることがわかります。 この古典的な事実は、衝突時に速度を交換すると、相互作用のない交差と等価な軌道が作成されるため当てはまります。 

したがって、衝突を完全に無視して、あたかも他のボールを通過するかのように各ボールを独立して計算し、ソートされた最終位置を出力します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(k)$|$O(1)$| 遅すぎる |
 | 最適 |$O(1)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 両方の座標について、有界グリッド内の動きを 2 倍の線形セグメント上の動きに換算します。 

1. 各方向をデルタのペアに変換します$(dr, dc)$、各コンポーネントは次のいずれかです$+1$または$-1$。 これにより、方向名に関係なく、動きを均一に表現できます。 
2. 長さの単一の座標軸の場合$L$、の期間を考慮して反射を置き換えます。$2(L-1)$。 後の位置$k$ステップは、跳ね返る直線上の単純な算術式になります。 
3. 各ボールと各軸について個別に計算します。 

後の展開線に沿った有効な位置$k$ステップ。 

これが機能する理由は、すべての反射が 2 倍になったセグメントの回り込みに正確に対応しているためです。 
4. 展開された座標を元のセグメントにマッピングし直します。$[1, L]$。 位置が周期の後半にある場合は、対称によって反映されます。 
5. 行と列の両方のディメンションに対して個別に繰り返して、最終的なディメンションを取得します。$(i, j)$各ボールの位置。 
6. シミュレーション中にコリジョン スワップを無視します。 ボールを相互に通過するものとして扱うと、交差点での交換によりエンドポイントに影響を与えることなく複数の軌道セットが保存されるため、最終的な位置は同一になります。 

### なぜ効果があるのか

 各座標はセグメント上の 1D ビリヤードとして独立して進化します。 展開構造は反射を周期のある線上の周期運動に変換します。$2(L-1)$、すべてのステップで正確な位置の対応を維持します。 システムは決定論的であり、衝突は軌道を変更せずにアイデンティティを交換するだけであるため、交換がシミュレートされるか無視されるかにかかわらず、占有位置の最終セットは不変です。 

したがって、各ボールの終点はその初期状態のみに依存し、相互作用履歴には依存しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def reflect(pos, L):
    # period is 2*(L-1)
    if L == 1:
        return 1
    period = 2 * (L - 1)
    pos %= period
    if pos < 0:
        pos += period
    if pos <= L - 1:
        return 1 + pos
    return L - (pos - (L - 1))

def move(x, dx, L, k):
    # convert to 0-indexed
    x0 = x - 1
    pos = x0 + dx * k
    return reflect(pos, L)

def parse_dir(d):
    if d == "UR":
        return (-1, +1)
    if d == "UL":
        return (-1, -1)
    if d == "DR":
        return (+1, +1)
    return (+1, -1)

n, m, k = map(int, input().split())

i1, j1, d1 = input().split()
i1 = int(i1); j1 = int(j1)
i2, j2, d2 = input().split()
i2 = int(i2); j2 = int(j2)

dr1, dc1 = parse_dir(d1)
dr2, dc2 = parse_dir(d2)

r1 = move(i1, dr1, n, k)
c1 = move(j1, dc1, m, k)

r2 = move(i2, dr2, n, m, k)
c2 = move(j2, dc2, m, k)

p1 = (r1, c1)
p2 = (r2, c2)

if p1 < p2:
    print(r1, c1)
    print(r2, c2)
else:
    print(r2, c2)
    print(r1, c1)
```この実装の核心は、バウンス動作を 2 倍の間隔でのモジュラー演算に削減することです。 機能`reflect`展開された座標から元のセグメントへのマッピングを実装します。 の期間を使用します。$2(L-1)$、完全な往復トラバーサルをエンコードします。 

各ボールは以下を使用して個別に処理されます。`move`、まず座標をゼロベースのシステムに変換し、直線運動を適用します。$x + dx \cdot k$、そしてそれを折り曲げます。 

方向解析により、すべての動きが符号付き整数に還元され、後で大文字と小文字が区別されなくなります。 

最後に、出力仕様の要求に応じて、辞書順に並べ替えが行われます。 

実装上の微妙な点の 1 つは、インデックス付けの一貫性です。0 ベースの座標と 1 ベースの座標を誤って混合すると、反射が 1 単位ずつシフトし、境界で体系的なオフバイ 1 エラーが発生します。

 ## 特殊なケース

 エッジケースの 1 つは次のような場合です$k = 0$。 アルゴリズムは、変換を適用せずに初期位置を返す必要があります。 直線運動を使った式なので$x + dx \cdot k$、 いつ$k = 0$元の座標に戻りますが、反射によって変更されることはありません。 これにより、アイデンティティの動作が保証されます。 

もう 1 つのエッジケースは、展開後にボールがちょうどコーナーにある場合です。 この場合、位置モジュロ$2(L-1)$正確に 0 または$L-1$、どちらも境界セルに正しくマップされます。 セグメントの両端が有効なエンドポイントに対応するため、reflect 関数はこれを自然に処理します。 

3 番目のエッジケースは、両方のボールが繰り返し衝突する場合です。 衝突のスワップを無視するため、軌道は独立して継続します。 たとえば、両方が対称的に始まり、中心で何度も交わる場合、交換では座標ではなくアイデンティティのみが並べ替えられるため、最終的な位置は影響を受けません。
