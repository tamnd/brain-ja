 ## 問題の理解

 直線のベースラインに基づいて構築された幾何学的構成が与えられています。 3 つの点が 1 つの線上に B、C、D の順序であり、B から C までの線分は C から D までの線分と同じ長さを持ちます。4 番目の点 A はこの線の上に配置され、点 A を共有する 2 つの三角形、三角形 ABC と三角形 ACD を形成します。 

２つの角度が知られている。 1 つ目はセグメント BA と BD の間に形成される B の角度であり、2 つ目はセグメント CA と CD の間に形成される C の角度です。 これら 2 つの角度制約と、BC が CD に等しいという事実のみから、タスクは、DA と DC の間の三角形 ACD 内に形成される D の角度を決定することです。 

入力は 2 つの実数値の角度 α と β で構成され、それぞれ厳密に 1 ～ 90 度の範囲になります。 出力は、∠ADC を高精度に表す単一の実数です。 

制約が非常に小さいため、パフォーマンスを心配する必要はありません。 本当の課題は、厳密な幾何学的構成を安定した代数式に変えることです。 この種の問題は、座標設定と角度の解釈に影響されます。 よくある故障モードは、特に ABD と ACD が同じベースラインに沿った異なる頂点で定義されているため、各角度がどの方向から測定されたかを誤って解釈することです。 

2 番目の微妙な問題は、A が BD の中点の真上にあることが保証されていないことです。 α と β によっては、点が線分 BC の外側に水平に移動する可能性があるため、図形の対称性を前提とした推論は暗黙のうちに失敗します。 

## アプローチ

 強引なアプローチでは、問題を一般的なジオメトリ構築として処理しようとします。つまり、すべての制約を満たす A、B、C、D の座標を選択し、両方の角度条件が一致するまで A を数値的に調整します。 これにより、当然のことながら、三角関数の制約を伴う非線形方程式系が得られます。 両方の角度が必要な値と一致するまで繰り返し座標を調整する、反復ソルバーまたは数値最適化を試すことができます。 

これは、構成が 2 つの独立した角度制約と 1 つの固定長比によって完全に決定されるため、原理的に機能します。 ただし、検索空間は連続的であり、制約は非線形です。 単純なサンプリングまたは勾配ベースの方法では、テスト ケースごとに多くの反復が必要となり、A がベースラインとほぼ同一直線上になる縮退構成に近い状態では数値的に不安定になります。 

重要な観察は、ベースラインに合わせて座標系を固定すると、ジオメトリが完全に固定されるということです。 検索する代わりに、三角関数の方向を使用して制約を直接エンコードできます。 B の角度は線 BA の方向を固定し、C の角度は線 CA の方向を固定します。 これら 2 つの光線を交差させると、明示的に A が得られます。 A が座標で既知になると、D における残りの角度は直接ベクトル角度計算で計算されます。 

これにより、問題が継続的な検索から閉じた形式の構築に軽減されます。

 ## アルゴリズムのチュートリアル

 最初にジオメトリを正規化して、スケーリングの自由を削除します。 BC は CD と等しいため、3 つの共線点を X 軸上に B を 0、C を 1、D を 2 として配置します。均一なスケーリングでは構成が不変であるため、これによりすべての比率と角度が保存されます。 

次に、点 A を、指定された角度によって決定される 2 本の光線の交点として表現します。

1. B を (0, 0) に、C を (1, 0) に、D を (2, 0) に配置します。 これにより、等セグメント制約が座標に直接エンコードされます。 
2. B での角度、つまり BA と BD の間の角度を解釈します。 BD は正の x 軸に沿って存在するため、光線 BA は水平線に対して角度 α を形成します。 これにより、一部の t > 0 に対して A = t(cos α, sin α) が得られます。 
3. C での角度、つまり CA と CD の間の角度を解釈します。 CD も正の x 軸に沿って存在するため、光線 CA は水平線に対して角度 β を形成します。 これにより、一部の s > 0 については A = (1, 0) + s(cos β, sin β) が得られます。 
4. 座標を等しくすることで、2 本のパラメトリック ラインの交点を解きます。 これにより、t と s に線形システムが生成され、A の閉形式の式が得られます。 
5. A がわかったら、ベクトル DA = A − D および DC = C − D を形成します。必要な角度 ∠ADC は、これら 2 つのベクトル間の角度です。 
6. 内積公式: cos θ = (DA · DC) / (|DA||DC|) を使用してこの角度を計算します。 θ を度に変換し直します。 

重要な考え方は、すべての幾何学的制約が 2 つの光線に集約され、その交差部分が構成を一意に定義するということです。 

### なぜ効果があるのか

 この構造では、B、C、D を直線上に固定し、指定された角度を使用して BA と CA に方向を割り当てることで、平面内のすべての自由が強制的に消費されます。 この問題により有効な構成が保証されるため、これら 2 つの光線は 1 点で交差します。 A が一意に決定されると、残りの角度はすべてユークリッド幾何学の固定結果になります。 近似や反復調整は必要ないため、数値の安定性は三角関数の標準的な浮動小数点評価のみに依存します。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

def solve():
    alpha, beta = map(float, input().split())

    a = math.radians(alpha)
    b = math.radians(beta)

    B = (0.0, 0.0)
    C = (1.0, 0.0)
    D = (2.0, 0.0)

    sin_a, cos_a = math.sin(a), math.cos(a)
    sin_b, cos_b = math.sin(b), math.cos(b)

    denom = cos_a - sin_a * (cos_b / sin_b)
    t = 1.0 / denom

    Ax = t * cos_a
    Ay = t * sin_a

    Dx, Dy = D
    Cx, Cy = C

    dax = Ax - Dx
    day = Ay - Dy

    dcx = Cx - Dx
    dcy = Cy - Dy

    dot = dax * dcx + day * dcy
    da_len = math.hypot(dax, day)
    dc_len = math.hypot(dcx, dcy)

    cos_theta = dot / (da_len * dc_len)
    cos_theta = max(-1.0, min(1.0, cos_theta))

    theta = math.degrees(math.acos(cos_theta))
    print(theta)

if __name__ == "__main__":
    solve()
```Python の三角関数はすべてラジアンで動作するため、実装は角度をラジアンに変換することから始まります。 ベースラインは、B、C、D に明示的な座標を割り当てることで固定されます。 

2 つの角度制約は方向ベクトルに変換されます。 B から A への線は α によって決定される方向を持つ光線として表され、C から A への線も同様に β によって決定されます。 それらの交差は、置換後に単一のスカラー方程式を解くことによって代数的に計算されます。 

A が計算されると、D での角度は、ドット積を使用してベクトル ジオメトリのみから取得されます。 コサインを有効な区間 [-1, 1] にクランプすると、浮動小数点ドリフトが acos への無効な入力を生成するのを防ぎます。これは、ジオメトリ問題におけるランタイム NaN の一般的な原因です。

 ## 特殊なケース

 微妙な状況の 1 つは、α と β が 90 度に非常に近い場合です。 この領域では、B と C からの光線がほぼ垂直かつほぼ平行になるため、交差の計算が数値的に不安定になる可能性があります。 この実装では、x 座標の小さな差による除算を使用して、ほぼ平行な線の系を明示的に解くことがないため、失敗が回避されます。 代わりに、すべてを三角恒等式から導出される単一の代数式に還元します。この代数式は、sin(β) がゼロでない限り安定しており、制約によって保証されています。 

もう 1 つのケースは、両方の角度が非常に小さい場合です。 ここでは両方の光線がほぼ水平であり、A はセグメント BC から遠く離れています。 スケーリングが固定されているため、座標系は引き続き保持され、両方向の傾きがわずかに異なるため、交差式は良好な状態を保ちます。 

最後の暗黙的なエッジ ケースは、A がセグメント BC 投影のはるか外側にある場合です。 このアルゴリズムでは A の境界位置を想定していないため、A がセグメントの左側にあるか右側にあるかに関係なく、D でのベクトルベースの角度計算は有効なままです。
