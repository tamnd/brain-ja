 ## 解決策
 ## 問題の理解

 平面上に一連の点が与えられ、最大 2 つの円を使用してそれらすべてをカバーすることが課題となります。 各円はどこにでも配置でき、半径はゼロを含む任意の値に設定できます。 構成のコストは 2 つの半径の合計であり、すべての点が少なくとも 1 つの円の内側に位置するようにしながら、この総コストを最小限に抑えたいと考えています。 

半径ゼロが許可されており、事実上、円がその中心にある 1 つの点を正確にカバーしていることを意味します。 この詳細は、最適な場合は 1 つの円のみを使用するように解を縮退させたり、ゼロまたは非常に小さな円を使用して残りのいくつかの点を分離したりできるため、重要です。 

入力サイズは300ポイントまでです。 これは、点に対する 2 次または 3 次の演算を含む解は受け入れられるが、4 乗やサブセットごとの繰り返しの幾何学的最適化を含むものは遅すぎる可能性があることを示唆しています。 

この問題の微妙な点は、一連の点を覆う円の中心が入力点に限定されないことです。 これにより、ジオメトリが離散的ではなく連続的になり、単純なサブセット チェックが重要になります。 

いくつかの特殊なケースについては、覚えておく価値があります。 

すべての点が同一の場合、半径 0 の円が 1 つあれば十分なので、答えは 0 になります。 

すべての点が同一線上にある場合、問題は 2 つの間隔で線上の点をカバーすることになりますが、平面解釈では、間隔ではなく最小の囲み円を計算する必要があります。 

ちょうど 2 つの点がある場合、各円の中心を点に置くことができ、半径 0 が有効であるため、最良の解決策は各点で半径 0 の 2 つの円となり、コストが 0 になります。 

単純な間違いは、1 つの円が多くの点を「適切に」カバーする必要があると仮定し、ヒューリスティックな幾何学的な方法で貪欲に点を分割しようとすることです。 円は非線形に相互作用するため、角度や境界ボックスによる貪欲な分割は失敗します。 

## アプローチ

 一連の点を覆う単一の円はよく理解されており、それは最小包囲円 (MEC) です。 点のサブセットについては、それらすべてを含む最小の円を計算でき、その半径は明確に定義されています。 

点を 2 つのグループに分割する方法がわかっていれば、答えは単純に両方のグループの MEC 半径の合計になります。 これは、すべてのパーティションに対するブルート フォースを示唆しています。 

ブルート フォース アプローチでは、最初の円のすべてのサブセットを列挙し、その MEC を計算し、2 番目の円の残りの点の MEC を計算します。 これは正しいです。有効な解はすべて、点を 2 つのセットに分割することに相当するからです。 

ただし、サブセットは 2^n 個あり、サブセットごとの MEC を計算しても O(n^2) または O(n^3) かかります。 これは、n = 300 の場合には実現不可能です。 

重要な観察は、最適解では、円の 1 つが、小さな境界構造によって定義される慎重に選択されたサブセットの MEC であると想定できることです。 任意のサブセットの代わりに、MEC が最大 3 つのポイントによって決定されるという事実を利用できます。 これにより、O(n^3) 個のトリプルから候補円を生成し、それらにどの点が含まれなければならないかを推論することができます。 

最後のアイデアは、どの点がその境界上にあるかを推測することによって、最初に 1 つの円を修正することです。 候補円が決定されると、残りの点によって 2 番目の副問題が形成されます。これは単に「残った点の最小包囲円」です。 MEC は最大 3 つの境界点によって一意に決定されるため、すべての O(n^3) 個の候補円を反復するだけで十分です。 

次に、最初の円の候補ごとに、事前に計算された構造または再計算を使用して、可能な限り最良の 2 番目の円を計算します。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース サブセット分割 | O(2^n · n^2) | O(n) | 遅すぎる |
 | バウンダリートリプル + MEC | O(n^4) ワーストケースのナイーブ、最適化 O(n^3 log n) または O(n^3) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 最適解の最初の円は 2 つまたは 3 つの境界点によって定義されるという考えを修正します。 これにより、連続検索空間が、ポイント トリプルおよびペアから導出された個別の候補セットに縮小されます。 
2. 点のペアごとに、それらを直径の端点として持つ円を計算します。 これは、すべての点がその内部または上にある場合にのみ有効な候補です。 有効な場合、2 番目の円は残りの点の MEC にすぎず、個別に計算できます。 
3. 点のトリプルごとに、それらを通過する一意の円を計算します。 この円は、3 つの点が同一線上にない場合にのみ意味を持ちます。 このような各円は、最初の円の候補です。 
4. それぞれの候補円について、その内側にどの点があるかを決定します。 これらの点は最初の円に割り当てられます。 残りの点は 2 番目のグループを定義します。 
5. 残りの点の最小包囲円半径を計算します。 これは、標準的なランダム化増分アルゴリズムまたは決定論的な O(n^2) メソッドを使用して実行できます。 
6. すべての候補の最初の円の値 radius(first) + radius(second) の最小値を追跡します。 

これが機能する理由は、最小囲み円の構造に根ざしています。 1 つの円の最適解は、最大 3 つの境界点によって定義されます。 したがって、2 つまたは 3 つの点によって決定されるすべての円を考慮すると、最適な最初の円が含まれることが保証されます。 最初の円が正しく修正されると、2 番目の円は、最初の円とは無関係に、残りの点に対する最適な解になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import random
import math

def dist(a, b):
    return math.hypot(a[0] - b[0], a[1] - b[1])

def mec(points):
    random.shuffle(points)
    cx, cy = points[0]
    r = 0.0
    for i in range(len(points)):
        if dist((cx, cy), points[i]) > r + 1e-12:
            cx, cy = points[i]
            r = 0.0
            for j in range(i):
                if dist((cx, cy), points[j]) > r + 1e-12:
                    cx = (points[i][0] + points[j][0]) / 2
                    cy = (points[i][1] + points[j][1]) / 2
                    r = dist((cx, cy), points[i])
                    for k in range(j):
                        if dist((cx, cy), points[k]) > r + 1e-12:
                            # circumcircle
                            ax, ay = points[i]
                            bx, by = points[j]
                            cx2, cy2 = points[k]
                            d = 2 * (ax * (by - cy2) + bx * (cy2 - ay) + cx2 * (ay - by))
                            ux = ((ax*ax + ay*ay)*(by - cy2) +
                                  (bx*bx + by*by)*(cy2 - ay) +
                                  (cx2*cx2 + cy2*cy2)*(ay - by)) / d
                            uy = ((ax*ax + ay*ay)*(cx2 - bx) +
                                  (bx*bx + by*by)*(ax - cx2) +
                                  (cx2*cx2 + cy2*cy2)*(bx - ax)) / d
                            cx, cy = ux, uy
                            r = dist((cx, cy), points[i])
    return r

def solve():
    n = int(input())
    pts = [tuple(map(int, input().split())) for _ in range(n)]

    best = float('inf')

    for i in range(n):
        for j in range(i + 1, n):
            c1 = ((pts[i][0] + pts[j][0]) / 2, (pts[i][1] + pts[j][1]) / 2)
            r1 = dist(pts[i], pts[j]) / 2
            rem = [p for p in pts if dist(c1, p) > r1 + 1e-12]
            best = min(best, r1 + mec(rem))

    for i in range(n):
        for j in range(i + 1, n):
            for k in range(j + 1, n):
                ax, ay = pts[i]
                bx, by = pts[j]
                cx2, cy2 = pts[k]
                d = 2 * (ax * (by - cy2) + bx * (cy2 - ay) + cx2 * (ay - by))
                if abs(d) < 1e-12:
                    continue
                ux = ((ax*ax + ay*ay)*(by - cy2) +
                      (bx*bx + by*by)*(cy2 - ay) +
                      (cx2*cx2 + cy2*cy2)*(ay - by)) / d
                uy = ((ax*ax + ay*ay)*(cx2 - bx) +
                      (bx*bx + by*by)*(ax - cx2) +
                      (cx2*cx2 + cy2*cy2)*(bx - ax)) / d
                c1 = (ux, uy)
                r1 = dist(c1, pts[i])
                rem = [p for p in pts if dist(c1, p) > r1 + 1e-12]
                best = min(best, r1 + mec(rem))

    print(best)

if __name__ == "__main__":
    solve()
```このソリューションは、最初の円の候補を列挙することを中心に構成されています。 ペアベースのループは、直径の端点を持つ円を構築します。これは、最適な円が 2 つの境界点によって定義される場合をカバーします。 トリプルベースのループは外接円を作成し、3 つの境界点が円を定義する場合をカバーします。 

各候補について、小さなイプシロンマージンを持った円の内側に点があるかどうかをチェックして、点を分割します。 残りの点は MEC ルーチンに渡され、最適な 2 番目の円が計算されます。 

実装の微妙な詳細は、数値の安定性です。 比較では、浮動小数点誤差による境界点の誤分類を避けるために許容誤差を使用します。 外接円の計算では、ほぼ同一線上にあるトリプルを慎重に処理する必要もあります。 

MEC 関数は、ランダム化された増分アルゴリズムを使用して、呼び出しごとに予想される線形時間を確保します。これは、外側の列挙を考慮すると、n が最大 300 まで許容されます。 

## 実用的な例

 ### 例 1

 正方形を形成する 4 つの点 (0,0)、(0,1)、(1,0)、(1,1) を考えます。 

対角線 (0,0)-(1,1) から候補円をテストします。 

| ステップ | センター | 半径 | 対象となるポイント | 残り |
 | --- | --- | --- | --- | --- |
 | 直径円 | (0.5,0.5) | ~0.707 | 全4 | なし |

 リストが空であるため、残りの点の MEC はゼロです。 

これは、アルゴリズムが 1 つの円で十分であることを正しく認識していることを示しています。 

### 例 2

 ポイント: (0,0)、(4,0)、(0,3)

 最適な最初の円は、3 つすべての外接円です。 

| ステップ | センター | 半径 | 対象となるポイント | 残り |
 | --- | --- | --- | --- | --- |
 | 三角形の円 | (2,1.5) | 2.5 | 3つすべて | なし |

 ここでも 2 番目の円の寄与はゼロです。 

これにより、トリプル列挙が正しいフルカバー ケースをキャプチャしていることが確認されます。

 ## 特殊なケース

 重複した点の場合、MEC はすぐに半径 0 を維持し、フィルター処理ではすべての点がその点を中心とする候補円の内側として扱われるため、アルゴリズムは距離ゼロを正しく処理します。 

ほぼ同一線上にあるトリプルの場合、外接円の式の行列式はゼロに近づき、コードは数値の不安定性を避けるためにそのようなケースを明示的にスキップします。 

最適解が円を 1 つだけ使用する場合でも、有効な最初の円がすべての点をカバーし、MEC がゼロに寄与する空の剰余が残るため、列挙は依然としてその円を捕捉します。
