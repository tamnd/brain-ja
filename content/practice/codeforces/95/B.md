 ## 解決策
 ## 問題の理解

 少なくとも次のような最小の数を構築する必要があります。`n`かつ 2 つの条件を同時に満たします。 すべての数字は次のいずれかである必要があります`4`または`7`、および合計数`4`s は次の合計数と等しくなければなりません`7`s.

 入力は 10 進数の文字列であり、非常に長くなる可能性があります。`10^5`数字。 そうすれば問題の性質はすぐに変わります。 値を通常の整数型として扱うことはできず、すべての数値を 1 つずつ上方チェックすることを繰り返すこともできません。 長さが大きくなると、同じサイズのすべてのラッキーナンバーを生成することさえ不可能になります。`2^L`考えられる長さのラッキー文字列`L`。 

ターゲット数値の構造により、より強力な制限が与えられます。 有効な回答は偶数の長さである必要があります。`4`と`7`s は正確に一致する必要があります。 長さに関しては`2k`、 その通り`k`位置に含まれる`4`そしてもう一つは`k`含む`7`。 

難しいのは、有効な数値を生成しないことです。 難しいのは、少なくとも有効な最小値を生成することです。`n`。 

いくつかのエッジケースは、素朴で貪欲な考えを打ち破ります。 

入力が次のとおりであるとします。```
5000
```不用意な左から右への貪欲な戦略は、次のようなことから始まる可能性があります。`7`なぜなら`4`プレフィックスが小さすぎます。 配置後`7`、残りを最小限に抑えて生成しようとする可能性があります`7447`。 しかし、正しい答えは次のとおりです。```
7474
```なぜなら`7447 < 5000`。 

同じ長さの有効な数値が存在しない場合にも、微妙なケースが発生します。```
7777
```長さの超ラッキーな数字はありません`4`それは少なくとも`7777`、最大のものは次のとおりです。`7744`。 正解は、次の偶数の長さの最小の有効な数になります。```
444777
```奇数の長さにも注意が必要です。```
100
```超ラッキーな数字に長さはありえない`3`、したがって、答えは長さにジャンプする必要があります`4`:```
4477
```最後の厄介な状況はバックトラック中に発生します。 考慮する：```
4748
```貪欲な構築がマッチするかもしれない`474`そして最後の桁で失敗します。`4`そして`7`許可されています。 アルゴリズムは以前の位置に戻り、慎重に値を増やす必要があります。 正しい答えは次のとおりです。```
4774
```ロジックを後戻りしないと、構築は行き詰まります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 から開始`n`, 1つずつ増やして、現在の数字が超ラッキーかどうかをテストします。 チェック自体は簡単です。数字をスキャンし、すべての数字が次のいずれかであることを確認します。`4`または`7`、それぞれが何個出現するかを数えます。 

これは小さな入力には機能しますが、検索スペースはすぐに爆発します。 周囲の長さ`10`、その数はすでに数十億に達しています。 入力には以下を含めることもできます`10^5`数字なので、数値を直接反復することは完全に不可能です。 

もう少し優れた総当り的な方法は、必要な長さのスーパー ラッキー ナンバーをすべて生成し、少なくとも`n`。 長さに関しては`2k`、どれを選択しますか`k`位置に含まれる`4`、与える：$$\binom{2k}{k}$$候補者たち。 

長さについて`20`、これはもう`184756`。 長さについて`100`、天文学的な大きさになります。 制約により、これは完全に排除されます。 

重要な点は、辞書編集的に最小の有効な文字列以上が必要なだけであるということです。`n`。 これにより、問題は制約された数字の構成問題に変わります。 

以下を追跡しながら、左から右に答えを構築します。 

1. 何個`4`が残っています。 
2. 何個`7`が残っています。 
3. 構築されたプレフィックスがすでに、対応するプレフィックスより厳密に大きいかどうか`n`。 

プレフィックスがすでに大きい場合は、できるだけ多くの桁を配置して、残りの桁を最小限に抑える必要があります。`4`できるだけ最初に。 

プレフィックスが依然として等しい場合、すべての選択は、次の条件によって課される下限を尊重する必要があります。`n`。 

これは当然、枝刈りを伴う深さ優先検索になります。 それぞれの位置に配置してみます`4`まず、最小の答えが必要だからです。 その選択が有効な完了につながる可能性がない場合は、次のことを試します。`7`。 

位置ごとに可能な桁は 2 つだけであり、枝刈りによってほとんどすべての無効な分岐が即座に削除されるため、検索の効率性は維持されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数関数的/実行不可能 | お(1) | 遅すぎる |
 | 最適 | O(L²) 最悪の場合 | O(L) | 承認済み |

 ここ`L`答えの桁数です。 

## アルゴリズムのチュートリアル

 1. 入力を整数ではなく文字列として読み取ります。 

入力には最大で次のものを含めることができます`10^5`数字であるため、固定サイズの数値型はそれを格納できません。 
2.長さの場合`n`が奇数の場合は、ターゲットの長さをすぐに次の偶数に増やします。 

スーパーラッキーナンバーには、同じ数の`4`と`7`s なので、長さは常に偶数です。 
3. 現在の長さを使用して答えを作成してみてください。 

現在の長さが元の長さより大きい場合、有効な最小の数値は単純に次のようになります。```
444...777...
```両方の桁のカウントが等しい。 
4. それ以外の場合は、位置に対して再帰的 DFS を実行します。 

DFS 状態には次のものが含まれます。 

- 現在のインデックス
 - 残りの数`4`- 残りの数`7`- 現在のプレフィックスがすでに次より大きいかどうか`n`5. 各位置で数字を試してください`4`初め。 

私たちは好みます`4`辞書編集的に最小の有効な答えが必要だからです。 
6. 無効な選択肢はすぐにスキップします。 

すでに使いすぎている場合`4`または`7`s、そのブランチは機能しません。 

プレフィックスが依然として等しく、選択された数字が、次の対応する数字より小さい場合`n`、そのブランチも機能しません。 
7. 数字を入力した後、`greater`フラグ。 

構築されたプレフィックスが厳密に次のプレフィックスよりも大きくなると、`n`、残りの桁はバランス条件を満たすだけで済みます。 
8. 再帰呼び出しが両方のカウントが 0 の状態で最後に到達した場合は、構築された文字列を返します。 
9. 現在の長さに対する解決策が存在しない場合は、長さを次のように増やします。`2`そして、その長さの最小の有効な数値を返します。 

### なぜ効果があるのか

 このアルゴリズムは、構築全体を通じて単純な不変条件を維持します。 

現在のプレフィックスは常に、少なくとも 1 つの有効なスーパー ラッキー ナンバーに拡張可能です。`n`。 

数字を配置するときは常に、この不変式に違反する選択肢は直ちに拒否されます。 試しています`4`前に`7`最初に成功した分岐が可能な限り最小の完了であるため、辞書編集上の最小性が保証されます。 

現在の長さですべての分岐が失敗した場合、その長さの有効な数は存在しません。 有効な最小の数値は次の偶数の長さを持たなければなりません。そのような数値すべての中で最小の配置は次のとおりです。`4`に続いて全員`7`s.

 ## Python ソリューション```python
import sys
from functools import lru_cache

input = sys.stdin.readline

def solve():
    n = input().strip()
    m = len(n)

    if m % 2 == 1:
        m += 1
        print('4' * (m // 2) + '7' * (m // 2))
        return

    while True:
        half = m // 2

        if m > len(n):
            print('4' * half + '7' * half)
            return

        @lru_cache(None)
        def dfs(pos, fours, sevens, greater):
            if pos == m:
                return "" if fours == 0 and sevens == 0 else None

            limit = n[pos]

            for d in ['4', '7']:
                if d == '4':
                    if fours == 0:
                        continue
                else:
                    if sevens == 0:
                        continue

                if not greater and d < limit:
                    continue

                ngreater = greater or (d > limit)

                res = dfs(
                    pos + 1,
                    fours - (d == '4'),
                    sevens - (d == '7'),
                    ngreater
                )

                if res is not None:
                    return d + res

            return None

        ans = dfs(0, half, half, False)

        if ans is not None:
            print(ans)
            return

        m += 2

if __name__ == "__main__":
    solve()
```解決策は、最も簡単で不可能なケースに対処することから始まります。 入力の長さが奇数の場合、同じ長さを持つ有効な答えは存在しないため、すぐに次の偶数の長さに移動し、バランスの取れた最小のラッキーナンバーを直接構築します。 

再帰関数はアルゴリズムの中核です。 そのパラメータは、残りの検索スペースを完全に記述します。 の`greater`特に旗は重要です。 そうであるうちに`False`、すべての数字の選択では、対応する接頭辞と少なくとも同じ大きさの数字を維持する必要があります。`n`。 そうなったら`True`、下限制限はなくなります。 

メモ化により、同一の状態を繰り返し探索することが防止されます。 キャッシュがないと、異なるパスが同じパスを再訪問する可能性があります。`(position, remaining fours, remaining sevens, greater)`設定を何度も繰り返します。 

数字を試す順序は重要です。 私たちは常にテストします`4`前に`7`。 DFS は有効な補完を見つけた直後に戻るため、最終的な答えが辞書編集上最小であることが保証されます。 

実装の微妙な詳細の 1 つは、数字を文字として比較することです。 以来`'4' < '7'`辞書順に数値順序を照合し、文字の直接比較は正しく機能します。 

もう 1 つの微妙な点は、同じ長さのソリューションが存在しない場合のフォールバックです。 長さを伸ばすには、`2`ではなく、`1`有効な長さは偶数のままである必要があるためです。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(L²) | メモ化された DFS は最大 O(L²) 状態を訪問します。 
| スペース | O(L²) | キャッシュは DFS 状態を保存します。 

状態の数は次の制限によって制限されます。$$L \times \frac{L}{2} \times \frac{L}{2} \times 2$$これを単純化すると`O(L²)`なぜなら、`4`と`7`が相互にリンクされています。 

と`L ≤ 10^5`DFS は積極的にプルーニングを行い、実行可能なプレフィックスのみを探索するため、実際の検索スペースは引き続き管理可能です。 ソリューションは制限内に問題なく収まります。
