 ## 解決策
 ## 問題の理解

 整数のいくつかの間隔が与えられます。 間隔ごとに$[l, r]$、幸運な数字が 2 つ含まれる数字がいくつあるかを数えなければなりません。`4`または`7`、その位置の違いは最大でも`k`。 

位置は、数値の 10 進表現内でカウントされます。 2 つの幸運な数字が十分近くに表示される場合、その数字はほぼ幸運であると呼ばれます。 

たとえば、$k = 2$:

 -`404`この 2 つはほぼ幸運です`4`は 2 つの位置離れています。 
-`4123954997`は、最も近い幸運の数字のペアが離れすぎているため、ほとんど幸運ではありません。 
- 幸運な数字が 1 つしかない数字は資格を得ることができません。 

間隔の限界は膨大です。 数値には最大 1000 桁の 10 進数を含めることができるため、範囲内のすべての値を反復処理することは不可能です。 数値を 1 桁ずつチェックするだけでも、すべての値に対して試してみるとコストがかかりすぎます。 

これにより、間隔の数値サイズに比例する解は即座に排除されます。 唯一実現可能な方向は、数字 DP であり、数字を 1 桁ずつ構築して有効な数を数えます。 

テストケースの数と値$k$桁の長さも最大 1000 であるため、次のような解決策が考えられます。$O(\text{digits}^2)$クエリごとに許可されます。 3 次的な解決策はすでに危険になります。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

考慮する$k = 1$。 その場合、隣接する幸運の数字だけが問題になります。 

入力：```
1 1
1 100
```有効な数字は次のとおりです`44`、`47`、`74`、 そして`77`、したがって、答えは次のとおりです`4`。 不用意に実装すると、次のような数値が誤ってカウントされる可能性があります。`404`、幸運の数字が距離によって区切られている場合`2`。 

もう 1 つの危険なケースは、先行ゼロです。 数値を固定長の文字列として処理するとします。 

入力：```
1 2
1 50
```先行ゼロが実数のように動作できるようにすると、次のようになります。`"004"`そして`"040"`誤って偽のラッキーペアを作成してしまう可能性があります。 先頭のゼロは条件に含めてはなりません。 

3 番目の微妙なケースは、有効なペアがすでに存在する場合に発生します。 十分に近い幸運の数字のペアがすでに見つかったら、それ以降の数字は有効性にとって重要ではなくなります。 

例えば：```
1 2
447000000000 447000000000
```最初の 2 桁が有効なペアを形成しているため、この数字はすでにほぼ幸運に近い数字です。 バグのある DP により、後で状態が上書きされ、その情報が失われる可能性があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 間隔内のすべての数値について、その 10 進数をスキャンし、すべての数値の位置を記録します。`4`そして`7`数字。 連続する 2 つの幸運な位置の差が最大でも異なる場合`k`、数を数えます。 

これが機能するのは、このプロパティが 1 つの数値の桁列のみに依存するためです。 

問題は規模だ。 間隔のエンドポイントには 1000 桁を含めることができます。 間隔のサイズ自体も天文学的に大きいです。 数字を列挙することは不可能です。 

したがって、数値を反復処理する代わりに、数値を組み合わせて数えます。 

重要な観察は、数字を左から右にスキャンする際、このプロパティはローカル情報のみに依存するということです。 どの時点でも、次のことだけを知る必要があります。 

- 有効なペアがすでに出現しているかどうか、
 - 最新の幸運の数字が発生した場所。 

これにより、この問題は数字 DP に最適になります。 

桁位置にわたる DP を定義します。 数字を一桁ずつ構築しながら、次のことを追跡します。 

- 現在の位置、
 - 最後の幸運の数字の位置、
 - すでに有効なペアを形成しているかどうか、
 - すでに番号を開始しているかどうか、
 - まだ上限が厳しいかどうか。 

を置くたびに、`4`または`7`、その位置を前の幸運の数字と比較します。 距離が最大でも`k`、番号は永久に有効になります。 

これにより、問題は値の反復から状態の反復に変換されます。 州の総数はおおよそ次のとおりです$1000^2$、完全に管理可能です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 不可能 | 不可能 | 遅すぎる |
 | 最適な桁 DP |$O(L^2 \cdot 10)$|$O(L^2)$| 承認済み |

 ここ、$L$桁数です。 

## アルゴリズムのチュートリアル

 1. 関数を定義する`solve(x)`範囲内に幸運に近い数字がいくつあるかを返します$[0, x]$。 

その場合、すべてのクエリの答えは次のようになります。$$solve(r) - solve(l-1)$$2. 上限を数値配列に変換します。 

Digit DP は、一度に 1 桁の位置を処理するため、文字列に対して自然に機能します。 
3. 状態を指定してメモ化された DFS を使用します。$$(pos,\ last,\ found,\ started,\ tight)$$どこ：

-`pos`現在の数字のインデックスです。 
-`last`は、最新の幸運の数字の位置です。 
-`found`有効なペアがすでに存在するかどうかを示します。 
-`started`先行ゼロ以外の数字がすでに配置されているかどうかを示します。 
-`tight`現在のプレフィックスが上限プレフィックスと等しいかどうかを示します。 
4. 数字列の終わりに達したら、return`1`場合のみ`found = True`。 

これは、構築された数字がほぼ幸運であることを意味します。 
5. 現在位置の可能なすべての桁を試します。 

許可される最大桁数は次によって異なります。`tight`。 
6. 先頭のゼロは慎重に扱ってください。 

数字がまだ始まっていない場合に、さらにゼロを置くと、そのままになります。`started = False`状態であり、ゼロを実数として扱いません。 
7. 配置された数字が`4`または`7`、ラッキー情報を更新。 

前の位置に幸運の数字があった場合`last`、 そして：$$pos - last \le k$$次に設定します`found = True`。 

その後、アップデート`last = pos`。 
8. 次の位置に再帰し、答えを剰余として累積します。$10^9 + 7$。 
9. クエリごとに、次を計算します。$$(solve(r) - solve(l-1)) \bmod (10^9+7)$$### なぜ効果があるのか

 DP 状態には、将来の数字が有効なペアを作成できるかどうかを判断するために必要な情報が正確に保存されます。 

新しい幸運の数字は最新のものと比較するだけでよいため、未来は最も近い前の幸運の数字にのみ依存します。 初期の幸運の数字はより遠くにあり、これより短い距離を生み出すことはできません。 

の`found`フラグは単調です。 有効なペアが出現すると、その後の数字に関係なく、その数字はほぼ幸運なままになります。 

すべての有効な数値は 1 つの DP パスに正確に対応し、すべての DP パスは正確に 1 つの数値を表すため、カウントは正確です。 

## Python ソリューション```python
import sys
from functools import lru_cache

input = sys.stdin.readline

MOD = 10**9 + 7

def subtract_one(s):
    if s == "0":
        return "0"

    a = list(s)
    i = len(a) - 1

    while i >= 0 and a[i] == '0':
        a[i] = '9'
        i -= 1

    a[i] = str(int(a[i]) - 1)

    res = ''.join(a).lstrip('0')
    return res if res else "0"

def count_nearly_lucky(s, k):
    digits = list(map(int, s))
    n = len(digits)

    @lru_cache(None)
    def dfs(pos, last, found, started, tight):
        if pos == n:
            return 1 if found else 0

        limit = digits[pos] if tight else 9
        ans = 0

        for d in range(limit + 1):
            ntight = tight and (d == limit)

            if not started and d == 0:
                ans += dfs(pos + 1, -1, found, False, ntight)
                ans %= MOD
                continue

            nfound = found
            nlast = last

            if d == 4 or d == 7:
                if last != -1 and pos - last <= k:
                    nfound = True
                nlast = pos

            ans += dfs(pos + 1, nlast, nfound, True, ntight)
            ans %= MOD

        return ans

    return dfs(0, -1, False, False, True)

def solve():
    t, k = map(int, input().split())

    out = []

    for _ in range(t):
        l, r = input().split()

        left = subtract_one(l)

        ans = (count_nearly_lucky(r, k) -
               count_nearly_lucky(left, k)) % MOD

        out.append(str(ans))

    print('\n'.join(out))

solve()
```機能`count_nearly_lucky`からのすべての数値に対して数字 DP を実行します。`0`指定された境界まで。 

の`last`変数には、最新の幸運の数字の位置が格納されます。 それ以前の幸運の数字は将来の位置からさらに遠いため、最新のものだけを使用するだけで十分です。 

先行ゼロは次の方法で処理されます。`started`フラグ。 最初のゼロ以外の数字が表示されるまで、位置は数値の一部としてカウントされません。 この区別がないと、長さの異なる数値が互いに干渉してしまいます。 

移行:```
if last != -1 and pos - last <= k:
```が問題の核心です。 現在の幸運の数字が前の幸運の数字と十分に近いペアを形成しているかどうかを検出します。 

減算ヘルパーも微妙です。 境界には 1000 桁を含めることができるため、それらを整数に変換することはできません。 デクリメントは文字列に対して直接実行する必要があります。 

最後に、答えは常に剰余で減算されます$10^9 + 7$。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(L^2 \cdot 10)$| DP の状態は、数字の位置と最後の幸運な位置に基づいています。 
| スペース |$O(L^2)$| メモ化テーブル |

 ここ、$L$は桁数で、最大 1000 です。 

1000 桁を超える 2 次 DP は簡単に制限内に収まります。 状態数は最悪の場合でも数百万にすぎず、遷移は一定の係数で小さくなります。

## 特殊なケース

 次のことを考慮してください。```
1 1
404 404
```幸運の数字は位置にあります`0`そして`2`。 彼らの距離は`2`を超える`k = 1`。 

DP中:

 | ポジション | 数字 | ラストラッキー | 見つかりました |
 | --- | --- | --- | --- |
 | 0 | 4 | 0 | 偽 |
 | 1 | 0 | 0 | 偽 |
 | 2 | 4 | 2 | 偽 |

 条件`pos - last <= k`は失敗するため、番号は正しく拒否されます。 

次に、先頭のゼロについて考えてみましょう。```
1 2
1 9
```DP は、上限と同じ長さの数値を内部で処理します。 例えば、`4`次のように表示される場合があります`"04"`。 

なぜなら`started = False`最初のゼロ以外の数字の前の先頭のゼロは無視され、数値の一部になりません。 アルゴリズムは決して処理しません`"04"`位置に幸運な数字があるものとして`0`そして`1`。 

最後に、次のことを考慮してください。```
1 100
447000000000 447000000000
```最初の 2 桁はすでに条件を満たしています。 

| ポジション | 数字 | 見つかりました |
 | --- | --- | --- |
 | 0 | 4 | 偽 |
 | 1 | 4 | 本当 |
 | 2..11 | いろいろ | 本当 |

 一度`found`true になると、永続的に true のままになります。 それ以降の数字は番号を無効にすることはできません。
