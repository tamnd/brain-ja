 **解決時間:** 1 分 21 秒

 ## 解決策
 ## 問題の理解

 この問題は、ノードがジャンクションを表し、エッジが指定された長さの道路を表す重み付き無向グラフを提示します。 各交差点には、最大距離まで乗客を運ぶことができる固定料金のタクシーがいます。 Petya は、タクシーの総コストを最小限に抑えて、出発ジャンクションから別のジャンクションにあるスタジアムまで移動したいと考えています。 各タクシーは最初の交差点からのみ利用でき、利用は 1 回限りです。 課題は、Petya が目的地に到達するために必要な最小コストを計算するか、それが不可能であると報告することです。 

この制約は、グラフに最大 1000 個のジャンクションと 1000 個の道路を含めることができることを示しています。 道路の長さとタクシーの範囲は最大になります。$10^9$。 ジャンクションの数が少ないため、3 次複雑さのアルゴリズム (フロイド-ウォーシャルなど) やダイクストラの複数回の実行が可能です。 タクシー乗車のすべてのシーケンスをチェックする単純なアプローチでは、指数関数的に増加し、実行不可能になります。 切断されたグラフやタクシー範囲で特定のジャンクションを接続できない状況では、特別な注意が必要です。 

明らかではないエッジ ケースは、タクシーの走行距離が、より長いマルチエッジ パスを通らなければ近隣のタクシーに到達できない場合に発生します。 たとえば、ジャンクションには長さ 2 と 5 のエッジを介して接続された 2 つの隣接道路がありますが、そのタクシー範囲は 3 です。各道路を個別に扱う単純な BFS では、タクシーがさらに隣の交差点に到達できないことを考慮できない可能性があります。 もう 1 つのエッジ ケースは、出発地と目的地が同じジャンクションである場合で、コストがゼロになるはずです。 

## アプローチ

 この強引な方法は、タクシー乗車のすべてのシーケンスを調査することです。 Petya が到達する各交差点で、到達可能な近隣の距離を制限するタクシーに乗車することを試みることができます。 新しいジャンクションに到達するたびに、残りのすべてのタクシーを再帰的に試行します。 このアプローチは、すべての有効な乗車シーケンスを列挙するため正しいですが、ジャンクションの数が指数関数的であるため、$n = 20$。 

重要な洞察は、各タクシーを「スーパーエッジジェネレーター」として扱うことです。 タクシーを利用すると、ジャンクションからタクシーの範囲内の他のジャンクションに到達できます。 これは、エッジの長さを含む元のグラフに対してダイクストラのアルゴリズムを使用して事前計算し、各タクシーが到達可能なジャンクションのセットを決定できます。 各タクシーがどのノードに到達できるかがわかれば、問題はグラフ上の重み付けされた最短経路に帰着します。ここで、ノードはジャンクションであり、エッジは「このジャンクションから到達可能なジャンクションまでのタクシー乗車とそのコスト」を表します。 これで、エッジの重みが距離ではなくタクシー料金であるこの新しいグラフでダイクストラを実行できるようになりました。 

ブルートフォースは正しいですが、遅すぎます。 各タクシーの到達可能なジャンクションを事前に計算することで大幅な速度向上が可能になり、タクシー グラフにダイクストラを適用すると、総コストを効率的に最小化できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | お(ん!) | O(n) | 遅すぎる |
 | タクシー リーチ + ダイクストラを事前計算する | O(n * (m + n log n) + n^2) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. n 個のノードと m 個の重み付きエッジを含む元のグラフを隣接リストとして構築します。 これにより、すべての近隣地域とその道路距離に迅速にアクセスできるようになります。 
2. 各ジャンクションについて、そのジャンクションからタクシーのみを使用して他のどのジャンクションに到達できるかを計算します。 道路の距離を考慮して、その交差点からダイクストラを実行し、タクシーの距離制限内のすべてのノードを到達可能としてマークします。 ジャンクションごとに到達可能なセットを保存します。 
3. u のタクシーが v に到達できる場合、ノード u からノード v までのエッジが存在する新しいグラフを構築します。このエッジの重みが u でのタクシー コストです。 これにより、問題は、物理的な距離ではなく、タクシーの総コストを最小限に抑えることが目標となる標準的な最短経路問題に変換されます。 
4. 新しいタクシー グラフ上の最初のジャンクション x から開始してダイクストラのアルゴリズムを実行します。 優先キューを使用して、各ジャンクションに到達するための最小限のコストを維持します。 現在のジャンクションからタクシーを利用した方が総コストが安くなる場合は、近隣住民を更新します。 
5. ダイクストラ実行中に最終接点 y に到達した場合は、計算された最小コストを返します。 到達できない場合は、-1 を出力します。 

機能する理由: タクシー グラフの各エッジがタクシーの許容距離内の有効な乗車を表すため、アルゴリズムは正確さを保証します。 ダイクストラは、最小累積コストが到達可能なすべてのジャンクションに正しく伝播されることを保証します。 各タクシーは最大 1 回使用され、元のジャンクションからの乗車のみが考慮されるため、使用上の制約が尊重されます。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

n, m = map(int, input().split())
x, y = map(int, input().split())
x -= 1
y -= 1

graph = [[] for _ in range(n)]
for _ in range(m):
    u, v, w = map(int, input().split())
    u -= 1
    v -= 1
    graph[u].append((v, w))
    graph[v].append((u, w))

taxi_info = []
for _ in range(n):
    t, c = map(int, input().split())
    taxi_info.append((t, c))

# Step 1: compute reachable nodes for each taxi
reachable = [[] for _ in range(n)]
for u in range(n):
    max_dist = taxi_info[u][0]
    dist = [float('inf')] * n
    dist[u] = 0
    heap = [(0, u)]
    while heap:
        d, v = heapq.heappop(heap)
        if d > dist[v]:
            continue
        for to, w in graph[v]:
            if dist[v] + w <= max_dist and dist[v] + w < dist[to]:
                dist[to] = dist[v] + w
                heapq.heappush(heap, (dist[to], to))
    for v in range(n):
        if dist[v] <= max_dist and v != u:
            reachable[u].append(v)

# Step 2: Dijkstra on taxi-graph
cost = [float('inf')] * n
cost[x] = 0
heap = [(0, x)]
while heap:
    c_acc, u = heapq.heappop(heap)
    if c_acc > cost[u]:
        continue
    for v in reachable[u]:
        c_next = c_acc + taxi_info[u][1]
        if c_next < cost[v]:
            cost[v] = c_next
            heapq.heappush(heap, (c_next, v))

print(cost[y] if cost[y] != float('inf') else -1)
```最初の部分は入力を読み取り、都市グラフの隣接リストを構築します。 次に、各タクシーに対してダイクストラを実行して、距離制限内で到達可能なすべてのジャンクションを決定します。 最後に、エッジがタクシー乗車に対応するダイクストラ ループ内でタクシー グラフを暗黙的に構築します。 プライオリティ キューにより、最小のコストで最初にノードに到達したときが最適なソリューションとなることが保証されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n * (m + n log n) + n^2) | 各タクシーのダイクストラには O(m + n log n) がかかり、さらにタクシー グラフ上のダイクストラもかかります。 
| スペース | O(n^2 + m) | 到達可能リスト O(n^2)、隣接リスト O(m) |

 n ≤ 1000 および m ≤ 1000 の場合、これは 2 秒以内に快適に適合します。 メモリ使用量は 256 MB をはるかに下回ります。
