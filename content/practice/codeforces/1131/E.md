 ## 解決策
 ## 問題の理解

 高度に構造化された文字列操作のプロパティを計算するように求められます。 文字列のシーケンスが与えられます$p_1, p_2, \dots, p_n$そして、デニスの文字列乗算を繰り返し適用するように求められます。$p_1 \cdot p_2 \cdot \dots \cdot p_n$順番に。 掛け算$s \cdot t$インサート$t$各文字の前後$s$、そして最初に一度。 すべての乗算を実行した後、結果の文字列の「美しさ」を計算する必要があります。これは、単一文字の最も長い連続ブロックの長さです。 

素朴なアプローチは、乗算ルールに段階的に従って、文字通り結果の文字列を構築することです。 ただし、乗算するたびに文字列の長さが大幅に増加する可能性があります。 長さの文字列$m$長さの文字列を乗算する$k$長さの文字列を生成します$k \cdot (m+1) + m$、指数関数的に増加する可能性があります。 と$n$まで$10^5$入力の合計長さは次のとおりです$10^5$、メモリと時間の制限内では、最終的な文字列を構築することは不可能です。 したがって、文字列を明示的に構築せずに美しさについて推論する必要があります。 

重要な非明白なケースは、文字列全体が単一の繰り返し文字で構成されている場合に発生します。 もし$p_i$「ああ」です、そして$p_{i+1}$も「aaa」である場合、乗算により、どちらかの文字列を個別に作成するよりも長い連続ブロックが作成される可能性があります。 逆に、文字が異なる場合は、同じ文字のプレフィックスとサフィックスが挿入間でどのようにマージされるかを考慮する必要があります。 小さな例としては、$p_1 = a, p_2 = a, p_3 = b$最初/最後の文字シーケンスを注意深く追跡する必要があることを示します。 不用意に実装すると、極大値だけを見て、連結された実行を見逃してしまう可能性があります。 

## アプローチ

 ブルートフォース手法では、完全な文字列を繰り返し構築し、各乗算後に同一文字の最長の連続ブロックを計算します。 これは乗算の定義に直接従うため、原理的には正しいですが、各ステップでは文字列サイズが乗算的に増加します。 最悪の場合、最終的な文字列の長さは次のような長さに達する可能性があります。$10^{100}$すべての文字列の長さが 2 の場合、$n=100$、それは不可能です。 

最適なアプローチでは、完全な文字列の構築が回避されます。 各文字列を効率的にマージするには、各文字列から 3 つの情報のみが必要です。それは、最大の内部の美しさ (文字列内の最長のブロック)、同一文字の接頭辞の長さ、および同一文字の接尾辞の長さです。 これにより、2本の紐を組み合わせた際に蓄積された美しさをアップデートすることができます。 洞察としては、乗算は、ある文字列の接尾辞を次の文字列の繰り返し文字とマージすることによってのみ内部の美しさに影響を与えるということです。 次の文字列が完全に 1 文字である場合、前のブロック長を倍増する可能性があります。 それ以外の場合は、プレフィックス、サフィックス、および内部最大値のみが問題になります。 文字列を順次処理する際にこれらの値を維持することで、合計入力サイズに関して線形時間で最終的な美しさを計算できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(最終文字列の全長) | O(最終文字列の全長) | 遅すぎる |
 | 最適 | O(入力文字列の長さの合計) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力文字列ごとに$p_i$、連続する同一文字の最大ブロック、および繰り返される文字のプレフィックスとサフィックスの長さを計算します。 
2. 最初の文字列の値を使用して、蓄積された美しさを初期化します。 
3. 残りの文字列を繰り返し処理します。 各文字列について、まずそれが完全に 1 つの繰り返し文字であるかどうかを検討します。 その場合は、繰り返しの挿入によって形成された連続ブロックを考慮した乗算ルールを使用して、累積されたプレフィックスとサフィックスの長さを更新します。 
4. 現在の文字列に複数の一意の文字がある場合は、最大の美しさを 3 つの候補のうち最大のものとして更新します。つまり、以前に蓄積された美しさ、現在の文字列内の内部最大ブロック、および前のサフィックス、現在の文字列の 1 つの出現、および現在のプレフィックスを組み合わせて形成される潜在的なマージ ブロックです。 
5. 蓄積されたプレフィックスとサフィックスを更新します。以前に蓄積された文字列が完全に単一の繰り返し文字であり、現在の文字列のプレフィックスがこの文字と一致する場合、新しいプレフィックスは繰り返しパターンを含むように拡張される可能性があります。 同じことがサフィックスにも当てはまります。 
6.全ての弦を加工し、積み重ねた最大限の美しさが答えです。 

機能する理由: 各ステップで、アルゴリズムは 3 つの不変条件を維持します。それは、これまでの最大の美しさ、先頭の同一文字のプレフィックス長、および末尾の同一文字のサフィックスの長さです。 乗算はこれらの値を予測可能な方法で拡張するだけであるため、より長く連続するブロックが見落とされる可能性はありません。 これらの概要統計のみを追跡することで、指数関数的に増加する文字列を構築することを回避できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n = int(input())
    strings = [input().strip() for _ in range(n)]

    # helper to compute prefix, suffix, internal max
    def analyze(s):
        max_block = 1
        cur = 1
        for i in range(1, len(s)):
            if s[i] == s[i-1]:
                cur += 1
                max_block = max(max_block, cur)
            else:
                cur = 1
        # prefix length
        pre = 1
        while pre < len(s) and s[pre] == s[0]:
            pre += 1
        # suffix length
        suf = 1
        i = len(s)-2
        while i >= 0 and s[i] == s[-1]:
            suf += 1
            i -= 1
        return s[0], s[-1], pre, suf, max_block, len(s)

    # process first string
    f_char, l_char, pre_len, suf_len, max_beauty, total_len = analyze(strings[0])
    full_same = (pre_len == total_len)

    for s in strings[1:]:
        c1, c2, p, su, mb, l = analyze(s)
        if full_same and f_char == c1:
            # previous is all same char
            if mb == l:
                max_beauty = max(max_beauty, (suf_len+1)* (l+1) -1) # multiplication effect
            suf_len = (suf_len + 1) * l + su
            pre_len = (pre_len + 1) * l + p
            f_char = f_char
            l_char = c2
            full_same = (mb == l)
        else:
            # compute merged beauty at junctions
            if l_char == c1:
                max_beauty = max(max_beauty, suf_len + 1 + p)
            max_beauty = max(max_beauty, mb)
            # update prefix/suffix for new accumulated string
            pre_len = pre_len if f_char != c1 else pre_len + p
            suf_len = su if c2 != l_char else su + suf_len
            f_char = f_char
            l_char = c2
            full_same = False

    print(max_beauty)

if __name__ == "__main__":
    main()
```このソリューションでは、まず内部ブロック長と各文字列のプレフィックス/サフィックスを事前計算します。 次に、完全な文字列を構築することなく、これらの統計を繰り返しマージして蓄積された「文字列の概要」を作成します。 乗算によりブロック長が指数関数的に増大する可能性があるため、文字列全体が単一の繰り返し文字で構成されている場合は、特別な注意が必要です。
