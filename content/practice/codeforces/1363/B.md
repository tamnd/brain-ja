 ## 解決策

 ## 問題の理解

 バイナリ文字列が与えられ、任意の文字を何度でも反転することができます。 反転するたびに、単一のビットが 0 から 1、または 1 から 0 に変更されます。目標は、文字列が「良好」になるように変換することです。つまり、3 つのインデックスを昇順に選択しようとしても、サブシーケンス 0, 1, 0 またはサブシーケンス 1, 0, 1 を決して形成できないはずです。 

重要な点は、ここでのサブシーケンスには隣接性が必要ないということです。 キャラクターが離れていても、順番に表示されれば十分です。 したがって、条件はローカルではなくグローバルです。 010 のようなパターンを部分文字列としてだけでなく、文字列内の任意の部分シーケンスとしても避けています。 

長さの制約は小さく、文字列あたり最大 1000、テスト ケースは最大 100 です。 これは、テスト ケースごとに 2 次以降のような高度な最適化の必要性を即座に排除しますが、文字列ごとに O(n) または O(n log n) のソリューションで簡単に十分であることも示唆しています。 O(n^2) でも合格する可能性がありますが、条件の構造から、それは必要ないことがわかります。 

文字が隣接していない場合でも、サブシーケンス パターンが形成される可能性があるという事実から、微妙なエッジ ケースが発生します。 たとえば、1001 のような文字列には、部分文字列 101 はありませんが、部分シーケンス 1 (最初の文字)、0 (2 番目の文字)、1 (最後) があります。 部分文字列またはローカル パターンのみをチェックする単純なアプローチは、ここでは失敗します。 もう 1 つの罠は、隣接していない交替でも禁止されたサブシーケンスを形成する可能性があるため、すべての交替を削除すれば十分であると考えることです。 

最大の難点は、1 つの文字を反転すると、ローカル構造だけでなく、多くの潜在的なサブシーケンスにグローバルに影響を与えるため、「適切な」文字列がどのようなものであるかをグローバルに特徴付ける必要があることです。 

## アプローチ

 まず、サブシーケンスとして 010 または 101 を含めることができないバイナリ文字列の種類を尋ねます。 これを考える強引な方法は、可能なすべてのフリップ セットを試し、到達可能なすべての文字列を生成し、禁止されたサブシーケンスについてそれぞれをテストすることです。 文字列のサブシーケンスとして 010 または 101 をチェックすることは O(n) で実行でき、2^n 通りの反転構成が可能なため、このアプローチは n = 1000 の場合でも完全に実行不可能です。 

代わりに、どのような構造的特性が両方のパターンを妨げるかを理解しようとします。 文字列に 0 と 1 の両方が含まれており、それらが柔軟な方法でインターリーブされている場合、0、次に 1、次に別の 0、またはその逆を選択することが可能になります。 重要な観察は、0 と 1 の間の複数の遷移を持つ「混合」構造では、これらの交互のサブシーケンスのための余地が生まれるということです。 

これを考えるのに役立つ方法は、最後の文字列を考慮することです。 良い場合、パターン 010 と 101 の両方をサブシーケンスとして持つことはできません。 これにより、文字列は非常に制限された形状になります。0 と 1 の間の「遷移」は最大でも 1 つだけです。それ以外の場合は、異なるビットの複数のブロックにより、交互のサブシーケンスを構築できます。 

したがって、適切な文字列は、すべて 0 の後にすべて 1 が続く形式、またはすべての 1 の後にすべて 0 が続く形式、または完全に均一である必要があります。 これらはまさに、シンボル間の境界が最大 1 つしかない単調なバイナリ文字列です。 

これにより、問題は単純な変換タスクに集約されます。元の文字列が与えられた場合、最小限の反転でそれを 000…0111…1 または 111…1000…0 に変換する必要があります。 すべての分割ポイントに対する総当り攻撃が簡単になりました。位置ごとに、左側のすべてを 1 つの値に、右側のすべてをもう 1 つの値に等しくするために必要なフリップの回数を計算し、両方の方向の最小値を取得します。 

これにより、問題はサブシーケンスに関する推論から、プレフィックス カウントを使用した線形スキャンに軽減されます。

 | 最適 (試行分割 + プレフィックス数) | 文字列あたり O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 分割を迅速に評価するために、ゼロと 1 のプレフィックス カウントを構築します。 

1. テスト ケースごとに、文字列の接頭辞に 0 と 1 がいくつ出現するかをクエリできる接頭辞配列を計算します。 これにより、どのセグメントでも一定の時間をカウントすることができます。 
2. 最後の文字列を 000…0111…1 の形式にすることを検討してください。 考えられるすべての分割位置 i について、位置 [0, i) はすべて 0 になり、位置 [i, n) はすべて 1 になると仮定します。 
3. 固定分割 i の場合、左側の部分の 1 の数 (ゼロに反転する必要がある) と右側の部分の 0 の数 (1 に反転する必要がある) としてコストを計算します。 これは、ターゲット構造との不一致を直接カウントします。 
4. 逆のパターン 111…1000…0 に対して同じプロセスを繰り返します。左はすべて 1、右はすべて 0 になります。コストは、左の 0 と右の 1 です。 
5. すべての分割および両方のパターンにわたる最小コストを取得します。 それがテストケースの答えです。 

単一の分割構造に制限できる主な理由は、有効な最終文字列には 2 つの別個の代替を含めることができないためです。 そうすれば、各地域の代表者を選択して、サブシーケンスとして 010 または 101 のいずれかを構築できるようになります。 したがって、すべての有効な文字列は、この単純な 2 つのブロック形式に折りたたまれます。 

### なぜ効果があるのか

 交互のセグメントから常に文字を選択できるため、0 と 1 の間の遷移が複数ある文字列には、必ずパターン 010 と 101 の両方がサブシーケンスとして含まれます。 したがって、すべての有効なターゲットには最大 1 つの遷移が必要です。 私たちのアルゴリズムは、すべての分割点と可能な両方の向きを試すことによって、そのような有効なターゲットをすべて暗黙的に列挙します。 各候補構造までの正確なハミング距離 (必要なフリップの数) を計算するため、すべての候補の最小値が最適な演算数になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    s = input().strip()
    n = len(s)

    pref0 = [0] * (n + 1)
    pref1 = [0] * (n + 1)

    for i, ch in enumerate(s):
        pref0[i + 1] = pref0[i] + (ch == '0')
        pref1[i + 1] = pref1[i] + (ch == '1')

    ans = n

    for i in range(n + 1):
        left_ones = pref1[i]
        right_zeros = pref0[n] - pref0[i]
        cost01 = left_ones + right_zeros

        left_zeros = pref0[i]
        right_ones = pref1[n] - pref1[i]
        cost10 = left_zeros + right_ones

        ans = min(ans, cost01, cost10)

    print(ans)
```この実装は、O(1) のセグメント数を評価するためにプレフィックスの合計に依存しています。 分割ポイント上のループにより、単一の許可された遷移のすべての可能な位置が確実に考慮されます。 2 つのコスト式は、それぞれの半分の不一致ビットを反転することに正確に対応します。 分割はプレフィックス境界 [0, i) とサフィックス [i, n)] として定義されているため、off-by-one の問題は発生しません。 

## 実用的な例

 2 つの入力をトレースして、分割評価がどのように動作するかを確認します。 

最初の入力は`001`。 

| スプリット i | コスト000→111? | コスト111→000？ | 分 |

 最良の値は、パターン 111→000 のスプリット 3 で 0 であり、正しい構造を選択した場合は変更が必要ないことと一致します。 

このトレースは、小さな文字列であっても、遷移が配置される場所に応じて複数の有効な最適な構造が許容される可能性があり、アルゴリズムがそれらすべてを体系的に評価することを示しています。 

2番目の入力は`001100`。 

| スプリット i | コスト000→111 | コスト111→000 | 分 |

 最小値は 2 で、モノトーン構造に一致させるために 2 つの不一致ビットを反転することに対応します。 これは、最適な解決策が同一の文字をグループ化することに依存するのではなく、単一の遷移境界をグローバルに適用することに依存することを示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        s = input().strip()
        n = len(s)

        pref0 = [0] * (n + 1)
        pref1 = [0] * (n + 1)

        for i, ch in enumerate(s):
            pref0[i + 1] = pref0[i] + (ch == '0')
            pref1[i + 1] = pref1[i] + (ch == '1')

        ans = n
        for i in range(n + 1):
            cost01 = pref1[i] + (pref0[n] - pref0[i])
            cost10 = pref0[i] + (pref1[n] - pref1[i])
            ans = min(ans, cost01, cost10)

        out.append(str(ans))

    return "\n".join(out)

 ## 特殊なケース

 のような文字列の場合`010`、アルゴリズムはすべての分割を考慮します。 分割 i = 1 では、000→111 のコストは 1 (中央を反転)、111→000 のコストも 1 となり、答えは 1 になります。これは、交互構造を削除するには 1 回の反転で十分であるという直観と一致します。 

のような文字列の場合`111000`、最適な分割はブロック間の境界にあり、コストは 0 になります。プレフィックスの合計は、正しい方向に位置合わせされた場合に不一致が存在しないことを正確に反映しており、アルゴリズムが特別な処理を行わずにすでに良好な文字列を自然に検出していることが確認されています。
