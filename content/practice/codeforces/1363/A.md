 ## 解決策
 ## 問題の理解

 整数の配列が与えられているので、正確に選択する必要があります`x`そこからの要素。 選択した要素は、配列内の任意の位置から取得できます。 問題は、正確な選択が存在するかどうかです。`x`合計が奇数の要素。 

数値の実際の値は、その等価性を超えて重要ではありません。 すべての整数は奇数か偶数のいずれかであり、合計のパリティは含まれる奇数の数によってのみ決まります。 和が奇数であるのは、奇数の奇数の要素が含まれている場合に限ります。 

制約は小さいです。 各テスト ケースには最大 1000 個の数値が含まれ、テスト ケースは最大 100 個あります。 たとえ`O(n²)`この解は許容可能ですが、パリティ観測により、さらに単純な線形解が可能になります。 動的プログラミングやサブセットの列挙は必要ありません。 

いくつかの特殊なケースは見落とされがちです。 

偶数のみを含む配列を考えてみましょう。```
1
4 3
2 4 6 8
```正しい答えは、`No`。 偶数の合計は偶数のままです。 かどうかだけを確認するいい加減な解決策`x`奇数だとここで失敗します。 

奇数のみを含む配列を考えてみましょう。```
1
4 2
1 3 5 7
```正しい答えは、`No`。 2 つの奇数を選択すると、偶数の合計が得られます。 一部の実装では、奇数を使用できれば常に十分であると誤って想定されています。 

すべての要素を取得する必要がある場合を考えてみましょう。```
1
3 3
1 2 3
```合計金額は`6`、これは偶数なので、答えは次のようになります。`No`。 いつ`x = n`、選択可能な選択肢は 1 つだけです。 

もう 1 つの微妙なケースは、合計を奇数にするのに十分な奇数があるが、残りのスロットを有効なパリティで埋めるのに十分な合計要素がない場合に発生します。```
1
3 3
1 2 2
```3つの要素をすべて取り入れなければなりません。 合計は`5`、したがって、答えは次のとおりです`Yes`。 実現可能性は、奇数要素の数と正確に選択する要件の両方に依存します。`x`要素。 

## アプローチ

 ブルートフォースアプローチでは、サイズのすべてのサブセットが列挙されます。`x`そしてそれらの合計が奇数であるかどうかを確認します。 これは、考えられるすべての選択肢を検討するため、正しいです。 問題は、そのようなサブセットの数です。 最悪の場合は検査が必要になる$$\binom{1000}{500}$$さまざまな選択があり、これは天文学的に膨大であり、制限時間内ではまったく不可能です。 

重要な観察は、パリティのみが重要であるということです。 させて`odd`配列内の奇数の要素の数であり、`even`偶数要素の数になります。 

選択された奇数要素の数が奇数の場合、選択された合計は奇数になります。 選択するとします`k`奇妙な要素。 それから：$$k + \text{chosen even elements} = x$$残りの選択された要素は偶数の要素である必要があるため、次のものが必要です。$$x - k \le even$$そしてまた$$k \le odd$$値`k`最終的な合計は奇数でなければならないため、奇数でなければなりません。 

問題は、奇数の整数が存在するかどうかです。`k`次のような:$$1 \le k \le odd$$そして$$x-k \le even$$そして$$k \le x$$多くてもあります`x`可能な値`k`したがって、奇数の値をすべてチェックするのは簡単です。

 ## アルゴリズムのチュートリアル

 1. 配列内の奇数要素と偶数要素の数を数えます。 
2. すべての奇数の値を試します`k`から`1`まで`min(odd, x)`。 
3. 治療する`k`選択したい奇数要素の数として指定します。 以来`k`奇数、正確に使用した有効な選択`k`奇数の要素の合計は奇数になります。 
4. コンピューティング`need_even = x - k`。 これらは偶数の要素で埋める必要がある残りの位置です。 
5. かどうかを確認します。`need_even`が非負であるかどうか`need_even <= even`。 両方の条件が当てはまれば、正確に選択を構築できます。`x`要素。 
6. おかしな点があれば`k`条件を満たしている場合、印刷します`Yes`。 
7. 機能する候補がない場合は、印刷します。`No`。 

### なぜ効果があるのか

 合計のパリティは、含まれる奇数の数のみに依存します。 そのカウントが奇数の場合、合計は奇数になります。 

アルゴリズムは考えられるすべての奇数カウントをチェックします`k`有効な選択範囲に表示される可能性があります。 そういったそれぞれに対して`k`、それらを提供するのに十分な奇妙な要素が存在するかどうかを検証します。`k`残りを埋めるのに十分な数の偶数要素が存在します。`x-k`ポジション。 

アルゴリズムが実行可能であると判断した場合`k`、実際の選択はこれらのカウントから直接構築できます。 あらゆる奇数の場合`k`失敗すると、必要なサイズと奇数パリティの両方を持つ選択はできなくなります。 すべての有効な解は、次の奇数の値に対応する必要があるため、`k`、アルゴリズムは完全であり、解決策を見逃すことはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n, x = map(int, input().split())
        a = list(map(int, input().split()))

        odd = sum(v % 2 for v in a)
        even = n - odd

        possible = False

        for k in range(1, min(odd, x) + 1, 2):
            need_even = x - k
            if need_even <= even:
                possible = True
                break

        ans.append("Yes" if possible else "No")

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```ソリューションの最初の部分では、奇数要素と偶数要素をカウントします。 それ以外の価値観は何も重要ではありません。 

ループオーバー`k`選択した奇数の考えられるすべての奇数カウントをチェックします。 ステップサイズは`2`、すべての候補者が`k`奇数です。 

条件`need_even <= even`選択を完了するのに十分な偶数が存在することを確認します。 個別のチェックは必要ありません。`need_even >= 0`ループは考慮するだけなので、`k <= x`。 

実現可能な構成が 1 つ見つかるとすぐに、答えは次のようにわかります。`Yes`, そのため、ループは早期に終了します。 

カウントのみが操作されるため、大きな値については特別な処理は必要ありません。 Python では整数のオーバーフローは不可能であり、とにかくカウントが 1000 を超えることはありません。
