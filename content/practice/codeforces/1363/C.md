 ## 解決策
 ## 問題の理解

 ゲームは、無向で接続された非循環グラフであるツリー上でプレイされます。 各ノードには次の番号が付けられます。$1$に$n$、および 1 つのノード$x$は特別です。 2 人のプレイヤーが交代でリーフ ノードを削除します。リーフとは、隣接するノードが 1 つだけあるノードとその接続エッジです。 スペシャルノードを削除するプレイヤー$x$勝ちます。 Ayush が最初に動き、最適なプレイでどちらのプレイヤーが勝つかを決定することが課題となります。 

入力ではツリーを次のように説明します。$n$ノードと$n-1$エッジ、その後に多数のテスト ケースが続く$t$。 出力は、各テスト ケースの勝者を識別する文字列です。 ノード数$n$せいぜい$1000$したがって、二次関数のアルゴリズムはすべて、$n$またはそれ以上の場合は効率的に実行されます。 

明らかではないエッジケースには、特殊なノードが存在する状況が含まれます。$x$すでに葉になっているので、Ayush は最初のターンに葉を除去してすぐに勝つことができます。 別の微妙なケースが発生するのは、$x$には近隣ノードが 1 つだけあり、ノードの総数は少ないです。 不注意な解決策がすべてのノードの次数が少なくとも 2 であると仮定した場合、または周囲の構造をチェックせずに盲目的にターンを交互に配置した場合$x$、間違った結果が得られます。 

たとえば、次のような木があるとします。$n=3$、$x=1$、およびエッジ$1-2$そして$1-3$。 ノード$2$そして$3$葉です。 Ayush はこれらのうち 1 つだけを削除できます。その後は$1$が葉になり、アシシュがそれを取り除くことができ、ゲームに勝ちます。 これは、たとえ小さな木であっても、周囲の局所的な構造が$x$結果が決まります。 

## アプローチ

 ブルートフォース手法では、ゲームを明示的にシミュレートします。 各ターンで、現在のリーフをすべて列挙し、考えられる各移動の結果としてツリーを生成し、次のターンの勝者を再帰的に計算します。 この方法はルールを直接適用し、すべてのゲーム状態を調査するため正しいですが、次のような場合には指数関数的に遅くなります。$n$サブツリーの数が急速に増加するため、$n$は最大 1000 になる可能性があるため、このアプローチは実行不可能になります。 

最適なアプローチは、ゲームが特別なノードの程度によって完全に決定されるという洞察を利用します。$x$およびノー​​ドの総数のパリティ。 もし$x$学位を持っています$1$または$0$, それは葉っぱか孤立しているので、アユシュはすぐにそれを除去して勝つことができます。 それ以外の場合、ゲームは単純なターンベースの除去と同等になります。$n-1$最後の動きで勝者が決まります。 具体的には、$n$均等であれば、Ayush が最後の葉を取り除いて勝ちます。 もし$n$は奇妙ですが、Ashish が最後の葉を取り除いて勝ちます。 この観察により、問題は次の程度を確認することに帰着します。$x$とのパリティ$n$、シミュレーションを回避します。

 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る$t$。 
2. 各テスト ケースについて、ノードの数を読み取ります。$n$そして特別なノード$x$。 
3. ツリーの隣接リストを$n-1$エッジ。 
4. 特殊ノードの次数を計算する$x$。 
5.次の程度の場合$x$は$1$または$0$, アユシュは初手で除去できるので即勝ちです。 
6. それ以外の場合は、パリティをチェックします。$n$。 もし$n$が互角の場合、Ayush が勝ちます。 もし$n$奇妙です、アシッシュが勝ちます。 その理由は、各移動によってノードが 1 つだけ削除され、残りのノードの総数が 1 になったときに移動するプレイヤーが移動するということです。$1$勝ちます。 

機能する理由: 重要な不変条件は、誰が最後のノードを強制的に削除するかによって勝者が決まるということです。 もし$x$最初は葉っぱですが、Ayush はすぐに勝ちます。 それ以外の場合、移動するたびにノードの数が 1 つずつ減るため、次のパリティは$n$最初の移動を基準にして、誰が最後のノードを削除するかを決定します。 このアルゴリズムは、明示的なシミュレーションを行わずにツリー構造を利用します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    t = int(input())
    for _ in range(t):
        n, x = map(int, input().split())
        adj = [[] for _ in range(n + 1)]
        for _ in range(n - 1):
            u, v = map(int, input().split())
            adj[u].append(v)
            adj[v].append(u)
        if len(adj[x]) <= 1:
            print("Ayush")
        else:
            if n % 2 == 0:
                print("Ayush")
            else:
                print("Ashish")

if __name__ == "__main__":
    main()
```このソリューションでは、まず入力を効率的に読み取り、ツリーの隣接リストを構築します。 チェック中`len(adj[x])`特別なノードの次数を示し、即時の勝利シナリオを直接決定します。 パリティチェックオン`n`次の場合の動きの交代を説明します。$x$葉ではありません。 ループ内で複数のテスト ケースを処理することで、さまざまな入力に対する正確性が保証されます。 微妙なポイントは、`n+1`隣接関係が 1 から始まるノード インデックスと一致するようにします。

 ## 特殊なケース

 ツリーが単一のノードで構成されている場合、そのノードは自動的にリーフになります。 アルゴリズムはチェックすることでこれを処理します。`len(adj[x]) <= 1`、アユシュが勝者として正しく報告されています。 

x が最初はリーフであるが n > 1 の場合、Ayush がすぐに勝ち、隣接リストに正しく表示されます。`len(adj[x]) == 1`、適切な分岐をトリガーします。 

x が次数 > 1 の中心ノードである長いチェーンまたはツリーの場合、n のパリティが結果を決定します。 1 ベースのインデックスを使用して隣接リストを構築すると、次数の計算が正確になり、モジュロ チェックによって最後のノードを削除するプレーヤーが正しく識別されます。 これらのエッジ ケースは、構造ベースのロジックとパリティ ベースのロジックの両方が正しく実装されていることを確認します。
