 ## 解決策
 ## 問題の理解

 それぞれが正の整数であるいくつかの重みが与えられ、天秤の左皿に置くことができる質量を表します。 右側のパンには、重量を確認したい製品を置くことができます。 秤は正確であると想定されており、任意の回数の計量を実行できます。 

重要な考え方は、重みの固定セットでは、必ずしもすべてのターゲットの重みを一意に識別できるわけではないということです。 一部の重量はあいまいなバランス結果を生成する可能性があり、製品重量が異なると同じ順序のバランス結果が得られる可能性があります。 タスクは最大の整数値を決定することです`p`重量のあるすべての製品が`1`まで`p`これらの重量と繰り返しの重量を使用して、一意に識別できます。 

この問題をより構造的に捉える方法は、重みが符号付きの組み合わせを通じて表現可能な値のシステムを定義するということです。 各重み付けにより、係数を選択するかのように動作する比較が効果的に可能になります。`{-1, 0, 1}`重量ごとに。 中心的な問題は、この符号付き表現を整数の表現可能性において衝突することなくどこまで拡張できるかということです。 

制約`n ≤ 2 * 10^5`サブセットを列挙するだけでも指数関数的に増加するため、達成可能なすべての合計を明示的にシミュレートしようとするアプローチは直ちに除外されます。 到達可能なすべての値に対する動的プログラミングであっても、重みが次の値に達するため失敗します。`10^9`、高密度範囲のDPは実行不可能になります。 

重みがまばらすぎるか縮退している場合、微妙なエッジ ケースが発生します。 たとえば、重みが 1 つしかない場合、`[5]`の場合、から重みをまったく一意に決定することはできません。`1`に`4`なぜなら、重み付けの組み合わせを使用してそれらを明確に表すことができないからです。 この場合の正解は、`0`たとえ素朴な解釈では 5 の倍数を測定できると思われるかもしれません。 

もう 1 つの特殊なケースは、重みが大きいものの、小さな増分が含まれる場合です。`[1, 3]`。 ここでは、次の重みを区別できます。`4`ただし、必ずしもそれを超えるわけではありません。その点を超えると、達成可能なバランスの結果に関して表現が重複し始めるからです。 

## アプローチ

 ブルートフォース解釈では、複数の計量にわたって各重量を左パン、右パン、または未使用のパンに割り当てるすべての可能な方法をシミュレートし、どの製品重量が一意に識別可能であるかを確認しようとします。 各重みには計量ごとに 3 つの状態があり、単一の計量でもすでに`3^n`構成。 複数の重み付けが許可されると、状態空間はさらに拡大し、中程度の重み付けであっても探索できなくなります。`n`。 

重要な洞察は、複数の重み付けによって、指定された重み付けの符号付きの組み合わせを超えて表現力が根本的に向上するわけではないということです。 それぞれの重みは固定の「解像度スケール」に寄与し、システムは数字を表すことができる数値ベースを構築するように動作します。`-1, 0, 1`。 制限要因は、表現可能性において隙間なく整数ラインを継続的にカバーできるかどうかになります。 

重みをソートすると、昇順に処理して最大連続範囲を維持できます。`[0, p]`ユニークに表現できるのです。 新しい重みが追加されるたびに、この範囲が拡張されるか、ギャップが作成されます。 現在、次の値までのすべての値を表現できる場合、`p`、次に新しい重み`x`この範囲を拡張できるのは次の場合のみです`x ≤ p + 1`。 そうしないと、次の部分に隙間が生じます。`p + 1`となり、その値を一意に表現できなくなり、プロセスが停止します。 

これにより、表現可能な値の到達可能なプレフィックスを維持しながら、問題をソートされた重みに対する貪欲なスキャンに変換します。

 ## アルゴリズムのチュートリアル

 1. 重みの配列を降順でない順に並べ替えます。 これにより、表現可能な範囲を拡張できる順序で処理できるようになります。 
2. 変数を初期化する`p = 0`、現在一意に決定できる最大重量値を表します。 
3. 各重みを反復処理します。`x`ソートされた順序で。 各ステップで、この重みが連続した表現可能な範囲を拡張できるかどうかを確認します。 

その理由は、すでにすべての重みを一意に決定できる場合、`p`の場合、次の欠損値は`p + 1`。 システムを拡張するには、新しい重みがこの次の値を「ブリッジ」またはカバーできる必要があります。 
4. もし`x > p + 1`、すぐに停止します。 これは、ギャップがあることを意味します`p + 1`これは、以前の重みや現在の重みを組み合わせても満たすことができないため、この点を超えると一意性が失われます。 
5. それ以外の場合は更新します`p = p + x`。 このステップは、新しい重みを追加すると、達成可能な区別可能な合計の範囲が正確に拡張されることを反映しています。`x`なぜなら、以前に表現できたすべての値をシフトしてこの重みと組み合わせることができるからです。 
6. すべての重みを処理した後、出力します。`p`。 

維持される不変条件は、反復中のどの時点でも、すべての整数が`[0, p]`処理された重みと符号付きの組み合わせを使用して一意に表現できます。 ソートされた順序により、この間隔を延長しようとしたときに、ギャップを埋めるために必要な、より小さな未処理の重みが欠落することがなくなります。 ギャップが発生した場合、ウェイトが大きくなると表現可能な増分を小さくすることができないため、ギャップは永続的になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

a.sort()

p = 0
for x in a:
    if x > p + 1:
        break
    p += x

print(p)
```貪欲な引数は常に欠落している表現可能な最小値を最初に拡張しようとすることに依存しているため、ソートのステップは不可欠です。 分類しないと、早い段階で大きな重量が表示され、誤って膨張する可能性があります`p`そしてさらなる進歩を妨げるはずのギャップを隠します。 

条件`x > p + 1`重要な境界チェックです。 現在の重みが大きすぎて、到達不可能な最小値を満たすことができない場合を検出します。これは常に`p + 1`。 代わりにチェックする実装`p`または、異なる不等式を使用すると、ギャップがちょうど 1 単位の場合には失敗します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))
    a.sort()

    p = 0
    for x in a:
        if x > p + 1:
            break
        p += x

    return str(p)

# provided samples (from statement)
assert run("4\n1 2 3 4\n") == "10"
assert run("2\n1 3\n") == "4"

# custom cases
assert run("1\n5\n") == "0", "single large weight"
assert run("1\n1\n") == "1", "minimal extension"
assert run("3\n1 2 5\n") == "3", "gap after small prefix"
assert run("5\n1 1 1 1 1\n") == "5", "repeated small weights"
assert run("6\n2 2 2 2 2 2\n") == "2", "no early bridging possible"
```| テスト入力 | 期待される出力 | 検証内容 |

 ## 特殊なケース

 より大きい重みが 1 つだけある場合`1`、アルゴリズムはすぐに停止します`p = 0`なぜなら`x > p + 1`。 入力用`5`、スキャンは即座に停止し、出力されます。`0`これは、より小さい値を一意に分離できないという事実と一致します。 

すべての重みが同じである場合、次のような小さな値`1`、範囲は直線的に増加します。 各ステップは条件を満たします`1 ≤ p + 1`したがって、区間は決定論的に拡大し、最終的な答えは次のようになります。`n`。 

有効なプレフィックスの後に空白がある場合、次のようになります。`1, 2, 10`、アルゴリズムの処理`1`そして`2`到達する`p = 3`、次に検出します`10 > 4`そして止まります。 トレースにより、欠落している表現可能な最小値が将来のすべての実現可能性を決定し、重みを大きくしても以前のギャップを修復できないことが確認されています。
