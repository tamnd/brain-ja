 ## 問題の理解

 私たちには、固定された構造物に配置された小さな色石のセットが与えられています。それは、常に正確に 6 つの可能なスロットを持つインフィニティ ガントレットです。 各スロットは 1 つの固有の Infinity Gem に対応しており、各宝石は色によって一意に識別されます。 

入力により、サノスが現在持っている宝石の数がわかり、それらの宝石の色がリストされます。 この部分的な情報から、可能な 6 色の完全な固定セットと比較して、どの宝石が欠けているかを判断する必要があります。 出力は、不足している宝石の数とその名前が続きます。 

重要な構造的詳細は、可能性の世界は一定であり、小さいということです。 色は常に正確に 6 色あり、すべての入力色は区別されます。 これにより、複雑な検索や最適化の必要性が即座になくなります。 このタスクは、2 つの固定セット間のセット減算に帰着します。 

n の制約は最大 6 です。つまり、メンバーシップを繰り返しチェックする最も単純なアプローチでも、簡単に高速になります。 定数リストをループしたり、セットを使用したりするソリューションは、定数時間で実行されます。 

唯一のエッジケースは、n の境界値から生じます。 n が 0 の場合、6 つの gem をすべて出力する必要があります。 n が 6 の場合、何も出力しません。 不注意な実装による微妙な失敗例は、入力色が小文字の文字列であるのに対し、出力形式では宝石名を大文字にする必要があるため、色名と宝石名の間の正しいマッピングを維持することを忘れたり、大文字と小文字が一致しないことです。 

## アプローチ

 ブルートフォースアプローチでは、これを一般的なメンバーシップの問題として扱います。 入力色をリストに保存し、可能な 6 色のそれぞれについてリストをスキャンして、その色が存在するかどうかを確認できます。 各メンバーシップ チェックのコストは O(n) で、一定の 6 回のチェックを実行すると O(6n) になりますが、この問題では依然として一定です。 

ただし、これでも不要なオーバーヘッドです。 問題の構造は、色と宝石名の間の直接のマッピングを示唆しています。 ユニバースは固定されているため、6 つのペアすべてを辞書またはリストに保存し、入力に現れるペアを削除するだけです。 

重要な観察点は、動的クエリの問題を解決していないということです。 アップデートや大きな変動のある複数のテストケースを処理することは求められません。 固定カタログをフィルタリングしているだけです。 これにより、直接のセットの差が最もクリーンなアプローチになります。

 ## アルゴリズムのチュートリアル

 この問題は、色と宝石名の間の固定マッピングを維持し、入力に表示されるものを削除することで解決します。 

1. 各色と対応する宝石名を組み合わせて、6 つの宝石すべての参照テーブルを作成します。 これは、観測前の完全なセットを表します。 
2. すべての入力カラーを読み取り、セットに保存します。 セットの使用は厳密には必須ではありませんが、メンバーシップのチェックが迅速に行われ、入力の仮定に違反した場合の偶発的な重複が回避されます。 
3. 可能な 6 色のリスト全体を繰り返し処理します。 
4. 各色について、それが入力セットに表示されるかどうかを確認します。 
5. 表示されない場合は、対応する gem 名を回答リストに追加します。 
6. 6 つすべてを処理した後、不足している宝石の数とその名前を出力します。 

入力を反復処理するのではなく、完全な固定リストを反復処理する理由は、存在する要素ではなく、欠落している要素を見つけるように求められるためです。 この反復方向により、存在しない gem を考慮することを決して忘れないことが保証されます。 

### なぜ効果があるのか

このアルゴリズムは、すべての有効な宝石が正確に 1 つの色に一意に関連付けられており、可能な色の世界は固定されており、完全であるという不変条件に依存しています。 すべてのステップで、考えられる各宝石を 2 つの状態 (観察されたか観察されなかった) のいずれかに分類します。 入力には重複がなく、有効な色のみが含まれるため、あいまいさは生じません。 したがって、欠落している宝石はすべて、その色が入力セットに表示されないものである必要があり、減算ロジックの正確性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    
    color_to_name = {
        "purple": "Power",
        "green": "Time",
        "blue": "Space",
        "orange": "Soul",
        "red": "Reality",
        "yellow": "Mind"
    }
    
    present = set()
    for _ in range(n):
        present.add(input().strip())
    
    missing = []
    for color, name in color_to_name.items():
        if color not in present:
            missing.append(name)
    
    print(len(missing))
    for x in missing:
        print(x)

if __name__ == "__main__":
    solve()
```解決策は辞書を中心にしています`color_to_name`、入力色と出力宝石名の間の固定全単射をエンコードします。 これにより、ループ内の条件付きロジックや手動マッピングが回避されます。 

メンバーシップを定期的にチェックするために、入力カラーをセットに保存します。 n は最大でも 6 ですが、これによりロジックがクリーンかつ堅牢になります。 

ディクショナリの反復により、入力サイズに関係なく、すべての可能な gem を常に 1 回だけチェックすることが保証されます。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    color_to_name = {
        "purple": "Power",

        "blue": "Space",

 ## 特殊なケース

 空の入力ケースの場合`n = 0`の場合、アルゴリズムは入力セットを空として初期化します。 固定の 6 色のリストを反復するたびにメンバーシップ チェックに失敗するため、6 つの宝石名すべてが追加されます。 出力は正しく gem の完全なセットになります。 

完全入力の場合`n = 6`、セットにはすべての色が含まれています。 各検索は成功するため、不足リストに gem が追加されることはありません。 このアルゴリズムは、必要な形式に一致するゼロと空のリストを出力します。 

どちらの場合も、正確さは反復空間が固定され、入力サイズに依存しないという事実から得られるため、境界値はメンバーシップ チェックにのみ影響し、制御フロー構造には影響しません。
