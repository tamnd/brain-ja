 ## 解決策
 ## 問題の理解

 線に沿って配置された一連の表示が与えられます。 各ディスプレイには、固定位置、フォント サイズ、レンタル料金がこの順に設定されています。 課題は、選択した 3 台の合計レンタルコストを最小限に抑えながら、厳密に位置を増やし、フォント サイズも厳密に大きくした 3 台のディスプレイを選択することです。 

形式的には、インデックスが必要です$i < j < k$そのような$s_i < s_j < s_k$、そしてそのようなすべての有効なトリプルの中で、最小化します$c_i + c_j + c_k$。 そのようなトリプルが存在しない場合は、-1 を返します。 

順序制約は非常に重要です。表示の順序を変更することはできないため、これは一般的な組み合わせの問題ではなく、位置と値の両方の単調性制約を伴う構造化されたサブシーケンスの選択問題です。 

制約$n \le 3000$すでに、二次または三次のアプローチが依然として実行可能である可能性があることを示唆しています。 立方体$O(n^3)$ソリューションは、すべてのトリプルを直接検査し、有効であればコストを計算します。 最悪の場合、これは遅すぎます。$2.7 \times 10^{10}$小切手。 二次方程式または$O(n^2)$メソッドが本当のターゲットです。 

エッジケースは、増加するペアが存在するにもかかわらず、増加するトリプルが存在しない場合に発生する傾向があります。 たとえば、次の場合$s = [5, 4, 3]$、値が減少しているため、有効なトリプルは存在せず、答えは -1 です。 ペアのみをチェックする単純なアプローチでは、拡張性を誤って想定してしまいます。 

もう 1 つの微妙なケースは、複数の有効なトリプルが存在するが、その一部のみが最小コストを満たす場合です。 たとえば、局所的に安価な要素を貪欲に選択すると、後続の安価な 3 番目の要素がブロックされると失敗する可能性があります。 

## アプローチ

 直接的な総当たりアプローチはすべてのトリプルを試行します$(i, j, k)$と$i < j < k$、どうかをチェックします$s_i < s_j < s_k$、コストを計算します。 これは、実行可能な空間全体を探索するため正しいですが、次のように退化します。$O(n^3)$小切手。 と$n = 3000$、これは許容範囲をはるかに超えています。 

重要な観察は、構造が中間要素の周囲で自然に分割されていることです。$j$。 直したら$j$、問題は最も安い有効なものを選択することになります$i < j$より小さいフォントサイズで$s_j$、そして最も安い有効な$k > j$より大きなフォントサイズで$s_j$。 これにより、問題は各中間位置に関する 2 つの独立した最適化クエリに変わります。 

したがって、各トリプルのコストを再計算する代わりに、すべてのポジションについて事前計算します。$j$、可能な限り最良の左候補コストと右候補コスト。 次に、それらを組み合わせます$O(n)$中間点ごとに、全体の$O(n^2)$解決。 

残る唯一の課題は、フォント サイズに対する厳密な不等式制約を尊重しながら、これらのプレフィックスとサフィックスの最小値を効率的に計算することです。

 | ブルートフォース | O(n^3) | お(1) | 遅すぎる |
 | 最適 | O(n^2) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 それぞれの指標を扱います$j$トリプルの中間要素として。 

1. ポジションごと$j$、最も安価な有効な左パートナーを計算します$i < j$そのような$s_i < s_j$。 左側のすべてのインデックスをスキャンし、制約を満たす最小コストを追跡します。 
2. ポジションごとに$j$、最も安価な有効な適切なパートナーを計算します$k > j$そのような$s_k > s_j$。 再び右にスキャンして、制約を満たす最小コストを追跡します。 
3. 与えられた条件に対してどちらかの側が存在しない場合$j$、 それから$j$有効なトリプルの中間として機能することはできません。 
4. 有効なすべての$j$、候補の答えを次のように計算します。$$c_j + \text{bestLeft}[j] + \text{bestRight}[j]$$すべてにおいて最小限を維持します$j$。 
5. 有効でない場合$j$完全なトリプルを生成し、-1 を返します。 

重要なアイデアは、中央の要素が固定されると、左右の選択肢が次の不等式によってのみ制約される独立した最小化問題になるということです。$s_j$。 

### なぜ効果があるのか

 中間インデックスの固定$j$、有効なトリプルは次の左インデックスを使用する必要があります。$\{ i < j \mid s_i < s_j \}$そして右のインデックスから$\{ k > j \mid s_k > s_j \}$。 コストは 3 つの独立した部分にきれいに分割され、選択した左右のインデックス間に共有以外の相互作用がないため、それぞれの側を個別に最小化することが安全です。$j$。 考えられるすべての中間位置を試すため、有効なトリプルはすべてその中間要素で 1 回だけ考慮され、候補が見逃されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    s = list(map(int, input().split()))
    c = list(map(int, input().split()))

    INF = 10**30

    left = [INF] * n
    right = [INF] * n

    for j in range(n):
        best = INF
        for i in range(j):
            if s[i] < s[j]:
                if c[i] < best:
                    best = c[i]
        left[j] = best

    for j in range(n - 1, -1, -1):
        best = INF
        for k in range(j + 1, n):
            if s[k] > s[j]:
                if c[k] < best:
                    best = c[k]
        right[j] = best

    ans = INF
    for j in range(n):
        if left[j] != INF and right[j] != INF:
            ans = min(ans, left[j] + c[j] + right[j])

    print(-1 if ans == INF else ans)

if __name__ == "__main__":
    solve()
```この実装では、分解を中間のインデックスと 2 つの独立した検索に直接ミラーリングします。 左側の配列には各ポジションの最も安価な有効な先行品が格納され、右側の配列には最も安価な有効な後続品が格納されます。 

ネストされたループは意図的に単純になっています。$n = 3000$おおよそ許可します$9 \times 10^6$Python では安全な操作です。 

微妙な点は、INF に大きなセンチネル値を使用していることです。 これにより、有効な左または右の候補が存在しない場合に誤って無効な状態を結合することがなくなります。

これは、アルゴリズムがグローバルに最小コストを貪欲に選択するのではなく、最適な中間インデックスをどのように分離するかを示しています。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、増加するサブシーケンスが存在するが、順序付けの制約により完全な長さ 3 のチェーンを形成できない場合です。 例えば：```
4
1 3 2 4
5 100 1 100
```ここで、単純な貪欲なアプローチでは、1 と 2 を早い段階で選択する可能性がありますが、2 は 3 の後に表示され、単調性が崩れます。 代わりに、アルゴリズムは各中間位置を独立して評価するため、3 を潜在的な中間とみなし、最も互換性のある近傍を正確に見つけます。 

もう 1 つのエッジ ケースは、順序付けの制約に違反するため、最も安価な要素をグローバルに使用できない場合です。 中間分割構造は、要素ごとにグローバルに最適化するのではなく、両側との互換性を強制することでこの罠を回避します。 

最後に、フォント サイズが等しいケースでは、厳密な不平等要件が強調されます。 左の配列も右の配列も比較において等価性を受け入れないため、等しいペアは構築時に無視されます。
