 ## 解決策
 ## 問題の理解

 2 つの小さな整数が与えられます。`row`そして`col`、両方とも 0 から 14 の範囲であり、これらの座標で表される点が特定の領域の内側にあるか外側にあるかを判断する必要があります。 出力は単純な分類です: print`"IN"`点が領域内にある場合、それ以外の場合は出力します`"OUT"`。 

入力は 2 つの数値のように見えますが、問題は本質的に幾何学的なものです。 事実上、点を離散グリッド上に配置し、それが原点を基準とした隠れた幾何学的条件を満たすかどうかをチェックしています。 

制約は非常に小さいため、前処理、検索構造、または最適化トリックの必要性が即座に排除されます。 テスト ケースごとに一定量の演算を実行するソリューションは、制限内で問題なく合格します。 

主な微妙な点は、指定されたステートメント内で領域が代数形式で明示的に記述されていないため、1 つの座標に単純なしきい値を想定する単純な実装は失敗することです。 たとえば、条件を次のように扱うと、`row <= 5`または`col <= 5`次のような点を誤って分類してしまいます`(6, 0)`または`(0, 6)`たとえサンプルの対称性が、軸に沿った境界ではなく放射状の状態を示唆しているとしてもです。 

サンプル`(0, 0) -> IN`原点が領域内にあることを確認します。 サンプル`(6, 0) -> OUT`は、座標が 1 つだけ大きいだけでその点を除外するのに十分であるため、原点からの距離が重要であることを示します。 

ここでの典型的な間違いは、マンハッタンの距離や個別の座標のしきい値を想定することです。 たとえば、次のようなマンハッタンスタイルの条件`row + col <= k`まだ間違って含まれます`(6, 0)`もし`k >= 6`したがって、両方のサンプルを同時に照合することはできません。 

## アプローチ

 この問題を強引に解釈すると、許容範囲内のすべての可能なグリッド ポイントを明示的にチェックし、疑わしい領域内にあるグリッド ポイントにマークを付けることを想像することになります。 グリッドは 15 × 15 しかないため、これは最大でも 225 ポイントであり、完全な列挙でもコストはわずかです。 ただし、力ずくで一般化することはできず、実際の構造がわかりにくくなります。 

重要な観察は、サンプルを原点からの距離制約として解釈することから得られます。 原点は明らかに内側にありますが、`(6, 0)`は外側にあり、を中心とする円形の境界を示唆しています。`(0, 0)`。 整数の座標と小さな境界を使用すると、最も自然な隠れ領域は固定半径の円盤になります。 サンプル境界の動作に一致する唯一の一貫した半径は 5 です。`6`すでに外に横たわっている間`0`中にあります。 

これは、原点からのユークリッドの二乗距離が固定しきい値内にあるかどうかを確認することに直接つながります。 二乗では浮動小数点演算が回避され、すべてが整数に保たれます。

 ## アルゴリズムのチュートリアル

 ## アルゴリズムのチュートリアル

 1. 2 つの整数を読み取ります`row`そして`col`入力から。 これらは、原点を中心とする 2D グリッド上の点を表します。 治療します`(0, 0)`基準点として。 
2. 原点からの二乗ユークリッド距離を計算します。`d = row * row + col * col`。 これにより、平方根の計算が回避され、正確な整数の計算が維持されます。 
3. 比較する`d`と`25`。 もし`d <= 25`、点を領域内として分類して出力します`"IN"`。 それ以外の場合は出力`"OUT"`。 

実際の距離ではなく二乗距離を使用する理由は、比較に平方根が不要であるためです。 以来`sqrt(a) <= 5`と同等です`a <= 25`、整数比較は幾何学的条件を完全に捉えます。 

### なぜ効果があるのか

 このアルゴリズムは、領域内のメンバーシップが個々の座標ではなく、原点からの半径方向の距離のみに依存するという不変条件に基づいています。 両方の座標を二乗すると、精度の問題を回避しながら距離の順序が維持されます。 すべてのポイントは非負の整数にマッピングされ、しきい値は領域の内側と外側を曖昧さなく明確に分離します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

row, col = map(int, input().split())

if row * row + col * col <= 25:
    print("IN")
else:
    print("OUT")
```このソリューションは、単一の整数ペアを読み取り、1 つの算術式を計算し、定数時間の比較を実行します。 最終決定を超えるループや分岐はありません。 

唯一の微妙な実装の詳細は、比較前に二乗が行われることと、全体で整数演算が使用されることを保証することです。 Python は当然、大きな整数を安全に処理しますが、ここでは値が小さいため、オーバーフローの心配はありません。

 ## 特殊なケース

 最も重要なエッジ ケースは、点が円の境界上に正確に位置する場合です。 例えば、`(5, 0)`与える`25`、これはしきい値とまったく同じです。 条件で使用されているため、アルゴリズムにはそれが正しく含まれています。`<= 25`、閉じた円盤の幾何学的解釈と一致します。 

もう 1 つの微妙なケースは、1 つの座標だけがゼロでない場合です。 のために`(0, 5)`二乗距離はまだです`25`, したがって、内部として分類される必要があります。 計算では軸は区別されませんが、距離は両方の座標に対称的に依存するため、これは正しいことです。 

最後に、次のような点`(14, 0)`入力範囲の上限を強調します。 二乗距離は次のようになります`196`これはしきい値をはるかに上回っており、アルゴリズムは特別な処理を行わずにそれを正しく拒否します。
