 ## 解決策
 ## 問題の理解

 2_n_ 桁の文字列として表されるチケットが与えられます。_n_ は 1 ～ 100 です。チケットの前半には最初の _n_ 桁が含まれ、後半には残りの _n_ 桁が含まれます。 そのチケットが「明らかにアンラッキー」であるかどうかの判断が求められます。 前半の各数字が後半の数字とペアになり、前半のすべての数字がペアの後半の数字より厳密に小さいか、前半のすべての数字がペアの後半の数字より厳密に大きい場合、チケットは明らかに不運です。 各数字はペアリングで 1 回だけ使用する必要があります。 

入力により、チケットの合計の長さが最大 ​​200 桁であることが保証されます。 これは小さいため、二次時間計算量のアプローチでも技術的には機能しますが、ソートを使用した線形ソリューションの方がはるかに自然で効率的です。 

微妙な点は、チケットに繰り返しの数字が含まれる可能性があることです。 たとえば、前半は次のようになります。`11`そして後半`22`。 ここで、合計を比較するだけの単純なチェックや、並べ替えを行わずに貪欲な一致を使用すると、失敗する可能性があります。 もう 1 つの特殊なケースは、次のような両方の半分が同一である場合です。`1234`として分割`12`そして`34`。 誤った「YES」の答えを避けるために、ソート後に対応する各ペアの厳密な不等式を検証する必要があります。 

## アプローチ

 ブルートフォースアプローチでは、2 つの厳密な不等式条件の 1 つが満たされる全単射を見つけるために、後半のすべての可能な並べ替えを試みます。 _n_ が 100 までの場合、順列の数は 100! ですが、これは天文学的に大きく、実行不可能です。 ブルート フォースは、考えられるすべての組み合わせをチェックするため、概念的には正しいですが、組み合わせ爆発により失敗します。 

重要な洞察は、特定の位置よりも桁の相対的な順序が重要であるということです。 両方の半分を昇順でソートすると、数字をペアごとに比較できます。つまり、前半でソートされた数字がすべて後半でソートされた数字よりも厳密に小さいか、すべてが厳密に大きいかのどちらかです。 ソートにより、各最小桁が残りの半分の最小桁と一致することが保証されます。これは、不運の基準をチェックするために必要かつ十分です。 これにより、ソート後の単純な線形スキャンに問題が軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n! * n) | O(n) | 遅すぎる |
 | ソート + ペアワイズ チェック | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 整数 _n_ と長さ 2_n_ のチケット文字列を読み取ります。 紐を二つに分けて、`first_half`そして`second_half`。 この分離により、2 つのグループを独立して推論することができます。 
2. それぞれの半分を整数のリストに変換します。 これにより、比較が簡単になり、文字列の文字コードを扱う必要がなくなります。 
3. 両方の半分を昇順に並べ替えます。 ソートは、問題をすべての順列の考慮から単一の正規ペアリングに軽減する中心的なステップです。 
4. ソートされた数字をペアごとに比較します。 2 つのフラグを初期化します。`all_first_less`そして`all_first_greater`。 インデックスごとに`i`0 から n-1 までの数字の場合`first_half`対応する値以上である`second_half`数字、セット`all_first_less`偽に。 同様に、次の数字が`first_half`対応する値より大きくない`second_half`数字、セット`all_first_greater`偽に。 
5. スキャン後、次のいずれかの場合は、`all_first_less`または`all_first_greater`true のまま、印刷`YES`。 それ以外の場合は、印刷します`NO`。 

機能する理由: 並べ替えにより、前半の各桁が残りの後半の最小桁と確実にペアになります。 ソート後に厳密な不等式が失敗した場合、他の置換は条件を満たすことができません。 したがって、並べ替えられた比較が必要かつ十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
ticket = input().strip()

first_half = sorted(int(x) for x in ticket[:n])
second_half = sorted(int(x) for x in ticket[n:])

all_first_less = True
all_first_greater = True

for a, b in zip(first_half, second_half):
    if a >= b:
        all_first_less = False
    if a <= b:
        all_first_greater = False

print("YES" if all_first_less or all_first_greater else "NO")
```このソリューションは、まず入力を読み取り、チケットを 2 つの部分に分割します。 並べ替えると、対応する数字を直接比較できるようになります。 ループは厳密な不等式条件を同時にチェックします。 使用する`zip`これは、桁をペアにする明確かつ簡潔な方法であり、1 つずつ異なるエラーを回避します。 最後の条件は、フラグに基づいて正しい結果を出力します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    ticket = input().strip()
    first_half = sorted(int(x) for x in ticket[:n])
    second_half = sorted(int(x) for x in ticket[n:])
    all_first_less = True
    all_first_greater = True
    for a, b in zip(first_half, second_half):
        if a >= b:
            all_first_less = False
        if a <= b:
            all_first_greater = False
    return "YES" if all_first_less or all_first_greater else "NO"

# Provided sample
assert run("2\n2421\n") == "YES", "sample 1"

# Custom cases
assert run("2\n1234\n") == "YES", "increasing halves"
assert run("2\n1221\n") == "NO", "mixed digits"
assert run("1\n12\n") == "YES", "minimum size, first less"
assert run("1\n21\n") == "YES", "minimum size, first greater"
assert run("3\n111222\n") == "YES", "all equal in halves, first less"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 2\n1234 | はい | ソート後のペアごとの厳密なless条件 |
 | 2\n1221 | いいえ | 混合数字は厳密な不等式を満たすことができません。 
| 1\n12 | はい | 最小値 n=1、最初は小さい |
 | 1\n21 | はい | 最小値 n=1、最初に大きい値 |
 | 3\n111222 | はい | 複数の等しい数字、並べ替えられた比較が機能する |

 ## 特殊なケース

 のようなチケットの場合`1221`（前半`12`、後半`21`)、ソートにより生成される`12`そして`12`。 ペアごとに比較すると、最初の桁 1 対 1 は、小さい方と大きい方の両方について厳密な不等式に違反するため、両方のフラグが false になります。 アルゴリズムは正しく出力します`NO`。 

最小サイズのチケットの場合、`12`、比較は即時です: 前半 1 < 後半 2、つまり`all_first_less`True のままで、降伏します`YES`。 

半分にまたがって数字が繰り返されるチケットの場合、次のようになります。`111222`、並べ替えにより、最小の数字がペアになることが保証されます。 前半`111`、後半`222`、前半の数字はすべて厳密に小さくなり、`YES`。 アルゴリズムは重複を正しく処理します。
