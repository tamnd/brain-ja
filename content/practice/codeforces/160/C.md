 ## 解決策
 ## 問題の理解

 の配列が与えられます`n`整数。 この配列から、すべての順序付きペアを形成します`(a[i], a[j])`、ペアを含む`i = j`。 両方の位置が独立して選択されるため、正確に`n²`ペア。 

これらのペアはすべて辞書順にソートされています。 つまり、ペアは最初に最初の値で順序付けされ、それらが等しい場合は 2 番目の値で順序付けされます。 

タスクは出力することです`k`このソート順で - 番目のペア。 

この制約により、すべてのペアを直接生成することが完全に排除されます。 いつ`n = 10^5`、ペアの合計数は次のようになります。`10^10`これは、メモリに収まるか、時間内に処理できる量をはるかに超えています。 すべてのペアを 1 回繰り返すことさえ、1 秒の制限の下ではすでに不可能です。 

このため、リストを明示的に構築する代わりに、辞書編集的な順序付けの構造を活用する必要があります。 

微妙な点は、配列に重複した値が含まれる可能性があることです。 順序付けはインデックスではなく値に基づいて行われます。 配列が`[1, 1, 2]`、次に、から始まるペア`1`が 2 回出現するため、複数回表示されます。`1`。 

例えば：```
Input:
3 4
1 1 2
```ソート後のすべてのペアは次のとおりです。```
(1,1)
(1,1)
(1,2)
(1,1)
(1,1)
(1,2)
(2,1)
(2,1)
(2,2)
```4番目のペアは、`(1,1)`。 

重複を一意の値に圧縮する不注意な実装では、間違った多重度が生成されます。 

もう 1 つの簡単な間違いは、0 から始まるインデックスと 1 から始まるインデックスを混合することです。`k`。 

考慮する：```
Input:
2 1
5 7
```ソートされたペア:```
(5,5)
(5,7)
(7,5)
(7,7)
```最初のペアは`(5,5)`。 

から1を引くと`k`遅すぎても早すぎても、うっかり戻ってしまうかもしれない`(5,7)`その代わり。 

大きな値も重要です。`k`と同じ大きさにすることができます`n² = 10^10`。 言語によっては、32 ビット整数では十分ではありません。 Python はこれを自然に処理しますが、C++ では次のことが必要になります。`long long`。 

## アプローチ

 ブルートフォースのアイデアは単純です。 すべて生成`n²`順序付きペアを辞書順に並べ替えてから、`k`-番目のペア。 

これが機能するのは、辞書編集によるソートが問題のステートメントと直接一致するためです。 問題は規模だ。 と`n = 10^5`、ペアの数は次のようになります。`10^10`。 ペアを保存するだけでも膨大なメモリが必要となり、それらを並べ替えることは完全に不可能になります。 

重要な観察は、元の配列をソートした後、辞書編集的な順序付けが非常に規則的な構造になっているということです。 

ソートされた配列が次のようになっているとします。```
b[0], b[1], ..., b[n-1]
```次に、で始まるすべてのペア`b[0]`が最初にあり、次に次で始まるすべてのペアが続きます。`b[1]`、 等々。 

各要素が正確に貢献します`n`連続するペアを最初のコンポーネントとして使用します。 

たとえば、次のような場合です。```
b = [1, 2, 5]
```次に、ソートされたペアは次のようにグループ化されます。```
First element = 1:
(1,1), (1,2), (1,5)

First element = 2:
(2,1), (2,2), (2,5)

First element = 5:
(5,1), (5,2), (5,5)
```これは、どのサイズのブロックを決定することで、答えの最初の要素を見つけることができることを意味します。`n`が含まれています`k`-番目のペア。 

最初の値が固定されると、2 番目の値はそのブロック内の位置によって決まります。 

複数の連続するインデックスに同じ値が含まれる可能性があるため、重複すると状況が少し複雑になります。 値が表示された場合`cnt`回、その値で始まるすべてのペアが占有されます。`cnt * n`連続ポジション。 

2 番目のコンポーネントもソートされた配列から選択されます。 最初の値を特定したら、ソートされた配列のどの要素が残りのオフセットに対応するかを判断するだけで済みます。 

これにより、明示的なペアの生成ではなく、ソートされた位置での算術の問題が問題となります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n² log n²) | O(n²) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を読み取り、並べ替えます。 

辞書編集的な順序は値のみに依存するため、配列をソートすると、ペアの順序付けの正確な構造が明らかになります。 
2.変換`k`1 を減算して 0 ベースのインデックスに変更します。 

これにより、整数の除算が 0 から始まるオフセットで自然に機能するため、ブロックの計算が容易になります。 
3. 最初の要素のインデックスを次のように計算します。`first_idx = k // n`。 

ソートされた配列内のすべての要素が正確に寄与します`n`ペアを最初のコンポーネントとして使用します。 で割る`n`どのブロックに答えが含まれているかがわかります。 
4. しましょう`first_value = b[first_idx]`。 

これは、答えのペアの最初の数字です。 
5. 何回数えるか`first_value`ソートされた配列に表示されます。 

現れたとします`cnt`回、最初に出現するのはインデックスです`l`。 

次に、で始まるすべてのペア`first_value`サイズの大きな連続セグメントを 1 つ占める`cnt * n`。 
6. 目的のペアがこのセグメント内でどのくらい離れているかを計算します。 

このセグメントの前のペアの数は`l * n`。 

それで：```
offset = k - l * n
```7. 2 番目の要素は次のように決定されます。```
second_idx = offset // cnt
```それぞれの異なる 2 番目の値が繰り返されます`cnt`回があるので`cnt`最初のコンポーネントの選択は同じです。 
8. 出力:```
(first_value, b[second_idx])
```### なぜ効果があるのか

 配列をソートした後、辞書編集的な順序付けにより、最初のコンポーネントごとにペアがグループ化されます。 値が出現するたびに、ブロック全体が構成されます。`n`ペア。 

値が複数回出現する場合、最初のコンポーネントが等しいため、それらのブロックは隣接します。 この結合されたセグメント内では、2 番目の要素がソートされた順序で表示され、それぞれが正確に繰り返されます。`cnt`最初の値が出現するたびに 1 回。 

アルゴリズムは、どのセグメントに`k`次に、繰り返される 2 番目の値のどれが残りのオフセットに対応するかを決定します。 構造は辞書編集上の順序と正確に一致するため、生成されるペアは正しいものでなければなりません。 

## Python ソリューション```python
import sys
from bisect import bisect_left, bisect_right

input = sys.stdin.readline

n, k = map(int, input().split())
a = list(map(int, input().split()))

a.sort()

k -= 1

first_idx = k // n
first_value = a[first_idx]

left = bisect_left(a, first_value)
right = bisect_right(a, first_value)

cnt = right - left

offset = k - left * n
second_idx = offset // cnt

print(first_value, a[second_idx])
```辞書編集上のペアの順序はソートされた値の順序に直接従うため、解決策は配列をソートすることから始まります。 

変換後`k`0 から始まるインデックスに変換すると、式は`k // n`答えがどのペアのグループに属しているかを識別します。 すべてのインデックスが正確に寄与します`n`ペアが最初のコンポーネントであるため、整数除算によって正しいブロックがすぐに分離されます。 

次のステップでは、以下を使用して等しい値の全範囲を見つけます。`bisect_left`そして`bisect_right`。 これが必要なのは、辞書編集順では重複する最初の値が 1 つの大きなセグメントにマージされるためです。 

表現:```
offset = k - left * n
```より小さい最初の値に属するすべてのペアを削除します。 残るのは、最初のコンポーネントが等しいセグメント内の位置です。`first_value`。 

このセグメント内では、すべての 2 番目の値が正確に表示されます`cnt`連続して何回も。 で割る`cnt`正しい 2 番目の要素のインデックスが得られます。 

微妙な点が 1 つありますが、`second_idx`ソートされた配列を直接参照します。 繰り返される値は順序付けの中で繰り返される必要があるため、重複は圧縮しません。 

もう 1 つの微妙な点は、随所で整数の除算を使用していることです。 順序付けは完全に規則的なブロックを形成するため、フロア分割は二分探索やシミュレーションを行わずに位置を値にマッピングします。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io
from bisect import bisect_left, bisect_right

def solve():
    input = sys.stdin.readline

    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    a.sort()

    k -= 1

    first_idx = k // n
    first_value = a[first_idx]

    left = bisect_left(a, first_value)
    right = bisect_right(a, first_value)

    cnt = right - left

    offset = k - left * n
    second_idx = offset // cnt

    print(first_value, a[second_idx])

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out.strip()

# provided samples
assert run("2 4\n2 1\n") == "2 2", "sample 1"
assert run("3 2\n3 1 5\n") == "1 3", "sample 2"

# minimum size
assert run("1 1\n42\n") == "42 42", "single element"

# all equal values
assert run("3 5\n7 7 7\n") == "7 7", "all equal"

# duplicate handling
assert run("3 4\n1 1 2\n") == "1 1", "duplicate multiplicity"

# last possible pair
assert run("2 4\n1 5\n") == "5 5", "largest k"

print("All tests passed")
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1 1 / 42`|`42 42`| 最小サイズの配列 |
 |`3 5 / 7 7 7`|`7 7`| すべての値が同一 |
 |`3 4 / 1 1 2`|`1 1`| 重複した多重度が正しく処理される |
 |`2 4 / 1 5`|`5 5`| 有効な最大値`k`|
