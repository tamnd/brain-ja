 ## 解決策
 ## 問題の理解

 各バスは、ある瞬間にアクティブになります。 停留所から出発するバス`s`そして停止で終わる`f`旅行間隔が定められている乗客を乗せることができます。`[l, r]`中に完全に含まれています`[s, f]`。 人が停留所に到着する`l`時に`b`, そのため、次の時間のバスしか利用できません。`t`満足する`t >= b`。 このようなバスの中で、彼らは常に時間が最も短いバスを選択します。 

すべての人について、一定の間隔で幾何学的な質問に答える必要があります。 

最低限の条件でバスを探す`t`次のような:

 -`s <= l`-`r <= f`-`t >= b`そのようなバスが存在しない場合は、次のように出力します。`-1`。 

この制約により、ペアごとのチェックが即座に除外されます。 まで`10^5`バスと`10^5`すべてのクエリを直接スキャンするには、`10^10`最悪の場合の比較は、1 秒に収まる範囲をはるかに超えています。 

難しいのは、クエリに一度に 3 つの条件があることです。 時間でフィルタリングしているだけでなく、ある間隔に別の間隔が含まれているかどうかも尋ねています。 1 つの次元のみを効率的に処理するソリューションでは、依然として遅すぎます。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

バスを考えてみましょう。```
1 5 10
2 6 20
```そしてある人：```
2 5 10
```正解は最初のバスです。その時間はちょうど次のとおりです。`b`、平等が許可されます。 を使用した不用意な二分探索`t > b`の代わりに`t >= b`ここで静かに失敗します。 

もう 1 つの微妙なケースは、バスの重なり合いで、前のバスには乗客間隔が含まれていないが、後のバスには含まれている場合があります。```
Buses:
1 4 5
2 10 7

Person:
3 8 1
```答えは2番目のバスです。 最小時間のアクティブなバスのみを維持する貪欲な構造では、最も早いバスが乗客にサービスを提供できないため、クエリが誤って拒否されます。 

もう 1 つの危険な状況は、複数のバスが同じ左側の境界をカバーしているが、右側の境界が異なる場合に発生します。```
Buses:
1 5 3
1 10 8

Person:
2 8 1
```正解は2番目のバスです。 情報を誤って圧縮し、開始点ごとにバスを 1 つだけ保持すると、必要な情報が失われます。 

## アプローチ

 ブルートフォースの解決策は簡単です。 各人について、すべてのバスをスキャンし、次の 3 つの条件を確認します。 

-`s <= l`-`r <= f`-`t >= b`すべての有効なバスの中で、最小のバスを選択します。`t`。 

このロジックはステートメントの定義を直接実装しているため、完全に正しいです。 問題はパフォーマンスです。 と`10^5`人々と`10^5`バス、最悪の場合のパフォーマンス`10^10`小切手。 高度に最適化された実装であっても、時間内に完了することはできません。 

重要な観察は、時間は完全に秩序があり、独特であるということです。 バスを昇順に処理すると、`t`、次に閾値のある人の場合`b`、答えは単に時間後の最初のバスです`b`その間隔には以下が含まれます`[l, r]`。 

これにより、問題はオフラインの幾何学的探索問題に変換されます。 

時間を増やしてバスを処理するとします。 私たちはいつでも次のように答えたいと思っています。 

すでに処理されたバスの中に、次のようなバスは存在しますか?

 -`s <= l`-`f >= r`これは古典的な 2 次元の支配クエリです。 

重要な構造上の詳細は、ストップ範囲が最大であることです。`10^9`、しかし、ただ`10^5`実際に座標が表示されます。 座標圧縮により、生の値ではなくインデックスを処理できるようになります。 

ここで、左側のエンドポイント条件を修正することを検討してください。 大きいところから掃いてみたら`s`小さい方へ`s`、その後、座標にいるときはいつでも`x`、挿入されたすべてのバスはすでに満たされています`s >= x`。 

左エンドポイントのクエリの場合`l`、バスが必要です`s <= l`、 ない`s >= l`。 スイープ方向を逆にすることができます。 

- バスを並べ替える`s`上昇。 
- クエリを並べ替える基準`l`上昇。 
- すべてのバスを挿入します`s <= l`。 

挿入されたバスのうち、一部のバスが`f >= r`、そのようなバスの中で、最も短い時間が必要です。 

これは、圧縮によってインデックス付けされたセグメント ツリー問題になります。`f`。 

すべてのバスエンドポイントに対して`f`、そこに終了するバスの最小時間を保存します。 次にサフィックスをクエリします`[r, maxF]`有効なバスの最小時間を示します。 

最後の厄介な点は、クエリには少なくともそれ以上の時間が必要なことです。`b`、絶対的な最小限だけではありません。 私たちはこれに分割統治法で答えを導き出します。 

時間ごとに順序付けされたバスのリストに対して、すべてのクエリに対する応答バスをバイナリ検索します。 1 回の並列二分探索反復中に、最初のバスの中に有効なバスが存在するかどうかをテストします。`mid`バス。 

その実現可能性テストは、まさに上記で解決された間隔封じ込めクエリです。 

組み合わせにより、`O((n + m) log^2 n)`解決。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nm) | お(1) | 遅すぎる |
 | 最適 | O((n + m) log² n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのバスを時間の増加順に並べ替えます`t`。 
2. バスや人物に出現するすべての停留所の座標を座標圧縮します。 

圧縮により、間隔の順序を維持しながらセグメント ツリーのインデックス作成が可能になります。 
3. すべての人について、サービスを提供できる最小のバス インデックスを二分探索します。 

バスは時間順に並べ替えられるため、最初の有効なバスを見つけると、自動的に最小有効時間が得られます。 
4. 並列二分探索を使用して、すべての人物をまとめて処理します。 

各人が探索範囲を維持する`[low, high]`バスインデックスを介して。 
5. 1 回の反復中に、現在の中間点に基づいて人々をグループ化します。`mid`。 

ある人が尋ねます：「最初のバスに乗ってもらえますか？」`mid`バスには私の間隔が含まれていますか？」
 6. バスを最小時間から徐々に処理します。 

バスの場合`i`が追加されたら、セグメント ツリーの位置に挿入します。`f_i`。 
7. セグメント ツリーには、最小の左端点が格納されます。`s`各位置で終了するバスの間。 

すべてのサフィックス範囲について`[r, maxF]`、保存されている最小値をクエリする`s`挿入されたバスが条件を満たすかどうかを示します`s <= l`。 
8. 人の質問に答えるため`(l, r)`中間点で`mid`、サフィックスを使用してセグメント ツリーをクエリします。`[r, maxF]`。 

最低限であれば`s`その接尾辞は最大でも`l`の場合、挿入されたバスの一部に間隔が含まれます。 
9. クエリが成功した場合は、二分探索範囲を左に移動します。 

それ以外の場合は右に移動します。 
10. 並列二分探索が終了すると、各人は実行可能なバスを持たないか、最初の実行可能なバス インデックスを持っています。 
11. インデックスを入力順序から元のバス番号に変換します。 

### なぜ効果があるのか

 中間点で`mid`、データ構造には、時間が最初のバスの中に正確に含まれています。`mid`最小値。 少なくとも 1 つの挿入されたバスに乗客間隔が含まれている場合、クエリは正確に成功します。 

セグメント ツリーの不変条件は次のとおりです。 

圧縮されたエンドポイントごとに`f`、ツリーは最小値を格納します`s`で終わる挿入されたバスの間`f`。 

サフィックスを問い合わせる場合`[r, maxF]`、すべてのバスを次のように調べます。`f >= r`。 最低限保存されている場合`s`そのサフィックスの内側は満たされます`s <= l`の場合、一部のバスは両方の封じ込め条件を同時に満たします。 

-`s <= l`-`f >= r`バスは時間の増加順に処理されるため、クエリが実行可能になる最初の中間点は、最小有効バス時間に正確に対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**18

class SegTree:
    def __init__(self, n):
        self.n = 1
        while self.n < n:
            self.n <<= 1
        self.seg = [INF] * (2 * self.n)

    def reset(self):
        for i in range(2 * self.n):
            self.seg[i] = INF

    def update(self, pos, val):
        pos += self.n
        if val < self.seg[pos]:
            self.seg[pos] = val
        else:
            return

        pos >>= 1
        while pos:
            self.seg[pos] = min(self.seg[pos << 1],
                                self.seg[pos << 1 | 1])
            pos >>= 1

    def query(self, l, r):
        res = INF
        l += self.n
        r += self.n

        while l <= r:
            if l & 1:
                res = min(res, self.seg[l])
                l += 1
            if not (r & 1):
                res = min(res, self.seg[r])
                r -= 1
            l >>= 1
            r >>= 1

        return res

def solve():
    n, m = map(int, input().split())

    buses = []
    coords = []

    for idx in range(n):
        s, f, t = map(int, input().split())
        buses.append((t, s, f, idx + 1))
        coords.append(s)
        coords.append(f)

    people = []

    for idx in range(m):
        l, r, b = map(int, input().split())
        people.append((l, r, b, idx))
        coords.append(l)
        coords.append(r)

    coords = sorted(set(coords))
    comp = {x: i for i, x in enumerate(coords)}

    buses.sort()

    bus_data = []
    for t, s, f, idx in buses:
        bus_data.append((s, f, idx))

    low = [0] * m
    high = [n - 1] * m
    ans = [-1] * m

    possible = [False] * m

    for i, (l, r, b, idx) in enumerate(people):
        if buses[-1][0] >= b:
            possible[i] = True
        else:
            low[i] = 1
            high[i] = 0

    while True:
        buckets = [[] for _ in range(n)]
        active = False

        for i in range(m):
            if low[i] <= high[i]:
                active = True
                mid = (low[i] + high[i]) // 2
                buckets[mid].append(i)

        if not active:
            break

        seg = SegTree(len(coords))

        ptr = 0

        for mid in range(n):
            while ptr <= mid:
                s, f, _ = bus_data[ptr]
                seg.update(comp[f], s)
                ptr += 1

            for qi in buckets[mid]:
                l, r, b, idx = people[qi]

                if buses[mid][0] < b:
                    low[qi] = mid + 1
                    continue

                cr = comp[r]

                best = seg.query(cr, len(coords) - 1)

                if best <= l:
                    ans[qi] = mid
                    high[qi] = mid - 1
                else:
                    low[qi] = mid + 1

    out = []

    for i in range(m):
        if ans[i] == -1:
            out.append("-1")
        else:
            out.append(str(buses[ans[i]][3]))

    print(" ".join(out))

ストップ数が次の値に達するため、座標圧縮が必要です`10^9`。 セグメント ツリーは相対的な順序のみを考慮するため、圧縮されたインデックスで十分です。 

セグメント ツリーには最小開始位置が格納されます。 この方向は間違いやすいです。 お問い合わせの場合`(l, r)`、すべてのバスを次のように調べます。`f >= r`。 その中で最低限保存しておけば、`s`せいぜい`l`、その場合、一部のバスにはインターバルが含まれます。 

並列二分探索は最適化の中核です。 すべての人物に対して個別の二分検索を実行して構造を繰り返し再構築する代わりに、同じ中間点を共有するすべてのクエリが一緒に処理されます。 

実装の微妙な詳細の 1 つは、時間によるフィルタリングの順序です。 中間点のセグメントツリー`mid`インデックスからのすべてのバスが含まれます`0..mid`、しかし、それらのいくつかはまだ残っているかもしれません`t < b`。 時間が整理されているので確認してみると`buses[mid][0] < b`十分です。 プレフィックス内の最大時間がまだ小さすぎる場合、そのプレフィックス内のバスは機能しません。 

もう 1 つの簡単な間違いは、セグメント ツリーの値を直接上書きすることです。 複数のバスが同じものを共有する場合があります`f`, したがって、最低限のものを保存する必要があります`s`その中で。

## 特殊なケース
