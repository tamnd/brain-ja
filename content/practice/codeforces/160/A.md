 ## 解決策
 ## 問題の理解

 それぞれが正の整数値を持つコインのコレクションが与えられています。 タスクは、選択したコインの合計価値が、他の人に残されたコインの合計価値よりも厳密に大きくなるように、これらのコインのサブセットを選択することです。 この目標を達成するには、取得するコインの数も最小限に抑える必要があります。 

入力はコインの数を提供します。$n$、および一連の整数としてのコインの値。 出力は単一の整数、つまり残りのコインの合計を超えるために必要なコインの最小数です。 各コインの価値は1から100の間であるため、$n$が最大 100 の場合、すべての計算は標準の整数演算の範囲内に問題なく収まります。 これは、オーバーフローや高価な操作を心配することなく、値を自由に合計したり、配列を並べ替えたりできることを意味します。 

単純なアプローチがつまずく可能性のあるエッジケースとしては、すべてのコインの価値が等しい場合や、1 枚のコインが既に合計額の半分を超えている場合などが挙げられます。 たとえば、入力の場合`4\n1 1 1 1`、3 枚未満のコインを取得しようとすると、引き分けになるか合計を失います。 もう 1 つの微妙なケースは、1 つのコインの価値が他のすべてのコインの合計と等しい場合です。`2\n3 3`; ここでは、厳密な不等式を満たすために両方のコインを取得する必要があります。 

## アプローチ

 ブルートフォースアプローチは、コインの考えられるすべてのサブセットを考慮し、それらの合計を計算し、各サブセットの合計が残りのコインの合計より大きいかどうかを確認することです。 これは正しいですが、非効率的です。$n$コイン、あります$2^n$サブセット。 でさえ$n = 20$、これには 100 万以上のチェックが必要となり、最大でも$n = 100$、それは不可能です。 

問題を単純化する重要な観察は、コインを選択する順序が重要であり、コインが大きいほど早く合計に大きく寄与するということです。 したがって、コインを降順に並べ替えて、大きいものから始めてコインを選択できます。 各ステップで、合計が合計の半分を超えるまで累積します。 最初に小さいコインを取得すると、残りの合計を超えるにはさらに多くのコインが必要になるため、これにより、必要なコインの最小数が保証されます。 

最適なアプローチでは、並べ替えと単純な貪欲な蓄積を活用し、すべてのサブセットをチェックする必要性を回避します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n * n) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. コインの枚数を読み取り、$n$、およびコインの値の配列。 合計を計算して並べ替えを実行するには、完全なリストが必要です。 
2. すべてのコインの価値の合計を計算します。 これは、超える必要があるしきい値を知るために必要です。 
3. コインを降順に並べ替えます。 これにより、選択した各コインが可能な限り最大の価値に貢献し、必要なコインの数が最小限に抑えられます。 
4. 2 つの変数を初期化します。1 つは選択したコインの累計を追跡する変数で、もう 1 つは取得したコインの数をカウントする変数です。 
5. ソートされたコインを反復処理し、各コインの値を累積合計に加算し、コイン数を増やします。 
6. 各コインを追加した後、累計額が合計額の半分を超えているかどうかを確認します。 存在する場合は、反復を停止し、取得されたコインの数を返します。 
7. 最小コイン数を出力します。 これは、合計が残りのコインの合計よりも厳密に大きいという条件を満たします。 

ここで不変なのは、反復のどの時点でも、累積合計がその数のコインで取得可能な最大の合計であるということです。 最初に最大のコインを選択することで、累積合計が残りの合計を超えるとすぐに、より小さなサブセットではより少ないコインでこれを達成することはできなかったことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
coins = list(map(int, input().split()))

total_sum = sum(coins)
coins.sort(reverse=True)

accum = 0
count = 0

for coin in coins:
    accum += coin
    count += 1
    if accum > total_sum - accum:
        print(count)
        break
```まず、コインの数と値のリストを読み取ります。 の`sum`関数は合計を効率的に計算します。 降順に並べ替えると、最大のコインが最初に確実に選択されます。 反復中に、合計を累積し、同時にコインをカウントします。 停止条件`accum > total_sum - accum`厳密な不等式要件を直接実装します。 使用する`break`この条件に達したらすぐに停止するようにします。 

## 実用的な例

 **サンプル 1:**`2\n3 3`| コイン | 蓄積 | total_sum - 累計 | カウント |
 | --- | --- | --- | --- |
 | 3 | 3 | 3 | 1 |
 | 3 | 6 | 0 | 2 |

 最初のコインでは十分ではないため、`3`より大きくない`3`。 両方のコインを取ると、`6 > 0`したがって、出力は次のようになります`2`。 

**サンプル 2:**`4\n1 2 2 2`| コイン | 蓄積 | total_sum - 累計 | カウント |
 | --- | --- | --- | --- |
 | 2 | 2 | 5 | 1 |
 | 2 | 4 | 3 | 2 |

 最大のコインを 2 枚取ると、`4 > 3`したがって、出力は次のようになります`2`。 これは、貪欲なアプローチにより最小数のコインが保証されることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | コインの仕分けが重要です。 合計を累積する反復処理は O(n) |
 | スペース | O(n) | コイン配列の保存 |

 と$n \leq 100$、2 秒の制限時間内では、並べ替えと蓄積は無視できます。 メモリ使用量は 256 MB の制約を大幅に下回っています。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    coins = list(map(int, input().split()))
    total_sum = sum(coins)
    coins.sort(reverse=True)
    accum = 0
    count = 0
    for coin in coins:
        accum += coin
        count += 1
        if accum > total_sum - accum:
            return str(count)

# provided samples
assert run("2\n3 3\n") == "2", "sample 1"
assert run("4\n1 2 2 2\n") == "2", "sample 2"

# custom cases
assert run("1\n10\n") == "1", "single coin"
assert run("5\n1 1 1 1 1\n") == "3", "all equal small coins"
assert run("3\n2 5 7\n") == "2", "large coin plus another"
assert run("6\n10 10 10 1 1 1\n") == "2", "take two largest"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1\n10 | 1 | シングルコインエッジケース |
 | 5\n1 1 1 1 1 | 3 | すべてのコインが等しい場合、半分を超える最小数 |
 | 3\n2 5 7 | 2 | 大小のコイン選択の組み合わせ |
 | 6\n10 10 10 1 1 1 | 2 | 貪欲は最大のコインを正しく選択します |

 ## 特殊なケース

 のために`2\n3 3`、ソートされたコインを反復すると、累積合計は次のようになります。`3`最初のコインの後、それを超えない`3`。 2 番目のコインを追加すると、`6 > 0`、アルゴリズムは正しく出力します`2`。 のために`5\n1 1 1 1 1`、アルゴリズムは到達する 3 つのコインを選択します`3 > 2`、すべて等しいコインを正しく処理できることを示しています。 停止条件は、タイまたは境界シナリオであっても、厳密な不等式が常に満たされることを保証します。
