 ## 問題の理解

 ちょうど 10,000 人の登録者からスタートします。 動画は2種類あります。 通常の動画では、チャンネル登録者数が増加します。`a_i`そして直接的な収益は得られません。 コマーシャルビデオにはパラメータがあります`c_i`そして`b_i`: リリースすると収入が得られます`c_i`現在存在するすべての加入者ごとにセントが加算され、加入者数は によって減少します。`b_i`。 

リクエストされた番号ごとに`d`、正確に選択する必要があります`d`用意された動画の中から選択し、選択した動画を最適な順序に並べます。 答えは最大総広告収入です。 元の制約には、`n,m <= 100`、`a_i,b_i,c_i <= 100`、制限時間は 1 秒で、メモリは 512 MB です。 

の小さな値`n`そして`m`任意のサブセットまたは順列を列挙するアルゴリズムを除外します。 利用可能なビデオが 200 あるため、考えられるすべての順序を列挙したとしても、すでに次のオーダーが必要になります。`200!`、これは実現可能なことをはるかに超えています。 有用な数値限界は、代わりに、すべての商用製品の合計です。`c_i`値は最大 10,000 です。 これにより、扱いやすいナップザックのような寸法が得られます。

## アプローチ

 直接的なアプローチは、考えられるすべてのビデオ セットとそのセットのすべての順序を列挙することです。 固定の場合`d`、あります

 [
 P(n+m,d)=\frac{(n+m)!}{(n+m-d)!}
 ]

 順序付けられた選択肢。 すべての可能な値が`d`がクエリされると、スケジュールの総数は次のようになります。 

[
 \sum_{d=0}^{n+m} P(n+m,d)。 
]

と`n+m=200`、これにはすでに用語が含まれています`200!`、 約`7.9 * 10^374`。 考えられるすべての選択とすべての順序が考慮されるため、強引な方法は正しいのですが、すぐに役に立たなくなります。 

最初の有益な観察は、通常のビデオが常にコマーシャル ビデオの前に来る必要があるということです。 通常の動画でチャンネル登録者が次のように増加すると仮定します。`a`、および係数を使用したコマーシャルビデオ`c`現在、でリリースされています`s`購読者。 まずはCM動画を公開すると収益が上がる`c*s`。 通常のビデオを最初にリリースすると収益が得られます`c*(s+a)`、厳密にはこれより大きくなります。 したがって、利益を損なうことなく、回答として選択されたすべての通常のビデオを前面に移動できます。 

2 番目の観察は、コマーシャル ビデオのセットが固定されると、それらの相対的な順序が単純なペアごとの交換引数によって強制されるということです。 コマーシャルビデオを検討する`x`そして`y`があるとします。`s`彼らの前に購読者がいます。 もし`x`前にリリースされる`y`、彼らの合計収益は

 [
 c_xs+c_y(s-b_x)。 
]

もし`y`前にリリースされる`x`、それは

 [
 c_ys+c_x(s-b_y)。 
]

 最初の順序は、少なくとも次の場合と同じくらい良好です。 

[
 c_xb_y \ge c_yb_x,
 ]

 これは以下と同等です

 [
 \frac{c_x}{b_x}\ge\frac{c_y}{b_y}。 
]

 したがって、コマーシャルビデオは降順で表示される必要があります。`c/b`。 

ここで順序を修正し、いくつかのコマーシャルビデオを選択するとします。 逆の順序で処理すると、つまり増加します。`c/b`、パラメーターを使用してコマーシャルビデオを追加します`(c,b)`以前に処理された広告により、次のペナルティが発生します。 

[
 b \cdot C、
 ]

 どこで`C`の合計です`c`以前に処理された広告の値。 これにより、ナップザック スタイルの動的プログラムが得られます。 

させて`dp[k][s]`正確に選択した後の最大の負のペナルティになる`k`コマーシャルビデオの合計`c`は`s`。 次のコマーシャルビデオにパラメータがある場合`(c,b)`、スキップしても何も変わりません。 それを取ると状態が変わります

 \max(dp[k+1][s+c], dp[k][s]-b\cdot s)。 
]

 実際の収益は簡単に再構築できます。 選択したコマーシャル動画の合計が`c`に等しい`s`、および選択された通常のビデオが貢献します`A`追加の加入者、すべてのコマーシャル ビデオで確認される最初の加入者数は次のとおりです。`10000+A`。 したがって、彼らの基本収益は

 [
 s(10000+A)、
 ]

 DP 値は、以前のコマーシャル ビデオによって生じた損失を正確に差し引きます。 

固定番号の場合`l`通常のビデオのうち、`l`最大`a_i`価値観。 選択されたすべての通常のビデオはすべてのコマーシャル ビデオの前に配置されるため、その貢献度全体に合計が乗算されます。`c`選ばれたコマーシャルビデオの中から。 小さいものを選ぶ理由はない`a_i`。 

Python に役立つ最適化がもう 1 つあります。 固定番号の場合`k`コマーシャルビデオのすべての DP 状態`(s, dp[k][s])`線を表します

 [
 f(x)=s x+dp[k][s]、
 ]

 どこで`x=10000+A`すべての広告の前の加入者数です。 いくつかの増加する値に対してこれらの行の最大値が必要です。`x`、通常のビデオの可能な数ごとに 1 つ。 坂道なので`s`が増加している場合、上部エンベロープは単調な凸包で構築でき、線形時間でクエリできます。 

ブルート フォース手法は、考えられるすべてのスケジュールを明示的に表すため機能しますが、スケジュールの数が非常に多いため失敗します。 通常のビデオとコマーシャルビデオの順序が正規化され、その後に固定されたビデオが続くことが観察されました。`c/b`広告の順序付けにより、問題は総商業係数に対する制限されたナップザック DP に縮小されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |`O(sum P(n+m,d))`|`O(n+m)`| 遅すぎる |
 | 最適 |`O(m²C + nm + m log m)`、 どこ`C=sum c_i <= 10000`|`O(mC + n)`| 承認済み |

 この実装ではさらに、すべての DP スキャンがそれぞれの到達可能な最小値と最大値に制限されます。`k`、すべてをスキャンするよりも大幅に小さくなります。`C`多くの入力での位置。 

## アルゴリズムのチュートリアル

 1. 通常のビデオの増加を降順に並べ替え、プレフィックスの合計を構築します。 正確に使用すると`l`通常のビデオの場合、最大の合計増加量は最初のビデオのプレフィックスの合計です。`l`価値観。 これが機能するのは、すべての通常のビデオがすべてのコマーシャル ビデオの前にリリースされるためです。そのため、加入者が追加されるたびに、選択されたすべての広告が平等に支援されます。 
2. すべてのコマーシャルビデオを`(c,b)`増加順に並べ替えます`c/b`。 実際の最適なリリース順序は減少しています`c/b`ですが、アドバタイズメントを逆の順序で処理すると、DP 移行が便利になります。 等比率の広告を交換しても収益は変わらないため、等比率は任意に注文できます。 
3. 定義する`dp[k][s]`を選択するための負の相互作用ペナルティの最大値として`k`コマーシャルビデオと合計係数`s`これまでに処理された広告の中で。 最初だけ`dp[0][0] = 0`到達可能です。 
4. コマーシャルビデオを 1 つずつ処理します。 動画の場合`(c,b)`、反復します`k`同じビデオを 2 回選択することはできません。 到達可能な金額ごとに`s`、ビデオをスキップしても状態は変わりません。 それを選択すると状態が作成されます`(k+1, s+c)`価値のあるもの`dp[k][s] - b*s`。 

用語`b*s`直接的な意味があります。 以前に処理されたすべての広告は、`c`合計係数に対する値`s`、そしてそれらの後に現在の広告をリリースすると、負けを意味します`b`これらの各係数ユニットの加入者。 
5. 数字ごとに`k`選択された広告のすべての有限 DP 状態を解釈します`(s,dp[k][s])`線として`s*x + dp[k][s]`。 ここ`x`は、選択されたすべての通常ビデオの後で、コマーシャル シーケンスの直前の加入者数です。 
6. これらのラインの上部船体を構築します。 傾きはちょうど合計であるため、傾きはすでに増加しています。`c`価値`s`。 前の線と次の線が交差する前に中央線と前の線が交差する場合は常に、中央線を削除します。 このような行は、どのようなクエリに対しても最適であることはありません。`x`。 
7. ハルに対して可能なすべての数値をクエリします。`l`通常のビデオの。 クエリ値は`10000 + prefix[l]`。 船体が与える場合`profit_ads`の場合、リリースされたビデオの総数は次のようになります。`d=l+k`ので、更新します`answer[d]`この値で。 
8. 要求された値を読み取ります`d`対応する事前計算された回答を出力します。 可能な限り`d`値はクエリを読み取る前に処理され、すべてのクエリは一定時間内に応答されます。 

### なぜ効果があるのか

 実行可能なすべてのスケジュールで、選択したすべての通常ビデオを先頭に移動しても、商用ビデオの登録者数を減らすことはできないため、最適なスケジュールではすべての通常ビデオが最初になります。 選択されたコマーシャルビデオの間で、ペアワイズ交換計算により、減少していることが証明されます。`c/b`は、同点までの唯一の最適な相対順序付けです。 DP はこの順序のまったく逆の処理を行い、その遷移により減算されます。`b`合計の倍`c`これは、正確には、それらの広告が以前にリリースされたために失われた収益です。 したがって、すべての商用サブセットは、1 つの DP 状態によって表される最適なペナルティを正確に持ちます。 最後に、最大の通常ビデオの増加を選択することは、固定数の通常ビデオごとに最適であり、ハルは、結果として得られる加入者数ごとに最適なコマーシャル サブセットを評価します。 したがって、最終的な最大化で考慮されるすべての組み合わせは、リリースされたビデオの数に最適であり、可能なすべての数が考慮されます。 

## Python ソリューション```python
import sys
from functools import cmp_to_key

input = sys.stdin.readline

NEG = -10**30
INF = 10**30
INITIAL = 10000

def solve():
    n = int(input())
    good = [int(input()) for _ in range(n)]
    good.sort(reverse=True)

    pref = [0]
    for x in good:
        pref.append(pref[-1] + x)

    m = int(input())
    ads = []
    total_c = 0

    for _ in range(m):
        c, b = map(int, input().split())
        ads.append((c, b))
        total_c += c

    # DP is processed in increasing c / b order.
    # The actual release order is the reverse.
    def cmp(x, y):
        left = x[0] * y[1]
        right = y[0] * x[1]
        if left < right:
            return -1
        if left > right:
            return 1
        return 0

    ads.sort(key=cmp_to_key(cmp))

    # dp[k][s] = maximum negative interaction penalty
    # for k ads with total coefficient s.
    dp = [[NEG] * (total_c + 1) for _ in range(m + 1)]
    dp[0][0] = 0

    # Exact lower/upper bounds on possible total c for k selected
    # advertisements among the already processed advertisements.
    min_sum = [INF] * (m + 1)
    max_sum = [NEG] * (m + 1)
    min_sum[0] = 0
    max_sum[0] = 0

    processed = 0

    for c, b in ads:
        # Descending k makes the update 0/1: the current advertisement
        # cannot be used again during this iteration.
        for k in range(processed, -1, -1):
            lo = min_sum[k]
            hi = max_sum[k]

            if lo == INF:
                continue

            row = dp[k]
            nxt = dp[k + 1]

            for s in range(lo, hi + 1):
                val = row[s]
                if val == NEG:
                    continue

                ns = s + c
                nv = val - b * s

                if nv > nxt[ns]:
                    nxt[ns] = nv

        # Update reachable sum bounds after using this advertisement.
        for k in range(processed, -1, -1):
            if min_sum[k] != INF:
                v = min_sum[k] + c
                if v < min_sum[k + 1]:
                    min_sum[k + 1] = v

            if max_sum[k] != NEG:
                v = max_sum[k] + c
                if v > max_sum[k + 1]:
                    max_sum[k + 1] = v

        processed += 1

    # Build upper hull and query it for every possible subscriber count.
    #
    # A line is represented by y = slope * x + intercept.
    # Slopes are increasing because slope = total commercial c.
    def build_hull(k):
        hull_m = []
        hull_b = []

        lo = min_sum[k]
        hi = max_sum[k]

        if lo == INF:
            return hull_m, hull_b

        row = dp[k]

        for s in range(lo, hi + 1):
            intercept = row[s]
            if intercept == NEG:
                continue

            while len(hull_m) >= 2:
                m1 = hull_m[-2]
                b1 = hull_b[-2]
                m2 = hull_m[-1]
                b2 = hull_b[-1]

                # Remove the middle line if:
                # (b1-b2)/(m2-m1) >= (b2-intercept)/(s-m2)
                if (b1 - b2) * (s - m2) >= \
                   (b2 - intercept) * (m2 - m1):
                    hull_m.pop()
                    hull_b.pop()
                else:
                    break

            hull_m.append(s)
            hull_b.append(intercept)

        return hull_m, hull_b

    answer = [NEG] * (n + m + 1)

    for k in range(m + 1):
        hull_m, hull_b = build_hull(k)

        if not hull_m:
            continue

        pointer = 0

        for l in range(n + 1):
            x = INITIAL + pref[l]

            while pointer + 1 < len(hull_m):
                cur = hull_m[pointer] * x + hull_b[pointer]
                nxt = hull_m[pointer + 1] * x + hull_b[pointer + 1]

                if nxt >= cur:
                    pointer += 1
                else:
                    break

            profit = hull_m[pointer] * x + hull_b[pointer]
            d = k + l

            if profit > answer[d]:
                answer[d] = profit

    q = int(input())
    out = []

    for _ in range(q):
        d = int(input())
        out.append(str(answer[d]))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```入力セクションでは、まず通常の増加を並べ替えて、それらのプレフィックスの合計を構築します。`pref[l]`は、正確に取得できる合計加入者数増加の最大値です。`l`通常の動画。 

コマーシャルビデオは、浮動小数点除算ではなく相互乗算によってソートされます。 コンパレータはより小さいものを配置します`c/b`まず 1 つは、DP が最適な商業注文を逆方向に処理するためです。 使用する`c1 * b2`そして`c2 * b1`浮動小数点比較で起こり得るあらゆる問題を回避します。

DPの合計は合計です`c`、合計ではありません`b`。 これは中心的な実装の詳細です。 広告が減少した場合`b`係数の合計が次の広告の後に配置されます。`s`、その収益はちょうど減少します`b*s`。 それがトランジションが減算する理由です`b * s`。 

の`min_sum`そして`max_sum`配列は実装の最適化にすぎません。 可能な最小合計と最大合計を記録します。`c`それぞれに`k`したがって、内側のループは DP 行内の不可能な位置をスキャンしません。 の`NEG`Sentinel は、実行可能なすべての答えよりもはるかに低い値が選択されますが、Python の整数は任意の精度を持っているため、オーバーフローは問題になりません。

## 実用的な例

 最初のサンプルの広告は次のとおりです。`(c,b)=(10,20)`そして`(20,10)`。 それらの比率は次のとおりです。`0.5`そして`2`したがって、DP は次のように処理します。`(10,20)`まずそして`(20,10)`2番。 

| 処理された広告 |`k`| 合計`c`| DPペナルティ |
 | --- | --- | --- | --- |
 | なし | 0 | 0 | 0 |
 |`(10,20)`| 1 | 10 | 0 |
 |`(10,20),(20,10)`| 2 | 30 | -100 |

 のために`d=1`、 2 番目の広告のみを取ると、`20 * 10000 = 200000`。 のために`d=2`、両方の広告を取ると、`30 * 10000 - 100 = 299900`。 のために`d=3`、通常のビデオは両方の広告の前に 10 人の登録者を追加するため、ベースは次のようになります。`10010 * 30`、そして同じ 100 のペナルティが与えられます。`300200`。 

|`d`| 通常のビデオ | コマーシャルビデオ | 基本加入者 | 合計`c`| ペナルティ | 利益 |
 | --- | --- | --- | --- | --- | --- | --- |
 | 0 | 0 | 0 | 10000 | 0 | 0 | 0 |
 | 1 | 0 | 1 | 10000 | 20 | 0 | 200000 |
 | 2 | 0 | 2 | 10000 | 30 | 100 | 299900 |
 | 3 | 1 | 2 | 10010 | 30 | 100 | 300200 |

 このトレースは、DP が合計に基づいている理由を示しています。`c`そして、なぜ通常のビデオ投稿が選択されたすべての広告に適用されるのか。 

2 番目のサンプルでは、​​定期的な増加は次のようになります。`[40,30,10]`、プレフィックス合計付き`[0,40,70,80]`。 商業比率は、`1/100`、`5/10`、 そして`15/20`したがって、DP の順序は次のようになります。`(1,100)`、`(5,10)`、`(15,20)`。 実際の最適なリリース順序はその逆です。 

|`d`| 通常のビデオ | コマーシャルビデオ | 基本加入者 | 合計`c`| ペナルティ | 利益 |

 最後の 3 行は、直接的な収益を生み出さないにもかかわらず、通常の動画がなぜ役立つのかを示しています。 すべてのコマーシャル ビデオが選択されると、通常のビデオが追加されるたびに、3 つの広告すべてで視聴される加入者数が増加します。 

## 複雑さの分析

 しましょう

 [
 C=\sum_{i=1}^{m} c_i。 
]

 なぜなら、すべての`c_i <= 100`そして`m <= 100`、 我々は持っています`C <= 10000`。 

| 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |`O(m²C + nm + m log m)`| DPは`m`広告のレイヤーと`m`選択可能なカウントの合計は次のとおりです`C`; 船体構造では各 DP 列を 1 回スキャンします。 
| スペース |`O(mC + n + m)`| DPは、`(m+1)(C+1)`プレフィックス合計とアドバタイズメント データが別々に保存される状態。 

DP の正式な最悪のケースは次のとおりです。`100 * 100 * 10000 = 10^8`基本的な状態の位置。 この実装により、到達不能な金額のスキャンが回避されます。これは、商用の場合に特に効果的です。`c_i`値が等しいか、大きな共通構造を持っています。 船体は追加のものを取り除きます`O(nmC)`直接的な実装で使用される最終スキャン。 メモリ使用量は DP の整数参照約 100 万件で、512 MB の制限内に十分収まります。

 ## 特殊なケース

 ビデオがゼロの場合は国が処理する`dp[0][0] = 0`。 最終的な船体は、`k=0`単一行が含まれています`y=0`、だから選択する`l=0`通常のビデオでは答えはゼロになります。 のために```
0
0
1
0
```プログラムは印刷します`0`。 

コマーシャルビデオがないときは、`m=0`、DP には以下のみが含まれます`dp[0][0]`。 選択された通常のビデオの数に関係なく、すべてのハル クエリは 0 と評価されます。 したがって、```
2
5
7
0
3
0
1
2
```3つの答えは`0`、`0`、 そして`0`。 

いつ`d`利用可能な商用ビデオの数を超えると、最終的な最大化では、次の状態が自動的に考慮されます。`k=m`そして`l=d-m`。 のために```
2
5
6
1
10 1
1
2
```正確に 2 つのビデオでプラスの利益を得る唯一の方法は、コマーシャル ビデオと 1 つの通常のビデオを選択することです。 通常の増加の最大値は 6 なので、答えは次のようになります。`10 * 10006 = 100060`。 

順序付けのエッジケースは比率ソートによって処理されます。 のために```
0
2
10 20
20 10
1
2
```DP の順序は`(10,20)`に続く`(20,10)`、 なぜなら`10/20 < 20/10`。 対応する実際のリリース順序は逆になります。 合計係数は 30 で、2 番目の DP 遷移には次のペナルティがかかります。`10 * 10 = 100`。 結果として得られる利益は、`30 * 10000 - 100 = 299900`。 

最後に、加入者数に関する保証は、考慮されるすべてのシーケンスが負でない加入者数で有効なままであることを意味します。 この問題は、すべてのコマーシャルビデオを単独でリリースするという最悪のケースでも実現可能性を保証するため、アルゴリズムは加入者の否定性に基づいて DP 状態を拒否する必要はありません。 

ハルの最適化は核となるアイデアを理解するために必要ありませんが、Python の実装は直接的な最終コードの直訳よりもはるかに実用的になります。`O(nmC)`スキャン。
