 ## 解決策
 ## 問題の理解

 数値 (n) は、異常に近い素因数から意図的に生成されます。 (k=2) の場合、2 つの異なる (b) ビット素数 (p_1,p_2) があり、(p_2) は (p_1) と (n=p_1p_2) の直後の素数です。 (k=4) の場合、そのような独立したペアが 2 つ存在するため、

 [
 n=p_1p_2q_1q_2。 
】

 すべての素数は正確に (b) ビットを持ち、すべての素因数は個別です。 入力により、因子が 2 つまたは 4 つであるかどうか (b)、および 16 進数の (n) が得られます。 素因数も 16 進数で出力する必要があります。 これらの保証は、単なる検証条件ではなく、私たちが利用する数学的構造の一部です。 

可能な最大の (n) には (4b\le240) ビットがあります。 これは通常の裁判区分としては大きすぎます。 すべての因数自体は 60 ビットしかありませんが、最初の因数までの可能な約数をすべて試すと、最悪の場合、約 (2^{60}) の除算が必要になる可能性があります。 (k=4) の場合、(\sqrt n) までのすべての約数を検索する通常の一般的な限界は、(2^{120}) 個の候補付近ではさらに悪くなります。 1 秒の制限により、両方のアプローチが除外されます。 

この構造の有用な部分は、素数が単なる 60 ビットの数値であるということではありません。 連続する素数は近いため、それらの積は互いに非常に近い因子のペアを許容します。 フェルマーの因数分解法は、密接な因子のペアを見つけるために設計されています。 

不注意な実装によって誤って処理される可能性のあるエッジケースがいくつかあります。 1 つ目は、(\sqrt n) の天井ではなく床からフェルマー探索を開始することです。 例えば、```
4 2
dd
```(221=13\cdot17) を表します。 (\sqrt{221}) は 14 と 15 の間にあるため、正しい開始値は (a=15) です。 次に (15^2-221=4=2^2)、(13) と (17) が得られます。 14 から開始すると負の差が生じるため、整数の平方根をすぐに呼び出す実装は失敗します。 

2 番目のエッジ ケースは、(a) が奇数の値を通じてのみ進むことができると仮定しています。 サンプルについて```
4 2
8f
```(143=11\cdot13) があり、成功した値は (a=12) で偶数です。 検索を奇数 (a) に制限すると、答えが完全にスキップされます。 

3 番目のエッジ ケースは (k=4) の場合に現れます。 のために```
6 4
534ee3
```因数は (37,41,59,61) です。 フェルマー表現の 1 つは (2257=37\cdot61) と (2419=41\cdot59) を与えますが、これらは素因数ではありません。 1 つの表現を見つけた後に停止する解は、2 つの合成約数しか見つけられませんでした。 別の表現が必要になり、その後、結果の約数間の gcd が必要になります。 

最後に、すべての素因数が等しい入力は有効なテスト ケースではありません。 このステートメントは、すべての因子が異なるものであることを明示的に保証しているため、(11\cdot11) のようなテストは入力コントラクトに違反します。 特に、正しいテスト スイートでは、提出されたソリューションがその無効な状況を処理することを期待すべきではありません。 

## アプローチ

 簡単なアプローチはトライアル分割です。 2 から始めて、各整数が割り算 (n) するかどうかをテストし、十分な因数が見つかったら終了します。 すべての合成整数の約数は平方根以下であり、ここでは最初の素因数自体がおおよそ (2^{b-1}) 以上であるため、これは正しいです。 (b=60) の場合、これは潜在的に (2^{60}) 程度の割り切りテストを意味します。 たとえ各検査が非常に安価だったとしても、これは期限をはるかに超えています。 

生成された素数の構造は、はるかに優れた出発点を提供します。 まず、(k=2) であるため、(n=pq) と (p,q) が近いと仮定します。 書く

 [
 a=\frac{p+q}{2}、\qquad c=\frac{q-p}{2}。 
】

 (p) と (q) は奇数であるため、どちらの式も整数になります。 それから

 [
 n=pq=(a-c)(a+c)=a^2-c^2。 
】

 その結果、

 [
 a^2-n=c^2。 
】

 約数を検索する代わりに、(a^2-n) が完全二乗となる最小値 (a\ge\sqrt n) を検索します。 このような (a) が見つかると、2 つの因子は単純に (a-c) と (a+c) になります。 

これがフェルマー因数分解です。 ここで高速である理由は、生成手順が弱いのと同じ理由であり、2 つの素因数が近いということです。 それらの差が (g=q-p) である場合、(a) の成功値は約

 [
 \frac{g^2}{8\sqrt n}
 】

 (\sqrt n) から離れた位置。 (2^b) 付近の連続する素数の場合、一般的なギャップは素数サイズの対数スケールにあるため、(b\le60) の場合、この検索は非常に小さくなります。 (x) 付近の素数間の平均ギャップはおよそ (\ln x) です。 

4 因子の場合は、(n) が 2 つの近い数値の積である必要がないため、最初は難しく見えます。 重要なのは、4 つの素数を異なる組み合わせにすることです。 検討してください

 [
 n=(p_1q_1)(p_2q_2)。 
】

 (p_1,p_2) と (q_1,q_2) が近いので、これら 2 つの積も近いです。 同様に使用できます

 [
 n=(p_1q_2)(p_2q_1)。 
】

 どちらも有効なフェルマー分解です。 それらの 4 つの因子は複合ですが、一度に 1 つの素数でのみ重複します。 たとえば、

 [
 \gcd(p_1q_1,p_1q_2)=p_1。 
】

 したがって、いくつかの近い因子ペアが得られると、通常の gcd 操作で個々の素数が回復されます。 

公式の解決策は、同じ二乗差の考え方に従い、フェルマー表現によって生成されたいくつかの約数を収集し、それらの間の gcd を取得します。 

この総当たり法は、割り算により最終的に素因数が明らかになるため機能しますが、因数自体が 60 ビットになる可能性があるため失敗します。 生成された因子が連続する素数であるという観察により、代わりに二乗差を検索することができ、(b) の指数関数的な作業から小さな素数ギャップによって支配される検索に作業が軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 最悪の場合の (O(2^b)) 分割 | (O(1)) | 遅すぎる |
 | 最適 | (O(T\cdot M(b)))、(T) は小さな素数ギャップによって支配されます | (O(k)) | 承認済み |

 ここで、(M(b)) は (O(b)) ビット整数の算術コストを表し、(T) はテストされたフェルマー候補の数を表​​します。 生成されたランダム素数の場合、(T) は非常に小さいです。 4 因子構築の場合、2 つの連続する素数ギャップが (g) と (h) である場合、近接ペア積により、おおよそ (O((g+h)^2)) 回のフェルマー反復が行われますが、これは (b\le60) にとってはわずかです。 

## アルゴリズムのチュートリアル

1. (n) を 16 進数から Python の任意精度の整数型に解析します。 Python の整数は完全な 240 ビット値を直接表すことができるため、オーバーフローの問題はありません。 
2. (a=\lceil\sqrt n\rceil) を計算します。 フェルマーの恒等式には (a^2-n\ge0) が必要なので、天井から始めると負の値が回避されます。 
3. 繰り返し計算する

 [
 d=a^2-n
 】

 (d) が完全な正方形であるかどうかをテストします。 (s=\lfloor\sqrt d\rfloor) を計算し、(s^2=d) かどうかを確認します。 そうであれば、

 [
 n=a^2-s^2=(a-s)(a+s)、
 】

 したがって、(a-s) と (a+s) は両方とも (n) の約数です。 同じ約数が異なる表現から生じる可能性があるため、それらをセットに挿入します。 

1. 少なくとも (k) 個の異なる約数が見つかるまで続行します。 (k=2) の場合、(n) には正確に 2 つの素因数があるため、最初に成功した表現は 2 つの素因数そのものでなければなりません。 
2. (k=4) の場合、前のステップで収集した個別の約数のすべてのペアの gcd を取得します。 収集されたすべての約数は、元の 4 つの素数のうちの 2 つの積です。 このような 2 つの異なる積は素数を共有しないか、またはちょうど 1 つの素数を共有するため、それらの gcd は 1 または目的の素数のいずれかになります。 
3. すべての gcd を 1 より大きく保ち、結果の素因数を並べ替えて 16 進数で出力します。 出力順序は数学的に重要ではありませんが、並べ替えにより結果が決定的になります。 

### なぜ効果があるのか

 不変条件は、除数セットに挿入されるすべての数値が恒等式 (n=(a-s)(a+s)) に由来するため、(n) の真の約数であるということです。 2 因子の場合、自明でない因子のペアは正確に 2 つの素因数で構成されます。 4 因子の場合、2 つのクロスペア分解により、(p_1q_1,p_2q_2,p_1q_2,p_2q_1) などの 4 つの異なる積が生成されます。 4 つの素数は別個であるため、これらの積の間で gcd を取得すると、各素数が分離されます。 したがって、最終的に出力されるすべての値は素数で除算 (n) され、必要な数の個別の素因数が回復されます。 

## Python ソリューション```python
import sys
from math import isqrt, gcd

input = sys.stdin.readline

def factor_case(b, k, n):
    a = isqrt(n)
    if a * a < n:
        a += 1

    divs = set()

    while len(divs) < k:
        d = a * a - n
        s = isqrt(d)

        if s * s == d:
            divs.add(a - s)
            divs.add(a + s)

        a += 1

    if k == 2:
        ans = sorted(divs)
    else:
        values = list(divs)
        ans = set()

        for i in range(len(values)):
            for j in range(i + 1, len(values)):
                g = gcd(values[i], values[j])
                if g > 1:
                    ans.add(g)

        ans = sorted(ans)

    return ans[:k]

def solve():
    b, k = map(int, input().split())
    n = int(input().strip(), 16)

    ans = factor_case(b, k, n)

    for x in ans:
        print(format(x, "x"))

if __name__ == "__main__":
    solve()
```の最初の部分`factor_case`フェルマー検索ポイントを確立します。`isqrt(n)`は下限を返すため、(n) が完全な正方形でない場合、上限に移動するには明示的な乗算チェックが必要です。 

メイン ループは二乗差の恒等式を直接反映します。 なぜなら (a\ge\lceil\sqrt n\rceil)、`d`決してマイナスではありません。`isqrt(d)`2乗が最大である最大の整数を与えます`d`、そして比較`s * s`と`d`は正確な完全二乗検定です。 

セット`divs`リストの代わりに意図的に使用されます。 正方形の表現では 2 つの約数が得られ、複数の表現に同じ約数が含まれる場合があります。 停止条件では、4 要素の場合に必要なロジックに一致する個別の除数が要求されます。 

(k=2) の場合、最初に成功した表現から得られた約数はすでに 2 つの素数です。 (k=4) の場合、コードは素数性テストを実行しません。 私たちが収集したすべての約数は、4 つの異なる素数のうちちょうど 2 つの積であるため、これは安全です。 このような 2 つの異なる積が複合 gcd を持つことはできません。両方の素数を共有する場合、それらは同じ積になります。 したがって、それらの gcd は 1 または 1 つの元の素数になります。 

ここでは、Python の任意精度の整数が特に便利です。 (n) の最大値は 240 ビットしかないため、乗算、減算、平方根、および gcd はすべて実用的です。 

16 進数の変換には、`format(x, "x")`。 先行ゼロのない小文字の 16 進数が生成され、必要な表現と正確に一致します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(T\cdot M(b)+k^2\log n)) | (T) フェルマー候補がテストされ、続いて (k=4) に対して最大 6 個の gcd がテストされます。 
| スペース | (O(k)) | 最大 4 つの異なる約数と 4 つの復元された素数が保存されます。 

重要な量は (T) であり、(n) 自体の大きさではありません。 ギャップ (g) のある 2 つの因子の場合、フェルマーはおおよそ (g^2/(8\sqrt n)) ずつ増分した後に答えに到達します。 4 つの因子の場合、2 つの連続した素数ギャップが (g) と (h) である場合、クロスペアリングは約 (2^b(g+h)) だけ異なり、その平方根は約 (2^{2b}) になります。 結果として得られる反復回数はおよそ ((g+h)^2/8) になります。 (2^b) 付近の連続する素数ギャップは、ここに関連するスケールでは小さいため、(b\le60) の検索は容易に実用的です。 この問題の 1 秒の制限は、この構造的なショートカットを中心に設計されています。 

## テストケース

 以下のテスト ヘルパーは、提出されたソリューションで使用されるのと同じファクタリング ルーチンを呼び出します。 最大サイズの場合は、すぐ上の 2 つの連続する素数 (2^{60}) を使用し、テスト内で 16 進入力を構築するため、120 ビットの積を手動で変換する必要はありません。```python
import sys
import io
from math import isqrt, gcd

input = sys.stdin.readline

def factor_case(b, k, n):
    a = isqrt(n)
    if a * a < n:
        a += 1

    divs = set()

    while len(divs) < k:
        d = a * a - n
        s = isqrt(d)

        if s * s == d:
            divs.add(a - s)
            divs.add(a + s)

        a += 1

    if k == 2:
        ans = sorted(divs)
    else:
        values = list(divs)
        ans = set()

        for i in range(len(values)):
            for j in range(i + 1, len(values)):
                g = gcd(values[i], values[j])
                if g > 1:
                    ans.add(g)

        ans = sorted(ans)

    return ans[:k]

def run(inp: str) -> str:
    global input
    old_stdin = sys.stdin
    old_input = input

    try:

        input = sys.stdin.readline

        ans = factor_case(b, k, n)

        return "".join(format(x, "x") + "\n" for x in ans)
    finally:
        sys.stdin = old_stdin
        input = old_input

16 進数の解析は次のように処理されます。`int(..., 16)`, そのため、例では小文字が使用されていますが、大文字と小文字の両方の入力数字が受け入れられます。 出力は小文字の 16 進数で先頭のゼロなしで生成されるため、10 進数の 11 や 13 などの値は正確になります。`b`そして`d`。 

最大値には特別なオーバーフロー処理は必要ありません。 240 ビット整数は Python の任意精度整数で快適にサポートされており、(a^2) などのすべての中間値は管理可能なサイズのままです。 この実装では (n) を浮動小数点に変換することはありません。これにより、(n) が (2^{240}) に近い場合に精度が失われることが回避されます。
