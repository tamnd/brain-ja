 ## 解決策
 ## 問題の理解

 入力は、スペースなしで記述された有効な算術式です。 そのオペランドは単一の小文字であり、式には二項演算子が含まれる場合があります。`+`、`-`、`*`、`/`括弧と一緒に。 このタスクは純粋に表面的なものです。式をそのまま保持しますが、すべての算術演算子の直前と直後にスペースを 1 つ入れます。 

例えば、`a+b*(c-d)`になる`a + b * (c - d)`。 括弧自体は変更されず、括弧の周囲にスペースも追加されません。 

式には最大 200 文字が含まれるため、二次アルゴリズムであっても、公式の制約に対して実行される演算の数はわずかです。 式の解析、演算子の優先順位の処理、評価は必要ありません。 入力は構文的に正しいことがすでに保証されています。つまり、`+`、`-`、`*`、 そして`/`私たちが遭遇するのは、書式設定が必要な演算子です。 

すべての文字を 1 回検査する必要があるため、リニア スキャンは自然な解決策です。 最大 200 文字であれば、1 秒の制限内に十分収まり、メモリの使用量も無視できます。 たとえ`O(n^2)`構築ではこれらの特定の制約が渡されますが、必要な変換を直接実行できる場合には、これを使用する理由はありません。`O(n)`。 

最初のエッジ ケースは、演算子を含まない式です。 入力用`a`、正しい出力は次のとおりです。`a`。 式の末尾に常にスペースを挿入する不注意な実装では、次のような結果が生成されます。`a`、変更されるはずのない文字が変更されます。 

2 番目のエッジ ケースは、かっこの隣にある演算子です。 入力用`(a)/(b)`、正しい出力は次のとおりです。`(a) / (b)`。 スペースは周囲に属します`/`、周りにはいません`(`または`)`。 すべての文字以外の文字を周囲のスペースを必要とするものとして扱う実装では、括弧が誤って変更されてしまいます。 

3 番目のエッジ ケースは、深くネストされた式です。 入力用`((a))-b+(c*(d))`、正しい出力は次のとおりです。`((a)) - b + (c * (d))`。 括弧は演算子の直前または直後に使用できるため、実装では式内の位置ではなく文字自体に基づいて決定する必要があります。 

4 番目のエッジ ケースは、単一文字の変数で区切られた複数の演算子です。 入力用`a+b+c+d`、正しい出力は次のとおりです。`a + b + c + d`。 最初の演算子のみを処理するソリューション、または挿入された文字を考慮せずにインデックスを前方に移動しながら元の文字列にスペースを挿入するソリューションでは、後の演算子をスキップできます。 

## アプローチ

 簡単なブルート フォース ソリューションでは、演算子を繰り返し検索し、前後にスペースを含む新しい文字列を構築できます。 現在の式に長さがある場合`m`、文字列全体を再構築してスペースを挿入するとコピーできます`O(m)`文字。 あれば`k`演算子では、挿入するたびに長さが増加するため、合計作業量は次のようになります。`O(nk)`、つまり`O(n^2)`最悪の場合。 ここでの実際の最大長である約 200 文字の式の場合、これは数万文字の操作にすぎないため、このアプローチは実際には、指定された制約に対して十分に高速です。 

すべての演算子を独立して処理できるため、総当たりアプローチが機能します。 その弱点は正確さではなく、不必要な繰り返し作業です。 1 つの演算子を処理した後、次の演算子に到達するためにすでに処理された多くの文字がコピーされる場合があります。 

重要な点は、目的の出力が現在の入力文字にのみ依存するということです。 キャラクターが次のいずれかの場合`+`、`-`、`*`、 または`/`、スペース、演算子、さらにスペースを追加します。 1 文字おきは変更されずにコピーされます。 異なる演算子間の相互作用はなく、スペースを挿入しても、後続の入力文字の解釈方法は変わりません。 

これにより、元の式を左から右に 1 回だけ処理できるようになります。 入力文字列を変更することはなく、スペースが挿入されたためにインデックスを調整する必要もありません。 結果は個別に構築されるため、各入力文字は一定時間で処理されます。

 ## アルゴリズムのチュートリアル

 1. 完全な式を文字列として読み取ります。 このステートメントでは、入力にスペースが含まれていないことが保証されているため、1 行を読み取るだけで十分です。 
2. 最終的な式の一部を格納する空のリストを作成します。 リストは便利です。リストへの追加は定数時間で行われ、最後に一度結合することで、新しい不変の Python 文字列を繰り返し作成する必要がなくなるからです。 
3. 入力を最初の文字から最後の文字までスキャンします。 すべての文字について、それが四則演算子のいずれかであるかどうかを確認します。 
4. 文字が演算子の場合、スペース、演算子自体、および別のスペースの 3 つの部分を結果に追加します。 これにより、必要な書式設定ルールが直接実装されます。 
5. 文字が演算子でない場合は、変更せずに追加します。 特に、括弧と変数はそのままの位置に置く必要があります。 
6. すべての結果部分を 1 つの文字列に結合し、出力します。 入力には既存のスペースが含まれていないため、すべての演算子の両側に 1 つだけスペースが作成され、他の場所にはスペースが作成されません。 

### なぜ効果があるのか

 入力のプレフィックスを処理した後、結果リストには、そのプレフィックスの正しくフォーマットされたバージョンが正確に含まれます。 変数または括弧は変更されずにコピーされますが、すべての算術演算子はちょうど 1 つのスペースで囲まれた演算子に置き換えられます。 次の文字を処理するとこのプロパティが保持されるため、帰納法により、スキャンが終了したときに式全体が正しくフォーマットされます。 すべての決定は現在の入力文字のみに基づいているため、演算子をスキップしたり 2 回処理したりすることはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def format_expression(s):
    operators = {"+", "-", "*", "/"}
    result = []

    for ch in s:
        if ch in operators:
            result.append(" ")
            result.append(ch)
            result.append(" ")
        else:
            result.append(ch)

    return "".join(result)

def main():
    s = input().strip()
    print(format_expression(s))

if __name__ == "__main__":
    main()
```の`operators`set には、書式設定が必要な 4 文字が正確に含まれています。 このセットのメンバーシップの確認には、入力文字ごとに一定の時間がかかります。 

の`result`list は作成中の出力を表します。 演算子が見つかると、コードは入力文字列を変更するのではなく、3 つの個別の文字列を追加します。 文字列は不変であるため、文字列に繰り返し挿入すると毎回文字列の大部分をコピーする必要がある可能性があるため、これは Python での実装の詳細として役立ちます。 

ループは、増大する出力ではなく、元の入力を処理します。 この区別により、この問題で最も一般的なインデックス作成の間違いが排除されます。 スキャンされる文字列にスペースを挿入すると、現在の位置は演算子ごとに移動します。 ここで、入力は決して変更されないため、ループ インデックスは常に正しい元の文字を参照します。 

決勝戦`"".join(result)`出力文字列の 1 つの構築を実行します。 整数の算術演算がないため、整数のオーバーフローは無関係で、入力の長さが非常に短いため、標準の Python I/O で十分です。

 ## 特殊なケース

 表現については`a`の場合、アルゴリズムは 1 文字だけを認識します。 以来`a`は演算子セットに含まれていないため、結果に直接コピーされます。 最終的な出力は次のとおりです`a`したがって、このソリューションでは、書式設定が必要ない場合に不要なスペースが導入されません。 

のために`(a)/(b)`、最初の 3 文字は`(`、`a`、 そして`)`、それらはすべて変更されずにコピーされます。 いつ`/`に達すると、アルゴリズムが追加します`/`1 つの論理演算として。 残りの文字は変更されずにコピーされ、`(a) / (b)`。 これは、括弧自体を演算子として扱うことなく、演算子と括弧の間の境界を処理します。 

のために`((a))-b+(c*(d))`、すべての開き括弧と閉じ括弧は、表示されているとおりにコピーされます。 いつ`-`、`+`、 そして`*`に遭遇すると、それぞれの両側に 1 つのスペースが入ります。 結果は`((a)) - b + (c * (d))`。 タスクでは式の解析が必要ないため、ネストされた構造はアルゴリズムに影響を与えません。 

のために`a+a+a+a+a`、 それぞれ`+`独立して処理されます。 最初の演算子の後の結果には次のものが含まれます`a + `、2 番目以降に含まれる`a + a + `、 等々。 最終的な出力は次のとおりです`a + a + a + a + a`。 これにより、元のすべての文字に対してスキャンが継続され、個別の結果に追加されたスペースによってその位置が失われることがないことが確認されます。 

最大長が 100 の式の場合`a`99 で結合された変数`+`演算子を使用すると、スキャンは 199 個の入力文字ごとに 1 つの定数時間判定を実行します。 99 個の演算子はそれぞれ正確に 2 つのスペースを生成するため、出力には 397 文字が含まれます。 アルゴリズムは入力サイズの線形性を維持し、最大の有効な式を快適に処理します。
