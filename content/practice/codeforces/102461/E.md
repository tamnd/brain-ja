 ## 問題の理解

 私たちは持っています`n`さまざまなビデオカードのタイプ。 タイプについて`i`、そのタイプの割引価格での購入は、何も購入しないか、または次の期間に整数のカードを購入した場合にのみ許可されます。`l_i`そして`r_i`。 ミーシャが持てるのはせいぜい`s`カードの合計があり、目標はその合計を最大化することです。 

選択したタイプの固定セットの場合、可能な最小購入額はそれらの合計です。`l_i`、最大のものはそれらの合計です。`r_i`。 これら 2 つの合計の間のすべての整数が達成可能であるため、選択されたセットは、合計の下限が超えない場合に正確に実行可能です。`s`。 可能な限り最良の貢献は、次の小さい方になります。`s`とその上限合計。 

難しいのは種類を選ぶことです。 直接のサブセット列挙では次のことを考慮します。`2^n`セット、これはすでに約`2^100000`最大入力サイズでの可能性。 によってインデックス付けされた動的プログラムであっても、`s`不可能だから`s`できる`10^13`。 意図したソリューションは主に次のものに依存する必要があります`n`ソートとそれに続く線形または対数スキャンは、次の場合に適しています。`n = 10^5`。 

不注意な実装を簡単に破ってしまう境界状況が 3 つあります。 まず、型には次のものがあります。`l_i > s`, なので、絶対に買えません。 たとえば、`s = 5`そして単一の間隔`[6, 10]`、正しい結果は次のとおりです`0`そして出力量は`0`。 治療中`r_i >= s`十分であると誤ってこのタイプを選択してしまいます。 

第 2 に、個別に実現可能ないくつかのタイプが同時には実現できない可能性があります。 例えば、```
3 20
1 2
10 17
11 16
```最適な合計がある`19`、最初の 2 つのタイプから取得されます。 2 番目と 3 番目のタイプを選択することは、上限から見て魅力的に見えますが、それらの最小合計は次のとおりです。`21`、すでにキャパシティを超えています。 

第三に、下限の合計を最大化するだけでは十分ではありません。 と`s = 10`、間隔`[3, 12]`そして`[8, 12]`両方を選択することはできませんが、どちらか一方のみを選択することはできます`10`。 できるだけ多くの必須カードを詰め込もうとするだけのソリューションでは、大きなサイズのカードが含まれるタイプのカードが必要であるという事実を見落とす可能性があります。`r_i`残りの容量を埋めることができます。 

公式ソリューションでは、以下で説明するのと同じ構造削減を使用します。しきい値で型を分割します。`2s/7`、十分に大きい 3 つの下限のケースを個別に解決し、そうでない場合は、残りの選択肢を最大 2 つの大きなタイプに減らします。 

## アプローチ

 ブルートフォースアプローチは概念的には単純です。 ビデオ カード タイプのすべてのサブセットを列挙し、その下限と上限の合計を計算し、下限の合計が超過した場合は破棄します。`s`、それ以外の場合は`min(s, sum_r)`そのサブセットの最適な合計として。 2 つのエンドポイントの合計間のすべての整数は、選択した間隔から取得できるため、これは正しいです。 最悪の場合は検査します`2^n`各サブセットには最大で`O(n)`仕事、与えること`O(n 2^n)`。 のために`n = 10^5`、これは遠隔的には実現可能ではありません。 

重要な観察は次の要素から来ています`1.4`。 次のように書きます`7/5`。 選択したセットに下限合計がある場合`L`、その上限合計は少なくとも`7L/5`。 その結果、一度、`L >= 5s/7`、セットは常に正確に到達できます`s`。 

次の場合に型を小さいものとして分類するようになりました。`l_i <= 2s/7`それ以外の場合は大きいです。 3 つの大きなタイプの下限合計は次の値より大きくなります`6s/7`。 3 つの最小の大きい型が以下に当てはまる場合`s`、それらの上限合計は少なくとも`7/5 * 6s/7 = 6s/5 > s`、

 したがって、これら 3 つのタイプはすぐに最適な答えを出します`s`。 

これら 3 つの大きな型が適合しない場合、大きな型の 1 つおきのトリプルにはさらに大きな下限合計があるため、実行可能なソリューションに 3 つの大きな型を含めることはできません。 したがって、実行可能なすべてのソリューションには、多くても 2 つの大きなタイプが含まれます。 

これにより、はるかに小さな組み合わせの問題が残ります。 最適な大きなタイプを 1 つまたは 2 つ必要としますが、その周りに小さなタイプを追加することもできます。 選択したタイプをすべて追加すると合計の下限を超える場合`s`、最初に最小の下限を削除します。 削除された型はどれも小さいため、その下限は最大でも`2s/7`。 合計が再び実行可能になった瞬間、その下限合計は`5s/7`。 これにより、すでに上記の上限額が保証されます`s`したがって、このケースは合計で自動的に最適化されます。`s`。 

したがって、唯一の非自明な検索は、最大値を持つ大きな型のペアを見つけることです。`r_i + r_j`の対象となる`l_i + l_j <= s`。 で並べ替えた後、`l_i`、これは二分探索と接頭辞最大値を使用して実行できます。

 ## アルゴリズムのチュートリアル

 1. すべての間隔を元のインデックスとともに保存し、間隔を次の基準で並べ替えます。`l_i`。 並べ替えにより、小さな型の接頭辞と大きな型の接尾辞が得られます。これはまさに、`2s/7`口論。 
2. 下限を満たす最初の型を見つけます。`7l_i > 2s`。 以前のタイプはすべて小さく、後のタイプはすべて大きいです。 正確な整数比較を使用します`7l_i <= 2s`入力値は整数であり、境界が重要であるため、浮動小数点演算の代わりに使用されます。 
3. 少なくとも 3 つの大きな型があり、3 つの最小の大きな下限が次の値に適合する場合`s`、その 3 つを選択します。 それらの下限合計が次より大きい`6s/7`、したがって、それらの上限合計は`s`。 したがって、答えはまさにそのとおりです`s`。 
4. それ以外の場合は、すべての小さなタイプを開始セットとして選択します。 現時点では、大きな型は実行可能な解決策に 3 つの型を提供できないため、最適な解決策には最大 2 つの大きな型が必要です。 
5. 大きな型の中から、最大値を持つ実現可能なペアを見つけます。`r_i + r_j`。 考えられるすべての 2 番目のタイプについて、下限がその横に収まる最大のインデックスをバイナリ検索します。 プレフィックスの最大値は`r`値により、最適な互換性のあるパートナーが得られます。 また、ペアが適合しない場合があるため、単一の大きなタイプを検討してください。 
6. 選択した 1 つまたは 2 つの大きなタイプを小さな開始セットに追加します。 大きなペア自体は、その下限合計が最大で以下になるように選択されています。`s`したがって、結合されたセットが大きすぎる場合は、小さい型のみを破棄する必要があります。 合計の下限が最大以下になるまで、最小の下限を削除します。`s`。 
7. 残りの選択したタイプに合計の下限を設定します`L`と上限合計`R`。 答えは`min(s, R)`。 もし`L <= s`、最初に選択したすべてのタイプにその下限を割り当て、次に目標に達するまで残りのカードを選択した間隔に分配することで、正確な答えを構築できます。 
8. 型が破棄された場合は、その型に対して 0 を出力します。 保持されているすべてのタイプに対して、元の間隔を使用して最終数量を割り当てます。これにより、元の入力順序が保持されます。 

### なぜ効果があるのか

 アルゴリズムの背後にある不変条件は、大きな型の分割後、すべての実行可能なソリューションにはすでに 3 つの大きな型が含まれている、ということです。この場合、最初の 3 つの型は次のようになります。`s`、または最大 2 つの大きなタイプが含まれます。 最初のケースは直接検出されます。 

2 番目のケースでは、最適な解決策を検討します。 その大部分には、タイプが 0、1、または 2 つあります。 互換性のある 2 番目の大きな型が存在する場合、それを追加しても達成可能な上限が増加するだけであるため、1 つの大きな型を使用した最適化は、そのようなペアが存在しない限り、何らかの実現可能なペアによって支配されます。 したがって、アルゴリズムは、次の合計を最大化することによって、可能な限り最適な大部分を見つけます。`r_i`。 

小さなパーツの場合、すべての小さなタイプが選択した大きなパーツに適合する場合、タイプを追加しても達成可能な合計を減らすことができないため、すべての小さなタイプを維持することが常に有益です。 適合しない場合、アルゴリズムは最小の下限を削除します。 削除される各タイプは最大で`2s/7`、最初の実行可能なプレフィックスの下限合計が次の値を超えています。`5s/7`。 その上限合計は次より大きくなります`s`、建設が絶対最大値に達するように`s`。 この場合、小さな型のアイデンティティはもはや重要ではありません。 これら 2 つのケースは、考えられるあらゆる最適値をカバーしています。 

## Python ソリューション```python
import sys
from bisect import bisect_right

input = sys.stdin.readline

def solve():
    n, s = map(int, input().split())

    items = []
    for i in range(n):
        l, r = map(int, input().split())
        items.append((l, r, i))

    items.sort()

    # Small: 7 * l <= 2 * s
    cnt = 0
    while cnt < n and 7 * items[cnt][0] <= 2 * s:
        cnt += 1

    # If three smallest large types fit, they already force answer s.
    if cnt + 2 < n:
        l0 = items[cnt][0]
        l1 = items[cnt + 1][0]
        l2 = items[cnt + 2][0]

        if l0 + l1 + l2 <= s:
            selected = [cnt, cnt + 1, cnt + 2]
        else:
            selected = None
    else:
        selected = None

    # Otherwise we need all small types plus the best one/two large types.
    if selected is None:
        selected = list(range(cnt))

        large = items[cnt:]

        if large:
            m = len(large)
            ls = [x[0] for x in large]
            rs = [x[1] for x in large]

            # Prefix maximum r and its index.
            pref_r = [0] * m
            pref_id = [-1] * m

            best_r = -1
            best_id = -1

            for i in range(m):
                if rs[i] > best_r:
                    best_r = rs[i]
                    best_id = i
                pref_r[i] = best_r
                pref_id[i] = best_id

            # Best single large type that fits.
            k = bisect_right(ls, s) - 1
            best_value = -1
            best_pair = None

            if k >= 0:
                best_value = pref_r[k]
                best_pair = (pref_id[k],)

            # Best pair of large types.
            for i in range(m):
                if ls[i] > s:
                    break

                remaining = s - ls[i]
                k = bisect_right(ls, remaining) - 1

                if k < 0:
                    continue

                # We need a partner with index < i.
                k = min(k, i - 1)
                if k < 0:
                    continue

                value = rs[i] + pref_r[k]
                if value > best_value:
                    best_value = value
                    best_pair = (pref_id[k], i)

            if best_pair is not None:
                for x in best_pair:
                    selected.append(cnt + x)

        # Remove the smallest lower bounds until the set fits.
        selected.sort(key=lambda i: items[i][0])

        lower_sum = sum(items[i][0] for i in selected)

        while selected and lower_sum > s:
            x = selected.pop(0)
            lower_sum -= items[x][0]

    # The selected set is now feasible by lower bounds.
    lower_sum = sum(items[i][0] for i in selected)
    upper_sum = sum(items[i][1] for i in selected)

    target = min(s, upper_sum)

    ans = [0] * n
    remaining = target - lower_sum

    # Start from all lower bounds and distribute the remaining amount.
    for pos in selected:
        l, r, original = items[pos]
        add = min(r - l, remaining)
        ans[original] = l + add
        remaining -= add

    print(target)
    print(*ans)

if __name__ == "__main__":
    solve()
```実装の最初の部分では、間隔を並べ替え、整数演算を使用してしきい値を見つけます。 の乗算`7`Python では安全であり、表現に関連するすべての精度の問題を回避します。`1.4`浮動小数点値として。 

3 つの大タイプの分岐は、一般的な分岐の前に意図的にチェックされます。 それが成功すれば、建設はすでに到達するのに十分です`s`なので、ペア検索は必要ありません。 

一般的なブランチは、大きな型に対してプレフィックス maxima を構築します。 固定式大型タイプの場合`i`、`bisect_right`下限が最大以下であるすべての大きな型を検索します`s - l_i`。 パートナーインデックスを以下に制限する`i`同じ型が二度使用されないことを保証します。 プレフィックスの最大値により、最大の上限を持つ互換性のある型が得られます。 

実現可能なペアが存在しない可能性があるため、単一タイプの候補が必要です。 また、大きな型が 1 つだけ存在する場合のフォールバックとしても機能します。 

大きな部分を選択した後、コードは選択したインデックスを下限で並べ替え、必要に応じて最小のものを削除します。 この順序は意図的なものです。 すべての大きな型には、すべての小さな型よりも大きな下限があるため、実行可能な大きなペアが保存され、小さな型が最初に破棄されます。 

最後に、選択したタイプごとに構築が開始されます。`l_i`。 目標は最大でも総額の上限であるため、残額は常に上限を超えずに分配できます。`r_i`。 コードは選択された型を並べ替えられた順序で処理しますが、`ans[original]`, したがって、出力は入力順序のままになります。

def brute_force(inp: str):
    it = iter(inp.split())
    n = int(next(it))
    s = int(next(it))

    a = []
    for _ in range(n):
        l = int(next(it))
        r = int(next(it))
        a.append((l, r))

    best = 0

    for mask in range(1 << n):
        low = 0
        high = 0

        for i in range(n):
            if mask >> i & 1:
                low += a[i][0]
                high += a[i][1]

        if low <= s:
            best = max(best, min(s, high))

    return best

def check(inp: str):
    out = solve_io(inp)
    tokens = list(map(int, out.split()))

    n, s = map(int, inp.splitlines()[0].split())

    ans = tokens[1:1 + n]

    assert len(ans) == n
    assert 0 <= w <= s
    assert sum(ans) == w

    lines = inp.splitlines()
    intervals = [tuple(map(int, line.split())) for line in lines[1:]]

    for x, (l, r) in zip(ans, intervals):
        assert x == 0 or l <= x <= r

    assert w == brute_force(inp)
