 ## 解決策
 ## 問題の理解

 各コンテストの期間は固定されているため、決定するのは開始時期だけです。 コンテスト 1 の開始時間`c1`はまさに次の場合に有効です`l1 <= c1 <= r1 - d1`。 

同様に、コンテスト 2 は、次の整数時刻に開始できます。`l2 <= c2 <= r2 - d2`。 

2 つのコンテストは重複してはなりません。 エンドポイントでのタッチが許可されているため、可能な相対順序は次の 2 つだけです。`c1 + d1 <= c2`または`c2 + d2 <= c1`。 

すべての有効なペアの中で`(c1, c2)`を最小限に抑えたい`|c1 - s1| + |c2 - s2|`。 

元の開始点はすでに個別の制限を満たしているため、何かを移動する唯一の理由は重複を削除することです。 この観察は、目的が単純に 2 つの開始位置が元の位置から離れる合計量であることを意味するため、役に立ちます。 

テスト ケースは最大 50,000 個まで存在できますが、毎回の座標は次のように大きくなる可能性があります。`10^9`。 考えられるすべての開始時間を調べる方法では、すぐに遅すぎます。 1 つのコンテストでも約`10^9`可能な整数が始まります。 すべての開始ペアを確認するには、約`10^18`1 つのテスト ケースに対して操作を行うのに、50,000 ケースに対してそれを実行することは完全に不可能です。 目的のソリューションでは、各テスト ケースを一定時間で処理する必要があります。 

一見合理的と思われる実装が失敗する可能性がある境界ケースがいくつかあります。 

1 つ目は、コンテストが既に重複していない場合です。 例えば、```
1
0 10 20 30
0 5 20 5
```はすでに有効なので、正解は```
0 20
```間隔が接触するまで常に 1 つのコンテストを移動するソリューションでは、答えが不必要に増加する可能性があります。 

2つ目は、タッチが許可されていることです。 例えば、```
1
0 3 2 5
0 2 2 1
```次のようにスケジュールできます```
0 2
```なぜなら、最初のコンテストは、2 番目のコンテストが始まると同時に終了するからです。 等式を交差点として扱うと、このスケジュールが誤って拒否されます。 

3 つ目は、最適なソリューションにより、1 つだけを動かすのではなく、両方のコンテストを動かす可能性があるということです。 例えば、```
1
14 22 12 18
15 5 16 2
```の最適な全体的な動きを持っています`3`。 最適なスケジュールの 1 つは、`17 15`、最初のコンテストが次のように進みます。`2`そして2番目は次のように移動します`1`。 コンテストを 1 つだけ移動すると、さらに悪い結果が得られます。 

最後に、実現可能性は元の位置だけではなく、利用可能な開始間隔によって決まります。 例えば、```
1
0 2 0 2
0 2 0 2
```両方のコンテストを強制的に占領する`[0, 2]`, したがって、重複しないスケジュールは存在しません。 正しい出力は次のとおりです```
-1 -1
```## アプローチ

 直接的なブルート フォース ソリューションでは、最初のコンテストのすべての有効な開始時刻と 2 番目のコンテストのすべての有効な開始時刻を列挙できます。 各ペアについて、コンテストが重複するかどうかをチェックし、重複しない場合は合計の動きを計算します。 これは正しいです。考えられるすべてのスケジュールが明示的に検査されるからです。 

問題は探索空間のサイズです。 開始間隔には、ほとんどの値を含めることができます。`10^9`整数値なので、両方の開始を列挙するにはおおよその時間がかかります`10^18`単一のテスト ケースをチェックします。 50,000 のテスト ケースでは、理論上の最悪のケースは次のとおりです。`5 * 10^22`ペアチェック。 総当たり力を 1 つの次元に削減したとしても、依然として残ります。`10^9`テスト ケースごとの反復回数は 1 秒の制限をはるかに超えています。 

重要な観察は、最終スケジュールで可能な注文が 2 つだけであるということです。 コンテスト 1 がコンテスト 2 より前にあると仮定して問題を解決し、その後、コンテスト 2 がコンテスト 1 より前にある対称ケースを解くことができます。 

最初の順序を考えてみましょう。`c1 + d1 <= c2`。 

修正するとします`c1 = x`。 2 番目のコンテストの開始が許可される場合`x + d1`、最初のコンテストの直後に置くのが最も便利な境界位置です。 2 番目のコンテストが最初のコンテストの前にある場合、対応するタッチ位置は次のようになります。`x - d2`。 そこで、一度候補者になったら、`x`が選択されている場合は、これら 2 つの接触位置のみを考慮する必要があります。 

残りの疑問は、なぜ少数の値だけが存在するのかということです。`x`が必要です。 費用`|x - s1| + |y - s2|`区分的に線形です。 どちらの絶対値も傾きを変えず、どちらの実行可能境界にも到達しない領域内では、両方のコンテストを同じ方向に移動しても、厳密に優れた内部最適値を作成することはできません。 したがって、関連する境界の 1 つに到達するか、元の開始位置の 1 つに到達すると、最小値が達成されます。 

最初のコンテストでは、それらの関連するポジションは、最も早い有効なスタートによって表すことができます。`l1`、その本来の始まり`s1`、およびその最新の有効な開始点`r1 - d1`。 これら 3 つの値のそれぞれについて、コンテストが接触する 2 つの位置をテストします。`x - d2`そして`x + d1`。 コンテスト 2 で許可されている開始間隔を超えた候補者は単純に破棄されます。 

これにより、一定数の候補が得られます。 次に、コンテストを交換して同じ計算が実行されます。 2 つの順序のうち良い方が全体的に最適な答えになります。 

この問題に対する公開されたソリューションでは、同じ定数サイズの候補構造が使用されています。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |`O(10^18)`テストケースごと |`O(1)`| 遅すぎる |

 ## アルゴリズムのチュートリアル

 1. 各コンテストの制限を開始の有効な間隔に変換します。 コンテスト 1 は に開始できます`[l1, r1 - d1]`、コンテスト 2 は に開始できます。`[l2, r2 - d2]`。 2 つのコンテストを比較する場合を除き、間隔チェックに継続時間を表示する必要はなくなりました。 
2. まず、元のスケジュールがすでに重複していないかどうかを確認します。 もし`s1 + d1 <= s2`または`s2 + d2 <= s1`、 戻る`(s1, s2)`すぐに。 移動コストはゼロであり、可能な限り最小限です。 
3. コンテスト 1 がコンテスト 2 より前に終了する必要がある場合を解決します。3 つの可能な値を検討します。`x = l1`、`x = s1`、 そして`x = r1 - d1`。 

これらは、コンテスト 1 の最も早い有効な開始、元の開始、および最も遅い有効な開始です。 

1. そういったものごとに`x`、コンテスト 2 の 2 つの接触位置をテストします。`y = x + d1`そして`y = x - d2`。 

1 つ目はコンテスト 1 の直後にコンテスト 2 を配置します。2 つ目はコンテスト 1 の直前にコンテスト 2 を配置します。 

1. 以下の場合に候補のみを保持します。`l2 <= y <= r2 - d2`。 残りのすべてのペアは重複しない有効なスケジュールであるため、その動きは次のように計算されます。`abs(x - s1) + abs(y - s2)`。 

最小値の候補を保持します。 

1. コンテストを交換して同じ手順を繰り返します。 この 2 回目の呼び出しでは、アルゴリズムは、元のコンテスト 2 がコンテスト 1 の前にあるスケジュールを検索します。結果が見つかったら、その 2 つの開始時刻を元に戻し、再び次のように報告されます。`(c1, c2)`。 
2. 2 つの可能な順序から最良の答えを比較します。 両方の注文が不可能な場合は、印刷してください`-1 -1`。 それ以外の場合は、動きの小さいペアを印刷します。 

定数候補セットで十分な理由は、1 つの固定順序の最適値が、元の開始点、許可された終了点、または 2 つの競合が接触する点に到達するまで、実行可能領域に沿って移動できるためです。 選択された 3 つの値`x`最初のコンテストに関連するポジションをカバーしながら、`x - d2`そして`x + d1`接触する境界をカバーします。 最適値が 2 番目のコンテストに属する境界によって引き起こされているように見える場合は、同じ実行可能な境界に沿って移動すると、これらの候補位置の 1 つで同等の最適値に到達します。 

### なぜ効果があるのか

 実現可能なスケジュールは 2 つの領域を結合したもので、1 つは満足のいくものです。`c1 + d1 <= c2`そしてもう一つは満足です`c2 + d2 <= c1`。 各領域を個別に最適化して、より良い結果を取得します。 

どちらの領域内でも、目的は絶対値の合計であるため、区分的に線形になります。 この 1 次元境界構造上のこのような関数の最小値は、その値を増やすことなくブレークポイントに向かってシフトできます。 ブレークポイントは元の開始位置と許可された間隔の終点から取得されますが、順序付けの制約が接触境界に影響します。 アルゴリズムは、これらの一定サイズの可能性を正確に列挙します。 

したがって、考えられるすべての最適な順序付けには、アルゴリズムによって検査された候補の中から少なくとも 1 つの最適なスケジュールが含まれます。 すべての候補の有効性が明示的にチェックされ、その正確な移動コストが計算されるため、最もよく保持された候補が全体的に最適になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**30

def fix_first(l1, r1, l2, r2, s1, d1, s2, d2):
    # Solve the case where contest 1 is before contest 2.
    if s1 + d1 <= s2 or s2 + d2 <= s1:
        return 0, s1, s2

    best_cost = INF
    best_c1 = -1
    best_c2 = -1

    latest1 = r1 - d1
    latest2 = r2 - d2

    for x in (l1, s1, latest1):
        for y in (x - d2, x + d1):
            if y < l2 or y > latest2:
                continue

            # Check that the two contests are actually disjoint.
            if x + d1 > y and y + d2 > x:
                continue

            cost = abs(x - s1) + abs(y - s2)

            if cost < best_cost:
                best_cost = cost
                best_c1 = x
                best_c2 = y

    return best_cost, best_c1, best_c2

def solve_case(l1, r1, l2, r2, s1, d1, s2, d2):
    first = fix_first(l1, r1, l2, r2, s1, d1, s2, d2)

    # Swap the contests. The returned pair is then swapped back.
    second = fix_first(l2, r2, l1, r1, s2, d2, s1, d1)

    if second[0] < INF:
        second = (second[0], second[2], second[1])

    if first[0] == INF and second[0] == INF:
        return -1, -1

    if first[0] <= second[0]:
        return first[1], first[2]

    return second[1], second[2]

def main():
    t = int(input())
    out = []

    for _ in range(t):
        l1, r1, l2, r2 = map(int, input().split())
        s1, d1, s2, d2 = map(int, input().split())

        c1, c2 = solve_case(l1, r1, l2, r2, s1, d1, s2, d2)
        out.append(f"{c1} {c2}")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    main()
```の`fix_first`この関数は、スケジュールの 1 つの方向を処理します。 最初のチェックでは、候補を列挙する前にコストがゼロのケースが処理されます。 これが重要なのは、コンテストがすでにバラバラである場合、最適コストはまったくゼロであり、別のスケジュールを探す理由がないからです。`latest1 = r1 - d1`そして`latest2 = r2 - d2`は最新の法的な開始時刻です。 これらの値を使用するのではなく、`r1`そして`r2`間違いのよくある原因です。 制限はコンテスト全体に適用されるため、から始まるコンテストは`r1`許可された時間を過ぎると終了します。 

The nested loops contain only three possible values of`x`および次の 2 つの可能な値`y`, したがって、候補者は最大でも 6 人です。 条件`y < l2 or y > latest2`コンテスト 2 の完全な有効範囲をチェックします。 

明示的なオーバーラップ チェックにより、生成された位置が通常は接触している位置であっても、関数が堅牢になります。 平等は意図的に受け入れられています。 例えば、`x + d1 == y`は、最初のコンテストが 2 番目のコンテストの開始と同時に終了することを意味します。 

すべての座標とすべての移動コストは、Python の整数に快適に収まります。 可能な最大の動きは次のとおりです。`10^9`, しかし、Python の任意精度の整数により、実装はオーバーフローの影響を受けにくくなります。 

2回目の電話は`fix_first`コンテスト固有のパラメータをすべて交換します。 その結果は入れ替えられた座標順序で表現されるので、`second[1]`そして`second[2]`最初の結果と比較する前に交換する必要があります。 

## 実用的な例

 ### サンプル 1

 最初のサンプルは```
l1 = 14, r1 = 22, l2 = 12, r2 = 18
s1 = 15, d1 = 5, s2 = 16, d2 = 2
```法的なスタートは、`[14, 17]`コンテスト1と`[12, 16]`コンテスト2用。 

本来の間隔は、`[15, 20]`そして`[16, 18]`, したがって、それらは重なっています。 アルゴリズムは両方の可能な順序を検索します。 

最初のオーダーでは、コンテスト 1 はコンテスト 2 の開始までに終了する必要があります。 

|`x`|`y`候補者 | 有効`y`| 動き |
 | --- | --- | --- | --- |
 | 14 | 12、19 | 12 |`1 + 4 = 5`|
 | 15 | 13、20 | 13 |`0 + 3 = 3`|
 | 17 | 15、22 | 15 |`2 + 1 = 3`|

 ここで見つかった最適な答えの 1 つは、`(15, 13)`トータルな動きで`3`。 スケジュールは`[15,20]`に続く`[13,15]`, そのため、コンテストはタッチのみです。 

交換された向きには、全体的な動きを伴う最適なソリューションもあります`3`。 その結果、アルゴリズムは動きのある有効なペアを返す可能性があります。`3`、 のような`(17, 15)`。 

サンプルの公式出力では、`(16, 14)`、動きもあります`3`。 このステートメントでは、あらゆる最適な答えが明示的に許可されているため、別の最適なペアが受け入れられます。 

### サンプル 2

 2つ目のサンプルは、```
l1 = 12, r1 = 22, l2 = 14, r2 = 20

```有効な開始間隔は次のとおりです。`[12,17]`そして`[14,16]`。

 | --- | --- | --- | --- |

 | 17 | 13 | 22 | なし |

 コンテスト 2 の前にコンテスト 1 には有効な候補者がありません。コンテストを交換した後、反対方向でも同じことが起こります。 

その理由は構造的なものです。 コンテスト 1 には 5 つのタイム ユニットが必要で、コンテスト 2 には 4 つのタイム ユニットが必要ですが、両方のコンテストを重複せずに配置するには、それらを組み合わせた利用可能なウィンドウが狭すぎます。 したがって、アルゴリズムは次の値を返します。`-1 -1`。

large_output = run("\n".join(large_input)).splitlines()

assert len(large_output) == 50000, "maximum n"
assert all(x == "0 1" for x in large_output), "maximum n output"

 ## 特殊なケース

 コンテストがすでに素である場合、アルゴリズムはすぐに終了します。`fix_first`。 例えば、```
1
0 10 20 30
0 5 20 5
```もっている`s1 + d1 = 5 <= 20 = s2`。 返されるコストはゼロで、スケジュールはそのまま残ります`(0, 20)`。 前向きな動きをする候補者はゼロに勝つことはできません。 

コンテストがエンドポイントで正確に接触する場合、比較では次を使用する必要があります。`<=`、 ない`<`。 のために```
1
0 3 2 5
0 2 2 1
```スケジュール`(0, 2)`満足する`0 + 2 = 2`。 最初のコンテストは`[0,2]`そして2番目が占めます`[2,3]`。 等しいことが 2 つのコンテスト間の有効な境界を表すため、アルゴリズムはこの候補を受け入れます。 

両方のコンテストが同じ期間に強制的に行われる場合、どちらの方向からも候補者を生み出すことはできません。 で```
1
0 2 0 2
0 2 0 2
```両方の正当な開始間隔には、`0`。 候補チェックでは有効な候補が見つかりませんでした`y`したがって、両方の方向で無限のセンチネル コストが保持され、最終結果は次のようになります。`-1 -1`。 

両方のコンテストを最適なスケジュールで進める場合、一方的な動きだけを考慮するだけでは不十分です。 で```
1
14 22 12 18
15 5 16 2
```スケジュール`(17, 15)`動きがある`|17-15| + |15-16| = 3`。 2 つのコンテストは同時に行われます`15 + 5 = 20`2 番目が最初の後にある場合のみですが、対称呼び出しによって同様に適切な逆の配置も見つけることができます。 このアルゴリズムは、元の順序が保持されるべきであると仮定するのではなく、両方の方向を比較します。 

座標が大きくても検索空間は変わりません。 のために```
1
0 1000000000 0 1000000000
500000000 1 500000000 1
```元のコンテストは重複します。 最初のオリエンテーションでは、コンテスト 2 を 1 ユニット早く移動できます。`(500000000, 499999999)`トータルな動きで`1`。 利用可能な時間範囲には約 10 億の開始時刻が含まれているにもかかわらず、アルゴリズムは依然として、その方向の候補 6 つと逆方向の候補 6 つだけをチェックします。
