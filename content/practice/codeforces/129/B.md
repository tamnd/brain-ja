 **確認済み:** はい

 ## 解決策
 ## 問題の理解

 学生と靴ひもを無向グラフとしてモデル化できます。 各生徒は頂点であり、2 人の生徒の間のすべての靴紐はエッジです。 

1 ラウンドで、学位がちょうど 1 の生徒はすべて同時に除外されます。 それらの生徒が去ると、すべての事件のエッジも同様に消えます。 これにより、次のラウンドで新しい次数 1 の頂点が作成される可能性があります。 このプロセスは、次数 1 の頂点がなくなるまで続きます。 

タスクは、何ラウンドの除去が発生したかをカウントすることです。 

制約は十分に小さいため、高度なグラフ理論機構は必要ありませんが、制約が十分に大きいため、不注意に再計算を繰り返すとコストが高くなる可能性があります。 ラウンドごとにすべての頂点の次数を最初から再計算すると、密なグラフではほぼすべてのエッジを何度もスキャンすることになります。 解決策$O(n + m)$または$O(n^2)$ここでは完全に安全ですが、それに近いものは$O(nm)$危険になり始める。 

最も危険な実装の詳細は、同時削除です。 グループ全体をまとめて削除するのではなく、生徒を 1 人ずつ削除するとします。 これによりラウンド中にグラフが変化し、余分な生徒が誤って削除される可能性があります。 

次のグラフを考えてみましょう。```
1 - 2 - 3
```入力：```
3 2
1 2
2 3
```正しいプロセスは次のとおりです。 

最初のラウンドでは 1 と 3 を一緒に削除します。 

2ラウンド目は2を取り除きます。 

答え = 2。 

欲張って一度に 1 つずつ削除すると、最初に 1 を削除すると、すぐに 2 が次数 1 になり、同じラウンドで誤って削除してしまう可能性があります。 

もう 1 つの簡単な間違いは、孤立した頂点の処理を誤ることです。 このルールでは次数 1 の頂点のみが削除されるため、次数 0 のスチューデントは削除されません。 

例：```
3 0
```生徒たちは最初から孤立している。 誰も辞めないので、答えは次のようになります。```
0
```次数が 1 以下のすべての頂点を削除する不注意な実装では、誤って 1 が生成されてしまいます。 

サイクルも重要なエッジケースです。 サイクルでは、すべての頂点の次数が 2 であるため、何も起こりません。 

例：```
4 4
1 2
2 3
3 4
4 1
```正しい出力:```
0
```プルーニングを繰り返すと、最終的にすべての接続コンポーネントが削除されると想定したソリューションは、ここでは失敗します。 

## アプローチ

 直接シミュレーションは簡単です。 現在のグラフを維持し、次数 1 のすべての頂点を見つけ、それらを同時に削除し、グラフを更新し、そのような頂点がなくなるまで繰り返します。 

ブルート フォース バージョンでは、各ラウンド後にすべての次数を最初から再計算します。 最悪の場合、長いチェーンではラウンドごとに 2 つの頂点しか削除されません。 あれば$n$頂点については実行できます$n/2$ラウンドします。 毎回すべての次数を再計算するとコストがかかる$O(m)$、おおよそにつながります$O(nm)$。 

これでも制約が小さい場合は問題ありませんが、ほとんどのエッジはラウンド間で変化しないため、不必要な作業が行われます。 

重要な点は、削除された頂点の隣接頂点のみが次数を変更できるということです。 学生が退席したら、すべてを再構築するのではなく、隣接する学生の学位を更新するだけで済みます。 

これにより、問題は階層化された葉の除去プロセスに変わります。 現在の次数を維持し、次数が 1 であるすべての頂点を繰り返し削除します。すべてのエッジは、その端点の 1 つが消えた場合にのみ処理されるため、合計作業量はグラフのサイズにおいて線形になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(nm)$|$O(n + m)$| 概念的には遅すぎる |
 | 最適 |$O(n + m)$|$O(n + m)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. グラフの隣接リストを作成し、すべての頂点の次数を計算します。 
2. 次数が正確に 1 である頂点をすべて見つけます。これらは、最初のラウンドで削除された生徒です。 
3. 現在のラウンドが空でない間は、一度に 1 ラウンド全体を処理します。 
4. 1 つのグループの生徒が追い出されるので、答えを 1 増やします。 
5. 現在のラウンド内のすべての頂点を削除済みとしてマークします。 削除は同時に行われるため、バッチ全体をまとめて処理します。 
6. 削除されたすべての頂点について、その隣接頂点を反復処理します。 
7. 隣接エッジがまだ削除されていない場合は、1 つの入射エッジが消失するため、その次数を 1 減らします。 
8. 更新後に近隣の次数がちょうど 1 になった場合、それを次のラウンドに配置します。 
9. 現在のラウンドを次のラウンドに置き換えて続行します。 
10. 次数 1 の頂点がなくなったら、停止してラウンド数を出力します。 

### なぜ効果があるのか

 度数配列は、すべての以前のラウンドが削除された後の現在のグラフと常に一致します。 頂点は、現在のラウンドが消滅した後、次数が 1 になったときに正確に次のラウンドに入ります。 削除はバッチで処理するため、アルゴリズムはステートメントの同時削除ルールに完全に一致します。 頂点の削除が早すぎたり遅すぎたりすることはありません。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    graph = [[] for _ in range(n)]
    degree = [0] * n

    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1

        graph[u].append(v)
        graph[v].append(u)

        degree[u] += 1
        degree[v] += 1

    removed = [False] * n

    current = deque()

    for i in range(n):
        if degree[i] == 1:
            current.append(i)

    rounds = 0

    while current:
        rounds += 1

        next_round = deque()

        current_nodes = list(current)
        current.clear()

        for node in current_nodes:
            removed[node] = True

        for node in current_nodes:
            for nei in graph[node]:
                if removed[nei]:
                    continue

                degree[nei] -= 1

                if degree[nei] == 1:
                    next_round.append(nei)

        current = next_round

    print(rounds)

solve()
```隣接リストはグラフを効率的に保存し、学位配列は各生徒の現在の残りの隣接数を追跡します。 

最初のループはすべての最初のリーフ、つまり次数が正確に 1 の頂点を収集します。これらが最初のラウンドを形成します。 

微妙な部分は、同時除去を正しく処理することです。 まず、現在のキューからすべての頂点をコピーします。`current_nodes`隣接するものを更新する前に、それらをすべて削除済みとしてマークします。 これにより、ラウンド内の 1 つの削除が、同じラウンド内の別の頂点がまだ存在するかどうかに影響を与えることがなくなります。 

の`removed`配列により、すでに削除された頂点に対する複数の更新が防止されます。 これがないと、次数が負になったり、将来のラウンドに頂点が繰り返し挿入されたりする可能性があります。 

よくある間違いは、次数が 1 以下になるたびに次のラウンドに頂点を追加することです。これにより、孤立した頂点が誤って削除されてしまいます。 条件は正確に一致する必要があります`degree[nei] == 1`。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(n + m)$| すべての頂点とエッジは一定の回数だけ処理されます。 
| スペース |$O(n + m)$| 隣接リスト、次数配列、キュー、および削除された配列 |

 これは簡単に制限に適合します。 最大の有効なグラフであっても、頂点とエッジにわたる線形処理は 2 秒以内の速度で処理されます。

 ## 特殊なケース

 孤立した頂点を考慮します。```
3 0
```初期学位は、`[0, 0, 0]`。 次数 1 の頂点はないため、キューは空から始まります。 ループは実行されず、答えは 0 のままです。孤立した生徒は叱責されないため、これはルールに一致します。 

ここで星形グラフを考えてみましょう。```
5 4
1 2
1 3
1 4
1 5
```初期学位は、`[4, 1, 1, 1, 1]`。 

最初のラウンドでは、頂点 2、3、4、5 が同時に削除されます。 頂点 1 は 4 つのエッジを失い、次数は 0 になります。削除できるのは次数 1 の頂点だけであるため、プロセスは 1 ラウンド後に停止します。 答えは 1 です。 

を使用した不注意な実装`degree <= 1`2 回目のラウンドで頂点 1 が誤って削除されてしまいます。 

最後に、チェーンについて考えてみましょう。```
5 4
1 2
2 3
3 4
4 5
```ラウンド 1 では頂点 1 と 5 が削除されます。 

学位は`[0, 1, 2, 1, 0]`。 

ラウンド 2 では頂点 2 と 4 が削除されます。 

学位は`[0, 0, 0, 0, 0]`。 

両方の隣接頂点が同じラウンドで消滅するため、頂点 3 は次数 1 になることはありません。 プロセスは答え 2 で停止します。 

これは、同時アップデートの重要性を裏付けています。
