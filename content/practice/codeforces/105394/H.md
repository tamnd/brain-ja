 ## 解決策
 ## 問題の理解

 私たちには、大学名のコレクション、いくつかの大学のペア間の一連のライバル関係、および一連のニュース記事が与えられます。 記事ごとに、それが「十分にバランスが取れている」かどうか、または少なくとも 1 人のコーチを怒らせるかどうかを判断する必要があります。 

ある大学に関係するコーチは、1 つの記事の中に、厳密に言えば自分の大学よりもライバル大学の方が多く登場すると怒ります。 ライバル関係は対称的であるため、各ライバル関係のペアは、相互に比較する必要がある大学のペアを定義します。 

したがって、すべての記事について、各大学名が記事テキスト内の部分文字列として出現する回数を効率的にカウントし、すべての競合エッジ u-v について、ルールに違反する方法で count[u] < count[v] または count[v] < count[u] かどうかを確認する必要があります。 ライバル関係のペアがどちらかの方向で不均衡な場合、その記事は拒否されます。 

難しいのは、大学名はスペースを含む任意の小文字の文字列であり、重複する可能性があり、ある名前が別の名前の中に現れる可能性があることです。 記事ごとの名前ごとの単純な部分文字列検索では、遅すぎます。 

全体としての制約は厳しいです。 すべての大学名とすべての記事の合計の長さは最大 10^6 ですが、大学、ライバル関係、記事の数はそれぞれ最大 10^5 になります。 これは、パターンごとのマッチングではなく、テキスト全体にわたって線形時間に近いものが必要であることを強く示唆しています。 大学名ごとに各論文を個別にスキャンするアプローチでは、結果が約 O(k · n · L) にまで低下し、これはまったく実行不可能です。 

2 番目の微妙な問題は、一致の重複です。 たとえば、ある大学が「uni」で、別の大学が「uni ulm」である場合、単純な部分文字列マッチングでは、複数の矛盾した方法で「uni ulm」内の「uni」をカウントする可能性があります。 すべての出現を正確にカウントする、一貫したマルチパターン マッチング方法が必要です。 

素朴なソリューションを壊すエッジケースには、次のようなものがあります。 

大学を「uni」と「uniu」で表す「uniuni」のような記事。 単純な検索では、実装によっては重複する一致を見逃したり、二重にカウントしたりする可能性があります。 

別の例は、「kit」や「kitten」など、他の名前の部分文字列である名前です。 「子猫キット」という記事では、両方のパターンを干渉せずに独立してカウントする必要があります。 

最後に、記事にはスペースやスペースにまたがるパターンが含まれる場合があるため、空白での分割は無効です。 

## アプローチ

 ブルートフォース手法では、各大学名をパターンとして試し、部分文字列検索を使用して各記事をスキャンします。 各記事、各大学について、考えられるすべての開始位置をチェックします。 論文の平均長が L で、大学が n 個ある場合、これは O(k · n · L) となり、限界をはるかに超えています。 

KMP を使用してパターンごとの部分文字列検索を最適化しても O(k · (n + L)) に削減されますが、大学ごとに個別に KMP を構築して実行すると、依然として n 倍になり、遅すぎます。 

重要な観察は、多くのテキストに対して多くのパターンを同時に照合しているということです。 これはまさにアホ・コラシックのオートマトンの設定です。 すべての大学名に対して単一のオートマトンを構築することで、各論文を線形時間で 1 回スキャンし、一致したすべてのパターンをレポートできます。 

このアイデアは、すべての大学名をトライ内の文字列として扱い、失敗リンクを追加して、一致したすべてのパターン ID を出力しながら、O (記事の長さ) でテキストを遷移できるようにすることです。 各キャラクターは状態を進め、パターンの終わりに対応するノードに到達するたびに、その大学のカウントをインクリメントします。 

記事の数を計算した後は、すべての競合エッジをチェックするだけで済みます。 各エッジは 2 つの整数の単純な比較です。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | パターンごとの総当たり攻撃 | O(k・n・L) | お(1) | 遅すぎる |
 | パターンごとの KMP | O(k · (n + L)) | O(n · パターン サイズ) | 遅すぎる |
 | アホ・コラシック | O(合計テキスト + 合計パターン + 一致 + m) | O(総パターンサイズ) | 承認済み |

 ## アルゴリズムのチュートリアル

 すべての大学名に対してマルチパターン マッチング オートマトンを構築し、それを使用して各論文を処理します。 

1. すべての大学名をトライに挿入し、それぞれの名前に一意の識別子を割り当てます。 各ターミナル ノードは、それが表す大学インデックスを格納します。 これにより、あらゆる出来事を大学にマッピングできるようになります。 
2. トライ上の BFS を使用して障害リンクを構築します。 ノードの障害リンクは、トライ内のプレフィックスでもある現在のプレフィックスの最も長い適切なサフィックスを指します。 これにより、テキストのスキャン中に不一致が発生した場合に効率的にフォールバックできるようになります。 
3. 出力リンクも伝播します。障害リンクが有効なパターンの終わりであるノードを指している場合、現在のノードもそのパターンを報告できることを確認します。 これにより、重複するものを含むすべての一致が検出されることが保証されます。 
4. 各記事について、オートマトンのルートから開始して文字を 1 つずつスキャンします。 各キャラクターのトランジションに従います。 遷移が存在しない場合は、一致するものが見つかるか、ルートに戻るまで失敗リンクをたどります。 訪問した各州は 1 つ以上の大学名に対応する可能性があり、それに応じてカウンターをインクリメントします。 
5. 記事をスキャンした後、すべての競合ペアをチェックします。 各ペア (u, v) について、count[u] < count[v]、または count[v] < count[u] の場合、記事を無効としてマークします。 
6. 競合制約に違反しない場合は「yes」を出力し、違反しない場合は「no」を出力します。 

### なぜ効果があるのか

 記事内のどの位置でも、オートマトンの状態は、ある大学名の接頭辞と一致する、処理された接頭辞の最長の接尾辞を表します。 障害リンクにより、すべての短いサフィックスも暗黙的に考慮されるようになります。 これは、現在位置で終わるすべてのパターンのすべての出現が 1 回だけ検出されることを意味します。 大学での発生はすべて正確かつ独立してカウントされるため、最終的なカウントは正確になります。 競合チェックは真の周波数での直接比較となるため、正確さはマルチパターン マッチングの正確さに帰着します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import deque

class Node:
    __slots__ = ("next", "link", "out")
    def __init__(self):
        self.next = {}
        self.link = 0
        self.out = []

class Aho:
    def __init__(self):
        self.t = [Node()]

    def add(self, s, idx):
        v = 0
        for ch in s:
            if ch not in self.t[v].next:
                self.t[v].next[ch] = len(self.t)
                self.t.append(Node())
            v = self.t[v].next[ch]
        self.t[v].out.append(idx)

    def build(self):
        q = deque()
        for c, v in self.t[0].next.items():
            self.t[v].link = 0
            q.append(v)

        while q:
            v = q.popleft()
            for c, u in self.t[v].next.items():
                q.append(u)

                f = self.t[v].link
                while f and c not in self.t[f].next:
                    f = self.t[f].link
                self.t[u].link = self.t[f].next[c] if c in self.t[f].next else 0

                self.t[u].out += self.t[self.t[u].link].out

    def run(self, text, cnt):
        v = 0
        for ch in text:
            while v and ch not in self.t[v].next:
                v = self.t[v].link
            if ch in self.t[v].next:
                v = self.t[v].next[ch]
            else:
                v = 0

            for idx in self.t[v].out:
                cnt[idx] += 1

def solve():
    n, m, k = map(int, input().split())
    names = [input().rstrip("\n") for _ in range(n)]

    aho = Aho()
    for i, s in enumerate(names):
        aho.add(s, i)
    aho.build()

    edges = [tuple(map(lambda x: int(x) - 1, input().split())) for _ in range(m)]
    articles = [input().rstrip("\n") for _ in range(k)]

    for t in articles:
        cnt = [0] * n
        aho.run(t, cnt)

        ok = True
        for u, v in edges:
            if cnt[u] < cnt[v] or cnt[v] < cnt[u]:
                ok = False
                break

        print("yes" if ok else "no")

if __name__ == "__main__":
    solve()

記事の処理中、単一の状態ポインターを維持します。 各文字遷移は O(1) で償却されるため、スキャンは記事の長さに対して線形になります。 出力のあるノードに到達するたびに、一致したすべての大学のカウントが増加します。 

競合エッジ上の最後のループはマッチングから分離されているため、スキャン中に繰り返しの比較を避けることができます。

 ## 特殊なケース

 重要なエッジケースの 1 つは、大学名が重複していることです。 「uni」と「uni ulm」がある場合、「uni ulm uni ulm」をスキャンすると、両方の位置で両方が正しくカウントされるはずです。 オートマトンは、「uni」と一致した後も続行でき、必要に応じて「uni ulm」と一致することを保証します。これは、遷移が完全なパスをエンコードし、障害リンクがサフィックスの再利用を可能にするためです。 

もう 1 つの特殊なケースは、繰り返し発生することです。 「uni uni uni」では、障害遷移後に状態が中間ノードに正しく戻るため、発生するたびに独立して増加します。 

3 番目のエッジケースは、大学がまったく表示されない場合です。 すべてのカウントはゼロであるため、すべての競合比較は同等であり、すべての記事が受け入れられます。 出力ノードが訪問されないため、実装はこれを自然に処理します。
