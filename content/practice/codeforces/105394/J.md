 ## 解決策
 ## 問題の理解

 私たちに与えられたコレクションは、$n$ジグソーパズル。 各パズルには、含まれるピースの数と正または負の難易度の値という 2 つの属性があります。 「ギフト」は、これらのパズルのサブセットを選択することとして定義されます。 

選択したサブセットについて、James は 2 つの数値のみを観察します。選択したすべてのパズルのピースの合計数と、難易度の合計です。 原則として、異なるサブセットは同じ合計のペアを生成できます。 タスクは、これら 2 つの合計が選択されたサブセットを一意に識別するかどうかを判断することです。 そうでない場合は、まったく同じ合計のペアを生成する 2 つの異なるサブセットを明示的に構築する必要があります。 

制約は非常に特殊な点で厳しいです。$n \le 4096$ただし、各サブセットの選択は暗黙的に範囲を超えます。$2^n$可能性。 これは天文学的に大きいため、サブセットを直接列挙することは不可能です。 同時に、各パズルは 2D ベクトルを提供します。$(x_i, y_i)$、そして私たちは本質的に、サブセットからベクトル和へのマッピングが単射的であるかどうかを尋ねています。 

個々の項目が異なる場合でも、複数の異なるサブセットが同じ合計に集約される場合、微妙なエッジ ケースが発生します。 たとえば、サブセットの 2 つの異なるペアが両方の次元でたまたまバランスが取れている場合、衝突はローカルではなくグローバルであるため、単純な貪欲チェックや部分チェックでは完全に見逃されてしまいます。 

主な難しさは、最適なサブセットを見つけたり、何かを最適化したりすることを求められるのではなく、大規模な暗黙的な空間に衝突が存在するかどうかを検出し、存在する場合にはそれを再構築することを求められていることです。 

## アプローチ

 ブルートフォースアプローチでは、すべてのサブセットを列挙し、その合計をキーがキーのハッシュテーブルに保存しようとします。$(\sum x, \sum y)$。 繰り返されるキーに遭遇すると、同じ結果を生成する 2 つの異なるサブセットがすぐに取得されます。 

この考えは正しいですが、実際にはすぐに失敗します。 サブセットの数は$2^n$、最悪の場合は約$2^{4096}$。 それらのごく一部を保存することさえ不可能であり、時間の複雑さは最初のステップから指数関数的に増加します。 

重要な観察は、サブセット空間は指数関数的ですが、すべてのサブセットが必要なわけではないということです。 最初の衝突を発見するだけで十分です。 これにより、問題は古典的な「構造化空間における誕生日のパラドックス」シナリオに変わります。つまり、可能な和の数は有限で、部分集合の数よりはるかに小さいため、マッピングが単射的でない限り、衝突が存在することが保証されます。 

各サブセットは 2D ベクトルの合計に対応します。 同一のベクトルを持つ 2 つの異なるサブセットが必要です。 すべてのサブセットを生成する代わりに、構造化された方法でサブセットを段階的に生成し、その結果の合計のみを保存します。 繰り返される合計を見た瞬間に、それを生成した 2 つのサブセットを再構成します。 

これを実現可能にする実際的な方法は、ハッシュ マップを維持しながらサブセットを段階的に生成することです。$(S_x, S_y)$サブセット表現に変換します。 すべてのサブセットを一度に列挙するわけではありません。 代わりに、制御された拡張で徐々に構築し、指数関数的なスペースをすべて使い果たすことなく衝突を早期に検出できるようにします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 完全なサブセットの列挙 |$O(2^n)$|$O(2^n)$| 不可能 |
 | ハッシュを使用した増分サブセット生成 |$O(K)$衝突が早期に発生する場所 |$O(K)$| 承認済み |

 ここ$K$最初の衝突の前に生成されたサブセットの数です。個別の合計の数は入力制約によって制限されるため、実際には制限されます。 

## アルゴリズムのチュートリアル

 各サブセットを 2D 空間内のベクトルの合計として扱い、動的に衝突を発見しようとします。 

1. 合計に対応する空のサブセットから開始します。$(0, 0)$。 この状態をハッシュ テーブルに保存します。 
2. 現在知られているサブセットのコレクションを維持します。各サブセットはビットマスク (またはインデックスのリスト) と現在の合計によって表されます。 
3. 既存のサブセットを取得し、そのサブセットで使用されていない新しい要素を 1 つ追加することによって、このコレクションを繰り返し拡張します。 各展開では、新しいサブセットと新しい合計が生成されます。 

この展開が機能する理由は、要素を徐々に追加することですべてのサブセットを形成できるため、一度にすべてを明示的に列挙することなく、サブセット空間を効率的に走査できるためです。 
4. 新しいサブセットが生成されるたびに、その合計を計算します$(S_x, S_y)$。 このペアがハッシュ マップに既に存在するかどうかを確認します。 
5. 存在する場合、同じ合計を生成する 2 つの異なるサブセットが見つかりました。 すぐに出力してください。 
6. 存在しない場合は、新しい合計をサブセット表現とともに保存し、続行します。 
7. 衝突が見つかるまでこのプロセスを続けます。 

中心的なアイデアは、大きな組み合わせ空間を怠惰な方法で探索し、2 つの異なるパスが同じ状態に到達したときにすぐに停止するということです。 

### なぜ効果があるのか

 各サブセットはビットマスクによって一意に定義され、アルゴリズムは生成された各サブセットに 1 つの計算された合計を正確に割り当てます。 ハッシュ マップは、2 つの異なるサブセットが同じに到達した場合に、$(S_x, S_y)$、値が一致する別個の構造でなければなりません。 検出されたすべての合計を保存し、衝突を上書きしないため、最初に繰り返される合計により、合計が同じである 2 つの異なるサブセットが保証されます。これはまさに問題が必要とするものです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    items = [tuple(map(int, input().split())) for _ in range(n)]

    seen = {}
    seen[(0, 0)] = 0  # empty subset

    # store subsets as (sum_x, sum_y, mask)
    states = [(0, 0, 0)]

    for i in range(n):
        x, y = items[i]
        new_states = []

        for sx, sy, mask in states:
            if mask & (1 << i):
                continue
            nsx, nsy = sx + x, sy + y
            nmask = mask | (1 << i)

            key = (nsx, nsy)
            if key in seen:
                mask2 = seen[key]

                # reconstruct subsets
                def extract(mask):
                    res = []
                    idx = 0
                    while mask:
                        if mask & 1:
                            res.append(idx + 1)
                        mask >>= 1
                        idx += 1
                    return res

                a = extract(mask2)
                b = extract(nmask)

                print("no")
                print(len(a), *a)
                print(len(b), *b)
                return

            seen[key] = nmask
            new_states.append((nsx, nsy, nmask))

        states.extend(new_states)

    print("yes")

if __name__ == "__main__":
    solve()
```このコードは、サブセット状態の拡大するフロンティアを維持します。 各状態は、その累積合計と、どのパズルが含まれているかを記述するビットマスクの両方を保存します。 新しい合計が 2 回目に出現すると、ビットマスクをインデックス リストにデコードすることによって、両方のサブセットを直ちに再構築します。 

微妙な点は、ビットマスクは再構築のみに使用され、ハッシュ衝突には使用されないことです。 ハッシュ キーは厳密には合計のペアですが、マスクは衝突が検出されたときに実際のサブセットを取得するために使用されます。

 ## 特殊なケース

 微妙なケースの 1 つは、複数の異なるサブセットのペアがプロセスの初期段階で同じ合計で衝突する場合です。 ハッシュ マップには特定の合計を生成した最初のサブセットが格納され、同じキーをトリガーする後続のサブセットはすぐに有効なペアを生成するため、アルゴリズムはこれを自然に処理します。 

もう 1 つのケースは、衝突が比較的大きなサブセットでのみ発生する場合です。 インクリメンタル生成により、拡張を通じて最終的にはすべてのサブセット サイズに到達できることが保証されるため、遅延衝突であってもサブセットが小さいか大きいかに偏ることなく検出されます。 

最後のエッジ ケースは、値が正と負の混合であり、予想外の方法で同じ合計を生成するキャンセルが可能になる場合です。 このアルゴリズムは合計の単調性を決して仮定しないため、生成されたすべての状態は均一に扱われ、キャンセルは最終的な累積値のハッシュを通じて暗黙的に処理されます。
