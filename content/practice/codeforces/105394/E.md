 ## 解決策
 ## 問題の理解

 有限のカードの集合が与えられ、各カードは共有整数状態に対する単項演算を表します。 移動するたびに、プレイヤーは未使用のカードを 1 枚選び、その操作を現在の値に適用します。 すべてのカードが消費されるまで、プレーヤーは交代します。 最後の動きの後、結果の数字のパリティによって勝者が決まります。ゲームで最初に動いたプレイヤーが奇数で終了した場合、そのプレイヤーが勝者と宣言され、そうでない場合は他のプレイヤーが勝ちます。 

重要な自由は、プレイヤーが固定されたカードの順序に従わないことです。 代わりに、交互のピックを通じてすべての操作の順列を共同で構築しています。 これにより、問題は逐次的な敵対的順序付けゲームになります。各プレイヤーは、現在どの操作を適用するかを決定するだけでなく、将来の操作の順序も決定します。 

制約により、最大 300 枚のカードが許可されます。 これにより、たとえ 300 であっても、置換に対する指数関数的な検索が即座に排除されます。 実現可能性をはるかに超えています。 サブセットに対する動的プログラミングであっても、大幅に単純化しない限り、サイズが大きすぎます。 実行可能な解決策は、ゲームを小さな状態空間、理想的にはカードの数が一定または対数に圧縮する必要があります。 

微妙な難点は、カードの効果が現在の値に依存するため、同じカードでもプレイするタイミングによって動作が異なる可能性があることです。 これにより、単純な可換性の仮定が排除されます。 すべての演算を任意に並べ替えることができると仮定する不注意なアプローチは、偶数の乗算がパリティをリセットする小さな反例では失敗します。 

最小限の失敗例は次のとおりです。奇数から開始して「偶数による乗算」を適用し、続いて「奇数の加算」を適用すると、順序を逆にした場合とは異なるパリティが得られます。 これは、プレイヤーが選択した順序が表面的なものではなく、本質的なものであることを示しています。 

## アプローチ

 ブルート フォースのビューは単純です。両方のプレイヤーからのピックをインターリーブするすべての可能な方法をシミュレートし、カードの可能なすべての順列を構築し、最終的な値を計算し、最初のプレイヤーが望ましいパリティを強制できるかどうかを確認します。 これは概念的には正しいですが、状態空間はカードのすべてのサブセットとそのターンの集合であり、n の順序で与えられます。 最終的な結果。 ゲームツリーを保存することさえ、非常に小さい n を超えると不可能になります。 

重要な単純化は、パリティの進化だけが関連する情報であることに気づくことから生まれます。 すべての演算は、正確な整数ではなく、パリティを変換する方法に還元できます。 縮小されると、各カードは単一ビットの決定的な関数になります。 

x による加算は、x が奇数であるかどうかのみに依存します。偶数を加算するとパリティは変更されませんが、奇数を加算するとパリティが反転します。 x の乗算は、x が偶数か奇数かによって決まります。偶数を乗算するとパリティは強制的に 0 になりますが、奇数を乗算するとパリティは維持されます。 

したがって、すべてのカードは、同一性、裏返し、またはゼロにリセットする 3 つの動作のうちの 1 つになります。 これにより、ゲームは 2 状態システム上で関数の順列を構築するように変換されます。 

この時点で、構造はゲーム理論的になりますが、非常に小さくなります。 唯一の重要な相互作用は、蓄積されたパリティ履歴を上書きするため、ゼロにリセットする操作から生じます。 アイデンティティ操作は無関係で、反転操作は最後のリセットとの関係でのみ重要です。 

これにより、支配構造が作成されます。リセットはシーケンスをセグメントに分割し、最後のリセット後のセグメントのみが存続する方法で最終パリティに影響を与えることができます。 したがって、プレイヤーは主に、誰が最後のリセットを制御するかについて争います。これは、蓄積されたフリップにとって重要な唯一のセグメントを決定するためです。

これが観察されると、ゲームの残りの部分は、最適なプレイによって最終的なリセット境界が決定された後、リセット カードが何枚存在するか、および関連性が残るフリップ カードが何枚あるかについての議論に崩壊します。

 ## アルゴリズムのチュートリアル

 1. 各カードを、パリティに対する効果に基づいて、反転、同一性、またはゼロへのリセットの 3 つのタイプのいずれかに分類します。 これにより、値の大きさへの依存がすべて取り除かれます。 
2. ゼロにリセットされるカードが何枚存在するかを数えます。 これらのカードは以前のパリティ履歴を上書きするため、ゲーム全体のセグメント化を決定します。 
3. どのプレイヤーが最後のリセットを強制できるかを決定します。 プレイヤーが交互にカードを選んでシーケンスを構築するため、これはリセット カードの数に関する単純なパリティ ゲームになります。最終リセットを効果的にコントロールするプレイヤーは、そのカードの枚数が奇数か偶数かによって決まります。 
4. 最終セグメントのみが重要になると、内部順序は複合パリティ効果に影響を及ぼさないため、アイデンティティ カードとフリップ カードを単一のプールとして修正します。 
5. 最後のリセット境界の後に関連性が残るすべてのフリップ カードの実効パリティ寄与を計算します。 最後のリセット後のサフィックスのみが最終状態に影響を与えるため、以前のフリップはすべて消去され、無関係になります。 
6. 初期パリティと最後に生き残ったフリップ貢献度を組み合わせて、先手プレイヤーが開始プレイヤーになることを目指すべきか、それとも応答プレイヤーになることを目指すべきかを決定します。 

本質的なアイデアは、ゲームは誰が歴史に対する最後の破壊的な操作を制御するかを決定することに帰着し、その後すべてが固定パリティ計算に崩壊するということです。 

### なぜ効果があるのか

 不変条件は、リセット トゥ ゼロ カードで終わる操作のプレフィックスは、それ以前のすべてのパリティ情報を完全に忘れることです。 つまり、最後まで生き残る唯一の情報は、構築されたシーケンスの最後のリセット後に何が起こるかということです。 両方のプレイヤーは操作を変更するのではなく、順序を選択するだけであるため、最後のリセットを配置するために間接的に競合します。 その位置が固定されると、残りの操作は等価な可換システムを形成するため、順序は重要ではなくなり、結果は決定的になります。

import sys
input = sys.stdin.readline

    flip = 0
    reset = 0
    start = None
    
    for _ in range(n):
        o, x = input().split()
        x = int(x)
        
        if o == '+':
            if x % 2 == 1:
                flip += 1
        else:
            if x % 2 == 0:
                reset += 1

```この実装では、各カードがそのパリティ効果に圧縮されます。 加算は、奇数の場合にのみフリップ数に寄与します。 乗算は、パリティを強制的にゼロにする場合、つまり偶数で乗算する場合にのみ、リセット カウントに影響します。 

最終的な決定は、構築された最終パリティが先手の勝利条件と一致するかどうかに基づいて行われます。 微妙な点は、パリティ削減が適用されるとインタラクティブ構造全体が消えるということです。 残るのは、集約された効果から結果の同等性を決定論的に計算することです。 

## 実用的な例

 開始値 5 と 3 枚のカード「+1」、「*2」、「+3」を持つ小さなインスタンスを考えてみましょう。 

| ステップ | 選択された操作 | | 前のパリティ 効果 | | 後のパリティ
 | --- | --- | --- | --- | --- |
 | 1 | +1 | 1 | フリップ | 0 |
 | 2 | *2 | 0 | 0にリセット | 0 |
 | 3 | +3 | 0 | フリップ | 1 |

 このトレースは、リセットが途中で発生しても、前の構造が後の反転を制約しないため、最終的なパリティはその後に起こることによってのみ決定されることを示しています。 

次に、リセット操作がない場合を考えます。「+1」、「+3」の 2 から開始します。 

| ステップ | 選択された操作 | | 前のパリティ 効果 | | 後のパリティ
 | --- | --- | --- | --- | --- |
 | 1 | +1 | 0 | フリップ | 1 |
 | 2 | +3 | 1 | フリップ | 0 |

 ここで、結果はフリップ操作の数のパリティのみに依存し、履歴を消去するためのリセットがないため、順序は無関係です。 これにより、リセットのない場合、問題はフリップ操作に対する単純な XOR に集約されることが確認されます。

import sys, io

def run(inp: str) -> str:

    flip = 0

        x = int(x)

 ## 特殊なケース

 単一の「*2」カードによる最小限の入力は、リセットの優位性を示します。 任意の値から開始して、偶数を乗算すると、パリティは即座にゼロになります。 アルゴリズムはこれをリセット カードとして正しく分類し、フリップとして扱わないため、誤った XOR の蓄積が防止されます。 

「+1」と「*2」のカードが交互にあるケースは、一般に順序が無関係であると想定できない理由を浮き彫りにします。 リセットにより以前のフリップが無効になりますが、このソリューションでは順序をシミュレートするのではなく、すべてをカテゴリ数に減らすため、インターリーブによる誤解を正確に回避できます。 

最後のエッジケースは、フリップカードがまったくない場合です。 最終パリティは、再生順序に関係なく開始パリティと同一になり、アルゴリズムは初期値によってのみ決定される一定の結果に正しく還元されます。
