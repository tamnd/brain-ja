 ## 解決策
 ## 問題の理解

 位置が 1e9 までの非常に大きな 1 次元の直線上で一連の操作が与えられます。 2 種類の操作がオンラインで実行されます。 

最初のタイプは波形を挿入します。 各波はある位置から始まります`p`、長さの連続したセグメントにまたがる`ℓ`、振幅を持っています`a`。 波形の形状は固定されています。波形は、正のピークから始まり 4 つの位置ごとに繰り返されます。`p`。 具体的には、`p`、貢献は繰り返しのパターンに従います`+a, 0, -a, 0, +a, 0, -a, 0, ...`セグメントの長さに切り捨てられます。 したがって、4 番目ごとの位置のみが寄与し、正と負の振幅が交互に切り替わります。 

2 番目のタイプは、以前に追加されたすべての波を適用した後の 1 つの位置での結果の合計高さを求めるクエリです。 波が蓄積するため、各クエリでは、その座標におけるすべてのアクティブな波からの寄与の合計が求められます。 

主な問題点は、位置が最大 1e9 と大きいのですが、演算数が少なく、最大 4000 であることです。これにより、明示的なサイズの配列の維持が即座に排除されます。`w`またはポジションごとのシミュレーションを実行します。 更新ごとに影響を受けるすべてのセルを反復処理するソリューションでは、最大で O(n・w) のコストがかかりますが、これは不可能です。 

さらに微妙な問題は、各更新が均一な範囲の追加ではないことです。 構造化された周期的なパターンです。 単純な間違いは、各波を間隔にわたる +a の単純な範囲更新として扱うことですが、これは交互の符号を無視し、不正確な結果を生成します。 

もう 1 つの一般的な失敗ケースは、更新が重なったときに発生します。2 つのウェーブが相互に干渉する可能性があり、それらの位相は各ウェーブ内のローカルな位置合わせではなく絶対位置に依存します。 たとえば、位置 1 から始まる波と位置 2 から始まる別の波は、同じセグメント上であっても完全に異なる残基パターンを生成するため、間隔によるグループ化だけでは不十分です。 

主なエッジケースは、間隔の off-by-one 処理から発生します。`[p, p + ℓ - 1]`そして、座標系全体にわたって 4 周期の位相を正しく調整することによって実現されます。 

## アプローチ

 直接シミュレーションでは、配列を維持し、波ごとにその間隔を反復して、周期パターンに一致する位置にのみ寄与を適用します。 長さ ℓ の各波のコストは O(ℓ) となり、最悪の場合約 4e3 × 1e9 回の演算が発生しますが、これは完全に実行不可能です。 

重要な観察は、波形パターンは次のもののみに依存するということです。`position mod 4`。 すべての位置は、4 つの独立した等差数列の 1 つに正確に属します: 剰余 0、1、2、および 3 モジュロ 4。各剰余クラス内で、波は次のいずれかに寄与します。`+a`、`-a`、 または`0`そして重要なことに、この動作はその残基のすべての位置で一貫しています。 

これにより、問題を 4 つの独立した範囲加算構造に分割することができます。 ただし、更新が任意の大きな座標上で行われるという問題に依然として直面しています。 これは座標圧縮によって解決されますが、単純な方法では全体的に解決されません。 代わりに、同じ残基を持つ位置のみが同じ更新ルールの下で相互作用するため、各残基クラス内で個別に圧縮します。 

残差ごとに圧縮されると、各波の更新は座標のサブセット上の範囲の追加になります。すべての位置を次のように配置します。`[p, p + ℓ - 1]`残留物に属するもの`p mod 4`(彼らは受け取ります`+a`)、同様に剰余に属するもの`(p + 2) mod 4`(彼らは受け取ります`-a`）。 他の 2 つの残基は影響を受けません。 

各剰余クラスは範囲更新とポイント クエリをサポートするフェンウィック ツリーで維持され、影響を受けるクラスごとに対数時間で各ウェーブを適用できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n・ℓ) | O(w) | 遅すぎる |
 | 最適（残渣分解 + BIT） | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 重要なすべての座標、つまりすべてのクエリ位置とすべての波間隔の両方のエンドポイントを収集します。 これにより、座標範囲全体ではなく、関連する点にのみ構造を構築できるようになります。 
2. これらの座標を、4 を法とする値に基づいて 4 つのグループに分割します。波の寄与が剰余を混合しないため、各グループは独立して処理されます。 
3. 残基グループごとに、座標をソートし、座標値から圧縮インデックスへのマッピングを構築します。 これにより、疎なマップの代わりにコンパクトなフェンウィック ツリーを操作できるようになります。 
4. 各残基グループのフェンウィック ツリーを初期化します。 各ツリーは、その残差クラスのみに影響を与える蓄積された寄与を格納します。 
5. 操作を順番に処理します。 波のために`! p ℓ a`、アクティブな間隔を決定します`[p, p + ℓ - 1]`。 
6. 剰余クラス内`r = p mod 4`、すべての位置は合同`r`受け取る`+a`彼らが間隔にあるときはいつでも。 これらの有効な位置に対応する圧縮インデックスの部分範囲を特定し、範囲加算を適用します。`+a`。 
7. 剰余クラス内`r2 = (p + 2) mod 4`、貢献は`-a`したがって、同じ範囲の更新を負の振幅で適用します。 
8. お問い合わせの場合`? x`、 決定する`r = x mod 4`、見つけます`x`その残差グループ内でそのインデックスでフェンウィック ツリーをクエリして、累積合計を取得します。 

### なぜ効果があるのか

 各位置は正確に 1 つの剰余クラスに属し、波形パターンは波の開始点に対する剰余オフセットによって完全に決定されます。 固定剰余クラス内では、すべての波形が圧縮された座標の連続セグメントにわたって均一な値に寄与するため、フェンウィック ツリー範囲の更新によりすべての寄与が正しく累積されます。 残基を決して混合しないため、波間の干渉は 4 つの構造にわたる独立した合計によって完全に捕捉されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class BIT:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

    def range_add(self, l, r, v):
        if l > r:
            return
        self.add(l, v)
        if r + 1 <= self.n:
            self.add(r + 1, -v)

def solve():
    n, w = map(int, input().split())
    ops = []

    coords = [[] for _ in range(4)]

    for _ in range(n):
        tmp = input().split()
        if tmp[0] == '?':
            p = int(tmp[1])
            ops.append(('q', p))
            coords[p % 4].append(p)
        else:
            p, l, a = map(int, tmp[1:])
            ops.append(('u', p, l, a))
            r1 = p
            r2 = p + l - 1
            coords[p % 4].append(r1)
            coords[p % 4].append(r2)
            coords[(p + 2) % 4].append(r1)
            coords[(p + 2) % 4].append(r2)

    mp = [{} for _ in range(4)]
    bit = []

    for r in range(4):
        vals = sorted(set(coords[r]))
        mp[r] = {v: i + 1 for i, v in enumerate(vals)}
        bit.append(BIT(len(vals)))

    def range_add(r, lval, rval, val):
        if lval > rval:
            return
        l = mp[r].get(lval)
        rgt = mp[r].get(rval)
        if l is None or rgt is None:
            return
        bit[r].range_add(l, rgt, val)

    def point_get(r, x):
        i = mp[r][x]
        return bit[r].sum(i)

    for op in ops:
        if op[0] == 'u':
            _, p, l, a = op
            r1 = p % 4
            r2 = (p + 2) % 4
            L = p
            R = p + l - 1

            range_add(r1, L, R, a)
            range_add(r2, L, R, -a)

        else:
            _, x = op
            r = x % 4
            print(point_get(r, x))

if __name__ == "__main__":
    solve()
```この実装は、残差クラスごとに寄与を分離することに依存しており、これにより周期構造が均一範囲の更新に変換されます。 各 BIT はプレフィックスの蓄積をサポートしており、範囲の更新は標準的な差分トリックによって実装されます。 重要な点は、すべての座標処理が残基ごとに行われることです。 それらを混合すると、波形パターンの位相調整が崩れてしまいます。 

マッピング手順により、次のサイズの配列が割り当てられることがなくなります。`w`すべての操作は、更新またはクエリによって実際に操作される個別の座標の数によって制限されたままになります。 

## 実用的な例

 複数の波が重なって干渉する 2 番目のサンプルを追跡します。 

初期状態にはアクティブな波形はありません。 

| ステップ | 操作 | アクティブな効果 | クエリ結果 |
 | --- | --- | --- | --- |
 | 1 | 波を追加 (2,6,1) | 残基 2 と 0 が更新されました | - |
 | 2 | 波を追加 (3,8,2) | 重複する更新が追加されました | - |
 | 3 | 波を追加 (5,2,3) | 短いローカライズされたアップデート | - |
 | 4 | クエリ6 | すべての貢献の合計 | 1 |
 | 5 | 波を追加 (5,5,4) | 新しい干渉が追加されました | - |
 | 6 | クエリ8 | 再計算された合計 | 3 |
 | 7 | クエリ9 | 最終的な複合効果 | 2 |

 トレースは、クエリが常に以前のすべてのウェーブからの累積干渉を反映していること、および更新によって以前の値が置き換えられるのではなく、残差クラス全体で追加的に階層化されることが示されています。 

重要な観察は、波が重なり合う場合でも、各剰余クラスは独立して進化するため、クエリは同じ位置で評価された 3 つの独立したアキュムレータの単純な合計であるということです。

 ## 特殊なケース

 微妙なケースの 1 つは、波の間隔がまさに負の位相に属する位置で終了する場合に発生します。 パターンは固定されたグローバル アラインメントで周期的であるため、最後の要素は必ずしも完全なサイクルに対応するとは限りません。 サイクルを反復するのではなく、正確な座標メンバーシップをフィルタリングすることによって更新が適用されるため、実装はこれを自然に処理します。 

別のエッジケースは、2 つの波が異なる残基で始まり、間隔が重なる場合に発生します。 たとえば、2 で始まる波と 3 で始まる別の波は両方とも位置 6 をカバーしますが、それらの寄与はクエリ時まで異なる残差 BIT に格納され、そこで合計されます。 この分離により、単純な結合構造で発生する可能性のある位相の破損が防止されます。 

最後のエッジケースは次のような場合です`ℓ = 1`、開始残基のみが寄与を受け取ります。 範囲更新は単一ポイント更新に縮退しますが、圧縮された間隔が 1 つのインデックスに正しく折りたたまれるため、フェンウィック ロジックが引き続き適用されます。
