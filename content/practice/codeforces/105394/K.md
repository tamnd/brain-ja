 ## 解決策
 ## 問題の理解

 4 文字のみで構成される長い文字列が与えられます。`b`、`d`、`p`、 そして`q`。 この文字列は硬いガラスの物体に印刷されています。 落下中、オブジェクトは一連の操作によって繰り返し変形され、すべての変形が適用された後に文字列がどのように見えるかを判断するように求められます。 

各変換はオブジェクトの剛体運動であり、3 つの操作のいずれかで記述されます。`h`、`v`、 または`r`。 これらの操作は、任意の方法で文字列を「編集」するものではありません。 代わりに、それらはオブジェクトの物理的な反転または 180 度の回転に対応し、文字は表面に描かれた硬いシンボルであるかのように一貫して変化します。 

重要な点は、すべての操作を構成全体に適用する必要があり、オブジェクトが剛体であるため、繰り返される操作が 1 つの全体的な変換を構成するということです。 文字列の長さは最大 500,000 であるため、文字列全体を再構築して各操作を単純に適用すると、時間がかかりすぎます。 

この制約により、線形時間で操作ごとに 1 回文字列を処理するソリューションは即座に除外されます。これは、最悪のケースが次のとおりであるためです。$5 \cdot 10^5 \times 5 \cdot 10^5$、これは実現可能な限界をはるかに超えています。 各操作が一定時間で処理され、最終結果が 1 回で構築される表現が必要です。 

微妙な問題は、入力内に同じ文字が複数回出現する可能性があり、変換中は各文字が一貫して動作する必要があることです。 グローバルな状態を使用せずに文字を位置ごとにローカルに再解釈しようとするアプローチは、すぐにエラーが発生しやすくなります。 したがって、変換はすべての文字に均一に適用されるグローバルな状態変更として表現される必要があります。 

## アプローチ

 簡単なアプローチは、すべての変換を文字列上で直接シミュレートすることです。 各操作は文字列全体をスキャンし、その変換下での変化に応じてすべての文字を置き換えます。 変換はグローバルかつ均一であるため、これは概念的には正しいです。 

ただし、それぞれの操作に費用がかかります$O(n)$、最大で$5 \cdot 10^5$操作。 これは最悪の事態を招きます$O(n \cdot m)$、それは約です$2.5 \cdot 10^{11}$制限時間をはるかに超えてキャラクターを更新します。 

重要な観察は、各操作がオブジェクトの剛体運動によって引き起こされる 4 つのシンボルの固定順列であるということです。 剛体運動は小さな閉じたグループを形成するため、それらを繰り返し適用しても順列を構成するだけです。 文字列を繰り返し更新する代わりに、これまでのすべての操作によって引き起こされたアルファベットの現在の並べ替えを 1 つだけ維持できます。 

すべての操作を処理した後、最終的な置換を文字列全体に 1 回適用します。$O(n)$時間。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 操作ごとに文字列を再構築する |$O(nm)$|$O(n)$| 遅すぎる |
 | 変換を作成して 1 回適用します。$O(n + m)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 各操作をセット上の順列としてモデル化します。`{b, d, p, q}`。 その考え方は、すべての変換はシンボルの名前を変更するだけであり、変換の合成は単にこれらの名前変更の関数合成であるということです。 

現在のマッピングを維持します`f`、最初はアイデンティティ マッピング、つまり各文字がそれ自体にマッピングされます。 

各操作のマッピングも事前に定義します`h`、`v`、 そして`r`。 これらはそれぞれ 4 つの文字の順列です。 操作を適用するということは更新することを意味します`f`対応する順列でそれを構成することによって。 

## ステップ

 1. マッピングを初期化する`f`そのような`f(x) = x`すべてのキャラクターに`x in {b, d, p, q}`。 これは、変換がまだ適用されていないことを表します。 
2. 3 つの固定順列を定義する`H`、`V`、 そして`R`変換に対応する`h`、`v`、 そして`r`。 これらは、各剛体モーションが 4 つのシンボルをどのように再ラベル付けするかによって決まります。 
3. 変換文字列を反復処理します。`t`左から右へ。 各キャラクターについて:

 - そうだとしたら`h`、 アップデート`f(x) = H(f(x))`。 
- そうだとしたら`v`、 アップデート`f(x) = V(f(x))`。 
- そうだとしたら`r`、 アップデート`f(x) = R(f(x))`。 

この順序により、新しい操作がそれぞれすでに変換された構成に作用するため、変換が正しい順序で構成されることが保証されます。 
4. すべての操作を処理した後、各文字を置き換えて最終的な文字列を構築します。`c`元の文字列で`s`と`f(c)`。 

### なぜ効果があるのか

 各演算は有限のアルファベットに対する全単射です`{b, d, p, q}`。 したがって、すべての変換シーケンスは、サイズが最大 24 の有限グループ内の 1 つの順列に対応します。演算の構成は結合的であるため、グループ化の順序は重要ではなく、シーケンスのみが重要です。 

累積順列を維持することにより`f`、操作の接頭辞を処理した後、不変式を保持します。`f`は、それらの操作の最終的な効果を正確に表します。 申請中`f`最後に 1 回実行すると、各操作を文字列全体に順番に適用した場合と同じ結果が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def compose(a, b):
    # return a ∘ b (apply b first, then a)
    return {c: a[b[c]] for c in "bdpq"}

def solve():
    s = input().strip()
    t = input().strip()

    # These mappings are consistent permutations of the alphabet
    H = {'b': 'p', 'd': 'q', 'p': 'b', 'q': 'd'}
    V = {'b': 'd', 'd': 'b', 'p': 'q', 'q': 'p'}
    R = {'b': 'q', 'q': 'b', 'd': 'p', 'p': 'd'}

    f = {c: c for c in "bdpq"}

    for op in t:
        if op == 'h':
            f = compose(H, f)
        elif op == 'v':
            f = compose(V, f)
        else:
            f = compose(R, f)

    res = ''.join(f[c] for c in s)
    print(res)

if __name__ == "__main__":
    solve()
```この実装は、すべての変換を辞書の順列として表現することに依存しています。 ヘルパーさん`compose`変換を順番に正しく蓄積することを保証します。 

最後のループオーバー`s`蓄積されたマッピングを 1 回適用します。これは、完全な文字列に触れる唯一の機会です。

    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    def compose(a, b):
        return {c: a[b[c]] for c in "bdpq"}

    def solve():
        s = input().strip()
        t = input().strip()

        H = {'b': 'p', 'd': 'q', 'p': 'b', 'q': 'd'}
        V = {'b': 'd', 'd': 'b', 'p': 'q', 'q': 'p'}

        for op in t:
            if op == 'h':
                f = compose(H, f)
            elif op == 'v':
                f = compose(V, f)
            else:
                f = compose(R, f)

        print(''.join(f[c] for c in s))

    solve()
    return ""

# provided samples (format adapted)

run("bbq\nv\n")

# custom cases
run("b\nhvr\n")

 ## 特殊なケース

 微妙なケースとしては、次のように同じ文字が複数回出現する場合があります。`bbq`。 正確さは、マッピングが均一であるかどうかに依存します。 たとえば、どのような変換でも`f`、両方の出現`b`同じシンボルにマップする必要があります。`f`は位置ではなくアルファベットの関数です。 

もう 1 つの重要なケースは、次のような繰り返しの変換です。`vvvvvv`。 各操作は順列であるため、アプリケーションを繰り返すと最終的に循環します。 順列の合成は順列のままであり、文字ごとの状態は導入されないため、アルゴリズムはこれを自然に処理します。 

最後に、次のような長い混合シーケンス`hvrhv`順序が重要であることを示します。 このアルゴリズムは、マッピングを順番に構成することで順序を維持し、以前の変換が失われたり、誤って上書きされたりしないようにします。
