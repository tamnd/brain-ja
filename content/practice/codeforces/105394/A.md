 ## 解決策
 ## 問題の理解

 私たちは、友情が無向のグラフを形成する人々のソーシャル ネットワークを与えられています。 エイリアンは独自に個人を誘拐することはできません。 つながっている友人グループから誰かを選ぶ場合は、行方不明の人が気づかれないように、つながっているグループ全体を同時に連れて行かなければなりません。 

任務は、必要な拉致をすべて完了できるように、宇宙船に必要な最小限の能力を決定することです。 接続された各コンポーネントは全体として考慮される必要があるため、1 回の旅行で 1 つのコンポーネント全体を運ぶことができ、船はそのような最大のコンポーネントを搭載できなければなりません。 

入力は、最大 200,000 人の人々と 200,000 の友人関係を含むグラフを記述します。 このスケールでは、新たな走査を使用してすべてのノードからの到達可能性を繰り返しチェックするなどの二次アプローチは除外されます。 正しい解決策は、グラフを線形時間 (通常は O(n + m)) で処理する必要があります。これは、O(n log n) であっても許容可能ですが不要であるためです。 

微妙な失敗例は、友情が希薄であるか、まったく存在しない場合に現れます。 エッジがない場合、すべてのノードが分離され、それぞれがサイズ 1 のコンポーネントを形成するため、答えは 1 になります。単純な間違いは、少なくとも 1 つのエッジが存在すると仮定し、隣接リストからのみコンポーネントの追跡を開始することです。これでは、分離されたノードを完全に見逃してしまいます。 

もう 1 つのエッジ ケースは、グラフが完全に接続されている場合です。 この場合、単一のコンポーネントには全員が含まれるため、答えは n になります。 エッジを誤って数えたり、複数のコンポーネントが存在すると仮定したりするソリューションは、必要な容量を過小評価することになります。 

## アプローチ

 問題を解決する直接的な方法は、各個人を開始点として扱い、未訪問のノードに遭遇するたびに深さ優先検索や幅優先検索などのグラフ走査を実行することです。 各走査で 1 つの接続されたコンポーネントが検出され、そのコンポーネントに含まれるノードの数がカウントされます。 すべてのコンポーネントの最大サイズを追跡します。 

この強引なアイデアは、ルールを明示的にシミュレートしているため、正しいです。つまり、友情によってグループ化が強制され、接続性によってグループのメンバーシップが定義されます。 コストは、大きなグラフを繰り返し走査することで発生します。 最悪の場合、不注意で訪問したノードを適切にマークしなかった場合、グラフの大部分を複数回再探索し、O(nm) の動作が発生する可能性があります。 訪問追跡が正しくても、すべてのノードとエッジを 1 回走査する必要がありますが、これは O(n + m) になりますが、これは問題ありません。 

重要な洞察は、この問題では複数の移動や動的なプロセスをシミュレートする必要がないということです。 無向グラフ内の最大の連結成分のサイズのみを要求します。 各アブダクションが 1 つの接続コンポーネントに正確に対応することが認識されると、問題全体はコンポーネントのサイズを計算して最大値を取得することに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 素朴な探求を繰り返す | O(nm) | O(n + m) | 遅すぎる |
 | DFS/BFS 接続コンポーネント | O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 友情ペアからグラフの隣接リスト表現を構築します。 これにより、すべてのエッジを繰り返しスキャンすることなく、任意の人の隣人を効率的に走査することができます。 
2. すべてのユーザーに対して false に初期化された訪問済み配列を維持します。 これにより、すべての走査にわたって各ノードが 1 回だけ処理されることが保証されます。 
3. 1 から n までのすべての人々について繰り返します。 各人について、訪問されていない場合は、そのノードからトラバースを開始します。 
4. トラバーサル中に、スタックまたはキューを使用して、同じ接続コンポーネント内の到達可能なすべてのノードを探索します。 再訪問を避けるために、訪問した各ノードを発見したらすぐにマークを付けます。 
5. この走査中に訪問されたノードの数を数えます。 このカウントは、現在の接続コンポーネントのサイズを表します。 
6. これまでに発生した最大コンポーネント サイズを使用して回答を更新します。 
7. すべてのノードを処理した後、最大値を出力します。 

この手順が機能する理由は、各走査が無向グラフの連結成分の定義と正確に一致するためです。 ノードが訪問済みとしてマークされると、そのノードは別のコンポーネントに属することができないため、すべてのノードが 1 つのコンポーネント サイズに正確に寄与します。 したがって、これらのサイズを超えた最大値が、必要な拉致グループを処理できる最小の船の容量となります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    adj = [[] for _ in range(n + 1)]

    for _ in range(m):
        a, b = map(int, input().split())
        adj[a].append(b)
        adj[b].append(a)

    visited = [False] * (n + 1)
    best = 1

    for i in range(1, n + 1):
        if visited[i]:
            continue

        stack = [i]
        visited[i] = True
        size = 0

        while stack:
            v = stack.pop()
            size += 1

            for to in adj[v]:
                if not visited[to]:
                    visited[to] = True
                    stack.append(to)

        if size > best:
            best = size

    print(best)

if __name__ == "__main__":
    solve()
```隣接リストの構築により、友人関係を効率的に横断できるようになります。 訪問された配列により、各ノードが 1 回処理されることが保証され、繰り返しのカウントが防止されます。 DFS スタックは、大きなグラフに対する Python での再帰の深さの問題を回避します。 変数`best`遭遇した最大の連結成分を格納します。 

実装の微妙な詳細は、ノードをポップ時ではなくプッシュ時に訪問したものとしてマークすることです。 これにより、同じノードがスタックに複数回挿入されることを防ぎます。これにより、密なグラフでの実行時間が増大します。 

## 実用的な例

 ### サンプル 1

 入力グラフには、コンポーネント {1,2,3} および {4,5} を形成するエッジを持つ 5 つのノードがあります。 

| 開始ノード | スタック | 訪問セット | コンポーネントのサイズ |
 | --- | --- | --- | --- |
 | 1 | [1] → [] | {1,2,3} | 3 |
 | 2 | スキップしました | すでに訪問済み | - |
 | 3 | スキップしました | すでに訪問済み | - |
 | 4 | [4] → [] | {4,5} | 2 |
 | 5 | スキップしました | すでに訪問済み | - |

 最大のコンポーネント サイズは 3 であり、これが必要な容量になります。 

### サンプル 2

 友情がなければ、すべてのノードは孤立します。 

| ノード | アクション | コンポーネントのサイズ |
 | --- | --- | --- |
 | 1 | 新しいDFS | 1 |
 | 2 | 新しいDFS | 1 |
 | 3 | 新しいDFS | 1 |

 最大値は 1 です。つまり、船には 1 回の旅行につき 1 人分のスペースしか必要ありません。 

これにより、孤立したノードが正しく処理され、アルゴリズムがエッジの存在を想定していないことが確認されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + m) | 無向グラフでは、各ノードが 1 回訪問され、各エッジが最大 2 回横断されます。 
| スペース | O(n + m) | 隣接リストと訪問済み配列およびトラバーサル スタック |

 この制約により、最大 200,000 個のノードとエッジが許可され、反復実装された場合、線形処理は Python の時間制限内に快適に収まります。

 ## 特殊なケース

 エッジのないグラフは、実装が間違っている場合に最も脆弱なケースです。 入力用`3 0`の場合、隣接関係リストはすべてのノードで空です。 このアルゴリズムは引き続きすべてのノードを反復処理し、それぞれのノードでサイズ 1 の DFS を開始します。 最大値は 1 のままですが、これは正しいです。 

完全に接続されたグラフでは、トラバーサルが誤って隣接するものに限定されたり、訪問済みのマーキングが遅れたりするエラーが発生します。 入力用`4 6`考えられるすべてのエッジを使用すると、ノード 1 から開始して最終的にすべてのノードに到達するトラバーサルが行われ、サイズ 4 が生成されます。時期尚早のマーキングや誤った近傍反復があると、このサイズが過小評価されます。 

チェーン グラフは、到達可能性の伝播をテストします。 で`1-2-3-4`、1 から始まり、中間ノードを介して最終的に 4 に到達する必要があります。 スタックベースの DFS により、推移閉包が完全に探索されることが保証されるため、コンポーネントのサイズは 1 または 2 ではなく 4 になります。これは、直接の近傍のみがカウントされる場合に発生します。
