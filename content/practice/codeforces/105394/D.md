 ## 解決策
 ## 問題の理解

 1 から n までの位置の 1 次元の路地に取り組んでいます。 特定の位置では、ランプを配置または削除することができ、各ランプは正の輝度値を持ちます。 環境は霧が多く、光は自由に伝わりません。光は 1 メートル進むごとに、同じ減衰係数が乗算されます。$1 - p$、 どこ$p$は厳密に 0 と 1 の間の実数として与えられます。 

ランプを所定の位置に置いた場合$x_i$明るさと$b_i$、どの点でも貢献します$x$路地沿いに。 寄与はランプと点の間の距離にのみ依存し、その距離とともに指数関数的に減衰します。 距離が$d = |x - x_i|$、ランプが貢献します$b_i \cdot (1 - p)^d$の明るさに$x$。 ある点での合計の明るさは、現在アクティブなすべてのランプからの寄与の合計です。 

システムは動的です。 ランプは挿入されたり取り外されたりするため、特定の位置での現在の明るさを尋ねる質問に答える必要があります。 

制約は大きく、最大で$2 \cdot 10^5$操作。 クエリごとにすべてのランプからの寄与を再計算するアプローチは、最悪の場合、次のような結果になるため、すぐに遅くなりすぎます。$O(nq)$、これは許容範囲をはるかに超えています。 この構造は、操作ごとに対数または償却定数に近いものが必要であることを示唆しています。 

微妙な難しさは距離の絶対値から来ます。 ランプはクエリ ポイントの左側にあるか右側にあるかに応じて異なる寄与をするため、単一の単純なプレフィックス構造が直接機能することはできません。 

2 番目の問題は数値構造です。減衰は乗算的であり、距離に依存します。これは、位置のシフトを、保存された値に事前に吸収できる乗算係数に変換する変換を示唆しています。 

エッジケースは、ランプが同じ明るさで同じ座標で挿入および取り外されるときに発生します。これは、構造がそれらを位置のみでマージするのではなく、独立したイベントとして扱う必要があるためです。 もう 1 つのデリケートな状況は、ランプがない場合のクエリです。この場合、答えは初期化されていない値ではなくゼロでなければなりません。 

## アプローチ

 直接的なアプローチでは、すべてのアクティブなランプを反復処理し、それらの寄与を合計することによって各クエリを評価します。 これは文字通り、すべてのランプが距離に基づいて独立して寄与するという定義に従っているため、正しいです。 ただし、各クエリにはコストがかかります$O(n)$、そして最大で$2 \cdot 10^5$クエリの合計作業量は次のとおりです$O(nq)$、大まかに言うと$4 \cdot 10^{10}$実行可能をはるかに超えた、最悪の場合の操作。 

重要な観察は、ランプがクエリ位置の左側にあるか右側にあるかに応じて、距離に基づく指数関数的減衰が 2 つのケースに分けられるということです。 固定クエリ位置の場合$x$、ランプを位置のあるものに分割します$i \le x$そして持っている人$i > x$。 これにより絶対値が削除され、各辺が代数的に均一になります。 

のために$i \le x$、貢献度は$b \cdot (1 - p)^{x - i}$、次のように書き換えることができます$(1 - p)^x \cdot b \cdot (1 - p)^{-i}$。 のために$i > x$、貢献度は$b \cdot (1 - p)^{i - x} = (1 - p)^{-x} \cdot b \cdot (1 - p)^i$。 

この変換により、クエリ位置への依存がすべて分離されます。$x$ランプ位置へのすべての依存性を事前に集約することができます。 この問題は、位置全体にわたって 2 つの動的なプレフィックス スタイルの集約を維持することに帰着します。これには、フェンウィック ツリーまたはセグメント ツリーの使用が推奨されます。 

私たちは 2 つの別々の構造を維持しています。1 つは店舗です。$b \cdot (1 - p)^{-i}$、その他の店舗$b \cdot (1 - p)^i$。 各更新は 1 つのインデックスにのみ影響し、各クエリはプレフィックスの合計、サフィックスの合計、および事前に計算された 2 つの累乗の組み合わせになります。$(1 - p)$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(nq)$|$O(n)$| 遅すぎる |
 | フェンウィック + トランスフォーム |$O(q \log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは定義します$r = 1 - p$、1 メートルあたりの減衰係数。 

### ステップ

 1. の値を事前計算します。$r^i$そして$r^{-i}$関連するすべてのインデックスについて、$n$。 

これらの能力により、クエリとは独立して距離のシフトを乗算調整に変換することができます。 
2. 1 から n までの位置にわたって 2 つのフェンウィック ツリーを維持します。 

最初のツリーには値が格納されます$b \cdot r^{-i}$、2号店$b \cdot r^i$。 
3. 位置にランプを挿入する場合$x$明るさと$b$、インデックスで両方のツリーを更新します$x$： 追加$b \cdot r^{-x}$最初の木へ、そして$b \cdot r^x$2本目の木へ。 

削除では、負の値を使用して同じ更新が実行されます。 
4. 位置での質問に答えるには$x$、プレフィックスの合計を計算します$S_1 = \sum_{i \le x} b_i r^{-i}$最初の木から。 
5. サフィックスの合計を計算する$S_2 = \sum_{i > x} b_i r^i$合計からプレフィックスを差し引いて 2 番目のツリーから取得します。 
6. 以下を使用して両方の貢献を結合します。$$\text{answer}(x) = r^x \cdot S_1 + r^{-x} \cdot S_2$$### なぜ効果があるのか

 各ランプの寄与は、クエリ位置への依存が完全に除外された形式に書き直されます。 フェンウィック ツリーには、更新しても安定した位置依存コンポーネントのみが保存されます。 すべてのランプは、クエリの左側または右側のパーティションで 1 回だけ考慮され、代数変換により重複や省略が発生しないことが保証されます。 更新とクエリは集計された変換値のみを操作するため、正確さは合計の線形性と距離項の正確な分解によって決まります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0.0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0.0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

def solve():
    n, q, p = input().split()
    n = int(n)
    q = int(q)
    p = float(p)

    r = 1.0 - p

    bit1 = Fenwick(n)
    bit2 = Fenwick(n)

    # precompute powers
    rp = [1.0] * (n + 1)
    rm = [1.0] * (n + 1)
    for i in range(1, n + 1):
        rp[i] = rp[i - 1] * r
        rm[i] = rm[i - 1] / r

    total2 = 0.0

    for _ in range(q):
        tmp = input().split()
        if tmp[0] == '+':
            b = int(tmp[1])
            x = int(tmp[2])
            bit1.add(x, b * rm[x])
            bit2.add(x, b * rp[x])
            total2 += b * rp[x]

        elif tmp[0] == '-':
            b = int(tmp[1])
            x = int(tmp[2])
            bit1.add(x, -b * rm[x])
            bit2.add(x, -b * rp[x])
            total2 -= b * rp[x]

        else:
            x = int(tmp[1])
            s1 = bit1.sum(x)
            s2 = total2 - bit2.sum(x)
            ans = (rp[x] * s1) + (rm[x] * s2)
            print(ans % MOD)

if __name__ == "__main__":
    solve()
```この実装は代数分解を直接反映しています。 最初のフェンウィック ツリーは、位置によって正規化した後、左側のランプからの寄与を蓄積します。 2 番目のツリーはすべてのランプに対して同じことを行いますが、合計マイナス接頭辞トリックによって右側の寄与を再構築するために使用されます。 

微妙な点は、2 番目に変換された配列の累計を維持することです。これは、サフィックス クエリは、グローバル合計からの反転または減算を行わないとフェンウィック ツリーによって直接サポートされていないためです。 

問題ステートメントでは指数関数的減衰が本質的に実数値であるため、すべての算術演算は浮動小数点で実行されます。 最後のモジュラー削減は、最終的な合理的な結果をモジュロで表現するという問題の要件に対応します。$10^9 + 7$。

 ## 特殊なケース

 重要なエッジケースは、同じ位置でランプの追加と削除が行われる場合です。 各ランプはフェンウィック構造内で独立して追跡されるため、削除では、追加されたのとまったく同じ変換値を減算する必要があります。 代数はキャンセルを保証します。 

もう 1 つのケースは、ランプがまったくない状態で位置をクエリすることです。 この場合、両方のフェンウィック ツリーにゼロが含まれるため、プレフィックスとサフィックスの寄与は両方とも 0 と評価され、特別な処理を行わなくても正しい結果が生成されます。 

最後に、路地の端に設置されたランプで、接頭辞と接尾辞の分解の正確さをテストします。 位置 1 のランプは、遠く離れたクエリの右側の定式化を通じて完全に寄与し、変換により境界調整が必要ないことが保証されます。
