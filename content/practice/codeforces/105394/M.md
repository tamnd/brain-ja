 ## 解決策
 ## 問題の理解

 最初のキーを基準としたピアノのキーのピッチ オフセットのシーケンスが与えられます。 これらの値は、絶対周波数ではなく現在の相対チューニングを表しますが、すべてのキーを同じ定数だけシフトすると有効な絶対チューニングを表すという意味で一貫しています。 

目標は、ピアノを完璧な「音楽の階段」に変えることであり、各キーは前のキーよりちょうど半音高くなるようになります。 つまり、最終的な構成は、連続するキー間の差が 1 である等差数列を形成する必要があります。 絶対的な開始ピッチを自由に選択できますが、その開始値が固定されると、他のすべてのキーが強制されます。 

各キーを個別に変更でき、コストは各キーに適用される絶対調整の合計になります。 タスクは、この総コストが最小限に抑えられるように、可能な限り最良の最終階段を選択することです。 

制約は最大 100,000 キーに達し、ブルート フォース アライメントによって考えられるすべてのターゲット構成を試行する二次戦略は即座に除外されます。 候補開始値ごとのコストを線形時間で再計算すると、最悪の場合、制限をはるかに超える約 10^10 の演算が必要になります。 これにより、問題が 1 つのパラメータに対するよく知られた最適化に帰着する定式化に向けて進むことができます。 

入力値が絶対的ではなく相対的であるという事実から、微妙な問題が発生します。 単純なアプローチでは、シーケンス t をきれいに増加するシーケンスと直接整列させようとし、絶対的なベースラインではなく、差異のみが重要であることを見落とす可能性があります。 もう 1 つのよくある間違いは、ターゲット シーケンスがゼロから始まる固定であると想定することですが、開始ピッチは実際には自由であり、最適化する必要があります。 

## アプローチ

 最終調整の候補を修正する場合、コストの計算は簡単です。各望ましい値を現在の値と比較し、絶対的な差を合計します。 強引なアイデアは、最後の階段に向けて可能なすべての開始ピッチを試すことです。 最初のキーが x の場合、シーケンスは x、x+1、x+2 などとなり、各 x の合計コストを計算します。 

すべての有効なソリューションは単一のパラメーターによって完全に決定されるため、これは正しく機能します。 ただし、可能な x 値の範囲は広いため、x ごとに n 個のキーすべてをスキャンすることになります。 n が最大 100000、x が 200000 程度の範囲にわたる場合、これはおよそ 2×10^10 の演算を必要とし、これでは遅すぎます。 

重要な点は、元のシーケンスと直接比較すべきではないということです。 代わりに、ターゲット シーケンスの強制構造をデータから分離します。 最終ターゲットが x + (i−1) の場合、入力のインデックス依存部分から x を分離する方法でコストを書き換えます。 これにより、問題は、導出配列までの L1 距離を最小にする単一の数値 x を選択することに変換されます。 

問題がその形式で表示されると、絶対偏差の合計を最小にする点を選択するという古典的な問題になり、その解は中央値になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 開始値に対するブルート フォース | O(nR) | お(1) | 遅すぎる |
 | 中央値変換 | O(n log n) | O(n) | 承認済み |

 ここで、R は可能な開始オフセットの範囲を表します。これは、ブルート フォースを実行不可能にするのに十分な大きさです。 

## アルゴリズムのチュートリアル

1. キー i の目的の最終ピッチを x + (i−1) として書き換えます。ここで、x は未知の開始ピッチです。 これは、最初のキーが選択されると最終的な構成が完全に決定されるという事実を捉えています。 
2. 各入力値 t[i] を正規化値 b[i] = t[i] − (i−1) に変換します。 これにより、ターゲット構造から強制的な線形トレンドが削除され、すべての変動が単一の共有パラメータに分離されます。 
3. 総コストが |(x + (i−1)) − t[i]| の i にわたる合計になることに注目してください。これは、正確に合計 |x − b[i]| と単純化されます。 この時点で、問題は x の選択のみに依存します。 
4. 配列をソートします。 絶対偏差の合計を最小化するための最適値は順序に依存するため、ソートが必要です。 
5. b の中央値要素として x を選択します。 n が奇数の場合、これが中央の要素になります。 n が偶数の場合、中間の 2 つの要素間のどの値も同じ最適コストを与えるため、どちらかの中間要素を選択するだけで十分です。 
6. 最終的な答えを |x − b[i]| の合計として計算します。 全体的に私は。 

### なぜ効果があるのか

 この変換により、すべての制約が、コスト関数が凸で区分線形となる単一変数の最適化問題に変換されます。 このような関数では、データの中央値で傾きの符号が変わります。 x が中央値から離れると、一方の側の不均衡が他方の側で減少するよりも大きくなり、中央値が絶対偏差の合計を最小限に抑えることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    t = list(map(int, input().split()))

    b = [t[i] - i for i in range(n)]

    b.sort()
    x = b[n // 2]

    ans = 0
    for v in b:
        ans += abs(v - x)

    print(ans)

if __name__ == "__main__":
    solve()
```実装は、変換された配列 b を構築することから始まります。これにより、隣接するキーが正確に 1 だけ異なるという要件によって引き起こされる強制的な傾きが除去されます。 これは重要な正規化ステップです。 これがないと、問題は単一パラメータの最適化ではなく、制約付きベクトル フィッティング問題のように見えます。 

中央値は順序付けされた構造でのみ意味があるため、b のソートが必要です。 どの中央値でも L1 目標が最小化されるため、中央の要素が直接選択されます。 

最後のループでは、中央値からの絶対偏差の合計を計算します。これは、調整作業の合計に直接対応します。 

よくある実装上の間違いは、b[i] = t[i] − i のインデックス シフトを忘れることです。 もう 1 つは、並べ替えずに答えを計算しようとして、中央値ではなく平均値を誤って選択することです。これは二乗誤差としては正しいですが、絶対誤差としては正しくありません。 

## 実用的な例

 シーケンス t = [0, 1, 4, 3, 6] の例を考えてみましょう。 変換後、b[i] = t[i] − i を計算します。 

| 私 | t[i] | b[i] |
 | --- | --- | --- |
 | 0 | 0 | 0 |
 | 1 | 1 | 0 |
 | 2 | 4 | 2 |
 | 3 | 3 | 0 |
 | 4 | 6 | 2 |

 b をソートすると [0, 0, 0, 2, 2] が得られるため、中央値は x = 0 になります。コストは 0+0+0+2+2 = 4 となります。 

このトレースは、正規化後に複数のキーがすでに最適な階段と一致しており、偏差のみが寄与していることを示しています。 

ここで、t = [0, -2, 10, 6, 7, -1] について考えてみましょう。 b を計算します。 

| 私 | t[i] | b[i] |
 | --- | --- | --- |
 | 0 | 0 | 0 |
 | 1 | -2 | -3 |
 | 2 | 10 | 8 |
 | 3 | 6 | 3 |
 | 4 | 7 | 3 |
 | 5 | -1 | -6 |

 ソートの結果は [-6、-3、0、3、3、8] になります。 範囲の中央値は 0 ～ 3 なので、x = 0 を選択します。最終コストは 6 + 3 + 0 + 3 + 3 + 8 = 23 です。 

この例は、値が広範囲に分散している場合でも、最適なアンカーが変換された分布の中心にあることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | ソートが優先、コストは線形パス |
 | スペース | O(n) | 変換された配列 | を格納します。 

Python では 100,000 個の要素の並べ替えが効率的であり、残りの計算が線形であるため、このソリューションは制約内に問題なく収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import inf

    n = int(input())
    t = list(map(int, input().split()))
    b = [t[i] - i for i in range(n)]
    b.sort()
    x = b[n // 2]
    return str(sum(abs(v - x) for v in b))

# negative values
assert run("4\n0 -1 -2 -3\n") == "4", "decreasing input"

# mixed case

 ## 特殊なケース

 n = 2 の場合、アルゴリズムは 2 つの絶対偏差を最小限に抑える単一の x を選択することになります。 変換後、 b には 2 つの値があり、どちらの中央値を選択しても同じ最適コストが得られます。 たとえば、t = [0, 5] は b = [0, 4] になり、x = 0 を選択するとコスト 4 が得られ、x = 4 もコスト 4 が得られ、L1 ではそれらの間の任意の点が最適であるという事実と一致します。 

t = [0, 1, 2, 3] など、すでに完全な階段になっている入力の場合、変換された配列は定数 b = [0, 0, 0, 0] になります。 中央値は 0、すべての偏差は 0 であるため、アルゴリズムは調整を必要とせずに 0 を正確に返します。
