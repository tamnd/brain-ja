 ## 問題の理解

 私たちは、Janise のバクラヴァ レイヤーの可能な構成を表す 9 桁の整数を使用しています。 有効な各構成は単なる整数です$N$からの範囲で$100{,}000{,}000$に$999{,}999{,}999$。 各テスト ケースの除数$K$が与えられたとき、これらの 9 桁の数字のうち何個が で割り切れるかを数えなければなりません。$K$さらに、追加の数字ベースの制約も満たします。 

その追加条件には、次の桁を反転することが含まれます。$N$。 その逆数が 5 で割り切れるとき、次のように考えます。$N$カウントの対象となる。 したがって、タスクは 9 桁の数値すべてを 2 つのプロパティで一度にフィルター処理することです。元の数値は次の数で割り切れる必要があります。$K$、その桁の反転は 5 で割り切れる必要があります。 

制約により、これはクエリごとの定数時間ソリューションに向けて推進されます。 まで$10^5$テストケースと$K$と同じくらい大きい$10^5$、各クエリのすべての候補番号を反復するには、おおよその必要があります$10^9$最悪の場合のテストごとの操作数は許容範囲をはるかに超えています。 数値を列挙したり、候補ごとに桁の反転をシミュレートしたりするソリューションは、直ちに実行不可能になります。 

反転条件の解釈には微妙な問題が生じます。 機械的に処理すると、次の倍数ごとに逆数を計算しようとする可能性があります。$K$, しかし、それによって不必要な数字操作が発生します。 重要なのは、逆転の割り切り条件が実際には、次の最初の桁の制約に崩壊するということです。$N$, これにより、数値の残りの部分への依存が削除されます。 

よくある間違いは、反転によって可分性が複雑に変化すると考えることです。 たとえば、$N = 120000005$、それを逆にすると、$500000021$、5 で割り切れるかどうかのチェックは、完全な構造ではなく、反転した数値の最後の桁にのみ依存します。 この観察により、問題全体が単純化されます。 

## アプローチ

 ブルートフォース手法では、9 桁の数値をすべて列挙し、それぞれを逆にして、5 で割り切れるかどうかを確認し、さらに次の値で割り切れるかどうかをテストします。$K$。 がある$900{,}000{,}000$このような数値が含まれるため、各テスト ケースではこの範囲全体をスキャンする必要があります。 まで$10^5$テストケースでは、これは完全に機能しなくなり、$10^{14}$操作。 

重要な単純化は、「逆 5 で割り切れる」が実際に何を意味するかを調べることから生まれます。 数値は、最後の桁が 0 または 5 の場合、正確に 5 で割り切れます。反転後、反転した数値の最後の桁は、元の数値の最初の桁になります。 これにより、条件が次の先頭の桁に対する制限に縮小されます。$N$。 以来$N$は 9 桁の数値であり、先頭の桁は 0 にすることはできないため、5 にする必要があります。 

これにより、検索空間全体が連続した間隔に変換されます。有効な数値はすべて、その間にあります。$500{,}000{,}000$そして$599{,}999{,}999$。 次に問題は、次の倍数を数えるということになります。$K$一定の区間内に収まる場合は、フロア分割を使用して一定時間で回答できます。

 ## アルゴリズムのチュートリアル

 1. 数値を反転すると桁の順序にのみ影響し、反転した数値の最後の桁が元の数値の最初の桁になることを認識します。 したがって、5 で割り切れる条件により、9 桁の数値の最初の桁が制限されます。 
2. 9 桁の数値は 0 で始めることができないため、最初の桁は 5 でなければならないと結論付けます。これにより、数値の有効範囲が 1 つのブロックに固定されます。$500{,}000{,}000$に$599{,}999{,}999$。 
3. で割り切れる整数を数えるという問題を再定式化します。$K$この間隔内で。 反復処理の代わりに、倍数の算術カウントを使用します。 
4. の倍数を計算します。$K$上限以下である$R = 599{,}999{,}999$、下限を厳密に下回っている数を減算します。$L = 500{,}000{,}000$。 
5. 各テストケースの差分を出力します。 

### なぜ効果があるのか

 正しさは、すべての有効な 9 桁の数値が固定間隔内の位置によって一意に決定され、逆転条件は最初の桁以外のどの桁にも依存しないという事実に基づいています。 これにより、元のフィルタリングの問題が区間交差の問題に縮小されます。 ～の倍数を数える$K$フロア分割による区間では、すべての有効な候補を省略や重複なく正確に列挙します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def count_multiples(r, k):
    return r // k

T = int(input())
L = 500_000_000
R = 599_999_999

for _ in range(T):
    K = int(input())
    ans = R // K - (L - 1) // K
    print(ans)
```この解決策は完全に整数の除算プロパティに依存しています。 表現`R // K`すべての倍数を数えます$K$上限までの間、`(L - 1) // K`有効な間隔を下回るものが削除されます。 これにより、明示的なループが回避され、クエリごとに一定時間の処理が保証されます。 

実装でよくある落とし穴は、減算を忘れることです。`L - 1`それよりも`L`。 使用する`L`有効な倍数である場合、下限に等しい数値を直接除外すると誤って除外されます。$K$。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    T = int(input())
    L = 500_000_000

    out = []
    for _ in range(T):
        K = int(input())
        out.append(str(R // K - (L - 1) // K))

 ## 特殊なケース

 のために$K = 1$、アルゴリズムは間隔の合計サイズを返します。$599{,}999{,}999 - 500{,}000{,}000 + 1 = 100{,}000{,}000$、範囲内のすべての数値が有効であるという事実と一致します。 計算は正しく次のようになります。`R - (L - 1)`。 

非常に大きい場合$K$、 のような$10^9$、 両方`R // K`そして`(L - 1) // K`区間内に倍数が存在しないため、0 と評価され、正しい結果 0 が生成されます。 

境界で$K = 500{,}000{,}000$、区間にはちょうど 1 つの倍数、つまり下限自体が含まれます。 減算式により、確実に含まれることが保証されます。`(L - 1) // K`その間はカウントされません`R // K`そうです。
