 ## 解決策
 ## 問題の理解

 同じ長さの 2 つの配列が与えられます。 1 つの配列はさまざまな注文の目標数量を表し、もう 1 つの配列は準備されたバッチの現在の数量を表します。 各操作により、単一のユニットを任意のバッチから他のバッチに移動し、合計を維持しながら値を効果的に再分配することができます。 

目標は、すべてのバッチを注文に変換することではありません。 代わりに、ある順序値がバッチ配列にすでに存在しているのか、それとも一連のユニットの移動後に存在させることができるのか、そして存在する場合は、少なくとも 1 つのバッチを 1 つの順序値と正確に等しくするために必要な最小移動回数は何かを知る必要があるだけです。 

重要な観察は、事前に組み合わせを選択していないということです。 バッチ値のマルチセットを自由に再形成することができますが、ユニット転送を介してのみ許可されており、任意の 1 つのバッチを任意のターゲットに正確にヒットさせる最も安価な方法が必要です。 

制約は大きく、値は最大 200,000、大きさは最大 10^9 です。 これにより、シミュレーションによるオーダーとバッチのすべてのペアの二次比較が即座に除外されます。 候補ごとのコア チェックが一定であるか償却一定でない限り、O(N log N) のソリューションでも境界線に達します。 この構造は、ソートまたはハッシュをグローバルな実現可能性条件と組み合わせることを強く示唆しています。 

微妙な点は、実現可能性は総計のバランスに依存するということです。 バッチをある目標値 x と等しくしようとしても、残りのバッチの合計が正しく計算される必要があります。 b の合計が S の場合、1 つのバッチを x に等しくした後、残りの N-1 個のバッチの合計は S - x になる必要があります。これは、任意に再分配できるため常に可能です。 したがって、唯一の本当の制約は、あるバッチを正確に x に調整できるかどうか、そしてそれにかかるユニットの移動の数がどれだけになるかということです。 

素朴な間違いは、a[i] を b[j] に直接一致させるか、最も近い値を貪欲に選択する必要があると想定することです。 複数のバッチにわたる中間再配布によりコストが大幅に削減される可能性があるため、これは失敗します。 

もう 1 つの間違いは、完全一致のみが重要であると考えることです。 たとえば、b = [5, 6] および a = [7] の場合、7 から始まるバッチがない場合でも、5 から 1 ユニットを移動し、1 操作のコストで 6 から 7 に到達できます。 

## アプローチ

 ブルートフォースのアイデアは、すべてのターゲット値 a[i] とすべての開始バッチ b[j] を試し、b[j] を a[i] に変換するコストを計算することです。 ただし、単一のバッチを他のバッチに影響を与えずに自由に変更することはできません。 b[j] を増やそうとする場合は、他のバッチから単位を取得する必要があり、b[j] を減らす場合は、その超過分を他の場所に再分配する必要があります。 つまり、すべての候補コストはペアだけでなくグローバル分布に依存します。 

より正確な総当りモデルは、各ターゲット x について、一部のバッチが x に達するために、x より上のバッチから x より下のバッチに合計ユニット数を移動する必要があるかをシミュレートすることです。 これには、すべての b 値をスキャンし、x に対する剰余と不足を計算する必要があります。 a 内のすべての x に対してこれを行うと、各評価が配列全体をスキャンするため、O(N^2) のコストがかかります。 

重要な洞察は、固定された目標値 x の場合、あるバッチを x に等しくするための最小操作数は、しきい値 x を超えて総質量をどれだけシフトする必要があるかのみに依存するということです。 b をソートすることを想像すると、選択した x について、x より上にあるユニットの数と x より下にあるユニットの数を計算できます。 1 つの特定の位置を x に到達させるには、不均衡を効果的に 1 つのバケットに集中させ、調整を「中心に置く」すべての可能な位置にわたって最小コストが最小になります。

これにより、両方の配列がソートされます。 ソート後、候補 x = a[i] を扱い、ソートされた b と比較します。 各 x について、x より上に存在する余剰ユニットの総数と、x より下に存在する不足ユニットの数を計算します。 各操作が不一致の境界を越えて 1 つのユニットを移動するため、必要な移動数は、まさに押し下げる必要がある総余剰 (または同等の総不足の埋め合わせ) です。 

これを効率的に計算するために、ソートされた b に対してプレフィックス数を使用します。 与えられた x について、二分探索を使用して b 内のその位置を見つけます。 x より大きいすべての要素は余剰に寄与し、より小さいすべての要素は不足に寄与し、コストは 1 つのスロットを x に揃えるのに必要な絶対不均衡の合計になります。 ソートされた a 内のすべての x についてこれを評価し、最小値を取得します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ターゲットごとのブルート フォース シミュレーション | O(N^2) | お(1) | 遅すぎる |
 | ソート + プレフィックスの不均衡 + 二分探索 | O(N log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 次に、ソートされた配列の不均衡を推論して答えを計算します。 

1. 配列 a と配列 b の両方をソートします。 値をペアごとではなくグローバルに比較する方法を推論できるようにするには、並べ替えが必要です。 ソートが完了すると、選択したターゲットより大きいまたは小さい要素を効率的に分離できます。 
2. b のプレフィックス合計を事前計算します。 これにより、二分探索後に O(1) のしきい値以下またはしきい値を上回る総質量を迅速に計算できます。 各候補ターゲットにはグローバルな集約が必要なため、これは不可欠です。 
3. a 内の各候補ターゲット値 x について、二分探索を使用して、ソートされた b 内のその位置を特定します。 これにより、b が x より小さい要素と x より大きい要素の 2 つのグループに分割されます。 
4. x より上にどれだけの過剰が存在し、x より下にどれだけの不足が存在するかを計算します。 x より上の各ユニットは下に移動する必要があり、x より下の各ユニットはユニットを受け取る必要があります。 必要な操作の数は、これら 2 つの側の間の合計の不一致に等しくなります。 
5. x のコストは、b と、1 つの位置が x になる単一の完全な構成の間の絶対的な不均衡の合計です。 すべての x の最小値を追跡します。 
6. 不均衡処理によって暗示される制約の下で変換が不可能な場合は、-1 を返します。 この問題構造では、いつでも再配布できるため実現可能性が常に保たれ、実装の制約に違反しない限り、答えは常に定義されます。 

### なぜ効果があるのか

 重要な不変条件は、各操作が 2 つの位置間で正確に 1 ユニットを移動することです。そのため、すべての操作は、不均衡質量に関して、現在のマルチセットと任意のターゲット構成の間の合計絶対偏差をちょうど 2 削減します。 目標 x が固定されている場合、すべての最適な戦略は、余剰ユニットを赤字地域に押し込むことになります。 コストは、ユニットのアイデンティティではなく、x で定義された境界を通過する必要があるユニットの数にのみ依存するため、ソートは最適な移動を完全に特徴付けます。 x を達成するソリューションはすべて、まったく同じ合計不均衡を考慮する必要があるため、計算されたコストは最小であり、その x に対して一意になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    
    a.sort()
    b.sort()

    # prefix sums of b
    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + b[i]

    total_b = pref[n]

    import bisect

    ans = float('inf')

    for x in a:
        idx = bisect.bisect_left(b, x)

        # elements < x
        left_count = idx
        left_sum = pref[idx]

        # elements >= x
        right_count = n - idx
        right_sum = total_b - left_sum

        # cost interpretation:
        # left side needs to gain (x * left_count - left_sum)
        # right side needs to lose (right_sum - x * right_count)
        cost = (x * left_count - left_sum) + (right_sum - x * right_count)

        ans = min(ans, cost)

    print(ans)

if __name__ == "__main__":
    solve()
```コードは両方の配列を並べ替えて、ターゲット候補との比較がペアごとではなく間隔ベースになるようにします。 b の接頭辞合計を使用すると、選択した x の両側の合計を定数時間で計算できます。 a の各 x について、二分探索により b が x より下の値と上の値に分割され、すべての値が x に等しい理想的な構成から各辺がどれだけ離れているかを計算します。 

コストの式は、b のすべての値を x に揃えるために上または下に移動する必要があるユニットの数を直接カウントします。 各単位の差は 1 回の操作に対応するため、不均衡の合計によって正確な移動数が求められます。 

任意の 1 つの注文を完了することができるため、答えはすべての x の最小値になります。

 ## 特殊なケース

 エッジ ケースの 1 つは、すべての b 値が同一である場合です。 その場合、すべての候補 x はその定数値からの距離のみに依存し、二分探索により b が空の範囲または全範囲に分割されます。 コストの計算式は、n 倍の絶対差にきれいに減少します。 

もう 1 つの特殊なケースは、 a に重複が含まれる場合です。 アルゴリズムは同じ x を複数回正しく評価しますが、最小値を取るため、重複は正確さに影響を与えず、実行時間にわずかに影響を与えるだけです。 

最後のエッジケースは、最適な x が b の中央値に近くない場合です。 候補は a[i] に制限されているため、中間値は既存の需要値に直接合わせる場合と比べて不均衡を増大させるだけであるため、最適なターゲットは既存の注文サイズの 1 つである必要があるという保証に依存します。
