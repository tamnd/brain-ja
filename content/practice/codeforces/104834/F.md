 ## 解決策
 ## 問題の理解

 私たちには、各セルが踏まれても許容範囲が限られた床のように動作するグリッドが与えられています。 すべての友達は左上隅から開始し、4 方向にのみ移動して右下隅に到達しようとします。 友人がセルを通過すると、そのセルの耐久性は 1 回使用するだけ減少します。 セルの耐久性がゼロになると、将来の友人がセルを踏むことはできなくなります。 

このタスクは、友人全員が次々に横断し、各横断で使用したパスに沿って耐久性を永続的に消費する場合に、何人の友人が最初から最後まで正常に歩行を完了できるかを判断することです。 

グリッド サイズは最大 100 x 100 なので、セルの数は最大 10,000 個になります。 各セルは最大 100,000 回使用できます。これは、答えが大きくなる可能性があることを示唆していますが、最終的には、重要なボトルネック セルが壊れる前にグリッドが維持できる「有効なルート」の数によって制限されます。 

単純なシミュレーションでは、最初から最後まで繰り返しパスを検索し、途中で容量を減らそうとします。 これはすぐに懸念を引き起こします。経路探索ステップだけでもすでにグリッド サイズにおいて少なくとも線形であるため、それを何度も実行する必要がある可能性があり、耐久性の合計が約 10^9 に達する可能性があります。 これにより、貪欲な DFS/BFS 戦略や繰り返しの DFS/BFS 戦略は実行不可能になります。 

複数のパスが 1 つのクリティカル セルを共有する場合、微妙なエッジ ケースが発生します。 たとえば、開始から終了までのすべてのルートが容量 1 の単一の中央セルを通過する必要がある場合、他の場所の容量が大きいかどうかに関係なく、通過できる友人は 1 人だけになります。 グローバルな制約を明示的に尊重せずに「フローを均等に分散」しようとする単純なアプローチでは、過大評価になってしまいます。 

もう 1 つの失敗例は、局所的な貪欲さに起因します。つまり、最短パスを繰り返し選択しても機能しません。 最短パスは重大なボトルネックを早期に消費し、その後の多くの切り離されたルートをブロックする可能性がありますが、より長い迂回は容量を維持し、より多くの合計フローを許可する可能性があります。 

## アプローチ

 重要な再定式化は、各フレンドが左上から右下までのフローの 1 つの単位に対応し、各セルが容量制限のある頂点のように機能することを認識することです。 各頂点が限られた回数しか使用できない場合、送信できるフローのユニット数を最大化することが求められます。 

これは古典的な最大流量問題ですが、エッジ容量ではなく頂点容量を使用します。 標準的な手法は、すべてのセルを 2 つのノード (「入口」ノードと「出口」ノード) に分割することです。 セルの耐久性に等しい容量を持つエッジで入口と出口を接続します。 これにより、セルを通過すると 1 単位の容量が消費されます。 

移動を強制するには、各セルの出口ノードを、無限の容量エッジを使用して隣接するセルの入口ノードに接続します。 これは、セル間の移動自体が耐久性を消費しないことをモデル化しています。 独房に留まるだけです。 

唯一の例外は開始セルと終了セルで、耐久性は無限です。 これらに対しては、ボトルネックにならないように、非常に大きな容量を割り当てるだけです (または分割制約を効果的にスキップします)。 

グラフが構築されると、答えはソース (セルの開始) からシンク (セルの終了) までの標準的な最大フローになります。 Dinic のアルゴリズムが適しているのは、グラフには分割後のノードが約 20,000 個、エッジが約 80,000 個あり、これは十分に制限内であるためです。 

ブルート フォース シミュレーションは、パスの検索とグリッドの更新を繰り返し、同じ構造を何度も再訪する可能性があるため、失敗します。 フロー定式化により、すべての相互作用が 1 つのグローバル最適化問題に圧縮され、ボトルネックが自動的に処理されます。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース パス シミュレーション | O(F · N · M) 最悪の場合、F は総流量まで | O(N・M) | 遅すぎる |
 | ノード分割による最大フロー | Dinic の場合は約 O(E √V) | O(N・M) | 承認済み |

 ## アルゴリズムのチュートリアル

 動きと耐久性の両方の制約をエンコードするフロー ネットワークを構築します。 

1. グリッド内のすべてのセルに対して、そのセルへの出入りを表す 2 つのノードを作成します。 この分割の理由は、セルに接触するエッジの数に関係なく、セルの使用回数に制限を設けるためです。 
2. セルの耐久性に等しい容量を持つ、入口ノードから出口ノードまでのエッジを追加します。 開始セルと終了セルについては、フローを制限すべきではないため、この容量を無限として扱います。 
3. 各セルについて、その 4 つの隣接セルを考慮します。 有効な隣接セルごとに、現在のセルの出口ノードを隣接セルの入口ノードに無限の容量で接続します。 これは追加コストなしで動きをモデル化します。 
4. ソースを (0, 0) の入口ノードとして定義し、シンクを (N-1, M-1) の出口ノードとして定義します。 これにより、すべてのパスが最初から最後までの完全な走査に対応することが保証されます。 
5. このグラフに対して最大流量アルゴリズム (通常は Dinic) を実行します。 結果として得られるフロー値は、容量がなくなる前に横断できるフレンドの最大数です。 

これが機能する理由は、フローのすべての単位がソースからシンクへの 1 つの有効なウォークに正確に対応しており、各トラバースが入口から出口のエッジを介して訪問された各セルから 1 単位の容量を消費するためです。 すべての容量はグローバルに適用されるため、すべてのパスを組み合わせた許容回数を超えてセルを使用することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

INF = 10**18

class Edge:
    def __init__(self, to, cap, rev):
        self.to = to
        self.cap = cap
        self.rev = rev

class Dinic:
    def __init__(self, n):
        self.n = n
        self.graph = [[] for _ in range(n)]
        self.level = [0] * n
        self.it = [0] * n

    def add_edge(self, fr, to, cap):
        forward = Edge(to, cap, len(self.graph[to]))
        backward = Edge(fr, 0, len(self.graph[fr]))
        self.graph[fr].append(forward)
        self.graph[to].append(backward)

    def bfs(self, s, t):
        self.level = [-1] * self.n
        q = deque([s])
        self.level[s] = 0
        while q:
            v = q.popleft()
            for e in self.graph[v]:
                if e.cap > 0 and self.level[e.to] < 0:
                    self.level[e.to] = self.level[v] + 1
                    q.append(e.to)
        return self.level[t] >= 0

    def dfs(self, v, t, f):
        if v == t:
            return f
        for i in range(self.it[v], len(self.graph[v])):
            self.it[v] = i
            e = self.graph[v][i]
            if e.cap > 0 and self.level[e.to] == self.level[v] + 1:
                pushed = self.dfs(e.to, t, min(f, e.cap))
                if pushed:
                    e.cap -= pushed
                    self.graph[e.to][e.rev].cap += pushed
                    return pushed
        return 0

    def max_flow(self, s, t):
        flow = 0
        while self.bfs(s, t):
            self.it = [0] * self.n
            while True:
                pushed = self.dfs(s, t, INF)
                if not pushed:
                    break
                flow += pushed
        return flow

def solve():
    N, M = map(int, input().split())
    grid = [list(map(int, input().split())) for _ in range(N)]

    def id_in(i, j):
        return (i * M + j) * 2

    def id_out(i, j):
        return (i * M + j) * 2 + 1

    n_nodes = N * M * 2
    dinic = Dinic(n_nodes)

    for i in range(N):
        for j in range(M):
            cap = grid[i][j]
            if (i, j) == (0, 0) or (i, j) == (N - 1, M - 1):
                cap = INF
            dinic.add_edge(id_in(i, j), id_out(i, j), cap)

    for i in range(N):
        for j in range(M):
            for di, dj in [(1, 0), (-1, 0), (0, 1), (0, -1)]:
                ni, nj = i + di, j + dj
                if 0 <= ni < N and 0 <= nj < M:
                    dinic.add_edge(id_out(i, j), id_in(ni, nj), INF)

    s = id_in(0, 0)
    t = id_out(N - 1, M - 1)
    print(dinic.max_flow(s, t))

if __name__ == "__main__":
    solve()
```実装は分割ノード構造に直接続きます。 各セルは、その「イン」ノードからその「アウト」ノードまで、正確に 1 つの容量エッジに寄与します。 動きのエッジは意図的に無限であるため、流れを制限することはなく、制限要因としてはセルの耐久性のみが残ります。 

微妙な点は、入力ノードと出力ノードに別々の ID を使用することです。 それらを混合したり、セルごとに 1 つのノードを再利用したりすると、容量を消費せずにセルを複数回使用することが誤って許可されてしまいます。 

## 実用的な例

 サンプル グリッドを考えてみましょう。 

入力:```
2 2
0 1000
2000 0
```次のようにセルにラベルを付け、それぞれを in ノードと out ノードに分割します。 

| ステップ | キーアクション | 効果 |
 | --- | --- | --- |
 | ノード容量の構築 | (0,1)=1000、(1,0)=2000 | 使用可能な中間セルは 2 つだけ |
 | 動きのエッジを追加する | すべての隣接する遷移は無限 | パスは自由にルーティング可能 |
 | 最初の拡張パス | (0,0)->(1,0)->(0,1)->(1,1) | パスに応じて最小ボトルネック 1000 または 2000 を使用します。 
| 2 番目のパス | 同様だが逆のボトルネックの使用法 | 容量がなくなるまで継続します。 

より具体的な解釈は、2 つの主要なコリドーが存在するということです。1 つは 1000 容量のセルを通るもの、もう 1 つは 2000 容量のセルを通るものです。 フローは最適に分割され、サンプル出力と一致する合計 3000 になります。 

これは、アルゴリズムが単一のルートにコミットせず、すべての実行可能なパスに使用量を分散していることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(E √V) | ノード分割を伴うグリッド グラフ上のディニック。ここで、V ≈ 20000 および E ≈ 80000 |
 | スペース | O(V + E) | 隣接リストとレベル配列の保存 |

 N、M ≤ 100 という制約により、V は十分に小さくなり、比較的重い最大フローの実装でも制限内で快適に実行できます。 グリッドの構造により次数が制限され、E が V で線形に保たれます。

 ## 特殊なケース

 重要なエッジ ケースは、単一の中間セルが開始点と終了点の間の唯一のブリッジである場合です。 次のような入力の場合:```
3 3
0 1 0
0 0 0
0 1 0
```すべての有効なパスは中央構造を通過する必要がありますが、唯一の有効な制約は中間の接続です。 アルゴリズムはボトルネック セルに容量 1 を割り当てるため、1 つのフロー単位のみが通過できます。 フロー ネットワークでは、すべての拡張パスがそのエッジを 1 回消費する必要があり、エッジが飽和すると、BFS はシンクへの有効なパスを見つけることができなくなります。 

もう 1 つのケースは、複数の大容量ルートが存在するものの、初期セグメントを共有している場合です。 共有ノードエッジが飽和すると、たとえ長くても代替ルートが優先されるため、フロー アルゴリズムによって使用量のバランスが自動的に調整されます。 これにより、貪欲な最短パスのトラップが防止され、全体的な最適性が確保されます。
