 ## 解決策
 ## 問題の理解

 サイズのグリッドが与えられています$n \times m$, ここで、各セルには高さの値が含まれます。 シロップはいくつかの開始セルに注がれ、高さと移動の制約に応じたルールに従って、各開始点からグリッド全体にシロップが広がります。 

どのセルからでも、シロップは 4 つの特定の隣接セルに移動できます。真上、真下、および 1 行上と 1 列左、または 1 行下と 1 列右に移動する 2 つの対角方向です。 ただし、移動が許可されるのは、次のセルの高さが現在のセル以下である場合のみです。 したがって、シロップは常に高さの増加しない経路に沿って流れますが、この限られた一連のエッジに沿ってのみ流れます。 

各注入は独立して開始されます。 開始セルごとに、これらのルールに基づいて到達可能な領域全体をシミュレートします。 開始点からセルに到達できるたびに、そのセルはその注入に対して 1 回カバーされたとみなされます。 各注入が終了すると、プロセスがリセットされます。 

タスクは、どのグリッド セルが最大数の流し込みによってカバーされるかを判断することです。 複数のセルが同点の場合は、行インデックスが最小のものを選択し、依然として同点の場合は列インデックスが最小のものを選択します。 

グリッドは最大でも$100 \times 100$、まであります$1000$注ぐ。 生のサイズに関しては、注入ごとの直接シミュレーションが可能ですが、これは各シミュレーションが効率的である場合に限られます。 クエリごとの完全な BFS は最大で次の場所にアクセスします。$10^4$ノード、約$10^7$全体的には遷移が大きく、境界線にありますが、注意して実装すれば Python ではまだ許容可能です。 セルごとにナイーブに繰り返される DFS で到達可能性を再計算するソリューションは、爆発的に$10^9$操作。 

動きを方向性のないものとして扱ったり、高さの制約の方向性を無視したりすると、微妙な失敗のケースが発生します。 たとえば、次のことを考えてみましょう。```
1 3
1 2 3
1 2 1
```(1,3) から、方向制約をチェックせずに下位の近隣に流入できると誤って想定し、カバレッジを誤って拡大する可能性があります。 

もう 1 つの問題は再計算です。DFS を繰り返してすべてのペア (開始、セル) の到達可能性を計算しようとすると、たとえ多くのポアが同じまたは類似した領域から開始したとしても、同じ到達可能な領域を何度も再計算することになります。 

重要な観察は、各注入が独立しており、グリッドのエッジと高さの制約によって定義された有向グラフに沿って到達可能性を前方に伝播するだけでよいということです。 

## アプローチ

 ブルートフォース手法により、各注入を個別にシミュレートします。 開始セルごとに BFS または DFS を実行し、到達可能なすべてのセルにマークを付けます。 次に、訪問したセルごとにグローバル カウンタをインクリメントします。 各BFSはタッチアップできるため、$n \cdot m$細胞があり、$q$土砂降りの場合、最悪の場合のコストは$O(qnm)$、それは約です$10^7$操作。 これはすでに限界に近づいていますが、まだ実行可能です。 

より単純な代替案では、全ペアの到達可能性または繰り返しのフラッド フィルを使用して、すべてのセルから他のすべてのセルへの到達可能性を事前計算します。 それは次のことにつながります$O((nm)^2)$あるいはさらに悪いことに、それは明らかに実行不可能です。 

重要な洞察は、異なる注入間で結果を再利用する必要はないが、各 BFS が効率的であり、セルの再訪問を回避する必要があるということです。 グラフは小さく、有向性があるため、訪問された配列を含むクエリごとの単純な BFS で十分です。 動きの構造では高さの制約に違反するサイクルは許可されないため、各 BFS は自然にグリッド サイズによって制限されます。 

したがって、各ポアをマルチソースの到達可能性の問題として扱うことができますが、独立して実行され、カバレッジ カウントが蓄積されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとのブルート フォース BFS |$O(qnm)$|$O(nm)$| 承認済み |
 | すべてのペアの到達可能性を事前計算する |$O((nm)^2)$|$O((nm)^2)$| 遅すぎる |

 ## アルゴリズムのチュートリアル

 BFS/DFS を使用して各注入を個別に処理します。 

1. グローバル 2D 配列を初期化する`cnt`サイズの$n \times m$ゼロに。 これにより、各セルに到達した注水の数が追跡されます。 
2. セルから開始する各注入について$(i, j)$、BFS を実行します。 

開始セルをキューにプッシュし、この特定の BFS に対して訪問済みであることをマークします。 高さの制約を満たす隣接するもののみに進みます。 
3. BFS 中にセルにアクセスするたびに、インクリメントします。`cnt[cell]`1つずつ。 これにより、すべてのポアが到達可能なセルごとに 1 回だけ寄与することが保証されます。 
4. ポップされた各セルから、許可された 4 つの隣接セル (上、下、斜め左上、および斜め右下) への移動を試みます。 隣接セルがグリッド内にあり、この BFS で訪問されておらず、高さが現在のセル以下である場合にのみ、隣接セルをキューに入れます。 
5. 注湯の BFS が終了したら、訪問した構造を破棄し、次の注湯に進みます。 
6. すべての注入を処理した後、グリッド全体をスキャンして、最大値を持つセルを見つけます。`cnt`。 タイを行ごとに分割し、次に列ごとに分割します。 

BFS の完了後ではなく、トラバーサル中にインクリメントする理由は、到達可能なセット全体を保存せずに、各セルがポアごとの参加を記録するためです。 

### なぜ効果があるのか

 注ぐたびに、BFS は、許可された移動に沿って高さが増加しないという指示された制約の下で到達可能なセルのセットを正確に探索します。 訪問された配列により、各セルが注入ごとに最大 1 回カウントされることが保証されます。 注入は独立しているため、これらの寄与を合計すると、各セルがカバーされる正確な回数が得られます。 最後のスキャンでは最大周波数セルが選択され、タイブレークにより確定的な出力が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n, m, q = map(int, input().split())
    h = [list(map(int, input().split())) for _ in range(n)]

    cnt = [[0] * m for _ in range(n)]

    dirs = [(-1, 0), (1, 0), (-1, -1), (1, 1)]

    for _ in range(q):
        si, sj = map(int, input().split())
        si -= 1
        sj -= 1

        vis = [[False] * m for _ in range(n)]
        dq = deque()
        dq.append((si, sj))
        vis[si][sj] = True

        while dq:
            i, j = dq.popleft()
            cnt[i][j] += 1

            for di, dj in dirs:
                ni, nj = i + di, j + dj
                if 0 <= ni < n and 0 <= nj < m:
                    if not vis[ni][nj] and h[ni][nj] <= h[i][j]:
                        vis[ni][nj] = True
                        dq.append((ni, nj))

    best_i, best_j = 0, 0
    best_val = -1

    for i in range(n):
        for j in range(m):
            if cnt[i][j] > best_val:
                best_val = cnt[i][j]
                best_i, best_j = i, j

    print(best_i + 1, best_j + 1, best_val)

if __name__ == "__main__":
    solve()
```BFS ループは、各セルがクエリごとに 1 回だけ処理されるように構造化されています。 訪問したマトリックスは、シミュレーション全体での汚染を避けるために、注入ごとに再作成されます。 方向配列は、指定されたとおりに 4 つの許可された遷移を正確にエンコードします。 

最終スキャンはグリッド上で線形であり、反復順序に依存してタイブレークを安全に処理します。

## テストケース```python
import sys, io
from collections import deque

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, m, q = map(int, input().split())
    h = [list(map(int, input().split())) for _ in range(n)]
    cnt = [[0] * m for _ in range(n)]
    dirs = [(-1, 0), (1, 0), (-1, -1), (1, 1)]

    for _ in range(q):
        si, sj = map(int, input().split())
        si -= 1
        sj -= 1
        vis = [[False] * m for _ in range(n)]
        dq = deque([(si, sj)])
        vis[si][sj] = True

        while dq:
            i, j = dq.popleft()
            cnt[i][j] += 1
            for di, dj in dirs:
                ni, nj = i + di, j + dj
                if 0 <= ni < n and 0 <= nj < m:
                    if not vis[ni][nj] and h[ni][nj] <= h[i][j]:
                        vis[ni][nj] = True
                        dq.append((ni, nj))

    best = (-1, -1, -1)
    for i in range(n):
        for j in range(m):
            if cnt[i][j] > best[2]:
                best = (i + 1, j + 1, cnt[i][j])

    return f"{best[0]} {best[1]} {best[2]}"

 ## 特殊なケース

 重要なエッジケースは、すべての高さが等しい場合です。 その状況では、許可された方向を通じて接続されている限り、すべてのセルはどの開始点からでも到達可能になります。 例えば：```
2 2 1
5 5
5 5
1 1
```すべての移動が非増加条件を満たすため、(1,1) の BFS はすべてのセルを訪問します。 アルゴリズムは 4 つのセルすべてを 1 回正しくインクリメントし、最終的な最大値は同じになります。 タイブレーク ルールでは、辞書編集上の最小のセルに一致する (1,1) が選択されます。 

もう 1 つのエッジ ケースは、開始時を除いて地形が厳密に増加しているため、動きが極端に制限されている場合です。 で：```
2 2 1
1 2
3 4
1 1
```すべての近傍が高さの条件に違反しているため、(1,1) のみが到達可能です。 BFS は開始セルのみをマークし、カウントは伝播せずに正しいままになります。 

最後の微妙なケースは、同じセルから繰り返し注ぐことです。 各 BFS は独立した訪問先アレイを使用するため、ポア間の重複は干渉しません。 同じ領域が複数回カウントされ、累積値は個別の開始位置ではなく正確な頻度を反映します。
