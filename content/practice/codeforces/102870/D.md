 ## 解決策
 ## 問題の理解

 ノードを持つ根付きツリーがあります`1`根として。 ランダム操作の無限シーケンス中に、毎回 1 つのノードが均一に選択されます。 ルートからそのノードまでのパスが参照され、そのパス上のすべてのエッジが、まだ優先されていない場合はその親の優先エッジになります。 タスクは、操作ごとの優先子の変更の長期平均数を見つけることです。 答えは必須です`998244353`。 元のステートメントでは、これらの操作を LCT アクセス操作として説明していますが、ソリューションにはリンクカット ツリーの知識は必要ありません。 

重要な難点は、プロセスがランダムであり、永久に継続することです。 動作シミュレーションは行っておりません。 代わりに、プロセスが安定した動作に達した後に各ノードによって引き起こされる予想される変更の数を計算します。 

までのツリーの場合`100000`ノードの場合、操作を繰り返しシミュレートしたり、考えられるすべての状態についてツリーの高さに比例した作業を実行したりするアプローチは、コストが高すぎます。 二次方程式のアプローチはすでに次のように実行できます。`10^10`最悪の場合、通常の 1 秒の制限をはるかに超えて操作が可能になります。 ツリーに対する線形または線形に近い計算が必要です。 

最初のエッジ ケースは単一ノード ツリーです。 優先される子はなく、変更の可能性もないため、答えは次のようになります。`0`。```
Input
1

Output
0
```すべてのノードに親エッジがあると仮定するか、反転しようとする不注意な実装`subtree_size - 1`チェックしないとここで失敗します。 

もう 1 つのエッジ ケースは、子が 1 つだけあるノードです。 ノードを介してその子にアクセスすると、その後そのノードを介してアクセスしても、優先される子が変更されることはありません。 例えば：```
Input
2
1

Output
0
```ルートは常にその唯一の子を優先するため、予想される変更の数はゼロです。 子供への訪問をすべて変化としてカウントする数式は、誤って正の値を出力します。 

3 番目のエッジ ケースは、子ノードのサブツリー サイズが大きく異なるノードです。 例えば：```
Input
5
1 1 1 1

Output
0
```ルートには 4 つの葉の子があります。 その優先子は、単にアクセスされた 4 つのうちの最後の子です。 ある子から別の子に変更される確率は、子の数だけではなく、以前のアクセスの分布によって決まります。 すべての子供を同等の可能性があるものとして扱うと、誤った期待が生じます。 

## アプローチ

 直接的なアプローチは、優先子の状態をシミュレートすることです。 操作ごとに、ノードを選択し、ルートからそのノードまで歩き、パスに沿って優先される子を更新します。 これはプロセスに正確に従っているため、これは正しいです。 ただし、操作の数が無限に近づくと、要求された値が制限となります。 シミュレーションでは正確なモジュール式の答えを得ることができず、深いツリーで 100 万回の操作を実行しただけでもすでに遅すぎる可能性があります。 の連鎖の中で`100000`ノード、1 回の操作でタッチできる`100000`エッジ、与える`10^11`エッジアップデート`10^6`模擬操作。 

有益な観察は、すべてのノードを独立して分析できることです。 ノードを検討してください`u`子供たちと一緒に`c1, c2, ...`。 の好ましい子供`u`選択したノードがこれらの子サブツリーのいずれかにある場合にのみ変更されます。 選択したノードが外部にある場合`u`のサブツリー、何も関係ありません`u`変化します。 

多くの手術の後、望ましい子供は`u`以下の最新のアクセスを含む子サブツリーです。`u`。 その子の確率は`c`現在優先される値は、そのサブツリーのサイズに比例します。 の子の下にあるノードの総数が`u`は`s`、 それから：$$P(c\text{ is preferred})=\frac{size[c]}{s}$$次の操作では、子供`c`確率で選択されます:$$\frac{size[c]}{n}$$新しい子が現在の優先子と異なる場合、変更が発生します。 の貢献`u`は：$$\sum_c \frac{size[c]}{n}
\left(1-\frac{size[c]}{s}\right)$$どこ：$$s = subtree[u]-1$$これは次のように単純化されます。$$\frac{1}{n}
\left(
s-\frac{\sum size[c]^2}{s}
\right)$$ここで、問題はツリー DP 問題になります。 必要なのは、サブツリーのサイズと、各ノードの子サブツリーのサイズの 2 乗の合計だけです。

 ## アルゴリズムのチュートリアル

 1. 親配列からルート付きツリーを構築します。 すべてのノードの子を保存して、後ですべての子サブツリーを検査できるようにします。 
2. 事後探索を使用して、すべてのサブツリーのサイズを計算します。 ノードのサブツリー サイズが必要なのは、各子がどのくらいの頻度で優先子になることができるかを示すためです。 
3. リーフ以外のノードごとに`u`、 させて`s = subtree[u] - 1`。 これは、すべての子サブツリーに含まれるノードの数です。`u`。 値を計算します。$$\frac{s-\frac{\sum size[child]^2}{s}}{n}$$そしてそれを答えに追加します。 

1. すべての除算をモジュロで実行します。`998244353`。 法は素数であるため、非ゼロの分母はすべて、べき乗剰余を使用した逆数を持ちます。 
2. 累積値のモジュロを出力します。`998244353`。 

なぜ効果があるのか:

 すべてのノードについて`u`の場合、優先される子は、その子サブツリーの 1 つに入った最新のアクセスによってのみ決定されます。 これにより、ツリーの残りの部分とは独立して、サブツリーのサイズに応じて各子が優先される安定した確率分布が作成されます。 この式は、次のアクセスで別の子が選択される確率を正確に計算します。 すべてのノードにわたるこれらの独立した予想される寄与を合計すると、1 回の操作での優先子の変更の予想数が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n_line = input().strip()
    if not n_line:
        return
    n = int(n_line)

    children = [[] for _ in range(n)]
    if n > 1:
        parents = list(map(int, input().split()))
        for i, p in enumerate(parents, start=1):
            children[p - 1].append(i)

    size = [1] * n
    order = [0]
    for u in order:
        for v in children[u]:
            order.append(v)

    for u in reversed(order):
        for v in children[u]:
            size[u] += size[v]

    inv_n = pow(n, MOD - 2, MOD)
    ans = 0

    for u in range(n):
        if not children[u]:
            continue

        s = size[u] - 1
        sq = 0
        for v in children[u]:
            sq += size[v] * size[v]
            sq %= MOD

        cur = (s % MOD - sq * pow(s, MOD - 2, MOD)) % MOD
        cur = cur * inv_n % MOD
        ans += cur
        ans %= MOD

    print(ans)

if __name__ == "__main__":
    solve()
```すべてのノードは直接の子からの情報のみを必要とするため、ツリーは子リストとして保存されます。 走査順序は、チェーン形状のツリーでの Python 再帰の深さの問題を回避するために反復的に構築されます。 

サブツリーのサイズは、逆走査順序で計算されます。 ノードが処理されるとき、そのすべての子はすでに最終的なサブツリー サイズを受け取っているため、それらを追加すると親の正しいサイズが生成されます。 

式は子を持つノードにのみ適用されます。 葉っぱに関しては、`subtree[u] - 1`はゼロであり、優先子が変更される可能性はないため、それらをスキップすると、ゼロによる除算も回避されます。 

すべての算術はモジュロで実行されます`998244353`。 の逆`s`なぜなら存在する`s`常に間にあります`1`そして`n-1`処理されたノードの場合。

 ## 特殊なケース

 単一ノードツリーの場合:```
Input
1
```このアルゴリズムは、子のないノードを 1 つ作成します。 優先される子が存在しないため、寄与ループはスキップされ、答えはゼロのままになります。 

子が 1 つあるノードの場合:```
Input
2
1
```根には、`s = 1`唯一の子にはサブツリーのサイズがあります`1`。 貢献度は次のようになります。$$1-\frac{1^2}{1}=0$$したがって、答えはゼロのままです。 この式は、同じ一人っ子を選択しても再割り当てを作成できないという事実を捉えています。 

等しい子の場合:```
Input
5
1 1 1 1
```ルートにはサイズ 1 の子が 4 つあります。 次のアクセスで優先子が変更される確率は次のとおりです。$$4 \times \frac{1}{5}\times\frac{3}{4}=\frac{3}{5}$$子状態はサブツリーのサイズによって処理されるため、アルゴリズムは、訪問するたびに優先エッジが変更されると誤って想定することはありません。 

チェーンなどの不均衡なツリーの場合、すべての内部ノードには優先される可能性のある子が 1 つしかないため、アルゴリズムは正しくゼロを生成します。 一般式は自然にゼロに崩壊するため、実装では特別な処理を行わなくても同じ結論に達します。
