 ## 解決策
 ## 問題の理解

 送信されるメッセージはハミング符号化されたブロックです。 ブロックには、`2^k`ビット、およびビットのインデックスは次のとおりです。`0`に`2^k - 1`。 受信したブロックは、最大 2 ビットの変更によって変更されている可能性があります。 タスクは、受信したブロックがまだ有効であるかどうか、1 ビットだけが破損していてそのインデックスを特定するか、または 2 ビットが変更されてエラーを修正できないかどうかを判断することです。 

入力には、ファイルの終わりまで複数の独立したブロックが含まれています。 ブロックごとに、`k`次に、受信したビットを表す完全なバイナリ文字列。 出力には、そのブロックの状態 (有効なコード ワード、単一の破損した位置、または修正不可能な 2 ビットの破損) が記述されます。 

制約は、どのような種類のソリューションが必要であるかを示します。 以来`k`と同じ大きさにすることができます`16`、ブロックには次のものを含めることができます`2^16 = 65536`ビット。 すべてのテスト ケースにわたる合計ビット数は約 100 万に制限されているため、各ブロックの線形パスが意図されたアプローチです。 可能性のあるエラー位置を試したり、すべての有効なコードワードと比較したりする方法は、検索空間が指数関数的に増大するため不可能です。 

インデックスにビットがあるため、見落としやすいケースがいくつかあります。`0`他のポジションとは動作が異なります。 これは追加のパリティ ビットであるため、インデックス付きパリティ ビットのみをチェックすると、単一エラーにゼロ位置シンドロームがあり、有効なブロックと誤認される可能性があります。 

たとえば、次の受信ブロックは、最初のビットのみが間違っている場合を表しています。```
3
10000000
```正しい答えは次のとおりです。```
d(0) is changed
```設定されたビットのインデックスの XOR を計算するだけのソリューションでは、ゼロが計算され、誤って出力されます。`good`。 

もう 1 つの微妙なケースは、2 つのエラーがあり、その 1 つはパリティ ビットです。```
3
11000000
```正しい出力は次のとおりです。```
broken
```位置 xor は位置を指します`1`ですが、全体的なパリティ チェックでは、反転されたビットが 2 つあることがわかります。 シンドロームを保証された単一エラーとして扱うと、誤って報告されます。`d(1) is changed`。 

## アプローチ

 直接的なアプローチでは、可能な限りあらゆる部分を修復しようとします。 それぞれを反転することができます`2^k`位置を確認し、結果のブロックがすべてのハミング パリティ条件を満たしているかどうかを確認し、その位置が破損していないかどうかを判断します。 これは正しいです。エラーが 1 つだけある場合、元のコード ワードは受信ブロックから 1 ビット離れている必要があるからです。 ただし、以下までの確認が必要です。`2^k`候補者とすべてのチェックにかかる費用`O(k)`または`O(2^k)`実装に応じて。 のために`k = 16`、より単純なバージョンでも、大規模な入力に対して数十億の操作を実行します。 

ハミング コードの構造により、エラーを見つけるはるかに簡単な方法が得られます。 ゼロ以外のすべてのインデックスはバイナリ表現を持ち、各パリティ条件はその表現の 1 ビットに対応します。 以下を含むすべての位置のインデックスを XOR すると、`1`、結果はすべての破損した位置の xor です。 この値はシンドロームと呼ばれます。 

インデックスの全体的なパリティ ビット`0`2 を法として変更されたビット数を示します。 受信したブロック内のセット ビットの総数が正しいパリティを持っている場合、奇数の変更はありません。 シンドロームと全体的なパリティを組み合わせると、考えられるすべてのケースが得られます。 

シンドロームがゼロで全体のパリティが正しい場合、ブロックは有効です。 

シンドロームがゼロでなく、全体のパリティが正しくない場合は、ちょうど 1 ビットが変更されます。 シンドローム自体が破損したインデックスです。 

シンドロームがゼロで全体のパリティが正しくない場合、ビットのみが`0`変わりました。 

シンドロームがゼロでなく、全体のパリティが正しい場合、ちょうど 2 ビットが変更されているため、ブロックは壊れています。 

ブルート フォース ソリューションは、近くの有効なコード ワードを検索するため機能しますが、ブロックが大きい場合は失敗します。 ハミング パリティ チェックがすでにエラー位置をエンコードしているという観察により、プロセス全体を入力の 1 回のスキャンに減らすことができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^k * k) | お(1) | 遅すぎる |
 | 最適 | O(2^k) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む`k`そして受信したビット列。 文字列の長さがブロックサイズになります。`2^k`。 
2. 次の式からすべての位置のインデックスを XOR してシンドロームを計算します。`1`に`2^k - 1`を含む`1`。 位置`0`これは全体的なパリティ ビットであり、インデックス情報がないため、スキップされます。 
3. の数を数えます`1`受信したブロック全体のビット。 このカウントのパリティにより、全体的なパリティ条件が満たされているかどうかがわかります。 
4. シンドロームとパリティの結果を使用してエラーを分類します。 

シンドロームがゼロでパリティが有効な場合、出力`good`。 

シンドロームがゼロ以外でパリティが無効な場合は、シンドロームを変更後の位置として出力します。 

シンドロームがゼロでパリティが無効な場合は、その位置を出力します`0`変わりました。 

それ以外の場合は出力`broken`。 

これが機能する理由は、シンドロームがすべての変更された位置の XOR であるためです。 単一の変更された位置は、それ自体のインデックスをシンドロームとして残します。 2 つの変更された位置により 2 つの異なるインデックスの xor が生成され、パリティ ビットによりこれを単一エラーの場合と区別できます。 

これが機能する理由: ハミング パリティ方程式は有効なブロックでは変更されないため、以下を含むすべての位置の xor が計算されます。`1`ゼロでなければなりません。 反転されたビットはそのインデックスを XOR に提供します。これは、シンドロームにはすべてのエラーを組み合わせた位置情報が正確に含まれていることを意味します。 追加のパリティ ビットにより、奇数のエラーと偶数のエラーが分離され、1 ビットの破損と 2 ビットの破損を区別できるようになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(k, s):
    n = 1 << k

    syndrome = 0
    ones = 0

    for i, ch in enumerate(s):
        if ch == '1':
            ones += 1
            if i != 0:
                syndrome ^= i

    if ones % 2 == 0:
        parity_ok = True
    else:
        parity_ok = False

    if syndrome == 0 and parity_ok:
        return "good"

    if syndrome != 0 and not parity_ok:
        return f"d({syndrome}) is changed"

    if syndrome == 0 and not parity_ok:
        return "d(0) is changed"

    return "broken"

def main():
    ans = []
    while True:
        line = input()
        if not line:
            break
        if not line.strip():
            continue
        k = int(line)
        s = input().strip()
        ans.append(solve_case(k, s))

    print("\n".join(ans))

if __name__ == "__main__":
    main()
```実装はウォークスルーの 4 つのケースに直接続きます。 変数`syndrome`以下を含むすべての非パリティ位置の xor を格納します。`1`。 ループがインデックスをスキップすることが重要です`0`これを含めると、パリティ ビット エラーと通常の位置エラーの区別が崩れてしまうためです。 

変数`ones`位置を含むすべての設定ビットをカウントします`0`。 合計パリティによって、変更されたビットの数が奇数か偶数かが決まります。 この問題では最大 2 つの変更が保証されるため、全体のパリティが無効であるということは、正確に 1 ビットが変更されたことを意味します。 

アレイや追加のストレージは必要ありません。 文字列は一度処理され、最大のインデックスは 1 つだけであるため、すべての計算は Python 整数内に快適に収まります。`65535`。
