 ## 解決策
 ## 問題の理解

 同一のマッチ棒が与えられたので、それらを組み立てて 10 進数にしたいと考えています。 標準の 7 セグメント表示構成に従って、各桁は固定数のマッチ棒を消費します。 十分なマッチ棒がある限り、どの数字を選んでも構いません。すべてを使用する必要はありません。 結果として得られる数値は、指定された桁の上限を使用する必要があります。つまり、答えのすべての桁は次の値を超えてはなりません。`k`、数値自体をゼロで始めることはできません。 

各テスト ケースについて、これらの制約の下で数値的に可能な最大値を構築する必要があります。 

重要な難しさは、問題がマッチ棒の合計や任意の分割に関するものではなく、コストが異なる数字の選択に関するものであるということです。 これにより、消費されるリソースの中で数字の値が線形にならないという組み合わせ最適化問題が発生します。 

この制約により、最大 1000 のテスト ケースと値が許可されます。`n`すべての数字の組み合わせを列挙したり、テスト ケースごとにナップザック スタイルの DP を実行しようとするソリューションは、単純に実装すると遅すぎるリスクがあります。`O(nk)`テストケースごとにそれ以上の場合もあります。 

微妙なエッジケースは、制約の下でマッチ棒が有効な数字を形成できない場合です。`digit ≤ k`。 その場合、答えは空であるか、事実上不可能である必要がありますが、一般的なコンテストの定式化では、許容範囲が与えられていれば、少なくとも 1 つの数字が常に構成可能であると想定されます。 もう 1 つのエッジ ケースは、貪欲な戦略が早い段階で小さい数字を選択するが、後で辞書編集的により長い数字を形成するブロックをブロックする場合です。 たとえば、多くのマッチ棒を消費する大きな数字を優先すると、合計の数字の数が減り、全体の数字が小さくなる可能性があります。 

この問題には、古典的な「マッチ棒の数字」構造も暗黙的に含まれています。数字 0 ～ 9 には固定コストがあり、辞書編集的に数字を最大化するということは、最初に桁数を最大化し、次に数字の値を最大化することを意味します。 

## アプローチ

 これを考える強引な方法は、マッチ棒の数と使用する桁を動的にプログラミングすることです。 定義できます`dp[i]`正確に使用して形成できる最良の数値として`i`マッチ棒、すべての数字を試して移行`0-k`。 各遷移では、辞書編集的に構築された数値が比較されます。 

これは原理的には正しいです。すべての有効な数値は一連の数字の選択肢に対応しており、DP はそのようなすべてのシーケンスを探索します。 ただし、各状態には文字列が保存され、各遷移では文字列の比較またはコピーが必要となるため、`O(n * k * length)`テストケースごとの操作。 と`n = 1000`そして`t = 1000`、これは限界をはるかに超えています。 

問題の構造により、貪欲な構築が可能になります。 目的は辞書編集的な最大化であるため、桁の値に関係なく、短い数値よりも長い数値の方が常に優れています。 これは、まず形成できる桁数を最大化し、次に左から右へ各桁を最大化する必要があることを示唆しています。 

桁数を最大化するには、許可された桁の中でマッチ棒の消費が最小となる桁を常に使用する必要があります。`0..k`。 長さが固定されると、各位置を最大の数字で貪欲に埋めることができ、残りの位置を最小コストの数字で完成させることができます。 

これにより、問題が全体的な最適化から残りの予算に基づくローカルな実現可能性チェックに軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 文字列に対するブルートフォース DP | O(n・k・n) | O(n・k) | 遅すぎる |
 | 貪欲な建設 | O(n · k) または O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 標準的な桁のコストは 7 セグメント ディスプレイからのものであると仮定します。これは、各桁に固定のマッチ棒要件があることを意味します。 

1. 次から各桁のコストを計算します。`0`に`k`。 までの桁のみを考慮します`k`、これより大きな数字は禁止されているためです。 また、マッチ棒の容量を超えている場合や無効な場合には表現できない数字も無視します。 
2. 許可されているすべての桁の中から最小コストを見つけます。 この数字は、マッチ棒を桁数に変換する最も効率的な方法であるため、数字の最大長が決まります。 
3. 最大桁数を計算します。`L`次のように構築できます`L = n // min_cost`。 
4. もし`L = 0`、何も出力しないか、不可能なケースを処理します。 これは、マッチ棒が少なすぎて 1 桁さえ形成できないことに相当します。 
5. 左から右に答えを作成します。 各位置で、以下の数字を試してください。`k`まで`0`。 
6. 候補数字の場合`d`、それを選択しても残りの位置に有効な数字を入力できるかどうかを確認してください。 これには、選択した後に残りのマッチ棒があることを確認する必要があります。`d`満たすのに十分です`remaining_positions`最小コストの数字を使用します。 
7. 有効な数字が見つかったら、それを答えに追加し、残りのマッチ棒からそのコストを差し引いて続行します。 

### なぜ効果があるのか

 正確さは 2 つの結合された不変式に依存します。 まず、構築のどの段階でも、アルゴリズムはマッチ棒の予算に応じて可能な最大の残り桁数を常に維持します。 これが保証されるのは、最小コストの桁を使用して桁数が事前に固定されるため、プレフィックスを選択しても最適な長さが短縮される可能性がないためです。 

第 2 に、各位置で実行可能な最大の数字を選択することで、残りの数字を完成させる可能性が保たれます。 実現可能性は最小コストの数字を使用してチェックされるため、拒否された数字は完全な解を完成する能力に違反することになり、辞書編集上の最適な答えに属することができないことを意味します。 

したがって、この構築は長さと辞書編集上の順序の両方において貪欲であり、後の決定が最適ではない前の桁を補償することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

# Standard 7-segment matchstick costs
cost = [6,2,5,5,4,5,6,3,7,6]

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())

        allowed = list(range(k + 1))

        min_cost = min(cost[d] for d in allowed)

        L = n // min_cost
        if L <= 0:
            print(0)
            continue

        res = []
        remaining = n

        for pos in range(L):
            for d in range(k, -1, -1):
                c = cost[d]
                if remaining >= c:
                    rem_after = remaining - c
                    # check feasibility for remaining positions
                    if rem_after >= (L - pos - 1) * min_cost:
                        res.append(str(d))
                        remaining -= c
                        break

        print("".join(res))

if __name__ == "__main__":
    solve()
```コードはまず、数字の固定マッチ棒コストをエンコードします。 次に、許可された桁の中で最も効率的な桁コストを計算し、それによって達成可能な最大長が決まります。 貪欲ループは、数字を桁ごとに構築し、常に最大の桁を最初に試しながら、残りの位置を完了するための実現可能性を確保します。 

実現可能性のチェックは重要な部分です。これにより、必要な桁数を完了するのに不十分なマッチ棒が残るような大きな桁の選択を防ぐことができます。

 ## 特殊なケース

 最初のエッジケースは次のような場合です。`k`非常に小さいです、例えば`k = 0`または`k = 1`。 この場合、ソリューションは 1 桁のみを使用するように縮退し、アルゴリズムは貪欲な選択中により大きな桁の試行を正しく回避する必要があります。 

2 番目のエッジケースは次のような場合です。`n`最も安い数字を除く、許容される数字のコストをわずかに下回ります。 たとえば、最も安い桁の価格がマッチ棒 5 本の場合、`n = 4`の場合、正しい出力は空またはゼロであり、アルゴリズムは部分的な数字の構築を試行してはなりません。 

3 番目のエッジケースは、文字列の早い段階で貪欲な数字を選択することが有益であるように見えても、後で実行可能性を妨げる場合です。 実現可能性チェックでは、すべてのプレフィックスが最小コスト桁での補完を許可する必要があることを強制し、取り消し不能な選択が行われないようにすることで、この状況を防ぎます。
