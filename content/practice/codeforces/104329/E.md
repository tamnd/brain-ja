 ## 解決策
 ## 問題の理解

 ノード 1 がルートとして固定されているルート付きツリーが与えられ、各ノードには 0 または 1 のバイナリ値が格納されます。特別な操作を何度でも実行できます。 各操作では、ツリー内の分岐点を中心とする 4 つのノードの特定のパターンが選択され、4 つの値すべてが反転されます。 

パターンは、少なくとも 2 つの子を持つノード x を選択することによって定義されます。 また、その親を選択し、x の 2 つの異なる子を選択します。 この操作により、これら 4 つのノードの値が反転されます。 反転とは、0を1に、1を0に変えることです。 

タスクは、指定された構成から始めて、これらの操作のシーケンスを適用した後、すべてのノード値を 0 にできるかどうかを判断することです。 

操作の構造は、ノードのすべてのサブセットを独立して反転できるわけではないことをすでに示唆しています。 それぞれの移動により、親、分岐ノード、および 2 つの子が結合され、ローカル ツリー近傍全体に強力なパリティ制約が即座に導入されます。 

制約が非常に厳しいため、演算ごとの 2 次または線形に近い推論は不可能です。 すべてのテスト ケースにわたるノードの合計数は最大 10^5 であるため、すべての解はテスト ケースごとに線形または線形演算である必要があります。 これは、問題をノードごとの局所的な条件に還元するか、1 回の走査でチェックできる単純な不変式を抽出する必要があることを強く示唆しています。 

ローカルで考えると、微妙な問題が発生します。ノードは、複数の孫構成の親として選択できるため、さまざまな Y 構造の一部である可能性があります。 このため、ローカルで各ノードを個別に修正できると考えたくなりますが、操作が大幅に重複するため、それは誤りです。 

素朴な推論によるいくつかの障害モード:

 ノードに子が 1 つしかない場合、そのノードが操作の中心になることはできないため、その値は、Y 字型の親または祖父母として表示される場合にのみ変更できます。 たとえば、長さ 4 のチェーンでは、操作はまったく不可能であるため、間接的に修正できない限り、最初に 1 を入力すると、答えはすぐに NO になります (間接的に修正することはできません)。 

もう 1 つの注意が必要なケースは、ルートに多くの子があり、それらの子が葉である場合です。 分岐があっても、有効な Y はありません。これは、少なくとも 2 つの子と親を持つノードが必要であるため、ルート自体は使用できません (親がありません)。 これにより、一見「反転可能」に見える多くの木が実際に凍結してしまいます。 

最も難しいのは、これらの Y 操作がすべての 1 を除去するのに十分な自由度をいつ生成するかを理解することです。 

## アプローチ

 ブルートフォースアプローチでは、考えられるすべての Y 操作をシミュレートしようとします。 少なくとも 2 つの子を持つ各ノード x について、子のすべてのペアを列挙し、考えられるすべての親の選択肢に反転を適用します。 各ノードは O(deg(x)^2) 操作に関与する可能性があり、一連の操作が任意の方法で相互作用する可能性があるため、これはすぐに爆発します。 状態を表すだけでも指数関数的な動作が発生します。 

重要な観察は、操作が恣意的ではないということです。すべての反転には常に、深さ d−1 の 1 つのノード (親)、深さ d の 1 つのノード (中心 x)、および深さ d+1 の 2 つのノード (その子) が含まれます。 この構造では、すべての操作が少なくとも 2 つの子を持つノードに「集中」するように強制されます。重要なことは、そのノード自体に親が必要であるということです。 

したがって、唯一使用可能な中心は、ルート化された意味で次数が少なくとも 3 の非ルート内部ノード (親 + 少なくとも 2 つの子) です。 各操作により、これらのローカル トリプル間のパリティ制約が切り替わります。 問題は、これらのパリティ制約の下で最初の 1 をペアにして削除できるかどうかを判断することに帰着します。

操作を再解釈する便利な方法は、適格な各ノード x に焦点を当てることです。 x では、その子の任意のペアを x とその親と一緒に反転できます。 これは、子のパリティ寄与が x とその親と密接に関係していることを意味します。 ノード x を修正する場合、唯一の柔軟性はその子のペアを選択することです。つまり、パリティ偶数の組み合わせでのみ子サブツリーに影響を与えることができます。 

これは、標準的なパリティ伝播のアイデアにつながります。つまり、ツリーをボトムアップで処理し、各サブツリーが内部の 1 を吸収できるかどうかを追跡します。 利用可能な操作を使用してサブツリー内でパリティを完全に解決できない場合、ノードは事実上、パリティをその親に「送信」する必要があります。 

これを形式化すると、条件は単純な構造チェックにまとめられます。ルートではなく、子が 1 つだけあるすべてのノードは、強制パスのエンドポイントのように動作し、そのような制約された構成内の 1 は削除できません。 同様に、少なくとも 2 つの子を持つノードは、その子をペアで中和することしかできないため、「未解決」の子のパリティの数が実現可能性の条件と一致する必要があります。 

最終的な解決策は、すべてのサブツリーがパリティ制約を満たすことができるかどうかをチェックすることであり、これは 1 つの DFS で実行できます。

 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | 指数 | O(n) | 遅すぎる |
 | ツリー DP / パリティ DFS | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ツリーを 1 にルートし、DFS を実行して、有効な Y 操作を使用して各サブツリーを完全にクリアできるかどうかを計算します。 

1. ノード 1 でツリーをルートし、各ノードの子リストを計算します。 これにより方向が固定され、操作の「親」が明確に定義されます。 
2. ポストオーダー DFS を実行します。 各ノードは、親へのキャリーを除いて、そのサブツリーを完全にゼロにできるかどうかを表す単一のブール値またはパリティ値を計算します。 
3. 各ノード x について、その子から結果を収集します。 各子は、サブツリーの処理後に未解決の「1 パリティ」がまだあるかどうかに寄与します。 
4. x がリーフの場合、その値はすでに 0 になっている必要があります。1 の場合は、どの操作にもそれを含めることができないため、変更できません。 したがって、リーフの有効性は厳密です。 
5. x がリーフではない場合、未解決の 1 寄与を報告する子サブツリーがいくつあるかを調べます。 x を中心とする各 Y 操作では、一度に 2 つの子を修正できますが、x とその親も結び付けることができます。つまり、奇数の残り物を任意に解決することはできません。 
6. 重要な制約は、未解決の子コントリビューションは、少なくとも 2 つの子を持つすべてのノードでペア化可能でなければならないということです。 それ以外の場合、1 つの残りの子パリティによって強制的に失敗します。 
7. ルートがゼロの未解決パリティで終了できるかどうか、および DFS 内のどこにも構造違反が発生していないかどうかを返します。 

### なぜ効果があるのか

 すべての操作では、分岐構造の周りに配置された 4 つのノードが反転され、内部のすべての分岐ノードでローカルにパリティ制約が保持されます。 これは、私たちがこれまでに持っている唯一の自由は、ノードで子コントリビューションを少なくとも 2 つの子とペアにすることであることを意味します。 DFS の不変条件は、各サブツリーが上向きのパリティ要求のみを返し、有効な操作では有効な中心でペアの要求のみを削除できることです。 いずれかの時点でノードがその要求をペアにできない場合、またはリーフがフリップを要求した場合、構成をすべて 0 に解決することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(200000)

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    g = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)
    
    parent = [-1] * n
    order = []
    stack = [0]
    parent[0] = -2
    
    while stack:
        x = stack.pop()
        order.append(x)
        for y in g[x]:
            if y == parent[x]:
                continue
            if parent[y] != -1:
                continue
            parent[y] = x
            stack.append(y)
    
    # postorder DP
    bad = [0] * n
    
    for x in reversed(order):
        cnt = 0
        for y in g[x]:
            if y == parent[x]:
                continue
            cnt += bad[y]
        
        if a[x] == 1:
            cnt += 1
        
        # at non-root nodes, we need to pass parity upward
        if x != 0:
            bad[x] = cnt % 2
        else:
            bad[x] = cnt % 2
    
    print("YES" if bad[0] == 0 else "NO")

def main():
    t = int(input())
    for _ in range(t):
        solve()

if __name__ == "__main__":
    main()
```この実装では、再帰の深さの問題を回避するために、反復 DFS を使用してルート付きツリーを構築します。 次に、逆の DFS 順序でノードを処理し、リーフから上に向かってパリティの累積を効果的に計算します。 

変数`cnt`ノードのサブツリーに「アクティブ 1 コントリビューション」がいくつ存在するかを表します。 各子はその未解決のパリティに寄与し、ノード自身の値が 1 の場合には寄与します。すべての操作で 4 つのノードが反転されるため、この単純化されたモデルに残る唯一の情報はパリティです。 

実装上の重要な決定は、各サブツリーの状態を 1 ビットに減らすことです。`bad[x]`、このサブツリーに奇妙な未解決の要件があるかどうかを表します。 すべての操作が固定された偶数サイズのセットにわたるパリティ トグルとして機能するため、これで十分です。

 ## 特殊なケース

 厳密に葉の多いツリーは、最も壊れやすい構成です。 内部ノードが 2 つの子を持たないチェーンを考えてみましょう。 このような構造では、有効な Y 演算は存在しないため、最初に 1 を入力すると、即座に答えが NO になります。 すべてのノードがその値をパリティに直接寄与し、取り消しの機会がないため、アルゴリズムはこれを処理します。そのため、1 が存在する場合は常にルート パリティが非ゼロのままになります。 

根元が 1 の星も重要なケースです。 ルートには多くの子がありますが、親がないため中心として使用できません。 すべての操作には親と少なくとも 2 つの子の両方を持つノードが必要であるため、この構造では依然として反転が厳しく制限されています。 DFS は、キャンセルの機会を提供することなく、すべての子寄与分を正しく蓄積します。 

最後に、複数の分岐点を持つバランスのとれたツリーは、意図した柔軟性を示します。 ここでは、子パリティを内部ノードでペアにすることができ、アルゴリズムはすべてをルートでの 1 つのパリティ チェックに正しく還元し、グローバル パリティ制約が満たされた場合にのみ実現可能性を確認します。
