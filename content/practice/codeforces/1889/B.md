 ## 解決策
 ## 問題の理解

 一連の都市が与えられ、各都市には人口を表す負でない重みが与えられます。 当初はどの都市間にも接続はありません。 目標は、最終的にすべての都市が単一の接続されたコンポーネントの一部になるように、エッジを徐々に追加できるかどうかを判断することです。 

問題は、2 つの都市間の境界が常に許可されるわけではないということです。 2 つの都市を接続できるかどうかは、少なくとも 1 つのエンドポイントを含む接続コンポーネント内の人口の合計に関する条件によって決まります。 都市 i と j を接続しようとすると、接続されたコンポーネントが結合されている現在すべての都市を調べ、それらの人口を合計し、この合計が少なくとも i · j · c である必要があります。 

重要な問題は、この状態がコンポーネントのマージ方法に動的に依存することです。 エッジが成功するたびに、将来のマージに使用できる合計が増加するため、プロセスは静的ではなく適応的になります。 

入力サイズは大きく、すべてのテスト ケースにわたって最大 2 · 10^5 都市です。 これにより、考えられるすべてのエッジを繰り返しシミュレートしたり、接続性を最初から再計算したりするアプローチは除外されます。 n = 2 · 10^5 の 1 つのテストでも約 4 · 10^10 のチェックが必要になるため、テスト ケースごとに O(n^2) に近いものは直ちに実行不可能になります。 

単純な解釈では、成長するグラフをシミュレートし、すべての可能なエッジを繰り返し試行する可能性があると考えられますが、各ステップでコンポーネントの合計を再計算する必要があるため、これは失敗します。 

さらに微妙な問題は、制約が積 i · j に依存することです。 これにより、強い順序付け圧力が生じます。大きなインデックスを含むエッジは、小さなインデックスを含むエッジよりも形成するのがはるかに困難です。 任意の有効なペアを接続する不用意な貪欲な戦略は、高価な接続で初期のマージを「無駄」にし、他の場所で必要な成長をブロックする可能性があるため、失敗する可能性があります。 

たとえば、高インデックス ノードのマージが早すぎると、まだ利用できない多額の費用が必要になり、たとえ別の順序が成功したとしても将来の接続が妨げられる可能性があります。 

## アプローチ

 ブルートフォース手法では、接続されたコンポーネントを繰り返し維持し、考えられるノード i と j のすべてのペアを試し、現在の合計条件でコンポーネントをマージできるかどうかを確認します。 マージが成功するたびに、共用体構造とコンポーネントの合計が更新されます。 ただし、O(n^2) 個の可能なエッジがあり、各チェックにはコンポーネントのクエリが含まれるため、このアプローチは非常に遅くなります。 

重要な観察は、実際には任意のエッジが必要ないということです。 制約 i · j · c はインデックスのみに依存し、現在の構造には依存しません。 i と j は固定されているため、各ノードはそのインデックスに応じて「接続コスト」を持つと考えることができますが、コンポーネントは a_i の合計によって累積的な「予算」を提供するだけです。 

問題は、制御されたマージ プロセスになります。私たちは、より実現可能なマージを解除し続ける方法でコンポーネントを拡張したいと考えています。 重要な洞察は、新しいノードを含めるためにコンポーネントを拡張することを決定した場合、常に、利用可能な最も安価なノードを最初にマージすることを優先する必要があるということです。これは、合計を早期に増やすと、将来のすべての制約が容易になるためです。 

これは、並べ替えベースの貪欲なアイデアにつながります。 制約は i · j とともに増大するため、インデックスが小さいほど接続が常に容易になります。 最小のインデックスから始めて徐々に成長するコンポーネントを構築し、各ステップで累積された合計が次のノードの接続に「支払う」のに十分であることを確認したいと考えています。

任意のエッジの観点から考える代わりに、成長するプレフィックスのようなコンポーネントを維持するものとしてプロセスを再解釈します。つまり、現在の合計で許容できる最小の残りのノードを接続しようと繰り返し試みます。 ある時点で次に必要なノードを接続できない場合、他の順序を選択しても将来のマージのコストが増加するだけであるため、他の順序付けも成功しません。 

したがって、問題をインデックスの昇順で次のノードを繰り返し選択し、現在の累積合計が接続要件を満たすかどうかを確認することに帰着します。

 ## アルゴリズムのチュートリアル

 1. ノードをインデックスでソートしますが、インデックスはすでに 1 ～ n であるため、直接昇順に処理します。 これは、小さいインデックスは弱い制約を課すため、最初に組み込む必要があるという事実を反映しています。 
2. 現在の接続コンポーネントの母集団合計の現在までの合計を維持します。 最初は最小のノードから開始するため、合計は a₁ になります。 
3. ノード 2 から n までを繰り返し、ノード i を既存のコンポーネントに接続しようとします。 
4. ノード i を接続するには、現在のコンポーネントの合計が、i を接続するための最悪の要求条件を満たすのに十分な大きさであるかどうかを確認します。 i が関与する接続は最終的に、コンポーネント内の既存の j に対して i · j · c を満たす必要があるため、最も制限的なケースは、コンポーネント内の最小のインデックス (最適な構築順序では常に 1) に接続することになります。 したがって、現在の合計が少なくとも i · c であるかどうかを確認します。 
5. 条件が満たされる場合、合計に a_i を追加することにより、ノード i をコンポーネントにマージします。 それ以外の場合は、接続は不可能であるとすぐに結論付けられます。 
6. すべてのノードが正常にマージされた場合は、YES が出力されます。 

### なぜ効果があるのか

 このプロセスは、構築が成功する場合、ノード i を追加する際のボトルネックは可能な限り早い接続であり、常に、成長するコンポーネント内にすでに最小のインデックスを持つノードへの接続であるという事実に基づいています。 i の追加を遅らせる代替戦略は、実現可能性を向上させることなく、将来必要な製品を増やすだけです。 これにより、単調な増加条件が作成されます。可能な限り最良のケースで i の合計が不十分になると、将来のすべてのノードはインデックスを増加させるだけであり、したがって要件が増加するため、将来のマージを再配置してもそれを修復できません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, c = map(int, input().split())
    a = list(map(int, input().split()))

    s = a[0]
    ok = True

    for i in range(1, n):
        if s < (i + 1) * c:
            ok = False
            break
        s += a[i]

    print("Yes" if ok else "No")
```実装は貪欲な構造に直接続きます。 現在の連結成分を表す単一の累計を維持します。 各ステップで、可能な最小限の接続要件の下で次のノードの追加が可能かどうかをテストします。 コードでは配列は 0 ベースですが、問題では 1 ベースであるため、使用されるインデックスは i + 1 です。 

唯一の微妙な点は、エッジを明示的にシミュレートする必要がないことに気づいたことです。 インデックスの昇順で順次接続すると仮定することで接続性が常に維持されるため、合計だけでも十分な状態となります。

 ## 特殊なケース

 重大なエッジ ケースは、初期のノードの値が極端に小さいかゼロである場合です。 後のノードに非常に大きな母集団が含まれている場合でも、最初のステップが初期しきい値を満たせない場合、アルゴリズムは直ちに失敗します。 たとえば、入力の場合`n=3, c=5, a=[0,0,100]`の場合、必要な値は将来の累積ではなくインデックス 2 に依存するため、プロセスは最初の遷移で停止します。 

値が大きいが c も大きい場合には、別の微妙なケースが発生します。 制約はインデックスに応じて線形に増加するため、均一に大きい配列であっても失敗する可能性があります。 例えば、`a=[10^12,10^12,10^12]`と`c=10^6`要件が 2・10^6 になり、後のステップで部分和がサポートできる範囲をすぐに超えてしまうため、i=2 で失敗します。 

これらのケースは、アルゴリズムの厳密な逐次実行可能性チェックがすべての不可逆的な失敗を正しく捕捉していることを確認します。
