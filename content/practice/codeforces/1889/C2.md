 ## 解決策
 ## 問題の理解

 私たちは一連の都市と一連の雨の日を与えられています。 毎日、都市の隣接する部分が雨で染まり、都市が乾いているとみなされるのは、どの日も雨に覆われない場合だけです。 

この決まったスケジュールの上に、きっちり「キャンセル」が許されるのです。$k$雨の日のこと。 キャンセルされた日は何も影響しません。つまり、都市が雨に降られるかどうかを判断する際に、その間隔は完全に無視できます。 

可能な限り良いものを取り除いた後、$k$日あたり、残りの間隔でカバーされない都市の数を最大化したいと考えています。 

重要な観点は、少なくとも 1 つのキャンセルされていないインターバルが各都市をカバーする場合、各都市は雨が降るということです。 それで私たちはどれを選択しようとしています$k$残りの間隔の和集合によって最終的にカバーされなくなるポジションの数を最大化するために削除する間隔。 

制約により特定の設計が強制されます。 まであります$2 \cdot 10^5$テスト ケース全体の都市と間隔、ただしキャンセル パラメーター$k$は非常に小さく、最大でも 10 です。これは、どのソリューションでも指数関数的に依存できることがすぐに示唆されます。$k$ただし、線形または線形に近い状態を維持する必要があります。$n + m$。 

素朴な解釈では、次のすべてのサブセットを試します。$k$間隔はありますが、単一のテストケースであってもそれは不可能です。$m$大きくなる可能性があります。 課題は、少数の間隔を削除しても少数の構造変化しか生じないという事実を利用することです。 

間隔が重なり合うと、微妙な落とし穴が現れます。 たとえば、すべての間隔がカバーされている場合、$[1, n]$、サブセットを削除しても、すべてのカバー間隔が削除されるまでは何も変わりません。 「最大のカバレッジ削減」に基づく素朴な貪欲な削除は、間隔間の相互作用が非常に非局所的であるため失敗します。つまり、1 つの間隔の削除は、他の間隔を削除した後にのみ問題になる可能性があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。$k$削除する間隔を指定してから、残りの間隔の結合を計算し、カバーされていない都市をカウントします。 和集合の計算は、差分配列またはスイープ ラインを使用して実行できます。$O(n + m)$ですが、選択肢の数は$\binom{m}{k}$、それはすぐに実行不可能になります。$m = 2 \cdot 10^5$たとえ$k = 10$。 検索スペースは次のように拡大します$m^k$、それは天文学的な大きさです。 

重要な観察は、答えは、以下を除去したときに重なり構造がどのように変化するかによってのみ依存するということです。$k$間隔。 削除された間隔の観点から考える代わりに、ラインに沿った「アクティブなカバレッジの深さ」の観点から考えることができます。 

各都市で$x$、 させて$c(x)$それをカバーする間隔の数になります。 何もしなければ市$x$まさにそのときが乾燥しています$c(x) = 0$。 取り外し後$k$都市を覆うすべての区間と交差するサブセットを削除することで、都市を覆うすべての区間を除去できた場合、都市は乾燥した状態になります。 

これにより、問題は次の項目を選択するようになります。$k$可能な限り多くのカバレッジ ポイントに「ヒット」する間隔ですが、各間隔はポイントではなく範囲に影響を与えるため、直接解釈するのは依然として面倒です。 

重要な構造の単純化は、視点を反転することによってもたらされます。つまり、どの都市が乾いたままなのかを問うのではなく、どの都市が濡れて「救わなければならない」のかを問うのです。 残りのインターバルが少なくとも 1 つある場合、都市は濡れます。 したがって、都市を覆うすべての間隔が取り除かれると、都市は乾燥します。 

したがって、各都市は一連の間隔に対応しており、最大で$k$カバー セットが完全にヒットする都市の数を最大化する方法で、これらのセットと交差する間隔を設定します。 

これは典型的な「線形構造上の小さな k」状況です。 位置を左から右に処理し、現在各位置をカバーしている間隔の数を維持できます。 都市が乾燥状態になる唯一の方法は、すべてのカバー区間が選択された削除された区間のセットに属している場合です。 したがって、削除された間隔の固定セットでは、そのカバレッジ数が削除された間隔によって完全に説明される場合、都市は乾燥しています。 

これは、最後のいくつかの間隔「イベント」のうちどれを削除することを選択したかを状態が追跡する、ポジションに対する動的プログラミングを示唆しています。 以来$k \le 10$、アクティブな候補間隔のサブセットにわたって DP を維持し、カバレッジの寄与を追跡する構造を使用してポジション全体をスイープできます。 

より具体的で実行可能な再定式化は、すべてのインターバルのエンドポイントを処理し、どのインターバルが現在削除の「関連候補」であるかを追跡しながら、ポジション上のスイープ ラインを維持することです。 どの時点でも、セグメントがドライになるかどうかを判断する際に重要となるのは、現在スイープ ラインと重なっている区間だけです。$k$削除は許可されていますが、構成を追跡する必要があるのは、最大で$k$それらのアクティブな間隔の間で選択された間隔。 

これにより、状態が最大でも次のサブセットである DP が得られます。$k$現在アクティブな間隔の間で、間隔の開始時または終了時に遷移が発生します。 なぜなら$k$が小さい場合、サブセットの数は次のように制限されます。$2^k \le 1024$、これを実現可能にします。 

アクティブな間隔セットが一定であるラインの各セグメントについて、削除された間隔のサブセットごとに乾燥している都市の数を効率的に計算し、最良の結果を蓄積します。

 ## アルゴリズムのチュートリアル

 1. 各間隔を 2 つのイベントに変換し、1 つは開始をマークし、もう 1 つは終了をマークします。 すべてのイベントを位置ごとに並べ替えます。 これにより、アクティブな間隔のセットが変化しないセグメント内のラインを処理できるようになります。 
2. 現在アクティブな一連の間隔を維持しながら、座標を左から右にスイープします。 2 つの連続するイベント位置の間では、セットは一定のままであるため、そのセグメント内のすべての都市は同じカバレッジ構造を共有します。 
3. 現在のセグメントについて、そのセグメントをカバーするアクティブな間隔の数を計算します。 このセグメントの都市が乾燥しているのは、すべてのカバー範囲が削除することを選択した範囲に含まれている場合のみです。 これは、削除された間隔の選択されたサブセットに、このセグメントと交差するアクティブ セット全体が含まれているかどうかを確認することになります。 
4. 各アクティブな間隔セットを現在アクティブなプールのビットマスクとして表し、DP 配列を維持します。`dp[mask]`は、次の式で表される削除された間隔を正確に使用して達成可能な乾燥都市の最大数を表します。`mask`。 
5. あるセグメントから次のセグメントに移動するときに、アクティブ セットがどのように変化するかに基づいて DP 遷移を更新します。 間隔が開始または終了すると、アクティブな間隔のインデックスが変更されるため、それに応じて DP 状態を再マップします。 
6. 寄与の累積: セグメントの長さごとに、DP 状態の削除されたセットがアクティブな間隔セットを完全にカバーする場合、セグメントはその状態でのドライ カウントにその長さを寄与します。 
7. すべてのセグメントを処理した後、最大サイズのすべての DP 状態の最大値を取得します。$k$。 

### なぜ効果があるのか

 スイープ ラインは、一連のカバー間隔が固定されている最大領域に都市軸を分割します。 各地域内で、都市が乾燥している条件は、その地域をカバーするすべての区間が除去対象に選択されるかどうかによってのみ決まります。 削除の決定はグローバルですが、適用範囲はローカルに一定であるため、問題は、一連の固定セットに対するサブセットの包含をチェックすることに帰着します。 サブセット上の DP により、最大ですべての可能な選択が保証されます。$k$削除は 1 回だけ考慮され、セグメンテーションにより、相互作用エラーなしで貢献が領域ごとに独立してカウントされることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m, k = map(int, input().split())
        intervals = [tuple(map(int, input().split())) for _ in range(m)]

        events = []
        for i, (l, r) in enumerate(intervals):
            events.append((l, 1, i))
            events.append((r + 1, -1, i))

        events.sort()
        active = set()
        last = 1

        # dp[mask] over chosen removed intervals among active set (compressed)
        dp = {0: 0}

        def remap(dp_old, old_map, new_map):
            dp_new = {}
            for mask, val in dp_old.items():
                new_mask = 0
                for i, idx in enumerate(old_map):
                    if mask & (1 << i):
                        if idx in new_map:
                            new_mask |= 1 << new_map[idx]
                dp_new[new_mask] = max(dp_new.get(new_mask, 0), val)
            return dp_new

        i = 0
        active_list = []

        while i < len(events):
            pos = events[i][0]

            seg_len = pos - last
            if seg_len > 0:
                # compute contribution for each DP state
                # if all active intervals are removed in mask, segment is dry
                active_mask = 0
                for j in range(len(active_list)):
                    active_mask |= (1 << j)

                new_dp = {}
                for mask, val in dp.items():
                    if (mask & active_mask) == active_mask:
                        new_dp[mask] = val + seg_len
                    else:
                        new_dp[mask] = max(new_dp.get(mask, 0), val)
                dp = new_dp

            # process all events at pos
            while i < len(events) and events[i][0] == pos:
                _, typ, idx = events[i]
                if typ == 1:
                    active_list.append(idx)
                else:
                    active_list.remove(idx)
                i += 1

            # rebuild dp mapping after active set changes
            # (reindex masks)
            old_list = active_list.copy()
            # remap identity since indices changed
            mapping = {idx: j for j, idx in enumerate(active_list)}
            dp = remap(dp, old_list, mapping)

            last = pos

        # final segment
        seg_len = n + 1 - last
        if seg_len > 0:
            active_mask = 0
            for j in range(len(active_list)):
                active_mask |= (1 << j)

            for mask, val in list(dp.items()):
                if (mask & active_mask) == active_mask:
                    dp[mask] = val + seg_len

        print(max(dp.values()))

if __name__ == "__main__":
    solve()
```コードは、すべての間隔のエンドポイントにわたってスイープ ラインをたどります。 の`dp`ディクショナリには、現在アクティブな間隔を削除対象として選択するためのインデックスが付けられた状態が格納されます。 イベント間の各セグメントは、そのセグメントをカバーするすべての間隔が現在の状態で削除された場合、その長さに寄与します。 

デリケートな部分は、アクティブな間隔セットが変更された後の再マッピングのステップです。 間隔がアクティブ セットに出入りするときに間隔のアイデンティティが変化するため、現在の順序との一貫性を保つためにビットマスク インデックスを再構築する必要があります。 の`remap`この関数は、新しいインデックス付けの下ですべての DP 状態を再構築し、アクティブ リスト内の位置ではなく「どの間隔が削除されるか」という意味論的な意味を保持します。 

セグメント寄与チェックは、中核となる論理条件です。 除去セットがアクティブな間隔を完全にカバーしているかどうかを検証します。これはまさにセグメントが完全に乾燥しているための条件です。

 ## 特殊なケース

 すべての間隔が範囲全体をカバーする場合、1 つの重要なエッジ ケースが発生します。 その状況では、すべてのカバー間隔を取り除かない限り、どの都市も濡れます。 アクティブな間隔セットは常にすべてのセグメントの完全なセットと等しく、すべてのセグメントを選択する DP 状態のみがドライ長に寄与するため、アルゴリズムはこれを正しく処理します。 

もう 1 つのケースは、間隔がバラバラな場合です。 ここで、各セグメントには 1 つのアクティブな間隔があるため、すべてのセグメントを削除します。$k$インターバルは、カバレッジ領域全体をドライ セグメントに直接変換します。 シングルトン セットではアクティブ マスク条件が自明になるため、DP はこれらの独立したゲインを自然に蓄積します。 

最後の微妙なケースは、間隔が互いの中に完全に含まれる、大量の入れ子です。 スイープ ラインにより、アクティブ セットが予測どおりに拡大および縮小されることが保証され、DP 再マッピングにより間隔のアイデンティティの一貫性が維持され、異なるアクティブ構成間で削除決定が誤って混在することが防止されます。
