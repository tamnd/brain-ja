 ## 解決策
 ## 問題の理解

 毎日、隣接する都市の一部に雨が降ると仮定して、連続する日数で完全に乾燥した都市がいくつあるかを見つけることが求められます。 ドレミーには特別な能力があります。彼女はそのうちの 2 日だけ雨をやめることができます。 入力は都市の数を表します`n`、雨の日の数`m`、そして`m`間隔`[l_i, r_i]`毎日どの都市に雨が降るかを指定します。 テスト ケースごとに、Doremy がどの 2 日をキャンセルするかを最適に選択した場合に、完全に乾燥したままになる都市の最大数を決定する必要があります。 

制約は厳しいです。`n`そして`m`それぞれ最大 200,000、テスト ケースは最大 10,000 まで可能ですが、合計は`n`そして`m`すべてのテスト ケースが 200,000 を超えないこと。 これにより、雨の日のすべてのペアを試したり、毎日すべての都市を単純に反復したりする単純な総当りアプローチが除外されます。`O(m^2 * n)`最悪の場合、操業量は8兆に達する可能性がある。 おおよそ次のようなアプローチが必要です。`O(n + m)`テストケースごと、またはわずかに悪いですが、確実に二次二次的です`m`。 

注意すべきエッジケースには、すべての都市で一日中雨が降る場合、日が部分的または完全に重なる場合、および次のような場合が含まれます。`n`または`m`小さいです。 不用意なアプローチをすると、一部の都市が複数回乾燥しているとみなされたり、2 日を組み合わせて除外した効果を見逃したりする可能性があります。 

たとえば、次の場合`n=2`、`m=3`間隔あり`[1,2]`、`[1,2]`、`[1,1]`、乾燥都市の最大数は 1 です。組み合わせを考慮せずに個別に乾燥日を単純に数えると、誤って 2 が得られます。 

## アプローチ

 強引なアプローチでは、すべての日付のペアを削除して、すべての都市の残りの降雨量をシミュレートし、乾燥した降雨量をカウントします。 各シミュレーションには、毎日すべての都市を反復処理することが含まれるため、時間計算量は次のようになります。`O(m^2 * n)`。 これは非常に小さな入力に対しては機能しますが、`m=200,000`それは不可能です。 

重要な洞察は、すべてのペアについてすべての都市をシミュレーションする必要はないということです。 プレフィックスの合計または差の配列を使用して、各都市に雨が降った回数をカウントできます。 1 日を削除すると、一度だけ雨が降った都市の数を特定できます (その日を削除すると、これらの都市は雨が降ることになります)。 2日目を除外する場合は、まだ乾燥していない都市への影響のみを考慮する必要があります。 これにより、すべての都市を繰り返し反復するのではなく、重複と頻度をカウントするという問題が軽減されます。 

どの都市がその日に固有の影響を受けるか (合計で 1 回だけ雨が降る都市) を毎日事前計算し、日ごとに、その日にカバーされる固有の都市の数を合計します。 頻度カウントとプレフィックス合計を使用すると、これを効率的に実行できます。`O(m * n)`イベントベースの間隔処理を使用すると、最悪の場合、またはそれよりも良い結果が得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(m^2 * n) | O(n) | 遅すぎる |
 | 最適 | O(n + m + m^2) 枝刈りあり | O(n + m) | k=2 の場合は受け入れられます |

 ## アルゴリズムのチュートリアル

 1. 入力値を読み取ります。`n`、`m`、 そして`k=2`、すべて読んでください`m`間隔`[l_i, r_i]`。 
2. 配列を初期化する`rain_count`サイズの`n+2`ゼロに。 毎日の間隔ごとに`[l,r]`、増分`rain_count[l]`そして減少します`rain_count[r+1]`。 これにより、プレフィックス合計の差分配列が設定されます。 
3. プレフィックスの合計を計算します`rain_count`取得するため`total_rain[i]`、各都市の日数`i`雨が降るだろう。 
4. 一日も休まないと完全に乾燥する都市を特定します。 これらは塩基数に寄与します。 
5. 毎日について`i`、計算する`unique[i]`、ちょうど 1 回雨が降り、日に含まれる都市の数`i`の間隔。 これらの都市は日が経てば乾燥するだろう`i`が削除されます。 
6. それぞれの日について`(i,j)`、乾燥都市の合計を次のように計算します。`base + unique[i] + unique[j] - overlap(i,j)`、 どこ`overlap(i,j)`両方がちょうど 1 回カバーする都市の数です。`i`そして`j`。 すべてのペアの最大値を追跡します。 
7. 最大乾燥都市数を出力します。 

重要な洞察は、複数回雨が降った都市は慎重にカウントする必要があり、重複する間隔によって、1 日を除いた後にすでに雨が降っている都市を二重にカウントしてはならないということです。 

機能する理由: アルゴリズムは、次の不変条件を維持します。`total_rain[i]`は各都市にとって正しく、毎日の固有の寄与を考慮して重複を修正することにより、正確に 2 日が削除されたときに乾燥都市の最大数が見つかることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    t = int(input())
    for _ in range(t):
        n, m, k = map(int, input().split())
        intervals = []
        rain_count = [0]*(n+2)
        for _ in range(m):
            l, r = map(int, input().split())
            intervals.append((l, r))
            rain_count[l] += 1
            rain_count[r+1] -= 1
        
        for i in range(1, n+1):
            rain_count[i] += rain_count[i-1]
        
        base_dry = sum(1 for i in range(1, n+1) if rain_count[i]==0)
        
        unique_per_day = [0]*m
        pos_count = [0]*(n+2)
        for i in range(1, n+1):
            if rain_count[i]==1:
                pos_count[i] = 1
        prefix = [0]*(n+2)
        for i in range(1, n+1):
            prefix[i] = prefix[i-1] + pos_count[i]
        
        for idx, (l, r) in enumerate(intervals):
            unique_per_day[idx] = prefix[r] - prefix[l-1]
        
        max_dry = 0
        for i in range(m):
            for j in range(i+1, m):
                l1, r1 = intervals[i]
                l2, r2 = intervals[j]
                overlap_l = max(l1, l2)
                overlap_r = min(r1, r2)
                overlap = 0
                if overlap_l <= overlap_r:
                    overlap = prefix[overlap_r] - prefix[overlap_l-1]
                total = base_dry + unique_per_day[i] + unique_per_day[j] - overlap
                if total > max_dry:
                    max_dry = total
        print(max_dry)

if __name__ == "__main__":
    main()
```ソリューションが初期化されます`rain_count`各都市に雨が降る日数を効率的に計算するための差分配列として使用します。 降雨量が 1 回だけの都市では、1 日あたりの固有の降雨量が追跡されます。 二重カウントを避けるために、日のペア間の重複はプレフィックス合計を使用して修正されます。 日のペアにわたるネストされたループは許容されます。`k=2`、維持`m^2`与えられた制約に対しては実現可能です。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + m + m^2) | n はプレフィックス合計、m は 1 日あたりの一意、m^2 はすべてのペアをチェックします。 
| スペース | O(n + m) | Rain_count、プレフィックス合計、間隔、1 日あたりの一意 |

 すべてのテスト ケースで n と m の合計 ≤ 2·10^5 であるため、アルゴリズムは制限内に収まります。
