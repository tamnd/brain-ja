 ## 解決策
 ## 問題の理解

 私たちには、人々が頂点、友情が辺である単純な無向グラフが与えられています。 有効なパーティとは、正確に 5 つの異なる頂点の選択であり、これら 5 つの頂点上に誘導されたサブグラフはエッジが完全に空か完全に満たされており、これは 5 頂点の独立したセットまたは 5 クリークであることを意味します。 

タスクは、そのようなセットが存在する場合にそれを見つけること以上に何かを最適化することではありません。複数の有効なセットが存在する場合は、どれでも受け入れられます。 

制約は頂点とエッジの点で大きく、両方とも最大 200,000 です。 これにより、頂点の 5 つのサブセットをすべて列挙しようとするアプローチは即座に除外されます。$\binom{N}{5}$、これは実現可能な限界をはるかに超えています。 隣接するトリプルまたは 4 つをすべて直接チェックしても、密な場合は遅すぎます。 

制約の構造は、エッジの数が線形であるため、グラフが平均してまばらであることを示唆しています。$N$。 これは通常、グローバルな組み合わせ列挙ではなく、貪欲な構築または隣接リストのローカル検索を指します。 

空のグラフなど、グラフが非常にまばらな場合、微妙なエッジ ケースが発生します。 その場合、任意の 5 つの頂点が有効な独立セットを形成します。 最初にクリークを見つけようとする単純なアルゴリズムは、独立集合の場合を対称的に考慮しない場合、不必要に失敗する可能性があります。 

もう 1 つのエッジ ケースはスター グラフです。 たとえば、1 つの中心が他のすべての頂点に接続されているとします。 アルゴリズムが注意せずに貪欲に独立セットを構築すると、葉の間にサイズ 5 の独立セットが明らかに存在する場合でも、誤って中心を早期に選択して、さらなる成長を妨げる可能性があります。 

最後に、疎なグローバル グラフ内にも密なローカル構造が存在する可能性があります。 たとえば、アルゴリズムが貪欲な独立性構築のみに依存している場合、大きな疎グラフに埋め込まれたサイズ 5 のクリークが見逃される可能性があります。 

## アプローチ

 直接的な総当たりソリューションでは、すべての 5 頂点のサブセットをチェックし、それがクリークを形成しているか独立したセットを形成しているかを検証しようとします。 隣接関係がハッシュ セットに保存されている場合、各チェックには一定の時間がかかりますが、サブセットの数は$\Theta(N^5)$、これはおおよそ次のことにつながります$10^{25}$最悪の場合、手術は完全に不可能になります。 

より合理的な総当たりのアイデアは、頂点を修正し、その隣接頂点と非隣接頂点間の組み合わせをテストすることで、有効な 5 セットに拡張しようとすることです。 これは、特に次数が大きい場合、最悪の場合、3 次または 4 次の動作にまで縮退します。 

重要な観察は、任意の構造を検索する必要がないということです。 単一の 5 クリークまたは単一の 5 独立セットのみが必要です。 これにより、2 つの構造のうちの 1 つに対して貪欲な構築を試みることができます。 

まず、貪欲に最大の独立集合を構築することを試みます。 頂点を反復処理し、S 内の 2 つの頂点が接続されないように集合 S を維持します。 頂点を検討するたびに、S 内の既存の頂点にエッジがない場合は頂点を追加します。必要な頂点は 5 つだけであるため、S がサイズ 5 に達したら早めに停止します。 

これが成功すれば完了です。 

それが失敗した場合、つまりサイズ 5 に到達できない場合、S のサイズは最大でも 4 となり、独立性に関しては最大になります。 これは、残りのすべての頂点が S の少なくとも 1 つの頂点に隣接していることを意味します。この構造的制約により、S の周りのエッジの強力なクラスタリングが強制され、これを利用して、共通の近傍と交差点に焦点を当てることでサイズ 5 のクリークを見つけることができます。 

特に、S によって強く制約されている頂点を調べ、近傍によって誘導された小さな候補セットをチェックすることによって 5 クリークの構築を試みます。 S が小さいため、これにより検索スペースが管理可能なサイズに縮小されます。

 ## アルゴリズムのチュートリアル

 ### 独立したセットの構築

 1. 高速エッジチェックのための隣接セットを構築します。 
2. 空のリスト S を初期化します。 
3. 1 から N までのすべての頂点を繰り返します。 
4. 各頂点 v について、すでに S にある頂点へのエッジがあるかどうかを確認します。 
5. そのようなエッジがない場合は、S に v を追加します。 
6.Sがサイズ5に達したらすぐに停止します。 

これが機能する理由は、S が独立集合であるという不変条件を明示的に維持しているためです。 既存のすべてのメンバーと照合するため、追加するたびに独立性が維持されます。 

### 貪欲フェーズの失敗の処理

 1. S がすでにサイズ 5 を持っている場合は、S を出力して終了します。 
2. それ以外の場合、S のサイズは最大 4 で最大になります。 
3. S にないすべての頂点 u は、S の少なくとも 1 つの頂点に隣接している必要があります。そうでない場合は、それを S に追加できます。 

この最大条件は、ソリューションの構造的な要点です。 これは、非 S 頂点が S に接続する方法を制限し、S への隣接性によって残りのグラフの分割を強制します。 

### 派閥を探す

 1. S の各頂点 v について、その近傍を考慮します。 
2. これらの近傍の中で、ペアで接続され、v にも接続されている 4 つの頂点を見つけようとします。 
3. このような選択は v とともに 5 クリークを形成します。 

近傍内のみを検索する必要がある理由は、v を含むクリークはすべてその隣接リスト内に完全に存在する必要があるためです。 S が小さいため、これらの制約された近傍によって引き起こされるすべての合理的な組み合わせを試しますが、これはまばらさと早期停止により実現可能です。 

## なぜ機能するのか

 このアルゴリズムは、サイズ 5 の貪欲な独立セットが存在するか、またはグラフが最大サイズ 4 の最大独立セットによって構造的に制約されるかのどちらかという二分法に依存しています。 後者の場合、S の外側のすべての頂点は S に接続する必要があり、近傍に重複が作成され、S 内のいくつかの頂点の周囲に密な局所サブグラフが強制されます。この密度こそが、グラフ全体ではなく近傍セットの交差に焦点を当てて 5 クリークを抽出できるものです。 

正しさは、考えられる 2 つの極限構造、つまり、クリークにつながる大きな独立した集合または強制的な密集近傍のみを徹底的にカバーすることによって得られます。

import sys
input = sys.stdin.readline

N, M = map(int, input().split())

adj = [set() for _ in range(N + 1)]

for _ in range(M):
    u, v = map(int, input().split())
    adj[u].add(v)
    adj[v].add(u)

S = []

for v in range(1, N + 1):
    ok = True
    for u in S:
        if u in adj[v]:
            ok = False
            break
    if ok:
        S.append(v)
        if len(S) == 5:
            print(*S)
            sys.exit(0)

if len(S) == 5:
    print(*S)
    sys.exit(0)

Sset = set(S)

# try to find clique of size 5
# since S is small, we use it as anchors
cand = S[:]

# also try neighbors of S vertices
for v in S:
    for u in adj[v]:
        if u not in Sset:
            cand.append(u)

cand = list(set(cand))

# brute small candidate set
K = len(cand)

# precompute adjacency check
def good_clique(nodes):
    for i in range(len(nodes)):
        for j in range(i + 1, len(nodes)):
            if nodes[j] not in adj[nodes[i]]:
                return False
    return True

from itertools import combinations

for comb in combinations(cand, 5):
    if good_clique(comb):
        print(*comb)
        sys.exit(0)

print(-1)

第 2 フェーズは、貪欲なプロセスが失敗した場合にのみアクティブになります。これは、独立した構造が制約されすぎていることを意味します。 次に、サイズ 5 のクリークが高度に接続された頂点の周囲に局所的に表示される必要があるため、小さな集合 S の周囲に候補プールを拡張します。 最大限の独立性によって引き起こされる制約の下では、候補セットは実際には小さいままであるため、組み合わせに対するブルートフォースは安全です。 

隣接セットのルックアップにより、クリーク検証の高速性が確保され、大規模な隣接リストの繰り返しスキャンが回避されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    from itertools import combinations

    N, M = map(int, sys.stdin.readline().split())
    adj = [set() for _ in range(N + 1)]
    for _ in range(M):
        u, v = map(int, sys.stdin.readline().split())
        adj[u].add(v)
        adj[v].add(u)

    S = []
    for v in range(1, N + 1):
        ok = True
        for u in S:
            if u in adj[v]:
                ok = False
                break
        if ok:
            S.append(v)
            if len(S) == 5:
                return " ".join(map(str, S))

    if len(S) == 5:
        return " ".join(map(str, S))

    Sset = set(S)
    cand = S[:]
    for v in S:
        for u in adj[v]:
            if u not in Sset:
                cand.append(u)
    cand = list(set(cand))

    def good(nodes):
        for i in range(len(nodes)):
            for j in range(i + 1, len(nodes)):
                if nodes[j] not in adj[nodes[i]]:
                    return False
        return True

    for comb in combinations(cand, 5):
        if good(comb):
            return " ".join(map(str, comb))

    return "-1"

 ## 特殊なケース

 完全に空のグラフは、貪欲な独立セット フェーズによってきれいに処理されます。 すべての頂点は他のすべての頂点と互換性があるため、最初に見つかった 5 つの頂点はすぐに受け入れられ、フォールバック ロジックを呼び出すことなく有効な独立したセットが生成されます。 

1 つの中心が他のすべてに接続されているスター グラフが処理されるのは、貪欲なプロセスにより、いくつかの葉を選択した後に中心を選択することが自然に回避されるためです。 リーフは互いに隣接していないため、独立したセットは干渉することなくサイズ 5 まで成長します。 

5 クリークが存在するが、初期の頂点を中心にしていないグラフは、フォールバック ステージで処理されます。 独立セットがサイズ 5 に達しないと、S の周りの候補拡張により、密な構造に参加する頂点が検索空間に確実に含まれるようになり、組み合わせチェックを通じてクリークを発見できるようになります。
