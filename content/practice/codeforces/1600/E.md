 ## 解決策
 ## 問題の理解

 一列に並べられた数値の配列が与えられます。 2 人のプレイヤーがアリスから順番に順番を変えていきます。 各移動で、プレイヤーは残っている左端または右端の要素を削除し、構築中のシーケンスに追加します。 唯一の制限は、結果として得られるシーケンスが移動のたびに厳密に増加し続けなければならないことです。 最後に有効な動きをしたプレイヤーが勝ちます。 

このゲームはスコアを最大化することではなく、単調な制約の下で生き残ることが重要です。 次に選択される値は、これまでに選択されたすべての値より厳密に大きくなければならないため、選択するたびに 1 つのエンドポイントが削除され、今後許可される移動が制限されます。 

制約$N \le 2 \cdot 10^5$状態空間の探索は直ちに除外されます。 単純なゲーム ツリーには分岐要素 2 と最大の深さがあります。$N$、につながる$2^N$完全に不可能な状態です。 最後に選択された値の状態追跡を伴う間隔にわたるメモ化された動的プログラミングであっても、最後の値は小さくなく、連続範囲の履歴に依存するため、問題があります。 

いくつかの小さなエッジケースがすでに構造を示唆しています。 

たとえば、すべての要素が等しい場合、$A = [5, 5, 5]$、5 を選択した後は、厳密にそれ以上の要素が存在しないため、1 つの移動のみが可能です。 ゲームは最初の動きの直後に終了するため、アリスが勝ちます。 

配列が厳密に増加している場合は、次のようにします。$A = [1,2,3,4]$、すべての動きは左または右から選択することを強制されますが、両端が常に昇順を維持するため、どの選択も有効です。 ゲームは戦略ではなく、純粋に残りの手の同等性を重視します。 

貪欲な直感が微妙に失敗するケースは、ローカルな選択によって将来の柔軟性が異なる形で維持される場合に現れます。 たとえば、より小さい終了値を取得することは、シーケンスを継続するために必要な大きな値への将来のアクセスをブロックする可能性があるため、常に最適であるとは限りません。 

## アプローチ

 ブルートフォースアプローチでは、考えられるすべてのゲームをシミュレートします。 各状態で、現在のサブ配列を考慮します。$[l, r]$最後に選択された値。 どちらかの端を選択し、その値が最後に選択した値より大きい場合、移動は有効です。 現在のプレイヤーが勝利を強制できるかどうかを再帰的に判断します。 これはゲームを正しくモデル化していますが、状態の数は指数関数的に増加します。$N$、さらにはメモ化による圧縮も可能$(l, r, last)$は実現不可能です。`last`までの任意の値を取ります$10^9$、状態爆発が避けられなくなります。 

重要な観察は、最適なプレイには、現在の境界以上のことや、シーケンスがどのように展開するかについての方向性の偏りを記憶する必要が決してないということです。 移動するたびにエンドポイントが削除されるため、プロセスは増加する制約を尊重しながらプレイ可能な間隔がどのように短縮されるかによって完全に制御されます。 重要な構造的事実は、プレイヤーが値を選択すると、その後のすべての有効な手は厳密にその値の上になければならず、どちらの側が有用であり続けるかを強く制限するということです。 これにより、ゲームは強制セグメントを使用した決定論的な縮小プロセスに縮小されます。ここで唯一の実際の決定は、左または右の選択がより長い有効な継続を維持するかどうかです。 

ゲームの状態を調査する代わりに、最適なプレイの下で常に小さい有効なエンドポイントを取得した場合に、連続した強制移動が何回実行できるかを追跡します。 ゲームは制御を交互に行いますが、その構造により、合計の手数は、増加する条件によって強制終了されるまでに、この欲張りな一貫性のあるプロセスがどれだけ継続するかによってのみ依存します。 

これにより、問題は 2 ポインタ プロセスのシミュレーションに変換され、プレイヤーは実現可能性を維持するより小さい有効なエンドポイントを交互に選択し、勝者は手の同等性によって決定されます。

 ## アルゴリズムのチュートリアル

 私たちは 2 つの指針を維持します。$l$そして$r$、最初は配列の端にあります。 また、最初に負の無限大に設定された、最後に選択された値も追跡します。 ブール値のフラグは誰の順番を追跡しますが、重要な考え方は、両方のプレイヤーが同じ最適なルールに従うため、結果として生じる強制プレイのみをシミュレートすることです。 

1.初期化$l = 0$、$r = N - 1$、 そして`last = -∞`。 移動カウンタを 0 に設定します。 
2. 各ステップで、次の中で有効な候補を検討します。$A[l]$そして$A[r]$厳密にそれよりも大きい`last`。 どちらも有効でない場合、ゲームは停止します。 
3. 両端が有効な場合は、2 つの値のうち小さい方を選択します。 これにより、より小さい値を選択すると、厳密に増加するプロパティを維持するために使用できる将来のオプションが増えるため、柔軟性が維持されます。 
4. 片方の端のみが有効な場合は、その端を選択します。 
5.アップデート`last`選択した値に設定し、対応するポインタを内側に移動し、移動カウンタをインクリメントします。 
6. 有効な動きがなくなるまで繰り返します。 
7. 合計の手数が奇数の場合、アリスが最後の手を行いました。 それ以外の場合はボブがそうしました。 

常に小さい有効なエンドポイントを選択する背後にある理由は、初期に大きな値を選択しても、将来の有効な拡張機能のセットを減らすだけで、増やすことはできないということです。 唯一の目標は総移動数を最大化することなので、両方のプレイヤーはこの貪欲な行動に一致します。 

### なぜ効果があるのか

 どの瞬間でも、ゲームの状態は間隔によって完全に決定されます。$[l, r]$最後に選択された値。 有効な移動は間隔サイズを 1 つ減らし、将来の許容値の下限を増やします。 2 つのエンドポイントのうち、小さい方の実現可能値を選択すると、その後の移動に対する弱い制約が維持されるため、将来の実現可能性の点で大きい方の値が優先されます。 これは、プレイヤーが逸脱することで利益を得られない状態の単調な展開を引き起こします。逸脱するたびに、残りの手数が減少するか、変更されないままになりますが、対戦相手に同じかそれ以上のポジションを与えます。 したがって、貪欲なシミュレーションにより、最適なプレイの下で正確な手数が得られ、勝者はパリティによって決定されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    l, r = 0, n - 1
    last = -10**18
    moves = 0

    while l <= r:
        left = a[l] if l <= r else None
        right = a[r] if l <= r else None

        valid_left = left is not None and left > last
        valid_right = right is not None and right > last

        if not valid_left and not valid_right:
            break

        if valid_left and valid_right:
            if left < right:
                last = left
                l += 1
            else:
                last = right
                r -= 1
        elif valid_left:
            last = left
            l += 1
        else:
            last = right
            r -= 1

        moves += 1

    print("Alice" if moves % 2 == 1 else "Bob")

if __name__ == "__main__":
    solve()
```コードは縮小間隔を維持し、次の方法で増加する制約を強制します。`last`。 各反復では貪欲なルールに従って 1 つの手を正確に解決し、ゲーム全体の線形シミュレーションを保証します。 のパリティ`moves`アリスが最初にスタートするため、勝者が直接決まります。 

共通の微妙な点は厳密な不平等です`> last`。 使用する`>=`誤って同等の要素を許可し、ゲームを人為的に拡張することになります。

 ## 特殊なケース

 すべての値が等しい配列の場合、後続の値が厳密に より大きい値がないため、アルゴリズムはただちに 1 つの要素を取得して終了します。`last`。 1手で間合いが崩れ、アリスが勝者となります。 

次のような厳密に減少する配列の場合`[5,4,3,2,1]`、貪欲ルールは、有効な場合にのみ常に大きい方の端を取得します。これは 1 回だけ発生します。 最初の動きの後、残りの要素は選択された値を超えないため、ゲームはすぐに終了し、再びアリスが勝者となります。 

厳密に増加する配列の場合、両端はすべてのステップで有効なままですが、アルゴリズムは要素が枯渇するまで一貫して要素を削除します。 これにより、次の決定的なシーケンスが作成されます。$N$が動き、勝者は同等性のみに依存し、次の場合にボブが勝ちます。$N$は均等です。
