 ## 解決策
 ## 問題の理解

 インデックスの順序付けされた 4 倍ごと ((x,y,z,w)) について、2 つの値が形成されます。 まずは普通の金額です

 [
 S=a_x+a_y+a_z+a_w、
 】

 2 番目はビット単位の XOR です。 

[
 X=b_x\oplus b_y\oplus b_z\oplus b_w。 
】

 この 4 倍の寄与は (S^X) であり、必要な答えは、そのような寄与をすべて (n^4) 法で合計したものです (998244353)。 公式問題では、まさにこのべき乗式が使用されています。 

配列には最大 (10^5) 個の要素が含まれますが、すべての (a_i) と (b_i) は最大で (500) 個です。 値 (n=10^5) は、インデックスの列挙ペア、トリプル、または 4 倍に近いものを直ちに除外します。 特に、直接列挙では、最悪の場合、(10^{20}) 回の反復が実行されます。 (O(n^2)) メソッドであっても、すでに (10^{10}) 個の操作が含まれており、3 秒の制限をはるかに超えています。 ただし、(500) という小さな値の境界は、制約の有用な部分です。 すべての (b_i) が 9 ビットに収まるため、4 つの (a) 値のすべての合計は (4) と (2000) の間にあり、4 つの (b) 値のすべての XOR は (0) と (511) の間にあります。 

よくある間違いを明らかにするいくつかの特殊なケースがあります。 まず、指数はゼロになる可能性があります。 例えば、```
1
500
500
```には 4 倍数が 1 つだけあり、その XOR は (500\oplus500\oplus500\oplus500=0) です。 その寄与は (2000^0=1) なので、答えは次のようになります。`1`。 指数ゼロを誤ってゼロを生成するものとして扱うソリューションは、ここで失敗します。 

第 2 に、(500) で囲まれた 4 つの値の XOR は、それ自体が最大 (500) である必要はありません。 たとえば、(512) より下の値は、任意の 9 ビットの結果を生成できます。 のみの変換`500`または`501`XOR 位置は安全ではありません。 正しいサイズは(512)です。 

3 番目に、インデックスは順序付けされており、再利用できます。 のために```
2
1 2
1 2
```単に 4 つの選択された要素の順序付けされていないマルチセットではなく、(2^4=16) 個の順序付けされた 4 つ組が存在します。 正しい答えは、`3088`。 周波数ベースのソリューションでは多重度を維持する必要があり、これがまさに畳み込みの機能です。 

## アプローチ

 ブルートフォース ソリューションは文字通り定義に従います。 すべての (x)、(y)、(z)、および (w) について、4 要素の合計を計算し、4 要素の XOR を計算し、べき乗を評価して、それを答えに加算します。 これは正しいです。なぜなら、考えられるすべての順序付けされた 4 倍数が 1 回だけ現れるからです。 問題は 4 倍体の数です。(n=10^5) の場合、(n^4=10^{20}) 個あります。 このアプローチは単に少し遅すぎるだけでなく、実現可能性から何桁も離れています。 

有益な観察は、(x,y,z,w) の合計と XOR が分かれば、個々の ID はもはや重要ではないということです。 1 つの配列要素をペア ((a_i,b_i)) で表すことができ、考えられるすべてのペアを生成する要素の数を数えます。 2 つの要素を結合すると、最初の座標が加算され、2 番目の座標が XOR されます。 4 つの要素を組み合わせると、これら 2 つの操作で正確に 4 つの畳み込みが行われます。 

2 つの操作には異なる標準変換があります。 最初の座標の通常の加算は多項式畳み込みによって処理されます。必要な係数が (998244353) という NTT に適した素数であるため、数論変換は特にうまく機能します。 2 番目の座標の XOR 演算は、高速ウォルシュ アダマール変換によって処理されます。 FWHT は、通常のフーリエ変換が通常の畳み込みを点ごとの乗算に変換するのと同じように、XOR 畳み込みを点ごとの乗算に変換します。 

重要な簡素化は、2 つの畳み込みを明示的に実行する必要がないことです。 2 次元の周波数配列 (F[s][x]) を構築します。ここで、(F[s][x]) は (a_i=s) および (b_i=x) を使用して入力要素をカウントします。 4 倍は、最初の座標での通常の加算と 2 番目の座標での XOR による (F) の 4 倍の畳み込みです。 

合計座標に沿って NTT を適用し、XOR 座標に沿って FWHT を適用します。 両方の変換の後、4 倍の畳み込みは、単純に各変換値の 4 乗になります。 次に、逆変換を適用し、考えられるすべての合計と XOR の 4 倍の数を取得します。 最後に、各状態 ((s,x)) に対して、次を追加します。 

[
 F_4[s][x]\cdot s^x。 
】

 最大 (500) の 4 つの値の合計は最大 (2000) であり、(2048) は次の 2 のべき乗であるため、合計座標には長さ (2048) が必要です。 循環ラップアラウンドは発生しません。 XOR 座標には長さ (512) が必要です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(n^4)) | (O(1)) | 遅すぎる |
 | 最適 | (O(2048\cdot512(\log2048+\log512))) | (O(2048\cdot512)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 頻度表 (F[s][x]) を作成します。ここで (s) は次の (a) 値です。`0`を通して`500`そして (x) は次の (b) 値です。`0``511 まで)。 入力位置 (i) ごとに、(F[a_i][b_i]) を増分します。 これにより、すべて (n) 個の要素が (501\cdot512) 個の可能な状態のみに圧縮されます。 
2. 最初の座標を多項式の次数として、2 番目の座標を XOR インデックスとして扱います。 2 つの状態を結合する操作は次のとおりです。 

(s_1+s_2,\ x_1\oplus x_2)。 
】

 したがって、選択された 4 つの入力要素は、(\star) の下での (F) の 4 重畳み込みに正確に対応します。 

1. 合計次元をゼロ埋めします。`2048`そして、すべての固定 XOR 座標に独立して NTT を適用します。 4 つの合計が達する可能性があるため、パディングが必要です`2000`、および長さ`2048`多項式の畳み込みが回り込むのを防ぎます。 
2. 固定の変換された合計座標ごとに、FWHT を適用します。`512`XOR 状態。 この操作の後、両方の次元は畳み込みに適した形式になります。 通常の NTT は和の加算を処理しますが、FWHT は XOR を処理します。 
3. 変換されたすべてのエントリを 4 乗モジュロ (998244353) に上げます。 変換された領域での点単位の乗算は元の領域での畳み込みを表すため、4 乗は 4 つの順序付けされた要素を選択し、それらの合計と XOR を結合することを表します。 
4. XOR 次元に沿って逆 FWHT を適用し、合計次元に沿って逆 NTT を適用します。 結果のテーブル (C[s][x]) には、合計 (a)-sum が (s) で、合計 (b)-XOR が (x) である順序付けされた 4 倍の数が正確に含まれます。 
5. 到達可能なすべての (s) と (x) に対して、次を追加します。 

[
 C[s][x]\cdot s^x
 】

 答えに。 指数は最大でも`511`したがって、べき乗剰余を 100 万回呼び出す代わりに、固定値のべき乗を反復的に生成できます。 

### なぜ効果があるのか

 不変条件は、元のテーブルが配列要素の 1 つの選択肢を表し、((+,\oplus)) の畳み込みが独立した選択肢の組み合わせを表すことです。 したがって、4 回の畳み込みの後、(C[s][x]) は、正しい多重度で繰り返されるインデックスと繰り返し値を含む、結合された合計 (s) と結合された XOR (x) を使用して、順序付けされたすべての 4 つ組をカウントします。 

NTT は通常の和畳み込みを点ごとの乗算に変換し、FWHT は XOR 畳み込みを点ごとの乗算に変換します。 したがって、両方の変換を同時に適用すると、4 倍の畳み込みが 4 乗に変換されます。 逆変換は必要なカウントを正確に回復するため、各カウントを (s^x) で乗算し、すべての状態を合計すると、要求された答えが得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353
G = 3

SUM_N = 2048
XOR_N = 512
LOG_SUM = 11
LOG_XOR = 9

INV_SUM_N = pow(SUM_N, MOD - 2, MOD)
INV_XOR_N = pow(XOR_N, MOD - 2, MOD)

# Bit-reversal permutation for the length-2048 NTT.
REV = [0] * SUM_N
for i in range(1, SUM_N):
    REV[i] = (REV[i >> 1] >> 1) | ((i & 1) << (LOG_SUM - 1))

ROOTS = []
INV_ROOTS = []

length = 2
while length <= SUM_N:
    root = pow(G, (MOD - 1) // length, MOD)
    ROOTS.append(root)
    INV_ROOTS.append(pow(root, MOD - 2, MOD))
    length <<= 1

def ntt(a, invert):
    n = len(a)

    for i in range(n):
        j = REV[i]
        if i < j:
            a[i], a[j] = a[j], a[i]

    roots = INV_ROOTS if invert else ROOTS

    length = 2
    stage = 0

    while length <= n:
        half = length >> 1
        root = roots[stage]

        for start in range(0, n, length):
            w = 1
            end = start + half

            for j in range(start, end):
                u = a[j]
                v = a[j + half] * w % MOD

                a[j] = (u + v) % MOD
                a[j + half] = (u - v) % MOD

                w = w * root % MOD

        length <<= 1
        stage += 1

    if invert:
        for i in range(n):
            a[i] = a[i] * INV_SUM_N % MOD

def fwht_row(row, invert):
    length = 2

    while length <= XOR_N:
        half = length >> 1

        for start in range(0, XOR_N, length):
            end = start + half

            for j in range(start, end):
                u = row[j]
                v = row[j + half]

                row[j] = (u + v) % MOD
                row[j + half] = (u - v) % MOD

        length <<= 1

    if invert:
        for i in range(XOR_N):
            row[i] = row[i] * INV_XOR_N % MOD

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    # data[s * XOR_N + x] is the frequency of the state (s, x).
    data = [0] * (SUM_N * XOR_N)

    for ai, bi in zip(a, b):
        pos = ai * XOR_N + bi
        data[pos] += 1

    # NTT in the sum dimension.
    # We extract each XOR column, transform it, then put it back.
    column = [0] * SUM_N

    for x in range(XOR_N):
        for s in range(SUM_N):
            column[s] = data[s * XOR_N + x]

        ntt(column, False)

        for s in range(SUM_N):
            data[s * XOR_N + x] = column[s]

    # FWHT in the XOR dimension.
    for s in range(SUM_N):
        row_start = s * XOR_N
        row = data[row_start:row_start + XOR_N]

        fwht_row(row, False)

        # Four selected elements correspond to the fourth power.
        for x in range(XOR_N):
            v = row[x]
            v2 = v * v % MOD
            row[x] = v2 * v2 % MOD

        data[row_start:row_start + XOR_N] = row

    # Inverse FWHT.
    for s in range(SUM_N):
        row_start = s * XOR_N
        row = data[row_start:row_start + XOR_N]

        fwht_row(row, True)

        data[row_start:row_start + XOR_N] = row

    # Inverse NTT in the sum dimension.
    for x in range(XOR_N):
        for s in range(SUM_N):
            column[s] = data[s * XOR_N + x]

        ntt(column, True)

        for s in range(SUM_N):
            data[s * XOR_N + x] = column[s]

    # Evaluate sum C[s][x] * s^x.
    ans = 0

    for s in range(1, 2001):
        row_start = s * XOR_N
        row = data[row_start:row_start + XOR_N]

        power = 1

        for x in range(XOR_N):
            ans = (ans + row[x] * power) % MOD
            power = power * s % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```の最初の部分`solve`入力から直接頻度テーブルを構築します。 私たちが使用するのは`ai * XOR_N + bi`フラットなインデックスとして使用されるため、2 次元配列全体が 1 つの Python リストにコンパクトに格納されます。 

最初の変換ループは XOR 値を修正し、すべての可能な合計に対して NTT を実行します。 まさにあります`512`このような列のそれぞれの長さ`2048`。 NTTはプリミティブルートを使用しています`3`、これは係数 (998244353) に適しています。 

次に、FWHT ループが各合計座標を処理します。 その基本的な操作は、ペア ((u,v)) を ((u+v,u-v)) に置き換えます。 逆変換は同じバタフライ構造を持ち、その後に (512^{-1}) が乗算されます。 これは、XOR 変換の標準の逆スケーリングです。 

順変換後、いずれかの逆変換の前に 4 乗が求められます。 この順序が重要です。 1 要素分布を 1 回変換してから、その 4 倍の畳み込みを計算しているため、変換された値は 2 乗ではなく 4 乗する必要があります。 

NTTは最後に反転します。 その逆関数は、すべての係数に (2048^{-1}) を乗算します。これは次のように事前計算されます。`INV_SUM_N`。 Python の整数はオーバーフローしませんが、すべての値は剰余化されます。`MOD`加算と乗算の後、数値が効率的に実行できるほど十分に小さいままになるようにします。 

最後のループでは合計のみが実行されます`1`を通して`2000`。 すべての入力 (a_i) が正であるため、合計ゼロには到達できません。 それぞれの定額額に対して、`power`(s^0,s^1,\ldots,s^{511}) を連続して格納し、テーブル エントリごとに個別の累乗剰余演算を回避します。

import io

def brute(inp: str) -> str:
    it = iter(map(int, inp.split()))
    n = next(it)
    a = [next(it) for _ in range(n)]
    b = [next(it) for _ in range(n)]

    ans = 0

    for x in range(n):
        for y in range(n):
            for z in range(n):
                for w in range(n):

                    e = b[x] ^ b[y] ^ b[z] ^ b[w]
                    ans = (ans + pow(s, e, MOD)) % MOD

    return str(ans)

 実際の最大サイズの場合、入力には (100,000) 個のコピーを含めることができます。`500`両方の配列で。 すべての 4 倍には XOR ゼロがあるため、答えは単純に (100000^4\bmod998244353) になります。 実稼働ストレス テストでは、数百キロバイトのリテラル文字列を保存するのではなく、その入力をプログラムで生成できます。 

## 特殊なケース

 指数がゼロの場合は、最終的なべき乗シーケンスによって直接処理されます。 考慮する```
1
500
500
```変換された分布は 1 つの状態を表します`(500,500)`。 4 つの畳み込みは単一の状態を生成します`(2000,0)`のコピーが 4 つあるため、`500`ゼロへの XOR。 最終評価はべき乗数列を (2000^0=1) で開始するため、答えは次のようになります。`1`。 

XOR 境界には 9 ビットすべてが必要です。 次のような値を検討してください。`500`、バイナリです`111110100`。 個々の値は最大でも`500`、XOR はビットを個別に結合し、最大で次の値を生成できます。`511`。 したがって、変換は正確に次のようになります。`512`位置、インデックス付け`0`を通して`511`。 より小さい変換では、異なる XOR 状態がマージされ、畳み込みが破損します。 

4 倍体の順序付けされた性質は、畳み込みによって自動的に保存されます。 のために```
2
1 2
1 2
```ペア分布には以下が含まれます`(2,0)`一度、`(3,3)`2回、そして`(4,0)`一度。 この分布を和/XOR 畳み込みで二乗すると、4 要素の状態が得られます。 

[
 C[4][0]=1、\quad C[6][0]=6、\quad C[8][0]=1、
 】

 そして

 [
 C[5][3]=2、\quad C[7][3]=4、\quad C[9][3]=2。 
】

 彼らの貢献は、

 [
 1+6+1+2\cdot5^3+4\cdot7^3+2\cdot9^3=3088。 
】

 多重度`6`、`2`、`4`、 そして`2`は、各状態を生成するための順序付けされた方法の正確な数であるため、繰り返されるインデックスや異なる順序付けが失われることはありません。 

最後に、合計の上限は次のようになります。`2000`、 ない`2047`。 変換自体は長さを使用します`2048`NTT の長さは 2 のべき乗である必要があるため、上記のすべての合計の係数は`2000`ゼロでなければなりません。 最大で 4 つの入力値が寄与するため、`500`それぞれ、真の多項式の次数は最大で`2000`。 余分な`47`変換位置は、NTT 中の循環ラップアラウンドを防ぐためにのみ存在します。
