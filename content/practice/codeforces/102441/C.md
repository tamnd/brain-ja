 ## 解決策
 ## 問題の理解

 (n \times m) のバイナリ行列 (A_0) から始めます。 1 回の操作で、すべてのセルが左上隅からそのセルまでの四角形のパリティで置き換えられます。 演算を繰り返し適用すると (A_1,A_2,\ldots) が生成され、現在の行列が再び正確に (A_0) になるまでの最小の正の演算数が必要です。 公式問題では、(1 \le n,m \le 10^6) と (nm\le 10^6) が与えられ、制限時間は 1 秒、メモリ制限は 256 MB です。 

積の限界が重要な制約です。 すべての (nm) セルにわたる線形パスを実行することはできますが、行列全体の多くの変換をシミュレートすることはできません。 単一の変換にはすでに (\Theta(nm)) のコストがかかり、その答えは (10^6) 程度になる可能性があるため、行列を繰り返し構築すると制限をはるかに超えてしまいます。 このソリューションでは、入力を基本的に 1 回処理する必要があります。 

行列の次元のみに基づいた実装では、誤った結果が得られるケースがいくつかあります。 たとえば、すべてゼロの行列の場合、次のようになります。```
2 3
000
000
```1 回の部分和演算では行列が変更されないため、正解は (1) です。 次元をカバーするのに十分な大きさの 2 の累乗を常に検索するソリューションでは、誤って (4) が返される可能性があります。 

1 次元行列の周期は、その長さが示すよりもはるかに小さい場合があります。 のために```
1 4
0001
```正解は(1)です。 唯一のゼロ以外のセルはすでに右端にあるため、プレフィックスの合計を法 (2) にしても行は変更されません。 答えが少なくとも (m) でなければならないと仮定する不用意な解決策は、(4) を返します。 

最初の非ゼロ セルの位置は、他の方向でも同様に重要です。 のために```
1 4
0100
```正解は(4)です。 (1) を含む最初のセルは列 (2) であり、2 の累乗が小さいと、必要な境界が十分に右に移動しません。 (1) の位置を考慮せずに、その存在だけを見ると、答えを決定する情報が失われます。 

## アプローチ

 直接的なアプローチは、(A_1)、次に (A_2) というように、そのうちの 1 つが (A_0) と等しくなるまで構築することです。 現在の行プレフィックス、列プレフィックス、および前の対角寄与をすべて法 (2) で維持することにより、単一の 2 次元プレフィックスサム変換を (O(nm)) 時間で実行できます。 このメソッドは操作の定義を正確に計算するため、正しいです。 

問題は変形回数です。 長さ (d) のベクトルに対する 1 次元の接頭辞合計演算子を考えてみましょう。 モジュロ (2) では、その次数は 2 のべき乗であり、そのべき乗が少なくとも (d) に達すると単位になります。 (d=10^6) の場合、次の 2 のべき乗は (2^{20}=1,048,576) になります。 したがって、ブルート フォース シミュレーションでは、およそ (1,048,576) 個の完全なマトリックス パスが必要になる可能性があります。 (nm=10^6) の場合、最悪の場合、約 (1.05\times10^{12}) 個のセル操作になります。 

この大きな要因を取り除く観察は、プレフィックスの合計を 2 つの要素を持つフィールド上の線形演算子として見ることから得られます。 (S) を、すべての要素を 1 つ下の位置に移動し、先頭に 0 を挿入するシフト演算子とします。 プレフィックスの合計は

 [
 P=I+S+S^2+\cdots。 
】

 2 のべき乗 (q=2^t) の場合、特性 (2) は次のようになります。 

[
 P^q=(I+S)^q=I+S^q。 
】

 すべての中間二項係数は (2) を法として消失します。 同じ同一性が行と列に独立して保持されます。 

完全な 2 次元変換は分離可能であるため、(q) 操作の後、

 [
 A_q=(I+R^q)A_0(I+C^q)、
 】

 ここで、(R) は行をシフトし、(C) は列をシフトします。 したがって、すべての細胞について、

 A[i,j]
 \oplus A[i-q,j]
 \oplus A[i,j-q]
 \oplus A[i-q,j-q],
 】

 ここで、行列の外側のインデックスはゼロに寄与します。 

もう一つ重要な構造的事実があります。 完全な変換には 2 のべき乗の順序があるため、特定の行列の周期は 2 のべき乗でなければなりません。 したがって、可能なすべての (k) をチェックする代わりに、2 の累乗を理解するだけで済みます。 

(q<\min(n,m)) および (A_q=A) と仮定します。 (i>q) および (j\le q) の場合、(j-q) に関係するシフトされた項は消え、(A[i-q,j]=0) になります。 (i>q,j>q) の場合、次のように定義します。 

[
 B[i,j]=A[i,j]\oplus A[i-q,j]。 
】

 等式 (A_q=A) は次のようになります。 

[
 B[i,j]=B[i,j-q]。 
】

 前の境界条件は、(B) の最初の (q) 列がゼロであることを示しているため、等式はすべての列にわたって伝播し、(B) は完全にゼロになります。 したがって、すべての行がピリオド (q) で繰り返されます。 

最初の (q) 列は下位行ではゼロであり、行はピリオド (q) で繰り返されるため、これらの列は実際にはどこでもゼロになります。 対称境界条件は、最初 (q) 行の最初 (m-q) 列がゼロであることを示します。 (q<m) ため、これら 2 つの領域は最初の (q) 行のすべての列をカバーします。 したがって、最初の (q) 行はゼロであり、行の周期性により行列全体がゼロになります。 

したがって、非ゼロ行列は、2 の累乗 (q) が満たされた後にのみ返されます。 

[
 q\ge \min(n,m)。 
】

 これにより、非常に単純な 1 次元の条件が残ります。 

(n\le m) の場合、関連するすべての (q) が (q\ge n) を満たすため、行シフト (R^q) はすでに 0 になります。 列の変換だけが残ります。 (1) から (m-q) までのすべての列がゼロの場合、行列は正確に変更されません。 (1) を含む最初の列が (c) である場合、これは次と同等です。 

[
 m-q<c、
 】

 または

 [
 q\ge m-c+1.
 】

 したがって、必要な 2 のべき乗は、少なくとも 2 の最小のべき乗です。 

[
 \max(n,m-c+1)。 
】

 (m<n) の場合は対称です。 (1)、たとえば (r) を含む最初の行が見つかり、必要な 2 の累乗は少なくとも 2 の最小累乗になります。 

[
 \max(m,n-r+1)。 
】

 ブルートフォース手法は文字通り定義に従いますが、2 の累乗恒等式により、問題全体が 1 つの境界位置を見つけることになります。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(nm\cdot 2^{\lceil\log_2\max(n,m)\rceil})) | (O(nm)) | 遅すぎる |
 | 最適 | (O(nm)) | (O(1)) おまけ | 承認済み |

 ## アルゴリズムのチュートリアル

 1. マトリックスの次元を読み取り、どちらの次元が小さいかを判断します。 小さい次元では最初の可能な 2 のべき乗期間がわかるため、大きい次元に沿った情報のみが必要になります。 
2. (n\le m) の場合、すべての行をスキャンし、(1) を含む最小の列を記録します。 この列を (c) と呼びます。 最終条件はこの最初の非ゼロ列にのみ依存するため、行列を保存する必要はありません。 
3. (1) が存在しない場合は、(1) を出力します。 ゼロ行列は、すべての接頭辞合計演算によって固定されます。 
4. (n\le m) について、数値の最小しきい値を計算します。 

[
 L=\max(n,m-c+1)。 
】

 有効な期間は少なくとも 2 のべき乗 (n) である必要があり、最初の非ゼロ列にはさらに (q\ge m-c+1) が必要です。 

1. (m<n) の場合、(1) を含む最初の行 (r) に対して対称スキャンを実行し、設定します。 

[
 L=\max(m,n-r+1)。 
】

 1. (1) から始めて、候補を 2 倍にして (L) 以上になるまで繰り返します。 考えられるゼロ以外の期間はすべて 2 の累乗であるため、結果の値が答えになります。 

### なぜ効果があるのか

 アルゴリズムの背後にある不変条件は、ゼロ以外の戻り時間はすべて 2 の累乗であるということです。 2 の累乗 (q) の場合、(q) 倍プレフィックス演算は、単位に各次元で (q) だけシフトを加えたものになります。 (q<\min(n,m)) の場合、境界項はすべての行と列を強制的に繰り返すと同時に、境界領域を強制的にゼロにします。これはゼロ行列でのみ可能です。 したがって、すべての非ゼロ行列には (q\ge\min(n,m)) が必要です。 

一度 (q\ge n)、(n\le m) になると、行シフトは完全に消えます。 残りの唯一の変更は、すべてのセルをその左側のセル (q) 位置と比較します。 (c) より前のすべての列がその境界から十分に離れている場合、行列は正確に変更されず、(q\ge m-c+1) になります。 行ハンドル (m<n) の同じ引数。 したがって、両方の下限を満たす 2 の最小累乗を取ることが、有効な最小値 (k) となります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    first = None

    if n <= m:
        for _ in range(n):
            row = input().strip()
            pos = row.find('1')
            if pos != -1:
                col = pos + 1
                if first is None or col < first:
                    first = col

        if first is None:
            print(1)
            return

        need = max(n, m - first + 1)

    else:
        for i in range(1, n + 1):
            row = input().strip()
            if first is None and '1' in row:
                first = i

        if first is None:
            print(1)
            return

        need = max(m, n - first + 1)

    ans = 1
    while ans < need:
        ans <<= 1

    print(ans)

if __name__ == "__main__":
    solve()
```入力は行ごとに処理されるため、プログラムは (n\times) 行列を割り当てません。 (n\le m) のとき、`row.find('1')`現在の行の最初のゼロ以外の列を直接与えます。 すべての行の最小値を取ると、任意の (1) を含む最初の列が得られます。 

(m<n) の場合、(1) を含む最初の行のみが重要となるため、コードは最初に現在の行インデックスを記録します。`'1' in row`成功する。 残りの行は入力ストリームの一部であるため、引き続き読み取る必要があります。 

表現`m - first + 1`そして`n - first + 1`は上記で導出された境界距離です。 の`+1`が不可欠です。 最初の (1) が最後の列にある場合は、(m-c+1=1) となり、ピリオド (1) が正しく許可されます。 を省略すると、`+1`誤ってしきい値としてゼロが生成されてしまいます。 

Python では整数オーバーフローの懸念はなく、実際、答えは最大でも (10^6) の次の 2 のべき乗、つまり (1,048,576) です。 したがって、2 倍化ループは約 20 回しか実行されません。

    sys.stdin = io.StringIO(data)

 ## 特殊なケース

 すべてゼロの行列は、非ゼロ行列には少なくとも (\min(n,m)) の期間が必要であるというステートメントに対する例外的なケースです。 のために```
2 3
000
000
```最初のゼロ以外の列または行はありません。 アルゴリズムはこれを検出し、すぐに (1) を返します。 プレフィックス演算をゼロに適用するとゼロが生成されるため、正の最小期間は実際には (1) になります。 

(1\times m) 行列には行の相互作用がまったくありません。 考慮する```
1 4
0001
```最初の非ゼロ列は (4) なので、

 [
 L=\max(1,4-4+1)=1。 
】

 答えは(1)です。 プレフィックスの合計は、`0001`モジュロ (2) はまだ`0001`。 

ここで考えてみましょう```
1 4
0100
```最初の非ゼロ列は (2) であり、次のようになります。 

[
 L=\max(1,4-2+1)=3。 
】

 (3) の下の 2 のべき乗は (1) と (2) なので、答えは (4) になります。 (m-c+1) の余分な (+1) により、この境界計算が正確になります。 

同じ理論が垂直方向にも機能します。 のために```
4 1
1
0
0
0
```最初の非ゼロ行は (1) なので、

 [
 L=\max(1,4-1+1)=4。 
】

 答えは(4)です。 1 列の行列の先頭にある 1 つの (1) は、下に向かって繰り返し蓄積されるため、シフト長が次元全体に達するまで元の位置に戻りません。 

最後に、次元が両方とも十分に大きいため、2 の小さな累乗が魅力的に見える非ゼロ行列を考えてみましょう。 任意の (q<\min(n,m)) について、2 の累乗恒等式は (q) によって周期性を強制しますが、境界セルは対応する初期ストリップを強制的にゼロにします。 これら 2 つのプロパティは、すべてのセルが 0 になるまで伝播します。 したがって、非ゼロ行列はそのような (q) を周期として持つことはできません。 これが、アルゴリズムが小さい次元より下の 2 の累乗を検査する必要がない理由です。
