 ## 解決策
 ## 問題の理解

 ゼロ以外の 10 進数の複数セットがあります。 すべての出現が重要であるため、入力に 3 つのコピーが含まれている場合、`7`、3 つのコピーはすべて 1 回だけ使用する必要があります。 私たちも持っています`n`上限。 私たちの仕事は、利用可能なすべての数字を正確に再配置することです。`n`正の整数を使用して、各境界に割り当てられる数値がその境界を超えないようにします。 

私たちが構築する数値は同じ桁数を使用する必要はありません。 たとえば、2 桁の境界は 1 桁の番号を受け取ることができます。 唯一のグローバル要件は、すべての入力数字が 1 回だけ消費されることです。 有効な割り当てはすべて元の順序で出力できるため、入力内に境界が表示される順序は重要ではありません。 

最大の入力文字列は 500 桁しかありませんが、境界は最大 50 個です。 これにより、置換ベースの検索が即座に排除されます。 ゼロ以外の可能な数字が 9 つしかない場合でも、可能な配置の数は出現回数に応じて指数関数的に増加します。 上限は最大 10 桁であるため、1 つの候補番号の構築は非常に少ない一定量の作業で処理できます。 便利な構造は、数字のアルファベットのサイズが一定である一方で、合計の桁数が大きくなる可能性があることです。 

不注意な実装によって誤って処理される可能性があるエッジ ケースが 3 つあります。 

まず、使用可能な桁の合計数が、境界で許可される位置の合計数よりも大きくなる可能性があります。 たとえば、`12345 2 21 43`、2 つの境界には最大 4 桁の数字を含めることができますが、5 桁を使用する必要があります。 正しい出力は次のとおりです`-1`。 2 つの有効な数値を構築し、未使用の数字を単純に忘れる貪欲な実装は、すべての数字を使用するという要件に違反します。 

第 2 に、現在の境界に可能な限り短い数値を与えることが常に安全であるとは限りません。 考慮する`129 2 13 22`。 単純な昇順戦略では 1 桁の数字が得られる可能性があります`2`または`1`最初の行き先まで行き、出発します`29`のために`22`、これは無効です。 有効な構造は`1 92`。 より大きな境界では、安全にできる限り多くの桁を消費し、より狭い境界のために小さな桁を残します。 

第三に、境界の対応する桁とのみ桁を比較するには、バックトラッキングが必要になる可能性があります。 のために`3241`そして縛られた`320`、有効な 3 桁の最大の数値は次のとおりです。`314`。 マッチングの試み`3`、 それから`2`、最大でも残りの桁がないためスタックします。`0`。 不用意に貪欲なルーチンを実行すると、たとえ 2 桁目を変更したとしても、3 桁の数字が存在しないと結論付ける可能性があります。`2`に`1`与える`314`。 

## アプローチ

 直接的な総当たりソリューションでは、すべての数字のパーティションが選択されます。`n`空でないグループの場合は、すべてのグループ内の数字を並べ替え、対応する数値を形成し、すべての上限をチェックします。 もし`m`入力された数字は区別可能なものとして扱われます。`m!`注文方法と`C(m-1, n-1)`挿入する方法`n-1`連続する数字の間の区切り文字。 したがって、単純な徹底的な検索では次の順序で調べることができます。`500! * C(499, 49)`最大の場合の候補。 数字を繰り返すと、結果として得られる個別の文字列の数が減りますが、検索は依然として天文学的な規模になります。 ブルート フォースは、検索対象の概念的な定義としてのみ役立ちます。 

重要な観察は、境界自体が順序を提供するということです。 境界を最大から最小の順に処理します。 大きな境界は、その後に続くすべての境界よりも自由度が高いため、最大の安全な数値を受け取り、可能な限り多くの桁を受け取る必要があります。 残りの境界は小さいため、小さい桁のままにする方が安全な選択です。 

特定の境界について、次があるとします。`r`残りの桁と`k`現在の境界を含む境界。 現在の数値はその境界の桁数を超えて使用することはできず、以降の数値ごとに少なくとも 1 桁を残す必要があります。 したがって、その最大可能長は次のようになります。`min(number_of_digits_in_bound, r - (k - 1))`。 

最初にその長さを試し、現在の境界内でその長さの数を形成できない場合にのみ長さを減らします。 

固定長の場合、境界を超えない最大の数値を構築します。 選択した長さが境界の長さより小さい場合、比較は自動的に行われるため、単純に使用可能な最大の桁が取得されます。 長さが等しい場合は、左から右にスキャンします。 すべての位置で、対応する境界桁を超えない、使用可能な最大の桁を試します。 厳密に小さい数字を選択した場合、プレフィックスはすでに境界より小さいため、残りのすべての数字を降順に配置できます。 同じ数字を境界として選択した場合は、再帰的に続行されます。 その同等の選択が最終的に失敗した場合は、戻って次の小さい桁を試します。 

後戻りは微々たるものです。 各位置には最大 9 個の候補数字がありますが、プレフィックスを厳密に保つことができるのは境界の数字に等しい候補だけです。 小規模な候補者はすべて、すぐに建設を完了します。 最大境界には 10 桁しかないため、これは事実上、試行された長さあたりの一定時間になります。 

境界を最大から最小の順に処理するため、貪欲な選択は安全です。 同じ長さの構造の中で、可能な最大の現在の数値を取得すると、最初に大きい桁が消費され、小さい範囲には小さい桁が残ります。 考えられる長さの中で、実現可能な最大の長さを選択すると、後の数値に配置できる桁数が消費されます。 現在の境界は少なくともその後の境界と同じ大きさであるため、ここでこれらの数字を使用しても、現在の数値の位置を減らして後の数値を構築しやすくすることはできません。 したがって、アルゴリズムは、より厳しい境界に対して可能な限り最強の残りのマルチセットを維持します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(m! · C(m-1, n-1)) | O(m) | 遅すぎる |
 | 最適 | O(m + n log n) (10 進定数付き) | O(m + n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 以下のすべての数字の出現を数えます。`1`を通して`9`。 入力にゼロが現れることはないため、必要なカウンターは 9 つだけです。 
2. グローバル長条件を確認します。 すべての境界`a_i`最大でも含めることができます`len(a_i)`桁数なので、入力桁数の合計が`sum(len(a_i))`、解決策は存在しません。 また、すべての数値に少なくとも 1 桁が必要なので、桁数がこれより小さい場合は、`n`、解決策は存在しません。 
3. 境界を数値の降順に並べ替えますが、元のインデックスは保持します。 最大の自由度が最も高いため、最大の境界が最初に処理されます。 
4. 現在の限界について、使用が許可されている最大桁数を計算します。 あれば`r`残りの桁数と`k`現在の境界も含めて境界は残りますが、少なくとも残す必要があります`k - 1`後の境界の数字。 したがって、最大長は次のようになります。`min(len(bound), r - k + 1)`。 
5. その最大値から 1 までの長さを試してください。 まずは一番長い長さを試すのが欲張りな選択です。 機能する場合、現在の境界は可能な最大桁数を消費します。 どの長さも機能しない場合、インスタンス全体を使用することは不可能です。 
6. バインドされた長さよりも小さい長さの場合は、使用可能な最大の桁を降順に取得します。 境界よりも桁数が少ない数値は自動的に小さくなるため、桁ごとの比較は必要ありません。 
7. 境界の長さに等しい長さについて、境界を超えない最大の順列を構築します。 タイトなポジションでは、バインドされた桁から下にある利用可能な桁を試します。 バインドされた桁より小さい桁はプレフィックス全体を小さくするため、残りのサフィックスを降順に並べ替えることができます。 数字が等しい場合はプレフィックスが厳密に保たれ、次の位置に進む必要があります。 
8. 数値が構築されたら、カウンターからその桁を減算し、その数値を境界の元のインデックスに格納します。 カウンタは、より小さい範囲でまだ使用可能な桁を正確に表します。 
9. すべての境界が処理された後は、すべての桁カウンターがゼロになる必要があります。 予備的な総容量チェックと最大長の選択により、解が存在する場合には常にこれが期待される結果になりますが、最終条件により、実装が偶発的に未使用の桁を残すことも防止されます。 

### なぜ効果があるのか

 不変条件は、境界を処理する前に、解が存在するときはいつでも、残りの数字のマルチセットを残りのすべての境界に割り当てることができるということです。 境界を最大から最小の順に処理します。 現在の境界については、最初にその長さを最大化しますが、後の数値ごとに 1 桁を残すことを条件とします。 より長い有効な現在の数値が存在するときに、より短い割り当てが必要な場合、後の数値で使用される桁の 1 つを現在の数値に移動しても、選択された構造が明示的に境界を満たしているため、現在の数値がその境界を超えることはできません。 後の境界は現在の境界よりも大きくなく、構築では可能な最大の現在の数値が選択されます。これにより、大きな桁が優先的に消費され、小さな桁はより厳しい境界に残されます。 固定長の場合、桁ごとの構成は、境界を超えない辞書編集上の最大の順列となります。 したがって、すべての貪欲な決定により、残りのより小さい境界を完了する可能性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_number(cnt, bound, length):
    """
    Return (number_string, new_count) for the largest number of
    exactly `length` digits that can be made from cnt and is <= bound.
    Return (None, None) if impossible.
    """
    work = cnt[:]

    if length < len(bound):
        ans = []
        need = length

        for d in range(9, 0, -1):
            take = min(work[d], need)
            if take:
                ans.append(str(d) * take)
                work[d] -= take
                need -= take
                if need == 0:
                    break

        if need != 0:
            return None, None

        return ''.join(ans), work

    # length == len(bound)
    ans = []

    def dfs(pos):
        if pos == length:
            return True

        limit = ord(bound[pos]) - ord('0')

        # Try the largest possible digit first.
        for d in range(limit, 0, -1):
            if work[d] == 0:
                continue

            work[d] -= 1
            ans.append(str(d))

            if d < limit:
                # The prefix is already strictly smaller.
                # Maximize the suffix.
                for x in range(9, 0, -1):
                    if work[x]:
                        ans.append(str(x) * work[x])

                return True

            # d == limit, so the prefix is still equal.
            if dfs(pos + 1):
                return True

            ans.pop()
            work[d] += 1

        return False

    if not dfs(0):
        return None, None

    return ''.join(ans), work

def solve_case(s, bounds):
    m = len(s)
    n = len(bounds)

    # Every output number needs at least one digit.
    if m < n:
        return None

    # Every output number has at most as many digits as its bound.
    capacity = sum(len(str(x)) for x in bounds)
    if m > capacity:
        return None

    cnt = [0] * 10
    for ch in s:
        cnt[ord(ch) - ord('0')] += 1

    # Process the largest bounds first.
    order = sorted(range(n), key=lambda i: bounds[i], reverse=True)
    answer = [None] * n

    remaining = m

    for step, idx in enumerate(order):
        bound = str(bounds[idx])
        remaining_numbers = n - step - 1

        # Leave at least one digit for every later number.
        max_len = min(len(bound), remaining - remaining_numbers)

        chosen = None
        chosen_cnt = None

        for length in range(max_len, 0, -1):
            candidate, new_cnt = build_number(cnt, bound, length)

            if candidate is not None:
                chosen = candidate
                chosen_cnt = new_cnt
                break

        if chosen is None:
            return None

        answer[idx] = chosen
        cnt = chosen_cnt
        remaining -= len(chosen)

    if remaining != 0:
        return None

    return answer

def solve(data):
    it = iter(data.strip().splitlines())
    t = int(next(it))
    out = []

    for _ in range(t):
        parts = next(it).split()
        s = parts[0]
        n = int(parts[1])
        bounds = list(map(int, parts[2:2 + n]))

        answer = solve_case(s, bounds)

        if answer is None:
            out.append("-1")
        else:
            out.append(" ".join(answer))

    return "\n".join(out)

def main():
    data = sys.stdin.read()
    sys.stdout.write(solve(data))

if __name__ == "__main__":
    main()
```の`solve_case`関数は最初に 2 つのグローバルな実現可能性チェックを実行します。 最初のチェックでは、作成するのに十分な桁数があるかどうかを確認します。`n`空ではない数字。 2 つ目は、使用可能な桁の合計数が、境界で許可されている桁位置の合計数を超えていないことを確認します。 2 番目のチェックは、`12534`サンプル。 

桁カウンタには 10 個のエントリしかないため、桁を削除するために元の文字列を操作する必要はありません。 これにより、繰り返される数字も自然に処理されます。 数字のオカレンスは、そのカウンタをデクリメントすることによって消費され、各グリーディ ステップ後のカウンタは、未使用のオカレンスを正確に表します。 

境界は、元のインデックスが保持されたまま、整数値によって降順に並べ替えられます。 これが必要なのは、貪欲引数が最大の制限を最初に処理することに依存しているためですが、出力には元の位置にバインドされた入力ごとに 1 つの回答が含まれている必要があります。 

表現`remaining - remaining_numbers`残りの数値の桁数が少なすぎることなく、現在の数値が消費できる最大桁数です。 これは、アルゴリズムがローカルで有効な数値を生成するのを妨げる一方、グローバルな桁数のカウントを不可能にする境界条件です。`build_number`最初に最大の長さを試します。 短い長さの場合は、以下から数字を取得します。`9`まで`1`実行する上限比較がないため、すぐに可能な最大の数値が得られます。 長さが等しい場合、ネストされた`dfs`関数はタイトプレフィックスの場合を処理します。 

微妙な部分は、`d < limit`支店。 選択した数字が対応する境界数字よりも厳密に小さい場合、接尾辞に関係なく、数値全体がすでに境界よりも小さくなります。 したがって、残りのすべての桁を降順に配置することができ、結果が最大化されます。 

いつ`d == limit`、プレフィックスは境界と等しいままであるため、サフィックスを引き続きチェックする必要があります。 この再帰的な試行が失敗した場合は、より小さい候補を試行する前にその数字が復元されます。 同じ数字のオカレンスが代替分岐で利用可能な状態を維持する必要があるため、復元は不可欠です。 

ここでは Python の整数はオーバーフローしません。 境界は最大でも`10^9`、そしてアルゴリズムはとにかくその文字列表現でほとんど動作します。 出力数値も文字列として表されるため、長い数字シーケンスの不必要な整数変換が回避されます。

    m = len(s)
    n = len(bounds)

    if m < n:
        return None

    if m > sum(len(str(x)) for x in bounds):
        return None

    cnt = [0] * 10
    for ch in s:
        cnt[int(ch)] += 1

    order = sorted(range(n), key=lambda i: bounds[i], reverse=True)
    answer = [None] * n
    remaining = m

    for step, idx in enumerate(order):
        bound = str(bounds[idx])
        later = n - step - 1

        max_len = min(len(bound), remaining - later)

        found = False

        for length in range(max_len, 0, -1):
            candidate, new_cnt = build_number(cnt, bound, length)

            if candidate is not None:
                answer[idx] = candidate
                cnt = new_cnt
                remaining -= length
                found = True
                break

        if not found:
            return None

    if remaining != 0:
        return None

    return answer

def run(inp: str) -> str:
    lines = inp.strip().splitlines()
    t = int(lines[0])
    out = []

    for line in lines[1:t + 1]:
        parts = line.split()
        s = parts[0]
        n = int(parts[1])
        bounds = list(map(int, parts[2:2 + n]))

        ans = solve_case(s, bounds)
        out.append("-1" if ans is None else " ".join(ans))

    return "\n".join(out)

# Provided samples
sample = """\
3
1234 2 21 43
12534 2 21 43
42 1 42
"""

assert run(sample) == "21 43\n-1\n42", "provided samples"

# Minimum-size input
assert run("1\n7 1 7\n") == "7", "single digit"

# All values equal
assert run("1\n3333 2 33 33\n") == "33 33", "all equal values"

# Boundary condition where the larger bound must receive more digits
assert run("1\n129 2 13 22\n") == "1 92", "length allocation"

# Tight-prefix backtracking
assert run("1\n3241 2 320 99\n") == "314 2", "backtracking"

# Maximum-size feasible digit set: 450 digits, 50 bounds of length 9
s = "1" * 450
bounds = " ".join(["999999999"] * 50)
expected = " ".join(["111111111"] * 50)
assert run(f"1\n{s} 50 {bounds}\n") == expected, "maximum-size feasible case"

# Maximum digit count but insufficient total capacity
s = "1" * 500
assert run(f"1\n{s} 50 {bounds}\n") == "-1", "maximum-size impossible case"

 ## 特殊なケース

 最初のエッジケースは総容量が不十分です。 のために```
12345 2 21 43
```5桁ありますが、`21`そして`43`それぞれ最大 2 桁を含めることができます。 アルゴリズムは計算します`5 > 2 + 2`最初の実現可能性チェック中にすぐに戻る`-1`。 暗黙的に破棄される数字はありません。 

2 番目のエッジ ケースは、長さ割り当てのトラップです。```
129 2 13 22
```境界は次のように処理されます。`22`、 それから`13`。 のために`22`、3 桁が残り、1 桁は後のバインド用に予約する必要があるため、最大長は 2 です。 以下から取得できる最大の 2 桁の数値`1,2,9`は`92`、これは有効です。 のみ`1`残っている、そして`1 <= 13`。 元の順序での最終出力は次のとおりです。`1 92`。 

3 番目のエッジ ケースは、タイトプレフィックス バックトラッキングです。```
3241 2 320 99
```のために`320`、アルゴリズムは長さ 3 を試みます。 最初に等しい接頭辞の後に続きます`3`、 それから`2`。 最後の位置では、境界には最大で 1 桁の数字が必要です`0`、ゼロが存在しないため不可能です。 検索は 2 番目の位置に戻って再試行されます`1`より小さい`2`。 プレフィックスは厳密に以下よりも小さくなりました`32`、それで残りは`4`がその後に配置され、`314`。 唯一未使用の数字は`2`、これは 2 番目の境界に対して有効です。 

4 番目のエッジ ケースは、数字が繰り返される場合です。```
3333 2 33 33
```桁カウンターには、次の 4 つのコピーが含まれています。`3`。 最初のバインドは 2 つのコピーとフォームを消費します`33`; 2 つ目は残りの 2 つを消費します。 すべての数字が異なるという仮定は、アルゴリズムのどこにもありません。 

5 番目のエッジ ケースは、実現可能な最大全長です。 450 桁とそれぞれ 9 桁の境界が 50 ある場合、すべての境界は正確に 9 桁を受け取る必要があります。 450部の場合`1`、構築されたすべての数値は`111111111`。 他に空き容量がないため、アルゴリズムの長さの計算では各境界に 9 桁が強制されます。 

最後に、可能な最小の境界は明示的に注目する価値があります。 利用可能な桁が`9`そして限界は`1`、1 桁の構築は失敗します。`9 > 1`。 数字を追加しても数値が 1 桁の境界より大きくなるだけなので、代替の長さは役に立ちません。 アルゴリズムは可能な長さだけを試行し、失敗を正確に報告します。 

ご希望であれば、これをより短い校正刷りでよりクリーンな、よりコンテスト固有の編集スタイルに変えることもできます。`O(10^3 n)`実装。
