 ## 解決策
 ## 問題の理解

 10 進表記で書かれた正の整数から始めます。 カットでは 2 桁の間の位置が選択されるため、数値は空ではない 2 つの小数部分に分割されます。 両方の部分を整数として解釈した後、元の数値をそれらの絶対的な差に置き換えます。 結果がゼロになることは禁止されています。 この操作を繰り返すと、必要な出力は、元の数値から有効なカットのシーケンスによって到達可能な最小値までのパスになります。 

たとえば、から`42`可能なカットは 1 つだけです`4 | 2`、与える`2`。 から`100`、カット`1 | 00`与える`|1 - 0| = 1`したがって、最適なのは`1`。 アウトプットは最適そのものだけではありません。 裁判官はすべての連続するペアが実際に 1 回の合法的なカットで取得できるかどうかを確認するため、数字のシーケンス全体が含まれている必要があります。 公式の制約は次のとおりです`t <= 1000`そして`n <= 10^12`。 

の上限`10^12`これは、64 ビット演算のみが必要なためではなく、構造的な理由で役立ちます。 このような数値の 10 進数は最大 13 桁です。 カットした後、`k`- 桁数。結果として得られる両方の部分は最大でも`k-1`桁数なので、それらの差も最大で`k-1`数字。 したがって、すべての演算により桁数が少なくとも 1 ずつ減ります。 パスには最大 13 個の数値を含めることができるため、同じ状態の再計算を回避した後、考えられるカットの検索が実行可能になります。 

いくつかの特殊なケースは、誤って処理されやすいものです。 のために`7`、カットする位置がないため、正しい出力は単純に`1 7`。 すべての数値に有効な遷移があると想定する実装は、ここで失敗する可能性があります。 のために`11`、唯一のカットは`1 | 1`、これはゼロを生成するため禁止されています。 したがって`11`それ自体は最小値であり、正しい出力は`1 11`。 ゼロを受け入れる不用意な実装では、ゼロで終わるパスが誤って報告されてしまいます。 のために`1001`、カット`10 | 01`与える`9`、2つのエンドカットが与える`99`そして`99`。 これにより、端付近のカットのみを試みる実装が捕捉されます。 のために`121`、ダイレクトカット`12 | 1`与える`11`、 しかし`1 | 21`与える`20`、 に続く`2 | 0`、与える`2`。 したがって、最小の即時結果を取得するだけでは十分ではありません。 

## アプローチ

 単純な総当り攻撃により、検索ツリー全体が構築されます。 現在のすべての数値について、考えられるすべてのカットを試行し、ゼロを生成するカットを無視し、結果として得られるすべての数値を再帰的に調査します。 これは正しいです。すべての正当な操作は 1 つの分岐で表され、その結果、すべての操作シーケンスは 1 つのルートからリーフへのパスで表されるからです。 

問題はパスの数です。 現在の番号が`k`数字、それはあります`k-1`可能なカット位置。 パスには最大でも次のものを含めることができます`k-1`すべての操作で少なくとも 1 つの数字が削除されるためです。 状態を記憶していなくても、葉の数は次の数に達する可能性があります。`(k-1)(k-2)...1 = (k-1)!`。 

最大 13 桁の入力の場合、これは次のようになります。`12! = 479,001,600`可能なパス。 これは、1 秒のソリューションで数えられる範囲をはるかに超えています。 ブルート フォースは状態空間を理解するのには役立ちますが、実装戦略としては役立ちません。 

重要な観察は、多くの異なるシーケンスを通じて同じ整数に到達できるということです。 ある値に到達したら`x`、その将来の可能性は、`x`、どのようにしてそこに到達したかではありません。 したがって、次の答えを定義できます。`x`再帰的にメモ化します。 これにより、検索ツリーが状態の有向非巡回グラフに変わります。 

2 番目の観測により、深さの限界がわかります。 もし`x`もっている`k`数字、カットの形式は次のとおりです。`x = A || B`、ここで両方とも`A`そして`B`より少ない量が含まれる`k`数字。 したがって、`|A-B| < 10^(k-1)`。 桁数は演算のたびに厳密に減少します。 サイクルは存在できず、指定された制約に対する再帰の深さは最大 12 です。 

結果として得られるアルゴリズムは、まさに到達可能な番号に対するメモ化された検索です。 すべての状態について、すべての正当なカット位置を列挙し、各子から到達可能な最良の最終値を再帰的に取得し、子が最小の結果を与えるようにします。 その結果とともに、どの子が選ばれたかを記憶し、後で必要なパスを再構築できるようになります。 公式コンテストの概要にも、この問題に対する意図した解決策が単に検索として記載されています。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 最悪の場合、テストごとに O((d-1)!) | O(d) 再帰の深さ | 遅すぎる |
 | メモ化された検索 | O(SD) | O(S) | 承認済み |

 ここ`d <= 13`は 10 進数の桁数であり、`S`実際に訪問した個別の到達可能な状態の数です。 各州には最大でも`d-1`カット。 実質的な重要な改善点は、繰り返される状態が 1 回だけ評価されることです。 

## アルゴリズムのチュートリアル

 1. 最初の番号を読み取ります`n`そしてそれを整数として扱います。 Python の整数は入力範囲全体を簡単にカバーできるため、オーバーフローの問題はありません。 
2. 定義する`solve(x)`到達可能な最終的な最小数として`x`。 もし`x`が 2 桁未満の場合、切り捨てがないため、答えは次のようになります。`x`自体。 次のような 2 桁の数字でも同じ状況が発生します。`11`唯一のカットではゼロが生成される場合。 
3. 再帰する前に、`x`はすでにメモ化テーブルにあります。 そうであれば、以前に計算された答えを返します。 の将来`x`は、そこに到達するために使用されるパスから独立しているため、再計算によって新しい情報が提供されることはありません。 
4.変換`x`10 進表現に変換し、2 桁の間のすべての位置を列挙します。 ポジション後のスプリットの場合`i`、左側の部分がプレフィックス、右側の部分がサフィックスです。 計算する`y = abs(left - right)`。 
5. 無視する`y = 0`ゼロは明示的に禁止されているためです。 お互いにとって`y`、再帰的に計算します`solve(y)`そして、返された値を現在の最良の回答と比較します。 
6.子供のことを思い出してください`y`それが最小の最終値を生成しました。 パス全体を保存するのではなく子を保存すると、メモ化テーブルがコンパクトに保たれ、後でパスを再構築できるようになります。 
7. 計算された答えと選択した子をメモ化テーブルに保存します。 今後、同じ整数にアクセスすると、すぐに戻ることができるようになりました。 
8. オリジナルから始める`n`そして、保存されている子ポインタを繰り返したどります。 選択された子が存在しない状態に到達するまで、訪問されたすべての値を出力パスに追加します。 

なぜ機能するのか: 状態`x`どのように到達したかに関係なく、将来の操作の可能性はまったく同じです。`solve(x)`は、すべての正当な最初のカットを検査し、結果の各状態の最適な答えを組み合わせて、可能な限り最良の継続を選択します。 すべての演算は厳密に 10 進数の桁数を減らすため、再帰は最終的には正当な演算が存在しない状態に達します。 したがって、保存された子ポインタは、最終値が元の数値から到達可能な最小値である有効なパスを記述します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(n):
    memo = {}
    nxt = {}

    def dfs(x):
        if x in memo:
            return memo[x]

        s = str(x)
        k = len(s)

        # No cut is possible for a one-digit number.
        # For a two-digit number, the only cut may produce zero.
        if k == 1:
            memo[x] = x
            nxt[x] = None
            return x

        best = x
        best_next = None

        power = 10 ** (k - 1)

        for i in range(1, k):
            power //= 10

            left = x // power
            right = x % power
            y = abs(left - right)

            if y == 0:
                continue

            value = dfs(y)

            if value < best:
                best = value
                best_next = y

        memo[x] = best
        nxt[x] = best_next
        return best

    dfs(n)

    path = [n]
    cur = n

    while nxt[cur] is not None:
        cur = nxt[cur]
        path.append(cur)

    return path

def main():
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        path = solve_case(n)
        out.append(str(len(path)) + " " + " ".join(map(str, path)))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    main()
```の`memo`ディクショナリには、すでに解決されているすべての状態の最適な最終値が格​​納されます。 別個の`nxt`ディクショナリは、その値に達する最初の遷移を記録します。 これら 2 つの情報を分離しておくと、再構築が簡単になります。 

ループオーバー`i`はすべての法定小数点以下の切り捨てを表します。`power`右側の部分の最初の桁に対応する位の値です。 たとえば、`1234`、3 つの反復では累乗を使用します`100`、`10`、 そして`1`、分割を生成します`1 | 234`、`12 | 34`、 そして`123 | 4`。 

の`y == 0`チェックは必須です。 ゼロの結果は単に望ましくない答えであるだけでなく、不正な遷移であるため、決して再帰に入ってはなりません。 

初期値`best = x`法的な非ゼロカットのない状態を処理します。 のために`11`、唯一の候補はゼロなので、`best`残る`11`そして`nxt[11]`残る`None`。 同じロジックですべての 1 桁の数値を処理します。 

Python では、中間式であっても整数オーバーフローは発生せず、最大の入力は`10^12`。 有効な演算が行われるたびに桁数が厳密に減少するため、再帰の深さは最大 12 です。

 ### サンプル 1:`7`番号は 1 桁なので、アルゴリズムはカットが不可能であることをすぐに認識します。 

| 現在`x`| 数字 | 法的カット | 最良の最終値 | 次へ |
 | --- | --- | --- | --- | --- |
 | 7 | 1 | なし | 7 | なし |

| 現在`x`| 分割 | 左 | 右 | 結果 | 最良の最終値 |

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(SD) | 到達可能な個別の状態はすべて 1 回処理され、最大でも`d-1`カット。 |
 | スペース | O(S + d) | メモ化テーブルには、訪問した状態ごとに 1 つの回答と 1 つの遷移が保存され、再帰の深さは最大です。`d`。 |

 ここ`d <= 13`、 なぜなら`n <= 10^12`。 検索では、数値自体に比例する再帰の深さは決してありません。 メモ化では繰り返しのサブツリーが削除されます。これが生の階乗探索との決定的な違いです。 10 進数が 13 桁のみで、テスト ケースが最大 1000 件ある場合、この検索は意図した制約に適合します。 

## テストケース

 出力には最適なパスが含まれる可能性があるため、テストでは出力文字列全体を文字ごとに比較するのではなく、パスを検証する必要があります。 次のテスト ハーネスは、すべての遷移が正当​​であること、および最終値がこれらの小規模なケースに対して個別に計算されたブルート フォースの答えと等しいことをチェックします。```python
# helper: run the solution on an input string
import sys
import io

def solve_case(n):
    memo = {}
    nxt = {}

    def dfs(x):
        if x in memo:
            return memo[x]

        s = str(x)
        k = len(s)

        if k == 1:
            memo[x] = x
            nxt[x] = None
            return x

        best = x
        best_next = None
        power = 10 ** (k - 1)

        for _ in range(1, k):
            power //= 10
            left = x // power
            right = x % power
            y = abs(left - right)

            if y == 0:
                continue

            value = dfs(y)
            if value < best:
                best = value
                best_next = y

        memo[x] = best
        nxt[x] = best_next
        return best

    dfs(n)

    path = [n]
    cur = n
    while nxt[cur] is not None:
        cur = nxt[cur]
        path.append(cur)

    return path

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)

    t = int(sys.stdin.readline())
    answers = []

    for _ in range(t):
        n = int(sys.stdin.readline())
        path = solve_case(n)
        answers.append(str(len(path)) + " " + " ".join(map(str, path)))

    sys.stdin = old_stdin
    return "\n".join(answers)

def can_cut(a, b):
    s = str(a)

    for i in range(1, len(s)):
        left = int(s[:i])
        right = int(s[i:])

        if abs(left - right) == b:
            return b != 0

    return False

def validate_output(inp, output):
    input_lines = inp.strip().splitlines()
    t = int(input_lines[0])
    ns = [int(x) for x in input_lines[1:]]

    lines = output.strip().splitlines()
    assert len(lines) == t

    for n, line in zip(ns, lines):
        data = list(map(int, line.split()))
        m = data[0]
        path = data[1:]

        assert m == len(path)
        assert path[0] == n
        assert path[-1] != 0

        for a, b in zip(path, path[1:]):
            assert can_cut(a, b), (a, b)

def brute(n):
    memo = {}

    def dfs(x):
        if x in memo:
            return memo[x]

        s = str(x)
        best = x

        for i in range(1, len(s)):
            left = int(s[:i])
            right = int(s[i:])
            y = abs(left - right)

            if y == 0:
                continue

            best = min(best, dfs(y))

        memo[x] = best
        return best

    return dfs(n)

100
42
"""
sample_out = run(sample)
validate_output(sample, sample_out)

sample_last = [int(x.split()[-1]) for x in sample_out.splitlines()]
assert sample_last == [7, 1, 2]

# Minimum-size inputs.

"""

validate_output(test, out)
last = [int(x.split()[-1]) for x in out.splitlines()]
assert last == [1, 9, 11, 22]

# Internal cut is necessary for 1001.

"""

"""

validate_output(test, out)

"""

validate_output(test, out)
assert int(out.split()[-1]) == brute(1000000000000) == 1

 ## 特殊なケース

 のために`7`、入力は`7`。 10 進表現には 1 桁しかないため、カット ループには反復がありません。`memo[7]`になる`7`、`nxt[7]`は`None`、そして再構築が生み出す`[7]`。 出力は`1 7`。 

のために`11`、可能な分割は次のとおりです。`1 | 1`、その差はゼロです。 実装はこの移行を次のように拒否します。`if y == 0`、出発`11`最適な値としてパスを指定します`[11]`。 このため、再帰呼び出しの前にゼロをフィルタリングする必要があります。 

のために`1001`、3つのカットが生み出す`999`、`99`、 そして`9`それぞれ。 最後のはから来たものです`10 | 01`したがって、検索ではすぐに次のパスが得られます。`9`。 以来`9`は 1 桁の端末なので、継続しても改善できません。 The final path is`1001 -> 9`。 

のために`121`、カットが生成します`20`そして`11`。 州`11`カットのみがゼロを生成するため、末期です。 州`20`のようにカットできます`2 | 0`、生産`2`。 メモ化された検索は最終値を比較します`2`そして`11`単なる即値ではなく`20`そして`11`、そして正しく選択します`121 -> 20 -> 2`。 

最大入力の場合`1000000000000`、最初の桁の後に切り取ると、`1 | 000000000000`、その違いは`1`。 アルゴリズムの記録`1`最適化され、再構築は即座に停止します。 Python は整数を直接処理し、成功したパスには 2 つの数値しか含まれないため、元の数値のサイズによってオーバーフローや長い再帰が発生することはありません。
