 ## 解決策
 ## 問題の理解

 各テスト ケースについて、2 つの正の整数を受け取ります`a`そして`b`。 整数を出力する必要があります`c`間`1`そして`50`そのような`c`とは異なります`a + b`。 有効な最小値または最大値を見つける必要はないため、条件を満たす任意の値が受け入れられます。 

境界があるため、問題は非常に小さくなります。 多くても`10^3`テスト ケース、および両方の入力数は最大でも`50`。 可能なすべての値をチェックするアプローチでも、`c`から`1`を通して`50`せいぜいパフォーマンスを発揮する`50 * 10^3 = 50,000`これは 1 秒の制限をはるかに下回ります。 この制約はブルートフォースをまったく排除するものではありません。 本当の目標は、`a`そして`b`もっと単純な定数の答えを教えてください。 

重要なエッジ ケースは、可能な最小値です。 もし`a = 1`そして`b = 1`、それらの合計は`2`、 それで`c = 1`はまだ有効です。 不注意な解決策では、入力番号の 1 つを選択するのは安全ではないと考えるかもしれませんが、ここでは`a`そして`b`は両方とも正であるため、それらの合計は常にどちらかの個別の数値よりも厳密に大きくなります。 たとえば、入力の場合`1 1`、出力中`1`は正しいです、なぜなら`1 != 2`。 

同じ理由で最大値も処理されます。 もし`a = 50`そして`b = 50`、合計は`100`、 その間`c`最大でも`50`。 したがって、許可されるすべての値は、`c`は合計とは自動的に異なります。 特に、`c = 1`有効です。 

重要な境界は実際には上限ではありません`50`、しかし、両方とも`a`そして`b`少なくとも`1`。 そのため、`a + b >= 2`、したがって固定値`c = 1`合計が等しくなることはありません。 

提供されたテキストでは、ステートメントのサンプル形式が破損しています。 元のサンプルには 3 つのテスト ケースがあります。`(1, 2)`、`(3, 4)`、 そして`(5, 6)`、考えられる出力の 1 つは次のとおりです。`12`、`34`、 そして`42`。 これらの出力は、答えが一意ではないことを示しています。 

## アプローチ

 直接的な総当たりの解決策では、すべての候補者を試すことになります。`c`から`1`に`50`満足のいくものを見つけたらすぐにやめる`c != a + b`。 これは正しいです。ループは出力制約で許可されているすべての値を検査するため、解決策が存在する場合、ループはそれに遭遇します。 与えられた制約の下では、最悪の場合でもパフォーマンスはわずかです。`50`テストケースごとの比較、または最大でも`50,000`すべての比較`10^3`テストケース。 したがって、ここではブルートフォースが遅すぎることはなく、完全に受け入れられます。 

候補の範囲が狭いため、総当り的なアプローチが機能しますが、算術構造を検討することでより適切に実行できる可能性があります。 以来`a >= 1`そして`b >= 1`、私たちはいつも持っています`a + b >= 2`。 値`1`は許可される出力であり、2 つの正の入力値の合計と等しくなることはありません。 これにより、検索が完全に不要になります。 

という観察`1`とは異なることが保証されています`a + b`まで交換しましょう`50`候補者は 1 つの課題でチェックします。 合計を計算する必要さえありません。

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る`t`。 各テスト ケースは独立しているため、毎回同じ固定構造を使用できます。 
2. ペアごとに`a, b`、出力`1`。 どちらの数値も正であるため、これは正しい選択です。`a + b`少なくとも`2`。 
3. すべてのテスト ケースに対してこれを繰り返します。 実際の値を検査する必要はありません。`a`そして`b`、下限があるため、`1`答えが有効であることを証明するには十分です。 

### なぜ効果があるのか

 すべてのテストケースについて、`a >= 1`そして`b >= 1`。 したがって、`a + b >= 2`。 アルゴリズムの出力`c = 1`、 それで`c < a + b`そしてその結果として`c != a + b`。 また、`1 <= c <= 50`, したがって、出力は必要な範囲を満たします。 同じ議論がすべてのテスト ケースに独立して適用され、アルゴリズムが無効な答えを生成することは決してないことが証明されています。

## テストケース

 この問題では複数の正しい出力が許可されるため、最も堅牢なテストでは、生成されたすべての値が`[1, 50]`とは異なります`a + b`特定の有効な回答を要求するのではなく、```python
import sys
import io

def solve():
    input = sys.stdin.readline

    t = int(input())

    for _ in range(t):
        a, b = map(int, input().split())
        print(1)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    try:
        sys.stdin = io.StringIO(inp)
        sys.stdout = io.StringIO()
        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

def validate(inp: str, out: str):
    input_lines = inp.strip().splitlines()
    t = int(input_lines[0])

    tests = []
    for line in input_lines[1:]:
        a, b = map(int, line.split())
        tests.append((a, b))

    answers = list(map(int, out.strip().split()))

    assert len(answers) == t

    for (a, b), c in zip(tests, answers):
        assert 1 <= c <= 50
        assert c != a + b

# Provided sample input.
sample = """\
3
1 2
3 4
5 6
"""
sample_output = run(sample)
validate(sample, sample_output)

# Minimum-size input.
case_min = """\
1
1 1
"""
assert run(case_min) == "1\n"

# Maximum-size input.
case_max = """\
3
50 50
50 1
1 50
"""
assert run(case_max) == "1\n1\n1\n"
validate(case_max, run(case_max))

# All values equal.
case_equal = """\
4
7 7
25 25
49 49
50 50
"""
assert run(case_equal) == "1\n1\n1\n1\n"
validate(case_equal, run(case_equal))

# Boundary sums around the smallest and largest possible values.
case_boundaries = """\
4
1 1
1 2
49 50
50 50
"""
assert run(case_boundaries) == "1\n1\n1\n1\n"
validate(case_boundaries, run(case_boundaries))
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`3 / 1 2 / 3 4 / 5 6`|`1 / 1 / 1`| 提供されたサンプル構造と非固有の出力 |
 |`1 / 1 1`|`1`| 最小入力値と最小可能合計値 |
 |`3 / 50 50 / 50 1 / 1 50`|`1 / 1 / 1`| 最大入力値と許容される境界`c`範囲 |

 ## 特殊なケース

 最小のケースは`a = 1, b = 1`。 アルゴリズムの出力`1`。 それらの合計は`2`、ということで条件は`c != a + b`になる`1 != 2`、それは本当です。 正確な入力は次のとおりです`1\n1 1\n`、出力は次のようになります`1`。 

1 つの入力がそれ自体である場合`1`不注意な解決策では、不必要な特殊なケースを引き起こす可能性があります。 のために`a = 1, b = 2`、アルゴリズムは引き続き出力します`1`。 合計は`3`、したがって、答えは有効です。 避ける理由はない`1`単に入力値の 1 つが次と等しいという理由だけで`1`。 

他の境界では、次のように考えます。`a = 50, b = 50`。 合計は`100`、これは許容出力範囲外です。 アルゴリズムの出力`1`、そしてそれ以来`1 != 100`、答えは有効です。 実際、許容されるすべての値は、`c`この特定のテストでは機能します。 

最後に、次のような等しい入力を考慮します。`a = 25, b = 25`。 それらの合計は`50`、したがって常に出力される不注意な解決策`50`失敗するだろう。 固定建設の出力`1`、 そして`1 != 50`, したがって、合計を検査する必要なく、この境界の衝突を回避します。 これは、許容される最小値を選択する方が、上限に近い値を選択するよりも強力である理由を示しています。
