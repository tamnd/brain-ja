 ## 問題の理解

 配列があります`a`の`n`整数。 各要素は確率で独立して選択されます`P = X / Y`。 選択した要素が XOR 演算され、ランダムな整数が生成されます。`s`。 何も選択されていない場合、XOR はゼロになります。 タスクは、次の期待値を計算することです。`s²`、最終的な答えはモジュロで表されます`10^9 + 7`。 

難しいのは、予想される XOR 自体を計算することではありません。 個々のビットの期待値を取得するのは非常に簡単です。 平方では異なるビット間の積が導入されるため、XOR ビットのペアがどのように動作するかを理解する必要もあります。 

制約`n <= 10^5`サブセットの列挙を即座に除外します。 あり得る`2^n`可能な選択の数は、数十個の要素であっても天文学的に大きくなります。 値は以下の通りです`10^9 + 7`、だからすべて`a_i`30 バイナリ ビットに収まる理由`2^30 > 10^9 + 7`。 この小さなビット幅は、問題を扱いやすくする構造的な特性です。 約 30 ビット位置に関係する作業を行う余裕はありますが、サブセットの数に比例する作業を行う余裕はありません。 

誘惑的な単純化によって間違った答えが得られる特殊なケースがいくつかあります。 まず、もし`P = 0`、何も選択されません。 例えば、```
1 0 7
123
```与える`s = 0`間違いなく、答えは次のとおりです`0`。 すべての確率が厳密に 0 と 1 の間にあると仮定する数式は、この境界を誤って処理する可能性があります。 

反対の極端な場合、`P = 1`、すべての要素が選択されています。 例えば、```
1 1 1
5
```常に生成します`s = 5`、したがって、答えは次のとおりです`25`。 確率的計算は、ランダムなプロセスが決定的になる場合にも機能する必要があります。 

より微妙なケースは、ビット間の相関です。 考慮する```
1 1 2
3
```結果はどちらかです`0`または`3`、それぞれ確率付き`1/2`、 それで`E[s²] = (0² + 3²) / 2 = 9/2`。 

モジュロ`10^9 + 7`、これは`500000008`。 不用意にアプローチすると、2 つのビットがそれぞれ独立して存在していることが観察される可能性があります。`1`確率的に`1/2`。 ここではそれらは独立していません。数値は次のいずれかです。`00`または`11`。 彼らを独立したものとして扱うと、間違った瞬間が与えられてしまいます。 

与えられたサンプルは、```
3 1 2
2 8 10
```そしてその正解は`42`。 

## アプローチ

 直接的なアプローチは、次のすべてのサブセットを考慮することです。`a`、選択した要素を XOR し、結果を 2 乗し、すべての値を対応する確率で平均します。 がある`2^n`サブセット。 すべてのサブセットがすべてを調べて構築される場合`n`要素の場合、演算回数は`O(n 2^n)`。 たとえグレイコード列挙によってサブセットごとの作業が軽減され、`O(2^n)`、最悪のケースはまだ含まれています`2^100000`と記載されているため、このアプローチは使用できません。 

ブルートフォースはランダムな実験に明示的に従うため機能します。 実験では指数関数的に多くの結果が得られるため、失敗します。 重要な観察は、最終的な XOR がビットごとに構築され、答えにはそれらの出力ビットに最大 2 次の項のみが含まれていることです。 

最終的な XOR のバイナリ表現を次のように記述します。`S = sum_k 2^k Z_k`、

どこ`Z_k`位置のランダムなビットです`k`。 二乗すると`S² = sum_k 2^(2k) Z_k + 2 sum_{i<j} 2^(i+j) Z_i Z_j`。 

したがって、必要なのは`E[Z_k]`そして`E[Z_i Z_j]`。 

それぞれ`Z_k`自体は独立したベルヌーイ変数の XOR です。 このようなパリティの場合、有用な量はその確率ではなく、その符号付き期待値です。`E[(-1)^Z_k]`。 

ビットと仮定します`k`正確に設定されています`c_k`配列要素。 ビットがゼロであるすべての要素が係数に寄与します`1`この署名された期待に。 ビットが 1 であるすべての要素が寄与します`(1-P) + P(-1) = 1 - 2P`。 

したがって`E[(-1)^Z_k] = (1 - 2P)^(c_k)`。 

させて`q = 1 - 2P`。 

それから`E[Z_k] = (1 - q^(c_k)) / 2`。 

同じ考え方でビットのペアを処理します。 2出力ビットの場合`Z_i`そして`Z_j`、 定義する`A = E[(-1)^Z_i]`、`B = E[(-1)^Z_j]`、`C = E[(-1)^(Z_i XOR Z_j)]`。 

最後の数量は、これら 2 つのビット位置で異なる値を持つ入力要素がいくつあるかによって異なります。 その数字を`d_ij`。 それから`C = q^(d_ij)`。 

2 つのブール変数の 4 つの可能な組み合わせは、3 つの符号付き期待値から復元できます。 特に、`P(Z_i = 1 and Z_j = 1) = (1 - A - B + C) / 4`。 

これにより、必要なすべての項が得られます。`E[S²]`。 

ビット位置は 30 個しかないため、単一ビットのカウントは 30 個だけです。`30 * 29 / 2`ペアの距離が必要です。 ペアの距離は、すべてのビット列をパックされたビットセットとして表すことで効率的に計算できます。 2 つの列間のハミング距離は、それらの XOR の母数になります。 Python では、大きな整数はまさにこのパック表現を提供します。列は、そのビットがすべてを表す整数として格納されます。`n`配列要素、および Python の C 実装は XOR と`bit_count()`効率的に。 

結果は、指数列挙から 30 ビット位置を超えて動作するように削減され、パックされます。`n`-ビット列。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |`O(n 2^n)`|`O(n)`| 遅すぎる |
 | 最適 |`O(30n + 30² n / W)`|`O(30n / 8)`| 承認済み |

 ここ`W`パックされたビット演算によって内部的に使用されるマシン ワード サイズです。 Python 実装では、対応する操作は最適化された任意精度の整数ルーチンによって実行されます。 

## アルゴリズムのチュートリアル

 1.読む`n`、`X`、`Y`、および配列。 作業モジュロ`MOD = 10^9 + 7`。 コンピューティング`q = 1 - 2X/Y`モジュロ`MOD`。 以来`Y < MOD`、その逆モジュールが存在します。 
2. 30 個の可能なビット位置ごとに 1 つのパックされたビット列を構築します。 の`r`列の - 番目のビット`k`ビットかどうかを記録します`k`の`a[r]`が設定されています。 これらの列を Python 整数として保存できます。 

この表現により、すべての列にアクセスするのではなく、列全体を一度に比較できます。`n`ビット位置のペアごとに要素が含まれます。 
3. ビットごとに`k`、セットされたエントリの数を計算します`c_k`使用して`column[k].bit_count()`。 次に計算します`R_k = q^(c_k)`。 

以来`R_k = E[(-1)^Z_k]`、最終的な XOR がビットを持つ確率`k`セットは`p_k = (1 - R_k) / 2`。 
4. 正方形の対角項を追加します。 少し`k`貢献する`2^(2k) p_k`に`E[S²]`。 
5. 異なるビット位置のペアごとに`i < j`、パックされた列の XOR を計算し、設定されたビットをカウントします。 これにより、`d_ij = number of input elements where bits i and j differ`。 

コンピューティング`R_ij = q^(d_ij)`。 

と共に`R_i`そして`R_j`、これは与えます`p_ij = P(Z_i = 1, Z_j = 1)`として`(1 - R_i - R_j + R_ij) / 4`。 
6.クロスタームを追加する`2 * 2^(i+j) * p_ij`すべてのペアの答えへ`i < j`。 
7. 最終値の剰余を減算します。`MOD`そしてそれを印刷します。 2 と 4 による除算は、次のような逆モジュラーを使用して実行されます。`2^(MOD-2)`そして`4^(MOD-2)`モジュロ`MOD`。 

### なぜ効果があるのか

 不変条件は、処理されたビットまたはビットのペアごとに、保存されている電力が`q`は、対応する XOR パリティの符号付き期待値とまったく同じです。 1 つのビットについて、そのビットが設定されている選択された入力要素ごとにパリティが反転され、係数に寄与します。`1 - 2P`。 2 ビットの場合、2 つの入力ビットが異なる場合に XOR が反転するため、異なる行の数によって対応する符号付き期待値が決まります。 1 つと 2 つのブール変数の式は、それらの確率を正確に回復します。 以来`S²`個々のビット項とペアごとのビット積のみが含まれており、これらの期待値を合計すると正確に得られます。`E[S²]`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 1_000_000_007
BITS = 30

def solve():
    n, X, Y = map(int, input().split())
    a = list(map(int, input().split()))

    inv_y = pow(Y, MOD - 2, MOD)
    q = (1 - 2 * X * inv_y) % MOD

    inv2 = (MOD + 1) // 2
    inv4 = inv2 * inv2 % MOD

    # Store every bit column as a packed integer.
    # Byte r contains the r-th row of the column.
    columns = [bytearray(n) for _ in range(BITS)]

    for r, value in enumerate(a):
        for bit in range(BITS):
            columns[bit][r] = (value >> bit) & 1

    packed = [int.from_bytes(col, "little") for col in columns]

    # signed[k] = E[(-1)^Z_k]
    signed = [0] * BITS

    answer = 0

    for bit in range(BITS):
        cnt = packed[bit].bit_count()
        signed[bit] = pow(q, cnt, MOD)

        p_one = (1 - signed[bit]) * inv2 % MOD
        weight = (1 << (2 * bit)) % MOD
        answer = (answer + weight * p_one) % MOD

    for i in range(BITS):
        for j in range(i + 1, BITS):
            differing = (packed[i] ^ packed[j]).bit_count()
            both_signed = pow(q, differing, MOD)

            p_both = (
                1
                - signed[i]
                - signed[j]
                + both_signed
            ) % MOD
            p_both = p_both * inv4 % MOD

            weight = (1 << (i + j)) % MOD
            answer = (
                answer + 2 * weight * p_both
            ) % MOD

    print(answer)

if __name__ == "__main__":
    solve()

の`columns`配列は、垂直方向に見た入力をコンパクトに表現したものです。 各数値の 30 ビットを個別の Python 整数として保存し、配列全体を繰り返しスキャンする代わりに、各列は次のように保存されます。`n`バイトを取得し、1 つの大きな整数に変換します。 変換ではリトルエンディアン順序が使用されるため、`r`-th 入力要素は、`r`パックされた整数の - 番目のビット位置。 

バイト間の区別`columns`そしてビットイン`packed`意図的です。 bytearray を使用すると、各入力行を直接割り当てることができるため、構築が簡単になります。 パッキング後、コストのかかるすべてのペア比較は、最適化されたネイティブ コードで実装された Python 整数に対して行われます。 

最初のループは計算します`signed[k]`、つまり`q`ビットを含む要素の数に丸められます。`k`。 この符号付き期待値を、最後の XOR ビットが 1 である確率に即座に変換し、対応する対角寄与を平方に加算します。 

2 番目のループは、ビット位置のすべてのペアを処理します。 2 つのパック列の XOR 演算により、2 つの入力ビットが異なる配列要素が正確にマークされます。`bit_count()`したがって、与えられます`d_ij`Python ループオーバーなし`n`要素。 ペアの確率は符号付き期待値の恒等式から導き出され、その寄与は係数を受け取ります。`2 * 2^(i+j)`平方の交差項から。

ビットに対するループはちょうど 30 回実行されます。 ペア ループは 435 回のみ実行されます。 潜在的に大きいのは、`n`ディメンションは、すべてのペアの Python レベルのループとして公開されるのではなく、パックされた整数演算内に隠蔽されます。

1 1 1
5
```考えられる唯一の結果は`5`、そしてアルゴリズムは`25`。 

繰り返される値には特別な処理は必要ありません。 のために```
2 1 2
1 1
```XOR は`0`どちらのコピーも選択されていない場合、または両方のコピーが選択されていない場合、`1`さもないと。 4 つの選択にはそれぞれ確率があります`1/4`、 それで`P(S = 1) = 1/2`そして`E[S²] = 1/2`、与える`500000004`。 ビット数は 2 であるため、この式では重複する値を個別に考慮しなくても同じ結果が得られます。 

相関例```
1 1 2
3
```がメインの罠です。 可能な出力は次のとおりであるため、両方のビットは常に同時に変化します。`00`そして`11`。 ペアの距離はゼロなので、`q^0 = 1`、次の同時確率を生成します。`1/2`。 ペアの距離が独立したビットの仮定によって誤って置き換えられた場合、答えは間違っています。 

最後に、値がゼロの要素は無害です。 で```
100000 1 2
0 0 0 ... 0
```すべてのビット列は完全にゼロであるため、すべての単一ビット カウントはゼロであり、すべてのペアの距離はゼロです。 どの要素が選択されているかに関係なく、最終的な XOR は常に 0 であり、アルゴリズムはすぐに次の答えを取得します。`0`。
