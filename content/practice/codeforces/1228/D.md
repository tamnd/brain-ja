 ## 解決策
 ## 問題の理解

 最大 100,000 個の頂点と最大 300,000 個のエッジを持つ無向グラフが与えられます。 タスクは、すべての頂点を正確に 3 つの空でないグループに分割し、グループの各ペア間の構造が完全に規則的になるようにすることです。 

2 つのグループ間の規則は厳密です。それらの間には、考えられるすべてのエッジが存在する必要があり、各グループ内ではエッジはまったく許可されません。 言い換えれば、2 つの異なるグループは完全な 2 部接続を形成する必要があり、各グループは個別に独立したセットである必要があります。 

したがって、最終的な構造は完全な 3 部構成のグラフのように動作する必要があります。1 つのグループ内のすべての頂点は、他の 2 つのグループ内のすべての頂点に接続されており、そのグループ内の頂点には決して接続されません。 

出力は、各頂点がどのグループに属しているかを示す単純な 1 から 3 のラベル、またはそのような分割が不可能な場合は -1 です。 

この制約により、すべてのパーティションのチェックなどは直ちに除外されます。 すべての代入を単純に列挙すると 3^n になりますが、これは不可能です。 単一のパーティションをテストするだけでも O(n + m) かかるため、グラフの構造特性に基づいた構築が必要です。 

いくつかの微妙な失敗例については、覚えておく価値があります。 

エッジのないグラフは柔軟に見えるかもしれませんが、グループ間には完全な 2 部接続が必要なため、機能しません。 たとえば、n = 3 および m = 0 の場合、グループ間のエッジが欠落しているため、どのパーティションも失敗します。 

もう 1 つの注意が必要なケースは、グラフがすでに密集しているものの、完全に構造化されていない場合です。 たとえば、ほぼ完成しているが 2 つの候補グループ間にいくつかのエッジが欠けているグラフは、2 つのグループ間のエッジが 1 つでも欠けていると条件が無効になるため、要件を満たしません。 

最後に、次数が均等でないグラフは、貪欲なグループ化の試みを欺いてしまうことがよくあります。 他の頂点と比較して次数が異常に小さい頂点は、外側への完全な接続を期待するグループに属することはできません。 

## アプローチ

 ブルート フォース アプローチでは、各頂点を 3 つのグループのいずれかに割り当て、すべての条件が満たされるかどうかを検証します。 これには、セットのトリプルをすべてチェックし、エッジが内部に存在しないことと完全な相互接続を検証する必要があります。 たとえ検証が O(n + m) であっても、すべての代入を試すのは指数関数的であり、実行不可能です。 

重要な洞察は、有効なソリューションの構造が非常に厳格であるということです。 任意の頂点を選択します。 そのグループは、非隣接者および隣接者によって非常に制約された方法で決定されます。 有効な 3 部構成補完では、1 つのグループ内のすべての頂点が、他のグループに対して同一の隣接パターンを持っている必要があります。 これにより、頂点は隣接構造によって定義された同値クラスのように動作するように強制されます。 

より建設的な方法は、グラフが有効な場合、任意の頂点 v について、v に接続されていないすべての頂点は v 自身のグループまたは 1 つの特定の他のグループに属している必要があり、これにより補数近傍に基づいて頂点が分割されることに注意することです。 隣接しない頂点に注目すると、同じ「欠落エッジ」パターンを共有する頂点をクラスター化できます。 

標準的な解決策は、問題を補グラフの接続性によって頂点をグループ化することに還元します。補グラフでは、同じグループ内の頂点がクリークを形成します。グループ内には元のグラフにエッジがないため、頂点はすべて補グラフで接続されます。 さらに、グループ間では、すべてのエッジが元のグラフに存在するため、異なるグループ間の補数にはエッジがありません。 つまり、各グループは補数グラフの連結成分となり、正確に 3 つの成分が存在する必要があります。 

したがって、問題は、補数グラフを暗黙的に構築し、それぞれが空ではない 3 つの連結成分があるかどうかをチェックすることに帰着します。

課題は、補数グラフが密であるため、明示的に構築できないことです。 代わりに、隣接セットと既存のエッジをスキップする BFS/DFS を使用して走査をシミュレートします。 

訪問されていないノードのセットを維持します。 コンポーネントを探索するとき、ノード v に関して、元のグラフで v に隣接しておらず、まだ訪問されていないすべてのノードは、補完グラフの同じコンポーネントに属します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(3^n · (n + m)) | O(n + m) | 遅すぎる |
 | 補体BFS構造 | O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. O(1) エッジ チェック用のハッシュ セットを使用して隣接リストを保存します。 これにより、非近傍を効率的に判断できるようになります。 
2. セットを維持する`unused`すべての頂点を含む。 これは、補グラフ内のコンポーネントにまだ割り当てられていないノードを表します。 
3. その間`unused`空ではありません。任意の頂点を選択してください`start`そして補体グラフで BFS/DFS を開始します。 
4. ノードからの BFS 時`v`に隣接していないすべての頂点を見つけたいとします。`v`元のグラフにあり、現在も`unused`。 これらはまさに隣人です`v`補完グラフで。 
5. これを効率的に行うために、次のことを繰り返します。`unused`元のグラフで隣接するものを削除し、隣接しないものだけを残します。 残りのコンポーネントは現在のコンポーネントに追加されます。 
6. BFS キューがなくなるまで繰り返します。 これにより、補数グラフに 1 つの連結成分が生成されます。 
7. すべてのコンポーネントを保管します。 コンポーネントの数が正確に 3 でない場合は、-1 を出力します。 
8. 3 つのコンポーネントにラベル 1、2、3 を割り当てます。 それぞれが空であってはなりません。 

### なぜ効果があるのか

 有効な 3 部グラフでは、同じグループ内の頂点間にエッジがないため、補グラフでは完全に接続されます。 グループ間には、元のグラフにすべてのエッジが存在するため、グループを横切る補完エッジはありません。 これは、各グループが補数グラフ内の 1 つの連結成分であることを意味します。 逆に、正確に 3 つの補数コンポーネントに分割すると、元の制約がすべて満たされることが保証されます。 

したがって、正しさは補グラフ内の連結成分を識別することに帰着します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import defaultdict, deque

def solve():
    n, m = map(int, input().split())
    adj = [set() for _ in range(n)]

    for _ in range(m):
        a, b = map(int, input().split())
        a -= 1
        b -= 1
        adj[a].add(b)
        adj[b].add(a)

    unused = set(range(n))
    comps = []

    while unused:
        start = next(iter(unused))
        unused.remove(start)

        q = deque([start])
        comp = [start]

        while q:
            v = q.popleft()

            to_remove = []
            for u in unused:
                if u not in adj[v]:
                    to_remove.append(u)

            for u in to_remove:
                unused.remove(u)
                q.append(u)
                comp.append(u)

        comps.append(comp)

    if len(comps) != 3:
        print(-1)
        return

    res = [0] * n
    for i, comp in enumerate(comps):
        for v in comp:
            res[v] = i + 1

    print(*res)

if __name__ == "__main__":
    solve()
```この実装は隣接セットに依存しているため、エッジ チェックは一定時間になります。 BFS は補数グラフ上で暗黙的に動作します。つまり、補数エッジを保存する代わりに、現在のノードの近傍を削除することによってグローバル未使用セットを繰り返しフィルタリングします。 

重要な点は、補数エッジを明示的に反復処理しないことです。 非近傍は除外によってのみ計算されます。 これにより、直接補数構成によって引き起こされる O(n^2) の爆発が回避されます。

 ### 例 1

 入力:```
6 11
1 2
1 3
1 4
1 5
1 6
2 4

```このグラフは、頂点 {1}、{2,3}、{4,5,6} が有効なパーティションを形成するようにすでに構造化されています。 

| ステップ | 開始 | 現在のコンポーネント | アクション |
 | --- | --- | --- | --- |
 | 1 | 1 | {1} | 補数グラフで BFS を開始 |
 | 2 | 1 | {1} | 未使用の 1 に隣接しないものをすべて追加 → {2,3} |
 | 3 | 2 | {1,2,3} | 2 から展開し、残りの有効なノードを追加します。 
| 4 | 4 | {4,5,6} | 新しいコンポーネントが発見されました |
 | 5 | - | 合計 3 つのコンポーネント | 停止 |

 これにより、補体の接続性によってグラフが 3 つのグループにきれいに分離されることが確認されます。 

### 例 2

 入力:```
3 0
```すべての頂点が分離されます。 補数グラフでは、すべてのペアが接続されているため、サイズ 3 の単一のコンポーネントが存在します。 

| ステップ | 開始 | 現在のコンポーネント | アクション |
 | --- | --- | --- | --- |
 | 1 | 1 | {1,2,3} | すべてのノードは補数で接続されます |
 | 2 | - | 1 コンポーネント | 停止 |

 取得できるコンポーネントは 1 つだけなので、空でない 3 つのグループを形成することは不可能です。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + m) 償却 | 各頂点は次から削除されます。`unused`1 回、隣接関係チェックはエッジごとに O(1) です。 
| スペース | O(n + m) | 隣接セットとブックキーピング配列 |

 n と m の両方が線形スケール境界であり、補数 BFS が二次列挙を回避しているため、アルゴリズムは制限内に快適に適合します。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    from collections import defaultdict, deque

    n, m = map(int, sys.stdin.readline().split())
    adj = [set() for _ in range(n)]
    for _ in range(m):
        a, b = map(int, sys.stdin.readline().split())
        a -= 1
        b -= 1
        adj[a].add(b)
        adj[b].add(a)

    unused = set(range(n))
    comps = []

    while unused:
        start = next(iter(unused))
        unused.remove(start)
        q = deque([start])
        comp = [start]

        while q:
            v = q.popleft()
            to_remove = []
            for u in unused:
                if u not in adj[v]:
                    to_remove.append(u)
            for u in to_remove:
                unused.remove(u)
                q.append(u)
                comp.append(u)

        comps.append(comp)

    if len(comps) != 3:
        return "-1"

    res = [0] * n
    for i, comp in enumerate(comps):
        for v in comp:
            res[v] = i + 1
    return " ".join(map(str, res))

 ## 特殊なケース

 重要なエッジケースは、グラフがまばらすぎる場合です。 たとえば、n = 3 でエッジがない場合、補グラフは 1 つのクリークになり、3 つのコンポーネントではなく 1 つのコンポーネントが生成されます。 このアルゴリズムはすべてのノードを 1 つのコンポーネントにマージし、正しく拒否します。 

もう 1 つのエッジ ケースは、グラフが完成したときです。 その場合、補グラフにはエッジがないため、すべての頂点が独自のコンポーネントになります。 これにより、3 ではなく n 個のコンポーネントが生成されますが、これも n = 3 でない限り正しく拒否されます。 

補数 BFS は次数やヒューリスティックではなく、補数グラフの到達可能性に基づいて正確なグループ化を強制するため、不均一な欠落エッジを持つグラフは依然として正しく動作します。
