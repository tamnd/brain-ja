 ## 問題の理解

 以下の数字の順列があります。`1`に`n`。 値`x`この未ソートの順列に対して実行される二分探索手順によって見つける必要があります。 この手順では、次の位置は検索されません。`x`直接。 中央の要素が最大かどうかに応じて、左右の境界線のみを移動します。`x`以上`x`、停止すると、現在の左の境界線が返されます。 目標は、検索が開始される前に最大 2 回のスワップを実行して、返される位置に次の値が含まれるようにすることです。`x`。 

入力には、いくつかの独立したケースが含まれています。 それぞれのケースについて、順列のサイズ、必要な値、現在の配置がわかります。 出力はスワップのリストです。 0、1、または 2 つのスワップを含む有効なシーケンスが受け入れられます。 

すべての順列の合計サイズは最大で`200000`。 これにより、可能なスワップを数多く試行したり、ポジションごとにプロセスを繰り返しシミュレートしたりするものは除外されます。 テスト ケースごとの線形ソリューションで十分です。`O(200000)`すべてのポジションのペアをチェックするなどのアプローチでは、最大で 2 時間の作業が必要になります。`O(n^2)`操作。 

この問題の微妙な部分は、二分探索では配列全体をソートする必要がないことです。 二分探索パスが訪問する位置のみが重要です。 よくある間違いは移動することです`x`証明することなく、検索パスが同じままであると仮定します。 もう 1 つの間違いは、問題では 1 から始まる位置を記述するのに、二分探索シミュレーションで 0 から始まるインデックスを使用することです。 

たとえば、次のことを考えてみましょう。```
1
4 1
2 3 4 1
```二分探索は次から始まります`l = 1`、`r = 5`。 位置を確認します`2`、わかります`3 > 1`、そして動きます`r`に`2`。 で止まります`l = 1`、しかし位置`1`含まれています`2`。 正しい出力は次のとおりです。```
1
1 4
```答えが常に元の位置であると仮定する不用意な解決策`x`アルゴリズムは位置ではなく比較によって決定された位置を返すため、失敗します。`x`。 

もう 1 つのエッジケースは次のような場合です`x`はすでに二分探索で返された位置にあります。```
1
5 3
1 2 3 4 5
```正しい出力は次のとおりです。```
0
```常にスワップを実行するソリューションは多くの場合まだ受け入れられますが、誤って移動してしまう可能性があります。`x`正しい位置から離れて間違った答えを作ってしまいます。 

## アプローチ

 簡単なアプローチは、可能なスワップを試して結果を確認することです。 単一のスワップには、`O(n^2)`可能性があり、2 回交換するとさらに多くの組み合わせが作成されます。 二分探索をシミュレートするだけでも、`O(log n)`試行するたびに、実行可能な操作数をはるかに超えます。`n`まで`200000`。 

重要な観察は、順列を修復する必要がないということです。 置くだけです`x`現在の二分探索が終了する位置に移動します。 その立場にしましょう`l`。 

元の順列に対して指定された二分探索を 1 回実行します。 もし`p[l]`すでに`x`変更する必要はありません。 それ以外の場合は要素を交換します`x`所定の位置に`l`。 

唯一の懸念は移転するかどうか`x`検索によって行われた比較の 1 つを変更します。 スワップにより 2 つのポジションが変更されます: 最終ポジション`l`そして元の位置`x`。 

位置`l`アルゴリズムが停止した後は決してチェックされません。 本来の位置は`x`のほうが面白いです。 検索でその位置がチェックされた場合、そこでの比較は値と行われます。`x`, そのため、検索により左の境界線がその位置に移動しました。 その後の左境界線の移動は、別のチェックされた値も最大値である場合にのみ発生します。`x`。 ということで最終的な順位は`l`常に最大でも値が含まれます`x`この場合。 交換後の古い値は、`l`元の位置に移動します`x`、それでも同じ比較結果を満たします。 元の位置であれば、`x`チェックされていないため、変更しても検索にはまったく影響しません。 

したがって、常に 1 回の交換で十分です。 この問題では 2 つのスワップが可能ですが、最適な構築には 0 または 1 つだけが必要です。

 ## アルゴリズムのチュートリアル

 1. の現在位置を確認します。`x`順列の中で。 唯一可能な変更は移動であるため、このインデックスが必要です`x`別の場所へ。 
2. ステートメントに記述されている正確な二分探索をシミュレートします。 維持する`l`そして`r`を 1 ベースの境界線として指定し、現在の順列値を使用して更新します。 ループが終了すると、`l`は、スワップの前にアルゴリズムが返す位置です。 
3. 位置の値が`l`すでに`x`、ゼロスワップを出力します。 現在の順列はすでに必要な条件を満たしています。 
4. それ以外の場合は、位置の値を交換します`l`そして`pos[x]`。 この場所`x`まさに二分探索が終了する場所です。 
5. この単一のスワップを出力します。 

機能する理由: スワップ前のバイナリ検索パスが最終位置を決定します。`l`。 スワップは`x`そこには。 以前に検査できた唯一の変更された位置は、古い位置です。`x`。 調べた場合、値はそこから移動しました`l`最大でも`x`との元の比較と同じ方向を示します。`x`。 他のすべての比較は変更されないため、アルゴリズムは引き続き次の値に達します。`l`を含む位置を返します`x`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n, x = map(int, input().split())
        p = list(map(int, input().split()))

        pos = 0
        for i, v in enumerate(p):
            if v == x:
                pos = i
                break

        l = 0
        r = n
        while r - l > 1:
            m = (l + r) // 2
            if p[m] <= x:
                l = m
            else:
                r = m

        if p[l] == x:
            ans.append("0")
        else:
            ans.append("1")
            ans.append(f"{l + 1} {pos + 1}")

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```配列は内部で 0 から始まるインデックスを使用しますが、必要な出力では 1 から始まる位置が使用されます。 変換は、スワップを出力するときにのみ行われます。 

シミュレーションでは、ステートメントと同じ境界規則が使用されます。`l`は現在有効な左境界線であり、`r`は排他的な右ボーダーなので、条件は`r - l > 1`停止条件と完全に一致します。 

の検索`pos[x]`直線的です。 二分探索シミュレーションには対数時間がかかるため、ソリューション全体は順列を 1 回スキャンすることによって支配されます。
