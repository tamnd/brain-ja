 ## 解決策
 ## 問題の理解

 1 から n までのインデックスが付けられた家の列が与えられます。 家の所有者はそれぞれ、道路の左側または右側のどちら側に住みたいかという好みを持っています。 この設定はバイナリ文字列としてエンコードされます。0 は道路の左側にいたいことを意味し、1 は右側にいたいことを意味します。 

連続する 2 つの家の間、または最初の家の前や最後の家の後に道路を配置することが許可されています。 位置 i の後に道路を配置すると、住宅 1 から i が左側を形成し、住宅 i+1 から n が右側を形成します。 

道路の両側で、その側の住民の少なくとも半数が側の割り当てに満足している場合、その配置は許容されるとみなされます。 満足度は純粋にその人の好みと側面が一致するかどうかで決まります。 

タスクは、両側が「少なくとも半分満たされる」条件を満たすような有効なカット位置 i を見つけることであり、そのようなすべての有効なカットの中で、村の中央に最も近い位置を選択します。 中央は当然 n/2 付近にあるため、n/2 までの距離を最小化する有効な i が必要です。同点の場合は、小さい i が優先されます。 

入力サイズは最大 300,000 に達するため、すべてのカットを試行し、毎回セグメントをスキャンして満足度を再計算するソリューションは即座に除外されます。 位置ごとの直接チェックには O(n²) のコストがかかりますが、この規模では遅すぎます。 ソリューションでは、セグメント評価を位置ごとの一定時間に短縮する必要があり、これによりプレフィックスの合計が示唆されます。 

微妙な点は、「少なくとも半分」の定義にあります。 サイズ k のセグメントの場合、「半分」は ceil(k/2) を意味します。 これは奇数の長さの場合に重要であり、単純に k/2 を整数の除算としてチェックするのは正しくありません。 

片側が空の場合、エッジケースが発生します。 i = 0 の場合、左側には居住者がいません。同様に、i = n の場合、右側は空きです。 これらのケースでも条件は満たされる必要があり、空のセグメントは矛盾がないため有効です。つまり、居住者 0 人のうち満たされた 0 人が要件を満たします。 

単純なアプローチでは、各カットの満足度カウントを再計算する可能性があります。 たとえば、各 i で、スキャンによってプレフィックスの 0 とサフィックスの 1 をカウントする可能性がありますが、これは配列を繰り返し走査し、制約の下で失敗します。 

## アプローチ

 ブルートフォースのアイデアは単純です。 考えられるカット位置 i ごとに、配列を 2 つの部分に分割し、左側で 0 を好む人の数と 1 を好む人の数を右側で数えます。次に、それぞれの側の住民の少なくとも半数が満足しているかどうかを確認します。 これには、i ごとに左右のセグメントをスキャンする必要があり、各スキ​​ャンのコストは O(n) となり、合計作業量は O(n²) になります。 n が最大 300,000 の場合、これは約 10¹⁰ の操作となり、時間制限をはるかに超えます。 

重要な観察は、任意のセグメントに必要なすべての情報を段階的に事前計算できることです。 0 と 1 のプレフィックス カウントを維持すると、プレフィックスに関するあらゆるクエリに一定時間内に答えることができます。 サフィックスは、プレフィックスと合計数から導き出すことができます。 

これにより、問題は i ごとの単純な条件のチェックに変換されます。 残る唯一の微妙な点は、「少なくとも半分満たされる」制約を効率的に表現することです。 長さ k のセグメントの場合、少なくとも半分が満たされる必要があるということは、satisfied_count * 2 >= k + (k mod 2) を意味し、浮動小数点推論を回避し、奇数の長さを正しく処理します。 

O(1) で各カットを検証できたら、すべての位置をスキャンし、中心までの距離に応じて最も有効な位置を選択します。

## アルゴリズムのチュートリアル

 1. 0 と 1 のカウントのプレフィックス配列を構築します。 

これにより、セグメントを再度スキャンすることなく、任意の i について、左側のセグメントの何人の居住者が各側を好むかを計算できます。 
2. 配列全体の 1 の合計数を計算します。 

これは、プレフィックスの合計からの減算を使用して、サフィックス セグメントのカウントを迅速に取得するために必要です。 
3. 0 から n までのすべての可能なカット位置 i を繰り返します。 

各 i は家 i の後に道路を配置することを表し、i = 0 はすべてが右側にあることを意味し、i = n はすべてが左側にあることを意味します。 
4. 各 i について、左側のセグメント サイズと右側のセグメント サイズを計算します。 

左のサイズは i、右のサイズは n - i です。 
5. 両側の満足度を計算します。 

左満足カウントは、プレフィックス [1..i] 内のゼロの数です。 

右満足カウントは、サフィックス [i+1..n] 内の 1 の数であり、total_ones から prefix_ones[i] を引いたものとして計算されます。 
6. 両側の「少なくとも半分」条件を使用して実現可能性を確認します。 

不等式 2 *満足度カウント >= セグメントサイズ + (セグメントサイズ mod 2) を使用します。 
7. すべての有効な i の中から、n/2 までの距離を最小にするものを選択し、より小さい i で同点を解消します。 

### なぜ効果があるのか

 正しさは、双方の満足度が取り決めではなく集計数のみに依存するという事実に基づいています。 プレフィックス合計は、これらの集計を完全に保存します。 すべてのカットで配列が 2 つの独立したセグメントに分割されるため、それらを個別にチェックするだけで十分です。 半満足条件は満たされたカウントに関して単調であるため、カウントが正確にわかれば、曖昧さなく妥当性が決定されます。 最後の選択ステップは、有効な候補の有限セットに対する決定論的な最適化です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input().strip())
s = input().strip()

# prefix counts
pref0 = [0] * (n + 1)
pref1 = [0] * (n + 1)

for i, ch in enumerate(s, 1):
    pref0[i] = pref0[i - 1] + (ch == '0')
    pref1[i] = pref1[i - 1] + (ch == '1')

total1 = pref1[n]

def ok(i):
    left_size = i
    right_size = n - i

    left0 = pref0[i]
    right1 = total1 - pref1[i]

    # at least half condition: 2*x >= k + k%2
    if left_size > 0:
        if 2 * left0 < left_size + (left_size & 1):
            return False
    if right_size > 0:
        if 2 * right1 < right_size + (right_size & 1):
            return False

    return True

best_i = 0
best_dist = abs(n / 2 - 0)

for i in range(n + 1):
    if ok(i):
        dist = abs(n / 2 - i)
        if dist < best_dist or (dist == best_dist and i < best_i):
            best_dist = dist
            best_i = i

print(best_i)
```プレフィックス配列`pref0`そして`pref1`累積カウントを保存し、任意のプレフィックスに対する定数時間のクエリを可能にします。 機能`ok(i)`これらのプレフィックスを使用して左右の満足度カウントを計算することにより、カットが有効かどうかを評価します。 パリティ調整された不等式は浮動小数点除算を回避し、奇数のセグメント サイズを正しく処理します。 

最後のループではすべての位置をチェックし、中心からの距離に応じて最適な有効な位置を保持します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    input = _sys.stdin.readline

    n = int(input().strip())
    s = input().strip()

    pref0 = [0] * (n + 1)
    pref1 = [0] * (n + 1)

    for i, ch in enumerate(s, 1):
        pref0[i] = pref0[i - 1] + (ch == '0')
        pref1[i] = pref1[i - 1] + (ch == '1')

    total1 = pref1[n]

    def ok(i):
        left = i
        right = n - i
        left0 = pref0[i]
        right1 = total1 - pref1[i]
        if left > 0 and 2 * left0 < left + (left & 1):
            return False
        if right > 0 and 2 * right1 < right + (right & 1):
            return False
        return True

    best_i = 0
    best_dist = abs(n / 2 - 0)

    for i in range(n + 1):
        if ok(i):
            dist = abs(n / 2 - i)
            if dist < best_dist or (dist == best_dist and i < best_i):
                best_dist = dist
                best_i = i

    return str(best_i)

 ## 特殊なケース

 すべての居住者が同じ側を好む場合、各側は常に少なくとも半分が満足しているため、すべてのカットが有効になります。 その状況では、答えは純粋に中心への近さによって決まります。 プレフィックス数が一方の側で正確な飽和を生成し、もう一方の側でゼロを生成し、すべてのセグメントの不等式を満たすため、アルゴリズムは依然として有効なカットを正しく計算します。 

弦が激しく交互に切り替わる場合など、`010101`、グローバルなカウントのバランスが取れている場合でも、多くのカットはローカルで無効になります。 プレフィックスベースのチェックでは、各位置を個別に正しくフィルタリングし、部分的な不均衡がセグメント間で漏れないようにします。 

i が 0 または i が n の場合、片側は空になります。 このような場合、満足条件は空でない側のみをチェックすることになります。 コードは空サイドのチェックを明示的にスキップしているため、残りのサイドが条件を満たしていれば、これらのカットは自動的に有効なものとして処理されます。
