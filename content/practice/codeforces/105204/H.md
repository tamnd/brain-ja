 ## 解決策
 ## 問題の理解

 単語と、最終的なハッシュタグにすべて含める必要がある一連の「必須」単語で構成される投稿が与えられます。 ハッシュタグは投稿内で選択された単語から構成され、各単語の全長が合計コストに寄与します。 目標は、投稿からできるだけ少ない単語を削除して、残りの単語に必要なすべてのキーワードが少なくとも 1 回含まれるようにし、残りのすべての単語の合計の長さが制限を超えないようにすることです。$d$。 

言い換えれば、複数の語長のセットから始めます。 一部の位置は、少なくとも 1 回は含める必要がある必須の単語に対応するため、特別です。 任意の単語を削除することができますが、削除後も、すべての必須単語を少なくとも 1 回保持する必要があり、保持する単語の長さの合計は最大でも$d$。 削除する単語の数を最大化するか、保持する単語の数を最小限に抑えたいと考えています。 

この制約により、解は単語数において線形または線形に近いものでなければならないことが明確になります。 There are up to 30,000 keywords and 45,000 words in the text, so any approach that tries subsets or recomputes feasibility for each removal independently will be too slow. たとえ$O(m^2)$削除に関するシミュレーションはすでに時間制限を数桁超えてしまいます。 

必須の単語だけですでに制限を超えている場合、微妙なエッジの状況が発生します$d$。 たとえば、必要な単語が「a」（長さ 100,000）と「b」（長さ 100,000）である場合、$d = 150,000$の場合、この 2 つだけを維持しても合計は 200,000 になるため、解決策は存在しません。 もう 1 つのケースは、必要な単語がテキスト内に複数回出現する場合です。 少なくとも 1 つのコピーを保持する必要がありますが、より多くのコピーを保持することは常に有害であるため、最適なソリューションでは、必要な単語ごとに 1 つの出現のみが保持されます。 

2 番目の重要なシナリオは、必須ではない単語の削除は常に有益ですが、必須の単語の削除が禁止されている場合です。 これは重要な構造につながります。必須の単語は固定されたバックボーンを形成し、それ以外はすべて、和の制約を満たすために削除できるオプションの重みです。 

## アプローチ

 強引なアイデアは、必要な各単語が少なくとも 1 回出現する単語のサブセットをすべて試して、その全長をチェックすることです。 これは概念的には正しいですが、すぐには実行不可能です。$2^m$サブセット。 必須ではない単語に注意を制限しても、依然として指数関数的な組み合わせが残ります。 

重要な観察は、制約が純粋に加法的であるということです。重要なのは全体の長さだけであり、実現可能性は、必要な単語はそのままにしながら不要な単語を削除して合計を削減できるかどうかにのみ依存します。 これにより、問題は寄与をめぐる貪欲な選択の問題に変わります。 

強制される唯一の構造から始めます。必須の単語ごとに、少なくとも 1 つの出現を保持する必要があります。 必須の単語が出現するすべての中で、避けられないベースライン コストを最小限に抑えるため、常に最短の単語を保持する必要があります。 それ以上発生しても、追加の利益は得られずに合計が増加するだけです。 

必須単語ごとに代表的な出現箇所を 1 つ固定した後、他のすべての単語はオプション項目になります。 問題は、合計の長さが範囲内に収まるように保持するオプションの単語のサブセットを選択することになります。$d$。 削除を最小限に抑えたいため、同様に、総和制約が許可する場合に限り、できるだけ多くのオプションの単語を保持したいと考えます。 

これは古典的な貪欲削減問題になります。選択した必要なすべての単語とオプションのすべての単語から開始して合計を計算し、合計が適合するまで最大のオプションの単語を繰り返し削除します。 大きな単語を最初に削除すると、各削除でステップごとに最大の削減が得られるため、予算の制約を満たすために必要な削除の数が最小限に抑えられます。

 | 選択と並べ替えに貪欲 |$O(m \log m)$|$O(m)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 必要な単語をすべてハッシュ セットに読み込み、単語ごとに一定時間でメンバーシップをテストできるようにします。 
2. テキストをスキャンし、必要な単語の出現をグループ化します。 必要な単語ごとに、その単語の最小長の出現を維持するだけで済みます。 これにより、固定の必須コストが発生します。 
3. テキスト内のすべての単語を必須またはオプションに分類します。 省略可能な単語はすべて削除の候補です。 
4. 選択した必須オカレンスの合計として基本コストを計算します。 これがすでに超えている場合$d$、削除を行わないと必要な貢献度が減少する可能性があるため、すぐに -1 を出力します。 
5. 最初にすべての単語を保持した場合の総コスト、つまりすべての単語の長さの合計を計算します。 
6. 削減する必要がある量は$total - d$。 最小限の削除でこれを達成するために、オプションの単語を長さの降順で並べ替え、最大の単語から繰り返し削除し、必要な削減に達するまで保存された長さを蓄積します。 
7. 削除された単語の数は、このプロセスで廃棄されたオプションの単語の数です。 

重要な考え方は、必須の単語が固定の下限を定義し、その他すべてが独立した取り外し可能なウェイトのように動作するということです。 ソートにより、各削除が最大限の削減に貢献することが保証されます。 

### なぜ効果があるのか

 不変条件は、すべてのステップで、必須の各単語が少なくとも 1 回出現する保持された単語のセットを維持することです。 正確に削除するためのすべての実行可能な方法の中で$k$オプションの単語、選択$k$最大のワードは可能な限り最小の残りの合計を生成します。 実現可能性は合計が以下になるかどうかのみに依存するため、$d$、この貪欲な順序付けにより、任意のセットが存在する場合、$k$削除も機能しますが、貪欲な選択も機能します。 これにより、必要な削除の数が過大評価されることがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    
    keywords = set()
    for _ in range(n):
        keywords.add(input().strip())
    
    words = input().split()
    d = int(input())
    
    # required occurrences: keep at least one per keyword
    from collections import defaultdict
    best_required = {}
    
    optional = []
    total_sum = 0
    
    for w in words:
        L = len(w)
        total_sum += L
        
        if w in keywords:
            if w not in best_required:
                best_required[w] = L
            else:
                best_required[w] = min(best_required[w], L)
        else:
            optional.append(L)
    
    required_sum = sum(best_required.values())
    
    if required_sum > d:
        print(-1)
        return
    
    # we initially assume we keep all words, but we can drop optional ones
    optional.sort(reverse=True)
    
    removed = 0
    saved = 0
    
    for L in optional:
        if total_sum - saved <= d:
            break
        saved += L
        removed += 1
    
    print(removed)

if __name__ == "__main__":
    solve()
```実装は、高速検索のためにキーワードをセットに分割することから始まります。 投稿をスキャンしている間、各キーワードの最小長の出現が維持されます。これは、重複が長く出現することは、厳密に最も短いものよりも悪いためです。 

オプションの単語は、その寄与のみが重要であるため、長さとしてのみ保存されます。 合計額と必要なベースラインを計算した後、実現可能性を確認します。 義務的なベースラインさえ超えた場合$d$、早期終了させて​​いただきます。 

貪欲な削除ループは、長さの降順にソートされたオプションの単語を処理します。 各反復では、現在残っている最大の単語の削除をシミュレートし、全長がどれだけ短縮されたかを追跡します。 残りの金額が収まったら$d$、やめます。

 ## 特殊なケース

 重大なエッジケースは、必要な単語だけが制限を超える場合です。 たとえば、必要な単語が十分に長く、その最小出現回数がすでに違反している場合$d$の場合、アルゴリズムはベースライン合計を計算した後、すぐに -1 を返します。 これにより、不必要な並べ替えや処理が回避されます。 

別のケースでは、必要な単語が異なる長さで繰り返されます。 必須の単語が長さ 10、5、7 で複数回出現するとします。アルゴリズムは必須コストとして 5 のみを保持します。 これにより、避けられない長さを過大評価することがなくなります。 誤ってすべての発生を保持した場合、有効な解が存在する場合でも、解は存在しないと誤って結論付ける可能性があります。 

最後のエッジケースは、オプションの単語がすべて必須の単語より短い場合です。 それでも、削除順序は必要な単語との比較ではなく、削除ごとの削減の最大化のみに依存するため、並べ替えは依然として正しく機能します。
