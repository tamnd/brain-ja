 ## 問題の理解

 固定予算と、それぞれ固定コストの 2 種類のアイテムが与えられます。 タスクは、最初のタイプのアイテムをいくつか購入し、2 番目のタイプのアイテムをいくつか購入することで予算に正確に一致するかどうかを判断することです。ただし、それぞれ 0 個以上購入することができます。 

より具体的に言えば、価格の線形結合が総予算と等しくなるような、2 つのアイテム タイプの数を表す 2 つの非負の整数が存在するかどうかを知りたいと考えています。 そのようなペアが存在する場合は、有効なペアを 1 つ出力する必要があります。 それ以外の場合は不可能であると報告します。 

制約により、予算と価格は最大 1,000 万まで可能です。 このサイズでは、考えられるすべてのカウントのペアを反復するものは除外されます。 可能な量を二重ループすると、おおよそ次のようになります。$10^{14}$合理的な制限時間をはるかに超えた最悪の場合の作戦。 1 つのアイテムの可能なすべての数量 (最大 1,000 万個) にわたる単一ループですら境界線に達しますが、各ステップが O(1) であれば通過できます。これは、解決策の方向です。 

アイテムの価格の 1 つが 1 の場合、微妙なエッジ ケースが発生します。その状況では、そのアイテムを使用して残りをいつでも調整できるため、答えは常に簡単に「はい」になります。 もう 1 つのエッジケースは、両方の価格が予算よりも高い場合です。 その場合、可能な合計はゼロのみであるため、制約によって除外される予算がゼロでない限り、答えは即座に「ノー」になります。 

素朴な推論のさらに興味深い失敗例は、すべての組み合わせを対称的に試す必要があると仮定することです。 たとえば、$n = 7, a = 2, b = 3$、すべてのペアを試しても問題ありません。 しかし、$n = 10^7$、$a = 2$、$b = 3$、有効な解決策が存在する場合でも、ブルート フォースは実行不可能になります。 

## アプローチ

 直接的なアプローチは、最初の項目の可能な数をすべて試してみることです。 それぞれの選択に対して$x$、残りのお金を計算します$n - x \cdot a$2番目のアイテムを使用して形成できるかどうかを確認します。 これは、剰余が負でなく、次で割り切れるかどうかを確認することを意味します。$b$。 このアプローチは、一方の変数のすべての有効な値を体系的に探索しながら、もう一方の変数を決定論的に計算するため、正しいです。 

問題はその範囲です$x$。 最悪の場合、$a = 1$、 それで$x$まで走る$10^7$。 各反復は O(1) ですが、ループは依然として 1,000 万回の反復を実行します。 これは Python では許容されますが、非効率性が生じる余地はなく、さらに重要なことに、これは私たちがもっと改善できることを示唆しています。 

重要な観察は、次のすべての値を試す必要はないということです。$x$。 有効なペアが存在するかどうかのみを気にするため、モジュール構造を利用することで検索スペースを減らすことができます。 方程式$x \cdot a + y \cdot b = n$に並べ替えることができます$y = (n - x \cdot a) / b$。 すべてをスキャンするのではなく、$x$、残余クラスにヒットすることを確認するだけで済みます。$n - x \cdot a$で割り切れるようになる$b$。 

これは、2 つの変数と非負以外の制約を持たない線形ディオファントス問題の標準的なトリックにつながります。つまり、1 つの次元のみを、他の係数から導出される小さな限界まで反復処理します。 増えてからは$x$による$b$式のモジュロを変更します$b$、せいぜいテストするだけで済みます$b$候補はいくつかありますが、次まで繰り返すことでさらに簡素化できます。$n / a$、これでも安全で簡単に実装できます。 

より効率的な観点は、ロールを交換して、常に 2 つのコストの小さい方を反復することです。 それはせいぜい$10^7 / 1 = 10^7$最悪の場合は反復回数が発生しますが、通常ははるかに少なくなります。

 ## アルゴリズムのチュートリアル

 1 つの変数の値を試し、もう 1 つの変数を直接計算すると仮定します。 

1. コストが小さい項目を最初に反復するようにします。 これにより、最悪の場合に必要な反復回数が減少します。 
2. 可能なすべてのカウントをループします。$x$そのような$x \cdot a \leq n$。 それぞれ$x$は、最初のタイプのアイテムをその数だけ購入することを表します。 
3. それぞれについて$x$、それらのアイテムを購入した後の残りのお金を計算します。 これは$rem = n - x \cdot a$。 これが負になると、さらに次の値が$x$それはさらにネガティブになるだけなので、やめておきます。 
4. 2 番目の項目を使用して余りが正確に形成できるかどうかを確認します。 これは次の場合にのみ当てはまります$rem \% b = 0$。 
5. 割り切れる場合は計算する$y = rem // b$そしてペアを出力します$(x, y)$。 これにより、合計が正確に一致することが保証されます。 
6. 有効でない場合$x$有効な結果を生成します$y$、NOを出力します。 

### なぜ効果があるのか

 すべての有効な解は、次の値に対応します。$x$列挙した範囲内で、どのソリューションも満たす必要があるため、$x \cdot a \le n$。 そういったそれぞれに対して$x$、の値$y$存在するかどうかは一意に決まります。 実現可能なものはすべて出し尽くしたので、$x$の有効な分解を見逃すことはできません。$n$。 正確かどうかは、最初の変数が固定されると 2 番目の変数が独立して選択されないという事実にかかっています。 それは方程式によって完全に決定されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = int(input())
b = int(input())

# iterate over smaller unit cost first for efficiency
if a > b:
    a, b = b, a

found = False

for x in range(n // a + 1):
    rem = n - x * a
    if rem < 0:
        break
    if rem % b == 0:
        y = rem // b
        print("YES")
        print(x, y)
        found = True
        break

if not found:
    print("NO")
```コードはまず問題を正規化して、より安価な項目を反復処理することで、ループの反復を減らします。 対称方程式内の変数の名前を変更しているだけなので、この交換によって正確さが変わることはありません。 

ループ境界`n // a + 1`の実現可能な値のみを考慮することを保証します$x$。 剰余チェックにより、無効な分解が試行されないことが保証されます。 割り算テストでは、問題で必要とされる 2 番目の変数が整数であることが保証されます。 

ここでよくある間違いは、交換を忘れることです`a`そして`b`出力変数の意味を変更します。 スワップ後、出力されたペアはスワップされた役割に対応します。これは、依然として有効な分解を返しているため、一貫性があります。
