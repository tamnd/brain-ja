 ## 解決策

 ## 問題の理解

 の配列が与えられます$n$各山にはある程度の数のキャンディーが含まれています。 1 回の操作で、1 つの山をキャンディー 1 個だけ増減できます。 私たちの目標は、値を等しくしたり、個別に最適化したりすることではなく、山のちょうど半分に完全な正方形が含まれ、残りの半分に非正方形が含まれるように値を調整することです。 

ここでの完全正方形とは、次の形の数を意味します。$k^2$ある整数に対して$k \ge 0$。 すべての山は独立して変更できますが、各ユニットの変更には 1 回の移動が必要です。 重要な問題は、山ごとに独立して値を選択していないことです。 私たちは正確に選択しなければなりません$n/2$山は正方形になるようにし、残りは強制的に非正方形にする必要があります。 

制約により許可されるのは、$n$最大 200,000、最大値$10^9$。 これにより、すべての値に対する変換をシミュレートしたり、前処理を行わずに負荷の高い方法で各パイルの最短パスを個別に再計算しようとするアプローチは即座に除外されます。 どのような解決策でも、前処理後に問題をほぼ線形の作業に減らす必要があります。 

素朴な考えは、各山を独立して扱い、それを正方形に変換するか非正方形に変換するかを貪欲に決定することです。 これは、選択がグローバルに相互作用するため失敗します。パイルを正方形にするのは安価かもしれませんが、カーディナリティの制約により、それを非正方形のグループに割り当てることを余儀なくされる可能性があります。 

2 番目の微妙な問題は、山がすでに正方形である場合に発生します。 欲張って正方形のままにしておくと、後で合計すると正方形の山が多すぎることが判明し、以前は残るだろうと思っていても、一部の正方形を高コストで変換しなければならなくなる可能性があります。 

たとえば、遠く離れたいくつかの数字を除いて、多くの数字がすでに正方形である場合を考えてみましょう。 貪欲な「最も近いものを修正する」戦略は、早い段階で正方形の割り当てに過剰にコミットし、後でいくつかの正方形を変換するために多額のコストを支払うことを余儀なくされる可能性があります。 

問題は基本的に正確に選択することです$n/2$2 つのラベルのそれぞれにアイテムがあり、各アイテムにはどのラベルを割り当てるかに応じてコストがかかります。 これはグローバルな割り当ての問題であり、要素ごとに独立しているわけではありません。 

## アプローチ

 大域的な制約を無視すると、各杭には 2 つの自然コストが発生します。 1 つは正方形に変えるためのコスト、つまり最も近い完全な正方形までの距離です。 もう 1 つは、非正方形に変えるためのコストです。これはより微妙です。すでに非正方形である場合、コストはゼロです。 それが正方形の場合、それを最も近い非正方形の整数に移動する必要があります。これは、最も近い正方形の境界から両方向に 1 単位離れており、小さな一定コストの近傍が得られます。 

ブルートフォース戦略では、あらゆる方法で選択を試みます。$n/2$積み重ねて正方形になります。 がある$\binom{n}{n/2}$そのような選択は、たとえ小規模であっても完全に実行不可能です$n$。 接頭辞と選択された正方形の数に対して動的プログラミングを試みたとしても、依然として処理が行われることになります。$O(n^2)$州。 

重要な観察は、各杭が 2 つの考えられるコストに独立して寄与しており、正確に選択するだけでよいということです。$n/2$1 つのカテゴリのアイテム。 これは、古典的な「コスト差を最小限に抑える正確に k 個の項目を選択する」構造です。 

各山について、それを正方形にするコストと非正方形にするコストの 2 つの値を計算します。 最初に、すべての杭がより安価なまたは任意のベースライン カテゴリ、たとえば非正方形に割り当てられていると仮定し、杭を正方形ステータスに切り替える「追加コスト」を計算します。 その後、タスクは正確に選択することになります。$n/2$各選択のデルタコストは、「正方形のコストから非正方形のコストを引いたもの」に等しくなります。 

これらのデルタを並べ替えると、最適な割り当てが得られます。$n/2$最小のデルタは正方形になります。 これは標準的な交換引数です。選択された要素のデルタが選択されていない要素よりも大きい場合、交換によりカウントの制約を維持しながら総コストが削減されます。

 | 最適 (ソート + 貪欲な選択) | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各パイル値について$a_i$、最も近い完全二乗値を計算します。 それを正方形にするコストは、最も近い正方形との絶対的な差です。 これは、平方値が整数の間に存在する必要があるため機能します。$k^2$、および最も近いもの$k^2$絶対的な調整コストを最小限に抑えます。 
2. 杭を非正方形にするためのコストを計算します。 もし$a_i$すでに正方形ではないため、このコストは 0 です。正方形の場合は、最も近い非正方形の整数に移動する必要があります。これは 1 回の操作です (どちらかの場合)。$a_i-1$または$a_i+1$は常に非正方形です$a_i > 0$）。 
3. 各パイルについて、デルタ値を計算します。$$d_i = \text{cost to make square} - \text{cost to make non-square}.$$これは、この山を非正方形グループではなく正方形グループに割り当てるとどれだけコストがかかるかを表します。 
4. すべて並べ替える$d_i$値を昇順に並べます。 
5. 正確に選択する$n/2$最小のものを積み重ねます$d_i$そしてそれらを正方形に割り当てます。 他のすべては非正方形に割り当てられます。 
6. 最終的な答えは次の合計です。 

すべての山を非正方形にするための基本コストに、選択した山のデルタを加えたもの$n/2$山。 

ステップ 6 が機能する理由は、問題を均一な割り当て (すべて非正方形) から開始し、その後追加料金を払って選択した山を正方形ステータスにアップグレードするものとして再解釈しているためです。 

### なぜ効果があるのか

 各パイルには、固定コストを持つ有効な「状態」が 2 つだけあります。 有効な最終構成は、サイズのサブセットの選択に対応します。$n/2$正方形の状態に割り当てます。 総コストは選択肢において線形であるため、基本コストと項目ごとの独立した調整に分解されます。 

選択された項目と選択されていない項目の間の反転は、制約を維持しながらコストを削減または維持する交換を意味するため、ソート引数によって最適性が保証されます。 この交換を繰り返し適用すると、ソートされた選択が最適になります。これは、独立した重みを持つ固定サイズのサブセット選択に対する標準的なマトロイド スタイルの貪欲なプロパティです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def is_square(x: int) -> bool:
    if x < 0:
        return False
    r = int(x ** 0.5)
    return r * r == x or (r + 1) * (r + 1) == x

def closest_square_cost(x: int) -> int:
    r = int(x ** 0.5)
    best = abs(x - r * r)
    best = min(best, abs(x - (r + 1) * (r + 1)))
    if r > 0:
        best = min(best, abs(x - (r - 1) * (r - 1)))
    return best

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    deltas = []
    base = 0

    for x in a:
        sq_cost = closest_square_cost(x)

        if is_square(x):
            non_sq_cost = 1
        else:
            non_sq_cost = 0

        base += non_sq_cost
        deltas.append(sq_cost - non_sq_cost)

    deltas.sort()
    ans = base + sum(deltas[:n // 2])
    print(ans)

if __name__ == "__main__":
    solve()
```実装は、最も近い正方形までの距離の観点から各杭を分類することから始まります。 最も近い平方コストを計算する関数は、最も近い平方が次の平方根にある必要があるため、隣接する平方根を明示的にチェックします。$\lfloor \sqrt{x} \rfloor^2$、$(\lfloor \sqrt{x} \rfloor + 1)^2$、または切り捨てたときの前の正方形が大きい場合もあります。 

次に、すべての杭が非正方形になると仮定してベースラインを計算します。 非正方形の変換は無料か 1 回のコストで行われ、簿記が簡素化されるため、これは重要です。 

デルタ配列は、山を正方形カテゴリに切り替えるのにどれだけのコストがかかるかをエンコードします。 並べ替えにより、$n/2$最も有益なスイッチが選択されます。 

実装の微妙な詳細は、ゼロの処理です。 ゼロは完全な正方形ですが、最も近い非正方形は 1 であるため、ゼロを非正方形に変換する場合もコストは 1 です。

 ## 特殊なケース

 重要なエッジケースは、多くの値がすでに完全な正方形である場合です。 たとえば、配列が`[0, 1, 4, 9]`、すべての要素は正方形カテゴリから始まります。 このアルゴリズムは、それぞれを正方形として維持する場合と非正方形に変換する場合のコストを反映するデルタを計算します。 のみを割り当てる必要があるため、$n/2$正方形の場合、ちょうど 2 つの要素が非正方形グループに強制的に入れられます。 並べ替えにより、変換が最も安価であるため、最も苦痛の少ない変換 (通常は 0 や 1 などの最小の正方形) が確実に選択されます。 

もう 1 つの微妙なケースは、次のような正方形の要素がない場合です。`[2, 3, 5, 6]`。 ここで、正方形以外のコストはすべてゼロであり、デルタは純粋に正方形に到達するためのコストです。 このアルゴリズムは、最も安価な 2 つの正方形への変換を選択します。これにより、半分が正方形になる必要があるという要件を満たしながら、全体の調整が正しく最小化されます。 

最後に、値 0 は完全な正方形ですが非対称に動作するため重要です。これを非正方形に変えると常に 1 のコストがかかりますが、近くの数値を正方形にすると小さい値がかかる可能性もあります。 両方のコスト関数が対称性の仮定に依存するのではなく明示的に計算されるため、アルゴリズムはこれを正しく処理します。
