 ## 解決策
 ## 問題の理解

 グループ内の生徒が試験後にどのように行動したかに関する要約統計が与えられます。 すべての学生は、4 つのカテゴリのいずれかに正確に属します。つまり、BugDonalds のみ、BeaverKing のみ、両方のレストランを訪れたか、試験に失敗したため家にいたかのいずれかです。 

入力から、BugDonalds を訪れた学生の合計数、BeaverKing を訪問した学生の合計数、両方の場所を訪れた学生の数、およびグループ内の学生の合計数がわかります。 課題は、これらの統計が学生の有効な分布から得られるかどうかを確認し、得られる場合は、試験に落ちて自宅に留まった学生の数を計算することです。 

重要な隠れた構造は、レストランの数がバラバラではないことです。 「両方のレストラン」を表す値は両方の合計内でカウントされるため、個別の訪問者の実際の数は慎重に再構築する必要があります。 少なくとも 1 つのレストランを訪れた学生の数がわかれば、残りの学生は全員家にいたはずです。 

制約は小さく、すべての値が最大 100 であるため、テスト ケースごとに一定時間で実行されるソリューションであれば十分であることがすぐにわかります。 100 で区切られた 4 つのカテゴリのすべての分布を強引に列挙することも可能ですが、その必要はありません。 

微妙な失敗のケースは、重複と合計の不一致から発生します。 よくある間違いの 1 つは、重複部分が A と B の両方に含まれていることを忘れることで、不可能なマイナスのカウントや過剰カウントにつながります。 

いくつかの具体的な無効なシナリオは、以下を明確にするのに役立ちます。 

A = 1、B = 1、C = 1、N = 1 の場合、A と B の両方が各レストランに少なくとも 1 人の学生が存在することをすでに暗示していますが、注意深く調整しない限り 1 人の学生がすべてのカウントを同時に満たすことはできないため、重複により矛盾が生じます。 

A = 2、B = 2、C = 3 のように、C が A または B のいずれよりも大きい場合、「両方」が「いずれかの合計」を超えることはできないため、これは直ちに不可能になります。 

A + B − C が N を超える場合、重複を考慮する前でさえ、グループ内に存在するよりも多くの生徒がすでに必要となります。 

これらの不一致は、アルゴリズムが検出する必要があるものです。 

## アプローチ

 強引な解釈では、N 人の生徒のそれぞれを 4 つの州のいずれかに割り当て、必要な数 A、B、C が正確に一致するかどうかを確認しようとします。 これには、N を 4 つのグループに分割するすべての可能性を反復し、制約を検証することが含まれます。 3 つを固定すると自動的に 4 つ目が決定されるため、N を 4 つの非負の整数に分割する方法の数は N3 のオーダーになります。 N ≤ 100 なので、これはかろうじて許容可能ですが、基本的には直接算術再構成問題であるため、これは不必要な複雑さになります。 

重要な観察は、オーバーラップ構造がパーティションを完全に決定するということです。 x はバグドナルドのみ、y はビーバーキングのみ、z は両方のレストラン、w は家にいるとします。 次に、A = x + z、B = y + z、および C = z となります。 これにより、すぐに x = A − C および y = B − C が得られます。これらが決定されると、少なくとも 1 つのレストランを訪れた生徒の総数は x + y + z = A + B − C となります。残りの生徒は w = N − (A + B − C) となります。 

全体の問題は、これらの導出された値がすべて非負の整数であるかどうか、およびそれらの合計が一貫して N になるかどうかをチェックすることに帰着します。違反がある場合は、入力が不可能であることを示します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N3) | お(1) | 遅すぎる/不必要 |
 | 最適 | お(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 代数を使用して、指定された合計から 4 つのカテゴリを再構成し、実現可能性を検証します。

1. 両方のレストランを訪れた学生の数を計算します (z = C で示されます)。これは直接与えられるため、推論は必要ありません。 
2. x = A − C、バグドナルドのみを訪問した生徒の数を計算します。 これにより、両方にカウントされた人が BugDonalds 訪問者の合計から削除されます。 
3. y = B − C、つまり BeaverKing のみを訪問した生徒の数を計算します。 これは 2 番目のレストランに適用される対称的な推論です。 
4. 少なくとも 1 つのレストランを訪れた学生の数を x + y + z として計算します。 z は正しくキャンセルされるため、これは A + B − C に単純化されます。 
5. 家にいた生徒の数を w = N − (A + B − C) として計算します。 これは試験に落ちた人を表します。 
6. 妥当性条件を確認します。x、y、z、および w はすべて非負でなければなりません。 いずれかが負の場合、カウントは現実と矛盾し、-1 を出力します。 
7. 有効な場合、w が不合格になった生徒の数として出力されます。 

これが機能する理由: 4 つの素なグループへの分解は、包含と排除によって強制されます。 すべての生徒は独自に分類されており、両方のレストランの合計を同時に満たすには公式が唯一の方法です。 非否定性の違反は、不可能な重複構造、またはグループの合計サイズと再構築された参加の間の不一致に対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    A, B, C, N = map(int, input().split())

    x = A - C
    y = B - C
    z = C

    if x < 0 or y < 0:
        print(-1)
        return

    total_attended = x + y + z  # equals A + B - C
    w = N - total_attended

    if w < 0:
        print(-1)
        return

    print(w)

if __name__ == "__main__":
    solve()
```実装は再構築された変数に直接続きます。 唯一の微妙な点は、減算によって無効な負のカウントが暗黙的に生成されないようにすることです。 x と y は物理的な生徒数を表し、負になることはできないため、先に進む前に明示的にガードします。 最終チェックでは、再構成された出席学生がグループのサイズを超えていないことを確認します。 

## 実用的な例

 ### 例 1

 入力:

 A = 10、B = 10、C = 5、N = 20

 次のように計算します。 

| ステップ | × | y | z | 出席合計 | w |
 | --- | --- | --- | --- | --- | --- |
 | 開始 | - | - | - | - | - |
 | オーバーラップを計算する | - | - | 5 | - | - |
 | バグドナルドのみ | 10−5 = 5 | - | 5 | - | - |
 | ビーバーキングのみ | 5 | 10−5 = 5 | 5 | - | - |
 | 訪問合計 | 5 | 5 | 5 | 15 | - |
 | ホーム | 5 | 5 | 5 | 15 | 20−15 = 5 |

 再構成されたすべてのグループが負ではなく、合計がグループ サイズと一致するため、結果は有効です。 出力は 5 で、5 人の生徒が家にいたことを意味します。 

### 例 2

 入力:

 A = 2、B = 2、C = 2、N = 3

 | ステップ | × | y | z | 出席合計 | w |
 | --- | --- | --- | --- | --- | --- |
 | オーバーラップ | - | - | 2 | - | - |
 | バグドナルドのみ | 2−2 = 0 | - | 2 | - | - |
 | ビーバーキングのみ | 0 | 2−2 = 0 | 2 | - | - |
 | 訪問合計 | 0 | 0 | 2 | 2 | - |
 | ホーム | 0 | 0 | 2 | 2 | 3−2 = 1 |

 これは有効で、自宅に生徒が 1 人いることになります。 代わりに N が 1 であれば、負の w が得られ、すぐに矛盾が証明されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    A, B, C, N = map(int, sys.stdin.readline().split())

    x = A - C
    y = B - C
    z = C

    if x < 0 or y < 0:
        return "-1"

    total_attended = x + y + z
    w = N - total_attended

    if w < 0:
        return "-1"

    return str(w)

# provided sample
assert run("10 10 5 20\n") == "5"

# all stayed home
assert run("0 0 0 5\n") == "5"

# impossible overlap
assert run("2 2 3 5\n") == "-1"

# impossible due to group size
assert run("10 10 0 5\n") == "-1"

# exact full attendance
assert run("3 3 3 3\n") == "0"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 0 0 0 5 | 5 | 生徒全員が不合格でした |
 | 2 2 3 5 | -1 | 無効なオーバーラップ (C > A、B) |
 | 10 10 0 5 | -1 | 出席者がグループの人数を超えている |
 | 3 3 3 3 | 0 | 全員が出席しましたが、家には誰もいません |

 ## 特殊なケース

 A、B、C がすべてゼロで、N が正の場合、アルゴリズムは x = 0、y = 0、z = 0、total_attended = 0 を計算します。したがって、w = N となります。これは、すべての生徒が自宅にいることに対応します。これは有効であり、否定的なチェックがトリガーされないため、正しく処理されます。 

A = 2、B = 1、C = 3 など、C が A または B のいずれかを超える場合、計算では x = −1 または y = −2 が生成されます。 アルゴリズムは、合計を計算する前にこのケースを即座に拒否し、重複が合計カテゴリを超えることができないことを正確に識別します。 

A + B − C が N を超える場合 (A = 10、B = 10、C = 0、N = 15 など)、total_attended = 20 および w = −5 になります。 この否定的な結果は、不可能であることを直接示しており、再構成された参加者数がグループのサイズを超えていることを反映しています。
