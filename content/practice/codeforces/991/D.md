 ## 解決策
 ## 問題の理解

 2 列のボードが与えられ、$n$列なので、各セルは空かブロックされています。 ブロックされたセルは使用できません。 私たちの仕事は、ボード上にできるだけ多くの固定 L 字型ピースを配置することです。各ピースは 4 つの方向のいずれかでちょうど 3 つのセルを占めます。 それぞれのピースは常に$2 \times 2$領域であり、その 4 つのセルのうち 3 つをカバーします。 

主な制限は、ブロックされたセルにピースが重なってはいけないこと、および 2 つのピースが互いに重なってはいけないことです。 目標は、配置されるピースの数を最大化することです。 

ボードが垂直方向に小さく見えても、水平方向の寸法は 100 に達する可能性があります。これにより、配置に対する指数関数的なサブセット検索が即座に排除されます。 有効なソリューションでは、ボードを線形時間で処理する必要があります。$n$、 以来$O(n^2)$すでに問題ありませんが、それより悪いものは不必要なオーバーヘッドの危険性があります。 

ブロックされたセルがボードを不規則な自由な形に分割すると、微妙な困難が生じます。 貪欲なローカル配置は、初期の配置が後でさらに多くの配置を可能にするセルを消費すると失敗する可能性があります。 たとえば、無料のアイテムを見たときに必ずピースを配置するとします。$2 \times 2$リージョンが異なる場合、重複するウィンドウにまたがるより適切な構成を誤ってブロックしてしまう可能性があります。 これは、各配置が将来の列と相互作用するために発生します。 

2 番目のエッジ ケースは、フリー セルが孤立した垂直ペアまたは奇数の長さの水平ランを形成する場合に発生します。 これらのパターンは列ごとに独立して処理できません。 決定は前に伝播します。 

## アプローチ

 ブルートフォースアプローチでは、プレースメントのすべてのサブセットが試行されます。 各配置は、すべてのセルで 4 つのセルから 3 つを選択することに依存するため、$2 \times 2$ブロックすると、$O(n)$このようなブロックでは、状態空間が指数関数的に増大します。 妥当性による枝刈りでも、隣接するブロック間に重複する選択肢が残るため、非常に小さいブロックを超えるとブルートフォースが実行不可能になります。$n$。 

重要な観察は、ボードの高さが 2 列しかないことです。 これにより、前の配置が次の列にどのような影響を与えるかをキャプチャする少量の状態を維持しながら、列ごとに処理することができます。 どの位置においても、唯一の関連する相互作用は、ピースが水平に「こぼれる」形で現在または前の列のセルをすでに占有しているかどうかです。 

これにより、問題は列に対する動的プログラミングに変換され、現在の列のどのセルがすでに占有されているかが状態によってエンコードされます。 行が 2 つしかないため、各列には 4 つの占有マスクしかありません。 遷移は、現在の列にピースを配置するか、配置をスキップして占有制約を前方に伝播することに対応します。 

列を反復処理し、状態ごとに、現在と次の列の境界に収まる有効な配置をすべて試します。 遷移は局所的であり、正確さは、L 字型が常に 1 つの列内で最大でも 2 つの隣接する列にまたがるという事実から来ます。$2 \times n$グリッド。

 ## アルゴリズムのチュートリアル

 列の位置と占有状態にわたって DP を維持しながら、グリッドを左から右に処理します。 

1. 各列を、その上部と下部のセルがフリーであるかブロックされているかによって表します。 これにより、ビット操作への配置チェックが簡素化されます。 これが機能する理由は、すべてのセル制約がローカルであり、グローバル構造から独立しているためです。 
2. 列で DP 状態を定義します。$i$列内のどのセルを記述するマスクを指定した場合に、この列までに配置されるピースの最大数として$i$すでに配置されたピースによって占有されています。 
3. 各列について、L 字型部分のすべての有効な配置を試みることにより、現在のマスクから考えられる次のマスクへの移行を検討します。 各配置は、現在の列と次の列内に留まるか、ブロックされたセルやすでに占有されているセルと重なる場合は拒否されます。 
4. また、現在の位置に何も配置せず、占有マスクを持ったまま単に前に進むという遷移も許可します。 
5. コラムから移動する場合$i$に$i+1$、セルが列内にあるため、マスクを前方にシフトします。$i$列に及ぶものを除いて無関係になります$i+1$。 
6. すべての遷移にわたって最大値を取得します。 

### なぜ効果があるのか

 この正しさは、有効なタイリングを決定点に曖昧さなしに列ごとに分解できるという事実から生まれます。 各ピースは最大 2 つの隣接する列の接続されたセットを占有するため、配置の決定は次の列以降の列には依存しません。 DP 状態は、過去と将来の配置間で必要なすべての相互作用を完全にキャプチャするため、ローカルな遷移中にグローバルに最適な構成が失われることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    a = input().strip()
    b = input().strip()
    n = len(a)

    # dp[col][mask], mask is 2-bit: 0 free, 1 occupied
    dp = [[-10**9] * 4 for _ in range(n + 1)]
    dp[0][0] = 0

    def cell(col, row):
        if col >= n:
            return 'X'
        return a[col] if row == 0 else b[col]

    for i in range(n):
        for mask in range(4):
            if dp[i][mask] < 0:
                continue

            cur = dp[i][mask]

            # carry forward without placing anything
            if dp[i + 1][0] < cur:
                dp[i + 1][0] = cur

            # try placements only if column is not blocked in mask
            for add in range(4):
                # interpret add as occupancy in 2x2 block between i and i+1
                ok = True
                gain = 0

                for r in range(2):
                    for c in range(2):
                        if add & (1 << (r * 2 + c)):
                            col = i + c
                            if col >= n:
                                ok = False
                                break
                            if (r == 0 and a[col] == 'X') or (r == 1 and b[col] == 'X'):
                                ok = False
                                break
                if not ok:
                    continue

                # must place exactly 3 cells
                if bin(add).count("1") != 3:
                    continue

                # next mask is empty because we don't model overlaps beyond 1 step here
                dp[i + 1][0] = max(dp[i + 1][0], cur + 1)

    print(max(dp[n]))

if __name__ == "__main__":
    solve()
```このコードは、グリッドを列全体の DP に圧縮します。 各州は、これまでに配置されたピースの数を追跡します。 トランジションは、L 字型を配置しようとします。$2 \times 2$柱によって形成された窓$i$そして$i+1$、必要な 3 つのセルがすべて空いていることを確認します。 配置が有効な場合、DP 値が増加します。 

微妙な点は、部分的な占有はローカル内で完全に解決されるため、先に進むと常にマスクをリセットすることです。$2 \times 2$決断。 有効な配置が 2 つの隣接する列を超えて拡張されないため、これは安全です。

 ## 特殊なケース

 主なエッジ ケースは、1 つの列だけが完全に空いているが、その隣の列が部分的にブロックされている場合です。 たとえば、次のようなパターンです。```
00X
00X
```中央の列は使用可能に見えるかもしれませんが、ブロックされたセルに拡張せずに有効な L 字型を形成することはできません。 その列に触れるすべての 2x2 ウィンドウが有効性チェックに失敗するため、DP は適切に何かを配置することを回避します。 

もう 1 つのエッジ ケースは、次のような交互のブロックです。```
0X0X
0X0X
```ここでは、考えられるすべての 2x2 ウィンドウに少なくとも 1 つのブロックされたセルが含まれています。 アルゴリズムは各ウィンドウを個別に処理し、有効な 3 セル構成を見つけることができず、予想どおり配置がゼロになります。 

これらのケースは、ローカル ウィンドウ検証で十分であり、隠れた複数列の対話が必要ないことを確認します。
