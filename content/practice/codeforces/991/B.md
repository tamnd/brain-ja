 ## 解決策

 ## 問題の理解

 それぞれ 2 から 5 までのラボの成績のリストが与えられます。コースの成績は、すべてのラボの成績の算術平均として計算され、最も近い整数に丸められます。 四捨五入ルールは標準の「四捨五入」です。つまり、4.5 のような値は 5 になり、4.49 のような値は 4 になります。 

Vasya は、いくつかの実験課題を選択してやり直すことで、最終成績を向上させることができます。 やり直すと、そのラボ グレードは強制的に 5 になります。やり直すたびに、ラボの数は変更されずにグレードの合計が増加し、平均が増加します。 

目標は、四捨五入された平均が 5 になるように、Vasya がやり直す必要があるラボ作業の最小数を決定することです。最終的な 5 を取得するための四捨五入のしきい値は、平均が少なくとも 4.5 に達しているため、問題は、アップグレード後に平均が少なくとも 4.5 になるようにすることになります。 

制約は小さく、グレードは最大 100 です。 これにより、本質的に 2 次または 3 次の解が可能になりますが、貪欲な並べ替え戦略も非常に自然な候補になります。 

平均がすでに 4.5 に近づいている場合、微妙な特殊なケースが現れます。 たとえば、5 の 1 つを除いてすべてのグレードが 4 の場合、平均はすでに 4.5 を超えている可能性があり、これは操作が必要ないことを意味します。 常に成績を修正しようとする単純なアプローチでは、誤って答えが増加する可能性があります。 

もう 1 つの特殊なケースは、丸め動作から発生します。 ルールは「四捨五入」なので、厳密には4.5より大きいというわけではなく、4.5以上という条件になります。 このしきい値が欠けていると、現在の構成がすでに十分であるかどうかを判断する際に、1 つずつずれたエラーが発生します。 

## アプローチ

 直接的なアプローチは、グレードのサブセットを増やしてみることです。 考えられるやり直し回数 k ごとに、任意の k 個の位置を選択し、それらを 5 に設定し、新しい平均を計算して、必要なしきい値に達しているかどうかを確認できます。 これは、改善のすべての組み合わせを徹底的に調査しているため、正しいです。 ただし、n が増加するにつれてサブセットの数が組み合わせ的に増加し、k ごとにおおよそ C(n, k) のオーダーで増加し、指数関数的な動作につながるため、これでは遅すぎます。 

重要な観察は、低いグレードを向上させる方が、高いグレードを向上させるよりも多くの利益が得られるということです。 2 を 5 に置き換えると合計は 3 増加しますが、4 を 5 に置き換えると合計は 1 だけ増加します。最小限の操作でしきい値に到達したいため、常に最小値からアップグレードすることを優先する必要があります。 これにより、ソート後の問題は貪欲な選択問題に変わります。 

等級が昇順に並べ替えられたら、最小値を 1 つずつ 5 に変換するシミュレーションを行います。 各変換後に合計を更新し、平均条件が満たされているかどうかを確認します。 条件が満たされた最初の瞬間に、最小限の操作数が得られます。

 ## アルゴリズムのチュートリアル

 この問題を、平均を少なくとも 4.5 にするために、最小要素の数を 5 に置き換える必要があるかを確認することに変換します。 

1. すべての等級の合計を計算します。 これにより、現在のベースライン平均が得られます。 
2. 最も弱いグレードが最初に改善の対象となるように、グレードを昇順に並べ替えます。 各アップグレードでは、最小値に適用すると最大のゲインが追加されるため、これは最適です。 
3. アップグレードすることを決定した要素の数を 0 から n まで繰り返します。 
4. 各 k について、k 個の最小要素の (5 - a[i]) を加算して新しい合計を計算します。 
5. new_sum ≥ 4.5 * n という条件が成立するかどうかを確認します。 
6. 条件を満たす最小の k が答えになります。

重要な決定点はステップ 2 です。分類しないと、すでに高いグレードをアップグレードする操作が無駄になる可能性があり、操作ごとの改善が少なくなり、必要なやり直しの回数が増加する可能性があります。 

### なぜ効果があるのか

 このプロセスは単調な特性に依存します。つまり、より小さい値を置き換えると、より大きな値を置き換える場合と比較して、常に合計がそれ以上増加します。 これは、結果を悪化させることなく、選択されたすべてのやり直しが最小の要素に適用されるように、最適な戦略を再配置できることを意味します。 ソートが完了すると、アップグレードのすべてのプレフィックスは、その操作数で達成可能な最良の改善を表すため、しきい値を超える最初のプレフィックスが全体的な最適値に対応する必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n = int(input())
    a = list(map(int, input().split()))
    
    total = sum(a)
    a.sort()
    
    need = 4.5 * n
    
    if total >= need:
        print(0)
        return
    
    for i in range(n):
        total += (5 - a[i])
        if total >= need:
            print(i + 1)
            return

if __name__ == "__main__":
    main()
```解決策は、グレードの数とその値を読み取ることから始まります。 合計は 1 回計算され、変更前の現在の状態を表します。 

配列のソートは、アップグレードをシミュレーションするときに常に最小のグレードを最初に選択し、操作ごとのゲインを最大化するため、必須です。 

次に、しきい値を n の 4.5 倍として計算します。 これにより、平均を繰り返し再計算する必要がなくなり、条件が合計の単純な比較に変わります。 

このループは改善を段階的に適用します。 各反復では、合計を (5 - 現在の学年) だけ増やすことで、もう 1 つのラボをやり直すことをシミュレートします。 しきい値に達すると、使用された操作の数がすぐに返されます。

 ## 特殊なケース

 重要なエッジケースは、初期平均がすでに 4.5 以上である場合です。 たとえば、入力`3, 5 4 5`合計は 14 になり、しきい値は 13.5 になります。 アルゴリズムはアップグレードの直前にこれを処理し、ループに入らずに 0 を返します。 

もう 1 つのケースは、すべての値が同一で低い場合です。`4, 4, 4`。 アルゴリズムはアップグレードを順番に処理し、十分な累積ゲインが蓄積された場合にのみ停止します。 各ステップにより継続的な改善が加えられ、ループによって最終的な成功が保証されます。 

最後に、最小入力サイズ`n = 1`一貫して行動します。 単一グレードが 5 の場合、答えは 0 です。5 未満の場合、値はすぐに 5 になり、しきい値が保証されるため、常に 1 回のアップグレードで十分です。
