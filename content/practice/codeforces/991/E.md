 ## 問題の理解

 ヴァシャが混乱した状態で観察したバスの番号から得られた一連の数字が与えられます。 重要な問題は、彼が覚えているのは正確な数字ではなく、そこから抽出された複数の数字セットであることです。 彼はいくつかの数字に何度も気づいたかもしれませんが、それらの繰り返しは実際の観察であり、数字の同一性のエラーではありません。 ただし、これらの数字の出現順序は信頼できません。 

このタスクは、再構築された整数がゼロで始まることができないという制約の下で、観測された数値とまったく同じ複数の桁セットを生成できる別の整数がいくつあるかを数えるというものです。 

言い換えれば、指定された数値の桁を取り出し、それらをバッグとして扱い、先頭のゼロのない有効な数値を形成するこれらの桁の一意の順列の数を数えます。 

入力サイズは最大 10^18 であるため、数値は最大 18 桁になります。 最大 18 要素にわたる階乗ベースの組み合わせは完全に実現可能であるため、これは重要です。 すべての順列を考慮したり、包含-排他を使用したりしても、検索スペースは正確にカウントするには十分小さいままです。 

ゼロが存在する場合、微妙なエッジケースが発生します。 先頭のゼロの制限を無視すると、有効な数字ではない「0123」のような配置が過剰にカウントされてしまいます。 もう 1 つの問題は、数字の繰り返しです。これには、単純な階乗カウントではなく、多項係数を使用して慎重に処理する必要があります。 

単純なアプローチでは、数字のすべての順列を生成し、重複を排除しようとします。 18 桁の場合は 18 までです。 それは実現可能な限界をはるかに超えています。 組み合わせカウントに切り替えない限り、重複を削除しても十分な効果はありません。 

## アプローチ

 ブルート フォース ソリューションでは、数字のマルチセットのすべての順列を生成し、ゼロで始まらないものをフィルタリングして、個別の結果をカウントします。 すべての有効なバス番号が正確に 1 つの数字の並べ替えに対応するため、これは概念的に機能します。 ただし、順列の数は桁数に応じて階乗的に増加します。 18 桁の場合、これは 18 です。 これは約 10^15 の演算に相当し、完全に実行不可能です。 

重要な観察は、順列を明示的に構築する必要がまったくないということです。 代わりに、それらを数えるだけで済みます。 マルチセットの順列をカウントすることは、標準的な多項係数問題です。 桁数が固定されている場合、個別の順列の数は次のようになります。$$\frac{n!}{c_0! c_1! \cdots c_9!}$$どこ$c_i$は桁の周波数です$i$。 

唯一厄介なのは、最初の数字をゼロにすることができないという制約です。 これは 2 つのケースに分けて処理できます。 最初の桁がゼロ以外であるか、ゼロが強制的に先頭に来る無効な順列を減算します。 標準的なトリックは、合計の順列を計算し、ゼロで始まる順列を減算することです。これは、最初の位置でゼロを固定し、残りを順列にすることになります。 

これにより、事前計算された階乗を使用して効率的に評価できるクリーンな組み合わせ式が得られます。

 ## アルゴリズムのチュートリアル

 数値の桁を配列に格納し、その合計数を次のようにします。$n$。 

1. 0 ～ 9 の各桁の頻度をカウントします。これにより、入力のマルチセット構造がキャプチャされます。 問題全体は、これらのカウントについての推論に帰着します。 
2. 多項カウントを使用して、すべての桁の合計順列を計算します。$$total = \frac{n!}{\prod c_i!}$$これにより、ゼロから始まるものも含め、すべての並べ替えがカウントされます。 
3. 最初の桁がゼロである無効な順列を計算します。 これを行うには、先頭にゼロを 1 つ固定します。 今、残りを並べ替えています$n-1$更新されたカウントを含む桁数$c_0$1 減ります:$$bad = \frac{(n-1)!}{(c_0 - 1)! \prod_{i=1}^9 c_i!}$$4. 無効なケースを減算します。$$answer = total - bad$$5. 結果を返します。 

これが機能する理由は、すべての順列がゼロで始まるか、そうでないためであり、これら 2 つのセットは素であり、すべての順列をカバーするためです。 最初の桁を固定してゼロから始まるサブセットを明示的にカウントすることで、二重カウントを回避し、正確な分割を保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from math import factorial
from collections import Counter

def solve():
    s = input().strip()
    cnt = Counter(s)
    digits = [cnt[str(i)] for i in range(10)]
    
    n = len(s)
    
    fact = [1] * (n + 1)
    for i in range(1, n + 1):
        fact[i] = fact[i - 1] * i

    def multinomial(total, c):
        res = fact[total]
        for x in c:
            res //= fact[x]
        return res

    total = multinomial(n, digits)

    if digits[0] == 0:
        print(total)
        return

    # invalid: leading zero
    digits[0] -= 1
    bad = multinomial(n - 1, digits)

    print(total - bad)

if __name__ == "__main__":
    solve()
```この実装では、階乗を使用して多項係数を直接エンコードします。 階乗表は n (最大 18) まで構築されるため、実際にはこれが継続的な作業となります。 

減算ステップは、一時的にゼロ カウントを減らすことによって実装されます。これは、先頭の位置にゼロを固定することに正確に対応します。 これにより、多項式内の位置制約による置換について明示的に推論する必要がなくなります。 

数値[0]が最初にゼロである場合は注意が必要です。 その場合、どの順列もゼロから始めることはできないため、すべての順列が有効となり、減算は必要ありません。

 これにより、置換「97」と「79」の両方が有効であることが確認されます。 

ここで、次のような繰り返しのある数値を考えてみましょう。`2028`。 

桁数は、2 が 3 回、0 が 1 回、8 が 1 回です。 

| ステップ | パーマの合計 | ゼロスタートパーマ | 答え |

 ## 特殊なケース

 次のような 1 桁の入力`7`有効な置換は 1 つだけ生成されます。 このアルゴリズムは 1 桁を数え、合計を 1 として計算します。ゼロがないため減算は行われず、出力は 1 のままになります。 

のような入力`10`先行ゼロの制限が公開されています。 合計の順列は「10」と「01」の 2 つです。 減算ステップでは、先頭のゼロを固定し、残りの順列をカウントすることで無効な「01」の場合を削除し、有効な結果を 1 つだけ残します。
