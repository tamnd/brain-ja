 ## 解決策
 ## 問題の理解

 私たちには最初のキャンディーの山と、時間の経過とともにこの山を変化させる固定の毎日のルールが与えられます。 毎朝、ヴァシャは定数を選びます`k`。 毎日、彼は正確に削除しようとしています`k`山からキャンディーを取り出しますが、残りが少ない場合は、すべてを受け取り、プロセスは事実上終了します。 夕方、ペティアは何が残っているかを確認し、最も近い整数に切り捨てて、残っているキャンディーのちょうど 10 分の 1 を取り除きます。 

キャンディーが残っている間、この毎日のサイクルが繰り返されます。 Vasya の総摂取量は、彼が午前中ずっと摂取することに成功したすべてのキャンディーの合計です。 目標は、最小の整数を選択することです`k`最終的にヴァシャは元の量の少なくとも半分を食べることになる`n`キャンディー。 

制約`n ≤ 10^18`各キャンディーを個別に追跡しようとするシミュレーションは除外されます。 1 日あたりのシミュレーションであっても、日数が対数的であるか、または大幅に減少している場合にのみ許容されます。線形のステップ数では遅すぎるためです。 

素朴な間違いは、プロセスが約 1 時間続くと仮定することです。`n / k`日を指定して、それを直接シミュレートします。 Petya の 10% 除去は状態を加法的ではなく乗法的に変更するため、これは破綻します。 もう 1 つの微妙な落とし穴は、丸めの誤解です: Petya の`floor(x / 10)`この動作によりシステムが非線形になり、追加のステップのために小さな残りが維持される可能性があります。 たとえば、9 個のキャンディーが残っている場合、Petya は何も削除しないため、Vasya がさらに削除しない限り、減衰は一時的に停止します。 

コーナーケースが現れるのは、`n`小さいです。 もし`n = 1`、 それから`k = 1`すぐに解決します。 ここでは、長い定常状態の動作を前提とした推論は、注意しないと失敗します。 

## アプローチ

 強引なアイデアは、可能なすべての値を試してみることです。`k`から`1`に`n`、各候補者のプロセス全体をシミュレートし、Vasyaが最初のキャンディーの少なくとも半分に達しているかどうかを確認します。 これはルールに直接従うため、正しいです。 失敗点はスケールです: それぞれ`k`、プロセスには最大で対数的に何日もかかる場合があり、試行すると最大で`n`の値`k`このアプローチは実行可能性をはるかに超えています`n = 10^18`。 

重要な観察は、固定の実現可能性です。`k`単調です。 ある場合`k`Vasya が少なくとも半分に達し、その後さらに大きくなるまで到達できるようにする`k`Vasya の取り分は増えるだけです。Petya の取り分は残ったものだけによって決まるのに対し、彼は毎朝さらに多くを削除するからです。 この単調性により、二分探索が適用可能になります。 

したがって、全員を対象にシミュレーションするのではなく、`k`、最小のものを二分探索します`k`そして、候補者ごとにプロセスを 1 回シミュレートします。 毎日終わると、キャンディーの数は少なくとも一定の割合、または一定の減算によって減少するため、シミュレーション自体は効率的です。`k`、終了までの反復回数が少なく、ほぼ次の値に比例することを意味します。`log n`。

 ## アルゴリズムのチュートリアル

 固定値が与えられた場合に、次のような関数を定義します。`k`、Vasya が食べるキャンディーの数を計算します。 

1. 完全な山から始めます`x = n`そしてカウンター`eaten = 0`。 これは、丸一日の各サイクル後のシステムの現在の状態を表します。 
2. その間`x > 0`、丸 1 日をシミュレーションします。 
3.ヴァシャは取る`min(k, x)`山からキャンディーを取り出し、これを追加します`eaten`。 それから減らす`x`同じ量で。 
4. もし`x`ゼロになると、Petya には何も取るものが残っていないため、すぐに停止します。 
5. Petya は削除します`x // 10`残ったものでキャンディー。 アップデート`x = x - x // 10`。 
6. 山が空になるまでループを繰り返します。 

このシミュレーションを定義した後、それを二分探索内にラップします。`k`から`1`に`n`。 中間点ごとにシミュレーションを実行し、Vasya の合計が少なくとも`n // 2`。 

最終的な答えは最小です`k`このチェックに合格したもの。 

### なぜ効果があるのか

 シミュレーションは、記述された正確な順序で操作を適用し、フロア分割が Petya の丸め規則と一致するため、プロセス定義に忠実です。 二分探索が機能するのは、「Vasya が少なくとも半分を取得する」という述語が単調であるためです。`k`。 増加中`k`Petya の除去は Vasya の移動後の残りの山にのみ依存するため、Petya の側から Vasya の側にさらに多くのキャンディーを移動することしかできず、Vasya の合計を減らすことはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can(k, n):
    x = n
    eaten = 0

    while x > 0:
        take = k if x >= k else x
        eaten += take
        x -= take

        if x == 0:
            break

        x -= x // 10

    return eaten * 2 >= n

def solve():
    n = int(input())
    lo, hi = 1, n

    while lo < hi:
        mid = (lo + hi) // 2
        if can(mid, n):
            hi = mid
        else:
            lo = mid + 1

    print(lo)

if __name__ == "__main__":
    solve()
```コア機能`can`日常のプロセスを直接実装します。 順序を逆にすると完全に異なるシステムがシミュレートされるため、重要な点は、Petya のパーセンテージを削除する前に Vasya の減算を実行することです。 Vasya の移動後の終了条件により、パイルがすでに使い果たされた場合の不必要な計算が回避されます。 

二分探索は候補間隔を維持します`[lo, hi]`考えられる答えの中から。 中間点テストでは、現在のテスト結果に応じてこの間隔が短縮されます。`k`で十分です。

 ## 特殊なケース

 いつ`n = 1`、Vasyaが唯一のキャンディーを取った後、シミュレーションはすぐに終了します。 二分探索はまだ機能します。`can(1, 1)`最初のチェックで true を返し、範囲を正しく折りたたみます。 

いつ`n < 10`, Petya は何も削除しません。 システムは純粋に線形になるので、答えは単純です。`(n + 1) // 2`事実上、シミュレーションにはこれが反映されています。`x // 10`は常にゼロです。 

いつ`k`非常に大きいです、例えば`k ≥ n`, Vasya は最初の動きで山を空にします。 シミュレーションは Petya アクションの前に終了し、そのような結果が正しく得られます。`k`は常に十分であり、二分探索は有効な最小値に向かって下方に移動します。
