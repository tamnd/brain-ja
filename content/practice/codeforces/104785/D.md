 ## 解決策
 ## 問題の理解

 私たちに与えられた会社は、$n$宅配業者、どこ$n$は 3 で割り切れることが保証されています。 各配達員には強度値があり、すべての配達員を正確に分割する必要があります。$k = n/3$グループ。各グループにはちょうど 3 人が含まれます。 

各グループの有効性は、グループ内の最大または最小の強度によって定義されるのではなく、3 つのグループの中で 2 番目に大きい値を意味する中央値の強度によって定義されます。 目標は、すべてのグループ中央値の合計ができるだけ大きくなるように、クーリエをトリプルに割り当てることです。 

したがって、タスクはチームのバランスをとったり、平等にしたりすることではなく、どの値が各トリプルの「中間」寄与者になるかを慎重に決定することです。 

制約は次のとおりです$n \le 10^6$、ソート後すぐに線形または線形の解を強制します。 グループ形成を直接列挙またはシミュレートしようとするアプローチは、トリプルに対する単一の組み合わせ構築でさえ爆発的に影響するため、遅すぎます。$O(n^3)$あるいはさらに悪いことに。 で並べ替えます$O(n \log n)$は許容されますが、配列を数回通過した後はすべて線形でなければなりません。 

よくある微妙な失敗のケースは、グローバルな順序付けをせずにローカル トリプルを貪欲にグループ化することに起因します。 たとえば、次のような値を使用します。 

入力:```
6
1 2 3 100 101 102
```単純なグループ化が形成される可能性がある`(100, 101, 102)`そして`(1, 2, 3)`、中央値を与える`101 + 2 = 103`。 これはもっともらしく見えますが、一般に最適なグループ化ロジックではありません。値がより敵対的な分布にインターリーブされている場合、そのような貪欲なローカル決定は失敗します。 

本当の難しさは、各要素がちょうど 1 つのトリプルに参加しているため、誰が中央値になるかを選択すると、他のすべての選択肢と相互作用することです。 選択された「中間」要素が可能な限り大きいと同時に、トリプル内の有効な中央値であることを保証する構造が必要です。 

## アプローチ

 ブルートフォースのアイデアは簡単です。配列をトリプルに分割し、各トリプルの中央値を計算し、最大合計を計算するために考えられるすべての方法を試します。 これはすべての有効な構成をチェックするため、原則的には正しいです。 ただし、分割方法の数は$n$要素を 3 つのグループに分けると、その数は天文学的に大きくなり、指数関数的よりも速く増加します。 たとえ$n = 30$、これは実行不可能になり、$n = 10^6$、それはまったく不可能です。 

重要な点は、実際には明示的にトリプルを構築する必要がないということです。 各トリプルの中間要素のみに注目します。 配列をソートすると、最適なグループ化の構造に制約が生じます。大きな値は中央値の「サポート」要素として機能し、小さな値はトリプルの下端として犠牲にされ、残りの要素は自然に中央値になります。 

並べ替えた後、配列の両端から内側に向​​かって歩いていくことを想像してください。 各トリプルには、選択した中央値の周りに 1 つの大きなヘルパー要素と 1 つの小さなフィラー要素が必要です。 これは、選択した中央値ごとに、そのグループを完成させるために 1 つの大きな要素と 1 つの小さな要素を「費やす」ことができることを意味します。 中央値をできるだけ大きくしたいので、中央値のコンパニオンとして大きな値を早期に無駄にしないようにします。 

これにより、クリーンな貪欲な構造が得られます。配列をソートし、最小の 3 分の 1 を強制フィラーとして無視し、最大の 3 分の 1 を強制サポートとして無視します。 残りの中央 3 分の 1 には中央値の最良の候補が含まれていますが、そのすべてが直接使用されるわけではありません。 代わりに、正しい中央値が並べ替えられた順序で一定の間隔で表示されます。 

具体的には、最適解は昇順にソートした後、インデックスから要素を選択します。$k$、次に 1 つスキップし、1 つ取り、これを繰り返します。 これは最初の理由で機能します$k$最小の要素はトリプルの「ローサイド」として使用するのが最適ですが、最大の要素は$k$要素は「ハイサイド」として機能し、正確に残ります。$k$要素を中央値として最大化できる位置に配置します。

 ## アルゴリズムのチュートリアル

 個々の割り当てではなく構造について推論できるように、最初に配列をソートします。 並べ替えは、問題を組み合わせによるグループ化から位置の選択に変換します。 

昇順で並べ替えた後、配列を 3 つの概念的なセグメント (最小要素、最大要素、中央値が抽出される中間領域) として扱います。 各グループはちょうど 1 つの小さいヘルパーと 1 つの大きいヘルパーを消費するため、最小のヘルパーを予約します。$k$下位のパートナーとしての要素と最大の要素$k$ハイパートナーとしての要素。 

真ん中の領域に残っているのは、$k$答えに貢献する要素。 ただし、連続して摂取するわけではありません。 代わりに、インデックスから始まる 2 つおきの要素を選択します。$k$なぜなら、連続する中央値の間では、有効なトリプル内のヘルパー要素の割り当てを考慮する必要があるからです。 

1. 配列を昇順に並べ替えます。 
2. しましょう$k = n/3$。 
3. 変数を初期化する`answer = 0`。 
4. インデックスから始める$k$、配列を反復処理し、次の要素が得られるまで 2 つおきの要素を選択します。$k$要素が選ばれます。 
5. 選択した各要素を`answer`。 
6. 出力`answer`。 

1 つおきの要素をスキップする理由は、選択された各中央値がそのトリプル構成で 1 つの小さい要素と 1 つの大きい要素用のスペースを暗黙的に予約しており、ソートされた構造により、他の選択された中央値を妨げることなくこれらの役割を常に満たすことができるためです。 

### なぜ効果があるのか

 配列がソートされると、必要な場合を除き、より小さい要素が中央値として表示されないように、有効なグループを再配置できます。 各中央値には、それより小さい要素と大きい要素が少なくとも 1 つ必要です。 最小のものを予約することで、$k$保証された小さな仲間と最大の要素としての要素$k$保証された大きな仲間として、私たちは正確に隔離します$k$中央値を取得できる位置。 

選択された 2 つの中央値ごとに、消費されたサポート要素に対応する構造的な分離があるため、交互に選択することで、2 つの中央値が同じヘルパー要素をめぐって競合しないことが保証されます。 これにより、許容可能な中央値領域から利用可能な最大の候補が常に選択されるため、合計を最大化しながら実現可能性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    a = list(map(int, input().split()))
    
    a.sort()
    k = n // 3
    
    ans = 0
    
    # pick medians: indices k, k+2, ..., k+2*(k-1)
    for i in range(k):
        idx = k + 2 * i
        ans += a[idx]
    
    print(ans)

if __name__ == "__main__":
    solve()
```この解決策は、配列をソートすることから始まります。これは、すべての構造的推論が相対的な順序に依存するため、不可欠です。 変数$k$形成するトリプルの数を表すため、正確に期待されます$k$最終的な合計に寄与する中央値。 

ループは、次から始まるインデックスを慎重に選択します。$k$そして毎回2ずつジャンプします。 開始オフセット$k$各トリプルの必須の下位コンパニオンとして予約されている最小の要素を回避します。 2 つのステップにより、選択した各中央値が、有効なグループ化のための構造的間隔として機能する 1 つの要素によって分離されることが保証されます。

 ## 特殊なケース

 エッジケースの 1 つは、すべての値が同一である場合です。 入力の場合:```
6
5 5 5 5 5 5
```ソートしても配列は変更されません。$k = 2$。 アルゴリズムは、どちらも 5 に等しいインデックス 2 と 4 を選択し、結果 10 が得られます。どのグループ化でも同じ結果が得られ、すべての要素が交換可能であるためアルゴリズムの一貫性が保たれ、中央値の選択パターンは問題になりません。 

もう 1 つのエッジ ケースは、有効な最小入力です。```
3

```ここ$k = 1$、ソート後、値 2 であるインデックス 1 (0 ベース) を選択します。これは、可能な唯一のトリプルの中央値であり、境界サイズであってもインデックス作成ロジックが定義と一致していることを確認します。
