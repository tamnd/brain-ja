 ## 解決策
 ## 問題の理解

 各タスクが頂点であり、各依存関係が有向エッジである有向グラフが与えられます。 エッジ`a -> b`タスクを意味します`a`タスクの前に実行する必要があります`b`。 

問題は、これらの依存関係に有向サイクルが含まれる可能性があり、すべてのタスクを有効な順序で実行できなくなることです。 すべてのサイクルを除去するために一部のエッジを削除することはできますが、元のエッジの少なくとも半分は保持する必要があります。 

出力はタスクの順序付けではなく、残りの有向グラフに有向サイクルがなく、保持されるエッジの数が元の数の少なくとも半分になるような依存関係エッジのサブセットです。 

重要な構造要件は、保持されたエッジが有向非巡回グラフを形成する必要があることです。 つまり、保持されるすべてのエッジが前の頂点から後の頂点に向かうように、頂点の順序が存在する必要があります。 

制約により、最大で`n = 100000`そして`m = 300000`これにより、エッジまたは頂点の順列に対する指数関数または二次推論が即座に除外されます。 順序を検索したり、削除ごとにサイクルを繰り返し確認したりすると、時間がかかりすぎます。 

微妙な点は、同じ頂点ペア間の複数のエッジが許可され、それらは独立して処理されることです。 各エッジは、選択された非環状構造に適合するかどうかに基づいて、個別に選択または削除されます。 

単純な間違いは、DFS サイクル検出を使用してサイクルを直接中断し、見つかったサイクルごとに 1 つのエッジを削除しようとすることです。 これは失敗します。サイクルが重複しており、貪欲な削除により必要以上に削除される可能性があり、必要な量を簡単に下回ってしまう可能性があります。`m/2`しきい値。 

もう 1 つの間違いは、元のグラフに対して完全なトポロジカル ソートを試みることです。 これはグラフがすでに DAG である場合にのみ機能しますが、保証されていません。 

## アプローチ

 ブルートフォース解釈では、エッジのサブセットをテストし、選択したサブセットが非周期的で十分な大きさであるかどうかを確認しようとします。 単一のサブセットをチェックする場合でも、サイクル検出が必要です。`O(n + m)`、そして、あります`2^m`サブセットですが、これは完全に不可能です。 

より構造化された総当りのアイデアは、頂点の順序を割り当て、エッジのみをそれに一致させることです。 これにより常に非循環グラフが生成されますが、エッジの少なくとも半分を維持する順序を見つけることが課題となります。 すべての順列を検索することはやはり不可能です。 

重要な観察は、頂点のすべての合計順序がエッジを 2 つの互いに素なグループ (順序で前に進むエッジと後向きのエッジ) に分割することです。 前方エッジは常に DAG を形成します。 アイデンティティの順序を選択すると`1 to n`、有効なサブセットを 1 つ取得します。 逆の順序を選択すると、別の有効なサブセットが得られます。 すべてのエッジは、これら 2 つのサブセットのいずれかに正確に属します。`a -> b`、 どちらか`a < b`または`a > b`。 

これは、2 つのサブセットが一緒にすべてのエッジをカバーするため、そのうちの 1 つにエッジの少なくとも半分が含まれている必要があることを直ちに意味します。 より大きなサブセットを選択すると、非周期性とサイズ要件の両方が保証されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | サブセットの列挙 / サイクル チェック | O(2^m) | O(m) | 遅すぎる |
 | 2 次パーティション (順方向と逆方向) | O(n + m) | O(m) | 承認済み |

 ## アルゴリズムのチュートリアル

 頂点の固定順序を使用して、エッジの 2 つの候補セットを構築します。 

まず自然の秩序を扱います`1, 2, ..., n`トポロジー順序の候補として、小さいインデックスから大きいインデックスに向かうすべてのエッジを収集します。 

次に、逆の順序を考えます`n, ..., 1`そして、その順序で前方に進むすべてのエッジを収集します。これは、次のエッジに対応します。`a > b`オリジナルのナンバリングで。 

次に、これら 2 つのセットのうち大きい方を選択します。 

### ステップ

 1. すべてのエッジを読み取り、入力インデックスを割り当てて、後で出力できるようにします。 出力には元のエッジ ID が必要なため、このインデックス付けは重要です。 
2. 2 つのリストを初期化します。1 つはエッジ用です。`a < b`もう 1 つはエッジ用です。`a > b`。 各リストは、異なる合計順序と一致するエッジを表します。 
3. すべてのエッジについて、そのエンドポイントを比較します。 もし`a < b`、それは自然な順序と一致しており、最初のリストに追加されます。 それ以外の場合は、逆の順序と一致し、2 番目のリストに追加されます。 
4. 2 つのリストのサイズを比較します。 少なくとも保証する必要があるため、大きい方を選択してください`m/2`エッジ。 
5. 出力`YES`、次に選択したリストのサイズ、次にそのエッジのインデックスです。 

これが機能する理由は、すべてのエッジが 2 つのリストのうちの 1 つに正確に割り当てられるため、それらのサイズの合計は次のようになります。`m`。 したがって、少なくとも 1 つのリストには少なくとも次のサイズが必要です。`m/2`。 どちらのリストも、全体の順序と一致するエッジに対応し、非循環性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    
    forward = []
    backward = []
    
    for i in range(1, m + 1):
        a, b = map(int, input().split())
        if a < b:
            forward.append(i)
        else:
            backward.append(i)
    
    if len(forward) >= len(backward):
        chosen = forward
    else:
        chosen = backward
    
    print("YES")
    print(len(chosen))
    print(*chosen)

if __name__ == "__main__":
    solve()
```この実装はエッジの直接分割に依存しています。 出力には元のエッジ ID が必要なので、インデックス ループが重要です。`i`読み取られた各エッジに対して。 

生のエッジを超えるグラフ構造は必要ありません。 ソリューション全体は、エンドポイントの比較とそれに応じたグループ化に基づいています。 

よくある実装エラーは、入力順序でエッジのインデックスが 1 であることを忘れることです。 もう 1 つは、インデックスを保存する代わりにエッジ リストを誤って再計算または変更してしまうことです。 

## 実用的な例

 ### トレース例 1

 入力を考慮してください:```
n = 3, m = 3
1 -> 2
2 -> 3
3 -> 1
```エッジ部分を一つ一つ加工していきます。 

| エッジ | a < b | 転送リスト | 後方リスト |
 | --- | --- | --- | --- |
 | 1->2 | はい | [1] | [] |
 | 2->3 | はい | [1,2] | [] |
 | 3->1 | いいえ | [1,2] | [3] |

 We compare sizes: forward has 2 edges, backward has 1 edge. 私たちは前進を選択します。 

選択されたエッジは順序付けの下で DAG を形成します`1 < 2 < 3`, したがって、サイクルは残りません。 

This demonstrates how a cycle is broken implicitly by discarding the backward edge.

 ## 特殊なケース

 重要なエッジ ケースは、すべてのエッジが降順で指している場合です。たとえば、`3 -> 2`、`2 -> 1`、`3 -> 1`。 この状況では、自然順序付けの下での前方リストは空ですが、後方リストにはすべてのエッジが含まれます。 アルゴリズムは逆方向リストを正しく選択します。これは順序を逆にすることに相当し、有効な DAG が生成されます。 

もう 1 つのケースは、すべてのペアが両方向を持つ、完全に対称な完全な有向グラフです。 各ペアは各リストに正確に 1 つのエッジを提供するため、両方のリストのサイズは同じになります。 どちらの選択も有効であり、対応する順序付けでは依然として非循環的です。 

これらのケースは、敵対的な入力分布の下でもパーティション戦略が安定していることを確認します。
