 ## 解決策
 ## 問題の理解

 各入力行は、ワインボトルの容量を 10 進数とそれに続く文字で記述します。`L`。 異なる行は、たとえ構文的に異なって見えても、まったく同じ数量を表すことがあります。たとえば、`1.0L`そして`1L`同じ値を表します。 タスクは、単一の小文字の単語を各個別のボリュームに割り当て、同一のボリュームが常に同じ単語を受信できるようにすることです。 

したがって、出力は数値自体の計算ではなく、10 進形式で与えられた実数の同値クラスの一貫したラベル付けです。 後で入力にボリュームが再び表示されるときは、新しいラベルを作成するのではなく、同じ割り当てられたラベルを再利用する必要があります。 

制約`n ≤ 10000`これは、すべての値のペアを直接比較するソリューションは遅すぎることを意味します。`10^8`最悪の場合の比較。 これにより、各値が一定時間内に正規表現に変換され、辞書に保存されるハッシュ化または正規化戦略が推進されます。 

浮動小数点表現には微妙な困難があります。 各値を Python として解析する単純なアプローチ`float`それを辞書キーとして使用すると、10 進数の解析によって精度にアーチファクトが生じる特殊なケースでは失敗する可能性があります。 たとえば、次のような 2 つの入力`0.1L`そして`0.10L`明らかに同一であるはずですが、浮動小数点解析では表現や言語に応じて小さな丸めの違いが生じることがあります。 もう 1 つのエッジ ケースは、小数点以下の桁数が 10 まで多く、バイナリ浮動小数点が正確ではない値です。 

正しいアプローチでは、形式の違いに関係なく、数値的に等しい 2 つの 10 進文字列が常に同じ内部キーにマップされるようにする必要があります。 

## アプローチ

 ブルート フォース戦略では、両方の文字列を解析し、数値的等価性をチェックすることで、各受信ボリュームを以前に確認されたすべてのボリュームと比較します。 各比較には 10 進数の文字列の解析が含まれ、場合によってはそれらの正規化が行われるため、全体で 2 次数の演算が必要になります。 ボトルが 10,000 個ある場合、これはおよそ 1 億回の比較になります。これは、各比較に文字列解析または浮動小数点処理が含まれる場合、Python では遅すぎます。 

重要な点は、入力がすでに精度が制限された構造化 10 進形式になっているということです。 浮動小数点演算に依存する代わりに、小数点を削除し、小数部の桁数を追跡することで、各値を正規の整数表現に変換できます。 2 つの値は、10 進数を揃えた後に正規化された整数形式が一致する場合に限り、等しくなります。 

各ボリュームが正規キーに変換されたら、ハッシュ マップを使用する前にそのボリュームが認識されているかどうかを確認するだけで済みます。 そうでない場合は、新しいラベルを割り当てます。 これにより、問題全体が文字列に対する線形時間ハッシュに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 正規化による最適なハッシュ | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 等価性チェックを正確に行い、フォーマットに依存しない各ボリュームの表現が必要です。 

1. ボリューム文字列を読み取り、末尾のボリューム文字列を削除します。`L`、数値部分のみを保持します。 
2. 数値文字列を小数点以下の整数部分と小数部分に分割します。 小数点が存在しない場合は、小数部を空として扱います。 
3. 整数部分の先頭のゼロを削除し、小数部分の末尾のゼロを削除して表現を正規化します。 トリミング後に小数部分が空になった場合は、小数部分を完全に破棄します。 これにより、`1`、`1.0`、 そして`01.000`すべてが同じキーに折りたたまれます。 
4. 正規キーを、クリーンな整数部分とクリーンな小数部分を含むタプルとして構築します。 このタプルは、浮動小数点エラーのない 10 進形式の実数を一意に表します。 
5. 辞書を使用して、各一意のキーを生成された単語にマッピングします。 新しいキーが見つかった場合は、次の未使用の単語識別子を割り当てます。 同じキーが再び表示された場合は、以前に割り当てられた単語を再利用します。 

### なぜ効果があるのか

 2 つの 10 進数文字列は、先頭のゼロや冗長な末尾のゼロなどの書式設定のアーティファクトを削除した後で整数と小数の桁が一致する場合に限り、同じ数値を表します。 正規化ステップでは、入力形式で表現可能な各実数値に対して一意の標準形式を適用します。 辞書はこの正規形式をキーとして使用するため、値空間の等価性は文字列表現の等価性に変換され、一貫したラベル付けが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def normalize(s: str):
    if s.endswith("L"):
        s = s[:-1]

    if "." in s:
        a, b = s.split(".")
    else:
        a, b = s, ""

    a = a.lstrip("0")
    if a == "":
        a = "0"

    b = b.rstrip("0")

    if b == "":
        return (a, "")

    return (a, b)

def solve():
    n = int(input())
    mp = {}
    out = []
    counter = 0

    for _ in range(n):
        s = input().strip()
        key = normalize(s)

        if key not in mp:
            mp[key] = f"w{counter}"
            counter += 1

        out.append(mp[key])

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```実装の中核となるのは、`normalize`この関数は、同じ数値の構文的に異なる表現が同一のタプルに折りたたまれることを保証します。 辞書`mp`正規化された数値から割り当てられた単語への最初のマッピングを保存します。 

の選択`tuple(int_part, frac_part)`浮動小数点を完全に回避し、正確な比較セマンティクスを保証します。 生成された名前`w0, w1, ...`プレースホルダーとしてのみ機能します。 同一のキーが同じ文字列を再利用する限り、一貫した小文字の文字列であれば問題の要件は満たされます。 

よくある実装上の間違いは、次のように使用することです。`float(s[:-1])`辞書キーとして。 これにより、長い小数入力の精度が失われる危険があり、異なる値をマージしたり、等しい値を誤って分離したりする可能性があります。

 ## 特殊なケース

 厄介なケースは、同じ数値が視覚的に異なる複数の形式で記述される場合です。 例えば、`01.0L`、`1L`、 そして`1.000L`すべて同じボリュームを表します。 分割して正規化すると、それぞれが整数部分になります`"1"`小数部分が空であるため、同じ辞書キーに折りたたまれ、同じラベルが付けられます。 

別のエッジ ケースには、末尾のゼロだけが異なる小数値が含まれます。`0.30L`そして`0.3L`。 正規化ステップでは、小数部分の末尾のゼロが削除されるため、両方とも次のようになります。`(0, "3")`により、入力形式の精度が異なる場合でも、正しいグループ化が保証されます。
