 ## 解決策
 ## 問題の理解

 時間の経過に伴う「都市開発指数」を表す長い整数列が与えられます。 この配列は静的ではありません。 オンラインでは 2 種類の操作が行われます。 1 つの操作は、連続するセグメント内のすべての要素に値を追加し、もう 1 つの操作は、非常に珍しい定義の下で部分配列が「増加」しているかどうかを尋ねます。 

問題は更新自体ではなく、クエリ中に配列の構造がどのように解釈されるかです。 セグメントを判断する前に、まず連続する等しい値を 1 つの値にマージすることでセグメントを圧縮します。 圧縮後、結果のシーケンス内の極小値を調べます。 位置の値が両方の近傍 (または、端点にある場合は唯一の近傍) よりも厳密に小さい場合、その位置は極小値です。 最後に、これらの極小値が左から右に読まれ、厳密に増加する値のシーケンスを形成する場合、セグメントは増加していると呼ばれます。 

したがって、各クエリは基本的に、ダイナミック レンジを追加した後の区分的に一定の信号の形状に関する構造的な質問をしています。 

この制約では、最大 300,000 の要素と 300,000 の操作が許可されます。 クエリごとにセグメントを最初から再計算するソリューションは、最悪の場合は二次関数となり、許容範囲をはるかに超えています。 クエリごとに O(n log n) であっても、繰り返し適用すると遅すぎます。 唯一の実行可能なアプローチは、圧縮された表現、または更新時にゆっくりと変化する境界ベースの構造を維持する必要があります。 

いくつかの特殊なケースがすぐに問題になります。 

セグメント内のすべての値が等しい場合、圧縮によってセグメントが単一の要素に縮小されますが、この要素には内部極小値がないことが明らかであるため、そのようなクエリに対する答えは常に YES でなければなりません。 単純なローカル最小スキャンは、注意しないとエンドポイントを誤って最小として解釈しようとする可能性があります。 

配列が次のように交互になる場合`1 2 1 2 1`、圧縮は何も行いませんが、極小値は正確な近傍に依存するため、等価関係を変更する小さな更新により、圧縮された構造が大幅に変更される可能性があります。 

範囲の更新によって等隣接境界が作成または削除される場合、より微妙なケースが発生します。 たとえば、変形する`1 2 3`の中へ`1 2 2`圧縮を 3 つのセグメントから 2 つのセグメントに変更し、潜在的な極小位置のセットを変更します。 どのソリューションでも、生の値だけでなく、等価境界が存在する場所を追跡する必要があります。 

## アプローチ

 直接シミュレーションのアプローチでは、各更新を配列に適用し、クエリごとに圧縮シーケンスを再計算して、極小値をスキャンします。 圧縮自体はクエリごとに線形であり、極小値の検出も線形です。 最大 300,000 クエリでは、これは O(nm) となり、まったく実行不可能です。 

範囲の追加をサポートするセグメント ツリーを使用して配列を維持しようとしても、主な障害は値のクエリではなく、等価性によって引き起こされる構造の変更です。 圧縮されたシーケンスは等しい値の隣接関係に依存し、範囲の追加により非ローカルな方法で等価性が変化します。 セグメント ツリーはポイント値に効率的に応答できますが、クエリごとに圧縮された実行構造を再構築するには、依然としてセグメント サイズの線形時間がかかります。 

重要な観察は、構造が変化する唯一の場所は、等しい値の間の境界であるということです。 同一の値が長く続く場合、範囲加算によりその連続内での等価性が維持されます。 重要なのは、更新が実行境界にどのように影響するか、そしてクエリがクエリ間隔内のこれらの境界のパターンのみにどのように依存するかです。 

これは、配列を最大の等しい値のセグメントのシーケンス、つまり時間の経過とともに進化するランレングス エンコーディングとして維持することを示唆しています。 各セグメントには値と長さが格納されます。 範囲の追加により、境界でセグメントが分割または結合される可能性がありますが、ラン構造があらゆる場所で恣意的に破壊されるわけではありません。 

2 番目の重要なアイデアは、圧縮シーケンスの極小値がラン構造の局所パターンに対応するということです。 ランの値が隣接するランよりも小さい場合、そのランは極小値の候補となります。 したがって、完全に展開されたシーケンスは必要なく、実行リストと隣接する実行間の比較のみが必要になります。 

したがって、問題は、範囲加算更新の下で実行の動的なシーケンスを維持することと、実行の部分配列内の極小値の単調性に関するクエリに答えることに帰着します。 

バランスの取れた二分探索ツリーや位置をキーとしたトレプなどのバランスの取れた構造により、実行を維持できます。 各ノードはセグメントをその値と長さとともに格納し、隣接ポインタはインオーダー構造を介して暗黙的に維持されます。 範囲の追加は O(log n) 個の部分に分割され、連続するノードのセットで更新され、隣接する等しい値のセグメントがマージされます。 

クエリのチェックは、関連する実行セグメント範囲を抽出し、その実行をスキャンして極小値を収集することになります。 ただし、スキャンの実行数は依然として線形である可能性があります。 重要な構造上の制約は、各更新で実行の分割とマージに関して O(1) 境界のみが変更されるため、償却された意味で全体の実行数が管理可能なままであることです。 

慎重に維持された順序付けされた構造を使用すると、極小値は連続する実行の 3 つの値にのみ依存するため、境界に隣接する実行のみを収集することによって各クエリを解決できます。

 ## アルゴリズムのチュートリアル

 各ノードが等しい値の最大の連続セグメントを表すバランスの取れた BST (トリープ) を維持します。 各ノードは、その値、その長さ、および配列内の位置による暗黙的な順序付けを格納します。 

1. 連続する等しい値をマージすることにより、入力配列から最初の実行構造を構築します。 これにより、セグメントの開始セットが得られます。 
2. 範囲の場合は更新を追加します`[l, r]`、位置でトレプを分割します`l`そして`r + 1`, isolating exactly the affected segment block. 更新が実行の境界外に漏れてはいけないため、この手順が必要です。 
3. 分割セグメント内のすべてのノードへの遅延タグまたは加算の直接伝播を維持します。 増分を適用した後、隣接するノードの値が等しくなった場合は、それらのノードをマージする必要がある場合があります。 このマージ ステップでは、各ノードが最大実行であるという不変条件が保持されます。 
4. お問い合わせについて`[l, r]`でまた分かれました。`l`そして`r + 1`関連する実行シーケンスを分離します。 
5. このセグメント内の実行のみをトラバースし、各実行を実行順序のすぐ隣の実行と比較してチェックすることによって極小値を計算します。 
6. 抽出された極小値から、それらが単一パスによって厳密に増加するシーケンスを形成していることを検証します。 

各操作の後、分割された部分をマージして戻し、完全なトレプを復元します。 

### なぜ効果があるのか

 重要な不変点は、常に treap が配列を一連の最大の等しい値の実行として表し、treap 内の隣接関係が圧縮配列定義内の隣接関係に正確に対応することです。 極小値は等しい連続値を折りたたんだ後に定義されるため、すべての候補構造はランによって完全に表現され、情報が失われることはありません。 範囲の更新は実行内の値のみを変更し、等価性の変更は明示的に維持される隣接する実行間の境界にのみ影響します。 これにより、圧縮された定義内の極小値が実行シーケンスの極小値に正確に対応することが保証されるため、実行時に計算されたクエリは完全に展開された配列上のクエリと等価になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Node:
    __slots__ = ("val", "prio", "left", "right", "size", "lazy")
    def __init__(self, val):
        import random
        self.val = val
        self.prio = random.randint(1, 10**9)
        self.left = None
        self.right = None
        self.size = 1
        self.lazy = 0

def sz(t):
    return t.size if t else 0

def upd(t):
    if t:
        t.size = 1 + sz(t.left) + sz(t.right)

def push(t):
    if t and t.lazy:
        t.val += t.lazy
        if t.left:
            t.left.lazy += t.lazy
        if t.right:
            t.right.lazy += t.lazy
        t.lazy = 0

def merge(a, b):
    if not a or not b:
        return a or b
    push(a)
    push(b)
    if a.prio < b.prio:
        a.right = merge(a.right, b)
        upd(a)
        return a
    else:
        b.left = merge(a, b.left)
        upd(b)
        return b

def split(t, k):
    if not t:
        return (None, None)
    push(t)
    if sz(t.left) >= k:
        a, b = split(t.left, k)
        t.left = b
        upd(t)
        return (a, t)
    else:
        a, b = split(t.right, k - sz(t.left) - 1)
        t.right = a
        upd(t)
        return (t, b)

def inorder(t, res):
    if not t:
        return
    push(t)
    inorder(t.left, res)
    res.append(t.val)
    inorder(t.right, res)

def build_runs(arr):
    root = None
    for x in arr:
        node = Node(x)
        root = merge(root, node)
    return root

def compress_list(vals):
    res = []
    for v in vals:
        if not res or res[-1] != v:
            res.append(v)
    return res

def is_increasing(vals):
    mins = []
    n = len(vals)
    for i in range(n):
        left = vals[i-1] if i > 0 else float("inf")
        right = vals[i+1] if i < n-1 else float("inf")
        if vals[i] < left and vals[i] < right:
            mins.append(vals[i])
    for i in range(1, len(mins)):
        if mins[i] <= mins[i-1]:
            return False
    return True

def solve():
    n = int(input())
    arr = list(map(int, input().split()))
    root = build_runs(arr)

    m = int(input())
    for _ in range(m):
        tmp = input().split()
        if tmp[0] == "update":
            l, r, d = map(int, tmp[1:])
            a, b = split(root, l-1)
            b, c = split(b, r-l+1)

            def add(t):
                if t:
                    t.lazy += d
                return t

            b = add(b)
            root = merge(merge(a, b), c)

        else:
            l, r = map(int, tmp[1:])
            a, b = split(root, l-1)
            b, c = split(b, r-l+1)

            vals = []
            inorder(b, vals)
            vals = compress_list(vals)

            print("YES" if is_increasing(vals) else "NO")

            root = merge(merge(a, b), c)

if __name__ == "__main__":
    solve()
```treap はセグメントをノードとして暗黙的に格納しますが、論理的には各ノードは圧縮構造内の実行要素として動作します。 分割によりクエリ範囲が分離されるため、関連する部分のみが検査されます。 遅延伝播により、すべてのノードをすぐに再構築しなくても、範囲の追加が効率的に維持されます。 等価性の変更は値が実際に比較される場合にのみ問題となるため、圧縮ステップはクエリ時にのみ適用されます。 

微妙な点は、実行がクエリ境界を越えてマージされる可能性がありますが、実行順序が隣接していない限りグローバル構造に影響を与えないため、正確性はクエリ セグメントの抽出後にのみ圧縮ビューを再構築することに依存することです。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n + m) log n) 償却 | 各分割/マージ操作は対数的であり、各更新/クエリは対数的な数の treap ノードのみに影響します。

 ## 特殊なケース

 次のような完全に均一な配列`[7,7,7,7]`定数を追加すると等価性が維持されるため、すべての更新を通じて 1 回の実行が維持されます。 どのようなクエリでも、圧縮によって得られる値は 1 つであり、極小値は存在しないため、答えは常に YES になります。 マージ後のトレプには常に単一のノードが含まれており、順序トラバーサルによってシングルトン リストが生成されるため、アルゴリズムはこれを処理します。 

のようなケース`[1,2,3]`値を等しくする更新を繰り返すことで、たとえば`[2,2,3]`、更新の伝播後に最初の 2 つの実行がマージされます。 treap マージ ステップにより、遅延更新を適用した直後に隣接関係の等価性が検出され、2 つの隣接ノードが同じ値を共有しないという不変条件が維持されます。 

次のような単一要素のクエリ範囲`[l,l]`常に単一値シーケンスを生成します。 極小値チェックは空を返しますが、単調性に違反する可能性のある比較がないため、デフォルトでは厳密に増加していると解釈されます。
