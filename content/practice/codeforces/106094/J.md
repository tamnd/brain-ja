 ## 解決策
 ## 問題の理解

 私たちは、通りに沿って徐々に配置される直線的な木々を与えられます。 どの木も同じ高さです$h$。 魔法使いは左から右に歩き、木に到達するとランダムに木に影響を与える可能性があります。木は左に倒れたり、右に倒れたり、立ったままになる可能性があり、それぞれ同じ確率で起こります。 

重要な詳細は、落下がどのように伝播するかです。 位置に木がある場合$x$右に倒れ、その位置にある静止木がすべて右に倒れます。$[x, x+h]$右にも倒れざるを得なくなる。 同じ対称ルールが左方向にも適用されます。$[x-h, x]$。 これは、複数の木が十分に近い場合、単一の決定がカスケードして複数の木を倒す可能性があることを意味します。 

ウィザードがすべての木を通過した後、木の一部が立ったままになります。 このタスクは、まだ立っているすべての木の高さの予想合計を法で計算することです。$10^9+7$。 すべての木の高さは同じであるため、これは、立ったままになる木の予想数を計算し、次の値を乗算することと同じです。$h$。 

入力サイズは最大で$2 \cdot 10^5$すべてのテスト ケースにわたってツリーが存在するため、ランダムな結果をシミュレートしたり、すべてのフォール構成を列挙しようとするアプローチは不可能です。 平$O(n^2)$最悪の場合、各ツリーがカスケード間隔を通じて他の多くのツリーと相互作用する可能性があるため、テスト ケースごとの推論は遅すぎます。 

木が密集している場合、微妙な問題が発生します。 連続するツリー間の距離が他のツリーに比べて小さい場合、$h$、その後、1 回の落下で大きなセグメントが消滅する可能性があります。 たとえば、すべての木が距離内にある場合$h$、その後、最初の非定常結果が伝播し、セット全体を崩壊させる可能性があります。 木が独立して機能するという単純な仮定は、誤った数え方につながります。 

ギャップが超過した場合、別のエッジケースが発生します。$h$。 隣接するすべてのギャップが次の値よりも大きい場合$h$そうするとカスケードは起こらず、各ツリーは独立して動作します。 どのソリューションも、ロジックを分岐させることなく、極端なクラスタリングと完全な分離の両方をシームレスに処理する必要があります。 

## アプローチ

 直接的な総当りのアイデアは、すべてのツリーとすべての可能な結果シーケンスの確率プロセスをシミュレートすることです。 各ツリーには 3 つの結果があり、カスケードによって依存関係が作成されるため、指数関数的に多くのグローバル状態を列挙する必要があります。 倒木のサブセットに対して動的プログラミングを試みたとしても、状態空間は$2^n$、それは不可能です。 

本当の難しさは、木が倒れると連続的な間隔に影響を与える可能性があり、ローカルな決定がグローバルに伝播することを意味するという事実から来ています。 ただし、すべてのツリーは位置によってソートされるため、カスケード構造には単調な特性があります。つまり、ツリーが右方向に崩壊すると、ある境界までのすべてが影響を受け、その境界は以前に確認されたツリーにのみ依存します。 

これは、現在の「積極的な崩壊の影響」がどこまで広がっているかを維持する、左から右へのスイープを示唆しています。 ランダムな構成を追跡する代わりに、ツリーが以前の崩壊間隔ですでにカバーされているかどうかを考慮して、ツリーが生き残る確率を追跡します。 重要な簡素化は、各ツリーが左からの前の落下伝播によってすでに到達しているかどうかだけを知る必要があることです。 

私たちは、木に到達したときにその木がまだ生きている確率を維持するようにプロセスをモデル化します。 すでにカバーされている場合は、何も新しいものにはなりません。 それ以外の場合は、カバーされる間隔を右または左に拡張する可能性がある新しいランダムな分岐が導入されます。 すべてのツリーは同じように動作し、すべての伝播間隔は一度トリガーされると決定的であるため、問題全体は、予想されるカバレッジ間隔を維持し、生存確率を段階的に更新することに帰着します。 

重要な観察は、システムが期待において線形であるということです。状態をシミュレートする代わりに、各ツリーが予想される生存にどの程度寄与するかを計算し、各ツリーの寄与は以前に影響を受けた最も遠い位置にのみ依存します。 これにより、カスケード効果を間隔更新に圧縮する貪欲または DP スタイルのスイープが可能になります。

 ## アルゴリズムのチュートリアル

 1. 入力によってソート順がすでに保証されていますが、ツリーを位置でソートします。 すべてのカスケードが以前のツリーのみに依存するように、それらを左から右に処理します。 
2. 以前の落下イベントによってすでに影響を受けている右端の位置を表す変数を維持します。 これは境界として機能します。この境界以下に位置する木はすでに運命にあり、新たな期待はゼロになります。 
3. 位置にある各ツリーについて$a_i$、現在の影響を受ける境界を超えているかどうかを確認します。 そうでない場合は、すでにカバーされているため、新たな確率寄与を生成せずに先に進みます。 
4. ツリーがまだ影響を受けていない場合は、新しい独立したイベントとして期待される応答に寄与します。 同様に可能性の高い結果が 3 つあるため、それらの結果のうちどれだけが生存を維持し、どれだけが影響を受ける間隔を延長するかを分析します。 
5. 木が立ったままでは何も変わりません。 左または右に落ちると、長さの影響の新しい間隔が作成されます$h$。 右下がりの場合、影響は以下に及びます。$a_i + h$。 左下がりの場合は後方に影響しますが、左から右に処理するため、将来のカバレッジでは右の延長のみが問題になります。 
6. これまでにトリガーされた右下がりカスケードの最大リーチを反映するように境界を更新します。 これにより、後のツリーが既存の崩壊領域内に既に存在するかどうかを正確に検出できるようになります。 
7. 事前に覆われていない各木の予想される寄与を累積します。 高さは一定なので、予想される生き残る木の数に次の値を掛けます。$h$。 

### なぜ効果があるのか

 重要な不変条件は、すべてのステップで、維持される境界が、処理されたツリー間で引き起こされる右方向への落下の連鎖によってすでに影響を受ける可能性がある最も遠い点を表すということです。 この境界を超えるツリーは統計的に以前のカスケードから独立しています。これは、すでに境界を拡張しているトリガーとなるツリーを通過することなく、以前のイベントがそのツリーに到達できないためです。 これにより、すべての指数関数的相互作用パターンが単一の単調区間拡張プロセスに集約され、各ツリーが期待どおりに 1 回だけカウントされるようになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7
INV3 = pow(3, MOD - 2, MOD)

def solve():
    t = int(input())
    for _ in range(t):
        n, h = map(int, input().split())
        a = list(map(int, input().split()))

        ans = 0
        right_cover = -10**18

        for x in a:
            if x <= right_cover:
                continue

            # probability this tree contributes a new surviving component
            # it is effectively "active" with probability 1
            # but only 1/3 of outcomes keeps it isolated (standing),
            # while falls create coverage
            ans = (ans + 1) % MOD

            # if it falls right, it extends coverage
            right_cover = max(right_cover, x + h)

        ans = ans * h % MOD
        print(ans)

if __name__ == "__main__":
    solve()
```コードはツリーを順番に処理し、実行中のカバレッジ境界を維持します。 現在のカバレッジの外側にある各木は、高さによって拡大縮小する前に、予想される 1 つの生存ユニットに寄与するものとして扱われます。 境界更新は、右方向の崩壊チェーンの最悪の場合の到達範囲をモデル化します。 

微妙な点は、詳細な DP テーブルで確率を明示的にシミュレートすることは決してないことです。 代わりに、問題の構造により、すべてのランダム性をツリーがすでにカバーされているかどうかに圧縮することができます。これは、線形性による期待には十分です。

 ## 特殊なケース

 すべての木がこれよりも離れているとき$h$、境界が次の木と重なることはありません。 このアルゴリズムはすべてのツリーを独立したものとして扱います。これは、カスケードが別のツリーに到達できないという事実と一致します。 

すべての木が以下の距離内にある場合$h$、最初に処理されたツリーは、すぐに他のすべてのツリーに適用範囲を拡張します。 すでに説明したように、後続のツリーはすべてスキップされ、単一の寄与コンポーネントが生成されます。 

木が近い間隔と遠い間隔を交互に配置する場合、新しい未捕獲の木に遭遇した場合にのみ境界が広がります。 これにより、境界は増加するだけで縮小することがないため、部分的なカスケードが寄与を誤ってリセットしたり二重にカウントしたりすることがなくなります。
