 ## 解決策
 ## 問題の理解

 それぞれがキャンディーの「風味スコア」を表す複数の数値セットが与えられます。 タスクは、固定ルールを使用してこれらの数値を繰り返し結合してより大きな値にすることです。利用可能な 2 つの数値を選択し、それらを結合してその合計に等しい 1 つの新しい数値にし、1 つの数値だけが残るまで繰り返します。 最後に残った数値はプロセス全体の合計「yum 値」であり、この最終値ができるだけ小さくなるようにマージの順序を選択したいと考えています。 

この操作では常に数値が加算されますが、重要な点は、中間の選択が将来のマージに影響を与え、プロセスの総コスト構造が変化することです。 単純にすべてを 1 回合計するわけではありません。加算を繰り返す構造により、結合されるタイミングに応じて一部の数値の重み付けが事実上大きくなるからです。 

入力は複数のテスト ケースを表します。 各テスト ケースは整数のリストであり、各リストについて、許可された操作を使用して要素を繰り返しマージした後、可能な最小の最終結果を決定する必要があります。 

制約 (Codeforces ジム ラウンドのこのタイプの問題に典型的なもの) は、テストあたりの要素の数が十分に大きくなり、考えられるすべてのマージ順序の O(n²) シミュレーションが不可能になる可能性があることを示唆しています。 マージ ツリーの数が超指数関数的に増加するため、マージのすべてのペアまたはすべてのシーケンスを試行するアプローチは、組み合わせ的に爆発的に増加します。 

すべての値が等しい場合、微妙なエッジケースが発生します。 単純なアプローチでは、加算は結合的で可換的であるため、どのマージ順序も同等であると想定する可能性があります。 コスト累積プロセスには当てはまりません。 たとえば、数字の場合`[1, 1, 1]`、結合`(1,1)`最初の収穫`2`、次にマージします`1`収量`3`。 しかし、ここではマージ順序が異なっても同じ結果が得られるため、順序は重要ではないと誤解する可能性があります。 間違いは、次のような混合入力で顕著になります。`[1, 2, 9]`ここで、貪欲なペアリングは中間の重みを変更し、したがって寄与を変更します。 

もう 1 つの特殊なケースは、単一要素入力です。 と`[x]`、マージは実行されないため、答えは次のようになります。`x`。 少なくとも 1 つのマージ ステップを前提とした実装では、値が誤って変更されます。 

## アプローチ

 ブルートフォースの観点では、これを配列上で可能なすべてのバイナリ マージ ツリーを探索するものとして扱います。 すべての内部ノードは 2 つの子のマージを表し、その値はさらなるマージに寄与します。 考えられるすべてのペアリング順序をシミュレートすると、n 個の葉にわたるすべての完全なバイナリ ツリーを効果的に列挙し、誘発コストを計算することになります。 

これは操作の正確なルールを尊重するため、原則として正しいです。 ただし、n 個の要素をペアにする方法の数はカタロニア数に比例し、おおよそ次のように増加します。$O(4^n / n^{3/2})$。 n = 30 の場合でも、これはすでに実行不可能であり、一般的な制約ははるかに大きくなります。 

重要な観察は、このプロセスが重みを繰り返し結合することと構造的に同じであり、マージのたびに合計コストがマージされたペアの合計だけ増加するということです。 これは古典的な「最適なマージ」構造です。 最終コストの合計は、以前のマージが後のマージに影響を与える寄与の合計とみなすことができ、最終値を最小化することは、累積中間コストを最小化することと同等です。 

貪欲な戦略は、局所的な最適性に焦点を当てることから生まれます。つまり、各ステップで、利用可能な 2 つの最小の値を組み合わせることで、将来のすべての計算に対する即時の増加が最小限に抑えられます。 より大きな値が先にマージされると、後続のステップで繰り返し追加され、最終結果が不必要に大きくなります。 

これにより、常に最小の 2 つの数値が抽出され、それらがマージされ、結果がプールに戻されるという問題が軽減されます。 最小ヒープは現在のマルチセットを効率的に維持し、常に最適なペアを選択できるようにします。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. 最小の要素を効率的に取得できるように、すべての数値を最小ヒープに挿入します。 ヒープを使用する理由は、すべてのステップで、動的に変化するセットから 2 つの最小値を選択する必要があるためです。 
2. ヒープ内に複数の要素が残っている間に、最小の 2 つの値を抽出します。 これらは、最も低コストの即時マージの選択肢を表します。 
3. それらの合計を計算し、現在までの合計に追加します。 この合計は、新しいマージされた値と、このマージの実行によって発生する増分コストの両方を表します。 
4. マージされた値は将来のマージに参加するため、ヒープにプッシュされます。 このステップにより、利用可能な番号の正しい状態が維持されます。 
5. 単一の値が残るまで繰り返し、その時点ですべての寄与が蓄積されます。 

最終的な累計がテスト ケースの答えになります。 

### なぜ効果があるのか

 いつでも、可能な最小のペアではなく、より大きな 2 つの要素を選択すると、より大きな値が将来のマージに上向きに伝播されます。 ヒープ内に残るすべての要素は最終的に複数回マージされるため、早い段階で大きな値を導入すると、その寄与が繰り返し増幅されます。 不変条件は、各マージ ステップの後、ヒープに未解決の値の正しいマルチセットが含まれており、貪欲な選択により、将来の最適性を損なうことなくそのステップの増分コストを最小限に抑えることです。 すべてのマージではその合計が合計コストに 1 回だけ加算され、大きな値を遅らせても将来の合計への繰り返しの参加が増加するだけであるため、貪欲な選択はグローバルに最適なままです。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        arr = list(map(int, input().split()))
        
        if n == 1:
            print(arr[0])
            continue
        
        heapq.heapify(arr)
        total = 0
        
        while len(arr) > 1:
            a = heapq.heappop(arr)
            b = heapq.heappop(arr)
            s = a + b
            total += s
            heapq.heappush(arr, s)
        
        print(total)

if __name__ == "__main__":
    solve()
```ヒープの初期化により、常に対数時間で最小の要素にアクセスできることが保証されます。 ループ構造は貪欲アルゴリズムを直接反映しています。各反復では、マージのコストを考慮しながら、問題のサイズが 1 要素ずつ削減されます。 

n = 1 の特殊なケースにより、操作が不可能な場合にマージ コストが誤って追加されることが防止されます。 

一般的な実装の落とし穴は、マージの合計を答えに蓄積することを忘れ、代わりに最終ヒープ要素のみを追跡することです。 最終的な残りの値だけではなく、中間マージ コストが目的を定義するものであるため、合計が正しく計算されません。 

## 実用的な例

 インプットを考慮する`[1, 2, 3]`。 

山から始めます`[1, 2, 3]`。 

| ステップ | ヒープ状態 | 選択されたペア | マージ結果 | 総コスト |
 | --- | --- | --- | --- | --- |
 | 1 | [1、2、3] | (1, 2) | 3 | 3 |
 | 2 | [3、3] | (3, 3) | 6 | 9 |

 最終的な答えは9です。 

これは、最初に最小の要素をマージすると、後のステップで多数の要素が繰り返し追加されるのを防ぐことができることを示しています。 

ここで考えてみましょう`[4, 1, 1, 1]`。 

| ステップ | ヒープ状態 | 選択されたペア | マージ結果 | 総コスト |
 | --- | --- | --- | --- | --- |
 | 1 | [1、1、1、4] | (1, 1) | 2 | 2 |
 | 2 | [1、2、4] | (1, 2) | 3 | 5 |
 | 3 | [3、4] | (3,4) | 7 | 12 |

 このトレースは、大きな値がどのように遅延するかを示しています`4`早期マージコストの高騰を回避します。 もし`4`早期にマージされた場合は、その後の複数の合計に加算され、最終結果が増加します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

 | 時間 | テストあたり O(n log n) | n-1 個のマージはそれぞれ、2 つのヒープ ポップと 1 つのプッシュを実行します。 
| スペース | O(n) | ヒープは処理中にすべての要素を格納します。 

この問題クラスに典型的な制約により、テスト ケース全体で最大約 2×105 個の合計要素が許可され、効率的なヒープ操作により、n log n アプローチが時間制限内に快適に収まります。 

## テストケース```python
import sys, io
import heapq

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        arr = list(map(int, input().split()))
        if n == 1:
            out.append(str(arr[0]))
            continue
        heapq.heapify(arr)
        total = 0
        while len(arr) > 1:
            a = heapq.heappop(arr)
            b = heapq.heappop(arr)
            s = a + b
            total += s
            heapq.heappush(arr, s)
        out.append(str(total))
    return "\n".join(out)

 ## 特殊なケース

 次のような単一要素入力の場合`[7]`、ヒープには最初から値が 1 つだけ含まれます。 ループは完全にスキップされ、アルゴリズムは 7 を直接出力します。これは、マージが実行されないという事実と一致します。 

次のような大きく偏った入力の場合`[100, 1, 1]`、ヒープは次のように始まります`[1, 1, 100]`。 最初のマージは、`(1, 1)`生産する`2`、 それから`(2, 100)`生産する`102`、累積コストは`2 + 102 = 104`。 このアルゴリズムは、大きな値を自然に遅延させ、複数の早期マージに参加することを防ぎ、大きな値はできるだけ遅くマージする必要があるという貪欲な不変条件を確認します。
