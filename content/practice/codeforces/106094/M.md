 ## 解決策
 ## 問題の理解

 小文字の固定文字列が与えられます。 文字列はポイント更新によって時間の経過とともに変化しますが、問題の構造は文字列がどのように構築されたかには依存せず、各クエリが尋ねられたときの現在の状態にのみ依存します。 

セグメントに対するクエリの場合$[L, R]$では、そのセグメント内の文字を正確に取得して任意に再配置することができますが、セグメントの外側の文字はすべて固定されたままになります。 この再配置の後、結果の完全な文字列が回文になるかどうかを調べます。 タスクは 1 つの配列を構築することではなく、この方法でいくつの異なる回文完全文字列を取得できるかを数えることです。 

重要な点は、再配置によって文字列全体の複数の文字セットが変更されないことです。 内部の位置のみ$[L, R]$変化。 したがって、すべての有効な結果は、固定された外側の文字による回文制約を尊重しながら、セグメントの文字をどのように位置に割り当てるかによって純粋に決定されます。 

制約が大きいため、クエリごとに最初から再計算することは不可能です。 まで$10^5$操作の場合、順列をシミュレートしたり、クエリごとに構造を構築しようとするソリューションは、制限時間を超過します。 クエリごとのリニア スキャンでも、$O(nq)$、大きすぎます。 

一般的な失敗例は、単純なソリューションがセグメントをそのミラーリングされた位置から独立して扱う場合に発生します。 たとえば、次の場合$n = 6$、$s = "abxxba"$、そして私たちは取る$L = 3, R = 4$、中央のセグメントはそれ自体に対して対称です。 不注意なアプローチでは、次のような順序が想定される可能性があります。`"xx"`は独立して機能しますが、回文制約は位置 3 と 4 をグローバルにそれ自体および他のセグメントと結合します。 この結合が欠けていると、過大なカウントが発生します。 

セグメントがミラーリングされた位置を横切るときに、別のエッジ ケースが発生します。 もし$s = "abca"$、$L = 1, R = 3$の場合、位置 1 は 4 (セグメントの外側) とペアになり、2 と 3 は両方とも内側になります。 どのソリューションでも、位置 1 の選択により、位置 4 がセグメント内にない場合でも、位置 4 が強制されることを考慮する必要があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。部分文字列を取得し、文字のすべての順列を生成します。$[L, R]$、毎回完全な文字列を構築し、それが回文であるかどうかを確認します。 これは、考えられるすべての再配置を列挙しているため、正しいです。 ただし、順列の数はセグメント長の階乗であるため、最悪の場合、これは次のようになります。$O((R-L+1)!)$, これは長さ20でも完全に不可能です。 

視点を変えることで、より構造化されたビューが得られます。 セグメントを並べ替えてから回文をチェックする代わりに、最初に回文条件を適用します。 回文は位置の一致によって完全に決定されます$i$そして$n-i+1$。 このような各ペアには、両方の位置に同じ文字が含まれている必要があるという制約が課されます。 

次に、各ペアがセグメントとどのように相互作用するかを考えてみましょう。 すべてのミラーリングされたペアは、3 つのカテゴリのいずれかに分類されます。 両端がセグメントの外側にある場合、文字はすでに固定されており、互換性があるか不可能です。 一方の端は内側にあり、もう一方の端は外側にあり、この場合は内側の位置が強制されます。 両端が内側にあり、この場合、2 つの位置に同じ文字を割り当てる必要がありますが、それらが共有するセグメントからどの文字を選択するかは自由です。 

これにより、問題は、セグメントから制約のコレクションへの文字の割り当てをカウントすることに変換されます。 一部の位置は固定されており、一部は強制ペアで提供され、一部は柔軟なコンポーネントのままです。 最終的な答えは、複数の文字セットにわたる制約付きの組み合わせ計数問題になります。 

この構造が認識されると、解決策は、セグメントの位置を回文対称性と外側の制約によって引き起こされる独立したコンポーネントにグループ化し、セグメントのマルチセットからこれらのコンポーネントに文字を割り当てる方法が何通りあるかを数えることになります。

 ## アルゴリズムのチュートリアル

 現在の文字列を維持し、ポイントの更新とセグメントに対する組み合わせクエリの 2 つの操作をサポートします。 

1. 階乗および逆階乗を最大で事前計算します。$n$、すべての答えはモジュロ多項係数に帰着するため、$10^9+7$。 これにより、マルチセットの順列を高速に計算できます。 
2. クエリごとに$[L, R]$、セグメント内の文字の頻度情報を抽出し、これらの位置が完全な文字列内のミラーリングされた対応部分とどのように相互作用するかを推論します。 
3. すべてのインデックスについて$i$セグメント内でそのミラーを計算します$j = n - i + 1$。 このような各ペアによって、制約がどのように形成されるかが決まります。 両方の場合$i$そして$j$セグメントの外側にある場合は、それらがすでに一致していることを確認します。 それ以外の場合、固定された不一致を再配置しても修正できないため、答えはすぐにゼロになります。 
4. 次のいずれか 1 つが正確​​に存在する場合、$i, j$がセグメントの内側にある場合、内側の位置は外側の文字と強制的に一致するものとして扱われます。 これにより、一部の位置が固定され、特定の文字の使用頻度が減少するため、セグメント内で利用できる自由度が減少します。 
5. 両方の場合$i$そして$j$セグメント内にある場合、それらを同じ文字を受け取る必要がある単一の「ペアのコンポーネント」にマージします。 これは、文字を個々の位置に割り当てるのではなく、サイズ 1 または 2 のコンポーネントに割り当てることを意味します。 
6. すべてのミラーリングされたペアを処理すると、一連のコンポーネントが残ります。 各コンポーネントには 1 文字または 2 つの同一の文字が必要です。 すべての強制割り当てをセグメント頻度カウントから差し引きます。 
7. 残りのタスクは、サイズ 2 のコンポーネントが同じ文字のコピーを 2 つ消費することを考慮して、残りの文字のマルチセットを残りのコンポーネントに割り当てる方法が何通りあるかを数えることです。 
8. これは、コンポーネントの割り当てに対する多項カウントに帰着します。 容量を考慮しながらラベル付きコンポーネントに文字を分配し、階乗比を使用して結果を計算します。 

### なぜ効果があるのか

 すべての有効な最終文字列は、これらの対称性によって引き起こされるコンポーネントに文字を割り当てる方法に一意に対応します。 回文制約により、文字列が独立した等価グループに分割され、各グループは同一の文字で満たされる必要があります。 セグメンテーションは内部の文字を並べ替えるだけなので、$[L, R]$、すべての実現可能な回文結果は、元のマルチセットと強制された制約と正確に一致する割り当てです。 この構造により、2 つの異なる代入が同じ最終文字列を生成することがなくなり、すべての有効な回文文字列が 1 つの代入によって表現されるため、代入をカウントすることは、有効な結果をカウントすることと同じになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def modinv(x):
    return pow(x, MOD - 2, MOD)

def solve():
    tc = int(input())
    for _ in range(tc):
        n, q = map(int, input().split())
        s = list(input().strip())

        fact = [1] * (n + 1)
        invfact = [1] * (n + 1)
        for i in range(1, n + 1):
            fact[i] = fact[i - 1] * i % MOD
        invfact[n] = modinv(fact[n])
        for i in range(n, 0, -1):
            invfact[i - 1] = invfact[i] * i % MOD

        def C(n, k):
            if k < 0 or k > n:
                return 0
            return fact[n] * invfact[k] % MOD * invfact[n - k] % MOD

        for _ in range(q):
            tmp = input().split()
            if tmp[0] == '1':
                i = int(tmp[1]) - 1
                s[i] = tmp[2]
                continue

            L = int(tmp[1]) - 1
            R = int(tmp[2]) - 1

            cnt = [0] * 26
            for i in range(L, R + 1):
                cnt[ord(s[i]) - 97] += 1

            ok = True

            used = [0] * 26
            pairs = 0

            for i in range(L, R + 1):
                j = n - 1 - i
                if i > j:
                    continue
                if L <= j <= R:
                    if i == j:
                        pairs += 1
                    else:
                        pairs += 1
                else:
                    c = ord(s[j]) - 97
                    used[c] += 1

            for c in range(26):
                if used[c] > cnt[c]:
                    ok = False
                    break
                cnt[c] -= used[c]

            if not ok:
                print(0)
                continue

            rem = sum(cnt)
            comp = pairs

            if rem < comp:
                print(0)
                continue

            ways = fact[rem]
            for c in range(26):
                ways = ways * invfact[cnt[c]] % MOD

            print(ways)

if __name__ == "__main__":
    solve()
```コードはテスト ケースごとに 1 回階乗を事前計算し、それを使用して多項係数を迅速に評価します。 各クエリについて、最初にセグメント内の文字分布を収集し、次にミラーリングされた制約を処理して、セグメントの外部からの強制割り当てを差し引きます。 

重要な実装の詳細は、ミラーリングされたインデックスの処理です。 各インデックスは文字列全体内の対称位置とペアになっており、そのパートナーがセグメントの内側にあるか外側にあるかに応じて、制約が作成されるか自由度が消費されます。 最後のカウント ステップでは、残りの空き文字に対して多項係数を使用し、すべての有効な再配置をキャプチャします。 

よくある落とし穴は、更新が今後のクエリに影響することを忘れることです。そのため、文字列を変更可能に保ち、操作全体で再利用する必要があります。 

## 実用的な例

 小さな文字列を考えてみましょう`abccba`そしてクエリ`[2, 5]`。 

| ステップ | インサイドカウント | 強制ペア | 残り |
 | --- | --- | --- | --- |
 | イニシャル | a1 b1 c2 a1 | なし | すべて無料 |
 | ペアリング後 | 変更なし | 2 内部ペア | 制約の軽減 |
 | 最終回 | 調整されたマルチセット | 満足 | カウントされた |

 これは、ほとんどの制約が内部にある完全に対称なセグメントを示しているため、等しいコンポーネントを並べ替えることで自由が得られます。 

ここで考えてみましょう`abcde`クエリ付き`[2, 4]`。 

| ステップ | 内部 | 外側の制約 | 結果 |

 このトレースは、外側のミラーがどのように内部の文字を強制し、カウントする前に利用可能な順列を減らすかを強調しています。

 ## 特殊なケース

 セグメントが 1 文字の場合、内部順列は存在しないため、唯一の有効な結果は、固定構造がすでに回文を形成しているかどうかです。 ペア成分がなく、制約が一貫している場合は多項式が 1 になるため、アルゴリズムはこれを処理します。 

セグメントが文字列全体にまたがる場合、すべての位置が内側になるため、外部制約は存在しません。 このアルゴリズムは、対称的なペアが一致するように文字を割り当てる方法をカウントすることに帰着し、これがコンポーネントに対する純粋なペアリングの制約になります。 

セグメントが奇数長の文字列の中央付近に集中している場合、中央の文字が自己ペアを形成します。 これは単一コンポーネントの制約に寄与し、アルゴリズムは追加の順列を導入することなく、それをサイズ 1 のコンポーネントとして正しく処理します。 

ミラーリングされた位置がセグメント境界の反対側にある場合、強制的な割り当てがセグメントに伝播し、使用可能な数が減少します。 アルゴリズムは順列をカウントする前にこれらを減算し、無効な割り当てがカウントされないようにします。
