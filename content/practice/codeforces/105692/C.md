 ## 解決策
 ## 問題の理解

 セルの行を表すバイナリのターゲット文字列が与えられます。最初はすべて白です。 許可される唯一の操作は、2 つの隣接するセルに作用します: インデックスを選択するとき$i$、セルを強制的に設定します$i$ホワイトとセルへ$i+1$以前の状態に関係なく、黒になります。 

目標は、このようなローカル操作のシーケンスによって、真っ白なラインを必要な白黒パターンに変換できるかどうかを判断し、変換できる場合は、有効な一連の動きを出力することです。 

各操作は 2 つの隣接する位置のみに触れ、常に固定された非対称な方法でそれらを上書きします。つまり、左のセルが白になり、右のセルが黒になります。 この非対称性が問題の構造の全体的な原因です。 

制約$n \le 100$構築に高度な最適化が必要ないことを意味します。 テスト ケースごとに 2 次作業を行う解、または小さな一定範囲内の 3 次作業を含む解は、問題なく合格します。 操作の数も適度な値に制限されているため、実行可能性を判断するだけではなく、シーケンスを明示的に構築することが期待されます。 

微妙なエッジケースは、ターゲット文字列がすでにすべて白である場合です。 その状況では操作は必要なく、セルを「修正」しようとしても不要な黒セルが取り込まれるだけなので、答えは空のシーケンスになるはずです。 

もう 1 つの重要なエッジ ケースは、黒いセルが最後の位置に表示される場合です。 黒のセルを作成するすべての操作では常に、選択したペアの右のエンドポイントとして黒のセルが作成され、その右側にはセルが存在しないため、$n$、最後の位置は、インデックスの右エンドポイントとしてペアにされている場合にのみ黒になります。$n-1$。 これは、この構造が基本的に操作の正しいエンドポイントを配置することを目的としているということをすでに示唆しています。 

より欺瞞的な状況は、次のようなパターンが交互に現れることです。$1010$。 以前の選択を再検討せずに左から右へ修正しようとする単純な貪欲な場合、すべての操作が両方の位置を上書きするため失敗する可能性があり、局所的な修正によって以前の正確さが破壊される可能性があります。 

## アプローチ

 強引なアイデアは、プロセスを全体的な状態グラフとして扱うことです。$2^n$バイナリ文字列を指定し、空の構成から BFS を実行します。 各州には最大で$n-1$遷移するため、エッジの数は次のようになります。$O(n 2^n)$。 これはすでに大きすぎます$n=100$しかし、より重要なのは、構造を無視していることです。操作では常に非常に特殊な方法で黒セルが導入され、恣意的に黒セルを削除できないため、ほとんどの状態は無関係です。 

重要な観察は、黒セルが独立していないということです。 すべての操作で、その位置に黒セルが 1 つだけ作成されます。$i+1$、同時に位置を強制します$i$白に。 これは、黒のセルが常に、右のエンドポイントがその位置にある操作によって「所有」されていることを意味します。 逆に考えると、すべての黒セルは、その左隣を対象とした少なくとも 1 つの演算によって説明されなければなりません。 

これは、右から左にスキャンすることを示唆しています。 必要な黒が位置にある場合$i$、それを作成する唯一の方法は、で操作を適用することです。$i-1$。 運用を決定したら$i-1$、配列に対する局所的な影響がすぐにわかります。 これにより、グローバル検索の必要がなくなります。各黒セルは決定的なローカル アクションを強制します。 

残りの問題は、隣接する強制作戦間の相互作用が互いに矛盾し得るかどうかである。 この構造は、操作によって常に正しいセルが黒になるように強制されるため、この問題を解決します。 右から左に処理する場合、位置が黒として固定されると、その後の操作で矛盾する方法で再びその位置に触れることがなくなります。

 ## アルゴリズムのチュートリアル

 1. 最終アレイから開始します。これは開始時の構成と一致するため、最初はすべて白です。 
2. ターゲット文字列をインデックスから右から左にスキャンします。$n$まで$2$。 右から左に進む理由は、その位置に黒いセルを作成するすべての操作が必要になるためです。$i$立場だけに依存する$i-1$、したがって、最後から処理することで、後の変更がすでに解決された位置に干渉するのを防ぎます。 
3. ターゲットが位置にあるとき$i$は黒です。インデックスでの操作を適用することで強制します。$i-1$。 この操作により位置が保証されます$i$黒になり、要件に一致します。 
4. 操作を適用した後、作業配列を明示的に更新します: setposition$i-1$白くして位置を決める$i$黒に。 これにより、シミュレーションと操作の上書き動作の一貫性が保たれます。 
5. ターゲットが位置にある場合$i$色は白なので何もしません。 影響を与える操作$i$強制的に黒にするため、そのままにしておくことが唯一の有効な選択です。 
6. スキャン終了後、位置を確認します$1$。 ターゲット内で黒の場合は、位置に書き込む操作がないため、作成できません。$1$正しいエンドポイントとして。 その場合はNOを出力します。 
7. それ以外の場合は、記録された操作とともに YES を出力します。 

正確さは単調性の特性に左右されます: 1 つの位置に 1 回$i$が処理され、選択されたすべての操作は位置にのみ影響します$\ge i$どれも後で変更する必要はありません$i$また。 右から左への順序付けにより、すべての黒セルがその固有の可能なジェネレータ操作によって 1 回だけ「支払われる」ことが保証され、将来の操作はすべて厳密に左にあるため、以前の決定が後で無効になることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    
    for _ in range(t):
        n = int(input())
        s = list(input().strip())
        
        ops = []
        cur = ['0'] + s[:]  # 1-indexed
        
        possible = True
        
        for i in range(n, 1, -1):
            if s[i - 1] == '1':
                ops.append(i - 1)
                cur[i - 1] = '0'
                cur[i] = '1'
        
        if s[0] == '1':
            possible = False
        
        if not possible:
            out.append("NO")
        else:
            out.append("YES")
            out.append(str(len(ops)))
            if ops:
                out.append(" ".join(map(str, ops)))
            else:
                out.append("")
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```実装では、各操作の効果を反映する単純なシミュレーション配列が保持されます。 問題の演算定義と一致するように配列には 1 のインデックスが付けられ、適用時の 1 つ違いの間違いを回避します。$i-1$操作。 

メインループはインデックスを処理します。$n$まで$2$。 黒のセルが必要な場合は、対応する操作をすぐに追加し、シミュレートされた状態を更新します。 これにより、複数の操作が重複するペアに影響を与える場合、最後に適用された制約が常に以前の仮定よりも優先されることが保証されます。 

どの操作でも位置 1 に黒のセルを生成できないため、最初のセルの最終チェックが不可欠です。操作の方向が固定されているため、それを間接的に導出する試みは失敗します。

 ## 特殊なケース

 文字列がすでにすべて 0 である場合、黒のセルを作成する必要がないため、スキャンでは操作は行われません。 アルゴリズムは当然、恒等変換が有効であるという事実と一致して、空の操作リストを返します。 

位置 1 に黒が現れると、どの操作も位置 1 を右端として黒に設定できないため、アルゴリズムは直ちに拒否します。 位置 1 は繰り返し白に上書きできますが、そこに黒を導入するメカニズムがないため、強制的に構築しようとすると失敗します。 

文字列が完全に黒の場合、アルゴリズムは 1 から n-1 までのすべての位置に演算を適用します。 各ステップでは、右のエンドポイントが満たされていることを確認し、後の制約との一貫性を維持するために以前の位置が繰り返し上書きされます。これは、以前の位置は常に左方向の操作によってのみ再訪されるため、許容可能です。
