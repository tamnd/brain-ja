 ## 解決策
 ## 問題の理解

 このタスクは、数値のコレクションから順序情報を抽出することです。与えられた順序では、最大の値だけでなく、重複が無視される順序でそのすぐ下の値も特定したいと考えています。 

より具体的には、整数のリストを見て、どの数値が最大であるかを繰り返し尋ねていると想像してください。 それがわかったら、概念的にその最大の数値が出現するすべてを削除し、同じ質問をもう一度尋ねます。 2 番目の質問に対する答えは、いわゆる 2 番目の最大値です。 

入力は単一の整数配列として解釈できます。 出力は、その配列内で 2 番目に大きい個別の値を表す単一の整数です。 すべての要素が同一である場合、または一意の値が 1 つだけある場合、レポートする有効な 2 番目の最大値は存在しないため、出力にはその欠如を反映する必要があります。 

制約の観点から見ると、このような問題の自然な上限は通常、最大 10^5 以上の要素です。 これにより、要素のすべてのペアを比較したり、クエリごとに部分配列を繰り返し並べ替えたりするソリューションは即座に除外されます。 O(n^2) アプローチでは、最悪の場合でもすでに約 10^10 の演算が実行されるため、一般的な時間制限内には収まりません。 ソートによる O(n log n) の解決策でも許容できますが、問題の構造では 2 つの値の追跡のみが必要であるため、これはやりすぎです。 

配列に最大値の重複が含まれているが、2 番目の個別の値が存在しない場合、微妙なエッジ ケースが発生します。 たとえば、入力`[5, 5, 5]`最大値があります`5`, ただし、2 番目の上限はありません。 ソート後に重複を削除せずに単純に 2 番目の要素を選択する単純な実装では、誤った出力が発生します。`5`、これは区別性の要件に違反します。 

別のエッジケースは、最大値が 1 回発生し、2 番目の最大値が何度も繰り返される場合に発生します。`[10, 3, 3, 3]`。 正しいソリューションでは、重複したスキャン位置を誤って別の候補として扱わないようにする必要があります。 周波数ではなく、値の遷移のみを考慮する必要があります。 

## アプローチ

 最も簡単なアイデアは、配列を降順にソートし、最初の要素を最大値として選択し、より小さい個別の値が見つかるまで前方にスキャンすることです。 これは正しいです。グループの並べ替えでは要素が等しいため、値が変化する最初の位置は 2 番目の最大値に正確に対応します。 欠点は、ソートに O(n log n) のコストがかかることと、この問題には実際には完全な順序付けは必要なく、上位 2 つの異なる値のみが必要であることです。 

より効率的なアプローチは、配列を 1 回スキャンする間に 2 つの値のみを考慮することを観察することによって得られます。 グローバルな順序を構築する代わりに、これまでに確認された最大の値と、これまでに確認された 2 番目に大きい個別の値という 2 つの実行変数を維持します。 新しい要素はそれぞれ、これら 2 つと比較するだけでよいため、問題は 1 つのパスに減ります。 

重要な観察は、現在の最大値より大きい値に遭遇すると、以前の最大値が 2 番目の最大値の候補になるということです。 値が現在の最大値と現在の 2 番目の最大値の間に厳密に存在する場合、2 番目の最大値が更新されます。 それ以外はすべて無視できます。 

これにより、問題全体が一定の追加スペースを伴う線形時間に短縮されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | 並べ替え | O(n log n) | O(1) または O(n) | 受け入れられるが不要 |
 | ワンパストラッキング | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 配列の 1 回のパス中に 2 つの変数を維持します。`max1`これまでに確認された最大値として、`max2`2 番目に大きい個別の値として。 

1. 両方を初期化します`max1`そして`max2`未定義 (または実装によっては負の無限大) として。 これは、まだ値を確認していないことを表します。 
2. 各番号を読み取ってください`x`配列から 1 つずつ。 
3. もし`x`より大きい`max1`、 それから`x`新しい最大値になります。 前回の`max1`(存在する場合) は新しいものになるように下にシフトされます。`max2`。 このステップでは、これまでに確認された最良の 2 つの異なる値が保存されます。 
4. それ以外の場合`x`厳密に次の間です`max1`そして`max2`、 それから`x`次善の候補を改善し、置き換える`max2`。 私たちは平等を無視します`max1`これは、重複によって新しい個別の最大値が作成されないためです。 
5. それ以外の場合は、何もしません。 この値は、すでに考慮した値と重複しているか、小さすぎて問題にならないかのいずれかです。 
6. すべての要素を処理した後、次のことを確認します。`max2`有効な値が割り当てられたことはありません。 そうでない場合は、2 番目の明確な最大値は存在しません。 

これが機能する理由は、スキャンのどの時点でも、`max1`すべての処理された値の中で最大の要素であることが保証され、`max2`より厳密に小さい最大値です`max1`同じ要素の間で。 上位 2 つの個別の値を決定するためには、より小さな構造はすべて無関係であるため、新しい要素はこれら 2 つの要約と競合するだけで済みます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    arr = list(map(int, input().split()))
    
    max1 = None
    max2 = None
    
    for x in arr:
        if max1 is None or x > max1:
            max2 = max1
            max1 = x
        elif x != max1:
            if max2 is None or x > max2:
                max2 = x
    
    if max2 is None:
        print("NO SECOND MAX")
    else:
        print(max2)

if __name__ == "__main__":
    solve()
```この実装は 2 変数不変式を直接反映しています。 最初のブランチは、最大位置への昇格を処理し、前の最大値を正しく降格します。 2 番目のブランチは、現在の最大値と厳密に異なる値のみが影響を与えることができることを保証します。`max2`、区別性を強制します。 最終チェックでは、有効な 2 番目の最大値を持つことと、すべての値が同一であることを区別します。 

よくある落とし穴は、次のような平等を認めてしまうことです。`max1`更新する`max2`これにより、最大値の重複が有効な 2 番目の最大値として誤って処理されてしまいます。

 ## 特殊なケース

 重要なエッジケースは、すべての値が同一である場合です。 この状況では、アルゴリズムは決して割り当てません。`max2`、すべての比較が一致するため、`max1`または、厳密に小さい候補を生成できません。 最終チェックではこれが正しく検出され、「2 番目の最大値なし」という出力が生成されます。 

最大値が配列の後半に現れる場合、別のエッジ ケースが発生します。 たとえば、`[1, 2, 3, 100, 50]`、アルゴリズムは両方を正しく更新する必要があります`max1`そしてリセット`max2`100 に遭遇した場合、以前の候補が新しい最大値に対して 2 番目に最適なものとして誤って保存されないようにします。 最初の分岐の降格ステップは、新しい最大値が見つかるたびに前の最大値を 2 番目の位置にシフトすることで、この動作を保証します。
