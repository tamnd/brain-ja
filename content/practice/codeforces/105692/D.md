 ## 問題の理解

 記入するよう求められます$n \times n$の整数を含むグリッド$1$に$n^2$、それぞれが 1 回だけ使用されるため、グリッドは行列形式に配置されたその範囲の順列になります。 制約は個々のセルに関するものではなく、行と列にわたる構造に関するものです。つまり、任意の行を取得してすべての最大公約数を計算すると、$n$その中の数字は、gcd が正確である必要があります$1$、すべての列にも同じことが当てはまります。 

したがって、このタスクは、セルのペア間の局所的な共主性に関するものではなく、すべてのエントリにわたって共有される共通の素因数を行または列に持たないようにすることです。 同様に、すべての行とすべての列には、潜在的な共有約数構造を壊す数値が少なくとも 1 つ含まれている必要があります。 

入力は複数のテスト ケースで構成され、それぞれにサイズが与えられます。$n$、そしてそれぞれについて、そのような置換行列を構築するか、それが不可能であることを報告する必要があります。 

制約は十分に強いので、$n$と同じ大きさにすることができます$500$、との合計$n^2$到達できるすべてのテストケースにわたって$10^6$。 これにより、構築中に単純に繰り返される方法で行または列ごとの gcd プロパティをチェックするアプローチが除外されます。 ソリューションは本質的にマトリックスを構築する必要があります$O(n^2)$一定のオーバーヘッドが非常に小さい合計時間。$O(n^2 \log n)$境界線にありますが、それでも許容できる可能性があります。一方、ビルド中に行と列に対するネストされた gcd の再計算を伴うものは遅すぎます。 

小さな値では微妙なエッジケースが現れます。 のために$n = 1$、唯一の行列$[1]$簡単に機能します。 のために$n = 2$、任意の配置$1,2,3,4$失敗: 1 つの行または列が両方の数値を偶数にするか、gcd を強制的により大きくする因子構造を共有することになります。$1$。 たとえば、試してみると$$\begin{matrix}
1 & 2 \\
3 & 4
\end{matrix}$$2番目の列にはgcdが含まれています$\gcd(2,4) = 2 \neq 1$。 並べ替えを行うと、すべてのエントリが偶数になるか、公約数を共有する列または行が強制されます。$2$4 つの数字しかないため、次の倍数の整列を避けることができます。$2$行と列の両方を同時に実行することは不可能です。 

のために$n \ge 3$、構造は明示的に構造を設計できるほど柔軟になります。 

## アプローチ

 ブルートフォースアプローチでは、バックトラックまたは貪欲な配置によってグリッドを埋めようとします。各セルで、その行または列の gcd 制約に直ちに違反しない残りの数値を選択します。 これは条件を明示的に強制するため、原理的には正しいですが、組み合わせ的には失敗します。 それぞれの配置は将来の選択に依存し、有効性をチェックするには、部分的に埋められた行と列の gcd を繰り返し再計算する必要があります。 それぞれのチェックがあったとしても、$O(n)$、全体の複雑さは次のようになります。$O(n^3)$テストケースごとに、これは遅すぎます$n = 500$。 

重要な観察は、gcd について動的に推論する必要がまったくないということです。 「行 gcd が 1」という条件は、各行に所定の素数で割り切れない数値が少なくとも 1 つ含まれるとすぐに満たされます。列についても同様です。 これは、単一の残基クラス パターンによって支配される行や列が存在しないように、小さな構造「アンカー」をグリッド全体に分散する必要があることを示唆しています。 

これを達成する簡単な方法は、連続する行が基本シーケンスの回転になるように巡回シフト方式で行列を埋めることです。 これにより、各列に剰余のモジュロが完全に含まれることが保証されます。$n$そしてさらに重要なことは、すべての列が構造化された方法で残基の完全な順列を受け取るため、列全体が素数の倍数で構成されないことを保証することです。 

うまくいく構造の 1 つは、数字を扱うことです$1$に$n^2$として$n \times n$ブロックして行を埋める$i$、 カラム$j$すべての行が基本ブロックの順列となり、すべての列が各剰余クラスと正確に 1 回交差するようにインデックスをシフトする式を使用します。 標準的な選択は、数値を行ごとに書き込みますが、各行を異なるオフセットで回転させます。 これにより、行または列内に要素が集中するような配置が回避されます。 

ブルート フォースはローカルで推論するため失敗しますが、構築はグローバルな均一性を強制するため機能します。すべての行と列で剰余の完全なサイクルが認識され、共有約数が行全体にわたって持続することが防止されます。

 ## アルゴリズムのチュートリアル

 まず不可能なケースを分離します$n = 2$なぜなら、4 つの異なる数値をどのように配置しても、1 つの行または列にわたる共有因子の導入を回避できないからです。 

全員にとって$n \ge 3$では、シフトされたシーケンスを使用して行列を決定論的に構築します。 

1. 数字を準備します$1$を通して$n^2$位置によって暗黙的に決定されるため、明示的に格納したりシャッフルしたりする必要はありません。 
2.その行を決定します$i$シフトされたベースインデックスから始まる数値、特に概念上の巡回オフセットが含まれます。$n \times n$レイアウト。 これにより、各行が完全なセットの順列であることが保証されます。 
3. 各セルについて$(i, j)$、次の形式の式を使用して値を割り当てます。$(i \cdot n + j + i) \bmod n^2 + 1$。 によるシフト$i$各行が前の行を基準にして回転され、垂直方向の配置パターンが破壊されます。 
4. 結果のグリッドを行ごとに出力します。 

シフトが重要な理由は、シフトがないと列が単に連続する数値を収集するだけになり、構造化された場合に素数が列全体を分割できるようになるためです。 オフセットにより、各列がすべての剰余クラスのモジュロにわたって均等に分散された数値を受け取ることが保証されます。$n$これにより、列が素数で均一に割り切れなくなります。 

これが機能する理由は、算術キャンセルではなく分散に基づいています。 任意の固定素数$p$モジュール構造によって引き起こされるすべての完全な剰余サイクルには、すべての行およびすべての列内に少なくとも 1 つの値が存在するため、行または列内のすべての数値を除算することはできません。 これにより、どの行または列も次の公約数を超えることができないことが保証されます。$1$というのは、その行のすべての要素が同じ素数で割り切れる必要があるため、この構造ではそれが妨げられます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        if n == 2:
            print(-1)
            continue
        if n == 1:
            print(1)
            continue

        # construct n x n matrix
        # cyclic shift construction
        for i in range(n):
            row = []
            base = i * n
            for j in range(n):
                val = (base + j + i) % (n * n) + 1
                row.append(val)
            print(*row)

if __name__ == "__main__":
    solve()
```コードはまず不可能なケースを処理し、次に行依存のシフトを使用して行列を構築します。 表現`(base + j + i)`重要な構造上の選択は次のとおりです。`base`一定のサイズのブロックを移動する$n$、 その間`i`行を区別する回転を追加します。 モジュロ$n^2$値を必要な範囲にラップして戻します。 

よくある間違いは、余分なシフトを省略することです。`i`これにより、同一の行パターンがブロック単位でのみシフトされ、列が規則的に整列しすぎて gcd 構造を共有する可能性があります。 

## 実用的な例

 検討してください$n = 3$。 この構築により以下が生成されます。

 したがって、行列は次のようになります。$$\begin{matrix}

\end{matrix}$$これは、各行が次の順列であることを示しています。$1..9$、各列には、構造化された等差数列ではなく、値の広がりも含まれています。 

のために$n = 4$、最初の 2 行は同じパターンを示しています。

これらのトレースは、すべての行にわたって一貫したモジュール構造を保持している列がないことを示しています。これが、共有 gcd を妨げる重要なメカニズムです。

 ## 特殊なケース
