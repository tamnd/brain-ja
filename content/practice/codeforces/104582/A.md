 ## 解決策
 ## 問題の理解

 私たちはパンケーキの列を与えられ、それぞれが幸せな面を上にするか空白の面を上にするかのいずれかになります。 また、常に正確に K 個の連続するパンケーキを裏返すフリッパーもあります。 反転すると、そのセグメント内の各パンケーキの状態が反転します。 

課題は、すべてのパンケーキを幸せな面にするために必要な裏返しの最小回数を決定するか、それが不可能であると判断することです。 

重要な制約は、すべてのフリップが固定長のウィンドウに影響を与えるため、決定は局所的ですが、長期的な影響を与えることです。 反転が適用されると、そのセグメント内のすべての K 個のパンケーキの状態が永続的に変更され、その後の操作では、さらなる反転を行わない限り、その効果を元に戻すことはできません。 

入力サイズはテスト ケースごとに最大 1000 パンケーキになるため、すべてのフリップ シーケンスを試行するソリューションは実行不可能です。 各位置で反転するかどうかを選択できるため、反転位置に対する総当り検索は指数関数的に増加します。$2^N$可能性。 

必要なフリップが文字列の終端を越える場合、微妙なエッジケースが発生します。 たとえば、最後のいくつかのパンケーキが空白で、残りの位置が K 未満である場合、有効なフリップがそれらをカバーできないため、それらを修正する方法はありません。 ここで、境界を明示的にチェックしないと、多くの単純な貪欲な試みが失敗します。 

## アプローチ

 ブルートフォース戦略では、有効なフリップ位置のすべてのサブセットを試し、各シーケンスの効果をシミュレートします。 各シミュレーションのコストは O(N) で、可能な反転位置は O(N) であるため、合計の検索空間は指数関数的になります。 これは20歳前後のNでもすぐに実行不可能になります。 

問題の構造は、より直接的な戦略を示唆しています。 左から右にスキャンする場合、位置 i で反転するかどうかを決定したら、残りのプロセスでのパンケーキ i の状態を完全に決定します。 i に影響を与えるその後の反転は、i 以降で開始する必要がありますが、左から右に処理し、前の位置に戻ることはないため、これは不可能です。 

これにより、強力な貪欲な構造が作成されます。各ポジションで、現在間違っている場合はすぐに修正する必要があります。 唯一の追加の複雑さは、以前のフリップが現在のインデックスに影響を与えているかどうかを効率的に追跡することです。 これは、現在位置に影響を与えるフリップの実行パリティを維持することで処理できます。 

この観点を採用すると、ソリューションはシングル パス シミュレーションに縮小されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^N・N) | O(N) | 遅すぎる |
 | 貪欲なシミュレーション | O(N) | O(N) または O(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 各位置が現在偶数回反転されているか奇数回反転されているかを追跡しながら、文字列を左から右に処理します。 

1. 現在のパンケーキが奇数回ひっくり返されたかどうかを示すスライディング インジケーターを維持します。 これにより、文字列を物理的に繰り返し変更することなく、その有効な状態を計算できます。 
2. 各インデックス i について、左から右に、前の反転を考慮した後でパンケーキの実際に表示される状態を計算します。 すでに幸せであれば、何もせずに続けます。 
3. 現在のパンケーキが空白の場合、i から開始して反転する必要があります。これは、以降の操作は、すでに固定されている以前の位置に影響を与えずに位置 i に影響を与えることができないためです。 
4. 位置 i で反転を適用する前に、i + K が文字列の長さを超えているかどうかを確認します。 そうなった場合、構成は不可能であると即座に判断します。 
5. フリップを適用すると、差分配列を使用するか、i および i + K で実行中のフリップ状態を切り替えることによって、その効果を記録します。これにより、後で O(1) の将来の位置に対する効果を確認できるようになります。 
6. このプロセスを文字列の終わりまで続けて、実行されたフリップの数を累積します。 

### なぜ効果があるのか

 すべてのステップ i で、厳密に i より小さいインデックスに影響を与えるすべての決定はすでに修正されており、再び変更されることはありません。 i の後に始まる反転は位置 i に影響を与えることはできません。 したがって、現在の累積フリップ パリティの下で位置 i が正しくない場合、唯一可能な修正は i でフリップを開始することです。 これにより、各位置での選択がオプションではなく強制されるため、可能であれば、貪欲な構築によって最小限の操作で有効なシーケンスが生成されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(S, K):
    n = len(S)
    diff = [0] * (n + 1)
    flip = 0
    res = 0

    for i in range(n):
        flip ^= diff[i]
        cur = S[i]

        if flip:
            cur = '+' if cur == '-' else '-'

        if cur == '-':
            if i + K > n:
                return "IMPOSSIBLE"
            res += 1
            flip ^= 1
            diff[i + K] ^= 1

    return str(res)

def solve():
    T = int(input())
    for tc in range(1, T + 1):
        parts = input().split()
        S = parts[0]
        K = int(parts[1])
        ans = solve_case(S, K)
        print(f"Case #{tc}: {ans}")

if __name__ == "__main__":
    solve()
```このソリューションは、スライディング ウィンドウ上のアクティブな反転を表す差分配列を維持します。 フリップを開始するたびに、開始時にエフェクトを切り替え、K 個の位置の後にキャンセルするため、将来のインデックスは自動的に正しいパリティを継承します。 

重要な実装の詳細は、現在のフリップ パリティを適用した後、新しいフリップが必要かどうかを決定する前に有効な文字を計算することです。 これにより、文字列の物理的な変更が回避されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    return solve(inp)

def solve(inp=None):
    data = sys.stdin.read().strip().split()
    T = int(data[0])
    idx = 1
    out = []
    for tc in range(1, T + 1):
        S = data[idx]
        K = int(data[idx + 1])
        idx += 2

        n = len(S)
        diff = [0] * (n + 1)
        flip = 0
        res = 0

        for i in range(n):
            flip ^= diff[i]
            cur = S[i]
            if flip:
                cur = '+' if cur == '-' else '-'

            if cur == '-':
                if i + K > n:
                    out.append(f"Case #{tc}: IMPOSSIBLE")
                    break
                res += 1
                flip ^= 1
                diff[i + K] ^= 1
        else:
            out.append(f"Case #{tc}: {res}")

    return "\n".join(out)

 ## 特殊なケース

 K が文字列の長さに等しい場合、可能な操作は配列全体を反転することだけです。 アルゴリズムは、少なくとも 1 つの「-」がある場合は 1 つの反転を正しく実行するか、構造が解決できない場合は不可能を返します。 

最後の「-」が n - K より大きいインデックスに出現する場合、反転はそれをカバーできません。 アルゴリズムは、そのインデックスに到達した瞬間にこれを即座に検出し、後で無効な操作を試行しないようにします。 

文字列がすでにすべて「+」である場合、すべての位置がパリティ 0 ですでに満たされているため、スキャンは反転を実行しません。これは、貪欲なルールによって不要な操作が導入されないことを示しています。
