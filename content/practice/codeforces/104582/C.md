 ## 解決策
 ## 問題の理解

 両端が常に占有されている屋台の長い列が与えられ、その間に N 個の空の屋台があります。 人々は一人ずつ入場し、両側の最も近い占有の屋台からの距離に基づいて屋台を選択します。 K 人が屋台に着いた後、左右の最も近い占有屋台の空きスペースに関して、K 人目の人が選んだ位置から何が「見える」かを判断するように求められます。 

重要な観察は、プロセスが恣意的ではないということです。 各ステップで、占有されたストールは空のセグメントを独立した間隔に分割します。 各間隔は、同じ問題の小さなインスタンスのように動作します。長さ L のブロック内で、次の人は、非常に具体的な決定論的な方法でブロックを分割する位置を選択します。 

制約は、非シミュレーション的なアプローチを強制するものです。 N は 10^18 に達する可能性があるため、各個人を明示的にシミュレートすることは不可能です。 K 自体も 10^18 に達する可能性があるため、K が大きい場合は、完全な間隔構造を維持して K 回更新しても失敗します。 唯一の実行可能なアプローチは、間隔がバルクでどのように変化するかを推論することです。 

複数の間隔の最適なサイズが同じである場合、微妙なエッジ ケースが発生します。 たとえば、区間が対称的に分割される場合、結果として得られる両方のサブ区間は同一の構造を持ち、同点分割ルールが重要になります。 間隔の長さだけを保存し、多重度や順序を無視する単純なシミュレーションは、どのセグメントが最初に処理されるかを再構築するときに失敗します。 

もう 1 つのエッジ ケースは、N が小さく、K が N に対して大きい場合であり、多くの間隔がサイズ 0 または 1 になります。 その時点で、最小距離と最大距離が崩壊し、基本ケースを不注意に扱うと、誤った負の値または 1 ずつずれた値が発生します。 

## アプローチ

 ブルートフォース手法では、各人物を順番にシミュレートします。 空のセグメントのデータ構造を維持します。最初はサイズ N の単一セグメントです。毎回、ルールに従って最良の選択をもたらすセグメントを選択します。つまり、エッジまでの最小距離を最大化し、次に最大距離を最大化し、次に左端を選択します。 セグメントを選択すると、2 つの小さなセグメントに分割されます。 

これが機能するのは、各選択が現在のセグメントのみに依存し、分割がローカルであるためです。 ただし、操作の数は K であり、各操作では、潜在的に O(K) 個のセグメントの中から最適なセグメントを選択する必要があります。 これにより、最悪の場合は O(K^2) の動作が発生しますが、K が 10^18 に達するとこれは不可能になります。 

重要な洞察は、実際には注文を段階的にシミュレートする必要がないということです。 代わりに、長さ L の各セグメントが常に同じように動作することが観察されます。つまり、サイズが L のみに依存する 2 つの子セグメントが生成されます。同じサイズのすべてのセグメントは交換可能です。 これにより、このプロセスは、個々の人々に対する明示的なシミュレーションではなく、セグメント サイズに関するカウントの問題に変わります。 

利用可能な最大のセグメント サイズを繰り返し処理し、その発生回数を数え、その分割を更新された多重度で 2 つの新しいサイズに伝播します。 これは、セグメント サイズに対する貪欲な BFS と同等ですが、マップまたは優先順位構造を使用して一括で実行されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(K^2) | O(K) | 遅すぎる |
 | 最適 | O(log N) から O(K log N) | O(K) | 承認済み |

 ## アルゴリズムのチュートリアル

 各自由区間をその長さによってモデル化します。 長さ L のセグメントの場合、人がその中のストールを選択すると、セグメントは 2 つの部分に分割されます。 選択されるポジションは常に中央ですが、L が偶数の場合、中央の候補が 2 人存在し、タイブレークでは左側が有利になります。 

これにより、分割サイズが決定的になります。 

長さ L のセグメントの場合、次のように定義します。 

左部分 = (L - 1) // 2

 右側 = L // 2

私たちは、キーがセグメントの長さ、値が現在存在するそのようなセグメントの数である頻度マップを維持します。 

また、より大きなセグメントは優先度の高い選択肢に対応するため、利用可能な最大のセグメントを常に抽出する構造も維持します。 

## ステップ

 1. サイズ N の単一セグメントを使用して max 構造体を初期化します。 

これは、誰も入る前の空のバスルーム全体を表しています。 
2. K が 0 より大きい間、現在利用可能な最大のセグメント サイズ L を繰り返し取得します。 

これは、貪欲ルールが常に最大の有効な空き間隔を最初に選択するため、有効です。 
3. サイズ L のセグメントに一度に何人を割り当てることができるかを決定します。これは、そのようなセグメントの数 cnt です。 

K が cnt より大きい場合は、すべてをまとめて処理します。 それ以外の場合は、そのうちの K 個だけを処理します。 
4. このセグメント サイズから実際に着席する人数 (use = min(K, cnt)) を計算し、使用量によって K を減らします。 

これにより、1 つずつシミュレーションするのではなく、一括で処理できるようになります。 
5. サイズ L の処理済みセグメントごとに、サイズ (L - 1) // 2 および L // 2 の 2 つの新しいセグメントに分割されます。 

結果として得られる各セグメントの使用コピーを構造に追加して戻します。 
6. K がゼロに達した場合、最後に処理されたセグメント サイズ L によって答えが決まります。 L から次を計算します。 

max(LS, RS) = L // 2

 min(LS, RS) = (L - 1) // 2

 ## なぜ機能するのか

 どの時点でも、すべての空きセグメントは独立して動作し、セグメント内の選択はその長さのみに依存します。 貪欲な選択ルールは常に大きなセグメントを優先するため、セグメントの処理順序は履歴ではなくサイズによって厳密に決定されます。 同じサイズのすべてのセグメントは交換可能であるため、セグメントをカウントにグループ化しても順序情報が失われることはありません。 L からその 2 つの子への変換は決定論的であるため、システムは曖昧さのないセグメント サイズのマルチセットとして進化します。 

## Python ソリューション```python
import sys
import heapq
from collections import defaultdict

input = sys.stdin.readline

def solve():
    T = int(input())
    for tc in range(1, T + 1):
        N, K = map(int, input().split())

        # max heap via negative values
        heap = [-N]
        cnt = defaultdict(int)
        cnt[N] = 1

        while heap:
            L = -heapq.heappop(heap)
            if cnt[L] == 0:
                continue

            c = cnt[L]
            cnt[L] = 0

            if K <= c:
                # answer comes from this segment size
                left = (L - 1) // 2
                right = L // 2
                print(f"Case #{tc}: {right} {left}")
                break

            K -= c

            left = (L - 1) // 2
            right = L // 2

            for nxt in (left, right):
                if nxt > 0:
                    if cnt[nxt] == 0:
                        heapq.heappush(heap, -nxt)
                    cnt[nxt] += c

solve()
```ヒープにより、問題の貪欲な構造に合わせて、常に最大のセグメント サイズが最初に処理されることが保証されます。 辞書は多重度を追跡するので、同一のセグメントを個別に扱うのではなく折りたたむことができます。 

終了条件は、K がセグメントの現在のバッチ内に該当するときに正確に発生します。これは、K 人目の人がサイズ L のセグメントに割り当てられることを意味します。そのセグメントからの距離は、純粋にその分割構造によって決定されます。 

よくある実装上の落とし穴は、同じサイズの複数のセグメントを一緒に処理する必要があることを忘れていることです。 それらを 1 つずつ処理しても論理的には機能しますが、時間がかかりすぎます。 もう 1 つの微妙な問題は、左右の部分の計算です。左右の部分を交換したり、両方に L // 2 を使用したりすると、正しいタイブレークに必要な非対称性が破壊されます。 

## 実用的な例

 ### 例 1

 入力: N = 5、K = 2

 サイズ 5 の 1 つのセグメントから始めます。 

| ステップ | 選択されたセグメント | カウント | 残り K | 新しいセグメント |
 | --- | --- | --- | --- | --- |
 | 1 | 5 | 1 | 1 | 2、2 |
 | 2 | 2 | 2 | 停止 | - |

 ステップ 2 で、K はサイズ 2 のセグメントに収まるので、次のようになります。 

方向ルールに応じて left = 0、right = 1 となり、最終結果は 1 0 になります。 

これは、大きなセグメントが消費されると、小さなセグメントがどのように優勢になるかを示しています。 

### 例 2

 入力: N = 6、K = 2

 セグメント 6 から始めます。 

| ステップ | 選択されたセグメント | カウント | 残り K | 新しいセグメント |
 | --- | --- | --- | --- | --- |
 | 1 | 6 | 1 | 1 | 2、3 |
 | 2 | 3 | 1 | 停止 | - |

 2 人目はサイズ 3 のセグメントになり、左 = 1、右 = 1 になります。 

これにより、分割伝播であっても、履歴ではなくセグメント サイズのみに依存することが確認されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(log N) 償却 | 各セグメント サイズは 1 回処理され、より小さいサイズに分割されます。 
| スペース | O(log N) | 個別のセグメント サイズのみが保存されます。 

各分割により間隔がほぼ半分になるため、個別のセグメント サイズの数はゆっくりと増加します。 これにより、N が 10^18 までの場合でも構造が小さいままとなり、解が制限内に十分に保たれます。

 ## 特殊なケース

 N = 1 の場合、唯一のセグメントは最初の分割後、サイズ 0 と 0 の 2 つの空の部分を即座に生成します。 計算された子は両方ともゼロであり、ヒープ内では無視されるため、アルゴリズムはこれを処理します。 答えは最初のセグメントから直接決定され、正確なゼロ距離が生成されます。 

N が偶数の場合、たとえば N = 6 の場合、分割は (5 // 2 = 2, 3) になります。 アルゴリズムは常に右側を L // 2 として割り当て、左側を (L - 1) // 2 として割り当て、決定的なタイブレーク ルールを維持します。 これにより、同等の中間位置の間で左に偏った選択が確実に尊重されます。 

K が指定されたサイズのセグメントの数と正確に等しい場合、アルゴリズムはセグメントを過剰に消費することなくそのレベルで正確に停止し、最終的なセグメントの選択がより小さい間隔にシフトすることになるオフバイワンエラーを回避します。
