 ## 解決策
 ## 問題の理解

 いくつかの独立したクエリが与えられます。 各クエリは正の整数を提供します$N$。 1 から 1 まで数え上げることを想像してください。$N$、各数値について、左から右に読んだときにその 10 進数が減らないかどうかを確認します。 スキャン中に桁が下がらないため、123、7、224488 などの数字を使用できます。 321 や 495​​ などの数値は、どこかの桁が前の桁よりも小さいため、受け入れられません。 

それぞれについて$N$、範囲内の最大の数値が必要です$[1, N]$これは、この単調な数字の特性を満たします。 

入力サイズでは最大 100 個のクエリが可能で、それぞれ$N$と同じ大きさにすることができます$10^{18}$。 これにより、1 から 2 までのすべての数値をチェックするアプローチは即座に除外されます。$N$、単一のテスト ケースには最大で$10^{18}$これは、数値ごとの検証が非常に高速であっても、実現可能な限界をはるかに超えています。 

微妙な特殊なケースは、「ほぼ整然とした」数字であっても、桁の後半で失敗する場合に発生します。 たとえば、次の場合$N = 332$、からの単純な減少$N$331 や 330 などの候補が生成される可能性がありますが、不注意な数字の処理により、修正の実装方法によっては 329 や 299 などの有効な回答がスキップされる可能性があります。 別の失敗例は、次のような数字の繰り返しの周囲で発生します。$N = 11110$、最良の答えは 1119 です。単純な貪欲な修正により、誤って無効な末尾構造が保持される可能性があります。 

重要な問題は、制約が位置演算ではなく、グローバルな桁の単調性制約であることです。 

## アプローチ

 ブルートフォースソリューションは以下から始まります$N$そして下に進み、各整数をチェックしてその桁が減少していないかどうかを確認します。 一つの数字を確認するのは、$O(d)$どこ$d \le 18$, so in the worst case we might inspect all numbers down to the correct answer. みたいな最悪のシナリオでは$N = 10^{18}$、最初の適切な数値は、それに比べて非常に小さい可能性があります。$N$つまり、数直線の膨大な接尾辞をスキャンできることになります。 これはまったく実現不可能です。 

構造上の観察によると、整然とした数字は厳密な数字形式をとります。ある位置で数字が減少すると、最大条件を破ることなく右側のすべてを 9 に置き換えることができます。これは、9 が最大の数字であり、それより小さいか等しい数字の後に配置されている限り、非減少順序が維持されるためです。 これは、スペースを検索する必要がないことを示唆しています。 代わりに、数値を左から右または右から左にローカルに修正できます。 

より正確な視点は、左から右にスキャンするときに桁の順序が崩れる最初の位置という観点から考えることです。 その時点で、プレフィックスを下方に調整する必要があり、プレフィックス以降のすべてが制約の下で最大化されます。 この修復を繰り返すと、整然とした状態が保証され、次を超えない最大の最終番号が生成されます。$N$。 

これにより、問題は整数の検索から、時折後方修正を伴う数字の単一の線形パスに変換されます。

 ## アルゴリズムのチュートリアル

 数値を変更可能な数字のリストとして扱います。 

1.変換$N$数字の配列に変換します。 これにより、算術再構成ではなく、位置の直接操作が可能になります。 
2. 左から右にスキャンして、桁が厳密に減少する最初のインデックスを見つけます。$digits[i] < digits[i-1]$。 これは整頓に対する最初の違反であり、それ以前のすべては依然として有効です。 
3. ポジションに違反があった場合$i$、位置の数字をデクリメントします$i-1$1 ずつ加算し、その位置を「修正点」としてマークします。 元の数字を保持すると、無効な順序付けを強制するプレフィックスが保持されるため、これが必要です。 
4. 補正ポイントを減少させた後、プレフィックスが減少しないことを確認する必要があります。 数字を減らすと前の数字の条件に違反する可能性があるため、連鎖反応が発生する可能性があります。 そこで、修正点から左に移動し、新たに作成された反転を修正します。 
5. プレフィックスが修正されたら、修正ポイントの右側にあるすべての桁を 9 に設定します。9 が最大の桁であり、有効なプレフィックスの後に新しい減少ペアが導入されないため、これにより、有効性を維持しながら数値が最大化されます。 
6. 修復が完了した後、先頭にゼロが導入された可能性があります (たとえば、1000 のような構造が 0999 になった場合)。 先頭のゼロを削除して、有効な整数表現を復元します。 
7. 結果として得られる数値が、このテスト ケースの答えになります。 

重要なアイデアは、違反を検出するたびに、単調性を回復するのに十分なだけ数値を下げてから、貪欲にすべてを右方向に最大化するということです。 

### なぜ効果があるのか

 すべてのステップで、現在の修正点までのプレフィックスが元の数を超えず、きちんとした数に拡張できる最大のプレフィックスであるという不変条件を維持します。 違反が発生するたびに、現在の桁を変更しないと、後の桁がその桁よりも小さくなるように強制されますが、整然とした数値ではこれは不可能です。 したがって、唯一の有効な修復は、前の桁を減らし、サフィックスを単調制約の下で可能な最大値 (すべて 9) にリセットすることです。 修正は左に移動するだけで桁が増えることはないため、以下を超えない辞書編集上最大の有効な数値に収束します。$N$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_one(n_str: str) -> str:
    digits = list(map(int, n_str.strip()))
    n = len(digits)

    # find first violation
    mark = n
    for i in range(n - 1, 0, -1):
        if digits[i] < digits[i - 1]:
            digits[i - 1] -= 1
            mark = i

    # fix potential cascading violations to the left
    for i in range(mark - 1, 0, -1):
        if digits[i] < digits[i - 1]:
            digits[i - 1] -= 1
            mark = i

    # set suffix to 9
    for i in range(mark, n):
        digits[i] = 9

    # handle leading zeros
    i = 0
    while i < len(digits) and digits[i] == 0:
        i += 1

    return ''.join(map(str, digits[i:])) if i < len(digits) else "0"

def main():
    t = int(input())
    for tc in range(1, t + 1):
        n = input().strip()
        print(f"Case #{tc}: {solve_one(n)}")

if __name__ == "__main__":
    main()
```このソリューションは、直接の数字操作を中心に構築されています。 逆方向スキャンにより、単調性が崩れる場所が検出されます。 ブレークが見つかったら、前の数字をデクリメントすることが最小限の変更であり、サフィックスが最大になるようにしながら、最終的な数値が厳密に入力以下であることが保証されます。 

2 番目の逆方向ループが必要なのは、1 つのデクリメントによって数値の前半で新しい違反が作成される可能性があるためです。 この伝播ステップがないと、332 のようなケースで中間の無効なプレフィックスが誤って生成されてしまいます。 

サフィックスを 9 に置き換えることで最大性が保証されます。プレフィックスが固定されると、その後の数字は 9 を超えることができなくなり、より小さい値を選択すると、より小さい有効な数値が生成されますが、これは最適ではありません。

 ## 特殊なケース

 10 のような入力の場合、アルゴリズムは 2 桁目で単一の違反を検出します。 最初の桁を 0 にデクリメントし、サフィックスを 9 に設定し、先頭のゼロを削除した後に 9 を生成します。 スキャンと補正は、特別なケースを使用せずにこれを直接処理します。 

11110 のような入力の場合、違反は最後の桁で発生します。 このアルゴリズムは、前の 1 を 0 に減らしてから、必要に応じて伝播し、1110 になるプレフィックスを生成し、その後サフィックスを埋めて、最終的に 1119 を生成します。単調チェックにより、伝播後に隠れた違反が残らないことが保証されます。 

1234 のようなすでに整った数値の場合、スキャンでは違反が検出されないため、桁は変更されず、元の数値がすぐに返され、アルゴリズムが有効なプレフィックスを過剰修正しないことが確認されます。
