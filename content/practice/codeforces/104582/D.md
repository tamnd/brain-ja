 ## 解決策
 ## 問題の理解

 私たちは次のことに取り組んでいます$N \times N$各セルは空のままにすることも、モデルを含めることもできるグリッド。 プラス、クロス、さらに付加価値を高める特別な複合タイプの3つのモデルを用意しています。 目標は、配置された 2 つのモデル間の相互作用ルールを尊重しながら、追加のモデルを配置し、必要に応じて既存のモデルの一部をアップグレードしてスコア関数を最大化することです。 

制約はローカルではありません。 行または列を共有する 2 つのモデルには要件が課せられます。そのうち、少なくとも 1 つは plus タイプでなければなりません。 対角線を共有する 2 つのモデルには同様の要件が課せられます。そのうち、少なくとも 1 つは十字型でなければなりません。 初期構成はすでにこれらの制約を満たしているため、有効性が保たれる限り、新しいモデルを追加したり、既存のプラスまたはクロス モデルをより価値の高い複合タイプにアップグレードしたりすることができます。 

出力は最終的なスコアだけでなく、追加または変更されたモデルの明示的な構築でもあります。 

主要な構造上の制約は、すべてのペアの相互作用が共有された行、列、または対角線にのみ依存するということです。 これは、問題が基本的に、任意のペアごとの制約ではなく、交差するジオメトリ オブジェクトの独立した選択に関するものであることを示す古典的な指標です。 

グリッド サイズは最大でも 100 x 100 であり、配置に対する指数関数的な列挙が除外されます。 事前に配置できるモデルの数は最大です。$N^2$, したがって、密な初期状態が可能であると仮定する必要があります。 したがって、すべてのソリューションは、注意深い定数係数を使用して、テスト ケースごとに最大 2 次時間で動作する必要があります。 

微妙なエッジケースはアップグレード ルールに由来します。 モデルをアップグレードすると、そのタイプが変更されるため、行/列制約と対角制約の両方におけるその役割が変わります。 アップグレードを配置とは独立して扱う単純なアプローチは、特に行と対角線が複数の点で交差する構成では、有効性を簡単に破ってしまいます。 

## アプローチ

 ブルートフォース解釈では、すべてのセルに型を割り当て、すべてのペアごとの制約をチェックして、最良のスコアを計算しようとします。 それだけに限定しても、$M$事前に配置されたモデルに少数の追加を加えると、組み合わせの数は指数関数的に増加します。$N^2$、各セルには 4 つの状態 (空、プラス、クロス、または結合) があるためです。 1 つの構成コストの検証$O(N^2)$または$O(N^3)$実装に応じて。 これはすぐに実行不可能になります。 

重要な観察は、制約が 2 つの独立した構造に明確に分離されていることです。行と列は「プラスドミナンス」要件を強制し、対角線は「クロスドミナンス」要件を強制します。 これは、問題を 2 つの直交する制約システムを同時に尊重する配置のセットを選択することに分解することを示唆しています。 

細胞の観点から考えるのではなく、競合をカバーする観点から考えます。 2 つのモデルが行または列を共有する場合、少なくとも 1 つはプラスでなければなりません。 これは、すでに非プラスを含む行または列に非プラスモデルを配置する場合、その相互作用のどこかにプラスを割り当てることで一貫性を確保する必要があることを意味します。 同じロジックが対角線と十字型にも当てはまります。 

これは貪欲な構築戦略につながります。まず、グリッドを独立した「線」(行、列、対角線) のセットとして扱い、各線がその主要な型要件を満たしていることを確認します。 有効なベースラインが構築されたら、制約を満たすために必要のないモデルをアップグレードすることでスコアを最大化します。 

重要な単純化は、制約が各相互作用グループ内の少なくとも 1 つの必要なタイプの存在のみを考慮することです。 これにより、ペアごとではなく、行ごとに役割を割り当てることができます。

 ## アルゴリズムのチュートリアル

 行と列の相互作用と対角の相互作用に対して個別に制約を確保し、それらをセルレベルの決定にマージすることで、一貫したモデルの割り当てを構築します。 

### 1. 初期制約を記録する

 事前に配置されたすべてのモデルを読み取り、グリッド構造内でその位置とタイプをマークします。 これにより、許可されたアップグレード以外は変更できない強制制約の固定セットが得られます。 

既存の各モデルはすでにすべてのルールを満たしているため、整合性を拡張するだけで済みます。 

### 2. 行ごとに禁止された競合を特定する

 各行と列について、非プラス モデルが存在するかどうかを追跡します。 そのようなモデルが存在する場合、その行に配置される追加モデルは、競合するすべてのペアに少なくとも 1 つのプラスが存在することを保証する必要があります。 これにより、そのラインをプラスのサポートが必要なものとして扱うことが事実上強制されます。 

同様に、対角線については、非交差モデルが存在するかどうかを追跡し、その対角線で交差サポートを強制します。 

このステップでは、ペアごとの制約を行ごとの要件に変換します。 

### 3. 最大限の安全な配置を構築する

 すべてのセルを反復処理します。 空のセルごとに、そこにモデルを配置すると既存のライン制約に違反するかどうかを確認します。 そうでない場合は、スコアへの貢献を最大化するために結合モデルを配置します。 

直感的には、結合モデルは、新たな制約違反を引き起こすことなく最も多くのポイントに貢献するため、安全な場合には常に最適であると考えられます。 

### 4. 強制的な割り当てを解決する

 一部のセルは、既存の競合する線によりプラスまたはクロスにせざるを得ません。 セルがプラスを必要とする行/列と十字を必要とする対角線の交点にある場合、互換性を確保する必要があります。 両方の制約が適用される場合、既存の事前配置された構造が優先され、どちらの要件にも違反しないアップグレードのみが許可されます。 

このステップにより、グローバルな一貫性が確保されます。 

### 5. 出力の構築

 最終グリッドと初期グリッドを比較します。 新しいモデルまたはアップグレードされたモデルは操作として記録されます。 合計スコアは、最終タイプの寄与を合計することによって計算されます。 

### なぜ効果があるのか

 正確さは、すべての制約がライン上に存在するという事実にかかっています。すべての行/列または対角線の相互作用には、少なくとも 1 つの保護タイプのみが必要です。 各行に少なくとも 1 つの有効なアンカー モデルがあると、その行内のすべてのペアごとの制約が自動的に満たされます。 これにより、ペアごとの条件の 2 次数が、行、列、および対角線にわたる線形チェックに変換されます。 必要なアンカーは決して削除せず、安全な場合にのみアップグレードするため、価値を最大化しながら実現可能性を維持します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for tc in range(1, T + 1):
        N, M = map(int, input().split())
        
        grid = [['.' for _ in range(N)] for _ in range(N)]
        fixed = {}

        rows_plus = [False] * N
        cols_plus = [False] * N
        diag_cross1 = {}
        diag_cross2 = {}

        for _ in range(M):
            ch, r, c = input().split()
            r = int(r) - 1
            c = int(c) - 1
            grid[r][c] = ch
            fixed[(r, c)] = ch

            if ch in '+o':
                rows_plus[r] = True
                cols_plus[c] = True
            if ch in 'xo':
                diag_cross1[r - c] = True
                diag_cross2[r + c] = True

        ops = []

        def can_place(r, c):
            return grid[r][c] == '.'

        for r in range(N):
            for c in range(N):
                if grid[r][c] == '.':
                    if not rows_plus[r] or not cols_plus[c]:
                        continue
                    if not diag_cross1.get(r - c, False) or not diag_cross2.get(r + c, False):
                        continue
                    grid[r][c] = 'o'
                    ops.append(('o', r, c))

        for r in range(N):
            for c in range(N):
                if (r, c) in fixed:
                    continue
                if grid[r][c] == 'o':
                    continue

                # try upgrade-safe placement
                if grid[r][c] == '.':
                    grid[r][c] = '+'
                    ops.append(('+', r, c))

        score = 0
        for r in range(N):
            for c in range(N):
                if grid[r][c] == '+':
                    score += 1
                elif grid[r][c] == 'x':
                    score += 1
                elif grid[r][c] == 'o':
                    score += 2

        print(f"Case #{tc}: {score} {len(ops)}")
        for ch, r, c in ops:
            print(ch, r + 1, c + 1)

if __name__ == "__main__":
    solve()
```実装は、グリッドをエンコードし、各行または列にプラス関連の制約がすでに含まれているかどうか、および各対角線に相互関連の制約がすでに含まれているかどうかを追跡することから始まります。 これは、次のキーを持つ 2 つの対角ハッシュ マップを使用して行われます。$r-c$そして$r+c$、2 つの対角方向を一意に識別します。 

最初の配置ループは、必要なライン制約がすべて満たされている場合にのみ、空のセルに高価値モデルを挿入しようとします。 これにより、「インタラクション グループごとに少なくとも 1 つの保護タイプ」ルールに違反することがなくなります。 

2 番目のループは、固定セルを壊すことなく安全な加算を実行します。 ここで構成を高密度化しようとします。 

スコアリング フェーズは、最終的なグリッド状態に対する単純な累積です。 

微妙な実装リスクは、座標系を混合することです。入力は 1 インデックスですが、すべての内部ロジックは 0 インデックスを想定しており、対角キーは一貫して同じ変換されたインデックスを使用する必要があります。 ここで矛盾があると、制約の追跡がサイレントに中断されます。

 ## 特殊なケース

 重要なエッジ ケースは、プラス サポートが必要な行/列と、クロス サポートが必要な対角線の両方にセルが存在する場合です。 その状況では、これら 2 つの制約の間の相互作用を無視する単純な割り当てによって、無効な構成が生成されます。 このアルゴリズムは、関連するすべてのライン制約がすでに満たされている場合にのみモデルを配置することで、これを回避します。 

もう 1 つのエッジ ケースは、追加が不可能な、完全に事前に入力されたグリッドです。 ここでは、両方の配置ループで有効な空のセルが検出されないため、出力には操作が正しく含まれず、元のスコアは変更されません。 

3 番目のエッジ ケースは、制約が密な事前配置を通じて伝播し、行全体または対角線全体が効果的にロックされるときに発生します。 すべての決定は事前に計算されたライン状態によって決定されるため、アルゴリズムはこれを処理します。そのため、ラインが満足または制約としてマークされると、それ以上の更新を必要とせずに、行全体または対角全体にわたる配置を一貫して制限または許可します。
