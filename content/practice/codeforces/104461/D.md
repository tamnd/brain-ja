 ## 問題の理解

 2 人のユーザーがタイムライン上で通信します。$n$日々。 ユーザーがいつ$A$にメッセージを送信します$B$、同様に、$B$にメッセージを送信します$A$。 各間隔は、その範囲内で毎日通信が発生することを意味するため、全体として各ユーザーのアクティビティは数直線上のセグメントの和集合として見ることができます。 

当日はフレンドシップポイントが付与されます$i$最後であれば、そしてその場合に限り$m$で終わる日$i$双方向からのコミュニケーションで完全にカバーされます。 つまり窓の中では$[i-m+1, i]$、ユーザー$A$そのウィンドウで毎日メッセージを送信している必要があり、ユーザー$B$も同じことをしたに違いない。 この条件が成立する日は、最終解答にちょうど 1 単位が寄与します。 

タスクは、全範囲にわたってそのような日が何日存在するかを計算することです。$[1, n]$、たとえいつでも$n$と同じくらい大きいです$10^9$。 通信を記述する間隔は少なく、各方向で最大 100 個であり、すでにソートされており、重複していません。 

重要な難しさはその規模です$n$。 繰り返しが発生するため、毎日のシミュレーションは不可能です$10^9$ポジションがすぐに時間制限を超える可能性があります。 代わりに、セグメントと遷移の観点から推論する必要があります。 

微妙なエッジケースが現れるのは、$m = 1$。 その後、両方のユーザーがメッセージを送信した日は、その期間がその日そのものであるため、すぐにカウントされます。 別のエッジ ケースは、ユーザーのカバレッジがほぼ完了しているものの、長い間隔内に 1 日の欠落がある場合に発生します。これにより、そのギャップをまたぐ有効なウィンドウが完全に破棄されます。 間隔をマージし、正確な 1 日あたりの補償範囲を無視する単純なアプローチでは、部分的な補償範囲を完全な補償範囲として誤って扱うことになります。 

## アプローチ

 ブルートフォースアプローチでは、毎日を 1 から 1 まで明示的にマークします。$n$両方のユーザーに対して、一定の長さのウィンドウをスライドさせます$m$。 毎日、ウィンドウ内のすべての日が両方のユーザーに対してアクティブであるかどうかを確認します。 プレフィックスの合計を使用しても、次の場合には完全な配列を構築することは不可能です。$n = 10^9$なぜなら、一日中保存したり繰り返したりすることは不可能だからです。 

重要な点は、個々の日を検査する必要がないということです。 各ユーザーのアクティビティは最大 100 個の間隔の和集合であるため、まず各ユーザーのスケジュールを経時的に 2 項関数に変換し、次にそれが継続的にアクティブになっている場所を計算できます。 私たちが望む条件は、両方のユーザーが長期間にわたって毎日アクティブであることです。$m$ウィンドウ。 これは、アクティブ セットの共通部分にも長さの完全な間隔が含まれている必要があると言っているのと同じです。$m$日に終わる$i$。 

したがって、問題は 2 つの区間和集合の交差を計算し、長さがいくつあるかを数えるということになります。$m$サフィックス ウィンドウはその交差の内側に完全に収まります。 タイムラインを拡張する代わりに、交差セグメントを直接計算します。 セグメントを取得したら$[L, R]$、で終わるすべての有効なウィンドウ$i$インデックスに対応します。$[i-m+1, i] \subseteq [L, R]$、これを単純化すると、$i \in [L+m-1, R]$。 各交差セグメントは単純な算術カウントに寄与します。 

したがって、完全なタスクは次のようになります。ソートされた 2 つの非結合間隔リストの交差間隔を計算し、結果として得られる各セグメントからの寄与を合計します。

 ## アルゴリズムのチュートリアル

 私たちは両方のユーザーのメッセージ履歴を、互いに素な間隔のソートされたリストとして扱います。 次に、2 ポインター スイープを使用してそれらのオーバーラップを計算します。 

1. 2 つのポインターを初期化します。1 つは$A$の間隔と 1 つの間隔$B$の間隔。 アイデアは、各ユーザーの現在のアクティブ セグメントを常に比較し、それらの重複部分を抽出することです。 
2. 各ステップで、現在の間隔の交差を計算します。 もし$A = [l_a, r_a]$そして$B = [l_b, r_b]$、それらの重なりは$[ \max(l_a, l_b), \min(r_a, r_b) ]$ただし、左の端点が右の端点を超えない場合に限ります。 これにより、両方のユーザーが同時にアクティブになるセグメントが作成されます。 
3. 重複セグメントが存在する場合、そのすべての日数はすぐにはカウントされません。 代わりに、それを有効なウィンドウ終了位置に変換します。 日で終わるウィンドウ$i$～を完全にカバーする必要がある$[i-m+1, i]$、したがって、有効です$i$オーバーラップ内の値$[L, R]$満足する$i \ge L + m - 1$そして$i \le R$。 もし$R \ge L + m - 1$、追加します$R - (L + m - 1) + 1$答えに。 
4. 最初に終了する間隔のポインタを進めます。 これにより、重複の可能性を見逃さずにすべてのセグメントを移動できるようになります。 これ以上拡張できない間隔は、将来の交差に寄与できないため、常に破棄されます。 
5. リストが 1 つなくなるまで繰り返します。 

正確さは、関連するすべての構造が間隔の境界によって捕捉されるという事実に依存します。 有効なウィンドウは、少なくとも 1 人のユーザーが非アクティブであるギャップ内で開始または終了することはできないため、すべてのコントリビューションが交差セグメント内に完全に含まれている必要があります。 

### なぜ効果があるのか

 アルゴリズムは、どの時点でも、前の間隔に関係するすべての重複がすでに処理されていることを維持します。 各交差セグメントは両方のユーザーのアクティビティに関して最大​​であり、少なくとも 1 人のユーザーの連続性を侵害することなく、有効なウィンドウが部分的にその外側に広がることはできないことを意味します。 有効なウィンドウは交差部分に完全に含まれる連続範囲に正確に対応するため、セグメントごとにウィンドウをカウントすることは必要かつ十分です。 2 ポインター進行により、重複するセグメントのすべてのペアが 1 回だけ考慮されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n, m, x, y = map(int, input().split())
        
        A = [tuple(map(int, input().split())) for _ in range(x)]
        B = [tuple(map(int, input().split())) for _ in range(y)]
        
        i = j = 0
        ans = 0
        
        while i < x and j < y:
            la, ra = A[i]
            lb, rb = B[j]
            
            L = max(la, lb)
            R = min(ra, rb)
            
            if L <= R:
                start = L + m - 1
                if start <= R:
                    ans += R - start + 1
            
            if ra < rb:
                i += 1
            else:
                j += 1
        
        print(ans)

if __name__ == "__main__":
    solve()
```このソリューションは、まず各テスト ケースの両方の間隔リストを読み取ります。 間隔は素でソートされていることが保証されているため、線形の 2 ポインター スイープで十分です。 

ループ内で、現在の間隔の重複を計算します。 重複が存在しない場合は何も追加されません。 重複が存在する場合は、数日間繰り返すのではなく、有効なウィンドウ エンドポイントの数に変換します。 

ポインタの前進ルールは非常に重要です。 最初に終了する間隔は、そのエンドポイントを超えて他のリストの将来の間隔と重なることができないため、常にその間隔を超えて移動します。 

オーバーラップセグメントから有効なウィンドウへの変換には注意が必要です。 表現$L + m - 1$サイズのウィンドウ全体が満たされる最初の日を定義します。$m$オーバーラップ内にとどまったまま終了することができます。 これを超えると$R$、セグメントは何も貢献しません。

これは、各交差セグメントが独立して有効なウィンドウ エンドポイントにどのように寄与するかを示しています。 

次に、オーバーラップが小さすぎる場合を考えてみましょう。 

A = [1,4]、B = [1,4]、m = 5

 | 間隔 | B 間隔 | オーバーラップ | 貢献 |

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、オーバーラップが存在するものの、オーバーラップがそれよりも短い場合です。$m$。 たとえば、両方のユーザーが 10 日目から 12 日目までアクティブであった場合、$m = 5$、交差は有効ですが、何も寄与しません。 アルゴリズムは正しく計算します$L + m - 1 > R$, したがって、セグメントを完全にスキップします。 

もう 1 つの特殊なケースは、間隔が接触しているが重なり合わない場合です。 A が 5 日目に終了し、B が 6 日目に始まる場合、計算された交差は次のようになります。$L > R$, そのため貢献度は加算されません。 これにより、重複のない隣接関係が誤って連続性として扱われることがなくなります。 

最後の微妙なケースは、交互の間隔によって引き起こされる複数の切り離されたオーバーラップです。 2 ポインター スキャンにより、各オーバーラップが 1 回だけ処理されることが保証されます。これは、先に終了する間隔のポインターを進めることで、交差セグメントがスキップされたり二重にカウントされたりしないことが保証されるためです。
