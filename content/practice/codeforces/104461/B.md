 ## 解決策
 ## 問題の理解

 いくつかのテストケースが与えられています。 各テスト ケースは、コンテスト用に用意されたプログラミング問題の難易度スコアを表す整数のリストで構成されます。 

各リストについて、有効なコンテスト セットを定義する一連の構造ルールを満たしているかどうかを判断する必要があります。 ルールは、問題の数、最小難易度値の分布、ソート時に難易度がどの程度スムーズに増加するかを制限します。 

最初の制限は純粋にサイズに関するものです。小さい固定範囲のサイズ、具体的には 10 から 13 の問題までのセットのみが受け入れられます。 この範囲外のセットは、その値に関係なく、直ちに無効になります。 

2 番目の制限は、最も簡単な問題の正体を定義します。 セット内の最小難易度を見ると、この最小値が出現するたびに正確に値 1 でなければなりません。これにより、任意の低い値を許可するのではなく、最も簡単な層が 1 に固定されるようになります。 その結果、最小値が 1 でない場合、構成は失敗します。 

3 番目の制限では、難易度 1 の問題が少なくとも 2 つある必要があります。これにより、最も簡単な問題が 1 つだけ存在するという劣化したケースが防止されます。 

4 番目の制限は、難易度を降順でない順に並べ替えた後に適用されます。 隣接する要素をスキャンする場合、隣接する要素間の絶対差が 2 を超えてはなりません。唯一の例外は、2 つの隣接する問題のうちの 1 つが独自の最も難しい問題、つまり配列内の最大値であり、それが 1 回だけ出現する場合です。 この最大値に関係する隣接関係は、差の制限をバイパスします。 

単純な間違いは、最大値を含むエッジを含めて隣接制約を均一に適用することです。 たとえば、次のようなソートされた配列を考えてみましょう。`[1, 1, 3, 4, 5, 6, 7, 13, 14, 15]`。 7 から 13 への変化は大きいですが、13 が固有の最大値である場合にのみ許可されます。 代わりに 15 が最大値の場合、そのジャンプは無効になります。 例外を無視するソリューションは、有効なケースを誤って拒否します。 

もう 1 つの微妙な失敗は、最小値が 1 であるにもかかわらず 1 回しか出現しない場合に発生します。 すべての隣接関係の差が小さい場合でも、セットは拒否される必要があります。 

制約は小さく、テスト ケースは最大 10^4 で、各配列の要素は最大 100 個です。 これは、テスト ケースごとに O(n log n) の解決策があれば簡単に十分であり、O(n^2) であっても境界線にはなりますが不要であることを意味します。 意図したソリューションは、ソート後に線形になります。 

## アプローチ

 ルールを解釈する強引な方法は、構造を単純化せずに、各テスト ケースですべての条件を直接シミュレートすることです。 すべてのプロパティを 1 つずつチェックし、場合によっては最小値、最大値、カウントを繰り返し再計算して、最大値が含まれているかどうかを動的に特定しながら隣接制約を検証します。 これは正しいですが、隣接関係の検証中に最大限のチェックを行うために配列を繰り返しスキャンする可能性があり、冗長な作業が発生する可能性があるため、概念的な意味では非効率的です。 最悪の場合、各隣接関係チェックの最大数を再計算すると、テスト ケースごとに O(n^2) に向かってドリフトします。 

重要な点は、すべての必要なグローバル プロパティを配列ごとに 1 回事前計算できることです。 値の最小値、最大値、および頻度は隣接性チェックとは独立しており、並べ替え後に必要な構造的推論は 1 回の線形スキャンだけです。 これにより、問題は、位置に最大値が含まれているかどうかを定数時間チェックしてソートされたリストを通過する単純な検証に集約されます。 

ブルート フォースはルールを直接適用するため機能しますが、ローカル チェックにグローバル クエリが混在するため、きれいに拡張できません。 概要統計を事前に計算すると、懸念事項が分離され、並べ替えによりすべてが O(n log n) に削減されます。

 | 最適 | テストあたり O(n log n) | O(1) おまけ | 承認済み |

 ## アルゴリズムのチュートリアル

 ### 最適な推論手順

 1. 配列を読み取り、すぐにその長さを確認します。 10 ～ 13 の範囲外の場合、構成は有効ではないため、それ以上の作業を行わずに拒否できます。 これにより、明らかに無効なケースに対する不必要な並べ替えが回避されます。 
2. 配列を降順でない順に並べ替えます。 このステップが必要なのは、隣接制約は順序付け後にのみ定義され、ソートなしでは滑らかさについて局所的に推論できないためです。 
3. ソートされた配列から最小値と最大値を計算します。 また、最小値が何回出現するかを数えます。 これらの値により、極値に関する構造要件が満たされているかどうかが決まります。 
4. 最小値が正確に 1 であることを確認します。そうでない場合は、「最も簡単な問題は 1」ルールに直ちに違反します。 
5. 1 の数が少なくとも 2 であることを確認します。これにより、簡単な問題が十分に存在することが保証されます。 
6. 最大値が 1 回だけ表示されることを確認します。 これにより、ルールで要求される固有の最も困難な問題が特定されます。 
7. ソートされた配列内の隣接するペアをスキャンします。 各ペアについて、絶対的な差を確認します。 いずれかの要素が最大値に等しい場合、そのペアの制約をスキップします。 それ以外の場合は、差が最大 2 であることを確認してください。いずれかのペアがこれに違反する場合、構成は無効になります。 

### なぜ効果があるのか

ソート後、最小値と最大値に関するグローバル条件を除き、すべての構造的制約はローカルな整合性チェックに限定されます。 最小値、最大値、および周波数を事前に計算すると、グローバル制約が分離されるため、隣接関係の検証が独立します。 不変条件は、すべての非最大要素が、最大 2 のステップ サイズで値が徐々に増加するシーケンス内に存在する必要があるということです。許可される唯一の不連続は、一意の最大値が関与する境界にあり、残りのチェーンの連続性に影響を与えません。 この分離により、グローバル チェックまたは単一の隣接ペア比較のいずれかで違反が現れることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        if n < 10 or n > 13:
            out.append("No")
            continue

        a.sort()

        mn = a[0]
        mx = a[-1]

        if mn != 1:
            out.append("No")
            continue

        cnt1 = 0
        for x in a:
            if x == 1:
                cnt1 += 1

        if cnt1 < 2:
            out.append("No")
            continue

        if a.count(mx) != 1:
            out.append("No")
            continue

        ok = True
        for i in range(n - 1):
            if a[i] == mx or a[i + 1] == mx:
                continue
            if abs(a[i + 1] - a[i]) > 2:
                ok = False
                break

        out.append("Yes" if ok else "No")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```この解決策では、まずサイズ制約を使用して不可能なケースをフィルタリングします。 並べ替えにより、後続のすべての推論で正しい順序が確立されます。 最小値と頻度のチェックにより、最も簡単な問題に対する構造要件が適用されます。 最大値の一意性チェックにより、特別な例外ルールが適切に定義されていることを確認します。 

最後のループは、核となる検証ステップです。 どちらの要素も最大値ではなく、例外規則に正確に一致する場合にのみ、差分制約が適用されます。 これにより、最大の要素が大きなジャンプを引き起こす有効な構成が誤って拒否されることが回避されます。

 ## 特殊なケース

 厄介なケースは、配列に複数の小さな値が含まれているものの、1 が 1 つだけ含まれている場合です。たとえ隣接関係の差が小さい場合でも、少なくとも 2 つの 1 を必要とするルールにより拒否が強制されます。 アルゴリズムは構造チェックの前に 1 の出現を明示的にカウントするため、これを正しく処理します。 

最大値が複数回出現する場合、別の特殊なケースが発生します。 たとえ隣接制約が通過したとしても、例外ルールが不明確になるため、アルゴリズムは最大値の一意性をチェックすることによって早期に例外ルールを拒否します。 

3 番目のケースは、大きなギャップが最大値に隣接して表示されるが、他の場所の最大値以外の遷移にも影響を与える場合です。 このアルゴリズムは、最大値に関係する比較のみをスキップすることで正確性を保証するため、他のすべてのペアは厳密に検証され、隠れた違反が見逃されないことが保証されます。
