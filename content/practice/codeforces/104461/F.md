 ## 解決策
 ## 問題の理解

 値のシーケンスが与えられ、それをいくつかのサブシーケンスに分割することができます。 各サブシーケンスは「ヒープ可能」である必要があります。つまり、すべてのノードが後の要素のみを指し、親の値が子の値よりも大きくならないように、その要素を出現順にバイナリ ツリーに配置できる必要があります。 

ここで重要な構造はツリー自体ではなく、ツリーが順序付けに課す制約です。 親は元のシーケンスの前に出現する必要があり、その値がその子よりも大きくない必要があります。 各要素はサブシーケンスの 1 つ内で 1 回だけ使用されます。私たちのタスクは、必要なそのような有効なサブシーケンスの数を最小限に抑えることです。 

出力はサブシーケンスの最小数だけでなく、インデックスの明示的な分割でもあり、各サブシーケンスはインデックスの昇順でリストされます。 

テスト全体にわたる最大 2×10^6 の制約 n により、O(n log n) 以上の解が強制されます。 ツリーを明示的にシミュレートしようとしたり、単純な方法で有効な接続点を繰り返し検索しようとしたりするものは、スケールできません。 この構造は、効率的な状態維持を伴う貪欲なプロセスに縮小する必要があります。 

いくつかの障害モードは見落とされがちです。 

「利用可能なスロット」を注意深く維持せずに、各要素を最初の有効なサブシーケンスに貪欲に追加しようとすると、失敗します。 たとえば、5 4 3 2 1 のような減少シーケンスの場合、単純な試みにより同じサブシーケンスを誤って再利用する可能性がありますが、以前の要素が有効な親として機能できないため、ヒープ制約によりすべての新しい要素が新しいチェーンを開始するように強制されます。 

別の微妙な失敗が同じ値で表示されます。 親 ≤ 子は等価性を許可するため、順序付けの制約が尊重される場合に限り、等しい値を連鎖させることができます。 これを無視すると、必要なサブシーケンスが過大評価されることがよくあります。 

## アプローチ

 ブルート フォース ビューでは、各サブシーケンスを成長する部分バイナリ ツリーとして扱います。 要素を処理するときは、値と順序の制約の両方を尊重して、まだ容量がある既存のノードの子として要素をアタッチしようとします。 これには、要素ごとに多くの親候補をスキャンし、サブシーケンスごとに完全な動的ツリー構造を維持する必要があります。 たとえ慎重に記録を行っていたとしても、これは多くの考えられる接続点をチェックすることになり、最悪の場合は二次的な動作につながります。 

重要な観察は、バイナリ ツリー構造は 1 つの事実以外には無関係であるということです。各ノードは最大 2 つの子を受け入れることができ、有効な親は、現在の要素以下の値で以前に出現していなければなりません。 これにより、以前の各要素が寄与する「利用可能なスロット」の管理の問題が軽減されます。 配置された各要素は 2 つの潜在的な子スロットを作成しますが、1 つはそれ自体が子になるときに消費されます。 

各サブシーケンスを、値の昇順にスロットを消費するプロセスとして再解釈できます。 ツリーを明示的に構築する代わりに、利用可能な「親スロット」のマルチセットのような構造を維持し、それらを満たすことができる最小値の順に並べます。 新しい要素はそれぞれ、既存のスロットを埋めるか、新しいサブシーケンスを開始して、新しい容量を提供します。 

これにより、問題は要素と利用可能なスロットの間の貪欲なマッチングに変換され、常に最も制限された有効なスロットが最初に再利用されます。 この貪欲な選択により、小さな値の要件で大きな値を無駄にしないことが保証されます。

 ## アルゴリズムのチュートリアル

 現在利用可能な「アタッチメント スロット」を表す構造を維持しながら、要素を左から右に処理します。 各スロットは、何らかのサブシーケンスにすでに存在しており、引き続き子を受け入れることができるノードに対応します。

1. 子を受け入れることができる最小値の順に並べられた、使用可能なスロットの優先順位構造を維持します。 

この順序により、常に最も制限された有効な親が最初に再利用されるようになります。 
2. 各要素 a[i] について、値が ≤ a[i] であるスロットを検索します。 

そのようなスロットが存在する場合は、そのスロットの子として a[i] を割り当てます。 

子の位置が消費されているため、そのスロットから利用可能な容量を 1 つ削除します。 
3. a[i] をアタッチした後、その 2 つの潜在的な子の位置に対応する 2 つの新しいスロットを作成します。 

子はその親以上である必要があるため、これらのスロットは値制約 a[i] を継承します。 
4. a[i] を収容できるスロットがない場合は、i をルートとする新しいサブシーケンスを開始します。 

この新しいルートは、2 つの新しいスロットも生成します。 
5. 親子関係を記録してサブシーケンスを再構築しますが、コアロジックは明示的なツリーではなくスロットの可用性によって完全に駆動されます。 

中心的な考え方は、すべてのノードが将来の挿入の可能性を正確に 2 つ提供し、以前のノードを可能な限り効率的に再利用しようと常に努めているということです。 

### なぜ効果があるのか

 任意の時点で、利用可能なスロットのセットは、構築されたすべてのサブシーケンスからのすべての有効な添付ファイルを完全に要約します。 各スロットは子を受け入れることができるノードを表し、その値の制約によりヒープの有効性が保証されます。 

実行可能な最小のスロットを常に使用するという貪欲な戦略により、「ブロッキング」が防止されます。小さい値のスロットが存在するときに大きい値のスロットを使用すると、将来の柔軟性が低下するだけです。小さい値の制約は後で満たすのが難しいためです。 挿入するたびに使用可能なスロットの数が固定量 (ノードごとに 2 つから使用されている 1 つを引いたもの) だけ増加するため、システムのバランスが保たれ、将来の要素が必要以上のサブシーケンスの作成を強制されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n = int(input())
        a = list(map(int, input().split()))

        # each subsequence is stored as list of indices
        seqs = []
        
        # available "slots": (value_constraint, seq_id)
        # each slot means: we can attach a child here if value >= constraint
        import heapq
        slots = []

        # track how many children already used per node is not needed explicitly,
        # we just push two slots per node creation and consume one per assignment.

        # for reconstruction: parent structure per index
        parent = [-1] * n

        for i, v in enumerate(a):
            # find usable slot
            chosen = None

            # we need to pop invalid slots (value > v)
            while slots and slots[0][0] > v:
                # cannot use this slot
                heapq.heappop(slots)

            if slots:
                _, sid = heapq.heappop(slots)
                parent[i] = seqs[sid][0]  # attach somewhere in subsequence root chain
                seqs[sid].append(i)
            else:
                sid = len(seqs)
                seqs.append([i])

            # new node contributes two slots
            heapq.heappush(slots, (v, sid))
            heapq.heappush(slots, (v, sid))

        print(len(seqs))
        for s in seqs:
            print(len(s) + 1, *(x + 1 for x in s))

if __name__ == "__main__":
    solve()
```このコードは、値制約によってキー設定された使用可能な添付スロットのヒープを維持します。 各要素について、受け入れられないスロットを破棄し、既存のサブシーケンスを再利用するか、新しいサブシーケンスを作成します。 配置後、新しいノードの容量を表す 2 つの新しいスロットをプッシュします。 

微妙な点は、バイナリ ツリーを明示的に構築していないことです。 代わりに、サブシーケンスはインデックスのコレクションとして扱われ、再構築は明示的な親ポインターではなくグループ化に基づいて行われます。 正確さは、正確なツリー構造ではなく、パーティションのみが重要であるという事実から来ています。 

実装の主な落とし穴は、可用性を確認する前に使用できないスロットを削除するのを忘れることです。これにより、要素が無効な親に誤ってアタッチされてしまいます。 

## 実用的な例

 順番を考えてみる`3 1 2`。 

サブシーケンスとスロットを追跡します。 

| ステップ | 要素 | 前のスロット | アクション | サブシーケンス | | 以降のスロット
 | --- | --- | --- | --- | --- | --- |
 | 1 | 3 | ∅ | 新しいサブシーケンス | [ [0] ] | (3)、(3) |
 | 2 | 1 | (3,3),(3,3) が無効です | 新しいサブシーケンス | [ [0],[1] ] | (1)、(1)、(3)、(3) |
 | 3 | 2 | (1,1)、(3,3)、(3,3) | スロット 1 を使用する | [ [0],[1,2] ] | 更新されたスロット |

 これは、互換性のあるスロットが存在しない場合に、より小さい値がどのように新しいサブシーケンスを強制するかを示しています。 

ここで考えてみましょう`1 2 3 4`。 

| ステップ | 要素 | 前のスロット | アクション | サブシーケンス |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | ∅ | 新しい | [ [0] ] |
 | 2 | 2 | (1,1),(1,1) | 再利用 | [ [0,1] ] |
 | 3 | 3 | ... | 再利用 | [ [0,1,2] ] |
 | 4 | 4 | ... | 再利用 | [ [0,1,2,3] ] |

 これは、スロットの貪欲な再利用が可能な場合には単一のサブシーケンスを構築することを裏付けています。

 ## 特殊なケース

 次のような厳密に減少する配列の場合`5 4 3 2 1`の場合、既存のスロットはすべて現在の要素より大きい値を持つため、アルゴリズムは新しい要素ごとに有効なスロットを見つけません。 各要素は新しいサブシーケンス ルートとなり、5 つのサブシーケンスが生成されます。 ヒープから無効なスロットが繰り返し削除され、不正な添付ファイルが発生しないようにします。 

次のような定数配列の場合`2 2 2 2`、最初の要素はサブシーケンスを作成します。 等価性が許可されているため、後続の各要素は既存のスロットを再利用でき、すべての要素が単一の構造に結合されます。 ヒープはすべてのスロットを破棄することはなく、再利用によりサブシーケンス数が最小限に抑えられます。
