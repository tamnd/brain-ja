 ## 解決策
 ## 問題の理解

 私たちにはパイプ穴のシステムが与えられており、各穴のサイズは固定されており、システムに水を注いだときに排水できる水の量が決まります。 アルカディは一定量の水を注ぎますが、彼にとって役立つと考えられるのは最初の穴だけです。 彼の目標は、少なくとも必要な量の水がこの最初の穴から確実に流出するようにすることです。 

彼が持つ重要な制御は、水を注ぐ前に穴のサブセットをブロックできることです。 ブロックした後、残った開いた穴はそのサイズに比例して水を共有します。 開いている穴の合計サイズが$S$、最初の穴は端数を受け取ります$s_1 / S$総水量のうち$A$したがって、その出力は次のようになります$A \cdot s_1 / S$。 

タスクは、最初の穴が少なくとも受信できるように、ブロックされる穴の数を最小限に抑えることです。$B$水の単位。 

この制約により、私たちは貪欲な解決策、または並べ替えベースの解決策に向かうことになります。 と$n$まで$10^5$、穴のすべてのサブセットを試すアプローチは不可能です。 すべてを繰り返しても$2^n$可能性は問題外であり、再計算で可能な除去数をそれぞれチェックすることさえ、単純に行うと遅すぎます。 

微妙な点は、穴の削除は分母にのみ影響することです。$S$、分子ではありません$s_1$。 これにより、単調な効果が生じます。つまり、穴を削除すると、常に最初の穴のシェアが増加します。 

いくつかの特殊なケースは見落とされがちです。 

穴が塞がれていない場合は、すでに十分である可能性があります。 たとえば、次の場合$s_1$すべてのサイズの合計と比較して大きい場合、条件は直ちに成立し、答えはゼロになります。 

他のすべての穴が他の穴と比較して極端に大きい場合、$s_1$の場合、条件を満たす唯一の方法は、最初の穴を除くほぼすべてを削除することです。 極端な場合、答えは次のようになります。$n-1$。 

3 番目の微妙なケースは、複数の穴が同じサイズである場合です。 重要なのは和だけであり恒等ではないため、決定は分母から最大の寄与を取り除くことだけに依存します。 

## アプローチ

 強引なアイデアとしては、ブロックする穴のサブセットをすべて試してみることです。 各サブセットについて、残りの合計を計算します$S$、どうかを確認してください。$A \cdot s_1 / S \ge B$。 これには、すべてのサブセットを反復処理し、残りの要素を合計する必要があります。$O(n \cdot 2^n)$行動。 と$n = 10^5$、これはまったく不可能です。 

条件を書き直すと、より構造化されたビューが得られます。$$\frac{A \cdot s_1}{S} \ge B \quad \Rightarrow \quad S \le \frac{A \cdot s_1}{B}$$したがって、最初の穴のシェアを直接最大化することを考えるのではなく、残りの合計を減らすことを考えます。$S$。 最初の穴のサイズは固定されているため、ブロックする穴をできる限り少なくしながら、残りの穴の合計をできる限り小さくしたいと考えています。 

これは貪欲な方向性を与えます。つまり、合計を最も早く減らすには、最初に最大の穴を削除する必要があります。 除去された穴はそれぞれ減少します$S$削除ごとに可能な限り。 したがって、ホール (最初のホールを除く) を降順に並べ替え、徐々に削除することが最適な戦略となります。 

条件が満たされるまで、最大のサイズを 1 つずつ削除するシミュレーションを行います。

 | ブルート フォース (すべてのサブセット) |$O(2^n \cdot n)$|$O(n)$| 遅すぎる |
 | 選別 + 貪欲な削除 |$O(n \log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての穴サイズの合計を計算します。 これは、削除前の分母を表します。 
2. 最初の穴は削除されないため、そのサイズを個別に抽出します。 
3. 何も削除せずに、すでに条件が満たされているかどうかを確認します。 もし$A \cdot s_1 \ge B \cdot S$、すぐに 0 を返します。 
4. 他のすべての穴サイズをリストに収集します。これらの穴のみが削除の候補となるためです。 
5. 分母への寄与が最も大きいものが最初に考慮されるように、このリストを降順に並べ替えます。 
6. ソートされたリストを繰り返し処理し、一度に 1 つの穴を削除します。 

1. 合計からそのサイズを減算します。 
2. 除去数を増やします。 
3. 不等式が満たされているかどうかを確認します$A \cdot s_1 \ge B \cdot S$今は成立しています。 

保持している場合は、停止して削除した穴の数を戻します。 

ソートの背後にある理由は、すべての除去によって分母が減少し、しきい値に達することのみを考慮する場合、より大きな量で分母を減らすことは、より少ない量で減らすことと常に少なくとも同じくらい良いということです。 

### なぜ効果があるのか

 重要な不変条件は、いつでも、同じサイズ (同じ除去数) の穴のすべてのセットのうち、利用可能な最大の穴を除去すると、残りの合計が最小になるということです。$S$。 条件は次のいずれかに依存するため、$S$が固定のしきい値を下回っている場合、最小限の削除でそのしきい値に到達することは、常に最大の削減を行うことと同じです。$S$各ステップで。 残っている最大の要素の削除からの逸脱は、同じ回数の削除後により大きな合計を残すことになるだけであり、不等式を早期に満たすのには役立ちません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, A, B = map(int, input().split())
    s = list(map(int, input().split()))
    
    s1 = s[0]
    total = sum(s)
    
    if A * s1 >= B * total:
        print(0)
        return
    
    rest = s[1:]
    rest.sort(reverse=True)
    
    removed = 0
    for x in rest:
        total -= x
        removed += 1
        if A * s1 >= B * total:
            print(removed)
            return

if __name__ == "__main__":
    solve()
```コードは導出された不等式に直接従い、条件を相互乗算することによる浮動小数点除算を回避します。 これにより、精度の問題が防止されます。 

ソートのステップにより、各反復で、削除された要素ごとの総和が最大限に削減されることが保証されます。 条件が満たされるとすぐにループが停止するため、必要以上に穴を削除することはありません。 

よくある落とし穴は、ソートされた削除リストに誤って最初のホールが含まれてしまうことです。 これにより、分子として依存している要素自体が誤って削除されてしまう可能性があります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n, A, B = map(int, input().split())
    s = list(map(int, input().split()))
    
    s1 = s[0]
    total = sum(s)
    
    if A * s1 >= B * total:
        return "0"
    
    rest = s[1:]
    rest.sort(reverse=True)
    
    removed = 0
    for x in rest:
        total -= x
        removed += 1
        if A * s1 >= B * total:
            return str(removed)

# provided sample
assert run("4 10 3\n2 2 2 2\n") == "1", "sample 1"

# all equal already satisfied
assert run("3 10 1\n5 5 5\n") == "0"

# need all removals except first
assert run("3 10 9\n1 100 100\n") == "2"

# minimal case
assert run("1 5 3\n10\n") == "0"

# large skew
assert run("5 100 1\n1 100 100 100 100\n") == "0"

 ## 特殊なケース

 穴が 1 つだけの場合、分母は変化せず、答えは常に 0 になります。 削除リストが空であり、初期の条件チェックによって結果が即座に決定されるため、アルゴリズムがこれを処理します。 

最初のホールを除くすべてのホールが非常に大きい場合、アルゴリズムはそれらを降順で削除し、分母を急速に縮小します。 それぞれの除去は不可欠であり、最初の穴だけが残るか、しきい値に達するまで、ループは自然に必要な数を正確にカウントします。 

初期設定がすでに不等式を満たしている場合、初期チェックはすぐに終了するため、ソートや削除は効果的に使用されません。
