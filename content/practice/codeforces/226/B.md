 ## 解決策
 ## 問題の理解

 いくつかの石の山があり、それぞれに初期サイズがあります。 1 つの操作でソース パイルを選択し、それを別のパイルにマージします。 ソース パイルが消滅し、宛先パイルが増加し、操作コストはソース パイルの現在のサイズと等しくなります。 

通常とは異なる制限は宛先側にあります。 すべてのパイルは最大でも受け取ることができます`k`受信マージはその存続期間中に行われます。 すでにパイルが受け入れられた後`k`他のパイルに結合すると、宛先として使用できなくなりますが、別のパイルにマージすることはできます。 

すべてのクエリ値に対して、`k`、単一の山で終了するために必要な最小の総コストを計算する必要があります。 

制約によってソリューションが完全に形作られます。 まであります`10^5`杭と`10^5`クエリ。 すべてのクエリに対して個別にマージをシミュレートするアプローチ`O(n)`あるいはさらに悪いことに、隠れた定数が大きい場合は遅すぎる可能性があります。 二次関数などは不可能です。 前処理と非常に安価なクエリ処理が必要です。 

パイルサイズは以下に達します`10^9`、合計の答えは 32 ビットの範囲よりもはるかに大きくなる可能性があります。 64 ビット整数型が必要です。 

この問題の最も難しい部分は、どのような構造がコストを最小限に抑えるかを理解することです。 制限は最終的なマージ ツリーにノードが持つ子の数ではなく、プロセス中にパイルがレシーバーとして機能する回数に制限されるため、不注意な貪欲な行為は簡単に失敗する可能性があります。 

微妙なエッジケースの 1 つは、`k = 1`。 

入力：```
4
1 2 3 4
1
1
```正しい出力:```
20
```なぜ？ と`k = 1`、すべてのパイルは最大 1 つのマージを受け取ることができるため、マージ プロセスはチェーンを形成する必要があります。 最小の山が最初にマージされ、次にその結合された山が再度マージされ、以下同様に続きます。 総コストは次のようになります。`1 + (1+2) + (1+2+3) = 1 + 3 + 6 = 10`しかし、それは追加の杭のコストにすぎません。 昇順にソートした後の実際の最適な順序は次のとおりです。`1 -> 2`、 料金`1`

`3 -> (1+2)`、 料金`3`

`4 -> (...)`、 料金`6`合計`10`。 

ハフマン符号のように「最小値を繰り返しマージする」という単純な解釈では、`19`、このルールの下では最適ではありません。 

もう一つの厄介なケースは非常に大きい`k`。 

入力：```
5
1 2 3 4 5
1
100
```正しい出力:```
10
```1 つの山は他の山を直接吸収できます。 単純に最大のパイルを最終レシーバーとして選択し、すべての小さなパイルをそれに追加します。 コストは、最大のものを除くすべての山の合計です。 

繰り返されるクエリも重要です。 ステートメントでは重複が許可されています`k`価値観。 毎回同じ答えを再計算すると時間の無駄になり、許容できる解がタイムアウトになってしまう可能性があります。 

## アプローチ

 強引なアイデアは、マージ シーケンスを明示的にシミュレートすることです。 固定の場合`k`、有効なマージ注文をすべて試して、最小コストを選択することができます。 すべての操作が明確に定義された方法で状態を変更するため、これは概念的に機能します。 

問題は、有効なマージ ツリーの数が指数関数的に増加することです。 小さいものでも`n`、検索スペースが膨大になります。 サブセットに対する動的プログラミングには、大まかに次のものが必要です。`O(2^n)`完全に不可能な状態`n = 10^5`。 

したがって、最適なマージ プロセスがどのようなものかを理解する必要があります。 

山を昇順に並べ替えるとします。```
a1 <= a2 <= ... <= an
```各杭が総コストにどのくらいの頻度で寄与するかを考えてください。 

パイルが別のパイルにマージされるたびに、その現在のサイズ全体が再度支払われます。 石が最終的に消えるまでに多くのレベルを生き延びた場合、それは答えに複数回貢献します。 

つまり、小さな山は早期に消えますが、大きな山は根元近くに留まるはずです。 

次に制限を見てみましょう。 パイルは最大でも受け取ることができます`k`合併します。 ツリー言語では、すべてのノードが最大で`k`子供たち。 

最適な構造が根付く`k`-ary マージ ツリー。大きい値はルートの近くに留まり、小さい値はより深くに存在します。 

並べ替え後の最適な戦略は驚くほど簡単です。 

最大の杭には深さがある`0`。 

次は`k`杭には深さがある`1`。 

次は`k^2`杭には深さがある`2`。 

次は`k^3`杭には深さがある`3`。 

等々。 

杭に深さがある場合`d`、その値が貢献します`d`合計コストの倍になります。 したがって、並べ替えた後は次のようになります。```
answer = sum(ai * depth_i)
```深さは完全なレベルごとに割り当てられます。`k`-ary 最大の要素から下への展開。 

なぜこれが最適なのでしょうか? 深いノードほど多くの回数が支払われるため、常に最大の深さで最小の残りのパイルが必要になるためです。 これは典型的な交換議論です。 

クエリごとに、各深度レイヤーに属する要素の数を追跡しながら、並べ替えられた配列を最小から最大まで処理できます。 

容量は幾何級数的に増加するため、層の数はわずかです。 たとえば、`k = 2`、深さごとのカウントは次のとおりです。```
1, 2, 4, 8, ...
```したがって、各クエリは大まかに実行されます`O(log_k n)`レイヤー遷移と配列上の線形トラバース。 

特殊なケースが現れるのは、`k = 1`。 この場合、すべてのレベルにはノードが 1 つだけ含まれるため、深さは次のようになります。```
n-1, n-2, ..., 1, 0
```このケースは単なる連鎖です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | 指数 | 遅すぎる |
 | 最適 |`O(n log n + q sqrt(n))`償却済み |`O(n)`| 承認済み |

 ## アルゴリズムのチュートリアル

 1. パイルのサイズを昇順に並べ替えます。 

深いノードほどコストでカウントされる回数が増えるため、小さいパイルはマージ ツリーのより深く表示されるはずです。 
2. ソートされた配列のプレフィックスの合計を事前計算します。 

これにより、連続する山のブロックの合計をすばやく計算できます。 
3. クエリごとに`k`、特殊なケースを処理します`k = 1`。 

各パイルがマージを 1 つだけ受信できる場合、マージ構造はチェーンである必要があります。 最小の山には深さがあります`n-1`、次は深さがあります`n-2`、 等々。 
4. のために`k > 1`、最大の山から下に向かってレイヤーごとに深さを割り当てます。 

ルートレベルには以下が含まれます`1`ノード。 

次のレベルには最大でも次のレベルが含まれます`k`ノード。 

次に含まれるのは最大でも`k^2`。 

この方法を続けると、パイルごとに許可される子の最大数に一致します。 
5. ソートされた配列を最大から最小に向かって走査します。 

より深い層に移動するたびに、その層内のすべてのパイルがその値のコピーを 1 つ追加して答えに貢献します。 
6. 以下を追加します。```
depth * sum_of_values_in_this_layer
```合計の答えに。 
7. すべてのクエリの結果を出力します。 

### なぜ効果があるのか

 パイルは、マージ ツリー内でその上にあるすべての祖先ごとに 1 回コストに寄与します。 まさにその奥深さです。 

「パイルは最大で受け取ることができる」という制限`k`「マージ」は、マージ ツリー内のすべてのノードが最大でも`k`子供たち。 より深いノードにはより大きな係数が乗算されるため、このようなツリーすべての中で、最も小さい値が最も大きな深さを占める必要があります。 

貪欲なレイヤーの割り当てはまさにそれを実現します。 利用可能な最も深い位置は残りの最小のパイルで埋められ、重み付けされた合計が最小化されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = sorted(map(int, input().split()))

    q = int(input())
    queries = list(map(int, input().split()))

    prefix = [0] * (n + 1)
    for i in range(n):
        prefix[i + 1] = prefix[i] + a[i]

    memo = {}

    ans = []

    for k in queries:
        if k in memo:
            ans.append(memo[k])
            continue

        if k == 1:
            cur = 0
            for i in range(n):
                cur += a[i] * (n - 1 - i)

            memo[k] = cur
            ans.append(cur)
            continue

        cur = 0

        depth = 0
        cnt = 1
        r = n

        while r > 0:
            l = max(0, r - cnt)

            layer_sum = prefix[r] - prefix[l]
            cur += depth * layer_sum

            r = l
            cnt *= k
            depth += 1

        memo[k] = cur
        ans.append(cur)

    print(*ans)

solve()
```最適なマージ ツリーではより小さい値がより深い深さに割り当てられるため、最初のステップで配列が並べ替えられます。 

プレフィックス合計配列を使用すると、定数時間の範囲合計クエリが可能になります。 レイヤーにインデックスの要素が含まれている場合`l`に`r-1`、その合計は次のとおりです。```
prefix[r] - prefix[l]
```メインループはクエリを独立して処理しますが、繰り返されるクエリはキャッシュされます。`memo`。 このステートメントでは重複が明示的に許可されているため、これは重要です。`k`価値観。 

の`k = 1`レイヤーサイズに を掛けるため、ケースが分離されます。`k`決して成長しないでしょう。 この場合、各レイヤーにはちょうど 1 つのパイルが含まれます。 

のために`k > 1`、アルゴリズムは幾何学的にレイヤーを構築します。```
1, k, k^2, ...
```最大の要素から始めます。 変数`r`未割り当てのままの要素の数をマークします。 各反復は最後のものを取得します`cnt`要素を作成し、それらに現在の深さを割り当てます。 

微妙な詳細の 1 つは、深さは次から始まるということです。`0`根元にある。 最大のパイルは別のパイルにマージされないため、何も貢献しません。 

もう 1 つの簡単な間違いは、他の言語における整数オーバーフローです。 答えは周りに届くかもしれない`10^19`したがって、64 ビット整数は必須です。

 ## 特殊なケース

 可能な最小の入力を考えてみましょう。```
1
7
1
1
```すでにちょうど 1 つの山が存在するため、操作は必要ありません。 ルート層には深さの唯一の要素が含まれるため、アルゴリズムはこれを自然に処理します。`0`、答えには何も貢献しません。 

次に、制限的なケースを見てみましょう`k = 1`:```
4
1 2 3 4
1
1
```ソートされた配列:```
[1, 2, 3, 4]
```深さの割り当ては次のようになります。```
3, 2, 1, 0
```貢献：```
1*3 + 2*2 + 3*1 + 4*0 = 10
```アルゴリズムは専用のブランチを使用します。`k = 1`、無限等比数列を回避します。 

非常に大きい場合`k`:```
5
1 2 3 4 5
1
100
```根は他のパイルを直接吸収します。 

層構造:```
depth 0 -> [5]
depth 1 -> [1,2,3,4]
```答え：```
1 + 2 + 3 + 4 = 10
```すべての要素が割り当てられると、アルゴリズムは正しく停止します。`k^2`よりもはるかに大きいです`n`。 

最後に、繰り返されるクエリについて考えてみましょう。```
5
1 2 3 4 5
4
2 2 2 2
```メモ化がなければ、同じ計算が 4 回繰り返されることになります。 このソリューションは最初の結果を保存し、その後の結果に対して即座に再利用します。
