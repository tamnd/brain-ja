 ## 解決策
 ## 問題の理解

 次のような整数の長方形テーブルが与えられます。$n$行と$m$列。 各セルには、正、負、またはゼロの数値が含まれています。 ハリーは 2 種類の操作を実行できます。行内のすべての数値の符号を反転するか、列内のすべての数値の符号を反転します。 目標は、このような一連の操作を適用して、すべての行とすべての列の合計が負でないようにすることです。 出力は、反転する行と列のセットである必要があります。 

とすれば$n, m \le 100$各数値の絶対値は 100 で制限されており、おおよそ最大で 100 まで許容されます。$10^4$単純なループを実行する場合、2 秒の制限時間内に解を維持するための操作。 行と列の反転のすべての組み合わせを試す単純な総当りアプローチは実行不可能です。$2^{n+m}$可能なフリップ構成は、たとえ$n=m=20$。 

単純な実装が失敗する可能性があるエッジ ケースには、すべての数値が負である単一行または単一列を持つテーブルが含まれます。 たとえば、値を含む 4×1 テーブルがあるとします。$[-1, -1, -1, -1]$、行を単独で考慮するだけの不注意なアルゴリズムでは、すべての行を反転するのではなく、何も反転しないか、存在しない列を反転する可能性があります。 もう 1 つのトリッキーなシナリオは、1 つの行または列を反転すると複数の合計に影響を与えるマイナスとプラスの市松模様のパターンです。 単純な貪欲なアプローチは、収束しない場合、無限に振動する可能性があります。 

## アプローチ

 ブルートフォース手法では、行と列のすべてのサブセットを反転して、結果の合計が負でないかどうかを確認しようとします。 解が存在する場合には必ずそれを見つけることができますが、サブセットの数は次のとおりです。$2^{n+m}$、これは明らかに不可能です$n, m = 100$。 

重要な洞察は、行または列を 2 回反転するとそれ自体がキャンセルされるため、任意の解は繰り返しのない行反転のセットと列反転のセットとして表すことができるということです。 さらに貪欲に反転もかけられます。 行の合計が負の場合、行を反転して正にします。 行を調整した後、列を確認します。 列の合計が負の場合、列を反転します。 ただし、列を反転すると一部の行の合計が再び負になる可能性がありますが、各反転は現在負の行または列の合計を厳密に増加させるため、繰り返し適用すると最終的には収束します。 

数値が制限されており、グリッドが小さいため、負の合計で行または列を繰り返し反転する貪欲な反復アプローチはすぐに収束し、常に有効な構成が生成されます。 最悪の場合のフリップ回数は最大で$n + m$行または列を 2 回反転する必要がないためです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(2^{n+m} \cdot n \cdot m)$|$O(n \cdot m)$| 遅すぎる |
 | 貪欲な反復 |$O(n \cdot m \cdot (n+m))$|$O(n \cdot m)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力グリッドを読み取り、2 つのブール配列を初期化して、反転された行と列を追跡します。 すべて false に初期化します。 
2. 各行の合計を計算します。 行の合計が負の場合は、反転マークを付けて行を反転し、そのすべての要素を無効にします。 行を反転すると、行の合計が負でなくなります。 
3. 各列の合計を計算します。 列の合計が負の場合は、反転マークを付けて列を反転し、そのすべての要素を否定します。 列を反転すると、列の合計が負でなくなります。 
4. 列反転後、一部の行の合計が負になる場合があります。 行または列の合計が負にならないまで、手順 2 と 3 を繰り返します。 
5. 反転された行と反転された列のリストを出力します。 順序は重要ではありません。各インデックスが最大 1 回出現することだけが重要です。 

機能する理由: 各反転は、少なくとも 1 つの負の行または列の合計の符号を厳密に改善します。 行または列の合計が正になると、他の行または列をさらに反転しても、それを無限に負にすることはできません。これは、それぞれの数値に制限があり、2 回反転するとそれ自体がキャンセルされるためです。 これにより、収束と正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
a = [list(map(int, input().split())) for _ in range(n)]

row_flip = [False] * n
col_flip = [False] * m

changed = True
while changed:
    changed = False
    for i in range(n):
        row_sum = sum(a[i][j] if not col_flip[j] else -a[i][j] for j in range(m))
        if row_sum < 0:
            row_flip[i] = not row_flip[i]
            changed = True
    for j in range(m):
        col_sum = sum(a[i][j] if not row_flip[i] else -a[i][j] for i in range(n))
        if col_sum < 0:
            col_flip[j] = not col_flip[j]
            changed = True

rows = [i + 1 for i in range(n) if row_flip[i]]
cols = [j + 1 for j in range(m) if col_flip[j]]

print(len(rows), *rows)
print(len(cols), *cols)
```コードはまずテーブルを読み取り、フリップを追跡するために 2 つのリストを初期化します。 メインループは、行の合計と列の合計のチェックを交互に行います。 反転は、負の合計が見つかるたびに貪欲に適用されます。 合計が負の行または列がない場合、ループは終了します。 最後に、反転された行と列のインデックスを抽出して出力します。 

微妙な詳細は、以前のフリップを考慮した合計を計算する方法です。 行も列も奇数回反転されていない場合、セルはプラスに寄与します。 否定を伴うブール値を使用すると、追跡が簡素化されます。

```| ステップ | 行の合計 | 列の合計 | 行反転 | 列反転 |

 テーブルには 1 つの列があります。 最初はすべての行の合計が負であるため、すべての行が反転されます。 列の合計がプラスになります。 これ以上フリップする必要はありません。

```| ステップ | 行の合計 | 列の合計 | 行反転 | 列反転 |
