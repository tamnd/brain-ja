 ## 解決策
 ## 問題の理解

 文字列が与えられています`s`長さの`n`そして、文字の出現はすべて行上の位置として考える必要があります。 2 つの位置間を移動するには、キャラクターが同じかどうかに応じてコストがかかります。 

2 つのインデックス間を移動する場合`i`そして`j`、両方の位置に同じ文字が含まれている場合、同じ文字間で「テレポート」できるため、コストはゼロです。 それ以外の場合、コストは単にインデックス間の絶対距離になります。 

各クエリには 2 つの文字が与えられます`u`そして`v`。 私たちは、どんな出来事からでも始めることができます。`u`文字列内で次の文字列が出現すると終了します。`v`。 中間インデックスを通過する場合があり、パスのコストは上で定義したエッジ コストの合計になります。 タスクは、各クエリの可能な最小コストを計算するか、そのコストに達したことを報告することです。`v`からは不可能です`u`。 

制約は特定の点で重要です。 文字列は 100,000 に達する可能性があるため、インデックスのすべてのペアを試行したり、クエリごとに最短パスを実行したりするソリューションは失敗します。 ただし、クエリの数は最大 26 x 26 です。つまり、小文字間の遷移のみを考慮する必要があります。 これは、状態空間のサイズが最大 26 ノードであることを直ちに示唆します。`n`ポジション。 

微妙なエッジ ケースは、文字列内に文字がまったく存在しない場合です。 たとえば、次の場合`s = "abac"`そしてクエリは次のことを要求します`z a`、開始位置はないため、答えは次のようになります。`-1`。 もう 1 つのエッジケースは次のような場合です`u == v`そしてそのキャラクターは少なくとも一度は存在します。 開始と終了に同じインデックスを選択できるため、コストはゼロです。 これを無視した素朴な最短パスの定式化も機能しますが、それは長さゼロの遷移が適切に処理される場合に限られます。 

もう 1 つの注意が必要なケースは、両方の文字が存在するものの文字列内で遠く離れており、最適なパスでは直接ジャンプではなく中間文字が使用される場合です。 たとえば、からの移動`a`に`c`ゼロコストホップオンを繰り返すことで安くなる可能性がある`b`中間構造によりロングジャンプの必要性が減るためです。 

## アプローチ

 ブルートフォース解釈では、すべてのインデックスがグラフ内のノードとして扱われます。 インデックスから`i`、どこにでも移動できます`j`、支払い`|i - j|`文字が一致しない場合は、コストはゼロになります。 次に、クエリごとに、文字のすべてのインデックスから最短パスを実行します。`u`文字の任意のインデックスに`v`。 

これは正しいですが、遅すぎます。 と`n = 10^5`、すべてのインデックスに対する単一のダイクストラには、すでに約`n log n`最大 676 個のクエリに対してこれを実行すると、完全に実行不可能になります。 

重要な観察は、等しい文字によって、そのすべての出現の間にコストがゼロの接続が作成されるということです。 これは、各キャラクター内で、そのすべての位置が単一のコストゼロのクラスターのように動作することを意味します。 別のキャラクターに移動すると、コストは位置間の距離のみに依存し、次のキャラクターへの最適な「エントリ ポイント」のみを考慮します。 

これにより、次の問題が軽減されます。`n`ノードを最大 26 の文字状態にします。 文字ごとに、その位置のソートされたリストを事前計算できます。 次に、26 文字のグラフ上でマルチソースの最短パスを実行します。文字から遷移します。`c1`に`c2`発生間の最小距離がかかります。`c1`そしてあらゆる出来事が`c2`。 

これらのペアごとの文字遷移コストが得られると、各クエリは直接検索になります。

 | 最適 (事前計算された遷移を使用した 26 ノードの最短パス) | O(26² · n) または O(26³) | O(26² + n) | 承認済み |

 ## アルゴリズムのチュートリアル

 文字列を各文字ごとに 1 つずつ、26 個のバケットに分割し、出現するすべてのインデックスを保存します。 次に、これらの 26 ノード間の重み付きグラフを構築します。 

1. 文字列内の各文字の位置を収集します。 

文字列を 1 回スキャンし、各インデックスをその文字のリストに追加します。 これにより、各文字がどこに出現するかを正確に知ることができ、後で最小距離を計算するために必要になります。 
2. 26 x 26 のコスト行列を無限大で初期化します。 

各エントリは、キャラクターからの最もよく知られたコストを表します。`a`キャラクターに`b`。 直接距離の計算と中間文字を使用してこれらの値を調整します。 
3. 文字の各ペア間の直接遷移コストを計算します。 

2文字の場合`x`そして`y`、任意の位置間の最小絶対差を見つけます。`x`そしてどの位置でも`y`。 両方のリストがソートされているため、2 ポインター スキャンを使用してこれを効率的に計算できます。 これにより、これらのキャラクター間の単一ステップのコストが最適になります。 
4. 対角エントリをゼロに設定します。 

同じインデックスを選択したり、同じ文字間を無料で移動したりできるため、文字からそれ自体への移動にはコストはかかりません。 
5. 26 文字に対して Floyd-Warshall を実行します。 

パスを改善するために中間文字を許可します。 から行く場合`x`に`k`その後`k`に`y`直接より安い`x`に`y`、更新します。 このステップでは、次のようなマルチホップの最適化をキャプチャします。`a -> b -> c`直接ジャンプよりも優れています。 
6. 事前に計算された行列を使用してクエリに答えます。 

クエリごとに`(u, v)`どちらかの文字が存在しない場合は、出力`-1`。 それ以外の場合は、対応するノード間の保存された最短距離を出力します。 

### なぜ効果があるのか

 核となる不変条件は、2 つの文字間の最適なパスを一連の文字遷移に圧縮できるということです。各遷移は、ある文字の出現から別の文字の出現への移動に対応します。 同じ文字のすべての出現はゼロコストでそれらの間で自由に到達できるため、最適な文字間距離を計算したら、個々のインデックスを追跡する必要はありません。 次に、Floyd-Warshall は、考えられるすべての中間文字シーケンスが考慮されることを保証し、26 ノードの状態空間にわたるグローバルな最適性を保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    s = input().strip()

    pos = [[] for _ in range(26)]
    for i, ch in enumerate(s):
        pos[ord(ch) - 97].append(i)

    INF = 10**18
    dist = [[INF] * 26 for _ in range(26)]

    for i in range(26):
        if pos[i]:
            dist[i][i] = 0

    # compute direct costs
    for a in range(26):
        if not pos[a]:
            continue
        for b in range(26):
            if not pos[b]:
                continue
            i = j = 0
            best = INF
            pa, pb = pos[a], pos[b]
            while i < len(pa) and j < len(pb):
                best = min(best, abs(pa[i] - pb[j]))
                if pa[i] < pb[j]:
                    i += 1
                else:
                    j += 1
            dist[a][b] = min(dist[a][b], best)

    # floyd warshall on 26 nodes
    for k in range(26):
        for i in range(26):
            for j in range(26):
                if dist[i][k] + dist[k][j] < dist[i][j]:
                    dist[i][j] = dist[i][k] + dist[k][j]

    for _ in range(q):
        u, v = input().split()
        u = ord(u) - 97
        v = ord(v) - 97

        if not pos[u] or not pos[v]:
            print(-1)
        else:
            ans = dist[u][v]
            print(ans if ans < INF else -1)

if __name__ == "__main__":
    solve()
```コードは、各文字の出現リストを構築することから始まります。これは、元の文字列から必要な唯一の構造です。 の`dist`行列にはペアごとの文字コストが格納されます。 2 ポインター スイープが使用されるのは、両方の位置リストがソートされており、すべてのペアをチェックすることなく最小絶対差を確実に見つけることができるためです。 

フロイド-ウォーシャル ステップは、グラフ サイズが 26 ノードに固定されており、3 次ループが無視できるため安全です。 最後に、クエリは定数時間の検索であり、欠落文字の追加チェックが行われます。 

微妙な点は、読む前に欠落文字を処理する必要があることです。`dist[u][v]`中間パスが存在する場合でも、これらのエントリには無限が含まれる可能性があるためです。 明示的な存在チェックにより、誤った出力が防止されます。

 ## 特殊なケース

 次のような欠落文字の場合`s = "abc"`クエリ付き`z a`計算の前に処理されます。 のポジションリスト`z`は空であるため、アルゴリズムはすぐに出力します`-1`距離行列を読み取らずに。

のような疎な分布`a.....a.....a`2 ポインター スキャンでクラスター間の最小ギャップが正しく検出されるようにします。 このアルゴリズムは、ソートされたリスト内の隣接するポインターのみをチェックするため、すべての組み合わせを列挙することなく、最も近いペアを自然にキャプチャします。
