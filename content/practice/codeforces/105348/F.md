 ## 解決策
 ## 問題の理解

 サイズの順列が与えられています$n$、そしてすべての連続した部分配列を考慮する必要があります。 各サブ配列について、その要素を取得し、その要素をそのサブ配列内の相対的なランクに置き換えます。 この圧縮の後、ランク付けされたバージョンの最後の要素を調べます。その値は部分配列の強度と呼ばれます。 タスクは、すべてのサブ配列にわたってこの強度を合計することです。 

定義を言い換えると次のようになります。部分配列の場合、強度は、その部分配列内の最後の要素以下の要素の数です。 これが機能するのは、個別の値のセットをランクに圧縮すると、最後の要素のランクが部分配列のソート順での位置、つまりそれ以下の要素の数になるためです。 

したがって、問題は次のようになります。すべてのサブ配列について$[l, r]$、要素の数を計算します。$a[l..r]$は$\le a[r]$、すべてのペアについてこれを合計します$(l, r)$。 

制約は大きいです:$n$テスト全体の合計は$10^6$。 どれでも$O(n^2)$テストごとに行うのは不可能ですし、$O(n \log n)$サブ配列ごとの処理は遅すぎます。 すべてのテストにわたって集計された、線形または線形対数に近いものが必要です。 

すべての部分配列に対する単純な二重ループと各ウィンドウ内の要素のカウントには、$O(n^3)$直接実行した場合、または$O(n^2)$最適化を行っても、すぐに失敗します。$10^6$。 

微妙なエッジ ケースは、配列が厳密に増加している場合です。 位置で終わるすべてのサブ配列$r$強度はその長さに等しいため、答えは二次関数的に増加します。 局所的な動作や隣接する比較だけを仮定する間違ったアプローチでは、長い部分配列からの寄与が過小評価されてしまいます。 

もう 1 つのエッジ ケースは、厳密に減少する配列です。 次に、次で終わるすべてのサブ配列は、$r$最後の要素は接頭辞内で常に最小であるため、強度は正確に 1 になります。 これは、答えが値だけではなく、注文構造に大きく依存することを示しています。 

## アプローチ

 ブルートフォース解釈から始めます。 右端ごとに$r$、すべてを考慮してください$l \le r$、各部分配列について要素の数を計算します。$\le a[r]$。 この数を動的に維持するにはコストがかかります$O(n)$当たり$r$、与える$O(n^2)$合計。 

重要な観察は、視点を反転することです。 右端点によって部分配列を処理し、より小さな要素を数える代わりに、各要素を右端点として固定し、前の要素の数がその強度に寄与しているかを尋ねます。 の貢献$a[r]$は、選択した部分配列内の要素の数と同じです。$\le a[r]$、すべての可能な開始点を合計します。 

同様に、固定の場合$r$、すべてのサブ配列$[l, r]$各インデックスの強度カウントに 1 を与えます$i \in [l, r]$そのような$a[i] \le a[r]$。 合計を交換すると、各ペアは$(i, r)$すべてのサブ配列に寄与します。$l \le i \le r$。 このような部分配列の数は$i$～の選択肢$l$1倍固定$r$、ただし、次の条件によって制約されます。$i$「有効な投稿」のセグメント内でカウントされる最後の要素でなければなりません。 

よりクリーンな組み合わせビューは、各位置を処理することです$i$で終わるすべてのサブ配列に寄与するものとして$r \ge i$どこ$a[i]$要素の間にあります$\le a[r]$。 したがって、それぞれについてカウントする必要があります$i$、将来のポジションはいくつありますか$r$持っている$a[r] \ge a[i]$、および開始位置の数による重み付け$i$。 その開始カウントは単純に$i$、いつからでも$l \le i$それが含まれます。 

したがって、各インデックスは以下に寄与します。$$\text{contribution}(i) = i \cdot \#\{r \ge i : a[r] \ge a[i]\}$$ここで、問題は、すべての位置について、その右側に出現する以上の要素がいくつあるかを数えるということになります。 これは、右から左にスキャンしながら、フェンウィック ツリーまたはセグメント ツリーを使用して実行できます。 

値を圧縮し (とにかく順列です)、表示された要素の数を維持します。 それぞれについて$i$、表示された値がいくつあるかをクエリします。$\ge a[i]$を追加します。$i \cdot \text{count}$。 次に挿入します$a[i]$。 

これにより問題は次のように縮小されます$O(n \log n)$。

 | --- | --- | --- | --- |

 | フェンウィック + リバーサル |$O(n \log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 値に対してフェンウィック ツリーを使用して、各テスト ケースを個別に処理します。$1$に$n$。 

1. フェンウィック ツリーをゼロで初期化します。 すでに処理された値の頻度を右から左に維持します。 これにより、「条件を満たす要素が右側にいくつあるか」を答えることができます。 
2. 反復する$i$から$n$まで$1$。 各ステップで私たちは治療します$a[i]$右端点がそれ以上にある将来のすべての部分配列の左境界として$i$。 
3. 少なくとも値を持つ要素の数についてフェンウィック ツリーをクエリします。$a[i]$。 これは、これまでに確認された合計からプレフィックスの合計を差し引いたものとして行われます。$a[i] - 1$。 この値はポジションの数を表します$r > i$満足する$a[r] \ge a[i]$。 
4.追加$i \times \text{query result}$答えに。 要因$i$それぞれのペアが表示されるため、$(i, r)$まさに含まれています$i$任意の位置から始まる部分配列$l \le i$。 
5.挿入$a[i]$をフェンウィック ツリーに追加して、将来の (より小さいインデックスの) 計算に使用可能としてマークします。 
6. すべてのインデックスが終了したら、累積された回答を出力します。 

### なぜ効果があるのか

 各インデックス$i$正しいエンドポイントの選択ごとに 1 回カウントされます$r$それが存在を通じて強さに貢献する場所$\le a[r]$。 固定ペアの場合$(i, r)$、要素$a[i]$まさに部分配列に含まれています$[l, r]$みんなのために$l \le i$。 まさにその通りです$i$サブアレイ。 フェンウィック ツリーは、有効な各ペアをカウントすることを保証します。$(i, r)$処理時に 1 回だけ$i$、カウントのみを行うため、無効なペアは含まれません。$a[r] \ge a[i]$。 これにより、元の定義の寄与とデータ構造によってカウントされた加重ペアとの間の 1 対 1 のマッピングが確立されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

    def range_sum(self, l, r):
        if r < l:
            return 0
        return self.sum(r) - self.sum(l - 1)

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        bit = Fenwick(n)
        ans = 0

        for i in range(n - 1, -1, -1):
            x = a[i]
            greater_eq = bit.range_sum(x, n)
            ans += (i + 1) * greater_eq
            bit.add(x, 1)

        print(ans)

if __name__ == "__main__":
    solve()
```フェンウィック ツリーは、右側にすでに表示されている値のカウントを維持します。 範囲クエリは、それらの値が少なくともいくつあるかを計算します。$a[i]$、必要な条件に一致します。 

の乗算$(i+1)$の代わりに$i$これは、実装内のインデックスが 0 から始まるため、有効な開始位置の数が$l$まさに$i+1$。

    from collections import deque

    class Fenwick:
        def __init__(self, n):
            self.n = n

                i += i & -i

            while i > 0:
                s += self.bit[i]
                i -= i & -i

 ## 特殊なケース

 次のような単一要素配列の場合$[1]$、インデックス 0 の処理時にはフェンウィック ツリーは空であるため、クエリはゼロを返しますが、寄与率は次のようになります。$1$なぜなら、要素はそれ自体の 1 つの部分配列を正確に形成するからです。 強度が 1 であるため、これは定義と一致します。 

厳密に増加する配列の場合$[1,2,3,4,5]$、各要素は、それ以降のすべての要素を有効な同等以上のパートナーとして認識します。 加工時$1$, 4 つの要素がカウントされ、大きく寄与しています。 フェンウィック ツリーは以前のインデックスが処理される前に将来のすべての値を蓄積するため、アルゴリズムはこれを正確に取得します。 

厳密に減少する配列の場合$[5,4,3,2,1]$の場合、後の要素はそれ以上の要素がないため、各クエリはゼロを返します。 インデックス重み付けによって処理される暗黙的な自己構造を除いて、すべての寄与はゼロになり、要素位置構造ごとに強度 1 を持つすべてのサブアレイと一致する最小の合計が得られます。
