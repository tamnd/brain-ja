 ## 解決策
 ## 問題の理解

 このタスクは、数値入力に正確な丸めルールを適用することを中心に展開します。 各入力値はテキスト形式で与えられ、標準的な丸め動作に従って整数に変換する必要があります。小数部分によって、値を上に移動するか下に移動するかが決まります。 

具体的には、各数値には小数部分が含まれる場合があります。 出力では、小数部が 0.5 未満の値は切り捨てられ、小数部が 0.5 以上の値は切り上げられるという規則に従って、最も近い整数に置き換える必要があります。 

計算の観点から見ると、このような問題に対する典型的な Codeforce 方式では、入力サイズは小規模から中程度であり、入力の各文字に対する線形スキャンで十分であることを意味します。 すべてのテスト ケースに最大 10^5 文字がある場合でも、シングル パス解析アプローチは時間制限内で問題なく維持されます。 

丸め問題における主なエッジ ケースは、小数境界がどのように処理されるか、および桁上げ伝播に近い整数部分がどのように動作するかによって決まります。 

最初の微妙なケースは、小数部がちょうど 0.5 の場合です。 たとえば、2.5 のような入力は 3 になる必要があります。0.5 を追加した後に切り捨てたりフロアしたりする単純な実装は、精度が正しく処理される場合にのみ機能します。 浮動小数点表現では、2.5000000001 が一貫性なく扱われるなどのエラーが発生する可能性があります。 

2 番目のケースは、7 などの小数点のない数値です。これらは変更されないままである必要があり、小数点が存在することを前提とする解析ロジックは失敗するか、例外がスローされます。 

3 番目のケースは大きな整数部分で、浮動小数点に変換すると精度が失われる可能性があります。 たとえば、999999999999.6 のような文字列は、すべての環境で安全に float として表すことができないため、文字列ベースの直接解析が必要です。 

## アプローチ

 素朴なアプローチは、各数値を浮動小数点値として解析し、言語の組み込み丸め関数を適用して、結果を出力することです。 丸めは標準ライブラリによって直接サポートされているため、これは概念的に機能します。 ただし、このアプローチは浮動小数点表現に依存しているため、大きな整数や境界線の小数値の精度の問題が発生します。 さらに、入力サイズが大きい場合、文字列と浮動小数点間の変換を繰り返すとボトルネックになる可能性があります。 

より堅牢なアプローチは、浮動小数点演算を完全に回避し、数値を文字列として処理することです。 このアイデアは、整数部分と小数部分を手動で分離することです。 小数部分が特定されたら、その最初の桁を検査して、整数部分をインクリメントするかどうかを決定します。 これにより、精度の問題が完全に回避され、問題は単純な文字列操作とキャリー処理に軽減されます。 

重要な点は、丸めは小数点以下の最初の桁にのみ依存するということです。 それ以降のすべては決定には無関係です。つまり、完全な小数値を数値的に解釈する必要はまったくありません。

 ## アルゴリズムのチュートリアル

1. 解析中に精度が失われないように、各入力数値を文字列として読み取ります。 これにより、すべての数字が指定されたとおりに正確に保存されます。 
2. 文字列に小数点が含まれているかどうかを確認します。 そうでない場合、その数値はすでに整数であるため、直接出力できます。 
3. 文字列を 2 つの部分に分割します。小数点の前の整数部分とその後の小数部分です。 この分離により、丸めに影響する部分のみが分離されます。 
4. 小数部の最初の桁を検査します。 「5」未満の場合は小数部をすべて破棄し、整数部をそのまま出力します。 
5. 最初の小数桁が「5」以上の場合、整数部分に 1 を加算する必要があります。 整数部分が大きい可能性があるため、文字列に手動で追加する必要があります。 
6. 整数部の下一桁からキャリー伝播による加算を行います。 すべての桁が「9」の場合、このキャリーにより桁数が 1 つ拡張される可能性があります。 
7. 結果の整数文字列を出力します。 

### なぜ効果があるのか

 正確かどうかは、最も近い整数への丸めが小数点の値が少なくとも 0.5 であるかどうかのみに依存するという事実に基づいています。 10 進数は、このしきい値の最初の小数桁で辞書編集的に一貫しているため、その桁のみをチェックするだけで十分です。 桁上げ演算は、オーバーフローや精度の損失なしに整数の増分を正確にシミュレートし、大きな入力であっても算術の指示どおりに正確に動作することを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def add_one(num: str) -> str:
    s = list(num)
    i = len(s) - 1
    carry = 1

    while i >= 0 and carry:
        if s[i] == '9':
            s[i] = '0'
            carry = 1
        else:
            s[i] = chr(ord(s[i]) + 1)
            carry = 0
        i -= 1

    if carry:
        s.insert(0, '1')

    return ''.join(s)

def round_number(x: str) -> str:
    if '.' not in x:
        return x

    integer_part, fractional_part = x.split('.')

    if fractional_part[0] < '5':
        return integer_part

    return add_one(integer_part)

def solve():
    data = sys.stdin.read().strip().split()
    out = []
    for x in data:
        out.append(round_number(x))
    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```実装は完全に文字列処理に依存しています。 ヘルパー関数`add_one`整数オーバーフローの想定を避けるために必要な手動インクリメントを実行します。 main 関数は、速度を上げるためにすべてのトークンを一度に読み取り、それぞれを個別に処理します。 

微妙な点は、完全な数値を整数型に変換しようとしていないことです。 一部の言語では制約によってネイティブの制限を超える非常に大きな整数が許可される場合があり、Python の任意精度は統一された競技プログラミングの説明に依存するものではないため、これは意図的なものです。

    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    def add_one(num: str) -> str:
        s = list(num)
        i = len(s) - 1
        carry = 1
        while i >= 0 and carry:
            if s[i] == '9':
                s[i] = '0'

 ## 特殊なケース

 クリティカルなエッジ ケースとは、整数部分が 9 だけで構成され、小数点以下の桁がキャリーをトリガーする数値です。 999.5 のような入力の場合、伝播後に整数は 1000 になります。 アルゴリズムは、すべての桁にキャリーを伝播し、必要に応じて新しい先頭の桁を挿入することでこれを処理します。 

もう 1 つのケースは、小数点のない入力です。 たとえば、1234 は変更しないでください。 「.」の存在をチェックします。 これらの値がすべての丸めロジックをバイパスするようにします。 

最後のケースは、0.0 や 0.9 などの最小の小数影響です。 0.0 では、最初の小数桁がしきい値を下回っているため、結果は 0 のままです。0.9 では、しきい値を超えて整数が 1 に増加し、両方の極値が正しく処理されていることを示しています。
