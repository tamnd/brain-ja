 ## 解決策
 ## 問題の理解

 各カメラは複数回ハッキングされる可能性があります。 2番目に実行されたハッキン​​グ`T`インターバル中にそのカメラを無効にします`[T + 1, T + s]`。 

重要なのは2回の盗難だけだ。 時間内に最初のダイヤモンドを盗みましょう`A`そして2回目`B`、 と`A < B`。 

最初のダイヤモンドを監視するカメラは、必ず無効にする必要があります`A`。 

2 番目のダイヤモンドを監視するカメラは、必ず無効にする必要があります`B`。 

両方のダイヤモンドを監視するカメラは、次のいずれかの間隔で無効のままにしておく必要があります。`A`に`B`または、盗難ごとに 1 回ずつ、計 2 回ハッキングされます。 

重要な観察は、最適なスケジュールにはアイドル時間が決して含まれないということです。 毎秒、ハッキングまたは 2 件の盗難のいずれかが発生します。 必要なハッキングの数がわかっていれば、答えは簡単です。```
(number of hacks) + 2
```なぜなら、2つの盗難自体にも秒数がかかるからです。 

制約は、ある次元では異常に小さく、別の次元では異常に大きくなります。 最大 1500 台のカメラがありますが、カメラの継続時間は最大でも`2n`期間範囲内の二次関数の解は許容されますが、カメラのサブセットに対する指数関数的な検索に似たものは不可能です。 

難しいのは、ハッキングのスケジュールを立てることではない。 どのカメラを 1 回のハッキングでカバーできるか、どのカメラを 2 回ハッキングする必要があるかを決定します。 

最初のダイヤモンドを監視しているすべてのカメラの継続時間が非常に短い場合、微妙なエッジ ケースが表示されます。```
1
1 1
```1 つ目のダイヤモンドはそのカメラを一度ハッキングすれば盗むことができますが、2 つ目のダイヤモンドは監視しているカメラがないため不可能です。 正しい答えは、`2`、 ない`-1`。 両方の盗難を同期させることにこだわるソリューションは、ここでは失敗します。 

もう 1 つの重要なケースは、両方のダイヤモンドを監視するカメラです。```
1
3 1
```1 つのハックだけでは十分ではありません。 カメラは 1 秒間だけ無効になりますが、2 回の盗難は異なる秒数で発生する必要があります。 正しい答えは、`4`、サンプルと一致します。 タイプ 3 カメラを 1 回のハッキングで両方のダイヤモンドを同時に満たすものとして扱うアプローチは、間違っています。 

3 番目の罠は、継続期間が長いほど常に良いと仮定することです。 一定の距離を保って盗難を防止するには、持続時間付きのタイプ 3 カメラを使用します。`x`1 つのハックでカバーできる場合もあれば、そうでない場合もあります。 決定は、選択した盗難間隔によって決まります。 

## アプローチ

 ブルートフォースアプローチでは、最初の盗難の可能なすべての瞬間、2 回目の盗難の可能なすべての瞬間、およびハッキングへのカメラの可能なすべての割り当てをシミュレートしようとします。 期間が最大 3000 であるという事実を利用した後でも、状態空間は膨大です。 タイプ 3 のカメラは、最初の盗難の前に 1 回、2 回目の盗難の前に 1 回、または 2 回ハッキングされる可能性があります。 このようなカメラが最大 1500 台ある場合、徹底的な検索は不可能です。 

ブレークスルーはギャップに焦点を当てることから生まれる```
len = B - A
```2つの盗難の間。 

この値を修正してください。 すべてのカメラを純粋に持続時間に従って分類できるようになりました。 

タイプ 1 カメラの場合、1 回のハッキングで最初の盗難をカバーする必要があります。 

タイプ 2 カメラの場合、1 回のハッキングで 2 回目の盗難をカバーする必要があります。 

少なくとも持続時間のあるタイプ 3 カメラの場合`len`、1 つのハッキングで両方の盗難をカバーできる場合があります。 その期間が以下の場合`len`、2つのハッキングは避けられません。 

固定後`len`、問題は実現可能性テストになります。 最初の盗難前と 2 回目の盗難の前に、利用可能な期間が必要なすべての位置をカバーできるかどうかを判断する必要があります。 

受け入れられたソリューションは、可能なすべての値を処理します。`len`。 以来`len`決して超えない`k₂ + k₃ + 1`、 のみ`O(n)`値を確認する必要があります。 値ごとに、範囲の追加と最大クエリをサポートするセグメント ツリーを使用して貪欲な割り当てが維持されます。 このツリーは、期間が期限として解釈される場合に生じるホールタイプの容量制約を検証します。 

結果として生じる複雑さはおおよそ次のようになります`O(n² log n)`に快適にフィットします。`n = 1500`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | 指数 | 遅すぎる |
 | 最適 | O(n² log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. カメラをタイプに応じて 3 つのグループに分割します。 
2. 各グループの継続時間を並べ替えます。 
3. 考えられるすべての値を列挙します。```
len = B - A
```から`1`に`k₂ + k₃ + 1`。 
4. 現在のところ`len`、各 Type-3 カメラを分類します。 

タイプ 3 カメラは、両方の盗難をカバーするために 1 回使用することも、2 つの独立した要件に変換することもできます。 貪欲な手順では、最初は 1 回のハッキングでできるだけ多くのタイプ 3 カメラを使用しようとします。 
5. 要件の 2 つのコレクションを維持します。 

左側の構造は、最初の盗難時にアクティブにする必要があるカメラを表しています。 

右側の構造は、2 回目の盗難時にアクティブにする必要があるカメラを表しています。 
6. すべてのデッドラインプレフィックスの中で最大の違反を格納するセグメントツリーを使用します。 

正の値は、一部のプレフィックスがスケジュールできるよりも多くのカメラを必要とすることを意味します。 非正の値は、現在の割り当てが実行可能であることを意味します。 
7. タイプ 2 カメラをスキャンします。 

スイープ中に、一部のカメラが右側から左側に移動します。 実現可能性が損なわれるたびに、貪欲な修復ステップにより、以前に共有されていた 1 台のタイプ 3 カメラが 2 回ハッキングされたカメラに変換されます。 
8. 左右両方の制約が実現可能で、盗難間のハッキング数が以下の場合`len`、ハッキングの合計数を計算します。 
9. この構成の答えは次のとおりです。```
n + extra
```ハッキングに加えて、2 つの盗難アクション。 
10. すべての値の最小値を取得します。`len`。 

### なぜ効果があるのか

 一定距離の場合`len`、すべてのカメラが期限タイプの制約に影響します。 セグメント ツリーは、期限のすべてのプレフィックスが満たされるかどうかを継続的にチェックします。 貪欲なルールでは、ハッキングの総数が最小限に抑えられるため、タイプ 3 のカメラを 1 回だけ使用することが常に好まれます。 実現可能性に違反した場合、対象となる最大の共有カメラを二重ハッキングされたカメラに変換することが、違反したプレフィックスを改善できる独自の修復です。 これは、古典的な期限スケジュールの問題に現れるのと同じ交換議論です。 

スイープはタイプ 2 カメラのすべての考えられる分布を調べ、外側のループは考えられるすべての盗難ギャップを調べます。 すべての実現可能なスケジュールは、アルゴリズムによって到達される 1 つの状態に正確に対応し、セグメント ツリーによって受け入れられるすべての状態は、実現可能なスケジュールに対応します。 したがって、報告される最小値が最適です。 

## Python ソリューション```python
import sys
from bisect import bisect_right
input = sys.stdin.readline

class SegTree:
    def __init__(self, sz):
        self.sz = sz
        self.tot = 0
        self.t = [0] * (4 * sz)
        self.lazy = [0] * (4 * sz)
        self._build(0, 0, sz)

    def _build(self, v, l, r):
        if l + 1 == r:
            self.t[v] = -l
            return
        m = (l + r) // 2
        self._build(v * 2 + 1, l, m)
        self._build(v * 2 + 2, m, r)
        self.t[v] = max(self.t[v * 2 + 1], self.t[v * 2 + 2])

    def _apply(self, v, x):
        self.t[v] += x
        self.lazy[v] += x

    def _push(self, v):
        if self.lazy[v]:
            x = self.lazy[v]
            self._apply(v * 2 + 1, x)
            self._apply(v * 2 + 2, x)
            self.lazy[v] = 0

    def _upd(self, v, l, r, ql, qr, x):
        if ql >= qr:
            return
        if l == ql and r == qr:
            self._apply(v, x)
            return
        self._push(v)
        m = (l + r) // 2
        self._upd(v * 2 + 1, l, m, ql, min(qr, m), x)
        self._upd(v * 2 + 2, m, r, max(ql, m), qr, x)
        self.t[v] = max(self.t[v * 2 + 1], self.t[v * 2 + 2])

    def upd(self, pos, x):
        self.tot += x
        self._upd(0, 0, self.sz, max(0, pos), self.sz, x)

    def _bad(self, v, l, r):
        if self.t[v] <= 0:
            return -1
        if l + 1 == r:
            return l
        self._push(v)
        m = (l + r) // 2
        if self.t[v * 2 + 1] > 0:
            return self._bad(v * 2 + 1, l, m)
        return self._bad(v * 2 + 2, m, r)

    def get_bad(self):
        return self._bad(0, 0, self.sz)

def solve():
    n = int(input())

    a = [[] for _ in range(4)]
    sz = 1

    for _ in range(n):
        t, s = map(int, input().split())
        a[t].append(s)
        sz = max(sz, s + 1)

    k = [0] * 4

    for t in range(1, 4):
        a[t].sort()
        k[t] = len(a[t])

    a[2].reverse()

    INF = 10000
    ans = INF

    for length in range(1, k[2] + k[3] + 2):
        L = SegTree(sz)
        R = SegTree(sz)

        used = []

        for x in a[1]:
            L.upd(x, 1)

        for x in a[2]:
            R.upd(x, 1)

        for x in a[3]:
            L.upd(x - length, 1)

            if L.t[0] <= 0:
                used.append(x - length)
            else:
                L.upd(x - length, -1)
                L.upd(x, 1)
                R.upd(x, 1)

        used.sort()

        for i in range(k[2] + 1):
            if L.t[0] <= 0 and R.t[0] <= 0 and R.tot + 1 <= length:
                ans = min(ans, n + (k[3] - len(used)) + 2)

            if i == k[2]:
                break

            x = a[2][i]
            R.upd(x, -1)
            L.upd(x - length, 1)

            while True:
                pos = L.get_bad()
                if pos == -1:
                    break

                idx = bisect_right(used, pos) - 1
                if idx < 0:
                    break

                v = used[idx]

                L.upd(v, -1)
                L.upd(v + length, 1)
                R.upd(v + length, 1)

                used.pop(idx)

    print(-1 if ans == INF else ans)

solve()
```セグメント ツリーには、最大プレフィックス違反が保存されます。 期間に対応する葉`d`最初に含まれています`-d`。 すべてのカメラが貢献します`+1`少なくとも、それをカバーするのに必要な期間と同じ長さのすべての期間に適用されます。 正の値は、一部の期限プレフィックスが過負荷でスケジュールできないことを意味します。 

変数`used`現在単一のハッキングの対象となっているタイプ 3 カメラが含まれています。 違反が発生した場合、貪欲な修復ステップにより、許容される最大の要素が削除されます。`used`そしてそのカメラを二重ハッキングされたカメラに変換します。 これはまさにリファレンス ソリューションで実行された遷移です。 

最もデリケートな実装の詳細は範囲の更新です。 元のソリューションは期間を解釈します`d`すべての接尾辞に寄与するものとして`[d, +∞)`。 サフィックスの更新を怠ると、実行可能性テストの意味が変わり、貪欲な不変条件が崩れます。
