 ## 解決策
 ## 問題の理解

 プロセスを逆に考えてみましょう。 

空のセットから始めて数字を挿入する代わりに、完全なセットから始めます。`{1,2,…,n}`1 つの数字だけが残るまで、繰り返し 1 つの数字を削除します。 

の後に書かれた文字は、`(i+1)`- 番目の挿入は、プロセスを元に戻すときに削除された番号に対応します。 

キャラクターが`>`、その後、逆のプロセスで現在の最大値を削除する必要があります。 

キャラクターが`<`の場合、現在の最小値を削除する必要があります。 

キャラクターが`?`の場合、最小値も最大値も削除する必要はありません。 

タスクは、可能な除去シーケンスの数を数えることです。これは、指定された文字列を生成する挿入順列の数を数えることとまったく同じです。 

制約こそが本当の課題なのです。 両方`n`そして`m`と同じくらい大きい`3·10^5`、更新のたびに回答を出力する必要があります。 答え全体を再計算するソリューション`O(n)`クエリごとのパフォーマンスはおおよそ`9·10^10`最悪の場合の操作は完全に不可能です。 周りに何かが必要です`O(1)`または`O(log n)`アップデートごとに。 

微妙なエッジケースがすぐに現れます。 

のために`n = 2`、数字は 2 つだけです。 最初の挿入後、2 番目の数値は常に新しい最小値または新しい最大値のいずれかになります。 あ`?`不可能です。 

例：```
n = 2
s = ?
```答え：```
0
```もう 1 つの簡単な間違いは、間違った貢献を`?`。 

考慮する：```
n = 4
s = <??
```最初`?`この時点では、有効な内部要素が 1 つだけ存在します。 2番目`?`は位置 3 で発生し、2 つの選択肢に影響します。 答えはそうではありません`2·3`、それは`1·2`。 

ポジション自体は要因ではありません。 因数は位置より 1 つ減ります。 

## アプローチ

 ブルートフォースソリューションでは、次のすべての順列が生成されます。`1..n`、挿入プロセスをシミュレートし、結果の文字列を構築し、ターゲット文字列に一致する順列の数をカウントします。 

これは定義に直接従っているため、正しいです。 残念ながら、それは必要です`n!`順列。 たとえ`n = 12`、これはすでに絶望的ですが、本当の限界は`3·10^5`。 

重要な観察結果は、プロセスを逆に行った後に表示されます。 

現在の設定サイズが`k`。 

次のキャラクターが`<`、最小限の要素を削除する必要があります。 選択肢はまさに 1 つです。 

次のキャラクターが`>`、最大の要素を削除する必要があります。 繰り返しますが、まさに 1 つの選択肢です。 

次のキャラクターが`?`、最小値でも最大値でもない要素を削除する必要があります。 現在のセット内容は、`k`要素があるので、`k-2`有効な選択肢。 

どの内部要素が選択されたかによって、後で起こることは何もありません。 すべての有効な選択により、同じ数の継続が行われます。 これは、有効なシーケンスの総数が単に各シーケンスの選択肢の数の積であることを意味します。`?`位置。 

元の文字列の位置に番号を付けます。`1`。 

位置を処理するとき`i`、逆プロセスでの現在の設定サイズは`i+1`。 

したがって、`?`位置にある`i`貢献する```
(i + 1) - 2 = i - 1
```選択肢。 

最初の位置は特別です:```
i = 1  =>  i - 1 = 0
```あ`?`有効なシーケンスがゼロであることを意味します。 

したがって、答えは次のとおりです```
0                              if s[1] = '?'
Π (i - 1) over all '?' at i>1  otherwise
```どのクエリでも 1 文字だけが変更されます。 この製品は動的に保守できます。 立場が変わるとき`?`、その寄与度を乗算します。 ポジションが存在しなくなったとき`?`、逆モジュラーを使用してその寄与度で除算します。

 ## アルゴリズムのチュートリアル

 1.読む`n`、`m`、および文字列`s`。 
2. 変数を維持する`ans`。 
3. ポジションごとに`i > 1`、 もし`s[i]`は`?`、乗算する`ans`による`(i-1)`モジュロ`998244353`。 
4. かどうかを示す別のフラグを維持します。`s[1]`は`?`。 
5. 現在の答えは次のとおりです。 

-`0`もし`s[1] == '?'`- さもないと`ans`。 
6. すべての値のモジュラー逆関数を事前計算します。`1`に`n`。 
7. 各クエリについて:

 1. 古いキャラクターの貢献を削除します。 
2.新キャラクターの貢献を追加します。 
3. 必要に応じて、特別な最初の位置を更新します。 
4. 現在の回答を出力します。 

### なぜ効果があるのか

 逆の処理では、現在設定されている位置のサイズが`i`まさに`i+1`。 

キャラクター`<`そして`>`固有の要素 (最小値または最大値) を強制的に削除します。 それらは次の要因に貢献します`1`。 

キャラクター`?`内部要素を取り外す必要があります。 の間で`i+1`要素、正確には`i-1`インテリアです。 すべての内部選択は同じタイプの将来の状態を残すため、有効なシーケンスの総数は次のように乗算されます。`i-1`。 

さまざまな位置での選択は独立した乗算係数であるため、合計数はすべての寄与の積になります。 唯一不可能なケースは、`?`位置にある`1`、インテリア要素がまったくありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

n, m = map(int, input().split())
s = list(input().strip())

inv = [1] * (n + 1)
for i in range(1, n + 1):
    inv[i] = pow(i, MOD - 2, MOD)

ans = 1

for i in range(1, n - 1):
    if s[i] == '?':
        ans = ans * i % MOD

def current_answer():
    if s[0] == '?':
        return 0
    return ans

out = [str(current_answer())]

for _ in range(m):
    pos, c = input().split()
    pos = int(pos) - 1

    if pos > 0:
        if s[pos] == '?' and c != '?':
            ans = ans * inv[pos] % MOD
        elif s[pos] != '?' and c == '?':
            ans = ans * pos % MOD

    s[pos] = c
    out.append(str(current_answer()))

sys.stdout.write("\n".join(out))
```変数`ans`すべての人の貢献の結果を保存します`?`最初のポジション以外のポジション。 

文字列は、ゼロから始まるインデックスを使用して保存されます。 インデックスの文字`pos`位置に対応する`pos + 1`声明の中で。 その貢献は、`(pos + 1) - 1 = pos`。 

そのため、更新では`pos`それよりも`pos + 1`。 

最初の文字は個別に処理する必要があります。 その寄与はゼロになるため、乗算の内部で表すことはできません。 常にゼロを出力するだけです`s[0] == '?'`。 

寄与分を削除するには除算モジュロが必要です`998244353`。 係数は素数なので、フェルマーの定理は次のようになります。```
x^(-1) = x^(MOD-2) mod MOD
```これにより、逆関数の事前計算後の定時間更新が可能になります。

 ## 特殊なケース

 次のことを考慮してください。```
n = 2
s = ?
```最初の文字で表される時点では、セットにはちょうど 2 つの要素が含まれています。 選択された要素はいずれも最小値または最大値のいずれかになります。 内部要素がないため、有効な選択肢の数はゼロです。 アルゴリズムはこれを即座に検出します。`s[1]`は`?`、および出力`0`。 

考慮する：```
n = 4
s = <??
```最初`?`位置にあります`2`、貢献`2-1 = 1`。 

2番目`?`位置にあります`3`、貢献`3-1 = 2`。 

答えは次のとおりです。```
1 × 2 = 2
```よくある間違いは、位置自体を乗算して次の値を取得することです。`2 × 3 = 6`。 逆プロセスの解釈により、内部要素の数は常に`set_size - 2`に等しい`i - 1`、 ない`i`。
