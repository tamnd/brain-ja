 ## 問題の理解

 整数が与えられます$n$そしてそれを 3 つの数値に分割し、その合計が正確に一致するようにする必要があります。$n$。 

3 つの数値は 3 つの条件を同時に満たさなければなりません。 それらはすべて正である必要があり、すべて異なるものでなければならず、どれも次の値で割り切れるものではありません。$3$。 

各テスト ケースについて、有効な構造を 1 つだけ見つける必要があります。 そのような構造が存在しない場合は、印刷します`NO`。 

アルゴリズムの観点から見ると、制約は非常に小さいです。 それでも$n$と同じ大きさにすることができます$10^9$までしかありません。$10^4$テストケース。 テスト ケースごとに一定量の作業を実行するソリューションは、事実上瞬時に実行されます。 検索空間はおおよそ次のように拡大するため、可能なトリプルに対する総当り検索は不可能です。$O(n^2)$またはさらに悪いことに、これに近い値ではまったく実行不可能です。$10^9$。 

難しいのは効率ではなく構築です。 

エッジケースの 1 つは次のような場合です$n$とても小さいです。 例えば：```
n = 4
```唯一の正の異なるトリプルの合計は、$4$次のような数字を使用する必要があります$(1,1,2)$またはその順列であり、明確ではありません。 正しい答えは、`NO`。 

もう 1 つの重要なケースは、残りの 3 番目の数が次の数で割り切れる場合です。$3$。 

私たちがいつも選択していると仮定しましょう$1$そして$2$最初の 2 つの数字として。 それから：```
n = 9
```生み出すだろう```
1 + 2 + 6 = 9
```しかし$6$で割り切れます$3$なので、この構造は無効です。 のみを使用するソリューション$(1,2)$すべての倍数で失敗します$3$。 

最後の微妙なケースは、3 番目の数字が選択した数字の 1 つと衝突する場合です。 

例えば：```
n = 6
```使用する$(1,2)$与える```
z = 3
```で割り切れるものは$3$。 

使用する$(1,4)$与える```
z = 1
```それは区別できません。 

正しい答えは、`NO`。 

## アプローチ

 ブルートフォースソリューションでは、すべてのトリプルを試行します。$(x,y,z)$と$$x+y+z=n,$$すべての数値が正であり、別個であり、次の数で割り切れないことを確認します。$3$、有効なトリプルが見つかったときに停止します。 

このアプローチは、あらゆる可能性を明示的に検査するため、正しいです。 問題は探索空間のサイズです。 修正さえ$z=n-x-y$、おおよそあります$O(n^2)$候補ペア$(x,y)$。 のために$n=10^9$、これはまったく不可能です。 

重要な点は、検索する必要がないということです。 有効な構築は 1 つだけ必要です。 

による割り算に関する制限$3$剰余を剰余とする小さな数を扱うことを提案します$3$が知られています。 

2 つのケースを考えてみましょう。 

もし$n$で割り切れない$3$、 選ぶ$$x=1,\qquad y=2.$$どちらの数も割り切れません$3$、そしてそれらは区別されます。 3番目の数字は$$z=n-3.$$以来$n \not\equiv 0 \pmod 3$、$$z \equiv n \pmod 3,$$それで$z$も割り切れません$3$。 

もし$n$で割り切れます$3$、前の構築は次の理由で失敗します。$z=n-3$も割り切れます$3$。 別のペアが必要です。 選ぶ$$x=1,\qquad y=4.$$それから$$z=n-5.$$なぜなら$n \equiv 0 \pmod 3$、$$z \equiv -5 \equiv 1 \pmod 3,$$それで$z$で割り切れない$3$。 

残っている唯一の作業はそれを確認することです$z$は正の値を保ち、選択した数値とは異なります。 これは、次のような小さな値の場合にのみ失敗します。$n=6$そして$n=9$、有効な答えはありません。

 ## アルゴリズムのチュートリアル

 1.読む$n$。 
2. もし$n \le 6$、印刷`NO`。 

3 つの異なる正の整数は、可能な最小和を持ちます。$$1+2+3=6.$$のために$n<6$解決策は不可能であり、$n=6$唯一の明確なトリプルは$(1,2,3)$の倍数が含まれる$3$。 
3. もし$n \bmod 3 \ne 0$、 選ぶ$$x=1,\quad y=2,\quad z=n-3.$$4. かどうかを確認します。$$z>2.$$これにより、積極性と明確さが保証されます。 
5. 印刷`YES`そしてトリプル。 
6. もし$n \bmod 3 = 0$、 選ぶ$$x=1,\quad y=4,\quad z=n-5.$$7. もし$$z\le4,$$印刷する`NO`。 

唯一問題となる倍数は、$3$より大きい$6$は$n=9$、それは与える$z=4$そして区別性を侵害します。 
8. それ以外の場合は印刷します`YES`そしてトリプル。 

### なぜ効果があるのか

 のために$n \not\equiv 0 \pmod 3$、建設$(1,2,n-3)$すべて非ゼロモジュロである数値を使用する$3$。 以来$n-3 \equiv n \pmod 3$、3 番目の数も次の数では割り切れません。$3$。 

のために$n \equiv 0 \pmod 3$、建設$(1,4,n-5)$機能するので$n-5 \equiv 1 \pmod 3$。 繰り返しますが、どの数値も割り切れません。$3$。 

唯一の失敗は、3 番目の数値が正でない場合、または選択した値の 1 つと等しくなった場合に発生します。 これらのケースは、まさにすでに拒否された小さな値です。 より大きな有効なケースはすべて、正しい構造を受け取ります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())

for _ in range(t):
    n = int(input())

    if n <= 6:
        print("NO")
        continue

    if n % 3 != 0:
        print("YES")
        print(1, 2, n - 3)
    else:
        z = n - 5

        if z == 1 or z == 4:
            print("NO")
        else:
            print("YES")
            print(1, 4, z)
```最初のブランチは、3 で割り切れない数値を処理します。 ペア$(1,2)$は固定され、残りの値は 3 で割り切れないように自動的に回避されます。 

2 番目のブランチは 3 の倍数を処理します。 ペア$(1,4)$モジュロを回避します-$3$最初の建設を壊す問題。 

唯一の特別な失敗は、$n=9$, ここで、3 番目の値は次のようになります。$4$、数字が区別できなくなります。 条件`z == 1 or z == 4`あらゆる問題のあるケースをキャッチします。 実際には、先ほどの後に、`n <= 6`チェックだけ`z == 4`発生する可能性があります。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())

        if n <= 6:
            out.append("NO")
            continue

        if n % 3 != 0:
            out.append("YES")
            out.append(f"1 2 {n - 3}")
        else:
            z = n - 5
            if z == 1 or z == 4:
                out.append("NO")
            else:
                out.append("YES")
                out.append(f"1 4 {z}")

    return "\n".join(out)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    return solve()

# provided sample
assert run("4\n10\n4\n15\n9\n") == (
    "YES\n1 2 7\n"
    "NO\n"
    "YES\n1 4 10\n"
    "NO"
)

# minimum value

# smallest valid non-multiple of 3

# smallest valid multiple of 3 after failure at 9

# maximum input
assert run("1\n1000000000\n") == "YES\n1 2 999999997"
