 ## 解決策
 ## 問題の理解

 私たちに数字が与えられているのは、$1$に$n$テストケースごとに、任意の 2 つの数値を繰り返し選択できます$x$そして$y$、それらを削除し、2 つの数値を追加します。$x+y$そして$|x-y|$。 目標は、合計をできるだけ小さく保ちながら、すべての数値を同じ値に変換することです。 すべての数値を等しくすることが不可能な場合は、次の値を返さなければなりません`-1`。 それ以外の場合は、これを達成する一連の操作を最長でも 1 以内に出力する必要があります。$20n$ステップ。 

入力できるサイズは、$n$まで$5 \cdot 10^4$テスト ケースごとの合計の合計$n$すべてのテスト ケースの境界も次のとおりです$5 \cdot 10^4$。 これは、$O(n \log n)$テスト ケースごとのアルゴリズムは許容されますが、二次関数は遅すぎる可能性があります。 

微妙な特殊なケースが発生します$n=2$, ここで数字は$1$そして$2$。 演算を適用すると次の結果が得られます$3$そして$1$、 それから$4$そして$2$、値は決して収束しません。 実際にはそれは不可能です$n=2$、その答えは次のようになります。`-1`。 もう一つのケースは次のような場合です。$n$は 2 の累乗です。 最適な戦略には、数値を階層的に組み合わせ、2 の次の累乗になるように数値を 2 倍にすることが含まれます。 これにより、等価性と最小和の両方が保証されます。 

## アプローチ

 ブルートフォース手法では、考えられる操作のすべてのペアをシミュレートし、すべての数値が等しくなるか、ステップ制限を超えるまでそれぞれを試行します。 原理的には正しいですが、可能性の数は爆発的に増加します。 各ステップで許可されるのは、$\binom{n}{2}$枝刈りを行ったとしても、状態の総数は指数関数的に増加します。 明らかに、これは不可能です$n$まで$5 \cdot 10^4$。 

重要な洞察は、操作自体を観察することから得られます。 ピッキング$x$そして$y$に置き換えます。$x+y$そして$|x-y|$、合計を保存します$x+y$プラス$|x-y| = 2 \cdot \max(x, y)$。 複数のステップにわたるこのプロセスは、2 のべき乗に達するまで数値を繰り返し 2 倍にするものとして解釈できます。 もし$n$はすでに 2 のべき乗であるため、貪欲に数値を組み合わせて、次に高い 2 のべき乗の均一な値に到達することができます。 それ以外の場合は、ゼロを導入する (またはゼロを模倣する方法で効果的に結合する) ことでシーケンスを「パディング」し、2 の累乗カウントに達することをシミュレートできます。 これにより、問題は同じ値の数値を繰り返し組み合わせるという問題に変換されます。 

最適なソリューションは、操作の記録を維持しながら、数値を段階的に組み合わせ、同じ現在値の数値をペアにして、次に高い値を作成します。 この戦略では、各数値が不均等な加算ではなく 2 倍の繰り返しによって増加するため、最小合計が保証されます。

 ## アルゴリズムのチュートリアル

 1. 以下の 2 の最小のべき乗を計算します。$n$、それを次のように表します$k = 2^{\lceil \log_2 n \rceil}$。 これにより統一目標数が決まります。 
2. もし$n=2$、すぐに戻ります`-1`。 どの組み合わせでも、次から始まる 2 つの等しい数値が生成されることはありません。$1$そして$2$。 
3. マルチセットを数値で初期化する$1$を通して$n$。 正確に到達するには$k$階層ペアリングの要素を追加することを検討してください。$k-n$概念的にはゼロ。 これらのゼロは、ペアリングを簡素化するためのプレースホルダーとして機能します。 
4. 同じ値の数字を繰り返しペアにします。 各ペアごとに$(x, x)$、操作を適用して生成します$(2x, 0)$。 この操作を記録します。 これにより、ゼロ以外の数値はすべて 2 の累乗であるという不変条件が維持されます。 
5. すべてのペアを処理した後、数字が残っている場合は、制御された方法でそれらをゼロと組み合わせて 2 の累乗を形成し、ゼロ以外の数字が 1 つだけ残るまで続けます。 各操作を記録します。 
6. 操作の合計数と操作の順序を出力します。 

機能する理由: 各演算では、数値が 2 倍になるか、ゼロが導入されます。 同じ値の数値をペアにすることで、どの数値も他の数値より早く増加することがなくなり、均一な数値が生成されます。 ゼロを使​​用すると、要素の合計数が 2 の累乗のままになり、階層ペアリングが可能になります。 時期尚早に大きな数値を作成することを避けるため、最小の合計が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(n):
    if n == 2:
        print(-1)
        return
    
    # Find the next power of two
    k = 1
    while k < n:
        k <<= 1
    
    numbers = list(range(1, n + 1))
    ops = []
    
    # Stage 1: bring numbers up to powers of two
    from collections import deque
    q = deque(numbers)
    
    while len(q) < k:
        q.append(0)
    
    # Stage 2: combine equal numbers
    power_dict = {}
    
    while True:
        counts = {}
        for x in q:
            if x == 0: continue
            counts[x] = counts.get(x, 0) + 1
        
        max_val = max(counts.keys(), default=0)
        if len(counts) == 1 and list(counts.values())[0] == k:
            break
        
        new_q = []
        used = set()
        for x in q:
            if x in used or x == 0:
                new_q.append(x)
                continue
            if counts[x] >= 2:
                ops.append((x, x))
                new_q.append(2*x)
                new_q.append(0)
                counts[x] -= 2
                used.add(x)
            else:
                new_q.append(x)
        q = new_q
    
    print(len(ops))
    for a, b in ops:
        print(a, b)

def main():
    t = int(input())
    for _ in range(t):
        n = int(input())
        solve_case(n)

if __name__ == "__main__":
    main()
