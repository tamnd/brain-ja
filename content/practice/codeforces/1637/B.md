 ## 解決策
 ## 問題の理解

 整数の配列が与えられ、そのすべてのサブセグメントの「値」の合計を計算するように求められます。 サブセグメントは、配列の連続したスライスです。 サブセグメントの値は、そのサブセグメントのパーティションの最大コストとして定義されます。 パーティションはサブセグメントを要素の連続グループに分割し、そのコストはグループの数に各グループの MEX (最小除外非負整数) の合計を加えたものになります。 

たとえば、サブセグメントが`[0, 1]`、その最適なパーティションは`[0, 1]`その MEX は次のとおりであるため、単一のグループとして扱われます。`2`そしてパーティションには`1`セグメント、コストを与える`3`。 に分割すると`[0]`そして`[1]`、MEX 値は次のとおりです。`1`そして`0`、2 つのセグメントがあるため、コストは次のようになります。`3`同じように。 どちらのパーティションでも同じコストがかかります。 このタスクでは、各テスト ケースのすべてのサブセグメントにわたるこの最大コストを合計するように求められます。 

制約は小さく、各配列の要素数は最大 100 個で、すべてのテスト ケースの長さの合計は 100 以下です。 これにより、すべてのサブセグメントを O(n²) 時間で検査するソリューションを検討することができます。 配列要素の値は非常に大きくなる可能性があります (最大 10^9) が、MEX は 0 から始まる個別の非負の整数にのみ依存します。この観察は、最適化にとって非常に重要です。 

配列要素がいくつかの小さな整数をスキップすると、明らかではないエッジ ケースが発生します。 たとえば、`[3, 5]`、メキシコは`0`すべての要素がポジティブであるにもかかわらず。 を想定した素朴なアプローチ`MEX = max + 1`ここで失敗するだろう。 同様に、要素が繰り返されると、最適なパーティションの選択に影響を与える可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、すべてのサブセグメントが明示的に生成されます。 各サブセグメントについて、考えられるすべてのパーティションを試し、そのコストを計算し、最大値を取得することができます。 長さのパーティションの数`k`指数関数的です(`2^(k-1)`)、したがって、`n=100`、これは絶望的です。 

重要な観察は、これまでに観察された要素の MEX を使用して、セグメントの最大コストを貪欲に計算できることです。 新しい要素を追加しても、セグメントの MEX は減少しません。これは、MEX が出現する小さな数値にのみ依存するためです。 最初に欠落している非負の整数がわかったら、セグメントを拡張してもその MEX を下げることはできません。 これにより、小さな数値の頻度カウントを維持しながら、動的プログラミング アプローチまたはすべてのサブセグメントにわたる単純な列挙が可能になります。`n+1`(長さ ≤100 のセグメントで可能な最大 MEX は ≤101 であるため)。 

すべてのサブセグメントを列挙するという考え方です`[i..j]`。 サブセグメントごとに数値のカウンターを維持します`0..n+1`そして、MEX を段階的に計算します。 サブセグメントの最大コストは貪欲に計算できます。現在の MEX がこれ以上増加できない場合は常に新しいセグメントを開始し、その値を総コストに追加します。 以来`n`小さいため、すべてのサブセグメントを反復し、カウンターを最大サイズに維持します`n+1`許容されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースパーティション | O(2^n * n^2) | O(n^2) | 遅すぎる |
 | MEX 追跡を使用してサブセグメントを列挙する | O(n³) 最悪の場合 | O(n) | n ≤ 100 の場合は受け入れられます |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る`t`。 
2. 各テスト ケースについて、次の内容を読んでください。`n`そして配列`a`。 
3. 変数を初期化する`total_sum = 0`すべてのサブセグメントの合計を累積します。 
4. すべての開始インデックスを反復処理します。`i`から`0`に`n-1`。 
5. それぞれについて`i`、周波数配列を初期化します`freq`長さの`n+2`(サブセグメント内の要素 0..n+1 をカウントするため) および`current_cost = 0`。 
6. 終了インデックスを反復処理する`j`から`i`に`n-1`:

 1. もし`a[j] ≤ n`、増分`freq[a[j]]`。 
2. 最小値を見つけて現在のセグメントの MEX を計算します。`k`そのような`freq[k] = 0`。 
3. 辞書を管理する`segment_counts`貪欲な分割の現在の候補セグメントに各数値が何回出現するかを追跡します。 
4. 現在の MEX が潜在的な最大値 (≤ n+1) に達するたびに、ここでセグメントを終了することを検討します。`1 + MEX`に`current_cost`、そしてリセット`freq`次のセグメントに向けて。 
7.延長後`j`、 追加`current_cost`に`total_sum`。 
8. すべてのサブセグメントを処理した後、印刷します。`total_sum`。 

これが機能する理由は、セグメントでは、最大 MEX が数値の存在によって決定されるためです。`0..n`。 これらの小さな数値の頻度を数え、現在の MEX に達するたびに新しいセグメントを開始することで、そのセグメントが可能な限り最高のコストに寄与することを保証します。 各サブセグメントは独立して処理されるため、それらを合計すると必要な答えが得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        total_sum = 0
        
        for i in range(n):
            freq = [0] * (n + 2)
            current_cost = 0
            for j in range(i, n):
                if a[j] <= n:
                    freq[a[j]] += 1
                mex = 0
                while freq[mex] > 0:
                    mex += 1
                total_sum += mex + 1  # count the single segment [i..j]
        print(total_sum)

if __name__ == "__main__":
    solve()
```このソリューションでは、すべてのサブセグメントを反復します`[i..j]`数値の頻度配列を維持します`0..n`。 MEX の計算は高速です。`n`小さいです。 追加します`mex + 1`単一のセグメントとみなされるすべてのサブセグメントが最大の MEX 寄与を与えるため、各サブセグメントを直接使用できます (小規模なセグメントでは、さらに分割してもコストは増加しません)`n`）。
