 ## 解決策
 ## 問題の理解

 配列があり、操作を 1 つだけ実行する必要があります。 配列を 2 つの空でない部分に分割する位置を選択します。 次に、左側の部分と右側の部分を個別に並べ替えます。 問題は、最終的な配列全体がまだソートされていないような分割が存在するかどうかです。 

テストケースごとに、次のことに答える必要があります。`"YES"`少なくとも 1 つの分割によりソートされていない配列が生成される場合、および`"NO"`可能なすべての分割でグローバルにソートされた配列が生成される場合。 

すべてのテスト ケースの要素の合計数は次のとおりです。$10^4$したがって、二次アルゴリズムでも問題なく制限内に収まります。 つまり、ここではパフォーマンスが実際の課題ではないということです。 難しいのは、操作の内部に隠された構造を認識することです。 

簡単な間違いの 1 つは、両方の部分を別々にソートすると常にソートされた配列が生成されると考えることです。 考慮する```
3
2 2 1
```最初の要素の後に分割を選択すると、```
[2] + [2,1]
```各面を並べ替えた後:```
[2] + [1,2]
```になる```
[2,1,2]
```そしてソートされていません。 正しい答えは、`"YES"`。 

不注意な解決策を誤解させる可能性があるもう 1 つの状況は、既にソートされた配列です。```
5
1 2 2 4 4
```どこで分割しても、左側の最大要素が右側の最小要素を超えることはありません。 結果として得られる配列はすべてソートされたままとなるため、答えは次のようになります。`"NO"`。 

重複にも注意が必要です。 例えば、```
4
1 3 3 2
```3 番目の要素の後で分割すると、```
[1,3,3] + [2]
```並べ替え後は何も変わりません。```
[1,3,3,2]
```それはまだ整理されていません。 値が等しいことは無害であり、厳密な反転のみが問題となります。 

## アプローチ

 直接的なアプローチでは、可能な限りあらゆる分割を試みます。 位置ごとに、プレフィックスとサフィックスを個別にソートし、それらを連結して、配列全体がソートされているかどうかを確認します。 がある$n-1$可能な分割点があり、試行ごとに 2 つのソートと 1 つの線形チェックが実行されます。 最悪のケースはおおよそ$O(n^2 \log n)$。 と$n\le10^4$、これでも問題はありませんが、必要以上の作業が実行されます。 

ブルートフォースが機能する理由は、各部分を並べ替えた後、無秩序が残る可能性がある唯一の場所が 2 つの部分の間の境界であるためです。 各ピースの内部では、すべてがすでに分類されています。 

ポジション後に分割したとします$i$。 ソート後、左側の部分は最大の要素で終わり、右側の部分は最小の要素で始まります。 配列全体は、次の場合に正確にソートされます。$$\max(\text{left}) \le \min(\text{right})$$代わりに$$\max(\text{left}) > \min(\text{right}),$$この場合、これら 2 つの境界要素は反転を作成し、最終的な配列はソートされません。 

次に、さらに単純なことを観察してください。 元の配列に反転が含まれている場合$a_i>a_j$と$i<j$次に、これらの位置の間で分割を行うと、大きい値が左半分のどこかに配置され、小さい値が右半分のどこかに配置されます。 内部でソートした後、左半分には最大値の一部として大きい値が含まれ、右半分には最小値の一部として小さい値が含まれるため、境界は反転したままになります。 

つまり、答えは`"YES"`まさに、元の配列自体がソートされていないときです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n² log n) | O(n) | 受け入れられるが不要 |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を読み取ります。 
2. 非減少配列は次の条件を満たす必要があるため、隣接するペアを左から右にスキャンします。$a_i\le a_{i+1}$どこでも。 
3. 隣接するペアのいずれかが満足する場合$a_i>a_{i+1}$、配列にはすでに反転が含まれています。 出力`"YES"`。 

これら 2 つの要素間の分割を選択すると、左の最大値が右の最小値よりも大きくなるため、単一の隣接する反転で十分です。 

1. そのようなペアが存在しない場合、配列はすでに非降順でソートされています。 出力`"NO"`。 

### なぜ効果があるのか

 ソートされた配列は、プレフィックスとサフィックスを個別にソートした後もソートされたままになります。 逆に、元の配列に反転が含まれている場合は、隣接する反転も存在する必要があります。 これら 2 つの要素を分割すると、大きい値が左半分に残り、小さい値が右半分に残ります。 それぞれの側を並べ替えても、この境界を越えた逆転を取り除くことはできません。 したがって、この操作ではソートされていない配列が生成されます。 これら 2 つの事実は、答えを完全に特徴づけます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())

for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))

    ok = False
    for i in range(n - 1):
        if a[i] > a[i + 1]:
            ok = True
            break

    print("YES" if ok else "NO")
```すべての未ソート配列には少なくとも 1 つの隣接する反転が含まれるため、隣接する要素に対するループで十分です。 そのようなペアが見つかったら、目撃者は 1 人で十分なので、すぐに停止できます。 

この実装では、不必要なソートが回避され、一定の追加メモリのみが使用されます。 ループは以下から実行されるため、境界条件は単純です。`0`に`n-2`、作る`a[i+1]`常に有効です。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        ok = False
        for i in range(n - 1):
            if a[i] > a[i + 1]:
                ok = True
                break

        out.append("YES" if ok else "NO")

    return "\n".join(out)

# provided samples
assert run(
"""3
3
2 2 1
4
3 1 2 1
5
1 2 2 4 4
"""
) == """YES
YES
NO"""

# minimum size, increasing
assert run(
"""1
2
1 2
"""
) == "NO", "already sorted"

# minimum size, decreasing
assert run(
"""1
2
2 1
"""
) == "YES", "single inversion"

# all equal values
assert run(
"""1
5
7 7 7 7 7
"""
) == "NO", "duplicates are allowed"

# inversion near the end
assert run(
"""1
5
1 2 3 5 4
"""
) == "YES", "boundary inversion"

# maximum-size style case
assert run(
"1\n10000\n" + " ".join(map(str, range(1, 10001))) + "\n"
) == "NO", "large sorted array"

 |`[2,1]`| はい | 反転時の最小サイズ |
 |`[7,7,7,7,7]`| いいえ | 等しい値は有効です |
