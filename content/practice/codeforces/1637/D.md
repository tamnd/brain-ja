 ## 解決策
 ## 問題の理解

 同じ長さの 2 つの配列があります。 すべてのポジションについて、ペアをそのまま維持することも、そのポジション内の 2 つの数字を交換することもできます。 すべてのインデックスに対してこれを独立して決定した後、両方の配列が新しい値を取得します。 

各配列について、順序のない位置のペアはすべて、対応する要素の合計の 2 乗に寄与します。 目的は、両方のアレイにわたるペアごとのコストの合計ができるだけ小さくなるようにスワップを選択することです。 

各配列の長さは最大 100 であり、すべてのテスト ケースの長さの合計も最大 100 です。各要素は最大 100 であるため、1 つのテスト ケース内のすべての数値の合計は 20000 を超えることはできません。これらの境界は合計に対する動的プログラミングには十分小さいですが、すべてのスワップ パターンを試行することは完全に除外されます。$2^n$考えられる選択肢。 と$n=100$、その数は天文学的な数字です。 

簡単な間違いの 1 つは、各ポジションに個別に焦点を当てることです。 考慮する```
n = 2
a = [1, 100]
b = [100, 1]
```どのように交換しても、1 つの配列には 1 と 100 が 1 つずつ含まれるため、答えは固定されます。 相互作用は位置のペア間で発生するため、インデックスを個別に調べても有益な情報は得られません。 

エラーのもう一つの原因は次のとおりです$n=1$:```
1
3
6
```ペアがまったく存在しないため、両方のコストはゼロとなり、答えは次のようになります。```
0
```すべての要素が正の多重度で関与していると仮定する式では、誤ってゼロ以外の値が生成されます。 

さらに微妙な問題は、1 つの配列の合計を最小化するだけでは十分ではないことです。 例えば、```
a = [1, 10]
b = [9, 2]
```一方の配列をできるだけ小さくすると、もう一方の配列が大きくなる可能性があります。 正しい目的は両方の配列に同時に依存するため、最終的にはパーティションの問題になります。 

## アプローチ

 最も直接的なアプローチは、すべてのスワップ パターンを列挙することです。 各インデックスには、保持またはスワップという 2 つの選択肢があります。$2^n$可能性。 各構成について、両方のコストを次のように計算できます。$O(n^2)$すべてのペアが一度ずつ貢献するため、時間がかかります。 全体的な複雑さは次のようになります。$O(2^n n^2)$。 

のために$n=100$、これはおおよその意味です$$2^{100}\cdot 10^4$$まったく実行不可能な操作です。 

重要な観察は、二次式が並べ替えられるということです。 1 つの配列の場合、$$\sum_{i<j}(x_i+x_j)^2$$に拡大します$$(n-1)\sum x_i^2 + 2\sum_{i<j}x_ix_j.$$両方の配列に対応する式を追加すると、次のようになります。$$(n-1)\sum (a_i^2+b_i^2) + 2\left(\sum_{i<j}a_ia_j+\sum_{i<j}b_ib_j\right).$$スワップによって各ペア内の数値のマルチセットが変更されないため、最初の部分は定数です。 

クロスタームのみが重要です。 もし$$S_a=\sum a_i,\qquad S_b=\sum b_i,$$それから$$\sum_{i<j}a_ia_j=\frac{S_a^2-\sum a_i^2}{2},$$そして同様に$b$。 二乗和はすでに固定されているため、答えを最小化することは、次のことを最小化することになります。$$S_a^2+S_b^2.$$すべてのインデックスは次のいずれかに寄与します$a_i$または$b_i$に$S_a$。 したがって、最初の配列のどの合計が達成可能であるかを知る必要があるだけです。 これは部分集合和動的計画法の問題になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(2^n n^2)$|$O(1)$| 遅すぎる |
 | 最適 |$O(n\cdot \Sigma)$|$O(\Sigma)$| 承認済み |

 ここ$\Sigma$は、最大 20000 までのすべての数値の合計を示します。 

## アルゴリズムのチュートリアル

 1. コンピューティング$$\text{base}=(n-1)\sum_{i=1}^n(a_i^2+b_i^2).$$答えのこの部分は、スワップに関係なく決して変わりません。 

1. しましょう$$T=\sum a_i+\sum b_i.$$最初の配列の最終合計が$x$の場合、2 番目の配列には自動的に sum が入ります。$T-x$。 

1. 部分集合和動的計画法を実行します。 最初は合計 0 のみに到達可能です。 
2. インデックスごとに$i$、以前の合計の場合$s$に到達可能であれば、このインデックスを処理した後、到達する可能性があります$$s+a_i$$または$$s+b_i.$$各位置は、最初の配列に正確に 1 つの数値を与えます。 

1. すべてのインデックスが処理された後、到達可能なすべての合計を調べます$x$。 
2. それぞれの合計について、次のように計算します。$$x^2+(T-x)^2.$$最小値を維持してください。 

1. 合計の答えは次のとおりです$$(n-1)\sum(a_i^2+b_i^2)+\min(x^2+(T-x)^2).$$### なぜ効果があるのか

 交換によって数値自体が変更されることはないため、インデックスの各ペアについて、個々の要素の 2 乗に関係する項は固定量に寄与します。 唯一の変数部分は、2 つの配列の合計に依存します。 

動的プログラミングでは、任意のスワップ後の最初の配列の合計の取り得るすべての値を正確に列挙します。 実行可能なすべての金額に対して$x$、2 番目の配列の合計は強制的に次のようになります。$T-x$。 すべてのスワップ パターンは 1 つの到達可能な合計に対応し、すべての到達可能な合計はあるスワップ パターンに対応するため、すべての到達可能な合計を検索すると、最小値が見つかることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())

for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    total = sum(a) + sum(b)

    base = 0
    for i in range(n):
        base += (a[i] * a[i] + b[i] * b[i]) * (n - 1)

    dp = [False] * (total + 1)
    dp[0] = True

    for i in range(n):
        ndp = [False] * (total + 1)
        for s in range(total + 1):
            if dp[s]:
                ndp[s + a[i]] = True
                ndp[s + b[i]] = True
        dp = ndp

    best = 10**18

    for s in range(total + 1):
        if dp[s]:
            cur = s * s + (total - s) * (total - s)
            if cur < best:
                best = cur

    print(base + best)
```最初のループは式の不変部分を計算します。 乗算$n-1$すべての要素が正確に関与しているため、機能します$n-1$ペア。 

動的プログラミング配列は、最初の配列の到達可能な合計を表します。 新鮮な配列`ndp`インデックスごとに作成されます。 同じ配列を再利用すると、現在の要素が複数回カウントされ、無効な状態が生成される可能性があります。 

合計が 20000 を超えることはないため、配列サイズは小さいままです。 Python の整数には制限がないため、オーバーフローは問題になりませんが、C++ では 64 ビット型が必要になります。 

到達可能な合計に対する最終スキャンでは、合計の可能なすべての分割を 2 つの配列に評価し、最小の二次寄与を選択します。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    ans = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        total = sum(a) + sum(b)

        base = 0
        for i in range(n):
            base += (a[i] * a[i] + b[i] * b[i]) * (n - 1)

        dp = [False] * (total + 1)
        dp[0] = True

        for i in range(n):
            ndp = [False] * (total + 1)
            for s in range(total + 1):
                if dp[s]:
                    ndp[s + a[i]] = True
                    ndp[s + b[i]] = True
            dp = ndp

        best = 10**18

        for s in range(total + 1):
            if dp[s]:
                best = min(best, s * s + (total - s) * (total - s))

        ans.append(str(base + best))

    return "\n".join(ans)

 ## 特殊なケース

 検討してください```
1
1
3
6
```DP は合計 3 と 6 に達します。$n-1=0$、一定の貢献は消滅します。 ペアがないため、答えは 0 になります。アルゴリズムは、特別な分岐を行わずにこのケースを自然に処理します。 

考慮する```
1
2
1 100
100 1
```到達可能な合計は 2、101、および 200 です。合計 101 は最小の 2 次式を生成します。 どちらのスワップ構成でも、1 が 1 つと 100 が 1 つ含まれる配列になるため、答えは決まります。 複数の構成が同じ合計にマップされる可能性があるため、DP はこれをキャプチャします。 

考慮する```
1
3
4 4 4
4 4 4
```スワップに関係なく、すべてのインデックスは 4 に寄与します。 到達可能な合計は 12 のみです。このアルゴリズムは、同等の構成を区別するために無駄な労力を費やすことなく、一意の答えを即座に計算します。 これにより、過剰なカウントが防止され、重複した値が無害であることが確認されます。
