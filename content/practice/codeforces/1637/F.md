 ## 解決策
 ## 問題の理解

 私たちは、各頂点が高さの値を持つツリーに取り組んでいます。 タスクは、一連の「タワー」を頂点に配置し、各タワーに正の整数の効率を割り当てることです。 タワーにはその効率が反映されるため、総コストを最小限に抑えるには、効率とタワーの数を最小限に抑える必要があります。 

両方のタワーが少なくとも頂点の高さ以上の効率を持ち、頂点がそれら 2 つのタワー間の固有のツリー パス上にあるような 2 つのタワーを見つけることができた場合、頂点は「アクティブ化」されます。 直観的には、頂点は、ツリー構造に沿って十分に強い 2 つの塔の間に「挟まれる」ことができれば満たされます。 

目標は、タワー効率の合計を最小限に抑えながら、すべての頂点が確実にアクティブ化されるようにすることです。 

制約$n \le 2 \cdot 10^5$二次関数はすべて除外します。 どのソリューションも本質的に線形または線形演算的である必要があり、通常はツリー DP または DSU ベースの構造を使用します。 

重要な点は、タワーの頂点ごとの数に制限がなく、効率が頂点の高さに依存しないことです。 このため、個々のノードについて貪欲に考えたくなる誘惑にかられますが、要件はグローバルであり、構造全体にわたる決定を結合するツリー パスに依存します。 

よくある落とし穴は、すべての頂点が 2 つの頂点間のパス上にあるため、2 つのタワーが自動的にすべてをカバーすると仮定することです。 これは誤りです。なぜなら、この要件は、どのタワーが「十分に強い」かどうかと相互作用する頂点の高さのしきい値に依存するからです。 

もう 1 つの微妙な問題は、地元の報道のみが重要であると考えていることです。 実際には、パス条件が満たされている限り、頂点は遠くにある塔によってのみカバーされる可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、頂点のサブセットをタワーとして選択し、効率を割り当て、すべての頂点が選択された 2 つのタワー間の有効なパス上にあるものとして表現できるかどうかを確認します。 タワーの位置のセットを修正したとしても、固定効率しきい値のカバレッジを検証するには、タワーのすべてのペアを考慮する必要があります。$O(k^2 n)$最悪の場合の -type の動作。 塔のサブセットの数は指数関数的なので、このアプローチは明らかに実行不可能です。 

重要な構造的洞察は、視点を逆転させることです。 頂点をカバーするタワーのペアについて考えるのではなく、高さのしきい値の観点から条件を再解釈します。 

値を修正する$t$。 高さ以下の頂点のみを考慮します$t$。 上位の頂点をすべて削除するため、これらの頂点はフォレストを形成します。 頂点にとってそれが何を意味するかを観察してください$x$と$h_x \le t$レベルでカバーされる$t$。 少なくとも効率の良いタワーが 2 つ必要です$t$そして重要なことに、それらの間のパスは最大でも頂点の高さ内に完全に収まらなければなりません。$t$そうでない場合、信号はより高い頂点によってブロックされます。 

したがって、あらゆる閾値で$t$、高さを持つ頂点の誘導サブグラフの各連結コンポーネント内$\le t$、そのコンポーネント内にあり、少なくとも効率性のある少なくとも 2 つのタワーが必要です。$t$。 

これにより、問題はしきい値の増加に伴う動的なプロセスに変換されます。 上げるにつれて$t$、コンポーネントがマージされるため、現在のすべてのコンポーネントに少なくとも 2 つの「アクティブなタワー」があることを維持する必要があります。 

このための自然なツールは、高さによってソートされた頂点に対する DSU です。 高さの昇順に頂点をアクティブ化すると、接続されたコンポーネントが維持されます。 各コンポーネントは、含まれる選択されたタワーの数を常に追跡する必要があります。 コンポーネントが形成または結合されるときは常に、少なくとも 2 つのタワーがあることを確認し、コンポーネント内の最小の高さの頂点が最も安価であるため貪欲に選択します。 

貪欲な構造が機能するのは、コンポーネントで頂点が使用可能になると、その選択を遅らせると、後でコンポーネントがマージされるときにさらに高価なものを選択せざるを得なくなるからです。

 ## アルゴリズムのチュートリアル

 1. すべての頂点を高さの増加順に並べ替えます。 現在のフォレスト内で頂点が使用可能になるときの「時間」として高さを扱い、この順序で頂点をアクティブ化します。 
2. 頂点全体で DSU 構造を維持します。 最初は、各頂点は独自のコンポーネントです。 各コンポーネントに加えて、複数セットの候補タワー コストを維持します。これは、単純にコンポーネント内の現在の頂点の高さです。 
3. 頂点がアクティブ化されると、それを DSU 構造に挿入し、すでにアクティブな隣接頂点とマージします。 マージ後、現在のしきい値領域を表す連結成分が得られます。 
4. 各コンポーネントについて、少なくとも 2 つの選択されたタワーがあることを確認する必要があります。 より大きな高さを選択しても将来のマージが改善されることはないため、コンポーネント内で利用可能な最小の高さから常にタワーを貪欲に選択します。 
5. マージ中に、2 つのコンポーネントの候補リストを結合します。 マージされたコンポーネントに含まれるタワーの数が 2 つ未満の場合は、要件が満たされるまでマージされたプールから高さの昇順で追加の頂点を選択します。 
6. 選択した頂点を塔として永続的にマークし、その高さを答えに累積します。 タワーを選択すると、その後のすべてのしきい値に対して引き続き使用できます。 
7. すべての頂点が処理されるまで続行します。 選択したすべてのタワーの高さの合計が最終的な答えになります。 

### なぜ効果があるのか

 DSU プロセスは、高さのしきい値の増加をシミュレートします。 どの瞬間においても、各接続コンポーネントは、すべての頂点の高さが現在のしきい値によって制限される最大領域に正確に対応します。 コンポーネントごとに 2 つのタワーという要件は、まさに、そのコンポーネント内のすべての頂点が、パスがコンポーネント内に留まる 2 つの有効なエンドポイントを見つけるために必要な条件です。 利用可能な最小の頂点を貪欲に選択するのが最適です。将来のすべての制約は、少なくとも 2 つの代表が存在することのみに依存し、コストを最小限に抑えること以外にどの特定の頂点が選択されたかには依存しないからです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n, h):
        self.parent = list(range(n))
        self.size = [1] * n
        self.nodes = [[h[i]] for i in range(n)]
        self.active = [False] * n
        self.comp_cnt = [0] * n
        self.best = [[] for _ in range(n)]  # selected towers (heights)

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b, select_set, ans):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return a

        if self.size[a] < self.size[b]:
            a, b = b, a

        self.parent[b] = a
        self.size[a] += self.size[b]
        self.nodes[a].extend(self.nodes[b])
        self.nodes[b].clear()

        # merge selected towers
        self.best[a].extend(self.best[b])
        self.best[b].clear()

        # ensure at least 2 towers in component
        self.nodes[a].sort()
        self.best[a].sort()

        while len(self.best[a]) < 2:
            # pick smallest unused node
            for v in self.nodes[a]:
                if v not in self.best[a]:
                    self.best[a].append(v)
                    ans[0] += v
                    break

        return a

def solve():
    n = int(input())
    h = list(map(int, input().split()))

    edges = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        edges[u].append(v)
        edges[v].append(u)

    order = sorted(range(n), key=lambda x: h[x])

    dsu = DSU(n, h)
    ans = [0]
    active = [False] * n

    for v in order:
        active[v] = True
        dsu.nodes[v] = [h[v]]
        dsu.best[v] = []
        dsu.parent[v] = v

        for to in edges[v]:
            if active[to]:
                dsu.union(v, to, None, ans)

        root = dsu.find(v)

        # ensure constraint locally satisfied
        if len(dsu.best[root]) < 2:
            dsu.nodes[root].sort()
            for val in dsu.nodes[root]:
                if val not in dsu.best[root]:
                    dsu.best[root].append(val)
                    ans[0] += val
                    if len(dsu.best[root]) == 2:
                        break

    print(ans[0])

if __name__ == "__main__":
    solve()
```DSU は、頂点が高さの昇順で利用可能になるにつれて、進化するコンポーネントを維持します。 各マージでは、コンポーネントには常に少なくとも 2 つの選択されたタワーがあるという不変条件が適用されます。 答えは、頂点が最初にタワーとして選択されたときにのみ累積され、二重にカウントされることはありません。 

実装における微妙な点は、選択では常に利用可能な最小の高さを優先する必要があるということです。そうしないと、後のマージで不必要に高価な選択が強制される可能性があります。 

## 実用的な例

 ### 例 1

 高さのある 3 つの頂点の単純なチェーンを考えてみましょう。$[1, 2, 1]$。 

| ステップ | アクティブ化されたノード | コンポーネント | 選択されたタワー | コスト |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | {1} | なし | 0 |
 | 2 | 3 | {3} | なし | 0 |
 | 3 | 2 | {1,2,3} | 1、3 (またはマージに応じて 1、2) | 4 |

 完全にアクティブ化した後は、完全なコンポーネント内に少なくとも 2 つのタワーが必要であり、高さの最も低い 2 つのエンドポイントを選択することが最適です。 

これにより、選択したエンドポイント間のパスを介して内部ノードがカバーされることが確認されます。 

### 例 2

 中心部が葉よりも高い星形の木。 

| ステップ | アクティブ化されたノード | コンポーネント | 選択されたタワー | コスト |
 | --- | --- | --- | --- | --- |
 | 最初に出発します | それぞれが孤立した | シングルトン | なし | 0 |
 | センター | 満天の星 | すべてのノードがマージされました | 2 つの最も小さい葉 | 写真 最小合計 |

 これは、マージがグローバル カバレッジを強制するのは最後の瞬間だけであり、最も安価なリーフを貪欲に選択することが最適であることを示しています。

 ## 特殊なケース

 主なエッジケースは、木が直線であり、高さが厳密に増加する場合です。 この場合、すべてのマージは段階的に行われ、コンポーネントは単純なままになります。 このアルゴリズムでは、最終コンポーネントが形成されるときにのみ最小の 2 つの頂点が選択されるようになり、時期尚早に高価な選択を回避します。 

もう 1 つのエッジ ケースは、すべての葉の高さが低く、中心が大きい星形の木です。 ここでは、最終的にはすべての葉がタワー候補として機能する必要がありますが、実際に必要なのは 2 枚だけです。 DSU 構造では、コンポーネントごとに少なくとも 2 つの代表者を常に強制することで、過剰選択を防止します。 

3 番目のケースは、多くの頂点が同じ高さを共有する場合です。 アクティブ化の順序があいまいになるため、マージはタイブレーク順序ではなく接続のみに依存し、選択は順序付けアーティファクトではなく純粋にコンポーネントの要件によって行われるため、アルゴリズムは依然として正しく動作します。
