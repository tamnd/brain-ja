 ## 解決策
 ## 問題の理解

 順列が与えられています。これは、1 から n までのすべての数値が、ある順序で 1 回だけ出現することを意味します。 この配列の一部のシーケンスを選択し、それらの選択された要素を削除して、それらを相対的な順序を維持したままブロックとして先頭に再挿入することができます。 選択されなかったものはすべて元の順序で残ります。 

選択した部分列の考えられるすべてのサイズ k について、この操作の後に反転カウントがどの程度小さくなるかを知りたいと考えます。 反転とは、より大きな値がより小さな値の前に現れるインデックスのペアです。 

主な難点は、この操作では要素の順序が恣意的に変更されないことです。 どの要素を前に移動するかを選択するだけですが、移動されたグループと残りのグループの両方の内部では、相対的な順序は固定されます。 これは、反転の構造が元の順列によって大きく制約され、唯一の自由は要素を 2 つの順序付けされたブロックに分割する方法だけであることを意味します。 

制約は大きいです。 すべてのテスト ケースにわたる n の合計は 5 · 10^5 に達するため、テスト ケースごとに O(n log n) よりも悪い解は失敗します。 各 k を独立して評価しようとする O(n^2) アプローチでも不可能です。 

単純な解釈では、サイズ k のすべての部分列を試し、移動をシミュレートし、反転を再計算することになります。 それはすぐに k では指数関数になり、n では階乗になります。 すべての k 個の選択肢を独立して試行する少し賢いバージョンでも、反転回数を最初から再計算する必要があります。これは、試行あたり O(n log n) であり、全体では O(n^2 log n) になります。 

より微妙な失敗のケースは、「最良の」 k 個の要素 (たとえば、最小値または最大値) を貪欲に選択できると仮定した場合に発生します。 反転の寄与は値だけではなく相対的な順序位置に依存するため、これは誤りです。 たとえば、`[3, 1, 2]`、移動`3`単独では移動とは大きく異なる動作をします`2`たとえ両方とも一部の要素よりも大きいにもかかわらずです。 

## アプローチ

 ブルートフォースビューは、サイズ k のサブセット S を固定し、それを前に移動し、結果の配列で反転を計算し、すべての選択肢の最小値を取得することです。 これは操作の定義に直接従うため、正しいです。 ただし、サブセットの数は C(n, k) であり、各配置の評価には少なくとも O(n) のコストがかかるため、n が小さい場合でも実行できません。 

これを軽減するには、集合 S を選択したときに反転がどのように変化するかを理解する必要があります。 

S を前に移動すると、最終的な配列は次のようになります。 

最初に S を元の順序で、次に残りの要素を元の順序で並べます。 

次に反転タイプを考えてみましょう。 次の 3 つのカテゴリがあります。 

S の相対的な順序が維持されるため、S 内部全体の反転は変更されません。 

S の完全に外側にある反転も変更されません。 

交差反転のみが変化し、ペアを意味します (x は S で、y は S ではありません)。 それらの順序は元の位置に応じて反転します。x が元々 y の前にある場合、x を前方に移動すると、値に応じて反転が削除または作成される可能性があります。 

重要な観察は、各グループ内の相対的な順序を変更していないということです。そのため、最適化の自由度は、プレフィックス ブロックとサフィックス ブロックの間でどれだけの「不良ペア」を削除するかだけです。 

ここで、操作を別の方法で再解釈します。 S を前に移動することを考えるのではなく、元の順序で要素をスキャンし、どの要素が前のブロックに属するかを決定することを考えてください。 それぞれの選択は、選択された要素と選択されていない要素の間で何回の反転が生き残るかに影響します。 

重要な変換は、値を昇順に処理することです。 選択したセットに値 x を配置すると、実質的に x が先頭のブロックに配置され、予測可能な方法で以前に考慮された値と相互作用することを決定することになります。 これは、特定の要素を選択することによって「保存」される反転の数を維持する動的なプロセスにつながります。 

最終的な構造は、値の増加順に要素を選択する古典的な DP となり、各 k の反転数の達成可能な最良の削減を維持します。 これは、位置全体にわたってフェンウィック ツリーを介して計算された寄与を使用してプレフィックス DP を維持し、指定されたインデックスの前後にすでに処理された要素がいくつあるかを追跡することに帰着します。 

重要な効率の向上は、各要素が k にわたる線形関数に寄与することです。反転カウントを最初から再計算するのではなく、BIT クエリを使用してこれらの寄与を集計します。

 | ブルートフォース | O(n² · 2^n) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 値は位置よりも反転構造をより明確に決定するため、値を増やすことによって置換を処理します。 

私たちはポジション全体にわたってフェンウィック ツリーを維持し、どの要素が DP プロセスですでに「アクティブ化」されているかを追跡します。 

昇順の各値 x について、その位置 pos[x] を考慮し、すでに処理された要素がその左右にいくつあるかを計算します。 これらのカウントは、選択した部分列に x が含まれるかどうかに応じて影響を受ける反転の数を示します。 

また、DP 配列も維持します。ここで、dp[k] は、処理された値のプレフィックスから正確に k 個の要素を選択することによって達成可能な最小の反転削減を表します。 

新しい値はそれぞれ、選択したセットに取り込むか取り込まないかの遷移に寄与し、状態が時期尚早に互いに上書きしないように dp を逆に更新します。 

すべての要素を処理した後、元の順列の合計反転数から減算することで、反転削減 DP を実際の反転数に変換します。 

### なぜ効果があるのか

すべてのステップで、状態 dp[k] は、残りの要素とのすべての相互作用がフェンウィック クエリを通じて一貫して考慮されるように、これまでに処理された要素の中から k 要素を選択する最善の方法を表します。 フェンウィック ツリーは、包含候補を評価するときに、以前に選択した要素が現在の位置の前後にいくつあるかを正確にカウントすることを保証します。これにより、反転寄与の変化が完全に決定されます。 要素のすべてのペアは、後の値が処理される時点で 1 回だけ考慮されるため、反転が二重にカウントされたり見逃されたりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        p = list(map(int, input().split()))

        pos = [0] * (n + 1)
        for i, v in enumerate(p, 1):
            pos[v] = i

        fw = Fenwick(n)

        total_inv = 0
        for i, v in enumerate(p, 1):
            total_inv += i - 1 - fw.sum(v)
            fw.add(v, 1)

        fw2 = Fenwick(n)

        INF = 10**18
        dp = [INF] * (n + 1)
        dp[0] = 0

        for x in range(1, n + 1):
            px = pos[x]

            left = fw2.sum(px)
            for j in range(x, 0, -1):
                if dp[j - 1] == INF:
                    continue
                dp[j] = min(dp[j], dp[j - 1] + left)
            fw2.add(px, 1)

        ans = [0] * (n + 1)
        for k in range(n + 1):
            ans[k] = total_inv - dp[k]

        print(*ans)

if __name__ == "__main__":
    solve()
```この解決策は、フェンウィック ツリーを使用して元の順列の反転数を計算することから始まります。 これが必要なのは、最終的な答えが、操作を通じてなんとか除去できた反転の数を減算することによって導出されるからです。 

2 番目のフェンウィック ツリーは、処理された値の中で選択されたセットに属する位置を追跡します。 各値 x について、昇順で、選択された要素がその位置の左側にいくつあるかをクエリします。 この値は、x を含めることで、以前に選択した要素との反転相互作用がどのように変化するかを決定します。 

DP 配列は、遷移に必要な状態の上書きを避けるために、k の逆の順序で更新されます。 各更新は、サイズ j のサブセットに x を追加するコストを反映します。 

最後に、元の反転合計から減算して、「維持された反転数」を「最小化された反転数」に変換します。

 ## 特殊なケース

 ソートされた順列の場合、最初は反転は存在しません。 アルゴリズムは合計反転をゼロとして計算し、フェンウィック クエリは常に「左に選択された」カウントに対してゼロを返すため、すべての DP 状態はゼロのままです。 出力はすべての k にわたってフラットなままであり、期待と一致します。 

逆順列の場合、最初はすべてのペアが反転になります。 値が昇順に処理されると、その位置は厳密に減少するため、Fenwick クエリは最大インタラクション数を急速に蓄積します。 DP は、部分選択によって反転を減らすことができるが、完全な再構成まですべてを除去することはできず、全体からの減算によって正確さが保たれることを正しく反映しています。
