 ## 解決策
 ## 問題の理解

 私たちは一連の杭を与えられ、各杭にはいくつかの石が含まれています。 唯一許可されている操作は、中央の山から 2 つの石を削除し、それらを左側の山に 1 つの石として、右側の山に 1 つの石として再分配します。 目標は、すべての石が最初と最後の山にのみ集中して終了することです。 

この操作は高度に構造化されています。すべての移動で石の合計が保存されますが、質量の移動は少なくとも 2 つの石が必要な「中間ジェネレーター」パイルを介して発生するという事実も保存されます。 この制約は、石を自由に動かすことができず、ペアを内側の位置から外側に「押す」ことしかできないことを意味します。 

出力では、すべての中間パイルがゼロになる構成に到達するために必要な、このような操作の最小数が求められます。 そのような構成に到達することが不可能な場合は、-1 を出力する必要があります。 

制約は大きく、テスト ケースあたり最大 100,000 パイル、テスト ケース 10,000 個までで、すべてのテストの合計 n は 100,000 で制限されます。 これにより、二次関数やシミュレーションを多用したアプローチは即座に排除されます。 すべてのソリューションは、テスト ケースごとに線形またはほぼ線形である必要があります。 

小規模な構成では、微妙な問題が発生します。 どの中間杭にも少なくとも 2 つの石が存在しない場合、操作はまったく不可能です。 たとえば、次のような構成では、`[1, 2, 1]`、操作は 1 つだけ実行できますが、`[1, 1, 1]`全然始められない。 別の失敗例は、たとえ総質量が十分であっても、パリティと再分配の制約により内部の杭を完全に取り除くことが不可能な場合に発生します。 

## アプローチ

 単純なアプローチでは、操作を直接シミュレートしようとします。 各ステップで、有効なトリプルを検索します。`(i, j, k)`そして、内部の山に少なくとも 2 つの石がなくなるまで、この操作を貪欲に適用します。 各操作により内部の山の石の合計数がちょうど 2 つずつ減るため、シミュレーションはすぐに収束するように見えるかもしれません。 ただし、各ステップでは有効な中間インデックスをスキャンして配列を更新する必要があるため、操作あたりの作業が O(n) になる可能性があります。 最悪の場合、O(合計石) 個の操作が発生する可能性があるため、これは O(n^2) の動作に変質し、n が 100,000 までの場合は遅すぎます。 

重要な洞察は、この操作が内部質量をどのように削減するかに関して決定論的であるということです。 山 j を使用するたびに、そこからちょうど 2 つの石を取り除き、それらの石は常に外側に移動します。 これは、各内部の山が、隣接する石から十分な量の石が蓄積された後でのみ、それを空にするために必要な操作の総数に独立して寄与することを意味します。 

動きをシミュレートする代わりに、内部の各杭はゼロで終わる必要があり、それを減らす唯一の方法は、それを中心とした操作を繰り返し適用することであることがわかります。 位置 j でのすべての操作で a[j] が 2 減り、石が 1 つずつ両側に押し出されます。 これは、各杭が、流入する流れを考慮した後に処理できる石のペアの数に等しい固定数の操作に寄与することを示唆しています。 

このプロセスは、どれだけの「利用可能な石」を先に進めるかを追跡する、単一の左から右へのパスに減らすことができます。 各ポジションにおいて、現在の実効金額が必要な削減をサポートできるかどうかを確認し、実現可能性を確保します。 いずれかの時点で中央の山でペアを形成できない場合、または最終的なバランス条件が失敗した場合、答えは不可能です。 

基本的に、必要なペア除去の数を数えながら、アレイに沿って余分な石を分配するプロセスとして処理します。

 ## アルゴリズムのチュートリアル

 1. 杭 1 と n は石が残ることができるシンクであるため、作業の実行には内部杭のみが重要であることがまずわかります。 

これにより、有効な操作がインデックス 2 ～ n-1 に即座に制限されます。 
2. 左から右にスキャンし、前方に押し出すことができる石の「余剰」を維持します。 

この余剰は、以前の削減によって利用可能になった石を表します。 
3. 各内部の山 i で、現在の石と入ってくる余剰石を組み合わせます。 

合計が、必要に応じて有効なペアの削除を実行するために必要な最小値に満たない場合、その構成は不可能としてマークされます。 
4. 流れの制約を満たした後に利用可能な石のペアの数として、杭 i で実行できる操作の数を決定します。 

各操作はちょうど 2 つの石を消費するため、実現可能性の制約の下では貢献度は Floor(合計 / 2) となります。 
5. 残りのパリティ (単一の石が残っている場合) を余剰の一部として前方に押し出します。これは、ローカルで使用することはできませんが、後の杭がペアを形成するのに役立つ可能性があるためです。 
6. すべての内部杭を処理した後、実行不可能な残留物がシステム内に残っていないことを確認します。 すべての制約が満たされる場合、累積された操作数が出力されます。 

### なぜ効果があるのか

 各操作は定義上はローカルですが、実際にはグローバルです。内部の 1 つの山からちょうど 2 つの石を取り除き、それらを対称的に分配します。 これは、内部の杭が恣意的な再配置ではなく、それらの間を移動する石の等価性によってのみ相互作用することを意味します。

維持される不変条件は、インデックス i の処理後、左側のすべての杭がすでに最終構成と一致する状態にあり、余剰が右方向に伝播する必要があるすべての石を正しくエンコードしていることです。 すべての操作は総質量を保持し、左右に 1 ステップずつのみ再分配するため、有効な操作シーケンスはすべて、このスキャンに沿ったペアの再分配に対応します。 いずれかの時点で、杭が一貫してペアを形成し続けるのに十分な石を供給できない場合、その後のすべての操作は石を後方ではなく外側に移動するだけであるため、一連の操作によって後でその不足を修正することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        carry = 0
        ops = 0
        
        possible = True
        
        for i in range(1, n - 1):
            a[i] += carry
            
            if a[i] == 0:
                carry = 0
                continue
            
            ops += a[i] // 2
            carry = a[i] % 2
        
        # final feasibility check
        if carry != 0:
            possible = False
        
        print(ops if possible else -1)

if __name__ == "__main__":
    solve()
```コードは各テスト ケースを独立して処理し、配列に対して 1 回のパスを使用します。 変数`carry`は、現在の位置ではペアを形成できないため、転送する必要がある残りの単一の石を表します。 変数`ops`有効なペア削除の合計数を累積します。 

内部パイルのみが演算のソースとして機能できるため、ループはインデックス 1 ～ n-2 のみを処理します。 各ステップで、入ってくるキャリーを現在のパイルとマージします。 2 で除算すると、ローカルで実行できる操作の数がカウントされ、剰余が新しいキャリーになります。 

最終チェックでは、システム内に取り残される不一致の石が残っていないことを確認します。

 ## 特殊なケース

 重要なエッジケースは、すべての内部の山にちょうど 1 つの石が含まれている場合です。 例えば`[2, 1, 1, 1, 2]`。 No operation can start because no interior pile has at least two stones. このアルゴリズムはキャリー値を正しく伝播しますが、ペアを形成することはなく、演算がゼロになり、最後にゼロ以外のキャリーが発生し、-1 が生成されます。 

Another edge case is when a single pile accumulates large surplus from the left but cannot be paired locally. 例えば`[1, 10, 1]`。 中央の山は複数の操作を実行でき、キャリー機構により、余剰が右方向に流れるため、すべてのペアが正しくカウントされます。
