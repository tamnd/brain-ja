 ## 解決策
 ## 問題の理解

 順序付けられた整数の 3 倍の数を数えるように求められます$(i, j, k)$範囲内で$[0, m]$方程式が$(i \oplus j) \cdot x + (j \oplus k) \cdot y = n$の整数解があります$x$そして$y$。 ここ$\oplus$はビット単位の XOR です。 つまり、トリプルごとに、2 つの XOR 差分が線形ディオファントス方程式の係数を形成し、その方程式が整数で解けるかどうかを確認する必要があります。 

入力$n$そして$m$比較的大きいもの:$n$まで可能です$10^9$、 そして$m$まで$3 \cdot 10^5$。 の合計$m$すべてのテスト ケースの境界は次のとおりです$3 \cdot 10^5$、つまり余裕があることを意味します$O(m^2)$テストケースごとですが、$O(m^3)$遅すぎます。 素朴なトリプルループオーバー$i, j, k$について関わるだろう$3\cdot 10^5^3$操作、つまり大まかに言うと$10^{16}$、完全に不可能です。 

エッジケースには、XOR の差がなくなる状況が含まれます。 たとえば、次の場合$i = j$、 それから$i \oplus j = 0$、最初の係数はゼロです。 このような場合、可解性は完全に第 2 項に依存します。$(j \oplus k) \cdot y = n$、 それで$n$で割り切れる必要があります$j \oplus k$。 同様に、$j = k$、第二項は消滅します。 両方の違いがなくなると、$(i \oplus j = 0$そして$j \oplus k = 0)$とすると、方程式は次のようになります。$0 = n$、だからそれだけ$n = 0$解決策を生み出すことができます。 非ゼロ係数を想定する単純なアプローチでは、有効なトリプルが誤って拒否されたり、カウントが間違ったりする可能性があるため、これらの係数がゼロのケースを慎重に処理することが重要です。 

## アプローチ

 ブルートフォースメソッドはすべてのトリプルを列挙します$(i, j, k)$、計算します$a = i \oplus j$そして$b = j \oplus k$、線形ディオファントス方程式が成り立つかどうかを確認します。$a x + b y = n$整数で解けます。 可解性をチェックする標準的な方法は、次のように計算することです。$\gcd(a, b)$そしてそれが分割されるかどうかを確認してください$n$。 正しいのですが、このアプローチには次のことが必要です$O(m^3)$反復が必要であり、それを超えてスケ​​ールすることはできません$m \sim 10^3$。 

最適化の重要な観察点は、問題は XOR の違いのみに依存するということです。$a = i \oplus j$そして$b = j \oplus k$の絶対値ではなく、$i, j, k$。 したがって、XOR の差によってペアをグループ化できます。 それぞれについて$a$で$0..m$、ペアの数を数えます$(i, j)$と$i \oplus j = a$。 同様に、それぞれについて、$b$で$0..m$、ペアの数を数えます$(j, k)$と$j \oplus k = b$。 次に、特定の値に対応するトリプルの数$(a, b)$は単にこれらのカウントの積です。 すべてを合計するだけで済みます$(a, b)$そのような$\gcd(a, b)$分割する$n$。 これにより、複雑さが軽減されます。$O(m^3)$に$O(m^2 + m \log n)$、これは実現可能です$m$まで$3 \cdot 10^5$慎重に扱った場合。 

XOR が関与するため、この問題はビットマスク DP または周波数配列に適しています。 Counting the number of pairs$(i, j)$指定された XOR を使用して$a$これは、各数値の頻度を計算し、恒等式を使用することと同じです。$\text{count}[a] = \sum_{i=0}^m \text{freq}[i] * \text{freq}[i \oplus a]$。 この方法では、すべてのペアに対する明示的な反復処理が回避されます。

 ## アルゴリズムのチュートリアル

 1. 範囲内の各数値の頻度を事前計算します。$[0, m]$。 すべての数値は 1 回だけ出現するため、$\text{freq}[i] = 1$。 この例ではこれは些細なことですが、数値が繰り返される場合は一般化されます。 
2. 考えられる各 XOR 値について$a$から$0$に$m$、ペアの数を計算します$(i, j)$そのような$i \oplus j = a$。 これを繰り返すことでこれを行うことができます$i$そして数えます$j = i \oplus a$。 count 配列をインクリメントします。$a$。 
3. 同様に、ペアの数を計算します。$(j, k)$各 XOR 値に対して$b$で$0..m$。 
4. すべてのペアを反復処理します。$(a, b)$。 それぞれについて、次のことを確認します。$\gcd(a, b)$分割する$n$。 その場合は追加してください$\text{count}[a] \cdot \text{count}[b]$結果に。 
5. 合計を有効なトリプルの数として出力します。 

機能する理由: このアルゴリズムはカウントの直線性を利用しています。 すべての有効なトリプルは、XOR 差分のペアに対応します。$(a, b)$整数解を使用します。 違いごとにペアの数を事前に計算することで、三重ループを回避します。 GCD の可分性により、整数が存在することが保証されます。$x, y$解決する$a x + b y = n$、二重カウントすることなくすべてのソリューションをカバーします。 

## Python ソリューション```python
import sys
import math
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        # count_xor[a] = number of pairs (i, j) with i xor j = a
        count_xor = [0] * (m + 1)
        for i in range(m + 1):
            for j in range(m + 1):
                count_xor[i ^ j] += 1
        result = 0
        for a in range(m + 1):
            for b in range(m + 1):
                if math.gcd(a, b) != 0 and n % math.gcd(a, b) == 0:
                    result += count_xor[a] * count_xor[b]
                elif a == b == 0 and n == 0:
                    result += count_xor[a] * count_xor[b]
        print(result)

if __name__ == "__main__":
    solve()
```外側のループは複数のテスト ケースを処理します。 ネストされたループ$i$そして$j$XOR を効率的にカウントします。$m \le 3\cdot 10^5$Pythonでは、すべての合計なので$m$有界である。 GCD チェックは整数の可解性を保証しますが、特殊なケースでは$a = b = 0$ハンドル$n = 0$。
