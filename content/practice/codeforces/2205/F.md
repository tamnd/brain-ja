 ## 解決策
 ## 問題の理解

 都市を表す長方形のグリッドが与えられ、座標が交差します。$(i,j)$。 道路は、水平方向または垂直方向に隣接する交差点の間にのみ存在します。 各ストリートには整数の重みがあり、再構築が許可される場合と許可されない場合があります。 再構築は、再構築可能な街路のサブセットを選択することで構成されます。 偶数の再建された街路と交差する交差点は、エレガントであると呼ばれます。 すべての交差点がエレガントであれば、再建は素晴らしいと言われます。 目標は、再構築が良好で、各行と列に沿った符号付き交互合計に従って計算された「美しさ」の値が最大化されるように、再構築可能な街路のサブセットを選択することです。 

制約は厳しいです:$n\cdot m$まで可能です$4\cdot 10^5$すべてのテスト ケースにわたって、どのソリューションも交差点や道路の数が線形である必要があります。 通りの数はおおよそ次のとおりであるため、すべてのサブセットを総当りで探索することは不可能です。$2\cdot n \cdot m$、列挙すると$2^{2\cdot n\cdot m}$サブセットはまったく問題外です。 

一部の道路が禁止されている場合、特に道路が境界線上にある場合、エッジケースが発生します。 たとえば、角の交差点に再構築可能な通りが 1 つだけあり、他のすべての道路が禁止されている場合、それをエレガントにする方法はなく、再構築でその通りを省略せざるを得なくなります。 もう 1 つの微妙な点は、負の重みのストリートは除外す​​る方が有利な場合もありますが、偶数次の制約により、それらを含める必要がある場合があります。 交差点での均等性を強制せずに、通りごとに局所的に美しさを最大化しようとする不注意な実装は失敗します。 

## アプローチ

 ブルートフォース手法では、再構築可能な街路のすべてのサブセットを列挙し、各交差点の次数が均等であるかどうかを確認し、美しさを計算します。 これは原理的には正しいですが、このサイズのグリッドでは明らかに不可能です$2\cdot 10^5$。 サブセットの数は指数関数的に増加し、偶数次制約を検証するとオーバーヘッドがさらに増加し​​ます。 時間計算量は次のようになります。$O(2^{nm})$それは絶望的です。 

重要な観察は、偶次制約がエッジ上の 2 色付け問題と同等であるということです。再構築されていない街路に 0 を割り当て、再構築された街路に 1 を割り当てると、各交差点の入射エッジの合計は 2 を法とする 0 にならなければなりません。これにより、次数にわたる線形システムが形成されます。$\mathbb{F}_2$ここで、グリッドの各行と列は方程式を引き起こします。 このシステムは、パリティに違反する方法で何らかのストリートを強制的に含めたり除外したりしない限り、常に解決可能です。 これらのパリティ制約を考慮して交互の合計を最大化することに問題を帰着すると、すべてのストリートの包含が単独で考慮した場合にプラスに寄与することがわかります。 行または列全体の場合、最適な交互合計は、パリティ制約によって調整された、その行内の再構成可能な街路の合計の絶対値にすぎません。 実際、最適な解決策は、行と列を独立して処理し、それらの寄与を組み合わせ、グローバル パリティを満たすために必要に応じて 1 つのストリートの包含を反転することによって決定できます。 

これは線形時間アルゴリズムにつながります。つまり、すべての道路を 1 回横断し、道路が含まれている場合は美しさへの潜在的な寄与を計算し、パリティ制約により追加の調整が必要かどうかを追跡します。 単一のパリティ調整を法として、行と列を独立して考慮できるという洞察により、一見指数関数的な問題が線形問題に変換されます。

 ## アルゴリズムのチュートリアル

 1. グリッドの寸法を読み取る$n$そして$m$そしてストリートウェイト$w_{i,j}$（縦）と$v_{i,j}$（横）復興旗とともに$p_{i,j}$そして$q_{i,j}$。 フラグ「1」が付いた通りのみが再構築可能です。 
2.初期化`total_beauty`ゼロに。 行と列の両方からの貢献を蓄積していきます。 
3. 各行について$i$から$1$に$n-1$、その行にある再構築可能な垂直の通りを考えてみましょう。 それらの重みを収集し、列インデックスで並べ替えます。 交互の合計を計算する$w_{i, c_1} - w_{i, c_2} + w_{i, c_3} - \dots$。 その行で再構築された街路の数が奇数の場合は、合計から最小絶対重みを減算して、端点で偶数次数を適用します。 
4. 各列に対して同様のプロセスを繰り返します。$j$から$1$に$m-1$、再構築可能な水平道路を考慮し、交互の合計を計算し、必要に応じてパリティ調整を適用します。 
5. 行と列からのすべての寄与を合計します。`total_beauty`。 
6. 出力`total_beauty`テストケースごとに。 

機能する理由: すべての交差点には 4 つのインシデント エッジがあります (境界を除く)。 偶数次の制約は、行と列を個別にパリティ条件に変換します。これにより、ラインごとに最大 1 つのパリティ調整で交互の合計を計算できます。 これにより、再構成が良好であることが保証され、可能な限り最大の交互合計を取得することで美しさが最大化されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        w = [list(map(int, input().split())) for _ in range(n-1)]
        v = [list(map(int, input().split())) for _ in range(n)]
        p = [input().strip() for _ in range(n-1)]
        q = [input().strip() for _ in range(n)]
        total = 0
        for i in range(n-1):
            row_edges = []
            for j in range(m):
                if p[i][j] == '1':
                    row_edges.append(w[i][j])
            row_edges.sort()
            sum_row = 0
            for idx, val in enumerate(row_edges):
                sum_row += val if idx % 2 == 0 else -val
            if len(row_edges) % 2:
                sum_row -= min(abs(x) for x in row_edges)
            total += sum_row
        for j in range(m-1):
            col_edges = []
            for i in range(n):
                if q[i][j] == '1':
                    col_edges.append(v[i][j])
            col_edges.sort()
            sum_col = 0
            for idx, val in enumerate(col_edges):
                sum_col += val if idx % 2 == 0 else -val
            if len(col_edges) % 2:
                sum_col -= min(abs(x) for x in col_edges)
            total += sum_col
        print(total)

if __name__ == "__main__":
    solve()
```コードは最初にすべての重みと再構成フラグを読み取ります。 行と列ごとに、再構成可能な街路を収集し、交互の合計を計算し、偶数次を満たすために必要に応じて最小限の調整を適用します。 交互パターンでは並べ替えはオプションですが、列/行の順序が適切であることが保証されます。 パリティ調整は、ラインに奇数の再構築可能なストリートがある場合に、無効な再構築を回避するために重要です。
