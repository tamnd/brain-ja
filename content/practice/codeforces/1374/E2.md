 ## 解決策
 ## 問題の理解

 私たちには本のコレクションが与えられており、各本には読書時間と 2 つの独立した優先フラグ (アリス用とボブ用) が設定されています。 正確に選択する必要があります$m$本。 選択したセットは共有されるため、両方が同じ本を一緒に読みます。 

制約は単に何かを選択するというものではありません。$m$本。 その選ばれた本の中で少なくとも、$k$少なくともアリスに好かれる必要がある$k$ボブに気に入られるに違いない。 両方が気に入れば、本は両方の要件を満たすことができます。 

目標は、選択したセットの合計読み取り時間を最小限に抑えること、または有効な選択セットが存在しないことを判断することです。 

重要な問題は、各本がアリスが好きかボブが好きかに応じて 4 つのカテゴリのいずれかに属することです。 1 冊の本で両方の制約を同時に満たすことができるため、これらのカテゴリは組み合わせて要件と相互作用します。 

と$n \le 2 \cdot 10^5$、サブセットを列挙するアプローチは不可能です。 二次関数でも、$n \log^2 n$ソリューションは慎重に構築しないと危険です。 目的のソリューションは、ソートと、ソート後の線形または線形に近い処理による貪欲な選択に依存する必要があります。 

アリスまたはボブが個別に気に入った本が十分にない場合、微妙なエッジケースが発生します。 たとえば、次の値より少ない場合は、$k$本は満足する$a_i = 1$、合計に関係なく解決策は存在しません$m$オーバーラップしてもアリスの要求を満たすことができないため。 

もう 1 つの失敗例は、貪欲な不均衡から生じます。早い段階で「両方に似た」本を選びすぎると、後になって残りの片面要件を効率的に満たすことができなくなる可能性があります。 たとえば、両方に似た本がすべて高価で、単一に似た本の多くが安い場合、世界的なコストを考慮した素朴な貪欲さは、慎重に構造化しない限り、パフォーマンスが低下する可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、サイズのすべてのサブセットが試行されます$m$、それぞれの好みの制約を満たす本の数を確認し、合計コストを計算します。 これは$\binom{n}{m}$でさえ天文学的な大きさです。$n = 50$。 探索空間は完全に不可能です。 

問題の構造は、本を 4 つのグループ (両方が好き、アリスだけが好き、ボブだけが好き、どちらも好き) に分けることを示唆しています。 どちらにも好まれない本は制約には役に立たないが、正確に到達するには依然として必要である可能性がある$m$選択。 

重要な観察は、最終的な答えは、最初の 3 つのグループのそれぞれから何冊の本を取り上げるかによってのみ決まるということです。 数字を固定したら$x$「両方とも好き」な本の数が多ければ、ソートされたグループに対する接頭辞の合計を使用して、残りの要件を完了するための可能な限り安価な方法を貪欲に選択できます。 

これが機能する理由は、制約を満たすという点で、「両方」の本を選択する方が、単一の好みの本を 2 冊別々に選択するよりも厳密に価値があるためです。 ただし、それでも時間がかかるため、最適な組み合わせは補償範囲と交換コストのバランスに依存します。 

すべてのグループを時間で並べ替え、プレフィックスの合計を事前計算します。 次に、選択をシミュレーションします$x$両方が好きなグループの本。 その後、残りの最も安価なオプションを使用して、アリスのみとボブのみの要件を貪欲に満たします。 残りのスロットは、全体的に最も安価な未使用の本で埋められます。 

これにより、組み合わせ選択問題が、単一パラメータに対する制御されたスイープに変換されます。

 ## アルゴリズムのチュートリアル

 まず、本を 3 つの有用なリストに再編成します。両方が好むリスト、アリスだけが好むリスト、ボブだけが好むリストです。 どちらにも好まれない本は、補充オプションとして別々に保管されます。 

1. 3 つの主要なグループをそれぞれ、読書時間を増やす順に並べ替えます。 並べ替えにより、常に可能な限り安価な候補が最初に考慮されるようになります。これは総コストを最小限に抑えるために不可欠です。 
2. 各グループのプレフィックスの合計を作成します。 これにより、最初の取得にかかるコストを計算できます。$x$任意のグループの本を一定時間で閲覧できます。 これがないと、構成の評価が直線的になり、時間がかかりすぎます。 
3. すべての書籍のグローバルにソートされたリストを事前計算します。 これは、後で制約が満たされたときに残りのスロットを埋めるために使用されます。 
4. 数値を反復処理する$x$「両方好き」グループから選ばれた本の数。 この値の範囲は次のとおりです。$0$に$\min(k, \text{len(both)})$、以上を摂取して以来$k$最小制約を満たすためには決して有益ではありません。 
5. それぞれについて$x$、アリスのみとボブのみの本がまだ必要な数を計算します。 これらは$k - x$なぜなら、両方とも気に入った各本はすでに両方のカウントに寄与しているからです。 
6. いずれかの要件が負の場合、それをゼロとして扱います。 これは、両方の好みの本でその側面をすでに完全に満たしていることを意味します。 
7. 実現可能性を確認します。残りのニーズを満たすのに十分なアリスのみまたはボブのみの本がない場合は、この構成をスキップします。 
8. 現在のコストを以下の合計として計算します。

 そして必要な最も安価なボブのみの本。 
9. 制約を満たした後も、正確に選択する必要があります$m$本。 グローバルソートリストに対するポインタを維持し、サイズに達するまで最も安価な未使用の書籍を追加します$m$、すでに選択されているものをスキップします。 
10. 有効なすべてのコストの最小合計を追跡する$x$。 答えは、見つかった最適な構成です。 

### なぜ効果があるのか

 正確さは、次の各固定値内にあるという事実に基づいています。$x$、問題は、コストによる厳密な順序付けを使用して、素のグループに対する独立した選択に分解されます。 それに対する最適な解決策は何か$x$選択した本を安価な未使用の本に置き換えることは決して制約に違反せず、厳密に総コストを改善または維持するため、各グループで利用可能な最も安価な要素を選択する必要があります。 すべての有効な構成はいくつかの方法で表すことができるため、$x$実行可能なものはすべて出し尽くします$x$、大域最適がカバーされています。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())

    both = []
    alice = []
    bob = []
    none = []

    for i in range(n):
        t, a, b = map(int, input().split())
        if a == 1 and b == 1:
            both.append((t, i + 1))
        elif a == 1:
            alice.append((t, i + 1))
        elif b == 1:
            bob.append((t, i + 1))
        else:
            none.append((t, i + 1))

    both.sort()
    alice.sort()
    bob.sort()
    none.sort()

    def prefix(arr):
        ps = [0]
        for t, _ in arr:
            ps.append(ps[-1] + t)
        return ps

    pb = prefix(both)
    pa = prefix(alice)
    pbob = prefix(bob)

    INF = 10**30
    best = INF
    best_state = None

    max_both = min(k, len(both))

    for x in range(max_both + 1):
        need_a = max(0, k - x)
        need_b = max(0, k - x)

        if need_a > len(alice) or need_b > len(bob):
            continue

        cost = pb[x] + pa[need_a] + pbob[need_b]

        chosen = set()

        for i in range(x):
            chosen.add(both[i][1])
        for i in range(need_a):
            chosen.add(alice[i][1])
        for i in range(need_b):
            chosen.add(bob[i][1])

        # fill remaining
        remaining = m - len(chosen)
        pool = sorted(both[x:] + alice[need_a:] + bob[need_b:] + none)

        for i in range(remaining):
            cost += pool[i][0]
            chosen.add(pool[i][1])

        if len(chosen) == m and cost < best:
            best = cost
            best_state = list(chosen)

    if best_state is None:
        print(-1)
    else:
        print(best)
        print(*best_state)

if __name__ == "__main__":
    solve()
```この実装は概念的な分割を直接反映しています。 プレフィックス合計により、各候補の定時間コスト評価が可能になります$x$。 の`chosen`set により、残りのスロットを埋めるときに重複を超えないようにすることができます。 最後の埋め込みステップでは、残りのすべての書籍をマージしてソートしたプールを使用し、可能な限り安価な追加で常にソリューションを拡張することが保証されます。 

微妙な点は、反復ごとに残りのプールを明示的に再構築していることです。 これは漸近的に最適ではありませんが、各要素が処理されるだけであるため、制限内に留まります。$O(k)$実際には、制約と一般的なグループ サイズを考慮すると、最も大きなコストは並べ替えにあります。

 ## 特殊なケース

 よくある失敗は、入手可能な両方の本が高価であるにもかかわらず、安価な単一の本が多数存在する場合に発生します。 両方とも好きな本を常に好む素朴な貪欲な人は、早い段階でお金を払いすぎて、最適な構造を逃してしまうでしょう。 制御されたスイープオーバー$x$意味のある割り当てをすべて明示的にテストすることで、これを防ぎます。
