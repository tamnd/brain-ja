 ## 問題の理解

 開始整数が与えられ、2 つの演算を使用してそれを変換できます。それを 2 倍にすることも、6 で割ることもできますが、6 で割り切れる場合に限ります。 各テスト ケースでは、値 1 に到達できるかどうか、到達できる場合は、必要な操作の最小数はどれくらいかを尋ねます。 

除算では数値が減り、乗算では数値が増加するため、このプロセスには方向性があり、実際には不可逆的です。 タスクは、考えられるすべてのシーケンスをやみくもにシミュレートすることではなく、数を正確に 1 に減らすこれらの操作のシーケンスが存在するかどうかを判断し、すべての有効なシーケンスの中からステップ数が最小のものを選択することです。 

この制約により、状態をグラフとして調査できないことが明らかになります。 最大 20,000 のテスト ケースと 10 億もの値を使用すると、ステップごとに複数の状態に分岐するアプローチは組み合わせ的に爆発的に発生します。 中間値は狭い範囲に制限されずに拡大または縮小する可能性があるため、単純な幅優先検索さえ不可能です。 

繰り返し 6 で割る構造と一致するように、数値が 2 または 3 で割り切れない場合、微妙なエッジ ケースが発生します。 たとえば、2 や 10 のような数値から始めると、掛け算を繰り返すことで割り切れる可能性を「修正」できるように感じるかもしれませんが、実際には 2 を掛けると 3 で割り切れるのが難しくなります。 もう 1 つの誤解を招きやすいケースは、いくつかの乗算の後、数値が最終的に 6 で割り切れる場合ですが、そのパスには常に最適なシーケンスよりも高いコストがかかるか、まったく有益ではない場合です。 

たとえば、12 から始めて、素朴な直感で操作を任意に混合しようとする可能性がありますが、因子構造が、実現可能性を維持する 6 ステップによる除算のみを使用して 1 に減らすという要件と一致しないため、正しい答えを得るのは実際には不可能です。 

## アプローチ

 ブルートフォースのアイデアは、各数値をグラフ内のノードとして扱い、エッジを有効な演算として扱うことです。つまり、x から 2x に進むことができ、割り切れる場合は x から x/6 に進むことができます。 次に、BFS を使用して n から 1 への最短パスを検索します。 すべての移動には等しいコストがかかり、BFS は最短パスを保証するため、これは理論的には正しいです。 

問題は、状態空間が無制限であることです。 10^9 のような数値から、2 倍の繰り返しはすぐに妥当な限界を超え、割り算の繰り返しは疎な割り算パターンに依存します。 各ノードが新しい乗算状態と潜在的に分割状態を生成する可能性があるため、BFS ツリーは指数関数的に成長し、大きな分岐要素が発生し、さまざまな形で多くの状態が再訪されます。 

重要な観察は、6 による除算が値を減らす唯一の演算であり、2 による乗算は、将来の 6 による除算を可能にする場合にのみ意味があるということです。 つまり、任意の数列ではなく、因子操作の観点から考える必要があるということです。 

任意の数値を 2 および 3 のべき乗倍の余りとして因数分解できます。 6 で除算すると、2 の因数 1 つと 3 の因数 1 つが同時に削除されます。 2 を掛けると係数 2 が加算されます。 3 の因数を作成するには、最初の数を使用するか、すでに存在する除算構造を使用する以外に方法がないため、プロセス全体は 2 と 3 の累乗のバランスによって決まります。 

重要な単純化は、2 と 3 のすべての要素を制御された方法で繰り返し削除することです。 2 と 3 の要素をすべて取り除いた残りの数が 1 でなければ、決して 1 には到達できません。 それ以外の場合は、すべての 6 による除算が有効になるように、乗算を使用して余分な 2 の累乗のバランスを取る方法を決定するだけで済みます。

これにより、問題は、6 で割る回数と、2 の余分な因数をいくつ導入する必要があるかを追跡することになります。

 ## アルゴリズムのチュートリアル

 各数値を個別に処理します。 

1. 数値から 2 と 3 の累乗をすべて因数分解します。 可能な限り2で割る、3で割るを繰り返します。 これにより、許可された操作と実際に対話する構造が分離されます。 
2. 2 と 3 の要素をすべて削除した結果、その数が 1 でない場合、直ちにそれは不可能であると結論付けます。 これは、2 以外の素因数を導入する演算がないために発生します。 
3. 最初に、その数値が 2 と 3 で割り切れる回数を数えます。 これらのカウントは、6 によるきれいな除算がすぐに何回可能であるかを表します。 
4. 6 による除算ごとに 3 の因数が 1 つと 2 の因数が 1 つ消費されるため、制限要因は 3 の数です。 構造を一致させるために必要な数より 3 が少ない場合は失敗します。 
5. 必要な除算ステップの合計数が、削除された 3 の数と等しいことがわかったら、2 の乗算を使用して調整します。 2 を掛けるたびに、必要に応じて将来の除算演算をサポートするために、追加の 2 因数を効果的に「作成」します。 
6. 最終的な答えは、除算演算の数を利用可能な因数 3 に合わせ、最小数の乗算を使用して不足している因数 2 を補償することによって計算されます。 

重要な構造的不変条件は、すべての有効なシーケンスを再配置して、すべての 2 による乗算が 6 による除算を可能にするために必要な場合にのみ行われるようにできることです。 これは、最適な戦略が、操作を恣意的にインターリーブすることによってではなく、因子数によって完全に決定されることを意味します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(n):
    # remove all factors of 2
    c2 = 0
    while n % 2 == 0:
        n //= 2
        c2 += 1

    # remove all factors of 3
    c3 = 0
    while n % 3 == 0:
        n //= 3
        c3 += 1

    # if remaining part is not 1, impossible
    if n != 1:
        return -1

    # we need at least as many 3s as 2s removed initially
    if c2 > c3:
        return -1

    # operations:
    # we need to match c3 divisions, but we have c2 surplus of 2-factors
    # each extra 3 beyond c2 requires a division step, and balance is c3
    return (c3 - c2) + c3

t = int(input())
for _ in range(t):
    n = int(input())
    print(solve_case(n))
```このコードは、数値を素数構造に分割することで機能します。 係数 2 と 3 を削除するループにより、各操作タイプが論理的に何回適用できるかが正確に特定されます。 

不可能チェック`n != 1`因数除去後は、2 または 3 以外の素数を含む数値から 1 に到達しようとしないことが保証されます。 条件`c2 > c3`は、3 に対して 2 のべき乗が多すぎるという構造的な不一致を捉えています。これは、有効な 6 による除算ステップにそれらを調整できないことを意味します。 

最後の式は、最初に暗黙的な乗算によって欠落している構造を補正し、次に必要な除算を実行する必要があるという考えをエンコードしています。

### 例 2: n = 12345

 因数 2 と因数 3 を取り除くと、他の素数を含む数値が残ります。 アルゴリズムはそれを即座に拒否します。 これは、2 をいくら掛けても 5 や 7 の因数が欠落することはありえないため、1 に到達することは構造的に不可能であることを示しています。

## テストケース```python
import sys, io

def solve(inp: str) -> str:
    import sys
    input = sys.stdin.readline
    data = inp.strip().split()
    t = int(data[0])
    idx = 1

    def solve_case(n):
        c2 = 0
        while n % 2 == 0:
            n //= 2
            c2 += 1
        c3 = 0
        while n % 3 == 0:
            n //= 3
            c3 += 1
        if n != 1:

    out = []

        n = int(data[idx]); idx += 1
        out.append(str(solve_case(n)))
    return "\n".join(out)

 ## 特殊なケース

 n が 1 に等しい場合、ループは何も行わず、両方のカウンターは 0 のままになるため、アルゴリズムは正しく 0 手を返します。 n が 2 や 4 などの純粋な 2 の累乗である場合、6 による除算が不可能なため、係数 3 の除去はすぐに失敗し、残りの係数構造により 1 に到達することができません。 n が 2 と 3 のみの積 (6 や 18 など) の場合、アルゴリズムは一致する因数のペアを正確にカウントし、計算された演算数は必要な除算の数と一致します。
