 ## 解決策
 ## 問題の理解

 配列と非常に具体的な基本的な操作が与えられます。任意の位置を選択し、3 つの連続する要素のブロックを右に回転できます。 それはローカルトリプルを意味します`[x, y, z]`になる`[z, x, y]`。 この操作を何度も繰り返すと、配列を非降順に変換したいか、それができないと判断します。 

重要な点は、操作が非常にローカルであるものの、スワップのように対称的ではないことです。 これは、制約付き順列ジェネレーターのように動作します。制御された循環パターンでのみ要素を左方向に移動できます。 くらいまでは許されます`n^2`テストケースごとの操作数とその合計`n`小さいので、`O(n^3)`スタイルシミュレーションは依然としてボーダーラインだが構造化されている`O(n^2)`建設が予想されます。 

微妙な問題は、この操作では任意のスワップができないことです。 たとえば、隣接する 2 つの要素を交換しようとしても、直接行うことはできません。 要素を「バブル」できるのはトリプルを使用することだけであり、順列のパリティが重要になります。 これが不可能性の最初の原因です。すべての順列が到達可能であるわけではありません。 

もう 1 つの明白ではないエッジ ケースは、重複が存在する場合です。 値は明確ではないため、順列パリティのみに依存しないように注意する必要があります。 代わりに、ソートされたマルチセット配置を構築できることを確認する必要があります。 

2 番目のエッジ ケースは、反転が配列の終端近くの距離 1 で「スタック」したときに現れます。 たとえば、長さ 3 の配列では循環回転のみが可能であるため、6 つすべてではなく、3 つの順列のみが存在します。これは、演算空間が制限されていることを直ちに示します。 

パリティや実現可能性を追跡せずに、最小限の要素を貪欲にバブルさせようとする単純なアプローチは失敗する可能性があります。 たとえば、`[3, 1, 2]`、不注意なスワップベースの直観は、サイズ 3 のものは何でもソートできると仮定するかもしれませんが、循環回転のみが存在し、到達することはできません。`[1,2,3]`から`[3,1,2]`なぜなら、そのためには非巡回置換パリティの変更が必要になるからです。 

## アプローチ

 強引なアイデアは、局所的な改善を使用して並べ替えをシミュレートすることです。正しい位置にない最小の要素を繰り返し見つけ、3 回転操作を使用して左に移動しようとします。 これはバブルソートに似ていますが、移動が制限されています。 

実際には、要素を 1 つの位置だけ左に移動することは直接不可能であるため、これはすぐに不明瞭になります。 代わりに、制御された位置の交換を効果的に実行する一連の 3 回転を使用する必要があります。`i`そして`i+1`3 番目の要素を使用します。 このような各スワップには一定の操作数がかかりますが、これをやみくもに実装すると構造が貧弱になり、必要な操作数を超える可能性があります。`n^2`慎重に整理しないと拘束されます。 

重要な洞察は、配列を左から右に固定することです。 位置で`i`、ソートされた順序に従ってどの要素をそこに配置する必要があるかを決定し、3 回の回転を使用してその要素を左に移動します。 操作`[a_i, a_{i+1}, a_{i+2}] -> [a_{i+2}, a_i, a_{i+1}]`制御された方法で要素をその前の 2 つの要素と交換することで、要素を効果的に左方向に回転させることができます。 これを繰り返し適用することで、ターゲット要素を正しい位置に向かって段階的に移動させるシミュレーションができます。 

ただし、構造上の制限があります。各操作は既知の不変式までの順列のパリティを保持するため、要素を貪欲に配置した結果、長さ 3 の回転では固定できない最終的な接尾辞が得られた場合は、拒否する必要があります。 これにより、最後の 2 つの要素の最終チェックが行われます。並べ替えがまだ完了していない場合は、許可されたローテーションを使用して残りの構成を解決できるかどうかを確認します。 実際には、これは、最終的に 2 レングスの交換だけが必要な位置で不一致があった場合、答えは不可能であるという標準的な条件につながります。 

機能する構造は、左から右への貪欲な配置と、繰り返しのローカル回転を組み合わせて、正しい要素を所定の位置に配置することです。`i`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 構造なしのブルートフォースバブリング | O(n^3) | O(n) | 遅すぎる/不安定 |
 | 3回転で貪欲に左から右へ | O(n^2) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 配列を維持し、ソートされた順序を段階的に構築します。 

1. 配列のソートされたバージョンを計算します。 これはターゲット構成であり、各位置に何を含める必要があるかを定義します。 
2. 位置を左から右に繰り返し、次の位置で停止します。`n - 2`。 それぞれのポジションで`i`、インデックスを見つけます`j`ここで、位置の正しい値は`i`現在在住。 
3. もし`j < i`、以前の位置がすでに固定されているため、何かが矛盾しています。 私たちが正しさを維持していれば、このようなことは起こりません。 
4. もし`j > i`で要素を移動します。`j`位置に達するまで左方向に`i`。 各ステップでは、位置で 3 回転を使用します。`k = j - 2`、相対的な順序制約を維持しながら、ターゲット要素を 1 ステップ左にシフトします。 
5. 各回転の後、デクリメントします。`j`局所構造に応じて 1 または 2 だけ変化しますが、効果的にはその距離を縮めています。`i`。 
6. 要素が所定の位置に配置されたら`i`に進みます。`i + 1`。 
7. ここまでの処理を行った後、`n - 2`、配列が完全にソートされているかどうかを確認します。 そうでない場合は、最大 2 回の最終ローテーションを使用して最後の小さなサフィックスを解決しようとします。 不可能な場合は出力します`-1`。 

### なぜ効果があるのか

 不変条件は、終了後の位置です。`i`、接頭辞`[0 .. i]`は固定されており、ソートされた配列と一致します。 3 回の回転によって要素がウィンドウの外に移動することはありません`[k, k+2]`したがって、要素が所定の位置に配置されると、`i`、後の操作が邪魔になることはありません。 これにより、単調な進行が保証されます。 置き忘れられた要素はすべて左に引っ張られるだけなので、`n`ポジションと各移動には一定の操作コストがかかり、操作の合計は次のように制限されます。`O(n^2)`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    ops = []
    
    b = sorted(a)
    
    for i in range(n - 2):
        # find target position
        j = i
        while j < n and a[j] != b[i]:
            j += 1
        
        while j - i >= 2:
            # apply rotation at j-2
            k = j - 2
            a[k], a[k+1], a[k+2] = a[k+2], a[k], a[k+1]
            ops.append(k + 1)
            j -= 2
        
        if j == i:
            continue
        
        # final adjustment if distance is 1
        if j == i + 1:
            # need to use a temporary rotation to resolve
            if i + 2 >= n:
                print(-1)
                return
            k = i
            a[k], a[k+1], a[k+2] = a[k+2], a[k], a[k+1]
            ops.append(k + 1)
            j = i
        
    if a != b:
        print(-1)
        return
    
    print(len(ops))
    print(*ops)

t = int(input())
for _ in range(t):
    solve()
```コア構造は貪欲なアライメント ループです。 実装の重要な詳細は、要素がどのように左に移動されるかです。各操作は次のように作用します。`(j-2, j-1, j)`ターゲットを2歩手前に近づけます。 これにより、不正な隣接スワップを直接シミュレートしようとすることが回避されます。 

最終チェック`a != b`これは、貪欲なプロセスによって、ローカルでは固定されているように見えても、グローバルではソートされていない構成 (特に最後の 2 つの位置付近) が残る可能性があるため、必須です。 

インデックスには注意が必要です。すべての操作は必要に応じて 1 から始まるインデックスに格納され、ループは範囲外のトリプルへのアクセスを回避します。

 ## 特殊なケース

 クリティカルなエッジ ケースは、正しい要素がすでにターゲット位置から距離 1 以内にあるにもかかわらず、その位置で終わる有効なトリプル ウィンドウがないために配置できない場合です。 たとえば、次のようなとき`i = n - 2`要素が次の位置にある場合、安全に回転を適用することはできません。`n - 1`、有効ではないため`(i, i+1, i+2)`存在します。 アルゴリズムは次のように要求することでこれを明示的に検出します。`i + 2 < n`最終調整の前に、無効な操作を試行しないようにします。 

もう 1 つの特殊なケースは、値が繰り返されることです。 重複が存在する場合、照合ステップでは正しい出現を確実に選択する必要があります。 そうしないと、要素を引っ張りすぎて正確さが損なわれる可能性があります。 貪欲なアプローチでは、ソートされていないサフィックスの左端の有効なオカレンスが常に使用され、ターゲットのマルチセット構造との一貫性が維持されます。
