 ## 解決策
 ## 問題の理解

 接続された無向グラフが与えられ、そのタスクは古典的なグラフのプロパティを計算することではなく、存在が保証されている 2 つのグローバル構造の 1 つを構築することです。 

最初に考えられる出力は、頂点の少なくとも半分を訪れる単純なパスです。 これは標準的なグラフ オブジェクトです。連続する頂点がエッジで接続されている一連の個別の頂点です。 

2 番目に考えられる出力は頂点のペアで、すべての頂点の少なくとも半分をカバーする素のペアを選択します。 この組み合わせは任意ではありません。 それは構造的制約を満たさなければなりません。任意の 2 つの選択したペアを選択し、関与する 4 つの頂点によって誘導されたサブグラフを見ると、その誘導されたサブグラフは非常にまばらで、可能な 6 つのエッジのうち多くても 2 つのエッジを含みます。 

この問題により、接続されたすべてのグラフがこれら 2 つの構造のうち少なくとも 1 つを受け入れることが保証されます。 課題は、それらの 1 つを常に効率的に構築することです。 

この制約により、テスト ケースごとに線形または線形に近い動作が求められます。 すべてのテスト ケースにわたる頂点の合計数は最大 5e5、エッジの合計は最大 1e6 であるため、エッジを繰り返しスキャンしたり、複数の DFS パスを実行したりするアルゴリズムは、全体で厳密に O(n + m) でなければなりません。 すべてのペアの相互作用をチェックしたり、候補構造ごとに接続性を再計算したりすることは、すぐには実行不可能です。 

ペアリング条件に微妙な問題が発生します。 隣接するノードのペアを回避したり、ツリー状に任意に一致させたりするだけでは十分ではありません。 単純な貪欲マッチングは、4 ノード制約に簡単に違反する可能性があります。 

たとえば、4 つのノードのサイクルを考えてみましょう。 反対側の頂点を任意にペアにすると、2 つのペア上に誘導された部分グラフに 3 つのエッジが含まれる可能性があり、規則に違反します。 これは、エッジ上の局所的な推論だけでは不十分であることを示しています。 条件はグローバルなペア間の相互作用に依存します。 

もう 1 つのエッジ ケースはスター グラフです。 単純なマッチングでは葉を恣意的にペアにしようとするかもしれませんが、慎重に構造化しないと、中心を含む 2 つのペア間に誘導された部分グラフによってエッジが過剰に作成される可能性があります。 

これらの問題は、ソリューションがローカル エッジ構造ではなく、スパニング ツリーと深さのパリティのグローバル構造を利用する必要があることを示唆しています。 

## アプローチ

 ブルート フォースの試行では、ペアを増分的に構築しようとし、追加するたびに、既存のすべてのペアが制約に関して有効なままであることを確認します。 これには、すべての新しいペアを以前のすべてのペアと比較してチェックし、チェックごとに隣接ルックアップを使用して 4 つの頂点間のエッジをカウントする必要があります。 n/2 ペアの最悪の場合、これは O(n^2) ペア チェックになり、各チェックのコストは最大で O(1) または O(n) に達し、壊滅的な二次または三次の動作につながる可能性があります。 

同様に、十分な長さの単純なパスをすべて探索してパスを検索しようとする試みは、基本的に長い単純なパスの存在を証明しようとしているため、単純に実行すると本質的に指数関数的になります。 

重要な点は、両方のエンドポイントを対称的に構築する必要がないということです。 必要な構造は、長いチェーン (パスの場合) のように動作するか、DFS ツリーによって誘導される 2 部構成のペアリング構造のように動作します。 

グラフに長い単純なパスがある場合は、すぐに作業が完了します。 それ以外の場合、DFS ツリーには境界分岐動作があり、多くのノードに「未使用の親子構造」が強制されるため、制御された方法でノードをペアにすることができるため、誘導されたすべての 4 ノード セットが最大 2 つのエッジを持つツリーのように動作します。 

重要なトリックは、グラフをルート化し、DFS を実行して、ルートからリーフまでの長いパスを抽出しようとすることです。 そのパスが短すぎる場合は、多くのノードが異なるサブツリーに存在し、密なサブグラフの生成を防ぐ方法で深さを超えてペアにすることができるという事実を利用します。

DFS 深さパリティ (同じ深さレイヤーにあるノード、または慎重に選択された交互の深さ) に従ってノードをペアリングすると、ペアリング戦略が明確になります。 これにより、ツリー エッジは隣接する深さを接続するだけであり、バック エッジは DFS 構造によって制御されるため、任意の 2 つのペア間では、誘導されたサブグラフのエッジが密なパターンを形成できないことが保証されます。 

DFS ツリーは、グラフを階層レベルに線形化するスケルトンとして機能し、すべての構造はこの階層内のペアリングまたは長いチェーンの抽出に帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースペアリング検証 | O(n^3) 最悪の場合 | O(n) | 遅すぎる |
 | DFS ツリーの構築 + 貪欲な抽出 | O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 テストケースごとに進めていきます。 

1. グラフの隣接リストを作成します。 エッジスキャンを繰り返さずに DFS ツリーを構築するには、高速トラバーサルが必要です。 
2. 任意のノードから DFS を実行し、親ポインターと深さを記録します。 これを実行している間、ルートから遭遇した最も深いパスの記録も維持します。 
3. 少なくとも ⌈n/2⌉ の長さのルートからノードへのパスが見つかった場合は、それを有効なパスとしてすぐに出力します。 これは要件を直接満たし、ペアリングを完全にバイパスするため安全です。 
4. そのような長いパスが存在しない場合は、DFS ツリー構造からペアリングの構築に進みます。 深度パリティまたは DFS オーダー バケットごとにグループ化されたノードを維持します。 
5. DFS ツリーのボトムアップ方式でノードを処理します。 各ノードについて、最初にペアになっていない子をペアにしようとします。 サブツリー内のペアリングにより、サブグラフ密度が増加する可能性のあるクロスサブツリー エッジの導入が回避されるため、これは重要です。 
6. 内部ペアリング後もノードにまだペアになっていない子がある場合は、それを上に移動し、別のサブツリーまたはその親チェーンのペアになっていないノードとペアリングしようとします。 
7. ペアの少なくとも ⌈n/2⌉ 頂点を収集するまで続けます。 すべてのノードは最大 1 回しか使用されないため、必要なカバレッジに達すると停止します。 

正確性は、DFS エッジがツリーを形成し、すべてのペアリングの決定がこのツリー構造に沿って行われるという事実に左右され、2 つのペアから誘導されたサブグラフには最大 2 つのツリー接続に対応するエッジのみが含まれることが保証されます。 3 番目の接続を作成する可能性のあるクロス エッジが 2 つの独立したサブツリーのペアの間に同時に導入されることはありません。 

### なぜ効果があるのか

 DFS ツリーは、すべてのエッジがノードをその祖先に接続するか、単一のサブツリー内に存在することを保証します。 上に移動する前に常にローカライズされた DFS 領域内でペアを形成することで、2 つのペアからの 4 つのノードが別々のブランチに存在するか、祖先と子孫のチェーンに沿って配置されることが保証されます。 どちらの場合も、DFS 構造に矛盾を生じさせずに、誘導されたサブグラフは 2 つを超えるエッジを蓄積することはできません。 これにより、制約に違反する密な相互接続パターンが防止されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    n, m = map(int, input().split())
    g = [[] for _ in range(n + 1)]
    for _ in range(m):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)

    parent = [-1] * (n + 1)
    depth = [0] * (n + 1)
    vis = [False] * (n + 1)

    path = []

    def dfs(u):
        vis[u] = True
        path.append(u)
        best = path[:]
        for v in g[u]:
            if not vis[v]:
                parent[v] = u
                depth[v] = depth[u] + 1
                cand = dfs(v)
                if len(cand) > len(best):
                    best = cand
        path.pop()
        return best

    best_path = dfs(1)

    if len(best_path) >= (n + 1) // 2:
        print("PATH")
        print(len(best_path))
        print(*best_path)
        return

    children = [[] for _ in range(n + 1)]
    for v in range(2, n + 1):
        if parent[v] != -1:
            children[parent[v]].append(v)

    pairs = []

    def dfs_pair(u):
        rem = []
        for v in children[u]:
            x = dfs_pair(v)
            if x != -1:
                rem.append(x)

        while len(rem) >= 2:
            a = rem.pop()
            b = rem.pop()
            pairs.append((a, b))

        if rem:
            return rem[0]
        return u

    dfs_pair(1)

    used = set()
    final_pairs = []
    for a, b in pairs:
        if a not in used and b not in used:
            used.add(a)
            used.add(b)
            final_pairs.append((a, b))

    print("PAIRING")
    print(len(final_pairs))
    for a, b in final_pairs:
        print(a, b)

t = int(input())
for _ in range(t):
    solve()
```DFS は 2 つの役割で使用されます。 まず、最適な再帰スタック パスを追跡することによって、ルートからリーフまでの長いパスを検出しようとします。 そのパスが十分に長い場合は、すぐに出力します。 

そうでない場合は、ツリーベースのペアリング戦略に切り替えます。 ルート化された DFS ツリーを構築し、各サブツリーが上向きに最大 1 つの一致しないノードを返すポストオーダー トラバーサルを実行します。 ノードが複数の不一致の子を受け取るたびに、サブツリー内でそれらを貪欲にペアにします。 これにより、ペアリングが局所化されることが保証されます。これは、誘導されたサブグラフの構造的制約を維持するために不可欠です。 

微妙な点は、一致しないノードが上方向に 1 回だけ伝播することです。これにより、サイズ要件に違反したり、ペアリングの不一致を引き起こす可能性のある方法で、ペアになっていないノードのチェーンが蓄積するのを防ぎます。 

## 実用的な例

 ノード 1 からの DFS が短い最大パスを生成する小さなツリー状のグラフを考えてみましょう。 DFS が最適なパスを返すと仮定します。`[1, 5, 3, 6]`そして、n = 6。 

最初に、再帰によって単純なパスが存在しないことが識別されるため、ペアリングに切り替えます。 DFS 親ポインターから子リストを構築し、ボトムアップで処理します。 

| ノード | 子供が戻る | ペアリング後のレム | 出力アクション |
 | --- | --- | --- | --- |
 | 3 | [] | [3] | 伝播3 |
 | 5 | [3、6] | [] | ペア (3, 6) |
 | 1 | [5] | [1] | 伝播1 |

 これにより 1 つのペア (3、6) が生成され、同様に他のペアが上位に形成されます。 

このトレースは、3 と 6 は同じサブツリー内にあり、サブツリー間のペアリングには決して参加しないため、サブツリーとローカルのペアリングによりブランチ間の干渉が回避されることを示しています。 

ここで、DFS ツリーが浅いが広い 2 番目のケースを考えてみましょう。 多くの葉は上向きに報告します。 内部ノード、たとえばノード 1 では、rem = [2, 4, 7, 9] が得られる可能性があります。 アルゴリズムはそれらを (9, 7) と (4, 2) としてペアにし、ペアになっていないものは何も残しません。 これは、ペアリング ステージがサブツリーの代表に対するスタック マッチングのように動作することを示しています。

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |

## 特殊なケース

 重要なエッジケースは、グラフが単純なパスである場合です。 その状況では、DFS は長さ n (常に少なくとも ⌈n/2⌉) のパスを即座に検出するため、アルゴリズムはペアリングをまったく試行してはなりません。 早期の終了により、有効な最適構造を不必要に分割しないことが保証されます。 

もう 1 つのエッジ ケースはスター グラフです。 DFS の深さは 2 であるため、長いパスは存在しません。 すべてのリーフは上向きのルートに戻り、ルートにペアになっていないノードの大きなリストが生成されます。 ペアリング ステップはリーフと任意に一致します。スター内の 2 つのペアは中心を通る最大 2 つのエッジを誘導し、制約を超えることはないため安全です。 

最後のエッジ ケースは、多くのサブツリーが単一の不一致ノードを返すバランスの取れたバイナリ ツリーです。 このアルゴリズムは、上に移動する前にこれらがローカルでペアになることを保証し、サブツリー間の相互作用が多すぎる可能性があるカスケードを防ぎます。
