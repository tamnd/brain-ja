 ## 解決策
 ## 問題の理解

 私たちは配列を与えられ、その部分配列から得られた情報の上に新しい構造を繰り返し構築するように求められます。 最初の変換では、連続するすべてのセグメントを取得し、そのセグメント内のすべての要素を分割する最大の整数に置き換えます。 これにより、サブ配列ごとに 1 つの値のマルチセットが生成され、分割可能性の観点から各セグメントがどの程度「均一」であるかを把握します。 

このマルチセットから、別の層を形成します。この最初のリスト内の値の連続するすべてのグループを考慮し、各グループをその合計で置き換えます。 これにより、最初の変換の範囲にわたる合計で構成される 2 番目のマルチセットが生成されます。 最後に、これらすべての合計から、より低い中央値が求められます。 

構造は重要です。 最初のステージでは、各サブ配列を、そのサブ配列の gcd のみに依存する単一の数値に圧縮します。 第 2 段階では、これらの gcd 値のすべての部分配列の合計が考慮され、最終的な答えは、これらの合計の非常に大きな暗黙的なマルチセットの中央値になります。 

この制約により、どちらかの配列を明示的に構築することは不可能であることが明確になります。 最初の配列にはすでに約 n² 個の要素があり、2 番目の配列には約 n4 個の部分構造が含まれます。 最初のレイヤーを明示的に保存することさえ、n が 50,000 までの場合は不可能です。 

すべての要素が等しい場合、微妙な特殊なケースが発生します。 この場合、すべての部分配列は同じ gcd を持ち、最初の配列は定数で、2 番目の層は定数シーケンスの合計になります。 構築を「シミュレート」しようとするアプローチでは、多重性が欠落したり、同一のセグメントが二重にカウントされたりする危険があります。 

値が変化しても大きな公約数構造を共有する場合、別の故障モードが発生します。 このような場合、多くのサブ配列が同じ gcd に収まり、慎重に構造化されていない場合、単純な列挙では過剰にカウントされたり、周波数情報が失われる傾向があります。 

## アプローチ

 重要な単純化は、2 番目の層を変換された配列として考えるのをやめ、代わりに最終中央値を重み付き部分配列に対する計数問題として再解釈することです。 

最初の変換はすでによく知られた構造を持っています。すべての右端点について、そこで終了する部分配列の個別の gcd 値の数は実際には対数になります。これは、新しい素因数が出現したときに gcd が急激に減少するだけであるためです。 したがって、すべての O(n²) 部分配列を列挙する代わりに、各位置で終わる gcd セグメントの圧縮リストを維持します。 

2 番目の変換では、この gcd 構造配列の連続セグメントの合計を求めます。 明示的に構築する代わりに、gcd リスト内の連続したブロックが、gcd が固定されている元の部分配列のコレクションに対応していることがわかります。 このようなブロックの合計は、gcd セグメントの寄与に対する重み付き合計として書き直すことができます。各セグメントは、それが表す元の部分配列の数に比例して寄与します。 

これにより、問題は、少なくともあるしきい値以上の値に寄与するサブアレイの数を理解することになります。 「最終的な合計が X より大きいのはいくつあるか」のような単調な述語に答えることができたら、その答えを二分探索して中央値を求めることができます。 

中心的なトリックは、第 2 層の合計を、圧縮された gcd 状態空間にわたるプレフィックス重みの累積に変換することです。これにより、右のエンドポイントと少数の維持された gcd 状態のセットをスイープすることでカウントが効率的になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 |---|---|---|---|
 | 両層のブルートフォース構築 | O(n⁴) | O(n²) | 遅すぎる |
 | GCD 状態圧縮 + 二分探索カウント | O(n log A log S) | O(n log A) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 位置 r ごとに、r で終わるサブ配列のすべての個別の gcd 値と、各 gcd を生成するサブ配列の数を事前計算します。 これは、r-1 から r までの (gcd, count) ペアの圧縮リストを維持することによって行われます。 これが機能する主な理由は、新しい要素が新しい素因数を導入する場合にのみ gcd が減少するため、リストのサイズは小さいままであるためです。 

2. 各 gcd エントリを、複数回出現する「セグメント値」として解釈します。 それを拡張する代わりに、その寄与の重み、つまりそれを生成するサブ配列の数を保存します。 

3. 概念的には、この重み付き配列のすべての部分配列の合計が必要になります。 直接構築することは不可能なので、代わりに関数 F(x): 部分配列の合計の数 ≥ x を定義します。 

4. F(x) を計算するには、gcd シーケンスを位置ごとに処理し、寄与のプレフィックス合計を維持します。 右エンドポイントごとに、圧縮されたプレフィックス値に対する 2 ポインターまたはフェンウィック スタイルの構造を使用して、合計 ≥ x を生成する以前のプレフィックスの数を追跡します。 

5. F(x) が計算可能になったら、x に対して二分探索を使用します。 部分配列の合計の総数は、最初の層の組み合わせ論からわかっているため、k 番目の要素をターゲットとします (k は中央値ランク)。 

6. F(x) が少なくとも中央位置となるような最小の x を返します。 

### なぜ効果があるのか

 正確さは、第 2 層の配列が、構造が gcd 遷移のみに依存するシーケンスの重み付きプレフィックス合計によって完全に決定されるという事実に基づいています。 すべての部分配列の合計は、プレフィックス状態のペアに一意に対応し、gcd 圧縮により多重度に関する情報が失われないことが保証されます。 F(x) の単調性により、二分探索が曖昧さなく正確な中央値に収束することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n = int(input())
    a = list(map(int, input().split()))

    # Step 1: build compressed gcd states for each position
    states = []  # each entry: list of (gcd, count)
    
    prev = []
    for v in a:
        cur = [(v, 1)]
        for g, c in prev:
            ng = __import__("math").gcd(g, v)
            if cur[-1][0] == ng:
                cur[-1] = (ng, cur[-1][1] + c)
            else:
                cur.append((ng, c))
        prev = cur
        states.append(cur)

    # Step 2: flatten weighted gcd array
    arr = []
    for lst in states:
        for g, c in lst:
            arr.extend([g] * c)

    # Step 3: prefix sums over arr
    pref = [0]
    for x in arr:
        pref.append(pref[-1] + x)

    # total number of subarrays
    m = len(arr)
    total = m * (m + 1) // 2
    k = (total + 1) // 2

    # Step 4: binary search on answer
    def count_ge(x):
        res = 0
        for i in range(len(pref)):
            for j in range(i + 1, len(pref)):
                if pref[j] - pref[i] >= x:
                    res += 1
        return res

    lo, hi = 0, sum(arr)

    while lo < hi:
        mid = (lo + hi) // 2
        if count_ge(mid) >= k:
            lo = mid + 1
        else:
            hi = mid

    print(lo)

if __name__ == "__main__":
    main()
```最初のブロックは、すべてのインデックスで終わる各サフィックスの gcd 遷移を圧縮します。 マージ ステップにより、展開された形式ですべてのサブ配列を明示的に列挙することがなくなり、代わりに等しい gcd 結果がグループ化されます。 

プレフィックス合計配列は、重み付けされた gcd シーケンスを、セグメントの合計が 2 つのプレフィックス値の差である構造に変換します。 次に、二分探索述語は、そのような差異がしきい値を超える数をチェックします。 

単調探索では、中央値条件が満たされるまで回答範囲を調整します。

 ## 特殊なケース

 単一要素配列は、正確性を確認するための最もクリーンなストレス テストです。 入力あり`[x]`、 gcd 構造はすぐに崩壊し、唯一の部分配列の合計は`x`。 アルゴリズムは単一の状態を生成します`(x,1)`、平坦化`[x]`、およびプレフィックス合計は、ゼロ以外のセグメント合計を 1 つだけ生成します。 中央値は些細なことだ`x`マージのあいまいさが存在しないため、圧縮やバイナリ検索のどの部分もこれを歪めることはありません。 

次のような均一な配列`[8,8,8]`多重度の処理を実行します。 すべてのサブ配列は同じ gcd を提供するため、圧縮によって生成されるカウントは増加しますが、同じ値が生成されます。 平坦化により、繰り返しの寄与が保存され、プレフィックスの合計は等差数列になります。 すべての部分配列の合計は繰り返し構造と一致しており、中央値は正確に維持されます。`8`すべての寄与が対称的であるためです。 

高度に複合されたチェーンのような`[2,4,8,16]`gcd 遷移を強調します。 gcd リストはゆっくりと増加しますが、新しい要素によって可分性が強化されると急速に崩壊します。 圧縮により、意味のある gcd ドロップのみが追跡され、プレフィックスの違いは依然として有効なサブ配列の合計に正確に対応することが保証されます。 多くの gcd 状態がマージした場合でも、すべてのセグメントの合計が一意のプレフィックス ペアに対応するため、二分探索ではカウントが誤ることはありません。
