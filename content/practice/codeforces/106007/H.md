 ## 解決策
 ## 問題の理解

 いくつかのテスト ケースが与えられ、それぞれのテスト ケースは 1 から n までのインデックスが付いた配列で構成されます。 インデックス 1 から開始し、インデックス n で終了する必要があります。 重要な移動ルールは、現在のインデックス i から、位置の差が最大 2 である限り、他のインデックス j にジャンプできるということです。言い換えれば、同じ位置のすぐ隣に移動することも、どちらの方向でも 1 つの位置だけスキップすることもできます。 

すべてのインデックスを 1 回だけ訪問する必要があるため、結果は、これらの移動制約の下で 1 から n までの有効なウォークを記述するインデックスの順列になります。 インデックスを訪問すると、訪問した各インデックスの値 a[i] を訪問順に追加してシーケンス b を構築します。 すべての有効なウォークの中で、辞書編集的に最小の結果シーケンス b が必要です。 

この制約では、すべてのテスト ケースにわたって要素の合計が最大 100,000 個まで許可されるため、ソリューションはテスト ケースごとに本質的に線形またはほぼ線形である必要があります。 テスト ケースあたり O(n²) のシミュレーションでは、最悪の場合約 10¹⁰ の操作が必要になるため、すでに遅すぎます。 

この問題の微妙な問題は、決定がローカルであるにもかかわらず、移動制限によってグローバルな制約が作成されることです。 現在のステップで最適と思われる貪欲な選択は、後で未訪問のインデックスをトラップする可能性があります。 

たとえば、インデックス 1 にいて、インデックス 2 と 3 の両方が使用可能な場合、接続に注意しないと、構成によってはすぐに 3 を選択すると 2 がブロックされる可能性があります。 この種の状況は、a = [?, ?, ?] のような小さなチェーンで発生し、中間ノードのスキップが早すぎると無効な完了が強制される可能性があります。 

n が小さい場合、別の特殊なケースが発生します。 n = 1 の場合、答えは自明です。 n = 2 の場合、1 から 2 に進む必要があります。n = 3 の場合、パス 1-2-3 と 1-3-2 の両方が許可され、値の辞書編集順のみがどちらが正しいかを決定します。 これらの小さなケースは、構造が固定されたパスではなく、制約されたハミルトニアン ウォークであることを明らかにするため、重要です。 

## アプローチ

 強引なアイデアは、これを、各インデックスがノードであり、インデックスの違いが最大 2 であるノード間にエッジが存在するグラフ問題として扱うことです。次に、1 から始まり n で終わるすべてのハミルトニアン パスを列挙しようとします。 有効なパスごとに、結果のシーケンス b を構築し、辞書編集上の最小値を取得します。 

これは原理的には正しいですが、ハミルトニアン パスの数は指数関数的に増加します。 中程度の n の場合でも、分岐係数は最大 4 (i ± 1、i ± 2) であり、局所的な隣接関係と一致するすべての順列を効果的に探索しています。 n = 30 でさえすでに天文学的な可能性があるため、これはすぐに実行不可能になります。 

重要な観察点は、グラフ構造が非常に制限されていることです。 各ノードは距離 2 以内のインデックスにのみ接続します。これは、未訪問のノードが常に非常に構造化された形状を形成することを意味します。常に、到達可能な未訪問のインデックスのフロンティアは小さく、現在の位置からの次の動きの候補は最大 4 つです。 さらに重要なのは、グラフでは長距離の依存関係が決して許可されないことです。 大きな切断された領域を「飛び越える」方法がないため、選択が有効かどうかはローカルで決定できます。 

これにより貪欲な構築が可能になります。 各ステップで、現在到達可能なすべての未訪問の近傍 (現在の位置から距離 2 以内にあるもの) を調べ、ウォークの実行可能性を保つ最小の a 値を持つものを選択します。 この問題では、実現可能性は構造自体によって保証されていることがわかります。残りの未訪問ノードは常に同じ移動ルールに従って接続されたままであるため、ローカルで有効な移動はグローバルな到達可能性を破壊しません。 

したがって、問題をパスの列挙から、ステップごとに最大 4 つの候補の中から最良のものを繰り返し選択することに軽減します。

 ## アルゴリズムのチュートリアル

 現在の位置と訪問した配列を維持します。 すべてのインデックスが使用されるまで、常にパスを一度に 1 ステップずつ拡張するという考え方です。 

### ステップ

 1. インデックス 1 から開始し、訪問済みとしてマークし、回答配列 b を a[1] で初期化します。 これは問題ステートメントによって強制されます。 
2. 各ステップで、j が未訪問であり、|j − current| となるようなすべてのインデックス j を考慮します。 ≤ 2. これらは、ウォークの 1 つのステップにおける唯一の正当な動きです。 
3. これらの候補の中から、値 a[j] が最も小さいものを選択します。 これにより、差異が現れる可能性のある最も早い位置で辞書編集上の最小性が貪欲に適用されます。 
4. 選択したインデックスに移動し、訪問済みとしてマークし、a[j] を b に追加します。 
5. すべてのインデックスにアクセスするまで繰り返します。 これらの制約の下で、1 から始まりすべてのノードをカバーする有効なハミルトニアン ウォークはすべて n で終了する必要があるため、最終位置は当然 n になります。 

### なぜ効果があるのか

 重要な特性は、グラフがエッジ |i − j| によって形成されることです。 ≤ 2 は局所的に十分に密であるため、貪欲な選択によって未訪問のノードを分離することはできません。 どのノードにも近くのインデックスへの接続があるため、将来の考慮事項からノードを削除しても、残りの未訪問のインデックスが到達不能なコンポーネントに分割されることはありません。 このため、すべてのステップを独立して処理できます。使用可能な最小の近傍を選択すると、常にパスが完全に有効に完了します。 

これにより、問題は、辞書編集上の順序が局所的な最適な選択肢と一致するという純粋に貪欲な構造に変わります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        visited = [False] * n
        cur = 0
        visited[cur] = True
        
        res = [a[cur]]
        
        for _ in range(n - 1):
            candidates = []
            
            for d in (-2, -1, 1, 2):
                nxt = cur + d
                if 0 <= nxt < n and not visited[nxt]:
                    candidates.append(nxt)
            
            # pick the best by value
            best = min(candidates, key=lambda x: a[x])
            
            visited[best] = True
            res.append(a[best])
            cur = best
        
        print(*res)

if __name__ == "__main__":
    solve()
```実装は貪欲ルールに直接に従います。 訪問済み配列により、インデックスを再訪することがなくなり、ハミルトニアンの要件が維持されます。 各ステップで最大 4 つの近傍をスキャンするため、選択は一定時間になります。 現在のインデックスは各移動の直後に更新され、結果は増分的に構築されます。 

微妙な点は、移動を選択した後に全体的な実現可能性を明示的に確認する必要がないことです。 グラフの構造により、距離 2 以内の未訪問の隣接ノードに常に移動する限り、すべてのノードが消費されるまで続行できることが保証されます。 

## 実用的な例

 ### 例 1

 n = 4 および a = [4, 3, 1, 2] の入力を考えてみましょう。 

インデックス 1 から始めます。 

| ステップ | 現在 | 候補者 | 選ばれた | b |

 | 3 | 2 | 4 | 4 | 4 1 3 |
 | 4 | 4 | - | - | 4 1 3 2 |

 ここでの重要な観察は、インデックス 2 が 1 の直接の隣であるにもかかわらず、最初にインデックス 3 にジャンプするとより小さい値が得られ、それでも完了できるということです。 

### 例 2

 n = 3 で a = [3, 1, 2] を考えます。 

| ステップ | 現在 | 候補者 | 選ばれた | b |

 | 1 | 1 | 2、3 | 2 | 3 |
 | 2 | 2 | 3 | 3 | 3 1 |
 | 3 | 3 | - | - | 3 1 2 |

 この例は、各ステップでの貪欲な選択が全体的な辞書編集上の最適化と一致していることを示しています。

    import sys
    input = sys.stdin.readline

    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        visited[cur] = True

            visited[best] = True
            res.append(a[best])
            cur = best
        
        out.append(" ".join(map(str, res)))
    return "\n".join(out)

 ## 特殊なケース

 n = 1 の場合、考慮すべき候補がないため、アルゴリズムはただちに単一の値を出力します。 訪問されたロジックはループに入らないため、出力は構造的に正しいものになります。 

n = 2 の場合、インデックス 1 から開始し、唯一の有効な手はインデックス 2 です。貪欲ルールが適用されても、候補は 1 つだけであるため、アルゴリズムは唯一の有効なハミルトニアン パスを決定的に生成します。 

n = 3 の場合、a = [3, 1, 2] と仮定します。 インデックス 1 からは、インデックス 2 と 3 の両方に到達可能です。 a[2] の方が小さいため、アルゴリズムはインデックス 2 を選択します。 2 に移動した後、残っているノードは 3 だけなので、ウォークは正しく完了します。 これは、スキップが利用可能な場合でも、早期の貪欲な選択によって完了がブロックされないことを示しています。 

a = [5, 4, 3, 2, 1] のような厳密に減少する配列の場合、すべてのステップに明確な最小近傍があり、アルゴリズムはノードをスキップすることなく一貫したパスに沿って効果的に歩きます。 これは、値がすでに順序付けされている場合、貪欲ルールは自然に単純な線形走査に退化することを示しています。
