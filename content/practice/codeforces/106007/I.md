 ## 解決策
 ## 問題の理解

 一連の数値と、それに対して実行するいくつかの操作が与えられます。 各操作では常に、シーケンスの現在の最初の要素が削除され、残っている要素はすべて元に戻されます。 これは正確に k 回繰り返され、これらすべての変換後に最終シーケンスを出力する必要があります。 

このプロセスについて考えると、配列の方向が反転し続けながら、繰り返し前から剥がされると考えると便利です。 削除するたびに、残りのサフィックスの相対的な順序は、すでに発生した反転の数に応じて変化するため、文字通りに実行すると直接シミュレーションのコストが高くなります。 

制約により、n は最大 100000 まで許可されるため、物理的に配列を k 回反転したり、要素を繰り返しシフトしたりするアプローチは遅すぎます。 単純なシミュレーションでは、最大 k 個の除去が実行され、各反転のコストは O(n) となり、O(nk) が得られますが、最悪の場合は O(n^2) に縮退するため、許容できません。 

単純な間違いを明らかにする微妙なエッジケースが 2 つあります。 まず、k が n マイナス 1 に近い場合、配列は非常に短くなり、反転を繰り返すと先頭と末尾が急速に変化するため、インデックスを正しく更新することを忘れた実装は失敗します。 たとえば、入力 n = 5、k = 4、a = [1, 2, 3, 4, 5] の場合、プロセスでは 1 つの要素のみが残されるはずですが、誤ったポインターベースのシミュレーションでは、交互の方向エラーにより要素が削除されたり重複したりすることがよくあります。 

第 2 に、ここでは k = 0 が禁止されているが、一般的に考えると、または k = 1 の場合、単純な実装では、削除後ではなく削除前に逆転する可能性があり、結果が完全に変わります。 たとえば、[1, 2, 3, 4]、k = 1 では、[4, 3, 2] ではなく、[2, 3, 4] が生成されます。 

最大の難点は、シーケンスが縮小するだけでなく、配列自体を変更せずに追跡できる構造化された方法で方向が交互に変わることです。 

## アプローチ

 直接的な総当たりアプローチは、文字通り、説明された操作を実行します。 リストの最初の要素を削除し、残りを反転して、これを k 回繰り返します。 デキューを使用する場合、各削除は O(1) ですが、残りの n i 要素の各反転は O(n i) となり、合計は O(n + (n−1) + … + (n−k))、つまり O(nk) になります。 k が大きい場合、入力のサイズは 2 次になります。 

重要な観察は、実際には中間配列が必要ないということです。 k 回削除した後にどの要素がどのような順序で残るのかを知る必要があるだけです。 この操作により、残りのセグメントが読み取られる方向が交互になります。 反転をシミュレートする代わりに、残りの配列の現在の左右の境界を表す 2 つのポインターと、現在の向きが通常か反転かを表すブール値フラグを維持できます。 

各操作では、方向に応じてアクティブなフロントから 1 つの要素が削除されます。 通常の向きの場合は、左側から削除します。 逆の場合は右側から削除します。 取り外した後、向きを反転します。 これにより、実際の配列反転の必要がなくなります。 

これにより、プロセス全体が O(k) ポインター更新に削減され、k < n ≤ 100000 であるため、簡単に効率的になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nk) | O(n) | 遅すぎる |
 | 方向フラグを持つ 2 つのポインター | O(k) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 2 つのインデックス、l は 0 から始まり、r は n − 1 から始まり、ブール変数 rev は最初は false で、左側から読み取ることを意味します。

1. l = 0 および r = n − 1 を初期化し、rev = false を設定します。 これは、アクティブなセグメント全体とその現在の方向を表します。 
2. これを k 回繰り返し、各ステップで回転数に応じてセグメントのどちらの端が「前」であるかを決定します。 rev が false の場合、フロントは l にあり、それ以外の場合は r にあります。 これは、すべての暗黙的な反転後の現在の配列とまったく同じです。 
3. rev が false の場合、l を 1 ずつ増分して、一番左の要素を削除します。 rev が true の場合、r を 1 減算して右端の要素を削除します。 これは、物理的に何も再配置せずに、現在の方向の最初の要素を削除することをシミュレートします。 
4. 取り外すたびに回転を反転します。 これにより、残りの配列を反転した効果がキャプチャされます。 要素を再配置するのではなく、どちら側を正面として解釈するかを変更するだけです。 
5. k 回の操作の後、残りのセグメントは区間 [l, r] になります。 最終的な方向は回転数によって決まります。 rev が false の場合、要素は l から r まで昇順に出力されます。 rev が true の場合、r から l までの要素が降順で出力されます。 

### なぜ効果があるのか

 どの時点でも、残りの配列は、連続セグメント [l, r] に制限された元の配列とまったく同じですが、逆転が発生した回数に応じて、逆の順序で表示される可能性があります。 各操作では、このセグメントの 1 つの端点が削除され、方向の解釈が反転されます。 不変条件は、現在の論理配列が常に元の配列の連続スライスと方向フラグとして表現できることです。 削除と反転の両方がこの構造を保持するため、操作によって不連続性が生じたり、グローバルな反転を超えて要素の順序が変更されることはありません。 これにより、ポインターの動きと 1 つのブール値フラグが進行中の状態を完全に記述することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())
a = list(map(int, input().split()))

l, r = 0, n - 1
rev = False

for _ in range(k):
    if not rev:
        l += 1
    else:
        r -= 1
    rev = not rev

if not rev:
    res = a[l:r+1]
else:
    res = a[l:r+1][::-1]

print(*res)
```実装では 2 つの境界 l と r が維持され、現在の方向に従ってそれらが更新されます。 ブール値 rev は、論理方向が反転したかどうかを追跡します。 k ステップの後、残りのセグメントを抽出します。 唯一の微妙な点は最終出力です。向きが逆の場合は、明示的にスライスを一度反転する必要があります。 これにより、各ステップで配列全体が反転することが回避され、解が線形に保たれます。 

ちょうど k 回の削除が完了するまでループは常に l ≤ r を保証するため、境界の処理は簡単です。 

## 実用的な例

 ### 例 1

 入力:

 n = 5、k = 2

 a = [1、2、3、4、5]

 | ステップ | l | r | 回転 | 削除されました | セグメントの解釈 |
 | --- | --- | --- | --- | --- | --- |
 | 0 | 0 | 4 | 偽 | - | [1、2、3、4、5] |
 | 1 | 1 | 4 | 本当 | 1 | 逆さまのビュー |
 | 2 | 1 | 3 | 偽 | 5 | 通常のビュー |

 2 回の操作の後、残りのセグメントは [1, 3] となり、これは [2, 3, 4] に対応します。 出力は次のとおりです。 

2 3 4

 これにより、反対側からの交互の除去が方向フラグによって正しく処理されることが確認されます。 

### 例 2

 入力:

 n = 6、k = 3

 a = [10、20、30、40、50、60]

 | ステップ | l | r | 回転 | 削除されました | セグメントの解釈 |
 | --- | --- | --- | --- | --- | --- |
 | 0 | 0 | 5 | 偽 | - | [10、20、30、40、50、60] |
 | 1 | 1 | 5 | 本当 | 10 | 反転 |
 | 2 | 1 | 4 | 偽 | 60 | 通常 |
 | 3 | 2 | 4 | 本当 | 20 | 反転 |

 残りのセグメントは [2, 4] で、[30, 40, 50] となり、出力と一致します。 

これは、削除が両端を交互に行っても、表現が決して壊れないことを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

 | 時間 | O(k) | 各操作は 2 つのポインターを更新し、フラグを 1 回反転します。 
| スペース | O(n) | 入力配列が保存されるため、追加の構造は必要ありません。 

k と n が最大 100000 であるため、解は制約内に問題なく収まります。各演算は定数時間であり、最終的な反転は 1 回だけ実行されます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、k が配列のほぼ全体を削除する場合です。 入力を考慮してください:

 n = 5、k = 4、a = [1、2、3、4、5]

 このプロセスでは要素を 1 つだけ残す必要があります。 ポインタのシミュレーションは次のように進行します。最初は l = 0、r = 4 です。最初の削除では左から 1 が取られるため、l は 1 になり、rev は true になります。 2 番目は右から削除され、r は 3 になります。3 番目は左から削除され、l は 2 になります。4 番目は右から削除され、r は 2 になります。セグメントは単一の要素 [3] に折りたたまれ、正しく出力されます。 

もう 1 つのエッジ ケースは最小 k = 1 です。 

n = 4、k = 1、a = [1、2、3、4]

 左から 1 を削除して [2, 3, 4] を残します。その後、ステップが 1 つだけ実行されるため、反転は最終出力には関係ありません。 このアルゴリズムは、ポインターのインクリメントを 1 回実行し、向きを 1 回反転して l = 1、r = 3、rev = true を生成するため、これに正確に一致しますが、スライスの最後の反転により正しい順序が復元されます。 

最後の微妙なケースは、最後のセグメントがすでに逆向きになっている場合です。 たとえば:

 n = 3、k = 2、a = [7、8、9]

 2 回の操作の後、セグメントは [1, 1] になり、rev はパリティに応じて false または true になります。 このアルゴリズムは、最終スライスが 1 回だけ反転されることを保証し、一貫性のない順序につながる構造変更の繰り返しを回避します。
