 ## 解決策
 ## 問題の理解

 次のような有向グラフが与えられます。$n$各ノードは都市を表し、最大 2 つの発信エッジを持ちます。 アリスは街から始まる$1$そして街に行きたいと思っています$n$。 途中で、彼女は任意に何度も都市を再訪問する可能性があり、事実上、グラフ内のサイクルを横断することができます。 

各都市には、固定サイズの石の山もあります。 アリスが都市を訪れるときはいつでも、その都市の山を取得することを選択できますが、各都市から取得できるのは旅全体で最大 1 回だけです。 彼女が街に着くまでに$n$、彼女は効果的に「使用する」パスによって決定されるパイルサイズのサブセットを収集することになります。 

彼女が到着すると、収集された山は標準的な Nim ゲームを形成します。各山は独立した山であり、プレイヤーは交互に 1 つの山から正の数の石を取り除きます。 アリスは2番目に移動します。 最適な Nim プレイは完全にパイル サイズの XOR によって特徴付けられるため、選択されたすべてのパイル サイズの XOR がゼロ以外の場合に限り、アリスが勝ちます。 

したがって、実際のタスクは、アリスが徒歩を選択できるかどうかを決定することです。$1$に$n$そして、重みの XOR がゼロ以外になるように、そのウォークに沿ってノードのサブセットを選択します。 

グラフ構造は重要な制約です。 まで$10^5$ノードが多く、各ノードが出ていくエッジが最大 2 つある場合、グラフはまばらですが、サイクルの存在は、指数関数的に多くの異なるパスと再訪問パターンが存在する可能性があることを意味します。 すべてのパスまたはサブセットを単純に探索することは不可能です。 

からのすべてのパスが存在する場合、微妙なエッジ ケースが発生します。$1$に$n$到達可能なノードの組み合わせの固定セットのみを許可し、事実上単一の XOR 結果を強制します。 たとえば、すべてのパスがまったく同じノードのマルチセットを訪問する場合 (分岐によって到達可能性が変わらないため)、アリスは XOR にまったく影響を与えることができません。 もう 1 つの例外的なケースは、自転車で繰り返しの再訪問が許可されている場合です。これは、値を繰り返し含めることを示唆している可能性がありますが、「都市ごとに最大 1 回」というルールにより、到達しやすさ以外の自転車による利点が失われます。 

## アプローチ

 強引な解釈により、都市から可能なすべての徒歩ルートを列挙しようとします$1$街へ$n$。 ウォークごとに、アリスは訪問したノードの任意のサブセットを選択できるため、各パスは指数関数的に多くの XOR サブセットに対応します。 サブセットの選択を無視したとしても、サイクルを含むグラフ内の個別のウォークの数は爆発的に増加し、簡単に指数関数的に増加する可能性があります。$n$。 分岐要素はノードごとに最大 2 であるため、パスの数だけで次の数に達する可能性があります。$2^n$最悪の場合、DAG のような構造になり、列挙が不可能になります。 

重要な簡素化は、移動を選択から分離することで実現します。 移動はどのノードが一貫した方法で到達可能であるかを定義し、選択はそれらの到達可能なノードに対する XOR の選択肢を定義します。 ノードを再訪問してもその値を再度取得することはできないため、サイクルは到達可能性と接続性の制約を決定する場合にのみ重要になります。 

この問題を、あるパスに沿ってノード値のどのサブセットが「アクティブ化可能」であるかについての推論に変換します。$1$に$n$。 これは、XOR 状態追跡によって強化されたグラフ到達可能性の問題になります。 各状態は、現在のノードとこれまでに蓄積された現在の XOR 値のペアとして見ることができます。 ただし、BFS を直接実行すると、$(node, xor)$XOR 値が次の値に達する可能性があるため、これも大きすぎます。$10^6$、約までを意味します$2^{20}$可能な状態。 

構造的なブレークスルーは、グラフの出次数が最大 2 であることに気づくことです。これにより、到達可能性に関する動的プログラミングを使用して、XOR 状態にわたる決定論的な遷移システムに動作を圧縮できるようになります。 すべての XOR 値をノードごとに明示的に追跡する代わりに、各ノードで達成可能な XOR 状態のセットを維持しますが、XOR 遷移が線形構造を形成することをさらに活用します。$\mathbb{F}_2$。 各ノードは「テイク」または「スキップ」のいずれかを提供し、ノードを取得すると XOR が反転されます。$a_i$。 したがって、グラフ内を移動すると、ノードの訪問のみに依存する XOR 更新が引き起こされます。 

このプロセスを次のように再解釈できます。すべての有効なパスは、次のように到達可能なノードのセットに対応します。$1$に$n$そして、任意の走査に沿って、到達可能性の順序を尊重するそれらのノードのサブセットを選択できます。 順序制約はノード間の唯一の結合です。 

これは、からのパスが存在するかどうかを計算することに帰着します。$1$に$n$そのため、訪問ノードのマルチセットは、ゼロ以外の XOR を持つサブセットを許可します。 アリスはパスに沿ってサブセットを自由に選択できるため、唯一の障害は、到達可能なノード値のすべての可能なサブセットが XOR ゼロに崩壊する場合です。これは、到達可能な値の線形スパンが空であるか、ゼロのみを強制する場合に正確に発生します。 実際には、これは、あるパス上に非ゼロ基底要素の導入を可能にするサイクル到達可能性構造が存在するかどうかをチェックすることになります。これは、グラフを通じて XOR 基底情報を伝播することで検出できます。 

したがって、ノードから DP のようなトラバーサルを実行します。$1$、各ノードで到達可能な XOR 値の基礎を維持します。 複数のパスがマージする場合、それらの XOR ベースをマージします。 答えは、ノードが$n$ゼロ以外の XOR 状態を実現できます。

 ## アルゴリズムのチュートリアル

 1. ゼロ エッジを無視して、各ノードの出力エッジから隣接リストを構築します。 これにより、各ノードが最大 2 つの近傍を持つ有向グラフが得られます。 
2. ノードからの到達可能性トラバーサルを実行します。$1$への有効なパス上に現れる可能性のあるすべてのノードを識別します。$n$。 これにより、宛先に関係なく行き止まりに情報が伝播することがなくなります。 
3. ノードごとの XOR 基底情報の構造を維持します。各ノードには、そこに到達する有効なパスに沿って選択されたノードのサブセットによって達成可能なすべての XOR 合計を表す値の小さな線形基底が格納されます。 
4. ノードでの基底の初期化$1$のみを含むものとして$a_1$、アリスは最初の山をすぐに取ることを選択するかもしれないからです。 
5. BFS またはトポロジに似た伝播方法でグラフを走査し、隣接ノードを更新します。 から移動するとき$u$に$v$、からすべての XOR 基底要素を伝播します。$u$の中へ$v$、さらに追加を検討してください$a_v$選択可能な要素として。 これは都市を選択するかスキップするかの選択をモデル化します$v$。 
6. 基底をマージするときは常に、XOR 空間上のガウス消去法を使用して各要素をターゲット基底に挿入します。 これにより、基礎が最小限かつ効率的に保たれます。 
7. 任意の時点でノードのベースが存在する場合$n$ゼロ以外の XOR 構成を表すことができる場合は、YES を返します。 それ以外の場合は、到達可能なすべての状態を処理した後、NO を返します。 

### なぜ効果があるのか

 からのそれぞれのパス$1$に$n$ノードの順序付けされたシーケンスを定義します。 アリスの選択は、それらのノードのサブセットの選択に正確に対応し、そのシーケンスに沿った重みのサブセットの XOR 合計に変換されます。 各ノードで維持される XOR ベースは、有効なプレフィックス パスに沿ったサブセットのすべての達成可能な XOR の組み合わせを表します。 XOR 演算はビット上のベクトル空間を形成するため、異なるパスに沿って基底をマージすると、サブセットやパスを明示的に列挙することなく、考えられるすべての XOR 結果が保存されます。 したがって、このアルゴリズムは、宛先で到達可能な XOR 結果の完全なセットをキャプチャします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

# Insert x into XOR basis (standard linear basis over integers)
def add_basis(basis, x):
    for b in basis:
        x = min(x, x ^ b)
    if x:
        basis.append(x)
        basis.sort(reverse=True)

def merge_basis(a, b):
    res = a[:]
    for x in b:
        add_basis(res, x)
    return res

def can_make_nonzero(basis):
    return any(x != 0 for x in basis)

n = int(input())
g = [[] for _ in range(n + 1)]

for i in range(1, n + 1):
    u, v = map(int, input().split())
    if u:
        g[i].append(u)
    if v:
        g[i].append(v)

a = [0] + list(map(int, input().split()))

# reachable nodes
from collections import deque

reach = [False] * (n + 1)
q = deque([1])
reach[1] = True

while q:
    u = q.popleft()
    for v in g[u]:
        if not reach[v]:
            reach[v] = True
            q.append(v)

# DP of bases
dp = [None] * (n + 1)
dp[1] = [a[1]]

q = deque([1])

while q:
    u = q.popleft()
    if dp[u] is None:
        continue
    for v in g[u]:
        if not reach[v]:
            continue
        new_basis = merge_basis(dp[u], [a[v]])
        if dp[v] is None:
            dp[v] = new_basis
            q.append(v)
        else:
            merged = merge_basis(dp[v], new_basis)
            if merged != dp[v]:
                dp[v] = merged
                q.append(v)

print("YES" if dp[n] and can_make_nonzero(dp[n]) else "NO")
```実装は、ノードごとに 2 つの発信エッジから隣接リストを構築することから始まります。 到達可能性パスにより、目的地に到達する可能性のある状態のみが伝播され、ノードへの到達にまったく寄与しない無駄なサイクルが回避されます。$n$。 

の`add_basis`関数は、縮小された XOR 基底を維持し、XOR 縮小を使用して線形依存性を排除しながら各候補値を挿入します。 これは、保存された状態の指数関数的な増加を防ぐ中心的なメカニズムです。 

DP はキューを使用して、改善された基底状態を前方に伝播します。 ノードがより厳密に優れたベースを受け取るたびに再処理され、到達可能なすべての構成にわたって最終的に安定化が保証されます。 これは精神的には最短経路緩和と似ていますが、「距離」がより豊かな代数状態に置き換えられる点が異なります。 

最終チェックでは、単にノードが$n$はゼロ以外の表現可能な XOR を持ち、これは、Alice が勝利する Nim 構成を構築できることに直接対応します。

 ## 特殊なケース

 重要なエッジ ケースは、グラフがすべて同じ値を共有するノード間で純粋なサイクルを形成する場合です。 アリスは無限にループできますが、値を再収集することはできないため、このサイクルは新しい XOR の柔軟性には寄与しません。 ノードを再訪しても基底が拡張されないため、アルゴリズムはこれを処理します。そのため、伝播はすぐに安定し、人為的な新しい状態を作成できません。 

別のエッジ ケースは、複数の着信パスがノードに到達するが、すべてが同一の XOR ベースを伝送する場合に発生します。 単純な BFS はノードを無限または冗長に再処理する可能性がありますが、厳密に新しい XOR 情報が表示されない限り、基準比較により更新が防止されます。 これにより、密なマージ構造でも確実に収束します。 

最後のエッジケースは、ノードが$n$には到達可能ですが、概念的には 1 つの値を複数回強制的に含めるパスを経由する必要があります。 各ノードが寄与するのは最大 1 回だけであるため、アルゴリズムは重複のカウントを正しく回避し、基底表現はすべての組み合わせを線形独立に減らすことで過剰カウントを防ぎます。
