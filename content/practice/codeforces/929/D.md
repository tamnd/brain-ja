 ## 問題の理解

 この問題は、次のもので構成される 1 次元の世界を記述します。$n$ゾーンが一列に並んでいます。 移動は隣接するゾーン間でのみ可能ですので、ゾーンから$i$に行くことができます$i-1$または$i+1$それらが存在する場合。 隣接するゾーン間の各境界線には色があり、その色によってその境界線を越えることが許可されるかどうかが決まります。 

制限は色の境界線を越えることです$c$色の鍵を与える神社を含むゾーンを少なくとも 1 つ訪れたことがある場合にのみ可能です$c$。 各ゾーンには神社が 1 つだけ含まれており、各神社には 1 つの色の鍵が与えられます。 キーを取得すると、その色のすべての境界線を何度でも自由に越えることができ、越えるたびに 1 回の移動が必要になります。 神社を参拝すること自体は移動を消費しません。 

ゾーンから移動するために必要な国境通過の最小回数を計算するように求められます。$a$ゾーンへ$b$、キーがまったくない状態から始まります。 到達不可能な場合$b$、答えは$-1$。 

構造は一見単純な折れ線グラフですが、エッジを横断する能力は動的に増加する一連の「ロック解除された色」に依存しており、色のロックを解除する唯一の方法は、事前にロックを解除しないとアクセスできないゾーンに物理的に到達することです。 

制約$n \le 100{,}000$アクセシビリティを最初から再計算しながら最短パスを繰り返しシミュレートするアプローチは除外してください。 フォームの状態に対する単純な BFS$(position, key set)$キー セットが大きく、組み合わせで増加するため、これは不可能です。 新しい色のロックを解除するたびにディクストラを繰り返し実行しても遅すぎます。 

微妙な失敗例は、貪欲な動きが「有用な色の最も近い神社がすぐに取られるべきである」と仮定したときに発生します。 たとえば、左に移動するには色 1 が必要ですが、最も近い色 1 の神社が色 2 の壁の後ろにあり、それ自体がラインの奥にある別の神社を必要とするとします。 キーの取得を計画せずに常にターゲットに向かう単純な貪欲なウォークは、たとえ迂回ロック解除シーケンスが存在していても、途中で行き詰まってしまう可能性があります。 

## アプローチ

 重要な観察は、色のセットが既知になると、ライン構造により到達可能間隔が適切に構造化されるということです。 

使用できる色がすでにわかっていると一時的に仮定すると、問題は、許可された色に対してのみエッジが存在するグラフ内の最短経路に帰着します。 直線上での最短パスは、到達可能なゾーン間のエッジの距離にすぎません。 

難しいのは、キーがゾーン自体に配置されているため、使用可能な色のセットがどのゾーンにすでに到達できるかによって異なることです。 

ブルートフォース戦略では、この依存関係を直接シミュレートしようとします。 BFS を実行できるのは、$a$, but whenever we enter a new zone we add its color to the available set and then restart BFS to propagate newly unlocked edges. 最悪の場合、それぞれの$n$色は、到達可能な領域全体の再拡張を引き起こし、$O(n^2)$行動。 

重要な洞察は、意味のある方法で同じゾーンを再訪する必要がないということです。 キーを含む状態という観点から考えるのではなく、視点を反転します。各色を、その色のすべてのエッジに沿った動きを「アクティブ化」するものとして扱い、そのアクティブ化がいつ有効になるかを尋ねます。 

これは 2 層構造を示唆しています。色ごとに、その神社がどこに表示されるかを知る必要があり、色ごとに、それらの神社の少なくとも 1 つに到達したかどうかを知る必要があります。 色の神殿に到着したら$c$、 色$c$はグローバルに使用できるようになり、その色のすべてのエッジを自由に横断できるようになり、さらなる神殿のロックが解除される可能性があります。 

これは当然、色と位置を同時に扱う BFS としてモデル化されますが、ライン上の到達可能なセグメントを拡張することで効率的に実装されます。 

最初から現在の到達可能な間隔を維持し、新しい色のロックを解除するたびにそれを拡張します。 到達可能な領域内または隣接する神社を発見するたびに、その色のロックを解除し、その色のすべての端を使用して再度拡張しようとします。 各ゾーンと各カラーは 1 回だけ処理されるため、合計の作業量は線形のままです。

 ## アルゴリズムのチュートリアル

 この問題を、到達可能なゾーンを発見するプロセスとして再構成します。$a$、その色の神社に遭遇するとすぐに、徐々に色のロックを解除しながら。 

1. 隣接情報を前処理します。色ごとに、その神社の色を含むすべてのゾーンの位置を保存します。 これにより、最初にいずれかのゾーンに到達したときに、その色をすぐにアクティブにすることができます。 
2. 色のエッジを横断するため、エッジも色ごとにグループ化します。$c$一度可能になる$c$ロックが解除されています。 
3.ゾーンからスタート$a$、訪問済みとしてマークし、それを使用して BFS キューを初期化します。 また、最初は空の、ロックされていない色のセットも維持します。 
4. ゾーンの処理中$x$、すぐにその神社の色のロックを解除します$k[x]$まだロックが解除されていない場合。 これが新たな横断力を獲得する唯一の方法です。 
5.新色のとき$c$ロックが解除されると、色のすべてのエッジがスキャンされます$c$。 すでに到達可能なそのようなエッジの端点は、それらのエッジを介してさらに伝播できるようになり、色で接続されたすべてのコンポーネントに沿って到達可能な領域を効果的に拡張できます。$c$。 
6. ゾーン上で BFS を実行しますが、ネイバーをキューに入れるだけです$y$間のエッジの場合$x$そして$y$すでにロックが解除されている色があります。 これにより、合法的な境界線のみを通過することが保証されます。 
7. 最初にゾーンに到達したら停止します$b$、BFS は通過するエッジの最小数を保証するためです。 

### なぜ効果があるのか

 すべてのステップで、ロック解除された色のセットは、現在到達可能な領域で神社に到達している色のセットと正確に一致します。 移動はすでにロックが解除されている色に沿ってのみ可能であるため、新しく到達可能なゾーンは、すでに有効なエッジのシーケンスを介して到達可能である必要があります。 BFS は、そのようなシーケンスをすべてエッジ交差の昇順で探索することを保証します。 

不変条件は、BFS フロンティアは常に、最小数の交差を使用して現在のロック解除された色のセットで到達可能なすべてのゾーンを表し、新しい色のロックを解除しても、以前に計算された距離を無効にすることなくこのセットを拡張するだけであるということです。 BFS は距離の増加順に状態を処理するため、必要以上に高いコストでゾーンが訪問されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import deque, defaultdict

n, a, b = map(int, input().split())
a -= 1
b -= 1

g = list(map(int, input().split()))
k = list(map(int, input().split()))

edges = defaultdict(list)
for i, c in enumerate(g):
    edges[c].append(i)

pos_of_color = defaultdict(list)
for i, c in enumerate(k):
    pos_of_color[c].append(i)

adj = [[] for _ in range(n)]
for i, c in enumerate(g):
    adj[i].append((i + 1, c))
    adj[i + 1].append((i, c))

unlocked = set()
dist = [-1] * n
dist[a] = 0

q = deque([a])

while q:
    x = q.popleft()

    c = k[x]
    if c not in unlocked:
        unlocked.add(c)

    for y, col in adj[x]:
        if dist[y] == -1 and col in unlocked:
            dist[y] = dist[x] + 1
            q.append(y)

print(dist[b])
```この実装では、ラインの標準の隣接リストが構築され、各エッジの色が保存されます。 BFS は開始ゾーンから実行され、カラーがすでにロック解除されているエッジのみをトラバースします。 

ノードを訪問するたびに、その神社の色のロックが解除されます。 これにより、ゾーンが到達可能になるとすぐに、その色が将来の拡張にすぐに使用できるようになります。 

よくある微妙な点は、新しい色のロックが解除されたときに BFS を再起動しないことです。 代わりに、新しく許可されたエッジが更新されたエッジに対して動的にチェックされるため、BFS は自然に続行されます。`unlocked`セット。

 ## 特殊なケース

 重要なエッジケースは、開始ゾーンにすでに有用な色が含まれているが、BFS が隣接するゾーンに到達するまでそのエッジがまだ使用できない場合です。 ロックの解除はトラバース条件にのみ影響し、即時の移動には影響しないため、アルゴリズムはこれを自然に処理します。 

もう 1 つの微妙なケースは、色がその神社に到達するために必要な場合です。 これは起こり得ません。神社はすでにゾーン内にあるため、ロックを解除するのに同じ色への既存のアクセスは必要なく、色レベルでの循環依存を防ぎます。 

最後のケースは、各ゾーンが次に必要な色のロックを正確に解除する長いチェーンです。 このような構成では、BFS は一度に 1 ステップずつ増加しますが、各ステップで新しいカラーのロック解除がトリガーされ、キューは再訪することなく単調に拡張し、全体を通して線形動作が維持されます。
