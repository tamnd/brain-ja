 ## 解決策
 ## 問題の理解

 私たちはドアでつながった部屋の列を与えられており、各ドアには自動的に開く時間があり、各部屋には鍵が入っている可能性があります。 時間 0 に部屋 1 から開始し、目標は後続の各部屋に到達するまでの最短時間を見つけることです。 ドアが開いているかどうかによって移動が制限され、閉じたドアは途中で拾った鍵を使用してロックを解除できます。 一度に持ち運べる鍵は 1 つまでで、どの部屋でも鍵の受け渡しが可能です。 

入力は複数のテスト ケースを提供します。 各テスト ケースでは、ドアの数、各ドアの自動開閉時間、および最初のキーの場所を示すバイナリ文字列を指定します。 各テスト ケースの出力は整数のリストで、各整数は各ドアのすぐ右側の部屋に到達するのに必要な最小秒数を表します。 

問題のサイズは大きく、テスト ケースあたり最大 200,000 個のドアと 10,000 個のテスト ケースがあり、合計で 2×10^5 個のドアを処理する必要がある可能性があります。 これにより、各秒の単純なシミュレーションが排除されます。 タイム ステップを繰り返すブルート フォース アプローチでは、時間が最大 2×10^5 に達する可能性があり、移動の決定により操作が倍増する可能性があるため、遅すぎます。 

微妙なエッジケースは、ドアが開く前に部屋で鍵が利用可能な場合、または鍵を使用してドアに到達するのにかかる時間よりも遅くドアが開く場合に発生します。 たとえば、部屋の開始位置に鍵があるものの、時間 0 に次のドアが開く場合があります。ドアが後で開くようにスケジュールされている場合でも、すぐに鍵を使用できます。 ドアが開くのを待つだけの不注意なアルゴリズムでは、最小時間を過大評価してしまいます。 

## アプローチ

 ブルートフォース手法では、毎秒シミュレーションして、現在の部屋、鍵を持ち歩いているかどうか、鍵の場所などの状態を維持します。 毎秒、時間が来たドアを開け、鍵を拾ったり落としたり、左右に移動したりします。 これは正確性を保つためには機能しますが、O(max(a_i) * n) となり、最悪の場合の入力では 4×10^10 の演算になる可能性があり、実行不可能です。 

重要な洞察は、両方向からの最も早い到着時間を事前に計算することで問題を解決できるということです。 各部屋について、ドアが開くのを待つか鍵を使用することで、左からその部屋に到達できる最も早い時間は次のとおりです。`max(time_needed_to_reach_prev_room + 1, door_open_time)`。 部屋に鍵がある場合は、待たずにすぐに次のドアのロックを解除できます。 同様に、どの部屋からでも右に移動して、キーを使用してドアを開けることができる最小時間よりも遅くドアが自動的に開く場合、最も早い到着時間は 2 つの時間のうち小さい方によって決定されます。 

もう 1 つの観察は、持ち運べる鍵は最大 1 つであるため、関連する鍵は左側の部屋にある鍵だけであるということです。 最適な戦略では、後でキーをドロップする必要がないため、キーのドロップを追跡する必要はありません。 最初に遭遇したブロックされたドアですぐに使用します。 これにより、動的プログラミング アプローチを使用した単純な線形スキャンに問題が軽減され、各部屋に順番に到達するまでの最小時間が計算されます。

 ## アルゴリズムのチュートリアル

 1. 配列を初期化する`dp`サイズの`n+1`各部屋に到達するまでの最小秒数を保存します。 セット`dp[0] = 0`時間 0 に部屋 1 から開始するためです。 
2. ドアを左から右に繰り返します。 ドア用`i`コネクティングルーム`i`に`i+1`、部屋に到着するまでの最短時間`i+1`ドアが自動的に開くのを待っているか、`a[i]`または、部屋に鍵がある場合は、鍵を使用してすぐに移動します`i`。 コンピューティング`dp[i+1]`最大として`dp[i] + 1`そして`a[i] + 1`すぐに使用するキーがない場合。 
3. 余裕がある場合`i`鍵が含まれています。その鍵を使ってすぐにドアを開けることができると考えてください。`i`。 これにより、`dp[i+1] = min(dp[i+1], dp[i] + 1)`。 の`+1`現在の秒の終わりに次の部屋に移動することを説明します。 
4. すべてのドアに対してこのプロセスを繰り返します。 最後に、`dp[i+1]`部屋に到着するまでの最短時間が含まれています`i+1`自動で開くのを待つことと、利用可能なキーを最適に使用することの両方を考慮します。 
5. 計算結果を出力します。`dp[1:]`テストケースごとに。 

機能する理由: アルゴリズムは、次の不変条件を維持します。`dp[i]`部屋に到着するまでの最短時間です`i`。 各ステップで、ドアが開くまで待つか、すぐに鍵を使用します。 ドアは 1 回しか開かず、鍵は最初は部屋ごとに 1 つに制限されているため、DP は時間を過小評価することはありません。 最適なパスにはキーを保存するための不必要な迂回が含まれないため、ドロップされたキーを追跡する必要はありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        s = input().strip()
        dp = [0] * (n + 1)
        for i in range(n):
            # arrive at room i+1 either by waiting for door a[i] or using a key
            dp[i + 1] = max(dp[i] + 1, a[i] + 1)
            # if key is present in room i, consider using it immediately
            if s[i] == '1':
                dp[i + 1] = min(dp[i + 1], dp[i] + 1)
        print(' '.join(map(str, dp[1:])))
        
if __name__ == "__main__":
    solve()
```コードは DP アルゴリズムを反映しています。 ライン`dp[i+1] = max(dp[i] + 1, a[i] + 1)`キーを使用しない限り、ドアが開く前に移動できないようにします。 次の行では、キーが存在するかどうかをチェックします。これにより、次の部屋にすぐに移動できるようになります。 最適な時間には最初にブロックされたドアのみが重要であるため、鍵の落下は追跡しません。 ドアと部屋のインデックスを注意深く作成することで、1 つずつ異なるエラーが回避されます。
