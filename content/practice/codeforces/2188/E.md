 ## 問題の理解

 すべての頂点には次の頂点へのエッジがあり、場合によってはより大きな頂点への追加のロング ジャンプが 1 つあります。 余分なエッジが交差することはありません。 すべてのエッジを数直線の上に描画すると、余分なエッジが 2 つもパターンを形成することはありません$u_i < u_j < v_i < v_j$。 

ジェリーは毎ターン移動しなければなりません。 トムは移動するかもしれないし、留まるかもしれない。 ジェリーは頂点に到達すると勝ちます$n$捕まる前に。 ターン終了時に両方のプレイヤーが同じ頂点を占めるとすぐにトムが勝ちます。 

注文された開始ペアごとに$(x,y)$と定義します。$f(x,y)$トムが勝利を勝ち取るためにしなければならない実際の動きの最小数として。 トムが勝利を強制できない場合、値は次のようになります。$0$。 

合計しなければなりません$f(x,y)$注文されたすべてのペアにわたって$x \ne y$。 

すべてのテスト ケースの頂点の合計数は、$2 \cdot 10^5$、これに近いものは直ちに除外されます。$O(n^2)$テストケースごとに。 最終的な答えにはすべての順序付きペアが含まれるため、ゲームを個別にシミュレートするのではなく、情報をグローバルに集約する必要があります。 

この問題の最も危険な部分は、ゲームがツリーではなく DAG 上でプレイされることです。 素朴なアプローチでは、任意のパスについて推論しようとする可能性があります。 非交差状態はまさにツリー構造を出現させます。 

頂点のあるグラフを考えてみましょう$1 \to 2 \to 3 \to 4$そして追加のエッジ$1 \to 4$。 

ジェリーが次から始める場合$1$そしてトムは$3$、トムはすぐに移動しなければなりません$4$。 ジェリーが直接ジャンプできるため、待つのは負けです。$4$。 答えは$f(1,3)=1$、 ない$0$。 

もう一つの微妙なケースは、$x=n$。 ジェリーはターンがプレイされる直前に勝ちます。 例えば：```
n = 2
x = 2
y = 1
```トムには動く機会がないので、$f(2,1)=0$。 

3 番目の罠は、トムがじっとしていられることです。 場合によっては、最適な戦略は、ゼロ手でクリティカル祖先で待機することです。 トムが常に前進することを前提とした解決策は、オーバーカウントになります。 

## アプローチ

 ブルートフォースソリューションでは、すべての順序付きペアが評価されます。$(x,y)$、対応するゲームを解き、答えを蓄積します。 

グラフには次の内容が含まれます$O(n)$エッジなので、$O(n)$ペアごとのゲーム分析にはすでにコストがかかります$O(n^2)$。 あるので$O(n^2)$ペアの場合、全体の複雑さは次のようになります。$O(n^3)$、それは絶望的です$n=2 \cdot 10^5$。 

重要な観察は、非交差条件から得られます。 

頂点ごとに$i$、 させて$a_i$すべての発信エッジの中で最大のエンドポイントであること$i$。 普通のエッジなので$i \to i+1$常に存在し、$a_i$は明確に定義されています。 

重要な事実は、からのすべてのパスは、$i$に$n$通過しなければならない$a_i$。 パスがバイパスしようとした場合$a_i$、最終的には交差エッジが作成され、グラフの制限と矛盾します。 この観察は、公式のソリューションの議論に現れています。 

すべての頂点を接続します$i$に$a_i$。 これらのエッジは根のある木を形成します。$n$。 頂点から頂点までのすべてのパス$n$このツリー内のその頂点のすべての祖先が含まれます。 

ゲームをこのツリーに変換すると、結果は簡単になります。 

させて$d_u$の深さになる$u$木の根元から測ったところ$n$。 させて$L=\operatorname{lca}(x,y)$。 

もし$d_x < d_y$、ジェリーは永遠に厳密にトムの前に留まり、到達することができます$n$、したがって、トムは勝利を強制することはできません。 

もし$d_x \ge d_y$、トムはレースで勝ちます$L$。 彼は届く$L$遅くともジェリーまでに、そしてジェリーはそこを通過しなければなりません$L$。 トムが必要とする最小移動数は次のとおりです。$$f(x,y)=d_y-d_L.$$これにより、ゲームは純粋な木の数の問題に縮小されます。 

順序ペアの合計を書き換えて対称ペアをグループ化すると、答えは次のようになります。$$A-B+C,$$どこ$$A=\sum_{x<y}\min(d_x,d_y),$$

$$B=\sum_{x<y} d_{\operatorname{lca}(x,y)},$$そして$$C=\sum_{\substack{x<y\\ d_x=d_y}} \left(d_x-d_{\operatorname{lca}(x,y)}\right).$$3 つの項はすべて次のように計算できます。$O(n \log n)$。

 ## アルゴリズムのチュートリアル

 1. 頂点ごとに$i<n$、計算する$a_i$、その発信エッジの中で最大のエンドポイント。 
2. 根を張った木を作ります。$a_i$の親$i$。 ルートが頂点です$n$。 
3. DFS を実行して、サブツリーのサイズと深さを計算します。 
4. コンピューティング$$A=\sum_{x<y}\min(d_x,d_y).$$すべての深さを並べ替えます。 ソートされた深さが次の場合$b_1 \le b_2 \le \dots \le b_n$、 それから$$A=\sum_{i=1}^{n} b_i (n-i).$$すべてのペアはより小さい深度に寄与します。これは、ソート順でちょうど左側のエンドポイントになります。 
5. コンピューティング$$B=\sum_{x<y} d_{\operatorname{lca}(x,y)}.$$ノードの場合$u$、LCA が等しい順序なしペアの数$u$は$$\binom{\text{sz}_u}{2} - \sum_{v \text{ child of } u} \binom{\text{sz}_v}{2}.$$このカウントを乗算します$d_u$そしてそれを追加します$B$。 
6. コンピューティング$$C_1=\sum_h h \binom{\text{cnt}_h}{2},$$どこ$\text{cnt}_h$深さの頂点の数です$h$。 

これは次の最初の部分に相当します$C$。 
7. コンピューティング$$C_2=\sum_{\substack{x<y\\ d_x=d_y}} d_{\operatorname{lca}(x,y)}.$$DSU オンツリーを使用します。 各ノードについて$u$、LCAが正確である同じ深さのペアを数えます$u$。 そのカウントが$P_u$を追加します。$$d_u \cdot P_u$$に$C_2$。 
8. 最終的な答えは次のとおりです。$$A-B+(C_1-C_2).$$### なぜ効果があるのか

 解全体は、すべての頂点の最大出力エッジによって引き起こされるツリー上にあります。 あらゆる道$n$はこのツリー内の親を通過する必要があるため、ゲームは祖先関係のみに依存します。 ジェリーは、トムより厳密にルートに近い位置から開始すると、キャプチャを正確に回避できます。 それ以外の場合は、トムが最初に LCA を占有して待機することができます。 これにより、次の閉じた式が得られます。$f(x,y)$。 残りの作業は、深さと LCA がすべてのペアにわたって寄与する頻度を数えることです。これは、まさに 3 つの集計された項が計算するものです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(1 << 20)

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n, m = map(int, input().split())

        parent = [0] * (n + 1)
        for i in range(1, n):
            parent[i] = i + 1

        for _ in range(m):
            u, v = map(int, input().split())
            if v > parent[u]:
                parent[u] = v

        g = [[] for _ in range(n + 1)]
        root = n

        for i in range(1, n):
            g[parent[i]].append(i)

        depth = [0] * (n + 1)
        sz = [0] * (n + 1)
        heavy = [0] * (n + 1)

        depth_cnt = [0] * n

        def dfs1(u):
            sz[u] = 1
            depth_cnt[depth[u]] += 1

            mx = 0
            for v in g[u]:
                depth[v] = depth[u] + 1
                dfs1(v)
                sz[u] += sz[v]
                if sz[v] > mx:
                    mx = sz[v]
                    heavy[u] = v

        dfs1(root)

        depths = depth[1:]
        depths.sort()

        A = 0
        for i, d in enumerate(depths):
            A += d * (n - 1 - i)

        B = 0
        for u in range(1, n + 1):
            pairs = sz[u] * (sz[u] - 1) // 2
            for v in g[u]:
                pairs -= sz[v] * (sz[v] - 1) // 2
            B += pairs * depth[u]

        C1 = 0
        for d, c in enumerate(depth_cnt):
            C1 += d * (c * (c - 1) // 2)

        big = [False] * (n + 1)
        freq = [0] * n

        C2 = 0

        def add_subtree(u, delta):
            freq[depth[u]] += delta
            for v in g[u]:
                if not big[v]:
                    add_subtree(v, delta)

        def count_subtree(u):
            nonlocal cur_pairs
            cur_pairs += freq[depth[u]]
            for v in g[u]:
                if not big[v]:
                    count_subtree(v)

        def dfs2(u, keep):
            nonlocal C2, cur_pairs

            for v in g[u]:
                if v != heavy[u]:
                    dfs2(v, False)

            if heavy[u]:
                dfs2(heavy[u], True)
                big[heavy[u]] = True

            pairs_here = 0

            for v in g[u]:
                if v == heavy[u]:
                    continue

                cur_pairs = 0
                count_subtree(v)
                pairs_here += cur_pairs
                add_subtree(v, 1)

            freq[depth[u]] += 1

            if heavy[u]:
                big[heavy[u]] = False

            C2 += pairs_here * depth[u]

            if not keep:
                add_subtree(u, -1)

        dfs2(root, False)

        ans = A - B + (C1 - C2)
        out.append(str(ans))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```最初のフェーズでは、すべての頂点からの最大出力エッジを使用して親ツリーを構築します。 グラフ プロパティにより、このツリーがルートへのすべての可能なルートをキャプチャすることが保証されます。 

最初の DFS は、深さ、サブツリーのサイズ、および重い子を計算します。 これらの値は、後のすべての式で再利用されます。 

の計算$B$標準の LCA カウント ID を使用します。 サブツリー内の順序のないペアはすべて、何らかの祖先に寄与します。 子サブツリーに完全に含まれるペアを減算すると、LCA が現在のノードであるペアがそのまま残ります。 

DSU-on-tree セクションは唯一デリケートな部分です。 ノードの処理中$u$、頻度テーブルには、以前に処理された子サブツリーからすでに蓄積された深さが格納されます。 別の子サブツリーをトラバースする場合、すべての頂点は、同じ深さのパートナーが既に存在する数を即座に見つけます。 これらのペアには正確な LCA があります$u$それらは異なる子サブツリーに存在するためです。 

すべての算術演算では Python 整数が使用されるため、オーバーフローが問題になることはありません。

 ## 特殊なケース

 次のことを考慮してください。```
1
2 0
```ジェリーは頂点から開始します$2$ペアのために$(2,1)$。 ゲームはジェリーの勝利ですぐに終了します。 頂点のツリーの深さ$2$は$0$したがって、この式は正しくは何も寄与しません。 

考慮する：```
1
4 1
1 4
```トムは頂点で待つことで勝つことができることが多い$4$。 LCA はすでにルートであり、$d_y-d_{LCA}=0$。 

考慮する：```
1
4 2
1 4
2 4
```頂点$1$そして$2$同じ深さに横たわります。 深さが等しいペアは、まさに対称ペアの変換が重要になる場所です。 修正項$C=C_1-C_2$余分なものを取り除き、正しい答えを導き出します。
