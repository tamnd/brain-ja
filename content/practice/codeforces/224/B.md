 ## 解決策
 ## 問題の理解

 整数の配列と数値 _k_ が与えられます。 タスクは、正確に _k_ 個の異なる整数を含む、連続したサブ配列またはセグメントを見つけることです。 この条件を満たすすべてのセグメントの中で、**包含により最小**であるセグメントを見つけるように求められます。これは、正確に _k_ 個の異なる整数を持つという要件に違反することなく、セグメントの先頭または末尾から要素を削除することはできないことを意味します。 そのようなセグメントが存在しない場合は、次の結果を返す必要があります。`-1 -1`。 

配列には最大 10^5 の要素を含めることができ、各要素の値も 10^5 までの大きさにすることができます。 _n_ は 10^5 で、制限時間は 2 秒であるため、すべての可能な部分配列を明示的にチェックする解決策には O(n^2) 時間がかかり、遅すぎます。 このため、線形または線形に近いアプローチを検討する必要があります。 エッジ ケースには、すべての要素が同一である配列、_k_ が個別の要素の数より大きい配列、最小セグメントが境界で発生する配列が含まれます。 

たとえば、配列が次の場合、`[1, 2, 2, 3]`_k_ = 2、セグメント`[1, 2]`は有効かつ最小限であるため、`[1, 2]`には、正確に 2 つの異なる数値が含まれており、短いサブセグメントには 2 つ未満の異なる数値が含まれます。 _k_ = 4 の場合、出力は次のようになります。`-1 -1`配列には異なる数値が 3 つしか含まれていないためです。 

## アプローチ

 ブルートフォースアプローチでは、考えられるすべてのセグメントが考慮されます。`[l, r]`配列内で、そのセグメント内の個別の要素をカウントし、それが _k_ に等しいかどうかを確認します。 個別の要素のカウントはセットを使用して行うことができます。 このアプローチは原理的には正しいですが、すべての O(n^2) セグメントをチェックし、それぞれの異なる要素のセットを計算すると、セットを毎回再構築すると、最悪の場合 O(n^3) までかかる可能性があります。 実行セットを使用した場合でも、すべてのセグメントの合計作業量は O(n^2) のままですが、これは n = 10^5 には遅すぎます。 

重要な観察は、個別の要素の数を追跡しながら拡大または縮小する **スライディング ウィンドウ**を維持できることです。 頻度辞書を使用して、現在のウィンドウ内で各数値が何回出現するかを追跡すると、効率的に右側に要素を追加し、左側から要素を削除して、操作ごとに O(1) 内の個別の数値のカウントを更新できます。 これにより、各要素の追加と削除が一度だけ行われるため、**O(n)** 時間で有効なセグメントを見つけることができます。 

スライディング ウィンドウを可能にする洞察は、部分配列上の個別の要素を数える問題には **単調な特性**があるということです。ウィンドウを右に拡大すると個別の要素の数は増加するだけで、左から縮小すると個別の要素の数は減少するだけです。 このプロパティにより、最小包含セグメントを失わずに 2 つのポインターを移動できることが保証されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | スライディング ウィンドウ / 2 つのポインター | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 2 つのポインタを初期化する`l`そして`r`0 は現在のセグメントを表します`[l, r)`。 辞書を初期化する`count`現在のセグメント内の各数値の頻度と変数を追跡します。`distinct`個別の要素の数を追跡します。 
2.右ポインタを移動します`r`個別の要素の数が揃うまでループ内を前進させます。`[l, r]`_k_ に達するか、それを超えます。 要素ごとに`a[r]`、その周波数を増加させます`count`。 この要素が初めて出現する場合は、インクリメントします`distinct`。 
3. 1回`distinct`_k_ に等しい、このセグメントかどうかを確認する`[l, r]`含めることで最小限になります。 一方、一番左の要素は`a[l]`周波数が 1 より大きい場合、その周波数を減らして移動します`l`右の方へ。 これにより、セグメントの先頭に不要な要素が残らないようになります。 
4. もし`distinct`縮小後の *k` と等しい場合は、このセグメントを有効な回答として記録します。 後で見つかったさらに有効なセグメントが含まれる範囲が小さくなることはないため、すぐに戻ることができます。 必要なのは、**1** の最小包含セグメントのみです。 
5. ループが終了すると、`distinct`_k_ に到達しない、出力`-1 -1`。 

### なぜ効果があるのか

 不変条件は、スライディング ウィンドウであることです。`[l, r)`常に最大 _k_ 個の異なる数値が含まれます。 右ポインタを移動するとウィンドウが拡大し、拡大される可能性があります。`distinct`。 左から縮小すると、巻き込みが最小限に抑えられます。 すべての要素がウィンドウに出入りするのは最大 1 回なので、O(n) の複雑さが保証され、頻度辞書によって正確な個別のカウントが効率的に維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def find_segment(n, k, a):
    count = {}
    distinct = 0
    l = 0
    for r in range(n):
        if a[r] not in count:
            count[a[r]] = 0
        count[a[r]] += 1
        if count[a[r]] == 1:
            distinct += 1
        
        while distinct > k:
            count[a[l]] -= 1
            if count[a[l]] == 0:
                distinct -= 1
            l += 1
        
        if distinct == k:
            # shrink from left to make it minimal by inclusion
            while count[a[l]] > 1:
                count[a[l]] -= 1
                l += 1
            return l + 1, r + 1  # converting to 1-based index
    return -1, -1

def main():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    l, r = find_segment(n, k, a)
    print(l, r)

if __name__ == "__main__":
    main()
```コードは頻度辞書を維持します`count`現在のウィンドウ内の要素を追跡します。 追加または削除するたびに、個別のカウントが更新されます。 左ポインタを縮小すると、セグメントが含まれることによって最小化されます。 1 つの微妙な点は、出力のためにインデックスを 1 ベースに変換することです。`l + 1`そして`r + 1`が返されます。
