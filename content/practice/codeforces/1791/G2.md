 ## 解決策
 ## 問題の理解

 0 から n+1 までのラベルが付いた位置を持つ数直線が与えられます。 位置 1 から n には、それぞれ指定されたコストのテレポーターがあります。 c コインで位置 0 から開始し、1 コインで 1 単位ずつ左または右に移動できます。または、現在の位置でテレポーターを使用すると、テレポーターのコストでラインのどちらかの端 (位置 0 または n+1) に即座に到達できます。 一度使用したテレポーターは再利用できません。 目標は、利用可能なコインで使用できるテレポーターの数を最大化することです。 

入力は複数のテスト ケースを提供します。 各テスト ケースでは、n、テレポーターの数、c、合計コイン、およびテレポーターのコスト a[1..n] の配列が与えられます。 出力は、各テスト ケースで使用されるテレポーターの最大数です。 

制約は、n を最大 2×10⁵ まで処理し、テスト ケース全体の n の合計も 2×10⁵ まで処理する必要があることを意味します。 考えられるすべてのテレポート シーケンスを反復する単純な O(n²) アプローチでは、遅すぎるでしょう。 テスト ケースごとにおよそ O(n log n) 以内に収める必要があります。 また、コインの価値とテレポーターのコストは 10⁹ に達する可能性があるため、不注意だと整数のオーバーフローが懸念されます。 

明らかではないエッジケースには、最も安価なテレポーターが回線の遠端近くにある状況が含まれます。 たとえば、n = 4、c = 3、a = [5、4、3、1] を考えてみましょう。 常に右に移動し、順番にテレポートを試す単純なアプローチでは、インデックス 4 でテレポートを選択できません。これは、4 つのユニットを移動するのにかかるコストはわずか 4 であり、予算をわずかに超えるため、使用可能です。 微妙な点は、移動コストを含めると、最初の近くでテレポーターを使用したほうが、最後のテレポーターを使用するよりも安いため、両端からの移動を考慮する必要があることです。 

もう 1 つのエッジ ケースは、n = 3、c = 1、a = [2,2,2] のように、すべてのテレポーターが個別に高価すぎる場合です。 正しい答えは 0 ですが、単純な実装ではとにかく最初のテレポーターを試行し、コインの数え間違いを引き起こす可能性があります。 

## アプローチ

 強引なアプローチは、テレポーターのすべての組み合わせを試し、それらの間の移動を含む総コストを計算することです。 テレポーターのサブセットごとに、それらに到達するためのコストとテレポーター自体のコストを合計します。 すべてのサブセットを検査する必要があるため、テスト ケースごとの複雑さは O(2ⁿ) です。 明らかに、これは n = 2×10⁵ では失敗します。 

重要な洞察は、テレポーターを使用するコストは、テレポーターのコストに、どちらかの端 (位置 0 または n+1) からテレポーターに到達するための最小移動コストを加えたものであることを観察することです。 テレポーター i の場合、0 から i 単位、n+1 から n - i + 1 単位移動するため、実効コストは min(a[i] + i, a[i] + (n - i + 1)) になります。 これらの有効コストを事前に計算すると、問題はコインの総予算内でできるだけ多くのテレポーターを選択することになります。 これは古典的な「予算内でアイテム数を最大化する」問題です。 

有効コストを昇順に並べ替え、予算を超えるまでテレポーターを繰り返し使用すると、O(n log n) のソリューションが得られます。 ソートにより、常に最も安価で使用可能なテレポーターが最初に選択され、最適なソリューションが保証されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2ⁿ) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テレポーター i (1 のインデックス付き) について、その実効コストを計算します。 これは`min(a[i] + i, a[i] + (n - i + 1))`。 第一項は左端からコスト、第二項は右端からです。 これは、テレポーターに到達するための最も安価な経路にそのコストを加えたものになります。 
2. 有効コストの配列を昇順に並べ替えます。 並べ替えると、最も安価なテレポーターが最初に考慮されるため、許容できる数が最大になります。 
3. 使用したテレポーターのカウンターと、c コインから始めて残りのコインを追跡する変数を初期化します。 
4. ソートされた有効コストを繰り返します。 各コストについて、残りのコイン以下であるかどうかを確認します。 「はい」の場合、予算からそれを差し引き、カウンターをインクリメントします。 それ以外の場合は、残りのすべてのテレポーターのコストが高くなるため、反復を停止します。 
5. すべてのテレポーターを処理するか、予算を使い果たすと、カウンターは使用可能なテレポーターの最大数を表します。 

機能する理由: 最小到達コストを事前に計算して並べ替えることにより、選択した各テレポーターが利用可能な中で最も安価であることが保証されます。 それ以外の注文では、すぐに予算を超えるか、選択するテレポーターの数が減るため、貪欲な選択が常に安全です。 この問題は、局所的な最適な選択 (次の最も安価なテレポーター) が全体的な最適化につながる、予算が限られた選択の問題に帰着します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, c = map(int, input().split())
        a = list(map(int, input().split()))
        eff = [min(a[i] + i + 1, a[i] + n - i) for i in range(n)]
        eff.sort()
        count = 0
        remaining = c
        for cost in eff:
            if cost <= remaining:
                remaining -= cost
                count += 1
            else:
                break
        print(count)

if __name__ == "__main__":
    solve()
```最初の行はテスト ケースの数を読み取ります。 各テスト ケースについて、n と c を読み取り、次にテレポーターのコストを読み取ります。 左右の動きを考慮して実効コストを計算します。 ソートは貪欲な選択の準備をします。 このループは、コインがなくなるまで、選択された各コストを予算から差し引きます。 移動に 1 から始まるインデックスを使用すると、数直線上の位置を一致させるためのコスト計算が簡素化されます。 

## 実用的な例

 ### サンプル 1

 入力: n = 5、c = 6、a = [1、1、1、1、1]

 | 私 | a[i] | 左コスト = a[i]+i | right_cost = a[i]+n-i+1 | 効果的 |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 2 | 5 | 2 |
 | 2 | 1 | 3 | 4 | 3 |
 | 3 | 1 | 4 | 3 | 3 |
 | 4 | 1 | 5 | 2 | 2 |
 | 5 | 1 | 6 | 1 | 1 |

 有効ソート: [1,2,2,3,3]

 1を取る→残り5、カウント1

 2テイク→残り3、カウント2

 2を取る→残り1→次の3は取れない

 答え = 2

 これは、効果的なコストを伴う貪欲な選択を裏付けています。 

### サンプル 2

 入力: n = 8、c = 32、a = [100,52,13,6,9,4,100,35]

 有効コストを計算します。 

[108, 57, 16, 9, 13, 9, 107, 42] → ソート → [9,9,13,16,42,57,107,108]

 コインがなくなるまでピック: 9 → 残り 23、9 → 残り 14、13 → 残り 1 → 停止

 答え = 3

 これは、効果的なコストを使用して両端からテレポーターを選択することで、高価なテレポーターを早期にスキップできることを示しています。
