 ## 解決策
 ## 問題の理解

 私たちは 0 から n までの整数点の線上に配置されます。 1 から n までのすべての位置 i には、1 回だけ使用できるテレポーターがあり、それを使用すると位置 0 に戻ります。i でのテレポーターの使用コストは a[i] です。 テレポーターを使用するまでの間に、ラインに沿って左または右に歩くことができ、各ステップのコストは 1 コインです。 

c コインの位置 0 から開始し、アクティブ化できる個別のテレポーターの数を最大化したいと考えています。 各テレポートの後は 0 に戻るため、新しいテレポートの試行はそれぞれ同じ基本位置から始まりますが、そこに到達するまでに歩く必要がある場合があります。 

重要な構造は、インデックス i でテレポーターを使用するたびに、0 から i まで歩くために i コインを支払わなければならず、その後、テレポーターをアクティブにするために a[i] コインを支払う必要があるということです。 その後、0 に戻り、残りのテレポーターでこのプロセスが繰り返されます。 

入力には、それぞれ異なる行の長さとバジェットを持つ複数のテスト ケースが与えられます。 予算内で使用できるテレポーターの最大数をテスト ケースごとに独立して計算する必要があります。 

この制約は、テスト ケース全体で線形の合計入力サイズを意味するため、テスト ケースあたり O(n log n) を超えるソリューションには TLE のリスクがあります。 n が全体で 2 · 10^5 に達する可能性があるため、最善の選択を動的に再計算したり、すべてのサブセットを試行したりする単純な試みはすぐに爆発します。 

最小の a[i] 値を選択することが常に最適であると仮定すると、微妙な故障モードが発生します。 これは、移動コスト i を無視します。a[i] が小さい場合でも、移動コスト i が支配的になる可能性があります。 

たとえば、c = 10 で a = [1, 1, 1, 100] の場合、最も安価な a[i] はすべて等しいですが、インデックス 4 は移動コスト 4 により実質的に高価であるため、実際のコストは 104 となり、使用できません。 純粋に a[i] に貪欲な人は、それを間違って選択するでしょう。 

もう 1 つのエッジ ケースは、予算が大きくても n が小さい場合に発生します。つまり、テレポーターのコストがゼロであっても、移動コストが累積します。 a = [0, 0, 0, 0] の場合、毎回 1+2+3+4 を支払うことになるため、順序は非常に重要です。 

## アプローチ

 直接的な総当たりアプローチでは、テレポーターのすべてのサブセットが試行され、サブセットごとに使用順序が決定されます。 各テレポーターのコストは、そのインデックスと選択されたかどうかによってのみ決まります。 インデックスやコストを増やすことで順序を修正したとしても、どのテレポーターを選択するかという組み合わせの選択に直面します。 これにより、およそ O(2^n) という指数関数的な動作が生じますが、これは 2・10^5 どころか、n = 40 の場合でも不可能です。 

私たちはテレポーターの使用コストを実際に決定するものを理解する必要があります。 すべてのテレポーター i は、i + a[i] に等しい固定実効コストに寄与します。これは、成功した使用はすべて 0 から始まり、i まで歩いてアクティブ化されるためです。 個別のテレポーターを選択し、これらの独立したコスト全体で予算を費やす必要があることを除いて、選択肢間に相互作用はありません。 

このように見ると、問題は、各項目が最大 1 回使用され、値ではなくカウントを最大化したいというナップザックのような制約の下で、重み w[i] = i + a[i] の配列からできるだけ多くの項目を選択することになります。 

合計制約の下で選択されたアイテムの数を最大化するための最適な戦略は、常に最小の重みを最初に選択することです。 これは古典的な交換の議論です。小さいコストをスキップして大きいコストを選択した場合、それらを交換することで実現可能性が向上するか、カウントを減らさずにコストを変更しないでください。 

したがって、すべての w[i] を計算し、並べ替えて、予算がなくなるまで貪欲に蓄積します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | 最適 (ソート + 貪欲) | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 各テレポーターを実際のコスト w[i] = i + a[i] に変換します。 これは、移動やアクティベーションを含む 1 回の完全な使用サイクルの全コストを表します。 
2. すべての w[i] 値をリストに収集します。 それぞれは、最大 1 回選択できる独立した「項目」を表します。 
3. 最も安価なテレポーターが最初に考慮されるように、リストを降順でない順に並べ替えます。 この順序により、より安価なオプションが利用可能であるにもかかわらず、高価な選択で予算を無駄にすることがなくなります。 
4. 現在の合計を維持しながら、ソートされたコストを繰り返し処理します。 各コストについて、追加しても c を超えない場合は、それを含めて答えを増分します。 そうしないと、残りのすべてのコストが少なくとも同程度になるため、早期に停止します。 
5. 選択したテレポーターの数を出力します。 

機能する理由: 各テレポーターはコスト構造において独立しており、目標は単一の予算制約の下で数を最大化することです。 安価なテレポーターを無視してより高価なテレポーターを選択するソリューションは、実現可能性に影響を与えることなく、それらを交換することで改善できます。 これにより、コストによるソートとプレフィックスの取得が最適であることが確立されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, c = map(int, input().split())
        a = list(map(int, input().split()))
        
        costs = [a[i] + (i + 1) for i in range(n)]
        costs.sort()
        
        total = 0
        ans = 0
        
        for w in costs:
            if total + w <= c:
                total += w
                ans += 1
            else:
                break
        
        print(ans)

if __name__ == "__main__":
    solve()
```キー変換は、各コストが a[i] + (i + 1) として計算される行で行われます。 これにより、動きとアクティベーションの両方が単一の同等の重みにエンコードされます。 ソートのステップは貪欲な構造を強制するため、不可欠です。 ソートがなければ、ローカルな決定はグローバルな最適性を反映しません。 

ランニングサムロジックは標準的なプレフィックス累積です。 一度収まりきらないコストに達すると、その後のすべてのコストは仕分けによって少なくとも同額になるため、早めの休憩が安全です。 

## 実用的な例

 サンプルセットから 2 つのケースを追跡します。 

### 例 1

 入力:

 n = 5、c = 6、a = [1、1、1、1、1]

 コストは w = [2, 3, 4, 5, 6] となります。 

ソート済みはすでに同じです。 

| ステップ | 考慮されるコスト | 累計額 | 使用されたテレポーター |
 | --- | --- | --- | --- |
 | 1 | 2 | 2 | 1 |
 | 2 | 3 | 5 | 2 |
 | 3 | 4 | 9 | 2 (追加する前に停止) |

 5 + 4 が 6 を超えるため、3 番目のコストで停止します。答えは 2 で、テレポーターを 2 つ用意できることを意味します。 

これは、すべての a[i] が同一であっても、移動コストによって区別されるため、貪欲な人は自然に小さいインデックス テレポーターを好むことを示しています。 

### 例 2

 入力:

 n = 4、c = 5、a = [4、3、2、1]

 コストは w = [5, 5, 5, 5] になります。 

| ステップ | 考慮されるコスト | 累計額 | 使用されたテレポーター |
 | --- | --- | --- | --- |
 | 1 | 5 | 5 | 1 |
 | 2 | 5 | 10 | 1 (追加する前に停止) |

 2 回目の使用はすでに予算を超えているため、テレポーターは 1 台しか使用できません。 

この例は、a[i] が減少しても、移動コストがすべての選択肢を均等にし、カウントが純粋に予算に制限されることを示しています。

 ## 特殊なケース

 エッジケースの 1 つは、すべてのテレポーターが a[i] 内で非常に安価であるにもかかわらず、遠く離れた場所にある場合です。 n = 3、c = 6、a = [0, 0, 0] の場合、コストは [1, 2, 3] になります。 1 + 2 + 3 = 6 であるため、アルゴリズムは 3 つすべてを採用します。インデックスを無視した単純な戦略では、すべてが同等に安価であると誤って想定され、他のディストリビューションでは正しく優先順位が付けられない可能性があります。 

もう 1 つのケースは、単一のテレポーターが安価だが遠い場合です。 n = 3、c = 3、a = [100, 0, 0] の場合、コストは [101, 2, 3] です。 インデックス 2 のみが適合するため、正解は 1 です。 貪欲な人はソート後に最初に 2 を正しく選択し、インデックス コストが変換で完全にキャプチャされることを示しています。 

最後の構造的なケースは、予算内で最小限のいくつかのアイテムがかろうじて許容されるものの、それらの組み合わせが許容されない場合です。 累積合計が c を超えるとすぐに停止し、無効な過剰カウントが発生しないようにするため、ソートされた接頭辞メソッドはこれを自然に処理します。
