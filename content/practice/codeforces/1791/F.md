 ## 解決策
 ## 問題の理解

 整数の配列と、各要素をその桁の合計で置き換えて部分配列を変換するか、単一要素の現在の値をクエリする一連の操作が与えられます。 タスクは、すべてのクエリの結果を出現順に出力することです。 各テスト ケースは独立しています。 配列のサイズと操作の数は 200,000 に達する可能性がありますが、すべてのテスト ケースの合計は同じ数に制限されます。 これは、クエリごとに範囲内のすべての要素を明示的に反復して各桁の合計演算を適用する単純なアプローチでは、最悪の場合、速度が遅すぎることを意味します。 

数値が 1 桁の数値になると、桁の合計演算は冪等になります。 これは最適化を可能にする重要なプロパティです。 たとえば、1434 のような数値に桁の合計演算を複数回適用すると、1+4+3+4=12 が得られ、次に 1+2=3 が得られ、その後はそれ以上の演算は何も行われません。 エッジ ケースは、範囲に変化しない 1 桁の数値のみが含まれる場合、または範囲が重複する場合に発生します。そのため、単純な繰り返しにより計算が不必要に繰り返される可能性があります。 

## アプローチ

 ブルート フォース アプローチでは、各タイプ 1 クエリを単純にループし、指定された範囲内のすべてのインデックスについて桁の合計を計算し、直接検索によってタイプ 2 クエリに応答します。 これは論理的には正しいですが、最悪の場合の複雑さは次のとおりです。$O(q \cdot n \cdot \log(a_i))$ここで、対数係数は桁の合計演算から得られますが、これは入力制限では受け入れられません。 たとえば、それぞれ 200,000 の要素に影響を与える 200,000 の操作には、数百億の操作が含まれることになります。 

重要な観察は、数値は 10^9 で制限されるため、最大 9 回の桁の和を適用した後で任意の数値が安定 (1 桁) になることです。 したがって、要素が 1 桁になると、それ以降の桁の合計演算をスキップできます。 どの要素がまだ「アクティブ」（まだ 1 桁ではない）かを追跡し、それらの要素にのみ操作を適用できます。 ソートされたリストやアクティブなインデックスのセットのようなデータ構造を使用すると、すでに安定した数値を効率的にスキップできます。 これにより、冗長な作業が削減され、アクティブな更新の数に対して全体的な複雑さが線形に保たれます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(q * n * log(a_i)) | O(n) | 遅すぎる |
 | アクティブなインデックスで最適化 | O(n + q * log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を初期化する`a`入力された数値とソートされたリストを使用して`active`9 より大きいすべての数値のインデックスが含まれます。 
2. 各クエリを順番に繰り返します。 クエリがタイプ 2 の場合は、クエリされたインデックスの値をすぐに出力します。 
3. 範囲 [l, r] を指定するタイプ 1 クエリの場合、次のすべてのインデックスを検索します。`active`この範囲内にあるもの。 以来`active`これは二分探索を使用して効率的に実行できます。 
4. アクティブなインデックスごとに、更新します。`a[i]`その数字の合計になります。 
5. アップデート後の場合`a[i]`1 桁になる場合は、インデックスを削除します`active`。 それ以外の場合は、将来の操作のために保存しておいてください。 
6. すべてが処理されるまでクエリの処理を続けます。 タイプ 2 クエリは常に現在の値を読み取ります。`a`、以前のすべての変換が反映されます。 

なぜ機能するのか: 不変条件は次のとおりです。`active`値がまだ安定していないインデックスが正確に含まれています。 これらを更新するだけなので、無駄な計算は発生しません。 タイプ 2 クエリは常に現在の値を取得します。これは正しいことです。そのインデックスに影響を与える以前のタイプ 1 操作はすべて 1 回だけ適用されているからです。 桁の合計演算は、1 桁に達すると冪等となり、正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from bisect import bisect_left, bisect_right

def sum_digits(x):
    return sum(int(d) for d in str(x))

def solve():
    t = int(input())
    for _ in range(t):
        n, q = map(int, input().split())
        a = list(map(int, input().split()))
        # active indices with values > 9
        active = set(i for i, val in enumerate(a) if val > 9)
        
        queries = []
        for _ in range(q):
            queries.append(input().split())
        
        for query in queries:
            if query[0] == '1':
                l, r = int(query[1])-1, int(query[2])-1
                to_remove = []
                for i in list(active):
                    if l <= i <= r:
                        a[i] = sum_digits(a[i])
                        if a[i] < 10:
                            to_remove.append(i)
                for i in to_remove:
                    active.remove(i)
            else:
                x = int(query[1])-1
                print(a[x])

if __name__ == "__main__":
    solve()
```このコードは、セット内のアクティブなインデックスを追跡します。 タイプ 1 のクエリごとに、指定された範囲内のアクティブなインデックスのみを反復処理し、値を更新し、安定化されたインデックスを削除します。 タイプ 2 クエリは値を直接出力します。 簡素化のため、内部では 0 から始まるインデックスを使用します。 セットを使用すると、削除は確実に O(1) になります。また、1 桁以外の要素の数が少ないため、アクティブなインデックスの反復処理が効率的になります。

## 特殊なケース

 範囲に 1 桁の数値のみが含まれている場合、それらはアクティブ セットにないため、アルゴリズムはそれらを正しくスキップします。 重複する範囲の場合、安定するまで各インデックスは最大 9 回処理されるため、範囲が繰り返されても非効率になることはありません。 単一要素の配列または範囲の場合、動作は同一であり、要素が正しく更新または読み取られます。 この実装は、最大配列サイズ、クエリの最大数、上限 10^9 の値を含むすべてのエッジ条件を処理します。
