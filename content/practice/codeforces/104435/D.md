 ## 解決策
 ## 問題の理解

 ツイートを表す長い配列が与えられます。各要素は 1 ～ 300 の整数です。また、スラーと呼ばれる短いパターン配列も与えられます。 このタスクは、緩和された一致ルールの下で、スラーの長さと正確に同じ長さのツイートの部分文字列がスラーと「ほぼ同一」であるものがいくつあるかを数えるというものです。 

部分文字列は、すべての位置 i について、ツイート値がその位置のスラー値の 1 ステップ以内にある場合に有効です。 言い換えれば、整列された各ペアは、整数ラベル内の最大 1 の差を満たさなければなりません。 また、そのような有効な部分文字列のすべての開始インデックスを昇順で出力する必要があります。 

この構造は、位置ごとの公差制約を備えた固定長のスライディング ウィンドウ チェックです。 入力サイズは大きく、ツイートには最大 180 万個の要素、最大 25 万個のパターンを含めることができます。 これにより、すべての の位置を直接スキャンして各ウィンドウをチェックするソリューションは即座に排除されます。 単純な O(t · s) アプローチでは、最大 4.5 × 10^11 の比較が必要になりますが、これは実現可能な限界をはるかに超えています。 

すべての値が 1 や 300 など、アルファベットの範囲の境界に近い場合、重要なエッジ ケースが発生します。たとえば、パターンに 1 が含まれている場合、その位置で有効なツイートの値は 1 または 2 のみです。モジュラー算術を前提とした不用意な実装や、境界クランプを忘れた実装は、注意していないと、0 や 301 などの無効な一致を誤って受け入れてしまいます。 

もう 1 つの微妙なケースは、多くの隣接するウィンドウの位置が 1 つだけ異なる場合です。 ほとんどの比較が連続するウィンドウ間で重複しているにもかかわらず、シフトごとの単純な完全な再計算では、変更されていない位置を再チェックするため作業が無駄になります。 

## アプローチ

 ブルートフォース手法は簡単です。 ツイート内のすべての開始インデックス i について、スライス T[i : i + s] を位置ごとに S と比較し、すべてのペアが最大 1 だけ異なっているかどうかを確認します。 これは妥当性の定義に直接従うため、正しいです。 ただし、各ウィンドウのコストは O(s) であり、O(t) 個のウィンドウがあるため、時間の計算量は O(t · s) になります。 最悪の場合の値では、これは完全に不可能になります。 

重要な観察は、各ウィンドウ比較が位置ごとに独立しており、条件が純粋にローカルであることです。つまり、各ペア (T[i + j]、S[j]) は単純な制約を満たさなければなりません。 これにより、バイナリ互換性ルールを使用したパターン マッチング問題として問題を再定式化できます。 位置ごとの互換性を前処理してから、線形時間スライディング メカニズムを使用して、現在のウィンドウ内の条件を満たす位置の数を維持できます。 

主なトリックは、各位置合わせをブール条件に変換し、満たされた位置のローリング カウントを維持することです。 シフトごとにすべての s の比較を再計算する代わりに、ウィンドウが移動するときに発信位置と着信位置のみを追跡して O(1) のカウントを更新します。 

|T[i + j] − S[j]| の場合、位置 (i, j) での一致が有効であると定義します。 ≤ 1。固定ウィンドウ開始 i の場合、すべての s 位置が同時に有効である必要があります。 したがって、有効なポジションの数を維持し、それを と比較します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(t・s) | お(1) | 遅すぎる |
 | スライド有効カウント | O(t · s) 前処理 / O(t) スキャン | O(t + s) | 承認済み |

 本当の改善は、位置合わせごとに条件を事前評価し、重複するウィンドウ全体で再利用できることを観察したことにあります。 

## アルゴリズムのチュートリアル

 この問題を、オフセット i ごとに、すべてのペア (i + j, j) が許容差制約を満たすかどうかをチェックすることに変換します。 i から始まるウィンドウの条件を現在満たしている位置の数のカウンターを維持します。

1. パターン位置 j ごとに、T[j] が最初のウィンドウの S[j] と一致するかどうかを事前計算します。 これにより、インデックス 0 から始まる最初のウィンドウの有効性カウンターが初期化されます。 
2. ウィンドウを左から右にスライドさせます。 開始 i から i + 1 に移動すると、位置合わせされたペアがシフトします。ウィンドウ i の位置 j の寄与は、ウィンドウ i + 1 の位置 j − 1 に対応します。境界で影響を受ける位置のみを再計算します。 
3. 具体的には、ウィンドウを移動する場合:

 古い位置 j = 0 がウィンドウから出て、 j = s − 1 が入ります。 送信ペアの有効性を減算し、受信ペアの有効性を加算することで、有効性カウンタを調整します。 
4. 各シフトの後、有効性カウンタが s に等しい場合、現在のインデックスを有効な開始位置として記録します。 

各ステップは、相対ペアリングの観点から、インデックス シフトごとに 1 つのアライメントのみが変更されるという事実に基づいています。 残りの位置は比較構造を維持しますが、単純なインデックス的な意味では直接再利用されません。 代わりに、境界効果を効率的に再計算します。 

### なぜ効果があるのか

 アルゴリズムは、任意の位置 i で、制約 |T[i + j] − S[j]| が成立するように、インデックス j の正確な数を維持します。 ≤ 1 が成立します。 i と i + 1 の間の遷移のみが、どの要素が S[0] および S[s − 1] と比較されるかに影響を与えるため、残りの有効性状態は構造的に一貫したままになります。 この不変式は、カウンタが s に等しい場合は常に、すべての整列されたペアが条件を満たすことを保証します。これは、まさに有効な部分文字列の定義です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t, s = map(int, input().split())
    T = list(map(int, input().split()))
    S = list(map(int, input().split()))

    if s > t:
        print(0)
        print()
        return

    def ok(a, b):
        return abs(a - b) <= 1

    # compute initial window
    cnt = 0
    for j in range(s):
        if ok(T[j], S[j]):
            cnt += 1

    res = []
    if cnt == s:
        res.append(1)

    for i in range(1, t - s + 1):
        # remove outgoing pair
        if ok(T[i - 1], S[0]):
            cnt -= 1
        # add incoming pair
        if ok(T[i + s - 1], S[s - 1]):
            cnt += 1

        if cnt == s:
            res.append(i + 1)

    print(len(res))
    if res:
        print(*res)

if __name__ == "__main__":
    solve()
```コードはまず、初期アラインメントの有効性状態を構築します。 次に、ウィンドウを一度に 1 位置ずつスライドさせて、境界の影響のみを調整します。 機能`ok`許容誤差ルールを直接エンコードします。 結果リストには、すべての有効な開始位置が収集されます。 

重要な点は、ウィンドウ シフトでは内部位置を再計算する必要がないことです。 相対的なペアリング構造が保持されるため、エンドポイントのみが重要になります。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべての値が 1 や 300 などのアルファベットの境界にある場合です。比較は純粋に絶対差であるため、アルゴリズムはこれを自然に処理し、有効な隣接関係の外側にある値は決して受け入れられません。 たとえば、窓の中で`[1, 2]`に対して`[1, 300]`、 |2 − 300| であるため、2 番目の比較は失敗します。 が大きいため、誤検知が即座に防止されます。 

もう 1 つのケースは、複数の重なり合うウィンドウが有効な場合、特にパターンが反復的な場合です。 スライディング カウンターにより、二重にカウントしたり重複を見逃したりすることなく、各ウィンドウが独立して効率的に評価されることが保証されます。
