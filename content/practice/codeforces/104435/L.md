 ## 解決策
 ## 問題の理解

 各位置に整数の高さが格納される 1 次元の風景が与えられます。 この配列から、隣接性だけではなく、高さの制約によって接続を定義します。2 つの隣接する位置は、高さが最大 ​​1 つ異なる場合にのみ通過できます。 このルールでは、陸塊は連結コンポーネントとなります。 

タスクは、3 種類の操作の下でこの接続構造を維持することです。 1 つの演算では、サブ配列内の接続されたコンポーネントの数が求められます。 1 回の操作で完全な間隔から定数を減算し、すべての高さを均一にシフトします。 最後の操作では、範囲内の交互の位置から 1 を減算し、そのセグメント内の 2 番目ごとのインデックスにのみ影響します。 

主な問題点は、接続性が隣接する高さ間の局所的な違いに依存するため、値を変更する更新により、隣接するインデックス間に存在するエッジも変更されることです。 クエリは基本的に、範囲内で接続の切断が何回発生するかを尋ねます。切断は、連続する高さの絶対差が 1 を超えたときに発生します。 

制約が大きいため、クエリごとに接続を再計算したり、更新のたびに隣接関係を再構築したりするソリューションは失敗します。 最大 250,000 回の操作では、操作ごとの直線的な作業でも遅すぎます。 この構造は、範囲更新時にローカル境界条件を効率的に維持できる表現が必要であることを示唆しています。 

微妙な点は、更新によって接続性が直接変更されるのではなく、高さが変更され、それによって近隣間の差異が変更されるということです。 これは、問題全体が、隣接する位置間の差異の配列を維持し、それらの差が 1 を超える場所を追跡することに帰着することを意味します。 

更新により値が範囲全体で均一にシフトされる場合、エッジ ケースが発生します。 すべての内部エッジの両方の端点が均等に移動するため、完全な間隔のデクリメントは間隔内の差異をまったく変更しません。 ただし、STARQUAKE は、交互のインデックスに適用されるため、この対称性を破ります。これは、隣接する差分が不均一に増加または減少する可能性があることを意味します。 違いを注意深く更新せずに高さのみを追跡する単純な実装では、この構造の非対称性を見逃してしまいます。 

## アプローチ

 ブルート フォース アプローチでは、フルハイトの配列が維持され、クエリごとに接続が再計算されます。 クエリに答えるために、範囲をスキャンし、隣接する差分が 1 を超える回数を数えます。これは新しいコンポーネントに対応します。 各クエリには範囲の長さに対して直線的な時間がかかり、影響を受ける各高さを変更する必要があるため、更新にも直線的な時間がかかります。 

最大 250,000 回の操作では、最悪の場合、およそ 10^10 回の操作が必要となり、これは実行可能な制限をはるかに超えています。 

重要な観察は、接続性は隣接するペアが |h[i] − h[i+1]| を満たすかどうかのみに依存するということです。 ≤ 1。これにより、各エッジが有効または無効になるエッジ上でバイナリ配列を維持するという問題が軽減されます。 範囲 [l, r] に対するクエリは、l と r−1 の間に存在する無効なエッジの数を数えることになります。さらに、範囲が空でない場合は 1 つを加えます。 

これにより、問題は動的配列に変換されます。そこでは、高さの範囲更新が必要ですが、隣接する差分がしきい値 1 を超えるかどうかだけが考慮されます。セグメントごとに十分な情報 (値だけでなく、更新時に境界差分がどのように動作するか) を追跡する場合には、遅延伝播を備えたセグメント ツリーで十分です。

重要な洞察は、どちらの更新タイプもインデックスに対するアフィン変換であるということです。 FISSURE はセグメントに均一なシフトを適用しますが、これは内部的な差異には影響せず、潜在的に境界でのみ影響します。 STARQUAKE はパリティ ベースのシフトを適用します。これは、インデックス パリティに依存する関数の追加として表すことができます。 これにより、セグメントごとに 2 つの線形コンポーネント (ベース値とパリティ調整されたオフセット) を維持できるようになります。 

保留中の遅延タグの下でエンドポイントの高さを再構築するのに十分な情報をセグメントごとに保存することで、すべての要素に触れるのではなく、必要なときに境界の差分のみを再計算できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nc) | O(n) | 遅すぎる |
 | 遅延パリティ モデリングを使用したセグメント ツリー | O((n + c) log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 この配列をセグメント ツリーでモデル化します。セグメント ツリーには、各ノードが集計情報だけでなく、遅延更新を適用した後に左端と右端の値を回復するのに十分なメタデータも格納されます。 

2 種類の遅延タグを維持します。 1 つ目は、セグメント内のすべての要素に適用される均一な減分です。 2 番目はパリティベースの減分で、範囲内の特定のパリティのインデックスから 1 を減算することで表現できます。 これをきれいに処理するために、ノードごとに 2 つのアキュムレータを維持します。1 つはセグメントのグローバル インデックスに対する偶数インデックス シフト用、もう 1 つは奇数インデックス シフト用です。 

各セグメント ツリー ノードは、すべての保留中の遅延操作を適用した後、その左境界値と右境界値を保存します。 接続性は隣接するペアのみに依存するため、これで十分です。 

## アルゴリズムのチュートリアル

 1. 配列上にセグメント ツリーを構築します。各ノードには、その間隔の左端と右端の高さが格納されます。 これにより、セグメント全体を拡張することなく、セグメント境界での隣接条件を計算できます。 
2. 各ノードについて、セグメント内のすべての要素に適用される均一なデクリメントと、交互のインデックスに影響を与えるパリティベースのデクリメントという 2 つの独立した変換を表す遅延タグを維持します。 これらのタグは保存されますが、子にはすぐには適用されません。 
3. 遅延更新をツリーにプッシュする場合、均一およびパリティ ベースの両方の寄与を子に伝播し、子セグメントが偶数インデックスで始まるか奇数インデックスで始まるかに応じてパリティ アライメントを調整します。 
4. [l, r] に関するクエリに答えるには、セグメント ツリーを走査し、一連のセグメント境界値を収集します。 隣接するセグメント境界が条件 |h[i] − h[i+1]| に違反する個数を数えます。 ≤ 1。違反ごとに接続成分の数が増加します。 
5. FISSURE 操作の場合は、範囲全体に均一なデクリメント タグを適用します。 この操作ではセグメント内の差異が保持されるため、境界値のみを遅延更新する必要があります。 
6. STARQUAKE 操作の場合は、パリティを意識したデクリメントを適用します。 これは、影響を受けるセグメントの両方のパリティ コンポーネントを更新することで処理され、明示的に反復することなく偶数と奇数のインデックス位置が正しくシフトされるようになります。 

重要な不変条件は、すべてのセグメント ツリー ノードが、少なくともそのエンドポイントでは、すべての保留中の更新がすでに適用されているかのように、常にその間隔を表すことです。 これにより、クエリ中に 2 つの隣接するセグメントが比較されるときに、計算された差が実際の基礎となる高さを反映することが保証されます。 

この正しさは、接続性がローカルの隣接する差異のみに依存するという事実から導かれます。 すべての更新は線形およびパリティ線形変換であり、これらの変換は保存された遅延タグによって完全にキャプチャされるため、隣接関係に関連する情報が失われることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.size = 1
        while self.size < self.n:
            self.size *= 2

        self.lval = [0] * (2 * self.size)
        self.rval = [0] * (2 * self.size)

        self.lazy_add = [0] * (2 * self.size)
        self.lazy_even = [0] * (2 * self.size)
        self.lazy_odd = [0] * (2 * self.size)

        for i in range(self.n):
            self.lval[self.size + i] = arr[i]
            self.rval[self.size + i] = arr[i]

        for i in range(self.size - 1, 0, -1):
            self._pull(i)

    def _apply(self, i, l, r, add, even, odd):
        self.lazy_add[i] += add
        self.lazy_even[i] += even
        self.lazy_odd[i] += odd

        if (l % 2) == 0:
            self.lval[i] += add + even
            self.rval[i] += add + even
        else:
            self.lval[i] += add + odd
            self.rval[i] += add + odd

    def _push(self, i, l, r):
        mid = (l + r) // 2
        add = self.lazy_add[i]
        even = self.lazy_even[i]
        odd = self.lazy_odd[i]
        if add == 0 and even == 0 and odd == 0:
            return

        left_child = 2 * i
        right_child = 2 * i + 1

        self._apply(left_child, l, mid, add, even, odd)
        self._apply(right_child, mid + 1, r, add, even, odd)

        self.lazy_add[i] = 0
        self.lazy_even[i] = 0
        self.lazy_odd[i] = 0

    def _pull(self, i):
        self.lval[i] = self.lval[2 * i]
        self.rval[i] = self.rval[2 * i + 1]

    def update(self, ql, qr, add=0, even=0, odd=0):
        def rec(i, l, r):
            if qr < l or r < ql:
                return
            if ql <= l and r <= qr:
                self._apply(i, l, r, add, even, odd)
                return
            self._push(i, l, r)
            mid = (l + r) // 2
            rec(2 * i, l, mid)
            rec(2 * i + 1, mid + 1, r)
            self._pull(i)

        rec(1, 0, self.size - 1)

    def get_segments(self, ql, qr):
        res = []

        def rec(i, l, r):
            if qr < l or r < ql:
                return
            if ql <= l and r <= qr:
                res.append((self.lval[i], self.rval[i]))
                return
            self._push(i, l, r)
            mid = (l + r) // 2
            rec(2 * i, l, mid)
            rec(2 * i + 1, mid + 1, r)

        rec(1, 0, self.size - 1)
        return res

def solve():
    n, c = map(int, input().split())
    arr = list(map(int, input().split()))
    st = SegTree(arr)

    out = []
    for _ in range(c):
        parts = input().split()
        if parts[0] == "QUERY":
            l, r = map(int, parts[1:])
            l -= 1
            r -= 1
            segs = st.get_segments(l, r)
            segs.sort()
            comps = 1
            for i in range(1, len(segs)):
                if abs(segs[i-1][1] - segs[i][0]) > 1:
                    comps += 1
            out.append(str(comps))

        elif parts[0] == "FISSURE":
            l, r, d = map(int, parts[1:])
            st.update(l-1, r-1, add=-d)

        else:
            l, r = map(int, parts[1:])
            l -= 1
            r -= 1
            st.update(l, r, even=-1)

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```セグメント ツリーには各セグメントのエンドポイント値が格納されるため、クエリはすべての要素を展開せずに隣接情報を再構築できます。 遅延伝播システムは均一シフトをパリティベースのシフトから分離します。これが必要なのは、STARQUAKE が交互のインデックスにのみ影響し、そうでない場合は単純な加算モデルが破損するためです。 

QUERY 操作は、互いに素なセグメントの要約を収集し、位置ごとに並べ替えて、隣接関係が壊れた場所をカウントします。 正確さは、セグメントの端点が境界が接続されているかどうかを完全に決定するという事実に依存します。 

## 実用的な例

 ### 例 1

 入力:```
n=5
h = [0, 1, 3, 2, 2]
QUERY 1 5
FISSURE 2 4 1
QUERY 1 5
```| ステップ | 配列状態 | 境界チェック | コンポーネント |
 | --- | --- | --- | --- |
 | イニシャル | [0,1,3,2,2] | (0-1 OK)、(1-3 ブレーク)、(3-2 OK)、(2-2 OK) | 2 |
 | 亀裂の後 | [0,0,2,1,2] | (0-0 OK)、(0-2 ブレーク)、(2-1 OK)、(1-2 OK) | 2 |

 最初のクエリは、1 から 3 への大きなジャンプによるインデックス 2 のブレークを識別します。中央のセグメントを下にシフトした後、ブレーク構造は残りますが、位置は移動します。 これは、更新によってコンポーネント数が必ずしも変更されるわけではないことを示しています。

```| インデックス | 前 | スタークエイク後 |
 | --- | --- | --- |
 | 1 | 5 | 4 |

これは、パリティ ベースの更新では位置が交互に均一にシフトされるため、多くの場合接続が維持されることを示しています。

 ## 特殊なケース

 エッジケースの 1 つは、フルレンジの FISSURE です。 すべての高さが均等に減少するため、すべての違いは同一のままです。 相対的な差異に影響を与えることなく遅延均一タグが適用されるため、アルゴリズムはこれを処理します。そのため、シフトされた絶対値を除いて QUERY の結果は変更されません。 

もう 1 つのケースは、配列の境界に一致する範囲にわたる STARQUAKE です。 パリティはグローバル インデックスに依存するため、実装では伝播中にインデックス パリティを保持する必要があります。 セグメント ツリーには各ノードの暗黙的なインデックスが格納され、偶数と奇数の位置が一貫して更新されることが保証されます。 

最後の微妙なケースは、重複する範囲にわたって交互に更新が繰り返されることです。 遅延伝播によりパリティ シフトが蓄積され、両方の更新が線形変換であるため、それらの合成は有効なままになります。 保存されたエンドポイント値は常に結合された変換を反映するため、再計算しなくても隣接性チェックは正しいままになります。
