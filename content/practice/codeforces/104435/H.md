 ## 解決策
 ## 問題の理解

 それぞれ整数の長さを持ついくつかの棒が与えられ、最終的に三角形のようなシェルターを生成する幾何学的な構造にそれらを編成する必要があります。 スティックはまず 2 つのグループに分割され、各グループはスティックを端から端まで配置してビームを形成します。そのため、各ビームは、割り当てられたスティックの合計の長さを持つ 1 つのセグメントのように動作します。 

2 本の梁を形成した後、各梁の 1 つの端点を地面上の共通のヒンジ ポイントに結合します。 両方のビームのもう一方の端点は接地線上にあります。 これにより、最終的な形状が三角形になり、その 2 つの辺が正確に梁の長さであり、3 番目の辺が 2 つの接地点間の距離であることが保証されます。 上部のヒンジの角度は自由に選択できるため、実際に自由なのは、スティックを 2 つのビームの長さにどのように分割するかだけです。 

重要な幾何学的な単純化は、2 つの辺の長さが固定されている場合、それらの間の角度が 90 度のときに三角形の面積が最大になるという事実から来ています。 その場合、面積はビームの長さの積の半分になります。 すべてのスティックの長さの合計は固定されているため、ビームの合計の積を最大化することは、1 つのビームを合計の半分にできるだけ近づけることと同じです。 

ここでの工夫は、分割する前に、スティックを 1 つ選択し、それを 2 つの正の整数部分に分割する必要があることです。 これによって合計の合計は変わりませんが、サブセットの合計をどの程度細かく調整できるかが変わります。 

スティックの数という点では制約は小さく、テスト ケースごとに最大 35 個ですが、値は最大 1e8 まで大きくなります。 これにより、合計をめぐる動的計画法は即座に排除されます。 唯一の実行可能な方向は、およそ 2^17 の州にわたる中間サブセット列挙です。 

単純な間違いは、スティックを分割することで合計が維持されるため、スティックを分割することは無関係であると考えることです。 これは誤りです。なぜなら、分割によって組み合わせの柔軟性が高まるからです。つまり、1 つの項目を二者択一で選択する代わりに、0 から xi までの達成可能な寄与の連続範囲が得られます。 これにより、達成可能な接近度は半分に大幅に変化します。 

もう 1 つの微妙な失敗例は、常に最大のスティックを小さい側に配置するなど、貪欲なパーティションが機能すると仮定することです。 これは、ほぼ完璧なバランスを実現するには、単一の大きな修正ではなく、多くの中程度の要素を組み合わせる必要がある場合に発生します。 

## アプローチ

 ブルートフォース戦略では、1 つのスティックの可能なすべての分割と、すべてのスティックの 2 つのグループへの可能なすべての分割を試み、ビームの合計を計算し、結果の領域を評価します。 分割インデックス i ごとに、a + b = xi となるすべての整数ペア a、b を試し、結果のマルチセットごとに、すべての 2^n 割り当てを列挙します。 これにより、i にはおよそ 35 の選択肢があり、構成ごとに a、b、および 2^35 のパーティションをすべて列挙する場合、最悪の解釈では最大 10^8 の分割になります。 分割列挙を無視しても、2^35 はすでに実現可能な限界をはるかに超えています。 

重要な観察は、その面積が 1 本のビームの合計にのみ依存し、その構成には依存しないということです。 総和が S で、1 つのビームの和が x の場合、面積は x(S − x) に比例し、x が S/2 に最も近いときに最大になります。 この問題は、単一の制御された変更を伴うサブセット和の近さの問題になります。つまり、1 つの要素を、合計は固定されているがサイド間で任意に分割できる 2 つの柔軟な部分で置き換えることができます。 

分割しない場合、これは古典的な中間部分集合和です。配列の半分の部分集合和をすべて列挙し、S/2 に最も近いものを選択します。 分割により、1 つの要素が厳密な選択から範囲寄与子に変更され、その要素が連続した間隔で任意の整数だけサブセットの合計を調整できるようになります。 つまり、考えられる分割要素をそれぞれ試して、修正されたサブセットの合計問題を効率的に解くだけで済みます。

したがって、分割する要素を修正して削除し、meet-in-the-middle を使用して残りの要素のサブセットの合計を計算し、選択したサブセットの合計を [0, xi] の任意の整数だけシフトできる場合に S/2 にどの程度近づくことができるかを決定します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | パーティションと分割に対する完全な総当たり攻撃 | O(n · 2^n) | O(2^n) | 遅すぎる |
 | 各分割を試して中間者に会う | O(n · 2^(n/2)) | O(2^(n/2)) | 承認済み |

 ## アルゴリズムのチュートリアル

 分割することを決定した候補スティック i を修正します。 他のすべてのスティックは変更されず、それらの合計を R として示します。 

次に、このスティックなしで部分集合の合計がどのように動作するかを検討します。 中間ミートを使用して、残りの要素を 2 つの半分に分割し、それぞれの半分のすべてのサブセット合計を列挙し、それらを選択した要素のすべての可能な合計 S のソートされたリストにマージします。 

このような S ごとに、分割スティック xi が 2 つのビーム間に分散できることが観察されます。 このうち t を最初のビームに入れると、残り xi − t が 2 番目のビームに入ります。 これは、このスティックの効果的な寄与により、サブセット合計 S を区間 [0, xi] 内の任意の整数値だけ最初のビームに向かってシフトできることを意味します。 

これにより、各サブセット合計 S が最初のビーム合計の到達可能な間隔 [S, S + xi] に変換されます。 私たちの目標は、合計 T/2 の半分にできる限り近づけることです。そのため、このターゲットまでの距離が最小になる間隔が必要です。 

すべてのサブセット合計 S をスキャンし、区間 [S, S + xi] が T/2 にどの程度近づくかを計算します。 最小の偏差を達成する最良のペア (i、S、t) を追跡します。 

最適な構成を選択した後、中間結合構造からサブセットを再構築し、それに応じて要素を割り当てます。 スプリットスティックの場合、最初のビームに t を割り当て、2 番目のビームに xi − t を割り当てます。 

### なぜ効果があるのか

 このジオメトリにより、目的は S1(T − S1) の最大化に限定されます。これは、S1 が T/2 にどれだけ近いかによってのみ決まります。 スプリット スティックは合計合計を変更しませんが、1 つの個別の決定をサブセット合計の連続的な間隔調整に変えます。 すべての有効な構成は、サブセット S と分割 t の選択に対応し、そのような選択はすべて、正確に 1 つのビーム和にマッピングされます。 したがって、分割スティックからのすべての実現可能なシフトと組み合わせたすべてのサブセットの合計を検索すると、構成を見逃すことなく、解空間全体がカバーされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def meet_in_middle(arr):
    n = len(arr)
    half = n // 2
    left = arr[:half]
    right = arr[half:]

    def gen(a):
        res = []
        m = len(a)
        for mask in range(1 << m):
            s = 0
            for i in range(m):
                if mask & (1 << i):
                    s += a[i]
            res.append((s, mask))
        return res

    L = gen(left)
    R = gen(right)

    sums = {}
    for s1, m1 in L:
        for s2, m2 in R:
            s = s1 + s2
            if s not in sums:
                sums[s] = (m1, m2)
    return sums

def solve_case(n, arr):
    total = sum(arr)
    best_diff = float('inf')
    best = None  # (i, S, subset_mask, split_t, side_choice)

    full_indices = list(range(n))

    for i in range(n):
        xi = arr[i]
        others = arr[:i] + arr[i+1:]

        sums = meet_in_middle(others)

        # target for first beam
        target = total / 2

        for S, (m1, m2) in sums.items():
            # interval [S, S+xi]
            if S <= target <= S + xi:
                diff = 0
                t = int(target - S)
            else:
                d1 = abs(S - target)
                d2 = abs(S + xi - target)
                if d1 <= d2:
                    diff = d1
                    t = 0
                else:
                    diff = d2
                    t = xi

            if diff < best_diff:
                best_diff = diff
                best = (i, S, m1, m2, t, xi)

    i, S, m1, m2, t, xi = best
    target_mask = (m1, m2)

    # reconstruct beams
    beam1 = []
    beam2 = []

    idx = 0
    for j in range(n):
        if j == i:
            continue
        if idx < len(arr[:i]):
            bit = (m1 >> idx) & 1
        else:
            bit = (m2 >> (idx - len(arr[:i]))) & 1

        if bit:
            beam1.append(j + 1)
        else:
            beam2.append(j + 1)

        idx += 1

    # split stick i
    a = t
    b = xi - t

    # assign split parts
    if a > 0:
        beam1.append(n + 1)
    if b > 0:
        beam2.append(n + 2)

    S1 = S + a
    S2 = total - S1
    area = 0.5 * S1 * S2

    return i + 1, a, b, beam1, beam2, area

def main():
    T = int(input())
    for _ in range(T):
        n = int(input())
        arr = list(map(int, input().split()))
        i, a, b, b1, b2, area = solve_case(n, arr)

        print(i, a, b)
        print(*b1)
        print(*b2)
        print(f"{area:.12f}")

if __name__ == "__main__":
    main()
```このソリューションは、分割スティックの考えられるすべての選択肢を評価し、次に中間集合を使用して残りの要素に関する制約付きサブセット和問題を解くことを中心に構成されています。 再構成ステップでは、どのスティックが各ビームに属するかを明示的に出力できるように、サブセット マスクを追跡します。 分割スティックは、選択されたシフト t を 2 つの新しい部分の実際の割り当てに変換することによって個別に処理されます。 

実装における微妙な点は、スプリット スティックを連続的な調整を導入するものとして扱う必要があることですが、再構築するときにインデックス n+1 と n+2 の個別の割り当てに変換し直すことです。 

## 実用的な例

 スティック [6、7、6] による小さな入力を考えてみましょう。 最適な戦略は、最初のスティックを 3 と 3 に分割し、合計 16 にすることです。最適な分割では、8 と 8 でビームのバランスが取れ、最大の製品が生成されます。 

| ステップ | 選択された分割 | 部分集合和 S | 調整t | ビーム 1 合計 | ビーム 2 合計 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 6 を 3,3 に分割する | 7 | 1 | 8 | 8 |

 このトレースは、スティック全体のみが許可されていた場合には不可能だった正確なバランスを分割によってどのように可能にするかを示しています。 

次に [5, 8, 2, 6] を考えてみましょう。 合計は21、目標は10.5です。 分割しない場合、最も近いサブセットの合計は 10 または 11 になる可能性がありますが、S = 9 および xi = 2 を与える構成を選択したとします。その場合、区間は [9, 11] となり、これには 10.5 が含まれるため、分割後に完全なバランスを達成できます。 

| ステップ | S | xi | 間隔 | ターゲット | 結果 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 9 | 2 | [9、11] | 10.5 | 正確なヒット |

 これは、分割が重要である理由を示しています。分割により、離散サブセットの合計が重複する間隔に変換され、中間点への正確またはほぼ正確な位置合わせが可能になります。

 ## 特殊なケース

 重要なエッジケースは、最適解がスティックを「対称」に分割する必要がなく、サブセット合計のギャップを埋めるために純粋に分割を使用する場合に発生します。 このような場合、最適な t は 0 または xi のいずれかになり、分割されたスティックは効果的に通常のアイテムに戻ります。 区間評価では常にエンドポイント S と S + xi の両方が考慮されるため、アルゴリズムはこれを自然に処理します。そのため、分割がバランスの取れた方法で使用される必要があるとは決して想定しません。 

もう 1 つのエッジ ケースは、複数のサブセットの合計が同じ最小距離の半分に達する場合です。 このようなサブセットはいずれも同じ目的値を生成し、ビームの割り当ては解の一意性ではなく、選択したマスクのみに依存するため、再構成は有効なままです。
