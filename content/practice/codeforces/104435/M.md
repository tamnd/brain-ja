 ## 解決策
 ## 問題の理解

 同じ一連の組織間の関係について 2 つの完全な説明が与えられていますが、一方の説明では組織に名前が付けられ、もう一方の説明では組織に番号が付けられています。 私たちのタスクは、組織のすべてのペアが両方の説明でまったく同じ関係タイプを持つように、名前と番号の間に 1 対 1 の対応関係が存在するかどうかを判断することです。 

最初の説明では名前を使用し、組織のペアごとに、同盟、紛争、または合併の検討という 3 つの対称関係タイプのいずれかを示します。 2 番目の記述では、1 から n までの整数ラベルを使用し、同じ種類の関係タイプをインデックスのペアに割り当てます。 どの名前がどのインデックスに対応するかは分からないため、一貫した再ラベル付けが存在するかどうかを判断する必要があります。 

再ラベル付けによって 2 つの関係構造が同一になる場合、答えは不可能です。 1 つの再ラベル付けが機能する場合は、それを出力する必要があります。 複数の再ラベル付けが機能する場合は、あいまいさを報告する必要があります。 

n ≤ 10 という制約が構造上の重要なヒントです。 名前とインデックス間の全単射はサイズ n の単なる順列であり、10 の階乗は十分小さいため、すべての可能性をチェックすることが可能です。 主な微妙な点はパフォーマンスではなく正確さです。すべての順列はすべてのペアごとの制約に対して一貫して検証される必要があり、有効な順列がいくつ存在するかをカウントする必要もあります。 

よくある失敗例は、グローバルな一貫性を強制せずにエッジを独立して処理することです。 たとえば、順列は 1 つの隠れた競合ペアを除くすべてのテストされたペアを満たす可能性があり、貪欲な割り当てまたは部分的な割り当てではその矛盾が見逃されます。 すべてのペアではなく、指定されたエッジのみをチェックする場合には、別の問題が発生します。 この問題では両方のデータセットの完全性が保証されているため、すべてのペアが一致する必要があります。 欠落しているエッジを無視すると、間違ったマッピングが黙って受け入れられてしまいます。 

## アプローチ

 直接的なアイデアは、インデックスに 1 つずつ名前を割り当てて、一貫性を確認しながら実行してみることです。 これは後戻り順列構造になります。 各ステップで、次の名前の未使用のインデックスを選択し、これまでに形成されたすべての関係を検証します。 これは正しいです。有効な解はすべて順列であり、すべての順列を体系的に探索するからです。 

ただし、枝刈りを行ったとしても、検索空間は基本的に n! 最悪の場合、n = 10 の場合、可能性は約 360 万通りになります。 各検証には、すべてのペアまたは記録されたすべての関係 (最大 45 ペア) のチェックが含まれます。 これにより、最悪の場合、数億回のプリミティブ比較が行われることになりますが、単純な配列と早期終了を使用して実装されている場合は、Python ではまだ許容されます。 

重要な観察は、この構造がエッジの色 A、B、C で完全にラベル付けされた完全なグラフ上のグラフ同型問題であるということです。グラフは小さくて密であるため、両方の構造を隣接行列として保存し、順列を直接テストできます。 これにより、複雑な状態管理が回避され、非常に小さな定数で各チェックが O(n²) になることが保証されます。 

また、0、1、または複数の有効な全単射を区別する必要もあります。 複数の有効な順列が検出されたら、早期に停止できます。

 ## アルゴリズムのチュートリアル

 両方のデータセットを 3 つの関係タイプにわたる隣接行列として表します。 

次に、インデックスに名前を割り当てるすべての順列を試し、それらを検証します。

1. すべての組織名を読み取り、0 から n−1 までのインデックスを割り当てます。 名前からインデックスへのマッピングを構築します。 
2. 名前付きグラフの n × n 行列を構築します。ここで、named[i][j] には、名前 i と名前 j の間の関係タイプが格納されます。 関係は対称であるため、両方の方向を満たします。 
3. インデックス付きグラフの n × n 行列を構築します。ここで、buzz[i][j] にはインデックス i と j の間の関係タイプが格納されます。 
4. インデックス [0..n−1] のすべての順列を繰り返します。 各順列は、名前インデックス i からバズ インデックス perm[i] へのマッピングを表します。 
5. 各順列について、すべてのペア i < j をチェックして一貫性を検証します。 named[i][j]がbuzz[perm[i]][perm[j]]と等しいことが必要です。 不一致が発生した場合は、この順列を直ちに破棄してください。 
6. すべての制約を満たす順列の数を数えます。 最初の有効なものを保存します。 
7. カウントが 0 の場合、IMPOSSIBLE を出力します。 カウントが 1 より大きい場合は、TOO MANY を出力します。 それ以外の場合は、マッピングを反転して、各バズ インデックスに対応する名前を出力します。 

### なぜ効果があるのか

 このアルゴリズムは、2 つの頂点セット間で考えられるすべての全単射を明示的に列挙します。 全単射候補ごとに、すべてのエッジ ラベルが保存されているかどうかがチェックされます。 すべてのペアがチェックされるため、グラフ間の構造上の矛盾が検出されます。 逆に、有効な同型写像は順列の 1 つとして出現する必要があるため、検出されます。 一意性は、有効なソリューションを数えることで正確に把握されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, r = map(int, input().split())
    names = [input().strip() for _ in range(n)]
    name_id = {names[i]: i for i in range(n)}

    # encode relations: A=0, B=1, C=2
    def enc(c):
        return 0 if c == 'A' else 1 if c == 'B' else 2

    named = [[-1] * n for _ in range(n)]
    buzz = [[-1] * n for _ in range(n)]

    # read named relationships
    for _ in range(r):
        p, x, y = input().split()
        i, j = name_id[x], name_id[y]
        named[i][j] = named[j][i] = enc(p)

    # read buzz relationships
    for _ in range(r):
        p, a, b = input().split()
        a, b = int(a) - 1, int(b) - 1
        buzz[a][b] = buzz[b][a] = enc(p)

    import itertools

    valid = 0
    best = None

    for perm in itertools.permutations(range(n)):
        ok = True
        for i in range(n):
            pi = perm[i]
            for j in range(i + 1, n):
                if named[i][j] != buzz[pi][perm[j]]:
                    ok = False
                    break
            if not ok:
                break

        if ok:
            valid += 1
            if valid == 1:
                best = perm
            elif valid > 1:
                print("TOO MANY")
                return

    if valid == 0:
        print("IMPOSSIBLE")
        return

    inv = [""] * n
    for i in range(n):
        inv[best[i]] = names[i]

    for x in inv:
        print(x)

if __name__ == "__main__":
    solve()
```このソリューションは、関係クエリが定数時間のルックアップになるように 2 つの隣接行列を構築します。 順列反復は、数値ラベルへの名前のあらゆる可能な割り当てを表します。 検証中、ネストされたループは順列ごとにすべてのペアを 1 回チェックします。グラフは完全で対称であるため、これで十分です。 

最後の反転ステップは重要です。順列は名前インデックスを数値インデックスにマップしますが、必要な出力は、インデックス 1 から n から名前に戻る逆マッピングです。 

微妙な点は、有効なマッピングが複数見つかった場合の早期終了です。 これがないと、出力があいまいであるとすでに判断されているにもかかわらず、検索が不必要に続行されてしまいます。 

## 実用的な例

 ### サンプル 1

 すべてを列挙するのではなく、概念的に順列を追跡します。 

| ステップ | パーマ | 検証ステータス | 有効な数 |
 | --- | --- | --- | --- |
 | 1 | (フォード、GM、クライスラー) | すべてのエッジが一致します | 1 |
 | 2 | 他の順列 | 2 番目の一致後に拒否またはスキップされました | 2 |

 最初の有効な順列は、すべての関係を一貫して整列させます。 2 番目の有効な置換が見つかったため、一意性は失われますが、このサンプル構造では 1 つだけが生き残り、具体的なマッピングが生成されます。 

これは、部分的な一致だけでなく、完全なペアごとのチェックによって構造の一貫性がどのように保証されるかを示しています。 

### サンプル 2

 | ステップ | パーマ | 検証ステータス |
 | --- | --- | --- |
 | 1 | 部分的な割り当ての試行 | 不一致が早期に発見されました |
 | 2 | すべての順列 | すべてのエッジを満たすものはありません。 

すべての置換は、少なくとも 1 つの競合する関係エッジが原因で失敗します。 これは、すべてのペアをチェックすることが重要である理由を強調しています。 ローカルの一貫性はグローバルな一貫性を保証しません。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n! · n²) | すべての順列がすべてのペアにわたってチェックされます。

n ≤ 10 の場合、階乗項は十分に小さいため、Python では完全な列挙でも、特に不一致の早期枝刈りが時間制限内に収まります。

 ## 特殊なケース

 重要なエッジケースは、すべての関係がペア間で同一である場合です。 この状況では、すべての順列が有効であるため、正しい出力は多すぎます。 アルゴリズムは停止する前に複数の有効な順列をカウントするため、これを自然に処理します。 

もう 1 つのエッジ ケースは、グラフ間で 1 つまたは 2 つのエッジのみが異なる場合です。 単純な部分チェックのアプローチでは、すべてのペアを検証しない場合、これらの不一致を見逃してしまう可能性があります。 ここでは、完全な行列比較により、たとえ 1 つの不一致であっても、置換が即座に拒否されることが保証されます。 

最後のエッジ ケースは、正しいマッピングが恒等順列である場合に発生します。 それでも、アルゴリズムはすべての順列を探索しますが、有効な解を 1 つだけ認識し、マッピングを反転した後にそれを正しく出力します。
