 ## 解決策
 ## 問題の理解

 頂点がイベントを表し、有向エッジが許容される時間遷移を表す有向グラフが与えられます。 イベント A から、A から B への有向パスが存在する場合、イベント B に到達できます。この問題は、「不可逆到達可能性」、つまり、A は B に到達できるが、B は A に到達できない場合にのみ焦点を当てています。強く接続された領域では、すべてが相互に到達可能であるため、そのような領域内にあるものは、それ自体に関して不可逆的であるとはみなされません。 

ある固定イベント X で終了するが、到達可能性の観点から厳密に X の「前」にあるノードから開始するすべての有向パスに注目すると、興味深い構造が現れます。 イベント X は、そのようなパスのすべてのペアが少なくとも 1 つの共通の有向エッジを共有する場合、安全であるとみなされます。 2 つのパスがエッジを共有しないように X に到達する 2 つの異なる方法が見つかる場合、X には問題があります。 

タスクは、すべてのノードがこの意味で安全になるように、できるだけ少ない有向エッジを削除することです。 

入力グラフは、テスト ケース全体で最大 3 × 10^5 のノードと 4 × 10^5 のエッジを含む大規模なものにすることができます。 これにより、パスの列挙、パスのペアの比較、またはノードごとのフロー計算の実行を試みるソリューションは直ちに除外されます。 テスト ケースごとに 2 次または 2 次に近いものはすべて失敗します。 

いくつかの危険な状況については、覚えておく価値があります。 

グラフがすでに何らかのルートに向けられたツリーである場合、すべてのノードには上から到達するための唯一の方法があるため、削除は必要ありません。 

ノードに、X で結合する 2 つの互いに素なパスなど、早期に分岐する複数の独立した受信ルートがある場合、すべてのルートが単一の必須エッジを通過するように強制するのに十分なエッジを削除しない限り、X は無効になります。 

強く接続されたコンポーネント内ではすべてのノードが他のすべてのノードに到達できるため、これらのノードは厳密な一方向の関係にならないため、サイクルによって不可逆的な構造が作成されることはありません。 SCC を圧縮しない場合、冗長な内部構造が過大にカウントされる危険があります。 

## アプローチ

 直接的な試みは、すべてのノード X を調べ、X へのすべての入力パスを列挙し、そのうちの 2 つをエッジ分離できるかどうかを確認することです。 これはすぐにパス爆発の問題に変わります。 すべての単純なパスを計算しても、最悪の場合は指数関数的になるため、これは実行できません。 

重要な構造的観察は、「X へのすべてのパスが共通のエッジを共有する」という条件は、X への入力ルートのセットに単一の避けられないボトルネック エッジがあると言うのと同じであるということです。 フローの観点からグラフを見ると、これは、X の入力構造が、すべてのパスが単一のエッジ チェーンを強制的に通過する構造のように動作するため、エッジに独立した意味での分岐は許可されないと言っているのと同じです。 

ここで、何が X への 2 つのエッジの共通でないパスを作成するかを考えてみましょう。これは、X に、X に到達する前に分岐する少なくとも 2 つの「独立した」入力ルートがある場合に正確に発生します。X への 2 つの異なる入力エッジが、共通のない上流構造によってサポートされると、直ちに 2 つのエッジの共通パスが得られます。 

これは単純化を示唆しています。つまり、2 つの保持された入力エッジがあるとすでにパスの分岐が可能になるため、ノードごとに 1 つを除くすべての有効な入力エッジを削除する必要があります。 最終グラフで各ノードの入力エッジが 1 つだけの場合、X へのパスは入力エッジの単一チェーンに従うことを強制されるため、そのようなすべてのパスはそのチェーン上のすべてのエッジを共有します。 

したがって、問題は、すべてのノードが可能な限り少数のエッジを削除しながら、最大 1 つの入力エッジを保持するようにエッジのサブセットを選択することに帰着します。 

これはノードごとのローカルな最適化です。 元のグラフでノードの次数 k がある場合、それらのエッジのうち多くても 1 つを保持でき、残りの k − 1 を削除する必要があります。これをすべてのノードで合計すると、最小の削除数が得られます。

SCC 内ではすべてのノードが相互に到達可能であり、「不可逆パス」条件が内部的に適用されることはないため、強接続コンポーネントによって答えが変わることはありません。 SCC を縮小すると、無関係な内部サイクルのみが削除され、結果の DAG には同じ度数ロジックが残ります。

 ## アルゴリズムのチュートリアル

 1. グラフを強く接続されたコンポーネントに分解します。 サイクル内の内部到達可能性は、異なるコンポーネント間の不可逆パスに影響を与えないため、各 SCC は単一ノードとして扱われます。 
2. 各 SCC がノードであり、異なる SCC 間のすべてのエッジが有向エッジになる凝縮グラフを構築します。 
3. 圧縮されたグラフ内の各ノードについて、他のコンポーネントから到着する個別の入力エッジの数を数えて、その入次数を計算します。 
4. 次数 k のノードの場合、k ≥ 1 の場合、入力エッジを 1 つだけ保持し、他のすべてを削除します。 これにより、エッジが切り離された入力パスを作成する可能性のある複数の独立したエントリ ポイントをノードが受け取らないことが保証されます。 
5. すべてのノードの削除されたエッジの数を合計します。これは max(0, indegree − 1) です。 

### なぜ効果があるのか

 重要な不変条件は、各ノードを処理した後、結果として得られるグラフ内のすべてのノードが最大 1 つの入力エッジを持つということです。 これにより、任意のノードにつながるすべてのパスが、入力エッジの単一チェーンに強制的にマージされます。 したがって、同じノードで終わる 2 つのパスは、そのノードへの最後の入力エッジを共有し、すべての上流の強制エッジも再帰的に共有する必要があります。 分岐がエッジ レベルで排除されるため、どのノードへの 2 つのエッジの独立したパスを構築することもできなくなります。 

逆に、ノードに 2 つ以上の入力エッジが残っている場合、それらのエッジはすでに 2 つの別個のエントリ ルートを提供しており、SCC 縮小によって内部サイクルが削除されるため、これらのエントリ ルートは、エッジに独立したパスに拡張できる真に異なる上流構造に対応します。 したがって、複数の入力エッジを保持することがまさに発散を生み出すものであり、1 つを除いてすべてを削除することが必要かつ十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def kosaraju(n, g, gr):
    visited = [False] * n
    order = []

    def dfs(v):
        visited[v] = True
        for to in g[v]:
            if not visited[to]:
                dfs(to)
        order.append(v)

    def rdfs(v, comp_id):
        comp[v] = comp_id
        for to in gr[v]:
            if comp[to] == -1:
                rdfs(to, comp_id)

    for i in range(n):
        if not visited[i]:
            dfs(i)

    comp = [-1] * n
    cid = 0
    for v in reversed(order):
        if comp[v] == -1:
            rdfs(v, cid)
            cid += 1

    return comp, cid

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        g = [[] for _ in range(n)]
        gr = [[] for _ in range(n)]
        edges = []

        for _ in range(m):
            a, b = map(int, input().split())
            a -= 1
            b -= 1
            g[a].append(b)
            gr[b].append(a)
            edges.append((a, b))

        comp, c = kosaraju(n, g, gr)

        indeg = [0] * c

        for a, b in edges:
            ca, cb = comp[a], comp[b]
            if ca != cb:
                indeg[cb] += 1

        ans = 0
        for x in indeg:
            if x > 1:
                ans += x - 1

        print(ans)

if __name__ == "__main__":
    solve()
```実装ではまず、Kosaraju のアルゴリズムを使用して強く接続されたコンポーネントを圧縮します。これにより、サイクルが入次構造に干渉しないことが保証されます。 圧縮後、各エッジは異なるコンポーネントのみを接続します。 

次に、コンポーネントごとに入力エッジをカウントします。 コンポーネントごとに最大 1 つの入力エッジを保持できるため、最初の入力エッジを超える余分な入力エッジはすべて削除する必要があり、正確に indegree − 1 が答えに寄与します。 

よくある間違いは、SCC 収縮をスキップすることです。 これにより、内部サイクル エッジが複数の受信代替として誤ってカウントされ、答えが水増しされてしまいます。 もう 1 つの微妙な点は、同じコンポーネントのペア間の複数のエッジを個別にカウントする必要があることです。これは、それぞれが独立したパスに寄与する可能性のある個別の遷移を表すためです。 

## 実用的な例

 ### 例 1

 入力:```
3 2
1 2
2 3
```サイクルがないため、各ノードは独自のコンポーネントになります。 度数は次のとおりです。 

| コンポーネント | 度 |
 | --- | --- |
 | 1 | 0 |
 | 2 | 1 |
 | 3 | 1 |

 どの度数も 1 を超えないため、エッジは削除されません。 

出力：```
0
```これは、グラフがすでに単純なチェーンであるため、任意のノードへのすべてのパスが同じエッジを通過するという直観と一致します。 

### 例 2

 入力:```
4 3
1 2
2 3
1 3
```SCC 収縮後 (サイクルが存在しない)、次のように度数を計算します。 

| ノード | 入力エッジ |
 | --- | --- |
 | 1 | 0 |
 | 2 | 1 |
 | 3 | 2 |

 ノード 3 には 2 つの入力エッジがあります。これは、ノード 3 に到達するための 2 つの独立した方法があることを意味します。 そのうちの 1 つを削除する必要があります。 

出力：```
1
```これは主要な障害モードを示しています。直接エッジ 1 → 3 が 2 → 3 をバイパスする代替ルートを作成し、発散を生じます。

 ## 特殊なケース

 純粋な有向サイクルを含むグラフでは、SCC 収縮後に除去がゼロになるはずです。 すべてのノードは単一のコンポーネントにマージされ、コンポーネント間で比較するエッジは残りません。 

同じ先行構造からの複数の並列入力エッジを持つノードは、圧縮後も複数の入力エッジとしてカウントされます。これは、各エッジがノードへの個別のパスを形成できる個別の遷移を表すためです。 

多くのノードが 1 つのノードを指している星形のグラフでは、そのノードで大きな入次数が生成され、アルゴリズムはそれらのエッジの 1 つを除いてすべてを正しく削除し、中心への残りのすべてのパスが単一のエントリ ルートを強制的に通過するようにします。
