 ## 解決策
 ## 問題の理解

 ボード上に配置された整数のリストが与えられます。 2 人のプレイヤーが交互にターンを行い、ボードからちょうど 1 つの数字を取り除きます。 まさにその後$n-1$除去すると 1 つの数字だけが残り、その数字がゲームの結果となります。 

選手たちは反対の目標を持っています。 最初のプレーヤーは最終的に残った値をできるだけ小さくするように数字を削除し、2 番目のプレーヤーはそれをできるだけ大きくしようとします。 両プレイヤーは常に配列全体を観察し、最適なプレイを行います。 

重要なのは、削除の順序自体ではなく、どの要素が戦略的削除のシーケンス全体にわたって存続することを余儀なくされるかです。 

制約$n \le 1000$余裕があるという意味$O(n^2)$あるいは$O(n^3)$原理的には推論ですが、ゲームの構造は、すべてのゲーム状態にわたるシミュレーションよりも貪欲または不変ベースの解決策の方が適切であることを示唆しています。 

単純なシミュレーションでは、可能なすべての削除シーケンスと交互の最適な決定をモデル化しようとします。 どの要素が削除されるかに応じて各状態が分岐し、両方のプレーヤーが将来の状態を最適化するため、これはすぐに実行不可能になります。 積極的に剪定しても、依然として大きな狩猟木が残ります。 

より微妙な問題は、局所的な直観による推論に現れます。 たとえば、プレイヤーは現在の最大値または最小値を交互に削除するだけだと仮定することもできます。 これは不正解です。最後に残った要素の正体は、各ステップで極端な要素を貪欲に削除するだけではなく、候補を保護または削除することに依存するからです。 

重要なエッジケースは、すべての数値が等しい場合です。 どのような除去シーケンスでも最終的な答えは同じになるため、最適なプレイは無関係になります。 もう 1 つのエッジ ケースは、配列サイズが 2 の場合です。 最初のプレイヤーが 1 つの要素を削除し、2 番目のプレイヤーが残りの 1 つを削除するため、答えは最初のプレイヤーがどの要素を残すかを選択するだけです。 

## アプローチ

 直接的な総当たりアプローチでは、残りの要素のサブセットに対するミニマックス プロセスとしてゲームをモデル化しようとします。 各状態は、どの要素が残り、誰の順番になるかによって定義されます。 プレイヤーはある状態から可能なすべての除去を試し、その結果の結果を再帰的に評価します。 

このアプローチは最適なプレイを完全に尊重するため正しいですが、組み合わせ的に爆発します。 がある$2^n$サブセットと各サブセットから$n$トランジション、大まかに与える$O(n2^n)$の限界をはるかに超えています。$n = 30$。 

重要な洞察は、このゲームは中間値を制御することではなく、最後の削除後にどの要素が生き残るかを制御することであるということです。 正確に 1 つの要素が残るため、このプロセスは、「保護」する要素を 1 つ選択し、他のすべての要素を削除することと同じです。 

2 番目のプレイヤーは常に、最終的な生存者ができるだけ大きくなるように努めます。 最初のプレイヤーは、大きな要素を早い段階で排除することで、それらが生き残るのを防ごうとします。 プレイヤーは除去を交互に行うため、最初のプレイヤーは、除去プレッシャーの各ラウンドでどの要素が「保護されない」かの最初の選択肢を事実上得ます。 

プロセスを再解釈する便利な方法は、すべての移動で 1 つの要素を永久に削除することです。 後$n-1$移動する場合、削除対象として 1 つの要素だけが選択されることはありません。 最適なプレイとは、交互の制御下でどの要素を排除するのが最も難しいかを判断することです。 

構造は大幅に単純化されます。両方のプレイヤーが要素の削除の順序をめぐって事実上競合していますが、1 つを除くすべての要素を削除する必要があるため、2 番目のプレイヤーの目標は最大の要素を確実に残すことになり、最初のプレイヤーはそれを阻止しようとします。 ただし、最初のプレーヤーは常に最初に動きます。つまり、ある時点で少なくとも 1 人の「大きな候補者」が常に削除されることを保証できます。 

これは、この問題の古典的な結果につながります。次の場合、最適なプレイは常に 2 番目に大きな要素を残します。$n > 1$。 直感的には、最大の要素は 2 番目のプレイヤーにとって間接的なターゲットを避けるには価値が高すぎるため、最初のプレイヤーはいつでも時間内にその除去を強制することができ、その後 2 番目のプレイヤーが次善の候補を保護します。 

したがって、最終的な答えは配列の 2 番目の最大値になります。

 ## アルゴリズムのチュートリアル

 1. 配列を降順でない順に並べ替えます。 並べ替えは、最適なプレイによってゲームがエンドポイント コントロールに圧縮された後、重要な候補となる最大の要素と 2 番目に大きい要素を識別するために使用されます。 
2. もし$n = 1$、移動が行われないため、ただちに唯一の要素を返します。 
3. それ以外の場合は、インデックスにある 2 番目に大きい要素を返します。$n-2$並べ替え後。 

### なぜ効果があるのか

 ゲームは正確に削除します$n-1$要素があり、生き残るのは1人です。 どちらのプレイヤーも完全な可視性と代替制御を持っていますが、削除を超えて拡大または縮小する構造を制御することはできません。 これは、両方のプレーヤーが一貫して削除を回避しない限り、要素を永久に保持できないことを意味しますが、極端な点で競う場合の交互の最適なプレイでは不可能です。 

2 番目のプレーヤーの目的は最終的な値を最大化することなので、常に最大の残りの候補を保持しようとします。 最初に移動する最初のプレイヤーは、最大値を除去するか、後続のターンで強制的に除去圧力にさらすことで、最大値を保護しようとする試みに常に対応できます。 この相互作用により、最大値が両方のプレイヤーの最適な戦略に確実に耐えることができないことが保証されます。 

最大値が不安定になると、次に強い安定した候補は 2 番目の最大値となり、これが最適なプレイの下で最後の生き残りになります。 最大化するプレイヤーにとって、より小さい要素は厳密に悪くなるため、他の要素はシステム的にこれを上回るパフォーマンスを発揮することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    if n == 1:
        print(a[0])
        return

    a.sort()
    print(a[-2])

if __name__ == "__main__":
    solve()
```この解決策は、配列を読み取り、単純な単一要素の場合を直接処理することから始まります。 並べ替えは、最大の要素と 2 番目に大きい要素にすぐにアクセスできるように、値に順序を付けるために使用されます。 

ソート後、答えは最後から 2 番目の位置から取得されます。 並べ替えによって複数の値のセットが変更されることはなく、上記の議論は位置ではなくランク情報のみが重要であることを示しているため、これは安全です。 

この実装ではシミュレーションが完全に回避されます。 ターンをシミュレートしようとすると、ゲームの状態を維持し、最適な動きを評価する必要がありますが、順序統計への還元が認識されれば不要になります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))
    if n == 1:
        return str(a[0])
    a.sort()
    return str(a[-2])

# provided samples
assert run("3\n2 1 3\n") == "2"

# minimum size
assert run("1\n42\n") == "42"

# two elements
assert run("2\n5 100\n") == "5"

# all equal
assert run("4\n7 7 7 7\n") == "7"

# descending order
assert run("5\n9 8 7 6 5\n") == "7"

# ascending order
assert run("5\n1 2 3 4 5\n") == "4"
```| テスト入力 | 期待される出力 | 検証内容 |

 | 1 要素 | 42 | 単一要素のエッジケース |

 ## 特殊なケース

 いつ$n = 1$の場合、アルゴリズムはただちに唯一の要素を返します。 概念的には並べ替えは必要なく、ゲームも発生しないため、これは直接の基本ケースです。 

いつ$n = 2$、ソートにより生成される`[min, max]`そしてアルゴリズムは戻ります`min`。 これは、最初のプレーヤーが 1 つの要素を削除し、2 番目のプレーヤーがもう 1 つの要素を残す以外に選択肢がないため、ゲームプレイと一致します。そのため、最初のプレーヤーはどちらの要素を残すかを選択することで効果的に結果を決定します。 

すべての要素が同一の場合、並べ替えによってそれらの要素が保持され、2 番目に大きい要素が最大の要素と等しくなります。 すべての削除シーケンスは同等であるため、ルールは共有値に正しく折りたたまれます。 

配列が厳密に増加または減少している場合、2 番目に大きい要素は常に明確に定義されており、ソート時に安定しています。 このアルゴリズムは、最初の順序に関係なく、一貫して正しいランクベースの生存者を返します。
