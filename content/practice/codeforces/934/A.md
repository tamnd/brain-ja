 ## 解決策
 ## 問題の理解

 2 人のプレイヤーが 2 つの整数配列を操作しています。 1 人のプレイヤーは長さ n の配列を所有し、もう 1 人のプレイヤーは長さ m の配列を所有します。 各数字はランタンの明るさを表し、明るさは正、負、またはゼロになります。 

相互作用は敵対的です。 まず、最初のプレーヤーは配列から値を 1 つだけ永久に削除します。 その後、2 番目のプレーヤーは最初のプレーヤーの配列から残りの 1 つの値を選択し、自分の配列から 1 つの値を選択します。 ゲームのスコアは、これら 2 つの選択された値の積です。 2 番目のプレーヤーはこのプロダクトを最大化しようとしますが、最初のプレーヤーは最初の除去を通じてそれを最小化しようとします。 

出力は、両方のプレーヤーが最適に動作した後の最終製品です。 

制約は小さく、n と m は両方とも最大 50 です。これは、3 次または 2 次のアプローチでも安全であることをすぐに示唆していますが、解決策は、多大な最適化手法ではなく、極値のケースを慎重に分析することに依存している可能性が高いことも示唆しています。 

負の数からは、微妙な特殊なケースが発生します。 積は符号に依存するため、単一の要素を削除すると、残りのどのペアが最適になるかが反転する可能性があります。 たとえば、最初の配列が`[1, -10, 2]`そして2つ目は`[5, 6]`、削除`2`葉`1`そして`-10`これにより、最良の製品が大きな正の値と大きな負の値のどちらの組み合わせから得られるかが変わります。 全体的な最大値または最小値を削除する単純な貪欲なアプローチは、ここでは失敗します。最適な削除は、達成可能な最良の製品をどのように再形成するかに依存するためです。 

もう 1 つのエッジ ケースは、両方の配列に混合符号が含まれる場合です。 積の最大値は、最大の正の積、または 2 つの負の積のいずれかから得られます。 max×max のみを考慮するソリューションは、次のような入力では失敗します。`[-10, 1]`そして`[-5, 2]`、最高の製品はどこにありますか`50`から`-10 × -5`。 

## アプローチ

 ブルートフォース解釈は簡単です。 最初の配列から考えられる各要素を削除してみます。 結果として得られる各配列について、縮小された最初の配列の 1 つの要素と 2 番目の配列の 1 つの要素によって形成されるすべてのペアを考慮し、達成可能な最大の積を計算します。 次に、すべての削除の最小値を取得します。 

これは、両方のプレーヤーの最適な戦略を直接シミュレートするため、正しいです。 2番目のプレイヤーは常に固定除去に利用可能な最良のペアを選択し、最初のプレイヤーはすべての除去を評価します。 

入れ子構造ではボトルネックが明らかです。 可能な除去は n 個あり、それぞれについて最大 (n−1) × m 個のペアをスキャンします。 これにより、O(n²m) が得られます。これは、n, m ≤ 50 の場合、最大でも約 125,000 回の操作ですが、それでも容易に制限内に収まります。 ただし、1 つの要素を削除した後、2 番目のプレーヤーは常に固定の 2 番目の配列と変更された最初の配列から選択し、最適な選択は 2 番目の配列の極値のみに依存することに注意することで、より良い結果を得ることができます。 

固定された残りの最初の配列の場合、2 番目のプレイヤーは常に、そこから選択した要素 x を、x の符号に応じて 2 番目の配列の最大値または最小値のいずれかと組み合わせます。 x が正の場合、最適なパートナーは b の最大値になります。 x が負の場合、最適なパートナーは b の最小値になります。 これにより、各構成の評価が最初のアレイを 1 回スキャンするだけで済みます。 

この改善は概念的なものです。すべてのペアを列挙する代わりに、2 番目の配列のグローバル極値を使用して内部最大化を定数時間の決定に削減します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²m) | お(1) | 承認済み |
 | 最適 | O(n²) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 最初の配列から 1 つの要素を削除した後、相手は選択された最初の配列要素の符号のみに基づいて最適に反応するという考えを修正します。 

1. 2 番目の配列の最大値と最小値を計算します。 最適なペアリングでは符号に応じていずれか 1 つが使用されるため、これら 2 つの値で十分です。 
2. 最初の配列の各インデックス i を反復処理し、削除する要素として扱います。 
3. 最初の配列内の残りの要素をすべてスキャンして、a[i] を削除する効果を構築します。 
4. 残りの要素 x ごとに、それが形成できる最良の積を計算します。 

x が負でない場合は x × max(b) に寄与し、それ以外の場合は x × min(b) に寄与します。 
5. この削除に対するすべての寄与の最大値を取得します。 
6. すべての除去の最小値を追跡します。 

最終的な答えは、すべての最適な応答に対するこの最小値です。 

これが機能する主な理由は、固定 x について、対戦相手の選択が他のすべての要素から独立しているためです。 2 番目のプレーヤーは、異なる x 値間で選択肢を混合しても利益を得ることはありません。そのため、2 番目の配列のグローバル極値は最適な応答を完全に記述します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    bmax = max(b)
    bmin = min(b)

    def best_value(arr):
        best = -10**30
        for x in arr:
            if x >= 0:
                best = max(best, x * bmax)
            else:
                best = max(best, x * bmin)
        return best

    ans = 10**30

    for i in range(n):
        reduced = a[:i] + a[i+1:]
        ans = min(ans, best_value(reduced))

    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションでは、2 番目の配列の極値は決して変更されないため、それらの値を 1 回事前計算します。 ヘルパー関数は、残りの各要素を個別にチェックすることによって、固定された最初の配列構成に対する 2 番目のプレーヤーの最良の応答を評価します。 

唯一の微妙な実装の詳細は、削除を効率的に処理することです。 n が小さいため、配列をスライスするだけで十分であり、コードを明確に保つことができます。 内部のサインに基づいた意思決定`best_value`は、ペアの列挙を回避する重要な削減です。

 最小オーバー除去数は 252 です。 

これは、最初のプレイヤーがより高い潜在値 (20) を犠牲にして、より低い最大結果を強制する方法を示しています。

| 削除されました | | のまま 残りのセットの最高の製品 | 結果 |

 ## 特殊なケース

 重要なエッジ ケースは、1 つの配列内のすべての値が負の場合です。 このような場合、2 番目のプレーヤーは常に他の配列の最小 (最も負の) 値との組み合わせを好みます。これは、最大の正の積が生成されるためです。 アルゴリズムは、負の x ごとに x × bmin を評価するため、これを正しく処理します。 

両方の配列に符号が混在している場合、別の特殊なケースが発生します。 ここでは最適な戦略が要素ごとに切り替わり、単純なグローバル ヒューリスティックは失敗します。 この実装では、単一のグローバル ペアリング戦略を想定するのではなく、要素ごとに最適なペアリングが正しく再計算されます。 

最後のエッジケースは、単一の要素を削除すると、残りのセットを支配する符号が変わる場合です。 アルゴリズムは削除ごとに最適な値を最初から再計算するため、このシフトは追加のロジックなしで自然に処理されます。
