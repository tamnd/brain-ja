 ## 解決策
 ## 問題の理解

 空間内に軸が揃った 3D ボックスのコレクションが与えられます。 各ボックスは、x、y、z 軸上の独立した間隔によって定義される実線領域を表します。 ボックスはどのようにしても重なり合う可能性があります。 

正確に 3 つの無限の軸に整列した切断面を配置することができます: x = a の形式の 1 つの垂直面、y = b の形式の 1 つ、および z = c の形式の 1 つです。ここで、a、b、c は整数でなければなりません。 これら 3 つの平面のうち少なくとも 1 つがボックスと交差する場合、つまり、平面がボックス内の点を通過する場合、そのボックスは「処理された」とみなされます。 

このタスクは、すべてのボックスが 3 つの平面の少なくとも 1 つと交差するような a、b、c の選択肢が存在するかどうかを判断し、存在する場合は有効なトリプルを出力することです。 

各ボックスは、単一の座標にローカルではない制約に影響します。 ボックスは、x 範囲に a が含まれる、y 範囲に b が含まれる、または z 範囲に c が含まれるという 3 つの独立した条件のうちの少なくとも 1 つが満たされる場合に満たされます。 したがって、この構造は、強力な軸揃え分解を伴う全体的なカバー問題です。 

制約では最大 100,000 個のボックスが許可されるため、ボックス間の二次関数以上の相互作用は直ちに遅すぎます。 候補カットのトリプルすべて、またはすべてのペアを試す解決策は実行不可能です。 候補カットごとに実現可能性を最初から再計算するものも、およそ O(n²) 個の動作を引き起こすため、失敗します。 

いくつかの特殊なケースは、早期に切り分ける価値があります。 

すべてのボックスが一次元で重なり合っている場合、適切に配置された 1 つのカットですでにすべてを満たすことができ、答えは自ずと「はい」になります。 たとえば、すべてのボックスが x = 0 と交差する場合、b と c に関係なく、a = 0 のみを選択するだけで十分です。 

反対の極端に、3 つの互いに素なボックスのグループを考えてみましょう。 

入力:

 n = 3

 ボックス 1: x は [0,1]、y は [0,1]、z は [0,1]

 ボックス 2: [10,11] に x、[10,11] に y、[10,11] に z

 ボックス 3: [20,21] に x、[20,21] に y、[20,21] に z

 軸ごとに 1 つのカットを選択できるため、正しい答えが存在しますが、各ボックスを「最適な軸に独立して」割り当てる単純な戦略は、割り当てがグローバルに干渉するため失敗します。 

もう 1 つの微妙な失敗例は、軸全体で独立していると仮定した場合に発生します。 「最も多く残っているボックスに当たる切断面を選択する」などの貪欲なアプローチはすぐに失敗します。x のボックスを削除すると、y または z でどの切断面が有効かが変わるためです。 

本当の難しさは、各ボックスが 3 つの異なる「出口」を提供しており、すべてのボックスを集合的にカバーするグローバル値 (a、b、c) を選択する必要があることです。 

## アプローチ

 ブルートフォース解釈では、考えられるすべてのトリプル (a、b、c) が試行されます。 ギャップ内でカットをシフトしても、どのボックスと交差するかは変わらないため、各座標の候補値は間隔の端点から取得できます。 これにより、最悪の場合でもすでに O(n³) 個の候補トリプルが生成されますが、これは大きすぎます。 

座標間の結合を減らす必要があります。 

重要な構造観察は、最初に 1 つの座標カット (たとえば x = a) を固定することです。 これが修正されると、すべてのボックスが 2 つのグループに分割されます。X カットと交差するグループとそうでないグループです。 最初のグループはすでに満たされているため、無視できます。 2 番目のグループは、y カットと z カットのみを使用して満たされる必要があります。 

したがって、問題は 2D バージョンになります。残りのボックスが与えられた場合、残りの各ボックスが y = b または z = c を満たすように b と c を選択する必要があります。 

この 2D 問題には有用な再定式化があります。 b がその y 間隔内にある場合、または c がその z 間隔内にある場合、ボックスは満たされます。 したがって、各ボックスには (b ∈ Y_i) OR (c ∈ Z_i) の形式の制約が課されます。 同様に、b が Y_i の外側にある場合、c は Z_i の内側に強制的に配置されます。 

b が固定されている場合、c の条件は非常に単純になります。y 間隔に b が含まれず、すべての z 間隔と交差するすべてのボックスを調べます。 その交差が空でない場合は、その中の任意の c を選択できます。

したがって、固定 a の実現可能性は、z 上の誘導交差が空ではないような任意の b を見つけることになります。 

ブルート フォースでは、すべての候補 b の値を試し、毎回 z 交差を再計算します。これは、固定 a あたり O(n²) です。 

この改善は、現在の一連の「アクティブな制約」を動的に維持しながら、これを b にわたるスイープに変えることで実現します。 各ボックスは、b がその y 間隔の外側にあるときに、c 制約に対してアクティブになります。 b が移動すると、ボックスは y 間隔の境界でこのアクティブ セットに出入りします。 挿入と削除をサポートするデータ構造を使用してアクティブ セットの Z 間隔の交差を維持し、グローバルな最小右端点と最大左端点を追跡できます。 

これを候補 a ごとに繰り返し、構成が成功した場合はそれを返します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | (a、b、c) に対するブルート フォース | O(n3) | O(n) | 遅すぎる |
 | a を修正し、b を動的交差でスイープ | O(n² log n) 最悪 | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. a の候補値をすべての x 間隔のエンドポイントのセットに制限します。 エンドポイント間では交差するボックスのセットが変化しないため、有効性に影響を与えることなく最適解を境界値にシフトできるため、これで十分です。 
2. 各候補 a について、ボックスを 2 つのセットに分割します。x 間隔に a が含まれるものと、x 間隔に含まれないものです。 最初のセットはすでに満たされているため、無視できます。 
3. 残りのセットが空の場合、すべてのボックスが X カットだけですでにカバーされているため、有効な解決策がすぐに得られます。 
4. 残りのボックスについては、y 間隔と z 間隔にわたって動的構造を構築します。 関連するすべての y 境界イベントにわたって b をスイープします。 
5. b が移動するとき、「アクティブな制約」であるボックスのセットを維持します。これは、b がその y 間隔の外側にあることを意味します。 これらはまさに、c がその z 間隔内にあることを必要とするボックスです。 
6. すべてのアクティブな Z 範囲の最大左端点と最小右端点を追跡することにより、アクティブ セット全体にわたる Z 間隔の交差を維持します。 
7. b の各イベント位置で、現在の交差が有効であるかどうか、つまり max_lz ≤ min_rz であるかどうかを確認します。 そうであれば、この交差部分内で c を選択でき、有効なトリプル (a、b、c) が見つかります。 

### なぜ効果があるのか

 固定の a と b の場合、x = a にヒットせず、同時に y = b にもヒットしない限り、ボックスは満たされます。 このような満たされていないボックスは、 c をその z 間隔内に強制的に配置します。 したがって、実現可能性の条件は、空ではない必要な Z 間隔の交差点に正確に帰着します。 スイープにより、「どのボックスが z を必要とするか」という組み合わせ的に異なるすべての構成が、このセットが変更される境界でチェックされるため、有効な解決策がスキップされることはありません。

```この実装は、x カットを固定してから、z に誘導された制約を維持しながら有効な y カットを検索するという考えに従います。 ヒープベースの構造は、Z 間隔の現在の交差を追跡するために使用されます。 左端の最小値と右端点の最大値によって、いつでも実現可能性が決まります。 

微妙な点は、b の候補値は、ボックスが「z が必要」セットに入るイベント境界またはそこから出るイベント境界でのみチェックする必要があることです。 このような境界間では、アクティブな制約セットは変化しないため、実現可能性は一定のままです。 

コード構造は、x 候補に対する外側のループを y に対する内側のスイープから分離し、各構造変更がフェーズごとに 1 回だけ処理されるようにします。

 ## 特殊なケース

 重要なエッジ ケースは、すべてのボックスが既に X 平面と交差している場合です。 たとえば、すべての x 間隔に選択された a が含まれている場合、残りのセットは空であり、b または c を検索せずにすぐに受け入れるのが正しい動作です。 

もう 1 つのケースは、正しいソリューションが 1 つまたは 2 つのプレーンのみを効果的に使用する場合です。 たとえば、すべてのボックスが固定 c に対して z = c と交差する場合、x と y のカットが任意であっても、アルゴリズムは依然としてそのグローバル値を見つけなければなりません。 すべてのイベントにわたって z 交差点が空ではないため、b のスイープは引き続き機能し、実現可能性が早期に検出されます。 

最後のエッジ ケースは、y 間隔の境界点でのみ実現可能性が現れる場合に発生します。 イベントベースのスイープでは、これらのポイントが明示的にチェックされるため、狭い間隔のエンドポイントにのみ存在するソリューションが見逃されることはありません。
