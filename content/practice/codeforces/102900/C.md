 ## 解決策
 ## 問題の理解

 2 つの整数が与えられます$X$そして$Y$、すべてのペアを考慮します$(i, j)$どこ$0 \le i \le X$そして$0 \le j \le Y$。 各ペアについて、2 つの数値のビット単位の AND が 0 であるペアのみを考慮します。これは、2 つの数値が共通の設定ビットを共有しないことを意味します。 

すべての有効なペアについて、値を計算します。$\lfloor \log_2(i + j) \rfloor + 1$、これは本質的に、表現するために必要なビット数です。$i + j$バイナリで。 この値をすべての有効なペアにわたって合計し、結果のモジュロを出力します。$10^9 + 7$。 

したがって、問題は、整数ペアのグリッドに対する重み付けされた計数タスクであり、有効性はビットごとの制約に依存し、寄与は合計のバイナリ長にのみ依存します。 

制約は非常に大きいです。$X, Y \le 10^9$そして最大まで$10^5$テストケース。 これにより、ペアを反復したり、テスト ケースごとに 1 つの次元を反復したりするソリューションは即座に除外されます。 平$O(X)$テストごとにテストすることは不可能であり、範囲にわたる寄与を明示的に列挙するものはすべて、通常はビットを介した動的プログラミングを伴う、数字ベースまたはビットごとの組み合わせアプローチに置き換える必要があります。 

素朴な推論を破る主なエッジケースは、AND 制約が無視されるか部分的に強制される場合です。 たとえば、$X = 3, Y = 3$、ペア$(1, 2)$以来有効です$1 \& 2 = 0$、 しかし$(1, 3)$ビットを共有しているため無効です。 単純なプレフィックスサム$i+j$フィルタリングを行わないと、ビット競合が大幅にオーバーカウントされます。 

もう 1 つの微妙な問題は、関数が次の最上位ビットのみに依存することです。$i+j$、非常に多くのペアが同じ寄与クラスに分類されます。 寄与をペアごとに独立したものとして扱うと、集約を可能にする組み合わせ構造を見逃してしまいます。 

## アプローチ

 ブルートフォースアプローチでは、すべてのペアが列挙されます。$(i, j)$、どうかを確認してください$i \& j = 0$、計算する$i+j$、バイナリの長さを追加します。 これは正しいですがコストがかかります$O(XY)$テスト ケースごとの操作数は次のとおりです。$10^{18}$最悪の場合は即実行不可能になります。 

それを反復処理に減らしても$i$有効なデータを高速にカウントする方法を使用します。$j$まだ私たちに残しています$O(X)$を掛けると大きすぎます。$10^5$テストケース。 

重要な構造的観察は、制約が$i \& j = 0$ビット間でビット単位に独立しています。 各ビット位置で、両方の数値に同時に 1 を配置することはできません。 これは、次のバイナリ表現に対する数字 DP を示唆しています。$i$そして$j$、私たちがまだ制限されているかどうかを追跡します$X$そして$Y$、ビットが重複しないようにします。 

指定された範囲の合計を生成する有効なペアの数を数えることができたら、ペアをグループ化することができます。$i+j$。 各ペアを個別に計算する代わりに、範囲に該当するペアの数を数えます。$[2^k, 2^{k+1}-1]$。 各範囲が貢献します$(k+1)$したがって、問題はビット長バケットの合計に帰着します。 

これにより、問題は多次元の数字 DP に変わり、状態はバイナリでの位置、境界への厳密性、キャリー伝播を追跡します。$i+j$。 AND 制限により、各ビットでのみ許可されるため、遷移が簡素化されます。$(0,0), (0,1), (1,0)$。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1.変換$X$そして$Y$固定長のバイナリ配列に変換します (最大 30 ～ 31 ビットですが、キャリーの安全性を考慮して 60 にパディングします)。 これにより、すべてのビット位置について均一に推論することができます。 
2. ビット位置に対する数字の DP 状態を定義します。$p$、ここでビットを決定します$i$そして$j$最も重要なものから最も重要でないものへ。 各位置で、次のプレフィックスが含まれているかどうかも追跡します。$i$そして$j$は依然として次のプレフィックスと等しくなります$X$そして$Y$。 境界内に留まらなければならないため、この「厳密な」追跡が必要です。 
3. 各状態について、すべての有効なビット割り当てを試します。$(b_i, b_j)$AND 制約に違反しないようにします。 これにより、ビットあたり 3 つの遷移に制限されます。$(0,0), (0,1), (1,0)$。 
4. コンピューティングのためのキャリーアウェアメカニズムを維持します$i+j$。 明示的に数値を形成する代わりに、次のビットへのキャリーを追跡し、現在のプレフィックスが最終的な合計が特定のしきい値を超えることをすでに保証しているかどうかを追跡します。 
5. すべてのビットが処理されたら、結果のペアを次の最上位ビットによって分類します。$i+j$。 これは、和の中で最も重要なキャリーまたは生成された最も重要な 1 の位置を追跡することによって行われます。 
6. 各ビット長クラスに該当する有効なペアの数にそのクラス値を乗じて寄与を累積し、すべてを剰余で合計します。$10^9+7$。 

重要な設計上の選択は、明示的に計算を行わないことです。$i$、$j$、 または$i+j$整数として。 すべては DP の状態遷移から推測されます。 

### なぜ効果があるのか

 DP は、有効なプレフィックスの完全な特徴付けを維持します。$(i, j)$両方の制約の下で: 有界性と素ビット。 ビットのすべての完全な割り当ては、DP 内の 1 つの有効なパスに正確に対応し、すべての有効なペアは 1 回だけ表されます。 貢献度は、最も高い設定ビットのみに依存するため、$i+j$、DP から導出されたビット長でグループ化すると、二重にカウントされることなく正確さが維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

MAXB = 60

def solve_case(x, y):
    # dp[pos][tight_x][tight_y][carry]
    dp = [[[[0] * 2 for _ in range(2)] for _ in range(2)] for _ in range(MAXB + 1)]
    dp[0][1][1][0] = 1

    for pos in range(MAXB):
        xb = (x >> pos) & 1
        yb = (y >> pos) & 1

        for tx in range(2):
            for ty in range(2):
                for carry in range(2):
                    cur = dp[pos][tx][ty][carry]
                    if not cur:
                        continue

                    for a in (0, 1):
                        for b in (0, 1):
                            if a & b:
                                continue

                            if tx and a > xb:
                                continue
                            if ty and b > yb:
                                continue

                            ntx = tx and (a == xb)
                            nty = ty and (b == yb)

                            s = a + b + carry
                            nc = s >> 1

                            dp[pos + 1][ntx][nty][nc] = (dp[pos + 1][ntx][nty][nc] + cur) % MOD

    ans = 0
    for tx in range(2):
        for ty in range(2):
            for carry in range(2):
                cnt = dp[MAXB][tx][ty][carry]
                if not cnt:
                    continue

                msb = MAXB + (1 if carry else 0)
                ans = (ans + cnt * msb) % MOD

    return ans

t = int(input())
for _ in range(t):
    x, y = map(int, input().split())
    print(solve_case(x, y))
```DP はビット位置ごとに編成され、各遷移はループ内で直接素のビット条件を強制します。$(a, b)$。 厳しいフラグにより​​、決して超えないことが保証されます$X$または$Y$バイナリ接頭辞で。 キャリーは、加算を上方に伝播するために必要な唯一の情報です。 

最終的な集計では、DP の後に欠落している情報は有効ビット長だけであるという事実を利用します。$i+j$これは、処理された最上位ビットを超えてキャリーが生き残るかどうかによって決まります。 

微妙な点は、DP がすべての数値を固定幅のバイナリとして扱うことです。 十分に大きな MAXB にパディングしないと、キャリー伝播によって 2 の累乗付近の合計の寄与が誤って切り捨てられてしまいます。 

## 実用的な例

 検討してください$X = 2, Y = 2$。 それらのバイナリ形式は手動で追跡できるほど小さいです。 

主要な DP トランジションのみをスケッチします。 

| 位置 | TX | タイ | キャリー | トランジション (有効) | dp値 |
 | --- | --- | --- | --- | --- | --- |
 | 0 | 1 | 1 | 0 | (0,0),(0,1),(1,0) | 1 |
 | 1 | * | * | * | 伝播された状態 | 3 |
 | 2 | * | * | * | 最終的な集計 | 依存します |

 これは、すべての有効な素のビットペアが列挙なしでどのように蓄積されるかを示しています。 

トレースでは、各有効なペアが 1 つの DP パスに正確に対応し、無効なペアが表示されないことが確認されます。$(1,1)$決して許されません。 

ここで考えてみましょう$X = 3, Y = 3$。 ペア$(1,2)$そして$(2,1)$は有効ですが、$(1,3)$はビット 0 を共有するため、早期に拒否されます。DP は当然、位置 0 でこれらの遷移を除外します。

 ## 特殊なケース

 いつ$X = 0$または$Y = 0$、有効なペアは 1 つだけ存在します。$(0,0)$。 DP は位置 0 の単一状態から始まり、すべてのビットが 0 であるため、分岐することはありません。 キャリーは全体を通してゼロのままであるため、最終的なビット長の寄与は 1 となり、正しいバイナリ表現の長さ 0+0 と一致します。 

いつ$X$そして$Y$両方とも 2 のべき乗 - 1 である場合、同時に 1 を除くすべての下位ビットの組み合わせが許可されます。 DP は深さの完全な三元ツリーを探索します$B$ただし、厳しい制約による枝刈りにより、無効なオーバーフローは発生しません。 キャリーは、両方のビットが 1 の場合にのみ表示されますが、これはすでに禁止されているため、この場合、キャリーは 0 のままで、最大ビット長はすべてのパスにわたって安定しています。
