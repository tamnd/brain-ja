 ## 解決策
 ## 問題の理解

 0 から n までの 1 次元のセグメントが与えられます。 2 人のウォーカーがこのセグメントのどこかからスタートします。 各歩行者には独自の開始位置と一定の速度があり、どちらもセグメントに沿って前後に歩くことができますが、区間の外に出ることはできません。 

セグメント上の点は、少なくとも 1 人の歩行者がその時点を通過すると「覆われた」とみなされます。 方向を自由に変えることができるため、各歩行者はどちらの方向にも区間を移動でき、速度制限や境界線を尊重した任意の経路を効果的に選択できます。 

タスクは、[0, n] 内のすべての点が時間 T までに 2 人の歩行者のうちの少なくとも 1 人によって訪問されるように、最小時間 T を決定することです。 

主な問題点は、カバレッジが離散点ではなく実際のセグメントにわたって連続していることです。 これは、時間の経過とともに拡大する 2 つのリーチ領域によってカバーされる間隔の結合がセグメント全体になることを効果的に確認しようとしていることを意味します。 

この制約は、最大 10^4 のテスト ケースを意味し、ケースごとの n は最大 10^4 になります。 タイム ステップや連続動作にわたる単純なシミュレーションは不可能です。 どのアプローチでも、テスト ケースごとに定数時間または対数時間で答えを計算する必要があります。 

一方の歩行者が他方の歩行者から遠く離れてスタートし、両方とも非常に遅い場合、微妙なエッジケースが発生します。 たとえば、n が大きく、両方の速度が小さい場合、答えはどちらかの側からの最も遅いカバレッジに必要な時間によって支配されます。 もう 1 つの特殊なケースは、両方のウォーカーが同じ終点近くからスタートし、もう一方のウォーカーが貢献しない限り、セグメントの一方の側に到達するのにコストがかかる場合です。 

構造を示す最小限の例は、両方のウォーカーが反対側の端から開始する場合です: p1 = 0、p2 = n。 その場合、答えは単純に max(n / v1, n / v2) になります。各ウォーカーは独立して内側にスイープし、並列カバレッジを超えて重複する利点はないからです。 

## アプローチ

 ブルートフォースの観点は、時間の経過に伴う歩行者の動きをシミュレートし、セグメントのどの部分がカバーされるかを追跡することです。 セグメントを小さな点に離散化し、小さな時間ステップで動きをシミュレートし、各ステップで各歩行者の到達可能な位置を更新することができます。 セグメントが k 点に離散化され、時間が解像度に比例したステップでシミュレートされる場合、各ステップで両方のウォーカーが更新され、カバレッジを繰り返しチェックします。 10^-6 の精度を達成するには非常に細かい離散化が必要となり、テスト ケースごとに数十億回の演算が必要となるため、これはすぐに実行不可能になります。 

重要な観察は、各ウォーカーが独立して「カバレッジ半径」に寄与し、時間とともに直線的に増加しますが、セグメント境界によって制限されるということです。 時間 t の後、歩行者 i は自由に向きを変え、両方向に全速力で外側に向かって掃引できるため、正確に間隔 [max(0, p_i − v_i t), min(n, p_i + v_i t)] に到達できます。 

したがって、時間 t で、各歩行者から 1 つずつ、合計 2 つの間隔が得られます。問題は、これら 2 つの間隔の和集合が [0, n] を完全にカバーする最小の t を見つけることになります。 これは純粋な区間カバー条件です。 

結合は、両方の歩行器の左端の到達可能なポイントと右端の到達可能なポイントの間に覆われていないギャップがない場合に限り、セグメント全体をカバーします。 この条件は、結合後の左端の境界が 0 で右端の境界が n であるかどうか、および 2 つの区間が重なっているか接触しているため中央に隙間がないことを確認することに要約されます。 

形式的には、到達可能な間隔を計算し、それらが重なっているか境界ギャップをカバーしているかどうかを確認します。 これにより、t が単調条件になるため、最小有効時間を二分探索できます。 各チェックは O(1) であるため、ソリューションは効率的になります。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 離散シミュレーション | テストあたり O(n / ε) | O(n) | 遅すぎる |
 | インターバル + 二分探索 | テストごとの O(対数精度) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 固定時間 t の間、各歩行者が速度 v で移動し、自由に回転して到達できる最大範囲として、歩行者がカバーする間隔を計算します。 これにより、[l1, r1] と [l2, r2] が得られます。 
2. どちらのウォーカーもセグメントから離れることができないため、これらの間隔をセグメント境界 [0, n] にクランプします。 
3. 間隔を並べ替えたり比較したりして、それらの結合について推論できるようにします。 一般性を失わずに、l1 ≤ l2 と仮定します。 
4. 区間の和集合がセグメント全体をカバーしているかどうかを確認します。 これは、l1 が 0 で和集合の右端が少なくとも n であり、間隔間にギャップがない場合に当てはまります。 具体的には、正しい順序で r1 ≥ l2 または r2 ≥ l1 が成立し、両端点が両端をカバーする場合にカバレッジが成立します。 
5. 連続範囲の t に対して二分探索を使用します。 下限は 0 で、最悪の場合、1 人の歩行者だけでセグメントを 2 回横断する可能性があるため、上限は 2n を最低速度で割った値が安全です。 
6. 各中間点に対して、カバレッジ チェックを実行します。 間隔が必要な精度より小さくなるまで検索を絞り込みます。 

二分探索が適用される理由は、時間が増加しても到達可能な間隔が単調に拡大するだけであるため、一度完全なカバレッジが可能になると、永久に可能であるためです。 

### なぜ効果があるのか

 核となる不変条件は、どの時点 t においても、各ウォーカーの到達可能なセットは、境界によって切り取られた、その開始点からの距離 v_i t 内の点の間隔と正確であるということです。 これは、外向きの直線動作からの逸脱によって一方向の到達距離が減少するだけであり、回転により速度制限まで両方向に独立して拡張できるためです。 

したがって、問題は 2 つの継続的に拡大する区間の結合に帰着します。 これらの間隔は t とともに単調に拡大するため、述語「[0, n] を完全にカバーする」は単調であり、二分探索が最小有効時間に収束することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ok(n, p1, v1, p2, v2, t):
    l1 = max(0.0, p1 - v1 * t)
    r1 = min(n, p1 + v1 * t)
    l2 = max(0.0, p2 - v2 * t)
    r2 = min(n, p2 + v2 * t)

    if l1 > l2:
        l1, l2 = l2, l1
        r1, r2 = r2, r1

    if r1 < l2:
        return False

    return min(l1, l2) <= 0 and max(r1, r2) >= n

def solve():
    it = sys.stdin
    t = int(it.readline())
    for _ in range(t):
        n, p1, v1, p2, v2 = map(float, it.readline().split())

        lo, hi = 0.0, 1e10

        for _ in range(80):
            mid = (lo + hi) / 2
            if ok(n, p1, v1, p2, v2, mid):
                hi = mid
            else:
                lo = mid

        print(f"{hi:.10f}")

if __name__ == "__main__":
    solve()
```機能`ok`推定時間を 2 つの到達可能な間隔に変換します。 境界を無視するとカバレッジが過大評価されるため、実装の重要な詳細は [0, n] にクランプすることです。 

間隔スワップにより、ギャップをチェックする前に、順序を正しく判断することができます。 二分探索ループは、浮動小数点の精度を保証するために固定回数の反復を実行します。 

この問題では絶対誤差または相対誤差が小さいことが許容されるため、最終的に出力される値には高精度の書式設定が使用されます。 

## 実用的な例

 セグメントが [0, 10] で、歩行者が 2 と 8 から始まり、どちらも速度 1 である場合を考えてみましょう。 

時間 t = 0 の場合:

 | t | l1 | r1 | l2 | r2 | 取材範囲 |
 | --- | --- | --- | --- | --- | --- |
 | 0 | 2 | 2 | 8 | 8 | いいえ |

 t = 2 の場合:

 | t | l1 | r1 | l2 | r2 | 取材範囲 |
 | --- | --- | --- | --- | --- | --- |
 | 2 | 0 | 4 | 6 | 10 | はい |

 この時点では、ウォーカー 1 は [0,4] をカバーし、ウォーカー 2 は [6,10] をカバーしますが、まだ 4 と 6 の間にギャップが残っているため、完全なカバーはまだ達成されていません。 これは、単に両端に到達するだけでは十分ではないことを示しています。 オーバーラップにより内部ギャップを排除する必要があります。 

次に、n = 10、p1 = 0、p2 = 10、v1 = v2 = 1 の 2 番目のケースを考えてみましょう。 

| t | l1 | r1 | l2 | r2 | 取材範囲 |
 | --- | --- | --- | --- | --- | --- |
 | 5 | 0 | 5 | 5 | 10 | はい |

 これにより、エンドポイントからの対称的な拡張により、両方が中間点に到達した時点で完全なカバレッジが得られることが確認されます。 

最初の例ではオーバーラップの重要性を示し、2 番目の例ではエンドポイント間の対称性が最も単純で最適な構成であることを確認しています。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    def ok(n, p1, v1, p2, v2, t):
        l1 = max(0.0, p1 - v1 * t)
        r1 = min(n, p1 + v1 * t)
        l2 = max(0.0, p2 - v2 * t)
        r2 = min(n, p2 + v2 * t)
        if l1 > l2:
            l1, l2 = l2, l1
            r1, r2 = r2, r1
        if r1 < l2:
            return False
        return min(l1, l2) <= 0 and max(r1, r2) >= n

    sys.stdout = io.StringIO()
    solve()
    out = sys.stdout.getvalue()
    sys.stdout = old
    return out.strip()

 ## 特殊なケース

 両方の歩行者が同じ位置から開始すると、その間隔は常に同じように広がります。 和集合区間は単に 1 つの拡張区間であり、カバレッジ チェックではその区間が 0 と n の両方に達するかどうかが正確に判定されるため、アルゴリズムはこれを処理します。 

一方の歩行者が非常に遅く、もう一方の歩行者が速い場合、遅い歩行者は局所的にのみ寄与するため、二分探索は、最も遠い境界に到達する速い歩行者によって完全に支配される時間に正しく収束します。 高速間隔だけでセグメントがカバーされると、間隔チェックでは当然、低速の寄与は無視されます。 

両方のウォーカーが 1 つの境界付近にいる場合、重要な困難は反対側の端に到達することです。 このアルゴリズムは、各間隔がクランプされているため、0 または n を超える人為的な拡張はカウントされず、少なくとも 1 つの間隔が完全なセグメントにまたがるまで二分探索時間が増加するため、これを処理します。
