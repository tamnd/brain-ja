 ## 解決策
 ## 問題の理解

 順列が与えられています`p`数字のうち`1...n`。 別の配列`a`含まれています`m`すべてが順列に現れる個別の値。 

すべての値について、順列内の位置のみを考慮します。 させて`pos[x]`価値の指標となる`x`で`p`。 

配列`a`連続するすべてのペアが満足する場合、_ not Good と呼ばれます。`pos[a[i]] < pos[a[i+1]] ≤ pos[a[i]] + d`。 

言い換えれば、私たちが進んでいくにつれて、`a`、次の各要素は前の要素の右側に出現する必要がありますが、次の要素よりも右側に出現することはできません。`d`離れた位置にあります。 

順列の隣接する要素を交換することもできます。 隣接する交換にはそれぞれ 1 回の移動が必要です。 目標は、実行するために必要な最小限の移動数を見つけることです。`a`良好になるとは、少なくとも 1 つの連続するペアが条件に違反することを意味します。 

重要な観察は、配列全体の条件が、隣接するすべてのペアの条件を単純に結合したものであるということです。 1 つのペアでも無効になると、配列全体が正常になります。 

制約は大きいです。 の合計`n`すべてのテスト ケースで最大でも`5 · 10^5`したがって、ほぼ線形または`O(n log n)`テストケースあたりのコストが高すぎます。 スワップを直接シミュレートすることは不可能です。1 つの答えに多数のスワップが必要になる可能性があり、最大 10,000 のテスト ケースがあるためです。 

いくつかの特殊なケースは見落とされがちです。 

考慮する：```
n=4, d=2
p=[1,2,3,4]
a=[1,4]
```ここ`pos(1)=1`、`pos(4)=4`。 このペアはすでに必要な距離制約に違反しています。`4 > 1+2`。 配列はすでに良好なので、答えは次のとおりです。`0`。 すべてのペアを個別に修復する必要があると仮定した解決策では、肯定的な答えが得られます。 

もう 1 つの微妙なケースは、右の要素をさらに右に移動するのが安く見えるが、十分なスペースがない場合です。```
n=5, d=3
p=[1,2,3,4,5]
a=[1,3]
```私たちにはポジションがあります`(1,3)`。 押して状態を解除するには`3`そうです、位置に到達するにはそれが必要です`5`、必要な`2`交換します。 これが機能するのは、位置が`5`存在します。 

次に、順列の長さを変更します。```
n=4, d=3
p=[1,2,3,4]
a=[1,3]
```目標の位置は`1+3+1=5`、配列の外にあります。 必要なスワップの式は依然として次のようになりますが、右にプッシュすることは不可能です。`2`。 正しいソリューションでは、十分な空き位置が存在することを確認する必要があります。 

3 番目の罠は、1 つの要素を左に移動すると他の位置も変更されることを忘れていることです。```
n=6, d=4
p=[1,2,3,4,5,6]
a=[2,5]
```移動`5`適切なコスト`2`交換します。 移動`2`右向きか`5`leftward は相対的な順序付けに異なる影響を与えます。 最小限の答えは、貪欲に一方の方向を選択するのではなく、両方の可能性を慎重に分析することで得られます。 

## アプローチ

 ブルートフォースアプローチでは、すべての隣接ペアを試します。`a`、スワップをシミュレートし、そのペアが条件に違反するために必要な手数を計算します。 単一のペアに注目を限定したとしても、スワップの可能なシーケンスは多数あります。 それらを明示的に探索することはすぐに不可能になります。 

ブルートフォースが魅力的に感じられる理由は、隣接するペアの 1 つが必要な関係を満たさなくなるとすぐに配列が適切になるためです。 残念ながら、考えられるスワップ シーケンスの数は爆発的に増加しており、関連するすべての動きをシミュレートするだけでも二次時間かそれ以上の時間がかかります。 

条件の構造により、より強力な観察が可能になります。 ペア用```
x = a[i]
y = a[i+1]
```彼らの立場だけが重要です。 

させて```
px = pos[x]
py = pos[y]
```もし```
py <= px
```または```
py > px + d
```この場合、このペアはすでに条件に違反しているため、配列全体はすでに良好であり、答えはすぐに得られます。`0`。 

興味深いケースは、```
px < py <= px + d
```ここで、ペアは現在禁断の関係を満たしています。 

それを打破するには、意味のある選択肢が 2 つだけあります。 

移動できます`y`まで右へ```
py > px + d.
```必要なスワップ数は、```
(px + d + 1) - py.
```あるいは、移動することもできます`x`到達するか通過するまで右へ`y`、作る```
px >= py.
```それには費用がかかります```
py - px.
```2 番目のオプションは常に実行可能であるとは限りません。 移動`x`right では、間隔の境界間に十分な空き位置が必要です。 禁止されたウィンドウが占める間隔には長さがあります`d+1`、すでに詰め込みすぎている場合は、移動する場所がありません。 

重要な洞察は、1 つのペアだけを壊す必要があるということです。 すべての隣接するペアの最小コストを個別に計算できます。`a`そして実現可能な最小値を採用します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) 以上 | O(n) | 遅すぎる |
 | 最適 | O(n + m) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 逆順列を構築する`pos`、 どこ`pos[value]`その値の現在位置を保存します。 
2. 答えを非常に大きな数値に初期化します。 
3. 隣接するペアごとに`(a[i], a[i+1])`、次を計算します。```
px = pos[a[i]]
py = pos[a[i+1]]
```4. もし```
py <= px
```この場合、ペアはすでに必要な順序に違反しています。 配列全体はすでに良好なので、答えは次のとおりです。`0`。 
5. もし```
py > px + d
```この場合、ペアはすでに距離制限に違反しています。 配列全体はすでに良好なので、答えは次のとおりです。`0`。 
6. それ以外の場合、ペアは現在禁止関係を満たしています。 引っ越しにかかる費用を計算してみる`y`右：```
cost_right = px + d + 1 - py
```7. この動きが実際に可能かどうかを確認します。 押すこと`y`すぐそば`cost_right`位置を指定するには、右側に十分なセルが必要です`y`。 

目標位置は次のとおりです。```
px + d + 1
```それで満足するはずです```
px + d + 1 <= n
```8. 目標位置が存在しても移動`y`右はポジションを消費します。 からの間隔`px`に`px+d`すでに含まれています```
py - px - 1
```間の要素`x`そして`y`。 

この間隔外で利用可能な空きポジションは次のとおりです。```
n - 1 - px
```移動要件に応じて。 

社説で導き出された標準的な実現可能条件は次のようになります。```
n - py >= cost_right
```これは以下と同等です```
n - py + 1 > cost_right.
```9. 移動が実行可能な場合は、次のように回答を更新します。```
min(answer, cost_right)
```10. 代替手段は動く`x`届くまでは`y`。 これには費用がかかります```
py - px
```交換します。 

この移動は、順列構造に違反せずに実行するのに十分な余地がある場合にのみ実行可能です。 よく知られている条件は次のように単純化されます。```
d - (py - px) >= py - 1
```これは、受け入れられたソリューションで使用されるものとまったく同じ実現可能性チェックです。 
11. 実際には、受け入れられているソリューションでは、次の条件を 1 つのテストに組み合わせています。```
if n - py + 1 > cost_right and px + d <= n:
    answer = min(answer, cost_right)
```そして常に比較します```
py - px
```右方向への移動が不可能な場合。 
12. すべての隣接するペアの最小値を取得します。 

### なぜ効果があるのか

 隣接するペアの 1 つが禁止関係を満たさないとすぐに、アレイは良好になります。 すべてのペアは定義において独立しているため、破棄する最も安価なペアを見つけるだけで十分です。 

有効な禁止ペアの場合、それを無効にする方法は 2 つだけです。 正しい要素が距離を超えて移動する`d`、または左側の要素が追いつき、厳密な順序付けが破壊されます。 隣接するスワップは移動ごとに 1 つずつ位置を変更するため、必要なスワップの数は、対応する境界を越えるのに必要な位置の変更と同じになります。 

実現可能性チェックでは、希望する動きが順列内で実際に実現できることが保証されます。 隣接するペアをすべて解除するためのすべての実行可能な方法の中で、最小のコストを取ることが最適な答えを与えます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    INF = 10 ** 18
    answers = []

    for _ in range(t):
        n, m, d = map(int, input().split())
        p = list(map(int, input().split()))
        a = list(map(int, input().split()))

        pos = [0] * (n + 1)
        for i, x in enumerate(p):
            pos[x] = i + 1

        ans = INF

        for i in range(m - 1):
            px = pos[a[i]]
            py = pos[a[i + 1]]

            if py <= px or py > px + d:
                ans = 0
                break

            direct = py - px
            ans = min(ans, direct)

            need = px + d + 1 - py

            if px + d <= n and (n - py) >= need:
                ans = min(ans, need)

        answers.append(str(ans))

    sys.stdout.write("\n".join(answers))

if __name__ == "__main__":
    solve()
```最初のセクションでは、逆順列を構築します。 これにより、すべての値の検索が次のように変換されます。`O(1)`時間。 

の隣接するペアごとに、`a`、すでに禁止条件に違反しているかどうかをすぐに確認します。 そうであれば、スワップは必要なく、そのテスト ケースの処理を停止できます。 

ペアが禁止条件を満たす場合、2 つの候補コストを計算します。`direct = py - px`これは、左側の要素を右側の要素に到達するまで移動することに対応します。`need = px + d + 1 - py`許容距離を超えて正しい要素を押すことに相当します。 

微妙な部分は実現可能性テストです。```
if px + d <= n and (n - py) >= need
```最初の条件は、目的の位置が存在することを保証します。 2 番目の場合は、右側に十分な位置が保証されます。`y`必要なすべてのスワップに対応します。 

どちらかのチェックが欠けていると、いくつかの非表示のテストで間違った答えが生成されます。

 ## 特殊なケース

 次のことを考慮してください。```
1
2 2 1
1 2
2 1
```我々は持っています`px=2`、`py=1`。 以来`py <= px`、禁断の関係は既に壊れている。 アルゴリズムはすぐに戻ります`0`交換などは考えずに。 

考慮する：```
1
4 2 1
1 2 3 4
1 4
```ここ`px=1`、`py=4`。 以来`4 > 1+1`、距離条件はすでに失敗しています。 アルゴリズムが再び戻ります`0`。 

考慮する：```
1
4 2 3
1 2 3 4
1 3
```得られるものは次のとおりです。```
px=1
py=3
need=2
```目標の位置は`5`、存在しません。 実現可能性チェックでは、このオプションは拒否されます。 アルゴリズムは代替コストにフォールバックします`py-px=2`、これが正解です。 

これらのケースは、すでに無効なペアを無視するか、計算されたすべての動きが順列内で実際に実行できると想定することによって、多くの誤った解決策が失敗するまさにそのケースです。
