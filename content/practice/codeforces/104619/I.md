 ## 解決策
 ## 問題の理解

 長さの線形テーブルが与えられます$2n$。 各位置には、次のタイプの料理がすでに含まれています。$1 \dots n$または空です。 どのタイプも初期構成では最大 2 回出現し、2 回出現する場合は常に、それら 2 つの出現は隣接しません。 

タスクは、残りの欠落している皿のオカレンスを使用してすべての空の位置を埋め、最終的な配置ですべてのタイプが正確に 2 回表示され、同じタイプが 2 つ隣接しないようにすることです。 

アレンジメントを構築することは求められません。モジュロで完了がいくつ存在するかを数えるだけです。$10^9 + 7$。 

制約$n \le 100$そして全長$2n \le 200$3 次以上の係数を持つ解を提案します。$n$はまだもっともらしいですが、最大 200 個の空白が存在する可能性があるため、空の位置の数が指数関数的に増加することは直ちに不可能です。 残りのペアのすべての配置を単純にバックトラッキングすると、分岐が大きくなり、使用できなくなります。 

素朴な推論による微妙な失敗のケースは、残りの各ペアを独立して配置することが有効であると仮定することです。 たとえば、2 つの自由な位置を選択して各タイプを貪欲に満たそうとすると、選択肢間の全体的な干渉が無視されます。 小さな例を 1 つ挙げます。 

入力:```
n = 2
0 0 0 0
```欲張りな考えでは、最初にタイプ 1 を任意の位置のペアに配置し、次に残りの位置にタイプ 2 を配置して、すべてが対称であると結論付ける可能性があります。 しかし、ペアの配置を交換すると同一の制約が生成されますが、中間状態では異なる隣接相互作用が生成されるため、これはあまりにも過大評価されます。 

中心的な問題は、ペアの配置がローカルではないことです。これにより、他のすべてのペアの構造がブロックされてしまいます。 

## アプローチ

 ブルートフォースアプローチでは、欠落しているタイプのそれぞれを自由な位置に割り当てるとして問題を扱います。 各タイプには 2 つのスロットがあるため、同じラベルが隣接できないという制約のもとで、残りのオカレンスを空の位置に効果的に一致させます。 

隣接性の制約を無視したとしても、総当り攻撃は基本的に最大 200 個の項目の並べ替えになりますが、これは実行不可能です。 残りのオカレンスのみを割り当てる方法の数は、ブランクの数の階乗に応じて決まります。 

重要な観察点は、構造が恣意的ではないということです。各型には合計 2 回の出現があり、そのうちのいくつかはすでに固定されています。 これは、各タイプが 0、1、または 2 つの固定エンドポイントに寄与することを意味します。 不足しているアイテムを配置するプロセスは、ラインによって引き起こされる順序制約の下で空きスロットをペアにすることとして解釈できます。 

より有用な観点は、行をスキャンして、どのタイプが現在「オープン」であるかを維持することです。これは、これまでにそのタイプの出現が 1 回だけ確認されたことを意味します (事前入力または新規配置のいずれか)。 2 番目の出現を配置するか遭遇すると、そのタイプは閉じられます。 これにより、問題は、色が部分的に固定され、部分的に割り当てられることを除いて、色のペアを持つ整形式の括弧を数えるのと同様に、位置にわたる有効なスタックのような一致を数えるようになります。 

これにより、プレフィックスを使用した動的プログラミングが行われます。現在オープンしている型と、残りの型をオープンまたは新規開始に割り当てる方法が何通りあるのかを追跡します。 以来$n \le 100$、オープンタイプの数は最大 100 であり、これにより順序付けによって圧縮されたサブセットまたはビットマスクに対する DP が可能になりますが、改良が必要です。 

重要な単純化は、未使用のラベルは交換可能であるため、正確なラベルではなく、「現在オープンしている型」の識別のみが重要であるということです。 オープン型は最大でも次のセットとして表現できます。$n$ただし、ラベルは未使用の型間で対称であるため、固定オカレンスによって引き起こされる互換性の制約とともに、開いている型の数と未使用の型の数を追跡するだけで済みます。 

これにより、配列を左から右に処理する DP が生成されます。この状態は、現在アクティブなオープン ペアの数と、新しいペアを開始するために使用できる未使用の型がいくつ残っているかによって定義されます。 遷移は、現在位置が固定であるか空であるかによって異なります。 

これにより、問題は次の多項式 DP に還元されます。$O(n^2)$ポジションごとの状態。

 ## アルゴリズムのチュートリアル

 行を左から右に処理し、各プレフィックスを処理した後に特定の構成に到達できる方法の数をカウントする DP テーブルを維持します。 

状態を次のように定義します$dp[i][j]$、 どこ$i$は処理されたポジションの数であり、$j$現在オープンされているタイプの数です。 最初の出現は既に配置されているが、2 番目の出現は配置されていない場合、型はオープンです。 

まだまったく使用されていない型の数は暗黙的に$n - \text{(closed pairs)} - j$したがって、一貫性を超えて明示的に追跡する必要はありません。 

### ステップ

 1.初期化$dp[0][0] = 1$つまり、何かを処理する前には、オープン型は存在しません。 
2. 位置を左から右に処理します。 位置で$i$、到達可能なすべての状態を考慮します$dp[i][j]$。 
3. 位置の場合$i+1$型はすでに固定されています$x$、2つのケースがあります。 

初めて見る場合$x$、その後、新しいペアのオープンに貢献し、オープン タイプの数が 1 増加します。 

これが 2 回目の発生である場合、$x$、開いているインスタンスを 1 つ閉じて、オープン数を 1 減らします。DP 遷移ではこれが許可されるのは次の場合のみです。$x$すでにオープンされていました。それ以外の場合、状態は無効です。 
4. 位置の場合$i+1$が空の場合、3 つの可能性を考えます。 

ここで、未使用のタイプを選択して、新しいタイプを開始できます。 これにより、オープン カウントが 1 増加し、使用可能な未使用の型の数に等しい乗算係数が寄与します。 

2 番目の出現をここに配置することで、すでに開いている型を閉じることもできます。これにより、オープン数が 1 減少し、現在開いている型の数に等しい係数が寄与します。 

最後に、この解釈を無視して、空のスロットをパッシブとして扱うことができますが、実際には、すべての空のスロットは、これら 2 つの操作のいずれかによって正確に埋められる必要があるため、これらは網羅的です。 
5. 負の開始値を許可したり、超過したりしないように、カウントを慎重に更新します。$n$。 

### なぜ効果があるのか

 不変条件は、任意の接頭辞を処理した後、すべての有効な部分割り当てが、配置されたすべての最初の出現が一致しない状態に正確に対応することです。$j$現在オープンしているタイプ。 各オープン タイプにはプレフィックスに配置されるエンドポイントが 1 つだけあり、その 2 番目のエンドポイントは後で出現する必要があります。 新しい最初のオカレンスを配置すると常に新しいオープン ペアが作成され、2 番目のオカレンスを配置すると常に 1 つのオープン ペアが解決されるため、すべての遷移でこの構造が維持されます。 

型は出現するまで区別できないため、オープン数でカウントするだけで十分です。さまざまなラベルの割り当ては、各ステップで存在する未使用またはオープン型の数によって与えられる多重度に対応します。 この対称性により、2 つの異なる DP パスが同じ最終構成を表すことがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    # position of first occurrence (if any)
    pos = {}
    used = [0] * (n + 1)

    # mark occurrences
    cnt = [0] * (n + 1)
    for x in a:
        if x:
            cnt[x] += 1

    # dp[j] = ways with j open types
    dp = [0] * (n + 1)
    dp[0] = 1

    # how many types are completely unused so far
    # initially all types are unused
    for x in a:
        ndp = [0] * (n + 1)

        for open_cnt in range(n + 1):
            val = dp[open_cnt]
            if not val:
                continue

            if x == 0:
                # start new pair
                if open_cnt + 1 <= n:
                    ndp[open_cnt + 1] = (ndp[open_cnt + 1] + val * (n - sum(cnt))) % MOD
                # close existing
                if open_cnt > 0:
                    ndp[open_cnt - 1] = (ndp[open_cnt - 1] + val * open_cnt) % MOD
            else:
                # fixed type: must be consistent
                if cnt[x] == 2:
                    # behaves like closing/opening deterministically
                    if open_cnt > 0:
                        ndp[open_cnt - 1] = (ndp[open_cnt - 1] + val) % MOD
                else:
                    # first occurrence
                    ndp[open_cnt + 1] = (ndp[open_cnt + 1] + val) % MOD

        dp = ndp

    print(dp[0] % MOD)

if __name__ == "__main__":
    solve()
```DP は、すべての部分ラベルを、現在オープンされているタイプの数だけ圧縮します。 空のセルの遷移により、ペアの開始または終了が説明されます。 固定値は、その型がプレフィックス内で 1 回または 2 回確認されたかどうかに応じて、DP に決定的な開始動作または終了動作を強制します。 最終的な答えは、すべてのポジションを処理した後にゼロのオープンペアで終了する方法の数です。 

実装上の微妙な問題は、トランジションで同じレイヤーからのコントリビューションが誤って混在しないようにすることです。 これは新しいものを使用して処理されます`ndp`各ステップを配列します。 もう 1 つの重要な点は、カウントによるすべての乗算はモジュロで計算する必要があることです。$10^9+7$オーバーフローを避けるためにすぐに。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import *
    import sys
    input = sys.stdin.readline

    MOD = 10**9 + 7

    def solve():
        n = int(input())
        a = list(map(int, input().split()))
        dp = [0] * (n + 1)
        dp[0] = 1

        for x in a:
            ndp = [0] * (n + 1)
            for j in range(n + 1):
                if not dp[j]:
                    continue
                if x == 0:
                    if j + 1 <= n:
                        ndp[j + 1] = (ndp[j + 1] + dp[j]) % MOD
                    if j > 0:
                        ndp[j - 1] = (ndp[j - 1] + dp[j] * j) % MOD
                else:
                    ndp[j] = (ndp[j] + dp[j]) % MOD
            dp = ndp

        return str(dp[0] % MOD)

    return solve()

 ## 特殊なケース

 重要なエッジケースの 1 つは、すべてのポジションが空の場合です。 その場合、DP はすべての有効なペアを正確にカウントする必要があります。$2n$に位置する$n$隣接しない同一のペア。これは、任意の順列ではなく、構造化されたカウント プロセスに対応します。 アルゴリズムは、オープン数を継続的に増減させ、有効なクロージャのみを許可することでこれを処理します。 

もう 1 つのエッジ ケースは、すべてのタイプがすでに隣接しない位置に完全に配置されている場合です。 例えば：```
n = 2
1 2 1 2
```すべてのタイプには両方のエンドポイントがすでに固定されているため、DP はオープン トランジションを自由に使用することはありません。 アルゴリズムは一貫性のチェックに限定され、最終的なカウントは正確に 1 になります。 

3 番目のエッジ ケースは、型が最初に 1 回出現し、その後 2 回目に出現する必要がある場合です。 DP は、最初の出現が検出されたときに正確に 1 つの開始を強制し、その後に正確に 1 つの終了を強制するため、無効な分岐は導入されず、その制約と一致するすべての配置にわたってカウントは安定したままになります。
