 ## 解決策
 ## 問題の理解

 2D グリッド上に一連の点が与えられ、各点は家やアパートなどの場所を表します。 新しい点を選択しなければなりません$(x, y)$充電ステーションが建設される場所。 候補地の品質は、その候補地から指定されたすべての点までのマンハッタンの距離の合計によって測定されます。 2 点間のマンハッタン距離は、水平距離に垂直距離を加えたものです。 

タスクは、この合計距離を最小化する場所を見つけることです。 複数の場所が同じ最小値を達成する場合は、最小値の場所を選択する必要があります。$x$。 まだ同点がある場合は、最小のものを選択します$y$。 

入力サイズは最大です$n = 100000$、座標は以下の範囲内に限定されます。$[-100000, 100000]$。 これにより、グリッド内のすべての候補位置を評価したり、考えられるすべての点からの距離を計算したりするアプローチは即座に除外されます。 座標範囲だけでも$200001^2$実現不可能な可能性。 

2 番目の単純なアイデアは、すべての入力ポイントを潜在的な施設の場所としてテストすることです。 これにより候補者は減少します$n$ただし、各評価には依然として費用がかかります$O(n)$、につながる$O(n^2)$総仕事量。 と$n = 10^5$、これは次のようになります$10^{10}$距離の計算が遅すぎます。 

複数のポイントが同じ最適な中央値構造を共有する場合、微妙なエッジ ケースが発生します。 たとえば、すべての点が垂直線上にある場合、$x = 0$、その後、任意の点$x = 0$と中央値$y$値が最適です。 中央値を個別に計算するが一貫してタイブレークを強制しない不注意な実装では、異なる有効な座標が返される可能性がありますが、問題には決定的な選択が必要です。 

## アプローチ

 重要な観察は、マンハッタンの距離が、$x$そして$y$:$$|x - x_i| + |y - y_i| = |x - x_i| + |y - y_i|$$したがって、総コストは次のようになります。$$\sum |x - x_i| + \sum |y - y_i|$$この分解は、最適化できることを意味するため、非常に重要です。$x$そして$y$独立して。 

まず 1D バージョンを検討します。値を選択します。$x$最小化する$\sum |x - x_i|$。 絶対偏差のよく知られた特性は、マルチセットの中央値がこの合計を最小化するということです。 直感的には、選択したポイントを左右に移動すると、少なくとも減少するポイントと同じ数のポイントまでの距離が増加します。 

したがって、最適な$x$の中央値です$x_i$値、および同様に最適な$y$の中央値です$y_i$価値観。 

ブルートフォースアプローチではすべての候補者を評価することになる$x$そして$y$、毎回合計を再計算し、コストを計算する$O(n)$評価ごとに。 それは次のことにつながります$O(n^2)$全体的に複雑さ。 中央値の洞察は、ソートを使用して検索空間全体を 1 つの決定論的な計算にまとめます。 

タイブレークには注意が必要です。 いつ$n$が偶数である場合、複数の中央値が存在します。 ルール「最小限にする」$x$、次に最小化します$y$」は、最適解の中で最小の有効な座標を生成するため、下位の中央値インデックス (ソート順で左中央の要素) を選択することになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^2)$|$O(1)$| 遅すぎる |
 | 最適 (中央値) |$O(n \log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 治療します$x$そして$y$コスト関数がきれいに分割されるため、独立しています。 

1. すべてのポイントを読み取り、そのポイントを保存します$x$そして$y$別々にコーディネートします。 各次元を個別に並べ替えるので、この分離が必要です。 
2. すべてのリストを並べ替えます$x$-コーディネート。 中央値は生の値ではなく注文統計に関して定義されるため、並べ替えが必要です。 
3.中央値を選択します$x$-座標。 もし$n$これは奇妙です。これは中間の要素です。 もし$n$が偶数である場合、最小化の要件を満たすために下位中間のインデックスを選択します。$x$すべての最適なソリューションの中で。 
4. 同じプロセスを繰り返します。$y$- 座標、中央値を抽出する$y$。 
5. 出力$(x, y)$最終的な答えとして。 

### なぜ効果があるのか

 正確さは、実数の任意の複数集合に対して、関数が次のような性質に依存します。$f(t) = \sum |t - a_i|$集合の任意の中央値で最小化されます。 引っ越したら$t$中央値の左側では、左側よりも右側に多くの点があり、合計距離が長くなります。 私たちが右に動けば、その逆が起こります。 目標は独立した合計に分割されるため、$x$そして$y$、各座標に最適な中央値を選択すると、同時に完全な 2D マンハッタンの目的が最小化されます。 タイブレーク規則は、より低い中央値インデックスを選択することによって満たされ、すべての最適解の間で辞書編集上最小の座標が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    xs = []
    ys = []
    
    for _ in range(n):
        x, y = map(int, input().split())
        xs.append(x)
        ys.append(y)
    
    xs.sort()
    ys.sort()
    
    # lower median for tie-breaking
    x_ans = xs[(n - 1) // 2]
    y_ans = ys[(n - 1) // 2]
    
    print(x_ans, y_ans)

if __name__ == "__main__":
    solve()
```このソリューションでは、入力を 2 つの配列に分割して、並べ替えを個別に適用できるようにします。 各配列をソートすると、前処理後に一定時間内に中央値に直接アクセスできるようになります。 インデックス$(n - 1) // 2$は、特にタイブレーク ルールを適用するために選択され、複数の最適な中央値が存在する場合に、実行可能な最小の座標が選択されるようにします。 

よくある実装上の間違いは、`n // 2`偶数サイズの場合や辞書編集上の制約を考慮せずに、盲目的に実行します。 使用する`(n - 1) // 2`は、常に左の中央値を選択することでこの問題を回避します。 

## 実用的な例

 ### 例 1

 入力:```
3
0 2
2 3
1 0
```並べ替え済み$x$: [0、1、2]

 並べ替え済み$y$: [0、2、3]

 | ステップ | xs | イース | 選択された x | yを選択しました |
 | --- | --- | --- | --- | --- |
 | 並べ替え | [0,1,2] | [0,2,3] | - | - |
 | 中央値 | - | - | 1 | 2 |

 中央値要素は次のとおりです。$x = 1$、$y = 2$。 この点は、マンハッタンの合計距離を最小化します。 

これは、中央の要素が両側の距離のバランスをとっているという特性を裏付けています。 

### 例 2

 入力:```
2
0 0
2 2
```並べ替え済み$x$: [0, 2]

 並べ替え済み$y$: [0, 2]

 | ステップ | xs | イース | 選択された x | yを選択しました |
 | --- | --- | --- | --- | --- |
 | 並べ替え | [0,2] | [0,2] | - | - |
 | 中央値の法則 | - | - | 0 | 0 |

 ここで、両方の中央値は一意ではありません。 このルールでは、より低い中央値が選択され、次のようになります。$(0, 0)$、これは最適であり、タイブレークを満たします。 

これは、均等なサイズの入力には一貫した中央値の選択が必要であることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(n \log n)$| x 配列と y 配列のソートが優勢 |
 | スペース |$O(n)$| 座標配列の保存 |

 制約により、最大で$10^5$ポイントであり、このスケールで 2 回の並べ替えは十分に制限内にあります。 このアルゴリズムは線形追加メモリを使用しますが、これは 2048 MB の制限内で許容されます。

 ## 特殊なケース

 キーエッジケースは均等です$n$、複数の中央値が存在し、タイブレークが重要となる場合。 

考慮する：```
2
0 0
2 2
```並べ替え済み$x = [0, 2]$、ソート済み$y = [0, 2]$。 アルゴリズムがインデックスを選択します$(2 - 1) // 2 = 0$、与える$x = 0$、$y = 0$。 代わりに上部中央値を選択すると、次のようになります。$(2, 2)$、総コストは同じですが、最小化の要件に違反します。$x$、 それから$y$。 より低い中央値を選択すると、正しい辞書編集上の最適な最小点が強制されます。 

もう 1 つのケースは、すべての点が同一である場合です。```
3
7 7
7 7
7 7
```ソートされた配列はどちらも定数であるため、インデックスの中央値は 7 になります。アルゴリズムは次の値を返します。$(7, 7)$一貫して、唯一の実現可能な最適解を照合します。
