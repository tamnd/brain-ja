 ## 問題の理解

 タイルに分割された長方形の壁があります。 一部の位置にはランプが含まれているため、塗装できません。 他のすべてのポジションは次のいずれかを受け取る必要があります`k`色。 

制限はローカルです。壁の端または両側のランプによって境界が定められている水平または垂直の連続したタイルを選択します。 このような作品の内部では、ペイントされたすべてのタイルが異なる色を持っている必要があります。 言い換えれば、中断されていない行セグメントまたは列セグメント内で色を繰り返すことはできません。 

課題は、そのような色が存在するかどうかを判断することです。 そうであれば、ランプの位置を維持しながら、有効な色を 1 つ印刷する必要があります。`0`。 

壁の寸法は最大でも`100 × 100`、すべてのテスト ケースにわたるセルの合計数は最大で`100000`。 これにより、すべての色の割り当てを繰り返し試行するアルゴリズムが排除されます。 可能な色の数は膨大であるため、直接構築する必要があります。 グリッド サイズが小さいため、セル上で線形または線形に近いスキャンが可能になります。 

主要なエッジ ケースは、ランプによって作成されたセグメントから生じます。 セグメントが使用可能な色の数よりも長く、行全体または列全体をチェックするだけでは十分ではない場合、長方形全体で機能する色付けが失敗する可能性があります。 

例えば：```

1
1

1
```同じ長さの列セグメントが 1 つあります`5`、しかし、ただ`3`色が存在します。 正しい出力は次のとおりです。```
NO
```不注意な実装では、行または列の数だけを見て、構造が常に存在すると仮定する可能性があります。 

別の例:```

```最も長い水平セグメントの長さは`4`2列目。 以来`3`色が利用可能な場合、正しい出力は次のとおりです。```
NO
```その列全体にはセパレータがないため、ランプは役に立ちません。 

有効な小規模なケースは次のとおりです。```

```セグメントには最大長があります`3`、したがって、答えは次のとおりです`YES`。 繰り返しの斜めパターンにより、セグメント内で重複することなくすべてのタイルに色を付けることができます。 

## アプローチ

 直接的なブルート フォース ソリューションでは、すべてのタイルを変数として扱い、有効な割り当てが見つかるまでさまざまな色を試します。 条件は、すべての行と列のセグメントをスキャンすることによって、各試行後にチェックできます。 これは、考えられるすべての色を探索するため正しいですが、割り当ての数は次のとおりです。`k`タイルの数まで引き上げられます。 たとえ小さなグリッドであっても、これは処理できる量をはるかに超えて大きくなります。 

有益な観察は、何がセグメントを不可能にするのかを調べることから得られます。 を含むセグメント`L`タイルのニーズ`L`内部の 2 つの位置が同じ色を共有できないため、異なる色になります。 最長セグメント長が より大きい場合`k`、着色は存在できません。 

逆方向がポイントです。 すべてのセグメントの長さが最大でも`k`、固定の繰り返しパターンを使用できます。 各タイルに色を割り当てる`(row + column) mod k + 1`。 水平方向に 1 ステップ移動すると色が 1 つ増加し、垂直方向に 1 ステップ移動すると色が 1 つ増加します。 最大でも長さの連続するセグメント`k`は個別の残基を受け取るため、すべての水平および垂直セグメントがルールを満たします。 

ランプは単にこれらのシーケンスを中断するだけです。 色は必要ないため、構築中にスキップされます。

 ## アルゴリズムのチュートリアル

 1. すべての行をスキャンし、連続する各タイル グループの長さを見つけます。 いずれかのグループの長さが次の値を超える場合、`k`の場合、その 1 つのグループにはすでに使用可能な色よりも多くの色が必要であるため、壁に色を付けることはできません。 
2. すべての列を同じ方法でスキャンします。 より長い垂直セグメント`k`も答えを不可能にします。 
3. すべてのセグメントが十分に短い場合は、次を使用してすべてのタイルに色を付けます。`(row + column) mod k + 1`。 すべてのランプをそのままにしておきます`0`。 
4. 構築されたグリッドを印刷します。 

最終的なパターンが機能する理由は、隣接するタイルへの移動ごとに色が 1 モジュロだけ変化するためです。`k`。 中断されていないすべてのセグメントには、最大でも`k`タイルでは、シーケンスが循環する前にカラー値を 2 回表示することはできません。 

### なぜ効果があるのか

 セグメントにそれ以上の値がある場合、`k`タイル、それ以上が必要です`k`色がはっきりしているのでレポートします`NO`避けられない。 すべてのセグメントの長さが最大でも`k`、水平または垂直のセグメントを考慮します。 それに割り当てられた色は、モジュロの連続した値のシーケンスを形成します。`k`。 最大でも次のシーケンス`k`連続する残基には重複を含めることはできないため、すべてのセグメントが要件を満たします。 考えられるすべての制限されたセグメントは水平または垂直であるため、壁全体が有効です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n, m, k = map(int, input().split())
        wall = [list(map(int, input().split())) for _ in range(n)]

        ok = True

        for i in range(n):
            cur = 0
            for j in range(m):
                if wall[i][j] == 1:
                    cur += 1
                    if cur > k:
                        ok = False
                else:
                    cur = 0

        for j in range(m):
            cur = 0
            for i in range(n):
                if wall[i][j] == 1:
                    cur += 1
                    if cur > k:
                        ok = False
                else:
                    cur = 0

        if not ok:
            ans.append("NO")
            continue

        ans.append("YES")
        for i in range(n):
            row = []
            for j in range(m):
                if wall[i][j] == 0:
                    row.append("0")
                else:
                    row.append(str((i + j) % k + 1))
            ans.append(" ".join(row))

    print("\n".join(ans))

if __name__ == "__main__":
    solve()

行と列のスキャンにより、`cur`、現在の中断されていないタイル セグメントの長さ。 ランプは 2 つの独立したセグメントを分離するため、このカウンタをリセットします。 その瞬間`cur`を超える`k`、建設は不可能です。 

着色フェーズでは、ゼロベースの座標が使用されます。 表現`(i + j) % k + 1`～から値を生成します`1`に`k`、追加しながら`1`使用を避けます`0`、ランプ用に予約されています。 小さなものであれば特別な処理は必要ありません。`k`なぜなら、実現可能性チェックによって、すべてのセグメントが十分に短いことがすでに保証されているからです。
