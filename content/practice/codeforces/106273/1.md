 ## 解決策
 ## 問題の理解

 整数の日数でインデックス付けされた気温のタイムラインが与えられます。ここで 0 日は今日です。 入力により、過去 N 日間、今日、および次の N 日間の連続した一連の観測温度が提供されます。 連続する 2 日の間では、温度は一定であるとは想定されず、直線的に変化するため、エンドポイント間のすべての中間実際の値は、その間隔中に達成可能であるとみなされます。 

この連続温度機能に加えて、複数の広告クエリがあります。 各クエリは、時間間隔と温度間隔の 2 次元で長方形の条件を記述します。 指定された日の範囲内に、その時点の気温が指定された温度範囲内にある瞬間が少なくとも 1 つ存在する場合、クエリは満たされます。 

タスクは、各クエリに対して、そのような時間が存在するかどうかに答えることです。 

重要な問題は、気温が整数日の間で連続しているため、「すべての瞬間をチェックする」ことが不可能であることです。 これにより、問題は線形セグメントに関する推論に変わります。つまり、i 日目と i+1 日目の間では、温度は線形に変化するため、各セグメントの関数は完全に決定されます。 

入力サイズは最大 200,001 温度ポイントと 100,000 クエリです。 すべての関連セグメントに対する単純なクエリごとのスキャンでは、各クエリが範囲全体に及ぶ可能性があり、最悪の場合 10¹⁰ の操作が発生する可能性があるため、遅すぎます。 

微妙なエッジケースは線形補間から生じます。 よくある間違いは、整数日の気温だけをチェックすることです。 日の間に有効な温度範囲に達すると、これは失敗します。 

たとえば、次のような温度があるとします。```
day -1: 10
day 0: 0
day 1: 10
```[-1, 1] で温度が 5 度を下回ることがあるかどうかをクエリで尋ねると、答えは「はい」です。 最小値は 0 日目に発生しますが、代わりにクエリが間隔 [-1, 1] の温度 1 について尋ねた場合、すべてのセグメントの端点で 1 に等しい整数点がない場合でも、これも真となります。 これは、セグメントのジオメトリが重要な理由を示しています。 

別の失敗例は、間隔が完全に 1 つのセグメント内にある場合に発生します。```
day 0: 0
day 1: 10
query: days [0, 1], temperature [9, 10]
```エンドポイントが範囲内にない場合でも、ラインは 1 日目近くに範囲を超えます。 

## アプローチ

 ブルート フォース ソリューションでは、各クエリが個別に処理されます。 クエリでは、[dmin, dmax − 1] 内の毎日の間隔で反復し、各セグメントで到達可能な最低温度と最高温度を計算します。 各セグメントは線形であるため、サブセグメントの最小値と最大値はエンドポイントで発生するため、セグメントごとにエンドポイントをチェックするだけで十分です。 

ただし、クエリごとにすべてのセグメントをスキャンすると、複雑さは O(NB) になり、最大 10¹⁰ の操作となり、非常に遅すぎます。 

重要な点は、すべてのセグメントを個別に検査する必要がないということです。 各セグメントは単純な幾何学的制約を提供します。つまり、2 つの既知の点間の線を定義します。 問題は、固定の水平ストリップ [tmin、tmax] と交差するセグメントがあるかどうかをチェックすることになります。 これは、多くの線分のいずれかが平面 (時間、温度) 内の長方形と交差するかどうかを尋ねることと同じです。 

クエリごとにセグメントを 1 つずつチェックする代わりに、セグメントを前処理し、温度配列に対する高速範囲の最大値と最小値のクエリをサポートします。さらに、隣接するポイント間の交差動作も考慮します。 いずれかの端点が帯域内にある場合、またはセグメントが温度帯域を横切っている場合、セグメントは温度帯域と交差しています。これは、端点の比較によって確認できます。 

これにより、各クエリが少数の範囲の極値クエリをチェックするだけになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | セグメントに対するクエリごとのブルート フォース | O(注) | お(1) | 遅すぎる |
 | 最小/最大範囲のセグメント前処理 (スパース テーブルまたはセグメント ツリー) | O((N + B) log N) | O(N log N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. アレイを構築する`a[i]`-N 日から N 日までの気温については、0 が 0 日に対応するようにインデックスが付けられます。これにより、範囲を効率的にクエリできる静的配列が得られます。 
2. この配列に対して範囲の最小構造と最大構造を事前計算します。 配列が静的であり、冪等範囲クエリのみが必要なため、スパース テーブルはうまく機能します。 これにより、O(1) の任意の間隔で最低温度と最高温度をクエリすることができます。 
3. 各クエリについて、時間間隔 [l, r] と温度間隔 [tmin, tmax] を読み取ります。 時間インデックスを配列インデックスに変換します。 
4. スパース テーブルを使用して、[l, r] の最低温度と最高温度をクエリします。 
5. [minTemp, maxTemp] と [tmin, tmax] の交差部分が空でない場合、少なくとも 1 つの整数日が条件を満たします。 ただし、有効な値が日の間に発生する可能性があるため、これだけでは十分ではありません。 
6. 連続性を処理するには、[l, r] 内の隣接するセグメントもチェックします。 各ペア (i, i+1) について、セグメントがバンド [tmin, tmax] に交差するかどうかを判断します。 一方の端点がバンドの上にあり、もう一方の端点が下またはその内側にある場合、セグメントは交差します。 
7. いずれかのエンドポイントがバンド内にある場合、またはセグメント上で交差が発生した場合は「yes」を出力し、それ以外の場合は「no」を出力します。 

### なぜ効果があるのか

 各単位間隔 [i, i+1] は連続線形関数を定義するため、間隔内の実現可能な温度値は端点または端点間の交差によって達成されます。 値の範囲と交差するセグメントの条件は、端点の包含と区間境界に対する符号の変化をチェックすることによって完全に捕捉されます。 [l, r] 内のすべてのセグメントの和集合は時間範囲全体を継続的にカバーするため、有効な瞬間の存在は、チェックが徹底的にキャプチャする少なくとも 1 つのセグメント上に存在することと同等です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

N = int(input())
arr = list(map(int, input().split()))
B = int(input())

# build sparse table for min/max
n = len(arr)
LOG = (n).bit_length()

st_min = [[0]*n for _ in range(LOG)]
st_max = [[0]*n for _ in range(LOG)]

for i in range(n):
    st_min[0][i] = arr[i]
    st_max[0][i] = arr[i]

j = 1
while (1 << j) <= n:
    length = 1 << j
    half = length >> 1
    for i in range(n - length + 1):
        st_min[j][i] = min(st_min[j-1][i], st_min[j-1][i + half])
        st_max[j][i] = max(st_max[j-1][i], st_max[j-1][i + half])
    j += 1

log = [0] * (n + 1)
for i in range(2, n + 1):
    log[i] = log[i // 2] + 1

def query_min(l, r):
    k = log[r - l + 1]
    return min(st_min[k][l], st_min[k][r - (1 << k) + 1])

def query_max(l, r):
    k = log[r - l + 1]
    return max(st_max[k][l], st_max[k][r - (1 << k) + 1])

out = []

for _ in range(B):
    tmin, tmax, l, r = map(int, input().split())

    cur_min = query_min(l + N, r + N)
    cur_max = query_max(l + N, r + N)

    if cur_max < tmin or cur_min > tmax:
        out.append("no")
    else:
        out.append("yes")

print("\n".join(out))
```この実装は、日 -N がインデックス 0 になるようにインデックスをシフトすることに重点を置いており、これにより、負のインデックス作成の複雑さが解消されます。 スパース テーブルは一度構築されると、すべてのクエリで再利用されます。 各クエリは 2 つの O(1) 範囲クエリになります。 

よくある実装の落とし穴は、ここではパフォーマンス上の理由から Python スライスが使用されていないことを忘れていることです。 もう 1 つは、両方のエンドポイントが含まれるため、日インデックスから配列インデックスに変換する際に発生する 1 つ違いのエラーです。 

## 実用的な例

 小さな温度配列を考えてみましょう。```
days:   -1   0   1
temps:  10   0  10
```クエリ: l = -1、r = 1、t ([5, 6])

 | ステップ | l、r 範囲 | 分 | 最大 | 決定 |

 | 初期化 | [-1,1] | 0 | 10 | [5,6] と重なる |

 範囲が重複しているため、5 に等しい整数の日がない場合でも、「はい」と答えます。セグメントが両側で 5 を横切るため、これは有効です。 

ここで次のことを考えてみましょう。```
temps: 3, 4, 5
query: [-1, 0], [6, 10]
```| ステップ | l、r 範囲 | 分 | 最大 | 決定 |
 | --- | --- | --- | --- | --- |
 | 初期化 | [-1,0] | 3 | 4 | 重複なし |

 ここではセグメント全体が必要な帯域の下にあるため、どこでも交差することはできません。 

トレースは、セグメントの連続性と組み合わせた場合、実現可能性を判断するには範囲の極値のみが必要であることを確認します。

 ## 特殊なケース

 重要なエッジ ケースは、セグメントの端点で有効な温度範囲に正確に達する場合です。 例えば：```
temps: 0 10
query: [0,1], [10,10]
```1 日目の気温はちょうど 10 度なので、答えは「はい」です。 範囲の最大値が境界に等しいため、アルゴリズムはこれを捕捉します。 

もう 1 つのケースは、セグメントの中央でのみ交差する狭い間隔です。```
temps: 0 10
query: [0,1], [4,6]
```線形補間は 0 ～ 10 の間のすべての値を通過するため、どちらのエンドポイントも帯域内に存在しない場合でも、答えは「はい」になります。 範囲チェックにより、最小値と最大値が間隔にまたがるため、これが見逃されないことが保証されます。
