 ## 解決策
 ## 問題の理解

 射手がセルの中心に位置する場合、1 人の射手が半径 _k_ の円形攻撃で完全にカバーできる六角形のセルの数を計算するように求められます。 各六角形の辺の長さは 1 です。セル内のすべての点が円内にある場合にのみ、セルは覆われたものとしてカウントされます。 入力は単一の整数 _k_ で、出力はこの条件を満たすセルの総数です。 

_k_ の範囲は最大 10^6 です。 大きなグリッドの距離を計算して射手の周囲の各セルを総当りチェックしようとすると、候補となるセルの数は円の面積 O(k²) に応じておおよそ増加するため、操作の数はすぐに実行不可能になります。 上限 k=10^6 の場合、これには約 10^12 のチェックが必要となり、2 秒の時間制限をはるかに超えます。 

重要なエッジ ケースは、_k_ の値が小さい場合、特に _k = 1_ の場合に発生します。 射手は自分自身のセルのみをカバーできるため、出力は 1 になるはずです。最低 7 セル (中央セルと 6 つの隣接セル) を想定する不用意なアプローチは間違っています。 もう 1 つの潜在的な落とし穴は、円の境界上のセルの数え間違いです。 **すべての点**が円内にある場合にのみ、セルが攻撃を受けているとみなされるため、中心が境界線に近いセルは、中心が内側であっても除外される場合があります。 

## アプローチ

 ブルートフォース手法では、射手の周囲におよそ _k_ の辺の長さの大きな六角形のグリッドを列挙し、射手から各六角形の各頂点までのユークリッド距離をチェックし、すべての頂点が半径内に収まるセルをカウントします。 これは定義を直接実装しているため正しいですが、k² セルとセルあたり 6 つの頂点に対して O(k²) 距離チェックが必要であり、k = 10^6 では実行不可能になります。 

重要な洞察は、六角形のタイルの対称性を観察することで得られます。 中央のセルの周囲の六角形の層はリングを形成します。中央のセルは層 0、その隣の 6 個のセルは層 1、次の周囲のリングには 12 個のセルが含まれます。 各レイヤーは、中心からの整数の「16 進距離」に対応します。 円の半径が少なくともそのヘクスの中心から最も遠い頂点までの距離である場合、層 _r_ のセルは完全に円の内側になります。 レイヤーの中心-_r_ hex からその最も遠い頂点までの距離は、_r_ に応じて直線的に増加します。具体的には r × √3 (頂点から頂点までの距離) です。 これを使用すると、円がカバーできる完全なレイヤーの最大数を計算し、レイヤー数ごとにセルを合計できます。 最初の _n_ 層のセルの数は、1 + 6 × (1 + 2 + ... + n) = 1 + 3 × n × (n + 1) です。 最大の被覆層がわかれば、これにより O(1) の式が得られます。 

このアプローチでは、各セルを反復処理する必要がなくなるため、複雑さが大幅に軽減されます。 唯一の計算は、円内に収まる最大のレイヤーを見つけて、式を適用することです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(k²) | お(1) | 10^6 までの k には遅すぎます |
 | レイヤーの式 | お(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 六角形のタイリングをレイヤーの観点から表します。中央のセルはレイヤー 0、周囲の 6 つのセルはレイヤー 1、次の 12 個のセルはレイヤー 2 を形成します。 各層 r には 6 × r のセルがあります。 
2. 射手のセルの中心からレイヤー r のセルの最も遠い点までの距離を計算します。 辺の長さが 1 の六角形の場合、中心から頂点までの距離は 1 です。層 r の最も遠い頂点までの距離は、r × √3 + 1 です。 
3. その層内のヘクスの中心から最も遠い頂点までの距離が k を超えないように、最大層番号 _n_ を決定します。 r × √3 + 1 ≤ k を解くと、r ≤ (k - 1)/√3 が得られます。 
4. 六角形の層の合計公式を使用します。 完全に覆われたセルの総数は、1 (中央セル) にレイヤー全体の合計を加えたものです: 1 + 6 × (1 + 2 + ... + n) = 1 + 3 × n × (n + 1)。 
5. 結果を印刷します。 

機能する理由: ヘックス レイヤーは均​​一に成長し、式は完全に含まれるレイヤー内のすべてのセルを考慮します。 層の境界のみをチェックすることで、部分的に覆われたセルが含まれていないことが保証され、セルのすべての点が円内に存在する必要があるという問題の要件が満たされます。 

## Python ソリューション```python
import sys
import math
input = sys.stdin.readline

k = int(input())
if k == 1:
    print(1)
else:
    # maximum layer fully contained in circle
    max_layer = int((k - 1) / math.sqrt(3))
    # sum of cells in layers
    result = 1 + 3 * max_layer * (max_layer + 1)
    print(result)
```このコードでは、式では層が 0 になるため、最初に自明なケース k = 1 を個別に処理します。 次に、幾何学的関係 r × √3 + 1 ≤ k を使用して、円の内側に収まる完全なレイヤーの最大数を計算します。 整数除算により、完全に含まれるレイヤーのみがカウントされることが保証されます。 最後に、閉じた式 1 + 3 × n × (n + 1) により、総セル数が効率的に計算されます。 off-by-one エラーと浮動小数点の丸めには細心の注意が払われます。`int()`。 

## 実用的な例

 k = 3 の場合:

 | ステップ | 最大層 | 結果 |
 | --- | --- | --- |
 | max_layer を計算する | int((3-1)/√3) = int(2/1.732) = 1 | - |
 | 計算結果 | 1 + 3_1_2 = 1 + 6 = 7 | 7 |

 表では、中央セルの周囲の 1 つのレイヤーが完全に円の内側にあり、合計 7 つのセルが生成され、サンプル出力と一致していることが確認されます。 

k = 5の場合:

 | ステップ | 最大層 | 結果 |
 | --- | --- | --- |
 | max_layer を計算する | int((5-1)/√3) = int(4/1.732) = 2 | - |
 | 計算結果 | 1 + 3_2_3 = 1 + 18 = 19 | 19 |

 これは、2 つの層が完全に覆われ、19 個のセルが生成されていることを示しています。

## テストケース```python
import sys, io
def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    k = int(input())
    if k == 1:
        return "1"
    else:
        import math
        max_layer = int((k - 1) / math.sqrt(3))
        result = 1 + 3 * max_layer * (max_layer + 1)
        return str(result)

# provided sample
assert run("3\n") == "7", "sample 1"
# minimal input
assert run("1\n") == "1", "k = 1"
# slightly larger
assert run("2\n") == "1", "k = 2, only central cell fits"
# larger k
assert run("5\n") == "19", "k = 5"
# maximum input
assert run("1000000\n") == run("1000000\n"), "sanity check for large k"
# exact layer boundary
assert run("1\n") == "1", "boundary k=1 edge case"

 ## 特殊なケース

 k = 1 の場合、円は隣接する六角形を完全に覆うことができません。 アルゴリズムは計算します`max_layer = int((1-1)/√3) = 0`、1 つのセルが生成されますが、これは正しいです。 k = 2 の場合、円は依然として小さすぎて、6 つの近傍を完全にカバーできません。 計算`max_layer = int((2-1)/√3) = 0`中央のセルのみがカウントされるようにします。 これらのチェックにより、レイヤーベースのアプローチが部分的なセルを過剰にカウントすることなく小さな半径を正しく処理できることが確認されます。
