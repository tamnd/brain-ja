 ## 解決策
 ## 問題の理解

 私たちは持っています`n`それぞれに長さのある独立したログ`m`。 移動中に、プレイヤーは既存の丸太を 1 つ選択し、それをいくつかの等しい部分に分割します。 長さのログの場合`x`に分かれています`t`等しい部分では、`t > 1`、`t`分けなければなりません`x`、結果として得られるすべての部分は少なくとも長さを持たなければなりません`k`。 

分割後、これらの小さな部分はゲーム内に残り、後で再び分割される可能性があります。 プレーヤーは交互に手番を行い、正当な手を打つことができなかった最初のプレーヤーが負けます。 

課題は、先発プレーヤーのティムールが最適なプレーで勝つかどうかを判断することです。 

この制約により、ゲーム状態のシミュレーションは即座に除外されます。 両方`n`そして`m`到達できる`10^9`したがって、考えられるすべてのログ長を反復したり、状態を再帰的に探索したりすることさえ不可能です。 解決策はゲーム理論と数論から導き出される必要がありますが、せいぜい約`O(sqrt(m))`仕事。 

重要な点は、次の場合を除き、ゲームは単一のログではプレイされないことです。`n = 1`。 各移動は 1 つのログにのみ影響するため、ゲーム全体は同一のサブゲームの xor-sum になります。 つまり、パリティとスプラーグ・グランディ推論が重要であるということです。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

考慮する：```
4 9 5
```すべての部分には少なくとも長さが必要であるため、分割はできません`5`。 の唯一の約数は、`9`より大きい`1`は`3`そして`9`、ピースの長さを生成します`3`そして`1`、どちらも無効です。 ティムールはすぐに負けます。 

かどうかだけをチェックする単純なアプローチ`m`より大きい約数があります`1`移動が存在すると誤って認識してしまいます。 

もう 1 つの注意が必要なケースは次のとおりです。```
2 15 4
```移動が存在する理由は、`15 = 3 * 5`、に分割します`3`長さの部分`5`合法です。 ただし、2 つの同一の勝ち山があった場合でも、全体として負ける位置を形成する可能性があります。 ゲームを「1 本の丸太が勝てばティムールが勝つ」と扱うと、間違った答えが得られます。 

最小値も重要です。```
1 1 1
```複数の等しい整数部分への分割は存在しません。 答えは`"Marsel"`。 

不用意に実装すると、次のように想定される可能性があります。`k = 1`常に移動を許可しますが、長さは`1`ログはまだ分割できません。 

最も重要な構造上のエッジケースは次のような場合です。`m < 2k`。 

例：```
100 7 4
```法的分割を行う場合は、少なくとも 2 つの部分を作成する必要があります。`4`したがって、元のログには少なくとも長さが必要です`8`。 以来`7 < 8`、約数に関係なく手は存在しません。 

## アプローチ

 ゲームについて考える最も直接的な方法は、再帰的に考えることです。 

長さのログの場合`x`、すべての約数を試すことができます`t > 1`。 に分割`t`等しい部分は同じサイズのログを生成します`x / t`。 結果として得られるゲーム状態は、`t`同一のサブゲーム。 

スプラーグ・グランディ理論を使用すると、その手のグランディ数は次のようになります。 

-`0`もし`t`偶数の同一値の xor が打ち消されるため、 は偶数です。 
-`g(x / t)`もし`t`奇数です。 

したがって、原理的には、到達可能なすべての長さについてグランディ数を再帰的に計算できます。 

この強引なアイデアは正しいですが、まったく現実的ではありません。 状態空間には、次の値まで含めることができます。`10^9`、そして約数に対する再帰的探索は膨大なものになります。 

ターニングポイントは、ここでは勝敗の情報だけが実際に重要であり、ゲームは非常に小さな構造に崩壊することに気づくことです。 

ログの長さを仮定します`x`偶数の部分に分割できます。 その場合、結果の xor は常に次のようになります。`0`、同一のゲームはペアごとにキャンセルされるためです。 それはすぐに負けポジションへの移動を引き起こします。`x`勝っている。 

ここで、すべての法的分割で奇数の部分が使用されていると仮定します。 次に、分割後の結果の位置`t`奇数部分は小さいログと同じ勝敗ステータスを持ちます。`x / t`。 

これにより、再帰的なパリティ構造が作成されます。 慎重に分析した結果、このゲームの特徴は 1 つだけになります。 

単一のログが失われるのは、その長さが分割するには小さすぎるか、奇数である場合に限ります。 

なぜ？ 

もし`x`均等であり、`x >= 2k`、いつでも次のように分割できます。`2`等しい部分。 各パーツには長さがある`x / 2 >= k`, したがって、これは合法です。 2 つの同一の山に分割すると xor が生成されます`0`, したがって、そのようなすべての偶数`x`勝っている。 

もし`x`奇数です、すべての約数がカウントされます`t`も奇数でなければなりません。 つまり、すべての手がより小さい奇数と同じステータスになることを意味します。 最終的に再帰は、次の値より小さい最終奇数に到達します。`2k`、負けています。 つまり、奇数はすべて負けになります。 

この削減の後、ゲーム全体は簡単なものになります。 

それぞれの`n`ログは同一です。 

- 単一の丸太が失われている場合、そのグランディ番号は次のようになります。`0`したがって、すべてのログの xor は次のようになります。`0`、そしてマルセルが勝ちます。 
- 単一の丸太が勝っている場合、そのグランディ数はゼロ以外になります。 実際、ここでの勝ちポジションはすべてグランディのように動作します`1`したがって、xor はパリティのみに依存します。`n`。 

つまり、ティムールはまさに次の場合に勝利します。 

-`m`均等です、
 -`m >= 2k`、
- そして`n`奇数です。 

それ以外はすべて負けています。

 ## アルゴリズムのチュートリアル

 1.読む`n`、`m`、 そして`k`。 
2. 単一のログで移動が可能かどうかを確認します。 

法的分割には少なくとも 2 つの部分が必要で、それぞれの長さは少なくとも`k`。 したがって、元のログは次の条件を満たす必要があります。$m \ge 2k$もし`m < 2k`、ゲームのどこにも動きが存在しないため、ティムールはすぐに負けます。 
3. もし`m`奇数です、出力`"Marsel"`。 

奇数を等しい整数部分に分割する場合は、必ず奇数の部分を使用する必要があります。 つまり、ゲームは常に奇数の同一の小さなサブゲームに移行し、負けの構造が再帰的に保存されます。 
4. これでわかりました`m`均等であり、`m >= 2k`。 

1 つの丸太を 2 つの等しい半分に分割することは常に合法です。$m = 2 \cdot \frac{m}{2}$結果として得られる 2 つのサブゲームは同一であるため、それらの xor はゼロになります。 つまり、1 つのログが勝利ゲームの状態になります。 
5. ゲーム全体の内容`n`同一の優勝コンポーネント。 

偶数個の同一のゼロ以外のグランディ値の xor はゼロになりますが、奇数のカウントはゼロ以外のままです。 
6. もし`n`奇数です、出力`"Timur"`。 それ以外の場合は出力`"Marsel"`。 

### なぜ効果があるのか

 核となる不変条件は、ゲームの状態がパリティのみに依存するということです。 

少なくともサイズのある均等なログ`2k`常に 2 つの等しい部分に分割することにより、ゼロ XOR 状態に直接移動します。 したがって、そのようなポジションはすべて勝利しています。 

奇数の約数はすべて奇数であるため、奇数のログは奇数の等しい部分にのみ分割できます。 結果として得られる位置は、より小さな奇数ログとまったく同じように動作します。 再帰は最終的に以下の分割不可能な奇数ログに到達するため、`2k`、奇妙なログはすべて負けています。 

したがって、すべてのログは次の 2 つのカテゴリのいずれかに分類されます。 

- 負け：奇数か小さすぎる、
 - 勝ち：均等で十分な大きさ。 

ゲームの合計は次の xor 合計です。`n`同一のサブゲームなので、同等性のみ`n`単一のログが成功すると重要になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())

    if m < 2 * k:
        print("Marsel")
        return

    if m % 2 == 1:
        print("Marsel")
        return

    if n % 2 == 1:
        print("Timur")
    else:
        print("Marsel")

solve()
```最初の条件は、動きがまったく存在しないポジションを処理します。 すべての移動で少なくとも 2 つの長さの部分を作成する必要があるため、`k`、以下より短いログ`2k`永久にブロックされます。 

2 番目の条件は、ログの長さが奇数かどうかをチェックします。 すべての合法的な分割では奇数パリティが維持され、最終的には最終的に負けの位置に達するため、奇数のログが勝ちになることはありません。 

これらのチェックの後、残りのケースは 2 つの等しい部分に分割するのに十分な大きさの偶数のログになります。 これにより、単一の丸太が勝利します。 

最終的な答えは、次のパリティによって異なります。`n`。 同一の勝利ゲームが奇数回発生すると非ゼロの XOR が生成され、偶数回の場合は相殺されます。 

実装の微妙な詳細の 1 つは、チェックの順序です。 テストしなければなりません`m < 2k`パリティについて考える前に。 例えば：```
1 3 2
```ログの長さが奇妙ですが、より深い理由は、動きがまったく存在しないことです。 現在の実装ではどちらの方法でも正しい答えが得られますが、最初に実現可能性をチェックして実際のゲーム ロジックと一致させます。 

もう 1 つの簡単な間違いは、`m / 2 >= k`浮動小数点除算を使用します。 整数演算`m >= 2 * k`よりクリーンになり、精度の問題が回避されます。

## 特殊なケース

 次のことを考慮してください。```
100 7 4
```アルゴリズムは最初に以下をチェックします。$7 < 2 \cdot 4$条件が true であるため、法的な措置は存在しません。 出力は`"Marsel"`。 

このケースでは、除数チェックだけでは不十分であることが確認されています。 それでも`7`約数があり、少なくとも長さの部分を生成するものはありません`4`。 

次に、次のことを考えてみましょう。```
2 15 4
```アルゴリズムはそれを認識します`15 >= 8`、したがって動きは存在します。 次に、パリティをチェックして見つけます。`15`が奇数であるため、1 つのログの位置が失われています。 すべてのログが失われているため、全体の xor はゼロとなり、答えは次のようになります。`"Marsel"`。 

これは、再帰的な奇数構造を示しています。 合法的な動きをしたからといって、そのポジションが勝っていることを意味するものではありません。 

最後に次のことを考慮してください。```
2 8 4
```ログは均一で満足`8 >= 8`, つまり、1つの丸太が勝っています。 しかし、同じ勝ちログが 2 つあります。 グランディ値の xor がゼロになるため、アルゴリズムは次のように出力します。`"Marsel"`。 

これにより、公平なゲーム合計全体ではなく、単一の山だけを分析するというよくある間違いが見つかります。
