 ## 解決策
 ## 問題の理解

 この問題では、同じ長さの 2 つの配列が得られます。これは、別々の棚にある 2 つの数値セットと考えることができます。 棚間で番号を交換することは許可されていますが、最大数までです。`k`交換します。 私たちの目標は、これらのスワップを実行した後、最初のシェルフの合計をできるだけ大きくすることです。 各テスト ケースでは、配列の長さ、許容される最大スワップ、および配列自体が提供されます。 出力は、単純に、スワップ制約の下で達成可能な最初の配列の最大合計です。 

制約は小さいです。`n`最大でも 30 にすることができ、`k`せいぜい`n`、テストケースの数は`t`これは、数百万の演算へのスケーリングについて心配する必要がないことを意味するため、二次関数や配列のソートを行うソリューションはどれも十分に効率的です。 各数値も最大 30 と小さいため、整数のオーバーフローは心配ありません。 明らかではないエッジ ケースには、最適なスワップ数がゼロである状況、たとえば、最初の配列のすべての要素がすでに 2 番目の配列のすべての要素よりも大きい場合が含まれます。 もう 1 つの注意が必要なケースは次のような場合です。`k`有利なスワップ数を超えた場合。 不必要なスワップを不注意に実行すると、合計が減少する可能性があります。 

## アプローチ

 単純なアプローチは、考えられるすべてのスワップ シーケンスを試すことです。 それぞれの動きに対して、ペアを選択します`(i, j)`交換して、どちらかに到達するまで次の手を再帰的に探索します。`k`スワップまたは排出の可能性。 これは、考えられるすべての結果を列挙するため正しいですが、シーケンスの数は非常に急速に増加します。`(n^2)^k`- これは、たとえ`n = 30`そして`k = 30`。 

重要な洞察は、最初の配列の合計を増加させたいことに気づくことです。 これを最適に行うには、2 番目の配列の要素の方が大きい場合に限り、その最小要素を 2 番目の配列の最大要素と交換する必要があります。 他のものを交換しても役に立ちません。 最初の配列を昇順で並べ替え、2 番目の配列を降順で並べ替えることで、交換に最適な候補をペアにすることができます。 次に、最初の処理を繰り返します`k`要素を分割し、2 番目の配列の要素が最初の配列の要素よりも厳密に大きい場合にのみ交換を実行します。 この貪欲なアプローチにより、実行するすべてのスワップが最初の配列の合計にプラスに寄与することが保証されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O((n^2)^k) | O(n) | 遅すぎる |
 | 最適 (貪欲に並べ替え) | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る`t`。 
2. 各テスト ケースについて、次の内容を読んでください。`n`そして`k`、配列を読み取ります`a`そして`b`。 
3. 並べ替え`a`最小の要素を識別するために昇順で並べます。 
4. 並べ替え`b`最大の要素を識別するために降順で並べます。 
5. 最初のものを繰り返します`k`要素を考慮して`a[i]`そして`b[i]`。 もし`b[i]`よりも大きいです`a[i]`、交換します。 それ以外の場合は、これ以上スワップしても合計が改善されないため、ループを中断します。 
6. 変更された配列の合計を計算します。`a`。 
7. Output this sum for each test case.

 機能する理由: 並べ替えにより、常に最小の利用可能な要素が比較されることが保証されます。`a`で利用可能な最大の要素を持つ`b`、これはまさに、即時の増加を最大化するスワップです。`a`の合計。 次の場合にはスワップを停止するという貪欲な決定`b[i] <= a[i]`以降の要素がないため、これは有効です`b`降順により前の要素よりも大きくなり、後の要素よりも大きくなりません。`a`昇順のため、前の要素よりも小さくなります。 これにより最適性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        
        a.sort()
        b.sort(reverse=True)
        
        for i in range(min(k, n)):
            if b[i] > a[i]:
                a[i], b[i] = b[i], a[i]
            else:
                break
        
        print(sum(a))

solve()
```コードは、貪欲なスワップを簡単にするために、最初に 2 つの配列を並べ替えます。 ループは最長で実行されます`k`を繰り返し、厳密に合計を改善する場合にのみスワップを実行します。`a`。 The use of`min(k, n)`範囲外のインデックスにアクセスしないようにします。これは見落とされがちな微妙な点です。 計算中`sum(a)`交換後に最終的な答えが得られます。

## 特殊なケース

 次のようなスワップによって合計が増加しない場合:```
2 2
5 6
1 2
```アルゴリズムによるソート`a`上昇`[5,6]`そして`b`降順`[2,1]`。 反復中`i=0`、`b[0]=2`より大きくない`a[0]=5`、そのため、ループはすぐに中断されます。 スワップは発生せず、合計は 11 のままです。これにより、スワップが逆効果となるシナリオをアルゴリズムが正しく処理していることが確認できます。
