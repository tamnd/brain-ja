 ## 問題の理解

 配列の長さが与えられます`n`と必要な合計額`m`。 タスクは、負でない整数を長さの配列に割り当てることです。`n`すべての要素の合計が等しくなるように`m`。 このようなすべての配列の中で、「隣接ジャンプ」の合計をできるだけ大きくする配列が必要です。各ジャンプは、隣接する要素間の絶対差です。 

最大化された式は、左から右に読み取られたときに配列がどの程度振動するかを測定します。 フラットな配列ではゼロが生成されますが、大きな値と小さな値を交互に使用すると、すべての遷移から大きな寄与が生じます。 

制約は非常に大きく、両方とも`n`そして`m`まで可能です`10^9`、最大で`10^4`テストケース。 これにより、配列を明示的に構築したり、それに比例するものをシミュレートしたりすることが直ちに除外されます。`n`。 どのようなソリューションでも、各テスト ケースを定数時間の演算に削減する必要があります。 

素朴な試みは配布しようとするでしょう`m`配列全体をさまざまなパターンで比較し、結果として得られる差の合計を計算します。 テスト ケースごとに 1 つの候補配列のみをシミュレートしようとした場合でも、構築または反復`n`要素は無理です。 

微妙なエッジケースが現れるのは、`n = 1`。 隣接するペアは存在しないため、答えは常に 0 になります。`m`。 もう一つのコーナーは、`n = 2`、答えは簡単になります。`|a1 - a2|`制約の下で`a1 + a2 = m`、すべての質量を片側に押し込むことで最大化されます。 

## アプローチ

 ブルートフォースの観点は、可能な長さの配列をすべて試すことです。`n`合計付き`m`、隣接する差分を計算し、最大値を追跡します。 たとえ次の整数合成に限定したとしても、`m`、可能性の数は指数関数的に増加します`m`そして組み合わせて`n`。 これは、たとえ小さな入力であっても完全に実行不可能です。 

重要な構造上の観察は、配列内に配置された値の各単位が、対称ではない位置間で移動された場合にのみ差異に寄与する可能性があるということです。 隣接する差を最大化するには、配列でできるだけ高い値と低い値を交互に配置する必要があります。 ただし、総質量による制約があります`m`したがって、どこにでも大きな交互値を自由に割り当てることはできません。 

最適な構築は非常に単純であることがわかります。ゼロ以外の質量はすべて、次の 2 つの極端なパターンに配置されます。`n`。 いつ`n = 1`、隣接するペアはありません。 いつ`n = 2`、置きます`m`完全に片側にあります。 いつ`n ≥ 3`を使用すると、値がゼロとゼロ以外の間で切り替わる完全な「ジグザグ」パターンを実現でき、境界制限を除いて、すべての質量単位が合計の差に 2 倍寄与します。 これにより、最大値が次のようになる閉じた形式の結果が得られます。`2 * m`いつ`n ≥ 3`、 そして`m`いつ`n = 2`。 

これが機能する理由は、内部位置に配置された各ユニットがトランジションで 2 回 (入場時と退場時に 1 回) カウントできることと、交互構造により平らなセグメントに無駄な質量が発生しないためです。

 ## アルゴリズムのチュートリアル

 各テスト ケースを、`n`そして`m`。 

1. もし`n == 1`、 戻る`0`。 隣接する要素がないため、差異は存在しません。 
2. もし`n == 2`、 戻る`m`。 私たちにできる最善のことは分割することです`m`の中へ`(m, 0)`または`(0, m)`、違いを与える`m`。 
3. もし`n >= 3`、 戻る`2 * m`。 次のような交互パターンを構築できます。`[0, m, 0, 0, 0, ...]`ジグザグに再配置され、すべての質量の動きが遷移全体で 2 回寄与します。 

ステップ 3 が機能する主な理由は、少なくとも 3 つの位置があれば、常にマスを分離してゼロで囲まれ、隣接する遷移で「入る」および「出る」ことができるためです。 

### なぜ効果があるのか

 目標の値は、連続するポジション間の変化にのみ依存します。 配列内に配置された各正の単位は、差の絶対値の合計に最大 2 回寄与できます。1 回目はゼロ (またはそれより低い値) から近づくとき、もう 1 回はゼロ (またはそれより低い値) に戻るときです。 少なくとも 3 つのスロットがあれば、寄与間の干渉を避ける方法で常にすべての質量の周囲にゼロを配置できます。`2m`達成可能かつ最大限。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        if n == 1:
            print(0)
        elif n == 2:
            print(m)
        else:
            print(2 * m)

if __name__ == "__main__":
    solve()
```このソリューションは、各テスト ケースを個別に読み取り、ケースの直接の区別を適用します。 実装は、答えが次のもののみに依存するという事実に依存しています。`n`そして`m`なので、配列の構築は必要ありません。 

唯一の微妙な点は、2 による乗算が Python 整数で確実に行われるようにすることです。これにより、最大の値が安全に処理されます。`2 * 10^9`制約の範囲内で。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = []
    t = int(sys.stdin.readline())
    for _ in range(t):
        n, m = map(int, sys.stdin.readline().split())
        if n == 1:
            output.append("0")
        elif n == 2:
            output.append(str(m))
        else:
            output.append(str(2 * m))
    return "\n".join(output)

 ## 特殊なケース

 のために`n = 1`、アルゴリズムは戻ります`0`すぐに。 入力あり`n = 1, m = 100`、隣接するペアがないため、計算値は分布に関係なく構造的にゼロになります。 条件`n == 1`これを直接強制します。 

のために`n = 2`、アルゴリズムは戻ります`m`。 私たちが取るなら`n = 2, m = 7`、合計を分割する唯一の方法は`(7, 0)`または`(3, 4)`または任意のパーティション。 最良のケースは、常にすべての質量を片側に配置し、違いを生み出すことです。`7`。 支店`n == 2`この正確な動作をキャプチャします。 

のために`n ≥ 3`、 考慮する`n = 3, m = 4`。 アルゴリズムは戻ります`8`。 有効な構造は`[0, 4, 0]`、生産`|0-4| + |4-0| = 8`。 これは、倍増効果が適用される最小のケースでも達成可能であることを示しています。
