 ## 解決策
 ## 問題の理解

 私たちには、一連のランプとして表される、ランプの線形の花輪が与えられています。`0`と`1`どこで`1`ランプが点灯していることを示します。`0`オフであることを示します。 ガーランドといいます`k`-periodic (連続する 2 つの間の距離の場合)`1`まさにそうです`k`。 ガーランドは周期的ではありません。つまり、パターンは指定された線形シーケンス内でのみ重要になります。 タスクは、最初のガーランドをガーランドに変換するための最小移動数を決定することです。`k`-定期的なもの。 移動するたびに、1 つのランプの状態が反転します。 

入力は複数のテスト ケースで構成され、それぞれがガーランドの長さを提供します`n`、期間`k`、現在のランプの状態`s`。 制約により許可される`n`まで`10^6`、すべての合計`n`テストケース全体の境界も次のとおりです`10^6`。 1 秒の制限時間は、すべてのソリューションがランプの総数に対してほぼ線形時間で実行されなければならないことを意味し、単純な指数関数または入れ子ループのソリューションは除外されます。`n`。 

明白でないエッジケースには、長さが以下の文字列が含まれます。`k`、すべてのランプがすでにオンになっている、すべてのランプがオフになっている、または複数の最小限の変更ソリューションが存在するガーランド。 たとえば、次の場合`s = "1"`そして`k = 5`、出力は`0`シングル以来`1`簡単に満たす`k`-周期性。 不注意な実装では、追加のランプを適用したり、フリップのカウントを誤ったりする可能性があります。`n < k`。 

## アプローチ

 ブルートフォースソリューションでは、`1`すべての開始インデックスで、そして毎回繰り返し`k`位置を調べてから、現在の文字列との不一致の数を数えます。 これには大まかに生成する必要があります`n`すべての可能な開始位置のシーケンスと、各シーケンスの最大のチェック`n`ポジション。 と`n`まで`10^6`、これは次の結果をもたらします`O(n^2)`テストケースごとに、これは遅すぎます。 

重要な洞察は、周期構造の観察から得られます。 各位置のモジュロ`k`独立して治療することができます。 ポジションを考えてみると`i, i+k, i+2k, ...`、これらすべてのポジションを一致させるためのコスト`k`-定期的な要件は、プレフィックス合計または動的プログラミング アプローチを使用して効率的に計算できます。 具体的には、`1`それぞれの過程で遭遇した`k`-シーケンスを作成し、反転するかどうかを決定します`0`に`1`またはその逆の場合は、全体的なフリップが減少します。 解決策は、インデックスから始まる各シーケンスを考慮することになります。`0..k-1`そして線形パスを使用して最小限の反転を計算します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る`t`。 
2. 各テスト ケースについて、次の内容を読んでください。`n`、`k`、および文字列`s`。 
3. コンピューティング`total_ones`、の合計数`1`にいる`s`。 これによりベースラインが得られます。`1`s、それらはフリップに貢献します。 
4. 配列を初期化する`dp`長さの`n`を作成するために必要な最小限のフリップを保存します。`k`- シーケンスは各位置で一貫して終了します。 
5. 文字列を左から右に繰り返します。 

1. もし`i < k`、 セット`dp[i]`に`1`もし`s[i]`は`0`、 それ以外`0`。 これは前例がないからです`k`-距離ランプに合わせて調整します。 
2. もし`i >= k`、計算します`dp[i]`として`dp[i-k] + (1 if s[i] == '0' else 0)`。 これは、その位置での最適なフリップ数が最適であるという考えを捉えています。`i`で終わるシーケンスを拡張します`i-k`。 
6. 各ポジションについて`i`、必要なフリップの数を次のように計算します。`dp[i] + total_ones - cumulative_ones[i]`、 どこ`cumulative_ones[i]`の数を数えます`1`これまでのシーケンスです。 グローバル最小値を更新します。 
7. テスト ケースのグローバル最小フリップを出力します。 

なぜ機能するのか: それぞれのモジュロを処理することによって`k`シーケンスを独立して実行し、そのシーケンスに沿って実行中の最小フリップを維持することで、可能な限りすべてのことを保証します。`k`-定期的なアライメントが考慮されます。 不変条件とは、`dp[i]`を行うための最小限のフリップを常に保持します。`k`- で終わるシーケンス`i`修正し、削除されたものと組み合わせる`1`シーケンスの外側にある s は、全体的な最小の反転を与えます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        s = input().strip()
        ones = [0]*n
        ones[0] = int(s[0])
        for i in range(1, n):
            ones[i] = ones[i-1] + int(s[i])
        
        total_ones = ones[-1]
        dp = [0]*n
        res = float('inf')
        for i in range(n):
            cost = 1 if s[i] == '0' else 0
            if i >= k:
                dp[i] = dp[i-k] + cost
            else:
                dp[i] = cost
            prev_ones = ones[i-k] if i >= k else 0
            res = min(res, dp[i] + (total_ones - ones[i]))
        print(res)

solve()
```の`ones`配列は累積を追跡します`1`s を使用すると、どれくらいの数かをすばやく計算できます。`1`現状の外側にある`k`-シーケンスは反転する必要があります。 の`dp`配列には、次で終わる各シーケンスに沿った最小のフリップが格納されます。`i`。 の組み合わせ`dp[i] + total_ones - ones[i]`両方の反転を考慮して、周期性と無関係な要素の除去を強制します。`1`s. エッジケース`i < k`自然に処理されるため、`dp[i-k]`アクセスされておらず、`prev_ones`正しくはゼロです。
