 ## 解決策

 ## 問題の理解

 長さの配列から始めます`n`ゼロで埋められています。 配列を繰り返し「埋める」`n`ステップ。 各ステップで、現在のゼロで埋められたセグメントを確認し、次の数字を配置するセグメントを 1 つ選択します。 

セグメントを選択するための規則は厳密です。常に、最も長く連続するゼロのブロックが選択されます。 複数のセグメントの最大長が同じである場合は、配列内で最も早く出現するセグメントが採用されます。 セグメントごとに 1 回`[l, r]`が選択されたら、次の整数を置きます`i`そのセグメントの中間位置に移動します。 セグメントの長さが奇数の場合、中央が正確になります。 偶数の場合は、左中間の位置を選択します。 

配置後`i`、その位置はゼロではなくなるため、セグメントは最大 2 つの小さなゼロ セグメントに分割されます。 これはすべてのポジションが埋まるまで続きます。 

出力はすべてのステップを経た後の単なる最終配列ですが、それを直接シミュレートするには、進化するセグメントを慎重に処理する必要があります。 

制約は私たちを効率化に向かわせます。 各テストには最大で次のものを含めることができます`2 · 10^5`したがって、配列を繰り返しスキャンして最大セグメントを見つけるアプローチは、二次関数の動作に低下します。 各ステップですべてのゼロセグメントを再計算する単純なシミュレーションでは、挿入ごとに配列全体をスキャンする必要があり、`O(n^2)`最悪の場合、動作が限界を超えて遅すぎる場合があります。 

重要なエッジ ケースは、複数のセグメントが同じ長さを共有する場合に発生します。 たとえば、対称配列に数回配置した後、両側に同じサイズの 2 つのゼロ セグメントが存在する場合があります。 ルールでは、最も左のものを選択することが強制されるため、安定したタイブレークのない順序付けされていない構造は失敗します。 

もう 1 つの微妙なケースは、偶数長のセグメントです。 指示には左中間の位置を取るようにと書かれています。 セグメントの場合`[l, r]`、 これはつまり`(l + r - 1) // 2`。 よくある間違いは、`(l + r) // 2`これにより、配置が右にシフトされ、将来の分割の構造全体が破壊されます。 

## アプローチ

 直接シミュレーションでは配列を維持し、最大のゼロ セグメントを繰り返しスキャンします。 各ステップでは、すべてのゼロ ブロックを識別し、最適なブロックを選択して、それを分割する必要があります。 各挿入には線形時間がかかるため、それを実行します`n`回すると、全体の複雑さは二次関数になります。 これでは遅すぎる`n`大きいです。 

プロセスの構造は別の見方を示唆しています。 各ゼロ セグメントは独立して動作し、選択されると、決定的に 2 つの小さなセグメントに分割されます。 これはまさに、間隔を超えた優先システムの動作です。 各セグメントを、その長さ (最初に大きいもの)、次に左端点 (最初に小さいもの) によって定義される優先順位を持つ状態として扱うことができます。 

これにより、必然的にセグメントの最大ヒープ (優先キュー) が生じます。 各セグメントは次のように保存されます。`(-length, l, r)`そのため、ヒープは次に処理する正しいセグメントを常に提供します。 セグメントをポップするたびに、その中間位置を計算し、現在の番号を割り当て、結果として得られる左右のサブセグメントが空でない場合はヒープにプッシュして戻します。 

これにより、アレイ全体のスキャンが回避されます。 各セグメントは 1 回だけ処理され、ヒープ操作により各操作には対数的な時間がかかります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (各ステップでセグメントをスキャン) | O(n²) | O(n) | 遅すぎる |
 | 最適 (セグメントの優先キュー) | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 完全なセグメントを含む優先キューから開始します。`[1, n]`。 セグメントは最初に最長の長さによって優先順位が付けられ、同点の場合は左側の端点が小さい順に優先されます。 
2. 最良のセグメントを繰り返し抽出する`[l, r]`行列から。 これにより、問題の選択ルールに常に正確に従っていることが保証されます。 
3. 中点を計算します。 長さが奇数の場合は、`(l + r) // 2`。 さえあれば、それは`(l + r - 1) // 2`。 これは、均等な長さの「左から真ん中」の要件に一致します。 
4. 現在のステップ番号を割り当てます。`i`配列内のその位置に移動します。 
5. セグメントを次のように分割します。`[l, mid - 1]`そして`[mid + 1, r]`それらが有効であれば、それらを優先キューに押し戻します。 
6.すべて終わるまで続けます`n`数字が配置されています。 

正確さは、すべてのゼロ セグメントが常にキュー内で 1 回だけ表され、優先順位が問題の選択ルールと一致するという事実から得られます。 各配置はそれ自体のセグメントにのみ影響するため、将来の選択は、キューが正確に維持する更新されたセグメント構造にのみ依存します。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        res = [0] * n

        # max heap using negative length
        heap = []
        heapq.heappush(heap, (-n, 1, n))

        for i in range(1, n + 1):
            neg_len, l, r = heapq.heappop(heap)

            length = -neg_len
            mid = (l + r) // 2
            if (r - l + 1) % 2 == 0:
                mid = (l + r - 1) // 2

            res[mid - 1] = i

            if l <= mid - 1:
                heapq.heappush(heap, (-(mid - l), l, mid - 1))
            if mid + 1 <= r:
                heapq.heappush(heap, (-(r - mid), mid + 1, r))

        print(*res)

if __name__ == "__main__":
    solve()
```ヒープにはアクティブなゼロセグメントが格納されます。 最良のセグメントをポップするたびに、偶数長ルールを尊重して、その中間インデックスを慎重に計算します。 分割されたセグメントは正しい長さで押し戻されるため、今後の選択の一貫性が保たれます。 

よくある実装の落とし穴は、ヒープの順序付けは左のインデックスによって関係を分割する必要があることを忘れていることです。 Python では、タプルによってすでにこれが保証されています。`(length, l, r)`比較すると当然小さい方が好まれます`l`否定後の長さが等しい場合。 

もう 1 つの微妙な点はインデックス付けです。問題では 1 から始まるインデックス付けが使用されていますが、Python 配列は 0 から始まるので、中点の代入では 1 を減算する必要があります。

 ## 特殊なケース

 単一要素の配列は、分割が発生しない基本ケースをテストします。 アルゴリズムはただちに唯一の位置を割り当て、1 回の操作後にヒープを正しく空にします。 

均等な長さのセグメントが主な微妙な点です。 セグメントが次のような場合`[1, 4]`が選択されると、中点は次のようになります`2`それよりも`3`。 これにより、後続のすべての分割がシフトされます。 アルゴリズムが明示的に適用される`(l + r - 1) // 2`これにより、左半分がルールで要求される値よりも小さくなることはありません。 

等しい長さのセグメントを繰り返してタイブレークをテストします。 2 つのセグメントの長さが同じ場合、タプルは 2 番目に比較されるため、ヒープは左端のセグメントが最初に処理されるようにします。`l`。 これにより、プロセス全体にわたって必要な決定的な動作が維持されます。
