 ## 解決策

 ## 問題の理解

 グリッドは、各セルが初期高さを持ち、右または下のステップを使用してのみ左上隅から右下隅に移動できる地形を表します。 高さのあるセルの上に立つと、動きが非常に制限されます。`x`、次に入るセルの高さは正確でなければなりません`x + 1`。 これにより、有効なパスはすべて、ステップごとに正確に 1 ずつ増加する厳密に増加するシーケンスをトレースするようになります。 

ウォークを開始する前に、グリッドを変更することができます。 各操作により、単一セルの高さが 1 つずつ減ります。 目標は、このようなデクリメントを最小限の回数実行して、少なくとも 1 つの単調パスが存在するようにすることです。`(1,1)`に`(n,m)`すべてのステップで厳密な +1 条件を満たします。 

主な難点は、パスを直接構築していないことです。 代わりに、グリッドを再形成して、一部のパスが連続する整数シーケンスと完全に位置合わせされるようにします。 

制約は、テスト ケース全体のグリッド サイズの合計という点で小さく、合計で最大 100 行と 100 列です。 これにより、サブ構造を再利用せずに、考えられるすべてのパスを独立して評価しようとするソリューションは除外されます。 すべてのパスの単純な列挙はすでに指数関数的です`n + m`、これは単一の 100x100 グリッドでも実現不可能です。 

大きな値が長時間の下方調整を強制する場合、微妙なエッジケースが発生します。 たとえば、パスに次のような値がある場合、`10 -> 20 -> 30`、単純な考えでは、貪欲にすべてを最小開始値に揃えようとするかもしれませんが、これは、1 つのセルを移動すると、そのセル自体の位置にのみ影響し、代替パス間の一貫性には影響しないという事実を無視しています。 もう 1 つのエッジ ケースは、複数のパスが部分的なプレフィックスを共有する場合です。パスを単純に独立して処理すると、再利用できる調整が 2 倍にカウントされます。 

## アプローチ

 ブルートフォースアプローチでは、からのすべてのパスが試行されます。`(1,1)`に`(n,m)`。 各パスについて、そのパスに沿って値が連続した整数になるように各セルをどれだけデクリメントする必要があるかを計算します。 パスが固定されており、開始値を選択する場合`s`の場合、必要な最終値は次のように完全に決定されます。`s, s+1, s+2, ...`。 コストは、その割り当てに一致させるために各セルをどれだけ削減する必要があるかの合計になります。 

これは正しいですが、パスの数が次のオーダーであるため、絶望的に高価になります。`C(n+m, n)`これは、中程度のグリッドであっても巨大です。 

重要な観察は、実際には絶対値は考慮しておらず、パスのエッジに沿った差異のみを考慮しているということです。 開始値を選択すると、`(1,1)`の場合、すべてのパスは、各セルで次の値に等しい必要な最終値を誘導します。`a[1,1] + distance`, ここで、距離はスタートからのステップ数です。 ただし、値を減らすことしかできないため、開始値は固定されていません。 代わりに、セルが増加しないように選択する必要があります。 

これにより視点が変わります。絶対的なターゲットを割り当てる代わりに、すべてのパスを一貫した「オフセット」値を決定すると考えることができます。 固定パスの場合、コストは完全に、各セルが本来のセルの値をどれだけ上回るかによって決まります。 これにより、近隣からの制約を伝播しながら、達成可能な最良の位置合わせコストを維持する、パス全体にわたる動的プログラミングの定式化が可能になります。 

各セルで`(i,j)`、ステップでパスの一部であると判断した場合`k = i + j - 2`の場合、その最終値は次のようになります。`a[1,1] - delta + k`一部のグローバル デルタ (開始時に適用される合計削減量) について。 再配置すると、各セルはデルタの大きさに制約を課します。 コストは、選択したすべてのセルを尊重しながら、パス全体を一貫してどれだけ「シフトダウン」できるかという点の最大化になります。 

これにより、問題が DP に変換され、増加するシーケンスとのパスの可能な限り最適な位置合わせが追跡され、元の高さの下でシーケンスを最も厳密に「適合」する場所を選択することで違反が最小限に抑えられます。 

標準的なソリューションは、これをグリッド上の最短パス スタイルの DP にさらに再構成します。パスが到達することを強制するための最小コストを計算します。`(i,j)`には一貫したオフセットがあり、トランジションは右または下に移動することで同じ位置合わせが実現可能であるかどうかを比較し、予想されるシーケンス値に一致させるために現在のセルをどれだけ減らす必要があるかに基づいてコストを調整します。

 ## アルゴリズムのチュートリアル

 1. 各セルについて`(i,j)`、任意のパスに沿って必要な位置インデックスを次のように計算します。`k = i + j - 2`。 このインデックスは、セルが有効なパス上にある場合に、セルがどの値と一致する必要があるかを決定します。 
2. 選択したパスについて、値を次のように固定すると想像してください。`(1,1)`ある開始値まで`s`。 次に、パス上の他のすべてのセルに値が必要です`s + k`。 セルを強制的に使用するコスト`(i,j)`これを満たすには`max(0, a[i][j] - (s + k))`。 
3. 増加していることを観察します。`s`常にコストを削減しますが、すべての値が減少のみで達成可能であるという要件に違反することはできません。 これは最高という意味です`s`選択されたパス上の最も制限的なセルによって決定されます。 
4. どのパスでも、最小コストはそのパスに沿った最大の「過剰な調整」にのみ依存します。 各セルに変換された値を定義します`b[i][j] = a[i][j] - k`。 有効な道に沿って、すべてが必要です`b[i][j]`少なくとも何らかのグローバルしきい値である必要があります。 
5. 問題は、からのパスを見つけることに帰着します。`(1,1)`に`(n,m)`の最小値を最大化するもの`b[i][j]`道沿いにあります。 これは、古典的な「最大ボトルネック パス」DP に相当します。 
6. DP テーブルを計算します`dp[i][j]`考えられる最大のボトルネックを表します (最大、最小、`b`値) 達成可能な到達`(i,j)`。 
7. 遷移は次のとおりです。 

- 上から`(i-1,j)`- 左から`(i,j-1)`取る`dp[i][j] = max( min(dp[i-1][j], b[i][j]), min(dp[i][j-1], b[i][j]) )`。 
8. 答えは、次の時点で達成可能な最良のボトルネックから導き出されます。`(n,m)`、シーケンスを全体的にどの程度下方にシフトできるかを決定します。 総コストは、選択された最適パス上のすべてのセルを最も厳密な一貫したシーケンスにするために必要な削減の合計です。 

### なぜ効果があるのか

 有効なパスはすべて、厳密に増加する連続値を割り当てる必要があるため、開始値が固定されると、パス上のすべてのセルに強制ターゲットが設定されます。 唯一の自由は、シーケンスをグローバルにどこまで下方にシフトするかです。 このシフトは、元の高さと、選択したパスに沿った必要なシーケンス位置との間の最小の差によって制限されます。 したがって、パスの最適化は、この最小スラックを最大化することと同じです。 パスのすべてのプレフィックスがすでに同じ制約を満たしている必要があるため、DP はこのボトルネック プロパティを正しく伝播し、最適な部分構造が保持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        a = [list(map(int, input().split())) for _ in range(n)]

        b = [[0]*m for _ in range(n)]
        for i in range(n):
            for j in range(m):
                b[i][j] = a[i][j] - (i + j)

        dp = [[0]*m for _ in range(n)]

        dp[0][0] = b[0][0]

        for j in range(1, m):
            dp[0][j] = min(dp[0][j-1], b[0][j])

        for i in range(1, n):
            dp[i][0] = min(dp[i-1][0], b[i][0])

        for i in range(1, n):
            for j in range(1, m):
                best_from_top = min(dp[i-1][j], b[i][j])
                best_from_left = min(dp[i][j-1], b[i][j])
                dp[i][j] = max(best_from_top, best_from_left)

        # compute cost from best bottleneck path
        best = dp[n-1][m-1]

        # reconstruct cost by summing required reductions along best path
        i, j = n-1, m-1
        cost = 0
        cur_min = best

        while True:
            target = cur_min + (i + j)
            if a[i][j] > target:
                cost += a[i][j] - target

            if i == 0 and j == 0:
                break

            if i == 0:
                j -= 1
                cur_min = min(cur_min, b[i][j])
            elif j == 0:
                i -= 1
                cur_min = min(cur_min, b[i][j])
            else:
                if dp[i-1][j] > dp[i][j-1]:
                    i -= 1
                else:
                    j -= 1
                cur_min = min(cur_min, b[i][j])

        print(cost)

if __name__ == "__main__":
    solve()
```DP テーブルは変換された値に基づいて構築されます`b[i][j] = a[i][j] - (i + j)`、連続シーケンス内の必要な位置に対して各セルが提供するスラックの量をエンコードします。 各パスの品質は最も弱いセルによって決まるため、遷移では最大-最小構造が使用されます。 

再構築のステップは、`(n,m)`に`(1,1)`DP の選択に従います。 選択された各セルを最終的に選択されたシーケンスと位置合わせするために必要な実際のデクリメント数が累積されます。 

## 実用的な例

 自明ではない最小のグリッドを考えてみましょう。 

入力:```

```私たちは計算します`b[i][j] = a[i][j] - (i+j)`:

 | i,j | | b |
 | --- | --- | --- |
 | 1,1 | 2 | 0 |
 | 1,2 | 5 | 2 |
 | 2,1 | 9 | 6 |
 | 2,2 | 10 | 8 |

 DP テーブル:

 | セル | dp値 |
 | --- | --- |
 | (1,1) | 0 |
 | (1,2) | 0 |
 | (2,1) | 0 |
 | (2,2) | 0 |

 最適なボトルネックは 0 です。これは、上にシフトする必要なく完全なパスを位置合わせできることを意味します。 再構成により、すべてのターゲット値が元の制約に厳密に一致しているため、コストがゼロであることがわかります。 

ここで、削減が必要なグリッドを考えてみましょう。 

入力:```
2 2
3 3
3 3
```ここ`b`は次のようになります:

 | セル | b |
 | --- | --- |
 | (1,1) | 1 |
 | (1,2) | 1 |
 | (2,1) | 1 |
 | (2,2) | 1 |

 DP ボトルネックは 1 です。これは、シーケンスを 1 だけ下にシフトできることを意味しますが、すべてのセルはパスに沿ったある時点でターゲットを正確に 1 超えているため、それぞれがコストに寄与します。 再構成ではこれらの超過を合計し、ゼロ以外の合計削減要件が与えられます。 

これらのトレースは、DP が任意にパスを選択しているのではなく、一貫した +1 チェーンの実現可能性を決定する最弱リンク制約を最適化していることを示しています。

 ## 特殊なケース

 次のような単一セルのグリッド`[[42]]`遷移が必要ないため、操作を行わずにすぐに条件が満たされます。 DP は 1 つの状態に崩壊し、正しくゼロコストを返します。 

次のような厳密に増加する最初の行`[1,2,3]`すでに 1 次元で有効なパスを形成しています。 変革`b[i][j]`パスに沿って非負性を維持し、DP は最小スラックに等しい一貫したボトルネックを維持します。これは違反されることはなく、コストがゼロになります。 

値が均一に減少するグリッドでは、すべての移動に大幅な減少が必要になります。 DP は引き続き最適なパスを正しく特定しますが、ボトルネックがネガティブになり、グローバルな下方シフトが必要であることを反映しています。 再構成ステップにより、すべてのセルが必要なシーケンス値に正確に調整され、過剰なカウントが回避されます。
