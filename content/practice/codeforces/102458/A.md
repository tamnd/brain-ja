 ## 解決策
 ## 問題の理解

 座標だけを見れば、幾何学的な話ははるかに単純になります。 ダニエルがすでにポイントを記録したとします`(u, v)`。 鉱山`(x, y)`いつでも避けなければなりません`x = u`または`y = v`2 つの点を結ぶ線分は垂直または水平になるためです。 言い換えれば、記録されたすべてのポイントにより、その垂直線と水平線全体が将来の地雷で使用できなくなります。 

起源はダニエルが何かを訪れる前に記録されるので、すべての鉱山は`x = 0`または`y = 0`すぐに使用できなくなります。 ダニエルが鉱山を訪れるたびに`(x, y)`、座標値`x`永久に利用できなくなり、座標値は`y`も永久に利用できなくなります。 

これにより、問題の実際の組み合わせ構造が得られます。 いくつかの鉱山を訪問することにした場合、訪問した鉱山が 2 つとして同じものになることはありません。`x`コーディネート、同じものは二つとありません`y`座標。 逆に、これら 2 つの条件を満たす鉱山のコレクションは、任意の順序で訪問できます。 一つの鉱山を訪れた後は、その鉱山だけを`x`そして`y`値は禁止されるため、両方の座標がまだ使用されていない別の鉱山は合法のままです。 

したがって、タスクは、すべての地雷が選択されるように、できるだけ多くの地雷を選択することです。`x`座標は明確であり、すべて選択されています`y`どちらかの軸上にある地雷を廃棄した後、座標は明確になります。 

まであります`80,000`座標は次のように大きくなる可能性がありますが、`10^9`。 座標範囲が広いということは、座標によって直接インデックス付けされた配列を構築できないことを意味します。 さらに重要なことは、`N = 80,000`二次アルゴリズムを除外します。`O(N^2)`前後が必要になります`6.4 * 10^9`最悪の場合はペアチェック。 線形に近いアルゴリズム、あるいはおそらく`O(N sqrt N)`。 

誤って対処しやすい特殊なケースがいくつかあります。 考慮する```
1
0 7
```答えは`0`、オリジンがすでに記録しているため`x = 0`, したがって、この鉱山は直ちに禁止されます。 現在の鉱山が未探索かどうかだけをチェックするソリューションでは、鉱山が誤ってカウントされてしまいます。 

ここで考えてみましょう```
3
1 1
1 2
2 3
```答えは`2`。 訪問でき​​ます`(1, 1)`その後`(2, 3)`。 両方を訪れることはできません`(1, 1)`そして`(1, 2)`なぜなら、最初の訪問の後、すべての鉱山は`x = 1`は禁止されています。 かどうかを確認するだけのいいかげんな解決策`y`座標が異なる場合は、3 つすべてをカウントできます。 

もう一つの微妙なケースは、```
4
0 1
1 2
2 3
3 0
```答えは`2`。 軸に接する 2 つの地雷は最初から使用できず、残ったままになります。`(1, 2)`そして`(2, 3)`。 彼らは異なるものを持っています`x`そして`y`両方を訪問できるように調整します。 すべての入力鉱山を利用可能なエッジとして単純に扱うと、オーバーカウントになります。 

## アプローチ

 直接的なブルート フォース ソリューションでは、考えられるあらゆる訪問シーケンスをシミュレートできます。 各州ですべての地雷をチェックし、現在合法であるすべての地雷を再帰的に選択します。 これは正しいです。すべての法的順序が考慮されるため、訪問した鉱山の最大数が検索に表示される必要があります。 

問題は配列の数です。 多くの地雷を選択できる構成では、検索ではほぼすべての地雷の順列を探索できます。`N`鉱山。 可能なプレフィックスの数は次のとおりです。`1 + N + N(N-1) + ... + N!`、

 それは`O(N!)`。 候補者のチェックが一定時間だったとしても、`N!`もう絶望的だ。 で`N = 20`、`20!`についてです`2.43 * 10^18`、実行可能なものをはるかに超えています。 

訪問では利用可能な座標値が変更されるだけなので、総当り攻撃が機能します。 この観察により、ジオメトリを完全に捨てることができます。 あらゆる特徴を与える`x`左側の 1 つの頂点とすべての個別の頂点を調整します`y`右側の 1 つの頂点を座標します。 各鉱山`(x, y)`を接続するエッジになります`x`頂点までの`y`頂点。 

ここで、鉱山を選択することは、それに対応するエッジを選択することを意味します。 2 つの鉱山は、エッジが終点を共有していない場合、両方とも正確に訪問できます。 したがって、有効な地雷のコレクションは、この 2 部グラフで正確に一致します。 

したがって、ダニエルが探索できる鉱山の最大数は、最大 2 部マッチングのサイズになります。 鉱山と`x = 0`または`y = 0`これらの座標は記録された原点によってすでに占有されているため、省略されます。 

単純な拡張パス マッチング アルゴリズムでは、グラフ全体を繰り返し検索することになり、二次関数になる可能性があります。 まで`80,000`エッジの場合、適切な実装は Hopcroft-Karp です。これは、バッチで拡張パスを見つけて実行します。`O(E sqrt V)`時間。

 ## アルゴリズムのチュートリアル

 1. すべての地雷を読み取り、すべての地雷を破棄します。`x = 0`または`y = 0`。 原点は両方の座標値をすでに記録しているため、これらの地雷を選択することはできません。 
2. 残りの個別のデータを圧縮します。`x`座標と区別`y`座標を連続する整数 ID に変換します。 元の座標は次のように大きくできます。`10^9`ただし、座標間の等しいことだけが重要なので、実際の大きさは無関係です。 
3. 2 部グラフを作成します。 残りの鉱山ごとに`(x, y)`を表す圧縮された頂点からエッジを追加します。`x`を表す頂点に`y`。 各エッジは正確に 1 つの地雷に対応します。 
4. メンテナンス`pair_left[x]`、現在左の頂点に一致している右の頂点、および`pair_right[y]`、左の頂点は現在右の頂点と一致しています。 一致しない頂点は次のように表されます。`-1`。 
5. Hopcroft-Karp を実行します。 まず、一致しないすべての左頂点から BFS を実行します。 BFS は、一致しないエッジと一致するエッジを交互に繰り返すことでレイヤーを構築し、自由な右頂点に到達できる最短距離を記録します。 
6. BFS レイヤーを尊重するエッジのみをたどって、現在一致していないすべての左頂点から DFS を実行します。 DFS が一致しない右側の頂点に到達すると、拡張パスが検出されるため、そのパスに沿ったすべてのエッジが反転され、一致するサイズが 1 つ増加します。 
7. 拡張パスが存在しなくなるまで、BFS フェーズと DFS フェーズを繰り返します。 その時点で現在のマッチングは最大であるため、そのサイズが答えとなります。 

なぜそれが機能するのかは、一致する不変条件によって把握されます。 あらゆる瞬間において、選択されたエッジはペアごとに異なる地雷を表します。`x`そして`y`座標を調整して、実行可能な探査計画を作成します。 Hopcroft-Karp が拡張パスを見つけるたびに、そのエッジを反転すると、サイズが 1 だけ増加しながら、一致するプロパティが維持されます。 BFS が拡張パスを見つけられなくなると、拡張パス定理により、より大きな一致は存在しないと判断されます。 ここでは、マッチングと地雷の実行可能なセットはまったく同じオブジェクトであるため、最終的なマッチング サイズは、ダニエルが探索できる地雷の最大数とまったく同じになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def maximum_mines(data):
    it = iter(map(int, data.split()))
    n = next(it)

    mines = []
    xs = {}
    ys = {}

    for _ in range(n):
        x = next(it)
        y = next(it)

        # The origin has already forbidden x = 0 and y = 0.
        if x == 0 or y == 0:
            continue

        if x not in xs:
            xs[x] = len(xs)
        if y not in ys:
            ys[y] = len(ys)

        mines.append((xs[x], ys[y]))

    nx = len(xs)
    ny = len(ys)

    graph = [[] for _ in range(nx)]
    for x, y in mines:
        graph[x].append(y)

    pair_left = [-1] * nx
    pair_right = [-1] * ny
    dist = [-1] * nx

    from collections import deque

    def bfs():
        q = deque()
        found = False

        for u in range(nx):
            if pair_left[u] == -1:
                dist[u] = 0
                q.append(u)
            else:
                dist[u] = -1

        while q:
            u = q.popleft()

            for v in graph[u]:
                matched_u = pair_right[v]

                if matched_u == -1:
                    found = True
                elif dist[matched_u] == -1:
                    dist[matched_u] = dist[u] + 1
                    q.append(matched_u)

        return found

    sys.setrecursionlimit(max(1_000_000, nx * 2 + 10))

    def dfs(u):
        for v in graph[u]:
            matched_u = pair_right[v]

            if matched_u == -1 or (
                dist[matched_u] == dist[u] + 1 and dfs(matched_u)
            ):
                pair_left[u] = v
                pair_right[v] = u
                return True

        dist[u] = -1
        return False

    matching = 0

    while bfs():
        for u in range(nx):
            if pair_left[u] == -1 and dfs(u):
                matching += 1

    return str(matching)

def main():
    data = sys.stdin.buffer.read()
    sys.stdout.write(maximum_mines(data))

if __name__ == "__main__":
    main()
```最初のパスでは、地雷を読み取りながら座標を圧縮します。 座標の範囲は次のとおりであるため、辞書を使用する必要があります。`10^9`; 圧縮された ID は最大でも`N - 1`。 

グラフには、使用可能な鉱山ごとに 1 つのエッジが含まれます。 アルゴリズムに必要な操作は 2 つの座標が等しいかどうかをテストすることだけであるため、圧縮後に元の座標を保存する必要はありません。`pair_left`そして`pair_right`両方向からの電流マッチングを説明します。 両方のアレイがあると、交互のパスを効率的にたどることができます。 右側の頂点がすでに一致している場合は、`pair_right[v]`次にどの左頂点を訪問する必要があるかをすぐに教えてくれます。 

BFS は、Hopcroft-Karp によって使用されるレイヤーを構築します。 右頂点が一致しない場合は、現在の BFS が拡張パスの終点候補を見つけたことを意味します。 その後、DFS は階層構造のみを検索し、最短の拡張パスに属せない任意のパスを回避します。 

Python の再帰制限を増やした後は、再帰 DFS は安全になります。 グラフ`80,000`エッジは長い交互パスを生成する可能性があるため、Python のデフォルトの再帰制限に依存するのは安全ではありません。 

Python には整数オーバーフローの問題はなく、座標自体が算術演算に使用されることはありません。 答えはせいぜい`N`, そのため、マッチングカウンターも小さいです。

import sys
from collections import deque

def solve_string(data: str) -> str:
    it = iter(map(int, data.split()))
    n = next(it)

    mines = []
    xs = {}
    ys = {}

    for _ in range(n):
        x = next(it)
        y = next(it)

        if x == 0 or y == 0:
            continue

        if x not in xs:
            xs[x] = len(xs)
        if y not in ys:
            ys[y] = len(ys)

        mines.append((xs[x], ys[y]))

    nx = len(xs)
    ny = len(ys)

    graph = [[] for _ in range(nx)]
    for x, y in mines:
        graph[x].append(y)

    left = [-1] * nx
    right = [-1] * ny
    dist = [-1] * nx

    def bfs():
        q = deque()
        found = False

        for u in range(nx):
            if left[u] == -1:
                dist[u] = 0
                q.append(u)
            else:
                dist[u] = -1

        while q:
            u = q.popleft()

            for v in graph[u]:
                w = right[v]

                if w == -1:
                    found = True
                elif dist[w] == -1:
                    dist[w] = dist[u] + 1
                    q.append(w)

        return found

    sys.setrecursionlimit(max(1_000_000, nx * 2 + 10))

    def dfs(u):
        for v in graph[u]:
            w = right[v]

            if w == -1 or (
                dist[w] == dist[u] + 1 and dfs(w)
            ):
                left[u] = v
                right[v] = u
                return True

        dist[u] = -1
        return False

    ans = 0

    while bfs():
        for u in range(nx):
            if left[u] == -1 and dfs(u):
                ans += 1

    return str(ans)

多数の地雷が同じ座標を持つ場合、それらはすべて 1 つのグラフ頂点に属するエッジになります。 のために```

1 3
1 4

2 1
3 3
```特に便利な構造を持っています。 単純な貪欲アルゴリズムは、最初に次のことを選択する可能性があります。`(1,1)`、両方をブロックします`(1,2)`そして`(2,1)`。 代わりに最大一致が選択されます`(1,2)`そして`(2,1)`、 それから`(3,3)`、到達`3`。 Hopcroft-Karp は、以前の選択を変更する拡張パスを通じてこれを発見できます。 これが、恣意的な貪欲なマッチングでは十分ではない理由です。 

最後に、次の座標制限は、`10^9`実装に特別なケースは作成されません。 座標は辞書キーとして保存され、すぐに小さな整数 ID に圧縮されます。 アルゴリズムは座標値に比例したサイズの配列を割り当てることはありません。`(1000000000, 999999999)`次のような鉱山とまったく同じ量のグラフ ストレージのコストがかかります。`(1,2)`。
