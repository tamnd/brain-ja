 ## 解決策
 ## 問題の理解

 配列があります`A`の`n`負でない整数と予算`M`。 空ではないすべての連続したサブ配列に対して`A[l..r]`, アンディは要素を増やすことができますが、追加される合計量は以下を超えることはできません。`M`。 彼の目標は、選択した部分配列を非減少にすることです。 

固定部分配列の場合、関連する量は 1 つだけです。それは、減少しないようにするために追加する必要がある最小合計量です。 この最小コストを持つサブアレイが最大でいくつあるかを数える必要があります。`M`。 

選択した部分配列が次から始まると仮定します。`l`。 左から右に処理していきます。 最初の値は変更する必要はありません。 位置で`i`、変更後の可能な最小値は、元の値より大きい値になります。`A[i]`および以前に変更された値。 したがって、最適に変更されたシーケンスは、プレフィックス最大値のシーケンスとまったく同じになります。 

[
 B_i=\max(A_l,A_{l+1},\ldots,A_i)。 
】

 最低コストは、`[l,r]`したがって

 [
 C(l,r)=\sum_{i=l}^{r}\left(\max_{j=l}^{i} A_j-A_i\right)。 
】

 サブ配列が勝っているのは、まさに次のような場合です。`C(l,r) <= M`。 

重要な制約は、`n <= 2 * 10^5`、 その間`M`と同じ大きさにすることができます`2 * 10^14`そしてそれぞれ`A[i]`と同じ大きさにすることができます`10^9`。 くらいあります`n(n+1)/2`サブ配列なので、それらを列挙するにはすでに約`2 * 10^10`最大サイズのケース。 サブアレイごとに線形時間を費やすソリューションは完全に不可能です。 近くに必要です`O(n log n)`すべてのコストは 64 ビット演算を使用する必要があります。 Python の整数はこの範囲を自然に処理します。 

誤答を引き起こしやすい特殊なケースがいくつかあります。 

いつ`n=1`、単一要素のサブ配列はすでに減少しておらず、コストはゼロです。 のために`1 0`配列あり`1234`、答えは`1`。 逆変換を含む部分配列のみをカウントする実装では、誤ってゼロが返されます。 

等しい値を厳密な増加として扱ってはなりません。 のために`n=4`、`M=0`、および配列`5 5 5 5`、10 個の部分配列のすべてがすでに非減少であるため、答えは次のようになります。`10`。 次に大きい構造が等しい値を大きい値として扱う場合、プレフィックス最大ブロックが誤って分割される可能性があります。 

予算の比較には包括的な内容が含まれます。 のために`n=3`、`M=3`、および配列`3 1 2`、サブ配列`[3,1,2]`正確にコストがかかります`3`: 小さい方の 2 つの値は次のようになります。`3`、追加`2+1`。 これは有効であるため、6 つのサブ配列すべてがカウントされます。 使用する`< M`の代わりに`<= M`この間隔が失われます。 

最後に、コストは 32 ビット整数よりもはるかに大きくなる可能性があります。 と`n=2*10^5`そして周囲の価値観`10^9`、合計補正は次のオーダーに達する可能性があります。`10^14`。 32 ビット アキュムレータは、固定幅の整数を使用する言語では静かにオーバーフローします。 

## アプローチ

 直接的なアプローチは、すべてのペアを修正することです`(l,r)`非減少シーケンスの貪欲な構築をシミュレートします。 から始まる`maximum = A[l]`、以下の各要素が貢献します`max(0, maximum - A[i])`、 そして`maximum`いつ更新されるか`A[i]`の方が大きいです。 これは正しいです。すべての要素は少なくとも以前の最終値である必要があるため、より大きな値を選択するとコストが増加するだけです。 

がある`n(n+1)/2`複数のサブ配列が含まれており、単一のサブ配列には以下が含まれる場合があります。`O(n)`要素。 最悪の場合、これはつまり

 [
 \シータ(n^3)
 】

 操作。 と`n=2*10^5`、それは次のとおりです`8*10^15`基本的な反復は 2 秒の制限をはるかに超えています。 

ブルート フォース アプローチは、厳密に貪欲な構造に従うため機能しますが、配列の同じ部分を繰り返しウォークスルーします。 より高速な解決策を明らかにする観察は、プレフィックスの最大値がどの位置でも変わらないということです。 ポジションから始める`l`、現在の最大値はそのままです`A[l]`値が厳密に大きい最初の位置まで`A[l]`。 その位置に到達した後、同じ推論が新しい最大値から再び開始されます。 

定義する`nxt[i]`の右側の最初の位置として`i`と`A[nxt[i]] > A[i]`。 間`i`そして`nxt[i]-1`、プレフィックスの最大値は正確に`A[i]`。 このブロックの合計コストは次のとおりです。 

[
 A_i(nxt[i]-i)-\sum_{j=i}^{nxt[i]-1}A_j。 
】

 したがって、長いサブアレイのコストは、完全な次に大きなブロックのチェーンと最後の 1 つの部分ブロックに分解できます。 

全て`nxt[i]`値は単調スタックを使用して線形時間で見つけることができます。 次に、バイナリ リフティングを使用して、次に大きいブロックを一度に多数スキップし、次の値を取得します。`C(l,r)`で`O(log n)`。 

最後の観察は、有効な右端点の最大値が単調であるということです。 引っ越したら`l`そのまま右へ`r`修正済みの場合は、最初から要素を削除するため、最低限必要なコストが増加することはありません。 したがって、有効な最大の`r`そのまま左に移動することはありません`l`が増加します。 これにより、2 ポインター スキャンが可能になります。各右エンドポイントのみが進みます。`O(n)`コストチェックには毎回時間がかかりますが、全体としては`O(log n)`。

 ## アルゴリズムのチュートリアル

 1. 通常のプレフィックス合計配列を構築する`pref`、 どこ`pref[i]`の合計です`A[0..i-1]`。 これにより、連続したブロックの合計を一定時間で計算できるようになります。 
2. コンピューティング`nxt[i]`、最初のインデックス`j > i`と`A[j] > A[i]`。 単調減少スタックで右から左にスキャンします。 上部の値はより小さいですが、`A[i]`、ポップしてください。`i`は、その最初の厳密に大きな要素になります。 等しい値が見つかってもプレフィックスの最大値は変わらないため、等しい値はポップされません。 
3. ポジションごとに`i`、ブロック全体のコストを次のコストとして定義します。`i`を通して`nxt[i]-1`。 これより大きな要素がない場合、ブロックは次の位置で終了します。`n`。 その費用は

 [
 block[i]=A_i(nxt[i]-i)-(pref[nxt[i]]-pref[i])。 
】

 この間隔内では、すべてのプレフィックスの最大値は次のとおりです。`A[i]`したがって、式は直接合計します。`A[i]-A[j]`。 

1. バイナリリフティングテーブルを構築します。`up[k][i]`は次の後に到達した位置を表します`2^k`から始まる次に大きなジャンプ`i`。`gain[k][i]`これらのジャンプによって交差されたすべての完全なブロック コストの合計を格納します。 基本レベルには 1 つのジャンプが含まれているため、`up[0][i] = nxt[i]`そして`gain[0][i] = block[i]`。 
2. 関数を実装する`cost(l,r)`作成の最小コストを計算します`A[l..r]`減っていない。 から開始`l`、バイナリリフティングレベルを最大から最小まで検査します。 ジャンプ先が最大でも`r`、そのブロック全体が要求された間隔内にあるため、事前計算されたコストを追加してそこにジャンプします。 完全なブロックが適合しなくなった後、残りの間隔は次から始まります。`cur`そしてで終わります`r`。 そのプレフィックスの最大値は次のとおりです`A[cur]`、最終的な部分コストを与える

 [
 A_{cur}(r-cur+1)-(pref[r+1]-pref[cur])。 
】

 1. 2 つのポインターを使用して配列をスキャンします。 正しいエンドポイントを維持する`r`。 新しい左端点ごとに`l`、繰り返し延長します`r`その間`cost(l,r+1) <= M`。 正しいエンドポイントを後方に移動する必要がないため、すべての拡張は永続的です。 次の拡張が予算を超えると、要素を追加しても必要な変更コストを削減できないため、より大きな右側のエンドポイントも無効になります。 
2. 現在のところ`l`、 その通り`r-l+1`で始まるサブ配列`l`有効です。 この数値を答えに加算して増加します`l`。 一番左の要素を削除しても最小変更コストを増やすことはできないため、既存の`r`有効なままであり、2 ポインターの不変条件は保持されます。 

### なぜ効果があるのか

 すべてのサブ配列について、各位置で可能な最小の最終値は、そのプレフィックスの最大値です。 次に大きい分解では、これらのプレフィックス最大値が、現在の最大値が一定である最大領域に分割されるため、ブロック式は直接貪欲スキャンとまったく同じコストを計算します。 バイナリ リフティングでは、合計の寄与を変更せずに連続する完全な領域のみがスキップされ、最後の部分領域が直接計算されます。 

2 ポインター部分は単調性に依存します。 固定の場合`l`、延長`r`は非負の寄与のみを追加できるため、右側のエンドポイントが無効になると、より大きなエンドポイントはすべて無効になります。 固定の場合`r`、移動`l`right は制約を削除し、最小コストを増やすことができないため、有効な最大コストが`r`左に移動できません。 したがって、有効なサブ配列はすべて 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, M = map(int, input().split())
    a = list(map(int, input().split()))

    # Prefix sums.
    pref = [0] * (n + 1)
    s = 0
    for i, x in enumerate(a):
        s += x
        pref[i + 1] = s

    # nxt[i] = first j > i with a[j] > a[i].
    nxt = [n] * n
    stack = []

    for i in range(n - 1, -1, -1):
        x = a[i]
        while stack and a[stack[-1]] < x:
            nxt[stack.pop()] = i
        stack.append(i)

    # Cost of the complete block [i, nxt[i)-1].
    block = [0] * n
    for i in range(n):
        j = nxt[i]
        block[i] = a[i] * (j - i) - (pref[j] - pref[i])

    LOG = n.bit_length()

    # Binary lifting tables.
    up = [nxt]
    gain = [block]

    for k in range(1, LOG):
        prev_up = up[-1]
        prev_gain = gain[-1]

        cur_up = [n] * n
        cur_gain = [0] * n

        for i in range(n):
            mid = prev_up[i]
            if mid < n:
                cur_up[i] = prev_up[mid]
                cur_gain[i] = prev_gain[i] + prev_gain[mid]

        up.append(cur_up)
        gain.append(cur_gain)

    def cost(l, r):
        """Minimum increments needed for a[l..r]."""
        cur = l
        ans = 0

        for k in range(LOG - 1, -1, -1):
            j = up[k][cur]
            if j <= r:
                ans += gain[k][cur]
                cur = j

        # cur is the beginning of the final partial block.
        ans += a[cur] * (r - cur + 1) - (pref[r + 1] - pref[cur])
        return ans

    ans = 0
    r = -1

    for l in range(n):
        if r < l:
            r = l

        while r + 1 < n and cost(l, r + 1) <= M:
            r += 1

        ans += r - l + 1

    print(ans)

if __name__ == "__main__":
    solve()
```プレフィックス合計の構造は、ブロックコストの式に直接対応します。`pref[j] - pref[i]`はブロック内のすべての元の値の合計です。`a[i] * (j-i)`は、そのブロック内のすべての要素がブロックの最大値まで引き上げられた後の合計です。 

単調スタックでは厳密な比較が使用されます。`a[stack[-1]] < x`。 これを次のように変更すると、`<=`それは不正確でしょう。 値が等しい場合、前の値は同じプレフィックス最大値のままであるため、厳密に大きい最初の値がブロックの終了となります。 

バイナリリフティングテーブルは以下を使用します。`n`より大きな要素が存在しないことを意味する番兵として。 ジャンプは、目的地が次の場合にのみ使用されます。`<= r`。 この条件は、ジャンプによって表されるブロック全体が属することを保証するものです。`[l,r]`。 

すべての完全なブロックが消費された後、`cur`次のより大きな要素がその先にある最初の位置です`r`。 したがって、すべてのプレフィックスの最大値は、`cur`を通して`r`等しい`a[cur]`これにより、最終的な定数時間の式が有効になります。 

2 ポインター ループは意図的にチェックします。`r+1`現在のウィンドウのコストを再計算するのではなく、 現在`[l,r]`が有効であることがすでに知られています。 一度`[l,r+1]`失敗すると、その後のすべての正しいエンドポイントも同様に失敗します。 

Python の任意精度の整数はここで役に立ちます。`M`累積コストは約`10^14`。 明示的なオーバーフロー処理は必要ありません。

## テストケース```python
import sys
import io

def solve_data(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out

    try:
        solve()
        return out.getvalue().strip()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

def solve():
    n, M = map(int, input().split())
    a = list(map(int, input().split()))

    pref = [0] * (n + 1)
    for i, x in enumerate(a):
        pref[i + 1] = pref[i] + x

    nxt = [n] * n
    stack = []

    for i in range(n - 1, -1, -1):
        while stack and a[stack[-1]] < a[i]:
            nxt[stack.pop()] = i
        stack.append(i)

    block = [0] * n
    for i in range(n):
        j = nxt[i]
        block[i] = a[i] * (j - i) - (pref[j] - pref[i])

    LOG = n.bit_length()
    up = [nxt]
    gain = [block]

    for _ in range(1, LOG):
        pu = up[-1]
        pg = gain[-1]
        cu = [n] * n
        cg = [0] * n

        for i in range(n):
            mid = pu[i]
            if mid < n:
                cu[i] = pu[mid]
                cg[i] = pg[i] + pg[mid]

        up.append(cu)
        gain.append(cg)

    def cost(l, r):
        cur = l
        res = 0

        for k in range(LOG - 1, -1, -1):
            j = up[k][cur]
            if j <= r:
                res += gain[k][cur]
                cur = j

        return res + a[cur] * (r - cur + 1) - (
            pref[r + 1] - pref[cur]
        )

    ans = 0
    r = -1

    for l in range(n):
        if r < l:
            r = l

        while r + 1 < n and cost(l, r + 1) <= M:
            r += 1

        ans += r - l + 1

    print(ans)

 ## 特殊なケース

 単一要素の場合`n=1`、`M=0`、`A=[7]`から始まる`r=l`。 費用`[7]`はゼロであるため、ループはそれ以上拡張できず、有効な部分配列が 1 つ追加されます。 答えは`1`。 

値が等しい場合は、次のように考慮します。`A=[5,5,5,5]`と`M=0`。 毎`nxt[i]`は`n`厳密にこれより大きな値はないからです。 したがって、完全な各ブロックは最後まで拡張されますが、すべての要素がブロックの最大値に等しいため、そのコストはゼロになります。 2 ポインタ スキャンが到達する`r=3`あらゆる人にとって`l`、数えます`4+3+2+1=10`サブアレイ。 

予算ぴったりの場合`A=[3,1,2]`、`M=3`、完全な間隔には接頭辞 maxima が付きます。`[3,3,3]`。 その費用は`(3-3)+(3-1)+(3-2)=3`、ということで条件は`cost <= M`それを受け入れます。 アルゴリズムが拡張される`r`1 つのポジションを早めに停止するのではなく、最終ポジションを通過します。 

減少する場合`A=[3,2,1]`、`M=1`、長さ 2 の区間にはコストがあります`1`、全間隔にはコストがかかります`1+2=3`。 したがって、開始位置ごとの有効なカウントは次のようになります。`2`、`2`、 そして`1`、与える`5`。 各要素の次に大きいチェーンは、後続の値がすべて小さいためすぐに終了します。そのため、ブロックの式は、間隔を延長するコストの増加を正確に把握します。
