 ## 解決策
 ## 問題の理解

 平面上に描かれたいくつかの円盤が与えられます。 各ディスクは、中心点と半径によって定義される塗りつぶされた円です。 円盤は危険になる領域のように機能し、残りの安全な空間の形状に興味があります。 

問題は、厳密にはすべての円盤の外側にあるが、少なくとも 1 つの円盤を横切らなければ無限に到達できないという意味で、完全に円盤に囲まれている点が平面内に存在するかどうかです。 言い換えれば、ディスクの結合の補数には、どのディスク境界にも触れていない、有界で接続された領域が含まれている必要があります。 

これは、隠れたトポロジー接続の問題です。 各ディスクは「ブロックされた領域」であり、空き領域にブロックされた領域で完全に囲まれた有限連結成分があるかどうかを尋ねます。 

制約は小さく、ディスク数は最大 250 なので、N の 2 乗または N の 3 乗程度の任意のアルゴリズムが妥当です。 これは、明示的な幾何学的グラフや円盤間の交差の配置を構築できることを直ちに示唆しています。 

微妙な点は、答えは、ディスクが重なっているのか、領域を密に覆っているのかということではないということです。 閉じた結界を形成しているかどうかです。 「多くの重なりは囲い込みを暗示している」という素朴な直観は誤りです。 

これが失敗する小さな例としては、3 つのディスクが三角形を形成しているが、中央に無限につながるギャップが残っている場合があります。 この領域は視覚的に囲まれているように見えますが、ディスクを横切ることなく外側に向かう連続したパスがまだ存在します。 

もう 1 つの微妙なケースは、ディスクが接触しそうになったが交差しない場合です。 この問題では、交差しない境界間の最小間隔が少なくとも 1 であることが保証され、接線および三重交点も除外されます。 これにより、縮退が除去され、交差のきれいな組み合わせ構造が保証されます。 

主な困難は、ディスクの結合が平面内で空の空間の穴をトラップする閉じた境界を形成しているかどうかを検出することです。 

## アプローチ

 直接的なアプローチは、ディスクの結合の幾何学的観点から考えることです。 円板の補体は平面領域であり、それに有界連結成分があるかどうかを知りたいと考えています。 

強引なアイデアの 1 つは、ディスクの境界によって引き起こされるすべての可能な面の内部で候補点を選択することです。 N 個の円の配置により O(N^2) 個の交点が作成され、これらの交点が平面のパーティションの組み合わせ構造を定義します。 この配置のすべての面を列挙して、どの面もディスク内部と交差しない境界領域であるかどうかをテストしてみることができます。 ただし、面を明示的に構築することは複雑であり、完全な平面配置の横断が必要ですが、制約を考慮すると不要です。 

より構造化された観察により、すべてが単純化されます。 主平面で作業する代わりに、交差構造に基づいて構築された二重グラフを介して自由空間の接続性をモデル化できます。 各ディスク境界は、交点間の円弧に寄与します。 重要なアイデアは、空き領域の領域を囲むディスク境界のサイクルが存在するかどうかを検出することです。 

これは、「円弧の交差グラフ」上のグラフの接続性の観点から考えると非常に簡単になります。 各ディスクは円形の境界を構成し、円間の交差点がノードを作成します。 円の境界に沿った連続する交点の間には、その円盤の境界に属する円弧があります。 

次に、重要な単純化が観察されます。 境界のある空の領域は、外側の無限領域を含まない面を囲む円境界の交互の弧によって形成されるサイクルが存在する場合にのみ存在します。 平面グラフの用語では、これは、配置に外側の面ではない面があるかどうかを検出することに相当します。

面を明示的に構築する代わりに、標準的な幾何学的縮小を使用できます。つまり、各円をグラフ内のノードとして扱い、2 つの円が交差する場合は接続します。 交差構造だけではエンクロージャーを検出するのに十分ではありませんが、各円に沿ったすべての交点によって引き起こされる配置を考慮することで、エンクロージャーを検出することができます。 各円の境界はセグメントに切断され、これらのセグメントは円に埋め込まれた平面グラフを形成します。 

次に、この埋め込まれた構造に対してトラバーサルを実行し、円弧の平面グラフを効果的にシミュレートします。 各円弧は状態：（円 ID、連続する交差角間の間隔）です。 円間の交点で円弧を接続し、ある円から別の円に切り替えます。 

このグラフが構築されると、境界領域の存在は、埋め込まれたグラフ内に外面に付随しないサイクルがあるかどうかに対応します。 これを検出する標準的な方法は、配置グラフの連結成分を計算し、「無限のエスケープ方向」を含む成分がないかどうかを確認することです。 実際には、これは、配置グラフに外部に接続されていない面があるかどうかをチェックすることになります。これは、すべてのディスクの外側にあることがわかっている点から始まる外部トラバースを追跡することで検出できます。 

遠距離ではディスクの制約は問題にならないため、外側の領域は遠く離れた点によってシードされる可能性があります。 そこから、円盤の内部を横切ることなく到達可能な円弧上を伝播します。 この外側のシードから到達できないアークまたは領域は、境界のある囲まれた領域に対応します。 

これにより、円弧上に平面隣接グラフを構築し、外側から塗り潰しを行うという問題が軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースフェイス列挙 | O(N^3) または指数 | O(N^2) | 遅すぎる/やりすぎ |
 | 円配置BFS（円弧グラフ） | O(N^2 log N) | O(N^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 連続する交点間の円境界上の円弧セグメントをノードが表すグラフを構築します。 

1. すべての円ペアの交点を計算します。 円のペアごとに、最大 2 つの交点を計算します。 各交点は、両方の円に対する角度形式で保存されます。 このステップでは、各円の境界上にすべての「カット ポイント」を構築します。 
2. 各円について、その交点を中心の周りの角度によって並べ替えます。 これにより、その円上の円弧セグメントの周期的な順序が定義されます。 各円弧は、連続する交差角の間のセグメントです。 
3. 円弧セグメントごとにノードを作成します。 各円弧は (円 ID、ソートされた角度リストのインデックス) によって識別されます。 これは、交差点によって中断されていない円の最大の連続境界部分を表します。 
4. 2 つの円間の各交点について、最初の円の対応する円弧を 2 番目の円の対応する円弧に接続します。 これにより、平面トラバーサル グラフに遷移が作成されます。 
5. 十分に離れた点を配置して、最初の「外側」領域を特定します。 これをシミュレートするには、ディスク内にない点 (たとえば、非常に大きな座標を持つ点) を選択し、その点がどの円弧領域にアクセスできるかを決定します。 これにより、アーク隣接上に BFS/DFS がシードされます。 
6. 外側のシードから開始して円弧グラフに対して BFS/DFS を実行します。 到達した円弧は、無限面に隣接する境界領域に対応します。 
横断後、訪問されていないアークが存在する場合、それは配置の境界面に属します。 そのような円弧が存在する場合は 1 を出力し、存在しない場合は 0 を出力します。 

### なぜ効果があるのか

円の境界の配置により平面グラフが形成され、その面はディスク内部の補体の接続領域に正確に対応します。 外側の面は、無限遠から到達できる唯一の面です。 円弧の隣接上の BFS は、面間の共有境界に沿った横断をシミュレートします。 外面から到達できない円弧は、ディスクで完全に囲まれた領域に相当する境界面の境界上になければなりません。 したがって、未訪問のアークを検出することは、完全に囲まれた空の領域の存在を検出することと同じです。 

## Python ソリューション```python
import sys
import math
input = sys.stdin.readline

EPS = 1e-9

def dist2(a, b, c, d):
    dx = a - c
    dy = b - d
    return dx * dx + dy * dy

def circle_intersections(x0, y0, r0, x1, y1, r1):
    dx = x1 - x0
    dy = y1 - y0
    d2 = dx * dx + dy * dy
    d = math.sqrt(d2)

    if d == 0 or d > r0 + r1 or d < abs(r0 - r1):
        return []

    a = (r0 * r0 - r1 * r1 + d2) / (2 * d)
    h2 = r0 * r0 - a * a
    if h2 < 0:
        h2 = 0
    h = math.sqrt(h2)

    xm = x0 + a * dx / d
    ym = y0 + a * dy / d

    rx = -dy * (h / d)
    ry = dx * (h / d)

    p1 = (xm + rx, ym + ry)
    p2 = (xm - rx, ym - ry)

    if dist2(*p1, x0, y0) > r0 * r0 + 1e-7:
        p1 = p1
    if dist2(*p2, x0, y0) > r0 * r0 + 1e-7:
        p2 = p2

    return [p1, p2]

def inside_any(x, y, circles):
    for cx, cy, r in circles:
        if (x - cx) ** 2 + (y - cy) ** 2 < r * r - 1e-7:
            return True
    return False

def angle(cx, cy, x, y):
    return math.atan2(y - cy, x - cx)

n = int(input())
circles = [tuple(map(int, input().split())) for _ in range(n)]

events = [[] for _ in range(n)]

for i in range(n):
    x0, y0, r0 = circles[i]
    for j in range(i + 1, n):
        x1, y1, r1 = circles[j]
        pts = circle_intersections(x0, y0, r0, x1, y1, r1)
        for px, py in pts:
            ai = angle(x0, y0, px, py)
            aj = angle(x1, y1, px, py)
            events[i].append((ai, j))
            events[j].append((aj, i))

arcs = []
arc_id = {}

for i in range(n):
    events[i].sort()
    m = len(events[i])
    if m == 0:
        continue
    for k in range(m):
        nxt = (k + 1) % m
        arcs.append((i, k))
        arc_id[(i, k)] = len(arcs) - 1

adj = [[] for _ in range(len(arcs))]

for i in range(n):
    m = len(events[i])
    if m == 0:
        continue
    for k in range(m):
        j = events[i][k][1]
        for t in range(len(events[j])):
            if events[j][t][1] == i:
                u = arc_id[(i, k)]
                v = arc_id[(j, t)]
                adj[u].append(v)
                adj[v].append(u)
                break

start = None
for i in range(n):
    x, y, r = circles[i]
    if not inside_any(x + r + 10, y + r + 10, circles):
        if len(events[i]) > 0:
            start = arc_id[(i, 0)]
            break

if start is None and len(arcs) > 0:
    start = 0

vis = [False] * len(arcs)
stack = [start]
vis[start] = True

while stack:
    u = stack.pop()
    for v in adj[u]:
        if not vis[v]:
            vis[v] = True
            stack.append(v)

ok = any(not v for v in vis)

print(1 if ok else 0)
```コードは最初にすべての円と円の交点を計算し、それらを各円上の角度イベントとして記録します。 次に、各円を、連続するイベント間の円弧セグメントの循環シーケンスに変換します。 各アークはグラフ ノードになります。 エッジは、同じ幾何学的交点で交わるが異なる円に属する円弧の間に作成され、円の境界を越えることができます。 

BFS は、すべてのディスクから遠く離れたポイントをテストすることで検出される、外部からヒューリスティックに到達可能なアークから開始します。 このシード処理が正確であるかどうかは、少なくとも 1 つの円の境界が無限領域に隣接しているかどうかに依存します。これは、有限の配置では外側の円弧が露出する必要があるためです。 

最後に、この外部横断からアークに到達できない場合、そのアークはディスクで完全に囲まれた境界領域の内側にあります。 

## 実用的な例

 ### サンプル 1

 閉じられた囲いのない、緩やかに接続された構造を作成する交差する 4 つの円を考えます。 

| ステップ | アクション | 訪問アーク |
 | --- | --- | --- |
 | 1 | 交差点を構築する | 部分円弧グラフ |
 | 2 | 円弧を作成する | すべての境界セグメント |
 | 3 | アークの外側から BFS を開始 | 外側領域の弧 |
 | 4 | トラバースを展開する | 到達可能なすべての円弧 |
 | 5 | 未訪問のチェック | なし |

 横断は最終的にすべての円弧に到達します。これは補空間が無限に完全に接続されていることを意味します。 境界のある空の領域は存在しません。 

### サンプル 2

 ここで、ディスクは中央に領域をトラップする構成を形成します。 

| ステップ | アクション | 訪問アーク |
 | --- | --- | --- |
 | 1 | 交差点を構築する | 環状構造 |
 | 2 | 円弧を作成する | 複数の閉ループ |
 | 3 | 外部から BFS を起動する | 外側のループのみ |
 | 4 | トラバースを展開する | 内部サイクルに入りません |
 | 5 | 未訪問のチェック | 内側のアークが存在します |

 BFS は円の境界で完全に囲まれているため、内側のサイクルに入ることができません。そのため、未訪問の円弧のセットが残り、境界領域を示します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N^2 log N) | ペアごとの交差と円ごとの並べ替え角度 |
 | スペース | O(N^2) | 交差構造の円弧と隣接関係 |

 N が最大 250 の場合、O(N^2) ペアごとの相互作用は約 60,000 ペアとなり、これは容易に制限内に収まります。 各円には最大で O(N) 個の交差があるため、円ごとの並べ替えは小さくなります。

 ## 特殊なケース

 主なエッジケースは、ディスクが重なり合っているにもかかわらず、脱出通路を離れている場合です。 このような場合、交差グラフは密になりますが、外側領域からの BFS は依然としてすべてのアークに到達します。 たとえば、中心が遠く離れた 2 つの大きな重なり合うディスクは、常に接続された外部領域を離れるため、内部の未訪問のアークは表示されません。 

もう 1 つのエッジ ケースは、小さなディスクが他のディスクによって形成された大きなループの内側に完全に収まる場合です。 これはまさに、内側の円弧コンポーネントがトラバーサル グラフ内で孤立する場合に当てはまります。 BFS は、内側のディスク境界を外側の境界に接続する交差パスがないため、内側のディスク境界の円弧に到達することができず、囲まれた領域が正しく検出されます。 

3 番目のケースは、3 つのディスクが三角形を形成する最小構造です。 視覚的に囲いを示唆している場合でも、円が閉じた環状境界を形成するように交差していない場合、円弧グラフは外面を介して接続されたままとなり、すべての円弧が BFS シードから到達可能になります。
