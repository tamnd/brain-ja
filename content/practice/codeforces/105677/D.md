 ## 解決策
 ## 問題の理解

 塔の列が与えられ、それぞれが左から右に整数座標に配置され、各位置に高さが割り当てられます。 すべての高さが異なるため、唯一の最も高い塔が存在します。 

最も高いタワーを除くすべてのタワーについて、厳密にそのタワーよりも高い最も近いタワーを探します。 「最も近い」はインデックス距離で測定されるため、左または右に 1 ステップ移動すると 1 単位のコストがかかります。 塔は、より高い塔が左側にあるか右側にあるかに関係なく、より近い方の塔までの距離に寄与します。 これより高い塔は存在しないため、最も高い塔は何も貢献しません。 

タスクは、最も高くないすべてのタワーにわたるこれらの最小距離の合計を計算することです。 

N が 200,000 までという制約により、二次戦略から遠ざけられます。 「より高い塔が見つかるまで各塔を左右にスキャンする」という単純なチェックでは、最悪の場合 O(N^2) まで低下します。これには 4 × 10^10 のオーダーの比較が必要となり、2 秒の制限をはるかに超えます。 

正確さのためには、いくつかの特殊なケースが重要です。 タワーの一方の側に高いタワーがなく、もう一方の側に高いタワーがある場合、有効な側のみが寄与します。 両側に高い塔がある場合は、単一方向のスキャンで最初に遭遇した塔ではなく、近い方の塔を取得する必要があります。 たとえそれが有効な答えを持っていないとしても、最も高い塔は完全に除外されなければなりません。 

単純な方向スキャンの微妙な失敗例は、スイープ中に最初に遭遇した高い塔が最も近い塔ではない場合です。 たとえば、高さ`[1, 100, 2, 3, 4]`インデックス 0 の場合: 右にスキャンすると距離 1 で 100 にヒットします。これは正しいですが、インデックス 2 の場合、右にスキャンすると 3 にヒットし、次に 4 にヒットし、その後何もヒットしません。一方で、最も近い高さの方が実際には距離 1 で 3 になります。正しいソリューションでは、常に両側を同時に比較する必要があります。 

## アプローチ

 ブルートフォースのアイデアは簡単です。各インデックス i について、H[j] > H[i] となるインデックス j が見つかるまで外側に拡張し、表示される最小距離を維持します。 これは定義に直接従うため機能し、考えられるすべての候補が距離の増加順にチェックされるため、正確さが即座にわかります。 

問題はコストです。 次のような単調減少配列では`[N, N-1, ..., 1]`、左側にある唯一の背の高い要素を見つけるには、すべての要素が配列のほぼ全体をスキャンする必要があります。 これにより、平均して要素ごとにおよそ N/2 の作業が発生し、合計で O(N^2) の操作が行われます。 

重要な観察は、1D 配列の「最も近い大きい要素」には構造があるということです。各位置について、答えは左側の最も近い大きい要素と右側の最も近い大きい要素にのみ依存します。 同じ側​​に近い要素が存在すると、より大きな要素は決して意味を持ちません。 

これにより、問題は古典的な単調スタック シナリオに変換されます。 各位置について、線形時間で左右に最も近い厳密に大きい要素を計算できます。 これら 2 つの候補がわかれば、各位置の答えは単にそれらまでの距離が小さい方になります。

 | --- | --- | --- | --- |
 | ブルートフォース | O(N^2) | お(1) | 遅すぎる |
 | 単調スタック | O(N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 この問題は、減少する高さを維持するスタックを使用して、両側で最も近い大きい要素を計算することで解決します。 

1. 配列を計算します`left[i]`i から最も近いインデックス j < i までの距離を H[j] > H[i] で表します。 高さが厳密に降順になっているインデックスのスタックを維持しながら、左から右にスキャンします。 i を処理するときは、最上部の高さが H[i] より大きくなるまでスタックからポップします。これは、「左側の最も大きい」ものだけが有効であるためです。 最も近い有効な値は、ポップ後の現在のスタックのトップ、またはスタックが空になった場合は存在しません。 
2. 配列を計算します`right[i]`同様に、同じ単調スタックの考え方で右から左にスキャンします。 これにより、インデックス距離に関して右側に最も近い大きい要素が得られます。 
3. 各インデックス i について、それが最も高い要素である場合、それを無視します。`left[i]`そして`right[i]`定義上無関係です。 
4. 1 つおきの i に対して、次の最小値を取ります。`left[i]`そして`right[i]`そしてそれを答えに追加します。 一方の側が存在しない場合は、その距離を無限大として扱い、もう一方の側が選択されます。 
5. 合計を出力します。 

それが機能する理由は、スタックによって維持される不変条件に基づいています。 スキャンのどの時点でも、スタックには厳密に減少する一連の高さのインデックスが含まれています。 これにより、最も近い大きい要素を検索するときに、それより小さいまたは等しい高さは無関係であり、安全に削除できることが保証されます。これは、現在または将来の要素に対する有効な答えとして機能しないためです。 H[i] より大きい最初の残りの要素は、必然的にその側で最も近いそのような要素になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    h = list(map(int, input().split()))
    
    left = [10**18] * n
    right = [10**18] * n
    
    stack = []
    
    # nearest greater to left
    for i in range(n):
        while stack and h[stack[-1]] <= h[i]:
            stack.pop()
        if stack:
            left[i] = i - stack[-1]
        stack.append(i)
    
    stack.clear()
    
    # nearest greater to right
    for i in range(n - 1, -1, -1):
        while stack and h[stack[-1]] <= h[i]:
            stack.pop()
        if stack:
            right[i] = stack[-1] - i
        stack.append(i)
    
    mx = max(range(n), key=lambda i: h[i])
    
    ans = 0
    for i in range(n):
        if i == mx:
            continue
        ans += min(left[i], right[i])
    
    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、計算が 2 つの単調なスタック パスに分割されます。 比較`<=`高さは異なるため、これは重要ですが、一貫性を保つことで、仮定が緩和された場合でも正確さが保証されます。 距離は大きなセンチネル値として保存されるため、欠落している辺が誤って最小値に影響を与えることはありません。 

最大要素のインデックスは一度計算され、最終的な合計から除外されます。 これにより、スタック ロジック内の特殊なケースが回避され、単調な構造が均一に保たれます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべての高さが厳密に減少している場合です。 のような入力の場合`[5, 4, 3, 2, 1]`、すべての要素の最も近い大きい値が常に左側にあります。 スタックは正しく折りたたまれ、各要素は以前に確認されたより大きな値のみを参照し、最初の要素を除くすべての要素について距離 1、1、1、1 が生成されます。 単純な右スキャンのみのアプローチは、右側に大きな要素が存在しないため、ここでは完全に失敗します。 

もう 1 つのエッジ ケースは、次のような厳密に増加するシーケンスです。`[1, 2, 3, 4, 5]`。 ここでは、すべての要素に最も近い大きい値が常に右側にあります。 単調スタックでは、各要素がすぐ次の要素と一致することが保証され、より近い候補をスキップすることはありません。 両側を比較しない単純な「一方向で最初に大きいものを見つける」アプローチでは、初期の要素の距離が誤って過大評価されてしまいます。 

3 番目のエッジ ケースは、次のような中央のピークです。`[1, 5, 2, 4, 3]`。 各中間要素には両側に競合する候補があり、同時追跡のみが正しい最小選択を保証します。 左右の配列は独立して計算され、最後にのみマージされるため、アルゴリズムはこれを自然に処理します。
