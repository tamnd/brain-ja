 ## 解決策
 ## 問題の理解

 グリッドは黒いセルによって部分的に水平セグメントと垂直セグメントに分割されています。 すべての白セルは、正確に 1 つの最大水平セグメントと正確に 1 つの最大垂直セグメントに属します。 このような各セグメントには、入力で指定された所定の合計があります。 有効な割り当てでは、各白いセルに 1 から 9 の整数が割り当てられ、すべての水平セグメントの合計がその必要な値と正確に一致し、すべての垂直セグメントの合計もその必要な値と正確に一致します。 

提供された塗りつぶされたグリッドと正確に一致する必要はありません。 代わりに、各白セルには推奨値が付属しており、別の値を選択すると絶対差に等しいペナルティが発生します。 目標は、すべてのセルにわたる合計ペナルティを最小限に抑えながら、すべてのセグメントの合計を満たす有効な割り当てを見つけることです。 

境界は十分に小さいため、グリッドのセル数は最大 16 x 16、つまり変数の数は最大 256 になります。 各セルは、正確に 1 つの水平制約と 1 つの垂直制約に関与するため、構造は非常に規則的です。すべての変数は、グリッドの 2 つの異なるパーティションからの 2 つの独立した線形方程式によって同時に制約されます。 

単純な検索では、すべての白いセルに値 1 ～ 9 を割り当て、すべての制約をチェックします。 制約を無視したとしても、9^256 通りの可能性があり、これは完全に実行不可能です。 各割り当ては行のようなセグメント制約と列のようなセグメント制約の両方に影響を与えるため、ローカル バックトラッキングでも爆発する可能性があります。 

貪欲な戦略には、より微妙な失敗モードが現れます。 たとえば、水平セグメントの合計を一致させて各水平セグメントを独立して満たそうとし、その後垂直方向に調整すると、垂直方向の制約がセグメント間の結合に依存するため、実現可能性が損なわれます。 小さな例でこれを説明します。 

両方のセルが白で、1 つの水平セグメントの合計が 10、両方の垂直セグメントの合計が 5 である 2 × 2 グリッドを考えます。 (5,5) などの貪欲な水平割り当てはすぐに垂直制約に違反しますが、1 つのセルを調整すると他の場所でも違反が強制されます。 結合はグローバルであり、行や列に対してローカルではありません。 

主な問題点は、各セルが 2 つの合計制約間で共有されることです。これにより、構造が境界と最適化目標を持つ 2 部線形方程式系になります。 

## アプローチ

 中心的な観察は、グリッドが 2 部グラフを定義しているということです。 1 つのパーティションは水平セグメントで構成され、もう 1 つのパーティションは垂直セグメントで構成されます。 すべての白いセルは、水平セグメントと垂直セグメントを接続するエッジです。 セルに値を割り当てることは、そのエッジに 1 から 9 までの整数フローを割り当てることと同じです。各水平セグメントでは、入射エッジ値の合計が所定の制約に等しいことが必要であり、各垂直セグメントでも同じ種類の要件が課されます。 

これにより、問題はノード要求と有界エッジ変数を備えたフローのようなシステムに変換されます。 目的関数はエッジ間で分離可能です。各エッジには優先値 T と、T からの絶対偏差に等しいコストがあります。 

この構造を総当たり的に解釈すると、1 ～ 9 のエッジ値のすべての割り当てが試行され、すべてのノードの合計が一致するかどうかがチェックされます。 これは、各ノード制約が複数のエッジを結合し、分岐係数がセル数で指数関数的に増加するため、失敗します。

重要な洞察は、各エッジをフロー ネットワーク内の変数として独立して扱い、最小コストのフローを通じて制約を強制することです。 唯一の問題は、エッジ コストがフロー内で線形ではなく、エッジの最終的な整数値に依存することです。 これは、各エッジ変数を 0 から 9 までの一連の単位増分に変換することによって解決されます。各増分には、絶対値関数から得られる限界コストが含まれます。 これにより、フロー グラフ内の各エッジがユニット容量エッジのチェーンに変わります。 

線形化されると、問題は要求を伴う標準的な最小コスト循環になります。水平ノードは必要な合計を供給し、垂直ノードはそれらを要求し、エッジは有界整数フローを運びます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | ユニット拡張時の最小コストフロー | O(E^2 log V) | お(え) | 承認済み |

 ## アルゴリズムのチュートリアル

 すべての水平セグメントと垂直セグメントがノードとなる 2 部構成のフロー ネットワークを構築します。 各白いセルは、対応する水平ノードと垂直ノードの間のエッジになります。 

1. すべての水平セグメントを特定してそれぞれにノードを割り当て、同様に垂直セグメントにもノードを割り当てます。 このステップでは、グリッド構造を位置ではなく制約のグラフに変換し、依存関係の構造を明示します。 
2. すべての白いセルについて、その水平セグメント ノードと垂直セグメント ノードの間にエッジを作成します。 このエッジは、そのセルの決定変数を表します。 
3. 各エッジについて、変数を 0 ～ 9 の整数 x としてモデル化します。コストは |x − T| です。ここで、T はそのセルに指定されたターゲット値です。 
4. 各エッジを 9 つの単位容量エッジのシーケンスに置き換えます。k 単位を取ることは、x = k に設定することに対応します。 流量が増加するにつれて総コストが正しく累積されるように、絶対値関数の差を使用して増分コストを定義します。 
5. ノードの要求を設定します。 各水平ノードは、そのセグメントの合計制約と等しいフローを送信する必要があります。 各垂直ノードは、必要な合計を正確に受け取る必要があります。 これにより、問題はエッジ フローの下限と上限を持つ循環に変換されます。 
6. ノードの要求のバランスをとった後、スーパー ソースからスーパー シンクまでの最小コスト フロー アルゴリズムを実行します。 このアルゴリズムは、ポテンシャルを使用して残差グラフ内の最短の増強パスを繰り返し送信し、非負の削減コストを維持します。 
7. 合計フローがすべての要求を満たさない場合、インスタンスは実行不可能であり、IMPOSSIBLE と出力されます。 それ以外の場合、累積コストは固定の加法定数までの最適な近さスコアを与えますが、解に依存しないため無関係です。 

### なぜ効果があるのか

 各白いセルは、合計制約によって導入される結合を除き、独立してコストに寄与します。 この変換により、各非線形エッジ コストがユニット フロー全体にわたる凸の区分線形関数に変換され、最小コスト フローの下で最適性が維持されます。 ノード制約により、グローバルに一貫した割り当てのみが考慮されることが保証され、フロー保存により、各セグメントの合計が正確に満たされることが保証されます。 したがって、最適なフローは有効なカクロー割り当てと 1 対 1 に対応し、実現可能な最短コストの循環によって全体の偏差が最小限に抑えられます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**18

class MinCostFlow:
    def __init__(self, n):
        self.n = n
        self.adj = [[] for _ in range(n)]

    def add_edge(self, u, v, cap, cost):
        self.adj[u].append([v, cap, cost, len(self.adj[v])])
        self.adj[v].append([u, 0, -cost, len(self.adj[u]) - 1])

    def min_cost_flow(self, s, t, maxf):
        n = self.n
        res = 0
        h = [0] * n
        prevv = [0] * n
        preve = [0] * n

        while maxf > 0:
            dist = [INF] * n
            dist[s] = 0
            inq = [False] * n
            from heapq import heappush, heappop
            pq = [(0, s)]

            while pq:
                d, v = heappop(pq)
                if dist[v] < d:
                    continue
                for i, (to, cap, cost, rev) in enumerate(self.adj[v]):
                    if cap > 0 and dist[to] > dist[v] + cost + h[v] - h[to]:
                        dist[to] = dist[v] + cost + h[v] - h[to]
                        prevv[to] = v
                        preve[to] = i
                        heappush(pq, (dist[to], to))

            if dist[t] == INF:
                return None, None

            for v in range(n):
                if dist[v] < INF:
                    h[v] += dist[v]

            d = maxf
            v = t
            while v != s:
                u = prevv[v]
                e = self.adj[u][preve[v]]
                d = min(d, e[1])
                v = u

            maxf -= d
            res += d * h[t]

            v = t
            while v != s:
                u = prevv[v]
                e = self.adj[u][preve[v]]
                e[1] -= d
                self.adj[v][e[3]][1] += d
                v = u

        return res, True

def solve():
    M, N, S = map(int, input().split())
    grid = [input().strip() for _ in range(M)]

    hor_id = [[-1] * N for _ in range(M)]
    ver_id = [[-1] * N for _ in range(M)]

    hor_cnt = 0
    ver_cnt = 0

    for i in range(M):
        j = 0
        while j < N:
            if grid[i][j] == '0':
                j += 1
                continue
            k = j
            while k < N and grid[i][k] != '0':
                k += 1
            for x in range(j, k):
                hor_id[i][x] = hor_cnt
            hor_cnt += 1
            j = k

    for j in range(N):
        i = 0
        while i < M:
            if grid[i][j] == '0':
                i += 1
                continue
            k = i
            while k < M and grid[k][j] != '0':
                k += 1
            for x in range(i, k):
                ver_id[x][j] = ver_cnt
            ver_cnt += 1
            i = k

    hsum = [0] * hor_cnt
    vsum = [0] * ver_cnt

    for _ in range(S):
        c, i, j, s = input().split()
        i = int(i) - 1
        j = int(j) - 1
        s = int(s)
        if c == 'H':
            hsum[hor_id[i][j]] = s
        else:
            vsum[ver_id[i][j]] = s

    cells = []
    for i in range(M):
        for j in range(N):
            if grid[i][j] != '0':
                cells.append((i, j))

    H = hor_cnt
    V = ver_cnt
    Snode = H + V
    Tnode = Snode + 1

    mcf = MinCostFlow(Tnode + 1)

    total = 0

    def add_edge(u, v, cap):
        mcf.add_edge(u, v, cap, 0)

    # demands
    for i in range(H):
        mcf.add_edge(Snode, i, hsum[i], 0)
        total += hsum[i]
    for j in range(V):
        mcf.add_edge(H + j, Tnode, vsum[j], 0)

    # cell edges expanded 1..9
    for i in range(M):
        for j in range(N):
            if grid[i][j] == '0':
                continue
            hi = hor_id[i][j]
            vi = ver_id[i][j]
            T = int(grid[i][j])

            for k in range(1, 10):
                cost = abs(k - T) - abs(k - 1 - T)
                mcf.add_edge(hi, H + vi, 1, cost)

    flow, ok = mcf.min_cost_flow(Snode, Tnode, total)
    if flow is None:
        print("IMPOSSIBLE")
    else:
        print(flow)

if __name__ == "__main__":
    solve()
```グリッド解析ステップでは、黒いセルがなくなるまでスキャンして水平セグメントと垂直セグメントを再構成します。 各セルには、その 2 つのセグメントの識別子が割り当てられます。 次に、フロー ネットワークは、各水平ノードが必要な合計を正確に出力し、各垂直ノードが必要な合計を正確に受け取るように強制します。 

各セルは 9 つの単位エッジに拡張され、フロー値が選択した桁に直接対応します。 コスト変換により、最適性に影響を与えない一定のシフトまで、累積フローが絶対差の目標を正確に再現することが保証されます。 

最小コスト フローは小さなグラフで実行され、需要を満たす循環によって実現可能性が正しくチェックされます。

 ## 特殊なケース

 重要なエッジ ケースは、すべての桁が極端になるように強制する合計制約がセグメントにある場合です。 このような場合、フローは常に 1 または 9 エッジを飽和させ、中間単位エッジのコストが高くなるため、最小コスト フローは自然に境界値を選択します。 

もう 1 つの特殊なケースは、水平合計と垂直合計の間のパリティのような不均衡によって純粋に引き起こされる実行不可能性です。 たとえば、水平方向の需要の合計が垂直方向の需要の合計と異なる場合、フローは需要と供給のバランスをとることができず、アルゴリズムは割り当てを試行する前にすぐに失敗します。
