 ## 解決策
 ## 問題の理解

 私たちには、ペアに配置された 2 つの軍隊間の現在の「勢力バランス」を表す一連の数字が与えられます。 各位置は整数値に寄与し、その値は配列全体にわたって均一に時間の経過とともに変化します。 

2 つの操作がオンラインで行われます。 1 回の操作で配列内のすべての要素に固定値を追加し、シーケンス全体を上または下にシフトします。 もう 1 つの操作では、配列の特定のセグメントを要求し、その中にある考えられるすべての連続したサブセグメントを評価する必要があります。 このようなサブセグメントごとに合計を計算し、それらの合計の最大値を取得します。 この最大値が負の場合、答えはゼロにクランプされます。 

したがって、各クエリは基本的に、制限された間隔内でサブ配列の最大合計を求めることになりますが、配列がクエリ間でグローバルにシフトされるというさらなる複雑さがあります。 

制約は最大 30 万の要素とクエリに達するため、クエリごとにセグメント情報を最初から再計算するソリューションは失敗します。 単純な最大部分配列の計算はクエリごとに線形であり、すでに 2 次の最悪のケースが得られます。 たとえ$O(N \log N)$セグメント ツリー ソリューションは、グローバル範囲の更新を効率的に処理できるように慎重に設計する必要があります。 

クエリされた間隔内のすべての値が負の場合、微妙なエッジ ケースが発生します。 この場合、部分配列の最大合計は負になりますが、問題の定義により出力は強制的にゼロになります。 

たとえば、配列を考えてみましょう。$[-5, -2, -7]$そして全範囲に対するクエリ。 すべての部分配列の合計は負であるため、正しい答えは次のとおりです。$0$。 サブ配列の合計の最大値を直接返す不用意な実装では、次のような出力が出力されます。$-2$、これはクランプが必要なため不正確です。 

グローバル追加によって別の問題が発生します。 定数を追加すると$X$すべての要素、すべてのプレフィックスの合計、したがってすべてのサブ配列の合計は構造化された方法でシフトするため、すべてのノードを個別に更新することは避けなければなりません。 

## アプローチ

 ブルート フォース ソリューションでは、各クエリを独立して処理します。 評価クエリの場合$[L, R]$、その範囲内のすべての部分配列を列挙し、それらの合計を計算します。 これにはすでに費用がかかります$O(N^2)$最悪の場合、クエリごとに$O((R-L+1)^2)$サブ配列と各合計は次のように計算できます。$O(1)$プレフィックス合計付き。 まで$3 \times 10^5$クエリ、これは完全に不可能です。 

これを Kadane のクエリごとのアルゴリズムに改善しても、依然としてコストがかかります$O(N)$すべての範囲の最大部分配列合計を再計算する必要があるため、クエリごとに。 主な障害は、更新が配列全体に均一に影響を与えるため、単純なモデルでは再計算が避けられないことです。 

重要な観察は、クエリが範囲にわたる古典的な最大サブ配列合計を要求していること、そしてこの構造がまさにセグメント ツリーが維持できるものであるということです。 各セグメントは、合計合計、最良のプレフィックス合計、最良のサフィックス合計、および最良のサブ配列合計の 2 つの半分をマージするのに十分な情報を格納できます。 

難しいのは、グローバルな追加操作です。 ただし、定数を追加すると、$X$セグメント内のすべての要素は、4 つの値すべてに予測可能な方法で影響を与えます。 合計額は次のように増加します$X \cdot len$、プレフィックスとサフィックスの合計もセグメントの長さに応じて線形にシフトし、最良の部分配列の合計は によって増加します。$X \cdot len$また、すべての候補部分配列はその長さに比例して同じオフセットを取得するためです。 

これを効率的にサポートするために、遅延伝播を備えたセグメント ツリーを使用します。 各ノードは 4 つの標準値を維持し、遅延タグは保留中のグローバル追加を保存します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(N^2 Q)$|$O(1)$| 遅すぎる |
 | 遅延伝播を使用したセグメント ツリー |$O((N+Q)\log N)$|$O(N)$| 承認済み |

 ## アルゴリズムのチュートリアル

 配列上にセグメント ツリーを構築します。各ノードは間隔を表し、間隔の合計、最大プレフィックス合計、最大サフィックス合計、および最大サブ配列合計の 4 つの量を格納します。 

1. リーフ ノードを配列値から直接初期化します。 各リーフには、合計、接頭辞、接尾辞、および最良の値がすべて値自体と同じになります。 1 つの要素には可能なサブ配列が 1 つしかないため、これは基本的なケースです。 
2. 2 つの子をマージして内部ノードを構築します。 左右のセグメントを結合する場合、合計は両方の合計の合計になります。 プレフィックスは、左プレフィックスと左合計と右プレフィックスの間の最大値です。 接尾辞は対称です。 最良のサブ配列は、左ベスト、右ベスト、および左サフィックスと右プレフィックスの最大値です。 これが機能するのは、最適な部分配列が完全に片側にあるか、境界を越えているためです。 
3. 各ノードについて、そのセグメント内のすべての要素への保留中の追加を表す遅延値も維持します。 これにより、更新を延期することができます。 
4.加算を適用する場合$X$ノードカバー長まで$len$、合計を増やします。$X \cdot len$。 プレフィックス、サフィックス、および最適なサブ配列はすべて次のように増加します。$X \cdot len$同様に、セグメント内のすべてのサブ配列は、セグメント表現全体で一貫して集計された長さの寄与と同じ定数倍だけ増加するためです。 
5. ツリーの下に伝播するときに、遅延値を子にプッシュし、親でそれをクリアします。 これにより、部分的な更新とクエリを混在させる場合の正確性が保証されます。 
6. STRENGTH 操作の場合、セグメント ツリー範囲全体に範囲更新を遅延的に適用します。 
7. ASSESS 操作の場合、セグメント ツリーにクエリを実行します。$[L, R]$、マージ操作を使用して結果を結合し、返します。$\max(0, best)$。 

機能する理由: すべてのノードは、すべての保留中の遅延更新の下で、そのセグメントの正しい概要を常に表します。 マージ操作は、セグメント境界を越えるサブ配列に関する必要な情報をすべて保持するという意味で結合的です。 遅延伝播では、論理的に割り当てられているすべての更新を適用した後、各ノードに格納されている値がそのセグメントに正確に対応するという不変条件が保持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

NEG_INF = -10**30

class Node:
    __slots__ = ("sum", "pref", "suf", "best", "lazy", "len")
    def __init__(self, s=0, p=0, su=0, b=0, lz=0, length=1):
        self.sum = s
        self.pref = p
        self.suf = su
        self.best = b
        self.lazy = lz
        self.len = length

def merge(left, right):
    res = Node()
    res.len = left.len + right.len
    res.sum = left.sum + right.sum
    res.pref = max(left.pref, left.sum + right.pref)
    res.suf = max(right.suf, right.sum + left.suf)
    res.best = max(left.best, right.best, left.suf + right.pref)
    return res

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.size = 4 * self.n
        self.tree = [Node(length=1) for _ in range(self.size)]
        self.build(1, 0, self.n - 1, arr)

    def apply(self, idx, val):
        node = self.tree[idx]
        node.sum += val * node.len
        node.pref += val * node.len
        node.suf += val * node.len
        node.best += val * node.len
        node.lazy += val

    def push(self, idx):
        lazy = self.tree[idx].lazy
        if lazy != 0:
            self.apply(idx * 2, lazy)
            self.apply(idx * 2 + 1, lazy)
            self.tree[idx].lazy = 0

    def build(self, idx, l, r, arr):
        if l == r:
            v = arr[l]
            self.tree[idx] = Node(v, v, v, v, 0, 1)
            return
        m = (l + r) // 2
        self.build(idx * 2, l, m, arr)
        self.build(idx * 2 + 1, m + 1, r, arr)
        self.tree[idx] = merge(self.tree[idx * 2], self.tree[idx * 2 + 1])

    def update(self, idx, l, r, ql, qr, val):
        if ql <= l and r <= qr:
            self.apply(idx, val)
            return
        self.push(idx)
        m = (l + r) // 2
        if ql <= m:
            self.update(idx * 2, l, m, ql, qr, val)
        if qr > m:
            self.update(idx * 2 + 1, m + 1, r, ql, qr, val)
        self.tree[idx] = merge(self.tree[idx * 2], self.tree[idx * 2 + 1])

    def query(self, idx, l, r, ql, qr):
        if ql <= l and r <= qr:
            return self.tree[idx]
        self.push(idx)
        m = (l + r) // 2
        if qr <= m:
            return self.query(idx * 2, l, m, ql, qr)
        if ql > m:
            return self.query(idx * 2 + 1, m + 1, r, ql, qr)
        left = self.query(idx * 2, l, m, ql, qr)
        right = self.query(idx * 2 + 1, m + 1, r, ql, qr)
        return merge(left, right)

def solve():
    n, q = map(int, input().split())
    arr = list(map(int, input().split()))
    st = SegTree(arr)

    out = []
    for _ in range(q):
        parts = input().split()
        if parts[0] == "STRENGTH":
            x = int(parts[1])
            st.update(1, 0, n - 1, 0, n - 1, x)
        else:
            l = int(parts[1]) - 1
            r = int(parts[2]) - 1
            res = st.query(1, 0, n - 1, l, r)
            out.append(str(max(0, res.best)))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```セグメント ツリーには完全な間隔の要約が格納されるため、クエリは対数のノードを結合するだけで済みます。 遅延伝播により、グローバルな追加ではすべての要素に明示的に触れる必要がなく、必要に応じてセグメントにマークを付けて値をプッシュするだけです。 

実装の微妙な詳細は、遅延追加中に 4 つの格納された値すべてを一貫して更新する必要があることです。 同じデルタによるプレフィックス、サフィックス、またはベストの更新を忘れると、後のマージでは各ノードが完全に正規化されていることが前提となるため、正確性が損なわれます。 

## 実用的な例

 サンプル入力を使用して、更新とクエリがどのように相互作用するかを説明します。 

開始配列は$[1, -2, 3, 4]$。 

各操作の後:

 | ステップ | 操作 | 配列状態 | クエリ結果 |
 | --- | --- | --- | --- |
 | 1 | 評価 1 4 | [1、-2、3、4] | 6 |
 | 2 | 評価 1 2 | [1、-2] | 1 |
 | 3 | 評価 2 2 | [-2] | 0 |
 | 4 | 強さ2 | [3、0、5、6] | - |
 | 5 | 評価 1 4 | [3、0、5、6] | 14 |
 | 6 | 評価 1 2 | [3, 0] | 3 |

 トレースは、どのセグメントが最適であるかの構造ロジックを変更せずに、一様な加算によって将来のすべての部分配列の合計がどのようにシフトされるかを示しています。 

2 番目の小さな例は、否定性の処理を強調しています。 考慮する$[-3, -1, -4]$。 任意の範囲にわたるクエリは常に負の最良の部分配列合計を生成するため、すべての出力はゼロにクランプされます。 これにより、最終的な max 操作の必要性が確認されます。

 ## 特殊なケース

 負の値を持つ単一要素間隔は、クランプ ルールを直接テストします。 配列が$[-5]$の場合、部分配列の合計のみが負であるため、正解はゼロです。 セグメント ツリーは次のように最適に保存します。$-5$ですが、クエリ レイヤーはそれをゼロに変換し、正確さを保ちます。 

フルレンジ STRENGTH 操作は、遅延伝播がすべてのノードを正しく更新するかどうかをテストします。 追加すると$+3$に$[1, -2, 3]$、すべてのノードは一貫したシフトを反映する必要があります。 そうしないと、マージによって矛盾した状態が結合され、不正確な最大値が生成されます。 

更新とクエリを交互に繰り返すことで、保留中の遅延値が適切なタイミングでプッシュされるかどうかをテストします。 最初にそのレイジー値をプッシュせずにノードがクエリされた場合、そのノードに格納されている最良の値は古くなり、答えは真のサブ配列構造から逸脱します。
