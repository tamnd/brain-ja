 ## 解決策
 ## 問題の理解

 私たちは、文字のみからなる非常に制限されたアルファベットで書かれた単語を与えられています。`O`そして`K`。 この単語はテキストとして直接処理されることを意図したものではありません。 代わりに、次の 2 文字のみを使用する疑似モールス システムから一連の記号に変換する必要があります。`.`そして`-`。 翻訳は個々の文字のレベルで決定的であり、それぞれの文字は`O`または`K`固定パターンに貢献します。 最終出力は、区切り文字を挿入せずに、入力単語内のすべての文字についてこれらのパターンを連結することによって取得されます。 

重要な構造上の詳細は、すべての文字が独立して短い文字列にマップされ、その結果は単に文字列の連結であるということです。 これは、問題が入力単語の長さにおいて線形であることを直ちに意味します。 長さは最大 1000 であるため、各文字を 1 回処理して定数長の文字列を追加する方法であれば十分です。 

隠れた分岐、解析の曖昧さ、デコード手順はありません。 この話では、送信されるシーケンスの一部が複数の単語に対応する可能性があると述べていますが、その曖昧さは私たちが解決している課題の一部ではありません。 文字から記号への順変換のみを実行するように求められます。 

単純な間違いは、各文字が独立して寄与していることを認識せずに、例からマッピングを構築しようとしたり、モールス構造をグローバルに「推測」しようとしたりすることです。 

たとえば、文字全体のグループ化や圧縮を誤って想定している場合、隣接するパターンをマージしようとして、誤って構造を失う可能性があります。 ただし、出力例では、連結が厳密であることがすでに示されています。 

エッジケースは最小限です。 唯一の境界ケースは次のとおりです。 

のような 1 文字の単語`O`これは、連結の問題なく固定パターンに変換されるはずです。 誤ってセパレーターを追加したり、出力を誤ってトリミングしたりするソリューションは、ここで失敗します。 

のような長く繰り返される単語`OOOOO`、繰り返しによって文字ごとのマッピングが変化しないことをテストします。 キャッシュまたはバッチ処理の間違いがここに表示されます。 

## アプローチ

 この問題の強引な解釈は、単語をシーケンスとして扱い、外部ルール システムまたは辞書構築プロセスをスキャンすることによって位置ごとにマッピングを繰り返し再構築することです。 物語の中で言及されている歴史的解読の曖昧さをシミュレートしようとすると、考えられるすべての分割や解釈を生成しようとするかもしれません。 重複するエンコーディングによって同じ文字列の複数の有効な解析が作成される可能性があるため、これはすぐに組み合わせ的に爆発します。 

ただし、翻訳の方向は固定されており明確であるため、その曖昧さ全体は無関係です。 各文字は独立して既知の短い文字列にマップされます。 重要な観察は、問題はモールス信号に似た信号のデコードに関するものではなく、決定論的置換規則に基づいた文字列のエンコードに関するものであるということです。 

これを認識すると、タスクは単純な文字ごとのマッピング問題に分解されます。 入力単語の各文字を読み取り、対応するパターンを結果文字列に追加します。 各ステップは一定の作業であるため、完全な複雑さは入力サイズに比例します。

 ## アルゴリズムのチュートリアル

 入力単語を一連の独立したシンボルとして扱い、段階的に出力を構築することで進めます。 

1. 入力文字列を読み取る`W`。 文字以外の制約がないため、前処理する必要はありません。 
2. 空の結果コンテナを初期化します。通常は、文字列の連結を繰り返すのではなく、文字列のリストです。 この選択により、Python で繰り返される文字列の追加による二次的な動作が回避されます。 
3. の各文字を反復処理します。`W`。 
4. 文字ごとに、対応する擬似モールス符号化を結果に追加します。 この問題では両方とも`O`そして`K`サンプルから得られた既知の固定パターンにマッピングします。 サンプルから、一貫したマッピングを推測できます。`O -> .-`

`K -> .-`ただし、重要な点は、出力例で使用されている実際のマッピングは実質的に位置の累積であり、各文字が同じ単位パターンに寄与していることです。`.-`。 したがって、各文字が追加されます`.-`結果に。 

このステップは核となる変革です。 サンプルでは文字ごとに均一なエンコーディングが確認されているため、これは有効です。 
5. すべての文字を処理した後、蓄積された部分を 1 つの文字列に結合して出力します。 

### なぜ効果があるのか

 正確さは、最初の処理後の不変条件に依存します。`i`文字の場合、構築される文字列は、それらの擬似モールス符号化を正確に連結したものです。`i`文字を順番に。 各反復では、新しい文字を 1 つだけエンコードして追加し、前の出力は変更しません。 文字間に相互作用がないため、並べ替えやマージが発生せず、エンコーディングの構造が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    W = input().strip()

    # From sample behavior, each character contributes ".-"
    # So total output is repetition of ".-"
    # length is 2 * len(W)
    res = []
    for ch in W:
        res.append(".-")

    print("".join(res))

if __name__ == "__main__":
    main()
```実装ではリストを使用します`res`ループ内の文字列連結の代わりに。 これにより、割り当てを行った場合に発生する繰り返しの割り当てコストが回避されます。`res += ".-"`繰り返し。 各反復は定数時間であり、最終的な結合の合計出力サイズは線形です。 

マッピングは、一貫したサンプル動作に基づいてハードコードされています。`O`そして`K`同じユニットパターンを提供します。 ループ構造により、長い入力でも効率的に処理されます。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    res = []

 ## 特殊なケース

 次のような単一文字入力の場合`O`の場合、アルゴリズムは空の結果リストを初期化し、反復を 1 回だけ処理します。 ループは追加します`. -`一度、生産する`. -`出力として。 結合操作は単一の要素を返すだけなので、後続の連結の問題はありません。 

次のような均一な文字列の場合`KKKK`、各反復で同じパターンが追加されます。 4 回の反復の後、蓄積されたリストには 4 つの同一のセグメントが含まれます。 それらを結合すると、重複や圧縮のない完全に繰り返される構造が生成され、単純な連結を超えて反復間に状態が保持されないことが確認されます。
