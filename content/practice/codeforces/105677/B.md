 ## 解決策
 ## 問題の理解

 私たちにはさまざまなギフトが与えられ、それぞれに「理想的な」配達日が指定されています。 すべてのギフトについて、実際の配達日を選択する必要があります。 選択した日は、理想的な日よりも早くなることはできませんが、遅くなることは可能です。 

問題は、Hermes が合計で最大 K 日しか利用できないことです。 それらの選択された日ごとに、彼は任意の数の贈り物を届けることができます。 したがって、タスクは単にギフトごとに 1 日を割り当てるだけではなく、最大 K 個の配達日を選択し、ギフトをグループ化することです。 

ギフトが理想的な日が d であるのに t 日に配達された場合、(t − d)² のペナルティが発生します。 目標は、合計ペナルティを最小限に抑えながら、t ≥ d を考慮して、選択した最大 K 個の配送日の 1 つに各ギフトを割り当てることです。 

問題の構造は、グループ化が個々の割り当てよりも重要であることを示唆しています。 お届け日が決まったら、各ギフトはその中から最適な日を選ぶだけですが、本当に難しいのは曜日とグループの選択です。 

制約は特定の点で重要です。 N が最大 5000、K が最大 20 であるため、広い範囲から K 日を選択するだけでも組み合わせ的に膨大になるため、配達日のすべてのサブセットを調査しようとするソリューションは不可能です。 同様に、パーティションに対するキュービックまたはそれより悪いアプローチは遅すぎます。 特に遷移が O(1) の場合、O(N²K) 動的プログラミング ソリューションが許容されます。 

微妙な点は、配達日数が指定された di 値内にあることに制限されないことです。 素朴なアプローチでは、既存の理想的な日のみを使用すると仮定するかもしれませんが、それは明言されていません。 ただし、後で説明するように、最適な構造では、ソート後に各グループの配達日がそのグループの境界要素と必然的に一致します。 

よくある落とし穴は、グループ化の制約を考慮せずに、各ギフトがその日または近くの選択された日に個別に切り上げられると考えていることです。 たとえば、すべてのギフトの di 値が近いものの、K が小さい場合、グループ化の決定により、配達日の共有が強制され、ペナルティが大幅に変わる可能性があります。 

## アプローチ

 ブルートフォース戦略では、各ギフトを最大 K 個の配達日の 1 つに割り当て、配達日自体も選択しようとします。 候補日が固定されていると仮定した場合でも、各ギフトには K 個の選択肢があり、K^N 個の割り当てが与えられます。 これは実現不可能です。 

もう少し構造化されたブルートフォースは、di でソートした後、ギフトを最大 K 個のグループに分割するあらゆる方法を試みます。 パーティションごとに、グループごとに最適な配達日を計算します。 これは N 個の要素を超えるスターリング数スタイルの増加になるため、パーティションのカウントでも指数関数的になります。 

重要な観察は、ギフトを理想的な日によって分類すると、最適なグループ化ではその順序が尊重されるということです。 グループにインターリーブされた値が含まれている場合、凸コストの下では遅い配信日が早い配信日を支配するため、スワップによってペナルティが軽減されるだけです。 

ソート後、各グループは連続したセグメントになります。 次に、固定セグメントについて考えてみましょう。 グループに値 d_l から d_r が含まれており、それらすべての配達日 t ≥ を選択するとします。つまり、 t ≥ d_r になります。 セグメントのコストは合計 (t − d_i)² です。 これを展開すると、制約のない最小値がセグメント内の d_i 値の平均である t の凸関数が表示されます。 しかし、すべての d_i ≤ d_r であるため、その平均も ≤ d_r です。つまり、制約 t ≥ d_r により、最適値は t = d_r に正確に位置することが強制されます。 

これにより、すべてが単純化されます。各セグメントの最適な配送日は、その最大の要素にすぎません。 問題は、ソートされた配列から最大 K 個のセグメントを選択することになります。この場合、各セグメントのコストは、その正しいエンドポイントによって完全に決定されます。 

この構造は、接頭辞を介した動的プログラミングに直接つながり、最後のセグメント境界をすべて試行します。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース パーティションと割り当て | 指数 | O(N) | 遅すぎる |
 | K 個のセグメントを持つソートされた配列に対する DP | O(N²K) | O(NK) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのギフトを理想的な配達日順に並べ替えます。 これにより、コストを増加させることなく交差割り当てを常に再配置できるため、一般性を失うことなく、最適なグループ化が連続範囲で動作すると想定できます。 
2. 値とその二乗の両方についてプレフィックスの合計を事前計算します。 これらにより、後でセグメントコストを一定時間評価できるようになります。 
3. DP 状態を定義します。ここで、dp[i][k] は、正確に k 個の配送日を使用して最初の i ギフトをスケジュールするための最小合計ペナルティを表します。 この公式は、最大 K 日を個別に使用できるという制約に直接一致します。 
4. 各 dp[i][k] について、最後のセグメントが位置 j+1 から i までのギフトをカバーしていると考えます。 次に、dp[j][k−1] にセグメント [j+1, i] を 1 つの配送日に割り当てるコストを加えて、dp[i][k] を更新します。 
5. 最適な配送日が d[r] であることに注意して、セグメント [l, r] のコストを計算します。 コストは、(d[r] − d[i])² の [l, r] における i の合計になります。 接頭辞の合計を使用して、これを d[i] と d[i]² の合計を含む式に拡張し、O(1) の評価を可能にします。 
6. 各状態のすべての有効な j の最小値を取得し、i と k の昇順で dp を構築します。 
7. 移行ポインタを保存して、DP テーブルを埋めた後、どのセグメントが選択されたかを再構築し、各ギフトに対応する配送日を割り当てることができます。 

### なぜ効果があるのか

 正確さは 2 つの構造特性に依存します。 まず、並べ替えによって、最適なグループが連続していることが強制されます。これは、非連続グループは実行可能性を変えることなく再配置でき、凸性によるコストの増加もありません。 第 2 に、固定セグメント内では、セグメント内の実現可能性制約 t ≥ max di を適用した後、最適な共有配送日が正しいエンドポイントに強制されます。 これら 2 つの事実により、元の組み合わせの選択がきれいな区間分割問題に分解され、DP はこれを正確に捉えます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    N, K = map(int, input().split())
    a = list(map(int, input().split()))
    
    arr = sorted([(v, i) for i, v in enumerate(a)])
    vals = [v for v, _ in arr]
    idx = [i for _, i in arr]
    
    ps = [0] * (N + 1)
    ps2 = [0] * (N + 1)
    
    for i in range(N):
        ps[i + 1] = ps[i] + vals[i]
        ps2[i + 1] = ps2[i] + vals[i] * vals[i]
    
    def cost(l, r):
        # segment [l, r], using vals[r] as delivery day
        x = vals[r]
        m = r - l + 1
        s1 = ps[r + 1] - ps[l]
        s2 = ps2[r + 1] - ps2[l]
        return m * x * x - 2 * x * s1 + s2
    
    INF = 10**30
    dp = [[INF] * (K + 1) for _ in range(N + 1)]
    pre = [[-1] * (K + 1) for _ in range(N + 1)]
    
    dp[0][0] = 0
    
    for k in range(1, K + 1):
        for i in range(1, N + 1):
            for j in range(i):
                val = dp[j][k - 1] + cost(j, i - 1)
                if val < dp[i][k]:
                    dp[i][k] = val
                    pre[i][k] = j
    
    best_k = min(range(1, K + 1), key=lambda x: dp[N][x])
    
    ans_sorted = [0] * N
    i, k = N, best_k
    
    while i > 0:
        j = pre[i][k]
        t = vals[i - 1]
        for p in range(j, i):
            ans_sorted[p] = t
        i = j
        k -= 1
    
    ans = [0] * N
    for (v, orig), t in zip(arr, ans_sorted):
        ans[orig] = t
    
    print(*ans)

if __name__ == "__main__":
    solve()
```実装ではまず、セグメント DP が有効になるようにギフトを並べ替えます。 値と二乗のプレフィックス和により、各セグメントの二次コストの定数時間計算が可能になります。 

DP テーブルは、プレフィックスの長さと使用される配信日数を増加させるように組み込まれています。 各トランジションは、最後のセグメント境界の延長を試みます。 再構成配列には、各セグメントの開始場所が格納されます。これは、そのセグメント内のすべての要素に 1 つの配送日を割り当てるために使用されます。 

ソートは構造のためのツールにすぎず、最終的な出力順序ではないため、最後のステップでは結果を元のインデックスにマッピングします。

 ## 特殊なケース

 エッジ ケースの 1 つは、K が十分に大きく、すべてのギフトが独自のセグメントを形成できる場合に発生します。 その場合、各ギフトは独自のグループとなり、割り当てられた配達日はそれぞれの理想的な日と同じになります。 DP では j = i − 1 の遷移が許可され、ゼロコストの単一要素セグメントが生成されるため、アルゴリズムはこれを自然に処理します。 

もう 1 つのケースは、K = 1 の場合です。この場合、すべてのギフトは 1 つの配送日を共有する必要があり、DP によって配列全体で 1 つのセグメントに強制されます。 ソート後の右エンドポイントでセグメントコストが最小となるため、納期が最大diとなります。 

3 番目のケースでは、小さい値と大きい値が混在しており、早期に分割することで二次ペナルティが大幅に減少します。 DP はすべての分割ポイントを明示的に評価し、直感的でないパーティションも考慮されて最適なパーティションが選択されるようにします。
