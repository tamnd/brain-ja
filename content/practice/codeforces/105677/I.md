 ## 解決策
 ## 問題の理解

 N 個のオブジェクトのコレクションが与えられ、各オブジェクトは紙を表します。 すべての論文には他の論文への参照リストが含まれており、論文から引用されている各論文に矢印が向かう有向グラフを形成します。 この構造には有向サイクルがないことが保証されているため、引用を先へ進めば同じ論文に戻ることはできません。 

タスクは、これらの論文を、すべての論文を 1 回だけ使用する単一のチェーンに配置して、各論文がチェーン内の次の論文を引用できるかどうかを判断することです。 グラフの用語では、有向非巡回グラフにエッジ方向に従うハミルトニアン パスが含まれているかどうかが尋ねられます。 

N が最大 100,000、総エッジ数が最大 500,000 という制約は、線形または線形に近い時間で動作する必要があることを意味します。 すべての順列またはすべてのパスを明示的にテストしようとする解決策は、この規模では O(N^2) でも遅すぎるため、直ちに実行不可能になります。 

微妙な点は、グラフが無向の意味で接続されているかどうかは問われないことです。 グラフを接続しても、分岐した場合は条件を満たさない可能性があります。 逆に、複数のコンポーネントが切断されていると、すべてのノードをカバーする単一のチェーンを形成することがすでに不可能になります。 

よくある失敗例は、「非循環」が有効な順序付けが自動的に機能することを意味すると仮定することから発生します。 たとえば、エッジ 1 → 2 および 1 → 3 を持つ 3 つのノードがある場合、グラフは DAG になりますが、1 の後に順番に 2 と 3 の両方に進むことができないため、3 つすべてを単一のチェーンに配置して各ステップがエッジに従う方法はありません。 

もう 1 つの失敗例は、トポロジカルな順序付けが機能すると仮定した場合に発生します。 トポロジー順序では、ノードが有効な依存関係の順序で配置される場合がありますが、連続するノードがエッジによって直接接続されているパスに対応できない場合があります。 

## アプローチ

 ブルートフォース解釈では、訪問したノードをマークしながら段階的にパスを拡張しようとする DFS またはバックトラッキングを実行して、すべてのノードから開始してパスを構築しようとします。 最悪の場合、各ノードが他の多くのノードに分岐する可能性があり、あらゆる可能性を探ると階乗または指数関数的な動作が発生します。 グラフは線形ではなく非巡回であるようにのみ制約されているため、訪問済みの状態で枝刈りを行っても、膨大な数の部分順列が探索されます。 

重要な観察は、そのような完全なチェーンが存在する場合、グラフは本質的に線形に近い構造になるということです。 有効なソリューションでは、最後のノードを除くすべてのノードに、チェーンに沿った「次の」選択肢が 1 つだけ存在する必要があります。 これは、DAG ではハミルトニアン パスが有効なトポロジー順序として現れる必要があるため、構造全体がトポロジー順序を使用して検証できることを示唆しています。 

トポロジー的順序付けを計算したら、その順序付け内の連続する各ペアが有向エッジで接続されているかどうかを確認するだけで済みます。 それが成立する場合、順序付け自体は有効なハミルトニアン パスになります。 それが成り立たない場合、有効なパスは位相順序として現れる必要があるため、ハミルトニアン パスは存在できません。また、連続する位置間にエッジがないことは、グラフが完全なチェーンをサポートできないことを示しています。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | パスを介した DFS のバックトラック | お(ん!) | O(N) | 遅すぎる |
 | トポロジカルソート + 隣接性チェック | O(N + M) | O(N + M) | 承認済み |

 ## アルゴリズムのチュートリアル

 引用構造を有向グラフとして扱い、標準的な次数ベースのトポロジカルソートプロセスを使用します。

1. グラフの隣接リストを作成し、すべてのノードの次数を計算します。 これにより、どのノードに前提条件がないのか、つまり引用が入っていないのかを特定することができます。 
2. 次数が 0 のすべてのノードでキューを初期化します。 これらのノードは、それらに依存するものがないため、有効な順序で最初に現れることができます。 
3. キューからノードを繰り返し削除し、それをトポロジー順序に追加し、ノードが指すすべてのノードの次数を減らします。 ノードの次数が 0 になると、そのノードはキューに追加されます。 このプロセスは、依存関係を考慮した有効な順序で「利用可能な」用紙を削除することをシミュレートします。 
4. すべてのノードを処理した後、すべてのペーパーのトポロジカルな順序を取得します。 グラフは非巡回であることが保証されているため、すべてのノードが処理されます。 
5. 順序内のすべての隣接するペアをチェックして、この順序が単一のチェーンを形成しているかどうかを確認します。 連続するペア (u, v) ごとに、直接エッジ u → v が存在するかどうかを確認します。 
6. すべての連続するペアがエッジで接続されている場合は、順序自体が有効な完全な引用チェーンであるため、1 を返します。 それ以外の場合は 0 を返します。 

### なぜ効果があるのか

 DAG では、エッジは常に依存関係に沿って進むため、ハミルトニアン パスはトポロジー的順序を尊重する必要があります。 ハミルトニアン パスが存在する場合、それはすべてのノードの合計順序を定義します。 トポロジカル ソートは、同じ部分順序の別の線形拡張です。 グラフがハミルトニアン パスを認める場合、パス内の任意のペアを反転すると有向エッジの存在と矛盾するため、すべての有効なトポロジカル ソートはそのパスの順序と一致する必要があります。 

したがって、トポロジカル順序付けを計算し、隣接するペアが直接接続されていないことが判明した場合、それはパスが続行できない「ギャップ」があることを意味し、ハミルトニアン パスがまったく存在しないことを意味します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n = int(input())
    adj = [[] for _ in range(n)]
    indeg = [0] * n

    for i in range(n):
        parts = list(map(int, input().split()))
        c = parts[0]
        for x in parts[1:]:
            x -= 1
            adj[i].append(x)
            indeg[x] += 1

    q = deque([i for i in range(n) if indeg[i] == 0])
    topo = []

    while q:
        u = q.popleft()
        topo.append(u)
        for v in adj[u]:
            indeg[v] -= 1
            if indeg[v] == 0:
                q.append(v)

    pos = [0] * n
    for i, x in enumerate(topo):
        pos[x] = i

    has_edge = set()
    for u in range(n):
        for v in adj[u]:
            has_edge.add((u, v))

    for i in range(n - 1):
        u = topo[i]
        v = topo[i + 1]
        if (u, v) not in has_edge:
            print(0)
            return

    print(1)

if __name__ == "__main__":
    solve()
```実装は、引用リストから直接隣接リストと次数配列を構築することから始まります。 キューには現在空いているすべてのノードが保持されるため、依存関係の制約が常に尊重されます。 

トポロジー順序を生成した後、ペアのセットを使用してエッジの高速検索構造を構築します。 これにより、連続するノード間の隣接性チェックが O(1) になり、隣接性リストの繰り返しスキャンが回避されます。 

最後のループは重要な検証ステップです。 これにより、トポロジカルな順序付けが依存関係の意味で有効であるだけでなく、途切れることのない連続したパスを形成するように強制されます。 

## 実用的な例

 グラフが 1 → 2 → 3 → 4 という単純な連鎖を形成している場合を考えます。 

| ステップ | キュー | ポップ | トポ注文 | 角度変化 |
 | --- | --- | --- | --- | --- |
 | 1 | [1] | 1 | [1] | 2が0になる |
 | 2 | [2] | 2 | [1,2] | 3 が 0 になる |
 | 3 | [3] | 3 | [1,2,3] | 4が0になる |
 | 4 | [4] | 4 | [1,2,3,4] | 完了 |

 連続するすべてのペアには直接エッジがあるため、答えは 1 になります。これにより、純粋なチェーン構造が正しく認識されていることが確認されます。 

次に、1 → 2 および 1 → 3 で、2 と 3 の間にエッジがない分岐 DAG を考えてみましょう。 

| ステップ | キュー | ポップ | トポ注文 |
 | --- | --- | --- | --- |
 | 1 | [1] | 1 | [1] |
 | 2 | [2,3] | 2 | [1,2] |
 | 3 | [3] | 3 | [1,2,3] |

 連続するペアをチェックすると、1 → 2 は存在するが 2 → 3 は存在しないことがわかり、アルゴリズムは 0 を出力します。これは、グラフが非巡回であり、トポロジカルな意味で完全に順序付けされているにもかかわらず、単一のハミルトニアン パスを形成していないことを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N + M) | 各ノードはカーンのアルゴリズムで 1 回処理され、各エッジは一定の回数検査されます。 
| スペース | O(N + M) | 隣接リスト、次数配列、エッジ セットにはすべてのグラフ情報が格納されます。 

この制約では、最大 100,000 個のノードと 500,000 個のエッジが許可されるため、線形時間グラフの走査は問題なく制限内に収まります。

 ## 特殊なケース

 重要なエッジ ケースは、非周期的だがすぐに分割されるグラフです。 たとえば、ノード 1 は 2 と 3 を指します。アルゴリズムはトポロジカル ソートで最初にノード 1 を処理し、次に 2 と 3 の両方が同時に使用可能になります。 結果の順序付けでは、[1,2,3] などの任意の順序で配置されますが、エッジ 2 → 3 がないため、連続チェックは失敗し、入力が正しく拒否されます。 

もう 1 つのエッジ ケースは、複数の有効なトポロジー順序が存在するが、そのうちの 1 つだけがハミルトニアン パスに対応できる場合です。 たとえば、キュ​​ーで異なるステップで異なる選択が許可されている場合でも、厳密には単一のチェーンではない順序付けでは、必然的に連続するノード間に欠落エッジが導入され、タイがどのように解決されたかに関係なく、検証ステップでこれが検出されます。
