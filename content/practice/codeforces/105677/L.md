 ## 解決策
 ## 問題の理解

 私たちは無限の整数グリッド上を移動する戦車を制御しています。 開始状態は原点に固定されており、毎秒戦車の方向を選択します。 方向を選択すると、戦車は現在の速度と同じ距離だけ前進し、その後速度が 1 増加します。 

私たちが受け取る唯一のフィードバックは、各移動後に現在位置から隠されたターゲット ポイントまでのマンハッタンの距離です。 移動後にターゲットに正確に着地すると、インタラクションは正常に終了します。 

したがって、隠れたタスクは、速度が大きくなりすぎる前に、ターゲットまでの距離のフィードバックのみを使用して、最終的にターゲットに正確に着地するようにしながら、時間の経過とともに加速するポイントを操縦し、各移動長が事前に決定されて増加するようにすることです。 

この制約は、ターゲットが原点を中心とする約 200 万辺の正方形内にある一方、速度は 20000 まで直線的に増加することを意味します。 これは、失敗するまでに数万手しか実行できず、各手は潜在的に非常に遠くまでジャンプする可能性があることを意味します。 構造を持たずにやみくもに「検索」しようとするソリューションは、永久にオーバーシュートするか、収束する前に制限速度を使い果たす危険性があります。 

微妙な失敗モードは、動きの大きさが不可逆であるという事実から生じます。一度間違った方向に大きな距離を移動すると、次の数回の小さな動きでは完全に補うことはできません。 これにより、進行状況を「元に戻す」ことができると仮定した、単純で貪欲な修正戦略が排除されます。 

## アプローチ

 強引な解釈では、これを継続的なナビゲーションの問題として扱います。各ステップで 3 つの可能なアクションをすべて試し、結果の位置をシミュレートし、距離を短縮すると思われるアクションを選択します。 ターゲットの座標は分からず、現在位置からの距離しか分からないため、これはすぐに中断されます。 ターゲットの位置が分からなければ、どの候補手がより優れているかを評価することができないため、貪欲な分岐ツリーには使用可能なスコアリング機能がありません。 

もう 1 つの素朴なアイデアは、プロセスをグリッド上の検索として解釈し、空間を体系的にカバーしようとすることです。 ただし、移動ルールは単純な単位歩数の歩行ではありません。 ステップの長さが 1、2、3 と増加するため、軌道は非常に速く広がります。 このため、加速するステップ サイズを考慮しない限り、標準スパイラ​​ルなどの固定パターンのトラバースは信頼性が低くなります。 

重要な点は、軌道を可逆にする必要も、最適化する必要もないということです。 必要なのは、境界のある座標範囲内のすべての領域が最終的にパスと交差することを保証することだけです。 ターゲットは最大 200 万辺の正方形内にあることが保証されているため、境界領域に崩れることなく外側に拡張する決定論的なパスを構築するだけで十分です。 

これを達成する簡単な方法は、方向を強制的に 4 つの基本方向を繰り返し循環させることです。 歩幅は増加しますが、これにより拡大する多角形の経路が生成され、戦車をあらゆる方向に繰り返し押します。 ステップ サイズが大きくなることで、探索領域が超線形に拡張され、方向変更が繰り返されるため、軌道が 1 つの光線に固定されることがなくなります。 

最終的に、この拡張する歩行は、ターゲットを含む、固定された有界格子点を通過する必要があります。 戦車が目標に正確に着地すると、オラクルはゼロを返し、プロセスは終了します。

 ## アルゴリズムのチュートリアル

現在の方向と、現在の速度を暗黙的に定義するステップ カウンターのみを維持しながら、インタラクションをシミュレートします。 

私たちは、右、上、左、下などの方向を一定のサイクルで繰り返し選択し、このパターンを無限に繰り返します。 

各ステップは次のように進みます。 

1. サイクル内の次の方向を選択し、それを出力します。 

方向を循環させる理由は、軌道が単一の無制限の光線に縮退して、平面の大部分が外れるのを防ぐためです。 
2. 戦車は現在の速度で前進します。 

これにより、パスが外側に向かって急速に拡張されるため、訪問領域は時間の経過とともに直線よりも早く拡大します。 
3. 裁判官からマンハッタンの距離を読み取ります。 

それがゼロの場合、戦車はターゲットに正確に着地したため、直ちに終了します。 
4. 終了するか、速度に関する問題の制約に近づくまで続行します。 

重要な構造特性は、一連の位置が、軸方向を繰り返し変更する無制限の拡張ウォークを形成することです。 ステップ サイズが厳密に増加するため、新しいセグメントごとに、以前に訪問した境界領域から軌道がさらに押し出されますが、方向サイクルにより、永久に訪問されない象限が存在しないことが保証されます。 

## なぜ機能するのか

 軌跡は、大きさが増加するベクトルの合計として見ることができ、各ベクトルの方向は、周期的に繰り返される有限セットから選択されます。 これにより、エンベロープがあらゆる方向に際限なく拡大する拡張パスが作成されます。 

ターゲットは境界領域内に固定されているため、パスが通過しなければならない有限の半径が存在します。 ステップ サイズの拡大特性により、最終的に一部のセグメントがその半径と交​​差することが保証され、周期的な方向変更により、単一の線に沿ってではなく全方向で交差が発生することが保証されます。 この組み合わせにより、許容される座標範囲内の任意の固定格子点との最終的な交差が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def flush():
    sys.stdout.flush()

def move(c):
    print(f"? {c}")
    flush()
    d = int(input())
    if d == 0:
        sys.exit(0)
    return d

def solve():
    # Direction cycle: R, U, L, D
    dirs = ["R", "U", "L", "D"]
    i = 0

    while True:
        c = dirs[i]
        i = (i + 1) % 4
        move(c)

if __name__ == "__main__":
    solve()
```このソリューションは、4 方向にわたって単純な循環ポリシーを維持します。 唯一の要件は、速度が大きくなりすぎる前に有界ターゲット領域を最終的に確実にカバーすることであるため、状態の再構成やジオメトリの計算はありません。 

インタラクティブな問題では、すべてのクエリ後のフラッシュが不可欠です。 これがないと、裁判官はコマンドを受信せず、プログラムはタイムアウトになります。 

終了条件は、オラクルがターゲットとの正確な一致を示すゼロを返すとすぐに処理されます。

## テストケース

 インタラクティブな問題では、決定論的な単体テストは通常、裁判官を嘲笑することによってシミュレートされます。 以下は、小規模なシミュレーション シナリオで予想される動作を示す構造テスト ハーネスです。```python
import sys, io

class FakeJudge:
    def __init__(self, tx, ty):
        self.tx = tx
        self.ty = ty
        self.x = 0
        self.y = 0
        self.v = 1

    def query(self, c):
        if c == "R":
            dx, dy = 1, 0
        elif c == "L":
            dx, dy = -1, 0
        elif c == "U":
            dx, dy = 0, 1
        else:
            dx, dy = 0, -1

        self.x += dx * self.v
        self.y += dy * self.v
        self.v += 1

        d = abs(self.x - self.tx) + abs(self.y - self.ty)
        return d

def run_sim(tx, ty, steps=50):
    j = FakeJudge(tx, ty)
    dirs = ["R", "U", "L", "D"]
    i = 0
    for _ in range(steps):
        d = j.query(dirs[i])
        if d == 0:
            return (j.x, j.y)
        i = (i + 1) % 4
    return (j.x, j.y)

# sample-like checks
assert run_sim(1, 0, 10) is not None
assert run_sim(2, 3, 50) is not None
assert run_sim(-5, -5, 100) is not None
```| テスト入力 | 期待される出力 | 検証内容 |

 ## 特殊なケース

 エッジケースの 1 つは、ターゲットが原点のすぐ近くにある場合です。 このような状況では、最初の数ステップですぐに別の方向にオーバーシュートする可能性がありますが、周期的な移動によってパスはすぐに同じローカル領域を横切って戻ります。 マンハッタン距離フィードバックにより、直撃が発生したときに直ちに終了が検出されることが保証されます。 

もう 1 つのエッジ ケースは、ターゲットが (1e6、1e6) などの隅の遠くにある場合です。 ここで、初期のステップでは意味のある近接度は得られませんが、加速するステップ サイズにより、最終的には軌道がその大きさの範囲に広がることが保証されます。 交互の方向により、パスが 1 つの軸にのみ沿ってドリフトすることがなくなり、最終的には両方の座標がカバーされます。 

最後のエッジ ケースは、ターゲットが速度キャップの直前の到達可能な値の境界近くにある場合です。 速度は直線的に増加するため、すべてのステップにわたる最大変位は、キャップに到達するかなり前に許容座標範囲全体を横切るのに十分な大きさとなり、到達が不十分なためにらせん状の拡張が失敗することがなくなります。
