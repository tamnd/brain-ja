 ## 解決策
 ## 問題の理解

 ネットワークはエージェントのツリーです。 その通り`k`エージェントはアクティブとしてマークされる必要があります。 2 つのエンドポイントが異なるステータス (1 つはアクティブ、もう 1 つは非アクティブ) を受け取るすべての通信チャネルが 1 ポイントを与えます。 目標は、そのような交差チャネルの数ができるだけ多くなるようにアクティブなエージェントを選択することです。 

ネットワークはツリーであるため、エージェントの各ペアにはそれらの間に一意のパスがあります。 このプロパティによりサイクルが削除され、サブツリー動的プログラミング アプローチが自然になります。 

制約`n <= 2000`が主な手がかりです。 すべてのテスト ケースにわたる頂点の総数もわずか 2000 であるため、二次解は現実的です。`O(n^2)`テスト ケースごとは安全ですが、サブセットを列挙するか、すべての選択肢を試すソリューションは安全です。`k`可能な選択の数が指数関数的に増加するため、頂点を選択することは不可能です。 

重要なエッジケースは、次の正確な値から得られます。`k`そして木の構造から。 

のために`k = 0`、アクティブなエージェントがないため、異なるグループに接続できるエッジはありません。 例えば：```
Input
1
2 0
1 2
```答えは次のとおりです。```
0
```少なくとも 1 つのアクティブな頂点が無効な状態にアクセスしたり、エッジを誤ってカウントしたりする可能性があることを前提とした不注意な解決策です。 

のために`k = n`、すべてのエージェントがアクティブであるため、やはり交差するエッジはありません。 例えば：```
Input
1
3 3
1 2
2 3
```答えは次のとおりです。```
0
```すべての頂点を選択すると、考えられるすべての境界が削除されるため、選択した頂点の次数を最大化しようとする貪欲な方法は失敗する可能性があります。 

チェーンもスターとは異なる動作をします。 考慮する：```
Input
1
5 2
1 2
1 3
1 4
1 5
```答えは次のとおりです。```
3
```中心と 1 つのリーフを選択すると、交差するエッジは 3 つだけになります。 2 つの葉を選択すると、交差するエッジは 2 つだけになります。 高次の頂点の選択のみに基づいた戦略では、選択した頂点がその子とどのように相互作用するかを考慮する必要性が失われる可能性があります。 

## アプローチ

 直接的な総当りの解決策では、考えられるすべてのグループを試します。`k`アクティブなエージェントの場合、アクティブなグループと非アクティブなグループの間で交差するエッジをカウントし、最大値を維持します。 有効な選択肢はすべてチェックされるため、これは正しいです。 ただし、選択肢の数は、`C(n, k)`、中程度の場合でも巨大になります`n`。 と`n = 2000`、サブセットを列挙することは完全に不可能です。 

ツリー構造により、答えを推測するのではなく構築する方法が得られます。 ツリーをルート化すると、すべてのエッジが頂点とその子のいずれか 1 つを接続します。 そのエッジが寄与するかどうかは、2 つのエンドポイントのステータスにのみ依存します。 これは、各サブツリーがその内部のすべての可能な選択肢を要約できることを意味します。 

1 次元サブツリー DP で欠落している情報は、そのサブツリーのルートがアクティブかどうかです。 子自体がまだ非アクティブである可能性があるため、アクティブな頂点を含む子サブツリーは、その親へのエッジを必ずしも交差エッジにするわけではありません。 この問題は、現在の頂点がアクティブな状態と非アクティブな状態の 2 つの状態を維持することで解決します。 

ブルート フォースは、考えられるすべてのアクティブ セットをチェックするため機能しますが、数が多すぎるため失敗します。 すべてのエッジの寄与が 2 つのエンドポイントにのみ依存するという観察により、ナップサック スタイルのマージを使用して、より小さなサブツリーからの最適な答えを組み合わせることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(C(n,k) * n) | O(n) | 遅すぎる |
 | ツリーDP | O(n^2) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 頂点などの任意の頂点でツリーをルートします。`1`、深さ優先検索を実行します。 DFS 順序により、親の前に子を処理できます。 
2. 頂点ごとに`v`、2 つの配列を維持します。`active[v][i]`サブツリー内の交差するエッジの最大数です。`v`正確にいつ`i`頂点がアクティブであり、`v`それ自体はアクティブです。`inactive[v][i]`の場合も同じ意味です`v`それ自体は非アクティブです。 
3. すべての頂点を 2 つの可能性で初期化します。 もし`v`がアクティブな場合、サブツリーには現在 1 つのアクティブな頂点が含まれており、ゼロ交差エッジを提供します。 もし`v`非アクティブな場合、アクティブな頂点は含まれず、交差するエッジもゼロになります。 
4. ナップザック遷移を使用して、すべての子サブツリーを現在の頂点にマージします。 子サブツリーが貢献すると仮定します。`j`アクティブな頂点。 もし`v`はアクティブです。ルートが使用するアクティブな子を選択します`active[child][j]`、非アクティブな子ルートを選択する際に、`inactive[child][j] + 1`なぜなら、間のエッジは`v`そして子供はパーティションを越えます。 
5. 次の場合に対称トランジションを実行します。`v`非アクティブです。 アクティブな子ルートを選択すると交差エッジが 1 つ追加されますが、非アクティブな子ルートを選択すると交差エッジは追加されません。 
6. すべての子がマージされた後、ルートをアクティブにする方が良いでしょう。`k`頂点をアクティブにするか、非アクティブにします`k`アクティブな頂点。 

なぜ効果があるのか:

 不変条件は、頂点の処理後、サブツリー ルートの状態を考慮しながら、各 DP 状態がアクティブな頂点の可能な数ごとにサブツリー内の交差エッジの可能な限り最良の数を保存することです。 すべてのエッジは、その親と子がマージされるときに 1 回だけ考慮されます。 この時点で、DP 状態は両方のエンドポイントのステータスを認識しているため、エッジは交差する場合は正確にカウントされるか、交差しない場合は無視されます。 すべてのサブツリーの組み合わせはナップザック マージを通じて調査されるため、最終的なルート状態は、正確に可能な最良の選択を表します。`k`アクティブな頂点。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(n, k, edges):
    graph = [[] for _ in range(n)]
    for u, v in edges:
        u -= 1
        v -= 1
        graph[u].append(v)
        graph[v].append(u)

    active = [None] * n
    inactive = [None] * n
    size = [0] * n

    def dfs(v, p):
        size[v] = 1
        active[v] = [-10**9] * 2
        inactive[v] = [-10**9] * 2

        active[v][1] = 0
        inactive[v][0] = 0

        for u in graph[v]:
            if u == p:
                continue
            dfs(u, v)

            new_active = [-10**9] * (size[v] + size[u] + 1)
            new_inactive = [-10**9] * (size[v] + size[u] + 1)

            for i in range(size[v] + 1):
                if active[v][i] > -10**9:
                    for j in range(size[u] + 1):
                        if active[u][j] > -10**9:
                            new_active[i + j] = max(
                                new_active[i + j],
                                active[v][i] + active[u][j]
                            )
                        if inactive[u][j] > -10**9:
                            new_active[i + j] = max(
                                new_active[i + j],
                                active[v][i] + inactive[u][j] + 1
                            )

                if inactive[v][i] > -10**9:
                    for j in range(size[u] + 1):
                        if active[u][j] > -10**9:
                            new_inactive[i + j] = max(
                                new_inactive[i + j],
                                inactive[v][i] + active[u][j] + 1
                            )
                        if inactive[u][j] > -10**9:
                            new_inactive[i + j] = max(
                                new_inactive[i + j],
                                inactive[v][i] + inactive[u][j]
                            )

            size[v] += size[u]
            active[v] = new_active[:size[v] + 1]
            inactive[v] = new_inactive[:size[v] + 1]

    dfs(0, -1)
    return max(active[0][k], inactive[0][k])

def main():
    t = int(input())
    ans = []
    for _ in range(t):
        n, k = map(int, input().split())
        edges = [tuple(map(int, input().split())) for _ in range(n - 1)]
        ans.append(str(solve_case(n, k, edges)))
    print("\n".join(ans))

if __name__ == "__main__":
    main()
```すべての頂点には多くの近傍を持つことができ、入力はエッジのみを与えるため、隣接リストにはツリーが格納されます。 DFS は、無向ツリーをルート付きサブツリーに変換します。 

2 つの DP 配列が中心的な実装の詳細です。`active[v][i]`そして`inactive[v][i]`これにより、子サブツリーにアクティブな頂点が含まれているが、子自体が非アクティブである場合にエッジを数えるというよくある間違いを回避できます。 

マージ中、ループは、既に処理された部分の間でアクティブな頂点の可能な限りの分割を試みます。`v`そして新しい子サブツリー。 遷移では、エンドポイントのステータスが異なる場合にのみ 1 が追加されます。 初期状態は境界ケースを処理します`0`そして`1`サブツリー内のアクティブな頂点。 

Python の整数はオーバーフローしませんが、不可能な状態を表すには負のセンチネル値が依然として必要です。 答えは常にインデックスで見つかります`k`というのは、問題にはまさにその数のアクティブな頂点が必要だからです。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    old = sys.stdin
    sys.stdin = io.StringIO(inp)
    data = sys.stdin.read().split()
    sys.stdin = old

    if not data:
        return ""

    it = iter(data)
    t = int(next(it))
    out = []

    def solve_case(n, k, edges):
        graph = [[] for _ in range(n)]
        for u, v in edges:
            u -= 1
            v -= 1
            graph[u].append(v)
            graph[v].append(u)

        A = [None] * n
        B = [None] * n
        sz = [0] * n

        def dfs(v, p):
            sz[v] = 1
            A[v] = [-10**9, 0]
            B[v] = [0, -10**9]

            for u in graph[v]:
                if u == p:
                    continue
                dfs(u, v)
                na = [-10**9] * (sz[v] + sz[u] + 1)
                nb = [-10**9] * (sz[v] + sz[u] + 1)
                for i in range(sz[v] + 1):
                    for j in range(sz[u] + 1):
                        if i < len(A[v]) and j < len(A[u]):
                            na[i+j] = max(na[i+j], A[v][i] + A[u][j])
                        if i < len(A[v]) and j < len(B[u]):
                            na[i+j] = max(na[i+j], A[v][i] + B[u][j] + 1)
                        if i < len(B[v]) and j < len(A[u]):
                            nb[i+j] = max(nb[i+j], B[v][i] + A[u][j] + 1)
                        if i < len(B[v]) and j < len(B[u]):
                            nb[i+j] = max(nb[i+j], B[v][i] + B[u][j])
                sz[v] += sz[u]
                A[v] = na[:sz[v]+1]
                B[v] = nb[:sz[v]+1]

        dfs(0, -1)
        return max(A[0][k], B[0][k])

    for _ in range(t):
        n = int(next(it))
        k = int(next(it))
        edges = []
        for _ in range(n - 1):
            edges.append((int(next(it)), int(next(it))))
        out.append(str(solve_case(n, k, edges)))

    return "\n".join(out)
