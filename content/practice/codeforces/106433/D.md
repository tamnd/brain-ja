 ## 解決策
 ## 問題の理解

 配列で表される本の棚があります。 移動では、そのセグメント内のすべての書籍のペアが互いに素の値を持つ棚の連続した部分を選択し、そのセグメント全体を反転します。 タスクは、繰り返しの移動によって配列を非減少順序に変換できるかどうかを判断することです。 

重要なのは、実際にどのような動きが可能であるかを理解することです。 ペアごとに互いに素な値のセグメントを反転することは、そのセグメント内で隣接するスワップを実行することと同じです。 このようなセグメント内のすべての隣接するペアも互いに素であるため、互いに素な値間のすべての隣接するスワップが許可されます。 長さ 2 のセグメントは逆方向を示すため、許可されたすべての隣接スワップも有効な操作と見なすことができます。 

入力には複数のテスト ケースが含まれています。 各テスト ケースでは、棚にある本の数と値が示されます。 出力は、初期配置がソートされた配置に到達できるかどうかです。 

制約が十分に大きいため、位置のすべてのペアをチェックすることは受け入れられません。 書籍の総数が約 200,000 に達すると、二次解法では最悪の場合でも約 400,000,000 回の比較が必要になりますが、これは通常の競技プログラミングの制限をはるかに超えています。 線形または線形演算に近い解決策が必要です。 

重要なエッジケースは、互いに交差できない値から生じます。 たとえば、入力の場合```
1
4
6 1 1 1
```出力は`YES`。 値 6 は各 1 と互いに素であるため、右に移動でき、配列をソートできます。 

考慮する```
1
4
2 2 6 3
```出力は`NO`。 最初の 2 と 2 番目の 2 には gcd 2 があるため、それらの相対的な順序は決して変更されません。 これらはすでに相互に相対的に昇順になっていますが、6 と 3 も因数を共有しているため、ソートされた配列内で 6 は 3 の後に移動する必要があります。 その横断は不可能です。 

不注意な解決策による単純な失敗例は次のとおりです。```
1
3
3 2 6
```答えは`NO`。 一部の隣接する交換が可能かどうかのみをチェックするソリューションでは、たとえ中央の値が両方と素であっても、3 と 6 が交換できないことを見落とす可能性があります。 

## アプローチ

 直接的なアプローチは、可能なスワップをシミュレートすることです。 バブルソートと同様に、隣接する互いに素のペアを繰り返し見つけて、順序が改善されるたびにそれらを交換することを試みることもできます。 実行されるすべてのスワップは合法であるため、これは正しいです。 ただし、最悪の場合、バブル ソートは O(n²) スワップを実行します。これは、n が 200000 付近では遅すぎます。 

有益な観察は、相対順序が変更できる唯一のペアは、gcd が 1 に等しいペアであるということです。2 つの値の gcd が 1 より大きい場合、その最後の交差ステップ自体が不正になるため、それらは決して隣接して交換することはできません。 

これにより、固定不変式が得られます。 すべての非共素ペアは、ソートされた配列に表示されるのと同じ相対順序ですでに表示されている必要があります。 gcd(a[i], a[j]) > 1 であるが a[i] > a[j] である位置のペア i < j が存在するかどうかを検出するだけで済みます。 このようなペアは避けられない逆転です。 

残りの課題は、これらのペアを迅速に見つけることです。 配列を左から右に処理し、すべての素因数について、その素数を含む数値の中でこれまでに確認された最大値を保持します。 値 x に到達すると、x と素因数を共有する以前のすべての値は x と互いに素ではありません。 それらの最大値が x より大きい場合、禁止された反転が見つかりました。 

10^6 までの値の個別の素因数の数は少ないため、これらの素数バケットの更新は効率的です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | 遅すぎる |
 | 素因数追跡 | O(n log A) | O(A) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての数値を個別の素因数に因数分解します。 gcd が 1 より大きいということは、少なくとも 1 つの素因数が共有されていることを意味するため、個別の因数だけが必要になります。 
2. 位置 p が素因数 p を含むこれまでに確認された最大値を格納する配列を維持します。 
3. 本を左から右にスキャンします。 現在の値 x について、そのすべての素因数を調べます。 これらの因子の中で、x と因子を共有する過去の最大値を見つけます。 
4. 以前の最大値が x より大きい場合、2 つの値は決して修正できない反転を形成するため、答えは次のようになります。`NO`。 
5. x をチェックした後、x のすべての素因数を値 x で更新します。これは、将来の位置では x がすでに出現していることを認識する必要があるためです。 

これが機能する理由: 素因数の維持された最大値は、現在の値を超えることができない、考えられる最悪の以前の値を表します。 現在の値と因数を共有する以前の値は、左側に永久にロックされます。 最大のロック値がすでに現在の値より大きい場合、ソートには不可能なスワップが必要になります。 これが起こらない場合、すべての禁止されたペアはすでに正しく順序付けされており、残りのすべての反転には互いに素の値が含まれており、許可されたスワップによって解決できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXV = 10**6

spf = list(range(MAXV + 1))
for i in range(2, int(MAXV ** 0.5) + 1):
    if spf[i] == i:
        for j in range(i * i, MAXV + 1, i):
            if spf[j] == j:
                spf[j] = i

def factors(x):
    res = []
    while x > 1:
        p = spf[x]
        res.append(p)
        while x % p == 0:
            x //= p
    return res

fac_cache = {}

def get_factors(x):
    if x not in fac_cache:
        fac_cache[x] = factors(x)
    return fac_cache[x]

def solve_case(a):
    best = [0] * (MAXV + 1)
    for x in a:
        fs = get_factors(x)
        mx = 0
        for p in fs:
            if best[p] > mx:
                mx = best[p]
        if mx > x:
            return "NO"
        for p in fs:
            if x > best[p]:
                best[p] = x
    return "YES"

def main():
    t = int(input())
    ans = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        ans.append(solve_case(a))
    print("\n".join(ans))

if __name__ == "__main__":
    main()
```ふるいは、可能な最大値までのすべての数値の最小の素因数を計算します。 これにより、各因数分解が迅速に実行されます。 

内部のスキャン`solve_case`アルゴリズムは直接に従います。 現在の値をプライム バケットに挿入する前に、以前の非共素値の方が大きいかどうかがチェックされます。 現在の値はそれ自体と比較してはいけないため、更新はチェック後に行われます。 

因数リストには各素数が 1 回だけ含まれます。 繰り返しの因子を保存すると、結果は正確になりますが、速度は遅くなります。 素因数を共有することはすでに gcd が 1 ではないことを意味するため、個別の因数で十分です。 

メモリ使用量は、最小素因数配列と最大値追跡配列によって支配されます。

 ## 特殊なケース

 のために`1 4 6 1 1 1`、値 6 は、どの 1 とも因数を共有しません。アルゴリズムは以前の競合する値を認識しないため、値がスワップを通じて正しく移動することができます。 

のために`1 4 2 2 6 3`、最後の値 3 が処理されるとき、素因数 3 にはすでに左側から値 6 が格納されています。 6 は 3 より大きく、それを横切ることができないため、アルゴリズムは直ちに配列を拒否します。 

次のようなすべての値が等しい配列の場合、`1 5 4 7 7 7 7`、値が等しいと反転が発生しないため、すべてのブロックされたペアはすでに順序付けされています。 最大共有値が現在の値より大きくなることはありません。そのため、答えは次のようになります。`YES`。 

単一要素配列の場合、移動は必要ありません。 配列はすでにソートされており、アルゴリズムは次の値を返します。`YES`。
