 ## 解決策
 ## 問題の理解

 私たちには次のシーケンスが与えられています$n$各レイヤーには文字で構成される文字列が含まれます$R$そして$G$。 各文字は特定の色のキャンディーを表し、文字列はそのレイヤー内でキャンディーが上から下に表示される順序を表します。 

重要な点は、Luogu がデザートをどのように「観察」するかです。 彼は、すべてのレイヤーを物理的にただちに 1 つのシーケンスにマージするわけではありません。 代わりに、彼は層を 1 つずつ順番に検査しますが、何を連続して食べるかを考えるとき、事実上、デザート全体を、すべての文字列を順番に積み重ねることによって形成される単一の連結されたシーケンスとして扱うことができます。 

タスクは、すべてのキャンディーが同じ色を持つ、このシーケンス全体の連続するセグメントの最大長を見つけることです。 

したがって、問題は次のようになります。$n$文字列が終わった$\{R, G\}$、それらを順番に連結し、同一の文字の最長の連続を計算します。 

制約は単純な意味で重要です。 すべての文字列の合計の長さは最大でも$2 \cdot 10^5$したがって、各文字を一定の回数だけ処理する任意のソリューションが受け入れられます。 レイヤーを介した二次アプローチや部分文字列の繰り返しスキャンでは、文字を繰り返し再利用する場合、すでに遅すぎます。 

よくある失敗例は、各レイヤーを独立して処理し、単一の文字列内で最大の実行を取得することです。 それは境界を越えるランをミスします。 

例えば：```
3
RR
R
GG
```最初の 2 つのレイヤーが結合されるため、正解は 3 です。`RRR`。 レイヤーごとの最大値が誤って 2 を返します。 

別の失敗例は、すべての層境界でカウントを無条件にリセットすることです。 連続性は、前のレイヤーの最後の文字と次のレイヤーの最初の文字によって決まります。 

## アプローチ

 ブルート フォースのアプローチでは、完全な連結文字列を明示的に構築し、それをスキャンして最長の等しい文字の続きを計算します。 これは、キャンディーの最終的なシーケンスを直接モデル化しているため、正しいです。 文字列を構築した後、単一パスで現在のストリーク長が維持され、最大値が更新されます。 

コストはメモリと繰り返しの連結オーバーヘッドによって発生します。 文字列を繰り返し連結すると、各追加に現在の全長で直線的な時間がかかる可能性があり、$O(n^2)$最悪の場合の行動。 事前に割り当てて一度参加したとしても、引き続きフルスキャンを実行します。$2 \cdot 10^5$それは問題ありませんが、意図したソリューションの精神は、不必要な中間構造の構築を避けることです。 

重要な点は、完全な文字列は必要ないということです。 現在の文字、現在のストリークの長さ、およびこれまでに確認された最大ストリークを追跡する必要があるだけです。 各レイヤーを順番に処理するときに、レイヤーの最初の文字が現在の文字と一致する場合はストリークを継続し、そうでない場合はリセットします。 レイヤー内では、単純に順次スキャンし、進行中に縞を更新します。 

これにより、問題は、グローバル文字列を構築することなく、すべてのレイヤーにわたるすべての文字に対する単一の線形パスに変わります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (連結 + スキャン) |$O(N)$または$O(N^2)$実装に応じて |$O(N)$| 受け入れられますが、実装が不十分だと安全ではありません |
 | ストリーミングスキャン |$O(N)$|$O(1)$番外編 | 承認済み |

 ## アルゴリズムのチュートリアル

 継続的な連続性を維持しながら、入力順に文字を処理します。 

1. 変数を初期化する`best`これまでに見つかった最大のストリークを変数に保存します。`cur_char`現在のストリーク文字の場合、および`cur_len`その長さのために。 

初めに、`cur_char`は未定義であり、`cur_len`キャンディーが処理されていないため、0 になります。 
2. 各レイヤー文字列について、その文字を左から右に繰り返します。 

これにより、各層内の実際の食べる順序が保存されます。 
3. キャラクターごとに$ch$、と比較してください`cur_char`。 

一致する場合は増分します`cur_len`連勝が途切れることなく続いているからです。 
4. もし$ch \neq cur_char$、ストリークをリセットします: set`cur_char = ch`そして`cur_len = 1`。 

これが必要なのは、変更がレイヤー内またはレイヤー間で発生した場合でも、異なる色によって連続性が損なわれるためです。 
5.アップデート後`cur_len`、 アップデート`best = max(best, cur_len)`。 
6. すべてのレイヤーが処理されるまで続行し、出力します。`best`。 

重要な設計上の選択は、レイヤーの境界を決して特別に扱わないことです。 隣接性は入力順序の連続する文字によってのみ定義されるため、スキャンではそれらが自然に処理されます。 

### なぜ効果があるのか

 処理中のどの時点でも、`cur_len`現在の位置で終わる、同一の文字で構成される最長の接尾辞の長さに等しい。 このサフィックスは、最後に表示された文字と、それが連続して繰り返された回数のみに依存するため、一意です。 考えられるすべての連続セグメントは何らかの位置で終了する必要があるため、すべてのサフィックス ストリークを追跡することで、すべての候補セグメントが確実に考慮されます。`best`その中で最大のものを捉えます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    
    best = 0
    cur_char = None
    cur_len = 0
    
    for _ in range(n):
        s = input().strip()
        for ch in s:
            if ch == cur_char:
                cur_len += 1
            else:
                cur_char = ch
                cur_len = 1
            if cur_len > best:
                best = cur_len
    
    print(best)

if __name__ == "__main__":
    solve()
```この解決策は、すべての文字を 1 回通過することに依存します。 状態変数`cur_char`そして`cur_len`現在の実行の不変条件を実装します。`best`グローバル最大値を累積します。 

微妙な点は初期化です。`cur_char`として開始する必要があります`None`これにより、最初の文字が常にリセットをトリガーし、最初のストリークが正しく処理されるようになります。 

反復順序によってすでに隣接性が強制されているため、レイヤー境界に対して特別な処理は必要ありません。

 | 測定 | 複雑さ | 説明 |

 | 時間 |$O(\sum c_i)$| 各文字は 1 回のリニア スキャンで 1 回だけ処理されます。 
| スペース |$O(1)$| 一定数の状態変数のみが維持されます。 

合計文字数は最大でも$2 \cdot 10^5$, したがって、リニアスキャンは時間制限内に快適に収まります。 入力サイズに比例する追加のメモリは必要ありません。

 ## 特殊なケース

 エッジ ケースの 1 つは、あるレイヤーで開始され、次のレイヤーにシームレスに続く実行です。 例えば：```
2
RRR
RR
```アルゴリズムは次から始まります`R`、最初のレイヤーを通過し、リセットせずに 2 番目のレイヤーに進みます。`cur_len`が 5 になり、`best`正しく追跡します。 単純なレイヤーごとのアプローチでは、誤って 3 が出力されます。 

もう 1 つのエッジ ケースは、文字ごとに完全にリセットされることです。```
3
R
G
R
```ここでは、あらゆる遷移が連続性を破壊します。 アルゴリズムがリセットされる`cur_len`あらゆる段階で、維持しながら`best = 1`。 これにより、最大限の断片化下での正確性が確認されます。 

3 番目のエッジ ケースは、非常に長い単一レイヤーです。 このアルゴリズムは、単純に 1 回スキャンしてストリークを線形に更新し、外部構造に依存しないため、メモリのオーバーヘッドと境界の混乱の両方が回避されます。
