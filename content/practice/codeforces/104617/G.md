 ## 解決策
 ## 問題の理解

 与えられた 2 つの独立したリストは、利用可能なコーンを使用して何人の顧客にサービスを提供するかという 1 つの決定を通じて相互作用します。 

顧客一人ひとりに価値観がある$r_i$、これは、その顧客にチョコミント コーンを提供することに成功した場合に得られる利益を表します。 ただし、コーンがチョコミントかどうかは実際には制御できません。 代わりに、提供された各コーンはランダムな結果のように動作し、Alex の賭けメカニズムを通じて経済的にヘッジできるようになります。 これにより、不確実性とは関係なく、各顧客の結果が固定の期待貢献に効果的に変換されます。 

供給側では、グレッグは次のように考えています。$M$コーン、それぞれに購入費用がかかります$c_i$。 コーンを使用する場合は購入する必要があります。 

決定は正確に選択することです$K$顧客とまさに$K$円錐、どこで$K$どちらも超えることはできません$N$または$M$。 選ばれた各顧客は、以下から導出される期待値に貢献します。$r_i$、選択された各コーンがコストに寄与します。$c_i$。 目標は、保証された利益を最大化し、その利益を達成するあらゆる方法の中で、それを達成する顧客とコーンを選択する方法の数を最大化することです。 

重要な微妙な点は、問題は適応ペアリングに関するものではないということです。 複雑な方法で個々のコーンを顧客に適合させることはありません。 代わりに、この構造は、顧客の最適なサブセットと、同じサイズのコーンの最も安価なサブセットを選択することになります。 

までの制約付き$10^5$、サブセットを列挙したり、選択肢をシミュレートしようとしたりするソリューションは直ちに不可能です。$O(N^2)$限界をはるかに超えています。 ソートベースまたは選択ベースの方法が唯一の実行可能な方向です。 

いくつかの特殊なケースについては、明示する価値があります。 

もしすべてなら$c_i = 0$、コーンは無料であるため、最良の戦略は依然として純粋に顧客の価値観によって決まります。 「ペアリングの最適化」を試みる単純なアプローチはこれを複雑にしすぎる可能性がありますが、それでも答えは利用可能な最大の顧客セットを選択することによって決まります。 

もしすべてなら$r_i$が等しい場合、顧客を選択するための最適な方法は数多くあり、これらの組み合わせを正確に数えることが主な困難になります。 

もし$N \neq M$、サービスできる顧客の数は小さい側で制限されており、これを無視すると、存在するよりも多くのコーンを使用しようとする無効な構造につながります。 

## アプローチ

 ブルートフォースアプローチでは、考えられるすべての値を試します。$K$、次に選択します$K$顧客と$K$コーンを作成し、利益を計算し、最良の結果を追跡します。 固定ごとに$K$、サブセットの選択にはすでに組み合わせ時間がかかるため、これはすぐに指数関数的になります。 「サイズのすべてのサブセットを試す」ように縮小しても$K$”につながる$O(\binom{N}{K} \binom{M}{K})$、それはたとえ小さくても実行不可能です$N$。 

固定の場合に観察すると、構造は単純化されます。$K$、顧客の最良の選択は常に$K$最大$r_i$、そしてコーンの最良の選択は常に$K$最小$c_i$。 逸脱すると、目標が改善されずに収益が減少するか、コストが増加します。 

これにより、問題は 1 次元の最適化に変わります。$K$、値は次のとおりです。$$\text{profit}(K) = \frac{1}{2} \sum_{\text{top } K} r_i - \sum_{\text{cheapest } K} c_i$$要因$1/2$これは、保証された期待に対する各顧客の貢献を効果的に半分にする賭けのメカニズムから来ています。 

この問題では最初に顧客の数を最大化することも求められているため、次のように修正します。$$K = \min(N, M)$$次に、この 1 つの構成のみを評価します。 

最適な方法の数を数えるのは組み合わせ論の問題になります。複数の顧客が並べ替えられたリストの境界値を共有している場合、有効な上位を形成するそれらのサブセットを選択できます。$K$。 同じことがコスト境界のコーンにも当てはまります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | サブセットに対するブルート フォース | 指数 | O(1)-O(N) | 遅すぎる |
 | 並べ替え + 選択 + カウント | O(N log N + M log M) | O(N + M) | 承認済み |

 ## アルゴリズムのチュートリアル

 修正します$K = \min(N, M)$。 これはサービスを提供できる顧客の最大数であり、目標ではまず顧客数を最大化することが優先されるため、有効な最適ソリューションではこの値を使用する必要があります。 

次に、次の手順に進みます。 

1. 顧客の価値観を分類する$r_i$降順で。 上位を選択していきます$K$最適なソリューションは報酬の合計貢献度を最大化する必要があり、選択した値をより小さい値に置き換えることは、合計を減らすだけであるためです。 
2. コーンコストの並べ替え$c_i$昇順で。 一番安いものを選択させていただきます$K$なぜなら、より高価な交換は実現可能性を向上させることなくコストを厳密に増加させることになるからです。 
3. 基本利益を次のように計算します。$$\frac{1}{2} \sum_{i=1}^{K} r^{\downarrow}_i - \sum_{i=1}^{K} c^{\uparrow}_i$$4. 選択できる方法が何通りあるか数えてください。$K$同じ最高額を達成する顧客。 これは、ソートされたリストのカットオフ位置に同一の値がいくつ存在するかによってのみ決まります。 
5. 同様に、選択できる方法が何通りあるか数えてください。$K$境界値で多重度を使用して、最小コストを達成するコーン。 
6. 2 つのカウントを剰余で乗算します。$10^9+7$。 

多重度が重要である理由は、$K$ソートされた順序で - 番目の値が繰り返され、それらの等しい要素の間でどのような選択を行っても合計合計やコストは変化しないため、そのような選択はすべて有効な最適解となります。 

### なぜ効果があるのか

 重要な不変条件は、並べ替え後の最適なソリューションは両方の配列のプレフィックス選択である必要があるということです。 選択した顧客が上位に含まれていない場合$K$、より高いものに置き換えます$r_i$徹底的に利益を増やします。 選択したコーンが最も安価なものではない場合$K$、より安価なコーンに置き換えると、コストが大幅に削減されます。 したがって、すべての最適なソリューションは、最上位を正確に選択することから構成されなければなりません。$K$顧客と最も安い$K$等しい境界値のグループ内でのみ自由を持つ円錐。 これにより、最適化とカウントの両方が、ソートされた配列に対する単純な組み合わせに削減されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def mod_pow(a, e, mod=MOD):
    r = 1
    while e:
        if e & 1:
            r = r * a % mod
        a = a * a % mod
        e >>= 1
    return r

def solve():
    N, M = map(int, input().split())
    r = list(map(int, input().split()))
    c = list(map(int, input().split()))

    K = min(N, M)

    r.sort(reverse=True)
    c.sort()

    # prefix sums for profit
    sum_r = sum(r[:K])
    sum_c = sum(c[:K])

    profit = sum_r / 2.0 - sum_c

    # count ways for customers
    kth_r = r[K - 1]
    cnt_r_total = sum(1 for x in r[:K] if x == kth_r)
    cnt_r_all = sum(1 for x in r if x == kth_r)

    need_r = sum(1 for x in r[:K] if x == kth_r)
    ways_r = 0

    # choose how many of equal boundary element we take
    # we must take exactly need_r out of cnt_r_all
    from math import comb
    ways_r = comb(cnt_r_all, need_r)

    # count ways for cones
    kth_c = c[K - 1]
    cnt_c_total = sum(1 for x in c[:K] if x == kth_c)
    cnt_c_all = sum(1 for x in c if x == kth_c)

    need_c = cnt_c_total
    ways_c = comb(cnt_c_all, need_c)

    ways = (ways_r * ways_c) % MOD

    # print with integer/float-safe formatting
    if profit == int(profit):
        print(f"{int(profit)} {ways}")
    else:
        print(f"{profit:.10f} {ways}")

if __name__ == "__main__":
    solve()
```このソリューションでは、まず顧客の数を可能な最大値に固定し、次に 2 つの独立した並べ替えられた選択から利益を計算します。 浮動小数点の 2 による除算は、最終的な利益の計算式に直接現れ、顧客ごとの期待価値への寄与を反映します。 

すべての非境界要素がすべての最適解に強制的に組み込まれるため、カウント ロジックは重複の境界領域のみを分離します。 組み合わせの選択は、カットオフ ポイントでの同一の値からのみ生じます。

## テストケース```python
import sys, io
from math import comb

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    MOD = 10**9 + 7

    N, M = map(int, input().split())
    r = list(map(int, input().split()))
    c = list(map(int, input().split()))

    K = min(N, M)

    r.sort(reverse=True)
    c.sort()

    sum_r = sum(r[:K])
    sum_c = sum(c[:K])

    profit = sum_r / 2 - sum_c

    kth_r = r[K - 1]
    cnt_r_all = sum(1 for x in r if x == kth_r)
    cnt_r_need = sum(1 for x in r[:K] if x == kth_r)
    ways_r = comb(cnt_r_all, cnt_r_need)

    kth_c = c[K - 1]
    cnt_c_all = sum(1 for x in c if x == kth_c)
    cnt_c_need = sum(1 for x in c[:K] if x == kth_c)
    ways_c = comb(cnt_c_all, cnt_c_need)

    ways = (ways_r * ways_c) % MOD

    if profit == int(profit):
        return f"{int(profit)} {ways}"
    return f"{profit:.10f} {ways}"

 ## 特殊なケース

 すべての顧客の価値観が同一の場合、サイズのすべてのサブセットは$K$同じ報酬額を生成します。 アルゴリズムは引き続き境界を修正しますが、すべての要素は実際には境界と非境界の両方であるため、組み合わせカウントはすべての顧客にわたる純粋な二項係数となり、実装では多重度カウントを通じてこれを取得します。 

すべてのコーンのコストが同じ場合、最も安いのは$K$円錐は任意であり、どの選択も有効です。 ソートされたプレフィックス ロジックは、すべての要素が交換可能であることを正確に識別し、カウントは同一の値の組み合わせに減ります。 

いつ$N < M$、 のみ$N$顧客にサービスを提供でき、ソリューションには当然のことながら上限が設定されます。$K$で$N$。 より多くの顧客の選択を強制しようとすると、存在しない利益条件が必要となり、実現可能性が損なわれます。
