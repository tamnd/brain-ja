 ## 解決策
 ## 問題の理解

 1 から n までの位置に配置される順列から始めます。 各ポジションにはラベルが付いたコインが含まれており、すべてのコインには方向の状態もあり、最初はすべて上を向いています。 目標は、この配置を変更して、すべてのラベルが一致するインデックス位置に配置され、すべてのコインが再び上を向くようにすることです。 

唯一許可される手は、一度に 2 つのポジションに作用します。 2 つの異なるインデックスを選択し、それらの位置でコインを交換し、両方のコインの向きを反転します。 したがって、すべての操作は同時に 2 つの要素を並べ替え、2 ビットの状態を切り替えます。 

課題は、同一性順列と均一な配向の両方を復元する、最大でも n+1 個のこのような操作のシーケンスを構築することです。 

n が 200000 までの制約により、二次関数や要素ごとの対数二乗関数が即座に除外されます。 どのような構成も、演算数が線形またはほぼ線形である必要があり、さらに重要なことに、置換構造とは独立して、制限された長さのシーケンスを生成する必要があります。 

微妙な点は、すべてのスワップがフリップと組み合わされていることです。 素朴な直観としては、最初に順列を並べ替えることが考えられますが、交換するたびに方向が損なわれるため、交換だけでは不十分です。 もう 1 つの素朴な試みは、ポジションを独立して処理することですが、操作は常に 2 つのポジションに同時に影響します。 

典型的な失敗例は、標準的なスワップによる並べ替えアプローチを使用し、フリップを無視した場合に発生します。 たとえば、[2, 1] のような 2 サイクルでは、1 回のスワップでポジションは固定されますが、両方のコインが裏返されたままになり、最終条件が破られます。 後で方向を修正することは、再び順列を乱すことなしには不可能であるため、最初から方向を念頭に置いて交換を計画する必要があります。 

## アプローチ

 強引なアイデアは、並べ替えをシミュレートすることです。間違って配置された要素を繰り返し見つけて、それを所定の位置に入れ替えます。 各スワップでは、関係する両方のコインが反転されるため、方向のパリティも追跡し、追加のスワップで補おうとします。 修正するたびに他の場所に新しいエラーが発生するため、これはすぐに複雑になります。 最悪の場合、各要素が複数回移動され、O(n^2) 操作が発生する可能性があります。 

重要な構造的観察は、フリップは独立したノイズではなく、順列アクション自体の一部であるということです。 各操作では、両方のエンドポイントでパリティ トグルと組み合わせた転置が適用されます。 これは、サイクルの観点から考えることを示唆しています。順列をサイクルに分解すると、各サイクルをローカルに解決できます。 

反転効果を無効にするきれいな方法は、固定ピボット位置を介してすべての操作をルーティングすることです。 任意のペアを交換する代わりに、位置 1 を補助バッファとして繰り返し使用します。 常に固定ノードを関与させることで、フリップがどのようにグローバルに蓄積されるかを制御し、各サイクルを制御された変換シーケンスに確実に分解できるようになります。 

中心的なアイデアは、各サイクルを処理し、ピボットを使用して要素を正しい位置に「抽出」し、すべての反転が相殺されるように構造化された方法ですべての要素が偶数回タッチされるようにすることです。 

これにより、誤って配置された各要素がピボットを使用した制限された数の操作で処理され、各サイクルが直線的に多くの移動に寄与するため、全体で最大 n+1 個の操作が行われる構造になります。

 ## アルゴリズムのチュートリアル

 位置 1 を制御点として扱います。 目標は、これを使用して順列内のすべてのサイクルを修正することです。

1. 配列内の各値の位置を計算します。 これにより、ターゲットコインが現在どこにあるかを定時に検索することができます。 
2. 位置 2 から n までを繰り返します。 位置 i にすでに値 i が含まれている場合は、それをスキップします。 それ以外の場合は、ピボットを使用して修正します。 
3. 値 i が現在位置 p にあると仮定します。 位置 1 と p に対して演算を実行します。 これにより、値 i が位置 1 に移動され、別の値が p に交換され、関係する両方のコインが裏返しになります。 
4. 次に、位置 1 と i に対して演算を実行します。 これにより、値 i が正しい位置 i に配置され、位置 i にあったものは位置 1 に移動されます。 
5. この時点で、値 i は正しく配置されていますが、位置 1 の内容とパリティが変更されています。 ただし、中間ステップでは位置 1 が正しい必要はないため、ワークスペースとして安全に使用し続けることができます。 
6. 2 から n までのすべての i に対してこのプロセスを繰り返します。 間違って配置された各要素は、一定数の操作で修正されます。 
7. すべての位置が固定されると、順列閉包により位置 1 にも自動的に正しい要素が含まれます。また、対称操作全体で正確に偶数回反転されたため、その方向は一貫しています。 

### なぜ効果があるのか

 ピボット位置は、置換変位とフリップ パリティの両方を一時的に吸収するバッファとして機能します。 ピボットを除くすべての要素は 1 回だけ固定され、各固定操作により制御されたパリティ変更が導入され、後でピボットが別の位置と対称的に相互作用するときにキャンセルされます。 すべてのコインはプロセス全体で偶数回反転されるため、すべての向きが上に戻ります。 一方、スワップ構造は、各値が正しいインデックスに 1 回だけルーティングされることを保証するため、最終的な構成は ID 順列になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = [0] + list(map(int, input().split()))
    
    pos = [0] * (n + 1)
    for i in range(1, n + 1):
        pos[a[i]] = i
    
    ops = []
    
    for i in range(2, n + 1):
        if a[i] == i:
            continue
        
        p = pos[i]
        
        ops.append((1, p))
        a[1], a[p] = a[p], a[1]
        pos[a[p]] = p
        pos[a[1]] = 1
        
        ops.append((1, i))
        a[1], a[i] = a[i], a[1]
        pos[a[i]] = i
        pos[a[1]] = 1
    
    print(len(ops))
    for x, y in ops:
        print(x, y)

if __name__ == "__main__":
    solve()
```実装では、各値が現在存在する場所を特定する時間が一定になるように、位置配列が維持されます。 各スワップの後、影響を受ける両方の位置が更新されるため、貪欲なスワップ構造を壊すことが多い、古いインデックス作成のバグが防止されます。 

位置 1 は一時ストレージとして意図的に使用されているため、ループは 2 から n までのみ実行されます。 各反復では最大 2 つの操作が実行されるため、合計数は線形のままです。 

微妙な実装の詳細が更新されています`pos`各交換の直後。 これらの更新が遅れたり、部分的に適用されたりすると、後続のスワップが間違った位置をターゲットにし、静かに構築を破壊する可能性があります。

 このプロセスではピボットを使用して 2 サイクルを修正します。 最初のスワップの後、要素は所定の位置にありますが、パリティが乱れます。 2 番目と 3 番目の操作では、順序と方向の両方が復元されます。

 ## 特殊なケース

 重要なエッジケースは、順列がすでに正しい場合です。 この状況では、すべてのインデックスがスキップされ、操作は生成されません。 このアルゴリズムは、次の場合にのみスワップをトリガーするため、これをきれいに処理します。`a[i] != i`。 

もう 1 つのエッジ ケースは、次のような単純な 2 サイクルです。`[2, 1, 3]`。 ここではピボット戦略が不可欠です。 直接スワップすると位置は固定されますが、フリップ パリティは矛盾したままになります。 ピボットを使用すると、要素が位置 1 を通過して確実に移動し、要素ごとに偶数の反転が作成されます。 

最後に、次のような長いサイクル`[5, 4, 3, 2, 1]`同じバッファを繰り返し使用する必要があります。 このアルゴリズムは、位置 1 までの各要素を独立して処理し、位置 1 が全体を通して変化しても、順列閉包によって正確さが保証される最後まで正しい必要がないことを保証します。
