 ## 解決策
 ## 問題の理解

 すべての位置に 0 または 1 のいずれかが含まれるバイナリ配列を操作しています。配列は 2 種類の演算を通じて時間の経過とともに変化します。 1 つの操作は、単一の位置を 0 から 1、または 1 から 0 に反転します。もう 1 つの操作は、特定のランクを上から見た場合に配列のソートされたバージョンに表示される値を要求します。 

重要な観察は、配列には 2 つの異なる値のみが含まれていることです。 これは、非昇順に並べ替えると、すべての 1 が最初に来て、すべての 0 が後に来ることを意味します。 したがって、ソートされた構造全体は、配列内に現在いくつあるかという 1 つの数値によって完全に決定されます。 

この制約では、最大 100,000 個の要素と 100,000 個のクエリが許可されます。 クエリごとに 1 の数を最初から再計算するソリューションでは、最悪の場合でも約 10^10 の演算が必要になりますが、これは 1 秒で可能な演算をはるかに超えています。 並べ替えられた配列を明示的に維持することさえ失敗します。反転するたびに線形更新または再並べ替えが必要になるためです。 

単純な間違いは、反転するたびにソートされた配列を物理的に維持しようとすることです。 たとえば、切り替えるたびに、ソートされた配列を再構築し、k 番目の要素を直接返すことができます。 各再構築は O(n) であるため、これは長い更新シーケンスではすぐに失敗します。 

もう 1 つの微妙な間違いは、クエリごとに配列全体をスキャンしてカウントを再計算することです。 これは単純に見えますが、やはり O(nq) 動作につながります。 

隠された構造は、すべてのクエリが 1 の位置ではなく 1 の数のみに依存するということです。 

## アプローチ

 ブルートフォースのアイデアは単純です。 クエリごとに、それがフリップの場合、配列を更新します。 クエリの場合は、配列を降順に並べ替えて、k 番目の要素を選択します。 ソートには O(n log n) のコストがかかり、これを最大 100,000 回実行すると、約 10^10 のログ操作が必要になり、これでは遅すぎます。 

また、配列をスキャンしてクエリごとに 1 をカウントするという、少し優れた総当たりアプローチを試すこともできます。 これによりソートのオーバーヘッドは削減されますが、それでもクエリごとに O(n) のコストがかかり、最悪の場合はやはり 10^10 の操作になります。 

重要な洞察は、配列には常に 0 と 1 のみが含まれるということです。 ソート後、最初のセグメントは完全に 1 になり、残りは 0 になります。 したがって、k 番目に大きい要素は、k が 1 のブロック内にあるかどうかによって決まります。 現在の 1 の数のみを維持する場合、すべてのクエリは O(1) になります。 フリップでは、その位置の前の値に応じてこのカウントが単純に増加または減少します。 

これにより、問題は単一の整数とバイナリ配列の維持に軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (再計算/並べ替え) | O(nq) または O(q・n log n) | O(n) | 遅すぎる |
 | 最適 (数えて 1) | O(n + q) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 配列自体と、現在存在する配列の数を格納するカウンターの 2 つの情報を維持します。 

1. 入力から配列を初期化し、すべての要素を合計して 1 の初期数を計算します。 これにより、あらゆるクエリに答えるために必要なベースラインが得られます。 
2. 位置 x のタイプ 1 クエリの場合、そのインデックスの値を反転します。 1 の場合は、1 の数を減らします。 0 の場合はインクリメントします。 これにより、再計算を行わずにカウンターが常に配列の実際の状態と一致することが保証されます。 
3. パラメーター k を持つタイプ 2 クエリの場合、k 番目に大きい要素が 1 か 0 であるかを決定します。ソート順ではすべての 1 が最初に来るため、k が 1 の数以下の場合、答えは 1 になります。それ以外の場合、答えは 0 でなければなりません。 
4. すべてのクエリに対してこのプロセスを繰り返し、必要に応じて回答を出力します。

これが機能する理由は、構造的不変条件に基づいています。配列は、概念的には常に 1 の後にゼロが続くプレフィックスに並べ替えることができ、そのプレフィックスの長さは正確に維持されるカウントになります。 すべてのフリップでは、このプレフィックス長が正確に ±1 ずつ更新されるため、カウントを超える履歴情報は必要ありません。 k 番目の要素のクエリは、そのプレフィックスのメンバーシップを確認することになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, q = map(int, input().split())
a = list(map(int, input().split()))

ones = sum(a)

out = []

for _ in range(q):
    t, x = map(int, input().split())
    if t == 1:
        x -= 1
        if a[x] == 1:
            a[x] = 0
            ones -= 1
        else:
            a[x] = 1
            ones += 1
    else:
        k = x
        if k <= ones:
            out.append("1")
        else:
            out.append("0")

print("\n".join(out))
```配列は、個々の位置を正しく反転することをサポートするためにのみ明示的に保存されます。 重要な最適化は、配列構造から直接答えを導き出さないことです。 不変の 1 の数だけを維持します。 

フリップ操作では、配列とカウンターの両方を一定時間内に注意深く調整します。 これにより、古いカウントが蓄積される再計算エラーが回避されます。 クエリ操作は、維持されているカウントとの 1 回の比較に削減されます。 

よくある実装上の間違いは、反転するときにインデックスを 1 ベースのインデックスから 0 ベースのインデックスに変換するのを忘れることです。 もう 1 つは、現在の値を確認する前にカウンタを更新することで、ロジックが反転します。 正しい順序は常に、最初に古い値を検査し、次に配列とカウンターの両方を一貫して更新することです。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n, q = map(int, input().split())
    a = list(map(int, input().split()))
    ones = sum(a)

    out = []
    for _ in range(q):
        t, x = map(int, input().split())
        if t == 1:
            x -= 1
            if a[x] == 1:
                a[x] = 0
                ones -= 1
            else:
                a[x] = 1
                ones += 1
        else:
            k = x
            out.append("1" if k <= ones else "0")

    return "\n".join(out)

 ## 特殊なケース

 エッジ ケースの 1 つは、配列が完全にゼロから始まる場合です。 この状況では、1 のカウンタは 0 であるため、フリップで 1 が導入されるまで、k 番目のクエリごとに 0 を返す必要があります。 たとえば、入力`[0,0,0,0]`クエリ付き`2 1`1 の接頭辞がまったくないため、正しく 0 が返されます。 

別のエッジ ケースは、同じインデックスの反転が繰り返されることです。 要素が複数回切り替えられる場合、その正しさは配列と同期してカウンターを更新するかどうかに完全に依存します。 たとえば、から始めて、`[1,0]`、位置 1 を 2 回反転すると、システムは元の状態に戻り、1 のカウンタは元の値に戻ります。 各フリップは対称であり、O(1) 更新で可逆であるため、アルゴリズムはこれを自然に処理します。 

最後の微妙なケースは、k が n と等しい場合です。 配列全体が 1 でない限り、これは常に 0 を返します。 ロジック`k <= ones`まだこれをきれいに処理します。`ones`決して超えることはできません`n`したがって、境界比較は特別な処理を行わなくても有効なままです。
