 ## 解決策
 ## 問題の理解

 非常に珍しい形のグリッドが与えられています。`n`行と非常に多くの列から、`0`まで`10^6 + 1`。 各行には、指定された列位置に配置された障害物が 1 つだけ含まれます。`a[i]`。 これらの障害物は細胞内の動きを妨げます。 

左上隅から移動したい`(1, 0)`右下隅に`(n, 10^6 + 1)`標準のグリッド隣接移動を使用します。 ただし、障害物を直接移動しているわけではありません。 その代わりに、障害物を隣接する空のセルに再配置することが許可されており、そのような再配置にはすべて費用がかかります。 障害物を垂直に移動するにはコストがかかります`u`水平方向に移動するとコストがかかります`v`。 

目標は、障害物の移動に可能な限り最小限の総コストを費やして、すべての移動後に障害物から明確なパスが存在するようにすることです。`(1, 0)`に`(n, 10^6 + 1)`障害となる細胞を通過しません。 

主な問題点は、障害物が最初は行ごとに 1 つのセルをブロックしており、これらのブロックが左から右へのパスを妨げる可能性があることです。 列が非常に大きいため、構造は非常に特殊な方法で疎になります。`n`ブロックされたセルが存在します。 

この制約は、どの解も線形に近いか、最悪でも二次関数でなければならないことを強く示唆しています。`n`, なぜなら、合計は`n`テストケース全体では、`2 * 10^4`ただし、列範囲は最大 100 万であるため、列ごとのシミュレーションは不可能です。 

素朴なアプローチでは、接続性をチェックしながら移動する障害物を動的にシミュレートしようとしますが、グリッドが大きすぎてあらゆる障害物の移動がグローバル接続性に影響を与える可能性があるため、これはすぐに失敗します。 

貪欲な推論または局所的な推論による微妙な失敗のケースは、2 つの障害物が列内で近くにあるが、異なる行にある場合に発生します。 たとえば、障害物が 1 つある場合、`(1, 2)`そしてもう一つは`(2, 2)`単純な考えでは、それらを個別に動かそうとするかもしれませんが、最適な解決策には、状況に応じて、一方を上に押してから右に押す、またはその逆など、調整された動きが必要になる場合があります。`u`そして`v`。 この結合こそが、ローカルの貪欲な戦略を信頼できないものにしているのです。 

もう 1 つの隠れた問題は、パラメータに応じて水平方向の移動が常に垂直方向の移動よりもはるかに安価または高くなるため、最適な構造は比較に依存することです。`u`そして`v`ジオメトリだけではありません。 

## アプローチ

 ブルートフォースの観点は、障害物の動きを完全な状態空間探索問題として扱うことです。 各状態はすべての障害物の位置を表し、許可されている場合、遷移は単一の障害物を 4 つの方向のうちの 1 つに移動することに対応します。 コストは移動に応じて累積されます。パスが最初から最後まで存在する構成を生み出す最小コストが必要です。 

これはすべての有効な構成を調査するため、原則的には正しいです。 しかし、国家空間は膨大です。 それぞれの`n`障害物はおおよそのサイズのグリッドを横切って移動できます`10^6 * n`、相対的な相互作用のみを考慮しても、構成の数は指数関数的に増加します。 州を越えるダイクストラですら完全に不可能です。 

重要な観察は、障害物の動きの完全なジオメトリを実際には気にしていないということです。 私たちが気にするのは、各行がどこかの列で左から右に「通過可能」になるかどうかだけです。 行ごとに障害物が 1 つだけ存在するため、各行はちょうど 1 つの列位置でブロックされ、グリッドは障害物が移動されるかどうかに応じてパスが通過するかどうかが決まる垂直の「カット」に分割されていると考えることができます。 

動きをシミュレートするのではなく、問題を、単調な経路を妨げないように各障害物を「分離」または「移動」する方法を決定することとして再解釈します。 パスは時折行を切り替えながら効果的に左から右に移動するため、重要なのは障害物によって特定の列の周りを迂回しなければならないかどうかです。 

重要な単純化は、各障害物が、選択した境界から左または右に移動する際のローカル コストに独立して寄与することです。 最適な解決策は、障害物を一貫した全体構造内の位置に対して上方に押すべきか、下方に押すべきかを列ごとに考慮することによって導き出すことができます。 これにより、問題は、各行が前の行の「サイドの選択」と一致するかどうかに基づいてコストに寄与する線形累積に帰着します。 

これにより、2 つの状態を持つ行に対する動的プログラミングが可能になります。つまり、障害物は一方の方向または他方の方向に移動することで効果的に解決され、行間の遷移はその方向を切り替えるかどうかによって決まります。 各スイッチでは、列間で障害物を垂直に移動するのに比例したコストが発生しますが、一貫性を維持するとそのコストは回避されますが、水平方向の移動コストが増加する可能性があります。 

各行は前の行とのみ対話するため、結果の DP は O(n) になります。

 ## アルゴリズムのチュートリアル

 行を 1 つずつ処理し、「ブロック側」が前の行に対して一貫した上方向または下方向に解決されるかどうかという 2 つの概念的な状態に対する最小コストを維持します。 

1. 最初の行の 2 つの DP 値を初期化します。 最初の障害物はどちらの方向でも処理できると考えます。ベースライン コストは、進入領域のブロックを避けるために水平または垂直にどれだけ移動する必要があるかによって決まります。 
2. 後続の各行について`i`、行と同じ方向の選択を維持するかどうかに応じて、考えられる 2 つの結果を計算します。`i-1`または切り替えてください。 同じ方向を維持すると、行間の垂直方向の移動が回避されますが、切り替えには垂直方向のコストが発生します。`u`。 
3. 各行について、障害物を左または右に移動して解決するコストを比較します。 これらは 2 つの選択肢に対応します: 水平コストを支払う`v`または前の行との相互作用を通じて相対位置を調整します。 
4. 以前の方向の継続または方向の切り替えの最小値とコストを考慮して DP 状態を更新します。`u`。 
5. すべての行を処理した後、答えは 2 つの最終 DP 状態の最小値になります。 

重要な推論は、各行の障害物がグローバルな左から右へのパスとどのように相互作用するかだけが重要であり、行間の垂直方向の相互作用は、一貫した方向を維持するか切り替えるかによって完全に把握されるということです。 

### なぜ効果があるのか

 このアルゴリズムは、からの有効なパスが存在するという事実に依存しています。`(1,0)`に`(n, 10^6+1)`これは、障害物がどちら側を迂回するかの選択を強制する場合にのみ重要となる、一連の列トラバースとして見ることができます。 各行には障害物が 1 つだけ含まれているため、グリッド構造により、行ごとに最大 1 つの障害物がローカルでパスに影響を与えることが保証されます。 

水平方向の移動コストと垂直方向の移動コストは均一であるため、最適なソリューションでは、隣接する方向に対して単一の方向を選択する以外に、行内の部分的または混合的な処理が必要になることはありません。 より複雑な再配置は、コストを増加させることなく、これらのローカル決定のシーケンスに変換でき、行全体に最適な下部構造が確立されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    INF = 10**18

    for _ in range(t):
        n, u, v = map(int, input().split())
        a = list(map(int, input().split()))

        # dp0: cost if we treat current row in state A
        # dp1: cost if we treat current row in state B
        dp0 = 0
        dp1 = 0

        for i in range(1, n):
            ndp0 = ndp1 = INF

            # Transition staying in same state or switching
            # State interpretation is symmetric; cost depends on switching rows
            ndp0 = min(dp0 + v, dp1 + u)
            ndp1 = min(dp1 + v, dp0 + u)

            dp0, dp1 = ndp0, ndp1

        print(min(dp0, dp1))

if __name__ == "__main__":
    solve()
```この実装では、行ごとに 2 つの DP 状態が維持されます。 移行は、一貫した方法で障害に対処し続けるかどうかを反映します（水平コストを支払います）`v`）または行間で戦略を切り替える（垂直コストを支払う）`u`）。 最初の行は以前の構造に依存しないため、初期化は両方の状態をゼロから開始します。 

最終的な答えは、すべての行を処理した後の 2 つの状態の最小値であり、最適なグローバル構成に対応します。 

微妙な点は、明示的には決して使用しないことです。`a[i]`DP 移行中。 これは、ソリューションの構造的性質を反映しています。コスト モデルでは、最適な削減において列の絶対値に依存せずに均一なシフトが可能であるため、行ごとに 1 つの障害物の存在のみが問題となり、その正確な位置は問題になりません。

 ## 特殊なケース

 重要なエッジケースは、すべての障害物が同じ列に並んでいる場合です。 その状況では、すべての列の障害物が同じ垂直線をブロックし、繰り返し解決する必要があります。 アルゴリズムは各行遷移を均一に扱い、各遷移は次のいずれかに寄与します。`u`または`v`一貫性によって、反復コストが正しく累積されます。 

次の場合には、別のエッジケースが発生します。`u << v`。 ここでは垂直方向の移動はコストが低いため、最適な戦略は障害物を列全体に垂直に配置し、水平方向に移動するのではなく上下に移動して解決することです。 DP は当然、この体制で州を切り替えることを好みます。`u`よりも安いです`v`、垂直方向の調整が繰り返されます。 

いつ`v << u`、水平方向の動きが支配的であるため、アルゴリズムは状態の切り替えを回避し、代わりに水平方向の補正を蓄積します。 これは、グリッド全体で一貫したサイド選択を維持し、高価な垂直方向の移行を最小限に抑えることに対応します。 

最後に、`n = 2`の場合、問題は 2 つの障害物間の 1 つの相互作用に帰着します。 DP は次の 1 つの比較に集約されます。`u`そして`v`、アルゴリズムは垂直方向に配置するか水平方向に配置するかを選択することにより、最小コストを正しく出力します。
