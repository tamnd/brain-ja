 ## 解決策
 ## 問題の理解

 私たちに与えられた木は、$n$頂点があり、それが Fib ツリーであるかどうかを判断したいと考えています。 Fib ツリーは、サイズがフィボナッチ数に等しいツリーです。$F_k$、単一の頂点で構成されているか、エッジを 1 つだけ削除することで 2 つの小さな Fib ツリーに分割できます。 言い換えれば、ツリーがエッジに沿ってサイズが連続したフィボナッチ数であるサブツリーに再帰的に分解できる場合、そのツリーは Fib ツリーです。 

入力により得られるのは、$n$そしてのリスト$n-1$ツリーを形成するエッジ。 出力は、ツリーが Fib-tree プロパティを満たすかどうかに応じて、単純な「YES」または「NO」になります。 最初のステップは、ツリーのサイズ自体がフィボナッチ数でなければならないことを認識することです。そうでない場合は、すぐに「NO」を返すことができます。 

と$n$まで$2 \cdot 10^5$1 秒の時間制限があるため、時間のかかるソリューションを提供する余裕はありません。$O(n^2)$。 これにより、サブツリーごとに考えられるすべてのエッジ除去を素朴に考慮するアプローチが排除されます。 もっと近いものが必要です$O(n \log n)$または$O(n \sqrt n)$最悪の場合。 

明らかではないエッジ ケースには、単一ノードまたは 2 つのノードなど、すでに Fib ツリーになっている小さなツリーが含まれます。 もう 1 つの微妙なケースは、ツリーを分割する方法が複数ある場合に発生します。少なくとも 1 つのエッジで有効なフィボナッチ分解が可能であることを確認する必要があります。 アルゴリズムがすべての可能性をチェックせずに特定の分割順序を仮定すると、誤って「NO」を返す可能性があります。 たとえば、サイズの木$3$エッジ付き$1-2$そして$2-3$は Fib ツリーですが、不注意なアプローチでは 1 つの分割のみをチェックし、有効な分解を見逃す可能性があります。 

## アプローチ

 ブルートフォース手法では、すべてのエッジを試して削除し、結果として得られる 2 つのサブツリーが Fib ツリーであるかどうかを確認します。 これは正しいです。Fib-tree プロパティは再帰的であるためです。エッジの削除から得られる 2 つのサブツリーが Fib-tree である場合、ツリー全体が Fib-tree になります。 ただし、このアプローチは遅すぎます。 がある$n-1$エッジごとにサブツリーのサイズを計算し、各サブツリーを再帰的にチェックする必要があります。 最悪の場合、これは次のような事態につながります$O(n^2)$受け入れられない操作$n = 2 \cdot 10^5$。 

重要な観察は、次のようなサイズの Fib ツリーでのことです。$F_k$、右端を削除して形成された 2 つのサブツリーには次のサイズが必要です。$F_{k-1}$そして$F_{k-2}$(前の 2 つのフィボナッチ数)。 この洞察により、問題は、サブツリー サイズが連続するフィボナッチ数と一致するエッジを効率的に見つけることに帰着します。 深さ優先検索 (DFS) を使用すると、任意のノードをルートとする各サブツリーのサイズを計算できます。 サイズが等しいサブツリーを見つけたとき$F_{k-1}$または$F_{k-2}$、対応するエッジを削除すると、ツリーが適切に分割されます。 次に、同じ手順を各サブツリーに再帰的に適用します。 

もう 1 つの重要な最適化は、フィボナッチ数とそのインデックスをメモ化して、各ステップで 2 つのサブツリーの予想サイズを迅速に決定できるようにすることです。 分割統治再帰により、各エッジがそのサブツリーのコンテキスト内で 1 回だけ考慮されるようになり、合計実行時間は次のようになります。$O(n \log n)$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 以下のすべてのフィボナッチ数を事前計算します。$2 \cdot 10^5$各フィボナッチ数からそのインデックスへのマッピングを保存します$k$。 もし$n$がこのセットにない場合は、すぐに「NO」を返します。 
2. ツリーを隣接リストとして構築します。 を初期化します`used`再帰的分割で削除されたエッジを追跡するための配列。 
3. DFS を実装して、各サブツリーのサイズを計算し、各ノードの親エッジを保存します。 
4. ある程度の大きさの木の場合$F_k$、目標は、削除によってツリーがサイズのサブツリーに分割されるエッジを見つけることです。$F_{k-1}$そして$F_{k-2}$。 DFS では、サブツリーのサイズが正確である場合$F_{k-1}$または$F_{k-2}$、対応するエッジをカットとしてマークし、結果として得られる両方のサブツリーを再帰します。 
5. 再帰は、サブツリーのサイズが 1 になると終了します。これは、明らかに Fib ツリーです。 
6. いずれかのステップで、ツリーを 2 つのフィボナッチ サイズのサブツリーに分割するエッジが見つからない場合は、「NO」を返します。 

機能する理由: このアルゴリズムは、再帰呼び出しごとに、サブツリーのサイズがフィボナッチ数であるという不変条件を保持します。 サイズのサブツリーを検索することによって$F_{k-1}$または$F_{k-2}$、結果として得られる 2 つのサブツリーが連続するフィボナッチ数に対応することを保証します。これはまさに Fib ツリーに必要なプロパティです。 DFS はすべてのエッジが効率的にチェックされることを保証し、再帰によってプロパティがすべてのサブツリーに保持されることを保証します。 

## Python ソリューション```python
import sys
sys.setrecursionlimit(1 << 25)
input = sys.stdin.readline

def main():
    n = int(input())
    edges = [[] for _ in range(n)]
    for _ in range(n-1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        edges[u].append(v)
        edges[v].append(u)
    
    # Precompute Fibonacci numbers up to 2*10^5
    fib = [1, 1]
    fib_idx = {1:1}
    while fib[-1] < 2*10**5:
        fib.append(fib[-1]+fib[-2])
        fib_idx[fib[-1]] = len(fib)-1
    
    if n not in fib_idx:
        print("NO")
        return
    
    used = [False]*n
    
    def solve(u, size):
        if size == 1:
            return True
        k = fib_idx[size]
        target1, target2 = fib[k-1], fib[k-2]
        
        parent = [-1]*n
        sz = [0]*n
        found = [None]
        
        def dfs(v, p):
            sz[v] = 1
            parent[v] = p
            for to in edges[v]:
                if to == p or used[to]:
                    continue
                dfs(to, v)
                sz[v] += sz[to]
            if sz[v] == target1 or sz[v] == target2:
                found[0] = (v, parent[v])
        
        dfs(u, -1)
        
        if found[0] is None:
            return False
        
        x, y = found[0]
        used[x] = True
        used[y] = True
        return solve(x, sz[x]) and solve(y, size - sz[x])
    
    if solve(0, n):
        print("YES")
    else:
        print("NO")

main()
```コードは、フィボナッチ数を事前計算し、それらをインデックスにマッピングすることから始まります。 の`used`配列は、以前の分割の一部であったノードをマークし、物理的にエッジを削除せずにツリーを効果的に切断します。 DFS はサブツリーのサイズを計算し、分割する有効なエッジを特定します。 再帰呼び出しは、サイズ 1 のサブツリーに到達するまで続けられます。 微妙な点には、再訪問を防ぐためにエッジの両端を使用済みとしてマークすること、サブツリーが正確に一致する場合の処理​​が含まれます。`target1`または`target2`、および再帰終了条件。
