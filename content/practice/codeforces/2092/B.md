 ## 問題の理解

 同じ長さの 2 つのビット列が与えられています。`a`そして`b`、パスワードを表します。 てんとう虫は最初の文字列を変換したい`a`ゼロのみが含まれるようにします。 彼女は、2 つの文字列の隣接する要素間で一連の交換操作、具体的には次のいずれかの交換操作を実行できます。`a[i]`と`b[i-1]`または`b[i]`と`a[i-1]`のために`i`2から`n`。 目的は、このような交換を何度でも行った後、文字列が`a`すべてゼロになる可能性があります。 

それぞれのテストケースで得られるものは、`n`、文字列の長さ、その後に 2 つの文字列自体が続きます。 テスト ケースの数は最大 10,000 まで可能で、すべてのテスト ケースにわたるすべての文字列の長さの合計が 200,000 を超えることはありません。 これは、ほぼ線形の解決策が必要であることを意味します。`n`そうしないと、考えられるすべてのスワップの総当りシミュレーションが遅すぎます。 

重要なエッジケースは、次の最初の要素が`a`は`1`そしての最初の要素`b`は`0`。 スワップにはインデックスのみが関与するため、`i ≥ 2`を直接移動することはできません。`1`で`a[1]`に`b[0]`または、パスワードの解読が不可能になる他の場所。 同様に、`b`はありません`1`到達できる場所ならどこでも`1`で`a`、私たちも失敗します。 小さい`n=2`利用可能なスワップが少数しかなく、文字列がすぐに解決できなくなる可能性があるため、このケースは重要です。 

## アプローチ

 素朴なアプローチは、文字列間で起こり得るすべての交換をシミュレートすることです。 各インデックスで`i`、どちらかの状態になるまで、両方の操作を再帰的または反復的に試行できます。`a`すべてゼロになるか、すべての可能性が使い果たされます。 これは正しいことが保証されていますが、完全に非現実的です。状態の数は、次のように指数関数的に増加します。`n`、 まで`2^n`、これは小さい場合でも 1 秒の制限をはるかに超えています。`n`。 

重要な洞察は、それぞれの`1`で`a`に「押し込む」ことができます`b`利用可能なスワップを使用します。 それぞれのスワップにより、`1`で`a[i]`に移動する`b[i-1]`または`1`で`b[i]`に移動する`a[i-1]`。 これは、文字列を左から右にスキャンする場合、唯一の状況が発生することを意味します。`1`で`a`がある場合は削除できません。`1`で`a[i]`そしていいえ`1`で`b[i-1]`または`b[i]`それはそれに到達することができます。 基本的に、すべての`1`で`a`で`i`どちらかを持っている必要があります`b[i-1]`またはその後の`b[j]`その位置に切り替えることができます。 

さらに単純化すると、必要なのは総数を数えるだけです。`1`にいる`a`そして`b`。 文字列のプレフィックスごとに、`1`にいる`b`少なくとも累積数でなければなりません`1`にいる`a`。 いずれかのインデックスの場合、累積`1`にいる`a`を超える`b`が多すぎるため、プロセスは失敗します。`1`にいる`a`それは移動できないものです。 これにより、問題が単一の線形スキャンに変換されます。

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る`t`。 
2. 各テスト ケースについて、次の内容を読んでください。`n`そして文字列`a`そして`b`。 
3. 2 つのカウンターを初期化します。`count_a`の数に対して`1`にいる`a`これまで見てきた、そして`count_b`の数に対して`1`にいる`b`これまで見られた。 
4. 文字列を左から右に繰り返します。 各インデックスで`i`、増分`count_a`もし`a[i]`は`1`そして`count_b`もし`b[i]`は`1`。 
5. いつでも`count_a`を超える`count_b`、このテスト ケースでは「NO」を出力します。 これは、さらに多くのものが存在することを示しています`1`にいる`a`によって「吸収」されるよりも、`b`このインデックスまで。 
6. 何もせずに反復が完了した場合`count_a > count_b`、「YES」を出力します。 

機能する理由: 各スワップで移動できるのは`1`から`a[i]`に`b[i-1]`またはから`b[i]`に`a[i-1]`。 By ensuring that for every prefix of the string, the total number of`1`にいる`b`少なくとも次の数です`1`にいる`a`、私たちはそれぞれを保証します`1`で`a`最終的には押し込まれる可能性がある`b`許可された操作を使用しています。 この累積的なカウントにより、それぞれの到達可能性が把握されます。`1`個々のスワップをシミュレートせずに。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = input().strip()
    b = input().strip()
    
    count_a = 0
    count_b = 0
    possible = True
    
    for i in range(n):
        if a[i] == '1':
            count_a += 1
        if b[i] == '1':
            count_b += 1
        if count_a > count_b:
            possible = False
            break
    
    print("YES" if possible else "NO")
```コードは、次を使用して入力を効率的に読み取ります。`sys.stdin.readline`。 の累積数を追跡します。`1`両方の文字列に s が含まれています。 ループは、任意の時点でさらに存在するかどうかをチェックします。`1`にいる`a`と一致するよりも`b`。 早めに中断することで、不必要な繰り返しを防ぐことができます。
