[CF 1650F - Vitaly および高度な役に立たないアルゴリズム](https://codeforces.com/problemset/problem/1650/F)

 **タグ:** dp、貪欲、実装

 **確認済み:** いいえ

 ## 解決策
 ## 問題の理解

 締め切りがすでに設定されている一連のコース課題があります。 

割り当て`i`絶対時間までに完全に完了する必要があります`a[i]`。 最初はすべての割り当てに次のような特徴があります`0%`進捗。 

がある`m`利用可能なトレーニング オプション。 オプション`j`正確に 1 つの割り当てに属します`e[j]`。 過ごしたら`t[j]`そのオプションの時間、課題の完了率`e[j]`増加します`p[j]`。 各オプションは最大 1 回使用できます。 

オプションは、当社が選択した順序で次々に実行されます。 時間は地球規模で蓄積されます。 いくつかのオプションを実行した後の合計経過時間は、それらの期間の合計になります。 

あらゆる課題に対して`i`、期限に達した瞬間までに`a[i]`、割り当てに属するオプションから得られる合計パーセンテージ`i`少なくとも`100`。 

個別のオプションの有効なシーケンスを構築するか、そのようなシーケンスが存在しないと判断する必要があります。 

最も重要な観察は、期限が時間の接頭語に付加されていることです。 締め切り時`a[i]`あらゆる任務が到着する`1..i`少なくともすでに到達しているはずです`100%`、期限は遅くても`a[i]`。 

制約はソリューションを推進するものです。 それでも`n`そして`m`それぞれは次のように大きくできます`10^5`、の合計`n+m`すべてのテストケースにわたって、`2·10^5`。 これにより、指数関数的なものはすぐに排除され、すべてのオプションをグローバルに実行する大きなナップザックも排除されます。 線形に近いものが必要です。`O(m · constant)`テストケースごとに。 

重要な隠れた制約は、どのパーセンテージの利益も最大でも次のとおりであるということです。`100`。 つまり、各割り当ては、からの進行状況の値のみを考慮します。`0`に`100`、小さなナップサック状態を示唆しています。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

オプションのある 1 つの割り当てを考えてみましょう。```
deadline = 10

(t=10,p=100)
(t=1,p=60)
(t=1,p=40)
```単一の 100% オプションを使用すると機能し、10 時間かかります。 他の 2 つのオプションを使用しても同様に機能し、所要時間はわずか 2 時間です。 実現可能性のみを確認する場合、どちらも有効であるように見えます。 ただし、締め切りが遅い場合は、合計時間が短い方が常に優れています。 ソリューションでは、各割り当てにかかる時間を最小限に抑える必要があります。 

もう 1 つの罠は、進行状況の過剰充填です。```
deadline = 5

(t=2,p=70)
(t=2,p=70)
```進行度は140%になります。 これは完全に合法です。 正確な合計のみを保存し、100 を超える値をクランプすることを忘れた DP では、この解決策が得られません。 

3 番目の罠は、割り当ては時間を通じてのみ相互作用するということです。```
assignment 1 deadline = 5
assignment 2 deadline = 6
```たとえ課題 2 が最終的に完了できたとしても、課題 1 に時間がかかりすぎて、期限までに余裕がなくなる可能性があります。 割り当てのために選択されたすべてのオプションに費やした累積時間`1..i`決して超えてはならない`a[i]`。 

## アプローチ

 ブルートフォースアプローチでは、オプションのサブセットを調べて、それらをスケジュールしようとします。 単一の割り当てであっても、何千ものオプションがある場合があります。`2^m`まったく不可能です。 

次のアイデアは、割り当てを独立して処理することです。 固定割り当ての場合、進行状況の合計が少なくとも次のレベルに達するオプションのサブセットが必要です。`100`、合計期間は可能な限り短くなります。 

これは突然、ナップザックの問題に似ています。 

各オプションは次のことに貢献します。```
weight = duration t
value = progress p
```少なくとも価値に達したい`100`重量を最小限に抑えながら。 

通常、ナップザックは持続時間が最大になる可能性があるため、高すぎます。`10^9`。 重要な観察は、進歩には限界があるということです。`100`。 時間に応じた DP の代わりに、進行状況に応じて DP を実行します。 

1 つの課題について、```
dp[x] = minimum time needed to obtain exactly x progress
```ここで、上記のすべての値は`100`に固定されている`100`。 

進歩が超えることはないから`100`、状態空間は`101`。 

割り当ての達成可能な最小時間を計算した後、それを以前の割り当てに費やした累積時間に追加します。 累積時間がその割り当ての期限を超える場合、スケジュールは存在しません。 

残る課題は復興だ。 実際のオプションインデックスを出力する必要があります。 ナップザックの実行中に、親情報を保存し、どのオプションが最適なサブセットを形成したかを再構築します。 

素晴らしい点は、合計経過時間への影響を除いて、割り当てが独立していることです。 各課題に必要な最小期間がわかったら、それより遅いものを使用すると、期限を守ることが難しくなるだけです。 したがって、すべての割り当てに対するローカルな最適な選択は、グローバルな最適な選択でもあります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^m) | O(m) | 遅すぎる |
 | 最適 | O(m・100) | O(m + 100) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのオプションを、それらが属する割り当てごとにグループ化します。 
2.からの割り当てを処理します`1`に`n`期限順に。 
3. 現在の割り当てについては、進行状況に応じて 0/1 ナップザックを実行します。 

させて`dp[s]`進行状況に到達するために必要な最小合計期間である`s`、すべての進行状況の値が より大きい`100`状態として保存されます`100`。 
4. 初期化します。```
dp[0] = 0
dp[1..100] = INF
```5. この割り当てのオプションを 1 つずつ繰り返します。 

各オプションについて`(t, p)`、標準の 0/1 ナップザックとまったく同じように DP を逆方向に更新します。 
6. 移行するたびに```
old_state -> new_state
```より良い持続時間を取得するには、親情報を記録します。 これにより、後で選択したオプションを再構築できるようになります。 
7. すべてのオプションが処理されたら、検査します。`dp[100]`。 

無限のままだと100%完成は不可能なので答えは`-1`。 
8. 状態から保存された親ポインターに従って、選択したオプションのインデックスを再構築します。`100`。 
9. 最小期間を追加します`dp[100]`以前の割り当てにすでに費やされた累積時間に加算されます。 
10. 累計時間が期限を超えた場合`a[i]`、出力`-1`。 

これは、課題を完了する最速の方法でもあることを意味します`1..i`締め切りに間に合わない。 
11. それ以外の場合は、再構築されたオプション インデックスをグローバル応答シーケンスに追加します。 
12. 次の課題に進みます。 
13. すべての割り当てが正常に処理された後、収集されたオプション インデックスを出力します。 

### なぜ効果があるのか

 固定割り当ての場合、DP は、進行状況が少なくとも`100`。 状態空間には、考えられるすべての上限付き進行状況値が含まれます。`0`に`100`, したがって、実行可能なサブセットは無視されません。 

課題が時間内に完了できると仮定します`X`、そしてDPは戻ります`Y > X`。 次に、サブセットが達成する`X`これは、有効な DP 遷移シーケンスに対応し、最小格納値の最適性と矛盾します。 したがって、DP は実際に最小期間を見つけます。 

すべてのオプションは 1 つの割り当てにのみ属しているため、割り当てはオプションをめぐって競合しません。 割り当て間の唯一の相互作用は、累積経過時間です。 一部の課題の最短期間の完了計画を、より遅い計画に置き換えても、期限を守ることはできません。 したがって、割り当てのすべての最小期間の合計は`1..i`すでに期限を過ぎています`a[i]`、有効なスケジュールが存在しません。 逆に、最小期間のすべてのプレフィックスがその期限を満たしている場合、選択されたサブセットの割り当てを割り当てごとに実行すると、有効なスケジュールが生成されます。 

これは正しさを証明します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**30

def solve():
    t = int(input())

    out = []

    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))

        by_task = [[] for _ in range(n)]

        for idx in range(1, m + 1):
            e, tt, p = map(int, input().split())
            by_task[e - 1].append((tt, p, idx))

        total_time = 0
        answer = []
        possible = True

        for task in range(n):
            opts = by_task[task]

            k = len(opts)

            dp = [INF] * 101
            dp[0] = 0

            parent_state = [[-1] * 101 for _ in range(k + 1)]
            used_option = [[-1] * 101 for _ in range(k + 1)]

            for i in range(k):
                tt, p, idx = opts[i]

                ndp = dp[:]

                for s in range(101):
                    if dp[s] == INF:
                        continue

                    ns = min(100, s + p)
                    cand = dp[s] + tt

                    if cand < ndp[ns]:
                        ndp[ns] = cand
                        parent_state[i + 1][ns] = s
                        used_option[i + 1][ns] = i

                for s in range(101):
                    if ndp[s] == dp[s]:
                        if parent_state[i + 1][s] == -1:
                            parent_state[i + 1][s] = s

                dp = ndp

            best = dp[100]

            if best == INF:
                possible = False
                break

            total_time += best

            if total_time > a[task]:
                possible = False
                break

            chosen = []

            state = 100

            for i in range(k, 0, -1):
                if parent_state[i][state] == -1:
                    state = state
                    continue

                prev = parent_state[i][state]

                if used_option[i][state] != -1:
                    opt_index = used_option[i][state]
                    chosen.append(opts[opt_index][2])

                state = prev

            chosen.reverse()
            answer.extend(chosen)

        if not possible:
            out.append("-1")
        else:
            out.append(str(len(answer)))
            out.append(" ".join(map(str, answer)))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```DP寸法は`101`これは、解決を迅速に行うための重要な観察です。 

再構成配列には次のインデックスが付けられます。`(processed_options, progress_state)`。 遷移によって状態が改善されると、以前の進行状況と、どのオプションが遷移を作成したかの両方を記憶します。 

進行状況の値が次より大きい`100`すぐに締め付けられる`100`。 多くの有効な解決策は、`100%`。 

期限チェックは、現在の割り当ての最小期間を追加した後に実行されます。 その時点で、割り当てのプレフィックスに対して可能な最小の累積時間を計算しました。 それさえも期限を過ぎた場合、他の選択肢を選択しても修復できません。

 ## 特殊なケース

 ### 進捗が 100% を超えました

 入力:```
1
1 2
10
1 1 70
1 1 70
```最初のオプションは進行状況 70 に達します。2 番目のオプションは進行状況 140 に達します。DP はこれを状態 100 として保存します。完了時間は 2 になります。クランプがなければ状態 140 は存在せず、解が失われる可能性があります。 

### 課題は完了可能ですが、期限を過ぎています

 入力:```
1
1 2
3
1 2 60
1 2 60
```100% に達する唯一の方法は 4 時間かかります。 DP は継続時間 4 を正しく検出します。これをプレフィックス合計に追加すると、次のようになります。```
4 > 3
```したがって、アルゴリズムは戻ります`-1`。 

### 100% を達成するための複数の方法

 入力:```
1
1 3
10
1 10 100
1 1 60
1 1 40
```解決策は 2 つあります。```
10 hours -> 100%
2 hours -> 100%
```DP はすべての進行状態の最小期間を格納するため、状態 100 は値 2 で終了します。再構築は対応する親ポインターに従い、より高速なサブセットを出力します。 

### 1 つの課題が完了していない

 入力:```
1
2 1
5 10
1 1 100
```課題 1 は完了できます。 課題 2 にはオプションがまったくありません。 

DP は終了します`dp[100] = INF`、したがってアルゴリズムはすぐに出力します`-1`すべての割り当てが少なくとも 100% に達する必要があるため、これは正解です。
