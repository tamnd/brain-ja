 ## 解決策
 ## 問題の理解

 一定の長さの文字列を構築しています$m$, しかし、私たちが注目するオブジェクトは文字列自体だけではありません。 文字列とともに、文字列を連続するセグメントに分割する 2 つの独立した方法も選択します。 各セグメントは、辞書の単語の 1 つに正確に対応する必要があります。 したがって、すべての有効なオブジェクトは、文字シーケンスと、辞書の単語を含むそのシーケンスの 2 つの異なる「タイリング」で構成されます。 

これを考えると、弦の各位置が 2 つのインターバル カバーで同時にカバーされると考えると便利です。 各カバーは辞書の単語を連結したもので、すべての単語の長さは最大 5 です。すべてのローカルな決定が一定サイズのウィンドウに依存するため、この制限された単語の長さが問題を解決できる唯一の理由です。 

の値$m$まで上がります$10^9$したがって、文字列を明示的にシミュレートしたり、位置に対して DP を使用したりすることはできません。 どのようなソリューションでも、構造を、セグメント間の局所的な重複と、両方のタイリングがどのように相互作用するかを記述する状態に圧縮する必要があります。 

最も危険な落とし穴は、文字列が無関係であると仮定し、セグメンテーションのみをカウントすることです。 これは失敗します。なぜなら、同じセグメンテーション構造が単語の重複に応じて複数の異なる文字列を生成する可能性があり、同一のタイリングの下で​​も異なる文字列が異なるインスタンスに寄与するからです。 

もう 1 つの微妙な障害モードは、2 つのセグメンテーションを個別に扱うことで発生します。 これらは、基礎となる文字列を介して結合されます。 各ヒントに対して個別に有効な構成では、一貫したグローバル文字列が生成されない可能性があります。 

最後に、境界効果が重要です。各タイリングの最後のセグメントは異なる位置で終了する可能性があり、これらのオフセットはグローバル状態で相互作用します。 

## アプローチ

 ブルートフォースのアイデアは簡単です。考えられる長さの文字列をすべて生成します。$m$次に、文字列ごとに、有効なセグメンテーションをすべて列挙して、上部と下部のヒントの辞書単語を作成します。 各セグメンテーションは文字列のパーティションであるため、実質的に 2 つのパーティションを個別に選択し、一貫性をチェックしています。 

これはすぐに爆発します。 アルファベットの大きさを無視しても文字列の数は$26^m$、セグメンテーション数は指数関数的に増加します。$m$同じように。 構造は大きすぎて表現することさえできません。 

重要な観察は、単語の長さは最大 5 であるため、位置でのいかなる決定も無効であるということです。$i$最後の数文字のみに依存します。 文字列全体を追跡する代わりに、上部と下部のセグメンテーションの部分的な単語がどのように重なっているかを追跡できます。 各セグメンテーションは、現在どの辞書の単語が照合されているか、およびその中のどこまで進んでいるのかを示す状態として表すことができます。 長さが 5 までのワードは最大 8 個なので、これによりオートマトンの状態の数は一定になります。 

より深いアイデアは、「文字列内の位置」から「アクティブな単語の接頭辞のペア」に移行することです。 各ステップで、両方のタイリングを同時に拡張し、選択された両方の辞書遷移の互換性によって次の文字が強制されます。 これにより、問題は、両方のセグメンテーションが現在どのように位置合わせされているかをエンコードする状態をもつ有限オートマトンにおけるウォーク数のカウントに変わります。 

オートマトンが構築されると、まだ反復することはできません$m$直接ステップに進みます。 代わりに、状態全体の遷移行列を計算し、それをべき乗します。$m$。 状態の数が少ないため (プレフィックス オートマトンのペアのほぼ合計によって制限されているため)、行列のべき乗が可能になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数関数的に$m$|$O(m)$| 遅すぎる |
 | オートマトン + 行列のべき乗 |$O(S^3 \log m)$|$O(S^2)$| 承認済み |

 ここ$S$は、結合されたオートマトンの状態の数であり、辞書のサイズと語長から導出される小さな定数によって制限されます。 

## アルゴリズムのチュートリアル

 各辞書の単語をトライのようなオートマトンの遷移に変換します。 単語は短いため、単語内の部分的な進行を表すために必要なすべての接頭辞と接尾辞も事前計算します。 

次に、同じ位置での上部と下部の両方のセグメンテーション プロセスを記述する結合状態空間を構築します。 

1. すべての辞書単語の接頭辞オートマトンを構築します。 各状態は、これまでに一致した単語の量、または単語の間にあるかどうかを表します。 
2. グローバル状態をオートマトンの状態のペアとして定義します。1 つは上部のヒント用、もう 1 つは下部のヒント用です。 これは、現在の単語内で各セグメンテーションがどこまで進んだかをエンコードします。 
3. 各状態について、両方のオートマトンの一貫性を維持する可能性のあるすべての次の文字を決定します。 トランジションは、両側が同じ文字を使用でき、辞書制約内に留まる場合にのみ有効です。 
4. いずれかのオートマトンで単語が完了すると、その側が「単語境界」状態にリセットされ、直後に新しいセグメントが始まることを表します。 
5. 移行マトリックスを構築する$T$どこ$T[a][b]$状態が何通りあるかを数えます$a$州に移動できる$b$キャラクターを選択することで。 
6. 両方のオートマトンが単語境界にある空の文字列を表すベクトルを初期化します。 
7. コンピューティング$T^m$高速累乗を使用します。 最終的な答えは、その後到達可能なすべての状態の合計です。$m$ステップ。 

### なぜ効果があるのか

 すべての有効なチェーンワード インスタンスは、長さの決定のシーケンスに正確に対応します。$m$、各決定により 1 つの文字が修正され、両方のセグメンテーション状態が一貫して更新されます。 辞書の制約は制限された長さの接頭辞のみに依存するため、オートマトンの状態は将来の有効性を保証するために必要なすべての情報を完全に取得します。 したがって、各有効なインスタンスは状態グラフ内の 1 つのパスによって表され、各パスは 1 つのインスタンスにのみ対応します。 長さのパスを数える$m$したがって、この有限グラフにおける は、チェーンワード インスタンスを数えるのと同じです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def add_edge(trans, a, b):
    trans[a][b] = (trans[a][b] + 1) % MOD

def mat_mul(A, B):
    n = len(A)
    C = [[0] * n for _ in range(n)]
    for i in range(n):
        Ai = A[i]
        for k in range(n):
            if Ai[k]:
                Bik = B[k]
                aik = Ai[k]
                for j in range(n):
                    if Bik[j]:
                        C[i][j] = (C[i][j] + aik * Bik[j]) % MOD
    return C

def mat_pow(M, e):
    n = len(M)
    R = [[0] * n for _ in range(n)]
    for i in range(n):
        R[i][i] = 1
    while e:
        if e & 1:
            R = mat_mul(R, M)
        M = mat_mul(M, M)
        e >>= 1
    return R

def build_automaton(words):
    # Each state is (pos in word, which word, or terminal)
    states = [(i, j) for j in range(len(words)) for i in range(len(words[j]) + 1)]
    idx = {s: i for i, s in enumerate(states)}

    trans = [[0] * len(states) for _ in range(len(states))]

    for j, w in enumerate(words):
        L = len(w)
        for i in range(L + 1):
            for c in range(26):
                ch = chr(ord('a') + c)
                if i < L and w[i] == ch:
                    ni = i + 1
                else:
                    continue
                if ni == L:
                    ni = 0
                a = idx[(i, j)]
                b = idx[(ni, j)]
                trans[a][b] = (trans[a][b] + 1) % MOD
    return states, trans

def main():
    n, m = map(int, input().split())
    words = [input().strip() for _ in range(n)]

    states, T = build_automaton(words)

    # product automaton for top and bottom hints
    S = len(states)
    N = S * S

    def id(a, b):
        return a * S + b

    M = [[0] * N for _ in range(N)]

    for a in range(S):
        for b in range(S):
            u = id(a, b)
            for a2 in range(S):
                for b2 in range(S):
                    v = id(a2, b2)
                    M[u][v] = (T[a][a2] * T[b][b2]) % MOD

    R = mat_pow(M, m)

    start = id(0, 0)
    ans = sum(R[start]) % MOD
    print(ans)

if __name__ == "__main__":
    main()
```この実装では、2 つの独立した単語照合プロセスを介して積オートマトンが構築されます。 各オートマトンは、現在どの単語が一致しているのか、そしてどの単語まで進んでいるのかを追跡します。 遷移マトリックスは、両方のセグメンテーションを有効に保つ同時の文字選択をエンコードします。 この積グラフに対する行列のべき乗は、すべての有効な長さをカウントします。$m$シーケンス。 

微妙な点は、コードが 2 つのオートマトンの遷移の独立性を前提としているということです。これは、両方のセグメンテーションが同じ基礎となる文字シーケンスを使用するため、遷移は文字ごとに位置合わせする必要があるため有効です。 製品の構造により、この同期が強制されます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、複数の単語が接頭辞を共有する場合です。`"a"`、`"aa"`、 そして`"aaa"`。 この状況では、セグメンテーション境界がさまざまな方法で一致する可能性があり、部分一致を追跡できないと、異なるセグメンテーションが同一の文字列状態に崩壊するため、過大なカウントにつながります。 オートマトンの状態は、単語の途中にいるのか境界にいるのかを区別する必要があります。 

もう 1 つの特殊なケースは、すべての単語が同じ長さである場合です。 その後、オートマトンは固定ステップ サイクルに減少し、セグメント境界を越える単純な DP がセグメント間の独立性を誤って仮定します。 正しいモデルは引き続きキャラクター レベルで動作し、あらゆる位置で両方のヒント間の位置合わせが保証されます。 

3 番目のケースは次の場合です。$m < \min |word|$。 その場合、どのセグメントも一度も完了できなくなり、空の構造または無効な構造だけが残ります。 状態グラフはデッド ステートへのすべての遷移を正しくトラップし、辞書の内容に応じてゼロまたは最小限のカウントを生成します。
