 ## 解決策
 ## 問題の理解

 いくつかのセルがブロックされ、残りのセルが使用できるグリッドが与えられています。 使用可能なすべてのセルは、赤または青のいずれかに色付けされている必要があります。 

色を選択したら、できるだけ多くのドミノを配置します。 水平ドミノは、両方のセルが赤である場合にのみ、2 つの隣接する使用可能なセルをカバーできます。 垂直ドミノは、両方のセルが青色の場合にのみ、2 つの隣接する使用可能なセルをカバーできます。 ドミノは重ねることができません。 

使用可能なセルのすべての可能な色について、配置できるドミノの最大数を計算します。 タスクは、すべてのカラーリングにわたるこれらの最大値を合計し、結果のモジュロを報告することです。`998244353`。 

最初に注意すべきことは、ボードには最大で次のものを含めることができるということです。`3·10^5`細胞。 以来`nm ≤ 3·10^5`1 つの次元が非常に大きく、もう 1 つの次元が小さい場合がありますが、セルの総数は制限されたままになります。 

色を直接列挙することは不可能です。 白マスが 50 個しかないボードでも、すでに`2^50`着色料。 ここでは、最大で`3·10^5`したがって、個々の色を理由とするアプローチは完全に除外されます。 

2 番目の制約はより微妙です。 答えはすべての色の合計ですが、合計される量はマッチングに似た最大値です。 この形式の問題は、加算順序を逆にして、特定の局所構造に寄与する色の数を数えると、扱いやすくなることがよくあります。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

長さ 1 の行セグメントを考えてみましょう。```
o
```そこに水平ドミノを置くことはできません。 すべての白セルが何らかのペアに参加していると盲目的に仮定する式は、過剰にカウントされてしまいます。 

長さ 2 の行セグメントを考えてみましょう。```
oo
```カラーリングは4種類あります。```
RR -> 1 domino
RB -> 0
BR -> 0
BB -> 0
```このセグメントの合計寄与度は 1 です。隣接するすべてのペアを個別にカウントする単純なカウント引数では、異なるドミノ配置が相互作用するため、間違った値が取得されます。 

もう 1 つの重要なケースは、長く連続したセグメントです。```
ooooo
```着色用```
RRRRR
```水平ドミノの最大数は 4 ではなく 2 です。隣接する候補ペアは重複するため、有効なペアを個別にカウントすることはできません。 

ソリューション全体は、これらの重複を正しく処理することを中心に展開します。 

## アプローチ

 ブルートフォースを試してみるとします。 

すべての白いセルの色ごとに、水平の赤いドミノと垂直の青いドミノの最大数を決定します。 次に、これらの値を答えに追加します。 

これはステートメントの直後にあるため、正しいです。 残念ながら、あります`2^w`着色、ここで`w`白血球の数です。 と`w`到達`3·10^5`、これは天文学的な大きさです。 

重要な観察は、最大値が隣接する白血球ペアの独立した寄与に分解されることです。 

まずは水平ドミノに注目してください。 

連続した長さの白セルの最大の水平セグメントを取得します。`L`。 固定カラーの場合、このセグメント内の水平ドミノの最大数は、頂点がセルであり、使用可能なエッジが隣接する赤と赤のペアであるパス上の最大一致数に等しくなります。 

すべてのカラーリングの最大一致を合計する代わりに、別の質問をします。 

セグメント内の特定の隣接するセルのペアについて、このペアは何色で貪欲マッチングに参加しますか?

 この観点から、出現する一致するペアの数に応じてカラーリングをカウントする DP が得られます。 

驚くべき単純化は、すべての最大の白色セグメントを独立して処理できることです。 水平ドミノは行セグメントのみに依存します。 垂直ドミノは柱セグメントのみに依存します。 

させて`f[L]`長さのセグメントによって寄与される水平ドミノの総数を示します`L`そのセグメントのすべてのカラーリングに適用されます。 一度`f[L]`既知である、すべての行セグメントの長さ`L`貢献する```
f[L] * 2^(total_white - L)
```セグメントの外側のセルは任意に色付けされる可能性があるため、グローバルな答えになります。 

まったく同じ理由が列セグメントにも当てはまります。 

残りのタスクはコンピューティングです`f[L]`。 

セグメントの左端の位置を考えてみましょう。 

最初の 2 つのセルがドミノを形成する場合、両方とも赤でなければなりません。 これにより、1 つの一致したペアが提供され、長さのセグメントが残ります。`L-2`。 

それ以外の場合、最初のセルは一致したペアで使用されず、長さのセグメントが残ります。`L-1`。 

これにより、公式の解決策と同じ繰り返しが得られます。 

しましょう`dp[i]`= ある長さのすべての色に対する合計寄与度 -`i`セグメント。 

最初の 2 つのセルが一致するドミノになるカラーリングには、追加のドミノが 1 つと、残りのサフィックスに表示されるものがすべて含まれます。 

その結果生じる再発は、$$dp[i] = 2dp[i-1] + dp[i-2] + 2^{i-2}.$$最後の項では、最初の 2 つのセルが両方とも赤で、新しく作成されたドミノを形成する色をカウントします。 

これらの値を事前計算した後、すべての行セグメントと列セグメントをスキャンし、それらの寄与を蓄積します。

 ## アルゴリズムのチュートリアル

 1. 白血球の総数を数え、それを呼び出します`w`。 
2. 2 のべき乗モジュロを事前計算する`998244353`まで`w`。 
3. DP 配列を事前計算します。 

させて`dp[i]`単一の長さの白いセグメントが寄与するドミノの総数になります。`i`そのセグメントのすべてのカラーリングにわたって。 

使用$$dp[i] = 2dp[i-1] + dp[i-2] + 2^{i-2}.$$と$$dp[0]=0,\quad dp[1]=0.$$4. すべての行をスキャンします。 

長さの白セルの最大連続ランをそれぞれ見つけます。`len`。 

最終的な答えへの貢献度は次のとおりです。$$dp[len] \cdot 2^{w-len}.$$この値を答えに追加します。 
5. すべての列をスキャンします。 

再度、白セルの最大連続ランをすべて見つけます。 

長いランの場合`len`、 追加$$dp[len] \cdot 2^{w-len}.$$6. 累積された答えのモジュロを出力します。`998244353`。 

### なぜ効果があるのか

 固定行セグメントの場合、`dp[len]`すでに、そのセグメントのすべての色における水平方向のドミノの最大数の合計に等しくなります。 セグメントの外側のセルの各色は独立しており、次のように選択できます。`2^(w-len)`方法。 この係数を乗算すると、セグメントの寄与が取締役会全体に拡張されます。 

同じ議論が列セグメントにも当てはまります。 

すべての水平ドミノは正確に 1 つの最大行セグメントに属し、すべての垂直ドミノは正確に 1 つの最大列セグメントに属します。 すべての行セグメントとすべての列セグメントからの寄与を合計すると、問題に必要な数量が正確にカウントされます。 

の再発`dp`すべてのカラーリングを最初の位置のステータスによって分割します。 最初の 2 つのセルが一致するドミノを形成する場合、1 つのドミノを取得し、長さを再帰します。`i-2`; それ以外の場合は長さを再帰します`i-1`。 これらのケースは網羅的であり、素であるため、反復ではすべてのカラーリングが 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

n, m = map(int, input().split())
g = [input().strip() for _ in range(n)]

white = sum(row.count('o') for row in g)

pow2 = [1] * (white + 1)
for i in range(1, white + 1):
    pow2[i] = (pow2[i - 1] * 2) % MOD

dp = [0] * (max(2, white + 1))
for i in range(2, white + 1):
    dp[i] = (
        2 * dp[i - 1]
        + dp[i - 2]
        + pow2[i - 2]
    ) % MOD

ans = 0

for r in range(n):
    cnt = 0
    for c in range(m + 1):
        if c < m and g[r][c] == 'o':
            cnt += 1
        else:
            if cnt >= 2:
                ans = (ans + dp[cnt] * pow2[white - cnt]) % MOD
            cnt = 0

for c in range(m):
    cnt = 0
    for r in range(n + 1):
        if r < n and g[r][c] == 'o':
            cnt += 1
        else:
            if cnt >= 2:
                ans = (ans + dp[cnt] * pow2[white - cnt]) % MOD
            cnt = 0

print(ans % MOD)
```実装は数学的分解に直接従います。 

パワーアレイストア`2^k`モジュロ`MOD`あらゆる可能性のために`k`。 以来`white`せいぜい`3·10^5`、この事前計算は線形です。 

DP の繰り返しは、最大で 1 回評価されます。`white`。 これが機能するのは、どのセグメントも白セルの総数より長くならないためです。 

行と列をスキャンする場合、境界を越えるセンチネルの反復により、最終セグメントが自動的にフラッシュされます。 これにより、各ループ後の特殊なコードが回避されます。 

要因`pow2[white - cnt]`最も重要な詳細です。`dp[cnt]`現在のセグメント内のカラーリングのみを考慮します。 残りのすべての白いセルは独立して色付けされ、正確に寄与します。`2^(white-cnt)`拡張子。 

すべての算術はモジュロで実行されます`998244353`。

import sys, io

def solve():
    input = sys.stdin.readline

    MOD = 998244353

    n, m = map(int, input().split())
    g = [input().strip() for _ in range(n)]

    white = sum(row.count('o') for row in g)

    pow2 = [1] * (white + 1)
    for i in range(1, white + 1):
        pow2[i] = (pow2[i - 1] * 2) % MOD

    dp = [0] * (max(2, white + 1))
    for i in range(2, white + 1):
        dp[i] = (
            2 * dp[i - 1]
            + dp[i - 2]
            + pow2[i - 2]
        ) % MOD

    ans = 0

    for r in range(n):
        cur = 0
        for c in range(m + 1):
            if c < m and g[r][c] == 'o':
                cur += 1
            else:
                if cur >= 2:
                    ans = (ans + dp[cur] * pow2[white - cur]) % MOD
                cur = 0

    for c in range(m):
        cur = 0
        for r in range(n + 1):
            if r < n and g[r][c] == 'o':
                cur += 1
            else:
                if cur >= 2:
                    ans = (ans + dp[cur] * pow2[white - cur]) % MOD
                cur = 0

    print(ans)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out

    solve()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out.getvalue()

o
