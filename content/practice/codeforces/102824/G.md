 ## 解決策
 ## 問題の理解

 岩のコレクションがあり、各岩は一連の小文字で説明されています。 文字はその岩石の中に現れる鉱物の種類を表します。 同じ鉱物が 1 つの岩石に何度も出現する可能性がありますが、鉱物が宝石とみなされるには、すべての岩石に少なくとも 1 回出現する必要があります。 

課題は、この条件を満たすさまざまな鉱物の種類がいくつあるかを数えることです。 入力により、岩石の数が与えられ、その後に各岩石の鉱物の説明が続きます。 出力は、すべての説明に共通する小文字の数です。 

主な制約は、アルファベットが固定されていることです。鉱物の種類は 26 種類しかありません。 たとえ岩の数が増えたり、記述が長くなったりしても、考えられる答えの数は一定のままです。 これは、単純な周波数または存在追跡方法で十分な場合には、すべての岩のペアを比較したり、すべての文字を繰り返しスキャンしたりすることは避けるべきであることを意味します。 岩の数の 2 乗に依存するソリューションは不必要な作業になりますが、各文字を 1 回処理するソリューションは簡単に十分に高速です。 

微妙なケースは、岩の中に出現する場合と、岩の中に複数回出現する場合の違いから生じます。 たとえば、入力が次の場合:```
3
aaa
a
aa
```答えは次のとおりです。```
1
```ミネラル`a`3 つの岩すべてに現れるため、宝石です。 個々の岩石の存在を確認するのではなく、出現総数をカウントする不注意な解決策は、それを過剰にカウントする可能性があります。 

もう 1 つの特殊なケースは、すべての岩石が共有する鉱物がない場合です。 例えば：```
2
abc
def
```正しい出力は次のとおりです。```
0
```すべての文字を有効として開始し、欠落している文字のみを削除するソリューションは、このケースを正しく処理する必要があります。 

最後の境界ケースは単一の岩です。```
1
xyz
```出力は次のとおりです。```
3
```唯一の岩石に現れるすべての鉱物は、すべての岩石の中に自動的に存在します。 少なくとも 2 つの岩を想定したソリューションでは、誤ってゼロが返される可能性があります。 

## アプローチ

 直接的なアプローチは、考えられるすべての鉱物を調べ、それがすべての岩石に含まれるかどうかをテストすることです。 文字が 26 文字しかないため、文字列のすべてのペアを比較するよりもはるかに優れています。 文字ごとにすべての岩をスキャンし、その文字が含まれていない岩がある場合は無効とマークします。 この作業は、岩の数に 26 を掛けたものに、各文字列内のメンバーシップをチェックするコストを加えたものに比例します。 毎回文字列を検索してメンバーシップを実装すると、総作業量は約`26 * n * m`、 どこ`m`平均的な岩の長さです。 

より自然な解決策は、アルファベットのサイズが小さいという事実から生まれます。 岩石に文字が存在するかどうかを繰り返し尋ねるのではなく、それぞれの岩石を一度要約します。 すべての岩石について、そこに現れる文字のセットを記録します。 次に、これらのセットを交差させます。 すべての岩石を加工した後、すべての交差点で生き残った文字だけが宝石です。 

考えられる鉱物の種類が少ないため、総当たり法は機能しますが、同じ存在チェックが何度も繰り返されます。 重要な観察は、岩石が提供する情報は、どの文字が存在するかについてのみであり、その文字が何回出現したかに関する情報ではないということです。 それぞれの岩を現在の文字のセットとして表すことで、不必要な繰り返し作業が不要になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(26 * n * m) | お(1) | 小さな入力であれば受け入れられますが、不必要な作業 |
 | 最適 | O(すべての文字列の合計の長さ + 26 * n) | お(26) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 使用可能な宝石のセットを 26 文字すべての小文字で初期化します。 初めは、あらゆる鉱物があらゆる岩石の中にまだ存在していた可能性があります。 
2. それぞれの岩を 1 つずつ読み、その岩に出現する文字のセットを構築します。 同じ文字が繰り返し出現しても、存在のみが重要であるため、セットは変わりません。 
3. 現在の候補セットと現在の岩で見つかった文字を交差させます。 この岩に欠けている文字は決して宝石ではないため、除去する必要があります。 
4. すべての石を加工したら、残った文字を数えます。 これらはまさにあらゆる岩石の中に現れた鉱物です。 

なぜ効果があるのか:

 維持されたセットは常に、これまでに処理されたすべての岩石に現れた鉱物を表しています。 最初は、岩が現れる前に、すべての文字がこの条件を満たします。 新しい岩石が処理されると、その岩石に存在する文字のみが条件を満たし続けることができるため、交差演算により不変条件が維持されます。 最後の岩以降、セットにはすべての岩に存在する文字が正確に含まれており、これが宝石の定義です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n_line = input().strip()
    if not n_line:
        return
    n = int(n_line)

    common = set("abcdefghijklmnopqrstuvwxyz")

    for _ in range(n):
        rock = input().strip()
        common &= set(rock)

    print(len(common))

if __name__ == "__main__":
    solve()
```このソリューションでは、最初にすべての小文字を含む候補セットを作成します。 これは、まだ岩がチェックされていない初期状態に対応します。 

それぞれの岩について、`set(rock)`説明を少なくとも 1 回出現する鉱物のコレクションに変換します。 これにより、重複した箇所が自動的に削除されます。これはまさにこの問題に必要な情報です。 交差演算子は、すでに可能であり、現在の岩石にも存在する鉱物のみを保持します。 

最終的なサイズは、`common`が答えです。 アルゴリズムは文字値を直接処理するため、インデックス作成に関する懸念はありません。 出力される最大値は 26 のみであるため、整数オーバーフローは問題になりません。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(すべての文字列の合計の長さ) | 各文字はセットの構築中に 1 回処理されます。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline
    n_line = input().strip()
    if not n_line:
        return
    n = int(n_line)
    common = set("abcdefghijklmnopqrstuvwxyz")
    for _ in range(n):
        common &= set(input().strip())
    print(len(common))

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout
    try:
        sys.stdin = io.StringIO(inp)
        sys.stdout = io.StringIO()
        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

assert run("3\nabcdde\nbaccd\neeabg\n") == "2\n", "sample 1"
assert run("2\nabc\ndef\n") == "0\n", "no common minerals"
assert run("1\nxyz\n") == "3\n", "single rock"
assert run("3\naaa\na\naa\n") == "1\n", "duplicate occurrences"
assert run("4\nabcdefghijklmnopqrstuvwxyz\nabcdefghijklmnopqrstuvwxyz\nabc\nabc\n") == "3\n", "large alphabet boundary"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`3 / abcdde / baccd / eeabg`|`2`| 標準交差点ケース |
 |`2 / abc / def`|`0`| 共有ミネラルなし |
 |`1 / xyz`|`3`| 単一の岩の挙動 |
 |`3 / aaa / a / aa`|`1`| 重複した文字は 1 回としてカウントされます。 
| 完全なアルファベットと縮小されたサブセットを含む 4 つの岩 |`3`| より大きな説明と境界の正しい処理 |

 ## 特殊なケース

 最初のエッジケースの場合:```
3
aaa
a
aa
```最初の岩は葉だけを残します`a`候補として。 2番目の岩にはまだ含まれています`a`、3番目の岩にも含まれています`a`, したがって、最終セットには要素が 1 つあります。 アルゴリズムの出力`1`周波数ではなく存在を追跡するためです。 

2 番目のエッジケースの場合:```
2
abc
def
```最初の岩を処理した後の候補は、`{a, b, c}`。 と交差`{d, e, f}`すべてを削除し、空のセットを残します。 アルゴリズムは正しく出力します`0`。 

単一岩の場合:```
1
xyz
```すべての文字の初期セットは次のように交差します。`{x, y, z}`一度。 残りのセットには 3 つの要素があるため、出力は次のようになります。`3`。 これが機能するのは、唯一の岩石内のすべての鉱物がすべての岩石に存在するためです。 

文字が頻繁に繰り返される場合:```
3
aaaaab
bbbbba
ababab
```最初の岩は貢献します`{a, b}`、2番目も貢献します`{a, b}`、3番目は貢献します`{a, b}`。 答えは`2`。 重複した出現は岩石中に鉱物が存在するかどうかに影響を与えないため、アルゴリズムは重複した出現を無視します。
