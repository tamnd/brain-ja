 ## 解決策
 ## 問題の理解

 最大 50 件の主題があります。 各主題には 3 つの特性があります。 

間隔$[a_i, b_i]$この被験者が割り当てることができる宿題演習の数を示します。 その間隔内で任意の値を自由に選択できます。 

値$c_i$主題の複雑さです。 時間割では、厳密に複雑さの高い順に主題を使用する必要があるため、主題を選択する場合は、$p_1, p_2, \dots, p_n$、 それから：$$c_{p_1} < c_{p_2} < \dots < c_{p_n}$$宿題の数も特別な移行ルールに従う必要があります。 現在の日付が$x$演習を行った場合、翌日には次のいずれかを含める必要があります。$$x + k$$または$$x \cdot k$$すべての有効な時刻表の中で正確に$n$科目の場合、合計演習数が最大の科目が必要です。 

制約で最初に重要になるのは、間隔のサイズです。 値自体は次のように大きくできます。$10^{16}$, したがって、宿題のカウントを強引に行うことは不可能です。 ただし、間隔幅は次の条件を満たします。$$b_i - a_i \le 100$$これですべてが変わります。 値が膨大であっても、各科目で許可される個別の宿題数は最大 101 個のみです。 それは、真の状態空間が小さいことを意味します。 

2 番目の重要な制約は、$m \le 50$。 複雑さを伴うソリューション$50^3 \cdot 100^2$完全に安全です。 

この問題の最も難しい部分は、任意の整数について考えるべきではないことを認識することです。 ある主題区間内に実際に現れる値のみを考慮します。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

仮定する$k = 1$。 この場合、許可される 2 つの遷移は次のようになります。$$x_i = x_{i-1} + 1$$または$$x_i = x_{i-1}$$不用意に実装すると、乗算によって値が常に増加すると想定し、誤ってサイクルや無効な遷移が作成される可能性があります。 

例えば：```
2 2 1
5 5 1
5 5 2
```正しい答えは次のとおりです。```
YES
1 5
2 5
```1 を掛けると値が変わらないためです。 

もう 1 つの危険なケースは、複雑さが重複していることです。 同じ複雑さの主題を両方ともタイムテーブルに含めることはできません。 

例：```
2 3 2
1 10 5
1 10 5
2 20 6
```最初の 2 つの主題のうち 1 つだけを選択できます。 

固定幅整数を使用する言語では、値が大きいとオーバーフロー トラップも作成されます。 

例：```
2 2 100
10000000000000000 10000000000000000 1
10000000000000100 10000000000000100 2
```この移行は次の理由から有効です。$$10^{16} + 100 = 10000000000000100$$32 ビット整数を使用すると、このケースは完全に解消されます。 

貪欲に合計を最大化すると、さらに微妙な問題が発生します。 ローカルで最大の宿題数を選択すると、将来の移行が妨げられる可能性があります。 

例：```
3 3 2
1 5 1
6 6 2
8 20 3
```初日に貪欲に 5 を選択した場合、次の値は 7 または 10 でなければなりませんが、どちらも主題 2 には当てはまりません。最適な有効な順序は次のとおりです。```
4 -> 6 -> 8
```合計18個。 

## アプローチ

 ブルートフォースアプローチでは、次のすべてのサブセットが試行されます。$n$主題、複雑さによるすべての有効な順序付け、およびすべての宿題が各間隔内でカウントされます。 

各科目には最大 101 個の可能な宿題値があります。 主題を修正したとしても、すでにおおよそ次の結果が得られます。$$101^n$$可能なシーケンス。 と$n = 50$、これは天文学的な大きさです。 

遷移ルール​​がローカルであるため、ブルート フォースは概念的に機能します。 昨日の宿題の数がわかれば、今日の可能性を判断できます。 問題は単に分岐係数が大きすぎることです。 

重要な観察は、使用可能な宿題の値はすべて、ある間隔に属している必要があるということです。$[a_i, b_i]$、各間隔には最大 101 個の数値が含まれます。 被験者は最大 50 個であるため、入力全体にわたる個別の宿題値の合計数は最大で次のとおりです。$$50 \cdot 101 = 5050$$これは動的プログラミングには十分な大きさです。 

それぞれの状態は次のように考えることができます。$$(dp[i][v])$$意味:

 「主題で終わります$i$宿題カウントを使用する$v$。」

 次の場合、ある状態から別の状態に移行できます。 

1. 次の主題は厳密にはより複雑です。 
2. 次の宿題の数は次のいずれかに等しい$v + k$または$v \cdot k$。 
3. 次の値は、次の対象範囲内にあります。 

目的は合計を最大化することであるため、DP には達成可能な最良の合計が保存されます。 

問題は、有向非巡回グラフ上の最長パス形式の DP になります。 複雑さの順序付けにより、非循環性が保証されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O\left(\binom{m}{n} \cdot 101^n\right)$| 指数 | 遅すぎる |
 | 最適なDP |$O(m^2 \cdot 101^2)$|$O(m \cdot 101)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての主題を読み、複雑さに従って分類します。 

有効な timetable では厳密に複雑さが増すため、並べ替えが必要です。 ソートが完了すると、有効な遷移はすべて配列内で前方に進みます。 
2. すべての科目について、その区間内で考えられるすべての宿題の数を列挙します。 

すべての間隔幅は最大 100 であるため、被験者ごとに最大 101 個の値が生成されます。 
3. DP 状態を定義します。 

させて：$$dp[i][t]$$subject で終わる有効なシーケンスの最大総演習数を表します。$i$を使用して$t$間隔の - 番目の値。 
4. すべての 1 つの主題のシーケンスを初期化します。 

どの 1 つの主題でもタイムテーブルを開始できるため、次のようになります。$$dp[i][t] = value$$最初は。 
5. すべての被験者間のトランジションを試してください。 

被験者向け$j \to i$、移行は次の場合にのみ許可されます。$$c_j < c_i$$次に、宿題の値ごとに$x$主題の$j$、次の可能な値を 2 つだけ計算します。$$x + k$$そして$$x \cdot k$$どちらかの値が件名に属している場合$i$の間隔で、DP を更新できます。 
6. 親ポインタを保存します。 

遷移によって DP 値が改善されるたびに、以前の状態を記録します。 これにより、後でタイムテーブルを再構築することができます。 
7. シーケンスの長さを個別に追跡します。 

まさに必要です$n$単に最大額ではなく、主題。 したがって、各 DP 状態には、使用されたサブジェクトの数も保存されます。 
8. すべての状態の中で正確に使用する$n$合計が最大となるものを選択してください。 
9. 親ポインターを使用して答えを再構築します。 
10. どの状態も長さに達しない場合$n$、印刷`"NO"`。 

### なぜ効果があるのか

 DP は、すべての有効な最終状態を 1 回だけ処理します。 

subject で終わる有効なタイムテーブル$i$そして価値観$v$正確に 1 つ前の宿題カウントから取得する必要があります。$$v - k$$または次を満たす値:$$v = previous \cdot k$$移行ルールはローカルであるため、最適な部分タイムテーブルを拡張すると常に最適性が維持されます。 複雑さが厳密に増加するため、遷移は DAG を形成し、循環依存関係は発生しません。 

DP の不変条件は次のとおりです。$$dp[i][t]$$は、その正確な状態で終了するすべての有効なシーケンスの中での最大合計演習を保存します。 

すべての正規のタイムテーブルは DP グラフ内の 1 つのパスに対応し、すべての DP パスは正規のタイムテーブルに対応します。 すべての長さのパスにわたって最大化するため、$n$、アルゴリズムは正しいです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())

    subjects = []
    for idx in range(1, m + 1):
        a, b, c = map(int, input().split())
        vals = list(range(a, b + 1))
        subjects.append((c, idx, vals))

    subjects.sort()

    # dp[i][t] = best total sum
    # len_dp[i][t] = length of sequence
    dp = []
    len_dp = []
    parent = []

    for _, _, vals in subjects:
        sz = len(vals)
        dp.append(vals[:])
        len_dp.append([1] * sz)
        parent.append([None] * sz)

    for i in range(m):
        ci, _, vals_i = subjects[i]

        pos_i = {}
        for t, v in enumerate(vals_i):
            pos_i[v] = t

        for j in range(i):
            cj, _, vals_j = subjects[j]

            if cj >= ci:
                continue

            for pj, x in enumerate(vals_j):
                candidates = [x + k, x * k]

                for y in candidates:
                    if y not in pos_i:
                        continue

                    pi = pos_i[y]

                    new_len = len_dp[j][pj] + 1
                    new_sum = dp[j][pj] + y

                    if new_len > len_dp[i][pi]:
                        len_dp[i][pi] = new_len
                        dp[i][pi] = new_sum
                        parent[i][pi] = (j, pj)

                    elif new_len == len_dp[i][pi] and new_sum > dp[i][pi]:
                        dp[i][pi] = new_sum
                        parent[i][pi] = (j, pj)

    best = None
    best_sum = -1

    for i in range(m):
        vals = subjects[i][2]

        for t, v in enumerate(vals):
            if len_dp[i][t] == n and dp[i][t] > best_sum:
                best_sum = dp[i][t]
                best = (i, t)

    if best is None:
        print("NO")
        return

    ans = []

    cur = best
    while cur is not None:
        i, t = cur
        _, idx, vals = subjects[i]
        ans.append((idx, vals[t]))
        cur = parent[i][t]

    ans.reverse()

    print("YES")
    for x in ans:
        print(*x)

solve()
```最初の主要な実装上の選択肢は、すべての科目の明示的な宿題値を保存することです。 間隔幅が 100 を超えることはないため、コンパクトなままとなり、複雑な座標圧縮が回避されます。 

DP は 2 つの別々の情報を保持します。`len_dp[i][t]`その状態で終了する最適なシーケンスで使用されるサブジェクトの数を保存します。`dp[i][t]`対応する合計値を格納します。 

比較の順序は重要です。 問題では正確な値が必要となるため、シーケンス長を最初に長くすることを常に優先します。$n$主題。 同じ長さのシーケンスの中で、合計の演習を最大化します。 

実装の微妙な詳細は、重複した遷移結果の処理です。 いつ$k = 1$、2 つのトランジション:```
x + k
x * k
```次のような連続した値になる場合があります`x + 1`そして`x`、または特殊な状況では値が重複する場合もあります。 両方が独立してチェックされるため、コードはこれを自然に処理します。 

の`pos_i`辞書が与える$O(1)$次の間隔内にターゲット値が存在するかどうかを検索します。 これがないと、すべての遷移で最大 101 個の値を繰り返しスキャンする必要があります。 

親の再構築では、以前の DP 状態のみが保存されます。 遷移は複雑さ順に並べられた DAG を形成するため、再構築は簡単です。
