 ## 問題の理解

 部分的に指定された長さの配列から構築できる配列の数を数えるように求められます。`n`、いくつかの要素が欠落しており、次のように表されます。`-1`。 それぞれ`-1`以下の任意の整数に置き換えることができます`1`に`k`。 重要な制約は、結果の配列には、`1`。 つまり、長さが 3、5、7 などの連続するセグメントは、前後から同じように読み取ってはなりません。 

入力配列には、いくつかの固定数値といくつかの数値が含まれる場合があります。`-1`s. 出力は単一の整数です。つまり、入力する方法の数です。`-1`s を使用して「適切な」配列を形成します (モジュロ)`998244353`。 

制約は大きいです:`n`そして`k`それぞれ最大 200,000 まで可能です。 考えられるすべての置き換えを試みる総当り的なアプローチ`-1`それは次のようなことになるため、完全に実行不可能です。`k^n`可能性。 に関して線形またはほぼ線形の時間で機能するソリューションが必要です。`n`。 

エッジケースには、すべての配列が含まれます。`-1`s、なしの配列`-1`s、隣接する 2 つ以上の同一の値を持つ配列、および固定値によってすでに回文が強制されている配列。 たとえば、配列`[1, -1, 1]`の場合、長さ 3 の回文があります。`-1`に置き換えられます`1`、だからそれだけ`k-1`選択肢は有効です。 もう 1 つのエッジ ケースは、次のような固定値が交互に並ぶ配列です。`[1, 2, 1, 2, 1]`ここで、長さ 3 の回文の形成を避けるために、特定の位置は異なっていなければなりません。 

## アプローチ

 単純なアプローチでは、数値のあらゆる組み合わせを試します。`-1`位置を確認してから、すべての奇数長の部分配列に回文があるかどうかを確認します。 これは原理的には正しいですが、`n = 20`そして`k = 5`、10兆を超える可能性があります。 チェック自体は候補ごとに O(n^2) であるため、このアプローチは実行不可能になります。 

重要な洞察は、奇数の長さの回文が局所的であり、特定の位置に中心があるということです。 長さ 3 の奇数長の回文には 3 つの連続する数字のみが含まれ、長さ 5 には 5 つの連続する数字が含まれます。 問題を 2 つの独立した問題に分割できます。1 つは奇数のインデックスの要素に関するもの、もう 1 つは偶数のインデックスの要素に関するものです。 回文は同じパリティ インデックス分離を持つ連続した要素間でのみ発生するため、各シーケンスは独立して処理できます。 

配列を分割すると、各サブシーケンスを個別に処理できるようになります。 サブシーケンスは、より単純な「制約で埋める」問題に帰着します。`-1`2 つの固定値の間にある場合、回文を引き起こすような繰り返しを作成せずにその値を埋める方法の数を数える必要があります。 これについてはよく知られた組み合わせ公式があります。セグメントの長さが`len`境界値が等しい場合、`(k-1)^(len//2)`方法があり、それらが異なる場合は、`(k-1)^((len+1)//2)`方法。 1つだけある場合`-1`制約がないため、入力できます。`k`方法。 

サブシーケンスのすべての独立したセグメントのカウントを乗算すると、そのサブシーケンスの合計カウントが得られます。 奇数と偶数のサブシーケンスのカウントを乗算すると、最終的な答えが得られます。

 ## アルゴリズムのチュートリアル

 1. 配列を 2 つのサブシーケンスに分割します。1 つは奇数のインデックスの要素を含み、もう 1 つは偶数のインデックスの要素を含みます。 これにより、長さ 3 以上の回文がシーケンスにまたがることがなく、独立した処理が可能になります。 
2. サブシーケンスごとに、その要素を反復処理し、連続するセグメントを特定します。`-1`s. 各セグメントは、2 つの既知の数値の間か、配列の境界にあります。 
3. 各セグメントについて:

 - 両側が既知の数で境界されている場合は、境界値が等しいかどうかに基づいて有効な詰め物の数を計算します。 数式を使用する`(k-1)^(segment_length//2)`境界が等しい場合と、`(k-1)^((segment_length+1)//2)`不平等な境界線の場合。 
- セグメントの片側に境界がない場合は、自由側に自由があるものとして扱います。 長さのセグメント`len`貢献する`k * (k-1)^(len-1)`方法。 
4. サブシーケンス内のすべてのセグメントのウェイ数を乗算します。 
5. 2 つのサブシーケンスの結果を乗算して、良好な配列の総数を法的に求めます。`998244353`。 
6. 結果を返します。 

これが機能する理由: 奇数と偶数のインデックスに分割することで、1 より大きい奇数の長さの回文が見逃されることがなくなります。 セグメントは固定境界を越えて相互作用しないため、各セグメントの有効な塗りつぶしを個別にカウントし、それらを乗算することで正確さが保たれます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def count_good(subseq, k):
    n = len(subseq)
    ans = 1
    i = 0
    while i < n:
        if subseq[i] != -1:
            i += 1
            continue
        j = i
        while j < n and subseq[j] == -1:
            j += 1
        left = subseq[i-1] if i-1 >= 0 else None
        right = subseq[j] if j < n else None
        length = j - i
        if left is None and right is None:
            ways = k * pow(k-1, length-1, MOD) if length > 0 else k
        elif left is None or right is None:
            ways = pow(k-1, length, MOD)
        else:
            if left == right:
                ways = pow(k-1, length//2, MOD)
            else:
                ways = pow(k-1, (length+1)//2, MOD)
        ans = ans * ways % MOD
        i = j
    return ans

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    odd = a[::2]
    even = a[1::2]
    res = count_good(odd, k) * count_good(even, k) % MOD
    print(res)

solve()
