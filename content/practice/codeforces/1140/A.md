 ## 解決策
 ## 問題の理解

 イワンの推理小説は、各ページに謎が紹介され、後のページでその謎の解決が明らかになるという構成になっています。 具体的には、次のような整数のリストがあります。$i$-番目の整数$a_i$ページで紹介された謎を解くページを教えてください$i$。 イワンは毎日最初の未読ページから順番に本を読みますが、「謎の連鎖」の途中で読むのを止めることはできません。 彼は遭遇したすべての謎が解決されるまで本を読みます。 課題は、その本を読み終えるのに何日かかるかを判断することです。 

入力は十分小さいので、$n$まで行くことができます$10^4$、つまり、アルゴリズムは次のとおりです。$O(n)$または$O(n \log n)$2秒の制限時間内で快適に走行できます。 本全体を繰り返し走査する二次アルゴリズムは、$10^8$操作が行われるため、タイムアウトになる危険性があります。 

エッジケースは微妙な場合があります。 たとえば、すべての謎が同じページですぐに説明される場合、イワンは 1 日あたり 1 ページを読みます。 のために$n=5$と$a = [1,2,3,4,5]$、毎日が 1 ページで、5 日分になります。 Ivan が 1 日に常に複数ページを読むと仮定した不用意なアプローチは、ここで間違った答えを生み出すでしょう。 もう 1 つの注意が必要なケースは、最後のページでこれまでの謎がすべて説明されている場合です。$a = [5,5,5,5,5]$; イワンは 1 日で 5 ページすべてを読まなければなりません。 

## アプローチ

 ブルートフォースアプローチは、Ivan の読書を明示的にシミュレートします。 1 ページから始めて順番に読み続け、遭遇したすべての謎が解決されたときにのみ停止します。 各停車地点を新しい日として数えます。 この方法は読み取りルールに直接従うので正しいですが、未解決の謎を繰り返しチェックするという単純な実装の場合は非効率になる可能性があります。 最悪の場合の複雑さは以下に達する可能性があります$O(n^2)$各ページが遠くのページを参照しているとき。これは、毎日、未読のページの先頭からスキャンして、以前のすべての謎を確認する必要があるためです。 

最適なアプローチの重要な観察は、毎日、イワンが最初の未読のページから、その日の謎に必要な最も遠いページまで読むということです。 正式には、ページを順番に反復しながら、最も遠いページを維持します。$max_page$これまでに遭遇したすべての謎を解決するには、それを読む必要があります。 現在のページインデックスが次の値を超えると Ivan が停止します$max_page$。 日数を増やして、次の未読ページから続行します。 これが機能するのは、停止条件が現在の連続セグメント内のすべての謎が解決されたときであるためです。 これにより、アルゴリズムがページを通過する単一の線形パスに削減され、次のようになります。$O(n)$時間の複雑さ。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(n^2) | お(1) | n が大きいと遅すぎます |
 | 最大ページ追跡 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 変数を初期化する`days`これにより、Ivan が行った読書セッションの数がカウントされます。 
2. ポインタを設定する`i`0 は、現在の未読ページのインデックスを表します。 
3. その間`i < n`:

 1.初期化`max_page`に`a[i] - 1`ゼロベースのインデックスが必要なためです。 
2. ポインタを初期化する`j = i`現在の日内のページを追跡します。 
3. その間`j <= max_page`:

 1.アップデート`max_page = max(max_page, a[j] - 1)`。 これにより、イワンはその日の謎がすべて解決されるまで読み続けることができます。 
2. インクリメント`j`1までに。 
4. インクリメント`days`Ivan が 1 日分の読書を終えたので、1 ずつです。 
5.移動`i`に`j`、次の未読ページ。 
4. 印刷`days`。 

なぜ機能するのか: アルゴリズムは次の不変条件を維持します。`max_page`これは、イワンがこれまで遭遇したすべての謎を解決するために常に読まなければならない最も遠いページです。 延長することで`max_page`後のページでさらに読み進める必要がある場合は常に、アルゴリズムにより、1 日の終わりに未解決の謎が残らないことが保証されます。 各ページは 1 回だけアクセスされ、正確性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

days = 0
i = 0
while i < n:
    max_page = a[i] - 1
    j = i
    while j <= max_page:
        max_page = max(max_page, a[j] - 1)
        j += 1
    days += 1
    i = j

print(days)
```外側のループは次の日の始まりに進み、内側のループは最も遠い未解決の謎まで続きます。 微妙な点は調整も含めて`a[i]`ゼロベースのインデックス作成と更新`max_page`増加する前に`j`。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各ページは 1 回だけ処理されます。 内部の while ループは前方にのみ進み、ページを再訪問することはありません。 |
 | スペース | O(n) | 配列の保存`a`。 追加の変数は O(1) スペースを使用します。 |

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    a = list(map(int, input().split()))
    days = 0
    i = 0
    while i < n:
        max_page = a[i] - 1
        j = i
        while j <= max_page:
            max_page = max(max_page, a[j] - 1)
            j += 1
        days += 1
        i = j
    return str(days)

# Provided sample
assert run("9\n1 3 3 6 7 6 8 8 9\n") == "4", "sample 1"

# Minimum input
assert run("1\n1\n") == "1", "single page"

# All explained immediately
assert run("5\n1 2 3 4 5\n") == "5", "all pages self-explained"

# All explained at the last page
assert run("5\n5 5 5 5 5\n") == "1", "all explained on last page"

# Sequential chunks
assert run("6\n2 2 4 4 6 6\n") == "3", "two-page chains"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 | 1 | 1 ページの本 |
 | 1 2 3 4 5 | 5 | 各ページは 1 日 1 つずつ説明されています。 
| 5 5 5 5 5 | 1 | 最後のページですべてが説明されます。 
| 2 2 4 4 6 6 | 3 | 複数のページのチェーンが正しくカウントされました。 

## 特殊なケース

 すべての謎が同じページで解決されるシナリオの場合、アルゴリズムは、そのページまで読書を続行する必要があることを正しく識別します。 と`a = [5,5,5,5,5]`、`i=0`、`j=0`、 そして`max_page=4`。 内側のループは j を 0 から 4 まで繰り返し、1 日ですべてのページを読み取ります。 不変条件`j <= max_page`一日が早く終わらないようにします。 同様に、ページ自体を説明するページの場合、アルゴリズムは設定によって単一ページの日を処理します。`max_page = a[i]-1`, そのため、すぐに一日が終わります。 これらのトレースは、アルゴリズムが両方の極端な値を正しく処理していることを確認します。
