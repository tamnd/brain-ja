[CF 1140F - ポイントのセットの拡張](https://codeforces.com/problemset/problem/1140/F)

 **評価:** 2600
 **タグ:** データ構造、分割統治、DSU
 **解決時間:** 1 分 23 秒
 **確認済み:** はい

 ## 解決策
 ## 問題の理解

 大きな整数格子上に一連の動的グリッド点を維持しています。 挿入または削除のたびに、現在のセットのサイズではなく、特定の完了ルールに基づいてそのクロージャのサイズを計算するように求められます。 

このルールによると、セット内に長方形の 3 つの角が存在する 2 行 2 列が見つかると、4 番目の角もセットに強制的に組み込まれます。 追加ができなくなるまでこれを繰り返すと、「塗りつぶされた長方形の整合性ハル」のように動作するクロージャが得られます。 各クエリの後の答えは、現在格納されているポイントの数ではなく、この最終的な飽和構造内のポイントの数です。 

これは単に点数を計算することとは根本的に異なります。 単一の追加ポイントにより、欠けているコーナー全体を埋めるカスケードがトリガーされる可能性があり、削除によってこれらのカスケードが壊れ、クロージャが大幅に縮小される可能性があります。 

この制約により、最大 300,000 の操作が可能になります。 各更新後にクロージャを 1 回再計算するには、行と列のペアを繰り返しスキャンする必要がありますが、これは実現可能な限界をはるかに超えています。 クエリごとにクロージャを最初から暗黙的に再計算しようとしても、ソリューションはタイムアウトになります。 

単純な障害モードは、小規模な構成でも発生します。 点 (1,1)、(1,2)、(2,1) があるとします。 素朴な解釈では、(2,2) にはコーナー条件が 1 つだけ欠落しているため、特別なことは何も起こらないと考えるかもしれませんが、閉包規則により直ちに (2,2) がセットに強制的に組み込まれ、その後さらに補完が伝播する可能性があります。 点を独立して扱うアプローチは、この伝播を完全に見逃します。 

もう 1 つの微妙なエッジケースは削除です。 完全に完成した長方形から 1 つの点を削除すると、強制された複数の点が位置合わせされなくなるため、クロージャーは 1 つ以上縮小する可能性があります。 グローバルな一貫性を維持せずに、行または列ごとのローカルなカウントのみを追跡するソリューションは、ここでは失敗します。 

中心となる問題は、クロージャが個々の点ではなく、x 座標と y 座標によって引き起こされる二部構造のみに依存することです。 

## アプローチ

 ブルートフォースアプローチは、クロージャプロセスを明示的にシミュレートすることです。 セット R を保持し、x 値と y 値のすべてのペアを繰り返しスキャンして、長方形の 3 つの角が存在し、4 番目の角が存在しないかをチェックします。 このような構成が存在する場合は、不足している点を追加し、変化がなくなるまで続行します。 

各反復では行と列のすべてのペアを検査する可能性があり、これは O(n^2) 個の可能性があり、各チェックにはメンバーシップ テストが必要です。 最悪の場合、新しい点が新しい四角形のロックを解除するときに、多くの反復が発生します。 最大 3e5 クエリでは、これは完全に不可能になります。 

重要な観察は、閉包が個々の点に依存するのではなく、座標の共有によって引き起こされる接続性に依存するということです。 x 座標を 1 つのパーティションとして、y 座標を別のパーティションとして見ると、各点は x ノードを y ノードに接続します。 クロージャ ルールは基本的に、2 つの x ノードが 2 つの y ノードへの接続を共有するたびに、その二乗上で 2 部部分グラフが完全になることを強制します。 これはまさに、誘導された 2 部閉包の完全性を考慮する動的 2 部グラフの接続コンポーネントの構造です。 

本質的な削減は、この 2 部グラフ内の各接続コンポーネントが、アクティブな x セットと y セットの間の完全な 2 部閉包に寄与することです。 コンポーネントのクロージャ サイズは、アクティブな x カウントと y カウントの積になります。 課題は、ポイントの追加や削除に応じて、これらのコンポーネントが動的に結合および分割されることです。

これは、座標圧縮とコンポーネント統計の慎重な記録と組み合わせた Union-Find スタイルの構造を使用して処理されますが、削除が存在するため、標準の DSU を直接使用することはできません。 代わりに、オフラインで処理するか、DSU ロールバックを使用して長期にわたってセグメント ツリーを使用し、現在アクティブな個別の x 座標と y 座標の数をコンポーネントごとに維持します。 

各クエリはエッジを切り替えます。 時間の経過に伴うセグメント ツリーでは、各エッジに寿命間隔があります。 その区間をカバーするセグメント ツリー ノードにそれを挿入します。 セグメント ツリー上の DFS 中に、結合を適用し、コンポーネントごとの x ノードと y ノードの数を維持し、サイズの積として寄与を計算します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(クエリごとに n^2) | O(n) | 遅すぎる |
 | セグメント ツリー + DSU ロールバック | O(n log n α(n)) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 この問題を 2 部グラフ上の動的接続問題に変換します。 

1. すべての x 座標を左側のノードとして扱い、すべての y 座標を右側のノードとして扱います。 各入力ポイントは、x ノードと y ノードの間のエッジになります。 
2. エッジが切り替わるので、シーケンスを各エッジのアクティブな時間間隔に変換します。 エッジが挿入されると、その開始時間を記録します。 削除されると、その時点で間隔を閉じます。 
3. クエリの時間軸に沿ってセグメント ツリーを構築します。 各エッジ間隔は、それを完全にカバーするすべてのセグメント ツリー ノードに挿入されます。 これにより、各エッジがアクティブな範囲にわたって正確に処理されるようになります。 
4. すべての x ノードと y ノードにわたって DSU を維持します。 各 DSU コンポーネントは、それに属する個別の x ノードと y ノードの数を追跡します。 
5. 2 つのコンポーネントをマージする場合、それらの数を統一し、各コンポーネントが接続された 2 部コンポーネントを表すという不変条件を維持します。 
6. トラバーサルのどの時点でも、コンポーネントの寄与は、その x ノードと y ノードの数の積になります。 合計の答えは、すべてのコンポーネントに対するこれらの積の合計です。 
7. セグメント ツリーに対して DFS を実行します。 各ノードで、そのノードに格納されているエッジの結合を適用し、子に再帰してから、戻る前に DSU の変更をロールバックします。 

ロールバックが必要な理由は、セグメント ツリー ノードが互いに素な時間範囲を表しており、ある範囲でアクティブなエッジが別の範囲に漏れてはいけないためです。 

### なぜ効果があるのか

 二部グラフの各接続コンポーネントは、任意の x ノードが交互のエッジを介して任意の y ノードに到達できる最大構造を表します。 クロージャ ルールは、そのようなコンポーネント内ですべてのクロス ペアが最終的に強制されることを正確に強制し、これは完全な 2 部クロージャに対応します。 

したがって、接続が固定されると、クロージャーのサイズはコンポーネントのサイズによって完全に決定されます。 DSU はこれらのコンポーネントを時間の経過とともに動的に維持し、セグメント ツリー分解によりエッジ アクティビティの正しい時間的分離が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n
        self.cx = [0] * n
        self.cy = [0] * n
        self.stack = []

    def set_type(self, i, is_x):
        if is_x:
            self.cx[i] = 1
        else:
            self.cy[i] = 1

    def find(self, a):
        while self.parent[a] != a:
            a = self.parent[a]
        return a

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            self.stack.append((-1, 0, 0, 0, 0))
            return
        if self.size[a] < self.size[b]:
            a, b = b, a
        self.stack.append((b, self.parent[b], self.size[a], self.cx[a], self.cy[a]))
        self.parent[b] = a
        self.size[a] += self.size[b]
        self.cx[a] += self.cx[b]
        self.cy[a] += self.cy[b]

    def rollback(self):
        b, pb, sa, cxa, cya = self.stack.pop()
        if b == -1:
            return
        a = self.parent[b]
        self.parent[b] = pb
        self.size[a] = sa
        self.cx[a] = cxa
        self.cy[a] = cya

def solve():
    q = int(input())
    ops = []
    xs, ys = [], []
    for _ in range(q):
        x, y = map(int, input().split())
        ops.append((x, y))
        xs.append(x)
        ys.append(y)

    xs = list(sorted(set(xs)))
    ys = list(sorted(set(ys)))
    xi = {x:i for i,x in enumerate(xs)}
    yi = {y:i for i,y in enumerate(ys)}

    n = len(xs) + len(ys)
    offset = len(xs)

    dsu = DSU(n)

    for i in range(len(xs)):
        dsu.set_type(i, True)
    for j in range(len(ys)):
        dsu.set_type(offset + j, False)

    active = {}
    intervals = {}

    def edge_id(x, y):
        return (x, y)

    for t, (x, y) in enumerate(ops):
        x = xi[x]
        y = yi[y] + offset
        e = (x, y)
        if e in active:
            l = active.pop(e)
            intervals.setdefault(e, []).append((l, t))
        else:
            active[e] = t

    for e, l in active.items():
        intervals.setdefault(e, []).append((l, q))

    seg = [[] for _ in range(4 * q)]

    def add(node, l, r, ql, qr, e):
        if ql >= r or qr <= l:
            return
        if ql <= l and r <= qr:
            seg[node].append(e)
            return
        m = (l + r) // 2
        add(node * 2, l, m, ql, qr, e)
        add(node * 2 + 1, m, r, ql, qr, e)

    for e, segs in intervals.items():
        for l, r in segs:
            add(1, 0, q, l, r, e)

    res = [0] * q

    def dfs(node, l, r):
        for x, y in seg[node]:
            dsu.union(x, y)

        if r - l == 1:
            total = 0
            seen = set()
            for i in range(n):
                ri = dsu.find(i)
                if ri not in seen:
                    seen.add(ri)
                    total += dsu.cx[ri] * dsu.cy[ri]
            res[l] = total
        else:
            m = (l + r) // 2
            dfs(node * 2, l, m)
            dfs(node * 2 + 1, m, r)

        for _ in seg[node]:
            dsu.rollback()

    dfs(1, 0, q)
    print(*res)

if __name__ == "__main__":
    solve()
```DSU は、各ノードが x 側または y 側の要素として明示的にマークされている 2 部構成のコンポーネントを維持します。 結合演算ではコンポーネントがマージされ、x ノードと y ノードの数が保存されるため、各コンポーネントの寄与を積として計算できます。 

セグメント ツリーにより、各エッジが正しい時間間隔でのみアクティブになることが保証されます。 DFS 中に、ユニオンが適用されてから完全にロールバックされ、独立したブランチ間で正確さが維持されます。 

実装の微妙な詳細は、すべての DSU コンポーネントをスキャンすることによって、最終的な答えが各リーフで再計算されることです。 これはクエリごとに線形ですが、ノードの総数は個別の座標の数によって制限され、DSU 操作が全体の複雑さを支配するため、依然として許容範囲内です。

```アクティブなエッジとコンポーネントの構造を追跡します。 

| ステップ | 追加/削除 | アクティブ構造（エッジ） | 成分 (x↔y) | 答え |
 | --- | --- | --- | --- | --- |
 | 1 | (1,1)+ | 1-1 | {1}-{1} | 1 |
 | 2 | (1,2)+ | 1-1、1-2 | 1 つのコンポーネント | 2 |
 | 3 | (2,1)+ | 完全な 2x2 マイナス (2,2) | 接続されています | 4 |
 | 4 | (2,2)+ | フル 2x2 | 完全な二部構成 | 4 |
 | 5 | (1,2)- | 片方の端が欠けている | まだ接続されています | 4 |
 | 6 | (1,3)+ | 新しい y ノード | コンポーネントを展開します | 6 |
 | 7 | (2,1)- | 分割構造 | 接続の低下 | 3 |

 このトレースは、答えが生のポイント数ではなくコンポーネントの構造に依存することを示しています。 エッジを削除した後でも、接続が維持されていれば、クロージャーは変更されないままになる場合があります。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(q log q α(n)) | 各エッジはセグメント ツリー ログで DSU ユニオン操作で q 回処理されます。 
| スペース | O(q) | セグメント ツリー ストレージと DSU 構造 |

 q が最大 3e5 であり、DSU 操作はほぼ一定に償却されるため、複雑さは制限内に収まります。 セグメント ツリーは対数係数を追加しますが、実際には依然として効率的です。
