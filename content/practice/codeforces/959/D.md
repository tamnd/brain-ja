 ## 問題の理解

2 番目の条件自体はそれほど制限的なものではありませんが、ペアごとの共素性と組み合わせることで、強い構造的制約が課せられます。つまり、各素数は配列全体で最大 1 つの位置に出現できます。 つまり、すべての$b_i$は基本的に、他のすべての素数から素数のセットが「割り当てられ」、値はその積になります。 

辞書編集上の制約はすべての位置を結合します。初期の要素を増やすと、後で完全に異なる構成が強制される可能性があるため、インデックスごとに有効な最小値を個別に選択することはできません。 

と$n \le 10^5$そして$a_i \le 10^5$、ペアごとの gcd 関係や因数分解能を位置ごとに繰り返しテストしようとするソリューションは遅すぎます。 ステップごとの試行分割によって素数か共素性をチェックする単純な貪欲なアプローチでさえ、$O(n \sqrt{A})$、これはすでに限界に達していますが、さらに重要なことに、プライム再利用のグローバル構造が欠けています。 

微妙な失敗のケースは、初期の選択が後のポジションを不必要にブロックする場合に発生します。 たとえば、貪欲に割り当てると、$b_1 = a_1$多くの素数が含まれているため、後で人為的に大きなジャンプを強制する可能性があります。$b_1$より少ない素数を使用するか、異なる素数を使用して、より小さい将来の値を許可することもできたはずです。

 ## アルゴリズムのチュートリアル

 最小の素因数を前処理します。$10^5$。 これにより、任意の候補数を高速に因数分解できます。 

また、どの素数が以前の位置ですでに使用されているかを示すブール配列またはセットも維持します。 

配列を左から右に処理し、常に両方の制約と一致する各位置の有効な最小値を構築しようとします。 

1.インデックス用$i$、から始めます$x = a_i$。 
2.因数分解$x$SPFを使って。 何らかの素因数がある場合、$x$すでに使用されており、$x$は無効です。 
3. 有効な場合は、割り当てます$b_i = x$、そのすべての素因数を使用済みとしてマークします。 
4. 無効な場合はインクリメントします$x$有効になるまで。 増分ごとに因数分解とチェックを繰り返します。 
5. 有効期限が切れたら$x$が見つかったので、次のように修正します$b_i$そして続けてください。 

重要な構造上の決定は、以前の立場を決して再考しないことです。 位置が固定されると、その素数は永久に予約されるため、後の選択によって以前の有効性が破られることはありません。 

それが機能する理由は、貪欲な最小性の不変条件に関係しています。 すべてのインデックスで$i$では、以前のインデックスの固定選択肢を考慮して、グローバル素数制約に違反しない最小の値を選択します。 辞書編集上の順序は最初の異なる位置にのみ依存するため、位置の増加は$i$有効な割り当てが存在しない場合、これは避けられません。$a_i$。 過ぎ去ったら$a_i$、再び、実行可能な最小の数値を選択し、後で人為的なインフレが発生しないようにします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXV = 100000

spf = list(range(MAXV + 1))
for i in range(2, int(MAXV ** 0.5) + 1):
    if spf[i] == i:
        for j in range(i * i, MAXV + 1, i):
            if spf[j] == j:
                spf[j] = i

def factorize(x):
    res = set()
    while x > 1:
        p = spf[x]
        res.add(p)
        while x % p == 0:
            x //= p
    return res

n = int(input())
a = list(map(int, input().split()))

used = set()
b = []

for ai in a:
    x = ai
    while True:
        primes = factorize(x)
        ok = True
        for p in primes:
            if p in used:
                ok = False
                break
        if ok:
            for p in primes:
                used.add(p)
            b.append(x)
            break
        x += 1

print(*b)
```SPF テーブルは一度構築されると、ほぼ対数時間で各因数分解が可能になります。 次に、貪欲ループは次から始まる候補を試行します。$a_i$数値を受け入れるのは、その素因数が以前に使用されていない場合のみです。 

実装の重要な詳細は、候補ごとに因数分解を再計算することです。 これはコストがかかるように見えるかもしれませんが、それぞれの拒否はすでに使用されている素数に遭遇することによって引き起こされ、一度使用された素数は将来の有効な数値に再び現れることはないため、競合はすぐに減少します。

 ## 特殊なケース

 エッジケースの 1 つは、多くの初期の数値が小さな素数を共有する場合です。 のような入力の場合`2 4 6 8`、最初の値は素数 2 を消費し、次に 4 と 6 が両方とも激しく競合し、ジャンプを強制します。 アルゴリズムは、新しい素数構造が見つかるまで候補をスキップすることでこれを正しく処理し、最終的には次のようなシーケンスを生成します。`2 3 5 7`。 

もう 1 つのエッジ ケースは、すべての入力がすでにペアごとに互いに素である場合です。 その場合、最初は使用される素数が存在せず、アルゴリズムはインクリメントを実行しないため、すべての数値がすぐに受け入れられます。 のために`2 3 5 7 11`、各ステップは単に新しい素数をマークして続行します。 

最後のエッジケースは、初期のコンポジットが繰り返しの増分を強制する長いチェーンです。 例えば、`4 6 8 9 10`アルゴリズムは各位置を最小限にエスカレートし、代入が成功するたびに素数が永久に削除されるため、検索スペースが確実に縮小し、無制限の再試行が防止されます。
