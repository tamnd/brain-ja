 ## 解決策

 ## 問題の理解

 各単語の送信コストが固定されており、同じ意味を共有するいくつかの単語がグループ化されている語彙が与えられています。 グループ内では、メッセージの意味を変えることなく、任意の単語を同じグループ内の他の単語に置き換えることができます。 

メッセージは一連の単語です。 メッセージ内の各単語について、それをそのまま送信することも、同値グループの別の単語に置き換えることもできます。 そのポジションに対して私たちが支払うコストは、単に私たちが送信することを選択した言葉のコストです。 

目標は、メッセージ全体を送信する総コストを最小限に抑えることです。 

重要な構造は、各単語が正確に 1 つのグループに属し、置換はそのグループ内でのみ許可されるということです。 これにより、問題はメッセージ ワードごとに、そのグループ内で最も安価な代表を選択することになります。 

制約は最大 100,000 の単語、グループ、およびメッセージの長さになります。 これにより、グループ メンバーに対するネストされた検索を使用して単語ごとの置換を探索しようとするソリューションは即座に除外されます。 グループが大きい場合、そのグループの単純な単語ごとのスキャンはすでに遅すぎます。これは、全体の作業が二次的な動作に低下する可能性があるためです。 

グループに非常に高価な単語と非常に安価な単語が含まれている場合、微妙な失敗のケースが発生します。 常に元の言葉を維持する必要があると誤って仮定すると、改善を見逃してしまいます。 たとえば、グループが`{A(cost 100), B(cost 1)}`そしてメッセージには以下が含まれます`A`、最適な答えは次を使用します`B`その代わり。 グループごとの最小コストを事前計算しないソリューションは、ここで失敗します。 

グループがシングルトンである場合、別の特殊なケースが発生します。 その場合、交換は不可能ですので、元の費用を直接使用する必要があります。 これによってロジックが壊れることはありませんが、グループ処理が少なくとも 2 つの要素を想定している場合、誤った処理が行われやすくなります。 

## アプローチ

 ブルートフォースアプローチでは、各メッセージワードが個別に処理されます。 メッセージ内のすべての単語について、そのグループを特定し、そのグループ内のすべての単語をスキャンして最小コストを見つけます。 ほぼすべての単語が 1 つの大きなグループに属する最悪の場合のグループ化を想定すると、各クエリのコストは O(n) になる可能性があり、m 個のクエリでは O(nm) となり、これは 10^5 制約には大きすぎます。 

重要な観察は、メッセージのコストは、置換の構造ではなく、各グループ内の最小コストのみに依存するということです。 各同値クラスで最も安い単語がわかれば、そのクラスで出現するすべての単語をその最も安い単語に置き換えることができます。 

これにより、問題は前処理ステップに短縮され、すべてのグループについて、そのメンバー間の最小コストが計算されます。 次に、各単語をそのグループの最小コストにマップし、メッセージを合計します。 

単語からインデックスへのハッシュ マップ、インデックスからグループ ID への配列マッピング、およびグループの最小コストを格納する配列を使用して、これを効率的に実装できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nm) | O(n) | 遅すぎる |
 | 最適 | O(n + m + n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての単語を読み取り、各単語にインデックスを割り当てます。 

これにより、メッセージ文字列からそのコストとグループまでの定数検索が可能になります。 
2. コスト配列を読み取り、各コストをその単語インデックスに関連付けます。 

これで、すべての単語の送信コストがわかります。 
3. 各単語インデックスからそのグループ ID へのマッピングを構築します。 

各単語は正確に 1 つのグループに属しているため、これは直接割り当てです。 
4. 各グループについて、そのグループ内のすべての単語の最小コストを計算します。 

グループ メンバーを 1 回スキャンし、最小限の実行を維持します。 
5. メッセージ内の各単語について、それをインデックスに変換し、そのコストを事前に計算されたグループの最小コストで置き換えます。 

これは、許可される可能な限り最良の置換をモデル化します。 
6. すべてのメッセージ ワードにわたるこれらの最小コストを合計し、結果を出力します。 

### なぜ効果があるのか

 各メッセージ ワードは置換の選択肢に関して独立しています。 唯一の制約は、置換が同じグループ内に留まるということです。 メッセージ内の位置間には相互作用がないため、各位置を個別に最適化することが全体的に最適です。 グループ内で最小コストの単語以外を選択するとコストが増加するだけであるため、最小値はすべての出現に対して常に最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k, m = map(int, input().split())
    
    words = input().split()
    cost = list(map(int, input().split()))
    
    idx = {w: i for i, w in enumerate(words)}
    
    group = [-1] * n
    group_min = [10**18] * k
    
    for gid in range(k):
        data = list(map(int, input().split()))
        x = data[0]
        members = data[1:]
        for v in members:
            v -= 1
            group[v] = gid
            group_min[gid] = min(group_min[gid], cost[v])
    
    msg = input().split()
    
    ans = 0
    for w in msg:
        i = idx[w]
        g = group[i]
        ans += group_min[g]
    
    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションでは、単語からインデックスまでの辞書を構築するため、メッセージの検索は一定時間になります。 次に、各単語をグループに割り当て、同時にそのグループの最小コストを計算します。 メッセージの最後のループでは、単純に各単語をそのグループ ID に変換し、対応する最小コストを累積します。 入力グループは 1 から始まるため、インデックスから 1 を減算する必要があります。 

よくある落とし穴は、前処理ではなくクエリ時にグループ最小値を再計算することです。 これにより、各メッセージの検索がグループ全体のスキャンになり、不必要かつ遅すぎます。

## 特殊なケース

 次のようなシングルトン グループ`1 1`その単語に代替手段がないことを保証します。 アルゴリズムは独自のコストをグループの最小値として割り当てるため、クエリでは元の値が正しく使用されます。 

すべての単語を含む大規模なグループは、前処理によって単一の最小値がすべてのメッセージ位置に正しく伝播されるかどうかをテストします。 このアルゴリズムは 1 つのグローバル最小値を計算し、それを一貫して適用します。 

同じ単語を複数回繰り返すメッセージでは、ルックアップが安定しており、状態の再計算や変更が行われないことがチェックされます。 出現するたびに、事前に計算された同じグループの最小値が独立して取得され、正確性が維持されます。
