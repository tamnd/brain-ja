 ## 問題の理解

 各値が 20 ビットの数値として扱われる整数の配列が与えられます。 すべてのクエリについて、配列のプレフィックス、特に最初のプレフィックスのみを調べます。$l$要素があり、そのプレフィックスの XOR がターゲット値と等しいサブシーケンスがいくつあるかをカウントする必要があります。$x$。 ここでのサブシーケンスとは、各要素を独立して取得またはスキップできるため、プレフィックス内のインデックスのすべてのサブセットが有効であることを意味します。 

キー出力は単一のサブシーケンスではなく、選択された要素の XOR がクエリ値と等しい、モジュロを取得したさまざまなサブシーケンスの数です。$10^9 + 7$。 

この制約により、サブシーケンスの列挙が直ちに除外されます。 配列とクエリの数は両方とも最大です$10^5$、各要素はサイズの状態空間に寄与します。$2^{20}$XOR 値が存在するため、$[0, 2^{20})$。 サブセット XOR を再計算したり、プレフィックスごとに明示的な DP を個別に維持したりして各クエリを処理するソリューションは、時間制限を何桁も超えてしまいます。 

微妙な特殊なケースは、空のサブシーケンスです。 その XOR はゼロとして定義されているため、$x = 0$プレフィックスを考慮する場合は、要素が選択されていない場合でも、それを含める必要があります。 

もう 1 つの重要な特殊ケースは、値またはゼロの繰り返しです。 たとえば、配列に多くのゼロが含まれている場合、各ゼロは固定 XOR ターゲットのサブシーケンスの数を 2 倍にしますが、これは DP 遷移を通じて一貫して伝播する必要がある構造化された方法でのみ行われます。 

## アプローチ

 直接的なアプローチでは、最初のサブシーケンスをすべて列挙します。$l$各クエリの要素。 長さの固定プレフィックスの場合$l$、これは$2^l$、そしてクエリ全体ではこれは不可能になります。$l$できる$10^5$。 クエリごとに個別に DP を計算するだけでもコストがかかります$O(q \cdot l \cdot 2^{20})$、これは実現不可能です。 

XOR サブセット計数問題に関する標準的な洞察は、サブセット XOR が GF(2) 上のベクトル空間上の線形結合のように動作するということです。 新しい要素はそれぞれ、到達可能な XOR の空間を変更しないか、現在の基底から線形独立している場合は次元を 1 つ増やします。 

すべてのサブセット数を直接追跡する代わりに、依存要素によって同じ XOR 値に集約される異なるサブセットの数を表すグローバル乗算係数とともに、XOR 値の線形基礎を維持します。 

重要な構造的事実は、現在の基盤にサイズがある場合、$k$、その後、最初の$i$要素、正確には$2^{i-k}$サブセットは、基底の範囲内で到達可能な各 XOR 値に対応します。 この均一性によりカウントが可能になります。スパン内のすべての XOR 値には、生成されるサブセットの数が同じになります。 

クエリの場合、ターゲット XOR を削減します。$x$基礎を使って。 表現できない場合、答えはゼロです。 それが表現可能であれば、答えは正確に$2^{l-k}$、 どこ$k$最初の基底ベクトルの数です。$l$要素。 

プレフィックス クエリを効率的にサポートするために、ベースを段階的に構築し、各プレフィックス位置でのサイズと構造のスナップショットを保存します。 各クエリは次のように回答されます。$O(20)$減らすことによって$x$保存された基準に対して。

 ## アルゴリズムのチュートリアル

 線形 XOR ベースを維持しながら、配列を左から右に処理します。 

1. 基底ベクトルを表すサイズ 20 の配列を初期化し、すべてゼロに設定します。 2 のべき乗モジュロも事前計算します$10^9+7$。 
2. 各要素について$a_i$、標準の最上位ビット除去を使用して XOR ベースに挿入します。 縮小後にゼロになった場合、依存性があり、基底サイズは増加しません。 
3. 基本ランクの継続カウントを維持する$k_i$各プレフィックスを処理した後$i$。 また、基本スナップショット、または少なくともそのプレフィックスの削減に答えるのに十分な構造も保存します。 
4. お問い合わせの場合$(l, x)$、接頭辞に対応する基底を取得します。$l$そして削減しようとします$x$保存された基底ベクトルを使用して最上位ビットを削除することによって。 
5. 削減後の場合$x$ゼロになると、答えは$2^{l - k_l}$。 それ以外の場合、答えはゼロです。 

リダクションが機能する理由は、基底が達成可能なすべての XOR 値の一連のセットを表すためです。 値をゼロに減らすことができない場合、その値はスパンの外側にあり、サブシーケンスはその値を生成しません。 

### なぜ効果があるのか

 すべてのサブセット XOR のセットは、GF(2) 上のベクトル空間を形成します。 私たちが維持する基盤は、この空間の基盤です。 すべてのサブセットは、基底ベクトルと依存要素の選択の線形結合に対応し、表現可能な XOR 値を変更せずにカウントのみを乗算します。 各独立要素はサブセットの数を 2 倍にし、独立している場合にのみ次元を増加させるため、表現可能な XOR ごとのサブセットの数は均一になり、等しくなります。$2^{\text{free dimensions}}$。 この不変式はすべてのプレフィックスに適用され、すべてのクエリに対する正しい答えが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7
MAXB = 20

def build_powers(n):
    pw = [1] * (n + 1)
    for i in range(1, n + 1):
        pw[i] = (pw[i - 1] * 2) % MOD
    return pw

def insert_basis(basis, x):
    for b in reversed(range(MAXB)):
        if not (x >> b) & 1:
            continue
        if basis[b]:
            x ^= basis[b]
        else:
            basis[b] = x
            return True
    return False

def reduce_x(basis, x):
    for b in reversed(range(MAXB)):
        if (x >> b) & 1:
            if basis[b]:
                x ^= basis[b]
    return x == 0

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    basis = [0] * MAXB
    prefix_basis = [None] * (n + 1)
    rank = 0

    prefix_basis[0] = ([0] * MAXB, 0)

    for i in range(1, n + 1):
        new_basis = basis[:]
        before_rank = sum(1 for x in new_basis if x)
        if insert_basis(new_basis, a[i - 1]):
            rank = before_rank + 1
        else:
            rank = before_rank
        basis = new_basis
        prefix_basis[i] = (basis[:], rank)

    pw = build_powers(n)

    out = []
    for _ in range(q):
        l, x = map(int, input().split())
        b, r = prefix_basis[l]
        if reduce_x(b, x):
            out.append(str(pw[l - r]))
        else:
            out.append("0")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装では、プレフィックス線形基底を構築し、各プレフィックスに対して基底ベクトルとそのランクの両方を保存します。 各クエリは保存された状態を取得し、そのベースに対してターゲットの XOR を削減します。 削減が成功した場合、答えはプレフィックスに存在する依存要素の数によって決まる 2 のべき乗になります。 

実装の微妙な詳細は、プレフィックスごとにベースをコピーすることです。 これにより、クエリが後の更新に干渉することがなくなります。 標準基底構造と一致させるために、リダクション ステップは上位ビットから下位ビットに進む必要があります。 

基底維持により位置間でベクトルがシフトされる可能性があるため、ランクの計算は基底配列内の単に非ゼロ ベクトルの数ではなく、独立した挿入の数を反映する必要があります。

 ## 特殊なケース

 重大なエッジケースは、配列にゼロのみが含まれる場合です。 基底はすべてのプレフィックスに対して空のままであるため、長さのすべてのプレフィックス$l$もっている$2^l$XOR がゼロに等しいサブシーケンスと、ゼロ以外のすべてのクエリはゼロを返します。 ゼロ以外の値の削減は失敗し、ランクはゼロのままであるため、アルゴリズムはこれを処理します。 

もう 1 つのケースは、すべての要素が同一のゼロ以外の値である場合です。 最初の挿入後、後続のすべての要素は依存します。 ランクは 1 に留まり、すべてのプレフィックスは 2 状態システムとして動作します。XOR は 0 またはその値で、カウントは依存する挿入に基づいて 2 のべき乗としてスケーリングされます。 

最後の微妙なケースは、次のようなクエリです。$x = 0$。 基底ベクトルが存在しない場合でも、すぐにリダクションが成功し、答えは次のようになります。$2^l$、空のサブセットを含むすべてのサブセットを正確にカウントします。
