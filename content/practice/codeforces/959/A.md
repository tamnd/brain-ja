 ## 解決策
 ## 問題の理解

 ゲームは単一の整数値から始まり、2 人のプレイヤーが交互に整数値を減らします。 マフムードの番では、現在の値を超えない正の偶数を減算することのみが許可されます。 エハブの番では、同じ範囲内で正の奇数を減算することのみが許可されます。 プレーヤーが自分の番に利用できる法的な減算を持っていない場合、そのプレーヤーはすぐに負けます。 

重要な点は、ゲームは多くの値の中からの戦略的な選択ではなく、許可される手のパリティ構造によって完全に決定されるということです。 各手は厳密に数値を減らすため、有限のステップ数を経た後にゲームを終了する必要があり、最適なプレイとは、最初のプレイヤーの開始位置が勝つか負けるかを決定することになります。 

入力サイズの制約により、n は最大 10^9 まで許容されます。 これにより、ゲーム ツリーの状態を探索しようとするシミュレーションは即座に除外されます。これは、n までのすべての状態を線形に走査するだけでも遅すぎるためです。 有効な解決策は、ゲームを n のプロパティに基づいた定数時間の決定に圧縮する必要があります。 

n が非常に小さい場合、微妙なエッジ ケースが発生します。 たとえば、n = 1 の場合、マフムードは偶数を引くことができないため、すぐに負けます。 n = 2 の場合、マフムードは 2 を引くことができ、エハブには 0 が残ります。エハブには利用可能な奇妙な手がなくなるため、マフムードが勝ちます。 これらの小さなケースは、n の大きさそのものよりも利用可能な手のパリティの方が重要であることを明らかにしています。 

もう 1 つの潜在的な落とし穴は、n が 0 になるまで両方のプレーヤーが常に動けると仮定していることです。これは誤りです。許可されるパリティによって利用可能な動きが非対称に制限されるため、一方のプレーヤーが予想よりも早く負ける状況に追い込まれる可能性があります。 

## アプローチ

 直接的なアプローチは、ゲームをシミュレートすることです。 各ステップで、現在のプレイヤーのすべての有効な手を試し、結果の状態を再帰的に評価し、対戦相手に不利な立場につながる手があるかどうかを判断します。 これは、0 から n までの状態の行に関する標準的なミニマックス ゲームです。 

ゲームは有限で決定的であるため、これは概念的に機能します。 ただし、任意の状態 n から、Mahmoud は最大 n/2 の偶数手を試すことができ、Ehab は最大 (n+1)/2 の奇数の手を試すことができます。 移動するたびに状態は減少しますが、新しいブランチが作成されます。 最悪の場合、再帰によって状態の大部分が繰り返し探索され、メモ化が使用されていない場合は指数関数的な動作が発生し、メモ化が使用されている場合でも少なくとも線形の動作が発生します。 n は 10^9 になる可能性があるため、O(n) さえ不可能です。 

重要な観察は、許可される手の構造がゲームを単純な同等の状態に崩壊させるということです。 マフムードは、少なくとも 1 つの偶数 ≤ n が存在する場合にのみ移動できます。これはまさに n ≥ 2 の場合に発生します。1 は常に有効な奇数の減算であるため、エハーブは n ≥ 1 のときはいつでも移動できます。 これらの制約間の相互作用は、唯一の意味のある区別は、最初の n が偶数であるか奇数であるかであることを示しています。 n が偶数の場合、マフムードはエハブを勝利継続のない位置に追い込む形で構造を維持する動きを行うことができます。 n が奇数の場合、マフムードはアドバンテージを完全に安定させる均等な動きを即座に行うことができなくなり、エハブがコントロールを奪います。 

これにより、ゲーム全体が n のパリティをチェックするだけになります。

 ## アルゴリズムのチュートリアル

1. ゲームの初期状態を表す整数 n を読み取ります。 
2. Mahmoud が最初に勝つかどうかはパリティのみで決まるため、n が偶数か奇数かをチェックします。 
3. n が奇数の場合、マフムードは有利な構造を残す手を打つことができないため、エハブが即座に勝つと結論付けます。 
4. n が偶数の場合、マフムードは最初に 2 を引いて、エハブに奇数を残すことができます。その後、マフムードはパリティ アドバンテージの制御を維持する方法でエハブの強制的な奇数の手に常に応答できるため、マフムードが勝ちます。 

### なぜ効果があるのか

 ゲームは、どのプレイヤーが最初に合法的な手が存在しない局面に直面することを余儀なくされるかを追跡することに要約されます。 マフムードは偶数の動きに制限されており、バランスの取れた削減パターンを維持する方法で即座に対応できないため、開始状態が奇数の場合に事実上コントロールを失うことを意味します。 n が偶数の場合、Mahmoud は常に奇数状態への最初の還元を行うことができ、その後 Ehab は不利なパリティ位置に追い込まれます。 すべての手が厳密に n を減らし、最適なプレイの下ではパリティが交互に現れるため、最初のパリティによってどのプレイヤーが最終的にブロックされるかが完全に決まります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())

if n % 2 == 1:
    print("Ehab")
else:
    print("Mahmoud")
```このソリューションは、単一の整数を読み取り、すぐにそのパリティをチェックします。 ゲームは二項分類に折りたたまれるため、状態の追跡やシミュレーションは必要ありません。 モジュロ演算は定数時間であり、結果を出力することで決定が確定します。 

唯一の微妙な実装の詳細は、n = 1 と n = 2 に対する正しいパリティ処理を保証することです。1 は奇数、2 は偶数であり、既知の結果と一致するため、これらはすでに同じ条件でカバーされています。

これら 2 つのトレースは、ゲーム全体の結果が初期状態の同等性によって直ちに決定されることを示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(sys.stdin.readline())
    return "Ehab" if n % 2 == 1 else "Mahmoud"

# provided samples
assert run("1\n") == "Ehab", "sample 1"
assert run("2\n") == "Mahmoud", "sample 2"

# custom cases
assert run("3\n") == "Ehab", "small odd"
assert run("4\n") == "Mahmoud", "small even"
assert run("1000000000\n") == "Mahmoud", "large even"
assert run("999999999\n") == "Ehab", "large odd"
assert run("5\n") == "Ehab", "odd mid case"

 ## 特殊なケース

 n = 1 の場合、アルゴリズムはパリティをチェックし、Ehab を出力します。 これは、マフムードがまったく均等な動きを持たないという事実と一致するため、ゲームは最初のターンですぐに終了します。 

n = 2 の場合、アルゴリズムは Mahmoud を出力します。 ロジックをたどると、n は偶数であるため、マフムードが勝者と宣言されます。これは、法的な奇数の減算を行わずに 2 を減算し、エハブを強制的に n = 0 にする一連の動きと一致します。 

10^9 などの非常に大きな n の場合、モジュロ 2 のみが評価され、大きさに依存する反復がないため、計算は同一のままです。
