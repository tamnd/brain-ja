 ## 解決策
 ## 問題の理解

 私たちは、各ノードがミツバチとスズメバチという 2 種類の昆虫を含む「営巣地」を表す木を与えられています。 すべての昆虫は自分の側に投票するため、ミツバチは常にその地域のミツバチの数に寄与し、スズメバチは常にスズメバチの数に寄与します。 

ツリーを正確に分割する必要があります$m$接続されたグループ。各グループは接続されたサブグラフです。 各グループは村として扱われ、各村内でスズメバチの総数とミツバチの総数を比較します。 スズメバチが厳密にミツバチを超えている場合、その村は醜いワスプの勝利としてカウントされます。そうでない場合は、プリティ ビーの勝利と見なされます。 目標は、スズメバチが獲得できる村の数を最大化するパーティションを選択することです。 

各村が接続されなければならないという構造上の制約により、すべての村が木の一部のエッジカットの接続されたコンポーネントに対応する必要があります。 したがって、実際の作業は、エッジを正確に形成するためにどこでカットするかを決定することです$m$スズメバチに有利に総重量差がプラスになるコンポーネントの数を最大化しながら、接続コンポーネントを増やします。 

この制約は十分に大きいため、パーティションを列挙しようとするソリューションや、すべてのサブツリー分割さえも不可能です。 と$n$テストあたり合計で最大 3000$10^5$、テストごとの 3 次またはそれより悪いアプローチは失敗します。 これにより、すべてのパーティションを試行したり、構造のないノードのサブセットに対して単純な DP を実行したりすることが直ちに排除されます。 

重要な微妙な点は、スズメバチとミツバチの合計がまったく同じ村は勝利としてカウントされないことです。 これにより、線形スコア関数ではなく鋭いしきい値効果が生じ、単純な貪欲な集計の信頼性が低くなります。 

もう 1 つの微妙なケースは、より多くの村に分割することが必ずしも有益であるとは限らないということです。 全体的に負けているサブツリーには、内部にポジティブなセグメントが含まれている可能性がありますが、それを誤って切断すると、他の場所での潜在的な勝利が損なわれる可能性があります。これは、切断では接続性が考慮されなければならず、コンポーネントの総数が固定されているためです。 

## アプローチ

 強引な視点では、ツリーが正確に分割されるようにエッジを切断するあらゆる方法を検討しようとします。$m$接続されたコンポーネントを抽出し、各コンポーネントのスコアを計算します。 エッジサブセットの数は指数関数的です$n$、さらには正確に有効なフォレストに制限することもできます。$m$コンポーネントには依然として指数関数的な数の構成が残っています。 コンポーネントの合計の計算は線形であるため、このアプローチは天文学的な規模になります。 

問題の構造は、実際には任意のパーティションを選択しているのではなく、正確にパーティションを選択していることを示唆しています。$m-1$削除するエッジ。 エッジが削除されると、サブツリーは独立し、その寄与は内部の集計​​値のみに依存します。 これは当然、サブツリーごとに、内部で実行するカットの数に応じて何が達成できるかを計算するツリー DP を示唆します。 

重要な観察は、各サブツリーは独立して処理できるが、サブツリー間の唯一の相互作用は、「費やす」カットの数によって行われるということです。 これにより、子に対するナップサック スタイルの DP が実現します。各ノードは子からの結果を集約し、形成される「適切な」コンポーネントの数を最大化しながら、各子サブツリーに割り当てるカットの数を決定します。 

重要な単純化は、どの連結コンポーネントについても、合計の差のみが重要であるということです。$\text{wasps} - \text{bees}$。 この合計が厳密に正であれば、コンポーネントは良好です。 これにより、各サブツリーをマージ可能な値を生成するものとして扱うことができ、分割されたサブツリーを独立した候補に切り分けることができます。 

したがって、完全なパーティションを追跡するのではなく、サブツリーを分割したコンポーネントの数を考慮して、サブツリー内で達成可能な最良のコンポーネントの数を追跡します。

 ## アルゴリズムのチュートリアル

 ツリーのルートをノード 1 に設定します。ノードごとに、サブツリー内のノードの数が指定された数の連結成分に分割される状態を表す DP 配列を計算し、取得できる勝利成分の最大数を保存します。 

させて$dp[u][k]$は、サブツリーから取得できる勝利村の最大数を示します。$u$正確に分割した場合$k$コンポーネント。 

1. 各ノードの初期化$u$となることによって$dp[u][1]$これは、サブツリーがまったく切断されない場合に相当します。 この場合、サブツリー全体が 1 つのコンポーネントであり、その値は合計の場合は 1 になります。$w-b > 0$それ以外の場合は 0。これは、カットが導入される前の基本ケースを表します。 
2. それぞれの子どもに対して$v$の$u$の DP をマージします。$v$の中へ$u$。 現時点では、現在の部分ソリューション間でコンポーネントを分散することを検討しています。$u$そしてサブツリー$v$。 これは、コンポーネント数を考慮した古典的なナップザック マージです。 
3. マージ中に、部分的な DP がすでに計算されていると仮定します。$u$、そして私たちは処理します$v$。 割り当てれば$x$コンポーネントを$v$そして$y$コンポーネントを現在の状態に戻す$u$、合計は次のようになります$x+y$コンポーネント。 すべての分割を試し、達成可能な最高の勝利コンポーネント数を更新します。 
4. マージ ステップでは、間のエッジが$u$そして$v$カットされているかどうか。 カットされてしまうと、$v$別個のコンポーネントとして独立して貢献します。 カットされていない場合は、$v$のサブツリーは次とマージする必要があります$u$、コンポーネント数を 1 減らして、それらの重みを結合します。 
5. これをきれいに処理するために、コンポーネント数ごとの DP だけでなく、合併した州の合計残高 (スズメバチからミツバチを差し引いたもの) も維持します。 2 つのパーツを結合するときに、接続されたままであれば、残高が合計されます。 結果の合計が正の場合、結合されたコンポーネントは 1 回の勝利に貢献します。 
6. すべての子を処理した後、$dp[u]$完全に計算されます。 根の答えが最大$dp[1][m]$。 

重要なアイデアは、エッジを「カット」するたびにコンポーネントの数が 1 ずつ増加し、その合計バランスのみによって勝利が左右される新しい独立した候補者が得られるということです。 DP は基本的に、正確な予算の下でどのエッジをカットするかを決定しています。$m-1$カット。 

### なぜ効果があるのか

 有効なパーティション内のすべての連結コンポーネントは、一連のエッジを削除した後に形成されたサブツリーに対応します。 DP は、サブツリー間でカットを分散する可能なすべての方法が、ナップザック遷移を通じて 1 回だけ考慮されることを保証します。 各コンポーネントの勝利条件は内部構造ではなく集計値のみに依存するため、DP 状態はすべての関連情報を取得するのに十分です。 ツリー構造ではサイクルがないことが保証されているため、エッジが切断されると部分問題は独立します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    n, m = map(int, input().split())
    b = list(map(int, input().split()))
    w = list(map(int, input().split()))

    g = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    # dp[u] = list of (components, best wins, total balance)
    # we will store only best wins; balance tracked separately during merge
    dp = [None] * n
    total_balance = [0] * n

    def dfs(u, p):
        # initial: one component consisting of u
        cur = [(1, 1 if w[u] - b[u] > 0 else 0, w[u] - b[u])]
        total_balance[u] = w[u] - b[u]

        for v in g[u]:
            if v == p:
                continue
            dfs(v, u)

            nxt = {}
            # option 1: keep v as separate component(s)
            for c1, w1, bal1 in cur:
                for c2, w2, bal2 in dp[v]:
                    nc = c1 + c2
                    nb = w1 + w2
                    nxt[nc] = max(nxt.get(nc, 0), nb)

            # option 2: merge v into u as one component
            merged_bal = total_balance[u] + total_balance[v]
            merged_win = 1 if merged_bal > 0 else 0

            for c1, w1, bal1 in cur:
                nc = c1 + (dp[v][0][0] - 1)
                nb = w1 - (1 if bal1 > 0 else 0) + merged_win
                nxt[nc] = max(nxt.get(nc, 0), nb)

            cur = [(k, v, 0) for k, v in nxt.items()]
            total_balance[u] += total_balance[v]

        dp[u] = cur

    dfs(0, -1)

    ans = 0
    for c, wv, _ in dp[0]:
        if c == m:
            ans = max(ans, wv)

    print(ans)

t = int(input())
for _ in range(t):
    solve()
```この実装は、形成されるコンポーネントの数を追跡しながら、子の DP 状態を親にマージするという考えに従っています。 再帰により DP がボトムアップで構築されます。 トリッキーな部分は、コンポーネントのカウントがエッジをカットするかマージするかによって異なり、これは子 DP 状態を直接追加するか、親のバランスにマージすることによってエンコードされることです。 

主な微妙な点は、マージ時にコンポーネント数の一貫性を確保することです。 マージするたびに、子サブツリーを個別に処理する場合と比較して、コンポーネントの数が 1 つずつ効果的に減少します。これは、マージによってコンポーネントの接続が保たれながら、エッジが切断されるとコンポーネント数が増加するためです。

 ## 特殊なケース

 重大なエッジ ケースは、サブツリーの合計残高がちょうどゼロになる場合です。 この場合、親にマージしても勝者のコンポーネントは生成されませんが、分割しても勝者のサブサブツリーが作成される可能性があります。 DP は両方の可能性を別々に保持する必要があります。 そうしないと、中立コンポーネントが誤って勝利としてカウントされます。 

別のエッジケースが発生するのは次の場合です。$m = n$。 すべてのノードは独自の村になる必要があります。 アルゴリズムは、各ノードが独立して扱われること、および勝利数がノード数に減少することを保証する必要があります。$w_i > b_i$。 誤って少なくとも 1 つのマージを強制するマージ ベースのロジックは、過小評価されます。 

最後の微妙なケースは、交互のノードが正と負のバランスを持つ長いチェーンです。 切断は必要なコンポーネントの正確な数によって全体的に制約されるため、極大値での貪欲な切断は失敗します。 DP は、予算が許す場合にのみ孤立したプラスのセグメントが形成されるように、カットを世界的に分散することでこれに対処します。
