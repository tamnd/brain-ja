 ## 解決策
 ## 問題の理解

 このプロセスは、数字 1、2、および 3 のみで構成される短い文字列から始まります。この文字列に加えて、文字間の位置を左から右に移動するカーソルと、コピーされた文字列の接尾辞を保存できるクリップボードを維持します。 

各反復では、カーソル位置の周囲で固定のローカル操作が実行されます。 まずカーソルが 1 位置進みます。 次に、カーソルの右側にあるものはすべて切り取られ、プレフィックスだけを残してクリップボードに保存されます。 最後に、クリップボードの内容が複数回追加され、繰り返しの回数はカーソル位置にある数字によって異なります。 

このプロセスは、カーソルが目標位置 x に到達するまで続きます。 私たちが気にする唯一の量は文字列の実際の内容ではなく、文字列の最終的な長さであり、結果は 1e9 + 7 を法として計算する必要があります。 

重要な制約は、すべてのテスト ケースの x 値の合計が最大 100 万であり、各初期文字列の長さが最大 500 であることです。これは、文字展開ごとではなくカーソル位置ごとにシミュレートできることを強く示唆していますが、最悪のケースでは長さが指数関数的に増加するため、文字列を明示的に構築することはできません。 

単純な解釈では、文字通り文字列をシミュレートします。 これは、カットアンドペーストの各ステップで大きなサフィックスが重複し、文字列の長さが爆発的に増加するため、すぐに失敗します。 1 つの数字 3 を何度も繰り返す場合でも、文字列の長さは倍増して、実行可能なメモリや時間の予算をすぐに超えてしまいます。 

2 番目の単純な間違いは、長さだけをシミュレートし、部分文字列をスライスまたはコピーすることでサフィックスの寄与を再計算することです。 サフィックスのサイズは現在の文字列の長さに比例するため、これもステップごとに 2 次になります。 

さらに微妙なエッジ ケースは、クリップボードが常に現在のカーソルのサフィックスであり、固定された部分文字列ではないことを忘れていることから発生します。 たとえば、次のように始めます。`231`、最初の移動と切り取りの後、クリップボードは`31`。 その後の変更の後、以前の直感では再利用が示唆されていたとしても、クリップボードは完全に変更されます。 

## アプローチ

 ブルートフォースアプローチは文字通りプロセスに従います。 完全な文字列を維持し、カーソルを移動し、サフィックスを切り取り、貼り付けを繰り返します。 現在の文字列の長さでは各反復に直線的な時間がかかる可能性があり、文字列自体が指数関数的に増大するため、このアプローチはすぐに実行不可能になります。 操作を正確に反映しているため、正確さは明らかですが、コストは文字列のコピーの繰り返しによって大きく左右されます。 

重要な点は、将来の成長にとって重要なのは、サフィックスの実際の文字ではなく、文字列の長さと現在の位置の値だけであるということです。 すべての貼り付け操作は同一のコピーを追加するだけであるため、クリップボードの内容は、その長さ以外の将来の操作と構造的に相互作用することはありません。 したがって、文字列を追跡する代わりに、長さを追跡します。 

させて`len[i]`反復 i が終了した後の文字列の長さを示し、`a[i]`反復 i の移動ステップ後のカーソル位置の数字になります。 この数字によって、追加されるサフィックスの長さを何倍にするかが完全に決まります。 

各反復には非常に特殊な構造があります。接尾辞 (カット) を削除し、その接尾辞を繰り返し追加します。`a[i]`回。 切断前の文字列の長さが L で、カーソルが位置 i にある場合、接尾辞の長さは次のようになります。`L - i`したがって、新しい長さは次のようになります。 

L' = i + (L - i) * a[i]

 これにより、プロセス全体が長さの値に対する線形反復に短縮されます。 唯一欠けているコンポーネントは、各移動後にカーソルの下の桁を決定する方法です。 カーソルは反復ごとに常に 1 つずつ進み、文字列の長さは予測どおりに変化するため、文字列を構築せずに位置の論理構造のみをシミュレートできます。 

私たちは概念的には進化する文字列の配列表現を維持しますが、それを保存する代わりに、元の各文字の「ブロック」がどこにコピーされるのか、そしてそれが何回コピーされたのかを追跡します。 

中心的なアイデアは、セグメントの観点からプロセスをシミュレートすることです。各元の文字は成長するブロックに寄与し、各反復ではこれらのブロックが保存または複製されます。 x は最大 1e6 であるため、接頭辞の追跡と長さの伝播を使用して、カーソルの動きをシミュレートし、O(x + |s|) の寄与を計算できます。

 ## アルゴリズムのチュートリアル

 各ステップでプロセスを、現在のカーソル位置 i と現在の全長 L という 2 つの情報だけを維持するものとして再解釈します。また、展開する文字列の位置 i の数字を知る必要もあります。 

文字列はサフィックスのコピーを追加することによってのみ変更されるため、元の各文字を時間の経過とともに多重度が増加するブロックを生成するものとして扱います。 

配列を維持します`cnt[j]`j 番目の元のキャラクターの貢献が最終文字列で現在複製されている回数を表します。 最初はすべて 1 です。 

また、これらの寄与の加重合計である現在の有効長も維持します。 

各反復は次のように進行します。 

1. カーソルを i から i + 1 に移動します。これは単に論理ポインタを進めるだけです。 まだ構造的な変化は起こっていませんが、現在は数字が存在する新しい位置に焦点を当てています。 
2. 桁を決定する`d = s[i]`。 進化では接尾辞が追加されるだけなので、i までのすべての接頭辞は元の構造と一貫性が保たれるため、これは常に導出可能です。 
3. 寄与数の観点から、i から末尾までのサフィックスの長さを計算します。 これは重複する部分です。 
4. 接尾辞を一度削除してから追加することで、全長を更新します。`d`回。 これにより、長さが L = i + (L - i) * d として変換されます。 
5. i が x に達するまで繰り返します。 

主な困難は、文字列を構築せずに (L - i) を効率的に計算することです。 L を直接維持し、i が既知であるため、サフィックスの長さはステップごとに O(1) です。 

### なぜ効果があるのか

 各ステップで、文字列はカーソル i までの固定プレフィックスと、常に以前のセグメントの繰り返しコピーであるサフィックスに分解できます。 切り取り操作ではそのサフィックスのコピーが 1 つだけ削除され、貼り付け操作ではそのサフィックスの同一のコピーが追加されます。 これにより、サフィックスは、その長さだけが関連するプロパティを持つ単一の原子単位として動作することが保証されます。 今後のすべての操作は存在するコピーの数のみに依存するため、追跡長によって状態遷移が完全に保存されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    t = int(input())
    for _ in range(t):
        x = int(input())
        s = input().strip()

        # 1-indexed logical cursor
        i = 0
        n = len(s)
        L = n

        # We conceptually extend s as it grows, but we avoid storing it.
        # Instead we maintain a dynamic representation using a list.
        # Since we only ever access positions up to x, we can safely
        # simulate expansion lazily.

        s = list(s)

        for step in range(x):
            i += 1
            if i >= len(s):
                # If cursor goes beyond current known prefix, it must be in repeated suffix
                # but we extend s logically using growth rule.
                i = len(s) - 1

            d = ord(s[i]) - ord('0')

            suffix_len = (L - i) % MOD
            L = (i + suffix_len * d) % MOD

            # We do not physically build the string; we only ensure s is large enough
            # to access future digits up to x if needed.
            if len(s) < x + 5:
                # append virtual structure: in reality this is conceptual
                # but we only need digit values, which remain consistent in prefix simulation
                s.append(s[i])

            if i == x:
                break

        print(L % MOD)

if __name__ == "__main__":
    solve()
```このコードは、カーソル位置と現在の文字列長という 2 つの変化する量のみを追跡します。 カーソルの位置にある数字は、文字列の遅延拡張表現から取得されます。 重要な繰り返しは長さの更新です`L = i + (L - i) * d`、各反復で適用されます。 

リスト拡張は、指数文字列を明示的に構築しなくても確実に数字を読み取ることができる実用的な方法です。 正確さは、位置の数字がサフィックスの複製の繰り返しによって決定されるという事実に依存しているため、以前の構造をコピーすると、将来の数字へのアクセスが保持されます。

import sys, io

MOD = 10**9 + 7

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []

    for _ in range(t):
        x = int(input())
        s = input().strip()
        i = 0
        L = len(s)
        s = list(s)

        for _ in range(x):
            i += 1
            if i >= len(s):

            if len(s) < x + 5:
                s.append(s[i])
            if i == x:
                break

        out.append(str(L % MOD))

    return "\n".join(out)

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、文字列全体が 1 で構成されている場合です。 この場合、各ステップでサフィックスが 1 回だけ保持されるため、線形成長を超える真の拡張は起こりません。 反復は L = i + (L - i) に減少し、長さが安定します。 1 を乗算するとサフィックスが変更されず、人為的な増加が発生しないため、アルゴリズムはこれを処理します。 

桁が常に 3 の場合、別のエッジ ケースが発生します。ここでは、反復ごとにサフィックスの寄与が 3 倍になります。 カーソルは着実に進み、サフィックスは幾何学的に成長します。 このアルゴリズムは、指数文字列を具体化することなく各ステップで繰り返しを正しく適用するため、長さが急速に増加してもメモリは一定のままです。 

最後の微妙なケースは、x が元の長さに等しい場合です。 プロセスは正確に境界で停止し、終了する前に最後のカットアンドペーストのステップを含める必要があります。 アルゴリズムは位置を更新した後にカーソルをチェックし、停止する前に繰り返しを適用するため、最後の変換を見逃すことなく最終状態が正しく考慮されます。
