 ## 解決策
 ## 問題の理解

 重み付けされたツリーが与えられています。$2k$頂点。 これらの頂点に配置する必要があります$2k$人々、人々がグループ化される場所$k$固定ペア。 配置後、各ペアは、ツリー内の固有のパスに沿って測定された、それらが占める 2 つの頂点間の距離に寄与します。 目標は、固定割り当ての距離を計算することではなく、割り当て自体を選択することです。 すべてのペアの距離の最小可能合計と最大可能合計の 2 つの極値が求められます。 

重要な問題は、既知のコスト行列を持つペアに頂点を任意に一致させていないことです。 代わりに、すべてのペアがツリー内の最短パス距離に寄与し、その構造はすべての選択肢を結合します。 割り当てによって、どの頂点ペアがツリー距離の点で「遠く離れているか」が変わります。 

この制約は、テスト ケースごとに線形または線形に近い解決策が必要であることを意味します。 すべてのテストにおける頂点の合計数は最大で次のとおりです。$3 \cdot 10^5$、つまり、どのようなアルゴリズムでも$O(n \log n)$または$O(n)$テストケースごとに許容されます。 二次関数の何か$2k$代入を列挙したり、すべてのペアの距離を計算したりすることは不可能です。 

微妙なエッジ ケースは、ツリーが単純なパスである場合です。 その場合、距離は配列内の絶対的な差のように動作し、極端な位置のペアによって合計がどのように変化するかを確認しやすくなります。 「貪欲な最近接ペアリングが常に最適である」と仮定する不注意なアプローチは、ここでは失敗します。ツリーでは、個々のペアの距離を局所的に最小化しても全体的な合計は最小化されないからです。 同様に、局所的に大きな距離を最大化するとブランチ間で干渉する可能性があるため、最も遠いノードを個別に単純に貪欲にマッチングすることも失敗します。 

もう 1 つのエッジケースは、星型のツリーです。 星では、ほとんどすべての距離が中心を通過するため、葉をペアにすることは、葉と中心をペアにすることとは大きく異なる動作をします。 これはまさに、ローカル ペアリング ヒューリスティックではなく、グローバルな順序付けのアイデアの必要性を明らかにする構造です。 

## アプローチ

 強引な解釈では、代入するすべての方法を検討することになります。$2k$人々に$2k$頂点を取得し、結果として得られるペアの距離の合計を計算します。 これはサイズの階乗です。$(2k)!$完全な割り当てではなく頂点のペアリングという観点だけを考えたとしても、エンドポイントを一致させる方法の数は$k$ペアは依然として指数関数的です。 各評価には合計が必要です$k$これらの距離を効率的に計算しても、組み合わせの爆発を防ぐことはできません。 これは非常に小さい値を超えるとすぐに失敗します$k$。 

重要な構造的観察は、各ペア内の個人の同一性は無関係であるということです。 エンドポイントのみが重要です。 そこで問題は、私たちが効果的に選択しているということです。$k$順序のない頂点ペア。各頂点は 1 回だけ使用され、各ペアのコストは端点間のツリー距離です。 これらの選択された距離の合計を最小化または最大化したいと考えています。 

これにより、問題はツリーによって引き起こされるメトリックに関するマッチング問題に変わります。 ツリー メトリクスの重要な特性は、距離がエッジにわたって分解されることです。各エッジは、そのエッジを「交差」する選択されたペアの数に応じて、合計距離の合計に独立して寄与します。 

どのエッジでも、それを削除すると、ツリーは 2 つのコンポーネントに分割されます。 ペアは、その端点が異なるコンポーネント内にある場合に限り、そのエッジの重みをその距離に寄与します。 したがって、すべてのペアの合計はエッジの合計として見ることができ、各エッジはその重みに交差するペアの数を乗じたものになります。 全体の最適化は、エッジによって引き起こされるすべてのカットにわたって、できるだけ多くまたは少ないペアがそれを横切るように頂点を分散する方法に関係します。 

ここで、問題はグローバルな計数問題になります。 各サブツリーに配置するペアのエンドポイントの数を理解する必要があります。これにより、各エッジと交差するペアの数が決まります。 両方の極端な場合の最適な構築は、サブツリーの寄与をリーフから上に向かって貪欲に決定し、各サブツリーで「ペアになっていないエンドポイント」が上に押し上げられる数を確実に制御することになります。 

標準ソリューションでは、サブツリーのサイズを計算し、各エッジを強制的に通過するエンドポイントの数を表す値を構築する DFS を使用します。 最大値を得るために、交差を最大化する必要があるため、サブツリーの寄与を可能な限り不均衡にしようとします。 最小限に抑えるために、少数のペアがエッジを横切ることを強制されるように、それらのバランスをとりたいと考えています。 

最後の単純化は、どちらの答えも、1 回の DFS トラバーサルで蓄積できるサブツリー DP 値のみに依存するということです。

 ## アルゴリズムのチュートリアル

 私たちは木を勝手に根付かせます。 サブツリーを最適に処理する場合に、親に渡す必要がある「オープン エンドポイント」の数を表す DFS 値をノードごとに計算します。 

1. 任意のノードでツリーをルートし、DFS 次数を計算します。 ルート化は距離を変更しませんが、サブツリーの寄与を計算する方向を与えます。 
2. 各ノードについて、そのサブツリー内の頂点の合計数を計算します。 これにより、そのサブツリー内で発生したエンドポイントの数がわかります。 
3. 各子サブツリーについて、サブツリー内で最適にペアリングした後、その中でペアになっていないエンドポイントの数を計算します。 この残りの量は、親へのエッジを越えなければならない量です。 
4. 合計を最小化するには、各エッジを横切るペアをできるだけ少なくする必要があります。 これは、何かを上向きに送信する前に、サブツリー内の頂点を可能な限りペアリングすることに対応します。 したがって、各ノードでエンドポイントをローカルで貪欲にペアリングし、残ったパリティのみを上向きに伝播します。 
5. 合計を最大化するには、交差を最大化する必要があります。これは、グローバル エッジの使用量が増加する場合、サブツリー内でのペアリングを可能な限り回避することを意味します。 これにより、可能な限りより多くのエンドポイントが上方に押し上げられ、各カットでの不均衡が効果的に最大化されます。 
6. 各エッジについて、各方向に通過するエンドポイントの数がわかったら、重みにエッジを通過する必要があるペアの数を乗じたものとしてその寄与を計算します。 これらをすべてのエッジにわたって累積すると、次のいずれかが得られます。$G$または$B$。 

重要な不変条件は、どのサブツリーでも、DFS は最適な戦略 (最小化または最大化) の下でサブツリーの外側に接続する必要があるペアになっていない頂点の正確な数を維持することです。 この値は、各接続エッジと交差するペアの数を完全に決定します。すべてのペアの距離は、そのパスに沿ったエッジの寄与の正確な合計であるため、正確さはエッジの分解によって決まります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    t = int(input())
    for _ in range(t):
        k = int(input())
        n = 2 * k

        g = [[] for _ in range(n + 1)]
        for _ in range(n - 1):
            a, b, w = map(int, input().split())
            g[a].append((b, w))
            g[b].append((a, w))

        # dp[u] = number of unmatched nodes in subtree u (for min construction)
        visited = [False] * (n + 1)

        def dfs(u):
            visited[u] = True
            rem = 1
            for v, w in g[u]:
                if not visited[v]:
                    child = dfs(v)

                    # each child contributes child unmatched nodes upward
                    # but we can pair as much as possible inside subtree
                    rem += child

            # at this node, we pair within subtree as much as possible
            # so leftover is parity only
            return rem % 2

        # compute subtree contributions for min
        visited = [False] * (n + 1)
        total_unmatched = dfs(1)

        # For min answer: each edge contributes weight if subtree size is odd on one side
        # We recompute more carefully: we need subtree sizes
        visited = [False] * (n + 1)
        subtree = [0] * (n + 1)

        def dfs2(u):
            visited[u] = True
            s = 1
            for v, w in g[u]:
                if not visited[v]:
                    s += dfs2(v)
            subtree[u] = s
            return s

        dfs2(1)

        def dfs_min(u):
            visited[u] = True
            res = 0
            for v, w in g[u]:
                if not visited[v]:
                    res += dfs_min(v)
                    # contribution: smaller side size determines crossings
                    sz = subtree[v]
                    res += w * min(sz, n - sz)
            return res

        visited = [False] * (n + 1)
        G = dfs_min(1)

        # For maximum: complement trick using same edge formula
        total_weight_sum = 0

        def dfs_max(u):
            visited[u] = True
            res = 0
            for v, w in g[u]:
                if not visited[v]:
                    nonlocal total_weight_sum
                    res += dfs_max(v)
                    sz = subtree[v]
                    total_weight_sum_list[0] += w
                    res += w * max(sz, n - sz)
            return res

        visited = [False] * (n + 1)
        total_weight_sum_list = [0]
        B = dfs_max(1)

        print(G, B)

if __name__ == "__main__":
    solve()
```この実装では、問題をサブツリー サイズの計算と、それらのサイズを使用してエッジの寄与を評価することに分割します。 すべてのエッジがツリーを 2 つの部分に分割し、最適な構築下でそのエッジを横切るペアの数を決定するために必要なのは片側のサイズのみであるため、サブツリー サイズの計算は不可欠です。 

最小の場合、各エッジは小さい方の辺のサイズに重みを掛けた値に寄与します。これは、強制しない限り、カットを越えてエンドポイントを送信することを避けることを反映しています。 最大の場合、各エッジは大きな辺のサイズに重みを掛けたものに寄与します。これは、カット全体で強制的に分離されるエンドポイントの数を最大化することに対応します。 

微妙な点は、どちらの式も同じルート分解に依存しており、各エッジはその誘導された分割を使用して 1 回だけ評価されるため、正確性はどのノードがルートとして選択されるかには依存しません。 

## 実用的な例

 ### 例 1

 4 つのノードが一列に並んだ小さなツリーを考えてみましょう。$1 - 2 - 3 - 4$、およびエッジの重み$1, 2, 3$。 この場合、サブツリーのサイズはルート 1 に依存します。 

| ノード | サブツリーのサイズ | エッジ寄与 (分) | 部分合計 |
 | --- | --- | --- | --- |
 | 1-2 | 3 対 1 | 1*1 | 1 |

 | 3-4 | 1 対 3 | 3*1 | 8 |

 この表は、分割の小さい側に基づいて各エッジがどのように寄与するかを示しています。 これは、パス内では、総交差距離を最小限に抑えるためにバランスのとれた分割のみが重要であることを裏付けています。 

### 例 2

 ここで、中心 1 と重み 1、2、3、4 を持つ葉 2、3、4、5 を持つ星を考えてみましょう。 

| エッジ | サブツリーのサイズ | 貢献度 (最大) | 部分合計 |
 | --- | --- | --- | --- |
 | 1-2 | 1 対 4 | 1*4 | 4 |
 | 1-3 | 1 対 4 | 2*4 | 12 |
 | 1-4 | 1 対 4 | 3*4 | 24 |
 | 1-5 | 1 対 4 | 4*4 | 40 |

 これは、最大化によって各エッジにわたって可能なすべてのエンドポイント分離がどのようにプッシュされ、高重みエッジでの大量の蓄積につながるかを示しています。

 ## 特殊なケース

 チェーン形状のツリーは、すべてのエッジに明確な分割があり、サブツリーのサイズが徐々に変化する長いパスをアルゴリズムが正しく処理するかどうかをテストします。 最小限の解決策では、バランスのとれた半分でローカルにペアリングすることにより、クロスの過剰カウントを回避する必要があります。 

星型ツリーは、すべてのエッジが 1 つの葉を分離し、最適化の方向に応じて最大または最小の寄与を強制することをアルゴリズムが正しく識別しているかどうかをテストします。 寄与は、ローカル サブツリーだけでなく、反対側のサイズに合わせてスケールする必要があります。 

均一重みツリーにより、ソリューションが重み順序に依存せず、エッジ順序ではなくサブツリー サイズからの純粋に構造的な寄与が正しく集約されます。
