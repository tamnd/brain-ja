 ## 解決策
 ## 問題の理解

 私たちはテーブルの行を表すバイナリ文字列を操作しています。各位置は反転されるか反転されません。 文字列は直接ポイント更新によってのみ変更されます。タイプ 1 のクエリは、単一の位置を 0 から 1、または 1 から 0 に切り替えます。 

これらの更新とは別に、文字列を変更しないランダムなプロセスも考慮します。 1 つの「実験」では、次の操作を繰り返し実行します。すべての部分配列の中から一様にランダムにセグメントを選択し、そのセグメント内のすべてのビットを反転します。 この操作を k 回繰り返し、そのたびにセグメントを再度個別に選択します。 タイプ 2 のクエリの場合、このランダム プロセスが現在の文字列に k 回適用された後、予想される 1 の数が求められます。 

重要な微妙な点は、ランダムなプロセスが常に概念的なものであるということです。 今後のクエリには影響しません。 タイプ 2 の各クエリは、現在の文字列スナップショットから開始して期待値を評価します。 

制約は文字列サイズが最大 100,000 と大きく、クエリ数も最大 100,000 ですが、k は小さく、最大でも 200 です。これは、どのソリューションでも文字列の展開やランダムな反転プロセスの明示的なシミュレーションを回避する必要があることを直ちに示唆しています。 セグメント フリップは O(n) であり、k が十分に大きいため、1 つの実験を 1 回シミュレーションするだけでも不可能です。シミュレーションを繰り返すと非常に遅くなります。 

出力精度の要件は、モンテカルロ シミュレーションではなく、浮動小数点演算または注意深く導出された有理式を使用して正確な期待値を計算する必要があることを意味します。 

素朴だが魅力的なアイデアは、位置ごとの確率を個別にシミュレートすることですが、セグメントの反転により位置間で強い相関が生じるため、これは失敗します。 たとえば、セグメント [l, r] を反転すると、i と j が内側にある場合、両方が同時に反転されるため、それらの状態は独立していません。 

2 番目の微妙な落とし穴は、繰り返しの構成を考慮せずに、ステップ間の直線性を仮定することです。 一度の手術の後、期待は簡単です。 k 回の操作の後、線形変換の繰り返し適用によって状態が進化し、クエリごとのステップごとの単純な再計算では O(nkQ) が発生しますが、これは遅すぎます。 

## アプローチ

 まず、単一のランダム操作で何が起こるかを考えます。 位置を固定します。 ランダムに選択されたセグメントが i をカバーする場合に限り、反転されます。 i を含むセグメントの数は i × (n − i + 1) であり、セグメントの総数は n(n + 1)/2 です。 したがって、位置 i が 1 回の操作で反転される確率は単純な有理値です。 

p[i] がこの確率を表すものとします。 ビットが 0 または 1 の場合、1 回のランダム操作の後、その期待値は次のように変化します。 フリップによってビットが切り替わるので、X が現在の値の場合、1 回の操作の後、確率 1 − p[i] で X になり、確率 p[i] で 1 − X になります。 期待値を取得すると、各ポジションの期待値が独立して線形再帰的に計算されます。 

これはすでに重要な構造を明らかにしています。線形フリップの期待値は、隣接するものではなく、その時点の期待値のみに依存するため、各位置は期待値内で独立して進化します。 期待を取ると相関関係はなくなります。 

したがって、E[i] が t 回の操作後の位置 i の期待値である場合、E[i] ← (1 − p[i])E[i] + p[i](1 − E[i]) という形式の反復が得られます。 これは E[i] ← E[i](1 − 2p[i]) + p[i] に単純化されます。 

これは、繰り返し適用される線形アフィン変換です。 各 i について、これは 1 次元の線形力学システムです。 k ステップの後、同じ変換を k 回適用します。 これは等比級数として明示的に解くことができます。 

a[i] = 1 − 2p[i] および b[i] = p[i] とします。 k ステップ後の E[i] は次のようになります。 

E[i] = a[i]^k *Initial[i] + b[i] * (1 − a[i]^k) / (1 − a[i]) a[i] ≠ 1 の場合。 

これにより、問題は数値の k 乗の計算と i の合計に集約されます。

ただし、最大 100,000 個のクエリに対する回答が必要です。各クエリには異なる k が含まれる可能性があり、initial[i] を変更する更新が必要です。 したがって、クエリごとの再計算能力は遅すぎます。 

重要な観察は、k ≤ 200 であるということです。これにより、200 までのすべての i とすべての t の累乗 a[i]^t を事前計算できます。各更新では 1 つの位置のみが変更されるため、その寄与を効率的に維持できます。 最終的な答えはすべてのポジションの合計であるため、期待値の全体的な合計を維持します。 

したがって、各クエリ タイプ 2 は O(1) になり、更新により O(k) の事前計算された寄与が調整されます。

 ## アルゴリズムのチュートリアル

 1. n を計算し、セグメントの総数、n(n + 1)/2 を事前計算します。 これは、各ポジションのフリップ確率を決定するために必要です。 
2. 各位置 i について、p[i] = i(n − i + 1) / total_segments を計算します。 これは、単一のランダム セグメント操作で i が反転される確率です。 
3. 各位置を線形変換 E ← a[i]E + b[i] に変換します。ここで、a[i] = 1 − 2p[i] および b[i] = p[i]。 これにより、ランダムな反転が繰り返されることによる期待への影響が分離されます。 
4. 0 から 200 までのすべての t の a[i]^t のべき乗を事前計算します。これにより、クエリごとにべき乗を再計算することなく、繰り返される変換を高速に評価できます。 
5. クエリごとに、初期文字列から初期化された現在の期待寄与配列を維持します。 期待される答えの合計は、すべての E[i] の合計です。 
6. タイプ 1 クエリの場合、S[i] を反転します。 位置 i の期待値は 1 − 現在の値になるため、古い寄与分を減算し、新しい寄与分を加算して累計を更新します。 これにより、O(1) におけるグローバル合計の一貫性が保たれます。 
7. パラメーター k を使用したタイプ 2 クエリの場合、指数 k を使用して事前に計算された式を使用して、各位置の最終的な予想寄与を計算し、それらを合計します。 

中心となるアイデアは、すべての位置が同じ線形演算子の下で独立して進化するため、システム全体が独立した 1D プロセスの合計であるということです。 

それが機能する理由は、期待の線形性と、操作ごとのセグメント選択の独立性から来ています。 各位置の期待値は、ランダム セグメントがその位置をカバーするかどうかのみに依存し、このイベントは位置固有です。 反転は 1 回の操作でポジション間で相関付けられますが、合計の期待値は期待値の合計に等しいため、期待値はきれいに分解され、各期待値はステップごとに 1 つのベルヌーイ イベントにのみ依存します。 繰り返し適用すると線形漸化が構成されるため、閉じた形式のべき乗が有効になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = list(input().strip())
    n = len(s)

    total = n * (n + 1) / 2

    p = [0.0] * n
    a = [0.0] * n
    b = [0.0] * n

    for i in range(n):
        l = i + 1
        r = n - i
        p[i] = (l * r) / total
        a[i] = 1.0 - 2.0 * p[i]
        b[i] = p[i]

    E = [1.0 if c == '1' else 0.0 for c in s]

    kmax = 200
    pow_a = [[1.0] * (kmax + 1) for _ in range(n)]
    for i in range(n):
        for k in range(1, kmax + 1):
            pow_a[i][k] = pow_a[i][k - 1] * a[i]

    # precompute geometric sums
    geom = [[0.0] * (kmax + 1) for _ in range(n)]
    for i in range(n):
        for k in range(1, kmax + 1):
            geom[i][k] = geom[i][k - 1] * a[i] + 1.0

    Q = int(input())
    for _ in range(Q):
        t = input().split()
        if t[0] == '1':
            i = int(t[1]) - 1
            E[i] = 1.0 - E[i]
        else:
            k = int(t[1])
            ans = 0.0
            for i in range(n):
                ak = pow_a[i][k]
                if abs(1.0 - a[i]) < 1e-12:
                    ans += E[i]
                else:
                    ans += ak * E[i] + b[i] * (1.0 - ak) / (1.0 - a[i])
            print(f"{ans:.6f}")

if __name__ == "__main__":
    solve()
```この実装では、位置ごとのパラメーター p、a、b が事前計算されます。 このモデルではバイナリ状態の期待値が 1 である確率と一致するため、配列 E には各位置の現在の決定値が格納されます。 

べき乗テーブル pow_a[i][k] を使用すると、再計算せずに a[i]^k の迅速な累乗が可能になります。 クエリ タイプ 2 では、閉じた形式の式を直接適用します。 a[i] が 1 に近い場合の特別な場合のチェックにより、除算の不安定性が回避されますが、実際には a[i] が 1 に等しいのは縮退境界の場合のみです。 

微妙な点は、ランダム プロセスの中間ステップをシミュレートしていないことです。 クエリは、k ステップ変換を現在の状態に直接適用します。 

## 実用的な例

 小さな文字列 S = "10" を考えてみましょう。 n = 2 となります。セグメントの確率は位置ごとに異なります。位置 1 はセグメント [1,1]、[1,2]、[2,2] に含まれるため、p[1] = 2/3 となります。 位置 2 も p[2] = 2/3 と対称です。 

更新がなく、k = 1 のクエリ シーケンスは次のようになります。 

| 私 | 初期E[i] | p[i] | a[i] | 1 ステップ後の E |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 2/3 | -1/3 | 1/3 |
 | 2 | 0 | 2/3 | -1/3 | 2/3 |

 合計は 1 です。 

次に、同じ状態から開始する k = 2 について考えます。 各位置は、同じ線形マップを繰り返し適用することによって進化します。 位置 1 は 1 から始まり、固定点 p[i] = 2/3 に向かって移動するため、その値は 1 から 2/3 に向かって減少します。 位置 2 は 0 から 2/3 に向かって増加します。 合計は4/3に近くなります。 

| 私 | E[0] | E[1] | E[2] |
 | --- | --- | --- | --- |
 | 1 | 1 | 1/3 | 5/9 |
 | 2 | 0 | 2/3 | 4/9 |

 合計は 1 です。 

このトレースは定常値 p[i] に向かう収縮挙動を示しており、繰り返し適用が位置ごとに独立して収束していることが確認されます。

 ## 特殊なケース

 n = 1 の場合、特殊なケースが発生します。唯一のセグメントは [1,1] であるため、すべての操作で単一ビットが決定的に反転されます。 確率 p[1] は 1 に等しいため、a[i] は -1 になります。 反復は 0 と 1 の間で正確に切り替わり、k ステップの期待値は k のパリティに依存します。 a[i]^k が正しく (-1)^k になり、閉じた形式が交互の値になるため、アルゴリズムはこれを処理します。 

もう 1 つのエッジ ケースは、クエリされていないにもかかわらず、推論で暗黙的に解釈された場合に k = 0 の場合に発生します。 正しい動作は、変換せずに現在の 1 の数を返すことです。 a[i]^0 = 1 であるため、式は恒等式に縮退します。 

最後の微妙なケースは、同じ位置に繰り返し影響を与える更新が長時間実行されることです。 各更新が E[i] を反転するため、クエリを適用する前に、繰り返されたトグルが保存された状態に正確に反映される必要があります。そうしないと、期待がずれてしまいます。
