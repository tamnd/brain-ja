 ## 解決策
 ## 問題の理解

 文字列内に非常に小さな一連の個別の文字が与えられます。$T$、さらに大きな文字列$S$とまったく同じ複数の文字セットが含まれる$T$、繰り返しの量だけ。 両方の文字列を自由に並べ替えることができます。 

重要な概念は、ペアがいつ$(A, B)$互換性があると考えられます。 弦$B$スケルトンのように機能します: の各文字$B$繰り返されるコピーのブロックに拡張することはできますが、異なる文字の順序は$B$保存しなければなりません。 言い換えれば、もし$B = abc$、次に次のような文字列$aaabcc$または$aabbcccc$許容されますが、次のようなものです$acb$の有効な展開に再配置することはできません$abc$ブロックの相対的な順序が違反されるためです。 

2 つの順列が与えられた場合$S_0$そして$T_0$、変換に必要な隣接スワップの最小数としてコストを測定します。$S_0$の何らかの有効な展開に$T_0$。 隣接するスワップは反転距離を測定するため、このコストは基本的に、現在の配置と可能な限り最良のブロック構造の配置の間の反転回数になります。 

タスクは敵対的です: 両方の順列を選択します$S_0$そして$T_0$このコストを最大化するために。 

制約は非常に重要です。 大きな文字列には最大で次の文字列を含めることができます。$3 \cdot 10^5$文字だけでなく、アルファベットも含まれます。$T$サイズは最大 5 です。これは、文字の順列に依存するあらゆる解が実行可能であることをすぐに示唆しますが、二次関数は何でも可能です。$|S|$ペアワイズ シミュレーションではなく、リニア スキャンの場合にのみ許容されます。 

よくある失敗例は、文字グループの相対的な順序のみが重要であることを無視したことに起因します。 たとえば、集計された数ではなく個々の文字を扱う場合、完全な文字列のスワップをシミュレートしようとする可能性がありますが、これは不必要であり、遅すぎます。$3 \cdot 10^5$。 

もう 1 つの微妙な問題は、修正したら次のように仮定することです。$T_0$の構造$S_0$は任意です。 実際に最適な配置は、$S_0$決まった順序で$T_0$は完全に決定されます。文字の出現はすべてグループ化される必要があります。そうしないと、潜在的な反転寄与が失われます。 

最後のエッジケースは次のような場合です$|T| = 1$。 どのような置換でもコストはゼロになりますが、少なくとも 2 文字を想定した不注意な実装では、無効なペア ロジックが試行される可能性があります。 

## アプローチ

 ブルートフォースの観点では、次のすべての順列を選択することから始まります。$T_0$。 そのような順序ごとに、次のすべての順列を試します。$S_0$、変換する最小スワップを計算します。$S_0$有効な展開に変換し、最大の結果を取得します。 これはすぐに爆発します。$S_0$もっている$3 \cdot 10^5$位置が異なるため、順列を表すことすら不可能であり、反転距離を繰り返し計算するとコストがかかります$O(n \log n)$試行ごとに、膨大な検索スペースが掛け合わされます。 

重要な観察は、実際には次の順列を考慮する必要がないということです。$S_0$全然。 文字の順番が決まったら、$T_0$が固定されている場合、反転距離を最大化する最善の方法は、最後の文字をすべて最初に配置し、次に前の文字を配置するという具合に配置することです。 これにより、異なる文字のすべてのペアが可能な限り反転される構成が作成され、スワップが最大化されます。 

これにより、問題全体が、最大 5 文字の順序に関する小さな組み合わせの最適化に集約されます。 固定順序の場合、コストは頻度のみを使用して計算できます。文字の各ペアは、相対的な順序に応じて文字数の積に寄与します。 

したがって、タスクは、重み付き反転合計を最大化する文字の順列を選択することになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | 文字列に対するブルートフォース | 実現不可能 | 実現不可能 | 遅すぎる |

 ここ$k \le 5$なので、列挙するのは簡単です。 

## アルゴリズムのチュートリアル

 1. 各キャラクターの出現頻度を数えます。$S$。 に存在する文字のみ$T$そしてそれらの数は問題を完全に説明します。 
2. から個別の文字のセットを抽出します。$T$。 これにより、並べ替える必要があるシンボルが最大 5 つになります。 
3. これらの文字のすべての順列を列挙します。 各順列は次の候補を表します。$T_0$。 
4. 各順列について、すべての順序付きペアの寄与を計算します。 キャラクターなら$a$前に現れます$b$順列では、次のすべての出現が$a$後に配置$b$で$S_0$逆転に貢献します。 後ほど手配させていただきますので、$S_0$最適には、寄与はそれらの周波数の積になります。 
5. ペアごとの寄与の合計が最大になる順列を選択します。 
6. 構築する$T_0$この最適な順列として。 
7. 構築する$S_0$文字を逆の順序で配置することで、$T_0$、それぞれがその頻度に従って繰り返されます。$S$。 

これが機能する理由は、2 つのブロック間の反転コストがそれらの相対的な順序とカウントのみに依存するという事実から来ています。 ブロックの順序を修正したら、$S_0$、異なる文字の各ペアは完全に貢献するか、まったく貢献しません。グループ化により、ブロック内で貢献が無駄にならないことが保証されます。 したがって、全体の最適化は、最大 5 つのノード上で重み付けされた完全なグラフを順序付けすることになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from itertools import permutations

def solve():
    T = input().strip()
    S = input().strip()

    freq = {}
    for ch in S:
        freq[ch] = freq.get(ch, 0) + 1

    chars = list(dict.fromkeys(T))  # preserve order but unique

    best_cost = -1
    best_order = None

    for p in permutations(chars):
        pos = {c: i for i, c in enumerate(p)}
        cost = 0
        for i in range(len(p)):
            for j in range(i + 1, len(p)):
                cost += freq[p[i]] * freq[p[j]]
        if cost > best_cost:
            best_cost = cost
            best_order = p

    T0 = ''.join(best_order)

    S0_list = []
    for ch in reversed(best_order):
        S0_list.append(ch * freq[ch])
    S0 = ''.join(S0_list)

    print(best_cost)
    print(S0)
    print(T0)

if __name__ == "__main__":
    solve()
```頻度テーブルは、大きな文字列を一定サイズの署名に圧縮するため、不可欠です。 アルファベットのサイズは 5 で区切られているため、置換ループは安全です。 

の建設$S_0$逆順にすることで、最大の反転寄与が保証されます。 文字をグループ化する代わりにインターリーブすると、文字列内の交換は追加の反転ゲインに変換されません。 

## 実用的な例

 次の場合を考えてみましょう$T = "abc"$そして$S$各文字のコピーが複数含まれています (a が 2 つ、b が 1 つ、c が 3 つなど)。 

次のような順列を試してみます$abc$コストを次のように割り当てます$2 \cdot 1 + 2 \cdot 3 + 1 \cdot 3$、注文に応じて。 代わりに使用する場合$cba$の構造$S_0$になる$c c c b a a$、すべての高頻度文字が他のすべての前に配置され、反転の累積が最大化されます。 

| ステップ | 順列 | ペアの貢献 | 合計 |
 | --- | --- | --- | --- |
 | 1 | ABC | a-b、a-c、b-c | 計算された合計 |
 | 2 | CBA | c-b、c-a、b-a | 大きい方の合計 |

 これは、高周波構造を反転すると、最適なグループ化と組み合わせると反転の可能性が高まる傾向があることを示しています。 

単一の文字を使用する別のケース:$T = "x"$、順列は 1 つだけ生成されます。 反転するペアがなく、出力文字列は任意の繰り返しであるため、コストは常にゼロです。$x$。

 ## 特殊なケース

 いつ$T$文字が 1 つだけ含まれている場合、置換ループは 1 つの候補に縮退します。 構築された$S_0$は単一のブロックになり、カウントする文字間の反転は存在しないため、コストはゼロのままです。 

周波数が大きく偏っている場合、たとえば 1 つの文字が優勢である場合$S$、最適な順序付けでは、その文字は順列の一方の極端に配置されます。 ペアワイズ積では頻度の高い文字を片側に配置することが非常に好まれるため、アルゴリズムはこれを自然に処理します。 

すべての文字の頻度が等しい場合、複数の順列が結合する可能性があります。 この場合、すべての順列が同一の合計を生成するため、アルゴリズムは引き続き有効な最大値を返します。$S_0$選択した順序を逆にすることで一貫性が保たれます。
