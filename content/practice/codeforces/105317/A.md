 ## 解決策
 ## 問題の理解

 2 つの整数が与えられます。 1 つはサンドイッチ 1 個のコストを表し、もう 1 つはフアンが利用できるお金を表します。 フアンは、満腹のサンドイッチだけにお金を使い、それを友人に渡したいと考えています。各友人にはサンドイッチが 1 つずつ与えられます。 

課題は、サンドイッチを何個食べられるかを判断することです。これは、彼が何人の友人をもてなすことができるかに相当します。 各サンドイッチの価格は固定されているため、問題は、利用可能な合計金額をサンドイッチ 1 個あたりの価格で割って、完全な購入のみをカウントすることに帰着します。 

制約は次のとおりです$10^9$両方の値の場合、一度にサンドイッチを 1 つずつ消費するシミュレーションは即座に除外されます。 コストを繰り返し減算するループには、最大で$10^9$最悪の場合の反復回数は、Python で 1 秒に収まる回数をはるかに超えています。 唯一の実行可能なアプローチは、定数時間の算術計算です。 

配列やグラフのような扱いにくい構造的なエッジケースはありませんが、整数の除算のセマンティクスに関しては正確性に関する微妙な懸念が依然としてあります。 結果は完全なサンドイッチの数でなければなりません。つまり、端数の手頃な価格は破棄されなければなりません。 たとえば、コストが 5 でお金が 4 の場合、四捨五入の間違いにより、正解は 0.8 や 1 ではなく 0 になります。 浮動小数点除算を使用する実装では、大規模な入力に対して精度の問題が発生するリスクがあります。$10^9$。 

## アプローチ

 素朴なアプローチは物語を直接反映しています。 私たちは、フアンがもう 1 つサンドイッチを買う余裕がなくなるまで、サンドイッチ 1 つ分の値段を繰り返しフアンのお金から差し引きます。 それぞれの減算は、サンドイッチを 1 つ購入し、提供される友人の数を増やすことに対応します。 これは正しいです。各ステップにより、残りのバジェットが有効な個別単位で減少するからです。 

ただし、この方法はコストが小さく予算が大きい場合には非常に遅くなります。 コストが1でお金が$10^9$、私たちはパフォーマンスします$10^9$繰り返し、それぞれが一定の作業を実行します。 これはすでに一般的な時間制限を桁違いに超えています。 

重要な観察は、この繰り返される減算がまさに整数の除算であるということです。 それぞれの購入をシミュレーションする代わりに、コストが予算内に何倍収まるかを直接計算できます。 これにより、プロセス全体が 1 つの算術演算に削減されます。 

問題の構造により、購入間の独立性が保証されており、割引や累積効果はなく、購入を相互にリンクする制約もありません。 それが商になります$m \div c$最終的な答えを説明するには十分です。

 ## アルゴリズムのチュートリアル

 1. 2 つの整数を読み取ります$c$そして$m$入力から。 これらは、サンドイッチあたりのコストと利用可能な合計金額を表します。 
2. 整数除算を使用して、予算内に収まるサンドイッチ全体の数を計算します。$m // c$。 この操作により、サンドイッチを完全に買うことができない使用できない残りのお金に相当する残りが自動的に破棄されます。 
3. 計算された値を、Juan が扱うことができる友達の数として出力します。 

### なぜ効果があるのか

 各サンドイッチは正確に消費します$c$お金の単位が異なるため、異なるサンドイッチからの部分的なお金を組み合わせる方法はありません。 有効な購入シーケンスでは、まとまったサイズのお金を消費する必要があります。$c$。 したがって、次の値に収まる有効なチャンクの最大数は、$m$はまさに次の商です$m$で割る$c$。 総予算を超えることを意味するため、これを超える取り決めはできません。また、残りのお金が以下になるまでいつでも貪欲にサンドイッチを買うことができるため、これより小さい取り決めはできません。$c$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

c, m = map(int, input().split())
print(m // c)
```この解決策は、整数の除算を直接適用します。 の使用`//`これは完全なサンドイッチのみをカウントして正確にモデル化するフロア分割を保証するため、非常に重要です。 

ループや追加のメモリは必要ありません。 計算全体は、入力を解析した後の単一の定数時間操作です。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    c, m = map(int, input().split())
    return str(m // c)

# provided samples
assert run("3 10") == "3"

# custom cases

 ## 特殊なケース

 エッジケースの 1 つは、予算がコストよりも小さい場合です。 入力用`c = 10, m = 3`、アルゴリズムは次のように計算します。`3 // 10 = 0`。 これは正しいです。サンドイッチ全体を購入することはできず、整数除算では特別な処理を行わなくても自然にこれが適用されます。 

もう 1 つのエッジケースは、予算がコストで正確に割り切れる場合です。`c = 4, m = 12`。 計算の結果は、`12 // 4 = 3`、残りはありません。 このアルゴリズムは、過剰にカウントすることなく、利用可能なすべての購入を正確にカウントします。 

最後のケースは、両方の値が最大サイズである場合です。たとえば、`c = 10^9, m = 10^9`。 結果は`1`Python の整数演算は大きな整数をネイティブに処理し、競技プログラミングのコンテキストではこのスケールでは除算が定数時間であるため、計算は安全に保たれます。
