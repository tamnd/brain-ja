 ## 解決策
 ## 問題の理解

 すべてのノードに値が書き込まれたツリーが与えられます。 各クエリは 2 つのノードを選択し、それらの間の一意の単純なパスを定義します。 そのパスに沿って、一連のノード値を調べ、各値が何回出現するかを数えます。 値 x が f(x) 回出現する場合、その周波数を 2 乗します。 クエリは、パス上に表示されるすべての値に対するこれらの二乗周波数の合計を求めます。 

したがって、各クエリはグローバル ツリー統計ではなく、パス統計を要求します。 この難しさは、エンドポイントとクエリ内の値の範囲の両方が動的であり、最大 100,000 個のクエリが存在するという事実に起因します。 

この制約は、ノードを通過してパスを再計算するソリューションは直ちに実行不可能であることを意味します。 1 つのパスの長さは O(n) になる可能性があり、クエリが 100,000 件あると、最悪の場合、10^10 の操作が必要になります。 クエリあたり O(n log n) でも遅すぎます。 ソリューションでは、前処理後に各クエリを O(1) または O(log n) に近い値に減らすか、クエリ間で作業を大幅に償却する必要があります。 

2 乗周波数構造の誤解から素朴な落とし穴が生じます。 たとえば、パスの値が [5, 5, 5] の場合、答えは 3^2 = 9 であり、3 ではありません。パスの値が [2, 2, 3, 3] の場合、答えは 2^2 + 2^2 = 8 です。もう 1 つの微妙な問題は、パスが必ずしもサブツリーまたは連続セグメントであるとは限らないため、ツリーに対する標準的な頻度プレフィックスのトリックは変換なしでは直接適用できないことを忘れていることです。 

## アプローチ

 直接的なアプローチは、各クエリを個別に処理することです。 クエリ (u, v) の場合、最も低い共通祖先構造を使用してパス上のすべてのノードを見つけ、それらの値を収集し、ハッシュ マップ内の頻度をカウントできます。 これは文字通りクエリの定義と一致するため、正しいです。 ただし、パスの長さは O(n) になる可能性があり、q が 10^5 までの場合、最悪のケースは O(nq) となり、制限をはるかに超えます。 

重要な観察は、式 ∑ f(x)^2 が、最終的な頻度ではなく個々の発生の寄与を分離する方法で書き換えられるということです。 正方形を拡張すると、組み合わせ解釈が得られます。f(x)^2 は、同じ値 x の出現の順序付きペアをカウントします。 したがって、答えは、同じ値を共有するパス上のノードのペアの数です。ペアは同じ値グループ内で順序付けされます。 

これにより、問題は「周波数を数えて二乗する」という問題から、「パス上の等しい値のペアをすべて数える」へと変わります。 これで、各ノードは、パスの移動中に以前に発生した同じ値との相互作用に寄与します。 これは、特に木の経路を線形化するオイラー ツアー表現と組み合わせた場合、まさに Mo の木に関するアルゴリズムが設計された構造のタイプです。 

ツリーをオイラー ツアー配列に変換し、LCA ロジックを使用して、各パス クエリをこの配列上で最大 2 つの間隔に削減します。 次に、これらの間隔にわたって Mo のアルゴリズムを適用します。 エンドポイントを移動している間、現在含まれている値の頻度カウントを維持し、ノードの追加または削除時に慎重に更新することで、実行中の答え ∑ f(x)^2 を維持します。 

値の頻度が c から c+1 に変化すると、その寄与は c^2 から (c+1)^2 に変化するため、デルタは 2c+1 になります。 c から c-1 に変化すると、デルタは -(2c-1) になります。 これにより、ノードの追加/削除ごとに O(1) の更新が可能になり、全体的な Mo プロセスが効率的になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースパスカウント | O(nq) | O(n) | 遅すぎる |
 | Mo on ツリー + LCA + 周波数維持 | O((n + q) √n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

まず、ツリーをルート化し、オイラー ツアーを計算します。 各ノードには開始時間と終了時間が割り当てられ、LCA クエリに効率的に答えるためにバイナリ リフティング テーブルも計算されます。 オイラー ツアーでは、サブツリー関係が区間関係になる線形構造が得られますが、パスには依然として 2 つの区間表現が必要です。 

各クエリ (u、v) はオイラー配列上のセグメントに変換されます。 u が v の祖先である場合、パスは単一の間隔に対応します。 それ以外の場合、パスは 2 つの間隔に LCA ノードを加えたものに相当し、個別に処理する必要があります。 

次に、これらの間隔で Mo の順序付けを使用してクエリを並べ替えます。 目標は、連続するクエリ間のポインタの移動を最小限に抑え、償却効率を確保することです。 

オイラー配列に対する現在のウィンドウとノード値の周波数配列 freq[x] を維持します。 また、オイラー ツアーにはノードが 2 回含まれており、純粋な加算ではなく切り替えが必要であるため、ブール値の訪問済み配列も維持します。 

ウィンドウの境界が移動するたびに、ノードを現在のセットの内外に切り替えます。 値 v を持つノードが追加されると、freq[v] を増加させ、2・freq[v]−1 を加算して答えを更新します。 削除されると、freq[v] が減少し、逆遷移に基づいて 2・freq[v]+1 が減算されます。 

クエリにオイラー区間でカバーされない余分な LCA ノードがある場合は、それを一時的に含めて答えを計算し、その後再び削除します。 

すべてのクエリを処理した後、保存された結果を元の順序で出力します。 

### なぜ効果があるのか

 正しさは、答えが現在のアクティブ セット内の値の頻度カウントのみに依存し、パス上のノード値のマルチセットを維持しているかのように、すべての操作でそれらのカウントが正確に更新されるという事実から得られます。 Euler + Mo フレームワークは、すべてのクエリがそのパス上のノードの正しいマルチセットに対して正確に評価されることを保証し、増分更新式は挿入または削除のたびに ∑ f(x)^2 の正確な値を保持します。 近似は導入されず、明確に定義された状態の正確な代数更新のみが導入されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    n, q = map(int, input().split())
    a = [0] + list(map(int, input().split()))

    g = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)

    LOG = 17
    up = [[0] * (n + 1) for _ in range(LOG)]
    depth = [0] * (n + 1)

    tin = [0] * (n + 1)
    tout = [0] * (n + 1)
    euler = []
    timer = 0

    def dfs(v, p):
        nonlocal timer
        tin[v] = timer
        euler.append(v)
        timer += 1
        up[0][v] = p
        for to in g[v]:
            if to == p:
                continue
            depth[to] = depth[v] + 1
            dfs(to, v)
        tout[v] = timer
        euler.append(v)
        timer += 1

    dfs(1, 1)

    for i in range(1, LOG):
        for v in range(1, n + 1):
            up[i][v] = up[i - 1][up[i - 1][v]]

    def is_ancestor(u, v):
        return tin[u] <= tin[v] and tout[v] <= tout[u]

    def lca(u, v):
        if is_ancestor(u, v):
            return u
        if is_ancestor(v, u):
            return v
        for i in reversed(range(LOG)):
            if not is_ancestor(up[i][u], v):
                u = up[i][u]
        return up[0][u]

    queries = []
    for i in range(q):
        u, v, l, r = map(int, input().split())
        queries.append((u, v, l, r, i))

    block = int(len(euler) ** 0.5) + 1

    def mo_key(x):
        l, r, _, _, _ = x
        return (l // block, r)

    def get_path(u, v):
        w = lca(u, v)
        if w == u:
            return (tin[u], tin[v], -1)
        if w == v:
            return (tin[v], tin[u], -1)
        return (tout[u], tin[v], w)

    def add(idx, vis, freq, cur):
        v = euler[idx]
        val = a[v]
        if vis[v]:
            freq[val] -= 1
            cur[0] -= 2 * freq[val] + 1
        else:
            freq[val] += 1
            cur[0] += 2 * freq[val] - 1
        vis[v] ^= 1

    queries.sort(key=mo_key)

    freq = [0] * 100001
    vis = [0] * (n + 1)
    cur = [0]

    ans = [0] * q

    L = 0
    R = -1

    for u, v, l, r, idx in queries:
        left, right, extra = get_path(u, v)

        def toggle(i):
            add(i, vis, freq, cur)

        while L > left:
            L -= 1
            toggle(L)
        while R < right:
            R += 1
            toggle(R)
        while L < left:
            toggle(L)
            L += 1
        while R > right:
            toggle(R)
            R -= 1

        if extra != -1:
            toggle(tin[extra])

        ans[idx] = cur[0]

        if extra != -1:
            toggle(tin[extra])

    print("\n".join(map(str, ans)))

if __name__ == "__main__":
    solve()
```このソリューションは、LCA 計算用のバイナリ リフティング構造を構築し、各ノードが 2 回出現するオイラー ツアーを実行します。これにより、パス クエリを間隔と LCA の補正の可能性として表現できるようになります。 

add 関数は重要なコンポーネントです。 現在の構造をノード値のマルチセットとして扱い、周波数の 2 乗の合計を維持します。 ノードがトグルインされると、その寄与は 2・c+1 だけ増加し、トグルアウトされると、対称的に減少します。 vis 配列は、重複したオイラーの外観を正しく処理できるようにします。 

Mo 順序付けにより、クエリ間のポインタの移動が最小限に抑えられ、全体的な複雑さが管理可能になります。 

実装の微妙な詳細は、LCA ノードがオイラー区間に含まれていない場合に、LCA ノードを個別に処理することです。 これにより、二重カウントや漏れが回避されます。 

## 実用的な例

 値 [1, 1, 2] と 1 から 3 までのクエリを持つノード 1-2-3 の単純なチェーンを考えてみましょう。 

オイラー ベースのウィンドウは、ノード 1、2、3 に対応するインデックスにわたって徐々に拡大します。ノードが追加されると、周波数が進化します。 

| ステップ | ウィンドウノード | 周波数 | 貢献 |
 | --- | --- | --- | --- |
 | 1を追加 | [1] | {1:1} | 1 |
 | 2を追加 | [1,1] (動作ハンドル構造の切り替え) | {1:2} | 4 |
 | 3を追加 | [1,1,2,2] 圧縮パス効果 | {1:2,2:1} | 4 + 1 = 5 |

 これにより、二乗周波数の累積が確認されます。 

2 番目の例では、中心 1 が 2 と 3 に接続されたスター ツリー、値 [5, 5, 5]、クエリ 2 から 3 です。 

パスは [2,1,3]、すべての値が 5 であるため、頻度は 3、答えは 9 です。 

| ステップ | アクティブなノード | 周波数[5] | 結果 |
 | --- | --- | --- | --- |
 | 2を追加 | {2} | 1 | 1 |
 | 1を追加 | {2,1} | 2 | 4 |
 | 3を追加 | {2,1,3} | 3 | 9 |

 これは、非線形パス上の周波数集約が正確であることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n + q) √n) | Mo のアルゴリズムは、クエリごとに平均約 √n 回の調整を処理します。

 ## 特殊なケース

 重要なエッジ ケースは、両方のエンドポイントが同じノードである場合です。 パスは単一の要素に縮退するため、値に関係なく答えは 1 でなければなりません。 アルゴリズムでは、これはおそらく LCA 補正を伴う Mo のウィンドウ内で長さ 0 の移動となり、トグル ロジックは引き続き 1 回の発生を正しくカウントします。 

もう 1 つのエッジ ケースは、LCA がエンドポイントの 1 つである場合です。 この場合、パスは追加のノードを必要とせずに単一のオイラー区間に対応します。 実装では、get_path でこれを明示的にチェックし、二重包含を回避します。 

最後の微妙なケースは、オイラー ツアーに繰り返しノードが含まれていることです。 各ノードは 2 回出現するため、単純な加算では頻度が 2 倍にカウントされます。 vis トグル メカニズムにより、各ノードがアクティブなマルチセット内に事実上 1 回だけ存在することが保証され、周波​​数計算の正確さが維持されます。
