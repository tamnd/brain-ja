 ## 解決策
 ## 問題の理解

 すべてのセルに小文字が含まれる、最大でも 10 × 10 の非常に小さなグリッドが与えられます。 どのセルからでも、対角線を含む 8 つの隣接セルのいずれかに移動することができ、任意に何度でもセルを再訪問することができます。 移動に関する唯一の制限は、ステップによって実際にセルが変更される必要があるため、その場にとどまることは許可されません。 

各クエリは短い文字列を与えるので、訪問したセル文字のシーケンスが正確にその文字列を綴るようなウォークがグリッド上に存在するかどうかを判断する必要があります。 

重要な詳細は、同じセルが何度でも再利用できるため、この構造は訪問制約のある単純なパス問題ではないということです。 代わりに、これは、シーケンスに一致するラベル付きウォークがグリッドに含まれているかどうかについてです。 

制約はソリューションを強力に形作ります。 グリッドには最大 100 個のセルがあり、各クエリ文字列の長さは最大 13 です。クエリは最大 100,000 個あります。 この組み合わせは、各クエリがおよそ数千の操作に近い限り、グリッド上でクエリごとにかなり重い動的プログラムを実行できることを意味します。 13 ステップで 8 方向に分岐すると、最悪の場合、最大 8^13 の可能性が生じるため、メモ化を行わないパス上の指数関数的検索を伴うものはすべて即座に失敗します。 

微妙な点の 1 つは、セルを再利用すると通常の「単純なパス」構造が削除されることです。 状態をメモ化しない単純な深さ優先検索では、特にすべての文字が一致する均一なグリッド上で、同じ構成を何度も再訪できます。 

2 番目の微妙な点は、各クエリが独立していることです。 文字列が異なり、有効性が文字シーケンスの正確な位置合わせに依存するため、クエリ間で状態を引き継ぐことはできません。 

## アプローチ

 直接解釈すると、パターンの最初の文字に一致するすべてのセルから開始し、次の文字に一致させながら各ステップで 8 つの動きすべてを試行する深さ優先検索を実行することを示唆しています。 これは、可能なすべてのウォークを明示的に列挙しているため、正しいです。 

ただし、このアプローチでは同じ部分問題が何度も繰り返されます。 文字列内の固定セルと固定インデックスから、残りの質問は常に同じです。ここから文字列の接尾辞の照合を続行できるか? メモ化がなければ、特にセルの再訪問が許可され、サイクルによって無限の再計算が作成されるため、再帰は多くの冗長なパスを指数関数的に探索します。 

問題の構造により、より明確な再定式化が可能になります。 クエリ文字列ごとに、文字列内のグリッド位置とインデックスで構成されるペアとして状態を定義します。 状態から、文字が次の文字と一致する隣接するセルに遷移します。 文字列の長さは最大 13 で、グリッドの位置は最大 100 であるため、クエリごとの状態の総数は最大 1300 です。各状態には最大 8 つの遷移があるため、メモ化による完全な探索はこの状態空間では線形です。 

重要な観察は、状態をメモ化すると、グリッド内のサイクルは重要ではなくなるということです。 たとえウォークがセルを再訪問したとしても、その状態からサフィックスが可能かどうかを再計算する必要はありません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | メモ化を行わないブルートフォース DFS | クエリごとに O(8^L) | O(L) 再帰 | 遅すぎる |
 | クエリごとの DP over (セル、インデックス) 状態 | クエリあたり O(nm · L · 8) | クエリあたり O(nm · L) | 承認済み |

 ## アルゴリズムのチュートリアル

 動的プログラミングまたはグリッド上のメモ化された DFS 定式化を使用して、各クエリを個別に処理します。 

1. すべてのセルをパターンの潜在的な開始点とみなします。 開始セルは、その文字が文字列の最初の文字と一致する場合にのみ有効です。 この制限により、不一致の開始が有効な一致につながることはないため、不要な作業が直ちに削除されます。 
2. 状態に対する関数を定義します`(r, c, i)`つまり、私たちは現在監房にいるということです`(r, c)`すでにプレフィックスと一致しています`s[0..i]`、つまり、次に一致する文字は次のとおりです。`s[i+1]`。 目標は、インデックスに到達できるかどうかを判断することです`len(s) - 1`。 
3. 状態から`(r, c, i)`、 もし`i`はすでに文字列の最後のインデックスであるため、パターン全体との一致に成功し、成功を返します。 
4. それ以外の場合は、隣接する 8 つのセルすべてに移動しようとします。`(nr, nc)`。 トランジションは、次の文字が存在する場合にのみ有効です。`(nr, nc)`等しい`s[i+1]`。 有効な近傍ごとに、状態を再帰的に評価します。`(nr, nc, i+1)`。 
5. 同じ状態を何度も再計算することを避けるために、結果を次のインデックスが付いたメモ テーブルに保存します。`(r, c, i)`。 状態が計算されると、再び検出されるたびにその状態が再利用されます。 
6. クエリの答えは、開始位置が文字列の正常な完了につながる場合は「YES」、それ以外の場合は「NO」です。 

実装の重要な詳細は、メモ化がグローバルではなくクエリごとに行われることです。 各文字列は異なる状態空間を定義するため、クエリ間で再利用すると無関係な計算が混在することになります。 

### なぜ効果があるのか

 正確さは、グリッド内のすべての有効なウォークが、次のように定義された状態グラフ内の一連の遷移に正確に対応するという事実から得られます。`(cell, index)`。 グリッド内で可能なすべての動きは遷移ステップで表され、有効な文字シーケンスはすべてこの状態グラフ内のパスに対応する必要があります。 

メモ化では、遷移ではなく同一状態の再計算のみが排除されるため、有効なパスは削除されません。 各状態は続行に必要なすべての情報を完全に取得するため、再計算しても結果が変わることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

dx = [-1,-1,-1,0,0,1,1,1]
dy = [-1,0,1,-1,1,-1,0,1]

def solve_one(grid, s, n, m):
    L = len(s)
    memo = [[[-1] * L for _ in range(m)] for _ in range(n)]

    def dfs(x, y, i):
        if memo[x][y][i] != -1:
            return memo[x][y][i]

        if i == L - 1:
            memo[x][y][i] = 1
            return 1

        nx_char = s[i + 1]
        for k in range(8):
            nx = x + dx[k]
            ny = y + dy[k]
            if 0 <= nx < n and 0 <= ny < m:
                if grid[nx][ny] == nx_char:
                    if dfs(nx, ny, i + 1):
                        memo[x][y][i] = 1
                        return 1

        memo[x][y][i] = 0
        return 0

    for i in range(n):
        for j in range(m):
            if grid[i][j] == s[0]:
                if dfs(i, j, 0):
                    return True
    return False

def main():
    n, m = map(int, input().split())
    grid = [input().strip() for _ in range(n)]
    q = int(input())

    for _ in range(q):
        s = input().strip()
        print("YES" if solve_one(grid, s, n, m) else "NO")

if __name__ == "__main__":
    main()
```グリッド トラバーサルは 8 方向のオフセット アレイを通じて実装され、隣接生成のステップごとの時間を一定にします。 メモ テーブルは 3 次元であり、行、列、文字列内の位置によってキー設定されます。 以前の結果は無関係であるため、クエリごとにこのテーブルが再構築されます。 

DFS は、文字の等価性によってトランジションを即座にフィルタリングします。これは、実際にソリューションの高速性を維持する主なプルーニング要素です。 このチェックがなければ、実行可能性に関係なくすべての近隣が探索され、各ステップで作業が最大 8 倍になります。 

## 実用的な例

 グリッドについて考えてみましょう。```
ab
ju
```とクエリ文字列`auabj`。 

DP が一致するセルから始めて可能な状態を探索する方法を追跡します。`'a'`。 

| ステップ | ポジション | インデックス | 次の文字 | アクション |
 | --- | --- | --- | --- | --- |
 | 1 | (0,0) | 0 | あなた | 隣人を試してみてください |
 | 2 | (0,1) | 1 | | 右に移動 |
 | 3 | (1,1) | 2 | b | 斜めに移動/有効な隣 |
 | 4 | (0,0) | 3 | j | 再訪可 |

 このトレースは、状態 ID には文字列内のインデックスが含まれているため、セルの再訪問が特別なマーキングなしで自然に処理されることを示しています。 

次に、どのステップでも文字が一致しない失敗パターンを考えてみましょう。 次に必要な文字が、特定の深さの到達可能な状態の近隣に存在しないと仮定します。 メモ化により、ある状態からのすべてのパスが失敗すると、その状態は二度と再検討されなくなり、行き止まりの探索が繰り返されることがなくなります。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(q・n・m・L・8) | 各クエリは最大ですべてを調査します`(cell, index)`状態を 1 回、それぞれに最大 8 つの遷移を持ちます。 
| スペース | O(n・m・L) | クエリごとのメモ テーブルには、すべての状態トリプルの結果が保存されます。 

と`n, m ≤ 10`そして`L ≤ 13`、各クエリのコストは数千操作程度であり、これは`q = 100000`最適化された実装、特にコンパイル言語で。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from sys import stdout
    out = []

    n, m = map(int, input().split())
    grid = [input().strip() for _ in range(n)]
    q = int(input())

    dx = [-1,-1,-1,0,0,1,1,1]
    dy = [-1,0,1,-1,1,-1,0,1]

    sys.setrecursionlimit(10**7)

    def solve_one(grid, s):
        n, m = len(grid), len(grid[0])
        L = len(s)
        memo = [[[-1]*L for _ in range(m)] for _ in range(n)]

        def dfs(x,y,i):
            if memo[x][y][i] != -1:
                return memo[x][y][i]
            if i == L-1:
                memo[x][y][i] = 1
                return 1
            need = s[i+1]
            for k in range(8):
                nx, ny = x+dx[k], y+dy[k]
                if 0 <= nx < n and 0 <= ny < m:
                    if grid[nx][ny] == need:
                        if dfs(nx,ny,i+1):
                            memo[x][y][i] = 1
                            return 1
            memo[x][y][i] = 0
            return 0

        for i in range(n):
            for j in range(m):
                if grid[i][j] == s[0]:
                    if dfs(i,j,0):
                        return True
        return False

    for _ in range(q):
        s = input().strip()
        out.append("YES" if solve_one(grid, s) else "NO")

    return "\n".join(out)

 ## 特殊なケース

 同じ文字で埋められたグリッドは、再利用と循環動作を強調します。 のようなパターンの場合、`"aaaaaaaaaaaaa"`、すべてのセルは有効なスタートであり、すべての移動は有効なままです。 メモ テーブルによって各`(cell, index)`概念ウォークの数が膨大であっても、ペアは 1 回だけ評価されます。 

単一セルのグリッドは境界処理を示します。 パターンの長さが 1 より大きい場合、移動によって常にセルが変更されるため、遷移は不可能です。したがって、唯一の有効な答えは、単一の文字に一致する長さ 1 の文字列です。 

最初の文字がグリッドに存在しないパターンは、DFS が開始される直前にフィルタリングされます。 これにより、不必要な状態の作成が防止され、その場合にはアルゴリズムが再帰にまったく入らないことが保証されます。
