 ## 解決策
 ## 問題の理解

 単一の文字列が与えられ、それを左側の部分と右側の部分に分割するカット位置を 1 つだけ選択できます。 カットごとに、結果として得られる 2 つの文字列を調べ、それぞれを回文に再配置できるかどうかを調べます。 回文を直接形成する必要はなく、文字のいくつかの並べ替えが回文を形成できるかどうかを確認するだけです。 

奇数の頻度を持つ文字が 1 つだけの場合、文字列を回文に置き換えることができます。 この条件は、問題を組み合わせの並べ替えの問題から頻度カウントの問題に変える中心的な特性です。 

タスクは、この回文順列条件を満たす 2 つの部分文字列を生成する分割位置の数を数えることです。 

入力長は 100000 に達する可能性があり、分割ごとに文字の頻度を最初から再計算するソリューションは除外されます。 分割ごとに再計算を行うすべての分割点の二次スキャンでは、最悪の場合、制限時間をはるかに超える 10^10 のオーダーの演算が必要になります。 実行可能なソリューションでは、プレフィックス情報を再利用し、位置ごとに一定またはほぼ一定の時間で状態を更新する必要があります。 

微妙な失敗のケースは、ソリューションが分割の片側のみをチェックする場合、または完全な文字列が「良好」であればすべてのパーティションが同様に動作すると誤って仮定する場合に発生します。 たとえば、次の文字列を考えてみましょう。`aabbb`。 完全な文字列は関係ありませんが、次のような一部の文字列は関係ありません。`aa | bbb`両方の側に最大 1 つの奇数周波数特性があるため、機能します。 単純なグローバル チェックでは、分割位置への依存性を完全に見逃してしまいます。 

プレフィックス周波数がキャッシュせずに繰り返し再計算される場合、別の問題が発生します。 のような文字列の場合`abababab...`、分割ごとの繰り返しカウントは繰り返しフル スキャンに変質し、小規模なテストは静かに通過しますが、制約の下では失敗します。 

## アプローチ

 ブルートフォースのアイデアは単純です。 考えられるすべてのカット位置について、左側の部分文字列と右側の部分文字列の文字頻度を計算し、両方の頻度テーブルで「奇数カウントが 1 つまで」条件を確認します。 これは、各分割で独立して定義を直接適用するため、正しいです。 問題はそのコストです。 各分割では、左側で最大 O(n) 文字、右側で O(n) 文字をスキャンする必要があり、合計 O(n^2) 個の作業が発生します。 

重要な点は、周波数を最初から再計算する必要がないということです。 文字列全体の各文字の頻度がわかれば、左から右にスイープするときにプレフィックスの頻度を維持できます。 サフィックス周波数は、合計周波数とプレフィックス周波数の差として暗黙的に決定されます。 これにより、スプリットごとに一定時間で双方の奇数情報を更新することが可能になります。 

重要な構造は、回文条件が正確な数ではなく、周波数のパリティのみに依存するということです。 これは、小さな固定サイズの配列 (通常の制約では 26 文字) を維持および更新し、プレフィックスとサフィックスで現在奇数の頻度を持つ文字の数を追跡できることを意味します。 スプリット ポイントが移動するたびに、正確に 1 文字の寄与がサフィックスからプレフィックスに反転され、再スキャンせずにパリティ カウンターを更新できるようになります。

 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | お(26) | 遅すぎる |
 | 最適 | O(26n) | お(26) | 承認済み |

 ## アルゴリズムのチュートリアル

 文字列を小さなアルファベット (通常は小文字) のシーケンスとして扱います。 

1. 文字列全体の各文字の合計頻度を計算します。 これは、分割が行われる前のサフィックスの状態を表します。 
2. 最初はプレフィックスが空であるため、プレフィックス周波数配列をすべて 0 で初期化します。 この時点で、すべての文字がサフィックスに属します。 
3. 2 つのカウンタを追跡します。1 つはプレフィックスに奇数の頻度を持つ文字の数を表し、もう 1 つはサフィックスを表します。 最初は、プレフィックスの奇数カウントはゼロであり、サフィックスの奇数カウントは合計周波数配列から計算できます。 
4. 分割位置を左から右にスイープします。 各文字で、概念的にそれを接尾辞から接頭辞に移動します。 これは、サフィックスのカウントをデクリメントし、プレフィックスのカウントをインクリメントすることによって行われます。 
5. 現在の文字のカウントを更新した後、プレフィックスとサフィックスの両方の奇数カウンターを調整します。 各ステップで変更される文字は 1 つだけであるため、パリティに影響を与えることができるのはその文字だけであるため、すべての更新は O(1) になります。 
6. 分割位置ごとに、プレフィックスとサフィックスの両方に奇数の頻度の文字が最大 1 つ含まれているかどうかを確認します。 そうであれば、この分割は有効であり、答えに貢献します。 
7. 最後の有効な分割位置 (最後の文字の前) まで続行します。 

各分割を段階的に処理できる理由は、パリティの変更がローカルであるためです。 1 文字を移動すると、プレフィックスとサフィックスの両方でその文字のパリティが切り替わるだけなので、グローバルな有効性条件を動的に維持できます。 

### なぜ効果があるのか

 正確さは、回文順列条件がパリティ数のみに依存するという事実に基づいています。 分割ごとに、プレフィックスとサフィックスの周波数ベクトルは、各文字がサフィックスからプレフィックスに転送された回数によって完全に決定されます。 各ステップで 1 つの文字のメンバーシップが変更されるため、状態遷移ではパリティ追跡の完全な正確性が維持されます。 したがって、各ステップでの条件のチェックは、最初から再計算するのと同じですが、繰り返しのコストはかかりません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)
    
    if n <= 1:
        print(0)
        return

    # assuming lowercase English letters
    total = [0] * 26
    for ch in s:
        total[ord(ch) - 97] += 1

    pref = [0] * 26

    def count_odd(arr):
        c = 0
        for x in arr:
            c += x & 1
        return c

    suffix = total[:]
    pref_odd = 0
    suff_odd = count_odd(suffix)

    ans = 0

    for i in range(n - 1):
        idx = ord(s[i]) - 97

        # remove from suffix
        if suffix[idx] & 1:
            suff_odd -= 1
        suffix[idx] -= 1
        if suffix[idx] & 1:
            suff_odd += 1

        # add to prefix
        if pref[idx] & 1:
            pref_odd -= 1
        pref[idx] += 1
        if pref[idx] & 1:
            pref_odd += 1

        if pref_odd <= 1 and suff_odd <= 1:
            ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、2 つの周波数アレイと 2 つのパリティ カウンターが維持されます。 微妙な部分は、奇数カウンタを正しく更新することです。周波数を変更する前に、以前のパリティ寄与を削除し、更新を適用してから、新しい寄与を追加します。 これにより、パリティを最初から再計算する必要がなくなります。 

ループはすべての有効なカット位置にわたって実行され、そこで停止します。`n-1`両側が空ではない必要があるためです。 各反復では、固定のアルファベット サイズで一定量の作業が実行されます。 

## 実用的な例

 ### 例 1:`aabbb`分割を移動するときに、プレフィックスとサフィックスの奇数の数を追跡します。 

| 分割位置 | プレフィックス | サフィックス | プレフィックス奇数 | サフィックス奇数 | 有効 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | | アッブ | 1 | 2 | いいえ |
 | 2 | ああ | BBB | 0 | 1 | はい |
 | 3 | アブ | BB | 1 | 0 | はい |
 | 4 | あーぶ | b | 0 | 1 | はい |

 このトレースは、有効性が文字列のグローバル プロパティではなく、カット全体に文字がどのように分布するかによって決まることを示しています。 

### 例 2:`abcabc`| 分割位置 | プレフィックス | サフィックス | プレフィックス奇数 | サフィックス奇数 | 有効 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | | BCBC | 1 | 3 | いいえ |
 | 2 | アブ | キャブ | 2 | 2 | いいえ |
 | 3 | ABC | ABC | 3 | 3 | いいえ |
 | 4 | アブカ | 紀元前 | 2 | 2 | いいえ |
 | 5 | アブキャブ | c | 1 | 1 | はい |

 最後の分割のみが機能します。これは、両側が最大でも 1 つの奇数周波数に減少する唯一の分割であるためです。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    from contextlib import redirect_stdout
    import io as _io

    out = _io.StringIO()
    with redirect_stdout(out):
        solve()
    sys.stdin = old_stdin
    return out.getvalue().strip()

# minimum size
assert run("a") == "0"

# simple case
assert run("aa") == "1"

# sample-like case
assert run("aabbb") == "3"

# all same characters
assert run("aaaaa") == "4"

# alternating case
assert run("abab") == "3"

 ## 特殊なケース

 次のような単一文字列の場合`a`、有効な分割ポジションがないため、答えはゼロです。 アルゴリズムは、空ではないパーティションが存在しないという事実と一致して、ループに入らずにすぐに戻ります。 

次のような均一な文字列の場合`aaaaa`、各分割により、それぞれ 1 つの異なる文字のみを含む 2 つの文字列が生成され、両側が回文順列条件を自明に満たします。 実行中、サフィックスの奇数カウントは各ステップでゼロのままで、プレフィックスは 0 と 1 の間で切り替わりますが、許可されたしきい値を超えることはないため、すべての分割は正しくカウントされます。 

次のような交互パターンの場合`abab`、パリティはステップごとに振動します。 このサフィックスは、早い段階で複数の奇数カウントを急速に蓄積するため、ほとんどの分割が失敗し、両方の制約を同時に満たすのは最終構成のみです。
