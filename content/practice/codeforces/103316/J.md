 ## 解決策
 ## 問題の理解

 各ノードが鉱山を表し、各鉱山がリソースの量として解釈される固定の重みを持つツリーが与えられます。 この構造は、任意の 2 つのノード間に 1 つの単純なパスを保証します。 

個別のノードの順序付きペアの場合$u, v$、それらを結ぶユニークなパスに注目します。 このパスに沿ってすべてのノードの重みを検査し、そのパス上に現れる最大重みと最小重みの差を計算します。 その値は、これら 2 つのエンドポイントが選択された場合に得られる報酬です。 

個別のノードの順序付けされていないペアはすべて同じように選択される可能性があり、そのようなすべてのペアに対するこの報酬の期待値が求められます。 最終的な答えは、次のモジュラー分数として指定する必要があります。$10^9 + 7$。 

制約は、最大で次のツリーを提案します。$10^5$ノード。すべてを明示的に列挙するアプローチは即座に除外されます。$O(n^2)$をペアにするか、ペアごとにパス統計を再計算します。 平$O(n^2)$記憶推論は不可能です。 許容可能な解決策はすべて、線形または線形演算に近いものでなければなりません。 

エンドポイントの処理方法に微妙な問題が生じます。 この問題では 2 つの異なる頂点を選択することが説明されていますが、パスは対称的に扱われるため、順序付けされていない各ペアは 1 回だけ考慮される必要があります。 単純な実装では、順序付きペアを誤って二重にカウントしたり、確率の正規化を誤って処理したりする可能性があります。 

もう 1 つの明白ではない落とし穴は、パス上の最大値と最小値が独立して動作すると想定していることです。 たとえば、次のようなパス上で$3 - 1 - 4$、最小値と最大値は異なるノードにありますが、異なるパス構造上では、同じノードが複数のペアの極値の両方の端点として機能する可能性があります。 貢献を不注意に分離可能として扱うと、誤ったカウントにつながります。 

## アプローチ

 ブルート フォース ソリューションは、ノードのすべてのペアを反復処理することから始まります。 各ペアについて、DFS または LCA 前処理を使用してパスに沿った最大値と最小値を計算します。 バイナリリフティングを使用しても、各クエリにコストがかかります$O(\log n)$、合計は次のようになります$O(n^2 \log n)$、これは大きすぎます。$n = 10^5$。 対数を無視しても、ペアの二次数がすぐに支配的になります。 

重要な変化は、パスの観点から考えるのをやめ、代わりに個々のノードの貢献の観点から考えることです。 「パス上の最大値マイナス最小値」という表現は、2 つの独立した寄与率として書き直すことができます。つまり、最大値であるノードの寄与率のすべてのペアの合計から、最小値であるノードの寄与率の合計を差し引いたものです。 

これにより、問題はノードごとにカウントされるようになります。$x$、何ペア$(u, v)$そのように存在する$x$はそれらの間のパス上の最大値です。 同じロジックが最小値にも適用されます。 

次にノードを修正します$x$。 パス上で最大値にするには、そのパス上のすべてのノードに重みが必要です$\le w_x$、パスには次のものが含まれている必要があります$x$。 これは接続性の観点を示唆しています: 最大でも重みを持つノードのみを保持する場合$w_x$、森林を取得し、$x$エンドポイントが異なるコンポーネント内にあるペアを介して接続されます。$x$追加されたとき。 

重みの昇順にノードを処理することで、ノードを段階的にアクティブ化し、接続されたコンポーネントを維持できます。 ノードをアクティブ化するとき$x$、すでにアクティブな近隣のいくつかを接続します。 重要な観察は、そのペアがどのようなものであるかということです。$x$最大値は、その時点で接続されているペアに正確に対応します$x$が導入され、その接続が通過します$x$。 

DSU 構造を使用して、ノード間のコンポーネント サイズを現在の値以下の重みで維持します。 アクティブ化するたびに$x$、それをアクティブな近傍と結合し、次のような新しいペアがいくつ形成されるかを計算します。$x$パス上の最も重みの高いノードとして。 この数は、マージされたコンポーネントのサイズを乗算して求められます。 

重みの降順でノードを処理するか、同等に重みを否定することによって、最小値を求める同じアイデアを繰り返します。

 ## アルゴリズムのチュートリアル

 貢献度を最大部分と最小部分に分割し、最後にそれらを結合します。 

1. ノードを重みの昇順に並べ替えます。 この順序でノードを徐々にアクティブ化していきます。 その理由は、ノードがアクティブになると、それが最大となるすべての潜在的なパスには、それより小さいか等しいノードがすべてすでに使用可能である必要があるためです。 
2. 各アクティブ ノードが最初に独自のコンポーネントを形成する DSU を維持します。 DSU は、アクティブなノードのみに制限された接続を表します。 
3. ノード起動時$x$、それをアクティブとしてマークし、その実行コンポーネントのサイズを 1 として初期化します。 
4. 隣人ごとに$y$の$x$、 もし$y$はすでにアクティブなので、コンポーネントを結合します$x$そして$y$。 サイズの 2 つのコンポーネントを結合する前$a$そして$b$、追加します$a \cdot b$最大の貢献を得る答えへ。 これは、経由で接続されるノードのすべてのペアをカウントします。$x$この段階では、つまり$x$接続パス上の最大の重みです。 
5. すべてのノードが処理されるまで繰り返します。 これにより、各ノードの合計貢献度が最大値として得られます。 
6. 最小寄与を計算するには、重みの降順でノードを処理することによってロジックを逆にします。 各アクティブ化では、同じ DSU メカニズムを使用して、ノードがパス上で最小値になるペアがカウントされるようになりました。 
7. 最終的な答えは、最大寄与度の合計と最小寄与度の合計の差を、順序のないノードのペアの数で割ったものです。 この分数モジュロを計算します$10^9 + 7$モジュラーインバースを使用します。 

### なぜ効果があるのか

 DSU プロセスは、ツリーのフィルタリングを重みによってエンコードします。 現時点ではノード$x$昇順でアクティブ化され、すでにアクティブになっているすべてのノードには最大で重みがあります$w_x$。 アタッチによって作成された新しい接続$x$最大許容重みが厳密に以下である、以前は別個だった 2 つのコンポーネントをマージします。$w_x$。 そのマージでカウントされるすべてのペアのパスの最大値は次の値に等しい必要があります。$w_x$、その時点でアクティブ セットには重いノードが存在せず、唯一の新しいコネクタがあるためです。$x$自体。 これにより、有効な各ペアは、その最大要素がアクティブになった瞬間に 1 回だけカウントされることが保証されます。 

逆の順序で処理する場合も、同じ推論が対称的に最小値に適用されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return 0
        if self.size[a] < self.size[b]:
            a, b = b, a
        res = self.size[a] * self.size[b]
        self.parent[b] = a
        self.size[a] += self.size[b]
        return res

def solve_for(order, adj):
    n = len(order)
    dsu = DSU(n)
    active = [False] * n
    comp_size = [0] * n
    res = 0

    for w, x in order:
        active[x] = True
        comp_size[x] = 1

        for y in adj[x]:
            if active[y]:
                res += dsu.union(x, y)
                res %= MOD

    return res

def main():
    n = int(input())
    w = list(map(int, input().split()))
    adj = [[] for _ in range(n)]

    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        adj[u].append(v)
        adj[v].append(u)

    nodes_inc = sorted([(w[i], i) for i in range(n)])
    nodes_dec = sorted([(w[i], i) for i in range(n)], reverse=True)

    max_pairs = solve_for(nodes_inc, adj)
    min_pairs = solve_for(nodes_dec, adj)

    inv = pow(n * (n - 1) // 2, MOD - 2, MOD)
    ans = (max_pairs - min_pairs) % MOD
    ans = ans * inv % MOD

    print(ans)

if __name__ == "__main__":
    main()
```DSU は、「すでにアクティブ化された」ノード間の接続トラッカーとしてのみ使用されます。 重要な実装の詳細は、union がマージ前のコンポーネント サイズの積を返すことです。これは、新しく形成されたエンドポイント ペアに直接対応します。 これにより、パスを明示的に追跡したり、LCA 計算を実行したりすることが回避されます。 

微妙な詳細は、順序付けされていないペアの数による正規化です。 DSU の計算では、すべてのペアにわたる合計寄与率が生成されます。 で割る$n(n-1)/2$それを一様ランダムペア選択の期待値に変換します。

 ## 特殊なケース

 単一ノードのケースには有効なペアがないため、答えはゼロでなければなりません。 DSU は結合を実行することはなく、最終的な正規化では、空のペア セットを個別に処理することで、ゼロによる除算が正しく回避されます。 

2 ノード ツリーは最も単純な健全性チェックです。 唯一のパスに沿った最大値と最小値は両方とも同じペアのエンドポイントであるため、差は常にゼロであり、アルゴリズムは効果的な寄与を生成しません。 

重みを厳密に増加させるチェーンにより、各アクティベーションで 1 つの新しいノードが既存のコンポーネントに確実にマージされ、ペア数の予測可能な線形累積が生成されます。 各ステップは既存のコンポーネントのサイズを正確に反映する必要があるため、これにより共用体サイズの乗算で 1 つずつ異なるエラーが発生します。
