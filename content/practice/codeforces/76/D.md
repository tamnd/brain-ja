 ## 解決策
 ## 問題の理解

 2 つの非負の整数が与えられます。`A`そして`B`。 他の 2 つの非負の整数を構築する必要があります。`X`そして`Y`、次のようになります。 

- それらの合計は等しい`A`- それらのビットごとの XOR が等しい`B`すべての有効なペアの中で、可能な限り最小のペアを出力する必要があります。`X`。 

興味深いのは、加算と XOR がキャリーを通じて相互作用することです。 xor だけを見ると、すべてのビットが独立して動作します。 加算は、下位ビットからのキャリーによって次のビットが変更されるため、異なります。 問題全体は、実際には、これら 2 つの操作がどのように組み合わされるかを理解することにかかっています。 

数値は次のように大きくすることができます`2^64 - 1`したがって、すべての可能な値に対してブルートフォースを実行することは不可能です。 すべての候補を反復処理しても、`X`まで必要になります`2^64`まったく実行不可能な操作です。 ほぼ一定時間で動作するか、最悪の場合でもビット数に比例して動作するものが必要です。 64 ビット整数には 64 桁しかないため、`O(64)`解決策は実質的に瞬時に行われます。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

考慮する：```
A = 5
B = 6
```私たちは次のことを知っています:```
X + Y >= X xor Y
```キャリーによって合計が増加するためです。 ここ`B > A`、したがって解決策は存在しません。 実現可能性をチェックせずにビットを操作するだけの不注意な実装では、負の中間値が誤って生成される可能性があります。 

もう 1 つの微妙なケースはパリティの不一致です。```
A = 10
B = 3
```ID の使用:```
A = (X xor Y) + 2 * (X & Y)
```得られるもの:```
A - B = 7
```それは奇妙だ。 以来`2 * (X & Y)`常に均等である必要がありますが、これは不可能です。 このパリティ条件が欠けていると、不正確な応答が発生します。 

重複条件もあります。```
A = 2
B = 2
```それから：```
(A - B) / 2 = 0
```これは有効であり、次のようになります。```
X = 0
Y = 2
```ただし、次の場合:```
A = 10
B = 8
```得られるもの:```
C = (A - B) / 2 = 1
```今`C & B = 0`、それで建設は機能します。 

それを以下と比較してください:```
A = 14
B = 10
```それから：```
C = 2
B = 1010
C = 0010
```これらはビット 1 でオーバーラップします。つまり、1 つのビットでキャリーを作成し、xor で異なる必要があることを意味しますが、これは不可能です。 ここで単純な再構築では、無効な数値が暗黙的に生成される可能性があります。 

## アプローチ

 最も直接的な総当り攻撃のアイデアは、可能なすべての値を試してみることです。`X`、次を計算します。```
Y = A - X
```そして、次のことを確認してください。```
X xor Y == B
```これは正しいです。有効なペアはすべて方程式を満たす必要があるからです。 問題は検索スペースです。 以来`A`に近づくことができます`2^64`、ブルートフォースアプローチには次のものが必要になる場合があります`10^19`繰り返し。 1 秒あたり 10 億回の操作でも数世紀かかります。 

重要な観察は、sum と xor を含む標準的な恒等式から得られます。$X+Y=(X\oplus Y)+2(X\&Y)$xor はビットが異なる位置をカウントします。 の`AND`両方のビットが存在する位置をカウントします。`1`、加算中にキャリーを作成します。 すべてのキャリーは、そのビット値の 2 倍を最終合計に反映します。 

以来`B = X xor Y`、次のように書き換えることができます。```
A = B + 2 * (X & Y)
```させて：```
C = X & Y = (A - B) / 2
```ここで問題は次のようになります。 

- xor が次の 2 つの数値を構築します。`B`- 誰と誰ですか`C`各ビットで:

 - 少し入っている場合`B`は`1`、次に、のビット`X`そして`Y`違うはずだ
 - 少し入っている場合`C`は`1`の場合、両方のビットは次のようにする必要があります。`1`これら 2 つの状態は、同じビットで同時に発生することはできません。 それで：```
B & C == 0
```保持しなければなりません。 

この条件が満たされると、再構築が容易になります。 

- 毎`1`少しの`C`両方の数字に入ります
 - 毎`1`少しの`B`いずれかの数字に正確に入力する必要があります

 最小限に抑えるには`X`、すべての xor 専用ビットを次のように割り当てます。`Y`の代わりに`X`。 

それは次のようになります:```
X = C
Y = C + B
```オーバーラップ条件が有効である場合に限ります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^64) | お(1) | 遅すぎる |
 | 最適 | お(64) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む`A`そして`B`。 
2. かどうかを確認します。`A < B`。 

以来：```
X + Y >= X xor Y
```合計が xor より小さくなることはありません。 
3. 以下を計算します。```
D = A - B
```もし`D`奇妙です、解決策は存在しません。 

数量:```
D = 2 * (X & Y)
```常に均等でなければなりません。 
4. 以下を計算します。```
C = D // 2
```これは共通のことを表しています`1`両方の数値で共有されるビット。 
5. 次のことを確認します。```
C & B != 0
```このような場合は出力してください`-1`。 

ビットは xor 構造とキャリー構造に同時に属することはできません。 xor ビットでは 2 つの数値が異なる必要がありますが、and ビットでは両方が異なる必要があります。`1`。 
6. 答えを組み立てます。```
X = C
Y = C + B
```すべての共有ビットは内部に留まります`C`。 すべての異なるバイトから`B`に割り当てられています`Y`保つ`X`できるだけ小さいもの。 
7. 出力`X`そして`Y`。 

### なぜ効果があるのか

 この構造は、バイナリ加算の XOR への正確な分解に基づいており、次の内容が含まれます。```
X + Y = (X xor Y) + 2 * (X & Y)
```値`C = (A - B) / 2`キャリーを生成するすべてのビットを一意に決定します。 いずれかのビットが両方に属する場合`B`そして`C`、異なることと一致することを同時に行うには同じビット位置が必要になりますが、これは不可能です。 

いつ`B & C == 0`、ビットの役割は完全に分離されています。 

- ビット`C`は`1`両方の数字で
 - ビット`B`は`1`正確に 1 つの数字で

 すべての XOR 専用ビットを`Y`最小化する`X`、これらのビットのいずれかを追加すると、`X`増えるだけだろう。

```最初の条件は、sum と xor の間の基本的な不等式をチェックします。 有効なペアは次の条件を満たす必要があります。```
X + Y >= X xor Y
```キャリーは合計を増やすだけだからです。 

次に、コードは計算します`D = A - B`。 この値は、共有ビット構造の 2 倍に等しくなければなりません。```
D = 2 * (X & Y)
```もし`D`奇妙です、再構築は不可能です。 

重複チェック:```
if C & B:
```が中心となる正確性の条件です。 セットビットイン`C`両方の数値が含まれていることを意味します`1`そこには。 セットビットイン`B`そこでは数値が異なることを意味します。 1 つのビット位置で両方の要件を同時に満たすことはできません。 

最終的な構造は意図的に非対称になっています。```
X = C
Y = C + B
```すべての xor 専用ビットが入ります`Y`、これは維持します`X`最小限。 ビット単位の代わりに加算を使用することは安全です。`C`そして`B`決して重なりません。 

Python の整数は 64 ビット値を自動的に安全に処理するため、オーバーフローのリスクはありません。

def solve():
    input = sys.stdin.readline

    sys.stdout = out

    solve()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout
