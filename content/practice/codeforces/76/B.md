 ## 解決策
 ## 問題の理解

 座標で水平線に沿って配置されたマウスの列が与えられます。`y = Y0`そして別の水平線に沿ってチーズ片が並んでいます。`y = Y1`。 各マウスは任意のチーズに向かって直接走ることができ、すべてのマウスは同じ速度で走ります。 複数のネズミが同じチーズを狙う場合、最初に到着したネズミだけがそれを食べます。 その後のマウスは空腹のままです。 私たちの仕事は、すべてのマウスが自分に最も近いチーズを最適に選んだ場合に空腹になるマウスの最小数を決定することです。 

入力により、マウスとチーズの x 座標が厳密に昇順で提供されます。 この厳密に増加する順序は、同じ座標での同点を気にせずに位置を効率的に比較できることを意味し、マッチングを簡素化します。 マウスとチーズの数はそれぞれ最大 100,000 に達する可能性があるため、マウスとチーズのポイントのすべてのペアを検査する単純なソリューションでは 10^10 の操作が必要となり、標準の制限時間には多すぎます。 

明らかではないエッジケースは、すべてのマウスが 1 つのチーズの近くに集まり、他のチーズが遠くにある場合に発生します。 たとえば、3 匹のマウスが所定の位置にある場合、`[0,1,2]`そしてチーズが2つあります`[0, 100]`、すべてのマウスに最も近いピースは次のとおりです。`0`。 相対的な到着時間を考慮せずに貪欲に割り当てた場合、可能な限り多くのマウスが餌を与えられると誤って仮定する可能性があります。 正しい出力は、最も近いマウスだけが最初のチーズを食べ、残りは空腹になるということです。 

チーズ片がまったくない場合にも、別の特殊なケースが発生します。 その場合、すべてのマウスは空腹のままになります。 最後の微妙な点は、マウスとチーズがすでに X 座標によってソートされている場合です。 並べ替えは不要であり、2 ポインタ アプローチによりこの順序付けを効率的に利用できます。 

## アプローチ

 ブルートフォースアプローチでは、すべてのマウスとチーズのペアを考慮し、ユークリッド距離を計算し、マウスを最も近いチーズに割り当てます。 各チーズの距離を分類した後、到着をシミュレートして、どのマウスが最初に食べるかを確認します。 これは正確性を保つために機能しますが、時間計算量 O(N * M) があり、マウスとチーズの上限が 100,000 である場合は実行不可能です。 

重要な洞察は、座標の厳密に増加する順序を利用することです。 すべてのマウスは同じ速度で走り、y 距離は一定であるため、マウスに最も近いチーズは x 距離のみに依存します。 2 ポインター手法を使用できます。つまり、マウスを左から右に繰り返し、マウスごとに最も近い利用可能なチーズを見つけます。 マウスが現在のチーズよりも次のチーズに近い場合、チーズ ポインタを前方に移動します。 このようにして、考えられるすべてのペアをチェックすることなく、各マウスが最適にペアリングされます。 

この問題は、ユークリッド距離が線間の垂直距離で簡略化された、単一次元に沿った 2 ポインターのマッチング問題に帰着します。 このアプローチでは、空腹のマウスが最小限に抑えられることが保証されています。これは、常に最も近い残りのチーズを順番に各マウスに割り当て、要求されていない近くのチーズに到達するマウスが存在しないことを保証するためです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N*M) | O(N+M) | 遅すぎる |
 | 貪欲なツーポインター | O(N+M) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ポインタから始める`i`マウス用と`j`チーズの場合、どちらもそれぞれのリストの先頭にあります。 
2. 位置にある各マウスについて`mice[i]`、現在のチーズまでの距離を確認します。`cheese[j]`そして次のチーズ`cheese[j+1]`それが存在する場合。 浮動小数点エラーを避けるために二乗ユークリッド距離を計算します。`(mice[i]-cheese[j])**2 + (Y0-Y1)**2`。 
3. 次のチーズが近い場合は、チーズポインタを移動します`j`現在のチーズが最も近いか、最後のチーズに到達するまで進めます。 
4. このマウスを最も近いチーズに割り当てます。 チーズがまだ割り当てられていない場合は、食べたとマークして次のマウスに移動します。 そうしないと、マウスがお腹が空いてしまいます。 
5. 空腹のネズミのカウンターを維持します。 各マウスについて、割り当てるチーズ片がない場合は、空腹カウンタをインクリメントします。 
6. すべてのマウスが処理されるまで続行します。 

これが機能する理由: あらゆる段階で、各マウスはまだ割り当てられていないチーズの中で最も近いチーズを貪欲にターゲットにします。 座標の厳密な昇順により、機会がスキップされることはありません。 不変条件は、各反復において、割り当てられたすべてのマウスが利用可能な最も近いチーズを持っているため、どのマウスもより近いチーズを割り当てられないということです。 これにより、空腹のマウスが最小限に抑えられることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    N, M, Y0, Y1 = map(int, input().split())
    mice = list(map(int, input().split()))
    cheese = list(map(int, input().split()))
    
    hungry = 0
    j = 0
    dy2 = (Y0 - Y1) ** 2  # constant vertical distance squared

    for x in mice:
        while j + 1 < M and (cheese[j+1] - x)**2 + dy2 <= (cheese[j] - x)**2 + dy2:
            j += 1
        if j >= M:
            hungry += 1

    print(hungry)

if __name__ == "__main__":
    main()
```コードでは、`dy2`垂直距離の二乗を考慮して、計算の繰り返しを回避します。 while ループは、次のチーズが厳密に近い場合にのみチーズ ポインタを移動し、貪欲な正確性を維持します。 境界チェックにより、最後のチーズを超えてインデックスが作成されないことが保証されます。

## 特殊なケース

 チーズなしの場合は、`M = 0`、ポインタ`j`決してインクリメントされず、マウスごとにハングリーカウンターがインクリメントされ、結果が得られます。`N`予想通り。 

複数のマウスが 1 つのチーズをめぐって競合する場合、貪欲ポインタにより、最も近いマウスが最初にカウントされ、残りのマウスは自然に空腹カウンターをインクリメントします。 たとえば、マウスの場合`[0,1,2]`とチーズ`[1]`、1 のマウスが最初に到達し、0 と 2 のマウスは空腹のままで、出力を確認します。`2`。 

すべてのチーズがすべてのマウスの右側にある場合、ポインタは次のチーズが近づいたときにのみ移動しますが、そのようなチーズが存在しない場合、すべてのマウスは空腹になります。 この動作により、エッジ間隔が正しく処理されます。
