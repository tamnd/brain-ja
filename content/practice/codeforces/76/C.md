 ## 解決策
 ## 問題の理解

 生物のゲノムを表す文字列が与えられます。各文字は最初の _K_ 大文字の 1 つです。 隣接する遺伝子は、非負の整数の指定された _K × K_ 行列に従って、合計の「病気のリスク」に寄与します。 さらに、一部の遺伝子タイプの出現をすべて削除することもできます。 遺伝子タイプを削除すると、その遺伝子タイプに関連付けられた固定値だけ合計リスクがさらに増加し​​ます。 

私たちの仕事は、結果として得られるゲノムの総リスクが所定の閾値 _T_ を超えないように、そのような欠失によって取得できる異なるゲノムの数を数えることです。 2 つのゲノムは、結果として得られる配列が同一でない場合、異なるものとみなされます。 

制約により、これは自明ではなくなります。 ゲノムの長さ _N_ は最大 200,000 になる可能性があるため、すべての部分文字列またはすべての可能な削除を単純に反復するアプローチは、遅すぎるでしょう。 一方、_K_ は最大でも 22 であるため、遺伝子型のサブセットはビットマスクを使用して表現でき、サブセットに対する動的プログラミングまたは包含-除外アプローチが実現可能であるというヒントが得られます。 

エッジケースには、ほぼすべての遺伝子を削除しても 1 つまたは 2 つの文字だけが残る場合や、複数の欠失が隣接するリスクへの影響で重複する状況が含まれます。 不用意なアプローチは、削除された遺伝子間の相互作用を無視し、全体のリスクを過小評価する可能性があります。 

たとえば、ゲノムについて考えてみましょう`ABAB`と`K = 2`、`T = 5`、`t = [1, 2]`、隣接リスク`a = [[0, 3], [3, 0]]`。 全部外すと`A`つまり、残っているゲノムは`BB`ただし、合計リスクには増分が含まれている必要があります。`t[0]`除去用`A`s、そうでない場合は、_T_ に対するチェックが正しくありません。 

## アプローチ

 ブルートフォースアプローチは簡単です。 _K_ 遺伝子タイプのすべての可能なサブセットを削除して試し、結果のゲノムをシミュレートし、隣接リスクを計算し、削除ペナルティを追加して、合計リスクが ≤ _T_ であるかどうかを確認することができます。 サブセットの数は 2^K で、K = 22 の場合、最大 400 万です。サブセットごとにゲノム リスクを単純に計算するには、最大 200,000 までの長さの文字列をスキャンする必要があります。 これにより、合計演算数はおよそ 2^22 × 2×10^5 ≈ 8×10^11 になりますが、これは明らかに実行不可能です。 

重要な洞察は、ゲノムの隣接寄与を除去ペナルティから切り離すことです。 遺伝子型の各ペアについて、そのペアが元のゲノム内で隣接して出現する回数を事前に計算できます。 遺伝子タイプを削除すると、その遺伝子が出現するペアにのみ影響します。 したがって、ゲノムを再スキャンする代わりに、これらの事前計算されたカウントを使用して、遺伝子のサブセットを削除した場合の影響を計算できます。 これにより、サブセットごとの計算が O(K^2) に削減されます。これは、2^22 × 22^2 ≈ 2×10^7 の演算が時間制限内で十分に行われるため、実現可能です。 

最適な解決策は、ビットマスク動的プログラミングを使用します。 遺伝子タイプのすべてのサブセットを反復処理し、削除された遺伝子によって寄与される追加リスクを追跡します。 除去された遺伝子の隣接寄与は、事前に計算されたカウントにリスク行列を乗算して合計することで効率的に計算できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^K × N) | お(1) | 遅すぎる |
 | 最適 | O(2^K × K^2) | O(K^2 + N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力を解析します: ゲノム長を読み取ります`N`、遺伝子の種類の数`K`、およびしきい値`T`。 ゲノム文字列の読み取り、削除ペナルティ`t[i]`、および隣接リスク マトリックス`a[i][j]`。 
2. 計算を簡素化するために、ゲノム文字を 0 から始まるインデックスに変換します。 
3. 隣接数の事前計算: K × K 行列を初期化します。`cnt[i][j]`遺伝子の種類の何倍かを表す`i`すぐに遺伝子型が続きます`j`ゲノムの中で。 ゲノムを 1 回ループしてインクリメントします`cnt[genome[i]][genome[i+1]]`。 
4. 変数を初期化する`result = 0`有効なゲノムをカウントします。 
5. ビットマスクを使用して、遺伝子タイプのすべてのサブセットを反復処理します。`mask`1 から 2^K - 1 まで。マスクに設定された各ビットは、削除する遺伝子タイプを示します。 
6. 各サブセットについて、これらの遺伝子の除去による追加リスクの合計を計算します。 次の合計から始めます`t[i]`削除されたすべての遺伝子タイプについて。 
7. 得られたゲノムの隣接リスクを計算します。 遺伝子型の各ペアについて`(i, j)`どちらも削除されない場合、合計`cnt[i][j] * a[i][j]`。 
8. 隣接リスクと削除ペナルティを合計します。 合計 ≤ の場合`T`、増分`result`。 
9. 出力`result`。 

これが機能する理由: 各サブセットは 1 回だけ考慮されます。 隣接数を事前に計算すると、ゲノムを繰り返しスキャンしなくても除去効果が正しく計算されます。 ビットマスクを使用してサブセットが系統的に列挙されるため、変異の可能性のあるすべてのゲノムが重複することなくカウントされ、合計リスクの計算が正確になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

N, K, T = map(int, input().split())
genome = input().strip()
t = list(map(int, input().split()))
a = [list(map(int, input().split())) for _ in range(K)]

# convert genome to 0-based indices
genome_idx = [ord(c) - ord('A') for c in genome]

# precompute adjacency counts
cnt = [[0] * K for _ in range(K)]
for i in range(N - 1):
    cnt[genome_idx[i]][genome_idx[i+1]] += 1

result = 0
for mask in range(1, 1 << K):
    removed = [bool(mask & (1 << i)) for i in range(K)]
    total_risk = 0
    
    # add removal penalties
    for i in range(K):
        if removed[i]:
            total_risk += t[i]
    
    # compute adjacency risk
    for i in range(K):
        if removed[i]:
            continue
        for j in range(K):
            if removed[j]:
                continue
            total_risk += cnt[i][j] * a[i][j]
    
    if total_risk <= T:
        result += 1

print(result)
```このコードはアルゴリズムに正確に従います。 隣接数を事前に計算することで、ゲノムを繰り返しスキャンすることがなくなります。 サブセットにビットマスクを使用すると、サブセットの列挙がきれいに保たれます。 境界条件は、空のゲノムを避けるためにマスク = 1 から開始して処理されます。 0 ベースのインデックスへの変換により、インデックス作成時の off-by-one エラーが回避されます`a[i][j]`そして`cnt[i][j]`。
