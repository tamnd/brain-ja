 ## 解決策
 ## 問題の理解

 すべての道路に 2 つのしきい値が関連付けられた無向グラフがあります。 

価値ある道へ`(g, s)`、王が少なくとも与えた場合にのみ、道路は安全になります。`g`金貨と少なくとも`s`山賊に銀貨を。 支払い総額は次のとおりです。$\text{cost} = G \cdot a + S \cdot b$ここ`a`はゴールドの量です、`b`は銀の量であり、`G`、`S`金貨1枚と銀貨1枚の価格です。 

国王はすべての都市が安全な道路でつながることを望んでいます。 グラフを接続できる最小の支払いコストを見つけなければなりません。 

この問題について考えるのに役立つ方法は次のとおりです。 

すべての都市を結ぶいくつかの道路を選択した場合、必要なゴールドの量は最大になります。`g`それらの道の中で、必要なシルバーの量は最大です`s`それらの道の間で。 

したがって、すべてのスパニング ツリーでコストが定義されます。$G \cdot \max(g_i) + S \cdot \max(s_i)$タスクは、そのような値が最小のスパニング ツリーを見つけることです。 

制約によってソリューションが完全に形作られます。 グラフには最大 50,000 のエッジを含めることができますが、これは、サブセットを列挙したり、高価なグラフ アルゴリズムを最初から繰り返し実行したりするソリューションにはあまりにも大きすぎます。 以来`N`わずか 200、アルゴリズムは周囲にあります`O(M * N^2)`まだ現実的ですが、`O(M^2)`重い定数を使用すると危険になり始めます。 

このグラフでは、同じ都市のペア間の複数のエッジや自己ループも許可されます。 不用意に実装すると、DSU のマージ中に誤ってループを使用したり、ここでは当てはまらない単純なグラフ プロパティを想定したりする可能性があります。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

切り離されたグラフを考えてみましょう。```
3 1
1 1
1 2 5 5
```都市 3 には決して到達できません。 正しい答えは、`-1`。 接続性を明示的にチェックせずにコストを最小限に抑えるだけのアルゴリズムは、ここでは失敗します。 

ここで、同じ頂点間の複数のエッジを考えてみましょう。```
2 2
10 1
1 2 1 100
1 2 100 1
```最初のエッジはゴールドで安価、2 番目のエッジはシルバーで安価です。 スパニング ツリー エッジが物理的に存在する必要があるため、これらを結合することはできません。 最適な答えは`101`、 ない`2`。 

自己ループも重要です。```
2 2
1 1
1 1 1 1
1 2 10 10
```ノード 1 のループは接続にはまったく貢献しません。 正しい答えは、`20`。 ループ マージをやみくもにカウントする DSU 実装では、グラフが実際より早く接続されていると誤って認識する可能性があります。 

もう 1 つの微妙なケースは、最適解が単一の重み関数の下での最小スパニング ツリーに対応しない場合に発生します。```
3 3
100 1
1 2 1 1000
2 3 1 1000
1 3 100 1
```小さな金の価値だけを使用すると、銀が巨大になることを余儀なくされます。 全体的にシルバーの方がはるかに安いため、最適な答えは高価なゴールドのエッジを使用します。 

## アプローチ

 ここでは強引な視点が驚くほど役に立ちます。 

考えられるすべてのペアを試してみるとします`(maxGold, maxSilver)`。 満足のいく道路のみを維持します。$g_i \le \text{maxGold},\quad s_i \le \text{maxSilver}$次に、それらの道路がグラフを接続しているかどうかを確認します。 

これが機能するのは、有効なギフトがそのようなフィルター処理されたグラフを正確に定義しているためです。 グラフがつながっていれば、支払いは可能です。 

問題は可能なペアの数です。 最大 50,000 個の個別のゴールド値と 50,000 個の個別のシルバー値があります。 すべての組み合わせを試してみると、おおよその結果が得られます`2.5 * 10^9`状態、完全に不可能です。 

次の観察が重要な転換点となります。 

ゴールドの昇順にエッジを処理すると、ある時点でゴールドの最大値がすでに固定されています。 ゴールドがこの値を超えないすべてのエッジの中で、最大シルバーを最小化するスパニング ツリーが存在するかどうかだけを知る必要があります。 

これにより問題が変わります。 

固定のゴールド制限の場合、接続を可能にする可能な限り小さいシルバー制限が必要です。 

これは、最大のエッジの重みを最小限に抑えながらスパニング ツリーを構築するのと非常によく似ています。 実際、候補エッジをシルバーでソートし、DSU フォレストを貪欲に構築すると、結果のスパニング ツリーで使用される最大のシルバーは最小限になります。 

したがって、アルゴリズムは次のようになります。 

増加するにつれてエッジを反復処理します`g`。 候補セットに新しいエッジを追加した後、次のように順序付けされたクラスカルのような構造を再構築します。`s`現在許可されているすべてのエッジの中で達成可能な最小の最大シルバーを見つけます。 

以来`N`はわずか 200 なので、すべてのエッジに対してこの構造を再構築するのは十分に高速です。 

これが機能する理由はエレガントな部分です。 

反復時`i`、許可されているすべてのスパニング ツリーは、最大でもゴールドのエッジのみを使用する必要があります。`g_i`、そのようなエッジのみを処理しているためです。 それらの木の中で、シルバーによるクラスカルは最大のシルバーエッジを最小限に抑えます。 これにより、このゴールドのしきい値に対して可能な限り最高のシルバーのしきい値が得られます。 

すべてのゴールドしきい値を試すと、意味のあるすべてのソリューションが暗黙的にチェックされます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 全てにおいてブルートフォース`(gold, silver)`ペア | O(M²・α(N)) | O(N) | 遅すぎる |
 | ゴールドで並べ替え + シルバーでクラスカルを再構築 | O(M²・α(N)) | お(お) | 承認済み |

 一見すると、最適な複雑さは総当たりと同じように見えますが、定数はまったく異なります。 ブルートフォースバージョンはすべての値のペアを検査しますが、受け入れられているソリューションは実際のエッジのみを処理し、次のような小さなDSU操作を使用します。`N ≤ 200`。 

## アルゴリズムのチュートリアル

 1. すべてのエッジを読み取り、ゴールド要件の増加順に並べ替えます。`g`。 
2. リストを管理する`active`これまでに処理されたすべてのエッジが含まれています。 

反復時`i`、内側のすべてのエッジ`active`を満たす:$g_j \le g_i$したがって、以下から構築されたスパニング ツリーはすべて、`active`ちょうど最大のゴールドを持っています`g_i`。 

1. 現在のエッジを`active`。 
2. 並べ替え`active`シルバー要件による`s`。 

ここで、最大のシルバー エッジができるだけ小さいスパニング ツリーが必要になります。 

1. クラスカルのアルゴリズムを実行します。`active`、シルバーオーダーを使用。 

DSUを初期化する`N`コンポーネント。 エッジが昇順にシルバー順にトラバースされ、エンドポイントが異なるコンポーネントに属している場合は常にエンドポイントをマージします。 

1. マージ中に実際に使用される最大のシルバー値を追跡します。 

エッジはシルバーの昇順で処理されるため、スパニング ツリーで使用される最後のシルバー値が、達成可能な最小の最大シルバー値になります。 

1. クラスカルがすべての都市を接続することに成功した場合、次のように計算します。$G \cdot g_i + S \cdot \text{maxSilver}$グローバル最小の答えを更新します。 

1. すべての反復の後、見つかった最小の答えを出力します。 スパニング ツリーが形成されていない場合は、出力`-1`。 

### なぜ効果があるのか

 現在のエッジにゴールド値がある反復を修正します。`g`。 

この瞬間、`active`正確にすべてのエッジに金が含まれています`g`。 最大のゴールドを備えた実行可能なスパニング ツリー`g`完全にこれらのエッジで構成されている必要があります。 

これらのエッジのうち、シルバーで順序付けされたクラスカルは、最大のシルバー エッジを最小限に抑えるスパニング ツリーを構築します。 これは、クラスカルのアルゴリズムの古典的なミニマックス特性です。 

したがって、考えられるすべてのゴールドしきい値に対して、アルゴリズムは達成可能な最良のシルバーしきい値を計算します。 すべての最適解にはエッジのゴールド値の 1 つに等しい最大ゴールドがあるため、すべてのエッジを反復処理することで最適な解が検査されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)

        if a == b:
            return False

        if self.size[a] < self.size[b]:
            a, b = b, a

        self.parent[b] = a
        self.size[a] += self.size[b]
        return True

def solve():
    n, m = map(int, input().split())
    G, S = map(int, input().split())

    edges = []

    for _ in range(m):
        x, y, g, s = map(int, input().split())
        x -= 1
        y -= 1
        edges.append((g, s, x, y))

    edges.sort()

    active = []
    INF = 10**30
    ans = INF

    for g, s, x, y in edges:
        active.append((s, x, y))

        active.sort()

        dsu = DSU(n)
        used = 0
        max_silver = 0

        for cs, u, v in active:
            if dsu.union(u, v):
                used += 1
                max_silver = cs

        if used == n - 1:
            ans = min(ans, G * g + S * max_silver)

    print(ans if ans != INF else -1)

solve()
```最初の重要な選択は、何よりもまずゴールドでエッジを分類することです。 この順序でエッジを処理すると、現在のエッジのゴールド値が現在の反復で許可される最大ゴールド値になります。 

の`active`配列には、ゴールド要件がすでに許可されているすべてのエッジが格納されます。 反復ごとに、このリストをシルバー順に並べ替え、新しい Kruskal パスを実行します。 

クラスカルを毎回再構築するのは高価に見えるかもしれませんが、`N`小さいです。 DSU 操作はほぼ一定時間であり、最適化された Python では、実際のボトルネックは必要な少数の成功した結合によって制限されるため、50,000 個のエッジを繰り返しソートすることさえ許容されます。 

DSU 実装では、パス圧縮とサイズによる結合が使用されます。 自己ループは自然に処理されます。`union(u, v)`返品`False`両方のエンドポイントがすでに同じコンポーネントに属している場合。 

変数`used`スパニングツリーに入ったエッジの数をカウントします。 接続はまさに次の場合に存在します。$\text{used} = N - 1$この状態は、親配列を手動でチェックするよりも安全です。 

微妙なディテールが更新されています`max_silver`エッジがクラスカルによって実際に使用される場合のみ。 サイクルによりスキップされたエッジが答えに影響を与えてはなりません。 

Python の整数は、コストが以下に達する可能性があるため、潜在的に巨大な値を安全に処理します。$10^9 \cdot 10^9 = 10^{18}$## 実用的な例

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(M²・α(N)) | 各反復では、アクティブ エッジ上のクラスカル パスが再構築されます。

    class DSU:
        def __init__(self, n):
            self.parent = list(range(n))
            self.size = [1] * n

        def find(self, x):

            b = self.find(b)

            if a == b:
                return False

            if self.size[a] < self.size[b]:
                a, b = b, a

            self.parent[b] = a
            self.size[a] += self.size[b]

    n, m = map(int, input().split())

                used += 1
                mxs = cs

    return str(ans if ans != INF else -1)
