 ## 解決策
 ## 問題の理解

 私たちは、動的なグリッドの色付けプロセスを管理するように求められます。 グリッドには、$n$行と$m$列、最初はすべて白です。 整数が与えられます$k$そして一連の操作。 各操作は水平または垂直のいずれかです。 水平方向の操作により、連続した領域が描画されます。$1 \times k$白い長方形を黒に、垂直方向の操作では長方形をペイントします。$k \times 1$白い長方形の黒い。 

すべての操作の後、いずれかの行または列が完全に黒になると、その行または列のすべてのセルが白にリセットされます。 複数の行と列が同時にいっぱいになった場合、このリセットはカスケードされる可能性があります。 課題は、黒いセルを塗りつぶすことなくすべての操作が成功するように、各操作の座標を生成することです。 

主な詳細は次のとおりです。 まず、行または列をリセットした後、以前に黒く塗られたセルを再利用できるため、貪欲な塗りつぶし戦略が可能になります。 第二に、適切な環境が存在しない状況を避けなければなりません。$1 \times k$または$k \times 1$白い四角形が存在するため、タスクは不可能になります。 たとえば、次の場合$n = m = k = 2$また、リセット前に垂直操作を同じ列に 2 回適用する必要があり、リセットが発生しない限り 2 回目の操作は失敗します。 

この制約は、グリッド全体に対するブルート フォースの各操作は許容できるものの、最適ではないことを意味します。$n, m \le 100$そして$q \le 1000$、とてもナイーブです$O(n m q)$ソリューションは最大で実行されます$10^7$これは 2 秒未満の Python の境界線です。 したがって、四角形を決定論的に配置するための構造化された方法を探す必要があります。 

## アプローチ

 ブルートフォースアプローチは簡単です。完全な状態を維持します。$n \times m$グリッドを作成し、操作ごとに、必要な形状の可能なすべての長方形をスキャンして、すべての白いセルを持つ長方形を見つけます。 黒にペイントし、すべての行と列をスキャンして完全に黒の行と列をリセットします。 これが機能するのは、問題のルールを直接反映しているためです。 欠点は、グリッドを繰り返しスキャンするとコストがかかることです。 最悪の場合、各操作で最大のチェックが必要になります。$O(n m)$長方形。 

より高速なソリューションを実現する重要な観察は、リセットにより行と列を無期限に再利用できるということです。 これは、行に沿った水平長方形と列に沿った垂直長方形の一連の位置を事前計算できることを意味します。 たとえば、いつでも最初の領域に横長の長方形を配置できます。$k$まだ完全に使用されていない行の連続する白い列。 グリッドのリセットにより、行または列全体が黒になった後、白にリセットされることが保証されるため、競合が発生することなく位置を循環できます。 

これを認識すると、水平操作を行に沿って独立して処理し、垂直操作を列に沿って独立して処理できるようになります。 各行/列のポインタまたはインデックスを維持することで、次に利用可能な長さのセグメントを常に選択できます。$k$グリッド全体をスキャンせずに。 これにより、操作の選択が操作ごとに一定の時間に短縮されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(q * n * m) | O(n * m) | 動作しますが、最悪の場合は遅くなります。 
| 決定的な配置 | O(q) | O(1) (プラス O(q) 出力) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、グリッドの寸法を読み取ります。$n, m$、長方形のサイズ$k$、および操作文字列$s$。 水平操作の場合は行に沿って、垂直操作の場合は列に沿って、次に使用可能な位置のカウンターを初期化します。 これらのカウンターは、次の四角形がどこから開始できるかを追跡します。 
2. の各操作について$s$、水平か垂直かを判断します。 水平の場合は、次に使用可能な行を選択し、開始列を選択します。$1 \times k$長方形がフィットします。 列ポインタをインクリメントします。 それを超えた場合$m - k + 1$、次の行の最初の列にリセットします。 行が残っていない場合は出力$-1$それは不可能なので。 
3. 操作が垂直の場合は、列に沿って同様の手順を実行します。 次の列を選択し、開始行を選択します。$k \times 1$長方形がフィットします。 行ポインタをインクリメントします。 それを超えた場合$n - k + 1$、次の列に移動します。 列が残っていない場合は出力$-1$。 
4. 選択した四角形の左上の座標を出力します。 リセット プロパティにより、この決定論的な循環によって常に有効な位置が得られることが保証されるため、実際のグリッドのカラーリングをシミュレートする必要はありません。 

これが機能する理由は、すべての水平操作を一意の操作にマッピングできるためです。$k$- ある行のセグメントとすべての垂直操作を一意に実行$k$いくつかの列の -segment。 グリッドをリセットすると、以前に使用された行と列がリサイクルされるため、このスキームでは白いセルが不足することがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m, k, q = map(int, input().split())
        s = input().strip()

        # Pointers for horizontal and vertical placements
        h_row, h_col = 1, 1
        v_row, v_col = 1, 1

        result = []

        for op in s:
            if op == 'H':
                if h_row > n:
                    print(-1)
                    break
                result.append(f"{h_row} {h_col}")
                h_col += k
                if h_col > m:
                    h_row += 1
                    h_col = 1
            else:
                if v_col > m:
                    print(-1)
                    break
                result.append(f"{v_row} {v_col}")
                v_row += k
                if v_row > n:
                    v_col += 1
                    v_row = 1
        else:
            print('\n'.join(result))

if __name__ == "__main__":
    solve()
```の`h_row`そして`h_col`ポインタは次の水平方向の長方形を選択するために使用されます。 列の制限を超えると、次の行に移動します。 垂直ポインタは列に沿って同様に機能します。 の`else`ループの句により、すべての操作が成功した場合にのみ結果を出力することが保証されます。 リセットメカニズムにより順次配置が常に有効であることが保証されるため、実際のセル状態はシミュレートしません。 境界条件はチェックによって処理されます。`> n`または`> m`そして戻ってくる`-1`疲れ果てた場合。
