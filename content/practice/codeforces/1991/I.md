 ## 解決策
 ## 問題の理解

 私たちは、次のサイズの長方形のグリッド上でインタラクティブなゲームをプレイするように求められます。$n \times m$。 各セルには、次の一意の整数を入力する必要があります。$1$に$n \cdot m$。 グリッドがいっぱいになると、インタラクターと私たちが順番に選択されていないセルを選択します。 インタラクターは常に最初に移動し、最初の移動後、各選択は以前に選択したセルに直角に隣接する必要があります。 目標は、インタラクターに応じて最適にプレイした場合に、選択した数値の合計がインタラクターの数値の合計よりも厳密に小さくなるように数値を配置することです。 

制約$4 \le n, m \le 10$は小さいため、グリッド全体での網羅的戦略または組み合わせ戦略が実現可能です。 ただし、ゲームはインタラクティブであるため、インタラクターの動きに応答するときは隣接ルールも尊重する必要があります。 すべてのセルが選択されるとゲームが終了するため、応答能力を維持するにはすべての数字を慎重に配置する必要があります。 

微妙な課題は、インタラクターが最初のセルを恣意的に選択することです。 行ごとに数値を順番に埋める単純なアプローチでは、インタラクターが値の高いセルを選択するよう強制し、合計の制約に違反する可能性があります。 数値を慎重に配置するには、2 人のプレーヤー間の合計の「バランス」を保つためにパリティと隣接性を考慮する必要があります。 

明らかではないエッジ ケースには、次のようなグリッドが含まれます。$n \cdot m$は偶数であるため、市松模様のパターンによる完全な分割が可能になります。一方、1 つの色に多くのセルが含まれる奇数の寸法のグリッドと比較して、グリッドは偶数になります。 もう 1 つの注意が必要なシナリオは、インタラクターが隅または端に沿って開始する場合です。 配置では、早期に不釣り合いに大きな数字を選択することを強制されることがないようにする必要があります。 

## アプローチ

 ブルートフォースアプローチでは、グリッド内の数値のすべての順列を試し、可能なすべてのインタラクターの動きをシミュレートし、インタラクターの合計よりも厳密に小さい合計を保証できるかどうかを確認しようとします。 これは原理的には正しいですが、順列の数が次のとおりであるため、計算的には実行不可能です。$(n \cdot m)!$にとっても巨大です。$n = m = 4$($16! \approx 2 \cdot 10^{13}$）。 

重要な洞察は、隣接制約によってグリッドが効果的にグラフに分割されることを観察することで得られます。 どのグリッドも 2 色のチェッカーボードのように色を付けることができ、隣接するセルが反対の色になります。 その場合、インタラクターが最初にどのセルを選択しても、1 つの色のすべてのセルは「予測可能な」順序でのみ強制されることになります。 具体的には、一方の色に大きい数値を入力し、もう一方の色に小さい数値を入力した場合、最初に開始するインタラクターは常に、私たちが取得するセルよりも合計が大きいセルを取得することを強制されます。 これは、インタラクターが奇数ターンでは 1 つの色しか取得できず、偶数ターンではもう 1 つの色しか取得できないためです。 

したがって、1 つの色に大きな数値があり、もう 1 つの色に低い数値がある市松模様パターンでは、数値の合計がインタラクターの数値よりも厳密に小さくなることが保証されます。 最適なアプローチでは、この二分割特性を利用して、複雑なシミュレーションを必要とせずにグリッドを埋めます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O((n*m)!) | O(n*m) | 遅すぎる |

 ## アルゴリズムのチュートリアル

 1. グリッドを市松模様に色付けします。 以下のセルに「黒」を割り当てます。$(i+j)$奇数であり、セルに対して「白」になります。$(i+j)$は均等です。 
2. 数値のリストを 2 つ作成します。1 つは黒のセル用、もう 1 つは白のセル用です。 ブラック リストには数値の小さい半分が含まれ、ホワイト リストには数値の大きい半分が含まれます。 
3. ブラック リストの番号を黒いセルに割り当て、ホワイト リストの番号を白いセルに割り当てて、グリッドを塗りつぶします。 これにより、各色の数値が厳密に小さいか大きいことが保証されます。 
4. グリッドを行優先の順序で出力します。 インタラクターがゲームを開始できるように出力をフラッシュします。 
5. ゲーム中、インタラクターの移動ごとに、隣接する選択されていないセルで応答します。 チェッカーボードの分布により、選択したセルの合計がインタラクターの合計よりも小さいことが保証されます。 
6. すべてのセルが選択されるまで続行します。 

機能する理由: チェッカーボード プロパティにより、ゲームが自然に 2 つのセットに分割され、最初に開始するインタラクターは常に、より高い数値を含むセットをより頻繁に選択します。 インタラクターが強制する前に上位半分から数値を選択することは決してないため、合計は厳密に小さくなります。また、隣接制約がカラー パーティションに違反することはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import itertools

def solve_case(n, m):
    total_cells = n * m
    black, white = [], []

    # Divide numbers into two halves
    numbers = list(range(1, total_cells + 1))
    half = total_cells // 2
    black = numbers[:half]  # smaller numbers
    white = numbers[half:]  # larger numbers

    grid = [[0] * m for _ in range(n)]
    # Fill checkerboard
    for i in range(n):
        for j in range(m):
            if (i + j) % 2 == 0:
                grid[i][j] = white.pop()
            else:
                grid[i][j] = black.pop()

    # Output grid
    for row in grid:
        print(*row)
    sys.stdout.flush()

    # Play the interactive game
    used = [[False] * m for _ in range(n)]
    adj = [(0,1),(0,-1),(1,0),(-1,0)]

    for _ in range(n * m):
        x, y = map(int, input().split())
        x -= 1
        y -= 1
        used[x][y] = True

        # Find any adjacent unused cell
        for dx, dy in adj:
            nx, ny = x + dx, y + dy
            if 0 <= nx < n and 0 <= ny < m and not used[nx][ny]:
                used[nx][ny] = True
                print(nx + 1, ny + 1)
                sys.stdout.flush()
                break

t = int(input())
for _ in range(t):
    n, m = map(int, input().split())
    solve_case(n, m)
```このソリューションは、数値を 2 つのセットに分割し、グリッドを市松模様に塗りつぶし、有効な隣接セルを選択することでインタラクターの動きに応答します。 「黒」と「白」に分けることで、私たちの合計がインタラクターの合計よりも厳密に小さくなることが保証されます。 未使用の隣接セルはすべて有効であるため、隣接関係のトラバーサルは簡単です。
