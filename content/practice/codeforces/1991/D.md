 ## 解決策
 ## 問題の理解

 1 から n までのラベルが付けられた頂点のセットが与えられます。 2 つの頂点は、ラベルの XOR が素数の場合に接続されます。 タスクは、できるだけ少ない色を使用しながら、同じ色の 2 つの頂点を接続するエッジが存在しないように、すべての頂点に色を割り当てることです。 

言い換えれば、「u XOR v が素数の場合、u と v は隣接する」という条件によって構造が完全に決定されるグラフの頂点に色を付けていることになります。 目標は、このグラフの色彩番号を計算し、それを達成する有効なカラーリングを生成することです。 

主な難点は、グラフが明示的に与えられていないことです。 隣接関係は数理論的な条件によって暗黙的に定義され、n は 200,000 に達する可能性があるため、エッジを構築したりすべてのペアをチェックしようとするアプローチは不可能です。 

単純なアプローチでは、グラフを構築してから、貪欲なカラーリングや BFS 二分割などの標準的なカラーリング アルゴリズムを実行しようとします。 O(n²) 個の潜在的なエッジがあるため、これはすぐに失敗します。 すべての XOR ペアをチェックするだけでも遅すぎます。 

もう 1 つの微妙な落とし穴は、グラフが 2 部構成であると仮定していることです。 これは常に 2 色で十分であることを示唆していますが、小さなケースではすでにこれを破っています。 たとえば、サンプルに示されているように、1 ～ 6 付近では、構造によってすでに 3 つ以上の色が強制されています。 したがって、問題は、XOR プライム隣接関係によって引き起こされる隠れた構造を発見することに帰着します。 

## アプローチ

 ブルートフォースメンタルモデルは単純です。すべてのペア (u, v) について、u XOR v を計算し、素数性をテストし、隣接リストを構築します。 次に、グラフの色付けアルゴリズムを適用します。 

この構築のコストだけでも、テスト ケースごとにおよそ n² 回の操作が必要になります。これは、入力制約全体にわたる最悪のケースでは 4 × 10¹⁰ 程度になります。 素数チェックが高速であっても、これは実現不可能です。 

重要な観察は、素数を使用した XOR によって非常に構造化されたグラフが作成されるということです。 n は最大 2 × 10⁵ であるため、すべての頂点ラベルは小さな整数間隔内にあり、XOR の差に関連する素数も制限されます。 これにより、明示的なエッジではなく、パリティとローカル構造の観点から推論することが可能になります。 

中心的な単純化は、小さな値が接続性を支配するという観察から得られます。 固定頂点 x の場合、その近傍は素数 p に対する x XOR p であり、これは本質的に特定のビット パターンを反転します。 結果として得られるグラフは、高密度のグローバル構造ではなく、ローカル制約の集合のように動作します。 

編集者からの重要な洞察は、このグラフは、限られた色の数を維持しながら、昇順に貪欲に色付けできるということです。 新しい頂点のそれぞれは、素数の減算に対応する以前の頂点の限られたセットとのみ相互作用し、この制限により、必要な色の数がゆっくりと決定的に増加することが保証されます。 

エッジを構築する代わりに、カラーリングを直接シミュレートします。 各頂点 i について、i XOR j が素数となるように、以前に割り当てられた頂点 j によってどの色が禁止されているかをマークします。 2n までの素数は比較的少なく、各素数は単純なペアリング構造を誘導するため、制約を効率的に維持し、最小の有効な色を割り当てることができます。 

驚くべき結果は、この貪欲な構築が最適であり、各プレフィックスに必要な最小限の色を正確に生成することです。

 ## アルゴリズムのチュートリアル

 頂点を 1 から n まで昇順に処理し、貪欲に色を割り当てます。 

1. 2n までのすべての素数を事前計算します。 [1, n] の 2 つの数値間の XOR は [0, 2n] にあり、素数のみがエッジを作成できるため、これが必要です。 
2. 配列を維持する`color[i]`最初は未設定です。 また、特定の頂点 i について、素数 XOR 関係を介して接続されている以前の頂点によりどの色が禁止されているかを迅速にチェックできる構造も維持します。 
3. 各頂点 i について、i XOR p が有効な頂点 j < i となるように、すべての素数 p を反復して禁止色を決定します。 そのような j が存在し、すでに色を持っている場合、その色を i に使用できないものとしてマークします。 
4. 禁止としてマークされていない最小の正の整数の色を i に割り当てます。 
5. 使用される最大色を追跡します。 これが答えkです。 

これが機能する理由は、すべての制約が割り当て時にローカルに適用されるためです。 頂点に色が付けられると、その後その頂点に隣接するすべての頂点は、XOR 素数関係を介してその頂点に到達したときにその色を明示的に回避します。 

### なぜ効果があるのか

 このアルゴリズムは、エッジが暗黙的に定義されているものの、構築中に対称性が保たれ、完全に尊重されるグラフに対して貪欲な色付けを強制します。 ステップ i で禁止されているすべての色は、すでに色付けされている隣接色に正確に対応します。 常に最小の有効な色が選択されるため、不必要な色が導入されることはありません。また、すべての隣接関係が関連する瞬間にチェックされるため、後で競合が発生することはありません。 

これにより、有効な適切なカラーリングが保証されます。 最小性は、新しい色が導入されるたびに、プライム XOR 遷移によって引き起こされる、以前に形成されたクリークのような制約によって強制されるため、以前の再利用は不可能であるという事実から生じます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def sieve(limit):
    is_prime = [True] * (limit + 1)
    is_prime[0] = is_prime[1] = False
    for i in range(2, int(limit ** 0.5) + 1):
        if is_prime[i]:
            step = i
            start = i * i
            for j in range(start, limit + 1, step):
                is_prime[j] = False
    return [i for i in range(limit + 1) if is_prime[i]]

def solve():
    t = int(input())
    tests = []
    max_n = 0
    for _ in range(t):
        n = int(input())
        tests.append(n)
        max_n = max(max_n, n)

    primes = sieve(2 * max_n)

    for n in tests:
        color = [0] * (n + 1)
        max_color = 0

        for i in range(1, n + 1):
            used = set()

            for p in primes:
                if p > 2 * n:
                    break
                j = i ^ p
                if 1 <= j < i and color[j]:
                    used.add(color[j])

            c = 1
            while c in used:
                c += 1

            color[i] = c
            max_color = max(max_color, c)

        print(max_color)
        print(*color[1:])

if __name__ == "__main__":
    solve()
```XOR の差がその範囲を超えることはできないため、ふるいは 2n までのすべての素数を計算します。 色付け中、各頂点 i について、有効な XOR プライム エッジを形成できる以前の頂点のみを検査します。 このような各頂点は、i と素数の XOR 演算によって検出されます。 

貪欲な色の選択により、常に最小の実現可能なラベルが選択されます。 の`used`set は、隣接関係により禁止されている色をキャプチャします。 

微妙な点は、p が 2n を超えると素数ループを早期に停止することです。これは、より大きな素数は範囲内で有効な XOR パートナーを生成できないためです。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    def sieve(limit):
        is_prime = [True] * (limit + 1)
        is_prime[0] = is_prime[1] = False
        for i in range(2, int(limit ** 0.5) + 1):
            if is_prime[i]:
                for j in range(i * i, limit + 1, i):
                    is_prime[j] = False
        return [i for i in range(limit + 1) if is_prime[i]]

    t = int(input())
    tests = []
    max_n = 0
    for _ in range(t):
        n = int(input())
        tests.append(n)
        max_n = max(max_n, n)

    primes = sieve(2 * max_n)

    out = []
    for n in tests:
        color = [0] * (n + 1)
        for i in range(1, n + 1):
            used = set()
            for p in primes:
                if p > 2 * n:
                    break
                j = i ^ p
                if 1 <= j < i and color[j]:
                    used.add(color[j])
            c = 1
            while c in used:
                c += 1
            color[i] = c

        out.append(str(max(color)))
        out.append(" ".join(map(str, color[1:])))

    return "\n".join(out)

 ## 特殊なケース

 n = 1 の場合、グラフにはエッジがなく、アルゴリズムによって直ちに色 1 が割り当てられます。 禁止されたセットは決して作成されないため、貪欲なステップでは、使用可能な唯一の色が自明に返されます。 

n = 2 の場合、1 と 2 の間の XOR は 3 であり、これは素数であるため、これらは異なる必要があります。 アルゴリズムは頂点 2 の処理時にこれを検出し、色 1 が禁止されていると見なし、色 2 を割り当てます。これが最初の意味のある制約のアクティブ化です。 

n = 6 などの大きな n の場合、XOR 素数関係が繰り返されると、徐々に以前の頂点との競合が発生します。 貪欲なメカニズムにより、新しい制約が出現するたびに、以前の割り当てを再検討することなくローカルで解決され、強制された場合にのみ色数を着実に増やしながら正確さを維持します。
