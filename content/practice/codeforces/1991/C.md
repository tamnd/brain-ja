 ## 解決策
 ## 問題の理解

 負ではない整数の配列が与えられ、1 回の操作で任意の数値を選択できます。$x$すべての要素を置き換えます$a_i$との絶対的な違い$x$、$|a_i - x|$。 私たちのタスクは、最大 40 回のそのような操作で配列をすべて 0 に変換するか、それが不可能であると報告することです。 入力は複数のテスト ケースで構成され、それぞれに配列があり、出力は一連の数値である必要があります。$x$操作のために選択するか、実行できない場合は -1 を選択します。 

重要な制約は配列サイズです$n$まで$2 \cdot 10^5$と合計$n$すべてのテスト ケースにわたって、次の制限も受けられます$2 \cdot 10^5$。 これは、テスト ケースごとの複雑さが線形または線形に近い複雑さを持つソリューションはタイムアウトになる可能性が高いことを意味します。 操作数 40 という制限は十分に大きいため、操作数を最小限に抑える必要はありませんが、単純な総当たりで可能な限りすべての操作を試してしまうほど厳しいです。$x$値を組み合わせて使用​​することは現実的ではありません。 

微妙なエッジ ケースは、配列がすでにすべて 0 である場合です。 不用意なソリューションでは不要な操作を実行しようとする可能性がありますが、正しい出力は操作がゼロであるはずです。 もう 1 つの厄介な状況は、配列に互いの 2 の倍数ではない要素が含まれている場合に発生します。その場合、指定された演算ですべての要素をゼロに減らすことが不可能になる可能性があります。 たとえば、配列$[1,2,3,4,5]$すべての値を同時に折りたためるほど差が対称的に整列することはないため、40 回の操作で をゼロに減らすことはできません。 

## アプローチ

 ブルートフォースアプローチでは、考えられるすべての選択肢が考慮されます。$x$各ステップで、配列がすべて 0 になるまで演算を繰り返し適用します。 各操作は各要素を次のように変換します。$|a_i - x|$、0 から最大要素までのすべての可能な整数を試してみると、シーケンスの数は指数関数的に増加します。 これは理論的には正しいですが、実行不可能です。$n$到達できる$2 \cdot 10^5$および最大値$10^9$徹底的な検索を不可能にします。 

効率的な解決策につながる洞察は、演算によって最大公約数 (GCD) を法とした要素間の一連の差異が保存されることを観察することで得られます。 私たちが選ぶなら$x$最大要素として、最大の要素はゼロになり、新しい配列は前の最大値とすべての要素の差で構成されます。 このプロセスを繰り返し繰り返すことで、問題は差分の GCD の計算に減ります。 配列が縮小可能な場合、このアプローチでは、最大でも$2 \log_2(\text{max element})$操作を実行すると、すべての要素がゼロに折りたたまれます。 

したがって、戦略は貪欲です。現在の最大要素を繰り返し選択します。$x$これにより、それがゼロに減らされ、配列がその最大値との差に置き換えられます。 各反復の後、最大値は減少し、最終的にはすべての要素がゼロになるか、差分の GCD の均一な配列になります。 いずれかの時点で、配列に現在の GCD の倍数ではない複数の個別の非ゼロ値が含まれている場合、それは不可能であると宣言します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(10^9 · n · 演算) | O(n) | 遅すぎる |
 | GCD で貪欲 | O(n · log(max a_i)) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取ります。 テスト ケースごとに、整数の配列を読み取ります。 
2. すべての要素がすでにゼロである場合は、直ちにゼロ操作を出力します。 これにより、些細なケースが効率的に処理されます。 
3. 個別の非ゼロ要素のセットを計算します。 一意のゼロ以外の要素が 1 つだけある場合は、その要素を次のように選択します。$x$そして 1 つの操作を実行して配列をゼロにします。 
4. それ以外の場合は、繰り返し選択します$x$現在の配列の最大要素として。 各要素を置き換えます$a_i$と$|a_i - x|$。 選択したシーケンスを記録します$x$価値観。 
5. 各操作の後、すべての要素がゼロになったかどうかを確認します。 「はい」の場合、シーケンスを出力して停止します。 
6. 40 回の演算後も配列にゼロ以外の要素が含まれている場合は、-1 を出力します。 
7. 常に制限 40 を超えないよう、オペレーションのカウンターを維持します。 

これが機能する理由は、各ステップで最大の要素を選択することで少なくとも 1 つの配列要素がゼロになることが保証され、絶対差分演算により差分のセットが時間の経過とともに確実に縮小するためです。 一連の操作により、すべての要素が徐々にゼロに揃えられ、解決策が存在する場合、問題構造により収束が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        if all(x == 0 for x in a):
            print(0)
            continue
        
        operations = []
        # Greedy approach: max element reduction
        for _ in range(40):
            if all(x == 0 for x in a):
                break
            x = max(a)
            operations.append(x)
            a = [abs(ai - x) for ai in a]
        
        if all(x == 0 for x in a):
            print(len(operations))
            print(" ".join(map(str, operations)))
        else:
            print(-1)

if __name__ == "__main__":
    solve()
```この解決策は、配列がすでにゼロであるかどうかを確認することから始まります。 次に、最大の要素を選択し、各配列要素をその最大値からの絶対差で置き換え、操作を記録することにより、最大 40 の貪欲な操作を実行します。 各ステップの後に、配列がすべて 0 になっているかどうかがチェックされます。 そうであれば、操作を出力します。 それ以外の場合は、-1 を出力します。 

微妙な選択には、各操作後のゼロ条件のチェック、操作を 40 回に制限する、絶対差を一貫して使用するなどがあります。 Python の組み込み機能の使用`max`これにより、常に最大の要素が効率的に選択されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n * 40) ≈ O(n) | 各操作では配列をスキャンして最大値を見つけ、絶対差を最大 40 回計算します。 |
 | スペース | O(n + 40) ≈ O(n) | 配列と操作のシーケンスを保存します。 |
