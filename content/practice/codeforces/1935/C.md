 ## 解決策
 ## 問題の理解

 それぞれ 2 つの特徴を持つ一連のメッセージが与えられます。`a_i`、メッセージの基本読み取り時間、および`b_i`、連続するメッセージ間の遷移コストに影響を与える座標。 メッセージのサブセットを読み取るのにかかる合計時間は、`a_i`値に絶対差の合計を加えたもの`b_i`選択した順序で連続するメッセージ間の値を取得します。 目標は、与えられた許容読書時間の合計です。`l`を超えずに読み取ることができるメッセージの最大数を確認します。`l`。 セットが空の場合もあり、その場合の読み取り時間は`0`。 

制約は非常に重要です。 各テスト ケースには、`n`2000までですが、合計額は`n^2`すべてのテスト ケースの数は 400 万に制限されています。 これは、最悪の場合の複雑さのアルゴリズムをおおよそ許容できることを示唆しています`O(n^2)`テストケースごと、でも何でも`O(n^3)`さらに悪い場合はタイムアウトになる可能性があります。 制限時間は 3 秒で、効率的に実装すれば 2 次解と一致します。 

エッジケースはすべての場合に発生します`a_i`値がより大きい`l`、したがって、答えはゼロでなければなりません、またはすべての場合`b_i`値が同一であるため、移行コストはゼロになります。 素朴で貪欲なアプローチで最小のメッセージを選択する`a_i`メッセージ間の移行コストが高くなると合計を超える可能性があるため、失敗する可能性があります`l`。 

## アプローチ

 ブルートフォース手法では、メッセージのすべてのサブセットとそれらのサブセットのすべての順列を列挙して、読み取り時間を計算します。 各サブセットについて、合計します。`a_i`そしてペアごとに`|b_i - b_j|`トランジション。 順列の数はサブセットのサイズに応じて階乗的に増加するため、これは明らかに実行不可能です。 サブセットだけでも`2^n`、これは大きすぎます`n = 2000`。 

重要な洞察は、問題を恣意的な順列を考慮しない形式に縮小することです。 メッセージを並べ替える`b_i`のシーケンスを考慮できるようになります`b_i`順序、絶対差の合計なので`|b_i - b_{i+1}|`番号がソート順に連続している場合、最小化されます。 ソート後、この順序でサブシーケンスに焦点を当てることができ、問題を動的プログラミングまたはスライディング ウィンドウ問題に変換し、そこで累積します。`a_i`価値と移行コストを効率的に実現します。 

最適なアプローチでは、シーケンスの潜在的な開始点として各メッセージを反復し、シーケンスを右に拡張します。`b_i`累積読書時間を追跡しながら順序付けします。 合計時間を超えた場合`l`、延長を停止し、長さを記録します。 これは次のように実装できます。`O(n^2)`テスト ケースごとに、制約の下で許容されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n! * n) | O(n) | 遅すぎる |
 | ソート + スライド/DP | O(n^2) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る`t`。 
2. 各テスト ケースについて、次の内容を読んでください。`n`そして`l`次に、メッセージのリストをペアとして読み取ります`(a_i, b_i)`。 
3. メッセージをメッセージ順に並べ替えます`b_i`価値。 これにより、この順序で連続するメッセージのサブシーケンスの移行コストが最小限に抑えられます。 
4.初期化`max_size`ゼロに。 これには、制限時間を満たす中で見つかった最大のサブセットが保持されます。 
5. 考えられる各開始メッセージ インデックスを反復処理します。`i`。 セット`total_time`に`a[i]`そして`current_size`1に。 
6. シーケンスをインデックスから右に拡張します。`i+1`に`n-1`。 新しいメッセージごとに`j`、 追加`a[j]`プラス`|b[j] - b[j-1]|`に`total_time`。 もし`total_time`を超える`l`、延長をやめてください。 それ以外の場合は増分します`current_size`。 
7.アップデート`max_size`もし`current_size`以前の最大値を超えています。 
8. すべての開始点を確認したら、出力します。`max_size`。 

機能する理由: 並べ替え`b_i`メッセージを順序どおりに挿入しても差の絶対値の合計が増加するだけであるため、連続するサブシーケンスの移行コストが最小限になることが保証されます。 各開始インデックスからシーケンスを拡張すると、すべての連続したサブシーケンスが確実に考慮されます。`max_size`実行可能な最大のシーケンスを正確に追跡します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, l = map(int, input().split())
        messages = [tuple(map(int, input().split())) for _ in range(n)]
        messages.sort(key=lambda x: x[1])
        max_size = 0
        
        for i in range(n):
            total_time = messages[i][0]
            if total_time > l:
                continue
            current_size = 1
            for j in range(i + 1, n):
                total_time += messages[j][0] + abs(messages[j][1] - messages[j-1][1])
                if total_time > l:
                    break
                current_size += 1
            max_size = max(max_size, current_size)
        
        print(max_size)

if __name__ == "__main__":
    solve()
```コードは、入力を効率的に読み取り、メッセージを並べ替えることから始まります。 並べ替えることにより、移行コストが最小限に抑えられます。 ネストされたループは、各開始メッセージを連続シーケンスに拡張します。`break`制限時間を超えた場合の不要な計算を防ぎます。 エッジケースなど`total_time > l`開始時に、実行不可能なシーケンスをスキップするために即座に処理されます。

```インデックス 0 から始めることを検討してください。 

| インデックス | あ_い | b_i | 合計時間 | 現在のサイズ |
 | --- | --- | --- | --- | --- |
 | 0 | 4 | 3 | 4 | 1 |

 この開始からの最大サイズは 2 です。他の開始から同様に計算すると、最終的な最大サイズは 3 になります。 

このトレースは、ソート方法を示しています。`b_i`そして蓄積する`a_i + |b_i - b_{i-1}|`実現可能なシーケンスを効率的にチェックできます。
