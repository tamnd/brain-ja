 ## 解決策
 ## 問題の理解

 一連のコースが与えられますが、各コースには固定値ではなく、可能なグレードの範囲があります。 もちろん$i$、任意の整数を選択できます$c_i$から$[x_i, y_i]$。 各学生には連続したコースのブロックが割り当てられ、最終スコアはそのブロック全体で選択された値のビットごとの OR になります。 

各クエリについて、選択されたすべての値の OR が最大化されるように、クエリ間隔内のコースごとに 1 つの有効な値を選択するように求められます。 

主な難点は、選択肢がコースごとに独立しているのに、目的が OR 演算によってそれらを結合することです。 これにより緊張が生じます。各コースは、潜在的に達成可能なビットのセットに貢献し、最終的な答えは、セグメント内の任意の場所でどのビットを少なくとも 1 回アクティブにできるかによって決まります。 

この制約は、コースとクエリの数の合計が次のようになることを意味します。$2 \cdot 10^5$したがって、テストケースごとに二次関数に近い解は不可能です。 平$O(n \sqrt{n})$最悪の場合は遅すぎるでしょう。 この構造は、各コースを前処理してコンパクトな表現にしてから、高速集計をサポートするデータ構造で範囲クエリに応答することを強く示唆しています。 

単純なアプローチでは、クエリごとに範囲内のすべてのコースを試し、最適な OR を直接再計算します。 それはすでにリスクがある$O(nq)$、大きすぎます。 コースごとの回答を事前計算しようとしても、高速な範囲集計をサポートする構造がなければ、範囲間の相互作用により直接の再利用が妨げられます。 

微妙なエッジケースは、間隔が大きいものの「ほぼ満杯」である場合に現れます。たとえば、$x_i = 0$、$y_i = 2^{30}-1$。 区間内のビットが独立していると仮定する素朴なビットごとのチェックでは、各ビットが実際に区間内のどこかに現れるかどうかを検証せずに、すべてのビットが常に達成可能であると誤って想定してしまいます。 

## アプローチ

 ブルート フォース戦略は、各クエリを個別に処理することから始まります。 特定のセグメントについて$[l, r]$、各コースに可能な限り最適な値を決定し、すべてを OR で計算します。 コースは独立しているため、コースごとに、その間隔で値を選択することでどのビットをアクティブにできるかを知る必要があるだけです。 これをコースごとに計算したら、クエリ範囲内のすべての貢献度の OR を計算します。 

ボトルネックは、各クエリが依然として最大で反復処理を必要とすることです。$O(n)$コースごとに最大 30 ビット、または完全なインターバル構造をスキャンします。 これは次のことにつながります$O(nq)$、それは限界をはるかに超えています。 

重要な観察は、各コースを、その区間でどのビットが達成可能であるかを記述する単一の 30 ビット マスクに圧縮できることです。 これを取得すると、各クエリは整数の配列に対する範囲 OR クエリになります。 

残りの問題は、間隔ごとの計算です。$[x_i, y_i]$、どのビットがその中の少なくとも 1 つの数値に現れる可能性があります。 これは古典的な「ビットが間隔内に現れる」問題であり、各ビットは整数に対して周期的に動作します。 この前処理が完了すると、最終的な構造は静的範囲 OR クエリになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(nq)$|$O(1)$| 遅すぎる |
 | 事前計算 + セグメント ツリー |$O((n+q)\log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 ### ステップ 1: 各コースをビットマスクに圧縮する

 各コースインターバルごとに$[x_i, y_i]$、マスクを計算します。$b$ビットのある区間に何らかの数値が存在する場合に設定されます$b$これにより、各間隔が固定の 30 ビット整数に変換されます。 

### ステップ 2: ビットが間隔内に出現できるかどうかを判断する

 固定ビットの場合$b$、このビットが 1 である数字は、ピリオド付きの繰り返しパターンに従います。$2^{b+1}$。 各期とも前半は少しずつ$b = 0$、後半は少しあります$b = 1$。 

ビットかどうかを決定するには$b$で達成可能です$[x, y]$、間隔がそのビット パターンの「ゼロ領域」内に完全に含まれているかどうかを確認します。 存在する場合、ビットは決して表示されません。 それ以外の場合は、間隔内の何らかの数値によってアクティブ化されます。 

これにより、モジュラー演算を使用して各ビットのチェックが一定時間に短縮されます。 

### ステップ 3: コース マスクの配列を構築する

 配列を計算します`val[i]`、各エントリは当然のことながら達成可能なビットの OR マスクです。$i$。 

### ステップ 4: 範囲 OR 構造を構築する

 次に、次の形式のクエリに答える必要があります。 OR を計算します。`val[l..r]`。 これは標準的な静的範囲クエリの問題です。 セグメントツリーを構築します`val`。 

### ステップ 5: 質問に答える

 各クエリは、セグメント ツリーにクエリを実行することによって回答されます。$[l, r]$、その範囲内のすべてのマスクの OR を返します。 

### なぜ効果があるのか

 各コースは、その間隔内で独立して実現できるビットのセットを正確に提供します。 コースの選択は独立しているため、これらのビットのサブセットを異なるコース間で同時にアクティブにする値を常に選択できます。 OR 演算は単調であるため、セグメント全体でコースごとに達成可能なすべてのビットを組み合わせることで最適な答えが得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.size = 1
        while self.size < self.n:
            self.size *= 2
        self.seg = [0] * (2 * self.size)
        for i in range(self.n):
            self.seg[self.size + i] = arr[i]
        for i in range(self.size - 1, 0, -1):
            self.seg[i] = self.seg[2 * i] | self.seg[2 * i + 1]

    def query(self, l, r):
        l += self.size
        r += self.size
        res = 0
        while l <= r:
            if l % 2 == 1:
                res |= self.seg[l]
                l += 1
            if r % 2 == 0:
                res |= self.seg[r]
                r -= 1
            l //= 2
            r //= 2
        return res

def build_mask(x, y):
    mask = 0
    for b in range(30):
        period = 1 << (b + 1)
        half = 1 << b

        def in_zero_region(v):
            pos = v % period
            return pos < half

        if in_zero_region(x) and in_zero_region(y) and (x // period == y // period):
            continue

        mask |= (1 << b)

    return mask

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        arr = []
        for _ in range(n):
            x, y = map(int, input().split())
            arr.append(build_mask(x, y))

        seg = SegTree(arr)

        q = int(input())
        out = []
        for _ in range(q):
            l, r = map(int, input().split())
            out.append(str(seg.query(l - 1, r - 1)))

        print(" ".join(out))

if __name__ == "__main__":
    solve()
```実装の中核は、各間隔をビットマスクに変換することです。 セグメント ツリーは、これらのマスクに対する単純な OR アグリゲータになります。 唯一のデリケートな部分は、ビットごとの周期的な推論です。 それ以外はすべて標準的な範囲クエリ機構です。 

クエリは 1 ベースですが、セグメント ツリーは 0 ベースのインデックスを使用するため、インデックスの処理は重要です。

 ## 特殊なケース

 みたいなコース$[0, 0]$マスクを強制的にゼロに設定します。これは、どの OR にも何も寄与しないことを意味します。 すべてのビットが「間隔内に存在する」チェックに失敗するため、アルゴリズムはすべてゼロのマスクを正しく生成します。 

みたいな広い間隔$[0, 2^{30}-1]$すべてのビットが間隔内のどこかに現れるため、マスク内のすべてのビットを設定します。 定期的なチェックにより、誤って除外されたビットがないことが保証されます。 

単一の要素にまたがるクエリはその要素のマスクを返すだけで、セグメント ツリーは直接検索に還元され、境界での正確性が維持されます。
