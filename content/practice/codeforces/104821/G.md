 ## 解決策
 ## 問題の理解

 私たちは宝石のコレクションを与えられており、それぞれに価格と美しさの価値があります。 私たちは一定の金額から始めて、最終的に完成した宝石の総合的な美しさを最大限に高めたいと考えています。 おもしろいのは、お金を使う前に、次のものを手に入れることができるということです。$k$宝石は無料で提供されます。つまり、宝石は美しさに貢献しますが、予算は減りません。 この無料枠を使用した後、選択した残りの宝石は予算内で購入する必要があります。$W$。 

決定は、どの宝石を採用するかだけでなく、どのサブセットを無料か有料として割り当てるかによって決まります。 無料で採取された宝石は、依然として次のいずれかを占めています。$k$スロットがあるため、高価なアイテムに無料枠を使用すると、予算が節約され、他の購入に振り向けられるため、有益である可能性があります。 

入力サイズは二次方程式または$n \log n$スタイルの動的プログラミング ソリューション。 と$n \le 5000$そして$W \le 10000$、予算に応じて寸法が決められた標準的なナップザックは実現可能ですが、自由選択の寸法が追加されるため、単純な 1D ナップザックがすべての状態を捉えることができなくなります。 無料アイテムのすべてのサブセットまたはすべての割り当てを試行する単純なアプローチでは、指数関数的に増加し、すぐには実行不可能になります。 

貪欲な直感による微妙な失敗例は、美品が高価な場合に現れます。 単純な戦略では、$k$最も美しいアイテムは無料ですが、すでに安く購入する価値があるアイテムや、まったく選択する価値のないアイテムの無料スロットが無駄になる可能性があります。 

たとえば、次の場合$k = 1$、アイテムがあります:```
(10 cost, 100 beauty), (1 cost, 90 beauty), (1 cost, 1 beauty)
```欲張って100点の美容アイテムを無料で手に入れることもできますが、予算が厳しい場合は、よりトータルな美しさを生み出す他の組み合わせを買う余裕はありません。 最適な戦略では、予算構成に応じて、代わりに高価なアイテムを購入し、空きスロットを安価だがまだ有用なアイテムに使用する可能性があります。 予算の決定と自由な割り当てとの間のこの結びつきが、問題を自明ではないものにしています。 

## アプローチ

 ブルート フォース ビューでは、項目のサブセットごとにどの項目を取得するかを決定し、最大で次の値を割り当てます。$k$それらは無料です。 サブセットごとに、有料アイテムの合計コストを計算し、それが範囲内に収まるかどうかを確認します。$W$トータルな美しさを最大限に引き出しながら。 これは大まかに調べます$2^n$各サブセット内の空きアイテムの最適な割り当てを計算しても、指数関数的な爆発は減少しません。 と$n = 5000$、これは不可能です。 

重要な観察は、自由選択がナップザック構造と局所的に相互作用するということです。 無料の項目をグローバルに最初または最後に決定する代わりに、自由な選択肢を動的プログラミング状態に直接組み込むことができます。 その秘訣は、これまでに使用された無料アイテムの数を追跡するディメンションを 1 つ追加することで、古典的なナップザック DP を拡張することです。 

アイテム、予算、使用されるフリーピックの数に基づいて DP を定義します。 各アイテムは無視されるか、（割り当てが残っている場合）無料で取得されるか、コストを支払って取得されます。 これにより、組み合わせ割り当て問題が階層化されたナップザックに変換され、各階層は使用された無料アイテムの数に対応します。 

これが機能するのは、問題によって導入された唯一の結合が限界であるためです。$k$そしてその制約は純粋にカーディナリティベースであり、重みや値には依存しません。 そのため、より複雑な構造を必要とするのではなく、追加の DP 次元に適しています。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(2^n \cdot n)$|$O(n)$| 遅すぎる |
 | 3D DP（アイテム×予算×フリーカウント） |$O(n \cdot W \cdot k)$|$O(W \cdot k)$| 承認済み |

 ## アルゴリズムのチュートリアル

 アイテムのプレフィックスを考慮し、一定の金額を費やし、一定数の空きスロットを使用した後に、各状態が達成可能な最高の美しさを表す動的プログラミング テーブルを構築します。 

1. DP 配列を初期化します。$dp[w][f]$総支払コストで達成可能な最大の美しさを表します$w$そしてまさに$f$無料アイテムを使用しました。 すべての状態は無効として開始されます。$dp[0][0] = 0$。 これは何も選択しないことに相当します。 
2. 宝石を一つ一つ加工します。 項目ごとに新しい DP レイヤーを作成し、同じ反復で後で必要になる状態が遷移によって上書きされないようにします。 
3. 現在の状態ごとに$(w, f)$、3つの可能性を考えます。 まず、状態を変更せずに項目をスキップします。 これにより、以前のすべての選択が保存されます。 
4. 次に、空きスロットがまだ残っているかどうか ($f < k$)、アイテムを無料で受け取り、に移行します。$(w, f+1)$その美しさを加えながら。 これは、お金の代わりに無料のスロットを使えるという考えを表しています。 
5. 第三に、余裕があれば ($w + w_i \le W$)、アイテムを購入し、に移行します$(w + w_i, f)$そしてその美しさを加えます。 これは標準的なナップザックの動作を表します。 
6. すべての項目を処理した後、すべての状態をスキャンします。$w \le W$そして$f \le k$美しさを最大限に引き出す。 

次元を圧縮するのではなく完全な 2D DP を使用する理由は、無料のアイテムと有料のコストは独立して進化し、状態の無効な混合を避けるために両方を追跡する必要があるためです。 

### なぜ効果があるのか

 アイテム処理のどの時点でも、各 DP 状態は、有料選択と無料選択を正確に区別して、処理済みアイテムの有効なサブセットをエンコードします。 各移行では実現可能性が維持されます。支払いは予算の制約を尊重し、自由な選択は制限を尊重します。$k$。 すべてのアイテムは 1 回だけ考慮され、3 つの相互に排他的な役割の 1 つが割り当てられるため、アイテムのすべての有効な構成は 1 つの DP パスに正確に対応します。 構成と DP 状態の間のこの全単射により、すべての最終状態の最大値が最適な答えとなることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, W, k = map(int, input().split())
    items = [tuple(map(int, input().split())) for _ in range(n)]

    NEG = -10**30

    dp = [[NEG] * (k + 1) for _ in range(W + 1)]
    dp[0][0] = 0

    for w_i, v_i in items:
        ndp = [[NEG] * (k + 1) for _ in range(W + 1)]

        for w in range(W + 1):
            for f in range(k + 1):
                if dp[w][f] == NEG:
                    continue

                val = dp[w][f]

                ndp[w][f] = max(ndp[w][f], val)

                if f < k:
                    ndp[w][f + 1] = max(ndp[w][f + 1], val + v_i)

                if w + w_i <= W:
                    ndp[w + w_i][f] = max(ndp[w + w_i][f], val + v_i)

        dp = ndp

    ans = 0
    for w in range(W + 1):
        for f in range(k + 1):
            ans = max(ans, dp[w][f])

    print(ans)

if __name__ == "__main__":
    solve()
```この実装は DP 定義を直接ミラーリングします。 新鮮なものの使用`ndp`配列により、特定の項目の遷移が相互に干渉しないことが保証されます。 各アイテムは、スキップ、無料テイク、または有料テイクの 3 つのトランジションのうちの 1 つを正確に提供します。 

よくある落とし穴は、インプレース更新を何度も実行しようとすることです。$w$そして$f$これにより、1 回の反復内で同じアイテムを複数回使用することが誤って許可されてしまいます。 階層型 DP は古い状態と新しい状態を分離することでこれを回避します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(n \cdot W \cdot k)$| 各項目は、予算と無料カウント グリッドを超えるすべての州を緩和します。 
| スペース |$O(W \cdot k)$| 同じサイズの DP レイヤーを 2 つだけ保存します$W \times k$|

 と$n \le 5000$、$W \le 10000$、通常は小さい$k$、特に遷移が単純な整数更新であるため、これは最適化された Python の下での時間制限内に収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import inf

    n, W, k = map(int, sys.stdin.readline().split())
    items = [tuple(map(int, sys.stdin.readline().split())) for _ in range(n)]

    NEG = -10**30
    dp = [[NEG] * (k + 1) for _ in range(W + 1)]
    dp[0][0] = 0

    for w_i, v_i in items:
        ndp = [[NEG] * (k + 1) for _ in range(W + 1)]
        for w in range(W + 1):
            for f in range(k + 1):
                if dp[w][f] == NEG:
                    continue
                val = dp[w][f]
                ndp[w][f] = max(ndp[w][f], val)
                if f < k:
                    ndp[w][f + 1] = max(ndp[w][f + 1], val + v_i)
                if w + w_i <= W:
                    ndp[w + w_i][f] = max(ndp[w + w_i][f], val + v_i)
        dp = ndp

    return str(max(max(row) for row in dp))

 ## 特殊なケース

 例外的なケースとしては、次のような場合があります。$k = 0$。 無料移行は決してトリガーされず、DP は予算を超過した場合のみ標準の 0/1 ナップザックに縮退するため、アルゴリズムは引き続き機能します。 例えば：```
3 5 0
2 10
3 20
4 30
```DP は自由次元を使用しないため、3 番目の項目のみを選択すると、達成可能な最良の値は 30 になります。 

もう 1 つのエッジケースは次のような場合です$k \ge n$、すべてのアイテムを無料で受け取ることができます。 DP は、制約に違反することがないため、すべての項目に対して自由な遷移を優先します。 例えば：```
3 5 10
1 10
2 20
3 30
```全ての項目を自由に撮った結果は60。DPは予算を消費せずに正しく美しさを蓄積します。 

3 番目のケースは、主要な項目で予算が厳しい場合です。 考慮する：```
2 3 1
2 10
2 100
```最適な戦略は、100 個の美容アイテムを無料で受け取るか、DP の推移に応じて購入することです。 DP は両方を調査し、100 を正しく選択します。常に最高の美しさを自由なものとして選択する貪欲な戦略は、他の構成では失敗する可能性がありますが、ここでは DP によって両方の割り当てが一貫して評価されることが保証されます。
