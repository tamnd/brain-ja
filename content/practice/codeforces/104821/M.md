 ## 解決策
 ## 問題の理解

 垂直バーのスカイラインを表す高さの配列が与えられます。 各操作の後、バーが 1 つ増加し、雨が谷を満たした場合にこれらのバーの間にどれだけの水が閉じ込められるかを計算する必要があります。 

各位置の水位は、左側の最も高いバーと右側の最も高いバーによって決まります。 位置 i より上の水は、これら 2 つの最大値のうち小さい方から現在の高さを引いた値になりますが、決して負ではありません。 タスクは、ポイント増分が更新されるたびにこの合計を維持することです。 

制約は大きく、テストあたり合計で最大 200,000 のポジションと更新、合計入力サイズは最大 100 万です。 これにより、各更新後にプレフィックスとサフィックスの最大値を最初から再計算することが除外されます。これは、クエリごとに直線的な時間がかかり、最悪の場合、約 10^11 の操作が必要になるためです。 

単純なアプローチは、速度だけでなく、より微妙な点でも失敗します。 たとえば、プレフィックスとサフィックスの最大値配列を維持し、変更されたインデックスを中心にローカルでのみ更新するとします。 これは、単一の増加によって新しい主要なピークが作成されるたびに、変更がはるか右または左に伝播する可能性があるため、問題が発生します。 

小さな例でこれを説明します。 

入力:```
5
1 2 3 2 1
update (3, +3)
```更新後、3 番目の要素は 6 になり、中央のバーがグローバル ピークに変わります。 プレフィックスの最大値はその右側のすべての位置で変更され、サフィックスの最大値はその左側のすべての位置で変更されます。 局所的な調整のみを前提としたアプローチでは、効果が過小評価され、不正確な捕捉水の値が生成されます。 

## アプローチ

 ブルートフォースのアイデアでは、更新ごとにプレフィックス最大値とサフィックス最大値を再計算し、各インデックスの水の寄与を合計します。 これは正しい定義です。つまり、各位置は現在の左右の最大値のみに依存します。 問題は、各再計算のコストが O(n) であり、q 回の更新ではこれが O(nq) になり、指定された制約に対して大きすぎることです。 

重要な観察は、接頭辞最大値と接尾辞最大値が単調な構造であるということです。 左から右にスキャンすると、プレフィックスの最大値は、新たな記録の高さに遭遇した場合にのみ変化します。 接尾辞最大値についても右側から対称的に同じことが当てはまります。 これは、配列が、制御最大値が一定であるセグメントに分割されていると見なすことができることを意味します。 

単一のポジションが増加すると、新しい記録が作成されたり、既存の記録が強化されたりする可能性があります。 これは、その位置付近のレコード最大値の構造にのみ影響します。 プレフィックスまたはサフィックス配列全体を再計算する代わりに、現在のレコード構造を維持し、更新により無効になった部分のみを修復します。 各修復では、新しいレコードが挿入されるか、支配されているレコードのチェーンが削除されます。各レコードは、すべての更新にわたって限られた回数だけ挿入および削除できます。 

接頭辞最大値と接尾辞最大値の 2 つの単調構造を維持します。 これらから、すべてのインデックスの f[i] と g[i] を復元できます。 次に、min(f[i], g[i]) - a[i] を合計することによって総水量が計算され、f または g の値が変化するインデックスのみを追跡することによって、この合計を増分的に維持します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nq) | O(n) | 遅すぎる |
 | プレフィックスとサフィックス maxima の単調修復 | O((n + q) log n) 償却 | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 現在の高さ a[i]、プレフィックスの最大配列 f[i]、およびサフィックスの最大配列 g[i] の 3 つの配列を維持します。 また、合計の答えを min(f[i], g[i]) - a[i] の合計として維持します。 

中心となる考え方は、更新によって 1 つの位置が増加するだけであるため、プレフィックスとサフィックスの最大値は増加するだけで、減少することはありません。 この単調性により、すべてを再構築するのではなく、影響を受けた領域を修復することができます。 

1. 単一の左から右および右から左のパスを使用して、初期 f[i] と g[i] を構築します。 式から最初の答えを計算します。 
2. 更新 (x, v) ごとに、a[x] を v ずつ増加させ、その新しい高さを取得します。 
3. この増加の影響を受ける領域のみで f と g を再計算します。 f については、x から右に向かって歩き、変化がなくなるまで f[i] = max(f[i], a[x]) を更新します。 g については、x から左に歩き、安定に達するまで g[i] = max(g[i], a[x]) を更新します。 

これがすぐに停止する理由は、f[i] がすでに a[x] 以上になると、さらに右側の位置も影響を受けないためです。 

1. f[i] または g[i] を更新するときに、グローバル応答内のインデックス i の寄与も更新します。 f または g が変化する各 i について、古い寄与分を減算し、新しい寄与分を加算します。 
2. 各更新の処理後に維持された合計を出力します。 

### なぜ効果があるのか

 位置 i でのプレフィックスの最大値は値 a[1..i] のみに依存し、同様にサフィックスの最大値は a[i..n] のみに依存します。 更新では単一の位置が増加するだけであるため、プレフィックスの最大構造は、その位置から開始して、より強力な既存の最大値に達するまで連続領域を増加することによって進化します。 左側の要素は変更されないため、以前のプレフィックス値は影響を受けません。 同じ対称性が接尾語の最大値にも当てはまります。

これにより、更新されたインデックスの周囲の連続領域のみが変更可能であり、すべての変更が単調増加することが保証されます。 各インデックスの f[i] と g[i] は、最終的なグローバル最大構造によって制限されるため、制限された回数のみ増加できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    q = int(input())

    f = [0] * n
    g = [0] * n

    # prefix max
    cur = 0
    for i in range(n):
        cur = max(cur, a[i])
        f[i] = cur

    # suffix max
    cur = 0
    for i in range(n - 1, -1, -1):
        cur = max(cur, a[i])
        g[i] = cur

    ans = 0
    for i in range(n):
        ans += min(f[i], g[i]) - a[i]

    for _ in range(q):
        x, v = map(int, input().split())
        x -= 1

        a[x] += v

        old = min(f[x], g[x]) - (a[x] - v)
        new = min(f[x], g[x]) - a[x]
        ans += new - old

        # repair prefix to the right
        cur = f[x]
        for i in range(x, n):
            if f[i] >= cur:
                break
            oldv = min(f[i], g[i]) - a[i]
            f[i] = cur
            ans -= oldv
            ans += min(f[i], g[i]) - a[i]

        # repair suffix to the left
        cur = g[x]
        for i in range(x, -1, -1):
            if g[i] >= cur:
                break
            oldv = min(f[i], g[i]) - a[i]
            g[i] = cur
            ans -= oldv
            ans += min(f[i], g[i]) - a[i]

        print(ans)

def main():
    t = int(input())
    for _ in range(t):
        solve()

if __name__ == "__main__":
    main()
```このコードは、プレフィックスとサフィックスの最大配列を維持し、各増分の影響を受ける領域のみを更新します。 答えは、どちらかの境界が変化した場合にのみ寄与を再計算することによって段階的に追跡されます。 

両方の修復ループの初期のブレーク条件が重要な最適化です。 既存のプレフィックスの最大値がすでに伝播された値を支配している場合、それ以降のインデックスは変更されず、安全にスキップできます。 

寄与を更新するときは注意が必要です。f[i] または g[i] を変更する前に古い値を減算する必要があります。そうしないと、2 つの最大値の間の重複が誤った計算につながります。 

## 実用的な例

 小さなヒストグラムを考えてみましょう。 

入力:```
5
1 2 1 3 2
```初期の接頭辞と接尾辞の最大値:

 | 私 | a[i] | f[i] | g[i] | 水 |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 1 | 3 | 0 |
 | 2 | 2 | 2 | 3 | 0 |
 | 3 | 1 | 2 | 3 | 1 |
 | 4 | 3 | 3 | 3 | 0 |
 | 5 | 2 | 3 | 2 | 0 |

 ここで位置 3 に +3 による更新を適用すると、a は 1 2 4 3 2 になります。 

| ステップ | × | a[x] | 影響を受ける f | 影響を受ける g | 合計の変化 |
 | --- | --- | --- | --- | --- | --- |
 | 初期化 | - | - | 計算された | 計算された | ベース |
 | 更新1 | 3 | 4 | 右に伝播する | 左に伝播する | ローカルで再計算する |

 更新後、位置 3 は強いピークとなり、少なくとも 4 に達するまでプレフィックスの最大値を右に増やし、同様にサフィックスの最大値を左に増やします。 影響を受ける唯一の領域は、更新されたインデックスの周囲に集中しています。 

このトレースは、更新ポイントからの単調伝播のみが必要であり、最大値が安定するとそれ以上の修正は必要ないことを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + q・k) 償却 | 各更新は既存の最大値に達するまでのみ伝播し、各インデックスは制限された回数だけ更新されます。 
| スペース | O(n) | 高さの配列、プレフィックス maxima、サフィックス maxima |

 すべてのテストを通じて、更新の総数と配列サイズは 100 万回に制限されるため、償却伝播は実際には制限内に留まります。

 ## 特殊なケース

 単一要素の配列は最も単純なストレス ケースです。 左右の境界がないため、プレフィックスとサフィックスの両方の最大値は要素自体と等しくなります。 min(f[i], g[i]) は常に a[i] に等しいため、更新では両方が単純に増加し、水は 0 のままになります。 

厳密に増加する配列は、接尾辞の最大値がどこでも優勢であるケースをテストします。 すべての接頭辞の最大値はすでに現在の要素であるため、水がトラップされることはありません。 中間の更新では、ローカル値が増加するだけであり、境界領域が導入されないため、谷は作成されません。 

1 2 5 2 1 のような対称的なピーク構造は伝播をテストします。 中心を増やすとプレフィックスとサフィックスの両方の最大値が強化されますが、寄与が変化するのはピーク付近の領域のみで、外側の領域は安定したままです。 これにより、伝播が必要な境界を超えて誤って拡張されないことが確認されます。
