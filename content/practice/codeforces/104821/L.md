 ## 解決策
 ## 問題の理解

 小包タイプのコレクションが与えられています。 各タイプは、同一の荷物がいくつ存在するかを表します。各荷物の重量は 1 または 2 で、特定のフロアに配送する必要があります。 各グループを個別の荷物に拡張し、それぞれに重みと目的階を指定することを考えることができます。 

エレベーターは、乗車ごとの総重量の観点から固定容量を持っています。 各乗り物は 1 階から出発し、その乗り物で運ばれる荷物の中で最も高い目的階まで上がり、戻ってきます。 乗車料金はまさにその最上階の料金です。 私たちの仕事は、重量制限を考慮してすべての荷物を乗り物に分割し、これらの最大フロアの合計が最小になるようにすることです。 

重要な構造は、重量制限の下でアイテムをグループに梱包することですが、コストは各グループの最大フロア数のみに依存し、グループ内のアイテムの数には依存しません。 

制約は大きく、テスト ケース全体で合計最大 3×10^5 グループ、グループあたり最大 10^5 パーセルです。 これにより、パーセルを個別に拡張したり、組み合わせてグループ化を試みたりするアプローチは除外されます。 どのソリューションも集計されたカウントを処理し、テスト ケースごとにおおよそ O(n log n) 以上の動作をする必要があります。 

素朴な解釈では、すべてのパッキングを試すか、フロアごとに分類して、構造のない乗り物を貪欲に詰めることを提案するかもしれません。 これらのアプローチは失敗します。なぜなら、重量 1 と重量 2 のパーセル間の相互作用が梱包の実現可能性を決定し、目的が品目ごとに加算されるのではなく、グループごとの最大フロアごとであるためです。 

いくつかの微妙な特殊なケースが落とし穴を示しています。 すべての区画の重みが 2 で k が小さい場合、各乗り物は k/2 個の区画しか保持できないため、フロアごとにグループ化することが非常に重要になります。 すべての区画が同じフロアを持つ場合、答えは、配置に関係なく、乗車総数とそのフロアの積になります。 ウェイトの最適な混合を無視すると、容量が無駄になりやすく、不必要に余分な乗り物が作成され、総コストが増加します。 

## アプローチ

 この強引なアイデアは、荷物を有効な配車にグループ化する可能なすべての方法をシミュレートすることです。 各乗り物は総重量が k を超えないサブセットであり、そのサブセット内の最大フロア料金を支払います。 これは本質的に、重み付き制約と非線形コスト関数を備えたマルチセットにわたる分割問題です。 各区画は既存または新規の乗り物に配置できるため、中程度の入力であっても分割する方法の数は指数関数的になります。 枝刈りを行ったとしても、状態空間は n との組み合わせで増大するため、これは実行不可能になります。 

重要な点は、料金が各乗り物の最大フロアにのみ依存するということです。 これは、区画をフロアごとに降順に並べ替えることを示唆しています。 乗り物の最大フロアが f であると決定したら、必要なのはフロア ≤ f のどの区画をその乗り物に詰め込むことができるかを決定することだけです。 これにより、問題は次のようになります。フロア レベルごとに、高層階の区画によってコストがすでに決定されている乗り物に、できるだけ多くの下層階の区画を「接続」しようとします。 

これにより、自然な貪欲な構造が形成されます。 最も高い階から最も低い階まで処理します。 新しいフロアで荷物を見つけるたびに、それらをカバーするのに十分な乗車を開始する必要があります。これらの荷物は、すでに確定している高層階の乗車に配置できないためです。 これらの乗り物をオープンした後、以前に確認した下層階の小包を使用して残りの容量を満たそうとします。容量を早く消費するため、重い商品を最初に優先します。 

k のパリティと均等性は重要です。重みは 1 と 2 だけであるため、重み 2 項目と重み 1 項目の貪欲なペアリングを使用して、各乗り物内のパッキングの問題を軽減して、容量の利用率を最大化できます。

アクティブなライド全体でウェイト 1 スロットがいくつ残っているかという観点から、利用可能な「残存容量」を維持し、ウェイト 2 の使用状況を個別に追跡します。 フロアが下に移動するにつれて、スロットが無駄にならないように、上位フロアの残りの容量を再利用しようと継続的に試みます。

 | ブルートフォース | 指数関数 | 指数関数 | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、フロアと重量別に荷物を集計し、各フロアに重量 1 および重量 2 の品目の数が含まれるようにします。 

1. すべての個別のフロアを降順に並べ替えます。 最高フロアから最低フロアまで処理するため、一度乗車にコストを割り当てると、そのコストは固定され、再検討されることはありません。 これは、乗車料金がその乗車の最大フロアによって決まるため、必要です。 
2. 以前に作成した乗り物からの未使用容量の 2 つのグローバル プールを維持します。1 つは重量 1 ユニットの利用可能なスロットを表し、もう 1 つは重量 2 のチャンクで消費できる利用可能な容量を表します。 
3. 特定のフロア f で、最初に強制される新しい乗り物の数を決定します。 フロア f の各荷物は配送する必要があるため、既存のキャパシティーがそれらを収容できない場合は、コスト f で新しい乗り物を作成します。 新しい乗り物はそれぞれ、k 単位の耐荷重に寄与します。 
4. フロア f に区画を割り当てるときは、まず既存のキャパシティを使用しようとします。 後で適合させるのが難しいため、残りの全容量を使用してウェイト 2 のパーセルを貪欲に配置します。 その後、重み 1 のパーセルを残りの単一ユニット スロットに配置します。 
5. 現在のフロアの区画を配置した後に残った容量は、下層のフロアに繰り越されます。 これは、総コストを増やすことなく、高額な乗車が後で安価な荷物を吸収できるようにするため、重要です。 
6. すべてのフロアに対してこのプロセスを繰り返し、f にそのフロアで作成された新しい乗り物の数を乗じて合計コストを累積します。 

正しさは、乗り物に最大フロア f が割り当てられると、コストを増加させることなく、より低いフロアの残りの区画を安全に吸収できるという事実に依存します。 

### なぜ効果があるのか

 どの時点でも、乗り物は事実上、すでに含まれている最上階に等しい固定コストを持つバケツです。 既存の乗り物に低層階の区画を導入してもコストは変わらないため、重要な唯一の決定は、現在の階で荷物を収容するために新しい乗り物が必要かどうかです。 常に最高階から最低階まで処理することで、すべての乗り物の料金が 1 回だけ決定されるようにし、人為的にコストが増加する可能性がある高層階の必須区画を将来の決定に先送りすることはありません。 ウェイト 1 の前にウェイト 2 を貪欲にパッキングすることで、容量を最大限に活用し、余分な乗り物の不必要な作成を防ぎます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        groups = {}
        
        for _ in range(n):
            c, w, f = map(int, input().split())
            if f not in groups:
                groups[f] = [0, 0]  # [w1, w2]
            if w == 1:
                groups[f][0] += c
            else:
                groups[f][1] += c
        
        floors = sorted(groups.keys(), reverse=True)
        
        carry_w1 = 0
        carry_w2 = 0
        total_cost = 0
        
        for f in floors:
            w1, w2 = groups[f]
            
            cap = carry_w2 * 2 + carry_w1
            
            use2 = min(w2, cap // 2)
            cap -= use2 * 2
            w2 -= use2
            
            use1 = min(w1, cap)
            cap -= use1
            w1 -= use1
            
            remaining = w1 + 2 * w2
            need = (remaining + k - 1) // k
            
            total_cost += need * f
            
            total_cap = need * k
            
            total_cap += cap
            
            carry_w2 = total_cap // 2
            carry_w1 = total_cap % 2
        
        print(total_cost)

if __name__ == "__main__":
    solve()
```このソリューションは、各フロアを重み 1 および重み 2 のパーセルの集計カウントに圧縮します。 個々の区画を追跡する代わりに、以前に作成された配車からすでに利用可能な容量を追跡します。 

変数`cap`高層階の乗り物の未使用容量を重量単位で表します。 断片化された容量に収容するのは難しいため、最初に重量 2 のパーセルを適合させようとします。 次に、重み 1 の区画を配置します。 

利用可能な容量をすべて使用した後、このフロアの残りの区画に必要な完全な新規乗車の数を計算します。 そうした乗り物のそれぞれが貢献します`k`容量にも貢献します`f`総コストに。 

現在のフロアの需要に対応した後の残りの容量は下方に繰り越されます。 将来のフロアで再利用できるように、これをウェイト 2 スロットと残りのウェイト 1 スロットの同等の数に変換します。 

重要な点は、乗り物を明示的にシミュレートしないことです。 フロア間の容量の伝播のみを追跡し、実際のグループを構築せずに正確性を保証します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import defaultdict

    input = sys.stdin.readline
    T = int(input())
    out = []

    def solve():
        for _ in range(T):
            n, k = map(int, input().split())
            groups = {}
            for _ in range(n):
                c, w, f = map(int, input().split())
                groups.setdefault(f, [0, 0])
                groups[f][0 if w == 1 else 1] += c

            floors = sorted(groups.keys(), reverse=True)
            carry_w1 = carry_w2 = 0
            total_cost = 0

            for f in floors:
                w1, w2 = groups[f]
                cap = carry_w2 * 2 + carry_w1

                use2 = min(w2, cap // 2)
                cap -= use2 * 2
                w2 -= use2

                use1 = min(w1, cap)
                cap -= use1
                w1 -= use1

                remaining = w1 + 2 * w2
                need = (remaining + k - 1) // k

                total_cost += need * f
                total_cap = need * k + cap

                carry_w2 = total_cap // 2
                carry_w1 = total_cap % 2

            out.append(str(total_cost))

    solve()
    return "\n".join(out)

 ## 特殊なケース

 エッジ ケースの 1 つは、すべての荷物の重量が 2 で、k が 2 よりわずかに大きい場合です。この状況では、各乗り物で運べる荷物の数が少ないため、余った容量を貪欲に再利用することが不可欠です。 このアルゴリズムは、利用可能な容量から常に重み 2 のパーセルを最初に消費することでこれを処理し、余分な乗車が発生する断片化を防ぎます。 

もう 1 つのエッジ ケースは、すべての区画が同じフロアを共有する場合です。 ここでは、フロア間で再利用する機会がないため、ソリューションは重量制約の下で純粋なビン梱包に減ります。 アルゴリズムは、そのフロアで必要なすべての乗り物を自然に計算し、期待される動作と一致する意味のある容量を下方に運びません。 

3 番目のエッジ ケースは、低層階の重み 1 の区画が多数あり、高層階の重み 2 の区画が少数存在する場合に発生します。 降順で処理しないと、誤って低層階の区画が最初に割り当てられ、高層階に確保されるべき容量が無駄になる可能性があります。 降順スイープにより、高コストの決定が最初に修正され、下位の項目がすべて埋め込み材料として扱われることが保証されます。
