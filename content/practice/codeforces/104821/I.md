 ## 解決策
 ## 問題の理解

 ゼロから始まり、長い一連の操作を通じて進化するカウンターが与えられていますが、そのシーケンス自体を見ることはありません。 各操作は、1 ずつインクリメントするか、カウンタを強制的にゼロに戻すリセットのいずれかです。 私たちが知っているのは部分的な観察です。特定の操作インデックスでは、カウンターは特定の値を取っているはずです。 タスクは、長さの増加とリセットのシーケンスが存在するかどうかを判断することです。$n$これらすべての観測結果が同時に一致します。 

重要な構造的観察は、次のことです。$n$巨大です、最大で$10^9$, そのため、プロセスを段階的にシミュレーションすることはできません。 唯一の意味のある情報は、$m$制約。最大でも$10^5$テストケースごとに。 これにより、すべてのソリューションは即座に完全なタイムラインを無視し、代わりに制約された位置間の関係のみを考慮するようになります。 

単純な間違いは、各制約を個別に扱い、カウンターをローカルに調整できると想定することです。 たとえば、制約があるとします。$(a=5, b=2)$そして$(a=7, b=1)$。 各位置に貪欲に操作を割り当てようとするかもしれませんが、リセットはタイムラインのサフィックス全体に影響を与えるため、これは失敗します。 

2 番目の微妙な障害モードは、隠れたリセットによってのみ制約が矛盾する場合に発生します。 たとえば、必要な場合は、$(a=4, b=3)$そして$(a=6, b=1)$、不注意なアプローチでは、両方が独立して達成可能であると考えるかもしれませんが、2 番目の制約により 4 と 6 の間でリセットが強制され、遡って最初の制約が破られる可能性があります。 

本当の難しさは、各観測値が単一の値だけでなく、その前の操作セグメント全体を制約することです。 

## アプローチ

 総当り攻撃を試みる場合は、それぞれの$n$「+」または「c」のいずれかの演算を実行し、カウンタをシミュレートしてすべての制約を検証します。 操作シーケンスの数は指数関数的であるため、これは直ちに不可能です。$n$、単一のシーケンスを保存することさえ不可能です。$n$到達できる$10^9$。 

重要な簡素化は、いつでもカウンターを決定するものを理解することから生まれます。 位置の値$i$前の最新のリセットによって完全に決定されます。$i$。 リセット後、カウンタは再びゼロから始まり、別のリセットが発生するかクエリ ポイントに到達するまで、後続の「+」ごとにカウンタが増加します。 

したがって、それぞれの制約$(a_i, b_i)$最後のリセットが以前に発生したはずの場所を暗黙的に特定します$a_i$。 前回のリセットが前であれば、$a_i$位置で発生しました$r_i$、次にカウンター$a_i$正確に等しい$a_i - r_i$、間のすべての操作があるため、$r_i+1$そして$a_i$「+」でなければなりません。 これにより、$r_i = a_i - b_i$、また、すべての位置を強制します$(r_i, a_i]$「+」になります。 

したがって、各制約は、特定のリセット位置と、その後のリセットが許可されない禁止領域という非常に厳格な構造に変換されます。 問題は、これらすべての暗黙のリセット ポイントが、互いの禁止セグメントと競合することなく共存できるかどうかを確認することになります。 

タスクを、別の制約で必要な「すべてプラス」の間隔内にリセットが存在しないように、これらのリセット位置を一貫して順序付けできることを検証することに縮小します。

 ## アルゴリズムのチュートリアル

 各制約を強制リセット位置に変換し、対応するセグメントによって課せられる構造に違反することなくこれらのリセットが共存できるかどうかを確認します。 

1. 制約ごとに$(a_i, b_i)$、計算する$r_i = a_i - b_i$。 もし$b_i > a_i$の場合、カウンタは最後のリセット以降の操作の数を超えることができないため、制約は直ちには不可能になります。 これにより、必要なリセット位置が得られます$r_i$。 
2. 各制約は、間隔内で次のことを意味します。$(r_i, a_i]$、すべての操作は「+」である必要があります。 これは、ポジション後のこの間隔内ではリセットが発生できないことを意味します。$r_i$。 
3. すべての制約をリセット位置で並べ替えます$r_i$。 この順序は、リセットが発生する必要がある時系列順序を反映しています。 
4. プロセス制約を昇順に設定します。$r_i$。 処理されたすべての制約の中で最大の右エンドポイント、つまり最大のエンドポイントを維持します。$a_i$これまでのリセットのグループで見られました。 
5. 位置をリセットして拘束に移動する場合$r_j$、それを確認してください$r_j$厳密に最大値を超えています$a_i$以前のすべての制約の。 もし$r_j \le \max a$の場合、このリセットは「+」のみを含む必要がある領域内にありますが、これは不可能です。 
6. 同一のグループ制約$r_i$これらは同じリセット ポイントを表し、それらの間で順序の競合が発生しないため、一緒に使用できます。 

すべての制約がこれらのチェックに合格した場合、有効な操作シーケンスが存在します。 

正確さは、すべての制約がインデックスの前の最後のリセットがどこで発生するかを一意に決定するという事実から来ています。 これらのリセット ポイントが修正されると、連続するリセット間のセグメントはすべて強制的に増分されます。 強制リセット領域と強制インクリメント領域の間にオーバーラップがあると矛盾が生じます。アルゴリズムは、リセット位置が常に以前の禁止範囲外にあることを保証することで、これらの矛盾を正確に検出します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        
        events = []
        ok = True
        
        for _ in range(m):
            a, b = map(int, input().split())
            if b > a:
                ok = False
            else:
                r = a - b
                events.append((r, a))
        
        if not ok:
            print("No")
            continue
        
        events.sort()
        
        max_a = -1
        i = 0
        ans = True
        
        while i < len(events):
            r = events[i][0]
            group_max_a = -1
            
            while i < len(events) and events[i][0] == r:
                group_max_a = max(group_max_a, events[i][1])
                i += 1
            
            if r <= max_a:
                ans = False
                break
            
            max_a = max(max_a, group_max_a)
        
        print("Yes" if ans else "No")

if __name__ == "__main__":
    solve()
```実装ではまず、各制約を暗黙のリセット位置に変換します。$r = a - b$。 制約違反$b \le a$は、最後のリセット以降の有効な増分数に対応できないため、すぐに拒否されます。 

リセット位置でソートした後、アルゴリズムは同じブロックの制約を処理します。$r$。 各ブロックは単一の強制リセット位置を表し、ブロック内で最も右のエンドポイントを追跡します。$a$これらすべての制約によりリセットが禁止されているため、$(r, a]$。 

変数`max_a`以前のリセットによって引き起こされた最も遠い禁止境界を保存します。 新しいリセット位置が現れるときは、厳密にこの境界を越えた位置になければなりません。 そうしないと、増分のみを含める必要がある領域内に収まります。 

## 実用的な例

 小規模な一貫したケースを考えてみましょう。 

入力:```
1
5 2
4 3
5 3
```ここで、制約は次のように変換されます。 

| 制約 | r = a - b | | グループ最大値 |
 | --- | --- | --- | --- |
 | (4,3) | 1 | 4 | 4 |
 | (5,3) | 2 | 5 | 5 |

 選別後、加工を行います$r=1$まず、それで`max_a = 4`。 それから処理します$r=2$。 以来$2 \le 4$これは、位置 2 のリセットが完全に「+」でなければならないセグメント内にあることを意味するため、最初の制約が破られてしまいます。 アルゴリズムはこのケースを正しく拒否します。 

次に、一貫した例を考えてみましょう。 

入力:```

6 2
4 3
6 2

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    T = int(input())
    out = []

    for _ in range(T):
        n, m = map(int, input().split())
        events = []
        ok = True

        for _ in range(m):
            a, b = map(int, input().split())
            if b > a:
                ok = False
            else:
                events.append((a - b, a))

        if not ok:
            out.append("No")
            continue

        events.sort()
        max_a = -1
        i = 0
        ans = True

        while i < len(events):
            r = events[i][0]
            group_max = -1

            while i < len(events) and events[i][0] == r:
                group_max = max(group_max, events[i][1])
                i += 1

            if r <= max_a:
                ans = False
                break

            max_a = max(max_a, group_max)

        out.append("Yes" if ans else "No")

    return "\n".join(out)

 ## 特殊なケース

 複数の制約が同じリセット位置を暗示する場合、アルゴリズムは順序付けを妨げないようにそれらをグループ化します。 たとえば、制約$(a=5,b=3)$そして$(a=7,b=5)$どちらも与える$r=2$。 彼らは単に禁止領域を強化するだけです$(2,7]$、グループ内で追加の整合性チェックは必要ありません。 

次のような 2 つの異なるリセットが非常に近い場合$r_1 = 3$そして$r_2 = 4$、アルゴリズムにより、前の制約の禁止間隔に後のリセットが含まれないことが保証されます。 もし$a_1 \ge 4$の場合、4 でリセットすると、増分のみを含める必要があるセグメント内に収まり、アルゴリズムはそれを正しく拒否します。 

境界ケースは、制約によって強制される場合に発生します。$r = 0$。 これは、セグメントがプロセスの最初から始まることを意味するため、プレフィックス全体が$a$増分のみで構成する必要があります。 それ以降のリセットは、厳密にその間隔の終了後に開始する必要があり、これは同じ比較によって強制されます。$r > \max a$。
