 ## 解決策
 ## 問題の理解

 最大 20 個の頂点を持つ小さな無向グラフが与えられます。 トラベラーは任意の頂点から開始し、正確に移動します。`d`日々。 毎日、1 つのエッジを隣接する頂点に移動することで構成されているため、訪問した頂点のシーケンスには長さがあります。`d`。 

頂点の中には、サイズが最大 7 の顕著なサブセットがあり、これらはすべて、選択したウォークのどこかに少なくとも 1 回出現する必要があります。 課題は、そのような長さがいくつあるかを数えるということです。`d`ウォークが存在します。2 つのウォークは、それらが占める頂点のいずれかの時点で異なる場合、異なるものとみなされます。 答えはモジュロで計算されます$10^9 + 9$。 

制約の構造は、ソリューションを強く形作ります。 頂点の数は少ないですが、歩行の長さは`d`最大 10 まで可能です。必須セットも小さく、最大 7 です。この組み合わせは、問題の主要な状態に、現在の頂点と、どの必須頂点がすでに訪問されているかの両方を含むことを示唆しています。 以来`n ≤ 20`、必要なノードのサブセットを含むあらゆる状態空間は管理可能です。$2^7 = 128$と乗算する`n`DPはまだ小さいままです。 

最も一般的な失敗例は、すべての特別な都市を訪問する必要があるという要件を無視することです。 すべての歩行距離の素朴なカウント`d`は単に隣接行列のべき乗になりますが、制約が満たされているかどうかは追跡されません。 もう 1 つの微妙な失敗は、開始頂点の扱いが間違っていることから発生します。任意の頂点が開始点になる可能性があるため、固定された開始点だけでなく、考えられるすべての初期状態を考慮する必要があります。 

小規模な失敗例としては、エッジで接続された 2 つの頂点のグラフが挙げられます。`d = 2`、および 1 つの必須頂点。 単純な「すべてのウォークをカウントする」アプローチでは 2 (両方向) が返されますが、必要な頂点が 1 つだけで、その頂点にアクセスせずに間違った頂点から開始する場合は、必要なノードに応じて一部のウォークを除外する必要があります。 これは、状態追跡が必要な理由を示しています。 

## アプローチ

 強引なアイデアは、考えられる長さの散歩をすべて列挙することです`d`。 任意の開始頂点から、ステップごとにすべての近傍を再帰的に試し、最後に必要な頂点がすべて訪問されたかどうかを確認します。 分岐係数は最大 20、深さは最大 10 であるため、これは最大 20 までを探索します。$20 \cdot 20^{10}$最悪の場合の可能性は大きすぎます。 

重要な観察は、ウォーク長は短いが、グラフ サイズも小さいこと、および制約はパスの最適性に関するものではなく、小さなサブセットのカバレッジに関するものであるということです。 これは、時間ステップにわたる動的プログラミングを示唆しています。 各ステップで必要なのは、現在の頂点と、これまでにどの必要な頂点が訪問されたかを知ることだけです。 必要な頂点は最大 7 つであるため、これを最大 128 状態のサイズのビットマスクとしてエンコードできます。 その後、DP はさらに進化します`d`ステップ、エッジに沿って伝播します。 

ブルート フォースは有効な遷移を探索するため機能しますが、同じサブ問題を同じ条件で再計算するため失敗します。`(node, visited_mask, step)`構造。 未来はこれら 3 つのコンポーネントのみに依存するという観察により、問題は層状グラフ DP に帰着します。

 | ブルートフォース DFS 列挙 |$O(n^d)$|$O(d)$再帰 | 遅すぎる |
 | DP オーバー (ノード、マスク、ステップ) |$O(d \cdot n \cdot 2^k \cdot n)$≈$O(d \cdot n^2 \cdot 2^k)$|$O(n \cdot 2^k)$| 承認済み |

 ## アルゴリズムのチュートリアル

 動的プログラミングテーブルを構築します。`dp[v][mask]`頂点に立つ方法の数を表します`v`一定数のステップを処理した後、すでにそのサブセットを正確に訪問している`mask`必要な頂点の数。 

1. まず、必要な各頂点にインデックスを割り当てます。`0`に`k-1`したがって、サブセットをビットマスクとして表すことができます。 これにより、必要な頂点にアクセスしたときの定時更新が可能になります。 
2. 設定によりステップ 1 の DP を初期化します。`dp[v][mask] = 1`すべての開始頂点に対して`v`、 どこ`mask`ビットが含まれています`i`もし`v`です`i`-番目に必要な頂点。 これは、どこからでも開始でき、必要に応じて最初の訪問状態に開始頂点がすでに含まれているという事実を反映しています。 
3. 2 から 3 までのステップを繰り返します。`d`。 ステップごとに、新しい DP テーブルを計算します。`ndp`ゼロに初期化されます。 
4. すべての州について`(u, mask)`現在の DP で、すべてのエッジに沿って移動しようとします`(u, v)`。 それぞれの動きが次のことに貢献します`ndp[v][new_mask]`、 どこ`new_mask`は`mask`OR に対応するビット`v`もし`v`が必要です。 
5. 現在のステップのすべての状態と遷移を処理した後、次のように置き換えます。`dp`と`ndp`。 
6.すべて完了したら`d`ステップ、合計`dp[v][full_mask]`すべての頂点にわたって`v`、 どこ`full_mask`必要な頂点がすべて訪問されたことを示します。 

この構造の背後にある理由は、各 DP 層が固定長のすべての有効な部分ウォークを表し、遷移によって隣接関係と蓄積された訪問状態の両方が保存されるためです。 

### なぜ効果があるのか

 どの段階でも`t`、DP 状態`(v, mask)`長さのすべてのウォークを正確に集計します`t`それは頂点で終わります`v`そして、によってエンコードされたセットを正確に訪れました。`mask`。 すべての遷移は有効なウォークを 1 つのエッジごとに拡張し、マスクの更新はこれまで制約が満たされているかどうかを正確に追跡します。 長い距離を歩くたびに`d`長さのプレフィックスに一意に分解できます`d-1`最後の動きに加えて、DP は有効なシーケンスを失ったり複製したりしません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 9

def solve():
    n, m, k, d = map(int, input().split())
    
    req = list(map(int, input().split())) if k > 0 else []
    req = [x - 1 for x in req]
    
    idx = {v: i for i, v in enumerate(req)}
    
    g = [[] for _ in range(n)]
    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)
    
    size = 1 << k
    dp = [[0] * size for _ in range(n)]
    
    # step 1: starting positions
    for v in range(n):
        mask = 0
        if v in idx:
            mask |= 1 << idx[v]
        dp[v][mask] = (dp[v][mask] + 1) % MOD
    
    # steps 2..d
    for _ in range(d - 1):
        ndp = [[0] * size for _ in range(n)]
        for u in range(n):
            for mask in range(size):
                if dp[u][mask] == 0:
                    continue
                val = dp[u][mask]
                for v in g[u]:
                    nmask = mask
                    if v in idx:
                        nmask |= 1 << idx[v]
                    ndp[v][nmask] = (ndp[v][nmask] + val) % MOD
        dp = ndp
    
    full = (1 << k) - 1
    ans = 0
    for v in range(n):
        ans = (ans + dp[v][full]) % MOD
    
    print(ans)

if __name__ == "__main__":
    solve()
```DP は歩数によって明示的に階層化され、異なる長さの歩行が混在するのを防ぎます。 隣接リストにより、各遷移が状態層ごとのエッジにわたって線形時間で処理されることが保証されます。 ビットマスクの更新は遷移中に遅延して実行されるため、状態拡張の事前計算が回避されます。 

微妙な点の 1 つは初期化です。すべての頂点は有効な開始点であり、マスクはその頂点がすでに要件の一部を満たしているかどうかを反映する必要があります。 これは見逃されることが多く、過少カウントにつながります。 

## 実用的な例

 ### 例 1

 折れ線グラフを考えてみましょう`1 - 2 - 3`、必要なセット付き`{2}`、 そして`d = 2`。 

初期 DP (ステップ 1):

 | 頂点 | マスク | カウント |
 | --- | --- | --- |
 | 1 | 0 | 1 |
 | 2 | 1 | 1 |
 | 3 | 0 | 1 |

 1 回移動した後:

 1 → 2、2 → {1,3}、3 → 2。 

| 頂点 | マスク | カウント |
 | --- | --- | --- |
 | 2 | 1 | 1 |
 | 2 | 0 | 1 |
 | 1 | 0 | 1 |
 | 3 | 0 | 1 |

 マスクで終わるパスのみを考慮します`1`したがって、ノード 2 を訪問した州のみが正しく貢献します。 

このトレースは、必要なノードにアクセスするとビットが反転され、その後のステップ全体でどのように維持されるかを示します。 

### 例 2

 三角グラフ`1 - 2 - 3 - 1`、必要なセット`{1,2}`、`d = 3`。 

ステップ 1 の後、マスクが必要かどうかに応じて、すべての頂点がマスクに影響します。 DP は 3 層にわたって展開され、両方のビットが設定されている状態のみが最終的な合計まで生き残ります。 この例は、アルゴリズムが必要なノードに連続してアクセスする必要はなく、ウォークの任意の時点でのみアクセスする必要があることを示しています。

 ## 特殊なケース

 エッジケースの 1 つは次のような場合です`k = 0`。 この状況では、歩くたびに`d`訪問した頂点に関係なく有効です。 マスク空間のサイズが 1 であるため、DP はこれを自然に処理し、すべてのパスがフィルタリングなしでカウントされます。 

もう 1 つのエッジケースは次のような場合です`d = 1`。 ここでは遷移は発生しないため、答えは単純に、初期マスクがすべての要件をすでに満たしている開始頂点の数になります。 必要な頂点がすべて異なる場合、必要なノードで始まる頂点のみが完全なマスクに寄与し、DP はこれを正しくキャプチャします。 

最後の微妙なケースは、必要な頂点が互いに接続されていない場合です。 このアルゴリズムは到達可能性を想定していないため、依然として機能します。 有効な歩行のみがカウントされ、到達不能な状態は単にゼロ遷移に寄与します。
