 ## 解決策
 ## 問題の理解

 私たちには 3 次元空間内の点のセットが与えられています。 各点には整数の座標があり、最大 1 万個あります。 中心が座標軸のいずれか、つまり x 軸、y 軸、または z 軸上のどこかに配置されるように拘束された球を配置したいと考えています。 中心が選択されると、球はある程度の半径で拡大し、ユークリッド空間内のその距離内のすべての点をカバーします。 

すべてのポイントをカバーする必要はありません。 代わりに、球には少なくとも半分の点 (切り捨て) が含まれていれば十分です。 軸と中心位置の有効な選択肢の中で、可能な限り小さい半径が必要です。 

出力は単一の実数、つまりそのような球に少なくとも ⌊in/2⌋ 点を含めることができる最小半径です。 

制約は非常に厳しいので、どの解法でもすべての中心にわたる二次比較を回避する必要があります。 n が最大 10^4 の場合、候補中心に対する O(n^2) スキャンはすでに遅すぎ、O(n^2 log n) ですら完全に実行不可能です。 もっともらしいのは、評価あたり O(n log n)、または連続パラメータの対数検索と組み合わせた評価あたり O(n) に近い値です。 

複数の点が中心候補から等距離にある場合、微妙なエッジ ケースが発生します。 少なくとも k 点が半径内にあるかどうかだけを考慮しているため、同点によって答えが不連続に変化する可能性があります。 もう 1 つの重要なケースは、1 つの投影を除いてすべての点が座標軸から遠く離れており、最適な軸が不明瞭になる場合です。 

素朴な推論による具体的な失敗シナリオは、中心を平均または中央の座標に固定し、そこから半径を計算できると仮定することです。 たとえば、異なる軸の周りに点が集まっていると、単純な座標統計から最適な中心が遠ざかってしまう可能性があります。 

## アプローチ

 直接的な試みは、軸上の中心、たとえば位置 t の x 軸を固定し、各点から (t, 0, 0) までのすべての距離を計算することです。 その固定 t について、距離を並べ替えて、k 番目に小さいものを選択できます。これは、k 点をカバーするのに必要な半径です。 これを多くの t の候補値に対して繰り返し、最小値をとれば問題は解決しますが、難しいのは t が連続であるため、可能性は無限にあるということです。 

t をすべての入力 x 座標に離散化したとしても、これでは十分ではありません。 k 番目の距離関数はこれらの値の間で区分的に一定ではないため、中心の最適な位置が点投影と一致することは保証されません。 t が移動するにつれて、各距離は滑らかに変化し、k 個の最も近い点の同一性は複数回変化する可能性があります。 

重要な観察は、固定軸の場合、中心位置 t を k 点をカバーするのに必要な半径にマッピングする関数が単峰的に動作することです。 単純な代数的な意味では厳密には凸ではありませんが、このジオメトリでは実際には連続線上の k 番目の距離に単一のグローバル最小値があるため、三項探索がサポートされます。 これにより、数値的に最小化することができます。 

各軸に対して独立して、中心の座標に対して三値検索を実行します。 候補 t について、その軸線までのすべての二乗距離を計算し、k 番目に小さいものを抽出します。 候補値を比較し、検索間隔を縮小します。 最後に、3 つの軸にわたって最良の結果を取得します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべてのセンターに対するブルートフォース | O(∞ または離散化された O(m・n log n)) | O(n) | 遅すぎる |
 | 軸ごとの三分探索 | O(3 · n · log(精度) · log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各座標軸に対して独立して問題を解き、その軸に沿った 1 次元の最適化問題として扱います。

1. 1 つの軸、たとえば x 軸を固定し、フォームの中心 (t, 0, 0) を考慮します。 中心が t にあるときに必要な半径として関数 f(t) を定義します。 これは、すべての点を取得し、(t, 0, 0) までのユークリッド距離を測定し、k 番目に小さい距離を選択することによって計算されます。 
2. k をフロア(n/2)に設定します。 これが私たちがカバーしなければならないポイントの数です。 関数 f(t) は評価にコストがかかりますが、決定論的であり t のみに依存します。 
3. すべての考えられる最適な位置 (たとえば、-20000 から 20000) を含む十分に大きな間隔で t に対して三項検索を実行します。境界は座標制約から得られます。 
4. 各反復で、間隔内の 2 つの候補点 t1 および t2 を選択します。 すべての点をスキャンし、軸までの二乗距離を計算し、nth_element を使用して k 番目に小さい値を選択することにより、f(t1) と f(t2) を計算します。 
5. f(t1) と f(t2) を比較します。 f(t1) が大きい場合は、間隔を右にシフトします。 それ以外の場合は左にシフトします。 これにより、最小値を含む領域が徐々に狭まります。 
6. 間隔が十分小さくなるまで繰り返します。 検索中に見つかった最良の値が記録されます。 
7. y 軸と z 軸についても手順 1 ～ 6 を繰り返し、それに応じて距離の式を変更します。 
8. 3 つの軸すべてにわたって見つかった最適な二乗半径の平方根を出力します。 

正確さは、固定軸の場合、中心位置の関数としての k 番目の最小距離が単一のグローバル最小値を持つという事実に依存します。 これにより、三分探索で最適な領域が破棄されなくなります。 

## なぜ機能するのか

 固定軸の場合、各点は二乗距離形式の t の凸関数 (x − t)^2 + 定数に寄与します。 このような関数のセットの k 番目に小さい関数は、k 点の組み合わせ選択の下側包絡線として動作します。 この関数はどこでも滑らかではありませんが、その大域最小値は三分探索に関連する意味で一意であり、2 つの内部点でそれを評価することで最小値が存在する方向が正しく決定されます。 各候補の正確な k 番目の距離を常に再計算するため、検索は正しい軸位置に収束します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def kth_radius(points, axis):
    n = len(points)
    k = n // 2

    if axis == 0:
        def dist2(t, p):
            x, y, z = p
            dx = x - t
            return dx * dx + y * y + z * z
    elif axis == 1:
        def dist2(t, p):
            x, y, z = p
            dy = y - t
            return x * x + dy * dy + z * z
    else:
        def dist2(t, p):
            x, y, z = p
            dz = z - t
            return x * x + y * y + dz * dz

    lo, hi = -20000.0, 20000.0

    best = float('inf')

    for _ in range(80):
        m1 = lo + (hi - lo) / 3
        m2 = hi - (hi - lo) / 3

        d1 = [dist2(m1, p) for p in points]
        d2 = [dist2(m2, p) for p in points]

        d1.sort()
        d2.sort()

        r1 = d1[k]
        r2 = d2[k]

        best = min(best, r1, r2)

        if r1 > r2:
            lo = m1
        else:
            hi = m2

    return best

def solve():
    n = int(input())
    points = [tuple(map(int, input().split())) for _ in range(n)]

    ans = float('inf')

    for axis in range(3):
        ans = min(ans, kth_radius(points, axis))

    print(ans ** 0.5)

if __name__ == "__main__":
    solve()
```この実装では、各軸を個別に評価し、中心座標に対して 3 値検索を実行します。 各候補中心について、すべての二乗距離を計算し、それらを並べ替えて k 番目に小さいものを抽出します。 平方根の繰り返しを避けるために平方距離が全体で使用され、最後の平方根は 1 回だけ適用されます。 

三項探索ループは固定回数の反復を実行します。これは倍精度の収束には十分です。 検索間隔は、座標制約が与えられた場合に最適な中心を安全に含むのに十分な幅で選択されます。

| 反復 | t1 | t2 | f(t1) | f(t2) | 間隔更新 |

 | 3 | -200 | 200 | 大きい | 小さい | 左に移動 |

 この表は、中心が軸に沿って最も密度の高いクラスターに近い領域に向かって検索がどのように一貫して移動するかを示しています。 k 番目の距離は、中心が点の少なくとも半分を含むクラスターに近づくにつれて減少します。 

### 例 2

 ここで、x の変動が小さい、ほとんどが yz 平面内に点が広がっていることを考えてみましょう。 

| 反復 | t1 | t2 | f(t1) | f(t2) | 間隔更新 |

 このトレースは、X 軸に沿ったより平坦な対物レンズを示しています。これは、すべての中心位置が同様に動作することを意味します。 このアルゴリズムは、勾配に依存するのではなく正確な k 番目の距離を継続的に評価するため、依然として収束します。

 ## 特殊なケース

 すべての点が同一である場合、重要なエッジ ケースが発生します。 その場合、k 番目の距離はゼロであるため、点の投影と一致する任意の軸上の中心は半径 0 になります。 このアルゴリズムは同一の距離配列を評価し、三分探索は直ちにゼロ値に収束します。 

もう 1 つのケースは、ポイントが 2 つの遠く離れたクラスターに分割される場合です。 必要な点は k 個だけであるため、最適な中心はより大きなクラスターの近くにある必要があります。 k 番目の距離関数はこれを自然に捉えています。これは、中心が密集したクラスター内に移動すると、多くの距離が小さくなり、順序統計量を支配するためです。 

最後のケースは、最適な中心がどの入力座標にも近くない場合です。 連続三分探索でも、離散的な候補位置に依存せず、実数線上で目的を直接評価するため、収束します。
