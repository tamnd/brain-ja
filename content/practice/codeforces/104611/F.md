 ## 解決策
 ## 問題の理解

 両方とも長さ n の 2 つの円形の宝石のシーケンスが与えられます。 各位置は宝石のタイプを保持し、シーケンスは周期的であるとみなされます。つまり、任意の開始点を選択して、円の周りの固定方向にそれらをトラバースすることができます。 

宝石の種類間には方向性のある変換規則があります。 各ルールには、ある程度のコストを支払えばタイプ a の宝石をタイプ b に変更できると記載されていますが、明示的に指定されない限り、その逆の操作は必ずしも利用できるわけではありません。 

タスクは、最初のシーケンスの開始回転と方向 (時計回りまたは反時計回り) を選択し、2 つの円を位置ごとに位置合わせすることです。 整列した宝石のペアごとに、一連の変換を適用して 2 つの宝石を等しくすることができ、それらの変換のコストの合計を支払います。 開始位置と方向のすべての選択において、総コストを可能な限り最小限に抑えたいと考えています。 すべての整列されたペアを等しくする方法が存在しない場合は、-1 を出力します。 

この制約は、ルールの数が多い一方で、宝石の種類の数が少なく、最大 400 であることを意味します。 シーケンスの長さ n は十分に大きいため、変換の試行ごとに O(n²) 以下の場合は慎重に処理する必要がありますが、400 状態を超える密な 3 次解は実現可能です。 この構造は、問題を 2 つの部分に分割することを示唆しています。つまり、すべての宝石タイプ間の最短の変換コストを計算し、次に 2 つのシーケンス間のすべての周期的アラインメントを効率的に評価します。 

変換が間接的である場合、微妙な失敗例が発生します。 たとえば、a → b と b → c のみが存在する場合、a → c は可能ですが、中間の手順を経て発見する必要があります。 貪欲なアプローチやダイレクトエッジのみのアプローチは、実現可能性を過小評価したり、コストを過大評価したりすることになります。 

もう 1 つの特殊なケースは、方向の処理です。 2 番目のシーケンスの 1 つの方向のみを考慮すると、走査順序を逆転する必要がある有効な最適解を見逃す可能性があります。 

## アプローチ

 直接的な総当たり戦略では、最初のサークルとあらゆる方向で可能なすべての開始インデックスが試行されます。 アライメントごとに、宝石タイプ間の最短パス クエリを使用して、各ペアの宝石を変換するコストを個別に計算します。 

これはすでに分解を示唆しています。任意の型 a を任意の型 b に変換するための最小コストがわかっている場合、各位置合わせコストは位置の単純な合計になります。 次に、ブルート フォースは 2n 個のアライメントをチェックすることになり、それぞれのコストは O(n)、各変換ルックアップは O(1) となり、前処理後のテスト ケースごとに O(n²) が得られます。 ボトルネックはアライメントの数ではなく、変換コストを正しく計算することです。 

重要な観察は、宝石の変換が最大 400 ノードにわたって有向加重グラフを形成するということです。 ある型を別の型に変換する最も安価な方法は、このグラフの最短経路問題です。 すべてのペアの最短経路が計算されると、任意の 2 つの宝石タイプ間の変換コストが直接検索されます。 

この削減の後、残りのタスクはすべての巡回シフトを効率的に評価することです。 固定のシフトと方向の場合、コストは、事前に計算されたタイプ間の距離の位置の合計になります。 これは構造的にはシーケンスに関する周期相関の問題です。 n が大きいため、各シフトを最初から再計算すると遅すぎますが、すべての計算は単純な加算寄与であるため、合計 O(n²) でシフトを直接評価できます。これは、n が数千までの一般的な制限の下では許容されます。 

また、この問題ではトラバース方向を選択できるため、順方向アラインメントと逆方向アラインメントの両方の方向を評価する必要があります。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 前処理なしのブルートフォース | O(n3) | お(1) | 遅すぎる |
 | フロイド + すべてのシフトをチェック | O(V3 + n2) | O(V²) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### ステップ 1: 最短の変革コストを構築する

 宝石の種類を有向グラフのノードとしてモデル化します。 コスト c の各ルール a → b は有向辺になります。 400 種類の可能なタイプに対して Floyd-Warshall を使用して、ノードのすべてのペア間の最小コストを計算します。 

このステップが必要なのは、変換が中間型を介して連鎖する可能性があり、すべてのペアの真の最小コストが必要であるためです。 

### ステップ 2: 両方のトラバース方向を準備する

 2 つのケースを別々に検討します。 順方向の場合、2 番目のシーケンスをそのまま保持します。 逆の場合は、概念的に 1 つの円の移動方向を反転します。これは、マッチング中に 1 つのシーケンスの順序を反転することに対応します。 

### ステップ 3: すべての循環シフトを列挙する

 最初のシーケンス内の考えられる開始インデックス k ごとに、s[i + k] を t[i] (mod n) と位置合わせします。 これは、開始点を固定し、両方の円を一緒に歩くことを表します。 

### ステップ 4: 固定シフトのコストを計算する

 与えられたシフト k について、すべての i にわたって dist[s[(i+k) mod n]][t[i]] を合計することで総コストを計算します。 これは、事前に計算された最短パス テーブルを直接使用します。 

### ステップ 5: すべての構成にわたって最小値を追跡する

 両方向のシフト評価を繰り返し、すべてのケースで最小値を維持します。 すべての構成で無限のコストが発生する場合は、-1 を出力します。 

### なぜ効果があるのか

 前処理後、宝石タイプ間のすべての変換は位置に依存しません。 これは、残っている唯一の構造は、変換の複雑さではなく、位置合わせであることを意味します。 すべてのアライメントは独立した位置ごとのコストに分解されるため、総コストは最適なローカル変換の合計となります。 すべての回転と両方向を徹底的にチェックすることで、2 つの円の有効な循環ペアをすべて考慮することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**18

def solve():
    n, m = map(int, input().split())
    s = list(map(int, input().split()))
    t = list(map(int, input().split()))

    MAXV = 400
    dist = [[INF] * (MAXV + 1) for _ in range(MAXV + 1)]

    for i in range(1, MAXV + 1):
        dist[i][i] = 0

    for _ in range(m):
        a, b, c = map(int, input().split())
        if c < dist[a][b]:
            dist[a][b] = c

    for k in range(1, MAXV + 1):
        dk = dist[k]
        for i in range(1, MAXV + 1):
            di = dist[i]
            dik = di[k]
            if dik == INF:
                continue
            for j in range(1, MAXV + 1):
                if dk[j] == INF:
                    continue
                nd = dik + dk[j]
                if nd < di[j]:
                    di[j] = nd

    def calc(arr_t):
        best = INF
        for shift in range(n):
            total = 0
            ok = True
            for i in range(n):
                a = s[(i + shift) % n]
                b = arr_t[i]
                d = dist[a][b]
                if d == INF:
                    ok = False
                    break
                total += d
            if ok:
                best = min(best, total)
        return best

    ans1 = calc(t)
    ans2 = calc(t[::-1])

    ans = min(ans1, ans2)
    if ans >= INF:
        print(-1)
    else:
        print(ans)

if __name__ == "__main__":
    solve()
```このソリューションは、400 x 400 の距離テーブルを構築することから始まり、それを直接変換コストで初期化します。 Floyd-Warshall は、dist[a][b] が a を b に変換するための最小コストになるように間接変換を伝播するために適用されます。 

関数 calc は、2 番目のシーケンスの 1 つの固定方向を評価します。 考えられるすべての回転に対して、n を法とするインデックスを整列させ、事前計算された dist テーブルを使用して変換コストを累積します。 変換できない位置がある場合、その設定は破棄されます。 

最後に、このプロセスを元の 2 番目のシーケンスに対して 1 回実行し、その逆のシーケンスに対して 1 回実行して、最小値を取得します。 

## 実用的な例

 n = 4 の小さな例を考えてみましょう。2 つの循環シーケンスを単純な変換ルールで比較します。 

s = [1, 2, 3, 4]、t = [1, 5, 3, 4] とし、変換により特定のコストで 2 → 5 および 5 → 3 が許可されると仮定します。 

### 順方向、シフト = 0

 | 私 | s[i] | t[i] | 費用 |
 | --- | --- | --- | --- |
 | 0 | 1 | 1 | 0 |
 | 1 | 2 | 5 | dist(2,5) |
 | 2 | 3 | 3 | 0 |
 | 3 | 4 | 4 | 0 |

 総コストは 2 を 5 に変換することによって完全に決定されます。 

このトレースは、不一致の位置だけがコストにどのように寄与するか、また最短パスの前処理によって各検索がどのように即時に行われるかを示します。 

### 逆方向、シフト = 1

 | 私 | s[(i+1)%4] | t[i] | 費用 |
 | --- | --- | --- | --- |
 | 0 | 2 | 4 | dist(2,4) |
 | 1 | 3 | 1 | dist(3,1) |
 | 2 | 4 | 5 | dist(4,5) |
 | 3 | 1 | 3 | dist(1,3) |

 この構成は、なぜ反転が重要であるかを示しています。反転すると循環構造は対称であるため、最良の位置合わせは横断方向を反転した後にのみ現れる可能性があります。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、直接的な変換は存在しないが、マルチステップ パスは存在する場合です。 Floyd の前処理により、そのようなケースも正しく処理されることが保証されます。 たとえば、1 → 2 と 2 → 3 のみが存在する場合、位置合わせ中の 1 から 3 への変換では両方のエッジが正しく使用されます。 

もう 1 つのエッジ ケースは、ある位置合わせ方向は不可能だが、その逆方向は有効である場合です。 このアルゴリズムは 2 番目のシーケンスの両方の方向を明示的に評価するため、対称性に依存しません。 

最後のケースは、すべての回転が有効であるが、最適なコストが得られるのは 1 つだけである場合です。 すべてのシフトが独立して列挙され、コストが完全に再計算されるため、ローカルな選択によりグローバルに最適なローテーションを逃すリスクがありません。
