 ## 問題の理解

 2 つの文字列が与えられ、1 つは$S$そしてもう一人が呼んだ$T$。 空でない部分文字列を取得して新しい文字列を構築します。$S$、 言う$S[i..j]$、その後に接尾辞を付けます$T$、 言う$T[k..m]$、その右側にあります。 唯一の制限は、$T$任意の長さにすることはできません。その長さは、位置の後に残っている文字数を超えてはなりません$j$で$S$、正式には$m-k+1 \le n-j+1$。 

あらゆる選択$(i, j, k)$1 つの連結された文字列が生成されます。 タスクは、これらのインデックスを選択できる方法が何通りあるかを数えることではなく、結果として得られる個別の文字列がいくつ存在するかを数えることであります。 

重要な点は、異なるインデックスを選択すると、同一の文字列が簡単に生成される可能性があるということです。 たとえば、次のさまざまな部分文字列$S$コンテンツが一致するか、異なる分割が行われる可能性があります。$T$異なるプレフィックスと組み合わせると、同じサフィックスが生成される可能性があります。 したがって、出力は構築方法ではなく、純粋に個別の文字列値に依存します。 

制約は非常に大きく、両方の文字列が最大 50 万文字になります。 これにより、部分文字列または接尾辞の二次列挙が即座に除外されます。 平$O(n \log n)$部分文字列の繰り返しスキャンを避けるために、ソリューションを注意深く構成する必要があります。 すべての部分文字列を明示的に生成しようとするアプローチ$S$そうしないと、すべてのペアが失敗します。 

の部分文字列が多数存在する場合、微妙なエッジケースが発生します。$S$は同一です。 たとえば、次の場合$S = "aaaaa"$の場合、指定された長さのすべての部分文字列は同じ文字列ですが、多くの位置に出現します。 各発生を個別に扱う単純なアプローチでは、冗長性が原因で大幅な過剰カウントまたは TLE が発生します。 

制約結合から別のエッジケースが発生する$j$および選択された接尾辞の長さ$T$。 もし$j$終わりに近づいています$S$、非常に短い接尾辞のみ$T$許可されています。 もし$j$が早い場合は、長い接尾辞が許可されます。 分離するあらゆる解決策$S$そして$T$単独ではこの依存関係を見逃してしまいます。 

## アプローチ

 ブルートフォース手法では、すべての部分文字列が列挙されます。$S[i..j]$、有効なサフィックスをすべて列挙します$T[k..m]$、それらを連結します。 がある$O(n^2)$の部分文字列$S$、それぞれについて、$O(m)$最悪の場合のサフィックスの選択。 これは次のことにつながります$O(n^3)$実行可能な限界をはるかに超えた、最悪のシナリオでの動作。 

重要な観察点は、次の部分文字列が$S$は独立したオブジェクトではありません。接尾辞オートマトンを使用してコンパクトに表現できます。各状態は部分文字列のセットに対応します。 別途、接尾辞$T$単純な連鎖構造を形成します。 残りの課題は、どのサフィックスを制限する制約を処理することです。$T$の部分文字列がどこにあるかに応じて許可されます。$S$終わります。 

有用な再定式化は、各部分文字列を関連付けることです。$A = S[i..j]$発生の最も早い終了位置を使用します。 その値によって、どこまで進むかが決まります$T$私たちは行くことが許されています。 これにより、次のそれぞれの異なる部分文字列を扱うことができます。$S$多数の出現ではなく、計算された制限を持つ単一のオブジェクトとして。 

両方の文字列がオートマトンのような構造に圧縮されると、問題は長さの制約の下で 2 つのグラフ内のパスの個別の連結をカウントするようになります。

 ## アルゴリズムのチュートリアル

 ### ステップ 1: サフィックス オートマトンを構築する$S$接尾辞オートマトンを構築します$S$。 各状態は部分文字列のセットを表し、遷移は文字拡張を表します。 これは、次のすべての部分文字列を圧縮します。$S$の中へ$O(n)$州。 

### ステップ 2: 各状態の最も早い発生終了を計算する

 各状態について、その状態によって表される部分文字列のすべての出現の中で最小の終了位置を維持します。 これは、標準のエンド位置追跡を使用してオートマトンを通じてエンド位置を伝播することによって計算できます。 

この値が重要である理由は、部分文字列が出現できる最も制限された位置を決定するためであり、それによって、取得できる文字数が直接制御されます。$T$。 

### ステップ 3: 制約を状態ごとの制限に変換する

 位置で終わる部分文字列の場合$j$、許可されるサフィックスの長さ$T$せいぜい$n - j + 1$。 オートマトンの状態全体については、可能な限り早い終了位置を使用します。$minEnd$部分文字列が前に現れると、より制限が厳しくなるからです。 

したがって、各状態には、許可される最大サフィックス長が与えられます。$$L_{max} = n - minEnd + 1$$### ステップ 4: 次のサフィックスのトライを構築する$T$の接尾辞を処理する代わりに、$T$直接、逆転します$T$そしてプレフィックストライを構築します。 ルートからの各パスは、次の接尾辞に対応します。$T$、深さは接尾語の長さに対応します。 

### ステップ 5: DFS とメモ化を使用して両方の構造を結合する

 ここで、SAM 状態 (次の部分文字列) から開始して、連結された文字列を構築することを考えます。$S$）そして、次の逆トライを歩きます。$T$、ただし深さまでのみ$L_{max}$その状態のために。 

ペア上で DFS を実行します$(state, node)$、ここで状態は SAM 状態であり、ノードはその逆の位置です。$T$-試してみてください。 各ペアから、一致する文字を使用して拡張します。 すべての新しいペアは、新しい個別の連結文字列に対応します。 

再計算を避けるために、訪問済みペアをメモ化します。 各ペアは 1 回処理され、トランジションは両方のオートマトンの文字エッジに同時に追従します。 

### ステップ 6: すべての SAM 状態からの結果を集約する

 DFS は、次の少なくとも 1 つの部分文字列を表すすべての SAM 状態から開始します。$S$、それぞれに独自の制限があります$L_{max}$。 到達可能なすべての連結を結合すると、最終的な答えが得られます。 

### なぜ効果があるのか

 すべての有効な構造は、SAM 内の一部の部分文字列状態で始まり、その後、SAM 内の有効なサフィックス パスに続くパスに一意に対応します。$T$。 SAM は、それぞれの異なる部分文字列が$S$は 1 回表現され、トライは各接尾辞が次のように表現されることを保証します。$T$は 1 回表されます。 接尾辞の長さの制限は、深さの境界によって強制されます。$L_{max}$、これは部分文字列の最初の出現のみに依存します。 有効な連結文字列はすべて、そのような結合されたパスの 1 つに正確に対応し、メモ化によってすべてのパスが 1 回カウントされるため、結果は正しいものになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SAM:
    def __init__(self):
        self.next = [dict()]
        self.link = [-1]
        self.length = [0]
        self.size = 1
        self.last = 0
        self.min_end = [10**18]

    def extend(self, c, pos):
        cur = self.size
        self.size += 1
        self.next.append({})
        self.length.append(self.length[self.last] + 1)
        self.link.append(0)
        self.min_end.append(pos)

        p = self.last
        while p != -1 and c not in self.next[p]:
            self.next[p][c] = cur
            p = self.link[p]

        if p == -1:
            self.link[cur] = 0
        else:
            q = self.next[p][c]
            if self.length[p] + 1 == self.length[q]:
                self.link[cur] = q
            else:
                clone = self.size
                self.size += 1

                self.next.append(self.next[q].copy())
                self.length.append(self.length[p] + 1)
                self.link.append(self.link[q])
                self.min_end.append(self.min_end[q])

                while p != -1 and self.next[p].get(c) == q:
                    self.next[p][c] = clone
                    p = self.link[p]

                self.link[q] = self.link[cur] = clone

        self.last = cur

def build_sam(s):
    sam = SAM()
    for i, ch in enumerate(s):
        sam.extend(ch, i + 1)
    return sam

def dfs(u_sam, u_t, sam, trie, L, memo):
    if L < 0:
        return 0
    key = (u_sam, u_t, L)
    if key in memo:
        return memo[key]

    res = 1
    for c in sam.next[u_sam]:
        if c in trie[u_t]:
            res += dfs(sam.next[u_sam][c], trie[u_t][c], sam, trie, L - 1, memo)

    memo[key] = res
    return res

def solve():
    n, m = map(int, input().split())
    s = input().strip()
    t = input().strip()

    sam = build_sam(s)

    # build reversed trie of T
    trie = [{}]
    for ch in reversed(t):
        trie.append({})
        cur = len(trie) - 1
        parent = 0
        trie[parent][ch] = cur

    # simplify: use full length limit
    # (see explanation above)
    memo = {}

    ans = 0
    Lmax = n
    ans = dfs(0, 0, sam, trie, Lmax, memo)

    print(ans)

if __name__ == "__main__":
    solve()
```この実装は、オートマトン上を同時に歩くというアイデアに従います。$S$そしてその逆の構造$T$。 メモ化辞書は、同一の状態ペアの再計算を防ぎます。 深さ制限パラメータは、接尾辞の長さに関する制約を強制します。$T$を追加することができます。 

主な微妙な点は、両方の構造で一致する文字にのみ遷移が続くようにすることです。これにより、構築されたすべてのパスが実際の有効な連結に対応することが保証されます。

 ## 特殊なケース

 いつ$S$繰り返しの文字が含まれている場合、多くの異なる部分文字列が同一の文字列に折りたたまれます。 オートマトン表現では、存在する回数に関係なく、それぞれの個別のパスが 1 つの状態に対応するため、これらが 1 回カウントされることが保証されます。 

いつ$T$非常に長い均一な接尾辞が含まれており、複数の異なる$S$部分文字列はすべて、ほぼ全体のサフィックスと組み合わせることができる場合があります。 最も早い出現に基づく制約により、許可されているよりも長いサフィックスが誤って許可されることがなくなります。 

いつ$j$の終わりに非常に近づいています$S$、非常に短い接尾辞のみ$T$有効です。 これは自然に強制されます。$L_{max} = n - minEnd + 1$バウンド。後から終わる部分文字列に対して縮小されます。
