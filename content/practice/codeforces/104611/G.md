 ## 問題の理解

 それぞれが 2 つの値で記述される項目のコレクションが与えられます。$l_i$そして$r_i$。 各アイテムをコンテナと考えることができます。コンテナには内部容量があります。$l$そして外寸$r$。 内側のアイテムの外側のサイズが外側のアイテムの内側の容量を超えない場合、あるアイテムを別のアイテムの中に入れることができます。$r_a \le l_b$。 

このタスクは、すべてのアイテムを任意に並べ替えてから、いくつかのシーケンスに分割することです。 各シーケンス内で、各項目をシーケンス内の前の項目にネストできるように、連続する項目が同じ包含条件を満たす必要があります。 各シーケンスは、外側のコンテナから始まり内側に向かうネスト チェーンとして見ることができます。 

有効なパーティションのコストは、すべてのシーケンスの合計寄与度として定義されます。各シーケンスは、最も外側の項目の外側サイズに寄与します。$r$。 目標は、この総コストを最小限に抑えることです。 可能な最小コストを見つけた後、この最小値を達成する異なる有効なパーティションの数を数えなければなりません。ここで、2 つのパーティションは、シーケンスの並べ替えによってのみ異なる場合は同じとみなされます。 

制約が大きいため、すべての並べ替えまたはすべてのパーティションを列挙することは不可能です。 まで$n = 10^5$、すべての組み合わせまたはすべての順列を探索しようとするソリューションは、組み合わせ論的に爆発します。 ペア上の二次遷移でさえ遅すぎるため、解決策はソートと貪欲なプログラミング、または近線形または動的プログラミングのような構造に縮小する必要があります。$O(n \log n)$行動。 

微妙な問題は、順序付けとグループ化はどちらも自由ですが、幾何学的な互換性条件を通じて相互作用することです。 これにより、純粋な間隔 DP ではなく、マッチングまたはチェーン分解構造が隠蔽されることがよくあります。

## アプローチ

 ブルートフォースアプローチでは、項目のあらゆる順列と、その順列をチェーンに切断するあらゆる可能な方法が試行されます。 構成ごとに、すべてのチェーンの有効性をチェックし、そのコストを計算します。 たとえ順列を修正したとしても、パーティションの数は指数関数的に増加します。$n$、チェーン全体の有効性のチェックには依然としてパーティションごとに直線的な時間がかかります。 これにより、複雑さが以前よりも速く増大します。$n!$、これはたとえ$n = 20$。

 ## アルゴリズムのチュートリアル

 ### 1. 各項目を潜在的なリンクとして解釈します

 各項目$i$アイテムの親になることができます$j$もし$r_i \le l_j$。 これは、直接的な互換性関係を定義します。 この関係はチェーンを構築するためにのみ使用します。 

コスト構造は、どの品目がチェーンのルートであるかのみを考慮することを意味します。 

### 2. コスト最小化を再定式化する

 アイテムがルートである場合、それは貢献します$r_i$総コストに。 別のアイテムの下に取り付けられている場合、直接的には何も寄与しません。 

したがって、総コストを最小化することは、次の合計を最小化することと同じです。$r_i$これは、有効な親子関係において子として正常にアタッチされるアイテムの数を最大化することと同じです。 

ただし、各項目は親を 1 つだけ持つことができ、互換性を考慮する必要があるため、添付ファイルは任意ではありません。 

### 3. 項目を並べ替えて実現可能性を制御する

 アイテムを増加順に並べ替えます$l$。 これにより、項目を処理するときに、その項目を含む可能性のあるすべての親が制御された順序で表示されるようになります。 

貪欲なデータ構造を使用して、利用可能な親を維持します。 

### 4. 子と最も利用可能な親との貪欲なマッチング

 項目を昇順に処理します$l$。 項目ごとに$j$、以前に見た項目の親として割り当てようとします。$i$と$r_i \le l_j$。 このようなすべての有効な親の中で、最も制約の大きいものを選択することは、将来の柔軟性を維持するために重要です。 

これは、常に実行可能な最小の残存容量を最初に割り当てる構造を使用して実装されます。 

### 5. DP を使用して最適な割り当てを数える

 貪欲な構築と並行して、特定の最適なマッチングを形成できる方法の数を追跡する DP 状態を維持します。 

子に対して複数の親が有効な場合、最適性を維持するすべての選択肢をカウントする必要があります。 DP は同等の州からの拠出を集約します。 

### 6. 最終的な答えを計算する

 マッチングが完了すると、一致しないすべてのノードがルートとして識別されます。 最小コストはそれらの合計です$r$価値観。 DP の結果は、このコストと一致する最大のマッチングを達成する方法の数を示します。 

### なぜ効果があるのか

 この変換により、問題はシーケンスの分割の問題から、各ノードが最大 1 つの出力エッジと 1 つの入力エッジを持つフォレスト構築の問題に軽減されます。 目的は、次のように重み付けされたルートの数を最小限に抑えることになります。$r$これは、有効な添付ファイルを最大化することと同じです。 

による貪欲な注文$l$実現可能性が常にプレフィックス一貫性のある方法でチェックされるようにします。 依存関係は元の順序ではなく不等式にのみ依存するため、最適解は妥当性やコストを変更することなくこの順序に並べ替えることができます。 これにより、ソート時にマッチング構造が安定します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n = int(input().strip())
    a = [tuple(map(int, input().split())) for _ in range(n)]

    # sort by inner capacity l
    a.sort(key=lambda x: x[0])

    # We maintain available "parents" as (r, count)
    # using a simple list since constraints imply O(n log n) alternative structure in full solution
    import bisect

    parents = []  # sorted by r
    ways = []     # parallel counts

    def add_parent(r, w):
        i = bisect.bisect_left(parents, r)
        if i < len(parents) and parents[i] == r:
            ways[i] = (ways[i] + w) % MOD
        else:
            parents.insert(i, r)
            ways.insert(i, w)

    def pop_valid(l):
        # all parents with r <= l are usable
        i = bisect.bisect_right(parents, l)
        usable = parents[:i]
        wsum = sum(ways[:i]) % MOD
        del parents[:i]
        del ways[:i]
        return wsum

    total_ways = 1
    for l, r in a:
        # try to attach current node as child
        w = pop_valid(l)
        if w == 0:
            # becomes a new root
            total_ways = total_ways * 1 % MOD
            add_parent(r, 1)
        else:
            # it can attach in w ways; DP merges choices
            total_ways = total_ways * w % MOD
            add_parent(r, w)

    print(total_ways % MOD)

if __name__ == "__main__":
    solve()
```コードは、潜在的なチェーン エンドポイントの動的なセットを維持します。 アイテムを処理するたびに、外部サイズが現在の内部容量に適合する、現在有効なすべての親を収集します。 存在しない場合、アイテムは新しいチェーンを開始する必要があります。 それ以外の場合は、最適な構築の数に乗算的に寄与します。 

重要な点は、私たちが世界的に単一の親にコミットすることは決してないということです。 代わりに、すべての最適な構成が保持されるようにカウントを集計します。
