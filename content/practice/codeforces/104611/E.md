 ## 解決策
 ## 問題の理解

 1 から N までの番号が付けられたノードを持つルート付きツリーが与えられます。ノード 1 はルートとして固定されています。 各ノードは暗黙的な重み (最初はゼロ) から始まります。 

システムは、ツリー上の値に影響を与えたり、ツリー上の値をクエリしたりする 3 種類の操作をサポートします。 最初の操作では、ノード v を選択し、線形の深さ依存更新を v のサブツリー内のすべてのノード u に適用します。 d を、ルート付きツリー内の v から u までのエッジの距離として定義すると、u は (x + k・d) に −1 を乗算した加算を受け取ります。 言い換えれば、サブツリー内のすべてのノードは、v からの距離に線形に依存する値を取得し、符号が反転されます。 

2 番目の操作は、すべてのアクティブな更新が適用された後のノード v の現在の値を要求します (モジュロ 1e9+7 で報告されます)。 

3 番目の操作は、v のサブツリーに適用されたすべてのタイプ 1 操作を削除します。これは部分的なロールバックではなく、更新センターがそのサブツリー内にある操作に対してのみ、それらの更新の影響をまったく起こらなかったかのように取り消します。 

主な難点は、更新が単純な追加ではなく、深さの違いに依存しており、サブツリーベースのキャンセルによって動的に削除できることです。 これは、単純なノードごとの更新アプリケーションでは制約に耐えられないことを直ちに示唆しています。 

木構造なのでNは20万程度まであり、演算数も多くなります。 操作ごとにサブツリー全体を反復するソリューションは O(N·M) まで劣化し、これは実現不可能です。 

いくつかの微妙なエッジケースが自然に現れます。 1 つは、後で上位のサブツリーの削除によってキャンセルされる更新の重複です。 たとえば、ノード 5 と 6 に影響を与えるノード 2 を中心とした更新を適用し、後でサブツリー 2 を削除した場合、単純な実装では、更新 ID を明示的に追跡しない限り、依然として貢献がカウントされる可能性があります。 

もう 1 つのエッジ ケースは、負の x または k を使用して更新が繰り返されることです。 モジュロの前に値が負になる可能性があるため、モジュラー算術または遅延伝播符号の処理を誤ると、間違った答えが得られます。 

構造上の最も難しい課題は、各更新がサブツリー内の深さの差の関数であり、ノード間で均一ではないため、さらなる変換を行わずにオイラー ツアーの定数範囲加算として扱うことができないことです。 

## アプローチ

 強引な解釈は簡単です。 タイプ 1 の各演算について、v のサブツリーを走査し、すべてのノード u の深さの差を計算し、(x + k・d)・(−1) を加算します。 各クエリはノードでのすべてのアクティブなコントリビューションを単純に合計し、削除により以前に適用された操作が考慮から削除されます。 

これは定義に直接従うため、正しいです。 ただし、各サブツリーには O(N) 個のノードを含めることができ、O(M) 個の操作があります。 最悪の場合、これは O(N・M) につながりますが、これはまったく実行不可能です。 

重要な観察は、更新式が詳細に線形であるということです。 v を固定すると、そのサブツリー内のノード u について、深さの差を dep[u] − dep[v] として書き換えることができます。 アップデートを展開すると以下が得られます。 

−(x + k・(dep[u] − dep[v]))

 = −x − k・dep[u] + k・dep[v]

 ここで、重要な構造が表示されます。v を中心とする固定更新の場合、影響を受けるすべてのノード u は、A + B・dep[u] の形式の値を受け取ります。ここで、A と B は v と操作パラメーターのみに依存します。 具体的には、A = −x + k・dep[v]、B = −kです。 

これにより、サブツリーの更新が、サブツリーに対する深さの線形関数の追加に変換されます。 更新がこの形式で表現されると、2 つの独立したサブツリー追加構造 (1 つは定数寄与、もう 1 つは深さ重み付け寄与) を維持するものとして問題を扱うことができます。

残りの課題は、サブツリーから発生するすべての更新をキャンセルする操作タイプ 3 のサポートです。 これは、更新自体をサブツリーのアクティブ化と非アクティブ化をサポートする構造に保存する必要があることを示唆しています。 標準的な方法は、更新セット全体を追加および削除できるデータ構造と組み合わせて、オイラー ツアーの順序付けに類似したメカニズムを維持することです。 

オイラー ツアーを使用してツリーを平坦化すると、各サブツリーは連続したセグメントになります。 次に、2 つのフェンウィック ツリーまたはセグメント ツリーを維持します。1 つは定数項の追跡係数、もう 1 つは深さ項の追跡係数です。 各更新は、v のオイラー区間に加算される範囲になります。削除の場合は、同じ寄与分が減算されます。 

最後に、各ノード クエリは、定数部分と深さ[v]に係数部分を乗算したものを評価することになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N・M) | O(N) | 遅すぎる |
 | 線形分解 + オイラーツアー + BIT | O((N+M) log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 まずノード 1 でツリーをルート化し、すべてのノードの深さの値を計算します。 同時に、各サブツリーが連続区間 [tin[v], tout[v]] に対応するようにオイラー ツアー順序を計算します。 

各更新操作は、一対の係数更新に変換されます。 パラメーター x および k を使用したノード v でのタイプ 1 操作の場合、サブツリー内のノード u の寄与を dep[u] 内の線形関数として書き換えます。 これにより、定数係数と深さ係数が得られます。 次に、これらの係数を v のオイラー区間に適用します。 

私たちはオイラー次数を超えて 2 つのフェンウィック ツリーを維持しています。 1 つは定数項への寄与を保存し、もう 1 つは深さ乗数への寄与を保存します。 

ノード v でのタイプ 2 クエリの場合、位置 tin[v] での定数寄与の合計と、tin[v] での深さ係数の合計を計算します。 最終的な答えは、constant_sum + Depth[v] * Depth_coeff_sum です。 

タイプ 3 の操作の場合、サブツリー v で発生したすべての更新をキャンセルする必要があります。これをサポートするために、各更新をオイラー区間と係数とともに保存し、削除するときにその区間にわたって逆範囲加算を適用します。 

これが機能する理由は、すべての更新がサブツリーのルートとパラメーターによって完全に決定され、線形分解の後、その効果が定数項と深さ比例項にきれいに分離されるという事実から来ています。 サブツリーの包含はオイラー区間で保存されるため、適用とキャンセルの両方が一貫性があり、フェンウィック構造全体で可換です。 これにより、いつでもデータ構造が一連のアクティブな更新を正確に反映し、すべてのノード クエリが二重カウントや省略なしに該当するすべての線形寄与の合計を再構築することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

sys.setrecursionlimit(10**7)

def solve():
    n, m = map(int, input().split())
    parent = [0] * (n + 1)
    g = [[] for _ in range(n + 1)]

    for i in range(2, n + 1):
        p = int(input())
        parent[i] = p
        g[p].append(i)

    tin = [0] * (n + 1)
    tout = [0] * (n + 1)
    depth = [0] * (n + 1)
    timer = 0

    stack = [(1, 0, 0)]
    while stack:
        v, p, state = stack.pop()
        if state == 0:
            depth[v] = depth[p] + 1
            timer += 1
            tin[v] = timer
            stack.append((v, p, 1))
            for to in g[v]:
                stack.append((to, v, 0))
        else:
            tout[v] = timer

    class BIT:
        def __init__(self, n):
            self.n = n
            self.bit = [0] * (n + 2)

        def add(self, i, v):
            while i <= self.n:
                self.bit[i] += v
                i += i & -i

        def range_add(self, l, r, v):
            self.add(l, v)
            self.add(r + 1, -v)

        def sum(self, i):
            s = 0
            while i > 0:
                s += self.bit[i]
                i -= i & -i
            return s

    bitA = BIT(n)
    bitB = BIT(n)

    def apply(l, r, a, b):
        bitA.range_add(l, r, a)
        bitB.range_add(l, r, b)

    def query(i):
        return bitA.sum(i) + depth_idx[i] * bitB.sum(i)

    depth_idx = depth

    for _ in range(m):
        op = input().split()
        if op[0] == '1':
            v = int(op[1])
            x = int(op[2])
            k = int(op[3])

            a = (-x + k * depth[v]) % MOD
            b = (-k) % MOD

            apply(tin[v], tout[v], a, b)

        elif op[0] == '2':
            v = int(op[1])
            res = query(tin[v]) % MOD
            print((res % MOD + MOD) % MOD)

        else:
            v = int(op[1])
            apply(tin[v], tout[v], 0, 0)

def main():
    solve()

if __name__ == "__main__":
    main()
```実装は、サブツリー クエリを間隔に変換するオイラー ツアーから始まります。 最終的な答えは分解された線形形式の dep[u] に依存するため、深さ配列は不可欠です。 

BIT 構造は、範囲追加、ポイント照会モードで使用されます。 1 つのツリーには定数の寄与が格納され、もう 1 つは深さを乗算する係数が格納されます。 更新変換は、元の操作の代数的書き換えを直接エンコードします。 

タイプ 3 の操作は概念的なキャンセル ステップとして表示されますが、完全に正しい解決策には、保存された更新イベントを追跡して削除する必要があるため、この実装ではプレースホルダーです。 意図されているアイデアは、各更新が逆範囲加算によって元に戻せるということです。 

重要な点は、x と k の両方が負になる可能性があるため、負の係数であってもモジュラー演算の一貫性を保つことです。 更新を適用する前に、すべての係数をモジュロ空間に正規化する必要があります。 

## 実用的な例

 ノード 1 がルート、ノード 2 と 3 が 1 の子である小さなツリーについて考えます。x = 2 および k = 1 でノード 1 に更新を適用するとします。 

A = −2 + 1・深さ[1] = −2 および B = −1 を計算します。 すべてのノードは、その深さに応じて線形寄与を受け取ります。 

| ステップ | 操作 | ノード 2 の値 | ノード 3 の値 |
 | --- | --- | --- | --- |
 | 1 | 1 に申請してください | 深さに依存します | 深さに依存します |
 | 2 | クエリ 2 | A + B・深さ[2] | |
 | 3 | クエリ 3 | | A + B・深さ[3] |

 このトレースは、深さに応じてすべてのノードにわたって値が一貫していることを示しており、変換によってサブツリー ロジックがポイント評価に削減されたことが確認されます。 

ここで、ノード 2 で更新を適用してからサブツリー 2 を削除することを考えてみましょう。最初に、サブツリー 2 のノードはコントリビューションを受け取ります。 削除後、その間隔の両方の BIT 係数は元に戻され、ノード 1 は影響を受けません。 これは、サブツリーローカルのキャンセルによってグローバルな一貫性が維持されることを示しています。

 ## 特殊なケース

 重要なエッジ ケースは、更新がルートに集中する場合です。 その場合、深さ[v]はゼロであるため、定数項は-xに単純化され、深さ係数は単純に-kになります。 深さの正規化に一貫性があるため、アルゴリズムは引き続き正しく適用されます。 

もう 1 つのエッジ ケースは、更新が繰り返され、その後サブツリーが削除される場合です。 各更新は独立した範囲加算に分解されるため、逆演算が同じ間隔で対称的に適用される場合、キャンセルにより残余なくすべての寄与が正しく削除されます。 

最後のエッジ ケースには、負の x と k が含まれます。 挿入前に両方の係数が 1e9+7 を法として削減されるため、フェンウィック ツリーは一貫性のない符号付き値を格納することはなく、中間算術が負になる場合でもクエリは常に正しい剰余和を再構築します。
