 ## 解決策
 ## 問題の理解

 一連の学生が与えられ、それぞれがシステムの処理中に変化する信頼値に関連付けられています。 いつでも、一部の学生は肯定的な信頼を持っていると考えられます。私たちは 2 つのことに興味があります。現在肯定的な信頼を持っている学生の数と、調整された貢献の合計です。 

各生徒には初期の信頼値があり、以前の更新から得られたグローバルな累積量もあります。 便宜上、実行値を定義します。$d_i$、これは現時点までの全体的な更新にのみ依存し、個々の学生には依存しません。 学生が肯定的な信頼を持っている場合、答えに対する学生の貢献度は、現在の信頼値からこのグローバル オフセットを引いたものになります。$d_i$。 

重要な構造は、すべてのアクティブな生徒が同じ減算項を共有することです。$d_i$したがって、すべてのアクティブな学生の貢献を合計する場合、このグローバル用語は、アクティブな学生の数と、$d_i$。 これは、すべての学生について個別にシフトされた値を明示的に追跡する必要はなく、誰がまだアクティブであるか、およびその生の信頼値の合計が何であるかについての情報を集約するだけであることを意味します。 

入力は、信頼値を変更するか、グローバル状態を進める一連の更新として解釈できます。 出力はすべての操作を処理した後に計算され、正に調整された信頼を持つ生徒の数と対応する合計が報告されます。 

制約の観点からは、意図したソリューションは次のように実行されます。$O(n \log n + q)$、これは約までを示唆しています$2 \cdot 10^5$更新と組み合わせた要素。 これにより、更新ごとにすべての生徒をスキャンする二次シミュレーションが即座に除外されます。 操作ごとにすべてのアクティブな状態を繰り返し再計算するアプローチでは、おおよその値に達します。$10^{10}$最悪の場合は操作が不可能になります。 

グローバル更新のたびに各生徒に対して調整された信頼値を熱心に再計算しようとすると、微妙な失敗例が発生します。 たとえば、すべての生徒が大きな信頼値から始めても、グローバル オフセットが徐々に増加する場合、単純なアプローチではすべての値が繰り返し減少する可能性があります。 

小さな例でこれを明らかにします。 信頼値 10、9、8 を持つ 3 人の生徒がいて、グローバル オフセットが 7 になるとします。正しいアクティブ セットは、各値が 7 を超えるかどうかにのみ依存するため、3 つすべてが正のままです。 ただし、単純な反復減算の実装では、論理条件が共有値との比較のみに依存している場合でも、操作ごとに各スチューデントが繰り返し更新され、パフォーマンスが低下する可能性があります。 

もう 1 つの落とし穴は、学生が削除されたり非アクティブになったときに発生します。集計で学生の貢献度を正しく考慮しないと、二重にカウントされたり、最終結果に古い値が含まれたりすることになります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 システムを直接シミュレートします。 操作ごとに、影響を受けるすべての生徒の信頼値を更新し、どれがプラスのままであるかを再計算して、貢献度の数と合計の両方を最初から再計算します。 これはプロセスの定義に直接従うため機能しますが、再計算のたびにすべての生徒がスキャンされます。 と$n$学生と$q$操作、これは次のことにつながります$O(nq)$、最悪の場合、入力構造に応じて 2 次から 3 次スケールになります。 で$n = 2 \cdot 10^5$、操作ごとに 1 回のフル スキャンでもすでに大きすぎます。 

重要な観察は、すべてのアクティブな学生がグローバル オフセットによって同様に影響を受けるということです。$d_i$。 これは、アクティブな学生の生の信頼値の合計と、アクティブな学生の数という 2 つのことだけを維持する必要があることを意味します。 これらが分かれば、合計貢献度は減算して得られます。$d_i \times s$、 どこ$s$はアクティブな学生の数です。 次に、問題は、動的に変化する値のセットを維持することに帰着します。要素は、によって定義された現在のしきい値を下回ると削除されます。$d_i$。 

これはまさに、最小ヒープが効率的にキャプチャするタイプの構造です。 私たちは常に、現役の学生の間で最小の信頼値を知りたいと考えています。 最小値がしきい値を下回る場合$d_i$、最小値が条件に失敗すると、現在のアクティブ セットが無効になる可能性があるという意味で、すべての寄与は単調であるため、これを削除する必要があります。 この削除プロセスを繰り返すことで、有効なスチューデントのみが残り、各スチューデントは最大 1 回挿入および削除され、償却対数計算量が得られます。 

別の観点としては、信頼度に基づいてすべての学生を並べ替え、しきい値が増加する順に処理することです。 これは、しきい値が単調な場合にも機能しますが、ヒープのアプローチはより一般的であり、動的な更新と一致します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(nq)$|$O(n)$| 遅すぎる |
 | 最小ヒープのメンテナンス |$O(n \log n + q)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは、信頼値とアクティブな学生の数の累計とともに、信頼値に基づいて候補学生の最小ヒープを維持します。 グローバルオフセットも追跡します$d_i$。 

1. 空の最小ヒープ、変数を初期化します。`active_sum = 0`、 そして`active_count = 0`。 これらは現在のアクティブ セットを表します。 
2. 各生徒の信頼値をヒープに挿入して処理し、両方の値をインクリメントします。`active_sum`そして`active_count`それに応じて。 これにより、最初の候補者プールが構築されます。 
3. グローバル更新を処理する際に、現在のオフセットを維持します。$d_i$。 この値は、学生が有効であり続けるために必要な最小の信頼しきい値を表します。 
4. 更新するたびに、ヒープ内の最小の信頼値を繰り返し検査します。 それが厳密に以下によって引き起こされる無効化条件以下である場合、$d_i$、ヒープからそれを削除し、から減算します。`active_sum`、減少しながら`active_count`。 この手順により、無効な生徒がアクティブ セットに残らないようにします。 
5. ヒープが空になるか、最小の要素がアクティブ状態を維持するための条件を満たすまで、削除を続けます。 
6. 安定に達したら、次を使用して答えを計算します。`active_sum - active_count * d_i`寄付総額とレポート`active_count`アクティブな学生の数として。 

除去ループは中心的な決定点です。 現在の基準を下回ると学生が無効であることが証明された場合にのみ削除されます。 これにより、正確性が保証されながら、不必要な再計算が回避されます。 

### なぜ効果があるのか

 このアルゴリズムは一貫した不変条件を維持します。つまり、現在ヒープ内にあるすべての要素が、現在のグローバル オフセットの下でアクティブであると見なされるために必要な条件を満たします。 この条件に違反する要素は、残りの信頼値の最小値であるため、最小ヒープの先頭になければなりません。そのため、失敗した場合、正確性を維持するためのより小さい候補は存在しません。 各要素は最大 1 回削除されるため、ヒープ操作の総数はスチューデントの数に比例し、各操作には対数的な時間がかかります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import heapq

def solve():
    n, q = map(int, input().split())
    arr = list(map(int, input().split()))

    heap = []
    active_sum = 0
    active_count = 0

    for x in arr:
        heapq.heappush(heap, x)
        active_sum += x
        active_count += 1

    d = 0

    for _ in range(q):
        typ, val = map(int, input().split())

        if typ == 1:
            d += val
        else:
            heapq.heappush(heap, val)
            active_sum += val
            active_count += 1

        while heap and heap[0] <= d:
            x = heapq.heappop(heap)
            active_sum -= x
            active_count -= 1

        if active_count <= 0:
            print(0, 0)
        else:
            print(active_count, active_sum - active_count * d)

def main():
    solve()

if __name__ == "__main__":
    main()
```コードはグローバル オフセットを保持します`d`これは、すべての学生に適用される累積シフトを表します。 挿入のたびにヒープと集計合計の両方が更新されるため、後でシフトされた合計を一定時間内に再構築できます。 ヒープにより、常に最小の違反要素が最初に削除されます。削除が必要かどうかを判断できるのは最小の要素だけであるため、これが必要です。 

引き算`active_sum - active_count * d`重要な再構築ステップです。 保存されているすべての値を調整するのではなく、オフセットの適用を遅らせ、クエリ時に一度計算します。 これにより、更新の繰り返しが回避され、ソリューションの効率が維持されます。 

ヒープからポップされるループは、各要素が 1 回挿入され、1 回削除され、償却対数動作が保証されるため安全です。 

## 実用的な例

 初期配列を考えてみましょう`[5, 3, 10]`グローバル オフセットを増やす更新が含まれます。 

開始時のヒープは`[3, 5, 10]`、合計は 18、カウントは 3、そして`d = 0`。 

| ステップ | 操作 | ヒープ | d | アクティブな数 | アクティブ合計 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 初期化 | [3,5,10] | 0 | 3 | 18 |
 | 2 | +2 から d | [3,5,10] | 2 | 3 | 18 |
 | 3 | <= d | を削除します。 [5,10] | 2 | 2 | 15 |

 3 を削除した後、残りの要素は有効になります。 答えは2となり、$15 - 2 \cdot 2 = 11$。 

このトレースは、最小の要素のみがチェックされ、それが削除されると、それ以上のカスケード削除は必要ないことを示しています。 

次に、挿入の場合を考えます。空から開始し、次に 4、1、6 を挿入し、徐々にオフセットを増やします。 

| ステップ | 操作 | ヒープ | d | アクティブな数 | アクティブ合計 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | +4 | [4] | 0 | 1 | 4 |
 | 2 | +1 | [1,4] | 0 | 2 | 5 |
 | 3 | +6 | [1,4,6] | 0 | 3 | 11 |
 | 4 | d += 3 | [1,4,6] | 3 | 3 | 11 |
 | 5 | <= d | を削除します。 [4,6] | 3 | 2 | 10 |

 これは、挿入としきい値の増加がどのようにきれいに相互作用するかを示しています。無効な要素は、必要な場合にのみ遅延して削除されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(n \log n + q \log n)$| 各要素はヒープに 1 回挿入され、1 回ヒープから削除されます。各操作には対数時間がかかります。 
| スペース |$O(n)$| ヒープには、多くてもすべてのアクティブまたは保留中の要素が格納されます。 

複雑さは、最大で一般的な制約内に快適に収まります。$2 \cdot 10^5$これは、最悪の場合の挿入と削除のシーケンスでもヒープ操作の効率が維持されるためです。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import heapq

    n, q = map(int, input().split())
    arr = list(map(int, input().split()))

    heap = []
    s = 0
    c = 0
    d = 0

    for x in arr:
        heapq.heappush(heap, x)
        s += x
        c += 1

    out = []
    for _ in range(q):
        t, v = map(int, input().split())
        if t == 1:
            d += v
        else:
            heapq.heappush(heap, v)
            s += v
            c += 1

        while heap and heap[0] <= d:
            x = heapq.heappop(heap)
            s -= x
            c -= 1

        if c <= 0:
            out.append("0 0")
        else:
            out.append(f"{c} {s - c*d}")

    return "\n".join(out)

# custom cases
assert run("3 3\n5 3 10\n1 2\n1 1\n1 5") is not None
assert run("1 2\n1\n1 1\n1 1") is not None
assert run("2 2\n1 100\n2 50\n1 60") is not None
assert run("5 1\n1 2 3 4 5\n1 10") is not None
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 小さな配列、しきい値を増加 | 有効な減少アクティブ セット | ヒープ削除の正確性 |
 | 単一要素 | 安定したエッジ動作 | 構造体を空にする処理 |
 | 挿入と更新の混合 | 動的一貫性 | 更新とヒープの相互作用 |
 | 大きなしきい値 | 完全除去ケース | すべての要素が非アクティブになります |

 ## 特殊なケース

 グローバル オフセットが十分に大きくなり、すべての学生が無効になる場合、重大なエッジ ケースが発生します。 入力用`[2, 3, 5]`大幅な増分で、たとえば$d = 10$、ヒープは最終的にすべての要素をポップします。 while ループがヒープを空にして最終チェックを行うため、アルゴリズムはこれを正しく処理します。`active_count <= 0`を引き起こします`(0, 0)`出力。 

もう 1 つの微妙なケースは、オフセットが既に大きくなった後に小さな値が繰り返し挿入されることです。 たとえば、次の場合$d = 100$そして値を挿入します`[1, 2, 3]`、新しい挿入はそれぞれ、クリーンアップ ループ中にすぐに削除されます。 ヒープには無効な要素が保持されることはないため、遡って修正する必要がなく、状態は一貫したままになります。 

最後に、すべての値が等しく、オフセットが徐々に増加すると、削除はバッチで行われます。 のために`[5, 5, 5, 5]`そして繰り返される増分$d$、各増分は一度に複数の要素を削除する可能性があります。 不変式により、順序がヒープ内に保持され、すべての要素が同一であるため、隠れた順序の問題が発生しないため、バッチ削除が安全であることが保証されます。
