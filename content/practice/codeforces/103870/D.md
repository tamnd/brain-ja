 ## 解決策
 ## 問題の理解

 n 行 m 列の整数の長方形グリッドが与えられます。 各セルは値を提供し、関数 f(a, b, c, d) を使用して任意の部分四角形の合計を計算できます。これは、行 a ～ b および列 c ～ d のすべてのセルを合計することを意味します。 

グリッド内の位置 (x, y) には、特別なセルが 1 つだけあります。 ステートメントでは負の数として説明されていますが、このセルの重要な役割は、行または列に沿ってグリッドを分割することでその影響を除去することを検討できることです。 

このタスクは、5 つの特定の長方形の合計の最大値を計算することです。つまり、グリッド全体の合計、行 x より上の上部の合計、行 x より下の下部の合計、列 y の前の左側の部分の合計、列 y の後の右側の部分の合計です。 

言い換えれば、領域を結合しているのではなく、これら 5 つの長方形の候補から 1 つを選択し、それらの中で最良の合計を求めています。 

入力サイズは n × m グリッドを意味します。 部分行列の合計を繰り返し行うと、各四角形を最初から直接計算すると時間がかかりすぎます。 注目すべき自然な制約は、n と m が O(nm) の前処理が必要になるほど十分に大きい可能性があるが、クエリごとの再計算は O(1) かそれに非常に近い値でなければならないということです。 

よくある失敗例は、許可された領域のジオメトリを誤解していることに起因します。 許可される領域は任意の部分行列ではなく、水平または垂直に分割されたグリッドの半分全体です。 

たとえば、誤って行と列を同時に削除して領域を結合しようとすると、許可されたセットの一部ではない、左上と右下などを誤って計算してしまう可能性があります。 この問題では、幅全体または高さ全体に揃えられた単一の連続する長方形のみが許可されます。 

## アプローチ

 ブルートフォース解釈では、含まれるすべてのセルを合計することによって、5 つの候補四角形のそれぞれを直接計算します。 各四角形はグリッド全体と同じ大きさになる可能性があるため、クエリごとにコストは O(nm) です。 候補が 5 つある場合、これは評価ごとに O(nm) になり、依然として O(nm) ですが、複数のテスト ケースが存在する場合、または合計を繰り返し再計算する場合、全体としては遅くなりすぎます。 

重要な観察は、すべての候補値がプレフィックスのような、またはサフィックスのような全幅または全高の部分行列であるということです。 この構造により、グリッド上の 2D プレフィックス合計を事前計算できます。 プレフィックスの合計が利用可能になると、任意の長方形の合計 f(a, b, c, d) を O(1) で計算できます。 

次に、問題は、それぞれが軸に揃えられた大きな長方形を記述する 5 つの固定式を評価することに帰着します。 プレフィックス合計は、線形スキャンを定数時間ルックアップに変換し、前処理後の解は候補ごとに効果的に O(1) になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | クエリあたり O(nm) | お(1) | 遅すぎる |
 | プレフィックスの合計 | O(nm) 前処理、O(1) クエリ | O(nm) | 承認済み |

 ## アルゴリズムのチュートリアル

1. グリッドを読み取り、すべての値を 2D 配列に保存します。 問題の構造上、高速な長方形和クエリをサポートする必要があるため、直接計算ではなく前処理の準備をします。 
2. 2D プレフィックス合計配列 pref を構築します。ここで、pref[i][j] には、(1,1) から (i,j) までの部分行列内のすべての値の合計が格納されます。 このステップは、包含排他を使用して四角形の合計を定数時間の式に変換するため、不可欠です。 
3. プレフィックス合計を使用して f(a, b, c, d) を計算するヘルパー関数を定義します。 この関数は、pref[b][d] から除外された上、左、およびオーバーラップ領域を差し引いて計算し、O(1) 内の四角形の合計を取得できるようにします。 
4. f(1, n, 1, m) を使用してグリッド全体の合計を計算します。 これは 5 つの候補のうちの 1 つであり、何も除外しない場合を表します。 
5. 上部の合計を f(1, x−1, 1, m) として計算します。 これは、厳密に特別な行より上の行のみを保持することに対応します。 
6. 下部の合計を f(x+1, n, 1, m) として計算します。 これは、厳密に特別な行の下の行のみを保持することに対応します。 
7. 左部分の合計を f(1, n, 1, y−1) として計算します。 これは、特別な列の厳密に左側の列のみを保持することに対応します。 
8. 右側の部分の合計を f(1, n, y+1, m) として計算します。 これは、特別な列の厳密に右側の列のみを保持することに対応します。 
9. これら 5 つの値の最大値を返します。 各候補は有効な許可された構成を表しており、その中から最適なものを選択しています。 

機能する理由: 許可されるすべての構成は、x 行または y 列に沿って最大 1 回切断することによって決定され、グリッドの全幅または全高にまたがる軸が整列した 1 つの長方形です。 プレフィックス合計は、そのような各四角形の合計が重複や欠落なく正確に 1 回計算されることを保証します。また、すべての有効な候補を明示的に評価するため、より良い解を見逃すことはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    grid = [list(map(int, input().split())) for _ in range(n)]
    x, y = map(int, input().split())

    pref = [[0] * (m + 1) for _ in range(n + 1)]

    for i in range(1, n + 1):
        row_sum = 0
        for j in range(1, m + 1):
            row_sum += grid[i - 1][j - 1]
            pref[i][j] = pref[i - 1][j] + row_sum

    def rect(a, b, c, d):
        if a > b or c > d:
            return 0
        return (
            pref[b][d]
            - pref[a - 1][d]
            - pref[b][c - 1]
            + pref[a - 1][c - 1]
        )

    ans = rect(1, n, 1, m)
    ans = max(ans, rect(1, x - 1, 1, m))
    ans = max(ans, rect(x + 1, n, 1, m))
    ans = max(ans, rect(1, n, 1, y - 1))
    ans = max(ans, rect(1, n, y + 1, m))

    print(ans)

if __name__ == "__main__":
    solve()
```実装は 2D プレフィックス合計テーブルを中心としています。 各行はまず実行中の行合計に累積され、次に前の行の値を使用してプレフィックス構造にマージされます。 これにより、合計の繰り返しが回避され、O(nm) の前処理が保証されます。 

rect 関数は、標準的な包含/除外計算です。 x−1 や y+1 のようなスライスでは空の四角形が生成される可能性があるため、無効な範囲の境界チェックが必要です。これは、プレフィックス インデックス付けを破壊するのではなく、ゼロを寄与する必要があります。 

各候補四角形は、このヘルパーを使用して直接評価され、最大値は段階的に維持されます。

 ## 特殊なケース

 エッジ ケースの 1 つは、x または y が境界線上にあり、いくつかの候補四角形が空になる場合です。 たとえば:

 入力:```
2 3
1 2 3
4 -5 6
1 2
```ここで x = 1 であるため、上部の長方形 (1, x−1, 1, m) は無効です。 この場合、アルゴリズムは 0 を返します。これにより、最大値に誤って影響を与えないことが保証されます。 残りの候補は通常どおり計算され、最終的な答えは有効な領域のみから取得されます。 

別のケースは、グリッドが 1 行または 1 列など非常に小さい場合に発生します。 このような場合、複数の候補が同じ長方形または空の長方形に折りたたまれます。 rect 関数は範囲外の間隔を安全に処理し、インデックス付けエラーがなく、正確性を維持するため、プレフィックス合計ロジックは引き続き適用されます。
