 ## 解決策
 ## 問題の理解

 x 軸上の間隔として考えることができる水平または斜めの「道路」のセットが与えられ、それぞれの道路には高さを表す y 座標が与えられます。 また、特定の最小 y レベルを超えたまま、ある x 位置から別の x 位置に移動できるかどうかを尋ねるクエリも提供されます。 

クエリは次のように解釈できます。 X 軸上の区間のどこかから開始し、その右側の別の区間に到達したいと考えています。 移動は、y 値が十分に高い道路によって「覆われた」位置を通過する場合にのみ許可されます。 クエリは、移動の開始点と終了点の間のすべての x 座標について、その x をカバーする高さが少なくとも必要なしきい値である道路が少なくとも 1 つ存在する場合に有効です。 

したがって、各クエリは基本的に、x 間隔に沿った最小の「利用可能な最良の道路の高さ」が少なくとも何らかの値であるかどうかを尋ねています。 

制約が十分に大きいため、すべての道路またはすべての X 位置に対する単純なクエリごとのスキャンは不可能です。 更新とクエリを組み合わせると最大 200,000 件になる場合、クエリごとに O(n) に達するソリューションは制限を数桁超えます。 これは、高速範囲更新と高速範囲最小クエリをサポートするデータ構造が必要であることを直ちに示唆しています。 

複数の道路が x では重なっているが、y では異なる順序で到着する場合、微妙なエッジ ケースが発生します。 道路を任意の順序で処理する単純なアプローチでは、より良い道路をより悪い道路で誤って上書きしたり、到達可能な最大の y のみが重要であることを強制できなかったりする可能性があります。 

別の特殊なケースは、クエリ間隔が道路によって部分的にのみカバーされている場合に発生します。 範囲内の最小値がしきい値を下回る可能性があるため、カバーされていない x 位置が 1 つでもあるとクエリは無効になります。 これにより、エンドポイントまたはサンプル ポイントをチェックするだけでは不十分になります。 

## アプローチ

 ブルート フォース戦略では、各クエリを個別に処理します。 しきい値 b の区間 [l, r] について尋ねるクエリの場合、その区間内のすべての x 位置をスキャンし、各位置をカバーするすべての道路をチェックして、その点で利用可能な最大の y を計算します。 次に、区間全体でこれらの最大値の最小値を取得します。 

これは定義を直接実装しているため機能します。位置ごとに可能な限り最適な道路を計算し、すべての位置がしきい値を満たしていることを確認します。 ただし、このアプローチは遅すぎます。 Q 個のクエリと N x 位置があり、各位置で最大 M 個の道路をスキャンする必要がある場合、最悪のケースは O(Q × N × M) となり、これはまったく実行不可能です。 

重要な観察は、条件が各 x について、それを覆う道路の最大 y にのみ依存するということです。 x に対するこの関数が判明すると、各クエリはその配列に対する範囲最小クエリに縮小されます。 課題は、構造化された順序で道路を処理しない限り、この機能を直接構築するとコストがかかることです。 

ここで、y のスイープが役立ちます。 道路を y の昇順に処理すると、道路をアクティブ化するたびに、その y が以前に処理されたものと少なくとも同じ大きさになることが保証されます。 したがって、その値を対象範囲の間隔に割り当てると、これまでのところそれらの位置に最もよく知られている値が安全に設定されます。 セグメント ツリーを使用すると、範囲割り当ての下でこの配列を動的に維持し、範囲最小クエリに効率的に答えることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(Q × N × M) | O(N + M) | 遅すぎる |
 | スイープ + セグメント ツリー | O((N + Q) log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 道路およびクエリに現れるすべての x 座標を圧縮して、セグメント ツリーが連続したインデックス範囲で動作するようにします。

1. すべての道路を Y 座標で昇順に並べ替えます。 これにより、道路を処理するときに、以前に処理されたすべての道路の y 値がそれより小さいか等しいことが保証されます。 
2. 圧縮された x 軸上にセグメント ツリーを構築します。 各ノードは、そのセグメント内の任意の位置に割り当てられた最大 y 値を格納します。 最初はすべての値がゼロで、どの位置も道路が覆われていないことを意味します。 
3. y の昇順に道路を繰り返します。 道路カバー区間 [l, r] ごとに、その区間内のすべての位置を道路の y 値に設定する範囲割り当てを実行します。 これにより、以前の値が上書きされます。 
4. クエリを処理しますが、関連するすべての道路が適用された後にのみ実行します。 クエリ [l, r, b] の場合、区間 [l, r] の最小値をセグメント ツリーにクエリします。 
5. この最小値が少なくとも b であれば、その区間は十分な高さの道路で完全にカバーされているため、答えは肯定的です。 それ以外の場合は不可能です。 

すべての道路を処理するまでクエリを遅らせることができる理由は、セグメント ツリーの最終状態が各 x について、それをカバーするすべての道路の最大の y を表すためです。 

### なぜ効果があるのか

 スイープ中のあらゆる瞬間に、各セグメント ツリーの位置には、その位置をカバーするこれまでに処理されたすべての道路の最大 y 値が格納されます。 道路は y の増加順に処理されるため、後の割り当てが常に前の割り当てよりも優先されます。 これにより、位置が小さい道路を置き換える必要があるより高い有効な道路を見逃すことがないことが保証されます。 

すべての道路が処理されると、セグメント ツリーに格納される配列は、x をカバーする任意の道路の関数 f(x) = 最大 y となります。 各クエリは、f(x) の [l, r] の x 上の最小値が少なくとも b であるかどうかを尋ねます。 これは実現可能条件と直接一致するため、アルゴリズムは正しいです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SegTree:
    def __init__(self, n):
        self.n = n
        self.mx = [0] * (4 * n)
        self.lazy = [-1] * (4 * n)

    def push(self, v):
        if self.lazy[v] != -1:
            val = self.lazy[v]
            self.mx[v * 2] = val
            self.mx[v * 2 + 1] = val
            self.lazy[v * 2] = val
            self.lazy[v * 2 + 1] = val
            self.lazy[v] = -1

    def update(self, v, l, r, ql, qr, val):
        if ql <= l and r <= qr:
            self.mx[v] = val
            self.lazy[v] = val
            return
        if r < ql or qr < l:
            return
        self.push(v)
        m = (l + r) // 2
        self.update(v * 2, l, m, ql, qr, val)
        self.update(v * 2 + 1, m + 1, r, ql, qr, val)
        self.mx[v] = max(self.mx[v * 2], self.mx[v * 2 + 1])

    def query_min(self, v, l, r, ql, qr):
        if ql <= l and r <= qr:
            return self.mx[v]
        if r < ql or qr < l:
            return 10**18
        self.push(v)
        m = (l + r) // 2
        return min(
            self.query_min(v * 2, l, m, ql, qr),
            self.query_min(v * 2 + 1, m + 1, r, ql, qr)
        )

def solve():
    n, q = map(int, input().split())

    coords = set()
    roads = []
    queries = []

    for _ in range(n):
        l, r, y = map(int, input().split())
        roads.append((y, l, r))
        coords.add(l)
        coords.add(r)

    for i in range(q):
        a, c, b = map(int, input().split())
        queries.append((a, c, b, i))
        coords.add(a)
        coords.add(c)

    coords = sorted(coords)
    mp = {x: i for i, x in enumerate(coords)}
    m = len(coords)

    seg = SegTree(m)

    roads.sort()

    for y, l, r in roads:
        seg.update(1, 0, m - 1, mp[l], mp[r], y)

    ans = [0] * q
    for a, c, b, i in queries:
        res = seg.query_min(1, 0, m - 1, mp[a], mp[c])
        ans[i] = 1 if res >= b else 0

    print("\n".join(map(str, ans)))

if __name__ == "__main__":
    solve()
```セグメント ツリーは 2 つの異なる概念を 1 つの構造に格納します。ノードの最大値はセグメントに割り当てられている現在の最適な y を表し、クエリは間隔にわたる最小値を集計して、すべての x 位置が制約を満たすように強制します。 遅延伝播では代入が使用されます。これは、スイープの後半でより高い y が到着すると、以前の値が安全に上書きされるためです。 

よくある落とし穴は、割り当ての代わりに「最大更新」を使用しようとすることです。 y によるソートにより単調な更新が保証されるため、ここではこれは不要です。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、クエリ間隔に道路が決してカバーしないポイントが含まれる場合です。 その場合、その時点のセグメント ツリー値は 0 のままであるため、間隔の最小値は 0 に低下し、エンドポイントがカバーされている場合でもクエリは正しく失敗します。 

もう 1 つのケースは、入力の y 次数が減少して道路が重なっている場合です。 並べ替えないと、低い y 道路が高い道路を誤って上書きする可能性があります。 y で並べ替えると、単調な改善が保証され、この失敗が防止されます。 

最後の微妙なケースは、道路がクエリの境界と正確に一致する場合です。 座標圧縮では、包含性が正しく処理されるように、エンドポイントを別個のインデックスとして保存する必要があります。 エンドポイントが誤ってマージされると、セグメント ツリーはカバレッジを過小評価し、有効なクエリが誤って失敗します。
