 ## 解決策
 ## 問題の理解

 ラベル付きのエッジを備えたグラフと、その上を同時に移動する 2 つのエンティティ (Waymo と Thomas) が与えられています。 システムの各状態は、1 つは Thomas の位置、もう 1 つは Waymo の位置のペアによって記述されます。 開始構成から、両方ともエッジ ラベルに関連付けられた特別なルールに従って移動でき、プロセスは到達可能な構成を交互に繰り返して継続します。 

重要なタスクは、従来の意味で時間の経過に伴う動きをシミュレートすることではなく、両方の参加者が互いの位置に対して最適に反応し続けることができると仮定して、すべての有効な動きのシーケンスの下で Waymo が最終的に訪問できるノードの数を決定することです。 

すべての動きがエッジ ラベルによって制限され、トランジションは、一方のプレイヤーがエンドポイントに立っているか、もう一方のプレイヤーが通過するエッジのラベルに立っているかによって異なるため、グラフの構造が重要になります。 これにより、状態が単一のノードではなく位置のペアであるシステムが作成されますが、状態間の遷移は高度に構造化され、まばらになります。 

状態空間は概念的にはノード数において 2 次ですが、各遷移は特定のエッジとラベルの相互作用によってのみトリガーされるため、実際に到達可能な部分ははるかに小さくなります。 これにより、探索が大幅に制限されます。 

複雑さの観点から見ると、このタイプの一般的な制約では、グラフには最大約 2×10^5 のエッジが存在する可能性があります。 すべてのノードのペアにわたる単純な探索には、O(n^2) または O(n^2 log n) の動作が必要ですが、これは実行可能な制限をはるかに超えています。 到達可能な状態の数が m 単位で線形であることを証明できない限り、すべての状態にわたる完全な BFS さえ不可能です。 

複数のエッジがラベルを共有する場合、またはラベルがノード インデックスと一致する場合、微妙なエッジ ケースが発生します。 単純な解釈では、双方向の状態遷移を強制せずにラベルを独立したノードとして扱い、不正確な到達可能性を引き起こす可能性があります。 

たとえば、エッジが (1, 2, ラベル 5) で、ノード 5 が他の場所に接続している場合、ラベル 5 がノードのように動作するのか、それともシンボリック コネクタとして動作するのかについて混乱が生じます。 処理を誤ると、ソルバーは逆遷移を許可できず、到達可能なノードを過小評価する可能性があります。 

## アプローチ

 ブルートフォース解釈では、各状態がペア (Thomas_position、Waymo_position) である状態グラフを明示的に構築し、移動ルールに従って遷移が適用されます。 各状態から、すべてのエッジベースのルールを適用して、新しい状態を生成し、BFS または DFS を実行しようとします。 

これは有効な手の定義に直接従うため、正しいです。 ただし、状態の数は潜在的に O(n^2) であり、各状態が複数のエッジに沿って遷移を試みる可能性があり、最悪の場合は O(n^2 + m·n) 個の動作が発生します。 これはすぐに実行不可能になります。 

重要な洞察は、遷移はノードのすべてのペア間で任意ではないということです。 遷移は、一方の参加者がエッジの端点に正確に配置され、もう一方の参加者がそのラベルに配置されている場合にのみ発生します。 これは、すべての有効な状態が何らかのエッジ インタラクションを通じて「作成」されている必要があることを意味します。 したがって、到達可能なすべての状態はエッジ イベントによって固定されます。 

これにより、意味のある状態の数が大幅に減少します。 任意のノードのペアの代わりに、エッジから直接生じる状態、またはそのようなエッジによって引き起こされる状態から最大 1 つの遷移ステップを介して接続される状態のみを考慮する必要があります。 これは、到達可能な状態の数が O(n^2) ではなく O(m) によって制限されることを意味します。 

この構造を受け入れると、エッジによって引き起こされる状態に対するコンパクトな隣接表現を構築できます。 各エッジは少数の構造化状態間の遷移を引き起こし、この暗黙的な状態グラフに対して DFS を実行できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2 + m・n) | O(n^2) | 遅すぎる |
 | 最適 | O(m log m) | O(m) | 承認済み |

## アルゴリズムのチュートリアル

 この問題を圧縮状態空間上のグラフ探索として再解釈します。 

各状態は 2 つの位置の構成ですが、すべてのペアを列挙する代わりに、エッジ誘発遷移を通じて到達可能な状態のみを生成します。 

## ステップ

 1. すべてのエッジ (u、v、l) を、u、v、l を含む構成を接続する相互作用ルールとして扱います。 これが、状態間の移動を生み出す唯一のメカニズムです。 
2. ノードが有効な構成 (u、v) である暗黙的な状態グラフを構築します。 すべてのペアを列挙することはありません。エッジによってトリガーされる遷移を通じて到達可能なペアのみを列挙します。 
3. 各エッジ (u、v、l) に対して、状態 (u、l) と (v、l) の間の双方向遷移を追加します。 これは、一方のエンティティがエンドポイント u にあり、もう一方のエンティティがラベル l にある場合、制約を維持しながら v に移動できるという考えを捉えています。 
4. 状態の数が O(m) で隣接関係が疎であるため、状態ごとにハッシュ マップまたは順序付きマップを使用して、発信遷移を効率的に格納します。 
5. 初期構成から DFS または BFS を実行します。 ある状態に到達するたびに、エッジの一致によって生成されたすべての遷移を調査します。 
6. 構成の再訪を避けるために、訪問した状態を追跡します。 訪問された各状態は、システムの到達可能な構成を表します。 
7. すべての訪問州にわたって、Waymo の異なるノード位置がいくつ出現するかを数えます。 これが最終的な答えです。 

到達可能な状態のみを安全にカウントできる理由は、すべての有効な構成は有効なエッジ トリガー遷移から発生する必要があり、このクロージャの外側に構成を生成するメカニズムがシステムに存在しないためです。 

### なぜ効果があるのか

 すべての到達可能な状態は、別の到達可能な状態からの有効なエッジ遷移を適用することによって作成されます。 遷移はエッジを通じてのみ定義され、すべての遷移は構築によって有効性を保持するため、到達可能な状態空間はエッジによって引き起こされる構成上で閉じたグラフを形成します。 DFS はまさにこのクロージャを調査し、無効なペアを導入することなく完全性を保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    
    adj = {}

    def add(a, b):
        if a not in adj:
            adj[a] = []
        adj[a].append(b)

    edges = []

    for _ in range(m):
        u, v, l = map(int, input().split())
        edges.append((u, v, l))
        add((u, l), (v, l))
        add((v, l), (u, l))

    start = (edges[0][0], edges[0][2])

    stack = [start]
    vis = set([start])

    reachable_waymo = set()

    while stack:
        u, w = stack.pop()
        reachable_waymo.add(w)

        if (u, w) not in adj:
            continue

        for nxt in adj[(u, w)]:
            if nxt not in vis:
                vis.add(nxt)
                stack.append(nxt)

    print(len(reachable_waymo))

if __name__ == "__main__":
    solve()
```この実装では、ペアとして表される圧縮状態に基づいて隣接リストを構築します。 各エッジは 2 つの有向遷移に寄与し、可逆性の特性を反映しています。つまり、移動が行われると、システムは一般性を失うことなく復帰または続行できます。 

DFS は、到達可能な部分にわたる線形探索を保証するために、状態全体にわたって訪問済みセットを維持します。 答えは、Waymo の考えられる立場に対応する訪問州の 2 番目の要素をすべて収集することで導き出されます。 

実装の微妙な詳細は、状態をタプルとして直接表現することです。 これにより衝突が回避され、ハッシュ化が簡素化されます。 もう 1 つは、可逆性がシステムの中核的な特性であるため、各エッジの両方向が確実に挿入されるようにすることです。

 ## 特殊なケース

 最小限のケースは、エッジが 1 つしかない場合に発生します。 この状況では、システムには意味のある遷移が 1 つだけあり、DFS は最大 2 つの状態を探索します。 アルゴリズムは最初のエッジから初期化され、すぐに両方向の動きを追加して、対称性が維持されるようにします。 

2 番目のケースは、エッジがサイクルを形成する場合です。 たとえば、(1,2,3)、(2,3,1)、(3,1,2)などです。 DFS は、訪問されたセットによって循環構成の再訪問が防止されるため、重複することなくすべての誘発された状態を介して拡張されます。 各状態は 1 回追加され、クロージャに到達すると到達可能性が安定します。 

3 番目のケースでは、複数のエッジにわたってラベルが繰り返されます。 状態はペアによってインデックス付けされるため、同一のラベルが衝突することはなく、隣接構造は正しいままになります。 各エッジは独立した遷移に寄与し、ハッシュ マップは共有エンドポイントを曖昧さなく自然にマージします。
