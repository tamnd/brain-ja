 ## 問題の理解

 私たちは、単純な繰り返しプロセスを時間の経過とともに追跡しています。 毎日は、最後のリセット イベントから経過した日数を測定する実行カウンターに寄与します。 このカウンタが一定期間の倍数に達するたびに$K$、アクションを実行します。「正気度」と呼ばれる値を 1 つ増やします。 

したがって、入力は一連の日を記述し、毎日暗黙的に日カウンターをインクリメントします。 唯一興味深い瞬間は、カウンターが次の値で割り切れる日です。$K$、それは正気度が高まる日だからです。 そのような日が経過すると、カウンターは継続するかゼロにリセットされますが、どちらの解釈も同等です。なぜなら、$K$重要です。 

出力は、シーケンス内のすべての日を処理した後の最終的な正気度値です。 

この声明は「チェスボットがボスロジストに電子メールを送信する」という観点から表現されていますが、核となる抽象概念は単なる定期的なカウントです。つまり、ブロックを完了するたびに、$K$数日間、答えに 1 を追加します。 

制約は最小限ですが、これは依然として線形時間シミュレーションの問題です。 日数の場合は$N$までです$10^5$または$10^6$、その後、$O(N)$トラバースは自明のことながら安全です。 サイクルの再計算やネストされた方法での割り算のチェックなど、線形より悪いものは不必要なオーバーヘッドになりますが、追加の要素が導入された場合は通過しません。 

主なエッジケースは、最初のサイクルがどのように開始されるか、およびどのように正確な倍数が実行されるかによって決まります。$K$振る舞う。 誤ってリセットしたり、間違った順序でインクリメントした後にチェックしたりする単純な実装では、カウントが 1 つずれる可能性があります。 

たとえば、次の場合$K = 3$3 日間処理すると、正気度はちょうど 1 回増加するはずです。 カウンターをリセットするのが早すぎると、増分を完全に見逃してしまう可能性があります。 逆に、リセットが遅すぎると、境界を越えて 2 回カウントされる可能性があります。 

## アプローチ

 ブルートフォース解釈では、最後のリセット以降の日数のカウンターを維持しながら、毎日シミュレートします。 毎日カウンタが 1 ずつ増加し、カウンタが 1 に達するたびに$K$、正気度を高め、カウンターをゼロにリセットします。 これは問題の説明を直接反映しており、構造的には正しいです。 

毎日一定の作業のみが必要となるため、このアプローチのコストは日数に比例します。 日の間に入れ子構造や依存関係がないため、さらなる最適化は必要ありません。 プロセスはすでに定期的で単純であるため、イベントを「事前計算」する試みは不要です。 

重要な点は、カウンタをモジュロ値を超えて格納する必要がないことです。$K$。 リセットという観点から考える代わりに、モジュラー算術という観点から考えることができます。つまり、毎日 1 単位が寄与し、累積合計が で割り切れるたびに、$K$、正気度を増加させます。 

これは問題を、次の倍数を数えるというものに再構成します。$K$範囲内に出現する$1$に$N$、これは単純に$N // K$。 シミュレーションは 1 つの算術式に分解されます。

 ## アルゴリズムのチュートリアル

 1. 日数を読み取る$N$そして期間$K$。 これらは完全なタイムラインを定義し、正気度の頻度が増加します。 
2. サイズの完全なブロックの数を計算します。$K$に適合する$N$。 これは整数の除算によって行われます$N // K$、倍数に達した回数を直接カウントします。$K$。 
3. この値を最終的な健全性レベルとして出力します。 各完全なブロックは正確に 1 つの増分に対応し、最後の部分ブロックは寄与しません。 

### なぜ効果があるのか

 重要な不変条件は、日カウンタはその剰余モジュロを通じてのみ重要であるということです。$K$。 全長のセグメントを完了するたびに$K$、カウンターは再びゼロに達し、新しいサイクルが始まります。 したがって、境界条件に到達した合計回数は、長さのプレフィックス内の完全なサイクル数と正確に一致します。$N$。 部分的なサイクルは増分に達しないため、増分をトリガーできません。$K$したがって、完全な除算のみが答えに寄与します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    data = input().strip().split()
    if not data:
        return
    n, k = map(int, data)
    
    # each full block of size k contributes +1 sanity
    print(n // k)

if __name__ == "__main__":
    solve()
```このソリューションは 2 つの整数を読み取り、整数の除算を直接計算します。 唯一の微妙な点は、一部のコンテスト形式では両方の値が 1 行で提供されるため、入力解析で空白を正しく処理することです。 

部門$n // k$次のような場合を含め、あらゆる場合に安全です。$n < k$、正しくゼロを返します。 これは、完全なサイクルがまったくないことに相当します。

 ## 特殊なケース

 場合の場合$N < K$、入力など`5 10`、カウンターがしきい値に到達することはありません。 アルゴリズムは計算します`5 // 10 = 0`、正しくは正気度が増加しないことを示しています。 ステップバイステップのシミュレーションでは、カウンターが 10 に到達することなく 1 から 5 に進むことが示され、増加がないことが確認されます。 

正確な境界位置合わせの場合、たとえば`9 3`、シミュレーションは 3、6、9 日目に正確にしきい値に達します。アルゴリズムは次の値を返します。`9 // 3 = 3`、3 つのリセット イベントと正確に一致します。
