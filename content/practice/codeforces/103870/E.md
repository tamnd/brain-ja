 ## 解決策
 ## 問題の理解

 時間の経過に伴う支出イベントを表すシーケンスが与えられ、各イベントは個人識別子に関連付けられます。 同じ人物が複数回出現し、アクティビティの連続したセグメントを形成する場合があります。 この一連の結果から、私たちは 2 つのことを導き出す必要があります。1 つは、各人の総関与に基づく最終的な金銭収支、もう 1 つは、単一の個人による最長の中断されない連続活動に依存する特別な「税金調整」です。 

最初の部分は基本的に簿記のタスクです。 シーケンスに人物が登場するたびに、それを支出または寄付の単位として解釈し、人物ごとの合計を累積します。 このフェーズの出力は、個人から税金調整前の純残高へのマッピングです。 

2 番目の部分は合計ではなく、シーケンス内の構造に依存します。 同じリストをスキャンし、同一人物の連続するセグメントを追跡します。 同じ人物の最大の連続ブロックごとに、その長さを測定します。 そのような最長のブロックを所有する人が税の大きさを決定します。その大きさは、そのブロックの長さに他の参加者の数を掛けて 1 を引いたものになります。 その値は選ばれた人から減算され、他の全員に一律の方法で再分配されます。 

この再分配を適用した後に最終的な出力が決定されます。調整された資産が最大の人と最小の調整された資産を持つ人を識別し、それらの差を出力します。 

制約は明示的に提供されていませんが、このタイプの問題には通常、最大約 10^5 のイベントが関係します。 これにより、すべての候補者についてセグメントの長さやバランスをゼロから再計算するなどの 2 次解は即座に除外されます。 どのアプローチも、ハッシュ マップまたはシングル パス スキャンを使用して、シーケンスの長さが線形またはほぼ線形である必要があります。 

「最長連続記録」の誤解から素朴な落とし穴が生じます。 たとえば、シーケンスが次の場合、`A A B B B A`、最も長い連続は`B B B`もう 1 つの微妙なケースは、複数の人が同じ最大ストリーク長を共有する場合です。 単純な実装では、タイの処理に応じて候補者の上書きが遅すぎたり早すぎたりする可能性があり、これにより誰に課税されるかが変わる可能性があります。 

別の障害モードは、境界でストリーク カウンタが誤って更新されることです。 考慮する`A A B A A`。 If the implementation forgets to reset the current streak properly when switching between people, it might incorrectly merge streaks and overestimate lengths.

 ## アプローチ

 A brute-force interpretation would recompute, for every person, the longest contiguous segment they appear in. This would require scanning the full array for each person and tracking segment boundaries. n 個のイベントと潜在的に n 個の異なる人物が存在する場合、最悪の場合、時間計算量は O(n^2) になります。 n が約 10^5 であるため、これは実現可能な限界をはるかに超えています。 

重要な点は、必要な両方の計算を 1 回のパスで実行できることです。 合計残高は、個人によってキー設定された辞書を使用して段階的に蓄積できます。 The longest contiguous streak can also be tracked while scanning once, since streaks are inherently local properties that do not require revisiting earlier positions.

 1 回のトラバース中に、現在の人物と現在のストリークの長さを維持します。 人が変わると連敗をリセットします。 これを実行しながら、これまでに確認された最大連続記録を継続的に更新します。 これにより、課税対象者の身元と O(n) の税乗数の値がわかります。 

課税対象者とストリークの長さの値がわかれば、再分配の式をすべての人々に直接適用できます。 これは均一な変換であるため、イベントごとにシミュレートする必要はなく、最終的な集計を調整するだけです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 辞書を維持しながらリストを 1 回スキャンする`balance`一人当たりの寄付総額を保存します。 人物が現れるたびに、残高が 1 単位ずつ増加します。 これにより、追加のパスを必要とせずに、生の税引き前の合計が得られます。 
2. 同じスキャンで、次の 2 つの変数を維持します。`cur_len`現在の連続ストリークの長さ、および`best_len`これまでに見られた最大の連続記録。 メンテナンスも行います`cur_person`そして`best_person`。 現在の人物が前の人物と一致する場合、増分します`cur_len`それ以外の場合は 1 にリセットします。これにより、連続したブロックのみをカウントすることが保証されます。 
3. いつでも`cur_len`を超える`best_len`、 アップデート`best_len`そしてセット`best_person`今の人へ。 このステップでは、最も長く中断されなかった活動セグメントの責任者を特定します。 
4. スキャン後、税額を次のように計算します。`best_len * (m - 1)`どこ`m`は個別の人の数です。 この値はから減算されます`best_person`そして均等に追加します（として`best_len`）他のすべての人に。 
5. このルールを使用して最終調整残高を作成します。納税者の場合は税額全額を差し引きます。 他の人全員に追加します`best_len`。 この変換により、合計の一貫性が維持されます。 
6. 最後に答えを次のように計算します。`max(final_balance) - min(final_balance)`。 

中心的な考え方は、配列構造は単一の優勢なストリークを特定する場合にのみ重要であるということです。 それ以外はすべて線形累積です。 

### なぜ効果があるのか

 このアルゴリズムは、必要な両方の統計が単一パスでプレフィックス分解可能であるという事実に依存しています。 バランスの累積は要素間で加算され、ストリークの計算は隣接する等式によって局所的に決定されます。 将来の要素は完了したストリークに遡って影響を与えることはできないため、現在の実行のみを追跡すれば十分です。 最大ランが記録されると、再分配ステップは決定論的であり、その単一の値のみに依存するため、残高の変換は曖昧さなく完全に決定されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    arr = input().split()

    balance = {}
    for x in arr:
        balance[x] = balance.get(x, 0) + 1

    best_person = arr[0]
    best_len = 1
    cur_person = arr[0]
    cur_len = 1

    for i in range(1, n):
        if arr[i] == cur_person:
            cur_len += 1
        else:
            cur_person = arr[i]
            cur_len = 1

        if cur_len > best_len:
            best_len = cur_len
            best_person = cur_person

    m = len(balance)

    final = {}
    for p in balance:
        final[p] = balance[p]

    tax = best_len * (m - 1)

    for p in final:
        if p == best_person:
            final[p] -= tax
        else:
            final[p] += best_len

    vals = list(final.values())
    print(max(vals) - min(vals))

if __name__ == "__main__":
    solve()
```ソリューションは 3 つのフェーズで構成されます。 最初のループでは、税引き前の財務状態を表す頻度マップを構築します。 2 番目のループは、ランニング ストリーク カウンタを維持し、厳密に大きなセグメントが現れた場合にのみ最良の値を更新することによって、最長の連続セグメントを分離します。 これにより、セグメント境界の再計算が回避されます。 

最終フェーズでは、再配分ルールが 1 人につき 1 回だけ適用され、線形の複雑さが維持されます。 選択した個人の減算では、導出された税金計算式が直接使用され、一連のシミュレーションが回避されます。 

ここでよくある間違いは更新です`best_person`ネクタイについて。 実装は意図的に次の場合にのみ更新されます。`cur_len > best_len`これにより、最初の最大ストリークの決定的な選択が保証されます。 

## 実用的な例

 入力シーケンスを考えてみましょう。`A A B B B A`ストリークとバランスを同時に追跡します。

 最も長い連続記録は`B B B`, したがって、B は課税対象者となり、`best_len = 3`。

 これは、縞が純粋に連続しており、総頻度から独立していることを確認します。 X は生データに最も頻繁に出現しますが、Y は関連性を得るために頻繁に出現する必要はありません。 連続した構造のみが重要です。

 ## 特殊なケース

 エッジケースの 1 つは、すべての要素が同一である場合です。 入力用`A A A A`、配列全体が単一の縞を形成するため、`best_len = 4`そして`best_person = A`。 等価条件が常に成り立ち、人為的なセグメンテーションが導入されないため、アルゴリズムが誤ってリセットされることはありません。 

別のエッジ ケースは、最長のストリークが配列の最後にある場合に発生します。`B A A A`。 更新条件は、ストリークが以前の最大値を超えて成長した後にのみトリガーされるため、最後のセグメントは、その後に境界がない場合でも正しくキャプチャされます。 

3 番目のケースは、複数の人が同じ最長の連続記録を共有する場合です。たとえば、`A A B B`。 更新は厳密な改善の場合にのみ行われるため、最初の最大ストリークは保存されます。 この動作は決定論的なままであり、再分配は選択された単一の所有者のみに依存し、固有の課税事業体という問題の暗黙の要件と一致します。
