 ## 解決策
 ## 問題の理解

 ある程度の長さの位置の行といくつかの制約が与えられ、各制約は連続したセグメントを記述します。 ここでのタスクは、すべての制約が満たされるように、ライン全体に 2 種類のシンボルを割り当てることが可能かどうかを判断することです。 

グローバルな構造要件があります。2 つのシンボルは、構造全体にわたって同じ量で表示されなければなりません。 これは、シーケンスが 2 つのタイプ間で均等に分割されるため、全長が偶数である必要があることをすでに暗示しています。 

各制約間隔は、対象となるセグメントに条件を課します。 重要な隠れた相互作用は、これらの間隔条件がグローバル パリティ制限から独立していないことです。 最終的に重要なのは、制約によって区間内の偶数位置と奇数位置の間の局所的な不均衡が強制されるかどうかです。 

制約はパリティを通じて意味を持ちます。 奇数長のセグメントを見ると、必然的に、一方のパリティ (偶数または奇数のインデックス) の位置が他方よりも 1 つ多く含まれます。 この非対称性は、グローバル構造を尊重するあらゆる有効な解釈において 2 つのシンボルのバランスが取れていなければならないという要件と直接矛盾します。 

この観点から、問題は、間隔のセットがパリティバランスとの矛盾を強制するかどうか、または常に有効な交互パターンを構築できるかどうかをチェックすることに帰着します。 

### エッジケース

 単純なアプローチでは、有効な代入を明示的に構築し、すべての制約をチェックしようとする可能性がありますが、構造が柔軟すぎて構築空間が指数関数的であるため、大規模な入力では失敗します。 

たとえば、位置 1 ～ 3 をカバーする単一の間隔がある場合を考えてみましょう。この間隔は奇数の長さです。 このような状況では、区間内でローカルにシンボルのバランスをとろうとすると、すぐにパリティの不一致が発生しますが、単純なチェッカーは依然として貪欲に割り当てを試み、代替がすでにグローバルにすべてを満たしていることを認識できない可能性があります。 

一方、すべての間隔の長さが偶数である場合、実現可能性を誤って仮定する可能性がありますが、意図されたロジックは、パリティのバランスが全体的に厳格になりすぎ、少なくとも 1 つの奇数長の間隔によって矛盾が引き起こされない限り、一貫した割り当てはすべての制約を満たすことができないことを示しています。 

## アプローチ

 ブルートフォース戦略では、各位置に 2 つのシンボルのいずれかを割り当て、すべての間隔制約を検証しようとします。 各ポジションには 2 つの選択肢があるため、これは次のようになります。$2^n$可能な割り当て。 課題ごとにすべてにチェックを入れると、$m$間隔がかかる$O(m)$、合計を与えます$O(m \cdot 2^n)$、これは実現可能な限界をはるかに超えています。$n$大きいです。 

重要な単純化は、構造全体がパリティによって支配されているという観察から得られます。 この制約は、シンボルの正確な配置には依存せず、間隔によって偶数と奇数のインデックス位置の不均衡が強制されるかどうかに依存します。 奇数長の間隔は本質的にこのような不均衡を生み出しますが、偶数長の間隔ではパリティ対称性が維持されます。 

これは、驚くほど直接的な特徴付けにつながります。つまり、有効な構築が強制されるのは、奇数の長さの区間が少なくとも 1 つ存在する場合だけです。 その場合、MTMTMT... などの単純な交互パターンは、すべての隣接ペアがバランスされており、すべての間隔に等しいパリティ構造または補償パリティ構造が含まれているため、すでにすべての制約を満たしています。 

したがって、何かを構築する代わりに、間隔をスキャンしてその長さをチェックするだけで済みます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(m \cdot 2^n)$|$O(n)$| 遅すぎる |
 | 最適 |$O(n + m)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. 位置の数と間隔の数を読み取ります。 問題の構造により、各テスト ケースを新しいパリティ システムとして扱うことができます。 
2. 長さが奇数の間隔に遭遇したかどうかを追跡するブール値フラグを維持します。 このフラグは、パリティ破壊制約の存在を表します。 
3. インターバルごとに$[l, r]$、その長さを次のように計算します。$r - l + 1$。 この値が奇数の場合は、フラグを true に設定します。 これで十分な理由は、奇数長のセグメントでは、交互パリティの位置間に避けられない不均衡が生じるためです。 
4. すべての区間を処理した後、フラグのみに基づいて答えを決定します。 奇数長の区間が少なくとも 1 つ存在する場合、有効な構築が可能であることを出力します。 それ以外の場合は不可能と出力します。 

### なぜ効果があるのか

 構築空間はパリティの一貫性によって完全に制御されます。 交互の割り当て MTMTMT... は、あらゆるセグメントにわたって偶数位置と奇数位置からの寄与のバランスを完全にとります。 間隔の長さが奇数の場合、システムはそのような変更がオプションではなく、インスタンス内のどこかで構造的に強制される状態になり、実現可能性が保証されます。 すべての間隔の長さが偶数である場合、そのような強制メカニズムは存在せず、等しいカウントというグローバル要件をすべての制約と同時に調和させることができず、システムの一貫性が失われます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        has_odd = False
        
        for _ in range(m):
            l, r = map(int, input().split())
            if (r - l + 1) % 2 == 1:
                has_odd = True
        
        if has_odd:
            print("YES")
        else:
            print("NO")

if __name__ == "__main__":
    solve()
```解決策は純粋に入力に対するストリーミング チェックです。 私たちが保持する唯一の状態は、奇数長の間隔が存在するかどうかです。 これにより、実際のシーケンスを構築する試みが回避されますが、実現可能性は構造的に決まるため不要です。 

よくある実装上の間違いは、テスト ケースを途中で終了し、残りの入力行をすべて消費しないことです。 問題はマルチテストであるため、テスト ケースのすべての間隔の読み取りに失敗すると、入力ストリームが非同期になり、後続のすべてのケースが破損します。 ループは常に、宣言された間隔数を完全に処理する必要があります。 

## 実用的な例

 ### 例 1

 間隔のあるテストケースを検討してください$[1, 2]$そして$[3, 5]$。 

| 間隔 | 長さ | 奇数？ | 奇数があります |
 | --- | --- | --- | --- |
 | 1-2 | 2 | いいえ | 偽 |
 | 3-5 | 3 | はい | 本当 |

 処理後、フラグは true になるため、出力は YES になります。 

これは、他の制約に関係なく、単一の奇数間隔が決定をどのように支配するかを示しています。 

### 例 2

 間隔を考慮する$[1, 2]$、$[2, 3]$、$[4, 5]$。 

| 間隔 | 長さ | 奇数？ | 奇数があります |
 | --- | --- | --- | --- |
 | 1-2 | 2 | いいえ | 偽 |
 | 2-3 | 2 | いいえ | 偽 |
 | 4-5 | 2 | いいえ | 偽 |

 間隔がない場合はパリティの不均衡が生じるため、結果は NO になります。 

これは、構造が均一すぎて有効な構築ができないという補足的なケースを示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = []
    
    def solve():
        t = int(input())
        for _ in range(t):
            n, m = map(int, input().split())
            has_odd = False
            for _ in range(m):
                l, r = map(int, input().split())
                if (r - l + 1) % 2 == 1:
                    has_odd = True
            output.append("YES" if has_odd else "NO")
    
    solve()
    return "\n".join(output)

 ## 特殊なケース

 1 つのエッジ ケースは、長さ 1 の範囲全体をカバーする単一の間隔です。アルゴリズムは直ちにそれを奇数としてマークし、YES を返します。 単一の位置がすでにパリティ対称性を破っており、フラグは構築することなくこれを正しくキャプチャしているため、正しい動作が続きます。 

もう 1 つのケースは、すべての間隔の長さが 2 であり、重複する可能性がある場合です。 などの入力の場合$[1,2], [2,3], [3,4]$、すべての間隔は偶数の長さであるため、フラグは処理全体を通して false のままであり、答えは NO です。 重なりはパリティ分類に影響を与えないため、アルゴリズムは重なり合う制約を正しく処理します。 

最後の微妙なケースは、間隔の数が最大になる大量の入力です。 このソリューションは間隔を保存したり再構築を試行したりしないため、それぞれを個別に安全に処理し、メモリ負荷やスタックの問題を回避します。
