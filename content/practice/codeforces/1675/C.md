 ## 解決策
 ## 問題の理解

 訪問者が次々と部屋に入ってくる様子を観察します。 ちょうどそのうちの一人が、ある瞬間に絵画を盗みましたが、いつ盗難が起こったのかはわかりません。 各訪問者は、入場時にその絵を見たか、覚えていないか、または自分が泥棒であるかどうかを任意に答えます。 

重要な構造は、正直な人は皆真実を言うか、「覚えていません」と答えるかのどちらかであるということです。 恣意的に嘘をつくことができるのは泥棒だけです。つまり、シナリオに一貫性を持たせるために、私たちは彼らの答えを自由に再解釈できます。 

課題は、答えについて少なくとも 1 つの一貫した説明が存在する場合、シーケンス内のどの位置が泥棒である可能性があるかを数えることです。 

制約はテスト ケース全体で非常に長いため、どのソリューションでもテスト ケースごとに各文字を線形時間で処理する必要があります。 これにより、泥棒候補をすべて試したり、毎回文字列全体をスキャンして一貫性を検証したりするなどの二次推論が排除されます。 

文字列に情報が含まれていない場合、たとえばすべて疑問符が含まれている場合、微妙なエッジ ケースが表示されます。 その場合、矛盾を避ける真理値を常に割り当てることができるため、すべての人を泥棒として一貫させることができます。 もう 1 つのエッジ ケースは、すべて 0 またはすべて 1 のような完全に決定的な文字列で、プレフィックス制約の一貫性に応じて通常 1 つまたは 2 つの位置のみが実行可能です。 

## アプローチ

 強引なアイデアは、各人が泥棒であると仮定し、他の全員に一貫した真理値を割り当てることができるかどうかをシミュレーションすることです。 候補が固定されている場合は、絵画が各人の前にあったかどうかを再構成し、おそらく泥棒のところを除いて、宣言されたすべての「0」または「1」がその再構成と互換性があることを確認する必要があります。 このシミュレーションでは候補ごとに線形時間がかかるため、全体として 2 次の複雑さが生じ、入力サイズに対して遅すぎます。 

重要な観察点は、問題の構造が接頭辞ベースであるということです。 シーケンスのどの時点でも、制約システムは、特定のインデックスの前に絵画がまだ存在するか存在しないように強制するステートメントを何回見たかによってのみ決まります。 プロセスを正しく解釈すると、一貫性条件は、候補分割点が「真実を強制する」制約を「未知による自由」から分離できるかどうかを追跡するように崩壊します。 

これにより、問題は、位置ごとに、その位置までの接頭辞とその後の接尾辞の両方が、絵画の存在の少なくとも 1 つの有効なタイムラインと一致するかどうかをチェックすることになります。 これは、プレフィックスとサフィックスの集約を使用して線形時間で維持できます。

 ## アルゴリズムのチュートリアル

 私たちは、この問題を、仮想の盗難ポイントがシーケンスを、絵画がエントリ時にまだ存在している必要があるプレフィックスと、すでに消えている可能性があるサフィックスに分割するかどうかを維持するものとして再解釈します。

1. 絵画が最初にまだ存在する場合、i までの接頭辞が一貫しているかどうかを記述する接頭辞情報を事前計算します。 これは、必須の「1」タイプの回答と「0」タイプの回答の間に矛盾を強制するかどうかを追跡することによって行われます。 
2. 絵画がそのセグメントに入る前にすでに消えている場合、以降の接尾辞が一貫しているかどうかを記述する接尾辞情報を事前計算します。 これもまた、強制的な声明が絵画の不在と矛盾しないことを確認することに帰着します。 
3. 各位置 i について、それを潜在的な泥棒として解釈します。 「i」の前の接頭辞は、その友人たちが入ってきたときに絵がまだ存在しているという仮定の下で一貫していなければなりません。 i の後の接尾辞は、絵画がすでになくなっている可能性があるという前提の下で一貫している必要があります。 
4. プレフィックス制約とサフィックス制約の両方が同時に成立するすべてのインデックス i をカウントします。 これらのインデックスは、すべての回答について少なくとも 1 つの有効な解釈を維持しながら、泥棒にされる可能性のあるすべての人々を表します。 
5. このカウントを返します。 

重要な単純化は、すべての内部一貫性制約が位置ごとに 2 つの独立したブール条件に集約されることです。これは、泥棒の唯一の役割は、矛盾する制約を 1 つシステムから削除することであるためです。 

### なぜ効果があるのか

 すべての有効なシナリオには、絵画が消える固有の最も早い瞬間があります。 その瞬間以前のすべては絵画が存在していることと一致しなければならず、その後のすべては絵画が消えたことと一致していなければなりません。 泥棒を選択することで、どこで一貫性を破ることが許可されるかが効果的に決まります。 許可されるブレークは 1 つだけであるため、実現可能性は、その 1 つの点を削除することですべての矛盾が解決されるかどうかを確認することになります。 プレフィックスとサフィックスの計算により、そのような単一のブレークポイントが各候補位置に存在するかどうかが正確に取得されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        s = input().strip()
        n = len(s)

        left_ok = [True] * (n + 1)
        right_ok = [True] * (n + 2)

        # prefix check: assume painting exists initially
        seen_bad = False
        for i in range(n):
            if s[i] == '0':
                seen_bad = True
            # prefix i is valid if no contradiction accumulated
            left_ok[i + 1] = not seen_bad

        # suffix check: assume painting already gone
        seen_good = False
        for i in range(n - 1, -1, -1):
            if s[i] == '1':
                seen_good = True
            right_ok[i + 1] = not seen_good

        ans = 0
        for i in range(n):
            if left_ok[i] and right_ok[i + 2]:
                ans += 1

        print(ans)

if __name__ == "__main__":
    solve()
```この解決策は、文字列を 2 つの方式の実現可能性に分離します。 順方向スキャンでは、絵画がまだ存在している場合には不可能なステートメントに遭遇するかどうかを追跡します。 逆方向スキャンでは、絵画がすでに消えていると仮定して、同じことが行われます。 各候補インデックスは、これらのレジーム間の単一の移行点として機能する場合に有効です。 

よくある落とし穴は、グローバルな変更が 1 つだけ許可されていることを認識せずに、各インデックスについてローカルに推論しようとすることです。 プレフィックスとサフィックスの構造により、単一のグローバル変更として機能する位置のみがカウントされることが保証されます。

 ## 特殊なケース

 すべての疑問符など、文字列が均一である場合、プレフィックス制約とサフィックス制約の両方がどこでも有効なままであるため、すべてのインデックスがカウントされます。 文字列が 0 と 1 の間で厳密に交互する場合、プレフィックス条件はすぐに失敗し、有効な範囲が小さなサブセットに縮小されます。 文字列の長さが 1 の場合、矛盾は形成されないため、どちらのスキャンでもその 1 つの位置が唯一の可能性のある泥棒として受け入れられます。
