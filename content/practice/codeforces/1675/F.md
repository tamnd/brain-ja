 ## 解決策
 ## 問題の理解

 私たちは木のように構造化された都市を与えられています。`n`でつながる家々`n-1`これにより、任意の 2 つの家の間に 1 つの単純な道が存在することが保証されます。 ヴラドは家から始まる`x`そして家にいるナスティアに連絡したいと思っています`y`、しかし旅を終える前に、彼は次のリストを手に入れました。`k`やるべきこと、それぞれが特定の家を訪問することに関連している`a_i`。 ヴラドはこれらのタスクを任意の順序で実行でき、何度も家を訪れることもあります。 すべての道路横断にはちょうど 1 分かかります。私たちの目標は、Vlad がすべてのタスクを完了してナスティアに到着するために必要な最小合計移動時間を計算することです。 

制約は次のことを教えてくれます`n`最大 200,000 およびすべての合計`n`テスト ケース全体でも 200,000 を超えません。 これにより、おおよそよりも複雑なアルゴリズムは除外されます。`O(n log n)`テストケースごとに、`O(n^2)`あるいは、タスクのすべての組み合わせを総当りで探索することは完全に不可能です。 

明らかではないエッジケースには、すべてのタスクがからの直接パスに沿って存在する状況が含まれます。`x`に`y`、追加の家を訪問しても余分な距離が追加されない場合、または`k = 1`、最適なパスは単純ですが、計算を間違えやすい場合があります。 別の微妙なケースが発生します。`a_i`と同じです`x`または`y`; 単純な実装では、そのような訪問が二重にカウントされる可能性があります。 

## アプローチ

 ブルートフォースアプローチは、次のすべての順列を考慮することです。`k`タスクハウスを作成し、各順列の合計パス長を計算し、最小値を選択します。 これは原理的には正しいです。タスクのすべての有効なシーケンスはツリーの有効な走査に対応しますが、順列の階乗増加は`O(k!)`、たとえ小さなものであってもすぐに管理できなくなります`k`もし`k`は10以上です。 

重要な洞察は、ツリー構造を観察することで得られます。 ツリーにはサイクルがないため、すべてのタスク ノードに接続する最短ルートは、基本的に、接続する最小のサブツリーになります。`x`、`y`、そしてすべて`a_i`。 これをグラフ理論の観点から考えると、ツリーに沿った距離を計算し、直接パスの外側を通過する必要がある「余分な」エッジを把握することになります。`x`に`y`。 重要なのは、深さ優先検索を次から実行できることを認識することです。`x`必要なパスをすべて検索し、タスクへのパス上にあるノードをマークします。 次に、2 回 (前方に 1 回、後方に 1 回) 通過する必要があるエッジを数え、最後に距離を加算します。`x`に`y`。 

要約すると次のようになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(k! * n) | O(n) | 遅すぎる |
 | 最適 (DFS + 必要なパスをマーク) | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ツリーを隣接リストとして構築します。 これにより、高速なトラバーサルと近隣ルックアップが可能になります。 
2. ブール配列を維持する`needed`サイズの`n+1`ノードまたはそのサブツリーにタスクハウスが含まれているかどうかを示す`a_i`。 
3. から開始して再帰的 DFS を実行します。`x`。 各ノードについて:

 - 初期化`needed[node]`に`True`タスクのリストにある場合。 
- 子ごとに、DFS を再帰的に実行します。 
- 子サブツリーが必要な場合は、マークを付けます。`needed[node]`として`True`。 
4. DFS 中に、必要とマークされたサブツリーにノードを接続するエッジの数を数えます。 このような各エッジは 2 回 (1 回はサブツリーに入り、もう 1 回は戻ります) 横断する必要があります。 
5. 最終的な答えは、必要なすべてのエッジに沿った合計距離の 2 倍に、エッジからの一意のパスに沿った距離を加えたものになります。`x`に`y`。 を計算するには、`x`に`y`パスにある場合、DFS を使用して深さまたは親チェーンを見つけて、このパスに沿ったエッジを合計するか、DFS が 2 回カウントした重複するエッジを単純に減算することができます。 
6. テスト ケースごとにこの合計を出力します。 

不変条件とは、`needed[node]`は`True`このノードがタスク ハウスであるか、そのサブツリーにタスク ハウスが存在する場合に限ります。 これにより、必要なエッジを決して見逃さず、不必要なエッジを横断することがなくなり、計算される距離が最小限になることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(1 << 20)

def solve():
    t = int(input())
    for _ in range(t):
        input()  # empty line
        n, k = map(int, input().split())
        x, y = map(int, input().split())
        tasks = set(map(int, input().split()))
        adj = [[] for _ in range(n + 1)]
        for _ in range(n - 1):
            u, v = map(int, input().split())
            adj[u].append(v)
            adj[v].append(u)

        needed = [False] * (n + 1)
        for a in tasks:
            needed[a] = True

        total = 0

        def dfs(u, parent):
            nonlocal total
            flag = needed[u]
            for v in adj[u]:
                if v == parent:
                    continue
                if dfs(v, u):
                    total += 2
                    flag = True
            needed[u] = flag
            return flag

        dfs(x, -1)

        # find distance from x to y
        dist = [-1] * (n + 1)
        def dfs_dist(u, parent, d):
            dist[u] = d
            for v in adj[u]:
                if v != parent:
                    dfs_dist(v, u, d + 1)

        dfs_dist(x, -1, 0)
        print(total - dist[y])

if __name__ == "__main__":
    solve()
```の`dfs`関数は、ヴラドの家からツリーを横断し、タスク ハウスに必要なすべてのパスをマークします。 必要なサブツリーに接続する各エッジは 2 回カウントされます。これは、Vlad が直接接続されていない場合、そこに行ったり戻ったりする必要があるためです。`x`に`y`パス。 の`dfs_dist`からの直線距離を計算します`x`に`y`そしてそれを合計から減算し、直接パスに沿った二重カウントを修正します。
