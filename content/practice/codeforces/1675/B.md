 ## 解決策
 ## 問題の理解

 いくつかの独立した配列が与えられています。 各配列について、要素を繰り返し縮小することができます。1 回の操作で位置を選択し、その値を半分を切り捨てた値に置き換えます。 入れ替えは許可されないため、要素の順序は固定されます。 

目標は、すべての変更後に配列が厳密に左から右に増加するように、このような縮小操作の適用を最小限に抑えることです。 要素をどのように縮小しても厳密な増加を達成する方法がない場合は、不可能であることを報告する必要があります。 

構造上の重要な点は、すべての要素は、整数を 2 で割ることを繰り返して得られる値の連鎖に沿って下方向にのみ移動できることです。 与えられた制約に対して、半減を繰り返すと最大約 31 ステップでゼロに達するため、各数値は短い「値の軌跡」を持ちます。 

テスト ケースごとの制約は非常に小さく、最大でも 30 個の要素が含まれます。 これにより、複雑なデータ構造やグローバルな最適化の必要性が即座に排除されます。 ただし、テスト ケースの数が多いため、テスト ケースごとの解は線形またはほぼ線形である必要があります。 

ここでよく失敗する素朴な誤解は、将来の結果を考慮せずに、前の結果よりも大きくなるように各要素を個別に貪欲に縮小することです。 現在の要素を小さすぎると、たとえわずかに大きな選択が機能したとしても、次の要素が不可能な位置に配置される可能性があるため、これは失敗する可能性があります。 

もう 1 つの故障モードは、必要な場合にのみ削減することによって発生します。 現在の要素が局所的に厳密な不等式をすでに満たしている場合でも、場合によっては、前の要素を積極的に削減して、後の要素のために「空き領域」を確保する必要があります。 

## アプローチ

 強引なアイデアは、各要素を、繰り返し 2 で割ることによって得られる、可能な値の小さなセットを持つものとして扱うことです。 配列全体でこれらの選択肢のすべての組み合わせを試し、途中で操作をカウントしながら、どのシーケンスが厳密に増加しているかを確認できます。 各要素には最大 31 個の状態があるため、これはおおよそ次のようになります。$31^n$それらの組み合わせは、たとえ$n = 30$、指数関数的に爆発するからです。 

重要な観察は、配列を左から右に処理すると、決定はローカルになるということです。 位置の値を固定する場合$i$、将来の要素に課す唯一の要件は下限です。次の要素は厳密にそれより大きくなければなりません。 したがって、要素ごとに、以前に選択した値よりも厳密に大きい、半分にすることで到達可能な最小値を選択するだけで済みます。 

ただし、重要な点が異なります。値を選択するだけでなく、半分にする操作の回数に等しいコストも支払うことになります。 したがって、すべての有効な変換値の中で、操作を最小限に抑えながら不等式を満たすものが必要です。 

これにより、貪欲な構築が可能になります。位置ごとに、元の数値から到達可能なすべての値を列挙し、各値と必要な分割数を組み合わせて、前の要素によって課された制約の下で最適な値を選択します。 

各数値は約 30 回しか半分にできないため、要素ごとにすべての状態を列挙するのはコストがかかりません。 位置の値を固定すると、貪欲な選択が機能します。$i$必要以上に大きな選択をしても、将来の制約が難しくなるだけで決して簡単にはならず、将来のコストも削減されません。

 | --- | --- | --- | --- |
 | すべての選択肢に対するブルートフォース |$O(31^n)$|$O(n)$| 遅すぎる |
 | 事前に計算されたチェーンを使用して貪欲に |$O(n \log A)$テストごと |$O(\log A)$| 承認済み |

 ## アルゴリズムのチュートリアル

 最後に選択した値を維持しながら、配列を左から右に処理します。 

1.各要素について$a_i$、到達可能なすべてのペアを生成します$(v, c)$、 どこ$v$は2で割ることを繰り返して得られる値であり、$c$到達するまでに必要な操作の数です。 これは、ゼロになるまで除算を繰り返すことによって行われます。 この列挙は深さが最大 31 であるため安価です。 
2. 価値を選択しようとします$v$現在の位置については、$v > \text{prev}$、 どこ`prev`前の要素に対して選択された値です。 
3. 有効なすべての中で$v$、コストが最小限のものを選択します$c$。 複数の値が同じコストを共有する場合、小さい方が優先されます。$v$。 この設定は、値が小さいほどその上に余裕ができるため、将来の制約を維持しやすくするのに役立ちます。 
4. 到達可能な値が満たされない場合$v > \text{prev}$、厳密に増加するシーケンスを構築してすぐに停止することは不可能であると結論付けます。 
5. 最適なペアを選択した後、更新します`prev = v`そしてコストを積み上げていきます。 

中心的な推論は、各ステップで将来のすべての可能性を単一の制約値に圧縮するということです。 引き継がれる唯一の情報は、実現可能性を維持できる最小のしきい値です。 

### なぜ効果があるのか

 正しさは、すべての要素の到達可能な値が単調減少チェーンを形成しているという事実に基づいています。 ポジションは何でも選べる$i$設定したしきい値を介して将来の要素にのみ影響します。 実現可能な値を選択すると、$a_i$、より大きな値を選択すると、有効なオプションの数が減るだけです。$a_{i+1}$、コスト構造を改善することなく、それらを増やすことは決してありません。 したがって、ローカルで最も安価な実現可能な値を常に安全に採用できます。 

状態空間は要素ごとに線形であり、決定を再検討することはないため、後戻りは必要ありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def get_states(x):
    states = []
    steps = 0
    while True:
        states.append((x, steps))
        if x == 0:
            break
        x //= 2
        steps += 1
    return states

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))

    prev = -1
    ans = 0
    possible = True

    for i in range(n):
        states = get_states(a[i])

        best_cost = float('inf')
        best_val = None

        for v, c in states:
            if v > prev:
                if c < best_cost or (c == best_cost and (best_val is None or v < best_val)):
                    best_cost = c
                    best_val = v

        if best_val is None:
            possible = False
            break

        ans += best_cost
        prev = best_val

    print(ans if possible else -1)
```機能`get_states`各数値の完全な半分のチェーンを明示的に構築します。 チェーンの長さは整数のビット数によって制限されるため、これは安全です。 

メインループ内で次のことを維持します。`prev`、最後に選択された値。 新しい要素ごとに、到達可能なすべての状態をスキャンし、最も安価で有効な状態を選択します。 タイブレーク オンの値により、次のステップのしきい値が不必要に大きくならないことが保証されます。 

微妙な実装の詳細が初期化されています`prev`可能な配列値より厳密に小さい値に設定します。 使用する`-1`変換後のすべての値は負ではないため、これで十分です。 もう 1 つの重要な詳細は、位置に有効な状態がない場合にすぐに中断することです。これは、後の要素では既に中断された厳密な増加条件を修正できないためです。

def solve(inp: str) -> str:

    input = sys.stdin.readline

    def get_states(x):
        res = []
        c = 0
        while True:
            res.append((x, c))
            if x == 0:
                break
            x //= 2
            c += 1
        return res

        n = int(input())

                break

            prev = best

        out.append(str(ans if ok else -1))

 ## 特殊なケース

 微妙なケースの 1 つは、値が早期にゼロに崩壊する場合です。 例えば、`[2, 1]`2 番目の要素が最初の要素よりも厳密に大きくなるように強制しますが、最初の要素は下降のみ可能であり、上昇することはできないため、誤って受け入れないように注意する必要があります。`0 > 0`スタイルの平等。 常に強制するため、アルゴリズムがこれを処理します。`v > prev`、 ない`>=`。 

別のエッジケースは、初期値が大きいほど悪くなるように見えても、実際には将来の実現可能性が維持される場合に発生します。 たとえば、選択すると、`1`初期に選択すると、後の要素がブロックされる可能性があります。`2`コストが少し高くなりますが、完全なシーケンスが可能になります。 到達可能なすべての状態の中から貪欲に選択することで、コミットする前にそのようなすべての代替案を常に考慮することが保証されます。 

最後に、多数のゼロを含む配列で不可能性の検出をテストします。 一度`prev`になる`0`、後の要素をそれ以下に減らすことはできないため、厳密に正の到達可能な値のみが問題になります。 何も存在しない場合は、次のように正しく終了します。`-1`。
