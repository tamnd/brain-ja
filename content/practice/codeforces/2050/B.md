 ## 解決策
 ## 問題の理解

 何らかのリソースの「プール」を表す整数の配列が与えられます。 各操作で、境界にない要素を選択し、1 つのユニットを 1 つの隣接要素から別の隣接要素に移動できます。 具体的にインデックスを選ぶと`i`(2 ≤ i ≤ n-1)、次のいずれかを減らすことができます。`a[i-1]`1ずつ増加します`a[i+1]`1 つまたは減らす`a[i+1]`1ずつ増加します`a[i-1]`負の値は禁止されているため、転送する前にソースは少なくとも 1 である必要があります。 

目的は、これらの操作を一定回数繰り返した後ですべての要素を等しくできるかどうかを判断することです。 

入力は複数のテスト ケースを提供し、それぞれに配列の長さと配列自体が含まれます。 すべての要素を均等化できるかどうかに応じて、各テスト ケースの出力は単純な「YES」または「NO」になります。 

配列サイズに関しては制約が厳しく、n は 2×10⁵ に達する可能性があり、テスト ケース全体のすべての n の合計は 2×10⁵ に制限されます。 これは、各操作が O(n) になる可能性があり、必要な操作の合計数が大きくなる可能性があるため、操作を明示的にシミュレートできないことを意味します。 アレイをグローバルに調べて、シミュレーションなしで実現可能性を判断するソリューションが必要です。 

端の要素の 1 つがその隣の要素よりも小さい場合、微妙なエッジ ケースが発生します。 操作は内部要素の隣接要素間で値をシフトするだけであるため、末端要素は一方向からのみリソースを受け取ることができます。 たとえば、次の場合`a[0]`は 1 であり、`a[1]`が 0 の場合、一連の動きは増加できません。`a[0]`すべての内部要素が小さいか等しい場合は 1 を超えます。 これは、最小値がキー制約であることを示しています。 

## アプローチ

 単純な総当たりアプローチでは、考えられるすべての操作シーケンスをシミュレートしようとします。 インデックスごとに`i`リソースを左右に移動してみることもできます。 運用ルールでは総計の保存が保証されているため、これは原理的には正しいのですが、遅すぎます。 サイズ 10⁵ の配列の場合、単一の一連の操作でも O(n²) ステップが必要となり、テスト ケースが 104 個ある場合、このアプローチは実行不可能です。 

重要な洞察は、不変条件、つまり配列の合計が一定のままであることを観察することです。 させて`S`すべての要素の合計となり、`n`配列の長さ。 すべての要素が等しくなるには、すべての要素が値に達する必要があります`S / n`。 これにより、直ちに実行可能性チェックが行われます。`S % n != 0`、それは不可能です。 

次に、隣接する要素が提供できる以上のものを必要とする要素がないことを確認する必要があります。 この操作では、一度に 2 つの隣接する要素間でリソースのみをシフトできるため、内部要素は必要な量を「吸収」または「与える」ことができなければなりません。 操作構造により、配列は内部要素間でリソースを自由に再分配できます。 合計が n で割り切れる限り、各内部要素が少なくともターゲット値である限り (端の要素は 1 つの近傍要素によって増加できるため)、常に可能であることがわかります。 

したがって、最適な解決策は、合計を計算し、n で割り切れるかどうかを確認し、割り切れる場合は YES、割り切れない場合は NO を出力することです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | テスト ケースあたり O(n²) | O(n) | 遅すぎる |
 | 和 + 割り算のチェック | テスト ケースあたり O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、長さを読み取ります。`n`そして配列`a`。 
2. 合計を計算します`S = sum(a)`。 
3. 目標値を計算する`target = S // n`。 
4. もし`S % n != 0`、印刷`NO`次のテスト ケースに進みます。 
5. それ以外の場合は、印刷します`YES`運用ルールにより目標に到達する再配分が許可されているためです。 

機能する理由: この操作により合計が保持されます。 合計が n で割り切れる場合、目標値が存在します。 この操作により、隣り合うユニット間で一度に 1 つのユニットを転送することができ、貪欲な方法で移動を繰り返し適用することで、どの内部構成でも過剰な値を不足している要素に再分配できます。 可分性チェックは実現可能性を保証します。これが唯一のグローバルな制約です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        total = sum(a)
        if total % n == 0:
            print("YES")
        else:
            print("NO")

solve()
```コードは高速 I/O を使用します。`sys.stdin.readline`。 各テスト ケースでは、配列の合計を計算し、割り算をチェックするだけです。 これはテスト ケースごとに O(n) であり、指定された制約の下では許容されます。 アレイストレージ以外の余分なメモリは使用されません。 微妙な点には、複数のテスト ケースを正しく処理することや、さまざまなサイズの配列を読み取ることが含まれます。 

## 実用的な例

 **サンプル入力 1:**`3 2 1`→ sum = 6、n = 3、6 % 3 = 0 → YES

 **サンプル入力 2:**`1 1 3`→ sum = 5、n = 3、5 % 3 ≠ 0 → NO

 | 配列 | 合計 | n | 合計 %n | 出力 |
 | --- | --- | --- | --- | --- |
 | [3,2,1] | 6 | 3 | 0 | はい |
 | [1,1,3] | 5 | 3 | 2 | いいえ |

 これは、和除算不変式が実行可能な構成を正しく識別することを示しています。
