 ## 問題の理解

 3 つの文字列が与えられます。`a`、`b`、 そして`c`。 概念的には、`c`～からの文字を取って形成されます`a`そして`b`いくつかのインターリーブ順序で。 各ステップで、どちらかの先頭から 1 文字が取り出されます。`a`または`b`そして追加されました`c`。 一方の文字列が空になると、もう一方の文字列の残りの文字が追加されます。 その後、いくつかの手紙が`c`勝手に置き換えられた可能性があります。 私たちの目標は、**の最小文字数を決定することです。`c`有効なインターリーブと比較して変更されている必要があります**`a`そして`b`。 

入力は複数のテスト ケースを提供します。 各文字列は最大 1000 文字であり、すべてのテスト ケースの長さの合計は 2000 を超えません。`a`または`b`。 これは、複雑なソリューションであることを意味します。`O(|a|*|b|)`テストケースごとに実行可能です。`1000*1000 = 10^6`制限時間は 2 秒以内です。 

すべての文字が同一である場合、または一方の文字列がもう一方の文字列より先に完全に消費される場合、明らかではないエッジ ケースが発生します。 たとえば、次の場合`a = "aa"`、`b = "b"`、 そして`c = "aba"`、変更の最小数は`0`以来`a`そして`b`インターリーブして形成することもできた`aba`。 の文字のみを照合する単純な貪欲なアプローチ`a`失敗するまでは、追加の変更が誤って計算されてしまいます。 

## アプローチ

 ブルートフォースアプローチは、すべてのインターリーブを生成することです。`a`そして`b`そしてそれを比較してください`c`、違いを数えます。 これは正しいですが、実行不可能です。`|a|=n`そして`|b|=m`、 がある`C(n+m, n)`インターリーブ。 たとえ`n = m = 20`、これはすでに1億以上の組み合わせです。 

重要な洞察は、これが編集距離の計算や文字列のインターリーブと同様の **動的プログラミングの問題**であるということです。 させて`dp[i][j]`最初の要素を形成するために必要な変更の最小数を表します。`i+j`の登場人物`c`最初のものを使用して`i`の登場人物`a`そして最初に`j`の登場人物`b`。 各ステップで、次の文字を次のいずれかで取得できます。`a`または`b`それを の対応する位置と比較します`c`、一致しない場合はコストが増加します。 

このアプローチにより、問題は指数関数的な問題から次のような問題に軽減されます。`O(|a|*|b|)`、制約を考慮すると、これは実現可能です。

 ## アルゴリズムのチュートリアル

 1. 2D 配列を初期化する`dp`サイズの`(len(a)+1) x (len(b)+1)`無限大を除く`dp[0][0] = 0`。 これは、空のプレフィックスには変更が必要ないことを表します。 
2. 全体を反復処理する`i`から`0`に`len(a)`そしてすべて`j`から`0`に`len(b)`。 各セルで`(i, j)`部分的にインターリーブしています`i`からのキャラクター`a`そして`j`からのキャラクター`b`。 
3. もし`i < len(a)`から次の文字を取得しようとします。`a`。 比較する`a[i]`と`c[i+j]`。 それらが一致する場合、コストは変わりません。 それ以外の場合は、コストを増分します`1`。 アップデート`dp[i+1][j]`現在の値とこのコストの最小値を使用します。 
4. もし`j < len(b)`から次の文字を取得しようとします。`b`。 比較する`b[j]`と`c[i+j]`そして同様に更新します`dp[i][j+1]`。 
5. テーブルに記入したら、`dp[len(a)][len(b)]`一致するために必要な最小限の変更が含まれています`c`。 

**機能する理由:** すべてのプレフィックスで`(i,j)`、`dp[i][j]`は、対応する接頭辞を形成するために必要な変更の最小数であることが保証されます。`c`。 両方のオプションを考慮することにより（以下から引用）`a`または`b`) 各ステップで、DP はインターリーブの欠落がないことを保証し、コストが正しく累積されます。 これはまさに、変更コストを伴う文字列をインターリーブする場合の繰り返しです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def min_changes(a, b, c):
    n, m = len(a), len(b)
    INF = int(1e9)
    dp = [[INF] * (m+1) for _ in range(n+1)]
    dp[0][0] = 0

    for i in range(n+1):
        for j in range(m+1):
            if i < n:
                cost = dp[i][j] + (a[i] != c[i+j])
                if cost < dp[i+1][j]:
                    dp[i+1][j] = cost
            if j < m:
                cost = dp[i][j] + (b[j] != c[i+j])
                if cost < dp[i][j+1]:
                    dp[i][j+1] = cost
    return dp[n][m]

t = int(input())
for _ in range(t):
    a = input().strip()
    b = input().strip()
    c = input().strip()
    print(min_changes(a, b, c))
```の`dp`初期化では、すべての状態が無限に設定され、未計算または無効な状態が表されます。 更新では最小値が慎重に選択され、最適なソリューションが確実に反映されます。 使用する`a[i] != c[i+j]`「変更されたキャラクター」のコストを簡潔にまとめています。 境界条件は、境界内にある場合にのみ次の文字を試行することによって処理されます。
