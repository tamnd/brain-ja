 ## 解決策
 ## 問題の理解

 の行が与えられています`n`当初番号が付けられた馬`1`に`n`左から右へ。 Xenia は行に対して最大 3 つの操作を実行しました。 各操作は、位置間でセグメントを反転することで構成されます`l`そして`r`、セグメントが反転されるまで、外側の要素を効果的に内側に交換します。 手術の後、馬の最終的な配置が与えられ、この結果を生み出す可能性のある一連の手術を再構築する必要があります。 問題は解決策の存在を保証します。 

入力が小さい（`n`≤ 1000)、これは、時間計算量が O(n³) または O(n²) までのアルゴリズムが 1 秒の制限時間内で動作する可能性があることを示唆しています。 ただし、これらの限界に合わせて適切に拡張できる効率的なアプローチが必要です。 主な課題は、最大 3 回の反転のすべての可能なシーケンスを単純に探索するのは組み合わせ的に膨大であることですが、最大 3 回の反転という問題の制約により、順列の構造を利用できるようになります。 

明白ではないエッジ ケースには、操作が必要ない (すでにソートされている) シーケンス、境界での 1 回の反転で配列が固定されるシーケンス、および複数の小さな反転が発生するシーケンスが含まれます。 たとえば、次の場合`n=5`そして最後のシーケンスは`[1, 4, 3, 2, 5]`、中３馬の一発逆転。`[4, 3, 2]`それを解決します。 不注意なアプローチでは、隣接する要素を貪欲に反転しようとする可能性があり、必要な最小数のセグメントを検出できない可能性があります。 

## アプローチ

 ブルートフォースアプローチは、可能な限りのシングル、ダブル、トリプルリバーサルを試みることです。 単一の反転の場合、すべてのペアをチェックします`(l, r)`そしてセグメントを反転します。 ダブルリバーサルの場合は、2 つのペアのあらゆる組み合わせを試します。 トリプルの場合は、3 つのすべての組み合わせ。 各反転のシミュレーションには O(n) のコストがかかり、O(n²) 個の反転が可能です`(l, r)`ペア。 したがって、合計作業量は 1 つ、2 つ、または 3 つの操作でおよそ O(n² + n⁴ + n⁶) になります。 明らかに、すべてのトリプル反転を試すのは非現実的ですが、もっと賢くすることはできます。 

重要な洞察は、反転によって連続する反転が修正されるということです。 最大 3 つの逆転が許可されるため、馬が同一性順列に対して場違いである最大 3 つのセグメントを特定することに集中できます。`[1, 2, ..., n]`。 並べ替え順序に対して逆になっている各セグメントを特定したら、それを逆転操作として出力できます。 この問題では、左から最初に配置されなかった要素と右から最後に配置されなかった要素を検出し、そのセグメントを反転するだけで十分です。 1 回の反転の後にまだ途中で反転が残っている場合は、2 回目の反転で処理でき、3 回目の反転で最後のケースをカバーできます。 

このアプローチは、反転の回数が制限されているため効率的に機能します。`n`小さいです。 これにより、組み合わせ検索が配列の単純なスキャンに削減され、誤って配置された境界が特定されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース全トリプル | O(n⁶) | O(n) | 遅すぎる |
 | セグメントの検出と反転 | O(n³ 最悪の場合) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 空の操作リストを初期化します。 
2. 現在の配列を恒等順列と比較します。`[1, 2, ..., n]`。 一番左のインデックスを特定する`l`ここで、値は期待値と等しくありません。 右端のインデックスを特定する`r`値が適切に設定されていない場合。 そのようなインデックスが存在しない場合、配列はすでにソートされているため、操作は必要ありません。 
3. セグメントを反転します`[l, r]`そして追加します`(l, r)`操作のリストへ。 
4. この最初の反転の後、配列に間違った要素が配置されていないか再度チェックします。 配列がまだソートされていない場合は、次の左端と右端の場違いのインデックスを見つけてそのセグメントを反転するというプロセスを繰り返します。 
5. 必要に応じて 3 回繰り返します。 最大で 3 回の逆転が許可されており、問題はこれで十分であることを保証します。 
6. 実行された操作の数と反転されたセグメントを出力します。 

**機能する理由:** 各反転は、反転の連続セグメントを厳密に修正します。 最大 3 回の反転が許可され、問題の解決が保証されているため、各パスで左端と右端の反転を修正するこの貪欲なアプローチは、常に最大 3 ステップで終了します。 不変条件は、各反転の後、少なくとも 1 つの反転が修正され、反転されたセグメントの外側に新しい反転が導入されないことです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))
target = list(range(1, n+1))

ops = []

def find_reversal_segment(arr):
    l = 0
    while l < n and arr[l] == target[l]:
        l += 1
    if l == n:
        return None
    r = n - 1
    while r >= 0 and arr[r] == target[r]:
        r -= 1
    return (l, r)

for _ in range(3):
    seg = find_reversal_segment(a)
    if seg is None:
        break
    l, r = seg
    a[l:r+1] = a[l:r+1][::-1]
    ops.append((l+1, r+1))  # 1-indexed output

print(len(ops))
for l, r in ops:
    print(l, r)
```コードはヘルパー関数を定義します`find_reversal_segment`左端と右端の間違って配置された要素を見つけます。 識別されたセグメントを反転し、操作を記録します。 この問題では 3 回以下の逆転で解決できることが保証されているため、最大 3 回繰り返します。 1 インデックス付きの出力は慎重に処理されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    a = list(map(int, input().split()))
    target = list(range(1, n+1))
    ops = []
    def find_reversal_segment(arr):
        l = 0
        while l < n and arr[l] == target[l]:
            l += 1
        if l == n:
            return None
        r = n - 1
        while r >= 0 and arr[r] == target[r]:
            r -= 1
        return (l, r)
    for _ in range(3):
        seg = find_reversal_segment(a)
        if seg is None:
            break
        l, r = seg
        a[l:r+1] = a[l:r+1][::-1]
        ops.append((l+1, r+1))
    out = f"{len(ops)}\n"
    for l, r in ops:
        out += f"{l} {r}\n"
    return out.strip()

# Provided sample
assert run("5\n1 4 3 2 5\n") == "1\n2 4", "Sample 1"

# Custom cases
assert run("6\n6 5 4 3 2 1\n") == "1\n1 6", "Full reverse"
assert run("5\n1 2 3 4 5\n") == "0", "Already sorted"
assert run("4\n1 3 2 4\n") == "1\n2 3", "Single adjacent swap"
assert run("7\n1 2 5 4 3 6 7\n") == "1\n3 5", "Middle segment reversal"
