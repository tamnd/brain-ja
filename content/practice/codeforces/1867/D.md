 ## 解決策
 ## 問題の理解

 配列から始めます`a`長さの`n`ゼロで埋められているので、それをターゲット配列に変換したい`b`同じ長さの。 許可される唯一の操作は「循環上書き」です。次のセットを選択します。`k`個別の位置にあり、これらの位置にある各要素を同じセット内の次の要素のインデックスに置き換えて、最後に折り返します。 もっと具体的に言えば、`l`は私たちが選択したインデックスセット、`a[l[i]]`になる`l[(i+1) % k]`。 

入力は複数のテスト ケースで構成され、それぞれが配列の長さを提供します`n`、操作サイズ`k`、およびターゲット配列`b`。 到達可能な場合、各ケースの出力は単純な「YES」です。`b`0 個以上の操作を使用する場合、それ以外の場合は「NO」です。 

重要な制約は、`n`まで可能です`10^5`テスト ケースごとに、すべてのテスト ケースの合計が以下を超えないようにします。`2·10^5`。 これにより、可能なシーケンスの数は組み合わせで増加するため、すべての操作シーケンスの総当りシミュレーションが禁止されます。 線形またはほぼ線形にスケールするソリューションが必要です。`n`。 

エッジケースが発生するのは次の場合です`k = 1`または`k = n`。 のために`k = 1`、この操作は単一の要素をそれ自体で置き換えます。これは次の場合にのみ役立ちます。`b[i] = i`。 単純な実装ではこれを見落とし、値が範囲外の場合に誤った「YES」が生成される可能性があります。 もう 1 つの微妙な点は、値が繰り返されることです。`b`: 連続する要素が循環操作に対して異なるソースを必要とする場合、不用意に貪欲な割り当てを行うと、循環依存関係が尊重されない可能性があります。 

## アプローチ

 ブルート フォース ソリューションでは、インデックス セットの可能なすべての選択をシミュレートします。`l`次のいずれかになるまで繰り返し周期操作を適用します。`a`等しい`b`あるいはすべての選択肢が尽きた。 原理的には正しいですが、その複雑さは天文学的です。 それぞれの選択`k`からのポジション`n`もっている`C(n, k)`可能性、それは`n = 10^5`そして`k = n/2`全く実現不可能です。 

最適なソリューションに対する洞察は、操作を逆に行うことで得られます。 「構築」しようとするのではなく、`b`段階的に見ていきます`b`そして、どの位置が同じ循環操作の一部になり得るかについての理由を説明します。 操作が単に一連のサイズ内の要素を並べ替えるだけであることを観察します。`k`、どのようなシーケンスであっても、`k`連続した値`b`連続したサイクルを形成している場合は「カバー」できます。 これは貪欲な分解につながります: スキャンします`b`左から右へ、長さの単一の循環演算によって割り当てることができる連続する値ごとに`k`、処理済みとしてマークします。 有効なサイクルに含めることができない要素がある場合、答えは「いいえ」です。 

これにより、問題はスキャンに限定されます`b`までの長さのサイクルを維持しながら`k`、これは線形です`n`。 唯一の追加要件は、`k = 1`、各要素は、直接チェックできる独自のインデックスと一致する必要があります。

 ## アルゴリズムのチュートリアル

 1. 配列の先頭でポインタを初期化します。`b`。 このポインタは左から右にスキャンし、要素をサイクルにグループ化しようとします。 
2. ポインタが最後まで到達していない間に、現在の要素を確認します。`b[i]`。 これは潜在的なサイクルの「先頭」です。 
3. 最大でも長さのサイクルを形成しようとする`k`から始まる`b[i]`。 次の要素が予想される巡回置換に対応するかどうかを確認します。 具体的には、サイクル内の次の要素は、サイクル長を法とした次のインデックスにマップバックされる値でなければなりません。 
4. 有効なサイクルの長さ ≤ の場合`k`が見つかった場合は、そのサイクルを越えてポインタを移動します。 それ以外の場合、設定は不可能であり、「NO」が出力されます。 
5. すべての要素がカバーされるまで繰り返します。 すべての要素が有効なサイクルに参加している場合、「YES」を出力します。 

なぜ機能するのか: この操作は以下に限定された順列です。`k`ポジション。 それぞれの連続したサブシーケンスを保証することで、`b`このような順列に対応する場合、構築する一連の操作が存在することを保証します。`b`。 すべての要素は、正確に 1 つのサイクルに属している必要があります。これは、各操作が選択されたセット内でのみ上書きするという不変条件と一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can_form_array(n, k, b):
    if k == 1:
        # Each element must be equal to its own index
        for i in range(n):
            if b[i] != i + 1:
                return False
        return True

    # Track groups of repeated numbers
    i = 0
    while i < n:
        start = i
        while i < n and b[i] == b[start]:
            i += 1
        group_len = i - start
        if group_len > k:
            return False
    return True

t = int(input())
for _ in range(t):
    n, k = map(int, input().split())
    b = list(map(int, input().split()))
    print("YES" if can_form_array(n, k, b) else "NO")
```取り扱っております`k = 1`長さ 1 のサイクルでは値を変更できないため、特殊なケースとして扱われます。 大型の場合`k`、同一の値をグループ化し、連続する各グループの長さをチェックします。 いずれかのグループが超過した場合`k`、サイクルに収まらないので、答えは「NO」です。 このアプローチでは、実際のサイクルの構築が回避され、時間的には直線的になります。
