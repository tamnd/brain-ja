 ## 問題の理解

 配列が与えられています`a`長さの`n`。 順列を構築する必要があります`b`からの数字の`1`に`n`要素ごとに減算すると、次のようになります。`c_i = a_i - b_i`、に現れる個別の値の数`c`できるだけ大きいです。 

簡単に言うと、各ポジションをペアにします。`i`固有の番号で`b_i`間`1`そして`n`、そして各ペアは違いを生み出します。 目標は、すべてのポジションにわたってこれらの違いを可能な限り多様にすることです。 

重要な制約は、`b`順列でなければならないため、次のすべての整数は`1`に`n`は 1 回だけ使用されます。 の値を最適化していません。`c`それら自体、異なる値がいくつ出現するかのみ`c`。 

テスト ケース全体の入力サイズの合計は最大でも`4 * 10^4`したがって、どのソリューションもテスト ケースごとに基本的に直線的な時間で実行する必要があります。 ソートと重いシミュレーションを伴うものであれば何でも問題ありませんが、二次関数を超えるものは何でも問題ありません。`n`何度も繰り返すと、すでに境界線に達しているでしょう。 

微妙なエッジケースは次のような場合です`n = 1`。 その場合、可能な順列は 1 つだけであり、答えは自明です。 注意すべきもう 1 つの状況は、`a_i`等しいです。 単純な考えでは、特別な方法で等しい値を一致させようとするかもしれませんが、この問題では違いの大きさを制御することはできず、違いの区別のみが役に立ちます。 

最も一般的な誤った直感は、次の数値の広がりを最大化しようとすることです。`c_i`。 それは無関係です: 間の平等な関係だけです。`c_i`案件。 

## アプローチ

 ブルートフォース戦略では、あらゆる順列を試すことになる`b`の`[1, 2, ..., n]`、すべての差を計算します`c`、出現する個別の値の数を数えます。 これは正しいですが、すぐには実行できません。 がある`n!`順列、そしてそれぞれについて計算します`n`違いがあり、大まかに言うと`O(n! * n)`たとえそれが天文学的な規模であるとしても、`n = 10`。 

改善するには、2 つの違いが等しいかどうかを実際に決定するものを理解する必要があります。 我々は持っています：`c_i = a_i - b_i`2つのポジション`i`そして`j`次の場合に同じ値が生成されます。`a_i - b_i = a_j - b_j`を再配置すると次のようになります。`a_i - a_j = b_i - b_j`これは、次のことを示しています。`c`の等しい差に正確に対応します`a`映り込んでいる`b`。 以来`b`は順列であり、個別の値を割り当てる完全な自由があるため、「構造を壊す」ことを試みることができます。`a`。 

重要な観察は、私たちは多様性を最大化できるということです。`c`できるだけ多くのペアを確保することで、`(a_i, b_i)`可能な限り、重複した差異が生じるのを避けてください。 これを行うための最も簡単かつ強力な方法は、`a`そして`b`。 

並べ替えると`a`、次に、次の最小要素をペアにします。`a`の最大値`b`、その逆も同様で、差異を可能な限り分散します。 これは標準的な並べ替えの原則であり、逆の順序にすることで線形結合の変動が最大化されます。 

したがって、インデックスを次のように並べ替えます`a_i`、次に割り当てます`b`その順序に沿って降順で。 

具体的には:

 最小の`a_i`取得します`n`、2番目に小さいものが得られます`n-1`、 等々。 

これにより、単調な構造が生成されます。`c`不必要な繰り返しを避けることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n! · n) | O(n) | 遅すぎる |
 | 最適 (ソート + 逆割り当て) | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を読み取る`a`そして、各値をそのインデックスに関連付けます。 値を正しい位置に配置するにはインデックスが必要です。`b`。 
2. 値の増加順にインデックスを並べ替えます。`a`。 これにより、最小から最大の順序が作成されます`a_i`。 並べ替える理由は、構造を課すことです。`a`したがって、違いがどのように動作するかを制御できます。 
3. 空の配列を作成する`b`長さの`n`。 
4. 値を割り当てる`b`可用性の逆順: 最小のもの`a_i`取得します`n`、次は取得します`n-1`、 等々。 これにより、より大きな`b_i`値は小さい値とペアになります`a_i`。 
5. 出力`b`元のインデックス順に。 

ステップ 4 の背後にある理由は、極端なペアを作成すると、対応する間の分離が最大化されるということです。`a_i`そして`b_i`、2 つの違いが一致する可能性が減少します。 

### なぜ効果があるのか

 並べ替えた後、次のようにします`a_i < a_j`。 次に、割り当てます`b_i > b_j`。 したがって、どのペアでも`i, j`では逆の順序になります`a`そして`b`。 この反単調なペアリングにより、次の式が保証されます。`a_i - b_i`が増加するため、値を可能な限り分散します。`a`の減少によって相殺される`b`。 

これにより、両方の配列が同様に順序付けされている場合に発生する構造化された繰り返しが破壊されます。 すべての違いが明確であることを明示的に保証するわけではありませんが、この構造により分離が最大化され、体系的な衝突が回避されます。これはまさに問題がもたらすものです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))

    idx = list(range(n))
    idx.sort(key=lambda i: a[i])

    b = [0] * n
    val = n

    for i in idx:
        b[i] = val
        val -= 1

    print(*b)
```このソリューションでは、最初にインデックス配列を構築するので、要素の元の位置が失われないようにします。`a`。 並べ替え順`a[i]`元の配列を変更せずに構造を強制することができます。 

変数`val`から始まります`n`と減少し、厳密な順列が保証されます。 各インデックスは一意の値を受け取るため、`b`有効です。 

微妙な点は、決して並べ替えないことです`a`それ自体、インデックスのみ。 これが必要なのは、出力が元の位置の順序を尊重する必要があるためです。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out_lines = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        idx = list(range(n))
        idx.sort(key=lambda i: a[i])

        b = [0] * n
        val = n
        for i in idx:
            b[i] = val
            val -= 1

        out_lines.append(" ".join(map(str, b)))
    return "\n".join(out_lines)

assert run("1\n4\n4 3 2 1\n") is not None, "reverse input stability"
