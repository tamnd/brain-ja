 ## 解決策
 ## 問題の理解

 ソートされた個別の整数のセットが与えられます。 私たちはこのセットを直接制御しません。 代わりに、私たちは対戦相手を変化させる動きを通じて対戦相手と対話します。 

移動するたびに、新しい番号をセットに挿入するか、ボブが制限の下で番号を削除できるようにします。 Bob が削除できるのは、最後に挿入した数値よりも厳密に小さい値のみです。 これにより、連続する移動の間に結合が作成されます。挿入するたびに、Bob の限られた削除ウィンドウのロックが解除される可能性があります。 

ゲームは、ボブが何も削除できなくなるか、固定移動制限に達するまで続きます。 最後に、最終セットの MEX を計算します。これは、存在しない最小の非負の整数を意味します。 

目標は、両側からの最適なプレイの下で最終的な MEX が最大化されるように、挿入される番号を選択することです。 

n が 100000 までという制約は、意味のある分岐やゲーム状態の検索をシミュレートできないことを意味します。 すべての動きは定数時間または対数時間で決定されなければなりません。 これはインタラクティブであるため、非常にクリーンな場合にのみ O(n log n) であっても許容されますが、セットの繰り返しスキャンや移動ごとの MEX の再計算を伴うものはすべて TLE または非同期インタラクションになります。 

ボブがどんな小さな数字でもすぐに削除できると仮定すると、微妙な失敗例が発生します。 削除は最後に挿入された値に依存するため、これは当てはまりません。 たとえば、セットに 0 と 1 の両方が含まれており、最初に非常に小さな数値を挿入した場合、挿入のしきい値を上げるまで、ボブはセットの大部分にアクセスできなくなります。 常に現在の MEX を挿入する単純な貪欲な戦略により、誤って Bob に低い値を削除する機会が多すぎる可能性があります。 

重要な問題は、MEX が数値の存在だけではなく、相互作用のダイナミクスの中で少数の数値が生き残るかによって影響を受けることです。 

## アプローチ

 ブルート フォース ビューでは、ゲーム ツリーをシミュレートしようとします。 どの状態からでも、アリスは未使用の番号を選択して挿入し、ボブは有効な番号を削除して応答し、最終的な MEX を追跡しながら終了まで再帰します。 移動ごとに複数の有効な削除と挿入が発生するため、これはすぐに指数関数的になります。 1 つのステップでも O(n) 個の分岐があり、ゲーム全体を手に入れるのが難しくなります。 

重要な観察は、アリスの選択は任意の最終集合を構築することではなく、ボブの削除後に小さな整数が生き残るかどうかを制御することであるということです。 MEX は 0 から始まる整数のプレフィックスの存在のみに依存するため、ゲーム全体は、ボブが選択したしきい値未満の範囲内の要素を削除し続ける時間を制御することに帰着します。 

これについて考えると便利な方法は、x を挿入するたびに「保護境界」を定義するということです。ボブは x より下の値のみを削除できます。 アリスが常に徐々に大きな値を挿入すると、ボブの削除権限は徐々に拡大しますが、それは制御された方法でのみです。 最適な戦略は、0 から上のすべての整数が効果的に早い段階でセットに強制的に組み込まれるようにすると同時に、十分な大きさの挿入によって整数を「ロック」する前にボブがそれらを選択的に削除することを防ぐことを中心に展開していることが判明しました。 

これにより、ボブの削除ウィンドウを慎重に管理しながら、最終的な MEX より小さいすべての整数が最終的に再導入または保存されるシーケンスを構築するという問題が軽減され、必要なプレフィックス要素を永久に削除することができなくなります。 

標準的な最適な構築では、可能な限り、常に現在の欠落している最小の非負の整数を挿入することに依存しています。これを行うと、ボブは限られた削除を小さな値に費やさなければならなくなるか、プレフィックスの形成を防ぐことができなくなります。

 ## アルゴリズムのチュートリアル

 正しい戦略は、セットの進化に応じてセットの現在の MEX を維持し、常に 0 から始まる連続する整数のプレフィックスを拡張しようとすることに基づいています。 

1. 指定されたセットの初期 MEX を計算します。 これは、最初に存在しない最小の整数です。 この値より下の値は初期構成によってすでに部分的に制約されているため、この値は自然なターゲット境界です。 
2. ポインタを維持する`cur`0 から始まり、最終セットで確実に残したい最小の整数を表します。 
3. アリスが移動するたびに、`cur`まだセットにない場合。 その理由は、最終的な MEX はこの連続したプレフィックスをどこまで拡張できるかに完全に依存するため、欠落しているプレフィックス要素を挿入しようとすることが、Bob にとって常に最適なプレッシャーとなるからです。 
4.挿入後`cur`、ボブの応答を読んでください。 Bob が値を削除した場合は、それに応じてセットを更新します。 
5. ボブが以下の値を削除した場合`cur`、私たちは変わりません`cur`。 これは、より小さい値を削除しても後でプレフィックスを再構築する能力に影響を与えないため、現在のプレフィックス候補が依然として正しい次のターゲットであることを反映しています。 
6. ボブが次の値を削除した場合`cur`、現在のプレフィックスの試行が中断されたことを認識する必要があるため、挿入を再試行します。`cur`また次の動きで。 
7. いつ`cur`セット内に正常に存在しており、ボブの応答によって永久に拒否されることはありません。`cur`次の整数に変更して続行します。 

重要なアイデアは、ボブの制約された削除の下でターゲット プレフィックスが安定した場合にのみ、ターゲット プレフィックスを進めるということです。 

### なぜ効果があるのか

 不変条件は、いつでもすべての整数が`[0, cur)`これらは、将来の移動でアリスが即座に再構築できるようにすることなく、ボブがそれらを永久に削除できない方法で、セット内で効果的に保護されます。 ボブの削除は最後に挿入された値によって制限されるため、アリスは必要に応じて再挿入することで、失われたプレフィックス要素の制御をいつでも取り戻すことができます。 その結果、ボブは最適な MEX 境界を超えるプレフィックスの拡大を確実に阻止することができず、最終的にアリスは最適な再生の下でプレフィックスを可能な限り拡大するよう強制します。 

これにより、ゲームは、最終的な MEX を直接決定する整数の保護されたプレフィックスを着実に拡張することになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def mex_of_set(s):
    m = 0
    while m in s:
        m += 1
    return m

t = int(input())
for _ in range(t):
    n = int(input())
    arr = list(map(int, input().split()))
    s = set(arr)

    cur = 0
    while cur in s:
        cur += 1

    # we try to extend mex greedily
    while True:
        print(cur)
        sys.stdout.flush()

        y = int(input())
        if y == -2:
            exit()
        if y == -1:
            break

        if 0 <= y <= 10**9:
            s.discard(y)

        # if current is now in set, advance
        if cur in s:
            cur += 1
```このソリューションは、現在の候補 MEX 境界を維持し、常にその値の挿入を試みます。 セットは、ボブが移動するたびに動的に更新されます。 唯一の微妙な部分は、対話は即時同期に依存するため、印刷後に必ずフラッシュするようにすることです。 

貪欲不変式により、ボブの削除によってプレフィックスの増加プロセスが永久に破壊されないことが保証されるため、このロジックはボブの最適な戦略を明示的にシミュレートしません。

 ## 特殊なケース

 重要なエッジ ケースは、初期セットに 0 から始まる長く連続したプレフィックスが既に含まれている場合に発生します。その状況では、アルゴリズムはすぐに設定を行います。`cur`そのプレフィックスを超えると、より大きな値の挿入が始まります。 Bob の削除はプレフィックスより上の要素にのみ影響するため、MEX はすぐに安定します。 間違った早期進行が発生しないため、この戦略は依然として機能します。 

もう 1 つのケースは、最初に 0 が欠落している場合です。 ここ`cur`は 0 から始まり、アルゴリズムは繰り返しその挿入を試行します。 ボブは許可されている場合はそれを削除できますが、アリスがその後の動きでそれを再導入するのを防ぐことはできないため、最終的には前進するのに十分な長さのセットで 0 が安定します。`cur`1に。 

最後に、セットに非常に大きなギャップが含まれている場合、欠落している最小のプレフィックスのみが重要となるため、要素を削除する Bob の能力は MEX 形成には無関係になります。 アルゴリズムは当然、これらの大きな値を無視します。`cur`欠落している整数を飛び越えることはありません。
