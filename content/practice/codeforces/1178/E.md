 ## 解決策
 ## 問題の理解

 文字のみから構成される長い文字列が与えられます`a`、`b`、 そして`c`、隣接する 2 つの文字が等しくないという制限があります。 この文字列から、回文でかなり大きいサブシーケンスを抽出する必要があります。その長さは、元の文字列の少なくとも半分 (切り捨て) でなければなりません。 

サブシーケンスとは、残りの文字の順序を変更せずに文字を削除できることを意味します。 回文とは、シーケンスが前方と後方で同じように読まれることを意味します。 タスクは回文の長さを最大化することではなく、十分なサイズの有効な回文を保証するか、それが不可能であることを報告することだけです。 

入力サイズは最大 100 万文字です。 これにより、古典的な動的計画法を使用して部分列を列挙したり、最長の回文部分列を計算したりしようとする解決策は即座に除外されます。これらのアプローチは最悪の場合でも少なくとも 2 次であるためです。 平$O(n \log n)$重い定数を使用するとタイトになるため、線形または線形に近い貪欲な構築を期待する必要があります。 

最も微妙な制約は、「隣接する文字が等しくない」というプロパティです。 これにより構造が大幅に制限されます。すべての文字が局所的に交互に切り替わるため、長いランは存在せず、遷移が頻繁に発生します。 それが、大きな回文の決定論的な構築を可能にする鍵であることが判明しました。 

素朴な試みは、最長の回文部分列を計算することです。 交互に弦の上で`abcabcabc...`多くの貪欲な回文構造では一致するエンドポイントの選択が少なすぎる可能性があるため、このようなアプローチは時間的にも構造的にも困難を伴います。 もう 1 つの間違った考えは、単一の文字が出現するすべてを選択しようとすることです。 文字列のバランスが取れていて交互になっている場合、これはひどく失敗し、必要なものよりもはるかに小さいサブシーケンスが生成される可能性があります。 

2 番目の失敗モードは、調整せずに両端の対称文字を一致させることによって貪欲に回文を構築しようとすると発生します。 文字は 3 種類しかないため、ローカルの貪欲一致では有用な構造が途中で消費され、一致できない中間部分が残る可能性があります。 

## アプローチ

 中心的な観察は、文字が 3 つだけで、隣接する同一の文字がない場合、少なくとも 1 つの文字が、大きな対称サブシーケンスを構築できる構造化された方法で出現する必要があるということです。 

私たちは問題を頻度に基づいた単純なケース分析に分割しました。 少なくとも何らかのキャラクターが登場すれば$\lfloor n/2 \rfloor$単一の繰り返される文字は常に回文であるため、その文字だけを使用して回文をすぐに作成することができます。 興味深いケースは、すべての文字が長さの半分未満で表示される場合です。 

文字が 3 つしかないため、半分に達しない文字がある場合は、少なくとも 2 つの文字で文字列の大部分をカバーする必要があります。 隣接制約により異常なクラスタリングが防止されるため、選択した 2 つの文字間のペアを利用できます。 

重要な建設的なアイデアは、2 つの異なる文字を修正することです。`x`そして`y`、これら 2 つだけを含むサブシーケンスを抽出します。 これにより、問題はバイナリ アルファベット上に回文を構築することに帰着します。 バイナリ文字列では、プレフィックスとサフィックスのペアリング戦略、つまり対称性を維持しながら左と右の出現箇所を一致させることによって、大きな回文を形成できます。 

3 つのペアすべてを試してみます。`(a,b)`、`(a,c)`、`(b,c)`。 各ペアについて、文字列をフィルターし、2 ポインターの貪欲マッチングを使用して最長の回文サブシーケンスの構築を試みます。可能な限り一致するエンドポイントを収集し、一致しない残りを中央に配置します。 最低限必要なのは長さだけなので$n/2$、これらのペアの 1 つは、十分に大きな対称構造を生成する必要があります。 

ブルートフォースの代替手段は、動的プログラミングを使用して、フィルタリングされた各文字列の LPS (最長回文サブシーケンス) を計算することです。 つまり$O(n^2)$ペアあたり、明らかに不可能です$n = 10^6$。 その洞察は、2 文字のアルファベットでは、最適な構造は常に「貪欲に極端なペアを組む」ことであり、DP を完全に回避するということです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース LPS (ペアごとの DP) |$O(n^2)$|$O(n^2)$| 遅すぎる |
 | 3 ペア + 貪欲な 2 ポインター構築を試してみる |$O(n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 次の文字の各ペアをテストして答えを構築します。`{a, b, c}`。 

1. 文字のペアを固定する`(x, y)`これらの文字のみを元の順序で含むフィルタリングされたリストを作成します。 これにより、サブシーケンスの有効性が維持されます。 
2. 両端の文字を収集して、このフィルタリングされたリストから回文を構築しようとします。 先頭と末尾に 1 つずつ、計 2 つのポインターを使用します。 
3. 左ポインタが右ポインタより前にあるときに、文字の一致を試みます。 

もし`s[l] == s[r]`、両方を答えに取り入れ、両方のポインターを内側に移動します。 これにより、回文の対称的な外層が構築されます。 
4. 一致しない場合は、後でより多くの一致の可能性を保持する側から内側に移動します。 登場人物が二人しかいないので、実現可能性を保ったまま安全にどちら側に進むことも可能です。 
5. ループの後、中央に文字が残っている可能性があり、必要に応じて回文の中心として使用できます。 
6. 収集された左側の文字、オプションの中央、および反転された左側の文字を連結することによって、最終的な回文を構築します。 
7. 結果として得られる回文に少なくとも長さがある場合$\lfloor n/2 \rfloor$、すぐに出力します。 
8. 機能するペアがない場合は、出力します。`"IMPOSSIBLE"`。 

貪欲なマッチングが有効な理由: バイナリ アルファベットでは、一致するペアが対称位置から来るように、最適な回文サブシーケンスを再配置できます。 シンボルが 2 つだけ存在するため、片側をスキップしても将来のすべての一致が破壊されることはないため、両端の不一致はグローバルな最適性を失うことなくローカルで解決できます。 

不変条件は、すべてのステップで、構築されたプレフィックスとサフィックスが鏡像であり、残りの文字が引き続き継続のための有効な候補部分列を形成するということです。 現在の選択肢との対称ペアに参加できない文字のみを削除するため、必要なサイズの有効なソリューションに必要な一致を破棄することはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_for_pair(s, a, b):
    # keep only two characters
    t = [c for c in s if c == a or c == b]
    n = len(t)
    l, r = 0, n - 1

    left = []
    mid = None

    while l <= r:
        if l == r:
            mid = t[l]
            break
        if t[l] == t[r]:
            left.append(t[l])
            l += 1
            r -= 1
        else:
            # drop one side; safe because only two symbols exist
            # prefer dropping a character that reduces imbalance
            if t[l] == a:
                l += 1
            else:
                r -= 1

    right = left[::-1]
    if mid:
        return "".join(left + [mid] + right)
    return "".join(left + right)

def solve():
    s = input().strip()
    n = len(s)
    need = n // 2

    chars = ['a', 'b', 'c']

    for i in range(3):
        for j in range(i + 1, 3):
            a, b = chars[i], chars[j]
            res = build_for_pair(s, a, b)
            if len(res) >= need:
                print(res)
                return

    print("IMPOSSIBLE")

if __name__ == "__main__":
    solve()
```この解決策では、まずすべての文字ペアを反復処理し、問題をフィルター処理された 2 つの記号文字列に縮小します。 2 ポインター構造は、等しいエンドポイントを一致させることによって貪欲に回文を構築します。 中央の文字があれば、それが中心として扱われます。 最終チェックでは、長さの制約が満たされていることを確認します。 

微妙な点は、単純なエンドポイントのマッチングを超える複雑なバランシング ロジックを決して試みないことです。 2 文字のアルファベットの構造により、有効な回文は同じ 2 つのシンボルの対称的な出現から描画する必要があるため、積極的な貪欲スキッピングが永続的に実現可能性を失わないことが保証されます。

 ## 特殊なケース

 次のような最小限の文字列`ab`これ以上の戦略は不可能であるため、アルゴリズムはただちに単一ペアの構築に依存するように強制されます。 

次のような完全に交互の長い文字列`abcabcabc...`ペア フィルタリング ステップを頻繁に実行します。 各ペアは密な部分列を生成しますが、十分に大きな回文を生成できるのはそのうちの 1 つだけです。 貪欲なマッチングにより、局所的な不一致による不安定性がなくなります。 

次のような均一な分布`ababababab`バイナリ リダクションで十分であることが確認されます。 2 ポインター マッチングは、ほとんどの文字を対称的にペアリングすることに常に成功し、中央処理により、奇数長の回文が引き続き正しく構築されることが保証されます。
