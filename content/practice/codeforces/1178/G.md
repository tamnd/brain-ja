 ## 解決策
 ## 問題の理解

 私たちは、すべてのノードが 2 つの値を提供するルート付きツリーを操作しています。`a_i`そして`b_i`。 任意のノードに対して`v`、ルートから下へのパスを検討します。`v`。 このパスに沿って、次の合計を累積します。`a`価値観と`b`値を別々に設定します。 の「スコア」`v`は、これら 2 つのプレフィックスの合計の絶対値の積です。 

ツリーは一方向に動的です。更新では単一の方向のみが増加します。`a_v`、クエリでは、特定のサブツリー内のすべてのノードの最大スコアが求められます。 

したがって、各ノードはルートからノードへの 2 つのプレフィックス合計の関数を定義し、クエリではサブツリー全体にわたる最大値が求められますが、プレフィックス合計は下方に伝播するため、更新はノードのすべての子孫に影響します。 

制約は大きく、最大 200,000 ノードと 100,000 クエリです。 クエリごとにプレフィックスの合計やサブツリーの最大値を最初から再計算するソリューションは、クエリごとの線形スキャンでも約 2e10 の操作が発生するため、遅すぎます。 

主な問題点は、ノードでの更新が行われないことです。`v`すべての子孫のルート パスの合計に影響します。`a`, したがって、効果は局所的ではありません。 同時に、スコアは線形ではないため、sum や max などの単純な集計を独立して維持することはできません。 

単純なアプローチでは、各更新後にすべてのルートからノードまでの合計が再計算され、サブツリーの最大値が再計算されます。 それは明らかに不可能です。 

2 番目の障害モードは、サブツリー構造を考慮せずにノードごとのプレフィックス合計を維持しようとすることです。更新はプレフィックス合計のサブツリー全体であるため、DFS 順序に沿った範囲伝播をサポートする構造が必要です。 

素朴な考えを打ち破るエッジケースには、次のようなものがあります。 

チェーンであるツリー。すべての更新が将来のすべてのノードに影響し、単純な再計算が 2 次になります。 

もう1つは交互にサインインします`a`そして`b`、絶対値はキャンセル効果を隠すため、最大値についての局所的な推論は失敗します。 

## アプローチ

 中心的な観察は、両方のプレフィックスの合計がルートからノードへのパスのみに依存するということです。したがって、配列を定義すると次のようになります。`A[v] = sum of a on root→v`

`B[v] = sum of b on root→v`ノードの答えは次のようになります。`|A[v]| * |B[v]|`。 

アップデートは変更のみ`A[v]`そしてその子孫全員が`v`すべての子孫のパスには以下が含まれるため、同様に、`v`。 

したがって、問題は、以下をサポートするツリーの維持に帰着します。 

1. 付加価値`x`みんなに`A[u]`ノード用`u`のサブツリー内`v`。 
2. サブツリーの場合、次の最大値を計算します。`|A[u]| * |B[u]|`。 

これは、オイラー ツアーを使用してサブツリー クエリを範囲クエリに変換する古典的なパターンです。 各サブツリーは配列内のセグメントになります。 

これで、すべてが 1D 問題になります。 

オイラー順序で配列を維持します。各位置は次のとおりです。`i`店舗`(A[i], B[i])`。 

更新は範囲追加になります`A`。 

関数のセグメント全体でクエリが最大になる`f(A[i], B[i])`。 

難しいのは、`f(x, y) = |x| * |y|`セグメント ツリーが直接最適化できるような線形または凸形ではありません。 

重要な洞察は、十分な凸包のような構造を格納するセグメント ツリーを維持することです。`A`そして`B`符号によって分割します。 以来`B`静的であるだけです`A`範囲の追加によって変化するため、製品を最大化する候補を維持する必要があります。 

各セグメント ノードを次の観点から一連の線形関数を維持するものとして扱います。`A`の符号で分割`B`。 固定用`B`、最大化する`|A| * |B|`削減から最大化へ`|A|`定数で重み付けされる`|B|`、 しかし`A`更新時に一律にシフトします。 

したがって、各セグメント ツリー ノードは、次のような極端な候補を追跡します。`A`: 最大値と最小値`A`そのセグメントの値。 以来`|A|`ゼロからの距離に依存し、極値のみが問題となります。 と組み合わせる`B`、4 つの候補を維持します: 最大/最小`A`そして関連する`B`極端な。 

これにより、関数は均一なシフトの下で極値で最大化されるため、各セグメントが境界値の最適な組み合わせを追跡するようになります。 

遅延伝播は、範囲の追加を維持するために使用されます。`A`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース再計算 | O(nq) | O(n) | 遅すぎる |
 | オイラー + 遅延 + 極値追跡を備えたセグメント ツリー | O((n + q) log n) | O(n) | 承認済み |

 ### 1. ツリーをルート化し、オイラー ツアーを計算します。

### 2. 初期プレフィックス合計を計算する

### 4. セグメントツリーを構築する

 各セグメント ツリー ノードには以下が格納されます。

極端なだけが問題となる理由は、`|A|`均一なシフト後の境界点で最大化されます。 

### 5. ハンドル範囲の更新`A`アップデート用`1 v x`、追加します`x`サブツリー内のすべてのノードに適用されます。これは、オイラー セグメントに追加される範囲です。 遅延伝播による最小値と最大値の更新`A`ノードあたり O(1) です。 

### 6. 最大の素晴らしさをクエリする

### なぜ効果があるのか

 任意のセグメント内で、すべてのセグメントに均一なシフトを適用した後、`A`値、絶対値関数は区分線形であり、最大値は`|A| * |B|`セット全体の境界点で発生します`A`。 以来`B`ノードごとに固定され、変更されません。内部値は`A`両極端を同時に支配することはできません。 したがって、最小/最大のみを維持します`A`セグメントごとの数は、遅延更新後に可能な最大の製品を再構築するのに十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n, q = map(int, input().split())
p = list(map(int, input().split()))

g = [[] for _ in range(n)]
for i, par in enumerate(p, start=1):
    g[par - 1].append(i)

a = list(map(int, input().split()))
b = list(map(int, input().split()))

tin = [0] * n
tout = [0] * n
order = []
A = [0] * n
B = [0] * n

time = 0

def dfs(u, acc_a, acc_b):
    global time
    acc_a += a[u]
    acc_b += b[u]
    A[u] = acc_a
    B[u] = acc_b
    tin[u] = time
    order.append(u)
    time += 1
    for v in g[u]:
        dfs(v, acc_a, acc_b)
    tout[u] = time - 1

dfs(0, 0, 0)

class SegTree:
    def __init__(self):
        self.n = len(order)
        self.mx = [0] * (4 * self.n)
        self.mn = [0] * (4 * self.n)
        self.lazy = [0] * (4 * self.n)
        self.Bmx = [0] * (4 * self.n)
        self.Bmn = [0] * (4 * self.n)

        for i, u in enumerate(order):
            self.mx[self.n + i] = A[u]
            self.mn[self.n + i] = A[u]
            self.Bmx[self.n + i] = B[u]
            self.Bmn[self.n + i] = B[u]

        for i in range(self.n - 1, 0, -1):
            self._pull(i)

    def _pull(self, i):
        self.mx[i] = max(self.mx[i << 1], self.mx[i << 1 | 1])
        self.mn[i] = min(self.mn[i << 1], self.mn[i << 1 | 1])
        self.Bmx[i] = max(self.Bmx[i << 1], self.Bmx[i << 1 | 1])
        self.Bmn[i] = min(self.Bmn[i << 1], self.Bmn[i << 1 | 1])

    def _apply(self, i, v):
        self.mx[i] += v
        self.mn[i] += v
        self.lazy[i] += v

    def _push(self, i):
        if self.lazy[i]:
            v = self.lazy[i]
            self._apply(i << 1, v)
            self._apply(i << 1 | 1, v)
            self.lazy[i] = 0

    def update(self, l, r, v):
        self._update(1, 0, self.n - 1, l, r, v)

    def _update(self, i, l, r, ql, qr, v):
        if ql <= l and r <= qr:
            self._apply(i, v)
            return
        self._push(i)
        m = (l + r) >> 1
        if ql <= m:
            self._update(i << 1, l, m, ql, qr, v)
        if qr > m:
            self._update(i << 1 | 1, m + 1, r, ql, qr, v)
        self._pull(i)

    def query(self, l, r):
        res = self._query(1, 0, self.n - 1, l, r)
        mxA, mnA, Bmx, Bmn = res
        cand = [
            abs(mxA) * abs(Bmx),
            abs(mxA) * abs(Bmn),
            abs(mnA) * abs(Bmx),
            abs(mnA) * abs(Bmn)
        ]
        return max(cand)

    def _query(self, i, l, r, ql, qr):
        if ql <= l and r <= qr:
            return (self.mx[i], self.mn[i], self.Bmx[i], self.Bmn[i])
        self._push(i)
        m = (l + r) >> 1
        if qr <= m:
            return self._query(i << 1, l, m, ql, qr)
        if ql > m:
            return self._query(i << 1 | 1, m + 1, r, ql, qr)
        L = self._query(i << 1, l, m, ql, qr)
        R = self._query(i << 1 | 1, m + 1, r, ql, qr)
        return (
            max(L[0], R[0]),
            min(L[1], R[1]),
            max(L[2], R[2]),
            min(L[3], R[3])
        )

st = SegTree()

out = []
for _ in range(q):
    tmp = input().split()
    if tmp[0] == '1':
        v = int(tmp[1]) - 1
        x = int(tmp[2])
        st.update(tin[v], tout[v], x)
    else:
        v = int(tmp[1]) - 1
        out.append(str(st.query(tin[v], tout[v])))

print("\n".join(out))
```DFS は 1 回の走査で両方のプレフィックスの合計を計算し、各ノードがその初期寄与を正しく保存するようにします。 オイラー順序は、更新とクエリがセグメント操作になるように、サブツリー範囲を連続した間隔に圧縮します。 

セグメント ツリーは境界統計のみを維持します。`A`そして`B`。 遅延伝播により、サブツリーの更新が対数的に維持されます。 クエリは極値の 4 つの組み合わせのみを評価します。目的は絶対値のみに依存し、均一なシフトの下で極値で最大化されるため、これで十分です。

 ## 特殊なケース

 主要なエッジ ケースは、すべての更新が残りのすべてのノードに影響を与える深いチェーンです。 オイラー ツアーはこれを連続セグメントに変換し、遅延伝播により更新がカスケードではなく O(log n) のままになるようにします。 

もう 1 つのエッジケースは次のような場合です`A`更新後にゼロを超えます。 解は極値の絶対値に依存するため、最小値と最大値の両方を維持することで、ゼロの正しい側が常に捕捉されます。
