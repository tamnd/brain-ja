 ## 解決策
 ## 問題の理解

 私たちには長い一片が与えられています$m$、最初はすべて色で塗られています$0$。 次に色$1$を通して$n$一つずつ適用されます。 各色$i$セグメントを選択することで適用されます$[a_i, b_i)$現在モノクロなのでカラーで塗り直す$i$。 

最後に、単位セグメントごとに、$[j-1, j)$最終的な色が固定されている$c_j$、ここでそれぞれ$c_j$いる$[1, n]$。 どの色も$1 \dots n$最終構成に少なくとも 1 回は表示されます。 

タスクは、セグメント操作の有効なシーケンスの数をカウントすることです。$(a_i, b_i)$まさにこの最終的な色のストリップを作成できます。 

主な問題点は、各再ペイント操作が、ペイント時に完全に 1 色のセグメントに作用する必要があるため、以前の操作が、ネストされた高度に構造化された方法で後のすべての操作を制約することです。 

制約は非常に具体的な意味で重要です。 ストリップの長さ$m$までです$10^6$したがって、二次遷移を使用して位置ごとに推論するソリューションはすべて$m$不可能です。 ただ、色数が少ないので、$n \le 500$これは、トランジションごとにすべての位置を反復することを避ける限り、色または構造間隔に関する動的プログラミングが実行可能であることを示唆しています。 

微妙な問題は、明らかに独立していない多くの異なる間隔履歴によって、同じ最終的な色が生成される可能性があることです。 たとえば、次のような単純な交互パターンでも、$1,2,1$、カラーで最初にペイントされる可能性のあるセグメント$1$色で可能なことを変える$2$中間の単色制約は以前にペイントされたブロックに依存するためです。 

単純な間違いは、各色が最後の連続セグメントに対応すると考えることです。 後の再色により、複数のばらばらの最終ブロックに色がペイントされる可能性があるため、これはすぐに失敗します。 もう 1 つの間違いは、各色間隔がその最終的な出現範囲全体をカバーする必要があると想定していることです。 実際には、以前の操作により、最終状態では表示されない方法で領域が一時的に結合または分割される場合があります。 

## アプローチ

 ブルート フォース ビューでは、プロセスを逆方向にシミュレートするか、各色の可能な間隔をすべて列挙しようとします。 各色ごとに$i$の場合、その順番で現在単色になっている有効なセグメントを選択し、再帰的に続行します。 無効な状態を取り除いたとしても、考えられるセグメントの選択肢の数は膨大です。すべての色が上に適用される可能性があります。$O(m^2)$セグメントがあり、$n$色を使用することで、実現可能な制限をはるかに超えた検索スペースを提供します。 

重要な構造的洞察は、視点を逆転させることです。 ペイントを進めることを考える代わりに、有効な再ペイント操作のシーケンスが存在するためには、最終配列にどのような構造が存在する必要があるかを考えます。 

色のとき$i$が適用されると、その時点では単色である連続したセグメントが描画されます。 最終的な構成では、これは、色が配置される領域が$i$最後に適用されたセグメントは、その内部が後でペイントされたより高いインデックスの色によって完全に「支配」されているセグメントを形成します。 これにより、入れ子構造が作成されます。各色の最後の適用は、以前の適用を分割して調整する間隔のように動作します。 

これは、古典的な間隔 DP の解釈につながります。 この問題を、最終的な配列のセグメントを考慮し、そのセグメントを生成する有効な「構築履歴」の数をカウントすることに圧縮します。 トランジションは、リージョンに影響を与えた最後の操作に対応する分割ポイントの選択によって異なります。 

重要な観察は、どのセグメントでも$[l, r]$、その中に最後に塗られた色は何らかの色でなければなりません$x$そのセグメントに表示されるものと、ペイントされた操作$x$サブセグメントを正確にカバーしている必要があります。$x$「最後に塗装された」色が支配的になります。 そのピボットを修正すると、左側と右側の部分が独立した部分問題になります。 

これは問題を間隔にわたる DP に変換しますが、すべての間隔にわたる直接の間隔 DP に変換します。$[l, r]$は$O(m^2)$、大きすぎます。 2 番目の重要な最適化は、遷移が色が変化する境界のみに依存するため、最も近い出現を使用して遷移を圧縮し、間隔ごとではなく位置ごとに DP 状態を維持できることです。 

最終的に最適化されたソリューションは、各位置が境界として機能し、同じ色の出現によって引き起こされる有効な分割からの寄与を遷移が蓄積する構造化 DP に帰着します。

 ## アルゴリズムのチュートリアル

 最終的な配列の間隔に基づいて DP を定義しますが、圧縮された方法で計算されます。 

1. 各色の位置を前処理します。 それぞれの色について、それが表示されるすべてのインデックスがわかっています。 これにより、その色が最後にペイントされた時刻に対応する可能性のある有効なセグメントを推論することができます。 
2. 定義します$dp[l][r]$セグメントを完全に構築する方法の数として$[l, r]$。 以来$m$大きい場合でも、そのようなすべての状態を明示的に構築することはありません。 代わりに、増分構造を使用して右エンドポイントごとに遷移を計算します。 
3. エンドポイントを反復処理します$r$左から右へ。 それぞれについて$r$、考えられるすべての左側の境界を考慮します$l$ここで、有効な最後の操作は次の時点で終了します。$r$。 これらの境界は、同じ色の出現によって決定されます。$c_r$位置に影響を与える最終的な再描画のアンカーとして機能できるのはそれらのみであるためです。$r$。 
4. 固定色の場合$x = c_r$、以前の出現位置を維持します。$x$。 連続する出現の各ペアは、最後の操作が含まれるセグメントを定義します。$x$始まって終わるかもしれない。 私たちは、そのようなすべての有効な選択肢からの貢献を集計します。 
5. からの移行が行われるように、プレフィックス DP の合計を維持します。$l$に$r$で計算できます$O(1)$そして、色ごとの累積寄与を保存することで内部合計の再計算を回避します。 
6. ポジションごとに貢献度を積み上げます$r$最終的な答え、または前方に伝播する DP 状態に変換されます。 

この構造により、すべての有効なペイント シーケンスが間隔ごとに正確に 1 つの分解ポイントに一意に対応することが保証されるため、各シーケンスは 1 回だけカウントされます。 

### なぜ効果があるのか

 すべての有効なシーケンスには、特定の間隔に影響を与える明確に定義された「最後の操作」があります。$[l, r]$。 その操作は、間隔内に表示される色に対応する必要があり、そのセグメントの境界は、適用時にその色が連続ブロックとして存在できる領域と位置合わせする必要があります。 この最後の操作を修正すると、区間の残りの部分が、互いに素なセグメント上の独立した部分問題になります。 これにより、DP が重複や省略なしに構築スペース全体を分割することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n, m = map(int, input().split())
    c = list(map(int, input().split()))

    # last occurrence tracking per color
    pos = [[] for _ in range(n + 1)]
    for i, x in enumerate(c):
        pos[x].append(i)

    # dp[i]: number of ways to finish at position i
    dp = [0] * (m + 1)
    dp[0] = 1

    # prefix sum of dp
    pref = [0] * (m + 2)
    pref[0] = 1

    # last occurrence pointer per color
    ptr = [0] * (n + 1)

    for r in range(1, m + 1):
        col = c[r - 1]

        # advance pointer
        ptr[col] += 1

        # basic contribution: extend from previous position
        dp[r] = dp[r - 1]

        # additional contributions from same color structure
        # (compressed transitions over occurrences)
        for i in range(ptr[col]):
            l = pos[col][i] + 1
            dp[r] = (dp[r] + pref[r - 1] - pref[l - 1]) % MOD

        pref[r] = (pref[r - 1] + dp[r]) % MOD

    print(dp[m] % MOD)

if __name__ == "__main__":
    solve()
```コードは、ストリップのプレフィックス上の DP を維持します。 配列`dp[r]`位置で「終了」する有効な構造の数を表します`r`、それまでの構造が完全に解決されたと解釈されます。 プレフィックス合計配列`pref`合計を繰り返し再計算することなく、範囲にわたる寄与度を高速に集計できます。 

以前に発生したカラーに対するループは、有効な再描画セグメントが最終構成で単色構造と一致する必要があるという重要な制約をエンコードするものです。 各出現境界は、その色の最後の再描画が適用された可能性のあるセグメント分割を定義します。 

プレフィックス合計を使用した減算により、有効なサブセグメント内に完全に収まる構成のみがカウントされることが保証されます。

 ## 特殊なケース

 重要なエッジケースは、すべてのポジションが同じ色を共有する場合です。 この状況では、すべての再描画操作を同じ領域上でネストする必要があるため、有効なシーケンスの数は、ネストされた間隔を選択する方法の数に応じて増加します。 アルゴリズムは、同じ色の出現に対して繰り返しプレフィックスを蓄積することでこれを処理し、すべての分割ポイントがカウントされるようにします。 

もう 1 つのエッジケースは、次のような厳密な代替です。$1,2,1,2,\dots$、各色が複数回再表示されます。 ここで、出現するたびに新しい有効なセグメント境界が作成され、DP は最後の出現だけではなく、すべてのセグメントからの寄与を蓄積する必要があります。 プレフィックスベースの集約により、これらの複数の構造分解が崩れないようになります。 

最後のエッジケースは、高度にクラスター化されたブロックに色が表示される場合です。 色が 1 つの連続したブロックに表示される場合でも、以前の発生は形成できる有効な再描画間隔の数に影響を及ぼし、DP は複数のネストされた間隔履歴を 1 つの選択肢にまとめるのではなく、正しくカウントします。
