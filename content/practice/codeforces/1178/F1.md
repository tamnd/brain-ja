 ## 解決策
 ## 問題の理解

 最後のストリップは次のもので構成されます。`n`単位セグメントであるため、`n = m`このサブタスクでは、次のすべての色が`1`に`n`は 1 回だけ表示されます。 入力配列は、すべての再描画操作が終了した後に各単位セグメント上に表示される色を記述する単純な順列です。 

最初はストリップ全体に色が付いています`0`。 色は昇順に 1 つずつ適用されます。 色のとき`i`を使用する場合、アリスは現在単色を持つ連続区間を選択し、区間全体を色で再描画する必要があります。`i`。 すべての操作の後、すべての位置に順列で指定された色が表示されます。 

最終的な配置を正確に生成する音程の選択肢がいくつあるかを数える必要があります。 

サイズ制限は 500 のみであるため、3 次動的計画法は完全に許容されます。 すべての間隔の選択肢を指数関数的に検索すると、すぐに爆発してしまいます。`n = 20`考えられるシーケンスはすでに天文学的にたくさんあります。 二次記憶も無害です。 

主な危険は、ペイントの順序が固定されていることです。 いつでも任意の間隔を再描画することはできません。 より大きな色に対して選択されたすべての間隔は、以前に作成した単色領域内に完全に収まる必要があります。 

もう 1 つの簡単な間違いは、ポジションを独立して考えることです。 仮定する```
3 3
1 2 3
```答えは```
5
```ない`1`。 間隔の異なるネスト構造によって、同じ順列が生成される可能性があります。 

2 番目の微妙なケースは、```
3 3
2 1 3
```誰の答えは```
2
```色`1`は配列全体の最小色であるため、その間隔が再帰のルートになります。 左から右に処理しようとするアプローチでは、有効な配置が 1 つ失われます。 

3 番目のトリッキーなケースは、```
4 4
2 4 1 3
```最小の色は中央にあります。 左辺と右辺は独立した部分問題になりますが、各辺はいくつかの方法で根に関連する可能性があります。 これらの添付ファイルの選択を忘れると、答えが過小評価されます。 

## アプローチ

 ブルート フォース検索では、考えられるすべての間隔シーケンスをシミュレートします。 いつでも色がつく`i`が適用されると、現在利用可能なすべての単色間隔を列挙し、再帰的に実行します。 これはすべての絵画の歴史を正しく調査しますが、州の数は指数関数的に増加します。 中程度の値であっても、`n`、可能性の数は非常に多くなります。 

重要な観察は、任意の間隔内の最小の色を観察することで得られます。 

いくつかの部分配列を考えてみましょう`[l,r]`。 その色の中で、位置を決めましょう`p`最小値が含まれています。 色は昇順に適用されるため、この色は内部の他の色よりも先にペイントされている必要があります。`[l,r]`。 したがって、左側のすべての色と右側のすべての色は、この最小の色に属する間隔内に作成されなければなりません。 

それは位置を意味します`p`再帰的分解のルートとして機能します。 左右の部分は独立していますが、各側がいくつかの異なる方法で根元に向かって拡張する場合があります。 これは自然に区間動的計画法につながります。 

間隔ごとに`[l,r]`、 定義する`dp[l][r]`正確にその間隔を生成する有効な絵画履歴の数として。 最小色が位置にある場合`p`、次に、左と右の部分間隔を結合する必要があります。 一方の側がルートに接続できる方法が何通りあるかを数えるには、追加の状態が必要です。 

結果として生じる複雑さは 3 次的なものになり、これは簡単に十分に高速になります。`n ≤ 500`。

 | ブルートフォース | 指数 | 指数 | 遅すぎる |
 | 最適 | O(n3) | O(n²) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. インターバルごとに`[l,r]`、位置を特定します`p`最小限の色です。 なぜなら`n=500`、各間隔内のすべての候補をチェックするのは十分安価です。 
2. 定義する`dp[l][r]`部分配列を構築する方法の数として`[l,r]`。 
3. 別のテーブルを導入する`f[l][r]`、ここで区間の根`[l,r]`左側の境界から強制的に接続されます。 
4. 対称テーブルの導入`g[l][r]`、ルートは右側の境界から強制的に接続されます。 
5. 空の間隔は一方向に寄与します。 
6. 最小の色を仮定します。`[l,r]`位置にあります`p`。 
7. 計算するには`f[l][r]`、分割ポイントを選択します`k`間`p`そして`r`。 セグメント`[p,k]`はルートの右拡張に属しますが、`[k+1,r]`独立した部分問題になります。 これら 2 つの部分のウェイの数を掛けて、全体を合計します。`k`。 
8. コンピューティング`g[l][r]`左側の分割ポイントを選択して対称にします。 
9. 最後に、全インターバル`[l,r]`左のアタッチメント数と右のアタッチメント数を乗算して得られます。```
dp[l][r] = f[l][p-1] × g[p+1][r]
```1. 短い間隔がすべて計算されるように、間隔を長さの昇順に処理します。 
2. 答えは次のとおりです。`dp[0][n-1]`。 

### なぜ効果があるのか

 任意の間隔内では、その間隔のすべての色の中で最小の色が最初に描画されます。 その後のすべての再描画は、その最小色によって作成された単色セグメント内で行われる必要があります。 したがって、最小値の左右の色が互いに干渉することはなく、各辺を独立して扱うことができます。 

テーブル`f`そして`g`残りのサフィックスまたはプレフィックスをより小さな部分問題に委任する前に、ルート間隔が連続する位置を吸収するためのすべての可能な方法を数えます。 すべての有効なペイント履歴は、そのような選択の 1 つのシーケンスに正確に対応し、反復によって生成されるすべてのシーケンスはペイント ルールに従います。 したがって、動的プログラムはすべての有効な履歴を 1 回だけカウントします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

n, m = map(int, input().split())
a = list(map(int, input().split()))

mn_pos = [[0] * n for _ in range(n)]
for i in range(n):
    pos = i
    for j in range(i, n):
        if a[j] < a[pos]:
            pos = j
        mn_pos[i][j] = pos

dp = [[1] * n for _ in range(n)]
f = [[1] * n for _ in range(n)]
g = [[1] * n for _ in range(n)]

def get_dp(l, r):
    if l > r:
        return 1
    return dp[l][r]

def get_f(l, r):
    if l > r:
        return 1
    return f[l][r]

def get_g(l, r):
    if l > r:
        return 1
    return g[l][r]

for length in range(1, n + 1):
    for l in range(n - length + 1):
        r = l + length - 1
        p = mn_pos[l][r]

        val_f = 0
        for k in range(p, r + 1):
            val_f += get_g(p + 1, k) * get_dp(k + 1, r)
            val_f %= MOD
        f[l][r] = val_f

        val_g = 0
        for k in range(l, p + 1):
            val_g += get_dp(l, k - 1) * get_f(k, p - 1)
            val_g %= MOD
        g[l][r] = val_g

        dp[l][r] = get_f(l, p - 1) * get_g(p + 1, r)
        dp[l][r] %= MOD

print(dp[0][n - 1])
```最初の前処理ループは、間隔ごとに最小要素の位置を保存します。 位置が 500 しかないため、二次前処理のコストはわずかです。 

ヘルパー関数は戻ります`1`空いた間隔で。 これは乗算の標準的な中立要素であり、多くの境界チェックを削除します。 この規則を忘れると、通常、配列の終わり付近で 1 つずつ誤差が生じます。 

間隔は長さの増加順に処理されます。 すべての繰り返しは短い間隔のみを参照するため、必要な値はすべてすでに使用可能です。 

テーブル`f`そして`g`非対称の添付ファイル数を実装します。 それらの式は互いに鏡像です。 両方のテーブルを別々にしておくと、遷移がきれいになり、複雑な大文字と小文字の区別が回避されます。
