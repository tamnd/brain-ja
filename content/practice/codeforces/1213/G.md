 ## 解決策
 ## 問題の理解

 すべてのエッジにコストがかかる重み付きツリーが与えられ、頂点のペア間のパスがどの程度「高価」になるかについて複数の質問を受けます。 

任意の 2 つの頂点について$u$そして$v$、グラフはツリーであるため、それらの間には単純なパスが 1 つだけ存在します。 そのパスに沿って、すべてのエッジの重みを調べ、最大のものを採用します。 クエリでは、個別の頂点のすべてのペアのうち、接続パス上のこの最大エッジの重みが指定のしきい値を超えないものがいくつあるかを尋ねます。$q$。 

したがって、各クエリは基本的に、重みまでのエッジのみを「使用」できるかどうかを尋ねています。$q$、そのようなエッジのみを介して接続されるノードのペアの数。 

直接的な解釈は、最大でも重みを持つエッジのみを保持することによって形成されたグラフの同じ接続コンポーネント内にある頂点のペアを数えているということです。$q$。 

制約は次のとおりです$2 \cdot 10^5$頂点、エッジ、クエリ。 これにより、クエリごとに接続を最初から再計算することが直ちに排除されます。 クエリごとに DFS または BFS を実行しようとするアプローチでは、おおよその結果が得られます。$O(m(n + n))$、これは実現可能な限界をはるかに超えています。 

2 番目の微妙な問題は、ペアがすべてのクエリに対して個別にカウントされることです。 ソートと再利用構造を利用しない限り、答えは単純な意味での増分ではありません。 

単純な間違いは、各クエリを個別に解釈し、毎回フィルタリングされたグラフを再構築することです。 たとえば、すべてのエッジが個別であり、クエリも大きい場合、中程度の入力でもトラバーサルを繰り返すとタイムアウトになります。 

もう 1 つの一般的な落とし穴は、LCA 前処理を使用してすべてのペアのパス最大値を計算しようとすることです。 LCA はパス上の最大エッジを計算できますが、$O(\log n)$、これを全員のためにやります$O(n^2)$ペアは無理です。 

## アプローチ

 ブルートフォースの視点は定義から始まります。 クエリごとに$q$、すべてのペアをチェックします$(u, v)$、パス上の最大エッジ重みを計算し、有効なペアをカウントします。 LCA 前処理を使用しても、各クエリにコストがかかります$O(n^2 \log n)$、これは完全に不可能です$n = 2 \cdot 10^5$。 

視点を反転すると、より構造化されたビューが得られます。 「各ペアについて、そのパス上の最大エッジはいくらか」を尋ねる代わりに、「各しきい値について、そのしきい値までのエッジがアクティブ化されたときに接続されるペアの数」を尋ねます。 

許容される重みを増やすと、エッジが昇順に表示されます。 エッジを追加するたびに、以前は別々だった 2 つのコンポーネントがマージされる場合があります。 サイズの成分が 2 つある場合$a$そして$b$マージすると、彼らは貢献します$a \cdot b$これは、一方のコンポーネントのすべての頂点が、最大で現在のウェイトのエッジを使用して、もう一方のコンポーネントのすべての頂点に到達できるためです。 

この観察により、問題はソートされたエッジを介した動的な接続プロセスに変換されます。これはまさに DSU (素集合結合) が効率的に維持するものです。 クエリごとにコンポーネントを再計算する代わりに、重みを増やしてエッジを処理し、接続されたペアの数を段階的に維持します。 

クエリはしきい値によって並べ替えることもできるため、エッジとクエリの両方を順番にスイープすることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(m n^2)$それより悪い |$O(n)$| 遅すぎる |
 | DSU + ソート |$O((n + m)\log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 クエリに昇順で応答しながら、重みを増加させながらエッジを処理します。$q$。 

1. すべてのエッジを重みで降順でない順に並べ替えます。 

これにより、エッジを処理するときに、以前に処理されたすべてのエッジがそのエッジよりも重くならないことが保証されます。 
2. クエリを並べ替えますが、元のインデックスは追跡します。 

これにより、効率的に処理しながら、元の順序で回答を出力することができます。 
3. 独自のコンポーネント内の各ノードを使用して DSU を初期化します。 

2 つの異なるノードが接続されていないため、各コンポーネントは最初はゼロペアを提供します。 
4. 実行中の変数を維持する`ans = 0`処理されたエッジのみを使用して現在接続されている有効なペアの数を表します。 
5. ポインタをエッジの上に置きます。 

各クエリしきい値について$q$、エッジに重みを付けながらエッジポインタを進めます。$\le q$。 

エッジを処理するたびに$(u, v, w)$：

もし$u$そして$v$サイズの異なる DSU コンポーネントにある$a$そして$b$、それらを結合すると増加します`ans`による$a \cdot b$。 

次に、コンポーネントを結合します。 
6. すべてのエッジを処理した後、$q$、 店`ans`その質問に対する答えとして。 

### なぜ効果があるのか

 重量に達するまでエッジを処理しているときはいつでも$q$、DSU コンポーネントは、正確に、最大でも重みを持つエッジによって形成されるサブグラフの接続コンポーネントです。$q$。 同じコンポーネント内のノードのすべてのペアには、最大エッジが以下のパスがあります。$q$コンポーネント内のすべてのエッジがこの境​​界を満たしているためです。 

逆に、2 つのノードが異なるコンポーネント内にある場合、エッジを使用したノード間にパスは存在しません。$\le q$、そのため、パスには より大きいエッジが含まれている必要があります。$q$。 したがって、それらは正しく除外されます。 

各ユニオン操作は、新しく追加されたエッジによって導入された新しい到達可能なペアを正確に考慮します。2 つのノードが接続されると、それらはすべての大きなしきい値に対して接続されたままになるため、どのペアも 2 回カウントされません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return 0
        if self.size[a] < self.size[b]:
            a, b = b, a
        self.parent[b] = a
        pairs = self.size[a] * self.size[b]
        self.size[a] += self.size[b]
        return pairs

def solve():
    n, m = map(int, input().split())
    edges = []
    for _ in range(n - 1):
        u, v, w = map(int, input().split())
        edges.append((w, u - 1, v - 1))

    edges.sort()

    queries = list(map(int, input().split()))
    q = [(queries[i], i) for i in range(m)]
    q.sort()

    dsu = DSU(n)
    ans = 0
    ei = 0
    res = [0] * m

    for val, idx in q:
        while ei < len(edges) and edges[ei][0] <= val:
            w, u, v = edges[ei]
            ans += dsu.union(u, v)
            ei += 1
        res[idx] = ans

    print(*res)

if __name__ == "__main__":
    solve()
```DSU は、すべてのマージが作成される新しい頂点ペアの数と正確に一致するように、コンポーネントのサイズを保存します。 エッジとクエリを並べ替えることにより、エッジを再訪したり、接続を再計算したりすることがなくなります。 

微妙な実装の詳細は、からの貢献を返しています。`union`DSU 内でグローバルに更新するのではなく、 これにより、ロジックが明示的に保たれ、誤って二重カウントされることが回避されます。 

もう 1 つの重要な点はインデックス付けです。DSU 操作中に変換が繰り返されることを避けるために、頂点はただちにゼロベースのインデックス付けに変換されます。

 ## 特殊なケース

 重要なエッジ ケースは、すべてのエッジの重みが最小のクエリよりも大きい場合です。 この状況では、初期のクエリに応答する前に結合は発生しないため、しきい値が最小のエッジの重みを超えるまで、すべての応答はゼロのままでなければなりません。 までマージは実行されないため、DSU はこれを保証します。`edges[ei][0] <= q`。 

もう 1 つのケースは、すべてのエッジの重みが同じである場合です。 その後、すべてのエッジが処理されると、すべてのクエリはゼロ (その重みを下回る場合) またはペアの全数を返します。 しきい値に達すると、すべての等しい重みのエッジが単一のバッチで処理されるため、アルゴリズムはこれを自然に処理します。 

3 番目の微妙なケースは、大きなコンポーネントが早期に形成される場合です。 非常に小さなエッジが 2 つの大きなサブツリーを接続すると、ペアの寄与はすぐに大きくなります。 共用体関数は次のように計算します。`size[a] * size[b]`マージ時に、接続時のカウントが正確であり、後で再計算されないことを保証し、将来のクエリでの二重カウントを回避します。
