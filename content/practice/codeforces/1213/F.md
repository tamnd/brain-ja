 ## 解決策
 ## 問題の理解

 文字列のインデックスの 2 つの順列が与えられ、両方の順列は、非表示の文字列がソートされて表示される順序を記述します。 言い換えれば、文字列を取得し、順列によって規定された順序で文字を読み取る場合`p`、文字のシーケンスは非減少である必要があり、順列の順序で読み取る場合にも同じことが当てはまります。`q`。 

これにより、同じ未知の文字配列に対して 2 つの独立した「並べ替え順序制約」が作成されます。 各順列は、文字値において前の位置が後の位置を超えてはいけないインデックスのチェーンを定義します。 タスクは、両方の制約を尊重し、少なくとも`k`はっきりとした文字。 そのような文字列が存在しない場合は、不可能であることを報告する必要があります。 

重要な問題は、単一の位置が 2 つの異なるソートされたシーケンスに参加しており、慎重にマージしない限り、これらのシーケンスが競合する可能性があることです。 この制約は、「等しくなければならない」というサイクルが出現した場合に、インデックス間の等価関係を効果的に強制します。 

複雑さの観点から見ると、`n`まで可能です`2 · 10^5`したがって、どのような解も線形または線形演算に近いものでなければなりません。 すべての位置のペアごとの比較や順列全体にわたる繰り返しの伝播を伴うものは遅すぎます。 Union-Find またはグラフ圧縮アプローチは、構造によって暗示されています。つまり、制約は順列内の連続する要素間でローカルであり、各制約は単調です。 

組み合わせた順序付けのサイクルによって矛盾が生じると、微妙な失敗のケースが発生します。 たとえば、両方の順列が意味する場合、`a ≤ b`そして`b ≤ a`さまざまな道を経て、`a`そして`b`等しくなければなりません。 このような等価クラスが崩壊しすぎると、十分な異なる文字を導入する能力が失われる可能性があります。`k`不可能。 

もう 1 つの隠れた落とし穴は、1 つの順列を満たすと自動的に他の順列も役立つと仮定することです。 実際には、制約は共有インデックスを介してのみ重なり合い、その相互作用により、その構造が実現可能性を決定するグラフが作成されます。 

## アプローチ

 直接的な試みは、各ステップで両方の順列をチェックしながら、貪欲に文字を割り当てることです。 最小文字から最大文字まで文字列を埋めて、一貫性を検証してみることができます。 ただし、各割り当てには両方の順列に沿ったスキャン制約が必要な場合があり、更新の伝播により同じノードに何度も触れる可能性があります。 最悪の場合、各文字割り当てが長さの連鎖に沿って繰り返し緩和を引き起こす可能性があるため、これは二次関数になります。`n`。 

重要な観察は、両方の置換が「このインデックスはそのインデックス以下の文字を持たなければならない」という形式の制約のみを課すということです。 これは有向関係です。 各エッジが次のようなグラフを作成すると、`u → v`手段`s[u] ≤ s[v]`の場合、すべての順列は、その連続するペアに沿ったエッジのチェーンに寄与します。 最終的な構造は、文字の半順序制約をエンコードした有向グラフです。 

問題は、すべてのエッジが尊重されるように、可能な限り最小の文字ラベルをノードに割り当てると同時に、少なくとも次のことを保証することになります。`k`異なるラベルが使用されます。 これは、DAG のような制約システムと一致する値を割り当てることと同じです。 ただし、グラフには循環が含まれる場合があり、強接続コンポーネント内ではすべてのノードが同じ特性を共有する必要があります。これは、それらのノードが推移閉包を通じて両方向に相互に制約し合うためです。 

したがって、最初にグラフを強く接続されたコンポーネントに圧縮します。 各コンポーネント内では、すべての位置が強制的に等しくなります。 コンポーネント間で DAG を取得します。 この DAG では、エッジが小さいか等しいラベルから大きいラベルに向かうようにラベルを割り当てる必要があります。 これは、最小ラベルの位相伝播に相当します。 

最後に、少なくとも必要なものは、`k`明確なラベル。 これは、コンポーネントの数が少なくとも次の場合にのみ可能です。`k`なぜなら、各コンポーネントは最大でも 1 つの異なる文字に寄与するからです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | SCC 凝縮 + DAG 標識 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 制約を有向グラフに変換し、強く接続されたコンポーネントを介してそれを解決します。 

1. 次のコマンドを使用して有向グラフを構築します。`n`ノード。 それぞれの順列について`p`、エッジを追加します`p[i] → p[i+1]`。 に対しても同じことを行います`q`。 これらのエッジは単調性制約をエンコードします。 
2. Kosaraju または Tarjan を使用して、このグラフの強接続成分を計算します。 等価性を強制する「≤」制約のサイクルが存在するため、同じコンポーネント内のノードは同じ文字を受け取る必要があります。 
3. 部品点数が以下の場合`k`、十分に明確な文字を生成できないため、すぐに「NO」を出力します。 
4. 各 SCC がノードとなる要約グラフを構築します。 コンポーネントと交差する元のエッジがある場合は常に、コンポーネント間にエッジを追加します。 
5. 各コンポーネントに文字値を割り当てます。 コンポーネントをトポロジカルな順序で処理します。 各コンポーネントは、出力制約に違反しない最小の文字を取得します。 グラフは DAG であるため、制約を前方に安全に伝播できます。 
6. 割り当て後の使用量が以下の場合`k`個別の文字を使用する場合、未使用の文字容量を独立したコンポーネント (出力制約を制限しないコンポーネント) 間で分割することで、制約を破ることなく一部のコンポーネントのラベルを安全に増やすことができます。 
7. 元の各位置をコンポーネントに割り当てられた文字にマッピングして、最終的な文字列を構築します。 

機能する理由: SCC 分解により、サイクルによって強制されるすべての平等が確実に尊重されます。 DAG は、矛盾した順序が残らないようにします。 最小限の有効なラベルを割り当てることで一貫性が保証され、非循環構造により、トポロジー順に処理した後に後方衝突が発生しないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    n, k = map(int, input().split())
    p = list(map(lambda x: int(x) - 1, input().split()))
    q = list(map(lambda x: int(x) - 1, input().split()))

    g = [[] for _ in range(n)]
    gr = [[] for _ in range(n)]

    def add(u, v):
        g[u].append(v)
        gr[v].append(u)

    for i in range(n - 1):
        add(p[i], p[i + 1])
        add(q[i], q[i + 1])

    visited = [False] * n
    order = []

    def dfs1(v):
        visited[v] = True
        for to in g[v]:
            if not visited[to]:
                dfs1(to)
        order.append(v)

    def dfs2(v, c):
        comp[v] = c
        for to in gr[v]:
            if comp[to] == -1:
                dfs2(to, c)

    for i in range(n):
        if not visited[i]:
            dfs1(i)

    comp = [-1] * n
    cid = 0
    for v in reversed(order):
        if comp[v] == -1:
            dfs2(v, cid)
            cid += 1

    if cid < k:
        print("NO")
        return

    cg = [[] for _ in range(cid)]
    indeg = [0] * cid

    for v in range(n):
        for to in g[v]:
            if comp[v] != comp[to]:
                cg[comp[v]].append(comp[to])
                indeg[comp[to]] += 1

    import heapq
    heap = list(range(cid))
    heapq.heapify(heap)

    label = [-1] * cid
    used = 0

    while heap:
        c = heapq.heappop(heap)
        if label[c] == -1:
            label[c] = used % 26
            used += 1
        for to in cg[c]:
            if label[to] == -1:
                label[to] = label[c]
            indeg[to] -= 1

    res = ['a'] * n
    for i in range(n):
        res[i] = chr(ord('a') + label[comp[i]])

    print("YES")
    print("".join(res))

if __name__ == "__main__":
    solve()
```実装では、まず両方の順列から含意グラフを構築します。 SCC フェーズでは、すべての強制等価グループが圧縮されます。 圧縮ステップでは、コンポーネント上に DAG を構築します。 

ラベル付け戦略は、エッジに沿った伝播を考慮した方法で文字を貪欲に割り当てます。 モジュロ`26`小文字の範囲内に収まることが保証され、最初の実現可能性チェックにより、要件を満たすのに十分なコンポーネントがあることが確認されます。`k`個性的なキャラクター。 

実装上の微妙な問題は、コンポーネント間のすべてのエッジが 1 回だけ考慮されるようにすることです。 重複は正確さに影響しませんが、実行がわずかに遅くなる可能性があります。 もう 1 つは DFS の再帰の深さであり、これは次のように処理されます。`sys.setrecursionlimit`。

 ## 特殊なケース

 両方の順列によりすべてのインデックスで単一サイクルが強制される場合、1 つの重要なエッジ ケースが発生します。 その状況では、すべてのノードが 1 つの SCC に属しているため、アルゴリズムは正しく出力します。`NO`いつでも`k > 1`。 SCC フェーズでは、すべての制約が崩壊し、不可能性が明示されます。 

別のケースは、順列が同一である場合です。 この場合、エッジはサイクルのない単純なチェーンのみを形成するため、各ノードは独自のコンポーネントになります。 DAG はすでに線形であり、文字を割り当てると貪欲に単調な文字列が生成され、あらゆる条件を簡単に満たすことができます。`k ≤ n`。 

3 番目の微妙なケースは、サイクルがローカルにのみ存在する場合です。 たとえば、3 つのノードがサイクルを形成し、残りのノードは独立したままになる場合があります。 SCC ステップは、サイクルを 1 つのコンポーネントに分離し、残りの自由度を保存して、依然として到達できることを保証します。`k`十分なコンポーネントが残っている限り、個別の文字を使用できます。
