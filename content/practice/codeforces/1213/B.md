 ## 解決策
 ## 問題の理解

 いくつかの独立した実験が与えられ、各実験は製品の日次価格のシーケンスで構成されます。 各シーケンスについて、次の意味で「不運」な日が何日あるかを特定する必要があります。価格がその日よりも厳密に低い後日が存在する場合、その日は悪い日とみなされます。 

したがって、配列内のすべての位置について、その右側のどこかに小さい値があるかどうかを事実上尋ねることになります。 そのような値が存在する場合、その位置は答えに寄与します。 

制約は合計すると大きくなり、すべてのシーケンスの合計の長さは最大 150,000 になります。 これにより、各要素をその右側のすべての要素と比較するソリューションは即座に除外されます。これは、最悪の場合は 2 次であり、敵対的な入力で約 10¹⁰ の演算が発生するためです。 テスト ケースごとに線形または線形に近いスキャンが必要です。 

配列が厳密に増加している場合、微妙なエッジケースが発生します。 たとえば、`[1, 2, 3, 4]`の場合、右側にこれより小さい値を持つ要素はないため、答えはゼロになります。 単純なアプローチでは、以下の値ではなく厳密に小さい値を適切にチェックしない場合、比較が誤ってカウントされる可能性があります。 

もう 1 つのエッジ ケースは、次のような厳密に減少する配列です。`[5, 4, 3, 2, 1]`。 最後の要素を除くすべての要素には、その後に小さな要素があるため、答えは次のようになります。`n-1`。 すべてのプレフィックス要素が不良として認定されるため、これはブルート フォースにとって最悪のシナリオです。 

## アプローチ

 直接解釈すると、毎日の単純な強引な方法が導き出されます。`i`、一日中スキャン`j > i`あるかどうかを確認してください`a[j] < a[i]`。 そのような日が存在する場合、その日の答えをインクリメントします`i`。 

これは定義に文字通り従っているため、正しいです。 しかし、そのコストが問題となる。 減少シーケンスなどの最悪の場合は、大まかに実行します。`n + (n-1) + ... + 1`、これはテスト ケースあたり O(n²) の比較です。 合計あり`n`150,000 までは非常に遅くなります。 

重要な観察は、将来の値がどれより小さいかを知る必要はなく、少なくとも 1 つが存在するかどうかだけを知る必要があるということです。 これは、配列のサフィックスに関する情報を維持することを示唆しています。 右から左にトラバースすると、これまでに確認された最小値を追跡できます。 各位置で、現在の要素とこの接尾辞の最小値を比較します。 現在の値がその右側の最小値より大きい場合は、より小さい将来の要素が存在することがすでにわかっているため、この位置は不適切です。 

これにより、サフィックスの最小値を段階的に更新できるため、問題はテスト ケースごとに 1 回のパスに減ります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | 遅すぎる |
 | サフィックス最小スキャン | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 各テスト ケースを個別に処理し、配列を右から左にスキャンします。 

1. 前日から開始して変数を初期化する`min_suffix`最後の価格で。 これは、現在位置の厳密に右側にあるすべての日の中で確認された最小価格を表します。 
2. 毎日点検しながら、一度に 1 ステップずつ左に移動します`i`。 
3. ポジションごとに比較します。`a[i]`と`min_suffix`。 もし`a[i] > min_suffix`、その後、より低い価格の後日が存在するため、その日`i`悪いので、答えをインクリメントします。 
4. インクリメントするかどうかに関係なく、更新します。`min_suffix = min(min_suffix, a[i])`で始まるサフィックスの最小値が常に反映されるようにするため`i`。 
5. 最初の要素が処理されるまで続行します。 

正確かどうかは、インデックスを処理するときに次のことが行われるかどうかにかかっています。`i`、`min_suffix`全く等しい`min(a[i+1], ..., a[n])`したがって、この比較は、より小さい要素が右側に存在するかどうかを確認することと同じです。 

### なぜ効果があるのか

 あらゆる段階で、`min_suffix`サフィックスの最小値を現在のインデックスの厳密に右側に格納します。 この不変条件は、各要素の処理後にのみ更新されるため、保持されます。 したがって、条件は、`a[i] > min_suffix`が存在する場合にまさに真です`j > i`そのような`a[j] < a[i]`。 の身元に関する情報はありません`j`必要なのは、その存在だけであり、接尾辞の最小値によって完全に捕捉されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
out = []

for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    
    min_suffix = a[-1]
    bad = 0
    
    for i in range(n - 2, -1, -1):
        if a[i] > min_suffix:
            bad += 1
        if a[i] < min_suffix:
            min_suffix = a[i]
    
    out.append(str(bad))

print("\n".join(out))
```実装は逆方向スキャンに直接続きます。 変数`min_suffix`は常に現在のインデックスの右側にある最小値を表すため、比較は`a[i] > min_suffix`これは「悪い日」の定義を正確に翻訳したものです。 更新条件により、新しい最小値が正しく伝播されることが保証されます。 

初期化には注意が必要です`min_suffix`最後の要素を使用します。最終日には将来の日がなく、決して悪い日になることはありません。 また、データセット間の相互汚染を避けるために、回答アキュムレーターはテスト ケースごとに保持されます。

 ## 特殊なケース

 次のような単一要素の配列では`[10]`、逆スキャンが初期化されます`min_suffix`10 として設定され、ループには入りません。 比較は行われないため、答えは 0 のままです。これは、将来の日数がないため、定義と一致します。 

次のような厳密に増加するシーケンスでは、`[1, 2, 3, 4]`、各ステップのサフィックスの最小値は常に現在の値以上であるため、条件は次のようになります。`a[i] > min_suffix`決してトリガーされません。 アルゴリズムは誤検知を正しく回避します。 

次のような厳密に減少するシーケンスでは、`[5, 4, 3, 2, 1]`、最後の要素を除くすべての要素は、その時点でのサフィックスの最小値より大きいため、それぞれが不良としてカウントされます。 アルゴリズムは正確にインクリメントします`n-1`これは、すべてのプレフィックス要素の将来の値が小さいという事実と一致します。
