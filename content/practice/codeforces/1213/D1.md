 ## 解決策
 ## 問題の理解

 整数のリストが与えられ、選択した数値をその半分を切り捨てたものに置き換えることによって繰り返し減らすことができます。 このような交換にはそれぞれ 1 回の操作が必要です。 目標は、すべての数値を等しくすることではなく、一連の半減操作の後に、少なくとも k 個の数値を正確に同じ値にすることです。 

重要な問題は、平等は与えられるものではなく、作られるものだということです。 10 のような値は、何回割るかに応じて、10、5、2、1、0 になります。 したがって、すべての要素は到達可能な値のチェーンを定義し、最小の総コストで少なくとも k 個の要素によって到達できる目標値を見つけようとしています。 

制約は非常に小さく、n は最大 50、値は 200000 までです。これにより、n の指数関数は即座に除外されます。 ただし、各数値は log2(200000) 程度 (20 ステップ未満) でしか割ることができないため、要素ごとの変換をシミュレートし、各要素のすべての可能な状態を収集する余裕があることが強く示唆されています。 

微妙なエッジ ケースは、異なる開始値が異なるコストで同じ中間値に崩壊する可能性があるという事実から生じます。 たとえば、パスは異なりますが、8 は 2 段階で 2 になり、9 も同様に 2 段階で 2 になります。 もう 1 つのエッジ ケースはゼロです。数値は一度ゼロになるとゼロのままであるため、多くの要素がそこに安価に収束します。 最も頻繁に出現する初期値を選択するような素朴な貪欲な選択は失敗します。なぜなら、等価性は変換後にのみ達成される可能性があるからです。 

## アプローチ

 ブルートフォースアプローチでは、ターゲット値を直接決定しようとします。 考えられるターゲットごとに、いくつの要素をそれにどれだけのコストで変換できるかを計算し、コストの合計が最小になる要素のうち k 個を選択することができます。 具体的には、要素ごとに、考えられるすべての値に達するまで 2 で割るシミュレーションを行い、それぞれに到達するまでのコストを記録し、目標ごとに集計します。 

要素ごとに到達可能な状態の数が少ないため、この強引なアイデアはすでに最適に近づいています。 各数値は最大で約 20 個の状態を生成するため、50 個の要素全体で合計約 1000 個の遷移しかありません。 重要な観察は、これらのチェーンによって生成されるものを超えるターゲットを考慮する必要がないということです。 すべての有効な等しい値は少なくとも 1 つの変換チェーンに出現する必要があるため、それらの候補のみを考慮します。 

各候補値について、その値に到達できる要素からすべてのコストを収集し、並べ替えて、最小の k コストを取得します。 答えはすべての候補者に対する最小値です。 これが機能するのは、目標値を固定すると、問題が要素ごとに独立したものになるためです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (ターゲットごとの完全なシミュレーション) | O(n * A log A) | O(nA) | 遅すぎる/ぎこちない |
 | 最適 (すべての状態 + 集計を事前計算) | O(n * log A + S log S) | O(S) | 承認済み |

 ここで S は生成された状態の総数で、約 n log A です。 

## アルゴリズムのチュートリアル

 1. 各要素について、各値に到達するまでに必要な操作の数を追跡しながら、2 による除算を繰り返すことによって到達可能なすべての値を生成します。 

これにより、その要素の値からコストへのマッピングが構築されます。 
2. 到達可能な値ごとに、ペア (コスト、要素インデックス) のリストを保存します。 

これは視点を逆転させます。1 つの要素がどのような値を生成できるかを尋ねる代わりに、どの要素が値を生成できるかを収集します。 
3. すべての要素にわたって見られる個別の値ごとに、それを最終ターゲットの候補として考慮します。 
4. 固定の候補値については、その値に到達できるすべての要素からすべてのコストを収集します。

到達できる要素が k 未満の場合は、k 個の等しい数を形成できないため、スキップします。 
5. 収集したコストを並べ替え、最小の k 値の合計を取得します。 
6. すべての候補値にわたる最小の合計を追跡します。 

### なぜ効果があるのか

 要素上のすべての操作シーケンスは、2 で割る回数によって完全に決定されるため、到達可能なすべての状態は事前計算されたチェーン内で一意に表現されます。 k 要素が等しくなる有効な最終構成は、少なくとも 1 つのチェーンに現れる何らかの値に対応する必要があります。 固定値の場合、各要素が独立して寄与し、パス構造ではなく全体の操作を最小化することのみを考慮するため、k 個の最小コストを選択することが最適です。 すべての候補が列挙されるため、グローバル最小値を見逃すことはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    from collections import defaultdict

    # value -> list of (cost)
    pos = defaultdict(list)

    for x in a:
        cur = x
        dist = 0
        while True:
            pos[cur].append(dist)
            if cur == 0:
                break
            cur //= 2
            dist += 1

    ans = float('inf')

    for v, costs in pos.items():
        if len(costs) < k:
            continue
        costs.sort()
        ans = min(ans, sum(costs[:k]))

    print(ans)

if __name__ == "__main__":
    solve()
```コア実装は、変換チェーンを正確に反映します。 数値ごとに、繰り返しの半分化をシミュレートし、遭遇した各値までの距離 (操作の数) を記録します。 ディクショナリは、さまざまな要素間で同じ値に到達するすべての方法をグループ化します。 

候補値を評価する場合、すべての寄与者の中で k 個の最も安価な変換が必要なため、ソートが必要です。 ソートされた最初の k 個のコストの合計は、その値を達成するためにどの要素を「費やす」かを選択する最適な方法を直接表します。 

よくある間違いは、同じ値が同じ要素チェーンから複数回出現する可能性があることを忘れることです。 この実装では、各要素がステップ レベルごとに正確に 1 つのコストを寄与するため、安全です。 

## 実用的な例

 ### 例 1

 入力:```
5 3
1 2 2 4 5
```チェーンを計算します。 

| 要素 | チェーン (価値 : コスト) |
 | --- | --- |
 | 1 | 1:0 → 0:1 |
 | 2 | 2:0 → 1:1 → 0:2 |
 | 2 | 2:0 → 1:1 → 0:2 |
 | 4 | 4:0 → 2:1 → 1:2 → 0:3 |
 | 5 | 5:0 → 2:1 → 1:2 → 0:3 |

 次に、値 2 をターゲットとして考えます。 

コストが 2 になるのは、2 (0) から、2 (0) から、4 (1) から、5 (1) からです。 

k = 3 つの最小コスト、0 + 0 + 1 = 1 を選択します。 

| ターゲット | 費用 | 選択された k=3 | 合計 |
 | --- | --- | --- | --- |
 | 2 | [0,0,1,1] | [0,0,1] | 1 |

 これは最適な答えと一致します。 

### 例 2

 入力:```
4 2
10 20 40 1
```チェーンには次のものが含まれます。 

10: 10,5,2,1,0

 20：20、10、5、2、1、0

 40：40、20、10、5、2、1、0

 1:1,0

 ターゲット 5 について考えてみましょう。 

| 要素 | コストを5にする |
 | --- | --- |
 | 10 | 1 |
 | 20 | 2 |
 | 40 | 3 |

 k=2 の最小値、つまり 1 + 2 = 3 が必要です。 

これは、最適なターゲットは必ずしも最初から頻繁に使用されている値である必要はなく、複数の要素によって低コストで到達可能な値であることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log A + S log S) | 各数値は O(log A) 状態を生成し、値ごとのグループ化と並べ替えが優先されます。 
| スペース | O(S) | すべての要素にわたって格納される、到達可能なすべての状態 |

 n ≤ 50 および log A ≤ 20 の場合、S は最大でも約 1000 であるため、時間とメモリは両方とも容易に制限内に収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import inf
    import sys
    input = sys.stdin.readline

    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    from collections import defaultdict
    pos = defaultdict(list)

    for x in a:
        cur = x
        dist = 0
        while True:
            pos[cur].append(dist)
            if cur == 0:
                break
            cur //= 2
            dist += 1

    ans = float('inf')
    for v, costs in pos.items():
        if len(costs) >= k:
            costs.sort()
            ans = min(ans, sum(costs[:k]))

    return str(ans)

# provided sample
assert run("5 3\n1 2 2 4 5\n") == "1"

# all equal already
assert run("3 2\n7 7 7\n") == "0"

# must go to zero
assert run("3 3\n1 2 3\n") == "3"

# larger spread
assert run("4 2\n10 20 40 1\n") == "3"

# boundary k=1
assert run("5 1\n8 3 5 7 9\n") == "0"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | すべて等しい | 0 | 操作は必要ありません |
 | 1 2 3 → k=3 | 3 | ゼロへの収束 |
 | 混合権力 | 3 | 最適な中間ターゲット |
 | k=1 の場合 | 0 | 些細な選択 |

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべての数値がすでに等しい場合です。 例えば`7 7 7`アルゴリズムはすべての要素から値 7 のゼロコスト エントリを記録するため、候補 7 はすぐに合計 0 を返します。 

もう 1 つのケースは、最適なミーティング ポイントがゼロの場合です。 のような入力の場合`1 2 3`、すべてのチェーンは最終的にゼロに達し、ゼロには十分な貢献者が蓄積されます。 コストは異なりますが、アルゴリズムは当然、候補として 0 を選択し、最も安価な k 個のパスを選択します。 

3 番目のケースは、最適な値が元の配列にない場合です。 で`10 20 40 1`、値 5 は最初は表示されませんが、低コストで複数の要素から到達可能です。 すべての中間状態が記録されるため、5 が依然として考慮され、最適になる可能性があります。
