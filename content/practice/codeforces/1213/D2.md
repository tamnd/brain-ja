 ## 解決策
 ## 問題の理解

 整数の配列が与えられるので、任意の数値を繰り返し選択し、それを 2 で割って切り捨てることができます。 目標は、少なくとも実行するために必要なそのような操作の最小数を見つけることです。$k$配列内の数値が等しい。 各操作では数値が減少しますが、増加することはありません。最終的な数値にはゼロが含まれる場合があります。 入力は次のように指定します$n$、要素の数、および$k$、等しくしたい数値のカウント。 出力は、除算演算の最小数を表す単一の整数です。 

制約は重要です。$n$は 200,000 に達する可能性があり、配列内の数値も 200,000 に達する可能性があります。 すべての数値に対してすべての一連の操作を試行する単純な総当りアプローチでは、次のようなパフォーマンスが得られます。$O(200{,}000^2)$制限時間をはるかに超えた作戦。 線形またはほぼ線形にスケールするアプローチが必要です。$n$そして数値の範囲。 

エッジ ケースには、多くの数値がすでに等しい状況、すべての数値が明確な 2 の累乗である状況、または次のような状況が含まれます。$k$に等しい$n$。 たとえば、次の場合$n = 3$、$k = 3$、配列が [8, 4, 2] の場合、最小限の演算は 3 になります。8 を 4 で割る (1)、8 を 2 で割る (2)、4 を 2 で割る (3) と 3 つの 2 が得られます。 最初の等しいペアで停止する不注意な貪欲なアルゴリズムは、グローバル最小値を逃す可能性があります。 

## アプローチ

 ブルートフォースソリューションは概念的には単純です。 数値ごとに、すべての割り算のシーケンスをシミュレートし、すべての中間値を記録してから、次の値を選択してみることができます。$k$各中間値と等しくなる可能性のある数値。 演算を合計して最小値を選択します。 これは、すべての分割シーケンスが予測可能であるため機能しますが、遅すぎます。 すべての数値がゼロに達するまでに最大 18 ステップかかる場合 (200,000 → 1 は約 18 分割であるため)、次のようになります。$n = 200{,}000$の場合、すでに数値ごとに約 360 万の中間値を調べていることになり、単純な列挙では 7,000 億ステップを超えることになります。 

重要な観察は、各数値が各除算後に得られる一連の値として表現できるということです。 たとえば、20 → 10 → 5 → 2 → 1 → 0 です。どの数値を最初に割るかを考慮する必要はありません。 必要なのは、考えられるすべての最終値について、元の数値がその値に到達するまでに必要な操作の数だけです。 これらのカウントを収集したら、すべての候補の最終値について、$k$少なくとも実行する最小の操作数$k$その値と等しい数値。 

この観察により、より迅速なアプローチが可能になります。 各数値を処理し、到達可能な各値からその値に到達するために必要な演算数へのマッピングを構築し、候補値ごとに演算を並べ替えて最小値を合計します。$k$。 これにより、問題は次のようなものに縮小されます$O(n \log n)$各数字は最大でも全体の時間にかかるため、$\log_2(\text{max a})$変換とせいぜいサイズの小さいリストのソート$n$候補値ごとに効率的です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * max(a) * k) | O(n * 最大(a)) | 遅すぎる |
 | 最適 | O(n log(max(a)) + n log n) | O(n log(max(a))) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 辞書を初期化する`ops_map`ここで、キーは潜在的な最終値を表す整数であり、値はそのキーに到達するために必要な操作数のリストです。 
2. 数字ごとに`x`配列内で、2 による除算を繰り返すシミュレーションを実行します。`x`ゼロに達します。 カウンターを維持する`op`操作はゼロから開始します。 それぞれの値について`v`遭遇、追加`op`に`ops_map[v]`そして増加します`op`。 このステップでは、考えられるすべての目標と、その目標を達成するために各数値がどれくらいのコストがかかるかを構築します。 
3. すべての数値を処理した後、すべてのキーを反復処理します。`ops_map`。 キーに関連付けられた各リストは、この値になる可能性のある数値の操作数を表します。 リストを昇順に並べ替えます。 
4. 各キーについて、リストに少なくとも$k$要素の最初の合計$k$必要な合計操作を計算するための値$k$この値と等しい数値。 すべてのキーにわたる最小合計操作を追跡します。 
5. 最小の合計操作を出力します。 これにより、少なくとも取得するために必要な最小分割数が保証されます。$k$等しい数。 

機能する理由: このアルゴリズムは、各数値から到達できるすべての値と、それらに到達するためのコストを列挙します。 最小のものを合計すると、$k$各候補値のコストは、選択された値であることを保証します。$k$最小限の操作で数値はすべてその値と等しくなります。 ソートにより、最適性が維持され、常にコストが最も低い数値が取得されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import defaultdict

def main():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    
    ops_map = defaultdict(list)
    
    for x in a:
        val = x
        op = 0
        while True:
            ops_map[val].append(op)
            if val == 0:
                break
            val //= 2
            op += 1
    
    ans = float('inf')
    for val, ops_list in ops_map.items():
        if len(ops_list) >= k:
            ops_list.sort()
            total_ops = sum(ops_list[:k])
            if total_ops < ans:
                ans = total_ops
    
    print(ans)

if __name__ == "__main__":
    main()
```コードが初期化されます`ops_map`リストのdefaultdictとして、各値に到達するコストを保存します。 内側のループは、2 で割ることによって得られるすべての中間数値と、必要な操作の数を記録します。 最後のループでは、少なくとも次の条件で達成可能な候補値をフィルタリングします。$k$数値、演算回数のソート、最小値の合計$k$、最小限の答えを更新します。 の`val == 0`条件により、到達可能な値としてゼロが含まれることが保証されます。
