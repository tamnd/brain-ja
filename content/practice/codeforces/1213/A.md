 ## 解決策
 ## 問題の理解

 ライン上の整数の位置に配置されたいくつかのチップが与えられます。 私たちの目標は、可能な限り低コストの移動シーケンスを使用して、すべてのチップを単一の共有座標に移動することです。 

各チップは 2 つの異なる方法で移動できます。 チップは、コストなしで左右に 2 ユニットジャンプできます。または、1 コインのコストで左右に 1 ユニット移動できます。 主な難点は、ゼロコストの移動では同じパリティ クラス内でポジション パリティを自由に変更できるのに対し、奇数のシフトでは実際にコストが発生することです。 

このタスクは、すべてのチップを同じ整数の位置に再配置できるように、必要なコインの最小合計数を計算することです。 

制約は小さく、最大でも 100 チップです。 つまり、単一のターゲットのチェックは n 内で線形であり、入力範囲内のすべての座標をスキャンしても O(n^2) 内で許容されるため、すべての候補ターゲット位置を試すソリューションはすでに実現可能です。 ただし、動きの構造は、より数学的な単純化が存在する必要があることを示唆しており、最適な解決策は、問題を最大 10^9 までの大きな座標値に依存しないものに減らす必要があります。 

素朴なアプローチでは、最小チップ位置と最大チップ位置の間で考えられるすべてのターゲット座標を選択し、そこにすべてのチップを移動するコストを計算します。 多くのターゲットはパリティにより同じように動作するため、問題は正確性ではなく冗長性です。 

すべてのチップがすでに同じ位置にある場合、微妙なエッジ ケースが発生します。 その場合、答えはゼロとなり、移動コストに基づく推論ではこれを維持する必要があります。 もう 1 つのエッジ ケースは、すべての位置が同じパリティを共有する場合 (たとえば、すべてが偶数である場合) です。 この場合、コストゼロの移動ですべてを揃えることができ、点間の距離が大きくても、答えはゼロになります。 コストと距離が等しいと誤って仮定する単純なアプローチは、ここでは失敗します。 

## アプローチ

 重要な観察は、2 ずつ移動するのは無料であるため、どのチップも何も支払わずに同じパリティですべての位置間を自由に移動できるということです。 これは、±1 の移動でパリティが反転し、1 コインのコストがかかるため、コインを支払うのはパリティを変更する必要があるときだけであることを意味します。 

これにより、問題は距離の最小化の問題ではなく、パリティのバランスの問題に変わります。 

選択された任意のターゲット座標 T について、位置 x のチップには 2 つの可能性があります。 x と T が同じパリティを持っている場合、±2 ステップを使用して、コインを支払わずに完全に移動できます。 パリティが異なる場合は、パリティを調整するために少なくとも 1 コインを支払う必要があります。その後、残りは再び無料の ±2 手で処理できます。 重要なのは、チップが ±1 の移動に対して支払いを行うと、そのパリティを効果的に T に合わせて、残りを無料で完了できるということです。 

したがって、固定ターゲット T のコストは、パリティが T と異なるチップの数にすぎません。 

T のパリティには、偶数または奇数という 2 つの意味のある選択肢しかありません。 T が偶数の場合、偶数位置のすべてのチップのコストは 0 になり、奇数位置のすべてのチップのコストは 1 コインになります。 T が奇数の場合、役割は逆になります。 したがって、答えは偶数位置の数と奇数位置の数の間の最小値になります。 

ブルートフォース手法では、考えられるすべてのターゲット座標を試し、すべてのチップのパリティ不一致を計算し、最小値を取得します。 パリティによってコストが完全に決定されるため、最大 10^9 の候補が 2 つのケースに減ります。

 | --- | --- | --- | --- |
 | 座標に対するブルートフォース | O(n * 範囲) | お(1) | 遅すぎる/不必要 |
 | パリティカウント | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 偶数のチップ位置と奇数のチップ位置がいくつあるかを数えます。 これは、選択したターゲット パリティに一致するチップの数を直接取得します。 
2. 偶数のターゲット位置を選択した場合に必要なコインの数を計算します。 その場合、パリティを反転するには、すべての奇数位置のチップがちょうど 1 コインを支払わなければならないため、コストは奇数位置の数になります。 
3. 奇数のターゲット位置を選択した場合に必要なコインの数を計算します。 対称的に、このコストは偶数ポジションの数に等しくなります。 
4. 2 つの値の最小値を返します。 これは、必要なパリティ フリップの数を最小限に抑えるターゲット パリティを選択することに対応します。 

### なぜ効果があるのか

 不変条件は、チップごとに最大 1 回の ±1 移動の後、すべてのチップをターゲット パリティ クラスに揃えることができ、その時点から残りのすべての移動を自由な ±2 ステップを使用して実行できることです。 ±2 移動はパリティを維持し、パリティ クラス内で無制限に移動できるため、距離はコストに寄与しなくなりました。 唯一削減不可能なコストは、チップが選択されたターゲットに対して正しいパリティ クラスで開始されるかどうかです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
x = list(map(int, input().split()))

even = 0
odd = 0

for v in x:
    if v % 2 == 0:
        even += 1
    else:
        odd += 1

print(min(even, odd))
```この実装ではパリティ数のみが追跡されます。 このループは数値を偶数バケットと奇数バケットに分割し、これらは 2 つの可能なターゲット パリティの選択肢に直接対応します。 最終的な答えは、バケット サイズを小さくすることです。 

パリティを超える絶対位置は無関係であるため、ソートや座標圧縮は必要ありません。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(sys.stdin.readline())
    x = list(map(int, sys.stdin.readline().split()))

    even = 0
    odd = 0
    for v in x:
        if v % 2 == 0:
            even += 1
        else:
            odd += 1

    return str(min(even, odd))

# provided sample
assert run("3\n1 2 3\n") == "1"

# all same parity (already optimal)
assert run("5\n2 4 6 8 10\n") == "0"

# all odd
assert run("4\n1 3 5 7\n") == "0"

# mixed balanced
assert run("4\n1 2 3 4\n") == "2"

# single element
assert run("1\n100\n") == "0"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | すべて偶数 | 0 | ゼロコスト調整のケース |
 | すべて奇妙 | 0 | 偶数の場合の対称 |
 | バランスミックス | 2 | 等価パリティ分割 |
 | シングルチップ | 0 | 最小限のエッジケース |

 ## 特殊なケース

 すべてのチップがすでに同じ位置にある場合、次のようになります。`5, 5, 5`、偶数と奇数の両方のカウントが 1 つのグループにまとめられ、答えはすぐにゼロになります。 パリティ カウントの 1 つがゼロであるため、アルゴリズムはこれを自然に処理します。 

すべてのチップが同じパリティを共有しているが、座標の差が大きい場合。`2, 100, 100000`の場合でも、距離に関係なくパリティ アライメントによってすべてのコストが削除されるため、解は依然として 0 を返します。 

偶数位置と奇数位置が交互になるなど、分布が混合されている場合、すべてのチップはパリティ バケットの 1 つに正確に寄与します。 アルゴリズムは依然として小さいバケットを正しく選択し、最小限のパリティ フリップを保証します。
