 ## 解決策
 ## 問題の理解

 都市は有向加重グラフです。 ドローンは特定のハブから出発し、指示されたルートに沿って飛行できますが、すべてのルートにはエネルギーコストがかかります。 一部のハブには荷物が含まれており、ドローンは開始ハブに戻る前に、正確に 5 つの異なる荷物を収集するのに十分な頻度でパッケージ ハブを訪問する必要があります。 荷物ハブを通過しても、ドローンが荷物を受け取ることを強制されるわけではないため、収集するかどうかは選択です。 

入力は、グラフ、開始ハブ、およびパッケージの場所のセットを記述します。 出力は、5 つのパッケージを収集しながら開始ハブで開始および終了するクローズド ウォークの最小エネルギー コストです。 そのようなウォークが存在しない場合、答えは次のようになります。`-1`。 

グラフには最大で次のものを含めることができます$10^5$ハブと$10^5$有向エッジ。 グラフ ノードの数が多すぎるため、考えられるすべてのパッケージの組み合わせにわたる通常の最短パス ソリューションは不可能です。 有用な制約は、パッケージ ハブが最大 35 個であるということです。これは、ソリューションの高価な部分がグラフ ノードの数ではなくパッケージの数に依存する可能性があることを意味します。 

エッジの重みは次のように大きくできます。$10^9$, そのため、答えは 32 ビット整数の制限を超える可能性があります。 Python の整数はこれを自動的に処理しますが、無限値は依然として十分な大きさを選択する必要があります。 もう 1 つの微妙な点は、ドローンがハブやエッジを再訪問する可能性があるため、単純な経路を想定できないことです。 5 つのパッケージ ハブを訪問するルートを 1 回だけチェックし、それらの間の最短パスを確認しないソリューションでは、有効な最適ルートを見逃してしまいます。 

たとえば、次のことを考えてみましょう。```
N = 3, M = 2
Start = 1
Edges:
1 -> 2 cost 5
2 -> 1 cost 5
Packages:
2
```正しい出力は次のとおりです。```
-1
```不注意なアプローチでは、1 つの荷物の訪問をカウントし、そのルートが有効であると考える可能性がありますが、ドローンには任意の数の荷物の訪問ではなく、正確に 5 つの収集された荷物が必要です。 

別のケース:```
N = 6, M = 6
Start = 1
Edges:
1 -> 2 cost 1
2 -> 1 cost 1
2 -> 3 cost 1
3 -> 2 cost 1
3 -> 4 cost 1
4 -> 3 cost 1
Packages:
2 3 4
```正しい出力は次のとおりです。```
-1
```異なるパッケージ ハブは 3 つだけです。 ルートはそれらを何度も再訪問できますが、再訪問しても新しい収集パッケージは作成されないため、必要な 5 つの異なるパッケージに到達できません。 

## アプローチ

 直接的なアプローチは、5 つのパッケージ ハブを訪問するあらゆる順序を試してみることです。 選択した注文ごとに、連続する場所間の最短パスを計算し、それらのコストを追加して最小値を取得します。 これは正しいです。有効なルートは、収集することを選択したパッケージ ハブ間の最短のセグメントに分解できるからです。 

問題は、パッケージ ハブが最大 35 個存在できることです。 可能な選択肢の数はおおよそ次のとおりです$35^5$これは、最短経路の計算を考慮する前でも約 5,200 万シーケンスになります。 すべてのシーケンスに対してグラフ アルゴリズムを繰り返し実行すると、作業は限界をはるかに超えてしまいます。 

重要な観察点は、グラフが巨大であるにもかかわらず、重要な位置の数が少ないということです。 重要な決定は、どのパッケージ ハブが収集されたかということだけです。 これらの重要な場所間の移動は、最短の経路距離に圧縮できます。 

まず、すべての重要な場所から他のすべての重要な場所までの最短距離を計算します。 重要な場所は、開始ハブとすべてのパッケージ ハブです。 それらは最大 36 個あるため、必要な最短パスの実行は 36 回だけです。 圧縮後、元のグラフは消え、小さな完全な有向グラフが得られます。 

次に、収集したパッケージのサブセットに対して動的プログラミングを使用します。 状態には、特定のパッケージ セットを収集した後、特定のパッケージ ハブに到達するための最小コストが格納されます。 パッケージは最大 35 個であるため、最大 5 個の収集されたパッケージを含む状態を保持するだけで済みます。 サブセットのサイズは小さいため、状態の数は管理可能です。 

すべての有効なルートには収集されたパッケージの順序があるため、ブルート フォースが機能します。 多くの部分ルートが同じ状況に到達することを覚えておらず、すべての順序を探索するため、失敗します。 サブセット DP は、これらの同等の状況をマージします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(K^5 \cdot \text{shortest path cost})$|$O(1)$| 遅すぎる |
 | 最適 |$O(K \cdot (M \log N) + \binom{K}{5} \cdot K)$|$O(\binom{K}{5} \cdot K)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 開始ハブとすべてのパッケージ ハブを含むリストを作成します。 パッケージ リストにも開始ハブが表示されている場合は、開始ハブを削除します。これは、開始時にパッケージを収集することは引き続きパッケージの場所としてカウントされますが、DP にはパッケージ インデックスの明確なマッピングが必要であるためです。 
2. あらゆる重要な場所からディクストラを実行します。 他の重要な場所までの距離のみを保存します。 これらの値は、不要な中間ハブを無視して、意味のあるポイント間を移動するための可能な限り安価なコストを表します。 
3. 存在するパッケージ ハブが 5 つ未満の場合は、すぐに戻ります`-1`。 収集する個別のパッケージが十分にありません。 
4. 状態に収集されたパッケージのビットマスクと現在のパッケージの位置が含まれる動的プログラミング テーブルを作成します。 保存される値は、マスク内のパッケージを正確に収集した後にそのパッケージ位置に到達するまでの最小コストです。 
5. 開始ハブから 1 つのパッケージ ハブに移動して、状態を初期化します。 このような移動のたびに、目的地で荷物が回収​​されます。 
6. まだ収集されていないパッケージ ハブに移動して、状態を繰り返し拡張します。 現在の位置と新しいパッケージの位置の間の最短パス距離を追加します。 
7. 州に収集されたパッケージがちょうど 5 つある場合は、現在のパッケージ ハブから開始ハブに戻るコストを追加します。 これらの完了したルートの中で最小値が答えです。 

これが機能する理由は、すべての移動セグメントを可能な限り最小のコストで置き換えた後、最適なルートは荷物を収集する順序だけで表現できるためです。 DP には、そのような部分注文ごとに可能な限り最良のコストが保存されます。 2 つのルートが同じパッケージを収集し、現在同じパッケージ ハブにある場合、より安価なルートのみがより良い最終答えにつながるため、1 つの値を維持しても何も失われません。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    start = int(input())

    graph = [[] for _ in range(n)]
    for _ in range(m):
        a, b, c = map(int, input().split())
        graph[a - 1].append((b - 1, c))

    k = int(input())
    packages = []
    if k:
        packages = list(map(int, input().split()))
        packages = [x - 1 for x in packages]

    if k < 5:
        print(-1)
        return

    important = [start - 1] + packages
    idx = {v: i for i, v in enumerate(important)}
    s = len(important)

    dist = [[10**30] * s for _ in range(s)]

    for i, src in enumerate(important):
        pq = [(0, src)]
        seen = [False] * n
        d = [10**30] * n
        d[src] = 0

        while pq:
            cur, v = heapq.heappop(pq)
            if seen[v]:
                continue
            seen[v] = True

            for to, w in graph[v]:
                nd = cur + w
                if nd < d[to]:
                    d[to] = nd
                    heapq.heappush(pq, (nd, to))

        for j, v in enumerate(important):
            dist[i][j] = d[v]

    pack_count = len(packages)
    dp = {}

    for i in range(pack_count):
        cost = dist[0][i + 1]
        if cost < 10**30:
            dp[(1 << i, i)] = cost

    ans = 10**30

    changed = True
    while changed:
        changed = False
        current = list(dp.items())
        for (mask, pos), value in current:
            if mask.bit_count() == 5:
                back = dist[pos + 1][0]
                if back + value < ans:
                    ans = back + value
                continue

            for nxt in range(pack_count):
                if mask & (1 << nxt):
                    continue
                new_mask = mask | (1 << nxt)
                move = dist[pos + 1][nxt + 1]
                if move >= 10**30:
                    continue
                nv = value + move
                key = (new_mask, nxt)
                if nv < dp.get(key, 10**30):
                    dp[key] = nv
                    changed = True

    print(-1 if ans == 10**30 else ans)

if __name__ == "__main__":
    solve()
```コードは最初に最短パス圧縮を実行します。 配列`important`重要なノードを保持し、`dist`それらのノード間の距離のみを保存します。 これにより、元のグラフでサブセット DP を実行することがなくなります。 

DP キーには、収集されたパッケージ マスクと現在のパッケージのインデックスが含まれています。 マスクはパッケージ ハブごとに 1 ビットを使用します。 必要なパッケージは 5 つだけであるため、到達可能なマスクの数は、考えられるすべてのサブセットよりもはるかに少なくなります。 

初期化では、最初のフライトが最初から処理されます。 すべての遷移では、まだ収集されていないパッケージを 1 つ選択し、事前に計算された最短距離を使用してそこに移動します。 状態が 5 ビットに達すると、リターントリップがチェックされます。 

よくある間違いは、開始ハブには最終パッケージ ハブから戻る最短パスも必要であることを忘れることです。 もう 1 つは、パッケージ インデックスとグラフ インデックスを混合することです。 DP はパッケージ インデックスを使用しますが、`dist`は圧縮された重要ノード インデックスを使用するため、`+1`オフセットは必要です。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(K \cdot (M \log N) + 2^K \cdot K)$| 重要なノードに対してのみダイクストラを実行し、圧縮された状態を処理します。 
| スペース |$O(K^2 + 2^K)$| 重要なノードと DP 状態の間の距離が保存されます。 

と$K \le 35$、サブセット部分は、最大 5 つのパッケージが収集された状態のみが実際に到達するという事実によって制限されます。 高価なグラフ作業は数十回のダイクストラ実行に限定されており、これは所定の制限内に収まります。

 ## 特殊なケース

 パッケージ ハブが 5 つ未満の場合、アルゴリズムは直ちに停止します。 入力の場合:```
3 2
1
1 2 5
2 1 5
1
2
```ドローンは荷物を永久に訪問できますが、5 つの異なる荷物を収集することはできません。 アルゴリズムは戻ります`-1`ディクストラを実行する前に。 

パッケージ ハブに到達できても、ルートが開始位置に戻れない場合、最後の遷移でそれが検出されます。 DP は 5 つのパッケージのパスを見つける可能性がありますが、開始点までの距離は無限のままであるため、ルートは拒否されます。 

複数のルートが同じ収集セットおよび現在のパッケージに到達する場合、DP は最も安価なルートのみを保持します。 将来のすべての移動コストは、以前の履歴ではなく、現在の場所と残りの荷物にのみ依存するため、より高価な部分ルートが後で改善されることはありません。 これは状態圧縮を可能にするプロパティです。
