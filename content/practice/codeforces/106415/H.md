 ## 解決策
 ## 問題の理解

 値が`0`モジュロ`m`。 元の文字列は、数字、3 つの二項演算子、および 2 つの括弧からなる 15 文字のアルファベットから均一に生成されます。 答えはカウントそのものではなく確率なので、有効な勝利文字列をカウントした後、次の値で割ります。`15^n`モジュロ`1e9+7`。 

困難は、妥当性が単なるローカルなプロパティではないという事実から生じます。 括弧が間違っている場合、演算子にオペランドがない場合、または算術値が 0 でない場合、文字列が失敗することがあります。 最大長はわずか 200 であるため、長さを超える動的プログラミング ソリューションを使用できますが、個々の文字列を解析することは避けなければなりません。 

長さ 200 は、多項式動的計画法には十分小さいです。 列挙は除外されます。`15^200`可能な文字列ですが、すべての長さとすべての剰余モジュロを含む状態が許可されます`m`。 以来`m`が最大 100 であるため、すべての剰余の式の数を保存することが可能です。 

主なエッジ ケースは、構文と値が相互作用する式です。 

例えば：```
1
```演算子はなく、有効な式ですが、答えは次の場合にのみ肯定的になります。`m = 1`、値が`1`。 

別のケース:```
(0)
```の長さは 3 であり、すべてのモジュラスの勝利式としてカウントされます。 数値と演算子のみを処理し、括弧を忘れたソリューションでは、このケースは失敗します。 

3 番目のケース:```
00
```は有効な数値であり、2 つの式ではありません。 ゼロと評価されるため、カウントする必要があります。 連続する数字を別個のトークンとして扱うパーサーは、それを拒否します。 

## アプローチ

 直接的なアプローチでは、考えられるすべての長さの文字列が生成されます。`n`、それが有効な式であるかどうかを確認し、評価して、勝者を数えます。 考えられるすべてのカードが検査されるため、これは正しいですが、文字列の数は`15^n`、非常に小さなものでも不可能になります`n`。 

有益な観察は、有効な式には文法構造があるということです。 実際の文字列は必要ありません。各長さの文字列の数が各可能な残基を生成するだけです。 

式の構文は当然 3 つのレベルに分かれます。 数値は一連の数字です。 因子は数値または括弧で囲まれた式のいずれかです。 項は、乗算によって結合された一連の因数です。 式は、加算または減算によって結合された一連の項です。 

これは算術の優先規則と一致するため、すべての有効な文字列はこれらのカテゴリのいずれかに正確に属します。 

動的プログラミングの状態は次のとおりです。`num[len][r]`: 長さの数値`len`価値のあるもの`r`。`fac[len][r]`: 長さの係数`len`価値のあるもの`r`。`term[len][r]`: 長さの乗算式`len`。`expr[len][r]`: 長さの完全な表現`len`。 

トランジションは、最初のオペレータで長いオブジェクトを分割します。 たとえば、項は 1 つの因子であることも、より小さな項であることもあります。`*`、そしてもう一つの要因。

 | ブルートフォース | O(15^n) | O(n) | 遅すぎる |
 | 動的プログラミング | O(n²m²) | O(nm) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての長さと剰余の数字列の数を計算します。 数字を追加すると値が変換されます`x`の中へ`(10*x+d) mod m`, したがって、すべての数値状態を段階的に構築できます。 
2. 要素を構築します。 因子は、括弧で囲まれた数値または式のいずれかです。 括弧は 2 文字を追加するため、長さの係数`i`長さの表現に由来する可能性があります`i-2`。 
3. 用語を作成します。 単一の要素から始めます。 期間を延長するには、を追加します`*`そしてもう一つの要因。 前の項はすでに乗算の左辺を表しているため、これは自動的に左結合に従います。 
4. 式を作成します。 1学期から始めましょう。 式を拡張するには、次のいずれかを追加します`+`または`-`そして別の用語。 減算により結果の剰余が変化するため、両方の演算子は個別に処理されます。 
5. 要求された長さごとに、`expr[n][0]`、剰余ゼロのみが勝ちカードであるためです。 文字列の総数で割ると、`15^n`、モジュラーインバースを使用します。 

機能する理由: すべての有効な式は、数値、因子、項、および式のレベルに固有に分解されます。 トランジションは文法規則に正確に従っているため、有効な文字列はすべて 1 回カウントされ、無効な文字列は作成されません。 保存された剰余は、対応する式のモジュロを評価することによって生成された値とまったく同じです。`m`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve_case(m, queries):
    nmax = max(queries)
    
    def conv(a, b, op):
        res = [0] * m
        for i, x in enumerate(a):
            if x:
                for j, y in enumerate(b):
                    if y:
                        if op == 0:
                            k = (i + j) % m
                        else:
                            k = (i * j) % m
                        res[k] = (res[k] + x * y) % MOD
        return res

    num = [[0] * m for _ in range(nmax + 1)]
    num[0][0] = 1
    for length in range(1, nmax + 1):
        for r in range(m):
            if num[length - 1][r]:
                val = num[length - 1][r]
                for d in range(10):
                    num[length][(r * 10 + d) % m] = (
                        num[length][(r * 10 + d) % m] + val
                    ) % MOD

    fac = [[0] * m for _ in range(nmax + 1)]
    term = [[0] * m for _ in range(nmax + 1)]
    expr = [[0] * m for _ in range(nmax + 1)]

    for length in range(1, nmax + 1):
        fac[length] = num[length].copy()
        if length >= 2:
            for r in range(m):
                fac[length][r] = (fac[length][r] + expr[length - 2][r]) % MOD

        term[length] = fac[length].copy()
        for left in range(1, length - 1):
            right = length - left - 1
            add = conv(term[left], fac[right], 1)
            for r in range(m):
                term[length][r] = (term[length][r] + add[r]) % MOD

        expr[length] = term[length].copy()
        for left in range(1, length - 1):
            right = length - left - 1
            plus = conv(expr[left], term[right], 0)
            minus = [0] * m
            for i, x in enumerate(expr[left]):
                if x:
                    for j, y in enumerate(term[right]):
                        if y:
                            minus[(i - j) % m] = (
                                minus[(i - j) % m] + x * y
                            ) % MOD
            for r in range(m):
                expr[length][r] = (
                    expr[length][r] + plus[r] + minus[r]
                ) % MOD

    ans = []
    for n in queries:
        denominator = pow(pow(15, n, MOD), MOD - 2, MOD)
        ans.append(str(expr[n][0] * denominator % MOD))
    return ans

def main():
    t, m = map(int, input().split())
    queries = list(map(int, input().split()))
    print("\n".join(solve_case(m, queries)))

if __name__ == "__main__":
    main()
```上位の文法レベルはすべて数字に依存するため、コードは最初に数字を構築します。 因子遷移では、`expr[length - 2]`、これが、長さが小さいものから大きいものまで処理される理由です。 

乗算層と加算層では、剰余の畳み込みを使用します。 乗算の場合、新しい剰余は 2 つの古い剰余の積です。 加算と減算の場合、剰余は和または差を法としたものになります。`m`。 

確率への最終変換は、カウントが終了した後にのみ行われます。 分母は決して割り切れない`1e9+7`なので、モジュラー反転は有効です。

## 特殊なケース

 単一文字入力長の場合`1`、有効な式は数字のみです。 数値 DP は、10 個の可能な 1 桁の式をすべて作成し、最後の剰余チェックでは、モジュロ 0 に等しいものだけが保持されます。`m`。 

括弧で囲まれたゼロの場合、次のようになります。`(0)`、因子遷移が追加されます`expr[length - 2]`因子テーブルに入力します。 これはまさに、括弧を算術演算子として扱わずに数えるために必要な遷移です。 

先行ゼロのある複数桁の数値の場合、次のようになります。`00`、数値 DP は、最初の桁を制限せずに桁を追加します。 結果の剰余は通常どおり計算されるため、先行ゼロのケースがすべて含まれます。
