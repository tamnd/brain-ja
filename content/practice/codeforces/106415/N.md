 ## 解決策
 ## 問題の理解

 テニス ボールのライン上の「評価」を表す整数の配列が与えられます。 1 回の移動で、単一のポジションを選択してその値を上書きできますが、新しい値は任意ではありません。 これは、その時点で配列全体から欠落している最小の非負の整数になるように強制されます。 1 つの位置を更新した後、配列が変更され、次の操作での最小の欠損値も変更される可能性があります。 

目的は、この操作を使用して最終的に配列のすべての要素を等しくできるかどうかを判断することです。 可能であれば、最小操作数とどのインデックスが順番に選択されるかを出力する必要もあります。 

重要な問題は、各ステップで書き込まれる値が、選択したインデックスではなく、配列の現在のグローバル状態に依存することです。 したがって、プロセスは適応的です。すべての操作は、配列の現在の「mex」によって駆動されます。 

入力サイズは最大 100,000 要素に達するため、mex を最初から繰り返し再計算したり、単純な方法で操作をシミュレートしたりするソリューションは遅すぎます。 mex の完全な再計算は線形であり、操作ごとに再計算を行うと、最悪の場合、二次的な動作が発生します。これは、一般的な 1 秒の制約では許容できません。 

素朴な直感を打ち破る微妙なエッジケースがいくつかあります。 

配列がすでに定数である場合、操作は必要ありません。 たとえば、入力`5 5 5`ゼロ操作を出力する必要があります。 

配列にギャップのない非負の整数の完全なプレフィックスが含まれている場合、次のようになります。`[0,1,2,3]`、メキシコは`4`。 1 回の手術の後、次のことを導入します。`4`しかし、これは素朴な戦略が依存する構造を破壊する可能性があります。 

配列にゼロがまったくない場合、mex は次のようになります。`0`したがって、最初の操作では常にどこかにゼロが挿入されます。これは、システムが以前は存在しなかった小さな値をすぐに導入し始めることを意味します。 

mex 操作を繰り返し適用することで、すべての値を何らかのターゲット値に「強制」できると考えるのは不注意な考えです。しかし、mex 制約は各ステップで出現できる値を厳しく制限するため、実現可能性は最終値が実際に安定化できるかどうかに依存します。 

## アプローチ

 ブルートフォース解釈では、プロセスを直接シミュレートします。 各ステップで、配列の mex を計算し、インデックスを選択して上書きし、すべての要素が等しくなるまで繰り返します。 mex を計算するには、配列全体をスキャンするか、周波数構造を維持する必要がありますが、周波数配列を使用する場合でも、操作ごとに 1 つの更新を実行し、要素ごとに最大で多くの操作を実行する可能性があります。 

最悪の場合、配列は O(n) 回程度の「修復」の成功を必要とする可能性があり、各修復は mex の再計算とカウントの維持に依存します。 すべての値をスキャンして mex を再計算する単純な実装では、O(n^2) になります。 周波数配列であっても、どの値を導入するかを注意深く制御しないと、不要な演算が実行されたり、収束に失敗したりする可能性があります。 

重要な観察は、mex 操作では常に最小の欠損数が導入されるということです。これは、値がすでに存在しない限り、プロセスは非常に構造化された順序 (0、次に 1、次に 2 など) でのみ値を生成することを意味します。 これにより、表示される値のセットに強い単調性が生じます。 

すべての要素を等しくするには、最終値が mex ダイナミクスの下で安定するものでなければなりません。 最終的な値が`x`の場合、最終的には配列に次のすべての値が含まれる必要があります。`0`に`x-1`（そうでなければメキシコはそうではありません`x`)、また以下の値はありません`x`安定化を試みた時点で欠落している可能性があります。 

これにより、問題は、配列構造が定数値に収束するまで欠落している整数を段階的に「埋める」ことができるかどうかを分析し、その後、目的の操作を実行して残りの不一致を排除できるかどうかの分析に変わります。

 ## アルゴリズムのチュートリアル

 1. 配列内の各値の頻度をカウントし、現在の mex に迅速に応答できる構造を維持します。 すべての操作が現在の mex に完全に依存するため、これが必要になります。 
2. すべての要素がすでに等しい場合は、いかなる変更も不要な外乱を導入するだけであるため、直ちにゼロ演算を出力します。 
3. 現在の配列の mex を繰り返し計算します。 この値を`m`。 mex は、配列に欠落している最小値を表します。 
4. もし`m`未満です`n`、現時点では目的の最終構造を保持していないインデックスで操作を実行し、それを次のように設定します。`m`。 演算値は固定されているため、ターゲットに対して「間違った」インデックスを選択するだけで十分です。 インデックスは値が書き込まれる場所のみを決定します。 
5. もし`m`等しい`n`、これは配列に現在次のすべての値が含まれていることを意味します。`0`に`n-1`。 この状態では、次のメックスは`n`、これは配列内にないため、演算を適用すると次のようになります。`n`。 これは、必要に応じて、より低い値の不一致を排除するのに役立つリセットとして機能します。 
6. 配列が均一になるまでこのプロセスを続けます。 正しい停止条件は、すべての要素が同じ値に一致する場合であり、頻度カウントによって確認できます。 
7. 操作中に選択した各インデックスを記録します。 これらのインデックスは、必要な出力シーケンスを形成します。 

実装の重要な詳細は、mex 更新が最初から再計算されないように頻度カウントを維持することです。 また、意図した最終的な安定値をすでに保持しているインデックスを可能な限り選択しないようにします。そうすることは収束に寄与しないからです。 

### なぜ効果があるのか

 mex 操作は、導入されるすべての新しい値が欠損値の中でグローバルに最小であることを保証するため、値は厳密に必要性の高い順に表示されます。 これにより、発振や任意の値の生成が防止されます。 候補の最終値を下回るすべての整数が存在すると、mex はその候補で安定し、さらなる演算はその構造を強化するだけです。 各操作では欠落している小さい整数が導入されるか、完全なプレフィックス構造が強化されるため、プロセスは最終的に、mex 制約に違反することなくすべての要素を単一の値に揃えることができる状態に到達する必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    if all(x == a[0] for x in a):
        print(0)
        return

    freq = {}
    for x in a:
        freq[x] = freq.get(x, 0) + 1

    mex = 0
    while mex in freq:
        mex += 1

    ops = []

    # We repeatedly push the system toward filling missing values
    # and then stabilizing the array.
    for _ in range(2 * n + 5):
        if len(freq) == 1:
            break

        mex = 0
        while mex in freq:
            mex += 1

        # choose any index whose value is not mex
        idx = -1
        for i in range(n):
            if a[i] != mex:
                idx = i
                break

        # apply operation
        old = a[idx]
        freq[old] -= 1
        if freq[old] == 0:
            del freq[old]

        a[idx] = mex
        freq[mex] = freq.get(mex, 0) + 1

        ops.append(idx + 1)

    print(len(ops))
    if ops:
        print(*ops)

if __name__ == "__main__":
    solve()
```このソリューションは明示的な周波数マップを維持するため、大きな整数の未使用の範囲をスキャンすることなく、常に現在の値のセットから mex が計算されます。 メイン ループは、現在の mex 値とまだ一致していない位置を繰り返し見つけて上書きします。 これにより、以前に欠落していた値が導入されるか、個別の値の数が減少することによって、各操作が確実に進行します。 

よくある落とし穴は、配列と周波数マップの両方を一貫して更新することを忘れることです。 周波数構造が矛盾すると、mex の計算が無意味になり、アルゴリズムが誤ってループする可能性があります。 

ループバウンド`2*n + 5`は、各操作が無秩序を軽減するか新しい値を導入することを反映する安全キャップであり、有効な構造では収束は線形ステップ内で発生します。

 ## 特殊なケース

 単一要素の配列は、導入する代替値がないため、すでに一貫性があります。 mex 操作では、同じインデックスを繰り返し上書きするだけで、メリットはありません。 

すべての要素が同一である配列は、最適な戦略の下では変更されずに残ります。これは、どのような操作でも mex によって決定される異なる値が導入され、均一性が直ちに損なわれるためです。 

最初の mex が常に 0 であるため、ゼロが欠落している配列の動作は異なります。そのため、最初の操作では新しいベースライン値が導入されます。 mex 計算はゼロの不在を即座に反映し、ゼロの導入を強制するため、アルゴリズムはこれを自然に処理します。
