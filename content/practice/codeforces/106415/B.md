 ## 解決策
 ## 問題の理解

 無向グラフとして表された接続された国があります。 各都市は頂点であり、各道路はエッジです。 道路はすでに機能している場合もあれば、壊れている場合もあります。 目標は、いくつかの変更を加えた後、作業道のみを使用して都市 1 から都市 n まで移動することです。 

壊れた道路を修復したり、作業道路を破壊したりすることは許可されています。 変更後、残すべき作業道路は、都市 1 から都市 n までの 1 つの最短経路に属する道路だけになります。 考えられるすべての有効な最終状態のうち、できるだけ少ない道路を変更し、それらの変更を出力する必要があります。 

重要な点は、最終的なパスは最小の修復コストではなく、エッジの数が最小の長さでなければならないということです。 すべての最短パスの中で、そのパス上の壊れたエッジはすべて修復する必要があるため、できるだけ多くの作業道路がすでに含まれているパスを優先します。 

グラフ サイズにより、線形または線形に近いグラフ アルゴリズムが可能になります。 最大約 10^5 の頂点とエッジがある場合、すべての可能なパスをチェックしたり、すべての最短パスの組み合わせを試したりすることは不可能です。 標準的な最短パス技術を指す O((n + m) log n) に近いものが必要です。 

いくつかの特殊なケースは見落とされがちです。 最短パスに壊れたエッジが含まれている場合は、別のより長いパスがすでに完全に機能している場合でも、そのエッジを修復する必要があります。 例えば：```
3 3
1 2 0
2 3 0
1 3 1
```最短パスの長さは 1 なので、1 から 3 への直接道路は残らなければなりません。 正しい出力では、必要に応じて、直接道路ではなく、他の 2 つの道路が壊れた道路に変更されます。 修理のみをカウントする貪欲なアプローチでは、都市 2 を通るより長いパスが誤って選択される可能性があります。 

もう 1 つのケースは、複数の最短パスが存在する場合です。 例えば：```
4 4
1 2 1
2 4 0
1 3 0
3 4 0
```両方のパスの長さは 2 です。変更が 1 つだけ必要なため、都市 2 を通過するパスが正しい選択となります。 最初に BFS を実行し、最初に検出された最短パスを選択する方法では、不必要な修復が行われる可能性があります。 

最後によくある間違いは、選択した最短経路以外の道路を忘れてしまうことです。 道路が現在機能しているが、選択した最短パスの一部ではない場合、その道路は破壊する必要があります。 例えば：```
2 1
1 2 1
```道路はすでに正しいので、変更する必要はありません。 より大きなグラフでは、すべての未使用の作業道路を明示的に処理する必要があります。 

## アプローチ

 直接的なアプローチは、最初に都市 1 と都市 n の間の最短パスをすべて見つけ、次にそれぞれを検査して、最も壊れたエッジが少ないパスを選択することです。 これは正しいです。すべての有効な回答は、作業道路に相当する最短パスを 1 つだけ残す必要があるからです。 ただし、最短パスの数は指数関数的に増加する可能性があるため、中程度のグラフであっても最短パスを列挙することは不可能です。 

問題を処理可能にする観察は、目的が最短経路探索自体に組み込まれることができるということです。 最初にエッジの数が最も少ないパスが必要であり、同じ数のエッジを持つパスの中で壊れた道路の数が最も少ないパスが必要です。 これは、すべてのエッジにコストのペアを割り当てることで表すことができます。 

作業道路には費用がかかります`(1, 0)`パスの長さが 1 つ増加しますが、修復は必要ないためです。 壊れた道路には費用がかかる`(1, 1)`なぜなら、長さが 1 つ長くなり、さらに 1 つの修理が必要になるからです。 

これらのペアの辞書編集的比較を使用してダイクストラを実行すると、アルゴリズムはまず距離を最小化し、2 番目の値のみをタイ ブレーカーとして使用します。 結果として得られるパスは、すべての最短パスの中で壊れた道路が最も少ない最短パスであることが保証されます。 

このパスを回復した後は、そのパス上のすべてのエッジが機能している必要があります。 折れたエッジは修復されています。 作業エッジは 1 つおきに破壊する必要があります。 選択されたパスによってすでに修復の数が最小限に抑えられており、その外側にある他のすべての作業エッジはすべての有効な最終グラフで消える必要があるため、変更されたエッジの数は最小限になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 最短パスの数の指数関数 | O(n + m) | 遅すぎる |
 | 最適 | O((n + m) log n) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての道路をその終点、元の状態、インデックスとともに保存しながらグラフを構築します。 出力には変化する正確な道路が必要なので、後でインデックスが必要になります。 
2. 各州が 2 つの値 (使用する道路の数と使用する壊れた道路の数) を保存する都市 1 からダイクストラを実行します。 優先キューは常に最小のペアを辞書順に処理します。 
3. エッジを緩める場合は、`(1, 0)`作業用道路と`(1, 1)`壊れた道路のために。 新しいペアが小さい場合は、宛先の現在の最適値を置き換えます。 
4. 都市がより適切なパスを受信するたびに、親エッジを保存します。 最終的な最短ペアで都市 n に到達すると、これらの親ポインターは選択された最適なパスを記述します。 
5. 親エッジを使用して都市 n から都市 1 まで後方に歩き、このパス上のすべてのエッジを動作する必要があるとしてマークします。 
6. すべての道路をスキャンします。 選択したパス上にある道路が壊れている場合は、修復操作を出力します。 道路がパス上になく、機能していた場合は、破壊操作を出力します。 

機能する理由: ダイクストラは、頂点が優先キューから削除されると、保存されるペアは可能な限り最小になるという不変条件を維持します。`(path length, number of broken edges)`ソースからのすべてのパスの中で。 ペア比較では最初に長さが考慮されるため、回復されたパスは常に最短になります。 2 番目のコンポーネントは同じ長さの中で最小化されているため、必要な修理も最小限で済みます。 パス以外の作業用道路はすべて削除する必要があるため、残りの変更はすべて強制的に行われます。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    graph = [[] for _ in range(n)]
    edges = []

    for i in range(m):
        a, b, c = map(int, input().split())
        a -= 1
        b -= 1
        edges.append((a, b, c))
        graph[a].append((b, c, i))
        graph[b].append((a, c, i))

    inf = (10**18, 10**18)
    dist = [inf] * n
    parent = [-1] * n

    dist[0] = (0, 0)
    pq = [(0, 0, 0)]

    while pq:
        d, bad, u = heapq.heappop(pq)
        if (d, bad) != dist[u]:
            continue

        for v, c, idx in graph[u]:
            nd = d + 1
            nbad = bad + (1 - c)

            if (nd, nbad) < dist[v]:
                dist[v] = (nd, nbad)
                parent[v] = idx
                heapq.heappush(pq, (nd, nbad, v))

    on_path = [False] * m
    cur = n - 1

    while cur != 0:
        e = parent[cur]
        on_path[e] = True
        a, b, c = edges[e]
        if a == cur:
            cur = b
        else:
            cur = a

    ans = []

    for i, (a, b, c) in enumerate(edges):
        if on_path[i]:
            if c == 0:
                ans.append((a + 1, b + 1, 1))
        else:
            if c == 1:
                ans.append((a + 1, b + 1, 0))

    out = [str(len(ans))]
    for a, b, c in ans:
        out.append(f"{a} {b} {c}")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```どちらの方向への移動も可能であるため、隣接リストにはすべての道路の両方向が保持されます。 保存された各エッジには元のインデックスも含まれるため、パスの再構築で正確な道路をマークできます。 

ダイクストラ状態には、1 つではなく 2 つの整数が含まれています。 1 つ目は走行したすべての道路をカウントし、2 つ目はその中で壊れた道路をカウントします。 Python の優先キューの順序付けでは、当然ながらタプルが辞書順に比較され、必要な最適化順序と一致します。 

親配列には、各都市に到達するために使用された最後のエッジが格納されます。 ダイクストラが終了した後、これらのエッジを都市 n から後方にたどることで、まさに 1 つの最適な最短パスがマークされます。 

最終スキャンでは、グラフの変更が行われます。 パスのエッジは壊れた場合にのみ修復が必要です。 パスの外側にある作業エッジはすべて破棄する必要があります。 その他の変更は必要ありません。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n + m) log n) | 各エッジはダイクストラ中に緩和され、ヒープ操作により対数係数が追加されます。 
| スペース | O(n + m) | グラフ、距離、親、エッジ情報が保存されます。 

各道路の処理回数が少ないため、この複雑さはグラフの制限に適合します。 このアルゴリズムは、指数関数的になる可能性がある唯一のアプローチである最短パスの列挙を回避します。 

## テストケース```python
import sys
import io

def run(inp: str) -> str:
    old = sys.stdin
    sys.stdin = io.StringIO(inp)
    data = sys.stdin.readline

    n, m = map(int, data().split())
    graph = [[] for _ in range(n)]
    edges = []

    for i in range(m):
        a, b, c = map(int, data().split())
        a -= 1
        b -= 1
        edges.append((a, b, c))
        graph[a].append((b, c, i))
        graph[b].append((a, c, i))

    import heapq
    dist = [(10**9, 10**9)] * n
    parent = [-1] * n
    dist[0] = (0, 0)
    pq = [(0, 0, 0)]

    while pq:
        d, bad, u = heapq.heappop(pq)
        if (d, bad) != dist[u]:
            continue
        for v, c, idx in graph[u]:
            nd = d + 1
            nb = bad + (1 - c)
            if (nd, nb) < dist[v]:
                dist[v] = (nd, nb)
                parent[v] = idx
                heapq.heappush(pq, (nd, nb, v))

    path = [False] * m
    cur = n - 1
    while cur:
        e = parent[cur]
        path[e] = True
        a, b, _ = edges[e]
        cur = b if cur == a else a

    ans = []
    for i, (a, b, c) in enumerate(edges):
        if path[i] and c == 0:
            ans.append((a + 1, b + 1, 1))
        elif not path[i] and c == 1:
            ans.append((a + 1, b + 1, 0))

    sys.stdin = old
    return "\n".join([str(len(ans))] + [f"{a} {b} {c}" for a, b, c in ans])

 ## 特殊なケース

 最初のエッジケースの場合:```
3 3
1 2 0
2 3 0
1 3 1
```ダイクストラは直接エッジに次のコストを割り当てます。`(1,0)`そして、より長いルートの費用は`(2,2)`。 最初の値が優先されるため、直接の道路がすぐに選択されます。 最終スキャンでは、すべての道路がすでに必要な状態と一致していることが確認されるため、出力は次のようになります。`0`。 

複数の最短パスの場合:```
4 4
1 2 1
2 4 0
1 3 0
3 4 0
```考えられる両方のパスには 2 つのエッジがあります。 都市 2 を通過するパスにはコストがかかります`(2,1)`、都市 3 を通るパスは受信します。`(2,2)`。 2 番目のコンポーネントはタイを切断するため、道路 2 から 4 のみが修復されます。 

撤去する必要がある屋外道路の場合:```
4 5
1 2 1
2 4 1
1 3 1
3 4 1
1 4 0
```壊れた直線道路を通る最短パスの長さは 1 です。 ディクストラはコストを考えてそれを選ぶ`(1,1)`なぜなら、2 つのエッジ ルートはすべて長くなるからです。 アルゴリズムは道路 1 から 4 を修復し、選択された最短パスの一部ではない 2 つの作業道路を破壊します。 これは、最終的なグラフには最短経路の道路のみが含まれるという要件に対応します。
