 ## 解決策
 ## 問題の理解

 私たちには、エージェントの循環システムが与えられており、インデックスが付けられます。`0`に`N-1`。 券売機は到着する国民を決定的なパターンで送り出します。`i`- 番目の市民は常にエージェントに送られます`(S + i·K) mod N`、 どこ`S`は開始オフセットであり、`K`はステップサイズです。 市民が到着し続けると、この式はエージェントのインデックスのウォークを生成し、すべてがモジュロで計算されるため、定期的に繰り返されます。`N`。 

このウォークでは、特定のエージェントのみが少なくとも 1 回訪問されます。 これらは「アクティブ」エージェントです。 重要な構造的事実は、訪問セットが循環群モジュロ上のまさに 1 つの算術数列であるということです。`N`、したがって、サイズが次の要素のみに依存する単一のサイクルを形成します。`gcd(K, N)`。 具体的には、個別の訪問エージェントの数は次のとおりです。`L = N / gcd(K, N)`。 

各エージェントにはコスト値があります`M[k]`。 エージェントがアクティブな場合、そのコストが合計に追加されます。 しかし、目的はこの合計を最小限に抑えることだけではありません。 非アクティブなままのエージェントの数に応じてペナルティも発生するため、最終的なスコアは、アクティブなエージェントの合計と、時間とともに増加するペナルティ期間を組み合わせたものになります。`N - L`。 

課題は選択することです`S`そして`K`この合計コストを最小限に抑えるためです。 

入力サイズは最大で`2 × 10^5`エージェント。 これにより、すべてのペアを試行するソリューションは即座に除外されます。`(S, K)`または、選択ごとにシーケンスを明示的にシミュレートします。これは、少なくとも 2 次またはそれ以上になるためです。 平`O(N^2)`はすでに大きすぎるため、候補ステップごとのサブセットの再計算を伴うものは実行不可能です。 

明らかではない問題は、シーケンスの定義は単純ですが、誘導された訪問ノードのセットが、連続するセグメントやプレフィックスではなく、算術構造 (gcd クラス) に依存することです。 単純な間違いは、訪問先エージェントが連続したブロックを形成しているか、またはのみに依存していると想定することです。`K`数値として表示されますが、これは false です。 

いくつかの危険な状況では、こうした落とし穴が露呈します。 もし`K = N`の場合、すべてのステップが同じインデックスに戻るため、アクティブになるエージェントは 1 つだけです。`S`。 もし`K = 1`、すべてのエージェントが訪問され、`L = N`。 もし`N = 1`、すべての選択は同じ単一のエージェントに集約され、両方のパラメータは無関係になりますが、不注意な実装では依然としてゼロで除算される可能性があります。`gcd`処理または想定`L ≥ 2`。 

## アプローチ

 ブルート フォースの解釈は簡単です。すべての有効なペアを試してください。`(S, K)`、シーケンスをシミュレートし、訪問したすべてのエージェントを収集し、それらの合計を計算し、ペナルティを計算し、最小値を取得します。 1 つのペアのシミュレーションには次の時間がかかります`O(N)`最悪の場合、循環する前に、`O(N^2)`ペア、につながる`O(N^3)`全体。 周期性に注目して冗長性を削除しても、依然として構成が多すぎて列挙できません。 

ターニングポイントは、次のことを認識することです`S`どのインデックスにアクセスするかには影響せず、サイクルの開始位置のシフトのみに影響します。 訪問セットは完全に依存します`K`を通して`gcd(K, N)`。 固定の場合`K`、訪問されたセットは正確に 1 剰余クラスのモジュロです`g = gcd(K, N)`。 これは、任意のサブセットを選択しているのではなく、配列を分割して選択していることを意味します。`g`互いに素なサイクル、各サイクルがインデックスを収集`i, i+g, i+2g, ...`。 

したがって、次の観点から考えるのではなく、`(S, K)`という観点から考えるようになります。`g`、の約数`N`。 可能なそれぞれについて`g`、配列がどのように分割されるかを決定できます。`g`独立したサイクル。 各サイクルは、1 つの開始剰余クラスのモジュロを選択することに対応します。`g`、そのクラス内のすべてのノードが一緒にアクセスされます。 以来`S`開始オフセットを選択します。固定オフセットに最適な選択です。`g`は単に最小コストの剰余クラスです。 

これにより、問題は次のすべての約数を反復処理することになります。`N`、モジュロクラスごとにインデックスをグループ化し、各クラスの合計を計算し、次を使用してコスト式を評価します。`L = N / g`。 

## アルゴリズムのチュートリアル

 1. すべての約数を計算する`g`の`N`。 各約数は、次の可能な値に対応します。`g = gcd(K, N)`、したがって訪問構造の可能性があります。 これにより、問題は選択の問題から変わります。`K`サイクル構造のサイズを選択します。 
2. 各約数について`g`、パーティションインデックス`0..N-1`の中へ`g`値のモジュロでグループ化する`g`。 各グループは、次の条件に応じて選択できる個別のサイクルを表します。`S`。 
3. 各グループについて、次の合計を計算します。`M[i]`みんなのために`i`そのグループの中で。 これは、この残基クラスがアクティブなサイクルになった場合の総コストを表します。 
4. このために`g`、最小の合計を持つグループを選択します。`S`開始点を移動して、任意の剰余クラス サイクルを選択できます。 
5. コンピューティング`L = N // g`。 これは、この gcd 構造でウォークが生成されるときのアクティブなエージェントの数です。 
6. 総コストを次のように計算します。`min_group_sum + floor(N/2) * (N - L + 1)`。 
7. 最高のものを追跡する`g`および最良の残基クラスインデックス。 有効な値に変換し直す`(S, K)`どれかを選択してペアリングする`K`そのような`gcd(K, N) = g`、 例えば`K = g`を選択してください`S`選択した剰余クラスのインデックスとして。 

### なぜ効果があるのか

 によって定義される散歩`(S, K)`繰り返し加算することによって決定されるサイクルにインデックスのグラフを分割します。`K mod N`。 サイクル構造の完全な特徴は次のとおりです。`gcd(K, N)`、サイクルの数とサイズの両方を修正します。 各サイクル構造内では、`S`構造自体ではなく、どのサイクルがアクティブであるかを選択するだけです。 したがって、最適化は終了しました`(S, K)`約数の選択に帰着する`g`次に、そのパーティション内で最適な残基クラスを選択します。 これらの gcd によって引き起こされるパーティションの外側で構成を行うことはできないため、除数を列挙することは、考えられるすべての動作を網羅することになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def divisors(n):
    ds = []
    i = 1
    while i * i <= n:
        if n % i == 0:
            ds.append(i)
            if i * i != n:
                ds.append(n // i)
        i += 1
    return ds

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    # prefix sums per residue class will be computed on the fly per divisor
    best_cost = float('inf')
    best_s = 0
    best_k = 1

    divs = divisors(n)

    half = n // 2

    for g in divs:
        # compute sums for each residue class mod g
        sums = [0] * g
        for i, val in enumerate(a):
            sums[i % g] += val

        min_sum = min(sums)
        best_class = sums.index(min_sum)

        L = n // g
        cost = min_sum + half * (n - L + 1)

        if cost < best_cost:
            best_cost = cost
            best_s = best_class
            best_k = g

    print(best_s, best_k, best_cost)

if __name__ == "__main__":
    solve()
```コードはまず、考えられるすべての gcd 構造を約数を介して列挙します。`N`。 構造ごとのサイズ`g`、剰余クラスのモジュロでグループ化された要素の合計を累積します。`g`。 そのグループ化は、ステップを実行することによって形成されるサイクルに正確に対応します。`K`それは持っています`gcd(K, N) = g`。 

の選択`best_class`の選択に対応します`S`、開始をシフトすることは、どの剰余クラスが最初に訪問されるサイクルであるかを選択するだけであるためです。 

実装の微妙な詳細は、すべての約数の剰余和を再計算すると、`O(N sqrt N)`許容可能な解決策`2 × 10^5`タイトなループを持つ Python で。 モジュロクラスごとにプレフィックス合計を事前計算することは可能ですが、ここでは不必要に複雑になります。 

## 実用的な例

 小さな配列を考えてみましょう`N = 6`、`M = [5, 2, 5, 1, 3, 5]`。 

約数を評価します`g = 1, 2, 3, 6`。 

のために`g = 2`、残基クラスは次のとおりです。 

| インデックス | 0 | 1 | 2 | 3 | 4 | 5 |
 | --- | --- | --- | --- | --- | --- | --- |
 | M | 5 | 2 | 5 | 1 | 3 | 5 |
 | モッド 2 グループ 0 | 5 + 5 + 3 = 13 | | | | | |
 | モッド 2 グループ 1 | 2 + 1 + 5 = 8 | | | | | |

 このために`g`、最高クラスの合計は`8`、与える`L = 6 / 2 = 3`。 

| g | 最高クラスの合計 | Ｌ | 費用 |
 | --- | --- | --- | --- |
 | 2 | 8 | 3 | 8 + 3*(6-3+1)=8+12=20 |

 これは、残基によるグループ化によって選択の問題が 1 つのサイクルの選択にどのように軽減されるかを示しています。 

別の例は`g = 3`:

 グループは次のとおりです。 

- mod 3: (0,3) → 5 + 1 = 6
 - mod 3: (1,4) → 2 + 3 = 5
 - mod 3: (2,5) → 5 + 5 = 10

 ベストは`5`、 と`L = 2`。 

| g | 最高クラスの合計 | Ｌ | 費用 |
 | --- | --- | --- | --- |
 | 3 | 5 | 2 | 5 + 3*(6-2+1)=5+15=20 |

 どちらの構成でもコストは同じであり、複数の最適な構造が共存できることがわかります。 

これらのトレースは、アルゴリズムが除数によって引き起こされるサイクル分割を一貫して評価し、それぞれの中で最良の剰余クラスを選択することを確認します。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    def divisors(n):
        ds = []
        i = 1
        while i * i <= n:
            if n % i == 0:
                ds.append(i)
                if i * i != n:
                    ds.append(n // i)
            i += 1
        return ds

    def solve():
        n = int(input())
        a = list(map(int, input().split()))

        best = float('inf')

    return str(solve()).strip()

 ## 特殊なケース

 いつ`N = 1`、約数は 1 つだけです`g = 1`。 剰余クラスのグループ化には単一の要素が含まれるため、アルゴリズムはそれを選択して計算します。`L = 1`。 ペナルティ期間は次のようになります。`floor(1/2) * (1 - 1 + 1) = 0`、出力は単純に`M[0]`。 モジュロインデックスは単一のバケットに正しく縮小されるため、グループ化ロジックは引き続き機能します。 

いつ`g = N`、各剰余クラスには要素が 1 つだけ含まれます。 このアルゴリズムは、すべての個々のエージェントをアクティブなシングルトン サイクルの可能性として評価します。 最低額は単純に`min(M)`、 そして`L = 1`。 これは、ウォークが決して動かず、1 つのエージェントだけがアクティブであるという極端なケースに対応します。 

いつすべて`M[i]`が等しい場合、すべての剰余クラスは同じ合計を持ちます。 アルゴリズムは、ペナルティ項と最大値を達成する除数のみに基づいて効果的に選択します。`L`最適になります。 これにより、残基選択によるタイブレークが重要ではないこと、および実装が最小クラスの一意性を想定していないことがチェックされます。 

もし`N`が素数である場合、約数は次のとおりです`1`そして`N`。 これにより、ソリューションは完全なサイクルと孤立したノードという 2 つの構造上の極端な点を正確に比較する必要があります。 除数列挙のバグはすべてここにすぐに表示されます。`g`値は存在せず、多くの場合、エッジ構造の欠落により不正確な答えが得られます。
