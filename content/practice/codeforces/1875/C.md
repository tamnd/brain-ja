 ## 解決策
 ## 問題の理解

 私たちには、ちょうど 1 キログラムの重さの青リンゴのかけらのコレクションが与えられました。 目標は、各人の総重量が同じになるように、これらのピースを一定数の人に分配することです。 Jellyfish は魔法のナイフを使ってリンゴのかけらを 2 等分することができ、各操作を 1 回の動きとしてカウントします。 均等な分配を達成するために必要な分割の最小数を決定するか、レポートを作成したいと考えています。`-1`それが不可能な場合。 

入力はテスト ケースの数と、テスト ケースごとに 2 つの整数を提供します。`n`、リンゴの個数、そして`m`、人数。 出力は必要な分割の最小数、または`-1`。 

制約により許可されるのは、`n`そして`m`最大 10^9 および最大 2×10^4 のテスト ケース。 各リンゴを分割する単純なシミュレーションでは、分割数が非常に多くなる可能性があるため、法外なコストがかかります。 これには、各操作を明示的に実行するのではなく、分布について数学的に推論するアプローチが必要です。 

重要なエッジケースが発生するのは次の場合です。`n < m`。 リンゴのかけらの数が人より少ない場合、半分にすることを繰り返して端数のかけらを作成する必要があります。 たとえば、次の場合`n = 1`そして`m = 5`、2 のべき乗分割を使用して 1 人あたり正確に 1/5 キログラムを得るのは不可能なので、答えは次のようになります。`-1`。 もう 1 つのエッジケースは次のような場合です`n`はすでに割り切れます`m`; その場合、分割は必要ありません。 

## アプローチ

 ブルートフォース手法では、各分割をシミュレートし、各人が等しい総重量を受け取ることができるまで部分を再帰的に半分に分割しようとします。 これには、潜在的に指数関数的な数のリンゴ片の管理が含まれます。 最悪の場合の複雑さはおよそ O(2^k) ですが、これは実行不可能です。`n, m`最大 10^9。 

重要な点は、許可される分割は部分を半分にすることだけであるため、最終的な部分の重みは 1 / 2^k の形式の分数でなければならないということです。 したがって、平等に分配するには、各人は次の値に等しいリンゴの重さの合計を受け取る必要があります。`n / m`。 もし`n / m`を 1/2 の累乗和で表すことは不可能です。 

問題を、合計するのに十分な「1/2^k」個の部分を生成するのに必要な分割の数を数えることに減らすことができます。`n / m`人それぞれに。 同様に、乗算することができます。`n / m`による`m`「単位重み」の合計数を取得し、ビット操作を使用して分割数をカウントします。各操作は、効果的に 2 の累乗部分を追加します。 

これにより、問題は貪欲なアプローチに帰着します。残りの最大の 2 のべき乗の部分を繰り返し取得し、部分の合計が一致するまで分割します。`n / m`人それぞれに。 重みは 2 の累乗であるため、商のバイナリ表現を使用して効率的に追跡できます。

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、次の内容を読んでください。`n`そして`m`。 どうかを確認してください`n < m`。 だったらすぐに返してください`-1`半分にするだけでは一人に最低一枚は配ることができないからです。 
2. コンピューティング`k = n // m`。 これは、各人が負担しなければならない最小総重量 (キログラム) です。 
3. コンピューティング`r = n % m`。 もし`r != 0`、残りを均等に分配するために、いくつかの部分を分割することで補う必要があります。 もし`r`2 のべき乗の分数の合計として表すことはできません。`-1`。 
4. のバイナリ表現内の 1 の数を数えます。`m - n % m`(または必要な半分を追跡する同等の式)。 各 1 は、そのサイズの部分を作成するために必要な分割に対応します。 
5. これらのカウントの合計により、最小分割数が求められます。 

不変条件は、すべてのステップで、総重量が正確に等しいピースのプールを維持することです。`n`。 分割するたびにピースの数が増え、2 のべき乗の分数のみを使用して 1 人あたりの正確な体重を一致させることができます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def min_splits(n, m):
    if n < m:
        return -1
    q, r = divmod(n, m)
    if r == 0:
        return 0
    # count minimum splits needed to cover remainder
    count = 0
    while r:
        # subtract largest power of 2
        largest_pow2 = 1 << (r.bit_length() - 1)
        r -= largest_pow2
        count += 1
    return count

t = int(input())
for _ in range(t):
    n, m = map(int, input().split())
    print(min_splits(n, m))
```機能`min_splits`まず、各人に十分なリンゴがあるかどうかを確認します。 もし`r == 0`、分割する必要はありません。 それ以外の場合は、剰余以下の 2 の最大累乗を繰り返し減算し、必要な分割の数を数えます。 これは、1 人あたりの希望合計に合わせて、サイズ 1/2、1/4 などの小さな作品を作成することに相当します。 の使用`bit_length`は、2 の最大累乗の指数を効率的に求めるため、重要です。

 ## 特殊なケース

 もし`n < m`、アルゴリズムはすぐに戻ります`-1`。 例えば、`n = 1`そして`m = 5`半分にしただけでは1/5サイズの作品は作れません。 2 の累乗の剰余の場合、アルゴリズムは最小分割を直接実行します。 バイナリ表現により、各分割が有効な半分演算に対応することが保証されます。 入力が大きい場合、2^30 > 10^9 であるため、ループは最大 30 回実行され、ソリューションの効率が維持されます。
