 ## 解決策
 ## 問題の理解

 小さな整数が与えられます$x$、別の整数を追加することができます$y$どこ$0 \le y \le 100$。 このずれた値から$n = x + y$、2 つの数値を計算します。$n^2$そして$n^3$。 次に、通常のように先頭のゼロを削除して 10 進表現を連結し、結果の数字列が 0 から 9 までの数字の完全な並べ替えであるかどうかを確認します。 

つまり、単一の文字列を形成した後、$n^2$すぐに続いて$n^3$、0 から 9 までのすべての数字は、繰り返しや省略がなく、連結全体で 1 回だけ出現する必要があります。 

入力サイズは小さいです:$x$最大でも 50 であり、$y$最大でも 100 なので、$n$これにより、漸近最適化の必要性が即座に排除されます。 すべての候補のフル スキャンでも最大 151 の可能性があり、各チェックには 2 つの整数累乗を計算し、その連結の桁をスキャンすることが含まれます。 

主な微妙な点はパフォーマンスではなく、桁処理の正確さです。 単純なアプローチは 2 つの点で簡単に失敗する可能性があります。 まず、連結前に概念的に先頭のゼロを削除することを忘れると、数値を固定幅の文字列として扱う実装で桁数を数え間違える可能性があります。 たとえば、治療する$n^2 = 16$そして$n^3 = 64$それは問題ありませんが、誰かが次のようなパディングでフォーマットした場合`"0016"`または`"064"`、桁数がおかしくなります。 Second, mixing integer concatenation logic instead of string conversion can lead to incorrect digit extraction, especially if one tries to build a number like$n^2 \cdot 10^k + n^3$の桁長を正しく計算せずに、$n^3$。 

正しい解決策では、連結を純粋に文字列操作として扱い、桁の頻度を正確に検証する必要があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 それぞれの可能性について$y$範囲内で$[0, 100]$、計算する$n = x + y$、次に計算します$n^2$そして$n^3$。 両方を文字列に変換して連結し、結果に正確に 10 桁の数字が含まれているかどうか、および 0 から 9 までの各数字が 1 回だけ出現するかどうかを確認します。 

これが機能するのは、検索スペースのサイズが一定であるためです。 最悪のケースは 101 回の反復であり、各反復で処理できる桁数はせいぜい数桁です ($150^3$は 400 万未満であるため、文字列の長さは最大 7 桁です)。 作業全体は簡単です。 

重要な観察は、制約によってすでにドメインが崩壊しているため、悪用できる隠れた構造がないということです。 桁の置換に関する代数的制約を導出しようとする試みは、直接列挙する場合と比較して不必要なオーバーヘッドになります。 この問題は、正確さが完全に桁数カウントを正しく実装するかどうかに依存するように設計されています。

 ## アルゴリズムのチュートリアル

 1. 整数を読み取る$x$。 これは調整前の開始値です。 
2. 反復する$y$0 から 100 まで。 各選択肢は、元の数値の候補シフトを表します。 
3. それぞれについて$y$、計算する$n = x + y$。 これは両方のべき乗に使用される基数です。 
4. コンピューティング$a = n^2$そして$b = n^3$。 これら 2 つの値は、最終的な数字のシーケンスを定義します。 
5. 両方を変換する$a$そして$b$文字列に変換し、次のように連結します$s = str(a) + str(b)$。 これは、先行ゼロの概念を削除した後、必要な数字シーケンスを直接モデル化します。 
6.長さが正しいかどうかを確認します$s$はちょうど 10 です。そうでない場合は、0 から 9 までの数字の順列を含めることができないため、この候補をすぐにスキップしてください。 
7. の各数字の出現を数えます。$s$。 0 から 9 までのすべての数字が 1 回だけ出現する場合は、戻り値を返します。$y$答えとして。 
8. の値がない場合は、$y$この問題は、有効な入力ではこの問題が発生しないことを保証しますが、完全を期すためにフォールバックの戻り値が含まれています。 

### なぜ効果があるのか

 各候補者$y$以下から導出される決定的な数字列を 1 つだけ生成します。$n^2$そして$n^3$。 このアルゴリズムは、許可されたドメイン全体のすべての可能性をチェックするため、有効なソリューションをスキップすることはできません。 桁頻度チェックでは、必要な条件が直接適用されます。文字列は、10 個の異なる桁の順列である場合にのみ受け入れられます。 ドメインが完全に網羅されており、すべてのチェックが正確であるため、正確さは有限集合に対する徹底的な検証から得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def is_valid(n: int) -> bool:
    a = str(n * n)
    b = str(n * n * n)
    s = a + b
    if len(s) != 10:
        return False
    cnt = [0] * 10
    for ch in s:
        cnt[ord(ch) - 48] += 1
    return all(c == 1 for c in cnt)

def main():
    x = int(input().strip())
    for y in range(0, 101):
        n = x + y
        if is_valid(n):
            print(y)
            return

if __name__ == "__main__":
    main()
```このソリューションでは、連結された数字列を構築し、その頻度分布をチェックするヘルパー関数に検証を分離します。 長さチェックは、全桁カウントを実行する前に、高速除去フィルターとして機能します。 

微妙な選択の 1 つは、算術数字の抽出を試みるのではなく、数値を文字列に変換することです。 文字列変換により、先頭のゼロが自動的に削除され、追加のロジックなしで問題ステートメントの要件に一致します。

 ## 特殊なケース

 エッジケースの 1 つは次のような場合です$n^2$または$n^3$の桁数が予想より少ないため、合計の連結長に影響を与える可能性があります。 たとえば、小さい$n$値は次のような短い文字列を生成します`"1"`そして`"8"`、結合された文字列は 10 文字をはるかに下回っているため、すぐに拒否する必要があります。 

もう 1 つの特殊なケースは、数字が繰り返されることです。 例えば、$n = 10$与える$n^2 = 100$、すでにゼロの繰り返しが含まれています。 チェックする前からでも$n^3$、桁頻度条件は失敗します。これは、長さだけに依存するのではなくカウントが必要な理由を示しています。 

最後に、接続長が大きくなるため、連結長が 10 を超える場合があります。$n$ただし、そのようなケースは長さチェックによって自動的に除外されるため、明示的に表現を切り詰めたり正規化したりする必要がなく、正確性が保証されます。
