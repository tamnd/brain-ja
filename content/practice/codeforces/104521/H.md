 ## 解決策
 ## 問題の理解

 2 人が小惑星の列の外側からスタートします。ジェシーは最初の小惑星の直前からスタートし、ジェリーは最後の小惑星の直後からスタートします。 各小惑星のサイズは固定されており、両方のプレイヤーは同じ小惑星に到達するまで、お互いに向かって一歩ずつ移動します。 

常に、ジェシーは現在の会議間隔の左側のどこかに立っていて、ジェリーは右側にいます。 ジェシーは、現在いる小惑星が少なくともジェリーの現在の小惑星と同じ大きさである場合にのみ満足します。 この制約は、最後だけでなく、すべての移動後にも保持される必要があります。 

正確に n+1 回の動きのシーケンスを構築するように求められます。 それぞれの動きは、ジェシーが右に 1 歩移動するか、ジェリーが左に 1 歩移動します。 すべての移動後の最終状態は、それらを同じ小惑星上に配置する必要があります。 すべての有効なシーケンスの中で、辞書編集的に最大のシーケンスが必要です。ここで、B は A よりも大きいと考えられるため、可能な限りジェリーを移動することを好みます。 

制約は十分小さいため、テスト ケースごとに O(n^2) が原理的に許容されますが、テスト全体の合計 n が最大 5000 であるため、テストごとに線形または線形に近い解が期待されます。 これは、O(n) または O(n log n) の実現可能性チェックによる貪欲な構築を強く示唆しています。 

いくつかの特殊なケースは過小評価されがちです。 

すべての小惑星のサイズが等しい場合、すべての移動は常に有効であるため、辞書編集的には常に B が優先されるため、最適な答えは単に最初にすべての B、次にすべての A になります。 

シーケンスの左側に非常に大きな小惑星があり、右側に非常に小さな小惑星がある場合、B の動きを遅らせる有効なグローバル シーケンスが存在するとしても、貪欲にジェリーをあまりにも積極的に左に押し出すと、ジェシーの幸福を早期に侵害する可能性があります。 

最後に、移動が局所的には有効であっても、後で行き詰まりにつながるケースがあります。 これが主な微妙な点です。現在の制約をチェックするだけではなく、最終ミーティング ポイントへの到達が可能であることを確認する必要もあります。 

## アプローチ

 ブルート フォース アプローチでは、これを状態 (L、R) にわたる最短経路問題として扱います。ここで、L はジェシーの位置、R はジェリーの位置です。 各状態から A または B を移動し、制約を適用して、長さ n+1 の有効なシーケンスを検索します。 各ステップで最大 2 つの選択肢に分岐するため、これにより、指数関数的な数の可能性が探索されます。 枝刈りを行っても、状態空間は最悪の概念形式で O(n^2) 状態と O(2^n) 遷移に成長します。 

重要な点は、このプロセスが非常に厳格であるということです。 各移動は常に L と R の間の距離をちょうど 1 だけ縮めます。 k が移動した後の残りの距離は固定されているため、後で「待機」したり位置を再配置したりする自由はありません。 これにより、グローバルな計画の複雑さのほとんどが解消されます。 

この剛性により、貪欲な構築が可能になります。各ステップで、システムを有効に保ち、完了を可能にする場合は、B を取得しようとします。 B が不可能な場合は、A に戻ります。B は辞書編集的に大きいため、これにより可能な限り最良の文字列が保証されます。 

残る唯一の困難は、移行の実現可能性を検証することです。 将来は残りの移動数によって完全に決定されるため、実現可能性は、移動後にエンドポイントの制約に違反しないようにすることになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 状態を超えたブルートフォース DFS | O(2^n) | O(n) | 遅すぎる |
 | 有効性チェックに貪欲 | テストあたり O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 2 つのポインター、L はジェシー、R はジェリーを追跡します。 最初は L = 0 および R = n + 1 で、位置 0 と n+1 は値 0 のダミー位置です。各 A は L を 1 ずつ増加させ、各 B は R を 1 ずつ減少させます。n+1 が移動した後は、L = R でなければなりません。 

各ステップで、B を追加するか A を追加するかを決定します。

1. L = 0 および R = n + 1 を初期化します。空の応答文字列を設定します。 
2. 移動するたびに R − L の距離が 1 ずつ減少するため、正確に n + 1 回繰り返します。 
3. B は辞書編集的に大きいため、最初に配置するようにしてください。 R が R − 1 になるときの動きをシミュレートします。 
4. ジェシーがまだジェリーより弱くないこと、つまり s[L] ≥ s[R − 1] を検証することによって、この動きが有効であるかどうかを確認します。 
5. チェックに合格した場合は、移動をコミットし、R を更新し、「B」を追加します。 
6. それ以外の場合は、A を移動し、L を更新し、「A」を追加します。 

この貪欲な順序が機能する理由は、有効な最終シーケンスは、n+1 から 0 までのギャップを減らす正確に n+1 の動きで構成されなければならないためです。すべての動きの構造上の重みが等しいため、唯一の制約は各ステップでの妥当性を維持することです。 B がステップで有効な場合、それを選択しても将来の実現可能性が低下することはありません。これは、ギャップを埋めるには残りの移動で十分であるという不変条件を維持しながら、R を局所的に変更するだけだからです。 

### なぜ効果があるのか

 状態は現在の間隔 [L, R] によって完全に記述され、重要な唯一の制約はエンドポイントの比較 s[L] ≥ s[R] です。 移動するたびに間隔が 1 つずつ縮小されるため、残りの移動数は正確に L と R の間の残りの距離になります。各ステップで A または B を選択する以外に将来の到達可能性の分岐はなく、どちらの操作でも、残りのステップで間隔が 1 つの点に折りたたまれるという特性が維持されます。 これにより、貪欲な選択が安全になります。B が現在有効である場合は常に、B 自体がすでに可能な限り最良のシンボルであり、A よりも将来の動きを制約しないため、B を延期しても辞書編集的により大きな将来を開くことはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = list(map(int, input().split()))
        
        # add dummy boundaries
        s = [0] + s + [0]
        
        L, R = 0, n + 1
        res = []
        
        for _ in range(n + 1):
            # try Jerry move first (B)
            if R - 1 >= L and s[L] >= s[R - 1]:
                R -= 1
                res.append('B')
            else:
                L += 1
                res.append('A')
        
        print("".join(res))

if __name__ == "__main__":
    solve()
```このソリューションは 2 つのエンドポイントを明示的に維持し、中間位置を追跡する必要はありません。 両端のダミー 0 により、特別な場合を除いて初期状態と最終状態を均一に処理できます。 

各ステップで、最初に B の動きを暫定的に確認することで、貪欲な決定が実装されます。 制約 s[L] ≥ s[R − 1] に違反する場合にのみ、A にフォールバックします。これにより、辞書編集上の最大性が保証されます。 

ループは正確に n+1 回実行され、必要な移動の数に一致し、各反復で O(1) の作業が実行されます。

 ## 特殊なケース

 n = 1 の最小入力は、両方の手が値に応じて制約を満たすか満たさない場合に、実装が単一の決定を正しく処理するかどうかを明らかにします。 L と R は 0 と 2 で始まり、両方の遷移が s[0] と s[1] に対して明示的にチェックされるため、アルゴリズムはこれを自然に処理します。 

すべての値が同じ場合、L ≤ R である限り、すべての状態は s[L] ≥ s[R] を満たすため、貪欲な人は不可能になるまで常に B を選択します。 このアルゴリズムは、辞書編集上の最大値と一致する、B の後に A が続く長い実行を生成します。 

値が厳密に左から右に増加している場合、ジェリーはすぐに左に移動するには強すぎるため、初期の A 移動を強制されます。 このアルゴリズムは、B がエンドポイント制約に違反するとすぐに A に正しくフォールバックし、無効な状態を防ぎながら可能な限り B の使用量を最大化します。
