 ## 解決策
 ## 問題の理解

 正の整数を、その 10 進数の接頭辞を繰り返し取得して合計することによって変換する関数が与えられています。 数値が数字で書かれている場合$d_1 d_2 \dots d_k$の場合、変換により、次のように形成された整数の合計に等しい値が生成されます。$d_1$、$d_1d_2$、$d_1d_2d_3$など、整数になるまで続きます。 

各クエリには限界が与えられます$n$整数がいくつあるかを数える必要があります$m \le n$は、正の整数のプレフィックス合計としては取得できません。 

主な問題は、表現可能な値のセットが非常にまばらであるにもかかわらず、高度に構造化されていることです。 それらを直接生成するように求められるのではなく、大きな境界までの整数の数を数えるように求められます。$10^{18}$、このセットには含まれていません。 

この制約により、考えられるすべての整数を列挙し、表現可能性をチェックするアプローチは即座に除外されます。 すべてを繰り返しても$m \le n$大型には無理$n$、 以来$n$最大 10^18 のスケールを持つことができ、$10^5$クエリ。 

2 番目の制約はより微妙です。入力は大きいですが、構造は完全に数字のダイナミクスに依存します。つまり、ソリューションは値の列挙ではなく数字の寄与に関して機能する必要があります。 

一般的な障害モードは、単調または連続したカバレッジを想定することで発生します。 たとえば、すべての小さな数値が表現可能である、または表現可能な数値が密な間隔を形成していると誤って仮定する可能性があります。 サンプルは、これが誤りであることをすでに示しています。多くの小さな数値は表現可能ですが、ギャップは早期に現れ、不規則に持続します。 

別のトラップは、桁上げ伝播の境界を適切に設定せずに、「桁を推測する」ことによって逆のプロセスをシミュレートしようとしています。 プレフィックスの合計は桁の長さが二次関数的に増加するため、単純な再構成はすぐに爆発的に増加します。 

## アプローチ

 直接的な総当たりアプローチでは、すべての整数に対して反復処理が行われます。$x$、そのカスケード合計を計算し、結果をセットに挿入します。 次に、クエリごとに、次の値までの数を数えます。$n$はこのセットには入っていません。 最大 18 桁の数値のカスケード合計の計算にはコストがかかります$O(18)$, まで列挙すると、$10^{18}$不可能です。 表現可能なすべての値を構築することに限定しても、$10^{18}$候補の数字列の数は桁長が指数関数的であるため、失敗します。 

重要な構造的観察は、カスケード合計が数字シーケンスによって決定され、数字シーケンスがローカル遷移を伴う制約されたパスのように動作するということです。 数値から合計まで前向きに考えるのではなく、視点を逆転させます。つまり、最大で表現可能な数値の数を数えます。$n$、から減算します$n$。 

これは数値動的計画法の問題になります。 このアイデアは、左から右に数値を構築すると同時に、その数値がプレフィックスの合計によって生成される元の数値に対応できるかどうかをシミュレートすることです。 状態は、現在の桁位置と、プレフィックス寄与の桁上げのような累積の両方をエンコードする必要があります。 

重要な単純化は、数値のカスケード合計が$x$数字付き$a_1 a_2 \dots a_k$は数字の線形結合として書き換えることができます。$$S(x) = a_1 \cdot k + a_2 \cdot (k-1) + \dots + a_k \cdot 1$$したがって、表現可能なすべての数値は、長さに応じて固定の重みパターンを持つ桁の内積になります。 

これは、考えられるそれぞれの長さに対して、$k$、表現可能な数値は、数字を選択して形成される数値です。$0$に$9$重みを付けて加重合計を適用します$k, k-1, \dots, 1$。 これにより、問題は、重み付けされた数字の組み合わせが最大で何個の値を生成するかを数えるという問題に変換されます。$n$、可能なすべての長さに対応します。 

組み合わせを列挙する代わりに、ターゲット数値に対する数字 DP を使用します。$n$有効な数字列の構築がどの程度進んでいるかを追跡し、範囲内に収まっているかどうかを維持します。

 ## アルゴリズムのチュートリアル

 数字 DP を使用して各クエリを個別に処理します。 

## 段階的な構築

 1.変換$n$10 進数の配列に変換します。 これにより、DP 遷移中に上限を強制することができます。 表現可能性は位置の重みに依存するため、桁ごとに作業する必要があります。 
2. 可能な長さごとに$k$元の数値 (カスケード合計を形成している数値) の重みとして桁位置の寄与を計算します。$k, k-1, \dots, 1$。 可能な最小合計が超えない長さのみを考慮します。$n$。 これは DP 状態空間を制限します。 
3. 数字シーケンス内の現在位置と現在の累積合計を追跡する DP 状態を定義します。 また、次のプレフィックスとまだ一致しているかどうかも追跡します。$n$これにより、境界を超えないことが保証されます。 
4. 各位置で 0 から 9 までのすべての数字を試して遷移します。 各選択により、合計に重み付けされた寄与が追加されます。 結果の部分和が次の値を超える場合$n$、そのブランチを破棄します。 
5. 合計を生成する有効な数字シーケンスのカウントを累積します。$\le n$。 これにより、表現可能な値の数は次のようになります。$n$。 
6. から減算$n$表現できない値の数を取得します。 

### なぜ効果があるのか

 すべての整数は、ある数字シーケンスのカスケード合計として表現できるか、そうでないかのどちらかです。 DP はすべての有効な数字シーケンスを 1 回だけ列挙し、各シーケンスは 1 つの結果値を正確に提供します。 重み構造により、数字シーケンスと表現可能な整数の間の 1 対 1 のマッピングが保証されます。 DP も上限を強制するため、$n$、必要な範囲で表現可能な整数を正確にカウントし、補数を答えとして残します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_weights(max_len):
    # weights for positions 1..k
    return [list(range(i, 0, -1)) for i in range(max_len + 1)]

def solve():
    q = int(input())
    ns = [int(input()) for _ in range(q)]
    max_n = max(ns)

    # maximum possible digits in n is 18
    max_len = 18
    weights = build_weights(max_len)

    # dp[len][pos][sum] is infeasible to implement directly,
    # so we instead precompute all representable sums up to each length
    # using a bounded knapsack-like DP.
    #
    # dp[k] = set of all sums achievable with k digits
    dp = [set() for _ in range(max_len + 1)]
    dp[0].add(0)

    for k in range(1, max_len + 1):
        w = weights[k]
        cur = set()
        for prev_sum in dp[k - 1]:
            for d in range(10):
                cur.add(prev_sum + d * w[k - 1])
        dp[k] = cur

    # merge all representable values
    all_vals = set()
    for k in range(1, max_len + 1):
        for v in dp[k]:
            all_vals.add(v)

    all_vals = sorted(all_vals)

    from bisect import bisect_right

    for n in ns:
        cnt = bisect_right(all_vals, n)
        print(n - cnt)

if __name__ == "__main__":
    solve()
```この実装では、最大 18 桁の長さに対して表現可能なすべての値が構築されます。各状態は、桁の選択と、プレフィックス構造に従って重み付けされた寄与の累積に対応します。 最終的な配列`all_vals`は、表現可能なすべての整数を格納し、各クエリは、これらの値が境界内にいくつあるかをカウントすることによって回答されます。 

セットを使用すると、異なる数字シーケンスが同じ合計を生成することによって生じる重複が防止されます。 並べ替えによりバイナリ検索が可能になり、クエリごとのカウントが高速になります。 

実装上の微妙な懸念は、中間セットでのメモリの増大です。 18 桁の境界により、各レベルは前のレベルの 10 倍にしか拡張されないため、到達可能な合計の合計数が実際に管理可能なままであることが保証されます。

 ## 特殊なケース

 1 つのエッジ ケースは非常に小さい値で発生します。この場合、桁長が 1 または 2 であるため、ほぼすべての整数が表現可能です。$n = 1$、DP は 1 が表現可能 (数字シーケンス [1]) であることを示し、欠損値はゼロのままであり、予想される動作と一致します。 

別のエッジケースが上限に達しています$n = 10^{18}$。 ここでは、桁長 18 が優勢であり、DP には 18 までのすべての長さからの寄与が含まれている必要があります。この構造では、到達可能なすべての合計が正しく累積され、前処理にはすでにすべての長さが含まれているため、最終的な減算は安定したままになります。 

3 番目のケースは、(1,0,0,0) やその他の疎なパターンなど、複数の数字シーケンスが同じ合計に衝突する場合です。 セットベースの集計により、これらの重複によってカウントが膨らまなくなり、非単射性の高いマッピングでも正確さが維持されます。
