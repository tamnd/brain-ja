 ## 解決策
 ## 問題の理解

 いくつかの材料を一定の割合で使用してスープを作りたいと考えています。 レシピに割合が記載されている場合は、`a1, a2, ..., an`、その場合、最終的なスープには次のものが含まれている必要があります。`a1 * x, a2 * x, ..., an * x`負でない実数値に対する各成分のリットル`x`。 

すでに各成分の量は限られており、`b1, b2, ..., bn`。 また、鍋の容量を超えることはできません`V`。 課題は、作ることができるスープの最大総量を決定することです。 

重要な点は、レシピの比率が厳密であるということです。 材料の量を独自に選択することはできません。 選択したら`x`、すべての材料の量が自動的に固定されます。 

制約はわずかです。 成分は最大 20 個あり、値はすべて小さな整数です。 これは、ほとんどすべての単純な計算が制限時間内に簡単に収まることを意味します。 課題はパフォーマンスではなく、比率、成分制限、総量の間の数学的関係を認識することです。 

よくある間違いは、材料ごとに貪欲に考えることです。 例えば：```
2 100
1 2
10 10
```不注意な解決策では、合計 20 リットルの材料が利用できるため、20 リットルのスープを調理できると言うかもしれません。 それは間違いです。 

比率には材料の量が必要です`(x, 2x)`。 2 番目の材料には 10 リットルしかないため、次のものが必要です。`2x <= 10`それで`x <= 5`。 

スープの総量は次のようになります。`x + 2x = 15`正しい答えは、`15`。 

もう 1 つの簡単なバグは、鍋の容量を忘れることです。 考慮する：```
1 5
1
100
```材料は100リットル分ありますが、鍋には5リットルしか入りません。 答えは`5`。 

浮動小数点の処理も重要です。 スケーリング係数`x`通常は分数です。 例えば：```
2 100
3 2
10 10
```最初の成分で許可されるのは、`x <= 10 / 3`、2番目の場合は許可されます`x <= 5`。 

制限要因は`10 / 3`, したがって、スープの量は次のようになります。`(3 + 2) * (10 / 3) = 50 / 3 = 16.666666...`整数除算を使用すると、結果が誤って切り捨てられます。 

## アプローチ

 強引な考え方では、多くの候補値を試してしまうでしょう。`x`。 スープの量は連続的に変化するため、実行可能な最大の二分探索を想像することができます。`x`。 各候補について、すべての材料要件が利用可能な供給量内に収まるかどうか、および総量が鍋の内側に収まるかどうかを検証します。 

これが機能するのは、実現可能性が単調であるためです。 ある値の場合、`x`が可能であれば、さらに小さな値も可能です。 

問題は、ここでは二分探索が不要であることです。 制約の構造によって、すでに正確な答えが直接得られます。 

あらゆる食材に`i`、レシピに必要なものは`ai * x`リットルですが、私たちが所有しているのは`bi`リットル。 それは次のようになります:```
ai * x <= bi
x <= bi / ai
```すべての成分には上限があります`x`。 最大の有効なスケーリング係数は、単にこれらすべての境界の最小値です。```
x = min(bi / ai)
```一度`x`が固定されている場合、スープの総量は次のようになります。```
(a1 + a2 + ... + an) * x
```最後に、パンの容量によってもう 1 つの制限が課せられます。 たとえ成分がより多くの量を許容しても、答えはそれを超えることはできません`V`。 

最終的な結果は次のようになります。```
min(V, sum(a) * min(bi / ai))
```これにより、問題全体が 1 つのリニア スキャンに減ります。

 | --- | --- | --- | --- |
 | 二分探索によるブルートフォース | O(n 対数精度) | お(1) | 承認済み |
 | 直接数学的解法 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む`n`そして`V`。 
2. 配列の読み取り`a`そして`b`。 
3. 可能な最大のスケーリング係数を計算します。`x`。 

すべての成分について、次のように計算します。```
bi / ai
```これは大きさを教えてくれます`x`その成分がなくなる前になくなる可能性があります。 
4. これらすべての値の最小値を取得します。 

最小の比率がボトルネック成分を決定します。 それより大きいもの`x`少なくとも 1 つの成分制約に違反する可能性があります。 
5. 合計レシピ係数を計算します。```
sum(a)
```レシピをスケールする場合`x`、スープの総量は次のようになります。```
sum(a) * x
```6. この体積をパンの容量と比較します。`V`。 

材料にスープの量が多くても、鍋にはそれ以上のスープを保持することはできません`V`。 
7. 小さい方の値を出力します。 

### なぜ効果があるのか

 実行可能なスープはすべて、レシピの正確な割合に従わなければなりません。 つまり、すべての材料の量は単一の倍率によって完全に決定されます。`x`。 

各成分は独立して大きさを制限します`x`多分。 レシピはすべての制約が同時に成立する場合にのみ実行可能であるため、有効範囲は`x`の最小値によって制限されます`bi / ai`。 

この最小値を選択すると、実現可能な最大のスケーリング係数が得られます。 合計レシピ係数を掛けると、スケーリング係数が最終的なスープの量に変換されます。 申請中`min(..., V)`パン容量の制約を強制します。 

すべての実行可能な解決策は、次の 1 つの値に正確に対応するため、`x`、可能な限り有効な最大値を選択します`x`、アルゴリズムは常に最適な答えを生成します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, V = map(int, input().split())
a = list(map(int, input().split()))
b = list(map(int, input().split()))

x = float('inf')

for ai, bi in zip(a, b):
    x = min(x, bi / ai)

answer = min(V, sum(a) * x)

print(answer)
```最初の部分は入力配列を読み取ります。 レシピの割合と利用可能な材料の量は材料ごとにペアになっているため、次のように繰り返します。`zip(a, b)`ロジックをシンプルかつ安全に保ちます。 

変数`x`これまでに発見された実現可能な最大のスケーリング係数を保存します。 無限大から始まるため、最初の成分が自動的に初期境界になります。 

すべての成分について計算します`bi / ai`。 この除算は浮動小数点のままでなければなりません。 整数の除算を使用すると、有効な小数点以下の回答が暗黙のうちに切り捨てられます。 

最小のスケーリング係数を見つけたら、それに次の値を掛けます。`sum(a)`。 これはレシピをスケーリングするため機能します。`x`すべての成分の量を乗算します`x`、したがって、合計ボリュームは同じ係数でスケールされます。 

最後に、パンの容量制限を次のように適用します。`min(V, ...)`。 

成分量がゼロの場合でも特別な処理は必要ありません。`b`なぜなら、数式はそれらを自然に処理するからです。 多少なら`bi = 0`、その成分が強制的に`x = 0`、つまりスープは調理できません。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    n, V = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    x = float('inf')

    for ai, bi in zip(a, b):
        x = min(x, bi / ai)

    print(min(V, sum(a) * x))

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue().strip()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out

# provided sample

# minimum-size input with zero ingredient
assert run("1 10\n1\n0\n") == "0.0", "zero soup possible"

assert run("1 5\n1\n100\n") == "5", "pan capacity limit"

) == "150.0", "all ratios identical"

## 特殊なケース

 1 つの材料が入手できない場合を考えてみましょう。```
2 100
1 1
10 0
```アルゴリズムは以下を計算します。```
10 / 1 = 10
0 / 1 = 0
```最小スケーリング係数は次のようになります。`0`。 スープの総量も`0`。 

レシピには両方の材料が必要なので、これは正解です。 材料が 1 つでも欠けていれば、レシピは不可能になります。 

ここで、鍋がボトルネックになっているケースを考えてみましょう。```
2 5
1 1
100 100
```成分の制約により、次のことが可能になります。```
x = 100
```レシピの合計係数は次のとおりです。```
1 + 1 = 2
```したがって、成分は許可します`200`スープのリットル。 次に、アルゴリズムが適用されます。```
min(5, 200)
```そして出力`5`。 

最後に、分数の答えを考えてみましょう。```
2 100
2 3
5 10
```境界は次のとおりです。```
5 / 2 = 2.5
10 / 3 = 3.333...
```最小倍率は次のとおりです。`2.5`。 

スープの量は次のようになります。```
(2 + 3) * 2.5 = 12.5
```このアルゴリズムは計算全体を通じて浮動小数点の精度を維持するため、整数以外の正しい答えが生成されます。
