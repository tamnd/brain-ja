 ## 解決策
 ## 問題の理解

 配列と、それがどの程度「変更が多い」かを示す具体的な尺度、つまり連続する要素間の絶対差の合計が与えられます。 この値は、配列を左から右に移動するときにどれだけ振動するかを捕捉します。 

タスクは値を変更することではなく、元の配列とまったく同じ合計振動を保持するサブシーケンスを選択することです。 同時に、このサブシーケンスをできるだけ短くしたいと考えています。 

したがって、中心的な問題は構造的なものです。動きの全量を維持するために実際に必要な要素はどれですか。また、単調な動きの直線セグメント上にあるため冗長なものはどれですか?

 制約は十分に大きいため、テスト ケースごとにすべての解が線形または線形に近いものでなければなりません。 すべてのテストの合計の長さは制限されているため、単一パスまたは並べ替えベースの方法が期待されます。 二次部分列 DP または総当たり除去戦略はすぐに失敗します。 

よくある失敗例は、積極的に削除しすぎた場合に起こります。 たとえば、次のような配列では、$[1, 2, 3, 2, 1]$、中央の山または谷を削除すると、全体のコントラストが変化します。 遷移を注意深く確認せずに局所的な極値のみを保持する単純なアプローチでは、セグメントが誤って崩壊し、コントラストが低下する可能性があります。 

もう 1 つの微妙な問題は、継続的な実行です。 のようなもので$[5, 5, 5, 5]$、正解は$1$ただし、すべての単調セグメントのエンドポイントを盲目的に保持する方法では、誤った出力が行われます。$2$またはそれ以上。 

## アプローチ

 強引なアイデアは、すべてのサブシーケンスを試し、そのコントラストを計算し、どれが元の配列のコントラストと一致するかを確認することです。 これは条件を直接強制するため概念的には機能しますが、サブシーケンスの数はおおよそ指数関数的に増加します。$2^n$、さえ不可能になります。$n = 30$。 

重要な洞察は、実際に何がコントラストに寄与しているのかを理解することです。 表現$|a_i - a_{i+1}|$方向の変化または平坦なセグメントと一致しない値の変化があった場合にのみ増加します。 単調増加の実行を見ると、すべての中間点は新しい「方向情報」を追加せず、単一の傾斜をより小さな同一の寄与に分割するだけです。 

これは、モノトーン セグメント内のほとんどの要素が冗長であることを示唆しています。 方向が変わる、または平等がプラトーを破るトランジションのみが必要です。 実際、コントラストを維持する最小のサブシーケンスは、等しい近傍を圧縮し、傾きの符号が変化する点または値の移動方向が変化する点のみを保持した後の、まさに「転換点」のシーケンスです。 

したがって、問題は、厳密な増加と減少が交互に起こるセグメントに配列を圧縮し、そのようなセグメントの数をカウントすることに帰着します。

 ## アルゴリズムのチュートリアル

 移動方向がどのように変化するかを追跡しながら配列を処理します。 

1. まず、連続する等しい値を圧縮します。 それらの差はゼロであるため、コントラストには寄与せず、方向には影響しません。 
2. 圧縮後の配列にサイズがある場合$1$、答えは$1$保存すべきコントラストがないからです。 
3. 次に、隣接する各ペアを増加または減少として扱い、連続する要素間の差の符号を計算します。 
4. この符号が配列に沿って何回変化するかを数えます。 各符号の変化は、完全なコントラストを維持するサブシーケンス内の必要なブレークポイントに対応します。 
5. 各セグメントが少なくとも 1 つの代表要素に寄与するため、サブシーケンスの最小サイズは符号変更の数より 1 つ大きくなります。 

これが機能する理由は、テレスコープによって全体の変動が維持されるため、絶対差の合計を変更せずに、厳密に単調なセグメント内の中間要素を削除できるためです。 

## なぜ機能するのか

 配列のコントラストは、最大の単調セグメントに沿って分解されます。 厳密に増加または減少するセグメント内では、すべての内部ポイントは、エンドポイントがすでに定義しているものを超える追加の変更には影響しません。 

コントラストを維持するサブシーケンスでは、変化の方向が切り替わるすべてのポイントを保存する必要があります。そのようなポイントを削除すると、2 つの反対の傾斜が 1 つの直接ジャンプにマージされ、全体の変動が厳密に減少または変更されるためです。 

したがって、最小サブシーケンスは、配列の区分的単調分解における極値点のシーケンスに正確に対応します。 これらの極値点の数は、正確に 1 に重複を削除した後の勾配符号の変化の数を加えたものになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        # remove consecutive duplicates
        b = []
        for x in a:
            if not b or b[-1] != x:
                b.append(x)

        if len(b) == 1:
            print(1)
            continue

        # compute sign changes
        changes = 0
        prev = 0

        for i in range(1, len(b)):
            if b[i] > b[i - 1]:
                cur = 1
            else:
                cur = -1

            if cur != prev and prev != 0:
                changes += 1

            prev = cur

        print(changes + 1)

if __name__ == "__main__":
    solve()
```等しい連続値はコントラストに影響を与えないため、解決策は重複を圧縮することから始まります。 次に、各ステップが増加しているか減少しているかを追跡しながら、縮小された配列をスキャンします。 この方向が反転するたびに、サブシーケンスに新しい必須要素が必要になります。 

主な微妙な点は、前の方向を正しく初期化することです。 ニュートラルな状態から開始し、方向性が確立されて初めて変化のカウントを開始します。 もう 1 つの微妙な点は、等価性がすでに削除されているため、すべての隣接するペアが厳密に比較され、方向が未定義の場合が回避されることです。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(n)$| 各要素は圧縮のために 1 回処理され、方向スキャンのために 1 回処理されます。 
| スペース |$O(1)$番外編 | 出力配列は暗黙的に再利用され、圧縮されたリストのみが保存されます。 

線形の複雑さが必要なのは、テスト ケース全体の入力サイズの合計が大きく、並べ替えやネストされたスキャンが制限を超えるためです。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        b = []
        for x in a:
            if not b or b[-1] != x:
                b.append(x)

        if len(b) == 1:
            out.append("1")
            continue

        changes = 0
        prev = 0

        for i in range(1, len(b)):
            cur = 1 if b[i] > b[i-1] else -1
            if prev != 0 and cur != prev:
                changes += 1
            prev = cur

        out.append(str(changes + 1))

    return "\n".join(out)

 ## 特殊なケース

 次のような完全に定数の配列$[7, 7, 7, 7]$単一の値に圧縮します。 アルゴリズムはすぐに戻ります$1$これは、トランジションが存在せず、保存する必要のあるコントラスト構造がないことを反映しています。 

次のような厳密に単調な配列$[1, 2, 3, 4, 5]$方向は 1 つだけであり、変更はありません。 答えは次のようになります$2$、各方向セグメントに対して 1 つのエンドポイントで十分であるためです。 

次のような交互配列$[1, 3, 1, 3, 1]$圧縮後に複数の符号反転が生成され、各反転が必要なブレークポイントとしてキャプチャされ、コントラスト構造を崩壊させることなくサブシーケンスがすべての立ち上がりと立ち下がりを確実に保持します。
