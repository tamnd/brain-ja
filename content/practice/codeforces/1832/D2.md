 ## 解決策
 ## 問題の理解

 最初は赤で色付けされた整数の配列が与えられます。 各操作で、単一の要素を選択します。 赤の場合は操作数だけ増やして青に切り替えます。 青色の場合は、操作番号だけ減少させて赤色に戻します。 各操作には 1 から始まる順次インデックスがあります。クエリの場合`k`、正確に後の最小要素の可能な最大値が必要です。`k`操作。 各クエリは独立しています。 配列はクエリの前にリセットされます。 

この課題は 2 つの主な制約から生じます。 配列には最大 200,000 個の要素を含めることができ、演算数は最大 10 億回です。 色を追跡し、配列を要素ごとに更新する単純なシミュレーションは、10 億回の操作を繰り返すことは制限時間をはるかに超えるため、直ちに実行できなくなります。 

明らかではないエッジ ケースには、最小要素が先頭または末尾にある配列、すべての要素が等しい配列、および次のようなクエリが含まれます。`k`よりも小さいです`n`または非常に大きい。 たとえば、次の場合`a = [5,5]`そして`k = 1`の場合、最適な方法は、小さい方の要素 (いずれか 1 つ) に 1 を加算することです。 操作が均等に分散される必要があると仮定する不用意なアプローチは、達成可能な最小値の最大値を誤って削減する可能性があります。 もう一つの微妙なケースは次のような場合です。`k`要素数を超えています。 最小値を最大化するには、複数の要素にわたって操作を最適に分散することを考慮する必要があります。 

## アプローチ

 ブルートフォース手法では、すべての操作を順番にシミュレートし、各要素の色と値を追跡します。 クエリごとに`k`、操作 1 から`k`、各ステップで、最終的な最小値を下げるリスクを最小限に抑える要素を選択します。 原理的には正しいですが、このアプローチは次のことを行います。`O(k)`クエリごとに更新するため、次の場合には法外な更新になります。`k`10^9 にすることもできます。 

重要な洞察は、各要素を複数回実行でき、増分の合計が予測可能であるということです。 想像してみると`x`演算が 1 つの要素に分散されると、最終的な効果は算術シーケンスの加算と減算の組み合わせになります。 最小値を最大化するための最適な戦略は、最小要素を増やすとグローバル最小値が上昇するため、最初に最小要素間で演算を分散することです。 これにより、問題は二分探索に帰着します: 候補の最小値を求める`m`、すべての要素が少なくとも到達するように操作を分散できますか?`m`? 「はい」の場合は、より高い最小値を試すことができます。 「いいえ」の場合は、目標を削減します。 各候補の最小値に対して必要な演算を計算するのは次のとおりです。`O(n)`、したがって、潜在的な最小値に対する二分探索は次のようになります`O(n log(max_a + k))`、これは制約に対して実現可能です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(q * k) | O(n) | 遅すぎる |
 | 最適 | O(q * n * log(max_a + k)) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. **配列を並べ替えます**。 これにより、最小の要素を迅速に特定し、最小値を効率的に引き上げることを検討できるようになります。 
2. **実現可能性チェックを定義**します。 最低限の目標を達成するには`m`、各要素に必要な操作の数を計算します。`a[i]`少なくとも到達するために`m`。 各要素について、それが以下の場合`m`を超えて増やすために必要な最小操作数を計算します。`m`、連続操作増分の合計の公式を使用します。 これは解決することから生まれます`sum_{j=1}^{x} j >= m - a[i]`、これは最小のものを見つけることになります。`x`そのような`x*(x+1)/2 >= m - a[i]`。 これは、要素に操作を適用すると色が交互になりますが、操作インデックスの段階で最終的な効果が増加するためです。 
3. **すべての要素にわたって必要な演算を合計します**。 合計が以下の場合`k`、目標の最小値`m`達成可能です。 
4. **答えを二分探索します**。 初期化する`lo`配列の現在の最小値として、`hi`として`max(a) + k`。 その間`lo < hi`、中点を確認します。 可能なら移動する`lo`上; それ以外の場合は移動する`hi`下。 最後に、`lo`は達成可能な最小値です。 
5. 同じ手順を使用して **各クエリに個別に回答します**。 

機能する理由: 最小要素への操作の貪欲な分散により、要素が人為的に取り残されることがなくなります。 二分探索が機能するのは、最小限の条件が満たされている場合です。`m`は達成可能ですが、より小さな値はすべて簡単に達成可能です。 整数の和の式により、大規模な場合でも、要素ごとの最小演算を正しく計算できるようになります。`k`。 

## Python ソリューション```python
import sys, math
input = sys.stdin.readline

def min_ops_needed(a, target):
    ops = 0
    for val in a:
        if val >= target:
            continue
        diff = target - val
        # solve x*(x+1)/2 >= diff for x
        x = math.ceil((-1 + math.sqrt(1 + 8*diff)) / 2)
        ops += x
    return ops

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))
    queries = list(map(int, input().split()))
    a.sort()
    
    for k in queries:
        lo = min(a)
        hi = max(a) + k + 1
        while lo < hi:
            mid = (lo + hi) // 2
            if min_ops_needed(a, mid) <= k:
                lo = mid + 1
            else:
                hi = mid
        print(lo - 1, end=' ')
    print()

if __name__ == "__main__":
    solve()
```の`min_ops_needed`関数は、二次公式を使用して、候補の最小値に到達するために各要素に必要な演算数を計算します。 仕分け`a`これにより、最小の要素を最初に効率的に推論できるようになります。 二分探索では、すべての可能な値を反復処理することなく、実行可能な最小値を絞り込みます。`10^9 + 10^9`。
