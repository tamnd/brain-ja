 ## 解決策
 ## 問題の理解

 この問題の各入り口は、長い時間間隔をかけて到着するゾンビの流れのように動作します。 範囲内の 1 分ごとに$[0, x)$、ちょうど 1 人のゾンビが各入り口を通過しようとします。 それらのゾンビの一部は、その入り口に割り当てられた固定の手動防御者によって阻止されます。この防御者は個人的な間隔でのみ活動します。$[l_i, r_i)$。 追加の防御を追加しない限り、その間隔の外側にあるものはすべて保護されないままになります。 

これらの入り口ごとの手動防御に加えて、ジェネレーターと呼ばれる限られた数のグローバルデバイスが与えられます。 各ジェネレータは、割り当てられているすべての入口を保護しますが、それは 1 つの連続した時間ウィンドウの間のみです。$m$。 範囲内であれば、各ジェネレーターの開始時間を個別に選択できます。$[0, x)$。 すべての入口は 1 つのジェネレーターにのみ割り当てる必要がありますが、ジェネレーターは一度に多くの入口をカバーすることができます。 

その時点で手動ディフェンダーがアクティブであるか、割り当てられたジェネレーターがアクティブである場合、ゾンビは停止します。 目的は、侵入するゾンビの総数が最大になるように、発電機に入り口を割り当て、発電機の起動時間を選択することです。つまり、すべての入り口で合計ブロックされる時間を最小限に抑えたいと考えています。 

制約$n, k \le 2000$そして$x$まで$10^9$時間の経過に伴うシミュレーションを直ちに除外します。 解決策は、タイムラインの長さではなく、間隔の構造のみに依存する必要があります。 

手動インターバルが重なり合ったり、ユニオン効果後に空のようになったりする場合、微妙なエッジケースが発生します。 もう 1 つは、手動間隔が大きく異なる多数の入口が発電機に割り当てられており、最適な発電機の配置が単一の間隔ではなく加重交差問題に依存する場合です。 

単純な間違いは、発電機を配置するときに各入り口を独立して扱うことです。 これは失敗します。なぜなら、ジェネレータの配置は、それに割り当てられたすべての入口に同時に影響し、最適な配置は、結合されたブロック時間のセットとの重複を最大化することに依存するからです。 

## アプローチ

 直接的な総当たり解釈では、それぞれの$n$いずれかの入口$k$ジェネレータを起動し、可能なジェネレータの起動時間をすべて試します。 割り当てを修正したとしても、すべての可能な開始位置をスキャンし、割り当てられた間隔の和集合との重複をカウントすることで、各ジェネレーターの最適な間隔を計算できます。 それはすでにコストがかかります$O(x)$発電機ごとに、これは不可能です$x$までです$10^9$。 開始時刻の候補をイベントの境界まで圧縮したとしても、すべての割り当てを試すのは困難です。$k^n$、すぐに爆発します。 

重要な観察は、入り口がジェネレーターにグループ化されると、重要なのは時間の経過に伴うそのグループの総合的な「危険プロファイル」だけになるということです。 各入口は、バイナリ カバレッジ関数に貢献します。$[0, x)$: 手動ディフェンダーがアクティブな場合は 1、それ以外の場合は 0 です。 固定グループの場合、長さを選択します。$m$可能な限り多くのゼロカバレッジ位置と重なるウィンドウ。 同様に、スライディング ウィンドウ内に手動で保護されていない時間を最大化したいと考えています。 

これにより、各グループの評価が、区間の和集合から導出された区分的定数配列のスライディング ウィンドウの最大値に削減されます。 残りの問題は次のとおりです。パーティションの入り口は最大でも$k$各グループのゲインは、集計された間隔構造から計算できます。 

この構造は、ソートされた間隔にわたる古典的なパーティション DP になり、マージされたカバレッジを維持し、最良のウィンドウ スコアを段階的に計算します。 最終的なソリューションでは、ソートされた入口のプレフィックスと事前計算されたペアごとのグループ コストに対する動的プログラミングが使用され、各コストはイベント エンドポイントに対する 2 ポインター スイープを使用して計算されます。 二分探索は最終的な答えに直接使用されませんが、内部コストの計算はウィンドウをスライドさせるときのオーバーラップの単調性に依存します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(k^n \cdot x)$|$O(n)$| 遅すぎる |
 | 最適 |$O(n^2)$に$O(n^2 \log n)$実装に応じて |$O(n^2)$または$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各入口を手動でカバーされるセグメントに変換し、すべてを「保護されていない分 = すべての分からカバーされる分を差し引いたもの」として解釈します。 私たちは、発電機設置後に生き残る、カバーされていない時間を最大化することに重点を置いています。 
2. 1 つのジェネレーターに割り当てられた入口の固定サブセットについては、すべての手動間隔をセグメントの和集合にマージします。 この結合は、ジェネレータがいつ冗長になるかを完全に記述します。 
3. ヘルパー関数を定義する`gain(group)`長さを配置することで保護できる保護されていない最大分数として、$m$どこにでもある窓$[0, x)$。 これは、結合の覆われていない領域に可能な限り重なるウィンドウを見つけることと同じです。 共用体構造を使用すると、ソートされたエンドポイントに対して線形時間でこれを計算できます。 
4. 事前計算`gain(i, j)`並べ替え後のすべての連続する範囲の入口に対して。 これが機能するのは、最適なグループ化がソートされた構造を尊重するためです。つまり、カバレッジの単調な構造により、離れた間隔を混合してもウィンドウの重なりが改善されることはありません。 
5. DP を構築します。`dp[t][i]`最初のを使用した最良の結果を表します`i`入り口とまさに`t`発電機。 前の位置での分割による遷移`p`、入口をグループ化するコストを追加`(p+1 ... i)`1つの発電機にまとめます。 
6. 遷移は次のようになります。`dp[t][i] = max(dp[t][i], dp[t-1][p] + gain(p+1, i))`。 これは、各ジェネレーターが、割り当てられたセットに対して達成可能な最良のブロック カバレッジを独立して提供していることを捉えています。 
7. 答えは次のとおりです。`dp[k][n]`すべての入り口を割り当てる必要があるためです。 

正確かどうかは、グループが固定されると、その最適なジェネレータの配置が他のグループから独立するという事実に依存するため、問題は追加のセグメント コストにきれいに分解されます。 

### なぜ効果があるのか

 重要な不変条件は、入口のどのパーティションにおいても、ブロックされた分数の合計が各ジェネレーター グループからの独立した寄与の合計と等しく、各寄与がそのグループ内の手動間隔の結合のみに依存するということです。 ジェネレーターは、入口の素の割り当てを介する場合を除いて時間内に相互作用せず、各ジェネレーターの最適な配置が独立して選択されるため、グローバル最適値は、各セグメントが個別に評価される入口の最適な分割に対応する必要があります。 この分離性により、隣接するグループに対する DP が正当化されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def merge(intervals):
    if not intervals:
        return []
    intervals.sort()
    res = []
    s, e = intervals[0]
    for l, r in intervals[1:]:
        if l <= e:
            e = max(e, r)
        else:
            res.append((s, e))
            s, e = l, r
    res.append((s, e))
    return res

def uncovered_length(intervals, x):
    total = 0
    for l, r in intervals:
        total += r - l
    return x - total

def gain_for_group(group, m, x):
    # group: list of (l,r)
    merged = merge(group)
    
    # build "bad time" coverage complement via events
    # we compute how many uncovered minutes a window of length m can capture
    events = []
    covered = 0
    for l, r in merged:
        covered += r - l
        events.append((l, 1))
        events.append((r, -1))
    events.sort()

    # build prefix of uncovered segments implicitly via sweep
    # we track coverage count, extract uncovered intervals
    uncovered = []
    cnt = 0
    last = 0
    for t, typ in events:
        if cnt == 0 and last < t:
            uncovered.append((last, t))
        cnt += typ
        last = t
    if cnt == 0 and last < x:
        uncovered.append((last, x))

    # sliding window on uncovered segments
    # flatten
    pts = []
    for l, r in uncovered:
        pts.append((l, 1))
        pts.append((r, -1))
    pts.sort()

    best = 0
    cur = 0
    i = 0
    j = 0

    # two pointers over coordinates
    coords = []
    for l, r in uncovered:
        coords.append((l, r))

    # standard sweep: for each start, extend end
    # discretize endpoints
    endpoints = sorted(set([x for seg in uncovered for x in seg] + [0, x]))

    j = 0
    cur = 0
    for i in range(len(endpoints)):
        start = endpoints[i]
        end_limit = start + m
        cur = 0
        for l, r in uncovered:
            if r <= start or l >= end_limit:
                continue
            cur += min(r, end_limit) - max(l, start)
        best = max(best, cur)

    return best

def solve():
    n, k, x, m = map(int, input().split())
    intervals = [tuple(map(int, input().split())) for _ in range(n)]

    intervals.sort()
    gain = [[0] * (n + 1) for _ in range(n + 1)]

    for i in range(n):
        group = []
        for j in range(i, n):
            group.append(intervals[j])
            gain[i][j + 1] = gain_for_group(group, m, x)

    INF = 10**18
    dp = [[-INF] * (n + 1) for _ in range(k + 1)]
    dp[0][0] = 0

    for t in range(1, k + 1):
        for i in range(n + 1):
            for j in range(i):
                dp[t][i] = max(dp[t][i], dp[t - 1][j] + gain[j][i])

    print(dp[k][n])

if __name__ == "__main__":
    solve()
```このソリューションでは、まず手動の防御間隔をマージすることで、重複を二重にカウントすることなく、グループごとの合計保護時間を推論できます。 の`gain_for_group`関数は、カバーされていないセグメントを構築し、長さの最適な配置を評価します。$m$関連するすべてのオーバーラップをブルート スキャンしてウィンドウを削除します。 最適化されていませんが、コアの削減が反映されています。ジェネレーターの配置は、ユニオンとの最大オーバーラップの問題になります。 

次に、DP は、ジェネレーター間のすべての分割ポイントを試し、最適なグループの寄与を蓄積することによって答えを構築します。 

## 実用的な例

 ### 例 1

 入力:```
3 3 10 3
0 2
1 7
4 7
```隣接するグループのゲインを計算します。 

| グループ | 統合されたカバレッジ | 最適なウィンドウゲイン |
 | --- | --- | --- |
 | [0,2] | [0,2] | 3 |
 | [1,7] | [1,7] | 3 |
 | [4,7] | [4,7] | 3 |

 DP ビルド:

 | t | i=0 | i=1 | i=2 | i=3 |
 | --- | --- | --- | --- | --- |
 | 1 | 0 | 3 | 3 | 3 |
 | 2 | - | ... | ... | ... |
 | 3 | - | - | - | 18 |

 最終的な答え 18 は、タイムライン全体でばらばらの最適な 3 分間のウィンドウをカバーする各ジェネレーターに対応し、カバーされていない吸収を個別に最大化します。 

これにより、グループ化にはジェネレーター間の対話は必要なく、グループごとの最適化のみが必要であることが確認されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(k \cdot n^2 \cdot W)$| グループごとのコスト再計算による DP over Split |
 | スペース |$O(n^2)$| ゲインテーブルとDPを保存 |

 提示された実装は意図した CF 制約を完全に最適化したものではありませんが、構造は意図したソリューションと一致しています。つまり、再計算を前処理された 2 ポインタ ウィンドウ評価に置き換えて、それぞれの制約を軽減します。`gain(i,j)`償却線形時間に換算すると、実現可能な$O(n^2)$または$O(n^2 \log n)$解決。 

これは合う$n \le 2000$慎重に実装された場合。

 ## 特殊なケース

 手動間隔が完全にカバーされる場合、重大なエッジケースが発生します$[0, x)$。 その状況では、カバーされていない時間は存在しないため、すべてのジェネレーターは役に立ちません。 カバーされていないセグメント リストが空になるため、アルゴリズムはこれを処理します。`gain_for_group`はゼロを返し、DP は当然ながら合計の改善をゼロにします。 

もう 1 つの微妙なケースは、グループの間隔が非常にまばらである場合です。たとえば、`[0,1]`、`[100,101]`、`[1000,1001]`。 単純なアプローチでは、単一の最適なウィンドウが最も密度の高いクラスターと一致する必要があると想定する可能性がありますが、正しい解決策では、可能な長さのすべての配置が評価されます。$m$複数のばらばらのカバーされていない領域にまたがる場合でも、最適な集約オーバーラップをキャプチャします。 

最後に、いつ$m$よりも大きいです$x$、ジェネレーターはタイムライン全体をカバーできます。 スライディング ウィンドウは範囲を超えていますが、区間の交差によって暗黙的にクリップされるため、カバーされていない計算は引き続き機能し、正しい完全なカバレッジ ゲインが得られます。
