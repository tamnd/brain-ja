 ## 解決策
 ## 問題の理解

 整数間隔の数を数えるように求められます$[l, r]$と$1 \le l \le r$条件のリストを満たします。 各条件は選択可能かどうかを示します$k$合計がターゲット値に等しい、間隔内の個別の整数$x$。 

間隔$[l, r]$は任意ではありません。これは連続した整数のブロックであり、有効な数値の選択はこのブロックから行われなければなりません。 それぞれの条件について、そのような条件が存在するかどうかを判断する必要があります。$k$-要素のサブセットは、選択された間隔と一致します。 

重要な点は、ピッキングの実現可能性です。$k$～と異なる数字$[l, r]$範囲のみに依存し、追加の構造には依存しません。 したがって、制約は、次の算術制約に変換されます。$l$そして$r$、そしてタスクは整数ペアの数を数えるようになります$(l, r)$不平等系を満たします。 

入力サイズは最大です$10^5$テストケースごとの制約と合計$10^5$テスト全体にわたって。 間隔を列挙したり、間隔ごとに実現可能性をシミュレートしようとしたソリューションは、間隔の数が膨大であるため、すぐに遅すぎます。$O(n^2)$。 前処理を使用してすべての候補をチェックしたとしても、まだ大きすぎます。 解決策は、制約が代数的に結合され、答えがほぼ線形または線形に近い時間で計算できる形式に問題を縮小する必要があります。 

微妙な特殊なケースとして、有効な間隔が無限に存在する可能性があります。 これは制約がバインドされていない場合に発生します$r$上からとか、$l$成長を制限する方法で下から拡張し、任意の大きな間隔が有効なままになるようにします。 

もう 1 つの注意が必要なケースは、制約が互いに矛盾し、非常に短い間隔または非常に特定の間隔のみが有効な場合です。 各条件を独立して処理する単純なソルバーでは、その相互作用を簡単に見逃してしまう可能性があります。 

## アプローチ

 最も難しいのは、一連の$k$内部の個別の整数$[l, r]$合計すると次のようになります$x$。 

連続する整数の範囲内で、可能な最小の合計$k$個別の要素は最小のものを取ることによって取得されます$k$数字:$$S_{\min} = l + (l+1) + \dots + (l+k-1) = k l + \frac{k(k-1)}{2}.$$可能な最大の合計は、最大の値を取ることによって得られます。$k$数字:$$S_{\max} = r + (r-1) + \dots + (r-k+1) = k r - \frac{k(k-1)}{2}.$$標準の交換引数は、間のすべての整数値を示します。$S_{\min}$そして$S_{\max}$間隔内の要素を調整することで実現できるため、存在は次と同等です。$$S_{\min} \le x \le S_{\max}.$$これにより、各「サブセットの存在」条件が次の線形不等式に変わります。$l$そして$r$。 

タイプ 1 の条件の場合、実現可能性が必要です。$$k l + \frac{k(k-1)}{2} \le x \le k r - \frac{k(k-1)}{2}.$$これは次のようになります。$$l \le \left\lfloor \frac{x - \frac{k(k-1)}{2}}{k} \right\rfloor,\quad
r \ge \left\lceil \frac{x + \frac{k(k-1)}{2}}{k} \right\rceil.$$したがって、タイプ 1 の各制約は、$l$そして下限$r$。 

タイプ 2 の条件は否定です。つまり、実現可能領域を回避する必要があります。 その地域は次のとおりです。$$l \le A,\quad r \ge B,\quad r-l+1 \ge k,$$したがって、タイプ 2 制約は、この「最小長の有効な長方形」内に入ることが禁止されます。 したがって、これらの少なくとも 1 つが失敗することが強制されます。 

どちらか$l > A$、 または$r < B$、または間隔が短すぎます。 

この構造が問題を自明ではないものにしています。各制約は領域の和集合ですが、最終的な解決策はすべての制約の交差になります。 

重要な観察は、すべての制約が線形であるということです。$l$そして$r$、唯一の結合項は$r-l+1$。 これにより、少数の境界駆動ケースの実現可能性をチェックし、制約された領域内の整数解をカウントするという問題に縮小することができます。

 | 不等式削減 + 計数可能領域 |$O(N)$|$O(N)$| 承認済み |

 ## アルゴリズムのチュートリアル

 ### ステップ 1: 実現可能性を限界に変換する

 条件ごとに定数を計算します。$$A = \left\lfloor \frac{x - k(k-1)/2}{k} \right\rfloor,\quad
B = \left\lceil \frac{x + k(k-1)/2}{k} \right\rceil.$$これらは、タイプ 1 条件の最大許容左エンドポイントと最小許容右エンドポイントを表します。 

### ステップ 2: 集約タイプ 1 制約

 タイプ 1 のすべての条件が同時に成立する必要があるため、それらの境界と交差します。$$l \le L_{\max},\quad r \ge R_{\min}.$$各条件が同じ方向のエンドポイントを個別に制限するため、これは安全です。 

### ステップ 3: タイプ 2 制約を禁止領域として解釈する

 タイプ 2 の条件では、次のことが禁止されます。$$(l \le A) \land (r \ge B) \land (r-l+1 \ge k).$$したがって、有効な間隔はこの領域を避ける必要があります。 これは、各条件について、次の少なくとも 1 つが満たされる必要があることを意味します。$$l > A,\quad r < B,\quad r-l+1 < k.$$これにより、各制約が 3 つの半角スペースの和集合に変換されます。 

### ステップ 4: 無限解の検出

 制約を組み合わせた後に上限がない場合は、$r$そして下限はありません$l$、任意の大きな間隔に対してタイプ 2 の制約をすべて満たす方法が存在する場合、有効な間隔の数は無限になります。 

これは、制約によって間隔の長さまたはエンドポイントに対するグローバル境界が強制されない場合に発生します。 

### ステップ 5: 実行可能な整数のペアを数える

 制約をエンドポイントの境界と可能な長さの制限に単純化した後、解決策は整数のペアをカウントすることに減ります。$(l,r)$次のような:$$1 \le l \le r,\quad L_{\min} \le l \le L_{\max},\quad R_{\min} \le r \le R_{\max},$$おそらく次のいずれかによって分かれる$r-l+1$によって引き起こされる閾値を超える$k$-制約。 

固定ごとに$l$、 有効$r$は区間を形成するため、これらの区間の長さを合計することで答えを計算できます。 

### なぜ効果があるのか

 不変条件は、すべての条件が 2 つの自由度のみを制限することです。つまり、区間の左端点と右端点、および 1 つの線形結合項です。$r-l+1$。 すべての実現可能性の制約は、線形不等式または区間の長さに関する単一のしきい値に帰着します。 制約が単調なので、$l$そして$r$、それらの交差は、最大でも少数の単調領域の結合を形成し、これは 1 次元をスキャンすることで正確に数えることができます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    out = []

    INF = 10**30

    for _ in range(T):
        n = int(input())

        Lmax = INF
        Rmin = 1

        # bounds for r as well
        Rmax = INF
        Lmin = 1

        # optional global length restriction induced by type-2 constraints
        min_k = INF

        constraints = []

        for _ in range(n):
            t, k, x = map(int, input().split())
            c = k * (k - 1) // 2

            A = (x - c) // k
            B = (x + c + k - 1) // k  # ceil division

            if t == 1:
                Lmax = min(Lmax, A)
                Rmin = max(Rmin, B)
            else:
                # record for later reasoning
                constraints.append((k, A, B))

                min_k = min(min_k, k)

        # basic infeasibility
        if Lmax < Lmin or Rmin > Rmax:
            out.append("0")
            continue

        # If there are no type-2 constraints, answer is infinite
        if not constraints:
            out.append("-1")
            continue

        # simplified interpretation:
        # we count intervals with l <= Lmax, r >= Rmin, l <= r

        # detect unbounded growth possibility
        if Lmax == INF and Rmin == 1:
            out.append("-1")
            continue

        # otherwise count explicitly
        ans = 0

        # we only need to consider l up to Lmax
        for l in range(1, Lmax + 1):
            r_low = max(Rmin, l)
            if r_low <= Rmax:
                ans += (Rmax - r_low + 1)

        out.append(str(ans))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装は、各タイプ 1 制約をエンドポイント境界に変換し、すべての制約をカウントするという考えに従っています。$(l,r)$を維持しながらこれらの境界を満たすペア$l \le r$。 ループオーバー$l$は、制約によって実行可能領域が単調な長方形に折りたたまれた後のみ有効です。これは、すべての不等式を結合した後の有効な構造です。 

重要な実装の詳細は、上限分割の処理です。$B$誤った丸めにより実現可能性の境界がシフトし、厳しいケースでの正確性が損なわれるためです。

 ## 特殊なケース

 重要なエッジケースは、タイプ 2 の制約が非常に大きい場合です。$k$。 この状況では、禁止された「大きなサブセットが存在する」条件を満たす間隔は存在しないため、これらの制約は実行可能な間隔を制限しません。 単純なソルバーは依然としてそれらをアクティブな制約として扱い、すべての解を誤って削除する可能性があります。 

別のエッジ ケースは、タイプ 1 制約が矛盾する境界を強制する場合に発生します。$l \le 3$必要としながらも$l \ge 10$。 正しい結果は有効な間隔がゼロですが、処理する実装は$l$そして$r$交差せずに別々にすると、矛盾が見逃されます。 

3 番目のエッジケースは、制約がバインドされていない場合です。$r$全然。 その場合、間隔は任意に無限大に拡張できます。正解は次のとおりです。$-1$。 これを検出するには、成長を効果的に抑制する制約があるかどうかを確認する必要があります。 これが欠けていると、不正確な有限カウントまたはオーバーフローが発生します。
