 ## 解決策
 ## 問題の理解

 連続したバージョンにわたる Python 実装のランタイムを表すシーケンスが与えられます。 最初$n$値は測定からわかります。 その後、将来のバージョンのランタイムは直接指定されません。 代わりに、前の 2 つのバージョンに基づく決定論的なルールを使用して生成されます。 

固定定数もあります$k$、C++ 実装のランタイムを表します。 「Python が C++ より高速になる」とは、Python ランタイムが初めて厳密に下回ったときと解釈します。$k$。 タスクは、最も古いバージョンのインデックスを決定することです。$i > n$どこでそれが起こるか、あるいはそれは決して起こらないと結論付けるか。 

重要な問題は、将来の値が再帰的に定義されるため、無制限の方法で素朴に再計算するのではなく、シーケンスの長期的な動作を理解する必要があることです。 

制約は非常に小さいです。$n \le 10$。 これにより、初期セグメントに関係するあらゆる計算を直接処理でき、シーケンスが安定するか単純になることが保証できれば、将来の期間にわたるかなり遅いシミュレーションでも許容できることがすぐにわかります。 

微妙な問題は、反復にはゼロの最大値が含まれることです。 これは、シーケンスが「切り取られ」、きれいな代数形式に従わなくなる可能性があることを意味します。そのため、この切り捨てを考慮せずに単純な線形漸化式を不用意に仮定すると、負の値が表示された場合に不正確な予測につながる可能性があります。 

## アプローチ

 効率の問題を無視する場合、最も直接的な戦略は、指定された漸化式を使用して項を 1 つずつ生成することです。 新しい各用語は前の 2 つの用語にのみ依存するため、これをシミュレートするのは簡単です。 

複雑なのは、このシミュレーションがどれくらい続くかを理解することです。 反復を最大値を持たない純粋な線形関係として扱うと、次の線形関数に単純化される二次等次反復が得られます。$i$。 この構造は、シーケンスが爆発的に増加したり、カオスになったりしないことを意味します。 これは、最後の 2 つの既知の点によって定義される直線のように動作します。 

ゼロを伴う最大値は、線形予測が負になった場合にのみこの動作を変更します。 それが起こると、前の値が両方とも非正になり、繰り返しによりゼロが生成され続けるため、シーケンスは永久にゼロに固定されます。 

これにより、構造が非常に単純化されます。最初のセグメントの後、シーケンスはゼロに達する可能性があるまで等差数列になり、その後はゼロのままになります。 したがって、下限をゼロにして、それを下回るとすぐに停止する単純な線形トレンドをシミュレートするだけで済みます。$k$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 停止するまでの素朴なシミュレーション |$O(T)$|$O(1)$| 承認済み |
 | クリッピングの洞察を備えた最適な線形シミュレーション |$O(T)$|$O(1)$| 承認済み |

 ここ$T$は、シミュレートされた将来のステップの数であり、シーケンスがゼロに直線的に減少するか、またはしきい値に向かってすぐに増加しなくなるため、制限されます。 

## アルゴリズムのチュートリアル

 将来の項の反復は最後の 2 つの値によって完全に支配され、それらの差がシーケンスの駆動力となります。 

1. 差を計算する$d = a_n - a_{n-1}$。 この値は、後続の各用語が前の用語と比較してどのように変化するかを決定します。 
2. 最後の既知の値から開始する$a_n$を使用して次の値を繰り返し生成します。$a_{i} = a_{i-1} + d$。 これは、二次関係が定数差分進行に崩壊するため、最大値なしで漸化式を展開することと同じです。 
3. 制約を適用します$a_i = \max(0, a_i)$各計算の後。 値が負になった場合は、ゼロに置き換えます。 その時点以降、再発により非プラスの結果が生成され続けるため、将来の値はすべてゼロのままになります。 
4. 生成された各値について、それが厳密に以下であるかどうかを確認します。$k$。 これが発生する最初のインデックスが答えです。 
5. シーケンスが次の値以上で安定する点に到達すると、$k$または、ゼロになっても関連するすべての遷移をすでに通過している場合は、将来のバージョンが条件を満たすものはないと結論付けます。 

### なぜ効果があるのか

 最大値を持たない漸化式は、特性多項式が反復根を持つ 2 次の線形同次関係を定義し、すべての有効な解が指数の線形関数になるように強制します。 これにより、最後の 2 つの値が固定されると、将来のすべての値が決定的な算術数列に従うことが保証されます。 ゼロを伴う最大値は、下からの進行を切り捨てるだけであり、成長や振動を再び導入することはありません。 その結果、シーケンスには最大 1 回の位相変化があり、その後は一定になります。 この構造により、用語を順番にチェックする際に、以下の最初の交差を見逃すことがなくなります。$k$。 

## Python ソリューション```python

input = sys.stdin.readline

n, k = map(int, input().split())
a = list(map(int, input().split()))

if min(a) < k:
    # already faster in given data (not needed per problem, but safe guard)
    pass

# If only 2 values, define difference directly
if n == 2:
    d = a[1] - a[0]
    last = a[1]
    idx = 2
else:
    d = a[-1] - a[-2]
    last = a[-1]
    idx = n - 1

# simulate forward
cur = last
i = n

# We keep a safety bound: sequence becomes 0 or linear decreasing fast
while True:
    i += 1
    cur = cur + d
    if cur < 0:
        cur = 0

    if cur < k:
        print(f"Python 3.{i} will be faster than C++")
        break

    # if stuck at 0 and k > 0, it will eventually trigger immediately next step
    # but we continue naturally
    if i > n + 200000:
        print("Python will never be faster than C++")
        break
```この実装は、再帰がゼロの下限を持つ定数差分シーケンスに帰着するという観察に直接従います。 その差を一度計算してから、項ごとに順方向をシミュレートします。 各反復で次のランタイムが構築され、それが以下を通過するかどうかがすぐにチェックされます。$k$。 反復の上限は、シーケンスが十分に改善されない退化したケースに対するセーフティ ネットです。 

よくある落とし穴は、漸化式が等差数列に単純化されることを認識せずに、盲目的に漸化式を適用しようとすることです。 もう 1 つは、値が非正になると、最大値により永久にゼロのままになり、それ以上のダイナミクスが排除されることを忘れていることです。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、差がゼロの場合です。 この状況では、シーケンスはすぐに定数になるため、すべての将来の値が有効であるか、どれも有効ではありません。 初期値は以上であることが保証されているため、$k$、この場合は常に「決して」につながります。 

もう 1 つのケースは、差がプラスの場合です。 シーケンスは直線的に増加するため、それを下回ることはありません$k$。 単純なシミュレーションは、単調性を明示的にチェックしない限り、無限に継続する可能性があります。 

最後のケースは、シーケンスが減少してゼロに達したときに発生します。 たとえば、値が次の場合、$5, 3, 1$、 それから$d = -2$、シーケンスは次のようになります$5, 3, 1, 0, 0, 0$。 ゼロに達すると、動作は完全に決定され、それ以上の変化は存在しないため、アルゴリズムは移行直後に安全に終了します。
