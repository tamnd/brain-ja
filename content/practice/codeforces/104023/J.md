 ## 解決策
 ## 問題の理解

 整数の複数セットが与えられています$a_1, a_2, \dots, a_n$。 各移動は、1 つの要素を選択し、それを減少させることで構成されます。$1$。 時間の経過とともに、要素は下方に流れていき、最終的には$0$。 

さらに、いくつかの値$x$上限がある$limit_x$配列内に一度に出現できる回数。 値に制約がない場合、値には実質的に制限がありません。 

実行後に任意の値が返された場合、その移動は不正です。$x$その限界を超えています。 特に、要素を から減らす場合、$v$に$v-1$の数を減らします。$v$の数を増やします$v-1$したがって、宛先の値のみが無効になる可能性があります。 

プレイヤーは正当な手を打てなかった場合に負けます。 これは、すべての値がゼロの場合、または考えられるあらゆる減分が直ちに制約に違反する場合に発生します。 

課題は、両方のプレイヤーが最適にプレイし、ピコが先に動いた場合に勝者を決定することです。 

この制約は、プレイを段階的にシミュレートできないことを意味します。 すべてのテスト ケースの合計サイズは次のとおりです。$10^5$したがって、どのような解も、関係する個別の値の数において本質的に線形または線形に近いものでなければなりません。 

値がちょうどその制限に達すると、微妙なエッジ ケースが発生します。 その状況では、より大きな値をそこに移動しようとする試みは禁止され、さらなる下向きの流れが効果的にブロックされます。 これにより、値のラインを独立した領域に分割する「障壁」が作成される可能性があります。 

## アプローチ

 直接シミュレーションでは、要素を繰り返し選択し、すべての制約をチェックしながらそれをデクリメントしようとします。 各移動では、2 つの頻度カウントを更新し、すべての制約された値を検証する必要があります。 まであり得るので、$10^9$値として、および最大$10^5$移動する場合、このアプローチは実行不可能です。 

重要な観察は、制約がゲームに影響を与える唯一の方法は、隣接する値間の遷移をブロックすることであるということです。 要素を移動するとき$x$に$x-1$の数を増やします。$x-1$。 もし$x-1$すでに限界に達しているため、この動きは禁止されています。 一度の値$x$飽和すると（その数がその制限に等しい）、永続的なバリアになります。つまり、要素をその中に移動することはできません。$x$これも、すぐに制約に違反してしまうためです。 

これにより、整数行の分割が独立したセグメントに作成されます。 各セグメント内では、要素はその下の最も近い飽和値に達するまで下方向にのみ移動でき、これが吸収境界として機能します。 このようなセグメント内では、すべての要素が境界上で崩壊するまで、すべての減少によって単純に質量が下方にシフトされ、有効な移動の数は正確にその境界を超える超過の合計になります。 

したがって、ゲームは、すべてが強制的に停止されるまでに要素を何回デクリメントできるかをカウントすることになります。 各デクリメントは 1 つの動きであるため、合計の手数は戦略に関係なく固定され、最適なプレイによって最後の手を取る人のみが決まります。 勝者は、有効な手の合計数の同等性によって決定されます。

 ## アルゴリズムのチュートリアル

 システムが移動不可能な状態に達する前に、有効なデクリメント操作の合計が何回存在するかを計算するという問題として再定式化します。 

### 1. 値の頻度を構築する

 私たちは計算します$cnt[x]$、各値の出現数$x$配列内で。 制約または配列に現れる値のみが問題となります。 

の役割$cnt$どの制約値がすでに飽和しているかを判断することです。 

### 2. 飽和した制約点を特定する

 あらゆる制約に対して$x \to limit_x$かどうかを確認します。$cnt[x] = limit_x$。 等式が成り立つ場合、$x$すぐに飽和してしまいます。 

そのような価値観$x$値を移動しようとする試みは永続的なバリアになります。$x+1$の中へ$x$は禁止されています。 

### 3. 飽和点を並べ替える

 飽和した値をすべて収集し、それらを徐々に並べ替えます。 これらの点は、整数ラインを独立したセグメントに分割します。 

2 つの連続する飽和値の間$b < c$、値が含まれる要素$(b, c]$到達するまで下に移動することしかできません$b$。 

### 4. 各値の有効下限を定義します。 

それぞれの値について$v$、 定義する$L(v)$最大の飽和値として$\le v$。 何も存在しない場合は、$L(v) = 0$。 

この値は、以降の要素の最低レベルです。$v$到達できる。 

### 5. 合計の手数をカウントする

 値から始まる各要素$v$正確にデクリメントできる$v - L(v)$行き詰まる前に。 

すべての要素に対するこの寄与を合計します。$$\text{moves} = \sum_{i=1}^{n} (a_i - L(a_i)).$$### 6. パリティによって勝者を決定する

 それぞれの行動でターンが反転します。 最後に動いたプレイヤーが勝ちます。 したがって:

 - 合計の手数が奇数の場合、ピコが勝ちます。 
・互角ならふうふうの勝ち。 

### なぜ効果があるのか

 値が飽和すると、それを増やすことはできず、どの要素もその値を通過できません。 これにより、状態空間を分割する不変の境界が作成されます。 各パーティション内では、移動するたびに「境界までの距離」の合計が厳密に減少し、パーティションを越える移動はできません。 したがって、すべての有効な移動は、合計距離を減らすことに正確に対応します。$\sum (a_i - L(a_i))$による$1$であり、他の一連の動きでこの合計を変更することはできません。 これにより、ゲームは通常のプレイにおけるそのサイズの単一の山と同等になり、最適な結果はパリティのみに依存します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

T = int(input())
for _ in range(T):
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    
    cnt = {}
    for v in a:
        cnt[v] = cnt.get(v, 0) + 1

    limit = {}
    saturated = set()

    for _ in range(k):
        x, y = map(int, input().split())
        limit[x] = y

    for x, y in limit.items():
        if cnt.get(x, 0) == y:
            saturated.add(x)

    sat = sorted(saturated)

    def floor(v):
        # largest saturated value <= v
        lo, hi = 0, len(sat)
        while lo < hi:
            mid = (lo + hi) // 2
            if sat[mid] <= v:
                lo = mid + 1
            else:
                hi = mid
        return sat[lo - 1] if lo > 0 else 0

    total = 0
    for v in a:
        total += v - floor(v)

    if total % 2:
        print("Pico")
    else:
        print("FuuFuu")
```この実装では、まず頻度カウントが構築され、次に飽和制約点が特定されます。 ソートされた飽和リストに対する二分探索により、各値の有効下限が計算されます。 最終的な合計は、強制デクリメントの数を集計したものです。 

重要な実装の詳細は、等価の場合のみバリアが作成されるということです。 厳格な不平等は将来の動きを制限するものではありません。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    T = int(input())
    out = []
    for _ in range(T):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        
        cnt = {}
        for v in a:
            cnt[v] = cnt.get(v, 0) + 1

        limit = {}
        for _ in range(k):
            x, y = map(int, input().split())
            limit[x] = y

        sat = []
        for x, y in limit.items():
            if cnt.get(x, 0) == y:
                sat.append(x)
        sat.sort()

        def floor(v):
            lo, hi = 0, len(sat)
            while lo < hi:
                mid = (lo + hi) // 2
                if sat[mid] <= v:
                    lo = mid + 1
                else:
                    hi = mid
            return sat[lo - 1] if lo else 0

        total = 0
        for v in a:
            total += v - floor(v)

        out.append("Pico" if total % 2 else "FuuFuu")

    return "\n".join(out)

# sample-like sanity checks
assert run("1\n3 0\n1 2 3\n") == "FuuFuu"
assert run("1\n3 1\n1 2 2\n0 1\n") == "Pico"
assert run("1\n1 1\n5\n5 1\n") in ("Pico", "FuuFuu")

 ## 特殊なケース

 重要なエッジ ケースは、制約された値が開始時にすでに正確に飽和している場合に発生します。 そのような状況では、それは即座に永久的な境界になります。 たとえば、次のすべての出現があった場合、$0$すでに到達しています$limit_0$、その場合は値がありません$1$以上に移行することができます$0$、その時点で構造を凍結します。 このような値は下限を計算する前に飽和セットに明示的に挿入されるため、アルゴリズムはこれを正しく処理します。 

もう 1 つのエッジ ケースは、制約が存在しない場合です。 その場合、飽和点は存在せず、すべてのフロアが$0$、結果はすべての要素の合計のパリティに帰着します。
