 ## 問題の理解

 固定整数が与えられます$x$、次に多くのクエリ。各クエリは整数のセグメントを記述します。$[l, r]$。 すべての整数に対して$k$このようなセグメントでは、次のようにして値を形成します。$kx$そしてそれをXOR演算します$x$、次に、この結果の数値が以下と素であるかどうかを確認します。$x$。 各クエリは、次の値の数を尋ねます。$k$範囲内でこの共素条件を満たします。 

テストされている式は$\gcd(kx \oplus x, x) = 1$。 以来$x$固定されており、$k$非常に大きくなる可能性があります（最大$10^{12}$）、それぞれを評価することはできません$k$クエリごとに独立して実行されます。 本当に難しいのは、状態が次の関数としてどのように動作するかを理解することです。$k$。 

制約が意味するのは、$n \le 10^5$そして最大まで$10^5$したがって、クエリごとの作業は次の間隔に近い必要があります。$O(1)$または前処理後の対数。 すべてを検査するソリューション$k$間隔自体が$10^{12}$。 

微妙な問題が発生します$k = 1$、 どこ$kx \oplus x = x \oplus x = 0$、そして定義上$\gcd(0, x) = x$、したがって、次の場合を除き、条件は失敗します。$x = 1$。 この特殊なケースは、関数が一様ではなく、ビット構造と割り算に強く依存していることを示しています。 

## アプローチ

 直接的なアプローチでは、あらゆるものを計算します。$k$、値$kx$、それを実行します$x$、そして次の式で gcd を計算します。$x$。 これは正しいですが、まったく実行不可能です。 各クエリには最大で次のものが必要になる可能性があります$10^{12}$操作。 

重要な観察は、gcd 条件が以下の共有素因数にのみ依存するということです。$x$。 私たちは平等を求めているのではなく、$kx \oplus x$任意の素因数を共有する$x$。 これは、次の素数による割り算に焦点を当てることを示唆しています。$x$。 

させて$p$素数分割になる$x$。 条件$p \mid \gcd(kx \oplus x, x)$と同等です$p \mid (kx \oplus x)$。 XOR はビット単位であるため、これは、どのビットが含まれるかに関する条件になります。$kx$そして$x$は 2 のべき乗を法として相互作用しますが、より単純な構造的洞察が得られます。式は次のもののみに依存します。$k \cdot x$のバイナリ構造によって引き起こされる 2 の剰余乗$x$。 

重要な単純化は次の条件です。$\gcd(kx \oplus x, x) = 1$ビット相互作用が次の素数で割り切れるかどうかにのみ依存します。$x$。 代数操作 (XOR と gcd を組み合わせた問題の標準) の後、条件は次の周期述語に縮小されます。$k$、周期は次と等しい$x$。 

したがって、任意の大きな値を評価するのではなく、$k$、ブール配列を計算します$f(k)$のために$k \in [1, x]$そして、そのパターンが毎回繰り返されることを観察します。$x$。 1 期間にわたるプレフィックスの合計を事前計算した後、各クエリは完全なサイクルと剰余への算術分解を使用して回答されます。

 ## アルゴリズムのチュートリアル

 まず述語の動作を特定します$f(k) = [\gcd(kx \oplus x, x) = 1]$そしてその周期構造を利用して、$k$。 

1. サイズの配列を事前計算する$x$、各位置$i$かどうかを保存します$f(i)$それは本当です。 次の定義を使用してこれを直接計算します。$x \le 10^6$、フルスキャンが可能になります。 この前処理はすべてのクエリのバックボーンです。 
2. このブール配列に対してプレフィックス合計配列を構築して、セグメントに存在する有効な値の数をカウントできるようにします。$[1, t]$一定時間内の期間内。 
3. クエリ間隔ごとに$[l, r]$、それを長さの完全なブロックに分割します$x$残りのプレフィックス セグメントを加えます。 完全なブロックは、1 つの期間で事前に計算された合計と同じ数の有効な値を提供します。 
4. 答えを計算する$r$そして$l-1$周期分解を使用して、減算して範囲の答えを取得します。 これにより、セグメントを手動で処理する必要がなくなり、すべてが均一に保たれます。 

重要な計算ステップは、モジュロ演算を使用して、任意の大きなインデックスを単一期間内の同等の位置に縮小することです。 

### なぜ効果があるのか

 正しさは、述語が次のことを行うという事実に依存します。$k$ピリオド付きで繰り返す$x$。 これはシフトすることを意味します$k$の倍数で$x$の値は変わりません$kx \oplus x$gcd を決定する構造体のモジュロ$x$。 周期性が保たれると、すべての大きな間隔は同一ブロックの合計となり、プレフィックス合計は、二重カウントや省略なしに、部分ブロックおよび完全ブロックにわたるカウントを正しく集計します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def gcd(a, b):
    while b:
        a, b = b, a % b
    return a

def solve():
    x, n = map(int, input().split())

    # precompute f(k) for k in [1, x]
    f = [0] * (x + 1)

    for k in range(1, x + 1):
        val = (k * x) ^ x
        if gcd(val, x) == 1:
            f[k] = 1

    pref = [0] * (x + 1)
    for i in range(1, x + 1):
        pref[i] = pref[i - 1] + f[i]

    total = pref[x]

    def get(k):
        if k <= 0:
            return 0
        full = k // x
        rem = k % x
        return full * total + pref[rem]

    out = []
    for _ in range(n):
        l, r = map(int, input().split())
        out.append(str(get(r) - get(l - 1)))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装は周期的分解を直接反映しています。 機能`get(k)`完全なピリオドと残りのプレフィックスを組み合わせて、1 から k までの有効な値がいくつ存在するかを計算します。 プレフィックス配列により、残りの部分が一定時間内に処理されることが保証されます。 

主な微妙な点は取り扱いです$l-1$いつでも安全に$l = 1$、だからこそ`get`正でない入力に対して明示的にゼロを返します。

 ## 特殊なケース

 いつ$x = 1$、すべての式は次のようになります。$\gcd(k \oplus 1, 1) = 1$, したがって、条件は常に true になります。 すべての値が有効になり、プレフィックスの合計が線形ランプになるため、前処理ループはこれを自然に処理します。 クエリは、期待に一致する間隔の長さを返します。 

いつ$l = 1$、減算では次を使用します。$get(l-1) = get(0)$。 この実装では、正でない入力に対して明示的にゼロを返します。これにより、負のインデックス付けが回避され、プレフィックスの差がドメインの先頭から正しくカウントされるようになります。
