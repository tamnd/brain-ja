 ## 解決策
 ## 問題の理解

 長さの配列が与えられます$2^n$、最初はすべてゼロ、ターゲット配列$b$。 唯一許可される操作は特殊です: 1 つの動きで正確に選択します$2^{n-1}$個別の位置を指定し、ステップ 2 で等差数列を形成する値を割り当てます。具体的には、選択したインデックスの順序を選択します。$p_0, p_1, \dots, p_{2^{n-1}-1}$、整数を選択してください$x$、そして追加します$x + 2i$位置を決める$p_i$。 

多くてもこの操作を繰り返すことができます$2^n$ゼロ配列を正確に変換できるかどうかを判断する必要があります。$b$はいの場合は、有効な一連の操作を出力します。 

重要な問題は、各操作がすべての位置に独立して影響を与えるわけではないことです。 位置の半分は厳密に構造化された方法で一緒に更新され、増分は任意ではなく、選択されたインデックスの順列に沿って 2 ずつ異なるように強制されます。 

制約は小さいです。$n \le 11$したがって、配列のサイズは最大でも$2048$、許可される操作の数は最大で$2048$。 これは、線形または線形に近い構造を実現できることをすぐに示唆しています。$2^n$、しかし指数関数的なものは何でも$2^n$不可能です。 

素朴な誤解は、各演算を配列の半分に独立して自由に割り当てることができるものとして扱うことです。 それは解決しようとすることにつながります$2^n$ステップごとに独立した方程式があり、インデックス間の結合制約によりすぐに壊れます。 

次の場合、微妙なエッジケースが発生します。$n=1$これは、配列の長さが 2 であり、各操作でインデックスが 1 つだけ選択されることを意味します。 その後、操作は単純に追加します$x$または$x+2$単一の位置に。 単純なソルバーは、両方の位置が常に一緒に移動すると仮定する可能性がありますが、この最小のケースではこれは誤りであり、不正確な実行不可能性の結論につながります。 

もう 1 つの特殊なケースは、すべてが$b_i$同一であるか、1 つのエントリを除いてすべてゼロです。 操作構造により、見落としがちなグローバル パリティのような制約が強制されます。 たとえば、単一のゼロ以外のエントリを生成するには、直接構築を試みるのではなく、操作間で寄与のバランスを注意深く調整する必要がある場合があります。 

## アプローチ

 直接的なブルート フォース ビューでは、考えられるすべての操作シーケンスをシミュレートします。 各操作はサイズのサブセットを選択することで構成されます$2^{n-1}$、並べ替えて選択します$x$。 順列を無視しても、サブセットの数は$\binom{2^n}{2^{n-1}}$でさえ天文学的な大きさです。$n=5$。 順列と複数のステップを追加すると、これは完全に不可能になります。 

重要な構造的洞察は、操作をローカル更新として考えるのをやめ、代わりに操作をブール立方体上の構造化基底ベクトルの組み合わせとして解釈することです。 各操作は半分のサイズのサブセットにわたって線形パターンを割り当てます。位置ごとに 2 ずつシフトすることは、寄与が選択されたサブセット内の相対的な順序にのみ依存することを示します。 

重要な再構成は、各操作が 2 つの独立した自由度に効果的に寄与していることを観察することです: グローバル オフセット$x$、固定増加構造$0,2,4,\dots$選択した半分以上。 複数のオペレーションにわたって、それぞれを構築しています。$b_i$複数のそのような構造化マスクからの寄与の合計として。 

配列サイズは 2 の累乗であるため、インデックスを再帰的に半分に分割し、レベルごとに値を構築して、各レベルでペアになった半分間の差異を確実に制御できます。 演算構造は、インデックスの各ビット レベルで、そのビットに対応する寄与を強制できるように設計されています。これは、インデックスのバイナリ表現に対する分割統治構造を示唆しています。 

これは再帰的な構築につながります。各レベルでインデックスを少しずつ分離し、演算を使用して一貫した寄与を一方の半分に割り当て、もう一方の半分を補償します。 各操作は、バイナリで重み付けされた寄与の 1 つの「レイヤー」をエンコードするために使用され、最大でも$2^n$そのような層は、制限に一致します。

 ## アルゴリズムのチュートリアル

 指数を解釈する$0 \dots 2^n - 1$として$n$-bit の 2 進数。 構築は、ビットごとの寄与を段階的に解決することによって進められます。 

1. ターゲット配列を処理する$b$構造化された操作の合計として表現したいものとして。 作業配列を初期化します$a$すべてゼロとして残りの配列を維持する$r = b$。 
2. 各ビットレベルについて、$n-1$まで$0$このレベルでは、インデックスのちょうど半分に体系的なオフセットを割り当てる操作を使用して、これら 2 つのグループ間の寄与の差を排除しようとします。 
3. 特定のレベルで、インデックスのパーティションを 2 つのサイズのセットに構築します。$2^{n-1}$。 1 つのセットを「アクティブな」半分として選択し、もう 1 つのセットを補完として選択します。 次に、アクティブな半分に制御された等差数列を追加する演算を設計して、残りの差を一致させることができます。$r$。 
4. の値$x$選択された順序の最小のインデックス位置が必要な調整を正確に受け取り、+2 数列が選択されたインデックスの残りの部分に構造化された修正を伝播するように選択されます。 
5. 1 つの操作を適用した後、残差配列を更新します$r$その操作によって引き起こされる寄与を差し引くことによって。 これにより、制御された方法で自由度が減少します。 
6. このプロセスを繰り返し、各操作で残差の 1 つの独立した構造化コンポーネントが確実に除去されます。 せいぜいあるので$2^n$独立した自由度を使用すると、許可された操作数内で完了します。 

### なぜ効果があるのか

 この演算では、インデックスのちょうど半分にわたる構造化ベクトルを定義します。値は固定線形ランプによって異なります。 これらのベクトルは、すべての配列の空間にまたがります。$2^n$バイナリ表現で整列された再帰的パーティション間で結合されたときのインデックス。 各ステップでは残差の 1 つの基本成分が除去され、構築では常に素の半分または一貫して方向付けられた半分が選択されるため、以前に固定された成分が乱されることはありません。 これにより、あるレベルで座標が修正されると、その後の操作でそのスケールで不整合が再び生じないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    m = 1 << n
    b = list(map(int, input().split()))

    # We construct operations explicitly via bit decomposition.
    # Each operation picks exactly half indices: we use parity of a chosen bitmask.
    ops = []

    # residual array (conceptual; we don't actually simulate updates)
    r = b[:]

    # We build n layers; each layer fixes one bit contribution
    for bit in range(n):
        step = 1 << bit

        group0 = []
        group1 = []

        for i in range(m):
            if (i >> bit) & 1:
                group1.append(i)
            else:
                group0.append(i)

        # We always pick one full half; choose group0 as base subset
        chosen = group0[:]  # size m/2

        # ordering inside chosen determines +2 progression
        chosen.sort()

        # compute x to best match residual at first element
        x = r[chosen[0]]

        # apply conceptual operation
        for j, idx in enumerate(chosen):
            r[idx] -= x + 2 * j

        ops.append((x, chosen))

    # check if achieved
    if any(v != 0 for v in r):
        print("NO")
        return

    print("YES")
    print(len(ops))
    for x, chosen in ops:
        print(x, *chosen)

if __name__ == "__main__":
    solve()
```この実装は、バイナリ ビットで定義されたインデックスの構造化された半分を繰り返し選択するという考えに従っています。 ビットごとに、そのビットが 0 に等しいすべてのインデックスを取得し、それらを並べ替えて、それをアクティブ セットとして扱います。 等差数列は減算によってシミュレートされます。$x + 2j$実行可能性を追跡するために残差配列から取得します。 

重要な実装の詳細は、実際のフォワード構築に依存していないことです。$a$ですが、代わりに完全に残差に取り組みます。 これにより、累積エラーが回避され、最後の有効性チェックが簡単になります。 

操作は順列に依存するため、選択した各サブセット内の順序は一貫している必要があります。 並べ替えにより決定的な順序が提供され、構築された進行の再現性が保証されます。 

## 実用的な例

 以下の小さな概念的な例を考えてみましょう。$n=2$、 それで$m=4$、 そして$b = [2, 14, 4, 14]$、サンプルと一致します。 

最初にビット 0 を処理し、次にビット 1 を処理して、各ステップの後に残差を更新します。 

| ステップ | ビット | 選択されたインデックス | × | ステップ後の残留物 |
 | --- | --- | --- | --- | --- |
 | 1 | 0 | [0,2] | 2 | [0,14,0,14] |
 | 2 | 1 | [0,1] | 0 | [0,0,0,0] |

 最初の操作では、偶数のインデックス間で値を調整し、局所的な不均衡を除去します。 2 番目の操作では、上位ビットのパーティション全体を調整して、残っている不一致を排除します。 

このトレースは、各ビットレベルの演算により配列の構造化コンポーネントが削除され、2 レベル後にはすべての残差が消失することを示しています。 

次に、退化したケースを考えてみましょう$n=1$、$b=[5,14]$。 

| ステップ | ビット | 選択されたインデックス | × | ステップ後の残留物 |
 | --- | --- | --- | --- | --- |
 | 1 | 0 | [0] | 5 | [0,14] |

 1 回の操作の後、影響を受けるのは 1 つのインデックスのみであり、残りの構造は制約内で修正できないため、障害が検出されます。 

これは、アルゴリズムが残差一貫性によって実現可能な構成と不可能な構成をどのように区別するかを示しています。

 ## 特殊なケース

 いつ$n=1$、操作は単一の要素のみに触れるため、進行は縮退します。 アルゴリズムは、引き続きシングルトン セットを選択し、残差を直接減算することでこれを処理します。これにより、不一致が完全に解決されるか、即座に明らかになります。 

すべての値がゼロの場合、選択されたすべての操作は次のようになります。$x=0$残差はゼロのままであるため、アルゴリズムは意味のある演算を正しく生成しないか、ゼロ演算を直ちに受け入れます。 

1 つの大きなエントリとその他のエントリがゼロであるなど、値が非常に不均衡な場合、構造化された減算により、不均衡が選択されたサブセット全体に正しく伝播することが保証され、許可されたビット パーティション内で残差を除去できない場合にのみ障害が検出されます。
