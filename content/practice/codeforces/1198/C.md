 ## 問題の理解

 いくつかの無向グラフが与えられ、それぞれが正確に$3n$頂点。 グラフごとに、次のサイズの 2 つの特定の構造のうち 1 つを構築する必要があります。$n$: 以下からなる一致のいずれか$n$エッジ、またはから構成される独立したセット$n$頂点。 どちらの構造も存在しない場合は、不可能であることを報告する必要があります。 

マッチングとは、選択した複数のエッジに頂点が表示されないエッジのセットです。 独立したセットとは、グラフ内のエッジが選択された頂点のペアを接続しないような頂点のセットです。 

主な問題点は、グラフが大きく、スパース制約が保証されていないことです。$n$まで可能です$10^5$テスト ケースごとのエッジの合計は次のとおりです$5 \cdot 10^5$。 これにより、頂点やエッジのサブセット、さらには二次関数を列挙しようとするあらゆるアプローチが即座に除外されます。$n$。 ソリューションは、テスト ケースごとに基本的に線形または線形対数である必要があります。 

両方の構造が存在する場合、微妙なエッジケースが発生します。 たとえば、頂点が多数の互いに素なエッジと孤立したノードを形成するグラフでは、サイズの一致するセットと独立したセットの両方が存在します。$n$可能です。 この問題ではどちらの答えも許容されるため、どのような決定論的な選択戦略も受け入れられます。 

もう 1 つの重要なエッジ ケースは、グラフが非常に密な場合です。 エッジが豊富な場合、一致は見つけやすいと思われますが、独立したセットは小さくなります。 逆に、エッジが非常にまばらな場合、独立したセットは大きくなりますが、構造のマッチングが失敗する可能性があります。 解決策はどちらの体制も想定してはなりません。 

3 番目の明白ではないケースは、サイズが完全に一致しないようにグラフが構造化されている場合です。$n$独立したサイズのセットもありません$n$存在します。 公式ソリューションの構造により、このケースでは単純な矛盾チェックを超える複雑なフォールバック ロジックが必要なくなります。 

## アプローチ

 直接的な強引なアイデアは、最大一致セットと最大独立セットを個別に構築してみることです。 貪欲なマッチングを実行し、補集合から貪欲な独立セットを計算したり、DP またはフローベースの削減を介して最大独立セットの計算を試みたりすることもできます。 これらのアプローチは指数関数的であるか、NP 困難部分問題を解決する必要がありますが、これは現時点では実行不可能です。$n = 10^5$。 

重要な構造的洞察は、グラフが次のことを示しているということです。$3n$頂点ですが、必要なのはサイズの構造だけです$n$、これは頂点セットのちょうど 3 分の 1 です。 この不均衡は非常に重要です。 これは、十分に分離されたエッジを見つけることができない場合、多くの頂点が強い意味で「一致しない」ままである必要があり、これらを独立したセットに編成できることを示唆しています。 

標準的な建設的なアイデアは、貪欲にマッチングを試みることです。 選択できれば$n$接続されていないエッジが完成しました。 失敗した場合、その失敗は、前の選択によって多すぎる頂点が「ブロック」され、大規模な独立したセットが存在することを余儀なくされたことを意味します。 このアルゴリズムは、使用された頂点を注意深く追跡し、1 回のパスでいずれかの構造を抽出します。 

より深い視点は、エッジを選択するたびに利用可能な頂点が減り、一致するエッジの選択に失敗するたびに、独立したセットに寄与する補数グラフの構造が得られるということです。

 ## アルゴリズムのチュートリアル

 このソリューションは、独立したセットのフォールバックを暗黙的に準備しながら、同時にマッチングの構築を試みる単純な貪欲なプロセスを維持することを中心に構築されています。 

未使用の頂点と訪問した配列のリストを維持します。 また、隣接リストも維持します。 

### 1. 貪欲にマッチングを構築しようとする

 入力順にエッジを反復処理します。 各エッジについて$(u, v)$、両方のエンドポイントが現在使用されていない場合、このエッジをマッチングに組み込み、両方の頂点を使用済みとしてマークします。 収集するまで続行します$n$エッジを仕上げるか、すべてのエッジを仕上げます。 

これが機能するのは、有効なマッチングには互いに素なエンドポイントのみが必要であり、初期のエッジを貪欲に選択することで、後で不要な競合が回避されるためです。 

### 2. マッチングが成功した場合

 なんとか選ぶことができたら$n$エッジがあれば、すぐに出力します。 これは要件を満たします。 

### 3. マッチングに失敗した場合

 届かない場合$n$エッジ、その後、より少ない$n$グラフ内に互いに素なエッジが存在します。 これは少なくとも次のことを意味します$3n - 2(n-1)$頂点は貪欲なプロセスによって完全にペアにされていないままなので、独立したセットを形成するのに十分な構造が保証されます。 

マッチング プロセスで使用されなかったすべての頂点を取得して、独立したセットを構築します。 選択されたすべてのエッジは 2 つの頂点を消費するため、残りのセットには少なくとも次のものが含まれます。$n$頂点。 その後、任意のものを受け取ります$n$彼らのうち。 

このセットが独立していることを確認する必要があります。 この残りのセット内のエッジは、(両方のエンドポイントが使用されていないため) 早期にマッチングに利用可能であり、貪欲なマッチング プロセスの最大性と矛盾します。 

### なぜ効果があるのか

 不変条件は、欲張りマッチングが停止した後は、2 つの未使用の頂点間にエッジが存在しないことです。 そのようなエッジが存在する場合、アルゴリズムはそのエッジを処理するときにそれを選択します。 したがって、未使用の頂点のセットは、残りのグラフ内で独立したセットを形成します。 サイズに達しなかったのでマッチングに失敗しました$n$、未使用のセットには少なくとも次のものが含まれている必要があります。$n$頂点を設定し、実現可能性を確保します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n, m = map(int, input().split())
        adj = [[] for _ in range(3*n + 1)]
        edges = []

        for i in range(1, m + 1):
            u, v = map(int, input().split())
            adj[u].append((v, i))
            adj[v].append((u, i))
            edges.append((u, v))

        used = [False] * (3*n + 1)
        matching = []

        for i, (u, v) in enumerate(edges, 1):
            if not used[u] and not used[v]:
                used[u] = used[v] = True
                matching.append(i)
                if len(matching) == n:
                    break

        if len(matching) == n:
            print("Matching")
            print(*matching)
            continue

        indep = []
        for v in range(1, 3*n + 1):
            if len(indep) < n and not used[v]:
                indep.append(v)

        print("IndSet")
        print(*indep)

if __name__ == "__main__":
    solve()
```コードは最初に隣接情報を構築し、エッジを入力順に保存します。 次に、エッジ上で貪欲なスキャンを実行し、互いに素なエンドポイントを選択してマッチングを構築します。 その瞬間$n$エッジを収集して出力します。 

欲張りプロセスが失敗すると、未使用の頂点が収集されます。 重要な詳細は、最初のものだけを取得する必要があるということです。$n$未使用の頂点。正確性により、少なくとも存在することが保証されるため、$n$彼らのうち。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque

    input = sys.stdin.readline
    T = int(input())
    out = []

    for _ in range(T):
        n, m = map(int, input().split())
        edges = []
        for i in range(1, m+1):
            u, v = map(int, input().split())
            edges.append((u, v, i))

        used = [False]*(3*n+1)
        match = []

        for u, v, i in edges:
            if not used[u] and not used[v]:
                used[u] = used[v] = True
                match.append(i)
                if len(match) == n:
                    break

        if len(match) == n:
            out.append("Matching")
            out.append(" ".join(map(str, match)))

            for v in range(1, 3*n+1):
                if not used[v] and len(ind) < n:
                    ind.append(v)
            out.append("IndSet")
            out.append(" ".join(map(str, ind)))

    return "\n".join(out)

 ## 特殊なケース

 エッジのないグラフでは、アルゴリズムは一致するエッジを選択せず、すべての頂点が未使用のまま終了します。 その後、構築は単に最初の要素を取得します。$n$エッジがないことで独立性が保証されるため、有効な独立セットを形成します。 

エッジは存在するが、いくつかの頂点の周りに密集しているグラフでは、貪欲なマッチングが早期に停止する可能性があります。 たとえば、1 つの頂点が他のほぼすべての頂点に接続している場合、インシデント エッジを選択すると、その頂点に関係する今後の一致はすぐにブロックされますが、依然として未処理の頂点の大きなプールが残ります。 これらの未処理の頂点は、内部エッジが一致する候補として以前に選択されているため、有効な独立セットを形成します。 

完全なマッチングが可能なグラフでは、貪欲な選択によりエッジの順序に応じて完全なマッチングが見つかる場合と見つからない場合がありますが、見つからない場合でも、独立したサイズのセットを形成するのに十分な未使用の頂点が残っていることが保証されます。$n$。 これは、マッチングの拡張に失敗するたびに、質量を補集合にシフトする構造的冗長性に対応するという事実から導き出されます。
