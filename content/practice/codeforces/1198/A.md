 ## 解決策
 ## 問題の理解

 それぞれが非負の整数である一連の音の強度が与えられます。 これを、サンプリングされたオーディオ振幅の時系列として考えてください。 ファイルは値ごとに固定ビット数を使用して保存され、そのビット コストは、配列を変更した後に表示される個別の値の数にのみ依存します。 

間隔を選択できます$[l, r]$。 この間隔内のすべての値は変更されず、小さい値はすべて上に押し上げられます。$l$、そしてそれより大きなものはすべて下に押し下げられます$r$。 この操作により、選択したウィンドウの外側にあるものはすべてその境界に収まるため、個別の値の数が減ります。 

この変換を適用した後のストレージ コストは、残っている個別の値の数によって異なります。 あれば$K$個別の値、各要素のコスト$k = \lceil \log_2 K \rceil$ビットなので、合計ストレージは$n \cdot k$ビット。 ディスク容量はバイト単位で指定されるため、制約は次のようになります。$n \cdot k \le 8I$。 

課題は選択することです$[l, r]$これにより、変換中に変更される要素の数を最小限に抑えながら、変換された配列がディスクに収まります。 

制約は私たちを$O(n \log n)$または$O(n)$解決。 と$n$まで$4 \cdot 10^5$、すべての区間の選択肢にわたる二次関数は不可能です。$O(n^2)$候補者$[l, r]$ペア。 たとえ$O(n^2)$間隔ごとに一定の作業を行うスキャンは、時間制限をはるかに超えてしまいます。 

圧縮要件が何も変更せずにすでに満たされている場合、微妙なエッジ ケースが発生します。 元の個別の値の数が十分に小さい場合、最適な答えはゼロになります。 すべての値が同一である場合、別の特殊なケースが発生します。 その場合$K = 1$、 それで$k = 0$これは、要素ごとにゼロビットを意味し、ファイルはどのディスクにも簡単に適合します。これは、対数またはしきい値を計算するロジックで慎重に処理する必要があります。 

素朴なアプローチでは、あらゆる可能性を試みる可能性があります$[l, r]$、圧縮後に個別の値を再計算し、移動した要素の数をカウントします。 圧縮された個別の値を再計算するには毎回配列をスキャンする必要があるため、これは失敗します。$O(n^3)$行動。 

## アプローチ

 ブルートフォース戦略は概念的には単純です。間隔を固定します。$[l, r]$、圧縮をシミュレートし、間隔の外側にある要素の数 (これらは変化する要素です) を数え、クランプ後に残る個別の値の数を計算します。 次に、結果のビット数が使用可能なディスク サイズに収まるかどうかを確認します。 すべての有効な間隔の中から、変更された要素の数を最小にする間隔を選択します。 

これは、操作の定義を直接評価するため、正解です。 問題はパフォーマンスです。$O(n^2)$間隔、および各シミュレーションは$O(n)$、につながる$O(n^3)$最悪の場合は複雑になります。 と$n = 4 \cdot 10^5$、これはまったく不可能です。 

重要な観察は、配列をソートした後、$[l, r]$これは、ソートされた配列内で変更されないままの連続セグメントを選択することと同じになります。 そのセグメントの外側にあるものはすべて境界に強制的に移動されるため、変更としてカウントされます。 したがって、値の観点から考えるのではなく、並べ替えられたリストのインデックスの観点から考えます。 

次に、ストレージの制約を再解釈します。 選択したセグメント内に個別の値を正確に保持し、さらに境界が崩れる可能性がある場合、個別の値の数は最大でも次のとおりである必要があります。$M = \left\lfloor \frac{8I}{n} \right\rfloor$ビット制約として解釈される場合$k$。 以来$k = \lceil \log_2 K \rceil$、これは境界と同等です$K$、そして問題は、ウィンドウ内で最大の値を表すことができる等しい値の最大のサブセットを見つけることに帰着します。$K$独特の要素。 

並べ替えると、最適な構造は個別の値に対するスライディング ウィンドウとなり、最大でセグメント内に収まる配列要素の数を最大化します。$K$明確な価値観。 そのウィンドウの外側のすべてが変更されるため、変更を最小限に抑えることは、保持される要素を最大化することと同じです。 

したがって、問題は、ソートされた配列カウントに対する古典的な 2 ポインタになります。

 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^3)$|$O(n)$| 遅すぎる |
 | 最適 |$O(n \log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列をソートします。 並べ替えにより、等しい値が確実にグループ化されるため、分散した位置ではなく連続した構造を使用して個別の値を推論できるようになります。 
2. それぞれの個別の値の頻度を順番に数えます。 これにより、すべての等しい値はどのような間隔圧縮下でも同様に動作するため、問題は要素レベルの移動からブロック レベルの推論に軽減されます。 
3. 個別の値の最大許容数を計算します。$K_{\max}$ファイルがディスクに収まるようにします。 これは解決することから生まれます$n \cdot \lceil \log_2 K \rceil \le 8I$。 最大のものを見つけます$K$そのような$\lceil \log_2 K \rceil$要素ごとに利用可能なビットを超えません。 
4. もし$K_{\max}$が少なくとも元の配列内の個別の値の数である場合、圧縮は必要ないため、答えは 0 です。 
5. それ以外の場合は、個別の値のリストに対してスライディング ウィンドウを維持します。 各ウィンドウは、連続する値のセットを変更せずに維持することを表しますが、外側の値はすべて境界に圧縮されます。 
6. ウィンドウの右側の境界を拡張すると、ウィンドウ内の個別の値によってカバーされる要素の総数が追跡されます。 
7. ウィンドウに次の内容が表示されるたびに、$K_{\max}$個別の値がある場合は、左側の境界が再度有効になるまで縮小します。 これにより、ウィンドウが常に実行可能な保存値のセットを表すという不変条件が維持されます。 
8. 有効なウィンドウごとに、保持される要素の数を計算します。 答えは$n - \max(\text{kept})$、外側のすべてが変更されるためです。 

### なぜ効果があるのか

 重要な不変条件は、最適な間隔が存在することです。$[l, r]$は、ソートされた個別の値の連続ブロックの選択に正確に対応します。 このブロック内の要素は変更されず、外側の要素は境界の 1 つに強制されるため、必然的に変更されたものとしてカウントされます。 並べ替えでは値の順序が保持されるため、値の非連続的な選択は最適とは言えません。個別の値の数が増加するか、境界での強制的な変更が増加することになります。 したがって、最適解は、個別のグループの数に関する制約の下で、グループ化された周波数にわたる最大合計ウィンドウとして現れる必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, I = map(int, input().split())
    a = list(map(int, input().split()))
    
    a.sort()
    
    # compress into frequencies
    vals = []
    cnts = []
    
    for x in a:
        if not vals or vals[-1] != x:
            vals.append(x)
            cnts.append(1)
        else:
            cnts[-1] += 1
    
    m = len(vals)
    
    # compute max bits per element
    # need n * k <= 8I => k <= (8I) / n
    max_bits = (8 * I) // n
    
    # find max K such that ceil(log2 K) <= max_bits
    # equivalently K <= 2^max_bits
    if max_bits >= 30:
        K = m
    else:
        K = min(m, 1 << max_bits)
    
    if K >= m:
        print(0)
        return
    
    # sliding window over distinct values
    left = 0
    current = 0
    best_keep = 0
    
    for right in range(m):
        current += cnts[right]
        
        while right - left + 1 > K:
            current -= cnts[left]
            left += 1
        
        best_keep = max(best_keep, current)
    
    print(n - best_keep)

if __name__ == "__main__":
    solve()
```コードは、配列を並べ替えて、同じ値のブロックに圧縮することから始まります。 すべての決定は、多重度の位置ではなく、個別の値にのみ依存するため、これは不可欠です。 

の計算$K$ビット制約を許容される個別の値の最大数に変換します。 大型の特殊な取り扱い`max_bits`Python の整数制限を超えたシフトを回避し、制約が事実上制限的でない場合もカバーします。 

スライディング ウィンドウは個別の値を反復処理し、最大で 1 つのウィンドウを維持します。$K$独特の要素。 変数`current`ウィンドウ内に保存されている元の配列要素の数を追跡します。 右の境界を拡張すると完全なブロックが追加され、左の境界を縮小すると完全なブロックが削除され、正確性が維持されます。 

最終的な答えは、最も保存されたカウントを次の値から引きます。$n$なぜなら、最良のウィンドウの外側にあるすべての要素は圧縮ルールによって必然的に変更されるからです。

 ## 特殊なケース

 重要なエッジケースは、すべての値が同一である場合です。 ソートされた圧縮により単一のブロックが生成されるため、スライディング ウィンドウは配列全体を即座にカバーします。 個別の値は 1 つだけであるため、許可された制限に違反することはなく、アルゴリズムは正しくゼロの変更を返します。 

別のエッジケースは、ディスクが非常に小さく、1 つまたは 2 つの異なる値しか残せない場合に発生します。 この場合、スライディング ウィンドウは積極的に縮小しますが、それでも常に連続した値のブロックを考慮します。 たとえば、入力の場合`[1,2,3,4,5]`容量が非常に小さい場合、最適なウィンドウは単一値ブロックとなり、アルゴリズムは最大の周波数ブロックを正確に選択し、最も繰り返される強度を維持することで変化を最小限に抑えます。
