 ## 解決策
 ## 問題の理解

 いくつかのセルが黒で、残りのセルがすでに白であるバイナリ グリッドが与えられています。 唯一の操作は、軸に揃えられた長方形を選択し、その中のすべてのセルを白に再描画することです。 このような各操作には、高さまたは幅の大きい方に等しいコストがかかります。 目標は、選択したすべての長方形の総コストを最小限に抑えながら、すべての黒いセルを削除することです。 

この問題を微妙にしているのは、長方形が任意に重なる可能性があり、セルを複数回再描画しても害はありませんが、長方形を選択するたびにコストがかかることです。 したがって、本当の決定は、セルを一度カバーすることではなく、コスト効率の高い方法で黒のセルを長方形に分割する方法についてです。 

グリッド サイズは最大でも 50 x 50 であり、これは既に 2 次または 3 次動的計画法が妥当であることを示唆しています。 セルのサブセットにわたる指数関数はすぐには実現できませんが、可能な四角形の数が約 \(O(n^4)\) で制限されるため、部分四角形に対する区間スタイルの DP は実行可能であり、これは追加の分割ロジックで管理できるほど十分に小さいためです。 

いくつかの特殊なケースは過小評価されがちです。 グリッドに黒いセルがすでに空である場合、操作は必要ないため、答えはゼロでなければなりません。 黒いセルが単一の完全な長方形を形成する場合、その長方形を 1 回ペイントするのが最適であるため、答えは単純にその長方形のコストになります。 より欺瞞的なケースは、黒いセルが切断されたパターンを形成する場合です。たとえば、2 つの離れた単一セルです。 単純なアプローチでは、それらを 1 つの大きな長方形でカバーしようとする可能性がありますが、コストは面積ではなく最大値 (高さ、幅) に依存するため、それらを個別に扱うよりも悪い可能性があります。 

もう 1 つの失敗モードは、長方形を貪欲に拡大することが常に役立つと仮定することから発生します。 多数の白セルを含む長方形も引き続き許可されますが、利点が追加されない場合でもコストが増加するため、最適な戦略では領域を結合する価値があるかどうかを慎重に判断する必要があります。 

## アプローチ

 ブルートフォースの観点では、黒いセルを四角形で覆うあらゆる可能な方法を考え、各構成のコストを計算し、最小値を取得します。 黒セルのサブセットをしっかりと囲む「有用な」長方形のみを考慮するように制限したとしても、サブセットの数は指数関数的であり、各サブセットは多くの長方形パーティションに対応する可能性があります。 これはすぐに実行不可能になります\(n = 10\)グリッド内の一連の点を四角形に分割する方法の数が非常に急速に増加しているためです。 

重要な構造的観察は、黒いセルを境界長方形で囲み、残りの領域をより小さな部分問題に分割することによって、最適な解を再帰的に分解できるということです。 黒いセルのセットを含む最小の四角形を選択した場合、その四角形の代金を直接支払うか、行または列に沿って分割して、結果として得られる 2 つの部分四角形を個別に解決することを選択できます。 これにより、問題はサブグリッド上の古典的な間隔 DP に変わります。 

これが機能する理由は、コスト関数が黒セルの内部配置ではなく、長方形の寸法のみに依存するためです。 これにより、すべての部分長方形が自己完結型の決定単位になります。長方形を固定すると、その外側で何が起こるかは独立したものになります。 

すべての部分四角形 \((x_1, y_1, x_2, y_2)\) に対して DP 状態を定義し、その中のすべての黒いセルをクリアするための最小コストを表します。 各状態について、2 種類の答えを計算します。1 回の操作で外接する四角形全体をクリアするか、水平または垂直に分割して解を結合します。

 ## アルゴリズムのチュートリアル

 すべての部分長方形を状態として扱い、面積の大きい順に答えを計算するので、必要なときに小さな長方形がすでに解決されています。 

1. DP テーブルを定義します。`dp[x1][y1][x2][y2]`そのサブ長方形内のすべての黒いセルをクリアするための最小コストを格納します。 これにより、可能なすべての領域で決定問題が直接エンコードされます。 

2. 各四角形について、最初に黒いセルが含まれているかどうかを確認します。 そうでない場合、コストはゼロです。 これにより、不必要な作業が回避され、空の領域が寄与しないことが保証されます。 

3. 長方形が空でない場合、そのコストを次のように初期化します。`max(height, width)`、1 回の操作で長方形全体をペイントすることに相当します。 これは最も単純で有効な戦略を表します。 

4. 次に、可能なすべての行で長方形を水平方向に分割してみます。 各分割により、領域が 2 つの独立した部分問題に分割され、そのコストが追加されます。 1 回の移動で長方形全体をカバーしない最適なソリューションでは、操作間の水平方向の分離を考慮する必要があるため、このような最適な分割で DP 値を更新します。 

5. 垂直分割についても同じアイデアを繰り返し、再び左と右の部分問題を組み合わせます。 これにより、領域の軸に沿った分解をすべて探索できるようになります。 

6. 最終的な答えは次のとおりです。`dp[1][1][n][n]`、これはグリッド全体をクリアするコストを表すためです。 

重要なアイデアは、すべての最適なソリューションは完全な長方形操作を使用するか、ペイントされた構造を独立した部分に分割するカットに沿って分解できるかのいずれかであるということです。 

### なぜ効果があるのか

 この正しさは、一連の長方形ペイント操作によってグリッドが各操作の影響を受ける最大領域に分割されるという事実から得られます。 このような解決策では、分割が発生する前に一緒に処理されるセルの境界ボックスを考慮してください。 このソリューションは、境界ボックス全体を直接描画するか、操作を互いに素な部分四角形に分割するカットを実行します。 コストは操作全体にわたって加算され、互いに素な領域間では独立しているため、DP 再帰では、考えられるすべての構造分解が正確に調査されます。 長方形ベースの演算シーケンスは最初の分離カットに沿って再帰的に分解できるため、最適な解はそのような分割のシーケンスとして表現可能になることを避けることはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
grid = [input().strip() for _ in range(n)]

pref = [[0]*(n+1) for _ in range(n+1)]

for i in range(n):
    for j in range(n):
        pref[i+1][j+1] = (
            pref[i][j+1]
            + pref[i+1][j]
            - pref[i][j]
            + (1 if grid[i][j] == '#' else 0)
        )

def has_black(x1, y1, x2, y2):
    return (
        pref[x2][y2]
        - pref[x1][y2]
        - pref[x2][y1]
        + pref[x1][y1]
    ) > 0

dp = [[[ [0]*n for _ in range(n)] for _ in range(n)] for _ in range(n)]

for h in range(1, n+1):
    for w in range(1, n+1):
        for x1 in range(n - h + 1):
            x2 = x1 + h
            for y1 in range(n - w + 1):
                y2 = y1 + w

                if not has_black(x1, y1, x2, y2):
                    dp[x1][y1][x2][y2] = 0
                    continue

                best = max(h, w)

                for k in range(x1 + 1, x2):
                    best = min(best,
                               dp[x1][y1][k][y2] + dp[k][y1][x2][y2])

                for k in range(y1 + 1, y2):
                    best = min(best,
                               dp[x1][y1][x2][k] + dp[x1][k][x2][y2])

                dp[x1][y1][x2][y2] = best

print(dp[0][0][n][n])
```この実装では、3D プレフィックス合計を利用して、サブ四角形に黒のセルが含まれているかどうかを迅速にチェックします。 そうしないと、すべての DP 遷移で長方形のスキャンが必要になり、複雑さが不必要に増加するため、これは不可欠です。 

DP テーブルはサブ四角形の座標によってインデックスが付けられ、すべての分割がすでに計算された小さな四角形のみを参照するようにサイズを増やすことを繰り返します。 初期値`max(h, w)`1 回の動作で領域全体をペイントするコストをエンコードし、すべての分割トランジションでそれを改善しようとします。 

座標の境界には注意が必要です。DP は半開間隔を使用します。`[x1, x2)`そして`[y1, y2)`これにより、分割時のオフバイワンの混乱が回避されます。

 ## 特殊なケース

 完全に空のグリッドは、すべての四角形のコストがゼロである DP 基本ケースをトリガーします。 アルゴリズムはプレフィックスの合計によってこれをチェックするため、すべての部分四角形には即座にゼロが割り当てられ、不要な再帰や更新が防止されます。 

大きなグリッド内に単一の黒いセルがあると、アルゴリズムは 2 つの戦略を比較することを強制します。それは、大きな四角形の料金を支払うか、セルが分離されるまで再帰的に分割するかです。 DP は単一セルの四角形を正しく優先します。`max(1,1) = 1`あらゆる分割を支配します。 

黒セルの薄い水平または垂直ストリップにより、直交軸に沿った分割が最適になります。 一方の方向では常にゼロコストの部分四角形が生成され、もう一方の方向では最小限の四角形コストが蓄積され、線に沿った分解に向けて DP が正しく導かれるため、アルゴリズムはこれを処理します。
