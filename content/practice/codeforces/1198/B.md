 ## 解決策
 ## 問題の理解

 私たちは、一定の国民の動的な残高リストを維持しています。 当初、各国民は既知の金額を持っています。 その後、一連のイベントにより、これらのバランスが 2 つの異なる方法で変更されます。 

最初のタイプのイベントは、あたかもレシートがその人の現在のお金に関する知識を上書きするかのように、特定の国民の残高を正確な値に直接設定します。 2 番目のタイプのイベントは、世界的な政府の行動です。残高が所定のしきい値を厳密に下回っているすべての国民はそのしきい値まで引き上げられますが、すでにしきい値以上の国民は変更されません。 

すべてのイベントを処理した後の出力は、単に各国民の最終的なバランスになります。 

主な問題は、グローバル アップデートが一度に多くの国民に影響を与える可能性があり、最大 200,000 件のイベントが発生する可能性があることです。 グローバルな更新ごとにすべての国民をスキャンする単純なアプローチでは、最悪の場合、最大 400 億回の操作が必要になりますが、これは 2 秒の制限をはるかに超えています。 これにより、更新ごとに完全な配列を再計算するソリューションは即座に除外されます。 

個人更新とグローバル更新を組み合わせると、微妙な問題が発生します。 グローバル操作によって市民が増加し、後で直接更新を受け取るとします。 注意しないと、古いグローバル操作を誤って「再適用」したり、新しい値を古い値で上書きしたりする可能性があります。 たとえば、グローバル イベントによって市民が 10 に引き上げられ、その後明示的に 5 に設定された場合、最小しきい値のみを追跡する単純な実装では、誤って最大 10 に戻されてしまいます。 

もう 1 つのエッジ ケースは、しきい値を減少させながらグローバル操作を繰り返すことです。 位置ごとの更新の順序と永続性を明示的に処理しない限り、最大しきい値に関する単純な単調な仮定は失敗します。 

## アプローチ

 ブルート フォース シミュレーションでは、各イベントが直接適用されます。 しきい値 x のタイプ 2 イベントの場合、すべての国民をスキャンし、値が x 未満の住民を更新します。 これは正しいですが、コストがかかります。このような各操作には O(n) のコストがかかり、q が 200,000 までの場合、総コストは O(nq) となり、大きすぎます。 

重要な観察は、グローバル更新では値が上昇するだけであり、それらはしきい値に基づいているということです。 これは、国民の価値が一定のレベルを超えて上昇すると、それをさらに低い閾値で再検討する必要がないことを示唆しています。 ただし、個々の更新により国民の価値が下方にリセットされる可能性があるため、単純に全体的な最大値を維持することはできません。 

秘訣は、イベントを逆方向に処理することです。 タイムラインを逆にすると、タイプ 2 のイベントは「将来の値は少なくとも x でなければならない」となり、タイプ 1 のイベントは、以前の制約をオーバーライドする可能性がある既知の最終割り当てになります。 逆方向に作業すると、最新の直接割り当てを尊重しながら、将来のグローバル更新によって課せられる最良の下限を各国民に対して計算することができます。 

これを正確にするために、実行値を維持します。`mx`これまでに逆処理で確認された最大しきい値を表します。 グローバルアップデートに遭遇すると、アップデートします`mx`。 市民 p に対する個人的な割り当てに遭遇したとき、その市民がまだ最終決定されていない場合は、それらを割り当てます。`max(a[p], mx)`。 

その洞察は、私たちが国民の最終的な価値を決定したら、以前の出来事はもはや彼らにとって重要ではないということです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nq) | O(n) | 遅すぎる |
 | Max Tracking による逆処理 | O(n + q) | O(n + q) | 承認済み |

 ## アルゴリズムのチュートリアル

 イベントを逆の順序で処理することで、グローバル制約が配列スキャンを繰り返すのではなく、累積された下限になるようにします。 

1. すべての初期値を読み取り、すべてのイベントを保存します。 
2. 配列を初期化する`ans`各国民に「割り当てられていない」ものとして。 
3. 変数を維持する`mx = 0`、これまでに発生したグローバル イベントの最大しきい値を逆に保存します。 
4. 最後から最初までイベントを繰り返します。 
5. イベントがしきい値のあるグローバル更新の場合`x`、 セット`mx = max(mx, x)`。 これは、後で決定する値が少なくともこの最小要件を満たさなければならないことを表します。 
6. イベントが市民の個人的な近況報告である場合`p`価値のあるもの`x`、この住民はまだ割り当てられていないため、設定されます。`ans[p] = max(x, mx)`。 これにより、直接割り当てと、将来の (元の順序での) すべてのグローバル制約の両方が確実に尊重されます。 
7. すべてのイベントを処理した後、まだ割り当てられていない国民は、`max(a[i], mx)`。 

これが機能する理由は、各国民は、最初に彼らの最新の割り当てを逆の順序で検出した瞬間に、一度だけ完了するためです。 この時点で、元のタイムラインでの割り当ての後に発生するすべてのグローバル制約はすでに蓄積されています。`mx`。 

### なぜ効果があるのか

 不変条件は、イベントを逆に処理するとき、`mx`元のタイムラインの現在の時点の後に発生するすべてのタイプ 2 操作の最大しきい値と常に等しくなります。 したがって、市民の価値を最終決定するときは、最後の直接割り当て後に、市民に影響を与えるすべてのグローバル更新を正しく適用します。 国民ごとに 1 回だけ割り当てるため、関連するすべての制約をすでに考慮した値を上書きすることはなく、今後のステップでその値が無効になることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))
q = int(input())

events = []
for _ in range(q):
    parts = list(map(int, input().split()))
    events.append(parts)

ans = [-1] * n
mx = 0

for e in reversed(events):
    if e[0] == 2:
        mx = max(mx, e[1])
    else:
        _, p, x = e
        p -= 1
        if ans[p] == -1:
            ans[p] = max(x, mx)

for i in range(n):
    if ans[i] == -1:
        ans[i] = max(a[i], mx)

print(*ans)
```実装の中核はリバース スイープです。 フルスキャンを繰り返す必要があるため、今後の更新のシミュレーションは行いません。 代わりに、グローバル操作を、蓄積された永続的な制約として扱います。`mx`。 

微妙な点は、`ans`-1で。 これにより、順方向では、後の割り当てが以前の割り当てを上書きするという事実と一致し、逆順の最新の割り当てのみが使用されることが保証されます。 

最後に、初期配列は直接割り当てイベントを決して受け取らない市民にのみ使用されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + q) | 各イベントは 1 回逆方向に処理され、各国民は最大 1 回だけ終了します。 
| スペース | O(n + q) | イベントと結果配列のストレージ |

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))
    q = int(input())
    events = [list(map(int, input().split())) for _ in range(q)]

    ans = [-1] * n
    mx = 0

    for e in reversed(events):
        if e[0] == 2:
            mx = max(mx, e[1])
        else:
            _, p, x = e
            p -= 1
            if ans[p] == -1:
                ans[p] = max(x, mx)

    for i in range(n):
        if ans[i] == -1:
            ans[i] = max(a[i], mx)

    return " ".join(map(str, ans))

# provided sample
assert run("""4
1 2 3 4
3
2 3
1 2 2
2 1
""") == "3 2 3 4"

# all equal, only global
assert run("""3

2 7
""") == "10 10 10"

# only personal updates
assert run("""3

""") == "1 10 7"

# minimum size

""") == "5"

 | すべて等しいグローバル | 10 10 10 | 繰り返される世界的支配 |
 | 個人的な更新のみ | 混合 | 上書き処理 |

 | 単一要素 | 5 | 境界の正確性 |

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、シチズンが複数回更新され、転送時間内の最も早い更新のみが最終状態として重要になる場合です。 逆の処理では代入するので自然に処理されます。`ans[p]`一度だけ。 

考慮する：```
3
1 1 1
3
1 1 5
1 1 2
2 10
```逆の順序:

 - グローバル 10 セット mx = 10
 - 人物 1 に対して最初に見つかった割り当ては、ans[0] = 10 を設定します。 
- 以前の割り当ては無視されます

 アルゴリズムは正しく次の値を返します。```
10 1 1
```もう 1 つのエッジケースは、個人的な更新が行われない場合です。 その場合、すべての値は、シーケンス内の任意の場所で見られる最大グローバルしきい値まで単純に引き上げられます。 以来`mx`すべてのタイプ 2 イベントを集約すると、最後の割り当てステップでそれがすべての国民に均一に正しく適用されます。
