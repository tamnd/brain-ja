 ## 解決策
 ## 問題の理解

 基本文字列が与えられています$s$そしてパターン文字列$t$、どちらも小文字で構成されています。 タスクは、各クエリが次のことを尋ねる、多くの独立したクエリに答えることです。$s$、何回ですか$t$連続した部分文字列として表示されますか?

 これについて考えるのに役立つ方法は、次のことです。$s$～の発生の始まりとなる可能性があります$t$。 ただし、クエリの場合は、$[l, r]$、私たちは星だけを数えます$i$完全に一致するように$s[i..i+m-1]$完全にクエリ範囲内にあります。 

制約は、非常に特殊な方法で解空間を形成します。 文字列の長さ$n, m \le 1000$十分に小さいため、すべての可能な位置合わせをチェックできます。$s$そして$t$実現可能です。 一方でクエリ数は$q \le 10^5$十分な大きさであるため、クエリごとの一致を再計算するとすぐに TLE になります。 これにより、前処理を繰り返すという古典的な分離が作成されます。$s$安価ですが、クエリごとの作業が必要です$O(1)$または対数。 

クエリごとの総当たり攻撃では、部分文字列内のすべての位置が試行され、比較されます。$t$、原価計算$O(n \cdot m)$最悪の場合、クエリごとに。 と$10^5$クエリを実行すると、非常に遅くなります。 

一般的な微妙な失敗のケースは、一致境界がクエリのエッジを横切るときに発生します。 たとえば、次の場合$s = \texttt{aaaaa}$そして$t = \texttt{aaa}$、オカレンスは位置 1、2、および 3 から始まります。$[2,4]$、2 と 3 で始まるもののみが有効ですが、境界条件を検証せずに完全一致をチェックする単純な部分文字列スキャンでは、クエリ範囲外にある場合でも、1 で始まる一致が誤ってカウントされる可能性があります。 

もう 1 つのエッジケースは次のような場合です$m = 1$。 次に、以下に等しいすべての文字$t$これは有効な現象であり、問​​題は範囲内の文字をカウントすることに帰着します。 を想定したソリューション$m > 1$次のようなインデックス計算により、ここで中断されることがよくあります。$r - m + 1$。 

## アプローチ

 直接的なアプローチは簡単です。クエリごとに、すべての位置をスキャンします。$i$から$l$に$r$、どうかを確認してください。$s[i..i+m-1] = t$。 これは、発生の定義に直接従うため、正しいです。 ただし、各小切手には費用がかかります$O(m)$、そして、あります$O(n)$クエリごとに可能な開始位置により、$O(nm)$クエリごとに、$O(qnm)$全体的に見て、それは不可能です。 

重要な点は、有効な一致の構造がクエリに依存しないことです。 かどうか$t$位置で一致します$i$どのクエリからも独立しています。 それはのみに依存します$s$そして$t$。 これは、バイナリ配列を事前計算できることを意味します$ok[i]$、 どこ$ok[i] = 1$もし$t$位置から開始して発生します$i$、それ以外の場合は 0。 

これが完了すると、各クエリはこの配列に対する範囲合計クエリに縮小されます。 プレフィックスの合計を使用すると、次の各クエリに答えることができます。$O(1)$。 文字列マッチングからプレフィックス合計への変換により、依存関係が排除されます。$q$。

 | --- | --- | --- | --- |
 | ブルートフォース |$O(q \cdot n \cdot m)$|$O(1)$| 遅すぎる |
 | 事前計算 + プレフィックスの合計 |$O(n \cdot m + q)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 この問題を静的マーキング + プレフィックス合計クエリ問題に変換します。 

1. インデックスごとに$i$から$1$に$n - m + 1$、部分文字列かどうかを確認します$s[i..i+m-1]$等しい$t$。 

このステップでは、クエリとは独立して、パターンの有効な開始位置をすべて識別します。 
2. アレイを構築する$ok$長さの$n$、 どこ$ok[i] = 1$試合が開始される場合$i$、それ以外の場合は 0。 

有効な開始位置のみを定義します。$n-m+1$、それを超えると完全な一致は不可能になるためです。 
3. プレフィックス合計配列を構築する$pref$、 どこ$pref[i] = pref[i-1] + ok[i]$。 

これにより、一定時間内の任意の間隔に一致するものがいくつあるかをカウントすることができます。 
4. 各クエリについて$[l, r]$、答えを次のように計算します。$pref[r-m+1] - pref[l-1]$ただし、次の場合に限ります。$r-m+1 \ge l$。 それ以外の場合、答えは 0 です。 

この条件により、全長がクエリ範囲内に収まる出現のみがカウントされるようになります。 

重要な詳細は適切な境界です$r - m + 1$。 これを超える開始位置があると、次の範囲を超える部分文字列が生成されます。$r$, したがって、除外する必要があります。 

### なぜ効果があるのか

 正しさは、次のことが起こるすべての事実に依存します。$t$開始位置によって一意に決定されます。 すべての有効な開始インデックスを事前計算すると、すべてのクエリは固定バイナリ配列に対するカウント問題になります。 プレフィックスの合計は、一定の間隔にわたって正確なカウントを保持し、制約は$i + m - 1 \le r$適切なエンドポイントを次のように制限することで適用されます。$r - m + 1$。 これにより、オカレンスが部分的にカウントされたり、見逃されたりすることがないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n, m, q = map(int, input().split())
    s = input().strip()
    t = input().strip()

    if m > n:
        # pattern longer than text, no matches possible
        for _ in range(q):
            input()
            print(0)
        return

    ok = [0] * n

    for i in range(n - m + 1):
        if s[i:i + m] == t:
            ok[i] = 1

    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + ok[i]

    out = []
    for _ in range(q):
        l, r = map(int, input().split())
        l -= 1
        r -= 1

        right = r - m + 1
        if right < l:
            out.append("0")
        else:
            out.append(str(pref[right + 1] - pref[l]))

    print("\n".join(out))

if __name__ == "__main__":
    main()
```前処理ループは、可能なすべてのアラインメントを明示的にチェックします。$t$で$s$。 どちらの文字列も十分に小さいため、これは安全です。$O(nm)$チェックは許容されます。 

プレフィックス配列は、範囲合計を計算する際の off-by-one の問題を回避するために、標準の 1 インデックス形式で構築されています。 各クエリはゼロベースのインデックスに変換され、有効な終了位置をクランプします。$r - m + 1$。 

微妙な実装の詳細は、次のような場合の処理​​です。$r - m + 1 < l$これは、完全なオカレンスがクエリ間隔内に収まらないことを意味します。 このチェックを行わないと、プレフィックスの減算により無効な範囲にアクセスしたり、オーバーカウントが発生したりする可能性があります。

 ## 特殊なケース

 パターンの長さがクエリ セグメントの長さを超える場合、アルゴリズムは正しくゼロを生成します。$r - m + 1$よりも小さくなる$l$、早期拒否条件がトリガーされます。 たとえば、次の場合$s = \texttt{abcde}$、$t = \texttt{abc}$、クエリは$[4,5]$、 それから$r - m + 1 = 3$より小さい$l = 4$, したがって、答えは正しく 0 です。 

のために$m = 1$、すべての一致は、次の 1 つの文字に正確に対応します。$s$。 前処理ステップでは、各インデックスにマークを付けます。$s[i] = t[0]$、プレフィックス合計は、変更せずに任意の範囲内の出現を正確にカウントします。
