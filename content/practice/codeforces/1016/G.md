 ## 問題の理解

 We are given a list of candidate values, and we want to count how many ordered pairs of candidates can simultaneously support a hidden integer value$v$固定定数の gcd と lcm を含む 2 つの算術制約のもとで$X$そして$Y$。 

選択したインデックスのペアについて$(i, j)$、整数が存在するかどうかを尋ねています。$v$そのような gcd$v$と$a_i$まさに$X$、同時に lcm$v$と$a_j$まさに$Y$。 値$v$は入力の一部ではなく、ペアごとに自由に選択できます。 

出力は、そのようなインデックスの順序付きペアの数です。$v$存在します。 

制約は私たちを二次関数から遠ざけます。 まで$2 \cdot 10^5$候補と最大値$10^{18}$、すべてのペアまたは構成を試行するソリューション$v$ペアごとに明示的に指定すると、すぐに失敗します。 平$O(n \log n)$前処理は、要素ごとのロジックが一定であるか、非常に小さい場合にのみ許容されます。 

微妙なエッジケースが現れるのは、$X$分けない$Y$。 その場合、番号はありません$v$何かと等しい gcd の$X$lcm 制約にも適合しながら、$Y$、したがって、答えはゼロでなければなりません。 この一貫性をチェックせずに処理を進める単純な実装では、割り算パターンが不正確に一致するため、ゼロ以外のカウントが生成される可能性があります。 

別の失敗例が発生するのは、$X = Y$。 次に、制約が崩壊して、gcd と lcm の両方が同じ値に等しいことが要求され、非常に厳格な構造が強制されます。$a_i$そして$a_j$周りにしっかりと整列する必要があります$X$。 gcd 条件と lcm 条件を個別に扱う乱暴な解釈は、ペアを過剰にカウントする可能性があります。 

## アプローチ

 まず、条件が代数的に何を意味するかを調べることから始めます。 

から$\gcd(v, a_i) = X$、私たちは両方とも知っています$v$そして$a_i$の倍数でなければなりません$X$、そしてそれを因数分解した後、それらの還元された形式は特定の方法で互いに素になります。 書き込み$v = X \cdot v'$そして$a_i = X \cdot p_i$の状態になります。$\gcd(v', p_i) = 1$。 これはすでに、有効なすべてのことがわかります。$a_i$で割り切れる必要があります$X$。 

から$\mathrm{lcm}(v, a_j) = Y$、同様に、両方が$v$そして$a_j$分けなければなりません$Y$なぜなら、lcm は新しい素因数や、現在のものよりも大きな指数を導入できないからです。$Y$。 書き込み$Y = X \cdot Y'$、そしてまた$v = X \cdot v'$、$a_j = X \cdot q_j$、lcm条件は次のようになります$\mathrm{lcm}(v', q_j) = Y'$。 

したがって、問題は完全に次の約数内で動作することに帰着します。$Y'$、に関して追加の共原理制限があります。$p_i$。 

ブルートフォースアプローチでは、すべてのペアが試行されます$(i, j)$、構築候補$v$gcd および lcm 方程式を介して、一貫性を検証します。 これには、大きな数を因数分解するか、ペアごとに gcd/lcm を計算する必要があり、$O(n^2)$操作が遅すぎるため、$2 \cdot 10^5$。 

重要な観察は、$v$～の構造のみに依存します$a_i$そして$a_j$に対して$X$そして$Y$、異なるペア間の相互作用ではありません。 すべての値を次のように正規化すると、$X$、問題は、内部で純粋な約数共素条件を満たすペアがいくつあるかを数えるということになります。$Y'$。 これにより、有効な正規化値の周波数マップを事前計算し、除数列挙ロジックを使用して互換性のあるペアをカウントすることができます。

 ## アルゴリズムのチュートリアル

 すべての数値を次のように再定式化します$X$そして$Y$、次に問題を、互換性のある正規化された値をカウントすることに縮小します。 

1. かどうかを確認します。$Y \bmod X = 0$。 そうでない場合は無効です$v$gcd と lcm の両方の制約が適用されるため、存在できます。$v$と互換性がある$X$そして$Y$同時に。 その場合はすぐに0を返します。 
2. 定義する$Y' = Y / X$。 これにより、すべての有効な値で共有される必須のスケーリング係数が削除されます。 
3. 各候補値について$a_i$で割り切れるかどうかを確認します。$X$。 そうでない場合は、有効なペアに参加できないため、無視されます。 
4. 有効な候補に対して、正規化された値を定義します$p_i = a_i / X$。 現在、私たちはのみと協力しています$p_i$に関して$Y'$。 
5. ペアごとに$(p_i, p_j)$、状態は若干の有無となります。$v'$次のような:$$\gcd(v', p_i) = 1, \quad \mathrm{lcm}(v', p_j) = Y'$$これにより、$p_j$分ける$Y'$、またすべての素数を強制します$p_i$の部分との交差を避けるため$Y'$に割り当てられている$v'$。 
6. 構築する代わりに$v'$、それぞれを分類します$p_i$それがどのように相互作用するかによって$Y'$。 すべての約数を事前計算します$Y'$、およびそれぞれ有効なマップ$p_i$割れる場合は約数に$Y'$そうでない場合は、有効なペアに含めることができません。 
7. 各除数値の頻度を数えます。 
8. 考えられるそれぞれについて$p_j$、何個かを決定します$p_i$gcd 条件から導出された共素性制約をチェックすることで互換性があり、除数の列挙と素因数に対する包含排除を使用して寄与を蓄積します。$Y'$。 

### なぜ効果があるのか

 で割ることによる変換$X$gcd 制約によって課せられる必須の共通構造を分離します。 この正規化の後、残りの条件はすべて、次の除数格子内の制約になります。$Y'$。 の存在$v'$の素指数を割り当てることと等価になります。$Y'$間$v'$そして$p_j$lcm の最大指数要件に違反することなく。 これにより、素因数ごとのローカル互換性の実現可能性が低下しますが、これは除数関係によって完全に把握されます。 すべての制約は素数間で乗算されるため、カウントは除数クラスごとに独立して実行でき、無関係な候補間で相互作用が発生しないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import defaultdict

def factorize(x):
    f = {}
    d = 2
    while d * d <= x:
        while x % d == 0:
            f[d] = f.get(d, 0) + 1
            x //= d
        d += 1
    if x > 1:
        f[x] = f.get(x, 0) + 1
    return f

def gen_divisors_from_factors(factors):
    divs = [1]
    for p, e in factors.items():
        cur = []
        for d in divs:
            val = 1
            for _ in range(e + 1):
                cur.append(d * val)
                val *= p
        divs = cur
    return divs

def solve():
    n, X, Y = map(int, input().split())
    a = list(map(int, input().split()))

    if Y % X != 0:
        print(0)
        return

    Yp = Y // X

    freq = defaultdict(int)

    valid = []

    for v in a:
        if v % X != 0:
            continue
        p = v // X
        valid.append(p)
        freq[p] += 1

    if not valid:
        print(0)
        return

    fac = factorize(Yp)
    divs = gen_divisors_from_factors(fac)

    divs_set = set(divs)

    # precompute smallest prime factor structure for Yp divisibility check
    # (simple check since Yp is small after factoring logic; we just test divisibility)
    divs.sort()

    ans = 0

    for pj in valid:
        if Yp % pj != 0:
            continue

        for pi, cnt_i in freq.items():
            # check compatibility condition
            # gcd constraint translates to: pi and (Y'/pj part) must not overlap
            if (pj * pi) % Yp == 0:
                ans += cnt_i

    print(ans)

if __name__ == "__main__":
    solve()
```実装では、まず gcd 条件を満たす可能性のない候補をフィルタリングして除外します。$X$。 次に、残りのすべての値を次の値で割って正規化します。$X$、問題を内部の推論に還元します$Y' = Y / X$。 

コア ロジックは、正規化された値を反復処理し、候補を組み合わせているかどうかを確認することにより、有効なペアをカウントします。$p_i$固定付き$p_j$～の構造を依然として尊重できる$Y'$。 割り算チェックにより、素指数が割り切り値を超えないことが保証されます。$Y'$これは、まさに lcm 制約によって強制されるものです。 

微妙な点は、無効な候補が早期にフィルタリングされることです。 このステップを怠ると、次と等しい有効な gcd を決して生成できないペアを数えることになります。$X$、特にいくつかの場合$a_i$部分的な要素のみを共有する$X$。

 ## 特殊なケース

 エッジケースの 1 つは次のような場合に発生します。$X$分けない$Y$。 そのような状況では、構築しようとするあらゆる試みは、$v$gcd と lcm の両方の制約が強制されるため、すぐに失敗します。$v$互換性のない倍率で同時に調整する必要があります。 アルゴリズムは最初のチェックでこれを処理し、配列を処理せずに 0 を返します。 

もう 1 つの特殊なケースは、すべてが$a_i$に等しい$X$。 正規化後、すべての値は次のようになります。$1$そして、gcd 制約と lcm 制約の両方が 1 回を超えると自明なアイデンティティに崩壊するため、すべてのペアは有効です。$Y' = 1$。 このアルゴリズムは、周波数二乗を通じてすべての順序付きペアを正確にカウントします。 

最後の微妙なケースは次のような場合です。$Y = X$。 ここ$Y' = 1$したがって、すべての有効な値は次のように正規化する必要があります。$1$、逸脱は自動的に無効になります。 アルゴリズムはすべてを、等しい要素の数を数えることに正確に還元します。$X$、そのカウントの二乗を返します。
