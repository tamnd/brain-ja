 ## 解決策
 ## 問題の理解

 このタスクは、固定された負の高さで水平に移動する点光源と、障害物として機能する X 軸上にある一連の独立したセグメントを中心に展開します。 平面内の各クエリ ポイントについて、光源が左から右に移動する間に、その点を光源に接続するセグメントが少なくとも 1 つのフェンス セグメントと交差する時間を測定するように求められます。 

幾何学的にクエリポイントを修正します$P = (x, y)$。 いつでも$t$、ライトは次のとおりです$S(t) = (t, s_y)$から直線的に移動します。$a$に$b$単位速度で。 ポイントは時間的にシェーディングされているとみなされます$t$セグメントの場合$PS(t)$フェンスを表す X 軸上の任意の間隔と交差します。 

制約が十分に大きいため、クエリごとにすべてのセグメントを反復するソリューションは直ちに実行不可能になります。 まで$2 \cdot 10^5$セグメントとクエリでは、クエリごとのリニア スキャンでも、おおよその結果が得られます。$4 \cdot 10^{10}$これは 2 秒の制限をはるかに超えています。 

重要な幾何学的なエッジケースは、セグメントの投影時に現れます。$PS(t)$フェンス間隔の終点にかろうじて触れます。 これも日陰時間としてカウントされます。 もう 1 つの微妙なケースは、点が x 軸よりはるかに上にある場合で、交差動作は時間的にはほぼ線形になりますが、代数的に処理しないと浮動小数点誤差の影響を受けやすくなります。 

主な困難は、「セグメントが x 軸上の一定の間隔と交差する」という条件が時間に継続的に依存するものの、空間間隔の結合によって定義されることです。 

## アプローチ

 直接シミュレーションでは、各クエリ ポイントと各フェンス セグメントに対して一連の時間を決定しようとします。$t$クエリのセグメントが次を指しているとき$S(t)$そのフェンスセグメントと交差します。 これにより、最大で$O(n)$クエリごとの時間間隔。 各間隔の計算は簡単ですが、それらの結合にはソートとマージが必要となり、各クエリが作成されます。$O(n \log n)$が鈍くなるにもほどがあります。 

構造的なブレークスルーは、交差条件が本質的に一時的なものではないことを観察することから生まれます。 からのセグメント$P$に$S(t)$単一点で X 軸と交差し、その X 座標は直線的に移動します。$t$。 時間内で直接作業する代わりに、この交点が x 軸に沿ってどのように移動するかを追跡できます。 

その形式で書き直されると、各クエリは、x 軸上の固定間隔が、互いに素なセグメントの固定結合とどの程度重複するかを測定することになります。 これは、クエリ ポイントごとに 1 つの範囲クエリを使用する純粋な 1 次元の間隔の問題です。 

これにより、問題が動的幾何学から静的区間演算に変換されます。

 ## アルゴリズムのチュートリアル

 クエリポイントを修正する$P = (x, y)$。 セグメント間の交差の x 座標がどのように変化するかを分析します。$P S(t)$x 軸は次のように移動します。$t$変化します。 

1. セグメントの交差パラメータを計算します。$P S(t)$どこ$y = 0$。 

垂直座標は次から直線的に変化します。$y$に$s_y$したがって、セグメントが x 軸に当たる部分は一定です。$$\lambda = \frac{y}{y - s_y}$$この値は次のものには依存しません$t$、これが重要な構造の簡素化です。 
2. 交点の x 座標を次の関数として表します。$t$。 

セグメントは両方の座標で線形であるため、交差する x 座標は次のようになります。$$x_{\text{int}}(t) = x + \lambda (t - x)$$これはアフィン関数です。$t$したがって、厳密に増加します。$\lambda \in (0,1)$。 
3. 動作間隔全体をマッピングします。$[a, b]$X空間に。 

エンドポイントを評価します。$$L_x = x_{\text{int}}(a), \quad R_x = x_{\text{int}}(b)$$問題は、間隔がどのくらいかを測定することになります。$[L_x, R_x]$X 軸上のフェンス セグメントの結合と重なります。 
4. フェンスセグメントをソートされた素結合として前処理します。 

セグメントはすでに重複しておらず、ソートされているため、分割された間隔の結合を直接表します。 
5. クエリごとに、交差する最初と最後のセグメントを見つけます。$[L_x, R_x]$。 

これは、セグメントのエンドポイントで二分検索を使用して行われます。 セグメントは互いに素であるため、交差するすべてのセグメントは連続したブロックを形成します。 
6. 境界セグメントと完全に含まれるセグメントからのオーバーラップ寄与を計算します。 

中央のブロックはセグメント全体の長さに寄与します。 2 つの境界セグメントは、次の方法で部分的にクリップされる可能性があります。$[L_x, R_x]$。 
7. x-length を時間に変換します。 

以来$x_{\text{int}}(t)$の係数で変化します$\lambda$、時間は次のようにスケールされます。$1/\lambda$:$$\text{answer} = \frac{\text{x-overlap length}}{\lambda}$$### なぜ効果があるのか

 重要な不変条件は、時間からのマッピングが$t$交点の x 座標への変換は、モノトーン アフィン変換です。 これにより、順序が確実に保持されます。つまり、時間の間隔は、歪みやオーバーラップの反転なしに X 空間の間隔に正確に対応します。 このため、シェーディング時間を測定することは、x 空間で幾何学的な長さを測定し、一定の係数でスケーリングすることと同等です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    sy, a, b = map(int, input().split())
    n = int(input())
    segs = [tuple(map(int, input().split())) for _ in range(n)]
    
    l = [s[0] for s in segs]
    r = [s[1] for s in segs]

    q = int(input())
    queries = [tuple(map(int, input().split())) for _ in range(q)]

    for x, y in queries:
        lam = y / (y - sy)

        x1 = x + lam * (a - x)
        x2 = x + lam * (b - x)
        L = min(x1, x2)
        R = max(x1, x2)

        # find first segment with r >= L
        lo, hi = 0, n - 1
        left = n
        while lo <= hi:
            mid = (lo + hi) // 2
            if r[mid] >= L:
                left = mid
                hi = mid - 1
            else:
                lo = mid + 1

        # find last segment with l <= R
        lo, hi = 0, n - 1
        right = -1
        while lo <= hi:
            mid = (lo + hi) // 2
            if l[mid] <= R:
                right = mid
                lo = mid + 1
            else:
                hi = mid - 1

        if left > right:
            print(0.0)
            continue

        total = 0.0

        for i in range(left, right + 1):
            total += max(0.0, min(r[i], R) - max(l[i], L))

        ans = total / lam
        print(f"{ans:.12f}")

if __name__ == "__main__":
    solve()
```コードはまず、各クエリを X 軸上の等価な間隔に変換します。 次に、二分探索を使用して、どのフェンス セグメントがこの間隔と交差するかを特定します。 残りの作業は純粋に区間のオーバーラップの計算です。 最後に、定数導関数係数を使用して、累積された x 長さを時間にスケールバックします。 

微妙な実装ポイントは、浮動小数点除算の処理です。$\lambda$。 すべての変換は線形であり、比率のみが必要であるため、必要な誤差許容範囲内では倍精度で十分です。 

## 実用的な例

 ### 例 1

 クエリ点と変換された区間を考慮します。$[L, R]$X 軸上。 

| ステップ | 値 |
 | --- | --- |
 | λ | を計算します。 ジオメトリからの固定定数 |
 | L、Rを計算する | [a, b] の画像 |
 | セグメント範囲を検索 | 二分探索経由 |
 | 合計オーバーラップ | ユニオン交差点 |

 このトレースは、投影された間隔と交差するセグメントのみが重要であることを示しています。 他のものはすべて、元の時間の影響に関係なく無関係です。 

### 例 2

 軸より高い点は非常に小さな λ を生成します。これは、x の動きが時間に対して遅いことを意味します。 

| ステップ | 値 |
 | --- | --- |
 | λ 小さい | 交差点は x 内でほとんど移動しません |
 | [L, R] 圧縮 | 狭い間隔 |
 | 重複はほとんどありません | 近くのセグメントのみが寄与する |

 これは、組み合わせ構造を変更することなく、λ によるスケーリングが垂直位置を正しく調整することを示しています。

 ## 特殊なケース

 境界に接触する構成は、投影された間隔の終点がフェンスの終点と正確に等しい場合に発生します。 このような状況でも、交差の長さには幅がゼロの接触が含まれるため、オーバーラップの式ではそれがカウントされます。 アフィン変換では等価性が維持されるため、このような場合は特別なケースを使用せずに時間と x 空間の間で一貫してマッピングされます。 

2 番目のエッジ ケースは、投影された間隔全体がすべてのセグメントの外側にある場合に発生します。 二分探索では空の範囲が得られ、アルゴリズムは累積ループに入らずに正しくゼロを返します。
