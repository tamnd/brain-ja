 ## 解決策
 ## 問題の理解

 原点から点まで長方形を形成する整数グリッド内で作業しています。$(n,m)$。 この長方形の内側または境界線上にある 3 つの格子点を選択し、面積が正確に次のとおりの三角形を形成する必要があります。$\frac{nm}{k}$。 出力は、選択した 3 つの点の座標とともにそのような三角形が存在することを確認するか、それは不可能であるという声明です。 

ジオメトリは離散的です。すべての点は整数の座標を持ち、すべての座標は境界ボックス内に収まる必要があります。 主な困難は、面積がわかったら三角形を構築することではなく、その面積が制約された整数グリッド内に収まる構成で表現できるようにすることです。 

制約は非常に大きく、$n,m,k$まで$10^9$。 これにより、点を列挙したり幾何学的に検索しようとするアプローチは即座に排除されます。 すべての候補の底辺または高さを反復処理することさえ不可能です。 解決策では、問題を少数の算術チェックと、せいぜい一定の構築試行に減らす必要があります。 

目的の領域が次の整数倍ではない場合、微妙なエッジ ケースが発生します。$1/2$。 整数座標の三角形の面積は常に整数の外積の半分であるため、値は$2 \cdot \frac{nm}{k}$整数でなければなりません。 そうでなければ、三角形は存在できません。 もう 1 つの失敗例は、単純な構築で有効な領域が生成されるものの、点が長方形の外側に配置される場合に発生します。これは、代数的な正しさをチェックするだけの場合は簡単に見落とされます。 

たとえば、次の場合$n=4, m=3, k=3$、必要な領域は$4$。 面積の代数的分解はいくつか存在しますが、すべての因子の選択が範囲内に収まるわけではありません。 不用意に因数分解を行うと、次の値を超える次元が選択される可能性があります。$n$または$m$、たとえ算術が機能しても、構築が無効になります。 

## アプローチ

 ブルート フォースの観点は、問題の定義から始まります。つまり、グリッド内の任意の 3 つの整数点を選択し、その三角形の面積を計算します。 各トリプルについて行列式を計算し、それが等しいかどうかを確認します。$\frac{nm}{k}$。 トリプルの数は次のとおりです。$(nm)^3$、たとえ小さな入力であっても完全に実行不可能です。$10^9$。 

重要な構造の簡素化は、三角形の面積が外積によって制御されることを認識することから生まれます。 一つの頂点を原点に固定すると、点で構成される三角形の面積が$(x_1,y_1)$そして$(x_2,y_2)$の絶対値の半分になります$x_1y_2 - x_2y_1$。 これにより、幾何学が純粋な数論の制約に変換されます。つまり、ターゲットの整数領域を整数行列式の半分として実現する必要があります。 

これは、軸に沿った直角三角形を構築しようとすることを示唆しています。 一点を置くとしたら$(0,0)$、別の場所$(x,0)$、そして 3 番目の$(0,y)$、面積は次のようになります。$\frac{xy}{2}$。 これにより、問題は整数の検索に簡素化されます。$x$そして$y$そのような内側の境界$$\frac{xy}{2} = \frac{nm}{k}
\quad \Longrightarrow \quad xy = \frac{2nm}{k}.$$したがって、タスクは純粋に算術になります: 整数を因数分解する$A = \frac{2nm}{k}$内に収まる 2 つのコンポーネントに分割$x \le n$そして$y \le m$。 このような因数分解が存在する場合、有効な三角形がすぐに得られます。 

ある方向でそのようなペアが見つからない場合は、軸に沿って脚を配置することもできるため、軸を交換することで別のチャンスが得られます。$(0,0)\to(0,x)$そして$(0,0)\to(y,m)$または同等の交換$n$そして$m$。 これにより、軸に沿ったジオメトリ内に留まりながら、構造の柔軟性が維持されます。

 ## アルゴリズムのチュートリアル

 1. コンピューティング$A = \frac{2nm}{k}$。 もし$2nm$で割り切れない$k$、必要な面積が単位三角形の面積の整数倍ではないため、すぐに停止します。 
2. 頂点を持つ直角三角形を作成してみます$(0,0)$、$(x,0)$、$(0,y)$。 この構成では、エリアは正確に$\frac{xy}{2}$、だから必要です$x \cdot y = A$。 
3. 設定してみる$x = n$。 もし$A$で割り切れます$n$、計算する$y = A / n$。 もし$y \le m$、これにより有効な構成が得られます。 
4. ステップ 3 が失敗した場合は、次のように設定して対称構築を試みます。$y = m$。 もし$A$で割り切れます$m$、計算する$x = A / m$。 もし$x \le n$、これも有効な三角形を生成します。 
5. 両方の軸を揃える試みが失敗した場合は、次の役割を交換します。$n$そして$m$そして同じロジックを繰り返します。 これは、実行可能な因数分解が存在するが、元の方向と一致していない場合をカバーします。 
6. すべての試行が失敗した場合は、解決策が存在しないことが出力されます。 

### なぜ効果があるのか

 整数グリッド内の三角形は整数の外積の半分に等しい面積を持つため、ターゲット面積によって特定の整数の行列値が強制されます。$A$。 すべての可能な構成の中で、軸を揃えた直角三角形は、次の任意の因数分解を実現できるため、十分です。$A$境界のある 2 つの辺に分割します。 この制約により、有効な三角形が存在する場合、一般性を失うことなく長方形の隅に三角形を埋め込むことができます。これは、グリッド軸に沿って拡張することで完全性が維持され、包含条件が維持されるためです。 したがって、境界制約の下で有効な因子ペアを見つけることは、必要かつ十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())

    # check feasibility of integer area
    if (2 * n * m) % k != 0:
        print("NO")
        return

    A = (2 * n * m) // k

    def try_case(n, m):
        # try (0,0), (n,0), (0, A/n)
        if n != 0 and A % n == 0:
            y = A // n
            if 0 <= y <= m:
                print("YES")
                print(0, 0)
                print(n, 0)
                print(0, y)
                return True

        # try (0,0), (0,m), (A/m, 0)
        if m != 0 and A % m == 0:
            x = A // m
            if 0 <= x <= n:
                print("YES")
                print(0, 0)
                print(0, m)
                print(x, 0)
                return True

        return False

    if try_case(n, m) or try_case(m, n):
        return

    print("NO")

if __name__ == "__main__":
    solve()
```この解決策は、幾何学的条件を単一の整数に縮小します。$A$、次に、長方形の境界内に収まる因子のペアを検索します。 構築では常に軸に整列した三角形が使用され、浮動小数点ジオメトリや最初のリダクションを超える行列式の操作が回避されます。 最初に成功した有界因数分解は直ちに出力される必要があるため、試行の順序は重要です。 

よくある落とし穴は、スワップを忘れることです$n$そして$m$は表面上のステップではなく、本質的な対称性です。因子のペアは転置された方向にのみ適合する可能性があります。

 ## 特殊なケース

 エッジケースの 1 つは次のような場合です$k$分けない$2nm$。 その状況では、アルゴリズムは幾何学的推論の前に入力を即座に拒否します。 例えば、$n=6, m=4, k=5$このステップでは失敗します。$48$で割り切れない$5$、三角形の構築は非整数のターゲット領域を修正できません。 

もう 1 つのエッジ ケースは、因数分解が存在するが、ある方向で範囲外にある場合です。 たとえば、次の場合$A = 12$、選択する$x=n$生み出すかもしれない$y > m$ただし、方向を交換すると、有効な有界ペアが得られる場合があります。 このようなケースを見逃さないように、アルゴリズムは明示的に両方向をチェックします。 

最後のエッジケースは次の場合に発生します。$A$非常に大きいですが、それでも 64 ビットの範囲内にあります。 このソリューションは、Python 整数を使用して計算することでオーバーフローを回避し、次のような場合でも正確性を保証します。$n$そして$m$は最大値に達しています。
