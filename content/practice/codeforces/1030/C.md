 ## 解決策
 ## 問題の理解

 単一の文字列として書かれた一連の数字が与えられます。 課題は、このシーケンスを複数の連続する部分 (少なくとも 2 つの部分) に分割して、各部分の桁の合計がまったく同じになるようにできるかどうかを判断することです。 

各部分は、元のシーケンスの連続した数字で構成されている必要があり、すべての数字が正確に 1 つの部分に属している必要があります。 したがって、問題は本質的に、すべてのブロックの合計が同じになるように、数字の配列を複数の連続したブロックに分割できるかどうかを問うことです。 

入力サイズは小さく、最大でも 100 桁です。 これにより、最悪の場合でも約 10,000 のセグメント チェックを処理することになるため、2 次または 3 次の動作を伴うソリューションが許容されることがすぐにわかります。 

微妙なエッジケースは、ゼロと繰り返される合計から発生します。 たとえば、次のようなシーケンス`0000`は多くの分割に有効ですが、次のようなシーケンスは`1111`すべてのパーティションを注意深くチェックしない限り、必ずしも明らかに分割可能であるとは限りません。 もう 1 つの重要なケースは、合計が 0 の場合です。この場合、すべての有効なセグメントの合計も 0 になる必要があります。つまり、すべての桁が 0 でなければなりません。 正の合計を仮定するアプローチや、ゼロを正しく処理せずに合計によって正規化しようとするアプローチは、ここでは失敗します。 

## アプローチ

 ブルートフォースのアイデアは、可能な限りの数のセグメントと、配列を切断するあらゆる可能な方法を試すことです。 パーティションごとに、各セグメントの合計を計算し、等しいかどうかを確認します。 

ただし、これは組み合わせの観点からすぐに実行不可能になります。 カット位置を配置する方法は非常に多くあります。 たとえ$n = 100$すべてのパーティションを列挙すると、おおよそ次のようになります。$2^{n}$実現可能な限界をはるかに超えた可能性です。 

セグメントの数を間接的に固定することで、これを大幅に減らすことができます。 カットを恣意的に選択するのではなく、有効なパーティションが存在するかどうかを観察します。$k$セグメントの場合、合計は次の数で割り切れる必要があります。$k$、各セグメントの合計は以下に等しい必要があります。$\frac{\text{total}}{k}$。 これにより、問題が指数関数的な分割から制御されたスキャンに変換されます。考えられるセグメント ターゲットを試し、等和チャンクを形成する配列を走査できるかどうかを貪欲に検証します。 

重要な洞察は、カット位置を自由に選択する必要がないということです。 ターゲット セグメントの合計が固定されると、累積によってカットが強制されます。

 ## アルゴリズムのチュートリアル

 1. シーケンス内のすべての桁の合計を計算します。 すべての有効なパーティションはこの合計をセグメント間で均等に分割する必要があるため、この合計により、考えられるすべての有効なセグメント合計が決まります。 
2. すべてのプレフィックスを最初のセグメントとして試してみます。 インデックスで終わる各プレフィックスについて`i`、その合計を計算します`s`。 これ`s`が候補セグメントの合計になります。 
3. もし`s`がゼロの場合は、特別に処理します。複数のセグメントに分割する唯一の方法は、すべての数字がゼロの場合です。ゼロ以外の数字はすぐに要件に違反するためです。 
4. 各候補者について`s`、実行合計を累積しながら、配列を左から右にスキャンすることをシミュレートします。 累計が達するたびに`s`、セグメントを「閉じ」、アキュムレータをリセットします。 
5. いずれかの時点で累計が超過した場合`s`の場合、セグメントの合計がすでにターゲットを超えているとセグメントを分割できないため、この候補は無効です。 
6. スキャンが終了したら、正確にセグメント境界で終了し、少なくとも 2 つのセグメントを形成したかどうかを確認します。 そうであれば、成功を返します。 
7. 有効な完全なパーティションにつながる候補プレフィックスの合計がない場合、答えは否定になります。 

### なぜ効果があるのか

 有効なパーティションには最初のセグメントが必要で、その合計が構造全体のセグメントの合計を一意に決定します。 この値が固定されると、パーティションの残りの部分が強制的に作成されます。どこで切断するかには自由はなく、強制的な切断が配列の終端と一致するかどうかだけが問題になります。 これにより、問題はすべての考えられる最初のセグメントをテストし、一貫性を検証することになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    s = input().strip()
    a = list(map(int, s))

    total = sum(a)

    # try all possible first segment endings
    curr = 0
    for i in range(n - 1):  # last split must leave at least one segment
        curr += a[i]

        if curr == 0:
            # only valid if all remaining digits are also zero
            if all(x == 0 for x in a[i+1:]):
                print("YES")
                return
            continue

        if total % curr != 0:
            continue

        target = curr
        seg_sum = 0
        ok = True
        cnt = 0

        for x in a:
            seg_sum += x
            if seg_sum == target:
                cnt += 1
                seg_sum = 0
            elif seg_sum > target:
                ok = False
                break

        if ok and seg_sum == 0 and cnt >= 2:
            print("YES")
            return

    print("NO")

if __name__ == "__main__":
    solve()
```このソリューションは、すべてのプレフィックスの合計を潜在的なセグメント サイズとして扱い、配列をそのサイズの連続したブロックに分解できるかどうかを検証することで機能します。 内側のループはセグメンテーションを厳密に適用し、誤って境界を越えることが決してないことを保証します。 小切手`cnt >= 2`これは、配列全体を単一のセグメントに分割することを受け入れないことを保証します。 

よくある落とし穴は、ゼロサムの場合の処理​​を誤ることです。 プレフィックスの合計がゼロの場合、ゼロで割ることは無意味であるため、割り算ロジックを使用することはできません。 代わりに、残りのすべての桁がゼロであることを直接検証します。これは、和がゼロの複数の等和セグメントが存在する唯一の状況です。

 ## 特殊なケース

 入力用`0000`、アルゴリズムはすべてのステップでゼロのプレフィックス合計を検出します。 割り算を試みるのではなく、残りの桁がすべて 0 であるかどうかを直接チェックします。 これが成り立つため、正しく YES が返され、複数のゼロサム セグメントが有効であることが確認されます。 

入力用`1111`、プレフィックスの合計により候補ターゲット 1、2、および 3 が生成されますが、セグメントの境界が等しい合計にきれいに整列しないため、各スキャンは失敗します。 アルゴリズムはすべての可能性を正確に網羅し、NO を返します。
