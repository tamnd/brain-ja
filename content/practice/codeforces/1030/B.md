 ## 解決策
 ## 問題の理解

 タスクは、4 つの境界点によって定義される固定幾何学的領域に関連して、平面内の点を分類することです。$(0, d)$、$(d, 0)$、$(n, n-d)$、 そして$(n-d, n)$。 これら 4 つの点は、正方形を 45 度回転して内側にクリップしたように見える凸状の四角形を形成します。$n \times n$グリッド。 

複数のクエリ ポイントが与えられ、それぞれがバッタの位置を表します。 それぞれのポイントについて$(x, y)$、この四角形の内側にあるのか、それとも正確にその境界上にあるのかを判断する必要があります。 

制約は非常に小さいです。$n \le 100$そして$m \le 100$。 これにより、高度なジオメトリ構造や最適化の必要性が即座に排除されます。 たとえ$O(m)$操作の総数は数千未満にとどまるため、クエリごとのチェックは簡単です。 ここで重要なのは、その地域を説明する正しい不等式を導き出すことです。 

重要な問題はパフォーマンスではなく正確さ、つまり回転された幾何学的形状を単純な座標条件に変換することです。 

通常、いくつかの失敗ケースが発生します。 

よくある間違いの 1 つは、領域を最小座標と最大座標で囲まれた単純な長方形として扱うことです。 たとえば、フィールドがちょうどであると仮定すると、$d \le x \le n-d$そして$d \le y \le n-d$それは間違いでしょう。 みたいなポイント$(1, 1)$一部の値については長方形の境界を満たしていても、依然として菱形のフィールドの外側にある可能性があります。 

もう 1 つの間違いは、境界が含まれていることを忘れていることです。 この問題ではエッジ上の点が内側として明示的にカウントされるため、次のような厳密な不等式が成立します。$<$そして$>$の代わりに$\le$そして$\ge$頂点などの有効な点が誤って拒否されてしまいます。 

正しい解決策は、回転された正方形の 2 つの対角線に対応する 2 つの線形制約によって形状が定義されていることを特定することで得られます。 

## アプローチ

 ブルートフォース幾何学的アプローチでは、方向テストまたは三角形分解を使用して、点が多角形の内側にあるかどうかを判断しようとします。 四角形を 2 つの三角形に分割し、外積を使用して点がいずれかの三角形の内側にあるかどうかを確認できます。 これは正しく機能し、概念的には一般的ですが、そのような制約された形状には不要です。 

ブルート フォースの問題は正確さではなく、過剰であることです。クエリごとに外積を計算すると必要以上に複雑になり、領域の構造がわかりにくくなります。 最悪の場合、まだ実行されます$O(m)$ただし、定数要素が重くなり、実装リスクが高くなります。 

重要な観察は、多角形が 45 度回転された完全な正方形であり、線に沿って配置されていることです。$x + y = d$そして$x + y = n + d$、また次によっても制約されます$x - y = -d$そして$x - y = n - d$。 これは、これらの対角線から導出される 2 つの線形不等式のみを使用してメンバーシップをチェックできることを意味します。 

これが認識されると、各クエリは、点が両対角方向の 2 本の平行線の間にあるかどうかをチェックすることになります。

 ## アルゴリズムのチュートリアル

 変換された 2 つの座標を使用して、ひし形の領域内にあるという条件を書き換えます。$x + y$そして$x - y$。 

1. 合計を計算する$s = x + y$。 これにより、1 つの対角方向に沿った位置が捕捉されます。 形状は定数合計の 2 つの線の間に境界があるため、これが最初の制約になります。 
2. 差を計算します$t = x - y$。 これにより、最初の制約に直交する、もう一方の対角方向に沿った位置がキャプチャされます。 この領域は、一定の差を示す 2 本の線の間にも境界されています。 
3. コーナーポイントから境界を導出します。 頂点を置き換えると、次のことがわかります。 

- 最小合計は$d$、最大合計は$n + d$- 最小差は$-d$、最大の差は$n - d$4. 各クエリ ポイントについて、両方の条件が満たされるかどうかを確認します。$d \le x + y \le n + d$そして$-d \le x - y \le n - d$5. 両方の不等式が満たされる場合、点は境界の内側または境界上にあります。 それ以外の場合は外側です。 

これが機能する理由は、四角形が 2 つのストリップの正確な交点であるためです。1 つは境界によって定義されます。$x + y$、もう一方は境界によって定義されます$x - y$。 それらの交差点は回転した正方形を形成します。 

### なぜ効果があるのか

 変革$(x, y) \rightarrow (x + y, x - y)$軸に合わせた正方形を回転した正方形にマッピングします。 この変換された空間では、領域は軸に沿った長方形になります。 軸に揃えられた長方形は各座標の独立した境界によって特徴付けられるため、メンバーシップは 2 つの独立した間隔チェックに減ります。 これにより、元の多角形のすべてのエッジが変換された座標の境界線の 1 つに正確に対応するため、正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, d = map(int, input().split())
    m = int(input())

    for _ in range(m):
        x, y = map(int, input().split())

        s = x + y
        t = x - y

        if d <= s <= n + d and -d <= t <= n - d:
            print("YES")
        else:
            print("NO")

if __name__ == "__main__":
    solve()
```このコードは、2 つの派生制約を直接実装します。 各クエリは独立して処理され、合計と差が 1 回計算され、固定境界と比較されます。 

最もデリケートな部分は、包括的な比較を確実に行うことです。 境界点が有効であるため、すべての不等式は次を使用する必要があります。$\le$そして$\ge$。 残りは単純な算術です。

 ## 特殊なケース

 エッジ ケースの 1 つは、点がポリゴンの頂点上に正確に位置する場合です。 例えば、$(0, d)$。 ここ$x+y = d$そして$x-y = -d$、どちらも包含境界を満たすため、アルゴリズムは正しく YES を返します。 

もう 1 つのケースは、点が一方の対角境界のすぐ外側にあり、もう一方の対角境界の内側にある場合です。 たとえば、次のような点$x+y = d-1$差分値が有効であっても、すぐに失敗します。 両方の条件が同時に必要であるため、アルゴリズムはこれを正しく拒否します。 

最後のケースは、ポイントが反対側のコーナーの近くにある場合です。$(n-d, n)$。 これらは両方の変換された座標を最大化します。$x+y = n+d$そして$x-y = n-2d$、どちらもまだ範囲内です。 アルゴリズムにはそれらが正しく含まれており、上限が厳密であり、ジオメトリから正しく導出されていることが確認されます。
