 ## 解決策
 ## 問題の理解

 私たちは少人数のグループを与えられ、それぞれが 1 つの問題について二者択一の意見を述べます。 各回答は、その人が問題を簡単だと考えていることを意味する 0、またはその人が難しいと考えていることを意味します。 コーディネーターのルールはシンプルです。誰もが簡単だと考える場合にのみ、問題はそのままにされます。 一人でも難しいと言う人がいると、その問題は拒否されます。 

課題は、回答の中に「厳しい」意見が含まれているかどうかを判断することです。 リスト内の少なくとも 1 つの値が 1 の場合、答えは「HARD」になります。 それ以外の場合、すべての値が 0 の場合、答えは「簡単」になります。 

n の制約は最大 100 です。これは、どのリニア スキャンも自明に高速であることを意味します。 すべてのサブセットをチェックしたり、複数のパスを再計算したりしても、パフォーマンスの点では許容できますが、不要です。 問題の構造から、単一パスで十分であることがすでに示唆されています。 

順序付けや算術を伴う、難しい隠れたエッジのケースはありません。 唯一意味のあるエッジケースは、決定が完全に単一の値に依存するため、n が 1 に等しい場合です。 もう 1 つは、すべての値が 0 の場合で、これは正しく「EASY」を返すはずです。 よくある間違いは、1 が存在しないことを確認せずに、0 の存在が簡単であることを意味すると誤って仮定することです。 

2 番目の微妙な問題は、出力のフォーマットです。 大文字化のバリエーションはどれも受け入れられますが、書式設定の選択に関係なく、論理条件が正しい必要があります。 

## アプローチ

 ブルートフォースアプローチでは、単純にリストをざっと調べて、「難しい」と答えた人の数を明示的に数えます。 カウントがゼロより大きい場合は「HARD」、そうでない場合は「EASY」と出力されます。 これはすでに最適な構造ですが、各要素を繰り返しチェックし、その結果を蓄積していると言えます。 

最悪の場合、すべての n 値を調べ、要素ごとに一定の作業を実行します。 n は最大でも 100 であるため、さらに複雑なアプローチは問題になりませんが、重要な点は、要素間の関係を処理する必要がなく、単一の値の存在を検出するだけであるということです。 

これは集計の問題ではなく、存在チェックの問題であるという洞察が得られます。 1 の合計数は必要ありません。必要なのは、少なくとも 1 つ存在するかどうかだけです。 これにより、単一の 1 が見つかるとすぐに早期終了することができます。

 | --- | --- | --- | --- |
 | ブルート フォース (すべてカウント) | O(n) | お(1) | 承認済み |
 | 最適（早期停止チェック） | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### 最適なアプローチ

 1. 処理する意見の数を示す整数 n を読み取ります。 これにより、実行する反復回数が定義されます。 
2. 意見を表す n 個の整数のリストを読みます。 それぞれの値は 0 または 1 なので、1 の存在を検出することだけを考慮します。 
3. たとえば、フラグ変数を初期化します。`has_hard = False`。 この変数は、これまでに少なくとも 1 つの厳しい意見を見たかどうかを追跡します。 
4. リスト内の各値を繰り返し処理します。 各値について、それが 1 に等しいかどうかを確認します。 
5. 値が 1 の場合、設定します。`has_hard = True`。 この時点で、最終的な答えが「HARD」になることがすでにわかっているため、オプションで早めに停止することができます。 
6. すべての値を処理した後 (または早期に停止した後)、フラグを確認します。 もし`has_hard`True の場合、「HARD」を出力します。 それ以外の場合は「EASY」を出力します。 

### なぜ効果があるのか

 この決定は、1 に等しい要素が少なくとも 1 つ存在するかどうかによってのみ決まります。フラグは、配列の接頭辞を処理した後、その接頭辞に 1 が出現したかどうかを正しく反映するという不変条件を維持します。 最後の配列は単なる完全なプレフィックスであるため、フラグは入力にハード応答が存在するかどうかを正確に表します。 これにより、追加の構造や計算を必要とせずに正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input().strip())
arr = list(map(int, input().split()))

has_hard = False

for x in arr:
    if x == 1:
        has_hard = True
        break

if has_hard:
    print("HARD")
else:
    print("EASY")
```このソリューションは入力を線形時間で読み取り、応答をリストに保存します。 次に、リストを 1 回スキャンし、1 に遭遇するとすぐに停止します。早期ブレークは正確性を保つために必要ありませんが、問題の存在チェックの性質を反映し、不必要な反復を回避します。 

主要な実装詳細はブール値フラグです。 カウントを回避し、関心のある条件を直接エンコードします。 もう 1 つの微妙な点は、すべての応答が 1 行で与えられるため、入力分割を正しく処理することです。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    from collections import deque

    data = inp.strip().split()
    n = int(data[0])

    has_hard = False
    for x in arr:
        if x == 1:
            has_hard = True

# alternating values

 ## 特殊なケース

 最も重要なエッジ ケースは、n が 1 に等しい場合です。入力の場合`1 0`の場合、ループは単一の要素を処理し、フラグを設定しないため、出力は正しく「EASY」になります。 入力用`1 1`の場合、すぐにフラグがセットされ、出力は「HARD」になります。 これにより、「バルク」入力構造がない場合でもアルゴリズムが正しく動作することが確認されます。 

もう 1 つのエッジ ケースは、すべての値が 0 である場合です。たとえば、`4 0 0 0 0`反復を通じてフラグを変更しないようにし、最終的な決定では正しく「EASY」を出力します。 これは、不在検出が適切に処理されていることを示しています。 

最後に、次のように 1 が複数ある場合`5 0 1 0 1 0`、アルゴリズムが誤ってカウントに依存しているかどうかをテストします。 フラグは最初の 1 でセットされ、決してリセットされないため、追加で 1 がいくつ出現したかに関係なく、最終結果は「HARD」のままになります。
