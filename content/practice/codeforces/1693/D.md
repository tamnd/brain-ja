 ## 解決策
 ## 問題の理解

 1 から 1 までの数字の順列が与えられます。$n$, そして、「Decinc」である連続した部分配列の数を数えるように求められます。 一部の減少するサブシーケンス (おそらく空) を削除でき、残りの要素が厳密に増加する場合、部分配列は Decinc になります。 言い換えると、すべての局所的な減少が、その減少の端点の 1 つを削除することによって処理できる場合、サブ配列は Decinc になります。 

順列を扱っているため、各数値は個別であり、1 から 1 までの範囲になります。$n$。 これは、繰り返される値ではなく、相対的な順序が主な課題であることを意味します。 出力は有効なサブ配列の合計数です。$(l, r)$どこ$1 \le l \le r \le n$。 

制約は重要です。$n$到達できる$2 \cdot 10^5$。 すべてをブルートフォースチェックする$O(n^2)$サブ配列はすぐに遅すぎます。 平$O(n^2)$サブアレイごとの分析は問題外です。 線形時間または線形算術時間に近いものが必要です。 

明らかではないエッジ ケースには、非常に短い配列、すでに厳密に増加または減少している配列、両端で 1 つの減少が発生する直前のサブ配列が含まれます。 たとえば、順列を使用すると、`[2, 3, 1]`、すべての部分配列は Decinc です。 単純なアプローチでは誤分類される可能性があります`[3, 2, 1]`最初または最後の要素のみをチェックする場合は有効ですが、この場合は一部のサブ配列のみがプロパティを満たします。 

## アプローチ

 ブルートフォースアプローチでは、考えられるすべてのサブ配列に対して反復処理が行われます。$(l, r)$それぞれが Decinc であるかどうかを確認します。 部分配列をチェックするには、要素の削除をシミュレートして要素の増加を試みることができます。 サブ配列は最大サイズにできるため、$n$、各チェックは$O(n)$。 これにより、$O(n^3)$最悪の場合、それは明らかに不可能です$n = 2 \cdot 10^5$。 

重要な観察は、部分配列が Decinc であるのは、減少する部分列を削除した後、左側のすべてが増加し、右側のすべてが増加するように最大要素を配置できる場合に限り、Decinc であるということです。 これは順列であるため、極小値と極大値の構造は非常に制限されています。 各要素について、Decinc 部分配列の一部となる可能性がある左右の最大セグメントを追跡できます。 これを左から右、右から左へ 1 回のパスで実行することで、インデックスごとに最も遠い有効な左境界と右境界を計算できます。 

これらの境界を取得すると、有効な部分配列の数をカウントすると、範囲全体の合計になります。 入れ子になったループは完全に避けます。 これは事実上、線形スイープ アプローチであり、順列構造を利用して、Decinc プロパティが失敗する無効な領域を検出します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^3) | お(1) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 順列内の各値をその位置にマッピングします。 これにより、相対的な順序について迅速に推論することができます。$O(1)$。 
2. 2 つの配列を初期化します。`left`そして`right`、各インデックスの最大有効セグメントを追跡します。`left[i]`Decinc サブ配列が次で終わる左端のインデックスを格納します。`i`可能です。`right[i]`で始まる Decinc サブ配列の右端のインデックスを格納します。`i`可能です。 
3. 左から右にスイープします。 要素ごとに`p[i]`、前の要素と増加シーケンスが続いているかどうかを確認します。 存在する場合は、セグメントを拡張します。 それ以外の場合は、新しいセグメントを開始します。 これにより、厳密に増加するすべてのプレフィックスが識別されます。 
4. 同様に右から左にスイープして、厳密に増加する接尾辞を見つけます。 
5. 各インデックスについて`i`、部分配列の範囲を計算します`[left[i], right[i]]`を含む`p[i]`そしてデシンです。 これらの範囲内のすべてのサブ配列の数を累計に加算します。 
6. 合計を出力します。これにより、すべての Decinc サブ配列が正しくカウントされます。 

機能する理由: すべてのインデックスにおいて、アルゴリズムは、その要素を含む部分配列が昇順に違反することなく減少を削除できることを保証します。 Decinc プロパティに違反すると有効なセグメントが縮小されるため、左右のスイープにより無効な部分配列がカウントされないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
p = list(map(int, input().split()))

pos = [0] * (n + 1)
for i, val in enumerate(p):
    pos[val] = i

# left[i] is farthest left boundary for Decinc subarray ending at i
left = [0] * n
for i in range(n):
    if i == 0:
        left[i] = 0
    else:
        if p[i-1] < p[i]:
            left[i] = left[i-1]
        else:
            left[i] = i

# right[i] is farthest right boundary for Decinc subarray starting at i
right = [0] * n
for i in reversed(range(n)):
    if i == n - 1:
        right[i] = n - 1
    else:
        if p[i] < p[i+1]:
            right[i] = right[i+1]
        else:
            right[i] = i

total = 0
for i in range(n):
    total += (i - left[i] + 1) * (right[i] - i + 1)

print(total)
```最初のループは、値を潜在的な拡張の位置にマップします。 左右のスイープでは、最大増加セグメントが計算されます。 最終的な合計では、以下を含むすべてのサブ配列がカウントされます。`p[i]`左右の選択肢の数を掛け合わせます。 使用する`i - left[i] + 1`で終わる部分配列の可能な開始点をすべてカウントします。`i`、 そして`right[i] - i + 1`から始まるサブ配列の可能なすべてのエンドポイントをカウントします。`i`。 

微妙な点: 配列の端での境界処理が重要です。 忘れるとオフバイワンエラーが発生します`+1`どちらの範囲の計算でも。 順列プロパティにより、等しい要素がないことが保証され、比較ロジックが簡素化されます。
