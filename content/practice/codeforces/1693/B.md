 ## 解決策
 ## 問題の理解

 私たちには根の生えた木が与えられています。 すべての頂点は値で始まります`0`、および各頂点`v`必要な間隔があります`[l_v, r_v]`。 

操作では、ルートから頂点までのパスを選択し、そのパスに沿って値を追加します。 追加された値は、ルートから選択した頂点に向かって移動するときに、非減少シーケンスを形成する必要があります。 

いくつかの操作を実行した後、すべての頂点値は、許可された間隔内に収まる必要があります。 タスクは、最小の操作数を見つけることです。 

一見すると、この操作はパス全体を変更し、追加されたシーケンスに制約があるため複雑に見えます。 主な課題は、各頂点で実際にどのような値が生成されるのか、およびツリー全体で操作がどのように相互作用するのかを理解することです。 

ツリーには以下が含まれます`2 · 10^5`すべてのテスト ケースにわたる頂点。 パスを繰り返し走査したり、操作を明示的にシミュレートしたりするソリューションは、非常に遅すぎます。 合計サイズのみなので、`2 · 10^5`、`O(n)`または`O(n log n)`テストファイルごとのソリューションが期待されます。 

微妙な点は、操作が祖先と子孫に同時に影響を与える可能性があることです。 頂点を独立して満たそうとする貪欲な戦略は、簡単にオーバーカウントする可能性があります。 

考慮する：```
1
|
2
```と```
[1,5]
[2,9]
```1 つの操作で両方の頂点をすでに満たすことができます。 各頂点を個別に扱うと、誤った答えが返されます`2`。 

もう 1 つの簡単な間違いは、すべての頂点が最終的​​には正確に受信する必要があると仮定することです。`l_v`。 

例：```

```と```
[1,100]
[50,100]
```頂点の場合`2`値を受け取ります`50`、次に頂点`1`少なくとも自動的に受信します`50`同じように。 それは完全に正当です。`50`まだ中に眠っている`[1,100]`。 

3 番目の落とし穴は、サブツリーが親を満足させるのに十分な貢献を提供できないときに発生します。 

例：```
    1

[1,1]
[1,1]
```子どもたちは一緒に貢献するだけです`2`。 頂点`1`少なくともまだ価値が必要です`10`、そのサブツリーの中心にある追加の操作を強制します。 下限をチェックせずに子の寄与だけを集計するアプローチは、ここでは失敗します。 

## アプローチ

 強引な見方は、運用の観点から直接考えることです。 間隔を最小限に抑えながら、すべての間隔を満たす操作を構築することもできます。 残念ながら、実行可能な操作の範囲は膨大です。 各操作では、パス、長さ、および任意の非減少整数シーケンスが選択されます。 小さな木であっても、指数関数的に多くの可能性があり、明示的な検索は不可能です。 

重要な点は、実際には操作自体を知る必要がないということです。 

をルートとするサブツリーを処理するとします。`v`。 そのサブツリー内で作成されたすべての操作が、ある程度の合計額に寄与すると想像してください。`s`頂点へ`v`。 

先祖にとって重要なのはこの総額だけです。 以下の操作の正確な分布`v`意味がなくなってしまいます。 

次に頂点で何が起こるかを考えてみましょう`v`。 

子からの累積貢献がすでに少なくとも`l_v`、その後、上向きに渡される値に上限を設けることができます。`min(s, r_v)`。 以上を送信します`r_v`の最終値であるため、上向きは役に立ちません。`v`超えることはできません`r_v`。 

累計貢献額が以下の場合`l_v`の場合、既存のサブツリー操作の組み合わせは満足できません。`v`。 最も有用な点がこのサブツリー内にある新しい操作を 1 つ作成する必要があります。 将来の利益を最大化するために、`v`直接に`r_v`。 これは貢献します`r_v`上向きであり、費用はちょうど 1 回の操作です。 

これは当然、事後 DFS につながります。 

各頂点について、サブツリー全体を最適に処理した後、頂点が上向きに寄与できる量を計算します。 

葉は特に目に見えます。 葉は最初に貢献します`0`。 もし`0 < l_v`、そこで 1 つの操作を開始して戻らなければなりません`r_v`。 これは、正の要件を持つリーフには独自の操作が必要であるという直観と一致します。 

ソリューション全体は貪欲なツリー DP になり、各頂点はその子からの合計を受け入れるか、1 つの新しい操作を開始します。

 ## アルゴリズムのチュートリアル

 1. ツリーの頂点にルートを作成します`1`。 
2. 頂点を事後順序で処理します。つまり、すべての子が親の前に処理されます。 
3. 頂点の場合`v`、次を計算します。```
sum_children = Σ contribution(child)
```これは、すでに入手可能な合計値です。`v`その子孫内で作成された操作から。 
4. もし`sum_children < l_v`の場合、サブツリーは満足できません`v`。 

新しいオペレーションを 1 つ作成します。 

答えを増やす`1`。 

戻る`r_v`このサブツリーの親への寄与として。 

新しい操作は効果的に`v`有用な値を最大にして、先祖に最大限の助けを与えます。 
5. それ以外の場合は、`v`新しい操作を作成しなくても、すでに満たされています。 

戻る：```
min(sum_children, r_v)
```上記の任意の金額`r_v`使用できないため`v`その間隔内に留まらなければなりません。 
6. ルートを処理した後、累積された答えが最小操作数になります。 

### なぜ効果があるのか

 すべての頂点について、その親に関連する唯一の情報は、サブツリー全体を有効に保ちながら上方に伝播できる最大の実現可能な値です。 

子孫操作で得られる値が以下の場合`l_v`、満足する方法はありません`v`サブツリーのどこかに新しい操作を導入する必要はありません。 操作を 1 つだけ作成し、結果の寄与を次のように設定するだけで十分です。`r_v`より大きな貢献は祖先を助け、害を及ぼすことはないため、常に最適です。 

子孫操作がすでに少なくとも`l_v`場合、別のオペレーションを作成する必要はありません。 上方に渡すための最良の寄与は、次の時点で許可される最大値です。`v`、つまり`min(sum_children, r_v)`。 

すべての頂点でこの局所的に最適な選択を行うことで、必要以上の操作を使用することなく、先祖に与えられる支援を最大化します。 どのソリューションでも常に操作を作成する必要があります`sum_children < l_v`、したがって貪欲な決定を強いられます。 これは最適性を証明します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans_list = []

    for _ in range(t):
        n = int(input())

        parent = [0] * (n + 1)
        children = [[] for _ in range(n + 1)

]
        p = list(map(int, input().split()))

        for i in range(2, n + 1):
            parent[i] = p[i - 2]
            children[parent[i]].append(i)

        l = [0] * (n + 1)
        r = [0] * (n + 1)

        for i in range(1, n + 1):
            l[i], r[i] = map(int, input().split())

        order = []
        stack = [1]

        while stack:
            v = stack.pop()
            order.append(v)
            for u in children[v]:
                stack.append(u)

        value = [0] * (n + 1)
        answer = 0

        for v in reversed(order):
            s = 0
            for u in children[v]:
                s += value[u]

            if s < l[v]:
                answer += 1
                value[v] = r[v]
            else:
                value[v] = min(s, r[v])

        ans_list.append(str(answer))

    sys.stdout.write("\n".join(ans_list))

if __name__ == "__main__":
    solve()
```最初の部分では、親配列からルート付きツリーを構築します。 

DFS は、Python の再帰の深さの問題を回避するために反復的に実装されます。 最初に走査順序を生成し、次にそれを逆に処理して、事後順序走査を生成します。`value[v]`サブツリーの量を格納します`v`最適に処理された後、上向きに貢献できます。 

児童拠出金の累計額が以下の場合`l[v]`、新たな操作は避けられません。 それをカウントして貢献度を設定します`r[v]`。 

それ以外の場合、サブツリーはすでに有効です。 貢献度は以下を超えることはできません`r[v]`なので、次のようにクランプします。`min(s, r[v])`。 

値は最大に達する可能性があります`2 · 10^5 × 10^9`, そのため、Python の任意精度の整数は便利です。 固定幅整数を使用する言語では、64 ビット型が必要です。
