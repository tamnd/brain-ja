 ## 解決策
 ## 問題の理解

 道路で結ばれたイタリアの都市を表す有向グラフが与えられました。 Keshi は都市 1 から開始し、AmShZ が待っている都市 n に到達したいと考えています。 毎日、AmShZ は 1 つの道路を通行止めとしてマークするか、Keshi に移動するよう指示することができます。 ケシが移動する場合、彼は自分の位置から現在到達可能なすべての都市の中からランダムに選択します。 課題は、Keshi の選択のランダム性に関係なく、AmShZ が Keshi に確実に届くまでの最小日数を決定することです。 

入力は都市の数を提供します`n`そして道路`m`、 に続く`m`有向エッジ。 出力は単一の整数です`d`、ケシで最も裕福な都市を保証するために必要な最小日数。 
制約は高いです:`n`そして`m`到達できる`2 * 10^5`。 これは、以下よりも悪いアルゴリズムを意味します。`O(n + m)`または`O((n + m) log n)`2 秒以内に実行される可能性は低いです。 遮断された道路やランダムな動きのすべてのシーケンスをシミュレートするような 2 次アプローチは、まったく実行不可能です。 同じ都市のペア間には複数のエッジが許可されるため、単純な隣接行列を仮定したり、各都市のペアが最大 1 つの道路で接続されていると仮定したりすることはできません。 

明らかではないエッジケースは、目的地までの距離が大きく異なる複数の下り道路がある都市がある場合に発生します。 たとえば、都市 1 に都市 2 と都市 3 への道路があり、都市 2 から都市 n まで 1 ステップでつながり、都市 3 から都市 n まで 100 ステップでつながる場合、道路をブロックしないという単純な戦略では、最悪の場合 100 日になる可能性があります。 正しい解決策には、ランダムな最短パスではなく、最適なブロッキング後の保証された最長パスを特定する必要があります。 

## アプローチ

 ブルートフォースのアイデアは、ブロッキング決定のすべてのシーケンスをシミュレートすることです。 すべての都市について、ケシがランダムに移動した場合に都市 n に到達するまでの予想日数を計算できます。 次に、可能な限り最長の日数を最小限に抑えるために、道路を遮断するあらゆる選択肢をシミュレーションします。 これは小さなグラフでは機能しますが、シーケンスの数は各都市の発信エッジの数に応じて指数関数的に増加します。 と`m`まで`2 * 10^5`、これはまったく不可能です。 

重要な観察は、問題が **最悪の場合に必要な最小日数** を計算することに帰着するということです。これは、「最適なブロック下での n までの距離」に類似した尺度を見つけるのと同等です。 ランダムに前進することを考えるのではなく、**都市 n** から逆方向に問題を考えてみましょう。 各都市には、最悪の場合に都市 n に到達するまでにかかる日数を表す数値を割り当てることができます。 発信エッジを持つ都市の場合、最適な戦略は、そのような数が最大の都市につながるエッジを最初にブロックすることです。 最終的に、都市の日数は、ブロッキングを考慮して **その子の最大日数**に 1 を加えたものになります。 

これにより、**反転グラフでのトポロジカル ソート**を使用した線形時間解が得られます。 各都市の「距離」は、発信エッジの数を考慮して、到達可能な都市の距離に基づいて計算されます。 これにより、最適なブロッカーによって Keshi が毎日都市 n に向けての進歩を最大化するパスをたどることが保証されるため、ランダム性のシミュレーションが完全に回避されます。

 | --- | --- | --- | --- |
 | ブルートフォース | O(2^m) | O(n + m) | 遅すぎる |
 | 最適 | O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. エッジが次の方向を指す**反転グラフ**を構築します。`u`に`v`元のエッジが`v`に`u`。 これにより、都市 n からの距離を逆に推論することができます。 
2. 配列を初期化する`days_to_n`長さの`n + 1`と`0`都市nの場合、ケシはすでにそこにあるため。 
3. 反転したグラフの **トポロジカル順序**を計算します。 これにより、都市を処理するときに、その都市から到達可能なすべての都市にすでに日付が割り当てられるようになります。 
4. トポロジ順に各都市について、n に達するまでの日数を決定します。 都市にとって`v`発信エッジ付き`u1, u2, ..., uk`、これらの目的地を **降順で並べ替えます`days_to_n`**。 次に割り当てます`days_to_n[v]`として`1 + max(days_to_n[ui] + i)`、 どこ`i`ソートされたリストのインデックスです。 の`+i`より困難なパスを最初にブロックすることを説明します。 
5. すべての都市が処理されると、答えは次のようになります。`days_to_n[1]`。 これは、AmShZ が都市 1 から Keshi に到着することを保証するために必要な最小日数を表します。 

機能する理由: 反転グラフとトポロジカル並べ替えにより、各都市の最悪の場合の日数が、すでに計算されている子の値にのみ依存することが保証されます。 発信エッジをソートすることで、ブロッキング戦略の効率が最大化されます。長いパスが最初にブロックされるため、Keshi は最小保証日数につながるパスを選択することになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import defaultdict, deque

def solve():
    n, m = map(int, input().split())
    g = [[] for _ in range(n + 1)]
    outdeg = [0] * (n + 1)
    
    for _ in range(m):
        v, u = map(int, input().split())
        g[u].append(v)  # reverse graph
        outdeg[v] += 1

    days = [0] * (n + 1)
    q = deque([n])
    
    while q:
        node = q.popleft()
        for prev in g[node]:
            outdeg[prev] -= 1
            days[prev] = max(days[prev], days[node] + 1)
            if outdeg[prev] == 0:
                q.append(prev)
    
    print(days[1])

solve()
```この実装では、都市 n から逆方向に推論するためにエッジを反転します。 の`outdeg`配列は、都市ごとに未処理の発信エッジの数を追跡します。 都市を繰り返し処理することで、`outdeg`がゼロに達すると、最悪の日を効率的に計算します。 使用する`max(days[prev], days[node] + 1)`最適なブロックを反映して、ケシが強制的に進むことができる最長ルートを確実に考慮します。
