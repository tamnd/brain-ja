 ## 解決策
 ## 問題の理解

 以下の数値の順列を操作する再帰的手続きが与えられています。`1`に`n`。 

関数は次のように動作します。 

のために`f(x)`、最初に再帰的に処理します。`x - 1`要素を配置し、位置を交換します`x - 1`そして`x`。 

電話したら`f(n)`、再帰は最終的にこれらのスワップを順番に実行します。 

- ポジションを交換する`(1, 2)`- ポジションを交換する`(2, 3)`- ポジションを交換する`(3, 4)`- ...
 - ポジションを交換する`(n - 1, n)`タスクは並べ替えをシミュレートすることではありません。 代わりに、これらすべてのスワップが実行された後、最終的な配列が昇順にソートされるように、初期の順列を構築する必要があります。 

制約`n ≤ 1000`とても小さいです。 二次シミュレーションでも問題なく制限内に収まります。 本当の課題は、再帰的なプロセスの中に隠されたパターンを認識することです。 

よくある間違いは、答えが何らかの形で反転した配列に似ているに違いないと仮定することです。 たとえば、`n = 4`、以下から始まります:```
4 3 2 1
```スワップにより以下が生成されます。```
3 4 2 1
3 2 4 1
3 2 1 4
```それはソートされていません。 

もう 1 つの簡単な間違いは、スワップの順序を誤解することです。 再帰では、要素が繰り返しバブルされることはありません。 隣接する各ペアは、左から右に 1 回だけ交換されます。 

のために`n = 3`、スワップは次のとおりです。```
swap(1,2)
swap(2,3)
```初期配列が次の場合:```
2 1 3
```次に、交換後:```
1 2 3
1 3 2
```結果は正しくありません。 実際のスワップ注文をトレースしない不注意な実装では、そのような無効な構造が簡単に生成される可能性があります。 

最小のエッジケースは次のとおりです。`n = 1`。 スワップはまったく発生しないため、唯一の有効な答えは次のとおりです。```
1
```これを個別に処理せずに要素のシフトに依存するソリューションでは、誤って空の配列または無効なインデックスが生成される可能性があります。 

## アプローチ

 最も直接的な総当り攻撃のアイデアは、次の数値のすべての順列を試すことです。`1`に`n`、再帰プロセスをシミュレートし、最終的な配列がソートされるかどうかを確認します。 

これが機能するのは、再帰関数が決定的であるためです。 開始順列が固定されると、すべての交換後の結果の配列が一意に決定されます。 

順列ごとに、次のことを実行します。`n - 1`スワップなので、1 つの候補をチェックするのにコストがかかります`O(n)`。 問題は順列の数です。 がある`n!`可能性。 

たとえ`n = 10`、これはすでに次のようになります。```
10! = 3,628,800
```すべての順列を試すことはすぐに不可能になります。 

重要な点は、再帰関数が非常に単純な変換を実行するということです。 最初の要素を除き、すべての要素が左に 1 位置移動します。最初の要素は最後に移動します。 

例えば：```
[a1, a2, a3, a4]
```スワップ後は次のようになります。```
[a2, a3, a4, a1]
```これは直接確認できます。```
swap(1,2): [a2, a1, a3, a4]
swap(2,3): [a2, a3, a1, a4]
swap(3,4): [a2, a3, a4, a1]
```これで問題は簡単になります。 

最終的な配列は次のようになります。```
1 2 3 ... n
```この操作では配列を 1 位置だけ左に回転するため、最初の並べ替えは、ソートされた配列を 1 位置だけ右に回転する必要があります。```
n 1 2 3 ... n-1
```再帰的なスワップの後:```
1 2 3 ... n
```この構築は即座に行われ、直線的な時間で実行されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n・n!) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(1) 出力を除く | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 整数を読み取る`n`。 
2. で始まる順列を構築します。`n`。 

再帰的プロセスにより配列が 1 ステップ左に回転されるため、この要素はすべての交換後に最後の位置に移動する必要があります。 
3. 以下のすべての整数を追加します。`1`に`n - 1`昇順で。 

スワップによって左回転が行われた後、これらの要素は正しいソート位置に移動します。 
4. 結果の順列を出力します。 

### なぜ効果があるのか

 再帰関数は、左から右への隣接するスワップを 1 回だけ実行します。 このシーケンスは次のように変換します。```
[a1, a2, a3, ..., an]
```の中へ：```
[a2, a3, ..., an, a1]
```これは 1 つの位置による左回転です。 

最終的な配列を次のようにしたい場合:```
[1, 2, 3, ..., n]
```この場合、最初の配列は逆変換、つまりソートされた配列の右回転でなければなりません。```
[n, 1, 2, ..., n-1]
```この順列に再帰的スワップを適用すると、ソートされた順序が生成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())

ans = [n] + list(range(1, n))

print(*ans)
```実装は数学的観察に直接従うものです。 

配列は次で始まります`n`再帰的なプロセスにより最初の要素が最後に移動されるためです。 残りの数値はすべてすでにソート順になっているため、左回転すると次のようになります。```
1 2 3 ... n
```表現:```
list(range(1, n))
```～から数値を正しく生成します`1`を通して`n - 1`。 

次の場合に、微妙な境界条件が 1 つ現れます。`n = 1`。 

その場合:```
list(range(1, 1))
```空のリストが生成されるため、最終結果は次のようになります。```
[1]
```それはまさに正しいです。 

スワップのシミュレーションは必要ありません。 再帰的な動作は、回転観察によって完全に捕捉されます。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    n = int(input())

    ans = [n] + list(range(1, n))

    print(*ans)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    output = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return output

# provided sample
assert run("1\n") == "1\n", "sample 1"

# custom cases
assert run("2\n") == "2 1\n", "smallest non-trivial case"

assert run("3\n") == "3 1 2\n", "checks left-rotation logic"

assert run("5\n") == "5 1 2 3 4\n", "general case"

expected = "1000 " + " ".join(str(i) for i in range(1, 1000)) + "\n"
assert run("1000\n") == expected, "maximum size input"
