 ## 解決策
 ## 問題の理解

 私たちは次のサイズの長方形グリッドに取り組んでいます。$2n \times 2m$チェスの色が固定されている: セル$(i, j)$なら白です$i + j$は偶数、それ以外の場合は黒です。 ゲームでは白マスのみが重要です。 時間の経過とともに、一連のクエリによって一部の白いセルが「削除」と「使用可能」の間で切り替わります。 

各切り替えの後、私たちは、正確に配置できるかという、全体的な実現可能性の質問に答える必要があります。$n \cdot m$2 人のキングが互いに攻撃しないように、現在利用可能な白いセルにキングを配置しますか? キングは 8 方向すべてに攻撃するため、選択された 2 つのセルがエッジやコーナーを共有してはなりません。つまり、チェビシェフ距離は少なくとも 2 でなければなりません。 

これにより、グリッドが現在利用可能な白いセルのセットに関するグラフ問題に変わります。エッジがチェビシェフ距離 1 でセルを接続します。このグラフが独立したサイズのセットを許容するかどうかを尋ねられます。$n \cdot m$ただし、ターゲット サイズが固定されており、グリッド構造に比べて非常に大きいという追加の制約があります。 

制約は大きく、最大 200,000 行、200,000 列、200,000 更新です。 これにより、グリッド全体にわたるクエリごとの再計算や、各切り替え後のすべてのアクティブ セルの走査に依存するソリューションが即座に排除されます。 どのようなアプローチでも対数更新またはほぼ一定の償却更新をサポートする必要があり、答えは増分的に維持される必要があります。 

微妙な点は、白のセルのみが切り替わることです。 黒セルは無関係であり、操作には決して表示されないため、有効なグラフは白セルのみに誘導されたグラフです。 

単純な間違いは、これを完全なグリッド隣接グラフでの 2 部マッチングまたはカラーリングの実現可能性の問題として扱うことです。 そのため、更新のたびに接続された制約が再計算されることになり、非常に時間がかかります。 

もう 1 つのよくある失敗ケースは、キングが隣接関係を禁止しているため、更新のローカル近傍をチェックするだけでよいと仮定することです。 単一の削除によって、複数のコンポーネントの相互作用を強制するグローバルな「ブロック パターン」が作成されると、この問題は解決されません。 

## アプローチ

 直接的な総当りのアプローチでは、グリッド全体の状態が維持され、各切り替え後に有効な配置の構築が試行されます。$nm$王たち。 これは、グリッド グラフ上で貪欲な配置または二部一致スタイル推論によって実行できます。 ただし、実現可能性チェックを 1 回行うだけでも、すでにすべてのスキャンが必要です。$O(nm)$白血球は、最悪の場合、最大4億個になります。 クエリが 200,000 件あると、これは完全に不可能です。 

重要な観察は、チェビシェフ隣接のみを持つチェス盤グリッド内の白セルの構造が大幅に単純化されていることです。 完全に$2n \times 2m$ボードでは、キングの最適な配置は厳密です。それは、より粗いスケールで固定の市松模様のようなパターンを選択することに対応します。 それぞれ$2 \times 2$ブロックは、有効な最大構成において、必須の配置スロットを 1 つだけ提供します。 これは、全体的な答えが任意の隣接関係に依存するのではなく、そのような各ブロックに少なくとも 1 つの使用可能な白セルがまだ含まれているかどうかに依存することを意味します。 

したがって、恣意的な独立性について推論する代わりに、すべての独立性が存在するかどうかをチェックすることとして問題を再解釈します。$2 \times 2$マクロブロックにはまだ少なくとも 1 つの使用可能な白セルがあります。 いずれかのブロックが完全に使用できなくなると、そのブロックは有効な配置に貢献できなくなるため、必要な数のキングを配置できなくなります。 

したがって、問題は、ポイントの切り替えの下で、すべてが$n \cdot m$ブロックには少なくとも 1 つのアクティブな白セルが含まれます。 

現在含まれているアクティブな白血球の数を追跡するブロックごとのカウンターを維持します。 答えは、カウント 0 のブロックがない場合に限り、「YES」です。

 ## アルゴリズムのチュートリアル

 各白セルをマッピングします$(i, j)$マクロブロックに$(i // 2, j // 2)$。 各ブロックは、$2 \times 2$元のグリッドの領域。 ブロックごとに、ブロックに含まれる現在アクティブな白セルの数を表す整数カウンターを維持します。 

1. すべてのブロック カウンタをゼロに初期化します。 また、現在「空」のブロック、つまりカウンターがゼロであるブロックの数を追跡するグローバルカウンターも維持しています。 最初はすべてのセルが存在するため、空のブロックはありません。 
2. クエリごとに、白いセルを切り替えます。$(i, j)$。 そのブロックインデックスを計算します$(bi, bj) = (i // 2, j // 2)$。 
3. セルが削除されている場合は、そのブロックのカウンターをデクリメントします。 カウンタがゼロになると、このブロックは最後の有効なセルを失ったため、グローバル空ブロック カウンタをインクリメントします。 
4. セルが復元中の場合は、現在のカウンターを確認します。 更新前にゼロだった場合、このブロックは復元後に空ではなくなるため、グローバル空ブロック カウンタをデクリメントします。 次に、ブロックカウンターをインクリメントします。 
5. トグルの処理後、グローバル空ブロック カウンタがゼロの場合は「YES」を出力し、それ以外の場合は「NO」を出力します。 

設計の重要なポイントは、隣接するブロックを検査したり、キングの配置をシミュレートしたりする必要がないことです。 関連するすべての制約は、各構造単位が少なくとも 1 つの使用可能なセルをまだ持っているかどうかに集約されます。 

### なぜ効果があるのか

 有効な構成$nm$王は、各国ごとに 1 人の「代表者」を必要とします。$2 \times 2$このようなブロック内では、任意の 2 つの白いセルが相互に隣接しているか、グローバル タイル構造全体で複数の安全な選択肢が同時に有効になることを妨げる隣接制約を共有しているためです。 したがって、各ブロックは少なくとも 1 つの使用可能なセルを提供する必要があります。 

逆に、すべてのブロックに少なくとも 1 つの使用可能な白セルがある場合は、異なるブロック間の相互作用によって、選択された代表レベルで隣接関係の競合が発生することがないため、ブロックごとに独立して 1 つを選択できます。 この独立性は、チェス色のグリッド上のチェビシェフ距離の固定幾何学から生じます。 

したがって、「空きブロックが存在しない」という条件は必要かつ十分である。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, q = map(int, input().split())
    
    # Each block (i//2, j//2) tracks number of active white cells
    # We store only non-zero entries in a dictionary for sparsity.
    from collections import defaultdict
    cnt = defaultdict(int)
    
    empty_blocks = n * m
    active = set()
    
    def key(i, j):
        return (i >> 1, j >> 1)
    
    out = []
    
    for _ in range(q):
        i, j = map(int, input().split())
        k = key(i, j)
        
        if (i, j) in active:
            # remove
            if cnt[k] == 1:
                empty_blocks += 1
            cnt[k] -= 1
            active.remove((i, j))
        else:
            # add
            if cnt[k] == 0:
                empty_blocks -= 1
            cnt[k] += 1
            active.add((i, j))
        
        out.append("YES" if empty_blocks == 0 else "NO")
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装では、ブロック全体のハッシュ マップとアクティブ セルのセットを維持して、切り替えをサポートします。 ブロック インデックスは整数の 2 による除算を使用して計算されます。これは、各ブロックが正確に 1 つのブロックであるため安全です。$2 \times 2$元のグリッド内の領域。 

重要な詳細は、ブロックがゼロと非ゼロの間で遷移する場合にのみ、グローバルな「空ブロック」カウントを更新することです。 これにより、クエリごとにすべてのブロックをスキャンする必要がなくなります。

 ## 特殊なケース

 クリティカルなエッジケースは、トグルの繰り返しによりブロックが空と空でない間で変動するときに発生します。 このアルゴリズムはゼロでの遷移の検出に完全に依存しているため、誤った処理はグローバル カウンターに off-by-1 エラーとして表示されます。 

たとえば、1 つのセルが繰り返し切り替わる単一のブロックを考えてみましょう。```

1 1
1 1
1 1
1 1
```ブロックの状態は 0 → 1 → 0 → 1 → 0 と変化し、グローバルな応答もそれに応じて変化する必要があります。 この実装では、ゼロしきい値を超えた場合にのみ空ブロック カウンタを更新することでこれを保証し、反復操作を通じて正確さを維持します。
