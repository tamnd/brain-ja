 ## 解決策
 ## 問題の理解

 私たちには構造が与えられています$n$各人に子供が 0 人かちょうど 1 人の子供がいる人々にラベルを付けました。 人に子がない場合、その発信ポインタは 0 です。それ以外の場合、すべての人は 1 つの子インデックスを正確に指します。$[1, n]$。 これによりフォレストのような構造が作成されますが、強い制約があります。つまり、何も持たない単一の終端ノードを除き、すべてのノードには出力エッジが 1 つだけあります。 

この関数グラフから、人の「家族セット」を、その人自身と、親リンクを上向きに繰り返したどることによって到達可能な全員を含むセットとして定義します。 親は直接与えられませんが、各ノードには 0 個または 2 個の親があるため、構造は暗黙的に逆ツリー関係を定義します。 

「スキュー」イベントは、2 つの親が定義されているノードで発生します。 このようなノードについては、2 つの親サブツリーのサイズを比較します (各親のファミリー セットに属するノードの数に関して)。 一方の辺がもう一方の辺の 2 倍以上である場合、このノードは 1 つのスキューに寄与します。 

課題は、そのような構造を構築できるかどうかを判断することです。$n$正確に生成するノード$k$イベントをスキューし、はいの場合は、子ポインターの有効な構造を出力します。 

制約$n \le 100{,}000$直線または直線に近い構造を強制します。 素朴な方法でノードごとにサブツリーのサイズを動的にシミュレートしようとすると、再計算コストが超過します。$O(n)$または$O(n \log n)$。 主な要件は、制御可能なサブツリー サイズと予測可能なスキュー カウントを備えた構造を直接設計することです。 

微妙なエッジケースは次のような場合です$k$に比べて大きい$n$。 各スキューは 2 つの親を持つノードに関連付けられており、そのような各ノードはバイナリのような構造のマージ ポイントに対応するため、そのような不均衡を強制できる数には暗黙の上限が存在します。 たとえば、$n = 3$有効な構造では 1 つのノードだけが 2 つの親を持つことさえできるため、2 つのスキューを取得することは不可能です。 すべての内部マージが独立してスキューを作成する可能性があるという単純な仮定は、過剰カウントにつながります。 

## アプローチ

 強引なアイデアは、制約を満たすすべての可能な親子構造を生成し、各ノードのサブツリー サイズを計算し、スキュー イベントをカウントすることです。 これには、追加の構造制限を伴う関数グラフを列挙する必要がありますが、これは非常に指数関数的です。$n$。 一つの構造物をチェックするだけでもコストがかかる$O(n)$、したがって、これは小さなことを超えると完全に実行不可能です$n$、おおよそ超えています$n = 10$または$n = 12$。 

重要な観察は、スキュー イベントは完全なグローバル構造ではなく、マージ ポイントでの相対的なサブツリー サイズのみに依存するということです。 チェーン状のバックボーンを構築し、制御されたサイズのサブツリーを接続すると、一方のサイズをもう一方のサイズの少なくとも 2 倍にすることで、選択したノードに決定論的にスキューを強制できます。 これにより、配布の問題が軽減されます$n$ノードをグループに分け、そのサイズがバイナリの成長パターンをエンコードします。 

この構造を、各マージ ポイントが以前に構築された 2 つのコンポーネントを結合するルート構造を構築するものとして再解釈します。 このような各マージでは、候補スキュー ノードが 1 つだけ作成されます。 スキューの条件は、コンポーネントのサイズ間の単純な不等式になります。 したがって、問題は選択に帰着します。$k$マージ ポイントでは不均衡を強制し、他のすべてのマージは偶発的なスキューを避けるために十分なバランスを保ちます。 

私たちはコンポーネントを繰り返し構築します。新しいコンポーネントはそれぞれ以前のコンポーネントを 2 倍にし、オプションで小さな「オフセット」リーフを追加してスキューを強制または防止します。 これにより、サブツリーのサイズが 2 のべき乗またはそれに近いバリアントになる制御されたバイナリ展開に構築が変わります。

 ## アルゴリズムのチュートリアル

 それぞれのサイズが既知である一連のコンポーネントを使用してグラフを段階的に構築し、マージ ポイントを慎重に選択します。 

1. から始める$n$孤立したノード。それぞれがサイズ 1 の自明なコンポーネントです。各ノードには、最初は子が割り当てられていません。 
2. コンポーネントのリストを管理します。各コンポーネントは、既知のルートとサイズを持つサブツリーを表します。 
3. 2 つのコンポーネントを 1 つの新しいコンポーネントに繰り返しマージします。 コンポーネントを結合するとき$A$そして$B$のルートを割り当てます。$A$のルートを指す$B$、またはその逆により、ルート間に親子関係が作成されます。 結果として得られるコンポーネントのサイズは次のとおりです。$|A| + |B|$。 
4. このマージでスキューを作成するかどうかを決定します。 このマージでスキューが必要な場合は、次のようにします。$|A| \ge 2|B|$または$|B| \ge 2|A|$。 スキューを望まない場合は、$|A| < 2|B|$そして$|B| < 2|A|$これは、サイズを可能な限り近づけた場合にのみ可能です。 
5. 正確に達成するには$k$スキューを考慮して、制御されたバイナリ ツリーの成長を模倣する一連のコンポーネント サイズを構築します。スキューを回避するために同じサイズのコンポーネントを繰り返し組み合わせます。また、場合によっては、スキューを強制するために大きなコンポーネントとはるかに小さいコンポーネントを組み合わせます。 
6. まず、2 の累乗を超えない最大のサイズのコンポーネントを構築します。$n$。 これにより、構造のバイナリ分解が得られます。 
7. 次に選択します$k$これらの組み合わせ間のマージ操作では、シングルトンまたは最小限のコンポーネントを大きなコンポーネントに接続することで意図的に不均衡を導入し、スキュー状態を保証します。 
8. 最後に、マージ履歴を必要な出力配列に変換します。$s$、記録されたマージに従って各ノードに 1 つの子を正確に割り当て、設定します。$s_i = 0$最後のシンクノードの場合。 

### なぜ効果があるのか

 この構造により、グローバルなスキュー状態がマージ ポイントでのローカルな比較に軽減されます。 各マージは、構築時に 2 つの親側サブツリーが完全に決定される 1 つのノードに正確に対応します。 コンポーネントのサイズは明示的に維持されるため、以前に作成されたマージが歪んでいるかどうかを後の操作で変更することはできません。 この独立性により、意図的に不均衡なマージごとにスキューが 1 回だけカウントされることが保証され、意図しない不均衡が他の場所で発生することはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())

    # We construct components as (size, root)
    # Each node starts as its own component
    comp = [(1, i) for i in range(1, n + 1)]
    parent = [0] * (n + 1)

    # We will greedily merge components; we track skew usage
    skews_left = k

    while len(comp) > 1:
        comp.sort()
        a_size, a_root = comp.pop()
        b_size, b_root = comp.pop()

        # decide if we force skew
        if skews_left > 0 and a_size >= 2 * b_size:
            # force skew: attach b under a
            parent[b_root] = a_root
            comp.append((a_size + b_size, a_root))
            skews_left -= 1
        else:
            # avoid skew: attach smaller under larger carefully
            parent[a_root] = b_root
            comp.append((a_size + b_size, b_root))

    # if we still have skews left, impossible under this construction
    if skews_left != 0:
        print("NO")
        return

    print("YES")
    print(*parent[1:])

if __name__ == "__main__":
    solve()
```このソリューションでは、すべてのマージ操作がサブツリー サイズに既知の影響を与えるように、明示的なコンポーネントとサイズが維持されます。 貪欲な選択では、十分に不均衡なペアが存在する場合は常に、スキューの機会を利用しようとします。 使用しないときは、偶発的なスキューの発生を避けるために、常に小さい構造を大きい構造の下に取り付けます。 

親配列は関数グラフを直接エンコードします。 各マージでは親ポインターが 1 つだけ割り当てられ、最終的な構造が「ノードごとに 1 つの子」ルールに従っていることが保証されます。 

実装の微妙な詳細は、反復ごとにコンポーネントをソートすることです。 これにより、常に最も有望な候補を最初にスキューをテストすることが保証されます。 これがないと、有効なスキュー配置を見逃して、不可能であると誤って結論付ける可能性があります。

 ## 特殊なケース

 のために$n = 1$、マージは不可能であるため、スキュー イベントは発生しません。 このアルゴリズムは、次のような単一ノード構造を即座に出力します。$s_1 = 0$、唯一の有効な構成と一致します。 

のために$k > 0$非常に小さい$n$、 のような$n = 2, k = 1$の場合、どのマージにも 2 つのシングルトンが含まれ、2 倍の差を満たすことができないため、この構造では不均衡条件を満たすマージが見つかりません。 このアルゴリズムは、スキュー クォータを消費せずにコンポーネントを使い果たすことで正しく拒否します。 

大型用$n$そして$k = 0$、プロセスでは常に、小さなコンポーネントが大きなコンポーネントの下にバランスよく取り付けられます。 各マージではサイズがほぼ均等に維持され、偶発的なスキューの作成が防止されます。 最終的な構造はほぼバランスのとれたマージ チェーンとなり、スキュー条件を満たすノードはなく、正確性が保たれます。
