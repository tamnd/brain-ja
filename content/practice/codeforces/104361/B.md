 ## 解決策
 ## 問題の理解

 私たちに与えられた花束には、まさにその内容が含まれていなければなりません`n`花、そしてそこにあります`m`花の種類。 各種類は何度でもご利用いただけます。 

タイプの報酬モデルは花ごとに一定ではありません。 私たちが取るなら`x`種類の花`i`、最初の人が貢献します`a_i`、そして次のすべてが貢献します`b_i`。 したがって、そのタイプの合計貢献度は次のようになります。`a_i + (x - 1) * b_i`いつ`x > 0`、 そして`0`いつ`x = 0`。 

タスクは合計を分配することです`n`貢献度の合計を最大化するために、さまざまな種類の花を咲かせます。 

重要な問題は、型の限界値が最初の選択後に変化することです。 ある種類の最初の花は、後続の花とは大きく異なる可能性があるため、単純に貪欲な戦略は、`b_i`またはオンのみ`a_i`失敗します。 

制約は大きいです:`n`まで行くことができます`10^9`、 その間`m`までです`100000`。 これにより、花を 1 つずつ摘むことをシミュレートしたり、花ごとの決定を維持したりするアプローチは即座に除外されます。 正しい解決策では、問題を O(m) または O(m log m) の前処理に減らす必要があります。 

型のサイズが非常に大きい場合、単純な推論による微妙な失敗のケースが発生します。`a_i`でも小さい`b_i`、またはその逆。 たとえば、あるタイプが`(a, b) = (100, 1)`そしてもう一人は`(1, 100)`、最初の選択が割り当ての残りの構造と相互作用するため、最初または 2 番目のゲインのみに基づいた貪欲な選択は誤解を招きやすいです。 

## アプローチ

 ブルートフォースのアイデアは単純です。 花の数は私たちが決めます`x_i`各タイプから取得し、すべての有効な分布を試して合計寄与度を直接計算します。 これは正確な式を評価するため正しいですが、分布の数は天文学的に膨大です。 それぞれに上限を設けたとしても`x_i`で`n`、整数パーティションの数`n`の中へ`m`部分は実行可能な計算をはるかに超えています。 これは次の場合にすぐに失敗します`n`数十を超えます。 

報酬関数の構造は、最初の要素以降は線形です。 各型はシーケンスのように動作します: 1 つの特別な値`a_i`、その後に無限のストリームが続きます`b_i`。 これは、問題を限界寄与の選択に変えることを示唆しています。 

直接限界ビューでは、タイプごとにゲインの無限シーケンスが生成されます。`a_i, b_i, b_i, b_i, ...`。 タスクは最適なものを選択することになります`n`これらすべてのシーケンスにわたる値。 The issue is that each sequence is infinite, so we cannot explicitly enumerate candidates.

 重要な観察は、最高のものだけが`b_i`すべての「非1位」指名にとって世界的に重要です。 多くの花を採取すると、追加の花はその種類の分のみを提供します。`b_i`したがって、私たちはそれらの貢献をできるだけ大きくしたいと考えています。 これは、どのような最適解でも、最初以外の選択のほとんどすべてが最大値を持つタイプから来るべきであることを示唆しています。`b_i`、より小さいものを使用しているため、`b_i`合計が減ります。 

これにより、すべてを分散するのではなく、構造が崩壊します。`n`アイテムを任意に、最大の 1 つの主要なタイプを扱います。`b_i`ベースフィラーとして使用し、それらのベースピックの一部を他のタイプの最初のピックで「置き換える」ことが有益かどうかのみを考慮します。

 ## アルゴリズムのチュートリアル

 すべてを可能な限り最良の「デフォルト」タイプと比較することに絞ります。 

### ステップ

 1. すべての値の中から最大値を見つけます`b_i`、それを呼びます`B`。 

これは、最初の花の後に追加される花ごとに可能な最高の値を表します。 
2. すべてが満たされるベースライン ソリューションから始めます。`n`花は価値のある種類から来ると想像されます`B`。 

これにより、基本寄与率は次のようになります。`n * B`。 
3. 種類ごとに`i`、ベースライン タイプのみを使用するのではなく、少なくとも 1 回使用した場合の効果を計算します。 

タイプを紹介すると`i`、そこから花を1つ取ります。`a_i`の代わりに`B`。 これにより合計が変わります`a_i - B`。 
4. もし`a_i - B > 0`、このタイプを少なくとも 1 回含めると有益です。 この値を答えに追加します。 
5. ステップ 4 からのプラスの寄与をすべて合計し、ベースラインに追加します。`n * B`。 

### なぜ効果があるのか

 重要な不変条件は、最初の花以降のすべての花はその型内で同じように動作し、それらの位置の型間の唯一のグローバルな区別は次の値であるということです。`b_i`。 したがって、特別でないすべてのポジションに対する可能な限り最良の割り当ては、常に最大値になります。`b_i`。 

このベースラインが固定されると、そこからのあらゆる逸脱は、タイプの最初の選択によってのみ発生します。 このような各偏差は、1 つのベースライン項目に相当するものを置き換えます`B`最初のアイテム相当の`a_i`、利益を生み出す`a_i - B`。 置き換えられたすべての位置が独立しており、残りの構造は依然として次の値で満たされているため、偏差間にはそれ以上の相互作用は存在しません。`B`。 この独立性により、すべての正のゲインを合計すると最適な構成が得られることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    
    a = []
    b = []
    
    B = 0
    for _ in range(m):
        ai, bi = map(int, input().split())
        a.append(ai)
        b.append(bi)
        if bi > B:
            B = bi

    ans = n * B
    
    for i in range(m):
        gain = a[i] - B
        if gain > 0:
            ans += gain

    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションでは、まずユニットあたりの最も強い成長率を特定します。`B`。 次に、すべての花が寄与すると仮定します。`B`、きれいなベースラインを形成します。 各タイプは、その最初の花がそのベースラインより強いかどうかをチェックすることによって個別に評価されます。 そうであれば、1 つのベースラインの花をそのタイプの最初の花に置き換えることによって、ソリューションをアップグレードします。 

よくある落とし穴は、各種類の花の数をシミュレーションしようとすることです。 ベースラインが固定されると、追加されるすべての花の寄与がすでに決定されるため、これは不要です。

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

 ## 特殊なケース

 例外的なケースは、すべての場合に発生します。`b_i`等しいです。 この状況では、ベースラインはすべてのタイプで共有され、解決策は純粋に最高のタイプを選択することになります。`a_i`。 アルゴリズムはこれを自然に処理します。`a_i - B`独立して評価されます。 

別のケースは、最良の場合です。`a_i`小さいタイプに属します`b_i`。 最初の値がグローバル ベースラインを超えた場合でも、アルゴリズムにはその値が含まれます。これは、その置換がその値に関係なく常に有益であるためです。`b_i`。 

最後に、いつ`n = 1`、答えは簡単です。`max(a_i)`、2番目のピックが存在しないため。 この式は正しく減少します。`n * B + max(a_i - B)`単純化すると`max(a_i)`。
