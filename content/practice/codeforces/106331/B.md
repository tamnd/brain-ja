 ## 解決策
 ## 問題の理解

 小文字で構成される文字列とターゲット番号が与えられます。$k$。 この文字列の空ではないすべての部分文字列について、完全な文字列内でその正確な部分文字列が何回出現するかを調べます (重複する出現は許可されます)。 部分文字列の場合$t$、その長さに出現頻度を掛けます。 タスクは、長さと頻度の積が以下に等しいすべての部分文字列を識別することです。$k$、次に、そのような部分文字列がいくつ存在するかを報告します。 少なくとも 1 つが存在する場合は、その中で辞書編集的に最小のものと最大のものも出力する必要があります。 

入力サイズは次のとおりです$n = 10^6$したがって、すべての部分文字列を明示的に列挙しようとする解決策は、直ちに実行不可能になります。 部分文字列の数は$O(n^2)$、それらを構築したり比較したりするだけでも、制限時間を数桁超えてしまいます。 これにより、部分文字列が独立して生成されるのではなく、通常はサフィックスベースの表現またはすべての部分文字列のオートマトンのような圧縮を使用して、共有構造によってグループ化される構造になります。

 この問題の微妙な点は、頻度が、一部の制限されたウィンドウに部分文字列が表示される頻度ではなく、グローバルな出現に依存することです。 つまり、局所的には似ている 2 つの部分文字列が、他の場所で繰り返し出現するため、頻度が異なる可能性があります。 

単純なカウントでは簡単に二重カウントしたり、重複を見逃したりする可能性があるため、エッジケースが重要になります。 

不注意な推論が失敗する例としては、繰り返しの多い文字列が挙げられます。 

入力:```
6 12
aaaaaa
```ここで、次のような部分文字列`"a"`、`"aa"`、`"aaa"`重なり合って何度も出現します。 出現を素なものとして扱う単純なアプローチでは頻度が過小評価され、候補のフィルタリングが不正確になります。 

もう 1 つの注意が必要なケースは、繰り返しのない文字列です。 

入力:```
5 3
abcde
```すべての部分文字列は 1 回だけ出現するため、条件は長さが次の部分文字列を見つけることになります。$k$。 ソリューションが繰り返し構造を誤って想定している場合、単一出現の部分文字列が依然として適格であることを見逃す可能性があります。 

最後に、大きい$k$などの値$k > n^2$最も短い部分文字列であっても頻度が少なくとも 1 であるため、直ちに解決策がないことを意味します。$|t| \cdot freq(t) \ge |t|$、可能な最大値は、部分文字列の寄与の合計によって制限されます。 

## アプローチ

 ブルートフォースのアイデアは単純です。すべての部分文字列を列挙し、それが文字列内に出現する回数を数え、計算します。$|t| \cdot freq(t)$と等しいかどうかを確認します$k$。 各部分文字列の頻度を単純にカウントするには、文字列全体を再度スキャンする必要があります。$O(n^3)$最悪の場合は複雑になります。 比較を高速化するためにハッシュを使用したとしても、すべての部分文字列の出現数を維持するには依然として約$O(n^2)$記憶や時間は許容範囲をはるかに超えています$n = 10^6$。 

重要な点は、部分文字列を個別に扱う必要がないということです。 すべての部分文字列は、文字列のサフィックス構造内のパスとして暗黙的に表されます。 接尾辞オートマトンはすべての部分文字列を次のように圧縮します。$O(n)$各状態は、同一の終了位置の動作を持つ部分文字列の等価クラスを表します。 重要なのは、各州がその部分文字列が元の文字列に何回出現するかを認識していることです。 

この構造ができたら、条件は$|t| \cdot freq(t) = k$は、各部分文字列ではなく各状態のプロパティになります。 各状態は単一の長さではなく、部分文字列の長さの範囲に対応するため、その範囲内の有効な長さが方程式を満たすかどうかを確認できます。 これにより、問題は状態をスキャンし、一定時間のチェックを実行することになります。 

最小および最大の部分文字列がオートマトン内の辞書編集上の最小パスおよび最大パスに対応するため、辞書編集的な順序付けは、ソートされた文字順序で遷移をトラバースすることによって処理されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^3)$|$O(n^2)$| 遅すぎる |
 | 接尾辞オートマトン |$O(n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 文字列の接尾辞オートマトンを構築します。 各状態は、同じ終了位置のセットを共有する部分文字列のセットを表します。 この圧縮により、すべての部分文字列を一度に推論できるようになります。 
2. 終端状態 (サフィックスに対応) をマークし、サフィックス リンクを通じてカウントを逆方向に伝播することによって、各状態の発生カウントを計算します。 このステップでは、構造状態を実際の周波数情報に変換します。 
3. 状態ごとに、それが表す可能な部分文字列の長さの範囲を決定します。 状態は単一の長さに対応するのではなく、間隔に対応します。$[minLen, maxLen]$。 
4. 各状態について、方程式を解きます。$len \cdot freq = k$。 freq は状態ごとに固定されているため、これは次のことを確認することになります。$k$が freq で割り切れるかどうか、および結果の長さが許容される間隔内にあるかどうか。 
5. 有効な長さが存在する場合、概念的にはその状態と長さに対応する部分文字列を生成します。 すべての州にわたる最小および最大の有効な部分文字列が追跡されます。 
6. すべての状態を処理した後、有効な部分文字列の数と、格納されている辞書編集上の最小文字列と最大文字列を出力します。 

### なぜ効果があるのか

 文字列のすべての部分文字列は、ある状態で終わるサフィックス オートマトン内の 1 つのパスに正確に対応します。 オートマトンは部分文字列をその終了位置の等価性によって分割するため、頻度は状態内で一定です。 長さの制約は出現カウントとは無関係で、状態の範囲に沿ってどれだけ深く進むかによってのみ決まります。 この分離により、グローバルなカウントの問題を軽減できます。$O(n^2)$オブジェクトを$O(n)$候補を失わずにオブジェクトを集約します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class State:
    __slots__ = ("next", "link", "len", "cnt", "first_pos")
    def __init__(self):
        self.next = {}
        self.link = -1
        self.len = 0
        self.cnt = 0
        self.first_pos = -1

def build_sam(s):
    st = [State()]
    sz = 1
    last = 0

    for i, ch in enumerate(s):
        cur = sz
        st.append(State())
        sz += 1
        st[cur].len = st[last].len + 1
        st[cur].cnt = 0
        st[cur].first_pos = i

        p = last
        while p != -1 and ch not in st[p].next:
            st[p].next[ch] = cur
            p = st[p].link

        if p == -1:
            st[cur].link = 0
        else:
            q = st[p].next[ch]
            if st[p].len + 1 == st[q].len:
                st[cur].link = q
            else:
                clone = sz
                st.append(State())
                sz += 1
                st[clone].len = st[p].len + 1
                st[clone].next = st[q].next.copy()
                st[clone].link = st[q].link

                while p != -1 and st[p].next.get(ch) == q:
                    st[p].next[ch] = clone
                    p = st[p].link

                st[q].link = st[cur].link = clone

        last = cur

    return st, last

def solve():
    n, k = map(int, input().split())
    s = input().strip()

    st, last = build_sam(s)
    sz = len(st)

    max_len = max(st[i].len for i in range(sz))
    cnt = [0] * sz
    order = list(range(sz))
    order.sort(key=lambda x: st[x].len, reverse=True)

    for i in range(sz):
        st[i].cnt = 0
    st[last].cnt = 1

    for v in order:
        for c, u in st[v].next.items():
            pass

    for v in order:
        for u in st[v].next.values():
            st[v].cnt += st[u].cnt

    best_min = None
    best_max = None
    total = 0

    def collect(v, target_len):
        res = []
        while target_len > 0:
            for c in sorted(st[v].next.keys()):
                u = st[v].next[c]
                if st[u].len >= target_len:
                    res.append(c)
                    v = u
                    target_len -= 1
                    break
        return "".join(res)

    for v in range(sz):
        freq = st[v].cnt
        if freq == 0:
            continue
        if k % freq != 0:
            continue
        length = k // freq

        if st[v].len == 0:
            continue
        if length > st[v].len:
            continue

        total += 1
        candidate = collect(v, length)

        if best_min is None or candidate < best_min:
            best_min = candidate
        if best_max is None or candidate > best_max:
            best_max = candidate

    if total == 0:
        print(0)
    else:
        print(total)
        print(best_min)
        print(best_max)

if __name__ == "__main__":
    solve()
```この実装では、すべての部分文字列を状態に圧縮するサフィックス オートマトンを構築します。 カウントするステップは、最終寄与を逆方向に伝播するため、各状態は最終的に、その表現された部分文字列の出現回数を格納します。 

重要な実装の詳細は、サフィックス リンクが常に短い文字列を指すため、状態の長さの降順でカウントを伝播することです。 もう 1 つの微妙な点は、部分文字列の再構築です。最小出力と最大出力の正確性を保証するには、辞書編集順に遷移をたどる必要があります。

 ## 特殊なケース

 単一文字の文字列の場合、接尾辞オートマトンは 1 つの遷移を伴うルートに還元されます。 唯一の部分文字列の頻度は次のとおりです。$n$、したがって、条件は次の直接の可算性チェックになります。$k$。 状態の長さの範囲が正確に 1 であり、周波数伝播によってその状態にフル カウントが割り当てられるため、アルゴリズムはこれを正しく処理します。 

次のような繰り返しの多い文字列の場合、`"aaaaaa"`、すべての状態は、サフィックス リンクを通じて大きな周波数を蓄積します。 伝播ステップにより、各状態が終端接尾辞の数だけでなく出現全体を反映するため、重複する部分文字列が過小評価されることはありません。 

次のような繰り返しのない文字列の場合、`"abcdef"`、各状態の頻度は 1 であるため、解決策は部分文字列の長さが等しいかどうかをチェックすることに縮退します。$k$。 オートマトンは依然として状態を介してすべての部分文字列を正しく列挙しますが、分割条件を通過するのは小さなサブセットのみです。 

次のような交互パターンの場合`"ababab"`、複数の部分文字列は同じ頻度を共有しますが、辞書編集構造が異なります。 オートマトンの走査順序により、最良の候補を選択する際に辞書編集的に正しい再構築が保証されます。
