 ## 解決策
 ## 問題の理解

 最大 18 都市にわたる方向のない道路網があります。 既存のすべての道路には、可能な 2 つの方向のうちの 1 つを割り当てる必要があり、選択された方向によって有向グラフ全体が強く接続される必要があります。 コストは個々の道路の選択された方向に依存するため、タスクは最も安価な有効な方向を見つけるか、有効な方向が存在しないことを報告することです。 

の小さな値`N`が主な手がかりです。 18 の都市には、`2^18`可能なサブセットは約 262,000 です。 これにより、すべてのエッジのすべての方向を試行するものは除外されます。これは、疎なグラフでも多くのエッジが存在する可能性があり、方向の数は道路の数に応じて指数関数的に増加するためです。 ソリューションでは、ビットマスク動的プログラミングを指す頂点制限を直接使用する必要があります。 

いくつかのケースは見落とされやすいものです。 グラフがまったく接続されていない場合、方向を指定してもすべての都市に到達できなくなります。```
3
-1 5 -1
5 -1 -1
-1 -1 -1
```答えは`-1`都市3は孤立しているからです。 ローカル エッジの選択のみをチェックする方法では、すべての道路が独立して方向付けられると誤って想定される可能性があります。 

2 番目のトラップは、接続されているがブリッジがあるグラフです。```
3
-1 1 -1
1 -1 2
-1 2 -1
```答えは`-1`。 一方の側ともう一方の側の間の唯一の道路としてどの方向を選択しても、一方の終点に戻ることができなくなります。 強力な接続には、通常以上の接続が必要です。 

選択した構造にすべてのエッジがすでに含まれている場合、実装に関する最終的な問題が発生します。 例えば：```
2
-1 7
3 -1
```考えられる唯一のオリエンテーション費用`7`道路が都市 1 から都市 2 に向かう場合、`3`反対方向に。 答えは`3`。 両方の方向を選択する必要がある、または常に安価な方向のみを使用できると想定するソリューションは失敗します。 

## アプローチ

 直接的なアプローチでは、すべての道路の可能な方向をすべて試し、強く接続された有向グラフを生成する最も安価な方向を維持します。 考えられるすべての答えが検討されるため、これは正しいです。 ただし、ある場合は、`m`道路、検索スペースにはサイズがあります`2^m`。 18 都市の場合、グラフには 153 本の道路が存在する可能性があり、これは完全に不可能になります。 

有用な観察は、強く接続された有向グラフの特徴付けから得られます。 強接続グラフは、1 つの頂点から開始して、「耳」を繰り返し追加することによって構築できます。これは、すべての内部頂点が新しい一方で、端点が現在の強接続部分の内側にすでにある有向パスです。 最初の頂点はすでに有効な開始時の強接続グラフであり、追加された各耳は強い接続性を維持します。 

これにより、問題はサブセット DP に変わります。 すべてのエッジを一度に決定するのではなく、すでに強力に接続された一連の都市を構築するための最も安価な方法を維持します。 その状態から、新しい都市を紹介する次の耳を探します。 

コストに関するトリックがもう 1 つあります。 すべての道路は最終的に方向を決定する必要があるため、最初にすべての道路の安い方向に支払います。 後でより高価な方向を選択した場合、追加の差額を支払うだけです。 これにより、DP は追加コストのみを最小限に抑えるように変更され、建設中に未使用の道路について心配する必要がなくなります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^m) | O(m) | 遅すぎる |
 | 耳の分解 DP | O(2^N N^3) | O(2^N N^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての道路について、両方向のコストのうち安い方を両方向から差し引きます。 これらすべての安価なコストを基本的な答えに追加します。 残りの値は、安くない方向を選択した場合の追加料金を表します。 
2. しましょう`f[mask]`都市を作るために必要な最小限の追加コストであること`mask`強くつながっている。 市を直す`0`が初期都市であるため、有効な開始状態は次のとおりです。`mask = 1`。 
3. 別の DP 状態を維持する`g[mask][x][y][b]`。 これは、現在のエンドポイントが次のような耳を現在構築していることを意味します。`x`、既存のコンポーネント内の最終エンドポイントは`y`、 そして`b`ダイレクトエッジを使用するかどうかを示します`x -> y`許可されています。 
4. 耳が最終終点に到達するたびに、最後の端で耳を閉じて更新します。`f[mask]`。 追加のフラグが存在する理由は、終了エッジのみを含むパスが構築中に常に有効であるとは限らないためです。 
5. 強く接続されたすべての状態から、新しい耳を開始します。 すでにコンポーネント内にある 2 つの都市をエンドポイントとして選択し、1 つの出力エッジをコンポーネントの外側の都市に取得します。 
6. 現在のエンドポイントから現在のセット外の新しい都市に移動して、未完成の耳を拡張します。 このような遷移ごとに、そのエッジの残留コストが追加されます。 
7. すべてのサブセットを処理した後、`f[(1 << N) - 1]`強く接続された方向性のための最小限の追加コストが含まれています。 基本コストを追加して戻します。 この状態が存在しない場合、グラフを強く接続することができません。 

なぜ機能するのか: 不変条件は、到達可能なすべてのものが`f[mask]`は、正確に都市の有効な強く関連した方向性を表します。`mask`。 新しい頂点には既存のコンポーネントへの出入りの方向のあるパスがあるため、耳を追加すると強力な接続が維持されます。 逆に、強く接続されたすべての有向グラフには耳分解があるため、これらの遷移の 1 つのシーケンスによって最適な方向を生成できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    cost = [list(map(int, input().split())) for _ in range(n)]

    base = 0
    for i in range(n):
        for j in range(i + 1, n):
            if cost[i][j] != -1:
                mn = min(cost[i][j], cost[j][i])
                base += mn
                cost[i][j] -= mn
                cost[j][i] -= mn

    total = 1 << n
    inf = 10**18

    f = [inf] * total
    g = [dict() for _ in range(total)]

    f[1] = 0

    for mask in range(1, total):
        if (mask & 1) == 0:
            continue

        cur = g[mask]

        for (u, v, can_close), val in list(cur.items()):
            if can_close and cost[u][v] != -1:
                nv = val + cost[u][v]
                if nv < f[mask]:
                    f[mask] = nv

        if f[mask] != inf:
            vertices = [i for i in range(n) if mask >> i & 1]
            for u in vertices:
                for v in vertices:
                    key = (u, v, 0)
                    if f[mask] < cur.get(key, inf):
                        cur[key] = f[mask]

        for (u, v, can_close), val in list(cur.items()):
            for w in range(n):
                if mask >> w & 1:
                    continue
                if cost[u][w] == -1:
                    continue
                nmask = mask | (1 << w)
                ncan = 1 if (can_close or u != v) else 0
                key = (w, v, ncan)
                nv = val + cost[u][w]
                if nv < g[nmask].get(key, inf):
                    g[nmask][key] = nv

    ans = f[-1]
    if ans == inf:
        print(-1)
    else:
        print(base + ans)

if __name__ == "__main__":
    solve()
```前処理部分は、元のコストを「追加コスト」に変換します。 すべてのエッジは可能な限り安価な方向を即座に提供し、DP は他の方向が必要な場合にのみ料金を支払います。 

の`f`配列には完成した耳が格納され、内部の辞書は`g`部分的に構築された耳を保管します。 多くの理論的状態は決して発生しないため、完全な 4 次元配列の代わりに辞書が使用されます。 

各マスクの操作の順序が重要です。 完成した耳は、最初に強く接続された状態を更新するために使用されます。 そして、その改善された状態から新しい耳が始まり、最終的にその耳がより大きなマスクに拡張されます。 遷移は頂点を追加するだけであるため、将来のすべての状態はより大きなビットマスクを持ち、後で処理されます。 

## 実用的な例

 最初のサンプルでは、すべての道路から最も安価な方向コストを削除した後、DP は 1 つの強く接続された方向を作成するために必要な方向変更の費用のみを支払う必要があります。 

| マスク | アクション | 状態 |
 | --- | --- | --- |
 |`{1}`| 開始 | 1 つの都市の強力に接続されたコンポーネント |
 |`{1,2}`| 最初の耳の頂点を追加 | コンポーネントが成長する |
 |`{1,2,3,4}`| 最後の耳を閉じる | 写真 すべての都市が双方向で接続 |

 最終的な追加費用は前払い費用に加算され、次のようになります。`27`。 

2 番目のサンプルでは、​​グラフは 1 つの接続で接続された 2 つの密な部分で構成されています。 DP は、欠落したリターン パスを導入するイヤーを構築できません。 

| マスク | アクション | 状態 |
 | --- | --- | --- |
 |`{1}`| 開始 | 初期コンポーネント |
 |`{1,2,3}`| 最初の側を展開 | まだリターンパスがありません |
 |`{1,2,3,4,5,6}`| 試行完了 | 有効な閉じ耳がありません |

 マスク全体には到達できないため、答えは次のようになります。`-1`。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(2^N N^3) | すべてのサブセットには耳の状態を含めることができ、遷移では可能なエンドポイントと次の頂点が試行されます。 
| スペース | O(2^N N^2) | 保存された未完成の耳は、サブセットとエンドポイントのペアの数によって制限されます。 

と`N <= 18`、サブセット数は、この動的プログラミング手法にとって十分に小さいです。 多項式係数は大きくなりますが、マスクの数は管理可能なままです。
