 # 問題の理解

 頂点 1 をルートとするルート付きツリーがあります。 各頂点には多数の人々が格納されますが、最初はゼロです。 2種類のアップデートを繰り返し適用します。 1 回の更新により、選択したサブツリー内のすべての頂点の数が増加します。 もう 1 つは、2 つの頂点間の選択されたパス上のすべての頂点の数を増やします。 

更新のたびに、現在の人口分布の集合点を見つける必要があります。 頂点 x の場合、コストは x からすべての頂点までの距離の合計であり、そこにいる人の数で重み付けされます。 最小のコストで頂点を出力する必要があります。複数の頂点のコストが同じ場合は、ルートに最も近い頂点を選択します。 これは、ツリーの最も浅い加重重心です。 

この制約により、更新のシミュレーションから遠ざけられます。 最大 100,000 個の頂点と 100,000 回の操作がある場合、クエリの影響を受けるすべての頂点に触れると、最悪の場合、約 10^10 の操作が必要になります。 単一の大きなサブツリー更新でも、ほぼすべての頂点が含まれる可能性があるため、ソリューションでは操作ごとに対数またはほぼ対数の作業が必要になります。 

厄介なケースは、同点や、同じ重みを持つ大きな接続領域によって引き起こされます。 たとえば、3 つの頂点を持つパスを考えてみましょう。```
3
1 2
2 3
3
1 2
1 3
1 1
```最初の 2 つの更新後の重みは次のようになります。`[0,1,1]`。 頂点 2 からの総コストはどちらのエンドポイントからのコストよりも小さいため、最適な頂点は 2 です。 最後の更新の後、重みは次のようになります。`[1,1,1]`。 一部の重心問題では、頂点 1 と頂点 2 の両方が同様の動作をする可能性がありますが、この問題ではルートに最も近い頂点が必要となるため、重心のみを見つけるソリューションは失敗する可能性があります。 

もう 1 つのエッジ ケースは、両方のエンドポイントが同じ頂点である単一パスの更新です。 例えば：```
2
1 2
2
2 1 1
1 2
```最初の操作では頂点 1 のみが増加します。2 番目の操作では頂点 2 のみが増加します。すべてのパス更新が少なくとも 2 つの頂点に接触すると仮定するソリューションでは、最初のクエリが誤って処理されます。 

## アプローチ

 直接的な解決策は簡単です。 すべての頂点の現在の重みを保存し、更新のたびにすべての頂点を試してその重み付けされた距離の合計を計算することで、最適な収集ポイントを計算します。 これが機能するのは、目的関数がまさに問題が求めているものであるためです。 ただし、答えを再計算するには、ツリーを繰り返し走査する必要があります。 最悪の場合、これはクエリごとに O(n^2) になります。これは、n と q が 100000 に近い場合には不可能です。 

重要な点は、実際には距離の合計全体が必要ないということです。 重み付けされた重心には構造的な特性があります。つまり、ツリーを重心にルートすると、子サブツリーには総重量の半分を超える値が含まれなくなります。 同様に、ルートから全人類の半分以上を含むサブツリーに向かって歩くとき、私たちは重心に向かって移動することを余儀なくされます。 

これを利用するために、重光分解を使用してツリーを平坦化します。 これにより、2 つの便利な機能が得られます。 範囲の追加として任意のサブツリーに 1 つを追加でき、一連のヘビー-ライト範囲追加として任意のパスに沿って 1 つを追加できます。 

セグメント ツリーには、DFS 順序で重みが格納されます。 また、すべてのセグメントの合計重みも保存されるため、プレフィックスの合計が総母集団の半分に達する最初の DFS 位置を見つけることができます。 この位置の頂点は、ルートから答えまでのパス上にある必要があります。 それを見つけた後、祖先をたどって、最も浅い有効な加重重心を見つけます。 

ブルートフォース手法はツリーの構造を繰り返し無視するため失敗します。 半分の重みのサブツリーに関する観察により、グローバル最適化問題を少数の祖先チェックに置き換えることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | クエリあたり O(n^2) | O(n) | 遅すぎる |
 | 最適 | クエリあたり O(log^2 n) | O(n log n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ツリーの重光分解を構築します。 すべての頂点の親、その深さ、サブツリーのサイズ、DFS 順序での位置を計算します。 
2. DFS 順序で遅延セグメント ツリー内の現在の頂点の重みを維持します。 サブツリーは 1 つの連続する DFS 間隔に対応するため、サブツリーの更新は 1 つの範囲の追加になります。 
3. パスを更新するには、重鎖を繰り返しジャンプします。 すべてのチェーン セグメントは DFS 順序で連続しているため、各部分はセグメント ツリー範囲の追加になります。 
4. 各更新後、総人口を S とします。プレフィックスの合計が少なくとも 1 である最初の DFS 位置を見つけます。`(S + 1) // 2`。 その頂点を u とします。 

この頂点が役立つ理由は、DFS 順序がすべてのサブツリーを連続した間隔にグループ化するためです。 重量の半分に達する最初の場所は、重心を含む固有の重い側を識別します。 

1. u から開始して、バイナリ リフティングで上に移動します。 祖先候補 v については、そのサブツリーの重みを確認します。 v のサブツリーに全人々の最大でも半分が含まれる場合、答えは v より下に存在することはできないため、v より上に移動します。 
2. ジャンプ後、直接の親をもう一度確認し、結果の頂点を出力します。 

なぜ効果があるのか:

 重み付き重心条件では、重心を削除した後、残りのすべての接続コンポーネントの重みが最大でも全体の半分になることを示します。 DFS プレフィックス検索は、依然として多すぎるウェイトを含むことができる唯一のコンポーネント内の頂点を見つけます。 どの重心もその頂点の祖先でなければなりません。 サブツリー条件が有効になるまで上に移動すると、最も浅い重心が正確に見つかります。これは、すべての無効な祖先がまだ重みの半分以上を含む子方向を持っているためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(300000)

def solve():
    n = int(input())
    g = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)

    parent = [[0] * 17 for _ in range(n + 1)]
    depth = [0] * (n + 1)
    size = [0] * (n + 1)
    heavy = [0] * (n + 1)

    def dfs(u, p):
        parent[u][0] = p
        size[u] = 1
        best = 0
        for v in g[u]:
            if v == p:
                continue
            depth[v] = depth[u] + 1
            dfs(v, u)
            size[u] += size[v]
            if size[v] > best:
                best = size[v]
                heavy[u] = v

    dfs(1, 0)

    for j in range(1, 17):
        for i in range(1, n + 1):
            parent[i][j] = parent[parent[i][j - 1]][j - 1]

    tin = [0] * (n + 1)
    tout = [0] * (n + 1)
    top = [0] * (n + 1)
    order = [0] * (n + 1)
    timer = 0

    def decompose(u, h):
        nonlocal timer
        timer += 1
        tin[u] = timer
        order[timer] = u
        top[u] = h
        if heavy[u]:
            decompose(heavy[u], h)
        for v in g[u]:
            if v != parent[u][0] and v != heavy[u]:
                decompose(v, v)
        tout[u] = timer

    decompose(1, 1)

    class SegTree:
        def __init__(self, n):
            self.n = n
            self.sum = [0] * (4 * n)
            self.lazy = [0] * (4 * n)

        def add_node(self, p, l, r, x):
            self.sum[p] += (r - l + 1) * x
            self.lazy[p] += x

        def push(self, p, l, r):
            if self.lazy[p]:
                m = (l + r) // 2
                x = self.lazy[p]
                self.add_node(p * 2, l, m, x)
                self.add_node(p * 2 + 1, m + 1, r, x)
                self.lazy[p] = 0

        def add(self, p, l, r, ql, qr, x):
            if ql <= l and r <= qr:
                self.add_node(p, l, r, x)
                return
            self.push(p, l, r)
            m = (l + r) // 2
            if ql <= m:
                self.add(p * 2, l, m, ql, qr, x)
            if m < qr:
                self.add(p * 2 + 1, m + 1, r, ql, qr, x)
            self.sum[p] = self.sum[p * 2] + self.sum[p * 2 + 1]

        def get_range(self, p, l, r, ql, qr):
            if ql <= l and r <= qr:
                return self.sum[p]
            self.push(p, l, r)
            m = (l + r) // 2
            res = 0
            if ql <= m:
                res += self.get_range(p * 2, l, m, ql, qr)
            if m < qr:
                res += self.get_range(p * 2 + 1, m + 1, r, ql, qr)
            return res

        def first_half(self, p, l, r, x):
            if l == r:
                return l
            self.push(p, l, r)
            m = (l + r) // 2
            if self.sum[p * 2] >= x:
                return self.first_half(p * 2, l, m, x)
            return self.first_half(p * 2 + 1, m + 1, r, x - self.sum[p * 2])

    seg = SegTree(n)

    def path_add(u, v):
        while top[u] != top[v]:
            if depth[top[u]] < depth[top[v]]:
                u, v = v, u
            seg.add(1, 1, n, tin[top[u]], tin[u], 1)
            u = parent[top[u]][0]
        if depth[u] > depth[v]:
            u, v = v, u
        seg.add(1, 1, n, tin[u], tin[v], 1)

    def subtree_sum(u):
        return seg.get_range(1, 1, n, tin[u], tout[u])

    def find_answer():
        total = seg.sum[1]
        u = order[seg.first_half(1, 1, n, (total + 1) // 2)]
        for j in range(16, -1, -1):
            v = parent[u][j]
            if v and subtree_sum(v) * 2 <= total:
                u = parent[v][0]
        if parent[u][0] and subtree_sum(u) * 2 <= total:
            u = parent[u][0]
        return u

    q = int(input())
    ans = []
    for _ in range(q):
        query = list(map(int, input().split()))
        if query[0] == 1:
            u = query[1]
            seg.add(1, 1, n, tin[u], tout[u], 1)
        else:
            path_add(query[1], query[2])
        ans.append(str(find_answer()))

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```DFS 前処理では、祖先ジャンプに使用される親テーブルと、セグメント ツリーで使用されるヘビーライト順序付けが作成されます。 すべての操作は範囲の加算であり、セントロイド検索にはプレフィックスの合計とサブツリーの合計のみが必要であるため、セグメント ツリーには個々の値ではなく合計が格納されます。 

の`first_half`関数は実装の重要な部分です。 格納されたセグメントの合計を使用してセグメント ツリーを下降し、配列をスキャンせずにプレフィックスが必要な半分の重みに達する最初の DFS 位置を見つけます。 

祖先ループは、サブツリーの合計を使用して、上位の頂点がまだ有効であるかどうかを判断します。 2 を乗算すると、浮動小数点比較が回避され、すべての決定が正確に保たれます。

 ## 特殊なケース

 すべての重みが 1 つのサブツリーに集中している場合、アルゴリズムはそのサブツリー内の最初の DFS 位置を見つけます。 その後、祖先の上昇は、ハーフウェイト ルールを満たす最高の頂点で停止します。これにより、より深いが同等の重心を返すことができなくなります。 

パス更新の 2 つのエンドポイントが等しい場合でも、重光分解ではその頂点のみを含む 1 つの最終セグメントが生成されます。 パス操作は自然に単一ポイントの更新に縮退するため、特別な処理は必要ありません。 

いくつかの頂点の最適コストが同じである場合、上向きの移動ルールが重要になります。 このアルゴリズムは、現在の頂点がすでに有効である場合にのみ親に移動します。これは、アルゴリズムが常に可能な限りルートに近く移動し、必要なタイブレーク ルールに一致することを意味します。
