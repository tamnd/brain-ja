 ## 解決策
 ## 問題の理解

 大文字の文字列が与えられます`S`そして小さな整数`k`。 異なる大文字の文字列が何個あるかを数えなければなりません`T`～と同じ長さの`S`～との最長共通部分列を持つ`S`少なくとも長さの`|S|-k`。 答えはモジュロで計算されます`10^9+7`。 

条件はこう言っています`T`とは異なる場合があります`S`LCS メトリックを通して見ると、ほんのわずかな量です。 以来`k`が最大 3 の場合、一致する長さの許容損失はわずかですが、文字列自体には最大 50,000 文字を含めることができます。 二次 LCS の計算には約`2.5 * 10^9`最悪の場合、通常の制限時間をはるかに超えて移行が行われます。 答えは数試合の負けだけを考慮しているという事実を利用する必要があります。 

厄介な点は、2 つの文字列がまったく異なる理由で同じ LCS 長を持つ可能性があることです。 LCS ではサブシーケンスによる並べ替えが許可されているため、不一致の位置をカウントするだけの方法や、文字を貪欲に比較しようとする方法は失敗します。 

最初のエッジケースは、`k = 0`。 例えば：```
S = A
k = 0
```答えは`1`、なぜなら、`T = A`長さ 1 の LCS を持ちます。`k = 0`空の遷移ウィンドウはゼロを返す可能性があるためです。 

もう 1 つの特殊なケースは、文字が繰り返される場合です。```
S = AA
k = 1
```正しい答えは、`5`。 有効な文字列は次のとおりです。`AA`、`AB`、`AC`、 ...、待ってください。アルファベットには 26 文字があり、LCS は少なくとも 1 文字あることに依存するため、この推論は間違っています。`A`。 有効な文字列は、少なくとも 1 つを含む長さ 2 の文字列です。`A`、与える`51`可能性。 ハミング距離に基づくアプローチでは、次のような文字列が誤って拒否されます。`BA`、たとえLCSが1であっても。 

最後によくある間違いが国境近くに現れます。 プレフィックスを処理する場合、LCS テーブルには対角バンドの有効範囲外の位置が含まれます。 例えば：```
S = ABC
k = 1
```最初と最後の文字には完全な文字がありません`k`片側にコンテキストの文字。 すべての状態が常に正確であると仮定すると、`2k+1`位置を変更すると、最初と最後でトランジションが不正確になります。 

## アプローチ

 ブルートフォースのアイデアは、可能なすべての文字列を生成することです`T`そしてそのLCSを次のように計算します`S`。 これは定義を直接チェックするので正しいです。 ただし、`26^n`たとえ小さな文字列であっても、これは爆発的に増加します。 通常の LCS 動的計画アルゴリズムをさらに実行すると、コストがかかります。`O(n^2)`、合計作業量は次のようになります。`O(26^n n^2)`、使用できなくなります。 

内部 LCS 動的プログラミング テーブルを調べると、有益な観察が得られます。 させて`dp(i,j)`最初のLCSになる`i`の登場人物`S`そして最初の`j`の登場人物`T`。 通常、全体が必要になります`n*n`表に記載されていますが、そのほとんどは答えに影響を与えることはできません。 

セルが与える最終的な LCS 寄与の最大値`(i,j)`作成できる範囲は次のとおりです。```
dp(i,j) + min(n-i, n-j)
```最初の項はすでに見つかった一致の数であり、2 番目の項は将来の一致の最大数です。 細胞が重要であるためには、到達可能でなければなりません`n-k`、これは次のことを意味します:```
min(i,j) + min(n-i,n-j) >= n-k
```これは次のように単純化されます。```
|i-j| <= k
```したがって、LCS テーブルの狭い対角バンドのみが重要です。 

2 番目の観察は、隣接する LCS 値が 0 または 1 だけ異なっているということです。 値そのものではなく差分を保存すると、各差分は 1 ビットになります。 取り得る状態の数は少なくなります。`k`小さいです。 対角オフセットと、バンド内の変化を記述するビット パターンを保存します。 州の総数はおおよそ次のとおりです。```
(k+1) * 2^(2k)
```のために`k=3`、これはわずか 256 州です。 

LCS テーブルは生成された文字列が有効かどうかを完全に記述しているため、ブルート フォースは機能しますが、テーブルが大きすぎるため失敗します。 圧縮された対角表現は、将来の遷移に必要な情報を正確に保持し、文字列を生成せずにすべての可能な文字列をカウントすることを可能にします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(26^nn^2) | O(n^2) | 遅すぎる |
 | 最適 | O(26 * n * k^2 * 2^(2k)) | O(k * 2^(2k)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 空のプレフィックスの圧縮 LCS 状態を初期化します。`T`。 現時点では、可能な LCS 値はゼロのみであるため、状態にはゼロ オフセットと空の差分パターンが含まれています。 
2. の文字を加工する`T`左から右へ。 すべての文字列を明示的に選択するのではなく、各圧縮 LCS 状態につながる文字列の数を維持します。 
3. 現在の状態ごとに、可能なすべての文字を追加してみます。 この遷移は、LCS 動的プログラミング テーブルの 1 つの新しい列をシミュレートします。 
4. トランジション中に、現在の位置の周囲に小さな斜めのバンドを再構築します。 この帯域外の値は、最終的な LCS が到達するかどうかに影響を与えることはできません。`n-k`, したがって、それらは無視されます。 
5. 結果の LCS バンドを圧縮表現に変換し、古い状態に到達するウェイの数を新しい状態に加算します。 
6. 結局のところ`n`文字が処理され、残りのすべての状態が検査されます。 最後のエンコードされた LCS 値が少なくとも`n-k`。 

なぜ効果があるのか:

 不変条件は、保存されたすべての状態が、現在のプレフィックスを構築した後、可能なすべての LCS バンドを正確に表すということです。`T`。 移行は元の LCS の繰り返しに従い、最終的な答えに依然として影響を与える可能性があるテーブルの部分にのみ制限されます。 破棄されたすべてのセルは数学的に将来の十分な一致に寄与できないため、それらを削除しても有効な答えを削除することはできません。 次に考えられるすべての文字が考慮されるため、有効な文字列はすべて 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve_case(s, k):
    n = len(s)
    s = " " + s
    states = {(0, 0): 1}

    def build_transition(i, offset, mask, c):
        start = max(i - k, 0)
        end = min(i + k + 1, n)

        last_dp = start - offset
        prev = 0
        new_offset = None
        new_mask = 0

        bit = 0
        for pos in range(start + 1, end + 1):
            inc = (mask >> bit) & 1
            cur = max(last_dp + inc, prev, last_dp + (s[pos] == c))
            if new_offset is None:
                new_offset = pos - cur
                if new_offset > k:
                    return None
            else:
                if cur > prev:
                    new_mask |= 1 << (pos - start - 2)
            last_dp = cur
            prev = cur
            bit += 1

        if new_offset is None:
            new_offset = 0
        return new_offset, new_mask

    for i in range(n):
        nxt = {}
        around = set(s[max(1, i-k+1):min(n, i+k+1)+1])

        for (offset, mask), ways in states.items():
            for c in around:
                res = build_transition(i, offset, mask, c)
                if res is not None:
                    nxt[res] = (nxt.get(res, 0) + ways) % MOD

            res = build_transition(i, offset, mask, '?')
            if res is not None:
                nxt[res] = (nxt.get(res, 0) + ways * (26 - len(around))) % MOD

        states = nxt

    ans = 0
    for (offset, mask), ways in states.items():
        lcs = max(n-k, 0) - offset
        lcs += mask.bit_count()
        if lcs >= n-k:
            ans += ways

    return ans % MOD

def main():
    s, k = input().split()
    print(solve_case(s, int(k)))

if __name__ == "__main__":
    main()
```辞書`states`到達可能な圧縮状態のみを保存します。 多くのビット パターンが出現しないため、考えられるすべての状態を割り当てるよりもこれが望ましいです。 

遷移関数は、元の反復を使用して LCS バンドを再構築します。 変数`last_dp`そして`prev`圧縮された対角線内の隣接する値を表します。 隣接する増加はそれぞれ 0 または 1 であるため、差分ビットは順番に読み取られます。 

文字圧縮も重要です。 関連する対角近傍にすでに出現している文字は、LCS を変更する可能性があるため、個別に試行する必要があります。 他のすべての文字は同じように動作するため、その数を掛けた 1 つの遷移にグループ化されます。 

最終チェックでは、圧縮表現から可能な LCS 値を再構築します。 境界位置は次のように処理されます。`max`そして`min`、文字列の先頭と末尾付近での無効なアクセスを回避します。

 ## 特殊なケース

 のために`k = 0`、斜めのバンドには幅がありません。 このアルゴリズムは、LCS テーブルの主対角線のみを保存します。 最終的な LCS は等しい必要があるため、一致に負けたすべての遷移は最後に破棄されます。`n`。 

次のような繰り返し文字の場合`AA`と`k = 1`、圧縮された状態では、個々の一致の位置は追跡されません。 代わりに、LCS 形状を追跡します。これはまさに必要な情報です。 少なくとも 1 つを含む任意の文字列`A`受け入れ状態に達します。 

開始境界と終了境界の場合、次のようになります。`ABC`と`k = 1`、アルゴリズムは次を使用して処理された帯域を短縮します。`max`そして`min`。 不変式では、元の LCS テーブルに存在する位置を保存することのみが必要であるため、欠落している対角セルがこの状態になることはありません。
