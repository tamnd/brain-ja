 ## 解決策
 ## 問題の理解

 根が生えた木があります`1`。 すべての頂点には値が格納されます。 クエリごとに`(u, v)`かどうかを判断する必要があります。`v`のサブツリー内にあります`u`そしてサブツリー全体を削除した後に頂点が残るかどうか`v`のサブツリーから`u`すべてのペアに 2 つの異なる値が含まれるようにペアにすることができます。 

最初の条件は純粋に祖先に関するものです。 もし`u`～の先祖ではない`v`の場合、それらの最下位の共通祖先は、`u`、だから答えはすぐにわかります`NO`。 

2 番目の部分は分割の問題のように見えますが、はるかに単純な観察にまとめることができます。 残りのセットには次のものが含まれているとします。`k`頂点。 それらを同じサイズの 2 つのグループに分割し、それらのグループを一致させる必要があります。 値があまりにも頻繁に出現すると、これが妨げられます。 何らかの値がそれ以上に表示される場合は、`k / 2`場合によっては、その値のすべての出現に対してペアにするための他の値を持つ頂点が十分にないことがあります。 一方、セットの半分を超える値がない場合は、いつでもペアを配置できます。 

したがって、すべてのクエリは次のようになります。 

サイズを調べてください`subtree(u) - subtree(v)`。 均等でなければなりません。 

このセットに過半数の値があるかどうか、つまりセット サイズの半分を超えて出現する値があるかどうかを調べます。 

木には最大で`100000`頂点と同じ数のクエリ。 二次解法では、クエリごとにツリーの大部分を調べる必要があり、クエリは広範囲に及ぶ可能性があります。`10^10`操作。 各クエリに対数時間で応答できるようにする前処理が必要です。 

困難な特殊ケースは、大きなツリーではなく、削除されたサブツリーの正確な意味です。 

たとえば、ツリーが次の場合:```
1
|
2
|
3
```値を使用:```
1 1 2
```そしてクエリは`(2, 3)`、残りのセットはノードのみです`2`、したがって、そのサイズは奇数であり、答えは次のようになります。`NO`。 色をチェックするだけでペアリング数を忘れるソリューションでは、誤って受け入れられてしまいます。 

別のケースは次のとおりです。```
1
|
2
```値を使用:```
5 5
```そしてクエリ`(1, 2)`。 残りのセットは、`{1}`、ペアを形成することはできません。 ここでの失敗の本当の理由は、繰り返される値ではなく、奇数のサイズです。 

より微妙なケースは次のとおりです。```
1
/ \
2  3
```値を使用:```
7 7 8
```そしてクエリ`(1, 2)`。 残りのセットは、`{1,3}`。 サイズは均等ですが、値が異なるため、答えは次のようになります。`YES`。 のサブツリー全体をチェックする不用意なアプローチ`1`2つ見えるだろう`7`s と間違って拒否します。 

## アプローチ

 ブルートフォースアプローチは簡単です。 すべてのクエリについて、まず次のことを確認します。`u`の先祖です`v`。 存在する場合、そのサブツリーを走査します。`u`のサブツリーをスキップしながら`v`、すべての値をカウントし、最大頻度が残りのサイズの半分を超えているかどうかを確認します。 これは互換性の定義を直接評価するため、正しいです。 

問題はコストです。 単一のクエリで影響を受ける可能性がある`O(n)`頂点と`10^5`クエリ 最悪の場合は`10^10`頂点の訪問が許可時間を大幅に超えています。 

重要な観察は、ペアリング条件はセットの過半数の値にのみ依存するということです。 すべてのクエリにすべての頻度が必要なわけではありません。 セットには、半分以上の時間で 1 つの値が出現するか、出現しないかのどちらかです。 

ボイヤー・ムーアの多数決のアイデアは、まさに必要な情報を提供します。 セグメントは候補値と残高で表すことができます。 2 つの互いに素なセグメントを組み合わせると、可能性のある多数派候補を保持したまま、それらの要約をマージできます。 

オイラー ツアーの後、すべてのサブツリーは 1 つの連続した区間になります。 以来`subtree(v)`から削除されます`subtree(u)`、残りの頂点は最大 2 つのオイラー区間です。 大部分の要約をセグメント ツリーに保存し、残りの 2 つの間隔を結合できます。 次に、結果の候補は、すべての値のソートされた位置を使用して実際の頻度をカウントすることによってチェックされます。 

ブルート フォースはすべての値を直接カウントするため機能しますが、多くのクエリが大きなサブツリーに重なる場合は失敗します。 考えられる過半数の値のみが重要であるという観察により、クエリは頂点のスキャンから数回の対数演算に減ります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nq) | O(n) | 遅すぎる |
 | 最適 | O((n+q) log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. DFS をルートから実行して、オイラー ツアーの位置、サブツリーのサイズ、開始時間と終了時間を計算します。 ノードのサブツリーが区間になります`[tin[node], tout[node]]`。 
2. 祖先用のバイナリリフティングテーブルを構築します。 これにより、祖先をチェックし、最小共通祖先関連のクエリを処理できるようになります。`O(log n)`時間。 
3. オイラー次数に基づいてセグメント ツリーを構築します。 セグメント ツリーの各ノードには、候補値とその残高を含むボイヤー ムーア多数決の概要が保存されます。 
4. すべての値のオイラー位置をソート順に保存します。 これにより、二分探索を使用して、任意の間隔内で選択した値が出現する回数をカウントできます。 
5. 各クエリについて`(u, v)`、まず次のことを確認してください。`u`の先祖です`v`。 そうでない場合の答えは、`NO`。 
6. 残りの頂点数を次のように計算します。`subtree_size[u] - subtree_size[v]`。 この数字が奇数の場合、答えは次のようになります。`NO`なぜなら、すべての頂点は正確に 1 つのペアに属している必要があるからです。 
7. もし`u == v`、残りのセットは空です。 形成するペアはないので、答えは次のようになります。`YES`。 
8. 削除されたサブツリーは、次のサブツリー内の 1 オイラー区間です。`u`。 残りの頂点は、その間隔の前後の部分です。 両方の部分のセグメント ツリーをクエリし、2 つの多数派のサマリーをマージします。 
9. 残りの間隔で候補値が実際に出現する回数を数えます。 この数が残りのサイズの半分より大きい場合、答えは次のようになります。`NO`。 それ以外の場合の答えは、`YES`。 

アルゴリズムの背後にある不変条件は、すべてのオイラー区間の要約が常にその区間の唯一の可能な多数候補を保持することです。 値がクエリ セットの真の過半数である場合、その値はすべての Boyer Moore マージ操作で存続する必要があります。 最後の頻度チェックでは誤った候補が削除されるため、アルゴリズムは過半数の値が存在しないセットを正確に受け入れます。 

## Python ソリューション```python
import sys
from bisect import bisect_left, bisect_right

input = sys.stdin.readline

class SegTree:
    def __init__(self, arr):
        self.n = 1
        while self.n < len(arr):
            self.n *= 2
        self.tree = [(0, 0)] * (2 * self.n)
        for i, x in enumerate(arr):
            self.tree[self.n + i] = (x, 1)
        for i in range(self.n - 1, 0, -1):
            self.tree[i] = self.merge(self.tree[2 * i], self.tree[2 * i + 1])

    def merge(self, a, b):
        if a[0] == b[0]:
            return (a[0], a[1] + b[1])
        if a[1] > b[1]:
            return (a[0], a[1] - b[1])
        return (b[0], b[1] - a[1])

    def query(self, l, r):
        if l > r:
            return (0, 0)
        l += self.n
        r += self.n
        left = (0, 0)
        right = (0, 0)
        while l <= r:
            if l & 1:
                left = self.merge(left, self.tree[l])
                l += 1
            if not (r & 1):
                right = self.merge(self.tree[r], right)
                r -= 1
            l //= 2
            r //= 2
        return self.merge(left, right)

def solve():
    n = int(input())
    a = [0] + list(map(int, input().split()))

    graph = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        x, y = map(int, input().split())
        graph[x].append(y)
        graph[y].append(x)

    LOG = 17
    while (1 << LOG) <= n:
        LOG += 1

    up = [[0] * (n + 1) for _ in range(LOG)]
    tin = [0] * (n + 1)
    tout = [0] * (n + 1)
    size = [0] * (n + 1)
    euler = []
    timer = 0

    sys.setrecursionlimit(300000)

    def dfs(v, p):
        nonlocal timer
        up[0][v] = p
        for i in range(1, LOG):
            up[i][v] = up[i - 1][up[i - 1][v]]
        tin[v] = timer
        euler.append(a[v])
        timer += 1
        size[v] = 1
        for u in graph[v]:
            if u != p:
                dfs(u, v)
                size[v] += size[u]
        tout[v] = timer - 1

    dfs(1, 1)

    for i in range(LOG):
        up[i][1] = 1

    positions = {}
    for i, x in enumerate(euler):
        if x not in positions:
            positions[x] = []
        positions[x].append(i)

    seg = SegTree(euler)

    def ancestor(x, y):
        return tin[x] <= tin[y] <= tout[x]

    def count_value(x, l, r):
        if l > r:
            return 0
        arr = positions.get(x, [])
        return bisect_right(arr, r) - bisect_left(arr, l)

    q = int(input())
    ans = []

    for _ in range(q):
        u, v = map(int, input().split())

        if not ancestor(u, v):
            ans.append("NO")
            continue

        remaining = size[u] - size[v]

        if remaining % 2:
            ans.append("NO")
            continue

        if remaining == 0:
            ans.append("YES")
            continue

        cand1 = seg.query(tin[u], tin[v] - 1)
        cand2 = seg.query(tout[v] + 1, tout[u])
        cand = seg.merge(cand1, cand2)[0]

        cnt = count_value(cand, tin[u], tin[v] - 1)
        cnt += count_value(cand, tout[v] + 1, tout[u])

        if cnt * 2 > remaining:
            ans.append("NO")
        else:
            ans.append("YES")

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```DFS セクションは、ツリーを配列問題に変換します。 開始時間と終了時間により、ツリーを繰り返したどることなくサブツリー クエリが可能になります。 

セグメント ツリーには周波数は保存されません。 真の過半数は一意であり、セットのパーティションを結合した後も候補のままでなければならないため、ボイヤー ムーア候補と残高のみが保存されます。 

職位リストは、候補者を取得した後にのみ使用されます。 ボイヤー・ムーアは多数派の可能性を見つけることはできるが、それが実際に存在することを証明できないため、この分離が必要である。 バイナリ検索は最終検証を実行します。 

クエリの処理順序は重要です。 奇数の頂点を完全にペアにすることはできないため、サイズ チェックは多数決ロジックの前に行われます。 空集合の場合も、セグメント ツリーをクエリする前に処理する必要があります。

 ## 特殊なケース

 クエリの場合、`u == v`、削除されたサブツリーは、`u`、空のセットが残ります。 アルゴリズムは次のレベルに達します。`remaining == 0`状態と返品`YES`ペアリングが必要な頂点がないためです。 

チェーンなど、残りのセットのサイズが奇数であるクエリの場合`1-2-3`価値観を持って`1 1 2`そしてクエリ`(2,3)`、アルゴリズムは次のように計算します。`size[2] - size[3] = 1`。 1 つの頂点をペアに分割できないため、次の値が返されます。`NO`大部分の作業を行う前に。 

値を持つスターなど、サブツリー全体が過半数を持っているが、残りの部分が過半数を持っていない場合の場合`7 7 8`そしてクエリ`(1,2)`、オイラー区間はノードを除外します`2`。 アルゴリズムは残りの頂点のみをカウントします`{1,3}`したがって、削除されたサブツリーからの偽多数は答えに影響を与えることはありません。
