 ## 解決策
 ## 問題の理解

 ソートされた配列から始めます$$[1,2,3,\dots,n].$$3つのポジション$i<j<k$選ばれます、$j-i>1$。 セグメント$[i,j-1]$が反転され、セグメントは$[j,k]$が逆転している。 

オリジナルの対話型バージョンでは、部分配列の反転カウントを要求できました。 ハッキングされたバージョンでは、値は$n,i,j,k$は入力として直接与えられるため、同じロジックをオフラインで再構築する必要があります。 

重要な観察は、結果として得られる配列の形状です。 

最初の反転変換$$[i,i+1,\dots,j-1]$$の中へ$$[j-1,j-2,\dots,i].$$2回目の反転変換$$[j,j+1,\dots,k]$$の中へ$$[k,k-1,\dots,j].$$外のすべて$[i,k]$ソートされたままです。 

内部$[i,k]$、2 つの減少するブロックが得られます。$$[j-1,\dots,i,\; k,\dots,j].$$最初のブロックのすべての値は 2 番目のブロックのすべての値より小さいため、2 つのブロック間に反転はありません。 すべての反転は、各減少ブロックの内部から発生します。 

させて$$a=j-i,
\qquad
b=k-j+1.$$次に、各ブロックが寄与する反転カウントは次のようになります。$$\frac{a(a-1)}2$$そして$$\frac{b(b-1)}2.$$オフライン版は単に提供するだけです$n,i,j,k$、しかし、これらの反転公式を理解することは、まさに元の解決策が依存していたことです。 

制約により許可されるのは、$n$まで$10^9$までしかありませんが、$100$テストケース。 どれでも$O(1)$または$O(\log n)$テストケースごとの計算は簡単です。 長さの配列をシミュレートする$10^9$は不可能なので、解決策は純粋に数学的でなければなりません。 

よくある間違いは、最初の反転セグメントの長さを混同することです。 

たとえば、次の場合```
i=2, j=5
```セグメントは$[2,4]$、長さは$$j-i=3,$$ない$j-i+1$。 

もう 1 つの簡単なオフバイワン エラーが 2 番目のセグメントに表示されます。 その長さは$$k-j+1.$$のために```
j=4, k=6
```セグメントは$[4,6]$、これには 3 つの要素が含まれます。 

使用する$k-j$代わりに反転を過小評価します。 

## アプローチ

 ブルートフォース手法では、配列を明示的に構築し、両方の反転を実行してから、反転をカウントします。 単純に反転をカウントするには、すべてのペアをチェックする必要があり、$O(n^2)$仕事。 

このアプローチは次のような場合にはすぐに失敗します。$n$到達できる$10^9$。 配列を構築することさえ不可能です。 

2 つの反転によって作成された構造は、最終的な配列自体よりもはるかに有益です。 

結果として生じる置換は、次の 3 つの部分で構成されます。$$\text{sorted prefix}$$に続く$$\text{first decreasing block}$$に続く$$\text{second decreasing block}$$に続く$$\text{sorted suffix}.$$長さが減少するブロックの内部$L$、すべての位置のペアが反転を形成します。 反転数は正確に$$\binom{L}{2}
=
\frac{L(L-1)}2.$$最初のブロックのすべての値が 2 番目のブロックのすべての値よりも小さいため、ブロック間の反転は発生しません。 

これにより、順列自体を操作するのではなく、問題がセグメントの長さに関する単純な算術に変換されます。

 ## アルゴリズムのチュートリアル

 1.読む$n,i,j,k$。 
2. 最初の反転セグメントの長さを計算します。$$a=j-i.$$セグメントは$[i,j-1]$なので、その長さは$j-i+1$。 

1. 2 番目の反転セグメントの長さを計算します。$$b=k-j+1.$$セグメントは$[j,k]$、両端を含みます。 

1. 最初のブロックによって寄与される反転数を計算します。$$inv_1=\frac{a(a-1)}2.$$長さの減少シーケンス$a$位置のすべてのペアの反転が含まれます。 

1. 2 番目のブロックによって寄与される反転数を計算します。$$inv_2=\frac{b(b-1)}2.$$1. 出力$$inv_1+inv_2.$$### なぜ効果があるのか

 2回の逆転後のインターバル$[i,k]$2 つの独立した減少ブロックになります。 すべての反転は、それらのブロックの 1 つの内部に完全に存在します。 

最初のブロックは正確に貢献します$\binom{a}{2}$反転し、2 番目は正確に寄与します$\binom{b}{2}$。 

最初のブロックから生じるすべての値は 2 番目のブロックから生じるすべての値よりも小さいため、ブロック間には反転はありません。 残りの位置はすべてソートされたままであるため、追加の反転は存在しません。 

2 つの三角数の合計が反転回数の合計となります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    
    for _ in range(t):
        n, i, j, k = map(int, input().split())
        
        a = j - i
        b = k - j + 1
        
        ans = a * (a - 1) // 2 + b * (b - 1) // 2
        print(ans)

solve()
```実装は完全に算術演算です。 

最初のセグメントは$[i,j-1]$、したがって、その長さは`j - i`。 これは、1 つ違いの間違いを犯しやすい場所です。 

2番目のセグメントは$[j,k]$、したがって、その長さは`k - j + 1`。 

反転数は両方とも三角数です。 Python の整数は、可能な最大の値を快適に処理できます。$n\le 10^9$、答えはせいぜい約$5\times10^{17}$、Python の整数の範囲内に十分収まります。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    t = int(input())
    out = []

    for _ in range(t):
        n, i, j, k = map(int, input().split())

        a = j - i
        b = k - j + 1

        ans = a * (a - 1) // 2 + b * (b - 1) // 2
        out.append(str(ans))

    return "\n".join(out)

 ## 特殊なケース

 最小の有効な構成を考えてみましょう。```
1
4 1 3 4
```最初のセグメントは`[1,2]`、 長さ`2`、1つの反転に貢献します。 2番目のセグメントは`[3,4]`、 長さ`2`、1つの反転に貢献します。 反転後の配列は次のようになります。$$[2,1,4,3].$$反転回数は、$1+1=2$。 この式ではまったく同じ値が計算されます。 

次に、2 番目のブロックが非常に短い場合を考えてみましょう。```
1
10 3 7 8
```ここ$$a=4,\qquad b=2.$$答えは$$\binom{4}{2}+\binom{2}{2}
=
6+1
=
7.$$使用する$k-j$の代わりに$k-j+1$間違って設定してしまう$b=1$そして1回の反転を失います。 まさにこれが、2 番目のセグメントの包括的なエンドポイントが重要である理由です。 

最後に、巨大な値を考えてみましょう。```
1
1000000000 1 500000000 1000000000
```このアルゴリズムは少数の整数演算のみを実行し、一定のサイズの配列を割り当てません。$10^9$。 複雑さは一定に保たれます。これが、指定された境界に対して実行可能な唯一のアプローチです。
