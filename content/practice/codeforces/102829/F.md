 ## 解決策
 ## 問題の理解

 講堂はグリッドとして表されます。 一部のセルは壁またはオープンフロアであり、一部は電源コンセント、一部は空の椅子、一部は競合他社が収容されています。 競合他社は、そのチームの小文字で表されます。 ラウンドごとに、すべての競技者は、隣の空の椅子に移動するかどうかを同時に決定します。 

移動は、目的地が椅子であり、その椅子が出口からマンハッタン ディスタンス 3 以内にあり、その椅子の隣に対戦相手が座っていない場合にのみ許可されます。 いくつかの隣接する椅子がルールを満たしている場合、競技者は固定の優先順位 (上、左、右、下) を使用して選択します。 すべての競技者が選択した後は、固有の目的地を持つ移動のみが成功します。 2 人以上の競技者が同じ椅子を狙った場合、関係者全員がその場に留まります。 

入力により、グリッドの寸法と 5 分間の間隔の数が与えられ、その後に講堂の初期レイアウトが続きます。 すべてのインターバルをシミュレートした後の出力は同じグリッドであり、競技者は最終位置に配置され、空いた椅子は元に戻されます。`#`。 

グリッドの次元と反復回数はすべて最大 100 です。これは、セルの総数が最大 10000 であることを意味し、グリッド全体ですべてのラウンドをシミュレートすることが可能です。 すべてのセルのペアに対してコストのかかる検索を実行したり、すべての競合他社を求めてグリッド全体を繰り返しスキャンしたりするアプローチでは、時間がかかりすぎます。`O(I * N * M)`シミュレーションは簡単に制限内に収まります。 

主なエッジケースは、動きの同時性から生じます。 同じラウンド中に別の競技者が椅子から離れた後、競技者はすぐに移動することはできません。 例えば：```
1 3 1
a#*
```出力は次のとおりです。```
a#*
```唯一の椅子は出口に十分近くないため有効な目的地ではなく、競技者はそのまま残らなければなりません。 

もう 1 つのよくある間違いは、2 人の競合他社が間違って交換したり競合を解決したりすることです。 例えば：```
3 3 1
.*.
#a#
.*.
```出力は次のとおりです。```
.*.
#a#
.*.
```両方の競合他社が同じ空の椅子を検討する可能性がありますが、宛先に複数のリクエストがあるため、どちらも移動しません。 

3 番目の問題は、近くの競争相手と近くの対戦相手を混同することです。 チームメイトは互いにブロックしませんが、別のチームはブロックします。 

## アプローチ

 直接的なアプローチは、プロセスを正確にシミュレートすることです。 ラウンドごとに、すべての競技者を検査し、その 4 つの隣接するセルをチェックし、優先順位に従って最初の有効な椅子を選択します。 すべての選択肢が収集されたら、目的地を処理し、正確に 1 人の競技者がその目的地を選択した場合にのみ実行します。 

ルールは同期プロセスを記述しているため、この方法は正しいです。 重要なのは、部分的に更新されたボードではなく、古いボードに基づいて決定が行われるということです。 費用がかかるのは、椅子がコンセントに十分近いかどうかを確認することです。 試みるすべての動きに対して幅優先探索で外側に探索すると、コストが不必要に大きくなります。 

重要な観察は、アウトレットの状態は競合他社ではなく、グリッドのみに依存するということです。 出口から距離 3 以内にあるすべてのセルを前処理できます。 半径が小さいため、これはすべてのアウトレットから一度に BFS を実行することによっても実行できます。 その後、すべての移動チェックは一定時間の検索になります。 

対戦相手のチェックも、現在の対戦相手の配置にのみ依存するため、隣接する 4 つのセルから直接評価できます。 これら 2 つの観測により、すべてのラウンドは単純なグリッド シミュレーションになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(I * N * M * N * M) | O(N * M) | 遅すぎる |
 | 最適 | O(I * N * M) | O(N * M) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 講堂を読み取り、出口に十分近いセルを前処理します。 すべてのアウトレット セルから BFS を一度に開始します。 最大 3 の距離で到達したセルは、使用可能な椅子の位置としてマークされます。 
2. シミュレーションを繰り返します。`I`ラウンドします。 現在のボード上の各競合他社について、上、左、右、下の順序で隣接する 4 つのセルを調べます。 
3. 隣接するセルは、それが空の椅子であり、コンセントの近くにあるとマークされており、他のチームの隣接する競争相手がいない場合にのみ候補になります。 最初に見つかった候補が、競合他社が選択した目的地です。 
4. ボードを変更せずに、選択したすべての手を保存します。 すべての競合他社が同時に行動するため、取締役会は意思決定中に変更されていなければなりません。 
5. 各目的地を選択した競合他社の数を数えます。 宛先が 1 回だけ選択された移動のみを適用します。 古いポジションは空の椅子になり、宛先は競合他社のチームレターを受け取ります。 

それが機能する理由: 各ラウンド中、すべての競技者の決定は、ルールで記述されているのとまったく同じ前の状態から計算されます。 前処理ステップでは、セルが出口に十分近いかどうかという静的な質問に答えるだけです。 宛先は、要求が 1 つだけ存在する場合にのみ変更されるため、保存された宛先数によって衝突ルールが再現されます。 すべてのラウンドが 1 回の座席移動間隔の数学的定義に一致するため、このプロセスを繰り返すことで必要な最終的な配置が生成されます。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    n, m, intervals = map(int, input().split())
    grid = [list(input().strip()) for _ in range(n)]

    dist = [[-1] * m for _ in range(n)]
    q = deque()

    for i in range(n):
        for j in range(m):
            if grid[i][j] == '*':
                dist[i][j] = 0
                q.append((i, j))

    dirs = [(-1, 0), (1, 0), (0, -1), (0, 1)]

    while q:
        r, c = q.popleft()
        if dist[r][c] == 3:
            continue
        for dr, dc in dirs:
            nr, nc = r + dr, c + dc
            if 0 <= nr < n and 0 <= nc < m and dist[nr][nc] == -1:
                dist[nr][nc] = dist[r][c] + 1
                q.append((nr, nc))

    near_outlet = [[dist[i][j] != -1 and dist[i][j] <= 3 for j in range(m)] for i in range(n)]

    for _ in range(intervals):
        moves = []
        target_count = {}

        for i in range(n):
            for j in range(m):
                if 'a' <= grid[i][j] <= 'z':
                    team = grid[i][j]
                    chosen = None

                    for dr, dc in [(-1, 0), (0, -1), (0, 1), (1, 0)]:
                        ni, nj = i + dr, j + dc
                        if not (0 <= ni < n and 0 <= nj < m):
                            continue
                        if grid[ni][nj] != '#':
                            continue
                        if not near_outlet[ni][nj]:
                            continue

                        blocked = False
                        for er, ec in dirs:
                            ai, aj = ni + er, nj + ec
                            if 0 <= ai < n and 0 <= aj < m:
                                if 'a' <= grid[ai][aj] <= 'z' and grid[ai][aj] != team:
                                    blocked = True
                                    break

                        if not blocked:
                            chosen = (ni, nj)
                            break

                    if chosen is not None:
                        moves.append((i, j, chosen[0], chosen[1], team))
                        target_count[chosen] = target_count.get(chosen, 0) + 1

        for i, j, ni, nj, team in moves:
            if target_count[(ni, nj)] == 1:
                grid[i][j] = '#'
                grid[ni][nj] = team

    print("\n".join("".join(row) for row in grid))

if __name__ == "__main__":
    solve()
```BFS セクションは、マップの永続的なプロパティを計算します。 アウトレットは決して移動しないため、ラウンド間でこの情報を再計算する必要はありません。 

シミュレーションは動きを変更するのではなく個別に保存します`grid`すぐに。 すぐに更新すると、順序付けのバグが発生し、後で処理された競合他社にまだ存在しないはずの手が表示される可能性があります。 

移動順序は方向リストに直接エンコードされます。`up, left, right, down`。 宛先カウンターは、同じチームまたは異なるチームの複数の競技者が同じ椅子を選択する場合を含む衝突を処理します。 

インデックスは近隣にアクセスする前にチェックされるため、講堂の端付近での境界エラーが防止されます。 Python の整数はオーバーフローの問題を回避し、格納される操作の最大数はセルの数によって制限されます。

 ## 特殊なケース

 1 つ目のエッジ ケースは、コンセントに十分近くない椅子です。 このようなセルは決して使用可能としてマークされないため、アルゴリズムは前処理中にこれを処理します。 通常の空の椅子の隣にいる競技者の場合、動きのスキャンは椅子に到達しますが、動きが記録される前に拒否されます。 

2 番目の特殊なケースは、宛先が競合しているものです。 このアルゴリズムは、最初に試行されたすべての移動を記録し、その後、目的地をカウントします。 カウントが 1 より大きい場合、更新は行われません。 これにより、競技者は同じ椅子を争わないというルールが維持されます。 

3 番目のエッジケースは、チームメイトと対戦相手の区別です。 目的地をチェックする際、アルゴリズムは移動する競合他社のチームと異なる隣接する小文字のみを拒否します。 隣接するチームメイトは無視されます。これは移動ルールに一致します。
