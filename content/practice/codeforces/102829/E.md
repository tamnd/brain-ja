 ## 解決策
 ## 問題の理解

 ケビンにはいくつかの種類のタコスがあります。 それぞれのタイプには通常の購入価格があり、可能な交換のセットも知っています。 取引所によると、彼が現在次のタイプのタコスを1つ所有している場合、`i`、彼はある程度の金額を支払うと、次のタイプのタコスを 1 つ受け取ることができます。`j`。 交換は繰り返すことができ、双方向に機能する必要はありません。 

目標は、可能な限り最小限の金額を支払いながら、あらゆる種類のタコスを必要な数だけ購入することです。 入力により、タコスの種類の数、交換ルール、各種類を直接購入するためのコスト、および各種類に必要なタコスの数がわかります。 出力は、要求されたすべての数量を満たすために必要な最小合計金額です。 

制限が非常に大きいため、考えられるすべての交換シーケンスをチェックすることは不可能です。 まであります`10^4`タコスの種類と`10^5`交換。 タコスの種類のすべてのペアを試すソリューションには、すでに約`10^8`パスは任意に長くなる可能性があるため、考えられる交換パスのシミュレーションははるかに悪化します。 為替価格はマイナスではないため、最短パス手法が適切であることが強く示唆されます。 

微妙なケースは、タコスの種類を直接購入するのが最も安くない場合です。 たとえば、入力が次のようになっているとします。```

```答えは`5`、 ない`50`。 不注意な解決策では、要求されたタコスはすべて直接購入する必要があると想定する可能性があります。 こちら、購入タイプ`1`費用`1`、でも買うタイプ`0`そして交換には費用がかかります`10 + 1`, なので、直販価格のほうがまだお得です。 この例は、交換が常に有用であると仮定するのではなく、各ターゲット タイプを個別に評価する必要があることを示しています。 

もう 1 つの注意が必要なケースは、最適な開始タコスがターゲットのタコスと異なる場合です。 考慮する：```

## アプローチ

 直接的なアプローチは、要求されたタコスの種類を個別に検討することです。 ターゲットタイプの場合`j`可能なすべての開始タイプを試すことができます`i`、から最安の交換パスを見つけます`i`に`j`、の最小値を取得します。`cost[i] + path_cost`。 これは正しいです。なぜなら、すべてのタコスは、最終的には直接購入されたタコスから来て、その後、ゼロ以上の交換が行われる必要があるからです。 

問題は最短経路の計算回数です。 すべてのタコスの種類からグラフ検索を実行するには、`10^4`グラフを検索します`10^5`エッジ。 ダイクストラのアルゴリズムを使用しても、複雑さが大まかになるため、これでは遅すぎます`O(t * (t + e) log t)`、それは限界をはるかに超えています。 

重要な点は、すべての宛先に対して最適なソースを個別に知る必要がないということです。 最初に開始タコスを購入できる場合にのみ、各目的地に到達するための最も安価な方法が必要になります。 これは、購入価格に等しいエッジを持つすべてのタコス タイプに接続された仮想ソース ノードを追加することとまったく同じです。 その仮想ソースからすべてのタコス タイプまでの最短距離により、各タイプのタコスを 1 つずつ入手する最も安価な方法が得られます。 

このノードを明示的に作成する代わりに、優先キューに既に存在するすべてのタコス タイプを使用してダイクストラを初期化できます。 タイプの初期距離`i`は直接購入価格です。 その後、すべての交換エッジが正常に緩和されます。 交換では、所有するタコスから必要なタコスへの移動が記述されるため、最短のパスは交換の指示に直接従う必要があります。 

結果の比較は次のようになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(t(t + e) log t) | O(t + e) | 遅すぎる |
 | 最適 | O((t + e) log t) | O(t + e) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各タコスの直接購入価格と交換ルールをお読みください。 エッジが存在するグラフを構築します。`i -> j`タコスの交換コストと同じ重さがある`i`タコスに`j`。 
2. 各タコス タイプの最短距離を直接購入価格で初期化します。 この初期値を使用して、すべてのタコス タイプを優先キューに挿入します。 これにより、すべてのタコスの種類が最終購入の開始点として扱われます。 
3. 交換グラフに対してダイクストラのアルゴリズムを実行します。 タコスタイプのときはいつでも`u`コストをかけて入手できる`d`からのすべての交換を試してください`u`別のタイプに`v`。 もし`d + exchange_cost`～の既知のコストを改善する`v`、更新してください。 
4. ダイクストラ終了後、タイプの距離`i`このタイプのタコス 1 個の可能な限り安い価格です`i`、考えられるすべての交換チェーンを含みます。 
5. 各最終距離に、そのタイプに必要なタコスの数を掛け、その値を加算します。 各タコスは個別に入手できるため、この合計が最小の総コストとなります。 

機能する理由: ダイクストラの不変条件は、現在の最小距離でノードが優先キューから削除されるときは常に、その距離がそのタコス タイプを取得する最も安価な方法であるということです。 最初の距離はタコスを直接購入することを表し、すべての緩和は有効な交換を行うことを表します。 すべての交換コストはマイナスではないため、ダイクストラは最終的なタコス タイプを再検討する必要はありません。 すべてのノードが完了した後、グラフ内の対応するパスを通じて、購入と交換の考えられるすべてのシーケンスが検討されます。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    t, e = map(int, input().split())

    cost = []
    for _ in range(t):
        cost.append(int(input()))

    graph = [[] for _ in range(t)]
    for _ in range(e):
        i, j, p = map(int, input().split())
        graph[i].append((j, p))

    need = []
    for _ in range(t):
        need.append(int(input()))

    dist = cost[:]
    pq = []

    for i in range(t):
        heapq.heappush(pq, (dist[i], i))

    while pq:
        cur, u = heapq.heappop(pq)

        if cur != dist[u]:
            continue

        for v, w in graph[u]:
            nd = cur + w
            if nd < dist[v]:
                dist[v] = nd
                heapq.heappush(pq, (nd, v))

    ans = 0
    for i in range(t):
        ans += dist[i] * need[i]

    print(ans)

if __name__ == "__main__":
    solve()
```入力解析はグラフの構造に従います。最初にタコスの種類と交換の数、次に直接価格、次に有向交換エッジ、最後に要求数量です。 

の`dist`配列は無限ではなく直接購入価格から始まります。 これは、通常のダイクストラをマルチソース バージョンに変える主な実装の詳細です。 Kevin はいつでも直接購入できるため、あらゆる種類のタコスがすでに入手可能です。 

タコス タイプは、古い値がすでに挿入されている後でより良い距離を受け取ることができるため、優先キューには古いエントリが含まれている可能性があります。 の`if cur != dist[u]`check はそれらの古いエントリを破棄します。 

すべてのコストは Python 整数内に安全に収まります。 必要な量による乗算は、最短経路がわかった後にのみ実行されるため、最終計算中にグラフ演算が繰り返されることはありません。

## テストケース```python
import sys
import io
import heapq

def solve_case(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t, e = map(int, input().split())
    cost = [int(input()) for _ in range(t)]

    graph = [[] for _ in range(t)]
    for _ in range(e):
        i, j, p = map(int, input().split())
        graph[i].append((j, p))

    need = [int(input()) for _ in range(t)]

    dist = cost[:]
    pq = [(dist[i], i) for i in range(t)]
    heapq.heapify(pq)

    while pq:
        d, u = heapq.heappop(pq)
        if d != dist[u]:
            continue
        for v, w in graph[u]:
            nd = d + w
            if nd < dist[v]:
                dist[v] = nd
                heapq.heappush(pq, (nd, v))

    return str(sum(dist[i] * need[i] for i in range(t)))
