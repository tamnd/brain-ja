 ## 解決策
 ## 問題の理解

 アリスとボブは、複数の番号セットでプレイします。 アリスとボブは交互に配列から要素を削除します。アリスが最初に移動します。 違いは、アリスが値を削除するたびに、その値を自分の個人配列にも保持することです。`c`一方、Bob は単に値を削除します。 

すべての要素が削除された場合、ゲームのスコアは次の MEX になります。`c`、アリスが収集した値の中に現れない最小の非負の整数を意味します。 

アリスは、この MEX をできるだけ大きくしたいと考えています。 ボブはそれをできるだけ小さくしたいと考えています。 両プレーヤーが完璧にプレーしたと仮定して、最終スコアを決定する必要があります。 

配列の値は常に次の範囲にあります。`0`そして`n-1`、すべてのテスト ケースにわたる要素の合計数は最大で`2 · 10^5`。 これは、二次関数は高価すぎることをすぐに示唆しています。 要素の数に比例した作業を実行するソリューション。`n log n`、簡単に十分に高速です。 

難しいのは、これはゲームだということです。 単純な実装では、最適なプレイを手ごとにシミュレートしようとしますが、考えられるゲーム状態の数は指数関数的に増加します。 本当の課題は、アリスがどの値を自分のコレクションに強制できるのか、どの値がボブに阻止できるのかを理解することです。 

いくつかの特殊なケースは判断を誤りやすいものです。 

考慮する：```
2
1 1
```ありません`0`全然。 アリスは決して手に入れることができません`0`、したがって、答えは次のとおりです`0`。 

考慮する：```
4
0 1 2 3
```必要な値はすべて 1 回だけ表示されます。 アリスはそのうちの 1 つを取得し、ボブはすぐにもう 1 つを削除します。 ボブは将来の MEX に欠けている成分を 1 つ破壊できるので、答えは次のとおりです。`1`、 ない`4`。 

考慮する：```
4
0 0 1 1
```重要な値はそれぞれ 2 回表示されます。 アリスは 1 つのコピーを取得し、ボブはもう 1 つのコピーを削除できます。 両方`0`そして`1`生き残る、だから答えはこうなる`2`。 

よくある間違いは、元の配列の通常の MEX を計算することです。 ゲームは、どの値が単に存在するかではなく、アリスがどの値を収集することを保証できるかについてのものです。 

## アプローチ

 ブルート フォース ビューでは、ゲームをミニマックス検索として扱います。 すべての状態から、アリスは最終的な MEX を最大化する要素を選択し、ボブはそれを最小化する要素を選択します。 これは最適なプレーを直接モデル化しているため、これは正しいです。 

残念ながら、控えめな場合でも、`n`、州の数は膨大になります。 あらゆる動きは多くの可能性に分岐し、その複雑さは本質的に指数関数的になります。 と`n`まで`2 · 10^5`、これはまったく不可能です。 

重要な観察は、値の頻度のみが重要であるということです。 

ある数字に注目するとします`x`。 

もし`x`まったく存在しないので、アリスは決してそれを手に入れることができません。 

もし`x`正確に 1 回出現すると、どのプレイヤーがその固有のコピーを取得するかによって決定されます。`x`アリスのコレクションに属することになります。 ボブはいつでもそのような脆弱な価値観をターゲットにすることができます。 

もし`x`少なくとも 2 回出現すると、アリスはより強力に保護されます。 ボブが 1 つのコピーを削除しても、別のコピーは利用可能なままになります。 

少なくとも最終的な MEX を作成するには`k`、アリスはからすべての値を取得する必要があります。`0`を通して`k-1`。 

ボブの最善の戦略は、欠損値をできるだけ早く作成することです。 周波数を伴う値`1`彼がその固有のコピーを取得することで番号を永久に破壊できる唯一の場所です。 

これにより、非常に単純な特性評価が得られます。 

からの値をスキャンします`0`上向きに。 

If a value never appears, that value becomes the answer immediately.

 Among values that do appear, count how many have frequency exactly`1`。 

このカウントが到達する最初の値`2`も答えです。 

なぜ？ アリスが最初に移動するため、ボブが別のシングルトンを破壊する前に、すべてのシングルトン値のうち最大 1 つを確保できます。 2 番目のシングルトンは、アリスのコレクションの最初の避けられないギャップになります。 

これにより、ゲームの問題が頻度カウントの問題に変換されます。

 ## アルゴリズムのチュートリアル

 1. 配列内のすべての値の頻度を数えます。 
2. カウンタの初期化`single = 0`。 これにより、これまでに確認された値が 1 回だけ発生した回数が追跡されます。 
3. からの値をスキャンします。`0`上向きに。 
4. 現在値に周波数がある場合`0`、この値をすぐに返します。 

欠損値はアリスでは収集できないため、自動的に MEX になります。 
5. 現在値に周波数がある場合`1`、増分`single`。 
6. もし`single`になる`2`、現在の値を返します。 

アリスは最大 1 つのシングルトン値の所有を保証できます。 2 番目のシングルトンは、ボブがアリスのコレクションから強制的に削除できる最初の値を作成します。 
7. 値が範囲に制限されているため、スキャンは常に終了します。`[0, n-1]`そして最終的には、既存の周波数を超える値がカウントされるようになります。`0`。 

### なぜ効果があるのか

 少なくとも 2 つの頻度を持つすべての値について、アリスが 1 つのコピーを取得する前に、ボブはその値を完全に削除することはできません。 このような値は安全です。 

周波数がちょうど 1 の値は脆弱です。 ボブは、シングルトンの唯一のコピーを取得することで、シングルトンを永久に削除できます。 アリスが最初に移動するため、MEX にとって重要な値の増加シーケンスのうち最大 1 つのシングルトン値を保護できます。 2 つのシングルトン値が出現すると、ボブはいつでもそのうちの 1 つがアリスのコレクションに入るのを防ぐことができます。 これが避けられない最小値は、まさに最終 MEX です。 

アリスは存在しないものを収集できないため、最初の欠落値によってもすぐに MEX が決まります。 

これら 2 つの条件は、最適なプレーを完全に特徴づけます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    answers = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        freq = [0] * (n + 1)
        for x in a:
            freq[x] += 1

        single = 0

        for mex in range(n + 1):
            if freq[mex] == 0:
                answers.append(str(mex))
                break

            if freq[mex] == 1:
                single += 1

            if single == 2:
                answers.append(str(mex))
                break

    sys.stdout.write("\n".join(answers))

if __name__ == "__main__":
    solve()
```周波数配列は核となるデータ構造です。 全ての値が満たされるので、`0 ≤ a[i] < n`、サイズの配列`n + 1`で十分です。 

MEX は最初の問題となる値に依存するため、スキャンは昇順に進行します。 欠損値に遭遇した瞬間、答えは決まってしまい、立ち止まってしまいます。 

の`single`カウンタは、出現した脆弱な値の数を追跡します。 最初のシングルトンはアリスによって保護されます。 2 番目のシングルトンは、ボブがギャップを強制できる場所なので、すぐに戻ります。 

微妙なディテールがスキャンされています`n`。 入力値が厳密に以下である場合でも、`n`、答えは次のとおりです`n`。 例えば：```
0 1 2 3
```通常のMEXを持っています`4`。 サイズのみの周波数配列を使用する`n`この可能性を逃してしまうでしょう。

 次のことを考慮してください。```
