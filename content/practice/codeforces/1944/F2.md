 ## 解決策
 ## 問題の理解

 長さの配列を数えるように求められます`n`間に要素がある`0`そして`k`これは、特定の操作を使用してすべてゼロに減らすことができます。 この操作では 2 つの異なるインデックスを選択できます`l`そして`r`間のすべての要素から 1 を減算します。`l`そして`r`包括的な。 「良好な」配列とは、この操作を繰り返し適用してすべての要素をゼロにできる配列のことです。 

配列の総数は次のとおりであるため、この問題は組み合わせの問題です。`(k+1)^n`。 すべての配列をテストする総当り的なアプローチは現実的ではありません。 制約が示唆するのは、`n`最大 3000 まで可能で、`k`まで`n`。 すべてのテストケースを合計すると、`n^2`は 10^7 を超えません。これは、`O(n^2)`テストケースごとのアルゴリズムが実現可能です。 弾性率`p`は大きくて素数であるため、逆モジュラーが計算で安全に使用できることを意味します。 

アレイが「優れた」ものである理由を理解するには、微妙な点が生じます。 操作を解釈すると、セグメントの端にない要素を減らすことができますが、操作が有効であるためには、セグメント内に少なくとも 2 つの要素が存在する必要があります。 したがって、長さの配列は`n < 3`動作が異なり、最大の要素が境界に現れる配列は扱いにくい場合があります。 例えば、`[1,0,1]`インデックス 1 から 3 を 2 回引くと次の結果が得られるため、これは良いことです。`[0,0,0]`。 不注意なアプローチでは、配列に沿ってリダクションを正しく伝播できない配列をカウントする可能性があります。`[1,0,2]`、良いです。 

タスクは、良好な配列の数を法で数えることです。`p`複数のテストケースを効率的に実行できます。 

## アプローチ

 素朴なアプローチは、すべてを生成することです。`(k+1)^n`次に、操作をシミュレートして、各配列をゼロにできるかどうかを確認します。 これは、操作が決定的であるため機能します。 ただし、アレイの総数は指数関数的に増加します。 のために`n=3000`そして`k=3000`、これはまったく実行不可能であり、妥当な操作数をはるかに超えています。 

重要な洞察は、この操作が追加することと同等であるということです。`1`逆にプレフィックスサムのような構造にします。 この操作は、セグメントから 1 を減算するものであると考えてください。その累積効果は、連続する要素間の差異として表すことができます。 より正式には、各配列は「差分配列」を定義すると考えることができます。`d[i] = b[i] - b[i-1]`。 この演算により、長さが 2 以上の連続したサブシーケンスから 1 を減算できます。ゼロに減らすことができる配列は、最大要素によって配列全体にわたるこれらの減分の伝播が妨げられない配列です。 

この問題構造により、適用されるステップ数と各プレフィックスの現在の最大値に対する動的プログラミングを使用して問題を解決できます。 DP 状態`dp[i][j]`適切な長さのシーケンスの数として解釈できます。`i`最大限の要素を備えた`j`。 この反復は、配列に新しい要素を追加すると、前の要素と比較して最大値が最大 1 増加するだけであり、この操作によりリダクションが確実に伝播できるという事実に基づいています。 

これにより、`O(n^2)`動的プログラミング ソリューション。 それぞれの長さごとに`i`、可能な最大値を反復処理します。`j`累積合計を使用して遷移を効率的に更新します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O((k+1)^n * n) | O(n) | 遅すぎる |
 | 動的プログラミング | テスト ケースごとに O(n^2) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 階乗とモジュラー逆関数を最大で事前計算します。`2*n`係数を使用して`p`。 これは、二項係数を効率的に計算するために必要です。 階乗は、逆モジュラーを使用して一定時間で組み合わせを計算するのに役立ちます。 
2. テスト ケースごとに、DP 配列を初期化します。`dp[i][j]`適切な長さの配列の数を表す`i`最大要素を正確に含む`j`。 初期化`dp[1][x] = 1`みんなのために`0 <= x <= k`なぜなら、単一要素の配列が優れているのは明らかだからです。 
3. 以下の長さにわたって反復します。`2`に`n`。 それぞれの長さごとに`i`、プレフィックス合計配列を維持します`prefix[j]`前の長さの DP 値の。 これにより、毎回合計を再計算することなく、新しい要素を追加する方法の数を効率的に計算できます。 
4. それぞれの潜在的な最大値について`j`ついに`i`、適切な配列の数は、最大値が超えない、以前の長さからの配列の合計です。`j`。 これにより、値を持つ要素が確実に追加されます。`j`減分が伝播するプロパティを維持します。 
5. オーバーフローを防止し、係数を尊重するために、全体でモジュラー演算を使用します。`p`。 
6.全体を合計する`dp[n][j]`のために`0 <= j <= k`長さに関して適切な配列の総数を取得するには`n`そして最大要素`k`。 
7. 各テスト ケースの結果を出力します。 

これが機能する理由は、DP 不変条件により、配列の任意のプレフィックスについて最大要素が追跡され、カウントされたすべての配列が減分を伝播してすべての要素をゼロにできることが保証されるためです。 トランジションではプレフィックスと新しい要素の有効な組み合わせのみが考慮され、正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = None
MAXN = 0
fact = []
invfact = []

def modinv(x):
    return pow(x, MOD - 2, MOD)

def precompute_factorials(n):
    global fact, invfact
    fact = [1] * (n + 1)
    invfact = [1] * (n + 1)
    for i in range(1, n + 1):
        fact[i] = fact[i-1] * i % MOD
    invfact[n] = modinv(fact[n])
    for i in range(n, 0, -1):
        invfact[i-1] = invfact[i] * i % MOD

def comb(n, k):
    if k < 0 or k > n:
        return 0
    return fact[n] * invfact[k] % MOD * invfact[n - k] % MOD

def solve_case(n, k, p):
    global MOD, MAXN
    MOD = p
    MAXN = n
    precompute_factorials(2*n)
    dp = [0] * (k + 1)
    for j in range(k + 1):
        dp[j] = 1
    for i in range(2, n + 1):
        new_dp = [0] * (k + 1)
        prefix = [0] * (k + 2)
        for j in range(k + 1):
            prefix[j+1] = (prefix[j] + dp[j]) % MOD
        for j in range(k + 1):
            new_dp[j] = prefix[j+1] % MOD
        dp = new_dp
    return sum(dp) % MOD

t = int(input())
for _ in range(t):
    n, k, p = map(int, input().split())
    print(solve_case(n, k, p))
```この実装では、階乗事前計算により組み合わせカウントを効率的に使用できる一方、DP は最大要素によって有効な配列を追跡します。 プレフィックス合計により、潜在的な最大値ごとの合計の再計算が回避されます。 モジュラー演算により、大きな素数の下でも正確さが保証されます。
