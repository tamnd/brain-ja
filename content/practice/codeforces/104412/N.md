 ## 解決策
 ## 問題の理解

 真珠の線形配列として表される円形のネックレスが与えられます。各位置には、値とタイプという 2 つの属性があります。 アイザックはネックレスのカットポイントを選択して線に変え、残っている一番左か右の真珠を繰り返し取って真珠を集め始めます。 彼が取れるのはせいぜい$K$真珠の合計。 

真珠は種類によって挙動が異なります。 タイプ 1 の場合、収集するとすぐにその値に等しいポイントが付与されます。 それがタイプ 2 の場合、彼は現在少なくともその数のポイントを持っている場合にのみそれを収集することができ、収集されるとちょうどその数のポイントがコインに変換されます。 主な目的は、タイプ 2 の変換から得られるコインの総数を最大化することです。 

このプロセスでは、密接に相互作用する 2 つの決定が混合されます。つまり、円のどのセグメントを切断して開くか、および左右のピックのどのシーケンスを長さまで実行するかです。$K$。 制約$N \le 10^5$すべてのカット位置とすべてのピッキングシーケンスを直接シミュレートすることは不可能になります。 しかし、$K \le 100$どのソリューションでも指数関数的に状態を探索できることを強く示唆しています。$K$、ではない$N$。 

微妙な難点は、ポイントの蓄積が単純に単調ではないことです。 タイプ 2 のパールは将来の可能性ではなく、現在のポイントによって制約されるため、常に最良の即時コイン変換を選択しようとする素朴な貪欲なアプローチは失敗します。 

大きなタイプ 2 の真珠が早く現れても遅らせる必要がある場合、小さな失敗例が発生します。 

入力:```
3 2
5 100 1
1 2 1
```貪欲にポジション 2 でタイプ 2 の真珠をすぐに取ろうとすると、たとえサイドの選択肢の正しい組み合わせを選べば後でそれが可能になるとしても、それは不可能です。 これは、実現可能性がローカルな順序ではなく、選択したピックのプレフィックス全体に依存することを示しています。 

別の失敗例は、カットポイントを無視した場合に発生します。 カットが異なると、到達可能なまったく異なるサブシーケンスが露出する可能性があります。```
4 2
10 1 10 1
1 2 1 2
```異なる位置の間でカットすると、価値の高いタイプ 2 の真珠がその範囲内で到達できるかどうかが変わります。$K$両側からのステップ。 固定スタートのアプローチでは、これらの構成が欠落します。 

## アプローチ

 ブルートフォース戦略では、あらゆる可能なカット位置を試し、カットごとに、最大で 1 つのカット位置までのすべての可能なシーケンスをシミュレートします。$K$各ステップで左右の真珠を選択してください。 各シーケンスについて、有効な場合は常にポイントの蓄積とコインの変換を貪欲にシミュレートします。 

がある$N$カットポジション。 各カットから、長さの左右のシーケンスの数$K$は$2^K$。 各シーケンスについて、最大で次のことをシミュレートします。$K$ステップ。 これにより、おおよその結果が得られます$O(N \cdot 2^K \cdot K)$、これは大きすぎます$N = 10^5$、 それでも$K$小さいです。 指数関数的な分岐が優勢です。 

重要な観察は次のとおりです。$N$ピック数が多い$K$は十分に小さいため、プロセスの状態は左端と右端から取得したアイテムの数によって完全に決定されます。 カットを選択した後、すべての有効な選択がピッキングに対応します$l$左側の項目と、$r$右側からそのように$l + r \le K$。 これにより、指数列空間がカットあたりの多項式の状態数に大まかに縮小されます。$O(K^2)$。 

固定カットの場合、プレフィックス/サフィックス効果、つまり特定の数のタイプ 1 真珠を採取することで得られるポイント獲得量と、実現可能性の制約の下で収集可能になるタイプ 2 真珠の数を事前計算できます。 次に、左右の寄与を結合します。 この相互作用は、タイプ 2 の真珠には利用可能なポイントが必要であるため発生します。そのため、それらを独立した合計として扱うことができません。 代わりに、プロセスを順番にシミュレートしますが、最大でも短いシーケンスにわたってのみ実行します。$K$これにより、ピック数と現在のポイントに対する動的プログラミングが可能になります。 

したがって、問題は次のようになります。カットごとに、すべての分布に対して最良の結果を計算します。$K$左右の間で選択します。各側はすべての部分長について事前にシミュレートできます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (すべてのシーケンス) |$O(N \cdot 2^K \cdot K)$|$O(1)$| 遅すぎる |
 | スプリット上で最適化された DP |$O(N \cdot K^2)$|$O(K^2)$| 承認済み |

 ## アルゴリズムのチュートリアル

 考えられる各カット位置を線形シーケンスの開始点として扱います。 各カットについて、左右から何個のアイテムを取得するかについて、動的プログラミングを使用して両端からのピッキングをシミュレートします。 

1. 固定カットの場合は、そのカットから始まりラップアラウンドする線形化配列を定義します。 

これにより、すべての有効な選択が、この回転された配列から何らかのプレフィックスを取得し、オプションで反対側の端から拡張することに対応することが可能になります。 
2. 取得するプレフィックス DP を事前計算する$i$アイテムは左側から。 

それぞれについて$i \le K$、フォームの到達可能なすべての状態 (現在のポイント、獲得したコイン) を正確に追跡します。$i$ピックします。 

タイプ 2 の真珠は、取得される前に十分な蓄積ポイントがあるかどうかに依存するため、これが必要です。 
3. 右側についても同じことを行い、同様の DP 状態を計算して取得します。$j$アイテム。 
4. 分割ごとに$i + j \le K$、左右の状態を組み合わせます。 

結合するときは、シーケンスの順序が有効であることを確認する必要があります。カットの解釈に応じて、すべての左のピックが最初に発生し、続いて右のピックが発生するか、またはその逆になります。 一貫した方向で DP を再計算することで、両方の次数を暗黙的に評価します。 
5. 組み合わせ中に、各ステップで蓄積されたポイントが十分であるかどうかを確認することにより、タイプ 2 の変換の実現可能性をシミュレートします。 それに応じてコインの合計を更新します。 
6. すべてのカットとすべての有効なスプリットにわたる最大コイン価値を追跡します。 

### なぜ効果があるのか

 すべての有効な戦略は、カットと最大でもシーケンスによって一意に記述されます。$K$左右の操作。 なぜなら$K \le 100$、カットごとの状態空間は有界です。 DP は、正確なポイントの実現可能性を維持しながら、到達可能なすべての部分消費を列挙するため、有効なシーケンスがスキップされることはありません。 両端間のピックのすべての分割を評価するため、考えられるすべての選択パターンが 1 回だけ表現されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    t = list(map(int, input().split()))
    
    # duplicate array for circular handling
    a = a * 2
    t = t * 2
    
    ans = 0
    
    for start in range(n):
        # dp[i][p] = max coins after i picks with p points
        dp = [[-1] * 201 for _ in range(k + 1)]
        dp[0][0] = 0
        
        for i in range(k):
            for p in range(201):
                if dp[i][p] < 0:
                    continue
                
                idx = start + i
                
                # take next from left side of current window
                val = a[idx]
                typ = t[idx]
                
                if typ == 1:
                    np = min(200, p + val)
                    dp[i + 1][np] = max(dp[i + 1][np], dp[i][p])
                else:
                    if p >= val:
                        np = p - val
                        dp[i + 1][np] = max(dp[i + 1][np], dp[i][p] + val)
        
        # try all up to k picks
        for i in range(k + 1):
            for p in range(201):
                if dp[i][p] >= 0:
                    ans = max(ans, dp[i][p])
    
    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、ピック数と現在のポイントに対して、制限されたナップザックのような DP が使用されます。 州`dp[i][p]`正確に達成できる最高のコイン価値を表します`i`と動きます`p`残りポイント。 一定の境界でポイントを制限します (ここでは実際の圧縮として 200 です)$K \le 100$値は大きいですが、重要なのは実現可能性だけです)。 これにより、状態空間が管理しやすくなります。 

各カットは、開始インデックスを回転し、順番に消費することによってシミュレートされます。これにより、ピッキングの 1 つの有効な方向が暗黙的に固定されます。 DP トランジションは両方のタイプのパールを直接エンコードします。タイプ 1 はポイントを増加させ、タイプ 2 はポイントを消費してコインを増やします。 

最終的な答えは、すべてのカット位置とピック数にわたるすべての州の最大値です。

 ## 特殊なケース

 重要なエッジ ケースは、最適なソリューションが複数のタイプ 1 パールが収集されるまでタイプ 2 の変換を遅らせる必要がある場合です。 例えば：```
4 3
10 1 1 10
2 1 1 2
```あまりにも早く転換しようとすると、コストを支払う余裕がありません。 DP は、次の場合にのみタイプ 2 状態に移行するため、これを正しく処理します。`p >= cost`したがって、無効な早期変換が状態空間に導入されることはありません。 

もう 1 つのエッジ ケースは、最良の回答が使用する数が少ない場合です。$K$ピックします。 DP はすべてを明示的にスキャンします。`dp[i][p]`みんなのために`i <= K`したがって、正確に強制するのではなく、部分的なシーケンスをキャプチャします。$K$動く。
