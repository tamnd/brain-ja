 ## 解決策
 ## 問題の理解

 長い数字の文字列が与えられ、それをいくつかの連続した部分に分割することができます。 選択された各部分は 10 進数として解釈され、その数値が素数または完全平方の場合にのみ有効とみなされます。 文字列全体をカバーする必要はありません。 ピースを選択した後に未使用のままになっている数字は完全に無視されます。 目標は、重複しないようにできるだけ多くの有効な部分を選択することです。 

したがって、このタスクは文字列全体を有効なブロックに分割することではなく、文字列内の任意の場所で重複しない「適切な」部分文字列を最大数選択することです。 

入力サイズによって、私たちの考え方がすぐに変わります。 文字列の長さは最大 100 万桁になるため、すべての部分文字列を列挙しようとするソリューションは不可能です。 すべての部分文字列をチェックする単純なアプローチでは、約 K² の候補が生成され、これは最悪の場合で約 10¹² の操作になります。 有効な部分文字列の大きさに強い制限がない限り、部分文字列のサブセットのみをチェックする場合でも、依然として時間がかかりすぎます。 

重要な構造上の意味は、実際に素数または完全二乗になり得る部分文字列のみを考慮するということです。 これにより、実際のソリューションでは有効な部分文字列が比較的短くなります。これは、コンテスト設定では、非常に大きな整数の素数テストと二乗チェックが実行できないためです。 これにより、意図した削減が行われます。つまり、短い固定長までの部分文字列のみが関連候補となります。 

素朴な推論を打ち破るようなエッジの効いた状況がいくつかあります。 

最初の落とし穴は、文字列全体を分割する必要があると想定していることです。 たとえば、`687`、すべての数字を取得することは不可能ですが、のみを選択します`7`有効かつ最適です。 

2 番目の落とし穴は、左から右への貪欲な選択が常に機能すると仮定していることです。 たとえば、`10067`、ピッキング`1`、`0`、`0`貪欲にローカルでより多くのピースを提供しますが、最適な解決策は次のとおりです。`100 | 67`これは、より長いセグメントを考慮した場合にのみ表示されます。 

3 番目の落とし穴は、重複する候補が存在することを忘れていることです。 文字列`10067`両方が含まれています`10`そして`100`同じ位置から開始し、選択肢に対する全体的な最適化のみが正しい答えを生成します。 

## アプローチ

 ブルートフォース戦略は、すべての部分文字列を考慮し、その数値が素数か完全二乗であるかを確認し、すべての有効な間隔を収集してから、重複しない間隔の最大セットを実行することです。 すべての有効な回答はそのような間隔で構成されているため、これは原理的には正しいです。 ただし、すべての部分文字列を列挙するにはすでに O(K²) のコストがかかり、K が 10⁶ までになると、これは完全に不可能になります。 間隔を保存するだけでもメモリを超えてしまいます。 

重要な観察は、有効な数字は非常に少数の候補者プールから得られる必要があるということです。 すべての素数と完全二乗を固定の上限 (通常は少数の桁内に収まるすべての値) まで事前計算する場合、有効な部分文字列はすべてその上限以下の長さでなければなりません。 これにより、問題は任意の長さの部分文字列のチェックから境界付きウィンドウ スキャンに変換されます。 

部分文字列の長さが定数 L (通常約 6 ～ 7 桁) によって制限されると、構造は管理しやすくなります。 各開始位置について、最大 L 文字までの拡張を試み、数値を計算し、事前に計算された有効な素数と平方のセットのメンバーシップをチェックするだけです。 

すべての有効な間隔を生成した後、問題は、各間隔が等しい重みを持つ、線上で重複しない間隔の最大数を選択することになります。 これは、単純な動的プログラミングを左から右にスキャンすることで解決できます。各位置で、そこから始まる有効な部分文字列をスキップするか取得するかを決定します。

 | 事前に計算された有効な数値を含む制限長 DP | O(K・L) | O(K) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### 事前計算ステップ

 1. 選択した桁制限 L の表現可能な最大値まですべての完全二乗を事前計算します。これは、i² を反復し、結果をハッシュ セットに保存することによって行われます。 これにより、後で定数時間の二乗チェックが可能になります。 
2. ふるいを使用して、同じ数値範囲までのすべての素数を事前計算します。 それらを同じハッシュ セットまたは別のセットに保存し、両方のソースをマージします。 これにより、どの候補部分文字列も O(1) で検証できるようになります。 

数値範囲を制限する理由は、L 桁より長い部分文字列は考慮されないため、より大きな値をテストする必要がないためです。 

### 有効な間隔を抽出する

 1. 文字列内のインデックス i ごとに、数値を文字ごとに長さ L まで拡張し、部分文字列 N[i..j] を形成します。 
2. 各部分文字列を最初から再解析するのではなく、段階的に整数に変換します。 これにより、繰り返しのオーバーヘッドが回避されます。 
3. 形成された数値が事前に計算された有効なセットに存在する場合は、間隔 (i, j) を有効な選択肢として保存します。 

このステップでは、文字列を、各セグメントが独立して有効である候補セグメントのコレクションに変換します。 

### 動的プログラミングの選択

 1. dp[i] を、位置 i から開始して選択できる有効なセグメントの最大数として定義します。 
2. 文字列を右から左にトラバースします。 各位置 i で、まずそれをスキップすると仮定し、dp[i] = dp[i+1] とします。 
3. i から始まる有効な間隔ごとに、dp[i] を dp[j+1] + 1 で更新します。ここで、j は間隔の終わりです。 

これにより、現在の文字を無視するか、ここから始まる有効なセグメントの 1 つを取得することが保証されます。 

### なぜ効果があるのか

 このアルゴリズムは、すべての決定点が将来のポジションのみに依存するという事実に基づいています。 i で始まる有効なセグメントを修正すると、問題の残りの部分は選択したセグメントから独立したものになります。 すべてのセグメントの重みは等しいため、カウントを最大化する場合を除いて、ある有効な部分文字列を別の有効な部分文字列よりも優先する必要はありません。 DP は、重複しない有効な間隔のすべての可能な組み合わせが、遷移を通じて 1 回だけ考慮されることを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXL = 6
LIMIT = 10**6  # enough for primes/squares in typical intended range

# Sieve primes up to LIMIT
is_prime = [True] * (LIMIT + 1)
is_prime[0] = is_prime[1] = False
for i in range(2, int(LIMIT ** 0.5) + 1):
    if is_prime[i]:
        step = i
        start = i * i
        for j in range(start, LIMIT + 1, step):
            is_prime[j] = False

valid = set()

# squares
i = 1
while i * i <= LIMIT:
    valid.add(i * i)
    i += 1

# primes
for i in range(LIMIT + 1):
    if is_prime[i]:
        valid.add(i)

K = int(input().strip())
s = input().strip()

n = len(s)

# dp[i] = best answer from i to end
dp = [0] * (n + 1)

for i in range(n - 1, -1, -1):
    best = dp[i + 1]
    num = 0
    for j in range(i, min(n, i + MAXL)):
        num = num * 10 + (ord(s[j]) - 48)
        if num in valid:
            best = max(best, 1 + dp[j + 1])
    dp[i] = best

print(dp[0])
```このソリューションでは、まず、有効なすべての数値に対する高速検索構造を構築します。 これにより、メインループから素数検査と二乗検査が削除され、定数時間のメンバーシップテストに置き換えられます。 

DP は右から左に実行されるため、dp[i] を評価するときに dp[j+1] がすでにわかっています。 各位置では、スキップするか、そこから始まる有効な部分文字列を取得しようとします。 内側のループは MAXL によって制限されるため、合計作業量は文字列サイズ内で線形に保たれます。 

微妙な詳細は、次の段階的な構築です。`num`。 スライスから整数を再計算すると部分文字列ごとに O(L) のコストがかかりますが、桁ごとに累積すると拡張ごとに O(1) に抑えられます。 

## 実用的な例

 ### サンプル 1:`687`長さ 6 までの有効な部分文字列を計算します。 

| 私 | 試した部分文字列 | 有効な選択 | dp[i] |
 | --- | --- | --- | --- |
 | 0 | 6, 68, 687 | なし | dp[1] |
 | 1 | 8、87 | なし | dp[2] |
 | 2 | 7 | 7 | 1 |

 インデックス 2 では、次のようになります。`7`、 dp[2] = 1 となります。それより前の位置では有効なセグメントが開始されないため、最良のものは 1 のままです。 

これは、有効な分離セグメントが表示されるまで文字をスキップすることが最適であることを示しています。 

### サンプル 2:`10067`| 私 | 試した部分文字列 | 有効な選択 | dp[i] |
 | --- | --- | --- | --- |
 | 0 | 1、10、100 | 100 | 1 + dp[3] |
 | 3 | 6、67 | 67 | 1 + dp[5] |
 | 5 | 7 | 7 | 1 |

 インデックス 3 から、`67`、インデックス 0 から取得します`100`。 DP は、これら 2 つの重複しないセグメントをチェーンします。 

これは、より小さな分割が存在する場合でも、より長いセグメントがどのように小さな分割を支配するかを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(K・L) | 各位置は L 桁まで展開されます。 
| スペース | O(K + リミット) | dp 配列と事前計算された素数/平方 |

 制約により、K は最大 100 万まで許容されるため、小さな定数係数を使用した線形スキャンで十分です。 前処理コストは、有効な数値に使用される数値境界のみに依存するため、K には依存せず、制限内に収まります。

 ## 特殊なケース

 次のような 1 桁の入力の場合`7`の場合、アルゴリズムはインデックス 0 から始まる有効な部分文字列をすぐに見つけて、dp[0] を 1 に設定します。それ以上の遷移はないため、結果は正しいです。 

のような文字列の場合`1234`、事前計算されたセットによっては、少数の短い部分文字列のみが有効な場合があります。 DP は、dp[i] が常にスキップと有効な間隔の取得を比較するため、複数の有効な部分文字列が重複している場合でも、重複しない最良の選択のみが選択されることを保証します。 

のために`100100`、部分文字列`100`ばらばらの位置に 2 回表示されます。 DP は、最初の出現を取得した後、両方の出現を独立して選択します。`100`の場合は、正しい次のインデックスから続行され、重複しない状態が自動的に維持されます。 

これらのケースは、状態定義が接尾辞の最適性のみに依存するため、以前の選択が後の最適なセグメントを無効にすることがないことを確認します。
