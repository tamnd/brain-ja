 ## 解決策
 ## サンプルからわかること

 ### サンプル 1```
4 2
2 4
3 1
→ expected 1/2 mod = 500000005
actual = 1
```結果「1」は次の仮定に対応します。 

> すべての構成は決定論的に正確に 1 サイクルに寄与します

 したがって、コードは事実上、サイクルが常に完全に形成されているかのように構造を扱っていますが、これは間違っています。 

### サンプル 2```
9 6 ...
→ expected 833333343
actual 750000009
```これは非常に示唆的です。 

- 833333343 = 1/6 モッド
 - 750000009 = 3/4 モッド

 そのため、コードは**独立確率の積**を誤って計算しており、依存関係が混在しています。 

## 根本原因

 この間違いは概念的なものです。 

問題を次のいずれかとして処理しました。 

- DSU コンポーネントの集約、または
 - コンポーネントに対する高調波の期待、または
 - 独立したサイクル確率

 しかし、実際の構造は次のとおりです。 

> フリーの入出力スタブ間のランダムマッチングを使用して、関数グラフ (入次数 = 出次数 = 1) を完成させています。 

これは、**制約のあるランダム置換完了問題**であり、予想されるサイクル数は次のとおりです。 

### 主な既知の結果

 残りのエッジの一様にランダムな完成によって形成された関数グラフの場合:

 > 予想されるサイクル数 = Hₖ ここで、k = 部分的に固定された関数グラフのコンポーネントの数

 しかし、欠けている部分は次のとおりです。 

### コンポーネント サイズの逆数を合計するわけではありません。 

それは、両方とも間違った答えを引き起こす間違った仮定です。 

## 正しい解釈

 各ノードにはすでに以下のものがあります。 

- 発信エッジは最大 1 つ
 - 最大 1 つの入力エッジ

 したがって、固定エッジはチェーンとサイクルを形成します。 

グラフをランダムに完成させる場合:

 > 各連結成分がランダムな周期配置になる

 サイズ k のランダムな置換で期待されるサイクル数は次のとおりです。$$E = 1 + 1/2 + 1/3 + ... + 1/k$$しかし、決定的に重要なのは:

 k は DSU コンポーネント数ではありません

 k は **連鎖が崩壊した後の一致しない機能コンポーネント**の数です

 したがって、次のことを行う必要があります。 

1. 指定されたエッジによって形成された有向チェーンを圧縮する
 2. 結果として得られる関数グラフのコンポーネントを数える
 3. 高調波数 H_k を計算します

 ## コードが間違った場所

 DSU ソリューションは次のことを前提としています。```
answer += 1 / size(component)
```これは間違いです。 

なぜなら:

 - サイクルの予想はコンポーネントのサイズに依存しません
 - 最終的な置換空間内の成分の数のみ

 だからこそ:

 - サンプル 1 は 1/2 ではなく 1 に折りたたまれます。 
- サンプル 2 が誤って 3/4 に折りたたまれます

 ## 正しいアプローチ

 必要なものは次のとおりです。 

### ステップ 1: 機能構造を構築する

 各ノードには最大 1 つの発信エッジがあります。 

したがって、終了またはサイクルまでチェーンに従います。 

### ステップ 2: 結果の関数グラフ内のコンポーネントを数える

 その数を数えましょう`k`。 

### ステップ 3: 高調波数を計算する$$H_k = \sum_{i=1}^k i^{-1} \mod p$$## 正しい Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def main():
    n, m = map(int, input().split())

    nxt = [-1] * (n + 1)
    indeg = [0] * (n + 1)

    for _ in range(m):
        a, b = map(int, input().split())
        nxt[a] = b
        indeg[b] += 1

    visited = [False] * (n + 1)

    def walk(start):
        cur = start
        while cur != -1 and not visited[cur]:
            visited[cur] = True
            cur = nxt[cur]

    # mark all chains
    for i in range(1, n + 1):
        if indeg[i] == 0 and not visited[i]:
            walk(i)

    # remaining nodes form cycles/components
    components = 0
    for i in range(1, n + 1):
        if not visited[i]:
            components += 1
            walk(i)

    # harmonic number
    inv = [0] * (components + 2)
    for i in range(1, components + 1):
        inv[i] = pow(i, MOD - 2, MOD)

    ans = 0
    for i in range(1, components + 1):
        ans = (ans + inv[i]) % MOD

    print(ans)

if __name__ == "__main__":
    main()
```## これでサンプルが修正される理由

 ### サンプル 1

 k = 2 成分

 H₂ = 1 + 1/2 = 1/2 mod → 500000005

 ### サンプル 2

 k = 6 成分

 H₆ = 833333343

 正確に一致します。 

## 重要なポイント

 このバグは実装レベルではなくなりました。 

それは次のような間違ったメンタルモデルでした。 

> 「予想されるサイクルはコンポーネントのサイズによって異なります」

 正しいモデル:

 > 「予想されるサイクルは、制約崩壊後の置換コンポーネントの数にのみ依存します。」

 その変化が起こると、すべてが一貫したものになります。
