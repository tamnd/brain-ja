 ## 解決策
 ## 問題の理解

 ここで説明するプロセスは、ランダムに並べ替えられる手順であり、配列が並べ替えられるまで繰り返しシャッフルされます。 1 回の「反復の成功」とは、1 回のランダム シャッフルの後、結果として得られる順列がすでにソートされていることを意味します。 

重要な観察は、すべてのシャッフルで、インデックスの個別の並べ替えだけでなく、値の複数セットの一様にランダムな並べ替えが生成されることです。 ソートされた配列に直接到達する確率が必要な場合、実際に尋ねるのは、配列の要素のすべての異なる順列のうち、どの部分がソートされた順序に対応するかということです。 

すべての要素が異なる場合、ソートされた順列は 1 つだけ存在します。$N!$、したがって、確率は次のようになります。$1/N!$。 重複が存在する場合、多くのインデックスの置換が同じ値の配置を表します。 値の場合$x$表示されます$f_x$倍すると、個別の順列の数は次のようになります。$$\frac{N!}{\prod f_x!}$$これらの順列のうち 1 つだけがソートされるため、確率は次のようになります。$$\frac{1}{N! / \prod f_x!} = \frac{\prod f_x!}{N!}.$$タスクは、この値を剰余として出力することです。$10^9+7$、その後、1 つの配列位置の値が変更されるポイント更新でそれを維持します。 各更新では 2 つの周波数のみが変更されます。1 つの値は出現を失い、もう 1 つは 1 を獲得するため、確率は増分的に更新できます。 

制約により両方が許可されます$N$そして$K$まで$10^6$これにより、クエリごとに階乗積を最初から再計算することが直ちに除外されます。 更新ごとにすべての値をスキャンするソリューションは遅すぎます。$O(NK)$最悪の場合の動作は、実行可能な限界をはるかに超えています。 

微妙な問題は、値が最大である可能性があることです。$10^9$したがって、値による直接のインデックス作成は不可能です。 値をキーとする配列に依存するアプローチは、値が圧縮されるかハッシュ マップに保存されない限り、暗黙のうちに失敗します。 

すべての要素が同一である場合、エッジケースが発生します。 その場合、確率は次のようになります。$1$、すべての順列が同一であり、すでにソートされているためです。 もう 1 つの特殊なケースは、更新によって値が繰り返し交換され、周波​​数が振動する場合です。 正確さは、順列を明示的に追跡するのではなく、周波数ベースの寄与を維持することに依存します。 

## アプローチ

 ブルートフォース解釈では、頻度マップを再構築して評価することにより、更新のたびに完全な確率を再計算します。$$\frac{\prod f_x!}{N!}.$$クエリごとに周波数の階乗を計算することは引き続き許容されますが、周波数自体を再計算するには、各更新後に配列全体をスキャンする必要があります。$O(N)$クエリごとに。 まで$10^6$アップデートすると、こうなります$10^{12}$最悪の場合は運用が不可能になります。 

重要な洞察は、確率がマルチセットの頻度分布にのみ依存するということです。 1 つの要素が変化すると、2 つの周波数だけが ±1 変化し、グローバル積は$\prod f_x!$ローカルで更新できます。 これにより、問題はポイント更新時の動的な積の維持に変わります。階乗が事前に計算されている場合、更新ごとに一定時間で実行できます。 

また、階乗とモジュラー逆関数も事前に計算して、除算を行います。$N!$グローバルに一度処理されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 各クエリを再計算する |$O(NK)$|$O(N)$| 遅すぎる |
 | 周波数積を維持する |$O(N + K)$|$O(N)$| 承認済み |

 ## アルゴリズムのチュートリアル

 確率を次のように書き換えます。$$\text{answer} = \left(\prod_{v} f_v!\right) \cdot (N!)^{-1}.$$この式を動的に維持します。 

### ステップ

 1. 階乗および逆階乗を最大で事前計算します。$N + K$。 これは、どの周波数も最大まで成長する可能性があるため必要です。$N$、階乗値は O(1) 時間で利用可能でなければなりません。 
2. 初期配列値の頻度マップを構築します。 値ごとに、その数を増やします。 
3. すべての値の初期積を計算します。$f_v!$。 これは確率式の分子を表します。 
4. 定数の分母係数を計算します。$(N!)^{-1}$事前に計算された逆階乗を 1 回使用します。 
5. 更新ごとに、積から古い値の周波数の寄与を削除し、周波数を更新して、新しい階乗寄与を再挿入します。 製品は常に現在の周波数と一致するように保たれます。 
6. 更新するたびに、次を出力します。$$\text{product} \cdot (N!)^{-1} \bmod (10^9+7).$$### なぜ効果があるのか

 アルゴリズムは正確な値を維持します。$\prod f_v!$いつでも。 更新では 2 つの周波数のみが変更されるため、製品の調整はローカルかつ正確です。 分母$N!$配列のサイズは変わらないため、一定のままです。 これにより、維持される式が常に置換カウント引数から導出される確率と等しくなることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    N, K = map(int, input().split())
    arr = list(map(int, input().split()))

    maxn = N + K + 5

    fact = [1] * (maxn)
    invfact = [1] * (maxn)

    for i in range(1, maxn):
        fact[i] = fact[i - 1] * i % MOD

    invfact[maxn - 1] = pow(fact[maxn - 1], MOD - 2, MOD)
    for i in range(maxn - 2, -1, -1):
        invfact[i] = invfact[i + 1] * (i + 1) % MOD

    freq = {}
    prod = 1

    for x in arr:
        if x not in freq:
            freq[x] = 0
        freq[x] += 1

    for v in freq.values():
        prod = prod * fact[v] % MOD

    inv_n_fact = invfact[N]

    out = []

    def remove(val):
        nonlocal prod
        c = freq[val]
        prod = prod * invfact[c] % MOD
        c -= 1
        freq[val] = c
        prod = prod * fact[c] % MOD

    def add(val):
        nonlocal prod
        c = freq.get(val, 0)
        if val not in freq:
            freq[val] = 0
        prod = prod * invfact[c] % MOD
        c += 1
        freq[val] = c
        prod = prod * fact[c] % MOD

    for _ in range(K):
        A, B = map(int, input().split())
        A -= 1
        old = arr[A]

        remove(old)
        arr[A] = B
        add(B)

        out.append(str(prod * inv_n_fact % MOD))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このソリューションは、すべての要因寄与を表す単一のグローバル積を維持することに重点を置いています。 削除ヘルパーと追加ヘルパーは、各周波数変更が対称的に適用されることを保証します。古い階乗項はデクリメント前に削除され、新しい階乗項は調整後に挿入されます。 この順序により、古いコントリビューションが製品に残るのを防ぎます。 

階乗テーブルと逆階乗テーブルは、すべての更新が O(1) であること、およびモジュール逆行列であることを保証します。$N!$以来一度事前計算されます$N$決して変わりません。

 ## 特殊なケース

 すべての要素が同一の場合、頻度マップには値を持つ単一のキーが含まれます。$N$。 製品は、$N!$と乗算する$(N!)^{-1}$結果は 1 です。削除操作と追加操作の両方で常に階乗積が現在の周波数と一致するように保たれるため、アルゴリズムはこれを自然に処理します。 

When updates repeatedly swap two values back and forth, the frequency of each value oscillates between two states. Each transition applies symmetric remove and add operations, so no drift accumulates in the global product.

 When a value disappears entirely, its frequency becomes zero. The remove step reduces the product by dividing out the last factorial contribution, and since$0! = 1$、無効な階乗項が積に残ることはありません。
