 ## 解決策
 ## 問題の理解

 次のサイズの正方形グリッドが与えられます。$N \times N$, ここで、各セルには地形タイプを表す 0 から 9 までの数字が含まれています。 固定サイズも与えられています$K$、そして私たちはあらゆる可能なことを調べる必要があります$K \times K$グリッド内のサブスクエア。 

サブ正方形は、角の 4 つのセルすべてに同じ値が含まれている場合に有効とみなされます。 タスクは、そのようなものが何個あるかを数えることです$K \times K$サブスクエアはグリッド内に存在します。 

入力制約により、グリッドが最大で大きくなる可能性があります。$1000 \times 1000$。 これにより、すべての項目を再チェックするソリューションは即座に除外されます。$K \times K$最悪の場合、セルごとに正方形になります。 正方形ごとの単純なチェックでは、$K^2$細胞、につながる$O(N^2 K^2)$、到達できる$10^{12}$操作時の操作$N = K = 1000$、実現可能な限界をはるかに超えています。 

さらに微妙な問題は、計算の重複です。 隣接$K \times K$窓は内部の大部分を共有しますが、単純なアプローチではすべてを最初から再計算することになります。 

いくつかの特殊なケースは注目に値します。 

もし$K = N$、チェックする正方形が 1 つだけあり、グリッド全体です。 答えは四隅が一致するかどうかで1か0になります。 

グリッド内のすべての値が同一の場合、すべての$K \times K$サブスクエアは有効なので、答えは次のようになります。$(N-K+1)^2$。 

角に 1 つの数字だけが表示され、内部が異なる場合、角だけではなくすべてのセルを誤ってチェックする単純な解決策は論理的には機能しますが、時間の無駄になります。 ただし、バグのあるソリューションには誤って内部制約が含まれる可能性があり、角だけが問題となるため、これは間違っています。 

## アプローチ

 ブルートフォースアプローチは簡単です。 可能なすべての左上隅を反復処理します$(i, j)$の$K \times K$サブスクエア。 それぞれについて、すべてを明示的に比較します$K^2$セルを移動するか、少なくとも境界を通過します。 わずかに最適化して四隅のみをチェックしたとしても、総当たりでこれを行う必要があります。$(N-K+1)^2$ポジション、最大でも$10^6$。 その部分は大丈夫です。 実際のコストは、完全な平方を誤って検証した場合にのみ表示されます。 

したがって、重要な観察は、条件が 4 つの位置 (左上、右上、左下、右下) にのみ依存するということです。 広場内のその他のものはすべて無関係です。 これにより、問題は位置ごとの一定時間のチェックに集約されます。 

したがって、グリッドをスキャンしたりプレフィックス構造を維持したりする代わりに、すべての有効な開始点を反復処理して 4 つのセルを比較するだけです。 

この問題は、2D 幾何学的集計タスクから、ウィンドウごとに一定の作業を伴う単純なスライディング列挙問題に縮小されます。

 | ブルートフォース（フルスクエアチェック） |$O(N^2 K^2)$|$O(1)$| 遅すぎる |
 | コーナーのみチェック |$O(N^2)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む$N$そして$K$、次にグリッドを 2D 配列に保存します。 これが必要なのは、コーナーをチェックするときに任意のセルにランダムにアクセスする必要があるためです。 
2. 可能なすべての左上の位置を反復処理します。$K \times K$四角。 これらのポジションは、$(i, j)$どこ$0 \le i \le N-K$そして$0 \le j \le N-K$。 これらの境界により、正方形がグリッド内に留まります。 
3. ポジションごとに$(i, j)$、その 4 つの角を特定します。$(i, j)$、$(i, j+K-1)$、$(i+K-1, j)$、 そして$(i+K-1, j+K-1)$。 これらは、有効性にとって重要な唯一のセルです。 
4. 4 隅の値がすべて等しいかどうかを確認します。 そうであれば、答えを増やします。 
5. すべてのポジションを処理した後、累積カウントを出力します。 

設計上の重要な選択は、チェックをコーナーのみに制限することです。 これは、条件が内部セルを参照しないため有効であり、追加の計算は冗長になります。 

### なぜ効果があるのか

 すべての有効な配置は、4 つの固定位置のローカル条件によって完全に定義されます。 それぞれ$K \times K$正方形は左上隅によって一意に決定され、有効性述語はそのアンカーからの固定オフセットの値にのみ依存します。 すべてのアンカーを正確に 1 回評価し、妥当性を定義する正確な条件を適用するため、有効な四角形が見逃されることも、無効な四角形がカウントされることもありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    N, K = map(int, input().split())
    grid = [list(map(int, input().split())) for _ in range(N)]
    
    ans = 0
    
    for i in range(N - K + 1):
        for j in range(N - K + 1):
            a = grid[i][j]
            b = grid[i][j + K - 1]
            c = grid[i + K - 1][j]
            d = grid[i + K - 1][j + K - 1]
            if a == b == c == d:
                ans += 1
    
    print(ans)

if __name__ == "__main__":
    solve()
```実装はアルゴリズムに直接従います。 ネストされたループは、有効な左上隅をすべて列挙します。 4 隅のアクセスは定数時間の配列ルックアップであり、内側のループが確実に維持されます。$O(1)$。 

主な微妙な点はインデックス付けです。右下隅は次のとおりです。$i + K - 1, j + K - 1$、 ない$i + K, j + K$。 ここでのオフバイワンエラーは、最も一般的なバグの原因です。

## 特殊なケース

 いつ$K = N$、候補となる正方形は 1 つだけです。 アルゴリズムは単一の反復を次のように評価します。$(i, j) = (0, 0)$。 グリッド全体の 4 隅を直接比較し、一致する場合にのみ 1 を返します。 境界外アクセスは発生しないため、$i + K - 1 = N - 1$、これは有効なインデックス付けです。 

すべてのグリッド値が同一の場合、すべての反復が条件を満たします。 ループが駆け巡る$(N-K+1)^2$位置を比較し、各比較で true を返します。 最終的な答えは、サブスクエアの組み合わせ数と一致する、可能な配置の数に等しくなります。 

内部セルのみが異なり、コーナーが一致する場合でも、アルゴリズムは内部位置を検査しないため、正しくカウントされます。 たとえば、$3 \times 3$四角：```
1 1 1
1 9 1
1 1 1
```あ$3 \times 3$ウィンドウには一致するコーナー (すべて 1) があるため、中央の 9 に関係なく 1 回カウントされます。これにより、注意をコーナーに制限するだけで十分であり、正確さのために必要であることがわかります。
