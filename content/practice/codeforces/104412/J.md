 ## 解決策
 ## 問題の理解

 最大 10 万の都市と道路を接続した無向グラフが与えられます。 各道路は両方向に使用できます。 このネットワーク上にクエリが与えられ、各クエリは都市 S と E のペアについて尋ねます。それぞれのペアについて、S から E に移動する旅行者が固有のルートをたどることを強制されるのか、それともエッジを繰り返さずに移動するための有効な方法が複数存在するのかを判断する必要があります。 

ここでの「旅行」とは、最短経路や最適化基準のことではありません。 唯一のルールは、有効なトリップではエッジを再利用できないということです。 ドライバーは予測できないため、2 つの都市間には複数の異なるエッジシンプル ルートが存在する可能性があります。 S と E の間に考えられる単純なルートが 1 つだけある場合、旅行を予測して「YES」と答えることができます。 異なる可能性が複数ある場合、またはエッジを S から E に横断する少なくとも 2 つの異なる方法がある場合、答えは NO です。 

この制約により、BFS または DFS を使用してクエリごとに接続またはパス構造を再計算しようとするソリューションは直ちに除外されます。 最大 100,000 のクエリと 100,000 のエッジでは、クエリあたり O(N + M) でも遅すぎます。 グラフ内のすべての冗長構造をツリー状のものに圧縮するグローバル前処理構造が必要です。 

重要な微妙なケースがサイクルを伴うグラフに現れます。 たとえば、単純な三角形 1-2-3-1 を考えてみましょう。 1 と 3 の間には、1-3 を直接パスするか、1-2-3 という 2 つの異なる有効なパスがあります。 したがって、グラフ構造がそれらを単一の強制ルートに折りたたまない限り、サイクル内のノードのペアは NO を生成するはずです。 

もう 1 つのエッジケースは木です。 グラフがすでにツリー (M = N - 1) である場合、ノードのすべてのペアには 1 つの単純なパスがあるため、すべてのクエリは YES を返す必要があります。 

最後に、ブリッジの多いグラフは、領域間がツリー状でありながら、一部の領域にサイクルを含むことができます。 サイクルコンポーネントを横断するクエリは、その内部のクエリとは異なる動作をするため、「サイクルの自由度」を「ツリーの剛さ」から分離する分解が必要です。 

## アプローチ

 単一のクエリに対する直接的なアプローチは、DFS または BFS を S から E まで実行し、複数の単純なパスが存在するかどうかを判断することです。 ただし、パスの一意性の検出は、1 つのパスを見つけることと同じではありません。 考えられるすべてのルートを探索するか、パスに影響を与えるサイクルを検出する必要がありますが、これは高密度コンポーネントではすぐに指数関数的な動作に陥ります。 クエリごとに DFS を実行しようとしても O(N + M) のコストがかかります。これは 10^5 クエリには大きすぎます。 

中心的な観察は、グラフに 2 つのノード間のルート上に存在するか、ルートに影響を与えるサイクルが含まれている場合に、パスの一意性が失われるということです。 最大の 2 エッジ接続コンポーネント (二重接続コンポーネント) をすべて 1 つのノードに圧縮すると、結果の構造はツリーになります。 ツリー内の 2 つのノード間には、単純なパスが 1 つだけ存在します。 あいまいさは、二重接続されたコンポーネント内にのみ存在します。 

したがって、問題は、2 つのクエリ ノードが複数のルートを許可する方法で同じサイクルを含む領域にあるかどうかを識別することに帰着します。 より正確には、二重接続コンポーネントとブリッジのブロック ツリーを構築した後、S と E の間のパスが分岐を導入するサイクル コンポーネントを通過するかどうかを答えることができます。 実際には、これは Tarjan のアルゴリズムを使用した標準的なアーティキュレーション ポイントと二重接続コンポーネントの分解となり、その後コンポーネント上にツリーが構築され、LCA ベースのクエリに応答します。

ブロック ツリーが構築されると、すべてのノードはコンポーネント ノードに属します。 S と E が同じコンポーネントにマッピングされている場合、そのコンポーネントがブリッジ チェーンである (つまり、そのコンポーネント内に単一パスを越えるサイクルがない) 場合、答えは YES です。 それらが異なるコンポーネントにある場合、ブロック ツリー内のコンポーネント ノード間のパスは一意であるため、パスに沿ったコンポーネントが循環している場合にのみあいまいさが存在します。 これは、各コンポーネントが内部に複数のエッジを持つかどうかをマークすることで事前に計算できます。 

次に、各クエリを「サイクル コンポーネント」とマークされたツリー上のパス クエリに縮小し、ルート パスで LCA 前処理とプレフィックス集約を使用できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとのブルート フォース DFS | O(Q(N + M)) | O(N + M) | 遅すぎる |
 | 二重接続コンポーネント + LCA | O(N + M + Q log N) | O(N + M) | 承認済み |

 ## アルゴリズムのチュートリアル

 グラフを、パスの一意性が推論しやすい構造に変換します。 

1. Tarjan のアルゴリズムを実行して、すべての二重接続コンポーネントを見つけます。 各エッジは正確に 1 つのコンポーネントに属し、各頂点はアーティキュレーション中に複数に属する可能性がありますが、ブロック ツリー表現では頂点をコンポーネント ID に割り当てます。 
2. 二重連結成分ごとに、循環が含まれているかどうかを判断します。 頂点から 1 を引いた数より多くのエッジがある場合、コンポーネントは循環的です。 これにより、内部ルーティングの曖昧さが内部に存在するかどうかが識別されます。 循環コンポーネントのみが内部のノード間で複数の異なる単純なパスを許可するため、この手順は重要です。 
3. 各ノードがコンポーネントである新しいグラフを構築します。 元のグラフ内のすべてのブリッジについて、2 つの対応するコンポーネントを接続します。 この構造はツリーかフォレストであることが保証されており、元のグラフがつながっているのでツリーになります。 
4. 任意のコンポーネントでコンポーネント ツリーをルートし、DFS を使用して親ポインタと深さを前処理します。 この DFS 中に、プレフィックス配列も計算します`bad[x]`ルートから x までのパス上に出現する循環コンポーネントの数を意味します。 
5. 各クエリ (S、E) について、S と E をコンポーネントの代表にマップします。 ツリー内のこれら 2 つのコンポーネントの LCA を計算します。 
6. 答えは、それらの間のパスに沿って循環コンポーネントが存在するかどうかによって決まります。 これは、プレフィックスの合計を使用してチェックできます。パスにサイクル コンポーネントが含まれている場合、`bad[S] + bad[E] - 2*bad[LCA] > 0`。 これが当てはまる場合は「NO」、そうでない場合は「YES」と答えてください。 

重要な考え方は、パス全体がサイクルを含むコンポーネントを通過せずにブリッジ構造内のみに存在する場合に、一意性が正確に保たれるということです。 

### なぜ効果があるのか

 接続されたすべての無向グラフは、ツリーを形成するブリッジによって接続された二重接続コンポーネントに分解できます。 ブリッジ ツリー内には、2 つのコンポーネント間に単純なパスが 1 つだけあります。 そのパス上のすべてのコンポーネントが内部的に非循環である場合、パスの各セグメントが強制され、代替ルートは残りません。 コンポーネントが循環している場合、そのコンポーネント内には境界頂点間を横断するための少なくとも 2 つの異なる方法が存在し、グローバル パスの一意性が直ちに損なわれます。 すべての代替ルーティングはサイクルから開始する必要があるため、正確さを保つためには、一意のコンポーネント ツリー パスに沿って循環コンポーネントをマークし、カウントすることが必要かつ十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    n, m, q = map(int, input().split())
    g = [[] for _ in range(n)]

    edges = []
    for i in range(m):
        a, b = map(int, input().split())
        a -= 1
        b -= 1
        g[a].append((b, i))
        g[b].append((a, i))
        edges.append((a, b))

    tin = [-1] * n
    low = [0] * n
    timer = 0
    stack = []
    comp_id = [-1] * n
    comps = []
    edge_in_comp = []

    def dfs(u, pe):
        nonlocal timer
        timer += 1
        tin[u] = low[u] = timer
        stack.append(u)

        for v, eid in g[u]:
            if eid == pe:
                continue
            if tin[v] == -1:
                dfs(v, eid)
                low[u] = min(low[u], low[v])
            else:
                low[u] = min(low[u], tin[v])

        if low[u] == tin[u]:
            comp = []
            while True:
                x = stack.pop()
                comp_id[x] = len(comps)
                comp.append(x)
                if x == u:
                    break
            comps.append(comp)

    for i in range(n):
        if tin[i] == -1:
            dfs(i, -1)

    comp_cnt = len(comps)
    cg = [[] for _ in range(comp_cnt)]
    edge_count = [0] * comp_cnt

    for a, b in edges:
        ca = comp_id[a]
        cb = comp_id[b]
        if ca == cb:
            edge_count[ca] += 1
        else:
            cg[ca].append(cb)
            cg[cb].append(ca)

    is_cyclic = [0] * comp_cnt
    for i in range(comp_cnt):
        vcnt = len(comps[i])
        if edge_count[i] > vcnt - 1:
            is_cyclic[i] = 1

    LOG = 17
    up = [[-1] * comp_cnt for _ in range(LOG)]
    depth = [0] * comp_cnt
    bad = [0] * comp_cnt

    def dfs2(u, p):
        up[0][u] = p
        bad[u] = bad[p] + is_cyclic[u] if p != -1 else is_cyclic[u]
        for v in cg[u]:
            if v == p:
                continue
            depth[v] = depth[u] + 1
            dfs2(v, u)

    dfs2(0, -1)

    for i in range(1, LOG):
        for v in range(comp_cnt):
            if up[i - 1][v] != -1:
                up[i][v] = up[i - 1][up[i - 1][v]]

    def lca(a, b):
        if depth[a] < depth[b]:
            a, b = b, a
        diff = depth[a] - depth[b]
        i = 0
        while diff:
            if diff & 1:
                a = up[i][a]
            diff >>= 1
            i += 1
        if a == b:
            return a
        for i in range(LOG - 1, -1, -1):
            if up[i][a] != up[i][b]:
                a = up[i][a]
                b = up[i][b]
        return up[0][a]

    comp_of = comp_id

    out = []
    for _ in range(q):
        s, e = map(int, input().split())
        s -= 1
        e -= 1
        cs = comp_of[s]
        ce = comp_of[e]
        w = lca(cs, ce)
        cnt = bad[cs] + bad[ce] - 2 * bad[w] + is_cyclic[w]
        out.append("NO" if cnt > 0 else "YES")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この解決策は、DFS ベースの低リンク計算を使用してグラフを二重接続コンポーネントに圧縮することから始まります。 各ノードにはコンポーネント ID が割り当てられ、エッジは内部またはコンポーネント間のいずれかに分類されます。 

第 2 フェーズでは、ツリーであるコンポーネント グラフを構築します。 内部エッジ数と最小ツリー構造要件を比較することにより、各コンポーネントが循環的かどうかを計算します。 

3 番目のフェーズでは、DFS を実行して、深さ、バイナリ リフティング祖先、および巡回コンポーネントのプレフィックス カウントを計算します。 これにより、ツリー パスを介した定時間集約が可能になります。 

LCA 関数は、ノードを同じ深さまで持ち上げてから、祖先が一致するまで両方を上にジャンプします。 これは標準的なバイナリ リフティング ルーチンです。 

各クエリはエンドポイントをコンポーネントにマップし、ツリー パス上のプレフィックス合計を使用して、そのパス上に循環コンポーネントがあるかどうかを検出します。

 ## 特殊なケース

 単一サイクルの最小限のグラフには、すでに故障モードが示されています。 で`1-2-3-1`、すべてのノードは、サイクリックとマークされた 1 つの二重接続コンポーネントに属します。 問い合わせ用`1 2`、LCA は同じコンポーネントであり、`bad[1] + bad[2] - 2*bad[lca] + is_cyclic[lca]`がプラスになり、NOが生成されます。 これは、2 つの異なる単純なパスの存在と一致します。 

のような純粋な木`1-2-3-4`周期成分は生成されません。 すべてのクエリの結果はパスに沿った循環寄与がゼロになるため、すべての答えは YES になります。 

チェーンに接続された三角形など、ツリーにサイクルが付加されたグラフは、サイクル コンポーネントを横切るパスのみがカウンタをトリガーするため、完全にチェーン内にあるクエリ (YES) と三角形コンポーネントを強制的に通過するクエリ (NO) を正確に区別します。
