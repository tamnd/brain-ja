 ## 解決策
 ## 問題の理解

 並行して作業できる 3 人のメンバーが与えられ、それぞれの生産性が異なります。 プログラミング タスクのリストもあり、それぞれに基本的な作業量が記載されています。 人がタスクに取り組むときの有効時間は、その人の速度によってスケールされたタスクのサイズとなるため、速い人ほど所要時間は比例して短くなります。 

各タスクは完了する必要があり、3 人の誰でもどのタスクでも引き受けることができますが、タスクが割り当てられると、その人だけがそれに取り組むことになります。 3 人全員が同時に異なるタスクに独立して作業します。最後に終了した人の合計終了時間ができるだけ短くなるように、3 人へのタスクの割り当てを調整したいと考えています。 最終的な答えは、切り上げられた最小完了時間です。 

重要な構造は、これが異なる速度で実行される 3 つの並列プロセッサによるスケジューリングの問題であり、どのプロセッサが割り当てられるかによって各タスクの処理時間が異なるということです。 

制約は十分に小さいため、割り当てに対する指数関数的な探索が妥当です。 タスクが最大 50 個ある場合、単純に各タスクを 3 人のうちの 1 人に割り当てると、3 の 50 乗の可能性が生じ、これはあまりにも大きすぎます。 ただし、タスクのサイズと速度の限界が小さいことから、枝刈りまたは構造化状態の圧縮を伴う動的プログラミングが意図されていることがわかります。 

タスクのサイズが大きく異なる場合、微妙なケースが発生します。 たとえば、あるタスクが他のすべてのタスクよりもはるかに大きい場合、他のタスクがどのように最適に分散されているかに関係なく、そのタスクを遅いワーカーに割り当てると、合計完了時間に影響を与える可能性があります。 もう 1 つのエッジ ケースは、すべての速度が等しい場合です。この場合、問題は 3 台の同一のマシン間でタスク サイズの合計のバランスを取ることになります。 

## アプローチ

 直接総当たりアプローチでは、各タスクを 3 人のワーカーの 1 つに個別に割り当て、その結果の完了時間を計算します。 割り当てごとに、各ワーカーに割り当てられたタスクのスケール処理時間を合計して、最大値を取得することで、各ワーカーの合計作業負荷を計算します。 これにより、考えられるすべてのスケジュールが正しく評価されますが、3^N 構成を検討する必要があり、これは N = 50 の場合でも実行不可能です。 

重要な観察は、問題の構造はタスクが 3 つのグループにどのように分割されるかによってのみ依存し、各グループのコストは加算されるということです。 各タスクは、選択されたワーカーの負荷に独立して影響します。 これにより、この問題は、少数の項目数と制限された重みに関する 3 方向のパーティション最適化問題に変換されます。 N が小さく、タスク サイズが小さいため、意味のある部分状態のみを保存し、支配的な状態を破棄しながら、枝刈りを伴う再帰的検索を使用して割り当て空間を探索できます。 

部分的な割り当ての多くが同等またはそれ以上の負荷分散につながるため、枝刈りは機能します。 2 つの状態の負荷が 3 つのワーカーすべてに同じかそれより大きい場合、悪い方の方が最終的なより良い答えを導き出すことはできません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース列挙 | O(3^N) | O(N) | 遅すぎる |
 | 負荷状態をプルーニングした DFS | O(枝刈り指数) | O(状態は維持) | 承認済み |

 ## アルゴリズムのチュートリアル

 各ワーカーがこれまでに蓄積した合計時間を追跡することで、部分的な割り当てを表します。 各タスクは 3 人のワーカーのいずれかに割り当てることができ、これらの選択肢を再帰的に検討します。 

### ステップ

1. すべてのワーカーの累積作業負荷がゼロの状態から開始します。 これは、タスクが配置される前の空の割り当てを表します。 
2. タスクを 1 つずつ処理します。 現在のタスクについて、各ワーカーの処理時間を Xi / A、Xi / B、Xi / C として計算します。これらは、タスクをそのワーカーに割り当てた場合の増分コストです。 
3. 状態ごとに、現在のタスクをワーカー 1、ワーカー 2、またはワーカー 3 に割り当て、それに応じてそのワーカーの累積時間を更新してみます。 
4. タスクを割り当てた後、3 つのワークロード値を並べ替えまたは正規化して状態を正規化します。 これにより、速度が順序に関係しない場合、同一の状態の順列が同じ構成として扱われることが保証されます。 
5. 各タスクの後に到達可能な一連の状態を維持します。 新しい状態を挿入するときは、最大完了時間を改善することはできないため、3 つのワークロードすべてで悪化する既存の状態を破棄してください。 
6. すべてのタスクを処理した後、残りのすべての状態の中で可能な最小の最大ワークロードとして答えを計算します。 

### なぜ効果があるのか

 各状態はタスクの有効な部分的な割り当てを表し、すべての遷移は次のタスクの可能な配置をすべて考慮しているため、正確さが維持されます。 ワークロード ベクトルは単調であるため、プルーニング ルールは安全です。タスクを追加すると値が増加するだけです。 すでにあらゆる面で劣っている状態は、さらに追加を加えても優勢な状態よりも良くなることはありません。 これにより、枝刈り中に最適な割り当てが削除されないことが保証されるため、残りの状態の最終的な最小値には真の最適解が含まれます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    N, A, B, C = map(int, input().split())
    X = list(map(int, input().split()))

    speeds = [A, B, C]

    # each state: (t1, t2, t3)
    states = {(0, 0, 0)}

    for x in X:
        new_states = set()
        for t1, t2, t3 in states:
            for i, s in enumerate(speeds):
                cost = x / s
                if i == 0:
                    nt = (t1 + cost, t2, t3)
                elif i == 1:
                    nt = (t1, t2 + cost, t3)
                else:
                    nt = (t1, t2, t3 + cost)

                # normalize ordering to reduce symmetry
                nt = tuple(sorted(nt))
                new_states.add(nt)

        # prune dominated states
        pruned = []
        for st in new_states:
            dominated = False
            for other in new_states:
                if other != st:
                    if other[0] <= st[0] and other[1] <= st[1] and other[2] <= st[2]:
                        if other != st:
                            dominated = True
                            break
            if not dominated:
                pruned.append(st)

        states = set(pruned)

    ans = min(max(st) for st in states)
    print(int(ans + 0.999999999))

if __name__ == "__main__":
    solve()
```このソリューションは、各タスクを繰り返し挿入することで、実現可能なすべてのワークロード分散を構築します。 各州は、各労働者が費やした時間を追跡します。 各挿入ステップの後、タプルをソートすることによって同等の順列が折りたたまれます。これにより、負荷構造の観点からワーカーの役割が交換可能な場合、ワーカー間の冗長な対称性が軽減されます。 

枝刈りステップでは、3 つのワーカーすべてで他のワーカーより厳密に悪い状態を削除します。 これにより、多くの部分的な割り当ては非効率的な初期の決定によってのみ異なるため、状態空間が急速に爆発するのを防ぎます。 

最終的な答えは、残りのすべての状態にわたる可能な限り最小の最大ワークロードです。 ワークロードは端数であるため、最後に切り上げます。 

## 実用的な例

 入力:```

5 7 6 1
```私たちは状態を 3 つのワークロードとして追跡します。 

| ステップ | タスク | 状態数 (概念) | 状態の例 |
 | --- | --- | --- | --- |
 | 0 | 初期化 | 1 | (0,0,0) |
 | 1 | 5 | 3 | (0.5,0,0) |
 | 2 | 7 | 9 | (1.2,0.7,0) |
 | 3 | 6 | たくさん → 剪定 | (1.8,0.7,0.6) |
 | 4 | 1 | 剪定された最終的な | (1.9,0.7,0.6) |

 最適な割り当てでは、タスクの主に最速のワーカーにバランスがとれます。 最大ワークロードは 2 未満にとどまるため、四捨五入された答えは 1 になります。 

このトレースは、枝刈りによってすべての組み合わせ割り当てが維持されるのではなく、バランスの取れた分布のみがどのように維持されるかを示しています。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべてのタスクが最も速いワーカーに割り当てられる場合です。 たとえば、A が B および C よりもはるかに大きい場合、最適なソリューションは単一ワーカーのスケジュールに崩壊します。 アルゴリズムは引き続き他の割り当てを探索しますが、プルーニングにより、遅いワーカーが不必要な負荷を蓄積する支配的な状態がすぐに排除されます。 

もう 1 つの特殊なケースは、タスクが同一である場合です。 その状況では、多くの異なる割り当てにより、同じワークロードが 3 倍になります。 正規化ステップにより、これらが単一の代表的な状態にマージされ、対称重複による指数関数的な爆発が防止されます。 

最後のエッジケースは、1 つのタスクが他のすべてのタスクよりも大幅に大きい場合に発生します。 遅いワーカーにタスクを割り当てる割り当てはすぐに優先され、プルーニング ステップによってそのような状態が早期に削除され、大きなタスクを最も速いワーカーに割り当てる構成だけが残ります。
