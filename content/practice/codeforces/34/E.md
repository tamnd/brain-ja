 ## 解決策
 ## 問題の理解

 一次元の線上を移動する点のようなボールがいくつかあります。 すべてのボールは、独自の速度と質量を持つある座標から始まります。 2 つのボールが同時に同じ位置を占めると、それらは弾性的に衝突し、その速度は 1 次元弾性衝突の標準物理公式に従って変化します。 

タスクは速度だけをシミュレートすることではありません。 元のボールの最終座標を正確に出力する必要があります。`t`秒。 衝突は将来の動きを変えるため、すべての衝突はその後のすべてのイベントに影響を与えます。 

制約は異常に小さいです。 ボールは最大 10 個、時間は最大 100 個です。`n`問題の性質を完全に変えます。 たとえ`O(n^3)`または`O(n^4)`イベント シミュレーションは十分に高速です。 課題は漸近的な複雑さではなく、数値の正確さと、衝突を正しい時系列で処理することです。 

小さなタイムステップを伴う単純な連続シミュレーションはひどく失敗します。 衝突は不合理に見える小数時間で発生する可能性があり、イプシロン増分で時間をステップ実行すると、浮動小数点誤差が蓄積されます。 意図した解決策はイベント駆動型であり、常に次の衝突に直接ジャンプします。 

簡単な間違いの 1 つは、衝突を間違った順序で処理することです。 考慮する：```
3 10
0 3 1
10 0 1
20 -3 1
```左のボールが先に真ん中のボールに当たり、その後真ん中のボールが右のボールに当たります。 時間順序を無視してすべてのペアを個別に更新すると、不可能な軌道が生成されます。 

もう 1 つの微妙なケースは、位置の同時更新です。 2つのボールが同時に衝突すると仮定します`2.5`。 新しい速度を計算する前に、その瞬間の位置を更新する必要があります。 速度を変更してから移動すると、衝突点がずれてしまいます。 

例：```
2 5
0 2 1
10 -2 1
```彼らは所定の位置で会う`5`後`2.5`秒。 等質量弾性衝突の後、速度が入れ替わります。 最終的な位置は次のようになります。```
5 - 2.5*2 = 0
5 + 2.5*2 = 10
```不用意に実装すると、5 秒間ずっと古い速度を使用して移動し、誤った出力が行われる可能性があります。`10`そして`0`。 

もう 1 つの危険なケースは、衝突時間がほぼ等しい場合です。 浮動小数点比較ではイプシロンを使用する必要があります。 そうしないと、精度ノイズが原因でアルゴリズムが間違った次の衝突を選択する可能性があります。 

この声明は、3 つのボールが同時に衝突しないことを保証します。 これにより、実装が大幅に簡素化されます。 マルチボディ衝突を解決する必要はありません。 

## アプローチ

 最も直接的なアイデアは、非常に小さな時間増分による物理シミュレーションです。 すべてのステップで、すべてのボールを移動します`v * dt`、次に、いくつかのペアが互いに交差したかどうかを確認します。 十分に小さいステップは連続的な動きに近似するため、これは概念的に機能します。 

問題は精度です。 もし`dt`が大きすぎると、衝突が完全に見逃されます。 もし`dt`信頼できるほど小さい場合、反復回数は爆発的に増加します。 たとえば、次のように使用します。`dt = 1e-6`100 秒を超えると、すでに`10^8`シミュレーションの手順。 たとえボールが 10 個しかなかったとしても、これは非実用的であり、数値的にも不安定です。 

問題の構造により、より明確なルートが得られます。 衝突と衝突の間、すべてのボールは一定の速度で直線的に移動します。 衝突の瞬間以外には何も興味深いことは起こりません。 つまり、中間時間を検査する必要はまったくありません。 将来最も早い衝突のみが必要です。 

すべてのボールのペアについて、ボールが出会ったときを分析的に計算できます。$$x_i + v_i t = x_j + v_j t$$これは次のようになります:$t=\frac{x_j-x_i}{v_i-v_j}$有効な衝突には、正の時間と相互の相対運動が必要です。 

最初の衝突が判明したら、すべてのボールをその時点まで直接進め、弾性衝突公式を使用して 2 つの衝突速度を更新し、これを繰り返します。 

なぜなら`n ≤ 10`、すべてのイベントの後にすべてのペアの衝突時間を再計算してもまったく問題ありません。 衝突が多くても、合計の作業量はわずかにとどまります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース タイム ステッピング | 非常に大きい、精度に依存 | O(n) | 遅すぎて不正確です |
 | イベント駆動型シミュレーション | O(C · n²) | O(n) | 承認済み |

 ここ`C`時間前に発生した衝突の数です`t`。 

## アルゴリズムのチュートリアル

 1. すべてのボールを現在の位置、速度、質量、および元のインデックスとともに保存します。 
2. 変数を維持する`cur_time`、最初は`0`。 
3. ボールのペアごとに`(i, j)`、速度が変わらない場合にいつ衝突するかを計算します。 
4. 無効な衝突時間を無視します。 

次の場合、衝突は無効です。 

- 距離は決して変わらないため、速度は等しくなります。 
- 衝突時間は正ではありません。 
- 残りの許容シミュレーション時間が経過した後に衝突が発生します。 
5. すべての有効な衝突の中で、最小の衝突時間を選択します。`dt`。 

これはシステム内の次の物理イベントです。 この瞬間までは直線運動以外何も変化しません。 
6. 目標時間までに衝突が存在しない場合:

 1. 残り時間までにすべてのボールを前進させます。 
2. シミュレーションを停止します。 
7. それ以外の場合:

 1. すべてのボールを前方に移動します。`dt`。 
2.増加`cur_time`による`dt`。 
3. ボールをしましょう`i`そして`j`衝突するペアになります。 
4. 弾性衝突公式を使用して新しい速度を計算します。$v_1'=\frac{(m_1-m_2)v_1+2m_2v_2}{m_1+m_2}$

$v_2'=\frac{(m_2-m_1)v_2+2m_1v_1}{m_1+m_2}$1. 合計シミュレート時間が経過するまで、手順 3 から繰り返します。`t`。 
2. 回答を印刷する前に、元の入力順序に戻します。 

### なぜ効果があるのか

 衝突と衝突の間では、すべてのオブジェクトは一定の速度で移動するため、位置は時間の一次関数になります。 将来の最初の衝突は、速度を変更できる唯一のイベントです。 そのイベントに直接進むと、正確な物理的な軌跡が保存されます。 

衝突を処理した後の新しい速度は、弾性衝突物理学によって正確に決定される速度になります。 このステートメントでは三重衝突が発生しないことが保証されているため、すべてのイベントには 1 つのペアだけが含まれるため、衝突を順番に処理することは有効です。 

常に最も早い衝突を選択することにより、シミュレーションはシステムの実際の時系列順序を再現します。 後の衝突は以前の衝突に影響を与えることはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

EPS = 1e-10

def solve():
    n, T = map(float, input().split())
    n = int(n)

    balls = []

    for idx in range(n):
        x, v, m = map(float, input().split())
        balls.append({
            "x": x,
            "v": v,
            "m": m,
            "idx": idx
        })

    cur_time = 0.0

    while cur_time < T - EPS:
        best_dt = float('inf')
        pair = (-1, -1)

        # Find earliest collision
        for i in range(n):
            for j in range(i + 1, n):
                xi = balls[i]["x"]
                xj = balls[j]["x"]
                vi = balls[i]["v"]
                vj = balls[j]["v"]

                rel_v = vi - vj

                if abs(rel_v) < EPS:
                    continue

                dt = (xj - xi) / rel_v

                if dt <= EPS:
                    continue

                if cur_time + dt > T + EPS:
                    continue

                if dt < best_dt:
                    best_dt = dt
                    pair = (i, j)

        # No more collisions
        if pair == (-1, -1):
            remain = T - cur_time

            for b in balls:
                b["x"] += b["v"] * remain

            break

        # Advance to collision
        for b in balls:
            b["x"] += b["v"] * best_dt

        cur_time += best_dt

        i, j = pair

        m1 = balls[i]["m"]
        m2 = balls[j]["m"]

        v1 = balls[i]["v"]
        v2 = balls[j]["v"]

        nv1 = ((m1 - m2) * v1 + 2 * m2 * v2) / (m1 + m2)
        nv2 = ((m2 - m1) * v2 + 2 * m1 * v1) / (m1 + m2)

        balls[i]["v"] = nv1
        balls[j]["v"] = nv2

    balls.sort(key=lambda b: b["idx"])

    print(*["{:.10f}".format(b["x"]) for b in balls])

solve()
```メイン ループは次の衝突イベントを繰り返し検索します。 以来`n`は小さいため、イベントの優先キューを維持するよりも、すべてのペアを毎回チェックする方が簡単で安全です。 

衝突公式は、線形会合方程式を解くことから直接得られます。 非正の時間は、浮動小数点ノイズによって引き起こされた過去の衝突または直前の自己交差を表すため、スキップします。 

シミュレーションでは、速度を変更する前に常に位置が更新されます。 その順序が重要です。 衝突の瞬間、すべてのボールはまず正しい物理座標に到達する必要があります。 

イプシロン比較により、浮動小数点演算による不安定性が防止されます。 これらがないと、更新を繰り返した後、数学的に同一の 2 つの時間が誤って比較される可能性があります。 

シミュレーション中にボールの順序が変更されることはありません。 結果が入力順序と一致するように、出力前に元のインデックスによってのみソートされます。

# helper: run solution on input string, return output string
import sys
import io

EPS = 1e-6

def solve_io(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    n, T = map(float, input().split())
    n = int(n)

    balls = []

    for idx in range(n):
        x, v, m = map(float, input().split())
        balls.append([x, v, m, idx])

    cur = 0.0

    while cur < T - 1e-10:
        best = float('inf')
        pair = (-1, -1)

        for i in range(n):
            for j in range(i + 1, n):
                xi, vi = balls[i][0], balls[i][1]
                xj, vj = balls[j][0], balls[j][1]

                if abs(vi - vj) < 1e-10:
                    continue

                dt = (xj - xi) / (vi - vj)

                if dt <= 1e-10:
                    continue

                if cur + dt > T + 1e-10:
                    continue

                if dt < best:
                    best = dt
                    pair = (i, j)

        if pair == (-1, -1):
            rem = T - cur

            for b in balls:
                b[0] += b[1] * rem

            break

        for b in balls:
            b[0] += b[1] * best

        cur += best

        i, j = pair

        x1, v1, m1, _ = balls[i]
        x2, v2, m2, _ = balls[j]

        nv1 = ((m1 - m2) * v1 + 2 * m2 * v2) / (m1 + m2)
        nv2 = ((m2 - m1) * v2 + 2 * m1 * v1) / (m1 + m2)

        balls[i][1] = nv1
        balls[j][1] = nv2

    balls.sort(key=lambda x: x[3])

    return " ".join("{:.6f}".format(b[0]) for b in balls)

```相対速度はゼロであるため、集合時間の式はゼロで除算されます。 アルゴリズムはそのようなペアを明示的にスキップします。 最終的な位置は次のようになります。```
30
35
```どちらのボールももう一方のボールを捕まえることは決してないからです。 

もう 1 つの微妙なケースは、まさに最後の時点での衝突です。```

0 1 1
10 -1 1
```彼らは次の場所で衝突します`t = 5`。 衝突時間が目標時間を超えていないため、アルゴリズムはこのイベントを受け入れます。 両方のボールがその位置で終了する`5`。 

strict を使用した浮動小数点実装`< T`比較により衝突が誤ってスキップされる可能性があります。

```最初の衝突はボール 0 と 1 の間で発生します。`10/3`。 等質量交換後、ボール 1 は速度とともに右に移動します`3`、最終的にボール 2 と衝突します。 

アルゴリズムは、イベントが発生するたびに、更新された状態から将来のすべての衝突時間を再計算するため、これを正しく処理します。 速度が変化したため、古い予測は破棄されます。
