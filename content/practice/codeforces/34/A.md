 ## 解決策
 ## 問題の理解

 私たちは円を描いて立っている兵士の身長を与えられています。 2 人の兵士が隣り合って立ち、隣接するすべてのペアの中で身長差ができるだけ小さい場合、偵察ユニットを形成できます。 

円形の配置では、重要な詳細が 1 つ変更されます。 最初と最後の兵士も隣人です。 左から右への隣接する位置のみをチェックするリニア スキャンでは、このペアが見逃されます。 

入力は高さの小さな配列です。 最小の絶対差を持つ隣接するペアの 1 から始まるインデックスを出力する必要があります。 

制約はわずかです。 兵士は最大でも 100 人しか存在しないため、$O(n^2)$ソリューションは制限内で快適に実行されます。 それでも、問題の構造により、当然のことながら、より単純な線形スキャンが行われます。 すべての有効なペアはすでにサークル内で隣接している必要があるため、すべての兵士を他のすべての兵士と比較する必要はありません。 

主なエッジ ケースは、最後の兵士と最初の兵士の間の循環接続です。 

次の入力を考えてみましょう。```
5
10 12 13 15 10
```最も小さな違いは、兵士 5 と 1 の間です。```
|10 - 10| = 0
```ペアだけをチェックするいい加減な実装`(1,2), (2,3), (3,4), (4,5)`最適な答えを誤って見逃してしまいます。 

複数のペアが同じ最小差を共有する場合、別の微妙なケースが発生します。```
4
5 7 9 11
```隣接するすべてのペアには違いがあります`2`。 任意の有効なペアを印刷できます。 実装は一意性を想定すべきではありません。 

最小入力サイズも重要です。```
2
100 1
```兵士は 2 人だけで、円形に配置されているため、両方向に隣接しています。 答えはまだあるはずだ`1 2`または`2 1`。 

## アプローチ

 ブルートフォースのアイデアは単純です。 すべての兵士のペアを比較し、円内で隣同士であるかどうかを確認し、最小の身長差を追跡します。 あるので$n^2$ペアの場合、最悪の場合の操作数は約$100^2 = 10{,}000$、それでも完全に許容できます。 

ここでブルートフォースの問題はパフォーマンスではなく、不必要な作業です。 隣接する兵士のみが許可されるため、ほとんどのペアは無関係です。 問題の構造から、どの比較が重要であるかが正確にわかります。 

各兵士には隣人が 2 人だけです。 円の周りを 1 周してすべての隣接するペアを比較すると、すべての有効な候補を 1 回だけ検査することになります。 これにより、タスクが単純なリニア スキャンに減ります。 

重要な観察は、答えは次のペアのいずれかから得られる必要があるということです。```
(1,2), (2,3), ..., (n-1,n), (n,1)
```他のペアは合法ではありません。 

したがって、最適解はすべての隣接ペアをチェックし、それらの絶対差を計算し、最小のものを記憶します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | 承認済み |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 兵士の数と身長を読み取ります。 
2. 現在の最良の差を非常に大きな値で初期化します。 
3. 以下のすべての位置を反復処理します。`0`に`n-1`。 
4. ポジションごとに`i`、その近隣を次のように決定します`(i + 1) % n`。 

The modulo operation is what makes the array circular. いつ`i`が最後のインデックスである場合、隣人が最初の兵士になります。 
5. 2 つの隣接する高さの間の絶対差を計算します。 
6. この差が現在の最良値より小さい場合は、回答インデックスを更新し、新しい最小差を保存します。 
7. スキャンが終了したら、1 から始まるインデックスを使用して保存されたペアを印刷します。 

### なぜ効果があるのか

 このアルゴリズムは、すべての有効な隣接ペアを 1 回だけチェックします。 この問題では円内に隣接する兵士のみが許可されるため、このセットの外には有効な答えは存在しません。 これまでに確認された最小の絶対差を維持することにより、アルゴリズムは、スキャン終了後に保存されたペアが最適であることを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

best_diff = float('inf')
ans_l = 1
ans_r = 2

for i in range(n):
    j = (i + 1) % n
    diff = abs(a[i] - a[j])

    if diff < best_diff:
        best_diff = diff
        ans_l = i + 1
        ans_r = j + 1

print(ans_l, ans_r)
```プログラムは、兵士の身長を配列に読み取ることから始まります。`best_diff`これまでに見つかった最小の差を保存します。 無限大から始まるため、最初のペアが常に置き換えられます。 

ループはすべての兵士を 1 回スキャンします。 インデックスごとに`i`、次の近傍は次のように計算されます。```
j = (i + 1) % n
```これは最も重要な実装の詳細です。 モジュロがなければ、最後の兵士には右側の隣人が存在せず、循環ペアは存在しません。`(n,1)`スキップされてしまいます。 

高さの順序は重要ではないため、比較では絶対差が使用されます。```
diff = abs(a[i] - a[j])
```Codeforces の問題では通常、1 から始まるインデックスが想定されているため、インデックスは保存時に 1 から始まる形式に変換されます。 

このアルゴリズムは、一定の追加メモリと配列の 1 回の走査のみを使用します。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))

    best_diff = float('inf')
    ans_l = 1
    ans_r = 2

    for i in range(n):
        j = (i + 1) % n
        diff = abs(a[i] - a[j])

        if diff < best_diff:
            best_diff = diff
            ans_l = i + 1
            ans_r = j + 1

    print(ans_l, ans_r)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()

    backup_stdout = sys.stdout
    sys.stdout = out

    solve()

    sys.stdout = backup_stdout
    return out.getvalue().strip()

# provided sample
assert run("5\n10 12 13 15 10\n") == "5 1", "sample 1"

# minimum size
assert run("2\n100 1\n") == "1 2", "minimum n"

# all equal values
assert run("4\n7 7 7 7\n") == "1 2", "all equal"

# circular edge case
assert run("5\n10 20 30 40 11\n") == "5 1", "last-first pair"

# multiple optimal answers
assert run("4\n1 3 5 7\n") == "1 2", "many valid answers"

# decreasing sequence
assert run("6\n20 18 16 14 12 10\n") == "1 2", "consistent differences"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`2 / 100 1`|`1 2`| 最小入力サイズ |
 |`4 / 7 7 7 7`|`1 2`| どこでも差異ゼロ |
 |`5 / 10 20 30 40 11`|`5 1`| 円形近傍の処理 |
 |`4 / 1 3 5 7`|`1 2`| 複数の最適な答え |

 ## 特殊なケース

 円形の境界の場合を考えてみましょう。```
5
10 12 13 15 10
```アルゴリズムは次の順序でペアをチェックします。```
(1,2), (2,3), (3,4), (4,5), (5,1)
```最終的な比較で違いがわかる`0`、これが新しい最小値になります。 モジュロ演算は最後の兵士を最初の兵士に戻すため、正解は`5 1`が見つかりました。 

次に、同じ高さについて考えてみましょう。```
4
7 7 7 7
```隣接するすべてのペアには違いがあります`0`。 最初の比較ではすでに最小値が次のように設定されています`0`、そしてそれ以降のペアはそれを改善しません。 アルゴリズムは戻ります`1 2`これは、最適なペアを出力できるため有効です。 

最後に、可能な最小の入力を調べます。```
2
100 1
```ループは以下をチェックします。```
(1,2)
(2,1)
```最初のペアはすでに最小の差に達しています`99`。 アルゴリズムは保存して出力します`1 2`。 円の概念が同じペアを逆の順序で複製しても、答えは正しいままです。
