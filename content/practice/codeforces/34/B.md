 ## 解決策
 ## 問題の理解

 ボブは古いテレビのコレクションのセールに参加しています。それぞれに値段が付いています。 無料のテレビもあれば、プラスの価格が設定されているテレビもあれば、マイナスの価格が設定されているテレビもあります。これは、所有者がボブにお金を払って引き取ってもらうことを意味します。 ボブは最大で _m_ 台のテレビを持ち運べるので、稼げる合計金額を最大化したいと考えています。 入力により、TV の数 _n_、持ち込み制限 _m_、および TV 価格の配列が得られます。 出力は、ボブが最大 _m_ 台のテレビを選択することで獲得できる最大金額です。 

制約は小さく、_n_ と _m_ は最大 100、テレビの価格は -1000 から 1000 の間です。これは、効率を心配することなく、時間計算量がおよそ O(n log n) または O(n²) までのアルゴリズムを許容できることを意味します。 

微妙な点は、ボブはマイナス価格のテレビからのみ恩恵を受けるということです。 プラスの価格でテレビを選ぶと、トータルの利益が減少します。 符号を確認せずに最も安いテレビを盲目的に合計する単純な実装では、誤ってプラスの価格が含まれ、合計額が減少します。 たとえば、_n = 5_、_m = 3_、価格が次の場合、`-5 2 4 1 3`、正解は`5`(選ぶだけ`-5`）、 ない`2 + 4 + 1 = 7`単純に昇順に並べ替えて最初の 3 つを合計するだけの場合、不注意なアプローチによって引き起こされる可能性があります。 

もう 1 つのエッジ ケースは、マイナス価格のテレビが _m_ 台未満である場合です。 その場合、ボブは利用可能なマイナス価格のみを取得し、残りは無視する必要があります。無料またはプラスのテレビを取得しても利益は増加しないためです。 

## アプローチ

 ブルートフォース手法では、サイズが _m_ までの TV のすべてのサブセットを考慮し、各サブセットの合計金額を計算します。 ボブは組み合わせごとにマイナスの価格を合計します。 これはすべての可能性をチェックするので正しいですが、複雑さは指数関数的です。O(2ⁿ) 個のサブセットがあります。 _n = 100_ の場合、これは明らかに実行不可能です。 

重要な洞察は、ボブの合計にプラスに寄与するテレビは、価格がマイナスのテレビだけであるということです。 したがって、最大 _m_ 台のテレビまで、最小のマイナス価格を選択するだけで済みます。 配列を昇順に並べ替えると、すべての負の価格が最初に来るようになります。 次に、最初の _m_ 要素を反復処理して、負の値のみを合計します。 これにより、問題は、すべてのサブセットを考慮することから、単純なソートとそれに続く線形スキャンへと軽減されます。 

ブルート フォース アプローチは、すべての可能性を探索するため機能しますが、指数関数的な組み合わせにより _n_ が増大すると失敗します。 負の価格のみが重要であるという観察により、問題を配列の小さなプレフィックスの並べ替えと合計に減らすことができ、O(n log n) の解決策を達成できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2ⁿ) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(1) または O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テレビの台数を読み取る`n`そして持ち込み制限`m`、価格の配列とともに。 
2. 価格の配列を昇順に並べ替えます。 これにより、すべてのマイナス価格が前面に表示されます。 
3. 変数を初期化する`total`これにより、ボブの収益が蓄積されます。 
4. 最初のものを繰り返します`m`ソートされた配列の要素。 
5. 各価格について、それが負の場合は、その絶対値を加算（または同等の減算）します。`total`。 ゼロまたは正の場合は、これ以上 TV を実行しても合計が増加しないため、反復を停止します。 
6. 蓄積された値を出力する`total`。 

これが機能するのは、並べ替え後の最初の`m`要素は最小であり、負の数のみがボブのゲインにプラスに寄与します。 不変条件は、どのステップでも、`total`ボブがこれまでに選択した負の価格の絶対値の合計に等しい。 正の数値は合計を増加させないため、無視しても安全です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
prices = list(map(int, input().split()))

prices.sort()
total = 0

for i in range(min(m, n)):
    if prices[i] < 0:
        total += -prices[i]
    else:
        break

print(total)
```コードは最初に読み取られます`n`そして`m`そして価格表。 並べ替えると、負の価格が前面に表示されます。 ループは最大で反復されます`m`マイナスでない価格に遭遇した場合は早期に停止します。 追加`-prices[i]`マイナスのコストをプラスの収益に変換します。 の`min(m, n)`次の場合に決して範囲外に出ないことを保証します`m > n`問題は保証しますが、`m ≤ n`。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | ソートが実行時間を支配し、最大 m 個の要素の反復処理は最悪の場合 O(n) です。 
| スペース | O(1) または O(n) | 実装によっては、並べ替えに O(n) 個の追加スペースが必要になる場合があります。それ以外の場合は、単一の変数を使用するだけです。`total`|

 n ≤ 100 の場合、O(n log n) 操作は約 700 ステップであり、2 秒の制限をはるかに下回ります。 メモリ使用量は、256 MB の制限に比べて無視できます。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, m = map(int, input().split())
    prices = list(map(int, input().split()))
    prices.sort()
    total = 0
    for i in range(min(m, n)):
        if prices[i] < 0:
            total += -prices[i]
        else:
            break
    return str(total)

# provided sample
assert run("5 3\n-6 0 35 -2 4\n") == "8", "sample 1"

# custom test cases
assert run("5 3\n-5 2 4 1 3\n") == "5", "only negative TV picked"
assert run("3 3\n1 2 3\n") == "0", "all positive, pick none"
assert run("4 5\n-1 -2 -3 -4\n") == "10", "m > number of TVs negative"
assert run("1 1\n-1000\n") == "1000", "single negative TV"
assert run("2 1\n0 -1\n") == "1", "zero and negative, pick negative"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 5 3、-5 2 4 1 3 | 5 | ネガティブなテレビのみが寄与する |
 | 3 3、1 2 3 | 0 | 全てがポジティブ、何も稼げない |
 | 4 5、-1 -2 -3 -4 | 10 | m はネガティブなテレビの数より大きい |
 | 1 1、-1000 | 1000 | 大きなマイナス価格の単一テレビ |
 | 2 1、0 -1 | 1 | ゼロと負、負を選択 |

 ## 特殊なケース

 マイナス価格が以下の場合`m`、アルゴリズムはまだ機能します。 入力用`4 5`そして価格`-1 -2 -3 -4`、ソートされた配列は次のようになります。`-4 -3 -2 -1`。 4 つの負の価格すべてを反復処理し、その絶対値を合計して取得します。`10`、テレビがなくなったのでやめます。 それでも`m = 5`、範囲外の要素にアクセスすることはありません。 これにより、アルゴリズムが次のようなケースを処理することが確認されます。`m`マイナス価格の数を正しく超えています。 

すべての価格がプラスの場合、たとえば`1 2 3`と`m = 3`、最初に並べ替えられた要素は 1 で、これは負ではありません。 ループはすぐに中断され、合計は`0`。 これは、アルゴリズムがボブの収入を減らすテレビの選択を正しく回避していることを示しています。
