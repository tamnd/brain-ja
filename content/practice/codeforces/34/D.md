 ## 解決策
 ## 問題の理解

 私たちに与えられた木は、`n`都市。 もともとは都市`r1`は首都とみなされ、他のすべての都市については、根が張ったツリーでその親がわかります。 値`p[i]`ということは、古都から街に向かって歩くと`i`、到達する前の最後の都市`i`は`p[i]`。 

王は首都をから変更します`r1`に`r2`。 道路自体は変化せず、木の根元が変化するだけです。 ツリーのルートが次の場合は、新しい親配列を出力する必要があります。`r2`。 

入力はすでに有効なツリーを記述しています。 ルートを除くすべての都市には親が 1 つだけあるため、親リストにはすべての都市が表示されます。`n - 1`エッジ。 課題は、再ルート後に親子関係を再構築することです。 

制約が十分に大きいため、二次解は安全ではありません。 と`n`まで`5 * 10^4`、`O(n^2)`アルゴリズムには次のものが必要になる可能性があります`2.5 * 10^9`制限時間を大幅に超えた最悪の場合の作戦。 直線または直線に近い横断が期待されます。 ツリーには正確な内容が含まれるため、DFS および BFS にとって特に適しています。`n - 1`エッジなので、完全な走査にかかる費用はわずかです`O(n)`。 

新しい首都が古い根の生えた木の奥深くにある場合、微妙な特殊なケースが現れます。 考慮する：```
5 1 5
1 2 3 4
```元の構造は次のとおりです。```
1 - 2 - 3 - 4 - 5
```で再ルートした後、`5`、パス上のすべてのエッジの方向を反転する必要があります。 正しい出力は次のようになります。```
2 3 4 5
```の直接の親のみを変更する不用意な解決策`5`残りは変更されないままになり、無効なルート付きツリーが生成されます。 

もう 1 つの簡単な間違いは、入力を再構築するときに発生します。 親配列は古いルートをスキップします`r1`、そのため、インデックスは入力位置と直接整列しません。 例えば：```
4 2 1
2 2 3
```値は以下に対応します。```
p[1] = 2
p[3] = 2
p[4] = 3
```それらを位置に読み取るバグのあるパーサー`1..n-1`機械的に間違ったエッジが取り付けられてしまいます。 

3 番目の特殊なケースには、再帰の深さが関係します。 鎖状の木と`50000`頂点により、Python の再帰 DFS がデフォルトの再帰制限を超えます。 アルゴリズム自体は正しいですが、再帰制限を増やすか反復走査を使用しないと実装がクラッシュします。 

## アプローチ

 ブルートフォースのアイデアは単純です。 新しいルートを除くすべてのノードについて`r2`、再ルートされたツリー内でその親を個別に検索できます。 1 つの方法は、次からトラバースを開始することです。`r2`毎回、どのノードが最初にターゲットに到達するかを決定します。 各走査にはコストがかかるため、`O(n)`すべてのノードに対してこれを繰り返すと、全体の複雑さは次のようになります。`O(n^2)`。 

ツリーには独自の単純なパスがあるため、ブルートフォースが機能します。 木を根付かせると、`r2`を除くすべてのノード`r2`ルートへのパス上に先行者が 1 つだけあります。 すべてのノードに対してこの関係を最初から再計算することは論理的には正しいですが、コストがかかりすぎます。`50000`ノード。 

重要な観察は、再ルートしてもエッジがまったく変化しないことです。 ルートに対する相対的な方向のみが変わります。 無向ツリーを再構築したら、次から開始して単一の DFS または BFS を実行できます。`r2`。 ノードから移動するたびに`u`ノードへ`v`、私たちは宣言します`u`の親として`v`新しく根を張った木に。 

これにより、問題は標準のツリー走査に変換されます。 木は正確に持っているので、`n - 1`エッジでは、DFS は各方向に 1 回ずつ、合計 2 回だけすべてのエッジを訪問します。 ソリューション全体は線形になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力値を読み取る`n`、`r1`、 そして`r2`。 
2. 親配列から無向ツリーを再構築します。 

あらゆる都市に`i`を除外する`r1`、入力はその親を提供します`p[i]`。 間に無向エッジを追加します`i`そして`p[i]`。 

再ルート後にエッジの方向が逆転する可能性があるため、ツリーは無向になる必要があります。 
3. 配列を作成する`parent`サイズの`n + 1`。 

この配列には、ルート化後のすべてのノードの新しい親が格納されます。`r2`。 
4.から DFS を開始します`r2`。 

DFS中、ノードから移動する場合`u`訪れていない隣人へ`v`、割り当てます:```
parent[v] = u
```これは正しいです。なぜなら、`u`まさにそのノードです`v`root トラバースで到達します。 
5. すべてのノードにアクセスするまで続行します。 

グラフはツリーであるため、DFS はすべてのノードに 1 回だけ到達します。 
6. 新しい親配列を元の形式で出力します。 

出力では新しいルートがスキップされます`r2`ルートには親がないためです。 

### なぜ効果があるのか

 旅は新首都から始まる`r2`したがって、DFS ツリーのすべてのエッジは新しいルートから離れる方向を指します。 訪問したノードごとに`v`、最初のノード`u`そこに到達するのは、`v`からの道中で`r2`に`v`。 ツリーには、任意の 2 つの頂点間に単純なパスが 1 つだけ含まれるため、代替の親の割り当ては不可能です。 

DFS は到達可能なすべてのノードを 1 回だけ探索し、グラフが接続されるため、`r2`親を 1 つだけ受け取ります。 結果として得られる構造は、ルートを持つ有効なルート付きツリーです。`r2`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(1 << 20)

n, r1, r2 = map(int, input().split())

adj = [[] for _ in range(n + 1)]

values = list(map(int, input().split()))

ptr = 0
for node in range(1, n + 1):
    if node == r1:
        continue

    p = values[ptr]
    ptr += 1

    adj[node].append(p)
    adj[p].append(node)

parent = [0] * (n + 1)
visited = [False] * (n + 1)

def dfs(u):
    visited[u] = True

    for v in adj[u]:
        if not visited[v]:
            parent[v] = u
            dfs(v)

dfs(r2)

answer = []

for node in range(1, n + 1):
    if node == r2:
        continue
    answer.append(str(parent[node]))

print(" ".join(answer))
```最初の部分では、ツリーを注意深く再構築します。 入力では古いルートが省略されます`r1`、そのため、別のポインタを使用します`ptr`親の値を正しく消費するため。 これは、インデックス作成のバグが最も入り込みやすい場所の 1 つです。 

隣接リストには、無向エッジが格納されます。 元の入力ですでに親関係が指定されている場合でも、それらの方向は古いルートに結び付けられており、再ルートすると役に立たなくなります。 

DFS は、新しいルートの観点から親を動的に割り当てます。`r2`。 DFS が次から移動するときは常に`u`に`v`、私たちはそれを知っています`u`の親になります`v`根を戻した木で。 

縮退チェーンには以下が含まれる可能性があるため、再帰制限が増加します。`50000`ノード。 この調整がないと、Python は次のようになります。`RecursionError`。 

最後に、出力がスキップされます`r2`、ステートメントの形式と正確に一致します。 順序は依然としてノード インデックスによるものであり、走査順序ではありません。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各ノードとエッジは DFS 中に 1 回処理されます。 
| スペース | O(n) | 隣接リスト、親配列、および訪問先配列はすべて線形にスケールします。 

と`50000`頂点、線形の複雑さは制限内に簡単に収まります。 隣接リストには正確に保存されます`2 * (n - 1)`エッジ エントリ。メモリ境界内に問題なく収まります。 

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    sys.setrecursionlimit(1 << 20)

    n, r1, r2 = map(int, input().split())

    adj = [[] for _ in range(n + 1)]

    values = list(map(int, input().split()))

    ptr = 0
    for node in range(1, n + 1):
        if node == r1:
            continue

        p = values[ptr]
        ptr += 1

        adj[node].append(p)
        adj[p].append(node)

    parent = [0] * (n + 1)
    visited = [False] * (n + 1)

    def dfs(u):
        visited[u] = True

        for v in adj[u]:
            if not visited[v]:
                parent[v] = u
                dfs(v)

    dfs(r2)

    ans = []

    for node in range(1, n + 1):
        if node == r2:
            continue
        ans.append(str(parent[node]))

    print(" ".join(ans))

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out

    solve()

    sys.stdout = sys.__stdout__
    return out.getvalue().strip()

# provided sample
assert run("3 2 3\n2 2\n") == "2 3", "sample 1"

# minimum size
assert run("2 1 2\n1\n") == "2", "minimum tree"

# chain reroot
assert run("5 1 5\n1 2 3 4\n") == "2 3 4 5", "full path reversal"

# balanced tree
assert run("5 1 3\n1 2 3 3\n") == "2 3 3 3", "reroot in middle"

# star centered at old root
assert run("4 1 2\n1 1 1\n") == "2 2 1", "many children of old root"

 | --- | --- | --- |
 |`2 1 2`|`2`| 最小有効ツリー |
 | 末端に新しいルートを持つチェーン |`2 3 4 5`| 親の方向を完全に逆転 |

 ## 特殊なケース

 鎖状のツリーを考えてみましょう。```
5 1 5
1 2 3 4
```元のルート構造は次のとおりです。```
1 -> 2 -> 3 -> 4 -> 5
```DFS は次から始まります`5`。 

初め、`parent[4] = 5`。 

それから、`parent[3] = 4`。 

それから、`parent[2] = 3`。 

ついに、`parent[1] = 2`。 

生成される出力は次のとおりです。```
2 3 4 5
```DFS は新しいルートから離れた一意のパスを自然にたどるため、すべてのエッジの方向が正しく反転します。 

ここで、インデックスに依存する入力について考えてみましょう。```
4 2 1
2 2 3
```古い根は、`2`したがって、値は次のようになります。```
p[1] = 2
p[3] = 2
p[4] = 3
```再構築されたツリーは次のとおりです。```
1 - 2 - 3 - 4
```DFSから`1`割り当てます:```
parent[2] = 1
parent[3] = 2
parent[4] = 3
```出力：```
1 2 3
```個別のポインター変数により、スキップされたルートによって入力の位置合わせがシフトされないことが保証されます。 

最後に、次のような深いチェーンを考えます。`50000`ノード。 再帰的 DFS は通常、Python の再帰スタックをオーバーフローさせます。 この実装では、走査前の再帰制限が引き上げられ、アルゴリズムが最悪の場合のツリー形状でも安全に処理できるようになります。
