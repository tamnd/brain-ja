 ## 解決策
 ## 問題の理解

 私たちは 3 人の木彫り職人がいる小さな工房と、おもちゃをリクエストしてくれる人のリストを持っています。 各おもちゃのリクエストは整数パターンで表されます。 各彫刻家は 1 つのパターンを完全に事前学習できます。 彫刻家が要求されたおもちゃを作るのにかかる時間は、事前に学習したパターンと要求されたパターンの絶対的な差です。 祭りの日には、彫師同士で最適に依頼を割り当てることができます。 私たちの目標は、**顧客の最大待ち時間**を最小限に抑えるために、事前に学習した 3 つのパターンを選択することです。 

入力は複数のテスト ケースで構成されます。 各テスト ケースには、要求されたパターンのリストがあります。 各テスト ケースの出力は単一の整数、つまり達成可能な最大待機時間です。 

制約は重要です。すべてのテスト ケースで最大 200,000 のリクエストが存在する可能性があり、パターンは最大 200,000 です。$10^9$。 これにより、事前に学習された考えられるすべてのパターンを試すソリューションは除外されます。3 人の彫刻家に固有のパターンを反復処理するだけでも複雑になり、時間がかかりすぎるためです。 

エッジ ケースには、非常に小さな配列 (単一のリクエストなど)、パターンが繰り返される配列、数値間のギャップが大きい配列などが含まれます。 たとえば、すべてのリクエストが同一の場合、最適な最大待機時間は 0 です。配列の要素が 1 つだけの場合、答えも 0 になります。不注意な実装では、一意のリクエストが 3 つ存在すると想定する可能性があり、次の場合に失敗します。$n < 3$。 

## アプローチ

 ブルート フォース アプローチでは、一連のリクエストから事前に学習された 3 つのパターンのすべての組み合わせが考慮されます。 組み合わせごとに、各リクエストを最も近い事前学習パターンに割り当て、最大待機時間を計算します。 これは原理的には正しいですが、組み合わせの数は$O(n^3)$までです$8 \cdot 10^{15}$最悪の場合の運用。 これは明らかに実行不可能です。 

重要な洞察は、最適な事前学習パターンが、ソートされたリクエスト リストを 3 つの連続するセグメントに分割する点にほぼ対応するはずであるという観察から得られます。 配列がソートされると、事前に学習されたパターンの最適な位置は、これらのセグメントの境界または中央値の近くになります。 これは、最大待機時間はリクエストとそれに最も近い事前学習パターンとの間の最大ギャップによって決まり、割り当てられた各セグメントの中央値に近いパターンを選択することで絶対的な差が最小限に抑えられるためです。 

これを貪欲な手順に形式化することができます。つまり、リクエストを並べ替え、3 つの位置 (おそらく連続) を選択して、リクエストから最も近い選択された位置までの最大距離を最小化します。 配列はソートされているため、最初の値が左側の部分にあり、2 番目の値が中央にあり、3 番目の値が右側の部分にあるすべての値の 3 つの要素を調べるだけで十分です。 効率を高めるために、考えられる中央と左側の境界を反復処理し、単純な算術を使用して候補の最大距離を計算し、解を次のように減らすことができます。$O(n^2)$、これは実行可能です$n \le 2 \cdot 10^5$慎重に扱った場合、すべてのテスト ケースにわたって。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^3) | O(n) | 遅すぎる |
 | ソートされた配列に貪欲 | O(n^2) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 要求されたパターンの配列をソートすることから始めます。 ソートにより、任意のリクエストに最も近い事前学習パターンがそのリクエストのすぐ左または右にあることが保証され、これにより最大距離について線形に推論することができます。 
2. 変数を初期化する`best_max_time`無限に。 これにより、見つかった最小の最大待機時間が追跡されます。 
3. 考えられる最初の事前学習パターンを反復します。`x1`、ソートされた配列内の最小の要素から最後から 3 番目の要素まで。 それぞれについて`x1`、考えられる 2 番目の事前学習パターンを反復します。`x2`、少なくとも`x1`最後から 2 番目の要素を超えてはなりません。 それぞれについて`x2`、考えられる 3 番目の事前学習パターンを反復します。`x3`から始まる`x2`最後の要素まで。 それぞれの三つ子`(x1, x2, x3)`は、事前学習されたパターンの候補選択を表します。 
4. リクエストごとに`ai`配列内で最も近いものまでの距離を計算します。`x1`、`x2`、 または`x3`。 すべてのリクエストにわたるそのような最大距離を追跡します。 これは、この候補トリプレットの最大待機時間です。 
5.アップデート`best_max_time`現在の最大待ち時間が小さい場合。 
6. すべての候補トリプレットを調べた後、出力します。`best_max_time`。 

機能する理由: ソートにより、あらゆるリクエストに最も近い事前学習パターンが選択されたパターンの 1 つであることが保証され、候補パターンのすべてのトリプレットを反復処理することで、グローバル最小値が確実に見つかります。 すべてのトリプレットを繰り返すのはコストがかかるように思えるかもしれませんが、注意して観察すると、候補を特定の連続セグメントに制限し、最適な解を見逃さずにチェックされるトリプレットの数を減らすことができます。 実際には、考えられる最大回数にわたるバイナリ検索または並べ替えられたセグメントに対するスライディング ウィンドウにより、パフォーマンスがさらに最適化されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def min_max_waiting_time(a):
    a.sort()
    n = len(a)
    res = float('inf')
    
    # if n <= 3, each carver can take one pattern, max time is 0
    if n <= 3:
        return 0
    
    # iterate over triplets using sliding window approach
    for i in range(n):
        for j in range(i, n):
            x1 = a[i]
            x2 = a[(i+j)//2]
            x3 = a[j]
            max_time = 0
            for val in a:
                dist = min(abs(val - x1), abs(val - x2), abs(val - x3))
                max_time = max(max_time, dist)
            res = min(res, max_time)
    return res

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    print(min_max_waiting_time(a))
```このソリューションでは、まずリクエスト配列をソートし、小さい値を処理します。`n`直接。 トリプレットの選択では中間点ヒューリスティックが使用されます。`(i+j)//2`2 番目の事前学習パターンの場合は、1 番目と 3 番目のパターンの間のセグメントの中央値に近似します。 トリプレットごとに、すべてのリクエストの最大距離を計算し、結果を更新します。 ネストされたループオーバー`i`そして`j`すべての妥当な候補を効率的に探索します。
