 ## 解決策
 ## 問題の理解

 二進法をテーマにしたカフェでトーマがデザートを選ぶ方法の数を数えるように求められます。 各デザートのコストは 2 の累乗です。最初のデザートのコストは 1 コイン、2 番目のデザートは 2 コイン、3 番目のデザートは 4 コインというように順番に続きます。$2^0, 2^1, 2^2, \dots, 2^{k-1}$。 トーマには予算がある$n$そしてデザートは何度も買わない。 目標は、何も買わない空のサブセットを含め、彼が買えるデザートのサブセットがいくつあるかを判断することです。 

入力では、それぞれが独自の複数のテスト ケースを指定します。$n$そして$k$。 制約により許可されるのは、$n$そして$k$まで行く$10^9$。 これにより、すべてのサブセットまたは合計を列挙する解は即座に除外されます。$k$デザートは$2^k$、これは天文学的に大きい$k$10億近く。 

エッジケースには、予算が最も安いデザートよりも少ない状況が含まれます。 たとえば、次の場合$n = 1$そして$k = 1$、手頃なサブセットは空のサブセットと最初のデザートのみです。 別の微妙なケースが発生するのは、$n$すべての合計より大きいです$k$デザート。 ここでは、すべてのサブセットが手頃な価格であり、その答えは次のとおりです。$2^k$。 

## アプローチ

 ブルートフォースアプローチでは、デザートのすべてのサブセットを列挙し、そのコストを合計し、以下を超えないものをカウントします。$n$。 これは非常に小さい場合に機能します$k$、でも$k = 30$生成する$2^{30} \approx 10^9$サブセットが多すぎます。 のために$k = 10^9$、これは不可能です。 

重要な洞察は、コストの二項構造を活用することです。 各デザートのコストは 2 の累乗であり、2 の累乗の合計は 2 進数に正確に対応し、各ビットはデザートが選択されたかどうかを表します。 次に、問題は 0 から 0 までの整数の個数を数えるということになります。$2^k - 1$(サブセット合計の全範囲) 以下である$n$。 計算できない$2^k$直接大規模な$k$、しかし、次の場合は観察できます。$2^k \le n+1$、 全て$2^k$サブセットは手頃な価格です。 それ以外の場合、サブセットの数は正確に$n+1$、サブセットの合計は 0 から合計までの連続した整数であり、以下を超えないものだけが必要であるためです。$n$。 

これにより、単純かつ直接的な公式が得られます。Toma がデザートを購入できる方法の数は次のとおりです。$\min(n + 1, 2^k)$。

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取り、$t$。 各ケースを個別にループしていきます。 これは、複数のクエリに対する標準の入力処理です。 
2. 各テスト ケースについて、次の内容を読んでください。$n$そして$k$。 ここ$n$は予算であり、$k$デザートの数です。 
3. コンピューティング$2^k$。 もし$k$が大きいと、一般的な整数型がオーバーフローする可能性がありますが、Python は任意のサイズの整数を処理します。 ただし、比較する必要があるのは、$n+1$なので、値が超えたら乗算を停止できます。$n+1$計算を節約します。 
4. 最小値として答えを計算します。$n+1$そして$2^k$。 これは両方の状況に当てはまります:$n$すべてのデザートの合計より小さい、または$n$すべてのサブセットを購入できます。 
5. 各テスト ケースの答えを出力します。 

機能する理由: 2 のべき乗コストにより、デザートの各サブセットが一意の整数の合計に対応することが保証されます。 最小の合計は 0 で、合計は 2 のべき乗のすべての組み合わせによって増加します。 したがって、合計を数えると、$n$の最小値を取ることと同じです$n+1$そして$2^k$, 合計は 0 からすべてのデザートの合計まで正確に連続する整数であるためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, k = map(int, input().split())
    # Compute 2^k safely without overflow using a loop if necessary
    power = 1
    for _ in range(k):
        if power > n:
            break
        power *= 2
    print(min(n + 1, power))
```ソリューションはすべてのテスト ケースを読み取り、計算します。$2^k$不必要な巨大な整数を慎重に回避し、min 関数を使用して手頃なサブセットの数を決定します。 微妙な点は、一度$2^k$を超える$n$、最小値はすでに次の値になるため、さらに乗算する必要はありません。$n+1$。 Python は大きな整数を処理しますが、この早期のブレークにより、次の極端な値に対する効率が保証されます。$k$。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | テスト ケースごとの O(k) | 累乗を計算するために最大 k 回ループしますが、累乗が n を超える場合は早期に中断します。 |
 | スペース | お(1) | n または k に関係なく、少数の整変数のみが使用されます。 |

 このソリューションは、時間とメモリの制限内に快適に収まります。$t = 1000$そして$k = 10^9$実際には、power > n になるとループが早期に中断されるためです。

## 特殊なケース

 もし$n = 0$の場合、アルゴリズムは空のサブセットに対応する 1 を正しく出力します。 例えば、$n = 0, k = 10$空のサブセットのみが手頃な価格であるため、1 が生成されます。 もし$k = 1$そして$n = 1$の場合、空のセットと 1 つのデザートの両方が予算内であるため、アルゴリズムは 2 を出力します。 いずれの場合も、ループは 2 の累乗を正しく乗算しますが、2 の累乗を超えるとすぐに停止します。$n+1$、次のような場合でも効率を確保します。$k$非常に大きいです。
