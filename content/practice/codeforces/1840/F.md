 ## 解決策
 ## 問題の理解

 座標のグリッド上を移動します。`(0, 0)`に`(n, m)`。 

1 秒ごとに、最初の座標を 1 つ増やすか、2 番目の座標を 1 つ増やすか、または現状のままにすることができます。 アクション後の位置は、その秒に発射されたすべてのレールガンのショットに対してチェックされた位置です。 

水平ショットと座標`x`最初の座標が等しいすべての位置を強制終了します`x`。 コーディネート付きの縦ショット`y`2 番目の座標が等しいすべての位置を強制終了します`y`。 

目標は達成することです`(n, m)`対応する時間にショットが当たったセルの上に立つことなく、できるだけ早く。 

最初の観察は、動きの構造から得られます。 私たちが現在いるとしたら、`(i, j)`そしてまさに待っていました`k`これまでの時刻が完全に決定されます。$$t = i + j + k$$あらゆる垂直移動が増加します`i`、水平移動ごとに増加します`j`、待ち時間が増えるたびに`k`。 

制約が異常に見えます。 グリッドには最大で次のものを含めることができます`10^4`すべてのテスト ケースにわたるセルの合計。これはグリッド セルごとの状態に問題がないほど十分な大きさです。 ショット数は最大です`100`、小さいです。 ショット時間は次のように長くすることができます。`10^9`したがって、時間を明示的にシミュレートする解決策は不可能です。 

重要な問題は、どれくらいの待ち時間を考慮する必要があるかということです。 しかないので、`r ≤ 100`最適なパスにはこれ以上のものは必要ありません。`r`待ちます。 これにより、状態空間が潜在的に数十億の瞬間から約わずかに縮小されます。`100`層。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

非常に大きなタイミングでショットが発生したとします。```
1 1
1
1000000000 1 0
```答えはまだです`2`。 最大のショット時間までのタイムラインを構築しようとするソリューションは、絶望的に遅くなるでしょう。 

もう 1 つの微妙なケースは、セルで待機していることです。```
1 1
1
1 1 0
```時間に`1`、 行`0`撃たれる。 私たちはこのままではいられない`(0,0)`最初の 1 秒間。 唯一の安全な行動は、ただちにその場を離れることです。 移動後のセルのみをチェックし、待機を無視するソリューションでは、誤ってそこに立つことが許可されてしまいます。 

3 番目のケースは、領域全体が同時にカバーされる場合に発生します。```
3 3
6
2 1 0
2 1 1
2 1 2
2 2 0
2 2 1
2 2 2
```時間に`2`、到達可能なすべての位置が破壊されます。 生き残る道はない、だから答えは`-1`。 ローカルの貪欲な決定ではこれを検出できません。 グローバルな到達可能性の計算が必要です。 

## アプローチ

 ブルートフォースビューとは、状態を次のように扱うことです。`(x, y, time)`そしてBFSを実行します。 各状態から、下に移動するか、右に移動するか、待機することができます。 すべてのアクションのコストは 1 秒であり、BFS は最も早い到着を見つけるため、このアプローチは正しいです。 

問題は時間の次元です。 到達ショットタイム`10^9`したがって、到達可能な状態を時間ごとに保存することさえ不可能です。 

重要な観察は、時間は独立していないということです。 位置がわかれば`(x, y)`そして何回待ちますか`k`が使用されている場合、現在時刻が正確です$$x + y + k.$$これにより、膨大な時間座標が非常に小さな待機座標に置き換えられます。 

なぜ制限できるのか`k`せいぜい`r`? 余分な待機は、ショットを避けるためにのみ存在します。 多くてもあります`r`合計ショット数なので、それ以上を考慮すると`r`待機だけでは最適なソリューションを改善することはできません。 これが問題を解決可能にする中心的な圧縮です。 

今、私たちは州を超えたDPを構築しています`(x, y, k)`。 

状態とは次のことを意味します。 

「その位置に立ってもいいですか？」`(x, y)`正確に使用した後`k`これまでのすべての攻撃を生き延びながら、待つのですか？」

 から`(x, y, k)`私たちは以下から来ることができます：`(x-1, y, k)`垂直に移動することで。`(x, y-1, k)`水平方向に移動することによって。`(x, y, k-1)`1秒待ってください。 

唯一の追加条件は、現在の状態自体を強制終了しないことです。$$t = x + y + k.$$州の数はたったの$$(n+1)(m+1)(r+1),$$which is roughly one million in the worst possible test case, well within limits.

 | アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースオン`(x,y,time)`| 時間切れのため不可能`10^9`| 不可能 | 遅すぎる |
 | DPオン`(x,y,waits)`|`O(nmr)`|`O(nmr)`| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 3次元配列を作成する`free[x][y][k]`。`free[x][y][k]`状態かどうかを示します`(x, y, k)`安全です。 
2. すべてのショットについて、そのショットによって死亡するすべての州にマークを付けます。 

水平ショットが列にヒットした場合`x = coord`時に`t`、その後、満足するすべての状態$$x = coord,\quad t = x + y + k$$は禁止されています。 

並べ替えると$$k = t - coord - y.$$列ごとに`y`、これなら`k`にある`[0,r]`、状態を危険としてマークします。 
3. 垂直方向のショットも同様に処理します。 

コラム撮影の場合`y = coord`そして時間`t`:$$k = t - coord - x.$$その方程式に一致するすべての有効な状態は安全でなくなります。 
4. DP アレイの作成`dp[x][y][k]`。`dp[x][y][k] = True`状態が到達可能で安全であることを意味します。 
5.初期化`dp[0][0][0] = True`。 
6. すべての状態を昇順に繰り返します。`x`、`y`、 そして`k`。 

状態が安全でない場合はスキップしてください。 

それ以外の場合は、次の場所からアクセスします。 

-`(x-1, y, k)`-`(x, y-1, k)`-`(x, y, k-1)`それらの状態が到達可能なときはいつでも。 
7. すべての状態を調べる`(n, m, k)`。 

到達可能な場合、到着時間は$$n + m + k.$$そのような最小の時間を選択してください。 
8. 到達可能な終端状態が存在しない場合、出力`-1`。 

### なぜ効果があるのか

 不変条件とは、`dp[x][y][k]`位置に到達する有効なアクションのシーケンスが存在する場合にのみ true になります。`(x,y)`使用後`k`遭遇するすべてのショットを待ち、生き残ります。 

すべての法的措置は、3 つの量のうちの 1 つを正確に変更します。`x`、`y`、 または`k`1 ずつ増加するため、すべての有効なパスは DP 遷移のシーケンスに対応します。 逆に、すべての DP 移行は 1 つの法的措置を意味します。 危険な状態は事前に除去されるため、到達可能なすべての DP 状態は生存可能なゲーム状態に対応します。 

時間は一意に決まるので、`x+y+k`、すべてのショットの制約が正確な瞬間にチェックされます。 したがって、DP はすべての有効なパスと、到達可能な最小値を正確に特徴付けます。`n+m+k`可能な限り最も早い到着時間です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n, m = map(int, input().split())
        r = int(input())

        free = [[[True] * (r + 1) for _ in range(m + 1)]
                for _ in range(n + 1)]

        for _ in range(r):
            tt, d, coord = map(int, input().split())

            if d == 1:
                x = coord
                if 0 <= x <= n:
                    for y in range(m + 1):
                        k = tt - x - y
                        if 0 <= k <= r:
                            free[x][y][k] = False
            else:
                y = coord
                if 0 <= y <= m:
                    for x in range(n + 1):
                        k = tt - y - x
                        if 0 <= k <= r:
                            free[x][y][k] = False

        dp = [[[False] * (r + 1) for _ in range(m + 1)]
              for _ in range(n + 1)]

        dp[0][0][0] = free[0][0][0]

        for x in range(n + 1):
            for y in range(m + 1):
                for k in range(r + 1):
                    if x == 0 and y == 0 and k == 0:
                        continue

                    if not free[x][y][k]:
                        continue

                    ok = False

                    if x > 0 and dp[x - 1][y][k]:
                        ok = True
                    if y > 0 and dp[x][y - 1][k]:
                        ok = True
                    if k > 0 and dp[x][y][k - 1]:
                        ok = True

                    dp[x][y][k] = ok

        ans = -1

        for k in range(r + 1):
            if dp[n][m][k]:
                ans = n + m + k
                break

        print(ans)

solve()
```前処理フェーズでは、ショット情報を禁止された DP 状態に直接変換します。 これは、ソリューションの最もエレガントな部分です。 ある州が銃撃を受けるかどうかを尋ねる代わりに、方程式を逆にして、殺されるであろうすべての州を直接マークします。 

DP は、ゲーム内で利用可能な 3 つのアクションを正確に使用します。 上下に動かすと変化します`x`、水平方向に移動すると変化します`y`、変更を待っています`k`。 

簡単な間違いの 1 つは、待つことが本当の移行であるということを忘れることです。 からの移行がなければ、`(x,y,k-1)`に`(x,y,k)`の場合、アルゴリズムは意図的に遅延させるパスを検出することはありません。 

もう 1 つの微妙な点は初期化です。 もし`(0,0,0)`それ自体が禁止されている場合、開始状態は到達不可能であると見なされなければなりません。 

最終的な答えは、到達可能な最小値です。`n+m+k`、ちょうど到着時間です。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |`O(nmr)`| ごとに 1 つの DP 状態`(x,y,k)`|
 | スペース |`O(nmr)`| 店舗`free`そして`dp`配列 |

 以来`r ≤ 100`との合計値`n·m`すべてのテストケース全体で最大でも`10^4`、州の総数はおおよそ次のとおりです。`10^6`。 これは時間とメモリの制限内に問題なく収まります。 

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline
    out = []

    t = int(input())

    for _ in range(t):
        n, m = map(int, input().split())
        r = int(input())

        free = [[[True] * (r + 1) for _ in range(m + 1)]
                for _ in range(n + 1)]

        for _ in range(r):
            tt, d, coord = map(int, input().split())

            if d == 1:
                for y in range(m + 1):
                    k = tt - coord - y
                    if 0 <= k <= r:
                        free[coord][y][k] = False
            else:
                for x in range(n + 1):
                    k = tt - coord - x
                    if 0 <= k <= r:
                        free[x][coord][k] = False

        dp = [[[False] * (r + 1) for _ in range(m + 1)]
              for _ in range(n + 1)]

        dp[0][0][0] = free[0][0][0]

        for x in range(n + 1):
            for y in range(m + 1):
                for k in range(r + 1):
                    if x == 0 and y == 0 and k == 0:
                        continue
                    if not free[x][y][k]:
                        continue

                    dp[x][y][k] = (
                        (x > 0 and dp[x - 1][y][k]) or
                        (y > 0 and dp[x][y - 1][k]) or
                        (k > 0 and dp[x][y][k - 1])
                    )

        ans = -1
        for k in range(r + 1):
            if dp[n][m][k]:
                ans = n + m + k
                break

        out.append(str(ans))

    return "\n".join(out)
