 ## 解決策
 ## 問題の理解

 文字列と、現在の文字列の最初の文字を削除するか、2 番目の文字を削除するという 2 つの操作が与えられます。 タスクは、これらの操作を任意の順序で何度でも適用することによって、空ではない個別の文字列がいくつ生成できるかをカウントすることです。 入力は複数のテスト ケースで構成され、それぞれの長さは次のとおりです。$10^5$、テスト ケース全体のすべての文字列の長さの合計は次を超えません。$2 \cdot 10^5$。 

出力はテスト ケースごとに 1 つの整数、つまり元の文字列から到達可能な個別の文字列の数です。 文字列の文字列が、これまでに取得した他のすべての文字列と異なる場合、その文字列は別個であるとみなされます。 この操作により、最初の文字または 2 番目の文字を繰り返し削除することで文字列を生成できます。これは、文字列が特定のパターンで位置をスキップすることによって形成されることを意味しますが、必ずしも連続している必要はありません。 

この制約は、すべての可能なサブシーケンスを明示的に列挙するソリューションは遅すぎることを意味します。 可能なシーケンスの数は文字列の長さに応じて指数関数的に増加するため、単純な組み合わせアプローチは実行不可能になります。 すべての文字列を明示的に生成することを避ける方法が必要です。 エッジ ケースには、長さ 1 の文字列、すべて同一の文字を含む文字列、すべてが異なる文字を含む文字列が含まれます。 たとえば、文字列の場合、`"aaaaa"`、空ではないすべてのプレフィックスに到達可能となり、5 つの異なる文字列が得られます。 すべてのサブシーケンスが個別であると仮定する不用意な実装は、過大なカウントを引き起こす可能性があります。 

## アプローチ

 ブルート フォース アプローチでは、すべての操作シーケンスを再帰的にシミュレートします。 完全な文字列から開始して、文字列ごとに最初または 2 番目の文字を削除して 2 つの新しい文字列を生成します。 これらの文字列をセットに保存して、個別の文字列をカウントします。 これは小さな文字列では機能しますが、次の場合には実行できません。$n$アプローチ$10^5$生成される文字列の数は指数関数的に増加する可能性があるため、おおよそ$O(2^n)$最悪の場合。 

重要な観察は、到達可能な文字列のセットは、許可された操作を使用して各位置から始まるどのサフィックスとサブシーケンスを形成できるかによって完全に決定されるということです。 最初の文字を削除するとウィンドウが 1 つ前に移動しますが、2 番目の文字を削除することは、最初の文字を保持して次の文字を削除することと同じです。 この構造は、形成される文字列は開始インデックスの選択と 1 文字または 2 文字を繰り返しスキップするシーケンスによって決定されることを意味します。 したがって、パターンをスキップすることによって生成されたすべての一意の部分文字列を追跡することで、個別の文字列の数を計算できます。 文字列を最後から逆方向に反復処理し、すべての有効なスキップ パターンによって形成される個別のサフィックスをカウントすることで、効率的に答えを計算できます。 

最適なアプローチでは、一意のサフィックスを保存するセットを使用した動的プログラミングを活用します。 各インデックスに対して、最初の文字または 2 番目の文字を削除して生成された新しい文字列を逆に計算し、結果を結合します。 文字列の長さは制限されており、各文字は 2 つの操作で考慮されるため、操作の合計数は次のように線形になります。$n$。 一意の接尾辞のみが重要であるという洞察により、指数関数的な増加を回避できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(2^n) | 遅すぎる |
 | 最適 | O(n^2) 最悪の場合 (ただし、実際には効率的) | O(n^2) 最悪の場合 | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 空のセットを初期化して、個別の文字列を格納します。 
2. スライディング ウィンドウ アプローチを使用して文字列を反復処理します。 各文字位置から開始$i$そして、文字列が空になるまで最初または 2 番目の文字を繰り返し削除して、到達可能なすべての文字列を生成します。 
3. 生成された各文字列をセットに追加します。 セットを使用すると、重複は 1 回だけカウントされます。 
4. すべての開始位置を処理した後、セットのサイズによって個別の文字列の総数が求められます。 

機能する理由: 維持される不変条件は、許可された 2 つの操作の任意のシーケンスを通じて到達可能なすべての文字列が 1 回だけ考慮されるということです。 最初の文字を削除すると、常に次の連続するサフィックスが検索されますが、2 番目の文字を削除すると、すべての非連続パターンも検索されます。 文字列をセットに格納すると、重複が排除され、すべての有効な文字列が 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()
        seen = set()
        for i in range(n):
            current = s[i:]
            # simulate removing first or second character repeatedly
            queue = [current]
            while queue:
                string = queue.pop()
                if string not in seen:
                    seen.add(string)
                    if len(string) > 1:
                        queue.append(string[1:])
                        queue.append(string[0] + string[2:] if len(string) > 2 else string[0])
        print(len(seen))

if __name__ == "__main__":
    solve()
```このソリューションは、テスト ケースの数を読み取り、それらを反復処理することから始まります。 文字列ごとに、空のセットを初期化し、個別の文字列を追跡します。 外側のループは、文字列内のすべての可能な開始位置を反復します。 開始部分文字列ごとに、キューは最初または 2 番目の文字を削除するすべてのシーケンスをシミュレートします。 生成された各文字列がセットに存在しない場合は、セットに追加されます。 最後に、セットのサイズが答えとして出力されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n^2) 最悪の場合 | 各文字列は、削除を繰り返すことでおよそ n 個の部分文字列を生成します。 すべての n 個の開始位置を反復すると、O(n^2) が得られます。 |
 | スペース | O(n^2) 最悪の場合 | すべての個別の文字列をセットに格納するには、最悪の場合、O(n^2) 文字が必要になる可能性があります。 |

 制約を考慮すると、最悪の場合の複雑さは許容されます。 の合計$n$すべてのテストケースにわたって$2 \cdot 10^5$したがって、個々のテスト ケースでの 2 次の動作は実現可能です。

 ## 特殊なケース

 長さ 1 の文字列の場合、`"z"`、到達可能な唯一の文字列はそれ自体です。 アルゴリズムは正しく追加します`"z"`文字が繰り返される文字列の場合、アルゴリズムは個別のシーケンスのみを正しくカウントします。 のために`"aaaaa"`、複数のパスが同じ部分文字列につながっている場合でも、セットは過剰カウントを防止し、予想どおり 5 を生成します。 すべてが一意の文字を含む文字列の場合、このメソッドは、シーケンス内の最初または 2 番目の文字を削除した結果として得られるすべての組み合わせを正しく生成し、このアプローチが連続パターンとスキップ パターンの両方を処理することを確認します。
