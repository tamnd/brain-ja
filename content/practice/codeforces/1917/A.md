 ## 解決策
 ## 問題の理解

 整数の配列が与えられ、各数値をゼロから現在の値までの任意の整数に減らすことができます。 正の数の場合、これはそれらをゼロにできることを意味します。 負の数の場合は、ゼロに向かって増加させることができます。 目標は、これらの演算を任意の数実行した後にすべての配列要素の積を最小化し、必要な最小演算数と、この最小積を達成する 1 つの有効なシーケンスを報告することです。 

配列の長さは最大 100 まで可能で、値の大きさは非常に大きくなる可能性があります。 以来$n$が小さい場合は、各要素を個別に検査して、変更するかどうかを決定する余裕があります。 ただし、この積は 64 ビット整数をすぐにオーバーフローさせる可能性があるため、計算せずに正確な値を推論する方が安全です。 重要な洞察は、ゼロを含む配列にはゼロの積、つまり最小の積が含まれるということです。 ゼロが存在しない場合、積は負の数のパリティによって決定されます。奇数の負の場合は負の積が得られ、偶数の場合は正の積が得られます。 したがって、積を最小化するには、ゼロを作成することが最優先です。 配列にすでにゼロが含まれている場合、操作は必要ありません。 そうでない場合は、任意の要素をゼロにすると最小積が得られます。 

配列に既にゼロが含まれている場合、または配列が完全に負の数で構成されている場合には、明らかではないエッジ ケースが発生します。 たとえば、配列では`[-1, -2]`、積は 2 です。負の数をゼロに減らすと、積は 0 に減り、厳密にはより小さくなります。 不注意なコードは、既存のゼロを含む配列の処理に失敗したり、すべての負の数値が負のままでなければならないと想定したりする可能性があります。 

## アプローチ

 ブルート フォース アプローチでは、配列内の各要素について考えられるすべての選択肢が考慮され、最小値を追跡しながら結果の積が計算されます。 これは原理的には正しいですが、指数関数的に遅くなります。$n = 100$各要素を 2 つのオプション (オリジナルまたはゼロ) に制限しても、$2^{100}$可能性。 

線形解のロックを解除する観察は、配列にゼロが含まれている場合、または任意の要素をゼロに削減した場合、最小積が常にゼロになるということです。 したがって、配列をスキャンしてゼロが存在するかどうかを確認し、存在しない場合は 1 つの要素をゼロに減らす単一の操作を実行するだけで済みます。 リダクションや符号の組み合わせを検査する必要はありません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取ります。 テスト ケースごとに、配列の長さを読み取ります。$n$そして配列要素。 
2. フラグを初期化して、配列内にゼロがすでに存在するかどうかを検出します。 ゼロが存在しない場合は、最初の要素のインデックスも追跡します。 
3. 配列を反復処理します。 ゼロが見つかった場合は、フラグをマークします。 そうでない場合は、削減の候補として最初の要素のインデックスを覚えておいてください。 
4. スキャン後、ゼロが見つかった場合は、最小積がすでに達成されているため、操作は必要ありません。 出力ゼロ操作。 
5. ゼロが存在しない場合は、格納されたインデックスの要素をゼロに減らす操作を 1 つ実行します。 インデックス (1 から始まる) と値 0 を指定する 1 つの演算を出力します。 

これが機能するのは、ゼロを作成すると最小積が保証されるためです。 複数のゼロによって積がさらに削減されることはなく、問題では最小限の演算数のみが要求されます。 削減する要素を選択すれば十分であるため、最初の非ゼロ要素を選択すると実装が簡素化されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    
    zero_found = False
    idx_to_zero = -1
    
    for i in range(n):
        if a[i] == 0:
            zero_found = True
            break
        if idx_to_zero == -1:
            idx_to_zero = i
    
    if zero_found:
        print(0)
    else:
        print(1)
        print(idx_to_zero + 1, 0)
```このソリューションは、次を使用して入力を効率的に読み取ります。`sys.stdin.readline`、複数のテスト ケースを処理し、操作に対して 1 から始まるインデックスを正しく出力します。 不要な操作を避けるためにゼロが存在するかどうかを注意深く追跡し、リダクション対象の最初の非ゼロ要素を選択します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | テスト ケースごとに配列を 1 回通過して、ゼロまたは候補要素を見つけます。 
| スペース | O(n) | 配列自体を保存し、余分な変数は無視できます。 

与えられた$t \le 500$そして$n \le 100$、合計作業量は最大 50,000 回の反復であり、1 秒の制限時間内に十分収まります。 

## テストケース```python

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = io.StringIO()
    sys.stdout = output
    # call solution
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        zero_found = False
        idx_to_zero = -1
        
        for i in range(n):
            if a[i] == 0:
                zero_found = True
                break
            if idx_to_zero == -1:
                idx_to_zero = i
        
        if zero_found:
            print(0)
        else:
            print(1)
            print(idx_to_zero + 1, 0)
    return output.getvalue().strip()

 ## 特殊なケース

 たとえば、正の整数を含むサイズ 1 の配列の場合、`[42]`の場合、アルゴリズムはその要素を選択してゼロに削減し、1 つの操作を生成します。 単一の要素がすでにゼロである場合、アルゴリズムはそれを正しく検出し、ゼロの演算を出力します。 すべて負の配列の場合、アルゴリズムは最初の要素をゼロに減らして積を最小化し、出力積が確実にゼロになるようにします。 ゼロを含む配列はすぐに認識され、操作は実行されません。 これにより、最小サイズの配列、ゼロを含む配列、すべてが負の配列、すべてが正の配列など、考えられるすべてのエッジ ケースがアルゴリズムで処理されることが確認されます。
