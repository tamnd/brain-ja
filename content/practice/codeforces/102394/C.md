 ## 解決策
 ## 問題の理解

 (n) 人のプレイヤーと (m) のラウンドがあります。 すべてのラウンドで、プレーヤーは 1 つの試合に参加するか、不戦勝を受け取ります。 試合には 2 試合または 3 試合が含まれており、各プレーヤーが何試合勝ったか、何試合引き分けたかが入力によって直接わかります。 

すべてのプレーヤーについて、ラウンドごとに 4 つの統計を報告する必要があります。 MP は累計マッチポイントです。 GW は、累積ゲーム ポイントを可能な最大ゲーム ポイントで割ったもので、下限は (1/3) です。 OMW は、プレーヤーが対戦したすべての対戦相手の現在の試合勝率の平均であり、繰り返された対戦を個別にカウントします。 OGW は、現在のゲームの勝率を使用して同じ方法で定義されます。 不戦勝は、プレイヤー自身の統計にポイントとゲームをもたらしますが、対戦相手を作成することはありません。 

入力により、各ラウンドの一致数が得られ、その後にそれらの一致がラウンド順に表示されます。 ラウンドの試合リストにいないプレイヤーは、自動的に不戦勝として扱われます。 

Codeforces の公式ページには、2 秒の時間制限と 512 MB のメモリ制限が記載されています。 主な構造的制約は (m\cdot16) ですが、すべてのテスト ケースにわたる (n\cdot m) の合計は最大でも (3\cdot10^5) です。 最後の条件は、すべてのプレイヤー ラウンド ペアにわたる (O(nm)) パスが簡単に入手できることを意味します。 (O(nm^2)) アルゴリズムであっても、(m) の境界は 16 であるため、実質的には (n m) の小さな定数倍です。ただし、プレーヤーのすべてのペアが関与するアルゴリズムは、(n=10,000) の場合、あまりにも高価になります。 

直接実装すると、気付かれずに問題が発生する可能性がある場所がいくつかあります。 

### エッジケース: プレイヤーは不戦勝のみを受け取る

 検討してください```
1
2 1
0
```両プレイヤーとも不戦勝となります。 それぞれ 3 MP、6 ゲーム ポイントを獲得し、2 ゲームをプレイしました。 彼らの GW は (6/(3\cdot2)=1) です。 どちらにも対戦相手がいないため、OMW と OGW は両方とも (1/3) として定義されます。 正しい出力は次のとおりです```
Round 1
3 1/3 1/1 1/3
3 1/3 1/1 1/3
```よくある間違いは、不戦勝を対戦相手として扱うこと、または不戦勝は 2-0 の試合と同等であるため、対戦相手のパーセンテージに (1) を使用することです。 プレイヤー自身の統計上のみ勝利に相当します。 

### エッジケース: (1/3) 下限により分数が変化します

 検討してください```
1
2 1
1
1 2 0 0 2
```両プレイヤーが0勝したため、試合は引き分けです。 引き分けた 2 つのゲームから、それぞれが 1 MP と 2 ゲーム ポイントを獲得します。 生の試合の割合は (1/3) ですが、生の試合の割合は (2/6=1/3) です。 したがって、どちらのパーセンテージも正確に (1/3) となり、各プレイヤーの対戦相手は同じ値を持ちます。 

正しい出力は次のとおりです```
Round 1
1 1/3 1/3 1/3
1 1/3 1/3 1/3
```より一般的には、ラウンド (r) の後、上限付き一致パーセンテージは次のように表すことができます。 

[
 \frac{\max(r,\mathrm{MP})}{3r}。 
】

 ゲームの場合、プレーヤーが (g) ゲームをプレイして (G) ゲーム ポイントを獲得した場合、上限値は次のとおりです。 

[
 \frac{\max(g,G)}{3g}。 
】

 OMW または OGW を計算するときに上限のない値を使用すると、プレーヤーにとって間違った答えが生成され、結果が悪くなります。 

### エッジケース: 同じ対戦相手が複数回出現する

 検討してください```
1
2 2
1 1
1 2 2 0 0
1 2 0 2 0
```プレイヤー 1 は最初の試合に勝ち、2 番目の試合に負けます。 プレイヤー 2 はその逆を行います。 最初のラウンドの後、プレーヤー 1 の MP は 3、プレーヤー 2 の MP は 0 になります。第 2 ラウンドの後、両方とも 2 回プレイしているため、プレーヤー 1 はまだ MP 3 を持ち、プレーヤー 2 は MP 3 を持っています。 

各プレイヤーの対戦相手リストには同じプレイヤーが 2 回含まれています。 第 2 ラウンドの OMW は、対戦相手の現在のパーセンテージを 1 回ではなく 2 回平均しなければなりません。 正しい出力は次のとおりです```
Round 1
3 1/3 1/1 1/3
0 1/1 1/3 1/1
Round 2
3 1/1 1/1 1/3
3 1/1 1/3 1/1
```一連の個別の対戦相手のみを保存するソリューションでは、繰り返される対戦が暗黙のうちに過小評価されてしまいます。 

## アプローチ

 最も直接的なブルート フォース ソリューションでは、これまでに確認されたすべての一致が保存されます。 各ラウンドの後、すべてのプレーヤーについて、以前のすべての試合をスキャンし、プレーヤーがそれに参加したかどうかを確認し、参加している場合は、その対戦相手の現在の MW と GW を追加します。 OMW と OGW の定義は過去の試合の正確な平均であるため、これは正しいです。 

問題は繰り返し作業の量です。 最悪の場合、ほぼすべてのプレイヤーがすべてのラウンドに参加するため、ラウンド (r) の後には約 (nr/2) 試合が行われます。 これらの試合をすべて (n) 人のプレイヤーに対して個別にスキャンすると、そのラウンドで約 (n^2r/2) 個のチェックがかかります。 全 16 ラウンドを合計すると、最悪のケースは次のようになります。 

136n^2。 
】

 (n=10,000) の場合、小数演算または出力をカウントする前に、約 (136) 億回の一致チェックが行われることになります。 

すべての統計はすでに行われた試合のみに依存するため、総当り攻撃が機能しますが、どの対戦相手が各プレイヤーに属しているかが繰り返し再発見されます。 重要な観察は、相手の関係が決して消えることはないということです。 プレーヤー (u) と (v) がプレイすると、(v) はその後のすべてのラウンドで (u) の対戦相手の 1 人のままになります。 プレイヤーはラウンドごとに最大 1 回プレイできるため、トーナメント全体が終了した後の各プレイヤーの対戦相手エントリーは最大 (m) 人になります。 

したがって、すべてのプレーヤーについて、プレーしたすべての試合の対戦相手を含むリストを保存できます。 ラウンドを処理した後は、これらのリストを順に見ていきます。 ラウンド (r) では、すべてのリストの長さは最大 (r) であるため、トーナメント全体で検査される対戦相手のエントリの総数は次のようになります。 

[
 O\left(n\sum_{r=1}^{m}r\right)=O(nm^2)。 
】

 (m\le16) なので、これは小さいです。 グローバル条件 (\sum nm\le3\cdot10^5) により、複数のテスト ケースにわたってさらに安全になります。 

OMW にはさらに簡略化されています。 固定ラウンド (r) では、すべてのプレイヤーの MW は分母 (3r) を持ちます。 プレイヤー (v) が MP (P_v) を持っている場合、その上限の MW は次のとおりです。 

[
 \frac{\max(r,P_v)}{3r}。 
】

 したがって、プレイヤー (d) の対戦相手エントリーの平均は単純に次のようになります。 

[
 \frac{\sum_v\max(r,P_v)}{3rd}。 
】

 OGW には共通点がありません。これは、不戦勝数や 2 試合または 3 試合の試合の数が異なるため、プレイヤーは異なる試合数をプレイした可能性があるためです。 したがって、通常の正確な分数演算を使用して相手の GW 分数を加算します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(n^2m^2)) | (O(nm)) | 遅すぎる |
 | 最適 | (O(nm^2)) | (O(nm)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各プレイヤーの累計 MP、ゲーム ポイント、およびプレイしたゲーム数の配列を作成します。 また、プレイヤーごとに対戦相手リストを作成します。 対戦相手リストには試合ごとに 1 つのエントリが保存されるため、繰り返されるミーティングは自然に複数回表示されます。 
2. ラウンドを順番に処理します。 試合ごとに、両方のプレイヤーがこのラウンドをプレイしたものとしてマークし、提供されたゲーム結果に従って MP、ゲーム ポイント、およびゲーム数を更新します。 

(w_1>w_2) の場合、プレーヤー 1 は 3 MP を取得し、プレーヤー 2 は 0 を取得します。(w_1<w_2) の場合は、その逆が起こります。 (w_1=w_2) の場合、両方とも 1 MP を受け取ります。 ゲームポイントは(3w+d)、ゲーム数は(w_1+w_2+d)です。 
3. 各プレイヤーを他のプレイヤーの対戦相手リストに追加します。 これは、2 人のプレイヤーが以前に対戦したことがあっても、試合ごとに 1 回だけ発生します。 定義は個別の対戦相手ではなく試合全体で平均されるため、繰り返しが必要です。 
4. 現在のラウンドのすべての試合が処理された後、マークされていないすべてのプレーヤーは不戦勝を受け取ります。 そのプレイヤーに 3 MP、6 ゲーム ポイント、2 ゲームを追加します。 

実際の試合後に不戦勝を処理することにより、パーセンテージが計算される前に、現在のラウンドの完全な統計が利用可能になります。 
5. すべてのプレイヤーについて、自分の累計ゲーム ポイントとゲーム数から制限付き GW を計算します。 

[
 GW_i=\frac{\max(\mathrm{ゲーム}_i,\mathrm{ゲームポイント}_i)}
 {3\mathrm{ゲーム}_i}。 
】

 分数を最大公約数で約定します。 

1. すべてのプレーヤーの現在の MW 分子を次のように計算します。

[
 M_i=\max(r,\mathrm{MP}_i)。 
】

 実際の MW は (M_i/(3r)) です。 対戦相手がいるプレーヤーの場合は、すべての対戦相手のエントリー (v) を合計 (M_v) し、(3r) と対戦相手のエントリーの数を掛けて割ります。 

1. OGW の場合、同じ対戦相手リストを調べます。 各対戦相手 (v) について、現在の上限付き GW を次のように取得します。 

[
 \frac{\max(\mathrm{ゲーム}_v,\mathrm{ゲームポイント}_v)}
 {3\mathrm{ゲーム}_v}。 
】

 これらの端数を正確に加算し、最後に対戦相手のエントリ数で割ります。 

1. プレイヤーに対戦相手がいない場合は、OMW と OGW の両方に (1/3) を出力します。 それ以外の場合は、計算された両方の分数を削減し、4 つの統計を出力します。 
2. ラウンドごとにこのプロセスを繰り返します。 すべての統計は累積されるため、対戦相手の平均を除き、生の試合結果から再計算する必要はありません。 

### なぜ効果があるのか

 ラウンド (r) の後、すべての試合とすべての不戦敗が 1 回処理されるため、配列 MP、ゲーム ポイント、およびゲームには、そのラウンドで獲得した累積値が正確に含まれます。 各プレーヤーの対戦相手リストには、そのプレーヤーがプレイしたすべての試合 (繰り返しの対戦相手や不戦勝を除く) のエントリが 1 つだけ含まれます。 

MW の計算では (\max(r,\mathrm{MP})/(3r)) が使用されます。これは、まさに必要な (1/3) 上限の一致パーセンテージです。 対戦相手リストのこれらの値を合計し、その長さで割ると、正確に OMW が得られます。 同じ議論が GW と OGW にも当てはまりますが、各対戦相手のゲームの分母はその対戦相手自身のゲーム数に依存します。 すべての算術演算は整数を使用して実行され、GCD によって約分されるため、出力される分数は正確で約分できません。 

## Python ソリューション```python
import sys
from math import gcd

input = sys.stdin.readline

def reduce_fraction(num, den):
    g = gcd(num, den)
    return num // g, den // g

def add_fraction(a, b, c, d):
    g = gcd(b, d)
    b1 = b // g
    d1 = d // g
    num = a * d1 + c * b1
    den = b1 * d
    g2 = gcd(num, den)
    return num // g2, den // g2

def main():
    T = int(input())
    out = []

    for _ in range(T):
        n, m = map(int, input().split())
        cnt = list(map(int, input().split()))

        mp = [0] * n
        game_points = [0] * n
        games = [0] * n
        opponents = [[] for _ in range(n)]

        for rnd in range(1, m + 1):
            played = [False] * n

            for _ in range(cnt[rnd - 1]):
                p1, p2, w1, w2, d = map(int, input().split())
                p1 -= 1
                p2 -= 1

                played[p1] = True
                played[p2] = True

                if w1 > w2:
                    mp[p1] += 3
                elif w1 < w2:
                    mp[p2] += 3
                else:
                    mp[p1] += 1
                    mp[p2] += 1

                game_points[p1] += 3 * w1 + d
                game_points[p2] += 3 * w2 + d

                total_games = w1 + w2 + d
                games[p1] += total_games
                games[p2] += total_games

                opponents[p1].append(p2)
                opponents[p2].append(p1)

            for i in range(n):
                if not played[i]:
                    mp[i] += 3
                    game_points[i] += 6
                    games[i] += 2

            out.append(f"Round {rnd}")

            for i in range(n):
                gw_num = max(games[i], game_points[i])
                gw_den = 3 * games[i]
                gw_num, gw_den = reduce_fraction(gw_num, gw_den)

                if not opponents[i]:
                    omw_num, omw_den = 1, 3
                    ogw_num, ogw_den = 1, 3
                else:
                    opponent_count = len(opponents[i])

                    omw_sum = 0
                    for v in opponents[i]:
                        omw_sum += max(rnd, mp[v])

                    omw_num = omw_sum
                    omw_den = 3 * rnd * opponent_count
                    omw_num, omw_den = reduce_fraction(
                        omw_num, omw_den
                    )

                    ogw_num, ogw_den = 0, 1
                    for v in opponents[i]:
                        v_num = max(games[v], game_points[v])
                        v_den = 3 * games[v]
                        ogw_num, ogw_den = add_fraction(
                            ogw_num, ogw_den, v_num, v_den
                        )

                    ogw_den *= opponent_count
                    ogw_num, ogw_den = reduce_fraction(
                        ogw_num, ogw_den
                    )

                out.append(
                    f"{mp[i]} "
                    f"{omw_num}/{omw_den} "
                    f"{gw_num}/{gw_den} "
                    f"{ogw_num}/{ogw_den}"
                )

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    main()
```3 つの累積配列は、すべてのプレーヤー自身のパーセンテージを再構築するのに十分です。 MP は試合の勝者または引き分けから更新されますが、ゲーム ポイントとゲーム カウントは指定されたゲーム カウントを直接使用します。 バイは、指定された 2-0 バイトの結果とまったく同じ累積増分によって表されます。 

の`opponents`リストは中心的なデータ構造です。 プレイヤー 1 と 2 が 3 回対戦した場合、プレイヤー 1 のリストには次のものが含まれます。`[2, 2, 2]`。 トーナメント定義ではすべてのミーティングがカウントされるため、重複排除は実行されません。 

更新の順序は重要です。 OMW と OGW はラウンド後に対戦相手の現在の統計を使用するため、パーセンテージを計算する前にラウンド全体を処理する必要があります。 コードは最初にすべての一致を処理し、次にすべての by を割り当ててから、出力を計算します。 

OMW の計算では、分数の加算が完全に回避されます。 丸め (r) では、すべての MW には分母 (3r) があるため、分子は整数のみになります。`max(r, mp[v])`蓄積する必要がある。 OGW では、2 人の対戦相手のゲーム数が異なる可能性があるため、実数の加算が必要です。 

Python の整数は任意の精度であるため、オーバーフローの問題はありません。 プレイヤーは 1 試合につき最大 16 ラウンドと最大 3 試合をプレイし、不戦勝が 2 試合に寄与するため、最大の分母はいずれにしても小さいです。 

の`add_fraction`関数は追加するたびに減少します。 これにより、中間の整数が小さく保たれ、すべての対戦相手にわたって大きな共通分母を構築することが回避されます。 

## 実用的な例

 ### サンプル 1

 最初のテスト ケースには 2 人のプレーヤーと 3 ラウンドがあります。 ラウンド 1 には試合が含まれていないため、両方のプレイヤーは不戦勝となります。 ラウンド 2 には 2-0-1 の試合が含まれ、ラウンド 3 には 1-1-1 の試合が含まれます。 

| ラウンド | プレーヤー | 国会議員 | ゲームポイント | ゲーム | 反対派 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 1 | 3 | 6 | 2 | [] |
 | 1 | 2 | 3 | 6 | 2 | [] |
 | 2 | 1 | 6 | 13 | 5 | [2] |
 | 2 | 2 | 3 | 7 | 5 | [1] |
 | 3 | 1 | 7 | 17 | 8 | [2] |
 | 3 | 2 | 4 | 11 | 8 | [1] |

 ラウンド 2 の後、プレイヤー 1 は MW (6/6=1) を持ち、プレイヤー 2 は MW (3/6=1/2) を持ちます。 それらの GW 値は (13/15) と (7/15) です。 彼らはそれぞれ 1 人の対戦相手とだけ対戦しているため、それらの値は相手の OMW と OGW になります。 

ラウンド 3 の後、同じ対戦相手リストがまだ存在しますが、現在の統計は変更されています。 プレイヤー 2 は現在 GW (11/24) を持っているため、それがプレイヤー 1 の OGW になります。 プレイヤー 1 は GW (17/24) を持っているため、プレイヤー 2 の OGW になります。 

このトレースは、対戦相手のパーセンテージを、試合が行われたラウンドの統計ではなく、現在の統計を使用して計算する必要がある理由を示しています。 

### サンプル 2

 2 番目のテスト ケースには 3 人のプレイヤーがいます。 ラウンド 1 では、プレーヤー 1 と 2 がプレーし、プレーヤー 3 は不戦勝となります。 ラウンド 2 では、プレーヤー 2 がプレーヤー 3 と対戦し、プレーヤー 1 は不戦勝となります。 

| ラウンド | プレーヤー | 国会議員 | ゲームポイント | ゲーム | 反対派 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 1 | 0 | 0 | 2 | [2] |
 | 1 | 2 | 3 | 6 | 2 | [1] |
 | 1 | 3 | 3 | 6 | 2 | [] |
 | 2 | 1 | 3 | 6 | 4 | [2] |
 | 2 | 2 | 6 | 12 | 4 | [1、3] |
 | 2 | 3 | 3 | 6 | 4 | [2] |

 ラウンド 1 の後、プレイヤー 1 の生の MW はゼロであるため、(1/3) に制限されます。 プレイヤー 2 の MW は 1 であるため、プレイヤー 1 は OMW (1) を持ち、プレイヤー 2 は OMW (1/3) を持ちます。

このトレースは、不戦勝と、プレーヤーの対戦相手リストに現在の統計が異なるさまざまなプレーヤーが含まれる可能性があるという事実の両方を示します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(nm^2)) | ラウンド (r) の後、各プレーヤーには最大で (r) 人の対戦相手のエントリーがあるため、すべての対戦相手のリストには (O(nr)) 個のエントリーが含まれます。 すべてのラウンドを合計すると、(O(nm^2)) が得られます。 |
 | スペース | (O(nm)) | 累積統計では (O(n)) 個のメモリが使用され、すべての対戦相手リストには合計で最大 (nm) 個のエントリが含まれます。 |

 (m\le16) であるため、(m^2) 係数は最大 256 です。さらに重要なのは、入力により、すべてのケースにわたる (n m) の合計が (3\cdot10^5) のみであることが保証されます。 結果として得られる対戦相手リストの反復回数は意図した範囲内に収まりますが、メモリ使用量はトーナメントの合計サイズ内で線形のままです。

import io
import sys
from math import gcd

def solve(data: str) -> str:
    inp = io.StringIO(data)

    def rd():
        return inp.readline()

    t = int(rd())
    out = []

    def reduce_fraction(a, b):
        g = gcd(a, b)
        return a // g, b // g

    def add_fraction(a, b, c, d):
        g = gcd(b, d)
        b1 = b // g
        d1 = d // g
        a = a * d1 + c * b1
        b = b1 * d
        g = gcd(a, b)
        return a // g, b // g

    for _ in range(t):
        n, m = map(int, rd().split())
        counts = list(map(int, rd().split()))

        mp = [0] * n
        gp = [0] * n
        games = [0] * n
        opp = [[] for _ in range(n)]

        for r in range(1, m + 1):
            played = [False] * n

            for _ in range(counts[r - 1]):
                p1, p2, w1, w2, d = map(int, rd().split())
                p1 -= 1
                p2 -= 1

                played[p1] = True
                played[p2] = True

                if w1 > w2:
                    mp[p1] += 3
                elif w2 > w1:
                    mp[p2] += 3
                else:
                    mp[p1] += 1
                    mp[p2] += 1

                gp[p1] += 3 * w1 + d
                gp[p2] += 3 * w2 + d

                g = w1 + w2 + d
                games[p1] += g
                games[p2] += g

                opp[p1].append(p2)
                opp[p2].append(p1)

            for i in range(n):
                if not played[i]:
                    mp[i] += 3
                    gp[i] += 6
                    games[i] += 2

            out.append(f"Round {r}")

            for i in range(n):
                gw_num, gw_den = reduce_fraction(
                    max(games[i], gp[i]),
                    3 * games[i]
                )

                if not opp[i]:
                    omw_num, omw_den = 1, 3
                    ogw_num, ogw_den = 1, 3
                else:
                    d = len(opp[i])

                    omw_num = sum(max(r, mp[v]) for v in opp[i])
                    omw_den = 3 * r * d
                    omw_num, omw_den = reduce_fraction(
                        omw_num, omw_den
                    )

                    ogw_num, ogw_den = 0, 1
                    for v in opp[i]:
                        x = max(games[v], gp[v])
                        y = 3 * games[v]
                        ogw_num, ogw_den = add_fraction(
                            ogw_num, ogw_den, x, y
                        )

                    ogw_den *= d
                    ogw_num, ogw_den = reduce_fraction(
                        ogw_num, ogw_den
                    )

                out.append(
                    f"{mp[i]} {omw_num}/{omw_den} "
                    f"{gw_num}/{gw_den} {ogw_num}/{ogw_den}"
                )

    return "\n".join(out)

def run(inp: str) -> str:
    return solve(inp)

 ## 特殊なケース

 不戦勝のみを受け取ったプレイヤーは、`played`配列。 ラウンド内のすべての実際の試合が処理された後、フラグがまだ false であるすべてのプレーヤーは、ちょうど 3 MP、6 ゲーム ポイント、および 2 ゲームを受け取ります。 対戦相手リストは空のままであるため、出力では OMW と OGW の両方に明示的に (1/3) が使用されます。 入力用```
1
2 1
0
```最初のプレイヤーが MP 3 と GW (6/6=1) に達すると、`3 1/3 1/1 1/3`、2番目のプレイヤーも同じ結果になります。 

(1/3) キャップは、`max(r, mp[i])`MWの場合と`max(games[i], gp[i])`GWに向けて。 プレイヤーがすべての試合に負けたとします。 ラウンド 3 の後、MP はゼロになる可能性がありますが、MW 分子はそのままです。`max(3, 0) = 3`、(3/9=1/3) を与えます。 同じ構造が GW にも機能し、ゲーム ポイントがゼロのプレイヤーでもゲーム数に等しい上限付きの分子を受け取ります。 

繰り返しの対戦相手は、すべての試合に対戦相手を追加することで保持されます。 対戦相手リストがこうなったら`[2, 2]`、OMW ループはプレーヤー 2 を 2 回処理します。 第 2 ラウンドの後、両方のエントリはプレーヤー 2 の現在のラウンド 2 MW を使用し、定義と正確に一致します。 アルゴリズムのどこにも設定または重複排除の操作は現れません。 

パーセンテージを計算するタイミングも重要です。 プレーヤー 1 と 2 がラウンド 1 で対戦し、プレーヤー 2 がラウンド 2 で他の誰かと対戦するとします。ラウンド 2 後にプレーヤー 1 の OMW を計算する場合、プレーヤー 2 のラウンド 2 の結果がすでに含まれている必要があります。 この実装では、出力を計算する前にラウンド 2 のすべての試合とラウンド 2 の不戦勝がすべて処理されるため、すべての対戦相手の統計は完了した同じラウンドから取得されます。 

最後に、ゲームのパーセンテージではラウンド数を分母として使用できません。 不戦勝は 2 ゲームに貢献し、通常の試合には 2 または 3 ゲームが含まれる可能性があるため、プレイヤーが異なればゲーム数も異なる可能性があります。 コードは維持します`games[i]`明示的に、(3\cdot\mathrm{games}[i]) を可能な最大ゲーム ポイントとして使用します。 これは、OGW がゲーム ポイントとゲーム カウントを組み合わせるのではなく、対戦相手の個々の GW 部分を加算することによって計算される理由でもあります。
