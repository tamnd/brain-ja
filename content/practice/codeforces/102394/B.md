 ## 解決策
 ## 問題の理解

 (0) から (2^m-1) までのすべての整数は、必要に応じて先頭のゼロを埋め込んで、(m) ビットのバイナリ文字列として見ることができます。 関数 (F_{m-1}(a,b)) は、最初の不一致の前に最上位側から連続して何ビットが等しいかをカウントします。 言い換えれば、これは 2 つの (m) ビット文字列の中で最も長い共通プレフィックス長 (LCP) です。 

間隔は、範囲全体 (0) から (2^m-1) の 1 つの連続したパーティションを形成します。 すべての間隔 ([L_i,R_i]) について、その間隔から 1 つの代表 (A_i) を選択します。 LCP の意味では、代表は、選択された他のすべての代表と少なくとも同じように、その区間内のすべての数値 (k) に類似していなければなりません。 

すべての代表者が選ばれた後、その選択の価値が彼らの成果となります。 すべての有効な選択に対するこれらの積の合計 (100000007) を法とする必要があります。 

制約は、有用な構造がどこから来なければならないかを正確に示します。 1 つのテスト ケースで使用できる整数は最大で (2^{17}=131072) 個であり、すべてのテスト ケースの (2^m) の合計は最大で (2^{18}) になります。 したがって、(2^m) において線形に近いアルゴリズムが望ましいです。 (O(2^{2m})) メソッドは直ちに不可能ですが、(O(2^m m^2)) メソッドは (m\le17) であるため合理的です。 

不注意な実装を簡単に壊す可能性のあるエッジケースがいくつかあります。 (m=0) の場合、取り得る整数は (0) のみであるため、答えは (0) になります。 例えば、```
1
0 1
0 0
```出力があります```
0
```常に少なくとも 1 つのビットが存在すると仮定するソリューションでは、無効なビット位置にアクセスしたり、DP を誤って初期化したりする可能性があります。 

間隔が 1 つしかない場合、他の代表者との比較はまったく行われません。 間隔内のすべての値は有効です。 例えば、```
1
2 1
0 3
```答えがあります (0+1+2+3=6)。 隣接間隔条件を不必要に課すソリューションは、候補を誤って削除する可能性があります。 

境界線のつながりも重要です。 考慮する```
1
2 2
0 1
2 3
```考えられる選択肢は 4 つあります。 4 つすべてが条件を満たしており、その積は (0\cdot2)、(0\cdot3)、(1\cdot2)、および (1\cdot3) となり、答えは (5) になります。 等しい LCP 値が許可されるため、不等式は非厳密である必要があります。 

最後に、係数は (1000000007) ではなく (100000007) です。 例えば、```
1
17 1
0 131071
```は無制限の合計 (8589869056) を持ち、その必要な剰余は (89868461) です。 より一般的な (10^9+7) 法を使用すると、間違った答えが自動的に生成されます。

すべての間隔に 2 つの数値が含まれており、(65536) 個の間隔がある場合 (m=17) の場合に可能ですが、選択肢を列挙するだけですでに次のようになります。

有益な観察は、(F) を LCP として解釈することから得られます。 (a<b<c) と仮定します。 数値順にソートされたバイナリ文字列の場合、2 つの外側の値間の共通の接頭辞は、隣接する値の共通の接頭辞によって制御されます。 特に、別の値がさらに右に移動すると、固定値の LCP は、新たに優れた競合他社を生み出すほど大きくなることができません。

 ## アルゴリズムのチュートリアル

 1. すべての数値を (m) ビットのバイナリ文字列として扱い、(F_{m-1}(a,b)) を (\operatorname{LCP}(a,b)) として解釈します。 2 つの整数の場合、LCP はそれらの XOR から計算できます。 (x=a\oplus b) がゼロ以外の場合、(x) の最も高い設定ビットが最初の異なるビットとなるため、LCP は (m-\operatorname{bit_length}(x)) になります。 (x=0) の場合、LCP は (m) です。 
2. ローカルネイバープロパティを使用して、有効性条件を緩和します。 間隔 (i) の場合、前の間隔に関係する唯一の制約は次のとおりです。 

[
 \オペレータ名{LCP}(A_i,L_i)
 \ge
 \オペレータ名{LCP}(A_{i-1},L_i),
 】

 一方、次の間隔に関係する唯一の制約は

[
 \オペレーター名{LCP}(A_i,R_i)
 \ge
 \オペレーター名{LCP}(A_{i+1},R_i)。 
】

 より遠い間隔ごとに、順序付き整数直線に沿った LCP の単調性によって自動的に処理されます。 
3. 間隔 (i) の処理後、次のインデックスが付いた状態を保存します。 

[
 (c,b)=
 \左(
 \演算子名{LCP}(A_i,L_{i+1}),
 \オペレーター名{LCP}(A_i,R_i)
 \右）。 
】

 その状態に保存される値は、その状態で終わるすべての有効な選択肢の積の合計です。 最初の座標は、次の間隔で (L_{i+1}) との比較として使用されるもので、2 番目の座標は次の間隔で (R_i) との比較として使用されるものです。 
4. 間隔を処理する前に、以前の状態テーブルを累積テーブルに変換します。 定義する

 \sum_{\substack{c\le x\b\ge y}} g[c][b]。 
】

 これはまさに、エンドポイント値 (x) および (y) を持つ現在の候補と互換性のある以前の代表のセットです。 変換は最初の座標の接頭辞の合計と 2 番目の座標の接尾辞の合計であるため、(O(m^2)) がかかります。 
5. すべての最初の代表が許可されるように累積テーブルを初期化します。 概念的には、これは単一の仮想状態を ((0,m)) に配置し、同じ累積変換を適用することと同じです。 以前の間隔がないため、考えられるすべての最初の候補が受け入れられる必要があります。 
6. 区間 (i) 内のすべての候補 (x) について、次の計算を行います。 

[
 A=\オペレーター名{LCP}(x,L_i),
 】

 [
 B=\オペレータ名{LCP}(x,R_i),
 】

 [
 C=\オペレータ名{LCP}(x,L_{i+1})
 】

 (i<N) の場合、それ以外の場合 (C=0)、および

 [
 D=\オペレーター名{LCP}(x,R_{i-1})
 】

 (i>1) の場合、そうでない場合 (D=0)。 

累積 DP 値 (f[A][D]) には、前の間隔からの互換性のある選択肢が正確に含まれます。 
7. 完全なシーケンスの値は選択されたすべての代表の積であるため、以前の寄与に現在の代表 (x) を掛けます。 結果を状態 ((C,B)) に追加します。 

[
 g[C][B]
 \マスレル{+}=
 f[A][D]\cdot x。 
】

 すべての算術は (100000007) を法として実行されます。 
8. 新しく構築された (g) テーブルに 2 次元の累積変換を適用します。 結果のテーブルは、次の間隔では (f) になります。 
9. 最後の間隔の後には次の間隔はないため、すべての最終状態は有効です。 したがって、答えは (f[m][0]) になります。これには、最初の座標が最大 (m) で、2 番目の座標が少なくとも (0) であるため、すべての状態が含まれます。 

機能する理由: 間隔 (i) の処理後、各 DP 状態は (i) までのすべての有効な選択を正確に表し、次の間隔で観察できる 2 つの LCP 値によって分類されます。 区間 (i+1) の候補を考慮すると、前の代表に対する不等式は正確に (c\le A) および (B\ge D) となり、累積テーブルはそれらの状態を正確に合計します。 したがって、すべての有効なシーケンスが 1 回転送され、すべての無効な遷移が除外され、現在の候補との乗算によって積の値が維持されます。 ローカル隣接補題は、これらの遷移を満たすことが、すべての代表に対する元の比較を満たすことと同等であることを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 100000007

def lcp(a, b, m):
    x = a ^ b
    if x == 0:
        return m
    return m - x.bit_length()

def cumulative(g, s):
    """Return f[x][y] = sum(g[c][b]) for c <= x and b >= y."""
    f = [row[:] for row in g]

    # Suffix sum in the second coordinate.
    for row in f:
        for k in range(s - 2, -1, -1):
            v = row[k] + row[k + 1]
            if v >= MOD:
                v -= MOD
            row[k] = v

    # Prefix sum in the first coordinate.
    for j in range(1, s):
        row = f[j]
        prev = f[j - 1]
        for k in range(s):
            v = row[k] + prev[k]
            if v >= MOD:
                v -= MOD
            row[k] = v

    return f

def solve():
    T = int(input())
    out = []

    for _ in range(T):
        m, n = map(int, input().split())
        intervals = [tuple(map(int, input().split()))
                     for _ in range(n)]

        s = m + 1

        # Initially every state is reachable for the first interval.
        f = [[1] * s for _ in range(s)]

        # Reuse g between intervals. Only touched entries need clearing.
        g = [[0] * s for _ in range(s)]

        for i, (left, right) in enumerate(intervals):
            touched = []

            next_left = intervals[i + 1][0] if i + 1 < n else 0
            prev_right = intervals[i - 1][1] if i > 0 else 0

            for x in range(left, right + 1):
                a = lcp(x, left, m)
                b = lcp(x, right, m)
                c = lcp(x, next_left, m) if i + 1 < n else 0
                d = lcp(x, prev_right, m) if i > 0 else 0

                value = f[a][d] * x % MOD

                if g[c][b] == 0:
                    touched.append((c, b))

                g[c][b] += value
                if g[c][b] >= MOD:
                    g[c][b] -= MOD

            f = cumulative(g, s)

            for x, y in touched:
                g[x][y] = 0

        out.append(str(f[m][0]))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```の`lcp`関数は XOR 表現を直接使用します。 2 つの数値が異なる場合、バイナリ文字列が最上位側から書き込まれたとき、それらの XOR の最も高い設定ビットが正確に最初の異なるビットになります。 パイソンの`bit_length()`定数時間でその位置が得られるため、各 LCP クエリにはすべて (m) ビットをスキャンするのではなく (O(1)) のコストがかかります。 

LCP はその範囲内の任意の値を持つことができるため、DP テーブルには (0) から (m) までのインデックスがあります。 初期テーブルは、仮想状態 ((0,m)) を明示的に構築して変換するのではなく、1 で埋められます。 これらは同等です。仮想状態はすべての四角形 (c\le A)、(B\ge D) に寄与するため、すべての初期クエリの値は 1 になります。 

候補者ごとに、`f[a][d]`は、2 つの隣接する制約によって必要とされる正確な長方形の合計です。 の乗算`x`DP には単に選択の数ではなく積の合計が格納されるため、候補を次の状態に追加する前に実行する必要があります。 

の`cumulative`関数は、最初に 2 番目の座標に沿って接尾辞の合計を実行し、次に最初の座標に沿って接頭辞の合計を実行します。 この 2 つのパスの後、

 [
 f[a][d]=\sum_{c\le a,\ b\ge d}g[c][b]。 
】

 最初のパスでは (b\ge d) 条件が確立され、2 番目のパスでは (c\le a) が確立されるため、順序が重要になります。 

実装では、`g`テーブルを参照し、現在の間隔で実際に操作された状態のみをクリアします。 これにより、間隔ごとに別の (O(m^2)) コレクションの構築と初期化を繰り返すことがなくなり、シングルトン間隔が多数ある場合に便利です。 

Python の整数はオーバーフローしませんが、すべての DP 値は剰余 (100000007) として減算されます。 すべての加算はすでに係数以下の 2 つの値を結合するため、次の値を使用する代わりに 1 回の減算で十分です。`%`内部の累積和ループ内で。

 ## 特殊なケース

 (m=0) の場合、取り得る整数は 1 つだけ (0) であり、そのバイナリ表現のビットは 0 です。 の`lcp`関数は受信します`a=b=0`、 (m=0) を返し、唯一の候補が係数 0 に寄与します。 したがって、DP は負のビット位置にアクセスすることなく (0) を返します。 

単一の間隔では、前または次の代表者は存在しません。 初期の DP テーブルでは、すべての候補に 1 の寄与が与えられますが、欠落している近傍座標はダミー値としてのみ 0 に設定されます。 すべての候補が処理されるため、([0,3]) の場合、4 つの寄与は (0,1,2,3) となり、(6) になります。 

間隔の境界では、等価性が許可されたままでなければなりません。 たとえば、サンプルでは、​​(A_1=1) と (A_2=3) を選択すると、いくつかの境界比較で等しい LCP が得られ、シーケンスは依然として有効です。 DP が使用するのは、`c <= A`そして`b >= D`、厳密な不平等は決してないので、絆は存続します。 

間隔のエンドポイントは包括的です。 間隔は完全なパーティションを形成するため、DP によって処理される候補の総数は正確に

 [
 \sum_i(R_i-L_i+1)=2^m。 
】

 これが、から反復する理由です`left`を通して`right`包括的であることが必要かつ十分です。 

候補がゼロの場合も当然扱います。 その遷移の寄与にはゼロが乗算されるため、その代表を含むすべての完全なシーケンスは、要求された積和にゼロを寄与します。 このような状態には特別な治療は必要ありません。
