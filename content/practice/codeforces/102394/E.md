 ## 解決策
 ## 問題の理解

 まず、非常に豊富な種類のギフトから始めます。 位置 (i) には、最初は (g_i) が含まれています。 出場者間でギフトを任意に交換できるため、最終的な配列は、元のギフト タイプのマルチセットを任意に並べ替えることができます。 

競技者は、交換後に自分の立場に置かれた価値が、元々持っていた価値と異なる場合に満足します。 課題は、そのようなポジションの数を最大化することです。 

問題は、最終的な配列 (g=s_n) が明示的に指定されていないことです。 シーケンスは、最大 (10^6) の値を使用して直接書き込むことも、以前に定義した 2 つのシーケンスを連結することによって形成することもできます。 シーケンスは何度も再利用される可能性があるため、実際の長さは (10^{18}) に達することがあります。 入力自体は、それが記述するシーケンスよりもはるかに小さいです。 

最初の単純化は、配列の順序を無視することです。 最も頻繁に使用されるギフト タイプが (M) 回発生し、配列全体の長さが (L) であると仮定します。 (M\le L/2) の場合、すべてのポジションが異なる種類を受け取るようにギフトを手配し、(L) の参加者に幸せを与えることができます。 (M>L/2) の場合、元々その支配的なタイプを保持しているポジションは (M) 個ありますが、そこに移動できるのは他のタイプの (L-M) 個のギフトだけです。 これらの位置の少なくとも (M-(L-M)=2M-L) は同じタイプを維持する必要があります。 他のすべての位置は異なるものにすることができます。 したがって、答えは次のとおりです

 [
 \min(L,2(L-M))。 
】

 同様に、

 [
 \text{答え}=
 \begin{ケース}
 L,&2M\le L,\
 2(L-M)、&2M>L。 
\end{ケース}
 】

 したがって、問題全体は、(s_n) の 2 つの量、つまり長さ (L) と、ギフトの種類の最大頻度 (M) を見つけることに帰着します。 

この制約により、(s_n) の拡張は不可能になります。 シーケンス定義の数は最大 (10^6) であり、すべてのテスト ケースにわたって明示的にリストされた値の合計数も最大 (10^6) ですが、生成されたシーケンスの長さは (10^{18}) にすることができます。 拡張された配列の線形スキャンでも、(10^{18}) 演算が必要になる場合があります。 (10^6) 個の入力オブジェクトでさえ (10^{12}) 個の演算がすでに実行不可能になっているため、2 次アプローチはかなり早い段階で除外されます。 目的のアルゴリズムは圧縮された記述を処理し、入力サイズに比例した時間を費やす必要があります。 

直接実装が通知なく失敗する可能性があるエッジケースがいくつかあります。 

単一の要素について、競技者は別のギフトを受け取ることはできません。 例えば、```
1
1
1 1 7
```答えは(0)です。 他に移動できる十分な贈り物が常にあると仮定する公式は、出場者が幸せになれると誤って主張することになります。 

すべての贈り物が同一であるというのは、もう一つの極端な例です。 のために```
1
1
1 4 5 5 5 5
```答えは (0) です。 すべての順列は元の配列と同一です。 重要な量は最大頻度であるため、配列に複数の個別の値が含まれているかどうかを確認するだけのソリューションでは十分ではありません。 

正確な半分の周波数の境界も重要です。 のために```
1
1
1 4 1 1 2 2
```各値は 2 回出現するため、すべての位置が他の値を受け取ることができ、答えは (4) になります。 (L/2) との厳密な比較を間違った方向で使用すると、一部の競技者が誤って不満を抱く可能性があります。 

最後に、繰り返されるシーケンス参照は、その多重度でカウントする必要があります。 考慮する```
1
3
1 1 1
2 1 1
2 2 2
```入力に明示的に出現するのは 1 つだけであるにもかかわらず、最終シーケンスには (1) のコピーが 4 つあります。 その答えは (0) です。 最終シーケンスによって参照される回数を記録せずに、各シーケンス定義を 1 回だけ処理する実装では、この問題が発生します。 

## アプローチ

 ブルートフォースアプローチは簡単です。 まず、完全な配列 (g) が使用可能になるまで、すべての連結を展開します。 次に、すべての種類のギフトの出現数を数え、最大頻度 (M) を見つけ、上記の式を使用して幸せな参加者の最大数を計算します。 

これは正しいです。ギフトの交換によって複数の価値観が変わることは決してないからです。 すべての値の頻度がわかれば、配列の元の構造はもはや重要ではなくなります。 

問題は、展開された配列のサイズです。 のようなチェーン```
1 1 7
2 1 1
2 2 2
2 3 3
...
```ステップごとに長さを2倍にすることができます。 わずか 60 回の連結の後、長さはすでに (2^{60}) になる可能性があり、これは (10^{18}) より大きくなります。 このような配列を展開するには、入力に数十行しか含まれていないとしても、約 (10^{18}) 個の要素操作が必要になります。 

重要な観察は、連結は周波数を追加するだけであるということです。 シーケンス (s_i) が最終シーケンス内で 1 回使用される場合、(s_i) のすべての要素が 1 回寄与します。 3 回使用すると、(s_i) のすべての要素が 3 回寄与します。 

これにより、シーケンス定義を有向非巡回グラフとして有用に解釈できます。 タイプ 2 シーケンス (s_i=s_x+s_y) には、(s_x) と (s_y) へのエッジがあります。 (s_n) から開始して、多重度を逆方向に伝播できます。 (w_i) を、展開された (s_n) 内でシーケンス全体 (s_i) が出現する回数とします。 最初は (w_n=1)。 (s_i=s_x+s_y) の場合、(s_i) が出現するたびに (s_x) と (s_y) の両方が 1 つ出現します。 

[
 w_x\mathrel{+}=w_i,\qquad
 w_y\マスレル{+}=w_i。 
】

 参照される各シーケンスのインデックスは小さいため、(n) から (1) までのインデックスを処理するだけで十分です。 

値 (q_1,\ldots,q_k) を含む直接指定されたシーケンスに到達すると、それらの明示的な値はすべて、最終シーケンスに (w_i) 回出現します。 各値のグローバル頻度に (w_i) を追加できます。 全長は(w_i\cdot k)と同時に累積することができます。 

これにより、最大 (10^{18}) 個の要素を走査するという不可能なタスクが、明示的に指定された要素とシーケンス定義のみの走査に変わります。 これは、参照溶液で使用されるものと同じ逆マーキング原理です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(L+n)), (L\le 10^{18}) | (O(L)) | 遅すぎる |
 | 最適 | (O(n+\sum k)) が期待されます | (O(n+\sum k)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのシーケンス定義を読み取ります。 直接指定したシーケンスの場合は、その値を保存します。 連結の場合は、2 つの参照シーケンス インデックスを保存します。 実際のシーケンスは天文学的に大きい可能性があるため、定義を保持します。 
2. 多重度の配列 (w) を作成し、(w_n=1) に設定します。 これは、最終シーケンスには現在 (s_n) のコピーが 1 つ含まれていることを意味します。 
3. シーケンス インデックスを (n) から (1) まで処理します。 (w_i=0) の場合、シーケンス (s_i) は最終的な答えに寄与しないため、スキップできます。 
4. (s_i) が連結 (s_x+s_y) の場合、(w_x) と (w_y) の両方に (w_i) を追加します。 (s_i) の各出現には、各子シーケンスの出現が 1 つだけ含まれます。 
5. (s_i) が (k) 個の値を持つ明示的にリストされたシーケンスである場合、リストされたすべての値の頻度に (w_i) を追加します。 また全長に(w_i k)を加算します。 シーケンスは多重度がすでに決定されている場合にのみ処理されるため、すべての明示的な出現は、(s_n) に出現する正確な回数でカウントされます。 
6. 値を累積しながら、最大のグローバル周波数 (M) を追跡します。 最終的な配列を再構築する必要はありません。 
7. 関連するすべての葉が処理された後、(L) を全長とします。 (2M\le L) の場合は、(L) と答えてください。 それ以外の場合は (2(L-M)) と答えてください。 最初のケースは、すべての位置が異なるタイプを受け取ることができることを意味します。 2 番目のケースでは、ドミナント値のコピーが多すぎるため、正確に (2M-L) の位置でそれを保持する必要があります。 

### なぜ効果があるのか

 不変条件は、シーケンス (s_i) を処理する直前に、(w_i) が完全に展開された最終シーケンス (s_n) で発生する回数 (s_i) に等しいということです。 (s_n) が 1 回出現するため、最初は true になります。 連結 (s_i=s_x+s_y) の場合、(s_i) が出現するたびに各子の 1 つの出現が寄与するため、両方の子に (w_i) を追加すると不変式が保持されます。 したがって、リーフでは、明示的にリストされたすべての値に (w_i) を乗算すると、最終シーケンスでの実際の出現数が正確に得られます。

すべての葉が処理された後、(L) とすべてのギフト頻度は正確になります。 変化しない位置の最小数は、最大周波数が配列の最大半分である場合は (0) ですが、それ以外の場合は (2M-L) になります。これは、(M) 個の優勢な位置を占める非優勢なギフトが (L-M) 個だけ存在するためです。 したがって、計算された答えは最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    out = []

    for _ in range(T):
        n = int(input())

        kind = bytearray(n + 1)
        left = [0] * (n + 1)
        right = [0] * (n + 1)
        leaves = [None] * (n + 1)

        for i in range(1, n + 1):
            parts = list(map(int, input().split()))

            if parts[0] == 1:
                kind[i] = 1
                k = parts[1]
                leaves[i] = parts[2:]
            else:
                left[i] = parts[1]
                right[i] = parts[2]

        # ways[i] = number of times sequence i occurs in s_n.
        ways = [0] * (n + 1)
        ways[n] = 1

        freq = {}
        total = 0
        maximum = 0

        for i in range(n, 0, -1):
            w = ways[i]
            if w == 0:
                continue

            if kind[i] == 1:
                values = leaves[i]
                total += w * len(values)

                for v in values:
                    nv = freq.get(v, 0) + w
                    freq[v] = nv
                    if nv > maximum:
                        maximum = nv

                # Release the large list as soon as it is no longer needed.
                leaves[i] = None
            else:
                x = left[i]
                y = right[i]
                ways[x] += w
                ways[y] += w

        if maximum * 2 <= total:
            answer = total
        else:
            answer = 2 * (total - maximum)

        out.append(str(answer))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```の`kind`、`left`、 そして`right`配列には圧縮された DAG が格納されます。`leaves[i]`は直接指定されたシーケンスに対してのみ設定されるため、生成されたシーケンスは決して実体化されません。 

の`ways`配列は、最終シーケンスからの逆伝播を実装します。 すべての連結は以前のシーケンスのみを参照するため、(n) から (1) までの順序は有効です。 したがって、子は、アルゴリズムがその子に到達する前に、その貢献をすべて受け取ります。 

辞書`freq`実際の各ギフト タイプの頻度を保存します。 ギフト値は (10^9) まで大きくなり、直接インデックス付けには適さないため、辞書が必要になります。 周波数自体は (10^{18}) まで大きくなる可能性があるため、ここでは Python 整数が役に立ちます。 C++ では、これらの量には 64 ビット整数が必要です。 公式の制約では、最大 (10^{18}) までのシーケンス長が明示的に許可されています。 

表現`maximum * 2 <= total`正確な半分の境界を正しく処理します。 最大周波数が全体のちょうど半分の場合でも、すべての位置を変更できます。 

リーフのリストは処理後に解放されます。 これにより、漸近的なメモリ使用量は変わりませんが、逆方向トラバーサル中のピーク メモリ負荷が軽減されます。
