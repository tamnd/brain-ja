 ## 問題の理解

 テストケースごとに、整数を分割する必要があります。`n`2 つの正の整数に変換`x`そして`y`そのような`x`プライムです、`y`複合的であり、`x + y = n`。 2 つの数値はどちらも厳密に次より小さい必要があります。`n`。 そのような分割が存在しない場合は、次のように出力します。`-1`。 

まであります`10^5`テストケースは、それぞれ`n`と同じ大きさにすることができます`10^9`。 これにより、次の値に比例して作業を実行するアルゴリズムが除外されます。`n`あらゆるテストケースに対して。 可能なすべての値にわたる線形スキャンでも、`x`最大約`10^14`入力全体にわたる反復。 候補を検索するのではなく、必要な素数と合成数の数学的特性を利用する必要があります。 

有用な最小の合成数は次のとおりです。`4`。 のパリティ`n`より単純な構造が得られます。 もし`n`が均一で十分に大きい場合、`x = 2`作る`y = n - 2`、これも偶数です。 以下のすべての偶数`2`複合なので、いつでもすぐに機能します`n - 2 >= 4`、 意味`n >= 6`。 

もし`n`奇数で十分に大きいので、選択します`x = 3`作る`y = n - 3`、これは偶数です。 奇数の場合`n >= 7`、 我々は持っています`y >= 4`、 それで`y`複合です。 したがって、あらゆる奇数`n >= 7`即時施工もございます。 

小さな値`1`を通して`5`別途扱う必要があります。 のために`n = 1, 2, 3`、プライムとコンポジットを入れるのに十分なスペースがありません。 のために`n = 4`、素数を使用して可能な唯一の分割は次のとおりです。`2 + 2`、 しかし`2`合成ではなく素数です。 のために`n = 5`、可能な素数第一分解は次のとおりです。`2 + 3`そして`3 + 2`、どちらの 2 番目の数値も合成ではありません。 したがって、5 つの値すべてが生成します。`-1`。 

たとえば、入力`1`生産しなければならない`-1`。 を扱う不注意な実装`1`コンポジットが誤って受け入れる可能性があるため`1 + 0`または別の無効な分解。 入力用`5`、単純に合計が次の 2 つの数値を見つけるだけです。`5`も不十分なので、`2 + 3`完全に素数で構成されています。 プライムとコンポジットの区別を正しくチェックする必要があります。 

## アプローチ

 直接的なブルートフォースソリューションでは、考えられるすべての主要な候補を試すことができます`x`から`2`を通して`n - 2`、 セット`y = n - x`、かどうかをテストします`x`プライムであり、`y`複合です。 すべての有効な回答が候補の中に出現する必要があるため、この方法は正しいです。 試行除算によって素数性をテストする場合、1 つの数値をチェックするのに時間がかかることがあります。`O(sqrt(n))`操作が必要なため、すべての候補をスキャンするのは最悪の場合の複雑さになります`O(n sqrt(n))`1 つのテスト ケースの場合。 と`n`と同じくらい大きい`10^9`、つまりおおよそ最大までを意味します`10^9`候補値とそれについて`31623`候補者ごとの試行除数のオーダー`3 * 10^13`最悪の場合の可算性チェック。 このような作業を最長で繰り返します`10^5`全く不可能なケースです。 

総当たりアプローチが機能するのは、答えが存在する場合、考えられる分割のどこかに存在する必要があるためですが、この問題は任意の検索問題よりもはるかに強力な構造を与えてくれます。 実際には近くの素数を見つける必要はありません`n`、固定素数なので、`2`そして`3`パリティと完全に相互作用します。 

偶数の場合`n`、素数を引く`2`偶数が残ります。 残りが少なくとも`4`、自動的に合成されます。 奇数のために`n`、素数を引く`3`偶数も残ります。`n >= 7`残りは少なくとも`4`。 その結果、検索は 1 回のパリティ チェックと 1 回の減算に集約されます。 

結果として得られるアルゴリズムは、テスト ケースごとに一定の作業のみを実行します。 素数性テスト、ふるい分け、因数分解、検索は必要ありません。

 ## アルゴリズムのチュートリアル

 1. 値を読み取る`n`。 以下の値`6`素数と合成値として表現できないため、すぐに出力します`-1`のために`n < 6`。 
2. もし`n`偶数です、印刷します`2`そして`n - 2`。 番号`2`は素数ですが、`n - 2`均等で少なくとも`4`, したがって、2 番目の数値は合成です。 
3. もし`n`奇数です、印刷してください`3`そして`n - 3`。 番号`3`は素数ですが、`n - 3`均等で少なくとも`4`, したがって、2 番目の数値は合成です。 

この構造では、常に より小さい正の数が生成されます。`n`。 のために`n >= 6`、選択された素数は最大で`3`、複合部分は`n - 2`または`n - 3`したがって、両方は厳密に次の範囲にあります。`0`そして`n`。 

### なぜ効果があるのか

 この構造の背後にある不変条件は、2 番目の数値が常に より大きい偶数の整数であるということです。`2`。 以下のすべての偶数整数`2`複合です。 偶数の場合`n`、素数を引く`2`そのような数値が得られるのは、`n >= 6`暗示する`n - 2 >= 4`。 奇数の場合`n`、素数を引く`3`そのような数値が得られるのは、`n >= 7`暗示する`n - 3 >= 4`。 残る唯一の値は、`1`を通して`5`、そしてどれにも素数と複合正の整数の両方を含めることはできないので、`-1`彼らにとってはそれが正しいのです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n = int(input())

        if n < 6:
            print(-1)
        elif n % 2 == 0:
            print(2, n - 2)
        else:
            print(3, n - 3)

if __name__ == "__main__":
    solve()
```最初のブランチは、あらゆるあり得ない小さな値を処理します。 閾値は`6`それよりも`4`なぜなら`n = 4`そして`n = 5`ただし、素数と複合加数の両方を含めることはできません。 

偶数の場合`n`、コードは選択します`2`。 結果として得られる`n - 2`均等で少なくとも`4`したがって、複合であるかどうかを明示的にテストする必要はありません。 

奇数のために`n`、コードは選択します`3`。 結果として得られる`n - 3`再び均等であり、少なくとも`4`。 使用する`3`それよりも`2`奇数マイナスなので必要です`2`は奇数であり、奇数は自動的に合成されません。 

Python では整数オーバーフローの問題はありません。 固定幅整数を使用する言語では、ここに出力される最大値は次のとおりです。`10^9`したがって、標準の 32 ビット符号付き整数でも十分です。 

概念的には条件の順序が重要です。 まず小さな不可能な値を削除し、次にパリティ構築を適用します。 なしで`n < 6`チェック、値など`n = 5`誤って奇数のブランチに入り、`3 2`、 どこ`2`合成ではなく素数です。 

## 実用的な例

 サンプルは 3 つのテスト ケースとして見ることができます。`n = 1`、`n = 6`、 そして`n = 7`。

より大きな偶数の例では、`n = 10`、同じ規則に従います。

もっと大きな奇妙な例としては、`n = 11`、奇妙なケースが使用される理由を示しています。`3`。 

|`n`|`n < 6`| パリティ | プライム`x`| 複合`y`| チェック |

## 特殊なケース

 のために`n = 1`、アルゴリズムは次に入ります。`n < 6`ブランチとプリント`-1`。 利用可能な正の合成数はまったく存在しないため、これは必然的に不可能です。

のために`n = 5`、結果はまた`-1`。 素数を含む可能な分解は次のとおりです。`2 + 3`そして`3 + 2`、2 番目の加数は両方とも素数です。 これにより、それを忘れた実装が捕捉されます`2`そして`3`複合ではありません。 

のために`n = 6`、アルゴリズムは最初の有効な偶数ケースを取得し、出力します。`2 4`。 ここ`2`プライムであり、`4`は合成であり、合計は正確に`6`。 これは、推測される分解が存在する最初の整数です。

最大値については`n = 10^9`、アルゴリズムの出力`2 999999998`。 2 番目の値は偶数であり、次の値よりも大きいです`2`, つまり複合です。 のサイズ`n`は操作の数には影響しません。これがまさに、定数時間構造が上限を快適に処理する理由です。
