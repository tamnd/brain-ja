 ## 問題の理解

 魚は座標から始まります`0`無限軸上にあり、座標に正確に着陸したい`K`。 移動は 3 つのジャンプ タイプから 1 つを選択して行われます。 初めてタイプが選択されると、それ自体の番号がジャンプします (`1`、`2`、 または`3`）。 その後同じタイプを使用するたびに、そのタイプの以前のジャンプ長が増加します。`3`。 

このタスクには 2 つの部分があります。 到達できる最小限のジャンプ数が必要です`K`、そして、到達する異なる選択シーケンスの数も必要です。`K`シーケンスで使用されるジャンプの数に関係なく。 2 番目の答えは必須です。`10^9 + 7`。 公式の制約は次のとおりです`K <= 10^7`そして最大まで`200`テストケース。 

ジャンプの長さは各選択の履歴に依存するため、動きの直接シミュレーションは誤解を招きます。 有益な観察は、選択タイプが考慮するのは使用回数だけであり、使用される順序ではないということです。 タイプの場合`j`使用されています`c`多くの場合、その寄与は固定等差数列です。 

タイプについて`1`:```
1 + 4 + 7 + ... + (1 + 3(c - 1))
= (3c^2 - c) / 2
```タイプについて`2`:```
2 + 5 + 8 + ... + (2 + 3(c - 1))
= (3c^2 + c) / 2
```タイプについて`3`:```
3 + 6 + 9 + ... + 3c
= (3c^2 + 3c) / 2
```最大`K`十分な大きさであるため、`O(K^2)`または位置を越えたグラフ検索は不可能です。 個々の数が少ないという事実を利用する必要があります。 単一タイプを使用`c`すでに時間は過ぎています`1.5c^2`距離があるので、`c`ほんの数千程度のとき`K`は`10^7`。 

見落としがちな特殊なケースがいくつかあります。 最初の間違いは、ジャンプの最小数がウェイの数も与えると仮定していることです。 のために`K = 5`、最小ジャンプ数は`2`、しかし、方法の数の答えは、`3`なぜならシーケンスは`(1,1)`、`(2,3)`、 そして`(3,2)`すべての仕事。```
Input
1
5

Output
Case 1: 2 3
```もう 1 つの間違いは、選択タイプが使用されない可能性があることを忘れていることです。 例えば、`K = 1`type を使用してアクセスできます`1`一度。 3 つのタイプすべてを必須として扱うと、このケースは見逃されます。```
Input
1
1

Output
Case 1: 1 1
```3 番目のよくある間違いは、一連の選択肢に対して 1 つの順序だけを数えることです。 カウントが次の場合`a = 1`、`b = 1`、 そして`c = 1`、同じ 3 つのジャンプが 6 つの異なる順序で現れることがあり、それらはすべて異なる方法です。 

## アプローチ

 ブルートフォースソリューションでは、考えられるすべての選択シーケンスが試行されます。 移動するたびに、各選択タイプの現在の距離と現在のジャンプの長さが維持されます。 状態にはプロセスを続行するために必要なすべての情報が含まれているため、これは正しいです。 ただし、可能なシーケンスの数は指数関数的に増加します。 わずか数十の手の深さでも、非常に多くの分岐が作成されますが、答えを得るには何千ものジャンプが必要になる場合があります。 

重要な変革は、まずジャンプの順序について考えるのをやめるということです。 タイプを仮定します`1`、 タイプ`2`、と入力します`3`使用されています`a`、`b`、 そして`c`回。 最終的な順位はこれら 3 つのカウントのみに依存します。 これらのカウントの異なるシーケンスの数が多項係数です。```
(a + b + c)! / (a! b! c!)
```したがって、問題はすべてのトリプルを見つけることになります`(a, b, c)`誰の貢献が等しいか`K`。 

カウントは小さいです。 のために`K = 10^7`、くらいしかありません。`2600`各カウントの可能な値。 すべてのペアを列挙する`(a, b)`およそ 700 万件のケースが得られます。 すべてのペアについて、残りの距離を計算し、タイプごとに生成できるかどうかを確認できます。`3`一定時間内に。 

これにより、実用的な事前計算が行われます。 有効なトリプルごとに、ジャンプの最小数を更新し、その多項寄与をウェイの数に追加します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | ジャンプ数の指数関数 | 指数関数的な検索深度 | 遅すぎる |
 | count トリプルを列挙する | O(C²) ここで、C は約 2600 | O(K) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのクエリを読み取り、必要な最大のクエリを見つけます。`K`。 より大きな位置は要求されないため、この値までの応答のみを事前計算します。 
2. 単一のジャンプ タイプに対して可能な最大のカウントを計算します。 カウントは終わりです`2600`したがって、最初の 2 つのタイプの使用法をすべて安全に列挙できます。 
3. 考えられるすべてのペアについて`(a, b)`、タイプによってすでに寄与されている距離を計算します`1`そして`2`。 
4. 残りの距離をタイプごとに埋めてみましょう`3`。 A型`3`貢献度は次のとおりです。```
3c(c + 1) / 2
```したがって、次のように解決します。```
3c(c + 1) = 2 * remaining
```方程式に非負の整数解がある場合、有効なトリプルが見つかったことになります。 

1. 有効なトリプルごとに、次のようにします。```
moves = a + b + c
```この位置の最小ジャンプ数を更新します。 追加：```
moves! / (a! b! c!)
```これらの選択肢の順序はそれぞれ異なる順序になるため、方法の数に応じて変化します。 

1. 事前計算された配列を使用して各クエリに答えます。 

なぜ効果があるのか:

 考えられるすべてのシーケンスには最終的なカウントがあります`(a, b, c)`3つの選択肢に対して。 シーケンスが移動する距離はこれらのカウントによって完全に決定されるため、列挙では 1 つのトリプルを通じて可能なすべての距離が正確に検出されます。 固定トリプルの場合、残された唯一の自由は選択の順序であり、多項係数はそれらの順序を正確にカウントします。 すべての有効なトリプルが処理されるため、シーケンスの最小長と総数の両方が正しく計算されます。 

## Python ソリューション```python
import sys

input = sys.stdin.readline

MOD = 10 ** 9 + 7

def prepare(max_k):
    cnt = 0
    while (3 * cnt * cnt + 3 * cnt) // 2 <= max_k:
        cnt += 1
    limit = cnt

    max_moves = limit * 3 + 5
    fact = [1] * (max_moves + 1)
    for i in range(1, max_moves + 1):
        fact[i] = fact[i - 1] * i % MOD

    invfact = [1] * (max_moves + 1)
    invfact[-1] = pow(fact[-1], MOD - 2, MOD)
    for i in range(max_moves, 0, -1):
        invfact[i - 1] = invfact[i] * i % MOD

    inf = 10 ** 9
    best = [inf] * (max_k + 1)
    ways = [0] * (max_k + 1)

    vals1 = []
    vals2 = []
    for i in range(limit + 1):
        vals1.append((3 * i * i - i) // 2)
        vals2.append((3 * i * i + i) // 2)

    vals3 = {}
    for i in range(limit + 1):
        vals3[(3 * i * i + 3 * i) // 2] = i

    for a, va in enumerate(vals1):
        if va > max_k:
            break
        for b, vb in enumerate(vals2):
            base = va + vb
            if base > max_k:
                break
            need = max_k - base
            c = vals3.get(need)
            if c is None:
                continue
            total = a + b + c
            add = fact[total]
            add = add * invfact[a] % MOD
            add = add * invfact[b] % MOD
            add = add * invfact[c] % MOD

            pos = base + need
            if total < best[pos]:
                best[pos] = total
                ways[pos] = add
            elif total == best[pos]:
                ways[pos] = (ways[pos] + add) % MOD

    return best, ways

def solve():
    t = int(input())
    queries = []
    mx = 0
    for _ in range(t):
        k = int(input())
        queries.append(k)
        mx = max(mx, k)

    best, ways = prepare(mx)

    ans = []
    for i, k in enumerate(queries, 1):
        ans.append(f"Case {i}: {best[k]} {ways[k]}")
    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```トリプルのシーケンスのカウントには多項係数が使用されるため、前処理ではまず階乗を構築します。 可能な最大手数はわずか数千であるため、階乗配列は小さくなります。 

配列`vals1`、`vals2`、 そして`vals3`各ジャンプ タイプを固定回数使用することによって生成される距離を保存します。 メイン ループは最初の 2 つのタイプのカウントを選択し、残りの距離から 3 番目のタイプを導出します。 

型の辞書検索`3`3 番目のネストされたループを回避します。 これがなければ、反復回数はおよそカウント制限の 3 乗になります。 辞書は最後のチェックを定数時間に変換します。 

更新ステップでは 2 つの状況に対処します。 トリプルが同じポジションの以前のすべてのトリプルよりも少ない手数を使用する場合、その最小値が置き換えられます。 同じ手数を使用する場合、その順序数が既存の答えに追加されます。 ウェイの最小長と合計数は独立した出力であるため、この区別は重要です。

 ## 特殊なケース

 のために`K = 1`、唯一の有効なトリプルは、`(a, b, c) = (1, 0, 0)`。 前処理では、型の 1 回の使用による寄与が検出されます。`1`、1 つの動きを与え、ちょうど 1 つの順序を数えます。 

のために`K = 5`、アルゴリズムは 2 つの異なるトリプルを見つけます。 トリプル`(2, 0, 0)`両方の手が強制的に type であるため、1 つの順序に寄与します。`1`。 トリプル`(0, 1, 1)`2 つの異なるジャンプ タイプを交換できるため、2 つの順序付けが可能になります。 これは、カウント ロジックが到達可能な組み合わせだけではなく、順列に基づいていることを裏付けています。 

次のような大きな値の場合、`K = 10000000`、アルゴリズムがシーケンスを明示的に作成することはありません。 少数の可能な使用回数のみがチェックされます。 これらのカウントの二次境界は、可能なすべてのソリューションをカバーしながら、前処理を制限内に保ちます。
