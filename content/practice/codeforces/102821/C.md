 ## 解決策
 ## 問題の理解

 1 つの固定線形関数が与えられます$f(x)=Ax+B$そして値の集合$x_1,x_2,\dots,x_N$。 すべてのクエリ関数について$g(x)=cx+d$、2 つの組成が恒等関数からどれだけ離れているかを測定する必要があります。 

1 つの値について$x_i$、クエリの寄与は次のとおりです。$$|f(g(x_i))-x_i|+|g(f(x_i))-x_i|$$クエリの答えは、指定されたすべての値に対するこれらの寄与の合計です。 

入力には複数のテスト ケースが含まれています。 各テスト ケースは、値の数、クエリ関数の数、係数を示します。$f$、値のリスト、そしてすべてのクエリ関数。 すべてのクエリ関数について、対応する合計を出力します。 

主な制約は、両方とも$N$そして$M$到達できる$10^5$。 すべての値に対してすべてのクエリを評価するソリューションのパフォーマンスは約$10^{10}$制限時間内に収まらない最悪の場合の作戦。 値を一度前処理し、対数時間で各クエリに答える必要があります。 

難しいのは、絶対値を正しく処理することです。 いくつかのケースでは、直接実装が簡単に壊れる可能性があります。 

の係数が$x$がゼロになると、式は定数になります。 たとえば、クエリが次の場合、$Ac-1=0$、 それから$$|(Ac-1)x_i+(Ad+B)|=|Ad+B|$$あらゆる人にとって$x_i$。 この場合、傾きによる除算は無効になります。 

例えば：```
1
3 1 2 0
1 2 3
0.5 5
```ここ$Ac-1=2\cdot0.5-1=0$。 最初の式は常に$|5|$、したがって、その貢献度は$15$。 ゼロで除算して転換点を計算しようとするソリューションは失敗します。 

転換点がすべての値の範囲外にある場合、別の特殊なケースが発生します。 例えば：```
1
4 1 1 0
1 2 3 4
1 100
```式は次のようになります$x_i+100$、したがって、答えは次のとおりです$101+102+103+104=410$。 配列の中央付近の値のみを考慮する不注意な実装では、すべての項が同じ符号を持つことを見落とす可能性があります。 

重複した値も間違いの原因となります。 例えば：```
1
5 1 1 0
2 2 2 2 2
1 -2
```その表現は、$x_i-2$したがって、すべての項はゼロであり、答えはゼロです。 プレフィックスの計算では、等しい値を正しく処理する必要があります。 

## アプローチ

 直接的なアプローチは簡単です。 すべてのクエリ関数について、すべてを置き換えます。$x_i$、2 つの組成を計算し、絶対値を取得して加算します。 これは定義に正確に従っているため、正しいです。 ただし、各クエリにはコストがかかります$O(N)$、与える$O(NM)$操作。 と$N=M=100000$、これは次のようになります$10^{10}$評価は利用可能な時間をはるかに超えています。 

重要な観察は、両方の組成の差が一次関数であるということです。 最初のものを展開すると、次のようになります。$$f(g(x))-x=A(cx+d)+B-x$$

$$=(Ac-1)x+(Ad+B)$$2 番目は次のようになります。$$g(f(x))-x=c(Ax+B)+d-x$$

$$=(Ac-1)x+(Bc+d)$$どちらの式も同じ傾きを持っています。 問題全体は、次の形式のクエリに応答することになります。$$\sum_i |px_i+q|$$どこ$p$そして$q$はクエリごとに既知です。 

もし$p\neq0$、傾きの絶対値を因数分解できます。$$\sum_i |p||x_i+\frac qp|$$させて：$$t=-\frac qp$$それから：$$\sum_i |p||x_i-t|$$したがって、必要なのは以下を返すデータ構造だけです。$$\sum_i |x_i-t|$$あらゆる本物の$t$。 

値を並べ替えた後の位置は、$t$配列を以下の値に分割します$t$より大きい値$t$。 プレフィックス合計を使用すると、二分探索後に両方の部分を一定時間で計算できます。 

アプローチを次のように比較します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(NM) | お(1) | 遅すぎる |
 | 最適 | O((N+M) log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての値を並べ替える$x_i$そしてプレフィックス合計配列を構築します。 プレフィックスの合計を使用すると、任意のプレフィックスの合計を即座に計算できます。これは、選択した任意の点までの距離を計算するのに十分です。 
2. クエリ関数ごとに$g(x)=cx+d$、共有勾配を計算します。$$p=Ac-1$$2 つの切片は次のとおりです。$$q_1=Ad+B$$そして$$q_2=Bc+d$$1. 以下を計算するためのヘルパー関数を作成します。$$S(p,q)=\sum_i |px_i+q|$$もし$p=0$、すべての項は同じ値です$|q|$したがって、結果は単純に次のようになります。$N|q|$。 

それ以外の場合は、式を次のように変換します。$$|p|\sum_i |x_i-t|$$どこ：$$t=-q/p$$1. 計算するには$\sum_i|x_i-t|$、最初の位置を見つけます。$x_i\ge t$。 この位置が$k$。 左側は以下に貢献します。$$t\cdot k-\sum_{i<k}x_i$$そして右側は次のように貢献します。$$\sum_{i\ge k}x_i-t(N-k)$$それらを加算すると、必要な距離の合計が得られます。 

1. クエリの最終的な答えは次のとおりです。$$S(p,q_1)+S(p,q_2)$$この値を十分な精度で出力します。 

正確さは、すべてのクエリ式がソートされた行上の距離の合計に正確に換算されるという事実から得られます。 分割点$t$の標識がある唯一の場所です$x_i-t$変化します。 それより前のすべての値は左側からの距離に寄与し、それより後のすべての値は右側からの距離に寄与します。 プレフィックスの合計には両方のグループの正確な合計が含まれるため、計算された値は常に絶対値の真の合計になります。 

## Python ソリューション```python
import sys
import bisect

input = sys.stdin.readline

def solve():
    data = sys.stdin.buffer.read().split()
    ptr = 0
    t = int(data[ptr])
    ptr += 1
    out = []

    for case in range(1, t + 1):
        n = int(data[ptr])
        m = int(data[ptr + 1])
        A = float(data[ptr + 2])
        B = float(data[ptr + 3])
        ptr += 4

        xs = [float(data[ptr + i]) for i in range(n)]
        ptr += n

        xs.sort()
        pref = [0.0]
        for x in xs:
            pref.append(pref[-1] + x)

        def dist_to_point(x):
            k = bisect.bisect_left(xs, x)
            left = x * k - pref[k]
            right = (pref[n] - pref[k]) - x * (n - k)
            return left + right

        def calc(p, q):
            if abs(p) < 1e-15:
                return n * abs(q)
            return abs(p) * dist_to_point(-q / p)

        out.append(f"Case {case}:")

        for _ in range(m):
            c = float(data[ptr])
            d = float(data[ptr + 1])
            ptr += 2

            p = A * c - 1.0
            q1 = A * d + B
            q2 = B * c + d

            ans = calc(p, q1) + calc(p, q2)
            out.append(f"{ans:.10f}")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```値の合計数が大きくなる可能性があるため、入力はバイトとして読み取られ、まとめて解析されます。 並べ替えられた配列とプレフィックスの合計は、クエリを処理する前に、テスト ケースごとに 1 回構築されます。 

機能`dist_to_point`転換点の周りで数学的分割を実装します。`bisect_left`点より小さくない最初の要素を見つけます。これは、まさに負の値と非負の値の間の境界です。$x_i-t$。 

機能`calc`特殊なゼロスロープの場合を個別に処理します。 これにより、ゼロによる除算が回避され、数値の不安定性も回避されます。 非ゼロの傾きの場合、線形絶対値からスケーリングされた距離合計への変換が適用されます。 

入力には実数が含まれており、必要な誤差許容度が次のとおりであるため、すべての計算では浮動小数点値が使用されます。$10^{-6}$。

 ## 特殊なケース

 いつ$Ac-1=0$、アルゴリズムは定数式分岐に入ります。 のために：```
1
3 1 2 0
1 2 3
0.5 5
```傾きはゼロなので、最初の項が寄与します$3\times5=15$。 2 番目の式も独自の切片を持つ定数であり、ヘルパーは転換点の計算を試行せずに両方を処理します。 

転換点がソートされた値の外側にある場合、二分検索は配列の先頭または末尾のいずれかを返します。 のために：```
1
4 1 1 0
1 2 3 4
1 100
```ターニングポイントは$-100$。 すべての値は右側にあるため、距離の計算は次のようになります。$$(1+100)+(2+100)+(3+100)+(4+100)=410$$分割の一方の側には要素が含まれていないため、接頭辞式はこれを自然に処理します。 

すべての値が等しい場合:```
1
5 1 1 0
2 2 2 2 2
1 -2
```ターニングポイントはまさに繰り返された値です。 二分探索では最初の等しい位置が見つかり、左右の寄与は両方ともゼロであり、結果は正しくゼロとして報告されます。
