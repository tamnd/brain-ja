 ## 解決策
 ## 問題の理解

 ゲームは 2 つの正の整数で行われます。 移動すると、そのうちの 1 つだけが 1 つ減ります。 ゲームはゼロに到達することではありません。 代わりに、危険な境界は値です`K`: どちらかの数字になった瞬間`K`、ボブが勝ちます。 アリスは、現在の 2 つの数字が両方とも素数の場合に勝ちます。ただし、`K`同時に起こった場合、ボブが勝ちます。`K`状態が優先となります。 

入力により、いくつかの独立したゲームが提供されます。 各ゲームで開始ペアが指定されます`(x, y)`、負ける境界線`K`、そして誰が最初に動くか。 出力では、両方のプレーヤーが最適な手を選択したと仮定して、最終的な勝者を求めます。 

上限`x, y <= 10^6`すべてのペアに対して完全な動的プログラミング テーブルを除外します。 まであります`10^12`可能な状態はメモリの制限をはるかに超えています。 最大 1000 までの値を持つ 90 パーセントの小さなサブタスクは、状態シミュレーションが最初は機能するが、最終的な解決策では動きの特別な構造と主条件を利用する必要があることを示唆しています。 解決策`O(max(x, y))`前処理が必要であり、クエリごとに少量の作業のみが必要です。 

いくつかの特殊なケースは見落とされがちです。 初期位置がすでに素数ペアの場合、いずれかの数字が既に一致していない限り、ゲームはすでに終了し、アリスの勝ちです。`K`。 たとえば、入力の場合`5 7 2 0`、両方の数値が素数であり、どちらも素数ではない`K`、ということで、答えはアリスです。 移動後の最終状態のみをチェックする再帰的な実装では、ゲームが誤って続行されます。 

もう 1 つのトリッキーなケースは、素数ペアに到達し、`K`一緒に起こります。 たとえば、`x = 3`、`y = 5`、`K = 3`、最初の数値はすでに等しい`K`。 どちらの数字も素数ですが、答えはボブです。 優先順位を無視して、`K`条件によっては間違った結果が得られます。 

先発選手も重要だ。 ボブが移動を強いられたときに勝っているポジションは、アリスが移動すると負ける可能性があります。これは、ボブがチャンスを得る前にアリスがすぐに素数ペアを作成できるためです。 例えば、`4 9 2 0`そして`4 9 2 1`最初の動きが異なるプレイヤーに属しているため、戦略的な状況は異なります。 

## アプローチ

 直接的なアプローチは、到達可能なすべての状態の勝者を保存することです。`(x, y, turn)`再帰または動的プログラミングを使用します。 状態遷移には 2 つの選択肢しかなく、どちらかの座標を減少させます。 これが機能するのは、ゲーム グラフが非周期的であり、すべての手が減少するためです。`x + y`。 ただし、可能な状態の数は膨大です。 に近い値`10^6`、約ある可能性があります`10^12`ペアなので、状態ごとに 1 バイトですら不可能です。 

有益な観察は、両方のプレイヤーが座標間の同じ関係を維持しようとする場合にのみ、グリッド内を斜めに移動するという事実から得られます。 両方の座標が 1 回ずつ減少すると、ゲームは到達します。`(x - d, y - d)`2移動後。 唯一の問題は、これらの同期位置の 1 つが交差する前に素数のペアになるかどうかです。`K`。 

定義する`sameStep(x, y)`存在するかどうかを確認するため`d`そのような`x - d`そして`y - d`両方とも素数であり、さらにより大きい`K`。 これは、対戦相手が中断できない場合に、アリスが最終的に素数ペアを強制できる位置を表します。 

残りのケースは、誰の順番になるかによってのみ決まります。 ボブが先に移動したとき、現在位置にすでに同期された主要な目的地がある場合は、アリスが勝ちます。 アリスが最初に移動する場合、彼女は最初の移動をどちらの座標でも行うことができるため、次に考えられる 2 つの位置をテストします。 

ブルート フォース手法では、あらゆる可能なパスが探索されます。 最適化された方法では、対角位置のみをスキャンし、ふるいを使用して素数チェックに一定時間で回答します。

 ## アルゴリズムのチュートリアル

 1. までのすべての数値の素数を事前計算します。`10^6`エラトステネスのふるいを使って。 ゲームでは数値が素数かどうかのみを問うため、繰り返しの除算の試行が不要になります。 
2. すでに終了しているポジションを処理します。 どちらかの座標が等しい場合`K`, 境界ルールが優先されるため、ボブはすぐに勝ちます。 両方の座標が素数で、どちらも素数でない場合`K`, アリスはすぐに勝ちます。 
3. 対角位置を通過するヘルパーを作成する`(x - d, y - d)`。 両方の座標が上にある間`K`、両方が素数であるかどうかを確認します。 そのようなポジションが存在する場合、アリスは勝利のターゲットとなる可能性があります。 
4. ボブが開始すると、現在の位置にそのような将来の素数ペアが含まれるかどうかを評価します。 ボブはアリスがそこに移動することを許可できないため、これによってアリスがそれでも強制的に勝利できるかどうかが決まります。 
5. アリスが開始したら、考えられる両方の最初の手をテストします。 彼女はどちらの座標も 1 つ減らすことができるため、どちらかの場合に勝ち手が存在します。`(x - 1, y)`または`(x, y - 1)`勝ちの斜めパスが含まれています。 

これが機能する理由: 重要な不変条件は、2 つの手ごとに、どちらのプレイヤーもゲームを終了していない場合、唯一争われない進行は両方の座標が同じ量だけ減少する対角線に沿ったものであるということです。 ヘルパーは、主要な条件が現れる可能性のある瞬間を正確にチェックします。 プライムペアに到達する前に強制的に到達できる最初のプレイヤー`K`境界によって結果が決まり、他のすべてのパスは最終的にボブの境界条件に負けます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

LIMIT = 10**6

def build_sieve(n):
    prime = [True] * (n + 1)
    prime[0] = prime[1] = False
    for i in range(2, int(n ** 0.5) + 1):
        if prime[i]:
            step = i
            start = i * i
            prime[start:n + 1:step] = [False] * (((n - start) // step) + 1)
    return prime

prime = build_sieve(LIMIT)

def diagonal_prime(x, y, k):
    while x > k and y > k:
        if prime[x] and prime[y]:
            return True
        x -= 1
        y -= 1
    return False

def can_alice_win_after_bob_turn(x, y, k):
    if diagonal_prime(x, y, k):
        return True
    if diagonal_prime(x - 2, y, k) and diagonal_prime(x, y - 2, k):
        return True
    return False

def solve_case(x, y, k, w):
    if x == k or y == k:
        return "Bob"

    if prime[x] and prime[y]:
        return "Alice"

    if w == 1:
        return "Alice" if can_alice_win_after_bob_turn(x, y, k) else "Bob"

    return "Alice" if (
        can_alice_win_after_bob_turn(x - 1, y, k)
        or can_alice_win_after_bob_turn(x, y - 1, k)
    ) else "Bob"

def main():
    t = int(input())
    ans = []
    for case in range(1, t + 1):
        x, y, k, w = map(int, input().split())
        ans.append(f"Case {case}: {solve_case(x, y, k, w)}")
    print("\n".join(ans))

if __name__ == "__main__":
    main()
```最大 100 個のテスト ケースが同じプライム チェックを再利用できるため、sieve はルックアップ配列を 1 回構築します。 の`diagonal_prime`関数は、アルゴリズムのウォークスルーからの中心的な観察です。 それは決して交差しない`K`ループ条件では、両方の値が厳密に境界より大きいままである必要があるため、`K`。 

機能`can_alice_win_after_bob_turn`ボブがプレイしようとしているときに必要な 2 つの手の構造をチェックします。 2 番目の条件は、ボブが最初に 1 つの座標を移動し、アリスがもう 1 つの座標で応答する状況を処理します。 チェックインの順番`solve_case`重要なのは、`K`条件は主条件をオーバーライドします。 

Python の整数はオーバーフローの問題を回避します。 注意が必要な唯一の境界詳細は、以下を含む素数ペアです。`K`受け入れてはなりません。そのため、`K`チェックはプライム チェックの前に行われます。

 ## 特殊なケース

 開始位置がすでにプライムの場合、アルゴリズムは移動を行う前に戻ります。 のために`5 7 2 0`、両方の数値が素条件を満たしており、どちらも等しくない`K`, したがって、アリスはすぐに勝ちます。 

いつ`K`が素数の場合、数値は両方の値になる可能性があるため、明らかな矛盾が生じる可能性があります。`K`そしてプライム。 アルゴリズムはチェックすることでこれを処理します。`x == K`または`y == K`初め。 のために`3 5 3 0`, 境界条件の方が優先されるため、Bob が勝ちます。 

先発プレイヤーが変わる場合、最初の一手で結果が完全に変わってしまうこともあります。 アリスが座標を 1 つ減らすことで素数対を作成できる位置の場合、`w = 0`アリスにすぐにその機会を与えますが、`w = 1`ボブにそれを避ける機会を与えます。 

両方の座標が等しい場合、対角線には同じ値が繰り返されます。 ヘルパーは、開始から到達までの可能な距離をすべてチェックするため、引き続き機能します。`K`、座標が異なることに依存する必要はありません。
