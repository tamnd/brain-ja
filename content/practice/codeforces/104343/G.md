 ## 解決策
 ## 問題の理解

 私たちはPK戦の歴史の一部を与えられています。 2 つの文字列は、これまでに行われたキックのシーケンスを表します。最初の文字列は最初のチームに属し、2 番目の文字列は 2 番目のチームに属します。 各キャラクターは 1 つのキックに交互に対応し、各キャラクターはゴールまたはミスのいずれかになります。 

銃撃戦は標準ルールに従って行われます。 両チームは最初にそれぞれ最大 5 回のキックを行いますが、残りのキックで一方のチームが到達できなくなった場合、試合が早く終了する可能性があります。 両チームが 5 回のキックを完了してもスコアが同点の場合、シュートアウトはサドンデス形式で継続され、同じ回数の試行でどちらかのチームがより多くのゴ​​ールを獲得するまで、チームが交互にキックを行います。 

課題は、銃撃戦をできるだけ早く終了するために将来の結果が最適に選択されると仮定して、さらに実行する必要がある追加キックの最小数を決定することです。 

入力サイズは小さく、文字列あたり最大 10 文字です。 これにより、漸近最適化に対するプレッシャーがなくなり、シミュレーションや直接のケース分析が可能になります。 重要な難しさはパフォーマンスではなく、試合がすでに決まっているときと、将来の最適な結果のもとでどれだけ早く試合を終了できるかを正確にモデル化することです。 

単純な間違いは、残りのプロセスを単に「最初の 5 つのキックを完了する」または「両方が完了するまでプレイする」と扱うことによって発生します。 これは 2 つの状況で失敗します。 

どちらかのチームがすでに数学的に劣っている場合、キックが残っているにもかかわらず、試合はすでに決まっている可能性があります。 たとえば、数回のキックの後、一方のチームが残りのシュートをすべて決めたとしても追いつけない場合、答えはゼロになります。 残りのスロットを常にカウントする単純なアプローチでは、過大評価してしまいます。 

別の失敗は突然死で発生します。 両チームが 5 回のキックに達すると、ゲームは固定制限に依存するのではなく、ペアの試行後の平等に依存します。 各チーム 5 回で停止する単純なシミュレーションでは、5 回がすでに完了している場合でも追加のキックが必要になる可能性があることを無視しています。 

## アプローチ

 強引なアイデアは、残りのキックで起こり得るすべての将来の結果をシミュレートすることです。 次のキックごとに、ゴールかミスかに分岐し、ゲームが終了するかどうかを追跡します。 キックはせいぜい数個しか残っていないので、これは実現可能と思われます。 ただし、深さが浅い場合でも、分岐は指数関数的で不必要です。これは、確率や実現可能性は求められず、最良の場合の最小限の終了時間のみが求められるためです。 

重要な観察は、不確実性をシミュレートする必要がまったくないということです。 今後のキックは常に、試合を早期に終了するために最も有利な方法で解決されると想定できます。 これにより、問題は、現在のスコアと残りの最大機会が与えられた場合に、どのくらい早く結果を強制できるかを計算することに変換されます。 

キックは 1 チームにつき 5 回までで、いずれかのチームが到達できなくなると試合は終了します。 そこで、一方が残りのショットをすべて決めても、相手が残りのショットをすべて外したとしても追いつけない最も早いポイントを計算します。 

両チームがまだ 5 回のキックに到達し、そのフェーズの後も同点のままである場合、問題はサドンデスに移行します。 サドンデスでは、1 つのペアの差が勝者を決定するのに十分であるため、キックのペアが追加されるたびに、試合は即座に解決されます。 

したがって、構造は 2 つのフェーズになります。到達可能性に基づいて枝刈りを行う固定の 5 キック フェーズと、決定的な差を即座に強いられるかどうかに応じて、追加の各ラウンドが 1 回または 2 回のキックとなるタイブレーク フェーズです。

 ## アルゴリズムのチュートリアル

 1. 2 つの入力文字列をスキャンして、両チームの現在のゴールとキックをカウントします。

各チームが蹴ったキックの数とゴール数を追跡します。 
2. 最初の 5 キックフェーズの残りの部分をシミュレートします。 

各チームについて、キックが 5 に達するまでに残っているキックの数を計算します。これにより、標準フェーズで将来可能な最大得点枠が決まります。 
3. 5 キックフェーズで 1 つのチームがすでに到達不能になっているかどうかを確認します。 

チーム A の場合、残りのキックをすべて得点したと仮定します。 チーム B の場合、残りのキックをすべて失敗したとします。 その最善のケースであっても、A が B の現在のスコアを上回ることができない場合、A はすでに敗退しており、B も同様です。勝者がすぐに決定できる場合は、追加のキックを 0 回返します。 
4. 両チームが最初の 5 回のキック以内でまだ結果に影響を与えることができる場合は、残りの固定フェーズを終了する可能性があるために必要な最小キック数を計算します。 

強制勝利が可能になるか、両方が 5 回のキックに達するまで、あと何回キックが必要かを評価します。 
5. 5 回のキックに達した後、スコアが同点の場合は、サドンデスロジックに切り替えます。 

ここからはペアキックで勝負が決まります。 各ラウンドはチームごとに 1 回のキックで構成され、累積結果が異なる場合は直ちに試合が終了します。 
6. サドンデスにおける残りの最小キックは、次のペアで決定を強制できるかどうかに応じて、常に 2k または 2k+1 のいずれかになります。 

最適な結果を想定しているため、最も早い解決は、一方のチームがリードできる最初のペアになります。 

### なぜ効果があるのか

 重要な不変条件は、どちらかのチームが固定フェーズですでに数学的に到達不可能であるかどうか、およびゲームがサドンデスに入っているかどうかという 2 つの状態だけが重要であるということです。 固定フェーズでは、残りの不確実性は将来のミスや目標によって制限されるため、到達可能性によって終了が正確に定義されます。 サドンデスでは、対称性によりペアのステップでのみ進行することが保証され、ペアの不均衡が発生すると即座にゲームが終了します。 早期に終了するための最も好ましい結果を常に想定するため、計算された結果は達成可能な下限となり、これ以上改善することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    a = input().strip()
    b = input().strip()

    ga = a.count('O')
    gb = b.count('O')
    ca = len(a)
    cb = len(b)

    # remaining kicks to reach 5
    rem_a = max(0, 5 - ca)
    rem_b = max(0, 5 - cb)

    # check if already decided in normal phase
    # best case: A scores all remaining, B misses all remaining
    if ga + rem_a < gb:
        print(0)
        return
    if gb + rem_b < ga:
        print(0)
        return

    # simulate finishing up to 5 each optimally
    # if both reach 5 and still tie, go sudden death
    # remaining kicks until both reach 5
    need = max(rem_a, rem_b)

    ga2 = ga
    gb2 = gb

    for i in range(need):
        if ca + i < 5:
            ga2 += 1
        if cb + i < 5:
            gb2 += 1

    # after forced completion of first 5 each
    # if not tied, can finish immediately at that point
    if ga2 != gb2:
        print(need)
        return

    # sudden death: each round is 2 kicks
    # minimum is 2 more kicks (one round)
    print(need + 2)

if __name__ == "__main__":
    solve()
```実装では、まず現在のスコアと蹴られたキックの数を再構築します。 次に、直接の最悪の場合の境界を使用して、初期段階での到達可能性をチェックします。残りのキックは、一方のチームでは保証されたゴールとして扱われ、もう一方のチームには保証されたミスとして扱われ、そのチームに考えられる最も強力な将来の状態が与えられます。 

まだ勝者を強制できない場合、コードは両チームをそれぞれ 5 回キックした時点まで進め、両チームを同期させるために必要な強制キックの数をカウントします。 これは変数で表されます`need`, これは単にチームあたり 5 人に達するための残りの最大ノルマです。 

両チームのキック数が 5 回揃ったら、スコアを比較します。 両者が異なる場合、その時点で試合は直ちに終了します。 それ以外の場合はサドンデスに入り、最短の解決策は追加の 1 ラウンド、つまり 2 回のキックです。

| ステップ | 目標 | B ゴール | キック | Bキック | 状態 |
 | --- | --- | --- | --- | --- | --- |
 | 開始 | 2 | 2 | 3 | 2 | 進行中 |

 残り 5 回のキック: A は 2 回、B は 3 回必要です。`need = 3`。 

最適な解決策でそれぞれ 5 回のキックを強制的に完了させた後:

 A はさらに最大 2 ゴール、B はさらに 3 ゴールを獲得できますが、最小限のエンディングを評価しているため、両方を 5 に揃えます。 

それぞれ 5 回のキックの後、同点になる可能性があるため、サドンデスに入り、追加の 1 ラウンド (キック 2 回) が必要になります。 ただし、一致は強制完了内の早い段階ですでに解決できるため、計算された最小の答えは 3 になります。 

これは、決定的な強制結果が存在する構成に到達するのに十分なキックのみが必要であることを反映しています。

 ## 特殊なケース

 エッジケースの 1 つは、一方のチームのキックの残りが少なくなっているにもかかわらず、数学的にはまだ生き残っている場合に発生します。 アルゴリズムは、残りのキック カウントを使用して到達可能性を明示的に計算することでこれを処理し、勝者を時期尚早に宣言しないようにします。 

もう 1 つのエッジケースは、両チームが同スコアで 5 回のキックに達した場合です。 このコードは、強制完了後に等価性を検出することでサドンデスにきれいに移行し、さらに 1 ラウンドだけ追加して最小限の拡張を保証します。 

最後のエッジ ケースは、1 つだけ異なる非対称の入力長であり、交互のターンに対応します。 シミュレーションはインデックスの位置合わせには依存せず、合計カウントと残りの容量のみに依存するため、入力形状に関係なく正確なままになります。
