 ## 問題の理解

 各ファイターは一連の戦闘スタイルを所有しています。 スタイルは、上半身と下半身を対象とした 2 つの同時アクションで構成されます。 各アクションは攻撃、ブロック、または何も行わないことのいずれかであり、待機以外のすべてのアクションには入力全体にわたって厳密に一意のタイムスタンプがあります。 

攻撃が実行されても、すぐにはヒットしません。 タイムスタンプどおりに着陸します。 ブロックはそのタイムスタンプでアクティブになり、ブロック時間後に厳密に到達する攻撃からその方向を保護します。 攻撃がブロックされても、まったく効果がありません。 ブロックされなければヒットとなり、すぐに相手のスタイルを終わらせます。 

試合は常にバーナードの 1 つのスタイルと相手の 1 つのスタイルで行われます。 対戦相手が選択したスタイルは一様にランダムであるため、目標は、すべての対戦相手のスタイルに対して各バーナード スタイルを評価し、どれくらいの頻度で勝つか、引き分け、または負けるかを計算することです。 出力は、勝利確率を最大化するバーナード スタイルのインデックスであり、引き分け確率が高いほど同点を破り、次にインデックスが小さいほど同点を破ります。 

この制約は、バーナード スタイルと対戦相手のスタイルのすべてのペアを直接比較することが可能であることを意味します。 片面あたり最大 1000 のスタイルがあり、$N \times M$評価はせいぜい与えられる$10^6$ペアワイズ シミュレーション。各シミュレーションが一定時間の場合、問題なく制限内に収まります。 

主な微妙な点は、ブロッキングと攻撃のタイミングが 2 つの独立した方向でどのように相互作用するかを正確にモデル化していることです。 単純な間違いは、上位と下位のインタラクションを分離せずに戦闘全体を単一のタイムライン イベント シーケンスとして扱うことであり、これが誤った順序付けロジックにつながります。 

もう 1 つの一般的な失敗ケースは、双方が「攻撃」しているように見えても、以前のブロックにより一方または両方の攻撃が実際には無効である場合に発生します。 たとえば、バーナードのアッパー攻撃が時間 10 で、相手のアッパーブロックが時間 5 の場合、相手のアッパー攻撃が存在しない場合でも、バーナードの攻撃は完全に無効化されます。 

2 番目のエッジケースは、両方の戦闘機が攻撃を成功させなかった場合です。 この状況では、複数の攻撃が存在し、すべてブロックされた場合でも、タイミング設定に関係なく、結果は常に引き分けになります。 

## アプローチ

 簡単なアイデアは、スタイルの各ペアを個別にシミュレートすることです。 固定のバーナード スタイルと相手のスタイルの場合、4 つの可能なアクションのそれぞれが有効な攻撃結果を生み出すかどうかを決定します: バーナード アッパー、バーナード 下、相手の上、相手の下。 

各アクションは、同じ方向の対応するブロックに対してチェックされます。 ブロックが存在し、攻撃よりも先に発生した場合、攻撃は無効になります。 それ以外の場合は、タイムスタンプで成功したヒットになります。 

有効なヒットがすべてわかったら、戦いは各側で最も早く成功したヒットを比較することに減ります。 一方の側のみが少なくとも 1 回のヒットに成功した場合、その側が即座に勝ちます。 双方がヒットに成功した場合、タイムスタンプが早いほうが勝者を決定します。 双方ともヒットが成功しなかった場合、結果は引き分けとなります。 

ブルートフォースアプローチはすべてを評価します$N \cdot M$ペアごとに一定の作業を実行し、合計で$O(NM)$。 両方なので$N$そして$M$最大 1000 であれば、これで十分です。 

これを効率化する重要な観察点は、各戦いが単純な比較により最大 4 つのイベントによって完全に決定され、異なるペア間の依存関係がないことです。 グローバルな並べ替えやグラフ構造は必要ありません。

 ## アルゴリズムのチュートリアル

 すべてのバーナード スタイルとすべての対戦相手のスタイルの結果を計算し、勝ち/引き分け/負けの数を集計します。 

1. バーナード スタイルごとに、勝ちと引き分けのカウンターを初期化します。 これらは、すべての対戦相手のスタイルにわたって結果を蓄積します。 
2. 対戦相手のスタイルごとに、バーナードのアッパー攻撃が生き残るかどうかを計算します。 バーナードのアッパーアクションが攻撃で、相手のアッパーアクションが先に発生したブロックの場合、その攻撃は解除されます。 それ以外の場合、それが攻撃であれば、その時点でヒットが生成されます。 
3. 上のレーンとは関係なく、バーナードの下のアクションに対して同じロジックを繰り返します。 ブロックは方向固有であるため、2 つの方向が干渉することはありません。 
4. バーナードのブロックをプロテクションとして使用し、同様に相手の上下の攻撃を計算します。 
5. 生き残る可能性のある 4 つの攻撃を 2 つの値に減らします。バーナードのベスト (バーナードの有効なヒットの最小時間) と相手のベスト (有効な相手のヒットの最小時間) です。 サイドに有効なヒットがない場合は、時間がまったくないものとして扱われます。 
6. 結果を決定します。 どちらの側にも有効なヒットがない場合は、引き分けと記録します。 一方の側のみが有効なヒットを持っている場合は、その側が勝ちます。 両方に有効なヒットがある場合、タイムスタンプの小さい方が勝者を決定します。 
7. すべての対戦相手のスタイルを処理した後、バーナード スタイルを勝利数、引き分け、インデックスの順に辞書順に比較します。 

正確さは、すべてのインタラクションが独立した方向性生存チェックと最終的な最小時間比較に帰着するという事実に依存します。 攻撃がブロックされ、生き残っていることが判明すると、一連の中間イベントによって最終結果が変わることはありません。 

### なぜ効果があるのか

 各アクションは 2 つのメカニズムのいずれかを通じてのみ試合に影響を与えることができます。つまり、前のブロックによる相手の攻撃の除去、またはタイムスタンプ付きの単一ヒットの生成です。 すべてのタイムスタンプは個別であるため、同時解決での同点は発生しません。 これにより、各方向が攻撃を削除するか変更せずに保存する単純なフィルターになります。 

フィルタリング後、戦闘全体は最大 2 つのスカラー値の比較となり、完全なシミュレーションを必要とせずにイベントの元の順序が保持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    bern = [None] * n
    opp = [None] * m

    for i in range(n):
        a, b, c, d = map(int, input().split())
        bern[i] = (a, b, c, d)

    for i in range(m):
        a, b, c, d = map(int, input().split())
        opp[i] = (a, b, c, d)

    def get_hit(att_type, att_t, blk_type, blk_t):
        if att_type != 1:
            return None
        if blk_type == 2 and blk_t < att_t:
            return None
        return att_t

    def fight(b, o):
        ba_u, bt_u, ba_l, bt_l = b
        oa_u, ot_u, oa_l, ot_l = o

        b_up = get_hit(ba_u, bt_u, oa_u, ot_u)
        b_lo = get_hit(ba_l, bt_l, oa_l, ot_l)

        o_up = get_hit(oa_u, ot_u, ba_u, bt_u)
        o_lo = get_hit(oa_l, ot_l, ba_l, bt_l)

        b_best = None
        o_best = None

        for x in (b_up, b_lo):
            if x is not None:
                b_best = x if b_best is None else min(b_best, x)

        for x in (o_up, o_lo):
            if x is not None:
                o_best = x if o_best is None else min(o_best, x)

        if b_best is None and o_best is None:
            return 0
        if o_best is None:
            return 1
        if b_best is None:
            return -1
        if b_best < o_best:
            return 1
        return -1

    best_idx = 0
    best_win = -1
    best_draw = -1

    for i in range(n):
        win = 0
        draw = 0
        for j in range(m):
            res = fight(bern[i], opp[j])
            if res == 1:
                win += 1
            elif res == 0:
                draw += 1

        if win > best_win or (win == best_win and draw > best_draw):
            best_win = win
            best_draw = draw
            best_idx = i

    print(best_idx + 1)

if __name__ == "__main__":
    solve()

外側のループはバーナード スタイルごとに結果を集計し、選択ルールの要求どおりに勝ちと引き分けを正確に追跡します。 インデックス付けは、最後に 0 ベースの出力から 1 ベースの出力に変換することによって処理されます。

 ## 特殊なケース

 重要なエッジケースは、両方のファイターのアクションがすべて非攻撃であるか、すべての攻撃がブロックされた場合です。 そのような状況では、あらゆる`fight`コールすると引き分けが返されます。 アルゴリズムは両方を残すことでこれを処理します。`b_best`そして`o_best`として`None`これにより、明示的な描画ブランチがトリガーされ、描画カウンターに正しく貢献します。
