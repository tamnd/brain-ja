 ## 解決策
 ## 問題の理解

 私たちには、特定の瞬間に起こる一連のイベントが与えられています。 各イベントは、平面に向かって垂直に移動する点に対応します。 点が平面に到達した瞬間に、その平面内での水平位置が固定され、その瞬間からその点は平面上で「アクティブ」であると見なすことができます。 

いつでも、平面内の原点を中心として回転する無限の線が存在します。 最初、この線は正の X 軸上にありますが、時間の経過とともに時計回りまたは反時計回りに回転する可能性があります。 唯一の制限は、回転できる速度です。その角速度は、選択した値 K によって制限されます。 

イベントがプレーン内でアクティブになった瞬間に、非常に小さな許容範囲内で回転線がその点を通過する場合、イベントは正常に「ヒット」したと見なされます。 線分は原点を通過するため、線分には方向がないため、この条件は、線分の方向が原点から点への方向と 180 度反転するまで一致することと等価です。 

したがって、各点は、それが使用可能になる特定の時間と、それが当たる可能性のある平面内の 2 つの対称的な有効な角度に寄与します。 タスクは、制限速度を遵守しながら、時間の経過とともにラインを連続的に回転させながら、少なくとも M 個のイベントにヒットできるように、最小の角速度 K を決定することです。 

N ≤ 500 という制約は、O(N²) または O(N² log N) アプローチが許容される一方で、二分探索と組み合わせる場合は、実行可能性チェックごとに 3 次以上のアプローチは避けなければならないことを示します。 これは、K の候補値をテストし、二次動的計画法構造を使用して実現可能性を検証する可能性が高いことを強く示唆しています。 

イベントが時間的に近いものの、大きな角度の移動が必要な場合、微妙な問題が発生します。 2 つの必須ヒットが短い間隔で矛盾する方向を要求する場合、小さな K は失敗します。 もう 1 つの失敗モードは、各イベントが独立して処理できると想定しており、イベント時間間でラインが継続的に移動する必要があるという事実を無視しています。 

素朴な間違いは、瞬間的な角度の実現可能性に対して各イベントを個別にチェックするだけでよいと想定することです。 たとえば、各イベントが個別に到達可能であっても、その順序により、連続して選択されたヒットの間でラインの回転が速すぎる可能性があります。 これが、この問題を点単位のチェックではなく、根本的に全体的なスケジュールの問題にする理由です。 

もう 1 つの特殊なケースは、M が小さいものの、最も互換性のあるチェーンが単に時間順の最初の M イベントではない場合です。 順序と角度の互換性は相互作用するため、時間または角度だけによる貪欲な選択は失敗する可能性があります。 

## アプローチ

 強引なアイデアは、M 個のポイントのすべてのサブセットを選択して、それらにヒットする継続的なローテーション スケジュールが存在するかどうかを確認することです。 固定サブセットの場合、各点に 2 つの有効な角度の 1 つを割り当て、連続して選択した点間の角度移動が速度 K で達成できるかどうかを検証する必要もあります。これにより、サブセットの数が指数関数的に増加し、1 つのサブセットをチェックするだけでも順序付けと制約の検証が必要になります。 N が 500 までの場合、これは完全に不可能です。 

重要な観察は、選択した点の順序を時間で固定すると、実行可能条件がローカルになるということです。つまり、選択した 2 つの連続するイベント間で、利用可能な時間枠内で線が 1 つの選択した角度から別の角度に回転する必要があります。 この制約は、構造の残りの部分ではなく、これら 2 つのイベントのみに依存します。

これにより、時間順序と角度の実現可能性によって定義される有向非巡回構造内の最長の有効なチェーンを選択するという問題が軽減されます。 固定 K の場合、動的計画法を使用してイベントを時間順に並べ替え、最長のチェーンを計算します。選択した角度バリアント間の角度差が時間差の最大 K 倍である場合、i から j への遷移が許可されます。 

実現可能性は K において単調であるため、少なくとも M 以上の長さのチェーンを許可する最小 K を二分探索できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース サブセット | O(2^N・N) | O(N) | 遅すぎる |
 | DP + 二分探索 | O(N² log R) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### ステップ 1: ジオメトリを角度と時間に変換する

 各点について、点が平面に到達する時間を t_i = Z_i / U_i として計算します。 また、その方向角 θ_i = atan2(Y_i, X_i) を計算します。 線には方向がないため、各イベントでは 2 つの有効な角度 θ_i と θ_i + π が許可されます。 

これにより、問題は、それぞれ 2 つの可能な角度状態を持つタイムライン上のイベントを選択することに変換されます。 

### ステップ 2: イベントを時間順に並べ替える

 t_i を増加させてすべてのイベントを並べ替えます。 ポイントがアクティブになったときにのみポイントをヒットできるため、有効なヒット シーケンスはすべてこの順序を尊重する必要があります。 

### ステップ 3: 固定 K の実現可能性チェック

 角速度 K の候補について、少なくとも M 個のイベントの有効なチェーンを構築できるかどうかを確認します。 

dp[i] を、イベント i で終了するヒットできるイベントの最大数として定義します。 

### ステップ 4: 移行ルール

 すべてのペア i < j について、i を j に接続することを検討します。 角度選択のすべての組み合わせ (i に 2 つ、j に 2 つ) を試します。 移行は次の場合に有効です。 

|角度_i − 角度_j| ≤ K · (t_j − t_i)

 有効な場合、 dp[j] = max(dp[j], dp[i] + 1) を更新できます。 

これは、線が利用可能な時間内にこれら 2 つの方向の間で物理的に回転する必要があるという事実をエンコードします。 

### ステップ 5: 最適なチェーンの長さを計算する

 すべてのイベントの dp を計算します。 max(dp[i]) ≥ M の場合、K で十分です。 

### ステップ 6: 二分探索 K

 十分に広い範囲にわたって K を二分探索します。 上限は、任意の高速回転を可能にする値として選択できます。 実際には、実現可能性テストには 1e7 以上で十分です。 各小切手のコストは O(N²) です。 

### なぜ効果があるのか

 DP の不変条件は、dp[i] が回転制約の下で i で終了する最良の有効なチェーンを格納することです。 有効なチェーンは時間順序を尊重する必要があるため、有効なソリューションのすべてのプレフィックスも有効であり、DP 状態空間に表示されます。 遷移条件は、選択された連続ヒット間の物理的な到達可能性を正確に強制するため、無効なチェーンが構築されることはなく、すべての有効なチェーンは遷移のシーケンスを通じて再構築されます。 

## Python ソリューション```python
import sys
import math
input = sys.stdin.readline

def can(K, pts, M):
    n = len(pts)
    dp = [1] * n
    
    for i in range(n):
        xi, yi, ti = pts[i]
        ai = math.atan2(yi, xi)
        ai2 = ai + math.pi
        
        for j in range(i + 1, n):
            xj, yj, tj = pts[j]
            dt = tj - ti
            if dt < 0:
                continue
            
            aj = math.atan2(yj, xj)
            aj2 = aj + math.pi
            
            best = dp[j]
            
            for a in (ai, ai2):
                for b in (aj, aj2):
                    diff = abs(a - b)
                    diff = min(diff, 2 * math.pi - diff)
                    if diff <= K * dt + 1e-12:
                        best = max(best, dp[i] + 1)
                        break
            
            dp[j] = best
    
    return max(dp) >= M

def solve():
    n, m = map(int, input().split())
    pts = []
    
    for _ in range(n):
        x, y, z, u = map(int, input().split())
        t = z / u
        pts.append((x, y, t))
    
    pts.sort(key=lambda p: p[2])
    
    if m == 1:
        print(0.0)
        return
    
    lo, hi = 0.0, 1e7
    
    ans = -1
    for _ in range(60):
        mid = (lo + hi) / 2
        if can(mid, pts, m):
            ans = mid
            hi = mid
        else:
            lo = mid
    
    if ans < 0:
        print(-1)
    else:
        print(f"{ans:.10f}")

if __name__ == "__main__":
    solve()
```このソリューションでは、まず各ポイントを時間と角度のペアに変換し、次に時間順に並べ替えて、すべての遷移が時間内に進むようにします。 実現可能性チェックでは、動的プログラミングを使用して互換性のある最長のシーケンスを構築し、角速度制約の下ですべての有効なペアごとの遷移をテストします。 最後に、二分探索により最小 K が厳しくなります。 

微妙な実装の詳細は、角度のラップアラウンドの処理です。 角度は円形であるため、直接の差の最小値と 2π 付近の補数を使用して差を計算する必要があります。 

二分探索は実現可能性が単調であるため安定しています。K を増加しても制約が緩和されるだけです。 

## 実用的な例

 ### サンプル 1

 時間を計算し、到着時間ごとにポイントを並べ替えます。 次に、K を増加させてテストします。K が十分に大きい場合、すべての遷移が実行可能になり、5 つの点すべてを連鎖させることができます。 

| ステップ | イベント i | dp[i] | 理由 |
 | --- | --- | --- | --- |
 | 初期化 | すべて | 1 | それぞれの点だけ |
 | トランジション | 複数 | 増加する | すべてのペアは K = 90 で互換性があります |

 最終チェーンは長さ 5 に達するため、K = 90 で十分です。 

これは、点が角度的に十分に分散されている場合、制約は純粋に時間ギャップ間の回転速度に関するものであることを示しています。 

### サンプル 2

 ここでは 2 点のみが存在し、両方を取得する必要があります。 それらの角度は適度に離れており、それらの時間は回転制約が厳しいほど十分に近いです。 

| ステップ | イベント i | イベント j | dt | 角度差 | 実現可能 |
 | --- | --- | --- | --- | --- | --- |
 | チェック | 1 | 2 | 小さい | 中程度 | しきい値 K を超える場合のみ |

 これは、核となる依存関係を示しています。2 つの点だけであっても、K は時間差に対する角距離によって決定されます。

 ## 特殊なケース

 主なエッジ ケースは、2 つのポイントが非常に近い時間に到着するが、ほぼ逆の方向を必要とする場合です。 その場合、必要な K は非常に大きくなり、DP は角度ジャンプを吸収するのに十分な時間差がある場合にのみ正しく遷移を許可します。 

もう 1 つのケースは、複数のポイントが同じ到着時間を共有する場合です。 dt がゼロになるため、同じ有効な角度を持つペアのみをチェーンできます。 それ以外の場合、回転する時間が存在しないため、K に関係なく遷移は無効になります。 

最後に、M = 1 の場合は、回転がまったく必要なく、線がすでに固定角度で始まっているため、常に 0 を返します。
