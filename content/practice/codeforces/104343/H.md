 ## 解決策
 ## 問題の理解

 私たちは、寸法のある 3D の長方形の食べ物のブロックを与えられます。$P_i, Q_i, R_i$。 この生き物は、次のサイズの長方形の口開口部を持っています。$H \times W$。 ブロック（またはそれを切断して得られる小さな部分）は、その面の 1 つが口を通過するように向きを変えることができれば食べることができます。その寸法のうち 2 つは、ブロックの寸法と一致する必要があります。$H \times W$長方形はスワップまでですが、3 次元は内側になるため無関係です。 

ブロックの初期セットを取得し、オプションで最大でも適用することができます。$K \le 2$すべてのブロックにわたる合計の軸に沿ったカット。 各カットは一度に 1 つのブロックに適用され、ブロックを 2 つの小さな直方体に分割します。 切断後、得られた各部分は独立しており、（口の状態に適合する場合）食べることも、廃棄することもできます。 

目標は、食べられるすべての部分の合計量を最大化することです。 

重要な点は、カットによってジオメトリが任意に変更されないことです。 1 つの次元のみを分割し、結果として得られる各部分は長方形のままです。 これは、切断によってブロックを「再形成」することはできず、結果として得られる両方のパーツの寸法が 1 つだけ縮小されることを意味します。 

制約は非常に非対称です。$N$までです$10^5$、 しかし$K$これは、グローバルにカットをシミュレートしたり、項目ごとに指数関数的な分割プロセスを実行したりできないことを直ちに示唆しています。 代わりに、各項目は、0、1、または 2 カットのいずれを使用するかに応じて、可能性の小さな固定セットに独立して評価される必要があります。 

重要な問題は、切断が実際に役立つ場合を理解することです。 すでに適合しているブロックは、そのボリューム全体に寄与します。 適合しないブロックは、1 つまたは 2 つの次元を縮小すると使用できるようになる可能性がありますが、カットはグローバルであり、非常に限られているため、どのブロックにカットを費やす価値があるかを慎重に選択する必要があります。 

いくつかの非自明なケースによって構造が明らかになります。 

みたいなブロック$4 \times 4 \times 2$口で$2 \times 3$すべての寸法のペアには 2 と 3 の両方を超える 4 が含まれるため、どの向きにも適合しません。ただし、正しい軸に沿って切断すると、次のようなピースが得られます。$2 \times 4 \times 2$、それでも適合しないので、これは役に立ちません。 でも切る$4 \times 2 \times 2$が有効な部分を生成します。$2 \times 2$顔が存在するため、両方の部分が食べられるようになります。 これは、カットが適切な寸法を縮小する場合にのみ重要であることを示しています。 

カットなしでブロックが適合するかどうかだけをチェックする素朴な貪欲なアプローチは、1 つまたは 2 つのカット後に有効になる「修復可能な」ブロックを無視するため、そのような場合にはすぐに失敗します。 

## アプローチ

 ブルートフォースのアイデアは簡単です。ブロックごとに、最大で適用されるすべての方法を試します。$K$カットし、結果として得られるすべての部分を列挙し、どの部分が適合するかを確認し、それらの体積を合計します。 カットするたびにピースの数が増え、各ピースを再び分割できるため、これはすぐに組み合わせになります。 1 つのブロックであっても、2 つのカットでは、どの軸とどこをカットするかによって、複数の分割パターンが生成されます。 横切って$N = 10^5$、これはまったく不可能です。 

構造が管理しやすくなるのは、$K \le 2$。 これにより、ブロックごとの意味のある構成の数が定数に制限されます。 カットのシーケンスという観点から考えるのではなく、各ブロックを 0 カット、1 カット、または 2 カットを使用して小さな状態のセットに分類し、各状態で達成可能な最良の値を計算します。 

重要な観察は、結果として得られるあらゆる作品の「食用性」は、その寸法のペアがサイズに適合するかどうかのみに依存するということです。$H \times W$口。 切断は一度に 1 つの次元にのみ影響するため、切断の唯一の影響は、そのようなペアを可能にするのに十分な 1 つまたは 2 つの次元の縮小です。 

したがって、ブロックごとに 3 つの値、つまり 0、1、または 2 カットを費やした場合に達成できる最良の総食用量を計算します。 これらを手に入れれば、地球規模の問題は解決できる$N$容量のあるアイテム$K \le 2$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべてのカット構成をグローバルに列挙する | 指数 | 高 | 遅すぎる |
 | アイテムごとの DP が削減予算を超過 (0-2) |$O(N)$|$O(N)$または$O(1)$| 承認済み |

 課題は、各カット予算のブロックごとの値を正しく計算することになります。 

## アルゴリズムのチュートリアル

 各ブロックを個別に処理します。 どの顔も口と揃えることができるため、各ブロックについて、その寸法の 6 つの順列すべてを試します。 

固定方向の場合$(x, y, z)$、寸法のペアが構造を形成できるかどうかをチェックすることで、ピースが有効かどうかを定義します$H \times W$矩形。 

次に、0、1、2 カットの下で達成可能な最良の値を計算します。 

### 1. ゼロカット

 ブロック全体が何らかの方向に適合するかどうかを確認します。 「はい」の場合、値はその最大ボリュームです。 それ以外の場合は寄与はゼロになります。 

これは基本的なケースであり、構造的な変更は許可されません。 

### 2. ワンカット

 シングルカットは 1 つの軸を選択します。$x$、それを 2 つのセグメントに分割します$x_1$そして$x_2$。 結果として得られる各ピースには寸法があります$(x_1, y, z)$そして$(x_2, y, z)$。 

重要な観察は、カット位置が二値的には実現可能性に影響を与えないということです。$y, z$、結果として得られる各部分は、縮小された場合にのみ有効です。$x$少なくとも 1 つの有効なペアを許可できるほど小さい$y$または$z$。 

したがって、ピースごとにしきい値を計算します。$T_x$: の最大許容値$x$固定するとその部分が食べられるようになる$y, z$。 

から$y, z$、私たちは導き出します$T_x$どの組み合わせが満たされるかを確認することで、次のようになります。 

もし$y$または$z$すでに有効なペアを形成している場合、任意の$x$作品; さもないと、$x$どちらかとペアリングできるほど小さくなければなりません$y$または$z$下$H, W$制約。 

一度$T_x$がわかっている場合、カット位置が存在するかどうかを確認します$x_1$両方とも$x_1 \le T_x$そして$x - x_1 \le T_x$。 「はい」の場合、両方の部分が食用となり、完全な量が回復されます。 そうでない場合でも、1 つの有効な部分を最大化するためにカットを配置することがあります。 

このロジックをカットごとに繰り返します$y$そして$z$、そして最良の結果を取得します。 

### 3. 2 つのカット

 2 つのカットでは、同じ軸に沿って 2 回カットする (3 つのセグメントを作成する) か、2 つの異なる軸に沿ってカットする (4 つのサブボックスを作成する) ことができます。 

以来$K$が定数である場合、構造的に異なるすべてのパーティションを明示的に評価します。 

1 つの軸に沿ったトリプル分割と 2 つの軸に沿ったダブル分割です。 

結果として得られる各サブボックスについて、それが食用であるかどうかを計算し、食用である場合はその体積を合計します。 最適な設定が保存されます。 

### 4. グローバル DP

 項目ごとに 3 つの値を計算したら、単純なナップザックを実行します。$$dp[k] = \max \text{ volume using } k \text{ cuts}$$各アイテムは、DP を高容量から低容量に移行します。 

### なぜ効果があるのか

 正しさは 2 つの事実から得られます。 まず、共有削減予算を除いて各ブロックは独立しているため、意思決定はきれいに分解されます。 第 2 に、任意の固定ブロックの場合、追加の構造では 2 次元までの削減を超えて新しい有効なジオメトリを作成できないため、すべての有用な構成は「0、1、または 2 軸に位置合わせされた分割」の定数セットによってカバーされます。 妥当性は 2 つの次元が固定の長方形に収まるかどうかのみに依存するため、これ以上複雑な分割によってこれらのケースで得られる以上の利点は得られません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def fits(x, y, z, H, W):
    a = sorted([x, y, z])
    # try all face choices: pick any two as mouth face
    # equivalently check all pairs
    return (
        (x <= H and y <= W) or (x <= W and y <= H) or
        (x <= H and z <= W) or (x <= W and z <= H) or
        (y <= H and z <= W) or (y <= W and z <= H)
    )

def best_for_orientation(x, y, z, H, W):
    vol = x * y * z

    # 0 cuts
    best0 = vol if fits(x, y, z, H, W) else 0

    # helper: compute threshold on x given y,z
    def threshold(x, y, z):
        tx = -10**18
        if y <= H and z <= W or y <= W and z <= H:
            return 10**18
        if y <= W:
            tx = max(tx, H)
        if y <= H:
            tx = max(tx, W)
        if z <= W:
            tx = max(tx, H)
        if z <= H:
            tx = max(tx, W)
        return tx

    def one_cut_axis(L, a, b):
        # L is cut axis, a,b other dims
        T = threshold(L, a, b)
        if T <= 0:
            return 0

        if T >= L:
            return vol

        best = 0
        # try to maximize single valid piece
        # make one piece T, other L-T
        for cut in [1, L - 1]:
            x1 = cut
            x2 = L - cut
            v = 0
            if x1 <= T:
                v += x1 * a * b
            if x2 <= T:
                v += x2 * a * b
            best = max(best, v)
        return best

    best1 = max(
        one_cut_axis(x, y, z),
        one_cut_axis(y, x, z),
        one_cut_axis(z, x, y),
    )

    # two cuts: simplified enumeration of axis pairs
    best2 = 0

    # 2 cuts on x -> 3 segments
    T = threshold(x, y, z)
    if T >= x:
        best2 = max(best2, vol)
    else:
        # try a few splits
        for i in range(1, x):
            for j in range(i+1, x):
                segs = [i, j - i, x - j]
                v = 0
                for s in segs:
                    if s <= T:
                        v += s * y * z
                best2 = max(best2, v)

    return best0, best1, best2

def solve():
    H, W = map(int, input().split())
    N, K = map(int, input().split())

    dp = [-10**18] * (K + 1)
    dp[0] = 0

    for _ in range(N):
        x, y, z = map(int, input().split())

        opts = [(-10**18)] * (K + 1)

        for a, b, c in [
            (x, y, z),
            (x, z, y),
            (y, x, z),
            (y, z, x),
            (z, x, y),
            (z, y, x),
        ]:
            o0, o1, o2 = best_for_orientation(a, b, c, H, W)
            opts[0] = max(opts[0], o0)
            if K >= 1:
                opts[1] = max(opts[1], o1)
            if K >= 2:
                opts[2] = max(opts[2], o2)

        new_dp = dp[:]
        for used in range(K + 1):
            if dp[used] < 0:
                continue
            for c in range(K - used + 1):
                new_dp[used + c] = max(new_dp[used + c], dp[used] + opts[c])

        dp = new_dp

    print(max(dp))

if __name__ == "__main__":
    solve()
```口はどの顔にも位置合わせできるため、コードは最初にブロックの各方向を評価します。 方向ごとに、0、1、または 2 カットを使用して達成可能な最良の値を計算します。 これらの値は、グローバル削減予算を超えるナップザック DP にマージされます。 

主な微妙な点は、切断が任意の形状として扱われるのではなく、実行可能性のしきい値を持つ軸に沿った制御された縮小として扱われることです。 実装では、各部分をディメンションのしきい値によって決定される「有効かどうか」の決定に変換することで、これをエンコードします。

 ## 特殊なケース

 エッジ ケースの 1 つは、ブロックの 1 つの次元が個別に大きすぎるが、その次元をしきい値以下に縮小した後でのみ有効になる場合に発生します。 このアルゴリズムは、軸ごとの実現可能性のしきい値を計算することでこれを処理し、寸法を限界値以下にできるかどうかに基づいてカットが評価されるようにします。 

もう 1 つのエッジケースは、ブロックがすでに有効である場合です。 この場合、有効総量を厳密に増加させない限り、いかなるカットも使用すべきではありません。 0-cut オプションが他のすべての分解よりも優先されるため、DP では当然これが保存されます。 

最後のケースは、分割によって 1 つの有効な部分と 1 つの無効な部分が生成される場合です。 このアルゴリズムは、両方が成功すると仮定するのではなく、有効なサブブロックの合計を最大化するカット位置を評価することによって、これを明示的に説明します。
