 ## 解決策
 ## 問題の理解

 タスクは長方形のグリッドを中心に構築されており、各セルは負でない値を提供するか、空の地面を表します。 「湖」は、対角線ではなく共有エッジを介して接続され、同じ意味のある領域に属するセル (通常は空でないセル) をグループ化することによって形成されます。 このような各領域には、その中のすべての数値を合計することによって得られる合計値があります。 目標は、これらすべての湖の中で最大の合計値を決定することです。 

グラフ用語では、すべてのセルはノードと見なされ、直交する隣接セル間にエッジが存在します。 その後、グリッドは暗黙的なグラフになり、接続されたコンポーネントを見つけて各コンポーネントの重みを計算するように求められます。 

制約が十分に大きいため、訪問したセルをマークせずに単純にフラッド フィルを繰り返すと、各セルを最大 1 回処理する必要があるため、時間がかかりすぎます。 複数の検索にわたってセルを再検討するソリューションは、グリッド サイズの二次的な動作にまで低下します。これは、10^6 セルのような一般的な制限では受け入れられません。 

いくつかの特殊なケースは見落とされがちです。 1 つは、グリッドに空のセルのみが含まれている場合で、通常の意味では湖が存在せず、答えはゼロになるはずです。 

たとえば、次のようなグリッドです。```
0 0
0 0
```累積する正の領域がないため、答えは 0 になります。 

もう 1 つのケースは、すべてのセルが単一の接続されたレイクの一部である場合です。```
1 2
3 4
```ここでは、グリッド全体が 1 つのコンポーネントを形成しており、答えは 10 である必要があります。各セルを個別に扱う不注意な実装では、誤って 4 が返され、接続を適切にマージできません。 

3 番目の微妙なケースは、複数の接続されていない湖が存在し、その数や構造ではなく最大の湖のみが問題となる場合です。```
1 0 2
1 0 2
```これには合計が 2 と 4 の 2 つの別々の湖が含まれているため、正解は 4 です。 

## アプローチ

 直接的なアプローチは、すべてのセルを湖の潜在的な開始点として扱い、セルがゼロではなく未訪問である場合は常に、そこからフラッド フィルまたは深さ優先検索を実行することです。 各フラッド フィルでは、到達可能なすべてのセルが調査され、それらの値が合計されます。 

これは、接続性を考慮しているため、正しいです。すべてのセルは、正確に 1 つの最大接続コンポーネントに属しており、そのコンポーネント内の未訪問のセルから開始するフラッド フィルにより、そのすべてが検出されます。 

ただし、訪問された構造なしで実装された場合、同じ領域が複数の開始点から繰り返し探索されることになります。 グリッドがすべて満たされている最悪のケースでは、各 DFS がほぼグリッド全体を横断する可能性があり、約 O((nm)^2) の操作が必要になります。 それは実現可能な限界をはるかに超えています。 

重要な点は、各セルの処理が必要なのは 1 回だけであるということです。 コンポーネントに割り当てられた後は、決して再アクセスしてはなりません。 これにより、問題はグリッド上の標準的な接続コンポーネントの走査に変わります。 訪問先アレイで DFS または BFS を使用すると、セル数の直線的な複雑さが確保されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 訪問なしのブルートフォースフラッドフィル | O((nm)^2) | お(1) | 遅すぎる |
 | 訪問先配列を含むグリッド DFS/BFS | O(nm) | O(nm) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. グリッドの寸法とグリッドの値を読み取ります。 各セルは、関連付けられた重みを持つノードとして扱われます。 
2. ブール行列を維持する`visited`グリッドと同じサイズです。 これにより、処理されたレイクに既に属しているセルを再訪問することができなくなります。 
3. グリッド内のすべてのセルを繰り返します。 セルの値が 0 であるか、すでに訪問されている場合は、新しいレイクを開始できないか、すでに考慮されているため、セルをスキップします。 
4. 未訪問の非ゼロ セルが見つかった場合は、スタックまたはキューを使用してそこからフラッド フィルを開始します。 現在の合計をその値で初期化します。 この合計は、現在の湖の合計値を表します。 
5. フラッドフィル中にセルをポップし、その 4 つの隣接セルを調べます。 各近傍について、それがグリッド内にあり、未訪問で、ゼロでない場合は、訪問済みとしてマークし、その値を現在の合計に追加してから、スタックまたはキューにプッシュします。 これにより、接続されたコンポーネントを 1 回だけ完全に探索できるようになります。 
6. フラッドフィルが終了したら、計算された合計をこれまでに確認された最良の答えと比較し、最大値を維持します。 

正確性は、すべての接続コンポーネントがそのセルの 1 つから 1 回だけ入力され、到達可能なすべてのセルを省略や重複なく含むようにトラバーサルが拡張されるという事実に依存します。 

### なぜ効果があるのか

 訪問された配列により、グリッドが結合されていない探索領域に分割されます。 各フラッド フィルは、4 方向の隣接関係にある 1 つの接続コンポーネント上でのみ動作します。 隣接関係は対称であるため、開始セルから到達可能なセルはすべて同じコンポーネントの一部である必要があり、そのコンポーネント内のすべてのセルは、そのコンポーネント内の他のセルから到達可能です。 これにより、トラバーサルがコンポーネントの外部に漏れたり、内部セルを見逃したりしないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    grid = [list(map(int, input().split())) for _ in range(n)]

    visited = [[False] * m for _ in range(n)]
    directions = [(1, 0), (-1, 0), (0, 1), (0, -1)]

    best = 0

    for i in range(n):
        for j in range(m):
            if grid[i][j] == 0 or visited[i][j]:
                continue

            stack = [(i, j)]
            visited[i][j] = True
            current_sum = 0

            while stack:
                x, y = stack.pop()
                current_sum += grid[x][y]

                for dx, dy in directions:
                    nx, ny = x + dx, y + dy
                    if 0 <= nx < n and 0 <= ny < m:
                        if not visited[nx][ny] and grid[nx][ny] != 0:
                            visited[nx][ny] = True
                            stack.append((nx, ny))

            best = max(best, current_sum)

    print(best)

if __name__ == "__main__":
    solve()
```The solution uses an iterative DFS to avoid recursion depth issues that can arise in large grids. の`visited`行列は、ノードがポップされたときではなく、ノードがスタックにプッシュされた瞬間に更新されるため、同じセルが複数回挿入されることがなくなります。 

ランニングサムはポップ中に累積されますが、プッシュ中に累積されることもあります。 各セルが正確に 1 回カウントされる限り、両方とも同等です。

 | 測定 | 複雑さ | 説明 |

 ## 特殊なケース

 非ゼロ セルを含まないグリッドは、フラッド フィル ループに入らないように処理されます。 以来`best`がゼロに初期化されると、出力はゼロのままとなり、評価するレイクが存在しないという考えと一致します。 

完全に塗りつぶされたグリッドは、1 つの接続されたコンポーネントとして処理されます。 アルゴリズムは DFS に一度入り、訪問したすべてのセルにマークを付けます。これにより、探索の繰り返しが防止され、二次爆発ではなく線形実行時間が保証されます。 

ゼロが交互に並ぶ高度に断片化されたグリッドにより、外側のループで多数の小さな DFS 呼び出しが確実にトリガーされますが、すべてのセルが 1 つのコンポーネントにのみ割り当てられ、再訪されることがないため、各呼び出しはセルごとに一定の償却作業となります。
