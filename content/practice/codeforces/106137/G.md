 ## 解決策
 ## 問題の理解

 ルートが頂点である根付きツリーがあります。`1`。 すべての頂点には、黒または白の 2 つの色のいずれかが割り当てられます。 各頂点について、その頂点から始まり、頂点自体を含むその頂点のすべての子孫を含むサブツリーを考慮します。 サブツリー内の黒い頂点の数がその中の白い頂点の数とまったく同じである場合、そのサブツリーはバランスが取れていると呼ばれます。 タスクは、バランスのとれたサブツリーを持つ頂点の数を数えることです。 

入力は、親ポインターを通じてツリーを記述します。 すべての頂点に対して、`2`に`n`、その親が与えられますが、それは常に小さい番号の頂点です。 カラー文字列は、各頂点の色を順番に指定します。 

この制約が、ソリューションが単一ツリーの走査に基づく必要がある主な理由です。 すべてのテスト ケースの頂点の合計数は最大で`2 * 10^5`、だから、`O(n)`または`O(n log n)`アプローチが快適です。 すべてのサブツリーを繰り返し探索するソリューションは、チェーン形状のツリーによってサブツリー サイズの合計が次の値に達する可能性があるため、遅くなりすぎます。`O(n^2)`、それは周りにあります`4 * 10^10`大きな入力に対する操作。 

主なエッジ ケースは、サブツリーのサイズと色数が各頂点にローカルであることが原因で発生します。 

ルートの他に頂点が 1 つあるツリーを考えてみましょう。```
2
1
BW
```ルート サブツリーには黒の頂点と白の頂点が 1 つずつ含まれているため、答えは次のようになります。`1`。 葉だけをチェックする不注意な解決策では、根を見逃してしまいます。 

別のケースは次のとおりです。```
3
1 1
BBB
```すべてのサブツリーには黒い頂点のみが含まれているため、答えは次のようになります。`0`。 サブツリーのサイズと色数のみを比較し、色の寄与を忘れたソリューションでは、不正確な結果が生成されます。 

最後の境界ケースはチェーンです。```
4
1 2 3
BWBW
```サブツリーには下から上に次のものが含まれます。```
vertex 4: B
vertex 3: WB
vertex 2: BWB
vertex 1: BWBW
```頂点のみ`1`そして`3`バランスがとれているので、答えは`2`。 子より前に親を処理する実装では、不完全な情報が使用され、この構造で失敗する可能性があります。 

## アプローチ

 直接的なアプローチは、すべての頂点から DFS を開始することです。 選択した頂点の DFS 中に、そのサブツリー内の黒と白の頂点をカウントし、2 つのカウントが等しいかどうかを確認します。 これは正しいです。なぜなら、各頂点はバランスの取れたサブツリーの正確な定義に対して個別にチェックされるからです。 

問題は繰り返し作業です。 の連鎖の中で`n`頂点、頂点のサブツリー`1`もっている`n`頂点、頂点のサブツリー`2`もっている`n-1`頂点など。 訪問した頂点の総数は次のようになります。```
n + (n - 1) + (n - 2) + ... + 1 = O(n^2)
```のために`n = 200000`、これは制限時間内に実行できる限界をはるかに超えています。 

ツリー構造はより良い方法を提供します。 頂点のサブツリーは、まさにその子のサブツリーと頂点自体の結合です。 頂点のすべての子の処理が完了すると、その頂点のカラー バランスを計算するために必要なすべてがすでにわかっています。 

2 つの別々のカウントを保存する代わりに、1 つの値を保存できます。 黒人に貢献させよう`-1`そして白も貢献する`+1`。 黒と白の頂点の数が等しい場合、サブツリーの合計は正確にゼロになります。 ポストオーダー DFS は、頂点ごとにこの合計を計算し、合計がゼロになるたびに答えを増分します。 

ブルートフォース手法は、各サブツリーの色数を繰り返し再構築するため機能します。 すべてのサブツリーがすでに処理された子サブツリーから構築されているという観察により、その情報を再利用し、問題を 1 回の走査に減らすことができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 親配列から子の隣接リストを作成します。 サブツリー情報は下から上に収集されるため、各頂点はその直接の子にアクセスするだけで済みます。 
2. DFS をルートから実行します。 現在のサブツリーはその子孫の計算済みの値に依存するため、現在の頂点を処理する前にすべての子を完了する必要があります。 
3. 頂点の場合`u`、バランスを開始します`+1`それが白であれば、`-1`黒なら。 次に、すべての子頂点によって返されたバランスを追加します。 
4. すべての子を結合した後、バランスが取れているかどうかを確認します。`u`はゼロです。 存在する場合、そのサブツリーは、`u`には同じ数の黒と白の頂点が含まれているため、答えを増やします。 
5. 計算された残高を返します。`u`その親に。 親は、この値を独自のサブツリー計算の一部として使用します。 

なぜ効果があるのか:

 不変条件は、DFS が頂点を終了した後、`u`、戻り値は、サブツリー内の白と黒の頂点の差です。`u`。 基本的な貢献度`u`は独自の色を表し、すべての子はそのサブツリーのすでに正しい差分を提供します。 サブツリー全体は頂点自体にすべての子サブツリーを加えたものであるため、計算された合計は正確です。 この差がゼロの場合、サブツリーは正確にバランスが取れているため、すべてのバランスのとれたサブツリーは 1 回カウントされ、アンバランスのサブツリーはカウントされません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        children = [[] for _ in range(n)]

        parents = list(map(int, input().split()))
        for i, p in enumerate(parents, start=1):
            children[p - 1].append(i)

        s = input().strip()

        ans = 0
        balance = [0] * n

        stack = [(0, 0)]
        order = []

        while stack:
            u, state = stack.pop()
            if state == 0:
                stack.append((u, 1))
                for v in children[u]:
                    stack.append((v, 0))
            else:
                order.append(u)

        for u in order:
            cur = 1 if s[u] == 'W' else -1
            for v in children[u]:
                cur += balance[v]

            balance[u] = cur
            if cur == 0:
                ans += 1

        out.append(str(ans))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```入力は子隣接リストに変換されます。 頂点には内部的に 0 から番号が付けられるため、トラバース中に繰り返し 1 を減算する必要がなくなります。 

反復 DFS によりポストオーダー シーケンスが作成されます。 再帰的 DFS も可能ですが、Python の再帰の深さは長いチェーンのツリーには小さすぎます。 明示的なスタックは、最大の深さを安全に処理しながら再帰をシミュレートします。 

の`order`リストには、すべての子孫が追加された後の頂点が含まれます。 このリストを左から右に処理すると、事後 DFS と同じ効果が得られます。 頂点が処理されるまでに、すべての子はすでに最終的なバランスを持っています。 

に保存されている値`balance[u]`サブツリー全体の色の違いです。 使用する`+1`そして`-1`2 つのカウンタを保存することを回避し、平衡状態を単純なゼロ比較にします。

 ## 特殊なケース

 最小の平衡型ケースの場合:```
2
1
BW
```DFS は最初に頂点を処理します`2`。 そのバランスは、`-1`, そのためカウントされません。 ルートはその値を受け取り、独自の値を追加します`+1`、生産`0`。 答えは次のようになります`1`。 

すべての頂点が同じ色を持つ木の場合:```
3
1 1
BBB
```それぞれの葉が戻ってきます`-1`。 ルートは子とそのルートの両方を結合します`-1`、 その結果`-3`。 バランス ゼロに到達する頂点がないため、アルゴリズムは次のように出力します。`0`。

BWBW
```トラバースは頂点を終了します`4`まず、それから`3`、 それから`2`、 それから`1`。 彼らの残高は、`-1`、`0`、`-1`、 そして`0`それぞれ。 答えは`2`、そしてこの例では、アルゴリズムが親の処理前に子結果の準備ができていることに依存していることを確認しています。
