 ## 解決策
 ## 問題の理解

 このタスクは、指定された正の整数から最小桁数を削除して、残りの桁が 25 で割り切れる数値を形成することです。桁を削除すると数値を並べ替えることができないため、残りの桁の順序は同じままでなければなりません。 答えは必要な削除の最小数であり、結果として割り切れる数ではありません。 

数値は、最後の 2 桁が次のいずれかである場合、正確に 25 で割り切れます。`00`、`25`、`50`、 または`75`。 数字を削除しても最後に表示される数字が変更されるだけであるため、このプロパティが重要です。 全体の数を構築しようとするのではなく、これら 4 つのエンディングの 1 つにどれだけ近づけるかを見つけるだけで済みます。 

入力は数値の 10 進表現であるため、重要なパラメーターはその長さです。 文字列は整数に変換せずに直接処理できます。 これにより、非常に大きな値に関する問題が回避され、アルゴリズムが桁数に比例した状態に保たれます。 長さが長い場合、多くの可能な削除を試みたり、多数の候補番号を生成したりするアプローチはすぐに実用的ではなくなります。 各桁を一定の回数だけ検査する必要があるため、リニア スキャンで十分です。 

いくつかの特殊なケースでは、不用意なソリューションが壊れる可能性があります。 番号がすでに有効なペアで終わっている場合は、削除する必要はありません。 たとえば、入力`100`出力があります`0`、 なぜなら`100`はすでに 25 で割り切れます。常に少なくとも 1 桁を削除するソリューションは、ここでは失敗します。 

数値には、最後のペアの前に多くのゼロを含めることができます。 例えば、`1000`出力があります`0`、 ない`2`、最後の 2 桁が次のとおりであるため、`00`。 探すだけの迂闊なアプローチ`25`有効なエンディングを見逃す可能性があります。 

有効なペアは、削除する必要がある数字で区切られている場合があります。 例えば、`71345`出力があります`2`、削除するため`1`そして`3`葉`745`、最後の 2 桁は`45`, したがって、この例では十分ではありません。 役立つ正しい例は次のとおりです`71375`、削除するところ`1`そして`3`葉`775`、余分なものを削除します`7`代わりに与える`75`、必要な`3`削除。 左から最初に一致する数字のみを検索する貪欲な方法では、間違った出現箇所が選択され、間違った答えが生成される可能性があります。 

最小の入力にも注意が必要です。 例えば、`7`有効な終了ペアを含めることはできません。 答えは、結果の数値の解釈を除いて桁がなくなるまで削除する必要がある桁数です。 この問題の標準的な解決策は、有効な 2 桁の末尾を見つけることを目標として扱い、文字列の長さを返すことによって不可能なケースを処理します。 

## アプローチ

 ブルートフォースの考え方は、削除された数字の可能なすべてのセットを試し、残った数字を保持し、結果の数値が 25 で割り切れるかどうかを確認することです。これは、考えられるすべての最終的な数値を調査するため、正しいです。 ただし、長さのある文字列`n`もっている`2^n`したがって、最悪のケースでは、指数関数的な数の候補をチェックする必要があります。 たとえ数十桁であっても、これでは遅すぎます。 

25 で割り切れる構造により、検索スペースが大幅に小さくなります。 最後の 2 桁は、その数値が 25 で割り切れるかどうかを完全に決定します。末尾は 4 つだけです。`00`、`25`、`50`、 そして`75`。 各語尾について、元の文字列内で、それらの間とその後の数字を削除した後の最後の 2 桁となる 2 桁を見つけるだけで済みます。 

この総当たり法は、考えられるすべての最終数値を考慮するため機能しますが、それらの選択のほとんどが無関係であるため失敗します。 最後の 2 桁のみが重要であるという観察により、すべてのサブシーケンスの検索を、可能な 4 つの数字ペアの検索に置き換えることができます。 文字列の末尾からスキャンして各ペアの 2 番目の桁を見つけてから、その前の最初の桁を見つけることができます。 削除の数は、2 桁目以降および選択した 2 桁の間に何桁あるかによって決まります。

 ## アルゴリズムのチュートリアル

 1. 25 で割り切れる数値の 4 つの可能な末尾を保存します。`00`、`25`、`50`、 そして`75`。 
2. 各語尾について、右から左に 2 桁目を検索します。 2 番目の桁は答えの最後の桁になる必要があるため、できるだけ右端の位置を選択すると、その後に削除される桁が最小限に抑えられます。 
3. 2 番目の桁を見つけたら、左に向かって末尾の 1 番目の桁を検索し続けます。 削除しても元の順序が保持されるため、最初の数字は 2 番目の数字より前に指定する必要があります。 
4. 末尾の両方の数字が見つかった場合は、削除を計算します。 2 番目に選択した数字以降のすべての数字を削除する必要があり、選択した 2 つの数字の間のすべての数字も削除する必要があります。 
5. 4 つのエンディングすべてから最小の削除数を取得します。 エンディングが形成できない場合は無視してください。 

この貪欲な検索が有効である理由は、固定終了の場合、選択した数字のいずれかをさらに右に移動しても、削除の数を減らすか維持することしかできないためです。 可能な限り右端の 2 番目の桁は、削除する後続の桁を最小限に残し、その前の可能な右端の最初の桁は、削除する必要のある中間桁を最小限に残します。 

なぜ効果があるのか:

 有効な最後の数値はすべて、許可される 4 つのペアのいずれかで終わる必要があります。 アルゴリズムは、考えられるすべてのペア タイプをチェックします。 選択されたペアについては、両方の数字が可能な限り右端で選択されるため、必要な末尾を維持しながら最も多くの数字を維持する配置が検索されます。 同じペアを他の配置にすると、少なくとも同じ数の桁が削除されます。 最適な答えはこれら 4 つのケースのいずれかに属さなければならないため、アルゴリズムによって見つかった最小値が全体的な最適値になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    patterns = ["00", "25", "50", "75"]
    ans = len(s)

    for p in patterns:
        second = -1
        for i in range(len(s) - 1, -1, -1):
            if s[i] == p[1]:
                second = i
                break

        if second == -1:
            continue

        first = -1
        for i in range(second - 1, -1, -1):
            if s[i] == p[0]:
                first = i
                break

        if first == -1:
            continue

        deletions = (len(s) - 1 - second) + (second - first - 1)
        ans = min(ans, deletions)

    print(ans)

if __name__ == "__main__":
    solve()
```コードは、4 つの可能な結末をそれぞれ個別にチェックします。 外側のループのサイズは一定であるため、合計の作業量は文字列の長さによってのみ決まります。 

各エンディングについて、最初の逆方向スキャンで最後の桁が選択されます。 数字をできるだけ右に保つことで、削除されるサフィックス数字を最小限に抑えることができるため、末尾から検索する必要があります。 2 番目のスキャンはその位置の前で開始され、ペアの前の桁を見つけます。 

削除式は 2 つの部分から構成されます。`len(s) - 1 - second`選択した最後の桁以降の桁をカウントします。`second - first - 1`選択した 2 桁の間の桁を数えます。 これらはまさに、必要な 2 つの数字が順番に残っている間に消える必要がある数字です。 

このアルゴリズムは入力を整数に変換しないため、非常に大きな文字列に対してもオーバーフローを心配することなく機能します。

## テストケース```python
import sys
import io

def solution(inp: str) -> str:
    s = inp.strip()
    patterns = ["00", "25", "50", "75"]
    ans = len(s)

    for p in patterns:
        second = -1
        for i in range(len(s) - 1, -1, -1):
            if s[i] == p[1]:
                second = i
                break
        if second == -1:
            continue

        first = -1
        for i in range(second - 1, -1, -1):
            if s[i] == p[0]:
                first = i
                break
        if first == -1:
            continue

        ans = min(ans, len(s) - 1 - second + second - first - 1)

    return str(ans) + "\n"

# provided-style cases

assert solution("505050\n") == "0\n", "multiple valid endings"
assert solution("123456789\n") == "7\n", "only final pair can be kept"
assert solution("99990001\n") == "2\n", "zero handling"

print("All tests passed")

 ## 特殊なケース

 のために`100`、アルゴリズムはエンディングを見つけます`00`。 2 番目のゼロは最後の位置で選択され、最初のゼロはその直前に選択され、次のようになります。`(2 - 1) + 0 = 0`削除。 番号は変わりません。 

のために`71375`、アルゴリズムはエンディングをチェックします`75`。 それは、`5`最後の位置と最も近い位置`7`その前に。 それらの間の数字は次のとおりです`13`、末尾の数字がないため、削除数は次のようになります。`2`。 検索で別の有効なペアが必要な場合でも、すべてのパターンの最小値が選択されます。 

のために`7`, 桁数が足りないため、4つのエンディングのいずれも形成できません。 答えは文字列の長さの初期値のままで、これは使用可能なすべての桁を削除することを表します。 

のために`505050`、アルゴリズムは次のことを見つけます。`50`文字列の終わりのすぐに。 選択した両方の数字がすでに正しい最終位置にあるため、戻り値が返されます。`0`。 これにより、すでに 25 で割り切れる数値がソリューションで不必要に変更されるのを防ぎます。
