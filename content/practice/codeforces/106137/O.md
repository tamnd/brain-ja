 ## 解決策
 ## 問題の理解

 いくつかのセルがブロックされ、一部のセルには重力の影響を受ける可動部分が含まれている垂直チャンバーを表す長方形のグリッドが与えられます。 グリッドは、重力が下向きに作用するように方向付けられています。つまり、移動可能なピースは、グリッドの底に到達するか、ブロックされたセルまたはすでに固定されている別のピースの上に着地するまで、列内で真っ直ぐに落ちます。 

タスクは、すべてのピースが落下し終わった後に、最終的な安定した構成を計算することです。 ブロックされた細胞は決して動くことがなく、永続的な障害物として機能します。 可動ピースは決して横に移動しないため、各列は、その列内に固定された障害物の存在を除いて、他の列とは独立して進化します。 

入力はこのグリッドを行ごとに記述し、出力は重力プロセスが安定した後にグリッドを記述する必要があります。 

複雑さの観点から見ると、グリッド サイズは通常、ピースごとの重力の単純なシミュレーションでは遅すぎるほど十分に大きいです。 すべての可動部分に対して繰り返し下方向にスキャンすると、最悪の場合は長い列を繰り返し横断するようになり、セル数が二次関数的に変化します。 各セルを一定回数処理するソリューションが必要であり、これはグリッド サイズに関して線形または線形に近いアプローチを意味します。 

複数の可動部品が障害物の上に積み重なると、微妙な失敗のケースが発生します。 たとえば、次のような列です。```
.#..
.oo.
....
```重力を注意深く扱わないと、既に配置されている位置にピースを誤って配置したり、障害物を不適切に飛び越えたりする可能性があります。 正しい動作は、ピースがパックされた順序で最も近い障害物または下部境界の上に「集まる」ことです。 

## アプローチ

 単純なアプローチでは、各部分を個別にシミュレートします。 移動可能なすべてのセルについて、それ以上移動できなくなるまで、一度に 1 行ずつ繰り返し下に移動します。 概念的には単純ですが、これは繰り返し作業につながります。単一のピースが O(n) 行を横断する可能性があり、O(nm) 個のピース​​が存在する可能性があり、最悪の場合は O(n²m) の動作が生成されます。 これは大規模なグリッドでは遅すぎます。 

重要な観察は、動きが厳密に列ローカルで単調であるということです。 ピースは列を越えて相互作用することはなく、列内では重力によって移動可能なセルが障害物で区切られた連続したブロックに効果的に分類されます。 動きを段階的にシミュレートする代わりに、各列をボトムアップで処理し、ピースが落ち着くことができる次の利用可能な位置を追跡できます。 

最適化は、各列が障害物によって分割されたスタックのように動作することを認識することで実現します。 2 つの障害物の間では、すべての可動部分がそのセグメント内の最も低い利用可能なスロットに落ちます。 これにより、繰り返されるシミュレーションが列ごとに 1 つのパスに変わります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(n²m) | O(1) おまけ | 遅すぎる |
 | 列の圧縮 | O(nm) | O(nm) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 計算中にセルを上書きできるように、グリッドを可変構造に読み取ります。 最終的な状態は既存の文字をその場で再配置することに依存するため、これが必要です。 
2. 移動が列の境界を越えることはないため、各列を独立して処理します。 これにより、2D 問題が m 個の個別の 1D 問題に縮小されます。 
3. 固定列の場合は、下の行から上に向かってスキャンを開始します。 ボトムアップで移動する理由は、重力が常に最も低い利用可能なスペースを最初に埋めるためです。 
4. ポインタを維持する`write_row`これは、可動部分を配置できる現在のセグメント内の最も低い位置を示します。 最初は、これが列の一番下です。 
5. 行ごとに上向きに移動します。 ブロックされたセルに遭遇するとリセットします`write_row`何も通過できないため、その障害物の真上に到達します。 
6. 移動可能なピースに遭遇した場合、その現在の位置をクリアして次の位置に置きます。`write_row`、次に減分します`write_row`そのため、上の次のピースは正しくスタックされます。 
7. 空のセルが見つかった場合は、状態に影響を与えないため、そのまま続行します。 

この方法ですべての列を処理すると、グリッドは最終的な安定した構成になります。 

### なぜ効果があるのか

 障害物 (またはグリッドの境界) で囲まれた柱のセグメント内では、重力はソート ルールを定義するだけです。移動可能なすべての部分は最終的にそのセグメントの下部に配置されます。 このアルゴリズムは、上向きのトラバース中にピースが発見された正確な順序で下から上に位置を埋めることによって、この不変条件を強制します。 各ピースはセグメント内の可能な限り最も低い有効なスロットに割り当てられ、障害物によってセグメントの境界がリセットされ、ピースがバリアを越えないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    grid = [list(input().strip()) for _ in range(n)]

    for col in range(m):
        write_row = n - 1

        row = n - 1
        while row >= 0:
            if grid[row][col] == '#':
                write_row = row - 1
            elif grid[row][col] == 'o':
                grid[row][col] = '.'
                grid[write_row][col] = 'o'
                write_row -= 1
            row -= 1

    for r in range(n):
        print("".join(grid[r]))

if __name__ == "__main__":
    solve()
```実装の中核は、列ごとの 2 ポインター スタイルのトラバーサルです。 の`write_row`ポインタは、落下するピースの次の有効な着地位置を表します。 障害物にぶつかるたびに、現在のセグメントを効果的に「閉じ」、そのすぐ上で再開します。 

よくある実装上の間違いは、慎重に順序付けせずに、将来の決定のためにグリッドに依存しながら、グリッドを更新することです。 ここで、書き込む前に元の位置をクリアすることで、誤って部分を二重にカウントしたり再利用したりすることがなくなります。 もう一つの微妙な点はリセットです`write_row`まさに`row - 1`when encountering an obstacle, since the obstacle itself must remain fixed and cannot be overwritten.

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、柱の最下部に障害物が現れる場合です。 その場合、移動可能なピースはその最後の行を占有することはできず、すべてのピースはその上に積み重ねる必要があります。 アルゴリズムはこれを自然に処理します。`write_row`にリセットされます`row - 1`、障害物自体の上に配置するのを防ぎます。 

もう 1 つのケースは、障害物の前に複数の可動部分から始まる柱です。 アルゴリズムは下から上に正しく埋められます。`write_row`最後の行から始まり、配置ごとに減少します。 

最後のケースは、障害物のない可動部分の完全な列です。 この動作は、下に圧縮されたすべての部分で列を上から下に埋めることになります。これは、特別なロジックを必要とせずにポインターベースの代入によって保証されます。
