 **確認済み:** いいえ

 ## 解決策
 ## 問題の理解

 グリッドは、各セルが 4 つの直交する隣接セルに接続されたノードである長方形のグラフとして見ることができます。 羊を含むノードもあれば、オオカミを含むノードもあり、残りは空です。 オオカミは空のマスを自由に一歩ずつ移動できますが、犬を配置すると、そこを通り抜けることはできません。 羊や犬は、動きという観点から見ると、静的な障害物です。 

課題は、犬以外のセルを通る 4 方向の移動のみを使用して、オオカミから羊への経路が存在しないように、空のセルに犬を配置できるかどうかを決定することです。 これが可能であれば、犬の配置の有効な構成を 1 つ出力する必要があります。 そうでない場合は、不可能であると報告します。 

この制約では最大 500 x 500 のグリッドが許可されるため、セルの総数は最大 250,000 になります。 セルごとに少量の一定量のグラフ探索を実行するソリューションであれば問題ありませんが、すべてのオオカミまたはすべての羊の到達可能性を個別に再計算しようとするものは、単一の走査として慎重に実装された場合にのみ許容されます。 オオカミと羊の間の単純なペアごとの到達可能性チェックは、最悪の場合、最大 O(R^2 C^2) の動作を意味するため、直ちに実行不可能です。 

微妙な点は、オオカミには個別の制約がないことです。 単一のオオカミが任意の羊に到達すると設定は無効になりますが、到達可能性は純粋にグラフに基づいているため、複数のオオカミが暗黙的に連携できます。 

主なエッジケースは、入力内でオオカミが羊に隣接している場合に発生します。 犬は空いたセルにのみ配置することが許可されているため、すでに隣接している場合は犬を引き離すことはできません。 たとえば、オオカミと羊が隣接する 2 × 2 のグリッドでは、すぐに答えを出すことは不可能に違いありません。 もう 1 つの重要なエッジ ケースは、オオカミからその羊までのすべての経路が 1 つの空の廊下セルを通過するような方法で、オオカミが羊を取り囲む場合です。 その廊下はブロックする必要があり、ソリューションでは犬を正確に識別してそこに配置する必要があります。 

## アプローチ

 強引なアイデアは、マルチソース BFS を使用してすべてのオオカミの動きをシミュレートし、到達可能なすべてのセルをマークすることです。 オオカミの到達可能な領域全体を計算した後、その中に羊がいるかどうかを確認するだけです。 羊に手が届く場合は、犬を配置して道を塞ぎ、これを繰り返します。 ただし、犬をどこに配置するかを動的に決定するには、グローバル最小カット スタイルの問題を解決する必要があるため、これは複雑になりますが、ここでは不要です。 

重要な観察により、すべてが単純化されます。オオカミと羊の間のすべての経路をグローバルに制御する必要はありません。 必要なのは、オオカミが隣接する空のセルを通って羊のセルに直接足を踏み入れることができないようにすることだけです。 オオカミが羊に到達できる場合、4 つの隣接する羊のうちの 1 つから最後の一歩が羊に入る経路が存在する必要があります。 これは、羊の空の隣をブロックすることによってオオカミと羊の間の隣接を妨げれば、問題全体が解決されることを意味します。 

これにより、問題は局所的な建設上の問題に帰着します。 グリッドをスキャンします。 オオカミがすでに羊に隣接している場合、それらの間に犬を挿入する方法はありません。したがって、答えは直ちに不可能です。 それ以外の場合は、羊に隣接するすべての空のセルに犬を配置します。 これらの犬は、将来オオカミが羊の地域に到達するのを防ぐ障壁として機能します。 オオカミは犬を通過できず、すべての羊はオオカミにつながる隣接する空のセルから隔離されているため、道は存在できません。 

ブルートフォース探索はグローバルな到達可能性をシミュレートしますが、グリッドの構造により、長いパスは最初に羊の隣を通過する必要があるため、直接の隣接のみが重要になります。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース BFS 到達可能性チェック | 検索ごとに O(RC)、潜在的に O(R^2C^2) | O(RC) | 遅すぎる/不必要 |
 | 最適なローカルブロッキング | O(RC) | O(RC) | 承認済み |

 ## アルゴリズムのチュートリアル

 グリッドを変更可能な構造として扱い、最終的な配置を直接構築します。 

1. 入力グリッドを可変配列にコピーして、元の情報を失わずに犬を配置できるようにします。 すべての羊とオオカミを変更せずに保存しなければならないため、これが必要です。 
2. グリッド内のすべてのセルを走査します。 羊を見つけたら、その隣の 4 つの房を調べます。 
3. 隣人がオオカミである場合、私たちは即座に答えは不可能であると結論付けます。 これは、羊やオオカミの独房に犬を入れることができないため、隣接関係を修復できないためです。 
4. 隣人が空の場合、私たちはそれを犬に変えます。 これにより、今後オオカミが羊に近づこうとする試みが境界で阻止されるようになります。 複数の羊が境界セルを共有する可能性があるため、すべての羊に対してこれを熱心に行います。 
5. すべてのセルを処理した後、変更されたグリッドを出力します。 

オオカミを明示的にシミュレートする必要がない理由は、オオカミから羊への有効なパスはすべて、羊の隣を通過する必要があるためです。 このような近隣すべてを確実にブロックすることで、考えられるすべてのルートを 1 回のパスで排除します。 

### なぜ効果があるのか

 オオカミから羊へのパスはすべて、羊のセルで終わる一連の隣接するセルです。 このようなパスの最後から 2 番目のセルは、その羊の隣接セルでなければなりません。 その隣人が犬や壁であれば、その道は存在できません。 したがって、道が存在する唯一の方法は、羊の隣人がオオカミであるか、ブロックされていない空のセルである場合です。 私たちはオオカミの隣接を明示的に禁止し、空の隣人をすべて犬に変換するため、羊への有効な最終ステップは不可能のままです。 ブロッキングはグローバルに行われるため、この不変条件はすべての羊に同時に当てはまります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    R, C = map(int, input().split())
    grid = [list(input().strip()) for _ in range(R)]
    
    dirs = [(1,0), (-1,0), (0,1), (0,-1)]
    
    for i in range(R):
        for j in range(C):
            if grid[i][j] == 'S':
                for di, dj in dirs:
                    ni, nj = i + di, j + dj
                    if 0 <= ni < R and 0 <= nj < C:
                        if grid[ni][nj] == 'W':
                            print("No")
                            return
                        if grid[ni][nj] == '.':
                            grid[ni][nj] = 'D'
    
    print("Yes")
    for row in grid:
        print("".join(row))

if __name__ == "__main__":
    solve()
```この実装は、前述したグリッド スキャンの直後に行われます。 重要な点は、スキャン中に変更が適切に行われることですが、空のセルを犬に変えることは保護を強化するだけであり、オオカミに新たな道をもたらすことはないため、これは安全です。 

境界チェックにより、無効なインデックスにアクセスしないことが保証されます。 隣接するオオカミを検出して早期に終了することで、不可能性が確立された後の不必要な処理が回避されます。 

## 実用的な例

 ### 例 1

 入力:```
3 3
S.W
...
W.S
```私たちは各羊をスキャンし、隣の羊をチェックします。 

| セル (i,j) | タイプ | 近隣チェック結果 | アクション |
 | --- | --- | --- | --- |
 | (0,0) | S | 右はW | 不可能が検出されました |

 オオカミは羊に隣接しているため、すぐに「いいえ」を出力します。これは、隣接が致命的な構成であることを確認します。 

### 例 2

 入力:```
3 3
S..
...
..W
```We process the sheep at (0,0).

 | セル (i,j) | タイプ | 近隣スキャン | グリッド変更 |
 | --- | --- | --- | --- |
 | (0,0) | S | (1,0)、(0,1) は「.」です。 | D を (1,0),(0,1) に配置します。 

最終的なグリッドは次のようになります。```
SD.
D..
..W
```ブロックした後は羊がオオカミに隣接しないため、出力は「はい」になります。 これは、ローカル ブロッキングがコンポーネントを完全に分離していることを示しています。

 ## 特殊なケース

 オオカミと羊の直接の隣接関係は、最も重大な障害モードです。 次のような入力の場合:```
2 2
SW
..
```アルゴリズムはセル (0,0) を検査し、羊を見つけ、すぐにその右側にオオカミを見つけます。 変更する前は No を返します。 これにより、不可能な構成を誤って「修復」しようとすることがなくなります。 

2 番目のケースは、複数の羊が境界セルを共有する場合です。 次のようなグリッド内で:```
3 3
S.S
...
W.W
```両方の羊に隣接する中央の列の空のセルは、各羊の処理中に犬に変換されます。 同じセルが複数回考慮される場合でも、「.」を再割り当てします。 「D」へのは冪等であるため、最終的なグリッドは一貫性があり、完全にブロックされたままになります。
