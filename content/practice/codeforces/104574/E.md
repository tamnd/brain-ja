 ## 解決策
 ## 問題の理解

 固定の 52 枚のカード デッキが与えられ、各位置には 1 から 13 までの数字が含まれており、各値はちょうど 4 回出現します。 このうち、値 1 のカードはエースであり、勝利に重要な唯一のカードです。 

デッキ上での 1 回の操作で完璧なリフル シャッフルが可能です。 デッキはサイズ 26 の 2 つの半分に分割されます。次に、これらの半分を固定パターンでインターリーブすることによってシャッフル デッキが形成されます。つまり、前半の最初のカード、後半の最初のカード、前半の 2 番目のカード、後半の 2 番目のカードなどです。 この操作は位置の決定論的な再配置を定義するため、それを繰り返し適用すると、デッキの順列のシーケンスが生成されます。 

このシャッフルは何度でも適用できます。 問題は、4 つのエースすべてが 1 位から 26 位以内に収まるシャッフルがいくつか存在するかどうかです。 

制約は小さく固定されています。デッキ サイズは常に 52 で、複数のテスト ケースはありません。 これにより、定数または非常に小さな多項式因数を超えた漸近最適化の必要性が即座に排除されます。 置換構造の直接シミュレーションは実行可能ですが、シャッフルは任意の再配置を探索するのではなく置換サイクルを繰り返すため、すべての可能なシャッフルを個別に総当たりで実行することは不可能です。 

微妙なエッジ ケースは、条件が個々のエースが独立して前半に到達することではなく、同じ回数のシャッフル後に同時にそこに到達することであるということです。 たとえば、各エースが異なるシャッフル カウントで前半に登場する可能性はありますが、4 人全員が一緒に前半に登場する単一のシャッフル カウントはありません。 この区別が、素朴な独立した推論を失敗させる原因です。 

もう 1 つのエッジ ケースは、シャッフルが「よく混ざり合う」ため、すべての構成が到達可能であると想定しています。 この操作は固定順列であるため、これは誤りであり、システムは位置の互いに素なサイクル内で進化します。 

## アプローチ

 素朴なアプローチは、シャッフルを繰り返しシミュレーションし、各ステップの後に 4 つのエースがすべて前半にあるかどうかを確認することです。 順列には、固定順列を繰り返し適用することで到達できる個別の配置の最大数の期間があるため、最大 52 のステップをシミュレートし、毎回チェックすることができます。 これは、最大 52 のアプリケーションの後、52 要素のシステムで構成を繰り返す必要があるため、原理的には機能しますが、概念的には無駄であり、問​​題の構造は明らかになりません。 

重要な観察は、シャッフルがポジションの固定順列であるということです。 各位置はサイクルに属し、シャッフルを繰り返し適用すると、それらのサイクル内の要素が回転するだけです。 各エースは独自のサイクルに沿って独立して移動しますが、すべてのサイクルは適用される同じ数のシャッフルによって同期されます。 

そこで問題は、4 つの開始位置があり、それぞれが何らかのサイクルにあることです。 各エースの時間 k での位置がデッキの前半にあるような、単一の時間ステップ k が存在するかどうかを知りたいと考えています。 

各サイクル内で、サイクル内のインデックスによって位置にラベルを付けることができます。 シャッフルを適用するたびに、サイクルに沿って 1 ステップずつ進みます。 したがって、各エースについて、どのサイクル インデックスが前半の位置に対応するかを事前に計算できます。 次に、各エースは、そのサイクル長を法とする有効な残基のセットに寄与します。 4 つの条件をすべて同時に満たす k の値が必要です。 サイクル長は短く、合計が 52 であるため、関連するすべてのサイクル長の最小公倍数も総当たり攻撃に十分小さいです。 

これにより、順列の検索から周期的制約の交差までの問題が軽減されます。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 多くのシャッフルに対するフルデッキのブルートシミュレーション | O(52・52) | お(52) | 受け入れられるが不要 |
 | サイクル分解 + モジュラー チェック | O(52 + LCM 検索) | お(52) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### ## アルゴリズムのチュートリアル

 1. 位置 1 ～ 52 で 1 回のシャッフルによって引き起こされる順列 P を構築します。これは、1 回のリフル インターリーブ後に各インデックスがどこに移動するかを計算することを意味します。 このステップにより、シャッフル プロセスがインデックスの純粋な順列問題に変わります。 
2. 順列 P を素のサイクルに分解します。 すべての位置は正確に 1 つのサイクルに属し、繰り返されるシャッフルはそのサイクル内で前方に歩くことに対応します。 
3. サイクルごとに、サイクルを 1 回通過するときに遭遇した一連の位置を記録します。 このシーケンスは、そのサイクルで開始される要素が時間の経過とともに占める可能性のあるすべての位置を表します。 
4. サイクル内の各ポジションについて、それがデッキの前半にあるかどうかを判断します。 サイクル内の対応するインデックスを、ターゲット領域内にある「良好な時間」としてマークします。 
5. 各エースについて、その開始サイクルとそのサイクル内の開始インデックスを見つけます。 そのサイクルのマークされた「良い時間」から、k 回シャッフルした後、エースが前半になるようにすべての残余 k を収集します。 
6. 次に、4 つのエースすべてを同時に満たす共通の k を検索します。 これは、k を 0 から関係するすべてのサイクル長の最小公倍数まで試し、その時点で各エースが有効な位置にあるかどうかをチェックすることによって行われます。 

### なぜ効果があるのか

 シャッフルではサイクル間で要素が混合されることはありません。そのため、各カードは固定された循環構造内で独立して進化します。 エース間の唯一の結合は、同じ数のシャッフル ステップがグローバルに適用されるという要件です。 これにより、問題は、各サイクルから得られるモジュラー算術制約に関する同期条件に変わります。 

すべての状態はそのサイクル長に等しい周期で繰り返されるため、結合システムの 1 つの完全な周期に注意を限定すると、前半に関して考えられるすべてのエースの配置が 1 回だけ観察されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_perm():
    # permutation on positions 0..51
    # new order: a0,a26,a1,a27,... in 0-indexed form
    p = [0] * 52
    for i in range(26):
        p[i] = 2 * i
        p[i + 26] = 2 * i + 1
    return p

def solve():
    a = list(map(int, input().split()))
    
    p = build_perm()

    # find cycles of permutation on positions
    vis = [False] * 52
    cycle_id = [-1] * 52
    cycles = []

    for i in range(52):
        if vis[i]:
            continue
        cur = []
        x = i
        while not vis[x]:
            vis[x] = True
            cycle_id[x] = len(cycles)
            cur.append(x)
            x = p[x]
        cycles.append(cur)

    # locate ace positions (value == 1)
    aces = [i for i, v in enumerate(a) if v == 1]

    # precompute position-in-cycle index
    pos_in_cycle = {}
    for cid, cyc in enumerate(cycles):
        for idx, node in enumerate(cyc):
            pos_in_cycle[node] = (cid, idx)

    # for each ace, compute allowed k residues
    mods = []
    lens = []

    for pos in aces:
        cid, idx = pos_in_cycle[pos]
        cyc = cycles[cid]
        L = len(cyc)
        good = set()
        for t in range(L):
            if cyc[t] < 26:  # first half
                good.add(t)
        mods.append(good)
        lens.append(L)

    L = 1
    for l in lens:
        L = (L * l) // __import__("math").gcd(L, l)

    for k in range(L):
        ok = True
        for pos in aces:
            cid, idx = pos_in_cycle[pos]
            cyc = cycles[cid]
            Lc = len(cyc)
            if cyc[(idx + k) % Lc] >= 26:
                ok = False
                break
        if ok:
            print("YES")
            return

    print("NO")

if __name__ == "__main__":
    solve()
```コードはまずシャッフルをインデックスの順列に変換します。 次に、繰り返されるシャッフルが各サイクルでモジュラー演算になるようにサイクルを抽出します。 各エースはそのサイクルを通じて個別に追跡され、最後のループでは、すべてのエースが有効な位置に着地する単一のグローバル ステップ カウントが存在するかどうかがチェックされます。 

実装の微妙な詳細は、配列全体に順列を繰り返し適用する代わりに、サイクル インデックスを使用することです。 これにより、冗長な作業が回避され、周期構造が明確になります。 2 番目の重要な詳細は、探索空間を安全に制限するためのサイクル長の最小公倍数を計算することです。 

## 実用的な例

 ### サンプル 1

 エースとそのサイクル動作のみを追跡します。 

| k | エース 1 のポジション | エース2ポジション | エース3ポジション | エース 4 ポジション | 前半のすべて |
 | --- | --- | --- | --- | --- | --- |
 | 0 | 前半 | 保証されていません | 前半 | 前半 | いいえ |
 | 1 | 前半 | 前半 | 前半 | 保証されていません | いいえ |
 | ... | ... | ... | ... | ... | ... |

 この場合、サイクルが揃っているため、4 つのエースの軌道すべてが前半で同時に交差するステップが存在します。 アルゴリズムはサイクル期間内でそのような k を見つけ、YES を出力します。 

### サンプル 2

 ここでは、エースのポジションのサイクルが期間と位相でずれています。 

| k | エース1 | エース2 | エース3 | エース4 | 前半のすべて |
 | --- | --- | --- | --- | --- | --- |
 | 0 | 悪い | 良い | 悪い | 良い | いいえ |
 | 1 | 良い | 悪い | 悪い | 悪い | いいえ |
 | 2 | 悪い | 悪い | 良い | 悪い | いいえ |

 全サイクル範囲にわたって、前半内で 4 つすべてが同時に整列するステップは存在しないため、出力は NO になります。 

これは、独立した到達可能性が同時到達可能性を意味しないことを示しています。

 ## 特殊なケース

 重要なエッジケースの 1 つは、エースが完全に後半に含まれるサイクルにある場合です。 その状況では、そのサイクルは位置 1 ～ 26 と交差することがないため、アルゴリズムはどの構成に対しても正しく NO を生成します。 

もう 1 つの特殊なケースは、4 つのエースすべてが同じサイクルにある場合です。 次に、問題は、前半で 4 つの出現がすべて一致するサイクル内に単一のインデックスが存在するかどうかを確認することになります。 すべての制約が 1 つのサイクル調整条件にまとめられるため、モジュラー チェックはこれを自然に処理します。 

最後の微妙なケースは、サイクルの長さが異なる場合です。たとえば、1 つのエースが長さ 6 のサイクルで移動し、もう 1 つのエースが長さ 8 のサイクルで移動する場合です。それぞれが個別に前半を定期的にヒットしたとしても、それらの期間が一致することはなく、結合された期間にわたる総当たりの同期が必要です。 このような場合、アルゴリズムは最小公倍数範囲全体を正しく探索し、誤検知がないことを保証します。
