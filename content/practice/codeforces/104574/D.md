 ## 解決策
 ## 問題の理解

 イギーの逃走経路に沿って並ぶ一連の敵が与えられます。 各敵にはある程度の体力があり、イギーも同様に一定の体力から始まります。 彼女はすべての敵の体力を 1 人ずつゼロ以下に減らし、自分自身の体力を決してゼロ以下にしないようにしなければなりません。 

敵を倒すために、イギーには 2 つの攻撃モードがあります。 最初のモードは、敵ごとに最大 1 回使用できます。 それはその敵に一定量のダメージを与えますが、イギー自身の体力も一定量消費します。 2 番目のモードは何度でも使用でき、使用するたびに敵にダメージを与えますが、イギーの体力も消耗します。 

課題は、すべての敵を倒し、イギーの健康状態が常に厳密にプラスに保たれるように、敵ごとに無制限の攻撃を何回使用するか、および単回使用の攻撃を使用するかを選択する方法があるかどうかを判断することです。 

制約は私たちを$O(M)$または$O(M \log M)$解決策は次のとおりです。$10^5$敵。 単純な方法で敵ごとに個別に攻撃の組み合わせをシミュレートしようとするソリューションは、すぐに爆発してしまいます。原理的には、敵ごとに特殊攻撃を使用するかどうかを選択し、チャージ攻撃の多くの組み合わせを選択できるからです。 これは、扱いを誤ると指数関数的、または少なくとも二次関数的な動作につながります。 

単純な推論による微妙な失敗例は、局所的なダメージ効率を常に最大化することで各敵を個別に扱うことです。 たとえば、ヒットごとに効率的であると思われる場合は常に親指スパイクを使用すると、弱い敵に対する最適な固定ダメージのオプションが無駄になり、後で強い敵にコストがかかりすぎる可能性があるため、失敗する可能性があります。 

もう 1 つのトリッキーなエッジケースは、ダメージ効率とダメージあたりの体力コストの両方においてチャージ攻撃の方が厳密にサム スパイクよりも優れている場合に発生します。ただし、サム スパイクは 1 回限りのバーストを与え、大型の敵に対してチャージの使用回数を大幅に減らすことができるため、依然として重要です。 

## アプローチ

 重要な観察は、残りの体力の合計を除いて、各敵が独立しているということです。 オプションで 1 回限りのボーナス攻撃を適用できることを考慮して、敵ごとに、その HP をゼロにするために必要なヘルス コストを最小限に抑える方法を決定する必要があります。 

親指のスパイクを無視すると、各敵は$a_i$必要$\lceil a_i / Q_1 \rceil$チャージ攻撃、コスト計算$Q_2 \cdot \lceil a_i / Q_1 \rceil$健康。 

次に親指スパイクを紹介します。 敵に使用すると、実質的にHPが減少します。$P_1$となるので、残りHPは$\max(0, a_i - P_1)$。 これにより、その敵に必要なチャージ攻撃の回数が減少します。 ただし、追加の固定費を支払います$P_2$そのような使用ごとに 1 回。 

したがって、敵ごとに、純粋なチャージコスト、または消費する混合コストの 2 つのコストから選択します。$P_2$＋HP減少後のチャージコスト$P_1$。 

これにより、問題は、敵ごとにこれら 2 つの値の最小値を計算し、すべての敵について合計することになります。 残る唯一の問題は、イギーの初期の健康状態が十分であるかどうかです。 

ブルートフォースアプローチでは、敵ごとに両方の選択肢を試し、突撃攻撃を個別にシミュレートします。$O(M \cdot a_i)$最悪の場合、それは不可能です$a_i$まで可能です$10^9$。 

簡素化の鍵となるのは、コスト構造が追加的であり、敵ごとに独立していることを認識することです。 敵の選択を修正すると、その最適な内部戦略は決定的になります。常にチャージ攻撃を使用し、オプションで単一のスパイクを先行させます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(M \cdot \max a_i)$|$O(1)$| 遅すぎる |
 | 最適 |$O(M)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 敵ごとに、チャージ攻撃のみを使用して倒すコストを計算します。 これは、必要なヒット数にヒットごとのヘルスコストを掛けたものです。 ヒット数は敵のHPの天井分割を使用して計算されます。$Q_1$。 
2. 同じ敵に対して、親指スパイクを 1 回だけ使用した場合の代替コストを計算します。 まずは敵のHPを減らします$P_1$、ただしゼロ未満ではない場合、残りの HP に対して必要なチャージ攻撃の回数を計算し、固定コストを追加します。$P_2$。 これは、スパイクがチャージ攻撃の数を実際に減らす場合にのみ有用であるという事実を捉えています。 
3. 計算された 2 つのコストの最小値を取得します。 これは、問題の全体的な構造を考慮すると、敵を単独で倒す最適な方法を表しています。 
4. すべての敵に対するこれらの最小コストを合計します。 この合計は、経路を確保するために必要な最小限の医療費です。 
5. 総コストが初期状態よりも厳密に小さいかどうかを確認する$N$。 「はい」の場合は「YES」を出力します。 それ以外の場合は NO を出力します。 

### なぜ効果があるのか

 重要な不変条件は、各敵の最適な戦略は自身の HP のみに依存し、他の敵の決定には依存しないということです。 攻撃は複数の敵間で相互作用しないため、合計コストを変更せずに 1 人の敵に対するすべてのアクションが連続するように、攻撃シーケンスを再配置できます。 したがって、敵ごとのコストを個別に最小化し、合計することで全体的な最適値が得られます。 全体的な健全性以外の結合制約はなく、敵全体で線形かつ相加的であるため、局所的な最適性は全体的な最適性を意味します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ceil_div(a, b):
    return (a + b - 1) // b

def solve():
    N, M = map(int, input().split())
    P1, P2 = map(int, input().split())
    Q1, Q2 = map(int, input().split())
    arr = list(map(int, input().split()))
    
    total_cost = 0
    
    for a in arr:
        # cost using only charge attacks
        hits = ceil_div(a, Q1)
        cost_charge = hits * Q2
        
        # cost using spike once + charge
        reduced = max(0, a - P1)
        hits2 = ceil_div(reduced, Q1)
        cost_spike = P2 + hits2 * Q2
        
        total_cost += min(cost_charge, cost_spike)
    
    print("YES" if total_cost < N else "NO")

if __name__ == "__main__":
    solve()
```実装は派生コスト モデルに直接に従います。 天井分割のヘルパー関数は浮動小数点演算を回避し、HP が攻撃ダメージで割り切れない場合の正確性を保証します。 各敵は 1 回のパスで個別に処理されます。 

微妙な実装の詳細は、`max(0, a - P1)`分割前。 これがないと、整数の除算の動作により、負の HP が必要なチャージ攻撃の数を誤って減らす可能性があります。 もう 1 つの重要なポイントは、厳密な比較を使用することです`total_cost < N`、イギーはすべてのダメージを受けた後もHPが厳密にゼロ以上に留まらなければならないためです。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import ceil
    input = sys.stdin.readline

    N, M = map(int, input().split())
    P1, P2 = map(int, input().split())
    Q1, Q2 = map(int, input().split())
    arr = list(map(int, input().split()))
    
    def ceil_div(a, b):
        return (a + b - 1) // b
    
    total = 0
    for a in arr:
        cost1 = ceil_div(a, Q1) * Q2
        reduced = max(0, a - P1)
        cost2 = P2 + ceil_div(reduced, Q1) * Q2
        total += min(cost1, cost2)
    
    return "YES\n" if total < N else "NO\n"

# provided sample
assert run("8 3\n5 2\n3 1\n5 8 6\n") == "YES\n"

# minimum input
assert run("1 1\n1 1\n1 1\n1\n") == "NO\n"

# spike useless case
assert run("20 2\n10 100\n1 1\n10 10\n") == "NO\n"

# spike dominates case
assert run("50 2\n9 1\n5 10\n20 20\n") == "YES\n"

# large HP single enemy
assert run("100 1\n50 1\n10 1\n1000000000\n") == "YES\n"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 最小限 | いいえ | いかなる犠牲を払ってもイギーを殺す境界 |
 | スパイクは役に立たない | いいえ | スパイクが常に選択されるわけではないことを保証します。 
| スパイクが優勢 | はい | スパイクにより充電使用量が確実に削減される |
 | 大きなHP | はい | 大きな値での正確性 |

 ## 特殊なケース

 エッジケースの 1 つは、スパイクによって HP がゼロ以下に減少するときに発生します。 この場合、すべてのチャージ攻撃は消滅し、スパイクコストのみが問題となります。 たとえば、次の場合$a_i \le P_1$、すると減少したHPはゼロになり、コストはちょうど$P_2$。 アルゴリズムはこれを正しく処理します。`max(0, a - P1)`そしてゼロチャージがヒットします。 

もう 1 つのエッジ ケースは、チャージ攻撃が非常に非効率であるにもかかわらず、スパイクのコストも高くつく場合です。 たとえば、次の場合$Q_1 = 1$そして$Q_2$が大きい場合、チャージコストは HP に線形になりますが、スパイクは制限された減少のみを提供します。 このアルゴリズムは引き続き両方の式を正しく評価し、貪欲な誤用を回避します。 

最後のエッジケースは、すべての敵が同一で大きい場合です。 このアルゴリズムは並べ替えや順序付けに依存しないため、繰り返される値は敵ごとの独立した評価を通じて自然に処理されます。
