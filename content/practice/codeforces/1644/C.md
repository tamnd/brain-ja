 ## 解決策
 ## 問題の理解

 整数と数値の配列が与えられます$x$。 タスクは、可能なそれぞれについて計算することです$k$0から$n$、追加が許可されている場合の連続する部分配列の最大合計$x$まさに$k$配列内の要素。 追加する要素$x$to は任意に選択でき、部分配列自体に増加した要素をすべて含める必要はありません。 合計がゼロの空の部分配列が許可されます。 

制約は十分小さいので、$O(n^2)$解決策は実現可能です。 の合計$n$すべてのテスト ケースの数は最大 5,000 です。これは、2 秒の制限時間内で合計で最大約 2,500 万の操作を実行できることを意味します。 配列の各要素と増分$x$は大きくなる可能性があるため、整数のオーバーフローを避ける必要がありますが、Python はそれをネイティブに処理します。 

明らかではないエッジ ケースには、すべて負の数を含む配列が含まれます。この場合、正の合計部分配列が存在しない場合、最大合計はゼロになる可能性があります。 たとえば、配列の場合、$[-5, -3, -2]$と$x = 4$増加する要素を選択しないと最大合計は 0 になり、1 つの要素を賢明に選択すると 2 が得られ、3 つすべてを選択すると 3 が得られます。常に最初の要素を選択する単純な実装$k$このような場合、要素は失敗する可能性があります。 

別のエッジケースが発生するのは次の場合です。$x = 0$。 次に、問題は古典的な最大部分配列合計問題に帰着し、アルゴリズムは正しく処理する必要があります。$k = 0$仮定せずに$x > 0$。 

## アプローチ

 ブルートフォースアプローチは、それぞれに対して次のようになります。$k$、サイズのすべてのサブセットを生成します$k$追加する$x$次に、サブセットごとに、サブ配列の最大合計を計算します。 すべてのサブセットを生成するのは、$O(\binom{n}{k})$、部分配列の最大合計の計算は次のようになります。$O(n)$。 このアプローチは原理的には正しいですが、実行不可能です。$n$最大5000まで可能ですので、$\binom{5000}{k}$小さいものでも天文学的に大きい$k$。 

重要な洞察は、次のことを追加することです。$x$要素への追加は常に有益であるため、部分配列の選択とどの要素を増やすかの選択を切り離すことができます。 任意の長さの部分配列に対して$l$を追加することで得られる最大のメリット$x$は$\min(l, k) \cdot x$部分配列に含まれる以上の要素を増やすことはできないためです。 したがって、サブ配列の長さごとに、増分なしでその長さの最大サブ配列合計を事前計算するだけで十分です。 それからそれぞれについて$k$、最大合計はすべての長さの最大値です。$l$の$\text{max\_sum\_of\_length}[l] + \min(l, k) \cdot x$。 

これにより、問題は指数関数的に減少します。$O(n^2)$: すべての長さの最大合計を計算するには時間がかかります$O(n^2)$、それぞれの結果を計算します。$k$かかります$O(n^2)$すべての長さの合計。 と$n \le 5000$、これは許容範囲です。

 ## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取り、各テスト ケースを繰り返します。 
2. 指定された長さの配列の場合$n$そして増加します$x$、配列を初期化します`max_sum_of_length`長さ (n + 1` で、各長さの部分配列の最大合計を格納します。
 3. 各開始インデックスについて$i$配列内で累計を初期化します`current_sum = 0`。 終了インデックスを反復処理します。$j$から$i$に$n-1$。 インクリメント`current_sum`による`a[j]`そして更新します`max_sum_of_length[j-i+1]`現在の値の最大値と`current_sum`。 これにより、サブ配列の長さごとの最大合計が取得されます。 
4. 回答配列を初期化する`answer`長さの$n + 1$ゼロ付き。 この店舗は$f(k)$それぞれに$k$。 
5. 考えられるそれぞれの k について` from 0 to \(n, iterate over all subarray lengths `私` from 0 to ⟦PROTECT_46⟧ and update `答え[k]` as the maximum of its current value and `max_sum_of_length[l] + min(l, k) * x`。 これにより、増加する要素の数ごとに最適な合計が計算されます。 
6. 印刷`answer`テストケースごとに。 

機能する理由: すべての長さの最大サブ配列合計を事前計算することにより、どのような選択でも、$k$、要素の数が増加するたびに最適な部分配列を検討できます。 機能$\min(l, k) \cdot x$部分配列に含まれる以上の要素を増やすことができないという制限を正しくモデル化します。 すべての長さにわたって反復することで、グローバル最大値を決して逃すことがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, x = map(int, input().split())
    a = list(map(int, input().split()))

    max_sum_of_length = [0] * (n + 1)

    for i in range(n):
        current_sum = 0
        for j in range(i, n):
            current_sum += a[j]
            length = j - i + 1
            if current_sum > max_sum_of_length[length]:
                max_sum_of_length[length] = current_sum

    answer = [0] * (n + 1)
    for k in range(n + 1):
        best = 0
        for length in range(n + 1):
            best = max(best, max_sum_of_length[length] + min(length, k) * x)
        answer[k] = best

    print(*answer)
```ソリューションは最初に構築します`max_sum_of_length`、すべての可能なサブ配列の合計が考慮されるようにします。 2 番目のループでは、`min(length, k)`増やすことができる要素の数を決して数えすぎないことを保証します。 初期値としてゼロを使用すると、空の部分配列が正しく考慮され、すべての数値が負の場合に結果がゼロになります。
