 ## 解決策
 ## 問題の理解

 完全に色付けされていないグリッドが与えられています。$n$行と$m$列。 次に、一連の操作を適用します。 各操作では行と列を選択し、その行と列のすべてのセルを選択した非白の色でペイントします。 複数の操作にわたってセルが複数回描画される場合、そのセルに触れる最後の操作によってその色が上書きされます。 

すべての操作が処理された後、最終的なグリッドは、一連の操作とそれらに割り当てられた色の選択によって完全に決定されます。 少なくとも 1 つのセルの最終色が異なる場合、2 つの最終グリッドは異なるものとみなされます。 

タスクは、各操作で次のいずれかを個別に選択した場合に、個別の最終グリッドがいくつ生成されるかを数えることです。$k$色。 

制約が非常に厳しいため、グリッドをシミュレートしたり、セルごとの状態を追跡したりするソリューションは直ちに実行不可能になります。 テスト ケース全体の操作の合計数は最大です。$2 \cdot 10^5$これにより、演算数が線形または線形に近い解が求められます。 グリッドを再計算したり、セルごとに更新を伝播しようとするアプローチは、時間制限を数桁超えてしまいます。 

同じ行と列のペアを操作で繰り返す場合、微妙な問題が発生します。 素朴な考えは、各演算を独立して扱い、次の値を乗算することかもしれません。$k^q$。 これは、異なる操作が互いに上書きする可能性があり、多くの場合、以前の選択が無関係になるため、失敗します。 たとえば、すべての操作が同じ行と列を対象とする場合、各セルにとって重要なのは最後の操作のみであるため、有効な色の数は次のとおりです。$k$、 ない$k^q$。 

もう 1 つの障害モードは、行と列を独立して処理できると想定していることです。 単一の操作で両方の色が同時に色付けされ、相互作用は操作の順序に依存するため、これらは独立していません。 

## アプローチ

 ブルートフォースアプローチでは、操作に対する色の割り当てをすべてシミュレートしようとします。 操作ごとに、次のいずれかを選択します。$k$色を調整し、グリッド上の効果をシミュレートして、最終結果を計算します。 これは正しいですが、探索するため実行不可能です。$k^q$可能性は、たとえ小さな入力であっても天文学的に大きくなります。 

グリッド全体を追跡することを避け、代わりに操作の構造的効果に焦点を当てる必要があります。 重要な点は、各行または列に影響を与える最後の操作のみが、その最終的な表示状態を決定するということです。 行が後の操作によって「カバー」されると、その行に影響を与える以前の操作は、後で上書きされない別の領域で発生する場合を除き、その行の寄与とは無関係になります。 

これは、「後の操作によって上書きされるため、初めて行または列が無関係になる」という観点からプロセスを再構成することにつながります。 各操作は、その行または列が後で上書きされるかどうかに応じて、新しい影響をもたらすか、冗長になります。 

操作は最後から最初に処理されます。 ペアを見たとき$(x, y)$、両方の列の場合$x$そしてコラム$y$後の操作によってすでに「ブロック」されている場合、この操作は何も新しいものを提供できません。 少なくとも 1 つがブロックされていない場合、この操作により、色の選択に新たな自由度が加わります。 処理後、行と列をブロック済みとしてマークします。 

この逆貪欲構造が機能するのは、行または列が後の操作によって考慮されると、前の操作は最終グリッドまで残る未割り当ての領域に影響を与えることができないためです。

 ## アルゴリズムのチュートリアル

 操作を逆の順序で処理し、どの行と列が後の操作ですでに「カバー」されているかを維持します。 

1. 2 つのブール配列を初期化します。1 つは行用、もう 1 つは列用で、最初はどちらも false です。 これらは、行または列が後の操作ですでに考慮されているかどうかを表します。 
2. 「アクティブなオペレーション」の寄与のカウンタをゼロに初期化します。 少なくとも 1 つの新しい行または列に依然として影響を与える操作が見つかるたびに、それは乗算係数に寄与します。$k$。 
3. 最後から最初まで操作を繰り返します。 それぞれの操作について$(x_i, y_i)$、行かどうかを確認します$x_i$すでにマークされているか列です$y_i$はすでにマークされています。 
4. 両方の列の場合$x_i$そしてコラム$y_i$がすでにマークされている場合、この操作は新たに目に見える自由を導入するものではないため、無視できます。 
5. それ以外の場合、この操作は色の新しい独立した選択に寄与するため、答えに次の値を掛けます。$k$、行をマークします$x_i$そしてコラム$y_i$カバーされているように。 
6. すべての操作が処理されるまで続行します。 

最終的な答えは積累積モジュロです$998244353$。 

### なぜ効果があるのか

 重要な不変条件は、リバース スイープのどの時点でも、マークされていないすべての行と列が、以前の操作による潜在的な影響を依然として受けているグリッドの領域に対応するということです。 少なくとも 1 つのマークされていない行または列に触れる操作を処理するとき、その領域は初めて逆の時間で「要求」されます。これは、その色の選択がまだ自由で独立していることを意味します。 行と列をマークすると、それらに影響を与えるすべての以前の操作は、新しい独立した選択肢を導入できなくなります。これは、それらが影響を与えるセルは、以降の操作によってすでに決定されているためです。 これにより、寄与する各操作が、正確に 1 つの独立した要素に対応することが保証されます。$k$、依存関係は 2 回カウントされません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

t = int(input())
for _ in range(t):
    n, m, k, q = map(int, input().split())
    ops = [tuple(map(int, input().split())) for _ in range(q)]

    row_used = [False] * (n + 1)
    col_used = [False] * (m + 1)

    ans = 1

    for x, y in reversed(ops):
        if row_used[x] and col_used[y]:
            continue
        ans = (ans * k) % MOD
        row_used[x] = True
        col_used[y] = True

    print(ans)
```この実装は、逆の貪欲なアイデアを直接反映しています。 操作は逆方向に処理する必要があるため、最初にすべての操作を保存します。 2 つのブール配列は、行または列が後の操作によってすでに要求されているかどうかを追跡します。 

重要な詳細は条件です`if row_used[x] and col_used[y]`。 これにより、新しい独立したカラーリングの選択肢を導入できない場合にのみ操作をスキップすることが保証されます。 If either the row or the column is still free, we must count this operation because it determines a fresh boundary of influence in the reverse process.

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    MOD = 998244353

    t = int(input())
    out = []
    for _ in range(t):
        n, m, k, q = map(int, input().split())
        ops = [tuple(map(int, input().split())) for _ in range(q)]

        row_used = [False] * (n + 1)
        col_used = [False] * (m + 1)

        ans = 1
        for x, y in reversed(ops):
            if row_used[x] and col_used[y]:
                continue
            ans = (ans * k) % MOD
            row_used[x] = True
            col_used[y] = True

        out.append(str(ans))
    return "\n".join(out)

 ## 特殊なケース

 微妙なエッジ ケースは、多くの操作が同じペアを繰り返す場合です。$(x, y)$。 アルゴリズムは、最後のこのような操作のみを逆に意味のあるものとして扱いますが、行または列が初めて導入される場合には、それぞれの繰り返しが影響を与える可能性があります。 たとえば、同じ操作が繰り返される場合、逆スイープでは 1 つの寄与のみがカウントされ、正しく結果が得られます。$k$、最初に処理されたオカレンスがすでに行と列の両方をマークしているためです。 

もう 1 つのエッジ ケースは、すべての操作が同じ行を共有するが、異なる列を共有する場合です。 逆に、最初の操作で行がマークされ、行と列の両方がすでにマークされると、後続の操作はスキップされます。 これにより、過剰カウントが正しく回避され、最初に遭遇した境界のみが自由な選択を導入することが反映されます。 

これらのケースは、不変条件が個々の操作に関連付けられているのではなく、逆の時間で以前には見られなかった行と列の境界を導入するかどうかに関連付けられていることを確認します。
