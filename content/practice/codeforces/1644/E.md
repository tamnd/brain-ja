 ## 解決策
 ## 問題の理解

 私たちに与えられているのは、$n \times n$グリッド、ロボットは左上隅から開始$(1,1)$。 ロボットは右 (R) または下 (D) に移動でき、シーケンスが提供されます。$s$そのような動きの。 それぞれの引っ越し$s$ロボットをグリッドの外に持ち出さないことが保証されています。 このシーケンスに対して変更を実行することが許可されています。各変更は 1 つの動きを複製し、D を DD に、または R を RR に変換します。 この問題は、これらの重複を任意の数だけ最適に適用した場合に、ロボットがグリッドから離れることなく、個別のセルの数に到達できるかどうかを尋ねます。 

入力サイズは重要です。 グリッドのサイズ$n$まで可能です$10^8$これにより、すべてのセルを個別に追跡しようとするシミュレーションが即座に除外されます。 テスト ケース全体のシーケンスの合計の長さは、$2 \cdot 10^5$これは、$n$。 内のすべての到達可能なセルをマークする単純な BFS または DP$n \times n$グリッドは非常に遅く、メモリを大量に消費します。 

エッジ ケースには、非常に短いパスや、一方向への移動のみで構成されるパスが含まれます。 たとえば、次の場合$s = D$で$3 \times 3$グリッドでは、ロボットは下方向にしか移動できないため、セルは$(1,1),(2,1),(3,1)$到達可能です。 ストレッチ移動の可能性を無視する単純なアルゴリズムでは、直接パス セルへの到達可能性が誤って制限される可能性があります。 

## アプローチ

 ブルートフォースアプローチは、可能なすべての組み合わせで動きを複製することによって、可能なすべての修正シーケンスを生成し、各シーケンスをシミュレートして到達可能なセルをマークすることです。 これはすべての可能性を探索するため、原理的には正しいですが、重複するたびにシーケンスの数が 2 倍になり、パスの数が指数関数的に増加するため、実行不可能です。 と$s$までの長さ$2 \cdot 10^5$、これは完全に非現実的です。 

重要な洞察は、動きを複製することでロボットはグリッドの境界までパスを「伸ばす」ことができるが、その方向のシーケンスは$s$それでも全体の順序が決まります。 それぞれのR$s$最後の列まで右方向に拡張できます$n$、各 D は最後の行まで下に拡張できます。$n$。 最初の R 動作は、ロボットが右に移動する必要が生じる前に下に到達できる距離を制限し、最初の D 動作は、下に移動する必要が生じる前にロボットが右に移動できる距離を制限します。 したがって、到達可能なセルの最大の長方形は、シーケンスの端にある R と D の数によって決まります。 

シーケンスの場合$s$、最後の D と最後の R の後に残っている R と D の数をそれぞれ数えます。 到達可能なセルは、次のすべてのセルになります。$(1,1)$に$(r_{\text{max}}, c_{\text{max}})$、 どこ$r_{\text{max}}$最後の R が一番下まで移動を開始できる行です。$c_{\text{max}}$最後の D が右端の列まで右に移動し始めることができる列です。 これにより、問題は明示的なシミュレーションではなく単純な算術に縮小されます。

 ## アルゴリズムのチュートリアル

 1. 特定のシーケンスの場合$s$、Rの合計移動数を数えます(`total_r`) と D が動きます (`total_d`）。 
2.初期化`r_count`そして`d_count`ゼロとして。 これらは、スキャン中に処理された R および D 移動の数を追跡します。$s$。 
3. 文字列を反復処理します。$s$。 それぞれの動きについて:

 - 移動が R の場合、インクリメントします`r_count`。 
- 移動が D の場合、インクリメントします`d_count`。 
4. スキャン後、移動を境界まで延長することで到達できるセルの数を計算します。 

- 最大行を計算します`max_row`として`n - (total_r - r_count)`。 これは、残りの R をすべて最後まで伸ばした場合に、ロボットがどこまで移動できるかを表します。 
- 最大列を計算します`max_col`として`n - (total_d - d_count)`。 これは、残りの D をすべて最後まで伸ばした場合に、ロボットがどこまで右に移動できるかを表します。 
5. 到達可能なセルの数は次のように計算されます。`max_row * max_col`。 長方形内の各セルは、$(1,1)$に$(max_row, max_col)$いくつかの重複シーケンスによって到達可能です。 
6. 各テスト ケースに対してこの値を出力します。 

これが機能する理由: 不変条件は、すべての R が最終的にロボットを最も右の列に移動でき、すべての D がロボットを一番下の行に移動できることです。 残りの動きをカウントすることで、ロボットがグリッドを越えて移動できるとは決して想定しません。 これらの最大値によって形成される長方形は、少なくとも 1 つの有効な変更されたパスで到達可能なすべてのセルをキャプチャします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()
        
        total_r = s.count('R')
        total_d = s.count('D')
        
        r_seen = 0
        d_seen = 0
        max_row = 0
        max_col = 0
        
        for move in s:
            if move == 'R':
                r_seen += 1
            else:
                d_seen += 1
            max_row = max(max_row, 1 + d_seen)
            max_col = max(max_col, 1 + r_seen)
        
        remaining_d = total_d - d_seen
        remaining_r = total_r - r_seen
        
        max_row = max(max_row, n - remaining_r)
        max_col = max(max_col, n - remaining_d)
        
        print(max_row * max_col)

if __name__ == "__main__":
    solve()
```解決策は、シーケンス内のすべての R および D の動きをカウントすることから始まります。 繰り返しながら、ロボットが行と列でどこまで到達したかを追跡します。 処理後、残りの動きを境界まで拡張します。 次を使用して最初のセルを含めるように注意してください。`1 +`最大値を更新するときに、グリッドの端に拡張するときに残りの移動を減算します。 これにより、過剰なカウントが保証されず、あらゆる長さのシーケンスが効率的に処理されます。
