 ## 解決策
 # 問題の理解

 アリスは次のような部屋を見つけます。`n`胸。 各チェストには値が書き込まれています`a[i]`。 正の値は、チェストを開けるとアリスのコインが得られることを意味し、負の値は、チェストに呪われたコインが含まれており、アリスの合計が減少することを意味します。 アリスはまさに所有しています`k`鍵を持っているので、彼女はせいぜい開けることができます`k`胸。 彼女の目標は、最終的にコインの数ができるだけ多くなるように、どのチェストを開けるかを選択することです。 

入力には、いくつかの独立したテスト ケースが含まれています。 ケースごとに、チェストの数、利用可能なキーの数、および各チェストの価値を受け取ります。 出力は、アリスが最善の選択をした後の最大のバランスです。 

制約が主な手がかりです。 すべてのテスト ケースのチェストの合計数は次のとおりです。`2 * 10^5`したがって、チェストのすべてのサブセットを試す解決策は不可能です。 すべての選択肢をチェックしても、`k`チェストは指数関数的に増加します。 線形または`O(n log n)`テストケースごとに必要です。 

キーのエッジ ケースは、アリスがすべてのキーを使用する必要がないという事実から生じます。 不用意に実装すると、常に正確に開かなければならないと想定される可能性があります。`k`胸。 

例えば：```
Input
1
3 2
5 -10 -20

Output
5
```アリスは 2 つの鍵を持っていますが、呪われた宝箱を開けると結果が減少します。 正しい選択は宝箱だけ開けることです`5`。 2 つのチェストを盲目的に選択するソリューションでは、より小さな値が生成されます。 

もう 1 つのケースは、すべての宝箱が呪われている場合です。```
Input
1
4 3
-1 -2 -3 -4

Output
0
```アリスはコインゼロからスタートし、単純にキーの使用を避けることができます。 値を並べ替えて常に最初の値を取得する`k`要素の符号をチェックしないと、誤って答えが負になってしまいます。 

## アプローチ

 直接的な総当たりアプローチでは、アリスが開けることができるすべての宝箱を試し、その合計値を計算し、最大値を維持します。 考えられるすべての決定が検討されるため、これは正しいです。 ただし、サブセットの数は`2^n`、数十個のチェストでも不可能になります。 と`n = 2 * 10^5`、このアプローチは利用可能な時間をはるかに超えています。 

問題を考察するより良い方法は、答えに寄与するものに焦点を当てることです。 正の値で宝箱を開けると、最終的な残高が増加します。 マイナスの値の宝箱を開けると値が減少します。 すべてのキーを使用する必要はないため、負の値は役に立ちません。 

唯一有用な操作は、最大の正の値を選択することです。 以下の場合は、`k`ポジティブチェスト、アリスはそれらをすべて受け取ります。 以上ある場合`k`、彼女はベストを保つべきです`k`正の値を使用すると、より小さい値にキーが費やされるたびに、より大きな報酬を受け取ることができなくなるためです。 

この観察により、問題は並べ替え問題に変換されます。 すべての正の値を収集し、最大値から最小値へ並べ替えて、最大値を追加します。`k`彼らのうち。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ソートのステップが実行時間の大半を占めます。 残りのアルゴリズムは配列をスキャンし、選択された値を合計するだけです。 

## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取り、各テスト ケースを個別に処理します。 
2. すべての胸の値を検査し、ゼロより大きい値のみを保持します。 これらは、アリスのバランスを改善できる唯一のチェストです。 
3. 残りの正の値を降順に並べ替えます。 並べ替え後の最初の要素が、最も収益性の高い選択肢となります。 
4. 最初のものを追加します`k`このソートされたリストの値、または値が少ない場合は使用可能なすべての値`k`。 
5. 結果の合計を出力します。 

この貪欲な選択が機能する理由は、選択されたすべてのチェストが 1 つのキーを消費するためです。 ソリューションに小さいポジティブ チェストが含まれているが、大きいポジティブ チェストが選択されていない場合、それらを交換すると合計が増加するか、変化しないままになります。 この交換を繰り返すと、最大の正の値のみが選択されたままになります。 

機能する理由: アルゴリズムは、利用可能なポジティブ チェストを考慮した後、選択された値が常に使用されるキーに対して可能な最高の報酬であるという不変条件を維持します。 マイナスの宝箱は合計を減らすだけなので、削除しても問題はありません。 最終的に選択されたセットは、まさに可能な最大の合計を含むセットです。 

## Python ソリューション```python
import sys

input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))

        positive = [x for x in a if x > 0]
        positive.sort(reverse=True)

        ans.append(str(sum(positive[:k])))

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```負の値は最適解の一部にはなり得ないため、リスト内包ではすべての呪われた宝箱が除外されます。 この並べ替えでは、アルゴリズム セクションの貪欲な推論と一致して、最高の報酬が最初に配置されます。 

スライス`positive[:k]`は、アリスが所有するキーを超えるキーの使用を防ぐ境界条件でもあります。 未満の場合`k`収益性の高い宝箱が存在する場合、Python は自動的にリスト全体を返します。 

合計には Python 整数が使用されるため、累積値が 32 ビットまたは 64 ビットの範囲を超えた場合でもオーバーフローの危険はありません。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | チェストの正の値を並べ替えることが作業の大半を占めます。 
| スペース | O(n) | 正の値のリストには、すべてのチェスト | が含まれる場合があります。 

すべてのテスト ケースのチェストの総数は次の制限を受けます。`2 * 10^5`したがって、収集されたすべての正の値を並べ替えると、制限内に問題なく収まります。 

## テストケース```python
import sys
import io

def solution(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    res = []

    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))

        pos = [x for x in a if x > 0]
        pos.sort(reverse=True)
        res.append(str(sum(pos[:k])))

    return "\n".join(res)

# provided samples
assert solution("""3
2 1
5 10
2 1
5 -10
3 3
1 -2 3
""") == """10
5
4""", "samples"

# minimum size
assert solution("""1
1 1
-7
""") == "0", "all negative minimum"

# all equal values
assert solution("""1
5 3
4 4 4 4 4
""") == "12", "equal positives"

# boundary where k exceeds positive count
assert solution("""1
6 5
8 -1 3 -2 0 4
""") == "15", "ignore non-positive values"

# large k with mixed values
assert solution("""1
7 2
-5 100 -10 50 20 1 -1
""") == "150", "take largest positives only"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1 / 1 1 / -7`|`0`| アリスはキーを使用しないことを選択できます。 
|`1 / 5 3 / 4 4 4 4 4`|`12`| 等しい正の値は正しく処理されます。 
|`1 / 6 5 / 8 -1 3 -2 0 4`|`15`| 負の値とゼロの値は無視されます。 
|`1 / 7 2 / -5 100 -10 50 20 1 -1`|`150`| 最高のものだけを`k`報酬が選択されました |

 ## 特殊なケース

 すべての宝箱が呪われると、ポジティブリストは空になります。 のために：```
Input
1
4 3
-1 -2 -3 -4
```アルゴリズムはフィルタリング中にすべての値を削除します。 並べ替えは何も行わず、選択された値の合計は次のようになります。`0`、これはアリスがチェストを選択しないことと一致します。 

プラスのチェストの数がキーよりも少ない場合:```
Input
1
5 4
6 -2 3 -8 1
```フィルタリングされたリストは`[6, 3, 1]`。 並べ替えても残る`[6, 3, 1]`、最初の 4 つの要素を取得すると、単純に 3 つの値すべてが取得されます。 答えは`10`。 

鍵よりも収益性の高いチェストがある場合:```
Input
1
5 2
9 7 5 3 1
```ソートされたリストは`[9, 7, 5, 3, 1]`。 最初の 2 つの値のみが使用され、次のようになります。`16`。 より小さい値に置き換えると結果が減少するため、欲張りな選択が最適です。
