 ## 解決策
 ## 問題の理解

 この問題は、左から右に処理される一連のタスクを記述します。 各タスクには報酬値とスタミナ減少率があります。 スタミナは 1 から始まります。タスクを完了すると、タスクの値に現在のスタミナを乗算した値に等しい報酬を獲得し、スタミナは指定されたパーセンテージだけ減少します。 タスクをスキップしても何も得られず、スタミナは変わりません。 目標は、最終的な報酬の合計ができるだけ大きくなるように、完了するタスクを選択することです。 

入力には複数のテスト ケースが含まれています。 各テスト ケースの最初の値はタスクの数です。 次の各ペアは 1 つのタスクを表します。最初の数値は報酬係数、2 番目の数値はタスクを完了した後に失われるスタミナの割合です。 出力は達成可能な最大スコアです。 

すべてのテスト ケースにわたるタスクの合計数が多すぎるため、すべてのサブセットをチェックすることは不可能です。 最大 100,000 個のタスクがある場合、総当たりアプローチでは、次のように指数関数的な数の選択肢を考慮する必要があります。$2^{100000}$、お取り扱いできません。 状態が多すぎる動的プログラムであっても失敗するため、ソリューションでは各タスクを一定の回数処理する必要があります。 

難しいケースは、スタミナはタスクが完了した場合にのみ変化し、1 つのタスクの決定はその後のタスクに依存するという理解から生じます。 常に最大の即時報酬を取得する貪欲なアプローチは、初期のタスクがスタミナを低下させ、後のタスクの価値を大幅に低下させる可能性があるため、失敗する可能性があります。 

例えば：```
1
10 100
```答えは`10`。 迂闊な実装だと減少後のスタミナに報酬を乗算してゼロになる可能性がありますが、スタミナが変化する前に報酬が獲得されます。 

別の例:```
3
10 5
10 80
20 5
```最良の答えは、`29`。 すべてのタスクを完了すると、以下が得られます。```
10 + 9.5 + 17.1 = 36.6
```実際、この例は、2 番目のタスクがスタミナの大部分を破壊するため、順序が重要である理由を示しています。 最適な選択は、中間のタスクをスキップすることです。```
10 + 20 * 0.95 = 29
```個々のタスクの報酬のみを比較するソリューションでは、将来完了するすべてのタスクの乗数となるスタミナの効果が見逃されます。 

## アプローチ

 直接的な総当りのソリューションでは、タスクのすべてのサブセットが試行されます。 各サブセットについて、現在のスタミナと累積スコアを維持しながら、選択したタスクを順番にシミュレートします。 考えられるすべての決定シーケンスが検査されるため、これは正しいです。 ただし、サブセットの数はタスクが追加されるたびに 2 倍になるため、タスクが 100,000 個になると、可能性の数はコンピューターが処理できる数をはるかに超えます。 

有益な観察は、リストの最後からタスクを見ると、将来のことがすでに要約されているということです。 現在のスタミナが 1 であると仮定して、現在のタスク以降のすべてのタスクから取得できる最大スコアがわかっているとします。現在のタスクを完了することに決めた場合、その報酬はすぐに得られ、その後のすべての報酬は残りのスタミナによって調整されます。 これをスキップすると、将来の価値が変更されないままになります。 

これにより、1 次元の動的計画法状態が得られます。 させて`dp`スタミナ要素を分離した、現在検討中のタスクの接尾語から得られる最高のスコアを表します。 報酬のあるタスクを処理する場合`c`残りのスタミナ乗数`m`を完了すると、次のようになります。$$c + m \times dp$$この問題の場合、タスク完了後のスタミナ乗数は次のようになります。$$1 - \frac{p}{100}$$したがって、終わりから始まりに向かって移動すると、遷移は次のようになります。$$dp_i = \max(dp_{i+1}, c_i + (1-\frac{p_i}{100})dp_{i+1})$$これが機能する理由は、現在のタスクが将来に与える影響は、将来の報酬に適用される 1 つの乗数だけであるためです。 以前の選択の履歴全体を記憶する必要はありません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(2^n \cdot n)$|$O(1)$| 遅すぎる |
 | 最適な動的プログラミング |$O(n)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. タスクを読み取り、最後のタスクから最初のタスクまで処理します。 接尾辞の答えがすでにわかっている場合、将来の決定を説明するのが簡単になります。 
2. 変数を維持する`dp`この逆方向のトラバーサルでこれまでに処理されたタスクから取得できる最大スコアが含まれます。 当初は今後のタスクはありませんので、`dp = 0`。 
3. 報酬のある現在のタスクについて`c`スタミナ減少率`p`、完了した場合の結果を計算します。 得られた報酬は、`c`、将来のすべての報酬は次のように乗算されます。`1 - p / 100`。 
4. タスクを完了した場合の値とタスクをスキップした場合の値を比較します。 大きい値を新しい値として保持します`dp`。 
5. すべてのタスクが処理されたら、`dp`シーケンス全体の答えです。 

なぜ機能するのか: 動的プログラミングの不変条件は、タスクを逆の順序で処理する前に、`dp`現在のスタミナ係数を 1 として扱った場合に、そのタスク以降のすべてのタスクから得られる最高スコアに相当します。 現在のタスクについては、有効な戦略はすべて、タスクをスキップするか、完了します。 移行では両方の可能性が正確に評価され、スタミナの変化は将来の報酬に適用される乗数によってのみ表されるため、以前のタスクからの他の情報は必要ありません。 すべてのサフィックスは左に移動する前に最適に解決されるため、最終的な値はタスク リスト全体にとって最適になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n = int(input())
        tasks = []

        for _ in range(n):
            c, p = map(int, input().split())
            tasks.append((c, p))

        dp = 0.0

        for c, p in reversed(tasks):
            multiplier = 1.0 - p / 100.0
            take = c + multiplier * dp
            skip = dp
            dp = max(take, skip)

        ans.append(f"{dp:.10f}")

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```タスクの総数には制限があるため、入力は通常どおり読み取られますが、`sys.stdin.readline`不要なオーバーヘッドを回避します。 

遷移は最後から最初まで実行する必要があるため、タスクのリストが保存されます。 逆方向に処理しながら、`dp`は、すでに処理されたサフィックスの最適な値のみを保存するため、完全な動的プログラミング配列は必要ありません。 

スタミナの減少にはパーセンテージが含まれるため、計算では浮動小数点数が使用されます。 Python の整数にはオーバーフローの問題はありませんが、小数点の報酬には浮動小数点の精度が必要です。 小数点以下 10 桁を印刷すれば、必要なエラー許容範囲を十分に満たすことができます。 

操作の順序が重要です。 報酬`c`タスクを完了するとすぐにポイントが付与され、その後のタスクのスタミナが減少するため、スタミナ乗数を適用する前に追加されます。

## テストケース```python
import sys
import io

def solution(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        tasks = []

        for _ in range(n):
            c, p = map(int, input().split())
            tasks.append((c, p))

        dp = 0.0
        for c, p in reversed(tasks):
            dp = max(dp, c + (1 - p / 100.0) * dp)

        out.append(f"{dp:.10f}")

    return "\n".join(out)

すべての削減がゼロになるタスクの場合:```
1
4
5 0
5 0
5 0
5 0
