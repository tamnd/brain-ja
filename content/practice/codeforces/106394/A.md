 ## 解決策
 ## 問題の理解

 問題は、すべての寿司が 2 つのタイプのいずれかに属する、一列に並んだ寿司に関するものです。 有効な食事セグメントは、前半には 1 種類の寿司のみが含まれ、後半にはもう 1 種類の寿司のみが含まれ、両方の半分のサイズが同じである連続したブロックです。 タスクは、そのようなセグメントの可能な最大長を見つけることです。 

入力は、寿司の個数と各個の種類を左から右に記述します。 出力は、有効な連続セグメントの最長の長さです。 

重要な制約は、寿司のピースの数が最大で 1 個程度になる可能性があることです。$10^5$。 考えられるすべてのセグメントをチェックするソリューションには、二次作業が必要になります。これは、大まかに意味します。$10^{10}$最悪の場合、通常の制限時間をはるかに超えた作業が行われます。 線形時間で行を処理する方法を見つける必要があります。 

難しいケースは、バランスがとれているように見えても、実際には有効ではないセグメントから発生します。 例えば：```
6
1 2 1 2 1 2
```答えは次のとおりです。```
2
```不注意なアプローチでは、配列全体に両方のタイプが同じ数存在することがわかり、より長いセグメントが選択される可能性がありますが、選択したセグメントの 2 つの半分は、それぞれ 1 つのタイプで構成されている必要があります。 交互寿司はルールを満たしていません。 

もう 1 つのエッジ ケースは、最長のセグメントが 2 つのグループ間の境界に正確に形成される場合です。```
9
2 2 1 1 1 2 2 2 2
```答えは次のとおりです。```
6
```有効なセグメントは`2 2 1 1 1 2`または`1 1 1 2 2 2`。 ソリューションでは、最大のグループだけでなく、同じタイプのグループの隣接するすべてのペアを考慮する必要があります。 

## アプローチ

 簡単なアプローチは、可能なすべての連続セグメントを生成することです。 各セグメントについて、同じ長さの 2 つの半分があるかどうか、および各半分に 1 種類の寿司のみが含まれているかどうかを確認します。 考えられるすべての答えが考慮されるため、これは正しいです。 問題は、$O(n^2)$考えられるセグメントをチェックすると、別の要素が追加される可能性があります。$n$、につながる$O(n^3)$最悪の実装での解決策。 プレフィックス情報によって検証が減少したとしても、候補セグメントの数は依然として多すぎます。 

重要な点は、有効なセグメントが寿司の種類が変わる境界を正確に越えて存在する必要があるということです。 配列を同じ値の連続するグループに圧縮することを想像してください。 セグメントは、あるグループの一部のサフィックスと、次のグループの同じサイズのプレフィックスのみを取ることができます。 2 つの隣接するグループを使用した場合の最大長は、小さいグループ サイズの 2 倍です。 

たとえば、グループが次の場合:```
2 2 2 1 1 1 1
```2 つのグループの長さは 3 と 4 です。3 つを取ることができます。`2`と３`1`s、長さ 6 のセグメントが得られます。2 番目のグループから 4 つを取得することは、十分な数がないため不可能です。`2`s.

 全体の問題は、すべての隣接するグループのペアの最大値を見つけることになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) 以上 | お(1) | 遅すぎる |
 | グループ圧縮 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を左から右にスキャンし、同じ種類の寿司の連続するブロックの長さを数えます。 
2. これらのブロック長を順番に保存します。 ブロックは、タイプが変更される前の、1 つの寿司タイプからの可能な最大の寄与を表します。 
3. 隣接するブロックのペアごとに、次の計算を行います。`2 * min(left_block, right_block)`。 両方の半分が同じ長さでなければならないため、これはこの境界を越える最長の有効なセグメントです。 
4. すべての境界の最大値を保持して印刷します。 

隣接するブロックのみを比較する理由は、有効なセグメントにはタイプ間の遷移が 1 つだけ含まれている必要があるためです。 2 つ以上のトランジションがある場合、半分の 1 つは混合寿司タイプを含みます。 

なぜ効果があるのか:

 すべての有効なセグメントには、一方のタイプの左半分と、もう一方のタイプの右半分があります。 2 つの半分は型が変わる点で交わるので、圧縮表現では 2 つの隣接するグループに属します。 セグメントの長さは、両方の半分が同じサイズである必要があるため、これら 2 つのグループの小さい方によって制限されます。 隣接するすべてのグループをチェックすると、考えられるすべての有効なセグメントがチェックされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    groups = []
    count = 1

    for i in range(1, n):
        if a[i] == a[i - 1]:
            count += 1
        else:
            groups.append(count)
            count = 1

    groups.append(count)

    ans = 0

    for i in range(len(groups) - 1):
        ans = max(ans, 2 * min(groups[i], groups[i + 1]))

    print(ans)

if __name__ == "__main__":
    solve()
```アルゴリズム全体で必要なのは寿司の種類の順序のみであるため、入力は単一の配列として読み取られます。 の`groups`list には、連続する等しい値の長さが格納されます。 

最初のループでは、圧縮表現を構築します。 現在の寿司タイプが前の寿司タイプと異なる場合、現在のグループは終了し、その長さは保存されます。 

最後のループでは、2 つのグループ間の考えられる境界をそれぞれ調べます。 小さいグループの長さに 2 を掛けると、その境界を越えることができる最大のバランスのとれたセグメントが得られます。 

Python では整数の精度が任意であるため、オーバーフローの問題は発生しません。 右隣が存在する間のみループが実行されるため、境界処理も簡単です。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))

    groups = []
    cnt = 1

    for i in range(1, n):
        if a[i] == a[i - 1]:
            cnt += 1
        else:
            groups.append(cnt)
            cnt = 1

    groups.append(cnt)

    ans = 0
    for i in range(len(groups) - 1):
        ans = max(ans, 2 * min(groups[i], groups[i + 1]))

    return str(ans) + "\n"

assert run("7\n2 2 2 1 1 2 2\n") == "4\n", "sample 1"
assert run("9\n2 2 1 1 1 2 2 2 2\n") == "6\n", "sample 2"

assert run("2\n1 2\n") == "2\n", "minimum size"
assert run("5\n1 1 1 1 1\n") == "0\n", "all equal values"
assert run("6\n1 2 1 2 1 2\n") == "2\n", "alternating values"
assert run("8\n2 2 2 2 1 1 1 1\n") == "8\n", "large single boundary"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`2 / 1 2`|`2`| 可能な最小の有効な遷移 |
 |`5 / 1 1 1 1 1`|`0`| 境界は存在しません |
 |`6 / 1 2 1 2 1 2`|`2`| 交互の値は長いセグメントを形成できません。 
|`8 / 2 2 2 2 1 1 1 1`|`8`| 配列全体が 1 つの有効なセグメントです。 

## 特殊なケース

 すべての寿司タイプが同一である配列の場合、タイプが変わるポイントがないため、有効なセグメントは存在できません。 

例：```
5
1 1 1 1 1
```アルゴリズムは 1 つのグループを作成します。```
[5]
```比較する隣接グループがないため、答えはそのままです`0`。 

寿司の種類を交互に切り替える場合:```
6
1 2 1 2 1 2
```グループは次のとおりです。```
[1, 1, 1, 1, 1, 1]
```すべての境界は、一定の長さのセグメントのみを作成できます`2 * min(1, 1)`したがって、最大値は`2`。 これにより、両方のタイプの等しい数を十分なものとして誤って扱うことがなくなります。 

大きな境界が 1 つある場合:```
8
2 2 2 2 1 1 1 1
```グループは次のとおりです。```
[4, 4]
```アルゴリズムはそれらを比較し、以下を取得します。```
2 * min(4, 4) = 8
```2 つの半分は両方とも 1 種類の寿司から作られているため、これが配列全体です。
