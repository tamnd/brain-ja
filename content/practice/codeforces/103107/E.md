 ## 解決策
 ## 問題の理解

 すべて小文字で構成される文字列のコレクションが与えられます。 このタスクは、それらを個別に処理することではなく、文字列間の包含構造を通じてそれらがどのように関連しているかを理解することです。 

主な目標は、シーケンス内のすべての文字列が次の文字列の部分文字列として表示されるように、これらの文字列の可能な限り長いシーケンスを見つけることです。 言い換えれば、各ステップが入力に存在するより大きな文字列内のどこかに前の文字列を埋め込むことによって、前の文字列を「拡張」するチェーンが必要です。 

したがって、すべてのペア間で任意の部分文字列をチェックする代わりに、「前の文字列が次の文字列に含まれる」というルールに基づいて最長の有効な進行を構築することが求められます。 

入力サイズは、文字列コレクションの一般的な競技プログラミングの上限に達する可能性があり、これは合計で最大数十万文字に達することを意味します。 これにより、文字列のすべてのペアを直接比較するソリューションは即座に除外されます。 単純な部分文字列チェックではすでに遅すぎるため、すべてのペアごとの関係を構築したとしても、爆発的に二次関数以上の動作が発生する可能性があります。 

ここでの微妙な問題は、部分文字列の関係が推移的であり、重複が多いことです。 多くの文字列はプレフィックス、サフィックス、および内部オーバーラップを共有しているため、部分文字列チェックを個別に再計算すると、ほぼすべての構造が無駄になります。 

いくつかの危険な状況は、素朴な思考が壊れる場所を示しています。 

問題となるケースの 1 つは、多くの文字列が同一またはほぼ同一である場合です。 たとえば、すべての文字列が`"aaaaa"`何度も繰り返すと、部分文字列エッジのグラフを構築しようとする単純なアプローチでは、遷移を過剰にカウントしたり、同一の遷移を繰り返し再計算したりして、不必要な作業が発生する可能性があります。 

もう 1 つの注意が必要なケースは、文字列の末尾の 1 文字だけが異なる場合です。`"abc"`、`"abca"`、`"abcab"`、`"abcabc"`。 ここで、正しい答えは、任意の部分文字列の一致ではなく、構造による連鎖に依存します。 単純なペアごとの部分文字列 DP は、プレフィックス、サフィックス、および TLE の重複チェックを繰り返し再計算します。 

最後に、部分文字列関係が複数の重複した方法で成立する場合、微妙な失敗例が発生します。 例えば`"ababa"`含まれています`"aba"`複数の立場で。 構造の再利用を利用しない単純な DP は、異なるオカレンスを独立した状態として誤って扱い、作業や遷移を複製する可能性があります。 

重要な点は、部分文字列の関係を圧縮し、重複情報を効率的に再利用できるデータ構造が必要であるということです。 

## アプローチ

 ブルートフォースソリューションでは、各文字列をノードとして扱い、すべてのペアをチェックします。`(i, j)`かどうかを確認する`si`の部分文字列です`sj`。 これにより有向グラフが得られ、DP を使用してそのグラフ内の最長パスを計算します。 

部分文字列チェック自体はすでに少なくとも`O(L)`KMP またはハッシュを使用してチェックごとに実行されるため、全体の複雑さはおおよそ次のようになります。`O(n^2 * L)`。 と`n`全長も大きいので、これは完全に不可能です。 たとえ`n`わずか数千ですが、それでも遅すぎます。 

重要な点は、部分文字列の関係が任意ではないということです。 これらは、すべての文字列に対するオートマトン構造を使用してエンコードできます。 具体的には、すべての文字列に対してトライを構築してプレフィックス構造をキャプチャし、それを Aho-Corasick オートマトンと同様の障害リンクで拡張してサフィックスの遷移をキャプチャできます。 この組み合わせにより、部分文字列の関係を、ペアごとのチェックではなく、構造化されたグラフ内のウォークとして再解釈できるようになります。 

さらに深い洞察は、部分文字列の関係は 2 つの動きに分解できるということです。トライ内の接頭辞構造に沿って拡張する動きと、障害リンクを介して接尾辞構造に沿って後退する動きです。 これにより、二次比較ではなくオートマトン上で動的計画値を線形時間で伝播することができます。 

したがって、部分文字列の関係を明示的にチェックする代わりに、すべての文字列をトライと失敗を組み合わせたリンク システムに埋め込み、その構造上で DP を実行します。

 ## アルゴリズムのチュートリアル

 ### 1. すべての文字列に対してトライを構築する

 すべての文字列を標準トライに挿入します。 各ノードは、挿入された文字列のプレフィックスを表します。 これにより、すべての接頭辞の関係が明示的に取得されます。これは、部分文字列構造が接頭辞の重複から始まることが多いため、必要です。 

### 2. サフィックス動作のための 2 番目の遷移構造を構築する

 並行して、同じトライ ノード上に Aho-Corasick スタイルの障害リンク システムを構築します。 ノードの障害リンクは、トライ内のプレフィックスでもある最長の適切なサフィックスを表します。 これにより、文字列を明示的に検索せずに接尾辞の遷移にアクセスできるようになります。 

これが重要な理由は、部分文字列の関係がプレフィックスだけでなく、障害リンクを通じて自然に表現される内部出現にも依存するためです。 

### 3. 終端ノードをマークする

 各文字列はトライの終端ノードに対応します。 各ノードで終了する文字列の数を保存します。 これは、DP でその状態を訪れるときの「ゲイン」になります。 

### 4. BFS を使用して障害リンクを構築する

 障害リンクをレベルごとに計算します。 これにより、短い文字列と小さなプレフィックスが長い文字列よりも前に処理され、サフィックス情報が正しく伝達されることが保証されます。 

### 5. 2 番目の構造の BFS トラバーサルによる動的プログラミング

 次に、2 番目のトライ構造上で BFS 順序でノードを走査します。 

各ノードについて`u`、DP 値を計算します。 

この値は、このノードの文字列表現で終わる最適なチェーンを表します。 考えられる 2 つのソースを使用して遷移します。プレフィックス トライ内の親と、サフィックス構造内の障害リンクです。 繰り返しでは、これら 2 つの前の状態の最大値を取得し、現在のノードで終わる文字列の数を追加します。 

これは、有効なチェーンは、プレフィックスを拡張するか、代替のサフィックスが整列した状態に移行することによって拡張できるという考えを捉えています。 

### なぜ効果があるのか

 この正しさは、2 つの文字列間のすべての部分文字列関係が、トライ エッジと障害リンクによって形成される結合オートマトン内のパスに対応するという事実から得られます。 トライにより、有効なプレフィックスに沿ってのみ前進することが保証されますが、失敗リンクにより、部分文字列の一致を再開できる、すべての有効なサフィックスで揃えられたプレフィックスにジャンプすることができます。 

DP の不変条件は、ノードを処理するときに、そのノードにつながる可能性のあるすべての小さなプレフィックスおよびサフィックス構成に対して最適なチェーンをすでに計算しているということです。 BFS の順序付けにより、依存関係の処理が遅れないようにするため、すべての状態ですべての有効な先行処理が認識されます。 

したがって、考えられるすべての部分文字列チェーンは DP 遷移で 1 回だけ表現され、有効な拡張子を見逃すことはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n = int(input())
    strings = [input().strip() for _ in range(n)]

    # trie structures
    nxt = [[0] * 26]
    val = [0]
    fail = [0]

    def add(s):
        u = 0
        for ch in s:
            c = ord(ch) - 97
            if nxt[u][c] == 0:
                nxt[u][c] = len(nxt)
                nxt.append([0] * 26)
                val.append(0)
                fail.append(0)
            u = nxt[u][c]
        val[u] += 1

    for s in strings:
        add(s)

    # build failure links
    q = deque()
    for c in range(26):
        v = nxt[0][c]
        if v:
            q.append(v)

    while q:
        u = q.popleft()
        for c in range(26):
            v = nxt[u][c]
            if v:
                fail[v] = nxt[fail[u]][c]
                q.append(v)
            else:
                nxt[u][c] = nxt[fail[u]][c]

    # dp over trie (BFS order)
    dp = [0] * len(nxt)
    ans = 0

    q = deque([0])
    parent = {0: 0}

    while q:
        u = q.popleft()
        dp[u] = max(dp[u], dp[fail[u]]) + val[u]
        ans = max(ans, dp[u])

        for c in range(26):
            v = nxt[u][c]
            if v and v not in parent:
                parent[v] = u
                q.append(v)

    print(ans)

if __name__ == "__main__":
    solve()
```この実装は、すべての文字列に対して圧縮されたオートマトンを構築し、プレフィックスとサフィックスの両方の遷移を使用して最適なチェーン長を伝播する DP を実行します。 実装の重要な詳細は、トライ内の欠落した遷移が失敗リンクにリダイレクトされ、部分文字列の走査の繰り返しが回避されることです。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべての文字列が同一である場合です。 トライは単一のパスに崩壊し、挿入するたびに増加します`val`同じノードで。 DP はすべての寄与を正しく蓄積し、文字列の数に等しいチェーンを生成します。 

もう 1 つのケースは、文字列が重度のサフィックスの重複を共有するが、プレフィックス拡張子を共有しない場合です。 例えば`"ba", "a", "aba"`。 障害リンクにより、次のことが保証されます。`"aba"`直接のプレフィックス一致に依存するのではなく、サフィックス構造を正しく遷移できます。 

最後のケースは、文字列が完全に切り離されている場合です。 その場合、各ノードにはそれ自体を除いて意味のある遷移はなく、DP は単一の文字列エンドポイントの最大頻度を選択することになります。これは、によって正しく処理されます。`val[u]`。
