 ## 解決策
 ## 問題の理解

 数字列が与えられます。 長さのすべての部分文字列に対して正確に`k`、1 回の圧縮操作を実行した後、可能な最小の長さを計算する必要があります。 

圧縮は、文字列を偶数の空でない部分に分割することによって定義されます。$$t_1,t_2,t_3,t_4,\dots$$各ペアを交換します$(t_{2i-1},t_{2i})$文字列によって$t_{2i}$繰り返された$t_{2i-1}$回。 最終的な長さのみが重要であるため、1 つのペアの寄与は次のようになります。$$(\text{numeric value of } t_{2i-1}) \cdot |t_{2i}|.$$タスクは、可能な最小の合計貢献度を見つけることです。 

最初の障害は入力のサイズです。 文字列の長さは次のとおりです$2\cdot10^5$、そして私たちは答えが必要です$n-k+1$窓。 動的プログラムをウィンドウごとに独立して再計算するアルゴリズムは絶望的です。 平$O(k)$ウィンドウごとの作業量は$O(nk)$、すでに存在しています$4\cdot10^{10}$最悪の場合の運用。 

最大の難点は、分割位置が固定されていないことです。 パーティションを最適化し、すべてのスライディング ウィンドウ クエリに同時に答える必要があります。 

明白ではない構造上の事実は、すべての最適解では、奇数のインデックスが付いた長さの部分が 1 つだけ使用されるということです。 奇数の部分に少なくとも 2 桁の数字が含まれているとします。 次のように書きます$10a+b$、 どこ$b$は最後の桁で、次の偶数部分の長さをとします$L$。 このペアの貢献度は、$$(10a+b)L.$$最後の桁を移動$b$奇数部分から偶数部分の前まで。 新しい貢献は次のようになります$$a(L+1).$$新しい値は常に小さいため、すべての奇数部分が 1 桁になるまで、最適なパーティションを改善できます。 この観察が、問題が扱いやすくなる理由のすべてです。 

よくある間違いは、DP 状態内で複数桁の奇数の部分を許可することです。 たとえば、`"5999"`の使用を検討するかもしれません`"59"`乗数として。 乗算器から反復ブロックに桁を移動すると常にコストが削減されるため、これは決して役に立ちません。 

もう 1 つの微妙なケースは、次のようなウィンドウです。`"111"`。 最適なパーティションは、`"1" | "11"`、長さを与える$2$。 すべてのキャラクターを独立して扱うと、$3$、これは最適ではありません。 

## アプローチ

 単一の固定文字列の場合、すべてのパーティションを乗算器ブロックと反復ブロックに交互に分割するという自然な総当たりのアイデアが考えられます。 パーティションの数は指数関数的なものであるため、これは正確性の参照としてのみ役立ちます。 

上記の構造補題によって状況は完全に変わります。 すべての奇数ブロックの長さは 1 であるため、文字列のスキャン中に重要な情報は現在アクティブな乗数の桁だけです。 

これにより、9 つの意味のある乗算状態のみを含む動的計画法が作成されます。 

ブルート フォースはすべての有効なパーティションを探索するため成功します。 その失敗は明らかです。長さ 100 の文字列でも、すでに天文学的な数のパーティションが存在します。 

すべての乗算器ブロックの長さが 1 であるという観察により、問題は一定数の状態に関する最短パス スタイルの DP に変換されます。 DP の次元が一定になると、すべての文字を min-plus 遷移行列として表すことができます。 部分文字列の答えは、連続した区間にわたる行列の積になります。 

今では、問題は文字列に関するものではなくなりました。 それは次のようになります:

 「一連の小さな最小プラス行列を与えて、長さのすべての区間の積を計算します`k`。」

 セグメント ツリーも機能しますが、それでも実行する行列の乗算が多すぎます。 重要な点は、すべてのクエリの長さが同じであるということです。 行列シーケンスをあるサイズのブロックに分割する`k`各クエリは、最大 1 つのサフィックス製品と 1 つのプレフィックス製品を使用して回答できます。 行列乗算の総数は線形になります。

 ## アルゴリズムのチュートリアル

 1. 最適なパーティション内のすべての奇数インデックス付きブロックの長さが正確に 1 であることを証明します。 
2. 現在の乗数の桁を状態に格納する DP を構築します。 
3. しましょう`dp[i][d]`最初の処理後の最小コストになります`i`文字と乗数桁を持つ`d`。 
4. 2 つの遷移が存在します。 

文字は現在の偶数ブロックを拡張することができます。 これにより、答えは次のように増加します`d`。 

キャラクターは新しいマルチプライヤーブロックを開始することができます。 前の偶数ブロックが終了し、新しい乗数が前の文字になります。 
5. これらの遷移を min-plus 行列としてエンコードします。 
6. DP に必要な最小値を格納する 2 つの補助状態を導入します。 これにより、$11\times11$すべての位置の行列。 
7. 任意の部分文字列について、答えは、その行列の積を固定の初期ベクトルに適用し、指定された 1 つの状態を読み取ることと同じです。 
8. 行列シーケンスを一定のサイズのブロックに分割します`k`。 
9. すべてのブロック内で、プレフィックス積とサフィックス積を事前計算します。 
10.窓用`[l,r]`:

 ウィンドウがブロック境界で始まる場合、その行列積は格納されたプレフィックス積になります。 

それ以外の場合、ウィンドウはちょうど 1 つのブロック境界を横切るため、その積は次のようになります。$$\text{suf}[l]\cdot \text{pre}[r].$$11. 積を初期ベクトルに適用し、結果の応答状態を出力します。 

### なぜ効果があるのか

 DP 状態は、将来の寄与を評価するために必要な情報、つまり現在の乗数の桁を正確に取得します。 偶数ブロックが拡張されるたびに、その桁がもう一度寄与されます。そのため、乗算器では遷移コストが線形になります。 

構造補題により、最適な解決策が除外されないことが保証されます。 すべての有効な最適パーティションは DP を通るパスに対応し、すべての DP パスは有効なパーティションに対応します。 min-plus 行列積は、そのようなパスすべての中での最小コストを計算します。 

すべてのクエリ間隔が同じ長さであるため、ブロック分解は正しいです。`k`。 すべての間隔は、ブロック接尾辞とその後に続くブロック接頭辞全体と一致するか、完全に 1 つのブロック内にあります。 事前に計算された積は、区間積を正確に再構築します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10 ** 18
A = 11

def mul(X, Y):
    Z = [[INF] * A for _ in range(A)]
    for i in range(A):
        xi = X[i]
        zi = Z[i]
        for k in range(A):
            v = xi[k]
            if v >= INF:
                continue
            yk = Y[k]
            for j in range(A):
                nv = v + yk[j]
                if nv < zi[j]:
                    zi[j] = nv
    return Z

def vec_mul(vec, M):
    res = [INF] * A
    for i in range(A):
        if vec[i] >= INF:
            continue
        base = vec[i]
        row = M[i]
        for j in range(A):
            nv = base + row[j]
            if nv < res[j]:
                res[j] = nv
    return res

def solve():
    n, k = map(int, input().split())
    s = input().strip()

    base = [[INF] * A for _ in range(A)]

    for d in range(9):
        base[d][d] = d + 1
        base[d][10] = d + 1

    base[10][9] = 0

    mats = [None] * (n + 1)

    prev = 0
    for i in range(1, n + 1):
        cur = ord(s[i - 1]) - ord('1')
        M = [row[:] for row in base]
        M[9][prev] = prev + 1
        M[9][10] = prev + 1
        mats[i] = M
        prev = cur

    def block_id(pos):
        return (pos - 1) // k

    num_blocks = (n + k - 1) // k

    pre = [None] * (n + 1)
    suf = [None] * (n + 2)

    for b in range(num_blocks):
        L = b * k + 1
        R = min(n, (b + 1) * k)

        pre[L] = mats[L]
        for i in range(L + 1, R + 1):
            pre[i] = mul(pre[i - 1], mats[i])

        suf[R] = mats[R]
        for i in range(R - 1, L - 1, -1):
            suf[i] = mul(mats[i], suf[i + 1])

    start = [INF] * A
    start[10] = 0

    ans = []

    for l in range(1, n - k + 2):
        r = l + k - 1

        if (l - 1) % k == 0:
            prod = pre[r]
            cur = vec_mul(start, prod)
        else:
            cur = vec_mul(start, suf[l])
            cur = vec_mul(cur, pre[r])

        ans.append(str(cur[10]))

    print(" ".join(ans))

solve()
```実装は行列の定式化に直接に従います。 各位置は、1 つの疎な最小プラス遷移行列に寄与します。 行列の次元はわずか 11 なので、慎重に乗算を作成すれば十分高速です。 

プレフィックスとサフィックスの積は、長さの各ブロック内で個別に計算されます。`k`。 これが重要な最適化です。 セグメント ツリーでは、追加の対数因数とさらに多くの行列の乗算が導入されます。 

回答抽出ステップでは、すべてのクエリに対して同じ初期ベクトルを使用します。 ウィンドウ間の唯一の違いは、その間隔を表す行列積です。
