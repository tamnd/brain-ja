 ## 解決策
 ## 問題の理解

 それぞれが正のサイズを持つスライムの列が与えられています。 スライムは、シンプルだが制約された方法で相互作用します。スライムは、厳密に大きい場合、隣接するスライムを食べることができ、食べると、食べたスライムのサイズに応じて成長します。 このプロセスは、隣のスライムを食べることができるスライムが少なくとも 1 つ存在する限り続きます。 スライムごとに、食べられるまでの最小秒数を決定するか、食べられない場合は -1 を報告する必要があります。 

入力サイズは以下に達します$3 \cdot 10^5$単一のテスト ケース内のスライム$10^4$テストケース。 これは、あらゆる可能な動きをチェックする総当りシミュレーションは実行不可能であることを意味します。 素朴なアプローチでは、$O(n^2)$時間制限を超える可能性のあるテスト ケースごとの操作。 考えられるすべての食事シーケンスをシミュレートすることなく、各スライムが最も早く食べられる時間を効率的に推定できる方法が必要です。 

スライムのサイズが等しい場合、またはスライムが極大値である場合には、明らかではないエッジ ケースが発生します。 たとえば、次の場合$a = [2, 2, 2]$、どのスライムも隣を食べることができないため、すべての出力は -1 になります。 もし$a = [1, 3, 1]$、中央のスライムはどちらかの隣をすぐに食べることができるため、両方の隣の1ステップ時間が発生しますが、中央のスライム自体は食べることができないため、結果は-1になります。 サイズの順序を無視したり、線形の成長を仮定したりする不注意な実装は、ここで誤った答えを生み出す可能性があります。 

## アプローチ

 ブルートフォースソリューションでは、プロセスを段階的にシミュレートします。 毎秒、隣接するすべてのペアをチェックして、一方がもう一方を食べることができるかどうかを確認し、サイズと位置を更新し、各スライムが食べられた時間を記録します。 これは原理的には正しく動作しますが、遅すぎます。 単一のテスト ケースの場合、$n = 3 \cdot 10^5$、比較の数はおよそに達します$O(n^2)$、それは約です$9 \cdot 10^{10}$実際には不可能です。 

重要な洞察は、スライムは厳密に大きな隣人によってのみ食べられるということです。 したがって、各スライムについて、中間のスライムが最初に食べられて大きなスライムの到達範囲が増える可能性があることを考慮して、その左または右に最も近い大きなスライムを見つける必要があります。 これにより、問題は両方向の「次に大きな要素」の問題の一種に縮小されます。 

スタックを使用して線形時間でこれを効率的に計算できます。 スライムを左から右に処理して、左から食べられる最小時間を決定し、右から右から左へ食べられる時間を決定します。 食事時間は、大きな隣のスライムがスライムに到達するまでにかかる歩数であり、最初に消費する必要がある小さなスライムの数によって捕らえられます。 サイズが厳密に増加するスライムのスタックを維持することで、各スライムに到達するまでの歩数を記録しながら、一定の償却時間で小さなスライムをすべてポップできます。

 ## アルゴリズムのチュートリアル

 1. 配列を初期化する`ans`サイズの$n$-1 は、最初はスライムを食べられないことを表します。 
2. ヘルパー関数を定義する`process_direction(slimes)`一方向の最小食事時間を計算します。 この関数はスタックを使用してペアを維持します`(size, time)`今後のスライムを食べる可能性があるスライムを表します。 スライムごとに次のことを行います。 

ａ． 初期化する`time = 1`。 スタックが空ではなく、一番上のスライムのサイズが現在のスライム以下である場合、スタックをポップして更新します。`time`に`max(time, popped_time + 1)`。 このステップは、現在のスライムが最終的にこの方向からのより大きなスライムに食べられるまでにかかるステップ数を累積します。 

b. ポップ後にスタックが空でない場合は、`ans[i]`に`time`現在の値より小さい場合。 

c. 押す`(current_size, time)`スタックに。 
3. 走る`process_direction`左から右へ、左隣の影響から最小の食事時間を見つけます。 
4. 走る`process_direction`右から左へ、右隣の影響から最小の食事時間を見つけます。 
5. を出力します。`ans`配列。 

**機能する理由:** 各スライムは厳密に大きなスライムによってのみ食べることができ、間に介在する小さなスライムがすべて消費された後にのみ到達できます。 このスタックにより、各方向で大きなスライムに到達するために必要な最小ステップ数が正確に計算されます。 両方向を処理することで、どちらかの近隣からの最も早い時間を考慮することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        ans = [-1] * n

        def process_direction(arr):
            stack = []
            res = [-1] * n
            for i, val in enumerate(arr):
                time = 1
                while stack and stack[-1][0] <= val:
                    time = max(time, stack.pop()[1] + 1)
                if stack:
                    res[i] = time
                stack.append((val, time))
            return res

        left = process_direction(a)
        right = process_direction(a[::-1])[::-1]

        final = [max(l if l != -1 else 0, r if r != -1 else 0) or -1 for l, r in zip(left, right)]
        print(' '.join(map(str, final)))

if __name__ == "__main__":
    solve()
```機能`process_direction`片側から最小ステップを効率的に計算します。 配列を反転すると、反対側にも同じロジックを使用できます。 左右の結果を組み合わせると、各スライムは最初に到達できる隣のスライムによって食べられるため、両方の時間を最大値とします。
