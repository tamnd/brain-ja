 ## 解決策
 ## 問題の理解

 キャラクターが位置 0 にあり、モンスターがいくつかの座標に配置されている線があります。$x_i$、それぞれが健康を持って$a_i$。 毎秒、次のことを実行できます$k$弾丸を使用して、選択したモンスターの体力を減らします。 発砲後、体力がプラスでないモンスターは死亡し、残りのモンスターはすべてキャラクターに向かって一歩進みます。 モンスターが0になったら負けです。 

入力では複数のテスト ケースが提供され、それぞれがモンスターの数を指定します。$n$、1秒あたりの弾数$k$、各モンスターの体力、および開始位置。 目標は、モンスターが到達する前にすべてのモンスターを倒すことができるかどうかを決定することです。 

制約は重要です。$n$到達できる$3 \cdot 10^5$すべてのテストケースの合計、および$k$そして$a_i$と同じ大きさにすることができます$10^9$。 これにより、モンスターごとに 1 秒ごとを個別にシミュレートするアルゴリズムは除外されます。 単純なアプローチでは、何十億回もの反復が必要になる可能性があります。 エッジケースは、モンスターが 0 に非常に近い状態から始まる場合、または少数のモンスターの体力が相対的に大きい場合に発生します。$k$非効率的に弾を発射すると、モンスターを倒す前にモンスターが 0 に達してしまう可能性があるためです。 

弾丸を任意に、または入力順に発射する単純な実装は失敗する可能性があります。 たとえば、モンスターが位置 1 にいて体力 5 の場合、$k=2$、別のモンスターが体力 1 で位置 5 にあるとき、最初に遠くのモンスターに発砲すると、近くのモンスターが 0 に達して私たちを殺すことができます。 正しい戦略では、健康状態と距離の両方を考慮する必要があります。 

## アプローチ

 ブルートフォース手法では、秒ごとにシミュレーションが行われます。生きているモンスターごとに、撃つモンスターを選択し、体力を減らし、死んだモンスターを取り除き、残りのモンスターを近づけます。 これは正しいですが、実行不可能です。 最悪の場合、$n=3\cdot 10^5$健康を持ったモンスター$10^9$、秒ごとに繰り返すと、次の順序になります。$10^{14}$操作。 

重要な洞察は、モンスターの「有効距離」を考慮することです。 遠くにいる怪物$x_i$健康とともに$a_i$少なくとも必要です$\lceil a_i / k \rceil$数秒間の集中砲火で殺される。 問題は貪欲な戦略に帰着します。モンスターを 0 からの距離で並べ替え (符号を無視)、最も遠いモンスターを最初に攻撃すると、距離バッファーが最大化され、予期せず 0 に到達するモンスターが存在しないことが保証されます。 すべての弾丸はあらゆるモンスターをターゲットにすることができるため、唯一の重要な要素は、モンスターが到達するまでに与えた累積ダメージがそれを倒すのに十分であるかどうかです。 

この観察により、距離別にソートされたモンスターを反復処理し、各モンスターが 0 になる前に発射できる弾丸がモンスターを倒すのに十分であるかどうかを確認できます。 アルゴリズムが機能するのは、$O(n \log n)$並べ替えのため、テスト ケースごとに。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(max(a_i) * n) | O(n) | 遅すぎる |
 | 距離に貪欲 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースごとに、モンスターを左側のモンスターに分けます ($x_i < 0$) と右 ($x_i > 0$）。 計算を簡素化するために、位置の絶対値を取得します。 
2. モンスターを距離 0 から大きい順に並べ替えます。 バッファー時間を最大化するために、最初に最も遠いモンスターを攻撃します。 
3. カウンタの初期化`total_damage`これまでに発射された累積弾丸を追跡します。 
4. 並べ替えたモンスターを繰り返し処理します。 

1. このモンスターの有効残り距離を計算します。`effective_distance = x_i - total_damage`。 これは、以前のモンスターにすでに発射された弾丸を考慮した後、0 に達するまでに残っているステップ数です。 
2. もし`effective_distance <= 0`、モンスターはすでに前の弾丸によって効果的に殺されています。 続く。 
3. それ以外の場合は、健康状態を確認してください`a_i`を超える`total_damage`。 もし`a_i > total_damage`、それはモンスターを倒す前にモンスターが0に達することを意味します。 この場合は「NO」を出力します。 
4. それ以外の場合は、追加します`a_i`に`total_damage`、事実上解雇されたことを表します`a_i`この怪物を倒すための弾丸。 
5. 0 に達しないモンスターをすべて処理する場合は、YES と出力します。 

機能する理由: 最も遠いモンスターを最初に攻撃することで、モンスターが 0 に達する前にバッファーが最大化されます。不変条件は、近くの脅威を無力化するのに十分なダメージをすでに蓄積しているため、各反復の後、現在のモンスターよりも遠いすべてのモンスターが 0 にならないことが保証されるということです。 小切手`effective_distance <= 0`これにより、弾丸がオーバーシュートせず、遠くのモンスターが以前のモンスターを「通過」しないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can_survive(n, k, health, pos):
    left = []
    right = []
    for a, x in zip(health, pos):
        if x < 0:
            left.append((-x, a))
        else:
            right.append((x, a))
    for group in [left, right]:
        group.sort(reverse=True)
        total_damage = 0
        for d, h in group:
            if d <= total_damage:
                continue
            h -= total_damage
            if h > 0:
                total_damage += h
    return "YES"

t = int(input())
for _ in range(t):
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    x = list(map(int, input().split()))
    
    left = []
    right = []
    for ai, xi in zip(a, x):
        if xi < 0:
            left.append((-xi, ai))
        else:
            right.append((xi, ai))
    
    def check(group):
        group.sort(reverse=True)
        total_damage = 0
        for d, h in group:
            if d <= total_damage:
                continue
            h -= total_damage
            if h > 0:
                total_damage += h
        return True
    
    if check(left) and check(right):
        print("YES")
    else:
        print("NO")
```説明: モンスターを横に分離し、位置を正の距離に変換します。 ソートにより、最も遠いモンスターから確実に処理されます。`total_damage`前のステップで発射された弾丸を考慮し、後続のモンスターの体力を効果的に減らします。 このアプローチでは、モンスター間で弾丸を最適に分配できるという洞察を利用して、毎秒の明示的なシミュレーションを回避します。 

## 実用的な例

 サンプル入力 1:```
3 2
1 2 3
-1 2 3
```| モンスター | 側面 | 距離 | 健康 | 合計ダメージ | 損傷後の健康 |
 | --- | --- | --- | --- | --- | --- |
 | 3 | 右 | 3 | 3 | 0 | 3 |
 | 2 | 右 | 2 | 2 | 3 | -1 |
 | 1 | 左 | 1 | 1 | 0 | 1 |

 最初に一番右のモンスター 3 を処理します。`h - total_damage = 3 - 0 = 3`、`total_damage += 3`。 モンスター２：距離２、`2 <= total_damage=3`、すでに取り扱い済みです。 モンスター１：距離１、`1 - total_damage=1 - 3 <=0`、また安全です。 はいを出力します。 

入力例 2:```
2 1
1 1
-1 1
```処理左：モンスター1、距離1、`h - total_damage=1 -0=1`、`total_damage +=1`。 次のモンスター (右): 距離 1、`h - total_damage =1 -1 =0`、 安全。 しかし、1 秒あたりの弾丸数 k=1 では、両方を十分に速く殺すことはできません。 アルゴリズムは NO を出力します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | 左辺と右辺のソートには O(n log n) かかります。 反復は O(n) です。 |
 | スペース | O(n) | モンスターと補助変数の 2 つのリストを保存します。 |

 テスト ケース全体の n の合計 ≤ 3 · 10^5、およびテスト ケースあたりの時間 O(n log n) を考慮すると、これは 2 秒に収まります。
