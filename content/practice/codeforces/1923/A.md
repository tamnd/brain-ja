 ## 解決策
 ## 問題の理解

 セルの列が与えられ、それぞれのセルにはチップが入っているか空です。 目標は、チップを繰り返し選択し、その左に最も近い空のセルに移動することにより、チップを左方向に移動して連続するグループにすることです。 タスクは、すべてのチップが単一の中断のないブロックを形成するために必要な最小移動数を決定することです。 

入力は複数のテスト ケースを提供します。 各テスト ケースには多数のセルがあります`n`(2 ～ 50) と、どのセルにチップが含まれているかを記述する配列。 各テスト ケースの出力は、必要な最小の手を表す単一の整数です。 

なぜなら`n`が最大 50 であれば、配列に対して単純なスキャンを数回行うアルゴリズムは効率的に実行されます。 と`t`最大 1000 のテスト ケースでは、各配列を線形時間で処理するソリューションが受け入れられます。 

この問題には微妙な特殊なケースがあります。 たとえば、すべてのチップがすでに連続している場合、移動は必要ありません。 左側に空のセルがある 1 つのチップがある場合は、移動する必要はありません。 すべての空のセルをカウントする、または盲目的に動きをシミュレートしようとする単純な実装では、**左端と右端のチップの間**の空のセルのみが問題となるため、カウントが過剰になる可能性があります。 例えば、`[0, 1, 0, 1, 0, 1, 0]`には 3 つのチップと 3 つのギャップがありますが、最初と最後のチップの間の 2 つのギャップだけを埋める必要があるため、必要な手は 2 つだけです。 

## アプローチ

 ブルートフォースアプローチは、プロセスを明示的にシミュレートすることです。連続したブロックが形成されるまでチップを選択し、左に移動することを繰り返します。 正しいのですが、正確な順序ではなく、最小限の移動数のみを考慮しているため、これは不要です。 それぞれの動きをシミュレートすることは、小さな配列であっても非効率的であり、off-by-one エラーが発生する危険があります。 

重要な観察は、**最初と最後のチップの間**の空のセルのみが移動に寄与するということです。 左端のチップの左側または右端のチップの右側にある空のセルは、そこにチップが移動しないため、埋める必要はありません。 したがって、最小移動数は単に最初と最後のチップの間のゼロの数になります。 

これにより、最初と最後のチップのインデックスを見つけるために配列を 1 回スキャンし、そのサブ配列内のゼロをカウントするという問題が軽減されます。 このソリューションは線形で実装が非常に簡単で、単純なシミュレーションの落とし穴を回避します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | テスト ケースあたり O(n²) | O(n) | やりすぎ/不要 |
 | 最初と最後のチップ間のゼロを数える | テスト ケースあたり O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る`t`。 
2. 各テスト ケースについて、次の内容を読んでください。`n`そして配列`a`。 
3. 左から右にスキャンして、一番左のチップを特定します。 そのインデックスを次のように保存します`first`。 
4. 右から左にスキャンして、右端のチップを特定します。 そのインデックスを次のように保存します`last`。 
5. カウンタの初期化`moves`ゼロに。 
6. 反復処理`first`に`last`。 各セルについて、セルが空の場合 (`0`)、増分`moves`。 
7. スキャン後、`moves`必要な最小限の操作数が保持されるようになりました。 印刷してください。 

機能する理由: チップを左に移動すると、空のセルを 1 つだけ埋めることができます。 すべての動きは独立しており、最初と最後のチップの間のゼロのみが重要であるため、それらをカウントすることで最小の動き数が得られます。 このカウントをさらに減らすことはできず、この範囲外に移動する必要はありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    
    first = a.index(1)  # leftmost chip
    last = len(a) - 1 - a[::-1].index(1)  # rightmost chip
    
    moves = 0
    for i in range(first, last + 1):
        if a[i] == 0:
            moves += 1
    print(moves)
```ソリューションでは、`list.index`最初のチップを見つけるためにスキャンし、最後のチップを見つけるために逆スキャンを行います。 これらのインデックス間の反復では、すべての空のセルがカウントされます。これは、必要な移動数に直接対応します。 余分な配列は作成されず、すべての操作はテスト ケースごとに O(n) です。 配列を反転して最後のインデックスを見つけることは安全です。`n <= 50`。 

## 実用的な例

 入力例:`[0, 1, 1, 1, 0, 1, 1, 0]`| 私 | a[i] | 動く |
 | --- | --- | --- |
 | 1 | 1 | 0 |
 | 2 | 1 | 0 |
 | 3 | 1 | 0 |
 | 4 | 0 | 1 |
 | 5 | 1 | 1 |
 | 6 | 1 | 1 |

 説明: 最初のチップはインデックス 1 にあり、最後のチップはインデックス 6 にあります。それらの間には 0 が 1 つだけあります (インデックス 4)。`moves = 1`。 

別の例:`[1, 0, 1, 0, 1]`| 私 | a[i] | 動く |
 | --- | --- | --- |
 | 0 | 1 | 0 |
 | 1 | 0 | 1 |
 | 2 | 1 | 1 |
 | 3 | 0 | 2 |
 | 4 | 1 | 2 |

 説明: 最初のチップは 0、最後のチップは 4 です。位置 1 と 3 にはゼロがあります。両方とも埋める必要があるため、最小移動は 2 です。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(t * n) | 各テスト ケースは配列を 2 回スキャンします。最初のチップで 1 回、最後のチップで 1 回、そしてその間のゼロをカウントするために 1 回です。 各スキャンは O(n) です。 |
 | スペース | O(n) | 入力配列のみが保存されます。 ループ変数以外に追加のデータ構造はありません。 |

 と`t <= 1000`そして`n <= 50`、最悪の場合の操作数は 50,000 であり、2 秒の制限内に十分収まります。 メモリの使用量はごくわずかです。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = []
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        first = a.index(1)
        last = len(a) - 1 - a[::-1].index(1)
        moves = sum(1 for i in range(first, last + 1) if a[i] == 0)
        output.append(str(moves))
    return "\n".join(output)

# provided samples
assert run("5\n8\n0 1 1 1 0 1 1 0\n6\n0 1 0 0 0 0\n6\n1 1 1 1 1 1\n5\n1 0 1 0 1\n9\n0 1 1 0 0 0 1 1 0\n") == "1\n0\n0\n2\n3"

# custom tests
assert run("2\n2\n1 0\n3\n0 1 0\n") == "0\n0"  # minimal n, single chip
assert run("1\n6\n0 0 1 0 1 0\n") == "2"  # zeros outside first/last ignored
assert run("1\n7\n1 0 0 0 0 0 1\n") == "5"  # all
```
