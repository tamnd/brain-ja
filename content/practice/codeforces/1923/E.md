 ## 解決策
 ## 問題の理解

 私たちに与えられた木は、`n`ノード間の整数で色分けされたノード`1`そして`n`。 このタスクは、最初と最後のノードが同じ色を持ち、この色を共有する中間ノードが存在しないような、少なくとも 2 の長さの単純なパスの数を数えることです。 パスは無向であるため、ノードからのパス`x`ノードへ`y`からのパスと同等です`y`に`x`。 

入力は複数のテスト ケースを提供します。各テスト ケースは頂点の数、色のリスト、および`n-1`有効なツリーを形成するエッジ。 出力は、美しいパスの数を表すテスト ケースごとの 1 つの整数です。 

制約は次のことを示します`n`まで到達できます`2 * 10^5`すべてのテストケースにわたって。 すべてのノードのペアを検査したり、すべてのパスを列挙したりする単純なアプローチでは、O(n^2) 以上の処理が必要となり、上限については非現実的です。 私たちは、線形または線形に近いアプローチを目指す必要があります。`n`テストケースごとに。 

微妙なエッジケースには次のようなものがあります。 

1. すべての頂点が同じ色を持つため、すべてのエッジが美しいパスになりますが、長いパスが複数回カウントされるのを防ぎます。 例：`n=4, colors=[2,2,2,2]`3 つの美しいパス (すべて単一エッジ) が生成されます。 
2. 各ノードが固有の色を持つ木。つまり、1 つの端よりも長いパスは美しくありません。 例：`n=5, colors=[1,2,3,4,5]`美しいパスは 0 つ生成されます。 
3. 連結コンポーネント内で色が 2 回以上出現するパス。 「中間ノードが色を共有しない」という制限を無視した不注意なアプローチでは、パスが二重にカウントされる可能性があります。 

## アプローチ

 ブルートフォース手法では、ノードのすべてのペアに対して反復処理が行われます。`(u, v)`、それらの間のパス（木に特有のもの）を見つけて、着色状態を確認します。 おおよそ n*(n-1)/2 のペアがあるため、最悪の場合のツリーに対して O(n^2) の操作が必要になります。 各パスをチェックすると、単純な DFS トラバーサルでは O(n) のコストがかかる可能性があり、これは O(n^3) にスケールされ、完全に実行不可能です。 

重要な洞察は、ツリーでは、単純なパスはその端点によって一意に決定され、美しいパスは同じ色のノードの位置によって制約されるということです。 特定の色のノードをすべて削除すると`c`、ツリーは接続されたコンポーネントに分割されます。 色付きのノードの各ペア`c`異なるコンポーネントに属するコンポーネントは、他の色のノードを介してそれらを接続する有効な美しいパスを持つことができません。 

したがって、色ごとに視点を逆にすることができます。`c`、色のノードをすべて削除した後、さまざまなコンポーネントのノードを接続するエッジの数を数えます。`c`。 このような各エッジは、美しいパスの潜在的な開始セグメントまたは終了セグメントを表します。 組み合わせカウントと DFS を使用して接続コンポーネントのサイズを効率的に追跡し、テスト ケースごとに問題を O(n) に削減します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) または O(n^3) | O(n) | 遅すぎる |
 | 最適な DFS + カラー コンポーネント | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る`t`。 テスト ケースごとに、次の内容を読んでください。`n`、色のリスト、および`n-1`エッジ。 
2. ツリーを表す隣接リストを作成します。 
3. 各色をその色を持つノードのリストにマッピングする辞書を初期化します。 
4.各色ごとに`c`、すべてのノードを色でマークします`c`ブロックされているため、残りのノードで DFS を実行して、接続されているコンポーネントを見つけます。 各コンポーネントのサイズを数えます。 
5. しましょう`total_nodes = n`。 サイズの各コンポーネントについて`s`、色付きの美しいパスの数`c`このコンポーネントを通過するのは、`s * (total_nodes - s)`なぜなら、各色のノードは`c`コンポーネントの外側は、「中間色なし」ルールに違反することなく、内側のノードとペアにすることができます。 
6. すべてのコンポーネントのこれらの寄与を合計し、2 で割って、パスの二重カウントを修正します。 
7. 個別の色ごとに手順 4 ～ 6 を繰り返します。 
8. テストケースの結果を出力します。 

機能する理由: 特定の色のノードをすべて削除し、残りの接続コンポーネントを考慮することで、この色のノードで開始および終了するパスには同じ色の中間ノードが含まれないことが保証されます。 コンポーネント サイズを介してパスをカウントすると、パスを明示的に列挙することなく、すべての有効なペアが取得されます。 各パスは各エンドポイントから 1 回カウントされるため、2 で割ることで二重カウントが修正されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(1 << 25)

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        colors = list(map(int, input().split()))
        adj = [[] for _ in range(n)]
        for _ in range(n-1):
            u, v = map(int, input().split())
            u -= 1
            v -= 1
            adj[u].append(v)
            adj[v].append(u)

        from collections import defaultdict

        color_nodes = defaultdict(list)
        for i, c in enumerate(colors):
            color_nodes[c].append(i)

        result = 0
        visited = [False] * n

        def dfs(u):
            visited[u] = True
            size = 1
            for v in adj[u]:
                if not visited[v] and blocked[v] == False:
                    size += dfs(v)
            return size

        for c, nodes in color_nodes.items():
            blocked = [False] * n
            for node in nodes:
                blocked[node] = True
            visited = [False] * n
            for i in range(n):
                if not visited[i] and not blocked[i]:
                    s = dfs(i)
                    result += s * (n - s)
        print(result // 2)

if __name__ == "__main__":
    solve()
```このソリューションでは、まず隣接リストを構築し、次に各色を個別に処理します。 DFS は、現在の色のノードをブロックした後のコンポーネント サイズをカウントするために使用されます。 コンポーネントのサイズに外側のノードの数を乗算すると、美しいパスを形成できるすべてのコンポーネント間のパスが取得されます。 2 で除算すると、各パスに方向性がないため、二重カウントが回避されます。 

## 実用的な例

 サンプル入力 1:```
3
1 2 1
1 2
2 3
```主要な変数のトレース:

 | ノード | 色 | コンポーネントのサイズ (カラー 1 をブロックした後) | 貢献 |
 | --- | --- | --- | --- |
 | 1 | 1 | [2] | 2*(3-2)=2 |
 | 3 | 1 | すでに数えられています | 0 |

 結果 = 1 (二重にカウントするために 2 で割ります)

 入力例 2:```
5
2 1 2 1 2
1 2
1 3
3 4
4 5
```カラー 1 と 2 を処理した後、コンポーネント サイズは合計 6、2 で割って 6 → 3 の美しいパスを生成します。 このテーブルには、カラー 1: [2,2]、カラー 2: [3] のコンポーネントがリストされ、有効なパス数にマッピングされます。
