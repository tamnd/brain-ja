 ## 解決策
 ## 問題の理解

 私たちは、パン屋で数日間にわたって古くなったパンの量を計算するように求められました。 パン屋では毎日決まった数のパンが生産され、需要がわかっている顧客が毎日やって来ます。 パンは先入れ後出し方式で販売されます。焼きたてのパンが最初に販売され、売れ残った古いパンがその後に販売されます。 最終日を過ぎて残ったパンは販売され、パンの腐敗は販売前に保管された日数として定義されます。 このパン屋の魅力のなさは、あらゆるパンの中で最も傷んでしまうことだ。 

入力は日数で構成されます`n`、潜在的な顧客需要値の数`m`、毎日の生産リスト`a`サイズの`n`、および潜在的な顧客の需要の昇順リスト`k`。 それぞれについて`k_i`、正確に言うと、最大の破損を計算する必要があります。`k_i`顧客は毎日到着します。 

制約は次のことを示します`n`そして`m`それぞれ最大 200,000 個に達し、毎日の生産量と顧客の需要は 10^9 に達する可能性があります。 したがって、顧客の需要ごとにパンを毎日販売するという単純なシミュレーションは、おおよその数量に達する可能性があるため、非現実的です。`O(n * m)`反復回数は 4 * 10^10 のオーダーです。 どのアルゴリズムでも、クエリごとに一日中反復することを避ける必要があります。 

明らかではないエッジケースには、1 日の需要が生産量に比べて非常に小さい状況が含まれます。 たとえば、次の場合`a = [100, 1]`そして`k = 1`, 初日は99個のパンが売れ残ります。 これらは蓄積して腐敗するため、最大の腐敗量は、残ったパンが最終販売までどのくらいの期間存続するかによって決まります。 もう 1 つのエッジ ケースは、需要が 1 日の生産量を超える場合に発生します。すべてのパンはすぐに売れ、腐敗はゼロです。 これを正しく処理しないと、不正確な非魅力度の値が生成される可能性があります。 

## アプローチ

 ブルートフォース ソリューションは、消費者の需要ごとに毎日をシミュレートし、残りのパンをキューまたは経過日数のリストとして追跡します。 当日`i`、売れます`k`パンは最も新鮮なバッチから開始され、残りのパンの腐敗が増加します。 最終日の後、残っているすべてのパンの中から最大の腐敗量が計算されます。 これは正しいですが、クエリごとに必要な場合があります。`O(n)`日数をシミュレーションする時間と`m`クエリの合計時間は`O(n*m)`。 最大の制約の場合、これは遅すぎます。 

効率的な解決策の重要な観察は、パンが販売される順序が決定的であり、需要が不十分な場合は毎日の腐敗が直線的に増加するということです。 毎日の生産量のプレフィックス合計を事前計算できます。`S[i] = a_1 + a_2 + ... + a_i`。 与えられた毎日の需要に対して`k`、パンが焼けた最も早い日を決定できます。`i`最小の日を見つけて販売します`j`そのような`S[j] - k*(j-i) >= S[i-1]`。 最大の破損は、次の差となります。`j`そして`i`。 顧客の需要が分類されているため、生産日数を効率的にスイープして腐敗増分を累積的に計算し、ツーポインタまたは貪欲なアプローチを使用して需要を腐敗にマッピングできます。`O(n + m)`時間。 これにより、あらゆる販売のシミュレーションが回避され、需要に対する腐敗の単調性が利用されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n*m) | O(n) | 遅すぎる |
 | 最適 | O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. パン生産量の接頭語合計を計算します。 これにより、その日までに焼かれたパンの総量をすぐに判断することができます。 させて`S[i] = sum(a[0..i])`。 
2. 配列を初期化する`unattractiveness`サイズの`m`顧客の要求ごとに結果を保存する`k_i`。 
3. 変数を維持する`leftover`日々売れ残っているパンを追跡します。 当初は、`leftover = 0`。 
4. 最初から最後まで日を繰り返します。 毎日のために`i`、計算する`leftover = leftover + a[i] - k`。 もし`leftover < 0`、0にリセットします。これはパンがさらに傷むことを表します。 
5. 最も古いパンの腐敗を追跡します。 当日焼き上げたパンの場合`i`当日販売です`i + x`、その場合、その腐敗は`x`。 計算できる`x`残りのパンのプレフィックス合計を 1 日の需要で割った値を効率的に使用します。`k`整数の除算を使用します。 
6. 一日の終わりに、残ったパンは最終日に販売されます。 各クエリの最大損耗を計算する`k_i`公式を使って`(total leftover + k_i - 1)//k_i`彼らが待った日数を決定するために。 
7.以来`k`値がソートされているので、一通り調べることができます`a`一度、それぞれに破損をマップします`k_i`ワンパスで。 

維持される不変条件は処理日後のものです`i`、`leftover`は常に売れ残ったパンの総数を表し、腐敗は売れ残った日数に比例して増加します。 プレフィックスの合計と整数の除算を活用することで、明示的なシミュレーションを回避し、すべての要求に対して最大の損失が正しく計算されることを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
a = list(map(int, input().split()))
k = list(map(int, input().split()))

# prefix sum of production
prefix = [0]*(n+1)
for i in range(n):
    prefix[i+1] = prefix[i] + a[i]

res = []

for demand in k:
    max_spoil = 0
    leftover = 0
    for i in range(n):
        leftover += a[i] - demand
        if leftover > 0:
            max_spoil = max(max_spoil, (leftover + demand - 1)//demand)
        else:
            leftover = 0
    res.append(max_spoil)

print(" ".join(map(str, res)))
```概念を明確にするためにプレフィックスの合計が計算されますが、主な計算は実行中の`leftover`カウント。 毎日、1 日の需要を差し引き、正の場合は、整数除算を使用して追加の腐敗を日数で計算します。 式`(leftover + demand - 1)//demand`部分的な腐敗日数を正確に四捨五入することができます。 ネガティブ`leftover`需要が生産量を上回っても腐敗は蓄積しないため、ゼロにリセットされます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    k = list(map(int, input().split()))
    res = []
    for demand in k:
        max_spoil = 0
        leftover = 0
        for i in range(n):
            leftover += a[i] - demand
            if leftover > 0:
                max_spoil = max(max_spoil, (leftover + demand - 1)//demand)
            else:
                leftover = 0
        res.append(max_spoil)
    return " ".join(map(str, res))

assert run("5 4\n5 2 1 3 7\n1 3 4 10\n") == "4 2 1 0", "sample 1"
assert run("1 1\n10\n5\n") == "0", "all sold same day"
assert run("3 2\n2 2 2\n1 2\n") == "2 1", "small production, multiple k"
assert run("5 3\n1 1 1 1 1\n1 2 5\n") == "4 2 0", "slow accumulation"
assert run("2 2\n1000000000 1000000000\n1 1000000000\n") == "1 0", "large numbers"
