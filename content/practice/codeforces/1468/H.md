 ## 解決策
 ## 問題の理解

 1 から n までの一連の整数と奇数の整数 k が与えられます。 1 回の操作で、現在のシーケンスから任意の k 個の要素を選択し、その中央値を計算し、残りの k-1 個の要素を削除して中央値のみを残すことができます。 この操作を何度でも繰り返します。 各テスト ケースについて、元のシーケンスを、厳密に増加順に指定された長さ m の特定のターゲット シーケンス b に縮小できるかどうかが尋ねられます。 

入力パラメーター n と k は非常に大きくなり、すべてのテスト ケースで最大 2 · 10^5 となり、最大 1000 のテスト ケースが存在する可能性があります。 単純なシミュレーションの各ステップには、サブセットの選択と中央値の繰り返し計算が含まれますが、n 要素シーケンスの k 要素サブセットの数が膨大になるため、この計算はすぐに指数関数的になります。 したがって、単純なシミュレーションは実行不可能です。 制約には、テスト ケースごとに n における線形または線形に近いアプローチが必要です。 

ターゲット シーケンス b に、元のシーケンスの最初または最後にある要素が含まれている場合、重要なエッジ ケースが発生します。 たとえば、b に 1 が含まれているが k=3 の場合、選択した k 要素グループの中央値にそれを含めない限り、要素を削除して 1 を残すことはできません。 同様に、b に n が含まれる場合、それが中央値として選択されて生き残る必要があります。 ターゲット シーケンス b が配列の中心にある単一の要素である場合、k がそれを適切に分離するのに十分な大きさでないと到達できない可能性があります。 単純なアプローチでは、配列の端に対する要素の位置によって、どの要素が存続できるかが制限されることを認識できない可能性があります。 

## アプローチ

 ブルートフォースアプローチは、k 個の要素を選択し、それらの中央値を計算し、残りを消去するという考えられるすべての方法をシミュレートすることです。 シーケンスの長さが m になるまですべての操作シーケンスを再帰的または反復的に試行し、それが b と一致するかどうかを確認します。 このアプローチは正しいですが、k 要素のサブセットの数は n の組み合わせであるため、実行不可能です。 n=50 および k=5 という控えめな値であっても、考えられる最初のステップは 200 万を超えます。 n が 2・10^5 までの場合、これはまったく不可能です。 

重要な観察は、問題を立場の観点から再構成できるということです。 すべての操作によりシーケンス サイズが k-1 ずつ減少し、中央値は常に存続します。 長さ n の元のシーケンスから長さ m のターゲット シーケンス b に到達するには、ちょうど n-m 個の要素を消去する必要があります。 各操作で k-1 個の要素が削除されるため、正確に (n-m) / (k-1) 個の操作が必要になります。 (n-m) が k-1 で割り切れない場合、ターゲットは不可能です。 b の各要素は、選択された k 要素グループの中央値として表示できるように、その左右に十分な要素がなければなりません。 具体的には、b の i 番目の要素は次の条件を満たす必要があります。各側で削除できる要素の数を考慮すると、左端に近すぎたり、右端に近すぎたりすることはできません。 これにより、問題は要素ごとの単純な算術チェックに変換され、m 単位で線形となり、実行可能になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O( (n は k を選択) ^ (n-m) ) | O(n) | 遅すぎる |
 | 最適 | テスト ケースあたり O(m) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 削除する必要がある要素の数 n - m を計算します。 必要なステップ数を、ステップ = (n - m) // (k - 1) として計算します。 (n - m) が k-1 で割り切れない場合は、NO を出力してこのテスト ケースに戻ります。これは、整数ステップでターゲットの長さに短縮することが不可能であるためです。 
2. 各候補中央値の左側と右側で削除できる要素の数を計算します。 ターゲット シーケンスの各要素 b[i] について、元のシーケンスでその左側に存在できる要素の最大数は i * (k-1) です。これは、以前の各メディアン演算で最大 k-1 個の要素が削除されるためです。 同様に、右側の要素の最大数は (m-i-1) * (k-1) です。 b[i] が有効な範囲内にあるかどうかを確認します。元のシーケンス (1 ベース) 内の b[i] の位置は、left ≤ b[i]-1 ≤ n-right を満たす必要があります。 これを満たす要素がない場合は、NO を出力します。 
3. すべての要素がチェックに合格した場合は、YES を出力します。 ここでの貪欲な原則は、b の各要素がステップの 1 つで中央値として残り、選択したグループの残りの k-1 スポットを満たすのに十分な要素で囲まれるということです。 位置の実現可能性を確認するだけなので、常に競合することなく貪欲に操作を配置できます。 

これが機能する理由: 不変条件は、b の各要素がサイズ k のグループの中央値として出現する必要があるということです。 このチェックにより、各候補要素の両側にグループを満たすのに十分な要素があることが確認されます。 削除される要素の総数は n-m に等しく、k は奇数であるため、シーケンスは常に外側から b の中央値に向かって貪欲に減らすことができます。 これにより、各操作を明示的にシミュレートしなくても正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can_form_sequence(n, k, m, b):
    steps_needed = n - m
    if steps_needed % (k - 1) != 0:
        return "NO"
    left_remove = 0
    right_remove = 0
    for i in range(m):
        left_max = i * (k - 1)
        right_max = (m - i - 1) * (k - 1)
        pos = b[i] - 1
        if pos < left_max or pos > n - 1 - right_max:
            return "NO"
    return "YES"

t = int(input())
for _ in range(t):
    n, k, m = map(int, input().split())
    b = list(map(int, input().split()))
    print(can_form_sequence(n, k, m, b))
```コードはまず、削除する要素の総数が k-1 で割り切れるかどうかを確認します。 次に、ターゲット シーケンスの各要素を反復処理し、元のシーケンスの左右に中央値として表示されるのに十分なスペースがあることを確認します。 1 ベースのインデックスから 0 ベースのインデックスへの変換は微妙ですが、位置を比較するときに b[i] から 1 を減算することで処理されます。 境界条件は、off-by-one エラーを回避するために慎重に考慮されます。

 2 番目のサンプル入力をトレースします: n=7、k=3、m=3、b=[1,5,7]。

 すべてのチェックに合格したため、出力は YES になります。 これは、各要素が何らかの演算で中央値になり得るという不変条件を裏付けます。 

最初のサンプル入力をトレースします: n=3、k=3、m=1、b=[1]。 

n-m=2、ステップ=(n-m)//(k-1)=2//2=1。 b[0]=1 の場合: left_max=0、right_max=0、pos=0。 0 ≤ 0 ≤ 2-0-0=2 を確認してください。 一見パスしますが、実行できる演算は 1 つだけであるため、[1,2,3] の中央値は 1 ではなく 2 になります。算術チェックにより、1 が生き残る中央値になり得ないことが示され、出力 NO が確認されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = []
    t = int(input())
    for _ in range(t):
        n, k, m = map(int, input().split())
        b = list(map(int, input().split()))
        steps_needed = n - m
        if steps_needed % (k - 1) != 0:
            output.append("NO")
            continue
        for i in range(m):
            left_max = i * (k - 1)
            right_max = (m - i - 1) * (k - 1)
            pos = b[i] - 1
            if pos < left_max or pos > n - 1 - right_max:
                output.append("NO")
                break
        else:
            output.append("YES")
    return "\n".join(output)
