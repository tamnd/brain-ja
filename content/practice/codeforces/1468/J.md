 ## 問題の理解

 この問題は国に次のような問題をもたらしています`n`によってつながる都市`m`双方向の道路。 各道路には整数の制限速度があり、ネットワークは最初から接続されているため、任意の都市間の移動が可能です。 政府は 2 つの行動を実行したいと考えています。道路の数を正確に減らすことです。`n - 1`ネットワークの接続を維持しながら、残りの道路の最高速度が正確に制限されるように速度制限を調整します。`k`。 道路の制限速度の増加または減少はそれぞれ 1 単位の操作としてカウントされ、目標は操作の総数を最小限に抑えることです。 

最初の要件は、ネットワークをツリーに縮小します。 2 番目の要件は、そのツリーの速度制限を変更します。 各テスト ケースの出力は、最大速度が正確に一致するツリーに到達するために必要な最小限の調整数です。`k`。 

制約は次のことを示します`n`そして`m`すべてのテスト ケースで最大 2 · 10^5 になる可能性があるため、考えられるすべてのツリーを反復したり、各増分または減分を個別にシミュレートしたりするソリューションは実行不可能です。 ツリー構造を識別し、理想的にはテスト ケースごとに O(m log n) で最小限の変更数を効率的に計算するメソッドが必要です。 

明らかではないエッジケースには、元のグラフの最大速度がすでに次の値に等しい場合が含まれます。`k`、すべての道路の制限速度が以下の場合`k`、および最小変更コストは同じだが構成が異なる複数の候補ツリーが存在する場合。 任意のスパニング ツリーを選択して速度を調整するという単純なアプローチでは、変更が過大にカウントされる可能性があります。 

## アプローチ

 ブルートフォース手法では、グラフの考えられるすべてのスパニング ツリーを列挙します。 スパニング ツリーごとに、最大速度を調整するために必要な操作の数を計算します。`k`。 このアプローチは正しいですが、スパニング ツリーの数はエッジの数とともに指数関数的に増加するため、完全に非現実的です。 

重要な洞察は、変更の最小数は、選択したツリーの最大速度のみに依存するということです。 最大のエッジができるだけ近くにあるスパニング ツリーが必要です。`k`。 樹木の最高速度が以下の場合`k`に到達するには、少なくとも 1 つのエッジを増やす必要があります。`k`。 最高速度を超える場合`k`、減らさなければなりません。 したがって、最小化するスパニング ツリーを選択すれば十分です。`abs(max_edge - k)`。 

クラスカルのアルゴリズムを彷彿とさせる貪欲な戦略を使用して、これを効率的に達成できます。 エッジを絶対的な差によってソートします。`k`。 次に、最初のエッジをこの順序で使用してスパニング ツリーを構築します。これにより、ツリーの最大値が可能な限り近いことが保証されます。`k`。 ツリーを構築した後、最大エッジを調べ、必要なユニット調整の正確な数を数えます。 このアプローチは、値ではなくカスタム優先度で並べ替えられたエッジを使用した単一の MST のような走査に問題を軽減するため、効率的です。

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、次の内容を読んでください。`n`、`m`、`k`そしてのリスト`m`エッジとそのエンドポイントおよび速度制限。 
2. 差の絶対値でエッジを並べ替えます`abs(s_i - k)`。 これにより、ターゲット速度に最も近いエッジが優先されます。 
3. Disjoint Set Union (DSU) 構造体を次のように初期化します。`n`ノードを使用して接続を効率的に追跡します。 
4. 変数を初期化する`max_edge_in_tree`に`-inf`選択したツリーの最大速度を追跡します。 
5. ソートされた順序でエッジを反復処理します。 

1. 各エッジについて、そのエンドポイントが異なる DSU コンポーネントに属しているかどうかを確認します。 
2.「はい」の場合、エッジをツリーに追加し、更新します。`max_edge_in_tree`必要に応じて、コンポーネントを結合します。 
3. 停止するタイミング`n - 1`エッジが追加されました。 
6. ツリーを形成した後、`max_edge_in_tree`等しい`k`、変更は必要ありません。 それ以外の場合、必要な単位変更の回数は次のとおりです。`abs(max_edge_in_tree - k)`。 

機能する理由: に最も近いエッジを選択することにより、`k`接続性を維持しながら、貪欲なアルゴリズムにより、ツリーの最大値からの絶対偏差が最小限に抑えられます。`k`。 DSU は、ツリーがサイクルを形成せずに接続されたままであることを保証します。 これにより、最小調整数が正しく計算されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.p = list(range(n))
        self.rank = [0]*n

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, x, y):
        x_root = self.find(x)
        y_root = self.find(y)
        if x_root == y_root:
            return False
        if self.rank[x_root] < self.rank[y_root]:
            self.p[x_root] = y_root
        else:
            self.p[y_root] = x_root
            if self.rank[x_root] == self.rank[y_root]:
                self.rank[x_root] += 1
        return True

def solve():
    t = int(input())
    for _ in range(t):
        n, m, k = map(int, input().split())
        edges = []
        for _ in range(m):
            x, y, s = map(int, input().split())
            edges.append((abs(s - k), s, x-1, y-1))
        edges.sort()
        dsu = DSU(n)
        cnt = 0
        max_edge = -1
        for diff, s, u, v in edges:
            if dsu.union(u, v):
                max_edge = max(max_edge, s)
                cnt += 1
                if cnt == n-1:
                    break
        print(abs(max_edge - k))

solve()
```このソリューションでは、接続を効率的に管理するために、ランクごとにパス圧縮とユニオンを備えた DSU クラスを定義します。 エッジは次の基準でソートされます`abs(s - k)`最小限の調整が必要なエッジを優先します。 結果として得られるツリーの最大エッジを追跡し、ツリーを形成した後、ユニット変更の最小数は次のようになります。`abs(max_edge - k)`。
