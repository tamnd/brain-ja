 ## 解決策
 ## 問題の理解

 いくつかの文字列部分があり、それらを任意の順序で連結できます。 結果の文字列のスコアは、連続する 3 文字の回数です。`SAD`現れる。 個々の部分内にすでに完全に含まれている出現は順序に依存しないため、唯一興味深いのは 2 つの部分間の境界を越えて何が起こるかです。 

ピース間の境界を考慮する`x`そして`y`。 以来`SAD`長さは 3 で、この境界を越える新しい出現では、次のいずれかの 1 文字を使用できます。`x`そして、からの2つ`y`、または 2 つから`x`そしてからの1つ`y`。 最初のケースでは次のことが必要です`x`で終わる`S`そして`y`まず始めに`AD`。 2番目に必要なのは`x`で終わる`SA`そして`y`まず始めに`D`。 2 つの部分に関するその他の情報は、その境界にとって重要ではありません。 

したがって、タスクは、できるだけ多くの隣接するペアが新しい 1 つを作成するように、すべてのピースを順序付けすることです。`SAD`、同時に、ピース内にすでに存在する固定数も追加します。 

制約は大きいです。 1 つのテスト ケースには最大 (2\cdot10^5) 個の部分が存在し、全体では最大 (10^6) 個の部分が存在します。 全長は (2\cdot10^6) のみです。これは、すべての文字を一定の回数だけ処理することが適切であることを示していますが、部分の数が 2 次のものはすでにコストが高すぎます。 順列に対する階乗検索は明らかに不可能であり、最初の 2 文字と最後の 2 文字のみが重要であるという事実を利用すると、(O(n\log n)) のアプローチでも必要以上に手間がかかることになります。 

一致するプレフィックスとサフィックスのカウントのみに基づいて実装を簡単に破壊するエッジ ケースがいくつかあります。 

たとえば、```
1
1
SAD
```答えは`1`、オカレンスはすでに唯一の部分内にあるためです。 別のオカレンスを作成するための境界はありません。 境界一致のみをカウントするソリューションでは、誤ってゼロが返されます。 

もう一つの重要な事例は、```
1
2
ADSA
DS
```2 つの部分は、どちらの順序でも 1 つの新しいオカレンスを作成できます。 で`ADSA+DS`、接尾辞`SA`最初の部分の最初の部分が結合されます`D`2番目の。 で`DS+ADSA`、接尾辞`S`最初の部分が最初の部分に結合されます`AD`2番目の。 答えは、`1`、 ない`2`。 線形順序付けではこれら 2 つの部分の間に境界が 1 つしかない場合でも、考えられるすべての接尾辞をすべての考えられる接頭辞と個別に照合する不注意な解決策は、両方の可能性をカウントする可能性があります。 

3つ目のケースは、```
1
3
S
AD
X
```ピース`S`そして`AD`一つ生産できる`SAD`、 その間`X`は無関係です。 答えは、`1`。 未使用のピースが存在するために、有用なチェーンを形成することが妨げられてはなりません。 

最後に、次のような作品`A`特別な注目に値します。 のために```
1
3
SS
A
DD
```最良の順序は`SS+A+DD`を作成します。`SAD`2 つの境界を使用します。 直接は無いよ`SS+DD`一致しますが、中央の部分が両側を接続します。 ピースの個々のペアのみを調べるアプローチでは、この構造が欠落しています。 

## アプローチ

 直接的な総当たりアプローチは、部分のすべての順列を試し、その順列の文字列を連結して、カウントすることです。`SAD`。 これは正しいです。考えられるすべての順序が明示的に検査されるため、最適な順序が必然的に見つかります。 入力の合計長が (L) の場合、1 つの順列の評価には (O(L)) かかり、(O(n!,L)) 時間がかかります。 文字列をスキャンするコストを無視しても、(20!) はすでに (2.43\cdot10^{18}) 個の順列になりますが、実際の制約により、(n) は (2\cdot10^5) に達することができます。 階乗探索は直ちに除外されます。 

重要な観察は、新しいものはすべて、`SAD`正確に 1 つの境界に属します。 境界は、左側の部分の接尾辞情報が右側の部分の接頭辞情報と一致する場合にのみ成功します。 これは、すべてのピースが参加できる 2 つの境界状態によってすべてのピースを表すことを示唆しています。 

すべての部分を小さなグラフ内の有向エッジとして表示することで、この表現をさらにわかりやすくすることができます。 から始まる作品`AD`が必要です`S`その直前なので、その左端は状態です`S`。 から始まる作品`D`ニーズ`SA`その直前なので、その左端点は`SA`。 どちらでも開始しない場合は、有効な左側の接続がないため、左側のエンドポイントは特別なエンドポイントになります。`START`州。 

対称的に、で終わる作品は、`S`状態を提供します`S`次の作品へ。 で終わる作品`SA`状態を提供します`SA`。 それ以外の場合は、特別なサービスが提供されます`END`州。 

連続する 2 つの部分が新しいものを作成します`SAD`正確に、最初のエッジの終点が 2 番目のエッジの始点と一致するときです。 言い換えれば、ピースのシーケンスは、有向トレイルに結合できる連続エッジのペアごとに 1 つの新しいオカレンスを作成します。 

したがって、元の順序付け問題はグラフ問題になりました。 可能な頂点が 4 つだけのマルチグラフがあり、すべての文字列が 1 つの有向エッジです。 すべてのエッジを最小限の数の有向トレイルに分割する必要があります。 合計 (n) 個のエッジを含む (k) 個のトレイルがある場合、それらのトレイルには正確に (n-k) 個の成功した結合が含まれます。 トレイルは任意の順序で連結でき、異なるトレイル間の結合部分のみが失われます。 

弱く接続された有向コンポーネントの場合、そのすべてのエッジをカバーするトレイルの最小数は、次数の不均衡によって決まります。 頂点に入力エッジよりも出力エッジが多い場合は、少なくとも同じ数のトレイルがそこから開始される必要があります。 必要な数は、

 [
 \max\left(1,\sum_v \max(0,\オペレーター名{out}(v)-\オペレーター名{in}(v))\right)。 
】

 すべての頂点のバランスが取れていれば、コンポーネント全体を 1 つのオイラー トレイルとして横断できます。 正の不均衡がある場合、超過発信次数の各ユニットには個別のトレイル スタートが必要です。 

グラフには頂点が 4 つしかないため、弱く接続されたコンポーネントを見つけるのは定数時間です。 内部出現をカウントし、4 次ペアを更新するには、入力文字列を 1 回スキャンするだけで済みます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(n!,L)) | (O(L)) | 遅すぎる |
 | 最適 | (O(L+n)) | (O(1)) 入力文字列のほか | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ピースごとに、何個あるか数えます`SAD`出来事はすでに完全にその部分の中にあります。 これらの出現は順序とは無関係であるため、回答に直接追加してください。 
2. ピースの左端点を決定します。 作品が次から始まる場合`AD`、エンドポイントを割り当てる`S`。 で始まるなら`D`、エンドポイントを割り当てる`SA`。 それ以外の場合はエンドポイントを割り当てます`START`。 

この変換の理由は、エンドポイントが前の部分で必要とされた正確なサフィックス条件を表すためです。 から始まる作品`AD`で終わる前の作品の後に役立つようになります`S`で始まる作品ですが、`D`で終わる前の作品の後に役立つようになります`SA`。 

1. 適切なエンドポイントを決定します。 作品が次で終わる場合`S`、エンドポイントを割り当てる`S`。 で終わったら`SA`、エンドポイントを割り当てる`SA`。 それ以外の場合はエンドポイントを割り当てます`END`。 

右のエンドポイントは、この部分が次の部分に提供できるものを表します。 州`START`そして`END`有用な境界を形成することはありませんが、すべての部分を 1 つの有向エッジとして均一に表現できます。 

1. 1 つの送信次数を左のエンドポイントに追加し、1 つの受信次数を右のエンドポイントに追加します。 また、2 つのエンドポイントが同じ弱接続コンポーネントに属していることも記録します。 
2. すべての部分が処理された後、すべての弱結合コンポーネントに必要なトレイルの最小数を計算します。 1 つの成分について、次の合計を計算します。`max(0, out[v] - in[v])`その頂点を越えて。 コンポーネントは、合計が正の場合はその数のトレイルを必要とし、グラフのバランスが取れている場合は 1 つのトレイルを必要とします。 
3. すべてのコンポーネントにわたって必要な証跡数を合計します。 合計個数が`n`トレイルの最小数は`k`、 追加`n-k`内部オカレンスの固定数に達します。 

なぜそれが機能するのかは、グラフの不変性を通じて説明できます。 すべてのピースが 1 つのエッジであり、2 つのピースが新しいエッジに貢献します。`SAD`対応するエッジが連続しており、共通のグラフ頂点で接続されている場合に、正確に境界を越えます。 トレイルは正確には、すべての内部境界が 1 つの新しい出現に寄与する一連の断片です。 したがって、(k) 個のトレイルに分解すると、正確に (n-k) 個の境界を越えた出現が得られます。 標準次数条件では、各弱いコンポーネントのトレイルの可能な最小数が与えられるため、どの順序付けでもより多くの境界を越えた出現を取得できません。`n-k`、最適なトレイル分解により、まさにその数が実現されます。 固定された内部オカレンスを追加すると、全体的な最適値が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def count_sad(s):
    cnt = 0
    for i in range(len(s) - 2):
        if s[i:i + 3] == "SAD":
            cnt += 1
    return cnt

def solve_case(strings):
    # Vertices:
    # 0 = START
    # 1 = S
    # 2 = SA
    # 3 = END
    #
    # Each string is an edge left_vertex -> right_vertex.
    out_deg = [0] * 4
    in_deg = [0] * 4

    parent = list(range(4))

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    def union(a, b):
        a = find(a)
        b = find(b)
        if a != b:
            parent[b] = a

    answer = 0

    for s in strings:
        answer += count_sad(s)

        # Determine the left endpoint.
        if s.startswith("AD"):
            left = 1
        elif s.startswith("D"):
            left = 2
        else:
            left = 0

        # Determine the right endpoint.
        if s.endswith("SA"):
            right = 2
        elif s.endswith("S"):
            right = 1
        else:
            right = 3

        out_deg[left] += 1
        in_deg[right] += 1
        union(left, right)

    # Every non-empty connected component needs at least one trail.
    component_has_edge = [False] * 4
    for v in range(4):
        if out_deg[v] + in_deg[v] > 0:
            component_has_edge[find(v)] = True

    trails = 0

    for root in range(4):
        if not component_has_edge[root]:
            continue

        positive_imbalance = 0
        for v in range(4):
            if find(v) == root:
                positive_imbalance += max(0, out_deg[v] - in_deg[v])

        trails += max(1, positive_imbalance)

    return answer + len(strings) - trails

def solve_io(data):
    it = iter(data.split())
    t = int(next(it))
    result = []

    for case_no in range(1, t + 1):
        n = int(next(it))
        strings = [next(it) for _ in range(n)]
        ans = solve_case(strings)
        result.append(f"Case #{case_no}: {ans}")

    return "\n".join(result)

def main():
    data = sys.stdin.buffer.read()
    sys.stdout.write(solve_io(data))

if __name__ == "__main__":
    main()
```入力は次のように読み取られます`sys.stdin.buffer.read()`合計入力には最大 (2\cdot10^6) 文字が含まれるためです。 入力を 1 回分割するだけでも十分高速であり、繰り返しのラインレベルのオーバーヘッドを回避できます。 

すべての文字列について、`count_sad`文字をスキャンし、内部の出現をカウントします。 文字列の最大長はわずか 20 であるため、この作業は部分ごとに事実上一定であり、入力全体にわたって (O(L)) となります。 

エンドポイントの分類には次のものを使用します。`startswith("AD")`、`startswith("D")`、`endswith("SA")`、 そして`endswith("S")`。 接尾辞テストの順序は重要です。`SA`で終わらない`S`したがって、ここではどちらの順序でも機能しますが、最初に 2 文字のパターンをチェックすると、意図した状態のマッピングが明示的になります。 

素セット構造は、頂点が 4 つしかないため、必要以上に一般的ですが、弱く接続されたコンポーネントを構築するきれいな方法を提供します。 すべてのエッジはその 2 つの端点を結合するため、同じ可能なトレイル コンポーネントに属するすべての頂点は同じ代表を受け取ります。 

最後のループでは、各コンポーネントのトレイル要件を計算します。 バランスの取れたコンポーネントには、正の不均衡がゼロですが、それでも 1 つのトレイルが必要ですが、正の不均衡を持つコンポーネントには、トレイルの超過出力度の合計が正確に必要です。 Python の整数には任意の精度があるため、潜在的に大きな答えには特別なオーバーフロー処理は必要ありません。 

## 実用的な例

 ### サンプル 1

 ピースは`SAD`、`D`、 そして`SA`。 

| ピース | 内部`SAD`| 左の頂点 | 右の頂点 | ピース後のアウト度 | ピース後の度で |
 | --- | --- | --- | --- | --- | --- |
 |`SAD`| 1 | スタート | 終わり | 開始: 1 | 終了: 1 |
 |`D`| 0 | SA | 終わり | スタート: 1、SA: 1 | 終了: 2 |
 |`SA`| 0 | スタート | SA | スタート: 2、SA: 1 | エンド: 2、SA: 1 |

 の`SAD`ピースは内部的に 1 つのオカレンスに貢献します。 グラフには 2 つのコンポーネントがあります。 エッジ`START -> END`から`SAD`有用なものから隔離されている`START -> SA -> END`によって形成される連鎖`SA`そして`D`。 各コンポーネントには 1 つのトレイルが必要なので、3 つのエッジに対して 2 つのトレイルがあります。 

境界を越えた発生数は次のとおりです。`3 - 2 = 1`。 内部オカレンスを追加すると、`2`、出力と一致します。 最適な連結の 1 つは次のとおりです。`SAD + SA + D`を生成します。`SADSAD`。 

### サンプル 2

 ピースは`SS`、`A`、 そして`DD`。 

| ピース | 内部`SAD`| 左の頂点 | 右の頂点 | ピース後のアウト度 | ピース後の度で |
 | --- | --- | --- | --- | --- | --- |
 |`SS`| 0 | スタート | S | 開始: 1 | S: 1 |
 |`A`| 0 | スタート | 終わり | 開始: 2 | S: 1、END: 1 |
 |`DD`| 0 | SA | 終わり | スタート: 2、SA: 1 | S: 1、END: 2 |

 コンポーネントは 2 つあります。 エッジ`START -> S`は 1 つのコンポーネントですが、`START -> END`そして`SA -> END`エッジが接続されていないため、別のコンポーネントを形成します`S`と`SA`。 

各コンポーネントには 1 つのトレイルが必要なので、3 つのピースに対して 2 つのトレイルがあります。 答えは、`3 - 2 = 1`。 

対応する順序は次のとおりです。`SS + A + DD`、与える`SSADD`。 の`SAD`ファイナルを使用します`S`の`SS`、全体`A`、そして最初の`D`の`DD`、スタンドアロンを介して交わる 2 つのエッジによって表されるのとまったく同じです。`A`。

 ## 特殊なケース

 最初のエッジケースは、すでに含まれている部分です。`SAD`。 入力用```
1
1
SAD
```その部分がグラフの端になります`START -> END`、そのため、境界を越えた出来事を作成することはできません。 その内部スキャンは答えに 1 つ貢献し、グラフには 1 つのエッジを含む 1 つの軌跡があります。 国境を越えた貢献は、`1-1=0`、正しい答えを与える`1`。 

2 番目のエッジケースは 2 ピースサイクルです```
1
2
ADSA
DS
```

`ADSA`で表されます`S -> SA`で始まるので、`AD`そして次で終わります`SA`。`DS`で表されます`SA -> S`で始まるので、`D`そして次で終わります`S`。 これら 2 つのエッジは 1 つのバランスの取れたコンポーネントを形成するため、最小トレイル数は 1 です。 1 つのトレイル内の 2 つのエッジにより、成功した結合が 1 つだけ生成されます。 答えは、`2-1=1`。 これはまさに、独立したプレフィックスとサフィックスのマッチングが過剰になる状況です。 

3 番目のエッジケースは孤立した部分です。```
1
3
S
AD
X
```

`S`になる`START -> S`、`AD`になる`S -> END`、 そして`X`になる`START -> END`。 最初の 2 つのエッジは 1 つのトレイルを形成し、1 つのトレイルを作成します`SAD`、 その間`X`は別のコンポーネントに属しており、有用な境界を作成しません。 3 つのエッジに対して 2 つのトレイルがあるため、境界を越えた寄与は次のようになります。`3-2=1`。 

4 番目のエッジ ケースはスタンドアロンです。`A`橋：```
1
3
SS
A
DD
```

`SS`は`START -> S`、`A`は`START -> END`、 そして`DD`は`SA -> END`。 グラフ計算だけで、次からの結合が 1 つ成功します。`SS`チェーンですが、実際に役立つ順序は次のとおりです。`SS+A+DD`、ここで、`A`決勝の間にある`S`そして最初に`D`。 グラフ表現はこれを捉えています。`A`は、1 つの境界で一致するリテラル文字ではありませんが、その部分自体がエッジとして元の文字列に参加しており、その 2 つの境界は両方ともその端点によって表されます。 結果として得られる最大値は、必要に応じて 1 になります。 

5 番目のエッジ ケースは、同一のものの大規模なコレクションです。`SAD`個。 すべての部分は 1 つの内部オカレンスに寄与しており、有用な境界エンドポイントはありません。 グラフには多くの並列が含まれています`START -> END`エッジは単一の弱いコンポーネントを形成するため、1 つのトレイルが必要です。 このような部分が 2 つも存在しないため、追加の要素を作成することはできません。`SAD`彼らの境界を越えて。 200000 個の場合、答えは正確に 200000 となり、アルゴリズムは可能な注文数に依存せずにこれを処理します。
