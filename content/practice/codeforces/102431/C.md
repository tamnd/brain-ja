 ## 解決策
 ## 問題の理解

 固定配列 (S) を左から右に構築する必要があります。 いつでも、新しい要素を 1 つ入力したり、紙上にすでに存在する部分文字列をクリップボードにコピーしたり、クリップボード全体を紙に追加したりすることができます。 入力コスト (X)、コピーコスト (Y)、およびすべてのペーストコスト (Z)。 クリップボードは貼り付け後も保存されるため、コピーされた同じ部分文字列を何度も貼り付けることができます。 

入力には、(T) 個の独立したテスト ケースが含まれています。 各テスト ケースでは、ターゲットの長さ (n)、3 つの操作コスト (X、Y、Z)、および (S) の (n) 個の整数値が与えられます。 必要な出力は、ターゲット配列を正確に生成するために必要な最小総コストと、それに続く必要なコストです。`Case #x:`接頭辞。 

最大 (n) は 5000 で、元のコンテストでは 15 秒の制限時間と 1024 MB のメモリが与えられます。 (O(n^3)) の解決策では、最悪の場合、すでにおよそ (5000^3=125) 億の候補が考慮されるため、現実的な選択ではありません。 (O(n^2)) アルゴリズムが自然なターゲットです。 また、入力ではテストの少なくとも 80% に (n\le1000) が含まれているため、慎重に実装された二次解が特に適切であることがわかります。 

表面的に合理的な解決策が間違っている可能性があるいくつかの特殊なケースがあります。 次のような 1 要素ターゲットの場合`1 5 1 1`に続く`7`の場合、まだコピーするものが何もないため、答えは 5 です。 すべての最終状態がペーストから得られると想定するソリューションは、ここで失敗する可能性があります。 

2つ目のケースは、`4 10 1 1`に続く`1 1 1 1`。 答えは 14 です。最初の文字を入力します。`1`10 の場合はそれをコピーし、1 の場合はそれをコピーし、さらに 3 の場合は 3 回貼り付けます。 ペーストごとにコピー コストを請求するソリューションでは、誤って 16 が取得されてしまいます。 

3つ目のケースは、`4 10 1 1`に続く`1 2 1 2`。 答えは 22 です。次のように入力します。`1 2`、その 2 要素の部分文字列をコピーし、一度貼り付けます。 繰り返される部分文字列は位置 0 から始まり、位置 2 から貼り付けられます。ソースと宛先が隣接しているため、境界チェックを不用意に行うと、この発生が誤って拒否される可能性があります。 

最後に、繰り返される部分文字列は直前の部分文字列である必要はありません。 で`6 10 8 8`と`1 2 2 1 2 3`、最初の 3 つの値が入力され、その後`1 2`位置 0 と 1 からコピーされ、最初の 3 つの値の後に貼り付けられます。 これにより、`1 2 2 1 2`、その後決勝`3`現在のプレフィックスに直接隣接する繰り返しのみを検索するソリューションでは、この構造が欠落しています。 

## アプローチ

 単純な動的プログラムは、(S) のすべての接頭辞を考慮し、可能なすべての貼り付けに対して、すでに構築された接頭辞のすべての部分文字列を可能なクリップボードの内容として試みます。 部分文字列の等価性がすでに前処理されている場合は、(O(n)) 個のプレフィックスごとに (O(n^2)) 個の候補ソース部分文字列があり、(O(n^3)) 個の遷移が与えられます。 (n=5000) の場合、最悪の場合、これは約 1,250 億の候補遷移になります。 部分文字列の同等性も文字ごとにチェックすると、複雑さはさらに悪化します。 

総当たり DP は正しいです。すべての正当な貼り付けでは、紙上にすでに存在する一部の部分文字列をコピーする必要があるため、考えられるすべてのソースとすべての宛先を列挙することで、すべての正当な操作シーケンスがカバーされます。 問題は、これらのソースの選択のほとんどが同等であることです。 特定の部分文字列をコピーするコストは、その部分文字列がどこにあるかには依存せず、後で問題になるのはクリップボードの内容だけです。 

重要な観察は、ペーストを逆から見ることです。 追加したい次のブロックの長さが (j) で、それが位置 (t) で終わる以前のブロックと等しいと仮定します。 そのブロックがクリップボードにあると、クリップボードを変更せずに、そのブロックの出現から最終的な貼り付け位置までのすべてを入力できます。 したがって、「このクリップボードを保持し、いくつかの文字を入力し、その後貼り付ける」操作のシーケンス全体を 1 つの DP トランジションで表すことができます。 

さらに便利な単調性プロパティがあります。 同じブロックが発生し、位置 (t_1<t_2) で終了するとします。 (t_1) のブロックがクリップボードである状態から、クリップボードを変更せずに (t_1) から (t_2-1) までの文字を入力できます。 その結果、

 [
 dp[t_2][j]\le dp[t_1][j]+(t_2-t_1)X。 
]

 並べ替えた後、

 [
 dp[t_2][j]-t_2X\le dp[t_1][j]-t_1X。 
]

 したがって、同じブロックのすべての出現のうち、最も早い出現は常に、このタイプの遷移では少なくとも同等に優れています。 すべての出来事を試す必要はありません。 すべての部分文字列の最初の出現のみが必要です。 

接尾辞オートマトンはまさにその情報を提供します。 すべての部分文字列は初期状態からのパスに対応し、同じ状態によって表されるすべての部分文字列は同じ終了位置のセットを持ちます。 もし`firstpos[v]`状態 (v) で表される部分文字列の最も早い終了位置を格納し、長さ (j) の部分文字列をたどった後、その最初の出現位置で終了します。`firstpos[v]`。 これは、サフィックス オートマトンの標準の最初に出現するプロパティです。 

すべての位置から開始して接尾辞オートマトンを順に進めることで、すべての (O(n^2)) 部分文字列を列挙できます。 各部分文字列について、その最も古い出現を記録します。 この場合、DP には (O(n^2)) 個の状態と、状態ごとの (O(1)) 個の作業のみが含まれます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース DP | (O(n^3)) | (O(n^2)) | 遅すぎる |
 | 最適な DP + サフィックス オートマトン | (O(n^2)) | (O(n^2)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ターゲット配列のサフィックスオートマトンを構築します。 すべての状態は、その最大表現部分文字列長、サフィックス リンク、遷移、および発生の最も早い終了位置を保存します。 位置 (p) の処理中に通常状態が作成された場合、その最も早い終了位置は (p) になります。 クローンが作成されると、クローンを作成した状態の最も古い位置が継承されます。 
2. すべての部分文字列の最も古い出現を事前計算します。 すべての開始位置 (l) について、オートマトンのルートから開始し、(S_l,S_{l+1},\ldots) を 1 つずつ消費します。 (S_l\ldots S_r) を消費した後の現在の状態はその部分文字列を表すため、`firstpos[state] + 1`この部分文字列が出現した最も古いプレフィックスの長さです。 この値をペア ((l,r)) に保存します。 
3. 定義する`dp[i][j]`for (j>0) は、部分文字列 (S[i-j]) をクリップボードに保持しながら、最初の (i) 要素を構築するための最小コストとして使用されます。この状態は、ペーストの直前に役立ちます。 定義する`dp[i][0]`クリップボードの内容が無関係な場合に、最初の (i) 要素を構築するための最小コストとして。 
4.初期化`dp[0][0]=0`。 値`best[i]`、全体の最小値として定義されます。`dp[i][j]`は、クリップボードの内容を気にしない場合に、最初の (i) 要素を構築する最も安価な方法を表します。 
5. 計算するには`dp[i][0]`、(i) 番目の要素を入力します。 以前のクリップボードは何でもよいため、最も安価な以前の状態は次のとおりです。`best[i-1]`。 したがって、
 [
 dp[i][0]=best[i-1]+X。 
]
 6. 1 から (i) までのすべての (j) について、プレフィックスを終了するために貼り付けられるブロック (B=S[i-j]) を考慮します。 (l=i-j) とすると、ブロックは最初の (l) 要素内のどこかからコピーされる必要があります。 
7. (B) に、あるプレフィックス長 (t\le l) で終わる出現がある場合、最初の (l) 要素を最適に構築し、(B) をコピーして、すぐに貼り付けることができます。 これにより、
 [
 dp[i][j]\le best[l]+Y+Z。 
]
 コピー ソースは、その位置がコストに影響しないため、任意の有効なソースにすることができます。 
8. クリップボードには既に (B) が含まれている可能性があります。 (t) を (B) の出現が終了する最も早いプレフィックス長とします。 から`dp[t][j]`、その出現位置と目的の貼り付け位置の間に (l-t) 要素を入力し、クリップボードを貼り付けます。 これにより、
 [
 dp[i][j]\le dp[t][j]+(l-t)X+Z。 
]
 9. 利用可能なトランジションを最小限にして更新します。`best[i]`。 プレフィックスを昇順に処理することで、参照されるすべての DP 状態がすでに計算されていることを保証します。 
10. 最終的な答えは`best[n]`完全なターゲットを構築した後は、クリップボードに何が残っているかは気にしなくなるからです。 

正確性が不変であるということは、すべての DP 状態がその指定されたプレフィックスの実現可能な構造を正確に表し、新しいプレフィックスを作成できるすべての可能な最終操作が 2 つの貼り付け遷移の 1 つまたは入力によってカバーされるということです。 貼り付けトランジションは、貼り付ける直前に必要なブロックをコピーするか、同じブロックがすでにクリップボードにある以前の状態から開始して、入力中にそのクリップボードを保持します。 同じクリップボードを保持しながら入力することで、以前の出現から後の出現に到達できるため、最初の出現で十分です。これでは式が改善されることはありません。`dp[t][j] - t*X`。 したがって、すべての最適な構造には再帰によって表される遷移があり、再帰によって生成されるすべての遷移は合法的なタイプライター操作に対応します。 

## Python ソリューション```python
import sys
from array import array

input = sys.stdin.readline

INF = 4_000_000_000_000_000_000

def build_suffix_automaton(s):
    nxt = [{}]
    link = [-1]
    length = [0]
    first = [-1]

    last = 0

    for pos, ch in enumerate(s):
        cur = len(nxt)
        nxt.append({})
        link.append(0)
        length.append(length[last] + 1)
        first.append(pos)

        p = last

        while p != -1 and ch not in nxt[p]:
            nxt[p][ch] = cur
            p = link[p]

        if p == -1:
            link[cur] = 0
        else:
            q = nxt[p][ch]

            if length[p] + 1 == length[q]:
                link[cur] = q
            else:
                clone = len(nxt)
                nxt.append(nxt[q].copy())
                link.append(link[q])
                length.append(length[p] + 1)
                first.append(first[q])

                while p != -1 and nxt[p].get(ch) == q:
                    nxt[p][ch] = clone
                    p = link[p]

                link[q] = clone
                link[cur] = clone

        last = cur

    return nxt, first

def solve_case(n, X, Y, Z, s):
    nxt, first = build_suffix_automaton(s)

    # earliest[l, r] = prefix length at which s[l:r+1]
    # first occurs in the whole string.
    #
    # Row l contains substrings starting at l:
    # [l,l], [l,l+1], ..., [l,n-1].
    total_occ = n * (n + 1) // 2
    earliest = array('H', [0]) * total_occ

    for l in range(n):
        v = 0

        # Start of row l in the triangular array.
        base = l * n - l * (l - 1) // 2

        for r in range(l, n):
            v = nxt[v][s[r]]
            earliest[base + (r - l)] = first[v] + 1

    # dp[i][j], 0 <= j <= i, stored in triangular form.
    #
    # Row i has i+1 entries.
    total_dp = (n + 1) * (n + 2) // 2
    dp = array('q', [INF]) * total_dp

    dp[0] = 0

    best = [INF] * (n + 1)
    best[0] = 0

    for i in range(1, n + 1):
        base_i = i * (i + 1) // 2

        # Type S[i-1]. The clipboard is irrelevant afterwards.
        cur_best = best[i - 1] + X
        dp[base_i] = cur_best

        for j in range(1, i + 1):
            l = i - j

            # Substring s[l:i] starts at l and has length j.
            base_l = l * n - l * (l - 1) // 2
            t = earliest[base_l + j - 1]

            if t <= l:
                # Construct prefix l, copy the block, paste it.
                cand = best[l] + Y + Z
                if cand < cur_best:
                    cur_best = cand

                # The block is already in the clipboard at prefix t.
                # Type the gap, then paste.
                idx_tj = t * (t + 1) // 2 + j
                cand = dp[idx_tj] + (l - t) * X + Z
                if cand < cur_best:
                    cur_best = cand

            dp[base_i + j] = cur_best

        best[i] = cur_best

    return best[n]

def main():
    T = int(input())

    out = []

    for tc in range(1, T + 1):
        n, X, Y, Z = map(int, input().split())
        s = list(map(int, input().split()))

        ans = solve_case(n, X, Y, Z, s)
        out.append(f"Case #{tc}: {ans}")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    main()
```接尾辞オートマトン構造は標準です。 新しく追加された各値は通常の状態を作成します。`first`位置は現在の配列インデックスです。 クローンは新しい出現ではないため、クローン作成される状態の最初の出現位置を継承します。 これはまさに、最初に出現するクエリに答えるために必要なプロパティです。 

の`earliest`(n(n+1)/2) 個の空ではない部分文字列があるため、配列では三角形のレイアウトが使用されます。 固定開始位置の場合`l`、行には、からのすべての終了位置が含まれます。`l`を通して`n-1`。 格納されるプレフィックスの長さは最大 5000 であるため、16 ビットの符号なし配列を使用するのが安全です。 

DP も同じ三角形のアイデアを使用しています。 行`i`含まれています`dp[i][0]`を通して`dp[i][i]`したがって、セルの総数は ((n+1)(n+2)/2) となります。 すべて型付けするソリューションでもコストは最大 (5000\cdot10^9=5\cdot10^{12}) ですが、最適なソリューションのコストがそれを超えることはないため、符号付き 64 ビット整数で十分です。 

最も微妙な境界条件は次のとおりです。`t <= l`。 ここ`l=i-j`最後のブロックが追加される前のプレフィックスの長さです。 で終わる出来事`t=l`は、ソースが宛先の開始点とまったく同じ場所で終了するため、有効です。 後に終了する出来事`l`生成されるブロックと重なるため、貼り付け時に紙上に存在することはできません。 

2 番目の DP 遷移では、`best[l]`コピーするとクリップボードが上書きされるため、特定のクリップボードの状態ではありません。 コピーの前に存在していたクリップボードは関係ありません。 対照的に、3 番目の遷移では次を使用する必要があります。`dp[t][j]`間にある文字を入力する際に​​、既存のクリップボードを保持することに依存しているためです。 

## 実用的な例

 ### サンプル 1

 ターゲットは`1 2 3 1 2 3`3 つのコストはすべて 1 です。重要な状態は、最終的に最適になる状態です。 

| プレフィックスの長さ`i`| クリップボードの長さ`j`| 最古の出来事`t`| 移行 |`dp[i][j]`|`best[i]`|
 | --- | --- | --- | --- | --- | --- |
 | 1 | 0 | | タイプ | 1 | 1 |
 | 2 | 0 | | タイプ | 2 | 2 |
 | 3 | 0 | | タイプ | 3 | 3 |
 | 4 | 1 | 1 | 保つ`1`、 タイプ`2 3`、貼り付け | 4 | 4 |
 | 5 | 2 | 2 | 構築 3、コピー`1 2`、貼り付け | 5 | 5 |
 | 6 | 3 | 3 | 構築 3、コピー`1 2 3`、貼り付け | 5 | 5 |

 プレフィックスの長さが 3 の場合、入力するとコスト 3 が得られます。`1 2 3`は最初の 3 つの要素として存在するため、長さ 6 で 1 にコピーし、1 に貼り付けることができます。最終コストは (3+1+1=5) で、サンプル出力と一致します。 

トレースはその理由も示しています`t=l`受け入れなければなりません。 最後の 3 要素ペーストの場合、ソースは位置 0 ～ 2 を占め、デスティネーションは位置 3 から始まります。ソースは境界で正確に終了します。`l=3`。 

### サンプル 2

 ターゲットは`1 2 2 1 2 3`、(X=10) と (Y=Z=8) です。 

| プレフィックスの長さ`i`| クリップボードの長さ`j`| 最古の出来事`t`| 移行 |`dp[i][j]`|`best[i]`|
 | --- | --- | --- | --- | --- | --- |
 | 1 | 0 | | タイプ`1`| 10 | 10 |
 | 2 | 0 | | タイプ`2`| 20 | 20 |
 | 3 | 0 | | タイプ`2`| 30 | 30 |
 | 4 | 1 | 1 | 早めに使う`1`、「gap」と入力し、 | を貼り付けます。 38 | 38 |
 | 5 | 2 | 2 | コピー`1 2`最初の 2 つの値から | を貼り付けます。 46 | 46 |
 | 6 | 0 | | 最終型`3`| 56 | 56 |

 キーの遷移はプレフィックス長 5 で発生します。最初の 3 つの値`1 2 2`タイプするのに30かかります。 次の 2 つの値は次のとおりです。`1 2`、すでに位置 0 と 1 で発生しています。コピーには 8 のコストがかかり、貼り付けにはさらに 8 のコストがかかるため、長さ 5 のプレフィックスのコストは 46 です。`3`コストが 10 なので、56 になります。 

この例は、ソース オカレンスが宛先に隣接する必要がない理由を示しています。 ソース`1 2`は先頭にあり、貼り付けは 3 番目の要素の後に始まります。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(n^2)) | 接尾辞オートマトンは線形であり、すべての部分文字列が一度走査され、DP には (O(n^2)) 個の状態があり、状態ごとに (O(1)) 個の作業が行われます。 |

 二次境界は、特に元の 15 秒と 1024 MB の制限では (n\le5000) に適しています。 Python 実装では、意図的に 2 つの二次テーブルをコンパクトに保存します。`array`通常の Python 整数リストの代わりにオブジェクトを使用することで、従来の 2 次元リストのはるかに大きなオブジェクト オーバーヘッドを回避できます。

 次のハーネスは、送信されたソリューションが次のように保存されることを前提としています。`solution.py`そして暴露します`main()`上に示した関数。```python
import sys
import io
from solution import main

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    try:
        sys.stdin = io.StringIO(inp)
        sys.stdout = io.StringIO()
        main()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

 ## 特殊なケース

 長さ 1 のターゲットの場合、次のように```
1
1 5 1 1
7
```以前に空ではない部分文字列が出現することはありません。 到達可能な唯一の構造は、単一の値を入力することです。 DP セット`dp[1][0]`に`best[0]+X=5`、答えは5です。 

繰り返しのないターゲットの場合、次のようになります。```
1
3 10 1 1
1 2 3
```すべての候補ブロックは、それぞれの宛先に最初に出現するため、その最古の終了位置は、ペースト前に利用可能なプレフィックス長よりも大きくなります。 どちらの貼り付けトランジションも拒否されます。 したがって、DP は 3 つの値をすべて入力し、30 を返します。 

正確に境界で発生する場合は、次のことを考慮してください。```
1
4 10 1 1
1 2 1 2
```最後の 2 要素ブロック (i=4)、(j=2)、および (l=i-j=2) を計算するとき。 ブロック`1 2`最初は終了プレフィックス長 (t=2) で発生します。 (t\le l) なので、ソースはデスティネーションが開始する前に完全に利用可能になります。 長さ 2 のプレフィックスのコストは 20、コピーのコストは 1、貼り付けのコストは 1 なので、22 になります。 

単一の値が繰り返される場合は、次の点を考慮してください。```
1
4 10 1 1
1 1 1 1
```最初の値を入力すると、その値がクリップボードに保存されます。 同じクリップボードを 3 回貼り付けることができます。 合計は(10+1+3=14)となります。 3 番目のトランジションでは既存のクリップボードが保持されるため、DP はその後の貼り付けに対して別のコピー コストを請求しません。 

最大サイズの場合は、(X=Y=10^9) および (Z=1) で 5000 個の同一の値を使用します。 1 つの値の入力には (10^9) のコストがかかり、それをコピーするには別の (10^9) のコストがかかります。残りの 4999 個の値は 4999 個に貼り付けることができます。結果は (2,000,004) です。 64 ビット ストレージの使用により、演算のオーバーフローが防止され、二次テーブルはコンテストの 1024 MB メモリ制限内に収まります。
