 ## 解決策
 ## 問題の理解

 各有向エッジには、0 から 9 までの 1 つの 10 進数が含まれます。パスは左から右への小数として解釈されますが、新しい各桁はさらに 10 の係数で除算されます。たとえば、エッジの重みを含むパス`3, 1, 3`価値がある

 [
 \frac{3+\frac{1+\frac{3}{10}}{10}}{10}=0.313。 
】

 タスクは、頂点からのすべてのパスの値の最大の下限を見つけることです。`0`頂点へ`1`。 サイクルを繰り返し実行すると、有限パスが実際には到達しない限界に近づく値が生成される可能性があるため、最小値と最小値の区別は重要です。 答えはモジュロ (10^9+7) で出力されます。 公式問題は 8 秒の制限時間と 256 MB のメモリを使用します。 

境界は、頂点の数をおよそ 2 次関数で処理できるほど十分に小さいです。 (n\le 2000) の場合、(O(n^2)) または (O(nm)) メソッドが合理的です。特に、すべてのテスト ケースの頂点の合計数が最大 20000、エッジの合計数が最大 40000 であるためです。パスを列挙するアプローチはまったく異なります。サイクルとは、無限に多くのパスが存在する可能性があることを意味し、ある固定長 (L) のパスに注目を限定した場合でも、指数関数的に多くのパスが生成される可能性があります。 歩く。 

直接的な最短パスの実装を誤らせるいくつかの罠があります。 まず、通常のエッジ重みの数値最小化は目的ではありません。 のために```
2 1
0 1 9
```唯一のパスの値は (0.9) なので、答えは (9/10) になります。`300000003`モジュロ (10^9+7)。 ダイクストラ式のエッジの重みの合計では 9 が報告されますが、これは別の問題です。 

第二に、下限に達する必要はない。 考慮する```
3 3
0 2 1
2 2 1
2 1 9
```有限パスの値は (0.19)、(0.119)、(0.1119) などです。 彼らの下限は

 [
 0.11111\ldots=\frac19、
 】

 そのモジュラー値は`111111112`。 有限の最小パスを検索するだけのソリューションでは、実際の答えが見つかりません。 

第三に、頂点 1 に到達できない重みゼロのサイクルが答えに影響を与えてはなりません。 例えば、```
4 4
0 2 3
2 1 4
0 3 0
3 3 0
```答え (0.34=17/50) があります。これは、`380000003`モジュロ (10^9+7)。 頂点 3 のゼロ サイクルは魅力的に見えますが、頂点 1 まで完了することはできないため、無関係です。 

最後に、同じ最小桁を持つ複数のエッジでは、それらのサフィックスを比較する必要がある場合があります。 のために```
4 4
0 2 1
0 3 1
2 1 9
3 1 2
```最初の数字は両方とも 1 であるため、次の数字を使用して決定を行う必要があります。 最適な値は (0.12=3/25) で、次のようになります。`840000006`モジュロ (10^9+7)。 

## アプローチ

 ブルート フォース ソリューションでは、頂点 0 からパスを列挙し、その 10 進数値を計算して、最小値を保持します。 これは単に非効率であるだけでなく、有用なサイクルが任意に何度も横断される可能性があるため、自然な停止点がありません。 分岐係数 (b) を持つグラフでは、長さ (L) のすべての歩行を列挙するのに、すでに (\Theta(b^L)) の作業がかかります。 エッジが 4000 個もある場合、(L=2000) などの境界でも天文学的な数の候補が得られます。 検索を単純なパスに制限しても問題は解決されません。サイクルを繰り返すパスが下限に近づく可能性があるためです。 

重要な点は、10 進数の比較が辞書編集的であるということです。 2 つのパスが完全に異なる最初の桁によって、どちらの値が小さいかが決まります。 したがって、答えは無限の数字のシーケンスであると考えることができます。 有限パスが頂点 1 に到達すると、ウェイト 0 の自己ループを頂点 1 に永久に追加することを想像できます。 その無限の桁シーケンスは、まったく同じ有限 10 進数値を表します。 逆に、1 に到達できるすべての頂点は、有効な有限パスのプレフィックスとして機能できます。 したがって、元の infimum は、頂点 1 にゼロ自己ループを追加した後、頂点 0 から生成できる辞書編集上最小の無限桁シーケンスを見つけることと同等です。これは、公式のソリューションで使用される中心的な変換です。 

頂点 1 に到達できない頂点は、すぐに破棄できます。 残りの頂点のうち、最小重みの出力エッジのみが問題となります。 頂点に重み 2 の外向きエッジと重み 5 の別の外向きエッジがある場合、最初の桁がすでに大きくなっているため、そこから始まる最適な無限シーケンスは 5 エッジを使用できません。 

最小重みのエッジがまだいくつか存在する可能性があります。 ある位置では、同じ最小桁を生成できる頂点が複数ある可能性があるため、それらすべてを候補セットとして保持します。 次の位置で、候補の中から利用可能な最小の桁を再度選択します。 この点集合プロセスを繰り返すと、パスを列挙することなく辞書編集上最小の数字シーケンスが構築されます。 

このシーケンスは最終的には周期的になります。 関連する有限グラフには頂点が (n) 個しかないため、最適な無限ウォークは概念的には有限プレフィックスとそれに続くサイクルで構成されます。 長さが最大 ​​(n) である 2 つの可能なプレフィックス プラス サイクル構造は、その長さの合計内で区別できます。これにより、公式ソリューションで使用される標準の (3n) 桁の境界が得られます。 (3n) 桁を生成し、位置 (n) から始まる部分文字列の最小ピリオドを検索します。 公式社説では、この点集合の反復と (3n) 限界について正確に説明しています。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 経路長の指数関数 | 経路長の指数関数 | 遅すぎる |
 | 点集合の反復 | (O(nm+n^2)) | (O(n+m)) | 承認済み |

 (n^2) 項は、候補サイクル長をテストして周期を見つけることから得られます。 (m\le 4000) と (n\le 2000) なので、境界は指定された制限に適しています。 

## アルゴリズムのチュートリアル

1. 逆グラフを構築し、頂点 1 からグラフ検索を実行します。最終的に 1 に到達できるすべての頂点にマークを付けます。マークされていない頂点に接触するエッジは、有効なパスが使用できないため、無視できます。 
2. 重み 0 の概念エッジ (1\to1) を追加します。これにより、頂点 1 での停止がゼロ桁で永遠に継続することに変換されます。 これにより、有限パスとサイクルを通じて無限に近づくパスのケースを個別に扱う代わりに、無限シーケンスについて完全に推論できるようになります。 
3. 残りのすべての頂点について、その最小の発信エッジの重みを見つけ、正確にその重みを持つエッジが到達するすべての宛先を保持します。 より大きな出力重みは、使用される最初の桁で失われるため、辞書編集上の最小の継続の一部になることはできません。 
4. 候補セット (S={0}) から開始します。 次の桁では、(S) のすべての頂点を検査し、それらの中で最小の最小出力重みを見つけます。 この数字を (d) と呼びます。 回答文字列に (d) を追加します。 
5. (S) を、最小重みが正確に (d) であった古い (S) 内の頂点からの最小重みエッジのすべての宛先に置き換えます。 2 つのパスは現在のプレフィックスを共有しながら、将来の異なるサフィックスを持つことができるため、結び付けられたすべての宛先を保持します。 
6. 前の 2 つの手順を (3n) 回繰り返します。 結果の文字列には、最適な無限 10 進数シーケンスの最終的な周期末尾を識別するのに十分な情報が含まれています。 公式のソリューションは、この (3n) ステップ構造を使用し、位置 (n) 以降のパーツを検索して最小サイクルを探します。 
7. (p) を最大 (n) までの最小の正の整数とし、位置 (n) から位置 (3n-1) までの部分文字列が (p) 位置ごとに繰り返されるようにします。 真のプレフィックスがより早く周期的になる場合でも、周期的表現の開始として位置 (n) を意図的に使用します。 プレフィックスを周期部分に拡張しても、表現される数値は変わりません。 
8. (P) を最初の (n) 桁で表される整数とし、(C) を次の (p) 桁で表される整数とします。 無限小数は

 [
 \frac{P}{10^n}
 +
 \frac{C}{10^n(10^p-1)}。 
】

 この式は、(p) 桁のブロック (C) を繰り返し追加するための等比級数にすぎません。 

1. 式のモジュロ (10^9+7) を計算します。 係数は素数であり、必要なすべての分母は関連する長さに対してゼロ以外であるため、フェルマーの小定理を使用して逆剰余を取得できます。 

### なぜ効果があるのか

 1 に到達できない頂点を削除した後、すべての候補プレフィックスを 1 への有効なパスに完成させることができます。 1 にゼロ自己ループを追加することは、有限パスとその無限のゼロ埋め込みバージョンがまったく同じ数値を持つことを意味します。 このような 10 進数値を比較することは、それらの数字シーケンスを辞書編集的に比較することと同じです。 

すべての位置で、アルゴリズムは現在最適なプレフィックスが生成できる最小の桁を選択します。 より大きな数字で始まるシーケンスはすぐに悪化しますが、選択した数字で始まるすべてのシーケンスは新しい候補セットで表されたままになります。 これにより、(i) 回の反復後、生成された (i) 桁の文字列がすべての有効な継続の中で辞書編集上可能な最小の接頭辞になるという不変条件が得られます。 

グラフは有限であるため、最適な無限継続は、サイクルが後に続く有限の接頭辞によって表すことができます。 公式の (3n) 桁の引数により、生成された文字列から周期部分を識別できることが保証されます。 周期が判明すると、等比級数の公式は、有限経路がその周期に到達しない場合も含めて、その最小値を正確に与えます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve_case(n, m, edges):
    # Reverse graph for finding vertices that can reach 1.
    rev = [[] for _ in range(n)]
    for u, v, w in edges:
        rev[v].append(u)

    good = [False] * n
    good[1] = True
    stack = [1]

    while stack:
        v = stack.pop()
        for u in rev[v]:
            if not good[u]:
                good[u] = True
                stack.append(u)

    # For every useful vertex, keep only minimum-weight outgoing edges
    # whose destinations are also useful.
    min_w = [10] * n
    nxt = [[] for _ in range(n)]

    for u, v, w in edges:
        if not good[u] or not good[v]:
            continue

        if w < min_w[u]:
            min_w[u] = w
            nxt[u] = [v]
        elif w == min_w[u]:
            nxt[u].append(v)

    # The added 1 -> 1 edge of weight zero.
    if good[1]:
        if min_w[1] > 0:
            min_w[1] = 0
            nxt[1] = [1]
        elif min_w[1] == 0:
            nxt[1].append(1)

    # Point-set iteration.
    # cur contains all vertices that can realize the currently
    # smallest prefix.
    cur = {0}
    digits = []

    for _ in range(3 * n):
        d = 10

        for u in cur:
            if min_w[u] < d:
                d = min_w[u]

        digits.append(d)

        new_cur = set()
        for u in cur:
            if min_w[u] == d:
                new_cur.update(nxt[u])

        cur = new_cur

    # Find the smallest period of digits[n:3*n].
    period = None
    for p in range(1, n + 1):
        ok = True
        for i in range(n, 3 * n - p):
            if digits[i] != digits[i + p]:
                ok = False
                break
        if ok:
            period = p
            break

    # The first n digits are the prefix.
    prefix = 0
    for i in range(n):
        prefix = (prefix * 10 + digits[i]) % MOD

    # The next 'period' digits form the repeating block.
    cycle = 0
    for i in range(n, n + period):
        cycle = (cycle * 10 + digits[i]) % MOD

    inv_10_n = pow(pow(10, n, MOD), MOD - 2, MOD)

    ten_p = pow(10, period, MOD)
    cycle_den = (ten_p - 1) % MOD
    inv_cycle_den = pow(cycle_den, MOD - 2, MOD)

    value = (prefix + cycle * inv_cycle_den) % MOD
    value = value * inv_10_n % MOD

    return value

def solve():
    t = int(input())
    out = []

    for case_id in range(1, t + 1):
        n, m = map(int, input().split())
        edges = [tuple(map(int, input().split())) for _ in range(m)]

        ans = solve_case(n, m, edges)
        out.append(f"Case #{case_id}: {ans}")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```逆グラフは到達可能性のためにのみ使用されます。 頂点 1 から始めて、反転グラフで検出されたすべての頂点には、元のグラフの 1 への何らかの有向パスがあります。 この前処理により、ターゲットに決して到達できない、誤解を招くゼロウェイト サイクルも削除されます。 

の`min_w`そして`nxt`配列は 2 番目のリダクションを実装します。 有用な頂点ごとに、`min_w[u]`は次の可能な最小の桁であり、`nxt[u]`には、その数字を達成するすべての宛先が含まれます。 頂点 1 の特殊な自己ループは、元のエッジを読み取った後に挿入されるため、1 に到達すると常にゼロ桁の継続が許可されます。 

点集合ループはアルゴリズムの中心です。`cur`は、すでに選択されている最適なプレフィックスの直後に発生する可能性のあるすべての頂点を表します。 最初のスキャンでは、それらの頂点の中から次の最小の桁が検索されます。 2 番目のスキャンでは、その数字を生成する遷移のみが保持されます。 ニシキヘビ`set`重複する宛先を削除します。これは、入力に平行エッジが含まれる場合に便利です。 

ピリオド検索は意図的に数字から開始します`n`、サイクルの正確な始まりを判断しようとするのではなく。 真のシーケンスが早期に周期的になる場合は、いくつかの周期的な数字をプレフィックスの一部として取得しても問題はありません。 同じ無限の周期的なテールがその長いプレフィックスの後に続くため、式は正確なままです。 

小数自体に関係するすべての算術は、(10^9+7) を法として実行されます。 Python の整数はオーバーフローしませんが、モジュラー リダクションにより中間値が小さく保たれ、意図した算術が明示的に行われます。

    for d in digits[n:n + period]:
        cycle = (cycle * 10 + d) % MOD

    inv_10_n = pow(pow(10, n, MOD), MOD - 2, MOD)
    inv_cycle_den = pow(
        (pow(10, period, MOD) - 1) % MOD,
        MOD - 2,
        MOD
    )

    return (
        (prefix + cycle * inv_cycle_den) % MOD
    ) * inv_10_n % MOD

def run(inp: str) -> str:
    data = iter(map(int, inp.split()))
    t = next(data)
    out = []

    for case_id in range(1, t + 1):
        n = next(data)
        m = next(data)
        edges = [
            (next(data), next(data), next(data))
            for _ in range(m)
        ]
        ans = solve_case(n, m, edges)
        out.append(f"Case #{case_id}: {ans}")

    return "\n".join(out)

## 特殊なケース

 直接のゼロウェイト パスの場合、```
2 1
0 1 0
```候補セットは次から始まります`{0}`次に、頂点 1 に到達します。そこで、追加された自己ループによってゼロ桁のみが生成されます。 生成されたシーケンスは、`000...`なので、答えはちょうど 0 です。 

重み 9 のダイレクト エッジの場合、```
2 1
0 1 9
```最初の桁は強制的に 9 になり、その後、頂点 1 はゼロになります。 順序は`9000...`、(9/10) を表します。 モジュラー計算では (10^{-1}) が使用され、次のようになります。`300000003`。 

定期的な場合には、```
3 3
0 2 1
2 2 1
2 1 9
```最初の桁は 1 です。頂点 2 では、送信される最小桁が再び 1 になるため、候補は頂点 2 に残ります。これは、生成されたシーケンス内で無限に繰り返されます。 最終的に重み 9 のエッジを通過するパスは (0.11111\ldots) に近づき、(1/9) になります。 期間検索では、次の内容を含む 1 桁の周期が見つかります。`1`。 

到達不可能なゼロサイクルの場合、```
4 4
0 2 3
2 1 4
0 3 0
3 3 0
```頂点 1 からの逆検索では、頂点 1、2、および 0 がマークされますが、頂点 3 はマークされません。頂点 3 のゼロ サイクルは、数字の処理が始まる前に削除されます。 したがって、頂点 0 には重み 3 の有用なエッジのみがあり、その後に頂点 2 からの重み 4 が続くため、シーケンスが始まります。`34`そしてゼロ。 値は (34/100=17/50) であり、次のようになります。`380000003`。 

2 番目のサンプルでは、グラフがサイクルを作成します。
