 ## 解決策
 ## 問題の理解

 A、B、Cの3つの島があり、フェリーはA、B、C、A…という順番で周期的に移動することになります。 すべての訪問者は A から出発し、B または C の固定目的地を持っています。訪問者には船酔い制限もあります。`t`。 複数人がフェリーに乗っている場合、次の端の移動時間が最も長くなります。`t`その中で。 フェリーには最大 3 人まで乗車できます。 

船員は重要な追加リソースです。 船員が持っている`t = 1`、目的地はなく、全航路にわたってフェリーに滞在することができます。 フェリーは誰も乗せずに出発することはできないため、各旅行サイクルに 1 人の船員を乗せることができます。 訪問者がボートを降りた後でも、船員は B から C に進み、さらに C から A に戻ることができます。 

入力には最大で次のものが含まれます`n = 50000`テスト ケースごとの訪問者数 (テスト ケースは最大 10 件)。 各訪問者は、目的地と 1 から 1000 までの値のみを入力します。`n`それは、サブセット、順列、または任意のペアを明示的に調査できないことです。 たとえ`O(n^2)`このメソッドは、最大のケースではすでに Python では望ましくないため、ソリューションではフェリー ロードの非常に小さな構造を利用する必要があります。 

フェリー サイクルには船員 1 名と最大 2 名の観光客を乗せることができます。 2 人の訪問者が値を持っていると仮定します。`x <= y`。 両方とも B を希望する場合、B で出発するため、旅行時間は次のようになります。`y`、`1`、 そして`1`。 サイクルコスト`y + 2`。 少なくとも 1 人の訪問者が C を希望した場合、その訪問者は A から B を経て C まで乗車したままになります。最初の 2 つの区間は両方とも時間がかかります。`y`、一方、船員は最後のCからAのレグを一人で持っていきます。 サイクルコスト`2y + 1`。 

したがって、元の問題はペアリングの問題になります。 すべての訪問者のペアは 1 つの A→B→C→A サイクルでまとめて送信され、そのコストは次のとおりです。`y + 2`B-B ペアの場合、

 または`2y + 1`少なくとも 1 つの C を含むすべてのペアに対して、

 どこで`y`大きいほうです`t`そのペアで。 

もし`n`奇妙なことに、訪問者は一人で旅行しなければなりません。 人為的な B 訪問者を 1 人追加することで特殊なケースを回避できます。`t = 1`。 このダミー訪問者を本物の B 訪問者と組み合わせるとコストがかかります`t + 2`、まさにその B 訪問者を一人で送るコストです。 C 訪問者と組み合わせるとコストがかかります`2t + 1`、まさにその C 訪問者を 1 人で送るコストです。 ダミーを追加した後の人数は常に偶数になります。 

いくつかの小さなケースでは、モデリングの間違いが明らかになります。 のために```
1
1
1 5
```答えは`7`、 ない`15`。 訪問者は時間 5 で B に到着し、その後船員だけが時間 1 で B から C までと C から A までの区間を移動します。 A が答えを過大評価するまで、訪問者は船に留まらなければならないと想定する解決策。 

のために```
1
1
2 5
```答えは`11`。 訪問者は B 経由で船内に滞在するため、A から B までと B から C までに時間 5 がかかり、その後船員は時間 1 で A に戻ります。 

のために```
1
3
1 1
1 2
1 3
```答えは`8`。 来場者とのベストなアレンジメント`t = 2`そして`t = 3`、原価計算`5`、一方、`t = 1`訪問者は効果的に一人旅になり、費用がかかる`3`。 最大の訪問者がシングルトンであると単純に仮定すると、間違った答えが得られます。 

より微妙なケースは最初のサンプルです。 訪問者を目的地のみに基づいてペアリングすると、次のコストがかかります。`16`、しかし最適なのは`14`。 最適なペアは B1-C1、B2-B2、B3-C3 であり、コストがかかります。`3`、`4`、 そして`7`。 これは、宛先グループを個別に最適化できないことを示しています。 

## アプローチ

 直接的なブルート フォース ソリューションでは、フェリー ロードへの可能なすべての分割が選択肢として考慮されます。 自転車は船員に座席を 1 つ予約した後、最大 2 人の訪問者を乗せるため、これは本質的に最小コストのペアリングの問題です。 偶数の場合`n`、完全なペアリングの数は`(n - 1)!!`、これは`n = 50000`製品です`49999 * 49997 * ... * 1`。 これらの組み合わせを徹底的に評価することは絶望的です。 

実現可能なフェリーのスケジュールはすべて A で始まり A で終わるサイクルに分解でき、各サイクルには最大でも 2 人の訪問者が含まれるため、強引なアプローチは正しいです。 1 つのサイクルに割り当てられる訪問者が判明すると、そのコストは目的地と最大料金によって完全に決定されます。`t`。 

問題を処理可能にする観察は、増加する訪問者を処理する一方で、現在一致しない訪問者の種類のみが重要であるということです。`t`。 どの時点でも、比類のない B 訪問者を 2 人保持しておく理由はありません。 そのような訪問者がすでに 2 人いる場合、今ペアにすることは、延期することと同じくらい高価ではありません。将来の訪問者はすべて、同等以上の訪問者を持っているからです。`t`。 同じ議論が 2 人の一致しない C 訪問者にも当てはまります。 

したがって、ソートされた順序で訪問者をスキャンする場合、一致しない訪問者 B は最大 1 人、一致しない訪問者 C は最大 1 人存在する可能性があります。 これにより、考えられる状態は 4 つだけになります。どちらのタイプも待機していない、B のみが待機している、C のみが待機している、またはそれぞれ 1 つが待機中です。 

現在の訪問者が B の場合、待機中の B がいない場合はマッチングしないままにするか、待機中の訪問者とペアにすることができます。 待っている訪問者が B の場合、ペアの料金は`t + 2`。 待っている訪問者が C の場合、ペアの料金は`2t + 1`。 現在の C の遷移は、C を含むすべてのペアがコストになる点を除いて類似しています。`2t + 1`。 

ダミー B 訪問者は奇数の実際の訪問者を処理するため、最終状態には常に一致しない訪問者が含まれていてはなりません。 これにより、ソート後の最適化全体が 4 状態の動的プログラムに変わります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O((n - 1)!!) | O(n) | 遅すぎる |
 | 4 つの状態の DP | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての訪問者をペアに分ける`(t, destination)`すべての訪問者を次の基準で並べ替えます`t`。 もし`n`奇妙です、ダミーの訪問者を追加します`(1, B)`。 現在の訪問者が以前の不一致の訪問者とペアになるたびに、現在の訪問者がペアになるため、並べ替えが必要です。`t`ペアの最大値です。 
2. 4 つの DP 状態を維持します。 州`0`一致しない訪問者がいないことを意味します。 州`1`1 人の B 訪問者が一致しないことを意味します。 州`2`1 人の C 訪問者が一致しないことを意味します。 州`3`1 人の B 訪問者と 1 人の訪問者 C が一致しないことを意味します。 各状態は、指定された訪問者をそのまま未使用のままにして、処理されたすべてのペアの最小コストを保存します。 
3. 価値のある B 訪問者を処理する場合`t`、 州`0`この訪問者を一致しないままにし、状態を生成することができます`1`すぐに費用がかかることはありません。 州`1`2 人の B 訪問者をペアにする必要があります。`t + 2`、状態に戻ります`0`。 州から`2`、B ビジターを待機状態のままにし、状態を生成することもできます。`3`、または B と C を組み合わせて、`2t + 1`そして状態に戻ります`0`。 
4. 状態がいつ`3`B と C の両方が含まれており、現在の訪問者が B である場合、現在の B は待機中の 2 人の訪問者のうちの 1 人とペアになる必要があります。 Bコストとのペアリング`t + 2`そしてCを待ったままにします。 Cコストとのペアリング`2t + 1`そしてBを待たせたままにします。 これら 2 つの選択肢は、どちらの選択も後の訪問者に影響を与える可能性があるため、両方とも必要です。 
5. C ビジターを対称的に処理します。 B または C とペアになる場合、そのペアには C が含まれるため、そのコストは常に`2t + 1`。 待機している C がない場合、現在の C は一致しないままにすることができます。 
6. すべての訪問者が終了したら、状態を取得します`0`。 奇数サイズの入力がダミー B ビジターを受け取ったため、すべての実際のビジターをペアにすることができ、ダミーは 1 つの可能なシングルトン サイクルを表します。 一致しない訪問者を含む状態は無効です。 

### なぜ効果があるのか

 不変条件は、現在までの訪問者を処理した後、`t`、各状態の DP 値は、その状態によって記述される訪問者タイプを正確に一致させない、処理された訪問者のすべてのペアの中での最小コストです。 同じタイプの 2 つの一致しない訪問者は、ペアになると現在の最大値がすぐに使用されるため、共存する必要はありません。`t`、ペアリングを延期すると、そのコストを最大値が少なくとも同じ大きさのペアに置き換えることしかできません。 したがって、4 つの状態には、最適な継続に影響を与える可能性のあるすべての情報が含まれています。 

現在の訪問者に対して可能なすべてのアクションは、遷移によって表されます。 一致しないままにすると、そのタイプの待機中の訪問者が 1 人作成されますが、それを可能な唯一の待機中の訪問者のタイプと組み合わせると、対応するフェリー サイクル コストが正確に適用されます。 ダミーは総人数を均等にするため、最適な完全なスケジュールは、状態で終わるパスに対応します。`0`、および state で終わるすべてのパス`0`は、フェリー サイクルの有効なコレクションを説明します。 したがって、最小 DP 値は、まさに可能な限り最短の合計時間になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**30

def solve_case(visitors):
    if len(visitors) & 1:
        # A dummy B visitor with t = 1 represents a possible singleton.
        visitors.append((1, 1))

    visitors.sort(key=lambda x: x[0])

    # State:
    # 0 -> no unmatched visitor
    # 1 -> one unmatched B
    # 2 -> one unmatched C
    # 3 -> one unmatched B and one unmatched C
    dp = [0, INF, INF, INF]

    for t, w in visitors:
        ndp = [INF, INF, INF, INF]

        if w == 1:
            # Current visitor wants B.

            # State 0: leave current B unmatched.
            ndp[1] = min(ndp[1], dp[0])

            # State 1: pair current B with waiting B.
            ndp[0] = min(ndp[0], dp[1] + t + 2)

            # State 2: either leave current B, or pair B with C.
            ndp[3] = min(ndp[3], dp[2])
            ndp[0] = min(ndp[0], dp[2] + 2 * t + 1)

            # State 3: pair current B with either waiting B or waiting C.
            ndp[2] = min(ndp[2], dp[3] + t + 2)
            ndp[1] = min(ndp[1], dp[3] + 2 * t + 1)

        else:
            # Current visitor wants C.

            # State 0: leave current C unmatched.
            ndp[2] = min(ndp[2], dp[0])

            # State 1: either leave current C, or pair it with B.
            ndp[3] = min(ndp[3], dp[1])
            ndp[0] = min(ndp[0], dp[1] + 2 * t + 1)

            # State 2: pair current C with waiting C.
            ndp[0] = min(ndp[0], dp[2] + 2 * t + 1)

            # State 3: pair current C with either waiting B or waiting C.
            ndp[1] = min(ndp[1], dp[3] + 2 * t + 1)
            ndp[2] = min(ndp[2], dp[3] + 2 * t + 1)

        dp = ndp

    return dp[0]

def main():
    T = int(input())
    for case_id in range(1, T + 1):
        n = int(input())
        visitors = [tuple(map(int, input().split())) for _ in range(n)]
        # Store as (t, destination) for convenient processing.
        visitors = [(t, w) for w, t in visitors]

        answer = solve_case(visitors)
        print(f"Case #{case_id}: {answer}")

if __name__ == "__main__":
    main()
```入力は最初に次から変換されます。`(destination, t)`の中へ`(t, destination)`、DP は船酔い制限を増やすように人々を処理するためです。 このソートにより、現在の訪問者が常に最大であることが保証されます。`t`以前に一致しない訪問者と形成されたペアのメンバー。 

奇妙なのは-`n`大文字と小文字の区別は、ソートの前に追加によって処理されます。`(1, 1)`、ダミーの訪問者 B を表します。 このダミー人形は実在の人物ではなく、単なるモデリング装置です。 価値のある実際の B 訪問者とペアになった場合`t`、ペアのコスト`t + 2`、これはまさに船員と一緒に旅行する訪問者の費用です。 C ビジターとペアになった場合のコストは次のとおりです。`2t + 1`、再びシングルトン C トリップと一致します。 

4 つの DP エントリは訪問者ごとにリセットされます。 遷移式はフェリーのルートを直接エンコードします。 B-B ペアのコスト`t + 2`、一方、C を含むすべてのペアにはコストがかかります`2t + 1`。 州`3`現在の訪問者に 2 つの異なる待機パートナーが存在する唯一の状態であるため、両方の遷移を保持する必要があります。 

Python では整数オーバーフローの問題はありません。 最大の答えは次のオーダーにすぎません。`n * max(t)`、 しかし`INF`到達不可能な状態が有効な値に干渉することがないように、意図的に大幅に大きくなっています。 

## 実用的な例

 ### サンプル 1

 並べ替えた後、訪問者は```
B1, C1, B2, B2, B3, C3
```4 つの DP 状態は次のように書かれます。`[none, B, C, BC]`。

### サンプル 2

 実際の訪問者は B5 ですが、訪問者が 1 人であるため、アルゴリズムによってダミーの B1 が追加されます。 

| 処理された訪問者 | なし | B | C | 紀元前 |
 | --- | --- | --- | --- | --- |
 | 開始 | 0 | INF | INF | INF |
 | ダミーB1 | INF | 0 | INF | INF |

 ダミーと本物の訪問者は B-B ペアを形成します。`5 + 2 = 7`。 物理的には、これは訪問者が時間 5 で A から B に移動し、続いて船員が時間 1 で B から C と C から A に移動することを表します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | ソートは 4 つの状態の DP を支配します。つまり、O(n) |
 | スペース | O(n) | 訪問者リストには O(n) メモリが必要ですが、DP 自体は 4 つの値を使用します。 

のために`n <= 50000`、並べ替えは簡単に実践でき、動的プログラミングは訪問者ごとに一定数の操作のみを実行します。 目的地と`t`境界には追加のデータ構造は必要ないため、メモリ使用量は訪問者数に対して線形に維持されます。

def solve_case(visitors):
    INF = 10**30

    if len(visitors) & 1:
        visitors.append((1, 1))

    visitors.sort()

    dp = [0, INF, INF, INF]

    for t, w in visitors:
        ndp = [INF, INF, INF, INF]

        if w == 1:
            ndp[1] = min(ndp[1], dp[0])

            ndp[0] = min(ndp[0], dp[1] + t + 2)

            ndp[3] = min(ndp[3], dp[2])
            ndp[0] = min(ndp[0], dp[2] + 2 * t + 1)

            ndp[2] = min(ndp[2], dp[3] + t + 2)
            ndp[1] = min(ndp[1], dp[3] + 2 * t + 1)

        else:
            ndp[2] = min(ndp[2], dp[0])

            ndp[3] = min(ndp[3], dp[1])

            ndp[1] = min(ndp[1], dp[3] + 2 * t + 1)

        out.append(f"Case #{case_id}: {solve_case(visitors)}")

    return "\n".join(out) + "\n"

 ## 特殊なケース

 単一の訪問者 B のケースはダミーによって処理されます。 のために```
1
1
1 5
```アルゴリズムは B1 を挿入し、B1 と B5 をソートし、それらをペアにします。`5 + 2 = 7`。 これは、時間 5 の物理ルート A から B、時間 1 の B から C、および時間 1 の C から A に正確に対応します。 

単一の C 訪問者の場合も同様に機能します。 のために```
1
1
2 5
```ダミー B1 は C5 とペアになります。 ペアには C が含まれているため、そのコストは`2 * 5 + 1 = 11`。 訪問者は B を経由して船に残り、2 時間 5 行程経って C に到着し、船員は一人で戻ります。 

奇数の訪問者の場合、最大の訪問者ではないシングルトンが生成される可能性があります。 のために```
1
3
1 1
1 2
1 3
```ダミー B1 が追加されます。 ソート後の最適なペアは、B1-ダミーおよび B2-B3 になります。 彼らのコストは`3`そして`5`、与える`8`。 これにより、最後の訪問者または最大の訪問者を盲目的に放置する実装が捕捉されます。 

宛先が混在すると、宛先間のペアリングが必要になる場合があります。 最初のサンプルでは、​​訪問者 B と訪問者 C をペアにするのにコストがかかります`16`。 代わりに、DP は B1-C1 を見つけます。`3`、B2-B2用`4`、および B3 ～ C3`7`、合計`14`。 この改善をもたらすクロスペアリングの選択を正確に記憶するには、4 つの状態があれば十分です。 

最終的には最大値`t = 1000`すべての遷移では整数の加算と 2 の乗算のみが使用されるため、安全です。 50,000 人の訪問者の場合、答えは通常の整数の範囲内に収まり、Python の整数演算によりオーバーフローの懸念が解消されます。
