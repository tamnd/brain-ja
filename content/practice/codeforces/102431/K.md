 ## 問題の理解

 (n) 個の頂点を持つ根付きツリーがあります。 頂点 (i) には人形 (i) が含まれており、頂点 (1) がルートです。 すべての頂点 (v) について、(v) をルートとするサブツリー全体を調べ、そこにあるすべての人形を収集し、できるだけ多くの人形をネストしようとします。 

人形 (i) は人形 (i+1) 内に直接入れ子にすることができ、これを繰り返すことができます。 他の人形番号のペアは安定した入れ子関係を形成できません。 したがって、(4,5,6,7) のようなシーケンスは 1 つのネストされたオブジェクトになる可能性がありますが、(4,5,7) は (5) と (7) を結合できません。 

入力には複数のテスト ケースが含まれています。 各テスト ケースでは、(n-1) 個のエッジを通じてツリーが得られます。 出力には、頂点 (v) ごとに 1 つの値、つまり (v) のサブツリー内のすべての人形を最適にネストした後に残る個別のオブジェクトの最小数が含まれます。 

重要な観察は、(k) 個の連続した人形番号を含む有効なネスト チェーンにより、個別のオブジェクトの数が正確に (k-1) だけ減少するということです。 同様に、選択したサブツリー内に出現する連続ラベル (i) と (i+1) の各ペアは、正確に 1 つのオブジェクトを保存します。 すべてのラベルは 1 回だけ表示されるため、これらの節約は単純にカウントできます。 

最大のテスト ケースには (n=2\cdot10^5) があり、すべてのテスト ケースの合計サイズは最大でも (10^6) です。 すべてのサブツリーを明示的に検査するソリューションでは、パス形状のツリーに対する (O(n^2)) 個の作業が必要になる可能性がありますが、これは実用的な作業をはるかに超えています。 テスト ケースごとに基本的に線形または (O(n\log n)) の作業が必要です。 

不適切な実装が露呈する可能性のあるエッジケースがいくつかあります。 

(n=1) の場合、連続する人形のペアはまったくありません。 入力は```
1
1
```そして答えは```
Case #1: 1
```取り外し可能なペアの数を誤って初期化するソリューションでは、ゼロが生成される可能性があります。 

葉も単純な境界ケースです。 考慮する```
1
2
1 2
```頂点 (2) の部分木には人形 (2) しか含まれていないため、答えは (1) になります。 頂点 (1) の部分木には人形 (1) と (2) が含まれており、それらは一緒に入れ子になっているため、答えも (1) になります。 正しい出力は次のとおりです```
Case #1: 1 1
```よくある間違いは、元のツリーのエッジをネスト ペアとして数えることです。 それはルールではありません。 ラベルは、頂点がツリー内で隣接しているかどうかに関係なく、正確に 1 だけ異なっていなければなりません。 

例えば、```
1
3
1 3
3 2
```は人形 (1,3) と (3,2) の間に木のエッジがありますが、人形 (1) と (2) は連続したペアです。 頂点 (1) のサブツリーには 3 つの人形すべてが含まれているため、人形 (1) と (2) をネストして 2 つのオブジェクトを残すことができます。 出力は```
Case #1: 2 1 3
```頂点 (3) の答えは (3) です。そのサブツリーには人形 (1) ではなく人形 (3) と (2) が含まれているからです。 そのサブツリー内に完全に連続するペアはありません。 

最後の微妙なケースは、多くの連続するペアが同じ最下位共通祖先を持つ場合に発生します。 (1) をルートとするスターでは、(i\ge2) のすべてのペア ((i,i+1)) は LCA (1) を持ちます。 それらはすべてルートの答えに寄与する必要があるため、LCA ごとに 1 つのペアだけを数えるのは正しくありません。 

## アプローチ

 直接的なアプローチは、すべての頂点を個別に処理することです。 選択した頂点 (v) について、そのサブツリーをトラバースし、そこに出現するすべてのラベルをマークし、ラベルをスキャンして両方が存在するペア (i,i+1) の数を数えます。 これは正しいです。そのようなペアはすべて、最終オブジェクトを 1 つだけ保存するからです。 

問題は、同じ頂点が繰り返し訪問されることです。 パス上のサブツリーのサイズは (n,n-1,\ldots,1) であるため、走査の合計量は次のようになります。 

[
 n+(n-1)+\cdots+1=\frac{n(n+1)}2.
 】

 (n=2\cdot10^5) の場合、これは約 (2\cdot10^{10}) 回の頂点訪問に相当します。 非常に小さな定数係数があっても、それは使用できません。 

サブツリーの答えは、サブツリーのサイズと、サブツリーに完全に含まれる連続ラベル ペアの数という 2 つの量のみに依存するため、ブルート フォースが機能します。 サブツリーのサイズは、1 回のツリー走査で頂点ごとに計算できます。 より難しいのは、すべてのサブツリーの連続するペアを一度にカウントすることです。 

連続するラベルの各ペア ((i,i+1)) について、ツリー内のそれらの 2 つの頂点を考慮し、それらの最も低い共通祖先を (L) とします。 (v) が (L) の祖先である場合、(v) をルートとするサブツリーには両方の端点が含まれます。 したがって、この 1 つのペアは、ルートから (L) までのパス上のすべての頂点に 1 つの節約に貢献します。 

これにより、問題はルートからノードへのパスの追加の集合に変わります。 実際には、これらのパス上のすべての頂点を更新する必要はありません。 代わりに、すべてのペア ((i,i+1)) について、その LCA に 1 を追加します。 すべてのペアが処理された後、ボトムアップ ツリーの累積により、LCA からすべての祖先に各寄与が伝播されます。 頂点 (v) での結果の値は、(v) のサブツリーに完全に含まれる連続ラベル ペアの数と正確に一致します。 

残りのタスクは、すべての (n-1) 個の LCA を効率的に見つけることです。 バイナリ リフティングでは、(O(n\log n)) 個の前処理の後、LCA ごとに (O(\log n)) 個の時間がかかります。これは、指定された制約に対して十分に高速です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(n^2)) | (O(n)) | 遅すぎる |
 | 最適 | (O(n\log n)) | (O(n\log n)) | 承認済み |

 公式解の観察は、サブツリーのサイズから、ラベルが 1 つ異なり、頂点が両方ともそのサブツリー内に存在するペアの数を引いたものとして答えを表示することと同じです。 

## アルゴリズムのチュートリアル

 1. 頂点 (1) でツリーをルートします。 すべての頂点とそのバイナリリフティング祖先の深さを計算します。 また、後で頂点をリーフからルートに向かって処理できるように、走査順序も記録します。 
2. すべてのサブツリーのサイズを計算します。 すべてのサブツリーのサイズを (1) に初期化し、逆のトラバーサル順序で頂点を処理し、各子のサイズをその親に追加します。 結果として得られる`size[v]`は、頂点 (v) が選択されたときに収集される人形の正確な数です。 
3. (1) から (n-1) までのすべての (i) について、人形 (i) と (i+1) を含む頂点を見つけます。 LCA を計算し、それを (L_i) と呼びます。 
4. (L_i) の補助配列に 1 を追加します。 すべての (n-1) ペアに対してそれを行うと、再び二次関数になる可能性があるため、ルートから (L_i) まですぐには歩きません。 LCA に寄与を配置すると、後の 1 つのボトムアップ パスでこれらすべてのパスの追加を同時に実行できるようになります。 
5. 逆のトラバース順序で頂点を処理します。 ルート以外の頂点 (v) ごとに、次を追加します。`pairs[v]`に`pairs[parent[v]]`。 この積み重ねを経て、`pairs[v]`LCA が (v) のサブツリー内にある連続ラベル ペアの数に等しくなります。 
6.セット

 [
 答え[v]=サイズ[v]-ペア[v]。 
】

 減算はまさに入れ子の操作です。 サブツリーには最初に次の内容が含まれます`size[v]`別々の人形であり、サブツリーに含まれる連続するペアごとにその数が 1 ずつ減ります。 

### なぜ効果があるのか

 (v) をルートとするサブツリーを考えてみましょう。 (k) 個の連続したラベルのペアが含まれていると仮定します。 このようなすべてのペア ((i,i+1)) は 1 つのネスト リンクとして使用でき、個別のオブジェクトの数が 1 つ減ります。 すべての人形には後続候補と前任候補が 1 つしかないため、これらのリンクは連続するラベルのばらばらのチェーンを形成します。 長さ (r) のチェーンは (r-1) 個のリンクを使用して 1 つのオブジェクトになるため、連続するすべてのペアをカウントすると、正確に合計の削減が得られます。 

特定のペア ((i,i+1)) については、(v) がその LCA の祖先である場合、両方の人形は正確に (v) のサブツリーに属します。 その LCA に 1 つの寄与を配置し、それをルートに向かって伝播します。 したがって、LCA のすべての祖先は正確に 1 つの寄与を受け取り、他のすべての頂点はそのペアから何も受け取りません。 すべてのペアが処理された後、`pairs[v]`これは、(v) のサブツリー内で使用可能な有効なネスト リンクの正確な数です。 

したがって`size[v] - pairs[v]`すべての安定したネストが実行された後のオブジェクトの正確な最小数です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    data = list(map(int, sys.stdin.buffer.read().split()))
    it = iter(data)

    t = next(it)
    output = []

    for case_id in range(1, t + 1):
        n = next(it)

        graph = [[] for _ in range(n)]
        for _ in range(n - 1):
            x = next(it) - 1
            y = next(it) - 1
            graph[x].append(y)
            graph[y].append(x)

        # Root the tree at 0 and build a traversal order.
        parent = [-1] * n
        depth = [0] * n
        order = [0]

        parent[0] = 0

        for v in order:
            for u in graph[v]:
                if u == parent[v]:
                    continue
                parent[u] = v
                depth[u] = depth[v] + 1
                order.append(u)

        # Binary lifting table.
        log = max(1, n.bit_length())
        up = [parent[:]]

        for j in range(1, log):
            prev = up[-1]
            cur = [0] * n
            for v in range(n):
                cur[v] = prev[prev[v]]
            up.append(cur)

        def lca(a, b):
            if depth[a] < depth[b]:
                a, b = b, a

            diff = depth[a] - depth[b]
            bit = 0
            while diff:
                if diff & 1:
                    a = up[bit][a]
                diff >>= 1
                bit += 1

            if a == b:
                return a

            for j in range(log - 1, -1, -1):
                if up[j][a] != up[j][b]:
                    a = up[j][a]
                    b = up[j][b]

            return parent[a]

        # Subtree sizes.
        size = [1] * n
        for v in reversed(order[1:]):
            size[parent[v]] += size[v]

        # pairs[v] initially stores contributions whose LCA is exactly v.
        pairs = [0] * n

        # Doll i is located at vertex i, because numbering and vertices
        # use the same labels.
        for i in range(n - 1):
            a = i
            b = i + 1
            w = lca(a, b)
            pairs[w] += 1

        # Propagate every LCA contribution to all its ancestors.
        for v in reversed(order[1:]):
            pairs[parent[v]] += pairs[v]

        answer = [size[v] - pairs[v] for v in range(n)]

        output.append(
            f"Case #{case_id}: " + " ".join(map(str, answer))
        )

    sys.stdout.write("\n".join(output))

if __name__ == "__main__":
    solve()
```最初のトラバースは無向ツリーをルート化し、次の結果を生成します。`parent`、`depth`、 そして`order`。 再帰的 DFS の代わりに明示的なトラバーサル リストを使用すると、(2\cdot10^5) 頂点を含むパスでの Python の再帰深さの問題が回避されます。 

バイナリリフティングテーブルストア`up[j][v]`、(v) の (2^j) 番目の祖先。 LCA ルーチンは、最初に両方の頂点が同じ深さになるまで深い頂点を上に移動し、次に両方の頂点を 2 の大きな累乗から 1 まで持ち上げます。 それらの祖先が異なる場合、両方とも上に移動されます。 それらの親は LCA になります。 

すべての頂点に 1 つの人形が含まれるため、サブツリーのサイズは 1 に初期化されます。 逆転する`order`親が処理される前に、すべての子がすでにサイズを提供していることを保証します。 

連続するペアごとに、コードは次を使用します。`a = i`そして`b = i + 1`内部表現がゼロベースであるためです。 これらは、1 から始まる表記の人形 (i+1) と (i+2) に対応します。 入力により人形番号と頂点番号が一致することが保証されるため、別個の位置配列は必要ありません。 

の`pairs`配列は最初の LCA でのみ意図的に更新されます。 後の逆走査では、すべてのコントリビューションがルートに向かって移動します。 これは、ルートから LCA へのすべてのパス更新を 1 つのツリー DP パスに圧縮する重要な点です。 

Python の整数はオーバーフローせず、可能な最大の答えまたはサブツリーのサイズは (2\cdot10^5) のみです。 メモリの主な使用はバイナリ リフティング テーブルです。

            diff = depth[a] - depth[b]
            bit = 0

            while diff:
                if diff & 1:
                    a = up[bit][a]
                diff >>= 1
                bit += 1

            if a == b:
                return a

            for j in range(log - 1, -1, -1):
                if up[j][a] != up[j][b]:
                    a = up[j][a]
                    b = up[j][b]

            return parent[a]

        size = [1] * n
        for v in reversed(order[1:]):
            size[parent[v]] += size[v]

        pairs = [0] * n

        for i in range(n - 1):
            pairs[lca(i, i + 1)] += 1

        for v in reversed(order[1:]):
            pairs[parent[v]] += pairs[v]

        answer = [size[v] - pairs[v] for v in range(n)]

        output.append(
            f"Case #{case_id}: " + " ".join(map(str, answer))
        )

    return "\n".join(output)

## 特殊なケース

 単一の頂点の場合、```
1
1
```ペア ((i,i+1)) はありません。 サブツリーのサイズは 1、ペア数は 0、答えは 1 です。 LCA ループは 0 回実行されるため、実装では空のペア セットが自然に処理されます。 

大きなツリーの頂点 (5) などのリーフの場合、サブツリーには 1 つの人形が含まれます。 そのサブツリーのサイズは 1 であり、連続したペアが両方のエンドポイントを持つことはできません。 ペア数は 0 なので、答えは 1 になります。 一部の LCA が実際にそのリーフである場合を除き、ボトムアップの累積によって誤って寄与が追加されることはありません。 

連続しないツリー エッジの場合は、次の点を考慮してください。```
1
3
1 3
3 2
```ツリーにはエッジ ((1,3)) と ((3,2)) が含まれていますが、連続する人形のペアは ((1,2)) です。 このアルゴリズムはラベル ペアを直接調べ、頂点 (1) と (2) の LCA を計算します。ツリー エッジ ((1,3)) または ((3,2)) 自体を入れ子の関係として扱うことはありません。 この区別により正しい結果が得られます。 

ようなスターの場合、```
1
5
1 2
1 3
1 4
1 5
```ペア ((1,2)、(2,3)、(3,4)、(4,5)) はすべて LCA (1) を持ちます。 アルゴリズムが増加します`pairs[1]`4回。 累積には単にペアが存在するかどうかではなく、ペアの数が保存されるため、等しい LCA を結合しても情報が失われることはありません。 ルートにはサブツリー サイズ 5 と 4 つのネスト リンクがあるため、答えは 1 です。 

チェーンの場合、```
1
5
1 2
2 3
3 4
4 5
```すべてのサブツリーは、ラベルの連続した間隔で構成されます。 たとえば、頂点 (3) の場合、サブツリーには人形 (3、4、5) が含まれており、2 つのネスト リンクと答え (3-2=1) が与えられます。 すべての頂点は同じように動作します。 このケースでは、ツリーの深さを可能な限り最大限に活用し、Python で再帰的 DFS よりも反復トラバーサルの方が望ましい理由を確認します。 

最も一般的な境界条件は、連続するペアの LCA が、クエリ対象の選択された両方のサブツリーを厳密に上回る場合です。 このようなペアはどちらのサブツリーにも寄与してはなりません。 LCA 定式化はこれを正確に処理します。ペアはその LCA の先祖にのみ伝播されるため、LCA の下の頂点はそのペアの寄与を決して受け取りません。
