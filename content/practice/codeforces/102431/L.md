 ## 解決策
 ## 問題の理解

 (n \times m) 個の長方形グリッドのブースがあります。 Lee は開始点として任意のブースを選択し、4 つの最初の方向のいずれかを選択できます。 その後のすべての動作は、直進するか、1 回右折してから 1 歩進みます。 左折は決して許可されず、連続する訪問セル間での一連の右折は一度に 1 回のみ許可されます。 

タスクは、すべての (nm) セルを正確に 1 回訪問できる個別の順序をカウントすることです。 訪問セルの順序が異なる場合、2 つのウォークは異なるものとみなされます。 答えはモジュロ (10^9+7) である必要があります。 公式問題には (n,m\le100) があり、最大 100 個のテスト ケースがあり、制限時間は 1 秒、メモリ制限は 256 MB です。 

制約は十分小さいため、線形または定数時間の数式は簡単に十分高速ですが、セル数の指数関数的な値は排除されます。 (100\times100) グリッドには 10,000 個のセルが含まれるため、テスト ケースあたり (O(nm)) であっても、わずか約 10,000 回の操作にすぎません。 対照的に、すべての可能なウォークを列挙すると、深さが 10,000 の指数関数的な検索ツリーが作成されますが、これはまったく実行不可能です。 

主要なエッジ ケースは非常に薄い長方形から構成されます。 (1\times1) グリッドの場合、ブースが 1 つしかないため、訪問順序は 1 つだけです。したがって、答えは 1 になります。通常の長方形を対象とした式では、ここでは誤って 0 が返されます。 例えば、```
1
1 1
```生成する```
Case #1: 1
```(1\times2) グリッドの場合、正確に 2 つの訪問オーダーがあり、1 つはいずれかのセルから始まります。 最初のセルが固定されている場合、最初の方向では追加の注文は作成されません。これは、唯一有用な移動が他のセルに向かうことであるためです。 したがって```
1
1 2
```生成する```
Case #1: 2
```2 番目の簡単な間違いは、(1\times m) と (n\times1) を通常の 2 次元の長方形として扱うことです。 少なくとも 2 つのセルを持つすべての 1 次元グリッドの答えは 2 であり、1 より大きい両方の次元に使用される式ではありません。 たとえば、(1\times100) には、左から右と右から左の訪問順序のみが含まれます。 

## アプローチ

 直接的なアプローチは、すべての可能なウォークに対して深さ優先検索を実行することです。 考えられるすべての開始セルと最初の方向を選択し、そのセルを訪問済みとしてマークし、1 つのセルを移動する前に直進または右折を繰り返し試行します。 歩行がすべての (nm) セルに到達するたびに、それをカウントします。 

この検索は正しいです。すべての正当な訪問順序が検索ツリーの 1 つのブランチに対応し、すべてのブランチがグリッドから出るかセルに再訪問するとすぐに拒否されるためです。 ただし、検索にはほぼすべてのステップで 2 つの選択肢があります。 (N=nm) 個のセルの場合、(O(nm)) 個の可能な開始状態を考慮した後の大まかな上限は、(O(nm\cdot 2^{N})) 個の作業量となります。 (100\times100) グリッドの場合、これは (10^4\cdot2^{10000}) 演算の次数の上限を意味し、リモートでは使用できません。 

有益な観察は、長方形のグリッド内の合法的なウォークには非常に制約があるということです。 Lee は決して左に曲がることができないため、歩行の方向は変更されないか、時計回りに回転することしかできません。 歩道が一度回転すると、その新しい方向は固定され、次の回転ではその時計回りの進行のみを続けることができます。 したがって、すべてのセルを訪れる自己回避歩行は、長方形の中を任意にさまようことはできません。 長方形全体をカバーするには、その境界を螺旋状にトレースする必要があります。 

両方の次元が 1 を超える場合、そのような訪問オーダーは (2(n+m)-4) 個だけです。 カウントを理解する 1 つの方法は、歩行をどこから開始できるか、および外側の境界がパスの残りの部分にどのような影響を与えるかを調べることです。 すべての有効なフルグリッド ウォークは、この螺旋状のトラバースが開始する境界位置の 1 つを選択することによって決定され、4 つのコーナー ケースが適切に識別されます。 結果の数値は正確に

 [
 2(n+m)-4.
 】

 この特性評価は、この問題に対する標準的なコンパクトなソリューションでもあります。 

ブルート フォース検索は、すべての正当なパスを明示的に探索するため機能しますが、部分パスの数が指数関数的に増加するため失敗します。 構造観察により、探索全体が 2 つの辺の長さのみに基づく定数時間の計算に置き換えられます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(nm\cdot2^{nm})) | (O(nm)) | 遅すぎる |
 | 最適 | テスト ケースごとの (O(1)) | (O(1)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 行数と列数 (n) と (m) を読み取ります。 すべてのセルは構造的に同一であるため、答えはセルの内容ではなく寸法のみに依存します。 
2. (n=m=1) の場合、1 を返します。セルは 1 つだけなので、可能な訪問順序は 1 つだけです。 
3. 正確に 1 つの次元が 1 の場合は、2 を返します。非自明な 1 次元グリッドは、2 つの方向を与えて、一方の端点からもう一方の端点まで移動することしかできません。 
4. 両方の次元が 1 より大きい場合、次のように計算します。 

[
 2(n+m)-4.
 】

 4 を減算すると、スパイラルの開始点が 4 つの辺に関連付けられている場合に 2 回カウントされる 4 つの角が考慮されます。 
5. 必要なコマンドを使用して結果を印刷します。`Case #x: y`形式。 最大の答えは (100\times100) の (396) のみであるため、整数演算を使用することで実装と指定された出力要件との互換性が保たれますが、モジュラスが指定された制約の下で実際に関連することはありません。 

**機能する理由** すべての合法的なウォークには、決して反時計回りに回転しない方向があります。 したがって、長方形の完全な走査には、任意のハミルトニアン パスを作成する自由がありません。 その回転は、長方形の時計回りの螺旋構造に強制的に組み込まれます。 2 次元の長方形の場合、可能な完全な螺旋は、(2(n+m)-4) 個の有効な境界の選択肢と 1 対 1 に対応します。 薄い長方形はこの構造を線に折りたたんで、2 つの横断方向のみが残り、単一セルの場合は次数が 1 つだけになります。 これらのケースでは、(n) と (m) の可能な値がすべて網羅されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    t = int(input())
    out = []

    for case in range(1, t + 1):
        n, m = map(int, input().split())

        if n == 1 and m == 1:
            ans = 1
        elif n == 1 or m == 1:
            ans = 2
        else:
            ans = 2 * (n + m) - 4

        ans %= MOD
        out.append(f"Case #{case}: {ans}")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```入力ループはテストケース構造に直接に従います。 各四角形について、最初の条件は、1 次元のケースがチェックされる前に、一意の 1 セルのケースを分離します。 

薄い長方形の表現は、一般的な公式から意図的に分離されています。 (n=1) を (2(n+m)-4) に代入すると (2m-2) が得られますが、これはすべての (m>2) で誤りです。 2 行目がなくなると、ジオメトリが完全に変わります。 

本物の 2 次元長方形の場合、答えは次のように直接計算されます。`2 * (n + m) - 4`。 シミュレーションやグリッドの割り当てはありません。 式自体は指定された範囲の法を下回っていますが、ステートメントが答えの法 (10^9+7) を要求しているため、法演算が含まれています。 

コードはすべての出力行を収集し、それらを 1 回書き込みます。 これは簡単で、100 ものテスト ケースにわたって繰り返し出力呼び出しを行う必要がなくなります。 

## 実用的な例

 このステートメントは 1 つのサンプル (2\times2) を提供します。 2 番目のサンプルがないため、2 番目のトレースでは (2\times3) が使用され、一般的な 2 次元の公式が実行されます。 

### 例 1: (2\times2)

 | ステップ | (n) | (男) | 状態 | 答え |
 | --- | --- | --- | --- | --- |
 | 寸法を読む | 2 | 2 | どちらの次元も 1 より大きい | |
 | 式を適用 | 2 | 2 | (2(n+m)-4) | (2(2+2)-4=4) |
 | 出力 | 2 | 2 | 最終結果 | 4 |

 4 つの訪問順序は、(2\times2) トラバースの 4 つの可能な方向に対応します。 これは、提供されたサンプルと一致します。その出力は次のとおりです。`Case #1: 4`。 

### 例 2: (2\times3)

 | ステップ | (n) | (男) | 状態 | 答え |
 | --- | --- | --- | --- | --- |
 | 寸法を読む | 2 | 3 | どちらの次元も 1 より大きい | |
 | 式を適用 | 2 | 3 | (2(n+m)-4) | (2(2+3)-4=6) |
 | 出力 | 2 | 3 | 最終結果 | 6 |

 このトレースの重要な部分は、長方形を (2\times2) から (2\times3) に増やすと、2 つの可能な完全な走査が追加されることです。 この式は、6 つのセルの明示的なシミュレーションではなく、周囲の寸法のみに依存します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(T)) | 各テスト ケースでは、一定数の算術演算が必要です。 |
 | スペース | (O(T)) | すべてのテスト ケースの出力文字列は、書き込まれる前に保存されます。 アルゴリズム自体は、ケースごとに (O(1)) 個の追加スペースを使用します。 |

 テスト ケースが最大 100 個で、ディメンションが 100 以下の場合、これは利用可能な 1 秒および 256 MB の制限をはるかに下回ります。 この実装では、(100\times100) グリッドの割り当て、検索の実行、またはセルごとの状態の維持は行われません。 

## テストケース```python
import sys
import io

def solve():
    input = sys.stdin.readline
    t = int(input())
    out = []

    for case in range(1, t + 1):
        n, m = map(int, input().split())

        if n == 1 and m == 1:
            ans = 1
        elif n == 1 or m == 1:
            ans = 2
        else:
            ans = 2 * (n + m) - 4

        ans %= 10**9 + 7
        out.append(f"Case #{case}: {ans}")

    sys.stdout.write("\n".join(out))

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    try:
        sys.stdin = io.StringIO(inp)
        sys.stdout = io.StringIO()
        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

# Provided sample
assert run(
    "1\n2 2\n"
) == "Case #1: 4", "provided sample"

# Minimum-size input
assert run(
    "1\n1 1\n"
) == "Case #1: 1", "single cell"

# One-dimensional boundary case
assert run(
    "1\n1 2\n"
) == "Case #1: 2", "one row"

# Transposed one-dimensional case
assert run(
    "1\n5 1\n"
) == "Case #1: 2", "one column"

# Small two-dimensional rectangle
assert run(
    "1\n2 3\n"
) == "Case #1: 6", "2 by 3 rectangle"

# Equal maximum dimensions
assert run(
    "1\n100 100\n"
) == "Case #1: 396", "maximum equal dimensions"

# Multiple test cases together
assert run(
    "4\n1 1\n1 100\n100 1\n3 4\n"
) == (
    "Case #1: 1\n"
    "Case #2: 2\n"
    "Case #3: 2\n"
    "Case #4: 10"
), "mixed boundary cases"

 ## 特殊なケース

 (1\times1) グリッドの場合、アルゴリズムはすぐに最初の分岐を選択します。 まったく動きがないため、訪問シーケンスは単一のセルのみで構成されます。 正確な入力```
1

```生成する`Case #1: 1`。 これにより、2 次元の公式を盲目的に適用してゼロを取得する実装が捕捉されます。

1

```生成する```
Case #1: 2
```グリッドを転置した後も同じ理由が当てはまります。 (100\times1) の場合、答えも 2 になります。この対称性は、回転によってジオメトリが変更されない場合でも、行と列を異なる方法で扱うコードを捕捉するのに役立ちます。

[
 2(2+2)-4=4。

[

 アルゴリズムはグリッドを構築したり走査したりしないため、グリッドが大きくなっても遅くなりません。 これはまさに、総当たり検索に対する構造上の利点です。
