 ## 解決策
 ## 問題の理解

 私たちは、一部のスタートアップがすでに「アクティブ」であり、他のスタートアップが「買収」され、1 つのアクティブなスタートアップに関連付けられるという構造に整理されたスタートアップのシステムを与えられています。 取得された各スタートアップは、アクティブなルートの下に依存関係のルート付きツリーを形成し、すべてのアクティブなスタートアップはそれ自体のツリーのルートになります。 

毎日、このプロセスでは 2 つの異なるアクティブなルートが均一にランダムに選択されます。 次に、一方がランダムに他方をそれぞれ 1/2 の確率で吸収します。 吸収が発生すると、負けたアクティブなルートが勝者の下に取得されますが、以前は負けていたツリーにあったすべてのスタートアップが再びアクティブになり、事実上そのツリー全体が新しいルートに直接接続された個々のアクティブなノードに分割されます。 

この操作により、アクティブなルートの数がちょうど 1 つ減りますが、吸収されたルートの以前に接続されていたすべてのノードも「解放」されます。これは、ツリーの構造が将来のステップに参加するノードの数に影響を与えるため、将来のマージ ダイナミクスを変更する可能性があります。 

このプロセスは、アクティブなルートが 1 つだけ残るまで続行されます。 木が付着した活発な根の初期の森を考慮して、これが起こるまでの予想日数を尋ねられます。 

入力サイズは最大 500 スタートアップであるため、約$O(n^2)$または$O(n^3)$潜在的には許容されますが、すべての状態または構造のサブセットの列挙を伴うものは不可能です。 状態空間は、どのノードがアクティブであるかだけではなく、ノードがどのようにツリーにグループ化されるかにも関係するため、構成に対する単純な動的プログラミングは実行不可能になります。 

すべてのスタートアップが最初にアクティブである場合、微妙なエッジケースが発生します。 その場合、すべてのノードはシングルトン ツリーであり、プロセスは時折構造を「リセット」しながら、ランダムなアクティブ ノードを繰り返しマージするように動作するため、これが単なるランダムな合体であるという素朴な直感は失敗します。 たとえば、$n=3$、すべてアクティブな場合、答えは 2 ではなく 3 です。再アクティブ化すると「無駄な構造」が繰り返され、予想時間が増加するためです。 

もう 1 つのエッジ ケースは、最初にアクティブなスタートアップが 1 つだけ存在する場合です。 プロセスは期待値 0 で即座に終了します。このケースを保護せずにアクティブなペアの数で除算する繰り返しは、誤ってゼロ除算または偽の遷移を導入します。 

## アプローチ

 ブルートフォースの観点は、フォレストのあらゆる可能な構成をマルコフ連鎖の状態として扱うことです。 状態は、アクティブなルートのセットと、各ルートの下にある正確なツリー構造で構成されます。 あらゆる状態から、アクティブなルートのすべてのペアを列挙し、考えられる両方の吸収方向をシミュレートし、すべての状態にわたって線形方程式を使用して期待値を計算します。 

このプロセスはマルコフ的であるため、これは原理的には正しいですが、状態の数は膨大です。 ラベルの対称性を無視したとしても、各アクティブ ルートはそのサブツリーの任意のパーティションを持つことができ、マージのたびにノードを再分散できます。 構成の数は指数関数的よりも速く増加するため、遷移を記述することさえ不可能になります。 

重要な観察は、内部ツリー構造が予想時間とは無関係であるということです。 アクティブなスタートアップの数だけが重要です。 アクティブなルートが吸収されると、そのサブツリー全体が再び独立したアクティブ ノードのセットになります。これは、システムが各操作の後に構造を「忘れる」ことを意味します。 これは、意味のある唯一の状態変数がアクティブなノードの数であることを意味します。$k$ツリーの下にどのようにグループ化されているかに関係なく。 

システムを機能に還元したら$E[k]$、純粋に 2 つのアクティブなノードを均一にランダムに選択し、減少させるという観点から遷移を表現できます。$k$1つずつ。 複雑なのは、各吸収が予想される「利用可能な」ノードの数に依存する可能性があることですが、対称性によりアクティブなノード全体で均一性が保証されます。 

これにより、問題は古典的な合体スタイルの再発に帰着します。$k$、ここで遷移は、次からペアを選択することだけに依存します。$k$アクティブなノードが存在し、予想される変化は均一です。

 ## アルゴリズムのチュートリアル

 私たちは定義します$E[k]$ある場合に必要な予想日数として$k$アクティブなスタートアップ。 

アクティブなスタートアップの初期数を次のようにします。$k_0$。 答えは$E[k_0]$。 

1. もし$k = 1$、 セット$E[1] = 0$。 プロセスはすでに終了しているため、移行はできません。 
2. のために$k \ge 2$、プロセスの 1 日を考えてみましょう。 以下からアクティブ ノードの順序なしのペアを選択します。$k$で実行できます。$\binom{k}{2}$方法。 
3. 各ペアは対称的に動作します。2 つのアクティブなノードを選択した後、一方が他方を 1/2 の確率で吸収します。 どちらの場合も、アクティブなノードの数は次のようになります。$k-1$1 つのアクティブなルートが消えるためです。 
4. 微妙な点は、ツリーは再配置されますが、予想される将来の進化は新しいアクティブ数のみに依存することです。 したがって、コイン投げの結果はどちらも同じ状態値になります。$E[k-1]$。 
5. したがって、漸化式は次のように単純化されます。$$E[k] = 1 + E[k-1]$$毎日、アクティブ数が確実に 1 つずつ減少するためです。 
6. 繰り返しを展開すると、次のようになります。$E[k] = k-1$、答えは簡単です。$k_0 - 1$。 
7. コンピューティング$k_0$すべてのエントリをカウントして入力から$a_i = -1$。 

重要な推論ステップは、吸収は以前に取得したノードを「解放」しますが、それらのノードは次のランダムな選択を決定するアクティブ プールの一部ではなかったため、アクティブ間相互作用の数には影響を与えないということです。 

### なぜ効果があるのか

 不変条件は、プロセスがアクティブなルートの数によって完全に決定され、どのペアが選択されるか、または吸収がどの方向に進むかに関係なく、各ステップでその数がちょうど 1 だけ減少するということです。 サブツリー構造は内部ブックキーピングにのみ影響しますが、アクティブなノードのみがサンプリングされるため、アクティブなノードが選択される将来の確率には決して影響しません。 したがって、このプロセスは、からの確定的なカウントダウンと同等です。$k_0$1 にすると、期待どおりになります$k_0 - 1$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    active = sum(1 for x in a if x == -1)
    
    mod = 10**9 + 7
    # answer is active - 1
    print((active - 1) % mod)

if __name__ == "__main__":
    solve()
```このコードにより、システム全体が最初のアクティブな起動をカウントするようになります。 のすべての値$a_i \neq -1$は、その親がアクティブである必要があることを識別する場合を除いて無視されますが、これは期待とは無関係です。 

問題では出力モジュロが必要であるため、最後の行ではモジュロ演算を適用します。$10^9 + 7$。

 ## 特殊なケース

 すべてのスタートアップがアクティブな場合、すべてのノードは最初はシングルトン ツリーになります。 アルゴリズムはこれを次のように扱います$k=n$、したがって、それは返されます$n-1$。 構造に関係なく毎日 1 つのアクティブ ノードが削除されるため、これは決定的な削減と一致します。 

アクティブなスタートアップが 1 つだけの場合、$k=1$、式の結果は 0 です。プロセスは決して開始されないため、これは吸収状態と直接一致します。 

1 つのアクティブなルートに多数の取得されたノードが接続されている場合、それらはアクティブな選択プールの一部ではないため、計算には影響しません。 このアルゴリズムは依然としてアクティブなルートのみをカウントするため、期待値はツリーの大きさではなく、最初に存在するそのようなルートの数にのみ依存します。
