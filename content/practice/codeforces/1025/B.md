 ## 解決策
 ## 問題の理解

 整数のペアのコレクションが与えられます。 各ペアから、正確に 1 つの数字を選択することができます。 ペアごとに 1 つの選択を行った後、選択された値の複数セットが得られます。 タスクは、選択したすべての値を除算する 1 より大きい整数を見つけることです。 この割り算条件を満たす有効な整数を見つける以外に、何かを最大化または最小化しようとするわけではありません。 そのような整数が存在しない場合、答えは -1 になります。 

重要な視点は、すべての数値の単一の大域約数を探しているわけではないということです。 代わりに、ペアごとに、最初または 2 番目の要素のいずれかを介して要件を「ルーティング」することができます。 この柔軟性が問題を自明ではないものにしています。除数はペアごとに少なくとも 1 つの要素にヒットする必要がありますが、すべてのペアにわたって同じ位置にある必要はありません。 

n が 150,000 までの制約により、あらゆる解が線形または線形に近くなるように強制されます。 すべての数値のすべての約数を調べたり、すべての数値を個別に因数分解しようとする戦略は、数値が 2×10^9 に達するため、構造なしで繰り返すと単純な因数分解が遅くなりすぎる可能性があるため、失敗します。 

グローバルな一貫性を考慮せずにペアごとに貪欲な選択をすると、微妙な失敗例が発生します。 たとえば、常に小さい数値を選択したり、常に最初の要素を選択したりすると、有効な解決策が見つからなくなる可能性があります。 もう 1 つのよくある落とし穴は、1 つの列または両方の列のすべての数値の gcd を計算しようとすることですが、有効な除数がペアごとに列間で切り替わる可能性があるため、失敗します。 

## アプローチ

 直接的な強引なアイデアは、1 より大きいすべての整数を試し、それが弱められた公約数として機能するかどうかを確認することです。 各候補 x について、すべてのペアをスキャンし、各ペアの少なくとも 1 つの要素が x で割り切れることを確認します。 これは正しいですが、実行不可能です。 可能な x 値の範囲は膨大で、n 個のペアにわたる割り切れ性をチェックすると、最悪の解釈ではおよそ O(maxA × n) の動作が発生し、これは限界をはるかに超えています。 

重要な構造上の観察は、有効な答えは各ペアの少なくとも 1 つの数値を除算する必要があるということです。 これは、約数を「担当する」ペアごとに 1 つの数値の選択を固定すると、答えは選択されたすべての数値の約数になる必要があることを意味します。 これにより、問題は、1 より大きい共通の gcd が存在する一貫した選択を検索することに変わります。 

これは、貪欲な伝播のアイデアを示唆しています。つまり、最初のペア、たとえば a1 または b1 から候補を選択し、それが最終的な gcd に寄与すると仮定します。 次に、他のすべてのペアについて、この候補と互換性のある値のみを保持することを強制されます。つまり、実行中の gcd を ai または bi と交差させることで更新できます。 いずれかの時点で両方の選択が gcd を超える (1 になる) 場合、候補は失敗します。 

2 つの初期シードを試す必要があるだけです: a1 から開始するか、b1 から開始します。 有効な解決策が存在する場合、最初のペアはその要素の 1 つが有効な構築に寄与する必要があるため、これらのシードの少なくとも 1 つは正しい選択パターンと一致します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべての整数に対するブルート フォース | O(U・n) | お(1) | 遅すぎる |
 | 2 つの貪欲な gcd 伝播を試してみる | O(n log A) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 有効な解の構築を 2 回試行します。1 回目は最初のペアの最初の要素が解の一部であると仮定し、もう 1 回は 2 番目の要素が解の一部であると仮定します。

1. 選択した開始値と等しい候補 gcd から開始します。 この値は、これまでに選択されたすべての要素を分割する必要がある現在の制約を表します。 
2. 各ペア (ai、bi) を繰り返します。 現在のペアについて、ai が現在の gcd 候補で割り切れるかどうか、または bi がそれで割り切れるかどうかを確認します。 両方が割り切れる場合は、gcd を変更せずに概念的にどちらかの側を選択できます。 1 つだけが機能する場合、私たちはそれを選択することを余儀なくされます。 
3. ai と bi の両方が現在の gcd 候補で割り切れない場合は、候補を修正する必要があります。 直ちに失敗を強制するのではなく、どちらの選択がまだ実行可能な可能性があるかに応じて、 gcd(candidate, ai) または gcd(candidate, bi) を使用して候補 gcd を再計算します。 
4. 更新後、両方のオプションによって互換性が 1 に低下した場合、この開始仮定は失敗し、この試みは早期に中止されます。 
5. すべてのペアの処理が完了し、gcd 候補が 1 より大きい場合、それを出力します。 

最初のペアの他の要素から同じプロセスを繰り返します。 

### なぜ効果があるのか

 このアルゴリズムは、現在の gcd 候補がこれまでに処理されたすべてのペアからの有効な選択と一致するという不変条件を維持します。 すべてのステップで、現在のペアから有効な選択された要素を分割できる値にのみ遷移します。 両方のオプションが gcd を 1 に強制的に下げる場合、将来の選択は新しい共通因数を作成するのではなく、割り算をさらに制限するだけであるため、継続では 1 より大きい有効な約数を復元できません。 これにより、すべてのペアを処理した後に残った候補が有効な弱められた公約数になることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from math import gcd

def check(start):
    g = start
    for a, b in pairs:
        if a % g == 0 or b % g == 0:
            if a % g == 0:
                continue
            else:
                continue
        ga = gcd(g, a)
        gb = gcd(g, b)
        if ga == 1 and gb == 1:
            return 0
        g = ga if ga > 1 else gb
    return g if g > 1 else 0

n = int(input())
pairs = [tuple(map(int, input().split())) for _ in range(n)]

ans = check(pairs[0][0])
if not ans:
    ans = check(pairs[0][1])

print(ans if ans > 1 else -1)
```このソリューションでは、開始値が最終除数に寄与すると仮定するシミュレーション関数を定義します。 次に、実行中の gcd 制約を維持しながら、すべてのペアを調べます。 

実装の重要な詳細は、どちらの値も現在の gcd で割り切れない場合の処理​​です。 その状況では、gcd 削減ステップに移行します。 これが必要なのは、真の答えが候補そのものではなく、現在の候補の約数である可能性があるためです。 このフォールバックがないと、アルゴリズムは有効な構成を誤って拒否してしまいます。 

有効なソリューションでは、どちらかの要素を構築の最初のアンカーとして使用する必要があるため、最初のペアの両方の要素を明示的に試します。

 ### 例 1

 入力:```

| ペア | | b | 前の gcd | アクション | | 後の gcd

 | 1 | 17 | 18 | 17 | 開始 | 17 |

 17 は後のペアと使用可能な構造を共有していないため、この試みはすぐに失敗します。 

ここで開始 = 18。 

| ペア | | b | 前の gcd | アクション | | 後の gcd

 | 3 | 12 | 15 | 6 | 12 割り切れる | 6 |

 最後は 6 で終わりますが、これは有効です。 

このトレースは、互換性によって強制された場合に gcd がどのように縮小し、最終的には有効な約数で安定するかを示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import math

    def solve():
        n = int(input())
        pairs = [tuple(map(int, input().split())) for _ in range(n)]

        def check(start):
            g = start
            for a, b in pairs:
                if a % g == 0 or b % g == 0:
                    continue
                ga = math.gcd(g, a)
                gb = math.gcd(g, b)
                if ga == 1 and gb == 1:
                    return 0
                g = ga if ga > 1 else gb
            return g if g > 1 else 0

        ans = check(pairs[0][0])
        if not ans:
            ans = check(pairs[0][1])
        print(ans if ans > 1 else -1)

    from io import StringIO
    old = sys.stdout
    sys.stdout = StringIO()
    solve()
    out = sys.stdout.getvalue()
    sys.stdout = old
    return out.strip()

 ## 特殊なケース

 重要なエッジケースは、真の答えがペアの最初の要素の約数ではないが、2 番目の要素によっても有効である場合に発生します。 デュアルスタート戦略は、両方のアンカーを試行することでこれを処理し、有効な構成が失われないようにします。 たとえば、正しい約数が 5 で、最初のペアが (6, 10) である場合、6 から開始するとすぐに失敗しますが、10 から開始すると伝播が可能になります。 

もう 1 つの特殊なケースは、早期の gcd 削減が必要な場合です。 開始値が制限的すぎる場合、直接の割り算チェックは失敗しますが、gcd 遷移により隠れた割り数が回復されます。 gcd による削減では、将来のペアと一致しない素因数のみが削除され、無効な因数が導入されることはないため、これは安全です。 

最後に、すべてのペアが個別に互いに素の組み合わせである場合は、即時終了につながります。 ペアの両方の gcd リダクションが 1 に達すると、将来のすべての選択は同じ制約構造によって制限されるため、今後の調​​整では 1 より大きい有効な除数を復元できなくなります。
