 ## 解決策
 ## 問題の理解

 子犬の列の色を表す文字列が与えられます。各文字は「a」から「z」までの色です。 目的は、非常に特殊な操作を使用して、すべての文字が同じになるようにこの文字列を変換できるかどうかを判断することです。 

この操作により、現在少なくとも 2 回出現する色 x のみを選択し、x が出現するたびに、選択した他の色 y に再色付けすることができます。 この操作は何度でも繰り返すことができます。 

重要なのは、再カラーの正確な順序ではなく、最終的に 1 つのカラー クラスを除いてすべてを削除できるかどうかです。 

重要な制約は、色が少なくとも 2 の頻度を持つ場合にのみ色変更に使用できるようになるということです。一度出現した色は再色ソースとして直接選択することはできないため、シングルトンは、他の操作によって間接的に吸収されない限り、「ロックされた」要素のように動作します。 

n が最大 100,000 の場合、どのソリューションも線形時間または線形に近い時間で実行する必要があります。 これにより、敵対的なケースでは O(n²) にまで低下する可能性があるため、各再色付け後の操作のシミュレーションや文字列の繰り返しスキャンが即座に排除されます。 

すべての文字が異なる場合、微妙なケースが発生します。 例えば、`abcdef`。 各色は 1 回ずつ表示されるため、何も操作することはできません。 答えは明らかに「ノー」です。 

もう 1 つの特殊なケースは、すべての文字がすでに同一である場合です。`aaaaa`。 ここでは操作はまったく必要ないため、答えは「はい」です。 

より興味深いケースは、1 より大きい頻度を持つ色が 1 つだけ存在し、他の色はすべてシングルトンである場合です。`aab`。 たとえ 1 つの色が使用可能であっても、再着色の連鎖においてソースとして選択されるのに十分な頻度を他の色に持たないため、決して除去できない色があります。 

## アプローチ

 ブルートフォース解釈では、操作をシミュレートしようとします。 各ステップで、文字列をスキャンし、少なくとも 2 つの頻度で任意の色を選択し、その出現箇所すべてを別の色に再着色します。 各操作の後に周波数を再計算し、すべての文字が等しくなるか、操作が不可能になるまで繰り返します。 

これはルールに直接従うため原理的には機能しますが、各ステップでは文字列全体の頻度を再計算する必要があり、最大 O(n) 個の操作を実行する可能性があります。 各再計算には O(n) のコストがかかるため、最悪の場合の複雑さは O(n²) となり、n = 100,000 では遅すぎます。 

重要な観察は、操作が位置には依存せず、周波数カウントのみに依存するということです。 このプロセスはカラー クラスを繰り返しマージするものと考えることができますが、マージを開始できるのは少なくとも 2 つのサイズのクラスのみです。 

これにより、より単純な不変条件が得られます。複数回出現する少なくとも 1 つの色が存在する場合、それを「コレクター」カラーとして使用し、最終的には他のすべての色をそのカラーに吸収できます。これは、ターゲット カラー y を選択すると、要素を受け取るときに制約を満たす必要がないためです。 唯一の要件は、すべてのマージが完了するまでの各ステップで、周波数 ≥ 2 のソース カラーが少なくとも 1 つ存在することです。 

したがって、私たちが行き詰まる唯一の状況は、開始時に頻度 ≥ 2 を持つ色がない場合です。 この場合、いかなる操作も実行できないため、文字列がすでに統一されていない限り、文字列を統一することはできません。 

したがって、問題は単純なチェックに帰着します。文字列にすでに 1 つの異なる文字がある場合は、「はい」と答えます。 それ以外の場合は、文字の頻度が 2 以上であるかどうかを確認します。はいの場合は「はい」と答え、それ以外の場合は「いいえ」と答えます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(n²) | O(n) | 遅すぎる |
 | 周波数チェック | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 文字列の周波数構造を分析していきます。 

1. 「a」から「z」までの各文字の頻度を数えます。 位置は重要ではないため、これにより操作に関連するすべての情報が取得されます。 
2. 異なる文字が何個存在するかを確認します。 1 つだけ存在する場合、文字列はすでに統一されているため、操作は必要なく、すぐに「はい」を返すことができます。 ターゲット条件がすでに満たされているため、これは機能します。 
3. 異なる文字が複数ある場合は、いずれかの文字が少なくとも 2 回出現するかどうかをスキャンします。 そのような文字が存在する場合は、少なくとも 1 つの操作の有効なソースとして機能する可能性があるため、「はい」を返します。 
4. 頻度が 2 以上の文字がない場合は、「いいえ」を返します。 この状況では、すべての文字は一意であるため、操作を適用することはできず、結合プロセスを開始することもできません。 

### なぜ効果があるのか

 重要な特性は、構成を変更する唯一の方法が、少なくとも 2 つの頻度でソース カラーを選択することであるということです。 そのような色が存在しない場合、システムは完全にフリーズします。 少なくとも 1 つ存在する場合、宛先の色には制限がないため、いつでもそれを使用して他の色を吸収できます。 これは、システムを完全な統合に向けて推進するには、単一の「アクティブな」カラー クラスで十分であることを意味します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    s = input().strip()

    freq = [0] * 26
    for ch in s:
        freq[ord(ch) - 97] += 1

    distinct = sum(1 for x in freq if x > 0)
    if distinct == 1:
        print("Yes")
        return

    for x in freq:
        if x >= 2:
            print("Yes")
            return

    print("No")

if __name__ == "__main__":
    solve()
```26 文字しか存在しないため、頻度配列は入力全体を一定サイズの状態に圧縮します。 小切手`distinct == 1`すでに均一なケースを直接処理します。 2 番目のループは、有効な操作を開始できるかどうかを検出します。 このようなスターターがなければ、変革は不可能です。 

操作のシミュレーションは行わず、存在条件のテストのみを行うため、順序付けの問題は発生しません。

 ## 特殊なケース

 入力用`a`、周波数配列には 0 以外のエントリが 1 つ含まれています。 アルゴリズムが検出するのは、`distinct == 1`そしてすぐに「はい」を返し、些細なケースを正しく処理します。 

のために`abcd`、すべての周波数は 1 です。アルゴリズムは最初の条件をスキップし、何も検出しません。`freq >= 2`、「No」を返し、操作を実行できないという事実と一致します。 

のために`aab`、周波数は`a:2, b:1`。 アルゴリズムは有効なソースを検出し、「はい」を返します。これは、単一の複製可能な色の存在が変換プロセスを駆動するのに十分であることを反映しています。
