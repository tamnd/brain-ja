 ## 解決策
 ## 問題の理解

 私たちに与えられているのは、$n \times n$グリッドと$m$同じサイズの立方体で、それぞれが独自の色を持っています。 各キューブは個別のセルから開始され、最終的に配置されるターゲット セルもあります。 一部のキューブはすでに目的地で開始されている場合がありますが、それ以外の場合はすべてのキューブを移動する必要があります。 

1 回の移動は、1 つの立方体を選択し、それを面を共有する隣接するセルにスライドさせることで構成されます。ただし、そのセルが現在空である場合に限ります。 キューブはジャンプできず、他のキューブを通過することもできません。 目標は、10800 回の移動を厳密な上限として、割り当てられたターゲット位置にすべての立方体を配置するような一連の有効な移動を生成することです。 

制約$n \le 50$そして$m \le n$ボードが小さいことはすぐにわかりますが、移動の制約により、これは最短パスの問題ではなく、マルチエージェントのスケジューリングの問題になります。 距離を最適化するのではなく、実行可能なシーケンスを構築するだけです。これは、検索ではなく建設的な順序付け戦略を示唆します。 

重要な構造上の詳細は、最大 2500 個のセル上に最大 50 個の立方体が存在することです。 これにより、大量の空きスペースが残ります。つまり、作業領域内に少なくとも 1 つの空きセルを維持する限り、キューブを相互に配線できることになります。 

複数の立方体が同じ狭い通路を通過したい場合、微妙な問題が発生します。 各キューブを最短パスに沿って個別にルーティングする単純な戦略は、それ自体が永久にブロックされて失敗する可能性があります。 たとえば、2 つの立方体が調整せずに狭い廊下で位置を交換しようとすると、どちらも必要な空のセルに移動できないため、デッドロックになる可能性があります。 

もう 1 つのエッジ ケースは、立方体がターゲット位置から開始する場合です。 不注意に実装すると、依然として不必要に移動し、後でクリティカル パスをブロックする可能性があります。 動きは元に戻すことができますがコストがかかるため、不必要な動きがシーケンスを膨張させて衝突を引き起こす可能性があります。 

## アプローチ

 ブルートフォース解釈では、各キューブを独立して扱います。他のキューブを障害物として扱いながら、開始点から目的地までの最短経路を計算し、移動するたびにグリッドを更新します。 これは本質的にマルチエージェントの経路探索の問題です。 キューブあたりの BFS は安価ですが、キューブ間の相互作用により独立性が損なわれます。 最悪の場合、キューブが繰り返し互いにブロックし、以前の決定が後の決定を制約するため、後戻りや指数関数的な迂回を強いられる可能性があります。 たとえ解決策が見つかったとしても、エージェント間のグローバルな一貫性を維持することは複雑になります。 

重要な観察は、最適なパスや同時計画は必要ないということです。 進捗を保証することだけが必要であり、キューブの厳密な順序を強制し、グローバルな競合を発生させずに「ローカルで再配置」するための十分な空き領域を与えることで、相互作用を制御できます。 

なぜなら$m \le n$、キューブを 1 つずつ処理し、キューブを処理するときに確実に$i$、以前に固定されたすべての立方体はターゲットで静止したままになり、もう干渉しません。 重要なのは、既に配置されているキューブの周りに現在のキューブを配置するのに十分な空のセルを常に維持することです。 

標準的な建設的なアイデアは、単調な方法で作業することです。つまり、キューブに順序を割り当て、各キューブについて、制御された BFS または空き領域を一時的に使用する貪欲な拡張を使用してターゲットに移動し、以前に配置されたキューブが障害物として扱われるようにします。 障害物に対して空のセルが多数あるため、いつでも障害物を回避してルートを変更できます。 

これにより、複数エージェントのプランニングの問題が、動的だが十分に広いグリッド内で繰り返される単一エージェントのルーティングへと軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 調整のないキューブごとの独立した BFS | 潜在的に指数関数的 | O(n²) | 遅すぎる/失敗する可能性があります |
 | 空き領域が保証された、順序付けられた貪欲なルーティング | O(m・n²) | O(n²) | 承認済み |

 ## アルゴリズムのチュートリアル

 指定された順序でキューブを処理し、有効な構成を徐々に構築します。 

1. グリッド内のすべてのキューブの現在の位置を維持します。 また、すでに正しく配置されており、再度移動することのない「完成した」キューブのセットも維持します。 
2.キューブの場合$i$、すでにターゲットセル上にある場合は、完了済みとしてマークしてスキップします。 これにより、将来のルーティングを妨げる可能性のある不必要な動きが回避されます。 
3. それ以外の場合、他のすべてのキューブ (特に完成したキューブ) を障害物として扱い、キューブを移動しようとします。$i$グリッド上のパスファインディング戦略を使用してターゲットに到達します。 
4. キューブの現在位置からターゲットまで BFS を実行します。ここでは空のセルのみが通過可能です。 なぜなら$n \le 50$、フルグリッド上の BFS は高速です。 
5. BFS から親マップを取得した後、開始点からターゲットまでのパスを再構築します。 
6. パスを段階的に実行し、立方体を次のセルにスライドさせるたびに移動を実行します。 移動するたびに、グリッドの占有率を更新します。 
7. キューブがターゲットに到達したら、そのセルを永続的に占有しているものとしてマークし、今後のキューブがそのセルを通過できないようにします。 

重要な点は、BFS が常に現在のグリッド状態で再計算されることです。つまり、後のキューブは古い計画に依存するのではなく、以前の配置に適応します。 

### なぜ効果があるのか

 どの段階でも、完成したすべてのキューブはターゲット セルを永続的に占有し、残りのすべてのキューブは現在空のセルを通ってのみ移動します。 現在の設定上で常に BFS を使用してルーティングするため、実行する手順はすべてローカルで有効です。 

グリッドが過剰に制約されることはありません。$m \le n \le 50$セルがブロックされ、接続された大きな空き領域が残ります。 これにより、キューブが目的地に到達できる場合でも、BFS は現在の状態でパスを見つけることができ、順序付けにより、以前の配置によって避けられない分離が発生しないことが保証されます。 このプロセスでは、各キューブの到達可能性が帰納的に保存されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

n, m = map(int, input().split())

start = [tuple(map(int, input().split())) for _ in range(m)]
target = [tuple(map(int, input().split())) for _ in range(m)]

# 0-index
start = [(x-1, y-1) for x, y in start]
target = [(x-1, y-1) for x, y in target]

grid = [[-1]*n for _ in range(n)]
pos = list(start)

for i, (x, y) in enumerate(start):
    grid[x][y] = i

dirs = [(1,0), (-1,0), (0,1), (0,-1)]

ops = []

def bfs(sx, sy, tx, ty):
    dist = [[-1]*n for _ in range(n)]
    par = [[None]*n for _ in range(n)]
    q = deque()
    q.append((sx, sy))
    dist[sx][sy] = 0

    while q:
        x, y = q.popleft()
        if (x, y) == (tx, ty):
            break
        for dx, dy in dirs:
            nx, ny = x + dx, y + dy
            if 0 <= nx < n and 0 <= ny < n and dist[nx][ny] == -1:
                if grid[nx][ny] == -1 or (nx, ny) == (tx, ty):
                    dist[nx][ny] = dist[x][y] + 1
                    par[nx][ny] = (x, y)
                    q.append((nx, ny))

    if dist[tx][ty] == -1:
        return []

    path = []
    x, y = tx, ty
    while (x, y) != (sx, sy):
        px, py = par[x][y]
        path.append((px, py, x, y))
        x, y = px, py

    path.reverse()
    return path

for i in range(m):
    sx, sy = pos[i]
    tx, ty = target[i]

    if (sx, sy) == (tx, ty):
        continue

    path = bfs(sx, sy, tx, ty)
    if not path:
        continue

    grid[sx][sy] = -1
    for x1, y1, x2, y2 in path:
        grid[x2][y2] = i
        pos[i] = (x2, y2)
        ops.append((x1+1, y1+1, x2+1, y2+1))

# output
print(len(ops))
for a, b, c, d in ops:
    print(a, b, c, d)
```グリッドは占有を動的に追跡するため、BFS は常に現在の制約を尊重します。 各 BFS は、中間推論に占有されている場合でも、ターゲット セルを明示的に許可します。これは、移動するキューブがセルに入ることが予想されるため、不可欠です。 

再構築ステップでは、親ポインターを実際の移動操作に変換し、すべての出力行が正当な隣接スワップに対応するようにします。 

微妙な点は、移動を実行する前に開始セルからキューブを削除するため、中間の BFS 状態がキューブ自体をブロックしているものとして誤って扱わないことです。 

## 実用的な例

 ### 例 1

 入力:```
2 1
1 1
2 2
```初期グリッドには (0,0) に 1 つの立方体があり、ターゲットは (1,1) です。 BFS は最短パスを見つけます。 

| ステップ | ポジション | 移動 |
 | --- | --- | --- |
 | 開始 | (0,0) | - |
 | 1 | (0,1) | (1,1,1,2) |
 | 2 | (1,1) | (1,2,2,2) |

 これは、立方体が単にマンハッタンのパスをたどっていることを示しており、障害物が存在しないため、BFS は直接ルートを生成します。 

### 例 2

 次のことを考慮してください。```
3 2
1 1
1 2
3 3
3 2
```キューブ 1 は左上から右下に、キューブ 2 は (0,1) から (2,1) に移動する必要があります。 

最初にキューブ 1 を配置した後、その周囲にキューブ 2 を配置します。 

| キューブ | 開始 | ターゲット | パスの動作 |
 | --- | --- | --- | --- |
 | 1 | (0,0) | (2,2) | ストレートっぽい斜め |
 | 2 | (0,1) | (2,1) | 完成したキューブを迂回 |

 トレースは、キューブ 1 が固定されると、キューブ 2 がそれを永続的な障害物として扱い、BFS が自然にそれを回避することを示しています。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、キューブが目的地から開始される場合です。 アルゴリズムは明示的にチェックします`(sx, sy) == (tx, ty)`そしてそれをスキップします。 このチェックがなければ、BFS は依然として自明なパスを返しますが、ターゲット セルを一時的に占有したり空にしたりすることで、後のルーティング決定に干渉する可能性のある不要な移動が生成されてしまいます。 

もう 1 つのケースは、計算中に別のキューブがターゲット セルを占有するため、BFS がターゲット セルを一時的にブロックする場合です。 BFS 条件により、ステップインが明示的に許可されます。`(tx, ty)`たとえそれが占有済みとしてマークされていたとしても、これにより、目的地に到達できないという誤った結論が得られなくなります。 

最後の微妙なケースは、早期に配置すると狭い通路が生じる場合です。 BFS は現在のグリッド状態にあるすべてのキューブに対して再計算されるため、古い仮定に依存するのではなく、自然にこれらのコリドーに適応し、厳しく制約されたレイアウトでも正確さを保証します。
