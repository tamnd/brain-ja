 ## 解決策
 ## 問題の理解

 各位置が正の整数を保持する配列が与えられます。 有効なトリプレットは、3 つのインデックスを昇順に選択し、それらのインデックスの値を調べることによって形成されます。 ただし、すべてのトリプルが許可されるわけではありません。値は右に行くにつれて厳密に減少する必要があり、また、左の値が中央の値で割り切れ、中央の値が右の値で割り切れるという割り算連鎖も満たさなければなりません。 

各クエリについて、注目を配列のセグメントに限定します。 そのセグメント内で有効なインデックスのトリプレットを見つける必要があり、すべての有効なトリプレットの中で、辞書編集的に重み付けされた値が最大のものを選択するように求められます。 左側の値には他のインデックスよりもはるかに大きな n 乗が乗算されるため、スコアリング関数は左側のインデックス、次に中央、次に右側のインデックスを非常に優先します。 この構造は、常に早い位置でより大きな値を優先し、同じ値の候補の中ではより小さなインデックスを優先することを意味します。 

制約は大きく、最大 100,000 個の要素と 100,000 個のクエリがあります。 クエリごとにすべてのトリプルをチェックしようとするソリューションでは、最悪の場合、r3 回の操作が必要になりますが、これは実行可能な制限をはるかに超えています。 クエリあたり O(n²) でも遅すぎます。 

微妙な問題は、最適なトリプルが値に関して必ずしも一意であるとは限らず、複数のインデックス トリプルが同じ値パターンに対応する可能性があることです。 この問題では、同点の場合に辞書編集上最小のインデックスが求められるため、位置を考慮せずに値を追跡するだけの解決策では、簡単に間違った答えが返される可能性があります。 

単純だが危険なエッジ ケースは、割り算を自明に満たす繰り返し値が配列に含まれている場合に発生します。 たとえば、セグメントが`[4, 4, 4, 4]`、インデックスのすべてのトリプルは割り算の観点から有効ですが、答えは次のようになります。`(1, 2, 3)`辞書編集上のタイブレークのため。 最初のインデックスを追跡せずに値のパターンを最大化するだけのアプローチは、ここでは失敗します。 

もう 1 つの注意が必要なケースは、有効なトリプルが存在するが、セグメント境界のギリギリ内側にしか存在しない場合です。 たとえば、有効なチェーンが配列全体に存在するが、そのインデックスの 1 つが外側にある場合です。`[l, r]`、答えは次のようになります。`-1`たとえローカルでは「ほぼ有効」に見えたとしてもです。 

## アプローチ

 ブルートフォース戦略では、すべてのトリプルを列挙します。`(i, j, k)`各クエリ セグメント内で、割り算条件をチェックし、スコアを計算します。 これは、考えられるすべての候補を直接テストするため正しいですが、クエリごとのコストはセグメント サイズの 3 乗に比例します。 要素が 100,000 個ある場合、最悪の場合の 1 つのクエリですでに約 10¹5 の操作が発生し、リモートでは使用できません。 

重要な観察は、有効なトリプルの構造が非常に厳格であるということです。 中央の要素を修正したら`j`、左の要素は次の値で割り切れる値でなければなりません。`a[j]`、右の要素は次の約数でなければなりません。`a[j]`同時に、インデックスの順序制約も尊重します。 これにより、検索空間が任意のトリプルから中間点を中心とした「互換性のある」値の関係のペアに折りたたまれます。 

スコアリング機能も重要な役割を果たします。 左の値は で重み付けされているため、`n²`、有効な解決策はすべて、最初に左側の要素を最大化することによって支配されます。 これにより、すべてのトリプルを同時に考慮するのではなく、「ポジションごとに、可能な限り最適な左右のパートナーを見つける」という問題として扱うことができます。 範囲内で値の最も左にある候補が判明すると、残りの構造は決定的になります。 

これは、前処理のアイデアにつながります。つまり、すべての位置およびすべての可能な値について、割り算の制約を満たす最も近い有効な先行および後続を維持します。 その後、各クエリは中間位置が存在するかどうかを確認することになります。`j`有効な左パートナーが両方とも含まれる範囲内`[l, j)`そして内部には正当なパートナーがいる`(j, r]`。 これらの候補の中から、最初に左側のインデックスを最大化するものを選択し、次に右側のインデックスを選択します。 

ブルート フォースとの違いは、すべてのクエリ内の互換性を再計算するのではなく、値間の構造的関係を事前に計算し、それらを再利用することです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(q · n³) | お(1) | 遅すぎる |
 | 除数 + スキャン候補を事前計算する | O(n√n + q · √n) | O(n√n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. n までのすべての値のすべての約数を事前計算します。 これが必要なのは、有効なトリプルが値間の割り切れる関係に完全に依存しているためです。 事前計算により、後で一定時間のアクセスが可能になります。 
2. インデックスごとに`j`、候補者のリストを作成します`i`そのように左に`a[i] > a[j]`そして`a[i] % a[j] == 0`。 このステップでは、ペアリングできるすべての有効な左エンドポイントを特定します。`j`中間要素として。 
3. 同様に、それぞれについて`j`、有効な右端点を計算します`k`そのような`a[j] % a[k] == 0`そして`a[k] < a[j]`。 これにより、トリプルに必要な構造的互換性が完成します。 
4. ポジションごとに`j`、これらを最も代表的なペアに圧縮します。`(i_best[j], k_best[j])`どこ`i_best[j]`制約内の最大の有効な左インデックスです。`k_best[j]`制約内の最小の有効な右インデックスです。 その理由は、スコアリング関数は大きい左側のインデックスを優先するのに対し、辞書編集のタイブレークは小さい右側のインデックスを優先するためです。 
5. 各クエリについて`[l, r]`、すべてを繰り返します`j`範囲内にあるかどうかを確認してください`i_best[j] >= l`そして`k_best[j] <= r`。 両方の条件が満たされる場合、トリプルのスコアを計算します。`(i_best[j], j, k_best[j])`。 
6. スコア関数に従って最良のトリプルを維持し、より良いスコアが見つかったとき、または辞書編集上の順序が同点を破ったときに更新します。 
7. 有効でない場合`j`制約を満たしている場合は、戻ります`-1`。 

### なぜ効果があるのか

 正確さは、固定された中間インデックスに対して、次の事実に依存します。`j`、左右のエンドポイントの最適な選択は、他のトリプルとは独立しています。 スコアリング関数は厳密な階層を強制します。左の値の最大化が他のすべてを支配するため、それぞれの値が`j`可能な限り最良の有効なものだけが必要です`i`。 同様に、一度、`i`固定されており、有効な最適なものを選択します`k`スコア内の最も重みの低い項のみに影響するため、独立しています。 この分離により、中間位置ごとに局所的に最適なエンドポイントに制限されるため、グローバルに最適なトリプルを見逃すことがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))
q = int(input())

divs = [[] for _ in range(n + 1)]
for i in range(1, n + 1):
    for j in range(i, n + 1, i):
        divs[j].append(i)

pos = [[] for _ in range(n + 1)]
for i, v in enumerate(a):
    pos[v].append(i)

left_best = [-1] * n
right_best = [n] * n

for j in range(n):
    v = a[j]
    li = -1
    ri = n

    for d in divs[v]:
        if d == v:
            continue

        for i in pos[d]:
            if i < j:
                li = max(li, i)
        for i in pos[d]:
            if i > j:
                ri = min(ri, i)

    left_best[j] = li
    right_best[j] = ri

for _ in range(q):
    l, r = map(int, input().split())
    l -= 1
    r -= 1

    best = None

    for j in range(l + 1, r):
        i = left_best[j]
        k = right_best[j]
        if i >= l and k <= r and i < j < k:
            score = n * n * a[i] + n * a[j] + a[k]
            cand = (score, i, j, k)
            if best is None or cand > best:
                best = cand

    if best is None:
        print(-1)
    else:
        print(best[1] + 1, best[2] + 1, best[3] + 1)
```除数の前処理により、各クエリ中に互換性チェックが最初から繰り返されることがなくなります。 配列`left_best`そして`right_best`潜在的な中間ポジションごとに、有効なチェーンに参加できる最も有利なエンドポイントを保存します。 

実装の微妙な詳細はインデックス処理です。一貫性を保つためにすべての計算は 0 から始まるインデックスで行われますが、最終出力は 1 から始まるインデックスに変換し直す必要があります。 もう一つ重要な点は、`left_best[j]`そして`right_best[j]`厳密な順序を尊重しなければなりません`i < j < k`そうでない場合、スコア計算は無効になります。 

## 実用的な例

 配列を考慮してください`[8, 4, 2, 1, 4, 2, 8, 1]`そしてクエリ`[2, 7]`。 

各候補者の中間ポジションについて`j`、割り算に基づいて有効な近傍を計算します。 たとえば、`j = 3`（価値`1`)、より大きいすべての値`1`で割り切れる`1`は左の候補として機能しますが、以下より小さい有効な右の候補はありません。`1`, したがって、このポジションは貢献できません。 

| j | a[j] | 左ベスト[j] | 右_ベスト[j] | 範囲内で有効ですか？ |
 | --- | --- | --- | --- | --- |
 | 2 | 4 | 1 | 3 | はい |
 | 3 | 2 | 1 | 4 | はい |
 | 4 | 1 | - | - | いいえ |
 | 5 | 4 | 4 | 6 | はい |
 | 6 | 2 | 5 | 7 | はい |

 これらの候補者を社内で評価する`[2, 7]`、ベストトリプルは`(2, 3, 4)`1 ベースのインデックス付け。 

このトレースは、アルゴリズムがすべてのトリプルをスキャンするのではなく、中間インデックスごとの局所的な実現可能性によってどのようにフィルター処理するかを示しています。 

有効なトリプルを含まない 2 番目の例。`[3, 5, 7, 11]`、すべての場合に空の左または右のセットを生成します。`j`したがって、すべての候補者が拒否され、答えは次のようになります。`-1`。 これにより、可分性構造の欠如が最終結果に正しく伝播されることが確認されます。

 ## 特殊なケース

 セグメント内のすべての要素が等しい場合、すべての組み合わせは可算性を満たします。 各位置が等しい値を左と右の両方の候補として扱うため、アルゴリズムは引き続き有効なトリプルを選択します。 以来`left_best[j]`が最大インデックスで更新されると、多くの同点が存在する場合でも、最終的な選択は辞書編集上最小のトリプルに収束します。 

左側に有効な約数と右側に有効な倍数の両方を持つ値がない場合、すべての`j`無効な左または右のエンドポイントが生成されます。 この場合、受験者全員が不合格になります。`i < j < k`条件を満たしていないか、クエリの範囲外にあるため、アルゴリズムは正しく返します。`-1`。 

有効なトリプルが部分的に外側に存在する、境界が多いクエリの場合`[l, r]`、事前計算された配列にはまだ有効な値が含まれている可能性があります。`(i, j, k)`構造、ただし範囲チェック`i >= l and k <= r`無効な候補の漏洩を防ぎ、セグメント境界を越えた正確性を保証します。
