 ## 解決策
 ## 問題の理解

 ログを含むものとしてマークされたいくつかのノードを含むツリーがあります。 丸太が切断されると、その黒い半分はその場に残り、赤い半分は黒い丸太を含まない隣接するノードに落ちなければなりません**。 すべてのログは、その赤い半分の宛先として、隣接する非ログ ノードを 1 つだけ選択する必要があります。 目的は、有効な切断構成がいくつ存在するかをカウントすることです。 答えは必須です`1,000,000,007`。 

興味深いのはスタイルの制限です。 黒いログを含むノードは、2 つの異なる隣接ノードに赤いログを持つことはできません。 ブラックログ ノードには、隣接する赤色の宛先が 0 つまたは 1 つある場合がありますが、2 つ以上の宛先があることはありません。 

ツリーには以下が含まれます`100000`ノード。 選択肢の組み合わせを明示的に調べるような解決策は絶望的です。 ログごとの分岐係数が 2 であっても、すでに指数関数的な動作が生じています。 線形または線形に近いツリー DP が唯一の現実的な方向です。 

微妙な観察により、状況は大幅に単純化されます。 

ログノードを検討してください`u`。 自身の赤い半分を隣接する非ログ ノードの 1 つに送信する必要があります。`w`。 以来`w`間違いなく赤いログ、他のすべての非ログ隣接が含まれます`u`完全に非アクティブなままにしておく必要があります。 さもないと`u`少なくとも 2 つの隣接ノードに赤いログが表示され、ルールに違反します。 

このローカルな解釈により、ツリー DP が可能になります。 

## アプローチ

 ブルート フォース ソリューションでは、すべてのログが隣接する非ログ ノードを 1 つ選択し、最終的な構成を検証します。 あれば`m`ログには 2 つの宛先しかありません。つまり、すでに`2^m`可能性。 と`m`まで`100000`、これはまったく不可能です。 

重要な点は、非ログ ノードに関して重要な情報は、そのノードが **アクティブ**になるか **非アクティブ**になるかだけであるということです。 

少なくとも 1 つの隣接するログがその赤い半分をそこに送信する場合、非ログ ノードはアクティブになります。 

ここで、ログ ノードをもう一度見てみましょう。 隣接する非ログ ノードを 1 つだけ選択します。 選択したネイバーはアクティブである必要があります。 他の隣接する非ログ ノードはすべて非アクティブである必要があります。 この条件は、隣接する非ログ ノードのアクティビティ状態にのみ依存します。 

これにより、問題は 2 種類のノードを含むツリー DP に変わります。 

- ログノード
 - 非ログノード

 非ログ ノードの場合は、子ログがそれをアクティブ化するかどうかを追跡します。 

ログ ノードの場合、その赤い半分がその親の非ログ ノードに送信されるか、その子の非ログ ノードの 1 つに送信されるかを追跡します。 

ツリー構造により、これらの選択肢をサブツリー間で独立して組み合わせることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | 指数 | 遅すぎる |
 | 最適なツリー DP | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### DP の状態

 非ログノードの場合`u`:`dp0[u]`= 子ログが赤の半分を送信しないようなサブツリー内のウェイの数`u`。`dp1[u]`= 少なくとも 1 つの子ログが赤い半分を送信するサブツリー内のウェイの数`u`。 

ログノードの場合`u`:`f0[u]`= そのような方法の数`u`は、赤い半分を親に送信しません**。`f1[u]`= そのような方法の数`u`**は** 赤い半分を親に送信します。 

### 非ログノードの処理

 1. すべての非ログ子は、独立して貢献します。`dp0 + dp1`。 
2. ログの子は、次のいずれかをアクティブ化できます。`u`使用状態`f1`、またはアクティブ化しない`u`使用状態`f0`。 
3.`dp0[u]`すべての丸太の子供が選ぶ製品です`f0`。 
4.`dp1[u]`すべての可能性の積から、誰もアクティブ化しない構成を差し引いたものです`u`。 

### ログノードの処理

 1. ログ以外の子をサブツリー内の可能な宛先とします。 
2. ログがその赤い半分を親に送信する場合、ログ以外のすべての子は非アクティブのままでなければなりません。 
3. これにより、`f1`。 
4. ログがその親に送信されない場合は、宛先としてログ以外の子を 1 つだけ選択する必要があります。 
5. 選ばれた子は、どのような方法でも活動できます。 他のすべての非ログ子は非アクティブのままにしておく必要があります。 
6. 選択した子を合計すると、`f0`。 

唯一の技術的な詳細はコンピューティングです$$\sum_i T_i \prod_{j\neq i} A_j$$効率的に、どこで$$A_i = dp0[child_i], \qquad
T_i = dp0[child_i] + dp1[child_i]$$プレフィックスとサフィックスの積を使用すると、ノード全体がその次数で線形時間で処理されます。 

### ルートの処理

 ルートが非ログの場合、答えは次のようになります。$$dp0[root] + dp1[root]$$ルートがログの場合、親がないため、子の中から非ログ近傍を 1 つだけ選択する必要があります。 これは、次の場合に使用されるのと同じ遷移です。`f0`。 

### なぜ効果があるのか

 不変条件は、すべての DP 状態が親が必要とする唯一の情報を完全に記述するということです。 

非ログノードの場合、親はノードがすでにアクティブであるかどうかのみを気にします。 中にある赤い丸太の正確な数は関係ありません。 

ログ ノードの場合、親はログが宛先として親を使用するかどうかのみを気にします。 

ログが宛先を選択するたびに、他のすべての隣接する非ログ ノードは強制的に非アクティブのままになります。 これは元のスタイル ルールと正確に一致します。 すべての有効なグローバル構成は 1 つの固有の DP 選択セットに対応し、すべての DP 構築によって有効な構成が生成されます。 したがって、カウントは正確です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 1000000007

n = int(input())
g = [[] for _ in range(n)]

for _ in range(n - 1):
    a, b = map(int, input().split())
    a -= 1
    b -= 1
    g[a].append(b)
    g[b].append(a)

m = int(input())
is_log = [False] * n
for x in map(int, input().split()):
    is_log[x - 1] = True

parent = [-1] * n
order = [0]

for u in order:
    for v in g[u]:
        if v == parent[u]:
            continue
        parent[v] = u
        order.append(v)

dp0 = [0] * n
dp1 = [0] * n
f0 = [0] * n
f1 = [0] * n

for u in reversed(order):

    if not is_log[u]:

        prod_w = 1

        log_children = []

        for v in g[u]:
            if v == parent[u]:
                continue

            if is_log[v]:
                log_children.append(v)
            else:
                prod_w = (prod_w * (dp0[v] + dp1[v])) % MOD

        none_active = prod_w
        all_cases = prod_w

        for v in log_children:
            none_active = (none_active * f0[v]) % MOD
            all_cases = (all_cases * ((f0[v] + f1[v]) % MOD)) % MOD

        dp0[u] = none_active
        dp1[u] = (all_cases - none_active) % MOD

    else:

        prod_b = 1
        w_children = []

        for v in g[u]:
            if v == parent[u]:
                continue

            if is_log[v]:
                prod_b = (prod_b * ((f0[v] + f1[v]) % MOD)) % MOD
            else:
                w_children.append(v)

        k = len(w_children)

        A = [dp0[v] for v in w_children]
        T = [(dp0[v] + dp1[v]) % MOD for v in w_children]

        pref = [1] * (k + 1)
        suff = [1] * (k + 1)

        for i in range(k):
            pref[i + 1] = pref[i] * A[i] % MOD

        for i in range(k - 1, -1, -1):
            suff[i] = suff[i + 1] * A[i] % MOD

        base = pref[k]

        f1[u] = prod_b * base % MOD

        choose_sum = 0
        for i in range(k):
            term = T[i] * pref[i] % MOD
            term = term * suff[i + 1] % MOD
            choose_sum = (choose_sum + term) % MOD

        f0[u] = prod_b * choose_sum % MOD

root = 0

if not is_log[root]:
    ans = (dp0[root] + dp1[root]) % MOD
else:
    prod_b = 1
    w_children = []

    for v in g[root]:
        if is_log[v]:
            prod_b = (prod_b * ((f0[v] + f1[v]) % MOD)) % MOD
        else:
            w_children.append(v)

    k = len(w_children)

    A = [dp0[v] for v in w_children]
    T = [(dp0[v] + dp1[v]) % MOD for v in w_children]

    pref = [1] * (k + 1)
    suff = [1] * (k + 1)

    for i in range(k):
        pref[i + 1] = pref[i] * A[i] % MOD

    for i in range(k - 1, -1, -1):
        suff[i] = suff[i + 1] * A[i] % MOD

    choose_sum = 0
    for i in range(k):
        term = T[i] * pref[i] % MOD
        term = term * suff[i + 1] % MOD
        choose_sum = (choose_sum + term) % MOD

    ans = prod_b * choose_sum % MOD

print(ans)
```ツリーをルート化した後、ノードは DFS の逆順序で処理されます。 すべての子の DP 値は、その親が評価されるときにすでにわかっています。 

非ログ ノードの場合、実装は、子がノードをアクティブ化しない方法の数と、少なくとも 1 つの子がノードをアクティブ化する方法の数を計算します。 

ログ ノードの場合、実装は次のプレフィックスとサフィックスの製品を構築します。`dp0`非ログの子に対する値。 これにより、特定の宛先の子の選択の寄与を O(1) で計算できるようになり、ノードごとに O(degree²) ではなく O(degree) の処理が行われます。 

ルートには親がなく、赤い半分を上向きに送信することに対応する遷移を使用できないため、別の処理が必要です。 

## 実用的な例

 ### 例 1

 入力:```
5
1 2
2 3
3 4
4 5
3
1 3 4
```ログはノード 1、3、および 4 にあります。 

可能な動きは次のとおりです。 

- 1 → 2
 - 3 → 2
 - 4 → 5

 | ノード | タイプ | 結果 |
 | --- | --- | --- |
 | 1 | ログ | 2 を選択します |
 | 3 | ログ | 2 を選択します |
 | 4 | ログ | 5 を選択します |

 ノード 3 は、1 つの隣接する赤色ノード (ノード 2) のみを認識します。ノード 4 は、1 つの隣接する赤色ノード (ノード 5) のみを認識します。設定は有効です。 

答え = 1。 

### 例 2

 入力:```
6
1 2
2 3
3 4
3 5
5 6
2
2 5
```ログはノード 2 と 5 にあります。 

ノード 2 はノード 1 またはノード 3 に送信できます。 

ノード 5 はノード 3 またはノード 6 に送信できます。 

有効な結果は次のとおりです。 

| ログ 2 | ログ5 |
 | --- | --- |
 | 1 | 6 |
 | 3 | 6 |

このトレースは、複数のログが赤の半分を同じ非ログ ノードに送信する可能性があり、アクティブ/非アクティブ ステータスのみが重要であることを示しています。

 ## 特殊なケース

 ログ ノードには隣接する非ログ ノードがまったく存在しない場合があります。```
3
1 2
2 3
3
1 2 3
```すべてのノードにはブラック ログが含まれています。 レッドハーフはブラックログノードに入ることが禁止されているため、移動することはできません。 すべてのログ ノードには有効な宛先の選択肢がないため、DP は当然ゼロを返します。 

もう 1 つの注意が必要なケースは、複数のログが赤の半分を同じ非ログ ノードに送信できる場合に発生します。 それは完全に合法です。 制限は、ノードに含まれる赤い半分の数に関するものではありません。 この制限は、黒ログ ノードが認識できる赤ログを含む隣接ノードの数に関するものです。 DP で使用されるアクティブ/非アクティブの表現は、まさにその区別を捉えています。
