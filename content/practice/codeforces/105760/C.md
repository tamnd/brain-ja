 ## 解決策
 ## 問題の理解

 ドナルドは電子レンジに次の形式で時間を入力します。`MM:SS`、それが分と秒を意味することを期待しています。 残念ながら、電子レンジはまったく同じ数字を解釈します。`HH:MM`、時間と分を意味します。 

たとえば、ドナルドが入った場合、`02:15`、彼は電子レンジが 2 分 15 秒間作動すると予想しています。 代わりに、電子レンジは 2 時間 15 分間作動します。 

この誤解によって生じる余分な調理時間を計算する必要があります。 答えは次のように出力する必要があります`HH:MM:SS`。 

入力は単一の文字列で構成されます`MM:SS`。 どちらの部分も 0 ～ 59 であり、少なくとも 1 つはゼロ以外です。 出力は以下の差分です。 

1. 実際に入力された時刻。時と分として解釈されます。 
2. ドナルドが意図した時間。分と秒として解釈されます。 

入力にはタイムスタンプが 1 つだけ含まれており、範囲が狭いため、ここでは効率は無関係です。 定数時間の算術ソリューションはどれも簡単に十分に高速です。 本当の課題は、異なる時間単位間で正しく変換し、結果をフォーマットすることです。 

よくある間違いは、フィールドを個別に減算することです。 考慮する：```
00:10
```ドナルドは 10 秒かかると予想しています。 

電子レンジはそれを 10 分として解釈します。 

違いは次のとおりです。```
600 - 10 = 590 seconds
```これは以下に等しい:```
00:09:50
```最初にすべてを秒に変換せずに、分と秒を別々に減算すると、必要な借用を簡単に誤って処理してしまう可能性があります。 

もう 1 つの簡単な落とし穴は、秒がゼロ以外の場合に発生します。 

入力：```
05:00
```予想時間:```
5 minutes = 300 seconds
```実際の時間:```
5 hours = 18000 seconds
```違い：```
17700 seconds = 04:55:00
```表示された数値を比較するだけのソリューションでは、時間と分がまったく異なる単位スケールに対応していることを見落とす可能性があります。 

## アプローチ

 最も直接的なアプローチは、両方の解釈を秒に変換することです。 

入力が`MM:SS`。 

ドナルドの予定期間は次のとおりです。```
MM minutes + SS seconds
```これは以下に等しい:```
MM * 60 + SS
```秒。 

電子レンジの実際の持続時間は次のとおりです。```
MM hours + SS minutes
```これは以下に等しい:```
MM * 3600 + SS * 60
```秒。 

必要な答えは、単にこれら 2 つの値の差です。 

より面倒なアプローチは、借用を使用して、時間、分、秒を使用して時間の減算を手動で実行することです。 これは機能しますが、不必要な複雑さが生じ、借用操作中にオフバイワンの間違いが発生する機会が生じます。 

重要な観察は、すべてが 1 つの単位で表現されると、時間計算が簡単になるということです。 差を秒単位で計算した後、除算と剰余演算を使用してそれを時、分、秒に変換し直します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 借用による手動時間減算 | お(1) | お(1) | 承認済み |
 | 秒に変換して減算します。 お(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力文字列を読み取り、コロンで分割します。 
2. 2 つの値を整数として解析します。`m`そして`s`。 
3. ドナルドが意図した期間を計算します。```
intended = m * 60 + s
```4. 電子レンジが実際に使用する時間を計算します。```
actual = m * 3600 + s * 60
```5. 延長時間を計算します。```
diff = actual - intended
```6.変換`diff`時、分、秒に戻ります。```
hours = diff // 3600
diff %= 3600

minutes = diff // 60
seconds = diff % 60
```7. 各フィールドに 2 桁を使用して結果を出力します。 

### なぜ効果があるのか

 どちらの解釈も同じ数値のペアを表しますが、それらに異なる単位が割り当てられます。 

意図した継続時間は分と秒として測定されますが、電子レンジでは時間と分として扱われます。 両方の時間を合計秒数に変換すると、あいまいさがすべて取り除かれ、単純な減算が可能になります。 

すべての所要時間は正確に秒単位で表されるため、計算された差は追加の調理時間と数学的に同じになります。 その差を時、分、秒に戻すことは、単に合計秒数を標準の時間単位に分解することになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

m, s = map(int, input().strip().split(':'))

intended = m * 60 + s
actual = m * 3600 + s * 60

diff = actual - intended

hours = diff // 3600
diff %= 3600

minutes = diff // 60
seconds = diff % 60

print(f"{hours:02d}:{minutes:02d}:{seconds:02d}")
```最初のステップでは、入力の 2 つのコンポーネントを解析します。 

次に、ソリューションは 2 つの独立した期間を計算します。 1 つはドナルドが望んでいたものに対応しており、分と秒で測定されます。 もう 1 つは、時間と分で測定される同じ数字を電子レンジがどのように解釈するかに対応します。 

継続時間を差し引いた残りの値は秒数になります。 に戻る変換`HH:MM:SS`標準的なプロセスに従います。最初に時間を抽出し、次に残りから分を抽出し、その後に残ったものから秒を抽出します。 

書式設定文字列`:02d`この問題ではすべてのフィールドに正確に 2 桁の数字が必要なので、これは重要です。 それがないと、次のような値が発生します。`4:5:0`の代わりに印刷されます`04:05:00`。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    m, s = map(int, input().strip().split(':'))

    intended = m * 60 + s
    actual = m * 3600 + s * 60

    diff = actual - intended

    h = diff // 3600
    diff %= 3600
    mm = diff // 60
    ss = diff % 60

    return f"{h:02d}:{mm:02d}:{ss:02d}"

# provided samples
assert run("05:00\n") == "04:55:00"

# minimum positive duration
assert run("00:01\n") == "00:00:59"

# exactly one minute intended, one hour actual
assert run("01:00\n") == "00:59:00"

# largest values
assert run("59:59\n") == "58:59:01"

# only seconds component present
assert run("00:59\n") == "00:58:01"
