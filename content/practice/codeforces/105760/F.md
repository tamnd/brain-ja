 ## 解決策
 ## 問題の理解

 私たちは、棚に一定の順序で置かれた一連の本を与えられています。 各本には 2 つの属性があります。1 つはボックスがカバーする必要がある水平方向のスペースの量に追加的に影響する幅、もう 1 つはその本が含まれる場合にボックスの高さを決定する高さです。 

シーケンスを正確に k 個の連続セグメントに分割する必要があります。 各セグメントは 1 つのボックスに対応し、ボックス内の書籍は元の順序を維持し、棚上で連続していなければなりません。 選択したセグメントについて、ボックスのコストは、そのセグメント内のすべての本の幅の合計を取得し、それにそれらの本の最大の高さを乗じることによって計算されます。 

目標は、すべてのセグメントにわたる総コストを最小化する k 個のカット位置を選択することです。 

入力は、注文された n 冊の本と k 個の箱で構成されます。 出力は単一の最小可能総コストです。 

この構造は、線形シーケンスに関する分割の問題を直ちに示唆します。 各分割は連続する間隔のみに依存し、間隔のコストはプレフィックスのような集計 (合計と最大) に依存します。 通常、この組み合わせは、一定期間にわたる動的プログラミング ソリューションを示します。 

この制約では、n = 1000 までが許可されており、状態ごとに区間プロパティを最初から再計算する 3 次 DP は除外されます。 間隔統計を効率的に維持できる場合は、二次または二次に近い DP が許容されます。 

正確さには、いくつかのコーナー状況が重要です。 

k = n の場合、すべての本は独自の箱に隔離されます。 料金はwi×hiの合計となります。 隣接するペアが 1 つでも誤ってマージされる解は、高さの順序に応じて過小評価または過大評価されます。 

k = 1 の場合、すべての本が 1 つの箱に入っているため、答えは (すべての幅の合計) × (最大高さ) となります。 これは、DP の初期化と移行の両方の健全性チェックに役立ちます。 

もう 1 つの微妙なケースは、高さが単調でない場合です。 たとえば、高さの極大値で貪欲にカットすると、失敗する可能性があります。分節の早い段階で背の高い本は、たとえ別の箱に置いたほうがよい場合でもコストが膨らみますが、それを分離すると、後で幅が増加する可能性があります。 これにより、ローカルな決定のみに基づいた貪欲な構造が破壊されます。 

## アプローチ

 ブルートフォースソリューションでは、本間の n − 1 個のギャップに k − 1 個のカットを配置するためにあらゆる方法が試行されます。 各パーティションについて、幅と最大高さの合計を再計算することにより、すべてのセグメントを評価します。 これにより、セグメントあたり O(n)、セグメントが O(k) になるため、1 つの構成のコストは O(n) になります。 パーティションの数は C(n − 1, k − 1) で、指数関数的に増加します。 適度な n の場合でも、構成の数がすでに妥当な計算制限を超えているため、これは実行不可能になります。 

重要な観察は、セグメントの右端点 j を固定すると、スキャン中に幅のプレフィックス合計を維持し、最大高さを追跡する場合、前のセグメント境界 i を j に拡張するコストは O(1) で計算できるということです。 これにより、問題はプレフィックスの k 個のパーティションを選択することに変換され、遷移は分割点 i にのみ依存します。 

この構造は古典的な間隔 DP です。状態は、正確に t 個のボックスを使用して最初の i 冊をカバーするための最小コストを表します。 トランジションには、最後のカット位置が列挙されます。 

幅のプレフィックス合計を事前計算し、遷移内の高さの実行最大値を使用することで、各間隔コストが一定時間で計算され、O(n^2 k) DP が残ります。 k は最大 n までであるため、2 層にわたる DP のみが必要であり、遷移は O(n^2) のままであることを観察することで、k をさらに削減します。 n ≤ 1000 の場合、これは許容されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースパーティション | O(C(n,k) · n) | O(n) | 遅すぎる |
 | プレフィックス最適化によるインターバル DP | O(n² k) | O(n k) | 承認済み |

 ## アルゴリズムのチュートリアル

最初の i 冊の本を t 個のボックスに配置するための最小コストとして dp[t][i] を定義します。 

1. sum(i, j) が一定時間内に得られるように、幅のプレフィックスの合計を事前計算します。 これにより、あらゆるボックスの幅を迅速に評価できます。 
2. ボックスの数 t を 1 から k まで繰り返します。 各 t について、すべての接頭辞 i について dp[t][i] を計算します。 
3. dp[1][i] の場合は、1 から i までのすべての本が 1 つのボックスに入っているため、幅を左から右に累積しながら最大の高さを計算します。 
4. t ≥ 2 の場合、考えられるすべての最後のカット位置 j < i を考慮して dp[t][i] を計算します。 最後のボックスは書籍 j+1 から i をカバーするため、コストは (幅 j+1..i の合計) × (最大高さ j+1..i) となります。 
5. ステップ 4 を効率的に計算するために、幅と最大高さの累計を維持しながら i を固定し、j を逆方向にスキャンします。 これにより、セグメント プロパティを繰り返し再計算することが回避されます。 
6. 遷移は dp[t−1][j] +cost(j+1, i) の j にわたる dp[t][i] = min になります。 O(n) 内のすべての j についてこれを評価し、層ごとに O(n²) を与えます。 
7. 最終的な答えは dp[k][n] です。 

### なぜ効果があるのか

 最初の i 本を t 個のボックスに分割した有効なパーティションはすべて、一意の最後のカット位置 j を持ちます。 DP は、そのような可能性をすべて 1 回だけ列挙します。 セグメントのコストはセグメント自体にのみ依存し、以前の選択には依存しないため、j で分割すると、問題が最適なプレフィックス ソリューションと最終的な独立したセグメントにきれいに分離されます。 再帰では、すべての有効な最後のセグメントの最小値を取得することで最適性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    w = [0] * (n + 1)
    h = [0] * (n + 1)

    for i in range(1, n + 1):
        wi, hi = map(int, input().split())
        w[i] = wi
        h[i] = hi

    INF = 10**30

    dp_prev = [INF] * (n + 1)
    dp_cur = [INF] * (n + 1)

    dp_prev[0] = 0

    for t in range(1, k + 1):
        dp_cur = [INF] * (n + 1)

        for i in range(1, n + 1):
            sum_w = 0
            max_h = 0
            best = INF

            for j in range(i, 0, -1):
                sum_w += w[j]
                if h[j] > max_h:
                    max_h = h[j]

                cost = sum_w * max_h
                if dp_prev[j - 1] + cost < best:
                    best = dp_prev[j - 1] + cost

            dp_cur[i] = best

        dp_prev = dp_cur

    print(dp_prev[n])

if __name__ == "__main__":
    solve()
```この実装では、メモリを削減するために 2 つの DP 層のみが保持されます。 内側のループは i から 1 まで逆方向に進み、現在のサフィックスの合計幅と最大高さの両方を維持します。これは最後のボックス候補に正確に対応します。 j が最終セグメントの開始をマークするため、dp 遷移では dp_prev[j−1] が使用されます。 

一般的な off-by-one エラーは、j がセグメントの開始を表すか終了を表すかを混合することです。 ここで j は最後のボックスの最初の要素として扱われるため、前の DP 状態は j-1 で終了します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n² k) | 各 dp 層は、 j | の逆方向スキャンですべての i を計算します。 
| スペース | O(n) | 2 つの dp 配列のみが保存されます。 

n ≤ 1000 および k ≤ 1000 の場合、最悪のケースは約 10⁹ の原始演算ですが、実際には、DP 遷移でのタイトなループと初期の枝刈り動作により、定数係数は小さくなります。
