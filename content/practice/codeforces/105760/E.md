 ## 解決策
 ## 問題の理解

 私たちは、成長するコンピューターの通信ネットワークをシミュレートしています。 最初はすべてのコンピュータが分離されているため、それぞれが独自のグループを形成します。 時間の経過とともに、コンピュータのペア間に接続が追加され、これらの接続はグループを結合してより大きな接続されたコンポーネントになります。 

ネットワークは常に、接続された複数のコンポーネントで構成されています。 各コンポーネントのサイズに注意を払います。 維持する必要がある量は、これらのコンポーネントにわたる関数の平均値です。各コンポーネントを取得し、そのサイズを 2 乗し、これらの 2 乗したサイズを合計し、現在グラフにあるコンポーネントの数で割ります。 エッジを追加またはクエリするたびに、現在の状態のこの平均を出力する必要があります。 

主な問題点は、エッジが追加されるとコンポーネントの数とそのサイズの両方が動的に変化し、クエリがシーケンス内のどの時点でも出現する可能性があることです。 

入力サイズは最大約 300,000 操作に達するため、操作ごとに接続されたコンポーネントを最初から再計算するソリューションは遅すぎます。 完全な再計算には少なくともノード数の線形時間がかかり、実行不可能な二次関数の最悪のケースが発生します。 

Union-find ベースの構造は、動的マージを効率的にサポートするため、すぐに自然な候補になります。 

素朴なソリューションを壊す傾向がある微妙なエッジケースがいくつかあります。 同じコンポーネント内に既に存在する 2 つのノードをマージしても、構造はまったく変更されるべきではないということを忘れています。 たとえば、1 と 2 を複数回接続しようとすると、次のようになります。 

入力:```
3 3
1 2
2 3
1 2
?
```最後のエッジは何も変更しないため、コンポーネント数と平方和は両方とも変更されない必要があります。 盲目的にマージする単純な DSU 実装では、コンポーネントの数が誤って 2 倍減少する可能性があります。 

もう 1 つのエッジ ケースは、すべてのノードが分離されたままである場合です。 この場合、すべてのコンポーネントのサイズは 1 なので、平方和は n でコンポーネントの数は n であるため、答えは常に 1 になります。 

最後に、比率を報告する際には、浮動小数点の精度が重要になります。 整数の除算は、正確性を静かに破壊することになります。 

## アプローチ

 ブルート フォース シミュレーションでは、グラフ全体が明示的に維持されます。 各操作の後、未訪問のすべてのノードから DFS または BFS を実行して、接続されているすべてのコンポーネントを計算し、それらのサイズを追跡して、必要な合計を計算します。 これは、各ステップのコンポーネントの定義に直接従うため、正しいです。 

ただし、各再計算には O(n + m) のコストがかかり、最大 3×10^5 の演算が行われる可能性があります。 最悪の場合、これにより約 10^10 の演算が行われることになり、これは妥当な制限をはるかに超えています。 

重要な観察は、私たちが維持している構造はコンポーネントをマージするだけであり、分割することは決してないということです。 これにより、この問題は Disjoint Set Union 構造に適したものになります。 DSU を使用すると、コンポーネントのサイズを段階的に追跡できます。 2 つのコンポーネントをマージする場合、すべてを再計算するのではなく、いくつかの集計値を更新するだけで済みます。 

残りの課題は、マージ時にコンポーネント サイズの 2 乗の合計を効率的に表現することです。 サイズ a と b の 2 つの成分が結合すると、二乗和の変化は次のようになります。 

(a + b)² − a² − b² = 2ab

 したがって、結合ごとに一定時間でグローバル合計を維持できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (コンポーネントを毎回再計算) | O(n・m) | O(n + m) | 遅すぎる |
 | 維持されたアグリゲートを含む DSU | O(m α(n)) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは、Disjoint Set Union 構造と 2 つのグローバル値 (接続コンポーネントの数と二乗コンポーネント サイズの合計) を維持します。 

1. 各ノードを独自の親とし、サイズを 1 として DSU を初期化します。この時点では、すべてのノードは個別のコンポーネントであるため、コンポーネント数は n で、平方和も n です。 
2. u と v の間の各エッジ追加について、その DSU 代表を見つけます。 これにより、それらがどのコンポーネントに属しているかがわかります。 
3. 両方のノードがすでに同じコンポーネント内にある場合は、何も行いません。 構造とすべての集合体は変更されません。 
4. それらが異なるコンポーネントに属している場合は、小さいコンポーネントを大きいコンポーネントにマージします。 これにより、DSU の効率が維持され、ほぼ一定時間の動作が保証されます。 
5. 2 つのコンポーネントのサイズを a と b とします。 (a+b)² が a² + b² に置き換わるため、2ab を追加してグローバル二乗和を更新します。 また、コンポーネントの数を 1 減らします。 
6. 操作を処理した後、それがクエリの場合は、sum_of_squares /Components の現在の値を出力します。 

正確さは、すべての必要な情報がコンポーネントのサイズのみに依存し、DSU が結合操作の下でこれらのサイズを正確に維持するという事実に依存します。 各マージは、平方の代数恒等式を使用して一貫して集計を更新します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return 0
        if self.size[a] < self.size[b]:
            a, b = b, a
        self.parent[b] = a
        added = 2 * self.size[a] * self.size[b]
        self.size[a] += self.size[b]
        return added

def solve():
    n, m = map(int, input().split())
    dsu = DSU(n)

    comp = n
    sumsq = n

    out = []

    for _ in range(m):
        parts = input().split()

        if parts[0] == '?':
            if comp == 0:
                out.append("0.000000")
            else:
                out.append(str(sumsq / comp))
        else:
            u = int(parts[0]) - 1
            v = int(parts[1]) - 1

            added = dsu.union(u, v)
            if added:
                comp -= 1
                sumsq += added

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```DSU クラスは、操作を高速に保つためにパスを圧縮しながら接続を処理します。 Union 関数は実際にマージが行われたときにのみ値を返すため、冗長なエッジが現れた場合に誤って更新されるのを防ぎます。 

メイン ループは 2 つの不変条件を保持します。comp は常に DSU ルートの数に等しく、sumsq は常にコンポーネント サイズの 2 乗の合計に等しくなります。 クエリはこれら 2 つの値を読み取るだけです。 

よくある実装上の間違いは、正しいデルタ 2ab を追加する代わりに、a² + b² のみを使用して sumsq を更新することです。 これにより、結合されたコンポーネントからの寄与が二重にカウントされたり、損失されたりする可能性があります。

 ## 特殊なケース

 重要なエッジケースは、結合が繰り返されることです。 同じペアを複数回接続するとします。 DSU は、2 回目以降の試行は構造を変更せずに返されることを保証するため、コンポーネント数も合計も変更されません。 たとえば、n = 3 の場合:

 1 と 2 をマージした後、サイズ 2 と 1 のコンポーネントが得られます。 1 と 2 を再度マージしようとすると、find() は両方に同じルートを返すため、結合はスキップされ、合計は正しいままになります。 

もう 1 つのエッジ ケースは、グラフがエッジをまったく受け取らない場合です。 二乗和は n であり、成分が n 個あるため、すべてのクエリの答えは単純に 1 になります。 アルゴリズムはこの状態に正確に初期化され、結合が発生しない限りそれを変更することはありません。 

最後の微妙なケースは、クエリを使用せず、ユニオンのみを使用する、大きい n です。 すべての更新はローカルでクエリのタイミングとは無関係であり、マージのたびに集計が有効なままであるため、DSU は依然として正しく動作します。
