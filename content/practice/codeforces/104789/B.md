 ## 解決策
 ## 問題の理解

 勤務日と休憩日が交互に繰り返されるスケジュールが与えられています。 1 つの完全なパターンは次のブロックで構成されます。`x`勤務日の後に続く`y`休息日、そしてそれが永遠に繰り返されます。 これは、タイムライン全体が周期的であることを意味します。`x + y`。 

私たちにも数日与えられています`d1, d2, ..., dn`。 これらの日はいずれも作業セグメント内に収まる必要があります。 ただし、サイクルの開始位置を選択することはできます。つまり、日を選択することになります。`D`これは作業ブロックの最初の日を表し、その後そのサイクルが作業として継続されます。`x`数日、その後は休息`y`日々、繰り返す。 

タスクは、そのようなシフトが存在するかどうかを判断することです`D`そうすれば毎日`di`定期スケジュールの作業間隔内に収まります。 そのようなシフトが存在する場合は、それを出力する必要があります。 それ以外の場合は、不可能であると出力されます。 

重要な構造的制約は周期性モジュロです`x + y`。 任意の 2 つの候補アライメントは、このサイクルのシフトによってのみ異なるため、すべての推論は剰余モジュロに還元できます。`x + y`。 

入力サイズは最大まで可能です`n`、つまり、日数の二次関数または線形関数`(x + y)`両方とも大きい場合は実行できなくなります。 これにより、私たちは次のような方向に向かって進みます。`O(n log n)`または`O(n)`純粋にモジュラー演算で機能するソリューション。 

間隔がサイクル境界を「回り込む」場合、微妙な問題が発生します。 循環空間における有効な作業間隔は、単一のセグメントのように見えたり、2 つの部分に分割されたりする可能性があり、モジュラー ラップを明示的に正しく処理しない限り、単純な線形間隔の処理は機能しません。 

よくある失敗例は、それぞれを割り当てようとした場合です。`di`交差制約を考慮せずに独立して計算します。 それぞれ`di`サイクルを開始できる場所を制限しており、これらの制限をグローバルに組み合わせる必要があります。 

## アプローチ

 直接的な総当たりアプローチにより、候補者の開始日を決定します`D`で`[1, x + y]`そして与えられたすべてをチェックします`di`。 固定の場合`D`、計算します`(di - D) mod (x + y)`そしてそれがそこにあることを確認してください`[0, x - 1]`。 すべての日がこの条件を満たす場合、`D`有効です。 

スケジュールは一度完全に決定されるため、これは正しいです。`D`固定されています。 ただし、すべて試してみると、`D`コストを重視する`O((x + y) * n)`、両方のパラメータが大きい場合、速度が非常に遅くなります。 

重要な観察は、それぞれが`di`単一の有効な値を定義していません`D`ではなく、循環空間内で可能な開始位置の範囲を指します。 与えられた`di`、サイクルスタートは次のように配置する必要があります。`di`作業セグメント内に着陸します。 これは、次の制約に変換されます。`D`モジュロ`x + y`, forming an interval on a circle.

 各候補を個別にチェックするのではなく、これらすべての周期的な間隔を交差させます。 答えは、交差点が空でない場合にのみ存在します。 

次に問題は、円上の間隔の交差を維持することに帰着します。これは、端点を並べ替えてスイープするか、循環間隔を線形セグメントに分割することで処理できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | D に対するブルート フォース | O(n(x+y)) | お(1) | 遅すぎる |
 | Interval intersection on circle | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 We convert everything into modulo space`m = x + y`。 

1. 毎日について`di`、有効なサイクル開始のセットを計算します。`D`そのような`di`仕事の合間にあります。 これはつまり`di - D mod m < x`。 並べ替えると制約が与えられます`D`循環形式で。 
2. 各制約は、次の周期的な間隔になります。`[0, m-1]`。 かどうかに応じて`di`境界に近い場合、この間隔は折り返す可能性があります。 
3. ラップアラウンドを処理するには、各周期間隔を最大 2 つの標準間隔に分割します。`[0, m-1]`。 
4. 問題をポイントの発見に変換する`D`それはすべての区間に同時に存在します。つまり、すべての区間制約と交差します。 
5. 世界的な実現可能な範囲を維持します。 完全な円から始めます`[0, m-1]`。 
6. 間隔制約ごとに、現在のセットと交差することで実行可能領域を更新します。 どこかの時点で実行可能領域が空になった場合、解決策は存在しません。 
7. 空でない領域が残っている場合は、その領域内の任意の点を有効な開始日として出力します。`D`。 

### なぜ効果があるのか

 それぞれ`di`作業セグメントに到達させるサイクル シフトのセットを個別に正確に定義します。 有効なグローバル アラインメントはすべての制約を同時に満たす必要があるため、正しい解決策はこれらすべてのセットの正確な交差になります。 すべての制約は固定期間にわたるモジュラー演算から導出されるため、円区間交差を超える追加の構造は必要なく、交差により偽の解が導入されることなく正確さが維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def normalize(l, r, m):
    if l <= r:
        return [(l, r)]
    return [(l, m - 1), (0, r)]

def intersect(a, b):
    res = []
    i = j = 0
    while i < len(a) and j < len(b):
        l = max(a[i][0], b[j][0])
        r = min(a[i][1], b[j][1])
        if l <= r:
            res.append((l, r))
        if a[i][1] < b[j][1]:
            i += 1
        else:
            j += 1
    return res

def solve():
    n, x, y = map(int, input().split())
    m = x + y
    ds = list(map(int, input().split()))

    # initial feasible set is whole circle
    cur = [(0, m - 1)]

    for d in ds:
        # we need D such that d lies in [D, D+x-1] mod m
        # equivalent to D in [d-x+1, d] mod m
        l = (d - x + 1) % m
        r = d % m

        intervals = normalize(l, r, m)
        cur = intersect(cur, intervals)
        if not cur:
            print("NO")
            return

    # pick any valid D
    D = cur[0][0]
    print("YES")
    print(D)

if __name__ == "__main__":
    solve()
```この実装では、実行可能領域を円上の互いに素なセグメントの結合として保持します。 新しい制約はそれぞれ 1 つまたは 2 つの線形セグメントに変換され、2 ポインターのマージを使用して現在のセットと交差します。 

重要な繊細さは、ラップアラウンド処理です。 制約`[l, r]`どこ`l > r`無効として扱うことはできません。 代わりに、2 つの有効なセグメントを表します`[l, m-1]`そして`[0, r]`。 

もう 1 つの微妙な点は、常に素のソート間隔を維持することで、線形時間マージが可能になることです。 この不変条件がないと、交差が繰り返されると二次関数の動作に劣化する可能性があります。 

## 実用的な例

 ### 例 1

 仮定する`x = 3, y = 2`、 それで`m = 5`、 そして`d = [2, 3, 7]`。 

実行可能な間隔を追跡します。 

| ステップ | d | 制約 [l, r] mod 5 | 実現可能なセット |
 | --- | --- | --- | --- |
 | 初期化 | - | - | [0,4] |
 | 1 | 2 | [0,2] | [0,2] |
 | 2 | 3 | [1,3] | [1,2] |
 | 3 | 7 (2 mod 5) | [0,2] | [1,2] |

 最終的な実現可能なセットは、`[1,2]`したがって、有効な答えが存在します。 

このトレースは、それぞれの`di`一貫したサイクル開始のみが残るまで、許容されるアライメント範囲を徐々に縮小します。 

### 例 2

 しましょう`x = 2, y = 3`、 それで`m = 5`、 そして`d = [1, 4]`。 

| ステップ | d | 制約 | 実現可能なセット |
 | --- | --- | --- | --- |
 | 初期化 | - | - | [0,4] |
 | 1 | 1 | [4,1] → [4,4] ∪ [0,1] | [4,4] ∪ [0,1] |
 | 2 | 4 | [2,4] | 交差点は [4,4] になります |

 最終的な答えは、`D = 4`。 

これはラップアラウンド制約を示し、周期間隔の分割が必要な理由を示しています。

 ## 特殊なケース

 一般的なエッジ ケースは、制約がモジュラス境界を囲むときに発生します。 たとえば、`x = 4, y = 3, m = 7`、 そして`d = 1`、有効な開始間隔は次のようになります。`[5, 1]`。 素朴な区間交差はこれを無効として扱いますが、正しい解釈は 2 つの互いに素なセグメントです。 アルゴリズムはこれを明示的に次のように分割します。`[5,6]`そして`[0,1]`、交差点は正しく進みます。 

すべてが揃った場合、別のエッジケースが発生します。`di`モジュロが同一である`m`。 この場合、すべての制約が完全に重なり、実現可能な領域は 1 点に縮小します。 このアルゴリズムは、有効なシングルトン間隔を決してマージしないことでこれを維持します。 

最後のエッジケースは、制約によってすべてのポジションが早期に削除される場合です。 実行可能セットが空になると、アルゴリズムは直ちに停止し、将来の交差では空のセットを復活させることができないため、正確性を保証しながら不必要な計算を回避します。
