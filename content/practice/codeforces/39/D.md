 ## 問題の理解

 単位立方体の 2 つの頂点が与えられます。 各頂点は 3 つの座標で記述され、すべての座標は次のいずれかになります。`0`または`1`。 各座標は 2 つの値しかとれないため、これらの座標は立方体の 8 つの角を表します。 

2 匹のハエが 2 つの異なる頂点に立っています。 両方の頂点が立方体の少なくとも 1 つの共通面に属している場合、それらは相互に認識できます。 タスクは印刷することです`"YES"`そのような顔が存在する場合、そうでない場合は印刷します`"NO"`。 

入力サイズが小さいです。 合計 6 つの整数だけを読み取るため、ここではパフォーマンスは関係ありません。 すべての立方体の面に対する強引な幾何学的チェックも即座に実行されます。 課題は、座標に隠された幾何学的特性を認識することです。 

重要な観察は、立方体の面が座標でどのように表されるかです。 すべての面は 1 つの座標を正確に固定します。 たとえば、顔`x = 0`最初の座標が以下であるすべての頂点が含まれます。`0`。 2 つの頂点が同じ位置で少なくとも 1 つの座標値を共有する場合、それらの頂点は同じ面上にあります。 

見逃しやすいケースがいくつかあります。 

反対側の頂点を考えてみましょう。```
0 0 0
1 1 1
```正しい答えは、`"NO"`。 すべての座標が異なるため、これらの頂点は面を共有しません。 ユークリッド距離またはエッジ接続性のみをチェックする不注意なアプローチは、ここで失敗する可能性があります。 

ここで、面を斜めに横切ってのみ接続されている頂点を考えてみましょう。```
0 0 0
0 1 1
```正しい答えは、`"YES"`。 これらの頂点はエッジによって隣接していませんが、依然として面に属しています。`x = 0`。 間違った解決策では、隣接する頂点のみが相互に認識できると想定する可能性があります。 

もう 1 つの微妙なケースは、1 つの座標だけが一致する場合です。```
1 0 1
1 1 0
```答えはまだです`"YES"`両方の点が面に属しているため`x = 1`。 

## アプローチ

 ブルート フォース ソリューションでは、立方体の 6 つの面を明示的にモデル化します。 各面には 4 つの頂点が含まれます。 すべての立方体の頂点を生成し、それらを面ごとにグループ化し、指定された両方の頂点がいずれかの面に一緒に表示されるかどうかを確認できます。 

可視性の定義はまさに「顔を共有する」ことであるため、このアプローチは正しいです。 立方体には面が 6 つしかないため、文字通りのシミュレーションでも一定の時間がかかります。 

座標を使用して面を記述すると、ジオメトリははるかに単純になります。 すべての立方体面は 1 つの座標を固定します。```
x = 0
x = 1
y = 0
y = 1
z = 0
z = 1
```少なくとも 1 つの座標が同じ位置で一致する場合、2 つの頂点は正確に同じ面上にあります。 最初の座標が等しい場合、両方の頂点はどちらかに属します。`x = 0`または`x = 1`。 同じロジックが次の場合にも当てはまります`y`そして`z`。 

これにより、すべてのジオメトリが実装から削除されます。 座標をペアごとに比較するだけで済みます。

 ## アルゴリズムのチュートリアル

 1. 最初の頂点の座標を読み込みます。`(x1, y1, z1)`。 
2. 2 番目の頂点の座標を読み込みます。`(x2, y2, z2)`。 
3. 対応する座標を比較します。 

もし`x1 == x2`、両方の頂点が同じ上にあります`x`顔。 

もし`y1 == y2`、両方の頂点が同じ上にあります`y`顔。 

もし`z1 == z2`、両方の頂点が同じ上にあります`z`顔。 
4. 少なくとも 1 つの比較が一致する場合、出力します。`"YES"`。 
5. それ以外の場合は印刷します`"NO"`。 

### なぜ効果があるのか

 立方体のすべての面は、1 つの座標を固定することによって定義されます。 たとえば、面上のすべての頂点`z = 1`3 番目の座標が次と等しい`1`。 

2 つの頂点が同じ位置の座標値を共有する場合、それらは両方とも対応する面に属します。 逆に、3 つの座標がすべて異なる場合は、1 つの頂点が立方体の反対側の隅にあり、両方の点を含む面は存在しません。 

アルゴリズムはこの条件を正確にチェックするため、必要かつ十分です。

```プログラムは 2 つのトリプル座標を読み取り、各座標を独立して比較します。 

条件は論理を使用します`or`両方の頂点を共通の面に配置するには、1 つの座標を共有するだけで十分だからです。 

よくある間違いは、2 つの一致する座標が必要なことです。 これでは、エッジで接続された頂点のみが検出され、次のような面の対角線が誤って拒否されます。`(0,0,0)`そして`(0,1,1)`。 

もう 1 つの考えられる間違いは、マンハッタンの距離によって隣接性をチェックすることです。 可視性は隣接性よりも広いため、このアプローチでは有効なケースが見逃されます。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    x1, y1, z1 = map(int, input().split())
    x2, y2, z2 = map(int, input().split())

    if x1 == x2 or y1 == y2 or z1 == z2:
        print("YES")
    else:
        print("NO")

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out

    solve()

    sys.stdout = sys.__stdout__
    return out.getvalue()

# provided sample
assert run("0 0 0\n0 1 0\n") == "YES\n", "sample 1"

# opposite corners
assert run("0 0 0\n1 1 1\n") == "NO\n", "opposite vertices"

# face diagonal
assert run("0 0 0\n0 1 1\n") == "YES\n", "same face but not adjacent"

# exactly one coordinate equal
assert run("1 0 1\n1 1 0\n") == "YES\n", "single matching coordinate"

# another opposite pair
assert run("1 0 0\n0 1 1\n") == "NO\n", "all coordinates different"
```| テスト入力 | 期待される出力 | 検証内容 |

 |`0 0 0 / 1 1 1`|`NO`| 反対側のキューブコーナー | 写真

 ## 特殊なケース

 反対側の頂点を考えてみましょう。```
0 0 0
1 1 1
```アルゴリズムは座標を 1 つずつ比較します。```
0 == 1 → false
0 == 1 → false
0 == 1 → false
```一致する座標がないため、プログラムは出力します。`"NO"`。 これにより、向かい合う角が面を共有しないことが正しく識別されます。 

次に、面の対角線について考えてみましょう。```
0 0 0
0 1 1
```最初の座標は次のように一致します。```
0 == 0 → true
```アルゴリズムは、両方の頂点が面に属していることをすぐに認識します。`x = 0`、それで印刷されます`"YES"`。 

最後に、共有座標が 1 つだけある場合を考えてみましょう。```
1 0 1
1 1 0
```比較結果は次のとおりです。```
1 == 1 → true
0 == 1 → false
1 == 0 → false
```少なくとも 1 つの座標が一致すれば、視認性を確保するには十分です。 出力は`"YES"`。 

これらのケースは、「少なくとも 1 つの等しい座標」という条件が立方体の面の形状と正確に一致する理由を示しています。
