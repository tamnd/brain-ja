 ## 解決策
 ## 問題の理解

 から始めます`a`個性的なボックスと`b`特徴的なアイテム。 ボックスは空のままであり、すべてのアイテムが独立してボックスの 1 つを選択するため、可能な配置の数は単純に次のようになります。$a^b$2 人のプレイヤーが交互にターンします。 各ターンで、プレイヤーはボックスの数を 1 つ増やすか、アイテムの数を 1 つ増やすことができます。 移動後、配置数が少なくとも`n`、そのプレイヤーはすぐに負けます。 

という状態からゲームがスタートします。`a^b < n`、スタスが先に動きます。 最初のプレーヤーが勝つか、2 番目のプレーヤーが勝つか、あるいは最適なプレイが無限ゲームにつながるかどうかを判断する必要があります。これをステートメントで呼び出します。`"Missing"`。 

制約によってソリューションが完全に形作られます。 項目数が超えることはありません`30`最初は増加しますが、ゲーム中にさらに増加する可能性があります。 ボックスの数は最大でも開始できます`10000`。 しきい値`n`せいぜい`10^9`、これは十分に小さいため、勢力が急速にそれを超えて成長します。 この観察は非常に重要です。なぜなら、たとえゲーム グラフが実際には小さいことを意味するからです。`a`それ自体は大きいかもしれません。 

メモ化を行わない単純な再帰的ゲーム検索では、同じ状態を繰り返し再訪することになります。 さらに悪いことに、ゲーム グラフにはサイクルが含まれています。 たとえば、から`(1,1)`に行くことができます`(2,1)`または`(1,2)`、そして両方とも以下に留まりながら永遠に続けることができます`n`しばらくの間。 ゲームが有向非巡回グラフであることを前提としたソリューションは、何も言わずに失敗します。 

微妙な特殊なケースの 1 つは、ドローの存在です。 考慮する：```
1 1 1000000000
```ここでの値は`1^1 = 1`。 ボックスの数を増やしても、値は維持されます。`1`, そのため、両方のプレイヤーが永遠にボックスを追加し続ける可能性があります。 状態を勝ちか負けかだけで分類するソリューションでは、たとえ完璧なプレイが無限のゲームを生み出すとしても、誤って答えを強制することになります。 

もう 1 つの危険なケースは、電力計算中のオーバーフローです。 次のことを確認するとします。```
10000 30 1000000000
```実際の値`10000^30`天文学的に大きいです。 早期に停止せずに通常のべき乗を使用すると、多くの言語で固定幅の整数がオーバーフローしたり、巨大な Python 整数を構築するのに時間が無駄になったりする可能性があります。 値が到達するかどうかだけを気にします`n`したがって、しきい値を超えたらすぐに計算を停止する必要があります。 

3 番目の微妙なケースは、一方の手がすぐに負けて、もう一方の手がゲームを継続する局面から発生します。 例えば：```
2 2 10
```現在の値は`4`。 ボックスを増やすと得られるもの`3^2 = 9`、まだ安全です。 アイテムを増やすと得られるもの`2^3 = 8`、また安全です。 しかし、慎重にプレーした後、先手のプレイヤーが後者のプレイヤーに負けの手を強いることができます。 次のステップのみに基づいた貪欲な推論では十分ではありません。 

## アプローチ

 最も直接的なアプローチは、すべてのペアを処理することです`(a,b)`ゲームの状態をゲームの状態として認識し、勝敗を再帰的に判断します。 各状態から最大 2 つの移動があります。```
(a+1, b)
(a, b+1)
```少なくとも価値を生み出すあらゆる動き`n`成功するとすぐに負けてしまうため、練習では禁止されています。 

公平な組み合わせゲームは自然に状態遷移に帰着するため、この再帰的定義は正しいです。 負けている状態への移行が存在する場合、その状態は勝利しています。 すべての有効な動きが勝利状態につながる場合、その状態は負けています。 

問題は、このゲーム グラフが非周期的ではないことです。 国家は、有効性を維持しながら、ある方向に永遠に成長し続けることができます。 最も単純な例は、次の状態です。`b = 1`、 なぜなら：$a^1=a$に限って`a < n`、プレイヤーは永遠にボックスを増やし続ける可能性があります。 最終的に終了することを前提とした DFS は、真に勝ちのポジションと無限のプレイを許可するポジションを区別できません。 

重要な観察は、状態を満足させるだけの場合、ゲーム グラフは依然として有限であるということです。$a^b<n$値に達すると`n`、ゲームはすぐに終了します。 以来`n ≤ 10^9`、指数は非常に急速に増加します。 のために`b ≥ 30`、小さな拠点でもすでに限界を超えています。 到達可能な安全な状態の総数は実際には非常に少なく、多くてもおよそ数十万です。 

これにより、ドローを含む有限有向グラフとしてゲームをモデル化できます。 次に、標準のゲーム状態の伝播を使用できます。 

ある州が負けている州に移行した場合、その州は勝利しています。 

すべての手が勝ちの状態に進むと、それは負けになります。 

勝ち負けが証明されていない州は、プレイヤーが永久に敗北を避けることができるサイクルに属しているため、引き分けとなります。 

これは有向グラフ上の逆行解析問題となる。 BFS を使用して、すべての有効な状態を構築し、すべてのエッジを反転し、結果を逆方向に伝播します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース DFS | 指数 | 指数 | 遅すぎる |
 | 逆行ゲーム分析 | O(S) | O(S) | 承認済み |

 ここ`S`は有効な状態の数です`a^b < n`。 

## アルゴリズムのチュートリアル

 1. 有効な状態をすべて列挙する`(a,b)`そのような`a^b < n`。 

ゲームがまだ終了していない状態のみを考慮します。 あらゆる動きを生み出す`a^b ≥ n`すぐに負けます。 
2. 各州について、その法的な措置を生成します。 

から`(a,b)`私たちは試します`(a+1,b)`そして`(a,b+1)`。 移動は、目的地がまだ満足している場合にのみ合法です`a^b < n`。 
3. すべての状態の出次数を計算します。 

出次数は、利用可能な安全な手の数です。 この値は逆方向伝播に必要です。 
4. 逆エッジを構築します。 

状態の場合`u`州に移動できる`v`、 それから`v`店`u`逆隣接リストにあります。 これにより、ステータスが変化したら、情報を逆方向に伝播することができます。`v`知られるようになる。 
5. 負けている状態を初期化します。 

合法的な手がゼロの州は、あらゆる可能な手が即座に到達または超過するため、負けます。`n`。 
6. BFS 伝播を実行します。 

負けている状態が発見されると、すべての先行者はその負けた状態に移行できるため、勝ちになります。 

勝利状態が発見されると、その前の状態の残りの未調査の手を減分します。 先行者のすべての手が勝利状態につながる場合、その先行者は負けになります。 
7. BFS 後の未分類の状態は引き分けです。 

これらの状態は、どちらのプレイヤーもゲームを強制終了できないサイクルに属します。 
8. 初期状態の結果を出力します。 

初期状態が勝っている場合、Stas は Masha を強制的に負けさせることができるため、次のように出力します。`"Masha"`。 

初期状態が負けの場合、最適なプレイでは Stas は負けるので、次のように出力します。`"Stas"`。 

それ以外の場合は印刷します`"Missing"`。 

### なぜ効果があるのか

 伝播により、標準的な公平なゲームの不変条件が維持されます。 

負けている状態への移行が存在するとき、その状態はまさに勝利しています。 負けている状態を特定すると、すべての前任者がすぐに勝ちになります。 

あらゆる合法的な動きが勝利した州に移ったとき、その州はまさに負けていることになる。 出次数カウンターは、未解決の手がどれだけ残っているかを追跡します。 すべての発信手が勝ちであることがわかっている場合、その状態は負けているはずです。 

これら 2 つのルールによって分類されない状態は、末期状態を永久に回避できるサイクルに属している必要があります。 どちらのプレイヤーもそのような地域から勝利を強要することはできないため、正しい結果は引き分けです。 

## Python ソリューション```python
import sys
from collections import deque, defaultdict

input = sys.stdin.readline

def safe_pow(a, b, limit):
    res = 1
    for _ in range(b):
        res *= a
        if res >= limit:
            return limit
    return res

def solve():
    a0, b0, n = map(int, input().split())

    states = []
    idx = {}

    max_b = 1

    # Enumerate all valid states
    a = 1
    while safe_pow(a, 1, n) < n:
        b = 1
        while safe_pow(a, b, n) < n:
            idx[(a, b)] = len(states)
            states.append((a, b))
            max_b = max(max_b, b)
            b += 1
        a += 1

    m = len(states)

    rev = [[] for _ in range(m)]
    outdeg = [0] * m

    # Build graph
    for i, (a, b) in enumerate(states):
        for na, nb in ((a + 1, b), (a, b + 1)):
            if (na, nb) in idx:
                j = idx[(na, nb)]
                outdeg[i] += 1
                rev[j].append(i)

    # 0 = draw/unvisited
    # 1 = winning
    # 2 = losing
    state = [0] * m

    q = deque()

    # Terminal losing states
    for i in range(m):
        if outdeg[i] == 0:
            state[i] = 2
            q.append(i)

    rem = outdeg[:]

    # Retrograde analysis
    while q:
        v = q.popleft()

        for u in rev[v]:
            if state[u] != 0:
                continue

            if state[v] == 2:
                state[u] = 1
                q.append(u)
            else:
                rem[u] -= 1
                if rem[u] == 0:
                    state[u] = 2
                    q.append(u)

    start = idx[(a0, b0)]

    if state[start] == 1:
        print("Masha")
    elif state[start] == 2:
        print("Stas")
    else:
        print("Missing")

solve()
```最初の重要な部分は、`safe_pow`。 正確な値に達すると、その値は必要ありません`n`, そのため、乗算は早期に停止します。 これにより、巨大な整数の構築が回避され、列挙が高速に保たれます。 

状態の生成は、安全な位置のみが重要であるという事実に基づいています。 最終的に電力が超過するため、入れ子になったループは自然に停止します。`n`。 それでも`a`大きくなる可能性があっても、有効な状態の総数は管理可能なままです。 

グラフ構築フェーズでは、次の両方の情報を作成します。`outdeg`そして情報を逆転させます`rev`。 逆エッジは逆方向伝播を効率的にするものです。 

BFS 自体は、標準的な勝敗ゲーム ロジックを実装しています。 負けているノードを処理すると、すべての先行ノードが敗北するための動きを持っているため、即座に勝ちになります。 勝者ノードを処理するとき、先行ノードは残りの安全なオプションを 1 つ失うだけです。 すべてのオプションが勝ちになった後でのみ、先行オプションを負けとして分類します。 

州は次のように残しました`0`BFS 以降はまさに描画状態になります。 プレイヤーは無期限にサイクリングを続けることができるため、どちらのカテゴリーにも強制されることはありません。 

実装の微妙な詳細の 1 つは、出力規則です。 この問題は勝者ではなく敗者を求めます。 初期状態が現在のプレイヤーの勝利である場合、Stas が勝ち、Masha が負けるので、次のように出力します。`"Masha"`。
