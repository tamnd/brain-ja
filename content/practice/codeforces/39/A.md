 ## 解決策
 ## 問題の理解

 単一の変数に関係する項から構築された算術式が与えられます。`a`。 すべての用語は次の 2 つの形式のいずれかになります。```
k * a++
k * ++a
```どこ`k`間の整数係数です`0`そして`1000`。 係数が欠落している場合は、次のように扱われます。`1`。 

式全体は、これらの項の和と減算です。 珍しいのは評価順序です。 この言語では、用語を組み合わせる前に任意の順序で評価できます。`+`そして`-`。 

各項は次の値を変更します。`a`。 

のために`a++`、の現在値`a`が最初に使用され、次に`a`増加します`1`。 

のために`++a`、`a`最初に増加した後、新しい値が使用されます。 

タスクは、式全体の最終値を最大化する評価順序を選択することです。 

加数の数は最大で`1000`したがって、二次関数よりもはるかに遅いアルゴリズムは不要です。 すべての順列を試すのは不可能です。`1000!`天文学的に大きいです。 それだけでも`15`つまり、ブルートフォースはすでに実行不可能になっています。 

式自体は十分に小さいため、リニア スキャンを使用して直接解析するのは簡単です。 すべての加数を抽出するだけで済みます。```
sign: +1 or -1
coefficient: k
type: post-increment or pre-increment
```いくつかの特殊なケースは、誤って処理されやすいものです。 

考慮する：```
0
a++-++a
```評価すると`a++`初め：```
0 - 2 = -2
```評価すると`++a`初め：```
1 - 1 = 0
```最大値は`0`。 順序を考慮せずに合計増分のみをカウントする素朴なアプローチでは、この区別が失われます。 

もう 1 つの微妙なケースは係数です。`0`。 

入力：```
5
0*a++-0*++a
```両方の用語が貢献します`0`数値的には変わりますが、それでも変更されます`a`。 読むと一期が増える`a`、読む前に秒が増えます。 係数がゼロであっても、順序は依然として重要です。 

3 番目の罠は、減算によって優先順位が反転することを忘れていることです。 

入力：```
1
10*a++-1*++a
```結果を最大化するには、大きな正の係数に大きな値が見られる必要があります。`a`一方、負の項には小さな値が表示されるはずです。 負の項を最初に評価する方が良いでしょう。 

符号を考慮せずに係数の大きさだけで並べ替える不注意な貪欲な場合、間違った結果が得られます。 

## アプローチ

 強引なアイデアは直接的です。 すべての加数を解析し、考えられるすべての評価順序を生成し、式をシミュレートして、最大の結果を維持します。 

各順列について、現在の値を維持します。`a`。 用語を評価する場合:

 のために`k * a++`、追加します`k * a`結果に応じて増加します`a`。 

のために`k * ++a`、増分します`a`まず、次に追加します`k * a`。 

すべての項が評価された後、それらを元の項と結合します。`+`そして`-`兆候。 

これが機能するのは、言語セマンティクスが逐次評価によって正確に記述されるためです。 問題は順列の数です。 と`n`命令、必要です`n!`命令。 平`12!`すでに約`4.8 * 10^8`、限界をはるかに超えています。 

重要な観察は、各項が増加することです。`a`まさに一度。 唯一の問題は、どの項がより小さい値を受け取るべきかということです。`a`、そしてどれがより大きなものを受け取るべきか。 

それぞれの用語を注意深く書き直してみましょう。 

現在のと仮定します`a = x`。 

ポジティブな言葉の場合:```
+k * a++  =>  +k * x
+k * ++a  =>  +k * (x + 1)
```否定的な用語の場合:```
-k * a++  =>  -k * x
-k * ++a  =>  -k * (x + 1)
```すべての項は現在の値に線形に依存します。`a`。 

項の有効係数が大きい場合、`x`、後で評価したいとき`a`大きくなります。 係数が小さいほど、早くする必要があります。 

これは古典的なペアごとのスワップ引数になります。 

有効係数を持つ 2 つの項を取る`c1`そして`c2`。 

項 2 の前に項 1 を評価すると、次のようになります。```
c1 * x + c2 * (x + 1)
```それらを交換すると:```
c2 * x + c1 * (x + 1)
```2 番目の順序は、まさに次の場合に適しています。```
c1 > c2
```したがって、項は有効係数の減少しない順序で処理する必要があります。 

ここで必要なのは、各加数に対する有効係数を決定することだけです。 

のために：```
+k * something
```実効係数は`+k`。 

のために：```
-k * something
```実効係数は`-k`。 

の`++a`対`a++`区別は一定のオフセットのみに寄与します。 具体的には、`++a`読み取り前にインクリメントされるため、符号付き係数のコピーが 1 つ追加されます。 

ソート後、その順に評価をシミュレーションします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n! · n) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

### なぜ効果があるのか

 学期ごとに増えていきます`a`ちょうど 1 回なので、評価した後`t`項、の現在値`a`順序に関係なく固定されます。 

唯一の自由は、どの用語がどの段階を受けるかを決定することです`a`。 

有効係数を持つ 2 つの隣接する項を考慮します`c1`そして`c2`。 

現在の場合`a = x`、次のように評価します。`(1,2)`与える:```
c1*x + c2*(x+1)
```それらを交換すると次のようになります。```
c2*x + c1*(x+1)
```2 番目の式は、正確に次の場合に大きくなります。`c1 > c2`。 

したがって、より大きな係数が先に現れる反転は、スワップによって改善できます。 この引数を繰り返すと、最適な順序が並べ替えられた順序に変換されます。 

これは、貪欲な順序が全体的に最適であることを証明しています。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    a = int(input())
    s = input().strip()

    terms = []

    i = 0
    sign = 1

    while i < len(s):
        if s[i] == '+':
            sign = 1
            i += 1
        elif s[i] == '-':
            sign = -1
            i += 1

        coeff = 0
        has_coeff = False

        while i < len(s) and s[i].isdigit():
            coeff = coeff * 10 + int(s[i])
            has_coeff = True
            i += 1

        if has_coeff:
            i += 1  # skip '*'
        else:
            coeff = 1

        if s[i:i + 3] == "++a":
            typ = 1
            i += 3
        else:
            typ = 0
            i += 3

        effective = sign * coeff
        terms.append((effective, sign, coeff, typ))

    terms.sort(key=lambda x: x[0])

    ans = 0
    cur = a

    for _, sign, coeff, typ in terms:
        if typ == 1:
            cur += 1
            ans += sign * coeff * cur
        else:
            ans += sign * coeff * cur
            cur += 1

    print(ans)

solve()
```パーサーは式を左から右にスキャンします。 各反復ではちょうど 1 つの加数が抽出されます。 

係数は省略される可能性があるため、係数の解析には特別な注意が必要です。 数字が見つからない場合、係数は次のようになります。`1`。 

間の区別`++a`そして`a++`で表されます`typ`。```
typ = 1  -> ++a
typ = 0  -> a++
```ソートキーは有効な係数のみです。```
sign * coeff
```これは、用語が以前の値を優先するか、後の値を優先するかを制御する量です。`a`。 

シミュレーション中は、増加順序が重要です。 のために`++a`、増分は貢献の前に発生します。 のために`a++`、寄与は増分の前に発生します。 これら 2 つのケースが混在することは、最も一般的な実装バグです。 

Python の整数はすべての可能な値を自動的に安全に処理するため、オーバーフローは心配ありません。
