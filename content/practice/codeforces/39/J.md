 ## 解決策
 ## 問題の理解

 2 つの小文字の文字列が与えられます。 最初の文字列は 2 番目の文字列よりちょうど 1 文字だけ長くなります。 最初の文字列内のすべての位置を検索して、その位置の文字を削除すると 2 つの文字列が同一になるようにしたいと考えています。 

任務は恣意的な編集を実行することではありません。 削除は 1 つだけ許可され、長い文字列内で削除する必要があります。 答えは、この削除が機能するすべての有効な 1 から始まる位置で構成されます。 

制約は、問題の性質を完全に変える部分です。 各文字列には最大で次の文字列を含めることができます。$10^6$文字。 ここでは二次解は不可能です。 たとえ$O(n^2)$小さな定数を使用するアルゴリズムでは、約$10^{12}$制限時間を大幅に超えた最悪の場合の作戦。 線形または線形に近いアプローチが必要です。 

この規模では文字列のコピーや再構築を繰り返し行うと非常にコストがかかるため、すべての削除位置を直接シミュレーションすることは危険です。 作成することさえ$n$一定の長さの一時文字列$n$大量のメモリと時間を使用することになります。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

すべての削除が機能する場合を考えてみましょう。 

入力:```
aaaa
aaa
```出力：```
4
1 2 3 4
```文字を削除すると、`"aaa"`。 不注意な不一致ベースのソリューションは、最初の有効な位置を見つけた後に停止し、他の位置を見逃してしまう可能性があります。 

もう 1 つの注意が必要なケースは、終わり近くで不一致が発生した場合に発生します。 

入力:```
abcd
abc
```出力：```
1
4
```最初の 3 文字はすでに一致しています。 有効な削除は最後の文字だけです。 最初の不一致のみを検索するアルゴリズムでは、削除は必要ないと誤って結論付ける可能性があります。 

文字が繰り返されるとあいまいさも生じます。 

入力:```
abcc
abc
```出力：```
1
4
```最後のものを削除する`'c'`動作しますが、最初のものを削除します`'c'`しません。 両方の文字列に含まれる文字数がほぼ同じであるため、単純な頻度ベースの方法は失敗します。 

最後に、有効な答えがない場合もあります。 

入力:```
abcd
axy
```出力：```
0
```から一文字削除しても`"abcd"`、文字列が等しくなることはありません。 

## アプローチ

 ブルートフォースのアイデアは単純です。 長い文字列からすべての文字を削除して、結果を短い文字列と比較してみてください。 

ある長さの文字列の場合$n$、 がある$n$候補の削除。 結果として得られる各文字列のコストを構築して比較する$O(n)$したがって、全体の複雑さは次のようになります。$O(n^2)$。 

と$n = 10^6$、このアプローチには次のようなものが必要になります$10^{12}$キャラクター操作。 それはまったく不可能です。 

重要な点は、1 文字を削除した後、文字列の残りの部分が完全に整列する必要があるということです。 

ポジションを削除するとします$i$長い文字列から$s$。 次に:

 - 前の接頭辞$i$はすでに一致している必要があります。 
- 後の接尾辞$i$で$s$の対応するサフィックスと一致する必要があります$t$、1 位置ずらされます。 

これは当然、前処理と接尾辞の一致を示唆しています。 

定義する：

-`pref[i]`かどうかのように`s[0:i] == t[0:i]`-`suff[i]`かどうかのように`s[i:] == t[i-1:]`サフィックス定義は、削除によって生じる 1 文字のシフトを考慮しています。 

今はポジション$i$次の場合に有効です。 

- 以前のすべて$i$マッチ
 - その後のすべて$i$シフト後の試合

 したがって、線形前処理後の位置ごとの定数チェックのみが必要です。 

これにより、複雑さが 2 次から線形に軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^2)$|$O(n)$| 遅すぎる |
 | 最適 |$O(n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 2 つの文字列を読み取ります`s`そして`t`。 
2. しましょう`n = len(s)`。 以来`s`1 文字長くなることが保証されています。`len(t) = n - 1`。 
3. プレフィックス一致配列を構築する`pref`。`pref[i]`最初のことを意味します`i`両方の文字列の文字は同一です。 

初期化:```
pref[0] = True
```それから、それぞれについて`i`から`0`に`n-2`:```
pref[i + 1] = pref[i] and (s[i] == t[i])
```これはプレフィックスが一致するため機能します。`i+1`前の接頭辞が一致し、現在の文字が等しい場合のみ。 
4. サフィックス一致配列を構築する`suff`。`suff[i]`手段：```
s[i:] == t[i-1:]
```から 1 文字がずれているため、インデックスがシフトされます。`s`削除されたものとみなされます。 

初期化:```
suff[n] = True
```次に、逆方向に繰り返します。```
suff[i] = suff[i + 1] and (s[i] == t[i - 1])
```5. 削除位置をすべて確認する`i`。 

削除中`s[i]`次の場合に機能します:```
pref[i] and suff[i + 1]
```

`pref[i]`左側の部分が一致することを保証します。`suff[i + 1]`スキップ後に正しい部分が一致することを保証します`s[i]`。 
6. 1 から始まるインデックスを使用して、すべての有効な位置を出力します。 

### なぜ効果があるのか

 任意の削除位置に対して$i$、結果の文字列は 2 つの変更されていない部分で構成されます。 

- 前の接頭辞$i$- 後の接尾辞$i$プレフィックス条件は次のことをチェックします。```
s[0:i] == t[0:i]
```サフィックス条件は次のことをチェックします。```
s[i+1:] == t[i:]
```両方が true の場合、結果の文字列内のすべての文字がターゲット文字列と一致します。 

いずれかの条件が満たされない場合、一部の文字が異なるため、削除は機能しません。 

すべての候補位置はこれらの必要十分条件に対して正確にテストされるため、アルゴリズムは正しいです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

s = input().strip()
t = input().strip()

n = len(s)

pref = [False] * (n + 1)
pref[0] = True

for i in range(n - 1):
    pref[i + 1] = pref[i] and (s[i] == t[i])

suff = [False] * (n + 1)
suff[n] = True

for i in range(n - 1, 0, -1):
    suff[i] = suff[i + 1] and (s[i] == t[i - 1])

ans = []

for i in range(n):
    if pref[i] and suff[i + 1]:
        ans.append(i + 1)

print(len(ans))

if ans:
    print(*ans)
```プレフィックス配列には、プレフィックスが特定の長さまで正確に一致するかどうかが格納されます。 累積ブール伝播を使用すると、比較を繰り返し再計算する必要がなくなります。 

サフィックス配列は、インデックスがシフトされるため、わずかに微妙になります。 削除後`s[i]`、 キャラクター`s[i+1]`と一致する必要があります`t[i]`。 そのため、接尾辞の比較では次のように使用されます。`t[i-1]`前処理中。 

逆方向ループは次から始まります`n - 1`そして止まります`1`なぜなら`t[i - 1]`有効なままにしておく必要があります。 位置`0`最初の文字の削除は以下にのみ依存するため、サフィックス値は必要ありません。`suff[1]`。 

最後のループでは、削除の可能性がすべて一定時間内に個別にチェックされます。 

この実装では、一時文字列の構築が完全に回避されます。 スライスを繰り返すと実行時間とメモリ使用量の両方が大幅に増加するため、これは大規模な入力の場合に重要です。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    s = input().strip()
    t = input().strip()

    n = len(s)

    pref = [False] * (n + 1)
    pref[0] = True

    for i in range(n - 1):
        pref[i + 1] = pref[i] and (s[i] == t[i])

    suff = [False] * (n + 1)
    suff[n] = True

    for i in range(n - 1, 0, -1):
        suff[i] = suff[i + 1] and (s[i] == t[i - 1])

    ans = []

    for i in range(n):
        if pref[i] and suff[i + 1]:
            ans.append(i + 1)

    out = [str(len(ans))]

    if ans:
        out.append(" ".join(map(str, ans)))

    print("\n".join(out))

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    result = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return result

# provided sample
assert run(
    "abdrakadabra\nabrakadabra\n"
) == "1\n3\n", "sample 1"

# minimum size
assert run(
    "ab\na\n"
) == "1\n2\n", "minimum size"

# all deletions valid
assert run(
    "aaaa\naaa\n"
) == "4\n1 2 3 4\n", "all positions valid"

# deletion at beginning
assert run(
    "xabc\nabc\n"
) == "1\n1\n", "delete first character"

# deletion at end
assert run(
    "abcd\nabc\n"
) == "1\n4\n", "delete last character"

# no valid deletion
assert run(
    "abcd\naxy\n"
) == "0\n", "impossible case"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`ab / a`|`2`| 最小の意味のある入力 |
 |`aaaa / aaa`|`1 2 3 4`| 複数の有効な回答 |
 |`xabc / abc`|`1`| 最初の位置の正しい処理 |
 |`abcd / abc`|`4`| 最後の位置の正しい処理 |
 |`abcd / axy`|`0`| 不可能な変換 |
