 ## 解決策
 ## 問題の理解

 ノードが交差点を表し、エッジが一方通行の路面電車を表す有向グラフが与えられます。 エンジン ハウスはノード 1 にあります。すべてのノードには少なくとも 1 つの発信エッジがあるため、路面電車が閉じ込められることはありません。 運転手は路面電車の路線に沿って任意の経路を選択できますが、機関室はいくつかの交差点にカメラを設置して、定期的に確認することを望んでいます。`t`、路面電車は常にカメラに捉えられています。 

正式には、最大のものが必要です`t`カメラを備えたノードのサブセットが存在し、路面電車は常にカメラを通過します。`t`ノード 1 から開始して数分。すべての最大値の中で`t`、カメラの数が最も少ないプランを選択します。 

入力制約では、最大 10^5 のノードとエッジが許可されます。 これにより、O(n + m) または O((n + m) log n) よりも悪いものは除外されます。O(n^2) は 10^10 の演算となり、遅すぎるためです。 したがって、ソリューションでは、すべてのパスまたは間隔ごとに総当たり攻撃を行うのではなく、グラフ構造を利用する必要があります。 

グラフに異なる長さのサイクルが含まれている場合、微妙なエッジ ケースが発生します。 たとえば、1 → 2 → 3 → 1 および 1 → 4 → 1 のようなグラフを考えてみましょう。サイクルの長さは 3 と 2 です。任意のカメラ間隔`t`ノード 1 から到達可能なすべてのサイクル長を分割する必要があります。不注意なアプローチでは、単一のサイクルのみをチェックして選択する可能性があります。`t`それに基づいて、間違った最大値が生成されます。 

別のエッジ ケースは、複数の平行エッジまたは自己ループです。 これらはサイクルの長さには影響しませんが、ノードごとに必要なカメラは 1 つだけであるため、カメラの数を慎重に数える必要があります。 

## アプローチ

 ブルートフォース手法では、可能なすべての間隔が試行されます。`t`1 からすべてのエッジの重みの合計まで (ここでは、すべてのエッジに暗黙的に 1 分かかります)。 それぞれについて`t`、考えられるすべての経路をシミュレートし、毎回トラムが常にカメラに表示されるかどうかを確認します。`t`分。 これは理論的には正しいですが、明らかに実行不可能です。すべてのパスをシミュレートするとノード数が指数関数的に増加します。 

重要な洞察はグラフ理論から得られます。 路面電車はグラフ内のサイクルを繰り返し移動します。 最大`t`路面電車が常にカメラ上にあることを保証する値は、ノード 1 から始まるグラフ内のすべてのサイクル長の最大公約数 (GCD) です。各ノードには、任意のパスに沿った「距離モジュロ t」があります。 同じ剰余モジュロを共有するノード`t`カメラを共有できます。 したがって、問題は、サイクルを見つけ、その長さを計算し、GCD を取得し、距離モジュロに従ってカメラを割り当てることに帰着します。`t`。 

これを効率的に実装するために、DFS を実行し、各ノードの深さを追跡し、バック エッジ (親を経由せずに既に訪問したノードを訪問する) に遭遇するたびに、深さの差に 1 を加えたものとしてサイクル長を計算します。次に、すべてのサイクル長の GCD を計算します。 カメラの配置では、各ノードはその深度モジュロ GCD によってラベル付けされます。 カバレッジには、モジュロ クラスごとに 1 つのノードで十分です。 ノード 1 には常にカメラが必要であり、当然何らかのクラスに属します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (すべてのパスをシミュレート) | お(ん!) | O(n) | 遅すぎる |

 ## アルゴリズムのチュートリアル

 1. 入力エッジからグラフの隣接リストを作成します。 これにより、各ノードからの発信エッジの効率的なトラバースが可能になります。 
2. ノード 1 から開始して DFS を初期化します。各ノードの DFS を追跡します。`depth`そして`visited`状態: 0 = 未訪問、1 = スタック内、2 = 処理済み。 
3. 各エッジについて`u → v`DFS 内:

 - もし`v`未訪問の場合は、DFS を再帰的に続行します。 
- もし`v`がスタック内にある場合 (状態 1)、バックエッジが検出されます。 サイクル長を次のように計算します。`depth[u] - depth[v] + 1`それをサイクル長のリストに追加します。 
4. DFS 後、すべてのサイクル長の GCD を計算します。 この GCD は最大間隔です`t`これにより、路面電車が何倍もの時間でカメラに映ることが保証されます。`t`。 
5. カメラを配置するには、各ノードにラベルを割り当てます。`depth[node] % t`。 それぞれの個別の残りについて、カメラの位置としてその残りを含む最初のノードを選択します。 ノード 1 にはカメラが必要なので、ノード 1 が選択されていることを確認します。 
6. 出力`t`、カメラの数、カメラが配置されているノードのソートされたリスト。 

**機能する理由:**

 DFS はノード 1 から到達可能なすべてのサイクルを検出するため、路面電車が通過できるサイクルのみを考慮します。 GCD は最大の均一間隔を保証します`t`すべてのサイクル長を分割します。 ノードをモジュロでラベル付けすることにより`t`、ノード 1 から始まるどのパスでも、ノードでの時間はその深度モジュロに一致するため、考えられるすべての時間ステップをカバーします。`t`。 モジュロ クラスごとに 1 つのノードを選択すると、完全なカバレッジが保証されます。 

## Python ソリューション```python
import sys
import math
from collections import defaultdict, deque

input = sys.stdin.readline
sys.setrecursionlimit(200000)

def main():
    n, m = map(int, input().split())
    adj = [[] for _ in range(n + 1)]
    for _ in range(m):
        u, v = map(int, input().split())
        adj[u].append(v)

    visited = [0] * (n + 1)
    depth = [0] * (n + 1)
    cycle_lengths = []

    def dfs(u):
        visited[u] = 1
        for v in adj[u]:
            if visited[v] == 0:
                depth[v] = depth[u] + 1
                dfs(v)
            elif visited[v] == 1:
                # back edge found
                cycle_lengths.append(depth[u] - depth[v] + 1)
        visited[u] = 2

    dfs(1)

    t = 0
    for length in cycle_lengths:
        t = math.gcd(t, length)
    
    camera_mod = {}
    cameras = []
    def place_cameras(u):
        stack = [(u, 0)]
        while stack:
            node, d = stack.pop()
            if node in camera_mod:
                continue
            mod_class = d % t
            if mod_class not in camera_mod:
                camera_mod[mod_class] = node
                cameras.append(node)
            for v in adj[node]:
                stack.append((v, d + 1))
    
    place_cameras(1)
    cameras.sort()
    print(t)
    print(len(cameras))
    print(" ".join(map(str, cameras)))

if __name__ == "__main__":
    main()
```DFS はサイクルを見つけてその長さを計算します。 の`place_cameras`関数は DFS のようなトラバーサルを使用して各深度モジュロを割り当てます`t`カメラに。 ソートにより、出力が要件と一致していることが確認されます。
