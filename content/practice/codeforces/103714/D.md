 ## 解決策
 ## 問題の理解

 左から右にインデックスが付けられた牛の列が与えられます。 牛にはそれぞれ体重があります。 その後、独立した「襲撃」が数多く与えられます。 Raid は、開始位置とステップ サイズという 2 つの数値によって定義されます。 与えられたインデックスから開始して、一定のステップで前方にジャンプして牛を取得することを繰り返し、インデックス a、a + b、a + 2b を収集し、最後の牛を超えた時点で停止します。 

クエリごとに、その等差数列がアクセスするすべての牛の合計体重を計算する必要があります。 

重要な点は、各クエリが独立しているということです。 牛は削除せず、クエリ間で何も変更しないため、静的配列の等差数列で値を繰り返し合計しています。 

制約は大きく、最大 3×10^5 の牛と 3×10^5 のクエリです。 クエリごとの直接シミュレーションでは、最悪の場合、最大 O(n) ステップが必要となり、O(n・p) ≈ 10^10 の操作が必要になります。 それは実現可能な限界をはるかに超えています。 

重要な問題は、ステップ サイズ b がクエリごとに異なる可能性があり、単一のプレフィックス合計トリックではすべてのクエリを均一に処理できないことです。 

いくつかの特殊なケースが重要です。 b = 1 の場合、クエリは a から n までの単なる範囲接尾語の合計です。 a が終わりに近い場合、進行には要素が 1 つだけ含まれる可能性があります。 b が大きい場合、各クエリは非常に少数の要素に触れますが、最悪の場合の b = 1 により線形になるため、それに依存することはできません。 

## アプローチ

 ブルートフォースのアイデアは簡単です。各クエリについて、インデックス a から開始し、n を超えるまで a、a + b、a + 2b を追加し続けます。 各ステップでは、答えに 1 つの値が追加されます。 これは、RAID の定義に正確に従っているため、正しいです。 ただし、b = 1 の最悪のケースでは、各クエリは O(n) 要素に触れるため、合計の複雑さは O(n・p) となり、遅すぎます。 

重要な観察は、ステップ サイズが大きさに応じて大きく異なる動作をするということです。 b が大きい場合、a + kb はすぐに n を超えるため、訪問される要素の数は少なくなります。 b が小さい場合、各クエリは多くの要素を訪問しますが、明確なステップ サイズはほとんどなく、剰余クラスに対する動的計画法を使用して、すべての小さい b に対する答えを事前計算できます。 

標準的な最適化では、クエリを 2 つのレジームに分割します。 大きい b の場合は、短いため、進行を直接シミュレートします。 小さい b の場合、サイズ b のステップに沿って配列の末尾から逆方向に合計を累積する DP テーブルを使用して答えを事前計算します。 これにより、重複する等差数列を繰り返し再計算することが回避されます。 

これが機能するのは、固定 b を持つすべてのジャンプが b を法とする剰余によって独立したチェーンを形成し、各チェーンを b ごとに線形時間で逆順に処理できるためです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(クエリごとの n) | お(1) | 遅すぎる |
 | ステップ サイズの sqrt 分解 | O(n √n + p √n) | O(n √n) | 承認済み |

 ## アルゴリズムのチュートリアル

 √n 付近のしきい値 B を選択します。 ステップ サイズは、小さい (b ≤ B) と大きい (b > B) に分類されます。 

1. 配列に対して DP テーブルを構築することにより、すべての小さなステップ サイズ b に対する答えを事前計算します。 固定 b の場合、n から 1 までのインデックスを処理し、i + b ≤ n の場合は dp[b][i] = w[i] + dp[b][i + b] を維持し、そうでない場合は単に w[i] を維持します。 これにより、どんな small-b クエリにも O(1) 時間で答えることができます。 
2. ステップ サイズ b が大きい場合、何も事前計算しません。 代わりに、クエリごとに、途中で重みを合計しながら、n を超えるまで i、i + b、i + 2b を直接シミュレートします。 b が大きいため、訪問位置の数は最大でも n / B と少なくなります。 
3. 各クエリについて、b ≤ B かどうかを確認します。そうであれば、dp[b][a] を返します。 それ以外の場合は、配列を手動でステップ実行して合計を計算します。 
4. 各クエリの結果を個別に出力します。

この分離が機能する理由は、すべてのクエリに個別のステップ チェーンがほとんどないか (小さい b)、またはチェーンあたりの要素がほとんどない (大きい b) ため、両方の次元で最悪の場合の爆発が回避されるためです。 

### なぜ効果があるのか

 b. ステップ サイズを固定します。 インデックスは、剰余 b に基づいて独立したシーケンスに分割されます。 各シーケンス内で、各位置の寄与は、同じシーケンス内の次の位置にのみ依存します。 右から左に処理することで、dp[b][i] を計算するときに、値 dp[b][i + b] がすでにわかっていることが保証されます。 これにより、RAID サムの定義と正確に一致する正しい繰り返しが作成されます。 ジャンプは決して残基クラスを越えないため、異なる残基間の重複は正確さに影響しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n = int(input())
    w = list(map(int, input().split()))
    p = int(input())

    B = int(n ** 0.5) + 1

    dp = [None] * (B + 1)
    for b in range(1, B + 1):
        dp[b] = [0] * n
        for i in range(n - 1, -1, -1):
            j = i + b
            if j < n:
                dp[b][i] = w[i] + dp[b][j]
            else:
                dp[b][i] = w[i]

    out = []
    for _ in range(p):
        a, b = map(int, input().split())
        a -= 1

        if b <= B:
            out.append(str(dp[b][a]))
        else:
            s = 0
            i = a
            while i < n:
                s += w[i]
                i += b
            out.append(str(s))

    print("\n".join(out))

if __name__ == "__main__":
    main()
```DP テーブルの構築は最適化の中核です。 各 dp[b][i] は、i から始まるステップ b の等差数列の合計を表します。 遷移がすでに解決されるように、逆方向に計算します。 

大きなステップの場合、ループは意図的に単純になります。単に進行方向を歩くだけです。 重要な正確性のポイントは、選択したしきい値により反復回数が十分に小さいため、通過できることです。 

実装の微妙な詳細はインデックス付けです。入力は 1 ベースですが、DP は 0 ベースのインデックス付けに基づいて構築されているため、 a を 1 回デクリメントし、その形式で一貫して使用する必要があります。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import sqrt
    input = sys.stdin.readline

    n = int(input())
    w = list(map(int, input().split()))
    p = int(input())

    B = int(n ** 0.5) + 1

            i = a
            while i < n:
                s += w[i]
                i += b
            out.append(str(s))

    return "\n".join(out)

 ## 特殊なケース

 b = 1 の場合、アルゴリズムは dp[1] に完全に依存し、事実上、配列全体のサフィックスの合計になります。 この場合、最大長の進行の正確性が保証されます。 

b ≥ n の場合、a + b はすぐに境界を超えるため、トラバースは 1 つの要素のみを訪問します。 このアルゴリズムは、DP パスとシミュレーション パスの両方でこれを自然に処理します。 

w = [1, 0, 1, 0, ...] と b = 2 などの小さな値を交互に繰り返す場合、DP は同じパリティのインデックスのみが正しく累積されることを保証し、剰余クラスの分解が適切であることを確認します。
