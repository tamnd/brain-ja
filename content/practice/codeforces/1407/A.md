 ## 解決策
 ## 問題の理解

 いくつかの独立したテスト ケースが与えられています。 各テスト ケースには、偶数長のバイナリ配列が含まれています。 要素は配列内のどこからでも削除できますが、削除できるのは最大でも半分です。 削除後、残りのサブシーケンスを元の順序で交互の合計がゼロになるように出力する必要があります。これは、奇数位置の要素の合計が偶数位置の要素の合計と等しくなることを意味します。 

すべての要素は 0 または 1 のいずれかであるため、交互の合計条件は、奇数の位置と偶数の位置に何個の 1 が配置されるかをバランスすることと同じです。 ゼロは合計には影響しませんが、位置を占め、1 がプラスに寄与するかマイナスに寄与するか反転する可能性があるため、依然としてパリ​​ティに影響します。 

出力は、選択した要素のインデックスではなく、結果のシーケンス自体です。 条件を満たす n/2 から n までの長さの有効なサブシーケンスを構築するだけで済みます。 

すべてのテスト ケースの合計 n が最大 1000 であるという制約により、見方が大きく変わります。 二次または中程度の三次構造も許容されますが、問題は大量の計算に関するものではありません。 それは、順序を尊重しながら、交互の立場での貢献間のバランスを強制する構造的な方法を認識することです。 

単純な間違いは、少なくとも n/2 のサイズのすべてのサブセットを試行するか、パリティに基づいて貪欲に削除をシミュレートする必要があると考えることです。 これは失敗します。パリティは以前の削除に依存するため、ローカルで貪欲な決定を行うと、制御されない方法で後の要素の役割が反転する可能性があります。 

もう 1 つのよくある間違ったアプローチは、順序を維持しながら、奇数と偶数の位置のペアに 1 を直接一致させようとすることです。 これは、ゼロが予期せぬ方法でパリティ境界をシフトする場合に問題が発生します。たとえば、[1,0,1,0,1,0] のような配列では、誤ったゼロを早期に削除すると、後の 1 が正の位置に着地するか負の位置に着地するかが変化します。 

## アプローチ

 主な難点は、交互の合計が値だけではなく位置に依存することです。 要素を削除すると、将来のパリティがすべて変更されるため、位置について直接推論するのは不安定です。 

ブルートフォース手法では、少なくとも n/2 のサイズのすべてのサブシーケンスを試し、それらの交互の合計を計算し、妥当性をチェックします。 正確に k 個の要素を選択するように制限したとしても、サブセットの数は指数関数的で、およそ 2^n であり、n = 1000 の場合でもまったく実現不可能です。 

重要な点は、すべての要素を保存したり、構造を注意深く最適化したりする必要がないということです。 交互構造という点で「行儀が良い」サブシーケンスだけが必要です。 最大 n/2 個の要素を削除できるため、配列の半分を破棄しても成功する可能性があります。 

建設的なアイデアは、対称性を利用することです。バランスの取れた交互パターンで表示されるように、1 つが制御されるシーケンスを構築しようとします。 非常に便利な単純化は、プレフィックスのような構造を維持しながら、パリティ制御を強制するのに十分な要素をスキップするという観点から考えることです。 

標準的な構造は、要素の不均衡が蓄積しないように機能を維持しながら要素を保持することです。 値は 0 と 1 のみであるため、問題のあるシンボルは 1 だけです。ゼロは、和に影響を与えることなくパリティを調整するために常に使用できます。 

現在の交互の合計パリティを追跡する貪欲なサブシーケンスを維持します。 ゼロはバランスに影響を与えることなく長さを調整するのに役立つため、常に含めます。 そのうちの 1 つは、奇数と偶数の貢献の間のバランスを維持または回復するのに役立つ場合にのみ含めます。 最大半分の要素を削除できるため、問題のある要素を破棄する十分な自由があります。

これにより、非常にシンプルだが強力な不変式が得られます。選択された要素の数が少なくとも n/2 であるサブシーケンスを構築し、選択された要素の間で、交互の寄与が相殺される方法でそれらがペアになることを保証します。 

より具体的な観点は、すべての 0 を確実に選択し、選択する 1 の数が偶数になるように十分な 1 を選択することで、常に有効な答えを構築できるということです。 次に、元の順序を維持することで暗黙的に配置します。 0 の交互の合計は中立であり、配列の最大半分を破棄することで最後の不一致の導入を常に回避できるため、1 のバランスをとることができます。 

これが機能するのは、最悪の場合、カウントを均等にするのに十分な数のものを破棄し、残りの構造を常に一貫して交互に作成できるためです。

 ## アルゴリズムのチュートリアル

 1. 概念的には配列を 0 と 1 に分割しますが、元の順序で処理されるため、出力はサブシーケンスとして有効なままになります。 
2. 答えの最初にすべてのゼロを集めます。 ゼロは、位置に関係なく交互の合計が変化しないため、常に安全です。 
3. 配列をスキャンするときに、リストを個別に維持します。 
4. 1 の数が偶数であることを確認します。 集めた数が奇数の場合は、任意の 1 つを破棄します (除去に制限がないため、どれを落としても安全です)。 
5. 配列を再度スキャンし、選択した要素のみを出力することにより、ゼロと選択したものを元の相対的な順序に戻します。 
6. 必要に応じて、最終的なサイズが少なくとも n/2 であることを確認します。これは、ゼロを決して破棄せず、最大 1 つの 1 のみを破棄するため、これが保証されます。 

重要な推論ステップは、ゼロは交互の合計に寄与しないため、バランスは 0 間の正確な配置ではなく、1 のパリティのみに依存するということです。 

### なぜ効果があるのか

 交互の合計は、奇数位置と偶数位置にどれだけのものが現れるかによってのみ決まります。 ゼロはニュートラル パディングとして機能し、合計を変更しませんが、パリティを柔軟に変更できます。 1 の数が偶数であることを確認することで、概念的にそれぞれを別の 1 つとペアにして、有効な配置で一方が正の位置に、他方が負の位置に表示されるようにすることができます。 最大 n/2 個の要素を自由に削除できるため、サイズ制約に違反することなくこのパリティ条件を強制するのに十分な余裕が常にあります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        zeros = []
        ones = []

        for x in a:
            if x == 0:
                zeros.append(0)
            else:
                ones.append(1)

        # ensure even number of ones
        if len(ones) % 2 == 1:
            ones.pop()

        # construct result greedily in original order
        res = []
        one_used = 0
        zero_used = 0

        for x in a:
            if x == 0:
                res.append(0)
                zero_used += 1
            else:
                if one_used < len(ones):
                    res.append(1)
                    one_used += 1

        print(len(res))
        print(*res)

if __name__ == "__main__":
    solve()
```この実装は、順序を維持しながらフィルタリングするという考えに従っています。 まず、多くても 1 つを破棄して、1 の数が偶数になるようにします。 次に、元の配列を調べて、必要な数だけ受け入れることによってサブシーケンスを再構築します。 常にゼロが含まれるため、必要な長さのしきい値を超えていることが保証されます。 

微妙な点は、構築中に交互の合計を明示的に計算しないことです。 正確さは、1 がペアで使用され、0 がパリティに影響を与えないという構造上の保証から得られるため、結果として得られるシーケンスの交互配置をバランスよく行うことができます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        ones = a.count(1)
        res = []
        if ones % 2 == 1:
            ones -= 1
        used = 0
        for x in a:
            if x == 0:
                res.append(0)
            else:
                if used < ones:
                    res.append(1)
                    used += 1
        out.append(str(len(res)))
        out.append(" ".join(map(str, res)))
    return "\n".join(out)

 ## 特殊なケース

 エッジケースの 1 つは、配列に 1 だけが含まれる場合です。 たとえば、[1,1,1,1]。 アルゴリズムでは、カウントがすでに偶数であるため、すべて 1 が維持され、交互の合計は恒等順序付けの下で 1 - 1 + 1 - 1 = 0 としてキャンセルされることが保証されています。 

もう 1 つのエッジ ケースは、配列が 0 と 1 を交互に配置する場合です。 [0,1,0,1,0,1] では、アルゴリズムは必要に応じてパリティを 1 つ削除することによってのみパリティを調整します。 ゼロは、合計を変更せずに任意のパリティ スロットを占有することができるため、位置の柔軟性が確保され、強制的な不均衡は発生しません。 

最後のエッジケースは、それが 1 つだけ存在する場合です。 [0,1] では、偶数の 1 が必要なため、その 1 を破棄し、交互合計条件を自明に満たす [0] だけを残します。
