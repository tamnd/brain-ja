 ## 解決策
 ## 問題の理解

 サイズ _n_ × _m_ の 2D グリッドが与えられ、各セルには星が含まれています。`*`または空の`.`。 課題は、十字の形をした星座を見つけることです。 十字は星を中心として、垂直方向と水平方向の 4 方向すべてに正確に _x_ 個の正方形に広がります。_x_ は、5 つのセルすべてが存在し、星を含むような正の整数です。 特定の順序に従って k 番目の星座を見つけるように求められます。最初に半径順 (小さい順)、次に中心星の行順 (一番上から順)、次に列順 (左端から順) です。 

境界は、_n_、_m_ ≤ 300、および _k_ ≤ 3,000 万です。 マップ サイズは中程度であるため、O(n² m²) アルゴリズムは許容されますが、O(n m max(n,m)) では限界が押し上げられ始めます。 300×300 のグリッドでは、すべての半径でブルートフォース試行を行うと、数千万件のチェックが発生する可能性があり、これは 2 秒で処理できる上限に達します。 エッジ ケースには、星のないマップ、端の十字、半径 1 とそれより大きい半径の十字、存在する星座が k より少ない場合に k 番目の星座を求めるなどが含まれます。 

不用意に実装すると、最初に境界を検証せずに潜在的なクロスを反復処理する可能性があります。 たとえば、中心の星が (1,1) にある場合、単純なチェックでは上腕の (0,1) にアクセスしようとし、インデックス エラーが発生する可能性があります。 同様に、中央の星が欠けている以外は星で埋め尽くされた地図は、単純な半径カウント アルゴリズムを騙す可能性があります。 

## アプローチ

 ブルート フォース アプローチは概念的に単純です。マップ上のすべての星について、1 から始まって十字が範囲外に広がるまで、考えられるすべての半径を試します。 各半径について、4 本のアームすべてをチェックして、星が存在するかどうかを確認します。 有効な場合はコンスタレーションを記録し、見つかったすべてのコンスタレーションを半径、行、列に従って並べ替えます。 これは正しいですが、非効率的です。 n = m = 300 の場合、中心の星の半径は最大 150 になる可能性があり、半径ごとに各星をチェックすると演算が増加し、最悪の場合は O(n m min(n,m)) になります。 90,000 のセルと 150 の半径チェックにより、操作数は 1,000 万を超え、制限に近づいています。 

重要な洞察は、各星の各方向の腕の最大長を知る必要があるだけであるということです。 動的プログラミングを使用して、セルごとに上下左右の連続する星の数を事前計算します。「上」配列の場合は上から下へ、「下」の場合は下から上へ、「左」の場合は左から右へ、「右」の場合は右から左へ繰り返します。 各星における最大交差半径は、これらの 4 つの事前計算値の最小値になります。 これが分かれば、すべての半径を個別に繰り返すことなく、すべての有効な十字を生成できます。 これにより、冗長なチェックが削減され、アルゴリズムが十分に高速になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n m min(n,m)) | お(1) | 上限では遅すぎる |
 | 腕の長さを事前計算する | O(nm) | O(n・m × 4) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. グリッドを読み取り、サイズ n×m の 4 つの行列 (上、下、左、右) を初期化します。 各行列には、現在のセルから開始してその方向に連続する星が格納されます。 
2. 各列を上から下に繰り返して、「上」マトリックスを埋めます。 セルに星が含まれている場合は、up[i][j] = up[i-1][j] + 1 (または一番上の行の場合は 1) を設定します。 現在のセルを含めて上に連続する星が何個存在するかをカウントします。 
3. 同様に、下から上に繰り返して「下」を塗りつぶし、左から右に繰り返して「左」に塗りつぶし、右から左に繰り返して「右」に塗りつぶします。 
4. 星を含むすべてのセルについて、その最大交差半径を次のように計算します。`r = min(up[i][j], down[i][j], left[i][j], right[i][j]) - 1`。 中心の星は各方向で数えられるため、1 を引きます。 
5. 1 から r までの半径ごとにタプルを記録します`(radius, row, col)`有効なクロスを表します。 すべてのタプルをリストに保存します。 
6. 十字のリストを半径、行、列の順に並べ替えます。 
7. k が十字の数を超える場合、-1 を出力します。 それ以外の場合は、k 番目のタプルを取得し、中心、上、下、左、右の星の座標を出力します。 

機能する理由: 事前計算により、すべてのセルについて 4 方向すべての最大到達距離がわかっていることが保証されます。 最小値を取ることで、無効なクロスの生成を回避します。 ソートにより、要求された k 番目のコンスタレーションが問題のランキング ルールを正確に満たすものであることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m, k = map(int, input().split())
grid = [input().strip() for _ in range(n)]

up = [[0]*m for _ in range(n)]
down = [[0]*m for _ in range(n)]
left = [[0]*m for _ in range(n)]
right = [[0]*m for _ in range(n)]

# Precompute consecutive stars
for i in range(n):
    for j in range(m):
        if grid[i][j] == '*':
            up[i][j] = 1 + (up[i-1][j] if i > 0 else 0)
            left[i][j] = 1 + (left[i][j-1] if j > 0 else 0)

for i in reversed(range(n)):
    for j in reversed(range(m)):
        if grid[i][j] == '*':
            down[i][j] = 1 + (down[i+1][j] if i < n-1 else 0)
            right[i][j] = 1 + (right[i][j+1] if j < m-1 else 0)

crosses = []
for i in range(n):
    for j in range(m):
        if grid[i][j] == '*':
            radius = min(up[i][j], down[i][j], left[i][j], right[i][j]) - 1
            for r in range(1, radius+1):
                crosses.append((r, i, j))

crosses.sort()
if k > len(crosses):
    print(-1)
else:
    r, i, j = crosses[k-1]
    print(i+1, j+1)
    print(i+1-r, j+1)
    print(i+1+r, j+1)
    print(i+1, j+1-r)
    print(i+1, j+1+r)
```このソリューションでは、冗長な半径チェックを回避するために、まず各方向の最大ストレッチを事前計算します。 半径を 1 減算すると、中心を越える星のみが数えられるようになります。 タプルのソート`(radius, i, j)`問題の順序を直接尊重します。 事前計算はグリッドのエッジで停止するため、境界チェックは暗黙的です。
