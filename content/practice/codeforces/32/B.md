 ## 解決策
 ## 問題の理解

 Borze エンコード システムで書かれた文字列が与えられます。 3 進数の各桁は、次の 3 つのパターンのいずれかで表されます。 

-`"."`を表します`0`-`"-."`を表します`1`-`"--"`を表します`2`タスクは、文字列全体をデコードし、結果の 3 進数を出力することです。 

重要な点は、エンコーディングがプレフィックスセーフであることです。 単一の点は常に単独で存在します`0`、一方、ダッシュは常に次の文字と組み合わせる必要があります。 つまり、私たちが遭遇するたびに、`'-'`、現在の数字が 2 つの文字を使用していることがすぐにわかります。 

入力長は最大 200 文字と非常に小さいです。 最悪の場合でも約 40,000 文字の演算を処理するため、二次解法でも制限時間内に問題なく収まります。 それでも、エンコードの構造により自然に単純なリニア スキャンが行われるため、追加の作業を行う必要はありません。 

間違いの主な原因は、文字列の解析中にポインターが正しく移動しないことです。 

次の入力を考えてみましょう。```
--.
```正しいデコードは次のとおりです。```
20
```不用意に実装すると、最初の内容が読み取られる可能性があります。`'-'`単独では次の文字と組み合わせることはできません。 エンコード規則では、すべてのダッシュが 2 文字を消費する必要があります。 

もう 1 つの簡単な間違いは、2 文字のトークンをデコードした後に文字列を進めるときに発生します。 

例えば：```
-.--
```正しい出力:```
12
```デコードすると`"-."`として`1`ただし、2 番目の文字は 2 つではなく 1 つだけ前に進みます。`'.'`再度処理され、間違った結果が生成されます。 

最後のエッジ ケースは、完全にドットで構成される文字列です。```
...
```正しい出力:```
000
```先頭のゼロはデコードされたとおりに正確に保持する必要があります。 結果を整数に変換すると、誤って単一の整数に折りたたまれます。`0`。 

## アプローチ

 最も直接的な総当り攻撃のアイデアは、現在のプレフィックスと 3 つの有効な Borze シンボルの照合を繰り返し試行することです。 各位置で、部分文字列が次で始まるかどうかを確認します。`"."`、`"-."`、 または`"--"`、対応する数字を追加して続行します。 

これが機能するのは、エンコード規則が明確であるためです。 現在の文字を検査し、必要に応じて次の文字を検査すると、有効な記号を別の記号と混同することはできません。 

すべてのステップで部分文字列を作成する非効率的な実装であっても、入力が非常に小さいため、ソリューションは依然として快適に通過します。 長さが最大でも 200 であれば、文字列のスライスを繰り返しても、数万回の操作を行っても十分に耐えられます。 

問題をさらに単純化する観察は、実際には 2 つの状況しかないということです。 

- 現在のキャラクターが`'.'`、答えの数字は間違いなく`0`。 
- 現在のキャラクターが`'-'`、次の文字を検査するだけで済みます。 

-`"-."`手段`1`-`"--"`手段`2`これにより、インデックス ポインターを使用して 1 回の左から右へのスキャンで文字列を処理できるようになります。

 ## アルゴリズムのチュートリアル

 1. Borze 文字列を読み取ります。 
2. 空の結果文字列を作成し、インデックスを初期化します。`i = 0`。 
3. その間`i`文字列内にあります:

 1. もし`s[i]`は`'.'`、追加`'0'`答えに向かって進みます`i`1ずつ進みます。 
2. それ以外の場合、現在の文字は`'-'`, したがって、数字には 2 文字を使用する必要があります。 

- もし`s[i + 1]`は`'.'`、追加`'1'`。 
- それ以外の場合は追加`'2'`。 

動く`i`2ずつ進みます。 
4. 構築された応答文字列を出力します。 

### なぜ効果があるのか

 エンコード ルールは、入力を重複しない有効なトークンに分割します。 

ドットは常にトークンを形成します`"."`、ダッシュは常に次のいずれかで始まります`"-."`または`"--"`。 このため、正しいトークンの位置は`i`は現在のキャラクターとおそらく次のキャラクターによって一意に決定されます。 

このアルゴリズムは常に現在の数字に属する文字を正確に消費し、文字をスキップしたり、文字を 2 回処理したりすることはありません。 各ステップの後、処理されたすべてのプレフィックスはすでに正しくデコードされています。 スキャンが終了すると、文字列全体がデコードされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

s = input().strip()

ans = []
i = 0

while i < len(s):
    if s[i] == '.':
        ans.append('0')
        i += 1
    else:
        if s[i + 1] == '.':
            ans.append('1')
        else:
            ans.append('2')
        i += 2

print(''.join(ans))
```ソリューションはポインタを保持します`i`Borze 文字列内の現在の未読位置を表します。 

現在のキャラクターが`'.'`の場合、マッピングは即時に行われます。 追記します`'0'`このトークンは 1 文字だけを使用するため、1 つ先に進みます。 

現在のキャラクターが`'-'`を区別するには、次の文字を検査する必要があります。`"-."`そして`"--"`。 どちらの場合も 2 文字を消費するため、ポインタは 2 ずつ進みます。 

答えは、文字列を繰り返し連結するのではなく、リストに保存されます。 この問題では、どちらのアプローチでも合格しますが、リストの累積に続いて、`''.join()`は Python の標準的な効率的なパターンです。 

境界アクセス`s[i + 1]`入力が有効であることが保証されているため、常に安全です。 孤独な後追い`'-'`決して現れることはできません。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    s = input().strip()

    ans = []
    i = 0

    while i < len(s):
        if s[i] == '.':
            ans.append('0')
            i += 1
        else:
            if s[i + 1] == '.':
                ans.append('1')
            else:
                ans.append('2')
            i += 2

    print(''.join(ans))

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    global input
    input = sys.stdin.readline

    solve()

    return sys.stdout.getvalue().strip()

# provided sample
assert run(".-.--\n") == "012", "sample 1"

# minimum size input
assert run(".\n") == "0", "single dot"

# only two-character tokens
assert run("------\n") == "222", "all twos"

# alternating token sizes
assert run(".--.-.\n") == "021", "mixed parsing"

# leading zeroes preserved
assert run("...\n") == "000", "leading zeroes"

# boundary condition with final two-character token
assert run(".--\n") == "02", "ending with double dash"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`.`|`0`| 有効な最小入力値 |

 |`.--.-.`|`021`| 混合トークン長 |
