 ## 解決策
 ## 問題の理解

 同じ長さの 2 つのバイナリ文字列が与えられており、非常に珍しい操作を使用して最初の文字列を 2 番目の文字列に変換したいと考えています。 各操作により、現在の文字列内の位置のサブシーケンスを選択し、それらの選択された位置にある文字を 1 ステップずつ循環的に回転できます。 選択したサブシーケンスの外側にあるものはすべて固定されたままになります。 

重要な点は、サブシーケンスが連続している必要がないため、1 回の操作で任意の位置間で値を「シャッフル」できるのですが、それは 1 回の循環シフトでのみ可能です。 これにより、各操作はローカルな編集ではなく、制約されたグローバルな再配置になります。 

出力は、初期文字列をターゲット文字列に変換するために必要なそのような操作の最小数、または一連の操作が変換を達成できない場合は不可能です。 

n が 10^6 までの制約により、操作のシミュレーションやサブセットの探索を試みるソリューションは即座に除外されます。 O(n log n) のアプローチであっても、線形スキャンを中心に注意深く構成する必要があります。 どのような推論でも、多くの演算の結果をいくつかのグローバル不変条件に圧縮する必要があります。 

1 つ目の微妙な問題は、この操作では選択された文字のみが並べ替えられるため、文字列内の 1 の合計数が保持されることです。 s と t で 1 の数が異なる場合、答えは直ちに不可能になります。 

もう 1 つのそれほど明白ではないエッジ ケースは、s がすでに t に等しいが、ゼロ演算が有効であることを確認する必要がある場合です。 単純な貪欲なメソッドでは、依然として不必要な操作を試行したり、変更のカウントを誤ったりする可能性があります。 

ローカルで考えると、さらに深い落とし穴が現れます。文字を左から右に一致させて、貪欲に「不一致を修正」する誘惑にかられるのです。 これは失敗します。1 つの操作が任意の多くの位置に同時に影響を与える可能性があり、最適な操作は非ローカルな方法で複数の不一致を一度に解決する可能性があるためです。 

## アプローチ

 ブルート フォース ビューでは、変換をシミュレートしようとします。 各ステップで、サブシーケンスを選択し、可能なすべての回転を適用し、文字列状態に対して BFS を実行できます。 意味のあるサブシーケンスに限定したとしても、各位置が各操作に参加することも参加しないこともできるため、状態の数は n で指数関数的になります。 これは、小さな n を超えると完全に実行不可能です。 

重要な観察は、この操作が基本的に、選択されたセットに適用される巡回置換であるということです。 正確な再配置を追跡するのではなく、1 と 0 を正しい順序で組み合わせることで、s と t の間の不一致がどのように「解決」されるかを追跡します。 

両方の文字列を一緒にスキャンすることを検討してください。 不一致 s[i] != t[i] が見られるときはいつでも、不一致の位置間で質量の交換が必要であると考えることができます。 t に対して s に過剰な 1 がある位置と s に過剰な 0 がある位置を交互に繰り返すサブシーケンスを慎重に選択すれば、1 回の操作で複数の不一致を修正できます。 

これにより、問題はタイプ「10」と「01」の不一致がどのように相互作用するかを理解することになります。 この操作により、選択した不一致位置でサイクルを効果的に回転させることができます。つまり、各操作で不一致の 1 つおきのサイクルを除去できます。 

この問題は、不一致の位置を交互の鎖に分解することと同等になり、答えはこれらの鎖の構造によって決まります。 実際、各操作は正確に 1 つの交互の不一致ブロックを修正でき、操作の最小数はそのような独立したブロックの数によって決まります。 

文字列を左から右に処理し、不一致をタイプが交互になるセグメントにグループ化します。 交代が途切れるたびに、新しい操作が必要になります。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 文字列に対するブルート フォース BFS | O(2^n) | O(2^n) | 遅すぎる |
 | 貪欲な不一致グループ化 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 各位置を正しいか不一致としてモデル化します。 不一致のうち、s が 0、t が 1 の位置とその逆の 2 種類に分類します。 

左から右にスキャンし、現在のグループに含めた以前の不一致のタイプを維持します。 

1. まず、s と t の 1 の数が同じであることを確認して、実現可能性をチェックします。 そうでない場合は、-1 を返します。 これが必要なのは、どの操作も文字を並べ替えるだけであり、グローバル カウントを変更できないためです。 
2. 演算用のカウンタを0に初期化します。 
3. s[i] == t[i] である位置を無視して、インデックスを左から右にトラバースします。 
4. 新しいセグメントで最初の不一致が見つかったら、新しい操作グループを開始し、答えを増やします。 
5. 不一致のタイプが (0→1) と (1→0) の間で切り替わる限り、このグループを拡張し続けます。 その理由は、交互の不一致は、選択したインデックスに対する 1 回の循環ローテーションで修正できるためです。 
6. 2 つの連続した不一致が同じタイプである場合、交互は中断されるため、現在のグループを閉じて新しいグループを開始する必要があります。 
7. 文字列の終わりまで続けます。 

これが機能する理由は、各操作が不一致の位置のセットを選択し、それらの間で値を回転することに対応しているためです。 このようなローテーションは、選択された位置が余剰のゼロと余剰の 1 の間で交互するサイクルを形成する場合にのみ、不一致を解決できます。 最大の交互チェーンは 1 回の操作で解決できますが、交互の要件に違反せずにチェーンをマージすることはできません。 したがって、最大の交互チェーンの数は最小限になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    s = input().strip()
    t = input().strip()

    if s.count('1') != t.count('1'):
        print(-1)
        return

    ops = 0
    i = 0

    while i < n:
        if s[i] == t[i]:
            i += 1
            continue

        ops += 1
        need = s[i]  # type of mismatch start

        while i < n and s[i] != t[i]:
            if s[i] != need:
                break
            i += 1

    print(ops)

if __name__ == "__main__":
    solve()
```この実装は、不一致が不一致の方向の一貫性によって決定されるブロックにグループ化されるという観察に基づいています。 不一致が発生した場合にのみ新しい操作を開始し、不一致パターンが一貫している間、1 回の循環ローテーションでカバーできる方法で操作を拡張します。 

1 の数を使用した実現可能性チェックは不可欠です。そうしないと、グローバル パリティが異なる不可能なケースを修正しようとする可能性があるからです。

 ## 特殊なケース

 主なエッジケースは、文字列のカウントが同一であるにもかかわらず、不一致が大きくインターリーブされている場合です。 たとえば:

 入力:```
6
010101
101010
```ここでは、すべての位置が一致せず、タイプが完全に交互になっています。 アルゴリズムはすべてを単一の交互チェーンにグループ化するため、必要な操作は 1 つだけです。 この操作がすべてのインデックスを含むサブシーケンスを回転させ、配置全体を効果的に循環させることができるため、これが機能します。 

もう 1 つのエッジ ケースは、不一致によって互いに素なブロックが形成される場合です。```
8
11000011
00110000
```不一致タイプの一貫性が失われるため、スキャンでは不一致が個別のセグメントに分割されます。 各セグメントには独自の操作が必要であり、アルゴリズムはそれらを個別に正確にカウントします。 

これらのケースは、グループ化戦略がサブシーケンスにわたる有効な循環回転の構造と正確に一致していることを確認します。
