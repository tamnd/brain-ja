 ## 解決策
 ## 問題の理解

 長さの配列が与えられます$2n$。 正確に 2 つの要素を永久に削除することができます。 その後、残ったものは、$2n-2$要素はペアに分割する必要があります。 各ペアは 2 つの要素の合計で置き換えられ、配列が生成されます。$b$長さの$n-1$。 

要件は構築プロセス自体に関するものではなく、最終的な配列、つまりすべての数値に関するものです。$b$1 より大きい公約数を共有する必要があります。言い換えると、すべてのペアの合計は同時に何らかの整数で割り切れる必要があります。$d > 1$。 

タスクは gcd 値を見つけることではなく、この条件が成立するようにどのインデックスがペアになっているかを明示的に出力することです。 

制約は小さいです。$n \le 1000$最大 10 個のテスト ケース。 これにより、ペア構造にはすでに階乗成長があるため、要素のすべてのペアに対する大量の組み合わせ検索が即座に排除されます。 最悪の場合でも約$O(n^2)$候補者と各チェックは直線的です。 

gcd 条件がどの程度制限されているかに微妙な問題が生じます。 個々のペアを、ペアごとに独立して選択した数値で割り切れるようにするだけでは十分ではありません。 同じ除数がすべてのペアの合計に対して同時に機能する必要があります。 このため、ローカルの貪欲ペアリング戦略は、モジュール制約などの共有構造を明示的に強制しない限り、信頼性が低くなります。 

単純な間違いは、グローバルな可分性を考慮せずに、任意の要素を貪欲に組み合わせることです。 たとえば、入力内の最小要素と最大要素または隣接する要素を組み合わせても、すべての合計が公約数を共有するという保証はありません。 もう 1 つの失敗モードは、常にペアリングするなどの固定ペアリング戦略を選択することです。$i$と$i+1$これは、gcd 制約で必要な算術構造を無視します。 

主な難しさは、最初に 2 つの要素を削除して、残りのマルチセットを均一なモジュラー パターンと「互換性」を持たせる必要があることです。そうして初めて、その構造内で自由にペアリングできるようになります。 

## アプローチ

 強引なアイデアは、2 つの要素を破棄するあらゆる方法を試し、その後、何らかの有効な方法で残りの要素をペアにして、結果の合計に対して共通の gcd が存在するかどうかを確認することです。 ペアリング戦略を修正したとしても、2 つの要素を削除する方法は何通りもあります。$O(n^2)$それぞれについて、有効なペアリングが存在するかどうかを確認し、場合によってはそれを構築する必要がありますが、単純に行うと複雑になる可能性があります。 

重要な点は、実際にはペアリングと gcd 値を個別に検索する必要がないということです。 すべてのペアの合計がある数で割り切れる場合$d$の場合、各ペアはローカルのモジュール条件を満たさなければなりません。 特に便利な選択肢は、$d = 3$3 を法とする剰余は閉じた対系を形成するため、次のようになります。$0+0$そして$1+2$これにより、問題は 2 つの要素を削除した後、3 を法とした残りの数がこれらのルールに基づいて完全にペアになることが保証されるようになります。 

したがって、ペアリングを直接構築する代わりに、残基数が構造的にバランスがとれるように 2 つの要素を適切に削除する方法を探します。つまり、すべての要素をペアにすることができます。$(0,0)$または$(1,2)$ペア。 その条件が成立すると、ペアリング自体は単純かつ貪欲なものになります。

 ## アルゴリズムのチュートリアル

 ### 重要なアイデア

 私たちは 3 を法として処理し、すべてのペアの合計が 3 で割り切れる構造を強制しようとします。 

### ステップ

 1. コンピューティング$a_i \bmod 3$すべての要素について、残基クラスごとにインデックスを追跡します。 

これが必要なのは、ペアリングの実現可能性に関しては残基カウントのみが重要であるためです。 
2. 考えられるすべてのインデックスのペアを削除してみてください$(i, j)$。 

それらを除去した後、残りの残留物数をシミュレートします。 
3. 削除ごとにカウントを計算します$c_0, c_1, c_2$残りの要素の残基 0、1、および 2。 
4. これらのカウントが次の 2 つの条件を満たしているかどうかを確認します。 

剰余 1 の要素の数は剰余 2 の要素の数と等しく、剰余 0 の要素の数は偶数です。 

これにより、すべての要素を、合計が 3 で割り切れる有効なペアに分割できるようになります。 
5. 有効な削除が見つかったら、以下を組み合わせて答えを作成します。 

まず、残りのすべての 0 剰余要素を任意にペアにして、次に残りの 1 剰余要素を 2 剰余要素とペアにします。 
6. 構築されたすべてのペアのインデックスを出力します。 

削除ペアのみを試行する必要がある理由は、問題によって少なくとも 1 つの有効な構成が存在することが保証されるためです。$n \le 1000$許可します$O(n^2)$検索。 

### なぜ効果があるのか

 不変条件は、残りの要素にグローバルなモジュール構造を強制することです。 もし$c_1 = c_2$、すべての 1 は 2 と一致し、3 で割り切れる合計が得られます。$c_0$は偶数であり、残りの 0 残基のペアはすべてそれらの間で生成され、3 の倍数も生成されます。すべての要素はペア内で 1 回だけ使用されるため、結果として得られるすべての合計は 3 で割り切れるため、すべての合計の gcd は少なくとも 3 になります。 

破棄された 2 つの要素により、まさに残余カウントをこのバランスの取れた構成に調整できるようになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_pairs(indices, res):
    # returns list of pairs (i, j)
    pos = {0: [], 1: [], 2: []}
    for idx in indices:
        pos[res[idx]].append(idx)

    pairs = []

    # pair 0 with 0
    while len(pos[0]) >= 2:
        a = pos[0].pop()
        b = pos[0].pop()
        pairs.append((a, b))

    # pair 1 with 2
    while pos[1] and pos[2]:
        a = pos[1].pop()
        b = pos[2].pop()
        pairs.append((a, b))

    return pairs

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))

    res = [x % 3 for x in a]
    m = 2 * n

    found = False

    for i in range(m):
        if found:
            break
        for j in range(i + 1, m):
            remaining = []
            for k in range(m):
                if k != i and k != j:
                    remaining.append(k)

            c = [0, 0, 0]
            for idx in remaining:
                c[res[idx]] += 1

            if c[1] == c[2] and c[0] % 2 == 0:
                pairs = build_pairs(remaining, res)
                for x, y in pairs:
                    print(x + 1, y + 1)
                found = True
                break
```このソリューションは、和の安定したペアリング条件を保証する構造であるため、最初に値を剰余クラス mod 3 に変換します。 次に、考えられる破棄されたペアをすべて試し、残りのマルチセットが完全なペアリングの必要十分条件を満たしているかどうかを確認します。 

構築ステップでは、インデックスを剰余ごとに分離し、有効なペアを貪欲に形成します。 実行可能性により、各グループが完全に一致する構造を持つことが保証されるため、順序は重要ではありません。 

実装の微妙な詳細は、出力には元の位置が必要なため、値の代わりにインデックスが全体的に使用されることです。 これにより、値が繰り返されるときのあいまいさが回避されます。

    out = []

    for _ in range(t):

        a = list(map(int, input().split()))
        res = [x % 3 for x in a]
        m = 2 * n

        found = False

            for j in range(i + 1, m):

                for k in range(m):
                    if k != i and k != j:
                        remaining.append(k)

                c = [0, 0, 0]
                for idx in remaining:
                    c[res[idx]] += 1

                if c[1] == c[2] and c[0] % 2 == 0:
                    pos = {0: [], 1: [], 2: []}
                    for idx in remaining:
                        pos[res[idx]].append(idx)

                    pairs = []
                    while len(pos[0]) >= 2:
                        a = pos[0].pop()
                        b = pos[0].pop()

 ## 特殊なケース

 重要なエッジケースは、多くの値が同じ残基クラスを共有する場合であり、他の残基クラスのバランスをとる必要性を無視した貪欲なペアリングを誘惑する可能性があります。 たとえば、ほとんどの数値が 1 モジュロ 3 に一致する場合、残りの剰余 2 要素が一致できないため、これらを任意にペアにすることはできません。 

もう 1 つの微妙なケースは、一見有効に見える削除によって、合計がバランスが取れているように見えても、構造的にペアリングが不可能な構成が残る場合です。そのため、明示的な条件が必要になります。$c_1 = c_2$そして$c_0$さえ必要かつ十分です。 アルゴリズムはこれを直接チェックし、誤った貪欲な仮定を回避します。
