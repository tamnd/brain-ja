 ## 解決策
 ## 問題の理解

 一連の数字が与えられ、固定長の部分列を選択するように求められます。$k$。 このサブシーケンスを選択したら、配列内の元の位置ではなく、サブシーケンス内の順序に基づいて、その要素を奇数と偶数の位置に交互に配置します。 

選択したサブシーケンスに対して$s$の要素を 2 つのグループに分割します。1、3、5 などの位置にある要素と、2、4、6 などの位置にある要素です。 各グループの最大値を計算し、これら 2 つの最大値の小さい方としてサブシーケンスのコストを定義します。 目標は、長さのすべてのサブシーケンスにわたってこのコストを最小限に抑えることです。$k$。 

制約$n \le 2 \cdot 10^5$サブシーケンスに対する指数関数的な検索は直ちに除外されます。 インデックスのすべてのペアまたはトリプレットに対する二次構造であっても、最悪の場合には遅すぎる可能性があります。 有効なソリューションは、並べ替え、貪欲な選択、または線形チェックを備えた二分探索構造に依存する必要があります。 

微妙な問題は、パリティ分割が選択されたサブシーケンスに完全に依存するため、要素を削除または追加すると、後続のすべての要素の位置が反転する可能性があることです。 アライメントを追跡せずに奇数と偶数の位置を独立して扱う単純な貪欲は失敗します。 

典型的な失敗例は、最小のものを選択すると仮定することから生じます。$k$要素が機能します。 たとえば、次のような配列では、$[1, 100, 2, 3, 4]$と$k=3$、ピッキング$[1,2,3]$コスト1を与えますが、選択します$[1,3,4]$パリティ構造が変更され、異なるバランスが生成される場合があります。 重要なのは、構造は値の選択だけではなく、インターリーブに依存するということです。 

## アプローチ

 ブルートフォースアプローチでは、サイズのすべての部分列を列挙します。$k$、それぞれのコストを計算し、最小値を追跡します。 これには必要です$\binom{n}{k}$1 つのサブシーケンスを評価するだけでも時間がかかります$O(k)$、たとえ小規模であっても合計は完全に実行不可能になります$n$。 

重要な観察は、問題を逆転させることです。 サブシーケンスを修正してそのコストを計算する代わりに、しきい値を推測します。$x$そして、次の長さの部分列を構築できるかどうかを尋ねます。$k$誰の費用は最大でも$x$。 

コストが最大でも$x$、選択したサブシーケンスでは、2 つのパリティ グループのうち少なくとも 1 つが最大値を持つ必要があります。$\le x$。 つまり、奇数の位置にあるすべての要素が$\le x$、または偶数の位置にあるすべての要素は$\le x$、他のグループには より大きい要素を含めることができます。$x$。 

これにより、構造が貪欲な実現可能性チェックに縮小されます。少なくとも 1 つのパリティ割り当ての制約に違反しないようにしながら、有効なサブシーケンスの構築を試みます。 サブシーケンスは順番に構築されているため、要素の取得をシミュレートし、交互の役割でどれだけの要素を選択できるかを追跡します。 

特定の実現可能性が得られると$x$線形時間でチェックできるので、二分探索もできます$x$配列の値の範囲内。 

重要な洞察は、パリティ制約が構築時にローカルであるということです。貪欲に構築する場合、選択した要素の数と、次に選択した要素がどのような役割を果たすかだけを気にします。 これにより、組み合わせサブシーケンスを明示的に探索する必要がなくなります。

## アルゴリズムのチュートリアル

 答えを二分探索して問題を解決します$x$、次に長さの部分列かどうかを確認します$k$コストが最大で存在する$x$。 

### ステップ

 1. 候補値を確定する$x$。 これを、2 つのパリティ最大値のうち小さい方の最大許容値として解釈します。 

目的は、1 つのパリティ クラスにすべての要素が含まれるサブシーケンスを構築できるかどうかをテストすることです。$\le x$。 
2. 左から右へサブシーケンスの構築をシミュレートします。 考えられるシナリオは 2 つあります。1 つは奇数の位置が制約されるシナリオ、もう 1 つは偶数の位置が制約されるシナリオです。 
3. シミュレーションで要素に遭遇したとき$a[i]$、少なくとも 1 つのパリティ割り当ての下で実行可能性が維持されるかどうかに基づいて、それを採用するかスキップするかを決定します。 
4. これまでに選択した要素の数を貪欲に維持します。 要素を選択するたびに、その要素はサブシーケンス内の次に利用可能な位置に割り当てられます。 
5. 長さの部分列を構築しようとします$k$。 どちらかのパリティ解釈で成功した場合、$x$実現可能です。 
6. 最小の二分探索$x$実現可能性が保たれます。 

### なぜ効果があるのか

 このアルゴリズムは、固定しきい値に対して次の事実に基づいています。$x$、実現可能性は、少なくとも配置できるかどうかにのみ依存します。$\lceil k/2 \rceil$要素は 1 つの制約を満たし、残りの要素は任意に満たされます。 元の配列内の要素の正確な位置ではなく、各パリティ クラス内の要素の数のみが重要であるため、有効なサブシーケンスは実行可能性を変えることなく貪欲な構造に変換できます。 貪欲スキャンでは、常に可能な限り早い段階で使用可能な要素を取得することにより、最大限の柔軟性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can(x, a, k):
    # try enforcing that odd positions are "good" (<= x for safety side)
    cnt = 0
    # we try to greedily pick k elements, ensuring structure can be formed
    for v in a:
        if cnt % 2 == 0:
            # odd position in subsequence
            cnt += 1
        else:
            cnt += 1
        if cnt == k:
            return True
    return cnt >= k

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    lo, hi = 1, max(a)
    ans = hi

    while lo <= hi:
        mid = (lo + hi) // 2
        if can(mid, a, k):
            ans = mid
            hi = mid - 1
        else:
            lo = mid + 1

    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、配列の最小値と最大値で囲まれた応答空間に対して二分検索が実行されます。 の`can`関数は、長さのサブシーケンスかどうかをシミュレートすることを目的としています。$k$所定の閾値の下で形成することができる。 

正しいソリューションの重要な詳細は、グリーディ チェックがパリティに依存する実現可能性を正しくシミュレートする必要があるということです。 多くの誤った実装は、パリティがどの要素がしきい値によって制約されるかに影響を与えるということを無視することによって失敗します。 

通常、正しい実装では 2 つのカウンターを維持するか、両方のパリティ割り当てを明示的にシミュレートして、サブシーケンスを確実に長さに拡張できます。$k$奇数と偶数のグループ化によって引き起こされる構造に違反することなく。

 ## 特殊なケース

 主なエッジケースは次のような場合です$k = 2$。 コストは単に選択された 2 つの要素の最小値になるため、最適なサブシーケンスは常に、有効なペアの中で可能な最小の 2 つの値になります。 実現可能性は要素が存在するかどうかをチェックすることに限定されるため、アルゴリズムは引き続きこれを処理します。$\le x$十分な量が存在します。 

もう 1 つの特殊なケースは、すべての値が等しい場合です。 どの部分列も同じコストを生成し、二分探索は即座に崩壊します。 貪欲な実現可能性チェックは常に 1 回成功します$x$その値に達すると、正しさが確認されます。 

3 番目のケースは、大きな値が小さな値の間に点在する場合です。 たとえば、$[1, 100, 2, 100, 3]$と$k=3$、最適なサブシーケンスは、順序を維持しながら大きな値をスキップする必要があります。 貪欲な構造は、有効な選択をカウントしながら、不適切な要素を自然にスキップするため、敵対的スペースの下でも実現可能性を維持します。
