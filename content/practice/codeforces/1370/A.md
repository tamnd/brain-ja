 ## 解決策
 ## 問題の理解

 1 から n までの異なる整数のすべてのペアの中で、可能な最大の最大公約数を見つけるように求められます。 与えられた n に対して、任意の 2 つの数値 a と b (1 ≤ a < b ≤ n) の最大 gcd が必要です。 入力は複数のテスト ケースで構成され、それぞれが値 n を指定し、出力はテスト ケースごとに 1 つの整数です。 

制約により、n は最大 10^6 まで可能であり、テスト ケースは最大 100 個存在できることがわかります。 すべての整数のペアを試す単純な解決策では、最悪の場合、およそ n²/2 回の gcd 計算が実行されます。 n = 10^6 の場合、これは 5 × 10^11 回の演算に相当し、1 秒で実行するには大きすぎます。 n に対してほぼ線形または対数時間で実行するアプローチが必要です。 

エッジ ケースには、最小の n = 2 が含まれます。この場合、唯一のペアは (1, 2) であり、gcd は 1 です。n が奇数である場合と偶数である場合には、別の微妙な問題が発生します。 たとえば、n = 3 の場合、ペアは (1, 2)、(1, 3)、(2, 3) となり、すべての gcd が 1 になります。n = 5 の場合、ペア (2, 4) の gcd は 2 となり、1 より大きくなります。これらのパターンを考慮しないソリューションでは、最大 gcd が過小評価される可能性があります。 

## アプローチ

 ブルートフォース手法は簡単です。すべてのペア (a, b) を反復処理し、それぞれの gcd(a, b) を計算し、最大値を追跡します。 これは、考えられるすべての組み合わせを直接テストするので正しいですが、n が 10^6 に達すると遅すぎます。 t = 100 のテスト ケースの場合、最悪のシナリオでは 10^13 を超える演算が必要になりますが、これは明らかに非現実的です。 

最適なアプローチは、可能な最大の gcd が少なくとも n//2 でなければならないという観察にかかっています。 数値 n 自体について考えてみましょう。 gcd k とペアを形成する k ≤ n の倍数を探す場合、[1, n] で 2 つの異なる倍数を許容する最大の k は n//2 です。 これは、k ≤ n//2 の場合、ペア (k, 2k) が常に範囲内にあるため機能します。 k の値がそれより大きくても、範囲内で 2 つの異なる倍数を生成することはできません。 したがって、各 n について、最大 gcd は単純に n//2 になります。 

この洞察により、問題はテスト ケースごとに 1 つの整数除算に削減され、ケースごとの解は O(1)、全体では O(t) になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | 遅すぎる |
 | 最適 | テスト ケースごとに O(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケース t の数を読み取ります。 これにより、処理する必要がある n の独立した値の数がわかります。 
2. 各テスト ケースについて、整数 n を読み取ります。 
3. 整数除算を使用して、n を 2 で割った値を計算します。 この値を max_gcd に割り当てます。 [1, n] 内で少なくとも 2 つの倍数を持つ最大の整数は正確に n//2 であるため、これは機能します。 
4. このテスト ケースの max_gcd を出力します。 
5. すべてのテスト ケースに対して手順 2 ～ 4 を繰り返します。 

機能する理由: k > n//2 の場合、[1, n] の k の倍数は k 自体だけであり、別個の数値のペアを形成することはできません。 k ≤ n//2 の場合、ペア (k, 2k) が有効であり、gcd k が保証されます。 したがって、n//2 はすべてのペアの中で可能な最大の gcd です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    print(n // 2)
```コードはテスト ケースの数を読み取り、n ごとに繰り返します。 整数の除算演算子`//`これは、奇数の n 値の場合に重要です。 計算後に直接印刷することで、不要なデータの保存が回避され、メモリの使用量が最小限に抑えられます。 

## 実用的な例

 サンプル 1:

 入力n = 3

 | n | n // 2 | 最大_gcd |
 | --- | --- | --- |
 | 3 | 1 | 1 |

 (1, 2) または (1, 3) または (2, 3) のペアはすべて gcd 1 を持ちます。n//2 は正しく 1 を返します。 

サンプル 2:

 入力 n = 5

 | n | n // 2 | 最大_gcd |
 | --- | --- | --- |
 | 5 | 2 | 2 |

 ペア (2, 4) の gcd 2 は最大値です。 n//2 はこれを正しく識別します。 

これらのトレースは、小さい奇数 n と偶数 n の両方について、アルゴリズムが正しい最大 gcd を選択することを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(t) | テスト ケースごとに 1 つの整数除算、定数時間 |
 | スペース | お(1) | 入力と出力以外に追加のメモリはありません。 

t ≤ 100 とすると、ソリューションは制限時間内で最大 100 回の単純な操作を実行します。 メモリはごくわずかで、256 MB の制限をはるかに下回っています。

 ## 特殊なケース

 n = 2 の場合、唯一のペアは (1, 2) です。 アルゴリズムは 2//2 = 1 を計算します。これは実際の最大 gcd と一致します。 7 のような奇数 n の場合、最大の gcd を持つ最大のペアは (3, 6) で、gcd は 3 になります。アルゴリズムは 7//2 = 3 を出力し、これを正しく識別します。 n = 10^6 が大きい場合、アルゴリズムはペア (500000, 1000000) の gcd である 500000 を計算します。これは、解が問題なく上限の制約に合わせてスケールされることを示しています。
