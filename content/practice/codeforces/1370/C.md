 ## 問題の理解

 単一の整数から始まる 2 人用のターンベース ゲームをプレイしています。 各手ごとに、現在のプレイヤーは 2 つの演算のいずれかを使用して数値を変換します。数値から 1 を引くか、1 より大きい奇数の約数で割ります。 除数は実際に現在の数値を除算する必要があり、除数には数値自体が含まれるため、数値が 1 より大きい場合は常に完全な数値で割ることができます。 

プレイヤーが何も行動できなくなった時点でゲームは終了します。これは数字が 1 になった場合にのみ発生します。引き算も割り算ももう不可能なので、その状況に直面した人はすぐに負けになります。 

タスクは、n の開始値ごとに、両側からの最適なプレイを想定して、最初のプレーヤーが強制的に勝利するかどうかを判断することです。 

この制約により、n は最大 10^9、テスト ケースは最大 100 個まで許可されます。 これにより、到達可能なすべての番号に対する状態空間検索が即座に除外されます。 n が大きすぎるため、n までのすべての状態にわたる単純な動的プログラミングさえ不可能です。 どのような解決策であっても、問題をいくつかの算術チェックと数値の構造的特性に帰着させる必要があります。 

単純だがよくある落とし穴は、ゲームがパリティのみ、または 1 に達するまでに必要な手数のみに依存していると想定することです。たとえば、「奇数は常に良い」という考え方はすぐに失敗します。なぜなら、n = 9 と n = 3 の動作が異なるためです。つまり、3 が勝ちですが、9 は複数の約数があるため、最適なプレイでは異なる動作をします。 もう 1 つの微妙な失敗例は、引き算が常に優勢なものとして扱われていることです。 実際には、奇数因数による除算は状態空間の大部分をスキップし、パリティ推論を完全に変える可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、すべての可能な動きにわたる再帰的なミニマックスとしてゲームをシミュレートしようとします。 与えられた n から、すべての奇数約数 d > 1 について、すべての状態 n - 1 および n / d に分岐します。これにより、n までの整数にわたるゲーム グラフが定義されます。 各状態の約数は O(sqrt n) のみですが、再帰の深さは O(n) になる可能性があり、繰り返し状態が複雑に現れます。 最悪の場合、これは指数関数的な探索につながりますが、これは 10^9 という小さな n の場合でも実行不可能です。 

重要な観察は、有効な手の構造が、ほとんどすべてのケースを少数の算術カテゴリに分類していることです。 奇数の合成は 1 より大きい奇数の約数を持ち、すぐに小さい奇数にできるため、奇数は非常に単純に動作します。 偶数は、2 の因数がいくつ含まれているかに応じて動作が異なります。 唯一本当にトリッキーな状況は、数値が 2 の累乗の場合です。これは、1 より大きい奇数の約数がないため、ゲームが単純なデクリメント チェーンのように動作することを強制するためです。 もう 1 つの特別な構造は、n が奇数の 2 倍である場合に発生します。この場合、除算により、一般的な偶数とは異なる動作をする素数状態が作成されます。 

最終的なソリューションでは、ゲーム全体を、テスト ケースごとに一定時間でいくつかの構造ケースをチェックするように削減します。

 ## アルゴリズムのチュートリアル

1. n が 1 の場合、最初のプレーヤーは何も動かず、すぐに負けます。 これはゲーム内で唯一のターミナル位置です。 
2. n が 2 に等しい場合、唯一の動きは 1 を引くことです。これにより、対戦相手に 1 が残り、最初のプレイヤーの勝利が保証されます。 
3. n が奇数で 1 より大きい場合、n は 1 より大きい奇数の約数であるため、最初のプレーヤーはいつでも n 自体で割ることができます。この手により、ゲームは直接 1 に送られ、強制的に勝ちとなります。 
4. n が偶数の場合、n = 2^k * m (m は奇数) として因数分解します。 動作は、k と m が 1 に等しいかどうかによって異なります。 
5. n が 2 の累乗 (m = 1) の場合、すべての手が繰り返し 1 を減算することを強制されるため、結果は純粋に k のパリティに依存します。 この状況では、k > 1 のときに最初のプレーヤーが負けます。これは、最終的には、負ける構成では依然として偶数であるものの 1 に近い、より小さい 2 の累乗を渡すためです。 
6. n に 2 の因数が 1 つだけある場合 (k = 1)、n = 2 * m になります。 m が素数の場合、2 番目のプレーヤーは常に勝ちの構造を維持する方法で応答できるため、最初のプレーヤーにとっては負けの立場になります。 m が合成の場合、最初のプレーヤーは奇数の係数で除算してより小さな偶数状態を強制し、コントロールを得ることができます。 

決定的な洞察は、すべてのポジションが即時勝利 (奇数 n > 1)、些細な勝利 (n = 2)、または偶数を有利に破ることができない構造的な負けのケースのいずれかに帰着するということです。 唯一重要な構造は、2 による因数分解が奇数の約数の利用可能性とどのように相互作用するかです。 

### なぜ効果があるのか

 ゲームの勝敗は、プレイヤーが数字の奇数成分をどこまで減らすことができるか、そして分岐の動きによって相手にきれいな減少連鎖を与えることを回避できるかどうかによって完全に決まります。 奇数には 1 への自滅的な動きが含まれているため、常に対戦相手にポジションを奪われます。偶数が危険なのは、奇数の約数を 1 つの素因数に制限し、ゲームを直線的なカウントダウンに強制する場合のみです。 これにより、状態グラフ全体が等価クラスの小さなセットに折りたたまれ、隠れた長いサイクルが存在しないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def is_prime(x):
    if x < 2:
        return False
    if x % 2 == 0:
        return x == 2
    i = 3
    while i * i <= x:
        if x % i == 0:
            return False
        i += 2
    return True

t = int(input())
for _ in range(t):
    n = int(input())

    if n == 1:
        print("FastestFinger")
    elif n == 2:
        print("Ashishgup")
    elif n % 2 == 1:
        print("Ashishgup")
    else:
        # n is even and > 2
        # check if power of two
        if (n & (n - 1)) == 0:
            print("FastestFinger")
        else:
            # remove factor 2
            m = n
            while m % 2 == 0:
                m //= 2

            # if odd part is 1 => power of two already handled, so safe
            if m == 1:
                print("FastestFinger")
            else:
                # if m is prime AND n has no extra structure
                if is_prime(m) and n // m == 2:
                    print("FastestFinger")
                else:
                    print("Ashishgup")
```このコードはまず、n が 1 に等しい、n が 2 に等しいという単純な最終ケースを分離します。その後、数字自体による割り算は常に正当であり、ゲームが終了するため、すべての奇数がすぐに勝ちになります。 

偶数の場合、ちょっとしたトリック`(n & (n - 1)) == 0`強制プレイ下ではゲームが 1 に達するまで減算を繰り返すことになるため、順位を失いつつある 2 の純粋なべき乗を検出します。 数値が 2 のべき乗でない場合は、その奇数成分 m を抽出します。 

重要な違いは、m が素数であるかどうか、および数値がその素数のちょうど 2 倍であるかどうかです。 この構成により、最初のプレーヤーにとって有利な奇数の手を打つことができなくなり、ゲームが負ける構造に固定されます。 

## 実用的な例

 サンプルセットから 2 つの代表的な入力をトレースします。 

### 例 1

 入力: n = 6

 | ステップ | n | タイプ | 移動 | 結果の n |
 | --- | --- | --- | --- | --- |
 | 1 | 6 | 偶数複合 | 3で割る | 2 |

 これは、最初のプレイヤーが 2 に減らされることを強制し、その後、相手が負けの手を強いられることを示しています。 鍵となるのは、奇数の約数 3 の存在です。 

### 例 2

 入力: n = 4

 | ステップ | n | タイプ | 移動 | 結果の n |
 | --- | --- | --- | --- | --- |
 | 1 | 4 | 2 の累乗 | 1 を引く | 3 |
 | 2 | 3 | 奇数素数 | 3で割る | 1 |
 | 3 | 1 | ターミナル | なし | 前のプレイヤーの損失 |

 ここで、最初のプレイヤーは相手に勝ちの応答を渡すことを避けることはできません。 減算や強制的な構造に関係なく、2 番目のプレーヤーはいつでも強制的に勝利を得ることができます。 

6 と 4 のコントラストは、すべての偶数が同じ動作をするわけではないことを強調しています。 可分性構造は大きさよりも重要です。

 ## 特殊なケース

 n = 1 の場合、手が存在しないため、アルゴリズムは直ちに負けとして分類します。 出力は FastestFinger で、動かなくなったプレイヤーが負けるというルールに一致します。 

n = 2 の場合、コードはそれを特別な成功ケースとして扱います。 唯一の動きは引き算であり、これにより相手に n = 1 が強制され、勝利が保証されます。 

n = 8 の場合、値は純粋な 2 のべき乗です。 ビットチェック`(n & (n - 1)) == 0`トリガーし、負けたカテゴリーに送信します。 その理由は、奇数の約数は存在しないため、遊びは強制的な引き算に退化するということです。 

n = 9 の場合、これは奇数で 1 より大きいため、最初のプレーヤーがすぐに 9 で割って、分類に一致して 1 回の手で勝ちます。 

n = 18 の場合、数値は偶数ですが純粋な 2 のべき乗ではなく、その奇数成分は 9 (合成値) になります。 有利な奇数の約数が存在するため、アルゴリズムはそれを勝ちのポジションとして識別し、最初のプレーヤーが対戦相手の負けの構造に強制的に削減することを可能にします。
