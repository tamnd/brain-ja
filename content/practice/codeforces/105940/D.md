 ## 解決策
 ## 問題の理解

 このタスクでは、動物がいくつかの種類にグループ化されており、それぞれの種類に既知の数の動物がいる動物園について説明します。 入力により、各値が 1 つの特定の種類に属する動物の数に対応するリストが得られます。 目標は、動物園全体の動物の総数を決定することです。 

より具体的に解釈すると、配列の各要素はすでにカウントになっています。 隠された構造、種類間の相互作用、順序や関係に依存する制約はありません。 必要な操作は、これらすべてのカウントを単一の最終値に集約することだけです。 

制約は小さく、最大 100 種類、各種類が最大 100 匹の動物に寄与します。 これにより、計算はすぐに、最も単純な線形スキャンでも十分すぎる領域に置かれます。 種類の数が線形であるアルゴリズムは実際には最適であり、データを繰り返し渡してもパフォーマンス上の問題は発生しません。 

エッジケースは最小限ですが、それでも明示する価値があります。 

たとえば入力が 1 種類だけの場合`1`に続く`7`、答えは簡単です。`7`。 アキュムレータを誤って初期化したり、単一要素のケースをスキップしたりする実装は、ここで失敗します。 

すべての値が同一の場合、たとえば`3 1 1 1`、正しい出力は次のとおりです。`3`。 合計の問題でよくある間違いは、構造を誤って乗算したり、構造をより複雑なものとして誤解したりすることですが、ここでは純粋な集計のままです。 

時々バグが明らかになる特殊なケースは、すべての値が最大値に達している場合です。`100`100回繰り返しました。 正しい出力は次のとおりです`10000`これにより、固定幅の整数を使用する言語でオーバーフローの問題が発生せずに実装が正しく蓄積されるかどうかがテストされます。 Python ではこれは問題ではありませんが、概念的な境界であることに変わりはなく、留意する価値があります。 

## アプローチ

 強引な解釈では、すべての値を反復して累計を累積します。 この問題には要素間の選択、変換、依存関係などの制約が導入されていないため、意味のある代替定式化はありません。 たとえ「家族ごとに動物を数える」というシミュレーションを試みたとしても、各家族は独立して貢献しているため、そのシミュレーションはすぐに崩壊して足し算になってしまいます。 

したがって、ブルートフォース手法はすでに最適です。 想像できる唯一の「非効率」は、クエリごとに配列を最初から合計することを繰り返すことですが、クエリがないため、その心配さえ生じません。 計算全体は入力に対する 1 回のパスで行われます。 

重要な観察は、問題は基本的に、独立した量のリストを単一のスカラーに縮小することにあるということです。 これが認識されると、解決策は、配列全体のプレフィックスの合計を計算するか、入力の読み取り中に単純に累計を維持することになります。

 ## アルゴリズムのチュートリアル

 最適なアルゴリズムは基本的に、入力値に対するストリーミング累積です。 

1. 整数を読み取る`n`、これは動物の種類が何種類存在するかを表します。 これにより、後に続く数字の数が決まります。 
2. アキュムレータ変数を初期化する`total`ゼロに。 この変数は、これまでに観察された動物の累積数を表します。 
3. を繰り返します。`n`入力内の値。 それぞれの値について`a_i`に直接追加します。`total`。 このステップが機能する理由は、それぞれ`a_i`重複や相互作用のない独立した貢献を表します。 
4. すべての値を処理した後、出力します。`total`。 この時点で、すべてのファミリーが 1 回だけ計算されているため、アキュムレータが最終的な答えを保持します。 

### なぜ効果があるのか

 各入力値は、特定のカテゴリに属する動物の素の数です。 どの動物も複数のカテゴリに属せず、カテゴリ間で変換が発生しないため、総個体数はすべてのカテゴリ サイズの正確な合計となります。 このアルゴリズムは、i 番目の値を処理した後も不変式を維持します。`total`最初の i ファミリ サイズの合計に等しい。 ループが終了すると、この不変式はすべての n 値に拡張され、正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
arr = list(map(int, input().split()))

total = 0
for x in arr:
    total += x

print(total)
```このソリューションは 1 回のパスでリストを読み取り、現在の合計を維持します。 中間クエリや変換が必要ないため、追加のデータ構造は必要ありません。 

微妙な実装の詳細により、入力解析ですべてのデータが正しく読み取られることが保証されます。`n`値が複数の行に分かれている場合でも。 使用する`split()`この問題に対する標準入力形式では、2 行目で十分です。

 ## 特殊なケース

 単身世帯の場合、例えば、`1`に続く`6`ループが 1 回だけ実行される基本ケースを実行します。 アキュムレータはゼロから開始され、1 つの更新を受け取り、すぐに最終的な答えになります。これにより、小さな入力に対して特殊なロジックが必要ないことが確認されます。 

次のような一様分布`1 1 1 1 1`繰り返される同一の更新が一貫して動作することを保証します。 累計はステップごとに 1 ずつ単調増加し、最終値は要素の数と一致するため、反復中に上書きやリセットが発生しないことが確認されます。 

のような最大密度のケース`100`100 回繰り返すと、累積でより大きな中間合計が正しく処理されるかどうかがチェックされます。 Python でのモジュラー算術演算やオーバーフロー処理を必要とせずに累計は 10000 まで増加します。これは、ソリューションが純粋に単純な算術集計に依存していることを裏付けています。
