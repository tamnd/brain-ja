 ## 問題の理解

 ケージは正確に保持できます`k`動物。 がある`n`すべての家族には無限に多くのメンバーが含まれるため、家族は負でない任意の数の動物を提供できます。 家族`i`体重のある動物に貢献する`a[i]`。 タスクは、正確に選択して形成できるすべての総重量を見つけることです。`k`動物を使用できるため、同じ家族を繰り返し使用できます。 出力は、到達可能なすべての合計を昇順に並べたリストです。 

家族の数や動物の数の制限は小さいですが、回答可能な範囲が重要です。 以来`k`すべての重量は最大でも`1000`、可能な最大の合計は最大です`1,000,000`。 これは、最大重量範囲に応じた解決策が現実的であることを意味します。 一方、すべての家族、すべての動物の数、およびすべての合計に対する直接的な動的プログラミング アプローチには、およその時間がかかります。`1000 * 1000 * 1,000,000`これは私たちが負担できる額をはるかに超えています。 

難しいケースは、ファミリが再利用できるという事実から生じます。 各ファミリーを 1 回だけ使用可能として扱うソリューションは失敗します。 例えば：```
Input
1 3
5

Output
15
```唯一可能な選択肢は、同じ家族を3回連れて行くことです。 サブセット スタイルの DP は、重みのみを誤って示します。`5`可能です。 

もう 1 つのよくある間違いは、まさにそれを忘れることです`k`動物は必須です。 例えば：```
Input
2 2
1 100

Output
2 101 200
```合計`1`たとえ単一の体重の動物であっても無効です`1`存在します。 到達可能な金額だけでなく、選択した動物の数も追跡する必要があります。 

最後のエッジケースは、すべてのファミリの重みが同じ場合に発生します。```
Input
5 5
7 7 7 7 7

Output

```さまざまな選択肢が存在しますが、それらはすべて同じ合計を生成します。 回答には一意の重みのみが含まれている必要があります。 

## アプローチ

 簡単なアイデアは、次のような動的プログラミング テーブルを構築することです。`dp[c][s]`正確に選択できるかどうかを教えてくれる`c`動物の総重量`s`。 到達可能なすべての州について、すべての家族を次の動物として試します。 これは正しいです。なぜなら、すべての有効な選択は、1 匹の動物を繰り返し追加することによって説明できるからです。 

問題は遷移回数です。 まであります`k`可能な動物の数、最大`k * max(a[i])`可能な合計額、および最大`n`次の動物の選択肢。 最悪の場合はこれくらいです`1000 * 1,000,000 * 1000`これはおよそ 1,000 兆回の演算に相当します。 

重要な観察は、到達可能なすべての合計に対して遷移が同じであるということです。 現在到達可能なすべての合計を各家族の体重に応じてシフトするだけです。 ビットセットはまさにこのために設計されています。 ちょっと位置的に`x`その合計を意味します`x`到達可能です。 ビットセットを左にシフトする`a[i]`家族から 1 匹の動物を追加することで作成できるすべての合計をマークします。`i`。 

すべての合計を大きなテーブルに保存する代わりに、動物の可能な数ごとに 1 つのビットセットを保持します。 新しい動物の数を処理するときは、ビット シフトを使用して次のレイヤーを更新します。 Python の整数はすでに任意の長さのビットセットのように動作するため、1 つのシフトと OR 演算で一度に数千の状態を更新します。 

ブルートフォースが機能するのは、可能な最終的な選択肢をすべて調査するためです。 より高速な方法では、同じ状態定義が維持されますが、何百万もの個々の遷移がマシンレベルのビット操作に置き換えられます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(k * k * max(a) * n) | O(k * k * max(a)) | 遅すぎる |
 | 最適 | O(k * n * (k * max(a)) / word_size) | O(k * k * max(a) / word_size) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.作成`k + 1`ビットセット。 の`i`-th ビットセットは、正確に使用して達成可能なすべての重みを表します`i`動物。 最初は体重ゼロの動物はゼロのみが可能であるため、最初のビットセットにはビットのみが含まれます。`0`。 
2. すでに選択されている動物の可能な数ごとに、`0`に`k - 1`, もう一匹追加してみてください。 家族の体重ごとに`w`、現在のビットセットを左にシフトします。`w`それを次のレイヤーにマージします。 このシフトは、その家族の動物を 1 匹追加することを表します。 
3. すべてのレイヤーを構築した後、ビットセットを正確に検査します。`k`動物。 設定された各ビットは 1 つの達成可能な合計重みに対応するため、これらの位置を昇順に収集します。 

更新順序は重要です。 少数の動物からより多くの動物に移動するだけなので、レベルで作成される合計は`c + 1`同じレベル中に再利用されることはなく、誤って追加の動物を使用したものとしてカウントされます。 

なぜ機能するのか: 不変条件は、レイヤーを終了した後です。`c`、その層内のすべての設定ビットは、次の方法で取得できる重みを正確に表します。`c`動物のため、無効な体重は保存されません。 任意のファミリーからさらに 1 匹の動物を追加することは、到達可能な体重のセット全体をそのファミリーの体重だけシフトすることと同じです。 このようなシフトをすべて結合すると、正確に有効な状態が生成されます。`c + 1`動物。 帰納法により、最終層には可能なすべてのケージの重量が正確に含まれます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    data = list(map(int, sys.stdin.buffer.read().split()))
    if not data:
        return

    n, k = data[0], data[1]
    a = data[2:2 + n]

    dp = [0] * (k + 1)
    dp[0] = 1

    for cnt in range(k):
        cur = dp[cnt]
        if cur == 0:
            continue
        nxt = 0
        for w in a:
            nxt |= cur << w
        dp[cnt + 1] = nxt

    ans = []
    bits = dp[k]
    pos = 0
    while bits:
        low = bits & -bits
        pos = low.bit_length() - 1
        ans.append(str(pos))
        bits ^= low

    print(" ".join(ans))

if __name__ == "__main__":
    solve()
```配列`dp`正確な動物数ごとにビットセットの状態を保存します。 初期化`dp[0] = 1`動物を選択する前に合計ゼロのみに到達できることを意味します。 

すべての層について、変数`cur`現在到達可能なすべての合計が含まれます。 それぞれ`cur << w`動物1匹の体重を追加します`w`これまでのあらゆる可能性に対して。 OR 演算は、可能なすべてのファミリーを結合します。 

抽出ループは、最も低い設定ビットを繰り返し見つけます。 整数ビットは低位から高位の順に並べられているため、当然のことながら、答えは昇順で生成されます。 最下位ビットを削除すると、考えられるすべての重み値をスキャンする必要がなくなります。 

Python の整数は自動的に増加するため、実装では整数オーバーフローに対する特別な処理は必要ありません。 メイン境界の詳細は、次の時点までのみ反復されます。`k - 1`、最後の遷移は正確に次の状態を作成するためです。`k`動物。

## テストケース```python
import sys
import io

def run(inp: str) -> str:
    old = sys.stdin
    sys.stdin = io.StringIO(inp)
    data = list(map(int, sys.stdin.buffer.read().split()))
    if not data:
        return ""
    n, k = data[0], data[1]
    a = data[2:2+n]

    dp = [0] * (k + 1)
    dp[0] = 1
    for c in range(k):
        for w in a:
            dp[c + 1] |= dp[c] << w

    ans = []
    x = dp[k]
    while x:
        b = x & -x
        ans.append(str(b.bit_length() - 1))
        x -= b

    sys.stdin = old
    return " ".join(ans)

assert run("""3 2
1 2 3
""") == "2 3 4 5 6", "sample 1"

assert run("""5 5
1 1 1 1 1
""") == "5", "sample 2"

assert run("""3 3
3 5 11
""") == "9 11 13 15 17 19 21 25 27 33", "sample 3"

assert run("""1 3
5
""") == "15", "repeated family"

assert run("""2 2
1 100
""") == "2 101 200", "exact count"

assert run("""4 1
7 7 7 7
""") == "7", "duplicate weights"

 |`2 2 / 1 100`|`2 101 200`| その通り`k`動物を選択する必要があります。 |

 ## 特殊なケース

 反復家族の場合:```
Input
1 3
5
```アルゴリズムは到達可能な合計から始まります`{0}`。 1 回の移行後、`{5}`、2 つ後には次のようになります。`{10}`、3 つ後には次のようになります。`{15}`。 最後の層には、`15`、正しくは 1 つの家族の無制限の使用を許可します。 

正確なカウントの場合:```
Input
2 2
1 100
```1 匹の動物の後に到達可能な体重は次のとおりです。`{1, 100}`。 2 番目の遷移では、これらの状態が再度結合され、`{2, 101, 200}`。 値`1`動物は 1 匹だけ使用されるため、最終レイヤーには表示されません。 

重みが重複する場合:```

```すべてのトランジションは同じ量だけシフトします。 到達可能なセットは次のように増加します`{0}`、`{7}`、`{14}`、`{21}`、`{28}`、`{35}`。 ビットは 1 回しか設定できないため、ビットセットは重複する可能性を自動的に削除します。
