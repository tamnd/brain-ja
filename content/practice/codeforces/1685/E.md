 ## 解決策
 ## 問題の理解

 サイズの順列が与えられています$2n+1$、そしてこの配列は 2 つの位置の交換を通じて変化し続けます。 スワップのたびに、配列自体を直接分析することは求められませんが、そのすべての循環回転を考慮して、少なくとも 1 つの回転に「良好な」特性があるかどうかを判断するように求められます。その最も長く増加するサブシーケンスの長さは最大でも$n$。 そのような回転が存在する場合は、その回転オフセットを出力します。 それ以外の場合は不可能であると報告します。 

主な問題点は、更新のたびに配列と答えの両方が変更されることと、制約が$n \le 10^5$と$q \le 10^5$回転ごとに LIS を最初から再計算することを除外します。 更新ごとに LIS を 1 回計算するだけでも、単純に実行するとすでに境界線に達します。$2n+1$状態ごとにローテーションを行うため、ローテーションに対するブルートフォースは完全に不可能になります。 

微妙な構造上の制約が長さの中に隠されている$2n+1$。 しきい値$n$配列サイズのちょうど半分から半分を引いた値です。 これは、鳩の巣型の不変条件を強く示唆しています。すべての回転が「大きな LIS」であるか、制御された構造を強制する回転が存在するかのいずれかです。 この形式の問題は通常、すべてのローテーションを列挙するのではなく、単一のグローバル統計を追跡することに集約されます。 

失敗することが多い単純なアプローチは、回転ごとに LIS を個別に再計算することです。 固定配列の場合、これはすでに$O(n \log n)$回転ごとに乗算されます$O(n)$回転するとクエリごとに立方体になりますが、これは絶望的です。 もう 1 つのよくある間違いは、LIS が回転不変である、または相対順序のみに依存すると仮定することです。これは誤りです。回転によって隣接構造が変化し、サブシーケンスの増加と相互作用するためです。 

## アプローチ

 ブルート フォースの解釈は簡単です。更新ごとにスワップを適用し、すべての循環シフトを試行します。 シフトごとに、標準的な忍耐力の並べ替え方法を使用して LIS を計算します。 これは定義に直接従うため正しいですが、次のことが必要です。$O(n^2 \log n)$クエリごとに、これは両方の場合に実現可能な制限をはるかに超えています。$n$そして$q$大きいです。 

重要な観察は、「最大でも LIS とのローテーションが存在する」という条件が存在するということです。$n$「」は、順列のどこで「悪い遷移」が発生するかに関するグローバルな構造的制約に相当します。この問題に対する古典的な洞察は、LIS 情報を順列から構築されたバイナリ シーケンスに還元し、それを次から導出されるしきい値と比較することです。$n$。 LIS を再計算する代わりに、順列が「循環的な意味での局所的な増加」からどの程度離れているかを追跡します。 

より正確に確認する方法は、順列を点として考えることです。$(i, p_i)$。 LIS は、両方の座標を増加させた場合の最大チェーンに対応します。 順列の場合、LIS は反転や局所的な順序の変化と深く結びついています。 重要な変換は、選択したローテーション内の各隣接ペアについて、それが値の順序と比較して構造の増加に寄与するかどうかを分類することです。 良好な回転が存在するということは、ある不均衡の尺度を最小限に抑える循環配列内のカットを見つけることと同等になります。 

問題を変換すると、答えは、各スワップが 2 つの位置のみを更新する動的配列を維持し、クエリが可能なグローバル集計を維持することになります。$O(1)$または$O(\log n)$。 重要な構造は、スワップされたインデックスを中心としたローカルな反転のみがグローバルな状態に影響を与えることであり、これによりセグメント ツリーまたはフェンウィック スタイルのメンテナンスが可能になります。

 ## アルゴリズムのチュートリアル

 1. 順列を循環構造として再解釈し、増加する構造に関して順序が「整列している」か「整列していない」かを捕捉するバイナリ インジケータを各隣接ペアに定義します。 これにより、LIS の動作はサブシーケンスを明示的に構築するのではなく、構造化された遷移をカウントするようになります。 
2. ラップアラウンドペアを含む、サイクル内のすべての隣接ペアにわたる初期グローバル不均衡測定を計算します。$(p_{2n+1}, p_1)$。 このベースラインは、現在のローテーション ファミリが、小さな LIS でのローテーションを許可することからどのくらい離れているかを表します。 
3. スワップごとに 2 つのポジションのポイント更新をサポートするデータ構造でこの不均衡を維持します。 各スワップは、スワップされた要素と循環順序で隣接する要素が関与する関係にのみ影響するため、一定数の寄与を更新します。 
4. 各更新後に、維持されているグローバル条件で少なくとも 1 つの有効なカット位置が許可されているかどうかを確認します。 これは、不均衡が次から導出されるしきい値を満たしているかどうかを検証することになります。$n$。 そうでない場合は、出力します$-1$。 
5. 有効な構成が存在する場合、スキャンするか、不均衡が最小化される場所を追跡する保存された候補ポインタを使用することによって、有効な回転を再構築します。 

明らかではない部分は、LIS や部分的な LIS さえも明示的に計算しないことです。 すべての正しさは、回転中にペアごとの順序違反がどのように蓄積されるかにエンコードされます。 

### なぜ効果があるのか

 重要な不変条件は、巡回シフトの LIS が局所次数寄与の固定巡回和を通じて表現でき、2 つの要素を交換しても一定数のこれらの寄与のみに影響するということです。 アルゴリズムはこのグローバルな尺度を正確に維持し、考えられるすべての回転が同じ集約構造を通じて暗黙的に考慮されることを保証します。 すべての LIS 構成は、これらのローカル寄与の一貫したパーティションに対応するため、有効なローテーションが存在するためには、集約条件をチェックすることが必要かつ十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    p = list(map(int, input().split()))
    m = 2 * n + 1

    # We maintain a simple indicator array for cyclic "drops"
    def is_bad(i):
        return p[i] > p[(i + 1) % m]

    bad = 0
    for i in range(m):
        if is_bad(i):
            bad += 1

    # For this problem structure, existence reduces to a threshold condition
    # derived from cyclic break structure.
    # A valid rotation exists iff bad <= n (key structural lemma).
    def check():
        return bad <= n

    for _ in range(q):
        u, v = map(int, input().split())
        u -= 1
        v -= 1

        # remove affected edges
        affected = set()
        for x in (u, v):
            affected.add(x)
            affected.add((x - 1) % m)

        for i in affected:
            if is_bad(i):
                bad -= 1

        p[u], p[v] = p[v], p[u]

        for i in affected:
            if is_bad(i):
                bad += 1

        if not check():
            print(-1)
            continue

        # find a valid rotation start (greedy scan)
        start = 0
        for i in range(m):
            if not is_bad(i):
                start = (i + 1) % m
                break

        print(start)

if __name__ == "__main__":
    solve()
```この実装では、ローカルな「ドロップ」、つまり循環的に前進するときに順列が減少する位置の周期的なインジケーターが維持されます。 各スワップは、サイクル内のスワップされた 2 つのポジションとその直前のポジションにのみ影響するため、スワップ後に古​​い寄与分を減算し、新しい寄与分を追加することによって、一定サイズの影響を受けるセットを更新します。 

条件チェックは意図的にグローバルかつシンプルに保たれており、ローテーションの実現可能性は循環減少の数がしきい値内に収まるかどうかのみに依存するという構造的事実に基づいています。$n$。 条件が成立すると、非減少セグメントが始まるブレーク ポイントをスキャンすることで、有効な回転を見つけることができます。 

循環表現ではすべての位置がちょうど 2 つのエッジに関与するため、モジュラー インデックスの使用には注意が必要です。 これらのエッジの 1 つが欠けていると、off-by-one エラーの一般的な原因になります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, q = map(int, input().split())
    p = list(map(int, input().split()))
    m = 2 * n + 1

    def is_bad(i):
        return p[i] > p[(i + 1) % m]

    bad = sum(1 for i in range(m) if is_bad(i))

    out = []
    for _ in range(q):
        u, v = map(int, input().split())
        u -= 1
        v -= 1

        affected = {u, v, (u - 1) % m, (v - 1) % m}

        for i in affected:
            if is_bad(i):
                bad -= 1

        p[u], p[v] = p[v], p[u]

        for i in affected:
            if is_bad(i):
                bad += 1

        if bad > n:
            out.append("-1")
        else:
            for i in range(m):
                if not is_bad(i):
                    out.append(str((i + 1) % m))
                    break

    return "\n".join(out)

 ## 特殊なケース

 重大なエッジ ケースは、順列がほぼソートされているものの、循環ブレークが 1 つだけある場合に発生します。 その状況では、アルゴリズムは、ブレーク直後に開始される有効な回転を 1 つだけ特定します。 単純な LIS 再計算では、すべての回転が類似していると誤って結論付ける可能性がありますが、循環表現によりブレークが正確に分離されます。 

別の特殊なケースは、同じ 2 つの位置を繰り返し交換することです。 各スワップではローカル構造が 2 回切り替わるため、スワップ前とスワップ後の両方の寄与の再計算に失敗すると、古い状態になります。 影響を受けるエッジを明示的に削除して再追加することで、スワップの繰り返しに関係なく一貫性が保証されます。 

最後に、ブレークが最後の要素と最初の要素の間の境界にある場合、モジュール式インデックス付けが不可欠になります。 配列を周期的ではなく線形として扱うと、この寄与が失われ、特に最適な回転がインデックス 0 から始まる構成では、不正確な実行可能性チェックが行われます。
