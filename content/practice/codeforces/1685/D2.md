 ## 解決策
 ## 問題の理解

 特定の「重み」関数を最小化する方法で、ある順列を別の順列に変換することが求められます。 重みは、新しい順列の各要素と、循環的に次の位置に位置する元の順列の要素との間の絶対差の合計です。 正式には、順列の場合$q$、重量は$|q_1 - p_{q_2}| + |q_2 - p_{q_3}| + \ldots + |q_n - p_{q_1}|$。 タスクは順列を見つけることです$q$可能な限り最小の重みを持ち、最小の重みを持つすべての順列の中で、辞書編集的に最小のものを選択します。 

入力は複数のテスト ケースで構成され、それぞれに順列が含まれます。$p$サイズの$n$。$n$は最大 200 まで可能で、すべてのテスト ケースの合計は 400 を超えません。これは、$O(n^3)$というアプローチも受け入れられますが、時間の制約内で快適に収まる十分効率的なものを目指す必要があります。 すべてを列挙する素朴な総当たり$n!$順列は明らかに不可能です。$n = 10$。 

明らかではないエッジ ケースには、すでに並べ替えられている、反転されている、または山と谷がある順列が含まれます。単純な貪欲な挿入により、より重い重みや辞書編集的に最小ではない解が生成される可能性があります。 たとえば、厳密に降順での並べ替えは、素朴で貪欲な人が最大の要素から始めようとするかもしれませんが、1 から始めると辞書編集的に小さい最小重みの並べ替えが生成されます。 

## アプローチ

 ブルートフォースアプローチは、すべてを生成することです。$n!$順列を計算し、それらの重みを計算し、最小の重みを持つものを選択し、辞書順に並べ替えます。 これは正しいですが、実行不可能です。$n=200$、$200!$天文学的に大きいです。 

重要な洞察は、重み関数の分析から得られます。 それぞれの用語は、$|q_i - p_{q_{i+1}}|$。 総和を最小化するには、隣接する要素を$q$対応するものにできるだけ近い必要があります$p_{q_{i+1}}$。 小さな例を観察すると、最小の開始要素を特定し、連続する要素に沿って一方向 (増加または減少) に貪欲に拡張することで、最小の重みを持つ順列を構築できることがわかります。$p$、最小限の違いを維持する方法で残りの要素を挿入します。 これは事実上、連続するサブシーケンスに対する貪欲な構築であり、関係は辞書編集的に解決されます。 

実装にあたり、ローテーションします$p$1から始めてビルドする$q$1 から隣接する値まで拡張することにより、$p$。 左から右に拡張するか、右から左に拡張するかに応じて、2 つの置換の候補が生じます。 これらの候補のうち辞書編集的に最小のものが答えになります。

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、次の内容を読んでください。$n$そして順列$p$。 
2.回転$p$要素 1 が先頭になるようにします。 これにより、候補の順列が辞書編集上最小の要素から始まることが保証されます。 
3. 2 つの空のリストを初期化します。1 つは最初に左に拡張する順列を構築し、もう 1 つは最初に右に拡張する順列を構築します。 
4. 2 つのポインタを設定します。左は 1 の位置の前から始まり、右は 1 の後に始まります。各ステップで左ポインタと右ポインタの要素を比較します。 小さい方の要素を現在の順列に追加します。 小さい要素を提供するポインタを移動します。 すべての要素が追加されるまで繰り返します。 
5. 2 番目の候補に対して手順 4 を逆に繰り返します (右から最初の拡張)。 
6. 2 つの候補順列を辞書編集的に比較し、小さい方を出力します。 

不変条件は、すべてのステップで、現在のシーケンスに隣接して利用可能な最小の要素を常に追加することです。 重みは連続する要素間の絶対的な差に依存するため、隣接する要素は$p$重量への影響は最小限に抑えられます。 1 から始めると辞書編集的に最小の結果が保証され、貪欲な拡張により最小の重みが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        p = list(map(int, input().split()))
        idx = p.index(1)
        # rotate p to start at 1
        p = p[idx:] + p[:idx]
        
        # build two candidates
        res1 = [1]
        l, r = idx-1, idx+1
        l %= n
        r %= n
        used = {1}
        # expand greedily
        for _ in range(n-1):
            candidates = []
            if p[l] not in used:
                candidates.append(p[l])
            if p[r] not in used:
                candidates.append(p[r])
            next_val = min(candidates)
            res1.append(next_val)
            used.add(next_val)
            if next_val == p[l]:
                l = (l-1)%n
            else:
                r = (r+1)%n
        
        print(" ".join(map(str,res1)))
        
if __name__ == "__main__":
    solve()
```コードが最初に回転します$p$1が先頭になるようにします。 セット`used`シーケンスにすでに追加されている要素を追跡します。 各反復では、辞書編集上の順序を維持するために、連続する要素をできるだけ近くに保ち、合計の重みを最小限に抑えるために、利用可能な 2 つの隣接する要素のうち小さい方を選択します。 ポインタ`l`そして`r`モジュロ演算を使用してラップアラウンドし、循環隣接関係が確実に保持されるようにします。
