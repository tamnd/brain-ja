 ## 解決策
 ## 問題の理解

 シェリーが到着する前に、私たちは人の列を与えられました。 これらの人々はそれぞれ、ピザのスライス、タコス、ソースで構成される共有プールから食べ物を摂取できます。 ピザまたはタコスのいずれかを 1 人につき 2 品まで自由に取ることができます。 さらに、ソースを 2 つだけ摂取することを選択した場合は、自分が選んだ追加のアイテムが 1 つ追加で与えられます。 

質問はキューの固定された動作に関するものではなく、可能性に関するものです。 シェリーの前にいる人々が、順番が来る前にピザのスライスをすべて食べるか、タコスをすべて食べるかのどちらかを選択できる何らかの方法が存在するかどうかを判断する必要があります。 

重要な点は、私たちが最悪の消費について推論しているということです。シェリーが到着する前にピザもタコスも完全に使い果たされることがないことを保証するのに十分なリソースがあるかどうかを尋ねているのです。 

この制約により、最大 100,000 人の人々と、各リソースの最大 100,000 単位が許可されます。 原則として各人は複数の組み合わせによる決定を行う可能性があるため、人ごとに選択肢を列挙しようとする単純なシミュレーションでは時間がかかりすぎます。 どのアプローチでも、個々の決定をシミュレートするのではなく、問題を可能な限り最大の消費量をカウントすることに帰着させる必要があります。 

ソースからは微妙なエッジケースが生じます。 素朴な読者は、各人が独立して追加のアイテムを摂取できると考えるかもしれませんが、追加のアイテムはソースの共有リソースによって制限されています。 これにより、人々の間につながりが生まれます。追加のアイテムは、人ごとではなく、ソースの合計によってグローバルに制限されます。 

たとえば、人が多いのにソースが 1 つまたは 2 つしかない場合、列に並んでいる人数に関係なく、余分なアイテムは少数しか表示されません。 これを無視すると、消費容量を過大評価することになります。 

もう 1 つの特殊なケースは、ソースが豊富にある場合です。 そうすれば、各人は効果的に 3 つのアイテムを摂取できますが、それは追加の変換ごとに十分なソースが存在する場合に限られます。 

## アプローチ

 この問題を考える強引な方法は、n 人それぞれをシミュレートし、考えられるすべての選択肢を試すことです。ピザやタコスの中から 0、1、または 2 つの食品を選択し、場合によってはソースを追加の項目に変換することもできます。 構成ごとに、残りのピザとタコスを追跡し、Shelly に到達する前にどちらかがゼロに達するかどうかを確認します。 

このアプローチは、すべての有効な一連の意思決定を調査するため、概念的には正しいです。 ただし、人ごとの分岐要素により、それは実行不可能になります。 各人には複数の選択肢があり、その組み合わせの数は n に応じて指数関数的に増加します。 単純化されたシミュレーションでもシナリオあたり O(n) ですが、シナリオの数は n で組み合わせられており、制限をはるかに超えています。 

重要な観察は、個人間の分布は気にせず、シェリーが到着するまでに消費できるアイテムの総数だけを気にするということです。 各人は最大 2 つの必須項目を提供しますが、ソースが許可する場合は 1 つの追加項目を提供する可能性があります。 すべてのアイテムは枯渇に関して交換可能であるため (ピザまたはタコス)、特定のリソースが枯渇する最悪のケースは、すべてのアイテムがそのリソースに割り当てられている場合です。 

したがって、問題は、全体的なソース制約を考慮して、n 人が集合的に摂取できるアイテムの最大合計数を計算し、その合計がピザまたはタコスのいずれかを使い果たすのに十分な大きさであるかどうかを確認することに帰着します。 

各追加アイテムには正確に 2 つのソースが必要であるため、追加アイテムの総数は人数とソースのペアの数の両方によって制限されます。

 ## アルゴリズムのチュートリアル

1. ソースから生成できる追加アイテムの数を計算します。 各追加アイテムは正確に 2 つのソースを消費するため、追加アイテムの最大数は Z // 2 です。これは厳しいグローバル制限です。 
2. 各人が追加アイテムを最大 1 つまで寄付できるため、人数 n によって追加アイテムをさらに制限します。 
3. 消費される合計最大アイテム数を 2n に追加アイテムの数を加えたものとして計算します。 値 2n は、すべての人々に保証される最大基本消費量を表します。 
4. この合計を利用可能な供給品と比較します。 総容量が少なくとも X 枚のピザの場合、すべての消費量をピザに割り当て、シェリーが到着する前に使い果たす方法が存在します。 
5. 同様に、総容量が少なくとも Y タコスであれば、タコスを使い果たすことができます。 
6. いずれかの条件が成立する場合は「yes」を出力し、そうでない場合は「no」を出力します。 

### なぜ効果があるのか

 重要な不変条件は、人によるすべての行動は、取得したアイテムごとに最大 1 単位の消費に寄与し、各アイテムはどのリソースを消費するかについて区別できないということです。 少なくとも 1 つのリソースが完全に枯渇する可能性があるかどうかだけをチェックしているため、敵対的戦略では常に、利用可能なすべてのアイテム スロットを 1 つのリソース タイプに割り当てることができます。 したがって、単一リソースの最大消費可能量は、すべての人々が利用できるアイテム スロットの合計数に、2n に可能なすべての追加アイテムを加えたものとなります。 この最大値がリソースの合計に達しない場合、有効な割り当てによってそのリソースが使い果たされることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    X, Y, Z = map(int, input().split())

    extra = min(n, Z // 2)
    total = 2 * n + extra

    if total >= max(X, Y):
        print("yes")
    else:
        print("no")

if __name__ == "__main__":
    solve()
```実装では、Shelly が到着する前に消費できるアイテムの最大数を直接計算します。 ライン`extra = min(n, Z // 2)`ソースの使用に関して両方の制約を強制します。各追加アイテムは 2 つのソースを消費し、各人がそのようなボーナスをトリガーできるのは 1 つだけです。 

値`total = 2 * n + extra`世界の消費能力を表します。 最終的な比較では、`max(X, Y)`なぜなら、ピザまたはタコスのいずれかを使い果たせば「はい」の結果が得られ、両方のリソースは同じ最悪の場合の割り当て容量を共有するからです。 

よくある間違いは、ソースを各人が独立して利用できるものとして扱うことです。`Z // 2`なしで`min(n, ...)`キャップ。 もう 1 つは、可能性をチェックするときに、同じ合計容量が 1 つのリソースに完全に集中する可能性があることを忘れることです。

 ## 特殊なケース

 重要なエッジケースの 1 つは、ソースがない場合です。 その場合、追加のアイテムは生成できないため、システムは厳密な 2n 容量モデルに崩壊します。 入力用`n = 5, X = 20, Y = 3, Z = 0`、合計 = 10 が得られます。ピザは使い果たされる可能性がありますが、タコスは使い果たされないため、少なくとも 1 つのリソースが到達可能であるため、答えは依然として「はい」です。 

もう 1 つのエッジケースは、ソースは豊富だが人が少ない場合です。 のために`n = 1, Z = 100, X = 5, Y = 5`、 元
