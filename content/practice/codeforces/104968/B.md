 ## 解決策
 ## 問題の理解

 私たちにはピザの山が与えられ、各ピザは同じ 8 つのスライスにカットされます。 と$n$ピザの場合、スライスの総数は固定されています$8n$。 これらのスライスは次のグループに分散する必要があります。$m$友達。 

分布には同時に 2 つの制約があります。 すべての友人はまったく同じ数のスライスを受け取る必要があり、その数は少なくとも$k$。 他の人よりも少ないスライスを誰かに残すことは許可されません。また、満足度の最小しきい値を下回る正の数のスライスを誰かに与えることも許可されません。 

したがって、問題は、ピザの総量を均等に分割できるかどうかを確認することになります。$m$同一の部分、および各部分が十分に大きいかどうか。 

制約の観点から見ると、$n$と同じ大きさにすることができます$10^5$、スライスの合計数は次のとおりです。$8 \cdot 10^5$。 友達の数はせいぜい100人と少ないです。 スライスごとに分散をシミュレートしたり、可能な割り当てを検索しようとしたりするソリューションは、複雑さという点では依然として些細なものですが、その必要はありません。 問題の構造は、定数時間の算術チェックで十分であることを強く示唆しています。 

ここでの単純な間違いは、割り算の要件を無視し、1 人あたりの平均スライス数が次を超えているかどうかだけをチェックすることです。$k$。 たとえば、次の場合$n = 2$、$m = 3$、$k = 1$、スライスの合計は 16 となり、$16/3 \ge 1$数値的には成り立ちますが、16 は 3 で割り切れないため、割り算は不可能です。正しい出力は false です。 

もう 1 つのよくある間違いは、割り算だけをチェックして、最小要件を忘れることです。 たとえば、次の場合$n = 1$、$m = 4$、$k = 3$の場合、スライスの合計は 8 で、4 で割り切れるので 1 人あたり 2 になりますが、2 は最小要件を下回っているため、失敗するはずです。 

これら 2 つの制約は同時に適用する必要があります。 

## アプローチ

 この問題を考える最も直接的な方法は、実際にスライスを分散することを想像することです。 各友人へのスライスの可能なすべての割り当てを反復して、各友人が少なくとも受信できるようにすることができます。$k$、有効な均等パーティションが存在するかどうかを確認します。 ただし、スライスは同一であり、カウントのみが重要であるため、これはすぐに組み合わせ割り当ての問題ではなく、カウントの問題に陥ります。 

たとえ強引な構築を試みたとしても、本質的には分割しようとすることになります。$8n$の中へ$m$等しい整数、それぞれ少なくとも$k$。 各友人の唯一の意味のある候補値は平均値です。$x = \frac{8n}{m}$、この分割が正確であれば。 除算が正確でない場合は、列挙しても修正できません。 正確であれば、残る唯一のチェックは、$x \ge k$。 

重要な観察は、有効な分布の構造が算術制約によって完全に決定されるということです。 平等が強制されると柔軟性はなくなります。各友人は正確に受け取る必要があります。$x$したがって、実現可能性は、そのような整数かどうかをチェックすることになります。$x$が存在し、下限を満たします。 

これにより、問題が指数関数的探索または組み合わせ探索から定数時間の計算に軽減されます。

 ## アルゴリズムのチュートリアル

 1. スライスの総数を次のように計算します。$total = 8 \cdot n$。 これは、残りを残さずに分割する必要がある完全なリソース プールを表します。 
2. かどうかを確認します。$total$で割り切れます$m$。 割り切れない場合、少なくとも 1 人の友人が必然的に異なる数のスライスを受け取ることになるため、均等に分割することは不可能です。 
3. 割り切れる場合は、1 人あたりの割り当てを計算します$x = total / m$。 この値は強制的なものであり、等価制約の下では代替の有効な分布はありません。 
4. かどうかを確認します。$x \ge k$。 これにより、すべての友人が同時に満足度の最低要件を満たすことが保証されます。 
5. 両方の条件が当てはまる場合にのみ true を返し、それ以外の場合は false を返します。 

### なぜ効果があるのか

 均等配分を強制すると、すべての有効な解にはまったく同じ整数を割り当てる必要があります。$x$それぞれの友達に。 つまり、合計額は完全に次のように決定されます。$m \cdot x$したがって、実現可能性は完全に次のいずれかに依存します。$8n$という形で表現できます。 可分性チェックは構造の実現可能性を保証し、不等式チェックは最小制約を強制します。 この 1 つの候補値以外には他の構成は存在しないため、決定は完了します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    m = int(input().strip())
    k = int(input().strip())

    total = 8 * n

    if total % m != 0:
        print("FALSE")
        return

    each = total // m

    if each >= k:
        print("TRUE")
    else:
        print("FALSE")

if __name__ == "__main__":
    solve()
```実装は派生を正確に反映します。 掛け算$8 * n$は定数時間で実行され、Python の整数内に安全に収まります。 割り算チェックが最初に行われるのは、存在しない個人ごとの割り当てについての計算や推論が回避されるからです。 分割が有効な場合にのみ計算します$each$、これは友達ごとの強制割り当てを表します。 

最終的な比較では、最小要件が適用されます。 等価性によってすべての柔軟性が失われるため、部分的な割り当てを伴う例外的なケースはありません。

import sys, io
from contextlib import redirect_stdout

def solve():
    import sys
    input = sys.stdin.readline

    n = int(input().strip())
    m = int(input().strip())
    k = int(input().strip())

    total = 8 * n

    if total % m != 0:
        print("FALSE")
        return

    each = total // m

    if each >= k:
        print("TRUE")
    else:
        print("FALSE")

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    with redirect_stdout(out):
        solve()
    return out.getvalue().strip()

# provided samples (interpreted as 1 4 3 and 1 4 2)
assert run("1\n4\n3\n") == "FALSE", "sample 1"

assert run("1\n1\n8\n") == "TRUE", "single friend gets all slices"

# impossible divisibility
assert run("2\n3\n1\n") == "FALSE", "not divisible by m"

assert run("3\n2\n12\n") == "FALSE", "exact split but below k"

 ## 特殊なケース

 エッジケースの 1 つは、友人が 1 人しかいない場合です。 入力用$n = 1, m = 1, k = 8$、合計スライスは 8、割り算が成り立ち、各友達は 8 を取得します。アルゴリズムは計算します。$each = 8$しきい値チェックに合格し、TRUE が生成されます。 これにより、ロジックが自明なパーティションを正しく処理していることが確認されます。 

もう 1 つのエッジケースは、合計が友人の数で割り切れない場合です。 のために$n = 2, m = 3, k = 1$、合計は 16 です。 16 % 3 はゼロではないため、アルゴリズムはこのケースを即座に拒否します。 これにより、部分割り当てに関する誤った推論が回避されます。 

最後のケースは、割り切れるが最小制約が満たされない場合です。 のために$n = 1, m = 4, k = 3$、合計は 8、それぞれが 2 であり、しきい値チェックは失敗します。 これは、アルゴリズムが分割の実現可能性と満足制約を混同しないことを確認します。
