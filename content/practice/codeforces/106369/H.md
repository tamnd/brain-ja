 ## 解決策
 ## 問題の理解

 ゲームは以下の数字を並べ替えることから始まります。`1`に`n`。 2 人のプレーヤーが、まだ正しくない 2 つのポジションを繰り返し選択し、それらのポジションの値を交換します。 独自の位置に到達した値はロックされ、その後のスワップに参加できなくなります。 最終的に全体の順列をソートするスワップを実行したプレイヤーが勝ちます。 スモーキン・ジョーが先に動く。 

入力には、順列のサイズと値の現在の配置が含まれます。 出力では、両方のプレーヤーが勝つ可能性を最大化する手を選択すると仮定して、どちらのプレーヤーが勝利戦略を持っているかが尋ねられます。 

主な制約は、`n`到達できる`10^6`。 これにより、シミュレーション、状態に対する動的プログラミング、または可能な動きを探ろうとするアプローチが即座に除外されます。 可能な順列の数は膨大であるため、解では開始順列の数学的特性を抽出し、それを線形時間で計算する必要があります。 

難しいのは、プレイヤーが順列をすぐに改善しない交換を行うことが許可されていることです。 ソートに必要な最小限のスワップ数のみをカウントするソリューションでは十分ではありません。 たとえば、順列```
3
2 3 1
```2 回のスワップでソートできるため、不用意なアプローチをすると 2 番目のプレーヤーが勝ちになる可能性があります。 しかし、本当の理由はもっと深いです。ソートされた順列で終了するすべての有効なゲームは、同じ手の動きを持っています。 ここではスワップの最小数が偶然そのパリティと一致しますが、証明では考えられるすべての選択肢を考慮する必要があります。 

もう 1 つのエッジ ケースは、複数の独立したサイクルで構成される順列です。 例えば：```
4
4 3 2 1
```正しい出力は次のとおりです。```
Oh No!
```並べ替えは、通常の意味での並べ替えから 2 回スワップします。 順列の合計パリティは偶数であるため、ソートされた状態に到達するために必要な手の数も偶数でなければなりません。これは、2 番目のプレーヤーが最後の手を取得することを意味します。 

最後によくある間違いは、すでに正しい位置を誤って処理することです。 考慮する：```
3
1 3 2
```最初の位置はすでに固定されており、タッチすることはできません。 残りの 2 つのポジションは 1 つのスワップを形成するため、答えは次のようになります。```
Smokin Joe!
```すべてのポジションを利用可能としてカウントする実装は、実際のルールを反映しません。 

## アプローチ

 直接的なアプローチは、決闘そのものをモデル化することです。 現在の順列から、移動可能な位置間のあらゆる可能なスワップを生成し、結果として生じるすべての状態を再帰的に解決し、現在のプレイヤーが強制的に勝利できる状態をマークすることができます。 これはゲームのルールに正確に従っているため、これは正しいです。 

問題は州の数です。 長さの順列`n`持つことができる`n!`さまざまな配置があり、単一の状態でも多くのスワップが発生する可能性があります。 のために`n = 10^6`、すべての可能なスワップを一度確認することさえすでに不可能です。 

重要な観察は、順列パリティを調べることから得られます。 スワップごとに、順列のパリティが変更されます。 ソートされた順列は恒等順列であり、常に偶数パリティを持ちます。 したがって、最初の順列のパリティが奇数の場合、ソート状態に到達するすべてのパスには奇数の移動が含まれている必要があります。 偶数パリティの場合、すべてのパスに偶数の移動が含まれている必要があります。 

ロック ルールによってこの引数は変更されません。 ロックされた要素は、現在の順列の単なる固定点です。 すべての正当な手は、現在移動可能な 2 つの位置の転置であるため、パリティが反転します。 ゲームは恒等順列で終了する必要があるため、手数のパリティは最初の手の前にすでに決定されています。 

手数が奇数でなければならない場合は、最初のプレイヤーが最後の手を行います。 平等でなければならない場合は、2 番目のプレーヤーが平等になります。 

順列のパリティは、そのサイクル分解から見つけることができます。 長さのサイクル`k`貢献する`k - 1`パリティにスワップするため、合計パリティは次のようになります。```
(n - number_of_cycles) mod 2
```サイクルを見つけるには直線的な時間がかかります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n! * n) | お(ん!) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 順列をたどって、それに含まれるサイクルの数を数えます。 未訪問の位置から開始し、訪問した位置に戻るまで、そこに保存されている値を繰り返したどります。 すべての訪問位置を一度マークすると、すべてのサイクルが線形時間で表示されます。 
2. コンピューティング`n - cycles`。 各サイクルの長さ`k`必要`k - 1`転置して固定小数点に分割するため、すべてのサイクルにわたってこれらの値を合計すると、置換符号の指数が得られます。 
3. その値のパリティをチェックします。 奇数の値は、開始順列のパリティが奇数であることを意味するため、すべての有効なゲームには奇数のスワップがあり、スモーキン ジョーが最後の動きをします。 
4. 値が偶数の場合、すべての有効なゲームには偶数のスワップがあり、The Outlaw が最後の動きをします。 

なぜ効果があるのか:

 不変式は順列のパリティです。 すべての転置は順列の符号を反転するため、スワップでは常にこのパリティが変更されます。 唯一の最終状態はソートされた順列であり、そのパリティは偶数です。 したがって、完了した決闘中に行われたスワップ数のパリティは、順列の初期パリティと正確に一致する必要があります。 プレーヤーは、その長さのパリティではなく、どの有効なシーケンスを再生するかを決定するだけであるため、勝者は完全に最初の並べ替えによって決まります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    p = list(map(int, input().split()))

    visited = [False] * n
    cycles = 0

    for i in range(n):
        if not visited[i]:
            cycles += 1
            cur = i
            while not visited[cur]:
                visited[cur] = True
                cur = p[cur] - 1

    if (n - cycles) & 1:
        print("Smokin Joe!")
    else:
        print("Oh No!")

if __name__ == "__main__":
    solve()
```配列は 0 から始まるインデックスを使用して保存されるため、値は`p[cur]`に変換されます`p[cur] - 1`サイクルに従うとき。 必要な情報はサイクル数のみであるため、順列を変更したり、スワップをシミュレートしたりする必要はありません。 

の`visited`配列は、同じサイクルを繰り返し実行することを防ぎます。 各位置は 1 回だけ入力されるため、最大入力サイズであってもトラバースは線形のままです。 

最終条件では次のパリティが使用されます。`n - cycles`。 この量は大きくなる可能性がありますが、Python 整数は安全に処理します。 最下位ビットのみが重要なので、次のようにチェックします。`& 1`不必要な作業を回避します。

## テストケース```python
import sys
import io

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    n = int(sys.stdin.readline())
    p = list(map(int, sys.stdin.readline().split()))

    visited = [False] * n
    cycles = 0

    for i in range(n):
        if not visited[i]:
            cycles += 1
            cur = i
            while not visited[cur]:
                visited[cur] = True
                cur = p[cur] - 1

    ans = "Smokin Joe!\n" if (n - cycles) & 1 else "Oh No!\n"

    sys.stdin = old_stdin
    return ans

assert run("""3
1 3 2
""") == "Smokin Joe!\n", "sample 1"

assert run("""4
4 3 2 1
""") == "Oh No!\n", "sample 2"

assert run("""2
2 1
""") == "Smokin Joe!\n", "single swap"

assert run("""5
1 2 3 5 4
""") == "Smokin Joe!\n", "fixed positions"

assert run("""6
2 1 4 3 6 5
""") == "Oh No!\n", "three independent swaps"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`2 / 2 1`|`Smokin Joe!`| 最小の自明でないサイクル |
 |`5 / 1 2 3 5 4`|`Smokin Joe!`| すでに位置が固定されています |
 |`6 / 2 1 4 3 6 5`|`Oh No!`| 合計パリティが偶数の複数の偶数サイクル |

 ## 特殊なケース

 入力用```
3
1 3 2
```最初の位置はすでに正しいので、唯一のアクティブなサイクルは位置 2 と 3 の間の交換です。 アルゴリズムは合計 2 つのサイクルを見つけて、`3 - 2 = 1`、奇数の手を予測します。 最初のプレイヤーが勝ちます。 

入力用```
4
4 3 2 1
```順列には、長さ 2 の 2 つの別個のサイクルが含まれます。 各サイクルはスワップ パリティに 1 つ寄与し、合計 2 つになります。 アルゴリズムは偶数の値を計算します。これは、最後の手が 2 番目のプレーヤーに属することを意味します。 

多くの固定点を含むすでにほぼソートされた順列の場合、次のようになります。```
5
1 2 3 5 4
```各固定位置は単純に長さ 1 のサイクルであるため、サイクル トラバースでは固定位置は自然に無視されます。 非自明なスワップのみがパリティ計算に影響を与えるため、答えは正しいままです。
