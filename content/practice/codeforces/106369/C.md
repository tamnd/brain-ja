 ## 解決策
 ## 問題の理解

 このタスクでは、位置の行で段階的に進化する小さなシステムについて説明します。各位置には、最初にスタック サイズを表す整数値が保持されます。 行は、隣接する要素間のローカルな相互作用によって繰り返し変更されるシーケンスのように動作します。 

シーケンスが非減少順でない限り、各ステップで、左側の値が右側の値より厳密に大きい隣接する位置のペアを見つけます。 このようなペアが選択されると、2 つの要素の位置が交換され、交換直後に、新しい右側の要素が加算によって新しい左側の要素の値を吸収します。 これは、すべての操作で順序が変更されるだけでなく、交換された要素からの情報が指示された方法でマージされることを意味します。 

出力は、有効な操作を適用できなくなった後のシーケンスの最終状態です。つまり、配列はプロセス制約の下で非降順でソートされます。 

このステートメントはローカル スワップ ルールのように見えますが、蓄積が存在するため、進化は自明ではなくなります。 値は単に移動するだけではなく、より小さな要素を通過するときに増加します。 

複雑さの観点から見ると、各ステップを個別に処理する場合、シーケンスの長さが十分に大きくなり、スワップを直接シミュレートすることが不可能になる可能性があります。 単純なシミュレーションでは、繰り返しスキャンして隣接するスワップを実行する必要があり、存在する反転の数に応じて二次関数またはさらに悪い動作が発生する可能性があります。 これは、意図したソリューションが、ローカル スワップを 1 つずつ実行するのではなく、繰り返されるローカル スワップの全体的な影響について推論する必要があることを直ちに示唆しています。 

大きな値が小さな値で囲まれている場合、微妙なエッジケースが発生します。 たとえば、次のような配列を考えてみましょう。`[5, 1, 2, 3]`。 素朴なアプローチは動くかもしれない`5`ステップごとに右に移動しますが、交換するたびに隣接する値も増加し、その後の比較が変化します。 もう一つのケースは、`[2, 1, 3]`ここで、最初のスワップは累積を通じて間接的に 3 番目の要素を変更します。これは、最終結果が単に合計のソートされた並べ替えではなく、相互作用の順序に依存することを意味します。 

これらの例は、各操作が将来の有効な動きに影響を与える方法で値を永続的に変更するため、スワップを独立した反転として扱うのは正しくないことを示しています。 

## アプローチ

 ブルートフォース手法では、説明どおりにプロセスを直接シミュレートします。 配列を左から右に繰り返しスキャンし、インデックスを見つけます`i`そのような`a[i] > a[i+1]`、交換を実行し、新しい左の値を新しい右の値に追加します。 各操作により反転の数が減少しますが、値自体が変化するため、必ずしも予測可能な量だけ減少するとは限りません。 

最悪の場合、各スワップは大きな要素を一度に 1 位置ずつ移動するだけであり、移動のたびに値をカスケード的に更新する必要がある場合があります。 と`n`要素は最大で`O(n^2)`スワップ、およびアレイの各パスのコスト`O(n)`、につながる`O(n^3)`単純な実装での動作。 最適化を行ったとしても、配列の再スキャンが繰り返されるため、このアプローチは大きな入力には使用できなくなります。 

重要な観察は、プロセスが常に大きな要素を右に移動し、小さな要素が通過するときに、それらの小さな要素が移動する値に効果的に吸収されることです。 これは、最終的な構成は、スワップの正確な順序ではなく、各要素が追い越す要素からの寄与をどのように蓄積するかに依存することを示唆しています。 

スワップをシミュレートする代わりに、各要素が最終的に、元はその右側にあったすべての小さな要素を、安定する前に収集するというプロセスを解釈できます。 これにより、問題は、位置ごとに、最終的にソートされた位置に到達したときに生じる寄与の合計を計算するように変換されます。 並べ替えプロセス自体は重要ではなくなります。 蓄積構造のみが重要です。 

これにより、構造化された方法で解決される反転の貪欲またはスタックベースの解釈を使用して、値がどのように伝播および結合するかを追跡し、各要素が 1 回処理されるようにする効率的なソリューションが得られます。

 ## アルゴリズムのチュートリアル

 右側の小さな要素によって「ブロック」されている要素は、最終的には 1 つの有効な値にマージされるという考えを維持しながら、配列を処理します。 

1. 配列を左から右に繰り返し、各要素を前のブロックを吸収する可能性のある「最終ブロック」として扱います。 

この方向が選択されるのは、マージではスワップ中に常に値が右方向に転送されるため、右方向の処理は最終的な累積を自然に反映するためです。 
2. 以前のすべてのローカル違反を解決した後、現在の有効なシーケンスを表す構造を維持します。 格納された各値は、以前の要素から必要なものすべてをすでに吸収したブロックを表します。 
3. 新しい要素ごとに、それをこの構造の最後のブロックと比較します。 最後のブロックが現在の要素より大きい場合は、元のプロセスでスワップとマージが発生することを意味するため、値を追加して単一のブロックにマージします。 

このステップでは、複数のスワップ操作を 1 つの算術更新に圧縮します。これは、同じ領域のペア間でスワップを繰り返すと、解決後に相対的な順序が変更されずに値が蓄積されるだけであるためです。 
4. 単一の要素が前の複数のブロックをカスケードする可能性があるため、最後のブロックが現在の要素より大きい限りマージを繰り返します。 
5. マージが不可能になったら、現在の要素を新しい独立したブロックとして追加します。 

すべての要素を処理した後、構造にはすべての暗黙のスワップとマージ後の最終状態が含まれます。 

### なぜ効果があるのか

 重要な不変条件は、維持される構造が、変換されたルールの下で、隣接するペアが非減少条件に違反しない状態を常に表すということです。 2 つのブロックをマージするたびに、累積された追加を含め、元のプロセスでそれらのセグメント間で発生したすべてのスワップの影響を正確にシミュレートします。 マージでは常に 1 つの反転が削除され、左側に新しい反転が作成されることはないため、各要素は 1 回だけファイナライズされ、その累積値は、すべての有効なスワップ操作が終了した後の値と一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    a = list(map(int, input().split()))

    stack = []

    for x in a:
        while stack and stack[-1] > x:
            x += stack.pop()
        stack.append(x)

    print(*stack)

if __name__ == "__main__":
    solve()
```このソリューションでは、スタックを使用して配列の現在の圧縮状態を表します。 受信した各要素は、前のブロックに追加されるか、前のブロックにマージされます。 1 回のマージで以前の要素との新しい違反が明らかになる可能性があるため、while ループが不可欠であるため、安定するまで解決を続けます。 

よくある間違いは、要素ごとにマージを 1 回だけ実行することです。これは、次のようなチェーンで失敗します。`5, 4, 3, 2`すべての値を正しく累積するには、完全なカスケード マージが必要です。 

最後の出力では、すべてのスワップおよびマージ操作が完了した後の配列に対応する、安定化されたシーケンスが出力されます。

 | 測定 | 複雑さ | 説明 |

 ## 特殊なケース

 次のような単一要素入力の場合`1\n7`、スタック ロジックは 1 回追加され、すぐに終了し、`7`、スワップが不可能であるという事実と一致します。 

次のような厳密に減少するシーケンスの場合、`5 4 3 2 1`、すべての新しい要素は前のスタックへの完全な折りたたみをトリガーし、値が 1 つだけ残るまでマージを繰り返します。 これを追跡すると、各プレフィックスを処理した後、スタックにはマージ ルールに基づく隣接反転のない完全に解決された状態が含まれているため、最終出力はすべての要素の合計になるという不変条件が示されます。 

次のようなほぼソートされたシーケンスの場合`1 2 100 3 4`、大きい値`100`右側の小さな値に遭遇するまでは安定しており、そこでそれらの値が順番に吸収されます。 スタックは、`100`と合併する`3`、さらにマージをトリガーする可能性があります`2`または`1`順序によって異なりますが、各要素は依然として 1 回だけ処理され、正確性を維持しながら局所的な不規則性を効率的に処理します。
