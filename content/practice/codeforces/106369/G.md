 ## 解決策
 # 問題の理解

 この問題では、コンドミニアムのユニットを`r`による`c`長方形のグリッド。 コンドミニアムは 1 つのグリッド正方形を占め、2 つのコンドミニアムを互いに接する正方形に配置することはできません。 タッチには、水平方向、垂直方向、斜め方向の隣接方向の 8 方向すべてが含まれます。 

タスクは、異なる有効な配置セットがいくつ存在するかを数えることです。 少なくとも 1 つの正方形に一方の配置にコンドミニアムが含まれているが、もう一方の配置には含まれていない場合、2 つの配置は異なります。 空の配置も有効です。 答えは非常に大きくなる可能性があるため、モジュロで出力する必要があります`10^9 + 7`。 

入力には、グリッドの行数と列数の 2 つの整数のみが含まれます。 行の数は多くても 10 と少ないですが、列の数は 1000 に達する場合があります。この非対称性が主な手がかりです。 行数に指数関数的に依存する解決策は実用的ですが、列数に指数関数的に依存する解決策は不可能です。 1000 列のグリッドは、すべての列の選択肢を試しても処理できないため、一度に 1 列ずつグリッドを処理する必要があります。 

限界について考えるのに役立つ方法`r <= 10`1 つの列には`2^r`考えられる占有パターン。 10 行の場合、これはわずか 1024 マスクであり、垂直方向に隣接するコンドミニアムの無効なマスクを削除すると、その数はさらに小さくなります。 これにより、状態圧縮アプローチが実現可能になります。 すべての正方形を単純に検索すると、`2^(r*c)`その可能性は、たとえ小さなグリッドであっても天文学的に大きくなります。 

厄介なケースは、ほとんどの場合、禁止された近隣方向の 1 つを忘れたことが原因で発生します。 

たとえば、1 つの列に 2 つの行があるとします。```
Input:
2 1
```正しい出力は次のとおりです。```
3
```可能な配置は、空、上部の正方形が占有されている、または下部の正方形が占有されているです。 水平方向の競合のみをチェックする不注意な解決策では、占有されている両方のマス目がカウントされ、誤って 4 が返される可能性があります。 

もう 1 つのよくある間違いは、斜めの競合を無視することです。 例えば：```
Input:
2 2
```正しい出力は次のとおりです。```
5
```2 x 2 のグリッド内のすべての正方形のペアが接しているため、空ではない有効な配置だけが 1 つのコンドミニアムを含みます。 隣り合ったものと垂直方向に隣接したものだけを防止するソリューションでは、誤って対角線のペアが許可されてしまいます。 

最小のグリッドにも注意が必要です。```
Input:
1 1
```正しい出力は次のとおりです。```
2
```可能性は 2 つあります。何も建てないか、コンドミニアムを 1 つ建てるかです。 動的プログラミング配列を誤って初期化する実装では、誤ってゼロを返す可能性があります。 

# アプローチ

 直接的なアプローチは、すべての広場を独立して検討し、そこにコンドミニアムを配置するかどうかを決定することです。 グリッドの場合`r * c`正方形、これは`2^(r*c)`可能な取り決め。 このメソッドは、考えられるすべての配置セットを調べて有効なものだけを保持するため、論理的には正しいですが、すぐに使用できなくなります。 10 行 20 列しかないグリッドでも、すでに`2^200`可能性。 

ブルートフォースが失敗する理由は、グリッドに構造がないからではありません。 重要な観察は、列間の相互作用が制限されていることです。 1 つの列の内容を決定するときに、前の列に関して必要な情報は、前の列の占有パターンだけです。 歴史全体を思い出す必要はありません。 

列はビットマスクとして表すことができます。 少し`i`行が 1 である場合`i`その列にはマンションが含まれています。 まず、2 つの隣接するセット ビットを持つマスクは、同じ列内で垂直に接触しているコンドミニアムを表すため、破棄します。 

次に、列を左から右に処理します。 連続する列マスクのすべてのペアについて、それらが競合するかどうかを確認します。 コンドミニアムが同じ行、1 つ上の行、または 1 つ下の隣の列に表示される場合、2 つの列は競合します。 それらが矛盾しない場合、2 つの列は有効な配置で連続して表示できます。 

すべての完全な配置は一連の列選択であるため、総当り攻撃が機能します。 シーケンスの数が膨大なため失敗します。 隣接する列のみが互いに影響を与えるという観察により、完全な履歴を小さな動的プログラミング状態に置き換えることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^(r*c)) | O(r*c) | 遅すぎる |
 | 最適 | O(c * S^2) | O(S) | 承認済み |

 ここ、`S`有効な列マスクの数です。 のために`r = 10`、`S`たったの144です。 

# アルゴリズムのチュートリアル

 1. 考えられるすべての列マスクを次から生成します。`0`に`2^r - 1`。 隣接する 2 つの行が両方とも占有されていないマスクのみを保持します。 1 つの列内では垂直方向の接触が禁止されているため、これらは 1 つの列で可能な唯一の状態です。 
2. 有効なマスクのどのペアを隣り合わせて配置できるかを事前に計算します。 2 つのマスクは、共通の占有行がなく、1 位置ずつシフトされた占有行がない場合に互換性があります。 シフトは、隣接する列間の対角線の接触を表します。 
3. 最初の列のすべての有効なマスクの動的プログラミング値を次のように初期化します。`1`。 各マスクは、可能な 1 つの最初の列の配置を表します。 
4. 残りの列を 1 つずつ処理します。 現在の列マスクごとに、前の列の互換性のあるすべてのマスクからその列マスクに到達する方法の数を追加します。 今後のすべての競合には現在の最後の列のみが関係するため、以前の列は重要ではなくなります。 
5. 最後の列の後のすべての動的プログラミング値を合計します。 考えられるすべての最終的な列状態は、完全に有効なグリッド配置を表します。 

これが機能する理由: 不変条件は、任意の数の列を処理した後、`dp[mask]`最後の列が占有パターンと正確に一致する、処理された列の有効な配置の数に等しい`mask`。 トランジションでは、接触ルールに違反しない列のペアのみが許可されるため、無効な配置が作成されることはありません。 すべての有効な配置には列マスクの一意のシーケンスがあり、そのシーケンス内の各遷移が考慮されるため、すべての有効な配置は 1 回だけカウントされます。 

# Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10 ** 9 + 7

def solve():
    r, c = map(int, input().split())

    masks = []
    for mask in range(1 << r):
        if (mask & (mask << 1)) == 0:
            masks.append(mask)

    n = len(masks)

    transitions = [[] for _ in range(n)]
    for i in range(n):
        a = masks[i]
        for j in range(n):
            b = masks[j]
            if (a & b) == 0 and (a & (b << 1)) == 0 and (a & (b >> 1)) == 0:
                transitions[i].append(j)

    dp = [1] * n

    for _ in range(1, c):
        ndp = [0] * n
        for prev in range(n):
            value = dp[prev]
            if value:
                for nxt in transitions[prev]:
                    ndp[nxt] += value
                    if ndp[nxt] >= MOD:
                        ndp[nxt] -= MOD
        dp = ndp

    print(sum(dp) % MOD)

if __name__ == "__main__":
    solve()
```最初の部分では、法的列の州のリストを作成します。 小切手`(mask & (mask << 1)) == 0`垂直方向に隣接する占有正方形を持つマスクを削除します。 垂直方向に接触できるのは連続する行のみであるため、マスクを 1 行ずらすだけで十分です。 

遷移構造では、有効な状態のすべてのペアが比較されます。 表現`(a & b)`水平方向に隣り合ったコンドミニアムを捉えます。 2 つのシフトされた比較により、対角線上に隣接するものが捕捉されます。 マスクは動的プログラミング配列に直接格納されるのではなくインデックス付けされるため、遷移がコンパクトに保たれます。 

動的プログラミング ループは、すでに処理された 1 つの列から始まります。 すべての状態には、空の状態を含め、最初の列として存在する方法が 1 つあります。 後続の各列は新しい配列を作成します。これは、前の値が前の列を正確に表す必要があり、異なる反復による状態が誤って混在することを避けるためです。 

Python の整数はオーバーフローしませんが、答えが指数関数的に増大するため、加算後にモジュロ演算が必要になります。 最終的な合計には、空の列を含む、考えられるすべての終了列状態が含まれます。

# テストケース```python
import sys, io

MOD = 10 ** 9 + 7

def solution(inp):
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    r, c = map(int, sys.stdin.readline().split())

    masks = []
    for mask in range(1 << r):
        if (mask & (mask << 1)) == 0:
            masks.append(mask)

    n = len(masks)
    trans = [[] for _ in range(n)]

    for i, a in enumerate(masks):
        for j, b in enumerate(masks):
            if (a & b) == 0 and (a & (b << 1)) == 0 and (a & (b >> 1)) == 0:
                trans[i].append(j)

    dp = [1] * n
    for _ in range(c - 1):
        ndp = [0] * n
        for i, val in enumerate(dp):
            for j in trans[i]:
                ndp[j] = (ndp[j] + val) % MOD
        dp = ndp

    ans = str(sum(dp) % MOD)
    sys.stdin = old_stdin
    return ans

assert solution("1 1\n") == "2", "minimum grid"
assert solution("2 2\n") == "5", "all cells touch in a 2x2 grid"
assert solution("1 5\n") == "13", "single row Fibonacci case"
assert solution("2 1\n") == "3", "vertical boundary case"
assert solution("3 3\n") == "35", "small multi-row grid"

 # エッジケース

 入力の場合:```
2 1
```生成されたマスクは`00`、`01`、 そして`10`。 列が 1 つしかないため、水平方向の遷移を考慮する必要はありません。 答えは、有効な単一列マスクの数、3 です。アルゴリズムはこれを処理します。これは、最初の動的プログラミング配列が既に完全なグリッドを表しているためです。`c = 1`。 

入力の場合:```
2 2
```このアルゴリズムは同じ 3 つの列状態を作成します。 遷移をチェックする場合、行が重なっているか、シフトされたマスクが斜めに重なっているため、空ではない状態のすべてのペアが拒否されます。 空の状態を含む遷移のみが残り、合計 5 つの配置が得られます。 これにより、対角チェックを忘れる実装が捕捉されます。
