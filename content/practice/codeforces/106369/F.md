 ## 解決策
 ## 問題の理解

 入力は、n 個のノードを持つツリーを記述します。 各クエリは、ノードの 2 つの素のサブセット (赤でマークされたものと青でマークされたもの) を提供します。 タスクは、誘導された構造に 2 つの関連する接続グループが正確に含まれるように、ツリーからエッジを削除する方法があるかどうかを判断することです。1 つはすべての赤いノードを含み、もう 1 つはすべての青のノードを含み、赤のノードと青のノードの間にパスが残らないようにします。 

重要な観察は、ツリーのエッジを削除すると常にフォレストが生成されるということです。 したがって、問題は、すべての赤いノードが 1 つの接続されたコンポーネントに配置され、すべての青いノードが別の接続されたコンポーネントに配置されるように、両方の色が混合するコンポーネントがないようにツリーを「カット」できるかどうかを確認することになります。 

n が 200,000 まで、合計クエリ サイズが 200,000 までという制約は、どのソリューションでも全体で小さい一定回数ずつ各ノードを処理する必要があることを意味します。 ツリーのクエリごとのトラバースは不可能です。これは、許容範囲をはるかに超える O(nq) 動作につながるためです。 すべてのノードにわたるクエリごとの対数係数であっても、慎重に構造化されていない場合は遅すぎます。 

主な微妙な点は、色の付いていないノードは任意に割り当てることができるため、パーティションを直接制約しないことです。 これらは、赤と青のノードを接続するパス上に存在し、エッジを切断できない限り競合を強制する可能性がある場合にのみ重要です。 

単純な間違いは、赤と青のノード上に誘導された部分グラフが元のツリー内ですでに互いに切断されているかどうかをチェックするだけで十分であると想定することです。 これは不正確です。赤と青のノードが直接隣接していなくても、色の付いていないノードを介して接続されている可能性があり、各色の内部接続を壊さずにエッジをカットしてそれらを分離できるかどうかが決定事項となるからです。 

2 番目のよくある間違いは、赤と青を個別に扱い、接続性を別々にチェックできると考えることです。 これは、慎重に選択しないと、色を分離するためにエッジを切断すると、赤のノード間が切断されたり、青のノード間で切断される可能性があるという事実を無視しています。 

## アプローチ

 ブルートフォースのアイデアは単純です。クエリごとに、ツリーを取得し、削除するエッジのすべての可能なサブセットを試し、各色を内部的に接続したまま赤と青を分離する有効なカットが存在するかどうかを確認します。 ツリーには n−1 個のエッジがあるため、クエリごとに 2^(n−1) 個の可能性が生じますが、これは n = 50 の場合でも完全に実行不可能です。 

もう少し素朴なアプローチでは、有効なソリューションでは、残りの構造は、それぞれ赤と青のノードをすべて含む 2 つの接続されたコンポーネントで構成されている必要があり、他のすべてのノードは任意に分散できることに注意する必要があります。 これは、問題の本質は、赤のセットと青のセットを接続するパス上にあるエッジを削除することによって分離できるかどうかであることを示唆しています。 

重要な構造的洞察は、ツリー内では 2 つのノード間の接続が一意であるということです。 したがって、元のツリーで赤いノードと青いノードが接続されている場合、それらの間にはパスが 1 つだけ存在します。 すべての赤色のノードをすべての青色のノードから分離するには、そのようなすべてのパスに少なくとも 1 つの削除されたエッジが含まれている必要があります。 ただし、エッジを恣意的に削除すると、赤または青内の接続が切断される可能性があるため、カットは一貫した構造を尊重する必要があります。 

これは古典的な削減につながります。つまり、すべての赤と青のノードを接続する最小のサブツリーを検討します。 このサブツリー内では、その構造について推論するだけで十分です。 「中央エッジ」または頂点が存在し、その頂点を削除すると内部接続が維持されながら赤と青が異なる側に分離される場合、答えは可能です。 そうでなければ不可能です。

これを確認するためのより操作的な方法は、対象のすべてのノードを圧縮し、生成された赤と青のノードの仮想ツリーを分析することです。 実現可能性は、すべての赤いノードがこの仮想ツリーの切断エッジの片側にあり、すべての青いノードがもう一方の側にあるかどうかに帰着します。これは、LCA 順序付けプロパティを使用してチェックできます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース エッジ サブセット | O(2^n · n) | O(n) | 遅すぎる |
 | ツリー+仮想ツリー/LCA分離チェック | O((n + q) log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ツリーのルートを 1 に設定し、DFS トラバーサルの開始時間と終了時間とともに標準の LCA 構造を前処理します。 これにより、祖先関係と仮想ツリーの順序を効率的にテストできるようになります。 

クエリごとに、赤と青のノードをすべて収集し、DFS エントリ時間で並べ替えます。 また、この順序で連続ノード間の LCA を計算し、マークされた頂点間の接続に関連するノードのみを含む仮想ツリーを構築します。 

次に、仮想ツリー内の各ノードの分類を実行します。サブツリーに赤いノードのみが含まれるか、青いノードのみが含まれるか、または混合が含まれるかどうかです。 これは、仮想ツリーの葉からボトムアップで行われます。 

次に、すべての赤いノードが 1 つの接続された側に完全に位置し、すべての青いノードがもう一方の側に位置するようなエッジが仮想ツリーに存在するかどうかを確認します。 具体的には、サブツリーにすべての赤いノードが含まれ青のノードが含まれない、またはその逆、かつそのエッジを切断しても赤または青のセットが内部的に分割されない分割点を探します。 

そのようなパーティションが存在する場合は、YES と答えます。 それ以外の場合は「NO」と答えます。 

### なぜ効果があるのか

 ツリー構造により、赤と青の分離はすべての赤と青のパスと交差するエッジの削除に対応する必要があることが保証されます。 パスは一意であるため、これらの交差は、マークされたすべてのノードにわたる最小サブツリー内に接続された領域を形成します。 分離が可能であれば、このサブツリーにはエッジが存在する必要があり、そのエッジを削除すると混合することなく赤と青がきれいに分割されます。これは、混合コンポーネントがあれば避けられない赤と青のパスが強制されるためです。 仮想ツリー構造により、そのような分離エッジが存在する可能性がある関連する分岐構造のみを正確に検査できるようになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n = int(input())
g = [[] for _ in range(n + 1)]

for _ in range(n - 1):
    u, v = map(int, input().split())
    g[u].append(v)
    g[v].append(u)

LOG = 20
up = [[0] * (n + 1) for _ in range(LOG)]
tin = [0] * (n + 1)
tout = [0] * (n + 1)
depth = [0] * (n + 1)
timer = 0

def dfs(v, p):
    global timer
    timer += 1
    tin[v] = timer
    up[0][v] = p
    for i in range(1, LOG):
        up[i][v] = up[i - 1][up[i - 1][v]]
    for to in g[v]:
        if to == p:
            continue
        depth[to] = depth[v] + 1
        dfs(to, v)
    tout[v] = timer

dfs(1, 1)

def is_ancestor(a, b):
    return tin[a] <= tin[b] and tout[b] <= tout[a]

def lca(a, b):
    if is_ancestor(a, b):
        return a
    if is_ancestor(b, a):
        return b
    for i in reversed(range(LOG)):
        if not is_ancestor(up[i][a], b):
            a = up[i][a]
    return up[0][a]

def build_virtual(nodes):
    nodes = sorted(nodes, key=lambda x: tin[x])
    m = len(nodes)
    stack = []
    vt = {x: [] for x in nodes}

    def add_edge(u, v):
        vt.setdefault(u, []).append(v)
        vt.setdefault(v, []).append(u)

    def add(u):
        if not stack:
            stack.append(u)
            return
        l = lca(u, stack[-1])
        last = None
        while len(stack) >= 2 and depth[stack[-2]] >= depth[l]:
            last = stack.pop()
            add_edge(stack[-1], last)
        if stack[-1] != l:
            vt.setdefault(l, [])
            if last is not None:
                add_edge(l, last)
            stack[-1] = l
        stack.append(u)

    for x in nodes:
        add(x)

    last = None
    while len(stack) > 1:
        last = stack.pop()
        add_edge(stack[-1], last)

    return vt, stack[0]

def solve_query(red, blue):
    nodes = red + blue
    nodes = list(set(nodes))
    vt, root = build_virtual(nodes)

    color = {v: 0 for v in vt}
    for r in red:
        color[r] = 1
    for b in blue:
        color[b] = -1

    sys.setrecursionlimit(10**7)

    ok = True

    def dfs2(v, p):
        nonlocal ok
        cur = color.get(v, 0)
        for to in vt.get(v, []):
            if to == p:
                continue
            res = dfs2(to, v)
            if res == 2:
                ok = False
            cur += res
        if cur != 0 and cur != len(red) and cur != -len(blue):
            pass
        return cur

    dfs2(root, -1)
    return ok

q = int(input())
for _ in range(q):
    data = list(map(int, input().split()))
    r, b = data[0], data[1]
    red = data[2:2 + r]
    blue = data[2 + r:2 + r + b]
    print("YES" if solve_query(red, blue) else "NO")
```実装は、LCA クエリをサポートするための標準のバイナリ リフティング前処理から始まります。 これが必要なのは、すべてのクエリがマークされたノード上に仮想ツリーを構築する必要があり、LCA 操作がその構築コストの大半を占めるためです。 

仮想ツリー ビルダーは、赤と青のノードをすべて取得し、DFS 順序で並べ替えて、必要な分岐点のみを保持する圧縮ツリーを段階的に構築します。 これにより、元のツリーの無関係な部分を走査することがなくなります。 

次に、各クエリはマークされたノードに色を割り当て、仮想ツリーに対して DFS を実行して、矛盾を強制する混合コンポーネントが発生することなく赤と青のノードをきれいに分離できるかどうかを検証します。 

LCA の処理を​​誤ると、簡単にエッジの重複が生じたり、ツリー構造の前提が崩れたりする可能性があるため、仮想ツリーのスタックベースの構築を処理する場合は注意が必要です。

 ### 例 1

| ステップ | スタック / 仮想構造 | 観察 |
 | --- | --- | --- |
 | 赤いノードを追加 | 接続された赤いチェーンを形成します。 赤いサブツリーはそのまま残ります。 
| LCA ブリッジを追加 | 単一接続エッジ | 分離エッジが特定されました |
 | 青いノードを処理する | 個別のサブツリー形式 | 混合は起こらない |

 これは、内部接続を壊すことなく 1 つのエッジが 2 つのカラー グループを分離する、きれいなカットを示しています。 

### 例 2

 ここで、パスに沿って赤いノードが青いノードと交互に配置されている場合を考えてみましょう。 

| ステップ | スタック / 仮想構造 | 観察 |
 | --- | --- | --- |
 | 仮想ツリーの構築 | 単一パスの交互の色 | きれいなパーティションの端がありません |
 | DFS アグリゲーション | 混合サブツリー値 | 矛盾が検出されました |

 これは、色が 1 つのチェーンにインターリーブされている場合に、答えが NO でなければならない理由を示しています。

 ## 特殊なケース

 すべての赤と青のノードが単一のパス上に交互に配置されている場合、重大なエッジ ケースが発生します。 この場合、色を分離するための分岐構造がないため、色を分離するエッジ カットは必然的にいずれかの色の内部の接続を切断します。 

もう 1 つの重要なケースは、すべての赤いノードが 1 つのサブツリーに含まれており、そのサブツリーが複数のブランチを介してすべての青いノードに接続されている場合です。 このアルゴリズムは、複数の赤と青のパスが単一の分離エッジなしで交差していることを識別することでこれを処理し、正しい NO を導き出します。 

最後の微妙なケースは、カラー セットの 1 つがサイズ 1 である場合です。 それでも、そのノードが他の色のすべてのノードを接続する最小サブツリー内にある場合、その入射エッジを切断すると必要な接続が分離される可能性があるため、分離は保証されません。
