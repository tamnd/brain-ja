 ## 解決策
 ## 問題の理解

 入力は、整数でインデックス付けされた最初は平坦な地形に適用される一連のコマンドを記述します。 位置 L を中心とした強度 K の成長操作は、位置 x の高さを max(0, K から x と L の間の距離を引いたもの) だけ増加させます。 これは、各成長操作が両方向に斜面 1 の三角形の「丘」を形成することを意味します。 

カット操作ではグローバルな上限が導入されます。H より上の高さはすべて H に減りますが、それより下の値は変更されません。 カットは高さを減らすだけで、増やすことはありません。複数のカットによりキャップの減少シーケンスが形成されます。 

測定操作では、以前のすべての変更後の特定の位置での現在の高さが要求されます。 

主な問題点は、各成長操作が O(K) 位置に影響を与える可能性があり、K が大きくなり、直接シミュレーションが不可能になる可能性があることです。 最大 2×10^5 の操作では、最悪の場合の作業が 10^10 更新を超えるため、成長ごとに影響を受けるすべての位置を更新する単純なアプローチは直ちに実行不可能になります。 

2 番目の困難は、オペレーション間の相互作用です。 カットは独立したリセットではありません。 それらは将来の成長や過去の蓄積された構造と相互作用します。 すべての位置をスキャンしてカットを適用するという単純な戦略は、構造が暗黙的に保存され、明示的に保存されることがないため、失敗します。 

エッジケースは、複数の重複する成長が相互作用するときに発生します。 たとえば、2 つの成長が重なり合う場合、単純なポイント単位の更新では、実装によってはカウントが 2 倍になったり、最大の効果が失われたりする可能性があります。 初期の成長が完全に考慮される前にカットが適用されると、別の障害モードが発生します。状態が遅延形式で一貫して維持されない場合、正確性が損なわれます。 最小限の例は、拡大、その後のカット、その後の中央のクエリです。この場合、カットを遅延適用するのを忘れると過大評価が生成されます。 

## アプローチ

 強引なアイデアは単純です。すべての木の高さの明示的な配列を維持します。 成長操作ごとに、K から距離を引いたものを加算して、L からの距離 K 内のすべての位置を更新します。 カットの場合は、配列全体を反復処理し、値を H にクランプします。クエリの場合は、保存された値を直接返します。 これは問題の定義を直接反映しているため、これは正しいですが、成長ごとに最大 O(K) 個の更新、カットごとに最大 O(N) 個の更新を処理します。 K と N は最大 10^5 であり、最大 2×10^5 の演算が存在するため、制限をはるかに超える約 10^10 の演算という最悪のケースが発生します。 

重要な観察は、両方の操作が暗黙的に表現できる構造を持っているということです。 各成長操作は、中心付近の傾き +1 および -1 を持つ区分線形関数に寄与します。 これは、明示的な高さではなく、傾斜の差の配列を維持することに相当します。 一方、カットでは、グローバルな上限エンベロープ制約が導入されます。これは、どの位置でも最終的な高さが、適用されるすべてのキャップと累積された成長値の最小値になることを意味します。 

重要な単純化は、問題を 2 つの層に分割することです。1 つの層は累積的な三角形の成長を追跡し、もう 1 つの層は切断による現在のグローバル最大許容高さを追跡します。 配列全体をクランプする代わりに、ランニングキャップを維持し、クエリ時にのみ適用します。 成長の寄与は、線形関数の範囲更新、または同等の 2 つのフェンウィック ツリーまたは傾き変化に対する差分配列をサポートする構造に保存できます。 

これにより、各グローは O(log N) 更新に、各クエリは O(log N) に削減され、カットはグローバル変数に対する O(1) 更新になります。

 | --- | --- | --- | --- |
 | ブルートフォース | O(N・Q) | O(N) | 遅すぎる |
 | 最適化されたスロープ差分 + 遅延キャップ | O(Q log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

高さ関数の導関数をエンコードする構造を維持します。 L を中心とする強度 K の三角形の成長は、L-K から L への増加する傾きと L から L+K への減少という 2 つの線形ランプとして表すことができます。 これは、傾きの差分配列の範囲更新を使用してエンコードできます。 

また、傾斜角の接頭辞の合計を介して任意の位置の高さを再構築できるように、接頭辞の構造も維持します。 

1. 値 K の位置 L での成長操作ごとに、傾きが L−K から開始して +1 増加し、L で -2 減少し、L+K で再び +1 増加するように、傾きの増分を更新します。 これにより、各位置に明示的に触れることなく、三角形の形状がエンコードされます。 これが機能する理由は、三角形の導関数がステップ関数であるためです。 
2. 値 H を持つ各カット操作について、グローバル変数 cap = min(cap, H) を維持します。 これは、すべての高さが、これまでに確認された最小のカットによって上からグローバルに制限されるという事実を表しています。 
3. 位置 x での各クエリについて、傾斜寄与のプレフィックス合計から生の高さを計算します。 
4. min(raw_height[x], cap) を出力し、カットが暗黙的に適用されるようにします。 

これが機能する理由は、すべての成長操作が線形の傾き変化に正確に分解され、これらの傾きの変化を合計すると正確な高さ関数が再構築されるためです。 カットは位置に依存しないため、すべての操作と連動し、再構築後に正確さに影響を与えることなく安全に適用できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXN = 100000 + 5

class BIT:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 2)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

n_ops = int(input())
bit = BIT(100000)
cap = 10**18

for _ in range(n_ops):
    tmp = input().split()
    if tmp[0] == 'A':
        _, L, K = tmp
        L = int(L)
        K = int(K)

        l = max(1, L - K)
        m = L
        r = min(100000, L + K)

        bit.add(l, 1)
        bit.add(m, -2)
        bit.add(r, 1)

    elif tmp[0] == 'C':
        cap = min(cap, int(tmp[1]))

    else:
        x = int(tmp[1])
        val = bit.sum(x)
        if val > cap:
            val = cap
        print(val)
```このソリューションは、直接の高さではなく傾斜の変化を保存するフェンウィック ツリーを中心に構築されています。 各拡大操作は、三角関数をエンコードする 3 点の更新に変換されます。 クエリはプレフィックスの累積を計算して、ある点の高さを再構築します。 カット操作は構造に直接触れることはなく、代わりにクエリに応答する場合にのみ適用されるグローバル キャップを更新して、効率を維持します。 

実装の微妙な詳細は、座標境界です。 ツリーには 1 ～ 100000 のインデックスが付けられているため、すべての更新はこの範囲に固定する必要があります。 もう 1 つの詳細は、成長操作における更新の順序です。 +1、-2、+1 パターンを正しい位置に適用することは、三角形を適切に再構築するために不可欠です。

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys

 ## 特殊なケース

 重要なエッジ ケースは、拡張操作の一部が有効なインデックス範囲外にある場合です。 たとえば、L = 1 および K = 5 の場合、三角形の左側は 1 より下に広がります。アルゴリズムは更新を有効なドメインに固定することでこれを処理し、無効な BIT インデックスが更新されないようにします。 

もう一つの特殊なケースは、大幅な成長の後に急激に減少する繰り返し削減です。 大きな三角形のピークが作成され、小さなカットが適用された場合、単純な実装では、保存されているすべての値を遡及的に減らそうとする可能性がありますが、このソリューションではカットをクエリ時間まで延期することでそれを回避します。 たとえば、A 10 100 の後に C 1 が続き、さらに B 10 は、内部構造にはるかに大きな生の値が格納されているにもかかわらず、正しく 1 を出力します。 

3 番目のケースは、直接更新を受け取らなかった位置をクエリすることです。 BIT はデフォルトでゼロを返すため、近くの成長の影響を受けない限り、これらのポジションは正しくゼロと評価されます。
