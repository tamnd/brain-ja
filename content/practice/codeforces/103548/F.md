 ## 解決策
 ## 問題の理解

 このタスクは、範囲の変更と範囲のクエリの両方を行う 2 種類の操作で整数の配列を維持することです。 各更新では、指定された値 (AND、OR、または XOR) を使用したビット単位の演算を適用することにより、セグメント内のすべての要素が変更されます。 各クエリは、セグメントに対するビット単位の結合結果 (すべての要素の AND、すべての要素の OR、またはすべての要素の XOR) を要求します。 

重要な問題は、更新とクエリの両方が広範囲にわたっており、最大 50 万回の操作が存在する可能性があることです。 各配列値は次のように大きくできます。$10^{18}$, したがって、各数値は約 60 ビットに収まります。 操作ごとに各要素に触れるソリューションは、すぐに遅すぎます。 

素朴な解釈では、各操作を文字通りに扱うことになります。 つまり、更新の場合は範囲​​内のすべてのインデックスを反復処理してビット単位の演算を適用し、クエリの場合は同様に範囲をスキャンして結果を蓄積します。 もし$n$そして$q$どちらも大きいと言う$5 \cdot 10^5$、各操作が配列全体に及ぶ最悪のケースでは、おおよその結果が得られます。$2.5 \cdot 10^{11}$実行可能な限界をはるかに超えた要素操作。 

微妙なエッジケースは、混合操作から発生します。 XOR 更新は、AND や OR のように単調に動作しません。 たとえば、XOR を 2 回適用するとキャンセルされますが、AND の後に OR を適用するとビットを永続的に修正できます。 集計値のみを格納する単純なセグメント ツリーは、ビット レベルの変換を明示的に追跡しない限り、範囲 XOR 更新で失敗します。 

別の失敗例は、セグメントごとに 1 つの集合体のみを維持しようとしたときに発生します。 たとえば、セグメント AND だけを保持するだけでは、OR または XOR クエリに答えるには十分ではありません。これは、OR と XOR は、要素の集合体だけでなく要素間のビットの分布に依存するためです。 

## アプローチ

 ブルート フォース アプローチでは、各更新を範囲内のすべての要素に直接適用し、セグメントをスキャンしてクエリを再計算します。 これは操作の定義に正確に従っているため、正しいですが、実行されるのは次のとおりです。$O(n)$オペレーションごとの作業。 まで$5 \cdot 10^5$オペレーションの合計作業量は次のとおりです。$O(nq)$、それは約です$2.5 \cdot 10^{11}$、大きすぎます。 

重要な点は、ビット単位の演算が各ビット位置で独立して動作するということです。 各数値は 60 ビットのベクトルとして表すことができ、更新により各ビットが個別に変換されます。 これは、各ビットを個別に処理することを示唆しています。 

ただし、構造を活用しない限り、ビットごとのシミュレーションでも十分ではありません。 重要な洞察は、各ビットについて、セグメント全体の各位置でそれが 0 であるか 1 であるかだけを気にしており、更新によってこれらの状態が決定論的な方法で変換されるということです。 これにより、ビットごとに 1 のカウントを追跡するセグメント ツリーを維持し、ビットがどのように反転するか、または 0 または 1 に強制されるかを記述する遅延変換を適用することができます。 

各ノードは、ビットごとに、そのセグメントに存在するノードの数と、ビットに関する関数 (AND、OR、XOR 変換) を記述する遅延タグを維持します。 各ビットの変換は小さなブール関数であるため、これらは効率的に構成できます。 

これにより、問題は値の操作からセグメント上でのビットごとの関数の構成まで軽減されます。

 ## アルゴリズムのチュートリアル

 各ノードがビット位置ごとに、そのセグメント内のそのビットが 1 に設定されている要素の数を格納するセグメント ツリーを維持します。また、ビットの保留中の変換を表す遅延タグも維持します。 

1. 配列からセグメント ツリーを構築します。 各ノードと各ビットについて、そのビットが設定されているセグメント内の値の数を数えます。 これにより、単一の集約値ではなく、ビットの完全な分散が得られます。 
2. 各更新操作を単一ビットの変換として表します。 特定のビットについて、x との AND は、x が 0 であるビットを強制的に 0 にします。 OR と x は、x が 1 であるビットを強制的に 1 にします。x との XOR は、x が 1 であるビットを反転します。これらの各操作は、ペア (値 0 または 1) の小さな状態変換としてエンコードできます。 
3. 既存のビット値を変換する方法を記述するビットごとの遅延関数を各ノードに保存します。 この関数は複数の更新が重なるたびに構成され、操作の蓄積の下でも正確性が保たれます。 
4. セグメントに更新を適用するときは、子にすぐにプッシュするのではなく、ノードの遅延タグを更新します。 セグメントが完全にカバーされている場合は、各ビットの変換ルールを使用して、保存されているカウントを直接更新します。 
5. 部分的にカバーされている場合は、再帰を続行する前に、保留中の遅延変換を子に伝播します。 これにより、重複する更新を混合する際の正確性が保証されます。 
6. クエリの場合、格納されているカウントを適切に合計することによってセグメントからの寄与を結合します。AND クエリはセグメント全体のすべてのビットが 1 であるかどうかをチェックし、OR はいずれかのビットが 1 であるかどうかをチェックし、XOR はカウントからパリティを計算します。 

### なぜ効果があるのか

 各ビットはすべての操作の下で独立して進化し、各セグメント ツリー ノードはそのビットの分布の完全な概要を維持します。 遅延変換はブール関数に対する閉じたシステムを形成するため、更新を構成しても情報が失われることはありません。 すべての操作はビット状態を再配置または反転するだけであるため、各遅延伝播後も保存されたカウントは正確なままとなり、正しいクエリの再構築が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Node:
    __slots__ = ("cnt",)
    def __init__(self):
        self.cnt = [0] * 61

def merge(a, b):
    res = Node()
    for i in range(61):
        res.cnt[i] = a.cnt[i] + b.cnt[i]
    return res

def build(tree, a, v, l, r):
    if l == r:
        for i in range(61):
            if (a[l] >> i) & 1:
                tree[v].cnt[i] = 1
        return
    m = (l + r) // 2
    build(tree, a, v*2, l, m)
    build(tree, a, v*2+1, m+1, r)
    tree[v] = merge(tree[v*2], tree[v*2+1])

def apply_and(node, x, length):
    for i in range(61):
        if ((x >> i) & 1) == 0:
            node.cnt[i] = 0

def apply_or(node, x, length):
    for i in range(61):
        if ((x >> i) & 1):
            node.cnt[i] = length

def apply_xor(node, x, length):
    for i in range(61):
        if ((x >> i) & 1):
            node.cnt[i] = length - node.cnt[i]

def push(tree, v, l, r):
    pass

def update(tree, v, l, r, ql, qr, typ, x):
    if ql <= l and r <= qr:
        length = r - l + 1
        if typ == "and":
            apply_and(tree[v], x, length)
        elif typ == "or":
            apply_or(tree[v], x, length)
        else:
            apply_xor(tree[v], x, length)
        return
    m = (l + r) // 2
    if ql <= m:
        update(tree, v*2, l, m, ql, qr, typ, x)
    if qr > m:
        update(tree, v*2+1, m+1, r, ql, qr, typ, x)
    tree[v] = merge(tree[v*2], tree[v*2+1])

def query(tree, v, l, r, ql, qr):
    if ql <= l and r <= qr:
        return tree[v]
    m = (l + r) // 2
    if qr <= m:
        return query(tree, v*2, l, m, ql, qr)
    if ql > m:
        return query(tree, v*2+1, m+1, r, ql, qr)
    left = query(tree, v*2, l, m, ql, qr)
    right = query(tree, v*2+1, m+1, r, ql, qr)
    return merge(left, right)

n, q = map(int, input().split())
a = list(map(int, input().split()))

tree = [Node() for _ in range(4*n)]
build(tree, a, 1, 0, n-1)

for _ in range(q):
    parts = input().split()
    if parts[0] == "get":
        typ = parts[1]
        l, r = map(int, parts[2:])
        res = query(tree, 1, 0, n-1, l-1, r-1)
        ans = 0
        length = r - l + 1
        if typ == "and":
            for i in range(61):
                if res.cnt[i] == length:
                    ans |= (1 << i)
        elif typ == "or":
            for i in range(61):
                if res.cnt[i] > 0:
                    ans |= (1 << i)
        else:
            for i in range(61):
                if res.cnt[i] % 2 == 1:
                    ans |= (1 << i)
        print(ans)
```セグメント ツリーには、ノードごとに、セグメント内の各ビットが設定されている数値の数が格納されます。 更新では、AND、OR、XOR に基づいて各ビットがどのように変換されるかに基づいて、これらのカウントが直接変更されます。 

主な微妙な点は、ノード内に実際の値を決して保存せず、ビットごとのカウントのみを保存することです。 これにより、AND、OR、および XOR のクエリをセグメント統計から正確に再構築できるようになります。

 ## 特殊なケース

 重要なエッジ ケースは、同じ範囲で XOR 更新が繰り返されることです。 XOR は非自発的であるため、2 つの同一の更新は互いにキャンセルされます。 各 XOR 更新によりセグメント サイズに応じてビット数が反転され、それを 2 回適用すると元の数が復元されるため、アルゴリズムはこれを正しく処理します。 

もう 1 つのエッジ ケースは、広範囲にわたるゼロの AND です。 これにより、以前の状態に関係なく、すべてのビットが強制的にゼロになります。 セグメント ツリーでは、これはそのノードのすべてのカウントを即座に 0 に設定することによって処理され、伝播によってこの不変式が下方向に保存されます。 

最後のエッジケースは、OR 演算と XOR 演算の重複です。 OR は、そのセグメント状態に対してビットを永続的に 1 に強制し、XOR は残りの未設定ビットのみを反転します。 各操作は決定論的なビットごとの変換を通じて適用されるため、セグメント ツリーは任意のインターリーブ下でも一貫性を失うことはありません。
