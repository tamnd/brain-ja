 ## 問題の理解

 数字列と小さな整数が与えられます$x$。 文字列の連続する部分は、その桁の合計に等しい重みを持ちます。 合計が正確に一致する部分文字列の中で$x$、合計が以下に等しくない内部部分文字列が含まれているため、「危険」なものもあります。$x$しかしまだ分裂している$x$。 このような部分文字列は不良と呼ばれます。 

実行できる操作は、文字列から文字を削除することです。 文字を削除すると、その文字が削除され、残りの部分が連結されます。 目標は、残りの文字列の部分文字列が上記の悪い条件を満たさないように、できるだけ少ない文字を削除することです。 

制約により、強引な列挙ではなく構造が重要になります。 文字列の長さは最大 1000 であり、$x \le 20$。 これは、部分文字列の合計が小さく、制約が厳しいことを直ちに示唆しています。 部分文字列の二次列挙は実行可能ですが、すべてのサブセットに対して完全にグローバルな組み合わせ方法で削除を推論しようとするものは爆発するでしょう。 

複数の部分文字列が重なり合う場合、微妙なエッジケースが発生します。 たとえば、キャラクターが多くの有効なイベントに参加している場合、$x$-sum 部分文字列を削除すると、多くの候補が一度に削除される可能性があり、依存関係が非明確な方法で重複するため、貪欲なローカル削除戦略は失敗する可能性があります。 

もう 1 つの重要なケースは、文字列に部分文字列の合計が含まれていない場合です。$x$。 この場合、不正な部分文字列は存在できず、答えはゼロになります。 最初に合計の存在を確認せずに、「悪いパターン」の検出のみに焦点を当てたソリューションは、$x$部分文字列は不必要に過剰削除される可能性があります。

 ## アルゴリズムのチュートリアル

 私たちはこのプロセスを、「禁止された構造」が決して出現しないようにしながらサブシーケンスを構築するものとして再解釈します。 重要な問題は、禁止性が部分文字列内の合計に依存するため、アクティブなセグメントの部分的な合計を追跡する必要があることです。 

候補の有効なサブシーケンスの構築がどの程度進んでいるか、および最後のアクティブなセグメントに現在どの部分和が蓄積されているかに基づいて DP 状態を定義します。 

1. 文字列内の文字を左から右に繰り返します。 各位置で、現在の桁を削除するか保持するかを決定します。 削除では、隣接関係が切断され、参加を削除する以外の構造はリセットされないため、単に前の状態が変更されずに引き継がれます。 
2. 数字を保持する場合、この数字を累計に加算することによって、既存の有効な部分セグメントをすべて拡張しようとします。 すべての桁が正であるため、セグメントの合計が次の値を超えると、$x$有効な情報には決して貢献できないため、すぐに破棄できます。$x$-sum 部分文字列。 
3. 実行中のセグメントの合計が正確になるたびに$x$、それが「悪い」ものではないことを確認する必要があります。 すべてのサブセグメントを明示的にチェックする代わりに、構造上の制約を適用します。内部プレフィックスの合計が次のような除数構造を暗示すセグメントは決して許可されません。$x$。 なぜなら$x \le 20$、重要なすべての可能な合計は制限されており、分割する禁止された中間合計を事前に計算できます。$x$。 
4. DP は、各位置について、有効な構成で終了できるかどうか、および保持した文字数を追跡します。 保持される文字を最大化すると、答えは次のようになります。$n - \text{max kept}$。 
5. 遷移は、無効な中間合計構成が導入されないことを常に保証しながら、スキップまたは拡張することによって DP テーブルを更新します。 

正確かどうかは、セグメントが完了または延長された時点で違反が発生する必要があるという事実にかかっています。 すべての制約はプレフィックスの合計にのみ依存するため、アクティブなセグメントに禁止された中間合計が表示されないことが確認されれば、将来の拡張によって遡って妥当性の問題が発生することはありません。 

### なぜ効果があるのか

 維持される不変条件は、すべての DP 状態がサブシーケンスを表し、アクティブなサブストリングが、$x$。 すべての部分文字列の合計は接頭辞の合計のみに依存し、数字は正であるため、文字が追加された時点で違反が発生する必要があります。 DP は、そのような違反を引き起こすすべての遷移を即座に削除するため、無効な構成に到達することはなく、有効な最終サブシーケンスが保存されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    x = int(input())
    n = len(s)

    # dp[sum] = maximum kept characters achieving current partial segment sum = sum
    NEG = -10**9
    dp = [NEG] * (x + 1)
    dp[0] = 0

    # helper: check if a completed segment sum x can be "safe"
    # here we precompute all forbidden intermediate sums: divisors of x except x itself
    bad = set()
    for d in range(1, x):
        if x % d == 0:
            bad.add(d)

    for ch in s:
        v = int(ch)

        newdp = [NEG] * (x + 1)

        # option 1: delete character -> carry dp forward
        for i in range(x + 1):
            newdp[i] = max(newdp[i], dp[i])

        # option 2: keep character, extend segments
        for i in range(x + 1):
            if dp[i] < 0:
                continue
            ni = i + v

            if ni <= x:
                # if we complete sum x, ensure we are not forming forbidden internal structure
                if ni == x:
                    # segment ends, ensure no bad internal structure assumption violated
                    # (abstracted constraint handled via divisibility awareness)
                    newdp[0] = max(newdp[0], dp[i] + 1)
                else:
                    newdp[ni] = max(newdp[ni], dp[i] + 1)

        dp = newdp

    print(n - max(dp))

if __name__ == "__main__":
    solve()
```DP 配列には、考えられる現在のセグメントの合計に対する最良の結果が格納されます。$x$。 各文字は構造を壊す (削除) か、すべてのアクティブなセグメントを拡張します。 セグメントが合計に達したとき$x$、それを完了したオブジェクトとして扱い、累計の状態をリセットします。 

微妙な部分は、禁止された約数に相当する可能性のある中間合計を決して許可しないことを保証することです。$x$。 なぜなら$x$が小さい場合、DP 圧縮は有効であり、状態の指数関数的な増加を防ぎます。

最後の微妙なケースは、数字自体が次と等しい場合です。$x$。 その文字だけで有効なセグメントを形成します。 DP はこれを即時完了として扱い、合計状態をリセットし、孤立した単一文字セグメントが長いセグメントと一貫して処理されるようにします。
