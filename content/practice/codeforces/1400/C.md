 ## 問題の理解

 バイナリ文字列が与えられます$s$と距離パラメータ$x$。 不明な元のバイナリ文字列が存在します$w$同じ長さの。 から$w$、文字列$s$決定論的ルールを使用して生成されました: の各位置$s$の最大 2 つの位置を調べます$w$、 1つ$x$左へ1歩$x$右へのステップ。 これらの参照位置のいずれかが$w$1 が含まれている場合、対応する位置が$s$それ以外の場合は 0 になります。 

タスクは、有効なデータを再構築することです。$w$それは与えられたものを生み出すことができたでしょう$s$、またはそのようなものはないと判断します$w$存在します。 

プロセスを言い換える便利な方法は、それぞれの 1 について考えることです。$w$まさにその影響力を「広める」$x$左右にステップして入ります$s$。 それぞれのポジションで$s$は、単に次の最大 2 つの位置の OR です。$w$それはそれに影響を与える可能性があります。 

入力サイズが到達しました$10^5$すべてのテスト ケースにわたって、インデックスのペアに対する二次推論が即座に除外されます。 有効なアプローチはすべて、テスト ケースごとに線形である必要があります。$O(n \log n)$許容されますが、不要です。 

重要な問題は、マッピングが単射的ではないことです。 単一の 1 インチ$s$の 2 つの立場のいずれかによって説明できます。$w$、複数の選択肢が相互作用します。 検証せずに貪欲に割り当てる単純なアプローチは、後の制約が以前の割り当てと矛盾する可能性があるため、失敗する可能性があります。 

微妙な失敗例は、複数のポジションが存在する場合に発生します。$s$は 1 ですが、説明が矛盾して重複しています。 たとえば、次の場合$s = 1001$そして$x = 2$、不注意な戦略により、対称的な位置に配置される可能性があります。$w$ただし、それは過剰に伝播し、誤って余分な値を強制したり、ゼロ制約を満たさなかったりする可能性があります。$s$。 

もう 1 つの重要なエッジケースは、ポジションが$s$は 0 です。つまり、両方の候補位置が$w$0 である必要があります。$w$内の者からのみ$s$ただし、ゼロ制約を無視すると、有効な構成が過大評価されます。 

## アプローチ

 強引なアイデアは、すべてのポジションを次のように扱うことです。$w$バイナリ変数としてすべてをシミュレートします$2^n$代入、結果の再計算$s$毎回。 これは明らかに実行不可能です。$n = 40$、状態空間はすでに約 1 兆の構成になっています。 もう少し洗練された総当り攻撃では、プルーニングによるバックトラックを試行することもできますが、それでも制約により指数関数的になります。 

変換の構造はローカルかつ線形です。 それぞれのポジションで$s$の 2 つの固定位置のみに依存します。$w$。 これにより、問題は制約システムに変わります。$s$最大 2 つの変数に OR 条件を課します。$w$。 これはまさに 2-SAT スタイルの構造ですが、もっと直接的に解決できます。 

重要な観察は、ロジックを逆転させることです。 構築する代わりに$s$から$w$、条件を強制します$w$に基づく$s$。 もし$s[i] = 0$、その後両方$w[i-x]$そして$w[i+x]$(存在する場合) は 0 でなければなりません。$s[i] = 1$の場合、それらの位置の少なくとも 1 つは 1 でなければなりません。 

これはすぐに建設的な戦略を示唆します。最も制限的な制約から始めて、強制されたすべてのゼロを修正し、その後、すべての 1 が確実に満たされるように貪欲に保証します。$s$少なくとも 1 つの空きポジションが「カバー」されています$w$。 すべての制約が満たされたら、一貫性を検証します。

 ## アルゴリズムのチュートリアル

 候補文字列を構築します$w$直接。 

1.初期化$w$すべてのものとして。 これは最も許容的な構成であり、後でゼロによって制限されます。$s$。 すべて 1 から始めることで、時期尚早な制限によって潜在的な解決策を見逃すことがなくなります。 
2. インデックスごとに$i$どこ$s[i] = 0$、内のすべての位置を削除します。$w$～に貢献できる可能性があること$s[i]$。 つまり設定$w[i-x] = 0$そして$w[i+x] = 0$それらのインデックスが存在するときはいつでも。 
3. すべてのゼロを処理した後、部分的に制約された$w$。 ここで、すべての位置を確認します$i$どこ$s[i] = 1$確かに、少なくとも 1 人の積極的な貢献者によって説明できます。$w$、どちらかを意味します$w[i-x] = 1$または$w[i+x] = 1$(境界内にいる場合)。 

いずれかの位置がこの条件を満たさない場合、再構築は不可能です。 

1. すべての制約が満たされている場合、構築された結果を出力します。$w$。 

この順序付けが機能する理由は、ゼロが絶対的な制約であるためです。ゼロは、特定の位置を禁止します。$w$全体的に。 1 つは実存的な制約です。少なくとも 1 つの支持位置のみが必要です。 絶対的な制約の前に存在的な制約を処理すると、誤った仮定が固定される危険があります。 

### なぜ効果があるのか

 アルゴリズムは単調不変式を維持します。つまり、ゼロを処理するたびに、$s$の位置を正確に削除します。$w$それはそれに違反することになります。 のポジションを削除して以来、$w$将来への貢献を減らすことしかできない$s$、ゼロ制約に対して誤って誤検知が発生することはありません。 

ポジションについては、$s[i] = 1$、すべての強制削除の後にのみ実現可能性を確認します。 その時点で貢献候補者が存在しない場合は、1 を満たすための唯一のメカニズムは、1 をサポートする少なくとも 1 つの存在であるため、以前の選択では問題を修正できなかったはずです。$w$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        s = input().strip()
        x = int(input())
        n = len(s)

        w = ['1'] * n

        # enforce zeros
        for i, ch in enumerate(s):
            if ch == '0':
                if i - x >= 0:
                    w[i - x] = '0'
                if i + x < n:
                    w[i + x] = '0'

        # verify ones
        ok = True
        for i, ch in enumerate(s):
            if ch == '1':
                left = (i - x >= 0 and w[i - x] == '1')
                right = (i + x < n and w[i + x] == '1')
                if not left and not right:
                    ok = False
                    break

        if not ok:
            print(-1)
        else:
            print("".join(w))

if __name__ == "__main__":
    solve()
```構築ステップは、文字列全体を 1 として初期化し、次にゼロから派生した禁止位置を選択的にゼロにすることによって実装されます。$s$。 これにより、強制された場合にのみ候補を削除するため、潜在的な解決策を見逃すことがなくなります。 

重複する制約により、一部の 1 が含まれる構成が生成される可能性があるため、検証ステップは不可欠です。$s$～において支持的な立場を持たない$w$。 

境界チェックには注意が必要です: インデックス$i-x$そして$i+x$アクセスまたは変更する前に検証する必要があります$w$そうしないと、無効なメモリ アクセスまたは不正なロジックが発生します。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        s = input().strip()
        x = int(input())
        n = len(s)

        w = ['1'] * n

        for i, ch in enumerate(s):
            if ch == '0':
                if i - x >= 0:
                    w[i - x] = '0'

 ## 特殊なケース
