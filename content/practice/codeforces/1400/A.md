 ## 解決策
 ## 問題の理解

 バイナリ文字列が与えられます`s`長さの`2n - 1`。 この文字列から、長さのすべての連続ウィンドウを調べます。`n`。 まさにあります`n`このようなウィンドウは、位置から開始します`1`を通して`n`。 各ウィンドウは、隣接するウィンドウと重なり合う候補文字列を表します。 

タスクはバイナリ文字列を構築することです`w`長さの`n`これらのウィンドウのすべてが「類似」するようにします。 2 つのバイナリ文字列は、両方が同じビット値を持つ少なくとも 1 つの位置を共有する場合、類似しているとみなされます。 言い換えると、すべてのウィンドウに少なくとも 1 つのインデックスが存在する必要があります。`w`そしてそのウィンドウは正確に一致します。 

ここでの重要な制約は次のとおりです`n ≤ 50`、 そして`t ≤ 1000`。 これは、`O(n^2)`テスト ソリューションごとの速度は簡単に十分に高速ですが、指数関数的なものはすべて`n`強く剪定された場合にのみ許容されます。 ただし、構造は線形で制約されているため、検索ではなく直接的な構築的なパターンを期待する必要があります。 

文字列が次の場合に微妙なエッジケースが発生します。`s`のように非常に交互になります。`1010101...`、すべてのウィンドウにわたってグローバルに安定した位置はありません。 もう 1 つのエッジ ケースは、すべてのウィンドウが異なる位置で矛盾する制約を強制し、誤って解釈されると単純な交差ベースの推論が失敗する場合です。 

たとえば、すべてのウィンドウで位置に関する多数決の調整を強制しようとすると、シフト間の一貫性を誤って仮定する可能性があります。 ただし、ウィンドウはシフトされるため、拘束の位置は単純な方法では整列しません。 

## アプローチ

 ブルートフォースアプローチは、考えられるすべてのバイナリ文字列を試すことです。`w`長さの`n`、各候補について、すべてのウィンドウと少なくとも 1 つの一致する位置を共有しているかどうかを確認します。`s`。 それぞれについて`w`、これにはスキャンが必要です`n`ウィンドウと比較`n`キャラクター、与える`O(n^2)`候補者ごとに。 あるので`2^n`候補者はこうなります`O(n^2 · 2^n)`、でもそれは不可能です`n = 50`。 

重要な点は、すべてのウィンドウを複雑な方法で個別に満たす必要はないということです。 各ウィンドウには、完全な位置合わせではなく、一致する位置が 1 つだけ必要です。 これにより、問題はウィンドウごとに 1 つの「証人」の位置を選択することになりますが、それらの証人は単一の固定文字列から取得する必要があります。`w`。 

条件を再構成することが主な単純化です。 ウィンドウごとに考えるのではなく、位置ごとに考えます。`w`。 ポジションごとに`i`で`w`、位置に合わせます`i + j`窓の中`j`。 だから位置`i`の`w`すべての文字と比較されます`s[j + i]`すべての有効なシフトにわたって`j`。 私たちが選ぶなら`w[i] = 0`の場合、この位置は、少なくとも 1 つを含むすべてのウィンドウを満たすことができます。`0`オフセットで`i`。 同様に、`1`。 

これにより、すべてのウィンドウに少なくとも 1 つのインデックスがあることを確認する作業が軽減されます。`i`どこ`w[i] == s[j + i]`。 以来`n`小さいので、単純に割り当てることができます`w[i]`貪欲に: 両方の値を試し、カバレッジが維持されていることを確認します。 より単純な建設的なショートカットが存在します。`w`カバレッジを保証する有効なアライメントを選択することによって、標準的なトリックはアライメントを行うことです。`w`中央のウィンドウを使用して外側に一貫性を伝播しますが、最も単純に受け入れられる構造は、実現可能性に基づいて位置ごとに直接貪欲に選択するものです。 

最も安定したアプローチは、次のように構築することです。`w`各ポジションごとに`i`では、ウィンドウ全体で対応する位置合わせされた文字の中で頻繁に出現するビットを選択し、一致しないウィンドウがないようにします。

 ## アルゴリズムのチュートリアル

 1. Consider each position`i`ターゲット文字列内で`w`。 この位置で、次のことを決定します。`w[i]`あるべきです`0`または`1`。 この決定により、ウィンドウが完全に「不一致」になることがないようにする必要があります。 
2. 固定の場合`i`、すべてのウィンドウを検査します`j`そんな位置`i`窓の内側にある`j`。 これはすべてを意味します`j`で`[max(1, i - n + 1), min(n, i)]`。 各候補ビットについて`b ∈ {0, 1}`を選択するかどうかを確認してください`w[i] = b`位置に応じてすべてのウィンドウが許可されます`i`全体で少なくとも 1 つの有効な一致位置があること。 
3.割り当て`w[i]`実現可能性を維持できるあらゆるビットに。 問題は解決策の存在を保証するため、2 つの選択肢のうち少なくとも 1 つは常に有効です。 
4. 以降のすべてのポジションに対してこのプロセスを継続します。`1`に`n`。 すべての位置が割り当てられたら、出力します`w`。 

### なぜ効果があるのか

 各ウィンドウには少なくとも 1 つの位置が必要です。`w`マッチ`s`。 位置処理時`i`、実際に以下を含むウィンドウのみに制限します。`i`。 ウィンドウが満たされる残りの可能性を壊さない値を選択した場合、すべてのウィンドウには、未割り当てのインデックスまたは既に割り当てられているインデックスの中に少なくとも 1 つの一致する可能性のある位置が依然として存在するという不変条件が維持されます。 解決策が保証されているため、ローカルでの実現可能性を貪欲に追求しても、有効なグローバル補完がすべて排除されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()

        # 0-index convenience
        s = " " + s

        w = ['?'] * (n + 1)

        # precompute windows: window j is s[j : j+n-1]
        # we ensure each window has at least one match position

        # track for each window whether it is already satisfied
        satisfied = [False] * (n + 1)

        # try greedy construction
        for i in range(1, n + 1):
            for bit in "01":
                ok = True

                for j in range(1, n + 1):
                    if j <= i <= j + n - 1:
                        # check if window j can still be satisfied
                        # assume we set w[i] = bit
                        matched = False
                        for k in range(j, j + n):
                            if k == i:
                                if s[k] == bit:
                                    matched = True
                            else:
                                if w[k - j + 1] != '?':
                                    if w[k - j + 1] == s[k]:
                                        matched = True
                        if not matched:
                            ok = False
                            break

                if ok:
                    w[i] = bit
                    break

        print("".join(w[1:]))

if __name__ == "__main__":
    solve()
```ソリューションは文字列を構築します`w`左から右へ。 位置ごとに、可能なビットを両方試して、そのビットを割り当てるとウィンドウを満たすことが不可能になるかどうかをシミュレートします。 将来の割り当てまたは現在の割り当てが一致する位置が少なくとも 1 つ残っている場合、ウィンドウは安全であるとみなされます。`s`。 

ネストされたチェックにより、現在影響を受けているウィンドウがデッド状態に強制されていない場合にのみ、値がコミットされることが保証されます。 

微妙な点は、割り当てられていないポジションが柔軟なものとして扱われることです。これにより、貪欲な戦略が後戻りすることなく成功することができます。

 ## 特殊なケース

 最小限のエッジケースは次のとおりです。`n = 1`。 ウィンドウは 1 つだけであるため、一致するビットはすべて有効であり、アルゴリズムによってそのビットがすぐに割り当てられます。 

次のような高度に交互する文字列の場合`10101...`、各ウィンドウはパターンをシフトしますが、未割り当ての位置は重複するチェックによって制限されるまで柔軟性を維持するため、貪欲なプロセスは依然として成功します。 

すべてゼロのような均一な文字列の場合、`w[i] = 0`すべての位置がすべてのウィンドウに自明に一致するため、すべてのウィンドウ チェックに合格します。
