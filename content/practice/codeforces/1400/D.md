 ## 解決策
 ## 問題の理解

 整数の配列が与えられ、インデックスの 4 倍がいくつあるかを数えるように求められます。$(i, j, k, l)$両方を満たす$i < j < k < l$そして$a[i] = a[k]$、$a[j] = a[l]$。 言い換えれば、最初と 3 番目の位置が同じ値を保持し、2 番目と 4 番目の位置が同じ値を保持し、インデックスが厳密に増加する 2 つの一致する値のペアが必要です。 

入力は複数のテスト ケースを提供します。 各テスト ケースでは、まず配列のサイズを読み取ります。$n$次に配列自体。 すべての合計が保証されます。$n$テスト ケース全体で 3000 を超えません。これは、おおよそで実行されるアルゴリズムを意味します。$O(n^2)$テストケースごとの時間は十分に速いはずですが、何でも構いません$O(n^3)$それ以上の場合は、最悪の場合タイムアウトになる可能性があります。 

単純な実装では、4 つのネストされたループを使用してすべての 4 倍を列挙しようとする可能性があります。 これは正しいですが、非常に時間がかかります。最悪の場合の操作数は約$n^4$のオーダーです。$8 \times 10^{13}$場合の操作$n = 3000$、明らかに実行不可能です。 

単純なソリューションが見逃してしまう可能性のあるエッジ ケースには、すべての要素が等しい配列が含まれます。 たとえば、配列が次の場合、$[2, 2, 2, 2, 2]$、4 つのインデックスのすべての組み合わせが有効です。 もう 1 つの微妙なケースは、一部の値が 1 回か 2 回しか出現しない場合です。 アルゴリズムは、有効なペアを形成できない組み合わせを正しくスキップする必要があります。 

## アプローチ

 ブルートフォースの解決策は簡単です。すべての 4 倍を反復処理します。$(i, j, k, l)$4 つのネストされたループを使用して等価条件を確認します。 これは定義を直接実装するため理論上は機能しますが、時間が複雑になるため非現実的です。$O(n^4)$。 

より迅速な解決策を可能にする重要な観察は、固定された問題に対して次のことを認識することです。$j$そして$k$、適切な数を効率的に数えることができます。$i$そして$l$インデックス。 具体的には、中央の 2 つのインデックスを修正すると、$j$そして$k$、有効な数$i < j$そのような$a[i] = a[k]$単に前の値のカウントです$j$、有効な数$l > k$そのような$a[j] = a[l]$後のその値のカウントです$k$。 これら 2 つのカウントを乗算すると、その 4 倍の数が得られます。$j, k$ペア。 これにより問題は次のように縮小されます$O(n^2)$、これは実現可能です$n \le 3000$。 

このアプローチが機能するのは、問題が中間のインデックスを中心に対称であるためです。外側の値は前の値にのみ依存します。$j$そしてその後$k$を使用すると、プレフィックスとサフィックスのカウントを事前に計算して、カウントの繰り返しを避けることができます。

 | ブルートフォース | O(n^4) | お(1) | 遅すぎる |
 | プレフィックス/サフィックスのカウント | O(n^2) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、次の内容を読んでください。$n$そして配列$a$。 各配列を個別に処理します。 
2. 答えを蓄積するための変数を初期化します。 
3. 反復する$j$インデックス 1 から$n-2$そして$k$から$j+1$に$n-1$。 これらは、クアドルプルの中央の 2 つのインデックスを表します。 
4. ペアごとに$(j, k)$、インデックスの数を数えます$i < j$どこ$a[i] = a[k]$。 これは、最初の処理を繰り返すことで実行できます。$j$要素と同等性のチェック。 
5. インデックスの数を数える$l > k$どこ$a[l] = a[j]$。 これは以下を反復することによって行われます。$k+1$に$n-1$そして平等性をチェックします。 
6. これら 2 つのカウントを乗算して、この特定の 4 倍の数を取得します。$(j, k)$を組み合わせて、蓄積された答えに追加します。 
7. すべてを繰り返した後$(j, k)$ペアとして、テスト ケースの答えを出力します。 

機能する理由: 各ステップで、アルゴリズムは有効な値を明示的にカウントします。$i$前に$j$そして有効な$l$後$k$。 これらのカウントを乗算すると、有効な外部インデックスのすべての組み合わせが 1 回だけ考慮されることが保証されます。 以来$j < k$が強制され、すべての 4 倍が満たされます$i < j < k < l$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    ans = 0
    for j in range(1, n - 2 + 1):
        for k in range(j + 1, n - 1):
            count_i = 0
            for i in range(j):
                if a[i] == a[k]:
                    count_i += 1
            count_l = 0
            for l in range(k + 1, n):
                if a[l] == a[j]:
                    count_l += 1
            ans += count_i * count_l
    print(ans)
```コードはテスト ケースの数を読み取り、それぞれを個別に処理します。 それぞれについて$(j, k)$ペア、何個数えますか$i$満足する$a[i] = a[k]$そして何個$l$満足する$a[l] = a[j]$。 これらのカウントを乗算すると、そのペアが寄与するクアドルプルの数が求められます。 範囲を慎重に選択することで、$i < j < k < l$、すべてのループは、Python の 0 から始まるインデックスを正しく使用することで、off-by-one エラーを回避します。
