 ## 解決策
 ## 問題の理解

 私たちにはいくつかの種類の作物が与えられています。 作物の種類ごとに、何キログラム収穫されたか、そしてその特定の作物を 1 つの保管ボックスにどれだけ収納できるかがわかります。 主な制限は、ボックスが作物ごとに異なることです。つまり、同じボックス内に異なる作物を混在させることはできません。 

作物ごとに、その作物の収穫重量すべてを保管するために同じ箱が何個必要かを決定する必要があります。 箱は分割できない単位であるため、箱を完全に満たさない残りの重量には、さらに追加の箱が必要です。 これを作物ごとに計算した後、すべての作物にわたるボックスの数を合計します。 

入力サイズは最大 100,000 作物まで可能です。 これにより、アイテムごとに箱に詰めるシミュレーションや、キログラム単位で反復するアプローチは即座に除外されます。 どのソリューションでも各クロップを一定時間で処理する必要があり、全体的な複雑さは線形 O(n) になります。 

収穫総量が箱の容量で正確に割り切れる場合、微妙なエッジケースが現れます。 たとえば、20 kg をサイズ 4 kg の箱に保管する場合、答えはちょうど 5 箱になります。 ただし、21 kg をサイズ 4 kg の箱に保管すると、答えは 6 箱になります。 上限処理を行わない単純な整数除算では、2 番目のケースで 5 が誤って計算されます。 

もう 1 つの特殊なケースは、n がゼロに等しい場合です。 この場合、クロップがないため、ボックスは必要なく、正しい出力は 0 です。 

## アプローチ

 この問題を考える最も直接的な方法は、各作物を個別に扱い、収穫物を箱に詰めるシミュレーションを行うことです。 1 つの作物について、残りの重量からボックスの容量を差し引き、何も残らないまでこれを何回繰り返すかを繰り返します。 これは実際のプロセスを正確にモデル化しますが、最悪の場合は非常に遅くなります。 作物の重量が 100,000 kg で箱のサイズが 1 kg の場合、このシミュレーションは 1 つの作物に対して 100,000 回の操作を実行しますが、100,000 個の作物全体ではこれは 10^10 の操作となり、これはまったく実行不可能です。 

重要な観察は、各作物が独立しており、単純な算術構造に従っていることです。 基本的に、a_i 項目をカバーするためにサイズ b_i のグループがいくつ必要かを計算しています。 これはまさに天井分割問題です。 グループ化をシミュレートする代わりに、整数演算を使用して完全なボックスの数を直接計算できます。 

各作物の箱の数は次のとおりです。 

ceil(a_i / b_i)

 これは次のように効率的に計算できます。 

(a_i + b_i - 1) // b_i

 この変換が機能するのは、b_i - 1 を追加すると、ゼロ以外の剰余があれば、除算が完全なボックス 1 つ分押し上げられる一方で、正確な倍数は変更されないためです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | シミュレーション | O(合計 a_i / b_i) | お(1) | 遅すぎる |
 | 作物ごとの天井区分 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 作物の種類 n の数を読み取ります。 n が 0 の場合、保存するものがないため、答えはすぐに 0 になります。 
2. アキュムレータ変数 total_boxes をゼロに初期化します。 これにより、すべての作物に必要なボックスの合計が保存されます。 
3. 各作物 i について、収穫重量と箱の容量を表すペア (a_i, b_i) を読み取ります。 
4. 天井除算を使用して、このクロップに必要なボックスの数を計算します: (a_i + b_i - 1) // b_i。 これにより、部分的に満たされた最終ボックスも確実にカウントされます。 
5. この値を total_boxes に追加します。 各作物は独立して寄与するため、作物間の相互作用がなくても合計は有効です。 
6. すべてのクロップを処理した後、total_boxes を出力します。 

### なぜ効果があるのか

各作物は、固定量 a_i をサイズ b_i のグループに分割する 1 次元の充填問題に帰着します。 有効な梱包では、少なくとも床 (a_i / b_i) 個の完全な箱を使用する必要があり、残りが存在する場合は、箱を分割したり作物を混合したりすることができないため、追加の箱を 1 つ追加することは避けられません。 式 (a_i + b_i - 1) // b_i はこの下限を正確に捉えており、これより少ないボックスを使用するソリューションは存在しないため、必要かつ十分になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    total = 0

    for _ in range(n):
        a, b = map(int, input().split())
        total += (a + b - 1) // b

    print(total)

if __name__ == "__main__":
    solve()
```このソリューションは各作物を 1 回読み取り、すぐに必要な数のボックスに変換します。 式 (a + b - 1) // b は、上限除算の標準的な整数トリックであり、浮動小数点演算を完全に回避するため、計算が高速かつ安全に行われます。 

アキュムレータの合計は単一の整数として維持され、各演算は O(1) であるため、全体の複雑さは線形のままです。

 ## 特殊なケース

 n = 0 の場合、ループは実行されず、合計は 0 のままであるため、特別な処理を行わなくても出力は正確になります。 

20 と 4 など、a_i が b_i で正確に割り切れるクロップの場合、式は (20 + 3) // 4 = 23 // 4 = 5 を与え、予想される正確なパッキングと一致します。 剰余がゼロであり、b_i - 1 の加算が b_i の倍数を超えないため、追加のボックスは追加されません。 

7 や 10 のような収穫量がボックスの容量より小さい作物の場合、(7 + 9) // 10 = 16 // 10 = 1 となり、部分的に満たされたボックスでもまだ必要であることが正しく反映されています。
