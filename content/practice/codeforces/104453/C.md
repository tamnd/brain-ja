 ## 解決策
 ## 問題の理解

 それぞれ長さが正確に N の 2 つのバイナリ文字列が与えられます。先頭にゼロが含まれる可能性があるため、その「書かれた形式」は必ずしも正規のバイナリ表現であるとは限りません。 私たちのタスクは、ビット単位の XOR を位置ごとに計算し、先頭のゼロを削除した後に結果のバイナリ文字列を出力することです。 

概念的には、2 つの等しい長さのビット配列を整列させ、入力ビットが異なる場合は各位置が 1、同じ場合は 0 となる 3 番目の配列を生成します。 最後のステップは純粋に書式設定です。不必要な先行ゼロを出力してはなりません。これは、結果がゼロになる特殊な場合を除き、答えは同じバイナリ値を最短形式で表す必要があることを意味します。`0`。 

入力サイズ N は 100,000 まで大きくすることができます。 これにより、文字列を整数に繰り返し変換し、高レベルの構造で単純な大きな整数演算を使用して算術演算を実行するアプローチは即座に除外されます。これは、高価なループ内で繰り返し変換やビットごとの文字列連結を行うと、二次的な動作が発生する危険性があるためです。 文字列の線形スキャンが唯一の安全なターゲットの複雑さです。 

XOR の結果がすべて 0 の場合、微妙なエッジ ケースが発生します。 たとえば、両方の入力が同一である場合、次のようになります。`0001`XOR`0001`、生の結果は次のとおりです`0000`ただし、出力は次のようにする必要があります。`0`、空の文字列ではありません。 空かどうかをチェックせずに先頭のゼロを削除する不注意な実装では、誤って何も出力されません。 

もう 1 つの特殊なケースは、入力自体の先頭のゼロに起因します。 例えば、`0001`そして`0001`まだ生産すべき`0`、 ない`0000`または空行。 これは、正規化は XOR の計算前ではなく、後にのみ行う必要があることを強調します。 

## アプローチ

 ブルートフォース解釈では、両方のバイナリ文字列を数値として扱い、それらを整数に変換し、XOR を適用して、バイナリに戻します。 これは論理的に正しく、コードは非常にコンパクトです。 ただし、大きな N の変換ステップでは文字列あたり最大 100,000 文字の解析が必要となり、変換の繰り返しや非効率な多倍長整数演算により、実装言語や実行時の制約によってはパフォーマンスが低下する可能性があります。 Python では依然として線形ですが、厳密な競技プログラミング設定では、意図したソリューションにより、不必要な解析オーバーヘッドと追加の割り当てが回避されます。 

より直接的で信頼性の高いアプローチは、文字列を 1 文字ずつ処理することです。 ビットの XOR は位置間で独立しているため、各出力ビットは対応する入力ビットのみに依存します。 左から右にスキャンし、オンザフライで XOR を計算し、結果から先行ゼロを削除できます。 重要な点は、中間の数値表現をまったく保存する必要がないということです。 文字列は必要なものすべてをすでにエンコードしています。 

これにより、問題は 1 つの直線パスとそれに続く単純なトリミング ステップに軽減されます。 また、大きな一時整数を作成したり、文字列を繰り返し連結したりすることも避けます。

 | 直接文字列 XOR スキャン | O(N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 整数 N と 2 つのバイナリ文字列 A および B を読み取ります。 

両方の文字列にはすでに明示的な長さ情報が含まれているため、N の値は入力検証を超えて厳密に必要というわけではありません。 
2. 結果の文字を格納するために空のリストを初期化します。 

Python 文字列は不変であり、連結を繰り返すとパフォーマンスが O(N²) まで低下するため、文字列の連結を繰り返す代わりにリストを使用することが重要です。 
3. 0 から N − 1 までのインデックスを繰り返します。 

各インデックスで、A[i] と B[i] を比較します。 異なる場合は追記`'1'`結果リストに追加、そうでない場合は追加`'0'`。 
4. リストを文字列に変換します。 

この時点で完全な XOR 結果が得られますが、先頭にゼロが含まれる場合があります。 
5. 文字列から先頭のゼロを削除します。 

これは、最初に出現したものを見つけることによって行われます。`'1'`。 そのような文字が存在しない場合、結果は完全にゼロになります。 
6. ストリップの結果が空の文字列になった場合は、次のように出力します。`'0'`。 

これは、すべてのビットが相殺される特殊なケースを処理します。 
7. それ以外の場合は、トリミングされた文字列を出力します。 

### なぜ効果があるのか

 XOR は各ビット位置で独立して定義されます。出力ビットは、同じインデックスにある 2 つの入力ビットにのみ依存します。 これは、問題には位置間の依存関係がないため、単一パスで十分であることを意味します。 唯一のグローバル変換はフォーマットです。先頭のゼロを削除します。これにより、ビット シーケンスで表される数値は変更されません。 このアルゴリズムは、構築によってビットごとの正確性を維持し、最後にのみ表現を調整します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n = int(input().strip())
    a = input().strip()
    b = input().strip()

    res = []

    for i in range(n):
        if a[i] == b[i]:
            res.append('0')
        else:
            res.append('1')

    s = ''.join(res)

    # remove leading zeros
    i = 0
    while i < len(s) and s[i] == '0':
        i += 1

    ans = s[i:]
    if ans == "":
        ans = "0"

    print(ans)

if __name__ == "__main__":
    main()
```実装ではロジックが厳密に線形に保たれます。 このループは、中間の数値変換を行わずに XOR 結果を構築します。 蓄積にリストを使用すると、文字列の再割り当てを繰り返す必要がなくなります。 メインパスの後、2 回目のリニア スキャンで先頭のゼロが削除されます。 最後の条件は、XOR の結果がどこでもゼロである場合に正確さを保証します。 

よくある間違いは、先頭のゼロを削除すると空の文字列が生成される可能性があることを忘れることです。 もう 1 つの微妙な問題は、`int(a, 2) ^ int(b, 2)`非常に大きな文字列を完全に解析する必要があることを考慮していません。 Python は大きな整数をサポートしますが、これにより直接ビット単位の処理と比較して不要なオーバーヘッドが生じます。

 ## 特殊なケース

 重大なエッジケースは、すべてのビットがキャンセルされる場合です。 入力用`A = 0000`、`B = 0000`、計算された XOR 文字列は次のようになります。`0000`。 トリミング手順ではすべての文字が削除され、空の文字列が生成されます。 アルゴリズムはこれを明示的にチェックし、次の値を返します。`0`有効なバイナリ表現を保証します。 

もう 1 つのケースは、結果の先頭にゼロがあるが、完全にキャンセルされていない場合です。`A = 0010`、`B = 0001`。 XOR の結果は次のとおりです。`0011`。 トリミング ループは先頭のゼロのみを削除し、意味のある接尾辞を保持します。`11`。 これにより、トリミング ロジックは表現にのみ影響し、値には影響しないことが確認されます。 

最後に、N = 1 の場合、アルゴリズムは単一の比較に退化します。 このロジックは特別なケースを使用しなくても機能し、アプローチがすべての入力サイズにわたって均一であることを示しています。
