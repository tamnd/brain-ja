 ## 解決策
 ## 問題の理解

 今後のコンテストによる評価の変更を表す一連の個別の整数が与えられます。 これらの値を任意に並べ替えて、プレーヤーが実際にプレイすることになるコンテストの数をシミュレートするプロセスにそれらをフィードすることができます。 

このプロセスは、計画された 2 試合の長さから始まります。 プレーヤーは、並べ替えられたシーケンスを最初の要素から実行し始めます。 i 番目に行われたコンテストが終了した後、予定されているコンテストの総数は 2 増加しますが、これは非常に特殊なローカル パターンに限ります。つまり、現在の値が正である必要があり、前の値も正である必要があり、現在の正の値が前の値より厳密に大きくなければなりません。 これが発生すると、計画された長さが増加し、プレーヤーが当初の計画を超えて続行できる可能性があります。 そうでなければ何も変わりません。 

重要なのは、プロセスが逐次的であり、自動的に停止することです。 プレーヤーは、現在のインデックスが現在計画されている長さを超えない限り続行します。 i が計画された制限に達すると、未使用の要素が残っていたとしても実行は停止します。 

私たちの仕事は、実際に再生されたすべての値の合計が最大になるように配列を並べ替えることです。 

テスト ケースごとに n が最大 100,000 で、総和も制限されているという制約は、テスト ケースごとに少なくとも線形または線形に近い並べ替えベースの動作が必要であることを意味します。 二次関数や多くの順列にわたるシミュレーションを伴うものは、直ちに実行不可能になります。 

微妙な問題は、停止点が順列自体に依存することです。 単純にプレフィックスの合計を最大化するのではなく、その代わりに、事前に作成する増加する隣接する正のペアの数に応じて長さが決まる、動的に拡張するプレフィックスを制御します。 

素朴な直感を打ち破る特殊なケースの 1 つは、ポジティブなものとネガティブなものが交互に配置される場合です。 

たとえば、[5、4、3、2] のように、大きなポジティブを早い段階で降順に配置した場合、条件ではポジティブを厳密に増加させる必要があるため、拡張は行われません。 プロセスは長さ 2 ですぐに停止し、ほとんどのゲインが失われます。 単純な貪欲な「大きな数字を優先する」ことは完全に失敗します。 

もう 1 つの失敗例は、拡張機能を常に最大化する必要があると想定していることです。 拡張機能を使用すると、到達可能なインデックスが増加しますが、有害な負の値を強制的に含める可能性があります。 したがって、有効なポジティブ チェーンの数をやみくもに最大化することも最適ではありません。 

## アプローチ

 ブルートフォースアプローチでは、すべての順列を試し、各順序のプロセスをシミュレートします。 順列ごとに、左から右にスキャンし、現在の計画長を維持して、拡張ルールを適用します。 これには順列ごとに O(n) のコストがかかり、n 個あります。 n = 10 の場合でも不可能な順列。 

重要な観察は、正の値の間の局所的な構造のみがプロセスの拡張に重要であるということです。 否定語は拡張条件には決して関与せず、停止する前に否定語が含まれるかどうかによってのみ答えに影響します。 これにより、問題は 2 つの相反する目標に分けられます。1 つはすべてのポジティブな要素を早期に消費すること、もう 1 つは過剰な拡張により多くのネガティブな要素が取り込まれないようにすることです。 

拡張ルールは、隣接する増加する正のペアにのみ依存します。 これは、ポジティブをどのように配置するかを制御すれば、プロセスが何回拡大するかを直接制御できることを示唆しています。 

ここで、プロセスで実際に何をしたいのかを考えてみましょう。 延長ごとに全長が 2 増加します。実行順序ですべての正の値が負の値の前に表示されるように管理できれば、延長に寄与するすべてのプレイ済みポジションが有益になります。 ポジティブが使い果たされると、それ以上の拡張は再生されるプレフィックスにネガティブをもたらすだけであり、これは有害です。

これは構造の単純化につながります。すべての正の値を最初に配置し、その構造を安定して予測可能に保ちながら、その中で有効な隣接増加ペアの数を最大化したいと考えています。 ポジティブの間で有効なペアの最大数を保証する最も簡単な方法は、それらを昇順に並べ替えることです。 隣接するすべての正のペアが拡張条件を満たします。 

ネガティブは、内部の順序が拡張子にまったく影響しないため、任意の順序で最後に配置するのが最適です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース順列 + シミュレーション | O(n! · n) | O(n) | 遅すぎる |
 | ポジティブを並べ替え、ネガティブを追加 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 正の値と非正の値を分離する方法で順列を構築します。 

1. 配列を正と非正に分割します。 その理由は、拡張トリガーに参加できるのは正の値のみであるため、それらを混合すると不必要な中断が発生するだけであるためです。 
2. 正の値を昇順に並べ替えます。 これにより、隣接するすべての正のペアが拡張をトリガーするための両方の条件を満たすことが保証されます。つまり、両方が正であり、2 番目が最初のペアよりも大きいということです。 これにより、制御された方法で有効なトリガーの数が最大化されます。 
3. 残りの値 (ゼロと負の値) を任意に並べ替えます。通常は昇順に並べ替えます。これにより、それらの値に達した場合は、最も害の少ない値が先に表示されます。 
4. 最初にすべての正を出力し、次にすべての非正を出力します。 

この順序が機能する理由を理解するには、プロセスがどのように進化するかを理解する必要があります。 実行は常に正のブロックで開始され、このブロック内に留まっている間、すべての隣接するペアが計画された長さの延長に寄与します。 すべてのポジティブは連続していてソートされているため、プロセスはポジティブ セグメント全体を効果的に消費するまで延長され続けます。 

プロセスが非正のセグメントに入ると、条件には正の値が必要であるため、それ以上の拡張は発生できません。 その時点で、プロセスは最終的に計画された長さに達するかアレイを使い果たすまで直線的に実行されます。 

重要な構造的不変条件は、すべての拡張機会がソートされた正のプレフィックス内に完全に集中しており、否定からの中断によって引き起こされる有益なトリガーを見逃すことがないことです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        pos = []
        neg = []

        for x in a:
            if x > 0:
                pos.append(x)
            else:
                neg.append(x)

        pos.sort()
        neg.sort()

        res = pos + neg
        print(*res)

if __name__ == "__main__":
    solve()
```実装は構築を直接反映します。 計画された一致数の延長に寄与できるのは正の値のみであるため、値を符号で区切ります。 ポジティブをソートすると、連続するすべてのペアが拡張機能のトリガーに有効であることが保証されます。 

すべてのポジティブを使い果たす前にネガティブを含めても、新たな延長の機会が作成されずに合計が減少するだけであるため、ネガティブ ブロックは最後に追加されます。 

実装の微妙な点は、プロセスをシミュレートする必要がまったくないことです。 最適な置換の構造により、動的停止ルールが常に予測可能な方法で展開されることが保証されるため、明示的なシミュレーションはオーバーヘッドを追加するだけです。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | 各テスト ケースでは並べ替えが優先されます。 
| スペース | O(n) | パーティション化された配列の保存 |

 この制約により、すべてのテスト ケースにわたって要素の合計が最大 100,000 個まで許可されるため、制限内でテスト ケースごとの並べ替えが効率的に行われます。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import defaultdict

    def solve():
        t = int(input())
        for _ in range(t):
            n = int(input())
            a = list(map(int, input().split()))
            pos = [x for x in a if x > 0]
            neg = [x for x in a if x <= 0]
            pos.sort()
            neg.sort()
            print(*pos, *neg)

    old_stdout = sys.stdout
    sys.stdout = io.StringIO()
    solve()
    out = sys.stdout.getvalue().strip()
    sys.stdout = old_stdout
    return out

# sample-like sanity checks
assert run("1\n3\n1 3 2") == "1 2 3"

# all negatives
assert run("1\n3\n-5 -1 -10") == "-10 -5 -1"

# mix
assert run("1\n4\n4 2 1 -3") == "1 2 4 -3"

# single positive dominant structure
assert run("1\n5\n5 1 2 3 -1") == "1 2 3 5 -1"

 ## 特殊なケース

 エッジケースの 1 つは、正の値がない場合です。 この状況では、拡張は決して起こらないため、プロセスは単に最初の 2 つの要素を取得して停止します。 ネガを選別することで、早期損失を最小限に抑えることができます。 

もう 1 つのケースは、すべての値が正の場合です。 このアルゴリズムはすべてを昇順に並べ替えるため、隣接するすべてのペアが拡張機能を繰り返しトリガーするように強制されます。 これにより、プロセスが最大限に拡張され、未使用の値が残らないようになります。 

[100, -1, 2, 3, 4] のような混合ケースは、分離が重要である理由を示しています。 もし 100 を 1 位にすると、早い段階ですべての延長の機会を失うことになります。 正の値を [2, 3, 4, 100] として配置することで、到達可能な合計を最大化しながら制御されたチェーンが保証され、負の値は安全に延期されます。
