 ## 解決策
 ## 問題の理解

 小文字の文字列と、パターン「awa」の目標出現数が与えられます。 文字を自由に変更できますが、変更ごとに 1 つの位置が小文字に変更されます。 目標は、最終文字列に部分文字列「awa」が少なくとも k 回出現するようにすることです。各出現は、連続する 3 つの位置を使用する場合にのみカウントされます。重要なことは、2 つの異なる出現の間で位置が共有されないことです。 

タスクは、少なくとも k 個の互いに素な「awa」部分文字列を含む構成に到達するために必要な文字変更の最小数を決定することです。 

重要な構造上の制約は、「awa」の出現が重複できないことです。 これは、k 個のパターンを配置すると決めた場合、それらは 3k の異なるインデックスを占有し、インデックスが再利用されないようにパターンの間隔を空ける必要があることを直ちに意味します。 

入力サイズ n は最大 2000 であり、O(n^2) または O(nk) スタイルのソリューションが実現可能であることを示唆しています。 すべての部分文字列と k パターンのすべての選択に対する 3 次解は依然として合格する可能性がありますが、位置に対する指数関数は遅すぎます。 

微妙な特殊ケースの 1 つは、候補が重複している場合に発生します。 たとえば、「awawa」のような文字列には、位置 1 と 3 で始まる「awa」に等しい 2 つの部分文字列がありますが、それらは位置 3 で重なっています。両方の部分文字列が局所的に一致しても、両方を同時にカウントすることはできません。 単純な部分文字列カウンターは、素性を強制しない場合、有効なパターンを過大評価し、不正確な答えを導きます。 

もう 1 つの重要な点は、k が 0 に等しい場合です。この場合、パターンは必要なく、文字列の内容に関係なく、答えは 0 でなければなりません。 少なくとも 1 つのパターンを想定する単純な DP は、誤って大きな値を返したり、初期化に失敗したりする可能性があります。 

## アプローチ

 直接的なアプローチは、長さ 3 の k 個の互いに素なセグメントを選択するすべての方法を検討することです。セグメントごとに、それを「awa」に変換するために必要な変更の数を計算します。これは、単に不一致の文字の数です。 次に、k 個のセグメントの有効な組み合わせをすべて試します。 

この強引なアイデアは、問題を直接モデル化しているため、正しいです。選択された各セグメントは強制的に「awa」に変換され、編集コストは私たちが支払います。 問題は、k 個の互いに素なセグメントを選択する方法の数が膨大であることです。 重複しない有効なトリプルに限定したとしても、間隔制約のあるおよそ n 個の可能な開始位置から k 個のセグメントを選択することになり、組み合わせ爆発が発生します。 

重要な観察は、これが重複しない間隔を持つ線上の重み付き選択問題であるということです。 各間隔は固定長 3 であり、コストがかかります。 正確に k 個の間隔が必要であり、重複はなく、総コストを最小限に抑えます。 これは古典的な動的プログラミング構造であり、文字列を左から右に処理し、各位置で間隔を開始するかどうかを決定します。 

位置 i でそれをスキップするか、i で「awa」ブロックを開始することを検討する DP を定義します。これにより、i、i+1、i+2 が消費され、不一致に等しいコストが寄与します。 これにより、問題は 2 つの状態 (選択されたブロックの位置と数) を持つ線形 DP に縮小されます。 

i にブロックを配置すると、次の有効な位置が i+3 になり、自然に素性が強制されるため、遷移は単純です。

 ## アルゴリズムのチュートリアル

 文字列を左から右に処理し、すでに配置された「awa」ブロックの数を追跡します。

1. dp[i][j] を、j 個の有効な「awa」セグメントがすでに配置されている、位置 i から始まるプレフィックスを使用して必要な最小限の変更数として定義します。 この状態は接尾語の決定の問題を表します。 
2. 各位置 i には 2 つの選択肢があります。 j を変更せずに、位置 i をスキップして i+1 に移動できます。 これは、i で「あわ」を開始しないことを表します。 
3. 少なくとも 3 文字が残っており、j < k の場合は、i から始まる「awa」を作成してみることができます。 このアクションのコストは、s[i]、s[i+1]、s[i+2] と文字列「awa」の間の不一致の数として計算されます。 
4. このオプションを選択すると、i+3 に移動し、j を 1 ずつ増やします。3 ずつジャンプすると、自動的に非オーバーラップが強制されます。 
5. 答えは dp[0][0] です。これは、構築されたパターンがゼロの状態から開始することを意味します。 

遷移の背後にある理由は、すべての有効な解は長さ 3 のブロックの開始位置のセットに一意に分解でき、DP はこれらの選択肢を反復せずにインデックスの昇順で列挙するということです。 

### なぜ効果があるのか

 核となる不変条件は、すべての状態 (i, j) で、dp が、i で始まるサフィックス内に正確に j 個の互いに素な「awa」ブロックを完全に配置する有効なすべての方法にわたる最小コストを格納することです。 すべての遷移は有効性を保持します。スキップするとサフィックスが保持され、ブロックを配置するとちょうど 3 文字が消費され、次の独立したサフィックスに進みます。 i 内でのみ前に進むため、構成を 2 回カウントしたり、無効な重複方法で構成したりすることはできません。 これにより、k ブロックの実行可能なすべての選択が正確に 1 つの DP パスに対応し、DP がそのコストを正しく評価することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**18

def solve():
    n, k = map(int, input().split())
    s = input().strip()

    # dp[i][j] = min cost from i with j blocks already used
    # we use rolling over i, so dp[i] is array of size k+1
    dp = [[INF] * (k + 1) for _ in range(n + 4)]

    # base: at position n, cost is 0 if j == k else impossible
    for j in range(k + 1):
        dp[n][j] = 0 if j == k else INF

    # fill backwards
    for i in range(n - 1, -1, -1):
        for j in range(k + 1):
            # option 1: skip
            dp[i][j] = dp[i + 1][j]

            # option 2: take block starting at i
            if j < k and i + 2 < n:
                cost = 0
                cost += (s[i] != 'a')
                cost += (s[i + 1] != 'w')
                cost += (s[i + 2] != 'a')
                dp[i][j] = min(dp[i][j], cost + dp[i + 3][j + 1])

    print(dp[0][0])

if __name__ == "__main__":
    solve()
```DP テーブルは右から左に構築されるため、i+1 および i+3 への遷移はすでに計算されています。 基本条件では、最後に到達するまでにちょうど k 個のブロックが形成されなければならないことが強制されます。 それ以外の場合、状態は無効です。 

コスト計算は状態ごとにローカルで一定時間であり、2 つの遷移はアルゴリズムの説明を直接反映しています。つまり、現在のインデックスから始まる「awa」をスキップまたは配置します。 

微妙な詳細は、dp[n][j] 初期化の使用です。 少なくとも k 回の出現が必要であり、満たされていない追加の要件は不可能であるため、最終的には j == k の状態のみが有効になります。

 ## 特殊なケース

 k = 0 の場合、ブロックは必要ないため、DP は最終層ですべての状態を有効なものとして正しく初期化します。 スキップによって常に実現可能性が維持されるため、これにより dp[0][0] は強制的に 0 のままになります。 

「awawa」のような重複パターンの場合、遷移構造では、ブロックが i で取得されると、位置 i+1 または i+2 の再利用は決して許可されません。 たとえ別の有効な「awa」が i+2 から始まっていても、DP は厳密に前方に進み、素の選択のみが考慮されるため、当然無視されます。
