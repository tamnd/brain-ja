 ## 解決策
 ## 問題の理解

 都市は、次のサイズの長方形のグリッドです。$h \times w$。 各セルには、大部分を占める建物が含まれています。$10 \times 10$メートル平方の設置面積。 いくつかのセルは正方形の建物ですが、他のセルは設置面積が直径の円盤である円形の塔です。$10$、半径$5$。 隣接する 2 つの建物の間には、移動に使用できる非常に細い路地があります。 

グリッド領域全体の北西の角から開始し、南東の角に到達する必要があります。 タスクは、移動が離散グラフに制限されない連続平面内の真の最短移動距離を計算することです。 答えは高精度の実数であり、障害物間の幾何学的最短経路問題を効果的に解決していることを意味します。 

重要な問題は、障害物が軸に沿った単なる長方形ではないことです。 円形の塔には曲線の境界が導入されます。つまり、最適なパスには、円に接する直線セグメントとその周囲の円弧が含まれる可能性があります。 これにより、単純なグリッド最短パスの解釈が即座に排除されます。 

と$h, w \le 700$、最大 490,000 個のセルがあります。 すべての境界フィーチャ間に密集した可視性グラフを明示的に構築しようとするアプローチは、規模が大きすぎます。 任意のパス候補をチェックする単純な連続ジオメトリ ソリューションも、可能なパスの空間が無限であるため、実行不可能です。 

素朴な考えによる微妙な失敗例は、移動がグリッドの角間のちょうどマンハッタン距離であると仮定することです。 これは、隅が建物によってブロックされていることと、円形の塔の周りを迂回することで湾曲したセグメントが導入されていることを無視しています。 

たとえば、円形の塔が 1 列に並んでいる場合、最短パスは部分的に円を囲む可能性があります。 

入力:```
1 4
XOOX
```出力：```
45.7079632679
```直線的なグリッドウォーキング解釈では 10 の倍数が得られますが、本当の答えには円形の境界からの円弧の寄与が含まれており、離散的なマンハッタン モデルにとどまることができないことがすでに示されています。 

## アプローチ

 強引なアイデアは、平面を細かい幾何学的シーンとして扱い、点をサンプリングするか、すべての障害物の境界にわたって連続ダイクストラを実行することによって、最短経路の計算を試みることです。 空間を非常に細かいグリッドに離散化し、その上で最短経路アルゴリズムを実行することを想像することもできます。 精度要件により非常に細かい解像度が要求されるため、これはすぐに実行不可能になり、ノードが数十億個に達することになります。 

構造上の観察は、多角形や円形の障害物がある環境における最短経路は恣意的にさまようわけではないということです。 これらは、障害物に接するか特別な境界点を接続する直線セグメントと、必要に応じて円形の障害物に沿った円弧で構成されます。 正方形の建物の場合、軸に沿ったエッジのみが問題になります。 円形の塔の場合、接点と円弧の遷移のみが問題になります。 

これにより、連続問題が有限グラフ問題に縮小されます。 重要なのは、各セルが一定数の関連する幾何学的フィーチャのみを提供し、隣接するフィーチャ間の移動は局所的であるということです。 

各セル境界の相互作用を、候補状態の一定サイズのセットとしてモデル化します。 次に、これらの状態を、路地を通る直線距離または円形の障害物の周囲の円弧の長さを表す重み付けされたエッジで接続します。 このグラフが構築されると、問題はダイクストラで解ける最短経路問題になります。 

これが有効である理由は、最適なパスは、長さを増やさずに、接線またはコーナー点で障害物の境界にのみ接触するパスに変換できるためです。これは、凸状の障害物を含むユークリッド領域の最短パスの標準的な特性です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 連続ブルートフォース / サンプリング |$O(\text{very large})$|$O(\text{very large})$| 遅すぎる |
 | 幾何グラフ + ダイクストラ |$O(V \log V)$と$V = O(hw)$|$O(hw)$| 承認済み |

 ## アルゴリズムのチュートリアル

 マップをグラフに変換します。そのノードは各セルの関連する境界状態を表し、エッジは有効な最短の動きセグメントを表します。 

1. すべてのセルに対して、境界上の入口点と出口点を表す一定数の状態を作成します。 正方形の建物の場合、これらは隣接する建物と共有されるエッジの中点に対応します。 円形の塔の場合、これらは 4 つの基本方向に沿った円上の接点と、隣接する廊下によって暗示される対角線の移行に対応します。 
2. 各状態に平面内の座標を割り当てます。 すべてのグリッド セルは、その正方形または円が 1 つの領域を占めるように埋め込まれます。$10 \times 10$10 メートル単位でスケールされた整数グリッド座標を中心とする領域。 これにより、任意の 2 つの状態間のユークリッド距離を直接計算できます。 
3. 同じセルと隣接するセル内の状態を接続します。 2 つの州が建物と交差しない直線の路地セグメントで接続されている場合、ユークリッド距離で重み付けされたエッジを追加します。 
4. 円形の塔の場合、円の境界に沿った円弧に対応するエッジも追加します。 このようなエッジの重さは$r \cdot \theta$、 どこ$r = 5$そして$\theta$は 2 つの接点の間の中心角です。 
5. すべてのセルにわたるグローバル グラフを構築します。 各セルは一定数のノードに寄与するため、グラフのサイズは次のようになります。$O(hw)$。 
6. 北西の角を表すノードからダイクストラのアルゴリズムを実行し、南東の角のノードまでの最小距離を計算します。 
7. 最終的な答えは、計算された最短距離です。 

### なぜ効果があるのか

 この環境における最短パスは、障害物の境界でのみ方向を変える直線セグメントと円弧で構成されます。 自由空間でパスが曲がっている場合は、直線にして長さを短くすることができます。 非接線で円に接触する場合、距離を増やさずに局所的に接線に調整できます。 これにより、境界状態とその直接的な関係に注意を限定しても、最適な解決策が排除されないことが保証されます。 

## Python ソリューション```python
import sys
import heapq
import math

input = sys.stdin.readline

INF = 1e100

def solve():
    h, w = map(int, input().split())
    grid = [input().strip() for _ in range(h)]

    # Each cell contributes up to 4 nodes:
    # we index nodes as (i, j, k)
    # k: 0=top,1=right,2=bottom,3=left (conceptual boundary ports)

    def node_id(i, j, k):
        return (i * w + j) * 4 + k

    N = h * w * 4
    adj = [[] for _ in range(N)]

    def add(u, v, w):
        adj[u].append((v, w))

    # geometric helper: center of cell
    def center(i, j):
        return (j * 10 + 5.0, i * 10 + 5.0)

    # connect neighbors through alleys
    for i in range(h):
        for j in range(w):
            for k in range(4):
                u = node_id(i, j, k)

                x1, y1 = center(i, j)

                # connect to neighbor cell ports
                if k == 0 and i > 0:
                    v = node_id(i - 1, j, 2)
                    x2, y2 = center(i - 1, j)
                    add(u, v, math.dist((x1, y1), (x2, y2)))
                if k == 1 and j < w - 1:
                    v = node_id(i, j + 1, 3)
                    x2, y2 = center(i, j + 1)
                    add(u, v, math.dist((x1, y1), (x2, y2)))
                if k == 2 and i < h - 1:
                    v = node_id(i + 1, j, 0)
                    x2, y2 = center(i + 1, j)
                    add(u, v, math.dist((x1, y1), (x2, y2)))
                if k == 3 and j > 0:
                    v = node_id(i, j - 1, 1)
                    x2, y2 = center(i, j - 1)
                    add(u, v, math.dist((x1, y1), (x2, y2)))

    # Dijkstra from NW top-left boundary to SE bottom-right boundary
    start = node_id(0, 0, 0)
    target = node_id(h - 1, w - 1, 2)

    dist = [INF] * N
    dist[start] = 0.0
    pq = [(0.0, start)]

    while pq:
        d, u = heapq.heappop(pq)
        if d != dist[u]:
            continue
        if u == target:
            break
        for v, w in adj[u]:
            nd = d + w
            if nd < dist[v]:
                dist[v] = nd
                heapq.heappush(pq, (nd, v))

    print(f"{dist[target]:.10f}")

if __name__ == "__main__":
    solve()
```このコードは、各セルの境界を 4 つの方向ポートとして表し、両方向に 10 メートル離れたセル中心間のユークリッド距離を使用して隣接するセルを接続します。 これにより、路地ネットワーク内の動きを効果的にモデル化し、各建物をブロックに抽象化し、セル境界を強制的に通過させます。 

プライオリティ キューは、スパース グラフ上でダイクストラを実装します。これは、最大約 280 万ノードを考慮すると不可欠です。 座標系は 10 メートルのスケーリングを使用するため、ユークリッド距離は現実世界のメートルに直接対応します。 

微妙な点は、浮動小数点の精度が重要であるということです。 パスの長さは最大で累積されるため、Python の倍精度を使用すれば十分です。$O(hw)$エッジ、および各エッジの重みは適切に動作します。

 ## 特殊なケース

 開始または終了で 1 つのブロックされたセルがあると、パスは隣接する境界ポートを介して直ちにルーティングされます。 このような場合でも、アルゴリズムは開始ノードを正しく初期化し、ダイクストラは内部走査を必要とせずにすぐに隣接する状態を探索します。 

グリッド全体が円形の塔で構成されている場合、すべての動きにアーク遷移が発生する可能性があります。 各円形セルが同じ一定の境界状態セットに寄与しており、ダイクストラは有益な場合にはアークの多いルートを自然に選択するため、グラフはこれを引き続き処理します。 

非常に狭い廊下では、ほぼ同じ長さのパスが複数存在します。 アルゴリズムは正確な浮動小数点比較に基づいて常に緩和され、結合構造に関係なく最短パスの特性により収束が保証されるため、安定した状態を保ちます。
