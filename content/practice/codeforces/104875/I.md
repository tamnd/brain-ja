 ## アルゴリズムのチュートリアル

 の再構築を分離します。$a$そして$b$、トランスクリプトを正しく解釈すると、それらは独立しているためです。

### なぜ効果があるのか

 すべての有効な解は 2 つの独立した可分性システムを満たさなければなりません。 Fizz 制約は、次の許容値を完全に特徴付けます。$a$、およびバズ制約は、の許容値を完全に特徴付けます。$b$。 唯一の追加要件は、マークされていない位置での偶発的な分割の排除であり、これはフィルタリング中に明示的に適用されます。 すべての制約はトランスクリプトに対して直接チェックされるため、生き残った候補者はすべてのインデックスに対してまったく同じラベル付けを再現し、正確さを保証する必要があります。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

def get_candidates(n, vals, bad):
    g = 0
    for v in vals:
        g = math.gcd(g, v)

    if g == 0:
        return list(range(1, 10**6 + 1))

    divisors = []
    i = 1
    while i * i <= g:
        if g % i == 0:
            divisors.append(i)
            if i * i != g:
                divisors.append(g // i)
        i += 1

    divisors.sort()

    res = []
    for a in divisors:
        ok = True
        for x in range(a, n + 1, a):
            if bad[x]:
                ok = False
                break
        if ok:
            res.append(a)
    return res

def solve():
    c, d = map(int, input().split())
    arr = input().split()
    n = d - c + 1

    fizz_vals = []
    buzz_vals = []

    bad_fizz = [False] * (n + 1)
    bad_buzz = [False] * (n + 1)

    for i, s in enumerate(arr, start=1):
        if s == "Fizz":
            fizz_vals.append(i)
            bad_buzz[i] = True
        elif s == "Buzz":
            buzz_vals.append(i)
            bad_fizz[i] = True
        elif s == "FizzBuzz":
            fizz_vals.append(i)
            buzz_vals.append(i)
        else:
            bad_fizz[i] = True
            bad_buzz[i] = True

    a_list = get_candidates(n, fizz_vals, bad_fizz)
    b_list = get_candidates(n, buzz_vals, bad_buzz)

    print(a_list[0], b_list[0])

if __name__ == "__main__":
    solve()
```実装では、まずトランスクリプトをインデックスベースの制約に変換します。 配列`bad_fizz`そして`bad_buzz`約数候補の分割が禁止されている位置にマークを付けます。 gcd ステップでは構造上の必然性が抽出され、一方、除数の列挙により小さな候補セットが生成されます。 複数のチェック ループにより、禁止された位置で誤って Fizz または Buzz を作成する候補は確実に拒否されます。 最後のステップでは、最初の有効なペアを選択するだけです。 

実装の微妙な詳細は、セグメント内のインデックスが 1 から始まり、割り算ロジックに直接一致するため、オフセット処理が必要ないことです。

 ## 特殊なケース

 セグメントに単純な数値のみが含まれている場合、両方の$a$そして$b$すべてのインデックスを分割することは避けなければなりません。 この状況では、gcd ベースの候補セットは 0 に相当する構造のすべての約数に折りたたまれますが、フィルタリング ステップでは、位置を決して分割しない値を除くすべてが削除されます。 アルゴリズムは当然、次のような有効な自明なペアを返します。$(1,1)$これは、どの位置もパラメータで割り切れないという要件に一致します。 

すべての位置が FizzBu​​zz の場合、両方の候補セットは完全なインデックス セットから導出されます。 すべての有効な$a$そして$b$セグメント内のすべてのインデックスを除算する必要があるため、両方ともセグメント gcd 構造の約数から取得されます。 禁止された位置が存在しないため、フィルタリング ステップではすべての約数が受け入れられ、元の定義の組み合わせ自由度に一致する任意のペアが有効になります。 

交互パターンなど、Fizz 制約と Buzz 制約が重なり合う場合、gcd ステップだけでは候補を過剰に制約してしまいます。 フィルタリングのステップにより、偶発的な割り算が確実に排除され、共有の約数から生じる誤検出が防止されます。
