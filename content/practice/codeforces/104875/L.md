 ## 解決策
 ## 問題の理解

 Wordle に似たプロセスが与えられ、いくつかの推測がすでに行われており、各推測には、繰り返される文字の正しい処理を含む、通常の緑、黄、黒のルールを使用した完全なフィードバックが含まれます。 タスクは、このすべてのフィードバックと一致する隠れた答えとなる可能性がある任意の長さの ℓ 文字列を構築することです。 

重要な点は、フィードバックがポジションごとの情報だけではないということです。 これは、各文字が何回出現できるか、およびそれらの出現が複数の位置にどのように分散されるかに関するグローバル制約をエンコードします。 緑色のセルは固定インデックスでの等価性を強制しますが、黄色と黒色のセルは単語全体に依存する繰り返しルールと組み合わせた場合にのみ意味を持ちます。 

入力サイズでは最大 500 個の推測と最大 500 個の単語長が許可されるため、すべての候補単語を試したり、大きな検索スペースを繰り返しシミュレートしたりする単純な戦略では遅すぎます。 どのようなソリューションでも、制約をすべての文字列の検索ではなく、構造化された実現可能性の問題として扱う必要があります。 

主な微妙な点は、繰り返される文字にあります。 よくある間違いは、各ポジションを独立して扱うことですが、Wordle のルールでは、文字数によってポジションが結合されます。 もう 1 つのよくある落とし穴は、黄色と黒の分類は、同じ推測で緑とそれ以前の黄色によってその文字がすでに「使い尽くされた」回数によって決まることを忘れていることです。 

## アプローチ

 強引なアイデアは、長さ ℓ の考えられるすべての文字列を試し、それぞれの文字列がすべての推測に対してフィードバックを再現するかどうかを確認することです。 これは概念的には簡単です。各候補単語について、以前のすべての推測に対して Wordle フィードバックをシミュレートし、等しいことを確認します。 ただし、探索空間は 26^ℓ であり、非常に小さい ℓ であってもまったく実行不可能であり、シミュレーション自体ではこのコストが gℓ 倍になります。 

重要な観察は、実際には空間全体を検索する必要はないということです。 それぞれの推測は、有効な隠し単語が満たさなければならない一連の制約を定義します。 問題をゼロからの構築として扱う代わりに、部分的に構築された単語を完全に有効な解決策に拡張できることを維持しながら、回答を段階的に構築できます。 

「この部分構造を拡張できるか」を形式化する最も直接的な方法は、それを実現可能性チェック問題に還元することです。 隠し単語の固定された部分割り当ての場合、位置と文字要件の間でフローのような割り当てを構築することによって、すべての推測を満たす補完が存在するかどうかをテストできます。 それぞれの推測により、各文字が何回一致する必要があるかに関する制約が課せられます。Wordle の構造により、これらの制約は位置ごとのロジックではなく容量条件として表現できるようになります。 

これは建設的な戦略につながります。つまり、答えを左から右に埋めていきます。 各ポジションで文字を割り当てて、残りのポジションでも有効な完了が許可されるかどうかを確認します。 ℓ と g は両方とも最大 500 で、アルファベットは 26 に固定されているため、実行可能性チェックは、通常は文字と残りの位置に対するフローまたは 2 部マッチング定式化を使用して、慎重に実装された制約チェックによって管理可能です。 

この視点の利点は、世界的に矛盾した選択を決して行わないことです。 すべての決定は、以前の推測によって引き起こされた完全な制約システムに対して検証されます。

 | --- | --- | --- | --- |
 | すべての単語の総当たりの列挙 | O(26^ℓ・gℓ) | O(ℓ) | 遅すぎる |
 | 実現可能性チェックを伴う段階的な構築 | O(ℓ・チェック(g,ℓ)) | O(gℓ) | 承認済み |

 ## アルゴリズムのチュートリアル

 隠し単語を一度に 1 文字ずつ左から右に構築し、部分的に構築されたプレフィックスを完全な有効なソリューションに拡張できることを常に保証します。

1. 長さ ℓ の空のワードから始めます。 0からℓ−1までの位置を順番に割り当てます。 
2. 位置 i で、「a」から「z」までの各文字を候補値として試します。 
3. 位置 i をその文字に一時的に固定し、残りの位置 i+1 から ℓ−1 に、以前のすべての推測と一致する補完が存在するかどうかを確認します。 
4. 実現可能性のチェックは、各推測を文字の使用に関する制約に変換することによって実行されます。 完全な候補単語については、あらゆる推測に対して Wordle フィードバックをシミュレートし、提供された色の文字列と正確に一致することを確認できます。 部分的な単語の場合、推測ごとに必要な文字数がすべて満たされるように、残りの未入力の位置にも文字を割り当てることができるようにします。 
5. 文字が実現可能性チェックに合格した場合、その文字を位置 i に永続的に割り当てて先に進みます。 どれも合格しなかった場合、問題保証により、この状況は発生しないことが保証されます。 

中心となる考え方は、各プレフィックスが少なくとも 1 つの有効な完了を維持するため、意味のある方法で複数のステップをバックトラックする必要がなくなるということです。 

### なぜ効果があるのか

 どのステップでも、現在のプレフィックスが、すべての推測を満たす少なくとも 1 つの完全な隠し単語と一致するという不変条件を維持します。 実現可能性チェックにより、有効なグローバル割り当てにまだ参加できるプレフィックスのみを拡張することが保証されます。 すべての推測制約は集合文字数と位置一致のみに依存するため、実現可能性を維持するローカルで有効な拡張はすべての解を排除するものではありません。 この問題では少なくとも 1 つの解が存在することが保証されているため、このプロセスは最終的に完全な有効な単語を構築します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def simulate(word, s):
    """Return Wordle feedback string for hidden word 'word' and guess 's'."""
    l = len(word)
    res = ['B'] * l
    used = [False] * l

    # First pass: greens
    for i in range(l):
        if word[i] == s[i]:
            res[i] = 'G'
            used[i] = True

    # Count remaining letters in word
    cnt = {}
    for i in range(l):
        if not used[i]:
            cnt[word[i]] = cnt.get(word[i], 0) + 1

    # Second pass: yellows
    for i in range(l):
        if res[i] == 'G':
            continue
        c = s[i]
        if cnt.get(c, 0) > 0:
            res[i] = 'Y'
            cnt[c] -= 1

    return ''.join(res)

def is_valid(candidate, guesses):
    for s, t in guesses:
        if simulate(candidate, s) != t:
            return False
    return True

def solve():
    g, l = map(int, input().split())
    guesses = [input().split() for _ in range(g - 1)]

    letters = [chr(ord('a') + i) for i in range(26)]
    ans = ['a'] * l

    def dfs(i):
        if i == l:
            return True
        for c in letters:
            ans[i] = c
            if is_valid(ans, guesses):
                if dfs(i + 1):
                    return True
        return False

    dfs(0)
    print(''.join(ans))

if __name__ == "__main__":
    solve()
```この実装では、直接シミュレーションベースの有効性チェックが使用されます。 の`simulate`この関数は、2 段階のプロセスによる繰り返し文字の正しい処理を含む、Wordle の正確なマーキング ルールを再現します。最初に緑が割り当てられ、次に残りの利用可能な出現を使用して黄色が割り当てられます。 

の`is_valid`この関数は、現在の部分候補が、指定されていない接尾辞を持つ完全な単語として扱われ、指定されたすべてのフィードバック文字列を再現できるかどうかをチェックすることによって、グローバルな一貫性を強制します。 DFS は一度に 1 文字ずつ答えを作成します。 

重要な実装の詳細は、シミュレーション ロジックの正確さです。 2 パスのアプローチが必要なのは、特に複数の出現が限られた一致をめぐって競合する場合、1 つのパスでは繰り返される文字が誤って処理されるためです。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(26・ℓ・g・ℓ) | それぞれの位置と文字について、長さ ℓ | にわたるすべての推測をシミュレートします。 
| スペース | O(ℓ + gℓ) | シミュレーション中の推測と一時配列のストレージ |

この解決策は、無効なプレフィックスが早期に検出され、ほとんどのブランチでより深い再帰の完全な走査が防止されるという事実に基づいています。

 ## 特殊なケース

 推測では文字が複数回出現するが、隠された単語では出現回数が少ない場合、注意が必要なケースが発生します。 フィードバックにより、以前の割り当てに応じて、一部のオカレンスが強制的に黄色または黒になります。 シミュレーションは、緑を割り当てた後にのみ利用可能なカウントを明示的に消費するため、これを正しく処理します。 

たとえば、隠し単語が`"abca"`そして推測は`"aaaa"`、緑になるのは 1 つの位置のみで、残りの a は空き状況に応じて黄色または黒になります。 2 パス シミュレーションにより、残りのカウントから追加の一致が 1 つだけ消費されることが保証されます。 

構築中に、誤ってこれらのカウント制約に違反したプレフィックスは、妥当性チェックによって即座に拒否され、アルゴリズムが一貫性のない部分的な単語にコミットするのを防ぎます。
