 ## 解決策
 ## 問題の理解

 円形のピザを次のように分割して与えられます。$n$スライス。 各スライスには、そのスライスを食べる顧客によって割り当てられた正確に 2 つのトッピングが含まれています。 すべてのスライスにわたって、$k$可能なトッピングの種類。 

重要な要件は、個々のスライスに直接関係するのではなく、準備中にトッピングをどのように適用するかにあります。 各トッピングの種類は、円に沿ったスライスの単一の連続セグメントに追加する必要があります。 ピザは円形であるため、セグメントは配列の端を囲む可能性があります。 すべてのスライスは、指定された 2 つのトッピングを正確に使用する必要があり、余分なトッピングはありません。 

そこで、それぞれのトッピングを割り当てようとしています$t$円上の連続した間隔に、スライスごとに$i$必要なペアで$(a_i, b_i)$、 両方$a_i$そして$b_i$位置をカバーする間隔がある$i$、他のトッピングはそれをカバーしません。 

これにより、問題は幾何学的一貫性条件に変わります。各トッピングを円上の単一の円弧として表現し、各スライスを正確に 2 つの円弧の交点として表現しようとしています。 

制約$n, k \le 10^5$すべての間隔配置を試行したり、二次オーバーラップ チェックを使用してトッピングごとの構成をシミュレートしたりするアプローチは直ちに除外してください。 スライスまたはトッピングのペアごとの比較を伴うものはすべて、隣接追跡やグラフ制約などの線形または線形に近い構造に還元する必要があります。 

微妙な問題は循環性から生じます。 多くの単純な解決策は、配列を線形として扱い、ラップアラウンド間隔が欠落しているために失敗します。 別の失敗モードは、各トッピングの出現が元の順序で単一の間隔を形成する必要があると仮定することですが、これは、異なるトッピング間の一貫性をチェックしない限り当てはまりません。 

誤解を招きやすい具体的なケースとしては、トッピングが 2 つの分離されたブロックに直線的に表示されるが、ラップアラウンドにより実際には有効である場合があります。 

入力:```
5 3
1 2
3 1
1 3
2 3
2 2
```単純な線形間隔チェックでは、トッピング 1 が位置 1、2、3 に出現することが示される可能性がありますが、これは問題ありませんが、出現が位置 1 と 5 のように分割されている場合、ラップアラウンドによって連続しているにもかかわらず、線形手法では誤って拒否される可能性があります。 

最も難しいのは、各トッピングが単一の間隔を形成する循環的な順序付けの解釈が存在するかどうかを判断しなければならないことです。 

## アプローチ

 強引な視点は、各トッピングに円上の間隔を割り当てようとしているところを想像することから始まります。 各スライスには制約が課せられます。2 つのトッピングが両方ともその位置をカバーする必要があります。 これは、すべてのスライスと一貫性のある各トッピングの開始点と終了点を選択することを試みることを示唆しています。 

素朴な試みは、トッピングを 1 つずつ処理し、可能なすべての間隔の開始を試し、すべてのスライスが満足できるかどうかを確認することです。 たとえ始まりを決めたとしても、終わりを選ぶとまだ残る$O(n)$トッピングごとに可能性があり、検証するにはすべてのスライスをスキャンする必要があります。 これは次のようなことにつながります$O(k \cdot n^2)$最悪の場合、それは不可能です$10^5$。 

重要な構造的洞察は、視点を反転することです。 トッピングに間隔を割り当てる代わりに、トッピングのペア間の制約について推論します。 各スライス$(a, b)$の間隔を強制します$a$そして$b$正確にその位置で重なり合います。そしてさらに重要なことに、円周上に順序制約が生じます。つまり、円周上で間隔の境界が一貫した方法で交互に配置されなければなりません。 

これにより、問題は、各トッピングの出現が単一の連続した円弧を形成するように、円上に間隔の端点を配置できるかどうかを確認することに変わります。 これは、巡回順序内の各トッピングの出現が単一のブロックとして現れるかどうかをチェックすることと同等であり、順序付け候補を構築し、隣接制約の一貫性を検証することでテストできます。 

標準的な削減は、連続するスライスによって引き起こされるトッピング間の制約のグラフのような構造を構築し、その間隔を離れた後に「再入力」を強制されるトッピングがないことを検証することです。 これは、最初と最後の発生を記録するリニア スキャンとなり、間隔の連続性を壊すインターリーブ パターンが存在しないことを保証する一貫性チェックと組み合わせられます。 

より具体的で実装可能なビューは次のとおりです。各位置を円上のノードとして扱い、各トッピングはそのすべての出現が 1 つの円弧内に含まれている必要があります。 開始点を選択して円を線形化してから、各トッピングについて、その線形化内でその出現が最大でも 1 つの連続セグメントを形成するかどうかを確認します。これにより、トッピングの出現の分割を避ける回転を選択することでラップアラウンド処理が可能になります。 正確かどうかは、トッピングの出現が複数のブロックに分割されないローテーションを見つけるかどうかにかかっています。 

これにより、問題は、そこから始まる線形順序ですべてのトッピングが単一の間隔で表示されるように、円上にカット ポイントが存在するかどうかをチェックすることに集約されます。 倍増配列表現における各トッピングの最初と最後の出現を計算し、候補カット位置を効率的にテストできます。

 ## アルゴリズムのチュートリアル

 1. スライスを 1 回スキャンして、各トッピングが表示されるすべての位置を記録します。 

各トッピングはアクティブでなければならないインデックスのリストを収集し、これらのインデックスによって 1 つの連続した間隔を形成できるかどうかが決まります。 
2. 円形配列を 2 倍の長さの配列に拡張します。$2n$、どこの位置$i+n$ミラーの位置$i$。 

これにより、ラップアラウンド間隔を線形構造の通常の間隔にすることができます。 
3. トッピングごとに、倍増配列内のその出現箇所をすべて計算します。 

次に、これらの出現が最大でもある長さの間隔内に収まるかどうかを検討します。$n$。 これは、円上の有効なカットを選択することに対応します。 
4. 各トッピングについて、2 倍の表現におけるその出現の最小位置と最大位置を計算します。 

トッピングのスプレッドが超過した場合$n$、それは、その出現が円上で連続することができない方法で折り返されていることを意味します。 
5. トッピングの出現間隔を分割しないグローバル カット ポイントが存在することを確認して、すべてのトッピングの一貫性を確認します。 

これは、各トッピングの出現範囲の補完間隔によって作成される「禁止されたギャップ」に含まれない点を見つけることと同じです。 
6. 差分配列または間隔カバレッジ手法を使用して、可能なカット位置をスイープして、少なくとも 1 つの有効なカットが存在するかどうかを判断します。 
7. 有効なカットが存在する場合は「可能」を出力し、存在しない場合は「不可能」を出力します。 

### なぜ効果があるのか

 各トッピングは、円上の 1 つの接続された円弧を占有する必要があります。これは、すべてのトッピングが最大でも 1 つの連続した長さのセグメント内に収まる回転が存在すると言っているのと同じです。$n$。 無効な構成では、回転ごとに必ず何らかのトッピングが 2 つの別々のセグメントに表示されることになります。これは、すべての禁止された間隔の外側に有効なカット ポイントが存在しないこととして現れます。 スイープ構築はこれらの禁止領域を正確にエンコードするため、カバーされていないポイントの存在は有効なグローバル配置と同等です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    pos = [[] for _ in range(k + 1)]

    arr = []
    for i in range(n):
        a, b = map(int, input().split())
        arr.append((a, b))
        pos[a].append(i)
        pos[b].append(i)

    # duplicate circle
    for t in range(1, k + 1):
        for p in pos[t]:
            pos[t].append(p + n)

    diff = [0] * (2 * n + 2)

    for t in range(1, k + 1):
        if not pos[t]:
            continue
        pos[t].sort()
        mn = pos[t][0]
        mx = pos[t][-1]

        # check if span fits in window of size n
        if mx - mn + 1 <= n:
            diff[mn] += 1
            diff[mx + 1] -= 1
        else:
            # wrap interpretation: forbidden cut positions
            # we mark complement interval
            diff[mx - n + 1] += 1
            diff[mn + 1] -= 1

    cur = 0
    for i in range(n):
        cur += diff[i]
        if cur == 0:
            print("possible")
            return

    print("impossible")

if __name__ == "__main__":
    solve()
```この実装では、トッピングごとにすべての出現インデックスが収集され、循環構造が 2 倍の線形配列に変換されます。 重要なアイデアは、回転ポイントの選択という観点から実現可能性を解釈することです。差分配列は、各トッピングのスパン制約によってどの回転ポイントが禁止されているかを追跡します。 カバレッジがゼロの位置は、有効なカットに対応します。 

主な微妙な点は、ラップアラウンドを正しく処理することです。 配列を 2 倍にすると、円形の間隔が確実に標準セグメントになりますが、それでも最初の範囲内のカット位置のみを考慮する必要があります。$n$インデックスを個別の回転として扱います。 差分配列はその範囲でのみチェックされます。

 ## 特殊なケース

 重大なエッジ ケースは、トッピングが 1 回または 2 回だけ表示されるが、円上で遠く離れた位置に表示される場合です。 その状況では、倍増配列表現によってラップアラウンドが正しく処理されることが保証され、計算されたスパンによって直接間隔制約を適用するか補数制約を適用するかが決まります。 アルゴリズムは、トッピングを分割する回転が除外されるように、禁止されたカット位置をマークします。 

もう 1 つのケースは、すべてのスライスが同じトッピングのペアを繰り返し共有する場合です。 すべてのトッピングには円全体をカバーする単一の連続したスパンがあるため、すべての回転が有効です。 差分配列はすべての位置をブロックすることはなく、範囲全体が実行可能なままになります。 

最後の微妙なケースは、次のようなペアをインターリーブすることです。$(1,2), (2,3), (3,1)$。 ここでは、すべてのトッピングがサイクル内の他の 2 つのトッピングと重なり、可能なすべてのカットで少なくとも 1 つのトッピングの出現を分割する必要があります。 スイープはカット位置を完全にカバーしていることを正確に示し、「不可能」を生成します。
