 ## 解決策
 ## 問題の理解

 各容疑者は、彼らが部屋にいた時間間隔に対応します。 容疑者 i については、到着時刻 a と継続時間 t が与えられ、a から a + t までの間隔が定義されます。 ある容疑者は、その間隔全体が他の容疑者の間隔をカバーしていれば、別の容疑者にアリバイを提供できます。 言い換えれば、間隔 A は、A が B より早く開始され、かつ B より早く終了しない場合に B を保証できます。 

各容疑者に「説得力」スコアを割り当てるよう求められます。 他の容疑者からの有効なアリバイがない容疑者にはスコア 0 が与えられます。それ以外の場合は、区間にそのアリバイが完全に含まれるすべての容疑者を調べ、それらの中で最大の説得力を取得し、1 を加算します。 

これは直接的な封じ込めだけではありません。 大きな間隔に中程度の間隔が含まれ、その中に小さな間隔が含まれるなど、チェーンが形成されることがあります。 したがって、容疑者のスコアは、その容疑者で終わる最長の封じ込めチェーンの長さから 1 を引いたものになります。 

この制約により、最大 200,000 の間隔が許可され、時間は最大 10^9 になります。 すべてのペアを直接比較しようとするソリューションでは、n^2 程度の間隔チェックが必要になりますが、この規模では遅すぎます。 数十億の操作でさえ、Python の 6 秒の制限をすでに超えています。 

微妙なケースは、間隔の開始時間が同じ場合に発生します。 ある間隔が後で終了する場合でも、その間隔に別の間隔が含まれる可能性があるため、同じ開始間の処理順序が重要になります。 処理を誤ると、同じ開始の長い間隔が存在する場合でも、短い間隔が有効なコンテナがないものとして誤って処理される可能性があります。 

## アプローチ

 問題を解決する直接的な方法は、すべての間隔のペアを確認することです。 間隔ごとに、他のすべてをスキャンし、それが含まれているかどうかをテストします。 存在する場合、そのコンテナを通じて最適なチェーンを計算しようとします。 これは、ノードが考えられるすべての親に依存するという定義に直接従うため、概念的に機能します。 

ただし、これにより間隔ごとにおよそ n 回のチェックが行われ、各チェックは O(1) となり、合計作業量は O(n^2) になります。 200,000 間隔の場合、これは数百億回の比較となり、実行不可能です。 

重要な観察は、封じ込めが間隔で半順序を定義するということです。 各間隔は 2 次元空間内の点、つまり開始時間と終了時間です。 コンテナには、それより小さいか等しい開始値と、大きいか等しい終了値がなければなりません。 したがって、各ノードは、右側に十分に広がる、より早く開始される間隔のみに依存します。 

この構造により、問題を点に関する支配クエリに変換できます。 開始時刻の昇順に間隔を処理すると、特定の間隔になった時点で、潜在的なコンテナーがすべてすでに表示されています。 それらの中で、終了が現在の終了と少なくとも同じ大きさである間隔の中で最良の dp 値のみが必要です。 これは、終了座標空間のサフィックスにわたる範囲最大クエリとなり、間隔を処理するにつれて更新されます。 

したがって、終了時間による間隔の挿入と、しきい値以上のすべての終了間の最大 dp のクエリをサポートするデータ構造を維持します。 圧縮された終了座標に対するフェンウィック ツリーまたはセグメント ツリーと、座標順序の逆転を組み合わせるだけで十分です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースペアチェック | O(n²) | O(n) | 遅すぎる |
 | スイープ + フェンウィック ツリー / セグメント ツリー | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各容疑者を区間 [a, a + t] に変換し、これらのエンドポイントのみを処理します。

1. 各間隔の終了時刻を計算します。 これにより、各容疑者にペア (開始、終了) が与えられます。 問題は、各間隔について、その間隔を含む最長の一連の間隔を見つけることになります。 
2. 開始時間を増やすことによってすべての間隔を並べ替えます。 2 つの間隔が同じ開始時間を共有する場合は、終了時間の降順に並べ替えます。 この順序付けにより、同じ瞬間に開始する間隔のうち、より大きな間隔が最初に処理され、より小さな間隔の潜在的なコンテナとして機能できるようになります。 
3. すべての終了値に対して座標圧縮を構築します。 これは、終了時間が 10^9 に達するため必要ですが、必要なのは相対的な順序付けだけです。 
4. 終了位置ごとに、その終了までに挿入された間隔の最大 dp 値を格納するフェンウィック ツリー (またはセグメント ツリー) を維持します。 
5. ソートされた順序で間隔を処理します。 各間隔 i と終了 e について:

 フェンウィック ツリーに対して、末尾が少なくとも e であるすべての間隔の最大 dp 値をクエリします。 これは、すでに処理されている i の考えられるすべてのコンテナに対応します。 
6. クエリが有用なものを返さない場合は dp[i] を 0 に設定し、それ以外の場合は dp[i] をクエリ結果に 1 を加えたものに設定します。これは、有効なコンテナの最適なチェーンの拡張を反映しています。 
7. dp[i] を計算した後、この区間をフェンウィック ツリーの終端に対応する位置に挿入し、dp[i] を将来の区間の候補として保存します。 

重要な考え方は、間隔を処理する時点で、考えられるすべてのコンテナがすでに構造内に存在しており、ツリーを使用すると、終了制約を満たすコンテナの中から最適なものを効率的に選択できるということです。 

### なぜ効果があるのか

 開始時間を増加させることによるスイープのどの時点でも、構造には、開始が現在の間隔より大きくない間隔のセットが正確に含まれます。 有効なコンテナはすべてこのセット内に存在する必要があります。 その中で、封じ込めは端が十分に大きいかどうかのみに依存します。 フェンウィック ツリーを使用すると、正確にこれらの候補の中から最適な dp を常にクエリできるため、すべての dp 値が正しい最適な先行処理を使用して計算され、包含階層全体で最適な下部構造が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def update(self, i, val):
        while i <= self.n:
            if val > self.bit[i]:
                self.bit[i] = val
            i += i & -i

    def query(self, i):
        res = 0
        while i > 0:
            if self.bit[i] > res:
                res = self.bit[i]
            i -= i & -i
        return res

n = int(input())
arr = []

ends = []

for _ in range(n):
    a, t = map(int, input().split())
    s = a
    e = a + t
    arr.append((s, e))
    ends.append(e)

# coordinate compression
ends_sorted = sorted(set(ends))
mp = {v: i + 1 for i, v in enumerate(ends_sorted)}

# sort by start asc, end desc
arr.sort(key=lambda x: (x[0], -x[1]))

fw = Fenwick(len(ends_sorted))
dp = [0] * n

for i in range(n):
    s, e = arr[i]
    idx = mp[e]

    # we need max dp among ends >= e
    # transform by reversing index
    # convert suffix query to prefix query
    pos = len(ends_sorted) - idx + 1

    best = fw.query(pos)
    dp[i] = best + 1 if best else 0

    fw.update(pos, dp[i])

print(*dp)
```この実装は、圧縮された座標を逆にして、「終了以上」条件をプレフィックス クエリに変換することに依存しています。 フェンウィック ツリーは合計ではなく最大 dp 値を保存するため、各更新ではそのエンドポイント領域でこれまでに確認された最適なチェーン長が維持されます。 

開始時間で並べ替えると、指定された間隔の処理時に、考えられるすべてのコンテナがすでに挿入されていることを確認できます。 等しい開始内で末尾の降順で並べ替えると、より大きな間隔がより小さな間隔の前に挿入されることが保証されます。これは、同じ開始時間を共有している場合でもコンテナとして機能する可能性があるため必要です。 

## 実用的な例

 ### 例 1

 すでに開始順にソートされている小さな間隔のセットを考えてみましょう。 

| ステップ | 間隔 | クエリ範囲 (終了 ≥ 現在) | ツリーからの最高の dp | dp値 | 挿入後のツリーの状態 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | (2, 8) | なし | 0 | 0 | {8:0} |
 | 2 | (1, 7) | なし | 0 | 0 | {8:0、7:0} |
 | 3 | (4,5) | 終了 ≥ 5 → (7,8) | 0 | 0 | {8:0、7:0、5:0} |
 | 4 | (5, 2) | 終了 ≥ 2 → すべて | 0 | 0 | {8:0、7:0、5:0、2:0} |

 このトレースは、どの間隔にも別の間隔が完全に含まれていないため、すべての値がゼロのままである場合を示しています。 この構造は依然としてすべての優位性チェックを正しく実行しますが、有効な先行構造がどこにも存在しません。 

### 例 2

 ここで、間隔がネストされているチェーンを考えてみましょう。 

| ステップ | 間隔 | クエリ範囲 (終了 ≥ 現在) | ツリーからの最高の dp | dp値 | 挿入後のツリーの状態 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | (2, 4) | なし | 0 | 0 | {4:0} |
 | 2 | (3, 3) | 終了 ≥ 3 → (4) | 0 | 0 | {4:0、3:0} |
 | 3 | (2, 2) | 終了 ≥ 2 → (3,4) | 0 | 0 | {4:0、3:0、2:0} |
 | 4 | (4,2) | 終わり ≥ 2 → (2,3,4) | 0 | 1 | {4:0、3:0、2:1} |
 | 5 | (4,1) | 終了 ≥ 1 → すべて | 1 | 2 | {4:0、3:0、2:1、1:2} |

 これは、より大きな間隔が後で処理されるにつれて、構造がどのようにチェーンの長さを増やし、より小さな間隔で形成されたチェーンを拡張できるかを示しています。

 ## 特殊なケース

 複数の間隔が同じ開始時間を共有する場合でも、封じ込めは終了時間のみに依存します。 アルゴリズムは、等しい開始を終了順にソートすることでこれを処理します。 これにより、長い間隔が最初に処理され、短い間隔の前に構造に挿入されます。 この順序が逆の場合、短い間隔が最初に挿入され、誤って大きい方の間隔の dp に寄与できなくなり、正確さが損なわれる可能性があります。 

間隔が、十分に終了する前に開始された間隔に含まれていない場合、Fenwick クエリはゼロを返します。 この場合、アルゴリズムは dp 値 0 を割り当て、「アリバイなし」の定義に一致します。 これにより、偶発的なアンダーフローや負の値が長いチェーンに伝播するのを防ぎます。 

すべての間隔の開始点が同一で終了点が異なる場合、構造は純粋に終了点の順序付けによってチェーンを構築します。 逆座標フェンウィック ツリーは、それぞれの短い間隔がすべての長い間隔を有効なコンテナとして正しく認識することを保証し、特別なケースを使用せずに説得力値の降順チェーンを生成します。
