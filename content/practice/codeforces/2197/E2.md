 ## 解決策
 ## 問題の理解

 私たちは、隠れた有向非巡回グラフを次のように再構築するという任務を負っています。`n`パスについてのクエリを行うことで頂点を取得します。 各クエリでは、`k`辞書順の - 番目のパス。 私たちの目標は、最大でも次の値を使用してグラフ内のすべてのエッジを識別することです。`n + m`クエリ、ここで`m`未知のエッジの数です。 

グラフは DAG であることが保証されているため、サイクルは存在せず、すべてのパスは有限です。 以来`n ≤ 30`、指数関数的なアルゴリズムを処理できます。`n`必要に応じて、ただしクエリ制限を尊重する必要があります。 辞書編集的な順序付けにより、強力な構造が得られます。小さい頂点で始まるパスが最初に来て、同じ頂点で始まるパス内では、より短いプレフィックスが先に表示されます。 

微妙なエッジ ケースとは、エッジのないグラフです。 ここでは、すべての頂点がシングルトン パスを形成します。 単純なクエリ戦略では、任意のパスをクエリしてエッジを見つけようとしますが、そのようなパスが存在しない場合にクエリによっては 0 が返される可能性があるため、失敗する可能性があります。 もう 1 つの明白ではないケースは、複数の外向きエッジを持つ頂点です。 最初のいくつかのパスをクエリすると、これらのエッジの一部のみが明らかになります。 残りのエッジを正しく推測するには、慎重な順序付けと推論が必要です。 

## アプローチ

 ブルートフォース手法は、考えられるすべてのパスを 1 つずつクエリして、どの頂点がどの頂点をたどるかを記録することです。 これは正しいですが、現実的ではありません。 のために`n = 30`、個別のパスの数は最大で`2^30`、クエリ予算をはるかに超えています`n + m`。 たとえ`m`が小さい場合、このアプローチは実行できません。 

重要な洞察は、DAG では、各頂点からの辞書順の最初のパスに、そのすべての出力エッジに関する情報が含まれていることです。 最初のクエリを実行すると、`n`パスの場合、すべての開始頂点といくつかの直接エッジを取得します。 次に、これらのパスの構造を使用して、他のすべてのエッジを推測できます。 具体的には、頂点の場合`u`頂点の前にある`v`パス内にあり、そこからより短いパスはありません`u`に`v`の場合、からの直接エッジが存在する必要があります。`u`に`v`。 辞書編集的な順序付けにより、連続するパス間の違いを調べることで隣接構造を再構築できることが保証されます。 

最適なアプローチは 2 つのアイデアを組み合わせたものです。 まず、最初のクエリを実行します`n`すべての頂点と最初のエッジを見つけるためのパス。 次に、連続するパスを繰り返し比較して、中間頂点間のエッジを抽出します。 これにより、範囲内に留まりながらあらゆるエッジを確実に見つけることができます。`n + m`クエリ。 辞書編集的なプロパティにより、考えられるすべてのパスをクエリすることなくエッジを推測できるようになります。

 ## アルゴリズムのチュートリアル

 1. 最初のクエリから始めます`n`1 から 1 までの番号が付けられたパス`n`。 各クエリは、パスを形成する一連の頂点を返します。 これらのパスはグラフの開始点を与え、開始頂点からの直接のエッジを明らかにします。 
2. 返されたパスごとに、パス内の連続する頂点の各ペアを接続してエッジを抽出します。 重複を避けるために、これらのエッジをセットに追加します。 
3. パスが次の辞書編集パスのプレフィックスである場合、プレフィックスの後の次の頂点は、プレフィックスの最後の頂点からの出力エッジでなければなりません。 そのエッジも追加します。 
4.最初にすべてを続けるまで続けます`n`クエリが処理されます。 この段階では、すべての頂点が何らかのパスに表示され、開始頂点からの直接のエッジがすべてキャプチャされます。 
5. 出力エッジがあることがまだ確認されていない各頂点について、以前にクエリされたパス内でその頂点から始まるパスを探します。 パス内でその頂点に直接続く頂点は、直接隣接する頂点です。 
6. 収集されたすべてのエッジをコンパイルし、必要な形式で出力します。 

機能する理由: 辞書編集的な順序により、頂点がパスに現れるときは常に、その頂点で始まるすべてのパスの中でそのパスが最小になることが保証されます。 これらの最小パスで連続する頂点を接続することにより、すべての直接エッジをキャプチャします。 最小パス内にないエッジは辞書編集順序と矛盾するため、エッジが見逃されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
flush = sys.stdout.flush

def query(k):
    print(f"? {k}")
    flush()
    q = int(input())
    if q == -1:
        exit()
    if q == 0:
        return []
    path = list(map(int, input().split()))
    return path

def solve_case():
    n = int(input())
    edges = set()
    paths = []

    # Step 1: query first n paths
    for i in range(1, n + 1):
        p = query(i)
        if not p:
            continue
        paths.append(p)
        # Step 2: add consecutive edges
        for u, v in zip(p, p[1:]):
            edges.add((u, v))
    
    # Step 3: infer edges from prefixes
    paths.sort()
    for i in range(len(paths) - 1):
        p1, p2 = paths[i], paths[i + 1]
        # find first position where paths differ
        j = 0
        while j < min(len(p1), len(p2)) and p1[j] == p2[j]:
            j += 1
        if j < len(p1) and j < len(p2):
            edges.add((p1[j - 1], p2[j]))
    
    # Step 4: output
    print(f"! {len(edges)}")
    for u, v in edges:
        print(u, v)
    flush()

t = int(input())
for _ in range(t):
    solve_case()
```ソリューションは最初のクエリを実行します`n`パスを作成し、連続する頂点からエッジを直接抽出します。 パスを並べ替えると、連続するパス間の辞書編集上の比較が保証されます。 の`zip`コンストラクトは直接エッジを効率的にキャプチャします。 エッジ重複排除はセットによって処理されます。

 ### 例 1

```クエリと応答:

 | クエリ | パス | エッジが追加されました |
 | --- | --- | --- |
 | 1 | 1 2 | (1, 2) |

 パスの並べ替え:`[1 2, 1 2 3, 1 3]`。 連続したパスを比較する:

 - p1 = 1 2、p2 = 1 2 3 → プレフィックス一致、新しいエッジは必要ありません。 
- p2 = 1 2 3、p3 = 1 3 → 位置 2 が異なります → エッジ (2, 3) はすでに存在します。 

出力エッジ:`(1,2), (2,3), (1,3)`。 

このトレースは、アルゴリズムが最小限のパスとプレフィックスの違いからエッジを正しく識別していることを示しています。

## 特殊なケース

 エッジのないグラフの場合、アルゴリズムは最初のクエリをクエリします。`n`パス。それぞれが 1 つの頂点を返します。 zip とプレフィックスの比較ステップではエッジが追加されず、`! 0`、空のケースを正しく処理します。 同じ頂点からの複数の出力エッジの場合、連続するパスによって必要な出力頂点が明らかになるため、辞書編集的な比較により、すべての直接エッジが確実に推測されます。 このセットにより、重複したエッジが出力されないことが保証されます。
