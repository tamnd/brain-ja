 ## 解決策
 ## 問題の理解

 整数が与えられます$x$、整数が何個あるかを数えたい$y$非常に特殊なバランス条件を満たす:$y$その数字の合計を引くと、正確に次のようになります。$x$。 つまり、それぞれの有効な数値は、$y$～に比べて「払いすぎ」$x$、過払い金は正確に次の桁の合計になります。$y$。 

したがって、タスクは構築することではありません$y$、ただし、それぞれにそのような構造がいくつ存在するかを数えます。$x$。 各テスト ケースでは、すべての整数の中で、異なるものがいくつあるかを尋ねます。$y$桁の合計を減算した後、同じ値にまで縮小しますか?

 制約は次のとおりです$x \le 10^9$そして$t \le 500$。 可能な限りすべての単純なスキャン$y$単一のテスト ケースでも潜在的に数十億の候補をチェックする必要があるため、これは直ちに不可能です。 近くだけスキャンしても$x$距離に制限がなければ安全ではない$y$漂流することができます。 

重要な構造的観察は、次のような変換です。$y \mapsto y - d(y)$最大でも桁数に 9 を掛けた分だけ数値を下方にシフトします。10 桁の数値の場合、桁の合計は最大 90 になります。$y$約90を超えることはできません$x$。 これにより、検索スペースが厳密に制限されます。 

次の場合、微妙なエッジケースが発生します。$x$小さいです。 たとえば、次の場合$x = 1$、次に潜在的な候補者$y$満足させる必要があるだろう$y - d(y) = 1$。 小さな値を試してみると、該当する数値が非常に少ないことがわかり、正確な制約関係を確認しないと、数値がまったく存在しないか、または多数あると誤って仮定する可能性があります。 

## アプローチ

 ブルートフォース戦略は、考えられるすべてのことを繰り返すことです。$y$ある程度の大きな制限までテストして、$y - d(y) = x$。 これは正しいですが、まったく実行不可能です。$y$までの範囲$10^9 + 100$そして、各候補に対して桁の合計の計算を実行することになります。 それはおおよそ次のことにつながります$O(10^9)$テスト ケースごとの操作数は、合理的な制限をはるかに超えています。 

重要な洞察は、方程式を逆にすることです。 から始めるのではなく、$y$から始めます$x$そして、どのような価値があるかを尋ねます$y$おそらくそれにマッピングされる可能性があります。 もし$y - d(y) = x$、 それから$y = x + d(y)$。 これは循環的に見えますが、重要な制約が明らかになります。それは、次の桁の合計です。$y$は小さく、最大で次の範囲に制限されます$9 \cdot 10 = 90$。 

したがって、考えられるすべての桁の合計を試すことができます$s$狭い範囲で。 直したら$s = d(y)$、 それから$y = x + s$。 次の桁の合計が正しいかどうかを確認するだけです。$x + s$等しい$s$。 それぞれ有効$s$有効な値を 1 つだけ提供します$y$。 

これにより、潜在的に数十億の候補が存在する問題が、テスト ケースごとに最大 100 個のチェックに減り、各テスト ケースには桁の合計の計算が含まれます。

 | 全てにおいてブルートフォース$y$|$O(N \cdot \log N)$|$O(1)$| 遅すぎる |

 ## アルゴリズムのチュートリアル

 1. 与えられた条件に対して$x$、有効な$y$満たさなければなりません$y = x + s$、 どこ$s = d(y)$。 以来$y$最大 10 桁、$s \le 90$したがって、狭い範囲の候補桁の合計を試行するだけで済みます。 
2. 可能なすべての値を反復処理します。$s$0 から 100 まで。エッジミスを避けるために上限はわずかに緩和されていますが、実際に成功できるのは 90 までの値のみです。 
3. それぞれについて$s$、計算する$y = x + s$。 これが、その桁の合計の唯一の候補です。 
4. 次の桁の合計を計算します。$y$で示される$d(y)$。 このステップでは、桁の合計に関する仮定が一貫しているかどうかを検証します。 
5. もし$d(y) = s$、 それから$y$は有効なフレンドリー番号です。 答えを増やします。 
6.すべての可能性を確認した後$s$、合計数を出力します。 

この列挙が機能する理由は、それぞれが有効であるためです。$y$はその桁の合計に一意に関連付けられます$s$、候補者が見逃されたり二重にカウントされたりしないようにします。 

### なぜ効果があるのか

 あらゆるソリューション$y$正確に 1 つの値を誘導します$s = d(y)$、満足する必要があります$y = x + s$。 可能なすべてのループ$s$すべての候補者を再構築することを保証します$y$おそらく方程式を満たす可能性があります。 桁の合計には制限があり、それらの間のオフセットが射出的に決定されるため、$x$そして$y$、検索スペースは完全であり、冗長ではありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def digit_sum(n):
    s = 0
    while n > 0:
        s += n % 10
        n //= 10
    return s

t = int(input())
for _ in range(t):
    x = int(input())
    ans = 0
    
    for s in range(0, 100):
        y = x + s
        if digit_sum(y) == s:
            ans += 1
    
    print(ans)
```このコードは、繰り返し呼び出される桁合計の計算をヘルパー関数に分割します。 ループオーバー$s$核となるアイデア: それぞれ$s$の桁和の仮説として扱われます。$y$、私たちはそれを直接確認します。 

10 桁の数値で取り得る最大桁合計は 90 であるため、100 の範囲は安全です。$x \le 10^9$最大 10 桁を保証します$y$。

import sys, io

 ## 特殊なケース

 いつ$x = 1$、アルゴリズムはすべてをチェックします$s \in [0, 99]$、候補者を生み出す$y = 1 + s$。 これらの候補者はいずれも満足しません$d(y) = s$これは、線形シフトに比べて桁の合計の増加が遅すぎるためです。 アルゴリズムは正しく 0 を返します。 

いつ$x = 999{,}999{,}999$、候補は約までの範囲です$10^9 + 100$。 ここでも、桁の合計は 90 で制限されたままであるため、シフトの小さなサブセットのみが機能します。 ループは依然としてすべての可能性を捕捉します。$y$列挙されたウィンドウ内になければなりません。 

いつ$x$9 の倍数であるか、末尾に 9 が多く含まれている場合、近くの数値の桁の合計はさらに変動しますが、依然として有界範囲内にあります。 このアルゴリズムは単調性に依存せず、実行可能なすべての桁の合計に対する徹底的なチェックのみに依存するため、これらのケースは変更することなく自然に処理されます。
