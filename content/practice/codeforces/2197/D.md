 ## 解決策
 ## 問題の理解

 整数の配列が与えられているので、インデックスのペアを数える必要があります。`(i, j)`どこ`i < j`対応する値の積はインデックス間の距離に等しくなります。`a[i] * a[j] = j - i`。 出力は、そのような「美しい」ペアの総数を表すテスト ケースごとの 1 つの整数です。 

この制約は、配列が 1 つのテスト ケースで最大 2 × 10^5 要素まで大きくなり、すべての要素の合計が可能であることを示しています。`n`テスト ケース全体の値も 2 × 10^5 によって制限されます。 2 秒の時間制限があるということは、合計入力サイズはほぼ線形または線形で、二次関数であれば安全に許容できることを意味します。`n`テストケースごとに実行すると遅すぎるでしょう。 値自体は最大 10^9 にすることができ、値によってインデックスを付ける単純な周波数配列アプローチは除外されます。 

厄介なエッジ ケースには、サイズ 2 の非常に小さな配列、すべての要素が同じである配列、または要素が非常に大きい配列などがあります。 たとえば、次の場合`a = [10^9, 10^9]`、美しいペアはありません。`10^9 * 10^9 = 10^18`よりもはるかに大きいです`j - i = 1`。 逆に、もし`a = [1, 1, 1]`、可能なすべてのペア`(i, j)`と`i < j`短い距離では積の条件を満たす可能性があり、単純な実装では複数のペアが欠落したり、二重にカウントされたりする可能性があります。 

## アプローチ

 最も簡単なアプローチは、インデックスごとに総当たり攻撃を行うことです。`i`、すべてを反復処理します`j > i`かどうかを確認してください`a[i] * a[j] == j - i`。 これは正しいですが、時間計算量はテスト ケースごとに O(n^2) です。 と`n`最大 2 × 10^5 の場合、最悪の場合、約 4 × 10^10 の操作が発生し、2 秒の制限をはるかに超えます。 

最適化のための重要な観察点は、次のような違いがあるということです。`j - i`よりも厳密に小さいです`n`、および製品`a[i] * a[j]`その差は正確に等しくなければなりません。 大きな値の場合、`a[i]`または`a[j]`、対応する`j - i`小さすぎて等式を満たすことはできません。 具体的には、両方の数値が相対的にかなり小さいペアのみを指定します。`n`貢献できる。 これは、すべてのペアを考慮する必要がないことを意味します。 代わりに、1 つのインデックスを反復処理して、可能なすべてのインデックスを計算できます。`j`式を整理すると条件を満たすものは次のようになります。`j = i + a[i] * a[j]`または同等に次の倍数をチェックします`a[i]`。 

反復することでこれを効率的に実装できます`i`1 から n まで、その後は可能な倍数ごとに`k * a[i]`（どこ`k`は次のような整数です`i + k * a[i] <= n`) かどうかを確認してください`a[i] * a[j] = j - i`が成立する。 これにより、候補者の数が大幅に減少します。`i`せいぜい`n / a[i]`、大きい割には小さい`a[i]`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | お(1) | 遅すぎる |
 | 倍数チェック | O(n * sqrt(n)) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る`t`。 
2. 各テスト ケースについて、次の内容を読んでください。`n`そして配列`a`長さの`n`。 
3. カウンタの初期化`ans`ゼロに。 
4. 各インデックスを反復処理します。`i`1から`n`。 それぞれについて`i`、候補インデックスを計算します`j`として`i + k * a[i]`どこ`k = 1, 2, 3...`それまで`j > n`。 
5. 計算されたそれぞれについて`j`、どうかを確認してください`a[i] * a[j] == j - i`。 そうなった場合はインクリメントします`ans`。 
6. すべてのインデックスを処理した後、印刷します。`ans`。 

このアプローチが機能するのは、次のことだけを考慮するためです。`j`現在の値に基づいて等式を満たすことができる値`a[i]`。 違いがあるので、`j - i`直線的に成長する一方で、`a[i] * a[j]`数値が大きいほど増加が速くなりますが、ほとんどのペアは自動的にスキップされ、操作の合計数が許容範囲内に保たれます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    ans = 0
    # Use 1-based indexing for easier mapping with formula
    a = [0] + a
    for i in range(1, n + 1):
        # Only consider multiples of a[i] that stay in bounds
        j = i + a[i]
        while j <= n:
            if a[i] * a[j] == j - i:
                ans += 1
            j += a[i]
    print(ans)
```ダミーのゼロを先頭に追加します。`a`1 インデックスにすると、式が簡素化されます。`a[i] * a[j] == j - i`。 それぞれについて`i`の倍数を考慮します。`a[i]`超えるまで`n`。 これにより、すべての候補者を確実にチェックすることができます`j`すべてのペアを反復することなく。 インクリメント`j`による`a[i]`等式を満たす可能性のある実行可能なインデックスのみをチェックするようにします。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = []
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        ans = 0
        a = [0] + a
        for i in range(1, n + 1):
            j = i + a[i]
            while j <= n:
                if a[i] * a[j] == j - i:
                    ans += 1
                j += a[i]
        output.append(str(ans))
    return "\n".join(output)
