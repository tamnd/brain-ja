 ## 解決策
 ## 問題の理解

 2 人の戦闘機が決定的な決闘を繰り広げ、数秒間で展開します。 毎秒、両方のクリーチャーが同時にダメージを与えます。あなたのクリーチャーはその攻撃値だけ対戦相手の体力を減らし、対戦相手はその攻撃値だけあなたのクリーチャーの体力を減らします。 戦いは、少なくとも 1 人の体力がゼロまたはマイナスになるまで続きます。 

戦闘が始まる前に、パンケーキと呼ばれる限られた数のアップグレードを配布できます。 パンケーキごとに攻撃力が 1 増加するか、体力が 1 増加します。 目標は、あなたのクリーチャーが決闘全体を生き残ることを保証することであり、必要なパンケーキの数を最小限に抑えたいと考えています。 

重要な問題は、生存は攻撃や体力だけの単一の閾値によって決まるわけではないということです。 攻撃力を上げると敵が生き残るラウンド数が減りますが、体力が上がると吸収できる敵の攻撃の数が増えます。 これら 2 つの効果は、戦闘が続くラウンド数によって相互作用します。 

入力は、自分の攻撃と体力を表す 4 つの整数と、それに続く相手の攻撃と体力で構成されます。 出力はユニットのアップグレードの必要最小限の数であり、攻撃と体力の間でユニットのアップグレードを最適に配分した後、戦闘中にクリーチャーが死ぬことはありません。 

素朴な解釈では、ダメージレースに勝つまで攻撃を個別に改善するか、十分に長く生き残るまで体力を個別に改善することを示唆するかもしれませんが、攻撃を改善することで戦闘が短縮され、受けるダメージが軽減されるため、どちらのアプローチも単独では機能しません。 

両方のクリーチャーが同じ最終交換で死亡した場合、微妙なエッジケースが 1 つ現れます。 たとえ最後のヒットで相手がゼロになったとしても、そのラウンドでダメージを与え続けるため、最後の同時攻撃の後も体力は厳密にプラスのままでなければなりません。 

もう 1 つの故障モードは、ラウンド数が固定されていると仮定することで発生します。 たとえば、最初の攻撃のみを使用してラウンドを見積もると、生存は不可能であると結論付ける可能性がありますが、攻撃をわずかに増加させるとラウンド数が大幅に減少し、生存が容易になります。 

## アプローチ

 パンケーキを分割する機能を無視すると、戦いのシミュレーションは簡単になります。 攻撃力と体力の​​値が固定されている場合、対戦相手は既知のラウンド数の後に死亡し、受けるダメージの合計が生き残れるかどうかを確認できます。 攻撃と体力の間のパンケーキの可能な分布をすべて試してみると、正確さが得られます。分割ごとに、戦闘をシミュレートし、生​​存を確認します。 

この強引なアイデアは、戦闘の正確なメカニズムを尊重しているため、正しいです。 しかし、それはすぐには不可能になります。 k 個のパンケーキを割り当てる場合、k+1 個の可能な分割があり、k 自体が大きくなる可能性があります。 さらに悪いことに、各シミュレーションでは死亡するまでのラウンド数を計算する必要があり、慎重に実行すると対数係数が追加され、単純に実行すると線形作業が発生します。 これは制約の下で爆発します。 

重要な観察は、戦闘の結果は 2 つの量、つまり相手が生き残るラウンド数と、ラウンドごとに受けるダメージの量のみに依存するということです。 自分の攻撃がAになれば相手は生き残る$$t = \left\lceil \frac{h_2}{A} \right\rceil$$ラウンドします。 この t ラウンド中に、あなたは正確に$t \cdot a_2$ダメージ。 最終的な体力が H の場合、生存には次の条件が必要です$$H > t \cdot a_2$$パンケーキは A と H を線形にのみ調整するようになりました。 すべてのスプリットを検索する代わりに、考えられる戦闘の長さ t を考慮して推論することができます。 t が固定されると、戦闘を t ラウンド以内に終了させるために必要な最小限の攻撃力と、正確に t ラウンドを生き延びるために必要な最小限の体力を計算できます。 固定 t に対する最適な割り当ては、攻撃とヘルスの制約が切り離されるという意味で独立しています。 

これにより、問題は t の候補値をチェックし、必要最小限の合計アップグレードを行うことに変換されます。

 ## アルゴリズムのチュートリアル

 1. 対戦相手がどれだけ長く生き残るかを表すラウンド数 t の候補を決定します。 この値は与えるダメージと必要な攻撃の両方を決定するため、全体の推論はこの値に基づいています。 
2. 対戦相手が最大 t ラウンドで死亡するために必要な最小限の攻撃を決定します。 これはつまり$$a_1 + x \ge \left\lceil \frac{h_2}{t} \right\rceil$$したがって、必要な攻撃アップグレードは次のとおりです。$$x = \max(0, \left\lceil \frac{h_2}{t} \right\rceil - a_1)$$3. x が修正されると、残りのアップグレードが正常になります。 tラウンドのダメージを受けて生き残るためには、$$h_1 + y > t \cdot a_2$$したがって、必要な健康アップグレードは次のとおりです$$y = \max(0, t \cdot a_2 + 1 - h_1)$$4. この選択された t に対して、必要なパンケーキの合計は x + y です。 t が固定されると、攻撃とヘルスのアップグレードは独立するため、これは有効な構成です。 
5. h₂ までのすべての t をチェックする代わりに、次の式が$\lceil h_2 / t \rceil$t が h₂ の約数と交差する場合にのみ変化します。 これにより、h₂ のすべての商をスキャンすることで、候補 t 値を効率的に列挙することができ、最大で O(√h₂) 個の候補が生成されます。 
6. 各候補 t について x + y を計算し、それらすべての最小値を取得します。 

### なぜ効果があるのか

 核となる不変条件は、すべての有効な最終構成が、選択された攻撃の下で対戦相手が生き残るラウンド数として定義される 1 つの有効戦闘長 t に正確に対応するということです。 任意の固定 t について、t ラウンドの発生を強制し、それらを存続させるために必要な最小限のリソースを計算します。 攻撃と健康への寄与は t が与えられると独立しているため、コストはきれいに分解されます。 可能なすべての個別の値を列挙する$\lceil h_2 / t \rceil$最適なものを見逃すことなく、構造的に異なるあらゆる戦闘体制を確実にカバーします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    a1, h1, a2, h2 = map(int, input().split())

    ans = 10**30

    # iterate over possible t values using sqrt decomposition
    t = 1
    while t * t <= h2:
        # direct t
        for T in (t, h2 // t):
            if T <= 0:
                continue

            need_attack = max(0, (h2 + T - 1) // T - a1)
            need_health = max(0, T * a2 + 1 - h1)

            ans = min(ans, need_attack + need_health)

        t += 1

    print(ans)

if __name__ == "__main__":
    solve()
```コードは、考えられる戦闘長にわたる分解を直接実装します。 ループオーバー`t`そして`h2 // t`天井分割のすべての個別の値が考慮されるようにします。 攻撃条件は天井分割式を使用し、健康条件は最終ラウンド後の厳格なポジティブを強制します。 

微妙な点としては、`+1`健康上の制約の中で。 これがなければ、このソリューションでは、最後の同時ヒットの後に体力がちょうど 0 の状態で生き残ることが誤って許可されてしまいますが、これはルールでは無効です。

 ## 特殊なケース

 両方の戦闘機が非常に弱い場合:`1 1 1 1`、戦闘は 1 回の交換で解決され、両方が同時に死ぬため、最適な解決策にはパンケーキは必要ありません。 アルゴリズムは、t = 1 を評価することによってこれを処理します。この場合、攻撃要件と正常性要件は両方とも 0 と評価されます。 

相手の体力は膨大だが攻撃力が低い場合、最適な戦略は攻撃を最大化して戦闘を大幅に短縮する方向に移行します。 候補となる t = h₂ ケースは、攻撃要件がゼロになり、健康だけが生存を決定するこの状況を捉えています。 

体力が多くても攻撃力が低い場合、アルゴリズムは当然、攻撃力が不十分なままで体力がコストを支配する大きな t 値を考慮します。 商に対する分解により、h₂ まで明示的に反復することなく、これらのケースが確実に含まれるようになります。
