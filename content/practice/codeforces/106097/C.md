 ## 解決策
 ## 問題の理解

 与えられた開始点は 1 つで、2 種類の動きを使用して目標距離に到達する必要があります。 1 つの移動は単位時間あたり一定の少量だけ前進し、もう 1 つの移動はより大きな固定距離をカバーするが固定の重要な時間を消費する特別なジャンプです。 重要な要件は、合計距離がそれを超えるだけでなく、正確に一致する必要があることです。 

したがって、タスクは、距離の合計が正確に等しくなるように、一連の歩行ステップとジャンプステップを選択することです。`n`合計時間を最小限に抑えながら。 ウォーキングは時間と距離の両方に直線的に寄与しますが、各ジャンプは固定距離に寄与します。`b`ただし、3 秒の固定時間がかかります。 

重要な点は、ジャンプが「より速い歩行」のように動作しないことです。 動きのセグメントを硬いブロックに置き換えます。それを完全に取り入れるか、全く取り入れないかのどちらかであり、常に正確に寄与します。`b`。 

これにより、ジャンプを選択した後の残りの距離がサイズの単位ステップを使用して構成できるかどうかによって実現可能性が決まる構造がすぐに作成されます。`a`。 

この制約により、私たちはシミュレーションから遠ざかってしまいます。 以来`n`非常に大きくなる可能性があるため (最大 10^18)、距離を超えて反復したり、ステップごとに貪欲なシミュレーションを試みたりするソリューションは不可能です。 州をまたぐDPでも、`n`全く実現不可能です。 

私たちは純粋に算術だけで推論することを強いられています。つまり、何回ジャンプするか、そして残りは歩行ステップを使用して表現できるかどうかです。 

単純な間違いは、ジャンプが有益であるように見えても、正確な到達可能性を損なう場合に発生します。 たとえば、次の場合`a = 2`、`b = 4`、 そして`n = 11`、ジャンプとウォークを組み合わせてみることもできますが、どの組み合わせでも均等な距離しか得られず、11 には到達できなくなります。 正しい答えは、`-1`。 

別の失敗例は、ローカルでオーバーシュートをジャンプするときに発生しますが、グローバルでは役立つと思われます。 たとえば、歩く歩数を減らすジャンプは最適に見えるかもしれませんが、それによって割り切れない余りが残る場合は、`a`、構築全体が無効になります。 

## アプローチ

 ブルートフォースアプローチでは、すべての一連の動きを試します。各ステップで歩くかジャンプし、到達するか超過するまで距離を蓄積します。`n`。 あらゆる点で 2 つの選択肢に分岐し、深さは次のオーダーになるため、これはすぐに指数関数的になります。`n / a`。 超えた道を枝刈りしても`n`、異なるシーケンスは異なる時間コストで同じ距離に到達できるため、状態空間は巨大なままです。 

重要な点は、順序は重要ではないということです。 すべてのジャンプは同じ距離と時間に寄与するため、ジャンプの数だけが重要です。 ジャンプ数を修正したら`k`、残りの距離が強制的に計算されます。`n - k*b`。 残りは、一定のサイズの歩行ステップのみを使用して達成可能でなければなりません`a`、これは割り切れる条件に帰着します。 

そこで問題は、整数を選択することです。`k >= 0`そのような`n - k*b >= 0`そして`(n - k*b) % a == 0`、最小化します`3k + (n - k*b)/a`。 

恣意的に検索するのではなく、実現可能性を考慮するだけで済みます。`k`価値観。 構造は十分に単調なので、関連するすべての剰余クラスを法でチェックします。`a`または、小さい境界範囲を反復するだけで十分です。`k`剰余を線形に変更します。 

これにより、問題はパス探索からモジュラー算術最適化に変換されます。

 ## アルゴリズムのチュートリアル

 1. まず表現可能かどうかを確認する`n`ウォーキングステップのみを使用します。 もし`n % a == 0`、これは次の基本的な答えを与えます`n / a`。 これにより、ジャンプを使用しないフォールバック ソリューションが確立されます。 
2. ジャンプを 1 つずつ導入することを検討します。 ジャンプするたびに削除されます`b`必要な歩行距離の単位ですが、3 秒のコストが追加されます。 一定回数のジャンプの場合`k`、残りの距離を計算します`rem = n - k*b`。 もし`rem < 0`、オーバーシュートするため、この選択は無効です。 
3. それぞれの有効な`k`、どうかを確認してください`rem`歩行ステップで正確に表現できます。 これには必要です`rem % a == 0`。 true の場合、合計時間を計算します`3k + rem / a`そして最低限のものを更新します。 
4. 使える範囲`k`値は制限されています。`k > n / b`、余りはマイナスになります。 したがって、検索空間は次のように線形になります。`n / b`、制約を考慮すると十分小さいので、推論も簡単です。 
5. すべての有効な構成にわたる最小時間を追跡し、出力します。 有効な構成がない場合は、出力`-1`。 

### なぜ効果があるのか

 有効な戦略はどれも、ジャンプの複数セットと残りの歩行ステップに分解できます。 どちらの操作も順序とは無関係に固定距離に寄与するため、それらを再配置しても実現可能性やコストは変わりません。 これは、すべてのソリューションが次の選択肢に一意に対応することを意味します。`k`そして残りは純粋に歩行ベースです。 割り算条件は、その剰余が達成可能となるために必要かつ十分であるため、有効なものをすべて列挙します。`k`ケースを欠落したり重複したりすることなく、ソリューション空間全体をカバーします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    a, b, n = map(int, input().split())

    INF = 10**30
    ans = INF

    # k = number of jumps
    k = 0
    while k * b <= n:
        rem = n - k * b
        if rem % a == 0:
            ans = min(ans, k * 3 + rem // a)
        k += 1

    print(-1 if ans == INF else ans)

if __name__ == "__main__":
    solve()
```コードを実行すると、ループは可能なジャンプ数を列挙します。 各反復により、問題は残りの距離が歩行ステップ サイズと正確に一致するかどうかを確認することになります。 算術チェックにより、シミュレーションの必要がなくなります。 大きなセンチネルを使用すると、有効な構成が存在しない場合の比較の偶発的なオーバーフローが回避されます。 

微妙な点は、剰余モジュロが得られるたびにローカルの貪欲性が失敗するため、貪欲な決定を混合して最適化しようとしていないことです。`a`ジャンプ数の変化に敏感です。 徹底的な列挙`k`その落とし穴をきれいに回避します。

## 複雑さの分析

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

 ## 特殊なケース

 いつ`n`よりも小さいです`b`、アルゴリズムは当然のことながら評価のみを行います`k = 0`これは問題を純粋な歩行の実現可能性の確認に正しく落とし込みます。 たとえば、`a = 3`、`b = 10`、`n = 1`、ループはジャンプを考慮せず、正しく出力します。`-1`以来`1 % 3 != 0`。 

いつ`n`は正確に割り切れます`a`の場合、アルゴリズムはゼロ ジャンプ ソリューションを正しく許可し、コストを悪化させるだけのジャンプ構成を無視します。 のために`a = 2`、`b = 5`、`n = 8`、最良の解決策は 4 回の四球と、すべての四球です。`k >= 1`割り切れない剰余が発生するか、コストが増加します。 

いつ`b`に比べて大きい`n`、ループは 1 回か 2 回だけ実行されるため、最大の制約でも隠れたパフォーマンスの問題は発生しません。
