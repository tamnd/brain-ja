 ## 解決策
 ## 問題の理解

 数値のリストと固定数のスワップ操作が与えられます。 スワップ操作とは、任意の 2 つのポジションを選択し、それらの値を交換することを意味します。 正確に実行した後$k$このような交換では、交互のスコアを使用して配列を評価します。位置 1、3、5、... の要素が追加され、位置 2、4、6、... の要素が減算されます。 

課題は、正確に演奏した後、この交互のスコアを最大化することです$k$交換します。 

重要な点は、複数の操作が許可されている場合、スワップはどの値がどの位置に配置されるかを意味のある形で制約しないことです。 スワップは転置であり、スワップを繰り返すことで値を非常に自由に並べ替えることができます。 唯一の潜在的な制限状況は、スワップがまったく許可されない場合です。 

複雑さの観点から見ると、$n$まで可能です$2 \cdot 10^5$すべてのテストケースにわたって、$k$と同じ大きさにすることができます$10^9$。 これにより、置換をシミュレートするアプローチや置換の検索が即座に除外されます。 どのような解決策であっても、問題を可能な限り最良の最終配置を直接構築することに帰着させる必要があります。 

単純ですが有益なアイデアは、スワップをシミュレートし、交互の合計を貪欲に改善してみることです。 これは 2 つの理由で失敗します。 まず、可能な状態の数は階乗です。$n$, そのため、小さな近所を探索することさえ不可能です。 第 2 に、大きな値を正の位置に移動するには、別の大きな値を負の位置に移動する必要がある可能性があるため、局所的な改善は全体的な最適性を保証しません。 

2 番目の単純なアイデアは、次の方法で到達可能なすべての順列を試してみることです。$k$交換します。 これも失敗します。到達可能な順列の数が非常に急速に増加し、状態空間が階乗のままであるためです。 

さらに深刻な問題は、少なくとも 1 回のスワップが許可されると、実際にはアレイが完全に再構成可能になるため、主な問題は操作のシミュレーションではなく、最適な配置を選択することになります。 

## アプローチ

 ブルートフォースの観点から始めます。 各スワップが新しい順列を生成すると考えると、$k$到達可能なすべての順列を正確に探索することを想像できるスワップ$k$移調。 各スワップは状態空間を大幅に分岐させます。$n$、これは組み合わせ的に爆発します。 これにより、直接シミュレーションが不可能になります。 

重要な観察は、スワップにより配列を完全に自由に並べ替えることができるということです。 任意の順列は、一連のスワップを使用して構築できます。$k$が大きく、スワップを最小限に抑えるという制約がない場合、問題は実際に取られるパスではなく、最終的な配置に関するものです。 

少なくとも 1 つのスワップが許可されるときはいつでも、あらゆる取り決めが達成可能であることを受け入れると、最適化はスワップ プロセスから独立したものになります。 大きな値を正の位置に、小さな値を負の位置に配置して、交互の合計を最大化するだけで済みます。 

ブルートフォース手法は、到達可能なすべての置換を探索するため理論的には機能しますが、置換の数が階乗的に増加するため失敗します。 スワップが完全な再配置の自由を意味するという観察により、問題は貪欲な割り当ての問題に帰着します。

 ## アルゴリズムのチュートリアル

 スワップが許可されているかどうかに基づいて、ソリューションを 2 つの方式に分けます。 

1. もし$k = 0$、変更はできません。 答えは単純に、元の配列の交互の合計です。 自由がないため、指定された構成を直接評価します。 
2. もし$k \ge 1$、完全な再配置の自由を前提としています。 最初の順序を無視し、代わりに最適な配置を構築します。 
3. 最大の値を最初に割り当てることができるように、配列を降順に並べ替えます。 これにより、値を正の位置に配置すると、その寄与が最大化されます。 
4. 交互の合計の構造を特定します。位置 1、3、5、... はプラスに寄与し、位置 2、4、6、... はマイナスに寄与します。 
5. 最初にすべての正の位置に最大値を割り当てます。 これらの位置は、式内で最も価値のあるスロットです。 
6. 残りの値を負の位置に割り当てます。 問題の制約ではすべての値が負ではないため、この配置により減算によ​​るダメージが最小限に抑えられます。 
7. この代入から直接、結果の交互合計を計算します。 

これが機能する理由: 交互の合計は配列値内で線形であるため、これを最大化すると、重みが位置によって固定される重み付き割り当て問題を最大化することになります。 正のウェイトのポジションは最大値を受け取り、負のウェイトのポジションは最小値を受け取る必要があります。 ソートにより、この割り当てが最適であることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))

        if k == 0:
            ans = 0
            for i, x in enumerate(a):
                if i % 2 == 0:
                    ans += x
                else:
                    ans -= x
            print(ans)
            continue

        a.sort(reverse=True)

        pos_count = (n + 1) // 2
        neg_count = n // 2

        ans = 0

        for i in range(pos_count):
            ans += a[i]
        for i in range(pos_count, n):
            ans -= a[i]

        print(ans)

if __name__ == "__main__":
    solve()
```このコードは、最初に、元の配列の交互の合計を直接計算することによって、スワップが許可されない縮退ケースを処理します。 これが必要なのは、次の場合に最適な再配置が達成できないためです。$k = 0$。 

スワップが許可されている場合、配列は降順にソートされます。 並べ替えられた値の前半は正の位置に割り当てられ、残りの値は負の位置に割り当てられます。 分割ポイントは、配列内に存在する奇数のインデックスの位置がいくつあるかによって決まります。 

その後、配列を明示的に再構築せずに交互の合計が計算されます。これにより、不必要なオーバーヘッドが回避され、ソート後の実装が線形に保たれます。 

## 実用的な例

 小さな例を考えてみましょう。$n = 5$そして配列は$[1, 5, 2, 4, 3]$、 と$k \ge 1$。 

並べ替えると、次のようになります$[5, 4, 3, 2, 1]$。 

ポジティブなポジションが 3 つとネガティブなポジションが 2 つあります。 

| ステップ | ポジティブスロット | マイナススロット | 貢献 |
 | --- | --- | --- | --- |
 | 並べ替え後 | [5、4、3] | [2、1] | 5 + 4 + 3 − 2 − 1 |

 最終的な答えは、$9$。 

このトレースは、最大値が常に正の位置に配置され、それが交互構造を支配していることを示しています。 

次に 2 番目の例を考えてみましょう。$n = 4$、配列は$[10, 1, 10, 1]$、 そして$k = 0$。 

再注文は一切行っておりません。 

| ポジション | 値 | サイン | 貢献 |
 | --- | --- | --- | --- |
 | 1 | 10 | + | 10 |
 | 2 | 1 | − | −1 |
 | 3 | 10 | + | 10 |
 | 4 | 1 | − | −1 |

 最終結果は$18$。 

この例では、次の場合には配列を変更しないという厳格な要件を強調しています。$k = 0$たとえもっと良い取り決めがあったとしても。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import isclose

    def solve():
        t = int(input())
        for _ in range(t):
            n, k = map(int, input().split())
            a = list(map(int, input().split()))

            if k == 0:
                ans = 0
                for i, x in enumerate(a):
                    if i % 2 == 0:
                        ans += x
                    else:
                        ans -= x
                print(ans)
                continue

            a.sort(reverse=True)
            pos = (n + 1) // 2
            ans = sum(a[:pos]) - sum(a[pos:])
            print(ans)

    old = sys.stdout
    sys.stdout = io.StringIO()
    solve()
    out = sys.stdout.getvalue()
    sys.stdout = old
    return out.strip()

# sample-like cases

assert run("1\n4 0\n10 1 10 1\n") == "18"

# edge cases

assert run("1\n3 0\n1 2 3\n") == "2"
assert run("1\n6 2\n5 4 3 2 1 0\n") == "9"

 ## 特殊なケース

 いつ$k = 0$、アルゴリズムはソートを行わず、元の構造を直接評価します。 のような入力の場合$[3, 1, 2]$、計算は次のように固定されます。$3 - 1 + 2 = 4$たとえ再配置すれば改善する可能性があります。 分岐を分離することで、この制約が正確に尊重されるようになります。 

いつ$n$などの最小限のものです$n = 2$、並べ替えは引き続き正しく動作しますが、正と負の分割は各側に 1 つの要素に縮退します。 この式はきれいに次のようになります。$a_1 - a_2$注文後。 

すべての値が等しい場合、並べ替えは効果がなく、どのように配置しても同じ結果が得られます。 このアルゴリズムは、特別な処理を行わなくても、自然に正しい定数値を返します。
