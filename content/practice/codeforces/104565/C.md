 ## 解決策
 ## 問題の理解

 ジャケット、パンツ、シャツの 3 種類の衣類を使用して、できるだけ多くの有効な服装を構築することが求められます。 各衣装は、各カテゴリの 1 つのアイテムで構成されるトリプルです。 この制約は、完全な衣装だけを繰り返すことに関するものではなく、選択されたすべての衣装にわたってアイテムのペアが一緒に表示される頻度を制限することにも関係します。 

カテゴリの各ペアには最大 K 回の出現回数の上限があります。特定のジャケットと特定のパンツのペアは最大 K 回出現できます。ジャケットとシャツのペアやパンツとシャツのペアにも同じことが当てはまります。 目標は、すべてのペアの制限を尊重しながら、そのようなトリプルの可能な限り最大のコレクションを出力することです。 

入力サイズは非常に重要な点で小さいです。 J、P、S はそれぞれ最大 10 であり、K も最大 10 です。これにより、可能なトリプルの総数は最大 1000 であることがすぐに分かります。したがって、この空間では二次関数や三次関数さえも実行可能です。 実現不可能なのは、トリプルのサブセットにわたる指数関数的なものです。これは、約 2^1000 の可能性があるためです。 

単純な試みでは、すべての衣装を生成し、最後に有効性をチェックしようとする可能性があります。 これは、ペアの制約がグローバルに相互作用するため、ローカルな決定が将来の可用性に影響を与えるため、失敗します。 

より微妙な障害モードは、特定のペアを早い段階で過剰に使用する貪欲な選択から発生します。 たとえば、ジャケット 1 とパンツ 1 を繰り返し修正し、シャツを変更すると、割り当てを使い果たし、後でよりバランスのとれた組み合わせがブロックされ、合計数が減少する可能性があります。 

## アプローチ

 強引な定式化は簡単です。すべての J × P × S トリプルのすべてのサブセットを考慮し、すべてのペアの周波数が K 以内に収まるかどうかを確認します。これは正しいですが、完全に実行不可能です。なぜなら、可能なトリプルが 1000 個しかない場合でも、サブセット空間は天文学的に大きいからです。 

重要な点は、サブセットを明示的に検索する必要がないということです。 有効な各ソリューションは、各ペアが使用される回数によって完全に記述されており、各ペアの容量が非常に小さい (最大 10) ため、ソリューションを安全に段階的に構築できます。 

サブセットに対してグローバルに推論するのではなく、考えられるすべてのトリプルを固定順序でスキャンし、ペアの制約に違反しない場合は必ずトリプルを追加することで、貪欲に答えを構築します。 各トリプルは、ジャケット-パンツ、ジャケット-シャツ、パンツ-シャツの 3 つのカウンターにのみ影響します。 すべてのカウンターの上限は K であり、すべての値が小さいため、この貪欲な構造はすぐに安定し、最大限の実現可能なセットを生成します。 検討の時点でスキップされたトリプルは、その 3 つのペアのうち少なくとも 1 つがすでに容量に達しているためブロックされます。そのため、後で追加するには以前の選択肢を削除する必要がありますが、すべての選択肢が対称であるため不要です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース サブセット検索 | O(2^(JPS)) | O(JPS) | 遅すぎる |
 | ペアカウンターで貪欲 | O(JPS) | O(JP + JS + PS) | 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは、ジャケットとパンツ、ジャケットとシャツ、パンツとシャツの各ペアが使用された回数を追跡する 3 つの頻度テーブルを管理しています。

1. すべてのペアのカウンターをゼロに初期化し、選択した服装の空のリストを作成します。 
2. 固定された決定論的な順序で、考えられるすべてのトリプル (j、p、s) を反復します。 順序は複雑である必要はありません。 すべてのトリプルは対称であり、制約は均一であるため、辞書編集的な順序で十分です。 
3. 各トリプルについて、追加すると 3 つのペアの制限を超えるかどうかを確認します。 これは、c[j][p]、c[j][s]、および c[p][s] がすべて厳密に K 未満であることを検証することを意味します。 
4. 3 つのチェックがすべて合格した場合、答えにトリプルを追加し、対応するペアのカウンターをインクリメントします。 
5. いずれかのチェックが失敗した場合、そのブロック状態はすでに飽和したペアによって引き起こされ、後で改善されないため、トリプルを永久にスキップします。 
6. すべてのトリプルをスキャンした後、収集されたリストを出力します。 

重要な考え方は、スキップされたトリプルを決して再考しないということです。 ペアが容量 K に達すると、安全に再利用することはできないため、決定を延期しても、失われた機会を回復することはできません。 

### なぜ効果があるのか

 この構造により、トリプルを受け入れるたびに、ローカルですべての制約が尊重されるようになります。 トリプルが拒否される唯一の理由は、以前に選択された有効なトリプルによってすでに完全に使用されているペアの容量を超える可能性があることです。 容量はハードリミットであり、すべての選択肢にわたって対称であるため、最適なソリューションには K より多くのそのペアの出現を含めることはできません。そのため、拒否されたトリプルは、不適切な順序付けの決定ではなく、飽和したリソースによって事実上ブロックされます。 これにより、与えられた制約の下で貪欲な解が最大になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for tc in range(1, T + 1):
        J, P, S, K = map(int, input().split())

        jp = [[0] * (P + 1) for _ in range(J + 1)]
        js = [[0] * (S + 1) for _ in range(J + 1)]
        ps = [[0] * (S + 1) for _ in range(P + 1)]

        ans = []

        for j in range(1, J + 1):
            for p in range(1, P + 1):
                for s in range(1, S + 1):
                    if jp[j][p] < K and js[j][s] < K and ps[p][s] < K:
                        ans.append((j, p, s))
                        jp[j][p] += 1
                        js[j][s] += 1
                        ps[p][s] += 1

        print(f"Case #{tc}: {len(ans)}")
        for j, p, s in ans:
            print(j, p, s)

def main():
    solve()

if __name__ == "__main__":
    main()
```このソリューションは、それぞれがペア タイプを追跡する 3 つの独立した 2D 配列を中心に構造化されています。 この分離は、候補となるトリプルごとに制約を最初から再計算する必要がなくなるため、非常に重要です。 

ネストされたループは、考えられるすべての服装を一度に列挙します。 各決定は O(1) であるため、全体の構成はトリプルの数において線形になります。 

微妙な点は、以前の選択を「修正」しようとしないことです。 これは意図的なものです。制約は増加するだけで減少しないため、バックトラッキングは不要であり、この制約された入力サイズの結果を改善することなく実装が複雑になるだけです。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(J・P・S) | 各トリプルは O(1) 更新で 1 回チェックされます。 
| スペース | O(J・P + J・S + P・S) | 制約追跡のためのペアカウンター |

 J、P、S がすべて最大 10 である場合、トリプルの最大数は 1000 であるため、制限時間内では 100 個のテスト ケースであっても簡単です。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    T = int(input())
    out = []

    for tc in range(1, T + 1):
        J, P, S, K = map(int, input().split())

        jp = [[0] * (P + 1) for _ in range(J + 1)]
        js = [[0] * (S + 1) for _ in range(J + 1)]
        ps = [[0] * (S + 1) for _ in range(P + 1)]

        ans = []

        for j in range(1, J + 1):
            for p in range(1, P + 1):
                for s in range(1, S + 1):
                    if jp[j][p] < K and js[j][s] < K and ps[p][s] < K:
                        ans.append((j, p, s))
                        jp[j][p] += 1
                        js[j][s] += 1
                        ps[p][s] += 1

        out.append(f"Case #{tc}: {len(ans)}")

    return "\n".join(out)

 ## 特殊なケース

 J = P = S = 1 の場合、アルゴリズムは可能な唯一のトリプルを直ちに受け入れ、単一の衣装を返します。 K を超えるペアは存在しないため、カウンターは自明なままであり、正しさはすぐにわかります。 

K = 1 の場合、すべてのペアは最大 1 回しか使用できないため、アルゴリズムは再利用を積極的にブロックします。 この場合、この構造は、三者空間全体で一致するような構造を効果的に選択し、ペアを再利用しようとする試みは、出現するとすぐに拒否されます。 

K が J、P、S に比べて大きい場合、制約はトリガーされません。 このアルゴリズムは、真の最大値と一致するすべての J × P × S トリプルを単純に列挙します。
