 ## 解決策
 ## 問題の理解

 ページは、1 センチメートル間隔で等間隔に配置された水平ガイドラインの固定セットと、任意の x 座標に配置された垂直ガイドラインのセットで描画されます。 水平線と垂直線のすべての交点は格子点であり、すべての角がこれらの交点上にある軸に整列した正方形が何個形成できるかを数えるよう求められます。 

正方形は、選択した水平線間の水平方向の間隔が、選択した垂直線間の垂直方向の間隔と等しくなるように、2 本の水平線と 2 本の垂直線を選択することによって決定されます。 水平線は等間隔であるため、正方形の垂直辺の長さは、2 本の水平線の間の連続する正確な k センチメートルの間隔を選択することによって完全に決定されます。 同じ k が、一対の垂直線の間の距離として表示されなければなりません。 

したがって、問題は水平線のギャップと垂直線のギャップのペアに帰着します。整数距離 k ごとに、正確に k だけ離れている垂直線のペアが何ペアあるか、垂直分離 k を持つ水平線のペアが何ペアあるかを知る必要があります。 最終的な答えは、互換性のある選択肢の合計数です。 

この制約は、最悪の場合、垂直線のすべてのペアを直接列挙することが不可能であることを意味します。 すべてのテスト ケースにわたって最大 200 万本の垂直線があるため、ペアの数は 10^12 のオーダーに達し、二次解は即座に除外されます。 すべてのペアワイズ差の完全な度数表を構築することさえ、構造を活用することなしには実現不可能です。 

垂直方向の距離は存在するが、水平方向のギャップの数を超えている場合、微妙なエッジ ケースが発生します。 たとえば、m が小さく、2 つの垂直線が遠く離れている場合、その間隔に一致するのに十分な水平線がないため、そのペアは正方形を形成できません。 このカットオフを考慮せずにすべての垂直方向の差をカウントするソリューションでは、カウントが過剰になります。 

もう 1 つの失敗モードは、問題を純粋に「すべての差異をカウントする」ものとして扱い、大きなギャップが負の寄与ではなくゼロ二乗に寄与することを無視して、やみくもに m を乗算することです。 

## アプローチ

 単純なアプローチでは、すべての垂直線のペアを試してしまうでしょう。 各ペア (i, j) について、それらの距離 d = a[j] - a[i] を計算し、正確に d 間隔を持つ水平ペアがいくつあるかを数えます。これは、d < m の場合は単純に m - d、それ以外の場合は 0 です。 これは原理的には正しいです。なぜなら、水平線は 1 から m-1 までの各ギャップ サイズ k に対してちょうど 1 つのペアを形成し、そのようなペアは m-k 個存在するからです。 

ただし、すべてのペアを列挙するにはすでに O(n^2) のコストがかかります。 n が合計 200 万に達すると、これは完全に不可能になり、最悪の場合、10^12 のオーダーの演算が必要になります。 

重要な観察は、垂直位置がソートされているため、ペアの寄与は差分 a[j] - a[i] のみに依存するということです。 それぞれの差を明示的にカウントする代わりに、スライディング ウィンドウ方式でペアを処理できます。 固定左端点 i の場合、a[j] - a[i] < m を持つ j だけが何らかの寄与をすることができます。 この制限により、完全なペア セットがアクティブ ウィンドウのセットになり、両方のポインターが前方にのみ移動するため、合計作業量は n で線形になります。 

各ウィンドウ内では、(m - (a[j] - a[i])) という形式の式の合計が必要になります。 これを拡張すると、寄与をウィンドウ内の要素の数とその値の合計に分けることができ、どちらもプレフィックス合計を使用して維持できます。

 ## アルゴリズムのチュートリアル

 順序付けられた差異のみが問題となるため、最初に垂直座標をソートします。

2 つのポインター i と r を維持します。ここで、r は、a[i] から a[r] までの垂直距離が依然として厳密に m 未満であるような最も遠いインデックスです。 これにより、i の潜在的なパートナーの有効な範囲が定義されます。 

また、任意のセグメントの合計を O(1) でクエリできるように、配列全体のプレフィックスの合計も維持します。 

1. 垂直線の配列をソートし、それらの位置にわたるプレフィックスの合計を計算します。 
2. 右ポインタ r = 0 を初期化します。 
3. 0 から n - 1 までの左のインデックス i ごとに、a[r] - a[i] が m より小さくなくなるまで r を進めます。 これにより、(i, r] 内のすべてのインデックスが潜在的に i で正方形を形成できることが保証されます。
 4. 固定 i については、(i, r] 内のすべての有効な j を考慮します。そのような各ペアは、m - (a[j] - a[i]) 乗に寄与します。合計の寄与は、ペアごとではなく集合的に計算されます。
 5. (i, r] の j の合計を、要素の数とその値の合計の組み合わせとして書き換えます。これにより、接頭辞の合計を使用して i ごとの定数時間の計算が可能になります。
 6. すべての i. にわたって貢献を蓄積します。 

中心となる考え方は、ペアを明示的に列挙することは決してないということです。 代わりに、有効なパートナーのアクティブな範囲を維持しながら、配列全体を 1 回スイープします。 

### なぜ効果があるのか

 i を固定すると、アルゴリズムは垂直距離が有効な正方形の辺の長さの候補となるように、それらの j を正確に考慮します。 すべての有効な正方形は、i < j の 1 つのペア (i, j) によって一意に表現されるため、二重にカウントされたり、見逃されたりするペアはありません。 

寄与式は、有効な垂直ギャップごとに水平選択肢の合計数を分解します。水平構造はギャップ サイズのみに依存するため、ウィンドウごとに集計すると、ペアごとの区別を失うことなく正確さが維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        m, n = map(int, input().split())
        a = list(map(int, input().split()))
        a.sort()

        # prefix sums
        pref = [0] * (n + 1)
        for i in range(n):
            pref[i + 1] = pref[i] + a[i]

        ans = 0
        r = 0

        for i in range(n):
            if r < i:
                r = i
            while r + 1 < n and a[r + 1] - a[i] < m:
                r += 1

            cnt = r - i
            if cnt <= 0:
                continue

            sum_seg = pref[r + 1] - pref[i + 1]

            # sum over j in (i, r]:
            # (m - (a[j] - a[i]))
            # = cnt*m - sum(a[j]) + cnt*a[i]
            ans += cnt * m - sum_seg + cnt * a[i]

        print(ans)

if __name__ == "__main__":
    solve()
```この解決策は、すべての有効なペアが各 i の連続セグメントとして表示されるようにソートすることに依存しています。 プレフィックス合計配列は、これらのセグメントを反復せずに合計を計算するために使用されます。 

よくある間違いは、ペアが i < j を満たす必要があるため、セグメントが i ではなく i+1 から始まることを忘れることです。 もう 1 つの微妙な点は、r を単調に維持することです。 前方にのみ移動する必要があり、後方にリセットすることはできません。そうしないと、複雑さが低下します。

 ## 特殊なケース

 垂直線が非常に近い場合、すべてのペアが大きな m の有効なウィンドウ内に収まります。 このアルゴリズムは r を最後まで正しく拡張し、接頭辞の合計を使用して寄与を計算し、二次列挙を回避します。 

垂直線が大きく離れている場合、各 i のウィンドウはほぼ即座に空になり、不必要な作業を行わずに寄与がゼロになります。 

すべての点がクラスター化されている場合、r は i が小さい場合は n 付近に留まりますが、r の単調な動きにより、全体の複雑さは二次ではなく線形のままになります。
