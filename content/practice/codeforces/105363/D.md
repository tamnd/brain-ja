 ## 解決策
 ## 問題の理解

 私たちは道路で結ばれた村のネットワークを与えられています。各道路は最初は使用できず、一定の時間が経過した後にのみ使用できるようになります。 すべての道路は、それぞれのスケジュールに従って並行して「ロック解除」されます。 道路のロックが解除されると、永続的に使用できるようになります。 

問題は、すでにロック解除が完了した道路のみを使用して村同士が完全に到達できるようになる最も早い時間を判断することです。 グラフに関して言えば、最小の時間が必要です$T$エッジを維持するだけであれば$h_i \le T$、結果のグラフが接続されます。 

各テスト ケースは重み付きの無向グラフを提供します。重みはアクティブ化時間を表します。 事実上、グラフを接続するエッジの重みの最小しきい値を見つけることが求められます。 

制約は大きく、最大で$10^5$頂点と$5 \cdot 10^5$テスト ケースごとのエッジ、合計の合計$10^6$。 これにより、すべての異なるエッジに対して BFS/DFS を繰り返し実行するなど、候補時間ごとに接続を最初から再計算するものは直ちに除外されます。$h_i$。 すべてのエッジをソートし、しきい値ごとに複数のグラフ全体の再構築をシミュレートしても、単純に実行すると遅すぎます。 

また、微妙な失敗のケースにも注意する必要があります。つまり、エッジを昇順で適切に処理しないと、部分処理という意味で接続性が単調になりません。 

たとえば、三角形について考えてみましょう。```
0 - 1 (10)
1 - 2 (10)
0 - 2 (100)
```単純なアプローチでは、エッジ (0,2) を待つ必要があると誤って考える可能性がありますが、実際にはノードは最初の 2 つのエッジを使用して時刻 10 ですでに接続されています。 

The correct answer depends on the structure of the minimum way to connect all nodes, not on any specific path between a fixed pair.

 ## アプローチ

 A brute-force strategy would be to simulate time increasing from 1 upward, and at each step check whether the graph formed by all edges with$h_i \le T$接続されています。 各接続チェックのコスト$O(n + m)$DFS または BFS を使用します。 最悪の場合、最大でスキャンする可能性があります。$10^6$重みが高密度で大きい場合、時間値が異なるため、法外な値が発生します。$O(m \cdot \max h)$あるいは$O(m^2)$-style の動作は実装に依存します。 これは限界をはるかに超えています。 

重要な点は、実際には毎回チェックする必要はないということです。 すべての頂点を接続するのに十分なエッジが存在する瞬間だけを考慮します。 それはまさに、可能な限り最小の最大エッジ重みを使用してスパニング ツリーを選択した瞬間です。 

これにより、問題は古典的な最小ボトルネック スパニング ツリーの問題に変換されます。つまり、すべてのスパニング ツリーの中で、使用される最大エッジ ウェイトを最小にするスパニング ツリーが必要になります。 答えは、最小スパニング ツリーの最大エッジの重みです。 

これを認識すれば、解決策は簡単になります。 エッジを重みでソートし、Disjoint Set Union (DSU) を使用してスパニング ツリーを構築します。 すべての頂点を接続すると、現在のエッジの重みが答えになります。

 | クラスカル + DSU |$O(m \log m)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 私たちはクラスカルのアイデアを使用していますが、接続が確立されるとすぐに停止します。 

1. すべての道路を開通時間順に並べ替えます$h_i$。 これにより、可能な限り最も早い接続が常に最初に考慮されるようになります。これは、グラフが接続されるまでの時間を最小限に抑えたいために必要です。 
2. 各村が独自のコンポーネントで始まる DSU 構造を初期化します。 最初は接続されている村はありません。 
3. ソートされたエッジを昇順に繰り返します。$h_i$。 各エッジについて$(u, v, h_i)$を含むコンポーネントをマージしようとします。$u$そして$v$。 それらがすでに同じコンポーネント内にある場合、エッジは接続を変更しません。 
4. マージが成功するたびに、接続されているコンポーネントがいくつ残っているかを追跡します。 結合が成功するたびに、このカウントが 1 ずつ減ります。 コンポーネントの数が 1 つになると、すべての村が接続されます。 
5. 答えは現在のエッジの重みです$h_i$これは、これまでのエッジのみを使用してグラフが完全に接続される最初の瞬間であるためです。 

重要なアイデアは、エッジの重みが増加する順序で効果的にスパニング フォレストを構築しており、それが 1 つのツリーになる瞬間がまさに接続が達成されるということです。 

### なぜ効果があるのか

 いつでも$T$、使用可能なエッジのセットは、最大でも重みを持つすべてのエッジです。$T$。 Kruskal のアルゴリズムは、エッジを昇順に処理し、そのプレフィックスの最小スパン フォレストを維持します。 DSU がすべてを 1 つのコンポーネントにマージした瞬間に、すべての頂点を接続するエッジの最小プレフィックスが見つかりました。 

現在のエッジの重みよりも早く接続が可能であった場合、それはスパニング ツリーがより小さいエッジのみを使用して存在することを意味し、Kruskal が常に最小限のボトルネック スパニング ツリーを構築するという事実と矛盾します。 したがって、最初に単一のコンポーネントに到達したときが最適な答えになるはずです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n
        self.components = n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return False
        if self.size[a] < self.size[b]:
            a, b = b, a
        self.parent[b] = a
        self.size[a] += self.size[b]
        self.components -= 1
        return True

def solve():
    T = int(input())
    out = []

    for _ in range(T):
        n, m = map(int, input().split())
        edges = []
        for _ in range(m):
            u, v, w = map(int, input().split())
            edges.append((w, u, v))

        edges.sort()

        dsu = DSU(n)

        ans = 0
        for w, u, v in edges:
            if dsu.union(u, v):
                ans = w
                if dsu.components == 1:
                    break

        out.append(str(ans))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```DSU は、エッジを昇順に処理するときに動的な接続を維持します。 の`components`カウンタは、接続性をテストするためにグラフ全体を走査する必要がなくなるため、重要です。 結合が成功するたびに接続コンポーネントの数が減り、接続コンポーネントの数が 1 つになると、グラフが完全に接続されたことがわかります。 

微妙な実装の詳細は、最後に使用されたエッジの重みを次のように保存することです。`ans`。 これが機能するのは、エッジが非降順で処理されるため、接続を完了する最後に成功した結合によって正しいしきい値が得られるためです。

 ## 特殊なケース

 エッジ ケースの 1 つは、グラフがすでにほぼ接続されており、接続を完了するために 1 つのエッジだけが欠けている場合です。 例えば：```
3 3
0 1 100
1 2 1
0 2 50
```DSU は最初に時間 1 で (1,2) に接続し、次に時間 50 で (0,2) に接続し、そこで停止します。 その瞬間前にノード 0 が分離されているため、答えは 50 です。 

もう 1 つのケースは、すべてのエッジの重みが同じである場合です。 アルゴリズムは引き続きその重みですべてのエッジを処理しますが、十分な結合が発生するとすぐに接続が確立されます。 のために：```
4 3
0 1 5
1 2 5
2 3 5
```各結合は重み 5 で発生し、最後のマージは接続を 5 で完了します。ソートではすべての等しいエッジが保持され、単一のコンポーネントが残るまで DSU がマージされるため、アルゴリズムは共通の重みを正しく出力します。
