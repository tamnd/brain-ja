 ## 解決策
 ## 問題の理解

 _n_ 個の頂点を持つツリー (サイクルのない接続されたグラフを意味します) と _k_ の数が与えられます。 タスクは、正確に _k_ 個のエッジによって分離されている別個の頂点のペアが何ペアあるかをカウントすることです。 ツリー内のすべてのエッジは 2 つの頂点を直接接続し、距離は 2 つの頂点間のエッジの最小数によって測定されます。 入力は、頂点の数、距離 _k_、およびエッジのリストで構成されます。 

制約により、_n_ は最大 50,000 まで可能であることがわかり、これはツリーの問題としては中程度の大きさです。 考えられるすべての頂点のペアを素朴にチェックしようとすると、O(n²) 回の操作が必要になり、最悪の場合で約 25 億回になります。 これは競技プログラミングの一般的な制限時間を超えるため、総当たりよりも大幅に高速なアプローチが必要です。 一方、_k_ は最大 500 であり、_n_ に比べて比較的小さいため、複雑度 O(n・k) または O(n・k²) のアルゴリズムが許容される可能性があることを示唆しています。 

いくつかの特殊なケースでは、単純な解決策がうまくいかない可能性があります。 ツリーにノードが 1 つしかない場合、または _k_ がツリーの高さより大きい場合、有効なペアは存在しないため、答えはゼロになります。 木が直線の場合、すべての距離は一意であり、茂みが多い場合、多くの頂点が祖先までの同じ距離を共有するため、二重にカウントせずに正しくカウントする必要があります。 

## アプローチ

 最も単純なアプローチはブルートフォースです。 各頂点について、幅優先検索または深さ優先検索を実行して、他のすべての頂点までの距離を計算し、正確に _k_ となる距離がいくつあるかを数えることができます。 これは正しいですが、n 個の頂点ごとに最大 n 個のノードを訪問できるため、O(n²) 時間がかかります。 n = 50,000 の場合、これは遅すぎます。 

最適なアプローチでは、ツリー上で動的プログラミングを使用します。 任意のルートを選択し、すべての頂点について、i 番目のエントリがそのサブツリー内の距離 i にある頂点の数をカウントする配列を計算します。 次に、親に対して子を結合するときに、異なる部分木の距離を考慮することで、距離が親を通過するペアを効率的に数えることができます。 各ノードはサイズ k+1 の配列を維持し、子配列を k に関して線形時間でマージするため、これは O(n・k) 時間で機能します。 重要な洞察は、ツリー内では、すべてのパスが完全にサブツリー内に存在するか、または最下位の共通祖先を通過するかのいずれかであるということです。 これにより、個別に検査することなく、すべてのペアをカウントすることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | DP オン ツリー | O(n・k) | O(n・k) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 頂点 1 でツリーを任意にルートします。この選択は正確さに影響しませんが、親子関係を単純化します。 
2. 頂点ごとに配列を維持します`dp`長さ k+1 の場合、`dp[i]`この頂点から距離 i にあるこの頂点をルートとするサブツリー内の頂点の数を格納します。 初期化する`dp[0] = 1`頂点自体は距離 0 にあるため、各頂点に対して。 
3. ルートから深さ優先検索を実行します。 各ノードについて、まず再帰的に計算します。`dp`すべての子の配列。 これにより、親を処理する前にサブツリー内の距離に関する完全な情報が得られます。 
4. ノードを処理するときは、異なる子間のペアを結合します。 距離のペアごとに`(i, j)`そのような`i + j + 2 = k`(親を介して接続するエッジを考慮して)、グローバル応答を増分します。`dp_child[i] * dp_other_children[j]`。 これは、距離が正確に k である、異なるサブツリー内のノードのペアをすべてカウントします。 
5. 子のペアを処理した後、親のペアを更新します。`dp`配列: 子ごとに、距離を 1 つずらし、親の距離に追加します。`dp`。 これにより、距離カウントが上方に伝播されます。 
6. DFS が完了すると、グローバル応答には、正確に k の距離にあるペアの総数が含まれます。 

ここでの不変条件は、`dp[v][i]`サブツリー内のノードの数を常に正確に表します。`v`私からの距離で`v`。 DFS は親の前に子を訪問するため、このプロパティはすべてのノードに適用され、サブツリー全体のペアのカウントが正確かつ網羅的であることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(100000)

def solve():
    n, k = map(int, input().split())
    tree = [[] for _ in range(n)]
    for _ in range(n-1):
        a, b = map(int, input().split())
        tree[a-1].append(b-1)
        tree[b-1].append(a-1)

    ans = 0

    def dfs(node, parent):
        nonlocal ans
        dp = [0] * (k+1)
        dp[0] = 1
        for child in tree[node]:
            if child == parent:
                continue
            child_dp = dfs(child, node)
            for i in range(k):
                ans += dp[i] * child_dp[k-1-i]
            for i in range(k):
                dp[i+1] += child_dp[i]
        return dp

    dfs(0, -1)
    print(ans)

solve()
```このコードはツリー隣接リストを設定し、再帰を伴う DFS を使用して距離配列を設定します。 それぞれ`dp`配列はサブツリーの距離をカウントし、ネストされたループは二重にカウントせずにクロスサブツリーのペアを計算します。 親に追加する前に子配列を 1 つシフトすると、正しい距離の伝播が保証されます。 

## 実用的な例

 サンプル入力の場合:```
5 2
1 2
2 3
3 4
2 5
```頂点 1 をルートとします。DFS はノード 1、2、3、4、5 を訪問します。`dp`各ノードの配列:

 | ノード | DFS後のdp | ansへの貢献 |
 | --- | --- | --- |
 | 4 | [1,0,0] | 0 |
 | 3 | [1,1,0] | 0 |
 | 5 | [1,0,0] | 0 |
 | 2 | [1,2,1] | 4 |
 | 1 | [1,1,0] | 0 |

 最終的な答えは 4 で、予想される出力と一致します。 

別の入力、k=1 のライン ツリー 1-2-3:```
3 1
1 2
2 3
```

`dp`配列と貢献:

 | ノード | DP | 貢献 |
 | --- | --- | --- |
 | 3 | [1,0] | 0 |
 | 2 | [1,1] | 1 |
 | 1 | [1,1] | 1 |

 距離 1 のペアは (1,2) と (2,3) であり、正しいことが確認されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n・k) | n 個のノードのそれぞれは、サイズ k+1 の dp 配列を維持し、子配列のマージには O(k) | かかります。 
| スペース | O(n・k) | DFS 再帰中にすべてのノードの dp 配列を保存します。 

n ≤ 50,000 および k ≤ 500 の場合、最悪の場合の時間は 2,500 万回の操作となり、これは 3 秒未満に収まります。 メモリ使用量は 100 MB 未満で、512 MB の制限を下回っています。

 ## 特殊なケース

 頂点が 1 つで k=1 のツリーは 0 を返す必要があります。DFS は`dp`配列は [1] であり、子が存在しないため、ペアはカウントされません。 k=1 の星型ツリーは、葉から中心までのすべてのエッジを正しくカウントしますが、中心を通る距離が 1 ではなく 2 であるため、葉から葉までは二重にカウントしません。 k が木の高さに等しいライン ツリーでは、DFS は離れた葉ノードをルートとのペアとして正しく累積します。
