 ## 解決策
 ## 問題の理解

 私たちはできるだけ多くの兵士に防弾チョッキを装備させる任務を負っています。 各兵士には好みのベストのサイズがありますが、所定の範囲内での逸脱は許容されます。 具体的には、i 番目の兵士は、次のサイズのベストを着用できます。`a[i] - x`そして`a[i] + y`。 利用可能なベストのサイズは固定されており、各ベストは 1 人の兵士のみに割り当てることができます。 目標は、兵士へのベストの割り当てとともに、装備できる兵士の最大数を出力することです。 

入力サイズは非常に大きく、最大 100,000 人の兵士と 100,000 個のベストが含まれます。 すべての兵士のすべてのベストをチェックする単純なソリューションでは、最大 10^10 の比較が必要になりますが、これは 3 秒の制限時間では許容範囲をはるかに超えています。 したがって、理想的には線形または線形に近い時間で機能するソリューションが必要です。`O(n + m)`または`O(n log n + m log m)`。 

複数の兵士が同じベストと互換性がある場合、微妙なエッジケースが発生します。 たとえば、2 人の兵士が両方ともサイズ 3 を受け入れ、利用可能なベストにサイズ 3 のベストが 1 つだけ含まれている場合、アルゴリズムはどの兵士を最初に割り当てるかを選択する必要があります。 不用意に実装すると、可能な割り当てを見逃したり、同じベストを再利用しようとしたりする可能性があります。 

もう 1 つのエッジ ケースは、兵士の許容範囲が利用可能なベストをすべて超えている場合です。 たとえば、兵士の許容範囲は 1 ～ 100 ですが、すべてのベストのサイズが 101 以上の場合、ベストを割り当てることはできず、アルゴリズムはこの兵士を正しくスキップする必要があります。 

## アプローチ

 ブルートフォース手法は簡単です。兵士ごとに、利用可能なすべてのベストをスキャンして、許容範囲内に該当するベストがあるかどうかを確認します。 互換性のあるベストが見つかった場合は、使用済みとしてマークして次に進みます。 このアプローチはあらゆる可能性をチェックするため、原理的には正しいですが、非常に非効率的です。 最大の制約の場合、最大 10^10 の比較が必要になる可能性がありますが、これでは遅すぎます。 

重要な観察は、兵士とベストの両方が降順ではないことです。 この構造により、兵士用に 1 つのポインターとベスト用に 1 つのポインターを維持する 2 ポインター アプローチが可能になります。 各ステップで、現在のベストが現在の兵士に適合するかどうかを確認します。 存在する場合は、それを割り当てて、両方のポインタを進めます。 ベストが兵士にとって小さすぎる場合は、ベストのポインタを進めます。 ベストが大きすぎる場合は、兵士ポインタを進めます。 この貪欲な戦略が機能するのは、兵士とベストが分類されているためです。ベストが現在の兵士にとって大きすぎると、前の兵士には適合しなくなり、ベストが小さすぎると、後の兵士には適合しなくなります。 

これにより、時間の複雑さが O(n * m) から O(n + m) に軽減され、割り当てを保存するための線形の追加スペースのみが必要になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * m) | お(1) | 遅すぎる |
 | 貪欲なツーポインター | O(n + m) | O(min(n, m)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 2 つのポインターを初期化します。`i`兵士にとっても、`j`ベストの場合、どちらも 0 から始まります。また、空のリストを初期化します。`assignments`最終的なペアを保存します。 
2. 両方のポインターが範囲内にあるときに、現在のベストのサイズを確認します。`b[j]`現在の兵士の許容範囲に反する`[a[i] - x, a[i] + y]`。 
3. もし`b[j]`よりも小さいです`a[i] - x`、ベストポインタを進めます`j`なぜなら、このベストはこの兵士や、少なくとも以下を必要とする後の兵士には適合しないからです。`a[i] - x`。 
4. もし`b[j]`よりも大きいです`a[i] + y`、兵士ポインタを進めます`i`なぜなら、この兵士にぴったりのベストが残っていないからだ。 
5. もし`b[j]`以内にあります`[a[i] - x, a[i] + y]`を追加して、このベストをこの兵士に割り当てます`(i + 1, j + 1)`に`assignments`、次に両方のポインタを進めます。 
6. ポインタの 1 つがそれぞれのリストの最後に到達するまで続行します。 
7. 長さを出力します。`assignments`続いてペア。 

これが機能する理由は、互換性のある最小のベストを貪欲に選択することで、後の兵士がベストを見つける最良の機会を確保できるためです。 維持される不変条件は、割り当てられたベストはすべて互換性があり、一度だけ使用されるということです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m, x, y = map(int, input().split())
a = list(map(int, input().split()))
b = list(map(int, input().split()))

i = j = 0
assignments = []

while i < n and j < m:
    if b[j] < a[i] - x:
        j += 1
    elif b[j] > a[i] + y:
        i += 1
    else:
        assignments.append((i + 1, j + 1))
        i += 1
        j += 1

print(len(assignments))
for soldier, vest in assignments:
    print(soldier, vest)
```コードは 2 ポインター アルゴリズムに従います。 私たちは各ベストを兵士の許容範囲と照らし合わせて注意深くチェックし、比較に基づいて正しいポインターを増分します。 Off-by-one エラーは、追加時に 0 ベースのインデックスを 1 ベースに変換することで回避されます。`assignments`。 使用する`sys.stdin.readline`大規模なデータセットの高速入力を保証します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, m, x, y = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    i = j = 0
    assignments = []
    while i < n and j < m:
        if b[j] < a[i] - x:
            j += 1
        elif b[j] > a[i] + y:
            i += 1
        else:
            assignments.append((i + 1, j + 1))
            i += 1
            j += 1
    out = [str(len(assignments))] + [f"{s} {v}" for s,v in assignments]
    return "\n".join(out)

# provided samples
assert run("5 3 0 0\n1 2 3 3 4\n1 3 5\n") == "2\n1 1\n3 2"
assert run("3 5 2 2\n3 4 5\n1 2 3 4 5\n") == "3\n1 1\n2 2\n3 3"

# custom test cases
assert run("1 1 0 0\n5\n5\n") == "1\n1 1", "minimum input"

assert run("3 3 0 0\n1 2 3\n10 11 12\n") == "0", "no compatible vests"
assert run("4 4 10 10\n5 6 7 8\n1 2 3 4\n") == "0", "vests smaller than range"
