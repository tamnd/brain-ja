 ## 解決策
 ## 問題の理解

 ゲームは固定の 3×3 グリッドでプレイされますが、ボードとして考えるよりも、1 から 9 までの 9 つのインデックス付きポジションとして扱う方が簡単です。2 人のプレーヤーが交互に手番を行い、X が最初に、O が 2 番目に、自分のシンボルを空のセルに配置します。 プレーヤーは、シンボルが完全な行、列、または対角線を形成すると、即座に勝ちとなります。 

面白いのは、ゲームの開始前に、セルを動的に無効にする制約が与えられることです。 各制約は、別のセル A がまだ空である間、特定のセル B が使用できなくなることを示しています。 いずれかのプレイヤーが A を埋めるとすぐに制限は消え、他の制限がブロックしていなければ B は再び使用可能になります。 

したがって、移動は、選択したセルが空で、そのセルを対象とするすべての制約の前提条件セルがすでに入力されている場合にのみ有効です。 これは、各セルが依存構造を持っていることを意味します。つまり、ゲームの早い段階で他の特定のセルが再生された後でのみ再生できます。 

課題は、両方のプレーヤーがすべての制約を理解し、完璧にプレーする最適なプレーの下で結果を決定することです。 

制約は最大 100000 と大きくなりますが、ボードのセルはわずか 9 つです。 入力サイズと状態サイズのこの違いが中心的なヒントです。 ボード構成のみを調査するソリューションはどれも実現可能ですが、移動ごとに単純に制約チェックをシミュレートしようとするものは、前処理しない限り TLE になります。 

微妙なケースは、循環依存関係から発生します。 セル 1 がセル 2 をブロックし、セル 2 がセル 1 をブロックした場合、どちらも最初にプレイすることはできないため、両方とも永久に利用できなくなります。 すべてのセルが最終的にプレイ可能になると仮定する単純なアプローチでは、そのようなセルがゲーム ツリーに誤って含まれてしまいます。 

もう 1 つの注意が必要な状況は、重要な瞬間に制約によって唯一の勝ち手が取り除かれる場合です。 たとえば、プレーヤーは勝ちラインを持っているように見えますが、そのラインの 1 つのセルは、別の無関係なセルがプレイされるまでブロックされ、最適な結果が完全に変わる可能性があります。 

## アプローチ

 ブルートフォースの観点では、ゲームをボードのすべての可能な状態の検索として扱い、各ステップでどのセルが X で占有され、どのセルが O で占有され、どのセルが空であるかを追跡します。 各状態からすべての合法的な手を生成し、適用して、結果を再帰的に評価します。 

ゲームは決定的で有限であるため、これは正しいです。 ただし、分岐係数は最大 9 で、各セルはさまざまな順序で配置でき、X、O、および空を区別すると、3⁹ 構成程度の状態空間になります。 これは小さいですが、状態を効率的に保存した場合に限ります。 移動ごとに制約を最初から繰り返しチェックする単純な実装では、遷移ごとにコストが最大 10⁵ 倍になる可能性があり、これでは遅すぎます。 

重要な点は、制約は前提条件のセルがすでに入力されているかどうかのみに依存し、どのプレイヤーがそのセルを入力したかには依存しないということです。 これは、手の合法性は占有されているセルのセットのみに依存し、勝ちは X と O の割り当てに依存することを意味します。ボードには 9 つのセルしかないため、完全な状態をコンパクトにエンコードし、すべての状態に対してメモ化されたミニマックスを実行できます。 

私たちはこのゲームを、状態のグラフに対する 2 人用の完全情報ゲームとして扱います。 現在のプレイヤーのマークを有効なセルに配置することで、各状態が他の状態に移行します。 メモ化による再帰を使用して結果を評価します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 繰り返し制約チェックを行うブルート フォース シミュレーション | 大きな定数係数を持つ指数関数、実質的に O(3⁹ · N) | O(3⁹) | 遅すぎる |
 | 前処理を備えた 3 ステート ボード上のステート DP | O(3⁹ · 9) | O(3⁹) | 承認済み |

 ## アルゴリズムのチュートリアル

各ボードの状態を、セルごとに空、X、O のいずれかを格納することで表します。セルが 9 つしかないため、これを基数 3 でエンコードでき、コンパクトな整数の状態が得られます。 

また、各セル B がすべてのセル A のビットマスクを格納する構造に制約を前処理します。このビットマスクは、B が使用可能になる前にすでに入力されている必要があります。 これにより、制約チェックが単一ビット演算に削減されます。 

1. 各ボードの状態を長さ 9 の 3 進表現としてエンコードし、塗りつぶされたセルを数えることによって誰のターンであるかを定義します。 
2. 三目並べのすべての勝利ライン マスクを事前計算します。 どちらかのプレイヤーが勝利トリプルをすでに占有している場合、状態は末期です。 
3. すべての A を含むセル B ごとに依存関係マスクを作成し、A が入力されるまで B を使用できないようにします。 
4. その設定から最適なプレイを想定した最終結果を返す再帰関数 dp(state) を定義します。 
5. dp(state) で手を生成する前に、状態がすでに終了しているかどうかを確認します。 X または O に勝ちラインがある場合は、その結果をすぐに返します。 
6. 空のセルを反復処理して、すべての正当な手を生成します。 移動は、そのポジションの前提条件セルがすべてすでに埋められている場合にのみ有効です。 
7. 正当な手ごとに、それを適用し、ターンを切り替え、結果の状態を再帰的に評価します。 
8. 現在のプレイヤーが少なくとも 1 つの分岐で自分の勝利を強制できる場合は、その結果を返します。 それ以外の場合、すべての手が相手の勝ちにつながる場合は、相手の勝ちを返します。 どちらの側も勝利を強制できず、結果が改善する手を打たなかった場合は引き分けに戻ります。 

核となる不変条件は、dp(state) が、X、O、および塗りつぶされたセルの正確な構成に対する最適なプレイの下でのゲーム結果を正しく表すことです。 再帰では、保存された同じ結果を返さずに状態を再訪することはなく、その状態に到達するすべてのパスにわたる一貫性が保証されます。 すべての遷移では、満たされたセルの数が厳密に増加するため、状態グラフは非循環となり、終了が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(1000000)

WIN_LINES = [
    (0,1,2),(3,4,5),(6,7,8),
    (0,3,6),(1,4,7),(2,5,8),
    (0,4,8),(2,4,6)
]

def check_win(board, player):
    for a,b,c in WIN_LINES:
        if board[a] == board[b] == board[c] == player:
            return True
    return False

def solve():
    n = int(input())
    prereq = [0] * 9

    for _ in range(n):
        a, b = map(int, input().split())
        a -= 1
        b -= 1
        prereq[b] |= (1 << a)

    memo = {}

    def encode(board):
        state = 0
        p = 1
        for i in range(9):
            state += board[i] * p
            p *= 3
        return state

    def decode(state):
        board = [0] * 9
        for i in range(9):
            board[i] = state % 3
            state //= 3
        return board

    def filled_mask(board):
        m = 0
        for i in range(9):
            if board[i] != 0:
                m |= (1 << i)
        return m

    def count_moves(board):
        return sum(1 for x in board if x != 0)

    def dp(state):
        if state in memo:
            return memo[state]

        board = decode(state)

        if check_win(board, 1):
            memo[state] = 1
            return 1
        if check_win(board, 2):
            memo[state] = -1
            return -1

        move_count = count_moves(board)
        turn = 1 if move_count % 2 == 0 else 2

        can_move = False
        best = -2

        for i in range(9):
            if board[i] != 0:
                continue
            if (prereq[i] & filled_mask(board)) != prereq[i]:
                continue

            can_move = True
            board[i] = turn
            nxt = dp(encode(board))
            board[i] = 0

            if turn == 1:
                best = max(best, nxt)
            else:
                best = min(best, nxt)

            if turn == 1 and best == 1:
                break
            if turn == 2 and best == -1:
                break

        if not can_move:
            memo[state] = 0
        else:
            memo[state] = best

        return memo[state]

    init = [0] * 9
    res = dp(encode(init))

    if res == 1:
        print("X")
    elif res == -1:
        print("O")
    else:
        print("E")

solve()
```エンコードのステップでは、各ボード全体が 1 つの整数に圧縮されるため、メモ化が効率的に機能します。 再帰では、明示的に保存するのではなく、塗りつぶされたセルの数から現在のプレーヤーを決定します。 

制約チェックはセルごとに 1 つのビットマスク比較に削減されるため、各移動中に N 個のルールすべてをスキャンすることができなくなります。 

勝利チェックはデコード直後に実行され、ラインを完了する手がそれ以上の手を探ることなくゲームを終了することが保証されます。 

## 実用的な例

 両方のプレイヤーが最適にプレイする、制約のない最小限のケースを考えてみましょう。 ゲームは標準的な三目並べのように動作し、引き分けにつながります。 

状態の進行:

 | ステップ | ボード (X=1、O=2) | 移動するプレーヤー | 法的措置 | これまでの成果 |
 | --- | --- | --- | --- | --- |
 | 0 | すべて空 | X | すべてのセル | 不明 |
 | 1 | 中央の X | ああ | 8セル | まだ開いています |
 | 2 | オーブロックコーナー | X | 削減 | まだ描ける |

 このトレースは、制約がなければ、最適な遊びが平衡状態に収束し、これが古典的な結果に対応することを示しています。 

ここで、前提条件のセルが満たされるまで、制約によって主要な防御の動きが無効になる場合を考えてみましょう。 初期の動きは対称的に見えるかもしれませんが、依存関係が満たされると、強制的な勝利ラインが利用可能になり、一方の側の評価が引き分けから勝利に反転します。 これは、合法性を静的に仮定するのではなく、充填セル構造から動的に再計算する必要がある理由を示しています。 

## 複雑さの分析

 | --- | --- | --- |
 | 時間 | O(3⁹ · 9) | 各状態は 1 回評価され、状態ごとに最大 9 つの遷移が行われます。

 ## 特殊なケース

 セル自体がブロックされる自己参照制約により、そのセルはゲーム全体で使用できなくなります。 前処理ステップでは、決して満たされない前提条件ビットとしてそれを保存するため、移動ジェネレーターはそれを許可しません。 DP は分岐を減らすことで自然に適応します。 

どちらの前提条件も満たされないため、2 つのセル間の相互依存関係は両方に同じ効果をもたらします。 状態の展開中、両方のセルは常にスキップされ、特別な処理を行わなくても効果的なゲーム ツリーが縮小されます。 

制約によってすべての正当な手が早期に排除される構成では、強制ドローにつながります。 その状況では、DP は遷移が不可能な状態に達し、すぐにゼロを返します。これは、ルールの下でゲームの停止を正しく表します。
