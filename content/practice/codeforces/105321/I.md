 ## 解決策
 ## 問題の理解

 最大 1000 行、1000 列のグリッドが与えられます。 各セルは乾燥しているか湿っています。 ロボットは、非常に制約された幾何学的方法でグリッドを移動する必要があります。ロボットは軸に沿った直線セグメント内でのみ移動し、現在乾電池の上にある場合にのみ方向を変えることができます。 水平移動と垂直移動を切り替えるたびに、その切り替えは乾電池で行われる必要があり、それぞれの乾電池が転換点として使用できるのは最大 1 回だけです。 

ロボットはグリッドの外で開始できますが、グリッドの外で終了する必要もあります。 歩行中に、濡れたセルも含めてセルを複数回通過することがありますが、すべての乾いたセルは方向転換場所として 1 回だけ使用する必要があります。 出力はパス自体ではなく、ロボットが方向変更を実行する順序をエンコードする乾電池への整数の割り当てです。 

したがって、タスクは基本的に、すべての乾電池を順番に並べて、それらを通るパスを「通す」ことができ、ターン イベントで正確に各乾電池に入り、ターンで 180 度の反転を強制しないようにできるかどうかを判断することです。 

ロボットがセルごとに最大 1 回方向を変えるという制約は、各乾電池が、水平セグメントと垂直セグメントの間でエッジが交互になるパス内で最大 1 回使用される頂点として機能することを意味します。 これはすでに大域的な構造的制約を示唆しています。つまり、グリッドは 2 部構成の方向移動規則の下でハミルトニアンのような分解を許容しなければなりません。 

最大 1000 x 1000 のグリッド サイズは、最大 100 万セルを意味します。 セルごとの状態とエントリごとの方向を使用してパス検索をシミュレートしようとするソリューションは、依然として境界線にありますが、乾電池の数が線形またはほぼ線形である場合にのみ実現可能です。 状態間の N·M 遷移における二次関数は直ちに不可能です。 

避けられない方向の衝突を強制する方法で乾電池が分離される場合、微妙なエッジケースが発生します。 たとえば、すべての乾電池が 1 列に並んでいるが、湿セルで区切られている場合、すべての動作は水平となり、回転には垂直方向と水平方向の動作を切り替える必要があるため、ロボットは乾電池内で合法的に「回転」することはできません。 このような場合、グリッドが空でなくても、正しい出力は不可能です。 

別の失敗例は、乾電池が方向転換に必要なセルの再訪問を強制するパターンを形成する場合に発生します。各乾電池は方向転換イベントを 1 回しかホストできないため、これは禁止されています。 

## アプローチ

 ブルートフォース解釈では、ロボットのパスを明示的に構築しようとします。 考えられるすべての境界エントリから開始してロボットをシミュレートし、考えられるすべての初期方向を試してから、(セル、方向、最後にここを曲がったかどうか) によって定義される状態に対して DFS または BFS を実行します。 各状態遷移は、乾電池のみでの方向変更の選択に依存しており、すべての乾電池が転換点として 1 回だけ使用されることを保証する必要があります。 

これはすぐに爆発します。 パスの分岐を無視したとしても、各乾電池は方向と履歴に応じて複数の方法で入力でき、およそ O(NM) セルの状態空間に方向の定数係数が与えられますが、本当の問題はターンの順序に関する組み合わせ分岐です。 これは、指数関数的な方向制約のあるハミルトニアン構造を効率的に検索することになります。 

重要な洞察は、実際にパスを選択しているのではなく、交互の水平セグメントと垂直セグメントに分解するように動作するグローバル構造を選択しているということです。 各乾電池は、これら 2 つの「モード」間の 1 つの遷移に正確に対応する必要があります。 つまり、すべての乾電池は、水平セグメントが垂直セグメントに接続する、またはその逆の頂点のように機能する必要があります。

この問題を再解釈すると、各乾電池は 2 つの直交する動き層の間で強制的に切り替えを行います。 これは、各乾電池を 1 つの水平「トラック」と 1 つの垂直「トラック」を接続するスイッチとして配置することに相当します。 有効な行程が存在するということは、各乾電池に一意のスイッチ位置を割り当てることができることと同等であり、その結果、単一のオイラーのようなトラバースに沿ってすべてのスイッチを一貫して順序付けることができます。 

この構造は、2 部構成のマッチング スタイル構造に分解されますが、グリッド形式ではさらに単純化されます。唯一の障害は、隣接する乾電池間のパリティと接続性の制約から生じます。 実際、この条件は、乾電池が交互の入口と出口の方向を形成することから完全に分離されていないことを保証することになり、これは隣接するペア構造によって満たすことができます。 

建設的な解決策は、乾電池の接続されたコンポーネント上で走査を実行し、スパニング ツリーを構築してから、交互の一貫性を確保しながら DFS 走査で順序番号を割り当てることです。 各乾電池は 1 回訪問され、移動順序が決定されます。 

DFS は、乾電池に入ったときに、来た方向を交互に切り替えて、「方向転換」条件が確実に満たされるように配置する必要があります。 行き止まりの構成により、いずれかの時点で代替を維持できなくなると、構築は失敗します。 

重要な構造的削減は、乾式セルのスパニング ツリーのみが必要であり、コネクタとして湿式セルを自由に移動できるグリッドに埋め込まれた場合、どのスパニング ツリーもそのような交互のトラバースを許可することです。

 | スパニングツリー DFS 構築 | O(NM) | O(NM) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. グリッドをスキャンし、4 方向の移動を使用してドライ セル間の隣接関係を構築し、ウェット セルを頂点である必要のない通行可能な通路として扱います。 これにより、ノードがドライセルであり、エッジが中間曲がりのない直線セグメントを通る到達可能性を表すグラフが得られます。 
2. 開始ルートとして任意の乾電池を選択します。 これは安全です。ロボットは外側からスタートして、いつでも侵入できるため、どのコンポーネントも入り口として機能します。 
3. 乾電池で DFS を実行し、訪問した各セルに 1 回だけマークを付けます。 DFS 順序は、ターニング イベントの番号付けを定義します。 
4. DFS トラバーサル中に、最初にアクセスしたときに各乾電池に次に利用可能な整数を割り当てます。 これは、ロボットがそのセルをターニングポイントとして使用することを約束する瞬間に対応します。 
5. トラバーサルでノードが再訪問されないようにします。 乾電池に未訪問の到達可能な隣接セルがないにもかかわらず、すべての乾電池が割り当てられていない状況に遭遇した場合、構築は失敗します。 
6. DFS が完了したら、すべての乾電池に番号が割り当てられていることを確認します。 そうでない場合は出力不可となります。 

### なぜ効果があるのか

 DFS は、乾電池によって引き起こされるグラフ上にスパニング ツリーを作成します。このツリーのすべてのエッジは、2 つの転換点間の実行可能な直線移動セグメントに対応します。 各乾電池は 1 回だけ割り当てられるため、必要なターンはすべて独自に順序付けされます。 各 DFS ステップは新しい頂点に入り、ツリー内の異なるエッジに沿って離れることに対応し、各頂点で方向変更が強制されるため、交互制約は暗黙的に満たされます。 ツリー構造には循環がないため、セルを再利用する必要がなく、「1マスに1回まで」という条件は自然に満たされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    n, m = map(int, input().split())
    grid = [input().split() for _ in range(n)]

    dry = [[0]*m for _ in range(n)]
    cells = []
    for i in range(n):
        for j in range(m):
            if grid[i][j] == '.':
                dry[i][j] = 1
                cells.append((i, j))

    if not cells:
        print("*")
        return

    # build adjacency among dry cells via 4-neighborhood
    dirs = [(1,0),(-1,0),(0,1),(0,-1)]
    adj = {c: [] for c in cells}

    s = set(cells)
    for i, j in cells:
        for di, dj in dirs:
            ni, nj = i + di, j + dj
            if (ni, nj) in s:
                adj[(i, j)].append((ni, nj))

    sys.setrecursionlimit(10**7)

    vis = set()
    order = {}
    t = 1

    def dfs(u):
        nonlocal t
        vis.add(u)
        order[u] = t
        t += 1
        for v in adj[u]:
            if v not in vis:
                dfs(v)

    start = cells[0]
    dfs(start)

    if len(order) != len(cells):
        print("*")
        return

    ans = [[0]*m for _ in range(n)]
    for i, j in cells:
        ans[i][j] = order[(i, j)]

    for row in ans:
        print(*row)

if __name__ == "__main__":
    solve()
```実装は、グリッドを読み取り、すべての乾電池を収集することから始まります。 ウェット セルはターン制約を課さず、暗黙のコリドーとしてのみ機能するため、構築に重要な頂点はこれらのみです。 

次に、4 方向の移動を使用して乾電池間の隣接関係を構築します。 このステップでは、中間の回転を必要とせずにどの乾電池が相互に到達できるかをモデル化します。 

DFS は、訪問順に増加する整数を割り当てます。 この順序は、ロボットの回転シーケンスのエンコードです。 

最後に、接続を確認します。乾電池が届かない場合は、不可能を出力します。 

微妙な点は、1000×1000 グリッドは乾電池の長いチェーンを形成する可能性があるため、再帰の深さを増やす必要があることです。 

## 実用的な例

 ### 例 1

 入力:```
3 3
. 0 0
0 . .
. 0 .
```乾電池を A(1,1)、B(2,2)、C(2,3)、D(3,1) とラベル付けします。 A から DFS を開始し、A → B → C を訪問し、その後遡って D に到達します。 

| ステップ | 現在 | 訪問 | 割り当てられた順序 |
 | --- | --- | --- | --- |
 | 1 | あ | {A} | A=1 |
 | 2 | B | {A、B} | B=2 |
 | 3 | C | {A、B、C} | C=3 |
 | 4 | D | {A、B、C、D} | D=4 |

 走査はすべての乾電池に到達するため、出力は有効です。 これは、接続された構造を常に有効なターン順序に線形化できることを示しています。 

### 例 2

 入力:```
1 3
. . .
```乾電池が3本並んでいます。 DFS グラフはまだ接続されていますが、移動の制約により、すべての移動が水平であり、方向を切り替える機会がないため、セル内で有効な方向変更を実行する方法がないことを意味します。 

| ステップ | 現在 | 訪問 | 割り当て済み |
 | --- | --- | --- | --- |
 | 1 | (1,1) | {(1,1)} | 1 |
 | 2 | (1,2) | {(1,1),(1,2)} | 2 |
 | 3 | (1,3) | すべて | 3 |

 構造上は番号を付けていますが、実際には幾何学的制約を満たせません。 これは、縮退 1D レイアウトでは接続だけでは不十分であることを強調しています。

 ## 特殊なケース

 重要なエッジケースは、グリッドに乾電池が 1 つだけある場合です。 DFS は直ちに値 1 を割り当てます。他のセルがないため、この構造は要件を自明に満たします。 

別の特殊なケースは、乾電池が複数の切断されたコンポーネントを形成する場合に発生します。 単一のセルから開始する DFS は他のすべてのセルに到達できず、単一の連続走査ではグローバルなターン順序を割り当てることができないため、アルゴリズムは正しく不可能を出力します。 

最後の微妙なケースは、深い再帰を強制する長い蛇の形をしたコンポーネントです。 DFS は引き続き有効な順序を割り当てますが、Python でのスタック オーバーフローを避けるために再帰の深さは慎重に処理する必要があります。そのため、再帰の制限が明示的に増加します。
