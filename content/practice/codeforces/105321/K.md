 ## 解決策
 ## 問題の理解

 私たちには、次のものだけで構成される文字の大きなグリッドが与えられています。`#`そして`.`。 このグリッド内には、隠されたタイルがあります。`#`は、厳密に 1 つの固定パターンに属しており、各パターンは、文字 T、A、および P を表す 3 つの固定 ASCII 図形のうちの 1 つのスケールなしのコピーです。これらの図形は複数回出現することができ、どこにでも配置でき、接触したり近接したりすることもできますが、決して重なり合うことはなく、すべての`#`グリッド内の文字は、配置された 1 文字だけで説明されなければなりません。 

タスクは配置を再構築することではなく、構築に使用された T、A、および P のコピーの数を決定することだけです。 

グリッド サイズは 1000 x 1000 までなので、セルの数は最大 100 万個になります。 すべての位置で形状のすべての配置を試行したり、セルごとに完全なパターン マッチングを繰り返し実行したりするソリューションでは、最悪の場合、二次的な動作が発生する危険があります。 正しいアプローチでは、基本的にセル全体にわたって線形時間でグリッドを処理する必要があります。 

微妙な難点は、乱雑な ASCII 画像では図形が隣接しているという意味では重なり合っていますが、図形の点では重ならないことが保証されていることです。`#`カバレッジ。 これは、分解特性を意味します。つまり、それぞれの接続された構造です。`#`セルは任意ではありませんが、いくつかの固定テンプレートの 1 つと正確に一致する必要があります。 

単純な失敗モードは、「左上アンカー マッチング」を試みることです。つまり、毎回形状をスキャンします。`#`完全なテンプレートとの一致を試みます。 これは 2 つの点で失敗します。 まず、重複する試行を二重にカウントできます。 第 2 に、順序付けに敏感です。不適切な貪欲なアプローチによる以前のチェックによって、形状が部分的に消費される可能性があります。 

2 番目の障害モードは、グリッドを任意の接続コンポーネントとして扱い、一般的なグラフ マッチングを使用することです。 形状が硬くて小さいため、これでは遅すぎて不必要です。 

## アプローチ

 ブルートフォースのアイデアは単純です。すべてのセルを反復処理し、`#`、その位置に中心または固定された 3 つのテンプレート (T、A、P) のそれぞれを一致させてみます。 テンプレートのマッチングとは、アンカーを基準とした固定座標セットをチェックすることを意味します。 一致が成功した場合は、それらのセルを使用済みとしてマークし、続行します。 

これが機能するのは、各文字のサイズが一定であるため、各試行は O(1) であるためです。 ただし、最悪の場合、グリッドがいっぱいになる場合があります。`#`、すべてのセルで 3 つのテンプレートを照合しようとして、O(NM) チェックが発生する可能性がありますが、これは問題ありません。 本当の問題は正確性です。貪欲なマーキングではスキャン順序への依存関係が生じます。 形状の割り当てが早すぎると、別の有効な分解に属するセルが消費される可能性があります。 

重要な観察は、分解が恣意的なマッチングからではなく、構造から局所的に認識可能であるということです。 それぞれの文字には、その表現方法に特有の「特徴」があります。`#`セルが分散されています。 完全な形状を繰り返し一致させるのではなく、領域ごとに 1 回構造的特徴を検出します。 特に、各文字は、その接続性と分岐パターンを調べることで識別できます。`#`細胞。 これにより、問題は配置の検索ではなくコンポーネントの分類に軽減されます。 

まず、接続されたコンポーネントを構築します`#`BFS または DFS を使用するセル。 各セルは正確に 1 つの文字に属しているため、各コンポーネントは T、A、または P の単一のインスタンスに対応します。コンポーネント内で、4 近傍グラフの次数分布などのいくつかの構造的不変量を計算します。 形状は安定した方法で異なります。1 つは横棒のある中央茎を持ち (T)、1 つは三角形または分岐構造を持ち (A)、もう 1 つは異なる分岐パターンを持ちます (P)。 これらのパターンは、次数と主要な接合点を数えることによって決定的に区別できます。 

各コンポーネントが分類されたら、出現数をカウントします。

 ## アルゴリズムのチュートリアル

 1. グリッドをスキャンし、それぞれが含まれるグラフを暗黙的に構築します。`#`セルはその 4 方向の隣接セルに接続します。 この表現は、文字が連続した形状であるという事実を捉えています。 
2. 未訪問のすべてに対して BFS/DFS を実行します。`#`セルを使用して各連結成分を抽出します。 これが機能するのは、すべての文字が完全に接続された文字で構成されているためです。`#`セルとセルを共有する 2 つの文字はありません。 
3. 各コンポーネントについて、そのすべてのセルを収集し、各セルの次数、つまり隣接するセルの数を計算します。`#`同じコンポーネント内にあるセル。 この局所的な尺度は形状定義の下で安定しています。 
4. エンドポイント (次数 1 セル)、接合部 (次数 3 または 4 セル) の数、垂直延長部と水平延長部の分布など、コンポーネント内の構造ランドマークの小さなセットを特定します。 
5. これらの不変量を T、A、および P の既知の署名と比較してコンポーネントを分類します。それぞれの文字の接続パターンが根本的に異なるため、個別の組み合わせが生成されます。T は 1 本の水平バーを持つ単一の垂直スパインを持ち、A は中央の頂点と交差結合を持つ対称構造を持ち、P は単一の上部ループ状アタッチメントを持つ垂直スパインを持ちます。 
6. T、A、または P の対応するカウンタをインクリメントします。 
7. 3 つのカウントを出力します。 

正しさは、各文字が剛体であり、隣接構造を変更せずに別の文字に変形できないという事実に依存します。 したがって、グラフの構造によって文字の種類が一意に決まります。 

### なぜ効果があるのか

 重要な不変条件は、有効な各文字が、4 近傍隣接の下で小さな接続されたグリッド グラフの一意の同型クラスに対応することです。 すべてのコンポーネントはまさにそのようなグラフの 1 つであるため、分類はどの同型写像クラスに一致するかを識別することになります。 BFS により、これらのグラフを明確に分離できるようになり、次数ベースの署名により、曖昧さなくグラフを区別できるようになります。 問題の固定テンプレート制約に違反するため、コンポーネントが部分的に複数の文字に似ることはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n, m = map(int, input().split())
    g = [input().strip() for _ in range(n)]
    
    vis = [[False] * m for _ in range(n)]
    
    def bfs(si, sj):
        q = deque([(si, sj)])
        vis[si][sj] = True
        cells = []
        
        while q:
            i, j = q.popleft()
            cells.append((i, j))
            for di, dj in ((1,0), (-1,0), (0,1), (0,-1)):
                ni, nj = i + di, j + dj
                if 0 <= ni < n and 0 <= nj < m:
                    if not vis[ni][nj] and g[ni][nj] == '#':
                        vis[ni][nj] = True
                        q.append((ni, nj))
        return cells
    
    def classify(cells):
        s = set(cells)
        deg = {}
        for i, j in cells:
            d = 0
            for di, dj in ((1,0), (-1,0), (0,1), (0,-1)):
                ni, nj = i + di, j + dj
                if (ni, nj) in s:
                    d += 1
            deg[(i, j)] = d
        
        cnt1 = sum(1 for v in deg.values() if v == 1)
        cnt2 = sum(1 for v in deg.values() if v == 2)
        cnt3 = sum(1 for v in deg.values() if v >= 3)
        
        if cnt3 == 1:
            return 'T'
        if cnt3 >= 2:
            return 'A'
        return 'P'
    
    T = A = P = 0
    
    for i in range(n):
        for j in range(m):
            if g[i][j] == '#' and not vis[i][j]:
                comp = bfs(i, j)
                t = classify(comp)
                if t == 'T':
                    T += 1
                elif t == 'A':
                    A += 1
                else:
                    P += 1
    
    print(T, A, P)

if __name__ == "__main__":
    solve()
```BFS セクションは、各文字インスタンスを分離する役割を果たします。 グリッドは決して再訪されることはありません。`#`は、正確に 1 回訪問されたとマークされます。 分類ステップでは隣接性のみが使用されるため、位置や向きには依存しません。 

文字によって含まれる分岐点の数が異なるため、次数ヒューリスティックで十分です。 この実装では、より複雑でエラーが発生しやすい幾何学的正規化やパターンの位置合わせが回避されます。

 ## 特殊なケース

 緻密な長方形のブロック`#`単一の BFS コンポーネントとして扱われます。 この場合、すべてのセルの次数が高いため、cnt3 が大きくなり、分類器は最も高い分岐カテゴリーに分類されます。 アルゴリズムは幾何学的妥当性を前提とせず、構造的一貫性のみを前提としているため、安定した状態を保ちます。 

2 番目のエッジ ケースは、コンポーネントが非常に小さいか線形である最小構造です。 このような場合、ほとんどすべてのノードの次数は最大 2 となり、分類子は最も分岐の少ない文字タイプに対応するデフォルトの分岐に導きます。 BFS は、接続性が維持されるため、形状が劣化した場合でも構造を正しく分離します。 

3 番目のケースは、隣接する境界線を持つ複数の文字が密に詰め込まれているものです。 2 つの文字が斜めに接触したり、グリッド内のエッジを共有したりしても、共有しない場合は 4 近傍用語で切断されたままになります。`#`接続性を確保し、BFS 分離が正しく維持されるようにします。
