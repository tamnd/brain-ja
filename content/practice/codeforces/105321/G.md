 ## 解決策
 ## 問題の理解

 大文字で構成される 1 つの文字列が与えられており、正確に 3 文字からなる互いに素なグループをできるだけ多く形成したいと考えています。 有効な各グループは、単語「TAP」または単語「TUP」のいずれかに再配置する必要があります。 あるグループで文字が使用されると、別のグループで再利用することはできません。 

タスクをより具体的に再構成すると、複数の文字セットが与えられます。 これをトリプルに分割する必要があります。各トリプルには、「TAP」または「TUP」のどちらを形成するかに応じて、T が 1 つ、P が 1 つ、および A または U が 1 つずつ、次のパターンのそれぞれが 1 つだけ含まれている必要があります。 したがって、すべての有効なグループは 1 つの T と 1 つの P を消費し、その後、A または U を消費します。 

制約は小さく、文字列の長さは最大 300 です。これにより、文字間の分布の多くの組み合わせをチェックするソリューションでも許容できることがすぐにわかりますが、それでも検索ではなく直接カウントする引数を目指す必要があります。 

単純なアプローチでは、文字の考えられるすべてのグループ化または並べ替えをシミュレートすることによって、明示的にトリプルを形成しようとする可能性があります。 ただし、重要なのは文字の存在数のみであるため、置換ベースのアプローチでは同等の状態を探索する労力が無駄になります。 問題の構造から、T、P、A、U の各関連文字がいくつあるかだけを気にする必要があることがわかります。 

ある文字が豊富にあるのに別の文字が少ない場合、微妙なエッジケースが発生します。 たとえば、T が多く、P が非常に少ない場合、答えは P によって完全に制限されます。別のケースは、A と U が同じ T-P バックボーンをめぐって競合するため、大きくアンバランスになっている場合です。 

小さな例は、以下を明確にするのに役立ちます。 

文字列が`TAPU`、T=1、A=1、P=1、U=1 となります。 正確に1つの花輪を形成できます。 

文字列が`TTTTPPPPAAAA`、TとPは十分にありますが、Aが制限要因であるため、TAPガーランドのみを形成します。 

文字列が`TPTPTPUU`、制限因子は T または P になり、U は TUP 形成にのみ寄与します。 

The key observation is that every garland consumes one T and one P regardless of type. The only decision is whether we pair that (T,P) with A or with U.

 ## Approaches

 ブルートフォース戦略では、各文字をトリプルに割り当て、各トリプルを「TAP」または「TUP」に再配置できるかどうかをテストします。 This quickly becomes a combinatorial packing problem. バックトラッキングを行ったとしても、最大 300 文字のパーティションを探索することになり、パーティションの数は実行可能な制限をはるかに超えて増加します。 

The failure point of brute force is that it treats letters as distinguishable objects, while in reality only counts matter. Once we compress the state into frequencies, the problem becomes purely arithmetic.

 重要な洞察は、問題を 2 つの独立したリソースに分離することです。 すべての有効なガーランドには 1 つの T と 1 つの P が必要であるため、ガーランドの数は min(T, P) を超えることはできません。 使用できる (T,P) ペアの数を決定した後、そのような各ペアに A または U を割り当てる必要があります。 したがって、k ペアを効果的に 2 つのバケットに分割し、一方のバケットは A によって制限され、もう一方のバケットは U によって制限されます。 

If we decide to form x TAP garlands, we need x A’s, and we need k - x U’s for TUP garlands. So x must satisfy x ≤ A and k - x ≤ U. This becomes a simple feasibility interval problem, and we maximize k under these constraints.

 すべての k を明示的に試す必要はありません。 可能な最大の k は、T と P によって制限され、また A + U の組み合わせによって制限されます。 これは、T と P のペアを固定した後、各ガーランドが A ∪ U から 1 つだけを消費するためです。 

We can compute the answer directly as the maximum k such that there exists a split of k into two parts respecting A and U capacities. これは、k ≤ min(T, P, A + U) をチェックし、A と U が個別に分割をサポートできることを確認することになります。これは、両方が k に対して過度に制約されていない限り、常に可能です。 

これは直接的な式につながります。k = min(T, P) をとります。 次に、A と U を使用してこれらの k ペアのうち何個を割り当てることができるかを確認します。これは単純に A + U によって制限されますが、どちらの側も超えないようにする必要もあります。 TUP の最適な数は U によって制限されるため、最大 U TUP、同様に最大 A TAP となります。 したがって、私たちができる最善のことは、貪欲に割り当てることです。まず、できるだけ多くの TUP または必要に応じて TAP を満たします。 両方とも対称であるため、合計は k ですが、個々の電源によってクリップされます。 

もっとすっきりした解釈は、常に k = min(T, P) とし、使用できるトリプルの数は、k 個のスロットに一致させる A と U の数 (単純に min(k, A + U)) によって制限されるというものですが、A + U はすでに実現可能性を制限しているため、k 自​​体が最終的な答えになります。 

したがって、問題は文字をカウントし、単一の最小の式を適用することに帰着します。

 ## アルゴリズムのチュートリアル

 1. 文字列内の関連する各文字、具体的には T、P、A、および U の出現をカウントします。これが必要なのは、これらの文字のみが有効なガーランドに寄与し、他のすべての文字は無関係なノイズであるためです。 
2. 形成できる (T,P) ペアの数 (min(T, P)) を計算します。 各ガーランドはそれぞれ 1 つずつ消費する必要があるため、これは厳しい上限です。 
3. A と U を一緒に使用して埋めることができる「3 番目のスロット」の合計数を計算します (A + U)。これは、すべてのガーランドがこれらの文字の 1 つを正確に選択する必要があることを反映しています。 
4. 最終的な答えは、利用可能な (T,P) ペアの数と利用可能な A/U 文字の数の間の最小値です。 これにより、どちらの構造要件も決して超えることがなくなります。 

### なぜ効果があるのか

すべての有効なガーランドには、正確に 1 つの T と 1 つの P が含まれている必要があるため、どの解も min(T, P) を超えることはできません。 独立して、すべての花輪は {A, U} からちょうど 1 文字を消費する必要があるため、合計で A + U を超えることはできません。 これらの制約は独立しており、有効なガーランドはそれぞれ両側から 1 つのユニットを使用するため、T-P スロットと利用可能な A または U 文字をペアにすることで、これら 2 つの量の最小値までの割り当てを実現できます。 これらの数を超える追加の構造上の制約はありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

s = input().strip()

t = s.count('T')
p = s.count('P')
a = s.count('A')
u = s.count('U')

tp = min(t, p)
print(min(tp, a + u))
```コードは、文字列を読み取り、関連する 4 つの文字の出現をカウントすることから始まります。 変数`tp`は、構築できる基本ペアの最大数を表し、それぞれに 1 つの T と 1 つの P が必要です。各ペアは、これらの文字の 1 つを使用して完全な 3 文字の花輪に拡張する必要があるため、最終的な答えは、A と U を組み合わせた合計の可用性によって制限されます。 

よくある間違いは、A と U の合計数のみが重要であることに気づかず、形成する TAP と TUP の数を個別に決定しようとすることです。 もう 1 つの微妙な問題は、それぞれのガーランドが 3 つの役割すべてを同時に必要とするため、未使用の T または P 文字が不足している A/U を補うことができないことを忘れていることです。 

## 実用的な例

 ### 例 1:`APPUNTATTE`文字を数えます: T=3、P=2、A=2、U=2。

トレースは、アルゴリズムが集計カウントのみに依存し、順序付けやグループ化の構造が重要ではないことを示しています。

## テストケース```python
import sys, io

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    s = input().strip()

    t = s.count('T')
    p = s.count('P')
    a = s.count('A')
    u = s.count('U')

    return str(min(min(t, p), a + u))

def run(inp: str) -> str:
    return solve(inp)

# provided samples (interpreted)
assert run("APPUNTATTE") == "2"
assert run("TULIPAN") == "1"
assert run("TAPTUPTAP") == "3"
assert run("TOP") == "0"

# custom cases
assert run("T") == "0", "minimum size no valid triple"
assert run("TPA") == "1", "exact single TAP"
assert run("TPUUUAAA") == "2", "A+U limits vs TP"
assert run("TTTTPPPPAAAAUUUU") == "4", "balanced maximum case"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | た | 0 | ガーランドには文字が足りない |
 | TPA | 1 | 正確な最小有効構成 |
 | つうううううう | 2 | TP と A/U 制約の間の相互作用 |
 | TTTTPPPPAAAAUUU | 4 | フルバランス大容量ケース |

 ## 特殊なケース

 次のような 1 文字または 2 文字の入力`T`または`TP`min(T, P) が 0 であるため、アルゴリズムが正しく 0 を返し、無効なグループ化が即座に防止されることを示しています。 

たとえば、T と P が多く、A や U が存在しないような、大きく偏った分布`TTTTPPPP`、結果は A + U = 0 となり、TP ペアが存在する場合でも答えは強制的にゼロになります。 min(tp, a + u) がゼロになるため、計算ではこれが自然に捕捉されます。 

AとUは豊富だがTかPのどちらかが欠けている場合など`AAAAUUUU`、 min(T, P) が 0 であるため、結果も 0 となり、両方の構造コンポーネントが同時に必要であることがわかります。
