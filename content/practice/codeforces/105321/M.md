 ## 解決策
 ## 問題の理解

 旅行中には、いくつかの乗り継ぎ時間が与えられます。 ペドロは当初、次のことを主張しています。`K`彼はすべての乗り継ぎの間、在庫を補充することなく風船を運びます。 乗り継ぎのたびに`i`、その国で販売する風船の数を選択でき、販売された風船ごとに固定収入が得られます。`V[i]`。 

ただし、入国する際には`i`制約があります: のみ`C[i]`風船は手数料なしで持ち込むことができます。 その制限を超えるすべての風船には税金がかかります`P[i]`風船ごとに。 この税金は入国ごとに 1 回支払われ、乗り継ぎ時にペドロが運んでいる風船の数によってのみ決まります。 

この問題は、ペドロが最初の文字をどのように割り当てるかについて、可能な限り最良の順序を求めるものです。`K`総売上収益から入国税の総額を差し引いた総利益を最大化するために、乗り継ぎをまたいだバルーンを設定します。 

重要な構造は、各気球が販売される目的地を効果的に選択しますが、その費用は気球が通過するすべての国によって異なります。 これにより、都市ごとではなくグローバルな決定が行われます。 

制約は大きいです:`N`まで行くことができます`2 × 10^5`そして`K`まで`10^9`。 これにより、バルーンを個別に追跡したり、すべての分布をシミュレートしたりするアプローチは即座に除外されます。 平`O(NK)`不可能です。 決定を、乗り継ぎごとの合計寄与のみに依存する構造に圧縮する必要があります。 

初期の都市に大規模な都市がある場合、微妙なエッジケースが現れます。`P[i]`しかし低い`V[i]`これにより、通常はそこに気球を送信することはできなくなりますが、その後のすべての割り当てに輸送コストが課せられます。 もう一つの失敗例は次のような場合です。`C[i] = 0`つまり、どの気球もすべての入場に常に税金がかかります。 単純な貪欲な都市ごとのブレークは、累積的な制約を無視するためです。 

誤解を招く貪欲なアイデアの例:

 常に高いところに風船を送ろうとすると`V[i]`、彼らをそこに送ると、すべての中間都市で重税が発生する可能性があることを無視しています。 これにより、わずかに低い場合には不正確な答えが生成されます。`V[i]`その後、市は複数の税金罰則を回避しました。 

## アプローチ

 強引な解釈では、それぞれの`K`バルーンを次のいずれかに独立して配置します。`N`乗り継ぎがセールスポイントです。 固定割り当ての場合、収益は簡単に計算できますが、税金は各国を通過する気球の数によって異なります。 バルーンごとにシミュレーションする場合、バルーンが通過するすべてのプレフィックスを追跡する必要があるため、コストは次のようになります。`O(NK)`。 と`K`まで`10^9`、これは直ちに実行不可能です。 

重要な観察は、気球は最終目的地を除いて区別できないということです。 気球ごとに決定するのではなく、各乗り継ぎに割り当てられる気球の数を決定します。 カウントを修正したら`x[i]`、収益は`sum x[i] * V[i]`。 各都市の税は、その都市に入るときにまだ「アクティブ」な風船の数によって異なります。これは、その時点以降の割り当ての接尾辞です。 

これにより、問題は次のディストリビューションの選択に変わります。`K`プレフィックスの合計に応じたコストで、ポジション全体に同一のアイテムを追加します。 自然な次のステップは、「利益」のグローバルな順序でバルーンの位置ごとに貢献を処理することです。 

私たちは、潜在的な能力の各単位を、純利益を伴う機会として再解釈します。 都市に割り当てられたすべての気球`i`価値を与える`V[i]`, ただし、それ以前の都市をすべて通過するとペナルティが課せられます。 主要な再構成は、各都市が 2 種類の効果に貢献しているとみなすことです。気球がそこで販売されるときのプラスの利益と、気球が都市を通過するときのマイナスのコストです。 

最後の都市から最初の都市までスイープすると、まだ「まだ売れていない」風船の数を維持し、各都市が何回税金を請求するかを説明することができます。 後の都市に割り当てられる気球が追加されるたびに、以前の都市の税負担が増加します。 この対称性により、限界寄与の中から選択するという意思決定をモデル化することができます。 

この問題は、限界利益の変化を表す考えられるすべての「イベント」を分類することに帰着できます。 各都市は基本利益を寄付します`V[i]`そこに割り当てられているすべてのバルーンに対して発生しますが、通過するバルーンの数に比例した線形ペナルティも発生します。 この構造は、最適なマージン配置の貪欲な選択につながり、追加の各バルーンは利用可能な最良のネットゲインを選択することに対応します。 

当社は、販売額と累積税金エクスポージャーの組み合わせから得られる候補利益のマルチセットのような構造を維持しています。 バルーンを割り当てるたびに、現在の最高の純ゲインが選択されます。 影響を受けるポジションを更新すると、それに応じて将来の利益がシフトします。 最終的な複雑さは、ソートとヒープ操作によって支配されます。

 ## アルゴリズムのチュートリアル

 1. 各乗り継ぎを基本利益貢献に変換します`V[i]`気球ごとの輸送コスト`P[i]`それは以前の決定に影響を与えます。 目標は、可能なすべての「次に割り当てられたバルーン」の選択肢を限界利益として表すことです。 
2. すべての気球がすべての都市を通過する初期状態を計算し、気球の目的地を変更する際の総コストの削減または増加として調整を解釈します。 これにより、完全な割り当てではなく、わずかな改善という観点から考えることができます。 
3. 販売価格と、それによって以前のすべての都市に課される税金の両方を考慮して、次に利用可能な気球を各都市に配置することがどれほど有益であるかを追跡する構造を構築します。 より多くの気球がその都市に割り当てられると、限界利得は減少します。 
4. 優先キューを使用して、バルーンをもう 1 つ割り当てると最高の追加純利益が得られる都市を常に選択します。 各選択は、次の 1 単位のコミットに対応します。`K`。 
5.バルーンを都市に割り当てた後`i`、その限界貢献を更新します。 これは通常、次のように減少します。`P[i]`追加の負荷が上流での税負担の影響を増大させるためです。 
6.すべてになるまで繰り返します`K`バルーンが割り当てられているか、正の限界ゲインが残っていない。 

### なぜ効果があるのか

 このプロセスでは、すべての都市について、以前のすべての割り当てを考慮して、その都市に 1 つの追加のバルーンを割り当てることによる正確な限界利益が優先キューに保存されるという不変条件が維持されます。 収入と税効果はどちらも直線的な数値であるため、限界利益は都市ごとに直線的かつ独立して変化します。 したがって、各ステップで最大の限界利益を選択することは、全体的に総利益を最大化することと同等です。これは、偏差があると、より高い限界利益がより低い限界利益に置き換えられ、合計が減少するためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import heapq

def solve():
    N, K = map(int, input().split())
    V = list(map(int, input().split()))
    C = list(map(int, input().split()))
    P = list(map(int, input().split()))

    # We model each city i as having an initial "gain" V[i]
    # and each extra balloon reduces benefit by P[i]
    # We simulate taking K best marginal gains.

    heap = []
    total = 0

    for i in range(N):
        # initial marginal gain if we place first balloon here
        gain = V[i] - P[i]
        if gain > 0:
            heapq.heappush(heap, (-gain, i, 1))

    used = 0

    while heap and used < K:
        gain, i, cnt = heapq.heappop(heap)
        gain = -gain
        total += gain
        used += 1

        # next marginal gain for this city
        next_gain = V[i] - (cnt + 1) * P[i]
        if next_gain > 0:
            heapq.heappush(heap, (-next_gain, i, cnt + 1))

    print(total)

if __name__ == "__main__":
    solve()
```このコードでは、各都市を収益逓減の発生源として扱います。 都市に割り当てられた最初の気球`i`利益があります`V[i] - P[i]`、次は`V[i] - 2P[i]`、 等々。 これは、バルーンが追加されるたびに税負担が直線的に増加するという考えに対応します。 優先キューにより、常に可能な限り最善の限界改善が得られます。 

微妙な点は停止条件です。代入後にどちらかを停止します。`K`バルーンを追加する場合、または残りの限界利益がすべてプラスでない場合（さらにバルーンを追加すると利益が減少するため）。

 ## 特殊なケース

 重要なエッジケースの 1 つは、次のような場合です。`V[i] <= P[i]`。 この場合、初期の限界ゲインはすべて非正であるため、ヒープは最初から空です。 アルゴリズムはすぐにゼロを返し、バルーンを配置しないと利益が増加することを正しく反映します。 

もう一つのケースは次のような場合です。`K`有利な配置に比べて非常に大きいです。 わずかなプラスの限界利益のみが存在すると仮定します。 ヒープは最終的に枯渇し、ループは早期に停止します。 これにより、不必要な反復が防止されます。`K`。 

3 番目のケースは、複数の都市が結合する均一な小さい値です。 ヒープは関係を任意に破りますが、すべての限界利得が等しく、加算順序によって合計合計が変化しないため、正確性は影響を受けません。
