 ## 解決策
 ## 問題の理解

 私たちには、一定量のパワーポイントから開始するヒーローが与えられます。 N 個の武器があり、各武器は最大 1 回使用できます。 すべての武器には 3 つのパラメータ A、B、C があります。現在 P のパワーを持っているときにヒーローが武器を使用すると、2 つのことが同時に起こります。ヒーローのパワーは (P − B) を C で割った値まで減少し、ボスは A のヘルス ポイントを失います。 

目標は、ヒーローが武器の使用順序を使用してボスを倒すことができるようにしながら、最初にボスをどれだけ強くできるかを決定することです。 各武器は一度使用することもスキップすることもできるため、選択した武器のサブセットを任意に組み合わせたものが有効な戦略となります。 ある時点で彼のパワーがマイナスにならず、ボスに与えられる合計ダメージが少なくとも彼女の初期体力以上であれば、ヒーローは勝ちます。 

重要な問題は、べき乗の変換が線形の加算や減算ではないことです。 各武器には B を減算した後でフロア分割が適用されるため、武器の順序が重要になります。 以前に使用された武器は、後の武器が使用できるかどうかを大幅に変える可能性があります。 

N という点では制約は小さく、武器の数は最大 200 ですが、出力 P は最大 100,000 と大きくなります。この組み合わせは、P を単純な動的プログラミング アプローチの次元として扱う場合、出力のすべての可能な状態を直接追跡することは実行不可能であることを示唆しています。 ただし、各兵器は出力を単調かつ永続的に減少させるため、状態遷移は出力が下方向にのみ移動し、決して上方向に移動することはありません。これは、到達可能な出力値を表す状態の最短パスまたは DP を強く示唆しています。 

床の分割から微妙なエッジケースが生じます。 たとえば、P が B に比べて小さい場合、(P − B) は負になり、除算では依然として有効な整数 (場合によっては負の数) が生成されます。 これは、中間出力が正でなくなっても、次の武器を適用する前に負にならない限り、一連の武器は引き続き有効である可能性があることを意味します。 もう 1 つのエッジケースは順序です。出力をわずかに低下させますが、分割構造を維持する武器は、より高いダメージを与えるが出力があまりにも早く崩壊する武器よりも厳密には優れている可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、武器のすべてのサブセットとそのサブセット内のすべての順列を試し、プロセスをシミュレートし、有効性を追跡しながら合計ダメージを計算します。 これは、考えられるすべての順序を明示的にチェックするため、正しいです。 ただし、順列の数だけでも N の階乗であり、サブセットに制限しても、N の k 乗倍の合計が得られ、N 階乗増加に単純化されます。 N が 200 までの場合、これは完全に不可能です。 

重要な観察は、武器を適用した後に重要なのは結果として得られるパワー値だけであり、この値は以前のパワーと使用した武器にのみ依存するということです。 これは、整数電力状態に対する有向遷移システムを定義します。 各武器は P からフロア ((P − B) / C) までの関数を作成します。 N は小さいが P は大きいため、視点を反転します。P から順にシミュレーションする代わりに、ある一連の武器を使用して特定の状態に到達できる中間の出力値を求めます。 

これは当然、ノードが可能なパワー値であるグラフ解釈につながりますが、状態空間が大きすぎて明示的に拡張できません。 代わりに、各遷移によって電力が厳密に減少することを利用して、状態を降順に処理し、動的プログラミングを使用して、到達可能な電力値ごとに達成可能な最良のダメージを計算できます。 

パワー値から達成可能な最大ダメージまでのマップを管理します。 状態ごとに、各武器を適用して次のパワーを計算します。 この次のパワーが有効で、最もよく知られているダメージが改善される場合は、それを更新します。 各状態は降順に 1 回だけ処理されるため、遷移の数は管理可能なままです。

 ## アルゴリズムのチュートリアル

 到達可能な各パワー値を状態として扱い、その状態で終了したときに達成可能な最大のダメージを計算します。 

1. dp[P] = 0 の辞書または配列から開始します。これは、与えるダメージがゼロでフルパワーで開始することを意味します。 これは、既知の唯一の初期状態を表します。 
2. 処理状態を電力の降順に並べます。 順序が減少する理由は、すべての遷移が電力を削減するためであり、そのため、一度状態が処理されると、その後の遷移ではその状態またはより上位の状態に戻ることはできません。 
3. 各現在のパワー値 p とそれに関連する最大ダメージ d について、すべての武器 (A、B、C) を考慮します。 
4. 次のべき乗 p2 を、floor((p − B) / C) として計算します。 これは、武器がヒーローの力をどのように変換するかを正確にモデル化しています。 
5. p2 が有効 (非負) で、p2 での最も既知のダメージを改善できる場合は、dp[p2] を dp[p2] + A に更新します。 
6. 到達可能な状態はいずれかの武器シーケンスの完了の可能性に対応するため、すべての状態で達成可能な最大ダメージを追跡します。 
7. 最大ダメージを、完全に消耗できる最大初期ボス体力として解釈して、答え V に変換します。 

本質的な考え方は、すべての状態が、ある一連の武器の後に到達可能な残りのパワーの構成を表し、すべての遷移がそのシーケンス内の次の武器の選択に対応するということです。 

### なぜ効果があるのか

 このアルゴリズムは、武器の使用が整数の出力状態にわたって単調減少システムを定義するという事実に基づいています。 すべての遷移では電力が厳密に削減されるか制限された状態に保たれるため、サイクルは存在しません。 これにより、明示的に構築されていなくても、状態グラフは有向非循環構造になります。 状態を降順で処理すると、ある状態からの遷移を計算するときに、そこに至る可能性のあるすべての状態がすでに解決されていることが保証されます。 したがって、各 dp 値は、どのように到達したかに関係なく、正確に残りのパワーに対して達成可能な最高のダメージを表し、異なる武器のオーダー間での一貫性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    N, P = map(int, input().split())
    weapons = [tuple(map(int, input().split())) for _ in range(N)]

    # dp[p] = maximum damage achievable when ending with power p
    dp = {P: 0}

    # process states in decreasing order of power
    states = sorted(dp.keys(), reverse=True)

    ans = 0

    while states:
        p = states.pop()
        cur_damage = dp[p]
        ans = max(ans, cur_damage)

        for A, B, C in weapons:
            if p < B:
                continue
            p2 = (p - B) // C
            if p2 < 0:
                continue

            nd = cur_damage + A
            if p2 not in dp or nd > dp[p2]:
                dp[p2] = nd
                states.append(p2)

        states.sort(reverse=True)

    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、パワー値から最大のダメージまでのマッピングが維持され、各武器によって引き起こされる遷移が繰り返し伝播されます。 最もデリケートな部分は更新条件です。より少ないダメージで同じパワーに到達することは厳密には悪いため、総ダメージを改善する場合にのみ状態を上書きします。 ソートされた状態リストにより、常により高い電力の状態を最初に展開し、厳密に減少する遷移によって引き起こされる単調構造を維持することが保証されます。 

除算ステップは、次を使用して Python の整数階除算として慎重に記述する必要があります。`//`これは非負入力の数学的な下限動作とすでに一致しており、コードは無効な負の遷移を明示的に回避します。

このトレースは、除算によって作成された順序制約がどのように特定の順序を強制するかを示しています。大きな除数の兵器は、威力が十分に小さくなるまで遅らせる必要があります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N · S log S) | 各状態は N 個の遷移を処理し、状態リストの維持には S 個の到達可能な電力値を並べ替える必要があります。 
| スペース | O(S) | 到達可能な各電力値は DP マップに一度保存されます。 

到達可能な状態の数は、フロア分割の繰り返しによって生成される個別の値の数によって制限されますが、実際には P よりもはるかに小さくなります。 N が最大 200 の場合、各状態の拡張は制限され、解は制限内に保たれます。

 ## 特殊なケース

 エッジケースの 1 つは、フロア分割により武器が即座にそれ以上の使用を無効にする場合です。 入力用`P = 6`そして武器`(A=3, B=7, C=5)`、条件`P < B`トリガーされるため、武器はスキップされます。 このアルゴリズムは負の状態を決して生成しないため、誤った遷移が導入されることはありません。 

もう 1 つのエッジ ケースは、繰り返し除算によって電力が急速にゼロになる場合です。 このような場合、複数の異なるシーケンスが同じ電力値に収束する可能性があります。 DP マップはこれを正しく処理します。各電源状態に対して常に最適なダメージのみを保持するため、重複した到着によって結果が歪むことはありません。 

最後のエッジケースは、複数の武器が同一の遷移を生成するがダメージ値が異なる場合に発生します。 アップデート条件`nd > dp[p2]`最も強いパスのみが確実に生き残り、将来の遷移は履歴ではなく電力のみに依存するため、弱いパスを破棄しても最適なソリューションが失われることはありません。
