 ## 解決策
 ## 問題の理解

 私たちは、一人のプレーヤーによってプレーされたテニスの試合の時系列の記録を与えられます。 各試合の結果は勝ちまたは負けとなり、1 が勝ち、0 が負けを表すバイナリ配列としてエンコードされます。 

スコアリング システムには 2 つの独立したコンポーネントがあります。 1 つ目は簡単です。すべての勝利は +1 ポイントに寄与し、すべての敗北は -1 ポイントに寄与します。 2 つ目は連勝に依存します。試合が終了し、プレーヤーが現在この試合を含む少なくとも 3 連勝しているときは常に、その瞬間に追加の +1 ポイントを受け取ります。 

重要な点は、この連勝ボーナスが試合終了時だけでなく、各試合後に評価されることです。 したがって、4 連勝は複数のボーナスをもたらします。その試合で終わるサフィックスの長さが少なくとも 3 であるポジションごとに 1 つずつボーナスが与えられます。 

入力サイズは小さく、N は最大 100 です。これにより、O(N) を超える最適化を気にせずに直接リニア スキャンがすぐに可能になります。 O(N^2) のシミュレーションでも許容されますが、問題の構造により明らかに O(N) が許容されます。 

単純な間違いは、少なくとも 3 つの長さのストリークが存在するかどうかだけをチェックし、ストリークごとに 1 つのボーナスを追加することです。 たとえば、入力の場合`1 1 1 1`、正しいボーナスは 2 (位置 3 と 4) ですが、単純な実装では誤って 1 しか追加されない可能性があります。 

もう 1 つのよくある間違いは、ポジションごとではなくグローバルにストリークをカウントすることです。 たとえば、`1 1 1 0 1 1 1`、2 番目の連続は、最初の連続とは独立して再び複数のボーナスに貢献します。 

正しい解釈は厳密にローカルです。各試合 i の後、最後の 3 つの試合 (i-2 から i) がすべて勝利したかどうかを確認し、そうであれば 1 ボーナス ポイントを追加します。 

## アプローチ

 この問題を考える強引な方法は、文字通り得点ルールをシミュレートすることです。 各ポジション i について、負けが発生するまで逆方向にスキャンして、i で終わる現在の連続勝利の連勝数を計算します。 そのストリークの長さが少なくとも 3 である場合、ボーナスが追加されます。 

これは定義に直接一致するため機能しますが、すべての一致が勝利した場合、最悪のケースでは O(N^2) に低下する可能性があります。 各位置は O(N) ステップを逆スキャンします。 

ただし、すべてを変える観察は、実際にはストリーク全体の長さは必要ないということです。 ボーナス条件は、最後の 3 試合が勝利したかどうかによってのみ決まります。 位置 i、i-1、および i-2 が存在し、すべて 1 の場合、プレーヤーは位置 i でちょうど 1 つのボーナスを受け取ります。 これにより、潜在的に無制限の逆方向スキャンが、位置ごとの一定時間のチェックに変換されます。 

したがって、問題はバイナリ配列上のサイズ 3 の単純なスライディング ウィンドウに帰着します。

 ## アルゴリズムのチュートリアル

 合計スコアを維持しながら、左から右に一致を処理します。 

1. 答えをゼロに初期化します。 この変数は、勝敗ポイントと連勝ボーナスの両方を蓄積します。 
2. 0 から N-1 までの各一致 i を繰り返します。 各試合について、結果が勝ちの場合は +1、負けの場合は -1 を加算してスコアを更新します。 これは、基本スコアリング ルールを直接エンコードします。 
3. i ≥ 2 の場合、Ri、Ri-1、および Ri-2 がすべて 1 に等しいかどうかをチェックします。このチェックにより、現在の試合が i で終わる少なくとも 3 つの連続勝利を達成したかどうかが判断されます。 
4. 条件が当てはまる場合は、答えにさらに +1 ポイントを追加します。 これは、対象となる各エンドポイントが独立して 1 つのボーナスを提供するというルールに正確に対応します。 

すべての試合を処理した後、累積された値が最終スコアとなります。 

### なぜ効果があるのか

 このアルゴリズムは、ボーナス ルールが位置 i で終了する長さ 3 のウィンドウが完全に勝ちで構成されているかどうかのみに依存するという事実に基づいています。 連勝が長くなると、3 回目の勝利以降、すべてのサフィックス エンドポイントでこの条件が自動的にトリガーされます。 したがって、有効な長さ 3 のウィンドウをそれぞれ 1 回だけカウントすることは、適格なストリーク エンドポイントをすべてカウントすることと同じです。 基本スコアはこの条件とは独立しているため、2 つの寄与を分離することで正確性が保たれます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    ans = 0
    
    for i in range(n):
        if a[i] == 1:
            ans += 1
        else:
            ans -= 1
        
        if i >= 2 and a[i] == 1 and a[i-1] == 1 and a[i-2] == 1:
            ans += 1
    
    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションでは、単一の実行中のアキュムレータが維持されます。 ループ内の最初の更新は、線形スコアリング ルールを直接処理します。 2 番目の条件ブロックは 3 連続勝利のスライディング ウィンドウ チェックで、少なくとも 3 つの試合が処理された場合にのみ適用されます。 

重要な実装の詳細は順序です。最初に現在の一致の基本スコアを適用し、次にその位置で終了するストリークを評価します。 これにより、ストリーク チェックには常に現在の一致が含まれるようになります。

 ## 特殊なケース

 最小限のインプットのために`N = 1`、入力と言います`1`の場合、アルゴリズムはベース スコアを +1 に設定し、i < 2 であるためストリーク チェックには入りません。長さ 3 のストリークは存在できないため、出力は 1 ですが、これは正しいです。 

次のような完全な損失シーケンスの場合`0 0 0 0`、各位置は -1 に寄与し、縞はありません。 ボーナス条件がトリガーされないため、スコアは -4 となり、ルールに一致します。 

などの長期連勝の場合は、`1 1 1 1 1`明示的にトレースすると、i = 2、3、4 でトリプル ウィンドウ条件が成立し、ちょうど 3 つのボーナス増分が生成されます。 これにより、重複するストリークの寄与が 1 つのイベントにグループ化されるのではなく、ポジションごとに独立して処理されることが確認されます。
