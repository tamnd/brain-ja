 ## 問題の理解

 長さの隠し文字列が与えられます$N$, しかし、私たちはそれを直接見ることはできません。 代わりに、部分文字列に関するクエリを尋ねることができ、各クエリは選択された部分文字列が正しいかどうかを尋ねます。$t = s[L..R]$文字列全体の有効期間です。 

部分文字列を整数回、少なくとも 2 回繰り返すことで文字列全体を形成できる場合、部分文字列はピリオドとみなされます。 言い換えれば、$t$それを数回連結する場合は、完全な文字列を正確に再構築する必要があります。$s$、不一致や文字の残りはありません。 

私たちの仕事は文字列を回復することではありません。 未知の文字列が周期的であるかどうかを判断するために、最悪の場合に必要なクエリの数を決定し、この最小値を達成する具体的なクエリのセットを出力するだけで済みます。 

各クエリは、文字列全体が候補ブロックの繰り返しから構築されているかどうかを効果的にテストします。 主な困難は、回答を見ずに事前にすべてのクエリを選択し、回答を受け取った後に有効な期間が存在するかどうかを常に判断できることを保証しなければならないことです。 

複雑さの観点から見ると、$N$と同じ大きさにすることができます$10^6$。 これにより、すべての部分文字列の探索や相互作用のシミュレーションに依存するものは即座に除外されます。 解決策は純粋に長さの構造特性に依存する必要があります。$N$実際の文字列とは独立した固定クエリセットを設計しているためです。 

微妙なエッジケースは次のような場合です$N$プライムです。 この場合、可能な期間の長さは次のとおりです。$1$、そして全体の決定は、すべての文字が同一であるかどうかに帰着します。 もう 1 つのエッジケースは次のような場合です$N$多くの期間の長さの候補が存在しますが、そのほとんどは情報の点で冗長であるため、非常に複合的です。 

## アプローチ

 自然な出発点は、文字列が周期的であることが何を意味するかを考えることです。 文字列が繰り返されるブロックで構成されている場合、最小のブロック長が存在します。$p$文字列がその長さの接頭辞の正確な繰り返しであるようなもの$p$。 有効な期間は分割する必要があります$N$なぜなら、繰り返しでは文字列を均等に並べる必要があるからです。 

これにより、隠れた構造が約数に還元されます。$N$。 各約数$p < N$は潜在的な期間の長さを表します。 どの約数が有効な期間であるかがわかっていれば、それらのいずれかが機能するかどうかをチェックすることで、文字列が周期的であるかどうかをすぐに答えることができます。 

ブルートフォース戦略は、ピリオドを表す可能性のあるすべての部分文字列をクエリすることです。 有効なピリオドは完全な繰り返しである必要があるため、次の形式の部分文字列をテストするだけで十分です。$[1, p]$あらゆる人にとって$p$それは分ける$N$。 各クエリにより、文字列がそのプレフィックスの繰り返しで正確に構成されているかどうかがわかります。 これは正しいですが、そのような約数の数は最大で約$10^6$病的なケースでは、クエリ予算の点でコストが高くなる可能性があります。 

重要な観察は、すべての約数をテストするだけで十分ではなく、最悪の場合にも必要であるということです。 約数を省略すると$p$、有効なピリオドのみが正確である文字列を構築できます。$p$、その他のテストされた長さはすべて失敗します。 これにより、正しい戦略ではすべての候補除数を個別のクエリとして含めることが強制されます。これは、それぞれが異なる非表示設定を一意に区別できるためです。 

文字列にピリオドがある場合、という意味での冗長性もあります。$p$、その場合はピリオドもあります$k \cdot p$任意の整数に対して$k$, しかし、より小さい約数が成り立つかどうかがわからないため、これはクエリセットを減らすのには役立ちません。 したがって、除数をスキップすると、完全性が失われる危険があります。 

したがって、最適な戦略は、それぞれの適切な約数に対して 1 つのプレフィックスをクエリすることです。$N$を選択し、回答を使用して、少なくとも 1 つが有効な期間であるかどうかを判断します。

 ## アルゴリズムのチュートリアル

 問題をすべての有効な期間の長さの候補を列挙することに縮小します。これらは正確に次の約数です。$N$より小さいもの$N$。 

## アルゴリズムのチュートリアル

 1. すべての整数を反復処理します。$d$1から$N$ただし、分割するもののみを考慮します$N$。 そういったそれぞれの$d$有効な周期構造では文字列を均等に並べる必要があるため、 は候補期間長を表します。 
2. 各約数について$d < N$、部分文字列に対するクエリを構築します$[1, d]$。 これは、文字列全体が最初の文字列の繰り返しで構成されているかどうかをチェックします。$d$文字。 有効なピリオドでは最初のブロックがパターンと正確に一致する必要があるため、プレフィックス部分文字列に制限します。 
3. このようなクエリをすべて収集します。 クエリの数は正確に次の約数の数になります。$N$。 
4. すべてのクエリを出力します。 各クエリは独立しており、回答に基づいて適応しているわけではないため、順序は重要ではありません。 

構造上の重要な点は、文字列を再構築しようとしているのではなく、考えられる各タイリング長との一貫性をテストするだけであるということです。 各約数は、隠し文字列の構造に関する独立した仮説として機能します。 

### なぜ効果があるのか

 文字列の有効なピリオドには長さが必要です$p$それは分ける$N$、文字列の接頭辞と一致する必要があります。 したがって、すべての有効な候補がクエリ セットに含まれます。 

逆に、文字列が周期的でない場合、これらの約数はいずれもテストに合格しません。 周期的であれば、真の周期に対応する少なくとも 1 つの約数が通過します。 除数セットに対してすべての可能性を徹底的にテストするため、正しい構造を見逃すことはなく、間違った構造によってすべての約数にわたる一貫性が偽られることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    
    divisors = []
    i = 1
    while i * i <= n:
        if n % i == 0:
            if i < n:
                divisors.append(i)
            j = n // i
            if j != i and j < n:
                divisors.append(j)
        i += 1

    divisors.sort()
    
    k = len(divisors)
    print(k)
    for d in divisors:
        print(1, d)

if __name__ == "__main__":
    solve()
```この実装は、約数を効率的に列挙することに完全に重点を置いています。 までのループ$\sqrt{N}$全範囲をスキャンすることなく、すべての因子ペアを確実に見つけることができます。 明示的に除外します$N$ピリオドは少なくとも 2 つの繰り返しで構成されている必要があるため、$N$長さの候補としては無効です。 

各約数は次の形式のクエリに変換されます。$(1, d)$、長さのプレフィックス部分文字列を表します$d$。

 ## 特殊なケース

 プライムの場合$N$、 のような$N = 7$、アルゴリズムは除数のみを出力します。$1$。 これは、可能な唯一のピリオドが長さ 1 であることを正しく反映しているため、唯一の意味のあるテストはすべての文字が同一であるかどうかです。 除数を列挙すると、問題は自然に 1 つの仮説にまとめられます。 

次のような高度に合成された数の場合、$N = 12$、アルゴリズムはすべての約数を生成します$1,2,3,4,6$。 これらの一部は周期構造の観点からは冗長ですが、最悪の場合の区別のためには必要です。 それらのいずれかを削除すると、有効な期間のみが不足している除数と一致する文字列が構築され、戦略が不完全になってしまう可能性があります。 

のために$N = 1$、少なくとも 2 回の繰り返しを必要とする有効期間がないため、クエリは生成されません。 単一文字の文字列は、より短い長さの繰り返しブロックに分解できないため、これは定義と一致します。 

これらの各ケースは、除数ベースの構造から直接続き、特殊なケースのロジックを使用せずに一貫性が確保されます。
