 ## 解決策
 ## 問題の理解

 3 人のプレイヤーが単純な同盟ゲームに参加し、そのうちの 2 人がチームを形成し、残りのプレイヤーが 1 人で競争します。 各プレーヤーは固定の整数スコアを持っています。 選択したペアの場合、デュオのスコアは個々のスコアの合計となり、この合計が単独プレーヤーのスコアと比較されます。 

結果ルールは非対称です。デュオの合計がソロ プレーヤーのスコアよりも厳密に大きい場合、デュオが勝ちます。 それ以外の場合は、合計がソロ プレーヤーのスコア以下であることを意味し、ソロ プレーヤーが単独で勝ちます。 

この質問は、このルールの下でソロ勝利を保証できるプレーヤーが少なくとも 1 人存在するかどうかを尋ねます。これは、事実上、合計スコアが選択したプレーヤーのスコアを超えないように、他の 2 人のプレーヤーの選択肢が存在することを意味します。 

入力は、3 人の参加者のスコアを表す 3 つの整数で構成されます。 出力は、あるプレイヤーが単独で勝てるかどうかを示す 1 文字です。 

制約は非常に小さいですが、この問題は基本的に、3 つの要素のすべての可能な分割を単一の要素とペアにチェックすることに関するものです。 

入力サイズが一定であるため、ここでは意味のあるアルゴリズムのパフォーマンス制約はありません。 正しい解はすべて一定時間で実行されるため、O(1) を超える複雑さのクラスは無関係です。 

エッジケースは主に平等と対称性に関するものです。 

最初の微妙なケースは、すべての値が等しい場合です。 たとえば、入力`50 50 50`すべてのペアの合計は 100 になりますが、これは残りの 50 よりも厳密に大きいため、ソロ プレーヤーは勝つことができません。 

もう 1 つのケースは、1 つの値がほとんど支配的ではない場合です。 例えば、`100 10 10`10 + 10 = 20 は 100 を超えないため、100 スコアのプレーヤーが単独で勝つことができます。 

素朴な解釈で誤解を招きやすいケースは、「最大値が常に単独で勝つ」と考えることです。 これは常に真実であるとは限りません。 最大値が少なくとも他の 2 つの値の合計である場合にのみ機能します。 

## アプローチ

 プレイヤーが 3 人だけの場合、最も直接的な方法は、ソロ プレイヤーの可能な選択肢をすべて試して、残り 2 人の合計を計算することです。 各候補者について、他の 2 人のプレーヤーの合計がその候補者のスコア以下であるかどうかを確認します。 このような構成が成立する場合、そのプレイヤーは単独で勝つことができます。 

構成の数が 3 に固定されているため、このブルート フォース ビューはすでに最適化されています。 各プレイヤーに対して一定量の演算を実行するため、合計の作業量は一定になります。 

重要な観察は、問題は最大要素が少なくとも他の 2 つの要素の合計と同じくらい大きいかどうかをチェックすることに帰着するということです。 最も強いプレイヤーが他の 2 人の強さを合わせたものを圧倒できない場合、同盟を再編成しても単独で勝利することはできません。 逆に、いずれかのプレイヤーがこの不等式を満たす場合、そのプレイヤーが単独勝者として選ばれ、残りの 2 人が相手のデュオを形成することができます。 

したがって、解決策は 3 つの単純な不等式を評価することになります。

 ## アルゴリズムのチュートリアル

 ## アルゴリズムのチュートリアル

 1. 3 つの整数スコア A、B、C を読み取ります。これらはプレーヤーの固定された強さを表し、異なる組み合わせで比較されます。 
2. A が B + C 以上であるかどうかをチェックして、A が単独で勝てるかどうかを計算します。これは、A が他の 2 人のプレイヤーのデュオに勝つというルールを直接エンコードします。 
3. B が A + C 以上であるかどうかをチェックして、B が単独で勝てるかどうかを計算します。これは、別のペアの下で 2 番目のプレーヤーに対して同じ条件をテストします。 
4. C が A + B 以上であるかどうかを確認して、C が単独で勝てるかどうかを計算します。これは、考えられる最終的な単独シナリオをカバーします。 
5. 上記 3 つの条件のいずれかが成立した場合、「S」を出力します。 それ以外の場合は「N」を出力します。 

3 つのケースすべてをチェックする背後にある理由は、ペアリングによって相手の合計が変わるため、各プレーヤーは潜在的な単独競技者として独立して評価される必要があるということです。 

### なぜ効果があるのか

 ゲームの結果は、1 つの値と他の 2 つの値の合計との比較にのみ依存します。 すべての有効な構成は、チェックされた 3 つの不等式の 1 つに正確に対応します。 それらのどれも当てはまらない場合、考えられるすべてのソロの選択において、デュオの合計はソロのスコアを厳密に上回り、すべてのケースでデュオが勝つことになります。 少なくとも 1 つが当てはまれば、そのプレイヤーはソロ参加者として選ばれたときに勝つことが保証されます。これは、代替ペアがそのパーティションの相手の合計が固定されているという事実を変えることができないためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    a, b, c = map(int, input().split())

    if a >= b + c or b >= a + c or c >= a + b:
        print("S")
    else:
        print("N")

if __name__ == "__main__":
    solve()
```この実装は、アルゴリズムで導出された数学的条件を直接反映しています。 各不等式は、可能な 1 つの単独構成に対応します。 最終的な決定では、これらのチェックを論理 OR で集計します。 

標準の整数加算を超える境界の問題はなく、所定の制約の下では安全です。 比較には、`>=`それよりも`>`なぜなら、平等とはデュオがソロプレイヤーを超えないことを意味し、それでもソロの勝利となるからです。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from contextlib import redirect_stdout
    out = io.StringIO()
    with redirect_stdout(out):
        solve()
    return out.getvalue().strip()

def solve():
    a, b, c = map(int, sys.stdin.readline().split())
    print("S" if (a >= b + c or b >= a + c or c >= a + b) else "N")

# provided samples

 ## 特殊なケース

 最も重要なエッジケースは平等であり、デュオの合計がソロ プレーヤーと正確に一致します。 入力用`1 2 3`、条件`3 >= 1 + 2`が成立するので、ソロプレイヤーが勝ちます。 よくある間違いは、厳密な不等式を間違った方向に使用することです。これにより、このケースが誤って拒否されてしまいます。 

別のケースは、次のような完全な対称です。`50 50 50`。 ここでは、各ペアの合計は 100 となり、残りの 50 を厳密に超えているため、ソロで勝つことはできません。 このアルゴリズムは、3 つの不等式すべてを正しく false と評価します。 

3 番目のケースは、次のような大きく偏った分布です。`100 10 10`。 小切手`100 >= 20`すぐに成功し、単独勝利が確定します。 これは、肯定的な答えを得るために成立する必要がある不等式が 1 つだけであることを示しています。
