 ## 解決策
 ## 問題の理解

 真っ直ぐな道路があり、いくつかのガソリンスタンドが徐々に位置を変えて配置されています。 各ステーションには燃料 1 リットルあたりの固定価格が設定されています。 車は空のタンク、限られたタンク容量、固定された合計予算でポジション 0 からスタートします。 

この車はどのステーションでも 1 リットルしか購入できず、1 リットルごとにちょうど 1 単位の距離を移動できます。 前進中に、車は通過する駅で停止し、残りの予算とタンク容量の範囲内で燃料を購入して、続行できます。 目標は、車が最適な購入方法を選択した場合に、道路に沿ってどこまで到達できるかを判断することです。 

重要な問題は、決定は局所的だが世界的な影響をもたらすということだ。高価な燃料を早期に購入しすぎると、後で安価なステーションに到達できなくなる可能性がある一方、早期にお金を節約すると、ステーション間の長いギャップを通過するのに十分な燃料が残らない可能性がある。 

入力サイズは最大 100,000 ステーション、位置は最大 10^9、予算と容量は最大 10^9 です。 これにより、すべての移動単位をシミュレートしたり、すべての購入の組み合わせを試したりする戦略は除外されます。 どのソリューションでも、各ステーションをほぼ線形または線形対数時間で処理する必要があります。 

微妙なエッジケースは、ステーション間の長いギャップから発生します。 たとえ総予算が全体的に十分であったとしても、タンク容量よりも大きなギャップがあると、車が戦略的に満タンで到着しない限り、それ以上の走行は不可能になります。 もう 1 つのエッジ ケースは、到達可能な最後のステーションが必ずしも予算や燃料がなくなるステーションではなく、次のギャップが大きくなりすぎる直前のポイントである場合です。 

将来の価格を考慮せずに、現在のステーションだけを貪欲に購入するような甘いアプローチは失敗する可能性があります。 たとえば、安いステーションの後にわずかに高価なステーションがあり、その後非常に高価な長いギャップがある場合、早期に過剰購入すると、後でギャップを埋めるために必要な予算が無駄になる可能性があります。 

## アプローチ

 強引なアプローチでは、現在の燃料と残りの予算を維持し、各ステーションで現地の状況に基づいて購入する燃料の量を決定しながら、段階的に旅行をシミュレーションします。 すべてのステップで、ゼロから残りの容量までのすべての実現可能な購入金額を検討し、各選択がどれだけの効果があるかを再帰的に評価します。 これはすぐに実行不可能になります。各ステーションには最大 C 個の選択肢があり、最大 n 個のステーションを通過する可能性があり、限界をはるかに超えた指数関数的または少なくとも O(nC) の動作につながるからです。 

重要な洞察は、すべてのリットルの決定をシミュレーションする必要はないということです。 重要なのは、燃料は価格を除いて交換可能であり、車は容量の制約を考慮しながら、より安価なステーションで燃料を購入することによってのみ恩恵を受けるということです。 これにより、問題は貪欲な「資源蓄積」プロセスに変わり、タンク容量と残りの予算の制限に基づいて、理想的にはどのくらいの量の燃料を前進させたいかを維持します。 

各ステーションでの購入決定を個別に考えるのではなく、ステーション間の移動を距離が既知の間隔として扱います。 連続する駅間の各区間について、その距離をカバーするのに十分な燃料を支払い、輸送できることを確認する必要があります。 最適な戦略では、後で安価な燃料が入手可能になった場合に、常に高価な燃料の購入を回避しますが、将来のことは明確にわからないため、制約をグローバルに追跡しながら実現可能性をシミュレーションします。 

これにより、現在の燃料と残りの予算を維持し、各セグメントで必要な距離を確実にカバーできるようにする前方スイープが行われます。 燃料が不足している場合は、価格と容量の制限内で以前のステーションで燃料を「遡って」購入する必要があります。 これは、必要に応じてより安価な早期購入を優先することで自然に処理されます。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 購入決定のブルート フォース シミュレーション | 指数関数または O(n·C) | O(1)-O(n) | 遅すぎる |
 | 燃料と予算を制限した追跡による貪欲なフォワード シミュレーション | O(n) | O(1)-O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 連続するステーション間の各ギャップを通過する必要があるセグメントとして扱い、ステーションを位置の昇順に処理します。 これにより、連続した道路が個別の必要な移動コストに変換されます。 
2. 各ステーションで、次のステーションに到達するために必要な燃料の量を計算します。 現在の燃料が不足している場合は、残りの予算とタンク容量の両方の制約を受けて、現在のステーションで燃料を購入しようとします。 
3. 購入できる量は、タンクにどれだけのスペースが残っているか、そしてどれだけのお金が残っているかによって制限されます。 現在のセグメントでの在庫切れを防ぐことができない限り、過剰購入は将来の制約に影響しないため、私たちは常に継続に必要なものだけを購入します。 
4. 現在のセグメントに十分な燃料を確保した後、タンクからセグメント距離を差し引いて前進します。 
5. すべてのステーションを処理するか、タンクをできるだけ満たした後でも次のセグメントの料金を支払うことができない点に達するまで、このプロセスを繰り返します。 
6. 到達可能な最遠距離は、駅またはセグメントを正常に通過するたびに更新されます。 

### なぜ効果があるのか

 重要な不変条件は、ステーション i と i+1 の間の各セグメントに入る前に、アルゴリズムがタンク容量や予算の制約を超えずにステーション i に蓄積できる実行可能な最大燃料を維持することです。 燃料は容量と費やされる総金額によってのみ制約されるため、また、将来のすべての決定は燃料をどのように入手したかではなく、今後の距離を生き延びることができるかどうかのみに依存するため、実行可能な燃料をこのように貪欲に維持するだけで十分です。 これから逸脱する代替戦略は、到達可能性を向上させることなく、キャパシティを侵害するか、より多くの予算を早期に消費することになるため、このシミュレーションで達成される範囲を超えて最終到達可能距離を延長することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, B, C = map(int, input().split())
    x = []
    p = []
    for _ in range(n):
        xi, pi = map(int, input().split())
        x.append(xi)
        p.append(pi)

    fuel = 0
    money = B
    pos = 0

    for i in range(n - 1):
        dist = x[i + 1] - x[i]

        if fuel < dist:
            need = dist - fuel

            can_buy = min(need, C - fuel)

            cost = can_buy * p[i]

            if cost > money:
                can_buy = money // p[i]
                cost = can_buy * p[i]

            fuel += can_buy
            money -= cost

        if fuel < dist:
            pos = x[i] + fuel
            print(pos)
            return

        fuel -= dist
        pos = x[i + 1]

    print(pos)

if __name__ == "__main__":
    solve()
```この実装では、ステーション間の移動中に残りの燃料と残りの予算を追跡します。 各セグメントでは、タンク容量と残金の両方を考慮して、現在のステーションの価格でのみ購入し、十分な燃料が利用可能であることを保証します。 実現可能な最大限の購入後でも次のセグメントをカバーすることが不可能な場合、プロセスは停止し、正確な到達可能な座標が現在位置と残りの燃料から計算されます。 

よくある間違いは、燃料の購入が容量と予算の両方によって同時に制約されていることを無視することです。 もう 1 つは、満タンまで貪欲に購入することが常に最適であると仮定することです。 予算が厳しく、早めに買いすぎて後で必要な購入ができなくなると、この機能が壊れます。

 ## 特殊なケース

 主要なエッジケースは、キャパシティまたは予算が低いために、最初のセグメントがすでにステーション 1 で購入できる量を超えている場合です。 その場合、将来のステーションは遡及的に支援できないため、アルゴリズムは、開始点から部分的な距離のみが到達可能であると即座に計算します。 

もう 1 つのエッジ ケースは、タンク容量がステーション間の 1 つのセグメントよりも小さい場合です。 予算が無限であっても、車はそのギャップを通過できないため、アルゴリズムは、それ以上の購入を試行することなく、到達可能な最後の駅の境界で正しく停止します。 

3 番目の特殊なケースは、最後のステーションの後に予算が残っている場合に発生します。 最後のセグメントを超える移動を制限する将来の制約がないため、アルゴリズムは残りの燃料を距離に変換することで自然に到達距離を延長します。
