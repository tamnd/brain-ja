 ## 解決策
 ## 問題の理解

 _n_ 個の頂点を持つルート付きツリーが与えられます。頂点 1 がルートで、他のすべての頂点 _i_ には指定された親 _p**i_ があります。 最初は、すべての頂点が赤く塗られています。 ランダムな再帰的ペイント プロセスについて推論するように求められます。このプロセスでは、再帰のグローバル カウンタと確率的分岐に応じて頂点の色を白または黒に変更できます。 

機能`paint(s)`は次のように動作します。グローバル カウンターは、現在の頂点が白 (偶数の場合) または黒 (奇数の場合) でペイントされるかを決定します。 次に、頂点の各子は、50/50 のランダムな決定に基づいて再帰的に描画される場合とされない場合があります。 さらに、子供たちの訪問順序は昇順または降順のいずれかにランダム化されます。 したがって、再帰が到達しない場合、一部の頂点は赤のままになる可能性があります。 

私たちの目標は、**ゼロ以外の確率で発生する可能性がある**、10^9 + 7 を法とする独特の色の数を数えることです。 

主な課題は確率的再帰から生じます。すべての頂点には、赤のままになる、白になる、または黒になるという 3 つの可能性があります。 子の順序と再帰呼び出しの間の相互作用により、単純なアプローチはさらに複雑になります。 

n が最大 10^5 で、制限が 1 秒であるとすると、可能なすべてのペイント シーケンスを明示的に反復する解決策は実行不可能です。 サブツリーごとの可能性の数を集計する組み合わせ推論に依存する必要があります。 

エッジ ケースには、頂点のチェーン (線形ツリー)、スター (すべての子を持つ 1 つのルート)、0 または複数の子を持つ頂点が含まれます。 たとえば、長さ 3 のチェーンでは、確率的分岐に応じて各頂点の色が変更される場合とされない場合があります。 すべての頂点が常に色変更されると単純に仮定すると、可能性が過大評価されてしまいます。 ノードごとに複数の子を持つツリーでは、サブツリーの可能性を慎重に組み合わせる必要があります。 

## アプローチ

 ブルート フォース アプローチでは、再帰呼び出しと子の順序の選択のすべてのシーケンスが列挙され、グローバル カウンターが更新され、各カラーリングが生成されます。 n = 10^5 の場合、再帰シーケンスの数が指数関数的に増加するため、これは直ちに不可能になります。 

重要な洞察は、子の確率的順序は **達成可能な色のセット**には影響せず、異なるシーケンスの数にのみ影響するという観察から得られます。 各ノードで可能なカラーリングは、その子のカラーリングのみに依存します。 具体的には、ノードに次のような子がある場合、`dp[child]`それぞれのカラーリングでは、ノードのカラーリングの総数は、各子が含まれる (ペイントされる) かスキップされる (赤のまま) かを考慮することで計算できます。 これはまさにサブセット積の原理です。子ごとに、`dp[child] + 1`可能性（それぞれのカラーリングまたはスキップ）。 親の合計は、すべての子の可能性の積です。親自体が子を描画しない「すべてスキップされた」ケースを除外したい場合は 1 を引いたものになります (問題の定式化によって異なりますが、この問題では親自体が常に描画されるため、減算は必要ありません)。 

したがって、動的計画法配列を計算できます。`dp[v]`頂点をルートとするサブツリーの個別の色の数を表す`v`。 再帰はボトムアップ (事後走査) であり、子の可能性を乗算的に組み合わせます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | 最適 (ツリー上の DP) | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力を解析して、ツリーを表す隣接リストを作成します。 各頂点はその子のリストを保持します。 これにより、効率的なトラバースが可能になります。 
2. を初期化します。`dp`配列`dp[v]`頂点をルートとするサブツリーの個別の色の数を保存します`v`。 リーフノードの場合、`dp[v]`は 2 (カウンターに応じて赤 + 白/黒) です。 
3. 再帰関数を定義する`dfs(v)`それは計算します`dp[v]`事後注文で。 それぞれの子どもたちにとって`u`の`v`、 電話`dfs(u)`最初に計算する`dp[u]`。 
4. すべての子を計算した後`dp`値を乗算的に結合します。`dp[v] = 1`。 それぞれの子どもたちにとって`u`、 アップデート`dp[v] = dp[v] * (dp[u] + 1) % MOD`。 の`+1`これは、子供が赤のまま（塗られていない）になる可能性を説明します。 
5. 親自体は白または黒にペイントできます。 これにより、異なる色の数が 2 倍になります。`dp[v] = dp[v] * 2 % MOD`。 
6. 戻る`dp[1]`答えはモジュロ 10^9 + 7 です。 

効果がある理由: それぞれ`dp[v]`サブツリーのすべてのカラーリングを正しくカウントします。 乗算の組み合わせは子間の独立した選択を考慮し、2 倍の場合は親の 2 つの色の可能性 (白または黒) を考慮し、グローバル カウンターのパリティを反映します。 子の順序やランダム性を明示的にシミュレートする必要はありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(200000)

MOD = 10**9 + 7

def main():
    n = int(input())
    parents = list(map(int, input().split()))
    
    tree = [[] for _ in range(n + 1)]
    for i, p in enumerate(parents, start=2):
        tree[p].append(i)
    
    dp = [0] * (n + 1)
    
    def dfs(v):
        res = 1
        for u in tree[v]:
            dfs(u)
            res = res * (dp[u] + 1) % MOD
        dp[v] = res * 2 % MOD  # parent can be white or black
    
    dfs(1)
    print(dp[1] % MOD)

if __name__ == "__main__":
    main()
```このソリューションでは、まず隣接リストを使用してツリーを構築します。 の`dfs`関数は動的プログラミング ソリューションの中核です。`res`1 を掛けても効果がないため、1 から始まります。 子どもたち一人ひとりが貢献します`dp[u] + 1`独特の色や赤いままであることを説明するためです。 最後に、2 を掛けると、親ノード自体の可能な 2 つの色が表されます。
