 ## 解決策
 ## 問題の理解

 すべての候補文字列が事前にわかっています。 そのうちの 1 つが均一にランダムに選択されます。 キャラクターの位置を尋ねることで情報を明らかにします。 

質問の順序は戦略的に選択されたものではありません。 すべてのステップで、まだ依頼されていないポジションの中から一律に選択します。 

いくつかの位置が明らかになった後でも、いくつかの文字列はこれまでに確認されたすべての回答と互換性がある可能性があります。 可能な文字列が 1 つだけ残るとすぐにゲームは終了します。 予想される質問数を計算する必要があります。 

重要なパラメータは非常に特殊な点で小さいです。 文字列は最大 50 個ありますが、文字列の長さは最大 20 です。長さが 20 であるということは、位置のサブセットが管理可能であることをすぐに示唆しています。$2^{20} = 1{,}048{,}576$。 これは大きいですが、慎重に設計されたビットマスク DP ではまだ手の届く範囲にあります。 一方、文字列の任意のサブセットが含まれる状態は、50 個の文字列が存在する可能性があるため、不可能になります。 

微妙な点は、ランダムなプロセスは、質問された順序ではなく、どのポジションがすでに質問されているかにのみ依存することです。 一連の位置が判明すると、残りの候補文字列が完全に決定されます。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

単一の文字列を考えてみましょう。```
1
abc
```正解は 0 です。選択された文字列は、何かを尋ねる前にすでにわかっています。 少なくとも 1 つの質問が必要であると盲目的に想定するソリューションは失敗します。 

1 つの位置だけが異なる 2 つの文字列を考えてみましょう。```
2
aab
aac
```ゲームでは、区別する位置が尋ねられるタイミングに応じて、1、2、または 3 つの質問が必要になる場合があります。 区別できる位置のみをカウントし、ランダムな順序を無視するソリューションでは、誤った期待が生じます。 

複数の位置からの情報を組み合わせた後にのみ区別可能になる文字列を考えてみましょう。```
3
ab
ac
cb
```すべての文字列を単一の位置で一意に識別することはできません。 DP は、公開された役職の数だけでなく、公開された役職のセット全体を追跡する必要があります。 

## アプローチ

 ブルートフォースの見方は簡単です。 状態を次のようにします。 

- 選択した文字列、
 - すでに質問されたポジションのセット。 

このような状態から、文字列がすでに一意に識別されているかどうかを判断できます。 そうでない場合は、要求されていない位置をランダムに選択し、再帰的に続行します。 

これにより正しい再帰が得られますが、状態空間には次のものが含まれます。$$n \cdot 2^m$$州。 と$n=50$そして$m=20$、それは5,000万以上の州です。 保管することすら現実的ではありません。 

問題を解決する観察は、選択された文字列ごとに個別の DP 値が実際には必要ないということです。 

すでに質問されたポジションのセットを修正する$M$。 

特定の文字列の場合$i$、少なくとも 1 つの他の文字列が、次の位置に関するすべての回答とまだ一致している場合、それを未解決として定義します。$M$。 

仮定する$F(M)$選択されたすべての文字列に対して予想される残りの質問の合計です。 

未解決の文字列ごとに、子状態に移行する前にもう 1 つの質問を費やす必要があります。 解決されたすべての文字列の期待値はすでにゼロです。 

これにより、位置マスクのみを含む繰り返しを書くことができます。$M$。 選択した文字列は DP 状態から完全に消えます。 

残りの課題は、マスクごとにコンピューティングすることです$M$、未解決の文字列の数。 ここで、短い文字列長が役に立ちます。 

2本の弦の場合$i$そして$j$、 させて`diff(i,j)`それらが異なる位置のセットになります。 

位置を尋ねてもまだ区別がつきません$M$まさに、それらの異なる立場がどれも明らかにされていないとき:$$M \cap diff(i,j)=\varnothing$$同様に、$$M \subseteq (\text{all positions}) \setminus diff(i,j)$$これは、古典的なサブセット SOS 伝播の問題になります。$2^m$マスク。

 ## アルゴリズムのチュートリアル

 1. 位置に 0 から 0 までの番号を付けます。$m-1$。 
2. For every ordered pair of distinct strings$(i,j)$、マスクを作成します`sameMask`2 つの文字列が等しい位置を含みます。 

現在公開されているポジションが次のサブセットである場合`sameMask`、次に文字列$i$そして$j$まだ区別がつきません。 
3. 配列を作成する`alive[mask]`64 ビットのビットセット。 

注文したペアごとに$(i,j)$、セットビット`i`内部`alive[sameMask]`。 

これはその文字列を記録します`i`公開位置マスクが次のサブセットである場合は常に未解決です。`sameMask`。 
4. スーパーセットからサブセットへの SOS 伝播を実行します。 

伝播後、`alive[M]`位置を明らかにした後もまだ解決されていない文字列のセットが正確に含まれています`M`。 

伝播が機能するのは、`sameMask`区別不能関係を継承します。 
5. 定義する$$K(M)=\text{number of set bits in } alive[M]$$これは、まだ一意に識別されていない文字列の数です。 
6. しましょう`dp[M]`位置が指定された場合に、選択されたすべての可能な文字列に対する予想される残りの質問の合計になります。`M`すでに明らかになっている。 
7. マスクを降順で処理します。 

もし`rem`ポジションは問われないままになる$$dp[M] = K(M) + \frac{1}{rem} \sum_{p \notin M} dp[M \cup \{p\}]$$最初の項は、未解決の文字列ごとに 1 つの質問を提供します。 第 2 項は、次の位置のランダムな選択の平均を計算します。 
8. フルマスク状態には子がありません。 その価値は単純に、`K(fullMask)`、これはゼロです。 
9. 必要な答えは次のとおりです$$\frac{dp[0]}{n}$$なぜなら`dp[0]`は、同じ確率で選択されたすべての文字列に対する期待値の合計です。 

### なぜ効果があるのか

 固定露出位置マスクの場合$M$、選択されたすべての文字列は、2 つのカテゴリのいずれかに分類されます。 

すでに一意に識別されている場合、残りの期待値はゼロです。 

一意に識別されない場合は、残りの位置の中から均一に選択された子マスクに移動する前に、さらに 1 つだけ質問が行われます。 

すべての文字列についてこれらの方程式を合計すると、次の漸化式が生成されます。`dp[M]`。 選択された個々の文字列に関する情報はもう必要ありません。 未解決の文字列の数のみが重要です。 

SOS フェーズは、明らかにされたすべての位置が等価マスクに属している場合、2 つの文字列は正確に区別できないままであるため、未解決の文字列を正しく計算します。 マスクからそのすべてのサブセットに情報を伝播すると、明らかにされた位置セットが正確に列挙されます。 

これら 2 つの事実を組み合わせると、ランダム プロセスが完全に特徴付けられるため、DP は正確な期待値を計算します。 

## Python ソリューション```python
import sys
from array import array

input = sys.stdin.readline

def solve():
    n = int(input())
    s = [input().strip() for _ in range(n)]

    m = len(s[0])
    N = 1 << m
    full = N - 1

    alive = array('Q', [0]) * N

    for i in range(n):
        for j in range(n):
            if i == j:
                continue

            same_mask = 0
            si = s[i]
            sj = s[j]

            for k in range(m):
                if si[k] == sj[k]:
                    same_mask |= 1 << k

            alive[same_mask] |= (1 << i)

    for b in range(m):
        bit = 1 << b
        for mask in range(N):
            if (mask & bit) == 0:
                alive[mask] |= alive[mask | bit]

    pc = bytearray(N)
    for mask in range(1, N):
        pc[mask] = pc[mask >> 1] + (mask & 1)

    dp = array('d', [0.0]) * N

    for mask in range(full, -1, -1):
        unresolved = alive[mask].bit_count()

        rem = m - pc[mask]
        if rem == 0:
            dp[mask] = float(unresolved)
            continue

        total = 0.0
        free = full ^ mask

        while free:
            bit = free & -free
            total += dp[mask | bit]
            free ^= bit

        dp[mask] = unresolved + total / rem

    print("{:.15f}".format(dp[0] / n))

solve()
```の`alive`配列は前処理の中心です。 各エントリには 64 ビットのビットセットが格納されます。$n \le 50$したがって、すべての文字列は 1 つの機械語に収まります。 

SOS の伝播により、情報がマスクからそのすべてのサブセットに移動します。 それが終わった後、`alive[M]`には、その公開位置マスクの未解決の文字列の正確なセットがすでに含まれています。 

DP は逆マスク順序で実行されます。 すべての遷移は厳密なスーパーセットに移行するため、すべての子状態はすでに計算されています。 

間違いやすい実装の詳細の 1 つは、次の解釈です。`K(M)`。 残っている候補文字列の数ではありません。 これは、選択された未解決の文字列の数です。 それらは異なる量です。 

もう 1 つの微妙な点は、順序付きペアの使用です。 文字列の場合`i`まだ文字列と混同される可能性があります`j`、次に文字列`i`未解決としてマークする必要があります。 逆方向も別途記録する必要があります。
