 ## 解決策
 ## 問題の理解

 の配列を構築するように求められます。`n`次のような負ではない整数`m`指定されたビット単位の AND 制約が満たされます。 各制約は部分配列を指定します`[l, r]`そして目標値`q`つまり、インデックスからすべての要素のビット単位の AND を取得すると、`l`に`r`、結果は次と等しい必要があります`q`。 私たちの目標は、そのような配列を作成するか、それが不可能であると判断することです。 

入力サイズは重要です。両方とも`n`そして`m`は 100,000 に達する可能性があり、各要素は最大約 2^30 になります。 配列の数が天文学的に多いため、考えられるすべての割り当てをチェックする単純なアプローチは明らかに扱いにくいでしょう。 これは、ソリューションがほぼ線形の時間、理想的には制約ごとに O(n log n) または O(n) で動作する必要があることを示しています。 

明らかではないエッジ ケースには、互換性のないビット パターンを持つ重複する制約が含まれます。 たとえば、1 つの制約で AND が必要な場合、`[1, 3]`なる`2`そしてもう一つが必要とするのは`[2, 4]`なる`1`、一貫して値を割り当てる方法がない可能性があります。 もう 1 つの微妙な点は、ゼロの処理です。ある範囲内ではビットが 0 である必要があるが、別の制約により重複する範囲内では 1 である必要がある場合、配列は不可能です。 単純に貪欲にどこでも 1 を埋め込むと、そのような入力で静かに失敗する可能性があります。 

## アプローチ

 ブルートフォース手法では、すべての配列要素を任意に割り当ててから、制約をチェックします。 これは小さな配列では機能しますが、`2^(30*n)`ビットを単純に処理しようとすると、組み合わせが難しくなります。 n は 10^5 であるため、制約に存在するビットのみに制限してもスケールは調整されません。 また、ブルート フォースは、ビット単位の AND が制限的で単調な演算であるという事実を利用しません。つまり、ある範囲内のビットが 0 になると、その範囲内のどこでも 0 になります。 

重要な洞察は、ビットごとに推論することです。 30 ビットのそれぞれは独立して考えることができます。 制約ごとに、すべてのビットが設定されます。`q`範囲の少なくとも 1 つの要素で設定する必要がありますが、ビットは設定解除されます。`q`範囲のすべての要素でゼロでなければなりません。 これにより、間隔全体でビットを賢く割り当てるという問題が軽減されます。 

最適なアプローチでは、差分配列を使用してビットを効率的に伝播します。 範囲内に 1 つである必要があるビットについては、間隔の開始と終了をマークして、後で累積ビット値を計算できます。 この方法ですべての制約を処理した後、配列を再構築し、元の各制約を検証して、ビットの競合が存在しないことを確認できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^(30*n)) | O(n) | 遅すぎる |
 | ビットごとの間隔の割り当て | O(n * 30 + m * 30) ≈ O(n + m) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を初期化する`a`長さの`n`すべてゼロで。 これは最終的な答えを保存します。 
2. 30 ビット (0 ～ 29) ごとに差分配列を作成します。`diff`長さの`n+2`このビットを設定する必要がある間隔をマークします。 
3. 制約ごとに`[l, r, q]`、30 ビットを繰り返します。 少しなら`b`に設定されています`q`、増分`diff[l]`による`1 << b`そして減少します`diff[r+1]`による`1 << b`。 これはそのビットをマークします`b`少なくともこの間隔のどこかに存在する必要があります。 
4. 次のプレフィックスの合計を計算します。`diff`候補配列を構築する`a`。 それぞれ`a[i]`インデックスをカバーする間隔で必要なすべてのビットの OR になります。`i`。 
5. ビット単位の AND を計算して各制約を検証します。`[l, r]`で`a`。 等しい場合`q`、 続く; そうでない場合は、「NO」を出力して終了します。 
6. すべての制約が満たされている場合は、「YES」を出力し、配列を出力します。`a`。 

機能する理由: 差分配列は、任意の間隔で必要なビットがその間隔の少なくとも 1 つの要素に存在することを保証します。 ビットごとの AND では、ゼロ ビットが伝播するにはすべての要素にすべてのビットが存在する必要があるため、ビットが設定されていないことを確認するだけで済みます。`q`これはゼロのままであり、ゼロで初期化し、必要なビットのみを OR 演算することで自然に満たされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
constraints = [tuple(map(int, input().split())) for _ in range(m)]

# Step 1: Initialize array and bitwise difference array
a = [0] * n
diff = [0] * (n + 2)

for b in range(30):
    diff = [0] * (n + 2)
    for l, r, q in constraints:
        if (q >> b) & 1:
            diff[l-1] |= 1 << b
            diff[r] ^= 1 << b
    cur = 0
    for i in range(n):
        cur ^= diff[i]
        a[i] |= cur

# Step 2: Verify all constraints
for l, r, q in constraints:
    val = a[l-1]
    for i in range(l, r):
        val &= a[i]
    if val != q:
        print("NO")
        sys.exit()
print("YES")
print(*a)
```コードはまず、各ビットの差分配列で XOR を使用してビット単位の間隔割り当てを構築します。 XOR アプローチにより、必要なビットの累積的な伝播が可能になります。 アレイを再構築した後`a`、すべての制約に対する素朴なチェックにより、正確性が保証されます。 

微妙な点としては、ゼロベースのインデックスを一貫して使用すること、差分配列の終点を慎重に処理すること、生の整数値に依存する代わりに 30 ビットを反復処理することなどが挙げられます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = io.StringIO()
    sys.stdout = output
    # call solution
    n, m = map(int, input().split())
    constraints = [tuple(map(int, input().split())) for _ in range(m)]
    a = [0] * n
    for b in range(30):
        diff = [0] * (n + 2)
        for l, r, q in constraints:
            if (q >> b) & 1:
                diff[l-1] |= 1 << b
                diff[r] ^= 1 << b
        cur = 0
        for i in range(n):
            cur ^= diff[i]
            a[i] |= cur
    for l, r, q in constraints:
        val = a[l-1]
        for i in range(l, r):
            val &= a[i]
        if val != q:
            print("NO")
            return output.getvalue().strip()
    print("YES")
    print(*a)
    return output.getvalue().strip()

# Provided sample
assert run("3 1\n1 3 3\n") == "YES\n3 3 3", "sample 1"
