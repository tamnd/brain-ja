 **タグ:** フロー、グラフ
 **解決時間:** 1 分 51 秒

 ## 解決策
 ## 問題の理解

 各頂点が都市を表し、各有向エッジがメッセンジャーが一方向に移動できる道路を表す有向グラフが与えられます。 一部の都市には最初から多数のメッセンジャーがいます。 これらのメッセンジャーは道路に沿って移動でき、一度計画のコピーを持ち運べば、都市にいるときはいつでもそれを自由に複製できるため、制限要因は後でコピーを何枚作成できるかではなく、最初に計画を注入する場所です。 

課題は、すべての移動と複製の後、すべての都市に計画を運ぶ少なくとも 1 人の使者が訪れるように、計画の最初のコピーを何部メッセンジャーに配布するかを決定することです。 メッセンジャーは有向グラフを任意に横断できるため、到達可能性は純粋に有向パスによって決まります。 

重要な構造的解釈は、メッセンジャーに設定された各初期計画が到達可能領域を開始するということです。最終的には、そのメッセンジャーの開始位置から到達可能なすべての都市がカバーされることになります。 複製は無料でローカルであるため、計画を持つメッセンジャーが都市に到着すると、そこにいるすべてのメッセンジャーがそれをさらに運ぶことができるため、このプロセスは開始メッセンジャーを選択し、到達可能性を前方に伝播することに相当します。 

テスト全体の都市の総数に対する制約は小さく、ノード全体で最大 200 個、エッジは最大 800 個です。これは、テストごとに O(n^2) または O(nm) のグラフ アルゴリズムが許容されることを強く示唆していますが、n の指数関数やノードのサブセット列挙を伴うものは許容されません。 

微妙な失敗例は、都市に到達可能な計画の情報源がなく、最初のメッセンジャーもいない場合に発生します。 たとえば、ノードの次数が 0 で a_i = 0 の場合、それは直ちに不可能になります。 別の失敗例は、グラフに複数の強接続コンポーネント (SCC) がある場合に発生します。SCC 内では 1 つのプランで十分ですが、SCC 間では方向が重要であり、到達できない SCC により追加の初期配置が必要になります。 

単純なアプローチでは、すべての開始位置をシミュレートしたり、貪欲に都市を選択したりすることも考えられますが、SCC 全体での到達可能性の重複が自明ではない場合、そのような戦略は失敗します。1 つの SCC で開始を選択すると、すでに他の多くの SCC をカバーしている可能性があり、ローカルの貪欲な選択ではグローバルな到達可能性の構造が捕捉されないためです。 

## アプローチ

 直接的な強引なアイデアは、計画の開始点としてメッセンジャーのサブセットを選択して、到達可能性をシミュレートすることです。 選択した開始メッセンジャーごとに、BFS/DFS を実行して、到達可能なすべての都市をマークし、すべての都市がカバーされているかどうかを確認します。 これには、サイズ k のすべてのサブセットをチェックし、k を 1 から増やしていく必要があります。 

k を固定したとしても、サブセットの数はメ​​ッセンジャーの数の組み合わせであり、O(2^n) になる可能性があります。 各シミュレーションのコストは O(n + m) であるため、合計は指数関数的となり、n = 200 の場合でも実行不可能です。 

重要な洞察は、到達可能性は強く接続されたコンポーネントによって決まるということです。 SCC 内で、その SCC 内の 1 つのメッセンジャーがプランを受信すると、SCC 内のすべてのノードは相互に通信できるため、同等になります。 したがって、各 SCC は、凝縮された DAG 内の単一ノードのように動作します。 

グラフを SCC に圧縮すると、DAG が得られます。 この DAG では、他の SCC からの入力エッジがない SCC には外部から到達できません。 このような SCC には、その中に少なくとも 1 つの初期計画配置が含まれている必要があります。そうでない場合は、永久に情報が得られないままになります。 このような SCC にも最初からメッセンジャーが含まれていない場合、それを満たすことはまったく不可能です。 

したがって、問題は、SCC を識別し、それらを縮小し、すべてのソース SCC (凝縮グラフの次数ゼロ) に少なくとも 1 つのメッセンジャーが含まれていることを確認することに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース サブセット | O(2^n · (n + m)) | O(n + m) | 遅すぎる |
 | SCC 圧縮 (コサラジュ/タルジャン) | O(n + m) | O(n + m) | 承認済み |

## アルゴリズムのチュートリアル

 1. 有向グラフの強接続成分を計算します。 これにより、相互の到達可能性が保証されている都市がグループ化されるため、1 つのノードに入ったプランはコンポーネント全体に広がります。 
2. 各 SCC がノードとなる要約グラフを構築します。 元のグラフのすべてのエッジ u → v について、u と v が異なるコンポーネントに属している場合は、それらの SCC の間にエッジを追加します。 
3. 要約グラフ内の各 SCC の入次数を計算します。 
4. 各 SCC について、a_i > 0 の都市が少なくとも 1 つ含まれているかどうかを判断します。これは、この SCC 内に少なくとも 1 つの初期計画を配置できるかどうかを示します。 
5. 次数 0 のすべての SCC について、少なくとも 1 つのメッセンジャーが含まれているかどうかを確認します。 そうでない場合は、外部 SCC がそれに到達できず、内部で開始できないため、-1 を返します。 
6. 次数 0 の SCC がいくつ存在するかを数えます。 このような各 SCC には少なくとも 1 つの独立した開始計画が必要であるため、この数値が答えになります。 

これが機能する理由は、SCC 凝縮により、情報がエッジに沿ってのみ流れる DAG が生成されるためです。 次数 0 の SCC はすべてこの DAG のソースであるため、他のコンポーネントはプランを DAG に伝播できません。 SCC 内では、完全な相互到達可能性によって完全な内部カバレッジと外部への伝播が保証されるため、1 つの開始プランで十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def kosaraju(n, g, gr):
    vis = [False] * n
    order = []

    def dfs1(v):
        vis[v] = True
        for to in g[v]:
            if not vis[to]:
                dfs1(to)
        order.append(v)

    for i in range(n):
        if not vis[i]:
            dfs1(i)

    comp = [-1] * n

    def dfs2(v, c):
        comp[v] = c
        for to in gr[v]:
            if comp[to] == -1:
                dfs2(to, c)

    cid = 0
    for v in reversed(order):
        if comp[v] == -1:
            dfs2(v, cid)
            cid += 1

    return comp, cid

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))

        g = [[] for _ in range(n)]
        gr = [[] for _ in range(n)]

        for _ in range(m):
            u, v = map(int, input().split())
            u -= 1
            v -= 1
            g[u].append(v)
            gr[v].append(u)

        comp, k = kosaraju(n, g, gr)

        indeg = [0] * k
        has_messenger = [False] * k

        for i in range(n):
            has_messenger[comp[i]] = has_messenger[comp[i]] or (a[i] > 0)

        for u in range(n):
            for v in g[u]:
                cu, cv = comp[u], comp[v]
                if cu != cv:
                    indeg[cv] += 1

        ans = 0
        for i in range(k):
            if indeg[i] == 0:
                if not has_messenger[i]:
                    out.append("-1")
                    break
                ans += 1
        else:
            out.append(str(ans))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装では、最初に Kosaraju のアルゴリズムを使用して SCC を計算し、前方隣接リストと逆隣接リストを分離します。 コンポーネント識別子を計算した後、コンポーネントごとにメタデータ、つまりコンポーネントに少なくとも 1 つのメッセンジャーが含まれているかどうか、およびその次数が凝縮グラフ内でどのようなものであるかを構築します。 

微妙な点は、エッジはコンポーネントと交差する場合にのみカウントされるということです。 内部 SCC エッジはコンポーネント間の伝播を表さないため、無視する必要があります。 最後のループでは、実現可能性を検証しながら、ソース SCC の数を正確にカウントします。 

## 実用的な例

 ### 例 1

 入力グラフには複数の SCC があります。 簡略化したトレースを考えてみましょう。 

| 都市 | あ_い | コンポーネント | 度数 | メッセンジャーあり |
 | --- | --- | --- | --- | --- |
 | 1 | 2 | 0 | 0 | はい |
 | 2 | 1 | 0 | 0 | はい |
 | 3 | 0 | 1 | 1 | いいえ |
 | 4 | 1 | 1 | 1 | はい |

 SCC 0 は次数 0 を持ち、メッセンジャーを含みます。SCC 1 は次数 1 を持ちます。 

SCC はトポロジー的な意味で処理されます。SCC 0 はソースですが、SCC 1 はソースではありません。 SCC 0 のみが開始計画を必要とします。 

答えは 1 です。 

これは、ダウンストリーム SCC は、ソース SCC から到達できるため、メッセンジャーが含まれている場合でも、応答に寄与しないことを示しています。 

### 例 2

 ソース SCC にメッセンジャーが存在しない場合を考えてみましょう。 

| 都市 | あ_い | コンポーネント | 度数 |
 | --- | --- | --- | --- |
 | 1 | 0 | 0 | 0 |
 | 2 | 0 | 0 | 0 |
 | 3 | 1 | 1 | 1 |

 SCC 0 はソースですが、メッセンジャーはありません。 その SCC には初期メッセンジャーが存在せず、着信エッジも初期メッセンジャーをもたらすことができないため、プランをそこに注入することはできません。 

アルゴリズムは、この状態を検出するとすぐに -1 を返し、実現可能性チェックが正しいことを示します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + m) | SCC のための 2 つの DFS パスと、凝縮されたグラフ上の線形エッジ処理 |
 | スペース | O(n + m) | 隣接リスト、逆グラフ、コンポーネント配列 |

 この制約では最大 200 個のノードと 800 個のエッジが許可されるため、線形グラフ アルゴリズムで十分です。 SCC ベースの削減により、組み合わせ探索が決して試行されなくなります。

 ## 特殊なケース

 重大なエッジ ケースは、送信元 SCC にメッセンジャーが存在しない場合です。 そうなると、構造的に強制されているにもかかわらず、発動することができません。 このアルゴリズムは、カウントする前に has_messenger をチェックすることで、SCC 集計中にこれを正しく検出します。 

もう 1 つのエッジ ケースは、完全に強接続されたグラフです。 すべてのノードは、次数 0 の 1 つの SCC を形成します。 少なくとも 1 つのメッセンジャーがどこかに存在する場合、それは SCC 全体に伝播するため、1 つのプランで十分です。 このアルゴリズムはグラフを 1 つのコンポーネントに折りたたみ、1 を返します。 

3 番目のエッジ ケースには、エッジのない接続されていないコンポーネントが含まれます。 各ノードは、次数 0 の独自の SCC です。 各メッセンジャーは独立して起動する必要があるため、答えは少なくとも 1 つのメッセンジャーを含むノードの数になります。
