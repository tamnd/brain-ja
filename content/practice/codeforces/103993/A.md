 ## 解決策
 ## 問題の理解

 レベルは無限数直線としてモデル化されます。 文字は位置 0 から始まり、位置 n に到達したいと考えています。 キャラクターは各瞬間に、単位ステップあたり 1 秒の固定コストを払って左右に 1 ユニット移動するか、ジャンプごとに b 秒を払って正確に左右に d ユニット移動するテレポートのようなジャンプを実行できます。 パスは 0 と n の範囲内に留まるように制限されていないため、合計時間の短縮に役立つ場合は、オーバーシュートまたは負の値になることが許可されます。 

タスクは、位置 n で正確に終了するのに必要な最小合計時間を計算することです。 

制約は、n が最大 1000 であるほど十分に小さく、すべてのコストとジャンプ長も 1000 によって制限されます。これは、整数状態にわたる最短パスが実現可能であることを直ちに示唆します。 状態空間が小さいため、すべての可能な位置と遷移に対する単純な動的プログラミングはすでに十分に高速です。 

微妙な点は、ジャンプがオーバーシュートし、その後歩きで修正される可能性があることです。 これにより、最初にターゲットから意図的に遠ざかることが最適な戦略となるケースが生じます。 たとえば、ウォーキングにはコストがかかるが、ジャンプは安価で大きい場合、ジャンプのパリティを調整するか、必要な小さなステップの数を減らすために、負または n を超えることが最適な場合があります。 

ジャンプ距離 d が n より大きい場合、別のエッジ ケースが発生します。 この場合、すべてのジャンプがターゲットをオーバーシュートするため、最適な解決策は、数回ジャンプした後に歩いて戻るという構成になる可能性があります。 単純な貪欲な「近づいたら常に前にジャンプする」アプローチは失敗する可能性があります。これは、一連のジャンプが単一のステップを混合するよりも適切に調整されている場合、遠ざかる方が総コストを削減できる可能性があるためです。 

## アプローチ

 ブルートフォース解釈では、すべての整数の位置がグラフ内のノードとして扱われ、すべての移動またはジャンプがエッジとして扱われます。 各位置 x から、コスト a で x+1、x−1 に移動し、コスト b で x+d、x−d に移動できます。 このグラフに対してダイクストラのアルゴリズムを実行すると、最短経路が見つかります。 

これは正しいです。すべての移動が重み付けされたエッジを形成し、総コストを最小限に抑えているからです。 ただし、単純に負の無限大から正の無限大までの位置を許可すると、グラフは無限大になります。 ブルート フォース アプローチは、最適なパスが [0, n] の周囲の境界ウィンドウの外側に大きく出る必要がないことに気づいた後にのみ意味を持ちます。 n ≤ 1000 であり、移動するたびに位置が少なくとも 1 変更されるため、最適なパスは最適性を失うことなく [-2000, 3000] のような範囲に制限できます。 これにより、約数千ノードの有限グラフが得られ、ダイクストラは実行可能になりますが、それでも必要以上に重くなります。 

重要な洞察は、状態空間が十分に小さいため、単純な最短経路の計算や、到達可能なすべての位置にわたる直接 DP さえも効率的に機能するということです。 各位置は一定数の近傍のみに依存するため、O(n) または O(n log n) の複雑さで標準の最短パス アルゴリズムを実行しても、問題なく制限内に収まります。 グラフはコストを除いて構造的に重み付けされていないため、優先キューを備えた BFS バリアントは簡単で堅牢です。 

もう 1 つの単純化は、すべての遷移には固定コストがあるため、これは本質的にノードごとのエッジ数が一定の折れ線グラフ上の最短パスであるため、標準のダイクストラを超える高度な最適化は必要ないことです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 限界のない完全な無限のブルートフォース | 該当なし | O(∞) | 無効 |
 | 有界範囲を超えるダイクストラ | O(N log N) | O(N) | 承認済み |
 | 小さなグラフ上の最適化された DP / 最短パス | O(N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 各整数の位置を、その位置に到達するまでに必要な最小時間を表すノードとして扱います。

1. まず、ポジションの合理的な限界を定義します。 ターゲットは n であり、各移動は最大でも d または 1 だけ位置を変更するため、すべての有用な状態を安全に含む範囲 (通常は -2n から 2n) に制限します。 これにより、有益な迂回が依然として表現可能であることが保証されます。 
2. コストなしで位置 0 から開始するため、距離配列を無限大で初期化し、dist[0] = 0 に設定します。 
3. 優先キューを使用してダイクストラのアルゴリズムを実行し、常に最小の既知のコストで状態を拡張します。 これにより、常に最適な順序で状態を処理することが保証されます。 
4. 各位置 x から、コスト a の x+1、コスト a の x−1、コスト b の x+d、およびコスト b の x−d の最大 4 つの遷移まで緩和します。 各緩和により、より安価なルートが見つかった場合、目的地位置の最も既知のコストが更新されます。 
5. 到達可能なすべての状態が処理されるまで続行します。 
6. 答えは dist[n]、つまり目標位置に到達するための最小コストです。 

これが機能する理由は、このプロセスが重み付きグラフ上で最短経路の計算を正確にモデル化しているためです。 各位置は状態であり、各移動は非負のコストを持つエッジであり、ダイクストラは非負の重みの下で最適性を保証します。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n, a, b, d = map(int, input().split())

    # Reasonable bound: enough to cover detours
    LIM = 2 * n + d + 10

    INF = 10**18
    offset = LIM
    size = 2 * LIM + 1

    dist = [INF] * size
    start = offset
    dist[start] = 0

    pq = [(0, start)]

    def relax(nx, nd):
        if 0 <= nx < size and nd < dist[nx]:
            dist[nx] = nd
            heapq.heappush(pq, (nd, nx))

    while pq:
        cur, x = heapq.heappop(pq)
        if cur != dist[x]:
            continue

        pos = x - offset

        # move +1
        relax(x + 1, cur + a)
        # move -1
        relax(x - 1, cur + a)
        # jump +d
        relax(x + d, cur + b)
        # jump -d
        relax(x - d, cur + b)

    print(dist[offset + n])

def main():
    solve()

if __name__ == "__main__":
    main()
```この実装では、整数の境界付きセグメント上に暗黙的なグラフが構築されます。 オフセット トリックは、すべてを非負の配列インデックス空間にシフトすることで負の位置を処理するために使用されます。 優先キューにより、常に最も安価で到達可能な位置が最初に拡張されます。 

よくある間違いは、必要な境界を過小評価することです。 範囲が狭すぎると、一時的に左または右に向かう有効な最適パスが遮断されます。 選択されたおよそ 2n + d の制限は安全です。なぜなら、有用な迂回は、解を支配する不必要な歩行コストを支払わずに、そのスケールを超えて分岐を繰り返す必要がないからです。 

もう一つの微妙なポイントはチェックです`cur != dist[x]`これにより、優先キュー内の古いエントリの処理が回避され、アルゴリズムが制限時間内に維持されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(L log L) | 一定の遷移を伴う O(L) ポジション上のダイクストラ |
 | スペース | O(L) | 距離配列と制限された範囲を超える優先キュー |

 値 L は選択された座標ウィンドウに比例し、n で線形になります。 n ≤ 1000 であるため、これは時間とメモリの両方の制限内に問題なく収まります。

        pos = x - offset
        relax(x + 1, cur + a)
        relax(x - 1, cur + a)
        relax(x + d, cur + b)
        relax(x - d, cur + b)

 ## 特殊なケース

 n が 0 の場合、開始状態がすでにターゲットと一致しており、遷移は必要ないため、アルゴリズムは直ちに 0 を返します。 

ジャンプ距離が目標よりも大きい場合、オーバーシュートの繰り返しにより不要なコストが蓄積されるため、最短経路の計算により過剰なジャンプが自然に回避されます。 ダイクストラ プロセスでは引き続きこれらの状態が考慮されますが、歩行または制限されたジャンプが優勢であることがすぐにわかります。 

歩行の方がジャンプより大幅にコストが低い場合、緩和ステップでは常に ±1 の遷移が優先され、アルゴリズムはジャンプ エッジに依存することなく折れ線グラフ上の標準の最短パスのように動作します。
