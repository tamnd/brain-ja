 ## 解決策
 ## 問題の理解

 私たちは 6 桁のパスワードを扱っており、各パスワードは 0 から 9 までの一連の数字です。パスワードの構造には非常に制約があります。異なる 2 桁を使用する必要があり、それぞれの数字が正確に 3 回出現する必要があるため、パスワードは常に AAA BBB のような、A と B が異なる数字の順列になります。 

この構造規則に加えて、禁止される一連の数字も与えられます。 これらの数字が 1 つでも使用されているパスワード候補は無効です。 

したがって、タスクは純粋に組み合わせです。許容される 2 つの数字を選択し、それぞれが正確に 3 回出現するように配置することによって、長さ 6 のシーケンスが何個形成できるかを数えます。 

入力は、禁止されている数字の小さなリストで構成されます。 リストされていないものはすべて許可されます。 数字の範囲は 0 ～ 9 のみであるため、有効範囲は非常に小さく、数字のペアに対する総当り攻撃で十分であることがすでに示唆されています。 

この制約は、非常に小さい検索スペースを意味します。 最大 10 桁が存在し、許可される桁のペアを選択しています。 これにより、最大でも C(10, 2) = 45 個の候補ペアが得られますが、これは非常に小さいです。 ペアごとに、手配を数えるのは絶え間ない作業です。 これにより、高度な最適化や前処理の必要性が即座に排除されます。 

エッジケースは主に、禁止された数字が使用可能なセットをどのように縮小するかに関するものです。 

微妙なケースとしては、使用可能な桁が 2 桁未満の場合があります。 たとえば、9 桁が禁止され、1 桁だけが残っている場合、2 つの異なる桁が必要となるため、有効なパスワードを作成することはできません。 もう 1 つの特殊なケースは、ちょうど 2 桁が残っている場合で、有効な桁ペアは 1 つですが、多くの順列が生成されます。 

貪欲な思考が失敗する例: 許可される数字が {1, 2} の場合、パスワードは「111222」 1 つだけであると誤って考えるかもしれませんが、実際の答えは、このマルチセットの個別の順列の数、つまり 6!/(3!3!) = 20 です。この組み合わせ要素が欠けていることが最も一般的な間違いです。 

## アプローチ

 ブルートフォースのアイデアは、0 ～ 9 の数字の長さ 6 のシーケンスをすべて生成し、各シーケンスが制約を満たすかどうかを確認することです。つまり、厳密に 2 つの異なる数字がそれぞれ 3 回出現し、禁止された数字がないことです。 このようなシーケンスは 10^6 個あります。 各チェックは O(6) であるため、このアプローチではテストごとに約 600 万回の操作が必要になります。これはすでに境界線に達していますが、一部の言語ではまだ許容されます (不要ではあります)。 

重要な観察は、有効なパスワードの構造は 2 桁の選択によって完全に決定されるということです。 数字 A と B が固定されると、有効なシーケンスの数は純粋に組み合わせになります。A の 3 つのコピーと B の 3 つのコピーを長さ 6 のシーケンスに配置します。 このような配置の数は、多項係数 6 です。 / (3!3!) = 20 (どの桁が選択されたかには関係ありません)。 

これにより、問題は、許容される数字のペアが何組存在するかを数えるという問題に軽減されます。 k 桁が許可されている場合は、順序のないペア (A, B) を選択し、C(k, 2) の可能性を与え、それぞれがちょうど 20 個のパスワードを提供します。

 | --- | --- | --- | --- |
 | すべてのシーケンスに対するブルート フォース | O(10^6) | お(1) | 遅すぎる/不必要 |
 | 数字のペア + 組み合わせを選択 | お(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 禁止されている数字のセットを読み、それらにマークを付けます。 このステップでは、構成で使用可能な桁を定義します。 
2. 0 ～ 9 をスキャンし、禁止マークが付けられていない数字を収集して、許可される数字のリストを作成します。 これにより、有効なアルファベットが分離されます。 
3. 許可される桁数を数え、それを k とします。 この値は、有効なパスワードが存在できるかどうかを決定します。 
4. k が 2 未満の場合は、2 つの異なる数字を選択できないため、すぐに 0 を返します。 これは構造上不可能です。 
5. それ以外の場合は、k から 2 つの異なる数字を選択する方法の数、つまり k * (k - 1) / 2 を計算します。このような各ペアは、パスワードで使用される固定の複数の数字セットに対応します。 
6. ペアの数に 20 を掛けます。選択したペア (A、B) について、3 つの A と 3 つの B を含む有効な 6 長さの配置の数は 6 であるためです。 / (3!3!) = 20。 

### なぜ効果があるのか

 有効なパスワードはすべて、正確に 2 つの異なる数字を使用する必要があるため、順序のない一意の数字のペアが必要になります。 逆に、許可された数字の順序のないペアは、各数字の 3 つのコピーを持つマルチセットのすべての順列で構成される有効なパスワードのファミリーを一意に定義します。 異なる数字のペアでは同じシーケンスを生成できないため、これらのファミリーは互いに素です。 各ファミリーのサイズは同じ固定サイズであるため、合計数は単純にペアの数に 1 つのファミリーのサイズを掛けたものになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    forbidden = set(map(int, input().split())) if n else set()

    allowed = [d for d in range(10) if d not in forbidden]
    k = len(allowed)

    if k < 2:
        print(0)
        return

    pairs = k * (k - 1) // 2
    ans = pairs * 20
    print(ans)

if __name__ == "__main__":
    solve()
```コードはまず、許可された数字セットを構築します。これは、禁止された数字が候補構造に入らないようにするために必要です。 小切手`k < 2`有効なペアが存在しない縮退ケースを処理します。 

表現`k * (k - 1) // 2`順序付けされていない数字のペアの数を、明示的に生成せずに効率的に計算します。 20 を掛けると、各桁のコピーを 3 つ配置するための固定の組み合わせ数が適用されます。 

よくある実装上の間違いは、順序は最終シーケンスでは重要であるが、桁の選択では重要ではないことを忘れていることです。 これが、ペアの選択 (組み合わせによる選択) を配置の数 (固定の順列数) から分離する理由です。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    forbidden = set(map(int, input().split())) if n else set()

 ## 特殊なケース

 ほとんどすべての数字が禁止され、1 つの数字だけが残っている場合、アルゴリズムは正しく k = 1 を生成し、ペアを形成できないため、すぐに 0 を返します。 たとえば、入力`9`数字付き`0 1 2 3 4 5 6 7 8`数字 9 のみが残るため、k = 1 となり、関数は期待どおり 0 を返します。 

数字が禁止されている場合、k = 10 であるため、ペアの数は 45 です。20 を掛けると 900 になります。アルゴリズムは、特別なケースを使用せずに、同じ式を通じてこれを明確に処理します。 

ちょうど 2 桁が残っている場合、k = 2 となり、1 つのペアが生成され、したがってちょうど 20 個の有効なパスワードが生成されます。 これは最小の非ゼロ シナリオであり、組み合わせ係数が正しく適用されていることを確認します。 

すべての場合において、計算の構造により、禁止された数字は許可されたセットのサイズにのみ影響し、カウント以外の特別な分岐は必要ありません。
