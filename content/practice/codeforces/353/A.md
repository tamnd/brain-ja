 ## 解決策
 ## 問題の理解

 ドミノタイルが並んでいます。 各タイルの上半分に番号があり、下半分に番号が付いています。 

すべてのタイルについて、そのままにすることも、180 度回転することもできます。 タイルを回転すると、単純にその上限と下限の値が入れ替わります。 各回転には 1 秒かかります。 

私たちの目標は、これらの合計を均等にすることです。 

1. 現在上半分にあるすべての数値の合計。 
2. 現在下半分にあるすべての数値の合計。 

必要な最小回転数を見つけなければなりません。 どの回転シーケンスも両方の合計を均等にすることができない場合は、次のように出力します。`-1`。 

タイルの数は最大でも 100 と非常に少ないです。 たとえ$O(n^2)$ここでの解決策は簡単です。 課題はパフォーマンスではなく、答えを即座に得るパリティ観察を発見することです。 

重要な点は、パリティのみが重要であるということです。 数値が 2 であるか 6 であるかは、どちらも偶数であるため、関係ありません。 同様に、1、3、5 は奇数であるため、すべて同じように動作します。 

パリティではなく実際の値に注目すると、いくつかのエッジケースは誤って処理されやすくなります。 

考慮する：```
1
1 2
```上の合計は奇数、下の合計は偶数です。 回転すると、上位 = 2、下位 = 1 となるため、パリティは単純に交換されます。 1 つの和は永遠に奇数のままです。 正しい答えは、`-1`。 

不注意な解決策では、1 つのタイルには奇数と偶数の両方が含まれているため、回転すれば常に問題を解決できると考える可能性があります。 

もう 1 つの重要なケースは次のとおりです。```
2
1 2
2 1
```最初は両方の合計が奇数です。 

上 = 3、下 = 3。 

いずれかのタイルを回転すると、両方の合計が奇数だけ変化し、両方の合計が均等になります。 正しい答えは、`1`。 

現在の合計が偶数であるかどうかだけをチェックするソリューションでは、誤った値が返されます。`-1`。 

もう 1 つの微妙なケース:```
2
1 1
3 3
```上限と下限の合計は両方とも偶数です。 

上 = 4、下 = 4。 

答えは`0`すべてのタイルが 2 つの奇数で構成されているにもかかわらずです。 目標のパリティがすでに達成されている場合は、何もローテーションする必要はありません。 

## アプローチ

 ブルートフォースソリューションでは、ドミノのすべてのサブセットを回転させようとします。 サブセットごとに、結果の上限と下限の合計を計算し、両方が偶数であるかどうかを確認します。 すべてのドミノには 2 つの状態があるため、$2^n$可能な構成。 

すべての有効な配置が回転されたタイルの 1 つのサブセットに対応するため、これは概念的に機能します。 残念ながら、たとえ$n = 100$、$2^{100}$構成は天文学的に大きく、列挙することはまったく不可能です。 

私たちがはるかに改善できる理由は、重要なのは同等性だけだからです。 

ドミノに値が含まれているとします。$(x, y)$。 回転させると上限値が変化します$y - x$そして下限の合計は$x - y$。 

もし$x$そして$y$同じパリティを持っている場合、$y - x$は均等です。 そのドミノを回転しても、どちらの合計のパリティも変わりません。 

もし$x$そして$y$パリティが異なる場合、$y - x$奇数です。 そのドミノを回転させると、両方の合計のパリティが同時に反転します。 

この観察は問題を完全に特徴づけています。 

させて：

-$S_u$現在の上限値になります。 
-$S_d$現在の下限合計になります。 

両方の合計がすでに偶数である場合、答えは次のようになります。`0`。 

一方の合計が偶数で、もう一方の合計が奇数であれば、答えはすぐに得られます。`-1`。 有効な回転ごとに両方のパリティが反転されるため、常に等しいままになります。 私たちは決して方向転換できない`(even, odd)`の中へ`(even, even)`。 

両方の合計が奇数の場合、パリティ反転ドミノが 1 つだけ必要になります。これは、2 つの数値が異なるパリティを持つドミノを意味します。 その 1 つのドミノを回転すると、両方の合計が均等になります。 そのようなドミノが存在しない場合、答えは次のようになります。`-1`。

 ## アルゴリズムのチュートリアル

 1. すべてのドミノを読み、上限の合計と下限の合計を計算します。 
2. 読み取り中に、2 つの値のパリティが異なるドミノが存在するかどうかを確認します。 

このようなドミノは、回転すると両方の合計のパリティが反転するため、特別です。 
3. 両方の合計が偶数の場合、出力`0`。 

目標はすでに満たされているため、ローテーションは必要ありません。 
4. 両方の合計が奇数の場合は、パリティ反転ドミノが存在するかどうかを確認します。 

存在する場合は出力`1`なぜなら、そのようなドミノを 1 つだけ回転させると、両方の合計が均等になるからです。 
5. 両方の合計が奇数であるが、パリティ反転ドミノが存在しない場合、出力`-1`。 

すべての回転でパリティが維持されるため、奇数の合計が偶数になることはありません。 
6. 一方の合計が偶数で、もう一方の合計が奇数の場合、出力`-1`。 

回転すると両方のパリティが同時に変更されるため、不一致は決して消えることはありません。 

### なぜ効果があるのか

 重要な不変条件は、等しいパリティの端を持つドミノを回転すると、どちらの合計のパリティも何も変化しませんが、異なるパリティの端を持つドミノを回転すると、両方の合計のパリティが同時に反転するということです。 

両方の合計は常に同時に変化するため、そこから移動することは不可能です。`(even, odd)`または`(odd, even)`に`(even, even)`。 これらの状態には到達できません。 

両方の合計が奇数の場合、単一のパリティ反転ドミノは直ちに変換します。`(odd, odd)`の中へ`(even, even)`、少なくとも 1 つの変更が必要なため、1 回転は明らかに最小限です。 これにより、考えられるすべてのパリティ状態が網羅されるため、アルゴリズムは正しいです。 

## Python ソリューション```python

すべての入力が処理された後、ソリューションでは 2 つの合計のパリティを検査するだけで済みます。 

分かりやすくするために、チェックの順序が多少重要になります。 すでに有効なケースはすぐに答えが返されるため、最初に処理されます。`0`。 の`(odd, odd)`単一の回転が役立つ唯一の状況であるため、次にケースが続きます。 それ以外はすべて不可能な部類に入ります。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    n = int(input())

    upper_sum = 0
    lower_sum = 0
    has_mixed = False

    for _ in range(n):
        x, y = map(int, input().split())
        upper_sum += x
        lower_sum += y

        if (x & 1) != (y & 1):
            has_mixed = True

    if upper_sum % 2 == 0 and lower_sum % 2 == 0:
        print(0)
    elif upper_sum % 2 == 1 and lower_sum % 2 == 1:
        print(1 if has_mixed else -1)
    else:
        print(-1)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out.strip()

# provided sample
assert run("2\n4 2\n6 4\n") == "0", "sample"

# minimum size, impossible
assert run("1\n1 2\n") == "-1", "single tile"

# one rotation solves it
assert run("2\n1 2\n2 1\n") == "1", "odd odd with mixed parity tile"

# odd odd but no mixed parity domino
assert run("2\n1 1\n3 3\n") == "-1", "cannot change parity"

# larger all-equal case
assert run("5\n2 2\n2 2\n2 2\n2 2\n2 2\n") == "0", "already valid"

# maximum-style repeated pattern
inp = "100\n" + "\n".join(["1 2"] * 100) + "\n"
assert run(inp) == "0", "large input"
```| テスト入力 | 期待される出力 | 検証内容 |

 |`2 / 1 2 / 2 1`|`1`| 1 回の回転で両方の合計が修正されます。 
|`2 / 1 1 / 3 3`|`-1`| パリティ変更ドミノは存在しません |
