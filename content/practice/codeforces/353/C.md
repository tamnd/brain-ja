 ## 問題の理解

 負ではない整数の配列が与えられます`a`長さのある`n`そして数字`m`バイナリ形式で。 からインデックスのサブセットを選択したいと考えています。`0`に`n-1`対応する値を合計します`a[i]`値ですが、ひねりが加えられています。サブセットは、ある整数のバイナリ表現に対応します。`x`(0から`m`) ここで少し`i`1 に設定すると、以下を含むことを意味します`a[i]`合計で。 目標は、この合計を超えずに最大化することです。`m`。 

配列の長さ`n`最大 10^5 までの値を指定できます。`a`最大 10^4 までの大きさになる可能性があります。 これにより、0 から 0 までのすべての数値を明示的にチェックするアプローチは除外されます。`m`なぜなら`m`までの可能性があります`2^n-1`、それは天文学的な大きさです。 どのビットを設定するかを判断するアプローチが必要です`x`数値を列挙するのではなく、直接的に。 

微妙なエッジケースが発生する場合`m`には高いビットが設定されていますが、すべての小さいビットはより大きな合計を生成する可能性があります。 たとえば、次のように考えてみましょう`a = [1, 100]`そして`m = 10`（バイナリ`10`）。 単純に最上位ビットを設定すると合計は 100 になる可能性がありますが、`x = 01`合計は 1 と小さくなります。 アルゴリズムは、ビットごとに反転が有効かどうかを慎重に判断する必要があります。`x`未満`m`そして合計を最大化します。 

## アプローチ

 ブルートフォース手法では、すべての整数を反復処理します。`x`0から`m`、の合計を計算します`a[i]`に設定されたビットについて`x`、最大値を追跡します。 これは小規模な場合に機能します`n`または小さい`m`なぜならコンピューティングだから`f(x)`O(n) ですが、最悪の場合`m`近くにあるかもしれない`2^n`、与える`O(n * 2^n)`操作は完全に不可能です`n`最大 10^5。 

重要な観察は、各ビットを独立して推論できるということです。 少しなら`i`で`m`が 1 の場合、最大値には 2 つのオプションがあります`x`。 1 つのオプションは、これを 0 に設定し、すべての下位ビットを自由に最大化することです (プレフィックスは厳密に よりも小さくなるため)`m`)、もう 1 つは、これを 1 に設定し、プレフィックスとの照合を続行することです。`m`。 ビットイン`m`0であるものは設定できません`x`私たちが滞在したい場合は ≤`m`。 この観察により、問題は、現在のプレフィックスが一致するかどうかを維持しながら、最上位ビットから最下位ビットまでビットごとに貪欲な決定に帰着します。`m`またはすでにそれを下回っています。 

これにより、指数関数的な問題がビット全体にわたる線形スキャンに変換されます。`n`(長さ`a`)、各決定点での単純な合計計算を使用します。 概念的には、最大数 ≤ を構築しています。`m`で与えられる加重合計を最大化するもの`a`。

 ## アルゴリズムのチュートリアル

 1. 配列を読み取る`a`とバイナリ文字列`s`代表する`m`。 変換する`s`整数に`m`必要に応じて。 
2. プレフィックスの合計を事前計算します。`a`逆の順序で、つまり、`suffix_sum[i]`すべての合計を格納します`a[j]`のために`j >= i`。 これにより、現在のビットを 0 に設定した場合、下位ビットの寄与合計の O(1) 計算が可能になります。 
3. 2 つの変数を初期化します。`max_sum`見つかった最良の合計を保存し、`current_sum`のビットを追跡しながら合計を累積します。`m`。 
4. 以下のビットを反復処理します。`m`最も重要なものから最も重要でないものまで:

 1. 現在のビットが`m`は 1 です。これを 0 に設定するとどうなるかを考えてください。プレフィックスは厳密に よりも小さくなります。`m`, したがって、残りの下位ビットはすべて自由に含めることができます。 サフィックス合計配列を使用して残りのビットの合計を計算し、次を加算します。`current_sum`。 アップデート`max_sum`これがもっと大きかったら。 
2. 現在のビットを 1 として追跡する場合、次を追加します。`a[i]`に`current_sum`そして続けます。 ビットが 0 の場合は、加算せずにそのまま続行します。`current_sum`。 
5. ループの後、次の場合の合計を考慮します。`m`その通り （`current_sum`）。 アップデート`max_sum`それが大きい場合。 
6. 印刷`max_sum`。 

機能する理由: アルゴリズムは、次のすべてのプレフィックスを探索します。`x`潜在的にこれよりも小さくなる可能性があります`m`残りのビットの合計を最大化します。 接尾語の合計を使用すると、O(1) の各選択肢を評価できます。 最適な`x`どちらかが一致する必要があります`m`このアプローチでは、明示的に列挙することなく、すべての可能性を考慮します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))
s = input().strip()

m_bits = [int(c) for c in s]
length = len(m_bits)

# pad array to match the bit length if n < length
a = [0]*(length - n) + a

# compute suffix sums for free evaluation of remaining bits
suffix_sum = [0]*(length + 1)
for i in range(length-1, -1, -1):
    suffix_sum[i] = suffix_sum[i+1] + a[i]

max_sum = 0
current_sum = 0

for i in range(length):
    if m_bits[i] == 1:
        candidate = current_sum + suffix_sum[i+1]
        max_sum = max(max_sum, candidate)
    if m_bits[i] == 1:
        current_sum += a[i]

max_sum = max(max_sum, current_sum)
print(max_sum)
```コードはまず、配列の長さを次のバイナリ表現に合わせます。`m`インデックス作成を簡素化します。 サフィックス合計には、現在位置より下のビットの可能な合計合計が格納されます。 ビットを反復するときに、「このビットをオフにする」ことと「このビットをオンのままにする」ことの両方を考慮して、最大合計を更新します。 ループ後は、`current_sum`正確に従うと合計が保持されます`m`、これが最適かもしれません。
