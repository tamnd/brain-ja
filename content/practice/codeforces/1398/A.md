 ## 解決策
 この失敗はアルゴリズムによって引き起こされるものではありません。 これはテスト ハーネスの純粋な構文エラーです。 

トレースバックには次のように書かれています。```
SyntaxError: unterminated string literal
assert run("4\n1
```したがって、渡される文字列は`run()`決して閉じられることはありません。 つまり、この失敗を引き起こしたコードは次のようなものです。```
assert run("4\n1
```次のような適切に閉じられた複数行の文字列の代わりに:```
assert run("4\n1\n8\n...")
```Python は、ファイル自体を解析し、文字列リテラルが不完全であることを検出するため、ロジックが実行される前にこのエラーを発生させます。 

### 具体的に何が間違っていたのか

 バグはテストケースの構築にあります。 

- 文字列内の改行がエスケープされていないか、正しく閉じられていませんでした。 
- 終了引用符がありません。 
- その結果、Python はその後のすべてを処理します。`"4\n1`同じ文字列の一部として EOF まで実行され、失敗します。 

これは 1401C の解決ロジックとは関係ありません。 最小値で割り切れるかどうかをチェックしたり、実現可能性をソートしたりするアルゴリズムが実行された形跡はありません。 

### 正しい修正

 次のことを確認する必要があります。 

- に渡されるすべての文字列`run()`で適切に閉じられています`"`。 
- テストケース内の改行は次のように記述されます。`\n`。 
- 完全な入力が正しくラップされます。 

例えば：```
assert run("4\n1\n8\n") == "YES"
```または完全なサンプルの場合:```

```### 正しい完全なソリューション (アルゴリズムは変更されていません)

 以下は、実際の問題ロジックの正しくクリーンな実装です。 これは、壊れたテスト ハーネスとは無関係です。```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        mn = min(a)
        b = sorted(a)

        ok = True
        for i in range(n):
            if a[i] != b[i] and a[i] % mn != 0:
                ok = False
                break

        print("YES" if ok else "NO")

if __name__ == "__main__":
    solve()
```### このロジックが正しい理由 (簡単な要約)

 最小要素は、再配置のための唯一の「コネクタ」として機能します。 これで割り切れる値は、有効な GCD 条件を含むスワップを通じて到達可能な任意の位置に移動できます。 最小値で割り切れない要素は事実上ロックされます。要素がまだソートされた位置にない場合、要素を修正できる正当なスワップ順序はありません。 

したがって、配置されなかったすべての要素がグローバル最小値で割り切れる場合に、正確に並べ替えが可能になります。 

### 重要なポイント

 ランタイムエラーは純粋に不正な形式のテスト入力文字列が原因であり、不正なアルゴリズムが原因ではありません。 引用符と改行の書式設定を修正すると、エラーはすぐに解消されます。
