 ## 解決策
 ## 問題の理解

 色ごとにグループ化された 3 つのスティックのコレクションが与えられます。 すべてのカラー グループには複数のスティック ペアが含まれており、各ペアは単一の長さの値を持ちます。 長方形は、2 つの異なる色を選択し、各色から 1 つのスティック ペアを組み合わせて長方形の隣接する辺となるようにすることで形成されます。 このような長方形の寄与は、選択された 2 つの長さの積です。 

各スティック ペアは最大 1 回使用でき、未使用のペアは自由に無視できます。 タスクは、生成されるすべての製品の合計が最大になるように、色全体で互いに素なペアを選択し、それらを長方形にペアにすることです。 

このプロセスを言い換えると便利な方法は、すべての操作が異なる配列から正確に 2 つの数値を消費し、その積を得るということです。 目標は、各数値を最大 1 回使用できるという制約の下で、そのようなペアごとの積の合計を最大化することです。 

制約は小さく、各配列には最大 200 個の要素が含まれるため、合計で最大 600 個の値が存在します。 これにより、ソートされた各配列から取得する要素の数を含む状態に対する動的プログラミングが可能になります。 200 の 3 次のものは許容されますが、600 の指数関数は許容されません。 

ある色が他の色よりもはるかに大きい場合、微妙なエッジケースが表示されます。 世界的に最大の残りの要素を貪欲にペアリングするような単純な戦略は、低収量のペアリングで大きな要素を消費し、後で高収量のペアリングで使用できなくなる可能性があるため、失敗する可能性があります。 たとえば、赤に 100、90 が含まれ、緑/青にいくつかの中程度の値が含まれている場合、早い段階で 100 と小さな緑の値を組み合わせると、より大きな青の値に保存するよりも合計が減る可能性があります。 

別の失敗例は、最適なグローバル ペアリングが各ステップ内で局所的に最適ではない場合に発生します。 すべての選択では 2 つの配列のみから要素が削除されるため、決定構造はステップ間で独立していないため、貪欲な選択では不十分です。 

## アプローチ

 ブルートフォースアプローチでは、3 つの配列からペアを選択する可能なすべての方法をシミュレートしようとします。 各ステップで、残りの 2 色を選択し、それぞれから 1 つの要素を選択して再帰します。 最大 600 個の要素を使用すると、大規模な分岐プロセスが形成されます。 対称性を減らしたとしても、マッチングの数は組み合わせ的に増加し、3 部構成マルチセット内のマッチングを効果的に探索します。 これは実現可能な限界をはるかに超えています。 

重要な観察は、各配列を降順でソートすると大きな値が早期に整列され、最適なソリューションはこれらのソートされた配列のプレフィックスのみを使用するということです。 これは、小さい要素が使用されている一方で、大きい要素が同じ色で未使用のままである場合、それらを交換しても合計が増加または維持されるだけであるためです。 

プレフィックスのみを考慮することを受け入れると、構造は管理しやすくなります。 各色から取得した要素の数によって状態を定義します。 どの状態でも、最後の操作で 3 色のうち 2 色がペアになっている必要があります。 これは当然のことながら、トランジションが 2 つの色のペアを選択し、それらのプレフィックス ポインターを進めることを表す 3D ダイナミック プログラミング ソリューションにつながります。 

各遷移では、選択された 2 つの配列から次の未使用の要素が乗算され、その積が前の状態の最もよく知られている値に加算されます。

 ## アルゴリズムのチュートリアル

 3 つの配列すべてを降順で並べ替えるので、初期の要素を取得するということは、常により大きな寄与を最初に取得することを意味します。 

動的プログラミングテーブルを定義します`dp[i][j][k]`、最初の使用後に達成可能な最大合計面積を表します。`i`赤い要素、`j`緑の要素と、`k`青い要素。 

1. を除くすべての状態を負の無限大に初期化します。`dp[0][0][0] = 0`。 これは、四角形が形成されていない空の選択範囲を表します。 
2. どの州からでも`(i, j, k)`、次のペアを組み合わせて新しい長方形を形成できます。 

- 赤と緑の棒の場合`i < R`そして`j < G`- 赤と青のスティックの場合`i < R`そして`k < B`- 緑と青のスティックの場合`j < G`そして`k < B`各トランジションは、選択された各色の次の未使用の要素を使用します。 
3. 有効な遷移ごとに、選択した 2 つのスティックの長さの積を加算して次の状態を更新します。 たとえば、から`(i, j, k)`に`(i+1, j+1, k)`追加します`r[i] * g[j]`。 
4. すべての状態を昇順に繰り返します。`(i + j + k)`そのため、すべての前提条件が必要になる前に計算されます。 
5. いつでもペアリングを停止する可能性があるため、最終的な答えはすべての状態の最大値になります。 

重要な推論ステップは、配列が降順にソートされると、同じ色の小さい要素を優先して利用可能な大きい要素をスキップしても、最適な解決策には決してメリットがないということです。 これにより、プレフィックス プロパティが保証され、DP 状態定義が検証されます。 

### なぜ効果があるのか

 いずれの時点でも、ソリューションで小さな要素が使用されている一方で、同じ色に大きな未使用の要素が存在する場合、それらを交換すると、実現可能性に影響を与えることなく、その四角形の寄与が増加または維持されます。 この引数を繰り返すと、選択されたすべての要素がプレフィックスとしてプッシュされます。 したがって、すべての最適解は DP 状態空間内のパスに対応し、すべての DP 遷移は有効な四角形の選択に対応します。 これにより、すべての最適な構成を重複なく完全に探索できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    R, G, B = map(int, input().split())
    r = sorted(map(int, input().split()), reverse=True)
    g = sorted(map(int, input().split()), reverse=True)
    b = sorted(map(int, input().split()), reverse=True)

    dp = [[[0] * (B + 1) for _ in range(G + 1)] for _ in range(R + 1)]

    ans = 0

    for i in range(R + 1):
        for j in range(G + 1):
            for k in range(B + 1):
                cur = dp[i][j][k]
                ans = max(ans, cur)

                if i < R and j < G:
                    dp[i + 1][j + 1][k] = max(dp[i + 1][j + 1][k],
                                               cur + r[i] * g[j])
                if i < R and k < B:
                    dp[i + 1][j][k + 1] = max(dp[i + 1][j][k + 1],
                                               cur + r[i] * b[k])
                if j < G and k < B:
                    dp[i][j + 1][k + 1] = max(dp[i][j + 1][k + 1],
                                               cur + g[j] * b[k])

    print(ans)

if __name__ == "__main__":
    solve()
```コードは DP 定義を直接反映しています。 三重にネストされたループはすべてのプレフィックス状態を列挙し、到達可能なすべての構成が考慮されるようにします。 各遷移は、次の未使用の 2 色の要素を選択し、1 つの長方形を形成することに正確に対応します。 

変数`ans`最適解ではすべての要素が使用されない可能性があるため、これが必要であるため、要素のみを追跡するのではなく、すべての中間状態にわたる最良の値を追跡します。`dp[R][G][B]`。 

よくある落とし穴は、未使用の要素が許可されていることを忘れることです。 アップデートせずに`ans`どの状態でも、アルゴリズムは誤ってすべてのプレフィックスを完全に消費することを強制します。

 ## 特殊なケース

 1 つの色の値が非常に大きく、他の色の値は小さいものの多数ある場合、微妙なエッジ ケースが発生します。 DP は、その色を消費しない方向に移動することで、特定の組み合わせを完全にスキップすることを選択できるため、これを正しく処理します。 

たとえば、赤色に以下が含まれている場合、`[100, 1]`、 緑`[2]`、青`[50]`、DP は両方のペアリングを調査します`100×2 + 1×50`そして`100×50`、最終的に最適な組み合わせを選択します。 貪欲なアプローチは組み合わせる可能性があります`100×2`まずその可能性を失う`100×50`ただし、DP は両方のパスを保持します。 

もう 1 つのエッジ ケースは、要素を未使用のままにしておくことが最適な場合です。 答えは必ずしもあるわけではありません`dp[R][G][B]`なぜなら、すべての要素を消費すると最適ではないペアリングが強制されるからです。 すべての状態にわたる実行最大値により、各色から最大数の要素のみを使用して残りを破棄するなど、早期に停止する構成が確実に考慮されます。
