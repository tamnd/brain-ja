 ## 解決策
 ## 問題の理解

 同じサイズの整数の 2 つのコレクションが与えられています。 これらをトークンの入った 2 つの袋と考えてください。順序は重要ではありませんが、多重度は重要です。 目標は、2 番目のバッグの要素に個別に適用される操作を使用して、2 番目のバッグを最初のバッグに変換できるかどうかを判断することです。 

2 番目のバッグの各要素は、2 つの方法で繰り返し変更できます。2 倍にすることも、半分の整数に置き換えることもできます。 これらの操作を繰り返すと、任意の開始番号から到達可能な値のセットが作成されます。 タスクは、2 番目のマルチセットの各要素に対してそのような操作のシーケンスを選択した後、両方のマルチセットを同一にすることができるかどうかを判断することです。 

重要な問題は、変換が対称的ではなく、きれいな方法で元に戻せないことです。 2 分の 1 にすると構造が壊れる丸めが導入され、2 倍にすると値が際限なく拡張されます。 多くの要素間の相互作用により、明示的な変換ではなく標準的な形式について推論する必要があります。 

この制約により、すべてのテスト ケースで最大 200,000 個の数値 (最大 10^9) の数値が許可されます。 値ごとに変換をシミュレートしたり、変換グラフを調べたりしようとするソリューションは失敗します。単一の数値が 2 倍と 2 分の 1 を繰り返すことで長いチェーンを生成する可能性があり、これをすべての要素に対して個別に実行すると、2 次またはさらに悪い動作が発生するためです。 

素朴な考え方による微妙な失敗例は、各値を貪欲に一致させることができると仮定することです。`a`何らかの価値がある`b`そしてローカルで修正します。 たとえば、一致させようとすると、`a = [8]`そして`b = [3]`、3 を 2 倍にすることで 8 に到達できると考えるかもしれませんが、他の数値の残りの構造がマルチセット内で一貫性を保っていることも確認する必要があり、これにより貪欲なマッチングが妨げられます。 

もう 1 つの誤解を招くシナリオは、半分にすることで生じます。7 のような数値は 3 になり、その後 1 になる可能性がありますが、これらの中間値が他の必要なターゲットの一致を妨げる可能性があります。 値がどのように「吸収」されるかを制御しない、単純で貪欲な割り当ては、矛盾にはまってしまいます。 

問題は基本的にそれぞれの割り当てにあります`b`ある目標に対する価値`a`すべての割り当てにわたる一貫性を確保しながら、構造化された変換スペースを通じて。 

## アプローチ

 単一の値に注目すると、`b`、0 になるまで半分にし、2 倍にすることを繰り返すことで、到達可能なすべての値を調べることができます。 これにより、可能性のツリー状構造が形成されます。 ブルートフォースアプローチでは、各要素に対して、`b`、それをある要素と一致させようとします。`a`すべての変換を調べて、使用されている要素をマークすることによって。 これは、実際にはすぐに指数関数的になります。各数値が log(最大値) に比例した長さのチェーンを生成する可能性があるためです。それでもすべての要素にわたる割り当てを考慮する必要があり、これらのチェーンにわたる階乗一致が効果的に行われます。 

重要な観察は、変換グラフが強力な構造を持っているということです。つまり、すべての数値は半減を繰り返すことで最終的には 0 に崩壊し、すべての数値は半減の下で固有の祖先チェーンを持ちます。 これは、前向きに考えるのではなく（から`b`に`a`）、「安定候補」になるまで半分にすることを繰り返して値を正規化し、多重度を制御する必要があります。 

プロセスを解釈する便利な方法は、次のとおりです。`b`多くのより小さな値に減らすことができますが、減少は単調であり、常に終了します。 可能性を広げるのではなく、数値を繰り返し圧縮していきます。`b`ターゲットに一致するまで下向きに`a`または無効になります。 順序付けを導入すると、常に大きな数値を最初に優先することができます。これは、値が大きいほど、大きなターゲットに一致する有効なリダクションが少なくなるためです。 

これは貪欲な戦略につながります。両方の配列をソートし、最大から最小まで一致させ、継続的に配列を減らします。`b`値が一致するか使用できなくなるまで。 一致するものが存在する場合は、それを消費します。 そうでなければ失敗します。

 ## アルゴリズムのチュートリアル

 1. 両方のマルチセットをソートする`a`そして`b`降順で。 これにより、必要な最大値は小さい数値から構築するのが最も難しいため、常に最初に必要な値を満たすように努めます。 
2. 値のマルチセット構造 (概念的には周波数マップまたはカウンター) を維持します。`b`。 これにより、一致した要素を効率的に削除できます。 
3. 各値を反復処理します。`x`で`a`最大から最小まで。 各ステップで、適切な値を見つけようとします。`b`それは正確に減らすことができます`x`。 
4. 残りの最大値が`b`まさに`x`、直接一致させて削除します。 
5. それ以外の場合、次の最大値が`b`より大きい`x`、以下になるまで繰り返し半分にします。`x`。 大きさを減らす操作は半分にすることだけであり、過剰な値は一致させる前に減らす必要があるため、この手順は正当化されます。 
6. 半分にした後、値がちょうどになった場合`x`、一致して削除します。 それより小さくなってしまうと、`x`、 これ`b`要素は貢献できない`x`なので、それを破棄し、次の候補を試します。`b`。 
7. いかなる時点でも有効な情報が見つからない場合は、`b`一部の人にとっての要素`x`、マッチングは不可能であると即座に結論付けます。 

### なぜ効果があるのか

 降順で処理することで、`b`大きな目標に対して価値を与える`a[i]`、後でそれが必要になることはありません`b`より大きな要件を満たすための値。 半分にするプロセスでは、単調減少パスが保存されます。`b`値には、下方向に到達可能な状態の決定的なシーケンスがあります。 私たちは常に利用可能な最大のものを消費するため、`b`まず、要素が大きくなる状況を避けます。`b`別の大きな値に必要な中間値を超えて時期尚早に減少する`a`。 この貪欲な安定性により、マルチセット全体にわたってマッチングの一貫性が保たれます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        
        a.sort(reverse=True)
        b.sort(reverse=True)
        
        i = 0
        
        for x in a:
            if i >= n:
                break
            
            while i < n and b[i] > x:
                b[i] //= 2
                if b[i] == 0:
                    i += 1
            
            if i < n and b[i] == x:
                i += 1
            else:
                print("NO")
                break
        else:
            print("YES")

if __name__ == "__main__":
    solve()
```この実装は貪欲なプロセスを直接反映しています。 両方の配列をソートすると、常に最大のターゲットを最初に満たそうとすることが保証されます。 ポインタ`i`現在の候補者を追跡します`b`。 値が大きすぎる場合、値が一致するか使用できなくなるまで、その値は繰り返し半分にされます。 一致が発生すると、それを消費して先に進みます。 

微妙な点は、減らされた値をヒープや構造に押し戻すことは決してないということです。 これは安全です。`b`単一の変換パスを下方向にたどります。 新たな候補として再検討する必要はありません。 単調ポインタにより線形処理が保証されます。

 ## 特殊なケース

 主なエッジケースは、複数の大きな値が含まれる場合です。`b`中間の一致を破壊することなく慎重に減らす必要があります。 たとえば、次の場合`a = [8, 8]`そして`b = [1, 16]`、ナイーブな貪欲さは減らすかもしれません`16`気づく前に間違って使用すると、結果が生じる可能性があります`8`ただし、適切な降順処理により、`16 → 8`最初に消費され、残ります`1`無関係であること。 

もう 1 つのケースは、半減を繰り返すと有効な値がスキップされる場合です。 のために`a = [3]`そして`b = [7]`、 我々は持っています`7 → 3 → 1`。 早めにやめたら`1`または中間体の取り扱いを誤る`3`、有効な一致を誤って拒否する可能性があります。 このアルゴリズムは、ターゲットを通過するかターゲットに正確に到達するまで継続的に半分にし、有効な中間がスキップされないようにすることでこれを回避します。
