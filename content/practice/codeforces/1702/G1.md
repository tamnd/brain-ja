 ## 解決策
 ## 問題の理解

 ツリーといくつかのクエリが与えられています。 各クエリは頂点のセットを指定します。 すべてのクエリについて、選択したすべての頂点がツリーの単一の単純なパス上に存在できるかどうかを判断する必要があります。 

ツリーには、任意の 2 つの頂点間の単純なパスが 1 つだけ含まれます。 クエリされたすべての頂点がそのパスに属するような単純なパスが存在する場合、クエリは合格であるとみなされます。 パスには、クエリの一部ではなかった追加の頂点を含めることができます。 

ツリーには以下が含まれます$2 \cdot 10^5$頂点の数は最大ですが、すべてのクエリにわたるクエリされた頂点の合計数も最大です。$2 \cdot 10^5$。 これにより、クエリされた頂点のペアごとにパス全体を繰り返したどるアプローチは即座に除外されます。 アン$O(n)$クエリされた頂点ごとの操作はすでにコストが高くなりすぎます。 ツリー上で前処理を行ってから、各クエリのサイズに応じてほぼ線形の作業を行う必要があります。 

誤解されやすい状況がいくつかあります。 

星型のツリーを考えてみましょう。```
    2
    |
3 - 1 - 4
    |
    5
```クエリ:```
{2,3,4}
```答えは`NO`。 

クエリされた頂点の各ペアにはそれらの間にパスがありますが、3 つの葉すべてを含む単一の単純なパスは存在しません。 2 つの葉の間のパスはすべて中心を通過し、それらの 2 つの葉にのみ到達します。 

別の例:```
1 - 2 - 3 - 4 - 5
```クエリ:```
{2,4}
```答えは`YES`。 

パスは、クエリされた頂点で開始または終了する必要はありません。 1 から 5 までのパスには 2 と 4 の両方が含まれています。 

より微妙なケース:```
    2
    |
1 - 3 - 4 - 5
```クエリ:```
{1,2,5}
```答えは`YES`。 

1 から 5 までのパスは頂点 3 を通過しますが、頂点 2 は通過しません。クエリされたすべての頂点を含む実際のパスは 2-3-4-5 で、これには 1? も含まれます。 いいえ、答えは実際には次のとおりです。`NO`。 これは、ペアごとの距離またはペアごとの接続性だけをチェックするだけでは不十分である理由を示しています。 クエリされたすべての頂点が 1 つの共通パスに属していることを確認する必要があります。 

## アプローチ

 ブルートフォースのアイデアは、クエリされた頂点のすべてのペアを、目的のパスの可能な端点として試してみることです。 各ペアについて、パスを構築し、クエリされたすべての頂点がその上にあるかどうかを確認します。 

ツリーの頂点$x$の間の道にあります$a$そして$b$まさにいつ$$dist(a,x)+dist(x,b)=dist(a,b).$$したがって、すべてのエンドポイントのペアをテストし、クエリされたすべての頂点を検証できます。 

これは正しいですが、遅すぎます。 クエリに次の内容が含まれる場合、$k$頂点、あります$O(k^2)$エンドポイントのペア、および各ペアのチェックが必要$k$頂点。 それは、$O(k^3)$。 と$k$到達$2 \cdot 10^5$、これは絶望的です。 

重要な観察は木の幾何学から得られます。 

クエリされたすべての頂点が 1 つの単純なパス上にあると仮定します。 次に、それらの頂点の中には、そのパスの両端である 2 つの頂点が存在する必要があります。 クエリされた他のすべての頂点は、これら 2 つの極端な点を結ぶ固有のパス上にあります。 

したがって、すべてのエンドポイント ペアを試す代わりに、極端になる可能性のある 1 つの候補ペアを見つけるだけで済みます。 

標準的なツリーのトリックは、クエリされた頂点を選択すると、$s$、次にクエリされた頂点から最も遠いもの$s$は、クエリされたセットの直径の 1 つの端点です。 次に、そのエンドポイントから開始して、クエリされた最も遠い頂点を再度見つけると、もう一方のエンドポイントを取得します。 

これらの頂点を呼び出します$a$そして$b$。 

クエリされた頂点が実際に 1 つのパス上にある場合、クエリされたすべての頂点はそのパスに属している必要があります。$a \leftrightarrow b$。 逆に、クエリされたすべての頂点がそのパスに属している場合、そのセットは合格です。 

残りのタスクは、効率的な距離の計算です。 DFS とバイナリ リフティングを使用してツリーを前処理します。 そうすれば、すべての距離クエリに次のように答えることができます。$O(\log n)$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(k^3)$クエリごと |$O(1)$| 遅すぎる |
 | 最適 |$O(n\log n + k\log n)$合計 |$O(n\log n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 ### 前処理

 ツリーを構築し、ルートから DFS を実行します。 

すべての頂点の深さとそのバイナリリフティング祖先を保存します。 これにより、最小共通祖先クエリが可能になります。$O(\log n)$。 

LCA を使用して、次のように距離を計算します。$$dist(u,v)=depth[u]+depth[v]-2\cdot depth[lca(u,v)].$$### クエリ処理

 1. クエリされた任意の頂点を開始頂点として取得します。$s$。 
2. からの距離を計算します。$s$to every queried vertex and find the farthest one. 電話してください$a$。 

クエリされた頂点がパス上にある場合、そのスパンの 1 つの端点は、選択した頂点から最も遠くにある必要があります。 
3. からの距離を計算します。$a$クエリされたすべての頂点を検索し、最も遠い頂点を見つけます。 電話してください$b$。 

ペア$(a,b)$は、クエリされた頂点の直径です。 
4. クエリされた頂点ごとに$v$、どうかを確認してください$$dist(a,v)+dist(v,b)=dist(a,b).$$5. クエリされたすべての頂点に対して等式が成立する場合、出力`YES`。 
6. それ以外の場合は出力`NO`。 

### なぜ効果があるのか

 しましょう$a$そして$b$は、クエリされた頂点間の直径の端点になります。 

クエリされたすべての頂点が 1 つのパス上にある場合、そのパスには両方の直径の端点が含まれている必要があります。 クエリされたすべての頂点はそれらの間にあるため、すべての頂点に対して距離の等しいことが当てはまります。 

逆の方向では、クエリされたすべての頂点が次の条件を満たすと仮定します。$$dist(a,v)+dist(v,b)=dist(a,b).$$ツリーでは、この条件はまさに次の場合に当てはまります。$v$～からのユニークなパス上にあります$a$に$b$。 したがって、クエリされたすべての頂点は同じ単純なパスに属します。$a \leftrightarrow b$。 セットはまずまずです。 

アルゴリズムは、合格可能なセットを正確に受け入れます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())

g = [[] for _ in range(n + 1)]

for _ in range(n - 1):
    u, v = map(int, input().split())
    g[u].append(v)
    g[v].append(u)

LOG = (n + 1).bit_length()

up = [[0] * (n + 1) for _ in range(LOG)]
depth = [0] * (n + 1)

stack = [(1, 0)]

while stack:
    v, p = stack.pop()
    up[0][v] = p

    for to in g[v]:
        if to == p:
            continue
        depth[to] = depth[v] + 1
        stack.append((to, v))

for j in range(1, LOG):
    prev = up[j - 1]
    cur = up[j]
    for v in range(1, n + 1):
        cur[v] = prev[prev[v]]

def lca(a, b):
    if depth[a] < depth[b]:
        a, b = b, a

    diff = depth[a] - depth[b]

    bit = 0
    while diff:
        if diff & 1:
            a = up[bit][a]
        diff >>= 1
        bit += 1

    if a == b:
        return a

    for j in range(LOG - 1, -1, -1):
        if up[j][a] != up[j][b]:
            a = up[j][a]
            b = up[j][b]

    return up[0][a]

def dist(a, b):
    c = lca(a, b)
    return depth[a] + depth[b] - 2 * depth[c]

q = int(input())

ans = []

for _ in range(q):
    k = int(input())
    nodes = list(map(int, input().split()))

    start = nodes[0]

    a = start
    best = -1

    for v in nodes:
        d = dist(start, v)
        if d > best:
            best = d
            a = v

    b = a
    best = -1

    for v in nodes:
        d = dist(a, v)
        if d > best:
            best = d
            b = v

    diameter = dist(a, b)

    ok = True

    for v in nodes:
        if dist(a, v) + dist(v, b) != diameter:
            ok = False
            break

    ans.append("YES" if ok else "NO")

sys.stdout.write("\n".join(ans))
```前処理後、すべての距離クエリで必要な LCA 計算は 1 回だけです。 各クエリについて、直径の端点を見つけるために 2 回のスキャンを実行し、検証のために 1 回の最終スキャンを実行します。 

DFS は、ツリー上の Python 再帰の深さの問題を回避するために反復的に実装されます。$2 \cdot 10^5$頂点。 

よくある間違いは、ツリー全体の直径の端点が重要であると想定することです。 クエリされた頂点の直径のみを考慮します。 2 つの最遠点検索は、クエリに表示される頂点に対してのみ実行されます。 

もう 1 つの微妙な点は、パス メンバーシップ テストです。 頂点が直径パスに近いことを確認するだけでは十分ではありません。 正確な平等$$dist(a,v)+dist(v,b)=dist(a,b)$$保持しなければなりません。

# helper: run solution on input string, return output string
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    n = int(input())
    g = [[] for _ in range(n + 1)]

    for _ in range(n - 1):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)

    LOG = (n + 1).bit_length()

    up = [[0] * (n + 1) for _ in range(LOG)]
    depth = [0] * (n + 1)

    stack = [(1, 0)]

    while stack:
        v, p = stack.pop()
        up[0][v] = p

        for to in g[v]:
            if to != p:
                depth[to] = depth[v] + 1
                stack.append((to, v))

    for j in range(1, LOG):
        for v in range(1, n + 1):
            up[j][v] = up[j - 1][up[j - 1][v]]

    def lca(a, b):
        if depth[a] < depth[b]:
            a, b = b, a

        diff = depth[a] - depth[b]

        bit = 0
        while diff:
            if diff & 1:
                a = up[bit][a]
            diff >>= 1
            bit += 1

        if a == b:
            return a

        for j in range(LOG - 1, -1, -1):
            if up[j][a] != up[j][b]:
                a = up[j][a]
                b = up[j][b]

        return up[0][a]

    def dist(a, b):
        c = lca(a, b)
        return depth[a] + depth[b] - 2 * depth[c]

    q = int(input())
    out = []

    for _ in range(q):
        k = int(input())
        nodes = list(map(int, input().split()))

        start = nodes[0]

        a = max(nodes, key=lambda x: dist(start, x))
        b = max(nodes, key=lambda x: dist(a, x))

        dab = dist(a, b)

        ok = all(dist(a, v) + dist(v, b) == dab for v in nodes)

        out.append("YES" if ok else "NO")

    return "\n".join(out)
