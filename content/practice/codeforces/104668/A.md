 ## 解決策
 ## 問題の理解

 小文字のみで構成されるターゲット文字列と、新聞から入手可能な複数の「単語」セットが与えられます。 各単語は何度でも使用でき、それを使用するたびに、ターゲットの連続した部分文字列が効果的に「カバー」されます。 重複する文字が正確に一致する限り、単語は重複することが許可されます。そのため、実際には、選択した複数の単語がカバーするすべての位置が一致する限り、文字列上に配置できます。 

目標は、使用する単語の数を最小限に抑えながら、これらの単語のコピーを使用してターゲット文字列全体をカバーすることです。 ターゲットのすべての位置を完全にカバーする方法がない場合は、失敗を報告する必要があります。 

制約構造は大きく、ターゲット長とすべての語長の合計は両方とも最大 3 · 10^5 です。 これにより、すべての位置ですべての単語を繰り返し試行するアプローチや、各位置ですべての単語を単純にスキャンする動的プログラミングは直ちに除外されます。 文字列の長さまたは辞書の合計サイズが 2 次のものはすべてタイムアウトになります。 

微妙な難点はオーバーラップです。 各位置で一致する最長単語を単純に貪欲に配置すると、局所的に最適な配置がより適切なグローバルな組み合わせをブロックする可能性があるため、失敗する可能性があります。 

たとえば、ターゲット「aaaaa」と単語「aaa」と「aa」について考えてみましょう。 常に左端のカバーされていない位置から始まる最長の一致を選択する場合は、最初に「aaa」を選択し、「aa」を残すことになりますが、より複雑なミックスでは、解決策が存在する場合でも、貪欲な選択は行き止まりにつながる可能性があります。 

もう 1 つの特殊なケースは、到達不能な文字です。 ある文字がどの単語にも出現しない場合、または単語がその位置で開始できない場合、その位置をカバーすることが不可能になり、出力は強制的に -1 になります。 

## アプローチ

 総当たりの定式化は、最短のカバー問題としては自然です。 状態を最も古い未発見のインデックスとして定義し、そのインデックスから、再帰的に、または動的プログラミングを介して、そこから開始して一致するすべての単語を試し、1 つの単語を取り出して前にジャンプします。 これにより、各位置が、一致する単語を配置することによって到達した位置への出力エッジを持つグラフが生成されます。 

すべての位置についてすべての単語を試して一致を確認する可能性があるため、単純に遷移を構築すると、最悪の場合 O(L · n) のコストがかかります。 合計ワード長が最大 3 · 10^5 になると、これは非常に遅くなり、文字列の繰り返しスキャンが実行時間の大半を占めます。 

重要な観察は、すべての遷移がターゲット内の位置で一致するプレフィックスに依存しているということです。 すべての位置ですべての単語をチェックする代わりに、辞書に対してパターン マッチング オートマトンを構築することができます。これにより、ターゲットを 1 回スキャンして、各位置でどの辞書の単語がそこで終わり、どこで始まるかを知ることができます。 これはまさに複数パターンのマッチング問題です。 

Aho-Corasick オートマトンを使用して、すべての単語を失敗リンクのあるトライに変換します。 次に、ターゲット文字列を 1 回ストリーミングします。 私たちが位置 i にいるときはいつでも、オートマトンは i で終わるすべての単語とその長さを教えてくれます。 このような各単語は、位置を越えた DP 内の i − len + 1 から i + 1 への遷移に対応します。 

次に、問題は、位置 0 から n にわたる DAG のような構造上の最短経路に帰着します。ここで、各単語の出現は、重み 1 を持つ始点から終点までのエッジです。位置 n に到達するエッジの最小数を計算します。 

これにより、単語を繰り返しチェックするという問題が、単一の線形スキャンと線形数の遷移に軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 位置 × 単語に対する総当たり DP | O(nL) 最悪の場合 | O(n) | 遅すぎる |
 | アホコラシック + DP 最短パス | O(n + 合計ワード長 + 遷移) | O(n + 合計単語長) | 承認済み |

 ## アルゴリズムのチュートリアル

 マルチパターン マッチング構造を構築し、それを使用して部分文字列の一致を DP 遷移に変換します。

1. すべての辞書単語をトライに挿入し、各終端ノードにそこで終わる単語の長さを格納します。 これにより、後でノードに到達したときにどの単語が一致したかを正確に知ることができます。 
2. BFS を使用してトライの障害リンクを構築します。 各ノードの障害リンクは、トライ内のプレフィックスでもある最長の適切なサフィックスを指します。 また、出力リストを障害リンクに沿って伝播し、すべてのノードがそのノードまたは接尾辞の状態で終わるすべての単語を認識できるようにします。 これにより、ある状態に到達したときに、失敗遷移によって間接的に終了する一致を見逃すことがなくなります。 
3. DP 配列を初期化します。ここで、dp[i] は、長さ i のプレフィックスをカバーするのに必要な最小ワード数を表します。 dp[0] = 0 に設定し、他のすべての値を無限大に設定します。 
4. 現在のオートマトンの状態を維持しながら、ターゲット文字列を左から右にトラバースします。 文字ごとに、有効な遷移が見つかるまで、失敗リンクを使用してトライを遷移します。 
5. 位置 i で、オートマトンの状態を更新した後、この状態で終わるすべての単語を反復処理します。 長さ len の各単語について、i − len + 1 から i + 1 への候補遷移を計算し、dp[i + 1] = min(dp[i + 1], dp[i − len + 1] + 1) を緩和します。 これは、その単語を i までの最後のセグメントとして使用することを表します。 
6. すべての位置を処理すると、答えは dp[n] になります。 dp[n] がまだ無限大の場合は、-1 を出力します。 

### なぜ効果があるのか

 オートマトンは、辞書に出現するすべての単語が、その終了位置が処理されるときに正確に検出されることを保証します。 単語の有効な配置はそれぞれ 1 つの DP 遷移に対応し、文字列の有効なカバーはすべてそのような配置のシーケンスに対応します。 DP は各プレフィックスに到達するために必要な最小数のセグメントを保存し、すべての遷移が正当​​な配置に対応するため、再帰によって単語への最適な分解がキャプチャされます。 複数のトランジションが同じ位置で終了する可能性があり、DP が常に最良のトランジションを維持するため、オーバーラップは自然に処理されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**18

class Node:
    __slots__ = ("next", "link", "out")
    def __init__(self):
        self.next = {}
        self.link = 0
        self.out = []

def build_aho(words):
    trie = [Node()]

    # build trie
    for w in words:
        v = 0
        for ch in w:
            if ch not in trie[v].next:
                trie[v].next[ch] = len(trie)
                trie.append(Node())
            v = trie[v].next[ch]
        trie[v].out.append(len(w))

    # build failure links
    from collections import deque
    q = deque()

    for c, v in trie[0].next.items():
        trie[v].link = 0
        q.append(v)

    while q:
        v = q.popleft()
        for c, u in trie[v].next.items():
            q.append(u)

            j = trie[v].link
            while j and c not in trie[j].next:
                j = trie[j].link
            trie[u].link = trie[j].next[c] if c in trie[j].next else 0

            trie[u].out.extend(trie[trie[u].link].out)

    return trie

def solve():
    L = int(input())
    s = input().strip()
    n = len(s)

    words = [input().strip() for _ in range(L)]

    trie = build_aho(words)

    dp = [INF] * (n + 1)
    dp[0] = 0

    v = 0

    for i, ch in enumerate(s):
        while v and ch not in trie[v].next:
            v = trie[v].link
        if ch in trie[v].next:
            v = trie[v].next[ch]
        else:
            v = 0

        for length in trie[v].out:
            start = i - length + 1
            if start >= 0 and dp[start] + 1 < dp[i + 1]:
                dp[i + 1] = dp[start] + 1

    print(-1 if dp[n] == INF else dp[n])

if __name__ == "__main__":
    solve()
```トライにはすべての辞書単語が格納され、各終端ノードはそこで終わる単語の長さを記録します。 BFS の構築中、障害リンクにより、ノードに到達したときに、任意のサフィックス状態で終了する一致にもアクセスできることが保証されるため、オカレンスが失われることはありません。 

DP 配列は、プレフィックス位置にわたる標準の最短パスです。 i で終わる単語を見つけるたびに、その長さから導出された開始位置を使用して dp[i + 1] を更新します。 重要な実装の詳細は、開始インデックスではなくプレフィックス エンドポイントによって dp を維持することです。これにより、遷移がクリーンに保たれ、配置の重複による曖昧さが回避されます。 

オートマトン ポインタ v は文字列のスキャン中に段階的に更新されるため、テキストに対する線形の処理時間が保証されます。

 ## 特殊なケース

 失敗モードの 1 つは、貪欲な配置が機能すると想定していることです。 「aaa」と「aa」という単語を含む「aaaaa」のような入力の場合、貪欲に最初に「aaa」を取得すると、より複雑なバリアントでの最適なセグメンテーションがブロックされる可能性があります。 DP 定式化では、各位置で終わるすべての有効な一致を評価することでこれを回避します。 

もう 1 つのエッジ ケースは、オートマトン内の失敗リンクを介してのみ接尾辞と一致する単語です。 障害リンクを介して出力を伝播しないと、一致が失われ、DP は起こり得る遷移を過小評価することになります。 BFS 構造により、これらの接尾辞の一致が確実に含まれます。 

3 番目のエッジ ケースは、単語が終了しない位置です。 その場合、dp[i] は到達不可能なままであり、完全なカバレッジが存在しないため、最終的な答えは正しく -1 になります。
