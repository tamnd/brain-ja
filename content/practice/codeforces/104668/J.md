 ## 解決策
 ## 問題の理解

 文字の長方形グリッドが与えられます。 「トリニティ」は、最初にこのグリッドの任意の正方形サブ領域を選択し、次にその正方形内の、正方形の対角線の片側上または厳密に片側にあるすべてのセルを選択することによって形成されます。 対角線は主対角線または反対角線のいずれかになります。 このフィルタリングの後、結果として得られる三角形領域を保持します。 その領域内のすべてのセルに同じ文字が含まれており、その領域に少なくとも 3 つのセルが含まれている場合、それは 1 つの有効なトリニティとしてカウントされます。 

タスクは、考えられるすべての正方形のサブグリッドにわたって、両方の対角方向にわたって、そのような有効な三角形領域がいくつ存在するかを数えることです。 

グリッド サイズは 1000 x 1000 まで大きくすることができ、これは最大 100 万個のセルを意味します。 すべての正方形のサブ領域を試す単純なアプローチでは、次のような作業が必要になります。$O(n^3)$またはさらに悪いことに正方形の組み合わせがあり、それぞれを明示的にチェックすると遅すぎて、潜在的に超過する可能性があります。$10^{12}$操作。 これは、すべての正方形を直接列挙することはできず、代わりに、より集計された方法で寄与をカウントする必要があることを直ちに示唆しています。 

この定義の微妙な点は、異なる正方形がグリッド内で同一の幾何学的な三角形を生成する可能性がありますが、異なる正方形の選択から生じた場合でも、それらは別個のものであると見なされるということです。 したがって、ユニークな形状ではなく、構成をカウントしています。 

エッジケースは、平方が最小の場合に発生します。 1 × 1 または 2 × 2 の正方形では、有効な三位一体は生成されません。これは、結果として得られる三角形領域に含まれるセルが 3 個未満になるためです。 もう 1 つのエッジ ケースは、正方形が完全に均一である場合です。これは、潜在的な有効な三角形が最大化されるためであり、そこではカウントミスが大きく過剰カウントされる傾向があります。 

## アプローチ

 直接的なアプローチは、すべてを反復処理することです$O(N^2 M^2)$考えられる正方形を選択し、各正方形について両方の対角方向を確認し、結果として得られる三角形領域内のすべてのセルが等しいかどうかを確認します。 文字の等価性チェックのためにプレフィックスの合計を事前に計算したとしても、あまりにも多くの正方形を反復処理する必要があり、1000 x 1000 のグリッドでは正方形部分行列の総数自体がすでに多すぎます。 

重要な観察は、有効な各三位一体が対角線に沿った頂点構造によって完全に決定されるということです。 完全な正方形で考える代わりに、構造を再解釈します。セルを三角形の一部として固定し、不一致に達するまで 2 つの直交する方向に拡張できます。 開始セルが固定され、選択された方向 (2 つの対角線の 1 つに対応) の場合、三角形の最大サイズは、均一な文字制約を維持しながらどこまで拡張できるかによって決まります。 

これにより、問題は、セルごとに、各対角方向で有効な正方形サイズがいくつあるかを数えるという問題に変換されます。 正方形を列挙する代わりに、動的プログラミングのような対角線に沿った伝播を使用して最大延長長を計算し、すべてのセルからの寄与を合計します。 

主な構造の単純化は、妥当性が対角線および反対角線に沿った局所的な一貫性にのみ依存することです。これにより、両方向で最大の均一な「アーム」を事前計算できます。 これらのアームの長さが判明すると、各セルはこれらの長さの関数に等しい有効な三角形の数に寄与します。

 ## アルゴリズムのチュートリアル

 問題を 2 つの方向の処理に分けます。主対角に基づく三角形と、反対角に基づく三角形です。 どちらのケースも対称であるため、一方について説明し、同じロジックをもう一方に適用します。 

1. 各セルについて、対角方向の正方形を定義する 2 つの垂直方向に沿って、同一の文字の正方形をどこまで拡張できるかを計算します。 これは、グリッド上で動的プログラミングを使用して行われます。 重要なアイデアは、セルごとに、行と列に沿って終了または開始する同一文字の最長の範囲を事前計算し、これらの制約を組み合わせて正方形の一貫性を確保することです。 
2. 左上隅がそのセルにあり、すべてのセルが同一である正方形の最大の辺の長さをセルごとに格納する DP テーブルを構築します。 これは古典的な最大二乗問題ですが、対角対称の制約を反映するために概念的に拡張されました。 
3. 各セルおよび各方向について、そのセルによって提供される有効なトリニティの数は、そのセルから開始して形成できる正方形のサイズの数によって決まります。 最大正方形サイズが$k$の場合、2 から 2 までのすべてのサイズが寄与します。$k$、そのような各正方形は、選択された対角方向に対して正確に 1 つの有効なトリニティを生成します。 
4. すべてのセルおよび両方の対角方向にわたるこれらの寄与を合計します。 

重要な計算は、候補正方形内のすべてのセルが同一であることを保証するための方向性前処理と組み合わせた標準的な最大二乗 DP に削減されます。 

### なぜ効果があるのか

 このアルゴリズムが機能するのは、すべての有効なトリニティが正方形と対角方向の選択に一意に対応しており、各正方形内で「すべてのセルが等しい」という条件が、すべての単位サブ正方形展開が一貫性を保つことを要求することと同等であるためです。 DP は、サイズが正方形の場合、$k$が特定のアンカーで有効であれば、そこにアンカーされているすべての小さな正方形も有効になります。不一致があるとすぐに DP 拡張が中断されるため、無効な正方形はカウントされません。 これにより、カウントされた DP 状態と有効なトリニティの間にクリーンな 1 対 1 マッピングが作成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    g = [input().strip() for _ in range(n)]

    def count_orientation():
        dp = [[1] * m for _ in range(n)]
        res = 0

        for i in range(n):
            for j in range(m):
                if i > 0 and j > 0 and g[i][j] == g[i-1][j] == g[i][j-1] == g[i-1][j-1]:
                    dp[i][j] = min(dp[i-1][j], dp[i][j-1], dp[i-1][j-1]) + 1
                else:
                    dp[i][j] = 1

                res += max(0, dp[i][j] - 1)

        return res

    def count_antiorientation():
        dp = [[1] * m for _ in range(n)]
        res = 0

        for i in range(n):
            for j in range(m - 1, -1, -1):
                if i > 0 and j + 1 < m and g[i][j] == g[i-1][j] == g[i][j+1] == g[i-1][j+1]:
                    dp[i][j] = min(dp[i-1][j], dp[i][j+1], dp[i-1][j+1]) + 1
                else:
                    dp[i][j] = 1

                res += max(0, dp[i][j] - 1)

        return res

    print(count_orientation() + count_antiorientation())

if __name__ == "__main__":
    solve()
```この実装では 2 つのパスを使用します。 各パスは、標準の最大二乗 DP を計算します。1 回は通常の対角方向の場合、もう 1 回はミラー方向の場合です。 繰り返しでは、2 x 2 ブロックが均一であるかどうかがチェックされます。 そうであれば、正方形を 1 つのレイヤーだけ拡張できます。 

重要な微妙さは合計です`dp[i][j] - 1`。 値 1 は、有効なトリニティに寄与しない縮退正方形に対応しますが、より大きな正方形は、そのセルに固定されているすべてのより小さな有効なトリニティ サイズに寄与します。 

反対角バージョンは、DP が既に計算された状態を引き続き参照するように、列トラバーサルを逆にすることによって実装されます。
