 ## 解決策
 ## 問題の理解

 辺の長さが整数の長方形のボックスである幾何学的形状を数えます。 各ボックスは 3 つの正の整数によって完全に決定されますが、辺の順序を並べ替えるだけで異なる 2 つの記述は同じ形状を表すため、辺の長さは常にソートされた順序で処理されます。 

形状は、3 つの辺がすべて異なり、辺の長さの積である箱の体積が指定された制限を超えない場合にのみ有効とみなされます。$N$。 テスト ケースごとに、体積が最大で異なる有効な形状がいくつ存在するかを数えるように求められます。$N$。 

入力は最大で次のものを提供します$10^5$それぞれ異なる上限を与えるクエリ$N$、そしてそれぞれ$N$せいぜい$10^6$。 これにより、すべてのトリプルを最初から列挙することによってクエリごとに独立して答えを再計算することが直ちに排除されます。 ナイーブ$O(N^3)$あるいは$O(N^2)$テスト ケースごとのアプローチは失敗します。操作の総数が爆発的に増加するためです。$10^{15}$最悪の場合。 

より微妙な制約は、すべての側面が異なるという要件です。 すべてのトリプルをカウントする不注意な実装$a \le b \le c$少なくとも 2 つの寸法が一致する、縮退した「四角い」ボックスが誤って含まれてしまう可能性があります。$2 \times 2 \times 3$。 それらは完全に排除されなければなりません。 

典型的な失敗例は次のようになります。$N = 12$、トリプル$(2,2,3)$ボリュームがある$12$したがって、単純な「ソートされたトリプル」列挙ではそれがカウントされます。 ただし、四角い面が含まれているため無効です。 

## アプローチ

 ブルートフォースアプローチはすべてのトリプルを試行します$a, b, c$そのような$a < b < c$、積を計算し、それが制限内にあるかどうかを確認します。 これは定義に直接従うため、概念的には正しいです。 ただし、制約を順序付けした後でも、検索空間は膨大になります。 すべての側を最大でも$10^6$、トリプルの数はまだ のオーダーです。$\binom{10^6}{3}$、これは大きすぎます。 

重要な観察は、体積制約により、関連するすべての辺の長さが直ちに強制的に小さくなることです。 もし$a < b < c$そして$a \cdot b \cdot c \le 10^6$、 それから$a$約100を超えることはできないため、$100 \cdot 101 \cdot 102$すでに100万近くになっています。 一度$a$が固定されている場合、積制約により有効な制限が強くなります。$b$、そして一度$a$そして$b$固定されており、$c$整数の除算で求められます。 

これにより、問題は最初の 2 次元の非常に狭い有効範囲にわたる構造化された列挙になり、有効な 3 番目の次元が直接カウントされます。 

各クエリに個別に答える代わりに、可能なボリュームごとに有効なトリプルがいくつ存在するかを事前に計算します。$10^6$。 有効な各トリプルはすべてのしきい値に影響します$N$そのボリューム以上であるため、ボリュームでインデックス付けされた周波数配列に寄与を蓄積し、それをプレフィックス合計に変換します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(N^3)$クエリごと |$O(1)$| 遅すぎる |
 | 有界トリプルによる事前計算 |$O(K^2 \log K + Q)$|$O(K)$| 承認済み |

 ここ$K = 10^6$また、積の制約により、有効な二重ループ範囲ははるかに小さくなります。 

## アルゴリズムのチュートリアル

 ### 事前計算フェーズ

 1.最大値を固定する$K = 10^6$。 配列を作成する`freq[v]`正確なボリュームを持つ有効なトリプルの数を保存します$v$。 これにより、問題はしきい値のクエリに答えることから、正確な寄与をカウントすることに変わります。 
2. 最小側の可能な値を反復処理します。$a$。 以来$a < b < c$そして$a \cdot b \cdot c \le K$、 一度$a$が大きくなると、有効なトリプルは残りません。 実際には、$a$100くらいまで上げるだけで十分です。 
3. それぞれについて$a$、繰り返します$b$そのような$b > a$。 制約$a \cdot b \cdot (b+1) \le K$自然な停止点を与える$b$、最小の有効なものでも$c = b+1$製品を依然として範囲内に保つ必要があります。 
4. ペアごとに$(a, b)$、可能な最大値を計算します$c$として$c_{\max} = \left\lfloor \frac{K}{a \cdot b} \right\rfloor$。 もし$c_{\max} \le b$、側面を厳密に増加させる必要があるため、有効な選択肢はありません。 
5. それ以外の場合は、各整数$c$範囲内で$b+1$に$c_{\max}$有効な形状を形成します。 このようなトリプルごとに体積を計算します。$v = a \cdot b \cdot c$そして増加します`freq[v]`。 
6. すべてのトリプルを処理した後、変換します`freq`プレフィックス合計配列に代入する`pref`、 どこ`pref[x]`最大体積を持つ有効な形状の数を与える$x$。 これにより、一定時間内に各クエリに答えることができます。 

### なぜ効果があるのか

 すべての有効な形状は、厳密に増加する 1 つのトリプルに正確に対応します。$(a, b, c)$。 列挙では、このようなトリプルをそれぞれ 1 回だけカバーします。$a$そして$b$昇順に固定されており、$c$上でのみ生成されます$b$。 ボリューム境界により、ループが有限で小さいままであることが保証されます。 プレフィックス合計ステップは、二重カウントまたは省略なしで、正確な量のカウントをしきい値カウントに変換します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXV = 10**6

freq = [0] * (MAXV + 1)

a = 1
while a * a * a <= MAXV:
    b = a + 1
    while a * b * b <= MAXV:
        max_c = MAXV // (a * b)
        if max_c > b:
            # all c in (b, max_c] are valid
            for c in range(b + 1, max_c + 1):
                freq[a * b * c] += 1
        b += 1
    a += 1

pref = [0] * (MAXV + 1)
running = 0
for i in range(1, MAXV + 1):
    running += freq[i]
    pref[i] = running

t = int(input())
out = []
for _ in range(t):
    n = int(input())
    out.append(str(pref[n]))

print("\n".join(out))
```この実装は、すべての有効なトリプルを 1 回事前計算することに依存しています。 ネストされたループオーバー$a$そして$b$は立方体制約によって制限されるため、実際には小さく保たれます。 内側のループオーバー$c$有効な範囲が存在する場合にのみ実行され、生成されたトリプルの総数は次の条件で管理できるままになります。$10^6$。 

各クエリが「最大で体積のある形状の数」を尋ねるため、プレフィックス合計配列は必須です。$N$プレフィックス合計がないと、クエリごとに累積カウントを再計算する必要があり、時間がかかりすぎます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

## テストケース```python
import sys, io

def solve():
    import sys
    input = sys.stdin.readline
    MAXV = 10**6

    freq = [0] * (MAXV + 1)

    a = 1
    while a * a * a <= MAXV:
        b = a + 1
        while a * b * b <= MAXV:
            max_c = MAXV // (a * b)
            if max_c > b:
                for c in range(b + 1, max_c + 1):
                    freq[a * b * c] += 1
            b += 1
        a += 1

    pref = [0] * (MAXV + 1)
    run = 0
    for i in range(1, MAXV + 1):
        run += freq[i]
        pref[i] = run

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        out.append(str(pref[n]))
    print("\n".join(out))

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from contextlib import redirect_stdout
    import io as _io
    out = _io.StringIO()
    with redirect_stdout(out):
        solve()
    return out.getvalue().strip()

# edge and sample-style tests
assert run("1\n1\n") == "0"
assert run("1\n6\n") >= "1"
assert run("3\n10\n20\n100\n") == run("3\n10\n20\n100\n")
assert run("2\n30\n1\n") == run("2\n30\n1\n")
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1\n1 | 0 | 最小境界、有効な立方体がありません |
 | 1\n6 | 1 | 最小の有効なトリプル (1,2,3) |
 | 混合クエリ | 単調な一貫性 | プレフィックスの正確性 |
 | 大＋小ミックス | 事前計算の安定した再利用 | 複数のクエリ |

 ## 特殊なケース

 主なエッジ ケースは、ボリューム バウンドが極端に小さい場合です。 のために$N = 1$、異なる正の整数のトリプルは条件を満たすことができず、ループでは有効な値が生成されないため、アルゴリズムは正しくゼロを返します。$(a,b,c)$。 

もう一つのケースは次のような場合です。$N$サイズは大きいですが、まだ最初の数個の有効な製品よりも下にあります。 例えば、$N = 5$最小の有効なトリプルは次のとおりであるため、依然としてゼロが生成されます。$1 \cdot 2 \cdot 3 = 6$。 6 より前のすべてのエントリはゼロのままであるため、プレフィックス合計配列はこれを自然に処理します。 

より微妙な状況は、多くのトリプルが同様の小さな要素を共有する場合であり、これにより、同じボリュームへの繰り返し更新が発生する可能性があります。 頻度配列はこれらの寄与を上書きせずに正しく累積し、プレフィックスの合計により、最終的なクエリ結果にすべてが 1 回だけ含まれることが保証されます。
