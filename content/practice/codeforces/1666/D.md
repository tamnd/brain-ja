 ## 問題の理解

 各テスト ケースには、最初の単語とターゲットの単語という 2 つの文字列が与えられます。 文字を選択し、現在の単語からその左端にある文字を削除する操作を繰り返し実行します。 このプロセスは何度でも繰り返すことができ、問題は最初の単語をターゲットの単語に正確に変換できるかどうかです。 

重要な詳細は、削除が出現順序によって制限されることです。文字を削除するときは、任意の文字ではなく、常にその最も古い残りの文字が削除されます。 これは、文字を自由に並べ替えることができないことを意味します。 不要な文字を制御された方法で左から右に「剥がす」ことしかできません。 

各文字列の長さは最大 30 で、テスト ケースは最大 10,000 個あります。 これは、たとえ$O(n^2)$テスト ケースごとのアプローチは許容されますが、操作の削除や並べ替えに対する組み合わせ検索を伴うものは、遅すぎるか不必要になります。 

よくある失敗例は、「左端の出現」ルールを無視した場合に発生します。 たとえば、最初の文字列が`AAB`そして私たちが望んでいるのは`BA`単純に考えれば、1 つだけ削除すればよいのではないかと思われるかもしれません。`A`暗黙的に再配置されますが、その構造により、位置を注意深く追跡する必要があります。 もう 1 つの微妙な失敗は、`t`に存在する`s`、答えは「はい」です。 これは、次のような順序制約では失敗します。`s = "ABAC"`そして`t = "AAC"`ここで、相対的な位置により、強制削除後に必要な文字を保持することが不可能になります。 

主要な問題は、削除がグローバルなシーケンスで発生し、文字の将来の利用可能性に影響を与えるため、必要なサブシーケンス構造を正確に保持する一連の削除が存在するかどうかを推論する必要があることです。 

## アプローチ

重要な点は、実際にはすべての削除命令をシミュレートする必要はないということです。 代わりに、逆に考えることができます。つまり、最終的に次の結果が得られるかどうかを判断しようとしているのです。`t`から文字を選択的に削除することで、`s`ただし、左端の削除ルールによって課せられる相対的な順序の制約は維持されます。 

重要な洞察は、`t`が表示される場合は、それが次の出現と一致することを確認する必要があります。`s`それは以前の文字がすべて削除されても残ります。 削除では常に最初に使用可能な出現が削除されるため、文字を渡すと、`s`、後の位置でそれを使用するために「戻る」ことはできません。`t`。 これは、貪欲な左から右への構築を示唆しています。`t`内部`s`。 

一致させようとします`t`の続きとして`s`ただし、より強力な制約があります: でキャラクターを消費するときは常に、`s`、以前の不一致の発生の強制削除により、将来必要な一致が無効になることはありません。 これを形式化する正しい方法は、スキャンをシミュレートすることです。`s`そして貪欲に一致する文字`t`順序どおりに実行されますが、未使用の文字も確実に削除されます。`s`今後の一致をブロックしないでください。

 ## アルゴリズムのチュートリアル

### なぜ効果があるのか

 重要な不変条件は、スキャン中のどの時点でも、`s`、の接頭辞`t`これまでに一致したものは、有効な削除シーケンスの下で保存できる最も古いプレフィックスです。 削除では常に選択した文字の最初の出現が削除されるため、文字はスキップされます。`s`削除の順序に違反しない限り、後で使用することはできません。 したがって、貪欲にマッチングすることで、実行可能な埋め込みを決して見逃すことがなくなります。`t`、一致しないということは、欠失を再配置しても欠落した構造を回復できないことを意味します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    out = []
    for _ in range(n):
        s, t = input().split()
        j = 0
        m = len(t)

        for ch in s:
            if j < m and ch == t[j]:
                j += 1

        out.append("YES" if j == m else "NO")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装は、アルゴリズムで説明されている貪欲なマッチングを直接エンコードします。 ポインタ`j`進行状況を追跡します`t`、一致する文字が見つかった場合にのみ先に進みます。`s`。 条件`j < m`一旦範囲外アクセスを阻止します`t`早期に完全に一致します。 

A subtle point is that we never explicitly simulate deletions. これは意図的なものです。貪欲なサブシーケンス チェックでは、一致に使用されていない文字は、すでに一致した構造に影響を与えることなく、ある時点で削除可能であるとみなされるため、すべての有効な削除シーケンスが暗黙的にモデル化されます。
