 ## 解決策
 ## 問題の理解

 チームを編成するよう求められています。`n`メンバーを二分探索ツリー (BST) 階層に統合し、通信コストを最小限に抑えます。 各チームメンバーには固有の番号が割り当てられています。`1`に`n`フロントエンドからバックエンドまでのスペクトルにおけるその位置を表します。 入力により対称が得られます。`n × n`マトリックス`c`どこ`c[i][j]`メンバー間で交換される月当たりのメッセージの予想数です。`i`そして`j`。 

階層は、メンバーを表すすべてのノードの BST プロパティを満たす必要があります。`v`、左側のサブツリー内のすべてのメンバーの番号は次のとおりです。`v`であり、右側のサブツリー内のすべてのメンバーの数値は次のとおりです。`v`。 ツリーが構築されると、間の通信コストは`i`そして`j`は`c[i][j]`ツリー内のノード間のパスの長さの倍。 目標は、メンバーのすべてのペアの通信コストの合計を最小化するツリー構造を選択することです。 

とすれば`n`は最大 200 になる可能性があるため、単純階乗計算量のアルゴリズムは不可能です。 すべての順列を計算する`n`要素を作成し、可能なすべての BST を形成するには、大まかに必要となります。`n!`許可されている操作よりも天文学的に大きい操作`O(10^8)`3秒間の制限時間内での操作。 これは、おおよそのアルゴリズムが必要であることを意味します。`O(n^3)`またはそれ以上の複雑さ。 

明らかではないエッジケースとしては、次のような場合があります。`n=1`、単一のメンバーがコストゼロで自動的にリーダーになる場合、またはコミュニケーション マトリックスが大きく偏っている場合、たとえば 1 人のメンバーが他のメンバーと頻繁に通信する場合。 このような状況では、単純にノードを番号順に接続する単純なアプローチでは、次善のコストが発生する可能性があります。 

## アプローチ

 ブルート フォース アプローチでは、考えられるすべての BST が生成されます。`n`メンバーを計算し、それぞれの合計通信コストを計算します。 BSTの数`n`ノードは`n`-th カタルーニャ語の数値。おおよそ次のように増加します。`4^n / n^{3/2}`。 のために`n = 20`、これはすでに 10^11 を超えており、`n = 200`それは想像を絶するほど大きいため、強引な攻撃は不可能です。 

重要な観察は、コスト構造が加算的であり、ツリー内の距離に依存するということです。 これはまさに、古典的な「最適二分探索ツリー」問題で利用される特性です。 定義すると`dp[l][r]`メンバーから BST を構築するための最小コストとして`l`に`r`、考えられるすべてのルートを反復できます。`k`で`[l, r]`そして、左と右のサブツリーのコストとルート自体によって引き起こされるコストの合計としてコストを再帰的に計算します。 ルートによって寄与される追加コストを効率的に計算するために、通信行列のプレフィックス合計を事前計算します。`cumulative[i][j]`連続した間隔を含む通信の合計がすぐに得られます。 これにより、単純な 3 次再帰が効率的な動的プログラミング ソリューションに削減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n! * n^2) | O(n^2) | 遅すぎる |
 | 最適なDP | O(n^3) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. コンピューティング`sumc[i][j]`メンバーからのコミュニケーションの合計として`i`メンバーへ`j`に`n`。 これにより、後で一定時間内にサブツリーのコストを高速に計算できます。 
2.初期化`dp[l][r]`メンバーで構成するBSTの最低限の通信費として`l`に`r`。 初期化する`root[l][r]`この最小限のコストを達成するルートを保存します。 
3. 間隔の長さを 1 から`n`、計算する`dp[l][r]`みんなのために`l`そして`r = l + length - 1`:

 ａ． 考えられるルートごとに`k`で`[l, r]`、合計コストを次のように計算します。`dp[l][k-1] + dp[k+1][r] + sum_c_subtree(l, r, k)`、 どこ`sum_c_subtree(l, r, k)`左右のサブツリーに接続するルートの増分コストを考慮します。 

b. ルートを追跡する`k`このコストを最小限に抑えるには`root[l][r]`。 
4. DP がいっぱいになったら、次のコマンドを使用してツリーを再帰的に構築します。`root`配列、リーダー (親 0) を割り当て、各メンバーの親を埋めます。 
5. 必要に応じて親配列を出力します。 

正確さを保証する不変条件は、すべての間隔について次のとおりです。`[l, r]`、`dp[l][r]`は、まさにこれらのメンバーを含む BST の最小通信コストを保持します。 すべてのサブツリーが最適に解決され、左右のサブツリーのすべての組み合わせが考慮されるため、最終的なルート選択により全体的な最適値が生成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(1000)

n = int(input())
c = [list(map(int, input().split())) for _ in range(n)]

# prefix sums of row sums to help compute cost of increasing depth by 1
s = [ [0]*(n+1) for _ in range(n+1)]
for i in range(n):
    for j in range(n):
        s[i][j+1] = s[i][j] + c[i][j]

# sum_c[l][r] is sum of all c[i][j] where l <= i,j <= r
sum_c = [[0]*(n+1) for _ in range(n+1)]
for l in range(n):
    for r in range(l, n):
        total = 0
        for i in range(l, r+1):
            total += s[i][r+1] - s[i][l]
        sum_c[l][r] = total

dp = [[0]*n for _ in range(n)]
root = [[-1]*n for _ in range(n)]

for length in range(1, n+1):
    for l in range(n - length + 1):
        r = l + length - 1
        best = None
        best_k = -1
        for k in range(l, r+1):
            left = dp[l][k-1] if k > l else 0
            right = dp[k+1][r] if k < r else 0
            left_cost = sum_c[l][k-1] if k > l else 0
            right_cost = sum_c[k+1][r] if k < r else 0
            total = left + right + left_cost + right_cost
            if best is None or total < best:
                best = total
                best_k = k
        dp[l][r] = best
        root[l][r] = best_k

parent = [0]*n

def build(l, r, p):
    if l > r:
        return
    k = root[l][r]
    parent[k] = p
    build(l, k-1, k+1)
    build(k+1, r, k+1)

build(0, n-1, 0)
print(' '.join(map(str, parent)))
```このソリューションでは、まず部分行列の合計を事前計算して、サブツリー接続の定数時間コスト計算を可能にします。 次に、すべての間隔の DP テーブルを埋め、それぞれの最適なルートを保存します。 最後に、親配列を再帰的に構築します。 単一ノードのサブツリーなどの境界条件は、チェックによって正しく処理されます。`k > l`そして`k < r`。
