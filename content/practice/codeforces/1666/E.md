 ## 解決策
 ## 問題の理解

 位置から伸びる、国全体を表す 1 次元のセグメントが与えられます。`0`位置を決める`l`。 このセグメント内には、`n`それぞれが別個の整数座標に位置する国民`a_i`、昇順に並べ替えられます。 

タスクはセグメント全体を分割することです`[0, l]`正確に`n`連続したサブセグメント。それぞれが 1 人の国民に割り当てられます。 各サブセグメントは正の整数の長さでなければならず、対応する国民の位置を含む必要があります。 セグメントは間隔を正確にタイル化する必要があります。つまり、端点を除いてセグメントは重なり合わず、それらの和集合は範囲全体をカバーします。 

このようなパーティションを割り当てる有効な方法の中で、最も長いセグメントの長さと最も短いセグメントの長さの差を最小限に抑えたいと考えています。 

出力は、この最小の差の値ではなく、それを達成する 1 つの実際のパーティションです。 

重要な制約は、`n ≤ 10^5`、 その間`l`と同じ大きさにすることができます`10^9`。 これにより、考えられるすべてのカット位置を列挙したり、きめ細かい再配分をシミュレートしようとするアプローチは即座に除外されます。 二次関数の何か`n`も遅すぎます。`O(n^2)`限界をはるかに超えているだろう。 

微妙な点は、各国民が自分のセグメント内に位置する必要があるため、連続する 2 人の国民の間でカットが制限されることです。`a_i`そして`a_{i+1}`、少なくとも 1 つのカットを次のどこかに配置する必要があります。`(a_i, a_{i+1})`。 これにより、連続する市民間に自然な「必須の境界」が作成されますが、これらのギャップ内のカットの正確な配置によってセグメントの長さが決まります。 

単純な間違いは、各国民が単に隣接する位置の中点間の間隔を取得していると仮定することです。 これは失敗します。`0`そして`l`また、最初と最後のセグメントとも相互作用し、整数制約により単純な中点の丸めが無効になったり、不均衡になったりする可能性があるためです。 

たとえば、次の場合`l = 10, n = 2, a = [4, 6]`、中間点の分割は示唆するかもしれません`[0,5]`そして`[5,10]`ただし、四捨五入ルールによっては、最初のセグメントに必ずしも 4 が含まれるわけではありません。 たとえそうであったとしても、これはエンドポイントの制約に対する最適なバランスを無視します。 

もう 1 つの失敗モードは、各セグメントに可能な限り最小の有効な長さを貪欲に割り当てることです。 その場合、最後のセグメントまでの長さが長くなりすぎて、大きなアンバランスが生じます。 

## アプローチ

 ブルートフォースの視点は、私たちが効果的に選択していることに気づくことから始まります。`n-1`間のカットポイント`l-1`整数の位置。 カットの構成ごとに、セグメントの長さを計算し、各市民が正しいセグメントに存在することを確認することで妥当性をチェックできます。 カットを選択する方法の数は次のとおりであるため、これは組み合わせ的に不可能です。`C(l, n)`、これは小さな値であっても天文学的に大きくなります。 

たとえ削減を意味のある場所（市民の周囲）のみに制限したとしても、境界スラックの分布数は依然として指数関数的に増加します。`n`。 

重要な構造的洞察は、市民の順序がセグメントの順序を固定するということです。 各セグメントは、市民の影響範囲の連続したブロックに対応しており、重要なのは、グローバルにどのカットを選択するかではなく、隣接する制約間に利用可能な「空きスペース」をどのように分配するかです。 

絶対的な位置の観点から考える代わりに、視点をセグメントの長さに移します。 各セグメントは、左のカットから右のカットまでカバーする必要があり、その市民を含める必要があります。 これは、各国民が周囲に少なくとも特定の最小限のセグメントの範囲を強制するローカル制約を課し、残りの柔軟性は余剰長をどのように配分するかだけであることを意味します。 

正しい構築は、可能な限り最適な不均衡をバイナリ検索することで得られます。 候補の最大許容セグメント長を固定する場合`X`を超えるセグメントがないように、貪欲にセグメントの割り当てを試みることができます。`X`依然として市民の封じ込めを尊重しながら。 この実現可能性チェックは単調です`X`、二分探索を可能にします。 

達成可能な最小の最大セグメント長がわかったら、有効なパーティションを貪欲に再構築して、その境界を決して超えないようにすると同時に、すべてのセグメントにその市民が含まれている必要があることを尊重します。

 ## アルゴリズムのチュートリアル

 1. ソートはすでに暗黙的に与えられています。`a_i`が増加しているため、国民を左から右に処理できます。 
2. 答えを二分探索します`X`、最小可能な最大セグメント長。 これは、最大セグメント長で有効なパーティションを構築できれば機能します。`X`の場合、さらに大きな値も可能です。 
3.固定の場合`X`では、左から右にセグメントを構築することをシミュレートします。 現在のセグメントの開始点を維持します`cur_l = 0`。 
4. 国民一人ひとりにとって`a_i`を含めるように現在のセグメントを拡張しようとします。`a_i`最長でも長さを保ちながら`X`。 これはセグメントの終了を意味します`cur_r`満たさなければなりません`cur_r ≤ cur_l + X`そしてまた`cur_r ≥ a_i`。 
5. 私たちが選ぶ`cur_r = max(a_i, cur_l + minimal feasible boundary rule)`ただし、重要な貪欲な決定は、次の制約に違反することなく、各セグメントを可能な限り拡張することです。 これにより、後の住民を満足させるために必要となる可能性のある長さを時期尚早に無駄にすることがなくなります。 
6. 現在のセグメントを超過せずに拡張できなくなった場合`X`または市民をスキップする場合は、セグメントを閉じて、その時点で新しいセグメントを開始します。 
7. 二分探索により実行可能な最小値が特定された後`X`、同じ貪欲な手順を使用して実際のセグメントを再構築し、エンドポイントを記録します。 

### なぜ効果があるのか

 本質的な不変条件は、貪欲な構築のどの時点でも、プレフィックスの有効なタイリングを維持することです。`[0, cur_r]`現在のインデックスまでのすべての国民がすでに有効なセグメントでカバーされており、どのセグメントも長さを超えないようにします。`X`。 貪欲な拡張から逸脱すると、前のセグメントが短縮されるだけであり、後のセグメントへの圧力が増大するだけであり、実現可能性は決して向上しません。 これにより、ローカルおよびグローバルで一貫した最適な貪欲な選択が行われます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can(l, n, a, X):
    cnt = 0
    i = 0
    cur = 0
    
    while i < n:
        start = cur
        # extend segment as far as possible while valid
        cur = start + X
        
        # must include at least one citizen
        if a[i] > cur:
            return False
        
        while i < n and a[i] <= cur:
            i += 1
        
        cnt += 1
    
    return cnt <= n

def build(l, n, a, X):
    res = []
    i = 0
    cur = 0
    
    while i < n:
        start = cur
        cur = start + X
        
        # ensure inclusion of first uncovered citizen
        cur = max(cur, a[i])
        
        # extend as far as possible while staying within X per segment
        while i < n and a[i] <= cur:
            i += 1
        
        res.append((start, cur))
    
    return res

def solve():
    l, n = map(int, input().split())
    a = list(map(int, input().split()))
    
    lo, hi = 1, l
    
    while lo < hi:
        mid = (lo + hi) // 2
        if can(l, n, a, mid):
            hi = mid
        else:
            lo = mid + 1
    
    segs = build(l, n, a, lo)
    
    # adjust last segment to end exactly at l
    segs[-1] = (segs[-1][0], l)
    
    for s, f in segs:
        print(s, f)

if __name__ == "__main__":
    solve()
```このソリューションは、市民を制限された長さのセグメントに詰め込むことを試みる実現可能性チェックを中心に構築されています。 の`can`関数は、指定された最大長かどうかをシミュレートします。`X`必要に応じて新しいセグメントを貪欲に開始するだけで十分です。 再構成では同じロジックが使用されますが、セグメント境界が記録されます。 

正確に終了するように最後のセグメントを最終調整します。`l`これを超えると市民が存在しないため、残ったスラックは制約に違反することなく常に最後のセグメントに吸収できるため、安全です。 

実装の微妙な詳細は、貪欲な拡張により、各セグメントがその正しい境界内に収まるすべての市民を常にカバーするようにすることです。 このステップを怠ると、必要な包含をスキップする無効なセグメントが生成されます。

 ## 特殊なケース

 すべての国民が左側の境界付近にいる場合、微妙なエッジケースが発生します。 例えば：```
10 3
1 2 3
```単純な中点アプローチでは対称分割を試みますが、最初のセグメントには依然として次の要素が含まれている必要があります。`1`、初期のカットを強制的に原点近くに束ねます。 貪欲な構造では、次のカバーされていない市民を含めるのに十分なだけセグメントを拡張することでこれを処理し、無効な省略を防ぎます。 

もう 1 つのケースは、市民が適切なエンドポイントに近い場合です。```
10 3
7 8 9
```ここでは、初期のセグメントが非常に小さくなる可能性があり、ほとんどの長さが最後のセグメントに押し込まれます。 アルゴリズムは固定全長制約を常に尊重し、早すぎるイコライゼーションを強制しないため、この不均衡を適切に吸収します。 

最後に、市民が等間隔に配置されている場合、アルゴリズムは自然に均一なセグメント長に収束します。 各セグメントは実現可能性を損なうことなく、隣接する制約間の中間点で正確に終了できるため、貪欲な拡張によってこれが歪められることはありません。
