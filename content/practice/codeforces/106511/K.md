 ## 解決策
 ## 問題の理解

 一連の整数が与えられ、固定ターゲット合計条件を生成する位置の異なるトリプルがいくつあるかを数えるように求められます。この問題では、これは古典的な「3 合計」条件です。つまり、インデックスによって選択された 3 つの異なる要素の合計がゼロになる必要があります。 

入力は単一の配列として理解でき、最終的な答えには順序は関係なく、値と各値の出現回数のみが重要になります。 出力は、インデックス トリプルの数を表す単一の整数です。$(i, j, k)$と$i < j < k$対応する値が満足するように$a[i] + a[j] + a[k] = 0$。 

主な問題は、有効なトリプルを 1 つ形成することではなく、配列が大きく重複が多数含まれる可能性がある場合に、すべてのトリプルを効率的にカウントすることです。 

単純な考えは、インデックスのトリプルをすべて試して、それらの合計がゼロかどうかを確認することです。 トリプルの数が三次的に増加するため、配列が数千要素を超えるとすぐにこれは実行できなくなります。 

さらに微妙な問題は重複に起因します。 配列に繰り返し値が含まれている場合、正しいソリューションでは、個別の値のトリプルだけでなく、インデックスの組み合わせもカウントする必要があります。 たとえば、配列が次の場合、`[0, 0, 0, 0]`の場合、正解は 4 つのゼロのうち任意の 3 つを選択する方法の数、つまり 4 です。値の重複を排除する単純なセットベースのアプローチでは、誤って 1 が返されます。 

値に大きな正と負の両方の数値が含まれているが、有効なトリプルが存在しない場合には、別のエッジ ケースが発生します。 正しいソリューションは、構造を前提とした早期終了ヒューリスティックに依存せずに効率的に実行する必要があります。 

## アプローチ

 ブルートフォース戦略は単純です。 インデックスのトリプルすべてを反復処理します$i < j < k$、合計を計算し、それがゼロに等しい場合は答えを増分します。 これは、考えられるすべての組み合わせに対して問題の定義を直接評価するため、正しいです。 

問題は手術回数です。 サイズの配列の場合$n$、このアプローチのパフォーマンスは約$\frac{n^3}{6}$小切手。 いつ$n = 5000$、これはすでに超えています$10^{10}$時間内に実行できる範囲をはるかに超えた操作。 

この改善は、検索の 3 次元を減らすことで実現します。 1 つの要素を修正すると、残りのサフィックスで合計が特定の値になるペアを見つけるという問題が発生します。 これは標準的な 2-sum 構造で、残りの部分がソートされていれば線形時間で解くことができます。 

配列をソートすると、固定の最初の要素ごとに 2 ポインター スキャンが可能になります。 選択したインデックスに対して$i$、ペアを検索します$(l, r)$そのような$a[i] + a[l] + a[r] = 0$。 これにより、問題は 3 次時間から 2 次時間に短縮されます。 

重要な構造上の利点は、ソートによって任意のペアの検索が単調なプロセスに変わり、ポインタの移動が合計に予測可能な影響を与えることです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^3)$|$O(1)$| 遅すぎる |
 | 固定 + 2 ポインター |$O(n^2)$|$O(1)$番外編 | 承認済み |

 ## アルゴリズムのチュートリアル

 私たちはソートと繰り返しの 2 ポインタ スキャンに依存しています。 

1. 配列を非降順で並べ替えます。 これにより、インデックスを内側または外側に移動したときに合計がどのように変化するかを推論することができます。 
2. トリプルの最初の要素を位置に固定します。$i$。 これを、検索するすべてのペアのアンカー値として扱います。 
3. 2 つのポインターを設定します。$l = i + 1$そして$r = n - 1$、合計を計算します$s = a[i] + a[l] + a[r]$。 
4. もし$s$がゼロの場合、有効なトリプルが見つかりました。 値が次の場合$l$そして$r$異なる場合、両側に重複がいくつ存在するかを数えて、その頻度を掛けます。 これにより、同一の要素を個別に繰り返すのではなく、繰り返される値が 1 ステップで正しく処理されます。 
5. もし$s$がゼロ未満の場合、合計が小さすぎるため、移動します$l$右に回すと増加します。 これが機能するのは、ソートされた配列の 2 番目の要素を増やしても合計が増えるだけだからです。 
6. もし$s$がゼロより大きい場合、合計が大きすぎるため、次のように移動します。$r$左に回すと減少します。 
7. 完了するまで手順 3 ～ 6 を繰り返します。$l$会う$r$、その後移動します$i$プロセスを進めて再起動します。 

### なぜ効果があるのか

 正確さは 2 つの結合された不変条件に依存します。 まず、固定の場合$i$、2 ポインター スキャンは、すべての実行可能なペアを検査します。$(l, r)$ソートされた配列セグメントの単調走査で 1 回だけ。 有効なペアはスキップされません。これは、合計が小さすぎるか大きすぎる場合は常に、一方向の移動のみで順序付けを行った場合に有効な合計を回復できる可能性があるためです。 

次に、重複をグループ化することで、インデックスのすべての組み合わせが 1 回だけカウントされるようになります。 同一の値を 1 つずつ列挙するのではなく、それらの組み合わせの寄与を 1 つのステップでカウントし、過剰なカウントを避けながら正確さを維持します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    a.sort()

    ans = 0

    for i in range(n):
        l, r = i + 1, n - 1

        while l < r:
            s = a[i] + a[l] + a[r]

            if s < 0:
                l += 1
            elif s > 0:
                r -= 1
            else:
                if a[l] == a[r]:
                    cnt = r - l + 1
                    ans += cnt * (cnt - 1) // 2
                    break

                lv = a[l]
                rv = a[r]

                lc = 0
                while l < r and a[l] == lv:
                    l += 1
                    lc += 1

                rc = 0
                while r >= l and a[r] == rv:
                    r -= 1
                    rc += 1

                ans += lc * rc

    print(ans)

if __name__ == "__main__":
    solve()
```プログラムは配列をソートすることから始まります。これは 2 ポインター推論に不可欠です。 固定インデックスごとに`i`、合計が次になる相補的なペアを見つけることとして問題を扱います。`-a[i]`。 

重複処理ロジックは最もデリケートな部分です。 ポインターが有効な 3 倍の和に到達する場合、2 つのケースがあります。 両方のポインターが同じ値にある場合、そのブロック内のすべてのペアが有効な組み合わせを形成し、組み合わせ公式を使用してカウントされます。 それ以外の場合は、左側と右側に同じ値がいくつ存在するかを数えてそれらを乗算します。これは、左側の出現はそれぞれ右側の出現と独立してペアになる可能性があるためです。 

ポインタの動きにより、領域が一度消費されると再利用されることがなくなり、全体の複雑さが二次関数に保たれます。

 ## 特殊なケース

 重要なエッジケースは、有効な領域内のすべての要素が同一である場合です。 入力用`[0, 0, 0, 0]`、アルゴリズムは次の状態に入ります。`l`そして`r`同じ値を指します。 ペアごとに反復する代わりに、範囲全体を圧縮し、次を使用して組み合わせをカウントします。$\binom{4}{2} = 6$固定アンカーごとにペアを作成し、すべてのトリプルが 1 回だけ含まれるようにします。 

もう 1 つのケースは、有効なトリプルが配列の境界にのみ存在する場合です。 のために`[-5, -2, 0, 2, 5]`、ポインタの移動により、両端から不可能な合計が徐々に削除されます。 有効な組み合わせがまばらであっても、すべての単調シフトが現在の固定インデックス セグメント内で実行可能なペアがスキップされないという不変条件を保持するため、アルゴリズムは依然としてそれらに到達します。
