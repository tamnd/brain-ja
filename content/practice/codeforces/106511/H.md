 ## 解決策
 ## 問題の理解

 それぞれの頂点が 2 色のいずれかで塗られているグラフが与えられます。 エッジは頂点のペアを接続し、グラフには方向性がありません。 課題は、「二色」とみなされる特定のサイクルを特定してカウントすることです。これは、そのようなサイクルに沿って、単色の構造内にとどまるのではなく、両方の色に遭遇する必要があることを意味します。 

目標を言い換える有用な方法は、サイクルを明示的に列挙することを求められるのではなく (それは実行不可能ですが、その代わりに、2 つの色の間の相互作用を考慮した上で、独立したサイクル構造がいくつ存在するかを計算することです) ということです。 重要な問題は、サイクルがグラフ内のグローバル オブジェクトであるため、直接組み合わせを試みるとすぐに指数関数的になってしまうことです。 

グラフに最大約 2×10^5 の頂点とエッジがある場合、すべての単純なサイクルを明示的に横断しようとするソリューションは直ちに除外されます。これは、中程度のグラフであっても指数関数的に多くのサイクルが含まれる可能性があるためです。 これにより、Disjoint Set Union やサイクル検出を伴うグラフ トラバーサルなどの線形または線形に近いグラフ処理手法が推進されます。 

サイクルが 1 つの色の頂点内に完全に存在する場合、微妙なエッジ ケースが発生します。 たとえば、三角形を形成する 3 つの頂点がすべて赤色であると考えてみましょう。 これはサイクルですが、二色ではありません。 単純なサイクル カウンターにはそれが含まれ、不正確な答えが生成されます。 もう 1 つの特殊なケースは、赤、青、赤、青の 4 サイクルなど、サイクルで色が完全に交互になる場合です。 単純な「単色構造」サイクルとして検出できない場合でも、その 1 つはカウントする必要があります。 

これらの観察は、問題は生のサイクルに関するものではなく、色のレンズを通して見たときに接続性がどのように異なるかに関するものであることを示唆しています。 

## アプローチ

 ブルート フォース パースペクティブでは、グラフ内のすべての単純なサイクルを列挙し、各サイクルに両方の色が含まれているかどうかを確認しようとします。 DFS バックエッジを介したサイクル検出に限定したとしても、各バックエッジがトラバース履歴に応じて多くの異なるサイクルに対応する可能性があるという問題に依然として直面します。 最悪の場合、密なグラフには 2^n 個のサイクルが含まれる可能性があり、これは完全に不可能になります。 

構造的な洞察は、実際には各サイクルを知る必要がないということです。 何らかのパスを介して既に接続されている 2 つの頂点を接続するエッジを追加すると、サイクルが正確に存在します。 これは、Disjoint Set Union で使用される古典的な特徴付けです。 

ここで複雑なのは色の状態です。 グラフを単一の構造として扱う代わりに、色の相互作用によってフィルタリングされたときに接続性がどのように動作するかを考慮します。 単一の色によって引き起こされる森の中でサイクルを完全に説明できない場合、サイクルは「二色性」になります。 言い換えれば、サイクルを作成する冗長性は、両方の色にまたがるパスを閉じるエッジから発生する必要があります。 

これにより、問題を、接続性を追跡し、すでに両方の色が混合している構造内でエッジが冗長性を導入するときを検出することとして再解釈することができます。 Disjoint Set Union は、エッジがサイクルを閉じるときを検出しながら、接続されたコンポーネントを段階的に維持できるため、自然なツールになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースサイクル列挙 | 指数 | O(n + m) | 遅すぎる |
 | DSU ベースの増分サイクル検出 | O(n α(n)) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 頂点上の Disjoint Set Union 構造を維持しながら、エッジを 1 つずつ処理します。

1. 各頂点が独自のコンポーネントで開始される DSU を初期化します。 各コンポーネントは、両方の色が含まれているか、1 つの色のみが含まれているかも追跡します。 サイクルは両方の色にまたがる場合にのみ関連するため、この追跡が必要です。 
2. 各エッジ (u、v) について、u と v がすでに同じ DSU コンポーネント内にあるかどうかを確認します。 そうでない場合は、それらをマージし、結果として得られるコンポーネントの色情報を更新します。 このステップは接続を拡張するだけであり、まだサイクルを形成することはできません。 
3. u と v がすでに同じコンポーネント内にある場合、このエッジはサイクルを閉じます。 この時点で、コンポーネントに両方の色が既に含まれているかどうかを検査します。 そうであれば、このサイクルは本質的に二色性であり、答えに貢献します。 
4. コンポーネントに以前に両方の色が含まれていなかった場合、構造的にサイクルが形成されていても、実質的には単色のままであり、寄与しません。 
5. すべてのエッジに対してこのプロセスを継続し、有効なサイクル形成エッジの数を蓄積します。 

重要な考え方は、すべてのサイクルは、接続されたコンポーネントに冗長性を生み出す最初のエッジによって一意に識別されるため、そのようなエッジをカウントすることで、重複することなくサイクルを正確にカウントできるということです。 

### なぜ効果があるのか

 いつでも、各 DSU コンポーネントは、処理されたエッジを介して接続された頂点の最大セットを表します。 サイクルは、エンドポイントがすでに接続されているエッジを追加するときに正確に導入されます。これは、エンドポイント間に代替パスがすでに存在することを意味します。 その代替パスは、新しいエッジとともに単純なサイクルを形成します。 

コンポーネントごとに色情報を維持することで、構造が必然的に両方の色にまたがるサイクルのみをカウントすることが保証されます。 各サイクルは DSU 処理順序の 1 つの冗長エッジに正確に対応するため、サイクルが 2 回カウントされることはなく、欠落するサイクルもありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n, color):
        self.parent = list(range(n))
        self.size = [1] * n
        self.has_color = [[False, False] for _ in range(n)]
        for i in range(n):
            self.has_color[i][color[i]] = True

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return False

        if self.size[ra] < self.size[rb]:
            ra, rb = rb, ra

        self.parent[rb] = ra
        self.size[ra] += self.size[rb]
        self.has_color[ra][0] |= self.has_color[rb][0]
        self.has_color[ra][1] |= self.has_color[rb][1]
        return True

    def is_bichromatic(self, x):
        r = self.find(x)
        return self.has_color[r][0] and self.has_color[r][1]

def solve():
    n, m = map(int, input().split())
    color = list(map(int, input().split()))

    dsu = DSU(n, color)
    ans = 0

    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1

        if dsu.find(u) == dsu.find(v):
            if dsu.is_bichromatic(u):
                ans += 1
        else:
            dsu.union(u, v)

    print(ans)

if __name__ == "__main__":
    solve()
```DSU は、各コンポーネントの接続性と色の構成の両方を維持します。 ユニオン操作は両方の側面をマージし、各コンポーネントが両方の色に遭遇したかどうかを常に認識できるようにします。 

重要な実装の詳細は、結合の前にサイクル検出が行われることです。 最初にマージすると、エッジが冗長であることを検出できなくなります。 

もう 1 つの微妙な点は、エンドポイントではなくコンポーネント レベルでカラー情報をチェックすることです。これは、2 つの頂点が接続されると、コンポーネント全体がその内部に形成されるサイクルが二色であるかどうかを決定するためです。 

## 実用的な例

 ### 例 1

 正方形のような構造で接続された 1 つの青い頂点を除くすべての頂点が赤である三角形を考えてみましょう。 

| エッジ | DSUのマージ? | 同じコンポーネントですか？ | コンポーネントの色 | サイクルカウント |
 | --- | --- | --- | --- | --- |
 | (1,2) | はい | いいえ | 赤 | いいえ |
 | (2,3) | はい | いいえ | 赤+青 | いいえ |
 | (3,1) | いいえ | はい | 赤+青 | はい |

 これは、最初の冗長エッジがどのようにサイクルを閉じるかを示しています。また、コンポーネントにはすでに両方の色が含まれているため、答えに寄与します。 

### 例 2

 3 つの赤いノードの単純な単色サイクル:

 | エッジ | DSUのマージ? | 同じコンポーネントですか？ | コンポーネントの色 | サイクルカウント |
 | --- | --- | --- | --- | --- |
 | (1,2) | はい | いいえ | 赤 | いいえ |
 | (2,3) | はい | いいえ | 赤 | いいえ |
 | (3,1) | いいえ | はい | 赤 | いいえ |

 サイクルは構造的に存在しますが、二色ではないため、正しく無視されます。 

これらのトレースは、コンポーネントが両方の色を混合するサイクルのみがカウントされることを確認します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n + m) α(n)) | 各エッジは最大 1 つの DSU 検索/結合操作をトリガーします。 
| スペース | O(n) | ノードごとの DSU 配列とカラー メタデータ |

 α(n) は実際には事実上一定であるため、数十万のエッジを持つグラフには線形に近い動作で十分です。

 ## 特殊なケース

 三角形で接続された 3 つの赤いノードなどの完全に単色のサイクルは、DSU コンポーネントが両方の色を含むものとして自身をマークすることがないため、正しく処理されます。そのため、サイクルを形成するエッジが現れた場合でも無視されます。 

赤と青の頂点が交互にある正方形などの完全に交互のサイクルは、最後のエッジがサイクルを閉じるときに 1 回だけカウントされます。これは、その時点でコンポーネントにすでに両方の色が含まれているためです。 

2 つの異なる色のノード間の単一エッジはサイクルをまったく作成しません。これは、エンドポイントが DSU で事前に接続されていないため、正しく無視されます。
