 ## 解決策
 ## 問題の理解

 いくつかのテスト ケースが与えられ、各テスト ケースは文字のみで構成される文字列です。`6`そして`7`。 タスクは、最初の位置に`6`、2 番目の位置には`7`、そして`7`選択したものの右側に厳密に表示されます`6`。 

言い換えれば、インデックスの順序付きペアを数えています。$(i, j)$どこ$i < j$のキャラクター$i$は`6`、およびのキャラクター$j$は`7`。 各テスト ケースは独立しており、各文字列のカウントを出力します。 

入力サイズは最大で$10^4$テスト ケース、および結合されたすべての文字列の合計長は最大で$2 \cdot 10^5$。 これが重要な制約です。多くのテスト ケースが存在する可能性がありますが、すべてのテスト ケースの合計作業量は、文字列の合計長において線形に保たれなければなりません。 各テスト ケースをその長さに対して線形時間を超えて処理するものは、遅すぎます。 

各文字列内の位置のすべてのペアに対する単純な二重ループは、最大で以下を検査します。$n^2$テストケースごとのペア。 単一の文字列に長さがある場合$2 \cdot 10^5$、それだけはもうあります。$4 \cdot 10^{10}$これは 2 秒の制限で処理できる速度をはるかに超えています。 したがって、各文字列を処理するメソッドが必要です。$O(n)$時間。 

不注意なロジックが壊れるエッジケースがいくつかあります。 

文字列にのみが含まれている場合`7`たとえば`777`、ありません`6`とペアになるため、答えはゼロでなければなりません。 少なくとも 1 つを想定するバグのあるアプローチ`6`または、最初の文字からカウントを開始すると、値が誤って追加される可能性があります。 

文字列にのみが含まれている場合`6`たとえば`6666`、まだ有効なものはありません`7`, したがって、答えは再びゼロになります。 ここでの間違いは、2 番目の文字タイプを確認せずに位置の組み合わせを数えようとしたときに発生することがよくあります。 

文字列が次のように交互になる場合`6767`、有効なフォワード ペアのみをカウントするようにする必要があります。 ここでの正解は 1 からの 3 です`6`位置 1 で両方と後でペアリング`7`と2番目`6`最後との組み合わせ`7`。 

## アプローチ

 ブルートフォース手法は簡単です。以下を含むすべての位置に対して、`6`、後のすべての位置をスキャンし、その数を数えます`7`。 これは正しいペアの定義に直接従うためです。 ただし、ある長さの文字列の場合、実行時間は最悪の場合でも 2 次になります。$n$、それぞれの$n$位置は最大でスキャンできます$n$将来のポジション。 合計入力サイズが次の値に達すると、$2 \cdot 10^5$、このアプローチは次の順序で試みます。$10^{10}$実行不可能な操作です。 

重要な観察点は、それぞれについて次のことです。`6`重要なのは、その数だけです`7`は個々の位置ではなく、その後に表示されます。 繰り返し前方にスキャンする代わりに、実行中のカウントを維持できます。`7`s は現在の位置の右側に残ります。 それぞれの値がわかっている場合`6`、答えに直接追加できます。 

これをより明確に考える方法は、カウントの方向を逆にすることです。 文字列を右から左にトラバースすると、次の数が維持されます。`7`これまで見てきました。 遭遇したとき`6`、以前に見たすべての`7`それと有効なペアを形成します。 これにより、ネストされたループ構造が単一のパスに変換されます。

 ## アルゴリズムのチュートリアル

 各文字列を個別に処理します。 

1. カウンタを初期化する`sevens = 0`何人かを追跡する`7`右から左にスキャンしながらこれまで見てきた文字。 これは、任意の有効なパートナーが何社存在するかを表します。`6`後で遭遇します。 
2.初期化`answer = 0`。 
3. 文字列を最後の文字から最初の文字まで繰り返します。 

私たちが見るとき、`7`、増分します`sevens`。 これは、いずれかの理由です`6`先に登場するものはこれと組み合わせることができます`7`。 

私たちが見るとき、`6`、追加します`sevens`に`answer`。 これが機能するのは、`7`私たちはこれの右側にある嘘をすでに見てきました`6`、有効なペアを形成します。 
4. 完全な文字列を処理した後、出力します。`answer`。 

トラバーサルの方向はロジックの一貫性を保つものです。つまり、`6`、変数`sevens`はすでに有効な将来のポジションの数を正確に表しています。 

### なぜ効果があるのか

 このアルゴリズムは、右から左へのスキャン中の任意の位置における不変式に依存します。`sevens`の数に等しい`7`s は現在のインデックスの右側にあります。 私たちが処理するとき、`6`インデックスで`i`、 毎`7`に数えられる`sevens`ユニークなペアを形成します$(i, j)$と$j > i$。 各ペアはその左端が処理される時点で 1 回だけカウントされるため、最終的な合計は文字列内の有効なペアの数と等しくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        s = input().strip()
        sevens = 0
        ans = 0

        for ch in reversed(s):
            if ch == '7':
                sevens += 1
            else:  # ch == '6'
                ans += sevens

        print(ans)

if __name__ == "__main__":
    solve()
```このコードは、右から左への推論を直接反映しています。 この反転は、サフィックス配列を明示的に事前計算する必要を回避し、次の条件に達したときに確実に`6`、すべて関連する`7`はすでにカウントされています。 

実装の微妙な詳細は、入力文字列を削除することです。 それなし`.strip()`を使用すると、改行文字が誤って余分な文字として処理され、環境によっては誤ったカウント ロジックが発生する可能性があります。

 ## 特殊なケース

 のみで構成される文字列`6`など`66666`、すべての文字が潜在的な左エンドポイントであるが、右エンドポイントが存在しないケースをトリガーします。 右から左へのスキャン中に、`sevens`全体を通してゼロのままなので、`6`答えにゼロを追加すると、正しい結果のゼロが生成されます。 

のみで構成される文字列`7`など`777`、逆の状況をテストします。 アルゴリズムが増加します`sevens`すべてのキャラクターに対応しますが、`6`したがって、答えには何も追加されません。 結果は正しくゼロのままです。 

混合されているがアンバランスな弦のような`666777`demonstrates accumulation. 右からスキャンする場合、最初の 3 つのステップが構築されます`sevens = 3`、そしてそれぞれ`6`答えに 3 を加えます。 これにより、すべての境界を越えたペアが正確に 1 回カウントされることが保証され、「右側の 7 の数」に関する不変式がすべての有効なペアを記述するのに十分であることが確認されます。
