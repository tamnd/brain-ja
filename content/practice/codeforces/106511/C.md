 ## 解決策
 ## 問題の理解

 一連の整数と一連のクエリが与えられます。 各クエリは、配列の連続セグメント内のすべての数値の最小公倍数を求めます。 タスクは、各クエリに個別に回答し、そのセグメントの結果の値を出力することです。 

中心となる問題は、LCM 自体を定義することではなく、多くの範囲クエリを効率的に処理することです。 クエリごとに LCM を直接再計算すると、配列の大部分が繰り返しスキャンされ、乗算と gcd 演算が最初から再計算されます。配列のサイズとクエリの数が両方とも大きい場合、これは非常に遅くなります。 

この種の問題に通常関連する制約は、配列が 2 次解が不可能になるほど大きくなる可能性があることを意味します。 各クエリを線形時間で再計算するソリューションであっても、q 回のおよそ n 回の操作が必要となり、これは 2 秒の制限で処理できる量を超えます。 これにより、各クエリが対数時間またはほぼ一定時間で応答できる前処理構造が実現します。 

この問題の微妙な問題は、LCM 値が非常に急速に増加することです。 中程度の入力であっても、標準の 64 ビット整数の範囲を超える数値が生成される可能性があります。 たとえば、30、42、70 などの値を組み合わせると、すでに大きな中間結果が生成されます。 オーバーフローを考慮せずに最初に乗算し、後で除算を行う単純な実装では、黙って不正確な答えが生成される可能性があります。 別のエッジ ケースは、最終的な答えがまだ制約内に収まる場合でも、中間 LCM 値が実用的な限界を超える場合に発生します。これにより、チェックされていない乗算が安全でなくなります。 

## アプローチ

 ブルート フォース ソリューションは、要求されたセグメントを反復処理し、値を実行中の LCM に繰り返し折り畳むことによって各クエリを処理します。 これは簡単です。1 から開始し、セグメント内の各要素について計算します。`lcm(current, a[i]) = current * a[i] // gcd(current, a[i])`。 LCM はペアに対して結合するため、これは正しいです。 

ただし、このアプローチではクエリごとに最初から再計算が行われます。 サイズ n の配列に対して q 個のクエリがある場合、最悪のケースでは O(nq) 個の gcd 操作が必要になります。 n と q の両方が大きい場合、これはすぐに実行不可能になります。 

重要な観察は、セグメントにわたる LCM 集計が結合的であるため、バランスの取れた構造で部分的な結果を事前計算できるということです。 各ノードがその区間の LCM を格納し、2 つの子を結合すると親区間の LCM が得られるため、セグメント ツリーは自然に適合します。 

唯一の問題は、LCM 値が際限なく増加する可能性があることです。 実際には、値が 10^18 などの安全なカットオフを超えると、それ以上乗算しても小ささが復元されないため、正確な値を区別することは役に立ちません。 これにより、値を固定のしきい値にクランプしながら、比較と最終的な答えの正確性を維持することができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nq) | お(1) | 遅すぎる |
 | セグメントツリー (LCM) | O((n + q) log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各ノードが配列のセグメントの LCM を表すセグメント ツリーを構築します。 

1. 配列上にセグメント ツリーを構築します。各リーフには、対応する配列値が格納されます。 各内部ノードは、その 2 つの子の LCM を保存します。 これにより、すべてのセグメントが事前に集約されることが保証されます。 
2. ノードで LCM を計算するときは、次の式を使用します。`lcm(a, b) = a // gcd(a, b) * b`。 中間オーバーフローのリスクを軽減するために、この順序で計算します。 
3. 計算された LCM が 10^18 などの固定制限を超える場合は、その制限に固定されます。 これ以上組み合わせても値が元に戻らないため、正確さを維持しながらオーバーフローを防ぎます。 
4. 各クエリ [l, r] について、セグメント ツリーをトラバースします。 ノードのセグメントが完全にクエリ範囲内にある場合は、格納されている値を直接使用します。 外側にある場合は無視してください。 それ以外の場合は、LCM を使用して両方の子の結果を結合します。 
5. 各クエリの最終集計値を出力します。 

この構造が機能する理由は、整数に対する LCM が結合演算を形成するためです。これは、計算をグループ化しても結果が変わらないことを意味します。 これにより、すべてのセグメントの部分 LCM を事前計算し、クエリ中に再利用できるようになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

LIMIT = 10**18

def gcd(a, b):
    while b:
        a, b = b, a % b
    return a

def lcm(a, b):
    if a == 0 or b == 0:
        return 0
    g = gcd(a, b)
    res = a // g * b
    return res if res <= LIMIT else LIMIT

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.size = 1
        while self.size < self.n:
            self.size *= 2
        self.t = [1] * (2 * self.size)

        for i in range(self.n):
            self.t[self.size + i] = arr[i]
        for i in range(self.size - 1, 0, -1):
            self.t[i] = lcm(self.t[2 * i], self.t[2 * i + 1])

    def query(self, l, r):
        l += self.size
        r += self.size
        res_left = 1
        res_right = 1

        while l <= r:
            if l % 2 == 1:
                res_left = lcm(res_left, self.t[l])
                l += 1
            if r % 2 == 0:
                res_right = lcm(self.t[r], res_right)
                r -= 1
            l //= 2
            r //= 2

        return lcm(res_left, res_right)

def main():
    n, q = map(int, input().split())
    arr = list(map(int, input().split()))
    st = SegTree(arr)

    out = []
    for _ in range(q):
        l, r = map(int, input().split())
        l -= 1
        r -= 1
        out.append(str(st.query(l, r)))

    print("\n".join(out))

if __name__ == "__main__":
    main()
```セグメント ツリーは、リーフが 2 のべき乗のオフセットで始まるフラット配列に格納されます。 これにより、構築とクエリのトラバーサルの両方が簡素化されます。 クエリ関数は、2 ポインター スタイルの反復的な上方へのウォークを使用し、左右の境界からの部分的な結果をマージします。 に分割`res_left`そして`res_right`結合性を維持しながら、順序の逆転の問題を回避します。 

最もデリケートな実装の詳細は LCM の計算です。 乗算の前に除算を行うのは、オーバーフローのリスクを軽減するために必要です。また、クランプにより、構造体を通じて無制限の整数が伝播されないようにすることができます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n + q) log n) | 各更新は存在せず、構築は O(n)、各クエリは O(log n) ノードを結合します。 
| スペース | O(n) | セグメント ツリーのストレージは配列サイズに比例します。 

対数クエリ時間により、各クエリはセグメント全体をスキャンするのではなく少数のツリー ノードのみに触れるため、多数のクエリを含む大規模な入力であっても制限内に収まることが保証されます。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    LIMIT = 10**18

    def gcd(a, b):
        while b:
            a, b = b, a % b
        return a

    def lcm(a, b):
        if a == 0 or b == 0:
            return 0
        g = gcd(a, b)
        res = a // g * b
        return res if res <= LIMIT else LIMIT

    class SegTree:
        def __init__(self, arr):
            self.n = len(arr)
            self.size = 1
            while self.size < self.n:
                self.size *= 2
            self.t = [1] * (2 * self.size)
            for i in range(self.n):
                self.t[self.size + i] = arr[i]
            for i in range(self.size - 1, 0, -1):
                self.t[i] = lcm(self.t[2*i], self.t[2*i+1])

        def query(self, l, r):
            l += self.size
            r += self.size
            res_left, res_right = 1, 1
            while l <= r:
                if l % 2:
                    res_left = lcm(res_left, self.t[l])
                    l += 1
                if not r % 2:
                    res_right = lcm(self.t[r], res_right)
                    r -= 1
                l //= 2
                r //= 2
            return lcm(res_left, res_right)

    n, q = map(int, input().split())
    arr = list(map(int, input().split()))
    st = SegTree(arr)

    out = []
    for _ in range(q):
        l, r = map(int, input().split())
        out.append(str(st.query(l-1, r-1)))
    return "\n".join(out)

 ## 特殊なケース

 次のような単一要素のクエリ`[7]`セグメント ツリーが変更せずにリーフ値を正しく返すことを示しています。 クエリは単一ノードを超える組み合わせロジックを入力しないため、LCM のアイデンティティ動作は維持されます。 

次のような繰り返し値の配列`[2, 2, 2]`冗長な要素が適切に崩壊することを示しています。 複数のノードが同じ値を提供する場合でも、LCM 操作を繰り返しても結果が増大することはありません。`lcm(2, 2) = 2`そしてこれはツリー全体に一貫して伝播します。 

全範囲クエリでは、最大の深さのトラバーサルが実行されます。 このアルゴリズムはツリーの両端からの複数のセグメントを結合し、正確さは LCM の結合性に依存しており、マージのグループ化が同じ最終値を生成することが保証されます。
