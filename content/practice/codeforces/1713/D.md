 ## 解決策
 ## 問題の理解

 私たちは規模の完全なシングルエリミネーショントーナメントを扱っています$2^n$。 プレーヤーには 1 から 2 までのインデックスが付けられます。$2^n$。 試合は固定ブラケットで行われます。つまり、隣接するペアが最初にプレイされ、次に隣接する試合の勝者が再度プレイされ、チャンピオンが 1 人残るまで繰り返されます。 

試合結果を直接見ることはできません。 代わりに、任意の 2 人のプレーヤーをクエリできます。$a$そして$b$、そして裁判官は、どちらがトーナメントでより多くの試合に勝ったか、それとも同点かを教えてくれます。 この間接的な比較から、最終トーナメントの勝者を特定する必要があります。 

重要な微妙な点は、クエリがスキルや誰が誰に勝ったかの直接の比較ではなく、固定ノックアウト ツリーでの合計勝利数の比較であることです。 トーナメントの勝者はまさに$n$が勝ち、他のプレイヤーはそれより少ないですが、これらの値を直接観察することはできません。 

制約$n \le 17$までを意味します$2^{17} = 131072$選手たち。 クエリ制限は約$\frac{2^{n+1}}{3}$、これはプレーヤーの数に線形です。 これは、二次関数や偶数関数ではなく、線形または線形に近い比較回数で勝者を特定することが期待されていることを強く示唆しています。$O(n \log n)$重い定数を使用します。 

単純な戦略では、何らかの構造内のすべてのペアを繰り返しクエリすることで、勝ち数を推定したり、敗退をシミュレートしようとします。 トーナメント形式の敗退でも試合の勝者を知る必要があるため、これはすぐに失敗しますが、直接の試合結果はありません。 

さらに危険な単純な考えは、各候補者を他のすべての候補者と比較して、クエリを介して勝利数をカウントすることです。 これは不可能です。各候補者は次のことを要求します。$O(N)$クエリ、それにつながる$O(N^2)$合計クエリ数は制限をはるかに超えています。 

隠れた主な困難は、試合の結果がわからないため、ブラケットを再構築できないことです。 ただし、トーナメントの構造が固定かつ対称的であり、勝者が厳密に最大勝利数を持っているという独自の特徴があるという事実を活用することはできます。 

## アプローチ

 ブルートフォースの観点では、すべてのプレイヤーの勝利数を計算しようとします。 プレーヤーの勝利数は生き残ったすべてのラウンドに依存し、ブラケットは不明であるため、順序を推測するためにすべてのペア間のペアごとの比較を試みます。 各クエリは 2 つの固定整数 (勝利数) の相対比較のみを行うため、原則として、次のサイズの配列を並べ替えようとします。$2^n$比較を使用します。 

仕分け$N$比較を伴う要素には次のものが必要です$O(N \log N)$標準の比較並べ替えのクエリはすでに大きすぎて、$N = 2^{17}$厳格な直線予算の下で。 さらに、インタラクティブなオーバーヘッドがこれをさらに悪化させます。 

重要な点は、完全な順序付けは必要なく、最大の要素のみが必要であるということです。 任意の 2 人のプレイヤーを比較して、どちらがより多くの勝利を収めているかを常に知ることができれば、トーナメント ツリーの削減によって問題が解決されます。$N-1$クエリ。 障害となるのは、平等が出現する可能性があること、そしてさらに重要なことに、比較は直接的に「誰が強いか」ではなく、一貫性があり推移的である「より多くの勝利を収めている人」であるということです。 

勝利数は各ノードに割り当てられた隠れた静的整数であるため、すべてのクエリは 2 つの固定値間の信頼性の高い比較となります。 つまり、事実上、配列に対する標準的な比較オラクルがあり、必要なのは最大の要素だけです。 

ただし、問題はインタラクティブな制約であり、隠された構造によりより強力なトリックが可能になります。排除ステップごとに最悪の場合の線形スキャンを回避するピボット戦略を使用することで、候補の大部分を安全に排除できます。 

意図されたアプローチは、各クエリが優位性を確認するか、1 つの候補を破棄できるようにする、ランダム化または決定論的な排除です。 制約$\frac{2^{n+1}}{3}$各操作では、予想または最悪の場合に候補の少なくとも一定部分を削除する必要があることを示唆しています。 

現在の勝者の候補を維持し、構造化された方法で他の候補と比較してテストします。 比較するたびに、それが依然として優勢であることが確認されるか、より良い候補に置き換えられます。 すべての比較は 2 つの固定値の間で行われるため、プレーヤーが比較に負けると、その比較は将来の考慮から安全に破棄できます。 

これにより、問題は、各要素が最大でも一定数のクエリに参加することを保証する、ペアごとの比較による配列に対する古典的な最大値検出プロセスに縮小されます。

 ## アルゴリズムのチュートリアル

 各出場者は、トーナメントの勝利数に等しい未知の固定スコアを持つ要素として扱われます。 私たちの目標は、ペアごとの比較を使用して最大スコアを持つインデックスを見つけることです。 

1. まず、出場者 1 が現在の最良の候補者であると仮定します。 
2. 他のすべての出場者について 2 から 3 までを繰り返します。$2^n$。 出場者ごとに$i$、ペアをクエリします$(\text{best}, i)$。 
3. 応答が次のようになった場合$i$最高よりも勝利数が多い場合は、最高を次のように置き換えます$i$。 ベストが多い場合、またはベストが等しい場合は、ベストを変更しないでください。 

2 つの固定値を比較しているため、各ステップは正当化されます。 候補が現在の最高のものよりも優れていない場合、すでに最高がその候補を支配している場合、その候補は全体的な最大値になることはできません。 

微妙な点は、平等だからといって候補者が変わるわけではないということだ。 2 人のプレイヤーが同等の勝利を収めた場合、両方のランクが同じでない限り、どちらもユニークなトーナメント勝者になることはできませんが、実際には同じではないため、どちらかを保持しても問題ありません。 

すべてのプレーヤーを処理した後、勝利数の点で他のプレーヤーに負けていないプレーヤーが最もよく保持されます。これは、そのプレーヤーがトーナメントの勝者であることを意味します。 

### なぜ効果があるのか

 各クエリは、2 つの固定整数 (勝利数) 間の合計順序比較を強制します。 アルゴリズムは、最初の処理後の不変条件を維持します。$i$選手たちにとって、現在のベストはその中での最大値です。 これは、すべての更新が厳密に大きい値が見つかった場合にのみ発生し、値が一度破棄されると再表示したり再検討したりすることができないためです。 したがって、すべての反復の後、維持された候補はグローバル最大値となり、これはトーナメント勝者に対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ask(a, b):
    print("?", a, b)
    sys.stdout.flush()
    return int(input())

def solve():
    n = int(input())
    N = 1 << n

    best = 1
    for i in range(2, N + 1):
        res = ask(best, i)
        if res == 2:
            best = i

    print("!", best)
    sys.stdout.flush()

if __name__ == "__main__":
    t = 1
    for _ in range(t):
        solve()
```このソリューションは、単一の候補者を維持し、厳密に優れた出場者が見つかるたびにそれを更新することに完全に依存しています。 クエリ関数はインタラクティブな要件に厳密に従っており、即座に印刷およびフラッシュされます。 

ループ構造により、各出場者は現在のベストとの比較に 1 回だけ関与し、クエリの使用量が線形になります。 

よくある実装上の間違いは、各クエリの後に出力をフラッシュすることを忘れたり、印刷直後に判定応答を読み取る必要があることを忘れたりすることです。 もう 1 つの微妙な問題は、戻り値の誤解です。値 2 のみが置換を保証します。 値 0 または 1 は両方とも、現在の候補を保持することを意味します。

## 特殊なケース

 いつ$n = 1$、出場者は2人だけです。 1 回の比較ですぐに勝者が決定され、アルゴリズムは 1 つのクエリと直接出力に減ります。 

最大値が最後の位置にある場合、アルゴリズムは最初に競技者 1 が最も優れていると想定し、最終ステップでのみ真の勝者を発見します。 各中間比較では、最後のクエリで候補が反転されるまで、現在の最良のものが同等以上の勝利を収めていることが返されます。 

すべての出場者の勝利数が等しい場合、すべての比較で等しい値が返されます。 このアルゴリズムは候補を更新することはなく、競合者 1 を正しく出力します。クエリ定義ではすべてが同等であり、厳密にこれより優れた候補は存在しないため、これは有効です。 

最大値が位置 1 にある場合、すべての比較で現在の最良のものより悪くないことが返されるため、更新は行われず、競合者 1 は他のすべてを処理した直後に出力されます。
