 ## 解決策
 ## 問題の理解

 私たちは 4 つの基本方向への移動が許可され、移動ごとに 1 ステップのコストがかかるグリッドに取り組んでいます。 このグリッド上にはいくつかの点が配置されていますが、制限があります。すべての点は厳密にいずれかの軸上にあります。つまり、その x 座標が 0 であるか、y 座標が 0 であることを意味します。 私たちのタスクは、総移動コストを最小限に抑えながら、原点から開始し、これらすべてのポイントを任意の順序で訪問し、原点に戻ることです。 

タスクを再構成する便利な方法は、各点が原点を通る水平線または垂直線上にあるようにすることです。 x 軸上の点はライン y = 0 上にあり、y 軸上の点は x = 0 上にあります。移動はマンハッタン距離であるため、点間の移動は軸に沿ったセグメントに沿って加算されます。 

テストごとの入力サイズは小さいですが、テスト ケースの数は大きくなる可能性があります。 各テストには最大 100 点が含まれるため、テストごとの 2 次または 3 次の解はすでに安全ですが、線形または線形に近い観測ベースの解を目指す必要があります。 テスト全体のポイントの総数には制限がありません。つまり、テスト ソリューションごとに O(n²) があればまだ問題ありませんが、テスト ケース構造ごとにこれより悪いものは不要になります。 

素朴な解釈では、最短の閉じた歩行を計算するために訪問点のすべての順列を試行することを提案するかもしれません。 n 個あるので、それはすぐに組み合わせ論的に爆発します。 可能な注文。 n ≤ 100 の場合、ペアごとの最短パスを計算して巡回セールスマン動的プログラミング ソリューションを実行することさえ過剰です。 

考慮する価値のあるエッジ ケースは、点の縮退分布から生じます。 

すべての点が (0, 0) にある場合、移動は必要ありません。 

すべての点が 1 つの軸側のみ (たとえば、y 軸の正側のみ) にある場合、単純な戦略では不必要な方向の間を縫おうとする可能性がありますが、最適なパスは単純に最も遠い点まで進み、途中ですべてを収集して戻ってきます。 

## アプローチ

 この強引なアイデアは、各ボックスをノードとして扱い、それらを訪問するあらゆる可能な順序を考慮し、連続するポイント間のマンハッタン距離を合計して原点に戻るというものです。 これは典型的な巡回セールスマンの定式化です。 考えられるすべてのツアーをチェックするため、正確性は簡単です。 

失敗は純粋に計算上のものです。 n 点の場合、順列の数は n! であり、n = 10 の場合でもこれはすでに実行不可能になりますが、ここでは n は 100 になる可能性があります。部分集合に対する動的計画法でさえ O(n² · 2ⁿ) が必要になりますが、これは限界をはるかに超えています。 

重要な点は、ジオメトリが大幅に制限されていることです。 すべての点は、原点で交差する 2 本の線のうちの 1 つに位置します。 これは、動きを x 軸方向と y 軸方向に沿って独立して分解できることを意味します。 各軸では、すべてのポイントが 1 つの線上にあるため、それらのポイントを訪問すると、中間ポイントを通過しながら 0 から最も遠いポイントまで歩いて戻ってくることが最適になります。 

x 軸の場合、正の最大 x と負の最小 x のみが問題になります。 両方の端を訪れるルートは、それらの間の全スパンを横断する必要があり、外側に単調に移動すると、中間点は自動的にカバーされます。 同じロジックが y 軸にも適用されます。 

したがって、最適な戦略は、各方向、つまり最も右、左、上、下に移動する必要がある距離を単純に計算し、各軸が往復する必要があるため、それらの距離の 2 倍を合計することです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (TSP オーバー ポイント) | お(ん!) | O(n) | 遅すぎる |
 | 最適 (極端な座標) | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 点を x 軸と y 軸の寄与に分割します。 y = 0 の点は水平方向の動きに寄与し、x = 0 の点は垂直方向の動きに寄与します。 この分離は、一方の軸の動きが他方の軸に影響を与えないため機能します。 
2. X 軸上のすべての点のうち最大の正の X 座標を追跡します。 
3. X 軸上のすべての点のうち最小の負の X 座標を追跡します。 
4. Y 軸上のすべての点のうち最大の正の Y 座標を追跡します。 
5. Y 軸上のすべての点の中で最小の負の Y 座標を追跡します。 
6. 必要な水平距離を max_x + abs(min_x) として計算します。 これは、原点から両方の極値に到達するために必要な合計スパンを表します。 
7. 同じ理由で、必要な垂直距離を max_y + abs(min_y) として計算します。 
8. 原点から極値をカバーするまでの各エクスカーションは戻らなければならないため、これら 2 つのスパンの合計の 2 倍を返します。 

これらのステップの背後にある重要な考え方は、線上のすべての点を訪問するのに中間構造を再検討する必要がないということです。 必要な移動範囲を定義するのは極端な場合のみです。 

### なぜ効果があるのか

 X 軸上のすべての点は 1 つの直線 y = 0 上にあるため、左端と右端の両方の点を訪れるルートは、それらの間の区間全体を通過する必要があります。 中間点はこの間隔内にあり、単調に移動すると、その横断中に自動的に訪問されます。 同じことが y 軸にも独立して当てはまります。 x 軸と y 軸の移動はマンハッタン距離の下では直交しており加算されるため、合計の最適パスは各軸の独立した最適な移動の合計となり、それぞれ原点からの往復が必要になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    
    max_x = 0
    min_x = 0
    max_y = 0
    min_y = 0
    
    for _ in range(n):
        x, y = map(int, input().split())
        if y == 0:
            max_x = max(max_x, x)
            min_x = min(min_x, x)
        else:
            max_y = max(max_y, y)
            min_y = min(min_y, y)
    
    ans = 2 * (max_x - min_x + max_y - min_y)
    print(ans)
```この実装では、すべての点の幾何学的エンベロープをキャプチャする 4 つの現在の値が保持されます。 原点は常に有効なベースラインであり、軸のみの点はそれに応じて正または負の極値を調整するため、ゼロでの初期化が機能します。 

すべての点を収集した後に原点に戻らなければならないため、最終的な式は 2 倍になり、各軸の移動が往復になります。 

## 実用的な例

 ### サンプル 1

 入力:```
n = 4
(0, -2), (1, 0), (-1, 0), (0, 2)
```私たちは極端な状況を追跡します。 

| ステップ | マックス_x | 最小_x | 最大y | 分_y |
 | --- | --- | --- | --- | --- |
 | (0,-2) | 0 | 0 | 0 | -2 |
 | (1,0) | 1 | 0 | 0 | -2 |
 | (-1,0) | 1 | -1 | 0 | -2 |
 | (0,2) | 1 | -1 | 2 | -2 |

 水平スパン = 1 - (-1) = 2

 垂直スパン = 2 - (-2) = 4

 合計 = 2 × (2 + 4) = 12

 このトレースは、順序に関係なく、極端な値によってコストがどのように完全に決定されるかを示しています。 

### サンプル 2

 入力:```
n = 3

```| ステップ | マックス_x | 最小_x | 最大y | 分_y |

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        max_x = 0
        min_x = 0
        max_y = 0
        min_y = 0
        for _ in range(n):
            x, y = map(int, input().split())
            if y == 0:
                max_x = max(max_x, x)
                min_x = min(min_x, x)
            else:
                max_y = max(max_y, y)
                min_y = min(min_y, y)
        out.append(str(2 * (max_x - min_x + max_y - min_y)))
    return "\n".join(out)

 ## 特殊なケース

 原点以外の位置に点が 1 つだけある場合、アルゴリズムは 1 つの軸スパンをゼロに設定し、もう 1 つの軸スパンを原点からその点までの距離に設定します。 たとえば、入力`(0, 5)`max_y = 5 および min_y = 0 が得られ、垂直方向のスパンは 5 になり、最終的な答えは 10 になります。走査は、(0,5) まで行って戻ることに対応します。 

すべての点が厳密に x 軸上にある場合、次のようになります。`(-2,0)`そして`(3,0)`、y スパンは 0 のままですが、x スパンは 5 になります。アルゴリズムは 10 を生成します。これは、原点から -2 に進み、原点を通過して 3 に戻って戻ることに対応します。 

点に原点自体が含まれる場合、極値には影響しません。 (0,0) の点は移動要件に寄与せず、すべての極値が変化しないため、スパン ロジックによって当然無視されます。
