 ## 解決策
 ## 問題の理解

 正の整数の配列が与えられます。 連続した部分配列を繰り返し選択し、その部分配列内のすべての要素を 1 つずつ減らすことができます。 目標は、できるだけ少ない操作ですべての配列要素をゼロにすることです。 で表しましょう$f(a)$配列に必要なそのような操作の最小数$a$。 タスクは、指定された配列が$a$の順列がないという意味で、すでに「最適」です。$a$より少ない操作でゼロに減らすことができます。 

入力は複数のテスト ケースで構成されます。 各テストケースは長さを示します$n$配列と配列自体。 配列が上記の意味で最適であれば出力は「YES」、そうでない場合は「NO」になります。 制約により許可されるのは、$n$まで$10^5$テスト ケースごとに、すべてのテスト ケースの合計も最大$10^5$。 これにより、二次またはそれよりも複雑な複雑さを持つアルゴリズムが除外されます。$O(n \log n)$または$O(n)$解決策が必要です。 

明らかではないエッジ ケースには、繰り返しの数値を持つ配列、ソート順または逆ソート順の配列、両端に最大要素を持つ配列が含まれます。 たとえば、$a = [3,1,3,2]$、配列を再配置すると最適ではありません。$[1,2,3,3]$演算の数が 5 から 3 に減ります。順列を考慮しない不注意な実装では、そのような配列が最適であると誤って宣言される可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、配列のすべての順列を試して計算します。$f(b)$それぞれに。 コンピューティング$f(b)$現在のセグメントの最小値を繰り返し減算する再帰的または反復的な戦略を使用して実行できます。 ただし、$n = 10^5$、順列の数は$n!$、それは完全に不可能です。 コンピューティングでも$f(a)$単純なセグメント減算アルゴリズムを直接使用するのは、大きな配列にとっては遅すぎます。 

重要な観察は次のとおりです$f(a)$配列が非減少の場合、最小化されます。 その理由は、非単調シーケンスの局所的な減少によって余分な演算が発生するためです。 言い換えれば、「最適な」配置は、降順ではない順序でソートされます。 配列がソートされると、前の要素をより大きなセグメントの一部として常にカバーできるため、最小の操作数は最大の要素と等しくなります。 したがって、配列は$a$非降順でソートされている場合は、すでに最適です。 先行する要素よりも小さい要素が存在する場合、その要素を小さくする順列 (ソートされたもの) が存在します。$f(a)$。 これは単純なチェックに直接つながります。つまり、配列をソートされたバージョンと比較します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n! * n) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る$t$。 
2. テスト ケースごとに、配列の長さを読み取ります。$n$そして配列$a$。 
3. 並べ替えられたコピーを作成します。$a$降順ではない順に。 
4. 比較する$a$ソートされたバージョンで。 同一の場合は「YES」と出力します。 それ以外の場合は、「NO」を出力します。 

このアルゴリズムが機能するのは、すべての順列の中で最小数の演算が必要であることが保証されている配列は、非降順でソートされている配列だけであるためです。 この順序からの逸脱は、決して増加しない非減少シーケンスに再配置することで常に改善できます。$f(a)$そしてそれを減らすことがよくあります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    if a == sorted(a):
        print("YES")
    else:
        print("NO")
```このソリューションは、次を使用して入力を効率的に読み取ります。`sys.stdin.readline`。 各配列のソートされたバージョンを構築し、直接比較を実行します。 Python の組み込み`sorted`関数が実行される$O(n \log n)$時間。 比較`a == sorted(a)`配列を反復処理してコストを計算します$O(n)$テストケースごとに。 配列の境界外のインデックスにはアクセスしないため、境界条件は自動的に処理されます。 

## 実用的な例

 ### サンプル 1

 入力配列:`[2,3,5,4]`ソートされた配列:`[2,3,4,5]`比較：`[2,3,5,4] != [2,3,4,5]`→「いいえ」を出力

 これは、元の配列がソートされておらず、演算を削減する順列が存在することを示しています。 

### サンプル 2

 入力配列:`[1,2,3]`ソートされた配列:`[1,2,3]`比較：`[1,2,3] == [1,2,3]`→「YES」を出力

 これにより、不変である、つまり非減少配列が最適であることが確認されます。 

### サンプル 3

 入力配列:`[3,1,3,2]`ソートされた配列:`[1,2,3,3]`比較：`[3,1,3,2] != [1,2,3,3]`→「いいえ」を出力

 これは、要素が繰り返され、順序が単調ではないという特殊なケースを強調しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | テスト ケースごとに並べ替えが優先され、比較は O(n) |
 | スペース | O(n) | 配列のソートされたコピー |

 合計すると$n$すべてのテスト ケース ≤ 10^5 で、合計操作は問題なく以内に収まります。$10^6$1秒制限です。

 ## 特殊なケース

 単一要素配列の場合`[1]`、アルゴリズムはソートします`[1]`に`[1]`そして「YES」を出力し、最小サイズの入力を正しく処理します。 逆ソートされた配列の場合`[5,4,3,2,1]`、ソートにより生成される`[1,2,3,4,5]`、比較は失敗し、出力は「NO」となり、アルゴリズムが最適でない順列を識別したことを確認します。 同一の要素の配列の場合`[2,2,2,2]`、並べ替えでは配列は変更されず、出力は「YES」となり、繰り返される数値が正しく処理されます。 For arrays with a small inversion such as`[1,2,3,5,4,6]`、並べ替えは反転を修正し、比較は失敗し、出力は「NO」となり、アルゴリズムが微妙な非単調なケースを検出していることを確認します。
