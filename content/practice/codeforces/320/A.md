 ## 解決策
 ## 問題の理解

 10 進数で書かれた 1 つの整数が与えられ、それが 3 つの固定構成要素の 1 つを繰り返し並べて配置することによって構築できるかどうかを判断する必要があります。`1`、`14`、 そして`144`。 数字は、余分な桁や並べ替えをせず、これらの許可されたパターンの連結のみで正確に形成する必要があります。 

これにより、タスクは隠れた文字列構築問題に変わります。 入力は最大 10^9 の整数ですが、連結は桁レベルで定義されるため、実際に重要なのはその 10 進表現です。 

制約`n ≤ 10^9`入力が最大 10 桁であることを意味します。 これにより、重いデータ構造や指数関数的な検索の必要性が即座に排除されます。 数値を桁数で線形に処理するソリューションや、小規模な境界検索を試みるソリューションでも、十分に高速になります。 

貪欲な解析について考えると、いくつかの特殊なケースが自然に現れます。 障害モードの 1 つは、数字を独立して解釈することです。 たとえば、治療する`144`として`1 + 4 + 4`多くの無効な数値が有効であるかのように誤って示唆してしまいます。 もう 1 つの問題は、貪欲な曖昧さです。 たとえば、次のような文字列では`14144`、選択する`1 | 4 | 1 | 4 | 4`は無効ですが、正しいセグメンテーションが次のように存在します。`14 | 144`。 最小単位を単純に左から右に貪欲に選択すると、正確性が損なわれてしまいます。 

プレフィックスの競合にも注意する必要があります。 パターンが重なり合う:`1`の接頭辞です`14`、 そして`14`の接頭辞です`144`。 これは、常に最短の一致を取得する素朴な貪欲なアプローチでは行き詰まる可能性がある一方、より構造化された貪欲な戦略では最初に長い一致を優先する必要があることを意味します。 

## アプローチ

 ブルートフォース手法では、数字列をセグメントに分割するためにあらゆる方法が試行されます。各セグメントは次のいずれかになります。`1`、`14`、 または`144`。 各位置には最大 3 つの選択肢があり、分岐再帰が発生します。 最悪の場合、これは桁数が指数関数的になり、およそ O(3^d) になります (d は数値の長さ)。 

これは有効な分解をすべて直接探索するため概念的には機能しますが、状態の数が急速に増加し、多くのパスが重複するため、10 桁の場合でも実行不可能になります。 

重要な観察は、構造が高度に制約されていることです。すべての有効なセグメントは次のいずれかで始まります。`1`、その後、オプションで次のように拡張されます。`14`、さらにオプションで`144`。 この入れ子構造は、`1`、常に最も長い有効なパターンを最初に使用することを試みる必要があります。 失敗した場合は、構成全体を拒否することで暗黙的に後戻りします。 

これにより、問題は左から右への貪欲なマッチングによる単一の線形スキャンに変わり、常に一致を試みます。`144`まず、それから`14`、 それから`1`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(3^d) | O(d) | 遅すぎる |
 | 最適な貪欲スキャン | O(d) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 数字を順番に検査できるように、数値を文字列に変換します。 パターンは算術プロパティではなく連続する数字に対して定義されるため、数字を直接操作する必要があります。 
2. 左端の桁からスキャンを開始します。 インデックスを維持する`i`それは私たちの現在位置を追跡します。 
3. 各位置で、次から始まる部分文字列が存在するかどうかを確認します。`i`から始まる`144`。 そうなったら3キャラ消費して移動する`i`3 ずつ進めます。この選択は正しいです。次の理由からです。`144`は最も具体的で制限的なパターンであり、これを使用すると有効な構造が誤って断片化することを防ぎます。 
4. もし`144`は利用できません。部分文字列が次で始まるかどうかを確認してください。`14`。 「はい」の場合、2 文字を消費して進みます`i`このステップにより、有効なブロックの方が短いものよりも優先されることが保証されます。 
5. どちらでもない場合`144`または`14`一致、現在の文字が一致するかどうかを確認します。`1`。 その場合、それを単一のブロックとして消費して進みます`i`1までに。 
6. 3 つの条件のいずれもどの位置でも当てはまらない場合、構築は失敗し、その数値は有効なマジック ナンバーではありません。 
7. スキャンが文字列の最後で正確に終了した場合、その番号は有効です。 

### なぜ効果があるのか

 正確さは、有効なパターンの入れ子構造に依存します。すべての有効な数値は、各トークンが次で始まるトークンの連結です。`1`、長いトークンは短いトークンを拡張します (`1 ⊂ 14 ⊂ 144`）。 この封じ込めにより、より長い一致が利用可能な場合は常に、それを選択しても、より短いプレフィックスで始まる可能性のある有効なソリューションがブロックされることはありません。 解決策が存在する場合、貪欲スキャンはそれを途中で破棄することはありません。マッチングの失敗は、その位置に有効なセグメンテーションが存在しないことを意味します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

s = input().strip()

i = 0
n = len(s)

ok = True

while i < n:
    if i + 3 <= n and s[i:i+3] == "144":
        i += 3
    elif i + 2 <= n and s[i:i+2] == "14":
        i += 2
    elif s[i] == "1":
        i += 1
    else:
        ok = False
        break

print("YES" if ok and i == n else "NO")
```コードは貪欲な戦略を正確に反映しています。 チェックの順序は重要です。`144`前にテストする必要があります`14`、 そして`14`前に`1`そうしないと、後でより長い有効なブロックとのマッチングを妨げるプレフィックスを消費する危険があります。 

最終条件`i == n`これは、部分的な解析では十分ではないため、残された数字を残さずに文字列全体を消費することが保証されます。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from sys import stdin

    s = stdin.readline().strip()
    i = 0
    n = len(s)
    ok = True

    while i < n:
        if i + 3 <= n and s[i:i+3] == "144":
            i += 3
        elif i + 2 <= n and s[i:i+2] == "14":
            i += 2
        elif s[i] == "1":
            i += 1
        else:
            ok = False
            break

    return "YES" if ok and i == n else "NO"

# provided sample
assert run("114114\n") == "YES"

# custom cases
assert run("1\n") == "YES", "single valid token"
assert run("14\n") == "YES", "two-digit token"
assert run("144\n") == "YES", "three-digit token"
assert run("1414\n") == "YES", "mixed valid composition"
assert run("1444\n") == "NO", "invalid tail digit"
assert run("514\n") == "NO", "invalid prefix"

 ## 特殊なケース

 貪欲な決定は交換可能であるように見えてもそうではない場合、微妙なエッジケースが発生します。 考慮する`14144`。 

それを処理すると:

 から開始`1`、 それから`41...`セグメントを慎重に位置合わせしないと問題が発生します。 正しい分解は、`14 | 144`。 アルゴリズムは常に次のことを試みることでこれを保証します。`144`そして`14`元に戻る前に`1`。 

段階的に:

 入力:`14144`私たちは以下をチェックします:

 i=0 では、`14`一致するので消費します`14`。 

i=2 の場合、部分文字列は次のようになります。`144`、だから私たちは消費します`144`。 

i=5 で完了です。 

これは、貪欲な順序付けにより早期の断片化が防止され、存在する場合は常に有効な分解が保証されることが示されています。
