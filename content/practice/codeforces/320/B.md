 ## 解決策
 ## 問題の理解

 私たちは、数直線上で増え続ける開区間のコレクションを維持しています。 新しい間隔が追加されるたびに、それは暗黙的な有向グラフのノードになります。 最初の間隔のエンドポイントの 1 つが厳密に 2 番目の間隔内にある場合は、どの間隔からでも別の間隔に移動できます。 これにより、端点の幾何学的包含に基づいて有向エッジが作成されます。 

この構造をオンラインで構築した後、到達可能性のクエリに答える必要があります。すでに追加されている 2 つの間隔が与えられ、最初の間隔から開始し、有効な動きに沿って繰り返しジャンプして最終的に 2 番目の間隔に到達できるかどうかを判断します。 

主な難点は、グラフが明示的に与えられていないことです。 それぞれの新しい間隔は、そのエンドポイントがその中にあるかどうかに応じて、以前の多くの間隔に接続される可能性があります。 すべてのペアを繰り返しチェックする単純なアプローチでは、間隔の数が大きくなると時間がかかりすぎます。これは、到達可能性クエリで密な暗黙的なグラフの探索が必要になる可能性があるためです。 

ここでの制約は小さいとしても、意図した解決策は、間隔の構造が可能な遷移をどのように制限するかを理解することにかかっています。 

微妙な失敗のケースは、間隔が重なっているものの、移動が可能な形でエンドポイントが含まれていない場合に発生します。 たとえば、(1, 10) と (2, 3) がある場合、(2, 3) の両方のエンドポイントが (1, 10) 内にあるため、(2, 3) から (1, 10) に移動できます。 しかし、1 も 10 も厳密には (2, 3) の内側にないため、その逆は不可能です。 重複が接続性を意味すると仮定すると、この非対称性は誤って処理されやすくなります。 

もう 1 つのよくある間違いは、構造をオーバーラップに基づく無向接続として扱うことです。 これにより、封じ込めが一方向である場合、不正確な到達可能性が生じます。 

## アプローチ

 直接的なブルート フォース ソリューションでは、各間隔がノードとなるグラフを構築し、すべてのペア間のエッジを明示的にテストします。 2 つの区間 i と j について、端点の包含条件がどちらの方向にも当てはまるかどうかを確認し、それに応じて有向エッジを作成します。 各クエリは、ソース間隔から DFS または BFS を実行することによって応答されます。 

このアプローチは、動きのルールを忠実に表現しているため、正しいです。 ただし、隣接構造の構築には既に間隔数の 2 次時間のコストがかかり、各到達可能性クエリはグラフの大部分を横断する可能性があるため、コストが高くなります。 最悪の場合、多くのネストされた間隔があると、グラフが密になり、すべてのクエリが線形走査に変質します。 

重要な観察は、制約が強力な構造特性を保証していることです。つまり、新しく追加された各間隔は、以前のすべての間隔よりも厳密に長くなります。 これは、「スケール」の増加に間隔が効果的に挿入され、サイクルの形成方法と到達可能性の伝播方法が大幅に制限されることを意味します。 

新しい間隔はそれぞれこれまでで最長であるため、非常に構造化された方法でのみ以前の間隔に接続できます。 実際、遷移は常に現在の間隔のエンドポイントを厳密に含む間隔に向かって移動し、単調増加により、到達可能性構造は任意のグラフではなくツリー状の入れ子階層のように動作します。 

これにより、明示的な隣接リストを構築せずに、クエリごとに最大 n ノードにわたる単純な DFS を使用して到達可能性を計算できます。 n は最大でも 100 であるため、合計解は O(n^3) 個でも十分です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (明示的なグラフ + クエリごとの BFS) | O(n² + q・n²) | O(n²) | 許容できるが不要 |
 | 暗黙的なグラフ上の DFS | O(q · n²) 最悪の場合 | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 追加されるすべての間隔を配列に保存します。 各間隔は、その挿入インデックスによって識別されます。 
2. 間隔 a が間隔 b に到達できるかどうかを尋ねるクエリの場合、a から開始する深さ優先検索を実行します。 
3. 現在の間隔 (x、y) から、まだ訪問されていない他のすべての間隔 (c、d) にわたって繰り返します。 
4. 各候補区間について、移動が可能かどうかを確認します。 

c < x < d または c < y < d の場合、移動は許可されます。 

このチェックは、「現在の間隔のエンドポイントは厳密に次の間隔の内側にある」というルールを直接エンコードします。 
5. 条件が満たされる場合は、その間隔から DFS を再帰的に続行します。 
6. DFS 中に b に到達した場合は、すぐに YES を返します。 
7. b に到達せずに DFS が終了した場合は、NO を返します。 

ここで総当たり探索が許容される理由は、n が十分小さいため、フル スキャンを繰り返しても高速なままであるためです。 

### なぜ効果があるのか

 このアルゴリズムは、問題によって定義された有向エッジを正確に探索します。 すべての再帰ステップは有効な移動の後に続き、現在のノードに対してすべての間隔をチェックするため、すべての有効な移動はある時点で考慮されます。 DFS はこれらの遷移の下で到達可能なすべてのノードを探索するため、a から b への有効な移動シーケンスが存在する場合に限り、YES を返します。 正当な移動は反復中にチェックされる同じエンドポイント封じ込め条件を満たす必要があるため、スキップされる代替の非表示パスはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can_reach(start, target, intervals):
    n = len(intervals)
    visited = [False] * n
    stack = [start]
    visited[start] = True

    while stack:
        i = stack.pop()
        if i == target:
            return True

        x, y = intervals[i]

        for j in range(n):
            if visited[j]:
                continue
            c, d = intervals[j]

            if (c < x < d) or (c < y < d):
                visited[j] = True
                stack.append(j)

    return False

def solve():
    n = int(input())
    intervals = []
    out = []

    for _ in range(n):
        parts = input().split()
        if parts[0] == "1":
            x = int(parts[1])
            y = int(parts[2])
            intervals.append((x, y))
        else:
            a = int(parts[1]) - 1
            b = int(parts[2]) - 1
            out.append("YES" if can_reach(a, b, intervals) else "NO")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装では、インデックスが挿入順序と一致するように、間隔が単純なリストに保持されます。 各クエリ タイプ 2 は、すべての間隔をスキャンして正確な移動条件を適用する DFS をトリガーします。 訪問された配列は、包含パターンの重複によって作成される循環構成での無限ループを防ぎます。 

よくある落とし穴は、移動が候補区間ではなく現在の区間のエンドポイントに依存することを忘れていることです。 小切手`(c < x < d)`そして`(c < y < d)`は方向性があり、逆にしてはなりません。 

## 実用的な例

 ### 例 1

 入力:```
1 1 5
1 5 11
2 1 2
```間隔 1 から 2 までの到達可能性を追跡します。 

| ステップ | 現在 | 訪問 | 次に検討する | アクション |
 | --- | --- | --- | --- | --- |
 | 1 | 1 (1,5) | {1} | 2 (5,11) | 5 は厳密には (5,11) の内側ではなく、1 もどちらでもない → エッジなし |

 DFS は 2 に到達せずに終了するため、出力は NO になります。 

これにより、条件が厳格であるため、エンドポイントへの接触は有効な封じ込めとしてカウントされないことが確認されます。 

### 例 2

 入力:```
1 1 5
1 5 11
1 2 9
2 1 3
```間隔 1 が間隔 3 に到達できるかどうかを確認します。 

| ステップ | 現在 | 訪問 | 次に検討する | アクション |
 | --- | --- | --- | --- | --- |
 | 1 | 1 (1,5) | {1} | 2 (5,11) | 厳密に内部にエンドポイントはありません |
 | 1 | 1 (1,5) | {1} | 3 (2,9) | 1 < 5 < 9 は偽ですが、2 < 5 < 9 は真です → 3 に進みます |

 3 に到達したので、出力は YES になります。 

これは、直接接続が存在しない場合でも、中間間隔がブリッジとして機能できることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(q · n²) | 各クエリはすべての間隔をスキャンすることができ、DFS はすべてのノードを訪問することができます。 
| スペース | O(n) | 間隔と訪問済みの配列を保存します。 

n ≤ 100 の場合、最悪の場合でもクエリあたり 10⁴ の操作が容易に制限内に収まります。

 ## 特殊なケース

 微妙なエッジ ケースは、エンドポイントが間隔の境界と一致する場合です。 たとえば、(1, 5) から (5, 10) への場合、5 は厳密には (5, 10) の内側にないため、有効な移動はありません。 条件では厳密な不等式が使用されているため、アルゴリズムはこれを正しく拒否します。 

もう 1 つのケースは、重複は存在するが方向が異なる、対称的に見える間隔です。 (2, 9) から (1, 5) までは、重なり合っているにもかかわらず移動できません。 (2, 9) のどちらのエンドポイントも厳密には (1, 5) の内側にないため、DFS は正常に失敗します。 

最後のケースは、到達可能性が中間間隔を介して複数のホップを必要とするチェーンです。 DFS は到達可能なすべてのノードを探索するため、隣接関係チェック以降の前処理を必要とせずに、これらのパスを自然に検出します。
