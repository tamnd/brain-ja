 ## 解決策
 ## 問題の理解

 順序は関係なく、正の整数を正の整数の合計に分解できる方法が何通りあるかを数えるよう求められます。 2 つの表現が同じ加数セットで構成されている場合、たとえ異なる順序で書かれていても、その表現は同じであるとみなされます。 

たとえば、4 のような小さい数の場合、有効な分解は 4、3+1、2+2、2+1+1、および 1+1+1+1 です。 これらはそれぞれ、整数を分割する個別の方法に対応します。 

入力は単一の整数 n を与え、出力は 1e9+7 を法として計算された n の分割数です。 

制約は 1e6 まであり、パーティションを列挙したり組み合わせを明示的に構築しようとするアプローチは即座に除外されます。 サブセットやナップザック形式の構築に対する動的プログラミングでさえ、通常は n^2 遷移かそれより悪い遷移に依存するため、失敗します。 

微妙なエッジケースは最小の入力です。 n = 1 の場合、1 を表す方法が 1 つだけあるため、答えは 1 になります。少なくとも 2 つの部分を想定するか、初期化せずに小さな正のインデックスから構築しようとする誤った実装は、ここで簡単に壊れる可能性があります。 

別の障害モードは、実装が異なる順序を別のものとして誤って扱った場合に発生します。 たとえば、n = 4 の場合、パーティションの順列をカウントすると、3+1 と 1+3 が異なるものとして誤って扱われ、結果が増大します。 正しい解釈は順序を完全に無視します。 

## アプローチ

 この強引なアイデアは、残りの合計から可能なすべての最初の部分を再帰的に減算しようとすることです。 数値 n の場合、1 から n までの最初の加数 k を選択し、順列の過剰なカウントを避けるために、次の部分が最大でも k であるという制約で n-k を再帰的に分割します。 この再帰は、パーティションの標準的な非増加構造を強制するため、正しいです。 

ただし、このアプローチは大規模な再帰ツリーに拡張されます。 メモ化を行っても、各状態が考えられる次の部分をすべて試行するため、状態の数は最悪の場合でも n^2 / 2 個の遷移程度になります。 n = 1e6 の場合、これは実現可能な限界をはるかに超えています。 

重要な観察は、整数分割にはオイラーの五角形数定理から導かれたよく知られた漸化式があるということです。 次の加数の選択肢からパーティションを構築する代わりに、p(n) を以前の値 p(n - k(3k−1)/2) で表現します。ここで一般化された五角形の数は、パーティション構造の包含と除外を自然にエンコードします。 これにより、問題は n にわたる単一の線形 DP に変換されます。ここで、各状態は、構造化されたオフセットのシーケンスによってインデックス付けされた少数の以前の状態に依存します。 

オフセットが O(k^2) のように増加するため、構造が重要になるため、各 n に対して有効な寄与は約 O(√n) のみになります。 これにより、計算がおよそ n√n 個の算術演算に削減されますが、これは C++ では許容可能であり、注意して実装すればまだ管理可能です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | メモ化によるブルート フォース再帰 | O(exp(n)) | O(n) | 遅すぎる |
 | オイラー五角形定理による DP | O(n√n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 0 から n までのすべての i のパーティション値 p[i] を事前計算します。ここで、p[i] は i の整数パーティションの数を表します。 p[0] = 1 と設定するのは、ゼロを分割する方法が 1 つしかないためです。それは、何も選択しないことです。 

1 から n までの各値 i について、一般化五角形数からの寄与を使用して p[i] を計算します。 これらの数値は、k(3k−1)/2 および k(3k+1)/2 (k = 1、2、3 など) から得られます。 このような各オフセットは、パーティションの形状に対する包含/除外の正確さを維持しながら、パーティションを拡張または縮小する構造化された方法に対応します。

2 つの投稿を 1 つのグループとして交互にサインします。 具体的には、k = 1、2、3、…の場合、t1 = k(3k−1)/2 と t2 = k(3k+1)/2 の 2 つのオフセットを取得します。 p[i − t] の寄与は、k のパリティに応じて加算または減算され、t が i を超えると停止します。 

すべての有効な寄与を合計した後、結果を 1e9+7 を法として正規化します。 

これが機能する理由は、分割番号の生成関数 1 / product(1 − x^i) が対数構造を持ち、その展開が一般化五角形数によって正確にインデックス付けされたキャンセルにつながるためです。 反復内の各項は、前の項によって導入された過剰カウントを修正し、交互の符号パターンにより、無効な構成が正確にキャンセルされます。 DP は、その再発を i の昇順で反復的に評価し、必要な部分問題がすべてすでに計算されていることを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n = int(input().strip())
    
    dp = [0] * (n + 1)
    dp[0] = 1

    for i in range(1, n + 1):
        total = 0
        k = 1
        while True:
            a = k * (3 * k - 1) // 2
            b = k * (3 * k + 1) // 2

            if a > i:
                break

            sign = 1 if k % 2 == 1 else -1

            total += sign * dp[i - a]
            if b <= i:
                total += sign * dp[i - b]

            k += 1

        dp[i] = total % MOD

    print(dp[n] % MOD)

if __name__ == "__main__":
    solve()
```DP 配列はボトムアップで構築されるため、すべての dp[i] はすでに計算されている小さなインデックスのみに依存します。 k にわたるループにより、五角形のオフセットが生成されます。 符号は 2 項ごとに切り替わり、再発の構造と一致します。 

よくある実装上の落とし穴は、オフセット k(3k−1)/2 と k(3k+1)/2 の両方が同じ符号グループに含まれなければならないことを忘れていることです。 もう 1 つの微妙な問題は、中間値が負になる可能性があるため、各加算中ではなく累積後にモジュロ演算を処理することです。 

## 実用的な例

 n = 5 とします。アルゴリズムは dp[1] から dp[5] を順番に計算します。 

dp[1] の場合、オフセット 1 を通じて k = 1 のみが寄与し、dp[1] = 1 となります。 

dp[2] の場合、寄与は dp[1] と dp[0] から五角形のオフセットを通じて得られ、dp[2] = 2 が生成されます。 

dp[5] の場合、計算には複数の k 値が含まれ、更新を追跡できます。 

| k | t1 = k(3k−1)/2 | t2 = k(3k+1)/2 | サイン | 貢献 |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 2 | + | +dp[4]、+dp[3] |
 | 2 | 5 | 7 | − | −dp[0]、dp[-2]をスキップ |

 合計後:

 dp[5] = dp[4] + dp[3] − dp[0] = 5 + 3 − 1 = 7

 これは、既知のパーティション値 5 と一致します。 

トレースは、より高いインデックスが以前に計算された状態のみにどのように依存するか、および無効なオーバーカウントが減算によってどのように削除されるかを示します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n√n) | 各 i は、五角形の数が i | を超えるまで k を繰り返します。 
| スペース | O(n) | DP 配列には、最大 n | までのすべてのパーティション値が格納されます。 

n ≤ 1e6 という制約により、これは境界線になりますが、最適化された実装、特にコンパイル済み言語では許容されます。 再帰化により、このスケールでは不可能な二次遷移が回避されます。

 ## 特殊なケース

 n = 1 の場合、アルゴリズムは dp[0] = 1 を初期化し、最初のオフセットがすでにインデックスを超えているため、すべての五角形の寄与をスキップします。 これにより、再帰の深さに依存せずに、dp[1] = 1 が正しく生成されます。 

n = 2 や n = 3 のような小さな値の場合、最小の五角形の数値のみが寄与します。 k にわたるループはすぐに停止するため、境界外アクセスは発生せず、dp 値は純粋に dp[0] と dp[1] から構築されます。 

n = 10 などの大きな値の場合、複数の k レベルが寄与しますが、すべての dp[i] は、j < i で以前に計算された dp[j] のみを使用することが保証されます。 これにより、初期化されていないアクセスがなくなり、反復構築全体を通じて正確さが維持されます。
