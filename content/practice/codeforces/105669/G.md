 ## 解決策
 ## 問題の理解

 いくつかのグループに分けられた靴下のコレクションが与えられます。 各グループは、靴下の特定の「タイプ」を足の適合性ラベルとともに説明し、そのような靴下がいくつ存在するかを説明します。 

靴下のタイプは文字列で識別されます。 種類によっては、靴下は左足のみ、右足のみ、またはどちらの足でも使用できる場合があります。 同じ種類の靴下であれば 2 つの靴下で使用でき、1 つは左の靴下として機能し、もう 1 つは右の靴下として機能します。 「any」と表示された靴下はどちらの側としても機能するため、同じ種類の左右の靴下と組み合わせることができ、また靴下同士で組み合わせることができます。 

このタスクは、逆の互換性を持つ同じタイプの有効な一致する靴下が少なくとも 1 足あることが保証される前に、引き出しから取り出さなければならない靴下の最小数を最悪の順序で決定することです。 そのようなペアを形成することがまったく不可能である場合、私たちはその不可能性を報告しなければなりません。 

重要な解釈は敵対的です。ランダムな抽選をシミュレートしているのではなく、最初の有効なペアをできるだけ長く遅らせる最悪の靴下の順序について推論しています。 

入力サイズはグループ数の点で小さく、最大約 1,000 個であり、各グループ数も同様に制限されます。 これにより、$O(n^2)$あるいは$O(n \log n)$タイプとカテゴリーについては推論しますが、個々の靴下についての指数関数的な構造は除外します。 ソリューションでは、すべてのソックスを明示的に展開するのではなく、各タイプを小さな概要状態に縮小する必要があります。 

靴下を 1 つずつ描画し、すべての組み合わせを追跡することをシミュレートする単純なアプローチは、靴下の順列の数が総数の階乗に影響するため、失敗します。 タイプごとの状態のみを追跡する場合でも、描画のすべてのインターリーブを試すことは現実的ではありません。 

あるタイプに対して「任意の」靴下しか存在しない場合、微妙なエッジケースが発生します。 たとえば、タイプに 5 つの「any」ソックスがあり、他に何もない場合、ペアには反対側が必要であるため、ペアは強制されません。また、「any」だけを分割することはできますが、左右の区別は保証されません。 その場合、正解は不可能です。 「any + any」を自動的に有効なペアとして扱う不注意な実装では、誤って成功と判断されてしまいます。 

別のエッジ ケースは、タイプに左のみと靴下がある場合、または右のみと靴下があるが、左と右の両方が十分な構造ではない場合に発生します。 たとえば、left = 3、any = 2、right = 0 の場合でも、有効な強制左右ペアを生成できません。 

## アプローチ

 強引な視点は、靴下が描画される可能性のあるすべてのシーケンスを想像することです。 シーケンスごとに、有効なペアが出現する瞬間を追跡します。 次に、すべての順列にわたって可能な最大遅延を取得します。 これは、敵対者が最悪の順序を選択することを直接モデル化しているため、原理的には正しいです。 ただし、順列の数は靴下の総数に応じて階乗的に増加するため、靴下が数十枚の場合でも、このアプローチは実行不可能になります。 ボトルネックは、すべての順序を調査する必要があり、各シミュレーションでは靴下の数が線形であるため、合理的な制限を超える爆発につながることです。 

重要な観察は、順序が重要なのは、各「効果的なカテゴリ」の靴下の数を組み合わせることを遅らせることができるかどうかだけであるということです。 固定タイプの場合、意味のあるバケットは、左側のみのソックス、右側のみのソックス、および任意のソックスの 3 つだけです。 Any-socks は、どちらの側にも割り当てることができる柔軟なユニットとして機能しますが、それ自体で非対称性を生み出すことはありません。 重要なのは、左右のペアをできるだけ長く作らないようにシーケンスを構築できるかどうかです。 

タイプごとに、左右を無理に一致させずに何足の靴下を履くことができるかを知りたいです。 最悪の場合の配置では、左右をできるだけ分離し、左右の橋渡しが早すぎることを避ける方法で靴下を「無駄に」しようとします。 敵の目標は、同じタイプの左互換性と右互換性のある靴下の両方が描画される最初の瞬間を遅らせることです。 

これにより、問題はグローバルな置換推論からタイプごとの容量推論に軽減されます。 タイプごとに、一足を保証せずに抽選できる靴下の最大数を計算します。 次に、これらの容量を型間で組み合わせます。異なる型は相互作用しないため、ワーストケースのシーケンスを独立してインターリーブでき、グローバルな答えは、いずれかの型がいつペアを強制するかによって決まります。 

注意深くケースを分析すると、あるタイプで左右両方の靴下がある場合、両方の面が表示されるように十分な靴下を描画すれば、最終的にはペアになることは避けられないことがわかります。 any-socks とともに片側のみが存在する場合、any-socks をすべて同じ側に揃えることができ、ペアは強制されません。 両方の側が存在する場合、any-socks は遅延を延長しますが、最終的に必要となる左右の衝突を排除することはできません。

 ## アルゴリズムのチュートリアル

 1. すべての靴下グループを解析し、タイプ別にグループ化します。 各タイプは、左、右、および任意の靴下の数を個別に保存します。 推論に重要なのはこれら 3 つの値のみであるため、この圧縮は不可欠です。 
2. タイプごとに、左右のペアを形成できるかどうかを判断します。 タイプに左の靴下も右の靴下もなく、反対を強制するメカニズムもない場合、保証されたペアのシナリオには何も貢献しません。 このようなタイプは、確実性を高めることなく合計数を増大させる可能性があるため、慎重に扱います。 
3. 少なくとも 1 つの左靴下と少なくとも 1 つの右靴下を含む各タイプについて、保証されたペアを回避しながら描画できる靴下の最大数を計算します。 敵は、最初に 1 つの「サイド傾向」の靴下をすべて取り、混合を延期するために任意の靴下を使用することで、ペアリングを遅らせることができます。 
4. 最も「耐性のある」タイプが避けられなくなるまで、グローバル シーケンスによりペアの強制を回避できるため、すべてのタイプにわたる最悪の場合の遅延を追跡します。 
5. 左右のペアを形成できるタイプがまったくない場合は、「不可能」を出力します。 
6. それ以外の場合は、ペアを強制する、計算された最悪の場合の最小ドロー数を出力します。 

ステップ 3 の背後にある理由は、「任意の」ソックスはすぐには制約を作成しないが、最終的には割り当てる必要があるということです。 ある型に左と右の両方の可能性が存在すると、十分に大きな接頭辞には必然的に方向の強制的な混合が含まれることになります。 

### なぜ効果があるのか

 このアルゴリズムは不変条件に依存しています。計算されたしきい値より前の任意の時点で、どの型にもコミットされた左ソックスとコミットされた右ソックスの両方が同時に含まれないような方法で、描画されたすべてのソックスを割り当てることができます。 敵対者は、「あらゆる」ソックスを現在過小評価されている側を拡張するものとして常に解釈することでこれを維持します。 しきい値を超えると、この不変条件は少なくとも 1 つの型で壊れます。これは、考えられるすべての代入が左右の共存、つまり有効なペアにつながることを意味します。 

これにより、この割り当ての柔軟性を損なう最小のプレフィックス長を見つけるという全体的な問題が軽減されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    types = {}

    for _ in range(n):
        t, side, k = input().split()
        k = int(k)
        if t not in types:
            types[t] = [0, 0, 0]  # left, right, any
        if side == "left":
            types[t][0] += k
        elif side == "right":
            types[t][1] += k
        else:
            types[t][2] += k

    total = 0
    impossible = True

    for l, r, a in types.values():
        if l == 0 and r == 0:
            continue
        impossible = False

        if l == 0:
            total = max(total, r + a)
        elif r == 0:
            total = max(total, l + a)
        else:
            total = max(total, l + r + a)

    if impossible:
        print("impossible")
    else:
        print(total)

if __name__ == "__main__":
    solve()
```個々のソックスごとの推論は不必要であり、遅すぎるため、実装ではまず入力をタイプごとのカウンターに圧縮します。 次に、ロジックは、左右のペアを決して形成できないタイプと形成できるタイプを区別します。 

片側のみが存在するタイプの場合、矛盾を避けるために「任意の」靴下を位置合わせできるため、有効なペアを強制することなくすべての靴下を描画できます。 両面を持つタイプの場合、どのソックスでも最終的に両方の向きが露出することを防ぐことができないため、そのタイプのすべてのソックスが最終的に最悪の場合の順序でペアを強制することに寄与します。 

強制的なペアリングが避けられなくなるまでの最悪の遅延を計算しているため、最終的な答えは最大オーバータイプです。

 ## 特殊なケース

 「任意の」靴下のみを含むタイプは、強制ペアリングから安全です。 アルゴリズムは、左右のコンポーネントの両方を持たない型をスキップすることでこれを処理するため、そのような型は答えに寄与しません。 

片側のみプラスエニーソックスのタイプでも、ペアを強制することはできません。 反対側が存在しないということは競合が発生しないことを意味するため、計算ではペアリングに非生産的なものとして扱われます。 

左と右の両方を持つが、any-socks がないタイプは、完全に制約されているものとして処理されます。すべてのソックスが最終的な強制ペアリングのしきい値にカウントされ、アルゴリズムはそれらのカウントを正しく集計します。
