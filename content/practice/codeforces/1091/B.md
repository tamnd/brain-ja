 ## 解決策
 ## 問題の理解

 私たちには、2D 平面上の一連のオベリスクと、オベリスクから隠された宝物へのベクトルを示す一連の手がかりが与えられます。 各オベリスクには正確に 1 つの手がかりがありますが、マッピングが混乱しているため、どの手がかりがどのオベリスクに属しているかはわかりません。 各手がかりはベクトルであり、オベリスクの座標に追加されると、宝物を正確に指します。 目標は、オベリスクへの手がかりの順列を見つけることなく、宝の座標を決定することです。 

入力サイズでは、最大 1000 個のオベリスクと 1000 個の手がかりが許可されます。 各座標の大きさは最大 10^6 であり、手がかりは最大 ±2×10^6 になります。 制限時間は2秒です。 n = 1000 の場合、n! であるため、すべての順列を総当りでチェックすることは不可能です。 天文学的に大きいです。 これにより、考えられるすべてのペアリングを直接テストしようとするソリューションが除外されます。 

単純な間違いは、最初の手がかりが最初のオベリスクに属していると仮定し、宝物を次のように計算することです。`T = obelisk + clue`。 手がかりが混乱している可能性があるため、これは失敗します。 たとえば、n = 2、オベリスクが (0,0) と (1,1) にあり、手がかりが (1,0) と (0,1) である場合、手がかりを順番に割り当てると、最初のオベリスクには T = (1,0)、2 番目のオベリスクには T = (1,2) が与えられますが、これは矛盾しています。 正しい解は手がかりを交換し、両方のオベリスクで一貫した T = (0+0,0+1) = (1,1) を与えます。 

また、有界整数を含む言語でのオーバーフローを避けるために、負の座標と大きな値を慎重に処理する必要があります。 Python ではこれは安全ですが、C++ または Java では必要になります。`long long`。 

## アプローチ

 ブルートフォースアプローチは、オベリスクにマッピングされた手がかりのすべての順列を試みることです。 順列ごとに、すべてのペアの宝物の座標を計算し、それらが同一であるかどうかを確認します。 これは正しいですが、その複雑さは O(n!) であり、n = 10 の場合でも実行不可能です。 

これをスピードアップするための重要な洞察は、直線性から得られます。 その宝物があれば、`T`の場合、各手がかりは 1 回だけ使用されるため、すべてのオベリスクのすべての宝物座標の合計は、オベリスク座標の合計と手がかりベクトルの合計に等しくなります。 正式には:```
T * n = sum_over_obelisks(x_i, y_i) + sum_over_clues(a_j, b_j)
```これから、次のように宝物の座標をすぐに計算できます。```
T_x = (sum of all x_i + sum of all a_j) / n
T_y = (sum of all y_i + sum of all b_j) / n
```この問題では整数解が保証されているため、n で割ると整数が得られます。 

このアプローチが機能するのは、加算が可換であるためです。オベリスクに割り当てられた手がかりの合計は、置換に依存しません。 これにより、問題が階乗の複雑さから線形時間に軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | お(ん!) | O(n) | 遅すぎる |
 | 合計ベース (最適) | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. オベリスクと手がかりの数 n を読み取ります。 オベリスクの x、y 座標の合計と手がかりからの a、b ベクトルの合計のアキュムレータを初期化します。 
2. n 個のオベリスクをループします。 各オベリスクについて、その座標を読み取ります`(x_i, y_i)`そして、x_i を x-sum に加算し、y_i を y-sum に加算します。 これは、すべてのオベリスクの位置の合計寄与度を収集します。 
3. n 個の手がかりをループします。 手がかりベクトルごとに`(a_j, b_j)`、 a_j を a-sum に加算し、 b_j を b-sum に加算します。 これは、すべての手がかりベクトルの合計寄与度を収集します。 
4. 宝物の座標を次のように計算します。`T_x = (x-sum + a-sum) // n`そして`T_y = (y-sum + b-sum) // n`。 この問題では整数の解が保証されているため、整数の除算は機能します。 
5. T_x と T_y を出力します。 

機能する理由: すべてのオベリスクのすべての宝物の座標の合計は、すべてのオベリスクとすべての手がかりの合計に等しくなければなりません。 オベリスクごとに手がかりが 1 つだけあるため、この合計は順列とは無関係です。 n で割ると、正しい宝物の座標が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
ob_x_sum = 0
ob_y_sum = 0

for _ in range(n):
    x, y = map(int, input().split())
    ob_x_sum += x
    ob_y_sum += y

clue_x_sum = 0
clue_y_sum = 0

for _ in range(n):
    a, b = map(int, input().split())
    clue_x_sum += a
    clue_y_sum += b

T_x = (ob_x_sum + clue_x_sum) // n
T_y = (ob_y_sum + clue_y_sum) // n

print(T_x, T_y)
```このソリューションでは、まずオベリスクと手がかりの合計を別々に蓄積します。 単一の変数ペアに蓄積することもできましたが、それらを分離するとロジックがより明確になり、アルゴリズムと一致します。 この問題では宝の座標が整数であることが保証されているため、整数の除算は安全です。 Python は大きな整数を自動的に処理するため、オーバーフローの心配はありません。 

## 実用的な例

 サンプル 1:

 | オベリスク | x-合計 | y-sum | 手がかり | サム | ビーサム | T_x | T_y |
 | --- | --- | --- | --- | --- | --- | --- | --- |
 | (2,5),(-6,4) | -4 | 9 | (7,-2),(-1,-3) | 6 | -5 | (-4+6)//2=1 | (9-5)//2=2 |

 説明: オベリスクの X 座標の合計は -4、手がかりの合計は 6、合計は 2、2 で割ると 1 です。同様に y についても、9-5=4、2 で割ると 2 です。これは (1,2) にある正しい宝物と一致します。 

サンプル 2:

 | オベリスク | x-合計 | y-sum | 手がかり | サム | ビーサム | T_x | T_y |
 | --- | --- | --- | --- | --- | --- | --- | --- |
 | (2,3)、(4,5)、(6,7) | 12 | 15 | (1,1)、(2,2)、(3,3) | 6 | 6 | (12+6)//3=6 | (15+6)//3=7 |

 これにより、アルゴリズムが 2 つを超えるオベリスクと任意のベクトルを正しく処理できることが確認されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各オベリスクと手がかりは 1 回だけ読み取られ、合計されます。 
| スペース | お(1) | n | に関係なく、必要な整数アキュムレータは 4 つだけです。 

n ≤ 1000 の場合、合計操作数はおよそ 2n = 2000 となり、パフォーマンスの限界をはるかに下回ります。 メモリの使用は最小限であり、Python は整数演算を安全に処理します。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    ob_x_sum = ob_y_sum = 0
    for _ in range(n):
        x, y = map(int, input().split())
        ob_x_sum += x
        ob_y_sum += y
    clue_x_sum = clue_y_sum = 0
    for _ in range(n):
        a, b = map(int, input().split())
        clue_x_sum += a
        clue_y_sum += b
    T_x = (ob_x_sum + clue_x_sum) // n
    T_y = (ob_y_sum + clue_y_sum) // n
    return f"{T_x} {T_y}"

# Provided samples
