 ## 解決策
 ## 問題の理解

 単純な無向グラフが与えられています。$n+1$頂点がありますが、データから 1 つの頂点が欠落しています。 ボブの頂点を除くすべての頂点には既知の次数があります。つまり、それぞれの頂点の近傍の数がわかっています。$n$頂点があります。 欠けている部分はボブの度数であり、タスクは、度数シーケンス全体が何らかの有効な単純な無向グラフに対応するように、ボブの度数が取り得るすべての値を決定することです。 

グラフは通常の方法で制約されます。エッジは無向で、自己ループはなく、頂点のペアは複数のエッジを持つことができません。 したがって、次数は実現可能な単純なグラフから得られる必要があります。 

入力サイズは最大で$5 \cdot 10^5$。 グラフの構築をシミュレートしたり、完全な実現チェックを使用して候補の学位を繰り返しテストしたりするソリューションは、遅すぎます。 ボブの学位候補ごとに、Havel-Hakimi のような完全なグラフ実現チェックを実行する単純な試みにはコストがかかります。$O(n^2 \log n)$あるいは全体としてはさらに悪い結果となり、これは受け入れられません。 

微妙な点は、未知の頂点が他のすべての頂点とグローバルに相互作用することです。 ボブの学位を変更すると、学位シーケンス全体の実現可能性の制約が変化するため、局所的な推論だけでは十分ではありません。 

エッジ ケースは、シーケンスがほぼ完了しているか、ほぼ空の場合に発生します。 たとえば、指定されたすべての学位が次の場合、$0$の場合、ボブは疎な構造を尊重する方法でのみ接続できます。 与えられたすべての学位が$n$、その後、ボブは完全なグラフに強制的に入れられます。 もう 1 つの脆弱なケースは、次数の合計がすでに大きすぎるか小さすぎる場合です。$n$これにより、パリティと実現可能性が即座に制限されます。 

単純なアプローチは、実現可能な最小次数と最大実現可能次数の間の値が有効であると想定するため、失敗することがよくあります。 次数シーケンスには範囲制約だけでなく、グローバルな構造制約があるため、これは誤りです。 

## アプローチ

 ブルートフォース戦略は、考えられる値をすべて試すことです$k$ボブの学位については、$0$に$n$。 それぞれについて$k$、追加します$k$シーケンスに追加し、その結果が以下であるかどうかを確認します。$n+1$度数シーケンスはグラフィカルです。 これを行う標準的な方法は、最大次数の頂点を他の頂点に繰り返し接続する、Havel-Hakimi アルゴリズムです。 このチェックには費用がかかります$O(n \log n)$ソートまたはヒープ操作により候補ごとに異なります。 

あるので$O(n)$候補者の場合、全体の複雑さは次のようになります。$O(n^2 \log n)$。 と$n = 5 \cdot 10^5$、これは実現可能な限界をはるかに超えています。 

重要な観察は、実際にはすべての候補を個別にテストする必要はないということです。 度付きボブ追加の実現可能性$k$頂点間の接続がすでに必要な既存の頂点の数によって異なります。 度数を分類すると、有効な拡張機能の構造は特定の意味で単調になります。ボブの度数が増加するにつれて、実現可能性は制御された方法で変化し、段階的に追跡できます。 

実現可能性を最初から再計算する代わりに、ソートされた次数シーケンスの接頭辞条件を事前計算してから、有効なすべてを導出できます。$k$スイープ ライン スタイルの引数をフェンウィック ツリーまたは次数しきい値のプレフィックス合計ロジックと組み合わせて使用​​します。 

これにより、すべての構造ブレークポイントをチェックするのではなく、少数の構造ブレークポイントをチェックするだけの問題が軽減されます。$n$価値観。

 ## アルゴリズムのチュートリアル

 この問題をより構造的な形式に書き直します。 私たちには学位の順序が与えられています$a_1, \dots, a_n$、新しい値を挿入したい$k$シーケンス全体がグラフィカルになります。 

グラフィカル シーケンスについて推論する標準的な方法は、並べ替え後のプレフィックス制約を使用することです。 

### ステップ

 1. 配列をソートする$a$昇順ではない順に。 

これが必要なのは、グラフィック シーケンスの既知の構造的特徴付けはすべて順序付けされた次数に依存しているためです。 
2. ソートされた配列のプレフィックスの合計を計算します。 

これらにより、最初の段階でどれだけの「需要」が存在するかを迅速に評価できます。$i$頂点。 
3. ボブ学位候補者について$k$、ソートされたシーケンスにそれを挿入することを想像してください。 

挿入する位置は本数によって異なります。$a_i \ge k$なので、構造は次のように滑らかに変化します。$k$変化します。 
4. それぞれをテストするのではなく$k$、スイープ$k$から$0$に$n$、挿入位置の移動方法を維持します。 

これにより、すべての候補に対する並べ替えの再計算が回避されます。 
5. ボブが挿入される各位置について、エルデシュ-ガライの不等式を確認します。$$\sum_{i=1}^t d_i \le t(t-1) + \sum_{i=t+1}^{n+1} \min(d_i, t)$$これは、プレフィックスの合計と、しきい値を超える要素の数に対するフェンウィック ツリーまたはバイナリ検索を使用して維持できます。 
6.すべて集める$k$すべてのプレフィックス制約を満たす値$t$。 

### なぜ効果があるのか

 エルデシュ ガライの定理は、グラフィック次数シーケンスの完全な特徴付けを提供します。 ここでの唯一の難点は、1 次が不明であるが、各不等式に対するその効果が単調であることです。$k$。 として$k$増加すると、ソートされたシーケンス内の値を 1 つだけシフトし、予測可能な方法で各プレフィックス制約への寄与を変更します。 各制約は位置を固定した後に挿入された値において線形であるため、実現可能性はボブが既存の次数と交差する点、または接頭辞制約が厳しくなる点でのみ変化します。 これにより、問題は、無限に多くのグラフ構造をテストすることから、構造イベントの有限セットをチェックすることに軽減されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    a.sort(reverse=True)
    
    prefix = [0] * (n + 1)
    for i in range(n):
        prefix[i + 1] = prefix[i] + a[i]

    # helper: count of elements >= x using binary search
    import bisect

    def count_ge(x):
        # array is decreasing, convert to increasing for bisect
        # so we invert sign logic via manual scan boundary
        lo, hi = 0, n
        while lo < hi:
            mid = (lo + hi) // 2
            if a[mid] >= x:
                lo = mid + 1
            else:
                hi = mid
        return lo

    def check(k):
        # position where k is inserted
        # number of elements >= k
        pos = count_ge(k)

        # build conceptual degree sequence:
        # a[0:pos], k, a[pos:]
        # we test Erdős–Gallai inequalities
        deg_prefix = 0

        # track suffix contributions dynamically
        ptr = 0
        for t in range(1, n + 2):
            if t <= pos:
                deg_prefix += a[t - 1]
            elif t == pos + 1:
                deg_prefix += k
            else:
                deg_prefix += a[t - 2]

            # compute RHS
            # naive but bounded by n constraints per k
            rhs = t * (t - 1)

            # sum min(d_i, t)
            # compute directly
            s = 0
            for i in range(n):
                val = a[i]
                if i == pos:
                    val = k
                if val > t:
                    s += t
                else:
                    s += val
            rhs += s

            if deg_prefix > rhs:
                return False

        return True

    res = []
    for k in range(n + 1):
        if check(k):
            res.append(k)

    if not res:
        print(-1)
    else:
        print(*res)

if __name__ == "__main__":
    solve()
```上記のコードは、エルデシュ ガライの実現可能性チェックを直接翻訳したもので、正しいソート位置に Bob が挿入されています。 挿入位置は二分探索を使用して再計算されるため、ソートされた配列を毎回再構築する必要はありません。 

実装の重要な詳細は、次の概念の挿入を処理することです。$k$すべてのチェック内で物理的に配列を再構築する必要はありません。 現在のバージョンでも、内部でプレフィックス制約が再計算されます。`check`ただし、完全に最適化されたソリューションでは、内部ループを回避するためにヘルパー構造が事前計算されます。

 ## 特殊なケース

 すべての度が 0 の場合、特殊なケースが発生します。 その状況では、何らかのポジティブな$k$既存の次数を増やすことなくエッジを形成する可能性が直ちに侵害されるため、$k=0$有効のままです。 

もう 1 つのエッジ ケースは、すべてが揃っているほぼ完全なグラフです。$a_i = n$。 ここで、何かを追加すると、$k < n$ボブが必要とするエッジは他のすべての頂点よりも少ないため、対称性が崩れますが、これらの頂点はすでに他のすべての頂点との接続を必要とするため、不一致が避けられません。 唯一の有効な選択肢は、$k = n$、完全なグラフ構造が保存されます。 

3 番目の脆弱なケースは、次数の合計が奇数の場合に発生します。 無向グラフの次数の合計は偶数でなければならないため、確実である$k$値はすぐに除外されます。 たとえば、既存の合計が奇数の場合、奇数のみ$k$値はパリティを修正し、構造チェックが適用される前に候補空間を刈り取ることができます。
