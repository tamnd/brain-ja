 ## 解決策
 ## 問題の理解

 黄色、青、赤の 3 つの飾りの山が与えられます。 各山からいくつかの数の装飾品を選択できますが、選択された数は独立していません。 カウントは厳密な算術パターンに従う必要があります。黄色の装飾品をいくつか選択した場合、青は黄色より正確に 1 つ多く、赤は青より正確に 1 つ多くなければなりません。 したがって、選択されたトリプルは常に次の形式になります。$(x, x+1, x+2)$。 

タスクは、利用可能な供給量を超えない、可能な限り最大の有効なトリプルを選択することです。$y, b, r$。 目標は合計を最大化することです$x + (x+1) + (x+2)$、これは最大化と同等です$3x + 3$ですので、実際には最大化しています$x$。 

制約は小さく、各値は最大 100 です。これにより、高度なデータ構造や最適化技術の必要性が即座に排除されます。 100 までのすべての可能性をチェックすることさえ一定時間内であれば簡単であるため、すべての実行可能な選択肢を直接検索するだけで十分です。 

素朴な推論による微妙な失敗例は、可能な最大値から開始すると仮定することです。$x$の最小値から導出される$y, b, r$直接的に働きます。 たとえば、$x = \min(y, b, r)$の場合、依存関係によって有効な制限が変化するため、必要なパターンはすぐに壊れます。 もう 1 つの落とし穴は、各色を独立して最大化することです。これは、色間の厳密な結合を無視します。 

## アプローチ

 ブルートフォースのアイデアは単純です。 私たちはあらゆる可能な値を試します$x$、必要な黄色、青、赤の装飾品の数を計算し、それらが入手可能な供給品の範囲内に収まるかどうかを確認します。 使用されている場合は、使用された合計を計算し、最大値を維持します。 

構造が 1 次元であるため、これが機能します。 すべての有効な構成は単一のパラメータによって完全に決定されます$x$。 そこで、3 次元空間を検索する代わりに、問題を単一の線形スキャンに縮小します。 

ブルートフォースは、範囲が広いため効率的であり続けます。$x$非常に小さいです。 0 から 100 までのすべての値をチェックする場合でも、各 O(1) ずつ最大 101 回のチェックが実行されます。 さらに最適化する必要はありません。 

重要な洞察は、実現可能性は以下によってのみ左右されるということです。$$x \le y,\quad x+1 \le b,\quad x+2 \le r$$したがって、有効な$x$値は、以下の中で最も厳しい制約によって制限されます。$y$、$b-1$、 そして$r-2$。 これにより、問題は単一の最小値の計算に集約されます。

 ## アルゴリズムのチュートリアル

 1. 3 つの値を読み取ります$y, b, r$。 これらは、各装飾タイプの利用可能な数量を表します。 
2. 有効な選択は次の構造に従う必要があることを認識します。$(x, x+1, x+2)$。 問題全体は、実現可能な最大値を決定することに帰着します。$x$。 
3. 各色によって課される上限を個別に計算します。 黄色では最大でも許可されます$x \le y$。 青の要件$x+1 \le b$となり、$x \le b-1$。 赤の要件$x+2 \le r$となり、$x \le r-2$。 
4. すべての制約が同時に満たされるように、これらの境界のうち最小のものを選択します。 これにより、$x = \min(y, b-1, r-2)$。 
5. 次のように使用される装飾品の合計を計算します。$3x + 3$を選択しているので、$x$、$x+1$、 そして$x+2$。 
6. 結果を出力します。 

### なぜ効果があるのか

 すべての有効な構成は単一の整数に一意に対応します$x$。 各色の制約により、許容される最大値が個別に制限されます。$x$。 1 つの制約に違反すると構成全体が無効になるため、正しいソリューションはすべての制約を一度に満たす必要があり、これは最小値を取ることで正確に取得されます。 これにより、どの成分も過大評価することがなくなり、結果として得られるトリプルが有効かつ最大であることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

y, b, r = map(int, input().split())

x = min(y, b - 1, r - 2)
print(3 * x + 3)
```このソリューションは、派生した制約を直接実装します。 の減算`b - 1`そして`r - 2`依存する制約を均一な境界に変換するため、これは重要です。$x$。 最終的な 3 の乗算と 3 の加算により、パラメータ化された形式から選択された装飾の総数が再構築されます。 

よくある実装上の間違いは、青と赤がシフトされた制約を課すことを忘れていることです。 使用する`min(y, b, r)`実現可能性を過大評価し、無効な構成が生成される可能性があります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    y, b, r = map(int, sys.stdin.readline().split())
    x = min(y, b - 1, r - 2)
    return str(3 * x + 3)

# provided samples
assert run("8 13 9") == "24"

# minimum case
assert run("1 2 3") == "6"

# tight blue constraint
assert run("10 2 10") == "3"

# tight red constraint
assert run("10 10 5") == "6"

# all equal-ish balanced
assert run("5 6 7") == "18"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 2 3 | 6 | 最小の有効な増加チェーン |
 | 10 2 10 | 3 | 青がボトルネックになる |
 | 10 10 5 | 6 | 赤がボトルネックになる |
 | 5 6 7 | 18 | バランスのとれた制約 |

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、シフト後の青が制限要因となる場合です。 入力用`10 2 10`、計算します$x \le b-1 = 1$、 それで$x = 1$、合計を与える$3$。 ナイーブ`min(y, b, r)`間違って提案してしまう$x = 2$が必要となるため、これはすでに青の制約に違反しています。$x+1 = 3 > 2$。 

もう一つのケースは、赤が非常に小さい場合です。 入力用`10 10 3`、私たちは得ます$x \le r-2 = 1$、生産$(1,2,3)$。 シフトされた制約を無視しようとすると、赤の使用量が過剰にカウントされ、無効なトリプルが生成されます。 

最後のケースは、すべての値が最小である場合です。`1 2 3`。 アルゴリズムは依然として正常に動作します。$x=1$、結果の構造は最小の有効な構成と正確に一致し、式が特別なケースを使用せずに境界条件を処理していることが確認されます。
