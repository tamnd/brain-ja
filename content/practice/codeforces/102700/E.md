 ## 解決策
 ## アプローチ

 直接的なアプローチは、距離がゼロのノードが見つかるまでツリー内のすべてのノードをクエリすることです。 これは正しいです。デバイスは正確な距離を提供するため、応答が 0 であればオスマンがすぐに特定されます。 ただし、ツリーには次のものがあります。`2^29 - 1`ノード数は 5 億ノードを超えます。 ノードごとに 1 つのクエリでも、クエリの制限をはるかに超えています。 

有用な構造は、ツリーが完全にバランスが取れており、距離によってノードのどちら側にターゲットが含まれているかが明らかになるということです。 まず、ルートを調べると、オスマンの奥深さがわかります。 その後、ノードに立っているとします。`v`そして、オスマンがその下のどこか離れたところにいることを知っています`d`。 の左の子をクエリすると、`v`、可能性は2つだけです。 オスマンが左側のサブツリー内にある場合、答えは次のようになります。`d - 1`1 つの端を近づけたためです。 オスマンが正しいサブツリー内にある場合、答えは次のようになります。`d + 1`、反対側に降りる前に移動したからです。 

これは、すべてのクエリがルートからオスマンまでのパスの 1 ビットを決定することを意味します。 これをツリーのレベルごとに繰り返すだけです。 ブルート フォースは距離によって答えが完全に特定されるため機能しますが、ツリー全体を探索するため失敗します。 単一の子クエリで次の方向が明らかになるという観察により、検索が指数関数的なサイズからツリーの高さまで縮小されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) クエリ | お(1) | 遅すぎる |
 | 最適 | O(n) クエリ | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. クエリノード`1`、ルート。 返される距離は、ルートからのオスマンの深さです。 答えがゼロの場合は、オスマンがルートなので、すぐに終了できます。 
2. 現在のノードを保持します`cur`ルートと残りの距離として`dist`最後のクエリによって返された距離として。 その間`dist`がゼロより大きい場合、左の子をクエリします。`cur`。 
3. 左の子の答えが次の場合`dist - 1`、 動く`cur`その左の子に。 これは、エッジを左側の子に移動すると距離が 1 減少したため、非表示ノードがそのサブツリー内にあることを意味します。 
4. それ以外の場合は移動します`cur`その右の子に。 答えは次のとおりです。`dist + 1`これは、非表示ノードが左側のサブツリーに存在せず、右側の子のどこかに存在する必要があることを意味します。 
5.アップデート`dist`新しい答えとともに。 一度`dist`ゼロになり、`cur`オスマンのノードです。 それを最終的な答えとして出力します。 

これが機能する理由は、どの段階でも、オスマンがサブツリー内にあるという不変条件を維持しているためです。`cur`そしてまさにそれです`dist`から離れた端`cur`。 左側の子をクエリすると、この不変条件を維持しながら、考えられる 2 つの子サブツリーが区別されます。 1 回の決定の後、残りのサブツリーの高さは 1 つ減少します。`n - 1`このような決定を行うことで、目標を達成できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())

def query(x):
    print(x, flush=True)
    return int(input())

cur = 1
dist = query(cur)

while dist != 0:
    left = cur * 2
    ans = query(left)
    if ans == dist - 1:
        cur = left
    else:
        cur = left + 1
    dist = ans

print("!", cur, flush=True)
```機能`query`インタラクティブな部分を処理します。 選択したノードを出力し、すぐに出力をフラッシュして、裁判官が応答できるようにします。 

変数`cur`答えの現在の祖先を保存します。 変数`dist`間の正確な距離を保存します`cur`そしてオスマン。 最初のクエリは、この不変条件をルートで初期化します。 

左の子はいつも`cur * 2`、右の子は`cur * 2 + 1`。 ループはその間のみ実行されるため、コードはこれらの子が存在するかどうかを明示的にチェックする必要はありません。`dist`はポジティブです。 正の残り距離は、現在のノードがリーフになることができないことを意味します。 

Python の整数はオーバーフローしないため、ノード インデックスは最大で`2^29 - 1`安全です。

 | 1 | 1 | 不明 | 1 | 2 | ルートから開始 |
 | 2 | 1 | 2 | 2 | 3 | 右に移動 |
 | 3 | 3 | 3? | 6 | 0 | 左に移動して終了 |

 上の表は方向決定を示しています。 ルートをクエリすると、隠れたノードが 2 エッジ離れたところにあることがわかります。 ノードのクエリ`2`はより大きな距離を返すため、答えはルートの左側のサブツリー内に存在することはできません。 ノードに移動します`3`、次のクエリでターゲットが見つかります。 

次の木を考えてみましょう`n = 4`ノードのオスマンと`5`。 

| ステップ | 現在のノード | 距離 | クエリ | 応答 | 決定 |

 | 2 | 1 | 2 | 2 | 1 | 左に移動 |
 | 3 | 2 | 1 | 4 | 0 | 左に移動して終了 |

 最初のクエリは、Osman がルートの 2 レベル下であることを示しています。 ルートの左側の子をクエリすると距離が減少するため、答えはそのサブツリー内にあります。 同じ推論を繰り返すとノードに到達`5`無関係なブランチを探索することなく。

## テストケース

 元の問題はインタラクティブであるため、通常のオフライン アサーション テストではジャッジのインタラクションを直接再現できません。 次のヘルパーは、事前定義された応答を返すことによってデバイスをシミュレートします。```python
import sys
import io

def solve(responses):
    idx = 0
    n = responses[0]
    answers = responses[1:]

    cur = 1
    dist = answers[idx]
    idx += 1

    while dist != 0:
        left = cur * 2
        ans = answers[idx]
        idx += 1
        if ans == dist - 1:
            cur = left
        else:
            cur = left + 1
        dist = ans

    return cur

assert solve([1, 0]) == 1, "single node tree"

assert solve([3, 2, 1, 0]) == 6, "right then left path"

assert solve([4, 3, 2, 1, 0]) == 5, "left path"

assert solve([4, 3, 4, 3, 2, 1, 0]) == 15, "deep right boundary"

assert solve([29, 28] + [27 - i for i in range(27)] + [0]) >= 1, "maximum depth simulation"

 ## 特殊なケース

 のために`n = 1`、入力はノードのみを含むツリーを表します`1`。 Osman はすでにルートにあるため、最初のクエリは 0 を返します。 ループ条件は直ちに停止し、答えは次のように出力されます。`1`。 子を盲目的に計算するアプローチは失敗します。`2`そして`3`存在しません。 

ノードなどのリーフ ノードの場合`7`木の中で`n = 3`、ルートクエリは距離を返します`2`。 アルゴリズムは 2 つの子の決定を行います。 ルートから正しい子に移動し、次に正しいリーフに移動すると、最後のクエリはゼロを返します。 ループはさらに下降しようとする前に停止します。 

ノードなどの右側のサブツリー内のターゲットの場合`5`、間違った左の子へのクエリは、より大きな距離を返します。 このアルゴリズムは、すべてのケースについて正確な距離の式を知る必要はなく、応答を比較するだけです。`dist - 1`。 距離が減少しなかった場合、左側のサブツリーは不可能であるため、右側の子が唯一の選択肢となります。
