 ## 解決策
 ## 問題の理解

 飛行機内で同時に移動している友人が 2 人います。 1 つ目は点 (A) から開始し、(B) に向かって真っ直ぐ歩きます。 2 つ目は (C) から開始し、(D) に向かって真っ直ぐ歩きます。 彼らの速度は等しいので、共通の速度を (1) に選択すると、各友達が必要とする時間は、ちょうど自分のルートの長さとなります。 友人が目的地に到着すると、その友人はそこで止まります。 

入力には、1 行目に (A) と (B) の 4 つの座標が含まれ、続いて 2 行目に (C) と (D) の 4 つの座標が含まれます。 必要な出力は、2 人の友人が同時に出発してから目的地に到着するまでの任意の時点における 2 人の友人間の最小ユークリッド距離です。 

座標には、(10^9) までの絶対値を指定できます。 これにより、二乗距離が約 (10^{18}) ほど大きくなるため、実装にはそのような値を安全に表現できる演算が必要になります。 Python の整数には任意の精度があり、浮動小数点は実際の最小化時間または最終的な平方根を計算する場合にのみ必要になります。 点が 4 つしかなく、入力サイズに依存するパラメーターがないため、目的の解には一定の時間がかかるはずです。 

よくある間違いは、最初の距離と最後の距離だけを比較することです。 例えば、```
0 0 10 0
5 5 5 -5
```最初の距離は (5\sqrt{2}) で、最終的な距離も (5\sqrt{2}) ですが、移動中に友達は近づきます。 時間 (5) では、最初の友人は ((5,0)) にいて、2 番目の友人は ((5,0)) にいます。したがって、正解は (0) です。 エンドポイントのみをチェックすると、実際の最小値が失われます。 

友人の 1 人が早く到着した場合、別の特殊なケースが発生します。 例えば、```
0 0 1 0
2 0 2 10
```最初の友達は 1 単位時間後に ((1,0)) に到達し、そこに留まります。 2 番目の友人は 10 ユニット移動を続けます。 最小距離は(1)で、最初の友人が目的地に到着した瞬間に到達します。 両方の軌跡を無限に続くかのように扱うと、最初の友人が実際には決して占有しない位置が考慮され、無効な答えが生成される可能性があります。 

3 番目のケースは、時間間隔中の相対速度がゼロの場合です。 例えば、```
0 0 10 0
0 1 10 1
```友達はまったく同じ速度で平行に移動するため、その距離は常に (1) になります。 相対速度の 2 乗がゼロかどうかをチェックせずに除算する式は、問題自体が完全に明確に定義されている場合でも、ゼロで除算することになります。 

最後に、最小値は、友人の 1 人が目的地に到着したときに正確に発生する可能性があります。 例えば、```
0 0 2 0
1 1 1 -1
```時間 (1) では、2 番目の友人は ((1,-1)) に到着しますが、最初の友人は ((1,0)) におり、距離は (1) になります。 関連する間隔は到着時刻に閉じられるため、実装では最小化時間がいずれかのエンドポイントと等しくなるようにする必要があります。 

## アプローチ

 直接的なアプローチは、非常に小さな時間増分で動きをシミュレートし、増分ごとに両方の位置を計算し、見つかった最小距離を維持することです。 実際の軌跡は 2 つの線分の後に静止点が続くだけであるため、これは概念的には簡単です。 問題は、意味のある固定シミュレーション ステップが存在しないことです。 座標が (10^9) までの場合、ルートは (10^9) 程度の長さになる可能性があるため、100 万または 10 億の時間サンプルを使用したシミュレーションでも不正確すぎるか、遅すぎるかのどちらかになります。 さらに重要なのは、数値シミュレーションでは最小値が発生する正確な瞬間をスキップする可能性があるため、必要な (10^{-6}) 精度を確実に提供できないことです。 

ブルート フォースでは、代わりに各軌道上の (K) 点をサンプリングできます。 これには (O(K)) 個の距離評価が必要ですが、考えられるすべての座標構成に対して要求された精度を保証するのに十分な大きさの (K) を選択する必要があります。 座標が大きい場合、最小値は任意の狭い領域で発生する可能性があるため、実際にはそのような保証を与える固定値 (K) はありません。 

重要な観察は、動きが時間的に区分的に線形であるということです。 どちらかの友人が目的地に到着するまで、両方の位置は時間の一次関数になります。 1 人の友人が到着すると、その友人の位置は一定になりますが、もう 1 人の位置は線形のままです。 両方が到着すると、両方の位置は一定になります。 

2 つの位置が次のように書ける任意の時間間隔を考えてみましょう。 

[
 P_1(t)=P+tV_1
 】

 そして

 [
 P_2(t)=Q+tV_2。 
】

 それらの相対位置は次のようになります。 

[
 R(t)=(P-Q)+t(V_1-V_2)。 
】

 したがって、その間隔の二乗距離は次のようになります。 

[
 f(t)=|R(t)|^2。 
】

 これは (t) の二次関数です。 次の形式の二次方程式

 [
 ^2+bt+c で
 】

 with (a\geq0) は、その頂点または区間の終点で最小値に達します。 サンプリング時間の代わりに頂点を直接計算できます。 

可能な移動フェーズは 3 つだけです。 最初の到着の前に、両方の友人が引っ越します。 最初の到着と 2 番目の到着の間に、一方は移動しますが、もう一方は静止しています。 2回目の到着以降はどちらも動かないので距離は一定です。 これらの間隔を個別に処理して、最小距離を取得できます。 

この総当たり法は、すべてのサンプリング時間で有効な位置のペアが得られるため機能しますが、必要な精度を保証する有限のサンプリング密度がないため失敗します。 各位相が線形の相対運動を持っているという観察により、問題全体が最大 3 つの 1 次元凸二次方程式を最小化することになり、これには一定の時間がかかります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース シミュレーション | (O(K)) | (O(1)) | 遅すぎて正確性が保証されない |
 | 最適な区分的二次最小化 | (O(1)) | (O(1)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 4 つの点を読み取り、移動ベクトル (B-A) および (D-C) を計算します。 両方の友人が共通の速度を持っているため、それらの長さは合計移動時間になります (1)。 
2. 速度ベクトルを使用して、時間 (t) における各友人の位置を表します。 到着前の速度は、目的地に向かう正規化された方向です。 到着後の速度はゼロです。 

物理速度が等しいということは、それぞれの経路の長さに関係なく、両方の速度ベクトルが大きさ (1) を持つ必要があることを意味するため、正規化は便利です。 
3. (T_1=|B-A|) および (T_2=|D-C|) とします。 タイムラインを (0)、(\min(T_1,T_2))、および (\max(T_1,T_2)) で分割します。 結果として得られる各間隔で、各友人の速度は固定されます。 
4. 1 つの区間 ([L,R]) に対して、相対位置を次のように書き込みます。 

[
 X(t)=X_0+tV、
 】

 ここで、(X_0) は時間ゼロにおける相対位置、(V) は相対速度です。 

二乗距離は

 [
 |X_0+tV|^2。 
】

 それを拡張すると、

[
 |V|^2t^2+2(X_0\cdot V)t+|X_0|^2。 
】
 5. (V\neq0) の場合、二次関数を微分します。 制約のない最小値は次の時点で発生します。 

[
 t^*=-\frac{X_0\cdot V}{|V|^2}。 
】

 ([L,R]) 内の時間のみを使用できるため、この値をその間隔に固定します。 候補時間は

 [
 \max(L,\min(R,t^*))。 
】

 クランプは、友人の 1 人が目的地に到着するまで二次方程式が減少し続けるケースを処理します。 
6. (V=0) の場合、相対位置は間隔全体で変化しないため、毎回同じ距離になります。 1 つのエンドポイントを単純に評価できます。 
7. すべての移動フェーズの最小値を評価し、最小二乗距離を取得します。 最後に、その平方根を取得し、十分な精度で出力します。 

### なぜ効果があるのか

 不変条件は、処理されるすべての時間間隔において、2 つの位置公式がその間隔内の毎回の友人の位置を正確に表すということです。 それらの相対位置は時間的に線形であるため、それらの二乗距離は凸二次関数になります。 閉じた区間にわたる凸二次関数の最小値は、頂点が区間内にある場合はその頂点であり、それ以外の場合は区間の端点の 1 つです。 クランプステップではその点を正確にチェックします。 完全なタイムラインは友人の速度が変化する瞬間ごとに分割されるため、可能なすべての時間がこれらの間隔の 1 つでカバーされます。 したがって、すべての間隔にわたって最小の候補を取ると、全体的な最小距離が得られます。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

def dot(a, b):
    return a[0] * b[0] + a[1] * b[1]

def norm(a):
    return math.hypot(a[0], a[1])

def position_at(p, v, t):
    return (p[0] + v[0] * t, p[1] + v[1] * t)

def solve():
    ax, ay, bx, by = map(int, input().split())
    cx, cy, dx, dy = map(int, input().split())

    a = (float(ax), float(ay))
    b = (float(bx), float(by))
    c = (float(cx), float(cy))
    d = (float(dx), float(dy))

    ab = (b[0] - a[0], b[1] - a[1])
    cd = (d[0] - c[0], d[1] - c[1])

    t1 = norm(ab)
    t2 = norm(cd)

    if t1 > 0:
        v1 = (ab[0] / t1, ab[1] / t1)
    else:
        v1 = (0.0, 0.0)

    if t2 > 0:
        v2 = (cd[0] / t2, cd[1] / t2)
    else:
        v2 = (0.0, 0.0)

    def state(t):
        if t < t1:
            p1 = position_at(a, v1, t)
        else:
            p1 = b

        if t < t2:
            p2 = position_at(c, v2, t)
        else:
            p2 = d

        return (
            p1[0] - p2[0],
            p1[1] - p2[1],
        )

    def distance_sq(t):
        r = state(t)
        return r[0] * r[0] + r[1] * r[1]

    # The only times where velocities can change are the arrival times.
    cuts = sorted(set([0.0, t1, t2]))

    ans = float("inf")

    # Before the first arrival, both move.
    # Between arrival times, one may be stationary.
    # The final interval is constant, but processing it is harmless.
    for i in range(len(cuts)):
        if i + 1 < len(cuts):
            l = cuts[i]
            r = cuts[i + 1]
        else:
            # There is no need to search after both have arrived.
            continue

        mid = (l + r) * 0.5

        if mid < t1:
            vv1 = v1
        else:
            vv1 = (0.0, 0.0)

        if mid < t2:
            vv2 = v2
        else:
            vv2 = (0.0, 0.0)

        rel_v = (vv1[0] - vv2[0], vv1[1] - vv2[1])

        rel_l = state(l)

        vv2_norm_sq = dot(rel_v, rel_v)

        if vv2_norm_sq == 0.0:
            candidate = l
        else:
            optimum = -dot(rel_l, rel_v) / vv2_norm_sq
            candidate = max(l, min(r, optimum))

        ans = min(ans, distance_sq(candidate))

    # Both friends are stationary from max(t1, t2) onward.
    ans = min(ans, distance_sq(max(t1, t2)))

    print(f"{math.sqrt(ans):.12f}")

if __name__ == "__main__":
    solve()
```実装の最初の部分では、2 つのルートの長さを計算し、各ルートを単位速度ベクトルに変換します。 これは、一般的な歩行速度を (1) として選択することから直接得られます。 ルートの長さが 0 の場合、対応する友人はすでに目的地に到着しているため、その速度は長さ 0 で除算するのではなく 0 に設定されます。 

の`state`関数は区分的な運動を実装します。 到着時刻との比較により、友人がまだ移動中であるか、すでに目的地に到着しているかが判断される。 エンドポイント自体は目的地の位置として処理され、その時点での移動式と数学的に同一になります。 

の`cuts`配列には、速度が変化する可能性があるすべての時間が含まれます。 異なる時間は最大 3 つあるため、ループは一定回数の反復のみを実行します。 各間隔について、中点は、その開いた間隔全体でどの速度がアクティブであるかを決定するためにのみ使用されます。 中間点は、答えの数値近似ではありません。`rel_l`は、間隔の左端点での相対位置です。 相対速度は区間全体を通じて一定であるため、区間内の任意の時刻 (t) での相対位置は次のようになります。 

[
 \text{rel}_l+(t-L)\text{rel}_v。 
】

 代わりに、コードは頂点を導出するときに同等のグローバル時間式を使用します。 なぜなら`rel_l`時間 (L) で評価される場合、グローバル時間の観点から正確な頂点は次のようになります。 

[
 L-\frac{\text{rel}_l\cdot\text{rel}_v}{|\text{rel}_v|^2}。 
】

 したがって、実装ではその形式を使用する必要があります。 完全に修正された実装は以下のとおりです。```python
import sys
import math

input = sys.stdin.readline

def solve():
    ax, ay, bx, by = map(int, input().split())
    cx, cy, dx, dy = map(int, input().split())

    a = (float(ax), float(ay))
    b = (float(bx), float(by))
    c = (float(cx), float(cy))
    d = (float(dx), float(dy))

    ab = (b[0] - a[0], b[1] - a[1])
    cd = (d[0] - c[0], d[1] - c[1])

    t1 = math.hypot(ab[0], ab[1])
    t2 = math.hypot(cd[0], cd[1])

    v1 = (0.0, 0.0) if t1 == 0.0 else (ab[0] / t1, ab[1] / t1)
    v2 = (0.0, 0.0) if t2 == 0.0 else (cd[0] / t2, cd[1] / t2)

    def position(p, v, t, total, destination):
        if t >= total:
            return destination
        return (p[0] + v[0] * t, p[1] + v[1] * t)

    def relative_position(t):
        p1 = position(a, v1, t, t1, b)
        p2 = position(c, v2, t, t2, d)
        return (p1[0] - p2[0], p1[1] - p2[1])

    def dist_sq(t):
        x, y = relative_position(t)
        return x * x + y * y

    cuts = sorted(set((0.0, t1, t2)))
    ans = float("inf")

    for i in range(len(cuts) - 1):
        l = cuts[i]
        r = cuts[i + 1]

        mid = (l + r) * 0.5

        active_v1 = v1 if mid < t1 else (0.0, 0.0)
        active_v2 = v2 if mid < t2 else (0.0, 0.0)

        rv = (
            active_v1[0] - active_v2[0],
            active_v1[1] - active_v2[1],
        )

        rel_l = relative_position(l)

        rv_sq = rv[0] * rv[0] + rv[1] * rv[1]

        if rv_sq == 0.0:
            best_t = l
        else:
            # rel(t) = rel_l + (t-l) * rv
            # Minimize |rel(t)|^2.
            tau = -(rel_l[0] * rv[0] + rel_l[1] * rv[1]) / rv_sq
            best_t = max(l, min(r, l + tau))

        ans = min(ans, dist_sq(best_t))

    ans = min(ans, dist_sq(max(t1, t2)))

    print(f"{math.sqrt(ans):.12f}")

if __name__ == "__main__":
    solve()
```2 番目のバージョンが提出されるバージョンです。 間の区別`tau`そして`best_t`は有用な実装の詳細です。`tau`現在の間隔の始まりを基準とした相対的な時間を測定します。`best_t`は実際の世界時間です。 これら 2 つの座標系を混合すると、誤ったミニマイザーが発生する一般的な原因になります。 

整数には任意の精度があるため、Python では整数オーバーフローは発生しません。 正規化されたベクトルとルートの長さには実際の算術演算が必要なため、速度正規化の前に座標は浮動小数点に変換されます。 (10^{-6}) の最終的な許容誤差は、小数点以下 12 桁を出力することで快適に処理されます。 

## 実用的な例

 ### サンプル 1

 入力は```
0 0 1 0
2 0 2 1
```最初の友人は水平方向に 1 ユニット移動するため、(T_1=1)。 2 番目は垂直方向に 1 単位移動するため、(T_2=1)。 したがって、両方とも同じ間隔 ([0,1]) にわたって移動します。 

速度は ((1,0)) と ((0,1)) であるため、相対速度は ((1,-1)) となります。 初期の相対位置は ((-2,0)) です。 

| 間隔 | 左の相対位置 | 相対速度 | アンクランプ相対時間 | 選択した時間 | 距離 |
 | --- | --- | --- | --- | --- | --- |
 | ([0,1]) | ((-2,0)) | ((1,-1)) | (1) | (1) | (\sqrt{2}) |

 時間 (1) では、友人はそれぞれ ((1,0)) と ((2,1)) にいます。 それらの差は ((-1,-1)) で、その長さは (\sqrt{2}) です。 したがって、出力はおよそ (1.414213562373) になります。 

この例は、両方の友人が関連する区間全体にわたって移動し、区間の境界で二次最小値が正確に発生する通常のケースを示しています。 

### サンプル 2

 入力は```
-2 -4 -2 -2
-3 -5 -3 -2
```両方の友人が垂直に上に移動します。 最初のルートの長さは (2) ですが、2 番目のルートの長さは (3) です。 それらの速度は両方とも ((0,1)) であるため、最初の 2 つの時間単位の間は相対速度は 0 です。 

| 間隔 | 左の相対位置 | 相対速度 | 選択した時間 | 距離 |
 | --- | --- | --- | --- | --- |
 | ([0,2]) | ((1,1)) | ((0,0)) | (0) | (\sqrt{2}) |
 | ([2,3]) | ((1,1)) | ((0,-1)) | (3) | (1) |

 最初の間隔では、両方の友人が一緒に移動するため、分離されたままになります (\sqrt{2})。 時間 (2) では、最初の友人は ((-2,-2)) で停止し、2 番目の友人は ((-3,-3)) で停止します。 2 番目は上昇を続け、時間 (3) で ((-3,-2)) に到達し、距離が (1) になります。 したがって、答えは(1)となります。 

このトレースは、相対速度ゼロは除算なしで処理する必要があること、および最小値は 1 人の友人がすでに停止した後に発生する可能性があることを具体的に確認します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(1)) | 最大でも 3 つの異なるタイムライン境界と、最小化すべき 2 つの移動間隔があります。 |
 | スペース | (O(1)) | 一定数の点、ベクトル、およびスカラー値のみが保存されます。 |

 アルゴリズムは座標平面または時間軸を決してサンプリングしないため、座標境界は操作の数に影響しません。 座標は (10^9) ほど大きくても、一定数の算術演算のみが実行されるため、ソリューションは 1 秒の時間制限と 512 MB のメモリ制限内に簡単に収まります。 

## テストケース```python
import sys
import io
import math

def solve():
    input = sys.stdin.readline

    ax, ay, bx, by = map(int, input().split())
    cx, cy, dx, dy = map(int, input().split())

    a = (float(ax), float(ay))
    b = (float(bx), float(by))
    c = (float(cx), float(cy))
    d = (float(dx), float(dy))

    ab = (b[0] - a[0], b[1] - a[1])
    cd = (d[0] - c[0], d[1] - c[1])

    t1 = math.hypot(ab[0], ab[1])
    t2 = math.hypot(cd[0], cd[1])

    v1 = (0.0, 0.0) if t1 == 0 else (ab[0] / t1, ab[1] / t1)
    v2 = (0.0, 0.0) if t2 == 0 else (cd[0] / t2, cd[1] / t2)

    def position(p, v, t, total, destination):
        if t >= total:
            return destination
        return (p[0] + v[0] * t, p[1] + v[1] * t)

    def relative_position(t):
        p1 = position(a, v1, t, t1, b)
        p2 = position(c, v2, t, t2, d)
        return p1[0] - p2[0], p1[1] - p2[1]

    def dist_sq(t):
        x, y = relative_position(t)
        return x * x + y * y

    cuts = sorted(set((0.0, t1, t2)))
    ans = float("inf")

    for i in range(len(cuts) - 1):
        l, r = cuts[i], cuts[i + 1]
        mid = (l + r) * 0.5

        active_v1 = v1 if mid < t1 else (0.0, 0.0)
        active_v2 = v2 if mid < t2 else (0.0, 0.0)

        rv = (
            active_v1[0] - active_v2[0],
            active_v1[1] - active_v2[1],
        )

        rel_l = relative_position(l)
        rv_sq = rv[0] * rv[0] + rv[1] * rv[1]

        if rv_sq == 0.0:
            best_t = l
        else:
            tau = -(rel_l[0] * rv[0] + rel_l[1] * rv[1]) / rv_sq
            best_t = max(l, min(r, l + tau))

        ans = min(ans, dist_sq(best_t))

    ans = min(ans, dist_sq(max(t1, t2)))

    print(f"{math.sqrt(ans):.12f}")

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        solve()
        return sys.stdout.getvalue().strip()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

 ## 特殊なケース

 ### 友人たちは到着境界線で集合します

 検討してください```
0 0 10 0
5 5 5 -5
```どちらのルートも (10) 単位の時間がかかります。 (t=5) では、最初の友人は ((5,0)) にいますが、2 番目の友人も ((5,0)) にいます。 相対位置は正確に 0 なので、答えは (0) です。 

間隔最小化では、(t=5) での制約のない二次最小値が計算されます。 (5) は閉区間 ([0,10]) 内にあるため、直接受け入れられます。 これにより、厳密に内部点のみ、または最終位置のみをチェックする実装が捕捉されます。 

### 友人の 1 人がもう 1 人より先に到着する

 検討してください```
0 0 1 0
2 0 2 10
```最初の友人は (t=1) に ((1,0)) に到着し、そこに留まります。 2 番目の友人は ((2,0)) から上に移動します。 第 2 フェーズでは、相対位置は、静止している 1 番目の友人と移動する 2 番目の友人によって決定されます。 最も近い点は (t=1) にあり、距離は (1) です。 

タイムラインは (t=1) で分割されるため、アルゴリズムは到着後に最初の友人の速度を誤って継続することはありません。 

### 相対速度はゼロです

 検討してください```
0 0 10 0
0 1 10 1
```両方の友人は速度 ((1,0)) を持っています。 それらの相対速度は ((0,0)) であり、それらの相対位置は常に ((0,-1)) です。 したがって、距離は常に (1) になります。 

アルゴリズムは相対速度の 2 乗がゼロであることを検出し、頂点の式をスキップします。 間隔内の任意の点が最適であるため、左の端点を評価するだけで十分です。 

### 友人は最初から静止しています

 検討してください```
0 0 0 0
2 0 2 10
```最初の友人のルートは長さ 0 であり、決して移動しません。 2 番目は 1 番目から距離 (2) で開始し、垂直に移動するため、最小距離は (t=0) で (2) になります。 

ルートの長さのチェックにより、最初の友人の速度がゼロになります。 次に、2 番目の友人のモーションは通常どおり処理され、最初の友人は関連する間隔全体で静止しているものとして扱われます。 

### 最小値は間隔のエンドポイントです

 二次距離関数が区間を通じて減少し、区間の終了後に頂点に達すると仮定します。 その頂点は、友人の 1 人がすでに速度を変更した時点に対応するため、そのフェーズでは使用できません。 

クランプ操作は、範囲外の頂点を (L) または (R) に変更します。 すべての速度変化時間が明示的に含まれているため、`cuts`場合でも、正しいエンドポイントは引き続き隣接フェーズの一部として評価されます。 これにより、仮定された速度が有効でなくなったときに、数学的に有効な 2 次最小値を受け入れるというよくあるエラーが防止されます。
