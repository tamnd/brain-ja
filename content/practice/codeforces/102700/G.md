 ## 解決策
 ## 問題の理解

 私たちは持っています\(N\)別々の生徒を一列に並べなければなりません。 その中には、\(M\)ばらばらのいじめっ子と被害者のペア。 すべての入力ペア \((A,B)\) に対して、生徒\(A\)学生の前に出なければなりません\(B\)。 声明ではこれを次のように説明しています\(B\)先を行っていない\(A\)。 

重要な構造的特性は、すべての生徒が最大でも 1 つのペアに現れるということです。 したがって、\(M\)制限には以下が含まれます\(2M\)違う生徒たち。 残り\(N-2M\)学生は完全に制限されていません。 

タスクは、次のすべての順列を数えることです。\(N\)全てを満足させる生徒たち\(M\)順序制限とモジュロをカウントする出力\(10^9+7\)。 

の値\(N\)到達できる\(10^5\)したがって、すべての順列を含むものは直ちに不可能になります。 がある\(N!\)順列、さらには\(N=20\)、それはすでに、典型的なコンテストプログラムが列挙できるものをはるかに超えています。 と\(N=10^5\)2 秒の制限があるため、意図したソリューションは本質的に線形である必要があります。\(N\)に応じて、おそらく小さな追加要素が含まれます。\(M\)。 2 番目の制約は特に便利です。\(2M\le 2000\), したがって、最大でも\(1000\)独立した制限。 

不注意な実装が失敗する可能性があるいくつかの特殊なケースがあります。 制限なしで、たとえば、```text
1 0
```まさに\(1\)有効な取り決め。 で割る式\(2^M\)しかし扱いを誤る\(M=0\)誤ってゼロを生成したり、逆数の計算に失敗したりする可能性があります。 

制限が 1 つある境界ケースは次のとおりです。```text
4 1
1 4
```がある\(4!=24\)トータルアレンジメント、ちょうど半分の生徒を配置\(1\)学生の前に\(4\)、したがって、答えは次のとおりです\(12\)。 不注意な解決策では、独立した制限の数のみが重要であるにもかかわらず、式で実際の生徒数を使用しようとする可能性があります。 

最後に、複数の制限には異なる生徒が関与する必要があります。 例えば、```text
6 3
1 2
3 4
5 6
```には 3 つの独立した制限があります。 答えは、\(6!/2^3=90\)。 制限を依存関係として扱うと、間違ったカウントが得られます。 すべてのエンドポイントが最大 1 回発生するという入力保証は、まさに次の単純な除算を行うものです。\(2^M\)有効。 

「すべて等しい値」というフレーズは、ここでは有効な入力ケースを説明していません。ペアに含まれるすべての生徒は、ペアになっている他のすべての生徒とは異なる必要があるからです。 最も近い意味のある同等物は次のとおりです。\(M=0\)、すべての学生に制限がなく、すべての順列が有効です。 

## アプローチ

 直接的なブルート フォース ソリューションでは、次のすべての順列が生成されます。\(N\)学生たち。 順列ごとに、いじめっ子と被害者のペアごとに生徒の位置を特定し、必要な向きがすべて正しいかどうかを確認できます。 これは正しいです。なぜなら、考えられるすべての行が 1 回だけ考慮され、すべての制限が適用される場合に行が正確にカウントされるからです。 

問題は順列の数です。 がある\(N!\)そのうちの、チェック中\(M\)それぞれの制限には \(O(N!\,M)\) の時間がかかります。 各順列を一定時間内に検証できるようにチェックを最適化したとしても、\(N!\)順列はまだ絶望的だろう\(N=10^5\)。 階乗増加が本当の障害です。 

制限の構造からは、さらに強力な観察が得られます。 1 つのペア \((A,B)\) だけを考えてみましょう。 一様に選択された順列では、すべての順列のちょうど半分が配置されます。\(A\)前に\(B\)、残りの半分の場所\(B\)前に\(A\)。 したがって、1 つの制限により、有効な順列の数がちょうど 2 分の 1 に減少します。 

だって全部\(M\)ペアは素であるため、これらの制限は独立して処理できます。 より正式には、すべてのペアの向きを選択することを想像してください。 がある\(2^M\)可能な方向パターン。 これらのパターンはどれも、まったく同じ数の順列によって実現されます。 これは全単射で証明できます。1 つのペアの方向を変更したい場合は、すべての順列でその 2 人の生徒のアイデンティティを交換します。 他のペアに属する生徒はいないため、この交換によりそのペアの方向のみが変更されます。 

がある\(N!\)順列は均等に分布します\(2^M\)向きのパターン。 望ましいパターンは 1 つだけです。つまり、すべてのいじめっ子が対応する被害者に先行するパターンです。 したがって、答えは次のとおりです\[
\frac{N!}{2^M}.
\]答えは剰余が必要なので、\(10^9+7\)、通常の整数の除算は実行できません。 係数は素数なので、\(2^M\)逆モジュラーを持っています。 私たちは計算します\[
N!\cdot (2^M)^{-1}\pmod{10^9+7}.
\]ブルートフォース手法は、カウントしたいオブジェクトを明示的に調べるため機能しますが、オブジェクトの数が非常に多いため失敗します。 すべての素のペアには同じサイズの 2 つの可能な方向があるという観察により、すべての順列を一度に数え、列挙を階乗およびモジュラー逆関数に置き換えることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 |---|---:|---:|---|
 | ブルートフォース | \(O(N!\,M)\) | \(O(N+M)\) | 遅すぎる |
 | 最適 | \(O(N+M)\) | \(O(1)\) 補助 | 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む\(N\)そして\(M\)。 ペアになった生徒の実際のアイデンティティは、最終的な式には影響しません。関連する唯一のプロパティは、\(M\)ペアは素です。 

2. すべて読む\(M\)ペア。 学籍番号を保管したり、読み取り後に検査したりする必要はありません。 彼らの役割は、あることを私たちに伝えることだけです。\(M\)独立した注文制限。 

3. コンピューティング\(N!\)モジュロ\(10^9+7\)。 から始める`fact = 1`からのすべての整数を掛けます。\(1\)を通して\(N\)、各乗算の後に剰余を求めます。 

4. コンピューティング\(2^M\)モジュロ\(10^9+7\)。 これは、\(2^M\)すべての順列が同じサイズの方向クラスに分割されます。 

5. モジュラー逆関数を計算します。\(2^M\)。 フェルマーの小定理により、ゼロ以外の値の場合\(x\)素数を法とする\(P=10^9+7\)、\[
x^{-1}\equiv x^{P-2}\pmod P.
\]したがって、次の逆\(2^M\)で得られます`pow(2, M, P)`その後に別のべき乗剰余演算を行うか、同等の演算を行います。`pow(2, M * (P - 2), P)`。 最初に分母を計算するとより明確になります。 

6. 階乗にその逆数を乗算し、結果の剰余を取得します。\(P\). This gives

\[
N!\cdot (2^M)^{-1}\pmod P,
\]これはまさに必要な有効な取り決めの数です。 

### なぜ効果があるのか

 すべての順列には、それぞれに対して 1 つの明確な方向があります。\(M\) disjoint pairs. Therefore every permutation belongs to exactly one of \(2^M\) orientation patterns.

For any two orientation patterns, we can transform every permutation belonging to the first pattern into a permutation belonging to the second by swapping the two students in each pair whose orientation needs to change. Because the pairs are disjoint, these swaps do not interfere with one another. The transformation is reversible, so all \(2^M\) patterns contain exactly the same number of permutations.

Since all \(N!\) permutations are partitioned among \(2^M\) equally sized classes, each class contains \(N!/2^M\) permutations. The required arrangements are exactly one of these classes, so the algorithm returns the correct count.

## Python Solution

```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n, m = map(int, input().split())

    for _ in range(m):
        input()

    fact = 1
    for x in range(1, n + 1):
        fact = fact * x % MOD

    denominator = pow(2, m, MOD)
    inverse_denominator = pow(denominator, MOD - 2, MOD)

    answer = fact * inverse_denominator % MOD
    print(answer)

if __name__ == "__main__":
    solve()
```入力ループはすべてを消費します\(M\)制限はありますが、意図的に制限を保存しません。 すべてのエンドポイントが異なることが保証されるということは、入力に次のものが含まれていることがわかった後は、その正確な値が無関係になることを意味します。\(M\)制限。 

階乗ループはすべての生徒に対して 1 回だけ実行されます。 すべての乗算の後に係数を取得すると、すべての中間値がおおよそ以下の範​​囲内に保たれます。\(MOD^2\), Python が快適に処理します。 

分母は次のように計算されます。\(2^M\bmod MOD\)。 以来\(M\le1000\)、Python の組み込み関数ではありますが、この累乗は非常に小さいです。`pow`また、はるかに大きな指数に対して累乗剰余演算も効率的に実行します。 

表現`pow(denominator, MOD - 2, MOD)`逆モジュラーを計算します。 これは有効です。\(MOD=10^9+7\)プライムであり、`denominator`で割り切れない\(MOD\)。 

Python では整数オーバーフローの問題はありません。 固定幅の整数を使用する言語では、乗算には十分な幅の型またはモジュラー乗算戦略を使用する必要があります。 

制限は答えを計算する前に読み取られるため、プログラムは次のことも処理します。\(M=0\)正しく。 その場合の分母は\(2^0=1\)、その逆もまた\(1\)、答えは簡単です。\(N!\)。 

## 実用的な例

 ### サンプル 1

 入力は```text
4 2
2 1
4 3
```生徒は 4 人、独立した制限は 2 つあります。 最初のものは学生が必要です\(2\)生徒の前に現れる\(1\)、2番目の場合は学生が必要です\(4\)生徒の前に現れる\(3\)。 

階乗と分母の計算は次のように行われます。 

| ステップ | 変数 | 値 |
 |---|---|---:|
 | 開始 |`fact`| 1 |
 |\(1!\)|`fact`| 1 |
 |\(2!\)|`fact`| 2 |
 |\(3!\)|`fact`| 6 |
 |\(4!\)|`fact`| 24 |

 2 つのペアにより、4 つの可能な方向パターンが得られます。 各パターンの内容は、\(24/4=6\)順列があり、ちょうど 1 つのパターンが\(2\)前に\(1\)そして\(4\)前に\(3\)。 したがって、答えは次のとおりです`6`。

```制限は 1 つだけあり、学生である必要があります。\(1\)生徒の前に立つ\(3\)。 

| ステップ | 変数 | 値 |

 | 開始 |`fact`| 1 |
 |\(1!\)|`fact`| 1 |
 |\(2!\)|`fact`| 2 |
 |\(3!\)|`fact`| 6 |

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 |---|---|---|
 | 時間 | \(O(N+M+\log MOD)\) | 階乗には \(O(N)\) が必要で、読み取り制限には \(O(M)\) が必要で、べき乗剰余には \(O(\log MOD)\) の乗算が必要です。 |
 | スペース | \(O(1)\) 補助 | 制限は保存されずに消費されます。 |

 と\(N\le10^5\)、階乗ループはのみを実行します\(10^5\)繰り返し。 制限数は最大です\(1000\), したがって、合計作業量は 2 秒の制限内に簡単に収まります。 プログラムは、入力機構とは別に、一定の補助メモリも使用します。

import io

MOD = 10**9 + 7

def solution():
    input = sys.stdin.readline

    n, m = map(int, input().split())

    for _ in range(m):
        input()

    fact = 1
    for x in range(1, n + 1):
        fact = fact * x % MOD

    denominator = pow(2, m, MOD)
    inverse_denominator = pow(denominator, MOD - 2, MOD)

    print(fact * inverse_denominator % MOD)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        solution()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

# Provided sample 1
assert run(
    """4 2
2 1
4 3
"""
).strip() == "6", "sample 1"

# Provided sample 2
assert run(
    """4 1
1 3
"""
).strip() == "12", "sample 2"

# Minimum size: one student, no restrictions
assert run(
    """1 0
"""
).strip() == "1", "minimum size"

# No restrictions: every permutation is valid
assert run(
    """5 0
"""
).strip() == "120", "M = 0"

# Three disjoint restrictions
assert run(
    """6 3
1 2
3 4
5 6
"""
).strip() == "90", "three independent pairs"

# Boundary student numbers: the identities do not affect the count
assert run(
    """4 1
1 4
"""
).strip() == "12", "boundary endpoints"

# Maximum-size configuration allowed by the constraints
n = 100000
m = 1000
pairs = "\n".join(f"{2 * i - 1} {2 * i}" for i in range(1, m + 1))
max_input = f"{n} {m}\n{pairs}\n"

expected = 1
for x in range(1, n + 1):
    expected = expected * x % MOD
expected = expected * pow(pow(2, m, MOD), MOD - 2, MOD) % MOD

assert run(max_input).strip() == str(expected), "maximum-size case"

 |---|---:|---|

|`6 3`ペアで`(1,2)`、`(3,4)`、`(5,6)`|`90`| いくつかの独立した制限 |
 |`4 1`ペアで`(1,4)`|`12`| 学生数の境界と単一の制限 |

## 特殊なケース

 最初のエッジケースは\(M=0\)。 のために```text
1 0
```アルゴリズムは制限読み取りループをスキップし、\(1!=1\)、を取得します\(2^0=1\)、その逆数を乗算します\(1\)。 結果は`1`。 より一般的には、`5 0`、結果は\(5!=120\)注文制限がまったくないためです。 

2 番目の特殊なケースは 1 つの制限です。 考慮する```text
4 1
1 4
```アルゴリズムは計算します\(4!=24\)。 がある\(2^1=2\)ペア \((1,4)\) の可能な方向、および両方の方向に同じ数の順列が含まれます。 2 で割ると次のようになります`12`。 これは、学生番号自体が計算式に入力されない理由も示しています。 

3 番目のエッジ ケースは、いくつかの独立した制限です。```text
6 3
1 2
3 4
5 6
```アルゴリズムは計算します\(6!=720\)で割ります\(2^3=8\)、与える`90`。 各ペアは独立して係数の 2 分の 1 に寄与するため、3 つの制限が一緒になって寄与します。\(1/8\)。 

最後のエッジケースは最大入力サイズです。 と\(N=100000\)そして\(M=1000\)、まだ残っているのは\(100000\)階乗乗算と\(1000\)消費する制限。 このアルゴリズムは順列を構築したり、ペアを保存したりすることはありません。そのため、実行時間は生徒の数に対して線形のままであり、補助メモリは一定のままです。 これはまさに、階乗計算式を指定された制限に適したものにするスケールです。
