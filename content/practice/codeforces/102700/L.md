 ## 解決策
 ## 問題の理解

 私たちは、`N × M`セルがクリーンまたはダーティであるグリッド。 を含む細胞は、`S`そして`E`もきれいです。 Vitor は、横に隣接するクリーン セル間を 1 ステップで移動できます。 さらに、同じ行内の 2 つのクリーンなセルは、その行内で厳密にその間にあるすべてのセルがダーティである場合に、トンネルによって接続できます。 同じルールが垂直方向にも適用されます。 

トンネルは任意の長距離接続ではありません。 2 つのクリーン セルが 1 つの行に接続されている場合、それらの間に別のクリーン セルが存在することはできません。 したがって、クリーン セルごとに、4 つの方向のそれぞれに最大 1 つのトンネル エンドポイントが存在できます。 したがって、移動グラフの次数は最大 4 です。 

入力により、グリッドが 1 つだけ与えられます。`S`そしてちょうど1つ`E`。 出力は、からの最短の一連の動きを要求します。`S`に`E`。 最も短いシーケンスが複数存在する場合は、辞書編集上で最も小さい方向文字列を出力する必要があります。 ディレクションキャラクターは、`D`、`L`、`R`、 そして`U`したがって、辞書編集上の順序は次のようになります。`D < L < R < U`。 

この制約は、グリッド自体に 400 万個のセルを含めることができるほど十分に大きいです。 グリッド サイズに比例して作業を実行するアルゴリズムは合理的ですが、すべてのセルに対して行全体または列全体を繰り返しスキャンすることは合理的ではありません。 特に、`O(NM max(N,M))`アプローチは大まかに実行できます`4 · 2000 · 2000 · 2000 = 32 billion`最悪の場合には方向性検査が行われます。 たとえ`O((NM)^2)`建設は 2 秒の制限をはるかに超えています。 有用なトンネル接続をすべて基本的に直線的な時間内に検出する必要があります。 

単純な実装が何も言わずに失敗する可能性があるエッジケースがいくつかあります。 

最小グリッドを考慮する```
2 2
SX
XE
```考えられるすべての中間セルがグリッドの外側にあるため、きれいなパスやトンネルは存在しません。 正しい出力は次のとおりです`-1`。 斜めに離れた 2 つのセルを接続されているものとして扱う不注意な実装や、誤って境界を通過するトンネルを許可してしまうと、パスが誤って検出されてしまいます。 

トンネルは多くのダーティ セルにまたがることができますが、それでも正確に 1 回の移動としてカウントする必要があります。 例えば、```
2 5
SXXXE
.....
```最初の行には以下が含まれます`S`、3 つのダーティ セル、および`E`。 ヴィトールはそこから直接ジャンプできます`S`に`E`、したがって、答えは次のとおりです```
1
R
```側面隣接の移動のみを考慮する実装では、代わりに長さ 4 のパスが返されます。 

トンネルのエンドポイントはクリーンでなければなりません。 例えば、```
2 5
SXXXX
XXXXE
```繋がらない`S`そして`E`、同じ行または列にないためです。 より一般的には、ダーティ セルは障害物であり、トンネルの中間頂点ではありません。 スキャンでは、すべての最大ダーティ セグメントを通過可能として扱うのではなく、クリーン セルを記録し、連続するクリーン セルを接続する必要があります。 

最後に、最短距離だけでは十分ではありません。 で```
3 3
S..
...
..E
```多くのパスの長さは 4 ですが、必要な答えは次のとおりです。`DDRR`。 以来`D < L < R < U`, BFS は、パスが同じ長さのパス間で辞書編集順に考慮されるように編成する必要があります。 単に最短経路を見つけるだけでは不十分です。 

## アプローチ

 最も直接的な解決策は、すべてのクリーンなセルをグラフの頂点として表示することです。 通常の横隣接移動はエッジを与え、トンネルは別のエッジを与えます。 そのグラフが構築されると、通常の BFS から`S`すべてのエッジが正確に 1 つの移動を表すため、最小移動数が得られます。 

グラフを構築する強引な方法は、すべてのクリーン セルに立ち、次のクリーン セルに到達するまで 4 方向すべてを見ることです。 次のクリーン セルは、まさにその方向のトンネルのエンドポイントとなる可能性があります。 最初に遭遇したクリーン セルが唯一の可能なエンドポイントであるため、このアプローチは正しいです。その前に別のクリーン セルが出現した場合、さらに離れた 2 つのセルの間にクリーン セルが存在し、トンネル条件を満たさないことになります。 

問題は繰り返しスキャンすることです。 単一セルは最大でスキャンできます。`M`水平方向に配置し、`N`垂直方向に配置します。 400 万のセルと 2000 の寸法により、これは数百億の検査に達します。 グラフ自体はまばらですが、総当たり検出ではそのまばらさを利用しません。 

重要な観察は、1 回の線形スキャンで行全体または列全体のトンネル隣接を見つけることができるということです。 連続して、最新のクリーンなセルの位置を保持します。 別のクリーン セルに遭遇すると、その 2 つはその行内で連続するクリーン セルとなるため、トンネルによって接続されます。 双方向の接続をすぐに記録できます。 すべての列に対して同じプロセスを繰り返すと、すべての垂直トンネル接続が得られます。 

これが機能するのは、2 つのクリーン セルの間にクリーン セルがない場合にトンネルが存在するためです。 したがって、1 つの行内のすべてのクリーン セルのうち、連続するクリーン セルのみがエッジを必要とします。 同じステートメントがすべての列に当てはまります。 

これら 4 つの方向性近傍が構築された後、BFS は最短パスの問題を解決します。 辞書編集上最小の最短パスを取得するには、各頂点の出方向エッジが次の順序で処理されます。`D`、`L`、`R`、`U`。 BFS は距離に基づいて頂点を処理し、1 つの距離レイヤー内で頂点に到達するために使用されたパスの辞書編集順に頂点を処理します。 辞書順に出力エッジを処理すると、すべての頂点への最初に検出されたパスが、その頂点へのすべての最短パスの中で最小のパスになります。 

したがって、2 つのアプローチ間の関係は単純です。 ブルート フォース ソリューションにはすでに適切なグラフと適切な BFS が備わっていますが、トンネルの近隣ノードを再検出するのに時間が無駄になります。 行と列のスキャンは、繰り返されるすべての検索をグリッド上の 4 つの線形パスに置き換えます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |`O(NM(N+M))`|`O(NM)`| 遅すぎる |
 | 最適 |`O(NM)`|`O(NM)`| 承認済み |

 ## アルゴリズムのチュートリアル

 1. グリッドを読み取り、セルを見つけます。`S`そして`E`。 この問題により、明示的に Vitor がそれらの上に立つことが可能になるため、接続を構築するときは両方をクリーン セルとまったく同じように扱います。 
2. 各方向で最も近いクリーンなセルを表す 4 つの配列を割り当てます。 インデックスのセルの場合`v`の場合、配列にはその左、右、上、下のトンネルの近隣が格納されます。 不在の近傍は次のように表されます。`-1`。 
3. すべての行を左から右にスキャンします。 以前のクリーンなセルのインデックスを保持します。 現在のセルがクリーンで、以前のクリーンなセルが存在する場合、2 つのセルを左右の隣接セルとして接続します。 次に、現在のセルを前のクリーン セルにします。 

この行では 2 つのセルは連続したクリーン セルであるため、それらの間のセルはすべてダーティです。 これらはまさに有効なトンネル ペアです。 行内の他のセルは、前のセルのすぐ右隣になることはできません。 
4. すべての列を上から下にスキャンします。 同じ連続クリーンセルのアイデアを垂直方向に適用します。 連続する 2 つのクリーン セルが見つかった場合は、それらを上下の隣接セルとして接続します。 
5. 次の場所で BFS を開始します。`S`。 すべての頂点の近傍を順番に処理します`D`、`L`、`R`、`U`。 未訪問のすべてのクリーン セルについて、その先行セルとそのセルに入るために使用された方向を記録し、それを BFS キューに入れます。 

順序はタイブレークの場合にのみ重要です。 BFS はすでに最小距離を保証していますが、辞書編集順に方向を処理することで、セルに到達する最初の最短パスが辞書編集上の最小の最短パスであることが保証されます。 
6. BFS が次のいずれかに達したら停止します。`E`または、到達可能なコンポーネントを使い果たしました。 もし`E`訪れたことはありません、印刷`-1`。 
7. もし`E`に達しました。からの先行ポインタに従います`E`に戻る`S`。 保存された各方向は、先行セルから現在のセルへの移動を記述します。 集めた文字を反転してルートを取得します`S`に`E`。 

機能する理由: 行と列のスキャン後、すべての正当なトンネルがエッジで表されます。 より正確には、クリーン セルの場合、左、右、上、または下の最初のクリーン セルが、まさにその方向で可能な唯一のトンネル隣接セルになります。 したがって、構築されたグラフにはすべての正当な手が含まれており、違法な手は含まれていません。 したがって、BFS は真の最小移動数を計算します。 各 BFS 距離レイヤー内では、親がその順序で処理され、その出力方向が次のように処理されるため、頂点は最短パス プレフィックスの辞書編集順に到達します。`D`、`L`、`R`、`U`。 初めて`E`が発見されると、そのパスはその結果、すべての最短パスの中で最短かつ辞書編集的に最小になります。 

## Python ソリューション```python
import sys
from array import array

input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    grid = [input().strip() for _ in range(n)]

    total = n * m

    left = array('i', [-1]) * total
    right = array('i', [-1]) * total
    up = array('i', [-1]) * total
    down = array('i', [-1]) * total

    start = -1
    target = -1

    for r in range(n):
        base = r * m
        row = grid[r]

        prev = -1
        for c in range(m):
            ch = row[c]
            if ch == 'X':
                continue

            v = base + c

            if ch == 'S':
                start = v
            elif ch == 'E':
                target = v

            if prev != -1:
                left[v] = prev
                right[prev] = v

            prev = v

    for c in range(m):
        prev = -1

        for r in range(n):
            v = r * m + c

            if grid[r][c] == 'X':
                continue

            if prev != -1:
                up[v] = prev
                down[prev] = v

            prev = v

    parent = array('i', [-1]) * total
    move = bytearray(total)

    queue = array('i')
    queue.append(start)
    parent[start] = start

    head = 0

    while head < len(queue):
        v = queue[head]
        head += 1

        if v == target:
            break

        r = v // m
        c = v - r * m

        # Lexicographic order: D < L < R < U.
        if r + 1 < n:
            to = down[v]
            if to != -1 and parent[to] == -1:
                parent[to] = v
                move[to] = ord('D')
                queue.append(to)

        to = left[v]
        if to != -1 and parent[to] == -1:
            parent[to] = v
            move[to] = ord('L')
            queue.append(to)

        to = right[v]
        if to != -1 and parent[to] == -1:
            parent[to] = v
            move[to] = ord('R')
            queue.append(to)

        if r > 0:
            to = up[v]
            if to != -1 and parent[to] == -1:
                parent[to] = v
                move[to] = ord('U')
                queue.append(to)

    if parent[target] == -1:
        print(-1)
        return

    path = bytearray()
    cur = target

    while cur != start:
        path.append(move[cur])
        cur = parent[cur]

    path.reverse()

    print(len(path))
    print(path.decode())

if __name__ == "__main__":
    solve()
```4人`array('i')`オブジェクトは、32 ビット符号付き整数を使用して整数セル インデックスを格納します。 400 万個の Python 整数は、パックされた表現よりも大幅に多くのメモリを消費するため、ここでは Python リストよりもこれが望ましいと考えられます。 

行スキャンは、グラフ構築の水平部分を実装します。`prev`最新のクリーンセルです。 新しいクリーンなセルが見つかると、そのセルは次のセルの右隣になります。`prev`、 その間`prev`新しいセルの左隣のセルになります。 それらの間に別のクリーンなセルが存在することはできないため、これはトンネル定義と正確に一致します。 

列スキャンは垂直方向に同じことを行います。 入力は行ごとに保存されるため、セルのインデックスは`(r, c)`は`r * m + c`。 下に移動すると追加されます`m`、上に移動しながら減算します`m`。 実装では事前計算された`up`そして`down`配列なので、境界チェックは主に防御的なものです。 欠落している近傍はすでに次のように表されています。`-1`。 

BFS が使用するのは、`parent[start] = start`開始セルの訪問済みマーカーとして使用されます。 1 つおきの未訪問のセルには親があります`-1`。 これにより、別のブール値の訪問先配列を維持する必要がなくなります。 

行列も`array('i')`。 の`head`インデックスは、最初の要素を繰り返し削除するのではなく、前方に移動します。これにより、`O(n)`の費用`pop(0)`。 

隣人の命令は意図的に行われます`D`、`L`、`R`、`U`。 ASCII 順序は暗黙的に依存されていません。 コードは、必要な辞書編集順に明示的に準拠しています。 セルが最初に検出されると、その前のセルと入ってくる方向が永続的に保存されます。 同じセルへの後のパスは、同じ距離を持ちながら辞書順に小さくすることはできません。これは、BFS が辞書順に親に到達し、そのエッジが辞書順に探索されるためです。 

Python 実装では整数オーバーフローは発生しません。 最大のセルインデックスは次のとおりです。`N*M-1`、最大でも`3,999,999`、符号付き 32 ビット整数内に快適に収まります。 

復興はそこから後退する`E`に`S`。 保存されたすべての方向が BFS 中に使用される前方エッジを記述するため、収集された文字列は最初に反転されます。 電話をかける`reverse()`実際のルートを復元します。

            if ch == 'X':
                continue

            v = base + c

            if ch == 'S':
                start = v
            elif ch == 'E':
                target = v

            if prev != -1:
                left[v] = prev
                right[prev] = v

            prev = v

    for c in range(m):
        prev = -1

        for r in range(n):
            if grid[r][c] == 'X':
                continue

            v = r * m + c

            if prev != -1:
                up[v] = prev
                down[prev] = v

            prev = v

    parent = array('i', [-1]) * total
    move = bytearray(total)

    queue = array('i')
    queue.append(start)
    parent[start] = start

    head = 0

    while head < len(queue):
        v = queue[head]
        head += 1

        if v == target:
            break

        r = v // m

        to = down[v]
        if to != -1 and parent[to] == -1:
            parent[to] = v
            move[to] = ord('D')
            queue.append(to)

        to = left[v]
        if to != -1 and parent[to] == -1:
            parent[to] = v
            move[to] = ord('L')
            queue.append(to)

        to = right[v]
        if to != -1 and parent[to] == -1:
            parent[to] = v
            move[to] = ord('R')
            queue.append(to)

        to = up[v]
        if to != -1 and parent[to] == -1:
            parent[to] = v
            move[to] = ord('U')
            queue.append(to)

    if parent[target] == -1:
        return "-1\n"

    path = bytearray()
    cur = target

    while cur != start:
        path.append(move[cur])
        cur = parent[cur]

    path.reverse()

    return f"{len(path)}\n{path.decode()}\n"

 ## 特殊なケース

 の`2 × 2`到達不能なケース```
2 2
SX
XE
```クリーンなセルが 2 つだけ含まれており、`S`そして`E`、そしてそれらは斜めになっています。 行スキャンでは最初の行に 2 番目のクリーン セルは検出されませんが、列スキャンでは 1 列目に 2 番目のクリーン セルは検出されません。 目的地についても同様です。 したがって、BFS には発信エッジがありません。`S`、 それで`parent[E]`残る`-1`そしてアルゴリズムは出力します`-1`。 

水平に長いトンネルの場合、```
2 5
SXXXE
.....
```行スキャンの最初のレコード`S`以前のクリーンセルと同様に。 3つを無視する`X`細胞、そして出会い`E`そして 2 つのエンドポイントを接続します。 BFS が見る`E`として`R`の隣人`S`したがって、最短距離は 1 で、出力は次のようになります。`1`に続く`R`。 ダーティ セルがグラフに挿入されることはありません。 

長い垂直トンネルの場合、```
5 2
SX
XX
XX
XX
EX
```最初の列には次の内容が含まれます`S`、3 つのダーティ セル、および`E`。 カラムスキャン中に、`S`になる`prev`、ダーティなセルはスキップされ、`E`ついにつながった`S`そのダウンネイバーとして。 BFS は 1 回で到達します`D`動く。 これは、隣接するクリーンなセルのみを移動可能として扱うというよくある間違いを捉えています。 

辞書編集上のケース```
3 3
S..
...
..E
```には長さ 4 の最短ルートがいくつかあります。 BFS は最初に左下のセルに到達します。`D`、右上のセルではなく、`R`、 なぜなら`D`辞書順に最初に来ます。 そこから処理を続行します`D`前に`R`、生産`DDRR`。 任意の隣接順序を使用する BFS は、最短パスを見つける可能性がありますが、返される可能性があります。`DRDR`、`DRRD`、または別の有効な長さ 4 のルート。これは出力要件に違反します。 

最大サイズのケースには 400 万個のセルが含まれていますが、ほとんどすべてが汚れています。 行と列のスキャンは依然として一定の回数だけ各セルに触れます。 BFS の訪問のみ`S`そこには法的なメリットがないからです。 パックされた配列ではメモリがセルの数に比例した状態に保たれるため、最悪の場合の次元によってアルゴリズムのアプローチが変更されることはありません。
