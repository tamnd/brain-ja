 ## 問題の理解

 参照文字列が 1 つあります`s`。 の空でないすべてのサブシーケンス`s`有効な呪文とみなされます。 入力文字列ごとに`a`、いくつかのオリジナルの呪文の後に任意の接尾辞が続いているため、`a`は、正確に、のサブシーケンスとしてまだ埋め込むことができる最長のプレフィックスです。`s`。 

したがって、このタスクは接頭辞と後続の問題になります。 の始まりから`a`に登場できる限りキャラクターを撮り続けていきたいと思っています。`s`厳密にポジションが増加しています。 以前に一致した位置の後に文字を配置できなくなると、プレフィックスは機能しなくなります。 最初の文字さえ一致しない場合、答えは次のようになります。`IMPOSSIBLE`。

## アプローチ

 直接的な解決策は、すべてのクエリを個別に処理し、サブシーケンスの定義をシミュレートすることです。 ポインタを保持しておきます`s`。 クエリの各文字について、前方にスキャンします。`s`そのキャラクターが見つかるまで。 見つかった場合は、ポインタをその上に移動して続行します。 終わりの場合`s`最初に到達した場合は停止し、それまでに一致したプレフィックスを返します。 

サブシーケンスは、増加する位置を選択することによって正確に定義されるため、この強引な方法は正しいです。`s`。 各クエリ文字について、最初に使用可能な出現を選択するのが最適です。後の出現を選択すると、残りの文字に使用できる位置が少なくなるだけです。 問題はその稼働時間だ。 1 つの文字のほぼすべてをスキャンする必要がある場合があります。`s`、これは多くのクエリに対して独立して発生する可能性があります。 と`|s| = 2 * 10^5`およびクエリの合計長`2 * 10^5`、最悪のケースは次のとおりです。`4 * 10^10`キャラクターの比較。 

有益な観察は、ブルート フォースの負荷の高い部分が同じ固定文字列を繰り返し検索していることです。`s`。 文字列はクエリ間で変更されないため、文字が出現する場所に関するすべての情報を一度に準備できます。 

すべての小文字について、その文字が出現する位置のソートされたリストを保存します。`s`。 以前に一致した位置が`p`次のクエリ文字は`c`。 最初の出現が必要です`c`誰の地位がより大きいか`p`。 出現リストはソートされているため、これは正確に、次の値より大きい最初の位置の二分検索になります。`p`。 

これにより、スキャンからの各文字の検索が変更されます。`s`1 つの文字の出現を二分探索します。 しかないので、`2 * 10^5`合計クエリ文字数の場合、計算全体は次のようになります。`O(|s| + L log |s|)`、 どこ`L`すべてのクエリの合計長です。 これらの制限があるため、これでも十分に高速です。 

同じアイデアを完全な次回出現テーブルで実装することもできます。`O(|s| + L)`しかし、Python では、このようなテーブルは各位置に 26 文字の情報を格納するため、かなり多くのメモリを消費する可能性があります。 出現リストはよりシンプルになり、制限に快適に適合します。

 ## アルゴリズムのチュートリアル

 1.読む`s`そして 26 個の出現リストを作成します。 あらゆるポジションについて`i`で`s`、追加`i`に属するリストに`s[i]`。 位置は左から右に処理されるため、すべてのリストは自動的にソートされます。 
2. 変更された各呪文を処理する`a`独立して。 セット`pos = -1`、の文字がないことを意味します`a`まだマッチングされています。 また、回答用の空のリストを作成します。 
3. キャラクターごとに`c`で`a`に属する出現リストを取得します。`c`より厳密に大きい最初の位置を二分探索します。`pos`。 これは可能な限り最も早い場所です。`c`後続の順序を維持したまま配置できます。 
4. そのような位置が存在しない場合は、このクエリの処理を停止します。 長いプレフィックスには同じ一致しない文字が含まれているため、サブシーケンスである可能性はありません。 
5. ポジションが存在する場合は追加します。`c`答えと更新へ`pos`その出来事に。 可能な限り早い出現を選択すると、可能な限り最大のサフィックスが残ります。`s`以降のキャラクターでも利用可能です。 
6. クエリの処理後、一致したプレフィックスが空でない場合は出力します。 最初の文字がすでに失敗している場合、回答リストは空であるため、次のように出力します。`IMPOSSIBLE`。 

### なぜ効果があるのか

 不変条件は、最初の処理後の`k`クエリの文字、`pos`の可能な限り最も早い位置です`s`そのプレフィックスが終了する場所。 最初は一致する文字がないため、これは当てはまります。 次の文字を処理するとき、二分検索はその後の最も古い文字を選択します。`pos`したがって、新しい位置は再び可能な限り早い終了位置になります。 

その出現が存在しない場合、前の接頭辞の有効な配置の後に次の文字を配置する方法はありません。 可能な限り早い段階で以前のキャラクターをすでに保持しているため、他の配置を選択しても右に移動するだけで役に立ちません。 したがって、現在の接頭辞が最も長い有効な接頭辞となり、もはや接頭辞を呪文にすることはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from bisect import bisect_right

def solve():
    s = input().strip()
    n = int(input())

    positions = [[] for _ in range(26)]

    for i, ch in enumerate(s):
        positions[ord(ch) - ord('a')].append(i)

    output = []

    for _ in range(n):
        a = input().strip()

        pos = -1
        answer = []

        for ch in a:
            occ = positions[ord(ch) - ord('a')]

            # First occurrence strictly after pos.
            idx = bisect_right(occ, pos)

            if idx == len(occ):
                break

            pos = occ[idx]
            answer.append(ch)

        if answer:
            output.append(''.join(answer))
        else:
            output.append("IMPOSSIBLE")

    sys.stdout.write('\n'.join(output))

if __name__ == "__main__":
    solve()
```の`positions`配列には、小文字ごとに 1 つのソートされたリストが含まれます。 たとえば、次の場合`s = "abracadabra"`、のリスト`a`すべてのインデックスが含まれます。`a`昇順に表示されます。 

クエリごとに、`pos`での位置を表します`s`最後に正常に一致した文字によって使用されます。 から始まります`-1`、したがって、最初の文字は位置を使用することができます`0`。 

微妙な操作は、`bisect_right(occ, pos)`。 より厳密に大きい位置が必要です`pos`、それ以上ではありません。これは、2 つの後続文字が異なる位置を使用する必要があるためです。 もし`pos`は`4`次の文字は次の位置に出現します`4, 7, 9`、正しい選択は`7`、 それで`bisect_right`必要なインデックスを正確に提供します。 

二分探索が戻ったとき`len(occ)`、前の一致の後に有効な出現はありません。 答えは接頭辞でなければならないため、すぐに停止します。 以降の文字の検査を続けても、有効な長いプレフィックスを生成できませんでした。 

Python には整数オーバーフローの問題はなく、位置の値が次の値を超えることはありません。`len(s) - 1`。 出力はリストに蓄積され、最後に 1 回書き込まれるため、繰り返しのフラッシュやコストのかかる出力操作が回避されます。

def solve():

    s = input().strip()

    positions = [[] for _ in range(26)]

        positions[ord(ch) - ord('a')].append(i)
