 ## 解決策
 ## 問題の理解

 Jolany の 1 年は次のとおりです。`n`日々。 彼女は毎日 1 回タイムマシンを試すことができます。 機械が成功すると、彼女はすぐに次の誕生日を迎えます。 成功確率は与えられたものです`n`値ですが、その順序はランダムに並べ替えられているため、すべての並べ替えは同じ確率で行われます。 

1つの固定注文の場合`p_1, p_2, ..., p_n`、 させて`T`彼女が待つ日数になります。 最初の段階でマシンに障害が発生した場合`k`何日も、彼女はすでに待っています`k`日々。 期待値の便利な形式は次のとおりです。 

[
 E[T] = \sum_{k=1}^{n}\Pr(T\ge k)。 
]

のために`T >= k`、 最初`k`試みはすべて失敗する必要があります。 書くとしたら

 [
 q_i=1-p_i、
 】

 次に、固定順列の場合、

 \sum_{k=1}^{n}q_1q_2\cdots q_k。 
】

 タスクは、この数量を全体で平均化することです`n!`可能な順列。 

公式の制約により、`n`まで`5000`、制限時間は 1 秒、メモリは 512 MB です。 階乗時間アルゴリズムは直ちに不可能であり、`O(n^3)`動的プログラムは大きすぎます。 アン`O(n^2)`アルゴリズムは当然のターゲットであり、次の場合に約 1,250 万の状態更新が必要になります。`n=5000`。 メモリ制限は 1 次元 DP に簡単に対応します。 

よくある間違いを明らかにする境界例がいくつかあります。 と```
1
0
```機械は常に故障するので、答えは正確に`1`。 成功した試行のみをカウントする数式は、誤ってゼロを返す可能性があります。 と```
1
1
```答えは`0`なぜなら、最初の試みは常に成功するからです。 と```
2
0 1
```同じ確率で考えられる 2 つの順序は次のとおりです。`[0,1]`そして`[1,0]`。 彼らの待ち時間は、`1`そして`0`、したがって、答えは次のとおりです`0.5`。 置換なしでサンプリングするのではなく、確率を独立した確率変数として扱う解決策は、このケースを誤ります。 最後に、重複確率を重複排除してはなりません。 ランダムなプロセスは位置の並べ替えであるため、同じ値であっても、依然として異なる位置を占めます。`n!`同様に可能性の高い順列。 

## アプローチ

 直接的なアプローチは、確率配列のすべての順列を列挙することです。 各順列について、その日数をスキャンし、失敗確率を使用して予想される待ち時間を計算します。 これは正しいです。なぜなら、すべての可能な隠れた順序付けを、規定された確率で正確に評価するからです。 残念ながら、`n!`順列、および 1 つのテイクの評価`O(n)`時間、与えること`O(n · n!)`操作。 平`n=10`すでに約 3,600 万の基本的な日レベルの操作を意味しますが、`n=5000`そのアプローチは完全に不可能になります。 

有益な観察は、最初の順序の正確な順序は実際には気にしていないということです。`k`確率。 期間中

 [
 q_1q_2\cdots q_k,
 】

 最初のセットのみ`k`要素が重要です。 一様にランダムな置換の下では、最初のものは`k`要素は一様にランダムを形成します`k`- 元の配列の要素のサブセット。 

させて`e_k`次数の基本対称和であること`k`失敗の確率:

 [
 e_k =
 \sum_{1\le i_1<i_2<\cdots<i_k\le n}
 q_{i_1}q_{i_2}\cdots q_{i_k}。 
】

 まさにあります

 [
 \binom nk
 】

 最初の可能なセット`k`位置、すべて同じ可能性です。 したがって、

 \frac{e_k}{\binom nk}。 
】

 結局のところ、最終的な答えは、

 [
 \sum_{k=1}^{n}\frac{e_k}{\binom nk}。 
】

 基本対称和は、標準的な 1 次元多項式 DP によって計算できます。 ただし、保管する`e_k`これらの値は次のように大きくなる可能性があるため、直接行うのは数値的に不便です。`\binom nk`。 代わりに、確率を 1 つずつ処理しながら正規化されたバージョンを維持します。 

加工後`m`失敗確率、定義

 [
 dp_k =
 \frac{e_k^{(m)}}{\binom mk},
 】

 どこで`e_k^{(m)}`学位は-`k`それらの基本対称和`m`価値観。 毎`dp_k`の数値の積の平均です。`[0,1]`、したがって、それはまた、`[0,1]`。 

次の失敗確率が`q`。 通常の初等対称漸化式は次のようになります。 

e_k^{(m-1)}+q e_{k-1}^{(m-1)}。 
】

 で割った後`\binom mk`、2 つの項は単純な係数を取得します。 

\frac{m-k}{m}dp_k^{(m-1)}
 +
 \frac{k}{m}q,dp_{k-1}^{(m-1)}。 
】

 これにより、`O(n^2)`のみを使用するアルゴリズム`O(n)`メモリ。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |`O(n · n!)`|`O(n)`| 遅すぎる |
 | 最適 |`O(n²)`|`O(n)`| 承認済み |

 ## アルゴリズムのチュートリアル

 1. あらゆる成功確率を変換する`p_i`故障確率に影響を与える`q_i = 1-p_i`。 予想される待ち時間は失敗の連続で自然に表現されるため、これらが DP に必要な量です。 
2.初期化`dp[0] = 1`そして他のすべて`dp[k] = 0`。 確率を処理する前に、空の積は次のようになります。`1`、ただし、正のサイズのサブセットは存在しません。 
3. 失敗確率を一度に 1 つずつ処理します。 現在の処理された値の数が`m`。 あらゆる人にとって`k`から`m`まで`1`、更新

 \frac{(m-k)dp_k+kq_mdp_{k-1}}{m}。 
】

 ループは逆方向に進む必要があるため、`dp[k-1]`処理された値の以前の数からの状態を引き続き参照する必要があります。 順方向を更新すると、その状態が使用される前に上書きされます。 
4. 結局のところ`n`確率は処理されており、`dp[k]`等しい

 [
 \frac{e_k}{\binom nk}、
 】

 これはまさに最初の失敗確率の予想される積です。`k`一様にランダムな順列の位置。 
5.合計`dp[1]`を通して`dp[n]`。 非負の整数値の待機時間のテールサム式により、この合計は Jolany が待機する予想日数になります。 

### なぜ効果があるのか

 加工後`m`値の不変条件は次のとおりです`dp[k]`すべての平均積に等しい`k`-それらの要素のサブセット`m`失敗の確率。 新しい値になると、`q`が追加され、`k`-要素のサブセットは次のいずれかを除外します`q`、その場合は古いものから来ています。`m-1`値、または含まれる値`q`、その場合はもう一方です`k-1`要素は古い価値観から来ています。 がある`m-k`正規化された平均に対する最初のタイプの選択肢と`k`2 番目のタイプで表される選択肢は、まさに上記の繰り返しを示します。 で`m=n`、 毎`k`-要素のサブセットが最初の要素を占める可能性も同様です。`k`ランダムな順列の位置。 したがって`dp[k]`はすべてが最初に起こると予想される確率です`k`試みは失敗します。 これらの確率を合計すると、予想される待ち時間が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    p = list(map(float, input().split()))

    # dp[k] = average product of all k-element subsets
    # among the probabilities processed so far.
    dp = [0.0] * (n + 1)
    dp[0] = 1.0

    m = 0
    for prob in p:
        q = 1.0 - prob
        m += 1
        inv_m = 1.0 / m

        # Descending order is required because dp[k - 1]
        # must still contain the previous-m state.
        for k in range(m, 0, -1):
            dp[k] = ((m - k) * dp[k] + k * q * dp[k - 1]) * inv_m

    answer = sum(dp[1:])
    print(f"{answer:.12f}")

if __name__ == "__main__":
    solve()
```配列`dp`生の合計ではなく、正規化された基本対称合計を格納します。 これにより、巨大な中間値が回避されます。 たとえば、すべての失敗確率が`1`、生の次数 2500 の係数は次のようになります。`\binom{5000}{2500}`これは通常の浮動小数点数の有効範囲をはるかに超えていますが、その正規化された値は単に`1`。 

外側のループが増加します`m`から`1`に`n`。 その時点で、内側のループは、最初のサブセット間に存在する可能性のあるすべてのサブセット サイズを考慮します。`m`価値観。 降順が重要な実装の詳細です。 たとえば、新しい`dp[3]`、`dp[2]`処理後にのみ取得された値でなければなりません`m-1`要素。 

表現```
((m - k) * dp[k] + k * q * dp[k - 1]) * inv_m
```はまさに正規化された再発です。 使用する`inv_m`すべての状態に対して 2 つの除算を実行することを回避します。 すべての値は間隔内に留まります`[0,1]`通常の浮動小数点丸めまでなので、整数のオーバーフローや維持する必要のある巨大な浮動小数点係数はありません。 

入力は 1 つのテスト ケースで構成されます。 ステートメントの実際の入力形式は次で始まります。`n`、続いて`n`確率。

 ## 特殊なケース

 機械に確率がある場合`0`、いつも失敗します。 入力用```
1
0
```アルゴリズムが変換する`p=0`に`q=1`。 で`m=1,k=1`、アップデートにより、`dp[1]=1`、したがって、答えは次のとおりです`1`。 DP には、利用可能な日数を最後まで生き残る確率が含まれており、これはまさに成功のみの計算では見逃される部分です。 

機械に確率がある場合`1`、常に成功します。 のために```
1
1
```失敗確率は`q=0`。 唯一の状態は、`dp[1]=0`、答えを与える`0`。 これは、成功確率の積ではなく失敗確率の積が正しい量である理由も示しています。 

のために```
2
0 1
```失敗の確率は`1`そして`0`。 最初の値の後、`dp[1]=1`。 2 番目の値を追加した後、
 [
 dp_1=\frac{1\cdot+1\cdot 0\cdot 1}{2}=0.5、
 】
 その間
 [
 dp_2=0。 
】
 答えは`0.5`。 これはまさに 2 つの可能な次数の平均です。`[0,1]`そして`[1,0]`、DP が位置間の独立性を仮定せずにサブセットにわたって平均化していることを確認します。 

等しい確率の場合、次のようになります。```
3
0.5 0.5 0.5
```順列は何も変わりません。 失敗確率は常に`0.5`したがって、予想される待機時間は次のようになります。 

[
 0.5+0.25+0.125=0.875。 
】

 DPがプロデュースするのは、`dp[1]=0.5`、`dp[2]=0.25`、 そして`dp[3]=0.125`、すべての値が等しい場合、正規化された対称和は通常の累乗になることが確認されています。 

最後に、いつ`n=5000`そしてあらゆる確率は`0`、 毎`q_i`は`1`。 すべてのサブセット製品も`1`したがって、正規化された各 DP 状態は次のようになります。`1`そして最終的な答えは`5000`。 これは、数学的に正しい答えを可能な最大値に保ちながら、許容される最大の年長に達するため、有用なストレス ケースです。 正規化された DP は、生の基本対称和の実装に必要な膨大な二項係数を構築することなく、これを処理します。
