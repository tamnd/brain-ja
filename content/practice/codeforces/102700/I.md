 ## 解決策
 ## 問題の理解

 (n) 個の建物の列があり、建物 (i) の高さは (h_i) です。 ポーラは任意の建物から開始し、現在の建物より厳密に高く、そこから見える建物に繰り返し移動することができます。 彼女が (i) から (j) に移動した場合、彼女の歩行に追加される距離は (|i-j|) です。 

建物 (j) は、厳密にそれらの間にあるすべての建物の高さが (h_j) 以下の場合に (i) から見えます。 (j) と同じ高さの建物は視界を遮りません。厳密に高い建物だけが視界を遮るからです。 

すべての開始建物 (i) について、有効な一連の移動における最大合計距離が必要です。 すべての移動は厳密に高い建物に移動するため、有効なルートは以前の高さに戻ることはできず、移動グラフは非周期的になります。 

重要な制約は (n\le 10^5) です。 (O(n^2)) アルゴリズムは、最悪の場合でもすでに (5\cdot10^9) 個程度のペア チェックを実行していますが、これは 1 秒の制限で処理できる範囲をはるかに超えています。 (O(n\log n)) 以上の解決策が必要です。 高さは (10^9) まで大きくすることができますが、比較にのみ関与するため、その大きさはデータ構造には影響しません。 

実装が静かに誤動作する可能性がある境界ケースがいくつかあります。 たとえば、単一の建物の場合、`1 / 15`答えがあります`0`、移動する場所がないからです。 すべての建物に左右の候補があると想定した実装では、無効なインデックスにアクセスする可能性があります。 

同じ高さの場合はさらに注意が必要です。 のために`3 / 1 3 3`、答えは`2 0 0`。 最初の建物からは、遠い建物も含めて高さ (3) の両方の建物が見えます。これは、近くの高さ (3) の建物が遠い建物よりも厳密に高いわけではなく、したがってそれを遮らないためです。 最も近い厳密に高い建物のみに基づくアプローチでは、最初の (3) のみが誤って考慮されてしまいます。 

2 つの方向も個別に処理する必要があります。 のために`3 / 5 4 3`、正解は`0 1 2`。 建物 (2) は距離 (2) だけ建物 (1) まで左に移動できますが、右への有効な移動はありません。 右方向のみを検索する実装では、これらのルートがすべて見逃されます。 

## アプローチ

 直接動的プログラミング ソリューションでは、考えられるすべての次の建物を考慮します。 固定された建物 (i) の場合は、最大の高さを維持しながら右にスキャンし、左にも同じことを行います。 より高い建物 (j) が見えるたびに、トランジションが発生します。 

[
 dp[i] = \max(dp[i], |i-j|+dp[j])。 
】

 建物は高さが減少するように処理できるため、(j) が (i) よりも高い場合は常に (dp[j]) が既知です。 この強引な方法は、すべての合法的な最初の手を明示的に考慮しているため、正しいです。 

問題は候補者の数だ。 厳密に高さを増やすことを検討してください。 どの建物からも、その右側のすべての建物が見えます。 アルゴリズムは調べる必要があります

 [
 \frac{n(n-1)}2
 】

 候補ペア。(n=100000) の場合、(4,999,950,000) ペアになります。 すべてのペアの直接可視性チェックはさらに悪化する可能性があり、ペア間の建物が毎回スキャンされる場合は (O(n^3)) に達します。 

有益な観察は、遷移を逆転できるということです。 より高い建物 (j) を修正し、どの低い建物からそれが見えるかを尋ねます。 

(L_j) を、その左側にある (j) より厳密に高い最も近い建物とします。 次に、すべての建物 (i) を満たす

 [
 L_j < i < j
 】

 そして (h_i<h_j) は (j) を見ることができます。 (L_j) がそのような建物に最も近いため、(i) と (j) の間に (h_j) より高い建物は存在できません。 逆に、(i\le L_j) の場合、(L_j) を構築すると (j) の視界が遮られます。 

同じ議論が右側にも当てはまります。 (R_j) が右側の最も高い厳密に高い建物である場合、すべての低い建物 (i) は次のようになります。 

[
 j<i<R_j
 】

 (j) を見ることができます。 

これにより、1 つの建物 (j) が 2 つの範囲更新に変換されます。 下の建物 (i<j) の場合、(j) を通過する遷移は値を持ちます。 

[
 dp[j]+j-i=(dp[j]+j)-i。 
】

 式の形式は定数マイナス (i) であるため、一定の間隔で定数 (dp[j]+j) を格納できます。 低層の建物 (i>j) の場合、遷移は次のようになります。 

[
 dp[j]+i-j=(dp[j]-j)+i、
 】

 したがって、(dp[j]-j) を別の間隔で保存します。 

範囲最大値の更新に続いてポイント クエリを実行するだけで十分です。 建物の高さを下げる加工を行っております。 同じ高さのすべての建物は、データ構造を更新する前にクエリされます。 ポーラは同じ高さの建物間を移動することができないため、この詳細は同じ高さを正しく処理します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(n^2)) | (O(n)) | 遅すぎる |
 | 最適 | (O(n\log n)) | (O(n)) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 高さが厳密に (h_i) より大きい、左に最も近いインデックス (L_i) を計算します。 減少する単調スタックでは、(O(n)) 内のこれらすべての位置が見つかります。 スタックの最上部の高さは最大 (h_i) ですが、(i) にとって最も近い厳密に大きい建物になることはできないため、それを削除します。 
2. 右から左にスキャンしながら、同じ単調スタックの考え方を使用して、高さが (h_i) より厳密に大きい、右に最も近いインデックス (R_i) を計算します。 そのような建物が存在しない場合は、監視員として (n) を使用します。 
3. 建物インデックスを高さの降順に並べ替えます。 同じ高さの建物は同じグループに保持されます。 高さ (H) の建物は厳密に (H) よりも高い高さにのみ移動し、高さ (H) の別の建物には決して移動できないため、このグループ化が必要です。 
4. 右からの動きに対して 1 つの range-chmax 構造を維持し、左からの動きに対して別の range-chmax 構造を維持します。 最初の構造体は値 (dp[j]+j) を格納し、2 番目の構造体は値 (dp[j]-j) を格納します。 (i) でのポイント クエリは、(i) に適用できる最適な格納定数を与えます。 
5. 現在の高さグループ内のすべての建物 (i) について、このグループからの更新を適用する前に両方の構造をクエリします。 左向きの構造が (A) を返す場合、対応するルートの値は (A-i) になります。 正しい構造が (B) を返す場合、対応するルートの値は (B+i) になります。 (dp[i]) をこれらの値の最大値とゼロに設定します。 
6. 現在の高さグループ内のすべての建物の (dp) 値が設定されたら、各建物の構造を更新します (j)。 左側の間隔は ([L_j+1,j)) です。これらは (j) が見える左側の位置であるためです。 そこに (dp[j]+j) を格納します。 正しい間隔は ([j+1,R_j)) であり、そこに (dp[j]-j) を格納します。 
7. すべての高さグループが処理された後、結果の (dp) 配列を印刷します。 値の計算に使用されるすべての遷移は、答えがすでに最終化されている厳密に高い建物からのものです。 

### なぜ効果があるのか

 (i<j) の場合、低層の建物 (i) から高層の建物 (j) への法的な移行を考えてみましょう。 この遷移は、厳密に (h_j) よりも高い建物がそれらの間に存在しない場合にのみ有効です。 定義上、(L_j) は左側にあるそのような建物に最も近いものであるため、この条件は (L_j<i<j) と同等です。 したがって、(j) によって生成された更新は、その左側にある有効な下の建物を正確にカバーします。 右側は左右対称です。 

このようなすべての遷移について、データ構造には (dp[j]+j) が格納されるため、(i) でのクエリは (dp[j]+j-i)、つまり正確に距離 (j-i) に (j) から始まる最適なルートを加えたものを再構築します。 身長の高いグループからの更新はすべてすでに適用されているため、(dp[i]) が計算されるときに、考えられるすべての最初の動きが表現されます。 同じ高さの建物は移動として許可されず、同じ高さのグループからのすべての更新を遅らせることで、相互に影響を与えることがなくなります。 したがって、各建物で生成される最大値は、まさに法定の最大歩行距離となります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

NEG = -10**30

class RangeChmaxPointQuery:
    def __init__(self, n):
        size = 1
        while size < n:
            size <<= 1
        self.size = size
        self.tree = [NEG] * (2 * size)

    def update(self, left, right, value):
        if left >= right:
            return

        size = self.size
        tree = self.tree

        left += size
        right += size

        while left < right:
            if left & 1:
                if value > tree[left]:
                    tree[left] = value
                left += 1

            if right & 1:
                right -= 1
                if value > tree[right]:
                    tree[right] = value

            left >>= 1
            right >>= 1

    def query(self, pos):
        tree = self.tree
        pos += self.size
        result = NEG

        while pos:
            if tree[pos] > result:
                result = tree[pos]
            pos >>= 1

        return result

def solve():
    n = int(input())
    h = list(map(int, input().split()))

    left_greater = [-1] * n
    right_greater = [n] * n

    stack = []

    for i in range(n):
        while stack and h[stack[-1]] <= h[i]:
            stack.pop()

        if stack:
            left_greater[i] = stack[-1]

        stack.append(i)

    stack = []

    for i in range(n - 1, -1, -1):
        while stack and h[stack[-1]] <= h[i]:
            stack.pop()

        if stack:
            right_greater[i] = stack[-1]

        stack.append(i)

    order = sorted(range(n), key=h.__getitem__, reverse=True)

    left_tree = RangeChmaxPointQuery(n)
    right_tree = RangeChmaxPointQuery(n)

    dp = [0] * n

    p = 0
    while p < n:
        q = p + 1
        height = h[order[p]]

        while q < n and h[order[q]] == height:
            q += 1

        for k in range(p, q):
            i = order[k]

            best = 0

            a = left_tree.query(i)
            if a != NEG:
                candidate = a - i
                if candidate > best:
                    best = candidate

            b = right_tree.query(i)
            if b != NEG:
                candidate = b + i
                if candidate > best:
                    best = candidate

            dp[i] = best

        for k in range(p, q):
            j = order[k]

            left_tree.update(
                left_greater[j] + 1,
                j,
                dp[j] + j
            )

            right_tree.update(
                j + 1,
                right_greater[j],
                dp[j] - j
            )

        p = q

    print(*dp)

if __name__ == "__main__":
    solve()
```最初の単調スタック パスは、左側にある最も近い厳密に高い建物を計算します。 の`<=`比較は意図的です。 同じ高さの建物は厳密には高いとはみなされないため、最も近い有効なブロッカーが選択される前にスタックから削除する必要があります。 

2 番目のパスでは、右側の境界の対称計算が行われます。 使用する`n`右側の境界が欠落しているため、後の範囲更新は自然に行われます。`[j+1,n)`特別な処理なしで。 

の`RangeChmaxPointQuery`構造では反復セグメント ツリーが使用されます。 更新は範囲最大値の割り当てのみであり、クエリはポイントのみであるため、通常の意味での遅延伝播は必要ありません。 範囲は (O(\log n)) 個の標準ツリー ノードに分解され、ポイント クエリはルート パス上の (O(\log n)) 個のノードの最大値を取得します。 

2 本の木は距離を表す 2 つの記号を表します。 (i) の右側の宛先 (j) の場合、式は次のようになります。`dp[j] + j - i`したがって、保存される値は次のようになります。`dp[j] + j`。 左側の目的地 (j) の場合、`dp[j] - j + i`したがって、保存される値は次のようになります。`dp[j] - j`。 

同じ高さのグループ内でのクエリと更新の順序は重要です。 高さ (H) の建物が別の高さ (H) の建物が処理される前に構造を更新した場合、2 番目の建物が最初の建物を目的地として誤って使用する可能性がありました。 最初にグループ全体を処理することでそれを防ぎます。 

Python の整数には任意の精度があるため、潜在的に大きな累積歩行距離がオーバーフローすることはありません。 固定幅言語では、64 ビット整数型を使用する必要があります。

4

```最も近い厳密に大きな境界は次のとおりです。 

[
 L=[-1,0,0,0]
 】

 そして

 [
 R=[3,2,3,4]。 
】

 次の表は、身長グループの処理中の重要な状態を示しています。 の`left query`は格納された (dp[j]+j) を表しますが、`right query`格納された(dp[j]-j)を表します。 

| 身長グループ | 建物 | 左のクエリ | 適切なクエリ | (dp) |
 | --- | --- | --- | --- | --- |

 | 2 | 2 | 3 | 3 | 5 |

建物(0)を処理すると答えは(3)になります。 その右側の更新では、位置 (1,2) に (dp[0]-0=3) が格納されます。 建物 (2) では、ルート (2\to0\to3) に対応する (3+2=5) が得られます。

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(n\log n)) | 並べ替えには (O(n\log n)) かかりますが、各建物では一定数の (O(\log n)) のセグメント ツリー操作が実行されます。 |

## テストケース```python
import sys
import io

NEG = -10**30

class RangeChmaxPointQuery:
    def __init__(self, n):
        size = 1
        while size < n:
            size <<= 1
        self.size = size
        self.tree = [NEG] * (2 * size)

    def update(self, left, right, value):
        if left >= right:
            return

        left += self.size
        right += self.size

        while left < right:
            if left & 1:
                self.tree[left] = max(self.tree[left], value)
                left += 1

            if right & 1:
                right -= 1
                self.tree[right] = max(self.tree[right], value)

            left >>= 1
            right >>= 1

    def query(self, pos):
        pos += self.size
        result = NEG

        while pos:
            result = max(result, self.tree[pos])
            pos >>= 1

        return result

def solve_data(data: str) -> str:
    tokens = list(map(int, data.split()))
    n = tokens[0]
    h = tokens[1:n + 1]

    left_greater = [-1] * n
    right_greater = [n] * n

    stack = []

    for i in range(n):
        while stack and h[stack[-1]] <= h[i]:
            stack.pop()

        if stack:
            left_greater[i] = stack[-1]

        stack.append(i)

    stack = []

    for i in range(n - 1, -1, -1):
        while stack and h[stack[-1]] <= h[i]:
            stack.pop()

        if stack:
            right_greater[i] = stack[-1]

        stack.append(i)

    order = sorted(range(n), key=h.__getitem__, reverse=True)

    left_tree = RangeChmaxPointQuery(n)
    right_tree = RangeChmaxPointQuery(n)
    dp = [0] * n

    p = 0
    while p < n:
        q = p + 1

        while q < n and h[order[q]] == h[order[p]]:
            q += 1

        for k in range(p, q):
            i = order[k]
            best = 0

            a = left_tree.query(i)
            if a != NEG:
                best = max(best, a - i)

            b = right_tree.query(i)
            if b != NEG:
                best = max(best, b + i)

            dp[i] = best

        for k in range(p, q):
            j = order[k]

            left_tree.update(
                left_greater[j] + 1,
                j,
                dp[j] + j
            )

            right_tree.update(
                j + 1,
                right_greater[j],
                dp[j] - j
            )

        p = q

    return " ".join(map(str, dp))

def run(inp: str) -> str:
    return solve_data(inp).strip()

assert run("3\n1 3 3\n") == "2 0 0", "equal-height farther building"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1 / 7`|`0`| 最小サイズと有効な遷移がありません |
 |`100000 / 42 42 ... 42`|`0 0 ... 0`| 最大サイズと等高さのバッチ処理 |
 |`5 / 5 4 3 2 1`|`0 1 2 3 4`| 最初の建物の左側の遷移と境界 |
 |`3 / 1 3 3`|`2 0 0`| 等しい高さは表示されたままであり、遠くにある等しい最大値が誤ってブロックされることはありません。 

## 特殊なケース

 単一の建物の場合、入力`1 / 7`与える`0`。 両方の最も近い配列には境界のみが含まれるため、どちらのセグメント ツリーも建物に到達できる更新を受け取りません。 必要に応じて、その DP 値はゼロのままです。 

同じ高さの場合、次の点を考慮してください。`3 / 1 3 3`。 高さ (3) の両方の建物が一緒に処理され、受信されます。`dp=0`。 そのグループが終了した後、インデックス (2) の遠方の建物がインデックス (0) の下部の建物を更新し、(0+2=2) を保存します。 したがって、建物 (0) は答え (2) を取得します。 同じ高さの建物は、グループ全体が評価されるまで更新が遅れるため、互いに更新されることはありません。 

有用な動きがすべて左に進むシーケンスの場合、`5 / 5 4 3 2 1`、最初の建物を除くすべての位置で最も近い、厳密に大きな建物が左側にあります。 最も高い建物を処理すると、最初に答えが 0 になり、次にそれより低い各建物は、最も高い建物までの距離に、すでに計算された継続を加えた値を受け取ります。 答えは次のようになります`0 1 2 3 4`。 

間隔の境界は、片側に厳密に大きな建物がない場合にも重要です。 左側に大きな障害物がない建物の場合、`left_greater`は`-1`、したがって、その更新は位置 0 から始まります。 右側に大きなブロッカーがいない場合、`right_greater`は`n`、したがって、その更新は最後の位置まで拡張されます。 ここで包括的なエンドポイントを使用すると、目的地の建物自体が独自の更新を受信することを誤って許可してしまうため、実装では一貫してハーフオープン間隔が使用されます。`[left, right)`。
