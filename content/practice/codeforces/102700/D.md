 ## 解決策
 ## 問題の理解

 同一のロードされたダイスのコレクションがあります。 1 つのサイコロは、m で割り切れる数を除く、1 から k までのすべての数を表示できます。 許可されているすべての顔の可能性は等しいため、最終的な合計に関して重要なのは、各ロールのモジュロ m の残りだけです。 

タスクは、n 個の独立したロールの合計が m を法とする 0 に一致する確率を見つけることです。 答えは分数としてではなく、モジュラー値として要求されます。 確率が p/q の場合、法 1000000007 での q の逆剰余を p に乗算する必要があります。 

制約はソリューションを強力に形作ります。 サイコロの数は 2 * 10^6 に達する可能性があるため、サイコロを 1 つずつシミュレートすることは不可能です。 辺の数は 2 * 10^6 に達することもありますが、m は 200 にすぎません。これは、解が n や k ではなく m に依存する必要があることを示しています。 O(nm) 付近のアプローチはすでに大きすぎますが、O(m^2 log n) は m が小さいため簡単に管理できます。 

単純な実装を壊すいくつかのエッジケースがあります。 n = 1 の場合、1 つのサイコロは m の倍数を示すことができないため、答えは常に 0 になります。 たとえば、入力`1 6 3`出力があります`0`、欠落している剰余クラスを考慮せずに組み合わせの合計数のみをチェックするソリューションは、ここで失敗する可能性があります。 

k が m より小さい場合、別の微妙なケースが発生します。 たとえば、入力の場合`2 2 5`、考えられるすべての額面値はすでに m 未満ですが、合計は m の倍数になる可能性があります。 可能な合計は 2、3、4 であるため、答えは次のようになります。`0`。 すべての残基が面の間に現れると仮定した解決策では、不正確な分布が作成されます。 

3 番目のケースは、多くの異なる額面が同じ剰余に崩壊する場合です。 入力あり`2 6 3`、各サイコロは 1、2、4、または 5 になります。剰余はすべての可能な剰余に均等に分散されませんが、最終的な答えは次のようになります。`1/2`となり、`500000004`モジュロ 1000000007。サイコロを剰余に対する一様確率変数として扱うと、間違った結果が得られます。 

## アプローチ

 直接的な解決策は、m を法とする現在の合計の確率分布を維持することです。 1 つのサイコロについて、それぞれの余りがいくつの面で生み出されるかを数えます。 次に、この分布をダイ分布と n 回繰り返し畳み込みます。 これは正しいです。部分和に関して必要な情報は m を法とする剰余だけであるためです。 

問題はサイコロの数です。 単純な動的計画法では、各ダイの剰余ごとに m 回の遷移が実行され、O(nm^2) 個の演算が行われます。 n = 2 * 10^6 および m = 200 の場合、これは約 800 億回の演算となり、制限をはるかに超えています。 

重要な点は、同じ遷移を何百万回も適用する必要がないということです。 分布の更新は循環畳み込みであり、x^m を 1 として扱いながら多項式を乗算することと同じです。初期ダイ分布は m 個の係数を持つ多項式です。 その多項式を n 乗すると、すべてのサイコロを振った後の分布が得られます。 

多項式の次数は常に x^m - 1 を法として減算されるため、すべての乗算には O(m^2) の作業のみが必要です。 2 進累乗では、乗算の数が O(log n) に減り、小さな値 m のみに依存するアルゴリズムが得られます。 

この強引な方法は、確率の推移に正確に従うため機能しますが、サイコロの数が大きくなると失敗します。 巡回多項式表現では、同じ数学的プロセスを維持しながら、累乗を使用して繰り返しの遷移をスキップできます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nm^2) | O(m) | 遅すぎる |
 | 最適 | O(m^2 log n) | O(m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各剰余 m を持つ許可された顔の数を数えます。 インデックス r の値は、剰余 r を生成する辺の数を表します。 これらの辺が削除されたため、残りの 0 カウントは常に 0 になります。 
2. この配列を多項式として扱います。ここで、インデックス r は x^r の係数です。 このような 2 つの多項式を乗算することは、2 つの独立したサイコロの余りを加算することに対応します。 m を法とする剰余のみが重要であるため、すべての指数は m を法として換算されます。 
3. 2 進累乗を使用してサイコロ多項式を n 乗します。 多項式 1 から始めます。これは、ゼロのサイコロとゼロの和を表します。 n の現在のビットが設定されるたびに、応答多項式に現在のべき乗多項式を乗算します。 
4. すべての乗算の後に、巡回畳み込みを実行します。 位置 i と j にある 2 つの係数の場合、2 つの剰余がモジュラー加算によって結合されるため、それらの寄与は位置 (i + j) mod m になります。 
5. べき乗後のインデックス 0 の係数は、合計が m で割り切れるロールの可能なシーケンスの数です。 考えられる結果の総数は s^n です。s は 1 つのサイコロ上の有効な面の数です。 係数に s^n の逆剰余を乗算して、カウントを確率に変換します。 

機能する理由: 多項式の不変条件は、任意の数のサイコロを処理した後、係数 i に剰余 i の和を求める方法の数が正確に格納されることです。 乗算は 2 つの独立したサイコロのグループを結合し、m を法とする指数を減算することで和の余りが保存されます。 2 進累乗は、これらの正確な多項式乗算が実行される順序を変更するだけなので、剰余ゼロの最終係数は、すべての n 個のサイコロを直接振ることと同じになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 1000000007

def multiply(a, b, m):
    c = [0] * m
    for i in range(m):
        if a[i]:
            ai = a[i]
            for j in range(m):
                if b[j]:
                    c[(i + j) % m] = (c[(i + j) % m] + ai * b[j]) % MOD
    return c

def solve():
    n, k, m = map(int, input().split())

    cnt = [0] * m
    for x in range(1, k + 1):
        if x % m:
            cnt[x % m] += 1

    base = cnt
    result = [0] * m
    result[0] = 1

    while n:
        if n & 1:
            result = multiply(result, base, m)
        base = multiply(base, base, m)
        n >>= 1

    sides = k - k // m
    answer = result[0] * pow(sides, MOD - 2, MOD) % MOD
    print(answer)

if __name__ == "__main__":
    solve()
```の`multiply`機能はソリューションの中核です。 x^m = 1 で定義されたリング内で乗算を実行します。そのため、すべてのターゲット インデックスは`(i + j) % m`。 配列には常にちょうど m 個の要素があるため、実行時間は k に依存しません。 

初期係数配列は、1 つのダイの実際の面から構築されます。 k は最大 2 * 10^6 であり、その後のすべての操作では m のみを使用するため、すべての k 面の反復処理は安全です。 有効な顔の数は`k - k // m`、正確に m の倍数が削除されるためです。 

べき乗ループは通常の二乗乗算方法に従います。 に保存されている多項式`base`2 つのサイコロの数の累乗を表し、`result`選択したパワーを蓄積します。 多項式の乗算は結合的であるため、これらの乗算の順序によって最終的な多項式は変わりません。 

最後の除算はモジュラー反転によって実行されます。 分子はすでにモジュロ MOD で表されており、分母は同様に起こり得る結果の数です。`sides^n`。 MOD が素数であるため、フェルマーの定理は逆数を与えます。 

## 実用的な例

 入力の場合:```
2 2 2
```各ダイの可能な面は 1 のみです。1 つのダイの多項式は x です。 これを二乗すると x^2 が得られますが、指数は 2 を法として計算されるため 1 になります。

 | n | の最初のビットを使用します。 [0, 1] | [0, 1] |
 | スクエアベース | [1, 0] | [0, 1] |

 剰余ゼロの係数は 1 であり、考えられる結果は 1 つだけであるため、確率は 1 です。 

入力の場合:```
3 2 2
```各サイコロの目は常に 1 になります。3 つのサイコロの合計は 3 であり、これは奇数であるため、答えは 0 になります。 

| ステップ | 現在の多項式 | 結果の多項式 |
 | --- | --- | --- |
 | 開始 | [0, 1] | [1, 0] |

 | 次のビットを使用する | [1, 0] | [0, 1] |

 最終的な多項式には、剰余ゼロの係数はありません。 トレースにより、べき乗によって正確な剰余分布が維持されることが確認されます。

## テストケース```python
import sys
import io

MOD = 1000000007

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout
    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    result = sys.stdout.getvalue()
    sys.stdin = old_stdin
    sys.stdout = old_stdout
    return result

def multiply(a, b, m):
    c = [0] * m
    for i in range(m):
        for j in range(m):
            c[(i + j) % m] = (c[(i + j) % m] + a[i] * b[j]) % MOD
    return c

def solve():
    n, k, m = map(int, input().split())
    cnt = [0] * m
    for x in range(1, k + 1):
        if x % m:
            cnt[x % m] += 1

    ans = [1] + [0] * (m - 1)
    while n:
        if n & 1:
            ans = multiply(ans, cnt, m)
        cnt = multiply(cnt, cnt, m)
        n >>= 1

    valid = k - k // m
    print(ans[0] * pow(valid, MOD - 2, MOD) % MOD)

assert run("3 2 2\n") == "0\n", "sample 2"
assert run("2 6 3\n") == "500000004\n", "sample 3"

assert run("1 6 3\n") == "0\n", "single die cannot reach multiple"
assert run("2 2 5\n") == "0\n", "no valid remainder five"
assert run("2 3 2\n") == "500000004\n", "boundary residue case"
assert run("2000000 2000000 200\n") != "", "large constraint execution"

## 特殊なケース

 のために`1 6 3`、アルゴリズムは分布を作成します`[0, 2, 2]`1 で累乗しても変化せず、係数 0 は 0 のままです。 最終的な確率はゼロであり、ロードされた 1 つのサイコロが 3 の倍数を示すことは決してないという事実と一致します。 

のために`2 2 5`、有効な額面値は 1 と 2 です。1 ダイ多項式は剰余 1 と 2 にのみ係数を持ちます。これを単独で乗算すると剰余 2、3、4 が作成されますが、5 を法とする剰余ゼロは生成されません。アルゴリズムは、すべての剰余が到達可能であると仮定せずに 0 を返します。 

のために`2 6 3`、1 ダイ多項式は次のようになります。`[0, 2, 2]`。 それを二乗すると剰余カウントが得られます`[8, 8, 0]`巡回畳み込み後。 合計 16 個の結果があり、8 個で剰余ゼロが生成されるため、確率は 2 分の 1 となり、次のように表されます。`500000004`モジュロ 1000000007。多項式には確率ではなくカウントが格納されるため、同じ計算が機能します。
