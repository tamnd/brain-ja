 ## 解決策
 ## 問題の理解

 重要な観察は、2 つの異なる鍵文字列が必ずしも 2 つの異なるヴィジュネール暗号を表すわけではないということです。 キー自体が短い文字列の繰り返しである場合、どちらかのキーを定期的に拡張すると、まったく同じシフトのシーケンスが生成されます。 

たとえば、バイナリ アルファベットでは、キーは`0`、`00`、`000`、などはすべて同じ無限シフト シーケンスを生成します。 同じく、`01`そして`0101`両方とも生成されるため、同等です`010101...`。 攻撃者は、そのような各等価クラスから 1 つの代表を試行するだけで済みます。 

空ではないすべての文字列は、最短の文字列の繰り返しとして一意に記述することができます。 その最も短い文字列は、その原始ルートと呼ばれます。 文字列自体が短い文字列の繰り返しとして記述できない場合、その文字列はプリミティブです。 したがって、この問題は、長さが最大で次のプリミティブ文字列をすべてカウントすることと同等です。`k`。 

アルファベットのサイズに合わせて`a`、 がある`a^n`一定の長さの文字列`n`。 させて`P(n)`長さのプリミティブ文字列の数になります`n`。 あらゆる長さの文字列`n`長さが分割される固有の原始根を持っています`n`、それで

 [
 a^n = \sum_{d\mid n} P(d)。 
]

 メビウス反転は与える

 [
 P(n)=\sum_{d\mid n}\mu(d)a^{n/d},
 ]

 どこで`μ`はメビウス関数です。 この標準的なプリミティブワードの公式は、独自のプリミティブルート分解から直接得られます。 

必要な答えは、

 [
 \sum_{n=1}^{k}P(n)。 
]

 アルファベットのサイズは最大です`10^3`、最大キー長は`5 * 10^6`。 重要な制約は後者です。 考えられるすべてのキーを含むアルゴリズムは指数関数的です`k`、さらには`O(k log k)`除数の列挙は不必要にコストがかかります。 線形時間ふるいの後に線形スキャンを行うのが適切なターゲットです。 

不注意な実装を簡単に壊す可能性のあるエッジケースがいくつかあります。 のために`a = 1`そして`k = 3`、あらゆる長さで唯一可能なキーは同一の記号の文字列であるため、すべてのキーは同じ暗号を表し、答えは次のようになります。`1`。 のために`a = 2`そして`k = 2`、考えられる 4 つのキーは次のとおりです。`0`、`1`、`00`、 そして`11`長さは2つまでですが、`00`原始的なルートを持っています`0`そして`11`原始的なルートを持っています`1`、したがって、答えは次のとおりです`4`、 ない`4`加えて、追加の繰り返しキー クラスがいくつかあります。 のために`a = 2`そして`k = 3`、プリミティブ数は次のとおりです。`P(1)=2`、`P(2)=2`、 そして`P(3)=6`、答えを与える`10`。 単純に合計するソリューション`2^n`繰り返されるキーを数回誤ってカウントしていました。 

公式声明では、同じ制約とサンプル動作が示されています。これには、次のようなキーが含まれるという事実も含まれます。`00`そして`11`両方を別々に試す必要はありません。 

## アプローチ

 直接的なアプローチでは、あらゆる長さの可能なすべてのキーが次から生成されます。`1`を通して`k`。 あります

 [
 a+a^2+\cdots+a^k
 ]

 このようなキー。 各キーについて、その最短期間を見つけて、それがプリミティブである場合にのみカウントできます。 これは正しいです。なぜなら、すべての暗号同等クラスの代表が 1 つだけプリミティブであるからです。 

問題は候補者の数だ。 いつ`a >= 2`、合計は`Θ(a^k)`、すでに指数関数的です。 最大値で`a=1000`そして`k=5*10^6`、長さの数-`k`候補者だけでは`1000^{5,000,000}=10^{15,000,000}`。 までも明示的に検査すると、`k`周期性をテストする位置にあると、作業は次のようになります。`Θ(k a^k)`。 列挙自体はすでに不可能であるため、期間テストを最適化してもこのアプローチを救うことはできません。 

有益な観察は、キーを構築する必要がないということです。 必要なのは、各長さのプリミティブ文字列の数だけです。 原始根分解により、きれいな除数の同一性が得られます。 

[
 a^n=\sum_{d\mid n}P(d)。 
]

 メビウス反転はこれを次の式に変換します。`P(n)`。 その式をすべての場合に独立して計算する`n`それでも約数を列挙する必要があります。 2 番目の観察により、そのコストが除去されます。 

から始める

 \sum_{n=1}^{k}\sum_{d\mid n}\mu(d)a^{n/d}。 
]

書く`n = d x`。 それから`d x <= k`、それで

 [
 \sum_{x=1}^{k}a^x
 \sum_{d=1}^{\lfloor k/x\rfloor}\mu(d)。 
]

 接頭辞メビウス和を定義する

 [
 M(t)=\sum_{d=1}^{t}\mu(d)。 
]

 答え全体は次のようになります

 [
 \箱入り{
 \sum_{x=1}^{k}a^x M\left(\left\lfloor\frac{k}{x}\right\rfloor\right)
 }。 
]

 メビウス接頭語の合計が判明すると、すべての項が一定時間で取得されるようになりました。 線形オイラーふるいを使用してすべてのメビウス値を生成し、それらの接頭辞の合計を構築し、さらに 1 回の線形パスで式を評価できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |`Θ(k a^k)`周期性を直接チェックする場合 |`O(k)`候補者ごと | 遅すぎる |
 | 最適 |`O(k)`|`O(k)`| 承認済み |

 ## アルゴリズムのチュートリアル

 1. アルファベットのサイズを読む`a`および最大キー長`k`。 もし`a=1`、すぐに戻ります`1`なぜなら、考えられるすべてのキーは同じシンボルで構成され、同じ原始ルートを持っているからです。 
2. メビウス関数を計算する`μ(1), μ(2), ..., μ(k)`線形オイラーふるいを使用します。 ふるいは各数値の最小の素因数を保持し、次のように構成します。`μ`同時に。 素数はメビウス値を取得します`-1`。 数値がその因数分解ですでに存在する素因数を受け取った場合、そのメビウス値は次のようになります。`0`。 そうしないと、符号が反転します。 
3. メビウス配列をプレフィックスの合計に変換します。 この変換後、位置に格納された値は`t`です

 [
 M(t)=\mu(1)+\mu(2)+\cdots+\mu(t)。 
]

 元のメビウス値は不要になったので、ふるいに使用したのと同じストレージをこれらのプレフィックス合計に再利用できます。 

1. メンテナンス`power = a^x mod MOD`繰り返しながら`x`から`1`に`k`。 現在のところ`x`、追加

 [
 a^x M\left(\left\lfloor\frac{k}{x}\right\rfloor\right)
 ]

 答えに。 プレフィックスの合計は次のようにインデックス付けされます。`k // x`それはまさに可能な約数の範囲だからです`d`置換後`n = d x`。 

1.アップデート`power`それを掛けることで`a`モジュロ`10^9+7`。 最後の反復の後、累積された答えのモジュロを出力します。`10^9+7`。 

### なぜ効果があるのか

 空ではないすべてのキーには一意のプリミティブ ルートがあります。 2 つのキーが同じプリミティブ ルートを持つ場合、同じ周期的なシフト シーケンスが正確に生成されるため、攻撃者が試行する必要があるキーの数は、最大でも長さのプリミティブ文字列の数となります。`k`。 

長さについて`n`、すべての文字列は、長さが分割される固有のプリミティブ文字列の繰り返しです。`n`。 したがって`a^n = Σ_{d|n} P(d)`、メビウス反転は次のようになります。`P(n) = Σ_{d|n} μ(d)a^{n/d}`。 

全体をまとめると`n <= k`合計の順序を交換すると、

 \sum_{x=1}^{k}a^xM(\lfloor k/x\rfloor)。 
]

 アルゴリズムはこの式を正確に評価するため、すべてのプリミティブ ルート クラスは 1 回だけ貢献します。 

## Python ソリューション```python
import sys
from array import array

input = sys.stdin.readline

MOD = 1_000_000_007

def solve():
    a, k = map(int, input().split())

    # With a one-letter alphabet, every key is a repetition
    # of the same one-character primitive root.
    if a == 1:
        print(1)
        return

    # lp[x] = smallest prime factor of x.
    # Using a compact integer array keeps memory usage small.
    lp = array('I', [0]) * (k + 1)

    # mu[x] is stored as -1, 0, or 1.
    mu = array('b', [0]) * (k + 1)
    mu[1] = 1

    primes = array('I')

    # Linear Euler sieve for the Möbius function.
    for i in range(2, k + 1):
        if lp[i] == 0:
            lp[i] = i
            primes.append(i)
            mu[i] = -1

        li = lp[i]

        for p in primes:
            x = i * p
            if x > k:
                break

            lp[x] = p

            if p == li:
                mu[x] = 0
                break
            else:
                mu[x] = -mu[i]

    # lp is no longer needed as a smallest-prime-factor array.
    # Reuse it to store Mertens prefix sums:
    # lp[i] = mu(1) + ... + mu(i).
    prefix = 0
    for i in range(1, k + 1):
        prefix += mu[i]
        lp[i] = prefix

    del mu
    del primes

    ans = 0
    power = a % MOD

    # ans = sum_{x=1}^k a^x * M(floor(k/x)).
    for x in range(1, k + 1):
        ans = (ans + power * lp[k // x]) % MOD
        power = (power * a) % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```オイラーふるいはステップ 2 の実装です。`lp`最小の素因数を記録しますが、`mu`は 3 つの可能な値のみを保存するため、Möbius 関数には符号付きバイト配列で十分です。 

条件`p == li`ふるいの重要な部分です。 もし`p`はすでに最小の素因数です`i`、 それから`i*p`には二乗素因数が含まれているため、そのメビウス値はゼロです。 それ以外の場合は、新しい素数を乗算すると、メビウス値の符号が変更されます。 

ふるいにかけた後、`lp`因数分解には必要なくなりました。 これを Mertens プレフィックス合計に再利用すると、別の大きな配列を割り当てる必要がなくなります。 これは重要な理由です`k`500万に達する可能性があります。 

最後のループは計算されません`P(x)`個別に。 代わりに、変換された合計を直接評価します。 

[
 a^xM(\lfloor k/x\rfloor)。 
]`power`常に含まれています`a^x mod MOD`反復の開始時に`x`。 現在の用語を追加した後に更新すると、off-by-one エラーが回避されます。 Python の整数はオーバーフローしませんが、各乗算の後に削減することで中間値が小さく保たれ、実装が効率的になります。 

特別な場合`a=1`これは単なる微細な最適化ではありません。 各長さで使用可能なキーは 1 つだけであり、すべてのキーが同じ原始ルートを持っているため、最大長のテストが即座に行われます。

関連するメビウス値は次のとおりです。

import sys
from array import array

MOD = 1_000_000_007

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    a, k = map(int, sys.stdin.readline().split())

    if a == 1:
        print(1)
    else:
        lp = array('I', [0]) * (k + 1)
        mu = array('b', [0]) * (k + 1)
        mu[1] = 1
        primes = array('I')

        for i in range(2, k + 1):
            if lp[i] == 0:
                lp[i] = i
                primes.append(i)
                mu[i] = -1

            li = lp[i]

            for p in primes:
                x = i * p
                if x > k:
                    break

                lp[x] = p

                if p == li:
                    mu[x] = 0
                    break
                mu[x] = -mu[i]

        s = 0
        for i in range(1, k + 1):
            s += mu[i]

    sys.stdout = old_stdout

 ## 特殊なケース

 のために`a=1`そして`k=3`の場合、使用可能なキーは 1 つのシンボルの文字列、その 2 つのシンボルの繰り返し、およびその 3 つのシンボルの繰り返しだけです。 どれも同じ原始的な根を持っています。 実装は戻ります`1`すぐにふるいにかけ、不必要なふるい作業を避けます。 

のために`a=2`そして`k=2`、プリミティブ文字列は次のとおりです。`0`、`1`、`01`、 そして`10`。 文字列`00`そして`11`の繰り返しであるため、新しい原始ルートではありません。`0`そして`1`。 メビウス計算では、`P(1)=2`そして`P(2)=4-2=2`、合計は`4`。 

のために`a=2`そして`k=3`、長さ 1 の寄与は`2`。 長さ 2 の 2 つの非プリミティブ文字列は次のようになります。`00`そして`11`、出発`2`プリミティブな文字列。 長さが 3 の場合、適切な約数は 1 だけです。`P(3)=2^3-2=6`。 答えは`2+2+6=10`。 このケースでは、素数の長さのプリミティブ文字列を誤って除外する実装が検出されます。 

のために`a=2`そして`k=4`、長さ 4 の文字列には、長さ 1 と長さ 2 のルートの繰り返しが含まれます。 式は次のようになります

 [
 P(4)=2^4-2^2=12、
 ]

 なぜなら`μ(4)=0`そして`μ(2)=-1`。 合計は

 # 2+2+6+12

 1.

 ]

 これにより、メビウス値がゼロでなければならない二乗因数に関係する除数境界の間違いが検出されます。 

最後に、`a=1`そして`k=5,000,000`、答えは残っています`1`。 これは数学的なエッジケースであると同時に、実際的なストレスケースでもあります。 すべての長さを不必要に構築またはふるい分けるソリューションは、かなりの時間を無駄にする可能性がありますが、特殊なケースはすぐに終了します。
