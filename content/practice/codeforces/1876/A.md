 ## 解決策
 ## 問題の理解

 の間でアナウンスを配布するよう求められています。$n$最小限のコストで住民を支援します。 Pak Chanek は費用を負担して住民に直接通知できます$p$、通知を受け取った各居住者は、その通知を限られた数の他の居住者に転送できます。$a_i$、支払い$b_i$1株あたり。 課題は、すべての住民が確実にメッセージを受信できるようにしながら、総コストを最小限に抑えるために、パク・チャネックが誰に直接通知すべきか、そして住民がメッセージをどのように転送すべきかを決定することです。 

入力は複数のテスト ケースで構成されます。 各テスト ケースが提供するのは、$n$、$p$、配列$a_i$そして$b_i$、各居住者の転送容量と共有あたりのコストを説明します。 出力は、すべての住民に通知するための最小の総コストです。 

制約を考慮すると、次の合計は$n$すべてのテストケースで次を超えない$10^5$、これにより、$O(n \log n)$せいぜいテスト ケースごとのアプローチです。$O(n^2)$解決策は制限時間を超える可能性があります。 エッジケースには、直接通知するコストが非常に高い場合、居住者の転送能力が非常に低い場合、または居住者が 1 人しか存在しない場合が含まれます。 不注意に実装すると、最もコスト効率の高い転送を行う居住者の選択を考慮できず、総コストが最適ではなくなる可能性があります。 

## アプローチ

 単純なアプローチでは、居住者の可能なすべてのサブセットに直接通知を試み、可能なすべての転送シーケンスをシミュレートします。 これは原理的には正しいですが、$n$まで$10^5$、サブセットを列挙することは不可能です。 各テスト ケースには以下が含まれる可能性があります$2^n$明らかに遅すぎる組み合わせです。 

重要な観察は、転送は制限されているものの予測可能であるということです。各居住者には通知できる人数が固定されており、各共有には固定コストがかかります。 したがって、問題は、安価に他の多くの人々に転送できる**貪欲な居住者の選択**に帰着します。 居住者を転送コストで並べ替え、最も安い転送業者を最初に選択できます。 連絡が取れない残りの居住者については、実費を払って直接通知した方が安くなる場合があります。$p$。 

これにより、問題は、ノードが特定のコストで限られた数の他のノードに転送できるグラフ上のコスト最適化 BFS に似た、**貪欲なリソース割り当て** 問題の変形に変換されます。 居住者を増加順に繰り返します$b_i$、リーチできる人の数を蓄積します。 到達可能な居住者の合計がカバーする場合$n$、やめます。 対象外の居住者には費用が発生して直接通知されます$p$、安ければ。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | ブルートフォース | お($2^n \cdot n$) | お($n$) | 遅すぎる |
 | 貪欲なフォワーダー | お($n \log n$) | お($n$) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る$t$。 
2. 各テスト ケースについて、次の内容を読んでください。$n$、$p$、および配列$a$そして$b$。 
3. 各居住者の転送容量とコストを次のようにペアにします。`(b_i, a_i)`。 
4. これらのペアを昇順に並べ替えます$b_i$。 これにより、最も安価なフォワーダーが最初に考慮されるようになります。 
5. 通知済みの居住者数をゼロに初期化します。 
6. ソートされた居住者を反復処理します。 

ａ． 居住者ごとに、通知できる他の人数を決定します。 

b. 株式の総コストを累計します。 

c. 通知された居住者の総数を追跡します。 
7. 利用可能なすべての転送を使用した後、一部の住民が何も知らされていない場合は、料金を支払います$p$残りの居住者ごとに。 
8. 最小コストの合計を出力します。 

**機能する理由**: コストで並べ替えることにより、各居住者がアナウンスを転送するために使用したシェアあたりのコストが可能な限り最小になることが保証されます。 不変条件は、各段階で最小限の限界費用でできるだけ多くの住民をカバーするということです。 より安価なフォワーダーが同じ数をカバーできる場合、私たちは決して高価なフォワーダーを選択せず​​、グローバルな最適性を確保します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, p = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    
    # Pair (cost, capacity) and sort by cost
    residents = sorted(zip(b, a))
    
    remaining = n
    total_cost = 0
    
    for cost, cap in residents:
        use = min(cap, remaining)
        if cost < p:
            total_cost += cost * use
            remaining -= use
        else:
            break
    
    # Remaining residents are notified directly at cost p
    total_cost += remaining * p
    print(total_cost)
```### 実装の詳細

 住民を並べ替える`b_i`常に最も安いフォワードを最初に使用するようにします。 の`min(cap, remaining)`残りの居住者より多くのシェアを決して割り当てないようにします。 もしそうなら早く休​​憩しましょう`b_i >= p`直接通知したほうが安いからです。 これにより、不必要な計算が回避されます。 高速 I/O の使用 (`sys.stdin.readline`) 大量の入力を効率的に処理します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = []
    t = int(input())
    for _ in range(t):
        n, p = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        residents = sorted(zip(b, a))
        remaining = n
        total_cost = 0
        for cost, cap in residents:
            use = min(cap, remaining)
            if cost < p:
                total_cost += cost * use
                remaining -= use
            else:
                break
        total_cost += remaining * p
        output.append(str(total_cost))
    return "\n".join(output)

# provided samples

assert run("1\n1 5\n1\n2") == "2", "single resident cheaper by forwarding"

 ## 特殊なケース

 エッジケースには、単一の居住者、転送コストが直接コストを超える居住者、および他のすべてをカバーするのに十分な容量を持つ居住者が含まれます。 このアルゴリズムは、最初に最も安価な転送を正しく選択し、転送がコスト効率が悪い場合は直接通知に切り替えます。 たとえば、入力では次のようになります。```
1 5
1
10
```このアルゴリズムは、直接コスト 5 よりも小さいコスト 1 で単一の居住者に転送し、最小の総コスト 1 を生成します。
