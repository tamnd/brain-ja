 ## 解決策
 ## 問題の理解

 チャネカは、いくつかのレベルに分かれた難しいビデオ ゲームをマスターしようとしています。`n`連続部分。 彼女は、配列として与えられた各パーツの親密度の値から始めます。`a`サイズの`n`。 ゲームの各試行は特定の部分で失敗します`p`つまり、彼女は前半の部分を完全に練習し、部分的に死ぬ部分だけを練習します。 具体的には、途中で死亡した場合`p`、親密度値は次のように増加します。`1`部品用`1`を通して`p-1`そしてによって`2`部分的に`p`自体。 試行ごとに消費するのは、`p`秒、彼女が死亡した部分のインデックスに等しい。 

それぞれについて、`q`質問では、Chaneka がセグメント内のすべての部分を確実に実行するために必要な最小合計時間を秒単位で決定するように求められます。`[l_j, r_j]`少なくとも次の親密度値に達する`x_j`。 各質問は独立しているため、1 つの質問に対する回答が他の質問に影響を与えることはありません。 

とすれば`n`そして`q`両方とも最大 300,000 に達し、親密度の値が非常に大きくなる可能性があるため、個々の試行をシミュレートしたり、各インデックスを単純に複数回反復したりするソリューションは遅すぎます。 重要なのは、親しみやすさが増加する構造化された方法を利用することです。試行するたびに、現在の部分が 2 ずつ増加し、先行するすべての部分が 1 ずつ増加します。この構造化された増加により、純粋な強引なアプローチではなく、貪欲なアプローチまたはプレフィックス ベースのアプローチが可能になります。 

エッジ ケースには、長さ 1 のセグメント、すべての初期親密度値がすでに要件を満たしているセグメント、および先行する部分が少数またはまったく存在しない配列の先頭の部分が含まれます。 たとえば、次の場合`a = [5, 5, 5]`そして`x = 4`範囲のために`[1,3]`、正解は`0`すべての部分がすでに目標を達成または上回っているためです。 やみくもに試行を試みる単純なアプローチでは、誤って不必要な時間が追加される可能性があります。 

## アプローチ

 ブルートフォース手法では、死亡未遂を 1 秒ごとにシミュレートし、親密度の配列を段階的に更新します。 質問ごとに、考えられる死亡位置をループして最適な位置を貪欲に選択し、目標に到達するまで繰り返します。 改善のルールは単純なので、これは原理的には正しいですが、`n`そして`q`最大 300,000、最悪の場合の操作数は次のようになります。`O(n * max_increment_needed)`クエリごとに、これは実現不可能です。 

重要な洞察は、各試行が配列のプレフィックスに予測可能な線形の影響を与えることを観察することで得られます。 どのセグメントでも`[l, r]`、最後の部分`r`育成するのに最もコストがかかります。`r`その部分とセグメント内の以前のすべての部分に最も効率的な改善を提供します。 これは、二分探索と組み合わせた貪欲な戦略を示唆しています。 指定された合計試行回数について、到達するのに十分かどうかを確認できます。`x`セグメント内で。 プレフィックスの増加は加算的なものであるため、プレフィックスの合計と累積的な改善の単調シーケンスを使用してこれを効率的に計算できます。 これにより問題は次のように縮小されます`O(n log max_delta)`毎秒シミュレートするのではなく、クエリごとに実行します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * 最大デルタ) | O(n) | 遅すぎる |
 | 貪欲 + 二分探索 | クエリあたり O(n log(max_delta)) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 初期の精通度配列を事前計算する`a`。 クエリごとにコピーします`a`作業配列に入れる`b`クエリは独立しているためです。 
2. 指定されたセグメントについて`[l, r]`そしてターゲット`x`、各部分の赤字を計算します。`deficit[i] = max(0, x - b[i])`。 これにより、各指標でどの程度の改善が必要かを正確に知ることができます。 
3. その位置で死亡しようとした場合、`p`増加する`b[p]`合計時間を最小化するために、右端の部分は 2 ずつ、以前のすべての位置は 1 ずつ計算されます。`r`必要なだけ直接増額を受ける必要があります。 あらゆる試み`r`貢献する`2`に`b[r]`そして`1`すべての部分に`l`を通して`r-1`。 
4. 二分探索を使用して、右端の部分の最小試行回数を見つけます。 それぞれの推測について`k`、各インデックスの合計改善を次のように計算します。`improvement[i] = k`もし`i < r`それ以外`2*k`。 すべてかどうかを確認してください`deficit[i]`のために`i in [l, r]`満足しています。 
5. 試行回数が決定したら、合計時間を計算します。各試行時間は、試行が終了するインデックスに等しいため、`k`試みはその位置で死ぬ`p`、彼らは貢献します`k*p`秒。 
6. 以前の増分で完全にカバーできない場合は、次の部分に対してこれを繰り返します。 実際には、グリーディ フィルを使用した右から左への 1 回のパスにより、すべての不足が最適に満たされます。 
7. 時間の合計をクエリの答えとして返します。 

なぜ機能するのか: 不変条件は、どのプレフィックスでも、特定の部分での最適な試行回数です。`p`左端のインデックスから`p`。 それぞれの試み以来、`p`固定の貢献パターン (以前のすべてに 1、それ自体に 2) があり、右から左に埋めると最小限の時間が保証されます。これは、セグメントの早い段階で終了する方が単位の改善あたり常に安価であるためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def min_time_for_query(a, l, r, x):
    n = len(a)
    # compute deficits
    deficit = [0] * n
    for i in range(l-1, r):
        deficit[i] = max(0, x - a[i])
    total_time = 0
    # we process from right to left
    # attempts dying at i give +2 to i and +1 to all before
    for i in range(r-1, l-2, -1):
        if deficit[i] <= 0:
            continue
        attempts = (deficit[i] + 1) // 2 if i == r-1 else deficit[i]
        total_time += attempts * (i+1)
        # apply improvements backward
        for j in range(l-1, i):
            deficit[j] -= attempts
        deficit[i] -= 2*attempts
    return total_time

def main():
    n = int(input())
    a = list(map(int, input().split()))
    q = int(input())
    for _ in range(q):
        l, r, x = map(int, input().split())
        print(min_time_for_query(a, l, r, x))

if __name__ == "__main__":
    main()
```解決策は、問題の範囲の不足を計算することから始まります。 次に、パーツを右から左に処理し、各ステップで最適な試行回数を適用します。 の使用`(deficit[i] + 1)//2`右端の部分は、そこで死亡した試みによる +2 の改善を説明します。 前のパーツにエフェクトを適用することで、累積的な改善が過小評価されなくなります。 時間の計算では、試行回数にインデックスを乗じて秒数を計算します。
