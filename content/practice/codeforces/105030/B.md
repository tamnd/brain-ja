 ## 解決策
 ## 問題の理解

 私たちは、単一の制約された組立ラインのように動作する 3 つの連続ステージからなる生産パイプラインをモデル化しています。 各最終ユニットであるハーベスターは、ステージ I の 1 つのユニットとステージ II の 1 つのユニットで構成されており、最初にこれらの両方を初期のステージで生産する必要があります。 ステージ I では無制限の金属スクラップから未加工コンポーネントを製造し、ステージ II ではステージ I の出力を精製し、ステージ III では 2 つの中間コンポーネントのそれぞれ 1 つのユニットから最終ハーベスターを組み立てます。 

各ステージには 1 台の専用マシンがあります。 そのマシンは一度に 1 つのアイテムしか処理できず、アイテムは順番にステージを通過する必要があります。 ただし、異なるステージは同時に動作する可能性があるため、ステージ II が 1 つのアイテムを精製している間に、ステージ I がすでに次のアイテムを生産しており、ステージ III が利用可能な場合は前のペアを組み立てている可能性があります。 

目標は、空のシステムから n 台の最終ハーベスタを生産するのに必要な最小時間を計算することです。 

制約は、n が最大 1000 であることを示していますが、ステージ時間 t2 および t3 は最大 100000 まで大きくなる可能性があります。これにより、時間単位ごとに追跡するシミュレーションは除外されます。 単純な離散時間シミュレーションには最大 O(答え) ステップが必要で、最悪の場合は約 10^8 以上に達する可能性があります。 代わりに、理想的には時間のシミュレーションではなく定常状態のスループットを推論することにより、ソリューションは O(n) または O(n log n) 時間で動作する必要があります。 

パイプラインのバランスが崩れると、微妙な問題が発生します。 たとえば、ステージ II がステージ I よりもはるかに遅い場合、ステージ I には準備完了コンポーネント I の大きなバッファが蓄積されます。ステージ III が遅い場合、完了したペアはキューに入れられます。 即時消費を想定したり、キューの蓄積を無視した単純なアプローチでは、完了時間を誤ってカウントします。 

t1 が非常に小さい場合、特に t1 = 1 の場合、別のエッジ ケースが発生します。その場合、ステージ I は消費されるよりも早くコンポーネントを生産するため、ステージ II とステージ III がボトルネックになります。 逆に、t3 が非常に小さい場合、最終組み立ては制限されず、ボトルネックは初期の段階に移動します。 

最大の難点は、スループットが最も遅い実効パイプライン セグメントによって左右されることですが、最初の数ユニットではパイプラインの遅延が依然として重要であることです。 

## アプローチ

 強引な方法は、生産システム全体を秒単位でシミュレートし、コンポーネント I と II のキューを維持し、各マシンがいつ空になるかを追跡することです。 各タイムステップで生産の進捗状況を更新し、可能な場合は完成したアイテムを前に進めます。 これはプロセス ルールに直接従うため、正しいです。 ただし、最終的な答えは n と (t1 + t2 + t3) の積と同じくらい大きくなる可能性があるため、このシミュレーションには最大約 10^8 のタイム ステップが必要になる可能性があり、これでは遅すぎます。 

重要な観察は、パイプラインが満たされた後、システムが一定の間隔でハーベスターが生成される定常状態に達することです。 生産ラインは、ステージ III が必要な両方の入力を受信できる頻度によって決定される固定サイクル タイムを持つ 3 ステージ パイプラインのように動作します。 ステージ I と II は事実上、ステージ III を供給する生産者チェーンを形成し、システムのボトルネックは最大 3 つの実効レートによって決定されます。つまり、I の生産、II の生産、最終ユニットの組み立てですが、ステージ II がステージ I の出力を消費するという追加の依存関係があります。 

時間をシミュレートする代わりに、スケジューリング ロジックを使用して、各ステージの可能な限り最も早い完了時間を計算できます。 私たちは各マシンがいつ利用可能になるかを追跡し、正しい順序を保証します。 これにより、3 つのタイムラインを維持し、次の完了イベントを繰り返しスケジュールするという問題が軽減されます。

## アルゴリズムのチュートリアル

 完了時間を表す 3 つの配列を維持します。つまり、各ステージ I ユニットの終了時、各ステージ II ユニットの終了時、および各ステージ III アセンブリの終了時です。 次の各ユニットは、以前の出力の可用性とマシンの可用性によって異なります。 

1. ステージ I の完了時間を順番に計算します。 各ユニットには t1 時間がかかるため、ステージ I の i 番目のユニットは時間 i * t1 に終了します。 これにより、コンポーネントの可用性が大幅に増加します。 
2. ステージ II を、ステージ I の出力を順番に処理する単一のマシンとしてスケジュールします。 各アイテム i について、ステージ II は、アイテムがステージ I で準備ができ、ステージ II が空いた後にのみ開始できます。 したがって、開始時間は max(finish_I[i],finish_II[i-1]) で、終了時間は start + t2 です。 これにより、単一ステージ II マシン内で重複が生じなくなります。 
3. これで、すぐに使用できる一連のステージ II 出力が完成しました。 ステージ III はハーベスタごとに 1 つのステージ I と 1 つのステージ II 出力を消費しますが、両方の入力が存在しない限りステージ III を続行できないため、ステージ II が制限ストリームとなります。 
4. 次に利用可能なステージ I およびステージ II の完了時間を追跡することにより、2 つのポインタを暗黙的に維持します。 k 番目のハーベスターについては、k 番目の使用可能なペアを取得します。ここで、ステージ II の完了により、ステージ I の製造オーダーとの一致する依存関係がすでに保証されています。 
5. 各ハーベスターでは、必要なコンポーネントが両方とも利用可能で、ステージ III マシンが空いているときにステージ III が開始されます。 開始時間は max(finish_I[k],finish_II[k],finish_III[k-1]) で、start + t3 に終了します。 
6. 答えは、n 番目のステージ III 操作の終了時刻です。 

重要な考え方は、各ステージが決定的な処理時間を持つキューのように動作し、依存関係が最大制約を通じて開始時間にのみ影響するということです。 

### なぜ効果があるのか

 すべての段階で、各マシンが利用可能になった順にアイテムを処理し、作業が可能なときは決してアイドル状態にならないという不変条件を維持します。 各ステージは単一サーバー FIFO であるため、完了時間の繰り返しは最も早い実行可能なスケジュールと正確に一致します。 このスケジュールから逸脱すると、順序付けの制約に違反するか、不必要なアイドル時間が発生するため、計算されたスケジュールは最適になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    t1, t2, t3 = map(int, input().split())

    finish_I = [0] * (n + 1)
    finish_II = [0] * (n + 1)
    finish_III = [0] * (n + 1)

    for i in range(1, n + 1):
        finish_I[i] = i * t1

    for i in range(1, n + 1):
        start = max(finish_I[i], finish_II[i - 1])
        finish_II[i] = start + t2

    for i in range(1, n + 1):
        start = max(finish_I[i], finish_II[i], finish_III[i - 1])
        finish_III[i] = start + t3

    print(finish_III[n])

if __name__ == "__main__":
    solve()
```実装では、各ステージの完了タイムラインを明示的に構築します。 ステージ I は競合がないため直接等差数列です。 ステージ II では、入力の準備状況とマシンの可用性を最大限に活用して、単一マシンの制約を強制します。 ステージ III では、両方の入力ストリームを結合し、前回の完了時点までの最終アセンブリのシリアル化を保証します。 

よくある落とし穴は、ステージ III が前の両方のステージに独立して依存しているため、両方を最大限にチェックする必要があることを忘れていることです。 もう 1 つの微妙な問題はインデックス作成です。i-1 を使用すると、特別なケース i = 1 を使用せずにマシンの可用性が明確に表現されます。

 ## 特殊なケース

 重要なエッジ ケースは、t1 が最小で、すべての下流ステージが大きい場合です。 たとえば、n = 3、t1 = 1、t2 = 100、t3 = 100 では、ステージ I で急速な累積が生成されます。ステージ II の開始時間は常にfinish_I によってゲートされているため、アルゴリズムがこれを処理します。したがって、ステージ II はオーバーフローすることなく自然にキューに入れられます。 

もう 1 つのケースは、t3 が最小の場合です。 n = 3、t1 = 2、t2 = 3、t3 = 1 の場合、ステージ III が最速のステージになりますが、それでも入力の可用性を追い越すことはできません。 繰り返しにより、ステージ III は max(finish_I,finish_II) で待機するため、無効な初期アセンブリは発生しません。 

最後に、n = 1 の場合、3 つのステージすべてが 1 つの依存関係チェーンに縮小されます。 アルゴリズムは、連続最大値を経て終了時間 t1 + t2 + t3 に正しく折りたたまれます。
