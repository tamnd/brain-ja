 ## 問題の理解

 数直線上に 2 つの隠れた構成が与えられます。 家の位置があります$h_1, \dots, h_n$、そして2つの特別なポイント$p_1$そして$p_2$。 座標は直接与えられるわけではありません。 代わりに、距離の 2 つのマルチセットが与えられます。すべての家について、その家から家までの距離です。$p_1$そしてへ$p_2$。 これらの距離は配列に記録されます$d_1$そして$d_2$ただし、インデックスとハウス間の対応は各配列内で失われます。つまり、各配列は単なるマルチセットになります。 

タスクは、すべての配置が存在するかどうかを判断することです。$h_i$、$p_1$、 そして$p_2$これら 2 つの距離マルチセットが絶対差と一致するような線上にあります。 そのような構成が存在する場合は、それを構築する必要があります。 

主な困難は、順序付けされていない距離マルチセットからジオメトリを再構築していることです。 各家がペアを提供します$(|h_i - p_1|, |h_i - p_2|)$、しかし、これらのペアは与えられず、それらの投影だけが与えられます。 

制約は十分小さいので、$n$テストごとに最大 1000 件、合計でおよそ 2000 件まで許可されます$O(n^2 \log n)$または$O(n^2)$テストケースごとのソリューション。 立方体のものなら何でも$n$リスクはありますが、定数係数が小さい場合はかろうじて合格する可能性があります。 これは、少数の候補構成を選択し、それらを検証するという問題の解決を試みるべきであることを示唆しています。 

重要な微妙な点は、多くの異なる幾何学的構成が同一の距離のマルチセットを生成することです。 例えば交換とか$p_1$そして$p_2$、すべての点を変換するか、ラインを反映すると、有効性が保持されます。 もう 1 つの微妙な問題は、複数の家が互いに重なったり、複数の家が重なったりする可能性があることです。$p_1$または$p_2$したがって、ゼロ距離は特別なケースとして扱うのではなく、自然に処理する必要があります。 

よくある失敗モードは、ソートされた配列を貪欲に一致させようとすることです。$d_1$そして$d_2$インデックス的に。 距離間のペアリングが保持されないため、これは不正確です。 もう 1 つの間違ったアプローチは、異なる中心からの距離が揃っていないため、単調性を仮定することです。 

## アプローチ

 直接的な総当たり的な視点では、すべてを再構築しようとします。$n$ペア$(|h_i - p_1|, |h_i - p_2|)$の要素を一致させることで$d_1$そして$d_2$。 これは 2 つのマルチセット間の完全なマッチングの問題になりますが、すべてのマッチングがライン上の実現可能なジオメトリに対応するわけではありません。 ペアリングを仮定したとしても、絶対値制約を満たす実際の座標を回復する必要があり、これにより連続的な自由度が導入されます。 すべてのペアリングを試すことは要因です$n$、それは不可能です。 

重要な観察は、位置を固定すると、変換と反射に至るまで全体の構成が決定されるということです。$p_1$そして$p_2$。 仮定すると$p_1 = 0$そして$p_2 = x$、次に各ハウスの位置$h$2 つの距離が正確に一致することを満たさなければなりません$(|h|, |h-x|)$。 これにより、問題は、ペアのマルチセットをライン上に埋め込むことができるかどうかを確認することになります。$x$。 

中心的な構造的洞察は、候補のセットが$x$値が小さいです。 家を選んで、それがある程度の距離に相当すると仮定すると、$d_1$そして少し離れたところに$d_2$、潜在的なポジションを導き出すことができます。$p_1$そして$p_2$。 直線上の点は 2 つの固定点までの距離によって反射されるまで決定されるため、距離の各ペアは一定数の幾何学的可能性のみを与えます。 これにより、検索スペースが折りたたまれます。$O(n)$または$O(n \log n)$候補となる建築物。 

一度$p_1$そして$p_2$が固定されている場合、すべてのハウスの位置は次の 2 つの値のいずれかになります。$p_1 \pm d_{1,i}$、そしてそれが一致するように方向を選択する必要があります$d_2$。 これは、各距離を割り当てることができるかどうかを確認する一貫性チェックになります。$d_1$記号に合わせて照合する$d_2$によって引き起こされる価値観$p_2$。 並べ替えと複数セットの検証で十分です。

 ## アルゴリズムのチュートリアル

 の候補を構築していきます$p_1$そして$p_2$そしてそれらを検証します。 

1.要素を選択します$a$から$d_1$そして要素$b$から$d_2$。 それらをどこかの家からの距離として扱う$h$に$p_1$そして$p_2$。 点の場合は、線上のジオメトリから$h$距離がある$a$そして$b$2点まで$p_1$そして$p_2$、次の間の距離$p_1$そして$p_2$どちらかである必要があります$a+b$または$|a-b|$。 これにより、最大で 2 つの候補値が得られます。$x = |p_1 - p_2|$。 
2. 各候補者について$x$、完全な構成を再構築してみてください。 修理$p_1 = 0$、$p_2 = x$。 ここで、すべての家は、0 までの距離が次の値であることを満たさなければなりません。$d_1$順列後だけでなく、からの距離も$x$一致する必要があります$d_2$。 
3. ハウスポジションを構築するには、距離を取ります$d$から$d_1$。 ハウスポジションはどちらかです$+d$または$-d$。 それぞれの選択肢について、その暗黙の距離を計算します。$x$そしてそれが存在するかどうかを確認します$d_2$。 マルチセットを使用して貪欲にマッチングします。 
4. すべての距離が一貫して一致する場合、構築された座標が出力されます。 

これが機能する理由は、一度$p_1$そして$p_2$が固定されている場合、各ハウスの位置は 2 点の選択に制限されます。 すべての選択は、正確に 1 つの要素を消費する必要があるため、マルチセット マッチングによりグローバルな一貫性が保証されます。$d_2$、矛盾がある場合は、間違った符号の割り当てまたは間違った候補を示します。$x$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import Counter

def try_build(d1, d2, x):
    c2 = Counter(d2)
    h = []

    for d in d1:
        candidates = [d, -d]
        chosen = None

        for v in candidates:
            dist2 = abs(v - x)
            if c2[dist2] > 0:
                chosen = v
                c2[dist2] -= 1
                break

        if chosen is None:
            return None
        h.append(chosen)

    return h

def solve_case(n, d1, d2):
    c1 = Counter(d1)
    c2 = Counter(d2)

    candidates = set()

    d1_list = list(c1.elements())
    d2_list = list(c2.elements())

    # generate possible x from one pair
    for i in range(n):
        for j in range(n):
            a = d1_list[i]
            b = d2_list[j]
            candidates.add(a + b)
            candidates.add(abs(a - b))

    for x in candidates:
        res = try_build(d1_list, d2_list, x)
        if res is None:
            continue

        p1 = 0
        p2 = x

        # shift to non-negative if needed
        minv = min(min(res), 0, x)
        shift = -minv
        res = [v + shift for v in res]
        p1 += shift
        p2 += shift

        return True, res, (p1, p2)

    return False, None, None

def main():
    t = int(input())
    for _ in range(t):
        n = int(input())
        d1 = list(map(int, input().split()))
        d2 = list(map(int, input().split()))

        ok, h, p = solve_case(n, d1, d2)
        if not ok:
            print("NO")
        else:
            print("YES")
            print(*h)
            print(p[0], p[1])

if __name__ == "__main__":
    main()

微妙な点は、有効なグローバル ソリューションは一貫したペアリングを誘発し、特定の住宅に一致するものを見つけることができないため、ハウスごとに貪欲な選択をするのが安全であるということです。$d_1$両方の記号オプションの下の値は、それが不可能であることを証明します$x$。

 ## 特殊なケース

 重大なエッジ ケースは、両方の配列に多くのゼロが含まれる場合です。 これは、正確に次の場所にある家に相当します。$p_1$または$p_2$。 距離がゼロの場合、家の位置が対応するピボットと強制的に等しくなり、割り当てに曖昧さが残らないため、アルゴリズムはこれを自然に処理します。 

もう 1 つのエッジケースは次のような場合です$p_1 = p_2$。 この状況では、両方の配列が同一のマルチセットである必要があります。 候補世代には以下が含まれます。$x = 0$、再構成は、単一の中心が両方の配列を同時に説明するかどうかのチェックに退化します。貪欲マッチングでは、同じ距離を強制することで、これが正しく検証されます。 

3 番目のエッジケースは、同じものに対して複数の有効な符号割り当てが存在する場合です。$x$。 このアルゴリズムは、一貫した割り当てを 1 つだけ必要とするため、依然として成功します。 初期に間違った割り当てが行われた場合、マルチセット内の要素が一致しないために後で失敗し、アルゴリズムは他の候補を再試行します。
