 ## 解決策
 ## 問題の理解

 空のマルチセットから始めます$S$。 各操作では、数値が 1 回挿入されます。$x$の中へ$S$、または次の 1 つの出現を削除します。$x$それは存在することが保証されています。 変更を加えるたびに、現在の要素のサブマルチセットを選択することによって形成できるすべてのサブセットの合計を調べ、そのような合計として表現できる個別の正の整数の数を数えます。 

言い換えれば、各ステップの後、要素のすべての有限選択を考慮します。$S$(これはマルチセットであるため、各コピーは最大 1 回使用できます)、それらの合計を計算し、異なる値がいくつあるかを尋ねます。$1,2,3,\dots$達成可能です。 各操作後の出力は、この到達可能なセットのサイズであり、正の整数に制限されます。 

重要な制約は、常に、現在存在するすべての要素の合計が$S$せいぜい$5 \cdot 10^5$。 これにより、サブセットの合計が合計を超えることはできないため、考慮する必要があるサブセットの合計の最大値が即座に制限されます。 また、合計を超える動的プログラミングの状態は、次の条件によって安全に制限できることも意味します。$5 \cdot 10^5$。 

操作数は最大で$5 \cdot 10^3$、したがって、おおよそ次のアルゴリズムを使用する余裕があります。$O(n \cdot \text{poly}(V))$どこ$V = 5 \cdot 10^5$ただし、理想的にはビットレベルの操作または償却再利用を使用して、ステップごとの作業が極度に最適化されている場合に限ります。 

各操作の後でサブセットの合計を最初から再計算する単純なアプローチでは、各再計算にすでに約$O(nV)$または$O(V \cdot \#\text{elements})$、そしてそれを$5 \cdot 10^3$時代は不可能になります。 

微妙な落とし穴は、削除により単調性が崩れることです。 挿入のみの場合、到達可能なセットは増加するだけであり、標準のナップザック ビットセットの更新で十分です。 削除操作では、一方向の DP ではなく、完全に動的な構造を維持する必要があります。 

もう 1 つの特殊なケースは、値が繰り返されることです。 挿入が一意であることが保証されていないため、次のように処理する必要があります。$S$真のマルチセットとして。 たとえば、$x$2 回実行すると、両方のコピーを使用する必要がある合計が作成される可能性があり、1 つのコピーを削除しても、それらの貢献は部分的にのみ撤回されます。 

## アプローチ

 ブルートフォースのアイデアは単純です。現在のマルチセットを維持し、各操作の後にサブセット合計 DP を再計算します。 ブール配列を保持します$dp[s]$合計かどうかを示す$s$達成可能であり、要素ごとに$x$古典的なナップサックトランジションを行います$dp[s] \leftarrow dp[s] \lor dp[s-x]$高いものから低いものまで。 これにより、現在の状態のすべてのサブセットの合計が正しく計算されます。 

問題は、操作のたびにこれを最初から再計算するとコストが高すぎることです。 それぞれの再構築にかかる費用$O(V \cdot |S|)$、そしてそれ以来$|S|$できる$O(n)$、合計作業量は次のようになります。$O(n^2 V)$、それは限界をはるかに超えています。 

重要な点は、操作ごとにすべてを個別に再計算する必要がないということです。 代わりに、時間を別の次元として扱うことができます。 各要素は、挿入から削除までの連続した時間間隔でのみ存在します。 これらの間隔がわかっていれば、出現するそれぞれの数値を割り当てることができます。$x$アクティブな操作のセグメントに適用されます。 

これにより、時間の経過とともに問題が完全にオフラインの動的なナップザックに変換されます。各要素は一定の間隔でアクティブになります。$[l, r]$、そして、その時点をカバーする間隔を持つ要素を正確に考慮して、時間の各プレフィックスの後の DP 結果が必要です。 これを処理する標準的な方法は、各ノードがその間隔で完全にアクティブな項目を格納する長期にわたるセグメント ツリーです。 

次に、分割統治スタイルの DP を実行します。各セグメント ツリー ノードで、そのノードに割り当てられた項目によって寄与されるサブセットの合計を表すビットセット DP を維持します。 DP を下向きに渡すことによって子を結合し、各要素がルートからリーフまでのパスごとに 1 回だけ適用されるようにします。 各要素が挿入されているため、$O(\log n)$ノードを使用すると、アプリケーションの総数を管理できます。 

DP 自体はビットセットとして実装されているため、シフト演算と OR 演算はマシンワードで実行され、単純なブール配列よりも大幅に高速に遷移します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 各操作後に DP を再計算する |$O(n^2 V)$|$O(V)$| 遅すぎる |
 | 経時的なセグメント ツリー + ビットセット DP |$O(n \log n \cdot V / w)$|$O(V)$| 承認済み |

 ここ$w$はマシンワードサイズ (通常は 64) であり、これによりビットセット操作が実用的になります。 

## アルゴリズムのチュートリアル

 ### 1. 操作をアクティブな間隔に変換します。 

操作を順番にスキャンし、各値のスタックまたは周波数マップを維持します。$x$。 を挿入するたびに、$x$新しいアクティブな間隔が開始され、削除されるたびに、最後に開いた間隔が閉じられます。$x$。 要素が複数回挿入された場合、各コピーは個別に追跡されます。 

このステップでは、動的シーケンスを要素の出現ごとの一連の素な時間間隔に変換します。 

### 2. 時間をかけてセグメント ツリーを構築する

 インデックス範囲にわたってセグメント ツリーを構築します$[1, n]$。 各ノードは時間間隔に対応します。 要素間隔ごとに$[l, r]$、その値を挿入します$x$この間隔を完全にカバーするすべてのセグメント ツリー ノードに分割します。 これにより、各ノードはセグメント全体を通じてアクティブであることが保証されている要素のみを格納するようになります。 

この分解が機能する理由は、すべての時点が以下に属しているためです。$O(\log n)$すべての要素は、アクティブな間隔の最小限の範囲を表すノードに正確に保存されます。 

### 3. サブセットの合計にはビットセット DP を使用します

 ビットセットを保守します$dp$、どこビット$i$合計の場合は 1$i$達成可能です。 最初だけ$dp[0] = 1$。 

ノードを処理するとき、すべての値を反復処理します。$x$そのノードに保存され、トランジションが適用されます$dp \leftarrow dp \,|\, (dp \ll x)$。 このモデルでは、次の各発生を含めるか除外します。$x$。 

シフトは大きな整数 (ビットセット) を操作するため、すべての合計を明示的に反復処理するよりも大幅に高速になります。 

### 4. セグメント ツリー上の DFS

 セグメント ツリーを再帰的にたどります。 各ノードでは、格納されているすべてのアイテムを DP のローカル コピーに適用します。 時間に応じた葉に到達すると$t$、DP は操作後のマルチセット状態を正確に表します$t$したがって、範囲内の設定されたビットを数えることによって、到達可能な正の合計の数を数えます。$[1, \text{sum}]$。 

各再帰ブランチは終了後に DP 状態を復元するため、兄弟ノードは影響を受けません。 

### なぜ効果があるのか

 正しさは 2 つの不変条件から得られます。 まず、すべての要素はアクティブな存続期間を正確にカバーするノードに挿入されるため、どのリーフでも、DP にはその時点でアクティブな要素が正確に含まれます。 第 2 に、各 DP 遷移は標準的なサブセット合計ナップザックであるため、ビットセットはそのノードで表されるマルチセットの達成可能なすべての合計を正確にエンコードします。 セグメント ツリーはオーバーラップ エラーなしで時間を分割するため、すべての操作の答えはアクティブ セットの正確な再構成から計算されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXV = 500000

def count_bits(x):
    return x.bit_count() - 1  # exclude 0

def add_interval(tree, node, l, r, ql, qr, val):
    if ql <= l and r <= qr:
        tree[node].append(val)
        return
    mid = (l + r) // 2
    if ql <= mid:
        add_interval(tree, node * 2, l, mid, ql, qr, val)
    if qr > mid:
        add_interval(tree, node * 2 + 1, mid + 1, r, ql, qr, val)

def dfs(tree, node, l, r, dp, ans):
    local = dp
    for x in tree[node]:
        local = local | (local << x)

    if l == r:
        ans[l] = count_bits(local)
        return

    mid = (l + r) // 2
    dfs(tree, node * 2, l, mid, local, ans)
    dfs(tree, node * 2 + 1, mid + 1, r, local, ans)

def solve():
    n = int(input())
    ops = []
    pos = {}
    intervals = []

    for i in range(1, n + 1):
        op, x = map(int, input().split())
        ops.append((op, x))
        if op == 1:
            pos.setdefault(x, []).append(i)
        else:
            l = pos[x].pop()
            intervals.append((l, i, x))

    for x, lst in pos.items():
        for l in lst:
            intervals.append((l, n, x))

    size = 4 * (n + 5)
    tree = [[] for _ in range(size)]

    for l, r, x in intervals:
        add_interval(tree, 1, 1, n, l, r, x)

    dp = 1  # bitset with only 0 reachable
    ans = [0] * (n + 1)

    dfs(tree, 1, 1, n, dp, ans)

    print("\n".join(str(ans[i]) for i in range(1, n + 1)))

if __name__ == "__main__":
    solve()
```この実装では、まずオンライン挿入/削除シーケンスが明示的なアクティブ間隔に変換されます。 次に、各間隔をセグメント ツリーに分散して、各ノードがその時間範囲内で完全にアクティブな要素のみを格納するようにします。 DFS はビットセット DP を下方向に伝送し、各ノードの要素で更新します。 Python の整数は任意の長さのビットセットとして機能するため、シフト演算と OR 演算によりサブセット合計遷移が自然に実装されます。 

正の合計のみが必要なため、各リーフの答えは、ゼロを除く設定ビットをカウントすることによって計算されます。

 ## 特殊なケース

 微妙なケースの 1 つは、削除前に同じ値が繰り返し挿入されることです。 たとえば、$x$2 回削除してから 1 回削除しても、1 つのコピーはアクティブなままにしておく必要があります。 間隔構築では、削除と最新の不一致の挿入をペアにすることでこれを処理するため、各コピーには独自の寿命が与えられます。 

もう 1 つのエッジ ケースは、マルチセットが空になる場合です。 DP はのみにリセットする必要があります。$\{0\}$、正の合計が存在しないことを意味します。 セグメント ツリー表現は、そのリーフに寄与する間隔がないため、その時点で空の DP を自然に生成します。 

最後のケースは、すべての要素が大きく、グローバル合計制限に近い場合です。 値は最大でも可能ですが、$5 \cdot 10^5$の場合、DP 幅は現在の合計値によって制限されたままであり、到達可能な最上位ビットを超えてシフトしても正確さに影響しないため、ビットセットは依然として正しく動作します。
