 ## 解決策
 ## 問題の理解

 各生徒の成績には、固定の試験スコアと制御可能な継続評価スコアという 2 つの要素があります。 学生向け$i$、現在の合計は$x_i + y_i$、 どこ$x_i$コースワークのスコアの上限は次のとおりです$a$、 そして$y_i$試験のスコアの上限は次のとおりです$b$。 合計が少なくとも以下の場合、学生は合格します$c$、そうでない場合は失敗します。 

教師は、単一のグローバル操作 (負でない整数の追加) を適用することができます。$d$すべての生徒のコースワークのスコアに。 この増加後、コースワークのスコアが$a$クリップバックされます$a$。 試験の点数は変わりません。 目標は、この操作後に何人の生徒が不合格から合格に変わったかを数えるということです。 

制約$n \le 1000$これは、固定された問題について各生徒を個別にチェックすることを意味します。$d$は自明なので、最大でも線形である解はどれも$n$候補ごとの操作で十分です。 値の範囲はすべて小さく、特に$d \le 100$、これは、あらゆる可能性に対してブルートフォースが行われることを示唆しています。$d$完全に実現可能です。 

微妙な点は、コースワークのスコアの切り抜きです。 もし$x_i + d > a$、貢献度は正確になります$a$、 ない$x_i + d$。 これにより、最終スコアに区分的な動作が生じ、これが素朴な推論における間違いの主な原因となります。 

よくある失敗例は、キャップ効果を無視することです。 たとえば、次の場合$a = 40$、$x_i = 35$、 そして$d = 10$、コースワークの貢献度は 45 ではなく 40 です。直接追加するソリューション$d$上限を適用しないと、スコアが過大評価され、ボーダーラインの生徒が誤って合格として分類されてしまいます。 

もう 1 つの落とし穴は、カウントされるものを誤解していることです。 手術後に合格した生徒全員をカウントするのではなく、最初は不合格だった生徒が手術のおかげで合格した生徒のみをカウントします。 

## アプローチ

 ブルートフォースのアイデアは簡単です。可能なすべての値を試してください。$d$0から100まで。それぞれ$d$、すべての生徒の調整されたコースワークスコアを再計算し、合計を計算して、合格したかどうかを確認します。 また、修正を加える前にどの生徒が失敗するかというベースラインも必要です。 

これが機能するのは、$d$小さいです。 最悪の場合の計算は次のとおりです。$101 \times 1000$生徒たち、そしてそれぞれの生徒のために私たちは継続的な仕事をしているので、$10^5$オペレーションの合計。 これは快適に小さいです。 

重要な単純化は、生徒間に相互作用が存在しないことです。 各生徒の結果は各生徒自身にのみ依存します$(x_i, y_i)$そしてグローバルパラメータ$d$。 この独立性により、サブセットに対する組み合わせ論や最適化の必要がなくなります。 少数のグローバル状態のみをシミュレートします。 

生徒ごとに 2 つの状態を計算します。$d$: 元の合否ステータス、および上限調整された増加を適用した後の新しい合否ステータス。 不合格から合格への移行をカウントします。

 ## アルゴリズムのチュートリアル

 1. すべての入力値を読み取ります。$n, a, b, c$、学生リスト、およびグローバル増分$d$。 
2. 各生徒について、現在合格しているかどうかを計算します。$x_i + y_i \ge c$。 このブール値またはカウント構造体を暗黙的に保存します。 
3. 与えられたもののために$d$、各学生の新しいコースワークのスコアを次のように計算します。$\min(a, x_i + d)$。 
4. 新しい合計スコアを次のように計算します。$\min(a, x_i + d) + y_i$。 
5. 生徒が合格したかどうかを確認します。 
6. 初期状態は失敗しているが、新しい状態は合格している生徒をカウントします。 
7. このカウントを出力します。 

各学生は独立して評価されるため、最終的なカウントを超えてグローバル状態を維持する必要はありません。 

### なぜ効果があるのか

 すべての学生に適用される操作は均一であり、合格条件は学生ごとに純粋に加算されます。 これにより、システムを生徒ごとの独立した移行に分離できるようになります。 コースワークの調整は固定的なものであるため、$d$、各生徒には状態遷移の結果が 1 つだけあります。 したがって、改善をカウントすることは、すべての生徒の独立したブール イベントを合計することと同じです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a, b, c = map(int, input().split())
    
    students = []
    for _ in range(n):
        x, y = map(int, input().split())
        students.append((x, y))
    
    d = int(input())
    
    improved = 0
    
    for x, y in students:
        before = (x + y >= c)
        
        x2 = x + d
        if x2 > a:
            x2 = a
        
        after = (x2 + y >= c)
        
        if not before and after:
            improved += 1
    
    print(improved)

if __name__ == "__main__":
    solve()
```このソリューションは、生徒ごとのシミュレーションに直接従います。 唯一の重要なステップは、キャップを正しく適用することです。修正後のコースワークは次のとおりです。`min(a, x + d)`、試験のスコアと合計する前に計算する必要があります。 

「前」フラグにより​​、もともと不合格だった学生のみがカウントされるようになります。 これを行わないと、すでに合格している生徒と引き続き合格している生徒が誤って結果に含まれてしまいます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input())
    a, b, c = map(int, input().split())
    students = [tuple(map(int, input().split())) for _ in range(n)]
    d = int(input())

    improved = 0
    for x, y in students:
        before = x + y >= c
        x2 = min(a, x + d)
        after = x2 + y >= c
        if (not before) and after:
            improved += 1
    return str(improved)

# sample
assert run("3\n40 60 60\n20 25\n10 40\n25 30\n10\n") == "1"

# minimum case
assert run("1\n0 100 50\n0 49\n10\n") == "0"

# exact boundary improvement
assert run("1\n10 100 50\n10 39\n5\n") == "1"

# already passing should not count
assert run("2\n50 50 80\n49 30\n10 60\n5\n") == "0"

# cap effect matters
assert run("1\n40 100 100\n35 60\n10\n") == "1"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 最小の場合 | 0 | 一人の生徒、改善の余地なし |
 | 境界改善 | 1 | 正確なしきい値を超える |

| キャップ効果 | 1 | min(a, x+d) の処理を​​検証します。 

## 特殊なケース

 主なエッジケースは、生徒が手術前に通過点のすぐ下にいて、クリッピング後にちょうど通過点に到達した場合です。 

入力：```
n = 1
a = 40, b = 100, c = 80
x = 35, y = 40
d = 10
```前に：$35 + 40 = 75$、失敗。 

変更後: コースワークは$\min(40, 45) = 40$、合計は$40 + 40 = 80$、通り過ぎます。 

アルゴリズムは以下を計算します。 

- 前 = false
 - x2 = 40 (キャップのため)
 - 後 = true

 したがって、この学生は正しくカウントされます。 

対照的なケースは、キャップを無視する場合です。 

誤って使用した場合$x + d = 45$、合計は次のようになります$85$、まだ合格しているため、この場合は正確性が損なわれることはありません。 本当の危険が現れるのは、$x$に近いです$a$そして、上限は、生徒が閾値を超えて予想される利益を高めることを防ぎます。 単純な追加では、これらのシナリオでの改善が過大評価されてしまいます。
