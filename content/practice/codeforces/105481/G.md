 ## 解決策
 ## 問題の理解

 1 つ以上の配列が与えられます。 各配列について、すべての連続するサブ配列を調べ、単純なルールに基づいて値を割り当てます。つまり、サブ配列内の最大要素を取得し、この最大値が何回出現するかを数え、そのカウントが少なくとも 1 つであるかどうかを調べます。`k`、サブ配列が寄与します`1`、そうでない場合は貢献します`0`。 タスクは、すべてのサブ配列にわたるこれらの寄与の合計を計算することです。 

したがって、問題は最大値を直接計算することではなく、セグメント内の最大値が「十分に繰り返される」頻度をカウントすることです。 すべてのサブ配列は適格か不適格かのどちらかであり、いくつが適格であるかを数えています。 

制約は、テスト ケースごとの線形または線形に近い解決策を意味します。 すべてのテスト ケースの全長は最大 1e6 であるため、部分配列の二次列挙は不可能です。 大幅に最適化しない限り、O(n sqrt n) であっても危険です。 この構造は、償却 O(n) または O(n log n) の動作をサポートする必要があります。 

単純な実装では、すべての O(n²) 個の部分配列を列挙し、前処理を使用して O(n) または O(1) の最大値とその頻度を計算し、条件をチェックします。 これにより、実装に応じてすでに O(n³) または O(n²) 時間がかかりますが、これでは遅すぎます。 

微妙に間違ったアプローチは、最大値のみを更新しながらスライディング ウィンドウを維持しようとすることです。 「現在のウィンドウの最大周波数」が単調ではないため、これは失敗します。要素を追加または削除すると、どの値が最大になるか、またその最大値が表示される回数も変化する可能性があります。 

もう 1 つの落とし穴は、配列全体のグローバル最大値が重要となるサブ配列のみを想定していることです。 この条件は各部分配列に対して局所的なものであるため、大域的最大値に注目を制限すると、ほとんどすべての有効なケースが失われます。 

## アプローチ

 ブルートフォースアプローチは簡単です。 開始インデックスごとに、部分配列を一度に 1 要素ずつ拡張し、最大値と頻度マップを維持し、最大値が出現する回数を数えます。 これにより、有効なサブ配列が正しく識別されますが、拡張ごとに O(n) の作業が費やされ、テスト ケースごとに O(n²) 以上の結果が得られます。 要素の総数が最大 1e6 である場合、これは実現できません。 

重要な観察は、条件が部分配列の最大要素のみに依存するということです。 最大値を固定する場合は、値を言います`x`の場合、次を超える要素がない部分配列のみを考慮します。`x`、その中で少なくとも欲しいのは、`k`の発生`x`。 これにより、問題は、値ごとに、制御された最大値とその値の十分な周波数を持つサブアレイの数を数えることになります。 

値を降順で処理できます。 価値観を考えるとき`x`、より大きいすべての要素を一時的に扱います`x`配列を独立したセグメントに分割する「ブロッキング境界」として。 各セグメント内では、値が等しい位置のみを考慮します。`x`。 

ここで問題は次のようになります。各セグメントで、部分配列を数えます。`x`少なくとも出現する`k`回。 これは古典的な「部分配列内に少なくとも k 個の出現」を数える問題であり、次の位置に対する 2 ポインタ アプローチで解決できます。`x`各セグメントの内部。 

私たちは以下の立場を維持します`x`これらの位置にスライディング ウィンドウを使用します。 発生期間の場合`[i, j]`と`j - i + 1 >= k`, k 番目に出現する部分配列の数`x`固定値は、以下の要素を越えることなく左右にどれだけ拡張できるかによって決まります。`x`。 

これにより、値ごとの線形スイープが行われ、各インデックスはその値がアクティブ化された場合にのみ処理に参加するため、合計の複雑さは O(n) に近くなります。

 | 値のスイープ + 2 つのポインター | O(n log n) または O(n) が償却 | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 最大値から最小値の順に値を処理できるように、配列値ごとにインデックスを並べ替えたりバケット化したりします。 これにより、値を処理するときに、`x`、より大きな値はすべてすでにバリアとして扱われます。 
2. 現在の値より大きいすべての要素が配列を分割する「アクティブ セグメント」の構造を維持します。 概念的には、これらをカウントをリセットする境界として扱います。 
3. 現在値について`x`、すべてのインデックスを収集します。`a[i] == x`。 各アクティブ セグメント内で、これらのインデックスを個別に処理します。 
4. 各セグメントについて、位置のリストを取得します。`x`。 これらの位置にはスライディング ウィンドウを使用します。 窓をそのままにしましょう`[l, r]`出来事という意味では。 以下のウィンドウのみを考慮します。`r - l + 1 >= k`。 
5. 位置での k 番目の出現の固定有効ウィンドウの場合`r`、前の出現 (またはセグメント開始) とこの k 番目の出現の間に左境界があり、この出現と次のブロック要素の間に右境界があるサブ配列の数を決定します。 これにより、各有効なウィンドウがカウント寄与に変換されます。 
6. すべての値にわたるすべての寄与を合計します。 

### なぜ効果があるのか

 正確さは、サブ配列の最大要素による分解に依存します。 すべての有効な部分配列には一意の最大値があります`x`。 修正したら`x`、より大きい要素`x`サブ配列が無効になるため、有効なサブ配列は、より大きな要素で囲まれた領域内に完全に存在する必要があります。 そのような領域内でサブ配列を数えると、`x`少なくとも出現する`k`時間は他の値から独立しています。 各サブ配列は、最大値を処理するときに 1 回だけカウントされます。これは、最大値が考慮されるのは次の場合のみであるためです。`x`セグメント内で許可される最大値です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    pos = [[] for _ in range(n + 1)]
    for i, v in enumerate(a):
        pos[v].append(i)

    # next greater element boundary: we build "blocks" using a monotonic stack
    nxt_block = [n] * n
    stack = []
    for i in range(n):
        while stack and a[stack[-1]] < a[i]:
            nxt_block[stack.pop()] = i
        stack.append(i)

    prev_block = [-1] * n
    stack = []
    for i in range(n - 1, -1, -1):
        while stack and a[stack[-1]] <= a[i]:
            prev_block[stack.pop()] = i
        stack.append(i)

    ans = 0

    # process values in decreasing order
    for val in range(n, 0, -1):
        if not pos[val]:
            continue

        # split positions by blocks implicitly
        group = []
        for i in pos[val]:
            group.append(i)

        if len(group) < k:
            continue

        # two pointers over occurrences
        for i in range(len(group) - k + 1):
            j = i + k - 1

            left_bound = prev_block[group[i]] + 1
            right_bound = nxt_block[group[j]] - 1

            # extend left and right choices
            left_choices = group[i] - left_bound + 1
            right_choices = right_bound - group[j] + 1

            if left_choices > 0 and right_choices > 0:
                ans += left_choices * right_choices

    print(ans)

def main():
    t = int(input())
    for _ in range(t):
        solve()

if __name__ == "__main__":
    main()
```この解決策は、等しい値のインデックスをグループ化することから始まり、各候補最大値について局所的に推論できるようになります。 次に大きい境界と前の大きい境界は、単調スタックで計算されます。 これらは、指定された値が、より大きな要素によって無効化されることなく最大値として機能できる最大セグメントを定義します。 

それぞれの値について、出現箇所を確認し、次のサイズのウィンドウを選択します。`k`。 ウィンドウは、周波数条件を満たすための最小要件を定義します。 k 番目の出現が修正されたら、有効なセグメント境界内に留まりながらサブ配列を左右に拡張するための選択肢がいくつ存在するかを数えます。 

微妙な点は、各ウィンドウが複数のサブ配列に対応しており、左右のエンドポイントの独立した選択を乗算していることです。 この因数分解により、ウィンドウごとのカウントが O(1) に減ります。

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    def solve():
        n, k = map(int, input().split())
        a = list(map(int, input().split()))

        pos = [[] for _ in range(n + 1)]
        for i, v in enumerate(a):
            pos[v].append(i)

        nxt_block = [n] * n
        stack = []
        for i in range(n):
            while stack and a[stack[-1]] < a[i]:
                nxt_block[stack.pop()] = i
            stack.append(i)

        prev_block = [-1] * n
        stack = []
        for i in range(n - 1, -1, -1):
            while stack and a[stack[-1]] <= a[i]:
                prev_block[stack.pop()] = i
            stack.append(i)

        ans = 0

        for val in range(n, 0, -1):
            if not pos[val]:
                continue
            if len(pos[val]) < k:
                continue
            for i in range(len(pos[val]) - k + 1):
                j = i + k - 1
                L = prev_block[pos[val][i]] + 1
                R = nxt_block[pos[val][j]] - 1
                left = pos[val][i] - L + 1
                right = R - pos[val][j] + 1
                if left > 0 and right > 0:
                    ans += left * right

        return str(ans) + "\n"

    out = []
    t = int(input())
    for _ in range(t):
        out.append(solve())
    return "".join(out)

 ## 特殊なケース

 k が 1 に等しい最小配列は、最大値が少なくとも 1 回出現するすべての部分配列をアルゴリズムが正しくカウントするかどうかをテストします。 その場合、すべての部分配列が有効になり、式は考えられるすべてのセグメントをカウントすることになります。 すべての要素が独自の最大クラスを形成し、各 k ウィンドウが 1 つの出現となるため、境界ベースの分解は引き続き機能します。 

すべて等しい配列では、左右の乗算の正確さが強調されます。 すべての部分配列の最大値は同じであるため、アルゴリズムは長さが少なくとも k であるすべての部分配列をカウントする必要があります。 オカレンスのスライディング ウィンドウにより、自然に正確に (n-k+1) 個のウィンドウが生成され、それぞれが正しいエンドポイントの選択肢に拡張され、二重カウントが発生しないことが確認されます。
