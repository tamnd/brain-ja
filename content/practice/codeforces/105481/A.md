 ## 解決策
 ## 問題の理解

 物語を表す長いテキストが与えられます。 テキストには、スペースやカンマ、ピリオド、感嘆符、疑問符などの句読点が混在した単語が含まれています。 各単語は一連の文字であり、単語の大文字小文字が異なる場合がありますが、大文字と小文字は区別されません。 

このテキストに加えて、読者がすでに知っている単語の小さな辞書が提供されます。 読者は物語の中で単語に出会ったとき、それが既知の単語セットにない場合、一度調べてから永久に覚えます。 しかし、読者は単語に対して欠陥のある認識を持っています。異なる形態は異なる単語であると考えられます。 したがって、「受け入れる」と「受け入れられる」は、根は同じですが、同じではありません。 

このタスクは、テキスト全体を左から右に読むことをシミュレートし、最初の既知のセットにない個別の単語の数をカウントすることです。 それぞれの未知の単語は、初めて出現したときに 1 回だけ辞書検索をトリガーします。 

テキストの長さは最大 5 × 10^6 文字です。 これにより、非効率的な方法で部分文字列のスキャンやコピーを繰り返すソリューションは即座に除外されます。 テキストを単一の線形パスで処理し、その場で単語を抽出して段階的に処理する必要があります。 辞書のサイズは最大 100 ワードであるため、ハッシュ セットに保存するとメンバーシップ チェックが定数で行われます。 

実際には、いくつかの特殊なケースが重要です。 入力単語の最初の文字は大文字になる可能性があるため、単語は小文字に正規化する必要があります。 句読点は単語の直後に現れるため、句読点を注意深く削除しない限り、単純なスペース分割では不十分です。 もう 1 つの微妙なケースは、未知の単語が繰り返される場合です。最初に出現した単語だけが答えを増やします。 

## アプローチ

 ブルートフォース解釈では、スペースと句読点を使用してテキスト全体をトークンに分割し、各トークンについて既知のリストに含まれるかどうかを繰り返しチェックします。 既知のリストは小さいため、すべてのトークンを線形にスキャンできます。 これはすでに境界線に達していますが、単独ではまだ実現可能です。 本当の問題は辞書検索ではなく、部分文字列を繰り返し作成したり、不用意にテキストを複数回スキャンしたりするコストです。 

もっと悪い総当たりアプローチでは、文字列比較を使用して単語ごとに既知のリストを繰り返しスキャンするため、O(total_words × n) の動作が発生しますが、n ≤ 100 であるため、この部分はボトルネックではありません。 真の非効率は、正規表現を使用して分割しようとしたり、500 万の文字列に多くの中間オブジェクトを割り当てる文字列操作を繰り返したりしようとした場合に発生します。 

重要な点は、テキストを 1 回パスするだけでよいということです。 読み取り中に文字をバッファに蓄積することができ、文字以外の境界に達すると、単語を完成させ、正規化し、すぐに処理します。 これにより、余分なパスや大きな解析オーバーヘッドが回避されます。 

既知の単語をハッシュ セットに保存し、読書中にすでに調べた単語の別のセットも維持します。 各単語は平均 O(1) 時間で処理されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 解析が重い場合は O(T × n) 以上 | O(T) | 遅すぎる/危険 |
 | 最適 | O(T) | O(T + n) | 承認済み |

 ## アルゴリズムのチュートリアル

 テキストを 1 文字ずつスキャンし、単語を段階的に抽出します。 

1. 空のセットを初期化する`known`与えられたすべての辞書単語が含まれています。 
2. 空のセットを初期化する`seen_unknown`辞書検索としてすでにカウントされている単語を追跡します。 
3. 空の文字列バッファを初期化します。`current`。 
4. テキスト内の各文字をたどります。 

1. 文字が文字の場合は、その小文字を末尾に追加します。`current`。 
2. それ以外の場合、`current`は空ではないので、完成した単語として処理します。 
5. 完成した単語を処理する場合:

 1. 入っていない場合`known`そして入っていない`seen_unknown`、答えをインクリメントして、に挿入します`seen_unknown`。 
2.クリア`current`。 
6. ループが終了したら、残りの単語を処理します。`current`同じロジックを使用します。 
7. 蓄積された回答を出力します。 

オンザフライで正規化する理由は、等価性チェックを壊す可能性がある大文字と小文字が混在したバリアントを保存することを避けるためです。 単語が完了するまでカウントを遅らせる理由は、句読点が単語の境界を妨げないようにするためです。 

### なぜ効果があるのか

 スキャンのどの時点でも、`current`は、テキスト内の 1 つの連続した文字シーケンスを正確に表します。 入力内のすべての単語は文字以外の文字で区切られているため、すべての単語は最終的に 1 回だけ確定されます。 未知の単語を挿入するので、`seen_unknown`最初に遭遇した直後は、その後の出現は答えに影響しません。 不変条件とは、`seen_unknown`常にカウントされた単語が正確に含まれており、`known`数える必要のないすべての単語が含まれます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    text = sys.stdin.readline().rstrip("\n")
    n = int(sys.stdin.readline())
    known_words = sys.stdin.readline().split()

    known = set(known_words)
    seen_unknown = set()

    ans = 0
    current = []

    def process(word):
        nonlocal ans
        if not word:
            return
        if word not in known and word not in seen_unknown:
            seen_unknown.add(word)
            ans += 1

    for ch in text:
        if ch.isalpha():
            current.append(ch.lower())
        else:
            if current:
                process("".join(current))
                current.clear()

    if current:
        process("".join(current))

    print(ans)

if __name__ == "__main__":
    solve()
```パフォーマンスに関する主な考慮事項は、ループ内で文字列の連結が繰り返されることを避けることです。 文字をリストに蓄積し、単語の境界に達した場合にのみ結合します。 これにより、文字数の合計における複雑さが線形に保たれます。 

また、蓄積中にすべての文字を明示的に小文字にすることで、後で単語を 2 回通過することを回避します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(T) | 各文字は 1 回処理され、各単語は平均 O(1) 時間でハッシュ セットに挿入/チェックされます。 
| スペース | O(T + n) | 最悪の場合、現在のワードプロセッサと辞書セットのすべての文字が保存されます。 

この制約では最大 500 万文字が許可されるため、文字ごとに一定時間の操作を行うリニア スキャンで制限内で十分です。 単語のセットと小さなバッファのみが保存されるため、メモリの使用は安全に保たれます。

 ## 特殊なケース

 特殊なケースの 1 つは、テキストが句読点のない文字列で終わる場合です。 その場合、明示的に処理しない限り、最後の単語は決して処理されません。 この解決策は、次の実行によってこれを修正します。`process(current)`ループが終了した後。 

入力：```
hello world
0
```トラバース中、「hello」と「world」は空間境界で処理され、最後にはバッファに単語は残りません。 最後のフラッシュでは何も行われず、正しさが確認されます。 

もう 1 つの特殊なケースは、複数の連続する句読点文字またはスペースです。 処理は文字から文字以外への移行時にのみトリガーされるため、区切り文字を繰り返しても空の単語は作成されません。 

入力：```
a,,!!b??
0
```アルゴリズムは「a」と「b」を 2 つの別々の単語として抽出し、両方とも 1 回だけカウントされます。
