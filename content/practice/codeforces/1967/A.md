 ## 解決策
 ## 問題の理解

 私たちには、1 から n までの番号が付けられたカードのセットが与えられます。 数字 i ごとに、そのタイプの a_i カードがあります。 k 個のコインもあり、各コインであらゆる種類の新しいカードを購入できるため、合計で k 個の購入を超えない限り、任意の数を増やすことができます。 購入後、すべてのカードを一列に並べ、長さ n の連続する部分配列が [1, 2, ..., n] の順列としていくつあるかを数えます。 私たちの仕事は、その数を最大化することです。 

入力は複数のテスト ケースで構成されます。 各テスト ケースは、n、k、および初期カウント a_1 から a_n を指定します。 各テスト ケースの出力は単一の整数、つまり完全な順列である長さ n の部分配列の最大数です。 

制約は大きく、n は最大 2×10^5、k は最大 10^12、a_i も最大 10^12 にすることができます。 これにより、すべてのサブ配列や再配置をシミュレートしようとするアプローチは除外されます。 シーケンスを明示的に生成するのではなく、カウントと分配のロジックに依存する必要があります。 

重要なエッジ ケースは、n = 1 の場合です。これは、すべてのカードが [1] の順列であることが自明であるためです。 別のケースは、k が a_i に対して極端に大きい場合に発生します。 すべての a_i を等しくするのに十分なカードを購入して、順列の数を最大化できるかもしれません。 不用意に実装すると、実際の配列を構築しようとして、メモリ制限またはオーバーフローが原因で失敗する可能性があります。 

## アプローチ

 ブルートフォース手法では、最大 k 枚の新しいカードを購入した後、カードのすべてのシーケンスを生成し、サイズ n のウィンドウをスライドさせて、各ウィンドウが順列であるかどうかを確認しようとします。 これは原理的には正しいですが、すぐに実行不可能になります。 n = 10^5 の場合でも、n 個あります。 a_i と k が 10^12 に達すると、長さ n の順列、および長さ sum(a_i) + k の配列の生成は不可能になります。 操作数は指数関数的に増加し、メモリ使用量は天文学的なものになります。 

重要な洞察は、問題が n 種類のカードを均等に分配することに帰着することを認識することです。 繰り返しシーケンスで順列を形成することを想像すると、長さ n の順列部分配列の最大数は、追加のカードを購入した後の任意のタイプの最小数によって決まります。 具体的には、購入後にすべてのタイプが少なくとも m 回出現することを確認できれば、m 個の完全な順列ブロックを形成できます。 残りのカードを使用すると、追加の順列を交互に形成できますが、支配的な要素は常に最小数のタイプになります。 

これにより、問題は二分探索に帰着します。最大 k 個のコインを使用して各 a_i を少なくとも m に増やすことができるように、最大​​の整数 m を探索します。 各候補 m について、必要な追加カードの合計を sum(max(0, m - a_i) for i = 1..n) として計算します。 その合計が <= k であれば、m は達成可能です。 二分探索は、実行可能な最大の m を効率的に見つけます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * (sum(a_i) + k)) | O(sum(a_i) + k) | 遅すぎる |
 | 二分探索 + カウンティング | O(n log(max(a_i) + k)) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. テスト ケースの数を読み取ります。 各テスト ケースを個別にループします。 
2. 現在のテスト ケースの場合、n、k、およびカウントの配列 a を読み取ります。 
3. 二分探索境界を初期化します。 可能な順列の最小値は 0 で、最大値は、最小タイプ max(a) + k を等しくするためにすべての k コインを費やした場合に可能な最大の数です。 
4. 二分探索を実行します。 各候補 m について、各 a_i を少なくとも m に上げるのに必要なコインの合計を計算します。 a_i がすでに >= m の場合、コインは必要ありません。 それ以外の場合は、m - a_i コインが必要です。 
5. 必要なコインの合計が k <= k の場合、候補 m が実行可能です。 検索を更新して、より大きな m を試してください。 それ以外の場合は、m を減らします。 
6. 二分探索の後、実現可能な最大の m は、保証できる完全な順列の最大数です。 
7. その数値を出力します。 

機能する理由: 二分探索が機能するのは、関数「実現可能」が単調であるためです。 m が達成可能であれば、それより小さな m も達成可能です。 m が達成できない場合、それより大きな m も不可能です。 不変条件は、[1, 2, ..., n] の少なくとも m 個の完全な順列を保証できるように、最後に最大の m を特定したことです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def max_permutations(n, k, a):
    low, high = 0, max(a) + k
    while low < high:
        mid = (low + high + 1) // 2
        required = sum(max(0, mid - x) for x in a)
        if required <= k:
            low = mid
        else:
            high = mid - 1
    return low

t = int(input())
for _ in range(t):
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    print(max_permutations(n, k, a))
```このソリューションでは、まず、現在の最大カード数と k コインに基づいて二分探索境界を設定します。 各候補 m について、必要なコインを計算し、それを k と比較します。 の選択`(low + high + 1) // 2`検索が実行可能な最大の m で正しく終了することを保証します。 の`max(0, mid - x)`a_i が Mid を下回るコインのみをカウントし、マイナスの寄与を回避します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log(max(a_i) + k)) | 各テスト ケースについて、二分探索は log(max(a_i) + k) 回反復され、各反復の n 回の合計が計算されます。 
| スペース | O(n) | 長さ n の配列 a を格納します。 追加の構造は必要ありません。 

n <= 2×10^5、すべてのテスト ケースの合計 <= 5x10^5、および k <= 10^12 の場合、ソリューションは 2 秒以内およびメモリ制約内で適切に実行されます。

## 特殊なケース

 n=1 の場合、任意の数のコインが単一タイプのカウントを直接増やすことができるため、出力は a_1 + k になります。 required = max(0, mid - a_1) であるため、二分探索はこれを正しく処理します。 a_i と比較して k が非常に大きい場合、二分探索により、コインを最適に分配した後に作成できる完全な順列の数が特定され、常に最小の調整されたタイプによって制御されます。 a_i がすでに大きく、k が小さい場合、アルゴリズムは、既存の最小数を超える追加の並べ替えは不可能であると正しく計算します。
