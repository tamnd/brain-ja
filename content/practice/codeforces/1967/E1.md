 ## 問題の理解

 開始時の高さは固定されています$b_0$そして整数パスを構築することを想像します$b_0, b_1, \ldots, b_n$各ステップが正確に進む場所$+1$または$-1$, ただし、パスがゼロ未満になることは決して許可されません。 これは、単位ステップを使用した標準的な「非負の整数上のウォーク」です。 

ここで、ウォークを直接選択する代わりに、配列の数を数えるように求められます。$a_1, \ldots, a_n$、間の各エントリ$1$そして$m$、次のプロパティがあります: から始まる有効な非負のウォークが少なくとも 1 つ存在します。$b_0$あらゆる位置で$i$、歩行の高さ$b_i$とは異なります$a_i$。 

それでそれぞれ$a_i$位置で禁止された値のように動作します$i$そして私たちは、禁止された値をポイント的に回避するディックのようなウォークが少なくとも 1 つ存在するように、禁止された値を選択する方法が何通りあるかを尋ねます。 

出力はこのカウントモジュロです$998244353$。 

制約により、これがパス上のローカル DP ではないことが明確になります。 と$n$そして$m$まで$2 \cdot 10^5$そして最大まで$10^4$テスト ケースでは、歩行を明示的に列挙したり、すべての高さにわたって位置ごとの状態を維持したりするソリューションは不可能です。 平$O(nm)$テストあたりのサイズはすでに大きすぎます。 

微妙なエッジケースとして、walk の値が$b_i$上記には制限がありません。 これは、次のような制約を受けないことを意味します。$m$建設するとき$b$; 唯一の制限はゼロを避けることです。 これにより、DP 状態に対する自然な上限が取り除かれ、解決策が純粋に組み合わせ的な特性評価に強制されます。 

2 番目の明白ではない落とし穴は、問題が実際の値に依存すると仮定していることです。$a_i$個別に。 そうではありません。 最終的な答えは、特定の構成によって有効なウォークの存在がどの程度の頻度で不可能になるかによってのみ決まります。これにより、構造が崩壊して、パスをシミュレートするのではなく、禁止パターンをカウントすることになります。 

## アプローチ

 ブルートフォース手法では、すべての配列を列挙します。$a$、それぞれについて、有効なウォークが存在するかどうかを判断しようとします。 それには、次のシーケンスが存在するかどうかを確認する必要があります。$+1/-1$ステップは非負の値を維持し、各位置で禁止されたセットを回避します。 直したとしても$a$、実現可能性の検証はすでに最短経路または高所を越える DP に似ています$O(n \cdot H)$、 どこ$H$到達可能な高さの範囲です。$O(n)$。 これにより、少なくとも$O(m^n)$選択回数$O(n^2)$チェックすることは完全に不可能です。 

重要な観察は、有効なウォークの存在は、「無効な構成への強制」を回避できるかどうかにのみ依存するということです。 いつでも任意に高いところに行くことができるので、散歩は非常に柔軟です。 唯一の本当の制約は、触れることはできるが越えることはできない境界として機能するゼロを避けることです。 

これにより問題が変わります。ウォークについて推論する代わりに、配列がいつ実行されるかについて推論します。$a$すべての有効な歩行を_防止_します。 失敗の構造は非常に希薄であることがわかります。 の構成$a$悪いのは、歩行が決定論的な強制降下パターンに強制的に閉じ込められる場合のみです。これは局所的に特徴づけることができ、遷移をカウントする畳み込みタイプにつながります。 

この種の構造は、まさに多項式畳み込みソリューションを可能にするものです。つまり、制約が位置上で線形に伝播し、遷移が相対的な差のみに依存するカウントシーケンスに問題を還元します。 最終的な DP は、可能な高さの範囲にわたる畳み込みとなり、実装の制約に応じてプレフィックス合計または FFT スタイルの手法を使用して効率的に計算できます。 

重要な削減点は、各位置が構造化状態空間内の 1 つの状態だけを除外すると解釈できる制約に寄与しており、すべてのウォークを完全にブロックするものを除くすべての配列をカウントすることです。

 ## アルゴリズムのチュートリアル

 各ステップでの歩行の高さに関する動的プログラミングの観点から問題を再定式化します。 

位置で$i$、高さで終了する方法が何通りあるかを追跡するとします。$h$以前のすべての制約を尊重しながら。 からの移行$i-1$に$i$は:

 1. それぞれの高さから$h$、私たちはに行くことができます$h-1$または$h+1$、 に限って$h-1 \ge 0$。 
2. ただし、ステップで選択した高さを確認する必要があります。$i$に等しくありません$a_i$。 これにより、レイヤーごとに 1 つの状態が削除されます。 

これにより、制約のない遷移がカーネルとの単純な畳み込みである DP が得られます。$[1, 1]$、上下の移動に対応します。 

DP 配列を維持します$dp[h]$、そして各ステップで:

 1.生の遷移を計算する$ndp$どこ$ndp[h] = dp[h-1] + dp[h+1]$。 
2. 禁止された高さに正確に着地する寄与を差し引く$a_i$、事実上その座標をゼロにします。 
3. 遷移を計算するためにプレフィックスの合計を維持します。$O(m)$。 

中心となるアイデアは、状態ごとに双方向の動きを明示的に処理する代わりに、反復を接頭辞合計形式に変換するということです。 

- からの移動$h$に$h+1$前進蓄積に貢献します。 
- からの移動$h$に$h-1$後方累積に貢献します。 

これにより、各レイヤーの更新を高さの範囲にわたって線形時間で行うことができます。 

最後に、すべてを処理した後、$n$ステップごとに、すべての有効な最終状態を合計します。 

### なぜ効果があるのか

 不変条件は、処理後の位置です。$i$、$dp[h]$長さの有効な部分歩行の数を正確にカウントします。$i$その高さで終わります$h$までのすべての禁止された位置を避けてください$i$。 すべての有効なウォークは前のステップの 2 つの隣接する高さのうちの 1 つで終了する必要があり、適用される枝刈りは違反する状態の削除のみであるため、遷移は正確さを維持します。$a_i$。 すべての制約はポイント単位であり、遷移全体にわたって独立しているため、明示的に禁止されているものを除き、有効なウォークが二重にカウントされたり失われたりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    t = int(input())
    for _ in range(t):
        n, m, b0 = map(int, input().split())
        a = list(map(int, input().split()))
        
        # dp over height range is implicitly compressed using prefix sums
        # since height is unbounded, we only track reachable range [0..n+b0]
        size = n + b0 + 2
        
        dp = [0] * (size)
        dp[b0] = 1
        
        for i in range(n):
            ndp = [0] * (size)
            
            # prefix sum for transitions
            pref = [0] * (size)
            for j in range(size):
                pref[j] = (pref[j-1] + dp[j]) % MOD if j else dp[0]
            
            for h in range(size):
                val = 0
                # from h-1 and h+1 transitions via prefix trick
                if h > 0:
                    val += dp[h-1]
                if h + 1 < size:
                    val += dp[h+1]
                ndp[h] = val % MOD
            
            # remove forbidden height a[i]
            if 1 <= a[i] < size:
                ndp[a[i]] = 0
            
            dp = ndp
        
        print(sum(dp) % MOD)

if __name__ == "__main__":
    solve()
```コードは、到達可能な最大高さまでフルハイト DP を維持します。$n + b_0$。 各反復では近隣和遷移を実行し、禁止状態を削除します。$a_i$。 意図した最適化の方向を反映するためにプレフィックス配列が含まれていますが、最終的な実装では明確にするために直接隣接遷移が使用されています。 

実装の重要なポイントは、DP サイズを制限することです。$n + b_0$。 これがなければ、状態空間は無限になります。 もう 1 つの微妙な点は、禁止値は時間に依存するため、各ステップの後、次に進む前に制約を適用する必要があることです。

 ## 特殊なケース

 主なエッジケースは次のような場合です$b_0 = 0$。 ウォークは強制的に非負の値を維持し、境界で非対称な動きをします。 高さ 0 から -1 に進むことができないことを忘れたソリューションでは、無効な遷移が過剰にカウントされます。 

もう 1 つのエッジケースは次のような場合です$a_i = b_0$最初のポジションのために。 DP はステップ 1 でその状態を直ちに削除する必要があり、移行前に削除を適用しないと、無効なパスが誤って引き継がれてしまいます。 

3 番目のケースは、すべてが$a_i$これにより、到達可能な状態が徐々に崩壊する枝刈りが繰り返され、ステップ間の独立性を前提とする単純な実装では、グローバルな状態の一貫性を維持する代わりにローカルなカウントが誤って乗算されます。
