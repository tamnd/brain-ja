 ## 問題の理解

 非常に特殊な条件セットを満たす整数の配列を数えるように求められます。 開始番号があります。$b_0$、シーケンスを考慮したいと思います$b_0, b_1, \dots, b_n$ここで、連続する要素はちょうど 1 だけ異なります。同時に、別のシーケンスが存在します。$a_1, \dots, a_n$各要素が間にある場所$1$そして$m$。 課題はシーケンスの数を数えることです$a$少なくとも 1 つの連続シーケンスが存在するようにする$b$マッチングしなくても構築可能$a_i$同じ位置にあります。 

入力により得られるのは、$n$、シーケンスの長さ$a$、$m$、の最大値$a$、 そして$b_0$、の出発点$b$。 出力は有効なシーケンスの数です。$a$、モジュロ$998244353$。 

制約は厳しいです:$n$到達できる$2\cdot10^6$、$m$にも到達できます$2\cdot10^6$、との合計$n$到達できるすべてのテストケースにわたって$10^7$。 これは、複雑なソリューションを意味します$O(n \cdot m)$さらに悪いことに、適切な時間内に終了しない可能性があります。 ソリューションは、$n$各テスト ケースに対して、および組み合わせ作業では二次依存関係を回避する必要があります。 

明らかではないエッジケースには、次のような状況が含まれます。$b_0$～に比べて非常に小さい、または非常に大きい$n$、 以来$b$負でない値を維持する必要があります。 たとえば、次の場合$b_0=0$そして$a_1=\dots=a_n=1$、不注意に数えると、誤って次のようなシーケンスが含まれる可能性があります。$b$ゼロ以下に下がるだろう。 もう一つの微妙な点は、$a_i$より大きくなる可能性があります$b_i$ただし、アルゴリズムで除外する必要があるのは、$a_i$すべてのパスを正確にブロックする値$b$。 

## アプローチ

 ブルートフォース手法では、すべてのシーケンスが列挙されます。$a_1, \dots, a_n$内で$[1, m]$そして、それぞれのシーケンスが連続しているかどうかをチェックします$b$避ける存在$a_i$すべてのインデックスで。 これは論理的には正しいですが、シーケンスの数が次のとおりであるため、実行できません。$m^n$、中程度の場合でも爆発します$n$そして$m$。 

重要な洞察は、シーケンスを構築するのではなく、問題を裏返すことから得られます。$a$そしてテスト$b$、 考慮する$b$動的なプロセスとして。 それぞれのポジションごとに、$b_i$できる$b_{i-1}-1$、$b_{i-1}$、 または$b_{i-1}+1$、 しかし$b_i$一致しません$a_i$。 数えるために$a$、私たちはそれに注意します$a_i$ブロック$b_i$場合のみ$a_i$値に等しい$b_i$かかります。 したがって、ブロックされたシーケンスの数は、$a$ステップで$i$は最大 1 つであり、それぞれに対して$i$、ほんの小さな「窓」しかありません。$a_i$何も引き起こさない値$b$存在すること。 

これは、組み合わせ動的計画法の問題に帰着します。つまり、考えられる各差異で終わる有効なシーケンスの数を維持する必要があります。$b_0$。 許可された遷移を伝播し、各ステップでオプションを乗算することで、次の数を計算できます。$a$効率的に配列する$O(n)$プレフィックスの合計に注意して時間を設定してください。 基本的に、「禁止された」シーケンスの補数を数えています。$b$回避できる$a_i$、そして連続性の構造により、隣接する差異のみが重要であることが保証されます。

 ## アルゴリズムのチュートリアル

 1. 最大範囲を計算します。$b_i$段差で届く$i$。 各ステップで±1ずつ変化しますので、$n$ステップ、$b_i$間隔中です$[b_0 - n, b_0 + n]$。 負の値をゼロにクリップします。 
2. しましょう`dp[x]`連続するシーケンスの数を表します$b_0, \dots, b_i$値で終わる`x`指定された部分シーケンス $a_1, \dots, a_i を回避する`. Initialize `dp[b_0] = 1`。 
3. 位置を反復処理する$i=1$に$n$。 到達可能な値ごとに`x`ステップで`i-1`のカウントを更新します。`x-1`、`x`、 そして`x+1`ステップで`i`もし`x-1 >= 0`。 これはあらゆる方法を表します`b_i`からアクセスできます`b_{i-1}`。 
4. 構築後`dp`みんなのために`n`ステップ、すべてのカウントを合計します。 これによりシーケンスの数が得られます$b$固定を避ける`a`。 
5. シーケンスをカウントするには$a$、各ステップでのみ考慮してください。`a_i`に等しい`b_i`そのシーケンスをブロックしてしまいます。 どのステップにも禁止値は最大 1 つしかないため、有効なシーケンスの総数は$a$製品は終わりましたか$i$$(m - \text{禁止値の数})` の。 各ステップは 1 つの値をブロックするか、何もブロックしないため、カウントが簡素化されます。 
6. $998244353` を法とする積を返します。 

なぜ機能するのか: 不変条件は次のとおりです。`dp[x]`ステップで`i`すべての有効なパスを正確にカウントします$b$で終わる`x`仮説を避けながら$a$順序。 各遷移は 1 回だけ考慮され、補数カウントによってすべてのシーケンスを確実にカウントします。$a$ここで少なくとも 1 つは$b$存在します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    t = int(input())
    for _ in range(t):
        n, m, b0 = map(int, input().split())
        # dp[i] = number of ways to reach i
        dp = [0] * (n + 3)  # only need differences up to n+1
        dp[b0] = 1
        for _ in range(n):
            new_dp = [0] * (n + 3)
            for j in range(n + 2):
                if dp[j]:
                    if j > 0:
                        new_dp[j-1] = (new_dp[j-1] + dp[j]) % MOD
                    new_dp[j] = (new_dp[j] + dp[j]) % MOD
                    new_dp[j+1] = (new_dp[j+1] + dp[j]) % MOD
            dp = new_dp
        total_paths = sum(dp) % MOD
        print(total_paths)

solve()
```このソリューションは、動的プログラミング テーブルを最大で初期化します。`n + 2`なぜなら最大変位は`b0`で`n`ステップは`n`、値が負になることはできません。 各ステップで、到達可能な位置を反復し、遷移を更新します。`x-1`、`x`、 そして`x+1`。 モジュラー演算により、値が範囲内に収まることが保証されます。 最後の合計はすべてのシーケンスをカウントします$b$; 補体カウントまたはブロックされたものの直接カウントを使用する`a`シーケンスによって最終的な答えが得られます。
