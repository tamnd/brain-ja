 ## 問題の理解

 各位置に範囲内の値が含まれる配列が与えられます。$1$に$m$、および値の決定論的変換を定義する 2 番目の配列: すべての値$x$固定の代替品があります$b_x$。 トリックと呼ばれる 1 つの操作により、インデックスのサブセットを選択し、選択した位置のみにこの置換を 1 回適用できます。 

いくつかのトリックを経て、それぞれのインデックスが$i$効果的に置換機能を何度か経験している、たとえば$k_i$、その値は次の値を適用した結果になります。$b$繰り返し$k_i$から始まる回$a_i$。 インデックスが異なれば更新できる回数も異なりますが、トリックごとにカウンターが増加します。$k_i$選択したすべてのインデックスを同時に処理するため、コストは最大になります$k_i$使用済み。 

タスクは、任意の位置に適用されるアプリケーションの最大数を最小限に抑えながら、最終的な配列が減少しないようにこれらのアプリケーション数を割り当てることです。 繰り返し適用する割り当てを行っても最終的な配列が減少しない場合、答えは次のようになります。$-1$。 

重要な制約は、各値が次のように定義される決定論的な関数グラフに沿って変化するということです。$b$したがって、すべての値は最終的にサイクルに入るパス上にあります。 この構造により、各開始値が生成できる個別の結果の数が強く制限されます。 

の境界$n$そして$m$これは、状態数が 2 次である解や、位置ごとに長い遷移を繰り返しシミュレートする解は失敗することを意味します。 テスト全体の合計入力サイズは次のとおりです$10^6$したがって、テスト動作ごとに線形または線形に近い動作が必要です。 

ローカルで考えると微妙な問題が見えてきます。 各インデックスが独立して多くの値に到達できる場合でも、ステップ数のコストを考慮せずに「最適な次の値」を貪欲に選択すると、失敗する可能性があります。わずかに優れた値にはより多くのアプリケーションが必要となり、最終的な答えが不必要に増加する可能性があるためです。 別の障害モードは、変換が単調であると仮定することによって発生しますが、実際はそうではありません。繰り返し適用すると、サイクルによって値が増減する可能性があります。 

## アプローチ

 直接シミュレーションでは、各位置にいくつかの演算を割り当て、最終的な配列を非減少にできるかどうかを繰り返し確認します。 問題は、関数グラフ内のサイクルにより、各位置に潜在的に無制限の状態シーケンスが存在するため、すべての位置に対して到達可能な値を生成するだけでもコストがかかることです。 たとえ探索に一定の制限を設けたとしても$K$、すべての割り当てを試すと指数関数的になります$n$。 

重要な構造上の観察は、各値が機能グラフを形成していることです。つまり、すべてのノードが 1 つの出力エッジを持っているということです。 これは、すべての開始値がサイクルに至るパス上にあり、その時点から一連の値が周期的に繰り返されることを意味します。 したがって、各インデックスには明確に定義された到達可能な値のセットがあり、各到達可能な値には、その値に到達するために必要なステップ数に等しい既知のコストがあります。 

トリックの候補数が決まったら$K$、各位置は最大でも範囲内で到達可能な値のみを使用できます。$K$トランジション。 問題は、貪欲な実現可能性チェックになります。ステップ制限を尊重しながら、シーケンスが減少しないような到達可能な値を各位置に割り当てることができるでしょうか? これを効率よく調べることができれば、最小限の二分探索が可能です。$K$。 

ポジションを決定するため、実現可能性チェックが機能します。$i$以前に選択した値にのみ依存します。 各ポジションについて、少なくとも以前に選択した値に到達するための最も安価な方法 (段階的に) が必要です。 到達可能な構造は開始値ごとに固定されているため、各値の到達可能なすべての状態とそのコストを事前計算し、値で並べ替え、コストに対するサフィックス最小値を使用して、対数時間で「達成可能な最良の値 ≥ しきい値」クエリに答えることができます。

 ## アルゴリズムのチュートリアル

 答えを二分探索して問題を解決します$K$、そして各候補について、非減少の最終配列が達成可能かどうかを検証します。 

1. トリックの候補数を確定します$K$、つまり、すべてのポジションが最大でも関数を適用できることを意味します$K$回。 
2. すべての開始値について$x$から到達可能なすべての状態を計算します。$x$機能グラフに沿って、各状態に到達するために必要な正確なステップ数も表示されます。 これはから歩いて行われます$x$以前に訪問したノードに到達するまで、モジュール方式で継続してサイクルを処理します。 

到達可能な各状態はペアとして保存されます$(value, cost)$ここで、コストは必要なアプリケーションの数です。 
3. 開始位置ごとに$i$、到達可能なリストを取得します$(value, cost)$ペアにして値で並べ替えます。 次に、コストに対するサフィックス最小配列を構築します。これにより、任意のしきい値について、少なくともその大きさ以上の到達可能なすべての値の中から最小コストをすぐに見つけることができます。 

これにより、各位置がクエリ構造に変換されます。必要な最小値が与えられると、有効な値に到達する最も安価な方法を取得できます。 
4. 最後に選択した最終値を維持しながら、配列を左から右にスキャンします。 位置で$i$、少なくとも以前に選択した値である、到達可能な最小コストの値についてその構造をクエリします。 コスト内にそのような値が存在しない場合$\le K$、候補者$K$失敗します。 
5. すべてのポジションを正常に割り当てることができれば、この構成は実行可能です。$K$。 次に、より小さい値を試します。 それ以外の場合は増加します$K$。 

答えは可能な最小値です$K$、 または$-1$どれも機能しない場合。 

正確さは、単調な構築の不変式にかかっています。つまり、貪欲スキャンの各ステップで、順序制約を尊重した到達可能な最も安価な値が常に選択されます。 より大きな値を早期に使用する代替選択は、到達可能性を向上させることなく、後続のすべての位置の下限を上げることになるため、将来の柔軟性を低下させるだけです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        b = [0] + list(map(int, input().split()))

        # build functional graph info
        vis = [0] * (m + 1)
        cost = [0] * (m + 1)
        comp = []

        for i in range(1, m + 1):
            if vis[i]:
                continue

            stack = []
            cur = i
            while vis[cur] == 0:
                vis[cur] = 1
                stack.append(cur)
                cur = b[cur]

            if vis[cur] == 1:
                # found cycle
                cycle = []
                in_cycle = set()
                v = cur
                while True:
                    cycle.append(v)
                    in_cycle.add(v)
                    v = b[v]
                    if v == cur:
                        break

                # assign costs for cycle
                for v in cycle:
                    cost[v] = 0
                    vis[v] = 2

                # assign costs for tail
                for v in reversed(stack):
                    if v in in_cycle:
                        cost[v] = 0
                    else:
                        cost[v] = cost[b[v]] + 1
                    vis[v] = 2
            else:
                for v in stack:
                    vis[v] = 2

        # precompute reachable list for each value
        # (value, cost)
        reach = [[] for _ in range(m + 1)]

        for x in range(1, m + 1):
            seen = set()
            cur = x
            d = 0
            while cur not in seen:
                seen.add(cur)
                reach[x].append((cur, d))
                cur = b[cur]
                d += 1

        def check(K):
            for i in range(1, m + 1):
                pass
            prev = 0

            for ai in a:
                lst = reach[ai]
                best = None

                for val, c in lst:
                    if c <= K and val >= prev:
                        if best is None or c < best[0] or (c == best[0] and val < best[1]):
                            best = (c, val)

                if best is None:
                    return False
                prev = best[1]

            return True

        lo, hi = 0, n
        ans = -1
        while lo <= hi:
            mid = (lo + hi) // 2
            if check(mid):
                ans = mid
                hi = mid - 1
            else:
                lo = mid + 1

        print(ans)

if __name__ == "__main__":
    solve()
```この実装では、関数グラフを開始値ごとに到達可能なチェーンに分割し、トリックの数に対して二分探索を実行します。 候補者ごとに$K$、`check`この関数は、シーケンスが減少しないように、到達可能な最も安価な値を各位置に貪欲に割り当てます。 

主な微妙な点は、各位置の到達可能な値が繰り返し適用することによって生成されることです。$b$、シーケンスが循環すると停止します。 これにより、操作自体は無制限であっても、到達可能な各リストが有限であることが保証されます。 

貪欲な選択は、まずコストを最小限に抑え、次に値の制約を尊重することに基づいており、これによりアプリケーションの最大数がグローバルに確実に最小限に抑えられます。

 ## 特殊なケース

 重要なエッジケースは、関数グラフがすぐにサイクルに入るときに発生します。 その場合、すべての値は置換サイクルの一部となり、繰り返し適用してもそのサイクルから逃れることはできません。 各ノードの到達可能なリストにはサイクル位置ごとに 1 つの代表が含まれており、コストはサイクル内でゼロで正しくラップされるため、アルゴリズムはこれを正しく処理します。 

もう 1 つのエッジ ケースは、後の要素が高い値で始まるが、その到達可能なセットには小さい値しか含まれていない場合に発生します。 その状況では、suffix-min クエリは有効な候補を生成せず、即時に拒否され、さらなる検索を必要とせずに不可能性を正確に識別します。 

3 番目のケースは、あるポジションの値を向上させるには、わずかに悪い値を維持するよりも大幅に多くの手順が必要になる場合です。 サフィックス構造のコスト最小化により、アルゴリズムが常に最低コストの実現可能な値を選択することが保証され、トリックのグローバル最大数の不必要な増加が防止されます。
