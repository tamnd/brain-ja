 ## 解決策
 ## 問題の理解

 私たちは、各セルが最初にゼロを含むセルのリボンに沿って移動するチップをシミュレートするように求められます。 最初のターンでは、チップは最初のセルから開始され、その後のターンごとに、チップを次のセルに移動するか、任意のセルにテレポートすることができます。 チップがセルに着地するたびに、そのセルの値が 1 ずつ増加します。 私たちの目標は、できるだけ少ないテレポートを使用して、セル内の整数のターゲット シーケンスに到達することです。 

入力は複数のテスト ケースで構成されます。 各テスト ケースにはリボンの長さがあります`n`そしてシーケンス`c`長さの`n`。 値`c[i]`チップがセルにアクセスする必要がある回数を示します`i`合計で。 最初のセルはゼロから始まりますが、チップは最初にそこに配置されるため、最初のセルには次の値が必要です。`c[0] ≥ 1`。 各テスト ケースに必要な最小限のテレポートを出力する必要があります。 

制約が示唆する`n`合計は最大 200,000 に達する可能性があります`n`すべてのテスト ケースの上限も 200,000 です。 これにより、考えられる各手を個別に検査するソリューションは除外されます。 テスト ケースごとに O(n) のソリューションが必要です。 

セルのターゲット値が前のセルのターゲット以下である場合、微妙なエッジ ケースが発生します。 たとえば、入力の場合`[1,0,1,0,1]`、単純なロジックでは、前に進むだけで常に十分であると想定する可能性がありますが、一部のセルでは前よりも少ない訪問数が必要であるため、オーバーシュートすることなくそれらを正しくインクリメントするには逆方向にテレポートする必要があります。そうしないと、単純なアプローチでは正しいセルでの訪問数が少なすぎます。 

もう 1 つのエッジ ケースは、次のような高い目標値を持つ単一セルです。`[12]`。 ここでは、移動は必要なく、増分を繰り返すだけで、テレポートはゼロになります。 これは、ソリューションが動きが不要なシーケンスを処理する必要があることを示しています。 

## アプローチ

 ブルートフォースアプローチでは、チップのすべてのターンをシミュレートし、移動とテレポートを明示的にカウントします。 セル 1 から開始し、可能であれば次のセルに移動し、必要に応じてテレポートします。 各ステップで、そのセルに必要な残りの訪問数を減らします。 これは論理的には機能しますが、演算上は O(c[i] の合計) になります。 c[i] は最大 10^9 になる可能性があるため、このアプローチは完全に実行不可能です。 

重要な洞察は、前方への移動により厳密に増加する順序でセルの最小増分が自動的に満たされることを観察することで得られます。 言い換えれば、もし`c[i] > c[i-1]`, 前に進むとセルにアクセスしたとみなされるため、右に移動してチップが自然に増加するようにするだけです。 テレポートは次の場合にのみ必要です`c[i]`未満です`c[i-1]`なぜなら、セルを「訪問解除」す​​ることはできないからです。 セル i の欠陥を修正するために必要なテレポートの数は正確に`c[i-1] - c[i]`, 前進による余剰は、後でこのセルにテレポートして再分配する必要があるためです。 

つまり、ターゲットがあるセルから次のセルに減少する場合にのみ、プラスの差を合計します。 最初のセルは、最初にチップを配置することで常に 1 回の訪問としてカウントされます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(c[i] の合計) | O(n) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る`t`。 テスト ケースごとに、次の内容を読んでください。`n`そしてターゲット配列`c`。 
2. カウンタの初期化`teleports`に`c[0] - 1`。 これは最初のセルを占めます。最初にそこにチップを配置するため、1 回の訪問は自動的に行われます。 
3. 2 番目のセルから最後のセルまでシーケンスを繰り返します。 細胞ごとに`i`、 もし`c[i] < c[i-1]`、増分`teleports`による`c[i-1] - c[i]`。 これは、前進移動のオーバーシュートを「修正」するために必要なテレポートの数を表します。 
4. シーケンスを処理した後、合計を出力します`teleports`。 

機能する理由: 先に進むと、各セルが順番に自然に増加します。 前のセルよりも増分が少なくて済むセルは、前進のみに頼ることはできません。 テレポートは、オーバーシュートせずに目標数を満たす唯一の方法です。 これらの不足分を合計すると、テレポートの最小数が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def min_teleports():
    t = int(input())
    for _ in range(t):
        n = int(input())
        c = list(map(int, input().split()))
        teleports = c[0] - 1
        for i in range(1, n):
            if c[i] < c[i-1]:
                teleports += c[i-1] - c[i]
        print(teleports)

if __name__ == "__main__":
    min_teleports()
```まず、テスト ケースの数を読み取ります。 テストケースごとに、シーケンスを読み取り、次のようにテレポートを初期化します。`c[0] - 1`。 配列を反復処理して、セルの訪問が前のセルよりも少なくなったときだけを考慮し、その差をテレポート数に追加します。 各テスト ケースの結果を出力すると、解決策が完了します。 高速入力を使用すると、最大の制約に対する制限時間内に確実に収まるようになります。
