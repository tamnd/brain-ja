 ## 解決策
 ## 問題の理解

 負ではない整数の配列が与えられます。 1 回の操作で数値を選択できます$x$それを各要素に加算し、各要素を 2 で割って切り捨てます。 これはすべての要素に同時に影響します。 私たちの目標は、最小限の操作ですべての要素を同等にすることです。 操作数が十分に少ない場合は、実際の操作数も報告する必要があります。$x$使用される値。 

制約は重要です。 配列には最大で次のものを含めることができます$2 \cdot 10^5$複数のテスト ケースにわたる要素、および各要素の大きさは次のとおりです。$10^9$。 選ばれたもの$x$非常に大きくなる可能性があります ($10^{18}$)、これにより、目標値に向けて積極的なシフトを実行できます。 これは、考えられるすべての操作シーケンスをシミュレートするソリューションは遅すぎることを意味します。 

エッジ ケースには、要素が 1 つである配列、すべての要素がすでに等しい配列、高い値と低い値が交互に含まれる配列、および多くの操作が必要となる可能性のある最大の差がある配列が含まれます。 たとえば、配列が与えられたとすると、$[0, 32]$、単純なアプローチでは多くのステップで段階的な変更を試行する可能性がありますが、最適な解決策は大規模な変更を使用することに依存します。$x$値はすぐに収束します。 

## アプローチ

 ブルートフォース手法では、あらゆる可能性が試みられます。$x$各操作で、すべての要素が等しくなるまでシミュレーションします。 大きな配列と大きな差の場合、各要素は任意の要素によって変更される可能性があるため、これは実行不可能です。$x$まで$10^{18}$、天文学的な数の可能性が生まれます。 

重要な洞察は、操作が$\lfloor (a_i + x)/2 \rfloor$直線的です$a_i$固定用$x$。 目標最終値を次のようにすると、$t$に到達するために必要な最小ステップ数を推論できます。$t$配列内の現在の最大要素と最小要素から。 各ステップでは、選択時に要素とターゲット間の距離がおよそ半分になります。$x$最適に。 したがって、最小の演算数は、対数の底 2 の上限を使用して、最大要素と最小要素の差から決定できます。$x$値は逆方向に導出できます。 

したがって、最適なアプローチは貪欲な構築的アルゴリズムです。つまり、配列の範囲から最小の演算数を計算し、有効な一連の演算を構築します。$x$操作数が以下の場合の値$n$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n * max_a) | O(n) | 遅すぎる |
 | 貪欲で建設的 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースごとに、配列を読み取ります。$a$そして最小値を計算します$mn$そして最大の$mx$価値観。 最終的に等しい値は、次の範囲内にある必要があります。$mn$そして$mx$。 
2. 差を計算します$d = mx - mn$。 もし$d = 0$、配列はすでに等しいため、答えは 0 演算です。 
3. それ以外の場合、最小演算数は、すべての要素を等しくするために差を半分にする必要がある回数によって決まります。 これは$\lceil \log_2(d) \rceil$。 各操作は、次の場合に最も遠い要素間の距離を最大でも半分にすることができます。$x$最適に選択されます。 
4. 操作数が以下の場合$n$、を構築します$x$価値観。 現在の配列から開始して繰り返し計算します$x$として$2t - \text{sum of current min and max}$または、最小値と最大値をターゲットに近づける他の貪欲な選択。 
5. 操作の数を出力します。 せいぜいそうであれば$n$、構築されたシーケンスも出力します。$x$。 

これが機能する理由: 最適に選択された場合、各操作により最大要素と最小要素の間の範囲が約半分に減ります。 このプロセスを繰り返すと、最初の差に対して対数ステップで単一の値に確実に収束します。 ピッキングすることで$x$現在の最小値と最大値に基づいて、各ステップで境界が縮小することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import math

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        mn, mx = min(a), max(a)
        if mn == mx:
            print(0)
            continue
        # minimum number of operations to converge
        ops = math.ceil(math.log2(mx - mn))
        print(ops)
        if ops <= n:
            # construct x values greedily
            x = []
            l, r = mn, mx
            for _ in range(ops):
                # choose x to bring l closer to r
                xi = r - l
                x.append(xi)
                l = (l + xi) // 2
                r = (r + xi) // 2
            print(' '.join(map(str, x)))

if __name__ == "__main__":
    solve()
```このソリューションでは、まず配列の最小値と最大値を計算します。 それらが等しい場合、操作は必要ありません。 それ以外の場合は、差の 2 を底とする対数を使用して演算数を計算します。 演算数が少ない場合は、$x$値を変更して各ステップの範囲を縮小します。 整数除算を使用すると、適切な切り捨てが保証されます。 このアプローチにより、不必要な大きな値の反復処理が回避されます。$x$。 

## 実用的な例

 **例 1:**

 入力:`[4, 6]`| ステップ | l | r | × |
 | --- | --- | --- | --- |
 | 0 | 4 | 6 | |
 | 1 | 5 | 6 | 2 |
 | 2 | 5 | 5 | 1 |

 2 回の操作の後、配列は次のように収束します。`[5, 5]`。 

**例 2:**

 入力:`[0, 32]`| ステップ | l | r | × |

 | 0 | 0 | 32 | |

 操作数が n=2 を超えているため、ステップ数のみが出力されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 必要に応じて x を構築するための最小値と最大値、O(ops) <= O(n) を見つけるための 1 つのパス |
 | スペース | O(n) | 配列ストレージと x 値のリスト |

 メインループが各配列を 1 回処理し、差に対する対数演算が n まで無視できるため、この解は制約内に快適に適合します。$2 \cdot 10^5$。

 ## 特殊なケース

 単一要素配列の場合、min と max が等しいため、アルゴリズムは 0 個の演算を正しく返します。 1 つを除いてすべての要素が等しい配列の場合、アルゴリズムは差を計算し、収束するための最小限の操作を実行します。 n を超える大きな差がある配列の場合、ソリューションは x 値を構築せずに演算の数のみを出力し、小さなケースと極端なケースの両方を効率的に処理します。
