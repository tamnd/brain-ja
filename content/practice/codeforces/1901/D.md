 ## 解決策
 ## 問題の理解

 最小初期電力を決定するように求められます$x$最適に攻撃する最初のモンスターを選択する限り、呪文がどのように伝播するかに関係なく、モンスターの列を倒すことができるチェーンライトニング呪文。 各モンスターには体力があります$a_i$、そして呪文は力から始まります$x$最初のターゲットでは、その後のヒットごとに 1 ずつ減少します。 問題は、最初のヒットの後、残りのモンスターをヒットする順序は任意ですが、隣接関係を尊重する必要があることです。次のターゲットは、以前にヒットしたモンスターの隣人でなければなりません。 これは、最悪の場合の伝播により、最も低い残りのダメージが最も高い体力を持つモンスターに割り当てられる可能性があることを意味します。 

私たちはあきらめています$3 \cdot 10^5$体力が最大のモンスター$10^9$。 呪文ヒットのあらゆる可能な順序を明示的に考慮するアルゴリズムは問題外です。$n!$順列。 これは、すべてのシーケンスをシミュレートすることなく、最悪のシナリオを推論する方法が必要であることを示唆しています。 注意すべきエッジ ケースには、非常に小さな配列 (サイズ 1 または 2)、すべての健全性が等しい配列、および健全性が厳密に増加または減少する配列が含まれます。これは、単純な貪欲なアプローチでは最小開始電力が過小評価される可能性があるためです。 

たとえば、入力が次の場合:```
3
1 10 1
```不注意なアプローチでは、最初に中央のモンスターを選択し、それが最適であると考えて、そこから直線的に減少するダメージを割り当てる可能性があります。 しかし、呪文が最初に極端なモンスターに当たった場合、私たちが選択しない限り、真ん中の高体力のモンスターが生き残る可能性があります$x$十分な大きさ。 正しい出力では、最適な最初のモンスターから開始して、ヒットのすべての順列がすべてのモンスターの殺害をもたらすことを保証する必要があります。 

## アプローチ

 ブルートフォースアプローチは、各開始位置を試し、隣接関係を考慮して残りのモンスターの有効な順列をすべて生成し、各シーケンスに必要な初期パワーを計算し、最大値を取得することです。 これは原理的には正しいですが、次のことが必要です。$O(n! \cdot n)$最悪の場合の操作は不可能です。$n = 3 \cdot 10^5$。 

重要な洞察は、最悪の場合、最大のダメージ減少は体力が最も高いモンスターにかかるということを理解することで得られます。 この呪文の効果は基本的に、ある位置から開始して、呪文が外側に伝播するにつれてダメージが 1 ずつ減少するというものです。 これは、配列を 2 つの半分 (選択した開始点からの左セグメントと右セグメント) に分割するものとして再構成できます。 各セグメントの最も遠いモンスターへのダメージは開始点からの距離となります。 最悪の場合の順列を生き延びるために、初期パワーは$x$満たさなければなりません$x \ge a_i + d$モンスターごとに、どこで$d$は、選択した方向の開始点からの距離です。 

このことから、初期パワーの最小値は、初期パワーの最大値が得られるように開始モンスターの選択によって決定されることがわかります。$a_i + \text{distance to start}$最小化されます。 これは古典的な 1D 配列最適化問題であり、次のように解決できます。$O(n)$順列をシミュレートするのではなく、プレフィックス maxima を使用して時間を計算します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | お(ん!) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての潜在的な開始モンスターについて、最大値を計算します。$a_i + \text{distance from start}$右にも左にも。 概念的には、モンスターへのダメージは距離が増加するにつれて直線的に減少するため、最も遠いモンスターが制限要因となります。 
2. プレフィックス最大値を左から右、右から左に事前計算します。 させて`pref[i]`最大値を保存する`a[i] - i`、 そして`suff[i]`最大値を保存する`a[i] - (n - 1 - i)`。 これらは、呪文が開始位置から左または右に伝播する場合に必要となる最悪の場合の追加パワーを表します。 
3. 各開始位置を反復処理し、必要な初期パワーを左右の伝播値の最大値に距離オフセットを加えたものとして計算します。 
4. すべての開始位置にわたる最小初期パワーを返します。 

これが機能するのは、呪文がどのように広がっても、各方向で最も遠いモンスターが常に開始時のパワーに比べて最小のダメージを受けるからです。 事前計算により`pref`そして`suff`では、問題をすべての順列の考慮から各インデックスでの単純な式の評価に縮小します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

# precompute prefix and suffix maxima for worst-case distances
pref = [0] * n
suff = [0] * n

pref[0] = a[0]
for i in range(1, n):
    pref[i] = max(pref[i-1], a[i] + i)

suff[-1] = a[-1]
for i in range(n-2, -1, -1):
    suff[i] = max(suff[i+1], a[i] + (n-1-i))

res = float('inf')
for i in range(n):
    left = pref[i-1] if i > 0 else float('-inf')
    right = suff[i+1] if i < n-1 else float('-inf')
    max_required = max(left - i if i > 0 else 0, right - (n-1-i) if i < n-1 else 0, a[i])
    res = min(res, max_required)

print(res)
```最初のループは、呪文が一番左のモンスターから始まり右に伝播すると仮定して、接頭辞の最大値を計算します。 それぞれ`pref[i]`インデックスからモンスターの最悪の条件を取得します。`0`に`i`。 2 番目のループでは、サフィックスに対して右から左に同​​じ処理を行います。 可能性のある各開始モンスターを反復処理するとき、両方向の最悪のケースをチェックして最大値を取得することによって、必要な呪文の威力を計算します。 最後に、そのような最小値が答えになります。 

境界条件は微妙です: 対処する必要があります`i=0`または`i=n-1`配列の片側にモンスターがいない場合。 これらは安全に次のように置き換えられます。`-inf`最大値への影響を避けるには、ゼロを指定します。 また、整数の減算は、距離計算における 1 つずつの誤差を避けるために慎重に処理する必要があります。
