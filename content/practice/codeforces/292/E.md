 ## 解決策
 ## 問題の理解

 2 つの整数配列を維持するように求められます。`a`そして`b`、それぞれの長さ`n`。 最初の配列`a`静的です: その値は決して変更されません。 2 番目の配列`b`は変更可能であり、次の 2 種類の操作を処理する必要があります。`a`の中へ`b`、および内の特定の要素の値をクエリします。`b`。 各コピー操作は、次の複数の要素に影響を与える可能性があります。`b`同時に、最大でサポートする必要があります`m`効率的な運用を実現します。 

制約を考慮すると、両方とも`n`そして`m`最大 100,000 まで可能です。 コピーあたり O(k) 時間でサブセグメントを文字通りコピーする単純な実装では、最悪の場合 (k も O(n) の場合) には最大 10^10 の操作が必要となり、これは 2 秒の時間制限をはるかに超えています。 これは、コピーごとの単純なループ クエリは実行不可能であることを意味します。 

複数のコピー操作が重なると、微妙なエッジケースが発生します。 たとえば、最初にコピーすると、`a[1:3]`の中へ`b[2:4]`そして後でコピーする`a[2:4]`の中へ`b[3:5]`、単純な配列上書き戦略では、元の配列を正しく追跡できない可能性があります。`a`要素は現在次のように表現されています`b`。 もう 1 つの潜在的な落とし穴は、次の要素をクエリすることです。`b`それは決して上書きされていません。 アルゴリズムは、元の値を正しく返す必要があります。`b`そのシナリオでは。 

## アプローチ

 ブルート フォース アプローチでは、コピー操作が直接シミュレートされます。 各タイプ 1 クエリはループします。`k`要素と代入`b[y + q] = a[x + q]`。 タイプ 2 の各クエリは単に次の値を返します。`b[x]`。 このアプローチは小さな入力に対しては正しく機能しますが、最悪の場合の時間計算量は O(m * n) で、これは 10^10 の演算に達する可能性があり、明らかに遅すぎます。 

パフォーマンスを向上させるための重要な点は、コピー操作が常に連続したブロックを次の場所から移動するということです。`a`に`b`。 各要素を個別に更新する代わりに、次の状態を表すことができます。`b`のセグメントに「オリジナル」または「リンク」として`a`。 これらのリンクを効率的な範囲更新と単一要素クエリをサポートする構造に格納すると、明示的なコピーを回避できます。 セグメント ツリーまたは treap のようなバランスのとれたツリー構造も機能しますが、より単純で十分なアプローチはマッピング配列を使用することです。`from_a`長さの`n`。 それぞれ`from_a[i]`インデックスを保存します`a`それ`b[i]`現在反映されている、または元の場合は -1`b`価値。 

コピーが発生すると、セグメント ツリーを使用して範囲のマッピング配列を O(log n) 時間で更新します。 クエリはマッピングに従い、次のいずれかを返します。`b[i]`もし`from_a[i] == -1`または対応する`a`それ以外の場合は値を設定します。 これにより、操作ごとの複雑さが O(k) から O(log n) に軽減され、合計操作が 2_10^5_log(10^5) 以内に維持されます。これは許容範囲内です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(m * n) | O(n) | 遅すぎる |
 | マッピング + セグメント ツリー | O(m log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を初期化する`from_a`サイズの`n`、-1で埋められます。 これにより、位置ごとに追跡されます。`b`の要素を指しているかどうか`a`または元の値を保持します。 
2. セグメントツリーを構築します`from_a`範囲の割り当てをサポートします。 各ノードは、-1 または開始インデックスのいずれかを格納します。`a`にマッピングされます。 セグメント ツリーを使用すると、部分範囲全体を O(log n) 時間で割り当てることができます。 
3. クエリごとに、コピー操作の場合は、セグメント ツリーで範囲の割り当てを実行します。 具体的には、クエリのコピーの場合`k`からの要素`a[x]`に`b[y]`、セグメントを割り当てます`[y, y + k - 1]`で`from_a`インデックスに対応する`[x, x + k - 1]`の`a`。 これにより、要素を物理的に移動することはなく、各要素がどこにあるかを追跡することが保証されます。`b`から読むべきです。 
4. クエリが読み取り操作の場合は、セグメント ツリーを使用して次の値を取得します。`from_a[x]`。 -1の場合は元の値を返す`b[x]`。 それ以外の場合は、正しいオフセットを計算します。`a`そして戻る`a[from_a[x]]`。 
5. すべてのクエリが処理されるまで繰り返し、タイプ 2 のクエリの結果を出力します。 

維持される不変条件は、どの位置でも維持されます。`i`で`b`、セグメント ツリーは、現在の値が元の値から来ているかどうかを常に知っています。`b[i]`または連続したセグメント`a`。 影響を受ける範囲はセグメント ツリーの割り当てによって常に置き換えられるため、重複するコピー操作は以前のマッピングを正しく上書きします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SegmentTree:
    def __init__(self, n):
        self.n = n
        self.data = [-1] * (4 * n)
        self.lazy = [None] * (4 * n)

    def push(self, v, l, r):
        if self.lazy[v] is not None:
            self.data[v] = self.lazy[v]
            if l != r:
                self.lazy[v*2] = self.lazy[v] + 0
                self.lazy[v*2+1] = self.lazy[v] + (r - l + 1)//2
            self.lazy[v] = None

    def update(self, v, l, r, ul, ur, val):
        self.push(v, l, r)
        if ur < l or r < ul:
            return
        if ul <= l and r <= ur:
            self.lazy[v] = val + (l - ul)
            self.push(v, l, r)
            return
        m = (l + r) // 2
        self.update(v*2, l, m, ul, ur, val)
        self.update(v*2+1, m+1, r, ul, ur, val)

    def query(self, v, l, r, pos):
        self.push(v, l, r)
        if l == r:
            return self.data[v]
        m = (l + r) // 2
        if pos <= m:
            return self.query(v*2, l, m, pos)
        else:
            return self.query(v*2+1, m+1, r, pos)

n, m = map(int, input().split())
a = list(map(int, input().split()))
b = list(map(int, input().split()))

tree = SegmentTree(n)

for _ in range(m):
    q = list(map(int, input().split()))
    if q[0] == 1:
        x, y, k = q[1]-1, q[2]-1, q[3]
        tree.update(1, 0, n-1, y, y+k-1, x)
    else:
        x = q[1]-1
        idx = tree.query(1, 0, n-1, x)
        print(a[idx] if idx != -1 else b[x])
```の`SegmentTree`クラスは範囲割り当ての遅延伝播を処理します。 の`update`このメソッドは、サブセグメントがコピーされるときに、ソース インデックスと一致するようにマッピングを正しくオフセットすることを保証します。`a`。 の`query`メソッドは、O(log n) 内の任意のインデックスの現在のマッピングを取得します。 ツリー内でゼロベースのインデックスを使用すると、1 ベースのクエリ入力から変換する際の off-by-1 エラーが回避されます。
