 ## 解決策
 ## 問題の理解

 コンピューター ネットワークを表す接続された無向グラフが与えられます。 タスクは、任意のグラフ構造を分析することではなく、グラフが 3 つの特定のトポロジの 1 つに正確に一致するかどうかを判断することです。 

バス トポロジは単なるパスです。 ちょうど 2 つの頂点が次数 1 の端点であり、他のすべての頂点は次数 2 です。 

リング トポロジはサイクルです。 すべての頂点には次数 2 があります。 

スター トポロジには、他のすべての頂点に接続された 1 つの中心頂点があります。 センターには学位がある$n-1$、残りのすべての頂点は次数 1 を持ちます。 

グラフは接続されることが保証されているため、接続性を自分で検証する必要はありません。 頂点の次数パターンを検査し、どのトポロジが一致するかを判断するだけで済みます。 

制約により、最大で次のことが許可されます。$10^5$頂点と$10^5$エッジ。 グラフを繰り返し走査したり、高価なペアごとのチェックを実行したりするアルゴリズムは不要になります。 入力全体には次のものしか含まれていないため、$O(m)$エッジ情報の場合、エッジと頂点にわたる線形スキャンが自然なターゲットになります。 アン$O(n+m)$解は簡単に制限内に収まりますが、二次関数は大きすぎて制限内に収まりません。$10^5$頂点。 

エッジの数だけを見ると、いくつかのエッジ ケースが誤った分類を引き起こす可能性があります。 

考慮する：```
4 3
1 2
1 3
1 4
```グラフには、$n-1$エッジはパスと同じですが、その次数シーケンスは次のようになります。$[3,1,1,1]$。 正しい答えは次のとおりです。```
star topology
```かどうかだけをチェックするソリューション$m=n-1$これをバスと呼ぶのは間違っています。 

別の例は次のとおりです。```
4 4
1 2
2 3
3 4
4 1
```すべての頂点には次数 2 があるため、これは次のようになります。```
ring topology
```接続性とエッジ数だけを見るだけでは十分ではありません。 頂点次数を検査する必要があります。 

最後の例:```
5 5
1 2
2 3
3 4
4 5
2 5
```度数は$[1,3,2,2,2]$。 このグラフは接続されていますが、必要な構造のいずれにも一致しません。 

正しい答えは次のとおりです。```
unknown topology
```## アプローチ

 ブルートフォースアプローチでは、各トポロジの形状を明示的に再構築することで、各トポロジを認識しようとします。 たとえば、すべての頂点から開始して、隣接する頂点を通過し、グラフが単一のパス、サイクル、またはスターを形成しているかどうかを確認できます。 グラフは接続されているため、このような走査は正しいですが、必要以上に多くのグラフ ロジックが含まれます。 

最悪の場合、グラフ ウォークやトポロジ チェックを繰り返し実行すると、次のような状態になる可能性があります。$O(n(n+m))$、これは必要な場合よりもはるかに大きいです。$n$到達する$10^5$。 

重要な観察は、3 つのトポロジすべてが頂点次数によって完全に特徴づけられるということです。 

リングの場合、すべての頂点の次数は 2 です。 

バスの場合、ちょうど 2 つの頂点が次数 1 を持ち、残りのすべての頂点が次数 2 を持ちます。 

星の場合、ちょうど 1 つの頂点が次数を持ちます$n-1$残りの頂点はすべて次数 1 になります。 

グラフは接続されることが保証されているため、この程度の条件で十分です。 追加の構造検証は必要ありません。 

これにより、問題全体が、エッジの読み取り中に頂点の次数を数えてから、いくつかの単純なパターンをチェックすることに集約されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n(n+m)) | O(n+m) | 遅すぎる |
 | 最適 | O(n+m) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む$n$そして$m$。 
2. 配列を作成する`deg`サイズの$n$ゼロに初期化されます。 
3. あらゆるエッジに$(u,v)$、増分`deg[u]`そして`deg[v]`。 

頂点の次数は入射エッジの数と正確に一致するため、すべてのエッジを処理した後の配列には完全な次数シーケンスが含まれます。 
4. すべての頂点に次数 2 があるかどうかを確認します。 

true の場合、グラフはリング トポロジです。 
5. 次数 1 を持つ頂点の数と次数 2 を持つ頂点の数を数えます。 

次数 1 の頂点がちょうど 2 つある場合、$n-2$次数 2 の頂点の場合、グラフはバス トポロジです。 
6.次数を持つ頂点の数を数えます$n-1$。 

そのような頂点が 1 つだけ存在し、残りが$n-1$頂点の次数は 1、グラフはスター トポロジです。 
7. 上記のいずれの条件も当てはまらない場合、出力`"unknown topology"`。 

### なぜ効果があるのか

 グラフはつながっており、これが重要な保証です。 

すべての頂点が次数 2 を持つ接続されたグラフは単一サイクルでなければならないため、リングになります。 

ちょうど 2 つの次数 1 の頂点と、残りのすべての次数 2 の頂点を持つ接続されたグラフは単一のパスでなければならないため、これはバスになります。 

次数の 1 つの頂点を持つ接続されたグラフ$n-1$他のすべての次数 1 は、その高次の頂点を中心とする星にしかなりえません。 

これらの条件は相互に排他的であり、必要な 3 つのトポロジを完全に特徴付けるため、アルゴリズムは常に正しい分類を返します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    deg = [0] * n

    for _ in range(m):
        u, v = map(int, input().split())
        deg[u - 1] += 1
        deg[v - 1] += 1

    if all(d == 2 for d in deg):
        print("ring topology")
        return

    cnt1 = sum(d == 1 for d in deg)
    cnt2 = sum(d == 2 for d in deg)

    if cnt1 == 2 and cnt2 == n - 2:
        print("bus topology")
        return

    cnt_center = sum(d == n - 1 for d in deg)

    if cnt_center == 1 and cnt1 == n - 1:
        print("star topology")
        return

    print("unknown topology")

if __name__ == "__main__":
    solve()
```実装はアルゴリズムに直接に従います。 

グラフから必要な情報は度数配列だけです。 すべてのエッジは各エンドポイントに 1 度寄与するため、すべてのエッジを 1 回処理するだけで十分です。 

3 つの有効なトポロジは、指定された制約に関して相互に排他的であるため、チェックの順序は特に重要ではありません。 コードは最初にリングをチェックし、次にバス、次にスターをチェックします。 

微妙な点は、星の状態をチェックするときに、すでに計算されている次数 1 の頂点の数を使用することです。 有効な星には度数中心が 1 つだけ存在する必要があります$n-1$そして他のすべての頂点は次数 1 を持つ必要があります。 

もう 1 つの詳細は、入力の 1 から始まる頂点番号付けから Python 配列の 0 から始まるインデックス付けへの変換です。
