 ## 解決策
 ## 問題の理解

 コンピューター ネットワークを表す無向グラフがあります。 頂点はコンピューター、辺はケーブルです。 ケーブルには 1 から 1 までの番号が付けられています。`m`入力に表示される順序で。 

各クエリは、インデックスからエッジの連続ブロックを削除します。`l`インデックスを付ける`r`、それらのエッジが一時的に切断されている間にグラフ内に残る接続コンポーネントの数を尋ねます。 回答後、グラフは次のクエリの前に元の状態に戻ります。 

グラフ自体は頂点の点で非常に小さく、最大 500 ノードのみです。 課題はエッジとクエリの数にあります。 最大 10,000 のエッジと 20,000 のクエリが存在できます。 グラフを再構築し、すべてのクエリに対して完全な走査を実行するソリューションは、コストが高すぎます。 

有益な観察は、すべてのクエリが正確に 2 つのエッジ範囲を保持していることです。 

- 前のエッジ`l`- 後のエッジ`r`削除された間隔は常に連続しています。 この構造により、問題は扱いやすくなります。 

不適切な解決策を簡単に破ってしまう微妙な状況がいくつかあります。 

平行なエッジを考慮します。```
2 2
1 2
1 2
1
1 1
```最初のエッジのみを削除しても 2 番目のエッジは残るため、グラフは接続されたままになり、答えは次のようになります。`1`。 2 つの頂点間にエッジが存在するかどうかのみを追跡するソリューションは、誤った結果を返します。`2`。 

もう 1 つの重要なケースは、すべてのエッジを削除することです。```
3 2
1 2
2 3
1
1 2
```グラフは 3 つの孤立した頂点になるため、答えは次のようになります。`3`。 少なくとも 1 つのエッジが残っていることを前提としたアプローチは、ここでは失敗します。 

3 番目のケースは、グラフがすでに切断されている場合です。```
4 1
1 2
1
1 1
```唯一のエッジを削除すると、4 つの頂点がすべて分離されるため、答えは次のようになります。`4`。 コンポーネントの数は、元のグラフの接続性とは関係ありません。 

この制約は、数百万回程度の操作が必要であることを強く示唆しています。 と`m = 10^4`そして`k = 2·10^4`、`O(m)`または`O(m log n)`クエリごとの回答には何億もの操作が必要となり、制限時間内に収まりません。 

## アプローチ

 最も直接的な解決策は、各クエリを個別に処理することです。 

お問い合わせの場合`[l, r]`、その区間内のエッジを除くすべてのエッジを含むグラフを作成し、DFS または BFS を実行して連結成分をカウントします。 これは、声明で説明されている実験を正確にシミュレートしているため、明らかに正しいです。 

問題はコストです。 クエリでは、すべてをスキャンする必要がある場合があります。`m`エッジを通過してからグラフを横断します。 複雑さはおおよそになります`O(k · (m + n))`。 

最大制限がある場合:```
k = 20000
m = 10000
```グラフ走査のオーバーヘッドを考慮する前に、約 2 億回のエッジ操作が得られます。 これでは遅すぎます。 

重要な点は、グラフの頂点が 500 個しかないことです。 

接続されたコンポーネントのみを考慮する場合は、DSU で十分です。 DSU の状態は、すでに追加されているエッジのセットによって完全に決定されます。 さらに、各クエリは 2 つの互いに素なエッジ セグメントを保持します。```
[1, l-1]
[r+1, m]
```これは、プレフィックスとサフィックスの DSU 情報を事前計算することを示唆しています。 

エッジのすべてのプレフィックスについて、そのプレフィックスの構築中に実行された成功したユニオンのシーケンスを保存します。 同様に、すべてのサフィックスについて、そのサフィックスを最後から構築するときに実行された成功した結合を保存します。 

それでは、ご質問に対して`[l, r]`では、空の DSU から始めて、次のように再生します。 

- 接頭辞からのすべての共用体`l-1`- サフィックスからのすべての共用体`r+1`頂点が 500 個しかないため、DSU が実行できるのは最大でも`n-1 ≤ 499`マージが成功しました。 したがって、保存された各プレフィックスまたはサフィックスには、最大 499 個の共用演算が含まれます。 

クエリごとに最大 10,000 のエッジを処理する代わりに、クエリごとに最大約 1000 の保存されたマージを処理します。 

この減少量は快適に通過するのに十分です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(k(m+n)) | O(m+n) | 遅すぎる |
 | 最適 | O(mn + kn) | O(mn) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのエッジを読み取り、内部で 0 から始まるインデックスに変換します。 
2. プレフィックス情報を構築します。 

DSU を作成し、左から右にエッジを追加します。 エッジが以前は別々だった 2 つのコンポーネントを結合するたびに、そのペアを`pref[i]`、 どこ`i`最初のものを表します`i`エッジ。 

失敗したユニオンは将来の接続に影響を与えないため、成功したユニオンのみが保存されます。 
3. ビルドサフィックス情報。 

別の DSU を作成し、右から左にエッジを追加します。 エッジが 2 つのコンポーネントを結合するたびに、そのペアを`suf[i]`、 どこ`i`からのエッジを表します`i`を通して`m`。 
4. 各クエリについて`[l, r]`を含む新しい DSU を作成します。`n`孤立した頂点。 
5. 保存されているすべてのマージを再生します。`pref[l-1]`。 

これらのマージは、削除された間隔の前にすべてのエッジによって寄与された接続を正確に表します。 
6. 保存されているすべてのマージを再生します。`suf[r+1]`。 

これらのマージは、削除された間隔後のすべてのエッジによって寄与された接続を正確に表します。 
7. DSU のコンポーネント カウンタは、エッジを削除した後の接続されたコンポーネントの数と等しくなります。`l...r`。 
8. そのカウンターを出力します。 

### なぜ効果があるのか

 あらゆるクエリを検討してください`[l, r]`。 

残りのグラフは 2 つのエッジ セットで構成されます。```
Eleft  = edges 1 ... l-1
Eright = edges r+1 ... m
```プレフィックスの前処理には、次の範囲にわたるフォレストが保存されます。`Eleft`。 サフィックスの前処理では、次の範囲にわたるフォレストが保存されます。`Eright`。 

スパン フォレストでは、接続されたコンポーネントが正確に保存されます。 結合を実行しないエッジは、以前に選択したエッジを介してすでに接続されている頂点を接続し、コンポーネントの構造とは無関係です。 

両方のフォレストから成功したすべての結合を新しい DSU に再生すると、残りのすべてのエッジを使用して生成されるのとまったく同じ接続コンポーネントが再構築されます。 したがって、DSU のコンポーネント数が正しい答えになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n
        self.components = n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)

        if a == b:
            return False

        if self.size[a] < self.size[b]:
            a, b = b, a

        self.parent[b] = a
        self.size[a] += self.size[b]
        self.components -= 1
        return True

def solve():
    n, m = map(int, input().split())

    edges = []
    for _ in range(m):
        u, v = map(int, input().split())
        edges.append((u - 1, v - 1))

    pref = [[] for _ in range(m + 1)]

    dsu = DSU(n)
    pref[0] = []

    for i in range(1, m + 1):
        pref[i] = pref[i - 1][:]

        u, v = edges[i - 1]
        if dsu.union(u, v):
            pref[i].append((u, v))

    suf = [[] for _ in range(m + 2)]

    dsu = DSU(n)

    for i in range(m, 0, -1):
        suf[i] = suf[i + 1][:]

        u, v = edges[i - 1]
        if dsu.union(u, v):
            suf[i].append((u, v))

    k = int(input())
    ans = []

    for _ in range(k):
        l, r = map(int, input().split())

        dsu = DSU(n)

        for u, v in pref[l - 1]:
            dsu.union(u, v)

        for u, v in suf[r + 1]:
            dsu.union(u, v)

        ans.append(str(dsu.components))

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```プレフィックス構造では、最初のプレフィックスを含む DSU が維持されます。`i`エッジ。 エッジが実際に 2 つのコンポーネントをマージするたびに、そのマージは保存されたフォレストに追加されます。 せいぜい`n-1`結合が成功しても、保存されているリストはすべて小さいままになります。 

接尾辞の構造は対称です。`suf[i]`エッジにまたがるフォレストを保存します`i...m`。 

各クエリでは、空の DSU から開始します。 プレフィックス フォレストとサフィックス フォレストを再生すると、残っているすべてのエッジの接続が再構築されます。 DSU によって維持されるコンポーネント カウンターが直接答えを与えます。 

最も一般的な実装上の間違いはインデックス作成です。 入力では、1 から始まるエッジ番号付けが使用されます。`pref[i]`最初に対応します`i`エッジなのでクエリ`[l, r]`用途`pref[l-1]`。 同様に、削除された間隔の後に最初に残っているエッジは次のようになります。`r+1`、したがって、私たちは使用します`suf[r+1]`。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(mn + kn) | 各プレフィックスとサフィックスのフォレストには、最大でも次のものが含まれます。`n-1`マージ |
 | スペース | O(mn) | まで保管します`n-1`各プレフィックスとサフィックスのマージ |

 以来`n ≤ 500`、保存されたすべてのフォレストのサイズは最大 499 です。前処理は大まかに実行されます。`m·n`最悪の場合、約 500 万回の操作が行われます。 各クエリは最大で約 1,000 回のマージを再生し、約 1,000 万回以上の操作が発生します。 これは制限内に快適に収まります。

 平行なエッジを考慮します。```

1 2
1

1
