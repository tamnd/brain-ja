 ## 解決策
 ## 問題の理解

 いくつかの独立したテスト ケースが与えられています。 各テスト ケースは、n 行 m 列の長方形グリッドと n·m 整数のマルチセットを記述します。 私たちのタスクは、これらすべての整数をセルごとに 1 つずつグリッドに配置し、エッジを共有する 2 つのセルに常に異なるパリティの数値が含まれるようにすることです。 言い換えれば、水平方向および垂直方向のすべての隣接関係は、偶数と奇数を接続する必要があります。 

出力は単なる妥当性チェックではなく、グリッド配置の明示的な構築です。 各テスト ケースでは、提供されたすべての値を使用して完全な n × m 行列を 1 回だけ出力するか、配置が存在しない場合は -1 を出力する必要があります。 

すべてのテスト ケースにわたって n·m が 100000 までという制約は、テスト ケースごとに本質的に線形の時間が必要であることを意味します。 ペアに対して繰り返し置換を試みたり、隣接条件をチェックしたりするソリューションは、遅すぎます。 私たちは、パリティ数と単純な順序のみに依存する構築を余儀なくされています。 

重要な観察事項は、要件の中にすでに示されています。隣接関係により、グリッドの厳密な 2 部構造が強制されます。 これは、問題をチェス盤のようなグリッドの色付けに直ちに結び付けます。 

パリティの実現可能性を無視すると、微妙な失敗のケースが発生します。 値 1、1、1、2 を持つ 2 × 2 のグリッドを考えてみましょう。奇数が 3 つと偶数が 1 つあります。 有効な配置では、チェス盤のようにパリティを交互にする必要があります。これにより、2 x 2 グリッドでは、奇数セルが 2 つと偶数セルが 2 つずつになります。 このインスタンスは機能しないため、答えは -1 でなければなりません。 カウントをチェックせずに貪欲な配置のみを試行する単純なアプローチでは、誤った出力が行われてしまいます。 

もう 1 つの特殊なケースは、単一の行または列です。 1 × m グリッドでは、隣接関係は線形であるため、依然としてパリ​​ティの厳密な変更が必要です。 これにより、シーケンスに沿って奇数と偶数の値が交互に配置されるようになり、実現可能性はライン全体でのパリティ カウントのバランスに依存します。 

## アプローチ

 ブルート フォース アプローチでは、セルに 1 つずつ値を割り当て、すべての配置後に既存の隣接関係がすべてパリティ制約を満たしているかどうかをチェックします。 各ステップで残りの未使用の値に分岐し、可能性が階乗的に増加するため、これはすぐに実行不可能になります。 枝刈りを行ったとしても、状態空間は基本的に n·m 個の項目の順列であり、これは n·m の許容範囲である 100000 をはるかに超えています。 

重要な単純化は、グリッド自体が固定された 2 部構造を課すことを認識することです。 (i + j) mod 2 でセルに色を付けると、すべての隣接エッジが反対の色の間に配置されます。 「隣接する数字は異なるパリティを持つ」という条件は、すべての黒セルが一方のパリティの数字を保持し、すべての白セルがもう一方のパリティの数字を保持する必要があることを意味します。 

これにより、問題は個々の値の配置から 2 つのグループ (偶数と奇数) に分散されるようになります。 どのパリティがどのカラー クラスに割り当てられるかがわかれば、カラーリングによって隣接関係が自動的に満たされるため、これらのクラス内の割り当ては機能します。 

したがって、問題は、カウントをグリッドの二分割サイズと一致させて、一貫した順序でセルを埋めることが可能かどうかを確認することになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | チェックを使用したブルート フォース配置 | O((nm)!) | O(nm) | 遅すぎる |
 | チェス盤の色分けによるパリティ パーティション | O(nm) | O(nm) | 承認済み |

 ## アルゴリズムのチュートリアル

 グリッドの自然な 2 部構造を使用して作業を進めます。

1. グリッド カラーリングの各パリティ クラスに属するセルの数を計算します。 グリッドの場合、1 つの色には ⌈nm/2⌉ セルがあり、もう 1 つの色には ⌊nm/2⌋ セルがあります。 これにより、必要な各パリティの値の数が決まります。 
2. 入力配列に奇数と偶数がいくつあるかを数えます。 これは、すべての値に対して 1 回のパスで実行されます。 
3. カラークラスへのパリティの可能な両方の割り当ての実現可能性を確認します。 奇数は黒のセルに一致し、偶数は白のセルに一致するか、その逆のいずれかでなければなりません。 どちらも一致しない場合、答えは不可能です。 
4. 有効な割り当てを選択します。 この問題では、どのカラー クラスが奇数の値に対応する必要があるかが解決されないため、この選択が必要になります。 
5. 2 つのリストを作成します。1 つはすべて奇数の値を含み、もう 1 つはすべて偶数の値を含みます。 各リスト内の順序は関係ありません。 
6. 行優先の順序でグリッドを移動します。 各セルについて、(i + j) mod 2 を使用してチェス盤の色を決定し、対応するリストから次の値を割り当てます。 
7. 塗りつぶされたグリッドを出力します。 

正確さは、隣接制約が 2 部カラーリングによって完全に捕捉されるという事実に依存しているため、パリティ クラスが一貫して割り当てられれば、それ以上の検証は必要ありません。 

### なぜ効果があるのか

 グリッド グラフは、標準的なチェス盤の色付けの下で 2 部構成になっており、すべてのエッジが反対の色を接続していることを意味します。 この制約では、隣接する値のパリティが異なる必要があるため、各エッジは奇数を偶数の値に接続する必要があります。 したがって、一方の色のすべてのセルには奇数の値のみが含まれ、もう一方の色のすべてのセルには偶数の値のみが含まれている必要があります。 これは必要かつ十分です。 パリティ カウントがカラー クラス サイズと一致すると、同じ色の 2 つのセルを接続するエッジが存在しないため、値とセルの間の全単射は有効性を維持します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))

        odds = [x for x in a if x % 2]
        evens = [x for x in a if x % 2 == 0]

        total = n * m
        black = (total + 1) // 2
        white = total // 2

        # try odd on black
        ok1 = (len(odds) == black and len(evens) == white)
        # try odd on white
        ok2 = (len(odds) == white and len(evens) == black)

        if not ok1 and not ok2:
            print(-1)
            continue

        if ok1:
            odd_cells = True  # black cells
        else:
            odd_cells = False

        oi = 0
        ei = 0

        res = [[0] * m for _ in range(n)]

        for i in range(n):
            for j in range(m):
                if (i + j) % 2 == 0:
                    if odd_cells:
                        res[i][j] = odds[oi]
                        oi += 1
                    else:
                        res[i][j] = evens[ei]
                        ei += 1
                else:
                    if odd_cells:
                        res[i][j] = evens[ei]
                        ei += 1
                    else:
                        res[i][j] = odds[oi]
                        oi += 1

        for row in res:
            print(*row)

solve()
```この実装では、まず線形時間のパリティによって値を分離します。 次に、パリティとチェスボードのカラー クラスの間で可能なグローバル割り当てが 2 つだけチェックされます。 グリッドは、パリティ リストへの 2 つのポインターを使用して、行優先の順序で埋められます。 

微妙な点は、セルの合計が奇数になる可能性があるため、整数除算を使用して黒と白のカウントを正しく計算することです。 もう 1 つは、入力分布に応じてどちらのマッピングも有効になる可能性があるため、コミットする前に両方の割り当てケースがテストされていることを確認することです。 

## 実用的な例

 単純な有効なケースを考えてみましょう。 

入力:

 値 = [1、2、2、3、4、1]

 オッズ = [1, 3, 1]、偶数 = [2, 2, 4] です。 セルの合計 = 6、つまり黒 = 3、白 = 3 です。両方のパリティ グループは完全に一致します。

 | 1 | (0,0) | 黒 | 奇数 | 2 | 3 |
 | 2 | (0,1) | 白 | 偶数 | 2 | 2 |

 すべての隣接関係がパリティ境界を越えるため、これにより完全に有効なグリッドが生成されます。 

次に、不可能なケースを考えてみましょう。 

入力:

 n = 2、m = 2

 値 = [1, 1, 1, 2]

 オッズ = 3、偶数 = 1 ですが、黒と白はそれぞれ 2 つのセルです。 

| チェック | 値 |
 | --- | --- |
 | 黒が必要 | 2 |
 | 白が必要 | 2 |
 | 奇数が利用可能 | 3 |
 | 利用可能でも | 1 |

 割り当ては機能しないため、アルゴリズムは正しく -1 を出力します。

 ## 特殊なケース

 1 × m グリッドでは、ラインに沿って厳密な交互配置が強制されます。 たとえば、値 [1、2、3、4、5] を持つ n = 1、m = 5 は、奇数と偶数のカウントが交互の位置に一致する可能性があるため機能します。 アルゴリズムはこれを、位置 j (j が偶数) に黒のセルがある標準的なチェス盤の色として扱うため、割り当ては同様に行われます。 

3 x 3 グリッド上の完全に奇数の入力はすぐに失敗します。 黒のセルが 5 つ、白のセルが 4 つあるため、両方のパリティが存在する必要があります。 アルゴリズムは、いずれかのパーティションに対する奇数カウントと偶数カウントの不一致によってこれを検出し、配置を試行せずに -1 を返します。 

偶数が 4 つと奇数が 5 つある 3 x 3 のような、ほぼバランスが取れているが不一致のケースは、パリティの割り当てがより大きなクラスと一致する場合にのみ受け入れられます。 このアルゴリズムは両方の方向を明示的にテストし、多数派パリティがすぐには明らかでない場合でも正確さを保証します。
