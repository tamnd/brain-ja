 ## 解決策
 ## 問題の理解

 各施設には、一定の日数にわたって一定数の訪問が行われます。 この履歴から周波数配列を計算します。$c_i$、各値は確立回数を表します$i$訪問されました。 

重要な観察は、最終的な答えはすべての施設の最大頻度のみに依存するということです。 させて$M = \max(c_i)$。 元の数を扱う代わりに、問題をバランス調整タスクに変換します。すべての施設に対して赤字を定義します。$h_i = M - c_i$、最も多くの訪問者に「追いつく」ためには、さらに何回訪問する必要があるかを示します。 

このプロセスでは、これらの不足を繰り返し削減するシミュレーションが行われます。 各段階で、赤字が大きい2つの事業所を組み合わせて両方を減らすか、特定の状況では、すべての赤字を一律に増加させ、同時に目標の最大値を増やすことを余儀なくされるかのどちらかです。$M$。 すべての赤字がゼロになると、プロセスは終了します。 

出力は事実上、これらのルールに基づいて必要な最小限の操作数です。操作は 2 つの欠損をペアにするか、ペアリングが不可能または不十分な場合にすべての欠損をグローバルに増加させます。 

この制約は、単純なシミュレーションが最大で次の処理を処理する必要があることを意味します。$O(D \cdot n)$各相互作用には、極端な値を繰り返し選択することが含まれます。 これは、配列の繰り返しスキャンに依存するソリューションは遅すぎるため、ヒープベースのシミュレーションであっても最悪の場合の動作を注意深く分析する必要があることを示唆しています。 

微妙な失敗のケースは、赤字の合計が奇数である場合、または最大の赤字が残りと比較して大きすぎる場合に発生します。 

たとえば、赤字 2 の施設が 1 つある場合、次のようにします。$h = [2]$、プロセスはそれを何ともペアリングできません。 単純な貪欲ペアリングはすぐに失敗しますが、正しい動作は、ペアリングが可能になるまでグローバル インクリメントをトリガーすることです。 

別の例は$h = [3, 1]$。 合計は均等ですが、最大の赤字が残りを上回っています。 アルゴリズムが実現可能性の条件を明示的にチェックしない限り、貪欲なペアリングでは不均衡を適切に減らすことができません。 

これらの状況は、正しさがローカルの貪欲ペアリングだけでなく、グローバルな構造の実現可能性にも依存することを示しています。 

## アプローチ

 ブルート フォース ビューは、説明されているプロセスを直接シミュレートします。 複数の欠損セットを維持し、最大 2 つの値を繰り返し抽出します。 両方が正の場合はそれらをデクリメントします。それ以外の場合は、すべての要素にグローバルなインクリメントを適用して増加します。$M$。 これは問題のステートメントと完全に一致しており、同じ遷移をたどっているため、明らかに正しいです。 

ただし、各操作では最大値を抽出し、場合によっては値を再挿入する必要があります。 まで$n$施設と潜在的に$O(D)$の成長$M$に達する操作の数$O(D \cdot n)$。 ヒープがあっても各ステップにコストがかかる$O(\log n)$を合計すると、$O(D \cdot n \log n)$、これは境界線に達しているか、大規模な入力に対して遅すぎます。 

重要な洞察は、ヒープ シミュレーションは単純な実現可能性条件を模倣しているだけであるということです。 要素を明示的にペアリングする代わりに、現在の状態でペアリングが可能かどうかだけを知る必要があります。 ペアリングは 2 つの条件が成立する場合に可能です。つまり、残りの赤字の合計が偶数であること、および、単一の赤字が大きすぎて残りの赤字に匹敵しないということです。 いずれかの条件が失敗した場合は、グローバル増分ステップを実行する必要があります。 

これにより、プロセスが繰り返し抽出から 2 つの集計量 (不足額の合計と最大不足額) の繰り返しチェックに変わります。 グローバルな増分ごとに、最大不足とすべての不足の両方が均一に増加し、構造が維持され、多くの中間ヒープ操作をスキップできるようになります。

 ## アルゴリズムのチュートリアル

 赤字配列を使用します$h$、各施設が現在の最大値からどれだけ離れているかを表すマルチセット表現$M$。 

1. 初期周波数を計算する$c_i$、 セット$M = \max(c_i)$、定義します$h_i = M - c_i$。 これにより問題が正規化され、すべての作業が生のカウントではなく欠損の観点から行われるようになります。 
2. 2 つの集計値 (合計) を維持します。$S = \sum h_i$そして最大値$maxH = \max(h_i)$。 これらは、個別の動作をシミュレートすることなくペアリングが構造的に可能であるかどうかをまとめています。 
3. 少なくとも 1 つの非ゼロが存在する間$h_i$、システムが「ペアリング可能」状態であるかどうかを確認します。 ペアリングには次のことが必要です$S$均等です、そしてそれ$maxH \le S - maxH$。 最初の条件は、すべての欠損がペアで一致することを保証し、2 番目の条件は、最大の欠損が残りを支配しないことを保証します。 
4. ペア可能条件が満たされない場合は、グローバル増分を実行します。つまり、次の間隔で増分します。$h_i$1ずつ増加します$M$このステップは、すべての施設が比較的「必要」になる追加ラウンドを強制することに対応し、バランスを回復します。 
5. 条件が成立する場合、概念的にはペアリング操作を実行します。 ペアリングごとに合計が減ります$S$2 ずつ減らして 2 つの大きな値を減らしますが、集計のみを追跡するため、次のように更新します。$S$それに応じて調整します$maxH$必要に応じて。 
6. すべての赤字がゼロになるまで続けます。 

中心的な考え方は、個々のペアの削除を明示的にシミュレートすることは決してないということです。 いつペアリングが可能かを決定するために十分なグローバル構造のみを維持します。 

### なぜ効果があるのか

 システムの状態は複数の欠損セットによって完全に特徴付けられますが、操作の実現可能性に関して重要なのは 2 つの特性だけです。それは、一致しないユニットの総数が偶数であるかどうか、および最大の欠損が残りの質量と一致できるかどうかです。 どちらかが失敗すると、一連のペア操作で現在の構成を完了できなくなり、グローバルな増分が強制されます。 

各グローバル増分は相対的な順序を維持しながら総容量を増加させ、最終的にシステムが貪欲なペアリングが常に可能な状態に到達することを保証します。 ペアリングは、可能な場合には常にシステムを最適に削減するため、代替シーケンスで生成されるグローバル増分を少なくすることはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    c = list(map(int, input().split()))

    M = max(c)
    h = [M - x for x in c]

    S = sum(h)

    while True:
        if S == 0:
            break

        maxH = max(h)

        if S % 2 == 0 and maxH <= S - maxH:
            # pair greedily in aggregate
            # we only need to reduce sum to zero
            # each conceptual operation removes 2 units
            # but we don't simulate individually here
            # collapse directly
            break

        # global increment
        n = len(h)
        h = [x + 1 for x in h]
        S += n

    print(S // 2)

if __name__ == "__main__":
    solve()
```このコードは、プロセスを実行可能性チェックの繰り返しに圧縮します。 重要な状態は欠損配列ですが、各ペアリングをシミュレートする代わりに、ペアリングが構造的に可能かどうかのみを追跡します。 実現可能性が成立した時点で、残る作業は純粋にペアリングです。$S/2$操作ごとに合計赤字が 2 ずつ減少するため、操作が減少します。 

微妙な点は、実現可能条件が満たされると、それ以上のグローバル増分は必要ないということです。 これが、ループがその瞬間にすぐに終了できる理由です。 

## 実用的な例

 ### 例 1

 検討してください$c = [3, 1, 1]$。 それから$M = 3$、 それで$h = [0, 2, 2]$。 

プロセスを追跡します。 

| ステップ | h 状態 | S | 最大H | 状態 | アクション |
 | --- | --- | --- | --- | --- | --- |
 | 1 | [0,2,2] | 4 | 2 | 4 偶数、2 ≤ 2 | ペアリング可能 |

 この時点でペアリングが可能であるため、グローバル増分を停止し、最終的な答えを次のように計算します。$S/2 = 2$。 

これは、システムがすでに十分にバランスが取れており、全体的な調整を回避できるクリーンなケースを示しています。 

### 例 2

 検討してください$c = [5, 1, 1]$。 それから$M = 5$、 それで$h = [0, 4, 4]$。 

| ステップ | h 状態 | S | 最大H | 状態 | アクション |
 | --- | --- | --- | --- | --- | --- |
 | 1 | [0,4,4] | 8 | 4 | 8 偶数、4 ≤ 4 | ペアリング可能 |

 これも直接解決可能ですが、代わりに$c = [5, 1, 0]$、私たちは得ます$h = [5, 0, 1]$ここで、不均衡はペアリングが有効になる前に少なくとも 1 つのグローバル増分を強制します。 

これらの例は、実現可能性がローカルの貪欲ペアリングではなくグローバル構造によって左右されることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + k) | 各グローバル増分はすべての要素に影響しますが、合計増分は実現可能性がどれくらい早く達成されるかによって制限されます。 
| スペース | O(n) | 不足配列 | のみを保存します。 

グローバルな増分ごとにシステムの容量が大幅に増加し、ペアリングが可能になると、集約された量に対する線形作業が即座に終了するため、アルゴリズムは効率を維持します。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

 ## 特殊なケース

 単一の施設の場合$c = [k]$、正規化後の赤字は常にゼロであるため、ペアリングが必要ないため、アルゴリズムはすぐにゼロの操作を返します。 

次のような非常に偏ったケースの場合$c = [100, 0, 0, 0]$、最初の赤字は 1 つの要素によって支配されます。 このアルゴリズムは、ペアリングが可能になる前に少なくとも 1 つのグローバル インクリメントをトリガーします。これは、ペアリングが発生する前に孤立した質量を再分配する必要があるという事実を反映しています。 

のような均一なケースの場合$c = [2,2,2,2]$、最初はすべての赤字がゼロであるため、システムはループに入らずにすぐに終了します。
