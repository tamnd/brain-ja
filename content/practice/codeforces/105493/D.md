 ## 解決策
 ## 問題の理解

 一連の正の整数が与えられます。 重複を削除した後、インデックスの昇順でそれらの位置に有向構造を構築することに興味があります。 2 つの値が自明でない公約数を共有する場合、つまり gcd が 1 より大きい場合、位置 j にある前の要素から、位置 i にある後の要素に移動することができます。 

タスクは、そのような動きの有効なシーケンスの最大長を計算することです。 各移動は配列内で厳密に前方に進む必要があり、各ステップでは、選択された 2 つの値が少なくとも 1 つの素因数を共有する必要があります。 

出力は単一の数値、つまりこれらのルールに従って構築できる最長のチェーンの長さです。 

制約が十分に大きいため、すべてのペアに対する二次アプローチは遅すぎます。 gcd チェックを使用した単純な O(n^2) トラバーサルはすでに境界線に達しており、値が大きい場合、gcd 計算を繰り返すと依然として負荷が高くなります。 本当のボトルネックは、以前のすべての要素と現在の要素の間の密な依存関係です。 

誤った試行を引き起こすことが多い微妙な問題は、一意の値のみが重要であるということを忘れていることです。 重複が削除されない場合、新しい接続を追加することなく、パスの長さが人為的に増大します。 もう 1 つの問題は、値空間における隣接性が重要であると想定していることです。 たとえば、6、10、15 のような数字は、値の順序が大きく離れていても、共有素数を介してより長いチェーンを形成します。 

構造を示す簡単な例:

 入力: 6、10、15

 6 と 15 も接続されていますが、gcd(6,10)=2 および gcd(10,15)=5 であるため、最適なチェーンは 6 → 10 → 15 です。 

単純なアプローチでは、任意の約数を共有する最も近い将来の要素に常に接続しようとする可能性がありますが、中間ノードをスキップすると長いチェーンがブロックされる可能性があるため、その貪欲なアイデアは失敗します。 

## アプローチ

 ブルートフォース解釈は簡単です。 すべてのインデックスをグラフ内のノードとして扱い、j < i かつ gcd(a[j], a[i]) > 1 の場合、j を i に接続します。次に、インデックスに対する動的計画法を使用して、この有向非巡回グラフ内の最長パスを計算します。 

各 i について、以前のすべての j を試し、エッジが存在する場合は dp[j] + 1 として dp[i] を更新します。 これによりすべてのペアがチェックされ、各チェックでは対数時間で gcd が使用されます。 n が 100000 までの場合、ペアの数は最悪の場合 10^10 になり、これはまったく実行不可能です。 

重要な観察は、gcd が 1 より大きいということは、少なくとも 1 つの素因数を共有することに等しいということです。 原子オブジェクトとしての数について推論する代わりに、その素因数についての推論に切り替えます。 各数値は小さな素数のセットとして表すことができ、遷移はこれらのセット間の共通部分にのみ依存します。 

これにより、遷移構造を折りたたむことができます。 以前のすべてのインデックスをチェックする代わりに、素数ごとに、この素​​数を含む以前の位置で終わる最適なチェーンを維持します。 次に、現在の数値について、それらの値を直接クエリすることで、それに含まれる任意の素数から拡張できます。 

これにより、インデックス上の密なグラフが素数上の疎な相互作用に縮小され、各要素が少数の状態のみに接触します。

 | ペアに対するブルート フォース DP | O(n^2 log A) | O(n) | 遅すぎる |
 | 状態圧縮を備えたプライムベースの DP | O(A log log A + n · Pmax) | O(A + n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各数値を個別の素因数のセットに圧縮します。 これを効率的に行うために、ふるいを使用して最小の素因数を事前に計算し、高速な因数分解を可能にします。 

配列 dpPrime[p] を維持します。これは、素数 p を含む数値の中でこれまでに確認された最良のチェーン長を表します。 これはキー状態の圧縮です。インデックスごとに最適なパスを記憶するのではなく、素数ごとに最適なパスを記憶します。 

数値を左から右に処理し、すべての遷移がインデックスの増加を考慮するようにします。 

### ステップ

1. 配列内の最大値までのすべての整数について、最小の素因数を事前計算します。 

これにより、すべての入力にわたってほぼ線形時間で各数値を因数分解できます。 
2. 各数値 a[i] について、最小の素因数テーブルを使用して繰り返し除算することにより、その個別の素因数のセットを抽出します。 

これにより、a[i] に関係する遷移に参加できるすべての素数が得られます。 
3. a[i] を除算するすべての素数 p の dpPrime[p] の最大値を取得し、1 を加算することにより、候補 dp[i] を計算します。 

これは、a[i] と素数を共有する任意の数で終わる最良の有効なチェーンを拡張することを表します。 
4. dp[i] が計算された後、a[i] を分割するすべての素数 p について dpPrime[p] = max(dpPrime[p], dp[i]) を更新します。 

これにより、現在の位置が将来の拡張に使用できるようになります。 
5. すべての位置にわたるグローバル最大 dp[i] を追跡し、それを返します。 

更新の順序は重要です。 まず前の状態から dp[i] を計算し、次に dpPrime を更新します。 これを逆にすると、数値自体が先行するものとして使用されることを誤って許可してしまうことになります。 

### なぜ効果があるのか

 任意の位置 i で、dpPrime[p] は、値に素数 p が含まれるインデックス j < i で終了する最良のチェーンを表します。 dp[i] を計算するとき、a[i] のすべての素数を考慮します。これは、i に遷移できるすべての有効な先行要素を正確に列挙します。 すべての有効なエッジは少なくとも 1 つの素数を共有する必要があり、そのようなすべての先行エッジはその素数の dpPrime で表されるため、遷移を見逃すことはありません。 順方向専用スキャンは、DP 順序付けの非周期性と正確さを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    if n == 0:
        print(0)
        return

    max_a = max(a)

    spf = list(range(max_a + 1))
    for i in range(2, int(max_a ** 0.5) + 1):
        if spf[i] == i:
            step = i
            start = i * i
            for j in range(start, max_a + 1, step):
                if spf[j] == j:
                    spf[j] = i

    def get_primes(x):
        res = []
        while x > 1:
            p = spf[x]
            res.append(p)
            while x % p == 0:
                x //= p
        return res

    dp_prime = {}
    ans = 1

    for x in a:
        primes = get_primes(x)

        best = 0
        for p in primes:
            if p in dp_prime:
                best = max(best, dp_prime[p])

        cur = best + 1
        ans = max(ans, cur)

        for p in primes:
            dp_prime[p] = max(dp_prime.get(p, 0), cur)

    print(ans)

if __name__ == "__main__":
    solve()
```ふるいは最小の素因数テーブルを構築するため、因数分解は試行除算の繰り返しに依存しません。 各数値は、その大きさではなく、その個別の素因数に比例して時間的に分解されます。 

ディクショナリ dp_prime には、各素数に関連付けられた最適なチェーン長が格納されます。 因数分解後に素数が大きくなりまばらになる可能性があるため、固定配列ではなく辞書を使用します。 

dp_prime を更新する前に、数値ごとに最初に最適な拡張を計算します。 この分離により、遷移では以前のインデックスのみが使用されることが保証されます。

## 複雑さの分析

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    from math import gcd

    def solve():
        n = int(sys.stdin.readline())
        a = list(map(int, sys.stdin.readline().split()))

        max_a = max(a)
        spf = list(range(max_a + 1))
        for i in range(2, int(max_a ** 0.5) + 1):
            if spf[i] == i:
                for j in range(i * i, max_a + 1, i):
                    if spf[j] == j:
                        spf[j] = i

        def get(x):
            res = []
            while x > 1:
                p = spf[x]
                res.append(p)
                while x % p == 0:
                    x //= p
            return res

        dp = {}
        ans = 1
        for x in a:
            ps = get(x)
            best = 0
            for p in ps:
                best = max(best, dp.get(p, 0))
            cur = best + 1
            ans = max(ans, cur)
            for p in ps:
                dp[p] = max(dp.get(p, 0), cur)

        return str(ans)

    return solve()

assert run("4\n2 3 5 7\n") == "1"
# mixed
assert run("5\n6 10 15 21 14\n") == "4"

 ## 特殊なケース

 特殊なケースの 1 つは、すべての数値がペアごとに互いに素である場合です。 たとえば:

 入力:```
4
2 3 5 7
```各数値には個別の素数セットがあるため、dp_prime は意味のある遷移を持ちません。 各 dp[i] は 1 になり、答えは 1 になります。素数が複数の位置に出現することはないため、アルゴリズムがこれを処理します。 

別のケースは、単一の素数の累乗の繰り返しです。 

入力:```
4
2 4 8 16
```ここで、すべての数値は素数 2 を共有します。 dp_prime[2] 値は、1、2、3、4 と単調に増加します。同じ素数がこれまでに確認されたグローバルな最大チェーン長を累積するため、各ステップは以前の最良のチェーンを正しく拡張します。
