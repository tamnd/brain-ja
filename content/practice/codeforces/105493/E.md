 ## 解決策
 ## 問題の理解

 2 つの特別な頂点が開始点として機能する有向非巡回グラフが与えられます。 これらの開始頂点のそれぞれから、前方の有向エッジをたどるパスを構築する必要があります。 最終的に、グラフ内のすべての頂点は、構築された 2 つのパスのうちの少なくとも 1 つに出現する必要があります。 パスは互いに素である必要はありませんが、それぞれが指定されたルートから始まる有効な有向ウォークである必要があります。 

構造は非巡回であるため、インスタンスが解決可能であれば、これらの開始点から何らかの順方向ですべての頂点に到達できます。 課題は、到達可能性だけではなく、2 つの単一の線形進行が、分岐や競合の再発生なしに結合してすべての頂点をカバーできるかどうかです。 

グラフに多くのエッジがある場合でも、意図された解決策はトポロジカルな順序付けから導出された層状構造に依存します。 この構造により、DAG はエッジが常に厳密に上方に移動するレベルに折りたたまれます。 

グラフに n 個の頂点と m 個のエッジがある場合、任意のパスの組み合わせを試みる単純な試みは組み合わせ論的に爆発します。 これを解決可能にする重要な制約は、トポロジー レベルを課すと、各頂点が明確に定義された位置を持ち、有効なパスはこれらのレベルを厳密に増加させる必要があるということです。 

最初の微妙な失敗ケースは、両方の開始点から頂点に到達できない場合に発生します。 そのような状況では、2 つのパスの構築にそれを含めることはできません。 2 番目の失敗ケースは、あるレベルに含まれる独立した頂点が多すぎる場合です。これは、レベルがパスに沿って厳密に増加する場合、各パスはレベルごとに最大 1 つの頂点しか寄与できないためです。 

具体的な問題のあるシナリオは、すべて以前のレイヤーに依存する 3 つの無関係な頂点を持つレイヤーです。 すべてが到達可能であっても、同じ深さで 3 つの独立した継続を強制する分割を 2 つのパスで同時にカバーすることはできません。 

## アプローチ

 強引な解釈では、2 つのパスを段階的に拡張するあらゆる方法を検討して、明示的に 2 つのパスを構築しようとします。 2 つのパスの現在の終端を表す各頂点ペアで、出力エッジに沿って可能なすべての次の移動を試みます。 各頂点が分岐する可能性があるため、ペアの状態の数はパスの長さに応じて指数関数的に増加し、密な分岐の場合にはおよそ O(2^n) 個の可能性が生じます。 これは、中程度のサイズのグラフであっても実現できません。 

重要な観察は、DAG 構造が厳密な階層を課しているということです。 各頂点に、その前の頂点の最大レベルに 1 を加えたレベルを割り当てることにより、すべてのエッジが下位レベルから上位レベルに移行します。 これにより、問題は任意のグラフ走査ではなく、レベル全体にわたる制御されたスイープに変わります。 

レベルを修正したら、2 つのパスはレベルごとに頂点を「消費」する必要があります。 どのレベルでも、パスは 1 つの頂点にのみ配置できます。 これは直ちに構造上の制限を意味します。実現可能なソリューションでは、各レベルに最大 2 つの頂点を含めることができます。そうでない場合は、2 つのパスのうち 1 つを分割する必要があり、これは不可能です。 

これにより、問題は実現可能性をレベルごとにチェックし、2 つのパスの終点がグラフのエッジと一貫して進むことができるかどうかを確認することに変わります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | n の指数 | O(n) | 遅すぎる |
 | レベルに貪欲な構築 | O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 次に、レベル構造を使用して構築プロセスを説明します。

1. 出力エッジに制限された DFS または BFS を使用して、両方の開始頂点からの到達可能性を計算します。 いずれかの頂点に到達しない場合は、直ちに不可能であると結論付けます。 これが必要なのは、すべての頂点が 2 つのパスの少なくとも 1 つに存在する必要があるためです。 
2. トポロジー順序を計算し、各頂点のレベルを、その先行する頂点の最大レベルに 1 を加えたものとして定義します。両方の開始頂点はレベル 0 で初期化されます。 これにより、すべてのエッジが下位レベルから上位レベルに移動することが保証されます。 
3. レベルごとに頂点をグループ化します。 グラフは非巡回であるため、レベルはゼロから上への有限シーケンスを形成します。 
4. 指定された 2 つのルートから開始して、2 つのパスの現在のエンドポイントを表す 2 つのポインターを初期化します。 
5. レベルを昇順に繰り返します。 各レベルで、そのレベルに属するすべての頂点を考慮します。 
6. レベルに頂点が含まれていない場合は、拡張するものが何もないため、次のレベルに進みます。 
7. レベルに 3 つ以上の頂点が含まれる場合、2 つのパスは単調進行に違反せずに同じレベルにある 3 つ以上の異なるノードをカバーできないため、不可能であると結論付けます。 
8. レベルに頂点 v が 1 つだけ含まれている場合、2 つのパスの端点のいずれかを v に移動しようとします。2 つの端点の少なくとも 1 つは v への有効なエッジを持っている必要があります。どちらの端点も v に直接到達できない場合、構築は失敗します。 
9. レベルにちょうど 2 つの頂点 v1 と v2 が含まれる場合、両方の割り当てを試します。 まず、パス m を v1 に、パス k を v2 に移動して、両方の遷移が存在するかどうかを確認します。 それが失敗した場合は、交換された割り当てを試します。 両方とも失敗した場合、このレベルには有効なペアが存在しません。 
10. すべてのレベルを処理した後、すべての頂点が一貫して割り当てられていれば、結果として得られる 2 つのシーケンスによって必要なパスが定義されます。 

なぜ効果があるのか

 重要な不変条件は、いつでも 2 つのパスのエンドポイントが各パスの最も高い処理レベルに正確に対応するということです。 レベルは厳密にエッジに沿って増加するため、有効なパスはすべてこの順序を尊重する必要があります。 貪欲な割り当てにより、頂点がそのレベルでパスに割り当てられると、後で再訪したり再配置したりする必要がなくなります。 レベルが現在のエンドポイントと一致しない場合は、以前のコミットメントと一致する有効な継続が存在しないことを意味するため、完全なソリューションはレベルの制約と矛盾します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import deque, defaultdict

def solve():
    n, m = map(int, input().split())
    g = [[] for _ in range(n)]
    rg = [[] for _ in range(n)]
    indeg = [0] * n

    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        rg[v].append(u)
        indeg[v] += 1

    t1, t2 = map(int, input().split())
    t1 -= 1
    t2 -= 1

    vis = [False] * n

    def bfs(start):
        q = deque([start])
        vis[start] = True
        while q:
            u = q.popleft()
            for v in g[u]:
                if not vis[v]:
                    vis[v] = True
                    q.append(v)

    bfs(t1)
    bfs(t2)

    if not all(vis):
        print("No")
        return

    # topological order
    q = deque([i for i in range(n) if indeg[i] == 0])
    topo = []
    while q:
        u = q.popleft()
        topo.append(u)
        for v in g[u]:
            indeg[v] -= 1
            if indeg[v] == 0:
                q.append(v)

    level = [0] * n
    pos = {v: i for i, v in enumerate(topo)}

    # compute levels in topo order
    for u in topo:
        for v in g[u]:
            level[v] = max(level[v], level[u] + 1)

    groups = defaultdict(list)
    maxL = 0
    for i in range(n):
        groups[level[i]].append(i)
        maxL = max(maxL, level[i])

    def can(u, v):
        return v in g[u]

    mcur, kcur = t1, t2

    for L in range(maxL + 1):
        nodes = groups[L]

        if not nodes:
            continue

        if len(nodes) > 2:
            print("No")
            return

        if len(nodes) == 1:
            v = nodes[0]
            if mcur != v and kcur != v:
                if can(mcur, v):
                    mcur = v
                elif can(kcur, v):
                    kcur = v
                else:
                    print("No")
                    return
            continue

        v1, v2 = nodes

        ok1 = can(mcur, v1) and can(kcur, v2)
        ok2 = can(mcur, v2) and can(kcur, v1)

        if ok1:
            mcur, kcur = v1, v2
        elif ok2:
            mcur, kcur = v2, v1
        else:
            print("No")
            return

    print("Yes")

if __name__ == "__main__":
    solve()
```このソリューションでは、まず、すべての頂点が少なくとも 1 つの開始点から到達可能であることを検証します。 これが必要なのは、到達できない頂点が両方の構築されたパスの外側に残るためです。 

次に、トポロジカルな順序付けを構築し、そこからレベルを導き出します。 レベルの計算により、すべてのエッジが厳密な単調性を遵守することが保証されます。 グループ化ステップでは、同じ依存関係の深さを共有するため、一緒に処理する必要がある頂点を収集します。 

貪欲ループは、2 つのパスの現在のエンドポイントを維持します。 各レベルでは、これらのエンドポイントが強制的に前進します。 ヘルパー関数は隣接性をチェックし、有効なエッジに沿ってのみ移動することを保証します。 

微妙な点は、レベルに 1 つのノードがある場合、それをいずれかのパスのエンドポイントに割り当てることができなければならないことです。 両方が失敗した場合、それは局所的な問題ではなく、以前の決定によってすでに構造がロックされているため、世界的に不可能になります。

| レベル | ノード | マキュア | ククル | アクション |

次に、失敗した構造を考えてみましょう。

これら 2 つのトレースは、このソリューションが完全にレベル容量の制約と連続するレイヤー間のエッジの実現可能性によって推進されていることを示しています。

 ## 特殊なケース

 レベルに頂点が 1 つだけ含まれているが、現在のエンドポイントの 1 つだけがそのレベルに到達できる場合、重大なエッジ ケースが発生します。 どちらの端点にもその頂点への直接のエッジがない場合、アルゴリズムは直ちに失敗する必要があります。 これは、抽象的にはグローバルな到達可能性がまだ存在しているにもかかわらず、初期のルーティング決定により両方のパスを必要なレベル構造に合わせることが不可能になった状況を表しています。 

レベル内に 2 つの頂点が表示されるが、一貫したペアリングが 1 つしかできない場合には、別のケースが発生します。 アルゴリズムは両方の割り当てを明示的に試行し、両方向で失敗した場合は、いずれかの試行によって 1 つのパスが必要な頂点をスキップし、単調レベル進行制約に違反することを示します。
