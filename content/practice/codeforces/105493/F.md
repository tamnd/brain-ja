 ## 解決策
 ## 問題の理解

 数直線上に一定の大きな間隔と、いくつかの小さな間隔が与えられます。 それぞれの小さな間隔は、大きな間隔の一部のカバレッジに寄与します。 課題は、大きな間隔がどれだけカバーされているかを知ることだけではなく、このカバレッジがオーバーラップの深さによってどのように分散されているかを理解することです。 

すべての整数のしきい値について$h$、より少ない数でカバーされる大きな区間の合計の長さを知りたいのです。$h$小さな間隔。 同様に、ポイントが 0、1、2、… の間隔でカバーされている場合、カバレッジ数が最大でも$h-1$。 

直接的な解釈は、大きな間隔内のすべてのポイントについて、それをカバーする小さな間隔の数を計算し、その後、カバレッジ値によって長さを集計することです。 これは直ちに削減を示唆します。「カバレッジ < h」と答える代わりに、最初に正確にカバーされる長さを計算します。$k$全員の間隔$k$、次に、これらの値に対してプレフィックスの合計を構築します。 

大きな間隔はすべての寄与を制限するため、その外側の小さな間隔の部分は無関係です。 これは、すべてのセグメントを範囲に安全にクリップできることを意味します。$[S, F]$。 

制約 (ICPC スタイルのステートメント構造によって暗示される) により、通常は最大で次のことが許可されます。$n$の順序で$2 \cdot 10^5$以上。 したがって、解決策は次のようなものでなければなりません。$O(n \log n)$または$O(n)$。 ポイントごとにカバレッジを明示的に追跡したり、間隔のクエリごとのスキャンを使用したりするアプローチは、遅すぎます。 

セグメントが大きな間隔の外側に広がる場合、微妙な失敗のケースが発生します。 たとえば、次の場合$[S, F] = [10, 20]$そしてセグメントは$[1, 15]$、その部分のみ$[10, 15]$重要です。 クリップを忘れると、対象領域外の長さをカウントしすぎてしまいます。 同様に、完全に外側のセグメント$[S, F]$、 のような$[1, 5]$または$[25, 30]$、完全に無視する必要があります。 

複数のセグメントのエンドポイントが一致する場合、別の特殊なケースが発生します。 イベントの順序が重要になります。 1 つのセグメントが別のセグメントの開始位置と正確に一致する場合、順序が間違っていると、単一点の重複カウントが人為的に増加する可能性があります。 

## アプローチ

 単純なアプローチは、大きな間隔を単位位置または詳細な座標に離散化し、各点について、その間隔をカバーする間隔の数をカウントすることです。 これは概念的に機能します。すべての整数または座標スライスについて、すべてのセグメントをチェックし、セグメントがカバーする場合はカウンターをインクリメントします。 すべての位置のカバレッジ数を計算した後、周波数ごとに長さを累積できます。 

このアプローチは正しいですが、遅すぎます。 間隔の長さが長い場合、$L$、ポイントごとのチェックコスト$O(nL)$、次のようなものに退化します。$10^{10}$両方の場合の操作$n$そして$L$大きいです。 数直線が密である場合や端点が大きい場合には、座標圧縮も役に立ちませんが、連続的な寄与は重要です。 

重要な観察は、カバレッジがセグメントのエンドポイントでのみ変化するということです。 2 つの連続するエンドポイント間では、アクティブなセグメントの数は一定のままであるため、その間隔全体の寄与を 1 回のショットで計算できます。 これにより、問題は、すべての重要なポイントをスイープしながら、アクティブな間隔の動的なカウントを維持することに変わります。 

各セグメントを 2 つのイベントに変換します。1 つは寄与を開始したとき、もう 1 つは寄与を停止したときです。 にクリッピングした後、$[S, F]$、各セグメントは、その左側の境界で「開く」イベントを提供し、右側の境界で「閉じる」イベントを提供します。 これらのイベントをソートされた順序でスイープすると、現在アクティブなセグメントの数を追跡し、重複カウントが同じである間隔の長さを蓄積することができます。 

微妙だが重要な詳細は、イベントの順序付けです。 同じ座標では、開始イベントの前に終了イベントを処理する必要があります。 そうしないと、共有境界に正確にある点が、両方のセグメントによって同時にカバーされているものとして誤ってカウントされてしまいます。 

このスイープライン アプローチにより、イベントの並べ替えとリニア スキャンの実行の問題が軽減され、効率的で安定しています。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n \cdot (F-S))$|$O(1)$または$O(F-S)$| 遅すぎる |
 | 最適なスイープライン |$O(n \log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 考えられるカバレッジ数ごとに、問題をコンピューティングに変換します。$k$、ちょうどカバーされる大きな区間の全長$k$セグメント。 これらの値がわかれば、しきい値の答えが得られます。$h$は単純に次からのすべてのカウントの合計です。$0$に$h-1$。 

1. セグメントごと$[b_i, e_i]$に置き換えて、まず意味のある範囲に制限します。$[\max(b_i, S), \min(e_i, F)]$。 結果の間隔が空の場合、何も寄与しません。 このステップにより、セグメントの関連部分のみが処理されるようになります。 
2. クリップされたセグメントごとに 2 つのイベントを作成します。1 つは開始時にアクティブ カバレッジの増加をマークし、もう 1 つは終了に減少をマークします。 これらのイベントは、オーバーラップ数が変化するポイントを表します。 
3. すべてのイベントを座標で並べ替えます。2 つのイベントが同じ座標を共有する場合は、開始イベントの前に終了イベントを処理します。 この順序付けにより、境界に正確にある点が重複するセグメント内で二重にカウントされないことが保証されます。 
4. 変数を維持する`active`現在スイープ位置をカバーしているセグメントの数と変数を表します。`last`前のイベントの座標を表します。 
5. 一つのイベント位置から移動する場合`x`次への間隔$[last, x]$以下に等しい一定のカバレッジを持っています`active`。 その長さを追加します$x - last$そのカバレッジ レベルに対応するバケットにコピーされます。 
6. 座標でイベントを処理する`x`アップデートすることで`active`: クローズ イベントの場合は減分し、オープン イベントの場合は増分します。 
7.アップデート`last = x`すべてのイベントが処理されるまで続行します。 
8. スイープ後、値が得られます`c[k]`正確なカバレッジ数を確認するには。 プレフィックスの合計を計算して取得します。`a[h] = c[0] + c[1] + ... + c[h-1]`。 

重要な不変条件は、任意の 2 つの連続するイベント座標間では、アクティブなセグメントのセットが変化しないことです。 したがって、カバレッジ数はその間隔では一定であり、その全長を 1 つのバケットに割り当てることは正しいことになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, S, F = map(int, input().split())
    
    events = []
    
    for _ in range(n):
        b, e = map(int, input().split())
        l = max(b, S)
        r = min(e, F)
        if l >= r:
            continue
        events.append((l, 1))   # open
        events.append((r, -1))  # close
    
    # sort: coordinate asc, close (-1) before open (+1)
    events.sort(key=lambda x: (x[0], x[1]))
    
    # max possible overlap is n
    c = [0] * (n + 1)
    
    active = 0
    last = S
    
    for x, typ in events:
        if x > last:
            c[active] += x - last
            last = x
        
        active += typ
    
    # no more events, but interval may continue to F
    if last < F:
        c[active] += F - last
    
    # prefix sums for answers
    a = [0] * (n + 1)
    for i in range(n):
        a[i + 1] = a[i] + c[i]
    
    print(*a[1:])

if __name__ == "__main__":
    solve()
```コードは、セグメントを読み取り、即座にそれらを関連する範囲にクリップすることから始まります。 これにより、ターゲット間隔外からの誤った寄与が回避されます。 有効なクリップされた各セグメントはちょうど 2 つのイベントを生成し、これらはタイブレークで並べ替えられ、近いイベントが最初に処理されるようになります。 

スイープでは、アクティブなセグメントの数が維持されます。 スイープが時間内に進むたびに、以前のアクティブ カウントを使用して、コントリビューション長が正しいバケットに蓄積されます。 

よくある実装の落とし穴は、最後のイベント位置から最後のセグメントまでの処理を忘れることです。$F$。 コードは、この残りの間隔を明示的に追加します。 もう 1 つの微妙な問題は、イベントの並べ替えです。`(x, typ)`機能するので`-1 < +1`、正しい境界処理を保証します。 

## 実用的な例

 大きなセグメントが次のような単純なケースを考えてみましょう。$[0, 10]$2 つの小さなセグメントは$[1, 5]$そして$[3, 7]$。 

クリッピング後にイベントを処理します。 

| イベントの位置 | タイプ | | 前にアクティブ 間隔を追加 | 寄付バケット |
 | --- | --- | --- | --- | --- |
 | 0 | 開始 | 0 | - | - |
 | 1 | +1 | 0 | [0,1] 長さ 1 | c[0] += 1 |
 | 3 | +1 | 1 | [1,3] 長さ 2 | c[1] += 2 |
 | 5 | -1 | 2 | [3,5] 長さ 2 | c[2] += 2 |
 | 7 | -1 | 1 | [5,7] 長さ 2 | c[1] += 2 |
 | 10 | 終わり | 0 | [7,10] 長さ 3 | c[0] += 3 |

 これは、イベント ポイント間でオーバーラップ数がどのように一定に保たれるか、またラインの各セグメントがどのように正しく属性付けされるかを示しています。 

ここでエッジの位置合わせを考えてみましょう。$[0, 5]$そして$[5, 10]$の上$[0, 10]$。 

| イベントの位置 | タイプ | | 前にアクティブ 間隔を追加 | 寄付バケット |
 | --- | --- | --- | --- | --- |
 | 0 | +1 | 0 | [0,5] | c[1] += 5 |
 | 5 | -1 の後に +1 | 1→0→1 | [5,10] は正しく分割されました | c[1] += 5 |

 オープンする前に処理をクローズすることで、ポイント 5 が二重にカウントされないようにします。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、大きな間隔の完全に外側にあるセグメントです。 例えば、$[1, 5]$と$[S, F] = [10, 20]$。 クリッピング後、間隔は空になり破棄されるため、イベントは作成されず、カバレッジは全体を通してゼロのままになります。 

もう 1 つのケースは、前に始まるセグメントです。$S$そして内部で終わります。$[0, 7]$と$[S, F] = [5, 10]$。 クリッピング後は次のようになります$[5, 7]$、5 ～ 7 の間のみに寄与します。スイープは 0 からではなく、5 から正しくカウントを開始します。 

最後の微妙なケースは、エンドポイントを共有する複数のセグメントです。 仮定する$[0, 5]$、$[5, 10]$、 そして$[5, 8]$。 ソート ルールにより、5 の終了イベントが開始前に処理されることが保証されるため、正確に 5 のオーバーラップ カウントは、境界の両側のアクティブ セグメントの正しいセットを反映し、カバレッジにおける人為的なスパイクを回避します。
