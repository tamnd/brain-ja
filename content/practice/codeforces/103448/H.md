 ## 解決策
 ## 問題の理解

 私たちには戦闘ユニットのコレクションが与えられ、それぞれが攻撃値と体力値によって記述されます。 1 つのユニットが最初の「アクティブ」ユニットとして選択されます。 その後、このユニットは他のユニットと 1 つずつ繰り返し戦闘を行い、各戦闘は決定的です。少なくとも一方の体力がゼロになるまで、両方の側が攻撃値に等しいダメージを同時に繰り返し与えます。 ユニットの体力がプラスでなくなると、ユニットは死亡したとみなされます。 

このプロセスは、アクティブなユニットがまだ生存しており、他のユニットが残っている限り継続されます。 各ステップで、アクティブなユニットは残りの敵と対戦する可能性があり、敵の順序は最も有利な方法で選択されると想定できます。 問題は、開始ユニットを含むすべてのユニットが最終的に死亡するような開始ユニットの少なくとも 1 つの選択肢と、その対戦相手の少なくとも 1 つの順序が存在するかどうかです。 

この制約により、最大 100,000 ユニットが許可され、攻撃値と体力値は最大 1e6 になります。 これにより、ペアごとに戦いをシミュレートしたり、すべての順列を試行したりするソリューションは即座に除外されます。 候補あたり O(n^2) の推論でも時間がかかりすぎるため、実行可能な解決策では問題を軽減してユニットあたりの計算を集約する必要があります。 

貪欲に戦闘をシミュレーションしようとすると、微妙な失敗例が現れます。 たとえば、アクティブなユニットが常に最も弱い敵と最初に戦うべきであると仮定することは誤解を招く可能性があります。なぜなら、高い攻撃力を持つ弱い敵は、低い攻撃力を持つ強い敵よりも危険である可能性があるからです。 もう 1 つの失敗モードは、アクティブなユニットがプロセスの途中で死亡する前に実際にすべてのキルを完了できるかどうかを考慮せず、生存が受けた合計ダメージのみに依存すると仮定することです。 

正しいモデルでは、有用な方法で順序に依存せずに、「各戦闘がどのくらい続くか」と「その間に受けるダメージの量」の両方を捕捉する必要があります。 

## アプローチ

 直接的な総当たりアプローチでは、可能なすべての開始ユニットを試し、それぞれについて、残りの対戦相手のすべての順列をシミュレートします。 各シミュレーションでは、戦闘プロセスを段階的に実行します。 各戦闘には最大 O(1e6 / atk) ラウンドがかかり、最悪の場合、順列ごとに O(n) 回の戦闘が発生します。 順列の数により、これは完全に不可能になります。 

重要な観察は、開始ユニットが固定されると、開始ユニットがその戦いに到達するのに十分長く生き残っている限り、各対戦相手は順序とは関係なく、完全に決定されたコストを開始ユニットに貢献するということです。 各対戦相手 j は、それを倒すのに必要な開始ユニットのヒット数によって決定される固定回数の攻撃ラウンドを必要とします。 これらの各ラウンド中、開始ユニットは相手の攻撃に等しいダメージを受けます。 これは、各対戦相手が開始ユニットに対して決定的な合計ダメージ コストを与えることを意味します。 

順序付けの問題は、見た目よりも簡単になります。 受ける合計ダメージは順序に関係なく固定されており、唯一の本当の制約は、開始ユニットがすべての戦闘を完了するのに十分長く生き残れるかどうかです。 生存は累積ダメージのみに依存するため、どのプレフィックスでも体力を超えない順序は有効であり、そのような順序は、合計ダメージが開始ユニットの体力を超えない場合にのみ存在します。 

これにより、問題は、考えられる開始単位ごとに閉じた形式の式を評価することになります。

 ## アルゴリズムのチュートリアル

 開始候補ユニット i を固定し、それが死ぬ前に他のすべてのユニットを除去できるかどうかを分析します。 

### 1. グローバル集計を事前計算する

すべてのユニットのすべての攻撃値の合計と、攻撃と体力を乗じた合計を計算します。 これらの集計により、すべての対戦相手の貢献をコンパクトに表現できます。 

### 2. ゼロ攻撃ケースを個別に処理する

 開始ユニットの攻撃力がゼロで、合計で複数のユニットがある場合、敵を倒すことはできないため、即座に無効になります。 それが唯一の単位である場合、答えは自明のことです。 

その理由は、攻撃がゼロであるということは、ヘルスがプラスのユニットを倒すために必要なヒットが無限であることを意味するためです。 

### 3. 固定開始ユニットに対する対戦相手の貢献度を計算する

 攻撃 A を持つ固定開始ユニット i の場合、各対戦相手 j は hp_j / A の上限に等しいヒット数を必要とします。各ヒット中に、j は i に atk_j ダメージを与えるため、j からの合計ダメージは次のようになります。 

ceil(hp_j / A) × atk_j。 

上限項を (hp_j + A − 1) // A として書き換えて、整数算術で計算できるようにします。 

### 4. 総ダメージを閉じた形式に変換する

 候補者ごとに O(1) で計算できるように、合計をすべての反対者に拡張し、グローバル集計を使用して表現します。 

### 5. 生存状況を確認する

 開始ユニットは、受けた合計ダメージが自身の体力以下の場合に有効です。 平等が許されるのは、最終決戦が双方同時に死亡して終了することを意味するからである。 

### 6. すべての候補を試してみる

 すべてのユニットに対してこの条件を評価し、少なくとも 1 つが条件を満たす場合は YES を返します。 

### なぜ効果があるのか

 開始ユニットが固定されている場合、すべての対戦相手は順序に依存しない決定的な総ダメージ量を与えます。 有効な順序付けでは、プレフィックスの合計が健全性を超えないことを確認するだけで済みますが、すべての寄与が負ではないため、合計が制限内にある場合は常にプレフィックスの実現可能性が保証されます。 したがって、生存率は、開始ユニットの健康状態に対して受けたダメージの合計を比較する単一の不等式に減ります。 このプロセスは常に、開始ユニットが死亡するか、すべての敵が死亡したときに終了するため、この不等式を満たすことがまさに実現可能性を特徴づけます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    atk = []
    hp = []

    total_atk = 0
    total_ah = 0  # sum atk * hp

    for _ in range(n):
        a, h = map(int, input().split())
        atk.append(a)
        hp.append(h)
        total_atk += a
        total_ah += a * h

    if n == 1:
        print("YES")
        return

    for i in range(n):
        a_i = atk[i]
        h_i = hp[i]

        if a_i == 0:
            continue

        # compute sum_{j != i} ceil(hp_j / a_i) * atk_j
        # = sum atk_j * (hp_j + a_i - 1) // a_i

        num = total_ah - atk[i] * hp[i] + (a_i - 1) * (total_atk - atk[i])
        if num // a_i <= h_i:
            print("YES")
            return

    print("NO")

if __name__ == "__main__":
    solve()
```コードは最初にグローバル合計を構築して、各候補を一定時間で評価できるようにします。 開始ユニットごとに、すべての敵に対して反復処理を行うのではなく、代数分解を使用して合計ダメージ表現を再構築します。 

重要な詳細は、選択されたユニットをグローバル合計から分離することです。これは、選択されたユニットが自身の対戦相手セットに寄与してはいけないためです。 もう 1 つの微妙な点は、分割が無効になるため、攻撃ゼロのユニットをスキップすることで安全に処理することです。 

## 実用的な例

 ### 例 1

 入力:```
2
2 6
3 3
```グローバル値を計算します: total_atk = 5、total_ah = 2×6 + 3×3 = 12 + 9 = 21。 

各ユニットをテストします。 

| 私 | 攻撃 | hp | 計算されたダメージ上限 | 有効 |
 | --- | --- | --- | --- | --- |
 | 0 | 2 | 6 | 不等式を満たす | はい |
 | 1 | 3 | 3 | 不等式は失敗します | - |

 i = 0 の場合、対戦相手 1 は 2 回のヒットで倒すことができ、ダメージは十分に小さいため、両方が死ぬまでユニットは生き残ります。 これにより実現可能性が確認されます。 

### 例 2

 入力:```
3
2 3
3 2
3 3
```グローバル値: total_atk = 8、total_ah = 2×3 + 3×2 + 3×3 = 6 + 6 + 9 = 21。 

各候補者を確認します。 

| 私 | 攻撃 | hp | 結果 |
 | --- | --- | --- | --- |
 | 0 | 2 | 3 | 失敗する |
 | 1 | 3 | 2 | 失敗する |
 | 2 | 3 | 3 | 成功する |

 i = 2 の場合、ユニットは他のユニットを順番に排除しながら総ダメージを維持するのに十分な有効体力を持っているため、これが有効な開始点となります。

 ## 特殊なケース

 重要なエッジケースは、選択したユニットの攻撃力がゼロの場合です。 次のような入力の場合:```
2
0 10
5 5
```最初のユニットは何も殺せないので、すぐに失敗します。 アルゴリズムは、ゼロ攻撃の候補をスキップすることでこれを処理します。 

もう 1 つのケースは、すべての単位が同一である場合です。```
3
2 2
2 2
2 2
```すべての候補は同じ対称的なダメージ構造を生成し、累積的に必要なヒットを維持できるものはないため、出力は NO になります。 この式は均等な寄与を正しく評価し、不等式を満たしません。 

3 番目のケースは、単一の非常に強力なユニットです。```
3
10 1
1 100
1 100
```ここでは、強力なユニットが非常に数ラウンドで両方の敵を倒しますが、それ自体の蓄積ダメージは体力によって制限されたままになります。 この不等式はその候補に対してのみ成立し、アルゴリズムが一意の実行可能な開始点を正しく識別していることを示しています。
