 ## 問題の理解

 参照文字列が与えられます$S$、その後に多くのクエリ文字列$T_i$。 各クエリ文字列について、繰り返して無限の文字列を構築することを想像します。$T_i$永遠に。 この無限の繰り返しから、最初のものだけを取り出します。$|S|$文字、と同じ長さの有限の文字列を形成します。$S$。 各クエリのタスクは、この生成された文字列と$S$。 

したがって、各クエリは効果的に比較されます$S$周期が次のような周期文字列を使用します。$T_i$、長さに合わせて切り詰められます$|S|$。 出力は、これら 2 つの文字列間のハミング距離です。 

制約は、クエリごとではなく合計入力サイズに対して厳しくなっています。 すべての合計$|T_i|$せいぜい$2 \cdot 10^5$、 そして$|S| \le 2 \cdot 10^5$。 これにより、各クエリの各文字を定数時間または償却定数時間以上で処理するソリューションは実行可能であることがすぐにわかりますが、時間を乗算するものはすべて実行可能です。$|S|$による$q$不可能です。 

単純な考えでは、最大長の繰り返し文字列を構築することで、各クエリを個別にシミュレートします。$|S|$、次に文字ごとに比較します。 これはすでに潜在的な問題を示唆しています。$|S|$サイズが大きく、多くのクエリでも完全な走査が強制されるため、繰り返しの作業が多すぎる可能性があります。 

さらに微妙な落とし穴が現れるのは、$|T_i| = 1$。 この場合、繰り返される文字列は定数となり、正しい解決策は文字列のすべての位置を比較する必要があります。$S$その単一のキャラクターに対して。 ここでは、位置合わせや部分的なサンプリングを前提とした最適化が失敗する可能性があります。 

もう 1 つのエッジケースは次のような場合です$|T_i| > |S|$。 次に、プレフィックスのみ$T_i$が使用され、残りは無関係であるため、切り捨てずに循環的な繰り返しとして扱うのは正しくありません。

 ## アルゴリズムのチュートリアル

 各クエリは位置をグループ化することによって評価されるという考えを修正します。$S$インデックスのモジュロに従ってクエリ文字列の長さを決定します。 

1. 入力文字列を超えるグローバル構造を事前計算しません。$S$すべてのグループ化はクエリ固有の MOD クラスに依存するためです。 
2. 特定のクエリ文字列の場合$T$、すべての位置を反復処理します$i$で$S$それらをバケットにグループ化することで暗黙的に$i \bmod |T|$。 すべてのペアを明示的に反復する代わりに、まず各剰余についてカウントする構造を構築します。$r$、各キャラクターがポジションに何回出現するか$i$の$S$どこ$i \equiv r \pmod{|T|}$。 

このステップにより、再度アクセスすることがなくなります。$S$関連するモジュラス パターンごとにその構造を 1 回集約するため、クエリごとに個別に処理されます。 
3. 文字位置ごとに$j$で$T$、残りに対応するバケットを確認します。$j$。 この位置によってもたらされる一致の数は、文字の頻度と正確に一致します。$T[j]$そのバケツの中。 
4. すべてのポジションの合計一致$T$等しい位置の数を与えます。 から引く$|S|$答えが得られます。 

正しさは、すべてのインデックスが$S$正確に 1 つの剰余クラスのモジュロに属します$|T|$、各クラスはちょうど 1 つの位置と一致します。$T$。 マッピングは決定的であり、すべてのインデックスを 1 回だけカバーします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

S = input().strip()
n = len(S)
q = int(input())

# Precompute nothing heavy globally; we will build per query buckets.
# But we can speed up by converting S into integer codes once.
S_int = [ord(c) - 97 for c in S]

for _ in range(q):
    T = input().strip()
    m = len(T)
    
    T_int = [ord(c) - 97 for c in T]
    
    # frequency table: for each remainder, count letters
    # we build only for needed structure: remainder -> 26 counts
    freq = [[0] * 26 for _ in range(m)]
    
    for i, c in enumerate(S_int):
        freq[i % m][c] += 1
    
    match = 0
    for j, c in enumerate(T_int):
        match += freq[j][c]
    
    print(n - match)
```重要な実装上の選択は構築です`freq[r][c]`クエリごとに。 これは、インデックスのモジュロ グループ化を直接エンコードします。 スキャンするのですが、$S$クエリごとに、ネストされた文字ごとのスキャンを回避し、操作をシンプルかつキャッシュに適した状態に保ちます。 

微妙な点は、文字を一度グローバルに整数に変換することです。これにより、繰り返しを避けることができます。`ord`内部ループ内の呼び出し。 もう 1 つは、ゼロベースのインデックスでモジュロを一貫して使用することを保証することです。 1 つずらすと、グループ化が完全にずれてしまいます。

 ### 例 1

 しましょう$S = \text{"abcbac"}$、$T = \text{"ac"}$。 

2 を法とする剰余グループを計算します。 

| 私 | S[i] | 私はモッド2 | バケツ |

 | 0 | | 0 | 0 |

 | 4 | | 0 | 0 |
 | 5 | c | 1 | 1 |

 したがって、バケット 0 には {a, c, a} があり、バケット 1 には {b, b, c} があります。 

のために$T = ac$、一致します:

 位置 0 はバケット 0 で「a」を使用 → 2 が一致

 位置 1 はバケット 1 で「c」を使用 → 1 一致

 合計一致 = 3、つまり不一致 = 6 − 3 = 3。 

これは、周期的なアライメントによって比較が周波数一致にどのように軽減されるかを示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    return solve()

def solve():
    import sys
    input = sys.stdin.readline

    S = input().strip()
    n = len(S)
    q = int(input())
    S_int = [ord(c) - 97 for c in S]

    out = []
    for _ in range(q):
        T = input().strip()
        m = len(T)
        T_int = [ord(c) - 97 for c in T]

        freq = [[0] * 26 for _ in range(m)]
        for i, c in enumerate(S_int):
            freq[i % m][c] += 1

        match = 0
        for j, c in enumerate(T_int):
            match += freq[j][c]

        out.append(str(n - match))
    return "\n".join(out)

 ## 特殊なケース

 いつ$|T| = 1$、アルゴリズムは単一のバケットを構築し、バケットのすべての位置を割り当てます。$S$それに。 すべての位置が同じ文字に対して比較され、頻度テーブルは 1 回のパスで一致を正確にカウントします。 例えば、$S = \text{"abc"}$、$T = \text{"a"}$。 バケットには a、b、c のカウントが含まれており、「a」のみが一致に寄与します。 

いつ$|T| > |S|$、多くの残りのバケットには最大でも 1 つの要素が含まれます。 モジュロ グループ化では引き続き各インデックスが正しく割り当てられ、プレフィックスのみが割り当てられます。$T$有効に活用されています。 例えば、$S = \text{"abc"}$、$T = \text{"xyz..."}$。 実際には最初の 3 文字のみが重要であり、各バケットには最大でも 1 つのインデックスがあります。 

文字が入っているとき$T$には現れない$S$、対応するバケットへの寄与はゼロです。 周波数ルックアップでは特別な処理を行わずにゼロが返されるため、アルゴリズムはこれを自然に処理します。
