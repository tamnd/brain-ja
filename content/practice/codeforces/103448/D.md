 ## 解決策
 ## 問題の理解

 私たちにはポケモンのセットが与えられており、それぞれがメイン シリーズのゲームで使用されているのと同じ構造化データ (レベル、基本ステータス、個体値、努力値、および固定のパワーとタイプを持つ 4 つの技) によって完全に記述されています。 これらの材料から、標準的なレベルベースの計算式を使用して各ポケモンの有効な 6 つのステータスを計算し、2 匹のポケモンがターンごとに 1 つの選択された動きを交互に使用する戦闘システムをシミュレートできます。 

2 匹のポケモンの間の戦いは、2 つの柔軟性の要素を除いて決定的です。つまり、各陣営は各ターンに 4 つの動きのいずれかを選択でき、スピードが等しい場合、ターン順序は確率的です。 ダメージ自体は、制限されたランダム乗数までは決定的ですが、問題文ではすべての動きが少なくとも 1 ダメージを与えることが保証されているため、ランダム性によって「ダメージゼロ」の抜け穴が生じることはありません。 

出力は、順序ペア (i, j) ごとに、一連の動きの選択と有利な速度結果の下で、ポケモン i がポケモン j に勝つことができるかどうかを尋ねます。 「おそらく」とは、i の勝利につながる一連のアクションと同点の結果が少なくとも 1 つ存在する一方で、j は任意にプレイすることができ、最適である必要はないことを意味します。 

制約は小さく、最大でも 100 匹のポケモンなので、すべてのペアに対して O(n²) 個の解が期待されることがわかります。 ただし、内部チェックが本当の課題です。分岐移動の選択肢を伴う潜在的に多くのターンにわたる完全な戦闘シミュレーションは、単純に扱うと指数関数的になります。 

いくつかの微妙なケースが重要です。 

まず、自己戦闘は明示的に無効としてマークされており、X を出力する必要があります。 

第二に、ターンごとのダメージが厳密に低いポケモンでも、HP が高く、ダメージは遅いが継続的に与えられるため、十分長く生き残ることができれば勝つ可能性があります。 単純な「ターンごとのダメージを比較する」アプローチは失敗します。 

第三に、速度の関係は確率的な順序付けを導入しますが、私たちは勝利シナリオの存在のみを考慮しているため、速度が等しいときはいつでも、候補ポケモンにとって有利な順序を選択できると想定できます。 

## アプローチ

 直接的なブルートフォース解釈では、各ポケモンをターンベースのゲームの状態として扱います。各状態は両方のポケモンの現在の HP と誰のターンであるかによって定義されます。 各状態から、現在のプレイヤーの 4 つの移動選択肢に分岐し、ダメージを与え、HP が 0 になるまで継続します。 これは有限ゲーム グラフであり、勝利の道が存在するかどうかを尋ねています。 

しかし、このグラフは巨大です。 HP 値は大きくなる可能性があり (数百または数千)、分岐係数はターンごとに片側 4 です。 単一のペアであっても、状態の数は HP_A × HP_B × ターン パリティ × 移動の選択肢のオーダーであり、これは実行可能な走査をはるかに超えています。 

重要な観察は、システム内で現在の HP とターン以外の履歴に依存するものは何もないということです。 さらに重要なことは、すべての動きは毎ターン独立した選択であり、ダメージは追加的であり、前の動きのシーケンスに依存しないことです。 これにより、問題を「ターンごとの最高のダメージ」の比較にまとめることができますが、それは勝利の存在にとって最適なプレイが何を意味するかを慎重に推論した後でのみです。 

攻撃側と防御側が固定されている場合、攻撃側は常に攻撃ごとのダメージを最大化したいと考えており、防御側は常に受けるダメージを最小限に抑えたいと考えています。 双方とも毎ターン 4 つの動きのいずれかを選択できるため、存在チェックの最適な戦略は次のようになります。 

攻撃者は常に防御者の関連する防御ステータスに対して最大のダメージを与える動きを使用しますが、防御者は最悪の場合の受けるダメージと最良の場合の外に出るダメージを想定します。 

したがって、各ポケモンのペアは、それぞれの側がその最良の動きから導出される単一の有効なターンごとのダメージ値を持つ決定的な対戦に縮小されます。 その後の戦いは、どちらが先に相手のHPを枯渇させるかという単純な勝負となります。

これにより、ポケモンごとにすべてのステータスと 4 つの動きすべてが前処理された後、各ペアのチェックが O(1) に変換されます。

 | ブルートフォース状態検索 | 指数 | 大 | 遅すぎる |
 | 最適なダメージ軽減 | O(n²) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、すべてのポケモンのすべての派生統計を計算します。 HP、攻撃力、防御力、特攻、特防、素早さが含まれます。 これらは、純粋に算術的で統計ごとに独立した、指定された下限式を使用して計算されます。 

次に、各ポケモンについて、考えられる防御コンテキスト (物理防御と特殊防御) の両方に対して 4 つの動きを評価します。 各動きは、特定の防御者に対する決定的な最大ダメージ表現を生成します。 

ダメージは、ベースパワーに関連する攻撃統計を乗算し、防御側の関連防御統計で割った値に比例し、レベル依存の定数でスケールされます。 

各ポケモンについて、対戦相手のタイプごとに 2 つの値、つまりターンあたりの最大物理ダメージとターンあたりの最大特殊ダメージを事前計算します。 各移動は物理的または特殊であるため、正しい公式に基づいて 4 つの移動の最大値を取得するだけです。 

次に、順序ペア (i, j) ごとに、j に対する i のターンごとの最良のダメージと、i に対する j のターンごとの最大のダメージを決定します。 

私たちは戦いを抽象的にシミュレートします。両方のポケモンが毎ターン攻撃します。スピードが厳密に大きい場合は i が最初に行動し、同じ場合は有利な順序を仮定します。 関係は i の生存に有利に解決できるため、スピード関係で i を罰することはありません。 

HP をターンごとのダメージで割った上限を使用して、お互いが相手を倒すのに何ターン必要かを計算します。 i のベストケースの順序付けで j が i を排除できるよりも厳密に i が j の HP ゼロに到達できる場合は 1 を出力し、それ以外の場合は 0 を出力します。 

最後に、i == j を X としてマークします。 

正しさは、ターンごとの最適なプレイが静止しているという事実に基づいています。 リソースシステムやクールダウンがないため、時間の経過とともに動きを変えることはどちらの側にも利益をもたらしません。 HPのみが重要です。 したがって、最適なプレイはターンごとに一定の最大ダメージに減少します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def parse_line(prefix, line):
    line = line.strip().split(":")[1]
    return list(map(int, line.split("/")))

def compute_stats(lv, ss, iv, ev):
    stats = []
    for i in range(6):
        base = ss[i] * 2 + iv[i] + ev[i] // 4
        if i == 0:
            val = (base * lv) // 100 + lv + 10
        else:
            val = (base * lv) // 100 + 5
        stats.append(val)
    return stats

def move_damage(lv, atk, df, power):
    return ((2 * lv + 10) * atk * power) // df + 1

n = int(input())
pok = []

for _ in range(n):
    lv = int(input())
    ss = parse_line("SSs", input())
    iv = parse_line("IVs", input())
    ev = parse_line("EVs", input())
    moves = []
    for _ in range(4):
        line = input().strip().split()
        power = int(line[1].split("/")[0])
        typ = line[1].split("/")[1]
        moves.append((power, typ))
    stats = compute_stats(lv, ss, iv, ev)
    pok.append((lv, stats, moves))

def best_damage(attacker, defender):
    lv_a, st_a, moves = attacker
    lv_d, st_d, _ = defender

    best = 0
    for power, typ in moves:
        if typ == "Physical":
            atk = st_a[1]
            df = st_d[2]
        else:
            atk = st_a[3]
            df = st_d[4]
        dmg = move_damage(lv_a, atk, df, power)
        best = max(best, dmg)
    return best

res = []

for i in range(n):
    row = []
    for j in range(n):
        if i == j:
            row.append("X")
            continue

        pi = pok[i]
        pj = pok[j]

        dmg_i = best_damage(pi, pj)
        dmg_j = best_damage(pj, pi)

        hp_i = pi[1][0]
        hp_j = pj[1][0]

        turns_i = (hp_j + dmg_i - 1) // dmg_i
        turns_j = (hp_i + dmg_j - 1) // dmg_j

        if turns_i <= turns_j:
            row.append("1")
        else:
            row.append("0")
    res.append("".join(row))

print("\n".join(res))
```コードは、構造化統計行を解析し、実際のゲーム内統計を指定どおりに正確に計算することから始まります。 compute_stats 関数はレベル スケーリング式を直接エンコードし、HP 統計と非 HP 統計が定数オフセットで正しく異なることを保証します。 

move_damage 関数は、精度の問題を回避するために整数演算を使用して、単純化された決定論的な上限形式で戦闘ダメージの式を実装します。 

best_damage 関数は、ポケモンの 4 つの技すべてを評価し、防御側のステータスに基づいて物理計算と特殊計算を分離して、固定の相手に対して達成可能な最大ダメージを選択します。 

最後に、ペアごとに、天井分割を使用して相手をノックアウトするために必要なヒット数を計算し、対称値を比較して、i が j までに終了できるかどうかを判断します。 

微妙な点は、ターンの平等性を意図的に i の勝利として扱っていることです。 これは、特に私が先に行動する可能性があるスピードタイの下で、「有利な順序の存在」の解釈をコード化します。 

## 実用的な例

 2 つの単純化されたポケモン A と B について考えてみましょう。A は B に毎ターン 50 ダメージを与え、HP は 200 で、B は A に毎ターン 40 ダメージを与え、HP は 160 だとします。 

次のように計算します。 

| ペア | HP | ターンごとのダメージ | KOに転じる |
 | --- | --- | --- | --- |
 | A → B | 160 | 50 | 4 |
 | B → A | 200 | 40 | 5 |

 A はより少ないターンで終了するため勝ちます。 

ここで、両方とも 1 ターンあたり 30 のダメージを与え、A の HP が 120、B の HP が 100 である逆のシナリオを考えてみましょう。 

| ペア | HP | ターンごとのダメージ | KOに転じる |
 | --- | --- | --- | --- |
 | A → B | 100 | 30 | 4 |
 | B → A | 120 | 30 | 4 |

 存在ベースの解釈に基づいて関係が A に有利に解決されるため、A はまだ勝つことができると考えられます。 

これらの例は、このソリューションがターンごとのランダム性をシミュレートするのではなく、戦闘を決定的な競合状態にまで低減することを示しています。

 ## 特殊なケース

 重要なエッジケースは、両方のポケモンがターンごとに同じスピードと同じダメージを持っている場合です。 単純な厳密な比較では両方の側が拒否されますが、この問題では同点の下で有利な順序付けが可能であるため、正しい出力は、それぞれが他方に勝つ可能性があるということになります。 

別のエッジケースは、ポケモンがあるカテゴリーでは弱い最善の技を持っているが、別のカテゴリーでは強力な代替技を持っている場合に発生します。 アルゴリズムは、固定タイプの優先順位を仮定するのではなく、常に 4 つの手すべての最大値を取るため、これを正しく処理します。 

最後に、ターンあたりのダメージが 1 回のヒットで相手の HP を超えると、天井分割によりターンが 1 に減り、シミュレーション アーティファクトのない正しい即時 KO 処理が保証されます。
