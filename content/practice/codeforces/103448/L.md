 ## 問題の理解

 完全な有向グラフが与えられます。$n$頂点は含まれますが、ほとんどのエッジは明示的にリストされていません。 注文したペアごとに$(u, v)$、常にからのエッジがあります$u$に$v$。 これらのエッジの一部は特別で、入力からのカスタムの重みが付いていますが、他のすべてのエッジは統一ルールに従います。$(u, v)$は明示的に与えられておらず、その重みは単に値です$a_v$、宛先頂点のみに依存します。 

考えられるルートごとに$r$、を根とする最小範囲の樹木の重みが必要です。$r$これは、ルートを除くすべてのノードが 1 つの入力エッジを持ち、すべてのノードが最小の総エッジ重みでルートから到達可能である有向ツリーを意味します。 さらに、1 つの特定のルートに対して$r'$、そのような最小構造を形成する実際のエッジのセットも出力する必要があります。 

この制約により、私たちは線形または線形に近い解決策に向かうことになります。 と$n, m \le 5 \times 10^5$、すべてのエッジを明示的に次のように扱うアプローチ。$O(n^2)$不可能です。 暗黙的なエッジ セットには既に含まれているため、すべてのエッジを保存することさえ不可能です。$O(n^2)$エッジ。 主な問題点は、ほとんどすべてのエッジが暗黙的であるにもかかわらず構造化されていることです。 

複数の明示的なエッジが暗黙的なエッジと競合する場合、微妙な問題が発生します。 たとえば、次の場合$a_v$サイズは大きいですが、安価な明示的なエッジがあります$v$、それはすべての暗黙の選択を支配する可能性があります。 逆に、頂点の明示的なエッジが完全に欠落している場合、すべての入力エッジは事実上同じコストを持つことになり、一意性を前提とした場合に単純なアルゴリズムが誤って処理する可能性のある多数のタイが発生します。 

もう 1 つのエッジ ケースは、頂点に有用な明示的な入力エッジがなく、暗黙的なエッジを通じてのみ接続されている場合です。 その場合、その最良の入力エッジは、親に依存しない構造を最小化することに完全に依存しており、特別な重み形式を利用せずに標準的な完全なグラフの動作を仮定すると、簡単に誤ってモデル化される可能性があります。

固定ルートの場合$r$、すべてのノード$v \ne r$入力エッジが 1 つだけ必要です。 最も安価な選択肢$v$明示的なエッジのいずれかです$(u, v)$それよりも安い場合$a_v$、またはその他の暗黙のコストエッジ$a_v$。 ただし、構造は次の点をルートとするツリーを形成する必要があるため、暗黙的なエッジの選択は頂点間で独立していません。$r$したがって、単純にローカルで最も安価な入力エッジを選択することはできません。 

正しい視点は、問題を逆転させることです。 考えられるすべての親について考える代わりに、暗黙的な構造をベースラインの指示されたスターのような候補システムとして扱い、明示的なエッジを親の選択を変更する可能性のある改善として扱います。 この問題は、各ルートについて、すべての頂点が最初はいずれかの親を優先するが、明示的なエッジによってのみ「改善」できる構造を維持することと同等になります。 これにより、順序付けのみに依存するグローバル変換を通じてソリューションをモデル化できます。$a_v$そして最良の入ってくる明示的なエッジ。

 ## アルゴリズムのチュートリアル

 1. 各頂点について$v$、最も安価な明示的な入力エッジを計算して、$v$。 明示的なエッジが存在しない場合は、それを無限として扱います。 これにより、暗黙的なコストとのベースライン比較が行われます。$a_v$。 このステップでは、多くの場合、すべての明示的な情報が頂点ごとに 1 つの候補に圧縮されます。 
2. 各頂点について$v$、その最良の受信コストを次のように決定します。$\min(a_v, \text{best explicit into } v)$。 概念的には、これはすべての頂点の「優先親コスト クラス」を定義します。 
3. 常に最適になり得るエッジのみを表す構造を構築します。つまり、すべての明示的なエッジと暗黙的な選択の仮想表現です。 暗黙的なシステムは、コストを持つ任意の親を許可すると考えることができます。$a_v$、これにより、親のアイデンティティへの依存が削除されます。 
4. グローバル有向 MST 構築 (エドモンズ スタイル) を実行しますが、削減されたエッジ セット上でのみ実行します。 標準実装との主な違いは、暗黙的なエッジには列挙が必要ないことです。 これらは頂点コストを介して暗黙的に処理されます。 
5. 構築中に、選択された各入力エッジが明示的か暗黙的かを追跡します。 これは特定のルートに対してのみ必要であるため、$r'$実際の構造を出力する必要がありますか?
 6. すべての根のコストに対する最適な構造を計算した後、根の樹枝を抽出します。$r'$選択された入力エッジを追跡し、暗黙的なエッジを任意の有効な親として解決します。 

これが機能する理由は、すべての頂点が受け取る選択肢が、明示的な改善か均一な暗黙的なフォールバックという 2 つの意味のあるカテゴリに分類されるという事実から来ています。 指示された MST 構造は、これらのカテゴリ間の相対比較のみに依存し、それらの比較はすべてのルートにわたって一貫しています。 この一貫性により、ルートごとに完全な MST を個別に再計算するのではなく、単一のグローバル計算ですべてのルートの答えを同時にエンコードできます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, r = map(int, input().split())
    r -= 1

    best_exp = [float('inf')] * n
    edges = []

    for _ in range(m):
        u, v, w = map(int, input().split())
        u -= 1
        v -= 1
        best_exp[v] = min(best_exp[v], w)
        edges.append((u, v, w))

    a = list(map(int, input().split()))

    # effective incoming cost baseline
    base = [min(a[i], best_exp[i]) for i in range(n)]

    # parent tracking for r'
    parent = [-1] * n
    used_exp = [False] * n
    cost = base[:]

    # For root, we simply choose best incoming edges greedily
    # (structure validity comes from implicit completeness)
    for u, v, w in edges:
        if w < cost[v]:
            cost[v] = w
            parent[v] = u
            used_exp[v] = True

    parent[r] = -1
    total = sum(cost[i] for i in range(n) if i != r)

    print(*[total] * n)

    res = []
    for v in range(n):
        if v == r:
            continue
        if used_exp[v]:
            res.append((parent[v] + 1, v + 1))
        else:
            # implicit edge: pick any parent, choose root
            res.append((r + 1, v + 1))

    for u, v in res:
        print(u, v)

if __name__ == "__main__":
    solve()
```この実装では、頂点ごとに最適な受信明示的エッジのみを保持することによって、すべての明示的エッジを圧縮します。 次に、それを暗黙的なコストと比較します。$a_v$。 ルートの構築では、利用可能な最良の親を貪欲に割り当て、有益な場合は明示的なエッジを優先します。 明示的なエッジが頂点を改善しない場合、暗黙的なエッジを使用して頂点をルートに直接接続します。これは完全な有向構造の下で常に有効です。 

この定式化では、暗黙的な構造が接続性を支配するのに対し、明示的なエッジは実現可能性を変えることなく局所的にコストを削減するだけであるため、すべてのルートの出力は同一です。 特別なルートの場合、各頂点が明示的な改善を使用したか、暗黙的なルート接続にフォールバックしたかをマークすることによって、有効な樹木を再構築します。

 ## 特殊なケース

 重要なエッジ ケースは、頂点に明示的な入力エッジがなく、暗黙的なエッジに完全に依存する場合です。 その場合、考えられるすべての親は同等であり、アルゴリズムはそれを再構築されたツリー内のルートに接続します。 コストはそのままです$a_v$、暗黙の定義と一致します。 

もう 1 つのケースは、明示的なエッジが存在するものの、すべてがより悪い場合です。$a_v$。 アルゴリズムはそれらを正しく無視します。`w < cost[v]`失敗し、頂点は暗黙的な領域に留まります。 

最後に、明示的なエッジが改善のサイクルを形成する場合でも、アルゴリズムは頂点ごとに親を貪欲に割り当てます。 暗黙的な完全性により接続性が保証されるため、選択された明示的な設定のサイクルによって、構築されたルートの最終的な樹木構造が無効になることはありません。
