 ## 解決策
 ## 問題の理解

 長さのシーケンスが与えられます$n$, しかし、それは任意の順序ではありません。 の順列です$1$を通して$n$したがって、すべての値は個別であり、各値は 1 回だけ表示されます。 インデックスを考えることができます$i$配列内の位置として、そして$a_i$その位置に格納される「ランクのような」値として。 

あらゆる固定位置に対応$i$、すべての部分配列を調べます$[l, r]$含まれている$i$。 このような各サブ配列内で値をソートし、どこにあるかを決定します。$a_i$ソートされた順序で表示されます。 その位置はそのランクであり、1 に厳密に小さいサブ配列内の要素の数を加えたものに等しくなります。$a_i$。 機能$f(i)$を含むすべてのサブ配列にわたるこのランクの合計として定義されます。$i$。 

出力には計算が必要です$f(i)$あらゆるポジションに。 

制約により許可されるのは、$n$まで$5 \times 10^5$これにより、すべての部分配列を列挙するソリューションは即座に除外されます。 固定インデックスを含むサブ配列の数$i$は$O(n^2)$最悪の場合、直接シミュレーションを行うには次のオーダーが必要になります。$O(n^3)$すべてのポジションにわたる合計オペレーション。 たとえ$O(n^2)$ポジションごとのアプローチは実現不可能です。 したがって、間隔を明示的に列挙するのではなく、集計されたカウントを通じて各位置が寄与するという解決策を余儀なくされます。 

小さい要素と大きい要素からの寄与を分離せずに間隔カウントのみについて推論しようとすると、微妙なエッジ ケースが発生します。 単純な試みでは、範囲内の要素の数だけを維持しようとする可能性がありますが、ランクは、要素の数が範囲内にどれだけ小さいかによって決まります。$a_i$存在する数だけではありません。 たとえば、配列が次の場合、$[3,1,2]$、次に、$i=3$価値のあるもの$2$、間隔が異なると、以下に応じて異なるランクが生成されます。$1$が含まれています。 すべての要素を対称的に扱うと、個別のケースが誤って折りたたまれます。 

## アプローチ

 強引な解釈は簡単です。 それぞれについて$i$、すべてのペアを列挙します$(l, r)$そのような$l \le i \le r$、部分配列を抽出し、並べ替えて、次の順位を計算します。$a_i$。 これは正しいですが、非常に高価です。 がある$O(n^2)$位置ごとのこのような間隔とランクの計算には少なくともコストがかかります$O(n)$、につながる$O(n^3)$時間。 

重要な観察は、ランクがペア形式で書き換えられるということです。 任意の間隔内でのランクは、$a_i$1 に、その間隔内の値が小さい要素の数を加えたものに等しい$a_i$。 これにより、問題は、位置の各ペアが間隔にどのくらいの頻度で寄与するかを数えるという問題に変換されます。 

2 つのインデックスを修正する$i$そして$j$。 両方を含む間隔が何回あるかを知りたい$i$そして$j$存在する。 このような間隔はいずれも満たさなければなりません$l \le \min(i,j)$そして$r \ge \max(i,j)$したがって、有効な間隔の数は次のようになります。$\min(i,j) \cdot (n - \max(i,j) + 1)$。 これにより、すべてのペアにわたるペアの寄与を合計するという問題が軽減されます。$a_j < a_i$。 

次に、貢献度をそれぞれの基本期間に分割します。$i$に加えて、すでに処理されたすべてのより小さい値からの集計された寄与分を加えます。 インデックスを昇順に処理することで、$a_i$、ポジションを処理するときに次のことを保証します。$i$、すべて関連する$j$と$a_j < a_i$はすでに知られています。

 ## アルゴリズムのチュートリアル

 ポジションはその値の昇順に処理されるため、ポジションを処理する際には、より小さい値はすべてデータ構造内ですでにアクティブ化されています。 

1. インデックスを値で並べ替えます$a_i$昇順で。 この順序でインデックスを 1 つずつアクティブ化します。 これにより、ポジションを処理するときに、$i$、すべてのアクティブなポジション$j$満足する$a_j < a_i$。 
2. インデックスに対して 2 つのフェンウィック ツリーを維持します。 1 つ目はインデックスの合計を格納し、プレフィックス上の位置の合計をクエリできるようにします。 2 番目はフォームの値を格納します$n - j + 1$これにより、サフィックス関連の貢献を効率的にクエリできるようになります。 
3. 新しいポジションを処理する場合$i$, first activate it in both Fenwick trees. これは、挿入することを意味します$i$最初の構造に入り、$n - i + 1$2番目に。 
4. ポジションごとに$i$、3 つの成分を計算します。 1 つ目は基本寄与であり、以下を含む間隔の数に等しくなります。$i$、つまり$i \cdot (n - i + 1)$。 これは、ランク定義の「+1」の用語に対応します。 
5. 次にアクティブなポジションからの貢献を計算します$j < i$。 これらは貢献します$j \cdot (n - i + 1)$それぞれ。 要因$n - i + 1$固定の場合は定数です$i$なので、インデックスの合計を掛けます。$j$アクティブな位置よりも厳密に左側にある$i$、フェンウィックの接頭辞の合計から取得されます。 
6. 最後にアクティブなポジションからの貢献を計算します$j > i$。 これらは貢献します$i \cdot (n - j + 1)$それぞれ。 要因$i$は定数なので、次の合計を掛けます。$n - j + 1$アクティブなポジションの上でちょうど右$i$、合計からプレフィックス クエリを差し引いたものとして取得できます。 
7. これら 3 つの部分を組み合わせて、$f(i)$。 

### なぜ効果があるのか

 変換は、ランクを定数項として書き換えることと、ペアごとの比較に依存します。 を含むすべての間隔$i$「自己ランク ベースライン」から正確に 1 単位に寄与し、間隔内の小さい要素はそれぞれ、正確に 1 単位の追加単位に寄与します。 合計の順序を交換することで、間隔のカウントからインデックスのペアのカウント、そして各ペアが含まれる間隔の数に移行します。 フェンウィック構造は、有効な小さい値のペアのみが含まれるようにしながら、位置の順序によって寄与を分離するためにのみ機能します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

    def range_sum(self, l, r):
        if l > r:
            return 0
        return self.sum(r) - self.sum(l - 1)

n = int(input())
a = list(map(int, input().split()))

pos = list(range(n))
pos.sort(key=lambda i: a[i])

bit_idx = Fenwick(n)
bit_rev = Fenwick(n)

ans = [0] * n

total_idx = 0
total_rev = 0

for i in pos:
    i1 = i + 1
    left_cnt = bit_idx.sum(i1 - 1)
    sum_left = left_cnt

    sum_right_rev = total_rev - bit_rev.sum(i1)

    base = i1 * (n - i1 + 1)
    ans[i] = base + (n - i1 + 1) * sum_left + i1 * sum_right_rev

    bit_idx.add(i1, i1)
    bit_rev.add(i1, n - i1 + 1)

    total_rev += (n - i1 + 1)

print(*ans, sep="\n")
```実装は分解を直接反映します。 フェンウィックの木`bit_idx`アクティブな小さい値のインデックスの合計を維持し、左側の寄与をサポートします。 フェンウィックツリー2号店$n - i + 1$、プレフィックス減算による右側寄与の効率的な計算が可能になります。 

処理順序は重要です。 各位置はデータ構造に挿入される前に評価され、それ自体の計算に誤って寄与しないことが保証されます。 

## 実用的な例

 順列を考慮してください$[3, 1, 2]$。 

値は昇順に処理されます (1 の位置、次に 2、次に 3)。 

| 値 | ポジション | ベース$i(n-i+1)$| 左の投稿 | 正しい貢献 | 結果 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 2 | 2・2 = 4 | 0 | 0 | 4 |
 | 2 | 3 | 3・1 = 3 | 位置 2 から: 2・1 = 2 | 0 | 5 |
 | 3 | 1 | 1・3 = 3 | 0 | 2,3 件の投稿から | 7 |

 このトレースは、以前に処理されたより小さい値のみから寄与がどのように蓄積されるかを示しており、間隔にわたるランク蓄積の定義と一致しています。 

2 番目の例$[1, 2, 3]$間隔構造からの寄与が厳密に増加し、各要素がより小さい要素とのみ相互作用することが確認され、アルゴリズムは位置の影響を値の順序から明確に分離します。

## テストケース```python
import sys, io

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    a = list(map(int, input().split()))

    class Fenwick:
        def __init__(self, n):
            self.n = n
            self.bit = [0] * (n + 1)
        def add(self, i, v):
            while i <= self.n:
                self.bit[i] += v
                i += i & -i
        def sum(self, i):
            s = 0
            while i > 0:
                s += self.bit[i]
                i -= i & -i
            return s

    pos = list(range(n))
    pos.sort(key=lambda i: a[i])

    bitL = Fenwick(n)
    bitR = Fenwick(n)

    totalR = 0
    ans = [0] * n

    for i in pos:
        idx = i + 1
        left_sum = bitL.sum(idx - 1)
        right_sum = totalR - bitR.sum(idx)

        ans[i] = idx * (n - idx + 1) + (n - idx + 1) * left_sum + idx * right_sum

        bitL.add(idx, idx)
        bitR.add(idx, n - idx + 1)
        totalR += (n - idx + 1)

    return "\n".join(map(str, ans))

 ## 特殊なケース

 単一要素配列の場合、区間は 1 つだけであるため、ランクは常に 1 になります。アルゴリズムは基数を計算します。$1 \cdot 1$他の要素からの影響はなく、正しい結果と一致します。 

厳密に増加する配列の場合、すべての要素は右側のより大きな要素にのみ寄与します。 Fenwick 構造では、各要素の右側ですでに処理されているより小さな値がないため、誤った左側の寄与が表示されないことが保証されます。 

厳密に減少する配列の場合、すべてのインタラクションは左側で以前に処理された要素から取得され、プレフィックス クエリとサフィックス クエリの間の分割により、二重にカウントされることなくすべての寄与が正しく累積されます。
