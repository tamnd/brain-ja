 ## 解決策
 ## 問題の理解

 正の整数の配列が与えられます`a`長さの`n`。 要素ごとに`a_i`、それを増やすことができます`1`費用をかけて何度でも`1`増分ごとに。 私たちの目標は、少なくとも 1 つの異なるインデックスのペアを作成することです`(i, j)`の最大公約数が`a_i`そして`a_j`より大きい`1`。 課題は、これを達成するための最小総コストを見つけることです。 

だって全部`b_i = 1`、すべての増分のコストは同じです。 これにより問題が単純化されます。どの要素を増やすのが安価であるかを考慮する必要はなく、1 より大きい GCD を達成するために必要な増分数だけを考慮する必要があります。 

制約により、次のことがわかります。`n`すべてのテストケースで次を超えない`2 * 10^5`つまり、テスト ケースごとに O(n log n) 個の解は許容されますが、O(n^2) では遅すぎます。 小さな配列ではブルートフォース攻撃が可能ですが、大きな配列ではよりインテリジェントなアプローチが必要です。 

重要なエッジケースは、すべての数字が次のような場合です。`1`。 次に、共通因数を作成するには、すべての数値を少なくとも 1 回増分する必要があります。 もう 1 つは、配列にすでに重複または割り切れる数値が含まれている場合です。この場合、増分は必要ありません。 実装を不注意にすると、他のすべての数値と素数または共素である数値を見落とす可能性があり、最も近い非共素値までの増分を慎重にカウントする必要があります。 

## アプローチ

 ブルートフォースアプローチでは、すべてのペアが考慮されます。`(i, j)`必要な最小増分数を計算します。`gcd(a_i + x, a_j + y) > 1`。 それぞれの数値について、次のように追加してみることができます。`0, 1, 2, ...`共通因数に達するまで。 これは原理的には機能しますが、n が 2 * 10^5 までの場合、操作の数がおよそ n^2 * log(a_max) に達する可能性があり、法外なため、すべてのペアと複数の増分をチェックすると遅すぎます。 

重要な観察は、1 より大きい GCD を生成するには最小の素数で十分であるということです。すべての整数には素因数があり、2 つの数値が素因数を共有する場合、それらの GCD は少なくともその素数になります。 数値をインクリメントできるため、小さな素因数をチェックし、その素数の倍数に達するまでにどれだけの増分が必要かを確認するだけで済みます。 以来`a_i <= 2 * 10^5`、エラトステネスの篩を使用して、およそ 450 (2 * 10^5 の平方根) までの素数を事前計算することが可能です。 

最適な戦略は、すべての素数を反復し、その素数の少なくとも 2 つの数値の倍数を作成するために必要な最小増分を計算します。 答えは、すべての素数にわたる最小のコストです。 これにより、問題がすべてのペアのチェックから少数の素数セットに対するすべての数値のチェックに減り、複雑さがおよそ O(n * π(sqrt(a_max))) にまで下がり、許容範囲内になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2 * log a_max) | O(n) | 遅すぎる |
 | 最適 | O(n * sqrt(a_max)) | O(n + sqrt(a_max)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. エラトステネスのふるいを使用して、450 までのすべての素数を事前計算します。 これらの素数を使用して、1 より大きい GCD を生成する可能性のある約数をテストします。 
2. 各テスト ケースについて、次の内容を読んでください。`n`そして配列`a`。 答えを初期化する`ans`無限を表す大きな数に。 
3. 各素数を反復処理します。`p`。 それぞれについて`a_i`、行うために必要な最小増分を計算します。`a_i`で割り切れる`p`。 これは`(p - a_i % p) % p`。 
4. 現在の素数に対するこれらの増分コストをすべて収集し、並べ替えて、最小の 2 つを合計します。 これにより、少なくとも 2 つの数値を次の数で割り切れる最小コストが得られます。`p`。 
5.アップデート`ans`電流の小さい方`ans`とステップ 4 で得られた合計。 
6. すべての素数をテストした後、出力します。`ans`テストケース用。 
7. すべてのテスト ケースに対して繰り返します。 

機能する理由: 1 より大きい数値には素因数があり、少なくとも 2 つの数値の間で共通の素因数が得られると、GCD が 1 より大きくなることから、このアルゴリズムは正確さを保証します。sqrt(a_max) までのすべての素数をチェックすることで、考えられるすべての最小 GCD をカバーし、2 つの最小の調整を合計することで、各候補素数の最小コストが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def sieve(n):
    is_prime = [True] * (n+1)
    is_prime[0] = is_prime[1] = False
    for i in range(2, int(n**0.5)+1):
        if is_prime[i]:
            for j in range(i*i, n+1, i):
                is_prime[j] = False
    primes = [i for i, val in enumerate(is_prime) if val]
    return primes

primes = sieve(450)

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))  # b_i = 1 for all i, not used

    ans = float('inf')

    for p in primes:
        costs = [(p - x % p) % p for x in a]
        costs.sort()
        ans = min(ans, costs[0] + costs[1])
    
    print(ans)
```sieve 関数は最大 450 の素数を生成します。各テスト ケースでは、各素数の増分コストを計算し、最小の 2 つを取得して、少なくとも 2 つの数値がその素因数を共有することを確認します。 並べ替えると、最小限の調整が確実に選択されます。 モジュロ演算の使用`(p - x % p) % p`すでに割り切れる数値を正しく処理します`p`不必要な増分を追加せずに。
