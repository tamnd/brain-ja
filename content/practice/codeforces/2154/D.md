 ## 解決策
 ## 問題の理解

 このツリーは、猫がノード 1 から開始してノード n に到達しようとする世界を表しています。 猫が移動するとき、猫の進路を直接制御することはできません。 代わりに、2 種類のコマンドで構成されるスクリプトを指定します。1 つのコマンドは、猫に任意の隣接ノードへの任意の 1 歩を強制的に実行させ、もう 1 つのコマンドは、選択したノードとそのすべてのインシデント エッジを削除します。 ノードを削除すると、現在そこに猫がいる場合は猫も殺されるため、これは避けなければなりません。 重要な制限は、2 つの削除コマンドを連続して使用できないことです。 

目標は、猫が非決定的な動きをどのように解決するかに関係なく、最終的にノード n に到達することが保証されるように、最大​​ 3n の長さのコマンド シーケンスを構築することです。 

難しさは、すべての「移動」ステップが実質的に敵対的であるという事実から来ています。猫に複数の隣人がいる場合、猫はそのうちのどれかを選択することができます。 したがって、木を慎重に剪定することによって、猫が通る可能性のあるすべての経路が最終的にノード n に向かうようにする必要があります。 

制約は、テスト ケースごとの線形または線形に近い解決策を意味します。 すべてのテスト ケースにわたる n の合計は 2×10^5 であるため、テスト ケースごとに O(n) を超えるアルゴリズムやノードごとの大量の再計算を使用するアルゴリズムは失敗します。 これにより、パスの再計算の繰り返しや、考えられるすべての猫の状態のシミュレーションが即座に除外されます。 

微妙な問題は、単純な貪欲な削除戦略では簡単に猫を殺す可能性があることです。 たとえば、到達可能性を慎重に制御せずに、猫の位置の可能性のある現在のフロンティアにあるノードを削除した場合、猫は非決定的な動きによりそのノードに座ったままになり、死亡する可能性があります。 もう 1 つの障害モードは、ブランチを積極的にプルーニングしようとしたときに連続して大量の削除が発行され、制約に違反することです。 

したがって、中心的な課題は、単一のパスを誘導するだけではなく、少なくとも 1 つの安全な軌道の間、ノード n への接続を確実に維持しながら、可能な猫の位置の縮小セットを維持することです。 

## アプローチ

 強引な解釈では、各指示の後に猫の考えられるすべての位置をシミュレートしようとします。 各移動コマンドの後、可能な猫の位置のセットは、すべての現在の位置の隣接するすべての位置に拡張されます。 削除するたびに、ノードはこのセットから削除されます。 到達可能な状態のセットが移動ステップごとに分岐するため、このサイズはすぐに指数関数的に増加します。 中程度のサイズのツリーであっても、可能な位置のセットが O(n) ステップでコンポーネント全体をカバーする可能性があるため、シミュレーションは実行不可能になります。 

重要な構造的観察は、猫の動きは非決定的であるが、基礎となるグラフはツリーであるため、任意の 2 つのノード間には一意の単純なパスが存在するということです。 ツリーをノード n にルートし、n までの距離を考慮すると、すべての削除を使用して、不要になったサブツリーを永久に削除できます。 一方、「移動」コマンドを繰り返すと、猫は端に沿って移動することができますが、葉を剪定して内側に向かって作業を繰り返すことで、全体的な方向を制御できます。 

このプロセスについて考えるのに役立つ方法は、常に cat とノード n の両方を含む縮小接続コンポーネントを維持することです。 現在のコンポーネントの n ではないリーフを繰り返し選択し、それを安全に削除し、猫が孤立した領域で立ち往生しないように移動ステップを許可します。 ツリーには常に少なくとも 2 つの葉があるため、進行状況を維持する方法でいつでも削除を選択できます。 

これは、標準的な木の剪定戦略につながります。つまり、猫が常に残りの構造の「中心に戻る」ように移動操作をインターリーブしながら、葉を外側から内側に繰り返し除去します。 連続した削除を禁止するという制約により、2 つの削除ごとに移動を挿入する必要があり、これはこのピーリング プロセスに自然に適合します。

 ## アルゴリズムのチュートリアル

 ノード 1 または任意のルートから始まる DFS 順序を構築しますが、これは制御されたシーケンスでどのノードを削除するかを知る方法として解釈されます。 より深いアイデアは、n を除くすべてのノードが最終的に 1 回だけ削除されるようにし、猫がそのノードにいないことが保証される場合には削除が常に適用されるようにすることです。 

1. ノード n でツリーをルートします。 これにより、すべてのノードがターゲットに対して明確に定義された親を持つようになります。 直感的には、安全なパスは最終的には n に向かって上向きに移動するはずです。 
2. ノード n から DFS を実行して、ノードの事後順序を生成します。 この順序により、子が親の前に処理されることが保証されるため、ノードを削除すると、そのサブツリーはすでに処理されています。 
3. ノードが DFS の意味で「処理」されたかどうかを追跡する訪問済みの構造を維持します。 これは猫に関するものではなく、サブツリーが既に構造的に無関係であるノードのみを削除するようにするためのものです。 
4. DFS の巻き戻し中、子サブツリーから戻るたびに、移動コマンドを発行します。 これは、猫がより深く移動したり、残りの有効成分内で調整したりできることを表します。 
5. あるノード u (u ≠ n) をルートとするサブツリーの処理が終了した後、u の削除コマンドを発行します。 これにより、u は安全に削除されます。その子孫はすべてすでに処理されており、n に到達するためにもう必要ないからです。 
6. 2 つの削除の間に、少なくとも 1 つの移動コマンドが挿入されるようにします。 これは、連続的な削除を禁止する制約を直接満たします。 
7. 一連の操作は、n を除くすべてのノードが削除されて自然に終了します。すべての代替分岐が削除されているため、残りの可能な cat 位置は強制的に n に向かって収束します。 

### なぜ効果があるのか

 重要な不変条件は、u をルートとするサブツリーを処理した後、n への有効なパスはおそらく u 自体を経由する場合を除き、そのサブツリー内のノードを必要としないということです。 親の前に子を処理するため、u を削除すると、その子孫を通るすべての代替ルートがすでに解決されています。 猫の非決定的な動きは、削除されたサブツリー内の位置を保持できません。また、ノードが n への唯一のコネクタである間はノードを削除しないため、猫は常に n を含む接続されたコンポーネント内に残ります。 時間が経つにつれて、すべての迂回路が削除され、n が唯一の安全な終点として残ります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        g = [[] for _ in range(n + 1)]
        for _ in range(n - 1):
            u, v = map(int, input().split())
            g[u].append(v)
            g[v].append(u)

        parent = [0] * (n + 1)
        order = []

        # iterative DFS to avoid recursion issues
        stack = [(1, 0)]
        parent[1] = -1

        while stack:
            u, p = stack.pop()
            parent[u] = p
            order.append(u)
            for v in g[u]:
                if v == p:
                    continue
                stack.append((v, u))

        # reverse order gives postorder-like processing
        order.reverse()

        res = []
        last_was_delete = False

        for u in order:
            if u == 1:
                continue
            if last_was_delete:
                res.append("1")
                last_was_delete = False
            res.append(f"2 {u}")
            last_was_delete = True

        if last_was_delete:
            res.append("1")

        print(len(res))
        print("\n".join(res))

if __name__ == "__main__":
    solve()
```この実装では、DFS トラバーサルを構築して、サブツリーが親の前に処理される順序を取得します。 逆の DFS 順序は安全な削除シーケンスとして使用され、子孫の後のノードを常に削除することが保証されます。 

ブール値フラグ`last_was_delete`2 つの削除が連続して出現できないという制約が適用されます。 削除を出力しようとしていて、前の命令も削除だった場合は常に、最初に移動命令を挿入します。 これにより、移動操作は将来の削除を制限しないため、正確さに影響を与えずにシーケンスの有効性が維持されます。 

DFS の順序付けによって構造的な安全性が保証されるため、この構築では cat の明示的なシミュレーションが回避されます。DFS ツリー内のその下にあるすべてのノードが処理される前にノードを削除することはありません。 

## 実用的な例

 ノード 4 がターゲットであり、ノードがチェーン 1-2-3-4 を形成する小さなツリーを考えてみましょう。 

| ステップ | 現在のノード | アクション | 出力 |
 | --- | --- | --- | --- |
 | 1 | 4 | DFS ルートを開始する | - |
 | 2 | 3 | プロセスの子 | 2 3 |
 | 3 | 2 | プロセスの親 | 1 |
 | 4 | 1 | 最終的な削除ステップ | 2 1 |

 このトレースは、削除がリーフからルートに向かってどのように進行するかを示しており、各ステップで残りの構造に 4 への有効なルートが含まれていることを確認します。 

次に、ターゲット ノード 5 がチェーンを介して接続されている、1 を中心とする星形のツリーを考えます。 

| ステップ | ノードが処理されました | アクション | 出力 |
 | --- | --- | --- | --- |
 | 1 | リーフノード | 葉を削除する | 2 葉 |
 | 2 | 中間 | 挿入された移動 | 1 |
 | 3 | 中央 | 最後に中心を削除 | 2 1 |

 これは、葉の剪定によって無関係な枝が最初に削除され、猫は常にターゲットにつながる生き残ったバックボーンの内側に留まることを示しています。

 ## 特殊なケース

 2 ノード ツリーは、ノード 1 がノード 2 (ターゲット) に直接接続する最も単純なケースです。 このアルゴリズムは、必要に応じて移動分離を確保した後、ただちにノード 1 の削除を生成します。 代替の分岐がないため、猫は唯一の経路に沿って移動することになり、縮退構造が正しいことが確認されます。 

星型ツリーでは、ノード 1 が n を含む他のすべてのノードに接続します。 DFS 注文は最初にリーフを処理するため、構造的リスクが現れる前にターゲット以外のリーフがすべて削除されます。 猫は移動操作中に葉の間を移動する可能性がありますが、葉が削除されると、猫は n につながるパスに限定され、確実に収束します。 

長いチェーンでは、n を除くすべてのノードは、ある時点で残りの構造のリーフになります。 事後削除では、n に向かう後続ノードが処理された後にのみ各ノードが削除されるため、cat は削除された領域で孤立することなく、エンドポイントに向かって徐々に圧縮されます。
