 ## 問題の理解

 整数の配列が与えられます`a`、各要素は「位置にある値」のように動作し、2 番目の配列`b`これは、対応するそれぞれの値を増やすのにどれだけのコストがかかるかを示しています`a[i]`すべての増分は独立しており、そのインデックスに対して同じ固定量のコストがかかります。 

目標は、すべての数値を等しくしたり、目標値に到達したりすることではありません。 代わりに、単一のインデックスのペアを作成することだけを考慮します。`(i, j)`ある程度の増分の後、これら 2 つの位置の値は 1 より大きい公約数を共有します。言い換えると、配列内の少なくとも 2 つの数値が、最小限のコストを支払った後に何らかの素数で同時に割り切れるようになる必要があります。 

各操作は単一の要素を 1 ずつ上方に移動し、インデックスが異なれば単位あたりのコストも異なります。 したがって、問題は本質的に、素因数を共有するためにどの 2 つのインデックスを「調整」するかを決定することと、その調整を達成するためにそれらを最小限に上方調整する方法を決定することです。 

制約はソリューションを強力に形作ります。 テスト ケース全体の要素の合計数は最大 200,000 であるため、インデックスのすべてのペアを直接考慮するソリューションはすでに遅すぎます。 すべてのペアと考えられるすべての gcd ターゲットを試す単純なアプローチは、特に値が 10^9 に達する可能性があるため、実行可能な限界をはるかに超えています。これは、総当たりの因子シミュレーションが不可能であることを意味します。 

重要な隠された構造は、一般に 1 より大きい gcd は必要なく、同じ素数の倍数に到達するには両方の数値が必要なだけであるということです。 これにより、問題は恣意的な gcd 推論からプライム アラインメントに軽減されます。 

配列に gcd が 1 より大きい 2 つの数値が既に含まれている場合、微妙なエッジ ケースが発生します。たとえば、次のような場合です。`a = [4, 8]`、たとえ改善を試みるとしても、答えはゼロです。 正しいアルゴリズムであれば、このケースを即座に検出する必要があります。 

もう 1 つの重要なエッジ ケースは、1 つの要素のみが調整され、別の要素がすでに素数で割り切れる場合です。 たとえば、次の場合`a = [2, 9]`の場合、コスト構造に応じて 9 を 10 または 12 に増やすことができますが、単純にすでに素数が豊富な 2 に合わせるのが正解かもしれません。 常に両側を修正する単純な戦略では、より安価な片側調整を見逃す可能性があります。 

## アプローチ

 ## アルゴリズムのチュートリアル

 1. の最大値までの最小の素因数を事前計算します。`a`。 これにより、任意の数値を対数時間で高速に因数分解できます。 このステップが必要なのは、すべての数値が複数の素数に寄与する可能性があり、それらを効率的に列挙する必要があるためです。 
2. 各インデックスについて`i`、値を考慮してください`a[i]`そしてそのすべての異なる素因数を計算します。 これらの素数は、別の同一または互換性のある要素と一致した場合に、すでに gcd > 1 を与える約数を表します。 
3. 各素数について`p`、作成コストを計算します。`a[i]`で割り切れる`p`。 これを行うには、次の倍数を見つけます。`p`以上`a[i]`。 もし`a[i] % p == 0`、コストはゼロです。 それ以外の場合、必要な増分は次のようになります。`p - (a[i] % p)`、合計コストはその増分倍です`b[i]`。 
4. 素数ごとに維持する`p`、すべてのインデックスの中で最も小さい 2 つのコスト。 ペアが必要なので、最高の 2 つだけが必要です`(i, j)`。 
5. 要素が素数に対してすでにゼロコストを提供している場合も処理します。 いずれかの素数に少なくとも 2 つのゼロコスト寄与子がある場合、これら 2 つのインデックスはすでに 1 より大きい gcd を共有しているため、答えはすぐにゼロになります。 
6. すべてのインデックスを処理した後、各素数について 2 つの最小コストの合計を取得し、すべての素数にわたるグローバル最小値を追跡します。 
7. この最小値を返します。 

### なぜ効果があるのか

 それぞれの有効な解は素数の選択に対応します`p`選択された両方の要素が次の倍数になるように調整されます。`p`。 gcd が 1 より大きいペアは少なくとも 1 つの素因数を共有する必要があるため、すべての有効な構成は何らかのプライム バケットの下でキャプチャされます。 アルゴリズムは素数ごとに、その素数の 2 つのインデックスをアクティブにする最も安価な方法を計算します。 コストはインデックスごとに独立しており、加算されるため、その素数に対して最小の 2 つの独立コストを選択することが最適です。 すべての素数の最小値を取ることで、より適切な共有約数を見逃すことがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXA = 200000

# smallest prime factor sieve
spf = list(range(MAXA + 1))
for i in range(2, int(MAXA ** 0.5) + 1):
    if spf[i] == i:
        for j in range(i * i, MAXA + 1, i):
            if spf[j] == j:
                spf[j] = i

def factorize(x):
    res = set()
    while x > 1:
        p = spf[x]
        res.add(p)
        while x % p == 0:
            x //= p
    return res

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    best1 = {}
    best2 = {}
    ans = float('inf')

    for i in range(n):
        x = a[i]

        primes = factorize(x)

        # also consider x+1 because next multiple effects can introduce new primes indirectly
        # but here we only need primes of x since increments are handled per prime alignment
        for p in primes:
            if x % p == 0:
                cost = 0
            else:
                cost = (p - x % p) * b[i]

            if cost < best1.get(p, float('inf')):
                best2[p] = best1.get(p, float('inf'))
                best1[p] = cost
            elif cost < best2.get(p, float('inf')):
                best2[p] = cost

    for p in best1:
        if best2.get(p, float('inf')) < float('inf'):
            ans = min(ans, best1[p] + best2[p])

    print(ans)
```ふるいは可能な最大値まで一度構築されるため、最小の素因数をたどることによって各数値をすばやく因数分解できます。 辞書`best1`そして`best2`素数ごとに 2 つの最も安いコストを維持します。 これにより、完全なリストの保存が回避され、遭遇する個別の素数の数においてメモリが線形に保たれます。 

コスト計算は、「ステップごとのコストの p 倍の次の距離までの距離」を直接エンコードします。 これは、数値の問題からモジュラー算術コスト問題への核心部分の削減です。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    MAXA = 200000
    spf = list(range(MAXA + 1))
    for i in range(2, int(MAXA ** 0.5) + 1):
        if spf[i] == i:
            for j in range(i * i, MAXA + 1, i):
                if spf[j] == j:
                    spf[j] = i

    def factorize(x):
        res = set()
        while x > 1:
            p = spf[x]
            res.add(p)
            while x % p == 0:
                x //= p
        return res

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        best1 = {}
        best2 = {}
        ans = float('inf')

        for i in range(n):
            x = a[i]
            primes = factorize(x)
            for p in primes:
                cost = 0
                if x % p != 0:
                    cost = (p - x % p) * b[i]

                    best2[p] = best1.get(p, float('inf'))

                    best2[p] = cost

        for p in best1:
            if best2.get(p, float('inf')) < float('inf'):
                ans = min(ans, best1[p] + best2[p])

        out.append(str(ans))

    return "\n".join(out)

 ## 特殊なケース

 重要なケースの 1 つは、配列に有効なペアが既に含まれている場合です。 入力用`a = [4, 8]`、どちらの数値も 2 で割り切れるため、演算は必要ありません。 素数 2 には 2 つのゼロコストのエントリがあり、最良の合計がゼロになるため、アルゴリズムはこれを捕捉します。 

もう 1 つのケースは、素数として使用できる要素が 1 つだけである場合です。 のために`a = [2, 9, 25]`、素数は要素間で異なりますが、アルゴリズムは依然としてすべての素数を独立して考慮し、2 つの候補が存在する場合にのみペアを形成します。 素数に 2 つの寄与者がない場合、素数は無視され、誤ったペアリングが防止されます。 

最後のケースは、次のような極端なコストの不均衡です。`b[i]`1 つのインデックスに対して非常に大きいです。 コストはインデックスごとに個別に計算され、最小の 2 つの値のみが取得されるため、アルゴリズムは自然に高価な寄与者を回避し、最適性を維持しながら最も安価な有効なペアを選択します。
