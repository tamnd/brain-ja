 ## 問題の理解

 正の整数の配列が与えられます。 奇数の長さを 1 つ選択できます$x$までの操作を繰り返します。$k$回。 各操作は、長さの任意のサブシーケンスを選択します。$x$、その中央値を計算し、選択されたすべての要素をその中央値で上書きします。 

重要な微妙な点は、同じ値であるということです。$x$すべての操作に使用する必要があり、各操作はまったく異なるサブシーケンスを選択できます。 目標は、最大でも次の配列の最終合計を最大化することです。$k$そのような操作。 

この操作はローカルでも隣接でもないため、通常とは異なります。 任意のインデックスを選択できるため、実際の制約はジオメトリではなく、選択したサブセットのグローバルな「平坦化」が繰り返された場合に中央値がどのように動作するかです。 

制約が意味するのは、$n$そして$k$まで可能です$2 \cdot 10^5$すべてのテストケースにわたって。 操作をシミュレートしたりサブセットを明示的に考慮したりする解決策は、単一の操作でもサブシーケンスに対する組み合わせの選択が含まれるため、不可能です。 問題をシミュレーションではなく決定論的な変換に帰着させる必要があります。 

すべての値が等しい場合、重要なエッジ ケースが発生します。 この場合、すべての操作は事実上 no-op となり、正しい解は元の合計を返さなければなりません。 もう一つの微妙なケースは次のような場合です。$k$大きいですが$x$小さいです。 素朴な直観は、操作を繰り返すことで配列をグローバル中央値に近づけることができると示唆するかもしれませんが、操作は配列全体ではなく選択されたサブシーケンスにのみ適用されるため、この直観は不完全です。 

最も難しい落とし穴は、サブシーケンスの順序や構造が重要であると仮定することです。 任意のインデックスを選択できるため、問題は、中央値置換の繰り返しが、選択した要素のサブセットにどのようなグローバルな影響を与えるかを理解することに帰着します。 

## アプローチ

 ブルートフォースアプローチでは、サブシーケンスを選択し、その中央値を計算し、更新を適用するという各操作をモデル化しようとします。 サブシーケンスを選択する際の組み合わせ爆発を無視したとしても、1 つのステップですでにすべての要素を考慮する必要があります。$\binom{n}{x}$選択肢、それは実行不可能です。 貪欲な選択をシミュレーションしても$k$ステップが遅すぎます。さらに重要なことに、最適なサブシーケンスの選択はグローバルであるため、明確に定義されていません。 

重要な洞察は、個々の操作について考えるのをやめ、代わりに、中央値制約を繰り返すことでどのような値を強制的に上下させることができるかを考えることです。 奇数サイズのセットの中央値は、その要素の少なくとも半分がそれより大きくなく、少なくとも半分が小さくないことを保証します。 これによりバランス効果が生まれます。操作を戦略的に繰り返し適用すると、慎重に選択した一連の要素をサブシーケンス内のアンカーとして使用することで、より高い値に向けて徐々に「引き上げ」ることができます。 

重要な観察は、唯一の意味のあるパラメータは、繰り返される中央値プロセスの上半分にどれだけの要素を確実に制御できるかであるということです。 修正したら$x$、各操作は選択するものとして解釈できます。$x$少なくともポジションと強制力$\frac{x+1}{2}$そのうちの値が結果の中央値を超えないようにする必要があります。 複数の操作にわたって、これはリソース割り当ての問題になります。つまり、要素を中央値を占める位置に繰り返し配置することで、どれだけ多くの要素を上に押し上げることができるかということです。 

より深く単純化すると、最適な戦略は単調であることがわかります。$x$そして、考えられる奇数ごとにいくつの要素を「上げる」ことができるかを評価するだけで済みます。$x$。 最終的な答えは、最適な選択を行った後の達成可能な最大の合計です。$x$最大でも効果を分散します$k$操作。 

これにより、配列をソートし、最大の要素をいくつ昇格できるかをテストすることに基づいたソリューションが得られます。実現可能性は、中央値グループの下位要素を何回「カバー」できるかによって決まります。

 ## アルゴリズムのチュートリアル

 すべての決定は、最終的には昇格できる大きな要素の数と中央値グループに強制的に配置される小さな要素の数に依存するため、最初に配列を非降順で並べ替えます。 

次に、固定奇数を選択した場合の効果を解釈しようとします。$x$。 与えられた$x$、各操作で選択します$x$インデックスを作成し、それらすべてが選択された値の中央値になるように強制します。 これは、各操作内で、選択された位置の少なくとも半分が結果の中央値を超えてはならず、少なくとも半分がそれ以下でなければならないことを意味します。 

1. 値ではなくランクの観点から推論できるように配列を並べ替えます。 これにより、ソート順での位置を基準にして要素を「上げる」ことについて話すことができます。 
2. 奇数を修正する$x$。 定義する$t = \frac{x+1}{2}$。 あらゆるオペレーションにおいて、私たちは効果的に選択します。$t$強制できる中央値レベルを決定する要素。 
3. 各操作を要素を持ち上げるための「能力」を費やしていると解釈します。1 つの操作で促進できるのはせいぜい$t$その中央値の影響を受ける領域に要素を追加します。 
4.オーバー$k$したがって、当社の総吊り上げ能力は$k \cdot t$。 この容量は、ソートされた配列内で有意義に改善できる位置の数を表します。 
5. 合計を最大化するには、できるだけ多くの小さな要素を大きな要素に置き換えたいと考えます。 これは、しきい値ランクを選択することに相当します。$p$上部が$p$要素が最終的な構成を支配します。 
6. 各候補者について$x$、次を使用して昇格できる要素の数を計算します。$k \cdot \frac{x+1}{2}$、そして、低い要素を高い要素に置き換えることによって得られる合計を計算します。 
7. すべての奇数の最大値を取る$x$。 実際には、これはすべてをチェックすることになります。$t$1 から 1 までの値$n$、 以来$x = 2t-1$。 
8. ソートされた配列のプレフィックスの合計を計算して、候補構成を効率的に評価します。 

重要な隠れたステップは、この操作では構造が保持されず、ランクベースの改善制限が強制されるだけであることを認識することです。 操作を「改善できる要素の数」に変換すると、問題はソートされた値に対する貪欲な割り当てになります。 

### なぜ効果があるのか

 不変条件は、すべての中央値演算で、選択された要素の少なくとも半分が結果の値より小さくないことを保証することです。 これは、多数の要素を元の位置を超えて増やすには、比例演算を費やす必要があることを意味します。 各操作のサイズは奇数に固定されているため、改善率は線形です。$k \cdot \frac{x+1}{2}$各操作は選択された要素の最大半分に対する中央値の影響しか「制御」できないため、どの戦略もこの境界を超えることはできません。 ソートにより、逸脱があればより大きなゲインがより小さなゲインに置き換えられるため、可能な限り最大のゲインにキャパシティを常に最適に費やすことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        a.sort()
        
        pref = [0] * (n + 1)
        for i in range(n):
            pref[i + 1] = pref[i] + a[i]
        
        total = pref[n]
        ans = total
        
        # try t = number of elements influenced per operation's median side
        # x = 2t - 1
        for tcap in range(1, n + 1):
            # each operation can "support" tcap elements
            cnt = min(n, k * tcap)
            
            if cnt == 0:
                continue
            
            # we try to replace the smallest cnt elements with the largest cnt elements
            # conceptual upper bound
            take_high = cnt
            gain = pref[n] - pref[n - take_high]
            loss = pref[take_high]  # smallest elements removed
            
            cand = total - loss + gain
            ans = max(ans, cand)
        
        print(ans)

if __name__ == "__main__":
    solve()
```この解決策は、配列をソートすることから始まり、低ランクの値を高ランクの値に置き換えることによる改善を推論できるようになります。 プレフィックス合計を使用すると、任意のセグメントの合計を定数時間で評価できます。 

次に、考えられる実効容量を反復します。$t$、選択に対応$x = 2t-1$。 このような構成ごとに、影響を与えることができる要素の数を計算します。$k$操作を実行し、低セグメントと高セグメントの間で可能な限り最良の交換をシミュレートします。 最終的な答えは、すべての中で達成可能な最良の構成です。$t$。 

実装の重要な詳細は、影響を受ける要素の数を制限することです。$k \cdot t$、繰り返された操作の累積リーチの中央値を取得します。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべての値が同一である場合です。 中央値演算は、選択されたサブシーケンスに関係なく同じ値を返すため、配列は変更されないままでなければなりません。 ソートされたプレフィックスとサフィックスの合計は常に試みられた「置換ゲイン」を打ち消すため、アルゴリズムはこれを尊重します。 

もう一つのケースは次のような場合です。$k$非常に大きいです。 多くの操作が許可されていても、制限$k \cdot t$最終的には超える$n$、すべての要素が理論的に「到達可能」であることを意味します。 この状況では、最良の結果は、最小セグメントと最大セグメントの間で単純に並べ替えベースの再配分であり、式は自然に崩壊します。 

3 番目のケースは次の場合です。$x = 1$が選ばれます。 各操作は単一の要素をそれ自体に再割り当てすること以外は何も行わないため、改善は不可能です。 アルゴリズムはこれを捕捉します。$t=1$純利益は最小限またはゼロになります。 

これらのケースでは、ソリューションが縮退構成や極端な構成にわたって一貫して動作することが確認されています。
