 ## 解決策
 ## 問題の理解

 私たちは持っています`n`製品タイプ。 製品`i`もっている`k_i`数日後には消えてしまいます`t_i`。 遠征隊は、`c`人々、だから毎日正確に`c`部分的に食べることができます。 異なる製品の一部を同じ日に混合することができます。これは、製品が単一の不可分なアイテムではないことを意味します。期限までに必要な合計の食べられる量だけが必要です。 

課題は、選択したすべての種類のすべての部分を、対応する期限までに食べられるように、できるだけ多くの製品の種類を選択することです。 出力は、この最大セットのサイズと選択された積のインデックスです。 

制約により、貪欲な解決策が強制されます。 あり得る`2 * 10^5`製品なので、すべてのサブセットをチェックすることは不可能です。`2^n`サブセットは手の届かないところにあります。 アルゴリズムさえも`O(n^2)`このサイズでは遅すぎます。 に近いものが必要です`O(n log n)`これは通常、並べ替えとデータ構造を意味します。 

大きな値は、`c`、`t_i`、 そして`k_i`も重要です。 食べられる量は`10^27`したがって、実装ではオーバーフローのない整数演算を使用する必要があります。 Python の整数はこれを自然に処理します。 

よくある間違いは、食品の総量だけを確認することです。 例えば：```
2 3
1 10
100 1000
```遠征全体の総容量は膨大だが、最初の商品だけでも初日に10人前必要となるのに対し、食べられるのは3人前。 正しい出力は次のとおりです。```
1
2
```もう一つの間違いは、正確な期限を無視することです。 考慮する：```
3 2
1 3
2 1
10 100
```最初の 2 つの製品は合わせて 2 日目までに 4 個必要ですが、利用可能な容量は 4 個だけなので、両方とも可能です。 3 番目の製品は、10 日前の生産能力がそれ以前のすべての期限によって制限されているため、それらに適合することはできません。 アルゴリズムは、すべての期限プレフィックスを継続的に検証する必要があります。 

3 番目のエッジケースは、現在の製品自体は適合するにもかかわらず、製品を取り外す必要がある場合です。 例えば：```
3 5
1 5
2 5
2 20
```最後の製品は大きいですが、それを保持すると、より小さい製品の 1 つが押し出されてしまいます。 最適な回答では 2 つの製品タイプが維持されますが、必ずしも最新の製品である必要はありません。 

## アプローチ

 ブルート フォース ソリューションでは、製品のすべてのサブセットを試すことができます。 サブセットごとに、その製品を期限ごとに分類し、毎日の期限付きの食品の量が最大でも期限内に収まるかどうかを確認します。`c * day`容量の一部。 考えられる唯一のボトルネックは期限プレフィックスであるため、このチェックは正しいです。 ただし、`2^n`サブセット、さらには`n = 50`これはすでに不可能です。 と`n = 200000`、このアプローチはそれほど近いものではありません。 

有用な観察は、実現可能条件の構造を調べることで得られます。 賞味期限で商品を分類した後、期限の早い商品から期限の遅い商品まで処理する場合、重要なのは、これまでに選択された合計数量だけです。 新しい製品を追加することで現在の締め切りが不可能になる場合は、選択した製品を 1 つ破棄する必要があります。 製品タイプの最大数を維持するには、廃棄される製品は、部分数が最も多い製品である必要があります。 

これは、期限付きのジョブの最大数をスケジュールする際の議論と同じです。 大型製品は、小型製品と同じ報酬を与えながら、より多くの容量を消費します。これは、どちらも正確に 1 つの製品タイプとしてカウントされるためです。 選択された大規模な製品を不合格の小規模な製品に置き換えることは、選択されたタイプの数を維持しながら実現可能性を向上させることしかできません。 

最大ヒープには、現在選択されている製品が部分数ごとに保存されます。 期限順に並べ替えた後、すべての製品を追加し、現在のプレフィックスがその容量を超える場合は、最大の製品をヒープから削除します。 残りのヒープには最適なセットが含まれます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n * n) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての商品を有効期限日の昇順に並べ替えます。 期限が短い製品は、より厳しい容量制限が設けられるため、最初に検討する必要があります。 
2. 現在選択されているセット内の部分の累計を保持し、処理された各製品を最大ヒープに挿入します。 ヒープを使用すると、消費容量の観点から最も高価な製品を見つけることができます。 
3. 期限のある商品を投入後`t`、選択した部分の合計数を次と比較します。`c * t`。 合計が大きすぎる場合は、最大部分数の製品をヒープから削除し、そのサイズを合計から差し引きます。 
4. すべての製品が処理されると、ヒープには、答えを形成する製品タイプのインデックスが含まれます。 

機能する理由: すべてのデッドラインを処理した後、ヒープは常に、これまでに検討されたすべての実行可能な選択肢の中で可能な最大数の製品を表します。 期限に違反した場合、実行可能な解決策では、現在のセットから少なくとも 1 つの製品を削除する必要があります。 最大の製品を削除すると、回答数から 1 つの製品だけが失われながら、最も多くの容量が解放されるため、可能な限り最良の選択です。 違反が発生するたびにこれを繰り返すことで、選択されたタイプの最大数が維持されます。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n, c = map(int, input().split())
    products = []

    for i in range(1, n + 1):
        t, k = map(int, input().split())
        products.append((t, k, i))

    products.sort()

    heap = []
    total = 0

    for t, k, idx in products:
        heapq.heappush(heap, (-k, idx))
        total += k

        if total > c * t:
            removed_k, removed_idx = heapq.heappop(heap)
            total += removed_k

    answer = [idx for _, idx in heap]

    print(len(answer))
    if answer:
        print(*answer)

if __name__ == "__main__":
    solve()
```製品は、すべての違反が発生する可能性のある最も早い期限にチェックされるように分類されます。 ヒープには負の部分のカウントが格納されます。`heapq`は最小ヒープであり、値を否定すると最大ヒープになります。 

変数`total`現在選択されているセット内の食品の量が含まれます。 プロダクトが削除されると、格納されているヒープ値は負になるため、プロダクトを追加し直すとその部分が減算されます。 Python の整数には制限がないため、次のような値になります。`c * t`と合計`k_i`オーバーフローしないでください。 

最後のヒープには、すべての容量チェックに合格した製品のみが含まれます。 この問題はインデックスの有効な順序を受け入れるため、それらの順序は無関係です。
