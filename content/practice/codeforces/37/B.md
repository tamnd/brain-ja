 ## 解決策
 ## 問題の理解

 上司はから始まります`max`健康と再生`reg`毎秒健康を維持します。 私たちはいくつかの巻物を所有しています。 各巻物は、ボスの体力が元の体力の最大でも数パーセントである場合にのみアクティブ化できます。 一度有効化すると、その巻物は永久に合計ダメージ出力に 1 秒あたりのダメージを追加します。 

1 秒のタイムラインは非常に重要です。 

1. 既存の有効な呪文はダメージを与えます。 
2. ボスは再生します。 
3. 私たちは最大 1 つの新しい巻物をアクティブにすることができます。 
4. ボスの体力が今の場合`<= 0`、戦いは終わります。 

発動条件は、その秒間のダメージと回復後のボスの健康状態によって異なります。 

課題は、ボスを倒すことができるかどうかを判断することです。 「はい」の場合、可能な最小終了時間を達成するスクロール アクティベーションの有効なシーケンスを 1 つ出力する必要があります。 

制約は、二次または三次の作業を可能にするのに十分小さいです。 最大でも1000巻あります。 ダメージ値も小さい。 これは、高度なデータ構造よりも、正しい貪欲戦略の発見に重点を置くべきであることを直ちに示唆しています。 

微妙な点は、巻物は一度限りのダメージではないということです。 各巻物は将来のダメージ率を永続的に増加させます。 より強力なスクロールをより早くアクティブ化すると、将来のしきい値に早く到達できるようになる可能性があります。 

もう 1 つの簡単な間違いは、1 秒以内のアクションの順序によって発生します。 再生後にボスの体力が十分に低くなったとします。 その秒の間に新しい巻物を起動することはできますが、その新しく起動した巻物はすぐにはダメージを与えません。 そのダメージは次の瞬間から始まります。 

次の例を考えてみましょう。```
1 10 0
50 100
```ボスのHPは10から始まります。 巻物に必要な体力は最大 5 です。既存のダメージ源がないため、体力が 10 を下回ることはありません。正解は次のとおりです。`NO`。 

不用意に実装すると、スクロールのダメージが大きいためすぐにスクロールをアクティブにできると誤って想定する可能性があります。 

現在の DPS が再生よりも大きくない場合、別の危険なエッジ ケースが発生します。 仮定する：```
2 100 10
100 5
90 100
```しきい値が 100% であるため、最初のスクロールをすぐにアクティブにすることができます。 その後、合計 DPS はわずか 5 で、再生 10 よりも小さくなります。ボスの HP は決して 100 を下回らないため、2 番目のスクロールは使用できません。 正しい答えは、`NO`。 

最終的なダメージの合計が再生を超えるかどうかだけを確認する単純なシミュレーションでは、誤って勝利を主張することになります。 

もう 1 つの微妙なケースは、しきい値が正確に等しいことから生じます。```
1 100 0
99 1
```巻物は体力が最大 99 の場合にのみ使用できます。最初は有効な呪文がないため、体力が 100 から変化することはありません。ボスが正確にしきい値に達すると、巻物は再生直後に合法になるため、平等が重要です。 

## アプローチ

 ブルート フォース アプローチでは、スクロール アクティベーションの考えられるすべての順序が試行されます。 各順列について、戦闘を秒ごとにシミュレートし、しきい値に到達できるかどうかを確認します。 

これは絶望的に高価です。 巻物が 1000 個あると、全命令のほんの一部を探索することさえ不可能です。 最も難しいのは、次にどの巻物をアクティブにするかを決定することです。 

重要な点は、以前に選択したスクロールに関して重要なのは、現在の合計 DPS だけであるということです。 

現在の合計 DPS が`D`。 毎秒、ボスは実質的に負けます`D - reg`健康。ただし、健康の上限は次のとおりです。`max`。 

もし`D <= reg`、ボスの体力は決して減りません。 現在の健康状態よりも小さい将来のしきい値には到達できません。 

もし`D > reg`、ボスの体力は着実に減少します。 最終的には、すべてのしきい値に到達可能になります。 

これにより、問題はスケジュールに関する質問に変換されます。 

しきい値パーセンテージのあるスクロールの場合`pow[i]`、アクティベーションの健全性制限を定義します。```
limit[i] = floor(max * pow[i] / 100)
```現在の健康状態が最高レベルになったら`limit[i]`、その巻物は永久に利用可能になります。 

ここで、貪欲な洞察が必要になります。 

すでに複数の巻物が利用可能な場合は、最大ダメージの巻物を最初にアクティブにすることが常に最適です。 初期のダメージはその後のすべての秒間に寄与するため、より大きな DPS を遅らせることは決して役に立ちません。 

これにより、次のような自然なプロセスが得られます。 

現在の DPS を使用してボスの体力を継続的に低下させます。 新しい巻物が利用可能になるたびに、私たちは利用可能な最も強力な巻物を貪欲にアクティブ化します。 

戦い全体が決定的になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | お(ん!) | O(N) | 遅すぎる |
 | 最適 | O(N² log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各パーセントしきい値を絶対的な健康制限に変換します。 

スクロール用`i`、次を計算します。```
limit[i] = floor(max_hp * pow[i] / 100)
```これは、スクロールがアクティブになる最大のボスの体力です。 
2. すべての巻物を制限値の小さい順に並べ替えます。 

ボスの体力が減少すると、より多くの巻物が利用可能になります。 閾値を降順で処理することは、実際の戦闘の進行に一致します。 
3. シミュレーション中は次の 3 つの点を維持してください。`cur_hp`、現在の2番目の再生後のボスの体力。`dps`、1秒あたりの合計アクティブダメージ。 

現在利用可能だが未使用の巻物をすべて含む優先キュー。ダメージ順に並べられます。 
4. 当初、ボスの体力は正確に`max`。 

すべてのスクロール`limit >= max`時間 0 ではすぐに使用可能になります。それらをヒープにプッシュします。 
5. 開始時にヒープが空の場合、ボスにダメージを与え始めることはできません。 

出力`NO`。 
6. 入手可能な最強の巻物を繰り返しアクティブにします。 

各アクティベーションは現在の時刻に行われます。 

そのダメージを追加する`dps`。 

アクティベーション操作を記録します。 
7. DPS を更新した後、次のことを確認します。`dps > reg`。 

そうしないと、ボスの体力がそれ以上減少することはありません。 戦いは永遠に行き詰まってしまいます。 

すでに利用可能なスクロールが存在する場合は、引き続きアクティブ化します。 最終的に利用可能なスクロールがなくなった場合、`dps <= reg`、出力`NO`。 
8. いつ`dps > reg`、ボスが負けます`dps - reg`1秒あたりの効果的な健康状態。 

1 秒ごとにシミュレーションするのではなく、次のしきい値に到達するまでに必要な秒数を直接計算できます。 

次に使用できないスクロールにはヘルスが必要であるとします。`next_limit`。 

最小のものが必要です`t`次のような:```
cur_hp - t * (dps - reg) <= next_limit
```これは天井分割で解決します。 
9.時間を進める`t`。 

それに応じてボスの健康状態を更新します。 

制限に達したすべてのスクロールがヒープに挿入されます。 
10. すべてのステージで、別のしきい値に達する前にボスをすでに倒せるかどうかも確認します。 

現在の健康状態が`cur_hp`1秒あたりの正味ダメージは`delta = dps - reg`、その後、ボスは次のように死亡します。```
ceil(cur_hp / delta)
```さらに数秒。 

今後のしきい値イベントの前にこれが発生した場合は、すぐに終了します。 

### なぜ効果があるのか

 重要な不変条件は、巻物を選択するたびに、現在利用可能なすべての巻物が代わりに選択される可能性があるということです。 ダメージは数秒にわたって永続的に蓄積されるため、最大のダメージを持つものを選択することが常に最適です。 

利用可能な 2 つの巻物にダメージがあると仮定します。`a < b`。 アクティベートしたら`a`まずそして`b`その後、順序を入れ替えると、中間秒ごとに累積ダメージの合計が増加します。 健全性のしきい値に到達できるようになるのは、より早い時期のみであり、後で到達することはできません。 

この交換議論のため、最適戦略は、現在利用可能な最強の巻物を繰り返し取るという独特の特徴を持ちます。 

しきい値イベント間の健康状態の変化は線形であるため、毎秒シミュレーションするのではなく、重要な瞬間の間を直接ジャンプできます。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n, max_hp, reg = map(int, input().split())

    scrolls = []

    for i in range(n):
        p, d = map(int, input().split())
        limit = max_hp * p // 100
        scrolls.append((limit, d, i + 1))

    scrolls.sort(reverse=True)

    ptr = 0
    heap = []

    cur_hp = max_hp
    dps = 0
    time = 0

    ans = []

    while ptr < n and scrolls[ptr][0] >= cur_hp:
        limit, dmg, idx = scrolls[ptr]
        heapq.heappush(heap, (-dmg, idx, limit))
        ptr += 1

    while True:
        while heap:
            dmg_neg, idx, limit = heapq.heappop(heap)
            dmg = -dmg_neg

            dps += dmg
            ans.append((time, idx))

        if dps <= reg:
            print("NO")
            return

        delta = dps - reg

        kill_time = (cur_hp + delta - 1) // delta

        next_limit = -1
        if ptr < n:
            next_limit = scrolls[ptr][0]

        if next_limit == -1:
            time += kill_time
            print("YES")
            print(time, len(ans))
            for t, idx in ans:
                print(t, idx)
            return

        if cur_hp <= next_limit:
            need = 0
        else:
            need = (cur_hp - next_limit + delta - 1) // delta

        if kill_time <= need:
            time += kill_time
            print("YES")
            print(time, len(ans))
            for t, idx in ans:
                print(t, idx)
            return

        time += need
        cur_hp -= need * delta

        while ptr < n and scrolls[ptr][0] >= cur_hp:
            limit, dmg, idx = scrolls[ptr]
            heapq.heappush(heap, (-dmg, idx, limit))
            ptr += 1

solve()
```最初の部分では、パーセントしきい値を絶対的な健康制限に変換します。 条件は実際の整数のヘルス値に基づいているため、整数除算を使用することは正しいことです。 

巻物は制限値の減少順に並べ替えられているため、ボスの体力が減少するにつれて徐々にロックを解除できるようになります。 

ヒープには、現在利用可能な巻物がダメージ順に格納されます。 パイソンの`heapq`は最小ヒープであるため、ダメージは負の値として挿入されます。 

内側のループは、現在利用可能なすべてのスクロールを即座にアクティブ化します。 利用可能なスクロールを遅らせることは、ダメージが後で寄与し始めるため、決して有益ではありません。 

条件`dps <= reg`デッドロック検出器です。 その時点で、ボスの体力はもう減少できなくなります。 より強力な巻物がまだ利用できない場合、戦いに勝つことはできません。 

式:```
(cur_hp - next_limit + delta - 1) // delta
```天井分割です。 ヘルスが次のしきい値に達するほど低くなったときの最初の 1 秒を計算します。 

実装の微妙な詳細の 1 つは、新たにアクティブ化されたスクロールが同じ秒間にダメージを与えないことです。 新しくロックが解除されたスクロールがアクティブになる前に時間が進むため、シミュレーションでは当然これが考慮されます。

## 複雑さの分析

 ## 特殊なケース

 最初に利用可能なスクロールがない場合を考えてみましょう。```
1 100 0
99 100
```しきい値は 99 HP ですが、ボスは 100 HP から始まり、ダメージソースは存在しません。 ヒープはすぐに空になります。 アルゴリズムはシミュレーションの前にこれを検出し、出力します。`NO`。 

次に、再生成のデッドロックを調べます。```
2 100 10
100 5
90 100
```時間 0 では、最初のスクロールのみが使用可能です。 有効にするとDPS 5が得られます。`5 <= 10`、実効ダメージはプラスではありません。 体力が 100 を下回ることはないため、2 番目の巻物はロックを解除できません。 アルゴリズムチェック`dps <= reg`そして正しく出力される`NO`。 

最後に、正確なしきい値の遷移を考えてみましょう。```
2 10 0
100 1
90 100
```最初の巻物をアクティブにした後の有効ダメージは 1 です。1 秒後、ボスの HP はちょうど 9 に達します。 2 番目の巻物は制限 9 なので、すぐに使用可能になります。 アルゴリズムは上限分割を慎重に使用するため、等価性は 1 秒スキップされるのではなく、到達可能として扱われます。
