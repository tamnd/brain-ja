 ## 問題の理解

 各生徒グループは 2 つのレッスンに正確に出席します。 グループの場合、最初のレッスンで使用する教室は2番目のレッスンで使用する教室を超えてはなりません。 

各教室で何グループが開始されるかを正確に把握しています。 もし`Xi = 3`、ちょうど 3 つのグループが部屋で最初のレッスンを受けます`i`。 

また、各教室の総収容人数の制限もわかっています。 グループが教室に貢献`i`最初のレッスンまたは 2 番目のレッスンが存在する場合。 もし`Yi = 5`、その場合、最大 5 つのグループがルームを使用できます`i`両方のレッスンを組み合わせたものです。 

タスクは、有効な timetable がいくつ存在するかを数えることです。 グループは個別であるため、グループ A を`(1,3)`そしてグループBへ`(2,2)`これらの割り当てを交換することとは異なります。 

グループの総数は$$N = \sum Xi$$そして声明は保証します`N ≤ 1000`。 

教室の数は最大 100 ですが、収容人数も最大 100 です。`O(M * N^2)`または`O(M * N^3)`Pythonでは現実的です。 指数関数的なものは何でも`N`すぐには無理なので、`N`1000に達する可能性があります。 

問題の微妙な部分は、容量条件が実際に何を意味するのかを理解することです。 

部屋を想定します`i`もっている`Xi = 4`。 すると、最初のレッスン中にすでに4つのグループがそこを占めています。 部屋の収容人数が`Yi = 6`、2 番目のレッスン中に追加の 2 つのグループのみが使用できます。 それはまさに意味します$$Yi - Xi$$先に開始したグループはルーム内で終了する場合があります`i`。 

これにより、問題は、グループを小さな教室から大きな教室に転送する方法を数えることに変わります。 

単純な実装を簡単に壊してしまういくつかのエッジケースがあります。 

考慮する：```
2
1 0
1 0
```部屋 1 から始まるグループが 1 つあります。部屋 2 には誰も含めることができないため、グループも部屋 1 で終了する必要があります。正解は次のとおりです。`1`。 

すべての割り当て後にのみ容量をチェックする不用意なソリューションでは、誤って許可してしまう可能性があります。`(1,2)`。 

もう 1 つの注意が必要なケースは次のとおりです。```
2
1 1
1 1
```各部屋は最初のレッスンだけですでに満員に達しています。 グループが別の部屋で終了することはできません。 どちらのグループも強制的にその場に留まるので、答えは次のようになります。`2! = 2`, because groups are distinct.

 分布のみをカウントし、グループの順列を無視する DP は、誤って次の値を返します。`1`。 

もう 1 つ重要なエッジ ケース:```
3
2 0 0
2 2 2
```どちらのグループも部屋 1 から始まります。各グループは部屋 1、2、または 3 で終了する可能性があります。答えは次のとおりです。`3^2 = 9`。 

後の部屋にはまだ空き容量があるため、グループはここでは独立しています。 左から右へ貪欲に容量を埋めようとするアプローチでは、誤って過小評価される可能性があります。 

## アプローチ

 ブルートフォース解釈は簡単です。 すべてのグループに対して、最初の教室と同じかそれ以上の 2 番目の教室を選択し、その収容人数を超える部屋がないことを確認します。 

あれば`N`グループと`M`各グループに最大で 6 つの部屋があります`M`選択肢。 検索スペースはおおよそ次のとおりです$$M^N$$それは絶望的だ`N = 1000`。 

ブルートフォースが概念的に機能する理由は、制約がローカルであるためです。 各グループには有効な終了部屋のみが必要で、部屋の収容人数は後で確認できます。 問題は、グループが共有能力を通じて相互作用し、巨大な組み合わせ状態空間を作成することです。 

重要な点は、最初のレッスンの回数がすでに固定されているということです。 

部屋用`i`、 その通り`Xi`そこからグループが始まります。 せいぜい`Yi`グループ利用可能人数、2回目のレッスンを受講するグループの合計数`i`でも、最初のレッスンが早かったのは、まさに$$Ci = Yi - Xi$$ここでプロセスを再解釈してみましょう。 

グループはある部屋から始まり、そこに留まるか右に移動します。 各部屋`i`正確に受け取らなければなりません`Ci`前の部屋からグループが到着します。 

これは、線に沿った組み合わせの流れの問題になります。 

部屋を左から右に処理します。 処理室中`i`、前の部屋の一部のグループはまだ「開いています」、つまり 2 番目の教室をまだ選択していません。 その数を数えましょう`j`。 

部屋`i`正確に吸収しなければならない`Ci`of them. 残りの開いたグループはさらに右に続きます。 それから、`Xi`ルームから始まるグループ`i`オープンプールに追加されます。 

これは、現在開いているグループの数を超える DP を示唆しています。 

残りの課題は組み合わせ計数です。 もし`j`グループはオープンで部屋も広い`i`吸収しなければならない`Ci`それらの中には、$$\binom{j}{Ci}$$ここで終了するグループを選択する方法。 

その移行後、次のように追加します。`Xi`新しくオープンしたグループ。 

グループは個別であるため、各部屋でどの特定のグループが開始されたのかも考慮する必要があります。 グループにラベルを付ける方法の合計は次のとおりです。$$N!$$DP は、区別できないグループを想定して、開始と終了の間の構造的一致のみをカウントします。 乗算`N!`個別のグループ ID を復元します。

 ## アルゴリズムのチュートリアル

 1. グループの総数を計算します。$$N = \sum Xi$$1. すべての部屋に`i`、次を計算します。$$Ci = Yi - Xi$$

`Ci`ルームで終わる必要がある、以前のルームからのグループの数です`i`。 

1. DP を定義します。`dp[j]`意味:

 いくつかの部屋を処理した後の方法の数`j`グループは現在開いていますが、まだ 2 番目の教室が必要です。 

オープン グループとは、最初の教室はすでに決まっているが、2 番目の教室がまだ選ばれていないグループです。 

1. 初期化します。```
dp[0] = 1
```ルームを処理する前は、開いているグループはありません。 

1. ルームを左から右に処理します。 

現在の部屋に次のものがあるとします。 

-`need = Ci`-`start = Xi`すべての州について`j`：

もし`j < need`、ここで終了するのに十分な開いているグループがないため、移行は不可能です。 

それ以外の場合:

 - どちらかを選択してください`need`グループはここで終了します
 - オープンセットからそれらを削除します。 
- を追加します`start`ここから始まる新しいグループ。 

開いているグループの新しい数は次のようになります。$$nj = j - need + start$$この遷移の方法は次のとおりです。$$\binom{j}{need}$$それで：$$ndp[nj] += dp[j] \cdot \binom{j}{need}$$1. すべてのルームが処理された後、すべてのグループがすでに終了している必要があります。 

したがって、有効な答えは次のとおりです。$$dp[0]$$1. 乗算`N!`。 

DPはグループのアイデンティティを無視した。 すべての構造ソリューションは正確に対応します`N!`グループへの個別のラベルの割り当て。 

したがって、最終的な答えは次のようになります。$$dp[0] \cdot N! \pmod{10^9+7}$$### なぜ効果があるのか

 不変条件は次のとおりです。 

最初の処理後`i`部屋、`dp[j]`最後の教室が最初の教室の中にあるすべてのグループの 2 番目の教室を決定する方法の数を正確に数えます。`i`部屋、正確に出発しながら`j`未完成のグループ。 

2 番目の教室は左に移動できないため、未完了のグループはすべて後の部屋で終了する必要があります。 

加工室時`i`、 その通り`Ci`未完了のグループはそこで終了する必要があります。 サイズのサブセットの選択`Ci`これらのグループはすべて以前のルームから発信されているため、これは有効です。 他の制約は残りません。 

すべての有効なタイムテーブルは、正確に 1 つの DP 遷移シーケンスに対応し、すべての DP 遷移シーケンスが有効なタイムテーブルを構築します。 これにより、時刻表とカウントされた州の間の全単射が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    m = int(input())
    x = list(map(int, input().split()))
    y = list(map(int, input().split()))

    n = sum(x)

    # factorials
    fact = [1] * (n + 1)
    for i in range(1, n + 1):
        fact[i] = fact[i - 1] * i % MOD

    # combinations
    C = [[0] * (n + 1) for _ in range(n + 1)]

    for i in range(n + 1):
        C[i][0] = 1
        C[i][i] = 1

    for i in range(2, n + 1):
        for j in range(1, i):
            C[i][j] = (C[i - 1][j - 1] + C[i - 1][j]) % MOD

    dp = [0] * (n + 1)
    dp[0] = 1

    for i in range(m):
        need = y[i] - x[i]
        start = x[i]

        ndp = [0] * (n + 1)

        for open_groups in range(n + 1):
            cur = dp[open_groups]

            if cur == 0:
                continue

            if open_groups < need:
                continue

            nxt = open_groups - need + start

            ways = C[open_groups][need]

            ndp[nxt] = (ndp[nxt] + cur * ways) % MOD

        dp = ndp

    ans = dp[0] * fact[n] % MOD
    print(ans)

solve()
```実装の最初の部分では、階乗と二項係数を構築します。 以来`N ≤ 1000`、完全なパスカル三角形は完全に実現可能です。 

DP 状態は、ウォークスルーからの数学的解釈を直接反映します。`open_groups`すでに始めているが、まだ 2 番目の教室が必要なグループを表します。 

移行ロジックは重要な部分です。```
nxt = open_groups - need + start
```まずは閉めます`need`現在のルームで以前にグループを開いてから、このルームから新しく開始するグループを追加します。 

組み合わせ乗数```
C[open_groups][need]
```ここで終了する未完了のグループをカウントします。 

最終的な乗算`fact[n]`見逃しやすいです。 それがなければ、DP はグループを区別できないものとして扱います。 階乗は個別のアイデンティティを復元します。 

もう 1 つの微妙な詳細は、答えは次のとおりでなければならないということです。`dp[0]`。 すべてのルームを処理した後に未完了のグループがある状態は、2 番目のレッスンをホストする後続のルームが存在しないため、無効になります。

 ## 特殊なケース

 もう一度考えてみましょう:```
2
1 0
1 0
```ルーム 1 には、`need = 0`、部屋2にもあります`need = 0`。 

処理室 1 の後、1 つのグループが開きます。 部屋 2 は新しいグループを開始せず、受信グループも受け入れません。 唯一有効な解釈は、部屋 1 のグループがすでに部屋 1 で終了しているということです。 

DP は正確に 1 つの有効な構造で終了し、次の値を乗算します。`1!`まだ与える`1`。 

次に、次のことを調べます。```
2
1 1
1 1
```どの部屋もそれぞれの開始グループで満席です。 

DP 構造数は次のとおりです。`1`、部屋を越えた移動は不可能だからです。 乗算`2!`与える`2`、2 つのグループを正しく区別します。 

ついに：```
3
2 0 0
2 2 2
```ルーム 1 の 2 つのグループは、次のいずれかの終了ルームを独立して選択できます。`1,2,3`。 

DP は、各部屋の後に開いているグループの数のみを追跡し、正確にどのグループであるかは追跡しません。 二項係数はすべての構造的可能性を再構築し、最終階乗は個別の恒等性を復元します。 

この組み合わせこそが、このメソッドが正確さを失うことなく 1000 グループまで拡張できる理由です。
