 ## 解決策
 ## 問題の理解

 からの数値の順列が与えられます。`1`に`n`。 順列の場合`p`、 定義する$$\text{cost}(p)=\sum_{i=1}^{n} p_i \cdot i-\max_{i=1}^{n}(p_i\cdot i).$$タスクは、長さのすべての順列の中で、この式の可能な最大値を見つけることです。`n`。 

最初の項は加重合計であるため、大きなインデックスに大きな数値を配置することに報酬を与えます。 2 番目の項では、単一の最大の寄与が減算されます。 これら 2 つの目的は相互に競合します。 加重合計が大きくなるようにしたいのですが、最大の個別製品が優勢になりすぎないようにしたいと考えています。 

制約`n ≤ 250`は順列問題としては異常に小さいです。 すべての順列を総当りで検索することは不可能です。`n!`順列。 たとえ`n = 10`、すでに 300 万を超える順列があります。 一方、 の小さな値は、`n`ということを示唆している`O(n²)`あるいは`O(n³)`テストケースごとのソリューションは完全に受け入れられます。 

微妙な点は、加重和だけを最大化するのは簡単であるということです。 並べ替え不等式により、 の最大値は、$$\sum p_i i$$ソートされた順列によって取得されます`[1,2,...,n]`。 ただし、その配置では可能な限り最大の製品も作成されます`n²`、それから減算されます。 最適な答えは、これら 2 つの効果のバランスから導き出されます。 

考慮する`n = 4`。 

恒等置換により得られるのは、$$1\cdot1+2\cdot2+3\cdot3+4\cdot4=30$$そして最大積は`16`ですので、コストは`14`。 

最適な順列は次のとおりです。`[1,2,4,3]`、コストは`17`。 

重み付けされた合計を最大化するだけのソリューションでは、最適値を逃すことになります。 

もう 1 つの簡単な間違いは、最大の積がその位置で発生するはずだと仮定することです。`n`。 たとえば、`[1,4,2,3]`、最大の製品は`4·2 = 8`、必ずしも最後の位置ではありません。 正しい解は、最大積を明示的に計算する必要があります。 

## アプローチ

 最も直接的なアイデアは、すべての順列を列挙し、その加重和と最大の積を計算して、最良の答えを保持することです。 

これが機能するのは、コストの定義が単純であるためです。 固定順列の場合、式の評価には次の時間がかかります。`O(n)`時間。 

問題は順列の数です。 最悪の場合は検査が必要になる`250!`順列の数が非常に大きいため、完全に実行不可能です。 

重要な観察は、公式のソリューションが特別に構造化された順列の非常に小さな検索空間に依存しているということです。 

増加順列から始めるとします。$$[1,2,3,\dots,n].$$この構成により、加重和が最大化されます。 最大の積からのペナルティを減らすために、いくつかの大きな値を最大のインデックスから遠ざけることができます。 

注目すべき事実は、分割位置を選択することで常に最適な順列が得られることです。`k`そして建設中$$[1,2,\dots,k-1,n,n-1,\dots,k].$$接頭辞は増加し続けますが、接尾辞は反転します。 

以来`n ≤ 250`、考えられるすべての分割位置を試すことができます。 各候補の置換について、そのコストを直接計算し、最大値を取得します。 

あるのは`n`候補の順列、それぞれに必要なもの`O(n)`評価する仕事。

 | すべての順列に対するブルートフォース | お(ん・ん!) | O(n) | 遅すぎる |
 | 分割位置を列挙する | O(n²) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースごとに、答えをゼロに初期化します。 
2. スプリットポジションごとに`k`から`1`に`n`、順列を構築します。$$[1,2,\dots,k-1,n,n-1,\dots,k].$$3. 加重合計を計算します。$$\sum p_i\cdot i.$$4. すべての製品の最大値を計算します`p_i · i`。 
5. この順列のコストは、加重合計から最大の積を引いたものです。 
6. これまでに確認された最大コストを使用して回答を更新します。 
7. すべての分割位置を確認したら、答えを印刷します。 

### なぜ効果があるのか

 順列が増加すると、加重合計が最大になります。 加重和を失いすぎると損失が大きくなるため、最適な解はその配置に近いものでなければなりません。 

唯一の重要な自由は、最大積を減らすためにどの大きな値を最大のインデックスから遠ざけるかを決定することです。 サフィックスを反転すると、まさにそのトレードオフが実現します。 この問題に対する編集者の見解は、すべての最適解はこの接尾辞を逆転した順列のグループに属するということです。 

そのファミリーのすべてのメンバーを明示的に評価するため、見つかった最大コストが真の最適値となります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans_list = []

    for _ in range(t):
        n = int(input())
        best = 0

        for k in range(1, n + 1):
            p = list(range(1, k))
            p.extend(range(n, k - 1, -1))

            total = 0
            mx = 0

            for i, x in enumerate(p, start=1):
                prod = i * x
                total += prod
                if prod > mx:
                    mx = prod

            best = max(best, total - mx)

        ans_list.append(str(best))

    sys.stdout.write("\n".join(ans_list))

solve()
```外側のループはテスト ケースを反復します。 スプリットポジションごとに`k`、上記で説明した候補順列を生成します。 

コストの計算は 1 回のスキャンで行われます。 加重合計を累積し、同時に最大の積を追跡します。 

すべての候補者にわたる最大の回答が報告されます。 

この実装では、1 から始まるインデックスを使用します。`enumerate(..., start=1)`式では 1 から番号付けされた位置が使用されるためです。 

Python では整数オーバーフローは問題になりません。 加重合計の最大値は次のとおりです。$$250 \cdot 250^2 = 15{,}625{,}000,$$これは Python の整数制限に比べれば小さいものです。
