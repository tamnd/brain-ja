 ## 解決策
 ## 問題の理解

 長さの 2 つの配列が与えられます$n$、$a$そして$b$。 開始点によって定義された任意の連続したサブ配列またはセグメントの場合$l$そして終わり$r$、次の式を使用して「コスト」を計算できます。$|b_l - a_r| + |b_r - a_l|$。 目標は、合計の長さが正確に一致する、重複しないセグメントを選択することです。$k$、セグメントコストの合計を最大化します。 

セグメントのコストはセグメントの両端と両方の配列に依存するため、この問題は微妙です。 たとえば、単一の要素セグメントを取ると、$[i, i]$収量$|b_i - a_i| + |b_i - a_i| = 2|b_i - a_i|$。 より長いセグメントを選択するとクロスタームが発生します$|b_l - a_r|$そして$|b_r - a_l|$、最適化では、高コストのセグメントの選択と全長の制約のバランスをとる必要があります。$k$。 

制約は中程度です。$n$最大 3000 まで可能で、すべての合計$n$テスト ケース全体の数も最大 3000 です。これにより除外されます。$O(n^3)$アルゴリズムでは、考えられるすべての組み合わせに対してすべてのセグメントが試行されます。$3000^3$およそ 270 億のオペレーションです。 アン$O(n^2)$または$O(nk)$2 秒間に 900 万回の操作が許容されるため、このソリューションは実現可能です。 

セグメントが長くなると期間間の寄与が小さくなるため、長さ 1 のセグメントが最適な場合には、明らかではないエッジ ケースが発生します。 たとえば、次の場合$a = [1, 3]$そして$b = [4, 2]$そして$k=2$の場合、最適な選択は、長さ 2 の 1 つのセグメントではなく、長さ 1 の 2 つのセグメントである可能性があります。長いセグメントのみをチェックする不注意な実装では、最大値を見逃してしまいます。 

Another edge case is when arrays$a$そして$b$等しいです。 この場合、単一要素のコストはすべてゼロになり、最初のサンプルで見られるように、場合によってはすべての複数要素セグメントでもコストがゼロになることがあります。 私たちのアルゴリズムは、正のコストを想定せずに、ゼロコストのセグメントを正しく処理する必要があります。 

## アプローチ

 ブルートフォースアプローチでは、全長が$k$、コストを計算し、最大額を選択します。 各セグメントのコストの計算自体には時間がかかります$O(1)$ただし、すべての長さのすべてのセグメントを列挙すると、次のようになります。$O(n^2)$セグメントを分割し、すべての組み合わせをすぐに試してみると、$O(2^n)$、それは完全に不可能です。 

重要な洞察は、動的プログラミングの観点から考えることです。 定義しましょう$dp[i][len]$最初のパラメータを使用して取得できる最大コストとして$i$配列の要素と選択されたセグメントの合計長$len$。 ポジションごとに$i$、スキップするか、次へ進めます。$dp[i-1][len]$) またはで終わるセグメントを取ります$i$ある程度の長さの$j \le i$そのコストを追加します$dp[i-j][len-j]$。 このアプローチが機能するのは、セグメントのコストはセグメントの開始と終了のみに依存するためです。 中間要素は無関係です。 すべてのセグメントのコストを事前計算する$cost[l][r]$で$O(n^2)$許可します$dp$での移行$O(n^2)$、全体的な制約に適合します。 

この問題を古典的な「長さバジェットを持つ重複しないセグメントの最大合計」動的計画問題に変えることにより、探索空間を指数関数から二次関数に縮小します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n * n^2) | O(n^2) | 遅すぎる |
 | 動的プログラミング | O(n^2) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのセグメントのコストを事前計算します。 インデックスのペアごとに$l \le r$、計算する$cost[l][r] = |b_l - a_r| + |b_r - a_l|$。 これは次の場合に実現可能です$O(n^2)$時間だから$n \le 3000$。 これを 2D 配列に保存すると、$O(1)$DP 中のルックアップ。 
2. DP テーブルの初期化$dp[i][len]$どこ$dp[i][len]$最初のパラメータを使用して達成可能な最大コストを表します。$i$セグメントの合計長を持つ要素$len$。 を除くすべてのエントリを負の無限大として開始します。$dp[0][0] = 0$。 
3. 位置を反復処理する$i$1から$n$。 それぞれについて$i$、全長を反復処理します。$len$0から$k$。 以前の最大値を繰り越します。$dp[i][len] = dp[i-1][len]$。 
4. 考えられる各セグメント長について$seg$1から$\min(i, len)$で終わるセグメントの使用を検討してください。$i$長さの$seg$。 アップデート$dp[i][len] = \max(dp[i][len], dp[i-seg][len-seg] + cost[i-seg+1][i])$。 
5. すべてのポジションを処理した後、$dp[n][k]$全長に対する最大コストが含まれます$k$。 

なぜ機能するのか: DP は次の不変条件を維持します。$dp[i][len]$常に最初の最適な合計を保存します$i$要素と全長$len$。 考えられるすべての最後のセグメントの長さを考慮すると、実行可能なすべての組み合わせが確実に考慮されます。 で終わるセグメントのみを考慮するため、重複しないことが自然に強制されます。$i$そのセグメントの前の要素の DP を使用します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        
        # Precompute costs
        cost = [[0]*n for _ in range(n)]
        for l in range(n):
            for r in range(l, n):
                cost[l][r] = abs(b[l] - a[r]) + abs(b[r] - a[l])
        
        # DP initialization
        dp = [[-float('inf')] * (k+1) for _ in range(n+1)]
        dp[0][0] = 0
        
        for i in range(1, n+1):
            for length in range(k+1):
                dp[i][length] = dp[i-1][length]  # skip i-th element
                for seg in range(1, min(i, length)+1):
                    dp[i][length] = max(dp[i][length],
                                        dp[i-seg][length-seg] + cost[i-seg][i-1])
        print(dp[n][k])

if __name__ == "__main__":
    solve()
```コードは、再計算を避けるために、最初にすべてのセグメントのコストを事前計算します。 DP テーブル`dp[i][length]`DP 状態は常に現在のセグメントの前の要素を参照するため、オーバーラップしないセグメントを自然に処理します。 長さ 1 のセグメントの取得や最初の要素への到達などのエッジ条件は、Python リストには 0 からインデックスが付けられており、DP では`i-seg`セグメントの前の状態を参照します。
