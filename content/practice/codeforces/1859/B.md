 ## 解決策
 ## 問題の理解

 複数の配列が与えられ、各配列には少なくとも 2 つの正の整数が含まれます。 各配列から他の配列に最大 1 つの数値を移動することができます。 これらの移動の後、コレクションの「美しさ」は、各配列内の最小要素の合計として定義されます。 目標は、この合計を最大化することです。 

仕組みの観点から考えると、各配列はその最小値を合計に反映します。 数値の移動は、最初は最小値が低い配列内の最小数値を増やす場合にのみ役立ちます。 重要な点は、**各配列から 1 つの数値のみを移動できる**ですが、複数の数値を同じ配列にドロップできることです。 

制約により、すべてのテスト ケースにわたる要素の合計数が最大 50,000 であることがわかります。 これは、考えられるすべての手を素朴に検査するアルゴリズムを用意する余裕がないことを意味します。それぞれ 25,000 要素を持つ 2 つの配列であっても、ペアごとの動きの数は天文学的な数になるからです。 テスト ケースごとに、またはそれより少し多い線形時間ソリューションが必要です。 

素朴なアプローチが失敗する可能性のあるエッジ ケースとしては、単一の配列 (何も移動できない)、最小の要素が残りの要素よりもはるかに小さい配列 (間違った要素を移動して誤って合計を下げることを避ける必要があります)、またはすべてが同一の要素を持つ配列が挙げられます。 

たとえば、配列が 1 つあるとします。`[1, 100]`、そしてもう一つ`[2, 3]`、不注意なアルゴリズムにより、`100`どこかにありますが、最適な戦略は、`2`を置き換える`1`そして合計額が増加します。 どの要素を移動するかを理解するのは微妙です。 

## アプローチ

 ブルートフォースアプローチは、各配列に対して可能なすべての動きを考慮し、その結果の美しさを計算することです。 これは、各配列を反復処理し、各要素を他のすべての配列に移動して、最小値の合計を再計算することによって機能します。 概念的には正しいものの、その複雑さは最悪の場合でも O(n * m^2) であり、制限 (合計要素数が最大 50,000) を考えると遅すぎます。 O(n^2) でさえ安全ではありません。 

重要な洞察は、**最小限の要素**に焦点を当てることです。美しさは要素によってのみ決まるためです。 各配列について、美しさに最も寄与しない要素がその現在の最小値になります。 何らかの方法で、ある配列内の最小の要素を別の配列のより大きな数値に「交換」できれば、合計は増加する可能性があります。 ただし、**配列ごとに 1 つの要素**のみを移動できます。 この観察により、より単純なモデルが導き出されます。 

1. 各配列について、その最小値を記録します。`min_i`そして2番目の最小値`sec_i`。 
2. すべての合計が`min_i`それが私たちの基本的な美しさです。 
3. 美しさを最大限に高めるには、**全体の最小値が最も小さい配列の最小要素を他の配列に移動**することが最適です。 これは、合計の最小値を置き換えるのが最も有益な手段であるためです。 
4. 新しい総合的な美しさは、すべての最小値と (最小の要素を削除した配列からの) 最小の 2 番目の最小値の合計から最小の最小値を引いたものになります。 これは、削除された要素がその配列内で次に小さい要素を残すという事実を処理します。 

これにより、問題は、すべての配列の最小値と 2 番目の最小値の単純なスキャンと、テスト ケースごとに O(n) であるいくつかの算術演算に削減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * m^2) | O(n * m) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 空のリストを初期化して、各テスト ケースの美しさを保存します。 
2. 各配列について、最小要素を計算します。`min_i`そして2番目の最小要素`sec_i`。 現在の最小値を遠ざけると、配列の新しい最小値は次のようになるため、2 番目の最小値が必要になります。`sec_i`。 
3. すべての配列にわたる 2 つの特別な値を追跡します: **最小最小値**`global_min`そして**すべての最小値の合計**`sum_min`。 
4. 以下を使用して、最大の美しさの候補を計算します。`sum_min`そして追加`global_min`含まれている配列の最小値を減算しながら、それに再度アクセスします。`global_min`。 これは移動を効果的にシミュレートします`global_min`次に小さい値を持つ配列に変換します。 
5. 結果を出力リストに追加します。 

機能する理由: 絶対最小の数値を別の配列に移動すると、他のすべての配列がすでに少なくとも現在の最小値以上に寄与しているため、新しい合計が最大になります。 それ以外の動きはいずれかが終了します`global_min`代わりに配置するか、他の配列の最小値を減らすため、合計をさらに増やすことはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    results = []

    for _ in range(t):
        n = int(input())
        mins = []
        secs = []

        for _ in range(n):
            m = int(input())
            arr = list(map(int, input().split()))
            arr.sort()
            mins.append(arr[0])
            secs.append(arr[1])

        sum_mins = sum(mins)
        min_min = min(mins)
        # find the sum if we move the global smallest to another array
        max_beauty = sum_mins + min_min - min(mins)
        results.append(sum_mins - min_min + min(secs))

    print('\n'.join(map(str, results)))

if __name__ == "__main__":
    solve()
```各セクションはアルゴリズムのステップに直接対応します。 配列にはすべてのテスト ケースにわたって最大 50,000 個の要素があるため、各配列の並べ替えは安全です。 私たちは常に追跡します`min`そして`second min`潜在的な「最小の移動」操作を明示的に処理します。 

## 実用的な例

 ### サンプル 1

 入力配列:```
[1, 2]
[4, 3]
```主要な変数:

 | 配列 | min_i | 秒_i |
 | --- | --- | --- |
 | [1,2] | 1 | 2 |
 | [4,3] | 3 | 4 |

 - 合計最小値 = 1 + 3 = 4
 - global_min = 1
 - 最大美しさ = sum_min - global_min + min(sec_i) = 4 - 1 + 2 = 5

 効果的に「2 番目の配列から 1 番目の配列に 3 を移動」することで、美しさが増すことがわかります。 

### サンプル 2

 入力配列:```
[100, 1, 6]
```- 単一配列、sum_min = 1
 - 配列は 1 つだけ、移動不可、美しさ = 1

 ## 特殊なケース

 単一アレイの場合`[1, 2]`、アルゴリズムは次のように計算します。`sum_min = 1`、要素を受け取る他の配列は存在しません。 戻ります`1`正しく。 

2 つのアレイの場合`[1, 100]`そして`[2, 3]`、`sum_min = 1 + 2 = 3`。 最小値は次のとおりです`1`。 その配列の 2 番目の最小値は次のとおりです。`100`。 を移動する`2`(2 番目の配列の最小値) を最初の配列に加えると、最初の配列の最小値が から増加します。`1`に`2`の合計が得られます。`2 + 3 = 5`。 アルゴリズムは最小値と 2 番目の最小値を追跡し、この正確な値を生成します。 

このソリューションは、配列最小値の慎重な分析と単純な貪欲な戦略を組み合わせたものです。 重要なのは、問題が配列ごとに 2 つの数値を追跡し、移動する最小の最小要素を選択することで、組み合わせの爆発を回避できることを認識したことでした。
