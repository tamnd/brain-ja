 ## 解決策
 ## 問題の理解

 私たちは、アンドレイがポータルを繰り返し使用できる 1 次元の世界で避難経路をモデル化するように求められます。 各ポータルはセグメントです`[l_i, r_i]`アンドレイはそこから入って、含まれている別のセグメントにテレポートできます`[a_i, b_i]`。 目標は、さまざまな位置から開始して、アンドレイが到達できる最も遠い座標を決定することです。 入力では複数のテスト ケースが提供され、それぞれに一連のポータルと一連の開始点が含まれます。 

制約はかなり大きいです。 各テスト ケースには最大で次のものを含めることができます`2 * 10^5`ポータルとポジション、およびすべてのテスト ケースの合計も超えることはできません。`2 * 10^5`。 最大の座標は次のとおりです。`10^9`、数直線全体をシミュレートすることは現実的ではありません。 内のすべての位置を反復するソリューション`[l_i, r_i]`各ポータルでは遅すぎるでしょう。 開始点ごとにすべてのポータルを繰り返しチェックするという単純なアプローチでは、次のような結果が得られます。`O(n * q)`テスト ケースごとの操作数は最大で`4 * 10^10`- 2 秒の制限には明らかに大きすぎます。 ポータル効果を効率的に集約し、複数の開始位置に対する素早いクエリをサポートする方法が必要です。 

ポータルが重複すると、明らかではないエッジ ケースが発生し、1 つのポータルを使用すると他のポータルへのアクセスが開かれるチェーンが作成されます。 たとえば、あるポータルがからテレポートする場合、`[1, 3]`に`[5, 6]`別のポータルは次から始まります`[5, 6]`に行く`[10, 10]`、から始まります`2`両方のポータルを順番に使用する必要があります。 開始位置からの直接のポータル ジャンプのみを考慮する単純な実装では、誤ったレポートが発生します。`6`の代わりに`10`。 同様に、どのポータル セグメントにもない位置から開始すると、ゼロやエラーではなく、開始点自体が生成されるはずです。 

## アプローチ

 ブルートフォースアプローチは簡単です。 クエリの開始点ごとに、すべてのポータルを繰り返しスキャンし、さらにジャンプできるポータルを確認し、ジャンプできなくなるまで現在の位置を更新します。 この問題によりポータルの無制限の使用が許可されるため、これは機能しますが、その複雑さは次のとおりです。`O(n * q)`そして打つことができる`4 * 10^10`最悪の場合、許容できないほど遅くなります。 

最適化するための重要な観察は、各ポータルが到達可能な座標のセグメントを圧縮していると考えることができるということです。 ポータルを左端点で並べ替え、重複するポータルを貪欲にマージすると、内部の任意の位置から到達可能な最大の座標を表す重複しないセグメントのセットを維持できます。 基本的に、これにより問題は区間マージとそれに続く二分探索クエリに集約されます。開始位置について、それが属するマージされた区間を見つけて、その区間から到達可能な最も遠い点を出力します。 

この観察が機能するのは、ポータル チェーンが常に右方向に移動するか、すでに到達可能な範囲内に位置を維持するためです。 ポータルを順番に処理し、最大の到達可能性を伝播することにより、少なくとも 1 つのポータルがカバーするすべてのポイントの最遠の目的地を事前に計算できます。 その後、クエリはこれらの間隔にわたる対数検索に縮小されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * q) | O(n) | 遅すぎる |
 | 最適 | O(n log n + q log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 現在のテスト ケースのすべてのポータルを読み取り、解析します。 各ポータルをタプルとして保存する`(l_i, r_i, a_i, b_i)`。 ポータルを左側のエンドポイントで並べ替えます`l_i`。 ソートにより、間隔を順番に処理し、重複する到達可能性を効率的にマージできます。 
2. 空のリストを初期化する`merged_intervals`タプルを保存します`(start, end)`ポータルを使用して到達可能な数直線のセグメントを表します。 各間隔も追跡します`max_reach`- アンドレイがその間隔内のどこからでも到達できる最も遠い座標。 
3. ソートされたポータルを繰り返し処理します。 ポータルごとに`(l_i, r_i, a_i, b_i)`の最後の間隔と重なっているかどうかを確認します。`merged_intervals`。 その場合は間隔を延長してください`max_reach`に`max(previous_max_reach, b_i)`間隔のエンドポイントを次のように延長します`max(previous_end, r_i)`。 重複しない場合は、次のコマンドで新しい間隔を開始します。`max_reach = b_i`。 これにより、マージされたすべての間隔が、Andrey が開始して最終的に到達できる連続した領域を表すことが保証されます。`max_reach`座標。 
4. 各クエリ位置について`x`、二分探索を実行します。`merged_intervals`を含む間隔を見つけるには`x`。 見つかった場合は、間隔を出力します。`max_reach`。 もし`x`どの区間にも当てはまらない、出力`x`自体。 二分検索により、各クエリが確実に実行されます。`O(log n)`。 
5. すべてのテスト ケースに対して手順 1 ～ 4 を繰り返します。 

機能する理由: マージされた間隔の不変条件により、マージされた間隔内のどの位置でも、ポータルを最適に使用することで、その範囲を超えることがないことが保証されます。`max_reach`記録された。 並べ替え順`l_i`重複する間隔が正しくマージされ、到達可能なポイントが見逃されないことが保証されます。 ポータルでは含まれるセグメント内での移動のみが許可されるため、`max_reach`伝播は、ポータルの使用チェーンを正しくモデル化します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import bisect

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        portals = []
        for _ in range(n):
            l, r, a, b = map(int, input().split())
            portals.append((l, r, a, b))
        portals.sort()
        
        merged_intervals = []
        for l, r, a, b in portals:
            if not merged_intervals:
                merged_intervals.append([l, r, b])
            else:
                last_l, last_r, last_b = merged_intervals[-1]
                if l <= last_r:
                    merged_intervals[-1][1] = max(last_r, r)
                    merged_intervals[-1][2] = max(last_b, b)
                else:
                    merged_intervals.append([l, r, b])
        
        starts = [interval[0] for interval in merged_intervals]
        
        q = int(input())
        x_list = list(map(int, input().split()))
        res = []
        for x in x_list:
            idx = bisect.bisect_right(starts, x) - 1
            if idx >= 0 and merged_intervals[idx][0] <= x <= merged_intervals[idx][1]:
                res.append(merged_intervals[idx][2])
            else:
                res.append(x)
        print(' '.join(map(str, res)))

if __name__ == "__main__":
    solve()
```このソリューションでは、最初にポータルを並べ替え、重複する間隔をマージして、最大到達可能性を事前計算します。 間隔の開始点での二分探索により、各クエリの正しい間隔が効率的に見つかります。 開始位置がポータルの外側にあるようなエッジケースに対処するには、細心の注意が必要です。 その場合、正解は開始位置そのものです。
