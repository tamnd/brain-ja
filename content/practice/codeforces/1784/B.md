 ## 解決策
 ## 問題の理解

 各人は次から選択したちょうど 3 つの文字で始まります。`w`、`i`、 そして`n`。 すべての人を合わせると、まさに`m`各手紙のコピーがあるため、世界的に供給はすでにバランスが取れています。 唯一の問題は、手紙が個人間で不均等に配布されていることです。 

交換は2名を選択します。 それぞれが 1 通の手紙を渡し、もう 1 通の手紙を受け取ります。 一連の交換の後、各人は最終的に 1 つだけを保持する必要があります。`w`、 1つ`i`、そして1つ`n`。 すべての有効な解のうち、最小限の交換数を使用して 1 つを出力する必要があります。 

人物について考える最も便利な方法は、文字列内の文字の順序ではなく、文字数に基づいて考えることです。 例えば、`"wwi"`この人は2つ持っていることを意味します`w`、 1つ`i`、いいえ`n`。 そういう人は1つ余る`w`そして1つ欠けています`n`。 

この制約により、検索ベースのアプローチは即座に除外されます。 テスト ケースには最大で次のものを含めることができます。`10^5`すべてのテスト ケースの合計も`10^5`。 取引相手を探しているすべての人々を繰り返しスキャンするアルゴリズムは、簡単に二次関数になってしまいます。 線形時間に近いものが必要です。 

微妙な点は、交換は最小限にする必要があるということです。 有効な再配布を行うだけでは十分ではありません。 私たちは赤字と黒字の構造を利用して、すべての取引所が可能な限り修正されるようにしなければなりません。 

見落としやすいエッジケースの 1 つは、交換が必要ない場合です。 

入力：```
2
nwi
inw
```二人ともすでにそれぞれの手紙を 1 つずつ持っています。 正しい答えは次のとおりです。```
0
```すでにバランスが取れているかどうかを確認せずに、全員を盲目的に取引構造に配置する実装では、不要な交換が出力される可能性があります。 

もう 1 つの重要なケースは、2 人がお互いの問題を直接解決できる場合に発生します。 

入力：```
2
wwi
inn
```人 1 は追加のものを持っています`w`そして欠けています`n`。 人 2 は追加のものを持っています`n`そして欠けています`w`。 1 回の交換で十分です。```
1
1 w 2 n
```2 つの交換を使用する解決策はどれも有効ですが、最小限ではありません。 

最後のトリッキーなケースは 3 サイクルです。 

入力：```
3
wwi
iin
nnw
```赤字は次のように形成されます。`wwi`： 余分な`w`、ニーズ`n`

`iin`： 余分な`i`、ニーズ`w`

`nnw`： 余分な`n`、ニーズ`i`どのペアもお互いを直接修復することはできません。 お互いの修正だけを求める不用意な欲張りは行き詰まってしまうでしょう。 最適解には 2 回の交換が必要です。 

## アプローチ

 ブルートフォース戦略では、交換によって状況が改善する 2 人を繰り返し検索します。 各個人を他の多くの個人と比較する必要がある場合があるため、これにはすぐにコストがかかります。 と`10^5`人々、たとえ`O(m²)`アプローチには前後が必要です`10^10`まったく実行不可能な操作です。 

重要な点は、使用可能な文字タイプが次の 3 つだけであるということです。`w`、`i`、 そして`n`。 この 3 つの文字の数によって、その人を完全に説明できます。 各カウントは間にあるため、`0`そして`3`そして合計は常に`3`、可能なカウント パターンは 10 個だけです。 

すべての人について、どの文字が余っていて、どの文字が欠けているかを識別できます。 誰かが手紙のコピーを 2 つまたは 3 つ持っている場合は、その手紙を寄付することができます。 誰かが手紙のコピーを持っていない場合、その手紙が必要になります。 

1人が余剰を持っていると仮定します`w`そして欠けています`i`、もう一方は余剰を持っています`i`そして欠けています`w`。 1 つの取引所で両方の欠点がすぐに修正されます。 1 回の操作で 2 つの欠落文字を同時に解決できるため、このような交換は常に最適です。 

可能なすべての直接交換を実行した後、残った不均衡のみが 3 つの文字タイプ間で有向サイクルを形成します。 文字が 3 つしかないため、残りのすべてのサイクルの長さは 3 になります。`w → i → n → w`または`w → n → i → w`3 人が関与するサイクルでは、ちょうど 2 回の交換が必要です。 3 つの赤字が残り、1 つの交換で最大 2 つの赤字を解消できるため、これも最適です。 

文字タイプの数が少ないため、インデックスが付けられたバケットに人々を保存できます。`(surplus letter, missing letter)`。 そうすれば、すべての操作はバケット間の一定時間の移動になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(㎡) | O(m) | 遅すぎる |
 | 最適 | O(m) | O(m) | 承認済み |

 ## アルゴリズムのチュートリアル

 文字に次のようにインデックスを付けます。`0 = w`、`1 = i`、`2 = n`。 

すべての人について、各文字の数を計算します。 

バケットの作成`pos[a][b]`、 どこ`a`余った手紙であり、`b`は文字が抜けています。 複数の余剰コピーと複数の紛失した手紙がある場合、その人は複数のバケットに表示されることがあります。 

バケット エントリごとに、個人のインデックスを保存します。 

### 1. すべての人を分類する

 すべての人について、カウントが 1 より大きい文字をすべて検索し、カウントが 0 の文字をすべて検索します。 

すべてのペアについて`(surplus, missing)`、その人をバケツに入れます`pos[surplus][missing]`。 

カウントのある人`(3,0,0)`は、2 つの異なる不足している手紙を満たすために同じ余剰の手紙を寄付できるため、2 つのバケット エントリを寄付します。 

### 2. すべての直接交換を実行します。 

順序付けられた個別の文字のペアごとに`(a,b)`、からの人物と繰り返し一致します`pos[a][b]`からの人と`pos[b][a]`。 

最初の人が手紙を渡します`a`、2番目は手紙を与えます`b`。 

二人とも不足している 1 つの文字をすぐに修正するため、1 回の交換で 2 つの不足が解決されます。 

両方の参加者をバケットから削除し、操作を記録します。 

### 3. 3 サイクルを解決する

 すべての直接一致がなくなると、循環依存関係だけが残ります。 

サイクルを考えてみましょう。`a → b`、`b → c`、`c → a`から1名を選択してください`pos[a][b]`、からの 1 つ`pos[b][c]`、およびからの 1 つ`pos[c][a]`。 

実行:

 1. 1人目と2人目の交換。 
2. 1人目と3人目の交換。 

これら 2 つの交換により、サイクル全体が排除されます。 

対応するバケットが空になるまで繰り返します。 

考えられる両方のサイクル方向に対してこれを実行します。 

### 4. 記録されたすべてのやり取りを出力します。 

記録される操作の数は最小限であるため、交換後に印刷してください。 

### なぜ効果があるのか

 各欠損は、余剰文字から欠落文字への有向エッジに対応します。 

間の直接のやりとり`a→b`そして`b→a`1 回の操作で 2 つの反対側のエッジを削除します。 1 つの取引所では 2 つ以上の赤字を解消できないため、これ以上の解決策はありません。 

すべての反対のペアが削除された後、各文字の合計数はすでにグローバルに正しいため、残りのすべての頂点の入力と出力の不均衡は等しくなります。 文字タイプが 3 つだけの場合、残りのグラフは有向 3 サイクルのみで構成されます。 

有向 3 サイクルには 3 つの欠損が含まれます。 1 回の交換で最大 2 つの不足を解消できるため、少なくとも 2 回の交換が必要です。 上記の構築では、ちょうど 2 つを使用しています。 

すべての操作は、それが解決する構造に対して最適であるため、交換の総数は最小限で済みます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    mp = {'w': 0, 'i': 1, 'n': 2}
    rev = ['w', 'i', 'n']

    out = []

    for _ in range(t):
        m = int(input())

        pos = [[[] for _ in range(3)] for _ in range(3)]

        for idx in range(1, m + 1):
            s = input().strip()

            cnt = [0, 0, 0]
            for ch in s:
                cnt[mp[ch]] += 1

            surplus = []
            missing = []

            for c in range(3):
                if cnt[c] > 1:
                    surplus.extend([c] * (cnt[c] - 1))
                elif cnt[c] == 0:
                    missing.append(c)

            for a in surplus:
                for b in missing:
                    pos[a][b].append(idx)

        ans = []

        def direct(a, b):
            while pos[a][b] and pos[b][a]:
                x = pos[a][b].pop()
                y = pos[b][a].pop()
                ans.append((x, rev[a], y, rev[b]))

        for a in range(3):
            for b in range(a + 1, 3):
                direct(a, b)

        cycles = [
            (0, 1, 2),
            (0, 2, 1),
        ]

        for a, b, c in cycles:
            while pos[a][b] and pos[b][c] and pos[c][a]:
                x = pos[a][b].pop()
                y = pos[b][c].pop()
                z = pos[c][a].pop()

                ans.append((x, rev[a], y, rev[b]))
                ans.append((x, rev[a], z, rev[c]))

        out.append(str(len(ans)))
        for x, ca, y, cb in ans:
            out.append(f"{x} {ca} {y} {cb}")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```分類フェーズでは、各人物を余剰文字と欠落文字に変換します。 カウントのある人`(2,1,0)`1 つのバケット エントリに貢献し、カウントを持っている人が`(3,0,0)`最終的に 2 つのコピーを転送する必要があるため、2 つのバケット エントリが提供されます。 

直接一致フェーズは、最小化議論の中心です。 反対の赤字が存在する場合は常に、1 つの取引所が両方を同時に修正します。 このような試合を遅らせることは決して助けにはなりません。 

サイクルフェーズは、すべての反対のペアが消滅した後にのみ実行されます。 その時点で、残りの構造は強制的に 3 サイクルになります。 この実装では、記録された操作を 2 つだけ使用して、一度に 1 つの完全なサイクルを削除します。 

よくある間違いは、1 つだけを保存することです`(surplus, missing)`お一人様ペア。 誰かが抱いている`"www"`余分なコピーが 2 つありますが、2 つの異なる文字がありません。 両方の赤字を表現する必要があります。 すべての余剰文字と欠落文字に対するネストされたループは、これを正しく処理します。
