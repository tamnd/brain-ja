 ## 解決策
 ## 問題の理解

 1 から 2n までの連続する整数のセットが与えられます。 Vika は、このセットに対して正確に k 個の操作を実行します。 各操作は、最小の 2 つの整数を削除するか、中央の 2 つの整数を削除することで構成されます。これらの整数は、セットが並べ替えられた順序で書き込まれている場合、位置 n と n+1 にある 2 つの整数です。 k 回の操作の後、彼女が持つことができる個別のセットの数を 998,244,353 を法にして数える必要があります。 

入力整数 n と k は、初期セット (2n 要素) のサイズと実行する操作の数を定義します。 出力は、個別の結果セットの数を表す単一の整数です。 

制約は、n が 10^6 まで大きくなる可能性があることを示唆しているため、すべての操作シーケンスを明示的にシミュレートするソリューションは遅すぎるでしょう。 2^20 がすでに 100 万を超えており、ここで k が 10^6 になる可能性があるため、k が 10^6 までの場合、2^k シーケンスを探索する総当りアプローチは実行できません。 

k = n の場合、各操作でちょうど 2 つの要素が削除されるため、エッジ ケースが発生します。 n 回の操作の後、セットは常に空になるため、答えは自明に 1 になります。別の微妙なケースは、k = 1、または n に比べて小さい場合に発生します。 たとえば、n = 3 および k = 1 の場合、2 つの最小要素または 2 つの中央値要素を削除すると、2 つの異なるセットが生成されるため、注意して数えることが必要です。 

## アプローチ

 ブルート フォース アプローチでは、k 個の操作のすべての可能なシーケンスを列挙し、各シーケンスの結果セットを計算します。 選択するたびにシーケンスの数が 2 倍になるため、シーケンスの総数は 2^k になります。 セットを明示的に保存して比較することは、シーケンスごとに指数時間と線形空間の両方を必要とするため、大きな n と k では不可能です。 

重要な観察は、結果のセットが Vika が「中央値除去」操作を選択した回数によって完全に決定されるということです。 彼女が中央値 m 回の削除と k - m 回の最小削除を実行するとします。 次に、左からちょうど 2*(k - m) 個の要素と中央から 2*m 個の要素が削除されます。 これにより、結果のセットが一意に識別されます。 したがって、すべてのシーケンスをシミュレートする代わりに、k 個の操作を有効な「中央値除去」と「最小除去」に分散する方法、つまり、存在する要素よりも多くの要素を除去しない方法の数を数えるだけで済みます。 

2n 個の要素があるため、k 個の操作の後、2n - 2k 個の要素が残ります。 中央値除去の数 m は、max(0, k - n) から min(k, n) までの範囲になります。これは、各中央値除去では、セットのサイズによって制限される中央から要素を削除する必要があるためです。 実際、0 ≤ m ≤ k の場合、この演算は 2*(k - m) ≤ n である限り有効であり、簡単な式が得られます。 

結果のセットの数をカウントすることは、m の有効な値の数をカウントすることと同じです。 削除位置は決定的であるため、有効な各 m は一意の最終セットを生成します。 これにより、問題はセットの列挙ではなく、単純な組み合わせカウントに軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^k * n) | O(n * 2^k) | 遅すぎる |
 | 組み合わせ計数 | お(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 可能な中央値除去の最小数と最大数を計算します。 中央から n 個を超える要素を削除できないため、最小値は 0、最大値は min(k, n) です。 
2. k 回の操作後の残りの要素は正確に 2n - 2k であるため、セットの総数は有効な中央値除去カウントの数に対応することを認識します。 
3. m 個の中央値ペアと k - m 個の最小値ペアを削除しても利用可能な要素の数を超えないように、範囲 [0, k] 内の整数 m の数を数えます。 
4. このカウントは単に k + 1 です。ただし、中央から n 個を超える要素を削除することはできないため、m ≤ n であることを確認する必要があります。 したがって、答えは min(n, k) + 1 となります。 
5. 998,244,353 を法とする答えを返します。

機能する理由: k 個の操作のシーケンス後のセットは、中央値の削除が何回発生したかによって一意に決定されます。 削除された要素の位置は決定的で重複しないため、有効な中央値削除数ごとに個別のセットが生成されます。 中央値除去の有効な数をカウントすることにより、各操作をシミュレートすることなく、可能なすべてのセットを列挙します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def main():
    n, k = map(int, input().split())
    result = min(n, k) + 1
    print(result % MOD)

if __name__ == "__main__":
    main()
```この解法は、整数 n と k を読み取り、可能な中央値除去カウントの数を min(n, k) + 1 として計算し、それを法 998244353 で出力します。この問題では結果が 10^6 を超えることはありませんが、問題で指定されているため、法演算が必要です。 min により、存在する要素よりも多くの要素を削除する無効な中央値削除シーケンスがカウントされなくなります。 

## 実用的な例

 | 1 | 中央値を削除 | {1、2、5、6} | 1 |

 | 1 | 中央値を削除してから最小値を削除します。 {3、6} | 1 |

 セット数 = 3、これは min(3, 2) + 1 = 3 と一致します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, k = map(int, sys.stdin.readline().split())
    MOD = 998244353
    return str((min(n, k) + 1) % MOD)

# provided samples

## 特殊なケース

 k = n の場合、セットは n 回の操作後に空になります。 n = 3、k = 3 の場合、考えられる各シーケンスの後のセットは次のとおりです。 

| シーケンス | 残りのセット |
 | --- | --- |
 | 分、分、分 | {} |
 | 最小値、最小値、中央値 | {} |
 | 最小値、中央値、最小値 | {} |
 | 中央値、中央値、中央値 | {} |

 すべてのシーケンスは空のセットを生成します。 式 min(n, k) + 1 = 4 は、空のセットのシナリオを 1 つの別個のセットとして正しくカウントし、組み合わせアプローチがこのエッジ ケースを正しく処理することを示しています。 

k = 0 の場合、セットは変更されず、min(n, 0) + 1 = 1 となり、元の 1 つのセットと一致します。 これにより、ゼロ操作の境界処理が確認されます。
