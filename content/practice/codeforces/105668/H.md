 ## 解決策
 ## 問題の理解

 コンテナのコレクションが与えられます。各コンテナには、ターゲット コンテナ インデックスによってラベル付けされたビー玉が最初に保持されます。 すべてのコンテナには最初にちょうど 1 つのビー玉がありますが、ビー玉は必ずしも正しい場所にあるとは限りません。 目標は、各コンテナが最終的にそれに属するビー玉を保持できるようにシステムを変換することです。つまり、コンテナ i は最終的にビー玉 i にのみ関連付けられる必要があります。 

2 つの操作が可能です。 1 回の操作で 2 つのコンテナーの内容が交換されます。 2 番目の操作では、ビー玉をあるコンテナから別のコンテナにマージし、ビー玉を効果的に移動し、場合によってはコンテナを空にします。 タスクは、最小限の操作を使用して正しい最終構成に到達することです。 

主な問題点は、マージ操作ではシステムに「存在する」ものの構造が変更されるのに対し、スワップ操作では宛先が再配置されるだけであることです。 これは、ソリューションが純粋に並べ替えに関するものではなく、同一構造のコンポーネントがどのように相互作用するかを制御するものであることを意味します。 

入力サイズが十分に大きいため、コンテナーまたは構成に対する二次シミュレーションまたは状態シミュレーションのアプローチは実行できません。 スワップを繰り返しシミュレートしたり、進化する構造上で到達可能性を再計算したりするソリューションは、制限時間を超えてしまいます。 構造は、ほぼ線形または対数時間で更新できるグラフ コンポーネント、サイクル、関数マッピングなどに圧縮する必要があります。 

いくつかの危険な状況は、早めに切り分ける価値があります。 

すべてのターゲット値が異なる場合、マージはまったく行われず、問題はスワップを使用した順列のソートに帰着します。 たとえば、c = [2, 3, 1] の場合、構成は長さ 3 の単一サイクルであり、唯一の意味のある操作は、すべてが固定点になるまでサイクルをブレークするためのスワップです。 

多くの値が同一である場合、マージは強力になります。 たとえば、c = [1, 1, 1, 1] では、すべてのビー玉を積極的に統合でき、マージされた代表を通じてすべてをリダイレクトできるため、スワップ構造が簡単になります。 

スワップ後のマージが「遅れて」適用されると、微妙な障害が発生し、冗長な操作が発生する可能性があります。 もう 1 つは、同じ値の異なる代表にマージすると、誘導されたグラフの構造が変化する場合で、一貫して処理しないと、スワップ コストが静かに増加する可能性があります。 

## アプローチ

 マージを無視すると、問題は古典的な順列修正タスクになります。 各コンテナは正確に 1 つのターゲットを指し、すべてのノードが出次数 1 を持つ関数グラフを形成します。 これは、ばらばらのサイクルに分解されます。 2 つの要素間のスワップは、それらの出力エッジを効果的に交換し、適用される場所に応じてサイクルを分割したり、サイクルをマージしたりすることができます。 

純粋な順列設定では、目標はすべてのサイクルを自己ループに分割することです。 サイクルの長さが k の場合、完全に解決するには、慎重に選択された k − 1 回のスワップが必要です。 これにより、総コスト n からサイクル数を引いた値が得られます。 

重複したターゲット値が存在する場合、困難が始まります。 複数のコンテナが同じ宛先に対応するようになり、マージによりこれらの重複がどこに固定されるかを選択できるようになりました。 インデックスごとに 1 つのノードの代わりに、同じ値を共有するインデックスのグループという観点から考えることができ、各グループ内のどの代表がその値のアクティブな「アンカー」になるかを決定できます。 

強引なアイデアは、マージ先の可能な選択肢をすべて試してから、誘導された関数グラフを再構築してサイクルをカウントすることによって、結果として得られるスワップ コストを計算することです。 各グループが異なるアンカー コンテナを選択できる可能性があるため、重複グループの数は指数関数的に増加します。 中程度のnでもこれは不可能です。

重要な構造的洞察は、スワップの前にマージを順序付けることができ、すべてのマージが修正されると、スワップの問題は再び機能グラフに帰着するということです。 各値グループは単一の頂点となり、エッジはグループからそのターゲットを含むグループを指します。 残る唯一の問題は、この誘導グラフが何サイクル保存できるかということです。 

この圧縮が完了すると、スワップ コストはこのグループ グラフ内のコンポーネントの数にのみ依存します。 各サイクルは、チェーンと比較して 1 単位の節約に貢献し、最適な動作は、発信エッジを一貫して揃えるマージ代表を選択することでサイクルの保存を最大化することです。 

これは明確な削減につながります。答えは、頂点が値グループであり、エッジがグループ間のターゲット マッピングに従うグラフによって決定されます。 スワップ コストは、このグラフのサイクル分解によって完全に決定されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | マージ割り当て + 再計算に対するブルート フォース | 指数関数 | O(n) | 遅すぎる |
 | グループ グラフ + サイクル分解を構築する | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、同じ目標値を共有するインデックスをグループ化します。 このような各グループは、ビー玉が最終的に同じカラー クラスになることを希望するすべてのコンテナを表します。 

次に、これらのグループに対して有向グラフを構築します。 各インデックス i について、そのターゲット値 c[i] を調べ、i を含むグループから c[i] を表すグループに有向エッジを追加します。 すべてのグループにはターゲット値によって誘導される一意の宛先グループがあるため、このグラフにはノードごとに出力エッジが 1 つだけあります。 

次に、このグループ グラフにいくつのサイクルを含めることができるかを分析します。 このグラフの各サイクルは、スワップによってグループを最適に解決できるようにグループを調整できる構造的な状況に対応します。 対照的に、チェーンは行き止まりで終わり、それ以上サイクルを形成することはできません。 

標準の関数グラフ走査を使用して、このグループ グラフのサイクル数を計算します。 各未訪問ノードは、訪問ノードに到達するかサイクルが検出されるまで、その出力エッジに沿って追跡されます。 検出された各サイクルを正確に 1 回カウントします。 

最後に、グループ頂点の数からグループ グラフ内のサイクル数を引いたものとして答えが計算されます。 これは、すべてを個別に解除する場合と比較して、各サイクルが 1 つのスワップを節約するのに対し、チェーンではそのような節約ができないという事実を反映しています。 

### なぜ効果があるのか

 マージがコミットされると、各値グループは、固定された送信依存関係を持つ単一のアトミック ノードのように動作します。 システムは、スワップ操作がサイクル構造にのみ影響し、到達可能性には影響しない関数グラフになります。 すべてのスワップでは、分割によってサイクル数が増加するか、マージによってサイクル数が減少します。最適化は、最終構造で存続するサイクル数を最大化することによって達成されます。 マージ順序は一般性を失うことなく正規化できるため、すべての最適解はある固定グループ グラフに対応し、そのグラフのサイクル数によって最小スワップ コストが完全に決まります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    c = list(map(int, input().split()))

    # compress values into groups
    groups = {}
    gid = 0
    g = [0] * n

    for i in range(n):
        v = c[i]
        if v not in groups:
            groups[v] = gid
            gid += 1
        g[i] = groups[v]

    m = gid

    # build functional graph on groups
    nxt = [-1] * m
    indeg = [0] * m

    for i in range(n):
        u = g[i]
        v = groups[c[i]]
        nxt[u] = v
        indeg[v] += 0  # structure is functional; indeg not required for answer

    visited = [0] * m
    in_stack = [0] * m
    cycles = 0

    def dfs(u):
        nonlocal cycles
        path = []
        while True:
            if visited[u]:
                return
            visited[u] = 1
            in_stack[u] = 1
            path.append(u)
            v = nxt[u]
            if in_stack[v]:
                cycles += 1
                break
            if visited[v]:
                break
            u = v
        for x in path:
            in_stack[x] = 0

    for i in range(m):
        if not visited[i]:
            dfs(i)

    print(m - cycles)

if __name__ == "__main__":
    solve()
```この解決策は、同一の値をグループ識別子に圧縮することから始まります。 これが必要なのは、同じターゲットを持つすべてのビー玉がマージ下で互換的に動作するため、それらを個別に区別しても結果は変わらずに状態サイズが増加するだけであるためです。 

次のステップでは、これらのグループに関する関数グラフを構築します。 各グループには、代表要素のターゲット値によって決定される固有の出力エッジがあります。 グループのすべての要素が同じ値を共有するため、マッピングは一貫しています。 

循環カウントは、機能グラフに対する DFS スタイルの走査を使用して行われます。 現在の再帰スタック内にすでに存在するノードに遭遇するたびに、サイクルが検出されます。 サイクル数はコンポーネント全体で累積されます。 

最後の式 m − サイクルは、マージが最適に配置された後に必要なスワップ操作の最小数に対応します。 

## 実用的な例

 ### 例 1

 c = [2, 2, 3] について考えてみましょう。 

グループを形成します: group(2) = A、group(3) = B。つまり m = 2。 

遷移は、A → A (2 が 2 にマップされるため)、および B → A (3 が 2 グループにマップされるため) です。 

トラバースは次のとおりです。 

| ステップ | ノード | 次へ | アクション | サイクル |
 | --- | --- | --- | --- | --- |
 | 1 | あ | あ | 自己ループが検出されました | 1 |
 | 2 | B | あ | 訪問サイクルにつながる | 1 |

 1 つのサイクルが見つかったので、答えは 2 − 1 = 1 となります。 

これは、B が A に依存しているにもかかわらず、構造サイクルが 1 つだけ存在し、最適なマージ後に必要なスワップは 1 つだけであることを示しています。 

### 例 2

 c = [1, 2, 1, 2] について考えてみましょう。 

グループは A が 1、B が 2 なので、m = 2 となります。 

エッジは A → A および B → B であり、2 つの自己サイクルが生成されます。 

| ステップ | ノード | 次へ | アクション | サイクル |
 | --- | --- | --- | --- | --- |
 | 1 | あ | あ | サイクル | 1 |
 | 2 | B | B | サイクル | 2 |

 答えは 2 − 2 = 0 です。 

これは、各グループが固定点を形成するすでに安定した構造に対応します。

 ## 特殊なケース

 c = [1] などの最小の単一ノードの場合は、グループ グラフ内で直ちに自己サイクルを形成するため、m = 1、cycles = 1 となり、演算はゼロになります。 アルゴリズムは、これを単一の固定点を持つ縮退関数グラフとして正しく処理します。 

c = [x, x, x, x] のような完全に均一なケースでは、すべてのノードが 1 つのグループにまとめられます。 そのグループはそれ自体にマップされ、正確に 1 つのサイクルを生成するため、スワップ コストはゼロとなり、マージ後にすべてがすでに調整されているという事実と一致します。 

すべての個別の値を含む順列のようなケースでは、m = n のグループと標準的なサイクル分解が生成されます。 各サイクルはスワップを 1 つ削減し、関数グラフの古典的な結果と一致します。
