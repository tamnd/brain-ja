 ## 解決策
 ## 問題の理解

 私たちは、各セルが空であるか、接続された構造に属している長方形のグリッドに取り組んでいます。 グリッドは固定されており、クエリごとにサブ四角形が与えられます。 課題は、そのサブ長方形の内部で、占有されているセルが「有効なヘビの形をしたコンポーネント」のみを形成しているかどうかを判断することです。 

この文脈でのヘビは、分岐することなく単一のパス状の構造を形成する、接続されたグリッド セルのセットです。 ヘビの各セル (端点を除く) には、構造内にちょうど 2 つの隣接セルがあり、パスは任意に回転しません。 この形状は制御された方法で方向を変えるため、木や太い領域というよりもジグザグの鎖のように見えます。 

各クエリは、指定された四角形内のセルのみに注目を限定した場合、占有されているセルのすべての接続されたコンポーネントが有効なヘビを形成するかどうかを尋ねます。 

グリッドのサイズとクエリの数が十分に大きいため、クエリごとに接続性を最初から再計算するのは現実的ではありません。 コンポーネントを再構築したり、クエリごとに BFS/DSU を実行したりするソリューションは、ディメンションとクエリ数の両方が大きい場合、時間制限を超えます。これは、最悪の場合の動作がすべてのクエリにわたって 2 次またはそれより悪化するためです。 

コンポーネントが局所的にはパスのように見えても、単純な交互スネーク構造の一部ではない 2×2 ブロックや直線トリプルなどの小さな禁止パターンが含まれている場合、微妙な障害が発生します。 

たとえば、2×2 の正方形を形成するコンポーネントを考えてみましょう。```
11
11
```これは接続されていますが、暗黙的に分岐が発生するため、スネークではありません。 単純なパスの再構築では、すべてのセルが何らかの順序でリストされる可能性がありますが、ローカル構造はスネークの定義に違反します。 

別の例は T 字型です。```
111
010
```これもつながっていますが、分岐点があるので蛇にはなりえません。 グローバル パス構造を保証せずに接続性または次数制約をローカルでのみチェックするソリューションは、それを誤って受け入れる可能性があります。 

主な問題点は、「蛇であること」が、クエリによって引き起こされる任意の部分グラフにおける単なる局所次数条件ではないことです。 グリッド内のどこにでも現れる可能性がある、禁止された幾何学模様の小さなセットを除外する必要があります。 

## アプローチ

 単純なアプローチでは、各クエリを個別に処理します。 特定の長方形に対して、そのセルに対してフラッド フィルまたは DSU を実行し、接続されている各コンポーネントを抽出し、コンポーネントがスネークを形成しているかどうかを検証します。 

コンポーネントを検証するには、そのすべてのセルを収集し、並べ替えて、順序をパスとして解釈しようとします。 2 つの単調順序付け (両方の座標で増加するものと、一方の座標を反転するもの) を試行し、隣接関係の一貫性と一定のステップ動作を検証できます。 これは単一コンポーネントでは機能しますが、コストがかかります。各クエリは四角形全体に及ぶ可能性があり、繰り返しの並べ替えが実行時間を支配します。 

グリッドが N×M でクエリが Q 個ある場合、最悪の場合の複雑さは走査とソートのオーバーヘッドだけで O(QNM) になります。これは、Q が大きい場合には制限をはるかに超えます。 

重要な構造的観察は、非常に小さな局所的な理由により、グリッド コンポーネントがスネークにならないということです。 クエリごとにコンポーネント全体を分析する代わりに、グリッド内でグローバルに違反が発生する場所を事前計算できます。 

非スネーク コンポーネントには、一定の禁止パターンのセットの 1 つが含まれている必要があります。 直感的には、有効なスネークは分岐できず、2×2 の塗りつぶされたブロックを形成できません。 これは、すべての無効な構造には、3 つの連続した整列セルまたは 2×2 の正方形のいずれかが含まれていることを意味します。 

これにより、グローバル接続の推論から固定サイズのパターンの検出までの問題が軽減されます。 これらのパターンのすべての出現がグリッド内で事前にマークされると、各クエリは四角形合計クエリになります。禁止されたパターンがクエリ四角形の内側に完全に存在するかどうかを確認します。 

これは、各パターンが代表セルのマークに寄与するため、2D プレフィックス合計を使用して答えることができ、マークがクエリ範囲内にあるかどうかをテストするだけで済みます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (クエリ DSU/BFS + 検証ごと) | O(QNM log NM) 最悪の場合 | O(NM) | 遅すぎる |
 | 最適 (パターン マーキング + プレフィックスの合計) | O(NM + Q) | O(NM) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### 1. 禁止されているローカル パターンを特徴付ける

 まず、スネーク構造を壊す最小限の構成を特定することから始めます。 無効なコンポーネントには、直線上の 3 つの連続するセル、または完全な 2×2 ブロックのいずれかが含まれている必要があります。 この減少は、分岐領域または脂肪領域が常にこれらのパターンの 1 つを局所的に出現させるという事実から来ています。 

### 2. 違反のグリッドを事前計算する

 グリッド全体を 1 回スキャンします。 各セルについて、禁止パターンの「アンカー」として機能できるかどうかを確認します。 たとえば、水平トリプルまたは垂直トリプルの中央のセル、2×2 ブロックの左上のセルなどです。 

そのようなパターンが存在する場合は常に、補助配列内の対応する位置をマークします。 

このステップが必要なのは、後から一定時間内にクエリに応答する必要があるため、高価な構造検出はすべて前処理に移されるためです。 

### 3. 各パターン タイプの 2D プレフィックス合計を構築する

 各パターン タイプは、独自のバイナリ グリッドに保存されます。 接頭辞の合計を作成して、四角形内に何回出現するかをクエリできるようにします。 

異なるパターンには異なるアンカー オフセットがあり、それらを混合するとクエリの変換が曖昧になるため、個別のグリッドを保持します。 

### 4. 四角形の合計チェックで各クエリに答えます

 クエリ四角形の場合、それを各パターン グリッド上のプレフィックス合計クエリに変換します。 いずれかのグリッドがゼロ以外の値を報告する場合、禁止された構成が四角形の内側に存在し、答えが否定的であることを意味します。 それ以外の場合、長方形は安全です。 

### なぜ効果があるのか

正確さは、すべての非スネーク コンポーネントに、事前に計算された禁止パターンが少なくとも 1 つ必ず含まれるという事実に依存します。 これらのパターンは、無効な構造のローカル証明書です。 すべての違反は一定サイズの監視を通じて検出されるため、大規模な再構築は必要ありません。 プレフィックス合計により、ウィットネスがクエリ四角形の内側に完全に存在する場合、それは集約によって 1 回だけ検出され、存在しない場合は無効な構造が存在できないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_prefix(grid):
    n, m = len(grid), len(grid[0])
    ps = [[0] * (m + 1) for _ in range(n + 1)]
    for i in range(n):
        for j in range(m):
            ps[i + 1][j + 1] = grid[i][j] + ps[i][j + 1] + ps[i + 1][j] - ps[i][j]
    return ps

def get(ps, r1, c1, r2, c2):
    return ps[r2][c2] - ps[r1][c2] - ps[r2][c1] + ps[r1][c1]

def solve():
    n, m, q = map(int, input().split())
    g = [input().strip() for _ in range(n)]

    hor = [[0] * m for _ in range(n)]
    ver = [[0] * m for _ in range(n)]
    sq  = [[0] * m for _ in range(n)]

    for i in range(n):
        for j in range(m):
            if j + 2 < m and g[i][j] == g[i][j+1] == g[i][j+2]:
                hor[i][j+1] = 1
            if i + 2 < n and g[i][j] == g[i+1][j] == g[i+2][j]:
                ver[i+1][j] = 1
            if i + 1 < n and j + 1 < m:
                if g[i][j] == g[i][j+1] == g[i+1][j] == g[i+1][j+1]:
                    sq[i][j] = 1

    ph = build_prefix(hor)
    pv = build_prefix(ver)
    psq = build_prefix(sq)

    out = []
    for _ in range(q):
        r1, c1, r2, c2 = map(int, input().split())
        r1 -= 1
        c1 -= 1

        bad = 0
        bad += get(ph, r1, c1, r2, c2)
        bad += get(pv, r1, c1, r2, c2)
        bad += get(psq, r1, c1, r2, c2)

        out.append("NO" if bad else "YES")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このソリューションでは、検出を 3 つの独立したパターン グリッドに分割します。 水平配列と垂直配列は、長さ 3 の直線セグメントの中央のセルをマークし、そのようなすべてのセグメントが少なくとも 1 つのマーカーに寄与することを保証します。 正方形の配列は、2×2 の均一ブロックの左上隅をマークします。 

各グリッドは 2D プレフィックス合計に変換されるため、各クエリは四角形に対する定数時間の包含テストになります。 インデックス付けには注意が必要です。入力ではクエリ四角形は 1 ベースですが、プレフィックス合計では 1 ベースの内部オフセットが使用されるため、それに応じて左上隅のみを変換します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(NM + Q) | パターンを検出するための 1 回のフル スキャン、1 回のプレフィックス構築、定数時間のクエリ チェック。 
| スペース | O(NM) | 3 つの補助グリッドとプレフィックスの合計 |

 ## 特殊なケース

 主なエッジケースは、コンポーネントが大きいにもかかわらず、ローカルでのみ無効である場合です。 例えば：```
1111
0000
```単純なアプローチでは、エンドポイントのみがチェックされる場合、これは単純なパスのような構造であると考えるかもしれませんが、長さ 3 のすべてのセグメントには禁止されたストレート トリプルが含まれています。 アルゴリズムは各トリプルの中間をマークするため、この行をカバーするクエリは無効を正しく検出します。 

別のケースは、より大きな領域に埋め込まれた 2×2 ブロックです。```
1110
1110
0111
```領域の大部分はヘビのような形状ですが、左上隅の 2×2 ブロックがマーカーをトリガーします。 その領域をカバーするクエリには、プレフィックス合計にマークされたセルが含まれるため、コンポーネントの残りの部分を分析することなく即座に拒否されます。 

最後の微妙なケースは、同じクエリ四角形内に複数の小さな有効なスネークが存在する場合です。 このアルゴリズムは禁止されたパターンにフラグを立てるだけなので、複数の独立した有効なコンポーネントが正確さを妨げることはありません。 マーカーの存在のみが答えを変えるため、追加の簿記を必要とせずに、ばらばらのヘビがきれいに処理されます。
