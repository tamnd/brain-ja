 ## 解決策
 ## 問題の理解

 整数のグリッドが与えられます。 ゲーム内で移動すると、移動が不可能になるまでグリッドが繰り返し変更されます。 重要な構造特性は、値はゲームを通じて変化する可能性がありますが、セル間の相対的な順序は決して変化しないことです。 あるセルが別のセルよりも小さく開始された場合、そのセルはプロセス全体にわたって小さいままになります。 

ゲームは常に、それ以上の移動が不可能な終端構成に向かって進化します。 この最終的な構成では、すべてのセルには、極小値を除いて、値がちょうど 1 つ小さい隣接セルがあります。 これにより、非常に厳格な構造が強制されます。各セルの値は、ステップを減少させることによって極小値からどれだけ離れているかによって純粋に決定されます。 

目的はゲームをシミュレートすることではなく、両方のプレーヤーが最適にプレイしたと仮定して勝者を決定することです。勝者は、この固有のターミナル グリッドに到達するために必要な合計手数が奇数か偶数かによって決まります。 

グリッドの寸法は、次のことを示唆する典型的な制約に従っています。$N \times M$移動のシミュレーションが不可能になるほど大きくなる可能性があります。 ローカル更新を繰り返し適用しようとするアプローチでは、移動ごとに最大 1 つの操作を実行する危険があります。また、移動の数はすべての値の合計に応じて増減するため、グリッド サイズではすぐに 2 次以下になります。 

すべての値がその近傍ですでに最小になっている場合、微妙なエッジ ケースが発生します。 このような場合、最初から手はあり得ず、答えは純粋にパリティ 0 に依存します。つまり、2 番目のプレーヤーが即座に勝ちます。 少なくとも 1 つの手が存在することを前提とした解決策は、ここで誤って勝者をひっくり返すことになります。 

別の特殊なケースが、どこでも同じ値を持つグリッドに現れます。 たとえば、5 で満たされた 2 x 2 のグリッドには、伝播する厳密な減少構造がないため、すでに終端しています。 比較に基づいて変換を適用しようとする単純なシミュレーションでは、誤って更新を試みてグリッド構造を変更し、間違ったゼロ以外の移動カウントが生成される可能性があります。 

## アプローチ

 ゲームのブルート フォース解釈は簡単です。グリッドを繰り返しスキャンし、すべての有効な手を適用し、不可能な手がなくなるまで継続します。 各移動はグリッドの合計をちょうど 1 だけ減らすので、正しさを正当化するのは簡単です。 ただし、そのような移動の数は、グリッド全体の累積された高さの差の合計と同じくらい大きくなる可能性があります。 最悪の場合、次のサイズのグリッド$N \times M$までの値$V$要求できる$O(NMV)$個々の操作が必要であり、各操作では近傍のスキャンまたは更新が必要となるため、全体的なコストが増加し、入力が大きい場合は実行不可能になります。 

重要な観察は、最終的な構成が、動きをシミュレーションすることなく一意に決定されるということです。 順序付け制約は、相対的な構造のみが重要であることを意味し、最終状態は、各セルに、隣接セルを通過するときにそのセルで終了する厳密に減少する最も長いパスの長さに等しい値を割り当てることに対応します。 

これにより、問題は、エッジがより高い値からより低い値に暗黙的に変化するグリッドのグラフ解釈に変換されます。 各セルの最終値が、より小さい元の値を持つ隣接セルにのみ依存することがわかれば、初期値の昇順で結果を計算できます。 各セルは、すでに計算されている小さい隣接セルの最大値に 1 を加えたもの、またはセルが存在しない場合は 0 になります。 

最終的なグリッドを再構築した後、総移動数は、単純に初期合計と最終合計の差になります。 各手で合計がちょうど 1 減るため、この差は正確であり、パリティだけで勝者が決まります。

 ## アルゴリズムのチュートリアル

 元の値の昇順にセルを処理することで、最終的な安定したグリッドを直接計算します。 

1. すべてのグリッド セルをその座標とともにリストに平坦化し、値で並べ替えます。 これにより、セルを処理するたびに、厳密に小さい隣接セルすべてに最終値が割り当てられるようになります。 
2. 新しいグリッドを初期化する`dp`すべての値がゼロに設定された同じサイズ。 
3. 並べ替えたセルを繰り返し処理します。 各セルについて、その 4 つの隣接セルを検査します。 元の値が厳密に小さい近傍の中で、最大値を取得します。`dp`価値。 
4. 現在のセルの割り当て`dp`1 にその最大値を加えた値です。 これより小さい元の値を持つ隣接するものが存在しない場合は、代わりに 0 を割り当てます。 
5. すべてのセルを処理した後、元のグリッドの合計とグリッドの合計を計算します。`dp`グリッド。 
6. 手数は、これら 2 つの合計の差です。 
7. この差が奇数か偶数かによって勝者が決まります。 

並べ替えの背後にある重要な考え方は、元の値の構造と一致する依存関係の順序を強制し、セルがまだ計算されていない状態に依存するのを防ぐことです。 

### なぜ効果があるのか

 順序制約により、有効な遷移が値の初期の厳密な順序を尊重することが保証されます。 このため、セルの最終値に対する有効な依存関係はすべて、厳密に小さい元の値に由来する必要があります。 ソートされた順序で処理することで、必要なときにそれらの依存関係が確実に解決されます。 

各セルの最終値は、そのセルで終了する厳密に減少する隣接ステップの最長チェーンを表します。 これは独特です。なぜなら、偏差は順序付け制約に違反するか、最小以外のすべてのセルがちょうど 1 つ少ない近傍を持つ必要があるという最終条件を満たさないからです。 

移動するたびに合計がちょうど 1 減り、プロセスは常にこの独自に定義された構成で終了するため、最初の合計と最終の合計の差はすべての有効なシーケンスにわたって不変です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    g = [list(map(int, input().split())) for _ in range(n)]

    cells = []
    for i in range(n):
        for j in range(m):
            cells.append((g[i][j], i, j))

    cells.sort()

    dp = [[0] * m for _ in range(n)]

    for val, i, j in cells:
        best = 0
        for di, dj in ((1, 0), (-1, 0), (0, 1), (0, -1)):
            ni, nj = i + di, j + dj
            if 0 <= ni < n and 0 <= nj < m:
                if g[ni][nj] < val:
                    if dp[ni][nj] > best:
                        best = dp[ni][nj]
        dp[i][j] = best + 1 if best > 0 or any(
            0 <= i + di < n and 0 <= j + dj < m and g[i + di][j + dj] < val
            for di, dj in ((1, 0), (-1, 0), (0, 1), (0, -1))
        ) else 0

    initial_sum = 0
    final_sum = 0

    for i in range(n):
        for j in range(m):
            initial_sum += g[i][j]
            final_sum += dp[i][j]

    diff = initial_sum - final_sum
    print("Busy Beaver" if diff % 2 == 1 else "Calico Bear")

if __name__ == "__main__":
    solve()
```このソリューションでは、依存関係の解決が常に有効になるように、最初にすべてのグリッド セルの並べ替え順序を構築します。 の`dp`グリッドは、各セルの計算された最終安定値を保存します。 各セルについて、元の値が厳密に小さい近傍のみを考慮します。これは、それらのみが逆方向の有効な増加チェーンに寄与できるためです。 

微妙な点は、「有効な小さい近傍がない」と「dp 値がゼロの有効な近傍」を区別する必要があることです。 これが、ゼロ以外の値を割り当てる前に、近隣ノードが該当するかどうかを明示的にチェックする理由です。 

最後に、初期合計と最終合計の差を計算します。 各手ごとに合計がちょうど 1 減るため、この差によって正確な手数が決まり、パリティが勝者を決定します。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque
    import sys

    input = sys.stdin.readline

    def solve():
        n, m = map(int, input().split())
        g = [list(map(int, input().split())) for _ in range(n)]

        cells = []
        for i in range(n):
            for j in range(m):
                cells.append((g[i][j], i, j))

        cells.sort()

        dp = [[0] * m for _ in range(n)]

        for val, i, j in cells:
            best = 0
            for di, dj in ((1,0),(-1,0),(0,1),(0,-1)):
                ni, nj = i+di, j+dj
                if 0 <= ni < n and 0 <= nj < m and g[ni][nj] < val:
                    best = max(best, dp[ni][nj])
            has_smaller = any(
                0 <= i+di < n and 0 <= j+dj < m and g[i+di][j+dj] < val
                for di,dj in ((1,0),(-1,0),(0,1),(0,-1))
            )
            dp[i][j] = best + 1 if has_smaller else 0

        s1 = s2 = 0
        for i in range(n):
            for j in range(m):
                s1 += g[i][j]
                s2 += dp[i][j]

        diff = s1 - s2
        return "Busy Beaver" if diff % 2 == 1 else "Calico Bear"

    return solve()

 ## 特殊なケース

 単一セル グリッドは、可能な限り最も単純な構成を示しています。 隣接セルが存在しないため、セルはすでに終了状態にあります。 より小さい近傍が存在せず、初期合計と最終合計の差が 0 であるため、アルゴリズムはそれに 0 の dp 値を割り当て、2 番目のプレーヤーの勝利となります。 

すべての値が等しいなどの均一なグリッドは、アルゴリズムが同じ値の近傍を介してチェーンを誤って伝播しようとしているかどうかを明らかにします。 この構築では厳密に小さい近傍を明示的に要求するため、遷移は発生せず、すべての dp 値はゼロのままで、結果はゼロ手の初期パリティのみに依存し、やはり 2 番目のプレイヤーの勝利となります。 

左上から右下に厳密に増加するグリッドは、最大の伝播を示します。 各セルは、より小さい隣接セルを介して減少するステップの最長チェーンを蓄積し、dp 値は最小領域からの距離を反映した勾配を形成します。 このアルゴリズムは、ソートされた処理を通じてのみこれらの依存関係を正しく構築し、初期化されていない状態が時期尚早に使用されることがないようにします。
