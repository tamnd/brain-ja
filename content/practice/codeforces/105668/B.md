 ## 問題の理解

 2 種類の文字から構成される文字列が与えられます。そのうちの 1 つは構造マーカーのように機能し、もう 1 つは繰り返しパターンを形成します。 タスクは、文字列が非常に厳密な方法で解釈できるかどうかを判断することです。特殊文字に遭遇するたびに、`M`、その後に続くすべてのこと`M`部分文字列の 1 つ以上の連続したコピーで構成されている必要があります`IT`。 

したがって、文字列は効果的に次のように分割されます。`M`。 連続する各セグメント間の`M`文字と最後の後の接尾辞`M`、パターンの空でない繰り返しである必要があります`IT`。 これらのセグメントの外側の文字はこの問題には存在しないため、妥当性はそのようなすべてのセグメントを次のように分解できるかどうかに完全に依存します。`"IT"`残さずに 1 回以上繰り返します。 

入力は単一の文字列であり、出力は文字列全体がこの構造上の制約を満たすかどうかの決定です。 

ここでは制約は明示的に述べられていませんが、意図されたソリューションの説明では、文字列に対する線形処理が想定されています。 これは、一般的な制限が 10^5 文字程度であることを意味しており、部分文字列を繰り返し再チェックしたり、すべてのセグメンテーションを試行したりするような 2 次アプローチは即座に除外されます。 どのソリューションでも、文字列を一定の回数スキャンする必要があります。 

微妙な失敗例は、位置合わせを無視した場合に発生します。 たとえば、次のように考えてみましょう`"MITITMII"`。 セグメント`"ITIT"`有効ですが、`"II"`両方の文字が他の場所でペアで表示されている場合でも、そうではありません。 カウントだけをチェックするか、存在をチェックするだけの単純なアプローチ`I`そして`T`無効なセグメントを誤って受け入れてしまう可能性があります。 繰り返しが連続的であることを強制しない場合、別の失敗ケースが発生します。`"ITTI"`適切な複数の文字セットが含まれていますが、次のもので構成されていません。`"IT"`ブロック。 

## アプローチ

 ブルートフォース戦略では、それぞれを処理します。`M`を境界として使用し、消費を試行して次のセグメントを検証します。`"IT"`貪欲にペアを作成するか、部分文字列の一致を繰り返し再計算します。 最悪の場合、文字列の大部分が次のもので構成されている場合、`I`そして`T`まばらの間`M`s、同じ文字を複数回繰り返しスキャンする可能性があり、二次的な動作が発生します。 

重要な観察は、各セグメントが独立しており、セグメント内の各文字が 1 つの潜在的な要素にのみ関与していることです。`"IT"`ペア。 これは、部分文字列を繰り返しチェックする代わりに、各セグメントを 1 回処理して 1 回のパスで検証できることを示唆しています。 出発するとすぐに、`M`、次のシーケンスを読まなければならないことはわかっています。`"ITITIT..."`次まで`M`したがって、文字をペアでチェックすることで、この構造を貪欲に検証するだけです。 

これにより、問題は単純な状態の線形スキャンに縮小されます。`I`、 それから`T`を繰り返し実行すると、逸脱すると文字列が即座に無効になります。

 ## アルゴリズムのチュートリアル

 によって作成されたセグメント境界を尊重しながら、文字列を左から右に処理します。`M`。 

1. 文字列の先頭からスキャンを開始します。 それぞれを治療いたします`M`新しい検証ブロックを開始するリセット ポイントとして。 すべてのブロックが独立して反復規則を満たさなければならないため、これは重要です。 
2. 何かに遭遇したとき`M`、次の文字に移動し、完全に次の文字で構成される必要があるセグメントの検証を開始します。`"IT"`繰り返し。 直後に開始する要件`M`空のプレフィックスまたは不正な形式のプレフィックスを許可しないようにします。 
3. セグメント内で、文字をペアでチェックします。 有効なペアの最初の文字は次のとおりである必要があります。`I`。 そうでない場合、再配置は許可されないため、文字列は直ちに無効になります。 
4. を読んだ後、`I`、私たちは見なければなりません`T`その直後。 次の文字が欠落しているかどうか`T`、文字列を拒否します。 これにより、次の固定構造が強制されます。`"IT"`原子ブロックとして。 
5. 消費を続ける`"IT"`別のペアがヒットするまでペア`M`または文字列の終わりに到達します。 境界で正確に停止した場合、セグメントは有効です。 それ以外の場合、セグメント内の残りの文字は不完全なペアを示し、無効になります。 
6. で区切られたすべてのセグメントに対してこのプロセスを繰り返します。`M`。 すべてのセグメントが検証に合格した場合、文字列は有効です。 

### なぜ効果があるのか

 このアルゴリズムは、セグメント内にいるときは常に、最後のセグメント以降に消費された文字数という不変条件を維持します。`M`常に偶数であり、有効であることがすでに検証されています`"IT"`ペア。 各ステップでは、この不変式をちょうど 2 文字だけ拡張します。 すべての文字が正確に 1 回消費され、セグメントが厳密に区切られているためです。`M`、セグメント間の依存関係は存在できません。 したがって、違反はペア内の不一致として局所的に現れる必要があり、アルゴリズムによって即座に検出されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

s = input().strip()
n = len(s)

i = 0
while i < n:
    if s[i] == 'M':
        i += 1
        while i < n and s[i] != 'M':
            if i + 1 >= n:
                print("NO")
                sys.exit(0)
            if s[i] != 'I' or s[i + 1] != 'T':
                print("NO")
                sys.exit(0)
            i += 2
    else:
        print("NO")
        sys.exit(0)

print("YES")

よくある実装の落とし穴は、セグメントが直後に開始されるように強制することを忘れることです。`M`。 条件`else: print("NO")`有効なセグメント コンテキスト外の文字が文字列を無効にすることを保証します。 もう 1 つの微妙な問題は、チェックを忘れることです`i + 1 >= n`、これにより、文字列を超えて読み取ることができなくなります。`I`一致せずに表示されます`T`。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from sys import stdout
    backup = sys.stdout
    sys.stdout = io.StringIO()

    # inline solution
    s = sys.stdin.readline().strip()
    n = len(s)

    i = 0
    ok = True
    while i < n:
        if s[i] == 'M':
            i += 1
            while i < n and s[i] != 'M':
                if i + 1 >= n:
                    ok = False
                    break
                if s[i] != 'I' or s[i + 1] != 'T':
                    ok = False
                    break
                i += 2
            if not ok:
                break
        else:
            ok = False
            break

    print("YES" if ok else "NO")

    out = sys.stdout.getvalue().strip()
    sys.stdout = backup
    return out

# provided-like samples
assert run("MITITMITIT") == "YES"
assert run("MITTMITIT") == "NO"

# custom cases
assert run("M") == "YES", "empty valid segment"
assert run("MITIT") == "YES", "single segment"
assert run("MITI") == "NO", "odd leftover"
assert run("TMITIT") == "NO", "invalid start"

 ## 特殊なケース

 1 つのエッジ ケースは、単一の文字列で構成される文字列です。`M`。 アルゴリズムは直ちにセグメントに入り、無効なセグメントは検出されません。`"IT"`ペアであるため、繰り返しルールに違反していないため、有効として受け入れられます。 

もう 1 つのエッジ ケースは、次で始まる入力です。`I`または`T`何かの前に`M`。 例えば`"ITM..."`または`"TM..."`すべての有効な構造はその後にのみセグメントを開始する必要があるため、すぐに拒否されます。`M`、スタンドアロンなし`"IT"`そのコンテキストの外では許可されます。 

3 番目のエッジ ケースは、単一の残り文字で終わるセグメントです。 のために`"MITI"`、摂取後`"IT"`、最後`I`パートナーがいない`T`、境界チェックでこれが検出されます。`i + 1`セグメント制限を超えているため、拒否されます。
