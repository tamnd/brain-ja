 ## 解決策
 ## 問題の理解

 時間の経過とともに更新される配列が与えられているので、「欠落している」数値を含む特定のルールの下で部分配列からどの値を安全に使用できるかについての質問に答える必要があります。 

インタラクションの構造は単純です。配列はポイントの更新を通じて変化し、各クエリは、配列の選択されたセグメントに関連する条件を満たすことが保証される数値を出力するように求めます。 隠された重要なアイデアは、答えは現在の配列に固定範囲のすべての値が含まれているかどうかのみに依存し、含まれていない場合は、欠落している値が普遍的な答えになるということです。 それ以外の場合、何も欠落していない場合は、クエリされた間隔の外側にあるものを確実に選択する必要があります。 

制約が大きいため、クエリごとに頻度やスキャン範囲を再計算すると時間がかかりすぎます。 間隔を反復してチェックするソリューションは、最悪の場合、二次関数の動作に低下します。配列のサイズと演算数が両方とも大きい場合、これは許容できません。 このため、操作ごとに対数時間または定数時間で更新できるグローバル情報を維持する必要があります。 

配列が正確に 1 から N までの値の順列である場合、微妙なエッジ ケースが発生します。その場合、グローバルな欠損値は存在しないため、常に「何らかの欠損数」を返すという単純な戦略は、存在しないため失敗します。 更新を追跡せずに常にクエリ範囲外の固定インデックスを選択すると、別の失敗ケースが発生します。これは、インデックスが有効であるかどうかが更新によって変更される可能性があるためです。 

たとえば、配列が次のような順列になった場合、`[1, 2, 3]`、欠番はありません。 単純な解決策では、範囲がより大きいか、慎重に制限されていないと仮定すると、誤って 4 などの「欠損」値を出力しようとする可能性があります。 この場合の正しい動作には、戦略を完全に切り替える必要があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 更新ごとに、配列を直接変更します。 各クエリについて、関連する間隔をスキャンして表示される値を計算し、1 から N までの値が欠落しているかどうか、または間隔外の値を選択できるかどうかを判断します。 これは問題の定義に直接従うため、正しいです。 ただし、各クエリには間隔のサイズに比例した時間がかかる可能性があり、最悪の場合、配列全体を繰り返しスキャンする可能性があります。 最大の制約がある場合、これはおよそ O(NQ) となり、遅すぎます。 

重要な観察は、間隔に関するクエリごとの構造情報が実際には必要ないということです。 必要なグローバル ファクトは 2 つだけです。配列全体に存在しない値が 1 ～ N に少なくとも 1 つ存在するかどうか、存在しない場合は、すべての値が少なくとも 1 回出現し、配列は順列のように動作します。 この順列の場合、クエリ間隔の外側の任意の位置が有効であり、クエリが配列全体をカバーしない限り、そのような位置は常に存在します。この場合、すべての値がどこにでも存在するため、任意の値が受け入れられます。 

これにより、値の頻度を維持し、現在どの値の頻度がゼロかを追跡するという問題が軽減されます。 これにより、有効な「欠落している」答えが存在する場合、その答えに即座にアクセスできるようになります。 欠損値が存在しない場合、必要なのはクエリ範囲外のインデックスだけであり、選択するのは簡単です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(NQ) | O(N) | 遅すぎる |
 | 最適 | O(N + Q) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 周波数配列を維持します`freq[x]`1 ～ N の範囲の値と、頻度がゼロのすべての値を格納する構造。 

1.初期化`freq`初期配列内の各値の出現をカウントすることによって。 頻度が 0 の 1 から N までの任意の値が欠損値のセットに挿入されます。 これにより、グローバルに欠落している番号が存在するかどうかを即座に検出できます。 
2. 位置でのタイプ 1 更新の場合`i`、値の変化は次のとおりです。`old`に`new`、デクリメントします`freq[old]`そして増加します`freq[new]`。 もし`freq[old]`ゼロになると、それを欠落セットに挿入します。 もし`freq[new]`更新前は 0 でしたが、正になると、欠落セットから削除されます。 これにより、操作のたびに欠損セットが正確に保たれます。 
3. 範囲に対するタイプ 2 クエリの場合`[l, r]`, まず、欠落しているセットが空でないかどうかを確認します。 存在する場合、その値は配列のどこにも現れず、すべてのクエリに対して有効であるため、そこから任意の要素をすぐに返します。 
4. 欠損セットが空の場合、配列は 1 から N の順列になります。この場合、クエリされた間隔に厳密に由来しない値を返さなければなりません。 最も単純な選択は、配列の外側から要素を返すことです。`[l, r]`、 例えば`a[1]`もし`l > 1`、 さもないと`a[N]`。 これにより、クエリ セグメントの外側のインデックスが選択されることが保証されます。 

### なぜ効果があるのか

 アルゴリズムは次の不変条件を維持します。`missing_set`すべての値が正確に含まれます`[1, N]`現時点では配列に存在しないもの。 これは、更新ごとに周波数がローカルに調整され、セット内の変更が即座に反映されるため、維持されます。 セットが空でない場合、セット内の要素はグローバルに存在しないため、クエリ間隔に関係なく有効になります。 セットが空の場合、すべての値が配列内のどこかに存在するため、順列のケースが強​​制されます。この場合、クエリ範囲定義によって制限されないことが保証されているため、クエリ間隔外のインデックスは有効な答えを提供します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    freq = [0] * (n + 1)
    for x in a:
        freq[x] += 1

    missing = set()
    for x in range(1, n + 1):
        if freq[x] == 0:
            missing.add(x)

    for _ in range(q):
        tmp = input().split()
        if tmp[0] == '1':
            i = int(tmp[1]) - 1
            v = int(tmp[2])

            old = a[i]
            if old != v:
                freq[old] -= 1
                if freq[old] == 0:
                    missing.add(old)

                if freq[v] == 0:
                    if v in missing:
                        missing.discard(v)
                freq[v] += 1
                a[i] = v

        else:
            l = int(tmp[1])
            r = int(tmp[2])

            if missing:
                print(next(iter(missing)))
            else:
                if l > 1:
                    print(a[0])
                else:
                    print(a[-1])

if __name__ == "__main__":
    solve()
```更新ロジックは、配列と頻度テーブルの間の一貫性を注意深く維持します。 値を置き換えるときは、不足しているセットが常に現在の状態を反映するように、古いカウントと新しいカウントの両方を正しい順序で更新する必要があります。 クエリ ロジックは、欠落しているセットが空かどうかに完全に依存しているため、正確性は正確さを維持することに大きく依存します。 

微妙な点は、実際には間隔を検査する必要がないことです。`[l, r]`更新または存在チェック用。 間隔が重要になるのは、配列が完全な順列である場合のみです。この場合、配列の外側に要素が 1 つだけ必要になります。 

## 実用的な例

 ### 例 1

 検討してください`a = [1, 2, 3, 4]`、およびについて尋ねるクエリ`[2, 3]`。 

初めに、`missing = ∅`配列は順列なので。 

| ステップ | l | r | 欠落しています | 選択したアクション | 出力 |
 | --- | --- | --- | --- | --- | --- |
 | クエリ | 2 | 3 | ∅ | 間隔の外側を選択 | 1 |

 配列は順列であるため、ここでは範囲外の要素を返します。`a[0] = 1`。 

これは、順列フォールバック動作を示しています。 

### 例 2

 検討してください`a = [1, 1, 2, 4]`N = 4の場合。 

初期の周波数は次のとおりです。`freq[1]=2, freq[2]=1, freq[3]=0, freq[4]=1`、 それで`missing = {3}`。 

| ステップ | l | r | 欠落しています | 選択したアクション | 出力 |
 | --- | --- | --- | --- | --- | --- |
 | クエリ | 1 | 4 | {3} | 戻り値がありません | 3 |

 不足番号が存在するため、すぐに返します`3`間隔も見ずに。 

これは、非順列の場合に区間構造が無関係である理由を示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    freq = [0] * (n + 1)
    for x in a:
        freq[x] += 1

    missing = set()
    for x in range(1, n + 1):
        if freq[x] == 0:
            missing.add(x)

    out = []
    for _ in range(q):
        tmp = input().split()
        if tmp[0] == '1':
            i = int(tmp[1]) - 1
            v = int(tmp[2])
            old = a[i]
            if old != v:
                freq[old] -= 1
                if freq[old] == 0:
                    missing.add(old)
                if freq[v] == 0 and v in missing:
                    missing.discard(v)
                freq[v] += 1
                a[i] = v
        else:
            l = int(tmp[1])
            r = int(tmp[2])
            if missing:
                out.append(str(next(iter(missing))))
            else:
                out.append(str(a[0] if l > 1 else a[-1]))

    return "\n".join(out)

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、更新後に配列が完全な順列になる場合です。 たとえば、重複から開始して、1 から N までのすべての値が 1 回だけ出現するまで徐々に更新します。 その瞬間、欠損セットは空になり、アルゴリズムは動作を切り替える必要があります。 更新のたびに値が削除されるため、実装はこれを処理します。`missing`周波数が正になるとすぐに加算され、ゼロに低下すると再び加算されます。 

もう 1 つのケースは、すべての値が同一である場合です。`[2, 2, 2, 2]`。 ここで、欠損セットには 2 を除くすべての値が含まれています。どのクエリでも、間隔をチェックせずに有効な欠損値がすぐに返されます。 値 2 のみが正のカウントで残るため、周波数ロジックにより正確さが保証されます。 

最後のエッジケースは、ある位置の値を変更しない更新が繰り返されることです。 条件`if old != v`周波数の破損を防ぎ、マルチセットが実際に変更された場合にのみ欠落したセットが更新されるようにして、冗長操作全体にわたって正確さを維持します。
