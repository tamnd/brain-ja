 ## 解決策
 ## 問題の理解

 2D 平面上の一連の点が与えられます。 各点は「都市」を表し、タスクは、ある都市から出発し、すべての都市を正確に 1 回訪問し、開始都市に戻る最短ルートの長さを計算することです。 2 つの都市間の距離は、平面上の標準的な移動を使用して測定されますが、問題の構造により、完全な 2D ジオメトリについて直接考える必要がなくなります。 

各点は 2 つの座標に寄与しており、重要な構造上のヒントは、都市間の移動コストがそれらの座標の組み合わせに依存するということです。 この問題は最終的に、この特定の距離構造の下ですべての点にわたる最小のハミルトニアン サイクルを求めます。 

これは巡回セールスマン問題として表現されていますが、制約 (これが由来する CF 問題群に暗黙的に含まれています) は、$O(n!)$、$O(n^2 2^n)$、または同様の組み合わせ探索は、点の数が小さな定数を超えて増加すると不可能になります。 ソリューションでは、ジオメトリを、ソートまたは線形時間集計で十分な構造に縮小する必要があります。通常、$O(n \log n)$またはそれ以上です。 

ユークリッド距離またはマンハッタン距離をペアごとに処理する必要があると仮定した場合、素朴な推論が微妙に失敗するケースが発生します。 たとえば、ポイントが$(0, 0), (1, 100), (2, 200)$、単純な最短サイクル計算では、すべての順列を評価しようとします。 それはすぐに実行不可能になります$n = 20$、 以来$20!$すでに天文学的な規模になっています。 

もう 1 つの間違った方向は、x と y を独立して扱い、各次元で個別の最適ツアーを合計することです。 パスが両方の座標間で共有されており、次元間の結合が効果的な順序を決定するため、これは問題になります。 

## アプローチ

 強引なアプローチは、巡回セールスマン問題の文字通りの解釈です。つまり、都市のすべての順列を生成し、各注文の合計サイクル コストを計算し、最小値を返します。 これが機能するのは、考えられるすべてのハミルトニアン サイクルを調査し、そのコストを直接評価するためです。 ただし、$n$ポイント、あります$n!$順列と各評価コスト$O(n)$、全体的な複雑さは次のようになります。$O(n \cdot n!)$を超えると使用できなくなります。$n = 11$とか。 

重要な観察は、この問題が 2 次元の記述の中に 1 次元の構造を隠しているということです。 各点$(x, y)$単一のスカラー値に変換できます$f(x, y) = x + y$。 この変換により、ジオメトリが線の順序に折りたたまれ、相対的な差異がすべての移動コストの寄与を捕捉します。 点がこの線上に投影されると、巡回セールスマンの問題は簡単になります。逸脱すると、より大きなギャップを横切る不必要な後戻りが発生するため、最適なツアーは単にソートされた順序に沿って歩いて戻ることです。 

ライン上のサイクルの構造は特に厳格です。 直線上でソートされた点上のハミルトニアン サイクルは、隣接する各ギャップを少なくとも 2 回、つまりサイクル全体で各方向に 1 回横断する必要があります。 したがって、最適な戦略は、最大スパンを最小限に抑え、余分な回り道をしないようにすることです。 

これにより、問題全体が、変換された値の範囲を見つけることに集約されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n・n!) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 変換された値を計算する$v_i = x_i + y_i$それぞれのポイントごとに。 このステップでは、2D 構造を単一の座標にエンコードし、順序付けが意味を持つようになります。 
2. すべての値をリストに保存します。 現在の目標は、2D ツアーを計画するのではなく、純粋に路線に沿った分布を分析することです。 
3. このリストから最小値と最大値を見つけます。 これら 2 つの極端な値によって、構成の合計範囲が決まります。 
4. 最大値と最小値の差を計算します。 これは、すべての点をカバーする線分の長さを表します。 
5. 差に 2 を掛けます。これは、ライン上の閉じたツアーが両方向に全スパンを通過する必要があるという事実を説明します。 
6. 結果を最小サイクル長として出力します。 

### なぜ効果があるのか

 に投影した後、$x + y$空間では、すべての点が単一線上にあり、その順序によって最適なツアーの隣接性が完全に決まります。 ハミルトニアン サイクルは、変換された最小値と最大値の間の区間全体をカバーする必要があります。 サイクルは開始点に戻る必要があるため、間隔のすべてのセグメントが 2 回横断されます。 単調な順序から逸脱すると、すでにカバーされているギャップを超える余分な走査が発生し、総コストが増加します。 したがって、最適なサイクルは最小値から最大値まで歩いて戻ることに相当し、答えはスパンのちょうど 2 倍に固定されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    vals = []
    
    for _ in range(n):
        x, y = map(int, input().split())
        vals.append(x + y)
    
    mn = min(vals)
    mx = max(vals)
    
    print(2 * (mx - mn))

if __name__ == "__main__":
    solve()
```この実装は、1 次元範囲問題への還元の直後に行われます。 変革$x + y$はオンザフライで計算され、最小値と最大値のみが追跡されるため、値のリストを超えて追加の構造を並べ替えたり保存したりする必要はありません。 

よくある間違いは、明示的にソートしてトラバースをシミュレートしようとすることです。 エンドポイントのみが重要であるため、これは不要です。 もう 1 つの微妙な問題は、サイクルでは開始点に戻る必要があることを忘れていることです。そのため係数 2 が必要です。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 変換された値の最小値と最大値を計算する単一パス |
 | スペース | O(n) | 変換された値の保存 |

 解は点の数において線形であり、これは一般的な制約に対して十分に高速です。$10^5$またはそれ以上。 並べ替えや組み合わせ検索は必要ないため、時間とメモリの両方が最小限に抑えられます。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    
    data = inp.strip().split()
    n = int(data[0])
    vals = []
    idx = 1
    for _ in range(n):
        x = int(data[idx]); y = int(data[idx+1])
        vals.append(x + y)
        idx += 2
    return str(2 * (max(vals) - min(vals)))

# all equal

 ## 特殊なケース

 次のような単一点入力$(10, 20)$変換された価値を生み出す$30$。 最小値と最大値は等しいため、計算されたスパンはゼロとなり、アルゴリズムは移動が必要ないことを反映して 0 を正しく返します。 

すべてのポイントが同一である場合、たとえば、$(2, 2)$、変換された値はすべて 4 です。範囲はゼロであるため、サイクル コストはゼロです。 最小値と最大値は変更されないため、アルゴリズムは自然に重複を処理します。 

次のような負の座標の場合$(-1, -1), (0, 0), (1, 1)$、変換された値は次のようになります$-2, 0, 2$。 スパンは 4 で、2 倍すると 8 になります。アルゴリズムは正数に依存せず、整数範囲全体にわたって均一に動作します。
