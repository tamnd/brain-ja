 ## 問題の理解

 私たちに与えられた木は、$n$ノード。 一部のノードのみがリーフであり、各リーフには「福利厚生の期待」を表す数値が含まれます。 内部ノードの入力値はゼロですが、どのリーフが通信できるかを定義するため、構造的に重要です。 

通信ルールは単純です。オプションでツリーから 1 つのノードだけを削除した後も接続されたままであれば、2 つのリーフはお互いを「見る」、または影響を与えることができると見なされます。 結果として得られるフォレスト内でそれらが接続されている場合、それらの福祉値は、あるグローバルしきい値を超えて異なってはなりません。$x$。 接続を切断し、制約を満たす必要があるリーフ ペアの数を減らすために、削除するノードを 1 つ選択することができます。 

タスクは、削除する最適なノードと可能な限り最小の非負の整数を選択することです。$x$そのノードを削除した後、結果として得られるフォレスト内のすべての接続された葉のペアが次を満たすようにします。$|a_u - a_v| \le x$。 

ツリーのサイズは最大です$10^5$、ただし葉の数は最大です。$500$。 これは、実際の組み合わせの複雑さがリーフに存在することをすぐに示します。 すべてのノードのペアまたはすべてのエッジのペアを考慮しようとするソリューションはすべて失敗しますが、問題をリーフ間の相互作用に帰着させるものであれば、潜在的に実行可能です。 

単純な誤解は、元のツリー内のすべての葉の間のペアごとの違いのみを考慮する必要があると想定することです。 ノードを削除すると接続されているリーフが変わるため、これは不正確です。 

さらに微妙な失敗例は、異なるノードを削除すると接続がまったく異なる方法で変化するという事実を無視することです。 たとえば、星形のツリーでは、中心を削除するとすべての葉が切断され、必要な$x = 0$、一方、リーフを削除してもリーフの接続性と強制力には何も影響しません。$x$すべての違いをカバーするために。 

もう 1 つのエッジ ケースは、単一の関節点を除いてすべてのリーフがすでに切断されている場合です。 次に、その点を削除すると、すべての制約が完全に崩壊し、再び次のようになります。$x = 0$、単純なペアごとの解決策ではこれを見逃してしまいます。 

## アプローチ

 直接的な総当たりアプローチでは、考えられるすべてのノードの削除が試行されます。 削除ごとに、リーフ間の接続性を再計算し、接続されたままのリーフの値間の最大差を計算します。 連結コンポーネントのスプレッドが大きい場合、そのスプレッドは必要な$x$、すべての削除の最小値を取得します。 

削除後の接続性を計算するには、事実上、それぞれに対してトラバーサルまたはユニオン検索構築を再実行する必要があります。$O(n)$選択肢。 それぞれの再構築にかかる費用$O(n)$次に、すべてのリーフ制約コストを確認します。$O(L^2)$最悪の場合、$L \le 500$。 これは約につながります$O(n^2 + nL^2)$、これは大きすぎます$n = 10^5$。 

重要な観察は、ツリー内のリーフの接続が非常に構造化されているということです。 2 つのリーフ間のパスはすべて一意であり、ノードを削除した後も接続が維持されるかどうかは、そのノードが一意のパス上にあるかどうかによってのみ決まります。 したがって、各内部ノードはリーフ ペアのサブセットのセパレータとして機能し、それを削除すると、特定の「ブロックされた」ペアが許可されたペアにマージされます。 

削除をシミュレートする代わりに、固定された候補について視点を反転します。$x$、葉の残りのすべての接続コンポーネントが最大でも値の範囲を持つことを保証するノードが存在するかどうかを知りたいのです。$x$。 これは決定問題となり、二分探索が可能になります。$x$、しかしさらに良いことに、リーフペアから直接制約を構築することで二分探索を回避できます。 

以来$L \le 500$、すべてのリーフペアを明示的に考慮する余裕があります。 任意の 2 つの葉について$u, v$、 させて$P(u, v)$彼らの道となる。 ノードを削除すると$c \in P(u,v)$、その後、このペアは切断されます。 したがって、各ペアはノードのセットを生成し、そのノードを削除するとそのペアの制約が「無効」になります。 

値の差が を超えるすべてのペアを削除するノードを 1 つ選択したいと考えています。$x$。 これはツリー ノードに対するヒッティング セット問題と同等ですが、構造が特殊です。各不良ペアはパスに対応しており、そのようなすべてのパスと交差する 1 つのノードが必要です。 

したがって、固定の場合$x$、すべての葉のペアを でマークします。$|a_u - a_v| > x$。 このタスクは、すべての不良ペア間のすべてのパス上に単一のノードが存在するかどうかを確認することになります。 ツリーでは、これらすべてのパスの交点はまさに頂点セットの交点であり、LCA エンドポイント削減によるペアごとのパス交点を使用して段階的に計算できます。 

パスを繰り返し交差させることで、交差候補領域を維持できます。2 つのツリー パスの交差は、空か別のパス (または単一のノード) です。 したがって、候補セットを繰り返し絞り込みます。 最後に交差点が空でない場合は、その交差点内の任意のノードを削除ポイントとして選択できます。 

最後に最小のものを探します$x$それがこれを実現可能にします。 値は以下までなので、$10^5$、リーフ値をソートし、考えられる差異に対して二分探索を行うこともできますが、より直接的なアプローチは、リーフ値をソートし、ペアごとの差異から候補しきい値を考慮するか、単純に二分探索を行うことです。$x$。

 ## アルゴリズムのチュートリアル

 リーフ間のパスを迅速に推論する必要があるため、ツリーを LCA クエリをサポートする構造に変換します。 

1. バイナリ リフティングを使用してすべてのノードの LCA を事前計算します。 これにより、パスの関係と交差点を計算できるようになります。$O(\log n)$。 
2. すべてのリーフを抽出し、その値を保存します。 以来$L \le 500$、すべてのリーフペアを明示的に列挙できます。 
3. リーフを値で並べ替えます。 これにより、どのペアが特定のしきい値に違反しているかを迅速に特定できるようになります。$x$。 
4. 固定の場合$x$、すべての葉のペアを収集します$(u, v)$そのような$|a_u - a_v| > x$。 これらのペアは、単一のノードを削除して分離する必要があります。 
5. 候補交差セットを完全なツリーとして初期化します。 これを、最初は未定義の 2 つのエンドポイントを使用して仮想パス範囲として表します。 
6. 不良ペアごとに、LCA を使用してエンドポイント間のパスを計算します。 このパスを現在の候補領域と交差させます。 2 つのツリー パスの交差部分は、LCA 用語でそれらのエンドポイント間隔の重なりをチェックすることで計算できます。 
7. どこかの時点で交差点が空になった場合、この候補は$x$失敗します。 
8. すべての不良ペアを処理した後、交差部分が空でない場合は、すべての不良パス上に少なくとも 1 つのノードが存在するため、それを削除するとすべての違反が解決されます。 
9. 最小二分探索$x$実現可能性が保たれます。 

### なぜ効果があるのか

 過剰な差があるリーフのペアごとに制約が強制されます。パス上の少なくとも 1 つのエンドポイントを削除する必要があります。 削除できるノードは 1 つだけであるため、そのノードはすべてのパス上に同時に存在する必要があります。 有効な削除のセットは、これらすべてのパスの正確な交差点です。 ツリー内のパスの交差はペアワイズ交差の下で閉じられるため、実行中の交差を維持するだけで十分です。 この交差が空になると、単一のノードはすべての制約を満たすことができなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n = int(input().strip())
vals = list(map(int, input().split()))

g = [[] for _ in range(n)]
for _ in range(n - 1):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    g[u].append(v)
    g[v].append(u)

root = 0
LOG = 17

parent = [[-1] * n for _ in range(LOG)]
depth = [0] * n

def dfs(u, p):
    parent[0][u] = p
    for v in g[u]:
        if v == p:
            continue
        depth[v] = depth[u] + 1
        dfs(v, u)

dfs(root, -1)

for k in range(1, LOG):
    for v in range(n):
        if parent[k-1][v] != -1:
            parent[k][v] = parent[k-1][parent[k-1][v]]

def lca(a, b):
    if depth[a] < depth[b]:
        a, b = b, a
    diff = depth[a] - depth[b]
    for i in range(LOG):
        if diff & (1 << i):
            a = parent[i][a]
    if a == b:
        return a
    for i in reversed(range(LOG)):
        if parent[i][a] != parent[i][b]:
            a = parent[i][a]
            b = parent[i][b]
    return parent[0][a]

leaves = []
deg = [0] * n
for u in range(n):
    deg[u] = len(g[u])
    if deg[u] <= 1 and u != root:
        leaves.append(u)

leaf_vals = [(vals[u], u) for u in leaves]
leaf_vals.sort()

m = len(leaf_vals)

pairs = []
for i in range(m):
    for j in range(i + 1, m):
        pairs.append((abs(leaf_vals[i][0] - leaf_vals[j][0]),
                      leaf_vals[i][1], leaf_vals[j][1]))

pairs.sort()

def on_path(a, b, x):
    c = lca(a, b)
    return lca(a, x) == x and lca(b, x) == x

def path_intersect(a1, b1, a2, b2):
    cand = []
    for x in [a1, b1]:
        if on_path(a2, b2, x):
            cand.append(x)
    for x in [a2, b2]:
        if on_path(a1, b1, x):
            cand.append(x)
    if cand:
        return cand[0]
    return -1

def check(x):
    cur_a, cur_b = -1, -1
    for d, u, v in pairs:
        if d <= x:
            break
        if cur_a == -1:
            cur_a, cur_b = u, v
        else:
            res = path_intersect(cur_a, cur_b, u, v)
            if res == -1:
                return False
            cur_a, cur_b = cur_a, cur_b if res == cur_a else cur_b
    return True

lo, hi = 0, 10**5
ans = hi
while lo <= hi:
    mid = (lo + hi) // 2
    if check(mid):
        ans = mid
        hi = mid - 1
    else:
        lo = mid + 1

print(ans)
```LCA 前処理は、交差チェックに必要なすべてのパス クエリをサポートします。 リーフ抽出ステップにより、関連するノードのみが考慮されるようになり、ペアの列挙が管理しやすくなります。 値の差によってペアを並べ替えると、ペアがしきい値内に収まった時点で実行可能性チェックが早期に停止されます。 

の`check`関数は不変式を維持します。`cur_a, cur_b`は、処理されたすべての違反ペアと交差するパスを表します。 ある時点で交差点が存在しない場合、候補は直ちに拒否されます。$x$。

 葉の値が 1、5、10 で、すべてが中央ノードを介して接続されている小さなツリーについて考えてみましょう。

 ## 特殊なケース

 重要なエッジ ケースは、すべてのリーフが単一の内部ノードに直接接続されている場合です。 そのノードを削除するとすべてのリーフが切断されるため、値に関係なく答えは常に 0 になります。 すべての違反ペアがその中心を通る 1 つのパスを共有するため、アルゴリズムはこれを処理します。そのため、交差点はそのノードのままになります。 

もう 1 つの特殊なケースは、ツリーが本質的にチェーンである場合です。 エンドポイントのみがリーフであるため、リーフのペアは 1 つだけです。 このアルゴリズムは 1 つの制約パスのみを処理し、交差部分はパス全体であるため、必要に応じてそれに沿ったノードの削除は有効になります。 

3 番目のケースは、リーフ値がすでに緊密にクラスター化されている場合です。 そうすれば、合理的なルールに違反するペアはありません$x$, したがって、二分探索はすぐにゼロに収束します。
