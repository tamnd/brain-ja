 ## 解決策
 ## 問題の理解

 いくつかの位置に以下が含まれるバイナリ文字列が与えられます。`1`その他`0`。 初期構成 (1 日目と呼ばれます) から始まり、文字列は時間の経過とともに進化します。 新しい日はそれぞれ、単一のローカル ルールを適用することによって生成されます。`0`それは少なくとも 1 つに隣接しています`1`になる`1`同時に。 ポジションが決まったら`1`、決して元に戻ることはありません`0`したがって、このプロセスでは、次のセットが展開されるだけです。`1`オリジナルのものよりも外側にあります。 

各クエリは、この拡散プロセスを指定された日数適用した後、何日かかるかを尋ねます。`1`は部分文字列間隔に存在します`[l, r]`。 

ダイナミクスに関する重要な観察は、このプロセスが直線上の最短距離の問題と同等であるということです。 ポジションは、`1`後`t`最も近い初期値との距離が正確に一致する日数`1`せいぜい`t - 1`。 これにより、問題は時間の経過に伴うシミュレーションから距離の静的な計算とそれに続く距離のカウントに変わります。 

この制約は、文字列の長さとクエリの数の両方が大きくなり、テスト ケース全体の合計サイズが最大約 100 万になる可能性があることを意味します。 これにより、クエリごとに毎日を明示的にシミュレートするアプローチは即座に除外されます。 クエリごとの線形シミュレーションでも、最悪の場合、約 10^11 の操作が発生します。これは、2 秒の制限が許容する値をはるかに超えています。 許容可能なソリューションでは、文字列を 1 回前処理し、対数時間またはほぼ一定の時間で各クエリに応答する必要があります。 

文字列に何も含まれていない場合、微妙なエッジケースが発生します。`1`全然。 この場合、拡散は決して起こらず、すべてのクエリは常にゼロを返す必要があります。`d`。 もう 1 つのエッジケースは次のような場合です`d`が非常に大きい場合、到達可能な位置の接続されたコンポーネント全体が完全になります。`1`つまり、距離が有限であるすべての位置がカウントされる必要があります。 

## アプローチ

 直接シミュレーションのアプローチでは、各クエリを個別に処理します。 特定の日について`d`の変換を繰り返し適用します。`d-1`ステップを実行してから、1 の数を数えます。`[l, r]`。 各ステップでは文字列全体をスキャンし、隣接する文字列を更新します。`O(n)`1日あたり。 したがって、単一のクエリにはコストがかかります`O(n * d)`、それは不可能です`d`最大 10^9 までの大きさになる可能性があります。 たとえシミュレーションの上限を`n`数日かかっても、各クエリには依然としてコストがかかります`O(n^2)`最悪の場合、許容範囲をはるかに超えます。 

プロセスの構造により、より良い視点が明らかになります。 それぞれのイニシャル`1`1 日に 1 つの速度で両方向に外側に広がる源のように機能します。 これは、各位置を、任意の初期値までの最小距離によってラベル付けできることを意味します。`1`。 この距離が分かると、その後の状態は`d`日数は純粋にその距離が最大かどうかによって決まります。`d-1`。 

これにより、問題は、距離の配列を前処理してから、「カウント インデックス」形式の多くの範囲クエリに答えるという問題に軽減されます。`i`で`[l, r]`そのような`dist[i] <= k`これは古典的なオフライン クエリの問題です。距離によって位置を並べ替え、インデックスに対するフェンウィック ツリーを維持しながら、それらを段階的にアクティブ化できます。各クエリは、範囲合計と組み合わせたプレフィックス アクティブ化問題になります。

 ## アルゴリズムのチュートリアル

 まず、進化する文字列問題を静的な距離問題に変換し、次にクエリをオフライン プレフィックス アクティベーションに削減します。 

1. すべての位置から最も近い初期値までの最小距離を計算します。`1`。 これは、マルチソース BFS または 2 つの線形スイープを使用して行います。 目的は、動的拡散プロセスを位置ごとの単一の数値に置き換えることです。 
2. 進化ルールをしきい値条件として解釈します。 ポジションというのは、`1`当日`d`その距離が最大である場合に限り、`d-1`。 これにより、各クエリが事前計算された距離配列の条件に変換されます。 
3. 各指標を点として表現する`(i, dist[i])`。 各クエリはインデックス範囲内のすべてのポイントを要求します`[l, r]`2 番目の座標の境界は次のとおりです。`k = d-1`。 
4. すべてのインデックスを距離値で並べ替えます。 これにより、「感染」したときの昇順でポジションをアクティブにすることができます。 
5. クエリを並べ替える`k`昇順で。 アクティブ化された位置に対するポインターを維持しながら、両方のリストを一緒に処理します。 
6. インデックスに対してフェンウィック ツリーを維持します。 ポジションをアクティブ化すると、そのポジションがフェンウィック ツリーに追加されます。 この構造により、任意の間隔にアクティブなポジションがいくつあるかを問い合わせることができます。`[l, r]`。 
7. クエリごとに、距離のあるすべての位置までアクティベーション ポインタを進めます。`<= k`が挿入されます。 次に、フェンウィック ツリーの範囲合計を使用してクエリに答えます。 

### なぜ効果があるのか

 核となる不変条件は、処理中のどの時点においても、距離が現在のクエリしきい値以下であるインデックスがフェンウィック ツリーに正確に含まれるということです。 位置とクエリは両方とも距離しきい値の昇順に処理されるため、以前にスキップされた位置を再検討する必要はありません。 各クエリは同じ単調なアクティベーション プロセスのプレフィックスに基づいて回答され、以前の状態に戻ることなく正確性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

    def range_sum(self, l, r):
        return self.sum(r) - self.sum(l - 1)

def solve():
    s = input().strip()
    n = len(s)
    q = int(input())

    dist = [10**18] * n
    from collections import deque
    dq = deque()

    for i, ch in enumerate(s):
        if ch == '1':
            dist[i] = 0
            dq.append(i)

    if dq:
        while dq:
            i = dq.popleft()
            for j in (i - 1, i + 1):
                if 0 <= j < n and dist[j] > dist[i] + 1:
                    dist[j] = dist[i] + 1
                    dq.append(j)

    queries = []
    for idx in range(q):
        d, l, r = map(int, input().split())
        queries.append((d - 1, l, r, idx))

    queries.sort()
    order = sorted(range(n), key=lambda i: dist[i])

    fenw = Fenwick(n)
    ans = [0] * q

    ptr = 0
    for k, l, r, qi in queries:
        while ptr < n and dist[order[ptr]] <= k:
            fenw.add(order[ptr] + 1, 1)
            ptr += 1
        ans[qi] = fenw.range_sum(l, r)

    print("\n".join(map(str, ans)))

if __name__ == "__main__":
    T = int(input())
    for _ in range(T):
        solve()
```このソリューションは、最初のすべてのソースからマルチソース BFS を使用して、動的感染プロセスを最短距離の計算に圧縮することから始まります。`1`ポジション。 このステップにより、各インデックスがいつ感染したかを正確に把握できるようになります。 

各クエリの日の値は 1 を引くことで距離のしきい値に変換され、離散時間プロセスを幾何学的距離に合わせます。 クエリは並べ替えられるため、しきい値の増加を段階的に処理できます。 

フェンウィック ツリーは、どのポジションが現在「アクティブ」であるかを維持します。これは、現在のしきい値以下ですでに感染していることを意味します。 アクティベーションごとに 1 つのインデックスが更新され、各クエリはアクティブなインデックスの範囲合計になります。 

入力では 1 から始まるインデックスが使用されますが、内部配列は 0 から始まるため、インデックス付けには注意が必要です。 したがって、フェンウィック ツリーは、オフバイワンの間違いを避けるために 1 ベースの形式でも使用されます。

 ## 特殊なケース

 なしの文字列`1`無限距離配列を生成します。 実装では、これはすべての距離を大きな値のままにすることで処理されるため、有限の距離に対して位置がアクティブになることはありません。`d`。 すべてのクエリは正しくゼロを返します。 

すべてを含む文字列`1`s はどこにでも距離ゼロを割り当てます。 この場合、すべてのクエリが配列全体を即座にアクティブ化し、すべての回答が`(r - l + 1)`かかわらず`d`。 フェンウィックのアクティベーション ループは、すべてのポジションを自然にトリガーします。`k >= 0`。 

大きい`d`距離値が超過することはないため、文字列の長さを超える値は安全に処理されます。`n`したがって、しきい値条件には最終的に到達可能なすべてのインデックスが含まれます。
