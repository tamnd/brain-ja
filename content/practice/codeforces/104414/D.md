 ## 問題の理解

 あります$n$ラベルが付いた学生アカウント$1$に$n$、さらにラベルが付いた特別な教師アカウント$-1$。 また、次のシーケンスも与えられます。$t$イベント。 各イベントでは 1 人の生徒が説明されます$x$別のアカウントのフォローリストを開いた人$y$、そして現在参加している全員をフォローします$y$さんのフォローリストです。 もし$x$すでに誰かをフォローしていますが、何も変わりません。 もし$x$自分自身をフォローしようとしても、そのアクションは無視されます。 

当初は学生$1$先生に従います$-1$。 他の生徒は誰もフォローしませんし、教師も誰もフォローしません。 

このプロセスは純粋にフォロー関係を拡大することだけを目的としています。 毎日、一連のフォロー エッジをあるノードから別のノードにコピーします。ただし、自己ループは無視され、重複したフォローは無害であるという制約があります。

微妙なエッジケースは、教師アカウントが$-1$グラフでは通常のノードのように動作しますが、ターゲットとして以外は最終出力ドメインから除外されます。 もう 1 つの特殊なケースは、同じ隣接リストの繰り返しコピーです。セットは冪等であるため、繰り返しの操作によって二重にカウントされたり、正確性が損なわれたりしてはなりません。

 ## アルゴリズムのチュートリアル

 私たちは体制を維持します`follow[i]`、ユーザーがフォローするアカウントのセットを表します$i$。 教師は次のようにインデックスされています$-1$、インデックスにマッピングします$0$利便性と学生のために$1..n$にマップします$1..n$。 

また、次のステートメントに従ってシステムを初期化します。$1$先生に従いますので、`follow[1] = {teacher}`他のすべてのセットは空です。 

各イベントごとに$(x, y)$のすべての要素をマージします。`follow[y]`の中へ`follow[x]`, 自分からのフォローは慎重に避けながら。 

すべてのイベントを処理した後、どの生徒がフォローセットに教師を持っているかをスキャンします。 

### ステップ

 1. セットの配列を初期化する`follow`サイズの$n+1$、ここでインデックス$i$学生を代表する$i$、および特別な識別子としての教師の別の表現。 この分離により、負のインデックス付けとの混同が回避されます。 
2. 初期条件を設定する`follow[1]`生徒だから教師を封じ込めるために$1$以下から始まります$-1$。 
3. イベントごとに$(x, y)$、すべてのアカウントを反復処理します$v$で`follow[y]`。 
4. それぞれについて$v$、 もし$v \neq x$、 入れる$v$の中へ`follow[x]`。 セルフチェックでは、システム ルールの要求に従って、アカウントが自分自身をフォローしていないことを確認します。 
5. すべてのイベントを処理した後、学生を反復処理します。$1..n$、それらのインデックスを収集します$i$先生がいるように`follow[i]`。 
6. 結果のリストを出力前にソートします。$1$に$n$すでにソート順が保証されています。 

### なぜ効果があるのか

 いつでも、`follow[i]`は、で終わる一連の「コピーフォローリスト」操作によって到達可能なアカウントのセットを正確に表します。$i$、初期構成から始めます。 各操作では、別のセットにすでに存在していた要素が追加されるだけなので、人為的な要素は導入されません。 セットが使用されるため、重複は状態に影響を与えず、エッジは追加されるだけであるため、以前の関係が失われることはありません。 これにより、すべての操作を処理した後、メンバーシップが確保されることが保証されます。`follow[i]`かどうかを正確に反映します$i$一連のコピーイベントを通じて教師を継承したことがあります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n, t = map(int, input().split())
    
    TEACHER = -1
    
    follow = [set() for _ in range(n + 1)]
    
    follow[1].add(TEACHER)
    
    for _ in range(t):
        x, y = map(int, input().split())
        
        # copy all follows from y to x
        for v in follow[y]:
            if v != x:
                follow[x].add(v)
    
    res = []
    for i in range(1, n + 1):
        if TEACHER in follow[i]:
            res.append(i)
    
    print(len(res))
    print(*res)

if __name__ == "__main__":
    main()
```このソリューションは、セットの伝播モデルを直接実装します。 教師はセンチネル値で表されます$-1$、すべての学生証が陽性であるため安全です。 各操作中に、現在のスナップショットを反復処理します。`follow[y]`そして延長します`follow[x]`。 セルフチェックにより、不正なセルフフォローエッジを防止します。 

最終スキャンでは、各生徒のセット内の教師のメンバーシップがチェックされるだけです。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, t = map(int, input().split())
    TEACHER = -1
    follow = [set() for _ in range(n + 1)]
    follow[1].add(TEACHER)
    for _ in range(t):
        x, y = map(int, input().split())
        for v in follow[y]:
            if v != x:
                follow[x].add(v)
    res = [i for i in range(1, n + 1) if TEACHER in follow[i]]
    return str(len(res)) + "\n" + " ".join(map(str, res)) + "\n"

# provided sample (conceptual check)
assert run("3 5\n1 2\n3 2\n1 -1\n1 -1\n3 1\n") == "2\n1 3\n"

# single propagation
assert run("2 1\n1 -1\n") == "1\n1\n"

# chain propagation

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、教師の唯一の情報源が間接的な場合です。 たとえば、学生の場合$2$決して直接フォローしない$-1$しかし後で学生をコピーします$1$、すでにフォローしている人$-1$、その後学生$2$結局は先生に従うしかない。 アルゴリズムはこれを処理します。`follow[1]`すでに含まれています$-1$、それをコピーすると、教師マークが前方に転送されます。 

もう 1 つのケースは、自己コピーの試行が繰り返されることです。 操作が`(1, -1)`いつ`follow[-1]`は空で何も変わりません。 重複がセット構造によって無視され、自己フォローが明示的にブロックされるため、何度も繰り返してもセットは安定したままになります。
