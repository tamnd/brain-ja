 ## 解決策
 ## 問題の理解

 2 つの隠れた正の整数が与えられます$x$そして$y$。 私たちが実際に見ているのはそれらの合計にすぎません$n = x + y$そして最小公倍数$k = \mathrm{lcm}(x, y)$。 タスクは 1 つの有効なペアを再構築することです$(x, y)$合計が一致するように$n$、lcm は一致します$k$、 そして$x \le y$。 

主な問題点は、どちらの操作でも情報が非線形に混在することです。 合計は加算されますが、lcm は両方の数値の素因数構造に依存します。 多くの異なるペアが同じ和を共有でき、多くの異なるペアが同じ lcm を共有できますが、両方を同時に満たすのは非常に特殊な構造だけです。 

テスト ケースの数には厳しい制約があり、最大で$10^5$、各テストには次の値が含まれます。$n \le 10^9$そして$k \le 10^{18}$。 これにより、ペアを検索しようとするアプローチは即座に除外されます。$(x, y)$直接。 すべての分割を繰り返しても、$n$テストケースごとに直線的であり、非常に遅すぎます。 

構造について推論するときに、さらに微妙な問題が発生します。 たとえば、次の場合$n = 10$そして$k = 12$、次のような有効な解決策が存在します。$(4,6)$。 しかし、のみに基づいて貪欲に因子を割り当てようとすると、$k$の場合、lcm には一致するが合計制約を満たさないペアを構築するのは簡単です。 逆に、合計のみを照合すると、乗算制約は完全に無視されます。 

素朴な落とし穴は、答えが常に次のものに近いと想定していることです。$n/2$、たとえば次のようなペアをテストします$(\lfloor n/2 \rfloor, \lceil n/2 \rceil)$。 これは次の場合にすぐに失敗します$k$大規模な共有主権を強制します。 例えば、$n = 6, k = 4$～によって満足できない$(3,3)$以来$\mathrm{lcm}(3,3)=3$、 ない$4$たとえ合計が正しいとしても。 

本当の課題は、gcd 分解を通じて加法構造と乗法構造を結合することです。 

## アプローチ

 まず、隠れた構造を標準的な整数論形式で書き直すことから始めます。 させて$g = \gcd(x, y)$。 そうすれば書けます$x = g a$、$y = g b$、 どこ$\gcd(a, b) = 1$。 これにより、共有要素が削除されます。$a$そして$b$、相互作用がよりクリーンになります。 

この表現では、制約は次のようになります。$$x + y = g(a + b) = n$$

$$\mathrm{lcm}(x, y) = g a b = k$$これらから、すぐに次のことがわかります。$$g \mid n, \quad g \mid k$$そして以下を定義します:$$t = \frac{n}{g}, \quad m = \frac{k}{g}$$私たちは以下を要求します：$$a + b = t, \quad ab = m, \quad \gcd(a,b)=1$$したがって、問題は次の因数分解を見つけることになります。$m$合計が等しい 2 つの互いに素な部分に分割する$t$。 

強引なアイデアは、すべてのペアを試してみることです$(x, y)$そのような$x + y = n$、lcm を計算し、と比較します。$k$。 これには費用がかかります$O(n)$テストケースごとに、次のようになります$10^{14}$すべてのテストにわたる最悪の場合の操作は完全に実行不可能です。 

重要な観察は、構造が少数の候補に崩壊していることです。$g$。 以来$g$両方を分割する必要があります$n$そして$k$、それはの約数でなければなりません$\gcd(n, k)$。 これにより、gcd スケーリング係数の検索スペースが大幅に制限されます。 

候補者ごとに$g$、残りのタスクは純粋に乗算的になります: 因数$m = k/g$、約数を列挙し、互いに素な部分に分割されたものが合計条件を満たすかどうかを確認します。 なぜなら$k \le 10^{18}$、素因数の数は少なく、約数の列挙は扱いやすいままです。

 ## アルゴリズムのチュートリアル

 1. コンピューティング$d = \gcd(n, k)$。 すべての有効な$g = \gcd(x,y)$両方を分割する必要があります$n$そして$k$、したがって、それはの約数でなければなりません$d$。 
2. すべての約数を列挙します$g$の$d$。 各候補について、それを隠れたペアの潜在的なスケーリング係数として解釈します。 
3.固定の場合$g$、次を計算します。$$t = \frac{n}{g}, \quad m = \frac{k}{g}$$どちらかが整数でない場合、これは$g$有効な解決策を生み出すことができません。 
4. 要因$m$を素因数分解します。 以来$m \le 10^{18}$までの試行分割で効率的に行うことができます。$\sqrt{m}$または事前に計算された素数。 
5. すべての約数を生成する$a$の$m$素数べき乗に対する再帰的構築を使用します。 各約数について$a$、 定義する$b = m/a$。 
6. ペアごとに$(a, b)$、どうかを確認してください$a + b = t$。 true の場合、次のように構築します。$$x = g a, \quad y = g b$$そしてソートされた順に出力します。 

問題が存在することが保証されているため、有効なペアが見つかると検索は直ちに停止します。 

### なぜ効果があるのか

 すべての有効なソリューションは、次のように一意に分解できます。$x = g a$、$y = g b$と$\gcd(a,b)=1$。 lcm力の条件$m = ab$、および合計条件の力$a+b = t$。 なぜなら、すべての素因数は$m$いずれかに完全に割り当てる必要があります$a$または$b$、約数を列挙する$m$考えられるすべての有効な分割をカバーします。 制限する$g$約数に$\gcd(n,k)$有効な gcd 構造が欠落していないことを保証します。 これにより、冗長性のない検索スペースの完全性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import math

# simple prime sieve for factorization help (enough up to 1e6)
MAXP = 10**6 + 5
is_prime = [True] * MAXP
primes = []
is_prime[0] = is_prime[1] = False
for i in range(2, MAXP):
    if is_prime[i]:
        primes.append(i)
        for j in range(i * i, MAXP, i):
            if j < MAXP:
                is_prime[j] = False

def factorize(n):
    res = {}
    for p in primes:
        if p * p > n:
            break
        if n % p == 0:
            cnt = 0
            while n % p == 0:
                n //= p
                cnt += 1
            res[p] = cnt
    if n > 1:
        res[n] = res.get(n, 0) + 1
    return res

def gen_divisors(i, items, cur, res):
    if i == len(items):
        res.append(cur)
        return
    p, e = items[i]
    val = 1
    for _ in range(e + 1):
        gen_divisors(i + 1, items, cur * val, res)
        val *= p

def get_divisors(factors):
    items = list(factors.items())
    res = []
    gen_divisors(0, items, 1, res)
    return res

def all_divisors(n):
    res = []
    i = 1
    while i * i <= n:
        if n % i == 0:
            res.append(i)
            if i * i != n:
                res.append(n // i)
        i += 1
    return res

t = int(input())
for _ in range(t):
    n, k = map(int, input().split())
    d = math.gcd(n, k)

    divisors_g = all_divisors(d)
    found = False

    for g in divisors_g:
        t_val = n // g
        m = k // g

        fac = factorize(m)
        divisors_m = get_divisors(fac)

        for a in divisors_m:
            b = m // a
            if a + b == t_val:
                x = g * a
                y = g * b
                if x > y:
                    x, y = y, x
                print(x, y)
                found = True
                break
        if found:
            break
```実装は分解の後に直接続きます。 外側のループは候補の gcd 値を反復します。$g$、の約数から導出$\gcd(n,k)$。 それぞれについて$g$、ペア$(t, m)$縮小された問題をエンコードします。 因数分解は次の場合にのみ実行されます。$m$これは、除数の生成を制限するため、非常に重要です。 

微妙な点の 1 つは、対称性の処理を確実にすることです。 除数の列挙では両方が生成されるため、$a$そして$b$、1 つの注文を受け入れて強制するだけで済みます。$x \le y$最後に。

 ## 特殊なケース

 エッジケースの 1 つは次のような場合です$k = 1$。 この状況では、どちらの数値も 1 でなければなりません。$n$、強制的に$n = 2$。 アルゴリズムはこれを処理します。$m = 1$約数が 1 つだけあり、すぐに結果が得られます$a = b = 1$。 

もう 1 つのエッジケースは次のような場合です$\gcd(n,k)$は大きいですが、その約数のほとんどは整数互換の縮小形式を生成しません。 これらの候補は、計算時に整数除算によって安全に除外されます。$t$そして$m$。 

さらに次のような場合があります。$m$主要な力です。 次に、除数の列挙により分割の線形チェーンが生成されますが、合計条件を満たすことができるのはそのうちの 1 つだけです。 アルゴリズムは引き続きすべての可能性をチェックし、特別な処理を必要とせずに正確性を保証します。
