 ## 解決策
 ## 問題の理解

 同じ長さの 2 つの配列が与えられています。 1 つの配列は毎日の予測気温を表し、もう 1 つの配列には実際の気温が含まれますが、実際の値はシャッフルされ、順序が失われます。 毎日の割り当て値が予測と一致するように、実際の気温の有効な順序を再構築する必要があります。予測値と割り当て値の差が、指定されたしきい値を超えてはなりません。$k$。 

重要な制約は、有効な割り当てが常に存在することが保証されているため、バックトラックや失敗の処理が不要になることです。 このタスクは純粋に建設的なものであり、すべてのローカル制約を満たす 2 番目の配列の順列を生成します。 

入力サイズが大きいため、すべてのテスト ケースにわたる要素の合計数は最大です。$10^5$。 これにより、二次またはそれ以上のマッチング戦略が即座に除外されます。 どのソリューションも基本的に、テスト ケースごとに線形演算時間内で並べ替えと照合を行う必要があります。 

値が密集している場合、微妙な問題が発生します。 複数の予測値と複数の実際の値が近い場合、順序付けのない単純な貪欲な割り当ては簡単に失敗する可能性があります。 たとえば、それぞれをペアリングすると、$a_i$利用可能な最も近いもので$b_j$グローバルに有効な一致が存在する場合でも、今後の割り当てがブロックされる可能性があります。 これはまさに、ローカルで貪欲な決定をグローバルに分類された戦略に置き換える必要がある種類の構造です。 

## アプローチ

 強引なアイデアは、これをインデックス間の二部マッチング問題として扱うことです。$a$そして$b$、接続する$i$に$j$もし$|a_i - b_j| \le k$。 次に、完全に一致するものを見つけようとします。 これは正しいですが、遅すぎます。エッジの構築にもコストがかかります$O(n^2)$、フローまたはハンガリースタイルのメソッドによるマッチングは、次の場合には実行できません。$n = 10^5$。 

重要な観察は、制約が位置ではなく値において単調であるということです。 両方の配列をソートすると、小さい値が含まれるという事実を利用できます。$a$の小さい値のみと一致します$b$許容誤差内で、大きな値の場合も同様です。 並べ替えると、問題は 1 次元の位置合わせの問題に変わります。 

両方の配列がソートされると、その存在が保証され、ソートされた順序でそれらをペアにすることが常に安全であることがわかります。 モノトーンペアリングから逸脱しようとする試みは、実現可能性を損なうことなくモノトーンペアリングに戻すことができます。これは、反転のスワップは絶対差の制約下でのみ有効性を改善または保持するためです。 

これにより、ソート後の単純な貪欲スキャンに問題が軽減されます。

 ## アルゴリズムのチュートリアル

 私たちは単一のテストケース内で作業します。 

1. 配列をソートする$a$降順ではない順に。 これにより、最も寒い予報から最も暖かい予報までの日が配置され、割り当てに一貫した構造が作成されます。 
2. 配列をソートする$b$降順ではない順に。 これにより、実際の気温が最も寒いものから最も暖かいものまで整理され、同等の等級に一致させることができます。 
3. 新しい配列を構築する$c$割り当てることによって$c[i] = b[i]$みんなのために$i$。 このペアリングは、$i$- 番目に小さい予測$i$- 番目に小さい実際の温度。 
4. 出力$c$。 

正確かどうかは、制約に違反することなく、有効な割り当てを並べ替えられた割り当てに変換できるかどうかにかかっています。 直感的には、2 つの割り当てが交差する場合、両方のシーケンスが同じ方向にソートされるため、それらを交換しても絶対差が許容しきい値を超えることはありません。 

### なぜ効果があるのか

 有効な順列が存在すると仮定します。$b$マッチング$a$。 ペアリングの逆転を考慮してください。$a_i \le a_j$しかし$b_i > b_j$。 スワッピング$b_i$そして$b_j$の最大値を増やすことはできません$|a_i - b_i|$そして$|a_j - b_j|$より大きな値をより大きなターゲットに移動し、より小さな値をより小さなターゲットに移動すると、絶対差の下で両方向の不一致が減少するためです。 この除去を繰り返すとすべての反転が除去され、単調なマッチングが生成されます。 そのモノトーンマッチングはまさにソートペアリング。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    
    a.sort()
    b.sort()
    
    print(*b)
```実装は派生構造に直接に従います。 必要な変換は両方の配列のソートのみです。 問題によって実現可能性が保証され、モノトーンの再配置によって妥当性が維持されるため、最終的なペアリングには明示的なチェックが必要ありません。 

よくある落とし穴は、それぞれを貪欲に一致させようとすることです。$a_i$ローカルで有効な$b_j$条件チェックで 2 つのポインターを使用します。 このアプローチでは、初期の選択が後で実行可能な一致をブロックする可能性があるため、行き止まりになる危険があります。 両方の配列をソートすると、この依存関係が完全に排除されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline
    
    t = int(input())
    out = []
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        a.sort()
        b.sort()
        out.append(" ".join(map(str, b)))
    return "\n".join(out)

 ## 特殊なケース

 すべての値が$a$同一である、任意の順列$b$値が範囲内にある限り有効です。 並べ替えても有効な割り当てが生成され、曖昧さが回避されます。 

いつ$k = 0$、制約は完全な等価性を強制します。 並べ替えにより、同一の値が位置的に整列するため、ロジックを追加しなくても実現可能性が維持されます。 

値が負の場合、または広範囲に分散している場合、絶対差分の対称性により並べ替えが有効なままであることが保証されます。 順序付けは算術構造ではなく純粋に大きさの一貫性に基づいているため、符号ベースの調整は必要ありません。
