 ## 問題の理解

重要な点は、値を選択しているのではなく、インデックスを選択していることです。 配列内に値が複数回出現する場合、グループ内で選択された値がその値の唯一の出現である限り、各出現を独立して選択できます。 

出力は、正確なサイズの有効なインデックス サブセットの数です。`m`両方の条件を満たすもの。

 ## アルゴリズムのチュートリアル

 1. 配列を値の周波数マップに圧縮します。 それぞれの個別の値は生徒の「タイプ」を表し、その頻度はその値が選択された場合にどれだけの選択肢があるかを表します。 
2. 個別の値を昇順の配列に並べ替えます`vals`、それらの周波数を平行に保ちます。 
3. スライディングウィンドウを維持する`[l, r]`以上`vals`そのため、ウィンドウは常に個別の値の候補セットを表します。 
4. 展開する`r`一歩ずつ。 追加後`vals[r]`、条件が満たされているかどうかを確認します`vals[r] - vals[l] < m`違反されています。 そうなったら移動する`l`再度有効になるまで転送します。 
5. ウィンドウ サイズが正確に等しい場合`m`、このウィンドウの寄与を、その中のすべての値の頻度の積として計算します。 
6. すべての寄与分を剰余として累積する`10^9 + 7`。 

重要な重要な部分はステップ 4 で、範囲制約を強制します。 これが機能するのは、値がソートされると、どのウィンドウでも最大値と最小値が常にその端にあるため、O(1) で妥当性をチェックできるためです。 

### なぜ効果があるのか

 有効な生徒の選択はすべて、一連の生徒の選択に一意に対応します。`m`範囲が以下の個別の値`m`。 ソートにより、そのようなセットはソートされた個別リスト内で連続したブロックとして表示されます。 スライディング ウィンドウは、そのようなブロックをすべて 1 回だけ列挙します。 頻度の積は、各値の出現が選択される独立した選択を説明し、各値は最大 1 回選択されるため、過剰カウントは発生しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))

        freq = {}
        for x in a:
            freq[x] = freq.get(x, 0) + 1

        vals = sorted(freq.keys())
        f = [freq[v] for v in vals]

        k = len(vals)
        l = 0
        prod = 1
        ans = 0

        for r in range(k):
            prod = (prod * f[r]) % MOD

            while vals[r] - vals[l] >= m:
                prod = (prod * pow(f[l], MOD - 2, MOD)) % MOD
                l += 1

            if r - l + 1 == m:
                ans = (ans + prod) % MOD

        print(ans)

if __name__ == "__main__":
    solve()
```重複はサブセット内で組み合わせではなく乗算的に処理されるため、実装では最初に頻度カウントが構築されます。 一意の値を並べ替えた後、スライディング ウィンドウにより有効な範囲のみが考慮されるようになります。 

変数`prod`現在のウィンドウ内の周波数の積を維持します。 左ポインタが移動すると、フェルマーの定理による逆モジュラーを使用して除算します。 MODがプライムなのでこれは安全です。 

条件`r - l + 1 == m`フルサイズの選択のみをカウントし、サブセットを過少カウントまたは過大カウントする部分ウィンドウを回避します。 

微妙な点は、サブセットを明示的に列挙することは決してないということです。これは、ウィンドウが固定されると、各値が独立して寄与するため、乗算ですべての組み合わせが取得されるためです。

 ## 特殊なケース

 すべての生徒が同じ値を共有すると、アルゴリズムはすべてを 1 つの異なる値に圧縮します。 もし`m > 1`、スライディング ウィンドウがサイズに達することはありません`m`, そのため貢献度は加算されません。 もし`m = 1`、ウィンドウはただちに合計頻度に寄与し、単一の生徒の選択肢の数と一致します。 

値がすべて個別であるにもかかわらず広範囲に分散している場合、多くのウィンドウが範囲制約に失敗します。 ポインタ`l`積極的に前進し、無効なスパンが決してカウントされないようにします。 たとえば、値の場合`[1, 100, 200]`そして`m = 2`、 のみ`[1,100]`の場合は有効です`99 < 2`失敗するため、誰も寄与せず、アルゴリズムは正しくゼロを返します。 

有効なウィンドウ内に重複が集中している場合など`[2,2,2,3]`と`m = 2`、窓`[2,3]`貢献する`3 × 1 = 3`、価値のある 3 人の同一の生徒から 1 人を選択する 3 つの方法を正しく反映しています。`2`シングルと組み合わせて`3`。
