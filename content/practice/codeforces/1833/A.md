 ## 解決策
 ## 問題の理解

 ターゲットとなるメロディーが与えられますが、これはアルファベットの上に文字列を重ねたものです。`{a, b, c, d, e, f, g}`。 Vlad は、この文字列を任意のチャンクに直接構築することはできません。 代わりに、次のように、ちょうど 2 文字の長さの断片しか記録できません。`"ab"`または`"gg"`。 

このような 2 文字の部分をいくつか録音した後、隣接する部分が境界で「一致」する場合に限り、それらを連結してより長いシーケンスにすることができます。 具体的には、連結によって不正なジャンプが発生しないように、ある部分の最後の文字は次の部分の最初の文字と等しくなければなりません。 

目標は、できるだけ少ない 2 文字の記録を使用して、指定された文字列全体を再構築することです。 

問題を再解釈する有効な方法は、各 2 文字の記録を最初の文字と 2 番目の文字の間の有向接続として考えることです。 記録を連結するときは、エンドポイントの連続性条件をウォーク制約として再利用し、基本的にこれらの接続に沿ってウォークすることになります。 課題は、重なり合ってシーケンス全体を生成できるように、そのような有向エッジがいくつ必要になるかということです。 

文字列の長さは最大 50 で、最大 10⁴ のテスト ケースがあります。 つまり、テストごとの O(n²) 以上のソリューションは簡単に十分に高速ですが、指数関数的またはエッジのサブセットに対する大量の検索を伴うものは不必要であり、リスクが伴います。 

次のように、文字列内のすべての文字が同一である場合、微妙なケースが発生します。`"aaaaaa"`。 ここで単一の録音`"aa"`概念的には再利用してチェーン全体を拡張できるため、答えは 1 になります。もう 1 つのエッジ ケースは、次のようなジグザグ パターンで遷移がすべて異なる場合です。`"abacaba"`、ここでは再利用が制限されており、重複するペア間で繰り返される遷移を考慮する必要があります。 

単純な間違いは、文字列内の隣接するペアごとに 1 つの録音が必要であると想定することです。 これは、エンドポイントが適切に一致していれば、単一の記録されたペアがチェーン内で複数回再利用され、必要な記録の数が減るため、失敗します。 

## アプローチ

 ブルートフォース解釈では、どの 2 文字セグメントを記録するか、およびそれらを結合して文字列を形成する方法を明示的に選択しようとします。 次のようなエッジの可能なマルチセット選択をすべて列挙することを想像できます。`"ab"`、`"ba"`、`"ac"`, などを順番に連鎖させて文字列が形成できるかどうかを確認します。 これは、アルファベットが小さい場合でも、文字列内の個別の遷移の数に応じて、可能なエッジのマルチセットの数が指数関数的に増加するため、すぐに扱いにくくなります。 各チェックにはパス構築のシミュレーションが必要となるため、このアプローチは n = 50 の場合でも非常に遅くなります。 

重要な洞察は、構築される完全な文字列という観点から考えるのをやめ、代わりにターゲット文字列内の連続する文字間の局所的な遷移に注目することです。 隣接するすべてのペア`(s[i], s[i+1])`つまり、すべての有向遷移タイプが少なくとも 1 回は利用可能であることを確認する必要があります。 ただし、重複は重要です: すでにセグメントがある場合`"ab"`そして後で必要になる`"ab"`繰り返しますが、構築パスで再利用できる限り、2 番目の記録は必要ありません。 

重要な単純化は、文字列の構造により、文字間の明確な遷移のみを考慮する必要があることです。ただし、1 つの例外があります。分岐点として機能する必要があるパターンに文字が出現する場合、1 つのエッジだけでは 1 つのチェーン内の複数の互換性のない方向に機能できないため、追加の記録が強制される可能性があります。 実際には、最適な解決策は、可能な限り以前に確認されたトランジションを再利用しながら、貪欲スキャンで異なるキャラクター間の「新しい」トランジションの数をカウントすることになります。 

正しい定式化は次のようになります。文字列の構築を貪欲にシミュレートし、前のチェーンを継続することで現在の遷移を満足させることができないため、「新しい録音を開始」する必要がある回数を数えます。

 | 貪欲な遷移追跡 | テストあたり O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 各文字列を個別に処理します。 

1. 使用する有向トランジションの空のセットから開始します。 各トランジションはペアです`(s[i], s[i+1])`。 
2. 文字列を左から右にスキャンし、隣接するすべてのペアを検討します。 各ペアについて、録音セットでこのトランジションをすでに「カバー」しているかどうかを確認します。 そうでない場合は、このペアに新しい 2 文字の記録を導入する必要があります。 
3. ペアに新しいレコーディングを導入するとき`(a, b)`、中古としてマークします。 これはセグメントの記録を表します`"ab"`。 
4. スキャンを続行します。 後で同じペアに遭遇した場合`(a, b)`、チェーン内の既存のものを再利用できるため、別の記録は必要ありません。 
5. 最終的な答えは、文字列内に現れる個別の有向遷移の数です。 

重要な詳細は、トランジションを指示どおりに扱うということです。`"ab"`そして`"ba"`は異なる録音です。 連結制約は方向に依存するため、これは不可欠です。 

### なぜ効果があるのか

 記録された各 2 文字列は、1 つの有向エッジに正確に対応します。 最終的な文字列の有効な構築は、何らかのエッジを通じて元の文字列内のすべての隣接するペアを実現できなければなりません。 2 つの同一の遷移が現れた場合、接続性が維持されている限りチェーン内の複数の位置で再利用できるため、記録されたエッジは 1 つで十分です。 したがって、記録の最小数は、文字列に必要な個別の隣接文字ペアの数と等しくなります。 

不変条件は、スキャンの各ステップで、記録された一連の遷移が、処理されたすべての隣接関係ペアを矛盾なく再現するのに十分であり、新しいタイプの隣接関係が出現した場合にのみそれを拡張するということです。 導入するエッジの数が少ないと、少なくとも 1 つの隣接関係がサポートされないままになるため、これにより最小性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    s = input().strip()

    used = set()
    ans = 0

    for i in range(n - 1):
        pair = (s[i], s[i + 1])
        if pair not in used:
            used.add(pair)
            ans += 1

    print(ans)
```この実装は、別個の隣接するペアを追跡するというアイデアを直接反映しています。 セット`used`移行を指示した店舗はすでに考慮されています。 新しいペアが見つかるたびに、答えが増加します。 までの繰り返しのみを超える境界問題はありません。`n-2`、いつもアクセスしているので`i+1`。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        s = input().strip()

        used = set()
        ans = 0
        for i in range(n - 1):
            p = (s[i], s[i+1])
            if p not in used:
                used.add(p)
                ans += 1
        out.append(str(ans))

    return "\n".join(out)

 ## 特殊なケース

 のような文字列の場合`"aaaaaa"`、隣接するすべてのペアは同一です。 アルゴリズムが見ているのは、`(a,a)`カウンタは 1 回だけ増加し、再度増加することはなく、出力 1 が生成されます。これは、単一の記録が行われたという事実と一致します。`"aa"`建設全体を通して再利用できます。 

次のような完全に交互のパターンの場合`"ababab"`の場合、スキャンでは 2 つの異なる遷移のみが生成されます。`(a,b)`そして`(b,a)`。 文字列の長さが遷移の数に比べて大きい場合でも、セットベースのアプローチは繰り返しを正しく再利用に折りたたんで、答えが頻度ではなく個別の隣接タイプにのみ依存することを確認します。
