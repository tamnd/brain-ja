 ## 解決策
 ## 問題の理解

 疑似木であることが知られているグラフ内の各頂点の次数のみが与えられます。 つまり、最終的なグラフは接続され、正確に 1 つのサイクルを含む必要があります。$n$エッジオン$n$頂点。 実際のエッジは失われており、その課題は、「花のような」と呼ばれる強い構造的制約も満たす次数と一致するグラフを再構築することです。 

構造条件を定義するのは、サイクルのみに関するものではなく、すべてのサイクル エッジを除去した後に何が起こるかについてです。 サイクルが削除されると、各サイクルの頂点はそこからぶら下がっている木のルートになります。 要件は、そのようなすべてのツリーがそのサイクル頂点にルートするときに同一の最大深さを持たなければならないということです。 言い換えれば、サイクルの周囲にあるすべての「垂れ木」の高さのバランスが完全に揃っていなければなりません。 

入力からは隣接関係の情報は得られず、度数のマルチセットのみが得られます。 次数は、各頂点が持つ必要がある入射エッジの数を制限するため、タスクは、それらの次数と一致し、バランス条件を満たす疑似ツリーが存在するかどうかを判断し、存在する場合は擬似ツリーを構築することです。 

制約は非常に大きく、合計すると$n$すべてのテストケースにわたって、$10^6$。 これにより、テスト ケースごとに二次関数が除外されます。 すべての解は線形または線形に近いものでなければならず、グラフ構築の試行やサイクル推測のシミュレーションを繰り返すことを避けなければなりません。 

フラワー制約を無視して次数から任意に疑似ツリーを構築しようとすると、単純な失敗モードがすぐに現れます。 たとえば、次のような次数シーケンスから有効な擬似ツリーを構築するとします。$[3,1,1,1]$、サイクルを形成する星と追加のエッジを生成する可能性がありますが、サイクルが配置される場所によっては深さ条件が失敗する可能性があります。 もう 1 つの微妙な失敗は、有効な擬似ツリー次数シーケンスが常に任意にアタッチされたツリーを備えたサイクルに配置できると仮定していることです。 これは、接続されているすべてのツリーが同じ高さでなければならないという要件を無視しており、構造が強く制限されています。 

2 番目の隠れた落とし穴はサイクル サイズです。多くの誤った構築では、度が許す限り任意の長さのサイクルが可能であると想定していますが、バランシング条件により、事実上、サイクル周囲の頂点の非常に特殊な階層化が強制され、どの頂点がサイクルに属することができるかが制限されます。 

## アプローチ

 ブルートフォースアプローチでは、次数シーケンスと一致するすべての疑似ツリーを明示的に構築し、次に接続性、サイクルの一意性をチェックし、最後にサイクルエッジを削除した後に深さが等しい条件を検証します。 次数シーケンスと一致する単純なグラフの数は指数関数的に増加するため、すべての候補グラフを生成することさえ不可能です。 擬似ツリーに限定しても、サイクルの配置を決定し、ツリーを接続するだけで、すでに組み合わせ爆発が引き起こされます。 

重要な簡略化は、視点を逆転させることで実現します。グラフを作成して花の状態をチェックする代わりに、その状態が構造に関して何を意味するかを特徴づけようとします。 

サイクルを修正すると、すべての非サイクル エッジは、あるサイクル頂点をルートとするツリーに属します。 このようなツリーすべての深さが等しいため、非常に厳格な構造が強制されます。サイクル頂点からのすべての分岐は、グローバルに同期された「階層化」を備えたチェーン状の構造を形成する必要があります。 これは、すべての頂点にサイクルの外側への深度値を割り当てることができ、エッジは常に連続する深度レイヤーを接続する必要があることを意味します。 

これにより、各頂点が固定次数を持ち、エッジがレベル 0 にちょうど 1 つのサイクルを持つレベル構造を尊重する必要がある層状グラフの構築に問題が軽減されます。サイクル自体は「ベース リング」のように動作し、残りのすべてのエッジはサイクル ノード間の高さの差を増加させてはならないツリーを形成します。 

この観察により、貪欲な構築が可能になります。最初に、次数制約とツリー エッジ間で残りの次数を分配する実現可能性に基づいて、どの頂点がサイクル上に存在する必要があるかを決定します。 次に、残りの頂点をレイヤーにアタッチし、常に制御された方法で次数を消費し、すべてのサイクル頂点から均一な高さの拡張を保証します。 

この構築は次数要件に基づいてツリーを構築することに似ていますが、複数のルート (サイクル ノード) が同一の BFS 深さを生成する必要があるという制約が追加されています。

 | ブルートフォース列挙 | 指数 | O(n) | 遅すぎる |
 | 度数 + レイヤード欲張り構造 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、どの頂点がサイクルを形成する必要があるかを分離します。 グラフには正確に 1 つのサイクルがあるため、すべての非サイクル エッジはツリーに属し、ツリー エッジは頂点エンドポイントの次数に正確に 1 を与えます。 サイクル頂点はサイクル自体に参加しているため、その次数に少なくとも 2 を寄与します。 

1. 頂点を次数 2 以上の頂点と次数 1 の頂点に分割します。サイクル頂点は少なくとも 2 つの入射エッジをサポートする必要があるため、次数 2 以上の頂点のみがサイクル上に存在できます。 
2. 候補サイクル セットを次のすべての頂点とする。$d_i \ge 2$。 このセットの頂点が 3 つ未満の場合、サイクルには少なくとも 3 つの異なる頂点が必要なので、構築は不可能です。 
3. 次に、サイクル頂点を任意の順序で配置し、単純なサイクルに接続します。 これは、サイクル頂点ごとに 2 度単位を消費します。 この後、各サイクル頂点には、ツリーを接続するために使用される残りの次数バジェットがあります。 
4. 各サイクル頂点の残りの次数を、生成できる「ツリー スタブ」の数として扱います。 ここで、すべてのサイクル頂点から開始するマルチソース展開を同時に実行します。 
5. 現在のフロンティア頂点からの利用可能なスタブのキューを維持します。 スタブを取得するたびに、未使用の次数がまだある新しい頂点にスタブを接続し、両方の容量を減らします。 これにより、常にサイクルに関連付けられた森林を構築できるようになります。 
6. 私たちは常にすべてのサイクル頂点にわたってバランスのとれた方法で拡大します。 この均一な拡張により、すべてのツリーがレイヤーごとに成長することが保証されるため、ツリーの深さは同期されたままになります。 
7. いずれかの時点で、残りの学位要件をすべて満たすことができない場合、またはスタブが途中で使い果たされる場合、建設は失敗します。 
8. すべての次数が正確に満たされ、すべての頂点が接続されている場合は、構築されたエッジを出力します。 

重要な不変条件は、すべての段階で、すべてのアクティブなフロンティア ノードがサイクルの同じ深さの層に対応するということです。 各拡張ステップでは、残りの次数がレイヤー全体で均一に減少するため、どのサイクル頂点も深さにおいて他の頂点に遅れたり、超えたりすることはできません。 これにより、サイクル頂点に根を張るすべてのツリーにわたって同じ最大深さが強制されます。これはまさに花の状態です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import deque

def solve():
    n = int(input())
    deg = list(map(int, input().split()))
    
    # cycle candidates: degree >= 2
    cycle = [i for i, d in enumerate(deg) if d >= 2]
    
    if len(cycle) < 3:
        print("No")
        return
    
    edges = []
    
    # build cycle in arbitrary order
    k = len(cycle)
    for i in range(k):
        u = cycle[i]
        v = cycle[(i + 1) % k]
        edges.append((u + 1, v + 1))
        deg[u] -= 2
    
    # nodes available for attachment
    # each cycle node now acts as a source with remaining degree
    q = deque()
    for i in cycle:
        if deg[i] > 0:
            q.append(i)
    
    # also include leaves later
    ptr = 0
    nodes = list(range(n))
    
    # expand trees
    for i in range(n):
        if deg[i] == 0:
            continue
        # attach until degree satisfied
        while deg[i] > 0:
            if not q:
                print("No")
                return
            v = q.popleft()
            edges.append((i + 1, v + 1))
            deg[i] -= 1
            deg[v] -= 1
            if deg[v] > 0:
                q.append(v)
    
    # final validation
    if any(d != 0 for d in deg):
        print("No")
        return
    
    print("Yes")
    for u, v in edges:
        print(u, v)

def main():
    t = int(input())
    for _ in range(t):
        solve()

if __name__ == "__main__":
    main()
```この実装では、まずサイクルに参加できるすべての頂点を抽出し、次にそれらを単純なリングに接続します。 これは、サイクル頂点ごとに 2 単位の度数を即座に消費し、サイクル エッジが各サイクル ノードで正確に 2 つの入射エッジを占めるという要件と一致します。 

残りの次数の値は、ツリー エッジに利用可能な「接続容量」として扱われます。 両端キューは、さらなるアタッチメントをサポートできる、現在アクティブな頂点のグローバル プールとして使用されます。 各エッジ構築は両方のエンドポイントから次数を消費し、頂点にまだ次数が残っている場合は常に、さらなる拡張のためにプール内に留まります。 

微妙な点は、明示的な深さの値を割り当てようとしていないことです。 キューを介した BFS のような伝播は、レベル構造を暗黙的に強制します。頂点が使用されると、まだ容量がある場合にのみプールに再入力されます。これは、同じツリーをレイヤーごとに拡張することに相当します。 

障害は、すべての次数が満たされる前にプールが空になったときに正確に検出されます。これは、必要な分岐の不均衡に対応します。

        if len(cycle) < 3:
            return ["No"]

 ## 特殊なケース

 サイズがちょうど 3 の最小サイクルは、最も緊密な有効な構造として動作します。 このアルゴリズムは、3 つの頂点すべてをサイクル ノードとして選択し、それぞれから 2 度単位を減算して、閉じた三角形を生成します。 残りの次数があると強制的に接続が行われますが、残りの次数はすべてゼロになるため、キューは空のままであり、無効な展開は発生しません。 

すべての頂点が次数 1 を持つ場合は、どの頂点もサイクルに属することができないため、すぐに失敗します。 サイクル候補セットは空であり、アルゴリズムは構築を試行する前にインスタンスを正しく拒否します。 

より微妙なケースは、十分なサイクル候補があるにもかかわらず、その残りの次数が残りのすべての頂点をサポートできない場合に発生します。 このような場合、拡張中にキューが早期に空になり、建設が停止します。 これは、必要な木の端と利用可能な付着能力の間の不一致に正確に対応し、有効な花のような構造を妨げます。
