 ## 解決策
 ## 問題の理解

 パーティーで人々のグループが与えられ、最初はそれぞれがいくつかのキャンディーを持っています。 各人は、指定された数のキャンディーを 1 回だけ他の人に与えることができます。その量は 2 のべき乗で、現在保持しているキャンディーを超えない範囲で与えられます。 目標は、各人が最大 1 人の他の人からキャンディーを受け取るようにしながら、すべての人が最終的に同じ数のキャンディーを手に入れることです。 言い換えれば、すべての転送後に全員が同じ数のキャンディーを持つように、キャンディー転送の 1 対 1 のマッピングを見つける必要があります。 

入力は複数のテスト ケースを提供します。 For each test case, we know how many people are present and the number of candies each person initially has. The output is a simple "Yes" if the transfers can be arranged to satisfy both fairness and equality or "No" otherwise.

 The constraints are such that the number of people can be up to 200,000, and the total sum over all test cases is also up to 200,000. 人それぞれが我慢できるのは、$10^9$キャンディー。 これにより、キャンディーの転送の考えられるすべてのシーケンスを試行するソリューションは除外されます。これは、組み合わせ爆発的な可能性があるためです。 代わりに、テスト ケースごとに線形または線形に近いアプローチが必要です。 

明らかではないエッジ ケースには、全員がすでに同じ数のキャンディーを持っている状況、キャンディー間の差が 2 の累乗である状況、差が 2 の累乗として表現できない状況、または 1 対 1 のマッピングでペアにできない状況が含まれます。 たとえば、入力が次の場合、`[1, 2, 3]`, 最初はキャンディーを3の人から1の人に、2から2人に移そうとするかもしれませんが、1人が複数の人から受け取ることができないため失敗します。 2 のべき乗に一致する 1 対 1 の転送を調整できるため、ここでの正しい出力は「Yes」です。 

## アプローチ

 ブルートフォースアプローチでは、可能なすべての転送シーケンスをシミュレートし、2 の累乗の授受の各組み合わせをチェックしようとします。 これには、各人のキャンディーの 2 つのサブセットのすべてのべき乗を生成し、それらを他のすべての人と照合し、最終的な数が等しいかどうかを確認することが含まれます。 可能性の数は指数関数的に増加します$n$そして各キャンディーのビット数もカウントされます。 のために$n$その周り$10^5$、これは絶望的に遅いです。 

重要な点は、各転送は 2 の累乗でなければならず、与え手と受け手の固有のペアの間でのみ発生できるということです。 これは、問題は、キャンディーの目標数と各人の最初のキャンディーの違いが、1 対 1 の割り当てを可能にする 2 の累乗和として表現できるかどうかをチェックすることを意味します。 まず、キャンディーの目標数を計算します。これは、全員が同じ数で終了する必要があるため、すべてのキャンディーの平均でなければなりません。 キャンディーの合計が人数で割り切れないと無理です。 次に、キャンディーを与える必要がある人とキャンディーを受け取る必要がある人に分けます。 各寄付金額は 2 の累乗である必要があり、各受け取り金額は寄付者と一致する必要があります。 2 のべき乗の最大の差を最初に考慮し、それらを貪欲にマッチングすることで、そのようなペアリングが可能かどうかを確認できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^(n log max_a)) | O(n) | 遅すぎる |
 | 最適 | O(n log max_a) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、すべてのキャンディーの合計を計算します。 合計が人数で割り切れない場合は、「いいえ」と出力して次のケースに進みます。 これにより、均一なターゲットが数学的に可能であることが保証されます。 
2. キャンディーの目標数を次のように計算します。`target = sum(a) // n`。 
3. 人ごとに差を計算します`diff = a[i] - target`。 もし`diff > 0`、この人はキャンディーを配らなければなりません。 もし`diff < 0`、この人はキャンディーを受け取る必要があります。 
4. 授受の差分を 2 つの別々のリストに保存します。 受信差の絶対値を取得します。 
5. 両方のリストについて、それぞれの違いを個別の 2 のべき乗の合計に分解してみます。 これは、差分のバイナリ表現をチェックすることと同じです。 バイナリ表現で設定された各ビットは、次の転送に対応します。$2^k$キャンディー。 
6. 2 の累乗ごとに、対応するギバーとレシーバーが一致するのに十分な数があることを確認します。 これは、提供できるギバーの数を数えることによって行われます。$2^k$受信機は何台必要ですか$2^k$。 いずれの累乗においても、ギバーの数がレシーバーに対して不十分な場合は、「いいえ」と出力します。 
7. 2 の累乗の差がすべて正常に一致した場合は、「Yes」と出力します。 

機能する理由: 2 の累乗への貪欲な分解は、任意の整数を個別の 2 のべき乗の合計として一意に表現できるため、機能します。 ビットごとに与える側と受け取る側を一致させることで、各人が最大 1 人に与え、最大 1 人から受け取ることが保証され、問題の制約が満たされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can_equalize_candies(n, candies):
    total = sum(candies)
    if total % n != 0:
        return False
    target = total // n
    give_counts = {}
    receive_counts = {}
    
    for c in candies:
        diff = c - target
        if diff == 0:
            continue
        x = abs(diff)
        bits = []
        i = 0
        while x:
            if x & 1:
                bits.append(1 << i)
            x >>= 1
            i += 1
        if diff > 0:
            for b in bits:
                give_counts[b] = give_counts.get(b, 0) + 1
        else:
            for b in bits:
                receive_counts[b] = receive_counts.get(b, 0) + 1
    
    for b in receive_counts:
        if receive_counts[b] > give_counts.get(b, 0):
            return False
    return True

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    print("Yes" if can_equalize_candies(n, a) else "No")
```このソリューションでは、まず均一なターゲットが可能かどうかを確認します。 差は 2 の累乗に分解され、各累乗ごとに必要な転送のカウントが維持されます。 これらの数を照合することで、1 対 1 の制約を効率的に適用します。 誰もがすでに同じ数のキャンディーを持っているなどのエッジケースは、差がゼロであるため自然に処理されます。

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log max_a) | それぞれの差は 2 の累乗に分解され、これは max_a | のビット数に比例します。 
| スペース | O(n) | 与える側と受け取る側のパワーのカウントを保存する |
