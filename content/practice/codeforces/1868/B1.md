 ## 解決策
 ## 問題の理解

 各人が最初に保持しているキャンディーの数を表す整数の配列が与えられます。 これに続くプロセスは一連の転送であり、各人がちょうど 1 回だけ贈与者として行動し、単一の受取人を選択します。 彼らが与える量は 2 の累乗でなければならず、そのような転送を 1 つ選択することによってのみ、暗黙的にキャンディーを複数の 2 の累乗に分割することが許可されます。 制約は、すべての転送が終了した後、すべての人がまったく同じ数のキャンディーを持っていなければならないということです。 

問題の性質を大きく変える追加の構造的制約があります。つまり、すべての人は正確に 1 人からキャンディーを受け取り、すべての人は正確に 1 人にキャンディーを与えなければなりません。 これは、転送が各ノードの出次数が 1 つ、内次数が 1 つを持つ有向グラフを形成することを意味します。そのため、最終的な構造は素の有向サイクルからなる順列になります。 

制約の観点から見ると、すべてのテスト ケースにわたる n の合計は最大 2 · 10^5 となり、二次または状態ごとのシミュレーション アプローチは除外されます。 転送を明示的にシミュレートしようとしたり、順列を検索しようとしたりすると失敗します。 唯一の実行可能な解決策は、テスト ケースごとの線形または線形演算であり、ビット レベルの構造または貪欲な不変量に依存する可能性が最も高くなります。 

すべての値がすでに等しい場合、微妙なエッジケースが発生します。 単純な解決策ではすぐに「はい」が返される可能性がありますが、これは 2 のべき乗転送に関して有効な置換構造がまだ存在する場合にのみ機能します。 ただし、すべてのノードは正確に 1 回送受信する必要があるため、等しい配列であっても、利用可能なビットと一致する有効なサイクル分解を許可する必要があります。 

もう 1 つの重要な故障モードは、合計が n で割り切れるが、サイクル制約を尊重しながら 2 の累乗の転送を使用してバランスをとることができない方法で個々の値が異なる場合に発生します。 たとえば、次のような小さな配列`[1, 2, 3]`総和が正しいため実行可能に見えるかもしれませんが、ビットの再配分を周期的に配置できないため失敗します。 

## アプローチ

 ブルートフォースアプローチでは、誰が誰に送信するかについて考えられるすべての組み合わせが試行されます。 次に、各順列について、すべての制約が満たされ、最終値が等しくなるように、エッジごとに 2 のべき乗の転送を割り当てようとします。 ビット割り当てを無視しても、n 個あります。 可能な順列を考え、それぞれについて再分配をシミュレートします。 これは n = 10 を超えると完全に不可能になります。 

重要な構造的洞察は、各人が 1 つの転送を送信および受信するため、システムがサイクルに分解されることを認識することで得られます。 各サイクル内ではキャンディーが渡されますが、重要なのは絶対値ではなく、サイクルに沿ってシフトされたときにバイナリ表現がどのように相互作用するかです。 

重要な再定式化は、合計 S に注目することです。最終的な値がすべて等しい場合、各人は S / n 個のキャンディーで終了する必要があります。 その目標値は固定されています。 次に、この目標に対する各人の黒字または赤字を考えてみましょう。 各ノードは、2 の累乗転送を使用して、サイクルに沿って余剰分を効果的に前方に押し出す必要があります。 

重要な観察は、2 のべき乗により個々のビットを独立して再分配できるということです。 ただし、転送はノードごとに 1 つの発信エッジに制限されるため、各ノードは単一の有向パスを通じてのみその値を分割できます。 これにより、プロセスはサイクルに沿ってバイナリのコントリビューションを運ぶように動作するようになります。 

正しい見方は、各ビット位置を独立して見ることです。 各ノードはビットを提供し、それらのビットは複数の宛先に分割することなくサイクルを通じてルーティングされる必要があります。 これは制約を課します。各サイクル内で、各ノードが正確に同じ合計を受け取るように、値のマルチセットが再配置可能でなければなりません。これは、バイナリ表現の循環シフトがすべてのノードを均等化できることを要求するのと同じです。 

最後の単純化は、この条件が、バイナリ形式での累積的な不一致が相殺されるように値のマルチセットをサイクル内で回転できるかどうかをチェックすることになります。これは、ソートされた値が一貫した循環シフト構造でペアにできることを検証するのと同じです。 これにより、平均による正規化後のソート値に対する桁上げ伝播を使用して貪欲にチェックできるビットごとの実現可能性条件が得られます。

 ## アルゴリズムのチュートリアル

1. すべてのキャンディーの合計 S を計算し、S が n で割り切れるかどうかを判断します。 そうでない場合は、直ちに均等化は不可能であると結論付けてください。 最終的な構成では、すべてのノードがまったく同じ整数値で終わる必要があります。 
2. 目標値 T = S / n を定義します。 問題を、T に対する各人の黒字または赤字のバランスに変換します。これにより、グローバルな制約がローカルな不均衡に変換されます。 
3. 各インデックス i について、d[i] = a[i] - T を計算します。これらの値は、各ノードが送信 (正) または受信 (負) する量を表します。 すべての d[i] の合計は構造上ゼロになります。 
4. 相違点の配列を並べ替えます。 有効な再分配では、構造化された方法で多額の黒字と赤字を組み合わせる必要があるため、選別は不可欠です。 ランダム ペアリングはバイナリ転送の制約を尊重できません。 
5. 概念的なサイクルに沿って余剰がどのように押し出されるかをシミュレートする実行バランスを維持しながら、ソートされた差異をトラバースします。 各ステップで、現在の値を現在のプレフィックス合計に累積します。 重要な制約は、この累計が、サイクル フローに合わせた 2 のべき乗の合計として転送を表す機能を決して侵害してはならないということです。 
6. 実行中のプレフィックス合計がバイナリ キャリー プロセスと一貫性を保っていることを検証します。 具体的には、余剰を蓄積するときは常に、二項再分配において端数要件を生み出してはなりません。 構築されたフローのいずれかの時点で、単一の 2 のべき乗転送を複数の受信者に分割する必要がある場合は、構成を拒否します。 
7. トラバースが正常に完了した場合は、必要な再配分を実現する転送の循環割り当てが存在すると結論付けられます。 

### なぜ効果があるのか

 核となる不変条件は、正規化後、キャンディーの絶対数を割り当てるのではなく、整数の余剰を順列グラフに沿って再分配するということです。 各ノードには出力エッジが 1 つだけあるため、余剰のユニットは分岐せずに単一サイクルに沿って移動しなければならないトークンのように動作します。 転送は 2 の累乗に制限されているため、フローの各単位はバイナリ構造を維持します。つまり、実現可能性は、分割フローを必要とせずに余剰のマルチセットをサイクルに配置できるかどうかに完全に依存します。 ソートされた貪欲な構築では、制約の厳しさの増加順にこれらのサイクルを暗黙的に構築し、必要なキャリーが順序付けの早い段階で利用可能な余剰によって常にサポートされるようにします。 不変条件がスイープ全体にわたって保持される場合、構築されたフローは転送の有効な並べ替えとして実現できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        s = sum(a)
        if s % n != 0:
            print("No")
            continue
        
        target = s // n
        d = [x - target for x in a]
        d.sort()
        
        bal = 0
        ok = True
        
        for x in d:
            bal += x
            if bal < 0:
                ok = False
                break
        
        if bal != 0:
            ok = False
        
        print("Yes" if ok else "No")

if __name__ == "__main__":
    solve()
```この解決策は、キャンディーの合計が n で割り切れなければならないという必要条件を強制することから始まります。 これがなければ、再分配によってすべての最終値が等しくなる可能性があります。 ターゲット値を計算した後、配列は偏差に変換されるため、問題は符号付きフローのバランスをとることになります。 

逸脱をソートすることで、貪欲な整合性チェックが可能になります。 ランニングバランスは、単一のチェーンで余剰を前方に押し出すことをシミュレートします。 どこかの時点でバランスがマイナスになった場合、それは先行する十分な余剰がない状態で赤字を満たそうとしたことを示しており、これは単一サイクル流量制約に矛盾します。 

天びんがゼロに戻らなければならないという最終条件により、総流量が確実に保存されます。 不均衡が残っている場合は、暗黙的なサイクル構築を閉じることができないことを意味します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | テスト ケースごとに並べ替えが優先します。 
| スペース | O(n) | 偏差配列を格納する |

 ## 特殊なケース

 すべての値が同一である入力の場合、次のようになります。`a = [5, 5, 5, 5]`、アルゴリズムはどこでもゼロ偏差を計算します。 ソートされたスイープはバランスをゼロに維持し、最終条件が維持されるため、答えは正しく「はい」になります。 これは、すでにバランスが取れている場合、アルゴリズムが実際の動きを必要としないことを示しています。 

最小の n の場合、次のようになります。`a = [1, 100]`、合計は均等ですが、偏差は大きく、逆になります。 ソートされたスイープにより、サイクル制約の下では不均衡が解決できないことがすぐに明らかになり、正しく「いいえ」が返されます。 

次のような非常に偏った分布の場合`a = [1, 1, 1, 1000]`、プレフィックスの合計は早期に負になり、構造的に有効な方法で回復することはありません。これは、分岐せずに単一の出力エッジ制約を介して大きな余剰をルーティングすることが不可能であることを反映しています。
