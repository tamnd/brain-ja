 ## 解決策
 ## 問題の理解

 値の配列があります。 2 つの演算が混在しています。1 つの演算は配列の連続部分を再配置し、もう 1 つは連続部分の合計を求めます。 

K シフトは、間隔全体の通常の回転ではありません。 選択した間隔は、サイズ K の連続したブロックに分割されます。各ブロック内では、最初の値が最後に移動し、他の値は 1 つずつ左に移動します。 K の可能な値は 2 と 3 のみです。これは、再配置が小さな周期的な並べ替えであることを意味します。 

課題は、配列の長さと操作の数が両方とも 200000 に達する可能性があることです。更新またはクエリのたびに一定の間隔でスキャンするソリューションでは、最悪の場合でも約 4×10^10 の操作を実行できますが、これは可能性をはるかに超えています。 すべての操作は、間隔の長さではなく配列サイズの対数に依存する必要があります。 

主なトラップは、K シフトが K だけでなく間隔の開始位置に依存するという事実から生じます。たとえば、2 シフトを位置 1 ～ 4 のスワップ (1,2) および (3,4) に適用する一方で、2 シフトを位置 2 ～ 5 のスワップ (2,3) および (4,5) に適用します。 セグメントが 2 または 3 シフトされたかどうかだけを記憶する構造では、必要な情報が失われます。 

もう 1 つのエッジ ケースは、いくつかの部分シフト後のクエリです。 考慮する：```
3 2
1 2 3
1 1 2 2
2 1 3
```最初の操作では、配列が次のように変更されます。`[2,1,3]`、したがって、答えは次のようになります。```
6
```操作をグローバルローテーションとして扱う不注意な実装では、間違った順序が生成され、その後のクエリが失敗する可能性があります。 

2 番目のエッジ ケースは、セグメント ツリー ノードが完全に更新範囲内にあるものの、その長さが K で割り切れない場合に発生します。たとえば、K=2 で更新すると、`[1,6]`子セグメントに遭遇する可能性があります`[1,3]`。 そのノードの長さが奇数であるため、全体としてシフトすることはできません。 更新は、遅延タグを誤って適用するのではなく、降順を続行する必要があります。 

## アプローチ

 直接的な解決策は、実際の配列を保存することです。 K シフトの場合、サイズ K のブロックの間隔を反復し、各ブロックを回転します。 範囲の合計は、要求された間隔ですべての値をスキャンすることによって計算されます。 このアプローチは、説明されている操作を正確に実行するため正しいですが、1 回の操作で O(n) 要素に影響を与える可能性があります。 200,000 回の操作では、最悪のケースでは約 4×10^10 要素の訪問に達します。 

有益な観察は、K が非常に小さいということです。 2 シフトでは、操作の開始を基準とした 2 を法とする位置のみが考慮されます。 3 シフトは 3 を法とする位置のみを考慮します。両方の周期が 6 を割るため、すべての演算は 6 を法とする位置の 6 つの剰余クラスの順列として表すことができます。 

セグメント ツリー ノード内の要素の正確な順序を保存する代わりに、6 つの合計を保存します。 バケット内の値`i`グローバルインデックスが残っているノード内のすべての要素の合計です`i`モジュロ 6。完全にカバーされたノード上の K シフトは、これら 6 つのバケットを単純に並べ替えます。 実際の位置を再構築する必要はありません。 

遅延伝播は、各ノードに適用された累積された順列を保存します。 範囲クエリは、対象となるノードから 6 つのバケットを収集し、適切な残余を追加します。 範囲の更新は、ノード全体を変換できない場合にのみ行われます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 操作ごとに O(n) | O(n) | 遅すぎる |
 | 最適 | 操作ごとに O(6 log n) | O(6n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのノードが 6 つの合計を格納するセグメント ツリーを構築します。 6 番目のバケットは、次の 6 つの可能な値に対応します。`index mod 6`。 この表現は、将来のシフトやクエリで必要な情報を正確に保持します。 
2. 完全な K シフト更新を受け取るノードの場合、6 つの剰余バケットの順列を計算します。 ブロックは更新間隔の左側の境界から始まるため、置換は更新間隔の左側の境界に依存します。 
3. ノードの 6 つの合計に順列を適用し、それをノードの遅延順列と組み合わせます。 ノードは、子を参照することなく、シフト後の同じ配列セグメントを表します。 
4. 完全にカバーされたノードの長さが K で割り切れないため、全体としてシフトできない場合は、その遅延情報をその子にプッシュし、再帰的に続行します。 これにより、不完全なブロックを含むセグメントに無効な変換が適用されるのを防ぎます。 
5. 範囲合計クエリの場合は、セグメント ツリーに再帰的にアクセスします。 ノードが完全にクエリ間隔内にある場合は、そのノード内のすべての要素が要求された範囲に属しているため、保存されている 6 つの合計をすべて加算します。 

機能する理由: すべての更新では、ブロック内の要素の位置のみが変更されます。 ブロック サイズは 2 または 3 であるため、要素の宛先はその位置のモジュロ 6 とシフトされた間隔の開始位置のみに依存します。 保存された 6 つの合計はこれらのクラスを正確に保存するため、すべての変換を順列で表すことができます。 遅延伝播により、セグメントを拡張せずに表現が有効に保たれ、クエリ分解によりすべての要素が 1 回だけ収集されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.tree = [[0] * 6 for _ in range(4 * self.n)]
        self.lazy = [list(range(6)) for _ in range(4 * self.n)]
        self.build(1, 1, self.n, arr)

    def build(self, p, l, r, arr):
        if l == r:
            self.tree[p][l % 6] = arr[l - 1]
            return
        m = (l + r) // 2
        self.build(p * 2, l, m, arr)
        self.build(p * 2 + 1, m + 1, r, arr)
        for i in range(6):
            self.tree[p][i] = self.tree[p * 2][i] + self.tree[p * 2 + 1][i]

    def apply_perm(self, p, perm):
        old = self.tree[p]
        self.tree[p] = [0] * 6
        for i in range(6):
            self.tree[p][perm[i]] = old[i]

        cur = self.lazy[p]
        nxt = [0] * 6
        for i in range(6):
            nxt[i] = cur[perm[i]]
        self.lazy[p] = nxt

    def push(self, p):
        if self.lazy[p] != list(range(6)):
            perm = self.lazy[p]
            self.apply_child(p * 2, perm)
            self.apply_child(p * 2 + 1, perm)
            self.lazy[p] = list(range(6))

    def apply_child(self, p, perm):
        old = self.tree[p]
        self.tree[p] = [0] * 6
        for i in range(6):
            self.tree[p][perm[i]] = old[i]

        cur = self.lazy[p]
        nxt = [0] * 6
        for i in range(6):
            nxt[i] = cur[perm[i]]
        self.lazy[p] = nxt

    def get_perm(self, l, k):
        perm = list(range(6))
        for i in range(6):
            pos = i
            rel = (pos - l) % k
            if rel == 0:
                new_pos = (pos + k - 1) % 6
            else:
                new_pos = (pos - 1) % 6
            perm[i] = new_pos
        return perm

    def update(self, p, l, r, ql, qr, k):
        if qr < l or r < ql:
            return
        if ql <= l and r <= qr and (r - l + 1) % k == 0:
            self.apply_perm(p, self.get_perm(ql % 6, k))
            return
        if l == r:
            return
        self.push(p)
        m = (l + r) // 2
        self.update(p * 2, l, m, ql, qr, k)
        self.update(p * 2 + 1, m + 1, r, ql, qr, k)
        for i in range(6):
            self.tree[p][i] = self.tree[p * 2][i] + self.tree[p * 2 + 1][i]

    def query(self, p, l, r, ql, qr):
        if qr < l or r < ql:
            return 0
        if ql <= l and r <= qr:
            return sum(self.tree[p])
        self.push(p)
        m = (l + r) // 2
        return self.query(p * 2, l, m, ql, qr) + self.query(p * 2 + 1, m + 1, r, ql, qr)

def solve():
    n, m = map(int, input().split())
    arr = list(map(int, input().split()))
    seg = SegTree(arr)
    ans = []

    for _ in range(m):
        data = list(map(int, input().split()))
        if data[0] == 1:
            _, l, r, k = data
            seg.update(1, 1, n, l, r, k)
        else:
            _, l, r = data
            ans.append(str(seg.query(1, 1, n, l, r)))

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```ツリーはグローバル インデックスのモジュロ 6 で合計を格納するため、ビルド フェーズでは各初期値が 1 つのバケットに正確に配置されます。 遅延配列は、これら 6 つのバケットを並べ替えたものです。 遅延操作を適用するということは、バケットの合計を移動し、既存の保留中の置換を新しい置換で構成することを意味します。 

順列関数は、更新間隔の左側の境界を使用します。 K シフトの場合、相対位置が 0 である要素はそのブロックの末尾に移動し、他の相対位置は 1 つ左に移動します。 両方の可能なブロック サイズが 6 を除算するため、モジュロ 6 を使用すると機能します。 

アップデート条件`(r - l + 1) % k == 0`は不可欠です。 セグメント ツリー ノードは要求された範囲内にある可能性がありますが、まだ不完全なブロックが含まれているため、変換を直接受け取ることができません。 

Python の整数はオーバーフローしません。これは、合計が約 2×10^14 に達する可能性があるため、必要です。 ツリー内のすべてのインデックス付けは、問題ステートメントに一致するように 1 から始まりますが、格納された残差は実際のインデックスのモジュロ 6 を使用します。

def run(inp: str) -> str:

    data = sys.stdin.read().split()
    sys.stdin = old

    it = iter(data)
    n = int(next(it))
    m = int(next(it))
    arr = [int(next(it)) for _ in range(n)]

    seg = SegTree(arr)

        else:
            l = int(next(it))
            r = int(next(it))
            out.append(str(seg.query(1, 1, n, l, r)))

    return "\n".join(out)

 ## 特殊なケース

 最初のエッジ ケースは、1 以外の位置から始まる更新です。 テストでは:```
5 3
10 20 30 40 50
1 2 5 2
2 2 4
```セグメント`[2,5]`になる`[30,20,50,40]`その間隔の中で。 順列は使用します`l mod 6`、したがって、保存された残差クラスは正しく移動されます。 

2 番目のエッジ ケースは、長さがシフト サイズと一致しないセグメント ツリー ノードです。 のために：```
3 2
1 2 3
1 1 2 2
2 1 3
```更新は 2 つの要素のみに影響するため、3 番目の要素は変更しないでください。 更新ルーチンは、無効なノード長に K シフトを適用することを拒否し、変換されたすべてのノードが完全なブロックを表すまで下方向に続行します。 

3 番目のエッジ ケースは、合計を保持しながら内部順序を変更するシフトを適用することです。 ケース:```
6 2
1 2 3 4 5 6
1 2 6 3
2 2 5
```いくつかの残基クラスの配置を変更しますが、クエリでは依然としてそれらを結合した値のみが必要です。 6 バケット表現では、注文全体を保存しなくても、後の部分的なクエリに十分な情報が保持されます。
