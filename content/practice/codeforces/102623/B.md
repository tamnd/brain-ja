 ## 解決策
 ## 問題の理解

 課題は、オリジンから送信されたメッセージがどれくらい早く少なくとも 1 つのスターに到達できるかを見つけることです。 星は 3 次元空間内の点であり、メッセージは 1 年に 1 単位の距離の速度で直線的に移動します。 目的地は指定された星のいずれかになる可能性があるため、答えは単純に原点から任意の星までの最小距離になります。 

各入力ポイントは 1 つの可能な目的地を表します。 座標のスターのために`(x, y, z)`、必要な移動時間はからのユークリッド距離です。`(0, 0, 0)`その時点まで、つまり`sqrt(x^2 + y^2 + z^2)`。 出力はこれらの距離の最小値であり、小数点以下 3 桁に四捨五入されます。 

星の数は最大でも 1000 個です。これは十分に小さいため、すべての星を 1 回検査できます。 二次動作のアルゴリズムではすでに約 100 万回の演算が実行されており、ここでは許容範囲ですが、問題の構造によりさらに単純な線形スキャンが可能になります。 座標値は絶対値で 1000 に制限されているため、二乗距離は Python の通常の整数範囲内に問題なく収まります。 

実装の詳細によっては、誤った答えが生じる可能性があります。 よくある間違いは、平方根を求めた後で距離を比較することですが、これは不必要であり、役に立たない精密な作業が発生する可能性があります。 もう 1 つの間違いは、印刷する桁数が少なすぎることです。 例えば：```
1
1 1 1
```正しい出力は次のとおりです。```
1.732
```距離はおよそ`1.73205`なので四捨五入が必要です。 丸めの代わりに切り捨てを行うプログラムは次のように出力します。`1.732`この場合は単なる偶然であり、10 進数の 4 桁目が答えを変える値で失敗する可能性があります。 

もう 1 つのエッジ ケースは、原点にあるスターです。```
1
0 0 0
```正しい出力は次のとおりです。```
0.000
```実装が最小距離を非常に大きな値ではなくゼロに初期化すると、すべての正の距離が誤って無視されます。 初期値では、最初の星に置き換えることができる必要があります。 

星の重複も可能です。```
2
5 0 0
5 0 0
```答えは次のとおりです。```
5.000
```ソリューションではすべての星を候補として扱う必要がありますが、最小距離のみが重要であるため、追加の情報を保存する必要はありません。 

## アプローチ

 直接的なアプローチは、すべての星の距離を計算し、見つかった最小値を保持することです。 これが機能するのは、すべての星が独立しているためです。 目的地間の相互作用はないため、すべての候補をチェックするだけで、最適な目的地が確実に見つかるようになります。 

より複雑な強引な解釈では、すべての星のペアを比較したり、不必要な幾何学的構造を構築したりする可能性がありますが、それらの操作はいずれも答えには寄与しません。 関連する唯一の関係は、各星と原点の間です。 したがって、有用な計算回数は、星ごとに正確に 1 回の距離計算です。 

重要な点は、この問題が固定点に最も近い点を求めていることです。 原点が変わらないため、並べ替えや検索の必要がありません。 1 回のパスで十分です。 平方根関数は増加するため、実際の距離の代わりに二乗距離を比較することもできます。 もし`a < b`、 それから`sqrt(a) < sqrt(b)`, したがって、二乗距離が最小の星は実際の距離も最小になります。 

すべての宛先をチェックすることで正確性が保証されるため、総当りが機能しますが、星の数が大幅に増加すると無駄になります。 答えは原点までの各点の距離にのみ依存するという観察により、解は線形スキャンに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n) | お(1) | スキャンとして実装されている場合は受け入れられます。 
| 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 星の数を読み取り、非常に大きな二乗距離を含む変数を準備します。 この値は、星を調べる前にこれまでに見つかった最良の答えを表します。 
2. 星ごとに計算します。`x * x + y * y + z * z`。 これは原点からの移動距離の 2 乗です。 2 乗値を比較すると、距離の順序を維持しながら、不必要な平方根の計算が回避されます。 
3. 現在の二乗距離が保存されている最小値より小さい場合は、保存されている最小値をこの値に置き換えます。 保存された値は常に、これまでに処理されたすべての星の中で最も近い星を表します。 
4. すべての星が処理されたら、最小二乗距離の平方根を計算し、小数点以下 3 桁で出力します。 

機能する理由: 入力の接頭辞を処理した後、保存される最小値は、その接頭辞内のすべての星の間の最小二乗距離になります。 次の星は、新しく最も近い星になるか、現在の答えを変更しないままになります。 この不変条件は、すべての星がチェックされるまで true のままであるため、最終的に保存された値は全体的に最も近い星に対応します。 最後のみ平方根を取ると、距離の 2 乗が必要な移動時間に変換されます。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

def solve():
    n_line = input().strip()
    if not n_line:
        return

    n = int(n_line)
    best = float('inf')

    for _ in range(n):
        x, y, z = map(int, input().split())
        dist2 = x * x + y * y + z * z
        if dist2 < best:
            best = dist2

    print(f"{math.sqrt(best):.3f}")

if __name__ == "__main__":
    solve()
```プログラムは値を 1 つだけ保持します。`best`、最も近い星の正体は無関係であるためです。 ループは、より良い候補が現れるたびに、アルゴリズムのウォークスルーの不変式と一致してそれを更新します。 

比較には二乗距離が使用されます。 これにより、浮動小数点平方根計算の繰り返しが回避され、すべての二乗距離が整数になるため、決定プロセスが正確に保たれます。 平方根演算は、最小値がすでに見つかった後に 1 回実行されます。 

出力形式は次を使用します`:.3f`、必要な小数点以下第 3 位までの四捨五入が実行されます。 無限大を使用した初期化は、最初の星がゼロを含むあらゆる可能な距離を持つ場合を処理します。

```実行は次のとおりです。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | すべての星は 1 回だけ訪問され、定数時間の演算が必要です。 |
 | スペース | お(1) | 現在の最小値のみが保存されます。 |

 星が最大 1000 個であれば、リニア スキャンは所定の制限内に簡単に収まります。 また、メモリ使用量が星の数に依存しないため、このアルゴリズムは適切に拡張できます。 

## テストケース```python
import sys
import io
import math

def solution(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n = int(input())
    best = float('inf')

    for _ in range(n):
        x, y, z = map(int, input().split())
        best = min(best, x * x + y * y + z * z)

    return f"{math.sqrt(best):.3f}"

assert solution("""3
0 1 1
2 0 0
0 -2 0
""") == "1.414", "sample 1"

assert solution("""1
0 0 0
""") == "0.000", "origin case"

assert solution("""3
1000 1000 1000
-1000 -1000 -1000
1 1 1
""") == "1.732", "large coordinates and minimum selection"

assert solution("""4
5 0 0
0 5 0
0 0 5
5 0 0
""") == "5.000", "duplicate equal distances"

assert solution("""2
-1000 0 0
0 999 0
""") == "999.000", "boundary coordinate values"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 単一の星`(0,0,0)`|`0.000`| 最小距離はゼロにすることができます。 
| での座標`1000`そして`-1000`|`1.732`| 大きな値と正しい比較 |
 | いくつかの同一の最近接距離 |`5.000`| 重複した候補は結果に影響しません。 
| 負の座標と境界座標 |`999.000`| 絶対位置は二乗距離によって決まります。 

## 特殊なケース

 距離がゼロの場合:```
1
0 0 0
```アルゴリズムは無限大から始まり、ゼロの二乗距離を計算し、保存されている最小値を置き換えます。 最後の平方根はゼロなので、出力される答えは次のようになります。`0.000`。 

重複したスターの場合:```
2
5 0 0
5 0 0
```最初の星は最小二乗距離を 25 に設定します。二番目の星も二乗距離は 25 なので、最小値は変わりません。 最終的な答えは、`5.000`。 

丸め精度については、次のとおりです。```
1
1 1 1
```アルゴリズムは二乗距離を保存します`3`そして計算します`sqrt(3)`最後に一度だけ。 フォーマットされた出力では値が正しく丸められます。`1.732`。 

負の座標の場合:```
1
-1000 0 0
```二乗距離は`1000000`、と同じ`(1000,0,0)`。 値は比較前に二乗されるため、座標の符号は距離に影響しません。
