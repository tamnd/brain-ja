 ## 解決策
 ## 問題の理解

 ゲームでは、1 から 8 までの番号が付けられた 8 つの可能な記号を文字列として使用します。小さい桁の前に大きい桁が現れる位置のペアごとにペナルティが発生します。 ペナルティの量は、マトリックスを通じて関係する 2 桁の値にのみ依存します。`P`。 

ペナルティを計算する前に、2 桁の値をグローバルに繰り返し交換することがあります。 スワップ操作ではポジションは選択されません。 代わりに、ある数字が出現するたびに別の数字に変更され、他の数字が出現するたびに元に戻ります。 数字の各ペアには、行列からの独自のコストがあります。`C`。 

タスクは、スワップ コストと最終的な反転ペナルティの合計を最小限に抑える一連のグローバル ディジット スワップを選択することです。 

文字列の長さは次のとおりです`100000`、したがって、文字列を少ない回数スキャンすることは問題ありませんが、位置の二乗の数に応じた方法は不可能です。 アルファベットのサイズは 8 つの値にのみ固定されており、問題の性質が変わります。 文字列の長さの指数関数的な演算は不可能ですが、8 つのシンボルにわたる演算は完全に調査できます。`8! = 40320`。 

いくつかの詳細が、他の点では合理的な解決策を壊す可能性があります。 まず、スワップの最適なシーケンスは、必ずしも 1 回のスワップではありません。 たとえば、現在のマッピングが`1 -> 3`1 と 3 を直接交換するとコストが 100 になる可能性がありますが、別の桁を介した 2 つのより安価な交換のコストはわずか 10 になる可能性があります。直接交換のみを試みるソリューションは失敗します。 

第 2 に、カウントのマルチセットだけでなく、桁値の最終的な配置も重要です。 たとえば、文字列`21`と`P[2][1] = 5`有用な変換が存在しない場合、反転のみが残るため、答えは 5 になります。 数字の頻度だけをカウントする不注意な解決策では、それを区別できません。`12`。 

第三に、文字列に現れない数字も依然として重要です。 これらは、安価なスワップ パスの中間ノードになる可能性があります。 たとえば、すべてを変換すると、`1`に`3`数字で見ると一番安いかもしれない`8`、元の文字列に何も含まれていない場合でも、`8`。 

## アプローチ

 直接的なアプローチでは、考えられるすべてのスワップ シーケンスを試します。 すべての操作で 8 つの値のうち 2 つが交換されるため、どの状態からでも 28 通りの動きが可能です。 状態は、8 桁の現在の順列です。 各ノードが順列であり、各エッジが 1 桁のスワップであるグラフを構築できます。 状態の数は`8! = 40320`したがって、このグラフ上の最短経路は完全に実現可能です。 

状態を記憶せずにすべての可能なスワップ シーケンスを試す総当りバージョンは、間違った検索方法です。 同じ順列を何度も再利用することができ、シーケンスの数は際限なく増加します。 各ステップに 28 の選択肢があり、たとえ奥行きが浅くても何百万もの可能性が生まれます。 

有益な観察は、文字列は 8 つのシンボルの最後の順列のみを考慮しているということです。 文字列のスワップをシミュレートする必要はありません。 必要な情報は 2 つだけです。すべての順列に到達するための最も安価な方法と、各順列を適用した後の反転コストです。 

最初の部分は、40320 の状態での最短経路問題になります。 ダイクストラのアルゴリズムは、すべてのスワップ コストが負ではないため機能します。 

すべての順列に到達するための最小コストを計算した後、最終的なマッピングとしてすべての順列を試行します。 反転コストは桁数から計算できます。 可能な最後の数字は 8 つだけなので、各順列について、元の文字が各最後の数字になる数を知るだけで済みます。

 ## アルゴリズムのチュートリアル

 1. 8 桁のすべての順列を状態としてエンコードします。 位置の値`i`どの桁が元の桁であるかを示します`i`となる。 
2.恒等順列からダイクストラを実行します。 任意の状態から、マップされた 2 つの数字を交換することによって得られる 28 の可能な状態を生成します。 エッジの重みはそのスワップのコストです。 これにより、考えられるすべての最終的な再ラベル付けの最小操作コストが計算されます。 
3. 元の各数字が文字列内に何回出現するかを数えます。 この時点以降、変換コストのために正確な位置は必要ありません。 
4. すべての順列状態について、元の各桁によって生成される最終桁の数を計算します。 次に、最後の桁の値のすべてのペアを考慮して、その反転ペナルティを計算します。`a > b`。 貢献は次のとおりです。`count[a] * count[b] * P[a][b]`なぜなら、`a`そしてあらゆる出来事が`b`ペナルティ付きペアを形成する場合`a`前に置かれます`b`。 
5. 順列のダイクストラ距離と反転ペナルティを追加します。 40320 個の順列すべての最小値が答えです。 

これが機能する理由: スワップ操作の考えられるすべての結果は、8 桁のラベルの 1 つの順列にすぎません。 ダイクストラは、そのような各順列に到達する最も安価な方法を見つけます。 順列が修正されると、残りのコストはすべての元のシンボルの最後の桁によって完全に決定されるため、反転式によって正確なペナルティが与えられます。 考えられるすべての最終的な置換がチェックされるため、見つかった最小値が全体的な最適値になります。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n = int(input())
    s = input().strip()

    P = [[0] * 8 for _ in range(8)]
    for i in range(8):
        P[i] = list(map(int, input().split()))

    C = [[0] * 8 for _ in range(8)]
    for i in range(8):
        C[i] = list(map(int, input().split()))

    cnt = [0] * 8
    for ch in s:
        cnt[ord(ch) - ord('1')] += 1

    perms = []
    ids = {}
    from itertools import permutations

    for p in permutations(range(8)):
        ids[p] = len(perms)
        perms.append(p)

    m = len(perms)
    dist = [10**30] * m

    start = tuple(range(8))
    dist[ids[start]] = 0
    pq = [(0, ids[start])]

    while pq:
        d, u = heapq.heappop(pq)
        if d != dist[u]:
            continue
        cur = list(perms[u])
        for i in range(8):
            for j in range(i + 1, 8):
                nxt = cur[:]
                nxt[i], nxt[j] = nxt[j], nxt[i]
                v = ids[tuple(nxt)]
                nd = d + C[i][j]
                if nd < dist[v]:
                    dist[v] = nd
                    heapq.heappush(pq, (nd, v))

    ans = 10**30

    for idx, p in enumerate(perms):
        final_cnt = [0] * 8
        for old in range(8):
            final_cnt[p[old]] += cnt[old]

        inv = 0
        for high in range(8):
            for low in range(high):
                inv += final_cnt[high] * final_cnt[low] * P[high][low]

        ans = min(ans, inv + dist[idx])

    print(ans)

if __name__ == "__main__":
    solve()
```実装の最初の部分では、8 つのラベルのすべての順列が作成されます。 アルファベットのサイズは固定されているため、これでも十分小さいです。 順列からインデックスへの辞書により、ダイクストラ中に一定の時間遷移が可能になります。 

ダイクストラ グラフはエッジを明示的に保存しません。 削除されたステートごとに、コードはオンデマンドで 28 の可能なスワップを生成します。 順列配列は、すべての演算後に元の各桁がどこに移動するかを表します。 

最後のループでは、考えられる終了順列をそれぞれ評価します。 カウントは順列に従って変換され、その後、位置ではなく桁値に対して反転寄与が計算されます。 これにより、次への依存が回避されます。`n`アルゴリズムの高価な部分の間。 

Python の整数は、大きな値に自然に使用されます。 スワップ コストと反転数の両方が大きくなる可能性があるため、可能な最大の答えは 32 ビットの制限を超える可能性があります。

 ## 特殊なケース

 文字列に数字が 1 つしか含まれていない場合、アルゴリズムは 1 つのシンボルをカウントし、位置のペアがないため、すべての順列の反転寄与はゼロになります。 恒等順列は常にコスト 0 で利用できるため、ダイクストラ部分は引き続き機能します。 

数字が 0 回出現しても、アルゴリズムはその数字を順列検索に含めます。 たとえば、文字列に数字のみが含まれている場合、`1`そして`2`、数字`8`依然として最も安価なスワップの一部となる可能性があります。 未使用の数字を無視すると、考えられる中間変換が誤って削除されてしまいます。 

すべての数字が等しい場合、たとえば`11111`、考えられるすべての最終文字列も均一であるため、すべての反転項の因数は 0 です。 答えは最小変換コストです。何もしないことは許可されているため、ゼロです。 

直接スワップが高価であるが、一連のスワップが安価な場合は、順列最短パスがそれを処理します。 たとえば、ラベルを変更する`1`ラベルに`3`交換が必要になる場合があります`1`と`8`その後`8`と`3`。 ダイクストラは、そのルートを直接エッジと比較し、より安価なシーケンスを維持します。
