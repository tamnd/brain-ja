 ## 解決策
 # 問題の理解

 このタスクは、意図的に悪いグループ化アルゴリズムに対する建設的な攻撃です。 最適なパーティションを見つけるように求められるわけではありません。 代わりに、指定された整数に対して`k`、最大 300 個の整数とそれらの有効なグループを作成する必要があります。 私たちが提供するグループ化は、最適なグループ化よりも悪いものであってもかまいませんが、`Y`グループの場合、偽の貪欲アルゴリズムは正確に使用する必要があります`Y + k`グループ。 

数値は競合グラフを定義します。 2 つの数値は、gcd が 1 より大きい場合、同じグループに入れることができないため、接続されます。 有効なグループは、このグラフの独立したセットです。 出力パーティションは、単にこのグラフの色付けです。 貪欲なアルゴリズムでは、指定された順序で頂点に色が付けられ、常に可能な限り最小の色が使用されます。 

の制限`k`が主な手がかりです。 以来`k`が最大 7 である場合、必要なのは小さな固定構造だけであり、可能な入力の検索は必要ありません。 数値の制限が 300 であるため、グラフ ガジェットに十分なスペースが与えられます。 数値自体は次のように大きくなる可能性があります`10^18`これにより、素因数を使用してグラフのエッジをエンコードできるようになります。 

提供されたパーティションが実際には有効ではない可能性があるため、不用意に構築すると失敗することがよくあります。 たとえば、数値については同じグループを出力します。`6`そして`10`は無効です。`gcd(6,10)=2`。 もう 1 つのよくある間違いは、意図した貪欲グラフを構築したが、貪欲アルゴリズムが入力順序に依存することを忘れていることです。 同じ数値を異なる順序で使用すると、まったく異なる数のグループが生成される可能性があります。 

のために`k=1`、小さな有効なパターンが考えられます。 サンプル スタイルの構築を考えてみましょう。```
4 2
8 3 45 100
1 2 1 2
```パーティションには 2 つのグループがあります。 最初のグループには以下が含まれます`8`そして`45`、共素です。 2番目には次の内容が含まれます`3`そして`100`、共素です。 貪欲な順序付けでは、最初にグループが作成されます`{8,3}`の場合、残りの数字のどちらもそこに置くことができないため、3 つのグループが必要になります。 違いは1つです。 

以下の構造は、クラウン グラフと呼ばれるグラフを使用してこのアイデアを一般化します。 

## アプローチ

 ブルートフォースアプローチでは、数値とパーティションを直接検索しようとします。 考えられる方向の 1 つは、整数の小さなセットを多数生成し、貪欲なグループ化をシミュレートし、ギャップが等しいかどうかを確認することです。`k`。 出力は必要なプロパティを満たすだけでよいため、これは正しいですが、検索スペースは膨大です。 候補数が 20 しかないとしても、考えられる gcd 関係が多すぎて探索できません。 可能なサブセットとパーティションの数は指数関数的に増加するため、このアプローチを信頼できるものにすることはできません。

 有益な観察は、問題は実際には数字に関するものではないということです。 貪欲な色付けが不適切な動作をするグラフを作成することです。 彩色数は小さいが、貪欲な色順で多くの色を使用するグラフが必要です。 

クラウン グラフはまさにこの動作を示します。 2 組の頂点があります。 左側のすべての頂点は、1 つの一致するパートナーを除き、右側のすべての頂点と競合します。 グラフはいつでも 2 色で色付けできますが、一致するペアが正しい順序で処理される場合、貪欲な色付けではペアごとに 1 つの新しい色が使用されます。 

残る唯一の課題は、グラフを整数に変換することです。 すべての競合エッジに対して、一意の素数を割り当てます。 その素数を 2 つのエンドポイント番号に代入します。 2 つの数値が衝突する必要がある場合に、正確に素数を共有します。 2 分割の同じ側の数値は素数を共有しないため、互いに素であり、有効なグループを形成します。 

のために`k`でクラウングラフを構築します。`k + 2`ペア。 貪欲なアルゴリズムは以下を使用します`k + 2`一方、グラフの両側から 2 つのグループを含む有効な分割が得られます。

 ## アルゴリズムのチュートリアル

 1. ペア数を設定します。`m = k + 2`。 グラフには次のようになります`m`左側の頂点と`m`右の頂点。 対象となるパーティションは、単純に、あるグループのすべての左頂点と、別のグループのすべての右頂点です。 
2. 十分に小さい素数を生成します。 すべてのペアについて`(left_i, right_j)`と`i != j`、一意の素数を 1 つ作成します。 その素数は、対応する両方の数値に乗算されます。 行方不明のペア`(left_i, right_i)`共有素数を受け取らないため、そのエッジが削除されます。 
3. 頂点を順番に出力する`left_0, right_0, left_1, right_1, ...`。 色に貪欲なとき`right_i`の場合、一致する左頂点を除くすべての以前の左頂点が表示されます。 これにより、各ペアに新しい色が強制的に導入されます。 
4. パーティションラベルを出力します。 左のすべての頂点がグループを受け取ります`1`、すべての右側の頂点がグループを受け取ります`2`。 

機能する理由: 構築された数値は、クラウン グラフの gcd 関係とまったく同じです。 片側の内側の数値に共通の素因数がないため、2 つのグループは有効です。 貪欲なカラーリング中、`i`右側の頂点は、1 つを除く前のすべての左側の頂点と競合するため、以前のすべての貪欲なカラーを参照し、次の貪欲なカラーを作成する必要があります。 すべてのペアが処理された後、greedy は`m = k + 2`グループは、パーティションが使用している間、`2`グループ。 その違いはまさに`k`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def primes_needed(cnt):
    primes = []
    x = 2
    while len(primes) < cnt:
        ok = True
        for p in primes:
            if p * p > x:
                break
            if x % p == 0:
                ok = False
                break
        if ok:
            primes.append(x)
        x += 1
    return primes

def solve():
    k = int(input())
    m = k + 2

    edges = []
    for i in range(m):
        for j in range(m):
            if i != j:
                edges.append((i, j))

    ps = primes_needed(len(edges))

    left = [1] * m
    right = [1] * m

    for p, (i, j) in zip(ps, edges):
        left[i] *= p
        right[j] *= p

    arr = []
    groups = []

    for i in range(m):
        arr.append(left[i])
        groups.append(1)
        arr.append(right[i])
        groups.append(2)

    print(len(arr), 2)
    print(*arr)
    print(*groups)

if __name__ == "__main__":
    solve()
```構築コードはまず、クラウン グラフの欠落している一致するエッジをすべて作成します。 がある`(k + 2) * (k + 1)`このようなエッジは最大 72 であるため、必要な素数は少数だけです。 

最大構成では数値ごとに素因数が 8 つしかないため、乗算ステップは安全です。 最初の素数のバランスのとれた分布により、すべての値が以下に保たれます。`10^18`。 Python の整数もオーバーフローを回避しますが、生成された値は依然として元の境界を満たしています。 

出力順序は構築の一部です。 左右の頂点をペアとしてではなく並べてグループ化して印刷すると、貪欲に必要な色数を強制されることはなくなります。 

## 実用的な例

 のために`k = 1`、建設は使用します`m = 3`ペア。 対象のパーティションには 2 つのグループがあります。 

| ステップ | 頂点タイプ | 貪欲な色の動作 | グループ |
 | --- | --- | --- | --- |
 | 1 | 左 0 | 以前に競合はなく、色 1 が取得されます。 グループ 1 |
 | 2 | 右0 | 後の左 1 および左 2 と競合しますが、前の色とは競合しないため、カラー 1 が取得されます。 グループ 2 |
 | 3 | 左 1 | 右の 0 と競合し、色 2 が取得されます。 グループ 1 |
 | 4 | 右 1 | left 0 と left 2 が競合し、色 1 と 2 が表示され、色 3 が取得されます。 グループ 2 |
 | 5 | 左 2 | 右 0 と右 1 が競合し、色 2 が取得されます。 グループ 1 |
 | 6 | 右2 | 色 1、2、3 を参照し、色 4 を取得します。 グループ 2 |

 正確な順序パターンでは 4 つの貪欲な色が作成されますが、パーティションには依然として 2 つのグループがあり、この例では 2 の差が生じます。 実際の問題としては、`m`として選ばれます`k + 2`、したがって、違いは常にあります`k`。 

のために`k = 7`、この構造では 9 つのペアが作成されます。 パーティションは 2 つのグループのままですが、greedy では 9 つのグループが作成されます。 同じ不変条件が適用されます。各新しい右頂点は、それ自身の一致するパートナーを除くすべての以前のカラー クラスに隣接しているため、次のカラーを強制します。

 ## 特殊なケース

 いつ`k = 1`、ペアの数は 3 です。 この構築では、パーティションが 2 色を使用しているのに対し、貪欲に 3 色を使用させるのに十分な頂点がまだ作成されています。 主要な割り当てには、クラウン グラフで必要な競合が正確に含まれているため、グループ内の偶発的な gcd は表示されません。 

いつ`k = 7`、9 つのペアと 72 の競合素数があります。 これが最大のケースです。 各数値には 8 つの素数のみが含まれ、積は以下のままになります。`10^18`。 左の 2 つの頂点または右の 2 つの頂点間で素数が共有されることはないため、同じ 2 つのグループの分割は有効なままになります。 

素数が 2 つの無関係なエッジに誤って再利用された場合、同じ側の 2 つの頂点が非共素となり、パーティションが無効になる可能性があります。 この構築では、グラフの各エッジに 1 つの新しい素数を割り当てることでこれを回避します。
