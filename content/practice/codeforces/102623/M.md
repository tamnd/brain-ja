 ## 解決策
 ## 問題の理解

 最大 30 行、わずか 8 列の長方形のファームがあります。 セルはブロックされた岩石か、使用可能な砂のいずれかです。 あらゆる砂細胞を水に変えることができるかもしれません。 水セルを選択した後、少なくとも 1 つの水セルに接触する残りの砂セルはすべてサトウキビを栽培できます。 タスクは、サトウキビのセルの数ができるだけ多くなるように、どの砂のセルが水になるかを決定し、結果として得られるグリッドを印刷することです。 

幅が小さいことがキーの制限です。 行数は 30 まで可能ですが、列数は 8 つだけなので、行は最大 256 個の可能な値を持つビットマスクで表現できます。 列数が指数関数的なソリューションは許容されますが、セルの総数が 1 つの指数関数になることは不可能です。 すべての砂セルのすべてのサブセットを試すことは、以下を確認することを意味する可能性があります。$2^{240}$これは実際の限界をはるかに超えています。 

いくつかの詳細が単純な貪欲なソリューションを壊す可能性があります。 たとえば、水のセル自体には価値はなく、隣接するセルへの影響のみが重要です。 1 行グリッドの場合:```
2 3
...
```中央のセルに水を入れると次のようになります。```
.X.
```ここではわかりやすくするために出力表現から水を省略していますが、水を端に配置すると、隣接するサトウキビのセルが少なくなります。 水のセルは将来の複数の行に役立つ可能性があるため、最も開いているように見えるセルに常に水を配置する戦略は失敗する可能性があります。 

もう 1 つの問題は、セルが次の行から水の影響を受ける可能性があるため、独自の水を選択した直後に行が必ずしも完了するとは限らないことです。 例えば：```
2 1
.
.
```下のセルが水になるかどうかが分かるまで、上のセルを判断することはできません。 アルゴリズムは前の行の決定を記憶しておく必要があります。 

## アプローチ

 直接的なアプローチでは、水に変化する砂セルの可能なすべてのセットが選択されます。 選択肢ごとに、グリッドをスキャンして、水に触れる残りの砂のセルの数を数えることができます。 これは、考えられるすべての最終的な取り決めを検討するため、正しいです。 ただし、ファームに 240 個の砂セルが含まれる場合、選択肢の数は$2^{240}$、それは不可能です。 

グリッドの構造により、視界が良くなります。 幅はわずか 8 であるため、グリッドの処理済み部分と未処理部分の間の相互作用は 1 つの行を通じて行われます。 前の行のどのセルが水であるかを覚えておく必要があるだけです。 これにより、問題は行マスクをめぐる動的プログラミングに変わります。 

行ごとに、その行の砂セルのサブセットである考えられるすべてのウォーター マスクを列挙します。 次の行の水マスクを決定すると、その行に隣接するすべての水のセルがわかっているため、前の行が完全に決定されます。 次に、その行に作成された杖セルの数を追加します。 マスクの数は最大 256 であるため、合計の遷移数は少なくなります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(2^{nm}nm)$|$O(nm)$| 遅すぎる |
 | 最適 |$O(n \cdot 2^m \cdot 2^m \cdot m)$|$O(n \cdot 2^m)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各行に対して可能なすべてのウォーターマスクを事前計算します。 マスクにビットがセットされると、対応する砂のセルが水に変化することを意味します。 岩細胞はウォーターマスクには決して現れません。 
2. 状態が前の行のウォーターマスクである動的プログラミングを使用します。 保存される値は、その行の上ですでに確定されている杖セルの最大数です。 今後のすべての効果はすぐ隣の行からのみ得られるため、前の行が必要な唯一の情報です。 
3.行処理時`i`、この行について考えられるすべてのウォーターマスクを試してください。 以前のマスクごとに、行のスコアを計算します。`i - 1`。 前の行のセルが砂で、隣接する 4 つのセルのうち少なくとも 1 つが水の場合、そのセルはサトウキビになります。 
4. すべての行と結果のマスクごとに最適なトランジションを保存します。 これらの親ポインターを使用すると、動的プログラミングの終了後に、選択した水の行を再構築できます。 
5. 実際の最後の行の後、空のウォーターマスクを使用して追加のトランジションを 1 つ実行します。 この最後のステップでは、水が含まれていない既知の「次の行」があるため、最後の行にスコアが付けられます。 
6. 保存されている親を逆方向にたどって、選択したウォーター マスクを再構築します。 次に、選択したすべての水セルを次のように変換します。`O`、水に隣接するすべての砂セル`X`、他の砂セルはそのままにしておきます。`.`。 

不変条件は、ある程度の数の行を処理した後、保存されたマスクの前のすべての行がすでに最終的な最適な寄与を受け取っているということです。 保存されたマスクには、新しいマスクが選択されたときに次の行を評価するために必要な情報が正確に含まれています。 考えられるすべての行遷移が考慮されるため、最終遷移後の最良の状態がケーン セルの可能な最大数を表します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    grid = [input().strip() for _ in range(n)]

    row_masks = []
    for r in range(n):
        masks = []
        for mask in range(1 << m):
            ok = True
            for c in range(m):
                if (mask >> c) & 1 and grid[r][c] == '#':
                    ok = False
                    break
            if ok:
                masks.append(mask)
        row_masks.append(masks)

    def score_row(r, above, cur):
        if r < 0 or r >= n:
            return 0
        res = 0
        for c in range(m):
            if grid[r][c] == '#':
                continue
            if (above >> c) & 1:
                continue
            water = False
            if c > 0 and ((above >> (c - 1)) & 1):
                water = True
            if c + 1 < m and ((above >> (c + 1)) & 1):
                water = True
            if (above >> c) & 1:
                water = True
            if (cur >> c) & 1:
                water = True
            if water:
                res += 1
        return res

    parent = [[-1] * (1 << m) for _ in range(n + 1)]

    dp = [-10**9] * (1 << m)
    dp[0] = 0

    for r in range(n):
        ndp = [-10**9] * (1 << m)
        for prev in range(1 << m):
            if dp[prev] < 0:
                continue
            for cur in row_masks[r]:
                val = dp[prev] + score_row(r - 1, prev, cur)
                if val > ndp[cur]:
                    ndp[cur] = val
                    parent[r][cur] = prev
        dp = ndp

    best = -1
    last = -1
    for prev in range(1 << m):
        val = dp[prev] + score_row(n - 1, prev, 0)
        if val > best:
            best = val
            last = prev

    water = [0] * n
    mask = last
    for r in range(n - 1, -1, -1):
        water[r] = mask
        mask = parent[r][mask]

    ans = [list(row) for row in grid]
    for r in range(n):
        for c in range(m):
            if (water[r] >> c) & 1:
                ans[r][c] = 'O'

    for r in range(n):
        for c in range(m):
            if ans[r][c] != '.':
                continue
            ok = False
            for dr, dc in ((1,0),(-1,0),(0,1),(0,-1)):
                nr, nc = r + dr, c + dc
                if 0 <= nr < n and 0 <= nc < m:
                    if ans[nr][nc] == 'O':
                        ok = True
            if ok:
                ans[r][c] = 'X'

    print('\n'.join(''.join(row) for row in ans))

if __name__ == "__main__":
    solve()
```の`row_masks`array は、動的プログラミングが開始される前に不可能な選択肢を削除します。 岩石細胞は決して水になることはできないため、それらの破片を含むマスクは廃棄されます。 

遷移関数は、次の行の決定が利用可能になった後にのみ行を評価します。 これにより、セルが下から垂直に水の影響を受ける可能性があることを忘れるというよくある間違いを回避できます。 マスクを使用した人工的な最終トランジション`0`一番下の行も同じ目的です。 

再構築では、選択された各状態の前のマスクのみが保存されます。 各行には最大 256 個のマスクがあるため、これらの親の格納は小さくなります。 最大スコアは 240 のみであるため、大きな整数の問題はありません。 

## 実用的な例

 小さな例としては、次のとおりです。 

入力:```
3 3
...
.#.
...
```動的プログラミングの状態は次のように要約できます。 

| 処理された行 | 現在保存されているマスク | 意味 |
 | --- | --- | --- |
 | 開始 |`000`| 以前の水なし |
 | 行 0 の後 | いくつかのマスク | 考慮される最初の行の選択 |
 | 行 1 の後 | 最高のマスク | 中央の行の選択を検討 |
 | 行 2 の後 | 最高のマスク | すべての行を考慮 |
 | 最終移行 |`000`| 一番下の行が確定しました |

 トレースは、アルゴリズムがスコアリングを遅らせる理由を示しています。 一番上の行は、2 番目の行マスクが判明するまで確定されません。 

2 番目のサンプルの場合:```
3 3
.#.
#.#
.#.
```中央の列は、岩が水の配置を妨げるため、選択肢が限られています。 行マスク制限により無効な遷移は直ちに削除され、動的プログラミングでは正当な構成のみが保持されます。 

| 行 | 利用可能なマスク数 | 保存情報 |
 | --- | --- | --- |
 | 0 | 4 | 非岩石セルに水が存在する可能性 |
 | 1 | 2 | 岩細胞が選択肢から削除されました。 
| 2 | 4 | 最後の行は最終遷移後に評価されます |

 このケースは、アルゴリズムがすべての細胞が水になる可能性を想定していないことを裏付けています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(n \cdot 2^m \cdot 2^m \cdot m)$| 以前のマスクと現在のマスクのすべてのペアがテストされ、各スコアが行をスキャンします。 
| スペース |$O(n \cdot 2^m)$| 再構築のために親を保存する |

 と`m <= 8`、マスクは最大 256 個あります。 遷移回数はおおよそ`30 * 256 * 256`、管理が簡単です。

def run(inp: str) -> str:

 ## 特殊なケース

 岩に囲まれた単一の砂のセルは、それ自体が水にならない限り、水の隣に存在する可能性はありませんが、水はサトウキビを作り出すことはできません。 のために：```
1 1
.
```唯一の有効な出力は`.`または`O`。 アルゴリズムは両方の状態を考慮し、水セルを杖としてカウントすることを正しく回避します。 

別の列の隣の列は、下から助けを受けることができます。 のために：```
2 1
.
.
```下のセルを水として選択すると、上のセルがサトウキビになります。 動的プログラミングでは最上位行のスコアが早すぎることはないため、この垂直方向の依存関係は正しく処理されます。 

岩だけを含むグリッド:```
2 2
##
##
```ゼロ以外にウォーターマスクの可能性はありません。 マスク生成ステップでは無効な水の選択がすべて拒否されるため、答えは変わりません。
