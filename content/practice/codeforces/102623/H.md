 ## 解決策
 # 問題の理解

 農場はグリッドであり、各セルには独自の雑草の成長速度があります。 値が入ったセル`a[i][j]`毎瞬間、同じ数のウィードユニットを獲得します。 特定の瞬間の終わりに、芝刈り機は行全体または列全体を刈り取ります。タスクは、すべての操作で除去された雑草の総量を見つけることです。 

入力により、成長率のグリッドが得られ、行と列の消去操作の時系列シーケンスが得られます。 操作時間は厳密に増加しているため、すべてのイベントを順番に処理できます。 答えは、すべての伐採の瞬間に除去されたすべての雑草の合計を法で計算したものです。`998244353`。 

グリッドの寸法は最大 500 x 500 なので、セルの数は最大 250,000 個になります。 芝刈り機の操作数は 300,000 回に達する可能性があります。グリッドを直接シミュレーションするには、操作のたびにすべてのセルに触れる必要があり、最悪の場合、約 7,5000000,000 回の操作が必要になります。 すべての操作でディメンション全体を反復処理することさえ許容されるのは、ディメンションが小さく、目的のソリューションがこのプロパティを使用しているためです。 

成長率と時間の値が大きい場合、計算中に 64 ビットの演算が必要になります。 よくある間違いは、答えまたは中間積を 32 ビット整数で保存することです。 もう 1 つの微妙なケースは、行と列の両方が最近カットされた場合です。 セルは、その行が最後に切り取られたときとその列が個別に切り取られたときを記憶しません。 実際の雑草の量は、これら 2 つの瞬間のうちのより最近のものによって異なります。 

たとえば、次のことを考えてみましょう。```
1 1 2
5
r 1 10
c 1 20
```最初のカットは削除します`5 * 10 = 50`。 唯一のセルが時間 10 ですでにクリアされており、さらに 10 分間成長するため、2 番目のカットでは何も削除されません。したがって、合計は次のようになります。`100`。 

最後の行のカットのみを追跡するか、最後の列のカットのみを追跡する不用意なソリューションでは、操作の 1 つでセルが時刻 0 から増加していると誤ってカウントされます。 

もう 1 つのエッジ ケースは、成長率がゼロの場合です。```
1 1 1
0
r 1 100
```答えは`0`。 将来の操作はそれらの時間に依存するため、実装は寄与がゼロの場合でもカット時間を更新する必要があります。 

# アプローチ

 簡単なアプローチは、すべてのセルで現在の雑草の量を維持することです。 時間が進むと、すべてのセルに成長を追加し、行または列が刈られたら、その行を合計してクリアします。 これはプロセスに正確に従っており、正しいことを証明するのは簡単です。 ただし、イベント間の時間が長くなる可能性があり、イベント数は 300,000 に達します。イベントごとにすべてのセルを更新するにはコストがかかります`O(k*n*m)`、それは限界をはるかに超えています。 

有益な観察は、セルの成長はその行または列が最後にクリアされた時間のみに依存するということです。 細胞の場合`(i,j)`、最後の行のカットが発生した場合`R[i]`そして最後の列カットは`C[j]`、すると、現在存在する雑草は次のようになります。`a[i][j] * (current_time - max(R[i], C[j]))`。 

行が切り取られるときは、その行のセルに対してこの式を計算するだけで済みます。 コラムカットも同様です。 どちらの次元も最大 500 であるため、イベントごとに 1 つの次元全体をチェックすることが可能です。 

グリッドが小さいためブルート フォースは機能しますが、すべてのセルを繰り返しシミュレートすると失敗します。 行と列の独立したリセット時間に関する観察により、作業を操作ごとに 1 つの行または列のスキャンに減らすことができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(k_n_m) | O(n*m) | 遅すぎる |
 | 最適 | O(k*max(n,m)) | O(n*m) | 承認済み |

 # アルゴリズムのチュートリアル

 1. すべてのセルの増殖率を保存します。 2 つの配列を維持します。`last_row[i]`最後の瞬間の行を保存します`i`クリアされました、そして`last_col[j]`最後の瞬間の列を保存します`j`クリアされました。 グリッドは空から始まるため、最初は両方ともゼロです。 
2.列のとき`x`時間でクリアされる`t`、すべての列を反復処理します`j`。 セル内の金額`(x,j)`行間の最後のクリア時間によって決定されます`x`そしてコラム`j`なので、次を追加します。`a[x][j] * (t - max(last_row[x], last_col[j]))`答えに。 行を処理した後、設定します`last_row[x] = t`。 
3. コラムの場合`y`時間でクリアされる`t`、すべての行に対して対称操作を実行します。`i`:`a[i][y] * (t - max(last_row[i], last_col[y]))`次に設定します`last_col[y] = t`。 
4. 答えのモジュロを取る`998244353`値を管理しやすくするために追加した後。 

機能する理由: アルゴリズムは、セルごとに、そのセルがクリアされるたびに、存在していた量の雑草を正確に追加します。 セルは、そのセル自体の行またはその列に対する操作のみの影響を受けます。 このような 2 つの操作の間にセルは継続的に成長し、その成長間隔の開始点は、直前の 2 つのクリア時間のうちの最新の時間になります。 すべての操作で使用される式はこの不変条件と一致するため、削除されたすべてのユニットは 1 回だけカウントされます。 

# Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n, m, k = map(int, input().split())

    a = [list(map(int, input().split())) for _ in range(n)]

    last_row = [0] * n
    last_col = [0] * m

    ans = 0

    for _ in range(k):
        typ, x, t = input().split()
        x = int(x) - 1
        t = int(t)

        if typ == 'r':
            lr = last_row[x]
            row = a[x]
            for j in range(m):
                start = lr if lr > last_col[j] else last_col[j]
                ans += row[j] * (t - start)
            last_row[x] = t
        else:
            lc = last_col[x]
            for i in range(n):
                start = last_row[i] if last_row[i] > lc else lc
                ans += a[i][x] * (t - start)
            last_col[x] = t

        ans %= MOD

    print(ans % MOD)

if __name__ == "__main__":
    solve()
```配列`last_row`そして`last_col`元のグリッド以外に必要な唯一の状態が含まれています。 これらは各ラインのリセット時間を表すため、セルの現在値を保存する必要はありません。 

行演算の場合、ローカル変数`lr`更新する前に古い行のタイムスタンプを保持します。 これは、芝刈り機が行をクリアする前の状態をコントリビューションで使用する必要があるため、重要です。 同じ考え方が次の列にも使用されます。`lc`。 

Python の整数は、最大値を含む大きな積を自動的に処理します。`10^18`ただし、モジュロ演算により最終的な答えは制限されます。 比較は、を使用する代わりに手動で記述されます。`max`これらのループは最大のケースでは何億回も実行される可能性があるためです。

 # エッジケース

 行と列の両方のカットの影響を受けるセルは、後のリセット時間を使用する必要があります。 で：```
1 1 2
5
r 1 10
c 1 20
```最初の操作は追加します`5 * 10 = 50`。 2 番目の操作の前、時間 10 での行リセットは最初の列リセットよりも新しいため、2 番目の寄与は次のようになります。`5 * (20 - 10) = 50`。 アルゴリズムはこれら 2 つのタイムスタンプを個別に保存し、それらの最大値を取得します。 

ラインが連続して何度もクリアされる場合、その同じラインの前回のクリアが重要になります。 例えば：```
1 1 2
3
r 1 4
r 1 9
```最初のイベントは削除します`12`、2番目は削除します`15`。 アルゴリズムは更新され続けます`last_row`したがって、2 番目の計算は時間 0 ではなく時間 4 から始まります。 

次のように時間値が非常に大きい場合`10^18`、特別な処理は必要ありません。 The formula only performs multiplication and subtraction on Python integers, which can represent these values exactly.
