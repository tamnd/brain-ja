 ## 解決策
 ## 問題の理解

 同一の金の延べ棒のコレクションが与えられ、各延べ棒は 3 つの効果的な方法のいずれかで向きを変えることができ、どちらかの高さに貢献します。`a`、`b`、 または`c`。 すべてのバーは 1 回だけ使用する必要があり、それらを 1 つのタワーに積み重ねます。 構成に関して重要なのは、その全体の高さです。これは、すべての要素の寄与の合計です。`n`バー。 

異なる向きを選択しても、全高が同じになる場合があります。 タスクは、達成可能な個別の合計高さを数えることです。 

入力により得られるのは、`n`、バーの数、および 3 つの整数`a`、`b`、 そして`c`、これは方向に応じて各バーの考えられる高さの寄与です。 出力は、それぞれの選択によって形成できる個別の合計の数です。`n`位置、3 つの値のいずれか。 

制約は重要です。 バーの数は 1200 に達する可能性があるため、すべてを列挙するアプローチは除外されます。`3^n`構成。 その空間は中程度の人でも天文学的に大きい`n`。 ただし、の値は、`a`、`b`、 そして`c`大きい、最大`10^9`, したがって、重量範囲が狭い境界付きナップザックにも依存できません。 

重要な観察は、問題の唯一の構造が加法的であるということです。各棒は独立して寄与しており、合計だけを気にします。 

値が等しい場合、エッジ ケースが発生します。 もし`a = b = c`の場合、すべての構成で合計の高さは同じになり、答えは 1 になります。2 つの値が等しい場合は、次のようになります。`a = b != c`の場合、事実上、バーごとに選択肢は 2 つだけですが、それでも個別の合計を正しくカウントする必要があります。 

単純な間違いは、構成の数が合計の数と等しいと仮定することです。これは、多くの異なる割り当てが同じ合計にまとめられるため、誤りです。 

## アプローチ

 ブルートフォースのアイデアは簡単です。それぞれのオブジェクトに割り当てるあらゆる方法を試してください。`n`いずれかの値をバーで囲みます`a`、`b`、 または`c`、結果の合計を計算し、セットに格納します。 これは、考えられるすべての構成を明示的に構築するため、正しいです。 ただし、反復処理が必要です`3^n`たとえそれが不可能になる状態`n = 30`、ましてや`n = 1200`。 

重要な構造は、最終的な合計は、位置ではなく、各値に割り当てられたバーの数のみに依存するということです。 させたら`x`、`y`、 そして`z`割り当てられたバーの数になります`a`、`b`、 そして`c`、全体の高さは次のようになります。`x*a + y*b + z*c`、 と`x + y + z = n`。 したがって、問題は、単純なシンプレックスによって制約されたすべての整数トリプルにわたる線形形式の個別の値をカウントすることに帰着します。 

割り当てを列挙する代わりに、カウント分布を列挙します。 あるのは`O(n^2)`有効なトリプル`(x, y, z)`なぜなら一度`x`そして`y`固定されており、`z`決まっている。 各トリプルは正確に 1 つの合計を生成するため、これらをセットに挿入して個別の結果をカウントできます。 

これにより、指数関数的な問題が二次問題に変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 割り当てに対するブルートフォース | O(3^n) | O(3^n) | 遅すぎる |
 | count トリプルを列挙する | O(n^2) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 視点を数列から数に移します。 

1. 可能なすべての値を反復処理します。`x`、寄与するバーの数`a`、 から`0`に`n`。 これで何回修正されるか`a`が使用されます。 
2. 固定ごとに`x`、繰り返します`y`、寄与するバーの数`b`、 から`0`に`n - x`。 残り`z`強制される`n - x - y`したがって、明示的にループすることはありません。 
3. トリプルごとに`(x, y, z)`、合計の高さを計算します`x*a + y*b + z*c`。 この値をハッシュ セットに挿入します。 このセットは、さまざまな原因で発生した重複を自動的に削除します。`(x, y, z)`同じ合計を生み出す組み合わせ。 
4. すべての反復の後、セットのサイズは、達成可能な個別の高さの数になります。 

この列挙が有効である理由は、すべての有効な構成がトリプルに一意に対応しているためです。`(x, y, z)`、すべてのトリプルは少なくとも 1 つの構成に対応します。 

### なぜ効果があるのか

 このアルゴリズムは、バーの配置は、順列に至るまで、各値が何回選択されるかによって完全に決定されるという不変式に依存しています。 順序は合計に影響しないため、2 つの構成は、同じものを共有する場合にのみ同等になります。`(x, y, z)`。 ネストされたループは、そのようなトリプルをすべて 1 回だけ列挙するため、考えられるすべての合計が考慮され、有効な合計が見逃されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, a, b, c = map(int, input().split())
    seen = set()

    for x in range(n + 1):
        for y in range(n - x + 1):
            z = n - x - y
            seen.add(x * a + y * b + z * c)

    print(len(seen))

if __name__ == "__main__":
    solve()
```実装はトリプルカウント列挙に直接続きます。 外側のループは何回修正するか`a`が使用され、内側のループは回数を修正します`b`が使用されます。 残りのカウントは、`c`は暗黙的に計算されるため、不要な 3 番目のループが回避されます。 

セットの使用は必須です。`(x, y, z)`特に次の場合、組み合わせによって同じ合計が得られることがあります。`a`、`b`、 そして`c`算術関係があります。 

## 実用的な例

 ここでの入力を考えてみましょう。`n = 2`、`a = 1`、`b = 2`、`c = 3`。 

すべてのトリプルを列挙します。 

| × | y | z | 合計 |
 | --- | --- | --- | --- |
 | 0 | 0 | 2 | 6 |
 | 0 | 1 | 1 | 5 |
 | 0 | 2 | 0 | 4 |
 | 1 | 0 | 1 | 4 |
 | 1 | 1 | 0 | 3 |
 | 2 | 0 | 0 | 2 |

 和の集合は`{2, 3, 4, 5, 6}`、したがって、答えは次のとおりです`5`。 

このトレースは、次のように、異なるカウント分布が同じ合計で衝突する可能性があることを示しています。`(x=0,y=2,z=0)`そして`(x=1,y=0,z=1)`どちらも生産している`4`。 

ここで考えてみましょう`n = 3`、`a = b = 1`、`c = 10`。 

| × | y | z | 合計 |
 | --- | --- | --- | --- |
 | 3 | 0 | 0 | 3 |
 | 2 | 1 | 0 | 3 |
 | 2 | 0 | 1 | 12 |
 | 1 | 2 | 0 | 3 |
 | 1 | 1 | 1 | 12 |
 | 1 | 0 | 2 | 21 |
 | 0 | 3 | 0 | 3 |
 | 0 | 2 | 1 | 12 |
 | 0 | 1 | 2 | 21 |
 | 0 | 0 | 3 | 30 |

 個別の合計は`{3, 12, 21, 30}`、したがって、答えは次のとおりです`4`。 

これは、以下の値がどのように等しいかを示しています。`a`そして`b`多くの折りたたみ構成が作成されますが、セットベースの列挙は依然として一意性を正しくキャプチャします。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n^2) | x と y に対する 2 つのネストされたループ。状態ごとに定数時間のセット挿入 |
 | スペース | O(n^2) | 最悪の場合、生成されたすべての合計は個別になります。 

制約`n ≤ 1200`約 720,000 回の反復が行われますが、これは Python では許容範囲です。 各反復は単純な算術演算とハッシュ挿入であるため、制限時間内に問題なく収まります。

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from contextlib import redirect_stdout
    out = io.StringIO()
    with redirect_stdout(out):
        solve()
    return out.getvalue().strip()

def solve():
    n, a, b, c = map(int, input().split())
    seen = set()
    for x in range(n + 1):
        for y in range(n - x + 1):
            z = n - x - y
            seen.add(x * a + y * b + z * c)
    print(len(seen))

 ## 特殊なケース

 たとえば、3 つの値がすべて等しい場合、`n = 1000, a = b = c = 5`、どの構成でも同じ合計が生成されます`5000`。 アルゴリズムはすべてを反復します`(x, y)`のペアですが、計算されたすべての合計は同一であるため、セットには要素が 1 つだけ含まれます。 最終的な出力は正しくなります`1`。 

2 つの値が等しい場合、たとえば`a = b = 1`そして`c = 100`、さまざまな`(x, y, z)`トリプルは同じ合計に崩壊します。 例えば、`(x=2,y=1,z=0)`そして`(x=3,y=0,z=0)`どちらも寄与度は異なりますが、それでも重複する範囲が生成されます。 このセットにより重複が確実にマージされるため、手動の重複排除ロジックは必要ありません。 

値が大きい場合、次のように`10^9`Python ではオーバーフローのリスクはありませんが、固定幅言語では 64 ビット整数が必要です。 アルゴリズムはそれを超えて増殖することはありません`n * max(a,b,c)`、これは 64 ビットの符号付き整数に安全に収まります。
