 ## 解決策
 ## 問題の理解

 いくつかの投票区があり、各区には多数の投票所があります。 各投票所には、何もしなければそこに追加されるであろう不正投票の予測量が存在します。 目標は、監視員を配置することで不正行為全体を減らすことです。 

オブザーバは合計で最大 C 個のステーションに配置でき、各ステーションは最大 1 つのオブザーバをホストできます。 ステーションに監視員がいる場合、そのステーションの不正行為は完全に防止されます。 

地区レベルで機能する追加のメカニズムがあります。 ある地区内で、配置されたオブザーバーの数がその地区固有のしきい値に達した場合、オブザーバーのいないステーションを含む地区全体で不正行為が防止されます。 

課題は、残りの不正行為の合計が最小限に抑えられるように、グローバル制限を尊重してオブザーバーをどこに配置するかを決定することです。 

重要な構造的側面は、決定がステーションごとに独立していないことです。 十分な監視員が地区内に集中すると、その地区は「完全に安全」になり、その地区内に追加のステーションレベルの配置が不要になる可能性があります。 これにより、オブザーバーを多くの地区に分散させることと、オブザーバーを集中させて地区全体の保護を解除することの間にトレードオフが生じます。 

この制約は、ステーションと観測者の数が両方とも数千に達する可能性があることを示しており、指数関数的なサブセットの列挙は除外されます。 二次または二次に近い動的計画法のアプローチは実現可能ですが、n の 3 次関数は遅すぎます。 

単純なアプローチでは、サイズが最大 C のステーションのすべてのサブセットを試し、各地区がアクティブになるかどうかをシミュレートします。 これは、4000 の組み合わせが C を選択するにつれてサブセットの数が増加するため、失敗しますが、これは完全に実行不可能です。 

2 番目の単純なアイデアは、各ステーションを独立して扱い、最大の a_i 値を貪欲に選択することです。 これは、地区のアクティブ化のしきい値を無視しているため、これも正しくありません。地区内で慎重に選択された中程度の値のステーションのセットによって、多額の残りの合計が消去される可能性があります。 

地区に多くの中程度のステーションがあり、しきい値 b_j が高い場合、微妙な失敗のケースが発生します。 世界最大のステーションを貪欲に選択すると、どの地区も活性化することなく複数の地区にオブザーバーを配置する可能性がありますが、わずかに弱いステーションを 1 つの地区に集中させると、大規模なステーションが全滅する可能性があります。 

## アプローチ

 重要な観察は、各地区内の決定を正しく記述すれば、他の地区から決定を分離できるということです。 

固定地区内に k 人の観察者を配置すると決めたとします。 その固定 k の利点を最大化するには、その地区内で最大の a_i 値を持つ k 個の測点にそれらを常に配置する必要があります。 これは、オブザーバー用にステーションを選択することは、その a_i 値が保存された不正として正確に寄与するためであり、固定カウントに対して保存された合計を最大化したいためです。 

地区内のステーションを a_i を減少させることによって並べ替えます。 上位 k 局にオブザーバーを配置した場合に、プレフィックス合計 P[k] を、保存された不正行為の合計として定義します。 

次に、地区のしきい値を考慮する必要があります。 k が少なくとも b_j の場合、地区は完全にアクティブになり、その地区内の残りのステーションもすべて保存されます。 つまり、値はkに依存するのをやめ、その地区の合計になるということです。 

したがって、各地区は小さな「ナップザック アイテム ジェネレーター」になります。考えられる k ごとに、その地区で得られる最高の値が正確にわかります。 

グローバル問題は、地区をめぐる古典的なナップザックになります。各地区は、何人のオブザーバーを費やすかについて複数の「選択肢」を提供します。各選択肢は、k に等しい値とコストを持ちます。 動的プログラミングを使用して、使用されるオブザーバーの総数に対して地区を 1 つずつ結合します。

ブルートフォースソリューションでは、地区全体にわたるすべてのオブザーバーの分布が試行されますが、これは指数関数的です。 DP ソリューションでは、これを最悪の単純形式で O(m * C^2) に削減しますが、すべての地区にわたるステーションの合計は n のみであるため、合計 O(n * C) の遷移を生成できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | サブセットに対するブルート フォース | 指数関数 | O(n) | 遅すぎる |
 | 地区ごとのナップザック DP | O(n・C) | O(C) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 地区ごとにステーションを分割します。 地区ごとに、その地区に属するすべての a_i 値を収集します。 これにより、ローカルな決定が分離されるため、他の地区からの干渉を受けることなく、1 つの地区内でのオブザーバーの配置を推論できます。 
2. 各地区の値を降順に並べ替えます。 これにより、この地区に k 人のオブザーバーを配置することを決定した場合、k の最大値を取得することで、常にその k について節約される不正行為が最大化されることが保証されます。 
3. 各地区のプレフィックス合計配列 P を構築します。ここで、P[k] は、その地区内の k 個の最良のステーションにオブザーバーを配置した場合に節約された不正行為の合計を表します。 これにより、組み合わせの選択が単純な検索に変換されます。 
4. 各地区の total_sum を P[size] として事前計算します。これは、その地区内のすべての不正行為を表します。 
5. DP 配列 dp[c] を構築します。ここで、dp[c] は、地区のいくつかのプレフィックスを処理した後、正確に c 個のオブザーバーを使用して達成できる、保存された不正行為の最大値です。 
6. 地区ごとに、負の無限大で初期化された一時的な遷移配列 ndp を構築します。 この地区で費やせる現在の観測者の数 c と考えられるすべての k について、現在の値と dp[c] に k 観測者に対する地区の寄与を加えたものを使用して、ndp[c + k] を更新します。 
7. k 個の観測者の寄与は、k が地区しきい値 b_j 未満の場合は P[k]、k が少なくとも b_j の場合は total_sum です。 
8. 地区を処理した後、dp を ndp に置き換えて続行します。 
9. すべての地区が処理された後、答えは total_fraud_sum から C までのすべての c にわたる最良の dp[c] を引いたものになります。 

### なぜ効果があるのか

 正確さは、各地区に割り当てられる監視員の数を決定すると、各地区が独立しているという事実から得られます。 任意の固定 k の場合、地区内の最良の戦略は常に k 個の最も値の高い測点を選択することです。選択した測点を選択されていないより高い値の測点と交換すると、結果が厳密に改善または保存されるためです。 しきい値条件は、どのステーションが選択されるかには依存せず、カウント k にのみ依存するため、この最適な構造が崩れることはありません。 次に、グローバル DP は、すべての実行可能な割り当てが地区ごとの選択の 1 つのシーケンスに正確に対応するため、地区全体にわたるすべての有効なオブザーバーの分布を構成を欠落することなく調査します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, C = map(int, input().split())
    c = list(map(int, input().split()))
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    districts = [[] for _ in range(m)]
    for i in range(n):
        districts[c[i] - 1].append(a[i])

    total_fraud = sum(a)

    dp = [-10**18] * (C + 1)
    dp[0] = 0

    for j in range(m):
        vals = districts[j]
        vals.sort(reverse=True)

        sz = len(vals)
        pref = [0] * (sz + 1)
        for i in range(sz):
            pref[i + 1] = pref[i] + vals[i]

        full = pref[sz]
        limit = b[j]

        ndp = [-10**18] * (C + 1)

        for used in range(C + 1):
            if dp[used] < 0:
                continue
            for k in range(sz + 1):
                if used + k > C:
                    break

                if k < limit:
                    gain = pref[k]
                else:
                    gain = full

                if dp[used] + gain > ndp[used + k]:
                    ndp[used + k] = dp[used] + gain

        dp = ndp

    print(total_fraud - max(dp))

if __name__ == "__main__":
    solve()
```DP は、各州の移行が単一の地区に一定数のオブザーバーをコミットすることを表すように組織されています。 各 k 範囲は地区サイズによって制限され、すべてのステーションが一緒になってサイズ n のパーティションを形成するため、すべての地区にわたる k 反復の合計数は n になるため、k にわたる内側のループは安全です。 

よくある実装上の間違いは、k がしきい値に達したときの「平坦化」効果を忘れることです。 k >= b_j の後は、その地区内の追加の観測者はすべて値を変更しないため、このプラトーなしで各 k を独立して扱うと、誤った過大カウントが発生します。 

もう 1 つの微妙な問題は、dp の到達不可能な状態を十分な負の数で初期化することです。 保存された不正行為を最大限に活用しているため、無効な状態が伝播することはありません。 

## 実用的な例

 ### 例 1 (単一地区の行動)

 値 [10, 5, 1] および b = 2、C = 2 を持つ 1 つの地区があるとします。 

プレフィックスの合計は P = [0, 10, 15, 16] です。 k = 0 の場合、ゲイン = 0。k = 1 の場合、ゲイン = 10。k = 2 の場合、k >= b であるため、ゲインは 16 になり、完全なアクティブ化を意味します。 k = 2 の場合、すべてのステーションがすでに含まれているため、一致します。 

| ステップ | 中古オブザーバー | k が選択されました | ゲイン | dp 状態 |
 | --- | --- | --- | --- | --- |
 | 初期化 | 0 | 0 | 0 | dp[0]=0 |
 | 地区 | 0 | 1 | 10 | dp[1]=10 |
 | 地区 | 0 | 2 | 16 | dp[2]=16 |

 これは、しきい値がどのように部分選択を全地区ゲインに変えるかを示しています。 

### 例 2 (複数地区のトレードオフ)

 地区 1: [8, 7]、b = 2

 地区 2: [6, 6]、b = 1

 C = 2

 地区 2 はオブザーバー 1 人だけでアクティベートされ、すぐに最大ゲイン 12 が得られますが、地区 1 は完全にアクティベートするには両方のオブザーバーが必要です。 

DP は、地区 2 で 1 人のオブザーバーを費やしてから、残りの容量が他の場所で役立つかどうかを判断することを正しく選択しています。 

| ステップ | 状態 | アクション | 結果 |
 | --- | --- | --- | --- |
 | 開始 | dp[0]=0 | なし | ベースライン |
 | D2 | dp[1]=6、dp[2]=12 | k=1 または 2 を選択します | 強力な活性化 |
 | D1 | 組み合わせる | 残容量 | 最終的な最適な分割 |

 これは、個々の a_i による貪欲な割り当てが失敗する理由を示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n・C) | 各ステーションはプレフィックス合計に 1 回寄与し、各 DP 遷移はオブザーバー カウントにわたって C | まで反復されます。 
| スペース | O(C) | サイズ C の 2 つの DP 配列のみが維持されます。 

合計の操作は数千万回程度であるため、制約 n ≤ 4000 および C ≤ 4000 はこの複雑さ内に問題なく適合します。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    from math import inf

    # inline solution for testing
    n, m, C = map(int, sys.stdin.readline().split())
    c = list(map(int, sys.stdin.readline().split()))
    a = list(map(int, sys.stdin.readline().split()))
    b = list(map(int, sys.stdin.readline().split()))

    districts = [[] for _ in range(m)]
    for i in range(n):
        districts[c[i] - 1].append(a[i])

    total = sum(a)

    dp = [-10**18] * (C + 1)
    dp[0] = 0

    for j in range(m):
        vals = sorted(districts[j], reverse=True)
        sz = len(vals)
        pref = [0] * (sz + 1)
        for i in range(sz):
            pref[i + 1] = pref[i] + vals[i]

        full = pref[sz]
        lim = b[j]

        ndp = [-10**18] * (C + 1)
        for u in range(C + 1):
            if dp[u] < 0:
                continue
            for k in range(sz + 1):
                if u + k > C:
                    break
                gain = full if k >= lim else pref[k]
                ndp[u + k] = max(ndp[u + k], dp[u] + gain)

        dp = ndp

    return str(total - max(dp))

 ## 特殊なケース

 地区のしきい値が 1 の場合、エッジ ケースが頻繁に発生します。その場合、オブザーバーを 1 人配置すると、直ちに地区全体が壊滅するはずです。 k ≥ 1 の場合、ゲインは地区全体の合計に切り替わるため、アルゴリズムはこれを正しく処理します。そのため、その地区に複数の観測者を配置しても dp は恩恵を受けません。 

もう 1 つのエッジ ケースは、地区に多くの測点があるものの、個々の値が非常に小さい場合です。 素朴な貪欲なソリューションでは地区を完全に無視する可能性がありますが、DP はしきい値に到達するとゲインが大幅に増加するかどうかを正しく評価します。 

最後に、C が n に比べて大きい場合でも、上限 k が地区のサイズによって制限され、選択肢を人為的に増やすことなく遷移が実行可能なオブザーバー数の範囲内にとどまることが保証されるため、DP は依然として正しく動作します。
