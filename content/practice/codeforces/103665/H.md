 ## アルゴリズムのチュートリアル

 無限の糸に沿って歩くことをシミュレートします$010101...$合わせようとしているときに$t$続編として。 

1. 交互シーケンス内の現在位置を表すポインターを初期化します。 値 0 に対応する位置 0 から開始します。 
2. インデックスを初期化する$i = 0$文字列をスキャンするため$t$。 合わせてみます$t[i]$交互シーケンス内の現在位置と一致します。 
3. その間$i < |t|$、 比較する$t[i]$現在の代替文字を使用します。 位置が偶数の場合、文字は 0 です。 奇数の場合は 1 です。 
4. 現在の文字が一致する場合$t[i]$、 前進$i$by 1. これは、正常に配置されたことを意味します$t[i]$サブシーケンス内のこの位置にあります。 
5. サブシーケンスのマッチングでは文字をスキップできるため、すべての場合において、交互シーケンス内の位置を 1 つ進めます。 
6. 1回$i$到達する$|t|$、すべての文字を一致させました。 交互シーケンス内の現在位置が最小です$m$埋め込みが可能になる$t$。 

重要な行動は、決して後戻りしないことです。 それぞれの不一致は単に文字をスキップすることを意味します。$s_m$、各一致は次の 1 文字を消費します。$t$。 

### なぜ効果があるのか

 どの時点でも、すでに一致している不変式を維持します。$t[0..i-1]$交互の文字列内の位置の増加シーケンスを使用します。 次に利用可能な位置は、順序を維持できる最小のインデックスです。 交互の文字列は固定されており決定的であるため、一致が現れたらすぐに貪欲に取得することで、最後の文字に使用される最終位置を最小限に抑えることができます。 キャラクターのマッチングが遅れると、その配置がさらに右に移動するだけで、それが早くなることはありません。そのため、貪欲な戦略により、可能な限り最小限の結果が得られます。$m$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = input().strip()
    pos = 0  # current position in s_m (conceptually infinite)
    
    for ch in t:
        # advance until we can match ch
        while pos % 2 != (ch == '1'):
            pos += 1
        # match at this position
        pos += 1
    
    print(pos)

if __name__ == "__main__":
    solve()

 ## 特殊なケース

 特殊なケースの 1 つは、次の最初の文字が$t$この状況では、位置 0 は使用できないため、アルゴリズムは最初の一致の前に位置 1 に進む必要があります。 たとえば、$t = 1$、pos = 0から開始し、不一致を確認し、1に増分して、そこで一致します。 出力は 2 になります。これは、1 のサブシーケンスを含む最も短い交互プレフィックスの長さが 2 であることを正しく反映しています。 

もう 1 つのケースは、次のような同一の文字が長く続く場合です。$t = 000...0$。 交互構造により、奇数の位置をすべてスキップする必要があるため、後続の各一致では一度に 2 ステップずつ前にジャンプする必要があります。 アルゴリズムはこれらのスキップを自然に蓄積し、実際の埋め込み要件に一致する、必要なゼロの数から 1 を引いた数の約 2 倍に増加する最終位置を生成します。 

最後の微妙なケースは、次のような交互のパターンです。$t = 101010$。 これは構造と一致しているにもかかわらず、$s_m$、サブシーケンスの埋め込みは依然として位置合わせに依存します。 このアルゴリズムは、互換性のある最も早い位置で各文字を照合し、パリティが交互に使用されるため、最終的には余分な遅延なく正確に連続した位置を消費し、次の結果が得られます。$m = |t|$または、開始時のアライメントに応じて非常に近くなります。
