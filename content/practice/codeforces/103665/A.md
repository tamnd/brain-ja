 ## 問題の理解

 2 人の出場者が、時間の経過とともにどれだけのプログラミングの問題を解決したかを追跡しています。 それぞれがすでにある程度の数の問題を解決しており、その後は毎日一定の割合で問題を解決し続けます。 タスクは、一定の日数が経過した後に、最終的にどちらが合計数が多くなるか、または同点かどうかを判断することです。 

具体的には、1人で初期カウントからスタート`a`そしてそれを増加させます`x`毎日のために`c`日々。 もう一つは次から始まります`b`そしてそれを増加させます`y`毎日同じ日数。 最終的な合計を比較するように求められます。 

最初の値は次のようになります`a + x * c`、2番目は次のようになります`b + y * c`、どちらが大きいかを出力します。 

制約は非常に小さく、すべての入力は 1 ～ 10 です。これにより、定数時間の演算以外のパフォーマンスを考慮する必要がすぐになくなります。 ループで合計を再計算するアプローチでも`c`反復の最大数は 10 であるため、ここでは days は重要ではありません。 

唯一の微妙な問題は、両方の線形数列を正しく累積した後で比較が確実に行われるようにすることです。 典型的な間違いは、日次料金を比較することです`x`そして`y`初期値を考慮せずに、または次のように誤って間違った乗算をしてしまう可能性があります。`(a + x) * c`の代わりに`a + x * c`。 

オーバーフローや入力サイズが大きいという点で隠れたエッジ ケースはありませんが、概念的には両方の合計が等しい場合が境界ケースとなります。 たとえば、次の場合`a = 3, x = 2, b = 5, y = 1, c = 2`の場合、両方とも 7 で終了し、出力は引き分けでなければなりません。 

## アプローチ

 ブルートフォース解釈により、プロセスが毎日シミュレートされます。 から始まる`a`そして`b`を繰り返し追加します`x`そして`y`のために`c`繰り返し。 これは単純明快で、ストーリーを正確に反映しています。 毎日の後に両方のカウンターを更新します。 後`c`数日かけて結果を比較します。 

これは、説明されているプロセスを直接モデル化しているため、正しく機能します。 ただし、この問題に対してはすでに効率的ではありますが、構造を最もきれいに表現したものではありません。 重要な観察は、両方のシーケンスが一定のステップ サイズを持つ等差数列であるということです。 すべてのステップをシミュレートする代わりに、単一の乗算を使用して閉じた形式で最終値を計算できます。 

この単純化が機能する理由は、定数値の繰り返しの加算が乗算と同等であるためです。 やってる`x`追加した`c`回はまさに`x * c`、同様に`y`。

 ## アルゴリズムのチュートリアル

 両方の最終結果を計算し、直接比較します。 

1. 5 つの整数を読み取ります`a, x, b, y, c`。 これらは、初期スコア、毎日の成長率、および成長が発生する日数を定義します。 
2. 最初の人の最終スコアを次のように計算します。`a + x * c`。 これはから始まることを表します`a`そして追加`x`1日1回`c`日々。 
3. 2 人目の最終スコアを次のように計算します。`b + y * c`、同じロジックを適用します。 
4. 2 つの最終値を比較します。 先の方が大きい場合は、最初の人が勝ちです。 2 番目の方が大きい場合は、2 番目の人が勝ちます。 それ以外の場合は同等です。 
5. 対応する文字列を出力します`"Feefa"`、`"Foofa"`、 または`"Draw"`。 

### なぜ効果があるのか

 各個人の進歩は直線的であり、1 日あたり一定の増加があります。 後の合計`c`日数は、初期値と同一の増分の合計にのみ依存します。 加算は結合的かつ可換的であるため、毎日の増分を 1 つの乗算にグループ化しても結果は変わりません。 したがって、最終的な合計の比較は、日ごとのシミュレーション結果全体を比較することに相当します。

唯一の微妙な点は、正しい演算子の優先順位とグループ化を確保することです。 書き込み`a + x * c`乗算は加算の前に評価されるため、これは正しいですが、意味を変えることなくわかりやすくするために括弧を追加できます。

def solve():
    import sys

 ## 特殊なケース

 主なエッジケースは、両方の参加者が同じ合計で終了する場合です。 例えば、`a = 3, x = 2, b = 5, y = 1, c = 2`アルゴリズムは両方の式を独立して計算し、等しいことを正確に識別し、`"Draw"`。 

もう 1 つの微妙なケースは、1 人の参加者が遅れてスタートしたが、1 日あたりのレートが高い場合です。 例えば、`a = 1, x = 3, b = 2, y = 1, c = 4`最終的な値が得られます`13`そして`6`。 この式は、初期値のみを比較するのではなく、毎日の増分をすべて集計するため、累積された利点を正確に把握します。 

問題のサイズが小さいとしても、これらのケースは、ソリューションが中間または日ごとのスナップショットではなく、完全な線形増加を比較する必要があることを強調します。
