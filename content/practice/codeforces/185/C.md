 ## 解決策
 ## 問題の理解

 私たちは「秤量板」を並べた三角形の構造を与えられています。 一番上の行には、$n$プレート、次は$n-1$、というように、プレートが 1 つある最後の行まで続きます。 各プレートには閾値重量があります。 プレートにかかる荷重がそのしきい値に達するかそれを超えると、そのプレートはすぐに壊れ、それが保持していたすべてのものを、プレートの位置に応じて左下または右下のいずれかの下の列に再分配します。 

最初に、最上列の各プレートには一定量のシリアルが与えられます。 プロセスが開始されると、プレートは何らかの順序で壊れる可能性があり、プレートが壊れると、その内容物が分岐構造を通って下に伝播し、最終的に何らかの塊が底部の単一プレートに到達することがあります。 問題は、正の量のシリアルが底に到達するような一連のブレイク決定 (各内部プレートの左または右) が存在するかどうかです。 

したがって、問題は 1 つの決定論的なプロセスをシミュレートすることではありません。 これは、最後のノードへの到達を妨げる形でマスがブロックされない、最上行から最下位までの有効なカスケード パスが少なくとも 1 つ存在するかどうかに関係します。 

入力サイズ$n \le 50$十分小さいので$O(n^3)$あるいは$O(n^4)$スタイルの動的プログラミングは許容されます。 ただし、すべてのブレーク シーケンスの単純なシミュレーションは指数関数的です。各内部プレートは 2 つの選択肢に分岐し、おおよその結果が得られます。$2^{n^2}$可能性はありますが、それは完全に不可能です。 

上の行の複数のプレートが共有の下流ノードを介して相互作用する可能性のある質量で始まる場合、微妙なエッジケースが現れます。 単一の「電流経路」のみを追跡する単純なシミュレーションでは、複数の独立したソースが低レベルで結合して質量が増加し、他の方法では発生しないさらなる中断が可能になる可能性があることを見逃してしまいます。 

もう 1 つの特殊なケースは、すべてのトップ ウェイトが小さすぎてプレートを破壊できない場合です。 この場合、伝播はまったく起こらず、底には何も到達しないため、答えは「Cerealguy」になるはずです。 

## アプローチ

 重要な問題は、質量の伝播が単一の経路に沿って直線的ではないことです。複数の流入源がノードで合流する可能性があり、プレートが破損するかどうかは、考えられるすべての上流ルートから到着する累積質量の合計に依存します。 これは、個々の軌道ではなく質量の到達可能性の観点から考える必要があることを示唆しています。 

強引なアプローチでは、すべての破壊イベントで左/右の考えられるすべての選択をシミュレートします。 各内部ノードには最大 2 つの発信エッジがあり、構造には$O(n^2)$したがって、可能なグローバル構成の数は指数関数的に増加します。 それぞれのシミュレーションがあったとしても$O(n^2)$、合計が手に負えなくなります。 

重要な洞察は、視点を逆転させることです。 質量がどのように流れ落ちるのかを問うのではなく、もし破壊方向を敵対的または最適に選択できる場合、各節点を強制的に通過させることができる最大質量はいくらか、と考えます。 正の質量が底部に到達するかどうかだけを気にするので、これを、底部まで生き残る量を最大化しようとするミニマックス スタイルの伝播問題として扱うことができます。 

各プレートは流れを分割するノードのように機能しますが、流れが壊れたときにどの出力エッジが全質量を受けるかを自由に選択できます。 したがって、各ノードでは、入ってくるすべての質量を、底部に到達するという点でより「有望な」子に向けると仮定できます。 

これにより、三角形に関する動的計画法が定式化されます。 各ノードについて、その時点以降の最適なルーティングの決定を前提として、そのノードから開始して下部に配信できる最大可能質量を計算します。 あるノードで蓄積された質量がそのしきい値に達すると、そのノードは「アクティブ化」され、その質量全体が下に渡されます。 それ以外の場合は、それ以上何も貢献しません。 

これにより、問題はボトムアップ DP に変わり、各ノードが上からの貢献を集約し、方向を選択して下に転送します。

 ## アルゴリズムのチュートリアル

 三角形をグリッドとしてモデル化し、各セルが$(i, k)$カスケード分割を介して最上列から質量を受け取ります。 

1. DP テーブルを初期化することから始めます`dp[i][k]`プレートに到達する総質量を表す$(i,k)$可能な限り最善の伝播戦略の下で。 
2. 一番上の行を直接設定します。`dp[1][k] = a_k`。 これがシリアルの初期配置です。 
3. 行を上から下に処理します。 各プレートで$(i,k)$、入ってくる質量がそれを破壊するのに十分であるかどうかを確認します。 もし`dp[i][k] < w[i][k]`の場合、このノードはそれ以上何も伝播できないため、下方向には何も寄与しません。 
4. プレートが破損した場合、このノードのすべての質量は、その 2 つの子の正確に 1 つに転送される必要があります。$(i+1, k-1)$または$(i+1, k)$、どちらが有効かに応じて。 
5. 最終的に最下位に到達する能力がより高いという意味で、どちらの子供が「優れている」かを計算します。 これを正しく行うために、寄与をボトムアップに伝播して、各ノードが最終的に最終シンクにどれだけの質量を提供できるかを認識できるようにします。 
6. すべてのノードを処理した後、一番下のノードを確認します$(n,1)$。 もし`dp[n][1] > 0`、その後、いくつかの穀物がネズミに到達できるようにする一連の休憩と指示が存在します。 

### なぜ効果があるのか

 このプロセスは、各ノードがフローをブロックするか、フロー全体を 1 つの子に転送する、有向非巡回グラフ上のフロー ネットワークとして見ることができます。 構造は DAG であり、決定はローカルであるため、グローバル戦略は各ノードでローカルな選択に分解されます。 DP は、すべての子孫で最適なルーティングを仮定して、ノードごとに達成可能な最大のダウンストリーム寄与を計算します。 これにより、正の流れが底部に到達した場合、その流れは根元の DP 値によって確実に捕捉されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    w = [None]
    for i in range(n):
        w.append(list(map(int, input().split())))
    
    # dp[i][k] = maximum mass that can reach (i,k)
    dp = [[0] * (n + 2) for _ in range(n + 2)]
    
    for k in range(1, n + 1):
        dp[1][k] = a[k - 1]
    
    for i in range(1, n + 1):
        for k in range(1, n - i + 2):
            if dp[i][k] < w[i][k - 1]:
                continue
            
            # if it breaks, we can send all mass down either way
            if i == n:
                continue
            
            left = (i + 1, k - 1)
            right = (i + 1, k)
            
            li, lk = left
            ri, rk = right
            
            # propagate to both possibilities as achievable states
            if lk >= 1:
                dp[li][lk] += dp[i][k]
            if rk <= n - i:
                dp[ri][rk] += dp[i][k]
    
    print("Fat Rat" if dp[n][1] > 0 else "Cerealguy")

if __name__ == "__main__":
    solve()
```DP テーブルには、各プレートに蓄積できる質量が格納されます。 トランジションはプレートが壊れるかどうかをチェックします。 その後のみ、その一括転送が行われます。 実装における重要な考え方は、複数の親が同じノードに貢献できるため、伝播を子への蓄積として扱うということです。 

境界処理は非常に重要です。左の子は次の場合にのみ存在します。$k-1 \ge 1$、正しい子は次の場合にのみ存在します。$k \le n-i$。 各行が 1 要素ずつ縮小されるため、ここでの 1 つ違いの間違いはよくあります。 

最終的な答えは、質量が最後の行の唯一のノードである左下のセルに到達するかどうかによってのみ決まります。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、最上列のプレートが破損していない場合です。 たとえば、すべてが$a_i < w_{1,i}$、 それから`dp`最初の行を超えて伝播することはありません。 遷移がトリガーされず、底値がゼロのままになるため、アルゴリズムはこれを自然に処理します。 

もう 1 つのケースは、単一の上部プレートのみが破損し、その質量がパス全体に分割され、後で両方が破損する場合です。 DP は依然として中間ノードで寄与を蓄積しますが、しきい値が満たされない場合、伝播はローカルで停止し、下部での誤った蓄積を防ぎます。 

最後の微妙なケースは、複数の上部ノードが同じ中間プレートに寄与する場合です。 アルゴリズムは、しきい値をチェックする前にこれらの寄与を正しく合計し、入ってくる総質量が十分な場合にのみプレートが破損することを保証します。
