 ## 解決策
 ## 問題の理解

 円状に配置された数字の文字列が与えられ、それを何度でも回転させることができます。 各回転は、左または右のいずれか 1 つの循環シフトです。 回転を選択した後、結果として得られる線形文字列を見て、その「可能性」を測定します。これは、単純に同じ桁の最大の連続セグメントの数です。 

たとえば、次のような文字列では、`112223`、セグメントは`11 | 222 | 3`したがって、可能性は 3 です。このセグメントの数が減れば、回転の方が優れていると考えられます。 可能な限り最小のセグメント数を実現するすべての回転の中で、元の文字列からの巡回シフトの必要数が最小のものを選択し、その数値を方向を示す符号 (左シフトは負、右シフトは正) とともに出力する必要があります。 

重要な観察は、回転によって隣接する文字の関係の複数セットが変化するのではなく、円を「カット」して線を形成する場所が変化するだけであるということです。 つまり、カットによって変化する隣接ペアが 1 つだけあることを除いて、すべての回転がほぼ同じ構造を持っています。 

n が 10^6 までの制約により、二次関数から遠ざけられます。 すべての回転を試してセグメント数を最初から再計算するソリューションでは、O(n^2) が必要になりますが、これでは遅すぎます。 すべての回転を暗黙的に評価する O(n) アプローチが必要です。 

微妙な特殊なケースは、すべての文字が同一である場合です。 その場合、回転ごとに 1 つのブロックが生成されるため、すべての答えは同様に最適であり、ゼロ シフトを返さなければなりません。 

もう 1 つの重要なケースは、有効な最適なカット位置が複数ある場合です。 たとえば、文字列に隣接する文字が異なる位置が複数ある場合、複数の回転により可能性が均等に減少するため、巡回シフト距離の観点から元の位置に最も近い位置を選択する必要があります。 

## アプローチ

 強引なアプローチでは、すべての回転を試みることになります。 回転ごとに、回転された文字列を構築し、隣接する文字が何回異なっているかを数えます。 これでセグメントの数が得られます。 セグメント数は遷移から簡単に計算できるため、これは正しく機能しますが、各回転のコストは O(n) であり、n 回の回転があるため、合計操作は O(n^2) となり、最大 10^6 の n には大きすぎます。 

重要な構造的洞察は、セグメント数は円形の文字列をどこで切断するかによってのみ決まるということです。 文字列を円形と見なす場合、すべての回転は開始カット位置の選択に対応します。 円内のすべての隣接するペアは変更されません。 回転された文字列の最後の文字と最初の文字の間のエッジのみがカットに依存します。 これは、すべての隣接不一致を一度事前計算し、カットが不一致を解消するかどうかをチェックすることによって一定時間で各回転を評価できることを意味します。 

これにより、円をカットする可能性のあるすべての位置をスキャンし、結果として得られるセグメント数を位置ごとに O(1) で計算し、最適なものを選択するという問題が軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 各位置 i を、文字 i−1 と i の間の可能な「カット」として扱います (ラップアラウンドあり)。 ここでのカットは、回転された文字列が i から始まることを意味します。

1. どの隣接するペアが元の循環的な意味で異なるかを計算します。 実際には循環構造を明示的に構築する必要はありません。 各位置について、s[j] と s[j−1] が異なるかどうかだけを知る必要があります。 
2. 円内の不一致の隣接ペアの総数が一定であることを観察します。 この値を T とします。 
3. 位置 i で選択されたカットの場合、影響を受ける隣接関係は s[i−1] と s[i] の間のエッジのみです。 線形表現では、このエッジは境界となり、内部遷移としてカウントされません。 
したがって、s[i-1]とs[i]が異なる場合、ここでカットすると全体から1つの遷移が削除され、セグメント数が1つ減ります。 それらが等しい場合、セグメント数は変わりません。 
5. すべての i について、それが「受益カット」であるかどうかを計算します。これは、s[i−1] != s[i] を意味します。 このような i ごとに、可能な最小のセグメント数が達成されます。 
6. すべての有益なカットの中で、元の文字列から必要な操作の数が最も少ないものを選択します。 i による回転は、i 回の左シフトまたは n−i 回の右シフトによって実現できるため、これら 2 つの値のうち小さい方を選択します。 等しい場合はどちらの方向でも問題ありません。 
7. 選択したシフトを、左シフトを使用する場合は負の符号を付けて出力し、右シフトを使用する場合は正の符号を付けて出力します。 

### なぜ効果があるのか

 回転のセグメント数は、隣接する等しくないペアがいくつ存在するかによってのみ決まり、単一のカット エッジを除いて、すべての回転は同じ一連の円形隣接関係を共有します。 これは、すべての回転が他の回転と異なるのは、トランジションを 1 つだけ削除するかどうかだけであるということです。 したがって、最適な値は、異なる境界でカットするかどうかによってのみ決まります。 これが修正されると、演算の最小化は、セグメント構造とは無関係に、サイクル上の単純な距離の問題になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    s = input().strip()

    if n == 1:
        print(0)
        return

    best_i = None

    for i in range(n):
        if s[i] != s[i - 1]:
            if best_i is None:
                best_i = i
            else:
                # choose closer rotation to 0
                def cost(x):
                    left = x
                    right = n - x
                    if left <= right:
                        return left, -left
                    return right, right

                c_best = cost(best_i)
                c_cur = cost(i)

                if c_cur < c_best:
                    best_i = i

    if best_i is None:
        print(0)
        return

    left = best_i
    right = n - best_i

    if left <= right:
        print(-left)
    else:
        print(right)

if __name__ == "__main__":
    solve()
```コードはまず、隣接する文字が異なるすべての有効なカット位置を特定します。 これらはまさに、セグメントの最小数を実現する回転です。 次に、左右のシフト コストを比較して、元の構成に最も近い回転をそれらの中から選択します。 そのようなカットが存在しない場合、文字列は均一であり、操作によって何も変更されません。 

微妙な点はインデックス付けです。i を i−1 と i の間のカットとして扱うと、Python の負のインデックス付けを使用してラップアラウンドが自然に処理されます。ここで、s[i-1] は i = 0 の場合の最後の文字を正しく参照します。 

## 実用的な例

 ### 例 1

 入力文字列:`12233321`隣接する文字が異なるカット位置を調べます。 

| 私 | s[i-1] | s[i] | 有効なカット | 残りのコスト | 適切なコスト | 選ばれた |
 | --- | --- | --- | --- | --- | --- | --- |
 | 0 | 1 | 1 | いいえ | - | - | - |
 | 1 | 1 | 2 | はい | 1 | 7 | 左 |
 | 2 | 2 | 2 | いいえ | - | - | - |
 | 3 | 2 | 3 | はい | 3 | 5 | 左 |
 | 4 | 3 | 3 | いいえ | - | - | - |
 | 5 | 3 | 3 | いいえ | - | - | - |
 | 6 | 3 | 2 | はい | 6 | 2 | 右 |
 | 7 | 2 | 1 | はい | 7 | 1 | 右 |

 右シフトを 1 回だけ必要とするため、最適なカットは i = 7 です。 これは、セグメント数の点では複数の回転が最適であっても、最終的な答えは原点までの循環距離によって決定されることを示しています。 

### 例 2

 入力文字列:`11111`| 私 | s[i-1] | s[i] | 有効なカット |
 | --- | --- | --- | --- |
 | 私はすべて | 同じ | 同じ | いいえ |

 有効なカットがないため、回転するたびに 1 つのブロックが生成されます。 何も改善したり、回転を区別したりする操作はないため、出力は 0 です。

 | 測定 | 複雑さ | 説明 |

 | 時間 | O(n) | 各位置は、隣接性の差について 1 回チェックされ、選択のために 1 回チェックされます。

 ## 特殊なケース

 すべての文字が同一の場合、隣接する文字が異なる位置はありません。 アルゴリズムは正しく終了します`best_i`すべての回転で 1 つのセグメントが生成され、回転によって結果が改善または区別されないため、設定を解除してゼロを直接出力します。 

交互または繰り返しのパターンなど、有効なカット位置が複数ある場合、アルゴリズムは各カット候補を個別に評価し、巡回距離を元の位置と比較します。 コスト関数は円上で対称であるため、選択される結果は常に最も近い有効なカットであり、右シフトより悪くない場合は左シフトを優先することで同点が自然に解決されます。 

最適なカットが位置 0 にある場合、つまり回転が必要ない場合、左右のコストは両方ともゼロになります。 アルゴリズムはゼロを出力し、元の文字列がすでに最適であることを正しく反映しています。
