 ## 解決策
 ## 問題の理解

 一列に並べられた一連の正の整数が与えられます。 各位置はハムスターを表し、各ハムスターは一連の「スキル」を提供します。ここで、スキルとは単にその数値の任意の約数です。 

L から R までのハムスターの連続セグメントについて、そのセグメント内の少なくとも 1 匹のハムスターに出現するすべての約数を調べます。 X をセグメント全体で収集された個別の約数の数とします。 セグメントのスコアは、X からセグメントの長さを引いたものです。 すべてのセグメントにわたって可能な最大スコアを見つけたいと考えています。 

したがって、問題は、セグメントを拡張して利用可能な約数の数を増やすことと、選択された要素の数に等しい線形ペナルティを支払うこととの間のトレードオフです。 

主な問題点は、各位置が 1 つの値ではなく、一連の約数に寄与し、これらのセットが重なり合うことです。 n が 5 × 10^5 まで、値が 5 × 10^6 までという制約により、セグメントごとの約数を再計算したり、範囲を繰り返し再スキャンしたりするソリューションは避けられます。 

素朴なアプローチでは、すべてのセグメントを試し、毎回約数の和集合を計算します。 O(n^2) 個のセグメントがあり、単一の結合計算ですら大きすぎるため、これはすぐに失敗します。 

注意深いブックキーピングを行わずにウィンドウをスライドさせながら除数の数を維持しようとすると、より微妙な失敗モードが発生します。 除数は多くの要素に出現する可能性があるため、要素を削除または追加するには多くの除数の状態を更新する必要がありますが、適切に構造化されていない限り、依然として時間がかかりすぎる可能性があります。 

有益な観察は、スコアがセグメント内でアクティブな個別の約数の数と、含まれる要素の数にのみ依存するということです。 これは、約数ごとの寄与と、セグメントを拡張するときに各約数が「存在」する頻度の観点から考える必要があることを示唆しています。 

## アプローチ

 ブルートフォース戦略は簡単です。セグメントごとに、すべての要素を列挙し、各数値を因数分解し、すべての約数を 1 つのセットに集めて、スコアを計算します。 単一セグメントの場合、最大 5 × 10^6 の数値を因数分解するには、前処理を使用するとおよそ O(sqrt(a_i)) 以上のコストがかかりますが、高速因数分解を前提としても、各セグメントでは潜在的に多くの約数リストをマージする必要があります。 O(n^2) 個のセグメントがあるため、最悪の場合、合計作業量は 10^10 操作を超えて爆発的に増加しますが、これはリモートで実行可能ではありません。 

核となる構造的洞察は、視点を逆転させることです。 セグメントについて考えて約数を収集する代わりに、各約数 d とその出現によって引き起こされる間隔構造について考えます。 

固定除数 d の場合、d が a[i] を除算する場合にのみ、位置 i に表示されます。 任意のセグメント内で、セグメントが d が出現する少なくとも 1 つの位置と交差する場合に限り、d は X に寄与します。 この条件は、セグメントにセット Occ[d] からのインデックスが少なくとも 1 つ含まれていると言うのと同じです。 

したがって、約数 d ごとに、間隔カバレッジ インジケーターのように動作します。選択したセグメントがその出現セットと交差する場合、X に 1 を与えます。 

ここでスコアを書き換えます。 

F(L, R) = 出現セットが [L, R] と交差する約数の数 - (R − L + 1)。 

これをすべてのセグメントで最大化したいと考えています。 

これは、アクティブになったときを追跡して各約数を個別に処理する場合、古典的な「イベントを含む最大部分配列」問題になります。 固定除数 d の場合、R を展開すると、d を含むインデックスを最初に含めたときにその寄与がオンになり、より複雑な状態ですべての出現をスライドしたときにのみオフになります。 ただし、完全な状態を維持する代わりに、R をスイープし、最も早い出現制約を追跡することによって寄与を処理できます。

よりクリーンな変換は、各約数 d に、それが出現するインデックスのリストを割り当てることです。 セグメント [L, R] の場合、L ≤ i ≤ R で Occ[d] に i が存在する場合に限り、d は 1 になります。これは、L ≤ max Occ[d] および R ≥ min Occ[d] と同等です。 したがって、各約数はインデックス ライン上の間隔 [minOcc[d], maxOcc[d]] に対応し、選択したセグメントがこの間隔と交差する場合は 1 になります。 

したがって、各約数は、それを「アクティブ化」する L と R のペアの範囲を定義します。 セグメントごとの約数を直接カウントする代わりに、役割を逆にします。各約数間隔について、それと交差するすべてのセグメントに +1 を加算しますが、各セグメントにはその長さに等しいコストがかかります。 

これは、セグメントの端点の線上の間隔にわたる幾何学的範囲の集約問題になります。 これを R をスイープし、各 L に対して現在アクティブな約数の数を維持してから長さを減算するという方法に減らすことができます。 

重要な単純化は、[L, R] に少なくとも 1 回出現する約数の数を L ごとに維持することです。 R が右に移動するにつれて、その約数を反復し、各約数が R に出現することをマークすることによって、a[a[R]] からの寄与を追加します。各約数について、それが現在のウィンドウに表示されているかどうかを維持し、アクティブな約数のグローバル カウントを維持します。 ただし、L への依存が必要なため、これだけでは十分ではありません。 

標準的な解決策は、代わりに各約数の発生をイベントとして扱い、約数ごとの周波数カウンタでスライディング ウィンドウを維持し、周波数 ≥ 1 を持つ約数の数のグローバル カウントを維持することです。 次に、2 ポインター ウィンドウを使用しますが、各 R のすべての L を最大化する代わりに、X − 長さがどのように動作するかを追跡することによって、最適な L をサポートするデータ構造を維持します。 これは、L を減算し、R が拡張するときにアクティブな寄与を追加する場合に、プレフィックスを最適に維持することと同等になります。 

これを実装する実際的な方法は、L を右にシフトすると、最後に出現した除数を削除した場合にのみ X が減少することに注意して、現在の X と L に依存する補正を維持することです。 したがって、ウィンドウ内で除数ごとのカウントを維持し、X は除数カウントが 0 から 1 または 1 から 0 になった場合にのみ変化します。 

次に、2 ポインター ウィンドウを保持し、候補の回答を X − (R − L + 1) として計算し、スコアを改善しながら L を貪欲に更新します。 ウィンドウは、スコアを増やしながら R ごとに L をできるだけ遠くに移動するように維持されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n² · sqrt(A)) | O(A) | 遅すぎる |
 | 最適 | O(n · 約数の合計ログ) | O(A + n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ふるいのようなアプローチを使用して、max(a[i]) までの数値のすべての約数を事前計算し、数値ごとにその約数リストを保存します。 これにより、ウィンドウの更新中に除数を繰り返し再計算することが回避されます。 
2. 現在のセグメントに除数 d が何回現れるかの周波数配列 freq[d] を維持します。 また、現在 freq[d] ≥ 1 を持つ約数の数を表す変数 X も維持します。 
3. ツーポインタウィンドウ[L、R]を使用します。 0 と空のウィンドウの両方から開始します。 
4. R を左から右に展開します。 新しい要素 a[R] ごとに、そのすべての約数を反復処理します。 各 d について、freq[d] をインクリメントし、freq[d] が 1 になった場合、セグメント内で d がアクティブになったばかりであるため、X をインクリメントします。 
5. a[R] を追加した後、スコア F(L, R) が増加または減少しない限り、L を右に移動してみます。 a[L] を削除する場合、a[L] の約数 d を繰り返し、freq[d] を減分し、freq[d] が 0 になった場合は X を減分します。 
6. 固定 R ごとに、L を最適化した後、答えの候補 X − (R − L + 1) を計算し、グローバル最大値を更新します。 

重要な考え方は、R が固定されている場合、スコアを向上させずに L をできるだけ右に押し込むと、それ以上動かしてもスコアが低下するだけであるということです。 したがって、R で終わる最良のセグメントは常にこの貪欲な短縮によって捕捉されます。 

## なぜ機能するのか

このアルゴリズムは、すべての約数がウィンドウ内に少なくとも 1 回出現するときに正確に X に寄与するウィンドウを維持します。 X に影響を与える唯一の状態変化は、ゼロと非ゼロの間の除数周波数の遷移です。 これらの遷移はエンドポイントの追加または削除に対してローカルであるため、X はウィンドウ定義に合わせて増分的かつ一貫して進化します。 

各 R について、貪欲な縮小を介して暗黙的にすべての L を検索します。 スコア関数は、長さの短縮に対してあまりにも多くのアクティブな除数を破壊しない要素を削除するときに単調に変化します。 これにより、維持される L がその R にとって最適であることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_divisors(max_a):
    divs = [[] for _ in range(max_a + 1)]
    for i in range(1, max_a + 1):
        for j in range(i, max_a + 1, i):
            divs[j].append(i)
    return divs

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    max_a = max(a)

    divs = build_divisors(max_a)

    freq = [0] * (max_a + 1)
    X = 0

    L = 0
    ans = 0

    for R in range(n):
        for d in divs[a[R]]:
            if freq[d] == 0:
                X += 1
            freq[d] += 1

        while L <= R:
            # try removing a[L] if it improves or does not hurt
            best_remove_gain = 0

            # compute effect of removing L
            # net change in score = -(loss in X) + 1
            loss = 0
            for d in divs[a[L]]:
                if freq[d] == 1:
                    loss += 1

            if 1 - loss >= 0:
                # safe to remove
                for d in divs[a[L]]:
                    freq[d] -= 1
                    if freq[d] == 0:
                        X -= 1
                L += 1
            else:
                break

        ans = max(ans, X - (R - L + 1))

    print(ans)

if __name__ == "__main__":
    solve()
```除数テーブルの構築は、値ごとに除数アクセスを O(1) にする前処理ステップです。 周波数配列は、現在のウィンドウ内の各除数の存在を追跡します。 

縮小条件では、長さを 1 減らすメリットと X の潜在的な損失を比較します。 a[L] を削除すると、長さは常に 1 減り、ウィンドウから完全に消える約数の数だけ X が減ります。 少なくとも 1 つの約数が消えた場合、正味の効果がまだ負ではないかどうかを確認し、貪欲に縮小します。 

## 実用的な例

 ### 例 1

 入力:

 n = 3、a = [14、2、20]

 スライディング ウィンドウを追跡します。 

| R | Ｌ | X (個別の約数) | ウィンドウサイズ | スコア |
 | --- | --- | --- | --- | --- |
 | 0 | 0 | divisors(14) = 1,2,7,14 したがって、X=4 | 1 | 4-1=3 |
 | 1 | 0 | add divisors(2) は、すでに表示されている 1,2 以外に新しいものを追加しません。したがって、X=4 | 2 | 4-2=2 |
 | 2 | 0 | add divisors(20) は 4,5,10,20 を加算するため、X=8 | 3 | 8-3=5 |

 最良のセグメントは [0,2] でスコア 5 です。 

このトレースは、除数の重複が早期に安定し、新しい数値のみが X を拡張する様子を示しています。

 ## 特殊なケース

 重要なエッジケースは、すべての数値が同一である場合です。 その場合、すべての約数は最初の要素から出現するため、X は R とともに増加せず、最適な答えは常に 1 − 長さであり、長さ 1 で最大化されます。要素を削除しても X が改善されることはないため、アルゴリズムはこれを処理します。そのため、L は固定されたままになるか、安全な場合にのみ縮小されます。 

もう 1 つのエッジ ケースは、数値が素数構造、たとえば素数やペアごとに互いに素な値を持つ場合です。 この場合、拡張するたびに X が大幅に増加するため、ウィンドウが完全に拡張されます。 X の損失は除去された約数に正確に等しいため、除去は有益ではないため、貪欲条件では L が縮小されることはありません。 

最後の微妙なケースは、密な数値と疎な数値が混在している場合で、一部の約数が配列全体で 1 回しか現れない場合です。 このアルゴリズムでは、これらの約数がウィンドウ内に 1 つ出現するときに正確にカウントされ、その要素が離れるときに正確に削除されるため、遷移中に X が過大カウントまたは過小カウントされることはありません。
