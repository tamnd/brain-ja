 ## 解決策
 ## 問題の理解

 すでに何人かが回答しているアンケートが提供され、その回答が言語ごとの数として要約されます。 回答者の総数は最終的に N に固定されますが、わかっているのはそれらの回答のサブセットだけです。 残りの人々は、まだ登場していないまったく新しい言語を含む、任意の言語を選択できます。 

N 個の回答がすべて収集されると、各言語が N のパーセンテージとして報告され、各パーセンテージは同点を上方向に四捨五入して最も近い整数に丸められます。 最終的に報告される結果は、すべての言語にわたるこれらの四捨五入されたパーセンテージの合計です。 

タスクは、可能性の高い結果を決定することではなく、残りの応答を敵対的に割り当てて、四捨五入されたパーセンテージの合計を最大化できると仮定することです。 

重要な出力は、残りの N から sum(Ci) を引いたすべての投票を分配した後のこの最大可能合計です。 

制約は非常に具体的な意味で重要です。 N が最大 10^5 であるため、可能なすべての割り当てをシミュレートしたり、残りの人々のすべての分布を反復しようとしたりするソリューションは不可能です。 残りの人材を言語を超えて割り当てるためにあらゆる方法を試みるようなことであっても、本質的には指数関数的であるため、すぐに除外されます。 代わりに、丸めがカウントの関数としてどのように動作するかを推論する必要があります。 

丸めに関して微妙な問題が発生します。 各言語は独立して四捨五入されるため、投票数のわずかな変化により、言語が複数の四捨五入しきい値を超える可能性があります。 たとえば、4/10 = 40% の言語は 40 に四捨五入されますが、5/10 = 50% の場合は 50 に跳ね上がり、大きな離散的ゲインが得られます。 問題全体は、これらのしきい値交差を最適に活用することにあります。 

よくある失敗例は、残りのすべての投票を既存の言語に与えることが常に最適であると仮定することです。 たとえば、カウントが [1, 1] (N = 3) の場合、最後の投票を 1 つの言語に割り当て、[2, 1] となり、パーセンテージは 67 と 33 となり、合計は 100 になります。しかし、それを新しい言語として割り当てると、[1, 1, 1] となり、33 + 33 + 33 = 99 となります。ここでは機能しますが、他の構成では、丸めが非線形に相互作用するため、新しい言語に分割すると合計が増加する可能性があります。 分母付き。 

もう 1 つの失敗モードは、パーセンテージを連続的なものとして扱い、正確な丸めしきい値を追跡せずに限界ゲインによる貪欲な割り当てを試行することです。 丸めにより区分的に一定の動作が導入されるため、限界ゲインは線形または滑らかではありません。 

## アプローチ

 ブルートフォースアプローチでは、残りの各投票を既存の言語または新しい言語に分配し、最終的なパーセンテージを再計算し、四捨五入された合計を評価します。 残りの票が R 個で、既存の言語が L 個ある場合、各票には (L + R) 個の選択肢があるため、これは (L + R)^R となり、20 程度の R であってもまったく実行不可能です。 

解決策を導き出す構造は、言語を分離し、最終的な四捨五入合計に対する限界寄与の観点から考えることです。 各言語は、round(100 * Ci / N) に等しい値を提供します。 追加の投票を分配した後、これらの貢献の合計を最大化したいと考えています。 

割り当てという観点から考えるのではなく、追加の投票ごとに 1 つの言語の丸められた貢献がどれだけ増加するのかという観点から考えます。 各言語の寄与は、その端数が丸め境界を越える場合にのみ変化します。 したがって、言語ごとに、四捨五入パーセンテージを 1 単位増やすために必要な追加投票の「コスト」を計算でき、最終合計の「利益」は常に +1 になります。 

さらに、新しい言語も重要です。k 票で新しい言語を導入すると、貢献ラウンド (100 * k / N) が与えられます。 投票数が少ないため、最適な構築では、多数の小さな言語を作成するか、既存の言語を次の四捨五入しきい値まで改善する傾向があります。

これにより、問題は残りの投票を「有益なアップグレード」に貪欲に割り当てることになり、各アップグレードにはコスト (必要な投票数) と価値 (四捨五入合計の 1 の増加) が設定されます。 投票がなくなるまで、最も安価なアップグレードを繰り返し選択します。 

重要な洞察は、各言語の四捨五入された値は O(N) 回のみ増加し、すべての中間割り当てを調査する必要はなく、次のしきい値の遷移だけを調査する必要があるということです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 残りの投票の指数関数 | O(N) | 遅すぎる |
 | 最適 (貪欲なしきい値シミュレーション) | O(N log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは問題を 2 つのフェーズに分割しました。既存の言語の処理と、新しい言語による未使用の投票の処理です。 

1. まず、残りの投票数 R = N − sum(Ci) を計算します。 これらは私たちが配布できるリソースです。 
2. 既存の各言語の現在の寄与を四捨五入されたパーセンテージとして計算します。 これにより、常に含まれるベースライン スコアが得られます。 
3. 既存の言語ごとに、四捨五入のパーセンテージを正確に 1 増やすために、さらに何票必要か分析します。これは、四捨五入 100 * (Ci + x) / N が増加する最小の x を見つけることによって行われます。 

任意の増加ではなく「次の増加」に焦点を当てる理由は、丸められた値が変更されない限り、すべての中間状態は無関係であるためです。 

1. このような改善ごとに、ペア (コスト、ゲイン = 1) を記録します。これは、最終的な答えを 1 増やすためにコスト投票を費やすことを意味します。 
2. これらすべての改善候補をコスト順の最小ヒープにプッシュします。 
3. まだ投票が残っている間、私たちは繰り返し最も安価な改善を採用します。 コスト ≤ R の場合、それを適用します。R からコストを減算し、答えに 1 を加え、その言語の次の改善を再計算してヒープに戻します。 

これが機能するのは、増加するたびに、その言語が次の丸めジャンプで異なる数の投票を必要とする可能性があるためです。 

1. 有用なアップグレードを使い果たした後、残った投票は新しい言語に割り当てられます。 丸め関数は小さいスケールでは凹型であるため、新しい言語はそれぞれ、できるだけ小さいときに最適に寄与します。 投票がなくなるまで言語の作成を 1 つずつシミュレートし、常に言語サイズごとに可能な限り最良の限界利益を選択します。 

この正しさは、すべての決定がローカルな「次のしきい値超過」に還元され、中間割り当てをスキップしても、一部の言語で次に利用可能なしきい値よりもわずかな改善をもたらすことができないという事実から来ています。 

### なぜ効果があるのか

 丸め関数は、各言語の寄与を個別のプラトーに分割します。 各プラトー内では、投票を追加しても効果はありません。 次のプラトーに入るということだけが重要です。 したがって、すべての有益なアクションは、明確に定義されたコストを伴う、隣接するプラトー間のジャンプとして表すことができます。 各ジャンプは同じ値 (+1) を生成するため、最適な戦略は常に、利用可能な最も安価なジャンプを最初に実行することです。 これは、コスト増加イベントに対する古典的な貪欲な問題であり、ヒープにより、次の最適な改善が常に選択されることが保証されます。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def rounded_percent(x, n):
    return (200 * x + n) // (2 * n)

def next_threshold(ci, n):
    # find smallest x such that rounded(ci+x) > rounded(ci)
    cur = rounded_percent(ci, n)
    lo = 0
    hi = n
    while lo < hi:
        mid = (lo + hi) // 2
        if rounded_percent(ci + mid, n) > cur:
            hi = mid
        else:
            lo = mid + 1
    return lo

def solve():
    t = int(input())
    for tc in range(1, t + 1):
        n, l = map(int, input().split())
        arr = list(map(int, input().split()))
        
        used = sum(arr)
        r = n - used

        heap = []
        ans = 0

        for c in arr:
            ans += rounded_percent(c, n)
            cost = next_threshold(c, n)
            heapq.heappush(heap, (cost, c))

        # helper to recompute next jump
        def push_next(ci):
            cost = next_threshold(ci, n)
            heapq.heappush(heap, (cost, ci))

        while heap and r > 0:
            cost, ci = heapq.heappop(heap)
            if cost == 0:
                continue
            if cost <= r:
                r -= cost
                ci += cost
                ans += 1
                push_next(ci)
            else:
                break

        # remaining votes: each new language contributes minimally 0 or 1 depending on rounding
        # best is to create single-vote languages while beneficial
        while r > 0:
            ci = 1
            gain = rounded_percent(ci, n)
            if gain == 0:
                break
            ans += gain
            r -= 1

        print(f"Case #{tc}: {ans}")

if __name__ == "__main__":
    solve()
```実装では、各言語の現在の数を追跡し、次の丸め境界に到達するまでのコストを繰り返し計算します。 ヒープにより、利用可能な中で最も安価な改善が常に選択されるようになります。 改善が行われるたびに、その言語は更新された状態で再挿入されます。 

最後のループは、ポジティブに貢献する場合にのみ新しい言語を作成することによって、残りの投票を処理します。 そうしないと、言語を追加しても合計額は改善されません。 

微妙な点は、浮動小数点エラーを避けるために、丸めの式が整数演算を使用して実装されていることです。 0.5 でのタイが正しく処理されるように、慎重にスケーリングして四捨五入して 100 * Ci / N を計算します。

 ## 特殊なケース

 エッジ ケースの 1 つは、すべての言語が既に丸め境界に正確に位置している場合に発生します。 そのような状況では、投票を追加しても四捨五入された値がすぐに増加しない可能性があります。 next_threshold が最初の意味のあるジャンプを返し、ゼロコストまたは非改善の遷移はスキップされるため、アルゴリズムはこれを処理します。 

もう 1 つのケースは、新しい言語の作成が最適になる場合です。 既存の言語がすべてアップグレードするには高価すぎる場合、ヒープは早期に空になり、残りの投票は個別に処理されます。 このアルゴリズムは、利益のない分割で投票を無駄にすることを正確に回避します。 

最後のケースは、N が小さく、丸め効果が極端に大きい場合です。 たとえば、N = 3 でカウントは [1] です。 ここで、残り 1 票で丸め込みの構造が完全に変わる可能性があります。 ヒープは、既存の言語をアップグレードするか、新しい言語を作成することでより高い限界利益が得られるかを正しく評価し、最適な割り当てを保証します。
