 ## 解決策
 ## 問題の理解

 赤いチェーンソーと青いチェーンソーの 2 種類のアイテムが与えられており、それらすべてを何人かのジャグラーに配布したいと考えています。 各ジャグラーは、扱う赤と青のチェーンソーの数を表す非負の整数のペアを受け取り、すべてのチェーンソーを 1 人のジャグラーに割り当てる必要があります。 

重要な制限は、2 人のジャグラーが同じペアを持つことは許されないということです。 ジャグラーが1人いる場合$(r, b)$、他のジャグラーは同じものを持っていない可能性があります$(r, b)$。 目的は、すべてのジャグラーを正確に消費しながら、ジャグラーの数を最大化することです。$R$赤と$B$青いチェーンソー。 

制約$R, B \le 500$テスト ケース全体で、テスト ケースごとの 2 次または 2 次に近い構成が許容されることを示唆しています。 分布の指数関数的な列挙を伴うものはすべて実行不可能ですが、構造化された組み合わせ構築または小さな状態空間に対する貪欲なパッキングは適切です。 

すべての赤を最初に割り当てたり、最初にすべての青を割り当てたりしようとすると、微妙な失敗が発生します。 これは、最適なソリューションが両方の色を混合してより明確なペアを作成するため、問題が発生します。 

たとえば、次の場合$R = 3, B = 3$、割り当て$(1,0),(1,0),(1,3)$スタイル分割は多様性を無駄にしますが、バランスのとれたセットは$(0,0),(1,1),(2,2)$は未使用の制約があるため有効ですらないため、単純な対称構造では実現可能性をチェックせずに簡単に過大カウントまたは過小カウントされる可能性があります。 

## アプローチ

 ブルートフォース解釈は分割を試みます$R$そして$B$の中へ$k$異なるペア$(r_i, b_i)$そのような$\sum r_i = R$そして$\sum b_i = B$。 これは、順序付きペアの個別性制約を伴う制約付き整数分割問題になります。 分割方法の数$R$の中へ$k$非負の部分はすでに$\binom{R+k-1}{k-1}$、同様に$B$なので、すべてを繰り返します$k$実現可能性をチェックすると、組み合わせ爆発が起こります。 

単純化の核心は、個別のペアの数のみが重要であり、その特定の配置は重要ではないということです。 最適な戦略は常に選択に対応します。$k$個別のペアを 1 つの座標の昇順に並べてから、残りの自由度で合計を分散できるかどうかを検証します。 構造は、最大のものを決定することに帰着します。$k$存在するように$k$第 1 象限内の個別の格子点で、座標の合計が正確に次のようになります。$(R, B)$多重度が適切に割り当てられている場合。 

隠れた構造は、最適な構成が階段を埋めるように動作するということです。$r$、 彼らの$b$値は衝突を厳密に避ける必要があり、最大値は$k$これは、合計のバランスを保ちながら、可能な限り最小の個別のペアを辞書編集順に使用するときに達成されます。

 ## アルゴリズムのチュートリアル

 この問題を、可能な限り最大の個別の整数ペアのセットを構築するものとして再解釈します。$(r_i, b_i)$合計が一致するように$(R, B)$。 

### ステップ

 1. 増加するジャグラーの数に合わせて構築を整理する$k$、各ジャグラーが独自のペアを提供するため、$k$それが私たちが最大化するものです。 
2. 固定の場合$k$、単調な構造で異なるペアを割り当てるようにしてください。 すべてのペアが異なるものであることを強制するため、赤のカウントを増やすことで順序付けを想定できます。$$r_1 < r_2 < \dots < r_k$$この順序付けにより、対称性の問題が回避され、一意性が簿記によって強制されるのではなく構造的なものになることが保証されます。 
3. この順序の下で、可能な最小の赤の合計は、$k$個別の非負の整数は$$0 + 1 + 2 + \dots + (k-1) = \frac{k(k-1)}{2}$$これを超えると$R$、 それから$k$ジャグラーは結成できません。 
4. 赤を最小限に修正した後、残りの赤予算は追加増分として自由に配布されます。 これによって実現可能性が低下することはありません。$r_i$区別性を保ちます。 
5. 同じ推論を青のカウントにも適用します。 最小の青和もまた、$\frac{k(k-1)}{2}$。 
6. したがって$k$その場合にのみ実現可能です$$\frac{k(k-1)}{2} \le R \quad \text{and} \quad \frac{k(k-1)}{2} \le B$$7. 最大の値を計算します。$k$条件が満たされなくなるまで直接増分します。 

### なぜ効果があるのか

 区別性により、1 つの座標内で少なくとも厳密に増加するシーケンスが強制されます。 厳密に増加する長さのシーケンスの最小合計$k$非負の整数では、次から始まる連続する整数によって達成されます。$0$。 いかなる偏差も合計を増加させるだけであるため、実現可能性は完全に三角数の限界によって特徴付けられます。 各座標はその合計によってのみ制約されるため、同じ議論が両方の色に独立して適用されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    out = []
    for tc in range(1, T + 1):
        R, B = map(int, input().split())

        k = 0
        while True:
            need = k * (k - 1) // 2
            if need > R or need > B:
                break
            k += 1

        out.append(f"Case #{tc}: {k - 1}")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装では、三角数の実現可能性条件が直接適用されます。 ループは安全であるため、$k$大体までしか成長しない$\sqrt{R}$または$\sqrt{B}$、制約の下では小さいです。 最後に 1 を減算すると、最後に失敗した増分が修正されます。 

よくある落とし穴は、赤と青のカウントに独立した貪欲な割り当てを使用することです。 正しい制約は、共有されたものを通じてのみ実現可能性を結合します。$k$ジャグラーごとの最適化ではありません。

 ## 特殊なケース

 のようなケース$R = 0, B = 0$アルゴリズムが単一の自明なジャグラーを正しく返すかどうかをテストします。$k=1$チェーンソーの総量はゼロであり、実現可能です。 

などの著しくバランスが崩れたケース$R = 10, B = 0$共有三角形の境界を超えて青が赤を制約しないことを示します。 制限因子は小さい座標になります。 

境界ケースでは、$R = B = \frac{k(k-1)}{2}$正確な飽和点をテストします。もう 1 人のジャグラーが、必要な最小額を利用可能なリソースを超えて増やすことで実現可能性を侵害することになります。
