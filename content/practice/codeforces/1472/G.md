 # 問題の理解

 頂点が都市、ルートが首都である都市 1 である有向グラフが与えられます。 あらゆる都市に$v$、 定義する$d[v]$都市 1 から都市 1 までの最短経路長として$v$。 これらの距離は固定されており、グラフから暗黙的にわかります。 

ポリュカルプはある都市から始まる$s$。 街に立つとき$u$、彼は任意の外向きエッジに沿って移動することができます$(u,v)$。 制限は、すべての移動の中で、宛先の BFS 距離がそれより大きくないことです。$d[v] \le d[u]$、彼は旅全体でそのような動きを最大でも1回しか使用できません。 

厳密に大きな BFS レベルに移行します。つまり、$d[v] > d[u]$、何度でも使用できます。 

開始都市ごとに$i$、から始まる有効な旅程で到達できる最小 BFS 距離値を決定する必要があります。$i$。 

グラフには最大で次のものを含めることができます$2 \cdot 10^5$すべてのテスト ケースにわたる頂点とエッジ。 すべての頂点から個別のグラフ検索を開始するソリューションでは、大まかに次のことが必要になります。$O(n(n+m))$限界をはるかに超えた最悪の場合でも動作します。 合計入力サイズは、各エッジを一定の回数だけ処理する必要があることを強く示唆しています。 

状況によっては、標準的な最短経路の質問よりも問題が微妙になります。 

考慮する：```
1 -> 2 -> 3
^         |
|_________|
```BFS 距離は次のとおりです。$0,1,2$。 都市 3 から始めて、単一の非増加移動を使用できます。$3 \to 1$、すぐに距離0に到達します。 より大きな BFS レベルに向かってエッジをたどるだけのソリューションでは、これを見逃してしまいます。 

考慮する：```
1 -> 2 -> 3 -> 4
     ^         |
     |_________|
```このサイクルにより、後のバックエッジによる改善が可能になります。 頂点を任意の順序で処理すると、必要なときに動的プログラミング値が不完全になる可能性があります。 

考慮する：```
1 -> 2
1 -> 3
2 -> 4
3 -> 4
4 -> 2
```頂点 4 には頂点 2 へのバック エッジがあります。頂点 4 は BFS ツリーのより深いところにありますが、それでも距離 1 に到達できます。情報を下方向に伝播するだけの単純な DFS では、間違った答えが計算されます。 

# アプローチ

 ブルートフォースアプローチでは、開始都市ごとに独立して答えを計算します。 状態を次のようにモデル化できます。$(u, used)$、 どこ`used`単一の非増加ムーブがすでに費やされているかどうかを示します。 各開始頂点からこれらの状態に対してグラフ検索を実行し、遭遇した最小距離を記録します。 

これが機能するのは、状態グラフが問題のルールに正確に一致するためです。 残念ながら、あります$2n$検索ごとに州を指定し、検索を繰り返します$n$回。 複雑さは次のようになります$O(n(n+m))$、おおよそに達します$4 \cdot 10^{10}$最悪の場合の運用。 

重要な観察は、BFS 距離から得られます。 

させて$d[v]$都市からの最短距離であること 1. 任意のエッジ$(u,v)$2 つのカテゴリのいずれかに属します。 

もし$d[v] > d[u]$、エッジは BFS レベルで厳密に前方に進みます。 

もし$d[v] \le d[u]$、エッジは、単一の許可された例外を消費する特別なタイプです。 

頂点に立ったとしましょう$u$。 すぐに非増加エッジを使用すると、$(u,v)$そうすると、すぐに距離を達成できるようになります。$d[v]$。 代わりに前方エッジを取ると$(u,v)$、例外は後で使用できるように保持しているため、最良の回答は次のとおりです。$v$からもご利用いただけます$u$。 

これは動的計画法が再発することを示唆しています。 

させて`ans[u]`から開始して取得可能な最小 BFS 距離になります。$u$。 

最初は、すべての頂点が少なくとも即座に停止できるため、`ans[u] = d[u]`。 

エッジ用$(u,v)$：

もし$d[v] \le d[u]$、その後、そのエッジを例外として使用すると、すぐに候補値が得られます$d[v]$。 

もし$d[v] > d[u]$、次に移動します$v$将来のすべてのオプションを保持し、候補値を提供します`ans[v]`。 

繰り返しは次のようになります。$$ans[u] = \min \left( d[u], \min_{d[v]\le d[u]} d[v], \min_{d[v]>d[u]} ans[v] \right)$$前方エッジによって引き起こされるグラフは、BFS 距離に関して非周期的になります。これは、そのようなすべてのエッジが厳密に増加するためです。$d$。 つまり、BFS 距離の降順で、または同等に、より深いレベルを最初に処理する DFS メモ化を使用して、答えを計算できます。 

これにより、計算全体がグラフ全体で 1 つの BFS と 1 つの DFS ベースの DP に削減されます。

 # アルゴリズムのチュートリアル

 1. 都市 1 から BFS を実行し、最短距離の配列を計算します。`dist`。 
2. DP アレイの作成`ans`すべての値を次のように初期化します`-1`。 
3. 定義する`dfs(u)`頂点から到達可能な最小 BFS 距離として`u`。 
4. から始める`best = dist[u]`Polycarp がすぐに停止する可能性があるためです。 
5. すべての出力エッジを検査する`(u,v)`。 
6. もし`dist[v] <= dist[u]`、このエッジは単一の必殺技として機能します。 アップデート：$$best = \min(best, dist[v])$$例外はすぐに消費されるため、目的地の距離のみが問題になります。 

1. もし`dist[v] > dist[u]`、BFS レイヤーで移動が進みます。 アップデート：$$best = \min(best, dfs(v))$$例外は引き続き利用可能なため、から到達可能なすべてのオプションは`v`からもアクセス可能です`u`。 

1. 結果を次の場所に保存します`ans[u]`そしてそれを返します。 
2. 走る`dfs(i)`頂点ごとに。 
3. 計算されたすべての答えを出力します。 

### なぜ効果があるのか

 BFS 距離は、すべてのエッジを前方エッジまたは非増加エッジに分割します。 

非増加エッジは、まさに 1 つの例外を消費できる手のタイプです。 このような優位性を獲得した後は、エンドポイントですでに到達した最小 BFS 距離を超えると、今後どのような動きでも答えを改善することはできないため、再帰では次を使用します。`dist[v]`。 

前方エッジは例外を消費しません。 から始まる`u`そして、そのようなエッジを取得することは、から開始することと同じです`v`すべてのオプションがまだ利用可能です。 したがって、`ans[v]`は有効な候補です。 

前方エッジは常に BFS 距離を増加させるため、再帰的な依存関係は短い距離から長い距離にのみ移行します。 これらの依存関係の間にサイクルが存在することはできないため、繰り返しは明確に定義されます。 すべての有効な行程は、停止することによって、増加しないエッジを取ることによって、または前進エッジを取ることによって始まります。 再帰化では 3 つの可能性すべてが考慮されるため、生成される最小値がまさに最適な答えになります。 

# Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline
sys.setrecursionlimit(1 << 20)

t = int(input())

for _ in range(t):
    line = input().strip()
    while line == "":
        line = input().strip()

    n, m = map(int, line.split())

    g = [[] for _ in range(n)]

    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)

    dist = [-1] * n
    dist[0] = 0

    q = deque([0])

    while q:
        u = q.popleft()
        for v in g[u]:
            if dist[v] == -1:
                dist[v] = dist[u] + 1
                q.append(v)

    ans = [-1] * n

    def dfs(u):
        if ans[u] != -1:
            return ans[u]

        best = dist[u]

        for v in g[u]:
            if dist[v] <= dist[u]:
                best = min(best, dist[v])
            else:
                best = min(best, dfs(v))

        ans[u] = best
        return best

    for i in range(n):
        dfs(i)

    print(*ans)
```解決策は首都からのBFSから始まります。 これにより、問題に必要な最短パス距離が計算され、すべてのエッジが反復で使用される 2 つのカテゴリのいずれかに分類されます。 

DFS は動的プログラミング関係を直接実装します。 メモ化配列`ans`各頂点が一度解決されることが保証されます。 エッジが BFS 距離のより長い頂点に移動すると、例外は未使用のままになるため、再帰が続行されます。 エッジが等しいかそれより短い距離に到達すると、例外はすぐに消費される可能性があるため、`dist[v]`重要です。 

依存関係は厳密に増加する BFS レベルにのみ従うため、再帰は安全です。 このようなエッジはサイクルを形成できません。 明示的な再帰制限により、長いチェーンでのスタック オーバーフローが回避されます。

# テストケース```python
import sys
import io
from collections import deque

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []

    sys.setrecursionlimit(1 << 20)

    for _ in range(t):
        line = input().strip()
        while line == "":
            line = input().strip()

        n, m = map(int, line.split())

        g = [[] for _ in range(n)]

        for _ in range(m):
            u, v = map(int, input().split())
            g[u - 1].append(v - 1)

        dist = [-1] * n
        dist[0] = 0

        q = deque([0])

        while q:
            u = q.popleft()
            for v in g[u]:
                if dist[v] == -1:
                    dist[v] = dist[u] + 1
                    q.append(v)

        ans = [-1] * n

        def dfs(u):
            if ans[u] != -1:
                return ans[u]

            best = dist[u]

            for v in g[u]:
                if dist[v] <= dist[u]:
                    best = min(best, dist[v])
                else:
                    best = min(best, dfs(v))

            ans[u] = best
            return best

        for i in range(n):
            dfs(i)

        out.append(" ".join(map(str, ans)))

    return "\n".join(out)

# エッジケース

 チェーンのみで構成されるグラフを考えてみましょう。```
1 -> 2 -> 3 -> 4
```BFS 距離は次のとおりです。`0 1 2 3`。 すべてのエッジは、より大きな BFS レベルに進みます。 DFS の反復では非増加エッジが見つからないため、それぞれの答えは独自の距離のままになります。 出力は次のとおりです。```
0 1 2 3
```直接のバックエッジを持つグラフを考えてみましょう。```
1 -> 2 -> 3
^         |
|_________|
```距離は`0 1 2`。 頂点 3 では、1 に戻るエッジは次の条件を満たします。`dist[1] <= dist[3]`そのため、答えはすぐに 0 になります。その改善は繰り返しを通じて伝播し、次のようになります。```
0 0 0
```同じ BFS レベルの頂点間にエッジを含むグラフを考えてみましょう。```
1 -> 2
1 -> 3
2 -> 3
```距離は`0 1 1`。 エッジ`2 -> 3`満足する`dist[3] <= dist[2]`, そのため、必殺技としてカウントされます。 このアルゴリズムは、等距離エッジをバック エッジと同じように正しく処理し、厳密に短い距離のみが重要であるという誤った仮定を防ぎます。 

数回前進した後に最良の改善が見られるグラフを考えてみましょう。```
1 -> 2 -> 3 -> 4
          |
          v
          1
```頂点 2 は、より低い BFS レベルに直接到達できません。 その最適なパスは、まず前方エッジをたどって 3 まで進み、その後特別な動きを使用します。 再発はこれを次のように捉えています。`ans[3]`に伝播して戻ります。`ans[2]`。 まさにこれが、DP が使用する必要がある理由です。`ans[v]`ローカルな情報だけではなく、前方のエッジにも影響を与えます。
