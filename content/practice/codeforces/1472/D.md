 ## 解決策
 ## 問題の理解

 整数の配列が与えられ、2 人のプレイヤーが交互にその配列から要素を削除します。 アリスが最初に始めます。 プレイヤーが数字を削除するたびに、特定の値のみが実際にスコアに寄与します。アリスは自分が選んだ偶数の数字からのみポイントを獲得しますが、ボブは自分が選んだ奇数の数字からのみポイントを獲得します。 「間違ったパリティ」を選択しても数値は削除されますが、スコアはゼロになります。 

すべての要素が取り除かれるとゲームは終了し、合計スコアを比較して勝者が決定されます。 

重要な問題は、両方のプレイヤーが自分のために貪欲に選択しているだけではないということです。 すべての除去は将来の利用可能性に影響を与えるため、最適なプレイでは、個人の利益を最大化するだけでなく、相手の良い機会を否定することも考慮する必要があります。 

入力サイズは、テスト ケース全体で合計 2 · 10^5 要素に達します。 これにより、考えられるすべての移動シーケンスのシミュレーションが即座に除外されます。 完全なゲーム ツリー アプローチでは、各ステップで分岐し、階乗的に成長しますが、これは実現可能な限界をはるかに超えています。 指数関数的な状態空間のため、サブセットにわたる DP さえも不可能です。 

重要な観察は、ルールは数値が偶数か奇数かのみに依存し、その値がスコアに寄与する場合にのみ依存するということです。 それは、構造が大幅に削減可能であることを意味します。 

すべての数値が 1 つのパリティ クラスに属する場合、微妙なエッジ ケースが発生します。 たとえば、すべての数字が奇数の場合、アリスは何も得られず、ボブは選んだものをすべて集めます。 「最適なブロッキング」をシミュレートしようとする単純なアプローチでは、アリスが干渉できると誤って仮定する可能性がありますが、有意義なスコアリングの意味で奇数へのボブのアクセスを変更することはできません。 同様に、すべての数値が偶数の場合、ボブのスコアは常に 0 になります。 

最大の数値がプレーヤーにとって「間違った」パリティに属している場合、別の特殊なケースが発生します。 たとえば、アリスが大きな奇数を選択した場合、アリスのスコアは向上しませんが、ボブの潜在的な利益からは除外されます。 これにより、パリティ分離が明示的でない限り、値による欲張りアプローチだけでは誤って処理される可能性があるというトレードオフが生じます。 

## アプローチ

 ブルートフォースソリューションでは、考えられるすべての動きをシミュレートします。 各ターンで、プレイヤーは残りの要素を選択し、パリティに応じてスコアを更新し、再帰的に行います。 これにより、考えられるすべての意思決定パスが試行されるため、ゲームが正しくモデル化されます。 ただし、各状態には最大 O(n) 個の選択肢と深さ n があり、およそ n! 可能なシーケンス。 メモ化したとしても、状態空間はターン情報を持つ残りの要素の集合であり、天文学的に大きくなります。 

重要な簡素化は、数値の実際の値がスコアリングの動きとして収集される場合にのみ重要であるという認識から来ています。 それ以外の場合は、単なるブロック動作にすぎません。 これは、数値を 2 つの独立した順序付きプール (偶数と奇数) に分離することを示唆しています。 各プレーヤーは、これらのプールのいずれか 1 つからのみ恩恵を受けます。 

ここで、ゲームは、各プールから誰がより効率的に選択できるかをめぐる競争になります。 どちらのプレーヤーも常により高い得点の機会を好むため、最適なプレイは各パリティ グループ内でソートされた順序を考慮することになります。 プレイヤーは効果的に残りの利用可能な最高の値を順番に消費しますが、スコアに寄与するのは関連するパリティのみです。 

重要な構造的洞察は、すべての意思決定はピックの順序に帰着し、最適なプレイはターンを交互に行いながら降順で数字を処理することに相当し、パリティとロールの調整に応じてスコアが更新されるということです。 

これにより、ゲーム ツリーの複雑さが完全に削除され、単一のソートされた走査に置き換えられます。

 ## アルゴリズムのチュートリアル

1. 配列を偶数値と奇数値に分け、配列全体を降順に並べ替えます。 

ソートにより、両方のプレイヤーが常に最も価値のある残りの選択肢を最初に直面することが保証されます。これは、値が低い方が後で良くなることはないため、必要です。 
2. スコアの 2 つのカウンター、AliceScore と BobScore を初期化します。どちらも 0 から始まります。 

得点にならない動きは将来の可用性に影響を与えるものの、合計には影響しないため、これらは有効な利益のみを追跡します。 
3. ソートされた配列を反復処理し、アリスから始まる厳密な交互のターンとして各位置を扱います。 

これは最適なプレイ構造を反映しています。プレイヤーはターンごとに常に 1 つの要素を削除するため、ターン順序は固定されます。 
4. アリスのターンで、現在の数値が偶数であれば、それをアリススコアに追加します。 それ以外の場合は何もしません。 

アリスは奇数から利益を得ることは決してないので、奇数を選択することは純粋に防御的です。 
5. ボブのターンで、現在の数値が奇数の場合は、それを BobScore に追加します。 それ以外の場合は何もしません。 

ボブは反対のパリティでアリスをミラーリングします。 
6. すべての要素を処理した後、スコアを比較し、それに応じて勝者を宣言します。 

重要な暗黙の考え方は、パリティの優先順位に関係なく、最適なプレイでは常に降順で数値が消費されるということです。 逸脱すると、対戦相手は次のターンでより高い値を取ることができますが、スコアはタイミングではなく収集された値のみに依存するため、厳密にはさらに悪いことになります。 

### なぜ効果があるのか

 不変条件は、k 回移動した後、残りの最大 k 個の数字が最適なプレイと一致する順序で削除され、より高い値の数字を遅らせたりスキップしたりして結果を改善できるプレーヤーはいないということです。 スコアリングはパリティ一致ピックの所有権のみに依存するため、最適な戦略は、代替分岐を考慮する必要がなく、ソートされた各要素をターンに決定的に割り当てることになります。 

利用可能な大きな数字を残したまま、より小さな数字を取得しようとすると、対戦相手は次の動きでその大きな数字にアクセスできるようになり、相手の達成可能な最高スコアが増加するか、自分のスコアが減少するだけになります。 したがって、貪欲な順序付けは、最適なプレイの下では安定します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        a.sort(reverse=True)
        
        alice = 0
        bob = 0
        
        for i, x in enumerate(a):
            if i % 2 == 0:
                if x % 2 == 0:
                    alice += x
            else:
                if x % 2 == 1:
                    bob += x
        
        if alice > bob:
            out.append("Alice")
        elif bob > alice:
            out.append("Bob")
        else:
            out.append("Tie")
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このソリューションでは、まず各テスト ケースが降順で並べ替えられ、最も高い値の選択肢が最初に解決されます。 その後、ループはインデックス パリティを使用して交互に回転します。 アリスが開始するので、偶数のインデックスはアリスに対応し、奇数のインデックスはボブに対応します。 各プレーヤーは、パリティ条件がスコア ルールと一致する場合にのみスコアを蓄積します。 

実装の微妙な点は、削除を明示的にシミュレートしていないことです。 ソートされた配列は、最適なプレイでの削除のシーケンスを暗黙的に表すため、インデックス トラバーサルがステートフルな削除を完全に置き換えます。 

## 実用的な例

 ### 例 1

 入力:```
4
5 2 7 3
```ソートされた配列は`[7, 5, 3, 2]`。 

| ステップ | ターン | 選んだ | アリススコア | ボブスコア |
 | --- | --- | --- | --- | --- |
 | 1 | アリス | 7 | 0 | 0 |
 | 2 | ボブ | 5 | 0 | 5 |
 | 3 | アリス | 3 | 0 | 5 |
 | 4 | ボブ | 2 | 0 | 5 |

 アリスは決してポイントを獲得しませんが、ボブは 5 と 2 を集めます。ボブの勝ちです。 

これは、アリスよりもボブにとって大きな奇数の価値がいかに高いかを示しており、値で順序付けすることで、可能な場合にはボブがそれらの値を確実に取得できるようになります。 

### 例 2

 入力:```
3
3 2 1
```ソートされた配列は`[3, 2, 1]`。 

| ステップ | ターン | 選んだ | アリススコア | ボブスコア |
 | --- | --- | --- | --- | --- |
 | 1 | アリス | 3 | 0 | 0 |
 | 2 | ボブ | 2 | 0 | 0 |
 | 3 | アリス | 1 | 0 | 0 |

 両プレイヤーは何も得られず、引き分けとなります。 

これは、重要なプレーにもかかわらず、パリティが得点を完全に無効にする境界ケースを強調しています。

 | 測定 | 複雑さ | 説明 |

 | 時間 | O(n log n) | 各テスト ケースでは並べ替えが優先されます。 
| スペース | O(n) | 配列と一時変数の保存 |

 合計の入力サイズは最大 2·10^5 であるため、すべてのテスト ケースにわたる並べ替えは、制限内で十分に高速に行うことができます。 各テスト ケースは、並べ替え後に直線時間で実行されます。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline
    
    t = int(input())
    out = []
    
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        a.sort(reverse=True)
        
        alice = bob = 0
        
        for i, x in enumerate(a):
            if i % 2 == 0 and x % 2 == 0:
                alice += x
            elif i % 2 == 1 and x % 2 == 1:
                bob += x
        
        if alice > bob:
            out.append("Alice")
        elif bob > alice:
            out.append("Bob")
        else:
            out.append("Tie")
    
    return "\n".join(out)

assert run("4\n4\n5 2 7 3\n3\n3 2 1\n4\n2 2 2 2\n2\n7 8\n") == "Bob\nTie\nAlice\nAlice"

# all same parity (all even)
assert run("1\n3\n2 4 6\n") == "Alice"

# all same parity (all odd)
assert run("1\n3\n1 3 5\n") == "Bob"

# alternating parity heavy values
assert run("1\n4\n10 1 9 2\n") == "Alice"

# minimal case
assert run("1\n1\n100\n") == "Alice"

 | すべてのオッズ | ボブ | ボブはすべての利益を蓄積します |
 | 高/低混合 | アリス | スコア分割に対する順序の影響 |
 | 単一要素 | アリス | 基本的な正確性 |

 ## 特殊なケース

 次のような完全に偶数の配列`[2, 4, 6]`その結果、アリスは順序に関係なくすべての値を収集することになります。 並べ替えによって結果は変わりませんが、決定的な処理が保証されます。 ボブのスコアは終始ゼロのままなので、合計でアリスが勝ちます。 

次のような完全に奇数の配列`[1, 3, 5]`ボブのみが奇数ピックから恩恵を受けるため、すべての有効ポイントをボブに与えます。 アリスの動きは要素を削除するだけでスコアに影響を与えないため、ボブが最終的な合計を支配します。 

のような混合配列`[10, 1, 9, 2]`は、値の順序付けとパリティ割り当ての間の相互作用を示しています。 収量の選別`[10, 9, 2, 1]`、交互のターンでは、ターンの配置に応じて、値の高い奇数がボブに割り当てられ、値の高い偶数がアリスに割り当てられます。 これは、順序が結果を予測するために必要な唯一の構造的要因であることを裏付けています。 

アリスが最初に移動するため、単一要素の配列は常にアリスに送られます。 要素が偶数の場合は彼女が得点しますが、そうでない場合はボブが応答できずにゲームがすぐに終了するため、少なくともすべての場合においてアリスは負けません。
