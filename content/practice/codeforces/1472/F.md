 ## 解決策
 ## 問題の理解

 2 行のセルを表す、サイズ 2 x n のストリップが与えられます。 一部のセルはブロックされており、使用できません。 私たちの目標は、サイズ 1×2 (水平) または 2×1 (垂直) のドミノを使用して、ブロックされていないすべてのセルを、重なったりストリップを超えたりすることなく完全にカバーすることです。 各テスト ケースでは、ブロックされたセルを指定します。 タイリングが可能であれば出力は単純に「YES」、そうでない場合は「NO」になります。 

重要な制約は、n は 10^9 まで大きくすることができますが、ブロックされたセルの数 m はすべてのテスト ケースで最大 2×10^5 であることです。 これは、ストリップ全体を保存したり、すべての列を反復したりできないことを意味します。 グリッド全体をシミュレートしようとするソリューションは、メモリまたは時間の制約によりすぐに失敗します。 代わりに、ブロックされたセルの位置のみに基づいて解決策を決定する必要があります。 

列パリティの意味でフリー セルの奇数長セグメントが作成されるような方法でブロックされたセルが配置されている場合、エッジ ケースが発生します。 たとえば、単一の列で両方のセルがブロックされていても問題はありません。 ただし、列 1 にブロックされたセルが 1 つあり、反対側の行の列 2 にブロックされたセルが 1 つある場合、ドミノでは隣接するセルが適切にペアになる必要があるため、タイリングが妨げられる可能性があります。 ブロックされたセルの相対位置を考慮せずにカウントするだけの不注意なソリューションでは、タイリングが不可能な場合に誤って「YES」と宣言する可能性があります。 

## アプローチ

 ブルートフォース手法では、2×n グリッド全体を表現してブロックされたセルをマークし、それを貪欲にまたはバックトラッキングしてタイル化しようとします。 どのタイルも段階的に構築できるため、これは原理的には正しいです。 ただし、n が 10^9 までの場合、このアプローチは不可能です。 ブロックされたセルを含む列のみを格納した場合でも、タイリングのシミュレーションは最悪の場合 O(n) となり、遅すぎます。 

効率的な解決策を導き出す観察は、ブロックされたセルを列ごとに観察することで得られます。 ブロックされた各セルにはパリティがあると考えることができます。行 1 はパリティ 0、行 2 はパリティ 1 です。列の位置で並べ替えられた連続するブロックされたセルを調べる場合、列の差と行のパリティによって、それらの間のセグメントをタイル化できるかどうかが決まります。 具体的には、2 つのブロックされたセルが同じ行にあり、列の差が奇数である場合、その行には奇数のブロックされていない正方形が残りますが、これは水平ドミノだけではカバーできません。 それらが反対の行にある場合は、行インデックスと列インデックスの合計のパリティを考えることができます。同じパリティの差を持つ連続したブロックされたセルが連続した列に現れる場合、タイル化は不可能になります。 

問題を、ブロックされたセルを列ごとにソートした後、奇数の列で区切られた同じパリティ (行 + 列のモジュロ 2) 内にブロックされたセルのペアが存在するかどうかをチェックすることに縮小します。 そのようなペアが存在する場合、答えは「いいえ」です。 それ以外の場合は「はい」。 この観察により、ストリップの膨大な空の部分を無視して、ブロックされたセルのみに焦点を当てることができるため、非常に大きな n に対してもソリューションを実行可能になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | テスト ケースあたり O(n) | O(n) | n ~ 10^9 では遅すぎます |
 | 最適 | テスト ケースごとに O(m log m) | O(m) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 各テスト ケースについて、n と m を読み取り、ブロックされたセル (行、列) のリストを読み取ります。 
2. ブロックされたセルごとに、行 + 列のモジュロ 2 としてパリ​​ティ値を計算します。これにより、このセルで開始するドミノまたは終了するドミノがタイリングの実現可能性に影響するかどうかが把握されます。 
3. ブロックされたセルを列インデックスで並べ替えます。 並べ替えにより、連続するブロックされたセルを左から右の順序で検査できるようになります。 
4. 辞書または配列を初期化して、パリティごとに最後に検出された列を追跡します。 
5. ソートされたブロックされたセルを繰り返し処理します。 現在のセルについて、同じパリティを持つ以前にブロックされたセルがあったかどうかを確認します。 そうである場合は、現在ブロックされているセルと以前ブロックされているセルの間の列の差を計算します。 差が奇数の場合、タイリングは不可能であるため、このテスト ケースではすぐに「NO」を返します。 
6. 現在のパリティについて最後に確認された列を現在の列に更新します。 
7. 奇数距離の競合が検出されずに反復が終了した場合は、「YES」を出力します。 

機能する理由: 不変条件は、ドミノが垂直または水平の 2 つの隣接するセルを覆うことです。 行 + 列モジュロ 2 のパリティは、ドミノ配置では一定のままであり、奇数の列で区切られた同じパリティを持つ連続したブロックされたセルは、タイル化できない奇数長のセグメントを残します。 この不変条件を追跡することで、グリッド全体をシミュレートすることなく正確性を保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    input()  # skip empty line
    n, m = map(int, input().split())
    blocked = []
    for _ in range(m):
        r, c = map(int, input().split())
        blocked.append((c, r % 2))  # store column and parity
    
    blocked.sort()
    last_seen = {}
    possible = True
    for c, parity in blocked:
        if parity in last_seen:
            if (c - last_seen[parity]) % 2 == 1:
                possible = False
                break
        last_seen[parity] = c
    print("YES" if possible else "NO")
```このソリューションは、空のスペースを無視して、各テスト ケースを効率的に読み取ります。 ブロックされたセルを (列、パリティ) ペアとして表すことで、問題を単純なパリティ追跡に集約します。 並べ替えにより、列が順番に処理されることが保証され、last_seen ディクショナリはパリティごとに以前にブロックされたセルの列を追跡します。 小切手`(c - last_seen[parity]) % 2 == 1`タイリングを不可能にする本質的な制約を捉えています。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = []
    t = int(input())
    for _ in range(t):
        input()
        n, m = map(int, input().split())
        blocked = []
        for _ in range(m):
            r, c = map(int, input().split())
            blocked.append((c, r % 2))
        blocked.sort()
        last_seen = {}
        possible = True
        for c, parity in blocked:
            if parity in last_seen:
                if (c - last_seen[parity]) % 2 == 1:
                    possible = False
                    break
            last_seen[parity] = c
        output.append("YES" if possible else "NO")
    return "\n".join(output)
