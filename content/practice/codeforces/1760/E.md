 ## 解決策
 ## 問題の理解

 私たちは、反転が次のペアからのみ生じるバイナリ シーケンスを扱っています。`1`の前に表示されます`0`。 このタスクでは、オプションで 1 つの要素を反転することができ、その 1 つの変更後の反転の総数を最大化したいと考えています。 

入力は複数の独立した配列で構成されます。 それぞれについて、何もしないのが最善なのか、それとも 1 つの位置だけを反転することで反転回数が向上するのかを判断する必要があります。 

この制約は、テスト ケースごとに線形または線形に近い解決策が必要であることを意味します。 すべてのケースにわたる全長は最大 2e5 であるため、フリップごとに O(n²) 回の再計算は実行できません。 正しいソリューションでは、位置を反転する効果の評価が O(1) または O(log n) になるように、事前に計算された構造を再利用する必要があります。 

ビットを反転するとグローバル構造が 2 つの方向に変化するため、エッジ ケースは微妙です。 を回す`0`の中へ`1`右エンドポイントである反転を削除し、左エンドポイントとなる反転を作成します。 反転の場合は逆のことが起こります`1`に`0`。 単純な間違いは、これらの効果の 1 つだけを考慮することであり、ゲインを過小評価または過大評価することにつながります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 配列の反転数を計算し、各インデックスを反転して、反転を最初から再計算して、最良の結果を取得します。 これは正しいですが、各再計算ですべてのペアが暗黙的または明示的にスキャンされるため、テスト ケースごとに O(n²) のコストがかかります。 

重要な観察は、完全な再計算は必要ないということです。 固定インデックス i の場合、プレフィックスとサフィックスのカウントを使用して、ビットを反転することによって引き起こされる反転の変化を表現できます。 を反転すると`0`に`1`、その前に 1 で形成された反転が失われ、その後ろに 0 で形成された反転が得られます。 を反転すると`1`に`0`、その前の 1 から反転を獲得し、その後の 0 から反転を失います。 この局所的な分解により、プレフィックスの合計後の各候補の評価が O(1) に減ります。 

したがって、1 と 0 のプレフィックス数と O(n) 内の基本反転数を計算し、O(n) 内のすべての位置をテストします。

 ## アルゴリズムのチュートリアル

 1 のプレフィックス カウントと 0 のプレフィックス カウントの 2 つの配列を前処理します。 これらから、任意の位置について、その前に 1 がいくつあるか、その後に 0 がいくつあるかを問い合わせることができます。 

また、ペアの数である初期反転数も計算します。`(i, j)`そのような`i < j`そして`a[i] = 1`、`a[j] = 0`。 

インデックスごとに、配列を左部分と右部分に分割して、そのビットを反転した効果を評価します。 

現在の値が`0`を反転して、`1`以前の反転がこの位置に寄与したすべての反転を削除します。`0`、そして、この新しい反転が作成されます。`1`後にゼロが続きます。 

現在の値が`1`を反転して、`0`として寄与していた反転を削除します。`1`ゼロの前に配置し、以前のものがこの新しいものとペアになる反転を作成します。`0`。 

各位置のデルタを計算し、答えを更新します。 

### なぜ効果があるのか

 インデックス i を含むすべての反転は、その左側または右側の要素にのみ依存します。 i を反転しても、他のペア間の関係には影響しません。 この独立性により、合計の変化が左右のカウントからの寄与にきれいに分解されることが保証されるため、考えられるすべての結果を調査するには、各インデックスを個別に評価するだけで十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        # prefix ones
        pref1 = [0] * (n + 1)
        for i in range(n):
            pref1[i + 1] = pref1[i] + a[i]

        total_ones = pref1[n]

        # initial inversion count (1 before 0)
        inv = 0
        zeros_seen = 0
        for x in a:
            if x == 0:
                zeros_seen += 1
            else:
                inv += zeros_seen

        best = inv

        for i in range(n):
            if a[i] == 0:
                # flip 0 -> 1
                ones_left = pref1[i]
                zeros_right = (n - i - 1) - (zeros_seen - (i - (pref1[i] + (i - pref1[i]))))
                # simpler correct derivation below

                zeros_right = (n - 1 - i) - ((n - 1 - i) - ((n - 1 - i) - (pref1[n] - pref1[i])))
                # cleaner approach: recompute directly

                zeros_right = (n - 1 - i) - ( (n - 1 - i) - ((n - 1 - i) - (pref1[n] - pref1[i])) )
                # fallback to correct simpler expression:
                zeros_right = (n - 1 - i) - (( (n - 1 - i) - ((n - 1 - i) - (pref1[n] - pref1[i])) ))

                delta = zeros_right - ones_left
            else:
                # flip 1 -> 0
                ones_left = pref1[i]
                zeros_right = (n - 1 - i) - ( (pref1[n] - pref1[i+1]) )
                delta = ones_left - zeros_right

            best = max(best, inv + delta)

        out.append(str(best))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```実装構造は分解の考え方に従います。まず反転ベースラインを計算し、次に各フリップを個別に評価します。 最も微妙な部分は、プレフィックス数が一貫して使用されるようにすることです。 左右の寄与を計算するときに要素自体をどちらの側にも含めてはいけないため、オフバイワン エラーがよく発生します。 

実際には、最もクリーンな実装では、過度に複雑な派生式を回避し、代わりに 1 と 0 のプレフィックス合計を明示的に使用するか、両方の配列を維持して、各デルタ計算が対称的で検証しやすいようにします。 

## 実用的な例

 配列を考慮してください`1 0 1 0`。 初期反転は次のとおりです。`(1,2), (1,4), (3,4)`3を与える。 

| 私 | 値 | 残りのもの | 右のゼロ | デルタ | 最高 |
 |---|------|-----------|---------------|------|------|
 | 0 | 1 | 0 | 2 | +0 | 3 |
 | 1 | 0 | 1 | 1 | 0 | 3 |
 | 2 | 1 | 1 | 1 | 0 | 3 |
 | 3 | 0 | 3 | 0 | -3 | 3 |

 反転しても結果は改善されないため、答えは 3 のままです。 

ここで考えてみましょう`0 1 0`。 初期反転数は 1 (ペアのみ)`(2,3)`）。 

| 私 | 値 | 残りのもの | 右のゼロ | デルタ | 最高 |

 | 0 | 0 | 0 | 1 | +1 | 2 |
 | 1 | 1 | 0 | 1 | 0 | 2 |
 | 2 | 0 | 1 | 0 | -1 | 2 |

 インデックス 0 を反転すると、最適な結果 2 が得られます。 

これらのトレースは、接頭辞 1 と接尾辞 0 のバランスをとることによってのみ改善がもたらされ、各位置が独立して寄与していることを示しています。

 ## 特殊なケース

 重要なエッジケースは、すべての要素が同一である場合です。 すべてゼロの配列では、任意の位置を反転すると、新しいものからのみ反転が作成されます。`1`左側には寄与があり、何も破壊されないため、すべてのポジションが同じ予測可能なゲイン構造を持ちます。 オール 1 配列では、反転はすでにゼロであり、反転によって以前のものとのみ相互作用するゼロが作成され、再びすべての候補デルタが均一になります。 プレフィックス数が左側の寄与を完全に決定し、サフィックス数がすべての位置で一貫しているため、アルゴリズムは両方を正しく処理します。したがって、特別な分岐は必要ありません。
