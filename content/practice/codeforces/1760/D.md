 ## 解決策
 ## 問題の理解

 整数の配列が与えられ、それが正確な定義に従って「谷」を形成しているかどうかを判断する必要があります。 概念的には、谷は両側の隣接する部分配列よりも低い平坦な部分配列です。 形式的には、等しい要素の連続するセグメントが 1 つだけ存在する必要があります。そのため、セグメントが境界にない場合、その左隣のセグメントの方が厳密に大きく、右隣のセグメントも厳密に大きくなります。 平坦なセグメントが境界にある場合、存在する隣接セグメントのみがこの条件を満たす必要があります。 出力は、そのような谷セグメントが 1 つだけ存在する場合は「YES」、そうでない場合は「NO」になります。 

この制約により、配列の長さは 200,000 まで、テスト ケースは 10,000 まで許可されますが、テスト ケース全体のすべての配列の長さの合計が 200,000 を超えることはありません。 これは、各配列をそのサイズに対して線形時間で処理する必要があることを意味します。 考えられるすべてのサブ配列を明示的に検査するアプローチは二次関数的であり、非常に遅すぎます。 注意深いリニアスキャンで十分です。 

誤って処理されやすいエッジ ケースとしては、長さ 1 の配列、すべての要素が等しい配列、または個別に谷のように見える複数の平らなセグメントを持つ配列などがあります。 例えば、`[1, 1, 1]`左側の境界が平坦なセグメントの始まりであり、その左側に小さい隣接セグメントがないため、谷になりますが、`[2, 1, 1, 1, 2]`中央に明確な谷が 1 つあり、「YES」を返す必要があります。 のような配列`[1, 2, 1, 2, 1]`複数の潜在的な極小点があるため、出力は「NO」になるはずです。 平坦な領域の数え間違いや境界条件の検証の失敗は、一般的なエラーの原因です。 

## アプローチ

 ブルートフォース手法では、少なくとも 1 つの長さのすべての可能なサブ配列をチェックして、谷の特性を満たすかどうかを確認します。 各部分配列について、すべての要素が等しいことを確認し、隣接要素が存在するかどうかを確認します。 これは正しいですが、各配列の長さは`n`O(n^2) 個の部分配列を持つ可能性がありますが、これでは遅すぎます。`n = 2*10^5`。 

重要な洞察は、谷は周囲よりも低くなければならないため、配列の最小限の要素のみが有効な谷を形成できるということです。 まず配列内の最小値を見つけてから、この値の連続したセグメントを調べます。 最小要素の連続するセグメントごとに、境界条件をチェックします。つまり、セグメントの前の要素が存在する場合はその要素が厳密に大きくなければならず、セグメントの後の要素が存在する場合は厳密に大きくなければなりません。 このようなセグメントが 1 つだけこれを満たす場合、その配列は谷になります。 それ以外の場合はそうではありません。 最小限の要素に焦点を当て、線形にスキャンすることで、配列のサイズの複雑さを 2 次から線形に軽減します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | お(1) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 現在の配列について、最小値を見つけます。 どの谷も隣接する谷よりも低くなければならないため、これが谷の唯一の候補です。 
2. 有効な谷セグメントの数のカウンターを初期化します。 
3. 配列を左から右に繰り返します。 最小値に遭遇した場合は常に、等しい最小値の連続セグメントを特定します。 
4. このセグメントについて、境界要素を確認します。 セグメントが配列の先頭から始まる場合は、右隣のみをチェックします。 最後のインデックスで終了する場合は、左隣のみをチェックします。 それ以外の場合は、左の近傍が最小値より大きく、右の近傍も同様に大きいことを確認します。 
5. セグメントが境界条件を満たす場合、谷カウンタをインクリメントします。 
6. 次の最小セグメントまで配列を最後までスキャンし続けます。 
7. 最後に、ちょうど 1 つのセグメントが境界チェックを通過した場合は、「YES」を出力します。 それ以外の場合は、「NO」を出力します。 

機能する理由: 最小値の観測により、潜在的な谷のみが考慮されることが保証され、境界チェックにより谷の定義が 1 回だけ満たされることが保証されます。 線形スキャンにより、重複や部分的なチェックを見逃すことなく、すべての連続する最小セグメントを検査することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def is_valley(a):
    n = len(a)
    min_val = min(a)
    i = 0
    valley_count = 0
    
    while i < n:
        if a[i] == min_val:
            start = i
            while i + 1 < n and a[i + 1] == min_val:
                i += 1
            end = i
            left_ok = start == 0 or a[start - 1] > min_val
            right_ok = end == n - 1 or a[end + 1] > min_val
            if left_ok and right_ok:
                valley_count += 1
            i += 1
        else:
            i += 1
    return valley_count == 1

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    print("YES" if is_valley(a) else "NO")
```機能`is_valley`配列を 1 回スキャンします。 内側の while ループは連続する最小値をグループ化し、境界条件が明示的にチェックされます。 インクリメント`i`セグメントのスキップや二重カウントを慎重に避けてください。 

## 実用的な例

 トレース入力`[3, 2, 2, 1, 2, 2, 3]`:

 | 私 | a[i] | 開始 | 終わり | 左_わかりました | 右_わかりました | 谷数 |
 | --- | --- | --- | --- | --- | --- | --- |
 | 0 | 3 | - | - | - | - | 0 |
 | 1 | 2 | - | - | - | - | 0 |
 | 2 | 2 | - | - | - | - | 0 |
 | 3 | 1 | 3 | 3 | 本当 | 本当 | 1 |
 | 4 | 2 | - | - | - | - | 1 |
 | 5 | 2 | - | - | - | - | 1 |
 | 6 | 3 | - | - | - | - | 1 |

 1 つのセグメントのみ`[3,3]`最小値が境界条件を満たしている場合、「YES」が出力されます。 

トレース入力`[1, 2, 3, 4, 3, 2, 1]`:

 | 私 | a[i] | 開始 | 終わり | 左_わかりました | 右_わかりました | 谷数 |
 | --- | --- | --- | --- | --- | --- | --- |
 | 0 | 1 | 0 | 0 | 本当 | 偽 | 0 |
 | 6 | 1 | 6 | 6 | 偽 | 本当 | 0 |

 2 つの最小セグメントが存在しますが、両方の境界を満たすものはなく、「NO」が出力されます。
