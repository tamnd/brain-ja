 ## 解決策
 ## 問題の理解

 私たちは、各エッジが走査時にビット単位の XOR 値に寄与する重み付きツリーを使用しています。 散歩はノードから始まります`a`蓄積された価値を持つ`x = 0`。 エッジに沿って移動するたびに更新されます`x`そのエッジの重みと XOR をとることによって。 

目標は、ノードに到達できるかどうかを判断することです`b`厳しい制約の下で、私たちは立ち入りのみを許可されています。`b`エッジを介して、踏み込んだ瞬間に XOR 値が正確にゼロになります。 さらに、利用可能な特別な操作が 1 つあります。ウォークのどの時点でも、以下を除く任意のノードに 1 回テレポートできます。`b`、現在の XOR 値を保持します。 

出力は単に、有効な一連の動きと、開始できるテレポートが 1 つだけ存在するかどうかです。`a`そして最終的には入ります`b`XOR はゼロに等しい。 

制約は大きく、すべてのテスト ケースで最大 100,000 ノードです。 これにより、ノードのすべてのペア間のパスを明示的にシミュレートしようとしたり、単純な方法で完全な状態履歴を追跡しながらパスを探索しようとしたりするソリューションは即座に除外されます。 どのアプローチも基本的にテストごとに線形であるか、ノードごとに対数的である必要があります。 

テレポートについての誤解から、微妙な特殊なケースが発生します。 素朴な解釈では、テレポートではコンポーネントを簡単に接続する任意の再配置が可能であると想定されるかもしれませんが、それでも XOR 状態が保持され、直接着陸することはできません。`b`。 別のトラップは、パス XOR を計算するだけでよいと仮定しています。`a`に`b`、テレポートによって可能になる迂回路の可能性を無視します。 

## アプローチ

 ブルートフォース戦略では、あらゆる可能なウォークを探索しようとします。`a`、現在のノードと現在の XOR 値の両方を追跡します。 それぞれの州から`(node, x)`、すべての隣接するエッジに沿って移動し、XOR を更新し、オプションでテレポートを 1 回使用します。 これは状態空間検索になります。`(node, x, used_teleport)`。 

問題はそれです`x`はツリー サイズによって制限されず、エッジの重みによって制限されます。エッジの重みは最大 1e9 になる可能性があるため、XOR 状態が爆発的に増加する可能性があります。 概念的に値を圧縮したとしても、ツリー内のパスに沿った個別の XOR 累積の数は依然としてノード数に線形であり、おおよその結果が得られます。`O(n^2)`最悪の場合の状態。 

重要な点は、ツリー上の XOR 値が構造化されていることです。 ルートを修正すると、すべてのノードがルートからの一意の XOR プレフィックスを持ちます。 2 つのノード間の XOR は、それらのプレフィックス XOR によって決まります。 これにより、パス XOR 推論が単純なプレフィックス比較に減ります。 

次に、テレポートによって実際に何が可能になるかを考えてみましょう。 テレポートなしで到達`b`XOR ゼロを使用すると、からのパス XOR を意味します`a`に`b`ゼロでなければなりません。 テレポートを使用すると、旅を 2 つのセグメントに分割できます。`a`どこかのノードに`u`、いくつかのノードにテレポートします`v`から歩いていきます。`v`に`b`。 XOR 制約は、最後のステップにのみ適用されます。`b`したがって、重要な条件はノードに到達できるかどうかになります。`v`からのパスが存在するように`v`に`b`XOR はゼロに等しい。 

これにより、問題は、到達可能な XOR 状態の分析に軽減されます。`a`、および接続できるノードがサブツリー構造内に存在するかどうか。`b`XOR 制約の下で。 解決策は最終的には、プレフィックス XOR 値を計算し、条件を直接満たせるか、またはテレポートを使用して XOR 状態を到達可能な構成に合わせることができるかどうかを確認することに依存します。`b`。

 ## アルゴリズムのチュートリアル

 1. 任意のノード (通常はノード) でツリーをルートします。`1`、そして計算します`xor_root[u]`、ルートから各ノードへの XOR`u`。 これは DFS を使用して行われます。 これが機能する理由は、ツリー内ではすべてのパスが一意であるため、プレフィックス XOR が明確に定義されているためです。 
2. 間のパスに沿って XOR を観察します。`u`そして`v`等しい`xor_root[u] XOR xor_root[v]`。 これにより、推論中に明示的にパスをトラバースする必要がなくなります。 
3. コンピューティング`xor_root[a] XOR xor_root[b]`。 これは、からの直接パスの XOR を表します。`a`に`b`。 この値がゼロの場合、から直接ウォークします。`a`に`b`すでに最終条件を満たしているため、答えはすぐに「YES」になります。 
4. ダイレクト パスの XOR がゼロでない場合は、テレポートに依存します。 テレポートを使用すると、以下のノードを除く任意のノードに一度だけ位置を変更できます。`b`、中間ノードを選択できることを意味します`u`ここでは、空間制約をリセットしますが、XOR 状態は変更されません。 
5. 重要な条件はノードが存在するかどうか`u`そのような`xor_root[u] == xor_root[a] XOR xor_root[b] XOR w`これにより、最終エッジが`b`累積値をキャンセルします。 
6. ツリー用語で言えば、これは、独立して到達可能な構成内にあるノードがツリー内に存在するかどうかをチェックすることになります。`b`エンドポイントから導出された必要な XOR 値を照合しながら。 
7. DFS 中に、コンポーネント内で到達可能なすべてのプレフィックス XOR 値のセットを維持します。ただし、`b`を選択し、必要な XOR ターゲットが存在するかどうかを確認します。 

### なぜ効果があるのか

 不変条件は、ツリー内を移動するたびに、走査順序とは無関係に、ルートからのプレフィックス XOR によって XOR 状態が完全に決定されるということです。 テレポーテーションは XOR 状態を変更せず、位置を変更するだけです。 したがって、問題は、プレフィックス XOR によって XOR を変換できるノードが存在するかどうかを確認することになります。`a`入るのに適した状態になる`b`ゼロ XOR エッジ経由。 すべての遷移はプレフィックス XOR の違いのみに依存するため、有効なテレポート着地点が存在することは、グローバル プレフィックス セット内に一致する XOR 値が存在することと同等です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    t = int(input())
    for _ in range(t):
        n, a, b = map(int, input().split())
        g = [[] for _ in range(n + 1)]
        for _ in range(n - 1):
            u, v, w = map(int, input().split())
            g[u].append((v, w))
            g[v].append((u, w))

        xor_root = [0] * (n + 1)

        stack = [(a, 0, -1)]
        visited = [False] * (n + 1)
        visited[a] = True

        # DFS from a to compute xor from a (we can treat a as root)
        while stack:
            u, x, p = stack.pop()
            xor_root[u] = x
            for v, w in g[u]:
                if v == p:
                    continue
                if not visited[v]:
                    visited[v] = True
                    stack.append((v, x ^ w, u))

        xor_ab = xor_root[b]

        if xor_ab == 0:
            print("YES")
            continue

        # second DFS from b to find any node with same xor value as xor_root[a]
        target = xor_root[a]
        found = False

        stack = [b]
        visited = [False] * (n + 1)
        visited[b] = True

        while stack:
            u = stack.pop()
            if xor_root[u] == target:
                found = True
                break
            for v, w in g[u]:
                if not visited[v]:
                    visited[v] = True
                    stack.append(v)

        print("YES" if found else "NO")

if __name__ == "__main__":
    solve()
```実装では、まずツリーの隣接リストを構築します。 次に、ノードからの XOR 距離を計算します。`a`反復 DFS を使用して、これらの値を`xor_root`。 これにより、次から始まるパスに沿って XOR 値に直接アクセスできるようになります。`a`。 

次に、からの XOR が得られるかどうかを確認します。`a`に`b`はゼロです。 この式では、それは次のように表されます。`xor_root[b] == 0`これは、一意のパスに沿って蓄積された XOR がすでに制約を満たしていることを意味します。 

そうでない場合、コードは次から検索します。`b`外側に向かって、XOR からのノードが存在するかどうかを確認します。`a`値が一致する`xor_root[a]`。 これは、XOR 状態を整列させる有効なテレポート着地点を見つけて、最終的な遷移が`b`有効になる可能性があります。 

2 番目の DFS が必要なのは、テレポーテーションによって空間位置が XOR 蓄積から切り離されるためです。そのため、構造的近傍を検索する必要があります。`b`互換性のため。

 ## 特殊なケース

 重要なケースの 1 つが次のような場合です。`a`構造的にはすでにそれに近い`b`ただし、XOR は直接入力を妨げます。 このアルゴリズムは、パスの長さではなくプレフィックス XOR 条件に完全に依存してこれを処理します。 

もう 1 つのエッジ ケースは、すべてのエッジの重みが同一であるツリーです。 このような場合、多くのノードが XOR 関係を共有し、直接パスが失敗しても有効なテレポート先が多数存在するため、2 番目の DFS が重要になります。 このアルゴリズムでは、すべてがプレフィックス XOR 空間での単純なメンバーシップ チェックに限定されるため、値が繰り返されても正確性が損なわれることはありません。
