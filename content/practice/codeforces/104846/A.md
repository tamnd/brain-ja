 ## 解決策
 ## 問題の理解

 私たちには2種類の本が与えられました。 A には数学の本、B にはプログラミングの本があります。 各数学書には X 件の新しい事実が含まれており、各プログラミング本には Y 件の新しい事実が含まれています。 すべての本にわたるすべての事実は個別であるため、選択した本の知識の合計は、選択した本の線形和にすぎません。 

Ira は棚に最大 K 冊の本を置くことができます。 タスクは、制限 K を尊重して、ファクトの総数が最大になるように書籍のサブセットを選択することです。 

したがって、構造は単純です。値 X のコピー A と値 Y のコピー B があり、合計で最大 K 個の項目を選択できます。 達成可能な最大の金額が必要です。 

テスト全体の制約は大きく、A または B では最大約 10^12 です。これにより、書籍ごとのシミュレーションやサブセットの列挙が即座に除外されます。 テストごとにすべての書籍を線形スキャンする場合でも問題はありませんが、単位書籍の選択ごとに反復するものは、K 上のループ内で単純に実行すると遅すぎます。 

カテゴリの 1 つが空の場合、微妙な失敗のケースが発生します。 A = 0 または B = 0 の場合でも、貪欲な混合戦略は単一のプールからの選択に正しく還元される必要があります。 もう 1 つのケースは、K が A + B を超える場合です。この場合、棚を完全に埋めることができず、すべての本をそのまま取らなければなりません。 

たとえば、A = 3、B = 0、K = 5、X = 10、Y = 1 の場合、正解は 30 であり、50 や存在しない本のパディングを伴うものではありません。 

もう 1 つの特殊なケースは、1 つの型が値では優勢であるものの、カウントでは希少な場合です。たとえば、A = 2、B = 100、K = 50、X = 1000、Y = 1 です。可用性を考慮せずに、見栄えの良い型の min(K, B) だけを取得する単純な戦略は、ロジックが正しく書かれていない場合は失敗しますが、正しいアプローチでは自然にキャップが処理されます。 

## アプローチ

 最も直接的に考えると、i + j ≤ K、i ≤ A、j ≤ B となるように i 冊の数学の本と j 冊のプログラミングの本を選ぶためにあらゆる方法を試すことができます。それぞれのペアについて、i・X + j・Y を計算し、最大値を取得します。 これは正しいですが、各 i に対して j を決定するため、またはその逆のため、検索空間は O(K) になります。 K が非常に大きくなる可能性がある場合、これは実行不可能になります。 

項目タイプごとに値が 2 つしかないことに気づくと、構造が単純化されます。 どの数学の本も同じであり、どのプログラミングの本も同じです。 これにより、組み合わせの複雑さが解消されます。唯一意味のある決定は、各種類の本を何冊購入するかということです。 

その時点で、問題は 2 つのバケットから最大 K 個の項目を選択することになります。 X が Y より大きい場合、A と K によって制限された範囲内で最初にできるだけ多くの数学の本を手に取り、次に残りの容量をプログラミングの本で埋めるのが常に最適です。 Y が大きい場合は、役割を交換します。 これは、交換によって正当化される古典的な貪欲な選択です。より価値の高い本がまだ利用可能である間に、より価値の低い本を使用するソリューションは、交換によって改善できます。 

この総当り攻撃は K のすべての分割を明示的に列挙するため機能しますが、K が大きい場合は分割の数が K に比例して増加するため失敗します。各タイプ内ですべての項目が同一であるという観察により、決定を最大 2 つの決定的な選択に集約できます。

 ## アルゴリズムのチュートリアル

 私たちは各検査を独立して扱います。 

## アルゴリズムのチュートリアル

1. X と Y を比較して、どちらのタイプの書籍の単位あたりの価値が高いかを判断します。 これにより、本を選ぶべき順序が決まります。 
2. より高い値を最初に選択します。 X ≥ Y と仮定すると、まず数学の本を手に取ります。 Y > X の場合、対称的にプログラミングの本から始めます。 その理由は、最適なソリューションでは可能な限り、より価値の高い項目を優先する必要があるためです。 
3. より優れたカテゴリからできるだけ多くの本を選択します。数学の方が優れている場合は、最初に = min(K, A) を選択し、プログラミングの方が優れている場合は、min(K, B) を選択します。 
4. 残りの容量を減らす: K が K - 最初になります。 
5. 2 番目のカテゴリからできるだけ多くの本を取り出します。どちらが残っているかに応じて、2 番目 = min(K, B) または min(K, A) となります。 
6. 合計値を first_count × value_first + Second_count × value_second として計算します。 

各ステップは、最大で K 冊しか取得できず、各カテゴリの在庫状況を超えることはできないという制約によって強制されます。 

### なぜ効果があるのか

 有効な選択は、i ≤ A、j ≤ B、i + j ≤ K のカウント (i, j) によってのみ定義されます。より価値の高い本がまだ利用可能で容量が残っている間に、より価値の低い本が選択されるという解決策が存在するとします。 1 冊の価値の低い書籍をより価値の高い書籍に置き換えると、総額が厳密に増加し、実現可能性が維持されます。 この交換議論を繰り返すと、あらゆる最適解は、まず制約が許す限りより価値の高いカテゴリーを使い尽くしてから、もう一方のカテゴリーを使用するものに変換されます。 これにより、貪欲な順序付けが最適であることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(A, B, K, X, Y):
    if X >= Y:
        take_x = min(A, K)
        K -= take_x
        take_y = min(B, K)
        return take_x * X + take_y * Y
    else:
        take_y = min(B, K)
        K -= take_y
        take_x = min(A, K)
        return take_x * X + take_y * Y

def main():
    data = sys.stdin.read().strip().split()
    t = 10
    idx = 0
    out = []
    for _ in range(t):
        A = int(data[idx]); B = int(data[idx+1]); K = int(data[idx+2])
        X = int(data[idx+3]); Y = int(data[idx+4])
        idx += 5
        out.append(str(solve_case(A, B, K, X, Y)))
    print("\n".join(out))

if __name__ == "__main__":
    main()
```この実装は、貪欲な構造を直接反映しています。 重要な決定は、消費の順序を決定する X と Y の比較です。 少数の算術演算と最小限の計算のみを実行するため、各テストは一定時間になります。 

最初のバッチを取得した後に K が更新されることに注意する必要があります。 そうしないと、2 番目の選択で容量制約が誤って無視されてしまいます。 また、境界が大きいため、すべての算術演算は Python 整数に安全に適合します。 

## 実用的な例

 A = 3、B = 5、K = 4、X = 4、Y = 2 の単純なケースを考えてみましょう。

 数学の本は価値が高いため、まず使い切ってから、残りの容量をプログラミングの本に使います。 この結果は、貪欲な構造を裏付けています。 

ここで、A = 2、B = 10、K = 5、X = 1、Y = 10 について考えてみましょう。 

ここではプログラミング書籍が主流です。 

| ステップ | プログラミングを取る | 残り K | 数学を考えてみましょう | 合計 |

 | 開始 | 0 | 5 | 0 | 0 |
 | プログラミング後 | 5 | 0 | 0 | 50 |

 K はより高い値の型によって完全に消費されるため、数学の本は無関係です。 これは、1 つのカテゴリが完全に優勢なケースをアルゴリズムが正しく処理していることを示しています。

 ## 特殊なケース

 A = 0 または B = 0 の場合、最小呼び出しの 1 つがゼロになるため、アルゴリズムは自然に減少します。 たとえば、A = 0 かつ X ≥ Y の場合、数学の本については min(0, K) = 0 を採用し、次に K までの考えられるすべてのプログラミングの本を採用します。コードは特別な分岐を行わずにこれを処理します。 

K ≥ A + B の場合、両方のブランチが利用可能な書籍を完全に消費します。 最初の min は順序に応じて A または B に飽和し、次に 2 番目の min は残りを他のフルカウントまで取得し、A·X + B·Y を生成します。 

X = Y の場合、順序は重要ではありません。 アルゴリズムは依然として最初に 1 つのカテゴリを選択しますが、値が同一であるため、どの分割でも同じ合計が得られます。
