 ## 解決策
 ## 問題の理解

 整数のシーケンスが 1 つずつ表示されます。 新しい数値がそれぞれ出現した後、以前の 2 つの数値を取得し、間に何も挿入せずにそれらの 10 進表現を順番に連結することによって、その数値が「構築」できるかどうかを判断する必要があります。 

たとえば、以前に 12 と 3 があった場合、「12」の後に「3」を書くと「123」が得られるため、123 は構成可能であるとみなされます。 両方の部分が同じ以前の番号であっても、両方が現在の位置より前に見られている限り、同じ考え方が当てはまります。 シーケンス中に、以前に見た 2 枚のカードからこの方法で現在の数字を形成できる回数を数えます。 

入力サイズは最大 100 万個の数値に達し、それぞれは最大$10^6 - 1$, したがって、各番号は最大 6 桁になります。 このことから、どのようなソリューションでも各数値をほぼ一定時間または対数時間で処理する必要があることがすぐにわかります。 二次関数または偶数関数$O(n \sqrt{n})$アプローチは不可能です$10^6$要素ごとの操作がすでに大きすぎる可能性があります。 

主な困難は、単純なメンバーシップ条件ではなく、構造化された分解をチェックするように求められることです。すべての数値は、その 10 進数文字列を 2 つの空でない部分に分割する可能性があるすべてに対してテストする必要があり、両方の部分が以前に確認された値に対応する必要があります。 

素朴なアプローチを打ち破る微妙なエッジケースがいくつかあります。 

数値にゼロが含まれる場合、連結は数値の等価ではなく、文字列の等価として厳密に動作します。 たとえば、0 と 1 が表示された場合、連結は「01」となり、整数 1 には一致しません。そのため、正確な文字列形式を保持せずに数値を整数のみとして扱うと、不正確な一致が発生します。 

もう 1 つの微妙なケースは、値が繰り返されることです。 以前に 7 が 1 回出現した場合、7 が少なくとも 2 回出現しない限り、数字 77 は「7 + 7」から構成できません。 セット内の存在のみを追跡するソリューションでは、このケースが誤ってカウントされます。 

最後に、先頭のゼロは文字列構造を通じて暗黙的に重要になります。 入力数値は先行ゼロなしで指定されるため、ゼロで始まる左または右の部分を生成する分割は依然として有効な整数表現に対応しますが、正規化されたバージョンではなく、以前に確認された既存の数値と正確に一致する必要があります。 

## アプローチ

 最も直接的なアプローチは、以前に確認したすべての数値の記録を維持することです。 受信する数値ごとに、それを文字列に変換し、考えられるすべての分割ポイントを試します。 付きの番号の場合$d$数字、試してみます$d - 1$分割します。 分割ごとに、以前に確認された数値の中に両方の部分が存在するかどうかを確認します。 「はい」の場合、答えをインクリメントします。 

これが機能するのは、すべての有効な構造が文字列表現の 1 つの分割に正確に対応する必要があるためです。 ただし、同じ数値が 2 回必要になる可能性があるため、正確さは単純なセットではなく頻度カウントを使用するかどうかに依存します。 

ブルート フォース バージョンでは、数値ごとに、以前の数値のペアをすべてスキャンし、連結をテストします。 それには必要なもの$O(n)$クエリごとの候補、$O(n^2)$トータルオペレーションは実現不可能です$n = 10^6$。 

重要な点は、連結構造によりペアをグローバルに検索する必要がなくなるということです。 代わりに、各数値は独自の分割境界とのみ相互作用します。 これにより、問題は数値ごとに最大 5 つの分割をチェックすることになり (値は最大 6 桁であるため)、各チェックは$O(1)$辞書引き。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ペアに対するブルートフォース |$O(n^2)$|$O(n)$| 遅すぎる |
 | ハッシュマップによる分割チェック |$O(n \cdot d)$、$d \le 6$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 これまでに確認されたすべての数値の頻度マップを維持しながら、シーケンスを左から右に処理します。 

1. 現在の数値を文字列表現に変換します。 これが必要なのは、連結が算術値ではなく桁の境界に依存するためです。 
2. 文字列内の可能な分割位置ごとに、文字列を左側の部分と右側の部分に分割します。 各分割は、連結によって現在の番号を形成する可能性のある以前のカードの潜在的なペアに対応します。 これは、有効な構造を生成できる唯一の構造です。 
3. 両方の部分を整数に変換し直し、以前に表示された数値の頻度マップにそれらが存在するかどうかを確認します。 
4. 2 つの部分が等しい場合、ペアを形成するには 2 つの異なる出現が必要であるため、その数値の頻度が前の要素の中で少なくとも 2 であることを確認します。 
5. いずれかのスプリットが条件を満たす場合、その位置を有効な「サウンド イベント」としてカウントします。 
6. 現在の数値を処理した後、マップ内の頻度を増分して、将来の構築で使用できるようにします。 

### なぜ効果があるのか

 すべてのステップで、頻度マップは現在のインデックスより前に利用可能なすべてのカードを正確に表します。 現在の数値の有効な構成は、その 10 進表現を 2 つの連続する部分文字列に分割することに対応する必要があります。 連結により桁の順序がギャップなく保持されるため、数値を形成する他の方法はありません。 考えられるすべての分解がチェックされ、正確なカウントを使用して存在が検証されるため、有効なペアが見逃されることはなく、無効なペアは受け入れられません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n = int(input())
    a = list(map(int, input().split()))
    
    freq = {}
    ans = 0

    for x in a:
        s = str(x)
        ok = False

        for i in range(1, len(s)):
            left = int(s[:i])
            right = int(s[i:])

            if freq.get(left, 0) > 0 and freq.get(right, 0) > 0:
                if left != right:
                    ok = True
                    break
                else:
                    if freq.get(left, 0) > 1:
                        ok = True
                        break

        if ok:
            ans += 1

        freq[x] = freq.get(x, 0) + 1

    print(ans)

if __name__ == "__main__":
    main()
```ソリューションの中核は、増分周波数マップです。 これにより、以前に見たカードのみを考慮することが保証されます。 分割ループは桁数 (最大 6) によって制限されるため、要素ごとに一定時間のままになります。 

唯一の微妙な実装の詳細は、均等分割の処理です。 両方の半分が同じ整数に評価される場合、1 枚のカードを 2 回再利用することはできないため、少なくとも 2 つの以前の出現があることを確認する必要があります。

 サンプルシーケンスを考えてみましょう。```

```周波数マップを追跡しながら進めます。 

| インデックス | 値 | 分割をチェック | 有効な分割が見つかりました | これまでの回答 |

 | 1 | 1 | なし | いいえ | 0 |
 | 2 | 23 | なし | いいえ | 0 |

このトレースは、各決定がグローバル検索ではなく、以前に蓄積された周波数データとローカル分割構造のみに依存していることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(n \cdot d)$| 各数値は最大 5 回分割され、各分割では定数時間のハッシュ ルックアップが使用されます。 
| スペース |$O(n)$| 周波数マップには、見られるすべての個別の数値が保存されます。 

と$n = 10^6$そして$d \le 6$、合計操作数は、制限内で快適に実行できるほど十分に少ないです。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n_and_rest = inp.strip().split()
    n = int(n_and_rest[0])
    arr = list(map(int, n_and_rest[1:]))

    freq = {}
    ans = 0

    for x in arr:
        s = str(x)
        ok = False
        for i in range(1, len(s)):
            l = int(s[:i])
            r = int(s[i:])
            if freq.get(l, 0) > 0 and freq.get(r, 0) > 0:
                if l != r or freq.get(l, 0) > 1:
                    ok = True
                    break
        if ok:
            ans += 1
        freq[x] = freq.get(x, 0) + 1

    return str(ans)

# provided sample
assert run("7 1 23 123 11 21 1 2311") == "3"

# minimum size
assert run("1 5") == "0"

# simple concatenation
assert run("3 1 2 12") == "1"

# repeated value requires two earlier occurrences
assert run("5 7 7 77 77 777") == "2"

# no valid splits
assert run("4 10 20 30 40") == "0"

 ## 特殊なケース

 1 つのエッジ ケースが同じ数に分割されて繰り返されます。 入力を考慮してください:```
7 7 77
```2 番目の 7 を処理するとき、分割は存在しません。 77 を処理する場合、分割は (7,7) になりますが、正確かどうかは、前の 2 つの 7 に依存します。 現時点では 1 つだけが存在するため、チェックはそれを正しく拒否します。 

別の特殊なケースには、ゼロを含む数値が含まれます。```
3 0 1 1
```最後に 1 を評価する場合、分割「01」は格納されている整数 1 と正確に一致しないため無効です。 このアルゴリズムは、部分文字列のみの等価性ではなく、格納された値に対する整数の等価性に依存するため、この不一致を回避します。 

最後のエッジケースは、構成可能な数値の長いチェーンです。 すべての数値が有効であっても、各ステップは定数時間の分割チェックにのみ依存するため、アルゴリズムは安定したままであり、シーケンスが大きくなっても劣化しません。
