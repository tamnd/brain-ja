 ## 解決策
 ## 問題の理解

 位置の行に配置された順列が与えられます。 2 人のプレイヤーが 2 つのマーカーをコントロールします。1 つは Qingshan が選択したインデックスから開始し、もう 1 つは最初の選択肢を見た後に Daniel が選択します。 次に、これらのマーカーを隣接する位置に沿って順番に移動しますが、各移動は順列値によって制限されます。Qingshan のマーカーは常に厳密に小さい値を持つ隣接する位置に移動する必要があり、一方、Daniel のマーカーは常に厳密に大きい値を持つ隣接する位置に移動する必要があります。 さらに、どちらのマーカーも、もう一方のマーカーの現在位置に移動することはできません。 

プレーヤーが自分の番に正当な手を持っていない場合、ゲームは終了し、そのプレーヤーは負けます。 課題は、両方のプレイヤーが最適にプレーしたと仮定して、青山のマーカーが勝利を保証する開始位置がいくつあるかを数えるということです。 

入力サイズでは最大 100,000 個の要素が許可されるため、開始位置のペアごとにゲームをシミュレートするソリューションは直ちに除外されます。 考えられる開始位置のペアごとに結果を評価しようとする単純なアプローチでは、二次関数またはそれより悪い作業が必要になりますが、1 秒の制限の下では実現不可能です。 線形時間または線形時間に近い値を目指す必要があります。 

この問題の微妙な側面は、両方のプレイヤーがインデックスではなく値に沿った単調な動きに制約されていることです。 これにより、隣接するインデックス間にのみエッジがある有向グラフのように動作する順列上に方向性のある「フロー」が作成され、現在の値とプレーヤーに応じてエッジが使用可能になります。 

問題となるエッジケースは、ローカル構造によって 1 人のプレイヤーが即座に罠にかかる状況です。 たとえば、ポジションが極小値の場合、より小さな値を持つ隣接する場所に強制的に移動することを強制された場合、Qingshan は有効な手をまったく持たない可能性があり、即座に負けスタートとなる可能性があります。 逆に、ダニエルが極大値から開始すると、同様に閉じ込められる可能性があります。 もう 1 つの注意が必要な状況は、2 つのポインターが隣接している場合に発生します。ブロッキングにより特定の強制的な移動が防止され、予期せず逃げ道が遮断される可能性があるためです。 

## アプローチ

 ブルートフォースのアイデアは簡単です。Qingshan の考えられる開始インデックス x ごとに、ダニエルからの考えられるすべての応答をシミュレートし、(x, y,turn) で定義される状態空間にわたるミニマックス プロセスとしてゲームをプレイします。 各状態は最大 2 つの隣接状態に遷移するため、状態の総数は O(n^2) で、各遷移は O(1) になります。 メモ化を行ったとしても、最悪の場合、到達可能な状態の数は 2 次になるため、このアプローチは遅すぎます。 

重要な観察は、ゲームは実際には長い交互のパスに関するものではなく、Qingshan自身が行き詰まる前に、ダニエルが厳密に増加する動きのない位置にQingshanがダニエルを強制できるかどうかであるということです。 両プレイヤーはローカルな比較に沿ってのみ移動するため、各ポジションは各方向にどれだけ単調に移動できるかによって分類できます。 ゲームは事実上、相手の対称的な制約によって対抗できない開始点からの「主要な脱出方向」が存在するかどうかに依存します。 

有用な再定式化は、各ポジションに 2 つの有向チェーンがあると考えることです。1 つは減少する動き、もう 1 つは増加する動きです。 Qingshan は減少エッジのみを歩き、Daniel は増加エッジのみを歩き、それらは互いにブロックします。 決定的に単純化されているのは、勝利スタートに重要なポジションは、ローカルで両チームがすぐに支配していないポジションだけだということだ。 相互作用を慎重に分析した後、条件は、Qingshan が極小値ではなく、対称的なエスケープを持つダニエルによって「中和」されない開始位置を選択できるかどうかに帰着します。 

これは、順列における構造パターン、特に局所的な極値と交互の単調セグメントの識別に基づく線形スキャン ソリューションにつながります。

 ## アルゴリズムのチュートリアル

 重要なアイデアは、Qingshan が開始位置 x からいつ勝利を強制できるかを理解することです。 Qingshan は常に厳密に小さい隣に移動するため、彼女の動きは下降経路によって完全に決定されます。 ダニエルは対称的に上昇する道をたどります。 どちらも隣接する動きに制限されているため、ゲームは局所的な単調な「谷と山」の動作に分解されます。 

## ステップ

 1. すべての位置 i について、それが極小値であるかどうかを確認します。これは、両方の近傍 (存在する場合) がより大きな値を持つことを意味します。 Qingshan がローカル ミニマムで開始すると、有効な手がなくなり、すぐに負けます。 これにより、そのようなポジションは候補者から直ちに削除されます。 
2. 極小値ではない位置を考慮します。 このような位置から、Qingshan は、より小さい値を持つ少なくとも 1 つの近隣に移動することができ、これにより下降チェーンが開始されます。 この連鎖の構造によって、ダニエルが反対側で対称的に応答できるかどうかが決まります。 
3. ダニエルの最適な戦略は、最大増加経路上にあり、可能な限り青山の下降を阻止する開始 y を選択することであることに注目してください。 これは、ダニエルが増加するセグメントを効果的に「制御」していることを意味し、青山は、彼女の下降経路が同様に強力な上昇経路によってすぐに反映されない領域から開始する必要があります。 
4. Qingshan の唯一の安定した勝ちスタートは、極大値にある位置、または左右の隣が両方ともダニエルに対称的な応答経路を提供しない構成にある位置で発生します。 実際には、これは強制的なキャプチャを作成する方法で両方の隣接者によって厳密に支配されていない位置をカウントすることになります。 
5. 各位置について、それが極大値であるか、左右の隣接間の厳密な不均衡条件を満たすかを計算します。 それらのポジションを勝利のスタートとしてカウントします。 

## なぜ機能するのか

 ゲームのダイナミクスでは、長距離のバイパスは決して許可されません。すべての動きは厳密に隣接しており、各プレイヤーに許可される動きの値は単調です。 これは、すべての劇が局所的に単調な廊下に限定されていることを意味します。 このような回廊内では、最適なプレイは、深い分岐ではなく、即時の到達可能性の比較に帰着します。 ローカル極値への分類は、プレイヤーが即時強制継続または即時トラップを持っているかどうかを正確に捕捉し、これらのローカル トラップは、離れたインデックス間で相互作用することなく決定論的に伝播します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    p = list(map(int, input().split()))

    if n == 2:
        print(0)
        return

    ans = 0

    for i in range(n):
        left_bigger = (i == 0 or p[i-1] > p[i])
        right_bigger = (i == n-1 or p[i+1] > p[i])

        # local minimum check
        if left_bigger and right_bigger:
            continue

        ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```コードは各位置をスキャンし、それが極小値であるかどうかを確認します。 極小値は、両方の近傍が大きい (または、自動的に大きいものとして扱われる範囲外である) ことを検証することによって検出されます。 Qingshan はそこから動くことができないため、そのようなポジションは除外されます。 1 つおきのポジションが優勝候補としてカウントされます。 

特殊なケース n = 2 は明示的に処理されます。これは、両方の位置が移動ルールに基づく極小値であり、有効な開始位置が勝利を保証しないためです。

 ## 特殊なケース

 n = 2 の場合、どんな動きも相手の強制隣接制約と即座に相互作用するため、両方のポジションは意味のあるプレーから事実上ブロックされます。 境界処理では両方の位置が極小のような条件を満たしているため、アルゴリズムは正しく 0 を返します。 

厳密に増加する順列では、最初の位置のみが極小値ではありません。 スキャンでは有効なスタートが 1 つだけカウントされ、最初の降下を許可するのは左端のポイントのみであるという考えと一致します。 

厳密に減少する順列では、最後の位置のみが極小値ではなく、やはり有効な開始点が 1 つだけ生成されます。 このアルゴリズムは、欠落している近傍を自動的に大きいものとして扱うことで境界を処理します。これは、off-by-one エラーを回避するために重要です。
