 ## 問題の理解

 いくつかのセルがすでに含まれているグリッドが与えられています。`'X'`残りのセルには次のものが含まれます`'.'`。 

元の物語では、雷がひまわりを破壊するという描写があります。 グラフの観点から見ると、マークされたセルは`'X'`すでに選択されている頂点です。 任意に変更することができます`'.'`の中へ`'X'`ただし、既存のものを変更することは決して許可されません。`'X'`に戻る`'.'`。 

最終セットの`'X'`セルは 4 方向の隣接関係で接続された非巡回グラフを形成する必要があります。 グラフ用語では、すべてのグラフの誘導`'X'`セルはツリーでなければなりません。 

重要な情報は、最初のオブジェクトの特殊な構造です。`'X'`細胞。 それらのうちの 2 つは、たとえ斜めであっても隣接していません。 既存`'X'`セルは少なくとも 1 つの行と 1 つの列によって互いに分離されます。 

すべてのグリッド サイズの合計は最大 250,000 です。 これは、受け入れられているソリューションでは、各セルを一定の回数だけ処理する必要があることを直ちに示唆しています。 アン$O(nm)$または$O(nm \log(nm))$ソリューションは容易に十分に高速になりますが、グリッド全体にわたるグラフ検索の繰り返しを伴うものは不要になります。 

難しいのは接続性ではありません。 新規追加も自由にさせていただきますので、`'X'`セル、すべてを接続するのは簡単です。 課題は、すべての元の状態を保証しながらサイクルを回避することです。`'X'`最後のツリーに残ります。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

単一行のグリッドを考えてみましょう。```
1 10
....X.X.X.
```垂直コネクタを構築する余地はありません。 3 列のブロックを前提とした建設は失敗します。 受け入れられた解決策は、必然的に行全体を埋めるように縮小される必要があります。 

高さが 3 で割り切れないグリッドを考えてみましょう。```
5 5
.....
.....
.....
.....
.....
```行 1、4、7、... のみにパターンを構築すると、最後の 2 行は切断されたままになります。 構築では最後の 1 行または 2 行を明示的に処理する必要があります。 

別の微妙なケースは次のとおりです。```
4 4
....
.X.X
....
.X.X
```オリジナル`'X'`セルは異なる列に配置されます。 毎回固定列を使用して行ブロックを接続すると、既存の列ブロックの一部が`'X'`セルが主構造から分離されてしまう可能性があります。 コネクタ列は、既存の場所に応じて選択する必要があります`'X'`セルはすでに表示されています。 

## アプローチ

 ブルートフォースの観点では、すべてのセルをグラフの頂点として扱い、元のすべてのセルを含むツリーを検索します。`'X'`細胞。 セルを徐々に追加し、選択するたびに接続性と非周期性をチェックすることを想像できます。 

有効な答えが常に存在するため、このような検索は理論的には正しいです。 残念なことに、国家空間は膨大です。 あ$500 \times 500$グリッドには 250,000 個のセルが含まれているため、各セルが最終ツリーに属するかどうかを個別に決定することさえ完全に不可能です。 

重要な観察は、オリジナルの異常な制約から来ています。`'X'`細胞。 オリジナルは２つもないので`'X'`細胞が接触しても、すでにサイクルを作成することはできません。 必要なのは、それらを接続する体系的な方法だけです。 

受け入れられた構造はバックボーンを構築します。 3 行ごとに完全に埋められます。`'X'`。 これらの行は、グリッドの幅全体にわたる水平なハイウェイになります。 

このような高速道路が存在すると、連続する高速道路の間に必要な垂直コネクタは 1 つだけになります。 2 つの高速道路間の列には、最大 2 つの列が含まれます。 オリジナルなので`'X'`細胞は分離されています。`'X'`これらの中間行に出現するものは、サイクルを作成せずに、選択したコネクタ列に接続できます。 

これにより、ツリー状の構造が生成されます。 塗りつぶされた行はメインのスケルトンを形成し、中間の行のセルはそのスケルトンからぶら下がっています。 

全体の構造は決定的であり、各セルに一定の回数だけ接触します。

 ## アルゴリズムのチュートリアル

 まず次のように仮定します$m > 1$。 

1. 3 行おきに完全に埋めます。`'X'`。 0 から始まるインデックスを使用すると、これらは行 0、3、6、9 などとなります。 
2. 連続する塗りつぶされた行の各ペアを検討します。 それらの間には 1 つまたは 2 つの中間行があります。 
3. これらの中間行で既存の行を検索します。`'X'`。 
4. 既存の`'X'`が見つかった場合は、その列をコネクタ列として選択します。 
5. 存在しない場合`'X'`中間行に存在する場合は、列 0 を選択します。 
6. コネクタ列に次のように入力します。`'X'`現在のブロックのすべての行を通過します。 これにより、2 つの隣接する高速道路の列が 1 つの連結コンポーネントに結合されます。 
7. 完全な 3 行ブロックをすべて処理した後、最後にちょうど 2 行が残る特殊なケースを処理します。 
8. 最後の 2 行については、2 行のいずれかにすでに含まれているすべての列を埋めます。`'X'`。 これにより、残りの行が上記の構造にマージされます。 

いつ$m = 1$、構造はミラーリングされています。 すべてのセルは単純に満たされています`'X'`。 単一の列にサイクルを含めることはできないため、結果は自動的にツリーになります。 

### なぜ効果があるのか

 3 行おきに完全に埋まり、長い水平パスが作成されます。 連続する高速道路の列は、1 つの垂直橋によって接続されます。 隣接する高速道路列の間には橋が 1 つしかないため、それらの間にサイクルを形成することはできません。 

あらゆるオリジナル`'X'`中間の列にあるものは、その橋の柱に取り付けられます。 元のセルは相互に接触していないため、単一のバックボーンにそれらを接続しても代替ルートを作成することはできません。 

結果として得られる構造は、背骨が完全に埋められた行で構成され、その枝が入力から継承されたセルであるツリーに似ています。 毎`'X'`は 1 つの接続されたコンポーネントに属しており、主要なコンポーネント間のすべての接続は一意のブリッジを使用します。 代替ルートのない接続されたグラフはツリーであるため、要件は満たされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    out = []

    for _ in range(t):
        n, m = map(int, input().split())
        g = [list(input().strip()) for _ in range(n)]

        if m == 1:
            for i in range(n):
                g[i][0] = 'X'
            out.extend(''.join(row) for row in g)
            continue

        for r in range(0, n, 3):
            for c in range(m):
                g[r][c] = 'X'

        r = 0
        while r + 3 < n:
            col = -1

            for c in range(m):
                if g[r + 1][c] == 'X' or g[r + 2][c] == 'X':
                    col = c
                    break

            if col == -1:
                col = 0

            g[r + 1][col] = 'X'
            g[r + 2][col] = 'X'

            r += 3

        if n % 3 == 2:
            last = n - 1
            prev = n - 2

            for c in range(m):
                if g[prev][c] == 'X' or g[last][c] == 'X':
                    g[prev][c] = 'X'
                    g[last][c] = 'X'

        out.extend(''.join(row) for row in g)

    sys.stdout.write('\n'.join(out))

if __name__ == "__main__":
    solve()
```最初のブランチは特殊なケースを処理します$m=1$。 単一の列はパスのみを形成できるため、すべてのセルを埋めるだけで十分です。 

次のループで行が埋められます`0, 3, 6, ...`完全に。 これが建築の根幹です。 

の`while`ループは一度に 1 つの 3 行ブロックを処理します。 の検索`col`既存のものを探します`'X'`中間の 2 つの列にあります。 このようなカラムを選択すると、既存の細胞が分離されるのではなく、自然にバックボーンに付着することが保証されます。 

決勝戦`n % 3 == 2`調整はバグの最も一般的な原因です。 これがないと、下の 2 列が構造の残りの部分から切り離されたままになる可能性があります。 このコードは、`'X'`どちらの列でも。 

構築自体が必要な構造を保証するため、再帰、グラフ走査、サイクル検出は必要ありません。
