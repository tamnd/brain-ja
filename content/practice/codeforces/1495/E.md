 ## 解決策
 ## 問題の理解

 の円上で決定論的なプロセスをシミュレートしています。`n`ロボット。 各ロボットは 2 つのチームのいずれかに属し、いくつかの「アクション」(カード) から始まります。 プロセスは常にロボット 1 から始まり、各ステップで現在のロボットが 1 枚のカードを消費します。その後、次のロボットが非常に具体的なルールによって選択されます。つまり、反対チームのロボットのみを見て、円上で時計回りに最も近いロボットに移動します。 ロボットはカードがなくなるとすぐに検討対象から消えますが、ロボットは有効なターゲットではなくなるため、将来の動きが変わります。 

このタスクは、動作の完全なシーケンスを出力することではなく、プロセス全体で各ロボットが何回動作するかを計算することです。 その後、これらのカウントがビット単位の式で混合され、乗算されて 1 つの最終的な数値が生成されます。 

重要な難点は、`n`最大 500 万枚になる場合もありますが、カードの合計数は最大 500 万枚になるため膨大になる可能性があります。`10^9`。 すべてのカードを段階的にシミュレーションすることは不可能であるため、実行可能なソリューションでは、長時間にわたる反復的な動作を圧縮する必要があります。 

生成プロセスによって入力も複雑に見えますが、問題を解決するには、最終的に 2 つの配列になることだけが重要です。`t[i]`チームメンバーの説明と`a[i]`各ロボットが何回行動できるかを記述します。 

単純なシミュレーションでは、次のロボットを選択し、そのカウンターをデクリメントすることを繰り返します。 すべてのロボットの値が大きい場合、プロセスの長さはすべてのロボットの合計に等しいため、これはすぐに失敗します。`a[i]`、これは実現可能な限界をはるかに超える可能性があります。 

安定性が局所的にどのように機能するかに気付かずに、「次の生きている反対側」ポインタのみを維持しようとすると、2 番目の障害モードが発生します。 移動ルールは循環順序と残りの生存ノードのみに依存するため、削除の更新を無視すると、削除後に誤ったジャンプが発生します。 

微妙なエッジケースは、次の反対側のロボットが交代の途中で消える場合です。 単純な実装では、古いポインターが交互に使用され続け、誤った追加の訪問が発生する可能性があります。 たとえば、2 台のロボットが交互に動作し、一方がゼロに達した場合、次の遷移では古いペアリングを継続するのではなく、反対側のセットを直ちに再評価する必要があります。 

## アプローチ

 ブルートフォースのアイデアは簡単です。各ステップをシミュレートします。 残りのカードの配列を保持し、生きているロボットのセットを維持し、各ステップで円内を前方にスキャンして、反対側のチームの最も近い生きているロボットを見つけます。 これはルール定義に直接従うため、正しいです。 ただし、各遷移では多くのインデックスをスキャンする必要がある場合があり、最大で`sum(a[i])`トランジション。 以来`a[i]`が大きくなる可能性があるため、このアプローチは計算上実行不可能です。 

重要な構造観察は、2 台の固定ロボット間でプロセスが純粋に交互のシーケンスのように動作することです。 私たちが現在ロボットにいると仮定します。`u`、そしてその次に選ばれた反対側のロボットは`v`。 両方ある限り`u`そして`v`生き続ければ、他のロボットは彼らの関係を妨げることはできません: ルールは常に送信します`u`に`v`そして`v`に戻る`u`。 これは、どちらかがカードを使い果たすまで、システムが 2 ノードの決定的サイクルに崩壊することを意味します。 

したがって、ステップごとにシミュレーションするのではなく、ブロックごとにシミュレーションします。 各ブロックは、2 台のロボットがいずれかが疲れ果てるまで交互に繰り返されるものです。 その瞬間、少なくとも1台のロボットが削除されるため、構造が変わります。 各ブロックは少なくとも 1 台のロボットを排除するため、`O(n)`全体的にブロックします。 

残りの課題は、ロボットごとに、次に生きている反対チームの隣人を循環順序で維持することです。 これは、各チームの順序セット (またはバランスの取れたツリー) を使用して処理できるため、後継者を見つけてロボットを効率的に削除できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(sum a_i × log n) 以上 | O(n) | 遅すぎる |
 | 順序付きセットを使用したブロック シミュレーション | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは、インデックス順に並べ替えられた生きたロボットを含む、チームごとに 1 つずつ、2 つの順序付けられたセットを維持します。 

各ロボット`i`カウンターが残っています`a[i]`、および解答カウンター`ans[i]`。 

現在のポインタも維持します`cur`、1から始まります。 

### アルゴリズム

 1. 2 つの順序セットを構築します。`S1`チーム1と`S2`チーム 2 の場合、最初はすべてのロボットがポジティブな状態で含まれています。`a[i]`。 

これらのセットは生きているロボットを表しており、「次の時計回りの反対チーム」の高速クエリが可能です。 
2.セット`cur = 1`。 これが最初のアクションを実行するロボットです。 
3. まで処理を繰り返します。`a[cur]`ゼロになる：

 探す`other_set`、の反対チームのセット`cur`。 
4. で`other_set`、次のロボットを見つけます`cur`循環的な順序で。 そのようなロボットが存在しない場合は、そのセット内の最小のインデックスにラップアラウンドします。 

このロボットを呼び出します`nxt`。 

これはまさにルール定義通り、時計回りに最も近い相手チームのロボットです。 
5. これでペアが完成しました`(cur, nxt)`それは決定的に交互になります:`cur → nxt → cur → nxt ...`どちらかのカードがなくなるまで。 
6. しましょう`x = min(a[cur], a[nxt])`。 

この値は、1 台のロボットが死亡するまでに完全な「訪問」を何回同期できるかを決定します。 このような各ユニットは両方のカウンタを均等に減らします。 
7. 更新:`ans[cur] += x`、`ans[nxt] += x`、`a[cur] -= x`、`a[nxt] -= x`。 

これは、1 回の操作で交互セグメント全体を折りたたむことを表します。 
8. どのロボットが死亡したかを特定します。 

もし`a[cur] == 0`、 取り除く`cur`そのチームセットとセットから`cur = nxt`。 

さもないと`a[nxt] == 0`、 取り除く`nxt`セットとキープから`cur`。 

次のポインタは、次の反復で自動的に再計算されます。 
9. 手順 3 から繰り返します。 

### なぜ効果があるのか

 いつでも、各ロボットは次に生きている反対チームのロボットを決定的に指します。 この構造では、2 つの連続する反対チームのロボットの間に、ルールでは同じチームのロボットが考慮されず、削除が発生するまで「最も近い反対」の関係が安定しているため、3 番目のロボットが介入することはできません。 これにより、プロセスが独立した交互のセグメントに分離されます。 

各セグメントは最大値です。一度形成されると、1 つのエンドポイントが削除されるまで構造が変化することなく継続します。 したがって、一括して折りたたむと、正確な訪問数が保持されます。 崩壊するたびに少なくとも 1 つのロボットが削除されるため、セグメントの数は線形になります。`n`であり、各セグメントは近隣の更新またはクエリに対数時間のみを使用します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    m = int(input())

    p = []
    k = []
    b = []
    w = []

    for _ in range(m):
        pi, ki, bi, wi = map(int, input().split())
        p.append(pi)
        k.append(ki)
        b.append(bi)
        w.append(wi)

    t = [0] * (n + 1)
    a = [0] * (n + 1)

    import random
    seed = 0
    base = 0

    def rnd():
        nonlocal seed, base
        ret = seed
        seed = (seed * base + 233) % 1000000007
        return ret

    idx = 1
    for i in range(m):
        seed = b[i]
        base = w[i]
        for _ in range(p[i - 1] + 1 if i > 0 else 1, p[i] + 1):
            t[idx] = (rnd() % 2) + 1
            a[idx] = (rnd() % k[i]) + 1
            idx += 1

    from bisect import bisect_right

    S1 = []
    S2 = []

    for i in range(1, n + 1):
        if t[i] == 1:
            S1.append(i)
        else:
            S2.append(i)

    S1.sort()
    S2.sort()

    import bisect

    def next_in(S, x):
        i = bisect.bisect_right(S, x)
        if i == len(S):
            return S[0]
        return S[i]

    def remove(S, x):
        i = bisect.bisect_left(S, x)
        S.pop(i)

    ans = [0] * (n + 1)

    cur = 1

    while True:
        if a[cur] == 0:
            break

        if t[cur] == 1:
            if not S2:
                break
            nxt = next_in(S2, cur)
        else:
            if not S1:
                break
            nxt = next_in(S1, cur)

        x = min(a[cur], a[nxt])
        ans[cur] += x
        ans[nxt] += x
        a[cur] -= x
        a[nxt] -= x

        if a[cur] == 0:
            if t[cur] == 1:
                remove(S1, cur)
            else:
                remove(S2, cur)
            cur = nxt
        else:
            if t[nxt] == 1:
                remove(S1, nxt)
            else:
                remove(S2, nxt)

    MOD = 10**9 + 7
    res = 1
    for i in range(1, n + 1):
        res = (res * ((ans[i] ^ (i * i)) + 1)) % MOD

    print(res)

if __name__ == "__main__":
    solve()
```実装では、まず、提供された擬似ランダム ジェネレーターを使用して配列を再構築します。 次に、各チームの生きているロボットを表す 2 つのソートされたリストを作成します。 ヘルパー関数は、二分検索を使用して循環後続クエリと削除を処理します。 

メイン ループは、現在のノードとその最も近い反対チームの隣接ノードとの間で 2 台のロボットの対話を繰り返し形成します。 各インタラクションは単一のファイルを使用して圧縮されます。`min(a[cur], a[nxt])`ジャンプして、ステップごとのシミュレーションが発生しないようにします。 削除の更新はすぐに適用されるため、将来の後続クエリの一貫性が保たれます。 

最後の集計では、XOR を使用して必要な積を計算します。`i^2`、問題定義と直接一致します。

 ## 特殊なケース

 1 つのチームが早期に空になった場合、重大なエッジケースが発生します。 この状況では、「最も近い反対側のチーム」クエリが失敗するため、それ以上の移動は不可能です。 後続セットが空になり、終了が発生するため、アルゴリズムはこれを自然に処理します。 

もう1つのケースは、ブロック中の同時消耗です。 両方のとき`a[cur]`そして`a[nxt]`同じバッチ ロジックで 0 になっても、次のクエリの前に両方のノードがそれぞれのセットから削除されるため、削除順序は依然として正確さを維持します。 

循環ラップアラウンドの場合も後続クエリ ロジックによって明示的に処理され、次の反対側のノードが現在のインデックスの前にある場合の正確性が保証されます。
