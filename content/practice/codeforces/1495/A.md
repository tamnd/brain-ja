 ## 解決策
 ## 問題の理解

 平面上に 2 組の点が与えられています。 1 つのセットにはマイナーが含まれており、それらはすべて厳密に垂直軸上にあるため、各マイナーは次の形式の座標を持ちます。$(0, y)$。 もう 1 つのセットにはダイヤモンド鉱山が含まれており、それらはすべて厳密に水平軸上にあるため、各鉱山は次の形式の座標を持ちます。$(x, 0)$。 すべてのポイントはこれら 2 つのセットのいずれかに正確に属し、同じ数のマイナーと鉱山が存在します。 

各マイナーは 1 つの鉱山に正確に割り当てられ、2 つのセット間で完全に一致する必要があります。 マイナーをペアリングするコスト$(0, y)$に鉱山がある$(x, 0)$はユークリッド距離です$\sqrt{x^2 + y^2}$。 タスクは、これらの距離の合計を最小にするペアリングを選択することです。 

入力サイズは最大です$n = 10^5$テストケースごと、すべての合計$n$テストケース全体の境界も次のとおりです$10^5$。 これにより、階乗数の代入は不可能であるため、すべてのマッチングを試みるアプローチは即座に除外されます。 平$O(n^2)$解決策は遅すぎます。$10^{10}$最悪の場合の運用。 

微妙な難しさは、座標が正または負の可能性があり、距離が二乗値に依存するという事実から生じます。 最小の絶対値を照合したり、座標記号を独立して照合したりするような単純な欲張りなアイデアは失敗する可能性があります。 たとえば、マイナーが次の場所にいる場合、$(0, 1)$、$(0, 100)$と鉱山$(1, 0)$、$(2, 0)$、絶対値のソート順のペアリングは合理的であるように見えますが、クロスペアリングが大きな距離をより効果的に短縮する可能性があることを無視しています。 

もう 1 つの重要なエッジ ケースは、多くの点が同じ座標の大きさを共有するが、符号が異なる場合です。 距離は平方に依存するため、正の引数に対する平方根関数の単調性について正しく推論しない限り、対称性は単純なペアリングを直ちに意味しません。 

## アプローチ

 ブルートフォースアプローチでは、マイナーと鉱山の間で可能なすべての全単射を試み、総コストを計算します。 これはすべての代入を評価するので正しいですが、全単射の数は$n!$、たとえそれがあまりにも急速に成長する$n = 10^5$。 たとえ小規模なケースに限定したとしても、計算は依然として実行不可能です。 

より構造化されたアプローチは、各コストがペアによってのみ決定されることを観察することから生まれます。$(|x|, |y|)$、距離は$\sqrt{x^2 + y^2}$。 重要な考え方は、実際には順序付けの目的で符号を気にするのではなく、大きさだけを気にするということです。 マイナーを絶対的な順に並べ替えると、$y$- 絶対的な座標と地雷$x$-座標を並べ替えると、平方和の平方根によって引き起こされる凸コストの合計が最小化されることがわかります。 

この直感は交換引数に似ています。2 つのペアが順序付けで「交差」している場合、それらを交換しても総コストは増加しません。$f(x, y) = \sqrt{x^2 + y^2}$は、両方の引数に関して対称の凸状に単調に動作します。 これにより、最適なマッチングがソートされた配置に向けて推進されます。 

したがって、問題は両方のリストを絶対値でソートし、対応する要素をペアにすることに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n!)$|$O(n)$| 遅すぎる |
 | 最適 |$O(n \log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 マイナーと鉱山を分離し、それらの絶対座標を抽出し、両方の配列を並べ替えます。 次に、それらをインデックスごとにペアにします。 

1. すべてのポイントを読み取り、マイナーと鉱山の 2 つの配列に分割します。 距離は正方形のみに依存し、符号は順序付けの決定に影響しないため、絶対値を使用します。 
2. すべてのマイナーを集める$y$- 1 つのリストとすべてのリストを調整します$x$-別のリストに統合します。 
3. 両方のリストを非降順で並べ替えます。 これにより、最小の大きさが一緒に整列され、最大の大きさが最大の大きさに整列されます。 
4. 左から右に反復して計算します$\sqrt{x_i^2 + y_i^2}$各ペアの合計を累積します。 
5. 最終的な合計を高精度に出力します。 

重要なステップは、並べ替えとペアリングのルールです。 この正しさは、独立した絶対値に対する距離関数の対称的な凸状の性質により、ペアリングの反転を交換して総コストを削減または維持できるという事実から得られます。 

### なぜ効果があるのか

 マグニチュードを持つ 2 人のマイナーを考えてみましょう$a \le b$そして、規模の大きな鉱山が 2 つあります$c \le d$。 考えられる組み合わせは 2 つあります。$(a, c), (b, d)$そして$(a, d), (b, c)$。 最適な構造は次の不等式で示されます。$$\sqrt{a^2 + c^2} + \sqrt{b^2 + d^2} \le \sqrt{a^2 + d^2} + \sqrt{b^2 + c^2}.$$これは、対の大きさ間の不均衡が増大すると、総ユークリッド コストが増加するため当てはまります。 このスワップ引数を繰り返し適用すると、すべての反転が削除され、最適なものとしてソートされたペアが得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import math

t = int(input())
out_lines = []

for _ in range(t):
    n = int(input())
    miners = []
    mines = []

    for _ in range(2 * n):
        x, y = map(int, input().split())
        if x == 0:
            miners.append(abs(y))
        else:
            mines.append(abs(x))

    miners.sort()
    mines.sort()

    total = 0.0
    for i in range(n):
        total += math.sqrt(miners[i] * miners[i] + mines[i] * mines[i])

    out_lines.append(str(total))

print("\n".join(out_lines))
```コードはまず、軸のメンバーシップに基づいて入力を分離します。 これにより、役割の混合が回避されますが、ペアリングは 2 つのグループ間でのみ有効であるため、これは不可欠です。 絶対値を取得すると、一貫した大きさの比較が保証されます。 

両方のリストのソートは、最適なペアリングを強制する構造的なステップです。 最後のループでは、一致した各ペアにユークリッド距離の公式を直接適用します。 この問題では許容誤差が非常に小さく、Python の倍精度で十分であるため、浮動小数点演算はここでは安全です。 

よくある実装上の間違いは、マイナーとマイニングを厳密に分離することを忘れたり、符号を含む生の座標をソートしようとしたりすることで、単調なペアの引数が壊れてしまいます。 もう 1 つの微妙な問題は、中間値に整数演算を使用することです。 距離には平方根が含まれるため、すべてを浮動小数点で計算する必要があります。

 ## 特殊なケース

 すべてのマイナーと鉱山が、原点から同じ距離にある複数の点など、絶対値が繰り返されて対称的に配置されている場合でも、等しい要素内の順列によって総コストが維持されるため、ソートによって有効なペアが生成されます。 このアルゴリズムはタイブレークに依存しません。 

マイナーなど、一方の側が極端に不均衡な場合$[1, 1, 1]$そして鉱山$[1, 100, 100]$、アルゴリズムは、最初に小さい値と小さい値のペアを確保し、大きい値と大きい値のペアを最後に残します。これにより、中間コストの不必要なインフレが防止されます。 

すべての値が同一の場合、すべてのペアの総コストは同じになり、ソートは正確さに影響を与えることなく任意のマッチングに退化します。
