 ## 解決策
 ## 問題の理解

 負ではない整数のシーケンスが与えられ、オプションで任意の要素に桁反転演算を適用することができます。 各数値を個別に反転できますが、反転できるのは 1 回のみです。 これらの選択を実行した後、最終的な配列を取得し、その mex を最大化したいと考えます。 

mex は、結果の配列に現れない最小の非負の整数です。 したがって、目標は、値を最大化したり要素を再配置したりすることではなく、到達可能な値のセットの中で小さな整数ができるだけ早く現れるように戦略的に確保することです。 

主な問題点は、各数値がシステムに 2 つの可能な値 (元の値と桁を反転した値) を与えることです。 順列や順序を選択するのではなく、各要素がどの表現を取るかを決定するだけです。 

この制約は、n が最大 100000 であり、値が 10^18 までであることを意味します。 逆向きまたは逆向きでないすべての代入を試みるアプローチは、n において指数関数的であり、直ちに不可能です。 各構成に対して単純に mex をチェックするだけでも、限界をはるかに超えてしまいます。 

反転によって新しい小さな数字が作成される場合、微妙なエッジケースが現れます。 たとえば、120 が 21 になると、もともと存在しなかった低い範囲の数値が突然利用可能になる可能性があります。 もう 1 つのエッジ ケースは、反転後に異なる数値が同じ値に崩壊する場合です。これは、ターゲット mex までのすべての整数を「カバー」できるかどうかに影響する可能性があります。 

単純な間違いは、元のセットのみを考慮する必要があると考えることです。 たとえば、配列が [10] の場合、mex は 0 ですが、反転すると 1 になり、小さい値の可用性が変わります。 これは、反転によってゼロから始まる最初のセグメントのカバレッジを直接シフトできることを示しています。 

## アプローチ

 ブルートフォース手法では、各数値を反転するかどうかの 2^n 個の選択肢をすべて試し、結果の配列を計算し、その mex を計算します。 各 mex 計算は O(n) であるため、合計の複雑さは O(n · 2^n) となり、n = 30 の場合でも実行不可能です。 

より構造化されたビューは、視点を反転することです。 最終的な構成を決定する代わりに、方向を選択した後に配列に含めることを保証できる 0 から上のどの整数を尋ねます。 mex を最大化するには、0 から k − 1 までのすべての整数が、元の形式または反転された形式のいずれかを使用して、少なくとも 1 つの要素によって形成でき、k 自体は形成できないことを保証したいと考えます。 

これにより、問題は整数を対象とした問題に変換されます。各配列要素は、最大 2 つの数値である小さな候補セットに寄与します。 要素ごとに 1 つのオプションを選択し、ゼロから始まる最初のカバーされる整数セグメントの長さを最大化したいと考えています。 

重要な観察は、ゼロから始まる連続した範囲の数値のみが重要であるということです。 整数 x の構築に失敗した場合、mex は正確に x となり、x を超えるものは無関係になります。 

整数を昇順に処理します。 各ターゲット値 x について、x を直接または反転によって表すことができる未使用の配列要素が存在するかどうかを確認します。 「はい」の場合、そのような要素の 1 つを x をカバーするために割り当て、それをさらなる検討から除外します。 そうでない場合は、停止します。 xはメキシコです。 

この貪欲な戦略が機能するのは、各整数 x が要件において独立しているためです。x が必ず出現すると決定すると、x に使用される要素は将来の値には必要なくなり、代入を遅らせても利用できる柔軟性が低下するだけです。

 ## アルゴリズムのチュートリアル

1. 配列内の各数値について、その逆桁形式を計算します。 両方の値を、その要素に関連付けられたオプションとして保存します。 これが必要なのは、各要素が 1 つの値しか提供できないためですが、両方の可能性を知っておく必要があります。 
2. すべての要素を構造に挿入すると、値 x がまだ使用されていない要素でカバーできるかどうかをすばやく見つけることができます。 一般的な選択は、ハッシュ マップまたはマルチセットを使用して値ごとにインデックスをグループ化することです。 
3. x = 0 から開始して上に移動します。 各 x について、x を元の値または反転した値として生成できる未使用の要素を探します。 必要なのは存在だけですが、選択した要素を使用済みとしてマークできる必要もあります。 
4. x を生成できる要素がない場合は、直ちに停止し、x を mex として出力します。 
5. そのような要素が存在する場合は、それを x に代入し、削除のマークを付けて、後の値に再利用できないようにします。 

この貪欲な割り当てが有効である理由は、要素を整数 x を表すためにコミットすると、それをより大きな値に使用しても x を回復するのに決して役立たないためです。これは、mex が最初に小さい値が欠落していることに厳密に依存しているためです。 

### なぜ効果があるのか

 このアルゴリズムは単純な不変条件を維持します。つまり、x − 1 の処理後、[0, x − 1] 内のすべての整数は、素な要素を使用して実現可能であることが保証されます。 各ステップは、このプレフィックスを 1 つ拡張するか、最初のギャップで停止します。 mex は最初に欠落している整数として定義されているため、x をスキップすると恒久的に欠落したままになるため、最適解は同じ最初のギャップでも失敗するはずです。 元の形式と逆の形式を選択できる機能は、各要素の候補セットを拡大するだけであり、プレフィックスの構築時に各要素を最大 1 回使用できるという事実は変わりません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def rev(x: int) -> int:
    return int(str(x)[::-1])

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    from collections import defaultdict, deque

    # map value -> deque of indices that can produce it
    pos = defaultdict(deque)
    used = [False] * n

    for i, x in enumerate(a):
        pos[x].append(i)
        rx = rev(x)
        pos[rx].append(i)

    x = 0
    while True:
        if x not in pos:
            break

        # find an unused element that can produce x
        found = -1
        dq = pos[x]
        while dq:
            i = dq.popleft()
            if not used[i]:
                found = i
                break

        if found == -1:
            break

        used[found] = True
        x += 1

    print(x)

if __name__ == "__main__":
    solve()
```このソリューションは、各値からインデックスへのマッピングを構築し、直接または反転によってマッピングを生成します。 ターゲットの整数 x を実現しようとするとき、未使用の要素がいずれかの形式でその整数にマップできるかどうかだけを気にするだけであるため、これは非常に重要です。 

貪欲ループは x を段階的に増加させます。 各 x に対して、x を表すことができる新しい要素の割り当てを試みます。 一度割り当てられると、その要素は使用された配列を介して今後のすべての考慮事項から削除されます。 これにより、異なる mex 位置間で要素が再利用されることがなくなります。 

微妙な点は、反転を繰り返し再計算しないことです。 代わりに、両方向を一度事前計算します。 これにより、検索ごとにトランジション O(1) が償却されます。 

## 実用的な例

 配列 [10, 0, 2, 3, 4] について考えてみましょう。 

反転を計算します。10 が 1 になり、その他は変化しません。 

x の割り当てを追跡します。 

| × | x の候補 | 選択されたインデックス | 使用される要素 |
 | --- | --- | --- | --- |
 | 0 | {0} | 0 | {0} |
 | 1 | {10} | 10 | {0,10} |
 | 2 | {2} | 2 | {0,10,2} |
 | 3 | {3} | 3 | {0,10,2,3} |
 | 4 | {4} | 4 | {0,10,2,3,4} |
 | 5 | なし | 停止 | |

 これは、0 から 4 までのすべての値をカバーできるため、mex が 5 になることを示しています。 

次に [12, 21, 3] を考えてみましょう。 

逆転：12→21、21→12、3→3。 

| × | 候補者 | 選ばれた | 中古 |
 | --- | --- | --- | --- |
 | 0 | なし | 停止 | |

 どちらの形式でも 0 を生成できる要素はないため、 mex はすぐに 0 になります。 

これは、小さな値の表現がまったく存在しない場合には反転が役に立たないことを示しています。

 ## 特殊なケース

 特殊なケースとしては、反転が中間値の生成に役立つだけで、必要なプレフィックスの生成に役立つわけではない場合です。 [10, 20, 30] のような入力の場合、反転すると [1, 2, 3] が得られ、突然 mex は最初に 0 を順番に代入できるかどうかに完全に依存するようになります。 10 も 20 も 30 も、その反転も 0 を与えないため、アルゴリズムは x = 0 で正しく停止します。 

もう 1 つの特殊なケースは、数字が繰り返されることです。 [10, 10, 1] の場合、どちらの 10 も反転によって 1 を生成できますが、使用できるのは 1 つだけです。 貪欲な構造により、1 つの 10 が割り当てられると、必要に応じて後の値に 2 番目の 10 が使用可能になり、プレフィックス構築の正確さが維持されます。 

最後のエッジ ケースは、同じ x に対して複数の表現が存在する場合です。 mex は存在のみを必要とし、多重度はカウントしないため、アルゴリズムは余分な候補を安全に破棄します。
