 ## 解決策
 ## 問題の理解

 ソートされたリストが与えられます$nk$に分割するよう求められました。$k$それぞれが正確に含むグループ$n$要素。 分割が完了したら、並べ替えられた順序で中央の上の位置を使用して各グループの中央値を計算します。これらすべての中央値の合計ができるだけ大きくなるようにします。 

重要な制約は、グループ内で入力配列をコストなしで自由に並べ替えることはできないが、グローバル配列はすでにソートされていることです。 このタスクは完全に、選択された中央値の位置ができるだけ大きくなるように、連続する値をグループに分割する方法に関するものです。 

制約により、最大で$2 \cdot 10^5$すべてのテスト ケースにわたる要素の合計。 これにより、考えられるすべてのパーティションをシミュレートしたり、サブセットを繰り返し並べ替えたりしようとするソリューションは即座に排除されます。 どのようなアプローチでも、基本的にはテスト ケースごとの配列サイズが線形であるか、最悪の場合でも線形である必要があります。$O(nk \log(nk))$ただし、配列はすでにソートされているため、ソートは不要です。 

微妙なエッジケースが現れるのは、$n = 1$。 この状況では、すべての要素が独自の中央値になるため、答えは配列の合計になります。 グループの「バランス」をとろうとする単純なグループ化戦略では、この単純化を簡単に見逃す可能性があります。 

もう 1 つの明白ではない例外的なケースが次の場合に発生します。$k = 1$。 この場合、グループは 1 つだけなので、答えは単純に配列全体、つまりインデックスの要素の中央値になります。$\lceil nk/2 \rceil$。 

主な問題は、両方の場合に発生します。$n$そして$k$中央値が可能な最大の利用可能な値から得られるように要素を分散する方法を決定する必要があるためです。 

## アプローチ

 ブルートフォースについて考えるなら、ソートされた配列を次のように分割するためにあらゆる方法を試みるでしょう。$k$サイズのグループ$n$。 たとえ順序を維持することに限定したとしても、位置を選択する方法の数は、多項係数のオーダーで組み合わせになります。 のために$nk \le 2000$、これはすでに実行不可能です。 のために$2 \cdot 10^5$、それはまったく不可能です。 

重要な観察は、配列がソートされており、完全なグループ構造ではなく中央値のみを考慮していることです。 各サイズのグループ内$n$、中央値は位置の要素です$\lceil n/2 \rceil$。 したがって、各グループは 1 つの「重要な」要素に貢献し、残りは実現可能性を保証する制約にすぎません。 

これは、選択するという観点から考える必要があることを示唆しています$k$配列からの中央位置。 最大値から順に貪欲にグループを構築することを想像すると、構造がより明確になります。中央値を最大化するには、各中央値をできるだけ大きくする必要がありますが、各グループを完成させるには、その周囲に他の要素を「費やす」必要があります。 

各中央値が効果的に消費するのは、$n - 1$サポート要素。 中央値を最大化したいので、利用可能な最大の要素を中央値として割り当てる必要がありますが、有効なグループを形成するのに十分な要素が残っていることを確認する必要があります。 

最大値から処理する場合、中央値を選択するたびに、グループを完成させるために十分な要素をスキップする必要があります。 最適なパターンは決定論的であることがわかります。1 つの要素を中央値として繰り返し取得し、その後破棄します。$n - 1$有効なグループの形成を妨げる要素。 

同様に、配列の末尾から作業して、次のように決定される特定のオフセットから始まる 2 つおきの要素を選択できます。$n$。 選択した中央値間の間隔は正確に$n - 1$ですが、ソートされた構造ではグループが重複しているため、効果的なステップは次のようになります。$n - 1$右から左にスキャンする場合、選択された連続する中央値の間で要素がスキップされます。 

したがって、最適な解決策は次のことを選択することになります。$k$ソートされた配列から一定の間隔で要素を取り出します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (すべてのパーティション) | 指数関数 | 高い | 遅すぎる |
 | 最適な貪欲な選択 |$O(nk)$|$O(1)$番外編 | 承認済み |

 ## アルゴリズムのチュートリアル

 1. コンピューティング$m = \lceil n/2 \rceil$、これはグループ内の中央位置です。 これにより、並べ替えたときに中央値がグループの先頭からどのくらい離れているかがわかります。 
2. 可能な限り、より大きな値が中央値に寄与する必要があるため、グローバルソート配列の最後から作業します。 
3. インデックスから始める$nk - 1$、サイズを段階的に左に移動しながら中央値として要素を選択します$n - m + 1$または、もっと単純に、グループ化制約から派生したパターンによって、中央値を 1 つ選択するたびに、スキップします。$n - m$同じまたは前のグループに属している必要がある要素。 

クリーンな実装では、これがさらに簡素化されます。後方に移動して、すべての項目を選択します。$(n - m + 1)$- 特定のオフセットから始まる 番目の要素。 
4. 正確に収集する$k$そういった要素があるので、$k$グループ、したがって$k$中央値。 
5. これらの選択された要素を合計し、結果を出力します。 

微妙な部分は、グループを明示的に構築していないことです。 代わりに、グループ化によって課せられる制約をシミュレートします。各中央値には、そのグループを満たすのに十分な要素がその右側 (ソート順) になければなりません。 

### なぜ効果があるのか

 不変条件は、中央値を選択した後、残りのすべての中央値に対して完全なグループを形成するのに十分な未使用の要素を常に残すということです。 配列はソートされているため、中央値を右から取得するとその値が最大化され、必要な数の要素を正確にスキップすることで、中央値以外の位置で大きな要素を無駄にすることなく実現可能性が保証されます。 より小さい中央値を先に選択するような偏差があると、合計が直接減少するか、さらに大きな要素が非中央値スロットに強制的に挿入されるため、合計を増やすことができません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        
        # median position in each group (1-indexed)
        m = (n + 1) // 2
        
        # step size between useful medians when scanning from right
        step = n - m + 1
        
        # start from the last element
        idx = len(a) - step
        
        ans = 0
        
        for _ in range(k):
            ans += a[idx]
            idx -= step
        
        print(ans)

if __name__ == "__main__":
    solve()
```この実装は、ソートされた配列に対するインデックス演算のみを処理します。 重要なのは、選択した中央値間の正しい間隔を計算することです。 変数`m`中央値が各グループ内のどこにあるかを決定し、そこから、選択した各中央値が重複せずに有効なグループに属するためにスキップする必要がある要素の数を導き出します。 

逆方向走査により、利用可能な最大の有効な候補が常に選択されます。

 ## 特殊なケース

 いつ$n = 1$、すべての要素は独自のグループであり、独自の中央値でもあります。 このアルゴリズムでは、ステップ 1 ですべての要素を選択します。インデックス演算は引き続き機能します。$m = 1$与える`step = n - m + 1 = 1`したがって、単純に配列全体を合計します。 

いつ$k = 1$、要素を 1 つだけ選択します。 開始インデックスは、配列全体の正しい中央位置になります。`step`最初に選択したインデックスをグローバル中央位置に合わせます。 このアルゴリズムは、ソートされた配列の中心要素を効果的に返します。 

すべての値が等しい場合、どのグループ化でも同じ中央値が得られます。 このアルゴリズムでは依然として等間隔の要素が選択されますが、分割に関係なく合計は一貫しており、縮退下でも正確であることが確認されます。 

境界ケースでは、$n$大きくて、$k$が小さい場合、選択された各中央値は、周囲に有効なグループを形成するのに十分な要素を暗黙的に予約するため、ステップ サイズによって要素が過剰に消費されることがなくなります。
