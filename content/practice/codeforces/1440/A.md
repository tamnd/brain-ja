 ## 解決策
 ## 問題の理解

 バイナリ文字列とそれに対する 2 つの支払い方法が与えられます。 1 つ目は直接購入です: すべてのキャラクター`0`費用`c0`コインとすべてのキャラクター`1`費用`c1`コイン。 2 つ目は変更です。購入する前に、文字を反転したり、向きを変えたりすることができます。`0`の中へ`1`または`1`の中へ`0`、各フリップのコスト`h`コイン。 

目標は、テスト ケースごとに、フリップの総コストと最終文字列の購入コストを最小限に抑えるために実行するフリップの回数を決定することです。 

文字列の長さは最大 1000 で、テスト ケースは最大 10 個であるため、テスト ケースごとに 2 次スキャンまたは線形スキャンで十分です。 すべてのフリップの組み合わせの指数関数的シミュレーションやキャラクターごとのシミュレーションは不要です。 

単純な間違いは、グローバル バランスを考慮せずにキャラクターごとにフリップを貪欲に扱うことから発生します。 たとえば、次の場合`c0`よりもはるかに大きいです`c1`、多くを反転すると有益かもしれません`0`に入る`1`たとえ各フリップが個別に高価に見えたとしても、最終的なキャラクターごとのコストの差がフリップ コストを上回る可能性があるためです。 

もう 1 つの微妙な問題は、現在「高価」な文字を常に反転する必要があると仮定していることです。 反転によって他の場所の総コストが増加する形で分布が変更される場合、これは失敗します。 

## アプローチ

 強引なアイデアは、可能なすべてのポジションのサブセットを反転してみることです。 サブセットごとに、それらの文字を反転するコストを計算し、結果の文字列を購入するコストを計算します。 各位置は反転することも反転できないこともできるので、これは次のようになります。`2^n`テストケースごとの可能性は大きすぎます。`n = 1000`。 

重要な観察は、その数を決定した後、`0`最終文字列に必要な場合、正確な位置は重要ではありません。 重要なのは、0 と 1 の数だけです。 必要なゼロの数がわかっていれば、それを達成するために元の文字列から何回フリップする必要があるかを計算できます。 

文字列に次の内容を含めます`z`ゼロと`o = n - z`もの。 最後の文字列を次のようにしたいとします。`k`ゼロ。 その状態に到達するには、次のように反転する必要があります。 

-`(z - k)`ゼロが 1 になる場合`k <= z`-`(k - z)`1 を 0 に変換する場合`k > z`したがって、考えられる最終的なゼロの数ごとに、`k`から`0`に`n`、必要なフリップの数を計算し、次の値を掛けます。`h`、購入コストを直接計算します。 

これにより、問題は文字列の考えられるすべての最終構成をチェックすることになり、これは次のように線形になります。`n`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース サブセット | O(2^n · n) | O(n) | 遅すぎる |
 | すべての最終カウントを試す | テスト ケースごとに O(n^2) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 元の文字列に 0 と 1 がいくつあるかを数えます。 これにより、位置を必要とせずに文字列のベースラインの説明が得られます。 
2. 可能なすべての値を反復処理します。`k`、 どこ`k`最終文字列内のゼロの数を表します。 各値は完全なターゲット構成を表します。 
3. それぞれについて`k`、何回フリップが必要かを計算します。 もし`k < z`、反転してゼロを減らします`(z - k)`ゼロを 1 にします。 もし`k > z`、反転してゼロを増やします`(k - z)`1 を 0 にします。 フリップの合計は`|z - k|`。 
4. を乗算してフリップをコストに変換します。`h`。 
5. 最終的な購入コストを次のように計算します。`k * c0 + (n - k) * c1`。 
6. フリッピングコストと購入コストを追加して、このターゲットの合計コストを取得します`k`。 
7. 全体的に最小限のものを取る`k`。 

重要な考え方は、考えられるすべての最終文字列はゼロの数によって一意に表現され、状態間の遷移は位置ではなくカウントにのみ依存するということです。 

### なぜ効果があるのか

 どの時点でも、問題の状態は存在するゼロの数によって要約できます。 キャラクターを反転するとこのカウントが 1 つだけ変更され、固定金額がかかります`h`。 最終的なコストは配置ではなくカウントのみに依存するため、最適な戦略は最終的なカウントに対応する必要があります。`k`。 そういったものを徹底的に評価することで、`k`、明示的にフリップをシミュレートせずに、考えられるすべての結果をカバーします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, c0, c1, h = map(int, input().split())
    s = input().strip()

    z = s.count('0')
    o = n - z

    ans = 10**18

    for k in range(n + 1):
        flips = abs(z - k)
        cost = flips * h + k * c0 + (n - k) * c1
        ans = min(ans, cost)

    print(ans)
```コードはまず文字列を単一の統計値、つまりゼロの数に減らします。 次に、その統計によってのみ定義される、考えられるターゲット構成をすべて列挙します。 表現`abs(z - k)`フリップごとに 0 カウントが 1 だけ変更されるため、必要な最小数のフリップがキャプチャされます。 

ループオーバー`k`安全なので`n ≤ 1000`したがって、テスト ケースごとに最大 1000 の候補州がチェックされます。

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = io.StringIO()

    sys.stdout = output

        print(ans)

    return output.getvalue().strip()

 ## 特殊なケース

 文字列が均一な場合、次のようになります。`00000`、アルゴリズムはすべての値を評価します。`k`しかし、逸脱があると、それを補うほど購入コストが削減されずにフリップコストが増加することがすぐにわかります。 のために`k = 5`、フリップは5になりますが、購入コストは向上しません。`c0`キャラごとに決まってます。 

コストを反転するとき`h`が非常に大きい場合、最適解は常にどちらかに対応します。`k = z`(反転なし) または最も近い境界。 列挙には当然このケースも含まれます。`k = z`フリップコストがゼロになります。 

いつ`c0`そして`c1`大きさが逆転すると、線形コスト項が支配的となり、一度フリップ ペナルティを上回るため、アルゴリズムは最適値をより安価なキャラクターへの完全な変換に向けて自動的にシフトします。`n * |c0 - c1|`を超える`h`。
