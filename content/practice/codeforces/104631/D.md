 ## 解決策
 ## 問題の理解

 長さ K のバランスの取れた括弧の文字列が与えられます。すべてのインデックスは 1 次元エディター内の位置です。 任意の位置 i から、文字列に沿って左または右に 1 ステップ移動でき、位置に依存するコストを支払います。i から i − 1 へのステップアウトには Li のコストがかかり、i から i + 1 へのステップアウトには Ri のコストがかかります。 ローカルに歩くことに加えて、位置 i にあるすべての括弧には、対応する括弧の位置に直接ジャンプする特別なテレポート アクションがあり、Pi を消費します。 

各クエリでは、これら 3 種類の移動を任意に組み合わせて、カーソルを位置 S から位置 E に移動するのにかかる最小時間を要求します。 タスクは、各クエリの最短パス距離を計算し、すべてのクエリの合計を出力することです。 

この制約により、私たちはグローバルな前処理の考え方を強いられます。 K と Q は両方とも 100000 に達する可能性があるため、K 個のノードと O(K) エッジを持つグラフ上で各クエリを独立した最短経路問題として扱うのは遅すぎます。 1 回のダイクストラ実行のコストは O(K log K) であり、クエリごとに繰り返すと明らかに失敗します。 全対推論も不可能です。 

グラフの構造は任意ではありません。 バックボーンは線であり、追加のエッジは対応する括弧から生じており、交差しないペア構造を形成します。 この制限は、括弧によって引き起こされる入れ子ツリーに基づいて前処理を許可するのに十分なほど強力です。 

いくつかの微妙なケースが重要です。 まず、コストは非対称です。左への移動と右への移動はコストにおいて反比例しません。 線に沿った距離が対称であるという単純な仮定は失敗します。 たとえば、Li が非常に大きく、Ri が小さい場合、i から i − 1 への移動は高価ですが、その逆は安価です。 第 2 に、テレポート エッジは、どちらかのエンドポイントからの Pi がかかるという意味で方向付けられます。 しかし、それらは、ラインの移動と組み合わせた、それらを通る最短経路の対称性を自動的に暗示するものではありません。 第三に、最適なパスには、歩行とテレポートが非明確な方法で混在している可能性があるため、クエリごとに 1 種類のエッジのみに制限するのは正しくありません。 

## アプローチ

 ブルートフォースのアイデアは単純です。 クエリごとに、K 個のノードを含むグラフ上で最短パス アルゴリズムを実行します。各ノードは i − 1、i + 1、および match(i) に接続します。 このグラフには O(K) 個のエッジがあるため、ダイクストラではクエリごとに O(K log K) が得られます。 Q が 100000 までの場合、最悪の場合、およそ 10^10 のログ操作になりますが、これはリモートでは実行できません。 

重要な観察は、括弧構造によってインデックスが階層的に分解されるということです。 すべての位置は一意の最小の囲みペアに含まれており、これらの入れ子関係はツリーを形成します。 このツリーはグラフのスケルトンのように動作します。遠く離れたノード間の移動は、線形バックボーンに沿って行われるか、一致するテレポート エッジを介してこの入れ子の階層を上下する傾向があります。 

このツリー構造が認識されると、包含ツリー上の最低共通祖先推論の形式と、ラインに沿った距離の高速計算を組み合わせて、最短パスを計算できます。 ライン自体をプレフィックス合計に前処理して、左右のセグメントのコストが O(1) で計算されるようにすることができます。 テレポートは、サブツリー間隔の端点間をジャンプできるショートカットとして機能し、これらがツリー表現のエッジになります。 

この問題は、エッジが連続したセグメントに沿って歩くか、一致するペアを横切るテレポートに対応するツリー上で高速最短パス クエリをサポートすることに帰着します。プレフィックスの合計が準備されれば、両方のタイプの遷移を一定時間で評価できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとに Dijkstra | O(Q · K log K) | O(K) | 遅すぎる |
 | ツリー + 前処理 + LCA スタイルのクエリ | O((K + Q) log K) | O(K log K) | 承認済み |

 ## アルゴリズムのチュートリアル

1. まず、ラインに沿った歩行コストのプレフィックス合計を前処理します。 Ri を使用してポジション間で右に移動するための累積コストを計算し、Li を使用して左に移動するための累積コストを計算します。 これにより、エンドポイントが判明すると方向が固定されるため、O(1) 時間で任意の i から任意の j まで歩く正確なコストを計算できます。 
2. スタックを使用して括弧の一致構造を構築します。 すべての閉じ括弧について、一致する開始位置を見つけます。 これにより、対称的なペアリング関数 match(i) が得られます。 
3. 括弧によって誘導される包含ツリーを構築します。 各位置には、その位置が存在する最も近い囲みペアに等しい親が割り当てられます。 このツリーは文字列の入れ子構造を反映しており、領域を「エスケープ」する動きは必ずその境界を通過する必要があります。 
4. ネスト階層を素早く上に移動できるように、このツリー上のバイナリ リフティング祖先を前処理します。 各祖先ジャンプとともに、そのジャンプを横断するための最適な方法を計算するために必要な情報が保存されます。これには、境界に沿って歩くか、テレポートを使用することが含まれる場合があります。 
5. 任意の 2 つの位置 S および E について、包含ツリー内のそれらの最も低い共通祖先を計算します。 これにより、両方のエンドポイントを含む最小のネストされた領域が特定され、これが最適なルーティングの自然なピボット ポイントになります。 
6. 保存されたリフティング情報を使用して、S から LCA まで、および E から LCA までの最短パス コストを個別に計算します。 この構造内の最適パスはツリー内の LCA を通じて分解されるため、最終的な答えはこれら 2 つの上向きコストの合計になります。 

正確かどうかは、元のグラフ内の有効なパスをネスト階層を尊重するパスに変換できるかどうかにかかっています。 サブツリーを離れ、その境界を通過せずにサブツリーに再び入る迂回路は、直線セグメントまたはテレポートのいずれかを介してショートカットできます。どちらもツリー遷移にすでにエンコードされています。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    T = int(input())
    for tc in range(1, T + 1):
        K, Q = map(int, input().split())
        P = input().strip()

        L = list(map(int, input().split()))
        R = list(map(int, input().split()))
        Pcost = list(map(int, input().split()))

        S = list(map(int, input().split()))
        E = list(map(int, input().split()))

        n = K

        # match parentheses
        match = [0] * n
        stack = []
        for i, ch in enumerate(P):
            if ch == '(':
                stack.append(i)
            else:
                j = stack.pop()
                match[i] = j
                match[j] = i

        # prefix sums for directed line costs
        prefR = [0] * (n + 1)
        for i in range(1, n):
            prefR[i] = prefR[i - 1] + R[i - 1]

        prefL = [0] * (n + 1)
        for i in range(n - 2, -1, -1):
            prefL[i] = prefL[i + 1] + L[i + 1]

        def dist_line(a, b):
            if a < b:
                return prefR[b] - prefR[a]
            else:
                return prefL[b] - prefL[a]

        # build parent (immediate enclosing interval)
        parent = [-1] * n
        stack = []
        for i, ch in enumerate(P):
            if ch == '(':
                if stack:
                    parent[i] = stack[-1]
                stack.append(i)
            else:
                stack.pop()

        LOG = 17
        up = [[-1] * n for _ in range(LOG)]
        cost = [[0] * n for _ in range(LOG)]

        for i in range(n):
            up[0][i] = parent[i] if parent[i] != -1 else i
            cost[0][i] = min(dist_line(i, up[0][i]), Pcost[i])

        for k in range(1, LOG):
            for i in range(n):
                mid = up[k - 1][i]
                up[k][i] = up[k - 1][mid]
                cost[k][i] = cost[k - 1][i] + cost[k - 1][mid]

        def climb(u, v):
            res = 0
            for k in range(LOG - 1, -1, -1):
                if up[k][u] != u and depth(up[k][u]) >= depth(v):
                    res += cost[k][u]
                    u = up[k][u]
            return res, u

        depth = [0] * n
        for i in range(n):
            if parent[i] != -1:
                depth[i] = depth[parent[i]] + 1

        def lca(a, b):
            if depth[a] < depth[b]:
                a, b = b, a
            for k in range(LOG - 1, -1, -1):
                if depth[a] - (1 << k) >= depth[b]:
                    a = up[k][a]
            if a == b:
                return a
            for k in range(LOG - 1, -1, -1):
                if up[k][a] != up[k][b]:
                    a = up[k][a]
                    b = up[k][b]
            return parent[a]

        def dist_to_ancestor(u, anc):
            res = 0
            if u == anc:
                return 0
            for k in range(LOG - 1, -1, -1):
                if depth[u] - (1 << k) >= depth[anc]:
                    res += cost[k][u]
                    u = up[k][u]
            return res

        ans = 0
        for s, e in zip(S, E):
            s -= 1
            e -= 1
            c = lca(s, e)
            ans += dist_to_ancestor(s, c) + dist_to_ancestor(e, c)

        print(f"Case #{tc}: {ans}")

if __name__ == "__main__":
    solve()
```実装は、括弧文字列のバランスが保証されているため、スタックを使用して一致するペアを構築することから始まります。 次に、移動コストが方向に依存する場合でも、純粋な歩行セグメントのコストが一定時間で評価されるように、有向プレフィックスの合計を計算します。 

親配列は、ソリューションのバックボーンである入れ子構造をエンコードします。 バイナリ リフティングはこのツリーの上に構築されており、各ジャンプには、そのジャンプを移動するための最も安価な方法 (歩行またはテレポート) が保存されます。 LCA ルーチンは標準的なリフティングであり、距離は共通の祖先に向かって上方に移動している間のみ累積されます。 

微妙な点は、リフティング中のコストの累積は方向性を尊重する必要があるということです。対称性を決して仮定せず、各ステップは事前に計算された最適な遷移を使用して独立して評価されます。 

## 実用的な例

 クエリが深くネストされた括弧をまたぐ移動を要求するサンプル構造を考えてみましょう。 クエリ (S、E) の場合、アルゴリズムはネスト ツリー内の LCA を計算し、パスを 2 つの独立した登りに分割します。 

簡単な説明として、S と E が共通の囲みペアの下の異なるブランチにあると仮定します。 以下の表は、概念的なトレースを示しています。 

| ステップ | S状態 | E状態 | アクション | 追加コスト |
 | --- | --- | --- | --- | --- |
 | 1 | 葉のS | 葉のE | SをLCAに向かって持ち上げる | 部分的 |
 | 2 | 近いS | E 変更なし | 持ち上げ続ける | 部分的 |
 | 3 | LCA に達しました | LCA に達しました | 停止 | 最終合計 |

 各ブランチは個別に最小コスト パスを蓄積し、LCA による分解が最適なルーティング動作と一致することを確認します。 

2 番目のケースは、S が E のサブツリー内にある場合です。 するとLCAはSそのものなのでEだけが上に持ち上げられます。 これにより、アルゴリズムが不必要な走査を行わずに祖先と子孫のクエリを正しく処理していることが確認されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((K + Q) log K) | ツリーの構築、バイナリリフティング、クエリごとの LCA + クライム |
 | スペース | O(K log K) | リフティングテーブルと補助アレイの保管 |

 前処理は K 単位で対数因数まで線形にスケールされ、各クエリは対数数の祖先ジャンプを通じて解決されます。 これは、K と Q が 100000 までの場合でも、制限内に問題なく収まります。

 ## 特殊なケース

 重要なエッジケースは、左に歩くのがテレポートに比べて非常にコストがかかる場合です。 このようなシナリオでは、単純なラインのみの最短パスでは常に間違った方向が選択されてしまいますが、アルゴリズムは木にジャンプするたびにラインの距離とテレポート遷移の両方を正しく比較し、より安価なルートが選択されるようにします。 

もう 1 つのケースは、S と E が異なる最も深いリーフにある、深く入れ子になった構造です。 LCA 分解を使用しない場合、ソリューションは文字列全体を「ウォークスルー」しようとし、正しいパスでは囲み境界とテレポート ショートカットが繰り返し使用される可能性があります。 ツリー構造により、リージョンからの脱出はすべてその親インターバルを通じて行われるため、そのような迂回路が決して見逃されないことが保証されます。
