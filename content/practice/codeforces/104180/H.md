 ## 解決策
 ## 問題の理解

 非常に大きな長方形のキャンバス、概念的には最大の座標を持つグリッドが与えられます。$10^9 \times 10^9$。 このキャンバス上で、ボブはすでに軸に沿った長方形をいくつか描いています。 これらの四角形は互いに重なり合わないため、ペイントされた各セルは最大でも 1 つの四角形に属します。 

塗装が完了すると、一連の垂直柱が雨によって流されます。 洗浄された各列は、列インデックスが指定された値のいずれかに一致する、ペイントされたすべてのセルを削除します。 タスクは、洗浄された列にあるすべての塗装されたセルを削除した後に残る塗装されたセルの数を計算することです。 

入力は、左下隅と右上隅で記述された重なり合わない四角形と、破棄される列インデックスのリストで構成されます。 出力は、それらの列内のすべてのペイントされたセルを削除した後に残っているペイントされた領域の合計です。 

制約により、最大で$2 \cdot 10^5$長方形と$2 \cdot 10^5$洗浄された列、座標は次のように大きくなる可能性があります$10^9$。 これにより、グリッドベースのシミュレーションが即座に除外されます。 セルごとまたは列ごとの情報を明示的に保存することさえ不可能です。 有効な解決策では、問題を間隔または集計カウントでの操作に減らす必要があります。理想的には、$O((N + M) \log N)$または$O(N + M)$。 

微妙な点は、長方形が互いにつながっていないことです。 これにより、重なり合う形状全体での座標圧縮の必要性がなくなり、各長方形の寄与を独立して安全に合計できることが保証されます。 

エッジ ケースは、列が四角形とどのように相互作用するかによって発生します。 

実際には、幅がゼロの長方形が発生する可能性があります。$c_1 = c_2$、単一の列ストリップを意味します。 その列を洗浄すると、長方形全体が消えます。 

例:

 入力:```
1 1
3 1 3 5
3
```出力：```
0
```単純なセルごとの解釈では、縮退した四角形を考慮せずに正の幅を仮定すると、依然として正しくカウントされない可能性があります。 

もう 1 つのエッジ ケースは、洗浄された列がどの長方形とも交差しない場合です。 答えは、長方形の面積の合計と等しくなります。 

例：```
1 2
1 1 3 3
10
20
```出力：```
9
```最後に、多くの四角形が同じ列範囲に重なっているが、空間的にはばらばらである場合、二重カウントを回避する必要があります。二重カウントは問題ステートメントによって保証されていますが、処理が列ごとに不注意に行われると誤って再導入されやすくなります。 

## アプローチ

 直接的なアプローチでは、すべての長方形を単位セルに拡張し、洗浄された列を差し引きます。 これは直ちに実行不可能です。 単一の長方形でカバーできる範囲は次のとおりです。$10^{18}$最悪の場合、セルが減少し、四角形ごとに列を反復処理しても、次のように劣化します。$O(N \cdot \text{width})$。 

最初に観察した方が良いのは、洗浄は行ではなく列のみに影響を与えるということです。 指定された四角形の内部では、すべての列がその高さをペイント領域全体に正確に反映します。 したがって、各長方形は、その列間隔全体に均一に適用される垂直高さの寄与として見ることができます。$[c_1, c_2]$。 問題は、各長方形について、削除されたセットに含まれていない列の数を計算し、その高さを乗算することです。 

残りの問題は、削除された列のセットが大きく、恣意的であることです。 列ごとのメンバーシップの確認が遅すぎます。 代わりに、削除された列を並べ替え、二分探索またはポインター スイープを使用して、四角形の間隔と削除されたセットの間の交差をカウントします。 

長方形は重なり合わないので、それぞれを独立して処理できます。 各四角形について、ソートされた配列の二分探索を使用して、その水平範囲内に削除された列の数を数えます。 これを合計幅から引くと、生き残った列が得られます。 

これにより、問題がソートに減ります。$M$コラムと回答$N$範囲カウントクエリ。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (セル/列シミュレーション) |$O(N \cdot W)$|$O(W)$| 遅すぎる |
 | 最適 (四角形ごとのソート + 二分検索) |$O((N+M)\log M)$|$O(M)$| 承認済み |

 ## アルゴリズムのチュートリアル

 この問題を、各四角形内に「良好な」列がいくつ残っているかを数えるという問題に変換します。 

1. すべての洗浄済みカラムインデックスを読み取り、並べ替えます。 二分探索を使用して任意の区間内にある嘘の数を効率的に数えるためには、並べ替えが必要です。 並べ替えを行わないと、各クエリですべての列をスキャンする必要があります。 
2. 最終的な答えをゼロに初期化します。 各長方形は重なり合わないため、各長方形からの寄与を個別に蓄積します。 
3. 各長方形について、その垂直方向の高さを次のように計算します。$r_2 - r_1 + 1$。 これは、各有効な列がその四角形内でどの程度寄与しているかを表します。 
4. 長方形の水平スパン内の列の合計数を決定します。$c_2 - c_1 + 1$。 
5. 二分探索を使用して、洗浄されたカラムの数を数えます。$[c_1, c_2]$。 これは、最初のインデックスを見つけることによって行われます$\ge c_1$そして最初のインデックス$> c_2$、そして 2 つの位置を減算します。 
6. 合計カラムから洗浄されたカラムを減算して、長方形内の生き残ったカラムを取得します。 
7. 残っている列に長方形の高さを乗算し、答えに加算します。 

各四角形は独立して処理されるため、二重カウントや領域間の干渉の危険はありません。 

### なぜ効果があるのか

 主要な構造特性は、長方形が重なり合わないことであり、これにより領域が加算されます。 各長方形は細胞の長方形ブロックに寄与し、洗浄は列に対して独立して作用し、すべての長方形にわたって垂直スライス全体を均一に除去します。 これは、セルの存続は、そのセルが属する四角形ではなく、その列インデックスのみに依存することを意味します。 その結果、削除された列のグローバル セットをその間隔に投影し、高さによってスケーリングすることによって、各長方形を評価できます。 二分探索ステップでは、この投影サイズを正確に計算します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    
    rects = []
    for _ in range(n):
        r1, c1, r2, c2 = map(int, input().split())
        rects.append((r1, c1, r2, c2))
    
    washed = [int(input()) for _ in range(m)]
    washed.sort()
    
    import bisect
    
    ans = 0
    
    for r1, c1, r2, c2 in rects:
        height = r2 - r1 + 1
        total_cols = c2 - c1 + 1
        
        left = bisect.bisect_left(washed, c1)
        right = bisect.bisect_right(washed, c2)
        
        bad_cols = right - left
        good_cols = total_cols - bad_cols
        
        if good_cols > 0:
            ans += good_cols * height
    
    print(ans)

if __name__ == "__main__":
    solve()
```この解決策は、範囲を効率的にクエリできるように、洗浄されたすべての列を並べ替えることから始まります。 各長方形について、高さと幅の観点からその幾何学的寄与を計算します。 二等分操作により、長方形の水平間隔に含まれる洗浄された列の数が正確に分離されます。 これらを減算すると生き残った柱の数が得られ、高さを掛けると柱の数が面積に変換されます。 

よくある間違いは、各列が 1 つのセルだけではなく、全体の高さに寄与することを忘れることです。 もう 1 つは、特に両方のエンドポイントが含まれるため、間隔の境界を誤って計算することです。 使用する`bisect_left`そして`bisect_right`手動で 1 つずつ調整することなく、包括的な範囲のカウントを正確に保証します。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    
    import sys
    input = sys.stdin.readline

    n, m = map(int, input().split())
    rects = []
    for _ in range(n):
        rects.append(tuple(map(int, input().split())))
    washed = [int(input()) for _ in range(m)]
    washed.sort()

    for r1, c1, r2, c2 in rects:
        h = r2 - r1 + 1
        total = c2 - c1 + 1
        l = bisect.bisect_left(washed, c1)
        r = bisect.bisect_right(washed, c2)
        good = total - (r - l)
        ans += good * h
    return str(ans)

 ## 特殊なケース

 主要なエッジ ケースは、単一の列に縮退する長方形です。 たとえば:

 入力:```
1 1
2 7 5 7
7
```長方形の高さ 4、幅 1 は、洗浄された列と正確に一致します。 二分探索により、内部に不良列が 1 つ見つかりました。$[7,7]$、良い列をゼロにし、貢献度がゼロになります。 これにより、幅 1 の間隔が正しいことが確認されます。 

洗浄された列がすべての長方形の外側に完全にある場合、別のエッジ ケースが発生します。 

入力:```
1 2
1 1 3 3
10
20
```バイナリ検索では、長方形の間隔で不良列が 0 個返されます。$[1,3]$、そのため、領域全体が保存されます。 アルゴリズムは、特別なケースを使用せずにこれを自然に処理します。 

最後の微妙なケースは、水平方向の間隔がバラバラであるものの、ウォッシュされた列が共有されている複数の長方形です。 各四角形は同じソートされた配列を独立してクエリするため、干渉や二重カウントは発生せず、各寄与は独自の範囲内で厳密に計算されます。
