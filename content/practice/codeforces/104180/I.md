 ## 解決策
 ## 問題の理解

 各頂点が友人の家を表し、各有向辺が 2 つの家の間の一方通行の道路を表す有向グラフが与えられます。 好きな頂点から開始することができ、一度開始すると、有向エッジを任意にたどり、頂点とエッジを複数回再訪することができます。 私たちの目標は、1 回の走査で訪問できる個別の頂点の数を最大化することです。 

グラフの用語では、再訪問は許可されますがカウントは増加しません、指示された移動の下で開始ノードと到達可能なセットを探します。 答えは、有向エッジに続く開始頂点から到達できる頂点の最大セットのサイズです。 

制約はアプローチを形作るのに十分厳しいものです。 と$N \le 1000$そして$M \le 2N$、グラフが疎であるため、次のようなアルゴリズムが使用されます。$O(N^2)$または$O(NM)$は許容されますが、すべてのペアにわたる三次関数や指数関数的な探索は実行できません。 各ノードからのナイーブ BFS または DFS を使用したすべてのノードにわたる完全なペアごとの到達可能性の計算は、すでに限界に近づいていますが、まだ妥当です。 ただし、構造体を再利用しない場合、再計算が繰り返されることに注意する必要があります。 

重要な点は、ノードの再訪問が許可されているため、構造が単純なパスの問題ではないことです。 代わりに、サイクルは制約なしで再訪できるため有益になります。これは、強く接続されたコンポーネントが単一の「自由移動ゾーン」のように動作することを意味します。 

重要なエッジケース:

 単純なチェーンは、到達可能性が方向性があり、非対称であることをすでに示しています。 たとえば:

 入力:```
3 2
1 2
2 3
```ノード 1 からは 1、2、3 に到達できるため、答えは 3 です。ノード 3 から開始する単純なアプローチでは、ノード 3 自体のみが表示されるため、すべての開始を試行しないとグローバル最大値を逃すことになります。 

サイクルも重要なケースです。```
3 3
1 2
2 3
3 1
```どのノードからでもすべてのノードにアクセスでき、再訪問が許可されるため、コンポーネント全体が完全に使用可能になります。 

最後の微妙なケースは、コンポーネントが非対称に相互に供給される場合です。 ノードは大きなチェーンに到達しても、元に戻ることはできないため、すべてのノードを探索するか構造を圧縮しない限り、最適な開始点は明らかではありません。 

## アプローチ

 ブルート フォースのアイデアは簡単です。開始ノードごとに、有向エッジに従って DFS または BFS を実行し、到達できる個別のノードの数を数えます。 最終的な答えは、すべての開始時の最大値です。 

これは正しいです。すべての有効なルートはいずれかのノードで始まり、BFS/DFS はその開始点から到達可能なノードのセットを正確に列挙します。 ただし、これでは作業の繰り返しが多くなります。 各走査のコスト$O(N + M)$、そして全員のためにそれを行う$N$ノードの収量$O(N(N+M))$、最悪の場合は約$10^6$実行ごとの操作はまだ限界に達していますが、慎重に実装した場合にのみ Python で許容されます。 ただし、これはより深い構造を無視しています。つまり、多くのノードが、強く接続された領域内で同じ到達可能性パターンを共有しています。 

重要な観察は、強結合コンポーネント (SCC) がサイクルを単一のユニットに崩壊させることです。 SCC 内では、すべてのノードが他のノードに到達できるため、SCC 内のどこから開始しても、同じ到達可能な「マクロ動作」が得られます。 SCC を折りたたむと、有向非巡回グラフ (DAG) が得られます。 この DAG では、どのコンポーネントから最大数のコンポーネントに到達できるかが問題になります。 

以来$M \le 2N$、グラフはまばらで、Kosaraju または Tarjan による SCC 分解は線形時間で実行されます。 圧縮後、DAG 上の DP をトポロジ順に計算します。ここで、各コンポーネントの値は、そのサイズに下流で到達可能な最良のコンポーネントの合計を加えたものになります。 

これにより、繰り返しの探索がエッジごとに 1 回の走査に減ります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべてのノードからのブルート フォース DFS | O(N(N+M)) | O(N+M) | 遅すぎる |
 | SCC + DAG DP | O(N+M) | O(N+M) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力エッジから有向グラフを構築します。 この構造は、順方向トラバーサルと SCC 処理の両方に使用されます。 
2. DFS ベースのアルゴリズムを実行して、強接続コンポーネントを計算します。 まず DFS を実行して終了順序を取得し、次にグラフを反転し、逆の終了順序でノードを処理してコンポーネント ID を割り当てます。 目的は、相互に到達可能なノードを単一のユニットにグループ化することです。 
3. 各 SCC について、そのサイズを計算します。 これは、そのコンポーネント内で「自由に交換可能な」元のノードの数を表します。 
4. 各 SCC がノードとなる要約グラフを構築します。 あらゆるオリジナルのエッジに$u \to v$、 もし$comp[u] \ne comp[v]$から有向エッジを追加します。$comp[u]$に$comp[v]$。 SCC の収縮によってサイクルが削除されるため、これにより DAG が生成されます。 
5. DAG で動的プログラミングを使用して、各 SCC から到達可能な最適なサイズを計算します。 SCC 仕上げ順序から派生した逆トポロジー順序でコンポーネントを処理します。 各コンポーネントの値は、そのコンポーネント自体のサイズに、すべての発信近隣の最大値を加えたものになります。 
6. どのノードからでも開始できるため、答えはすべての SCC にわたる最大 DP 値です。 

この順序付けが機能する理由は、SCC が形成されると、依存関係は DAG 内でのみ進行するため、コンポーネントの最適な到達可能性を計算するときに、下流の結果はすべて既知であるためです。 

### なぜ効果があるのか

 圧縮後、すべての有効なウォークは SCC DAG 内のパスに対応します。 DAG にはサイクルがないため、どのパスもコンポーネントを再訪問することができないため、有向エッジに沿って到達可能性が加算されます。 コンポーネント内ではすべてのノードが相互に到達可能であるため、各 SCC はそのフル サイズを 1 回だけ提供します。 したがって、到達可能なノードを最大化するとは、ノードの重みが SCC サイズである DAG 内の最大パス合計を見つけることになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    n, m = map(int, input().split())
    g = [[] for _ in range(n)]
    rg = [[] for _ in range(n)]

    for _ in range(m):
        a, b = map(int, input().split())
        a -= 1
        b -= 1
        g[a].append(b)
        rg[b].append(a)

    visited = [False] * n
    order = []

    def dfs1(u):
        visited[u] = True
        for v in g[u]:
            if not visited[v]:
                dfs1(v)
        order.append(u)

    for i in range(n):
        if not visited[i]:
            dfs1(i)

    comp = [-1] * n
    cid = 0

    def dfs2(u):
        comp[u] = cid
        for v in rg[u]:
            if comp[v] == -1:
                dfs2(v)

    for u in reversed(order):
        if comp[u] == -1:
            dfs2(u)
            cid += 1

    comp_size = [0] * cid
    for i in range(n):
        comp_size[comp[i]] += 1

    dag = [[] for _ in range(cid)]
    for u in range(n):
        for v in g[u]:
            cu, cv = comp[u], comp[v]
            if cu != cv:
                dag[cu].append(cv)

    dp = [-1] * cid

    def dfs_dp(u):
        if dp[u] != -1:
            return dp[u]
        best = 0
        for v in dag[u]:
            best = max(best, dfs_dp(v))
        dp[u] = comp_size[u] + best
        return dp[u]

    ans = 0
    for i in range(cid):
        ans = max(ans, dfs_dp(i))

    print(ans)

if __name__ == "__main__":
    solve()
```Kosaraju のアルゴリズムでは両方向のトラバーサルが必要なため、解決策は順方向と逆方向の両方の隣接リストを構築することから始まります。 最初の DFS は終了順位を計算し、反転グラフ上の 2 番目の DFS はコンポーネント ID を割り当てます。 

SCC ラベル付け後、各コンポーネントに属する元のノードの数を数えることにより、コンポーネントのサイズを累積します。 各 SCC が多数の異なるフレンドに貢献しているため、これは不可欠です。 

DAG 構築ステップでは、異なるコンポーネント間にエッジを追加することのみに注意してください。 このフィルターがないと、自己ループによって冗長な遷移が発生し、DP が複雑になる可能性があります。 

最後の DP は、圧縮された DAG 内の最長の重み付きパスを計算します。 メモ化により、各コンポーネントが一度解決されることが保証されます。 

## 実用的な例

 ### 例 1

 入力:```
3 2
1 2
2 3
```SCC 分解により、{1}、{2}、{3} の 3 つのコンポーネントが生成されます。 DAG は 1 → 2 → 3 です。 

| ステップ | ノード | DP結果 |
 | --- | --- | --- |
 | dfs_dp(3) | 3 | 1 |
 | dfs_dp(2) | 2 | 2 (2 + 1) |
 | dfs_dp(1) | 1 | 3 (1 + 2) |

 最終的な答えは 3 で、これはノード 1 から開始してチェーン全体を横断する能力に一致します。 

これにより、DP が線形 DAG に沿って到達可能なノードを正しく蓄積していることが確認されます。 

### 例 2

 入力:```
3 1
1 2
```SCC は {1}、{2}、{3} です。 DAG には単一エッジ 1 → 2 があります。 

| ステップ | ノード | DP結果 |
 | --- | --- | --- |
 | dfs_dp(3) | 3 | 1 |
 | dfs_dp(2) | 2 | 1 |
 | dfs_dp(1) | 1 | 2 |

 答えは2です。 

これは、到達不能なノードはカウントされず、ノード 1 から開始するのが最適であることを示しています。

 ## 特殊なケース

 A single-node graph like`1 0`サイズ 1 の SCC が 1 つ生成されます。出力エッジがないため、DP はすぐに 1 を返します。そのため、到達可能な最良のセットはそれ自体です。 

次のような完全な双方向サイクル`1 2, 2 1`サイズ 2 の 1 つの SCC に折りたたまれます。圧縮されたグラフにはノードが 1 つあるため、DP は 2 を返し、サイクル内で再訪するとすべてのノードにアクセスできることが正しく反映されます。 

チェーンが切断されたグラフでは、開始点が重要になります。 のために`1→2→3`そして`4→5`、SCC はシングルトンのままで、ノード 4 からの DP は 2 を生成しますが、ノード 1 からの DP は 3 を生成します。最終的な最大値は正しく 3 を選択し、コンポーネントに対するグローバルな最大化が不可欠であることを示しています。
