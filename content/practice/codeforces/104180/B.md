 ## 解決策
 ## 問題の理解

 初日に収集される雨水の開始量が整数で示されます。$i$。 この値がその週の残りのすべてを決定します。 2 日目から 7 日目まで、雨の量は着実に増加します。毎日同じ増加量が追加されます。$x$、 どこ$x$の桁の合計として計算されます。$i$。 合計 7 日間にわたって、収集された水の累積量を計算する必要があります。 

問題を単純な等差数列として再解釈するのに便利な方法です。 最初の学期は$i$、次の各項は ずつ増加します$x$。 したがって、シーケンスは次のようになります。$i, i + x, i + 2x, \dots, i + 6x$。 タスクは、これらの項をすべて合計することです。 

制約は小さく、$i \leq 10^5$したがって、桁の合計を計算し、一定数の算術演算を実行することは、パフォーマンスの点で簡単です。 テスト ケースごとの完全に直接的な計算でも定数時間です。 

エッジケースは微妙ですが、桁の合計がどのように動作するかという点で重要です。 

エッジケースの 1 つは、$i = 0$。 桁の合計は$0$, したがって、7 日間すべてがゼロになります。 正の数を想定したり、先頭のゼロのような動作を無視した単純な実装でも、桁の合計ロジックが堅牢な場合にのみ正しく処理されます。 

もう 1 つのエッジケースは次のような場合です$i$たとえば、末尾にゼロがある$i = 10000$。 桁の合計は$1$、ゼロの影響を受けないため、増分は小さいですが、シーケンスは引き続き正しく増加します。 間違いは、増分を桁の合計ではなく「桁の追加」のようなものとして誤って解釈することから発生することがよくあります。 

最後に、シーケンスの長さは固定 (7 項) であるため、Python ではオーバーフローの危険はありませんが、より厳密な言語では、大規模な算術演算を使用する単純な累算には注意が必要になる可能性があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 桁の合計を計算します$x$、次に 7 日間を明示的にシミュレートします。 から始まる$i$を繰り返し追加します$x$そして合計を積み上げます。 これは問題で説明されているプロセスを正確に反映しているため、これは正しいです。 

このアプローチのコストは 7 日間しかないため、テスト ケースごとに一定です。 桁の合計を再計算したり、算術演算を繰り返し実行したりしても、複雑さは依然として固定定数によって制限されます。 ただし、より一般的な非効率性は構造を無視していることにあります。シーケンスは算術演算であるため、反復累積ではなく閉じた形式で合計を実行できます。 

重要な観察は、数列が最初の項を持つ等差数列であるということです。$i$、前期$i + 6x$、合計7期。 等差数列の合計は次のようになります。$$\text{sum} = \frac{7}{2} \cdot (2i + 6x)$$これにより、桁の合計を 1 回計算して直接式を適用するだけで済みます。 

これにより、問題は純粋な算術に変わります。

 ## アルゴリズムのチュートリアル

 1. 整数を読み取る$i$入力から。 これはシーケンスの基本値であり、進行全体を定義します。 
2. コンピューティング$x$、の桁の合計$i$。 この値は固定の毎日の増分として機能するため、正確さは数値を適切に抽出するかどうかに完全に依存します。 
3. 7 つの毎日の値が、次から始まる等差数列を形成していることを認識します。$i$共通の違いがある$x$。 
4. 等差数列の公式を使用して合計を計算します。$$S = \frac{7}{2} \cdot (2i + 6x)$$これにより、正確な同等性を維持しながら、7 日間にわたる反復が回避されます。 
5. 出力$S$。 

### なぜ効果があるのか

 毎日の値の構築では、毎日が入力から導出される固定の加法定数のみに依存するため、線形進行が保証されます。 一度$x$が固定されている場合、すべての項は次のように一意に決定されます。$a_k = i + kx$。 これらの項の合計は等差数列の合計と等価であり、閉じた形式の公式は代数的には直接累積と同一です。 中間ステップが変更されないため、$x$、構造は 7 つの期間すべてにわたって安定しています。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

i = int(input().strip())

x = sum(int(c) for c in str(i))

# arithmetic series: i + (i+x) + ... + (i+6x)
# sum = 7/2 * (2i + 6x) = 7 * (2i + 6x) / 2
total = 7 * (2 * i + 6 * x) // 2

print(total)
```このソリューションは入力を読み取り、整数を文字列に変換し、文字を合計することによって、すぐに桁の合計を計算します。 これは、ゼロを含むすべての入力に対して安全です。`"0"`正しい桁の合計ゼロが生成されます。 

重要な実装の詳細は、浮動小数点演算を回避することです。 この式には 2 による除算が含まれていますが、式は常に偶数であるため、整数の除算は安全です。 として書くと`7 * (2 * i + 6 * x) // 2`正確な整数出力が保証されます。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    i = int(input().strip())
    x = sum(int(c) for c in str(i))
    total = 7 * (2 * i + 6 * x) // 2
    return str(total)

 ## 特殊なケース

 入力用`0`、桁の合計は`0`したがって、シーケンスは 7 日間を通じて一定の 0 です。 アルゴリズムは計算します$x = 0$、次のような結果が得られます。$S = \frac{7}{2}(0) = 0$、これは予想される出力と正確に一致します。 

入力用`10000`、桁の合計は`1`。 シーケンスは次のようになります。$10000, 10001, 10002, 10003, 10004, 10005, 10006$。 

アルゴリズムは以下を計算します。$S = 7(20000 + 6)/2 = 70003$、これは直接合計と一致します。 

入力用`99`、桁の合計は`18`。 シーケンスははるかに高速に増加しますが、算術公式は変更されずに適用されます。 各項は固定増分によってのみ決定されるため、等差数列の定義から逸脱するステップはありません。
