 ## 解決策
 ## 問題の理解

 整数の決定論的な落下過程をシミュレートしています。 1 から指定された制限までのすべての開始高さに対して$H$、「レインドロップ」を放ちます。 それぞれの雨粒は 1 秒ずつ個別に下に移動します。 1 秒間に、身長は現在の身長の素因数の合計数だけ減少します (多重度でカウントされます)。 たとえば、12 は 3 に寄与します。$12 = 2^2 \cdot 3$, つまり、1秒間に3単位の高さが失われます。 このプロセスは高さが 1 に達するまで繰り返され、その高さが地面として扱われ、その雨滴のシミュレーションが終了します。 高さを順番に処理し、各落下が終了するのを待ってから次の落下を開始します。すべての開始高さの合計秒数が必要です。 

コア入力は開始時の最大高さにすぎません$H$。 出力は、開始値の個々の立ち下がり時間をすべて合計したものです。$1, 2, \dots, H$。 

制約$H \le 4 \cdot 10^6$ステップごとに新しい因数分解を使用して、各開始値を個別にシミュレートするものはすべて除外されます。 プロセス全体の単純なシミュレーションでは、数値の因数分解と値の減算が繰り返し行われるため、最悪の場合の動作が次のようになります。$O(H \sqrt{H})$さらに悪いことに、1 秒をはるかに超えます。 

微妙な点の 1 つは、「移動量」が個別の素数ではなく、素因数の多重度に依存することです。 これを個別の素数のカウントと混同すると、間違った遷移が発生します。 たとえば、12 は 3 ではなく 2 ずつ誤って移動し、軌道全体と合計時間が変わります。 

もう 1 つの問題は、シミュレーション中に因子数を最初から再計算することです。 それぞれの数値の因数分解が行われていても、$O(\log n)$平均して、最大 400 万の州を掛けると、これでは遅すぎます。 

## アプローチ

 各開始高さの直接シミュレーションは概念的に簡単です。 所定の高さの場合$x$、その素因数の和を繰り返し計算します。$\Omega(x)$、次に設定します$x := x - \Omega(x)$までの時間を蓄積します。$x = 1$。 全員のためにこれを行う$x \le H$正確に答えを導き出します。 プロセス定義を反映しているため、正確さは明らかです。 

ボトルネックは再計算です$\Omega(x)$繰り返し。 事前計算しても$\Omega(x)$みんなのために$x$ふるいを使用しても、すべての開始値の遷移をシミュレートする必要があります。 重要な観察は、すべての状態遷移はより小さい値にのみ依存するということです。つまり、高度にあるときは、$x$にジャンプします$x - \Omega(x)$、これは厳密に小さいです。$\Omega(x) \ge 1$のために$x \ge 2$。 これにより、整数に対する自然な依存関係 DAG が作成されます。 

つまり、高さの昇順に答えを計算できるということです。 すべての小さな値から必要な時間がすでにわかっている場合は、$x$は単純に 1 に次の位置からの時間を加えたものです。 これにより、事前に計算された関数によって定義された遷移を使用して、問題が線形状態空間にわたる動的計画計算に変換されます。$\Omega(x)$。 

まず事前計算します$\Omega(x)$みんなのために$x \le H$素因数を多重度で累積する改良されたふるいを使用します。 次に、各エントリが以前に計算されたエントリのみに依存する DP 配列を計算します。

 ## アルゴリズムのチュートリアル

 ### 素因数のカウントの事前計算

 1. 配列を作成する`omega`サイズの$H+1$、ゼロに初期化されます。 
2. 各整数について$p$2から$H$、まだマークされていない場合は、素数として扱います。 
3. 倍数ごとに$k$の$p$、増分`omega[k]`1 で除算し、sieve 構造を通じて暗黙的に効果の除算を続けます。 
4. すべての素数を処理した後、`omega[x]`の素因数の合計数に等しい$x$多重度で数えます。 

これが機能するのは、素数に遭遇するたびに$p$、すべての倍数は、因数分解においてその素数のコピーを 1 つだけ提供します。 

### 高所を越える動的プログラミング

 1. 配列を作成する`dp`サイズの$H+1$、 どこ`dp[x]`高さから落下が始まる時間を表します$x$1に到達するために。 
2.セット`dp[1] = 0`地面から始まる落下はすでに終わっているからです。 
3. あらゆる人にとって$x$2から$H$、次の位置を次のように計算します。$nx = x - \omega[x]$。 
4. 定義する`dp[x] = dp[nx] + 1`。 

この順序が機能する理由は次のとおりです。$nx < x$、 それで`dp[nx]`処理時に常にすでに計算されています$x$。 

### 最終累積

 1. すべてを合計します`dp[x]`のために$x = 1$に$H$、これはすべての雨滴を連続的に落とす合計時間に相当します。 

### なぜ効果があるのか

 DP は厳密に減少する遷移に依存しています。つまり、すべての高さが 1 ステップで厳密に小さい高さに移動します。 これにより、計算時に次のことが保証されます。`dp[x]`、から到達可能なすべての州$x$すでに解決されています。 それぞれ`dp[x]`は、決定論的ルールに従って 1 に到達するために必要な遷移の正確な数を表すため、すべての開始高さを合計すると、合計ランタイムが正しく集計されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    H = int(input().strip())
    
    omega = [0] * (H + 1)
    
    for i in range(2, H + 1):
        if omega[i] == 0:
            for j in range(i, H + 1, i):
                x = j
                while x % i == 0:
                    omega[j] += 1
                    x //= i
    
    dp = [0] * (H + 1)
    total = 0
    
    for i in range(2, H + 1):
        nxt = i - omega[i]
        dp[i] = dp[nxt] + 1
        total += dp[i]
    
    print(total)

if __name__ == "__main__":
    solve()
```最初のループは関数を構築します$\omega(x)$、ふるいのようなアプローチを使用した、多重性を持つ素因数の数。 素数ごとに$i$、その倍数をスキャンし、累乗を繰り返し除算します。$i$、何回積み上げますか？$i$がそれぞれの数字に表示されます。 

次に、DP ループは昇順に応答を構築します。 すべての遷移は厳密に小さい数値に進むため、`dp[nxt]`すでに計算されていることが保証されます。 また、すべてを個別に保存するのではなく、回答を段階的に蓄積します。 

よくある落とし穴は、多重性が必要であることを忘れていることであり、それが繰り返し分割を繰り返す理由です。`x`単純に素除数ごとに 1 回インクリメントするのではなく、内側のループ内で実行します。

 ## 特殊なケース

 のために$H = 1$の場合、DP ループは実行されず、答えは 0 になります。これは、雨滴の動きが発生しないという解釈と一致します。 配列が初期化され、累積ループが 2 から開始されるため、アルゴリズムはこれをきれいに処理します。 

次のような素数の場合$H = p$、私たちは得ます$\omega(p) = 1$したがって、遷移は常に次のようになります。$p-1$。 DP は、素数がすでに計算された複合値またはそれより小さい値にのみ依存することを保証するため、循環は発生しません。 

16 などの 2 の累乗の場合、次のような長いチェーンが得られます。$16 \to 12 \to 9 \to 7 \to 6 \to 4 \to 2 \to 1$。 各ステップでインデックスが厳密に減少し、以前に計算された状態の終了と正しい累積が保証されるため、DP はこれを正しく処理します。
