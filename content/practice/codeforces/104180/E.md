 ## 問題の理解

 私たちに与えられているのは、$n \times n$セルの値が入っているグリッド$(i, j)$は整数の除算として定義されます$\left\lfloor \frac{j}{i} \right\rfloor$。 行インデックス$i$と列インデックス$j$どちらも 1 から始まります。タスクは、グリッド全体で固定整数に評価されるセルの数をカウントすることです。$k$。 

これはグリッドの構築に関する問題ではありません。グリッドを明示的に構築するとすでに大きすぎるためです。$n$までです$10^5$。 代わりに、ペアの数を数えています。$(i, j)$満足する$\left\lfloor \frac{j}{i} \right\rfloor = k$。 

制約により、二次解は即座に除外されます。 フルグリッドシミュレーションは次のとおりです。$O(n^2)$、つまり$10^{10}$最悪の場合、制限時間内に操作が実行されない場合があります。 すべてのペアを反復しても$(i, j)$不可能です。 

重要なエッジケースは、次の小さな値にあります。$i$。 固定列の場合$i$、の値$j$の区分定数関数を生成します$\left\lfloor \frac{j}{i} \right\rfloor$、単純な実装では列ごとに頻繁に変更されることが想定されますが、実際には関数は長い間隔にわたって一定のままです。 

もう一つの微妙なエッジケースは、$k = 0$。 これはすべてのペアに対応します。$j < i$、この領域はグリッド内で三角形を形成します。 の正の倍数のみを考慮する素朴なアプローチ$i$この地域全体を見逃してしまうでしょう。 

## アプローチ

 ブルートフォース手法では、すべてのセルを直接評価し、計算します。$\left\lfloor \frac{j}{i} \right\rfloor$と等しい場合にカウンターをインクリメントします。$k$。 これは定義に正確に従っているため、正しいです。 ただし、すべてを繰り返す必要があります$n^2$ペア。 と$n = 100000$、これは次のようになります$10^{10}$実現可能な限界をはるかに超えた評価です。 

関数の構造$\left\lfloor \frac{j}{i} \right\rfloor$は別の見解を示唆しています。 各セルをスキャンする代わりに、行を修正します$i$そして、どの範囲について尋ねます。$j$値は等しいですか$k$? 不平等$$\left\lfloor \frac{j}{i} \right\rfloor = k$$と同等です$$k \le \frac{j}{i} < k+1$$に変身する$$k \cdot i \le j < (k+1)\cdot i.$$したがって、各行について$i$、すべて有効です$j$連続した間隔の中にあります。 これにより、問題は 2 つの区間間の整数の交差を数えるというものに縮小されます。$[k i, (k+1)i - 1]$そして$[1, n]$。 各行はゼロまたは完全なセグメント長に寄与し、これは行ごとに一定時間で計算できます。 

これにより、問題はセルに対する二次スキャンではなく、行に対する線形スキャンに変わります。

 ## アルゴリズムのチュートリアル

 1. 行インデックスを修正する$i$そして状態を解釈する$\left\lfloor \frac{j}{i} \right\rfloor = k$有効な列インデックスの制約として$j$。 これにより、問題は個々のセルから連続した範囲に移ります。 
2. 床条件を不等式として書き直す$k i \le j < (k+1)i$。 これにより、行内の列のセットが正確に識別されます。$i$価値を生み出すもの$k$。 
3. この間隔を有効なグリッド範囲と交差させます。$[1, n]$。 実際に使用可能なセグメントは、$$L = \max(1, k i), \quad R = \min(n, (k+1)i - 1).$$4. もし$L \le R$、 追加$R - L + 1$答えに。 それ以外の場合は行$i$貢献度はゼロです。 これが必要なのは、間隔が部分的または完全にグリッド境界の外側にある可能性があるためです。 
5. これを全員に対して繰り返します$i$1から$n$、合計を積み上げます。 

### なぜ効果があるのか

 固定ごとに$i$、関数$\left\lfloor \frac{j}{i} \right\rfloor$次の場合にのみ増加します$j$の倍数と交差する$i$。 商が等しい範囲内$k$、すべての整数$j$同じ不等式制約を満たします。 したがって、カウントは有効です$j$per row は、グリッドを互いに素なセグメントに正確に分割し、フロア条件を満たす場合にのみ、すべてのセルが 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    ans = 0

    for i in range(1, n + 1):
        L = k * i
        R = (k + 1) * i - 1

        if R < 1 or L > n:
            continue

        if L < 1:
            L = 1
        if R > n:
            R = n

        if L <= R:
            ans += R - L + 1

    print(ans)

if __name__ == "__main__":
    solve()
```コアループは各行を独立して処理します。 境界$L = k i$そして$R = (k+1)i - 1$床の状態を再配置することから直接得られます。 に対するクリッピング$[1, n]$有効な列は負または超過できないため、必須です。$n$。 この調整を行わないと、次の行は$k i > n$誤って正のカウントを提供してしまう可能性があります。 

条件$R < 1$間隔の上限さえもグリッドの外側にあるケースを除外します。 これは特に次のことに関連します。$k = 0$、 どこ$L = 0$有効な範囲は次から始まります$j = 1$。

 ## 特殊なケース

 のために$k = 0$、式は次のようになります$L = 0$そして$R = i - 1$。 にクリッピングした後、$[1, n]$、貢献度は$1$に$i-1$、正確にすべてを数えます$j < i$。 たとえば、$n = 4$、行 3 は次のようになります。$j \in \{1,2\}$、グリッド定義と一致します。 

大型用$k$、特にいつ$k i > n$、間隔はグリッドを超えて始まり、何も寄与しません。 たとえば、次の場合$n = 5$、$k = 3$、 そして$i = 2$、 それから$L = 6$、グリッドの外側にあるため、行の寄与はゼロです。 これにより、境界のあるグリッド内に実際には存在しない大きな商領域を過剰にカウントすることが防止されます。
