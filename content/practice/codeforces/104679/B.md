 ## 解決策
 ## 問題の理解

 整数の配列が与えられると、単一の位置を選択し、その要素の符号を反転するという 1 つの操作を実行する必要があります。 これを 1 回実行した後、配列全体の合計を計算し、この合計が偶数であるかどうかを確認します。 課題は、反転したポジションのさまざまな選択肢が最終的に均等になる数を数えることです。 

したがって、入力は整数の単一のリストを記述します。 各選択は、1 つのインデックスを選択し、その値を否定し、合計を再計算することに対応します。 操作をスキップしたり、複数の要素を反転したりすることはできないため、すべての候補結果は、どの要素の符号が反転されているかによってのみ異なります。 

この形式の典型的な Codeforces 問題によって暗示される制約構造は、配列サイズが十分に大きいため、インデックスごとに合計を最初から再計算すると遅すぎる可能性があることを示唆しています。 二次スキャンはすでに境界線に達しており、配列が約 10^5 要素に達すると、選択肢ごとに合計を再計算するソリューションは直ちに実行できなくなります。 

素朴な推論をつまずく可能性がある微妙な点は、符号を反転すると、自明ではない方法で寄与の等価性が変化すると仮定することです。 もう 1 つのよくある落とし穴は、実際には符号の変化がパリティにまったく影響を与えないのに、符号の反転によって奇数または偶数がいくつ変化するかを追跡しようとすることです。 こうした誤解により、大文字と小文字が正しく分割されないことがよくあります。 

## アプローチ

 直接シミュレーションのアプローチでは、各インデックスが順番に考慮されます。 各位置 i について、要素を一時的に否定し、配列全体の合計を再度計算し、それが偶数であるかどうかを確認します。 これは、許可されているすべての操作を明示的に評価するため、正しいです。 ただし、合計の各再計算には線形時間がかかり、すべてのインデックスに対してそれを実行すると、二次アルゴリズムが必要になります。 要素が n 個あると、およそ n 個の操作が発生し、各操作のコストは O(n) となり、合計作業量は O(n^2) となり、大きな入力には遅すぎます。 

重要な観察は、単一の要素が否定されたときに合計がどのように変化するかを理解することから得られます。 元の合計が S で、Ai を反転すると、新しい合計は S - Ai + (-Ai) となり、単純化すると S - 2Ai になります。 この式は、すべての候補合計が S と偶数値、つまり 2Ai だけ異なることを示すため、重要です。 2Ai は常に 2 で割り切れるため、どの要素が反転されても、和のパリティは決して変わりません。 

これにより、各インデックスを個別に評価する必要が完全になくなります。 n 個の異なる結果をチェックする代わりに、元の合計のパリティを 1 回チェックするだけで済みます。 元の合計が偶数の場合、すべての操作で偶数が維持されます。 元の合計が奇数の場合、すべての演算で奇数が維持されます。つまり、どの結果も有効ではありません。 

ブルート フォースは問題定義に明示的に従うため機能しますが、冗長な情報が再計算されるため失敗します。 符号反転により合計が偶数だけ変化するという観察により、すべてのケースが 1 つのグローバル パリティ チェックにまとめられます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | お(1) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### 最適なアイデアの実行

 1. 配列内のすべての要素の合計を計算します。 これにより、すべての操作が導出されるベースライン値 S が得られます。 
2. S が偶数か奇数かを確認します。 この 1 ビットの情報が、考えられるすべての符号反転の動作を決定します。 
3. S が偶数の場合、各フリップはパリティを保持するため、すべてのインデックスが有効な演算を生成すると結論付けます。 答えは要素の総数です。 
4. S が奇数の場合、許可された変換の下ではパリティが不変であるため、有効な演算を生成するインデックスはないと結論付けます。 答えはゼロです。 

### なぜ効果があるのか

核となる不変条件は、任意の単一要素の符号を反転すると、2Ai が減算されて合計が変化するということです。 2Ai は常に偶数であるため、許可されたすべての操作において和のパリティは変化しません。 これは、単一のフリップを介して元の配列から到達可能なすべての状態が同じパリティを共有することを意味します。 その結果、初期合計が偶数の場合はすべての演算が有効になるか、初期合計が奇数の場合は何も無効になります。 一部のインデックスが他のインデックスと異なる動作をする中間のケースはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    data = list(map(int, input().split()))
    n = data[0]
    arr = data[1:]
    
    s = sum(arr)
    if s % 2 == 0:
        print(n)
    else:
        print(0)

if __name__ == "__main__":
    solve()
```このソリューションは配列を読み取り、その合計を 1 回計算してから、1 回のパリティ チェックを実行します。 この構造では、入力が n の後に配列要素が続く単一行形式で提供されることを前提としています。これは、多くの簡素化された Codeforce タスクの標準です。 

重要な実装の詳細は、インデックスごとの再計算を回避することです。 すべてはグローバル合計のみに依存するため、意思決定には合計を超えるループは必要ありません。

 ## 特殊なケース

 単一の要素を含む最小限の配列は、ロジック全体を直接強調表示します。 値が偶数の場合、合計は偶数であり、パリティを維持できる唯一の反転が行われるため、答えは 1 になります。 値が奇数の場合、合計は奇数であり、パリティを変更するフリップはないため、答えはゼロになります。 

たとえば、次のように入力します。```
1
7
```合計は 7 で奇数です。 唯一の要素を反転すると -7 が得られますが、変換により合計差分フレームワークから 14 が減算されるため、そのパリティは依然として奇数です。 アルゴリズムは正しく 0 を出力します。 

すべてゼロの配列の場合、合計はゼロ、つまり偶数になります。 すべてのフリップではパリティの合計が変更されないため、すべてのインデックスが有効になります。 アルゴリズムは n を出力します。これは、すべての操作が均一性を維持するという事実と一致します。
