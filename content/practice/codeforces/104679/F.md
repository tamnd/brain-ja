 ## 解決策
 ## 問題の理解

 個別の非負の整数の隠れたセットを表す 2 つの整数が与えられます。 これらの値の 1 つはセット内のすべての要素のビット単位の OR で、もう 1 つは同じセット内のすべての要素のビット単位の XOR です。 これら 2 つの集合だけから、タスクは、そのようなセットを形成できる個別の整数の可能な最大数を決定するか、そのようなセットが存在し得ないと判断することです。 

OR 値は、セットの少なくとも 1 つの数値にどのビット位置が現れるかを表します。 この OR 内のビットがゼロである場合、セット内のすべての数値がその位置にゼロを持つように強制されます。 XOR 値は、すべての要素にわたるパリティ情報をビットごとに取得します。これにより、非ローカルな方法で OR 構造と相互作用する制約が導入されます。 

この問題を直接解釈すると、両方の制約を同時に満たすセットを構築することが示唆されます。 ただし、一般に数値に制限はありませんが、OR を使用すると、すぐに有限のビットマスク領域に制限されます。 OR で k ビットを使用する場合、これらの k ビットはそれぞれ独立して 0 または 1 として選択できるため、有効な数値はすべてサイズ 2^k の空間内に収まる必要があります。 

単純な試みでは、このユニバースのすべてのサブセットを列挙し、各サブセットの OR と XOR を計算しようとします。 サブセットが 2^(2^k) あり、k が小さい場合でも爆発的に増加するため、これはすぐに不可能になります。 

さらに微妙な問題が一貫性において現れます。 入力に互換性のない OR および XOR ペアが記述される可能性があります。 たとえば、ビットが XOR に設定されているが OR には設定されていない場合、XOR がビットごとに 1 であるということは、奇数の要素にそのビットが設定されていることを意味し、それを完全に禁止する OR と矛盾するため、構築は不可能です。 このチェックを無視した不用意なアプローチでは、誤って肯定的な応答が報告されてしまいます。 

もう 1 つのエッジ ケースは、OR がゼロの場合です。 これにより、任意の数値にビットを含めることができないため、すべての要素が強制的にゼロになります。 その場合、XOR もゼロでなければなりません。 そうしないと、入力に一貫性がなくなります。 

## アプローチ

 ブルート フォースの観点は、OR で定義された許可されたビット ユニバースから抽出された数値のすべての可能なサブセットを想像することから始まります。 各サブセットについて、OR と XOR を計算し、ターゲット値と比較します。 これは、考えられるすべての構成を明示的にチェックするため、正しいです。 ただし、許容ビットが k であっても、ユニバースには 2^k 個の要素があり、サブセットの数は 2^(2^k) であり、k が 5 または 6 を超えると、実現可能性をはるかに超えて増加します。 

重要な単純化は、視点の変更によってもたらされます。任意のサブセットを選択する代わりに、完全なユニバースに対して XOR によって課せられる構造について推論します。 k 個の許容ビットのサブセットから形成されるすべての数値のセットは、強い対称性を持っています。 各ビット位置はユニバースの半分にわたって個別にバランスがとられており、ユニバース全体の XOR が強制的にゼロになります。 これにより、OR 制約を最大限に満たした自然なベースライン構成が得られます。 

そこから、XOR 制約は、この対称構造に対する 1 つの修正として見ることができます。 慎重に選択した 1 つの要素を削除すると、XOR がゼロからその要素に反転されます。 これにより、問題はサブセットの列挙から、固定された 2^k サイズのユニバース内での制御されたパリティ調整に変わります。 

残りの作業は、k が小さい場合の縮退ケースの処理です。これは、対称引数はビット寄与のバランスをとるのに十分な構造があることに依存するためです。

 ## アルゴリズムのチュートリアル

 どのビット位置が使用可能であるかを定義する、指定された OR 値から開始します。

1. OR が 1 となるすべてのビット位置を抽出します。これらの位置を許可ビットのリストにします。 このようなビットの数は k です。 有効な数値はすべて、これらの k 位置のみを使用して形成する必要があります。そうしないと、OR 制約に違反します。 
2. XOR に OR に存在しないビットが含まれているかどうかを確認します。 そうであれば、解決策は存在しません。 これは、禁止ビットに 1 がある XOR は、そのビットが設定されている数値が奇数であることを意味しますが、OR はそのような数値を禁止するためです。 
3. OR がゼロの場合、すべての数値はゼロでなければなりません。 可能なセットは {0} のみです。 これは、XOR もゼロの場合にのみ機能します。 そうしないと有効な構築ができません。 
4. 許可されるビットが 1 つだけの場合、取り得る値は 0 と OR のみです。 空でないセットには OR 制約を満たすために OR が含まれている必要があるため、答えは常に 2 となり、XOR は OR に等しくなければなりません。 
5. k が少なくとも 2 の場合、許可されたビットのサブセットによって形成されるすべての 2^k 数値の完全なセットを構築します。 これは、OR 制約の下での完全なユニバースです。 
6. この完全な世界では、各ビットがすべての数値にわたって同じ頻度で出現するため、すべての 2^k 要素の XOR が 0 であることに注目してください。 
7. 必要な XOR がゼロの場合、この完全なユニバースはすでに有効なソリューションであるため、最大サイズは 2^k です。 
8. 必要な XOR がゼロ以外の場合でも、許可されたビット空間内になければなりません。 ユニバース全体から XOR に等しい要素を 1 つだけ削除します。 要素を削除すると、その値によって XOR が反転されるため、結果として得られる XOR は必要な XOR とまったく同じになり、OR は変更されません。 
9. 結果セットのサイズ (2^k − 1) を返します。 

### なぜ効果があるのか

 この構造は、選択されたビットで異なる状態の完全なペアリングにより、k 個の独立したビットにわたるフルパワーセットの XOR がゼロに等しいという事実に依存しています。 これにより、セットは GF(2) 上の線形構造になり、XOR はベクトル加算のように動作します。 ゼロ和マルチセットから 1 つのベクトルを削除すると、そのベクトルに等しい新しい合計が生成されます。XOR は許可された空間内に留まらなければならないため、そのベクトルはユニバース内に存在することが保証されます。 要素を削除しても新しいビットが導入されることはないため、OR 制約は保持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    O, X = map(int, input().split())

    if (X & ~O) != 0:
        print(-1)
        return

    if O == 0:
        print(1 if X == 0 else -1)
        return

    bits = []
    for i in range(60):
        if O >> i & 1:
            bits.append(i)

    k = len(bits)

    if k == 1:
        print(2)
        return

    if X == 0:
        print(1 << k)
    else:
        print((1 << k) - 1)

if __name__ == "__main__":
    solve()
```このソリューションでは、まず、XOR が禁止ビットをアクティブにしないことをチェックすることで、XOR と OR の間の一貫性を確保します。 次に、OR が 0 であるか単一ビットを持つ縮退ケースを処理します。 一般的なケースでは、利用可能なビット数をカウントし、完全なサブセット ユニバースが XOR ゼロを与える構造的な結果を使用します。 答えは、XOR 制約に一致させるために 1 つの要素を削除する必要があるかどうかによってのみ異なります。 

微妙な点は、セットを明示的に構築しないことです。 この推論は、有効なビット サブセットがいくつ存在するかを数えることのみに依存しており、ビット サブセットを列挙することには依存しません。

 ## 特殊なケース

 OR が 0 の場合、宇宙は単一の可能な数値に崩壊します。 入力用`0 0`の場合、アルゴリズムはただちに 1 を返し、唯一の有効なセットを反映します。`{0}`。 XOR がゼロ以外の場合、次のようになります。`0 1`、小切手`(X & ~O)`これは、XOR が禁止ビットを使用し、構築を試行する前にアルゴリズムがそれを正しく拒否するためです。 

OR に 1 つのビットが設定されている場合、次のようになります。`O = 1`の場合、アルゴリズムは XOR が 0 か 1 であるかに関係なく 2 を返します。この状況では、取り得る数値は 0 と 1 の 2 つだけであり、1 を除外すると OR 要件が満たされないため、サイズは固定されます。 XOR 整合性チェックにより、有効な構成のみがこのブランチに到達することが保証されるため、評価中に矛盾は発生しません。
