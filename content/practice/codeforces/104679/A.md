 ## 解決策
 ## 問題の理解

 未知の正の整数のペアを要約する 2 つの数値が与えられます。 1 つの数値はそれらの合計を表し、もう 1 つの数値はそれらの差を表し、差は 1 番目から 2 番目を引いたものと見なされます。 これら 2 つの値から、元のペアを再構築する必要があります。 

タスクは基本的に、単純な線形システムを反転することです。 2 つの未知の整数が直接与えられる代わりに、それらを組み合わせた 2 つの測定値が与えられ、元の値を一意に回復する必要があります。 

計算は純粋に算術的であるため、制約の構造は最小限です。 これは、広範囲にわたるループは不必要なオーバーヘッドとなるため、ソリューションはテスト ケースごとに一定時間で実行する必要があることを意味します。 したがって、期待されるアプローチは直接代数操作であるはずです。 

再構成された値の妥当性から微妙な問題が生じます。 元の整数は正であるため、計算結果も正の整数である必要があります。 もう 1 つの重要なエッジ ケースはパリティです。和と差を 2 で割ったときに整数の結果が得られない場合、入力は有効な整数のペアと一致しません。 

たとえば、入力が和 5、差 2 の場合、再構成はきれいに機能します。 ただし、入力が和 5、差 3 の場合、再構築された値は両方とも非整数になり、厳密な整数設定が無効であることを示します。 

## アプローチ

 ブルートフォース解釈では、考えられるすべての正の整数のペアを試し、どのペアが指定された合計と差の両方に一致するかを確認します。 各候補 x および y について、x + y が指定された合計に等しいかどうか、および x − y が指定された差に等しいかどうかを検証します。 これは、解空間を徹底的に検索するため、概念的に機能します。 

ただし、候補ペアの数は合計のサイズに応じて二次関数的に増加します。 合計が 10^9 程度の場合、チェックするペアの数はその大きさの 2 乗に比例しますが、これは計算上実行不可能です。 

重要な観察は、2 つの方程式がすでに線形システムを定義していることです。 検索する代わりに、変数を排除することで未知の部分を直接解決できます。 両方の方程式を加算すると 1 つの変数が分離され、それらを減算するともう 1 つの変数が分離されます。 これにより、問題が検索から定数時間演算に軽減されます。 

この削減を可能にするのは問題の構造です。 この制約は、反転を複雑にする非線形挙動や追加条件を導入しないため、直接代数によって完全に解が決定されます。

 ## アルゴリズムのチュートリアル

 1. 未知の数とその差の合計を表す 2 つの指定された値を一定の順序で読み取ります。 

どちらの変数が大きいかは差によって決まるため、順序は重要です。 
2. 2 つの方程式間の関係を使用して、最初の数値を分離します。 和と差を加算すると、2 番目の変数がキャンセルされ、最初の数値の 2 倍が残ります。 
3. 結果を 2 で割って、最初の元の数値を取得します。 この除算は、入力が整数解と一致する場合にのみ有効であることが保証されます。 
4. 合計から最初の数値を引くか、合計から差を引いて 2 で割ることにより、2 番目の数値を計算します。 
5. 両方の再構成値を出力します。 

機能する理由: システムは 2 次元で一意の直線交点を定義します。 元の変数から和と差への変換は、2 による算術除算で整数が得られる限り、元に戻すことができます。 加算と減算は線形演算であるため、それらを逆にすると一貫性が保たれ、再構築されたペアが両方の元の方程式を正確に満たすことが保証されます。

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    data = input().split()
    S = int(data[0])
    D = int(data[1])

    x = (S + D) // 2
    y = (S - D) // 2

    print(x, y)

if __name__ == "__main__":
    solve()
```このソリューションは 2 つの入力値を読み取り、システムの代数逆変換を直ちに適用します。 式 (S + D) は最初の数値の 2 倍に相当し、(S − D) は 2 番目の数値の 2 倍に相当します。 この問題では、再構成が正確である場合に有効な入力が保証されるため、整数除算が使用されます。 

よくある間違いは、符号を逆にしたり式を交換したりすることです。これにより、見た目は正しくても間違ったペアが生成されます。 もう 1 つの微妙な問題は、両方の値が整数である必要があることを忘れていることですが、この問題に対する標準的な競技プログラミング設定では、端数の結果を避けるために入力が構築されています。 

## 実用的な例

 ### 例 1

 入力:

 S = 10、D = 4

 再構成された値を段階的に計算します。 

| ステップ | 式 | 値 |
 | --- | --- | --- |
 | 合計 | S | 10 |
 | 違い | D | 4 |
 | 最初の番号 | (S + D) / 2 | 7 |
 | 2 番目の番号 | (S − D) / 2 | 3 |

 これにより、7 + 3 = 10 および 7 − 3 = 4 であることが確認され、再構成が一貫していることがわかります。 トレースは、変換によって 2 つの未知数が曖昧さなく明確に分離されたことを示しています。 

### 例 2

 入力:

 S = 8、D = 2

 | ステップ | 式 | 値 |
 | --- | --- | --- |
 | 合計 | S | 8 |
 | 違い | D | 2 |
 | 最初の番号 | (S + D) / 2 | 5 |
 | 2 番目の番号 | (S − D) / 2 | 3 |

 ここで、再構成されたペアは 5 と 3 です。逆置換を検証することで、正確さが確認されます。 この例は、手順が対称的でスケールに依存しないことを強調しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from contextlib import redirect_stdout
    out = io.StringIO()
    with redirect_stdout(out):
        solve()
    return out.getvalue().strip()

def solve():
    import sys
    input = sys.stdin.readline
    S, D = map(int, input().split())
    x = (S + D) // 2
    y = (S - D) // 2
    print(x, y)

assert run("10 4\n") == "7 3", "sample 1"
assert run("8 2\n") == "5 3", "sample 2"

assert run("2 0\n") == "1 1", "minimum equal numbers"
assert run("1000000000 0\n") == "500000000 500000000", "large equal case"

 ## 特殊なケース

 エッジケースの 1 つは、差がゼロの場合です。 入力 2 と 0 の場合、再構成により両方の値が等しくなります。 このアルゴリズムは (2 + 0) / 2 = 1 および (2 − 0) / 2 = 1 を計算し、有効な同一ペアを生成します。 これは、このメソッドが特別な分岐を行わずに対称性を自然に処理していることを確認します。 

もう 1 つのケースは、合計が大きいが差も大きく、合計に近い場合です。 入力 100 と 98 の場合、計算により x = 99 および y = 1 が得られます。どちらの式も負でない整数を生成し、減算によって Python でオーバーフローや精度の問題が発生しないため、算術演算は安定しています。 

最後のエッジケースはパリティの一貫性です。 5 や 2 などの仮定の入力が許可された場合、数式は小数値を生成します。 このアルゴリズムは、(S + D) と (S − D) の両方が偶数になるように入力が構築され、整数出力が保証されることを前提としています。
