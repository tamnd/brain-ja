 ## 問題の理解

 2 つの整数が与えられます。 1 つは固定ベースのようなパラメータです$k$、もう一方は上限です$r$。 負でない整数の場合$n$、プロセスを定義します。$n$で割り切れます$k$で割ります。$k$そうでない場合は 1 を減算します。これを 0 に達するまで繰り返すと、いくつかの演算が得られます。$f(n)$。 課題は最大化することです$f(n)$すべての整数にわたって$n$範囲内で$[0, r]$。 

重要な問題は計算ではない$f(n)$単一の値の場合。 プロセスが基数の最後の桁を繰り返し削除するような動作をしていることに気づくと、その部分は構造化されます。$k$。 本当の課題は、次の値までのすべての値を検索することです。$r$これは非常に大きくなる可能性があるため、すべてをシミュレーションすることなく、数値の構造がコストにどのような影響を与えるかを推論する必要があります。$n$。 

問題設定によって暗示される制約は、典型的な競技プログラミングの制限です。$r$すべての値を反復処理するのは不可能なほど大きいため、それぞれの値を評価するソリューションはすべて$n$独立して二次または線形になります$r$が遅すぎます。 桁数が対数に近いか、最悪でも線形に近いものが必要です。 

微妙なエッジケースが現れるのは、$n$塩基に主要な構造変化がある$k$。 たとえば、デクリメント後に最上位桁が 0 になると、桁数は事実上縮小します。 もう 1 つの問題は、次の値が小さいことです。$n$ここで、「数字の式」は引き続き有効ですが、表現が 1 桁しかない場合は注意して解釈する必要があります。 

## アプローチ

 素朴なアプローチは簡単です。 あらゆる人にとって$n \le r$、プロセスをシミュレートします: で割り切れる場合$k$、除算、そうでない場合は 1 を引き、歩数を数えます。 各シミュレーションの費用$O(\log_k n)$, 除算するたびに大きさが小さくなりますが、最悪の場合、除算が行われる前に何度も減算することになるからです。 全体$n$、これは約につながります$O(r \log r)$、これは実現可能な限界をはるかに超えています。$r$大きいです。 

ターニングポイントは、そのプロセスが拠点での作業と同等であると認識したことです$k$。 減算するたびに最後の桁が減り、除算するたびに 1 桁が削除されます。 これは、ステップ数が次の桁構造に直接関連付けられていることを意味します。$n$基地内で$k$。 実際、各桁はその価値に加えて構造コストに寄与し、きれいな閉じた形式につながります。$$f(n) = (\text{sum of digits of } n \text{ in base } k) + (\text{number of digits}) - 1$$したがって、遷移をシミュレートする代わりに、数字ベースの関数を最大化しています。 

さて、問題は次のとおりです。すべての数字の間で$n \le r$、基数の数字のみに依存する関数を最大化します。$k$。 これは古典的な数字 DP スタイルの構造ですが、完全な DP は必要ありません。 最大値のみが必要であり、目的は各桁で単調です。大きい桁は常に役に立ちます。 

これにより、次のプレフィックスに対する貪欲な構築が可能になります。$r$基地内で$k$。 一致するプレフィックス長を修正します$r$、次に下に落ちる最初の位置で$r$、その数字を 1 つ減らし、残りを次のように埋めます。$k-1$を下回ったまま桁の合計を最大化します。$r$。 

また、ゼロ共通プレフィックスを選択する特殊なケースも処理します。これにより、先頭の桁で許可されている場合、実質的に桁数が 1 つ減ります。

 ## アルゴリズムのチュートリアル

 1.変換$r$その基地に$k$表現。 これにより、各位置が次のべき乗に対応する数字配列が得られます。$k$。 目的関数が数値ベースであるため、これが必要になります。 
2. 考えられるプレフィックス長ごとに$p$から$0$の桁数に$r$、最初のものと一致すると仮定します$p$の桁$r$。 これにより、候補番号の最上位構造が固定されます。 
3. もし$p$が全長に等しい場合、候補は正確に$r$, したがって、その値は桁の合計と桁数から直接計算されます。 
4. それ以外の場合は、位置$p$の桁を減らします。$r$ゼロでない限り、1 ずつ加算されます。 ゼロの場合、事前に長さを短縮しないとより小さい数値を形成できないため、このプレフィックスの選択は無効です。 
5. その桁を減らした後、残りのすべての位置を次のように入力します。$k-1$。 これにより、構築される数値が厳密に以下であることを保証しながら、桁の合計が最大化されます。$r$。 
6. 私たちが選択するなら$p = 0$、より少ない桁数で効果的に数値を構築しています。$r$。 この場合、可能な限り最良の数値は、すべての桁が次と等しいです。$k-1$より桁が 1 つ少ない$r$これにより、制約の下で桁の合計と桁数の両方が最大化されるためです。 
7. 各候補の目標値を計算し、最大値を取得します。 

### なぜ効果があるのか

 任意の数$n \le r$一致する必要があります$r$一部のプレフィックスで、最初の異なる桁が異なります。 その位置では、厳密に小さくする必要があり、それ以降のすべての桁は自由に選択できます。$k-1$。 目標は厳密に各桁で増加し、桁数とともに増加するため、最適なソリューションでは、最初の偏差の後の桁を最大化し、偏差をできるだけ右に遅らせる必要があります。 これにより、接頭辞に対する貪欲な構造が強制され、これらの構築された形式以外の候補が目的を改善できないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def to_base_k(x, k):
    if x == 0:
        return [0]
    digs = []
    while x > 0:
        digs.append(x % k)
        x //= k
    return digs[::-1]

def value(digits):
    # (sum of digits) + (number of digits) - 1
    return sum(digits) + len(digits) - 1

def solve():
    k, r = map(int, input().split())

    digits = to_base_k(r, k)
    n = len(digits)

    best = 0

    # case: use r itself
    best = max(best, value(digits))

    # try prefix matches
    for p in range(n):
        if digits[p] == 0:
            continue

        cand = digits[:p]
        cand.append(digits[p] - 1)
        cand.extend([k - 1] * (n - p - 1))

        best = max(best, value(cand))

    # try shorter length (p = 0 type case)
    if n > 1:
        cand = [k - 1] * (n - 1)
        best = max(best, value(cand))

    print(best)

if __name__ == "__main__":
    solve()
```ベースへの変換$k$減算と除算のプロセスを数字の問題に変換するため、これは不可欠です。 ヘルパーさん`value`派生した式を直接エンコードし、シミュレーションを回避します。 

メインループは、ブレーク元となる最初の位置を列挙します。$r$。 条件`digits[p] == 0`事前に借用しないとその桁を減らすことができない無効なケースをスキップします。 数字を減らしたら、接尾辞を次のように埋めます。$k-1$残りのポジションからの最大の貢献を保証します。 

最後の特殊なケースは、次の桁数より少ない数値を処理します。$r$ここでは、すべてを使用して桁数と桁の合計の両方を個別に最大化します。$k-1$数字。 

## 実用的な例

 ### 例 1

 しましょう$k = 10$、$r = 274$。 10 進数の数字は、$[2, 7, 4]$。

 | --- | --- | --- |
 | 3 | [2、7、4] | 2+7+4+3-1 = 15 |

 最も良いのはプレフィックス 1 で、21 になります。これは、桁数とサフィックスの最大化が相互作用するため、偏差を早めることが時々支配的になる理由を示しています。

| 接頭辞 p | 候補数字 | 値 |

 ## 特殊なケース

 重大なエッジケースは次のような場合です。$r$の力です$k$、 のような$1000_k$。 単純なプレフィックス削減では、ゼロ桁を削減しようとするのが遅すぎる可能性があり、これは無効です。 アルゴリズムはそのようなプレフィックスを正しくスキップし、代わりに以前の位置またはより短い長さの構造に依存します。 

もう一つのエッジケースは、$r < k$、基本表現は 1 桁です。 この場合、候補は 2 つだけ存在します。$r$それ自体と$k-1$。 プレフィックス ループは意味のあるものを何も提供せず、短い長さのケースが存在しないか適切に優先され、特別なケースを使用せずに正しい結果を生成するため、アルゴリズムは当然両方をカバーします。
