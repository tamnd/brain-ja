 ## 解決策
 ## 問題の理解

 1 から始まる自然数の無限シーケンスが与えられます。Polycarp は特別な除去操作を正確に実行します。$x$回。 各操作では、次の倍数の位置にあるすべての数値が削除されます。$y$現在のシーケンスでは。 これらの操作の後、最終的に次の値になる数値を見つけたいと思います。$k$最終シーケンスの - 番目の位置、または次の位置よりも少ないと判断します。$k$残った数字。 

入力は複数のテスト ケースを提供します。 各テスト ケースが提供するのは、$x$、$y$、 そして$k$。 数字$x$そして$y$と同じ大きさにすることができます$10^{12}$つまり、シーケンスを明示的に構築したり、すべての削除をシミュレートしたりするアプローチは不可能です。 出力は、テスト ケースごとに 1 つの整数であり、$k$-番目の残りの番号、または$-1$シーケンスが短すぎる場合。 

主な課題は、非常に大きなシーケンスを効率的に処理することです。 単純なシミュレーションでは、次のことを試みます。$10^{12}$計算上実​​行不可能な操作です。 各演算でいくつの数値が削除されるか、また数値がどこに残るかについて、慎重な数学的推論が必要です。 

エッジケースが発生するのは次の場合です$y=1$、すべての操作で残りの番号がすべて削除されるため、$k$が大きすぎるため、シーケンスはそれに到達する前に使い果たされてしまいます。 たとえば、次の場合$x=1$、$y=1$、$k=1$、残りのシーケンスは空であり、答えは次のようになります。$-1$。 もし$x$大きいですが$k$が除去数に比べて小さい場合、答えは存在し、式を使用して計算できます。 

## アプローチ

 ブルートフォース手法はシンプルです。数値の配列を維持し、すべての数値を繰り返し削除します。$y$-番目の要素$x$回。 これは操作を正しくシミュレートしますが、各削除は一連の長さで行われます。$n$費用$O(n)$時間と繰り返し$x$時代は～につながる$O(x \cdot n)$、これは不可能です$n, x$まで$10^{12}$。 

重要な観察は、その後です。$x$操作では、残りの数字の位置はパターンに従います。 具体的には、すべての操作ですべての数値から 1 つの数値が削除されます。$y$連続した数字。 シーケンスの最終的な長さを次のように表すと、$n_{\text{final}}$、その後、各操作は元のシーケンス内の数値の実効インデックスをスケーリングします。 これを使用すると、目的の値に到達するためにスキップする必要がある元の数値の数をモデル化できます。$k$最終シーケンスの - 番目の番号。 

形式的に、次のように表すと、$z$の前に削除された数値の数として$k$- 番目の数から、線形ディオファントス関係を導き出すことができます。$$\text{remaining numbers} = \text{original number} - \text{number of removed multiples of } y$$この関係を使用すると、効率的に$k$すべての削除をシミュレートせずに、元のシーケンスに対する **二分探索** による - 番目の数値。 二分探索では、元のシーケンス内の現在の候補番号が少なくとも残っているかどうかを確認します。$k$後の数字$x$除去作業。

 | --- | --- | --- | --- |
 | ブルートフォース | O(x * n) | O(n) | n、x には遅すぎます$10^{12}$|

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、次の内容を読んでください。$x$、$y$、$k$。 
2. 関数を定義する`count_remaining(n)`これは、最初の要素を考慮した場合に残っている要素の数を返します。$n$実行後の自然数$x$削除操作:$$\text{remaining} = n - x \cdot \left\lfloor \frac{n-1}{y} \right\rfloor$$この式は、各削除が約$n//y$数字とそれを実行する$x$この効果は倍増します。 
3. 二分探索境界を初期化します。`low = 1`、`high = k * y * x`。 上限は保守的です。 最悪の場合、削除ごとに 1 つの数字がスキップされます。$y$ポジション。 
4. 二分検索を実行します。 

- コンピューティング`mid = (low + high) // 2`。 
- もし`count_remaining(mid) >= k`、 セット`high = mid`。 
- それ以外の場合は設定します`low = mid + 1`。 
- まで繰り返します`low == high`。 
5. 二分探索後、`low`は、少なくとも次のような元のシーケンス内の最小の数です。$k$数字はその後も残ります$x$撤去。 
6. もし`count_remaining(low) < k`、出力`-1`; それ以外の場合は出力`low`。 

なぜそれが機能するのか: 公式`count_remaining(n)`厳密に増加しています$n$。 二分探索はこの単調性を利用して最小の数を見つけます。$n$条件を満たすものです。 正確さは、除去を次の倍数としてモデリングすることから導き出されます。$y$、二分探索により、正確に到達することが保証されます。$k$-番目の残りの数。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(x, y, k):
    # function to compute number of remaining elements after x removals in first n numbers
    def count_remaining(n):
        return n - x * ((n - 1) // y)
    
    low, high = 1, k * y * x
    while low < high:
        mid = (low + high) // 2
        if count_remaining(mid) >= k:
            high = mid
        else:
            low = mid + 1
    return low if count_remaining(low) >= k else -1

t = int(input())
for _ in range(t):
    x, y, k = map(int, input().split())
    print(solve_case(x, y, k))
```このソリューションでは、残りの数値のヘルパー関数を定義し、元の数値の位置に二分探索を適用します。 の選択`high = k * y * x`解が境界内にあることを保証し、無限の探索を回避します。 Python では任意の精度があるため、大きな整数を安全に処理できます。
