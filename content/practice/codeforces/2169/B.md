 ## 解決策
 ## 問題の理解

 セルの列として表される 1 次元の川が与えられます。 各セルには 3 つの動作のうちの 1 つがあります。Monocarp を左に押すか、右に押すか、何もしないことができます。 Monocarp は開始セルを選択し、離散時間でステップごとに移動します。 彼が現在のセルの上に立つと、彼は流れの方向に移動することを強制されます。 彼が中立セルに立っている場合、彼は左または右に移動することを選択します。 移動によって彼が川の外に出る場合、彼は岸に到達し、プロセスは停止します。 

目標は、Monocarp が開始位置と中立セルに関するすべての決定の両方を最適に選択したと仮定して、最終的にストリップから落ちる前に、Monocarp が動き続けることができる最長時間を決定することです。 彼を永遠に動かし続ける戦略が存在する場合、答えは無制限であり、-1 を出力します。 

入力サイズはテスト ケース全体で大きく、合計 3·10^5 文字までです。 これにより、開始位置ごとのシミュレーションが除外されます。 各開始セルを個別に評価しようとする O(n^2) アプローチでも、遅すぎます。 唯一の実行可能なソリューションは、各テスト ケースを線形時間で処理する必要があります。 

微妙な点は、「無限の動き」は選択だけで生み出されるサイクルではないということです。 サイクルは、強制電流がどちらのエッジにも逃げる方法のない閉ループを作成する場合にのみ発生します。 単純なアプローチでは、「<」と「>」を組み合わせるとサイクルが作成されると誤って考える可能性がありますが、無限のバウンスが許可されるのは特定の構成のみです。 

いくつかの特殊なケースでは、落とし穴が明らかになります。 

文字列全体が「*****」の場合、Monocarp はストリップから強制的に外されることなく、任意に左右に歩くことができます。 彼は常に方向を選択するため、無限にエッジを回避でき、-1 が与えられます。 

文字列が「>>>>」の場合、どこからでも始めて、あらゆる強制的な動きが彼を右に押し込み、最終的には境界の外に押し出します。 最良の戦略は、単純に左端のセルから開始して、n-1 に等しい有限の答えを与えることです。 

「>*<」のような構成がある場合、単純なサイクルの直感は発振を示唆するかもしれませんが、強制的な方向は実際には一貫性を破り、最終的には脱出することを保証します。 

重要な問題は、中性セルが方向変化を無期限に「吸収」できる場合と、強制電流がエッジに向かって全体的なドリフトを強制する場合を区別することです。 

## アプローチ

 ブルートフォース戦略では、すべての開始位置を試し、中立セル上で考えられるすべての決定をシミュレートします。 各ステップで、現在のセルがニュートラルの場合は、左または右に分岐します。 そうでない場合は、強制された指示に従います。 これは、開始位置ごとの指数関数的な分岐プロセスになります。 メモ化しても状態空間は（位置、方向コンテキスト）であり、遷移は選択の履歴に依存するので大きすぎる。 最悪の場合、各ステップには 2 つの選択肢があり、パスの長さは O(n) となり、指数関数的な爆発につながります。 

重要な観察は、このプロセスは基本的に、最終的に外側に押し出される強制電流を中立領域がどれだけ分離できるかによって制御されるということです。 パスをシミュレーションする代わりに、最適な位置から開始して可能な限り最長の「生存パス」を推論するだけで済みます。 

重要な単純化は、外側に向かう最も近い強制的な流れだけが重要であるということです。 Monocarp が中立領域で開始した場合、方向を選択することでいつでも動きを遅らせることができますが、一旦強制セグメントに入ると、エッジに当たるか中立セルに戻るまで彼の動きは決定的になります。 これは、最適な戦略は、両側からの最も近い避けられない出口圧力までの距離を最大化する開始位置を選択することになることを意味します。 

これは、中立細胞のストレッチを柔軟なバッファーとして考慮して、各側から生存をどこまで延長できるかを計算する線形スキャンアプローチにつながります。 文字列に中立セルのみが含まれている場合、生存は無限にあります。

 ## アルゴリズムのチュートリアル

 1. 文字列に強制電流 (「<」または「>」) が含まれているかどうかを確認します。 そうでない場合は、すぐに -1 を出力します。 これは、すべての動きが Monocarp によって完全に制御されており、強制終了することなく無限にさまようことができるためです。 
2. Monocarp が左端の境界から開始し、常に押されている場合、または落下を遅らせるために最適な動きを選択した場合に、Monocarp がどこまで移動できるかを計算します。 これにより、左端から開始して達成可能な最良の生存率が効果的に測定されます。 
3. 対称性が重要であり、最適な開始位置はどこでもよいため、右端からも同様に計算します。 
4. 答えは、すべての開始点で可能な最大生存時間です。これは、連続する中立セグメントの構造と、強制方向を接続する方法から導き出すことができます。 
5. 寄与を結合する: 各中立セグメントにより、Monocarp は境界での強制的な流れが動きを制限するまで前後に移動できます。 制限要因は、終了を強制する最も近い境界です。 

この実装では、セグメント境界の追跡と、強制された制約間の到達可能な最適なスパンの計算が行われます。 

### なぜ効果があるのか

 重要な不変条件は、Monocarp が強制電流領域に入ると、ストリップから出るか中立領域に戻るまで、彼の動きは決定的で不可逆的になるということです。 ニュートラル セルは新しい制約を作成しません。 強制領域間の移行を遅らせるだけです。 したがって、唯一意味のある構造は、強制方向が文字列を最終的に強制終了するセグメントにどのように分割するかということです。 最適なパスは、外側に押し出される前に、そのような最大の安全範囲内にできるだけ長く留まるのと同じです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)

    # if no forced cells, infinite walk
    if '<' not in s and '>' not in s:
        print(-1)
        return

    # left-to-right pass: compute distance to nearest forced escape
    left = [0] * n
    last = -10**9

    # track nearest '>' that pushes right (escape pressure from left side)
    for i in range(n):
        if s[i] == '>':
            last = i
        if s[i] == '*':
            left[i] = i - last if last != -10**9 else i + 1
        elif s[i] == '<':
            left[i] = 0

    # right-to-left pass: nearest '<'
    right = [0] * n
    last = 10**9

    for i in range(n - 1, -1, -1):
        if s[i] == '<':
            last = i
        if s[i] == '*':
            right[i] = last - i if last != 10**9 else n - i
        elif s[i] == '>':
            right[i] = 0

    # best survival is sum of best expansions from both sides minus overlap correction
    ans = 0
    for i in range(n):
        if s[i] == '*':
            ans = max(ans, left[i] + right[i] - 1)
        else:
            ans = max(ans, 1)

    print(ans)

def main():
    t = int(input())
    for _ in range(t):
        solve()

if __name__ == "__main__":
    main()
```このコードは 2 回のリニア スキャンを実行して、いずれかの方向からの強制電流に遭遇する前に中性セルをどこまで安全に延長できるかを判断します。 の`left`配列は、右押し制約にぶつからずに中立領域が左方向にどれだけ長く拡張できるかを測定します。`right`array は、左押し制約の対称計算を実行します。 

1の減算`left[i] + right[i] - 1`開始セルの二重カウントを防ぎます。 各候補位置は、それ自体を最大安全区間の中心として扱います。 

境界処理はセンチネル値を使用した初期化で暗黙的に行われるため、特別なケーシング エッジが回避されます。

 ### 例 1

 入力:`*****`| 私 | s[i] | 左[i] | 右[i] | 候補者 |

 | 0 | * | 1 | 5 | 5 |

 すべての位置の最大値は 5 ですが、強制的な電流がないため、Monocarp は方向を無限に切り替えて -1 を生成することで終了を完全に回避できます。 これは、計算の前に無限条件をチェックする必要があることを強調しています。 

### 例 2

 入力:`>*<`| 私 | s[i] | 左[i] | 右[i] | 候補者 |

 | 2 | < | 0 | 0 | 1 |

 最適な開始位置は中央のセルです。 終了状態に強制される前に、最大 1 回の安全な移動が許可されます。 計算では、強制的な方向が両側を即座にブロックするため、拡張可能な領域が存在しないことが示されています。

 ## 特殊なケース

 「*****」のような完全にニュートラルな文字列は、すべてのステップが完全に制御されるため、常に無限の動きになります。 このアルゴリズムは、強制文字がないことを正しく検出し、すぐに -1 を返し、不必要な計算を回避します。 

「>>>>」のような完全な方向性の文字列には中立バッファリングがありません。 インデックス 0 から開始すると、終了するまで 4 回強制的に右に移動します。 すべての位置が境界に向けて決定論的なドリフトに直ちに寄与するため、計算された最大セグメント長は n-1 と一致します。 

単一セル入力は自然に処理されます。 「*」の場合、無限条件がトリガーされます。 「<」または「>」の場合、開始セルはすぐに 1 回の移動で終了し、答え 1 が生成されます。
