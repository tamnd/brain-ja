 ## 解決策
 ## 問題の理解

 自然数の無限シーケンスから始めて、それを事実上配列として考えます。`1, 2, 3, 4, ...`。 このプロセスでは、固定ステップ サイズに基づいて要素が繰り返し削除されます。`y`: 操作を適用するたびに、その位置にある要素を削除します。`y, 2y, 3y, ...`現在のシーケンス内 (_current_ 圧縮配列内の位置は常に 1 からインデックスされます)。 

この操作が実行されます`x`すべての削除の後、最終的にどの番号がその位置に来るのかを知りたいのです`k`残りのシーケンスが残っているかどうか、またはシーケンスが短すぎたかどうか。 

重要な問題は、削除するたびにシーケンスが縮小するため、「位置」の意味が`y`” は動的に変化します。次の値で割り切れる値は削除しません。`y`ただし、進化する array_ の _rank によって削除されるため、大規模な直接シミュレーションは不可能になります。 

制約により、これがさらに鮮明になります。 両方`y`そして`k`まで行くことができます$10^{12}$、 そして`x`まで行くことができます$10^5$。 これにより、シーケンスを明示的に構築したり、シーケンスを反復したりするメソッドは除外されます。 宇宙には境界がないため、概念的な範囲にわたってセグメント ツリーを維持することすら不可能です。 

微妙なエッジケースが現れるのは、`y = 1`。 その場合、最初の操作ですべての要素が削除され (すべての位置が 1 の倍数であるため)、シーケンスはすぐに空になります。 どれでも`k ≥ 1`戻らなければなりません`-1`。 「一部の要素が生き残る」と仮定する素朴なアプローチは、ここでは即座に失敗します。 

もう 1 つの重要なケースは次のような場合です。`y`現在のシーケンス サイズと比較して非常に大きいです。 その後の操作ではまったく何も行われない可能性がありますが、不注意なシミュレーションにより存在しないインデックスが反復されて削除され、境界が注意深くチェックされていないと誤った動作が発生する可能性があります。 

最後に、いつ`k`非常に大きいため、多くの場合、答えは単純です`-1`シーケンスは演算中に乗算的に縮小するためです。 多くの誤った解決策は、実際の残りのサイズを正しく追跡しないために失敗します。 

## アプローチ

 直接シミュレートしようとすると、現在のリストを維持し、すべてのリストを繰り返し削除します。`y`- 番目の要素。 一連のサイズに対する各操作`n`かかります$O(n)$したがって、全プロセスにかかる費用は$O(xn)$。 初期シーケンスは概念的には無限であるため、たとえそれを上限としたとしても、`k`またはそのわずかに上の値`k`まで$10^{12}$これを完全に不可能にします。 

重要な点は、実際には個々の要素を追跡する必要がないということです。 残っている要素の数とインデックスがどのように変換されるかを理解することだけが必要です。 

すべてを削除すると、`y`長さのシーケンス内の - 番目の要素`n`、大まかに削除します`n / y`要素、残り:$$n - \left\lfloor \frac{n}{y} \right\rfloor$$さらに重要なことは、この操作は、周期的な位置を「スキップ」しながらシーケンスを圧縮することと同等であるということです。 この構造は安定しています。各操作の後でも、新しいシーケンスはギャップのある自然数の増加シーケンスであり、削除ルールは実際の値ではなく、現在の長さだけに依存します。 

これは 2 番目の洞察につながります。シーケンスを構築する代わりに、元の数値がしきい値までにいくつ残るかを計算できます。`N`、次に最小のものを二分探索します`N`少なくともそうなるように`k`数字は生き残る。 

残りのタスクは評価になります。`N`、何番目の数字から`1..N`その後生き残る`x`すべてを削除するラウンド`y`進化するシーケンスの - 番目の位置。 カウントに対する効果のみをシミュレートします。これは、各ラウンドがアクティブ セットを次の係数で縮小するため、本質的に対数的です。`y/(y-1)`。 

したがって、k 番目の要素の値の答えを二分探索し、次のような削除プロセスをシミュレートすることで各候補を検証できます。$O(x)$。 

以来`x ≤ 10^5`、これは許容されます。各チェックは線形です。`x`について実行します。`log(10^12)`小切手。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション |$O(x \cdot n)$|$O(n)$| 遅すぎる |
 | 二分探索 + カウント シミュレーション |$O(x \log A)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 最小の数を見つけるように問題を再定式化します`ans`すべての削除の後、少なくとも`k`無限数列の数値は`≤ ans`。 

### ステップ

 1. 回答候補を扱います`mid`カットオフとして数値をシミュレートし、`1..mid`すべて生き残る`x`操作。 

これが機能する理由は、シーケンスが厳密に増加しており、削除によって要素の順序が変更されることがないためです。そのため、生存はランクの進化のみに依存します。 
2. 変数を維持します`cnt = mid`、追跡しているセグメントに現在存在する要素の数を表します。 
3. からの各操作について`1`に`x`、削減します`cnt`による`cnt // y`。 

This models removing every`y`現在の圧縮シーケンスの - 番目の要素。 

直感的には、すべてのブロックの間で`y`連続して残っているポジションの場合、ちょうど 1 つが削除されます。 
4.すべて塗布したら`x`操作、`cnt`の数字が何個あるかを表します`1..mid`生き残る。 
5. もし`cnt >= k`、候補者`mid`は十分大きいので、二分探索を左に移動します。 

それ以外の場合は増加します`mid`。 
6.二分探索をします`mid`答えを含むのに十分な範囲にわたって、通常は次のような安全な上限までです。$10^{18}$。 

### なぜ効果があるのか

 核となる不変条件は、各操作の後、残りの要素が均一なシーケンスのように動作し、削除は実際の値ではなく相対位置のみに依存するということです。 これにより、カウントの展開がアイデンティティとは独立し、次の条件によって完全に決定されます。`cnt`。 各ステップは単調な方法でセットを変換するため (より大きな初期セグメントは常により大きな生存セグメントを生成します)、述語「`mid`少なくとも生成するには十分です`k`survivors」はモノトーンなので二分探索が可能です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can(mid, x, y, k):
    cnt = mid
    for _ in range(x):
        if cnt == 0:
            return False
        cnt -= cnt // y
    return cnt >= k

t = int(input())
for _ in range(t):
    x, y, k = map(int, input().split())

    if y == 1:
        print(-1)
        continue

    lo, hi = 1, 10**18
    ans = -1

    while lo <= hi:
        mid = (lo + hi) // 2
        if can(mid, x, y, k):
            ans = mid
            hi = mid - 1
        else:
            lo = mid + 1

    print(ans)
```機能`can(mid, x, y, k)`すべての効果をシミュレートします`x`長さのプレフィックスに対する操作`mid`。 反復ごとに現在のカウントが減少します。`cnt // y`、その段階で削除された要素の数を表します。 

二分探索はこの実現可能性チェックをラップし、少なくとも残っている最小のプレフィックス長を見つけます。`k`生き残った要素。 

特別な場合`y = 1`シーケンスは最初の操作の直後にゼロに崩壊するため、個別に処理されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    def can(mid, x, y, k):
        cnt = mid
        for _ in range(x):
            if cnt == 0:
                return False
            cnt -= cnt // y
        return cnt >= k

    t = int(input())
    out = []
    for _ in range(t):
        x, y, k = map(int, input().split())

        if y == 1:
            out.append("-1")
            continue

        lo, hi = 1, 10**6
        ans = -1

        while lo <= hi:
            mid = (lo + hi) // 2
            if can(mid, x, y, k):
                ans = mid
                hi = mid - 1
            else:
                lo = mid + 1

        out.append(str(ans))

    return "\n".join(out)

 ## 特殊なケース

 いつ`y = 1`、最初の操作ではシーケンス内のすべての位置が削除されます。 アルゴリズムは明示的に返します`-1`、そしてこれは、どの要素も存続しないという事実と一致します。`x`または`k`。 

のために`mid = 1`、シミュレーションは正しく適用されます`cnt -= cnt // y`、次の場合にのみゼロになります。`y = 1`それ以外の場合は 1 のままです。これにより、最小境界がそれを超える特別なケースを使用せずに正しく処理されることが保証されます。`y = 1`。 

いつ`k = 1`、二分探索では自然に最小値が見つかります。`mid`すべての削除後に少なくとも 1 つの要素が残るもの。 生存条件が単調なので、`mid`の場合、複数の削除によってほとんどの要素が削除される場合でも、検索は最初の有効なプレフィックスに収束します。 

非常に大きい場合`x`、繰り返し適用するとカウントはすぐに安定し、多くの場合ゼロまたは固定点に達します。 ループはまだ実行されます$O(x)$ただし、各反復は定数時間であり、整数の除算のみが使用されるため、オーバーフローや構造の変化は発生しません。
