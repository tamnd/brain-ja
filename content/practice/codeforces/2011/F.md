 ## 解決策
 ## 問題の理解

 単一の整数から始まり、配列内の既存の要素よりも同じ数、1 つ少ない数、または 1 つ多い数を繰り返し追加するプロセスによって各部分配列が生成されるように、指定された整数配列の連続するすべての部分配列をカウントするように求められます。 簡単に言うと、サブ配列内の任意の 2 つの要素間の差が最大 1 であり、そのサブ配列内で前に確認された数値から 1 ずつ増減することで中間の数値に到達できる場合、そのサブ配列は「良好」です。 

入力は複数のテスト ケースで構成され、それぞれが最大 300,000 のサイズの整数配列を持ち、すべてのテスト ケースのすべての配列サイズの合計が 300,000 を超えません。 時間制限が 3 秒であることは、要素あたりの時間が線形より悪いアルゴリズムは遅すぎる可能性があることを意味します。 考えられるすべてのサブ配列を明示的にチェックするブルート フォース アプローチには、大まかに次の作業が含まれます。$O(n^2)$テスト ケースごとに操作を行う必要がありますが、上限を考えると実行不可能です。 

いくつかの特殊なケースは微妙です。 要素が繰り返される配列、厳密に増加または減少するシーケンスを形成する配列、または 1 を超える突然のジャンプがある配列はすべて、サブ配列が適切であるかどうかに影響を与える可能性があります。 たとえば、配列では`[1, 3]`、サブ配列`[1, 3]`は2が足りないのでダメです。 中間数値が出現するかどうかを考慮せずに、隣接する差分だけをチェックする単純なアプローチでは、そのような部分配列が誤って分類されてしまいます。 

## アプローチ

 ブルートフォース手法は簡単です。開始インデックスごとに、必要な中間値がすべて存在し、相互に最大 1 の差があるかどうかを確認しながら、部分配列を右に拡張します。 これは、「適切な」部分配列の定義を直接反映しているため機能します。 問題は、$\frac{n(n+1)}{2}$合計でおよそに達するサブ配列$4.5 \cdot 10^{10}$操作時の操作$n=3 \cdot 10^5$。 これは許容範囲をはるかに超えています。 

最適化のための重要な洞察は、「適切な」サブ配列の最大長が、それに含まれる個別の値の数によって制限されることを観察することから得られます。 適切なサブ配列には相互に最大 1 つだけ異なる値しか含めることができないため、適切なサブ配列は 3 つを超える連続する整数にまたがることはできません。 これにより、個別の要素のセットのサイズが最大 3 である部分配列に注目を限定することができます。 

さらに、長さが 3 を超える配列を調べると、良好なサブ配列の内部構造は高度に制限されています。 最小値と最大値の間には最大 1 つの「中間」値が存在できます。そうでない場合は、許可された操作によってその値を生成できません。 これにより、問題はスライディング ウィンドウ タスクに変換されます。最小値、最大値、および中間値の存在を追跡するウィンドウを維持し、ウィンドウが無効になるまで右に拡張し、その後、左側の境界を前方に移動します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | スライディング ウィンドウ + 値の追跡 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. カウンタを初期化する`ans`ゼロに。 これにより、現在のテスト ケースの良好なサブ配列の総数が保存されます。 
2. 2 つのポインターを使用します。`l`そして`r`、考慮されている配列の現在のウィンドウを表します。 両方を配列の先頭から開始します。 
3. 現在のウィンドウ内の各数値の出現をカウントするために、小さな頻度辞書または配列を維持します。 ウィンドウ内の最小値と最大値を記録してください。 
4. 右ポインタを展開します`r`一度に 1 つの要素。 周波数マップを更新して調整する`min_val`そして`max_val`それに応じて。 
5. 要素を追加した後、現在のウィンドウが有効なままであるかどうかを確認します。 以下の違いがある場合、ウィンドウは無効です。`max_val`そして`min_val`2 を超えるか、範囲内の 3 つの可能な値すべてが満たされている場合`[min_val, max_val]`許可された操作で配列を生成できるように配置されていません。 
6. 無効な場合は、左ポインタを移動します。`l`ウィンドウが再び有効になるまで右に動かし、要素が削除されると周波数マップが減少します。 
7. 各ステップの後に、`r`、で終わるすべてのサブ配列`r`間の任意のインデックスから開始します`l`そして`r`良いものであることが保証されています。 追加`r - l + 1`に`ans`。 
8. 配列全体が処理されたら、保存または印刷します。`ans`テストケースの結果として。 

機能する理由: このアルゴリズムは、現在の右側の境界で終わる最大の連続した良好なサブ配列を常に表すスライディング ウィンドウを維持します。 不変条件は、ウィンドウは貪欲に拡張され、必要な場合にのみ縮小されるため、このウィンドウ内に含まれるすべてのサブ配列が良好であるということです。 それぞれで終わるすべてのサブ配列を数えることにより、`r`、すべての可能な連続した良好なサブ配列を 1 回だけ計算します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def count_good_subarrays(a):
    n = len(a)
    ans = 0
    l = 0
    freq = {}
    
    for r in range(n):
        freq[a[r]] = freq.get(a[r], 0) + 1
        while True:
            keys = list(freq.keys())
            if max(keys) - min(keys) > 2:
                freq[a[l]] -= 1
                if freq[a[l]] == 0:
                    del freq[a[l]]
                l += 1
            else:
                break
        ans += r - l + 1
    return ans

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    print(count_good_subarrays(a))
```このコードは、辞書を使用して、現在のスライディング ウィンドウ内の要素の頻度を追跡します。 新しい要素ごとに、周波数マップが更新され、値の範囲が 2 を超えているかどうかがチェックされます。超えている場合は、ウィンドウが再び有効になるまで、左側の境界が増分されます。 それぞれで終わるすべてのサブ配列を数える`r`で終わります`r - l + 1`。 辞書を使用すると、任意の値の範囲を確実に処理できますが、この問題では`1 ≤ a[i] ≤ n`、固定サイズの配列も機能する可能性があります。
