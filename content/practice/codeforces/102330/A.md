 ## 解決策
 ## 問題の理解

 配列があります`a`の`n`動物。 値`a[i]`アイボリット医師が動物を検査するのに必要な時間です`i`。 医師は一度に 1 頭の動物を扱うため、動物は 1 つの列を形成します。 

選択した順序に対して、最初の動物が待機します`0`時間単位。 2 番目の動物は、最初の動物の検査が完了するまで待ちます。 3 番目は最初の 2 つの検査を待ち、以下同様に続きます。 すべての待機時間の合計ができるだけ小さくなるように、配列要素の順序を選択する必要があります。 

たとえば、試験時間が次のとおりであるとします。`[5, 1, 2]`そして私たちは順序を使用します`[1, 2, 5]`、待ち時間は`0`、`1`、 そして`3`、合計を与えます`4`。 

到達できる動物の数`10^6`、すべての試験時間は最大でも`10^5`。 次のようなアルゴリズム`O(n^2)`すでに約必要になります`10^12`1 秒の制限をはるかに超える最悪の場合の操作。 平`O(n log n)`入力自体に 100 万個の数値が含まれるため、かなり効率的に実装する必要がありますが、簡単に実現可能です。 答えは 32 ビット整数よりもはるかに大きくなる可能性があります。`10^6`試験時間は同じです`10^5`、答えは約です`5 * 10^16`。 Python の整数はこれを自動的に処理します。 

間違いが明らかになる可能性のある小さなケースがいくつかあります。 たとえば、1 匹の動物の場合、入力は次のようになります。```
1
7
```そして答えは`0`、誰も待ってくれないからです。 解答を蓄積する前に現在の試験時間を加算する実装では、誤った結果が生成されます。`7`。 

検査時間が等しい場合、すべての注文は同等です。 のために```
5
2 2 2 2 2
```待ち時間は`0, 2, 4, 6, 8`、したがって、答えは次のとおりです`20`。 この場合、誤って降順に並べ替えたソリューションは失敗しません。これにより、等しい値は、順序のみに依存するのではなく、数式自体が正しいことを確認するのに役立ちます。 

もう 1 つの一般的なエッジ ケースは、入力内で後から現れたとしても、最も背の低い動物を最初に処理する必要があることです。 のために```
3
7 1 2
```最適な順序は`1, 2, 7`、待ち時間を与える`0, 1, 3`そして答える`4`。 動物を入力順に処理するだけで、`0 + 7 + 8 = 15`したがって、配列の順序を変更しない実装はすぐに失敗します。 

## アプローチ

 直接的な力ずくのアプローチでは、動物のあらゆる可能な順序が試行されることになります。 各順列について、それを左から右にスキャンし、すでに実行された検査時間の合計を保持し、その値をすべての動物の答えに追加できます。 これは正しいです。考えられるすべてのスケジュールが考慮され、待機時間の合計が最小のものを選択できるからです。 

問題は順列の数です。 がある`n!`可能な注文、および 1 つの注文の評価には時間がかかります`O(n)`時間なので、全体の複雑さは次のようになります。`O(n · n!)`。 たとえ`n = 20`、これはすでに巨大です。 のために`n = 10^6`、単に遅すぎるだけでなく、スケジュールを列挙し始めることができません。 

待ち時間の構造により、より強力な観察が可能になります。 連続する 2 匹の動物に検査時間があったとします。`x`そして`y`、そして彼らの前にあるすべてのものはすでに取られています`T`時間。 注文が`x, y`、合計待ち時間への寄与は次のとおりです。`T + (T + x) = 2T + x`。 

それらを次のように置き換えると、`y, x`、彼らの貢献度は`T + (T + y) = 2T + y`。 

違いは次の点にのみ依存します`x`そして`y`。 もし`x > y`、置く`y`まず合計を小さくします。 したがって、より長い検査が短い検査の直前にある場合は常に、それらを交換することでスケジュールが改善されます。 

このような逆転の除去を繰り返すことにより、検査時間は昇順にソートされる。 すべての反転は答えを悪化させるだけであるため、配列を最小から最大の順に並べ替えることによって最適なスケジュールが得られます。 

順序がわかったら、すべての待ち時間を明示的に保存する必要はありません。 維持する`prefix`、すでに処理されたすべての動物の合計検査時間。 現在の動物は正確に待機します`prefix`時間単位なので追加します`prefix`答えに到達してから増加します`prefix`現在の試験時間までに。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |`O(n · n!)`|`O(n)`| 遅すぎる |
 | 最適 |`O(n log n)`|`O(n)`| 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む`n`そして`n`検査時間を配列に格納します。 目的は最適な順序を見つけることだけであるため、元の位置は重要ではありません。 
2. 配列を非降順で並べ替えます。 短い検査は、検査後のすべての動物にとって、待ち時間に追加される時間が短縮されることで恩恵を受けるため、より早く実施されるべきです。 
3.初期化`prefix = 0`そして`answer = 0`。 ここ`prefix`は、現在の動物の前にすでに配置されているすべての動物の合計検査時間を表します。 
4. ソートされた配列を左から右に走査します。 現在の試験時間に関しては`x`、 追加`prefix`に`answer`、まさに`prefix`この動物が診察室に入るまでに、単位時間が経過します。 
5.追加`x`に`prefix`。 現在の動物は処理されているため、その検査時間は後続のすべての動物の待ち時間の一部になります。 
6. すべての動物が処理された後、出力`answer`。 最初の動物の寄与はゼロです。`prefix`は最初はゼロです。 

### なぜ効果があるのか

 隣接する 2 つの試験時間が含まれるスケジュールを考慮します。`x`そして`y`と`x > y`。 これら 2 匹の動物の前にあるすべてのものには一定の量がかかります`T`。 順番に`x, y`、彼らの貢献度の合計は`2T + x`、注文中に`y, x`それはです`2T + y`。 以来`y < x`、それらを交換すると、合計待ち時間が厳密に減少します。 

したがって、最適なスケジュールには隣接する反転を含めることはできません。 配列がソートされていない場合、配列には反転があり、反転した隣接するペアを繰り返し交換すると、最終的には答えが増加することなく非減少の順序が生成されます。 したがって、ソート順序は最適です。 ソート後、プレフィックスの合計は現在の各動物の待機時間と正確に等しくなるため、それを累積すると最小の合計が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    a.sort()

    prefix = 0
    answer = 0

    for x in a:
        answer += prefix
        prefix += x

    print(answer)

if __name__ == "__main__":
    solve()
```最初の 2 行には動物の数と検査時間が表示されます。 この問題にはテスト ケースが 1 つだけあるため、外側のテスト ケース ループは必要ありません。`a.sort()`試験時間を必要な最短順に並べます。 Python の組み込みソートは以下で実行されます。`O(n log n)`100 万の整数に対して十分効率的に実装されます。 

ループは意図的に追加します`prefix`に`answer`現在の値を追加する前に`x`に`prefix`。 この順序は必須です。 現在の動物は自分自身の検査を待たず、その前の動物の検査を待つだけです。 配列の場合`[1, 2, 3]`、答えに使用される接頭辞のシーケンスは次のとおりです。`0, 1, 3`、 ない`1, 3, 6`。 

Python の整数型もオーバーフローを回避します。 考えられる最大の答えは次のとおりです。`5 * 10^16`これは符号付き 32 ビット整数を超えますが、Python はそのような値を正確に表します。 

入力サイズが大きいため、ソリューションでは次のように使用します。`sys.stdin.readline`要求どおりに。 メモリ使用量の大部分は、100 万要素の配列の保存によって占められます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |`O(n log n)`| ソートはリニア スキャンよりも優先されます。 
| スペース |`O(n)`| 配列にはすべてが格納されます`n`試験時間 |

 のために`n = 10^6`100 万個の整数をソートするのは実用的ですが、次のスキャンでは`O(n)`追加の操作。 答えは大まかに到達できます`5 * 10^16`、Python 整数はそれを安全に表します。 

## テストケース```python
import sys
import io

def solve():
    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))

    a.sort()

    prefix = 0
    answer = 0

    for x in a:
        answer += prefix
        prefix += x

    print(answer)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        solve()
        return sys.stdout.getvalue().strip()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

# Provided samples
assert run("5\n2 2 2 2 2\n") == "20", "sample 1"
assert run("5\n5 1 2 7 3\n") == "21", "sample 2"

# Minimum-size input
assert run("1\n7\n") == "0", "one animal waits zero time"

# Already sorted, checks that the prefix is added before the current duration
assert run("3\n1 2 3\n") == "4", "already sorted input"

# Reverse order, checks that sorting is actually performed
assert run("3\n7 2 1\n") == "4", "reverse order"

# All values at the maximum boundary
assert run("4\n100000 100000 100000 100000\n") == "600000", "maximum ai"

# Large n and large values, checks that the answer exceeds 32-bit range
assert run("1000000\n" + "100000 " * 1000000) == "49999950000000000", "maximum n"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1 / 7`|`0`| 最初の動物の最小サイズと待ち時間ゼロ |
 |`3 / 1 2 3`|`4`| プレフィックスは現在の期間の前に追加する必要があります |
 |`3 / 7 2 1`|`4`| 並べ替えが必要です |
 |`4 / 100000 100000 100000 100000`|`600000`| 最大検査時間境界 |
 |`1000000 / all values 100000`|`49999950000000000`| 最大`n`大きな整数の結果 |

 最後のテストは意図的に大きくなっています。 これは、漸近的な動作と、実装が固定幅の 32 ビット アキュムレータを誤って使用していないという事実の両方をチェックします。 

## 特殊なケース

 1 匹の動物の場合、入力は```
1
7
```は変更されずにソートされます。 ループは次から始まります`prefix = 0`、したがって、答えは受け取ります`0`。 それから`prefix`になる`7`、しかしそれを待ってくれる次の動物はいません。 出力は`0`。 

試験時間を均等にするためには、```
5
2 2 2 2 2
```どのような順序でもまったく同じ結果が得られます。 アルゴリズムは 5 つの値を処理し、接頭辞を追加します。`0, 2, 4, 6, 8`、生産`20`。 交換引数では、厳密に長い検査が短い検査の前に行われないことのみが要求されるため、等しい値に対する特別な処理はありません。 

最も背の低い動物が最後に現れる入力の場合、```
3
7 1 2
```並べ替えると順序が変わります`1, 2, 7`。 接頭辞は次のとおりです。`0, 1, 3`、したがって、答えは次のとおりです`4`。 元の注文で生成されるのは、`15`、入力順序の保持が無効である理由を示しています。 

試験時間の最大値については、```
4
100000 100000 100000 100000
```接頭辞は`0, 100000, 200000, 300000`、与える`600000`。 値自体は通常の整数の範囲に問題なく収まりますが、累積された答えははるかに速く増加します。 

最大検査時間の最大数の動物の場合、最初の動物を除くすべての動物は、次の倍数が増加するまで待機します。`100000`。 結果の合計は次のとおりです`100000 * (0 + 1 + 2 + ... + 999999) = 49999950000000000`。 

この実装では、個々の時間単位のシミュレーションや二次関数の動作を行わずに、接頭辞合計不変式を使用してこれを直接計算します。
