 ## 解決策
 ## 問題の理解

 あります`n`電車の車両。 車の中で`i`、`a[i]`化学チームがチケットを購入した後も、座席はまだ空いています。 情報学チームはまさに`k`参加者は、乗車するすべての車両が満席になるようにチケットを購入したいと考えています。 化学参加者以外の誰もそのような車両を共有することはできないため、選択した車両の残りの空席はすべて情報科学参加者によって占有されなければなりません。 

したがって、チームが一連の車両を使用する場合、それらの車両の空き座席の合計数は正確に次のとおりでなければなりません。`k`。 選択した車両は、最初と最後の車両番号に関して可能な限り最小の連続セグメントを形成する必要があります。 が付いている車`a[i] = 0`この車両はすでに満席であり、新しい切符を必要としないため、関連する 2 台の車両間で発生する可能性があります。 最適なセグメントのエンドポイントを出力するだけで済みます。 

たとえば、`a = [1, 2, 3, 4]`そして`k = 5`、2 号車と 3 号車にはちょうど 5 つの自由席があるため、答えは次のようになります。`2 3`。 と`a = [1, 0, 2]`そして`k = 3`, 1号車から3号車まではちょうど3席の空きがあり、真ん中の車両は既に満席となっています。 

車の台数は最大でも`10^5`。 二次アルゴリズムでは次のことを考慮します。`n(n+1)/2`に近い`5 * 10^9`最大サイズの間隔。 これは、競技プログラミングの制限である 1 秒で処理できる範囲をはるかに超えています。 の値`a[i]`そして`k`到達できる`10^9`、それらの合計は以下に達することもあります`10^9`したがって、実装では概念的に、このサイズの合計を安全に処理する整数演算を使用する必要があります。 ここでは、Python の整数にはオーバーフローの問題はありません。 

不注意な実装が失敗する可能性のあるエッジケースがいくつかあります。 まず、答えは1台の車で構成できます。 入力用```
1 5
5
```正しい出力は`1 1`。 少なくとも 2 つ以上の長さのセグメントのみをチェックする実装では、これを見逃してしまいます。 

第二に、答えの中に完全に満員の車が発生する可能性があります。 のために```
3 3
1 0 2
```正しい出力は`1 3`。 中間のゼロは何も寄与しませんが、エンドポイントは依然として次のように報告される必要があります。`1`そして`3`。 

第三に、正確な合計が必要です。 のために```
2 5
2 2
```正しい出力は`-1`。 列車全体の自由席は 4 つだけなので、5 枚のチケットを購入しても、選択した車両すべてを埋めることはできません。 

最後に、値がゼロの車両は、同じ数の非ゼロ車両でエンドポイント距離が異なる複数のセグメントを作成できます。 のために```
5 3
0 1 0 2 0
```正しい出力は`2 4`。 このセグメントには 3 つの空きシートが含まれていますが、ゼロ値のエンドポイントを含めるように拡張すると、間隔が長くなり、結果が悪化します。 

## アプローチ

 直接的な解法では、可能なすべての間隔を列挙できます。`[l, r]`そしてその合計を計算します。 プレフィックス合計を使用すると、各間隔の合計を一定時間で取得できるため、アルゴリズムには次の時間がかかります。`O(n^2)`時間と`O(n)`メモリ。 これは正しいです。最初と最後の車両のすべての可能な選択肢が明示的に検査され、その合計が`k`、最短のものを保持できます。 

問題は間隔の数です。 のために`n = 100000`、 がある`n(n + 1) / 2 = 5,000,050,000`さまざまな間隔。 各合計ルックアップは一定時間ですが、数十億回の反復では遅すぎます。 

重要な観察点は、すべての`a[i]`は非負です。 これにより、区間合計が単調な動作になります。 間隔を右に拡張した場合、その合計は同じままか増加することしかできません。 左の端点を右に移動すると、その合計は同じままか減少することしかありません。 

これはまさに 2 ポインター スライディング ウィンドウに必要な構造です。 窓口を整備しております`[l, r]`とその合計。 延長します`r`合計額に達するか超えるまで`k`。 合計が正確であれば`k`の場合、現在のウィンドウが候補になります。 次に、正の値を削除するとウィンドウが短くなり、より適切な答えが得られるため、可能な限り左側の要素を削除します。 ゼロ値の車については、特別な注意が必要です。これを削除しても合計は変化せず、合計が次と等しいままであっても、答えが短くなる可能性があるためです。`k`。 

すべての間隔が独立して「このセグメントには正確に含まれているか」という質問に答えるため、総当り攻撃が機能します。`k`非負の値により合計が単調になるという観察により、ある間隔からの情報を次の間隔に移動する際に再利用でき、作業を線形時間に減らすことができます。

 ## アルゴリズムのチュートリアル

 1.読む`n`、`k`、および配列`a`。 合計が正確に一致する区間を見つける必要があります。`k`、最小の長さ。 
2. 左ポインタを初期化します。`l = 0`、現在の合計`s = 0`、およびこれまでに見つかった最良の間隔を格納する変数。 
3. 右ポインタを移動します`r`左から右へ。 追加`a[r]`に`s`, 現在のウィンドウにこの車が含まれているためです。 
4. ながら`s > k`、 取り除く`a[l]`から`s`そして増加します`l`。 すべての値は負ではないため、過剰な合計を減らす唯一の方法は、左側の境界を前方に移動することです。 
5. ウィンドウを縮小した後、次の場合は`s == k`、現在の間隔は有効です。 その長さをこれまでに見つかった最良の間隔と比較し、短い場合はそのままにします。 
6. いつ`s == k`、先頭のゼロを繰り返し削除すると、合計が変わらないため便利です。 実装では、これは当然、候補の長さを比較する前に同じ左境界移動ロジックによって処理されるか、正確な合計を求めた後に明示的にゼロを縮小することによって処理されます。 これは重要な理由です`[0, 1, 2]`そして`[1, 2]`合計は同じですが、後者の方が良い間隔になります。 
7. すべての右エンドポイントを処理した後、合計の間隔がない場合`k`見つかった、印刷する`-1`。 それ以外の場合は、1 から始まる車両番号を使用して最適な間隔のエンドポイントを出力します。 

### なぜ効果があるのか

 あらゆる瞬間に、窓には連続した車の列が表示されます。`s`まさに自由席の合計です。 だって全部`a[i]`は非負であり、右端点を拡張しても減少することはありません`s`、左端を進めても増加することはありません。 したがって、ウィンドウの合計が次の値を超えると、`k`、現在の左端点を維持すると、有効なより大きな右端点を生成できないため、左端点は安全に前進できます。 ウィンドウに正確な合計があるときはいつでも`k`、これは有効な解決策であり、先頭のゼロを削除すると、同じ右のエンドポイントで最短の間隔が得られます。 すべての右のエンドポイントが処理され、すべてのポインターは前方にのみ移動するため、アルゴリズムはすべての位置に関連付けられた可能な最短の有効な間隔を考慮し、全体的に最も短いものを見つけます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    left = 0
    current_sum = 0

    best_left = -1
    best_right = -1
    best_len = n + 1

    for right in range(n):
        current_sum += a[right]

        while left <= right and current_sum > k:
            current_sum -= a[left]
            left += 1

        if current_sum == k:
            while left <= right and a[left] == 0:
                left += 1

            length = right - left + 1

            if length < best_len:
                best_len = length
                best_left = left
                best_right = right

    if best_left == -1:
        print(-1)
    else:
        print(best_left + 1, best_right + 1)

if __name__ == "__main__":
    solve()
```入力は一度読み取られ、次の場所に保存されます。`a`、その後`left`そして`right`現在のスライディング ウィンドウを表します。`current_sum`いずれかの境界が移動するたびに更新されるため、プレフィックスサム配列は必要ありません。 

の`while current_sum > k`すべての値が負ではないため、ループは安全です。 合計が大きすぎると、それを減らすことができる唯一の操作は左の境界を移動することです。 すべての要素はウィンドウから一度だけ削除されるため、このループは`O(n)`総作業量ではなく、`O(n)`あらゆる適切なエンドポイントに対応します。 

2 番目のループは、正確な合計が見つかった後、値がゼロの車を左側から削除します。 これは微妙な境界条件です。 現在のウィンドウが`[0, 1, 2]`そして`k = 3`。 その合計はすでに正しいですが、`[1, 2]`厳密に短い有効間隔です。 ゼロを消しても変わらないので`current_sum`、そのような車を安全に廃棄できます。 

答えは内部的に 0 から始まるインデックスを使用して保存され、印刷時にのみ 1 から始まるインデックスに変換されます。 Python の整数は必要に応じて自動的に増加するため、Python では特別な整数型は必要ありません。

 ## 特殊なケース

 ### 車一台

 のために```
1 5
5
```右ポインタが唯一の車を訪問し、`current_sum = 5`。 これは等しいので、`k`、間隔`[0, 0]`がベストアンサーになります。 1 ベースのインデックス付けに変換した後、プログラムは次のように出力します。`1 1`。 

ここでよくある間違いは、あたかも少なくとも 2 台の車を選択する必要があるかのように最良の答えを初期化してしまうことです。 問題にはそれを必要とするものは何もないため、1 台の車が有効であり、多くの場合最適な間隔となります。 

### 答えの中のすでに満員の車

 のために```
3 3
1 0 2
```ウィンドウは拡大します`[1]`、 それから`[1, 0]`、 それから`[1, 0, 2]`。 その合計はちょうど 3 になります。 値ゼロの車はすでにいっぱいですが、情報学参加者を含む 2 台の車の間にあるため、エンドポイントは次のようになります。`1`そして`3`。 

ゼロを単に障害物として扱うことはできません。 そうすると、必要な合計をもつ連続した間隔が存在しないと誤って結論付けられてしまいます。 

### 正確な合計はありえません

 のために```
2 5
2 2
```列車全体の自由席の数は合計 4 つです。 以来、`a[i]`は負ではないため、部分配列は総和より大きな和を持つことができないため、5 に達することは不可能です。 正しいポインタは、最終的には配列全体を生成せずに処理します。`current_sum == 5`、そしてプログラムは出力します`-1`。 

少なくとも最小の合計を探すという不用意な実装`k`配列全体を誤って受け入れる可能性があります。 要件は平等ではなく、`sum >= k`。 

### ゼロ値の境界

 のために```
5 3
0 1 0 2 0
```最初の正確なウィンドウは`[0, 1, 0, 2]`、その合計は 3 です。 次に、アルゴリズムは合計を変更せずに先頭のゼロを削除し、残りの値を残します。`[1, 0, 2]`。 導き出された答えは「車」`2`を通して`4`。 

末尾のゼロは、候補の評価時に右ポインタが進んでいないため含まれません。 いずれかのゼロ境界を含めると、有用なシートを追加することなく、より長い間隔が生成されます。
