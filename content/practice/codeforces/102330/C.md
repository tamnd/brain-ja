 ## 問題の理解

 Petya は Vova に向かって 1 分ごとに 1 つのボールを投げます。 それらの間の距離は`L`、そしてすべてのボールが高速で動きます`X`、したがってボールが必要です`L / X`ヴォヴァまであと数分。 

Vovaはすぐにボールを発射しません。 ボールが距離に近づくと彼はシュートを開始する`D`彼の。 彼の銃は即座に発砲しますが、発砲するたびに正確に必要になります`M`再び発火するまでの数分。 いくつかのボールがすでに射程内にある場合、彼は常に最も近いボールを撃ちます。すべてのボールの速度は同じであるため、それがまだ生きているボールの中で最も古いボールになります。 

最初のボールが Vova に到達するときに Petya が投げたボールの数が必要です。 Vova がすべてのボールを永遠にシュートできるとしたら、答えは次のとおりです。`-1`。 

パラメータはすべて次のように大きくできます。`10^9`。 これにより、分数やボール数に比例するシミュレーションは即座に除外されます。なぜなら、答え自体はさまざまである可​​能性があるからです。`10^9`。 必要なソリューションでは、一定数の算術演算のみを使用する必要があります。 Python の整数では、次のような積も作成できます。`X * (M - 1)`特別なオーバーフロー処理を行わなくても安全です。 

最初の微妙なケースは、`M = 1`。 Vova は 1 分に 1 回、Petya がボールを作成するのと同じ頻度でシュートできます。 例えば、`5 2 2 1`答えがあります`-1`。 シミュレーションは実装の制限だけが原因で最終的に停止する可能性がありますが、数学的にはすべてのボールは Vova に到達する前に除去されます。 

2 番目の微妙なケースは、Vova がシュートできるのとまったく同じ瞬間にボールが Vova に到達する場合です。 例えば、`6 1 3 2`答えがあります`4`。 4番目のボールは、4番目のショットと同時にVovaに到達しました。 ゲームはその瞬間に終了するため、同点はショットの成功としてではなく、Vova の失敗として扱われなければなりません。 

3 番目の微妙なケースは、最終的な式の正確な除算です。 たとえば、`L = 10`、`X = 2`、`D = 6`、 そして`M = 2`、関連する比率は正確に`6 / 2 = 3`、したがって、答えは次のとおりです`4`、 ない`5`。 浮動小数点を使用しておおよその上限を求めると、不必要なエラーの原因が生じる可能性があるため、実装では整数の除算が使用されます。 

## アプローチ

 直接シミュレーションでは、ボールを 1 つずつ処理できます。 各ボールについて、ボールが Vova の射撃場にいつ入るかを判断し、銃がいつ使用可能になるかを追跡し、Vova に到達する前にそのボールが発射されるかどうかを決定できます。 これが機能するのは、発射時間を除いてすべてのボールが同一であり、最も近いボールが常に最も古い生き残ったボールであるためです。 

このアプローチの問題はボールの数です。 考慮する`X = 1`、`D = 10^9`、 そして`M = 2`。 Vova に到達する最初のボールは、おおよその後にのみ表示されます。`10^9`ボールが投げられてきました。 これらすべてのボールのループは約 10 億回の反復を実行しますが、これは 0.5 秒の制限をはるかに超えています。 最適化されたイベント シミュレーションでも、イベントが多すぎるため、根本的な問題は解決されません。 

重要な観察は、実際には個々のボールがどこにあるかを知る必要がないということです。 最初のショットは、最初のボールが射撃距離に到達したときに発生します。 その後、すべてのショットが正確に行われます`M`数分後、まだボールが待っている場合に限ります。 Petya は 1 分間隔でボールを発射するので、`M >= 1`、`k`- 番目のショットは常にターゲットをターゲットにします`k`- 番目のボール。 

時間通りに最初のボールを投げましょう`1`。 射撃境界に到達した後`(L - D) / X`分。 したがって、`k`- 番目のショットは次の時点で発生します`1 + (L - D) / X + (k - 1)M`。

 ## アルゴリズムのチュートリアル

 1.読む`L`、`X`、`D`、 そして`M`。 距離`L`最終的には不等式は解消されますが、それでも入力の一部です。 
2. もし`M = 1`、印刷`-1`。 Petya は 1 分に 1 つのボールを発射し、Vova も 1 分に 1 回発射できるため、銃が遅れることはありません。 
3. のために`M > 1`、ボールごとにシュートアドバンテージが変化する分数を計算します。 Vova が増加`M - 1`Petya の 1 分間の打ち上げ間隔に比べて、さらに数分の遅延が発生します。 
4. そのアドバンテージにボールスピードを掛けます。 該当する数量は、`X * (M - 1)`。 最初のロストボールは、そのようなユニットがどれだけ射撃距離内に収まるかによって決まります`D`。 
5. コンピューティング`ceil(D / (X * (M - 1)))`整数演算を使用します。 もし`q = D // denominator`そして`r = D % denominator`、天井は`q`いつ`r = 0`、 さもないと`q + 1`。 
6.追加`1`その天井に到達し、結果を印刷します。 余分な`1`これは、一連のショットが始まる前に、最初のボールに最初の 1 分間のオフセットがあるという事実に由来します。 

なぜこれが機能するのかは、タイミングから直接わかります。`k`- 番目のボール。 その到着時間は、`k + L/X`撮影可能時間は`1 + (L-D)/X + (k-1)M`。 ゴールがシュートまでに到着した時点でゲームは終了します。これは、ボールがすでに Vova に到達していることを意味するためです。 並べ替えると`k + L/X <= 1 + (L-D)/X + (k-1)M`。 

キャンセル後`L/X`そして並べ替えると、`(M - 1)k >= (M - 1) + D/X`。 

乗算`X`与える`X(M - 1)(k - 1) >= D`。 

Thus the smallest possible`k`まさに`1 + ceil(D / (X(M - 1)))`。 

The invariant behind the derivation is that the`k`- 番目のショットは常に`k`- 番目のボール。 最初のショットでボール 1 が削除され、その後のショットごとに、シューティング ゾーンで待機している最も古いボールが削除されます。 ボールは順番に発射され、同じ速度で移動するため、後のボールは先に生き残ったボールよりも近づくことはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    L, X, D, M = map(int, input().split())

    if M == 1:
        print(-1)
        return

    denominator = X * (M - 1)
    shots_needed = (D + denominator - 1) // denominator

    print(shots_needed + 1)

if __name__ == "__main__":
    solve()

 ## 特殊なケース

 いつ`M = 1`、正確な入力を考慮してください`5 2 2 1`。 主な式の分母には次のものが含まれます。`M - 1 = 0`したがって、式を盲目的に適用すると、ゼロによる除算が試行されることになります。 さらに重要なのは、物理的なプロセスが異なることです。Vova は 1 分間に 1 回シュートできますが、Petya は 1 分間に 1 つの新しいボールしか作成できません。 キューは決して大きくならないため、ボールは Vova に到達せず、正しい結果は次のようになります。`-1`。 

同時到着境界には、次を使用します。`6 1 3 2`。 最初の 4 つの可能なショット時間は次のとおりです。`4`、`6`、`8`、 そして`10`。 4球目はVovaにタイムリー到達`10`。 Vovaに到達するとゲームが終了するため、時間的には平等`10`ショットの成功ではなく、ボールの到着に成功したとみなされます。 アルゴリズムチェック`arrival <= shot`、それは次のことにつながります`k = 4`。 

正確な天井境界については、次を使用します。`10 2 6 2`。 ここ`X(M-1) = 2`、 そして`D = 6`、 それで`D / (X(M-1)) = 3`その通り。 答えは`1 + 3 = 4`。 厳密な不等式を使用した数式または不適切に丸められた除算は、次の結果を返す可能性があります。`3`または`5`。 

正確でない境界の場合は、次を使用します。`10 3 5 3`。 分母は`3 * 2 = 6`、 その間`D = 5`。 比率は 0 と 1 の間であるため、その上限は次のようになります。`1`、答えを与える`2`。 これは、整数の上限が次のように実装されていることをチェックします。`(D + denominator - 1) // denominator`通常のフロア分割ではなく。
