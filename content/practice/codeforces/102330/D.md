 ## 解決策
 ## 問題の理解

 現在 2 つのオファーがあります。`x`バーナムから、そして`y`カーライルから、`x <= y`。 バーナムはオファーを次のように増額します`a`、その後、カーライルはオファーを減らします`b`。 次の動きでは、変化は次のようになります。`2a`そして`2b`、 それから`3a`そして`3b`、 等々。 

このプロセスは、2 つのオファーが一致または交差するとすぐに終了します。 答えは、実際に話された最後のオファーです。 すべての終了条件は、バーナムの現在のオファーが少なくともカーライルの現在または次のオファーである場合に発生するため、答えは常に終了ラウンドでのバーナムのオファーになります。 

完了したとします。`k`ラウンドします。 バーナムさんが追加しました

 a(1+2+⋯+k)=a 2 k(k+1)

 彼の最初の提案に。 カーライルは減算した

 b(1+2+⋯+k)=b 2 k(k+1) 。 

したがって、ラウンドの両方の動きの後`k`、彼らのオファーは

 B k =x+a 2 k(k+1)

 そして

 C k =y−b 2 k(k+1) 。 

プロセスはラウンドで終了します`k`まさにこれら 2 つの値が満たされるとき`B_k >= C_k`。 並べ替えると

 (a+b) 2 k(k+1) ≧y−x。 

したがって、シミュレーション全体は、最小の非負の整数を見つけることになります。`k`この不等式を満たすこと。 一度`k`はわかっていますが、答えは簡単です`B_k`。 

多くてもあります`2000`テストケース、一方で`x`そして`y`ほぼ異なる場合があります`10^12`。 したがって、ラウンド数は約`sqrt(10^12)`、 だいたい`1.4 * 10^6`、ステップ サイズが 1 つの場合でも、`1`。 したがって、直接シミュレーションでは、すべてのテストにわたって数十億回の反復が実行される可能性があり、これは 1 秒の制限をはるかに超えています。 すべてのラウンドをシミュレートするのではなく、三角数の単調増加を利用する必要があります。 

いくつかの境界ケースには特別な注意が必要です。 たとえば、最初のオファーがすでに等しい場合、`1 1 5 7`、交渉はすぐに終了し、答えは次のとおりです。`1`。 常に最初に 1 ラウンドを実行するループは、誤ってより大きな値を出力します。 

境界での等価性も直ちに終了する必要があります。 のために`1 4 1 1`、2ラウンド後のオファーは次のようになります。`4`そして`1`、そして答えは`4`。 より一般的には、条件は次のとおりです。`>=`、だけでなく`>`。 これを厳密な比較に置き換えると、答えを次のラウンドに進めることができます。 

ステップ サイズは大きく異なる場合があります。 のために`7 18 1 3`、答えは`10`: バーナムが言った後`8`そしてカーライルは言う`15`とバーナムは言う。`10`、その後カーライルは意図した`9`すでに以下です`10`。 バーナムのオファーがカーライルの以前のオファーに達したかどうかだけをチェックするソリューションでは、この終了条件を逃してしまいます。 

## アプローチ

 単純な解決策では、交渉をラウンドごとにシミュレートします。 ラウンド中`k`、バーナムのオファーを増加させます`k*a`そしてカーライルのオファーを引き下げる`k*b`、次にオファーが満たされているかどうかを確認します。 これは、プロセスで説明されているオファーのシーケンスに正確に従っているため、正しいです。 

問題はラウンド数です。 と`y-x`に近い`10^12`そして`a=b=1`、大まかに必要です

 2 k(k+1) ≈5⋅10 11 、

 それは与える`k`その周り`10^6`。 と`2000`テストケース、最悪の場合のシミュレーションは約`2 * 10^9`ラウンドします。 各ラウンドの時間が一定であるとしても、それはあまりにも大きすぎます。 

有益な観察は、ラウンド後に`k`、ギャップが減少した合計量は正確に

 (a+b) 2 k(k+1) 。 

三角数`k(k+1)/2`非負の場合は厳密に増加しています`k`、つまり述語

 (a+b) 2 k(k+1) ≧y−x

 小さいものはすべて false`k`十分に大きいすべての場合に当てはまります`k`。 この単調性により、二分探索がシミュレーションの自然な代替品となります。 

オファーの順序にも微妙なポイントがあります。 バーナムはどのラウンドでも最初に発言します。 彼の新しいオファーがすでにカーライルの以前のオファーに達している場合、プロセスはバーナムの値で直ちに停止します。 そうでない場合は、カーライルが次に話します。 カーライルの新しいオファーがバーナムの価値以下になった場合、プロセスもバーナムの価値で停止します。 両方の状況を 1 つの条件で捉えます`B_k >= C_k`、 なぜなら`C_k <= C_{k-1}`。 バーナムが到達したら`C_{k-1}`、彼は確かにさらに小さなものにも到達します`C_k`。 

したがって、ラウンド後のオファーが満足する最初のラウンドのみが必要です。`B_k >= C_k`。 答えはそのラウンドでのバーナムのオファーだ。

 ## アルゴリズムのチュートリアル

 1. 初期ギャップを計算する`d = y - x`。 もし`d`がゼロの場合、オファーはすでに一致しているため、答えは次のようになります。`x`そしてラウンドは必要ありません。 
2. 候補者ラウンドの場合`k`、三角数を計算します

 T k = 2 k(k+1) 。 

そのラウンドで両方のオファーがあった後の距離は、

 d−(a+b)T k 。 

この値が正でない場合、ネゴシエーションはそのラウンドまでに終了します。 
3. 二分探索を使用して最小値を見つけます`k`誰のために

 (a+b)T k ≧d。 

述語が単調なので、`T_k`厳密に増加する`k`。 
4. 最小値が有効になったら`k`が見つかったら、バーナムのオファーを計算します

 x+aT k .

 それが交渉終了となる金額です。 
5. 現在のテスト ケースのこの値を出力し、すべてのテスト ケースに対して繰り返します。 

### なぜ効果があるのか

 ラウンド前`k`、バーナムによる累積増加は次のとおりです。`a(1 + ... + k)`、一方、カーライルによる累積減少は`b(1 + ... + k)`。 したがって、それらが互いに向かって結合した動きは、`(a+b)T_k`。 この動きが少なくとも元のギャップである最初のラウンドは、対応する減少後のバーナムのオファーが少なくともカーライルのオファーである最初のラウンドです。 

カーライルのラウンド後のオファーだから`k`ラウンド前の彼のオファーより大きくない`k`、バーナムが最初に話したときに発生する交差点も同じ条件で表されます。`B_k >= C_k`。 したがって、最小の`k`二分探索で見つかったものはまさに終了ラウンドであり、`x + aT_k`正確に最後に話された量です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        x, y, a, b = map(int, input().split())

        if x == y:
            out.append(str(x))
            continue

        gap = y - x
        step = a + b

        # Find the smallest k such that
        # step * k * (k + 1) / 2 >= gap.
        lo, hi = 0, 1

        while step * hi * (hi + 1) // 2 < gap:
            hi *= 2

        while lo < hi:
            mid = (lo + hi) // 2
            triangular = mid * (mid + 1) // 2

            if step * triangular >= gap:
                hi = mid
            else:
                lo = mid + 1

        k = lo
        triangular = k * (k + 1) // 2
        answer = x + a * triangular

        out.append(str(answer))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```最初の特殊ケースハンドル`x == y`直接。 その状況で`k = 0`は終了条件を満たしているため、別の反復を実行すると、off-by-one エラーが発生します。 

他のすべてのテストでは、`gap`最初のオファー間の距離を保存します。`step = a + b`三角数列の単位当たりの距離の減少量です。 表現`k * (k + 1) // 2`は後の累積乗数です`k`ラウンドします。 

二分探索の上限は 2 倍にすることで求められます。`hi`。 これにより、手動で選択した定数に依存することがなくなります。 必須なので、`k`はギャップの平方根程度にすぎないため、この 2 倍化にはほとんど操作が必要ありません。 

二分探索では、答えが次のどこかにあるという通常の不変条件が維持されます。`[lo, hi]`。 中点がすでに必要な不等式を満たしている場合、次の可能性が残ります。`mid`それ自体が答えなので、`hi`に移動します`mid`。 それ以外の場合、答えはさらに大きくなるはずですので、`lo`になる`mid + 1`。 

Python の整数には任意の精度があるため、次のような式が使用できます。`a * k * (k + 1)`オーバーフローしないでください。 整数の除算も乗算の前に行われます。`a`最終的な計算では、`k(k+1)`は常に偶数であり、三角数は整数です。

import io

def solve():

    t = int(input())
    out = []

    for _ in range(t):
        x, y, a, b = map(int, input().split())

        if x == y:
            out.append(str(x))
            continue

        gap = y - x
        step = a + b

            hi *= 2

            if step * triangular >= gap:
                hi = mid
            else:
                lo = mid + 1

        k = lo
        triangular = k * (k + 1) // 2
        out.append(str(x + a * triangular))

    sys.stdout.write("\n".join(out))

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

 ## 特殊なケース

 初期の等価の場合は次のようになります。`1 1 1 1`。 ここ`gap = 0`、 それで`k = 0`すでに条件を満たしています。 アルゴリズムはすぐに戻ります`x = 1`、不必要な最初のラウンドを回避します。 

等価境界は次のように表されます。`1 4 1 1`。 初期ギャップは`3`。 のために`k = 1`、成約金額の合計は`2`、不十分です。 のために`k = 2`、三角数は`3`、 それで`(a+b)T_2 = 6`、ギャップを超えます。 バーナムの提案は、`1 + 3 = 4`、正しい答えを与える`4`。 厳密に比較すると、2 つのオファーが正確に一致するケースが誤って処理されます。 

最初のサンプルは、`7 18 1 3`、2 つのオファー間の順序の問題をキャッチします。 で`k = 2`、バーナムが提供する`10`一方、同じラウンド後のカーライルのオファーは`9`。 プロセスは次で終了します`10`たとえバーナムの申し出がカーライルの以前の申し出に届かなかったとしても、`15`。 結合ギャップ条件はこれを正確に捕捉します。

 1+1000000⋅500000500000=500000500000000001。
