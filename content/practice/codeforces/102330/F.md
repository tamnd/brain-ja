 ## 解決策
 ## 問題の理解

 私たちはn匹の動物を飼っています。 動物 i には 3 つのパラメータ a i 、 b i 、および c i があります。 現在ケージ内に最大でも c i の動物がいる場合、この動物は a i 攻撃性に貢献します。 ケージに c i を超える動物が含まれている場合、それは b i に寄与します。ここで a i ≤ b i です。 

ケージには、現在の攻撃性の値の合計が最大 s である場合にのみ、動物のコレクションを保持できます。 同時に中に入れることができるできるだけ多くの動物が必要です。 

難しいのは、動物の貢献がケージ内の最終的な動物の数に依存することです。 正確に k 匹の動物を選択できるかどうかを確認する場合、動物 i には固定コストがかかります。 

w i (k)={ a i , b i , c i ≧k, c i <k。 ​

 k が固定されると、問題は単純になります。最小の w i (k) を持つ正確に k 匹の動物を選択します。 したがって、可能な最小の攻撃性は、k 個の最小の現在のコストの合計になります。 

制約 n ≤ 10 5 は、指数関数的に多くの操作を必要とするサブセットの検査を除外し、また、各サイズですべての動物を調べる必要がある場合、考えられるすべてのケージ サイズにわたる O(n 2 ) スキャンも除外します。 a i ,bi ,s の値は 10 9 に達する可能性があるため、実装でも 64 ビット サイズの算術演算を使用する必要があります。 Python の整数はすでにこれを安全に処理しています。 

不注意な実装が失敗する可能性がある境界ケースがいくつかあります。 まず、条件は c i ≧k であり、 c i ≧k ではありません。 例えば、```
1 5
5 10 1
```保管できる動物は 1 つだけです。動物が 1 匹の場合は 1 ≦ 5 なので、その攻撃性は 5 になります。答えは次のとおりです。`1`。 を使用した実装`c_i > k`誤ってアグレッション 10 に切り替えられてしまいます。 

2 番目のケースは、 a i =bi の場合です。 例えば、```
2 0
0 0 1
0 0 1
```どちらの動物も攻撃性がゼロなので、答えは次のようになります。`2`。 すべての遷移で値が変更されると想定するデータ構造は引き続き機能しますが、2 つの値が等しい場合に誤って動物を削除したり複製したりしてはなりません。 

3 番目のケースは、正の数の動物が適合しない場合に発生します。```
1 0
1 5 1
```1 匹の動物の攻撃性は 1 で、ケージの容量を超えています。 正しい答えは、`0`。 アルゴリズムでは、少なくとも 1 匹の動物が選択できると仮定するのではなく、答えとしてゼロを許可する必要があります。 

## アプローチ

 直接的な強引なアイデアは、可能な限り k 個の動物を試すことです。 固定 k の場合、上記のルールを使用してすべての動物の現在の攻撃性を計算し、n の値を並べ替えて、最小の k を取得します。 これは正しいです。最終的なケージのサイズが固定されると、すべての動物には固定コストがかかり、最も安価な k コストを選択することが最適になるためです。 

ただし、これを k ごとに行うには、n 個の要素を n 個の別々の種類で処理する必要があります。 結果として得られる複雑さは O(n 2 logn) です。 n=10 5 では、意図した範囲をはるかに超えており、並べ替え比較を考慮する前に、およそ 10 10 個の要素が並べ替え作業に参加しています。 

重要な観察は、k が 1 増加するとき、動物はそのコストを 1 回だけ変更するということです。 動物 i は c i までのすべてのケージ サイズに対して a i を使用し、ケージ サイズが c i +1 になると永続的に b i に変更します。 したがって、k ごとにコストのリスト全体を再構築する代わりに、現在のすべてのコストを動的に維持できます。 

各 k について、現在のマルチセット内の k 個の最小値の合計が必要です。 フェンウィック ツリーは、すべての可能な攻撃性の値を座標圧縮した後、これを効率的に維持できます。 1 つのフェンウィック ツリーには、現在各値を持つ動物の数が保存され、もう 1 つはそれらの値の合計が保存されます。 k が増加すると、c i =k−1 であるすべての動物は a i から b i に変更されます。 それぞれの変更は、フェンウィック ツリーの削除と挿入にすぎません。 

残りの操作は、k 個の最小値の合計を求めることです。 カウントを含むフェンウィック ツリーを使用すると、O(logn) 内の k 番目に小さい値の位置を見つけることができます。 次に、2 番目のツリーはその位置の下にあるすべての値の合計を示し、最終値のコピーを必要なだけ追加します。 

固定 k に対する最適なセットは単純に k 個の最も安い動物のセットであるため、ブルートフォースが機能します。 段階的にしか変化しない情報を繰り返し再構築するため、失敗します。 各動物がコストを正確に 1 回変更するという観察により、ソートされたマルチセットを暗黙的に維持し、すべてのケージ サイズを O(logn) で処理できます。

 ## アルゴリズムのチュートリアル

 1. すべての動物を読み取り、すべての値 a i と b i を収集します。 これらは、発生する可能性のある唯一の攻撃性値であるため、これらを座標圧縮すると、最大 2n のサイズのフェンウィック ツリーが得られます。 
2. 最初に、1 匹の動物が入っているケージを考えます。 すべての c i ≧ 1 であるため、すべての動物は現在攻撃性 a i を持っています。 すべての a i 値をカウントに挿入し、フェンウィック ツリーを合計します。 
3. c i の値に基づいて動物をグループ化します。 ケージのサイズ k を評価しようとしているとき、 c i =k−1 を持つすべての動物がちょうどその閾値を超えたところです。 データ構造からその a i 値を削除し、その b i 値を挿入します。 より大きな c i を持つ動物は依然として a i を使用しますが、以前の閾値を超えた動物はすでに b i を使用しています。 
4. カウント フェンウィック ツリーを使用して、k 番目に小さい現在の攻撃性の値を見つけます。 圧縮された位置が値 x に対応する場合、合計フェンウィック ツリーを使用して x より厳密に小さい値の数と合計を見つけます。 
5. あると仮定します。`cnt`x より小さい値、合計値`sm`。 残りの k-cnt の選択された動物はすべて攻撃性 x を持っているため、k 匹の動物の可能な最小限の攻撃性は次のようになります。 

sm+(k−cnt)x。 

この値が最大 s であれば、k 匹の動物を保存できるため、答えを更新します。 

1. 1 から n までのすべての k を続けます。 答えは実現可能な最大の k です。 

### なぜ効果があるのか

 ケージのサイズ k を確認する前に、ケージに k 匹の動物が含まれている場合、データ構造にはすべての動物の現在の攻撃性の値が正確に含まれます。 動物は、まさに c i <k のときに a i から b i に変化しており、他の動物は変化する必要がありません。 

この固定 k の場合、有効な選択には正確に k 個の動物が含まれます。 各動物の現在の攻撃性値は固定されているため、可能な最小の合計攻撃性は、k 個の最小値を取ることによって得られます。 フェンウィック ツリーはその最小合計を正確に計算します。 したがって、アルゴリズムは、k 個の動物のセットがケージに収まるときに、k が実行可能であるとマークします。 

別の動物を追加しても動物の数が増えるだけで、選択した動物の攻撃性を下げることはできないため、実現可能性は単調です。 すべての k を直接処理すると、個別の実現可能性検索の必要性が回避され、最大の実現可能なサイズが得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, s = map(int, input().split())

    animals = []
    values = []

    for _ in range(n):
        a, b, c = map(int, input().split())
        animals.append((a, b, c))
        values.append(a)
        values.append(b)

    coords = sorted(set(values))
    m = len(coords)
    pos = {x: i + 1 for i, x in enumerate(coords)}

    count_bit = [0] * (m + 1)
    sum_bit = [0] * (m + 1)

    def add(bit, i, delta):
        while i <= m:
            bit[i] += delta
            i += i & -i

    def prefix(bit, i):
        res = 0
        while i > 0:
            res += bit[i]
            i -= i & -i
        return res

    # Find the smallest Fenwick index whose prefix count is >= k.
    def kth(k):
        idx = 0
        step = 1 << (m.bit_length() - 1)

        while step:
            nxt = idx + step
            if nxt <= m and count_bit[nxt] < k:
                idx = nxt
                k -= count_bit[nxt]
            step >>= 1

        return idx + 1

    # Animals with c = k - 1 change from a to b before size k is checked.
    by_c = [[] for _ in range(n + 1)]

    for a, b, c in animals:
        by_c[c].append((a, b))

        p = pos[a]
        add(count_bit, p, 1)
        add(sum_bit, p, a)

    answer = 0

    for k in range(1, n + 1):
        threshold = k - 1

        for a, b in by_c[threshold]:
            if a == b:
                continue

            pa = pos[a]
            pb = pos[b]

            add(count_bit, pa, -1)
            add(sum_bit, pa, -a)

            add(count_bit, pb, 1)
            add(sum_bit, pb, b)

        p = kth(k)

        cnt_before = prefix(count_bit, p - 1)
        sum_before = prefix(sum_bit, p - 1)

        value = coords[p - 1]
        total = sum_before + (k - cnt_before) * value

        if total <= s:
            answer = k

    print(answer)

if __name__ == "__main__":
    solve()
```座標圧縮により、考えられるあらゆる攻撃性の値がフェンウィック インデックスに変換されます。 すべての動物は a i と b i のみに寄与するため、異なる値は最大 2n 個あります。 

初期のフェンウィック状態には、すべての a i 値が含まれています。 すべての c i は少なくとも 1 であるため、これは k=1 の場合は正しいです。 の`by_c`配列は、各動物がその値をいつ変更する必要があるかを正確に記録します。 

ループは使用します`by_c[k - 1]`サイズkを確認する前に。 これが臨界境界条件です。 c i =k−1 の動物は k>c i を認識するため、すでに b i を使用している必要があります。 逆に、 c i =k である動物は依然として a i を使用します。 

カウント フェンウィック ツリーは注文統計に使用されます。 の`kth(k)`ルーチンは、O(logn) 内の k 番目に小さい現在値を含む圧縮位置を見つけます。 次に、合計フェンウィック ツリーは、それより厳密に小さいすべての値の合計を取得します。 最終値を下回る動物が k 未満の場合、残りの動物はすべて正確にその値になります。 

の`a == b`check は、攻撃性が決して変わらない動物に対して 2 つの不必要な更新を実行することを回避します。 正確さを保つために必須ではありませんが、作業が軽減され、移行ロジックが明確になります。 

すべての合計は約 10 14 に達する可能性があるため、固定幅の 32 ビット整数では不十分です。 Python の整数はこれを自動的に処理します。
