 ## 解決策
 ## 問題の理解

 小文字とワイルドカード文字を含む可能性のある文字列が与えられます。 各ワイルドカードは任意の小文字に置き換えることができます。 置換を選択した後、文字列は連続したセグメントに分割され、最終的に埋められた文字列ではすべてのセグメントが回文になる必要があります。 

ワイルドカードに文字を割り当てて文字列を分割するすべての可能な方法の中で、一度に 2 つのことが必要です。回文セグメントの最小数と、この最小値を達成するためのさまざまな方法の数です。埋め込まれた文字列またはセグメント化のいずれかが異なる場合、2 つの方法は異なります。 答えは 998244353 を法として計算されます。 

重要な問題は、回文構造とワイルドカードの柔軟性が相互作用することです。 部分文字列は単に「回文であるか否か」ではなく、「回文にすることができ、どのようにして回文に完成させることができるか」ということです。 

文字列の長さが十分に長いため、3 次または重い定数を使用した 2 次のアプローチさえも困難になります。 回文の有効性を再計算したり、再利用せずに分割ポイントごとに個別にカウントしたりするものはすべてタイムアウトになります。 これにより、すべての回文区間と各区間の有効な充填数を前処理してから、分割のために標準区間動的プログラミングを実行する方向に進みます。 

ワイルドカードの多重性が無視されると、微妙な失敗のケースが発生します。 たとえば、部分文字列「??」について考えてみましょう。 これは構造的には常に回文ですが、1 ではなく 26 の選択肢を提供します。実現可能性のみを追跡する単純な DP では、正しい最小カットは計算されますが、カウントは完全に間違っています。 

もう 1 つの特殊なケースは、固定文字とワイルドカードを対称の位置で混合することです。 たとえば、「a?b」は、両端が柔軟に見えても、どの代入でも回文になることはできません。 このタイプの不一致により、センターを中心に拡張する場合は早期終了が余儀なくされます。 

## アプローチ

 直接的なアプローチでは、文字列のすべてのパーティションを列挙し、セグメントごとに回文に変換できるかどうかを確認し、それが有効になる代入の数を数えます。 たとえ回文チェックが 2 つのポインターを使用して最適化されたとしても、パーティションの数は指数関数的であり、部分文字列の数は 2 次であるため、このアプローチはすぐに実行不可能になります。 

より構造化されたアイデアは、問題を 2 つの独立した層に分離することです。 最初の層は、すべての部分文字列について、回文になり得るかどうか、および回文に完成する方法は何通りあるかを答えます。 2 番目の層は、各部分文字列を候補ブロックとして扱い、インデックスに対して最小セグメンテーション動的プログラムを実行します。 

重要な観察は、回文の有効性と割り当てのカウントが部分文字列に対してローカルであり、中心展開を使用して事前計算できることです。 中心を固定したら、外側に拡張して一貫性の制約を維持できます。 一致するペアを拡張するたびに、既存のカウントを伝播するか、両端がワイルドカードの場合は 26 を乗算します。 これにより、部分文字列の評価が中心ごとの償却線形仕事に変わります。これは、すべての O(n^2) 部分文字列に対して十分です。 

この前処理の後、問題は標準的な「重み付き最小回文分割」DP になります。 各エンドポイント i について、部分文字列 (j+1, i) が有効な回文セグメントとなるように、すべての j < i を考慮します。 最適なカット数を更新し、ウェイの数を累積して、そのセグメントの充填数を掛けます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースパーティション | 指数 | O(n) | 遅すぎる |
 | 回文 + DP を事前計算する | O(n^2) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 ソリューションを 3 つのフェーズに分割しました。回文の有効性とカウントの前処理、最適なセグメンテーションのための動的プログラミング、および 1 つの有効な充填ソリューションの再構築です。

1. すべてのインデックス i について、それを回文の中心として扱い、奇​​数長の回文の場合は外側に拡張します。 (j, k) から拡張しながら、文字の互換性を確認します。 競合が発生した場合、拡張は停止します。 文字が一致する場合、またはワイルドカードが含まれる場合、部分文字列は回文形式のままになる可能性があります。 これを有効な回文間隔としてマークします。 

この拡張中に、この間隔を完了できる方法が何通りあるかも計算します。 両端が「?」の場合、一致する文字のペアを自由に選択するため、塗りつぶしの数は 26 倍になります。 片側のみが「?」の場合、ワイルドカードが強制されるため、値は内部の部分文字列から継承されます。 これにより、間隔ごとの乗算カウントが構築されます。 

1. 隣接する中心 (i, i+1) から開始して、偶数長の回文に対して同じ展開を繰り返します。 有効性とカウントについては同じルールが適用されます。 
2. 2 つのテーブルを保存します。1 つは部分文字列が回文になり得るかどうかを示すブール テーブル、もう 1 つはその部分文字列の有効な補完の数を保存するテーブルです。 
3. DP over プレフィックスを定義します。 dp[i] に、i で終わる接頭辞をカバーするために必要な回文セグメントの最小数と、その最適値を達成するための方法の数からなるペアを格納します。 
4. dp[0] を一方向のゼロセグメントとして初期化します。 
5. 各エンドポイント i について、可能な以前のカット位置 j をすべて反復します。 部分文字列 (j+1, i) が有効な回文である場合、dp[j] から dp[i] への遷移を試みます。 
6. dp[i] を更新するときは、まずセグメントの数を最小限に抑えます。 厳密に優れた最小値が見つかった場合は、最小値とカウントの両方を上書きします。 同じ最小値が達成される場合は、ウェイの数を追加します。 各遷移では、dp[j].ways に部分文字列 (j+1, i) の回文充填の数を乗算します。 
7. 先行アレイを維持して、1 つの最適なパーティションを再構築します。 
8. DP の後、n から逆方向に歩いてパーティションを再構築します。 各セグメントについて、文字をミラーリングしてワイルドカードを埋めます。 両端が「?」の場合は、「a」などのデフォルトの文字を割り当てます。 片側だけが「？」の場合は対称の位置からコピーしてください。 

### なぜ効果があるのか

 すべての回文セグメントは、そのエンドポイントと一貫したミラー制約によって完全に決定されます。 拡張フェーズでは、考えられるすべての有効な回文区間が 1 回だけ列挙され、各区間に付加されたカウントは、他のセグメントからの干渉を受けることなく、ワイルドカード置換の独立した選択を反映します。 次に、DP は各間隔をアトミック ブロックとして扱い、プレフィックスの最適なセグメント化は有効な回文接尾辞で終了する必要があり、すべての接尾辞の選択肢が列挙されるため、最適な部分構造が保持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n = int(input().strip())
    s = input().strip()
    s = " " + s

    isp = [[0] * (n + 1) for _ in range(n + 1)]
    cnt = [[1] * (n + 1) for _ in range(n + 1)]

    dp = [(10**9, 0) for _ in range(n + 1)]
    pre = [0] * (n + 1)
    dp[0] = (0, 1)

    def relax(i, j):
        nonlocal dp, pre
        cost = dp[j][0] + 1
        ways = dp[j][1] * cnt[j + 1][i] % MOD

        if cost < dp[i][0]:
            dp[i] = (cost, ways)
            pre[i] = j
        elif cost == dp[i][0]:
            dp[i] = (cost, (dp[i][1] + ways) % MOD)

    for i in range(1, n + 1):
        isp[i][i] = 1
        if s[i] == '?':
            cnt[i][i] = 26

        j, k = i - 1, i + 1
        while j >= 1 and k <= n:
            if s[j] == '?' and s[k] == '?':
                cnt[j][k] = cnt[j + 1][k - 1] * 26 % MOD
            elif s[j] == s[k] or s[j] == '?' or s[k] == '?':
                cnt[j][k] = cnt[j + 1][k - 1]
            else:
                break
            isp[j][k] = 1
            j -= 1
            k += 1

    for i in range(1, n):
        if s[i] == s[i + 1] or s[i] == '?' or s[i + 1] == '?':
            if s[i] == '?' and s[i + 1] == '?':
                cnt[i][i + 1] = 26
            isp[i][i + 1] = 1

            j, k = i - 1, i + 2
            while j >= 1 and k <= n:
                if s[j] == '?' and s[k] == '?':
                    cnt[j][k] = cnt[j + 1][k - 1] * 26 % MOD
                elif s[j] == s[k] or s[j] == '?' or s[k] == '?':
                    cnt[j][k] = cnt[j + 1][k - 1]
                else:
                    break
                isp[j][k] = 1
                j -= 1
                k += 1

    for i in range(1, n + 1):
        for j in range(i):
            if isp[j + 1][i]:
                cost = dp[j][0] + 1
                ways = dp[j][1] * cnt[j + 1][i] % MOD
                if cost < dp[i][0]:
                    dp[i] = (cost, ways)
                    pre[i] = j
                elif cost == dp[i][0]:
                    dp[i] = (cost, (dp[i][1] + ways) % MOD)

    p = n
    ans = []
    while p:
        l = pre[p] + 1
        t = list(s[l:p + 1])
        x, y = 0, len(t) - 1
        while x <= y:
            if t[x] == '?' and t[y] == '?':
                t[x] = t[y] = 'a'
            elif t[x] == '?':
                t[x] = t[y]
            elif t[y] == '?':
                t[y] = t[x]
            x += 1
            y -= 1
        ans.append("".join(t))
        p = pre[p]

    ans.reverse()
    print(dp[n][0], dp[n][1])
    print(" ".join(ans))

t = int(input().strip())
for _ in range(t):
    solve()
```コードの最初のフェーズは、回文の有効性と多重度のテーブルを設定するために中心を中心に展開されます。 2 番目のフェーズでは、すべての有効な回文接尾辞が遷移として考慮される古典的な接頭辞 DP を実行します。 再構成ステップでは、先行配列を使用して逆方向に進み、対称性を強制することで文字をワイルドカードに決定的に割り当てます。 

よくある微妙な点は、移行中のカウントの乗算です。 各セグメントは独立して寄与するため、グローバル構築の数はセグメント全体で増加します。 これが、dp 遷移が cnt[j+1][i] 倍になる理由です。

| 私 | ベストカット | 方法 | ラストカット |
 | --- | --- | --- | --- |
 | 0 | 0 | 1 | - |

2 番目の例として、「a?b?」について考えてみましょう。 不一致のため、部分文字列は範囲全体にわたって回文を形成できないため、DP はより小さなセグメントに分割されます。 拡張フェーズでは無効な大きな間隔を正しくマークできないため、DP はそれらの間隔を考慮しません。 

| 接頭語 | 有効なセグメント | 決定 |
 | --- | --- | --- |

 これは、無効な回文間隔が早期に枝刈りされ、誤った長距離遷移が防止されることを示しています。

 ## 特殊なケース

 単一文字の文字列は単純な回文として動作します。 DP は dp[0] を正しく初期化するため、文字が「?」の場合は dp[1] が 26 通りの 1 つのセグメントになり、それ以外の場合は 1 通りになります。 再構築ステップでは、単純に文字自体を返します。 

「????」のような完全なワイルドカード文字列 は完全に回文であり、拡張フェーズではすべての対称ペアにわたってカウントが乗算的に伝播します。 DP は、最適解が 1 つのセグメントであり、塗りつぶしの数が 26 の対称選択肢の数に累乗され、区間乗算によって暗黙的に累積されることを認識する必要があります。 

「ab」などの強制的な不一致を伴う文字列は回文にはできないため、isp[1][2] は false のままになります。 DP は 2 つの単一文字セグメントに強制的に分割されるため、個々の文字がワイルドカード関連の多重度を持つ場合でも正確さが保証されます。
