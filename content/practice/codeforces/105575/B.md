 ## 問題の理解

 各問題インスタンスは 3 つの長さの配列で構成されます。$n$、これは問題ごとのパラメータと考えることができます。 インデックスごとに$i$、固定値があります$a_i$、$b_i$、 そして$c_i$。 これらの配列を読み取った後、入力は以下を提供します。$n$追加のペア$(t, s)$、インデックスごとに 1 つ$i$、各ペアは貢献度指数を決定します$i$最終的な答えに追加します。 

インデックスごとに$i$に基づいて候補スコアを計算します。$t$そして$s$。 もし$s \le 0$、そのインデックスは何も貢献しません。 それ以外の場合は、両方の値で減少する線形式を評価します。$t$そして$s$、固定キャップと比較します。$c_i$。 指数の貢献度$i$上限値間の最大値です$c_i$そして計算された式。 すべてのインデックスに対するこれらの寄与を合計すると、最終的な答えが得られます。 

問題の説明と参照ソリューションによって暗示される制約は、すべての算術演算が 32 ビット符号付き整数内に問題なく収まることを示しています。 これにより、大きな整数の処理やモジュラー演算の必要がなくなります。 アルゴリズムは直線的な時間経過で実行されます$n$、したがって、の値$n$少なくともここまでは$10^5$または$10^6$単一パスで処理されることを目的としています。 

微妙なケースが発生するのは、$s \le 0$。 その場合、インデックスは完全にスキップされます。 単純な実装でも式を計算して含める可能性があり、誤った負の寄与につながる可能性があります。 

たとえば、次のように仮定します。$a_i = 100$、$b_i = 2$、$c_i = 10$、そして入力は次を与えます$t = 5$、$s = 0$。 正しい出力寄与は次のとおりです。$0$。 を無視した不用意な実装$s \le 0$警備員が計算するだろう$100 - 2 \cdot 5 - 50 \cdot (0 - 1) = 100 - 10 + 50 = 140$、その後、間違って摂取します$\max(10, 140) = 140$、問題によりそのようなエントリが明示的に抑制されるため、これは無効です。

 ## アルゴリズムのチュートリアル

 1. 整数を読み取る$n$、計算する必要がある独立寄与の数を決定します。 後続のすべての値はインデックスによって整列されるため、インデックス$i$すべての配列で、同じ論理項目を参照します。 
2. 配列の読み取り$a$、$b$、 そして$c$。 これらは、インデックスごとのスコア計算式で使用される固定パラメータを表します。 それらを保存すると、最終計算段階でインデックス付きの直接アクセスが可能になります。 
3. インデックスごとに$i$、ペアを読みます$(t, s)$。 これらは、その特定のポジションのスコアの計算方法を変更する動的入力です。 
4. もし$s \le 0$、このインデックスをスキップして、回答には何も追加しません。 この条件は、2 番目のパラメーターが正でない場合に貢献を無効にする問題レベルの制約を反映しています。 
5. それ以外の場合は候補値を計算します$$x = a_i - b_i \cdot t - 50 \cdot (s - 1).$$この式は、スコアの線形減少を次のように捉えます。$t$そして$s$増加。 
6. この値を固定しきい値と比較します。$c_i$そして大きい方を取ります。 これにより、計算された式が低すぎる場合に、各インデックスが少なくともそのベースラインの上限に寄与することが保証されます。 
7. 結果を累計に加算します。 
8. すべてのインデックスを処理した後、累積合計を出力します。 

正確性は、各インデックスが独立して 1 回だけ処理されるため、相互作用や順序付け効果が存在しないという事実に左右されます。 

### なぜ効果があるのか

 各インデックスは、独自のパラメータと入力ペアによって完全に定義された値に寄与します。 計算は次の純粋な関数です。$(a_i, b_i, c_i, t_i, s_i)$、最終的な答えは、これらの独立した結果の合計です。 唯一の条件分岐は、$s \le 0$この場合、寄与ゼロを明示的に定義します。 加算以外にインデックス間の共有状態を変更するステップはないため、アルゴリズムは構築によって正確さを維持します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = [0] * (n + 1)
    b = [0] * (n + 1)
    c = [0] * (n + 1)

    for i in range(1, n + 1):
        a[i] = int(input())
    for i in range(1, n + 1):
        b[i] = int(input())
    for i in range(1, n + 1):
        c[i] = int(input())

    ans = 0
    for i in range(1, n + 1):
        t, s = map(int, input().split())
        if s <= 0:
            continue
        val = a[i] - b[i] * t - 50 * (s - 1)
        if val < c[i]:
            val = c[i]
        ans += val

    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションは、最初に 3 つのパラメーター配列を読み取り、クエリを処理する前に各インデックスが完全に初期化されていることを確認します。 ループオーバー$t, s$ペアはインデックスと同期されます$i$したがって、各計算では正しいパラメーターが使用されます。 

重要な実装の詳細は、次の場合の早期続行です。$s \le 0$これにより、無効なエントリに対する誤った演算が防止されます。 もう 1 つの重要な詳細は、すべての値が安全な整数範囲内に留まるため、浮動小数点変換を行わずに直接整数演算を使用することです。

 ## 特殊なケース

 いつ$s \le 0$の場合、アルゴリズムは計算を明示的にスキップします。 入力用$t = 10, s = 0$どれでも$a_i, b_i, c_i$、ループが実行されます`continue`したがって、演算は実行されず、寄与はゼロのままです。 これにより、負のシフト項を誤って使用することが防止されます。$50 \cdot (s - 1)$そうしないと、値が誤って増加してしまいます。 

計算式が より小さくなった場合$c_i$、アルゴリズムはそれを次のように置き換えます。$c_i$。 たとえば、$a_i = 20$、$b_i = 5$、$c_i = 15$、$t = 3$、$s = 2$、式は次のように評価されます。$20 - 15 - 50 = -45$。 max 操作では、寄与が強制的に適用されます。$15$結果がベースラインの上限を下回らないようにします。 

これらのケースでは、無効なエントリのスキップと最小制限の強制という 2 つの制御ルールが、考えられるすべての入力に対して正しい動作を完全に定義していることを確認します。
