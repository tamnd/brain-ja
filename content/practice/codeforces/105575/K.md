 ## 解決策
 ## 問題の理解

 いくつかの 2 次元整数ベクトルが与えられます。 各ベクトルは使用が許可されているステップを表し、これらのベクトルの整数線形結合を行うことが許可されています。つまり、それらを何度でも加算または減算し、整数でスケーリングできます。 問題は、これらの操作を使用して、両方の座標で単位基底状態と同等のターゲット構成を構築できるかどうかです。これは、生成された整数格子が強い意味で完全なグリッドにまたがることを効果的に意味します。 

目標を別の言い方で表現すると、指定されたベクトルのセットが整数グリッドの基底のように動作するベクトルのペアを生成できるかどうかを知りたいということです。その結果、許容される整数の組み合わせによって両方の座標を独立して最小の非ゼロ形式に減らすことができます。 

重要な問題は、フィールド上で作業しているわけではないということです。 実数や有理数に関しては、除算は常に可能であるため、ガウス消去法がこれを直接解決します。 整数を自由に除算することはできないため、整数の構造を保持する gcd スタイルのリダクションに依存する必要があります。 

目的の解決策ではペア間でユークリッドのようなリダクションが繰り返し実行されるため、制約では最大数千のベクトルが示唆されます。 これにより、すべての線形結合を列挙しようとしたり、格子を明示的に探索しようとしたりするアプローチが除外されます。 指数関数的または大規模な状態検索を伴うものは直ちに不可能になります。 

1 つの座標が早期にゼロになる場合、微妙なエッジ ケースが発生します。 たとえば、すべてのベクトルの最初の座標が 0 である場合、最初の座標が 0 以外のものを構築することはできないため、答えはすぐに負になる必要があります。 グローバル gcd を座標ごとに個別にチェックするだけの単純な実装では、座標が分離されており共有格子基底に結合できない場合、誤って「はい」と答えてしまいます。 

別の失敗モードは、操作が同じシーケンスのスワップとユークリッド縮約を通じて結合されていることを考慮せずに、各座標で独立して縮約が実行された場合に発生します。 この結合によって正確さが保たれます。 

## アプローチ

 ブルートフォース解釈では、ベクトルの可能なすべての整数線形結合をシミュレートしようとします。 各演算ではベクトルの加算または減算が可能であるため、状態空間は 2 次元の整数格子になります。 係数を制限したとしても、到達可能な状態の数は爆発的に増加します。 中程度の範囲の係数を持つ m 個のベクトル、たとえば [-K, K] の場合、組み合わせの数は (2K+1)^m であり、これは m が小さい場合でも実行不可能です。 

重要な洞察は、実際にはすべての組み合わせを構築する必要はないということです。 代わりに、これらのベクトルによって生成された格子に、両方の座標が絶対値 1 に等しいベクトルが含まれているかどうかだけを知る必要があります。これは、整数スパンが完全な Z^2 格子を形成しているかどうかを確認するのと同じです。 

これにより、問題はシステムの gcd のような不変量の計算に軽減されます。 1 次元では、古典的な結果は、数値のすべての整数の組み合わせが、その gcd の倍数のセットを正確に生成することです。 2 次元では、構造はより微妙ですが、ベクトル成分間に Euclid スタイルの消去を繰り返し適用することで問題を軽減できます。 

このアルゴリズムは、2 次元の拡張 gcd プロセスを効果的にシミュレートします。生成される整数格子を維持しながら、あるベクトルを別のベクトルに対して縮小し、システムを gcd 情報のみが残る正規形式に徐々に崩壊させます。 最後に、この変換の下で両方の座標方向が独立して gcd が 1 に等しいかどうかを確認します。

 ## アルゴリズムのチュートリアル

 各座標方向の格子の進化する基礎を表す値の作業ペアを維持します。 ユークリッド縮小を使用して、各入力ベクトルをこの構造に繰り返しマージします。 

1. まず、最初のベクトルを現在の参照ペア (x, y) として選択します。 これは、他のすべてに対して単純化しようとしている電流ジェネレーターのように機能します。 
2. 残りの各ベクトル (a[i][0]、a[i][1]) について、その最初の座標がゼロでないことを確認します。 参照がゼロ以外の最初の座標を持っているにもかかわらず、それがゼロである場合、それを参照と交換します。 これにより、最初の次元で現在の gcd プロセスに実際に影響を与える可能性のあるベクトルに対して常にリダクションすることが保証されます。 
3. 最初の座標にユークリッド ステップを適用します。 現在のベクトルの最初の座標が x に適合する回数を計算し、両方のベクトルからその倍数を減算し、役割を交換します。 これはまさに剰余あり除算の整数バージョンですが、2 番目の座標が同じ線形変換を追跡するように値のペアに拡張されています。 
4. 作業ベクトルの最初の座標がゼロになるまで、この縮小を繰り返します。 その時点で、x の残りの値は、これまでに処理されたすべての最初の座標の gcd であり、y は、2 番目の座標空間内の対応する累積線形結合です。 
5. メインの第 1 座標チェーンから削減されたベクトルの第 2 座標にわたって gcd アキュムレータ fy を独立して維持します。 これは、1 次元が固定された後に 2 次元にどの程度の自由が残っているかを示します。 
6. すべてのベクトルを処理した後、最終的な縮小された第 1 座標値と累積された第 2 座標 gcd の両方が絶対値で 1 に等しいかどうかを確認します。 両方が 1 の場合、両方向に完全な単位ステップを生成できます。これは、格子が完全な整数グリッドにまたがることを意味します。 

正確さは、すべてのリダクション ステップでベクトルのセットによって生成された整数格子が保存されるという不変条件から得られます。 各ユークリッド減算は、整数に対する可逆変換です。つまり、スパンではなく基底を変更するだけです。 このプロセスは基本的に、各座標方向の格子の正準形式を計算します。 いずれかの座標が 1 より大きい gcd に崩壊する場合、その座標は基本的に制約されており、1 に到達できないため、答えは負でなければなりません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def gcd(x, y):
    return x if y == 0 else gcd(y, x % y)

def solve():
    T = int(input())
    for _ in range(T):
        m = int(input())
        a = [None] + [list(map(int, input().split())) for _ in range(m)]

        for i in range(2, m + 1):
            if a[i][0] != 0:
                a[1], a[i] = a[i], a[1]

            if a[1][0] == 0:
                print("NO")
                break

            x, y = a[1][0], a[1][1]
            fy = 0

            for i in range(2, m + 1):
                if a[i][0] == 0:
                    fy = gcd(fy, a[i][1])
                    continue

                while a[i][0] != 0:
                    length = x // a[i][0]
                    nx = a[i][0]
                    ny = a[i][1]

                    a[i][0] = x - a[i][0] * length
                    a[i][1] = y - a[i][1] * length

                    x, y = nx, ny

            else:
                if abs(fy) == 1 and abs(x) == 1:
                    print("YES")
                else:
                    print("NO")

solve()
```このコードは、上で説明したユークリッド換算を反映しています。 主な構造は代表ベクトル (x, y) を保持し、最初の座標が gcd 形式に安定するまで、それに対して他のベクトルを繰り返し削減します。 変数 fy は、最初の座標のリダクションに参加しなくなったベクトルからの gcd 情報を蓄積します。 

重要な点は、減算のたびに両方の座標が同時に更新されることです。 これが格子構造を維持するものです。 最初の座標だけを削減した場合、2 番目の座標が同じ整数演算にどのように依存するかについての情報が失われ、最終的な条件は無意味になってしまいます。 

もう 1 つの微妙な点は、各反復の開始時のスワップです。これにより、最初の座標に常にゼロ以外のピボットが存在することが保証されます。 これがないと、ゼロ除算が発生するためユークリッドのステップは失敗し、さらに重要なことに、gcd 削減を継続できなくなります。 

## 実用的な例

 ベクトル (6, 10)、(4, 6)、(2, 3) を持つ小さなインスタンスを考えてみましょう。 

| ステップ | ピボット (x, y) | 現在のベクトル | 操作 |
 | --- | --- | --- | --- |
 | 開始 | (6, 10) | (4,6) | 初期ピボット |
 | 減らす | (6, 10) | (4,6) | 6 mod 4 は新しいピボットを与えます |
 | スワップ | (4,6) | (2, 3) | 削減を続ける |

 縮小を繰り返した後、最初の座標は gcd 2 に崩壊します。これは、1 に到達できないことを意味します。 

これは、すべてのベクトルが個別に「リッチ」に見える場合でも、それらが生成する格子は依然として 1 つの座標の公約数によって制約される可能性があることを示しています。 

ここでベクトル (3, 5)、(2, 7) を考えてみましょう。 

| ステップ | ピボット (x, y) | ベクトル | 結果 |
 | --- | --- | --- | --- |
 | 開始 | (3, 5) | (2, 7) | ピボット |
 | 減らす | (2, 7) | (1, -2) | ユークリッドステップ |
 | 最終回 | (1, -2) | - | gcd は 1 になります |

 ここでは両方の座標を 1 に減らすことができるため、格子はフルランクであり、答えは YES です。 

これらのトレースは、アルゴリズムが整数ガウス消去法を効果的に実行し、gcd 情報のみが残るまで構造を崩壊させる様子を示しています。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべてのベクトルの最初の座標が 0 である場合です。 その状況では、アルゴリズムはピボットを形成できないことを即座に検出します。 (0, 3)、(0, 7) のような入力の場合、最初の次元に影響を与える方法がないため、格子は 1 次元となり、両方の座標で単位ベクトルを生成できません。 

もう 1 つのケースは、1 つのベクトルの大きさが他のベクトルを圧倒する場合です。 ユークリッド換算により、すべてがすぐにそのベクトルの gcd 構造に折りたたまれます。 たとえば、(100, 1)、(50, 3) では、最初の座標 gcd は 50 になり、1 ではないため、アルゴリズムは単位ステップを形成する可能性を正しく拒否します。 

最後の微妙なケースは、最初の座標が小さいベクトルと大きいベクトルの間でリダクションが交互に行われる場合です。 スワップベースのユークリッド ループでは、各反復で少なくとも 1 つのアクティブな座標ペアの絶対値が厳密に減少するため、このような変動シナリオでもプロセスが確実に収束します。
