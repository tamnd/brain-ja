 ## 問題の理解

 複数の独立したクエリが与えられ、各クエリは単一の整数で構成されます。$n$。 それぞれについて$n$、小さな整数から導出された固定基本式から始まる特定の成長プロセスをどこまで繰り返し適用できるかに応じて値を計算する必要があります。 各テスト ケースの最終的な答えは、制限を超える前にこのプロセスを何回適用できるかということです。$n$。 

問題を解釈する便利な方法は、3 に等しい最小の「構成サイズ」から開始し、次に非常に厳格な方法でそれを繰り返し拡張することです。つまり、各拡張ステップで現在の値が 2 倍になります。 それぞれに私たちに問われているのは、$n$、制限内で何回拡張を実行できるか$n$。 

入力サイズは十分に小さいため、各テスト ケースを対数時間または定数時間で独立して処理できます。 値は 2 倍化の繰り返しにより指数関数的に増加するため、段階的に増加をシミュレートするソリューションはすでに効率的です。 除外されるのは、クエリごとに不注意に浮動小数点対数を使用して最初から再計算しようとするアプローチです。精度誤差が蓄積され、正確に 2 のべき乗で境界決定が反転する可能性があるためです。 

の小さな値の周囲で微妙なエッジケースが発生します。$n$。 いつ$n$非常に小さい、特に$n = 2$、解釈によっては、初期化がすでにしきい値を超えているか、しきい値にほとんど一致していません。 常に同じ初期合計から開始して 2 倍をカウントする単純な実装では、これらの境界入力が誤って過大カウントまたは過小カウントされる可能性があります。 

別の失敗例は、浮動小数点の対数や累乗を使用して答えに「ジャンプ」することによって発生します。 たとえば、次のようなものを計算します$\lfloor \log_2(n) \rfloor$double を使用すると、次のような 2 の正確なべき乗を誤って分類する可能性があります。$16, 32, 64$、丸め誤差により 1 つずれた答えが生成されます。 

## アプローチ

 問題の核心構造は単調な成長プロセスです。 初期値から開始し、各操作で現在の値を 2 で乗算します。超過する前に、この乗算を何回適用できるかを知りたいのです。$n$。 

ブルートフォースアプローチはこれを直接シミュレートします。 テスト ケースごとに、カウンターを初期化し、現在の値が範囲内にある間、繰り返し 2 を乗算します。 値はステップごとに 2 倍になるため、反復回数は 2 を底とする対数に比例します。$n$したがって、この単純なシミュレーションでも、一般的な制約に対しては十分に効率的です。 プロセスの定義を反映しているため、その正しさは即座にわかります。 

ソリューションのより微妙な部分は、現在の値を超えるものを追跡する必要がないことを認識することです。 このプロセスは、問題の初期式から導出された固定定数から始まる純粋に等比数列です。 提供された実装では、この基数は効果的に 3 の定数開始合計に減算され、各ステップは 2 の乗算になります。 

したがって、答えは単純に、以下の値を維持しながら 3 を 2 倍にすることができる回数です。$n$。 これは最大のものを見つけるのと同じです$k$次のような:$$3 \cdot 2^k \le n$$これを書き直すと、事実上、制限を超える前に 2 を何回掛けられるかを数えていることになります。 これはまさに対数増加の問題ですが、浮動小数点対数を使用する代わりに、整数演算を使用して安全に計算します。

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る$t$。 各テスト ケースは独立しているため、結果を保存せずに 1 つずつ処理できます。 
2. それぞれについて$n$、特殊なケースを処理します。$n = 2$。 この場合、最初の意味のある構成はすでに許容範囲に適合していないため、問題の動作で指定されているように、答えはそのまま 1 になります。 
3. 変数を初期化する`sum = 3`、開始時の構成サイズを表します。 
4.初期化`ans = 0`、適用できる有効な 2 倍演算の数をカウントします。 
5. ながら`sum <= n`、乗算する`sum`2ずつ増加します`ans`。 各反復は 1 つの有効な拡張ステップを表します。 
6. 出力`ans`ループが終了した後。 

重要な設計上の選択は、浮動小数点演算を使用して 2 の累乗を計算しないことです。 完全に整数空間内にとどまり、境界での正確な比較を保証します。 

### なぜ効果があるのか

 このプロセスでは、厳密に増加するシーケンスが定義されます。$$3, 6, 12, 24, 48, \dots$$各用語は前の用語のちょうど 2 倍です。 2 を乗算すると順序が維持され、分岐や代替状態が導入されないため、シーケンスは決定的で単調になります。 アルゴリズムは、この等比数列の項が制約内にいくつあるかを効率的にカウントしています。$n$これにより、最終的なカウントの一意性と正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        if n == 2:
            print(1)
            continue

        s = 3
        ans = 0

        while s <= n:
            s *= 2
            ans += 1

        print(ans)

if __name__ == "__main__":
    solve()
```実装はアルゴリズムを正確に反映しています。 特別な場合$n = 2$縮退ループ動作を回避するために明示的に処理されます。 

ループは次の不変条件を維持します。`s`正確な後のサイズは常に現在のサイズになります`ans`倍増。 各反復では、両方の変数を一緒に更新することにより、この不変条件が維持されます。

import sys, io

def run(inp: str) -> str:

 のために$n = 2$の場合、アルゴリズムはループに入らずにすぐに 1 を返します。 これが必要なのは、一般的なループが開始値 3 を想定しており、このような小さな入力の条件にすでに違反しているためです。 

たとえば:

 入力:```

```実行:

 条件`n == 2`トリガーなので、1 を直接出力します。 

これにより、問題がこの境界に対する特別な結果を明示的に定義しているにもかかわらず、有効なステップがないと誤って示唆される 2 倍化プロセスの開始が回避されます。 

非常に大きい場合$n$、 のような$10^9$、指数関数的な増加によりループは約 30 回のみ実行され、各反復では正確な整数演算が維持され、2 のべき乗の境界で精度の問題が発生しないことが保証されます。
