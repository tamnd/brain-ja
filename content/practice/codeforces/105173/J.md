 ## 解決策
 ## 問題の理解

 肉まんと卵の2種類を1食で注文します。 各パンには 0.6 通貨単位の固定価格があり、各卵のコストは 1 単位です。 注文サイズは、バンズの数と卵の数という 2 つの整数で完全に指定されます。 タスクは、この固定食事の合計コストを計算し、それを小数点以下 2 桁に四捨五入した 10 進数として出力することです。 

入力形式では整数を使用できますが、問題の重要な部分は算術精度です。 出力は整数ではないため、浮動小数点書式設定を不注意に扱うと、印刷などの不正確な結果が発生しやすくなります。`39.2`の代わりに`39.20`。 

この制約により、アルゴリズムの複雑さに関する懸念が解消されます。 テスト ケースは 1 つだけあり、両方の値は次のように固定されています。`n = 32`そして`m = 20`。 これは、定数時間演算を実行するソリューションであればどれでも十分であり、冗長な解析ロジックであってもパフォーマンスに影響を与えないことを意味します。 

範囲や無効な入力に関して構造的なエッジケースはありません。 唯一の重大なリスクは、浮動小数点出力が正しくフォーマットされていないこと、特に小数点以下 2 桁を保持できなかったり、バイナリ浮動小数点アーティファクトが発生したりすることです。 

単純な間違いは計算でしょう`32 * 0.6`2 進浮動小数点演算を使用し、生の結果を出力します。 たとえば、Python では、`0.6 * 32`次のような値が生成される可能性があります`19.2`、正常に印刷されますが、他の言語では次のように表示されることがあります。`19.199999...`。 もう 1 つのよくある間違いは、固定精度を適用せずに印刷することです。`39.2`の代わりに`39.20`、厳密な出力チェックでは正しくないと考えられます。 

## アプローチ

 問題の強引な解釈は、購入を直接シミュレートすることです。各パンを反復処理し、累計に 0.6 を加算し、次に各卵を反復処理して、毎回 1.0 を加算します。 これは価格設定の定義を正確に反映しているため、これは正しいです。 ただし、52 回の加算演算が実行されますが、入力の固定的な性質を考慮すると、これはすでに不要です。 さらに重要なのは、このアプローチは両方の量が事前にわかっており、直接乗算できることを無視しているため、構造的に無関係です。 

より効率的なアプローチでは、総コストが入力数の一次式であることが認識されます。 加算を繰り返す代わりに、単純な加重合計としてコストを計算します。バンズが貢献します。`n * 0.6`卵も寄与する`m * 1.0`。 この問題の例では両方の値が定数であるため、計算全体は単一の算術評価とそれに続く書式設定に短縮されます。 

The key observation is that the structure is not dynamic. There is no decision-making, no conditional logic, and no dependence between items. Each unit contributes independently and identically, which allows aggregation through multiplication instead of iteration.

 ## アルゴリズムのチュートリアル

 1. 2 つの整数を読み取ります`n`そして`m`入力から。 これらは、パンと卵の固定数を表します。 
2. バンズからの寄与を乗算して計算します。`n`0.6ずつ。 これにより、同一のコストが 1 つずつ合計されるのではなく、直接集計されます。 
3. 卵からの寄与を乗算して計算します。`m`1.0ごとに。 このステップは、算術効果の観点から概念的には冗長ですが、コスト モデルの明確性は維持されます。 
4. 両方の寄与を加算して、合計コストを取得します。 
5. 結果を小数点以下 2 桁にフォーマットして出力し、末尾のゼロが保持されるようにします。 

### なぜ効果があるのか

 正確さはコストの累積の直線性から生まれます。 各アイテムは独立して追加的に最終価格に寄与するため、同一のアイテムをグループ化しても結果は変わりません。 繰り返される加算を乗算に置き換えることで、正確な算術構造が保持され、最後の書式設定により、値を変更することなく、出力が必要な 10 進表現と一致することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    total = n * 0.6 + m * 1.0
    print(f"{total:.2f}")

if __name__ == "__main__":
    solve()
```このソリューションは 2 つの整数を読み取り、加重合計を直接計算し、フォーマットされた結果を出力します。 重要な実装の詳細は、Python の書式設定された文字列リテラルを次のように使用することです。`:.2f`これにより、末尾のゼロを含む小数点以下 2 桁が保証されます。 

問題の構造は完全に静的であるため、ループや条件は必要ありません。

 ## 特殊なケース

 唯一意味のあるエッジケースは出力フォーマットであり、特に次のような値が保証されることです。`39.2`として印刷されます`39.20`。 このアルゴリズムは、この問題スケールで数学的に正確な浮動小数点数を計算しますが、印刷では固定精度を強制する必要があります。 

入力用`32 20`、計算は次のように進みます。`32 * 0.6 = 19.2`そして`20 * 1 = 20`、与える`39.2`。 書式設定を行わないと、一部の言語または単純な print ステートメントは出力します。`39.2`、厳密な等価性チェックに失敗します。 フォーマットされた出力の場合、結果は次のようになります。`39.20`要求仕様を満たしています。 

入力が固定されており、テスト ケース間で異なる分岐条件や制約がないため、他のエッジ ケースは存在しません。
