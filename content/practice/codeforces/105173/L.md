 ## 解決策
 ## 問題の理解

 完全にバランスの取れた括弧文字列が与えられています。 これは、入れ子になって連結されたセグメントから構築された構造であると考えてください。一致するすべての括弧のペアが、それ自体にいくつかの小さなバランスのとれた部分を含む「コンテナ」を定義します。 

構築プロセスは、可能な限り最小の有効なオブジェクト、つまり 1 対のかっこから始まります。 そこから、2 つの操作が許可されます。 1 つの操作で、現在の構造の右端に新しい空のペアが追加されます。 もう 1 つの操作では、すでに有効なブラケット シーケンスである連続セグメントを選択し、それを追加の外側のペアでラップし、既存のバランスの取れたブロックの周囲に新しいコンテナを効果的に作成します。 

これらの操作の異なるシーケンスによって同じ最終文字列が生成される可能性があり、指定された最終括弧文字列につながる別の操作シーケンスの数を数えるように求められます。 同じラッピングが異なる有効な間隔に適用される場合など、選択された操作がいずれかのステップで異なる場合、2 つのシーケンスは異なるものとみなされます。 

文字列の長さは最大 100 万に達する可能性があるため、操作を列挙したり、間隔にわたって可能性を直接カウントしようとするソリューションは不可能です。 長さの二次関数はすでに失敗しており、シングルパス構築と組み合わせ集計が必要なため、線形時間の作業でさえ慎重に構造化する必要があります。 

単純なアプローチでは、すべての有効な部分文字列を潜在的なラッピング ターゲットとして扱い、可能性を再帰的にカウントしようとします。 これは、バランスの取れたシーケンス内の有効な部分文字列の数が最悪の場合、たとえば「((((....))))」のような文字列では 2 次であるため、すぐに失敗します。 もう 1 つの魅力的なアイデアは、すべての構築シーケンスをシミュレートすることですが、挿入ごとに分岐因子が増加し、状態空間が指数関数的になります。 

さらに微妙な問題は、有効な部分文字列の重複によって発生します。 たとえば、「(())()」では、「(())」と「()」の両方がさまざまな段階でラップする有効な候補であり、これらの選択は相互作用するため、グローバル構造を持たないローカルなカウントは、過剰なカウントや依存関係の欠落につながります。 

## アプローチ

 この問題を扱いやすくするための鍵は、任意の部分文字列という観点から考えるのをやめ、代わりに最後の括弧のシーケンスを階層ツリーとして見ることです。 

すべてのバランスの取れた文字列は、トップレベルで一連のプリミティブ ブロックに独自に分解できます。 各プリミティブ ブロックは、いくつかの小さなバランスのとれたブロックを含む外側のペアであり、再び再帰的に分解されます。 これにより、各ノードが連続したバランスの取れたセグメントに対応し、その子がその内部の直接のバランスの取れたコンポーネントとなるルート付き順序ツリーが自然に形成されます。 

ここで操作を再解釈します。 「append ()」操作は、現在のトップレベルに新しい独立したリーフを作成します。 ラッピング操作では、すでに形成されている平衡セグメントを取得し、その周囲に新しい親ノードを導入します。 これは、ラッピングでは間隔がすでに有効であることが必要であるため、ノードはその間隔内のすべてのノードがすでに存在する後にのみ作成できることを意味します。 

したがって、構築シーケンスを直接カウントする代わりに、すべてのノードがそのサブツリー内のすべてのノードの後に​​出現する必要があるという制約に従って、このツリー内でノードを作成する有効な順序をカウントします。 異なるサブツリーを自由にインターリーブできます。 

強引なアイデアは、ノード作成のすべての有効なインターリーブをシミュレートすることです。 これは、祖先制約の下でツリーのすべてのトポロジー次数を列挙することと同じです。 ただし、これらを直接カウントすると指数関数的になります。

構造的な洞察は、子が固定されると、各ノードのサブツリーが独立して動作するということです。 ノードの場合、その子サブツリーの作成シーケンスをインターリーブしており、すべてのサブツリーが完了した後にのみノード自体を作成できます。 これにより、問題は、多項係数を使用したツリーに対する標準的な組み合わせカウントに帰着します。 

各ノードについて、その子にサブツリー サイズがある場合$s_1, s_2, \dots, s_k$、それでは合併します$k$長さのシーケンス$s_i$、それらをインターリーブする方法の数が多項係数です。 これに各子サブツリーの内部カウントを掛けます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 部分文字列/シーケンスに対するブルート フォース | 指数 | 指数 | 遅すぎる |
 | 多項マージを使用したツリー DP | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、括弧文字列を構造ツリー表現に変換します。 

1. スタックを使用して文字列を解析し、かっこを照合し、包含関係を構築します。 一致したすべてのペアは、その間隔を表すノードを定義します。 
2. 各ノード内で、その直接の子を特定します。 これらは、ペアの直接内側にある最大のバランスの取れたセグメントであり、順番に連続した素の子間隔のシーケンスに対応します。 
3. 最上位レベルでは、文字列全体がプリミティブ コンポーネントの連結です。 これらの最上位コンポーネントを子とする仮想ルートを導入します。 
4. このツリーに対する DFS を使用してサブツリーのサイズを計算します。 各ノードのサイズは、その子のサイズの合計に 1 を加えたものになります。 
5. 各ノードの DP 値を定義します。これは、ノード自体がそのすべての子孫の後に作成されるように、そのサブツリー内の有効な構築オーダーの数です。 
6. ノードについては、まずその子のシーケンスをインターリーブする方法の数を計算します。 お子様にサイズがある場合$s_1, s_2, \dots, s_k$の場合、内部の子の順序制約を尊重しながらサブツリー内のすべてのノードを順序付けする方法の合計が多項係数になります。$$\frac{(s_1 + s_2 + \dots + s_k)!}{s_1! s_2! \cdots s_k!}.$$1. 各子サブツリー自体は任意の有効な方法で構築できるため、このインターリーブ数にすべての子の DP 値を掛けます。 
2. 仮想ルートの DP 値が最終的な答えになります。 

### なぜ効果があるのか

 構築プロセスでは、すべてのノードがその区間内のすべてのノードに依存する半順序が生じます。 この依存関係は、まさに分解ツリーにおける祖先関係です。 有効な操作シーケンスはすべてこのツリーのトポロジー的順序付けに対応し、すべてのトポロジー的順序付けは構築操作の有効なシーケンスに対応します。 

異なるサブツリーは依存関係を共有しないため、それらの操作を任意にインターリーブすることができ、子シーケンスの正しいマージを保証することにより、すべての制約が各ノードでローカルにキャプチャされます。 これにより、グローバル カウンティングの問題が、多項インターリーブによって結合された独立したサブツリー DP 状態に軽減されます。

import sys
input = sys.stdin.readline

MOD = 998244353

def modinv(x):
    return pow(x, MOD - 2, MOD)

def build_tree(s):
    n = len(s)
    parent = [-1] * n
    children = [[] for _ in range(n)]
    stack = []

    for i, c in enumerate(s):
        if c == '(':
            stack.append(i)
        else:
            j = stack.pop()
            parent[j] = i
            parent[i] = j

    # Now build adjacency based on nesting
    # We reconstruct using stack of open intervals
    stack = []
    nodes = []

    for i, c in enumerate(s):
        if c == '(':
            stack.append(i)
        else:
            l = stack.pop()
            nodes.append((l, i))

    # sort by left endpoint
    nodes.sort()

    # build containment tree using stack of active intervals
    tree = [[] for _ in range(n)]
    st = []

    for l, r in nodes:
        while st and not (st[-1][0] < l and r < st[-1][1]):
            st.pop()
        if st:
            tree[st[-1][1]].append(r)
        else:
            tree[n].append(r) if False else None
        st.append((l, r))

    return nodes, tree

def solve():
    s = input().strip()
    n = len(s)

    # simpler correct construction using stack of indices
    pair = [-1] * n
    st = []
    for i, c in enumerate(s):
        if c == '(':
            st.append(i)
        else:
            j = st.pop()
            pair[i] = j
            pair[j] = i

    children = [[] for _ in range(n)]
    root_children = []

    # build children by scanning stack intervals
    # use stack of (l, r)
    intervals = [(i, pair[i]) for i in range(n) if s[i] == '(']
    intervals.sort()

    st = []
    for l, r in intervals:
        node = (l, r)
        while st and not (st[-1][0] < l and r < st[-1][1]):
            st.pop()
        if st:
            children[st[-1][0]].append(l)
        else:
            root_children.append(l)
        st.append(node)

    # better reconstruction via stack of lists
    stack = []
    nodes = []

    for i, c in enumerate(s):
        if c == '(':
            stack.append(i)
        else:
            l = stack.pop()
            nodes.append((l, i))

    nodes.sort()
    child = {l: [] for l, r in nodes}

    st = []
    for l, r in nodes:
        while st and not (st[-1][0] < l and r < st[-1][1]):
            st.pop()
        if st:
            child[st[-1][0]].append(l)
        else:
            root_children.append(l)
        st.append((l, r))

    fact = [1] * (n + 1)
    invfact = [1] * (n + 1)
    for i in range(1, n + 1):
        fact[i] = fact[i - 1] * i % MOD
    invfact[n] = modinv(fact[n])
    for i in range(n, 0, -1):
        invfact[i - 1] = invfact[i] * i % MOD

    sys.setrecursionlimit(10**7)

    size = {}
    dp = {}

    def dfs(x):
        sz = 1
        res = 1
        total = 0

        for y in child.get(x, []):
            dfs(y)
            sz += size[y]

        ways = fact[sz - 1]
        for y in child.get(x, []):
            ways = ways * invfact[size[y]] % MOD

        for y in child.get(x, []):
            res = res * dp[y] % MOD

        dp[x] = res * ways % MOD
        size[x] = sz

    for r in root_children:
        dfs(r)

    # combine roots
    total_size = sum(size[r] for r in root_children)
    ways = fact[total_size]
    for r in root_children:
        ways = ways * invfact[size[r]] % MOD

    ans = ways
    for r in root_children:
        ans = ans * dp[r] % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```この実装は、一致する括弧上のスタックを使用して包含ツリーを再構築することを中心に構築されています。 一致した各間隔はノードになり、間隔の包含によってネストが検出されます。 ツリー構造がわかれば、階乗および逆階乗を使用して、子サブツリーをインターリーブするために必要な多項係数を高速に計算できます。 

微妙な点は、トップレベルのコンポーネントを分離することです。 文字列全体は複数のプリミティブ ブロックで構成されている場合があり、これらは暗黙的なルートの子として扱われます。 それらのシーケンスは任意にインターリーブできるため、すべてのルートを処理した後に最終的な多項マージが適用されます。

| ノードタイプ | 子供のサイズ | ローカルマージ |

 トレースは、複雑さは深さによるものではなく、各ノードが持つ兄弟部分構造の数によるものであることを示しています。これはまさに多項係数が捉えているものです。

 ## 特殊なケース

 「((...))」のような完全にネストされた構造には、中間レベルでの兄弟インターリーブがないため、すべての多項係数は 1 に崩壊します。アルゴリズムは、子の DP 値のみを乗算することになり、葉では 1 のままになり、最終的な答えは 1 になります。これにより、純粋なチェーンが組み合わせ分岐に寄与しないことが確認されます。 

「()()()()」のような完全にフラットな構造では、ルートでのみ最大の分岐が生成されます。 ルートにはサイズ 1 の子が複数あるため、階乗項は次のようになります。$n!$、すべての dp 値が 1 であるため、結果は独立した葉の構成の順列の数とまったく同じになります。
