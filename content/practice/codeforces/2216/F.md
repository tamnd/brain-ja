 ## 解決策
 ## 問題の理解

 星を増加順に並べ替えた後$x$-座標、すべての星は独自の水平位置に表示され、独自の$y$-座標。 ジオメトリは、次の順列によって完全に決定されます。$y$-値をこの順序で並べます。 

調和のとれた三角形は、任意の三角形よりもはるかに制限が厳しくなります。 だって全部$x$そしてすべて$y$値は別個であり、3 つの星は、中央の星が軸に沿った長方形の境界上にある場合にのみ存在できます。$x$-order は、3 つのうちの厳密な極大値または厳密な極小値のいずれかです。 言い換えれば、調和のとれた三角形は、まさに、$y$-コーディネート。 

星座には多くの三角形が含まれている可能性がありますが、それらの内部が重なってはいけません。 エッジまたは頂点の共有は許可されます。 

すべてのテスト ケースの星の合計数は最大で$2 \cdot 10^5$。 すべてのトリプルを検査する解決策は直ちに不可能です。 平$O(n^2)$最悪の場合、テスト ケースごとにコストがかかりすぎる可能性があります。 ソート後には線形に近いものが必要です。 

微妙なケースは、ある点がこれまでに見られた隣接点に関して極大値である場合に現れますが、後の点がその周囲に大きな構造を作成する可能性があります。 恒久的なコミットが早すぎる貪欲なアルゴリズムでは、重複する三角形が生成されたり、存在するはずの三角形が欠落したりする可能性があります。 受け入れられた解決策は、ピークまたは谷が現在のスイープ状態によって完全に決定されるまで決定を遅らせます。 

もう 1 つの簡単な間違いは、答えが多角形の三角形分割に関連していると仮定することです。 星は境界順に与えられた多角形を形成しません。 最適な構成は、次のようにソートした後の点の順列構造から得られます。$x$、平面三角形分割の議論からではありません。 

## アプローチ

 この強引なアイデアは、すべての星のトリプルを調べ、調和しているかどうかをチェックし、その後、何らかの方法でペアごとに素の内部を持つ最大のコレクションを選択することです。 

がある$O(n^3)$トリプル。 調和性を効率的にチェックしても役に立ちません。$n$到達できる$2 \cdot 10^5$。 トリプルの数は次のようになります。$10^{15}$。 

重要な観察は、次のように並べ替えた後です。$x$、調和のとれた三角形は、次のシーケンスの局所極値に対応します。$y$-価値観。 極大値は当然ながら上部エンベロープに属し、極小値は下部エンベロープに属します。 点が上部エンベロープ上で確認されたピークになるたびに、その点を削除して 1 つの調和のとれた三角形に変換できます。 同じ考え方が、下部エンベロープの谷にも対称的に機能します。 

これにより、2 つの単調なスタックが生成されます。 

1 つのスタックは現在の上位チェーンを維持します。 最後の 3 点が厳密な頂点を形成している場合、中央の点を剥がして調和のとれた三角形を作成できます。 

2 番目のスタックは、現在の下位チェーンを維持します。 最後の 3 つの点が厳密な谷を形成している場合、中央の点を剥がして、別の調和のとれた三角形を作成できます。 

すべてのポイントは各スタックから 1 回プッシュされ、多くても 1 回ポップされ、ソート後に線形スイープが行われます。 公式の構築ではまさにこのプロセスが使用され、最大サイズのコンスタレーションが生成されます。

 ## アルゴリズムのチュートリアル

 1. すべてのスターを昇順に並べ替えます$x$-座標。 
2.`up`現在の上位チェーンを表すスタック。 
3. ポイントを左から右に処理します。 
4. 現在点を挿入する前に$p$、上部チェーンの最後の 3 点が厳密なピークを形成しているかどうかを確認します。 最後から 2 番目の点の方が大きい場合$y$隣接する両方の点よりも、これら 3 つの点によって形成される三角形を作成し、スタックからピークを削除します。 
5. 可能な限りピークの除去を続けます。 
6. 現在のポイントを上のチェーンに押し込みます。 
7. 2 番目のスタックを維持する`down`下のチェーン用。 
8. 現在点を挿入する前に$p$、下のチェーンの最後の 3 つのポイントが厳密な谷を形成しているかどうかを確認します。 最後から 2 番目の点の方が小さい場合$y$隣接する両方の点よりも、これら 3 つの点によって形成される三角形を作成し、谷を削除します。 
9. 可能な限り谷の除去を続けます。 
10. 現在のポイントを下のチェーンに押し込みます。 
11. いずれかのスタックによって生成されたすべての三角形が答えに追加されます。 
12. 生成されたすべての三角形を出力します。 

### なぜ効果があるのか

 上部スタックには、処理されたポイントの現在の上部エンベロープが常に格納されます。 この包絡線上で、ある点が隣接する 2 つの点の間の厳密な頂点になると、これら 3 つの点によって形成される三角形は調和します。 そのピークを削除することは、エンベロープから 1 つの面を剥がすことに相当します。 

下のスタックは谷に対して同じことを行います。 

生成された三角形は、まさにエンベロープの連続バージョン間の基本領域です。 これらの領域の内部は互いに素であるため、生成された 2 つの三角形が重なり合うことはありません。 すべての最大の山または谷は、最終的に 2 つのスタックのいずれかによって剥がされる必要があるため、この構造は最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())

        pts = []
        for i in range(n):
            x, y = map(int, input().split())
            pts.append((x, y, i + 1))

        pts.sort()

        up = []
        down = []
        ans = []

        for p in pts:
            while len(up) >= 2:
                a = up[-2]
                b = up[-1]

                if b[1] > a[1] and b[1] > p[1]:
                    ans.append((a[2], b[2], p[2]))
                    up.pop()
                else:
                    break

            up.append(p)

            while len(down) >= 2:
                a = down[-2]
                b = down[-1]

                if b[1] < a[1] and b[1] < p[1]:
                    ans.append((a[2], b[2], p[2]))
                    down.pop()
                else:
                    break

            down.append(p)

        out.append(str(len(ans)))
        for tri in ans:
            out.append(f"{tri[0]} {tri[1]} {tri[2]}")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```最初のステップでは次のように並べ替えます。$x$なぜなら、幾何学的な推論はすべて左から右の順序で行われるからです。 

の`up`stack には、内部頂点が決して厳密なピークではないチェーンが格納されます。 新しいポイントが到着してスタックの最上部にピークを作成するたびに、そのピークは削除されて三角形に変換されます。 

の`down`スタックは完全に対称です。 山の代わりに谷を削除します。 

重要な実装の詳細は、両方のスタック クリーニング ループが`while`ループではなく`if`発言。 1 つのピークを削除すると、そのすぐ下の別のピークが露出する可能性があります。 このカスケードが欠けていると、不正確な答えが生成されます。 

座標自体は比較以外の演算に関与しないため、オーバーフローの懸念はありません。
