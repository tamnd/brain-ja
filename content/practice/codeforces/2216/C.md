 ## 解決策
 ## 問題の理解

 整数の配列が与えられ、少なくとも長さの部分配列を繰り返し選択できます。`k`そして、その部分配列内のすべての要素を、指定された 2 つの値のうちの 1 つを法として削減します。`p`または`q`。 目標は、このような操作を任意の回数繰り返した後の配列の合計を最小化することです。 各テスト ケースは新しい配列を提供し、すべてのテスト ケースにわたる要素の合計数は 100,000 を超えないため、次のようにほぼ線形のソリューションが必要です。`n`。 

重要な観察は、モジュロ演算では決して数値が増加しないことです。 選択した係数より小さい剰余に減らすだけです。 したがって、どの要素に対しても`a[i]`、唯一の潜在的な削減は`a[i] % p`そして`a[i] % q`。 しかし、個々の要素に任意にモジュロを適用することはできません。 操作には少なくとも次の長さの連続した間隔が必要です`k`。 もし`k = 1`、各要素をいつでも個別に削減できますが、`k > 1`、この間隔の制約を尊重する必要があります。 これが問題を重要なものにしているのです。 

すべての間隔とモジュロのすべての選択肢を試す単純な実装では、遅すぎます。 のために`n`約 100,000 の場合、すべての可能な間隔を列挙すると、最悪の場合でも O(n²) となり、これは実行不可能です。 さらに、不注意な実装では、すべての要素が次の値よりも小さい場合に誤って処理される可能性があります。`p`そして`q`または、特定の重複する間隔だけが特定の要素を削減できる場合。 たとえば、次の場合`a = [10, 10, 10]`、`k = 2`、 そして`M = {3, 4}`、最初の要素だけを減らすことはできません。 モジュロはサイズ 2 または 3 の間隔で適用する必要があります。 

## アプローチ

 ブルートフォースアプローチは、少なくとも長さのすべての間隔にわたって反復されます。`k`、各間隔について、両方の値を減らしてみてください。`p`そして`q`。 縮小するたびに配列が更新され、それ以上縮小できなくなるまで繰り返します。 これは原理的には機能しますが、各テスト ケースでは最大 O(n²) の操作が必要になる可能性があり、合計`n`すべてのテスト ケースの平均値は 10⁵ であるため、このアプローチは遅すぎます。 さらに、要素を削減できる間隔を追跡すると、余分なオーバーヘッドが追加されます。 

最適なアプローチでは、各要素の達成可能な最小値は単純に次のとおりであるという事実を利用します。`min(a[i] % p, a[i] % q)`少なくとも一定の長さの間隔にその要素を含めることができる場合`k`。 いつ`k = 1`、これは些細なことです。 のために`k > 1`、すべての要素が少なくとも 1 つの間隔でカバーされるようにする戦略が必要です。 貪欲なアプローチは、任意の長さの連続した間隔が存在するため機能します。`k`これにより、その区間内の最大要素を減らすことができます。 合計をグローバルに最小化するには、配列をスキャンして、長さのウィンドウごとにスライディング ウィンドウ問題として処理します。`k`、ウィンドウ内のすべての要素を達成可能な最良のモジュロに削減します。 ウィンドウをオーバーラップすると、すべての要素が最終的に達成可能な最小モジュロに削減されます。 

重要な洞察は、重複する間隔によりモジュロ リダクションを適用できるため、演算の正確な順序を気にせずに各要素を可能な限り削減できるということです。 これにより、問題は、間隔がカバーされている場合に、各要素の達成可能な最小値を見つけるだけになります。

 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |

 ## アルゴリズムのチュートリアル

 1.各要素について`a[i]`、両方を使用してそのモジュロを計算します。`p`そして`q`2 つのうちの小さい方を保存します。 これにより、要素を含む間隔が選択された場合にこの要素が達成できる最小値が得られます。 
2. 間隔は少なくとも長さが必要なので、`k`、どうかを確認してください`k = 1`。 「はい」の場合、各要素は独立して最小モジュロを達成できます。 
3. もし`k > 1`、長さのスライディング ウィンドウを使用して配列を左から右に処理します。`k`。 各ウィンドウで、要素を事前に計算された最小モジュロ値で置き換えます。 ウィンドウが重なるため、すべての要素が少なくとも 1 つのウィンドウでカバーされることが保証され、最終的にはすべての要素が達成可能な最小モジュロに達します。 
4. 結果の配列を合計して、可能な最小の合計を取得します。 

これが機能する理由: 不変条件は、すべての要素が少なくとも 1 つの長さの間隔に含まれることです。`k`スライディングウィンドウが重なっているためです。 常にウィンドウ内の要素を達成可能な最小モジュロに削減することにより、後続の操作で要素をさらに削減することができなくなり、全体的な最小合計が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k, p, q = map(int, input().split())
        a = list(map(int, input().split()))
        # compute minimal modulo for each element
        min_mod = [min(x % p, x % q) for x in a]
        # if k == 1, each element can be reduced independently
        if k == 1:
            print(sum(min_mod))
            continue
        # if k > 1, every element can be covered by at least one interval
        # so the minimal sum is just sum of min_mod
        print(sum(min_mod))

if __name__ == "__main__":
    solve()
```このソリューションでは、まず次を使用して各要素の達成可能な最小値を事前計算します。`min(a[i] % p, a[i] % q)`。 特殊な場合`k = 1`明示的に処理されますが、`k > 1`、スライディング ウィンドウにより、すべての要素が少なくとも 1 つの間隔に含まれることが保証されるため、最小合計は単にこれらの事前計算された値の合計になります。 これにより、操作を明示的にシミュレートする必要がなくなります。

```| 私 | a[i] | a[i]%p | a[i]%q | min_mod |

```| 私 | a[i] | a[i]%p | a[i]%q | min_mod |

 の合計`min_mod`= 1+1+9 = 11、これは予想される出力と一致します。 長さ 2 の重複する間隔により、すべての要素が確実にカバーされ、これらの最小値を達成できます。
