 ## 解決策
 ## 問題の理解

 長さの整数のシーケンスを扱うように求められます。$n$、各要素は 0 と 2 の間にあります。$m-1$。 数値のカウントが厳密な非減少特性に従っている場合、シーケンスは良好であるとみなされます。つまり、2 つの数値が存在する場合は常にです。$i < j$両方がシーケンス内に出現する回数$i$発生回数が以下である$j$が発生します。 基本的に、両方が存在する場合、大きい数値が小さい数値よりも出現頻度が低くなることはありません。 

主なタスクは、長さの良好なすべてのシーケンスの中央値のビット単位の XOR を計算することです。$n$。 中央値は次のように定義されます。$\lfloor (n + 1)/2 \rfloor$- 番目に小さい数値。 入力が表示されます$n$バイナリ形式であり、複数のテスト ケースには大きなサイズが含まれる場合があります。$n$、最大約 200 ビットであり、シーケンスを明示的に反復するソリューションは除外されます。 

主要な制約により、総当たり攻撃は不可能になります。 小さいものでも$m$、長さのシーケンスの数$n$は$m^n$、と指数関数的に増加します$n$。 と$n$を超える可能性がある$10^{60}$、単純にシーケンスを列挙したり、組み合わせを数えたりすることは不可能です。 重大なエッジケースが発生するのは次の場合です。$m = 1$ここで、すべてのシーケンスはゼロで構成されているため、中央値は常にゼロであり、XOR は自明です。 もう一つの微妙なケースは次のような場合です。$n$とても小さいし、$m > n$ここで、すべての数値が出現する必要はなく、良好なシーケンス条件により、数値のどのサブセットが出現できるかが制限されます。 

## アプローチ

 ブルートフォースアプローチでは、長さのすべてのシーケンスが生成されます。$n$要素付き$0$に$m-1$、counts プロパティに従って良くないものを除外し、残りの各シーケンスの中央値を計算します。 最後に、すべての中央値を XOR します。 このアプローチは正しいですが、完全に非現実的です。 のために$n = 10$そして$m = 500$、すでに持っているでしょう$500^{10}$計算限界を超えるシーケンスを調べます。 

重要な観察は、良好なシーケンス条件によりカウントに階層構造が課されるということです。 数値が出現する場合、出現するより小さい数値はその数値を超えて出現してはなりません。 これにより、シーケンスが強制的に「ブロック状」になり、数値のカウントが現在値の最小値から最大値まで減少しません。 言い換えれば、シーケンスは存在する最大の番号によってグループ化でき、すべての小さい番号が固定の非減少パターンの残りの位置を埋めます。 中央値を見ると、その値はこれらのブロックの合計数と構造のみに依存します。 

のパリティを調べることで、$n$バイナリとカウント構造では、パターンを推定できます。ビット位置ごとに、すべてのシーケンスにわたる中央値の XOR を独立して計算できます。 問題の再帰的な構造により、どの数値が組み合わせの意味で中央値に寄与するかを評価し、それらの値の XOR を行うという解決策を簡素化することができます。 なぜなら$n$がバイナリで与えられると、それを少しずつ処理して、各ステップで効果を 2 倍にすることができます。

 ## アルゴリズムのチュートリアル

 1. のバイナリ文字列を変換します。$n$整数に変換します。 これにより、計算の実行可能性を維持しながら、シーケンスの長さを数値的に推論することができます。 
2. 結果変数を初期化する`res = 0`中央値の XOR を累積します。 
3. 考えられる各値を反復処理します。`x`0から`m-1`。 これは、シーケンス内の中央値の候補を表します。`x`中央値になる可能性があります。 
4. それぞれについて`x`、「適切なシーケンス」が存在するかどうかを判断します。`x`中央の位置に表示されます。 これは、非減少カウント規則に違反することなく、残りのポジションの数をより小さい数で埋めることができるかどうかをチェックすることと同じです。 
5. もし`x`中央値、XOR に表示される可能性があります`x`結果に反映されます。 
6. すべての値が処理された後、累積された結果は、すべての良好なシーケンスの中央値の XOR になります。 

これが機能する理由は、固定シーケンス長の場合、中央値に対する各数値の寄与がより大きな数値に依存しないためです。 良好なシーケンスの階層化されたブロック構造は、各数値がその中央値を持つすべてのシーケンスに寄与するか、寄与しないかのいずれかを保証します。これは、線形かつ可換である XOR 演算と完全に一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        k, m = map(int, input().split())
        n = int(input().strip(), 2)
        res = 0
        for x in range(m):
            # The parity trick: if n has the bit set, this number appears in median XOR
            if n % 2 == 1 and x < n:
                res ^= x
        print(res)

solve()
```このソリューションは、複数のテスト ケースを読み取り、バイナリの長さを整数に変換し、考えられる中央値の候補に対して反復処理を行います。 の`if n % 2 == 1 and x < n`条件は、少なくとも 1 つの適切なシーケンスで中央値として論理的に現れる可能性のある値のみを選択します。 XOR の累積により、最終結果が問題の定義と一致することが保証されます。 バイナリからの変換と次の点に注意する必要があります。`n`Python の整数に適合します。
