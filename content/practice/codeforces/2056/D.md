 ## 解決策
 ## 問題の理解

 中央値が一意に定義されている特定の配列の部分配列を数えるように求められます。 実際には、これは、並べ替え後の中央の要素 (長さが偶数の場合は中央の 2 つの要素) が等しい場合、サブ配列が適切であることを意味します。 奇数長の部分配列の場合、単一の中央値は常に「それ自体に等しい」ため、これは簡単です。 偶数長の部分配列の場合、中央の 2 つの数値が同一である必要があります。 

配列値は 1 ～ 10 の範囲と小さいですが、配列は最大 10^5 要素まで大きくすることができます。 最大 10^4 のテスト ケースでは、すべてのテストにわたる合計配列サイズの上限は 10^5 です。 これは、最悪の場合、10^10 の演算が必要となるため、テスト ケースごとに O(n^2) のアプローチを使用する余裕がないことを意味します。 テスト ケースごとに O(n) または O(n log n) に近い値が必要です。 

エッジ ケースは、すべての要素が同一ですべてのサブ配列が良好になる場合、またはすべての要素が区別され、良好な偶数長のサブ配列の数が減少する場合に発生します。 不注意な解決策では、すべての部分配列の中央値を明示的にチェックしようとする可能性がありますが、これでは時間がかかりすぎます。 小さな例でこれを説明します。`[1,2]`、サブ配列`[1,2]`2 つの中央値が異なるため、これは適切ではありません。 のために`[1,1,1,1]`、中央値が常に一致するため、すべての部分配列は良好です。 

## アプローチ

 ブルート フォース ソリューションでは、すべてのサブ配列を反復処理し、それぞれをソートして、中間の要素をチェックします。 それは正しいですが、最悪の場合は O(n^3) としてスケールされます (O(n^2) 個のサブ配列、それぞれに O(n log n) ソートが必要です)。 n が 10^5 までの場合、これは完全に不可能です。 

重要な観察は、問題が「中心」値の頻度に基づいてサブ配列をカウントすることに帰着できるということです。 番号を修正する`x`そしてそれを候補中央値とみなします。 配列内の各位置について、実行カウントを追跡します: 要素が等しい場合は +1`x`未満の場合は -1`x`、それ以外の場合は 0。 偶数長の部分配列の場合、次の値より大きい要素の数が必要です。`x`未満`x`周りのバランスをとるために`x`中央値を正確に作るには`x`。 これにより、問題はプレフィックス合計カウント問題に変換されます。カウント間の差がキーを形成し、各インデックスで終わる良好なサブ配列の数は、これらのキーの頻度を追跡するハッシュマップを使用して計算できます。 

この洞察は、潜在的に三次的な問題を候補中央値ごとの線形な問題に変換します。 値は 10 で制限されているため、可能なすべての値を反復できます。`x`1 から 10 までの範囲で計算すると、全体的な複雑さは O(10 * n) = O(n) になりますが、これは許容範囲内です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^3) | O(n) | 遅すぎる |
 | 最適 | O(n * max(a_i)) | O(n * max(a_i)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 考えられる各中央値候補を反復処理します。`x`1 から 10 まで。これは実行可能です。`a_i`≤ 10. 各候補者`x`別途検討させていただきます。 
2. アレイをランニングバランスアレイに変換します。`balance`、位置 -1 で 0 で初期化されます。 配列内の各要素について、次の値に等しい場合`x`、前の残高に 1 を追加します。 未満の場合`x`、1を減算します。 より大きい場合`x`、残高は変更しないでください。 このエンコーディングは、`x`接頭辞で。 
3. ハッシュマップを使用する`freq`各残高値の出現をカウントします。 で初期化します`{0: 1}`空のプレフィックスのバランスは 0 であるため、位置ごとに、中央値でこの位置で終わる部分配列の数`x`の現在のバランス値の周波数に等しい`freq`。 これは、同じバランスを持つ 2 つのプレフィックスは、それらの間のサブ配列のネットバランスが 0 であることを意味するため、機能します。`x`は中央値です。 
4. すべての位置にわたるこれらのカウントを合計して、この候補中央値の良好なサブアレイの総数を取得します。 
5. 1 から 10 までのすべての候補のカウントを合計して、テスト ケースの答えを取得します。 

機能する理由: バランス配列は、同じバランスを持つ 2 つのプレフィックス間のサブ配列内で、`x`より小さい要素の数を引いたもの`x`は変わっていない。 これにより、`x`はその部分配列の中央値です。 全てを考慮した上で`x`、配列内のすべての可能な中央値をカバーします。 

## Python ソリューション```python
import sys
from collections import defaultdict
input = sys.stdin.readline

def count_good_subarrays(a):
    n = len(a)
    ans = 0
    for x in range(1, 11):
        balance = 0
        freq = defaultdict(int)
        freq[0] = 1
        for val in a:
            if val == x:
                balance += 1
            elif val < x:
                balance -= 1
            # val > x does not change balance
            ans += freq[balance]
            freq[balance] += 1
    return ans

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    print(count_good_subarrays(a))
```このソリューションは、高速 I/O を使用して入力を読み取ります。 候補の中央値を 1 から 10 までループし、暗黙的にプレフィックス バランス配列を計算します。 ハッシュマップ`freq`以前の残高をカウントして、サブ配列カウントの O(1) 取得を可能にします。 微妙な点には初期化が含まれます`freq[0] = 1`インデックス 0 から始まるサブ配列を考慮し、現在のプレフィックスの欠落を避けるために頻度を増やす前に答えを更新します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n * 10) = O(n) | 外側のループはテスト ケースごとに 10 回実行され、内側のループは n 回実行されます。 
| スペース | O(n) | ハッシュマップ`freq`最大で n+1 個の固有の残高を保存できます。 

これは、n ≤ 10^5 および t ≤ 10^4 の制約内で快適にスケーリングされます。 残高は小さな整数であり、候補中央値ごとに最大でも n 個のキーが存在するため、メモリ フットプリントは 512 MB 未満のままです。
