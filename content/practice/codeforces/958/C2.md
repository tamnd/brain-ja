 ## 問題の理解

 一連の整数が与えられ、それを正確に切り分けるよう求められます。$k$連続した空ではないセグメント。 各要素は正確に 1 つのセグメントに属している必要があり、要素の順序は保持されます。 

任意のセグメントについて、その要素の合計を取得し、その合計を剰余として減算します。$p$。 パーティションの合計スコアは、これらのセグメントごとのモジュロ値の合計です。 タスクは、$k-1$この合計スコアが最大になるように位置をカットします。 

この問題の重要な問題点は、セグメントの合計が剰余のモジュロを通じてのみ相互作用するということです。$p$一方、カット自体は連続性を尊重する必要があります。 この組み合わせは、プレフィックスとセグメント数に対する動的プログラミング構造を示唆しています。 

この制約は、k x n x n の指数関数または二次関数のアプローチを除外するのに十分なほど強力です。 と$N \le 20000$そして$k \le 50$、約の解決策$O(N^2 k)$に達してしまうため、すでに遅すぎます。$2\times 10^{10}$操作。 これにより、私たちは次のような方向に向かって進みます。$O(N k)$または$O(N k p)$-スタイルの繰り返しでトランジションが最適化されます。 

セグメントの合計が次の値を超えると、微妙な問題が発生します。$p$。 単純な実装では、セグメントの合計を繰り返し再計算したり、セグメントの合計を計算するのにプレフィックスの合計だけが必要であることを忘れたりする可能性があります。$O(1)$。 

もう 1 つの落とし穴は、DP 状態の方向を誤解していることです。 セグメントは連続しているため、最後のセグメントが 位置で終了することを確認する必要があります。$i$、すべての可能な以前のカット位置を正確に考慮しています。 

不注意な推論が失敗する小さな例としては、次のような場合があります。$k = 1$。 答えは単純です$\sum A \bmod p$しかし、単純な DP は誤って少なくとも 1 つのカットとアンダーカウントを強制する可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、あらゆる方法で配置を試行します。$k-1$間のカット$N-1$可能性のあるギャップ。 各パーティションはセグメントの合計を計算し、モジュロを適用します。$p$。 パーティションの数は、$\binom{N-1}{k-1}$、これは中程度の場合でも天文学的に大きくなります。$N$、各スコアのコストを計算する$O(N)$実行不可能な実行時間につながります。 

セグメントの値がその和の剰余にのみ依存することを観察すると、問題の構造は管理可能になります。$p$、セグメントの合計はプレフィックスの合計を使用して迅速に計算できます。 これは、固定数のセグメントを持つ配列のプレフィックスに対して達成可能な最良のスコアを追跡する DP を示唆しています。 

させて$dp[j][i]$最初の値を使用して最大スコアを表します$i$要素が分割される$j$セグメント。 計算するには$dp[j][i]$、可能なすべての以前のカットポイントを試します$t < i$、治療する$[t+1, i]$最後のセグメントとして。 セグメント貢献度は$(prefix[i] - prefix[t]) \bmod p$。 

これにより、問題は従来のパーティション DP に限定されます。 ただし、ナイーブな移行は$O(N^2 k)$が遅すぎます。 重要な最適化は修正することです$j$そしてプロセス$i$左から右へ、可能な限り最良の値を維持$dp[j-1][t] - prefix[t] \bmod p$-調整された構造ですが、モジュロが小さいため($p \le 100$)、代わりに、残差クラス全体で最良の値を追跡することで遷移を最適化できます。 

遷移を書き換えます。$$dp[j][i] = \max_{t < i} \left( dp[j-1][t] + (prefix[i] - prefix[t]) \bmod p \right)$$モジュロ項を展開すると、次の依存関係が得られます。$prefix[i] \bmod p$そして$prefix[t] \bmod p$。 以来$p$が小さい場合、各残基の最良の値を維持します。$prefix[t] \bmod p$、状態ごとに一定時間の遷移が可能になります。 

これにより、各 DP レイヤーが折りたたまれます。$O(Np)$、全体的に複雑になります$O(Nkp)$。
