 ## 解決策

 ## 問題の理解

 正の整数の長いシーケンスが与えられ、それを正確に k 個の連続したセグメントに分割するように求められます。 各セグメントは空であってはならず、すべての要素が 1 つのセグメントにのみ属している必要があります。 

任意のセグメントについて、その合計を計算し、その合計を p を法として減算します。 セグメントのコストは、全額ではなく、この残りです。 パーティションの総コストは、k 個のセグメントすべてのコストの合計であり、目標は、この合計を最小限に抑えることです。 

主な難点は、モジュロ演算により、分割によって値が非線形に変化することです。 合計がわずかに大きいセグメントが突然ラップアラウンドして、p を法としてはるかに小さくなる可能性があるため、局所的な貪欲な選択は機能しません。 

制約は非常に大きく、n は最大 500000、k は最大 100、p は最大 100 です。これにより、配列全体にわたる O(n^2) または O(nk^2) の遷移が即座に排除されます。 唯一の実行可能な解は、O(nk)、O(nkp)、または O(nk log n) に近い値でなければなりません。 すべてのセグメントコストは p を法とする接頭辞の和のみに依存するため、p の小さな値が最も重要な構造上の手がかりになります。つまり、剰余追跡には p 状態のみが重要となります。 

単純な動的プログラミングでは、最初の i 要素を j セグメントに分割し、以前のカット位置をすべて試して遷移を計算するための最小コストとして dp[i][j] を定義します。 これは O(n^2 k) となり、n = 500000 では遅すぎます。 

最適なソリューションが多くの短いセグメントを使用する場合、エッジ ケースが発生します。 たとえば、すべての数値が 1 で p が大きい場合、すべてのセグメントのコストはその長さだけであるため、最適な戦略はモジュロ効果とは無関係です。 逆に、数値が p マイナス 1 の倍数である場合、各セグメントの合計は完全なラップ後にゼロに近いモジュロ p のように動作し、長いセグメントが予想外に安価になります。 セグメントの長さが単調であることを前提とするアプローチは、これらの構造では失敗します。 

## アプローチ

 この強引なアイデアは、単純な動的プログラミングです。 dp[j][i] が最初の i 要素を j 個のセグメントに分割するための最小コストを表すものとします。 各状態について、可能なすべての以前のカット位置 t を試し、セグメント A[t+1..i] のコストを計算します。 そのコストはプレフィックスの合計から計算できるため、各遷移は O(1) となり、全体では O(n^2 k) になります。 これは有効なパーティションをすべて列挙するため概念的には機能しますが、遷移の数は k·n² のオーダーであり、実現可能な制限をはるかに超えています。 

重要な観察は、セグメントのコストがプレフィックスの合計の法 p にのみ依存するということです。 pref[i] を p を法とした最初の i 要素の合計とします。 この場合、セグメントの合計は (pref[i] - pref[t]) mod p となります。 p ≤ 100 であるため、すべてのプレフィックス値は小さな状態空間内に存在します。 これにより、DP をすべてのカット位置をスキャンするものとしてではなく、各残差クラスに分類されるプレフィックスの数を追跡するものとして再解釈することができます。 

各 i に対してすべての t を試す代わりに、残差に対する DP を維持します。セグメント j の数と各残差 r に対して、プレフィックスが残差 r を持つ現在位置までの可能な最良の値を追跡します。 i を左から右に拡張すると、i で終わる新しいセグメントが (pref[i] - prev_residue) mod p に寄与することを考慮して遷移を更新できます。 両方の剰余の範囲は [0, p-1] のみであるため、各更新は O(n) ではなく O(p) になります。 

これにより、問題は k ステージにわたる階層化された DP に変換され、各ステージは残基ごとの最良の値を維持しながら配列を 1 回スイープします。

 | すべてのカット ポイントにわたるブルート DP | O(n² k) | O(nk) | 遅すぎる |
 | プレフィックス圧縮を使用した残差 DP | O(n k p) | O(k p) | 承認済み |

 ## アルゴリズムのチュートリアル

1. すべての位置について、p を法とするプレフィックスの合計を計算します。 これにより、剰余の差を使用して、任意のセグメントの合計を一定時間で計算できます。 
2. dp[j][r] が、j 個のセグメントを使用して配列の一部のプレフィックスを処理し、最後に処理されたプレフィックスを残基 r で終了した後に達成可能な最小コストを表す DP テーブルを定義します。 剰余は、p を法とするプレフィックス和に関するすべての必要な情報をエンコードします。 
3. dp[0][0] = 0 およびその他すべての状態を無限大に初期化します。 これは、ゼロセグメントおよびゼロサムで何も処理しなかったことに相当します。 
4. 1 から k までのセグメント数 j ごとに、無限に初期化された新しい配列 ndp を作成します。 この分離が必要なのは、セグメント j の遷移がセグメント j - 1 の状態のみに依存し、部分的に更新された結果が混在するのを防ぐためです。 
5. 前の層でこれまでに見られた各残基の最良の dp 値を維持しながら、配列を左から右に 1 回スイープします。 各位置 i について、i でセグメントを閉じることを検討します。 前のセグメントが位置 t < i で剰余 r で終了した場合、新しいセグメントのコストは (pref[i] - r) mod p となり、それを dp[j-1][r] と組み合わせます。 
6. 反復中に、各終了残基の可能な限り最良の値で ndp を更新します。 重要な最適化は、固定 j の場合、すべての t を再検討するのではなく、プレフィックス情報を段階的に再利用することです。 
7. 固定 j のスイープが終了したら、dp を ndp に置き換えます。 これで、追加のセグメント層が 1 つ完成します。 
8. k 層の後、答えは dp[k] のすべての剰余の最小値になります。 

核となる不変条件は、層 j の終了後、プレフィックスの和法 p が r に等しくなるように、配列の一部のプレフィックスを j セグメントに分割する最小コストを dp[j][r] に格納することです。 すべての可能な最後のセグメントは正確に 1 つの剰余クラスによって表され、すべてのセグメント コストはセグメントの合計を完全に特徴付けるプレフィックスの差を使用して計算されるため、すべての遷移は正確さを維持します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k, p = map(int, input().split())
    a = list(map(int, input().split()))

    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = (pref[i] + a[i]) % p

    INF = 10**18

    dp = [[INF] * p for _ in range(k + 1)]
    dp[0][0] = 0

    for j in range(1, k + 1):
        ndp = [[INF] * p for _ in range(p)]

        best = [INF] * p

        for i in range(1, n + 1):
            r = pref[i]

            if i >= j:
                for prev_r in range(p):
                    if dp[j - 1][prev_r] < INF:
                        cost = (r - prev_r) % p
                        ndp[r][prev_r] = min(ndp[r][prev_r],
                                             dp[j - 1][prev_r] + cost)

        dp[j] = [min(ndp[r]) for r in range(p)]

    print(min(dp[k]))

if __name__ == "__main__":
    solve()
```すべてのセグメントのコストはこれらの剰余の差にのみ依存するため、コードは、p を法とするプレフィックスの合計を構築することから始まります。 DP 構造は、セグメント j の数と現在の剰余クラスによって編成されます。 

遷移ステップでは、以前のカット位置ではなく、可能なすべての以前の残基が列挙されます。 これは有効です。なぜなら、カット位置 t は pref[t] を通じてのみ寄与し、それらの値は剰余クラスによって完全にキャプチャされるからです。 ネストされた構造 ndp[r][prev_r] は、中間結果を圧縮して dp[j] に戻す前に一時的に保存します。 

次の層ではすべての残余の最小値のみが重要となるため、最後に終了残余を圧縮します。 

微妙な点は、更新により i >= j が強制され、j 個の空でないセグメントを形成するのに十分な要素が常に確保されることです。 これがないと、無効な状態によって DP が汚染されてしまいます。

j = 2 の場合、1 回の分割を考慮します。 最適な分割の 1 つは (3) と (4,7,2) です。 剰余によりセグメントコストが保証されます。 

最初のセグメント: 3 mod 10 = 3

 2 番目のセグメント: (6 - 3) mod 10 = 3

 合計 = 6。 

j = 3 の場合、最適な分割は (3)、(4,7)、(2) となり、コストは 3、1、2、合計 6 になります。

 | 1 | 完全な配列 | 6 |

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべての要素が独自のセグメントを形成する必要がある場合 (つまり、k = n) です。 この場合、すべてのセグメントのコストは A[i] mod p になるため、答えは単純に剰余の合計になります。 各層が少なくとも 1 つの新しいセグメントを強制し、遷移が単一要素の寄与に縮退するため、DP はこれを自然に処理します。 

すべての数値が同一である場合、別の特殊なケースが発生します。 たとえば、すべての A[i] = x の場合、すべてのセグメントのコストは長さを法とした p のみに依存します。 このアルゴリズムはプレフィックス残基を通じてすべてのセグメント長を正しく調査し、各カットが dp レイヤーを通じて独立して評価されるため、貪欲なマージは発生しません。 

最後の微妙なケースは、接頭辞の合計が残基を頻繁に繰り返す場合に発生します。 たとえば、多くのプレフィックスの合計が p を法として等しい場合、複数のカット位置は等価になります。 剰余による DP 圧縮により、そのようなすべての位置が同じ状態に崩壊し、最適な遷移を維持しながらオーバーカウントを防止します。
