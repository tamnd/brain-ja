 ## 解決策
 ## 問題の理解

 平面内に 2 つの点のセットが与えられ、それぞれに同じ数の点が含まれます。 1 つのセットは宇宙船を表し、もう 1 つのセットは基地を表します。 すべての点は固有の位置を持ち、単一の直線上に 3 つの点が存在することはありません。 

タスクは、各宇宙船を個別のベースとペアにして、すべての宇宙船が正確に 1 つのベースに一致するように、またその逆も同様であり、一致したペア間に引かれた直線セグメントが互いに交差しないようにすることです。 

出力は、入力順の各宇宙船について、どの基地に接続されているかを記述する順列です。 交差しない有効な完全一致を自由に選択できます。 

n が 10000 までという制約は、合計で最大 20000 点を扱うことを意味します。 単純な O(n^2) または O(n^2 log n) アプローチはすでに限界に達していますが、慎重に実装すれば受け入れられます。 すべてのペア間の一般的な幾何学的交差チェックを伴うものは、O(n^2) 個の潜在的なセグメント相互作用が存在するため遅すぎます。これは最大サイズで約 10^8 であり、構造が利用されない限り、複数の再帰レベルでは依然として危険です。 

素朴な貪欲マッチングの微妙な失敗例は、最近傍を選択するか、X 座標によるペアリングを選択することです。 たとえば、各宇宙船を最も近い基地とペアリングすると、グローバルに一貫したマッチングが存在する小規模な構成であっても、すぐに交差を作成できます。 

もう 1 つの間違った考え方は、船と基地を X 座標で個別に並べ替え、それらを順番にペアにすることです。 これは、正しい非交差構造が線形順序付けではなくピボット ポイントを中心とした「回転」を必要とする場合には失敗します。 艦艇と基地が凸状の位置で交互に配置される小さな構成では、すでにこのアプローチが崩れており、交差する対角線が生成されます。 

重要な問題は、局所的な幾何学的近接性が全体的な平面性の制約を考慮しないことです。 

## アプローチ

 ブルートフォース戦略では、段階的にマッチングを構築しようとします。 各ステップで、残りの宇宙船と残りの基地を組み合わせて、このセグメントが以前に選択したセグメントと交差するかどうかを確認します。 これには、選択肢ごとに O(n) 個の交差チェックが必要で、層ごとに n 個の選択肢があり、O(n^2) の決定が行われ、それぞれのコストが O(n) となり、O(n^3) になります。 枝刈りを行ったとしても、幾何学的制約により、このアプローチは n = 10000 では実行不可能になります。 

構造上の画期的な進歩は、すべての点の結合を平面内の色付きのセットとして見ることによってもたらされます。 非交差完全マッチングは常に存在するため、接続セグメントが残りの点を 2 つの独立した部分問題に分割するペアを 1 つ選択する方法が必要です。 形状により、そのような「バランスの取れたセパレータ エッジ」が存在することが保証されます。 

この構造を公開する標準的な方法は、ピボット ポイントを固定し、その周囲の極角に基づいて他のすべてのポイントを並べ替えることです。 船を +1、基地を -1 として扱いながら円周を歩くと (ピボット タイプによってはその逆)、この円周順序の累積合計はゼロに戻らなければなりません。 これは、プレフィックスのバランスがとれた位置が存在し、そのプレフィックスがプレーンを 2 つの領域にきれいに分割する有効な一致エッジに対応することを意味します。 

このようなペアが選択されると、それらの間のセグメントは有効な解の構造と交差せず、残りの点を 2 つの独立したグループに分割し、再帰的に解くことができます。 

これにより、角度ソートを使用して選択したピボットのバランスの取れたパートナーを繰り返し見つけ、両側で再帰するという問題が軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | Brute force incremental matching | O(n^3) | O(n^2) | 遅すぎる |
 | Angular partition + recursion | O(n^2 log n) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

1. すべての船と基地を単一の点セットとして扱い、それぞれにその種類を示すラベルを付けます。 一致するペアを削除することで問題を繰り返し軽減します。 
2. 残りの点をピボットとして選択します。 最初の未使用の宇宙船を選択するのが便利ですが、存在引数が対称であるため、残りの点はどれでも機能します。 
3. 残りのすべての点をピボットの周りの極角で並べ替えます。 この順序付けはピボットの周りの完全なスイープを表すため、すべての幾何学的方向が線形化されます。 
4. 現在のバランス値を維持しながら、このソートされた順序をたどって、船の場合は +1、基地の場合は -1 を追加します (一貫性がある限り、ピボットが基地の場合はその逆)。 バランスは、角度プレフィックスに一方のタイプが他方よりもどれだけ多く現れるかを測定します。 
5. この循環移動でバランスがゼロになる最初の位置を見つけます。 その位置にある点がピボットの有効なパートナーを形成します。 

これが機能する理由は、ゼロバランスに戻ると、ピボットとその点の間の角度セクターに同数の船舶と基地が含まれ、閉鎖された自己完結型の領域になるためです。 
6. ピボットをこの特定されたパートナーと照合し、両方のポイントをアクティブ セットから削除します。 
7. それらの間に描かれた線分は、残りの点を有向線の異なる側にある 2 つのグループに分割します。 両方のサブセットで独立して再帰します。 

### なぜ効果があるのか

 重要な不変条件は、すべての再帰呼び出しが、交差することなく完全に一致する点のセットに対して動作し、選択されたピボット パートナー セグメントが常に残りの点を、一致の実現可能性の点で独立した 2 つの領域に分割することです。 

極スイープにより、選択したパートナーがバランスの取れた分割を作成することが保証され、将来のマッチングでセグメントをまたぐ必要がなくなります。 再帰ごとに点の数が 2 ずつ減り、各辺の実現可能性が維持されるため、このプロセスでは最終的に交差のない完全なマッチングが生成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def cross(o, a, b):
    return (a[0]-o[0])*(b[1]-o[1]) - (a[1]-o[1])*(b[0]-o[0])

def solve(points, res):
    if not points:
        return

    p = points[0]
    others = points[1:]

    # sort by polar angle around p
    others.sort(key=lambda x: (-(x[0]-p[0]) / ((x[1]-p[1]) or 1e-18)))

    # We avoid floating instability by using cross-product comparator via angle sorting trick
    def cmp(a):
        dx = a[0] - p[0]
        dy = a[1] - p[1]
        return (dy < 0, 0)  # placeholder not used in final logic

    # Proper polar sort using atan2 via tuple trick
    import math
    others.sort(key=lambda x: math.atan2(x[1]-p[1], x[0]-p[0]))

    bal = 1 if p[2] == 0 else -1  # 0 ship, 1 base

    partner = None
    for q in others:
        bal += 1 if q[2] == 0 else -1
        if bal == 0:
            partner = q
            break

    res[p[3]] = partner[3]
    res[partner[3]] = p[3]

    # partition remaining points by line pq
    left = []
    right = []
    for r in others:
        if r is partner:
            continue
        if cross(p, partner, r) > 0:
            left.append(r)
        else:
            right.append(r)

    solve(left, res)
    solve(right, res)

def main():
    n = int(input())
    pts = []
    for i in range(n):
        x, y = map(int, input().split())
        pts.append((x, y, 0, i))

    for i in range(n):
        x, y = map(int, input().split())
        pts.append((x, y, 1, i))

    res = [-1] * n
    solve(pts, res)

    print("\n".join(map(str, res)))

if __name__ == "__main__":
    main()
```コードは再帰的分解を維持します。 各呼び出しはピボット ポイントを選択し、角度スイープ ロジックを使用してパートナーを見つけようとします。 一致すると、一致したセグメントに対する外積を使用して残りの点を分割し、2 つの独立した部分問題への幾何学的分離を保証します。 

主要な実装の詳細は外積分割です。これにより、再帰中に角度について明示的に推論する必要がなくなります。 再帰構造により、パートナーの選択が有効でバランスの取れたものである場合でも、正確さが保証されます。 

## 実用的な例

 2 つの船 S1、S2 と 2 つの基地 B1、B2 が、交差しないペアが対角線上に存在するように配置された小規模な構成を考えてみましょう。 

| ステップ | ピボット | 並べ替え順序 (概念的) | バランス進化 | 選択されたペア |
 | --- | --- | --- | --- | --- |
 | 1 | S1 | B1、S2、B2 | S2 で +1、0 | S1-S2 |
 | 2 | 残り | B1、B2 | つまらない | B1-B2 |

 これは、角度スイープによってバランスの取れたパーティションが即座に強制され、エッジの交差を防ぐ方法を示しています。 

ここで、船と基地が円の周りで交互に配置される、少し大きな凸状の構成を考えてみましょう。 

| ステップ | ピボット | スイープ注文 | バランス | ペア |
 | --- | --- | --- | --- | --- |
 | 1 | 任意の船 | 交互ラベル | 反対側の点ではゼロに戻ります | 有効な反対のペアリング |
 | 2 | 削減されたセット | 小さいサイクル | 繰り返し構造 | 再帰的マッチング |

 トレースは、アルゴリズムが交互の構造を繰り返し独立した半分に折りたたんで、平面性を維持していることを示しています。

 ## 特殊なケース

 すべての点が凸包上にある構成では、角度スイープ ステップにストレスがかかります。 すべてのポイントが巡回順序で表示され、有効なパートナーでは残高が必然的にゼロに戻り、強制的な交差が発生しないため、ピボットの選択は引き続き機能します。 

多くの点がほぼ揃っているものの、制約により正確に揃っていない、ほぼ同一線上にある摂動のケースでは、外積分割が縮退しないことが保証されます。 「3 つの共線性がない」という厳密な保証により、ポイントがどちら側にあるのかが曖昧になることがないため、すべての再帰的分割は明確に定義され、安定した状態に保たれます。
