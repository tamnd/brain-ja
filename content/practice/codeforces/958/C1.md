 ## 解決策

 ## 問題の理解

 整数の配列とモジュラス値が与えられます。$p$。 タスクは、配列を 2 つの連続する空ではないセグメントに分割する単一のカット位置を選択することです。 各セグメントについて、その合計を計算し、それを剰余で減らします。$p$を選択し、2 つの結果を加算します。 目標は、この合計値を最大化するカットを見つけることです。 

正式には、ポジションの後にカットすると$i$、答えは次のようになります。$$(\text{sum of } A[1..i] \bmod p) + (\text{sum of } A[i+1..n] \bmod p)$$出力は、すべての有効なカット位置で達成可能な最大値です。 

制約は、配列サイズで線形または線形に近い解を強制するのに十分なほど厳しいものです。 と$n \le 100{,}000$、 どれでも$O(n^2)$すべての部分配列の計算を直接試行するアプローチは遅すぎます。 たとえ$O(n \log n)$解決策は受け入れられますが、不要です。 プレフィックス合計の構造により、この問題は線形時間で解決可能になります。 

微妙な落とし穴は、モジュロが分割とどのように相互作用するかを誤解していることから発生します。 たとえば、分割ごとに合計を再計算する必要があると考える人もいるかもしれませんが、プレフィックス合計では各セグメントの合計が O(1) になります。 

もう 1 つのよくある間違いは、両方の部分が独立して最大化されていると仮定することです。 これは、カットによってそれらが結合されるため、不正確です。一方の合計を増加させると、他方のモジュロ結果が減少する可能性があります。 

エッジケースの小さな例は次のとおりです。 

入力:```
3 5
4 4 4
```最初の要素の後でカットすると、次のようになります。$4 \bmod 5 + 8 \bmod 5 = 4 + 3 = 7$。 

2 番目以降をカットすると:$8 \bmod 5 + 4 \bmod 5 = 3 + 4 = 7$。 

どちらも同等であり、単純に貪欲な選択をすると、一方の方向が優れていると誤って仮定する可能性があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 考えられるすべての分割ポイントを試します$i$。 分割ごとに、左側のセグメントと右側のセグメントの合計を計算し、モジュロを適用します。$p$を追加してください。 カットごとにセグメントの合計を最初から再計算すると、各評価コストがかかります$O(n)$、につながる$O(n^2)$トータルオペレーション。 と$n = 10^5$、これは次のようになります$10^{10}$、制限時間をはるかに超えています。 

すべてのセグメントの合計がプレフィックスの合計を使用して表現できることに気づくことで、これを改善できます。 プレフィックス合計配列を事前に計算すると、セグメント合計は定数時間の減算になります。 これにより、各分割評価が次のように減少します。$O(1)$、フルスキャンを実行します$O(n)$。 

重要な構造的観察は、目的が接頭辞の合計とその補数にのみ依存するということです。 合計が分かると、右側のセグメントの合計が左側のセグメントの合計から即座に決定されるため、プレフィックスの累積以上のものを再計算する必要はありません。

 ## アルゴリズムのチュートリアル

 各分割を即座に評価できるように、プレフィックスの合計に関して問題を書き直します。 

### ステップ

 1. 配列の合計を計算します。 これにより、接尾辞の合計を合計との差として表すことができ、再計算を回避できます。 
2. 配列を左から右に反復処理しながら、実行中のプレフィックス合計を構築します。 
3. ポジションごとに$i$から$1$に$n-1$、カットポイントとして扱います。 
4. 各カットで、左の合計をプレフィックスの合計として計算します。$i$。 正しい合計は、合計からこのプレフィックスの合計を差し引いたものです。 
5.モジュロを適用する$p$左右の和を足し合わせます。 
6. すべてのカット位置にわたる最大値を追跡します。 

までしか反復しない理由$n-1$両方の部分が空であってはいけないため、最後の要素の後のカットは無効になるということです。 

### なぜ効果があるのか

 配列のすべての有効なパーティションが 1 つのプレフィックス境界に正確に対応するため、アルゴリズムは正しいです。 各境界について、左右の合計は一意に決定され、他の隠れた構造はスコアに影響を与えません。 考えられるすべての境界を 1 回だけ評価するため、これらの評価の最大値が全体的な最適値になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, p = map(int, input().split())
    a = list(map(int, input().split()))

    total = sum(a)
    prefix = 0
    best = 0

    for i in range(n - 1):
        prefix += a[i]
        left = prefix % p
        right = (total - prefix) % p
        best = max(best, left + right)

    print(best)

if __name__ == "__main__":
    solve()
```この解決策は、プレフィックス合計の単一パスの累積に依存しています。 合計は 1 回計算されるため、各右セグメントは一定時間で導出されます。 ループは次で停止します$n-1$分割の両側が空でないことを確認します。 モジュロ演算は累算中ではなく評価時にのみ適用されるため、誤った中間リダクションが回避されます。

 ## 特殊なケース

 エッジ ケースの 1 つは、すべての要素が同一である場合であり、複数の分割が同様に最適になる可能性があります。 入力の場合:```
5 7
3 3 3 3 3
```プレフィックス評価により対称的な結果が得られます。 各カットで、アルゴリズムはプレフィックス mod とサフィックス mod を一貫して計算し、分割がスキップされることはありません。 最大値はスキャン中に自然に現れます。 

もう 1 つのエッジ ケースは、モジュロが一方の側に強く影響する場合です。 のために：```
4 5
4 4 4 4
```プレフィックスの合計は急速に増加しますが、カットごとにモジュロ 5 が異なる方法で減少します。 このアルゴリズムは引き続きすべての境界を 1 回評価するため、生の合計が誤解を招く場合でも最適な分割を取得します。 

最後のエッジ ケースは、有効な最小入力サイズです。```
2 5
1 2
```分岐はちょうど 1 つあります。 ループは 1 回実行され、プレフィックス = 1、サフィックス = 2 を計算して、次の結果を返します。$1 + 2 = 3$。 ループ範囲では両方の部分が空ではないという制約が自然に強制されるため、特別なケースは必要ありません。
