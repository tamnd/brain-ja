 ## 解決策
 ## 問題の理解

 私たちにはジェダイの一行が与えられ、それぞれが配列内の固定位置を占め、各ジェダイはいくつかの可能なライトセーバーの色の 1 つを持っています。 これに加えて、各色のジェダイを何人選ばなければならないかを示すターゲットの仕様も与えられます。 

タスクは、そのセグメント内のジェダイだけを見た場合に、各色の出現数が必要な数と正確に一致するような、ラインナップの連続したセグメントが存在するかどうかを判断することです。 

したがって、入力は基本的に、1 ～ m の範囲の値を含む長さ n の配列に、ターゲット周波数ベクトルを記述する長さ m の別の配列を加えたものになります。 出力は単純な実現可能性チェックです。つまり、サブアレイが正確にその周波数プロファイルを持っているかどうかです。 

制約は小さく、n は最大 100 です。これにより、高度なデータ構造や漸近的に最適な前処理の必要性が直ちになくなります。 O(n3) のソリューションでも許容範囲内であり、O(n²) または O(n² log n) は快適に高速です。 

微妙だが重要な点は、要素の並べ替えや選択を求めているのではなく、連続したセグメントだけを求めているということです。 この制限により、プレフィックス頻度技術が有用になります。 

よくある落とし穴の 1 つは、複数のセグメントの全長が目標合計と同じであっても、構成が異なる可能性があることを忘れていることです。 たとえば、m = 2 でターゲットが {1, 2} の場合、[1, 1, 2] のようなセグメントの長さは正しいですが、配分が間違っています。一方、[1, 2, 2] も、カウントのバランスに関する部分的な直感と一致していても失敗します。 全長だけでなく、すべての色の数を正確に一致させる必要があります。 

もう 1 つのエッジ ケースは、一部の色のターゲットがゼロである場合です。 有効なセグメントには、これらの色の出現がゼロである必要があります。つまり、それらの色を完全に回避する必要があります。 

## アプローチ

 最も直接的なアイデアは、考えられるすべての部分配列を調べることです。 開始インデックスごとに終了インデックスを拡張し、現在のウィンドウ内の各色のカウントを維持します。 カウントがターゲット ベクトルと一致する場合は、すぐに YES を返すことができます。 

これが機能するのは、部分配列が O(n²) 個しかなく、頻度カウントを段階的に維持することで、拡張ステップごとに各チェックが O(1) になるためです。 したがって、合計作業量は n² 回の更新程度になります。 

ブルート フォースは、別の方法で説明するとさらに明確になります。左のエンドポイントごとに周波数配列をリセットし、カウントを更新しながら右のエンドポイントを拡張します。 各拡張には一定の時間がかかりますが、エンドポイントのペアごとに実行されます。 

重要な点は、制約によりすべての間隔を直接チェックできるため、ハッシュやプレフィックス合計の減算などの高度な最適化は必要ないということです。 色に対するプレフィックスの合計は、もう 1 つの有効な観点です。各セグメント クエリが O(m) になるようにプレフィックス頻度配列を事前計算できます。また、m ≤ n ≤ 100 であるため、それでも許容されます。 

したがって、最適な解決策は本質的に、増分簿記による総当り攻撃と同じです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (セグメントごとのカウントを再計算) | O(n3) | O(m) | 遅すぎる |
 | スライディング ウィンドウ / 増分周波数 | O(n² · m) または O(n²) | O(m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ターゲット周波数配列を保存する`k`、一致させる必要がある正確な構成を定義します。 これはすべての比較の基準ベクトルになります。 
2. 可能なすべての左側のエンドポイントを反復処理します。`l`セグメントの。 それぞれの選択`l`空のセグメントから開始する新しい周波数カウンターを定義します。 
3. 周波数配列を初期化する`cnt`サイズの`m`電流をゼロにする`l`。 これは現在のサブ配列内のカウントを表します`[l, r]`。 
4. 右側のエンドポイントを延長します`r`から`l`に`n - 1`、更新中`cnt[color[r]]`ステップごとに 1 つずつ。 この増分更新により、カウントを最初から再計算する必要がなくなります。 
5. 各拡張後に比較します。`cnt`ターゲット配列で`k`。 すべての色で同じである場合は、すぐに YES を返します。 このチェックは正しいです。`cnt`常に部分配列を正確に表します`[l, r]`。 
6. ペアがない場合`(l, r)`すべての反復後に一致が生成された場合は、NO を返します。 

### なぜ効果があるのか

 すべての固定左端点で`l`、アルゴリズムはすべての可能な正しいエンドポイントを列挙します。`r ≥ l`、各ペアについて、部分配列の正確な周波数ベクトルを計算します。`[l, r]`。 この列挙では、考えられるすべての連続セグメントが 1 回だけ出現するため、有効なソリューションはすべてテストされます。 周波数比較はすべての m 次元で正確に等しいため、間違ったセグメントが通過することはなく、正しいセグメントが見逃されることもありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    k = list(map(int, input().split()))

    for l in range(n):
        cnt = [0] * m
        for r in range(l, n):
            cnt[a[r] - 1] += 1
            if cnt == k:
                print("YES")
                return

    print("NO")

if __name__ == "__main__":
    solve()
```外側のループはセグメントの左側の境界を固定します。 このような境界ごとに、カウントが次から始まるサブ配列に正確に対応するように、新しい周波数配列が作成されます。`l`。 

内側のループは、右側の境界を一度に 1 ステップずつ拡張し、周波数配列内の 1 つのエントリのみを更新します。 これにより、セグメント全体のカウントが再計算されるのではなく、各展開が O(1) になります。 

比較`cnt == k`どちらもサイズ m の固定長リストであり、Python は要素ごとに比較するため、安全です。 m ≤ 100 であるため、この比較は依然として効率的です。

 ## 特殊なケース

 エッジ ケースの 1 つは、必要なセグメントが配列全体である場合です。 例えば：```
n = 4, a = [1,2,3,1], k = [1,1,1]
```アルゴリズムは最終的には`l = 0, r = 3`、ビルドします`cnt = (1,1,1)`、正しくYESを返します。 

もう 1 つのケースは、有効なセグメントが最後にある場合です。 例えば：```
a = [2,2,1], k = [1,2]
```サブアレイのみ`[2,1]`で発生する動作`(l=1, r=2)`。 外側のループにより、`l=1`に到達し、内側のループは次の拡張時に一致を検出します。`r=2`。 

最後の微妙なケースは、色の表示が許可されていない場合です。 もし`k[i] = 0`一部の色については、その色がインクリメントされるとすぐに周波数ベクトルの比較が失敗するため、アルゴリズムは当然その色を含むセグメントを拒否します。
