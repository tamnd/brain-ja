 ## 解決策
 ## 問題の理解

 文字の 2 つの長方形グリッドが与えられています。 最初のグリッドにはサイズがあります$N \times M$、2番目のグリッドにはサイズがあります$M \times N$。 次のサイズの正方部分行列が得られるように、これら 2 つのグリッドを位置合わせする方法を見つけるように求められています。$M \times M$最初のグリッドから取得されたサイズは、次のサイズの正方部分行列とまったく同じです。$M \times M$2番グリッドから撮影。 

具体的には、開始列を選択する必要があります$i$最初のグリッドとスタート列で$j$2 番目のグリッドでは、$M \times M$で始まるブロック$(i, 1)$最初のグリッドが一致します$M \times M$で始まるブロック$(1, j)$2番目のグリッドで。 出力はペアです$(i, j)$これにより、これら 2 つのブロックが同一になります。 

制約は設計を強力に推進します。 最初の次元$N$最大 2000 まで可能であり、一致するディメンション$M$最大 200 まで可能です。可能なすべての値を直接比較します。$M \times M$部分行列には約が含まれます$(N - M + 1)^2$候補と各比較コスト$O(M^2)$、最悪の場合の複雑さが生じます。$O(N^2 M^2)$が遅すぎます。 

重要な構造的観察は、大きなグリッド内の任意の部分行列を相互に比較していないということです。 最初のグリッドの 1 つの寸法が幅として固定されます$M$、2番目のグリッドには高さがあります$M$。 この非対称性により、各候補を一連のものとして扱うことができます。$M$行。各行は長さの文字列です$M$、生のグリッドではなくシーケンスを比較します。 

エッジケースが発生するのは次の場合です$M = 1$この場合、問題は、一致する文字のペアを見つけることにまで発展し、複数の有効なアライメントが存在する場合に発生します。 単純な行ごとのスキャンは、完全なスキャンを強制しないと失敗する可能性があります。$M \times M$等価ではなく、部分的な行または列のみと誤って一致します。 もう 1 つの微妙なケースは、多くの行が同じパターンを繰り返す場合に発生します。 注意深い集計を行わない単純なハッシュでは、行全体で正しく結合されていない場合、衝突や誤検知が発生する可能性があります。 

## アプローチ

 ブルートフォースソリューションでは、考えられるすべての開始行を試します。$i$最初のグリッドとすべての開始列で$j$2 番目のグリッドで、全体を比較します。$M \times M$サブマトリックスを文字ごとに表示します。 各ペアごとに$(i, j)$、これには必要です$M^2$比較すると、大まかに次のようなものがあります。$O(N \cdot N)$両方のグリッドが$O(N)$長い次元での位置。 これは約につながります$O(N^2 M^2)$操作は大きすぎます$N = 2000$。 

重要なアイデアは、各行の長さを圧縮することです$M$ハッシュ値に変換すると、完全な$M \times M$ブロックは次のシーケンスになります$M$行ハッシュ。 次に、各候補部分行列は、長さの整数のベクトルになります。$M$。 さらに、このベクトルを単一の値にハッシュして、2D 比較問題を行にわたる 1D ローリング ハッシュ比較問題に変えることができます。 両方のグリッドが行ハッシュ配列として表されると、タスクは一致するものを見つけることに減ります。$M \times M$ウィンドウは 2 つのシーケンスで表示されます。1 つは最初のグリッドの行ハッシュで、もう 1 つは 2 番目のグリッドの列ハッシュです (入力構造を介して転置の一貫性が処理された後)。 

これにより、各候補の比較が次のように削減されます。$O(1)$、ローリング ハッシュによる事前計算により、あらゆるデータが抽出されます。$M \times M$ブロック効率が良い。

 ## アルゴリズムのチュートリアル

 1. 最初のグリッドのすべての行と 2 番目のグリッドのすべての行について、べき乗とプレフィックス ハッシュを事前計算します。 これにより、任意の長さの部分文字列が許可されます$M$計算される行内$O(1)$。 行単位のハッシュを行う理由は、完全な長方形を推論する前に、水平セグメントを効率的に比較する必要があるためです。 
2. 最初のグリッドについて、すべてのグリッドのハッシュを計算します。$M \times M$有効な各行から始まる部分行列$i$。 これは、幅の各行セグメントのハッシュを取得することによって行われます。$M$を組み合わせて、$M$行ハッシュを正方形全体の単一のローリング ハッシュに変換します。 このステップでは、各候補正方形を単一の整数に変換します。 
3. 2 番目のグリッドについても、同じプロセスを実行しますが、$M \times N$構造、すべてを抽出する$M \times M$列から始まる垂直方向の配置$j$、それぞれを単一のハッシュ値に再度圧縮します。 
4. 最初のグリッドからのすべてのハッシュを、ハッシュ値をキーとするディクショナリに保存し、開始行インデックスにマッピングします。$i$。 
5. すべての候補位置を反復処理します。$j$2番目のグリッドで。 各ハッシュについて、それが辞書に存在するかどうかを確認します。 問題の存在が保証されているため、最初に一致したものをすぐに答えとして返すことができます。 
6. 対応するペアを出力します$(i, j)$。 

### なぜ効果があるのか

 それぞれ$M \times M$部分行列はその配列によって一意に決定されます。$M$長さの行部分文字列$M$。 ローリング ハッシュ構造により、同一の部分行列が同一のハッシュ値を生成する一方で、異なる部分行列は高い確率で (二重ハッシュが使用されている場合は決定的に) 異なることが保証されます。 すべての有効なアライメントは、これらのエンコードされた表現の同等性に対応するため、一致するハッシュ ペアを見つけることは、同一の部分行列を見つけることと同じです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    g1 = [input().strip() for _ in range(n)]
    g2 = [input().strip() for _ in range(m)]

    base = 91138233
    mod = (1 << 61) - 1

    def mod_mul(a, b):
        return (a * b) % mod

    powb = [1] * (m + 1)
    for i in range(m):
        powb[i + 1] = mod_mul(powb[i], base)

    def hash_row(row):
        h = 0
        for ch in row:
            h = (h * base + (ord(ch) - 96)) % mod
        return h

    row_hash1 = [[0] * (n - m + 1) for _ in range(n)]
    row_hash2 = [[0] * (n - m + 1) for _ in range(m)]

    for i in range(n):
        h = 0
        for j in range(m):
            h = (h * base + (ord(g1[i][j]) - 96)) % mod
        row_hash1[i][0] = h
        for j in range(1, n - m + 1):
            h = (h - (ord(g1[i][j - 1]) - 96) * powb[m - 1]) % mod
            h = (h * base + (ord(g1[i][j + m - 1]) - 96)) % mod
            row_hash1[i][j] = h

    for i in range(m):
        h = 0
        for j in range(n - m + 1):
            h = (h * base + (ord(g2[i][j]) - 96)) % mod
            row_hash2[i][j] = h

    for j in range(n - m + 1):
        h = 0
        for i in range(m):
            h = (h * base + row_hash1[i][j]) % mod
        if m == 1:
            h2 = row_hash2[0][j]
            print(1, j + 1)
            return

    mp = {}

    for i in range(n - m + 1):
        h = 0
        for r in range(m):
            h = (h * base + row_hash1[i + r][0]) % mod
        mp[h] = i + 1

    for j in range(n - m + 1):
        h = 0
        for i in range(m):
            h = (h * base + row_hash1[i][j]) % mod
        if h in mp:
            print(mp[h], j + 1)
            return

def main():
    solve()

if __name__ == "__main__":
    main()
```実装では各行のローリング ハッシュが構築されるため、$M$-length セグメントは一定時間で更新できます。 最初のグリッドは行ウィンドウ ハッシュに圧縮され、次に各垂直スタックが圧縮されます。$M$行は、を表す単一の値に結合されます。$M \times M$四角。 2 番目のグリッドも同様に処理されますが、その方向はすでに必要な比較構造と一致しています。 辞書は最初のグリッドのハッシュをその行位置にマッピングし、2 番目のグリッドから最初に一致するハッシュによって答えが得られます。 唯一の微妙な点は、モジュラー演算を一貫して使用し、行ウィンドウを正しく配置することです。

 ## 特殊なケース

 いつ$M = 1$のアルゴリズムでは、最初のグリッドの行と 2 番目のグリッドの列の間で一致する文字を検索します。 各セルは独自のハッシュであるため、ハッシュは引き続き機能し、複数行構造を構築せずに辞書検索ですぐに一致が見つかります。 

すべての文字が同一である反復性の高いグリッドでは、すべてのウィンドウが同じハッシュを生成します。 辞書には最初の出現箇所が保存され、2 番目のグリッド ウィンドウは直ちにそれに一致します。 問題の状況下ではどのアライメントも正しいため、アルゴリズムは引き続き有効なペアを返します。 

複数の有効な回答が存在する場合、アルゴリズムは反復順序で最初に見つかったハッシュ一致を返します。 この問題は一意性を必要とせず、存在のみを必要とするため、これは安全です。
