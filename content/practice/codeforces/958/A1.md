 ## 解決策

 ## 問題の理解

 次のサイズの 2 つの正方形グリッドが与えられます。$N \times N$、各セルは星または空のスペースです。 課題は、正方形の剛体対称性を使用して一方を変換できる場合に、これら 2 つのグリッドが同じパターンを表現できるかどうかを判断することです。 

許可される変換は、グリッドを物理的に 90、180、または 270 度回転すること、または水平または垂直に反転することに対応します。 これらの操作のシーケンスを適用した後、1 つのグリッドをセルごとに他のグリッドと同一にすることができれば、それらは同じ構成とみなされます。 

計算の観点から見ると、各マップは単なる文字のマトリックスです。 問題は、幾何学的変換の小さな有限セットの下で 2 つの行列が同等であるかどうかになります。 

制約$N \le 10$非常に小さいです。 三次的な操作や、すべての変換を明示的に試行する操作も、この規模では簡単です。 これは、ハッシュ手法、検索プルーニング、漸近的に最適なマッチング手法が必要ないことをすぐに示します。 すべての変換候補を直接シミュレーションするだけで十分です。 

微妙な点は、変換は離散的ですが、重複する可能性があることです。 たとえば、水平方向の反転に続いて垂直方向の反転を行うと、180 度の回転と同等になります。 クロージャを理解せずに変換のサブセットのみを実装しようとすると、有効な一致を見逃しやすくなります。 

いくつかの危険な状況については、覚えておく価値があります。 両方のグリッドがすでに同一である場合、変換は必要なく、答えは「はい」になります。 すべてのセルが同一であるなど、パターンの対称性が高い場合、すべての変換で等価性が維持されるため、実際には変換が正しく適用されない実装のバグが誤ってマスクされる可能性があります。 もう 1 つの失敗例は、反転を行わずに回転のみを比較しようとすることです。 たとえば、パターンとその鏡像は回転だけでは関係ありません。 

## アプローチ

 ブルートフォースのアイデアは簡単です。最初のグリッドで許可されているすべての変換を列挙し、それを適用し、その結果を 2 番目のグリッドと比較します。 グリッドはせいぜい$10 \times 10$、各比較コスト$O(N^2)$、無視できるほどです。 唯一の問題は、いくつの変換をチェックする必要があるかということです。 

単純な間違いは、反転と回転の任意のシーケンスを試行することです。これにより、無制限の検索スペースが生成される可能性があります。 ただし、正方形の対称構造は閉じており、有限です。 許可された回転と反転のシーケンスは、正確に 8 つの異なる変換の 1 つに変換されます。つまり、4 つの回転 (0、90、180、270 度) とそれらのミラーリングされた対応物です。 これが正方形の二面体グループです。 

重要な観察は、シーケンスを探索する代わりに、結果として得られるこれら 8 つのグリッドをそれぞれ直接構築し、それらを比較できることです。 これにより、組み合わせ検索が定数因数の列挙に変わります。

 ## アルゴリズムのチュートリアル

 最初のグリッドのすべての個別の変換バージョンを明示的に生成し、2 番目のグリッドと一致するものがあるかどうかを確認します。 

1. 2 つのグリッドを読み取り、文字列のリストとして保存します。 
2. セルをマッピングしてグリッドを時計回りに 90 度回転する関数を定義します$(i, j)$に$(j, N-1-i)$。 すべての回転は繰り返し適用することで得られるため、これは基本的な構成要素です。 
3. グリッドの 4 つの回転を作成します: 0 度 (オリジナル)、90 度、180 度、270 度。 各回転は、同じマッピング ルールを使用して前の回転から取得されます。 
4. 回転されたグリッドごとに、その水平方向の反射も作成します。 水平方向に反転すると、各行が反転します。 
5. 各回転とその反転バージョンにより、合計 8 つの候補グリッドが得られます。 
6. 各候補グリッドをターゲット グリッドと比較します。 一致するものがセルごとに同一である場合は、すぐに Yes を出力します。 
7. 8 つの可能性をすべてチェックした後、一致する変換がない場合は、No を出力します。 

任意のシーケンスを混合しない理由は、許可された操作の組み合わせは常に、これら 8 つの正規形式のいずれかに折りたたまれるためです。 それらを直接列挙することで冗長性が回避され、完全性が保証されます。 

### なぜ効果があるのか

 正方形の変形は、サイズ 8 の閉じたグループを形成します。許可されるすべての操作はこのグループの要素であり、合成によってこのグループの外に何かが生成されることはありません。 各グループ要素に対して 1 つの代表を生成することにより、最初のグリッドのすべての可能な変換バージョンが 1 回だけ考慮されることが保証されます。 これにより、許可された操作シーケンスの下で等価性が存在する場合、それが列挙に表示されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def rotate(grid):
    n = len(grid)
    return ["".join(grid[n - 1 - r][c] for r in range(n)) for c in range(n)]

def flip_h(grid):
    return grid[::-1]

def solve():
    n = int(input())
    a = [input().strip() for _ in range(n)]
    b = [input().strip() for _ in range(n)]

    variants = []

    cur = a
    for _ in range(4):
        variants.append(cur)
        variants.append(flip_h(cur))
        cur = rotate(cur)

    for v in variants:
        if v == b:
            print("Yes")
            return

    print("No")

if __name__ == "__main__":
    solve()
```この解決策は 2 つの基本的な変換に依存します。 回転関数は、元のグリッドの列を下から上に読み取ることによって新しいグリッドを構築します。これは、時計回りに 90 度回転することに相当します。 フリップ関数は行の順序を反転し、垂直方向の反射を生成します。 解釈によっては、この反転と組み合わせた回転によりすべてのミラー ケースが生成されるため、これで十分です。 

新しいグリッドがそれぞれ前のグリッドから派生するように回転を繰り返し生成し、元のグリッドからの繰り返しの再計算を回避します。 これにより、実装がシンプルになり、インデックス作成ミスの可能性が減ります。 

比較は行リストの直接的な文字列の等価性によって行われます。これは、各行がグリッド構造を完全にエンコードしているため安全です。

 ## 特殊なケース

 最小限の$1 \times 1$グリッドは、変換に関係なく常にそれ自体と一致します。 回転操作と反転操作は同じ単一セル グリッドを返すため、アルゴリズムはこれを自然に処理します。そのため、文字が一致する場合、唯一のバリアントがターゲットと等しくなります。 

完全に「X」で埋められたグリッドなど、対称性の高いグリッドは、すべての変換で同一のバリアントを生成します。 このような場合、生成されたすべての候補はターゲットと等しいため、最初の比較はすぐに成功します。 このアルゴリズムは変換の一意性を想定しておらず、存在のみを想定しているため、これは正確さに影響しません。 

もう 1 つの微妙なケースは、正しい変換が反転とその後の回転のような組み合わせである場合です。 その結合された変換は、回転反転サイクル中に生成される 8 つの正規のバリアントの 1 つとして現れるため、列挙は依然としてそれをキャプチャします。
