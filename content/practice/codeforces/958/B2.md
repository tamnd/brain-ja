 ## 解決策
 ## 問題の理解

 私たちに与えられた木は、$N$これは、ノードのすべてのペアが 1 つの単純なパスによって接続されていることを意味します。 私たちは選択することが許されています$K$ノードを「アクティブステーション」として扱います。 ノードを選択すると、ノードが制御されるようになり、選択された 2 つのノード間の単純なパス上にあるノードも制御されます。 

したがって、最終的に制御されるセットは、選択されたノード自体だけではなく、それらを接続する最小限のサブツリー内のすべてのものになります。 ツリー言語では、これはまさに、選択されたノードによって誘導されるシュタイナー ツリーです。 

あらゆる人にとって$K$から$1$に$N$、この誘導されたサブツリーの最大可能サイズを決定する必要があります。 

重要な問題は、選択したノードの構造が個々の位置よりも重要であることです。 遠く離れて配置された 2 つのノードは多くの中間ノードを制御できますが、クラスター化されたノードはほとんど寄与しません。 

制約は厳しいです:$N \le 10^5$。 すべてのサブセットを試すアプローチは不可能です。$K$ノードはすでに与えています$\binom{N}{K}$可能性。 二次関数でも、$O(N^2)$建設は通過しません。 これにより、ほぼ線形またはほぼ線形の時間でグローバル構造情報を構築するソリューションが必要になります。 

木が線である場合、微妙なエッジケースが現れます。 その場合、エンドポイントを選択すると、カバレッジが最大化され、それぞれの答えが得られます。$K$は連続セグメント長になります。 グローバルな直径構造を考慮せずに局所的な拡張を仮定する誤った貪欲は、ここで失敗します。 

もう 1 つのエッジケースは、星型のツリーです。 いずれかのリーフを選択すると、すぐに中心を通る範囲が拡大されるため、最適なセットはパスとは大きく異なる動作をします。 これは、「最高次数ノードを選択する」などの単一のローカル ヒューリスティックが一貫して機能しないことを示しています。 

## アプローチ

 直接的な総当たりアプローチでは、すべての選択肢が試行されます。$K$ノードを選択し、各選択肢のシュタイナー ツリー サイズを計算し、最大値を取得します。 固定セットのシュタイナー ツリーの計算は、ノードをマークし、仮想ツリー構築または DFS プルーニングを実行することで実行できます。$O(N)$サブセットごとに。 ただし、サブセットの数はすでに指数関数的であるため、たとえ$N = 30$、ましてや$10^5$。 

問題の構造は、別の視点を示唆しています。 制御セットは、両側でノードを選択することによってどのエッジが「アクティブ化」されるかによってのみ決まります。 各エッジは、選択したノードがそのエッジの片側に完全に含まれていない場合に限り、答えに寄与します。 

これにより、問題はノードの選択から、選択したセットによって「カット」されるエッジの数を最大化することに変わります。 課題は、エッジがグローバルに相互作用することです。ノードを配置すると、多くのエッジに同時に影響します。 

重要な洞察は、ツリーの階層的な分解を通じてノードの寄与を再解釈することです。 重心分解を構築すると、各ノードは対数の重心成分に関与します。 ノードが重心から考慮されるたびに、その重心までの距離に等しい値が与えられます。 これらの距離は、ノードがツリーのさまざまな構造パーティションからどれだけ「離れているか」を捉えます。 

重要な事実は、最適に制御されたサイズが$K$ノードは選択すると表現できます$K-1$これらの寄与のうち、1 つのノードのベースに対する合計ゲインを最大化します。 直感的には、単一のルート ノードから開始し、追加で選択された各ノードが重心階層内で最適な「スプレッド値」に寄与します。 これらの寄与を並べ替えることで、すべての答えを直接計算することができます。 

これにより、すべての重心距離の寄与を収集し、それらを並べ替えて、プレフィックスの合計を取得するという問題が軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ノードセットに対するブルートフォース | 指数 | O(N) | 遅すぎる |
 | 重心分解 + 貢献度のソート |$O(N \log N)$| O(N \log N) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### 1. ツリーの重心分解を構築する

 サブツリーの重心を再帰的に見つけます。 各ノードは、重心祖先のチェーンに関連付けられています。 この分解により、ツリーの各エッジが対数レベルで表現されるようになります。 

重心分解を使用する理由は、ツリーをバランスの取れた部分に分割し、構造化されたマルチスケールの方法で距離を測定できるようにするためです。 

### 2. すべてのノードの重心距離の寄与を計算する

 すべての重心について$c$からの距離を計算します。$c$そのコンポーネント内のすべてのノードに。 各ノードについて$u$、値を記録します$\text{dist}(u, c)$。 

したがって、各ノードは、重心祖先ごとに 1 つずつ、複数の値を蓄積します。 

これらの値は、分解のさまざまな部分で選択された他のノードと組み合わせたときに、ノードがどの程度の「新しいリーチ」を提供するかを表します。 

### 3. すべての投稿をグローバル リストに収集します

 記録されたすべての重心距離を 1 つの配列に収集します。 この配列にはサイズがあります$O(N \log N)$、各ノードは最大で対数的に多くの重心層に現れるためです。 

各値は、ツリー内で十分に分離されたノードを選択する場合の潜在的な増分ゲインを表します。 

### 4. 貢献を降順に並べ替えます

 大きな構造的寄与が最初に来るようにリストを並べ替えます。 長い距離に対応するノードを選択すると、シュタイナー ツリーの拡張速度が最大化されます。 

このステップでは、構造最適化問題を貪欲な累積問題に変換します。 

### 5. プレフィックスの合計を使用して回答を作成する

 選択すると解釈します$K$ノードはルートの寄与に最良の寄与を加えたものとして計算されます$K-1$追加の利益。 したがって：$$\text{answer}[K] = 1 + \sum_{i=1}^{K-1} \text{top gains}[i]$$ソートされた配列に対してプレフィックスの合計を計算し、すべての値を出力します。 

### なぜ効果があるのか

 各重心レベルは、ツリーを独立した領域に分割するのにノードがどのように寄与するかを捕捉します。 ノードを選択すると、接続に役立つセントロイド パーティションの数に比例したメリットが得られます。 分解により、ツリー内のすべての構造ゲインが分離レベルごとに 1 回正確に表現されることが保証されます。 ソートにより、常に最も影響力のある分離が最初に行われるようになり、誘導されたシュタイナー ツリーのエッジの数を最大化する組み合わせ構造と一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    n = int(input())
    g = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    size = [0] * n
    dead = [False] * n
    contrib = []

    def dfs_size(u, p):
        size[u] = 1
        for v in g[u]:
            if v != p and not dead[v]:
                dfs_size(v, u)
                size[u] += size[v]

    def dfs_centroid(u, p, tot):
        for v in g[u]:
            if v != p and not dead[v]:
                if size[v] > tot // 2:
                    return dfs_centroid(v, u, tot)
        return u

    def dfs_collect(u, p, c, d):
        contrib.append(d)
        for v in g[u]:
            if v != p and not dead[v]:
                dfs_collect(v, u, c, d + 1)

    def build(croot):
        dfs_size(croot, -1)
        c = dfs_centroid(croot, -1, size[croot])
        dead[c] = True

        dfs_collect(c, -1, c, 0)

        for v in g[c]:
            if not dead[v]:
                build(v)

    build(0)

    contrib.sort(reverse=True)

    pref = [0]
    for x in contrib:
        pref.append(pref[-1] + x)

    ans = []
    for k in range(1, n + 1):
        if k - 1 <= len(contrib):
            ans.append(1 + pref[k - 1])
        else:
            ans.append(1 + pref[-1])

    print(*ans)

if __name__ == "__main__":
    solve()
```この実装では、重心分解を構築し、各重心レベルから距離の寄与を収集して、それらをグローバルに集計します。 セントロイド DFS は、各ノードがのみ処理されることを保証します。$O(\log N)$これにより、総作業量が制限内に抑えられます。 

並べ替えステップは唯一の超線形操作であり、複雑さの中で最も重要です。 プレフィックスの合計は、次のすべての値に直接答えます。$K$。 

各重心ステップでサブツリーのサイズをリセットし、すでに削除されたコンポーネントを走査しないように注意する必要があります。そうしないと、分解が中断され、ノードが二重にカウントされます。

 ## 特殊なケース

 単一ノード ツリーは自明です。重心分解により、エッジのない 1 つのノードがすぐに返され、寄与リストは空になります。 アルゴリズムの出力$1$、唯一可能な制御セットと一致します。 

道の形をした木は、長距離構造の重要性を示しています。 重心分解では、端点から中心に向かって増加する距離の寄与を収集します。 ソートにより、より多くのノードを選択すると、正しい順序でチェーンに沿ってカバレッジが拡張され、シュタイナー ツリーのサイズが増加します。 

星型の木はその対極を示しています。 すべての葉は中心からの距離が 1 であるため、寄与は均一です。 ソートされた配列は、新しいリーフが選択されるたびに制御されたサイズで線形に増加します。これは、すべての新しいリーフが中心を強制的に含め、誘導されるサブツリーを毎回 1 つのエッジずつ増加させるという事実と一致します。
