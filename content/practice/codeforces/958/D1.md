 ## 問題の理解

 各船は、「(a + b) / c」という形式の短い算術式からターゲット座標を独立して計算します。ここで、a、b、c は小さな正の整数です。 この式を評価すると、結果は有理数になります。 まったく同じ値を取得した船は、最終的に同じ目的地に到着します。 

タスクは、幾何学的なものを計算したり、動きをシミュレートしたりすることではありません。 これは、各式を評価し、同一の結果で船舶をグループ化し、各船舶について最終値を共有する船舶の数を報告することに帰着します。 

m が 200,000 までという制約は、船舶のすべてのペアを比較するような解決策は不可能であることを意味します。 二次アプローチでは、最悪の場合でも約 4 × 10^10 の比較が実行されますが、これは 5 秒の制限をはるかに超えています。 これにより、各式が 1 回処理され、正規化された表現とハッシュ化またはカウントを使用して一定時間またはほぼ一定時間で等価性がテストされるという戦略が強制されます。 

値が浮動小数点数として格納されている場合、単純な実装のリスクがすぐに現れます。 a、b、c が小さい場合でも、(1+2)/3 や (2+1)/3 などの式は有理算術では正確ですが、浮動小数点の丸めによりわずかな差が生じ、誤ったグループ化につながる可能性があります。 もう 1 つの微妙な問題は、約分を行わずに分数を比較することです。 たとえば、(2+2)/4 は (1+1)/2 に等しい 1 ですが、生の分子と分母を保存すると、正規化されない限り、それらは異なるものとして扱われます。 

## アプローチ

 ブルート フォース戦略では、各式を小数に分けて評価し、それを他のすべての式と比較します。 各評価は単純ですが、m 個の結果をペアごとに比較すると、O(m²) 個の比較が行われます。 m = 200,000 では、これは実現不可能です。 

重要な観察は、ペアごとの比較がまったく必要ないということです。 それぞれの個別の値が何回出現するかを知る必要があるだけです。 これは、値が正規形式に変換されると、古典的な度数計算の問題になります。 主な困難は、2 つの等しい有理数がまったく同じキーにマップされることを保証する (a + b) / c の表現を定義することです。 

浮動小数点の直接評価は安全ではありません。 代わりに、各式を有理数として扱い、最大公約数を使用してそれを削減します。 分子は a + b、分母は c で、両方を gcd(分子, 分母) で割ることによって正規化します。 これにより、同一の有理値が同一の縮小ペアを生成することが保証されます。 

すべての式が正規ペア (p、q) にマッピングされたら、カウントをハッシュ マップに保存します。 最後に、元の式ごとに頻度を出力します。

 ## アルゴリズムのチュートリアル

1. すべての式を 1 つずつ読みます。 各文字列について、固定位置を解析するか、既知のシンボルを中心に分割することによって、a、b、および c を抽出します。 形式は厳格であるため、解析は決定的かつ一定時間で行われます。 
2. 分子の値 n = a + b を計算します。 これは除算前の完全な整数部分を表します。 
3. 結果を有理数 n / c として表します。 この時点では、同じ値に評価されるさまざまな式が依然として異なる表現を持つ可能性があります。 
4. g = gcd(n, c) を計算して分数を減らします。 分子と分母の両方を g で割って、正規化されたペア (n/g、c/g) を生成します。 このステップにより、等価な有理数が常に同じ表現に折りたたまれることが保証されます。 
5. 正規化された各ペアを周波数マップに保存します。 キーはタプル (分子、分母) で、値はこれまでに出現した回数です。 
6. すべての式を処理した後、保存されている正規化ペアを元の順序で再度繰り返し、それぞれの頻度を出力します。 

すべての結果を最初に保存する理由は、各出力が増分状態ではなくグローバル周波数に依存するためです。 

### なぜ効果があるのか

 各式は有理数 (a + b) / c を定義します。 2 つの式が等しいのは、その換算された分数が同一である場合に限ります。 gcd 正規化により、表現の一意性が保証されます。つまり、すべての有理数が 1 つの既約整数ペアに正確にマップされます。 Python 辞書はタプルの構造的等価性を使用するため、同一の分数が同じキーに衝突し、カウントが正確になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from math import gcd

def parse(expr):
    # format: (a+b)/c
    # strip parentheses and split manually
    # expr example: (12+33)/15
    expr = expr.strip()
    expr = expr[1:]  # remove '('
    plus_idx = expr.find('+')
    slash_idx = expr.find('/')
    a = int(expr[:plus_idx])
    b = int(expr[plus_idx + 1:slash_idx - 1]) if expr[slash_idx - 1] == ')' else int(expr[plus_idx + 1:slash_idx])
    # safer direct parsing ignoring ')'
    if expr[slash_idx - 1] == ')':
        b_str = expr[plus_idx + 1:slash_idx - 1]
    else:
        b_str = expr[plus_idx + 1:slash_idx]
    b = int(b_str)
    c = int(expr[slash_idx + 1:])
    return a + b, c

def main():
    m = int(input())
    nums = []
    denoms = []
    freq = {}

    for _ in range(m):
        expr = input().strip()
        n, d = parse(expr)
        g = gcd(n, d)
        n //= g
        d //= g
        nums.append(n)
        denoms.append(d)
        freq[(n, d)] = freq.get((n, d), 0) + 1

    res = []
    for i in range(m):
        res.append(str(freq[(nums[i], denoms[i])]))

    print(" ".join(res))

if __name__ == "__main__":
    main()
```解析ロジックは式の固定構造に依存します。 すべての式は厳密に「(a+b)/c」に従うため、プラス文字とスラッシュ文字を見つけて、それに応じて部分文字列を抽出します。 浮動小数点演算を明示的に避け、整数のみを扱います。 

gcd 正規化は、正確性を保証する重要なステップです。 これがないと、(2+2)/4 や (1+1)/2 などの値は、同じ有理数を表している場合でも、異なるキーを生成します。 

2 番目のパスで再計算せずに元の順序で答えを出力できるように、分子と分母をリストに別々に保存します。

## テストケース```python
import sys, io
from math import gcd

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    def parse(expr):
        expr = expr.strip()
        expr = expr[1:]
        plus = expr.find('+')
        slash = expr.find('/')
        a = int(expr[:plus])
        b = int(expr[plus+1:slash-1]) if expr[slash-1] == ')' else int(expr[plus+1:slash])
        if expr[slash-1] == ')':
            b = int(expr[plus+1:slash-1])
        else:
            b = int(expr[plus+1:slash])
        c = int(expr[slash+1:])
        return a+b, c

    m = int(input())
    vals = []
    freq = {}

    for _ in range(m):
        n, d = parse(input())
        g = gcd(n, d)
        n //= g
        d //= g
        vals.append((n, d))
        freq[(n, d)] = freq.get((n, d), 0) + 1

    return " ".join(str(freq[v]) for v in vals)

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、異なる式が同じ有理数に帰着するが、構文的には同一ではない場合です。 たとえば、(10+10)/20 と (5+5)/10 は両方とも 1 と評価されます。gcd リダクションがなければ、それらは異なるキーを生成し、別々にカウントされます。 リダクション後は両方とも (1,1) になり、周波数マップはそれらを正しくグループ化します。 

もう 1 つのケースは、分子と分母がすでに互いに素である場合です。 (5+1)/7 のような式の場合、gcd(6,7) = 1 となるため、表現は変わりません。 正規化は冪等であり、すでに削減された分数を変更しないため、アルゴリズムは依然として正しく動作します。 

最後の微妙なケースは、解析が固定フォーマットに依存する場合です。 入力では、スペースがなく、+ と / が 1 つだけ含まれる厳密なパターンが保証されているため、部分文字列の解析は安全です。 この形式から逸脱すると完全な式パーサーが必要になりますが、問題の設計ではその複雑さは完全に回避されています。
