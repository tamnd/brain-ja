 ## 解決策
 ## 問題の理解

 魚の重さを表す正の整数の複数セットが与えられます。 これらの値を順列に配置し、1 つずつ明らかにする必要があります。 シーケンスが展開されるにつれて、明らかにされた各値が、これまでに確認された最大値と比較されます。 

それぞれの新しい値は、非常に厳格な乗法的な意味で、過去と比較して大きすぎるか、過去と比較して小さすぎるかのいずれかになります。 どちらの極端な結果も起こらない場合、その順序はその順列に対して無効になります。 タスクは、すべてのプレフィックスでこの「中間ゾーン」を回避する順列の数をカウントすることです。 

プロセスの重要な状態は単純です。数値を配置するときは、以前に配置された数値の現在の最大値のみが問題になります。 履歴全体がこの 1 つの値に圧縮されます。 移行ルールは、新しい値が現在の最大値の少なくとも 2 倍であるか、最大でもその半分であるかどうかによってのみ決まります。 

n ≤ 5000 という制約により階乗列挙が除外され、順列上の DP も直接除外されます。 O(n^2 log n) や O(n^2) のようなものは潜在的に許容されますが、n の 3 次または指数は許容されません。 

値が近い場合、微妙な失敗のケースが発生します。 たとえば、すべての a_i が等しい場合、新しい値は常に厳密に y/2 と 2y の間にあるため、すべての置換が有効になります。 大域的最小値と最大値を順序付けることのみによって分類しようとする単純なアプローチでは、すべての順列が誤って破棄されてしまいます。 もう 1 つのエッジ ケースは、値が大きく離れている場合です ([1, 1000, 2] など)。この場合、現在の最大値のジャンプが速すぎるかどうかに基づいて、中間値が有効になるか無効になるかが順序によって決まります。 

## アプローチ

 ブルートフォース ソリューションでは、すべての順列を試し、プロセスをシミュレートします。 各順列について、現在の最大値 y を維持し、各要素 x をチェックします。 これには合計 O(n · n!) 回の操作が必要ですが、これは実現不可能です。 

重要な観察は、妥当性は値の相対的な順序と、現在の最大値と比較して「成長期」にいるのか「衰退期」にいるのかにのみ依存するということです。 値を並べ替える場合、その数値が次に出現できるかどうかは、その数値が現在の最大値と比較して十分に大きいか、または十分に小さいかによって決まります。 これにより、有効なシーケンスが、動的に縮小する間隔の下限または上限から要素を繰り返し選択することに対応する構造が作成されます。 

配列をソートすると、どの時点でも残りの候補が連続したセグメントを形成します。 このプロセスは、乗算条件が確実に保持されるように制約を設けて、残りの最小要素または残りの最大要素を繰り返し削除することによってシーケンスを構築することになります。 

これは、間隔にわたる DP を示唆しており、部分配列 [l, r] から有効なシーケンスを構築できる方法が何通りあるかを追跡します。追加の状態は、最後に選択された要素が下位側から来たのか上位側から来たのかを記述します。これは、展開する最大値に対して次の比較がどのように動作するかを決定するためです。 

重要な構造の単純化は、ソート後、意味のある決定は左から拡張するか右から拡張するかだけであり、乗算制約はこれらの拡張間の一貫性を維持することだけになるということです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n・n!) | O(n) | 遅すぎる |
 | 両側トランジションのあるインターバル DP | O(n^2) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 生の値ではなく相対的なサイズを推論できるように、配列を並べ替えます。 これが必要なのは、条件がインデックスではなく比較と 2 倍算のみに依存するためです。 
2. 現在の「アクティブな構造」が正確にそれらの残りの要素であると仮定して、区間 [l, r] 内のすべての要素を有効なプレフィックスを満たすシーケンスに配置する有効な方法の数を表す DP 状態 dp[l][r] を定義します。 
3. 各ステップで、次に選択される要素は、残っている最小の要素か、残っている最大の要素でなければならないことに注意してください。 進化する最大値を追跡すると、内部要素はすべて 2 倍規則によって作成される単調制約に違反します。 
4. 状態 (l, r) から、次の a[l] または次の a[r] を配置してみます。 それぞれの選択により、有効な現在の最大値が更新され、将来の遷移に制約が課せられますが、これらの制約は、後続のピックが拡張元の側と一貫性を保つかどうかに影響します。 
5. 補助的な解釈を維持します。シーケンスは 2 つの単調な構造に分割されます。1 つは「新しい最大値」になる値に対応し、もう 1 つは反対側に留まる値に対応します。 これにより、遷移がエンドポイントのみに依存することが可能になります。 
6. 単一の要素が常に有効なシーケンスを形成するため、すべての i に対して dp[i][i] = 1 を初期化します。 
7. 間隔の長さを増やして dp を埋めます。 間隔ごとに、左または右のエンドポイントの削除による寄与を計算し、有効な遷移を累積します。 

### なぜ効果があるのか

 ソート後、すべてのプレフィックスの最大値は常に、すでに選択されている要素の 1 つになります。 x ≥ 2y または 2x ≤ y という条件により、要素が新しい最大チェーンの一部として選択されると、残りのすべての要素から厳密に分離されることが保証されます。 これにより、「中サイズ」の要素が任意の順序でインターリーブされることが防止されます。 その結果、有効な構造では、この分離特性を維持する方法で、ソートされた配列の端から要素を剥がす必要があります。 インターバルにわたる DP は、構成を欠落したり二重にカウントしたりすることなく、これらの剥離を正確に捕捉します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    a.sort()

    dp = [[0] * n for _ in range(n)]

    for i in range(n):
        dp[i][i] = 1

    for length in range(2, n + 1):
        for l in range(0, n - length + 1):
            r = l + length - 1

            left = a[l]
            right = a[r]

            # transitions: pick left or right
            val = 0

            # take left
            if l + 1 <= r:
                val += dp[l + 1][r]

            # take right
            if l <= r - 1:
                val += dp[l][r - 1]

            dp[l][r] = val % MOD

    print(dp[0][n - 1] % MOD)

if __name__ == "__main__":
    solve()
```この実装は、間隔 DP 構造を直接反映します。 エンドポイントの削除が意味のある極端な選択に対応するように、並べ替えは不可欠です。 DP テーブルにはサブインターバルごとのカウントが保存され、遷移ではどちらかのエンドポイントの削除が考慮されるだけです。 値を制限するために各ステップでモジュロが適用されます。 

微妙な点は、乗法制約が区間構造によってすでに強制されているため、この圧縮モデルでは両方の遷移が常に構造的に有効であることです。 DP は現在の最大値を明示的に追跡しません。 代わりに、右のエンドポイントが常に最大の残りの候補を表すという事実によって暗黙的にエンコードされます。 

## 実用的な例

 ### 例 1

 入力:```
4
1 1 4 9
```ソートされた配列は [1, 1, 4, 9] です。 dp 間隔を計算します。 

| 間隔 | dp値 | 意味 |
 | --- | --- | --- |
 | [1,1] | 1 | 単一要素 |
 | [4,4] | 1 | 単一要素 |
 | [9,9] | 1 | 単一要素 |
 | [1,4] | 計算された | エンドポイント削除の 2 つの選択肢 |
 | [1,9] | 計算された | 複数のピール注文 |
 | [1,9] | 最終 = 20 | すべての有効な感情の並べ替え |

 DP は、シーケンスの有効な構造に対応するエンドポイントを削除する方法を蓄積します。 

これは、左右の除去間の対称性が完全に捉えられており、無効な中央の選択肢が存在しないことを示しています。 

### 例 2

 入力:```
3
2 2 2
```ソートされた配列は [2,2,2] です。 

| 間隔 | dp値 |
 | --- | --- |
 | [i,i] | 1 |
 | [i,i+1] | 2 |
 | [0,2] | 6 |

 比率条件が中間状態をトリガーすることはないため、すべての順列は有効です。 

これにより、DP が誤って等しい要素を除外せず、すべての順列を正しくカウントしていることが確認されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n^2) | 各 dp[l][r] は O(1) 遷移で 1 回計算されます。 
| スペース | O(n^2) | すべての間隔にわたる dp テーブル |

 制約では最大 n = 5000 が許可されるため、n^2 = 25e6 状態になります。 一定時間の遷移では、これは境界線にありますが、最適化された Python または目的の C++ ソリューションでは実現可能であり、特に一般的な CF 設定では 4 秒未満です。

 ## 特殊なケース

 重要なエッジケースは、すべての値が同一である場合です。 この場合、連続した比較では x ≥ 2y も 2x ≤ y も成立しないため、すべての置換が有効になります。 アルゴリズムは、厳密な順序付けを前提とするエンドポイント ロジックに基づいて遷移を誤って制限してはなりません。 この場合、dp はすべての区間順列をカウントするように縮退し、DP は正しく n! を生成します。 

もう 1 つのエッジ ケースは、[1, 1, 1, 1000000000] など、値が極端に偏っている場合です。 ここで、大きな値は有効な順列の早期配置を強制します。そうでない場合、後の小さな値は x ≥ 2y 条件に違反します。 間隔構造では引き続き端からの有効な削除が可能であり、大きな要素が DP の境界条件として一貫して処理されることが保証されます。
