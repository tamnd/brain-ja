 ## 解決策
 ## 問題の理解

 私たちは料理のコレクションを与えられ、それぞれの料理をオーブンから取り出す「理想的な」時間が関連付けられています。 この問題の時間は離散的であり、一度に 1 分ずつ増加します。 1分ごとに取り出せるのはせいぜい1皿までで、最終的にはすべての皿を1回ずつ取り出さなければなりません。 ご希望の時間帯のお料理の場合$t_i$時間に取り出されます$T$、絶対差額に等しいペナルティを支払います$|T - t_i|$。 目標は、正確な整数である削除時間をスケジュールすることです。$1, 2, \dots, n$、すべての料理に固有の時間が割り当てられ、合計ペナルティが最小限に抑えられるようにします。 

言い換えれば、各料理を長さの順列で個別の時間帯に一致させているということです。$n$、コストは優先ポジションからの絶対偏差の合計です。 

制約は小さく、すべてのテスト ケースにわたるディッシュの総数は最大 200 です。これにより、テスト ケースごとに 2 次または 3 次の挙動を持つ解は許容されるが、順列を超える指数関数的なものは許容できないことがすぐにわかります。 単純な階乗列挙は不可能です。$20!$はすでに大きすぎますが、サブセットまたはソートされた位置に対する動的プログラミングは実行可能です。 

複数の料理が同じ優先時間を共有する場合、微妙な問題が発生します。 「入力順に各料理に最も近い利用可能な時間を常に割り当てる」などの貪欲な割り当ては、早期の決定がより適切なグローバル ペアリングを妨げるため、失敗する可能性があります。 この構造は本質的にグローバルです。1 つの料理の時間を選択すると、他の料理の利用可能な時間枠がシフトされます。 

素朴な貪欲さの小さな失敗例は、時間の経過とともに構築される可能性があります$[1, 1, 100, 100]$。 最初に両方の 1 を貪欲に 1 と 2 に割り当てると、すぐに 100 を不必要に遠くに押しやってしまいます。 グローバルに最適な配置では、割り当てが対称的に分散されます。 

## アプローチ

 最も難しいのは、2 つの順序付けられた構造 (料理と値) を一致させることです。$t_i$、および時間帯$1 \dots n$。 両方を並べ替えると、問題はライン メトリックの割り当て問題に似てきます。 

強引なアイデアとしては、時間枠に料理を割り当てるすべての順列を試し、コストを計算するというものです。 すべての有効なスケジュールは時間の順列であるため、これは正しいです。 ただし、置換の数は、$n!$、たとえそれが困難になる$n = 20$。 それぞれの評価にかかる費用$O(n)$、合計は次のようになります$O(n \cdot n!)$、すぐに爆発します。 

重要な観察は、ライン上の絶対差額コストには強い順序付け特性があるということです。 2つの料理に希望の時間があった場合$a \le b$しかし、時間に割り当てられています$x \le y$、割り当てを交換してもコストが増加することはありません。 これは、両方のシーケンスが一貫してソートされている場合に最適な解が存在することを意味する、古典的な交換引数です。 

そこで、希望する時刻の配列を並べ替えます。 ここで、タスクはペアリングになります。$i$- 番目に小さい皿$i$-番目のタイムスロットは、絶対偏差の合計を最小化する方法で調整されます。 ただし、割り当てを強制されるものではありません。$1..n$直接順番に。 私たちは位置を選択しており、最適な DP は時間の経過を追跡します。 

クリーンな定式化は、並べ替えられた料理のインデックスと現在時刻に対する動的プログラミングです。 時間は厳密に増加し、制限されるため、$n$、時間の増加順に料理を配置する DP を定義します。 ステップで$i$、時間を選択します$t$以前よりも大きくなり、支払います$|t - a_i|$。 これは、単調遷移を伴う直線上の標準 DP となり、次のように解くことができます。$O(n^2)$。 

次のように計算します。$$dp[i][j] = \text{minimum cost to assign first } i \text{ dishes ending at time } j$$これまでのすべての時代からの移行とともに$k < j$:$$dp[i][j] = \min_{k < j}(dp[i-1][k]) + |j - a_i|$$余分な要素を避けるためにプレフィックス最小値を最適化できます。

 ## アルゴリズムのチュートリアル

 1. 希望する調理時間の配列を並べ替えます。 これにより、順序付けされた位置の一致の問題が軽減されますが、これは絶対距離に関する交換引数により有効です。 
2. ソート順に料理を 1 つずつ処理する DP テーブルを定義します。 各ステップで、現在の皿を取り出す時間を決定します。 
3. 1 から 2 までのタイムスロットのインデックスを維持します。$n$。 各タイムスロットは 1 回しか使用できないため、時間の増加は厳密に保証されます。 
4. 料理ごとに$i$、可能な時点ごとに配置するコストを計算します。$j$、つまり$|j - a_i|$、それを以前の最良の配置と組み合わせます。 
5. 前の DP 行に対して接頭辞最小値を使用して、次の遷移を計算します。$O(1)$以前すべてをスキャンするのではなく、状態ごとにスキャンします。 これにより、複雑さが 3 次から 2 次に軽減されます。 
6. 答えは、すべての有効な終了時間にわたる最後の DP 行の最小値です。 

### なぜ効果があるのか

 重要な不変条件は、最初の処理後、$i$皿の場合、すべての DP 状態は、すべての有効な割り当ての中で可能な最小コストを表します。$i$料理は厳密に増加する時間枠に割り当てられます。 順序制約により、再割り当てを行わなくても、実現可能性を損なうことなく局所的にコストを向上させることができます。 絶対差コストは直線上で凸であるため、最適な構造はソート後の単調マッチングを尊重するため、増加する時間インデックスに DP を制限しても最適解は破棄されません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    q = int(input())
    for _ in range(q):
        n = int(input())
        a = list(map(int, input().split()))
        a.sort()

        INF = 10**18

        # dp[j]: min cost after placing current i items, ending at time j
        dp = [INF] * (n + 1)

        # initialize: place first dish at any time
        for j in range(1, n + 1):
            dp[j] = abs(j - a[0])

        for i in range(1, n):
            new_dp = [INF] * (n + 1)

            prefix_min = INF
            for j in range(1, n + 1):
                prefix_min = min(prefix_min, dp[j-1])
                new_dp[j] = prefix_min + abs(j - a[i])

            dp = new_dp

        print(min(dp[1:]))

def main():

if __name__ == "__main__":
    main()
```実装は優先時間をソートすることから始まり、これにより DP 引数に必要な単調構造が強制されます。 DP 配列は、料理のプレフィックスを割り当てた後の、特定のタイムスロットで終了する最適なコストを表します。 

移行では、以前の状態に対してローリング プレフィックス最小値が使用されます。 表現`prefix_min = min(prefix_min, dp[j-1])`直前の割り当てを時間よりも前に終了するための最良の方法を取得します。`j`、タイムスロットの一意性を強制します。 これにより、これまでのすべての回での明示的な内部ループが回避されます。 

最後のディッシュはどこでも終わる可能性があるため、最終的な答えは、可能なすべての最終位置の最小値になります。 

実装の微妙な詳細は、タイム スロットの 1 から始まるインデックス付けです。 これは問題のステートメントと一致し、絶対差を計算する際の off-by-one エラーを回避します。

 ## 特殊なケース

 同じ希望時間の場合、次のように$[x, x, x]$、DP は自然に割り当てを連続したタイムスロットに分散します。 正確な最適時間を占めることができるのは 1 つのディッシュだけであり、残りのディッシュは外側にシフトする必要があるため、追加のディッシュごとに少なくとも 1 単位の変位が生じます。 prefix-min 遷移により、アルゴリズムは順序に違反することなく、徐々に後の時間位置を考慮するようになります。 

厳密に増加または減少するシーケンスの場合、並べ替えによりそれらが同一になり、DP は一致するインデックスに減ります。$i$時間まで$i$、値がすでに位置と一致している場合、コストはゼロになります。
