 ## 解決策
 ## 問題の理解

 0 と 1 が同じ量で出現し、長さが偶数であるバイナリ文字列が与えられます。 ターゲットの構成は任意ではありません。文字列が完全に交互になるようにしたいのです。つまり、隣接する文字のペアはすべて異なる必要があります。 文字列はバランスが取れているため、最終的な形式は 2 つだけです。1 つは 0 で始まり、もう 1 つは 1 で始まります。 

許可される唯一の操作は、連続する部分文字列を反転することです。 反転すると、文字列の残りの部分を変更せずに、そのセグメント内の要素の順序を完全に変更できます。 タスクは、最初の文字列を有効な代替文字列に変換するために必要なそのような反転の最小数を見つけることです。 

テスト ケース全体にわたる全長の制約は最大 10^5 です。 これにより、すべての部分文字列を試したり、変換を段階的にシミュレートしたりするソリューションは即座に除外されます。 テスト ケースごとに線形または線形に近いものより悪いものは困難になるため、ソリューションでは操作をシミュレートするのではなく、文字列の構造特性を抽出する必要があります。 

微妙な点は、反転は非常に強力な操作であるということです。 素朴な直観では、反転はローカルであるため多くの操作が必要であると思われるかもしれませんが、実際には、正しく選択されていれば、1 回の反転で複数の誤って配置された文字を修正できます。 難しいのは、操作を実行することではなく、基本的に必要な操作の数を特定することです。 

素朴で貪欲な考えを誤解させるエッジ ケースの 1 つは、文字列がすでに代替されているものの、想定されるターゲットと比較して「間違った」最初の文字で始まっている場合です。 たとえば、ターゲットが 0101… であるが、最適値は 1010… であると仮定すると、単純な位置ごとの修正戦略では作業が過剰にカウントされる可能性があります。 

不一致が集中している場合、別の失敗ケースが発生します。 たとえば、111000 のような文字列では、単純な戦略では各不一致を個別に修正しようとする可能性がありますが、適切に選択された 1 つの反転により複数の位置を同時に修正できます。 これが、総当たりのローカル修正が失敗する主な理由です。 

## アプローチ

 ブルート フォース アプローチでは、各ステップですべての可能な部分文字列の反転を試み、代替構成が見つかるまで、到達可能なすべての文字列に対して BFS を実行します。 各状態には O(n^2) 個の遷移があり、状態の数が指数関数的に多いため、n が約 20 の場合でも、これはすぐに実行不可能になります。BFS はすべての可能性を探索するため、正確さは簡単ですが、状態空間はすぐに爆発します。 

改善するために、私たちは操作の構築から、交互のターゲットに対する無秩序の測定へと視点を変えます。 1 つのターゲット パターン、たとえば 0101 を修正します。入力文字列をこのターゲットと比較し、不一致の位置をマークできます。 正しい位置が局所的に最終目標をすでに満たしているため、問題となるのはこれらの不一致だけです。 

重要な洞察は、反転によって 1 回の動きで最大 2 回のミスマッチを修正できるということです。 ここでの実行とは、文字列がターゲット パターンと一致しない連続したセグメントを意味します。 このようなセグメント内では、反転すると構造が反転し、複数の誤った配置が同時に崩壊する可能性があります。 最適なソリューションの構造は、これらの不一致セグメントをペアにすることに帰着します。 

両方の可能な交互ターゲットに対して不一致の位置を計算すると、答えはすべての不一致を除去するために必要な最小限の操作数になります。 各操作で 2 つの境界遷移をマージまたは修正できるため、これは、より適切なターゲットの不一致セグメントの数の半分であることがわかります。 

したがって、逆転をシミュレートする代わりに、各ターゲットとの比較において正しい位置と誤った位置の間の遷移をカウントすることに問題を縮小します。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 文字列に対するブルート フォース BFS | O(2^n · n^2) | O(2^n · n) | 遅すぎる |
 | 不一致セグメントのカウント | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 2 つの候補ターゲット (0 から始まるものと 1 から始まるもの) を交互に評価します。 

ターゲットごとに文字列をスキャンし、各インデックスをそのターゲット パターンに対して正しいか間違っているかに分類します。 

1. インデックスのパリティをチェックして、予想される交互パターンを暗黙的に構築します。 インデックス i が偶数の場合、一方のターゲットでは 0、もう一方のターゲットでは 1 が期待されます。 
2. 文字列をトラバースし、s[i] が予想と異なる位置にマークを付けます。 
3. 位置が一致しない連続セグメントの数を数えます。 一致した領域から不一致な領域に入るたびに、セグメント数が増加します。 
4. そのターゲットの場合、必要な操作の数は、不一致セグメントの数の半分に等しく、切り上げられます。 
5. 他のターゲットに対しても同じ手順を繰り返し、2 つの結果の最小値を取得します。 

2 で割る背後にある直感は、反転の動作から来ています。つまり、1 回の反転で、セグメント間のセグメントを反転することで、2 つの分離された不一致ブロックを接続して解決し、修正作業を効果的にマージできます。 

### なぜ効果があるのか

 重要な不変条件は、唯一の意味のある構造は、固定された交互パターンに対する正しい位置と不正確な位置の間の境界であるということです。 不一致セグメント内では、すべての位置が同様に「文脈上間違っている」ため、パリティ アライメントを反転することでセグメントを削除またはマージする反転を選択できます。 各操作で除去できる不一致境界は最大 2 つであるため、答えはそのような境界がいくつ存在するかによって決まり、これは連続する不一致ブロックをカウントすることで正確に把握されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()

        def calc(start_bit):
            mismatches = []
            for i, ch in enumerate(s):
                expected = '1' if (i % 2) ^ start_bit else '0'
                mismatches.append(ch != expected)

            segments = 0
            i = 0
            while i < n:
                if not mismatches[i]:
                    i += 1
                    continue
                segments += 1
                while i < n and mismatches[i]:
                    i += 1

            return (segments + 1) // 2

        ans0 = calc(0)
        ans1 = calc(1)
        print(min(ans0, ans1))

if __name__ == "__main__":
    solve()
```この解決策では、まず、交互パターンを特定のビットで開始する場合に必要な操作の数を評価するヘルパー関数を定義します。 不一致配列は、このターゲットに違反するすべての位置を分離します。 次に、これらの不一致を連続ブロックに圧縮します。これは、ブロックの内部構造は反転には重要ではなく、個別のブロックがいくつ存在するかだけが重要であるためです。 

最終的な式`(segments + 1) // 2`は、最良の場合、各反転で 2 つの不一致ブロックを処理できる一方、残った 1 つのブロックには 1 つの操作が必要であるという事実を捉えています。 

メイン ループは、考えられる交互のターゲットの両方を評価し、より良い方を選択します。

### 例 2

 入力:```
n = 8
s = 11101000
```ターゲット 01010101:

 不一致の配列は次のようになります。 

位置 0、1、2、4、6、7 は不一致であり、セグメント [0,2]、[4]、[6,7] を形成します。 

セグメント = 3、答え = (3+1)//2 = 2。 

ターゲット 10101010 は同様かそれより悪いセグメンテーションを提供し、同様に 2 を生成します。 

これは、アルゴリズムが正確な文字値には敏感ではなく、不一致がどのようにクラスター化されるかに敏感であることを示しています。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        s = input().strip()

        def calc(start_bit):
            mismatches = []
            for i, ch in enumerate(s):
                expected = '1' if (i % 2) ^ start_bit else '0'
                mismatches.append(ch != expected)

                if not mismatches[i]:
                    i += 1
                    continue
                segments += 1
                while i < n and mismatches[i]:
                    i += 1

            return (segments + 1) // 2

        out.append(str(min(calc(0), calc(1))))

    return "\n".join(out)

 ## 特殊なケース

 次のような完全に交互の文字列`10101010`正しいターゲットに対して不一致セグメントが生成されないため、セグメント数はゼロとなり、答えは即座にゼロになります。 不一致境界が存在しないため、アルゴリズムは不必要な操作を正しく回避します。 

のような文字列`0011`いずれかの交互パターンと比較すると、不一致セグメントが 1 つだけ作成されます。 式`(1 + 1) // 2`は 1 を返し、単一の連続する間違った領域を修正するには 1 回の反転で十分であるという直観と一致します。 

次のようなより断片化された文字列`110010`複数の不一致セグメントが生成されます。 アルゴリズムはそれらを正確にグループ化し、セグメントの数を操作に変換して、孤立した間違った領域が最適にペアになるようにします。
