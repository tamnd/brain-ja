 ## 解決策
 ## 問題の理解

 単一パックのサイズを選択しています`a`キャットフードの缶を販売するためです。 どの顧客も最初は何らかの番号を購入したいと考えています`x`一定の範囲内で`[l, r]`。 顧客は 2 つの段階で行動します。まず、同じサイズの完全割引パックをできるだけ多く購入します。`a`できる限り、残った缶は個別に購入するようにしています。 ただし、残りが半分以上ある場合は、`a`、彼らは切り替えて、残った個別の缶の代わりにもう1つのフルパックを購入します。 

これにより、次のような最終購入数量が作成されます。`x + (a - (x mod a))`余りが十分大きいとき、または単に`x`小さいときは。 目標は選択することです`a`可能な限りすべてのことを`x`で`[l, r]`、最終購入金額は厳密に次の金額よりも大きくなります`x`。 

入力は複数の独立した間隔を与えます`[l, r]`、それぞれについて、そのようなパックサイズが存在するかどうかを判断する必要があります。 

制約は次のとおりです`10^9`したがって、すべての可能な値をシミュレートまたはテストしようとするソリューションは、`a`またはすべての値`x`直接は無理です。 すべてを繰り返しても`a`まで`r`までの時間が必要となるため、遅すぎるでしょう。`10^9`テストケースごとの操作。 

微妙なエッジケースが小さな間隔から発生します。 たとえば、次のようなとき`l = r = 1`、任意の選択`a`失敗するので、`x = 1`常に強制的なアップグレードは発生しません。 一方、間隔が大きい場合、特に連続する少なくとも 3 つの整数にまたがる場合、少なくとも 1 つの値を強制するパック サイズを見つけることが可能になります。`x`常にアップグレード動作をトリガーします。 

主な難点は、条件がモジュラー演算としきい値の比較に依存していることです。`a / 2`、それぞれについて素朴な推論をします`x`別に誤解を招く。 

## アプローチ

 強引なアイデアは、可能なすべてのパック サイズを試してみることです。`a`から`1`のようなものに`2r`そして、それぞれについて`a`、すべてをチェックしてください`x`で`[l, r]`。 ペアごとに計算します`x mod a`最終的な購入額が超過するかどうかを確認します`x`。 このアプローチは顧客の行動を直接シミュレートするため、原理的には正しいですが、その複雑さは次のようなものに比例します。`(r - l + 1) * max_a`、最悪の場合は周囲にまで達します。`10^18`操作が行われ、完全に実行不可能になります。 

重要な簡素化は、実際に何を保証する必要があるかを観察することから生まれます。 私たちは特定の商品に対する追加購入を最大化しようとしているわけではありません。`x`、しかし、すべての人にとってそれを確実にするために`x`、貪欲ルールによりアップグレードがトリガーされます。 それは残りがあるかどうかにのみ依存します`x mod a`下の「安全地帯」に着陸することはありません`a/2`。 

存在する場合`x`そのような`x mod a < a/2`の場合、その顧客はアップグレードせず、条件は失敗します。 したがって、残りが残らないようにしたいのです。`[0, a/2)`。 それは間隔がある場合にのみ可能です`[l, r]`十分に小さいので、適切な選択によってすべての残基を上半分に押し込むことができます。`a`。 

重要な構造的観察は、区間の長さが少なくとも 4 になると、どのような係数を選択しても残基が必然的に両方の半分をカバーし、すべての値を強制的にアップグレードすることが不可能になるということです。 間隔が小さい場合 (長さは最大 3)、常に適切な間隔を構築できます。`a`。 

これにより、問題は間隔のサイズのみを確認するようになります。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. 間隔の長さを計算します。`len = r - l + 1`。 これにより、同時に満たさなければならない顧客の個別の要求がいくつあるかがわかります。 
2. もし`len >= 4`、すべての顧客にアップグレードを強制できるパック サイズはない、とすぐに結論付けます。 これは、このような広い範囲にわたる係数構造では、一部の区間の下半分に剰余が必然的に生成されるという事実から導かれます。`x`。 
3. それ以外の場合、`len <= 3`、出力`YES`常にすべての値をプッシュするのに十分な大きさのパック サイズを構築できるため、`[l, r]`「アップグレード領域」に移行するか、残りすべてを強制購入状態に陥らせます。 

### なぜ効果があるのか

 システムの動作は完全に剰余剰余によって支配されます。`a`。 成功するには、すべての整数が`[l, r]`選択した係数の下で小さな剰余が生成されることを避ける必要があります。 間隔が 4 つ以上の連続する整数にまたがる場合、剰余は任意の剰余を法とします。`a`必ず連続する値の完全なブロックをカバーし、常に係数の下半分と交差します。 これにより、少なくとも 1 人の顧客がアップグレードせず、条件を破ることが保証されます。 間隔が最大 3 つの値の場合、いつでも選択できます。`a`剰余の構造がこの失敗のケースを完全に回避するのに十分な大きさです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        l, r = map(int, input().split())
        if r - l + 1 >= 4:
            print("NO")
        else:
            print("YES")

if __name__ == "__main__":
    solve()
```この実装は、間隔の長さの計算のみに依存します。 完全なモジュール式システムは純粋な長さの状態に折りたたまれるため、顧客の行動をシミュレーションする必要はありません。 各テスト ケースは一定時間で処理され、スケーラビリティが確保されます。

 ## 特殊なケース

 次のような単一点間隔の場合`l = r = 1`、アルゴリズムは長さを計算します`1`、これはしきい値を下回っているため、返されます。`YES`。 これは、要求値が 1 つだけあれば、アップグレード動作を強制するか、条件を空虚に満たすことができるパック サイズを選択することが常に可能であるという事実と一致します。 

境界例の場合`l = 1, r = 4`、計算された長さは`4`、トリガー`NO`。 選択しようとするあらゆる試み`a`これは、4 つの連続する値により、任意の係数の下で小さい剰余と大きい剰余の両方が強制され、少なくとも 1 人の顧客がアップグレードしないことが保証されるため、失敗します。
