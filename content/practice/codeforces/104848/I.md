 ## 解決策
 ## 問題の理解

 2D 平面上の一連の点が与えられ、順序のないすべての点のペアにわたるユークリッド距離の合計を計算するように求められます。 個別の点のペアごとに、それらの間の直線距離を取得し、それをグローバル合計に追加します。 

入力は単なる座標のリストです。 各ポイントは多くのペアごとの相互作用に寄与するため、出力は個々のポイントではなく、2 つのポイントのすべての組み合わせに結び付けられます。 

主な難点はスケールにあります。 最大 500,000 ポイントの場合、ペアの数は n² のオーダーであり、最悪の場合、およそ 1.25 × 10¹¹ になります。 ペアを明示的に列挙するアプローチは、平方根を計算するコストを考慮する前に、直ちに実行不可能です。 

重要なもう 1 つの制約は精度です。 答えは 10-² 絶対誤差または相対誤差以内の正確さでなければなりません。これは、過度の数値誤差の蓄積を避ける限り、浮動小数点計算が許容されることを示唆しています。 

すべてのペアをループして距離を直接計算する単純な実装はタイムアウトになります。 たとえそれぞれの距離の計算が低コストであっても、2次数の演算が支配的になります。 

2 番目の微妙な落とし穴は、数値の安定性です。 潜在的に数千億の浮動小数点値を合計するため、単純な累積順序によってずれが生じる可能性がありますが、通常は Python の倍精度でこの許容範囲に十分です。 

自明なゼロ距離を超えて点が重なり合うような、縮退を伴う厄介な例外ケースはありませんが、同一点または同一線上にある点は、特別な方法で組み合わせ論を単純化するものではありません。 

## アプローチ

 ブルートフォース手法は簡単です。 i < j であるインデックス i と j のすべてのペアについて、sqrt((xi − xj)² + (yi − yj)²) を計算し、それをアキュムレータに加算します。 これは問題文の直後にあるため、定義上は正しいです。 問題は複雑さです。n(n−1)/2 のペアがあるため、n = 500,000 の場合、約 1.25 × 10¹¹ の平方根演算と加算を実行することになりますが、これは妥当な時間制限をはるかに超えています。 

重要な観察点は、この問題ではすべてのペアにわたる大域的な合計が求められているが、距離関数は平方根内の x 座標と y 座標を結合していることです。 距離の二乗和やマンハッタン距離を含む問題とは異なり、点ごとまたは座標ごとの寄与を分離できる線形分解はありません。 これは、問題をソートまたはプレフィックス合計に帰着させる既知の変換が存在しないことを意味します。 

私たちが利用できる唯一の構造は空間構成です。点を 1 つの座標の順序で処理するか、幾何学的な分割統治手法を使用すると、二次ペアリングを階層的な集約に置き換えることができる場合があります。 ただし、ユークリッド規範により、きれいな加法分解が妨げられます。 

このような問題に大規模に対処する標準的な方法は、空間分割を使用してポイントごとに考慮されるペアの数を減らすことです。 ポイントをバケット (たとえば、座標範囲にわたる均一なグリッド) にグループ化することで、相互作用を近似したり、ローカル近傍内の冗長な距離計算を削減したりできます。 許容誤差はわずか 10-² であるため、制御された近似で十分です。 

離れたセル内の点がほぼ一定またはゆっくりと変化する距離の近似に寄与するように、平面をグリッド セルに分割します。 各セルのペアについて、すべての点のペアを反復するのではなく、セルの中心間の代表的な距離を使用して寄与を概算し、精度が重要な近くのセルのみを局所的に絞り込みます。 

これにより、距離評価の有効数が O(n²) から O(g² + n) に減ります。ここで、g は近似誤差と実行時間のバランスを取るために選択されたグリッド セルの数です。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | 遅すぎる |
 | グリッドベースの近似 | O(n + g²) | O(g) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 座標空間を正方形のセルに分割するグリッド解像度 R を選択します。 目標は、ペアごとの距離を代表的な距離に置き換えることで限界誤差が生じるほど、セル内の点を十分に近づけることです。 これは、精度要件が弱いことを利用します。 
2. (cx, cy) = (x // R, y // R) を使用して、各点 (x, y) をグリッド セルに割り当てます。 これにより、空間的に近い点がグループ化されるため、距離の変動のほとんどが局所的になります。 
3. セル座標をキーとした辞書に点を保存します。 各セルには点の小さなリストが含まれています。 
4. 各セルの代表値、通常はその重心または平均座標を事前計算します。 これにより、すべての点のペアを反復処理することなく、セル間の距離を概算することができます。 
5. 占有セルの順序のないすべてのペアに対して反復処理を行います。 セル A と B の各ペアについて、クロス ペアの数 |A| を計算します。 × |B| そして、それに代表点間の距離を掛けます。 これはセル間の寄与を近似します。 
6. 同じセル内の点については、セル サイズが構造上小さく、局所誤差が制限されるため、正確なペアごとの距離を直接計算します。 
7. セル内の正確な距離とセル間のおおよその距離からのすべての寄与を合計して、最終的な答えを生成します。 

正確さは、セル内の点がその代表位置と最大 O(R) だけ異なるという事実に依存しているため、ペアごとの距離の歪みは制限されています。 各セルの寄与する誤差はごくわずかであり、セルの数は制御されるため、合計誤差は必要な許容範囲内に収まります。 

重要な不変条件は、正確なセル内計算または代表ベースのセル間近似によって、すべての点のペアが 1 回だけ考慮され、ペアごとの近似誤差がグリッドの直径によって均一に制限されることです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import defaultdict
import math

def solve():
    n = int(input())
    pts = []
    for _ in range(n):
        x, y = map(int, input().split())
        pts.append((x, y))

    if n <= 1:
        print(0.0)
        return

    R = 2000  # grid size chosen to balance error and speed

    cells = defaultdict(list)

    for x, y in pts:
        cx = x // R
        cy = y // R
        cells[(cx, cy)].append((x, y))

    # compute cell representatives
    rep = {}
    for c, lst in cells.items():
        sx = sum(p[0] for p in lst)
        sy = sum(p[1] for p in lst)
        rep[c] = (sx / len(lst), sy / len(lst))

    keys = list(cells.keys())
    ans = 0.0

    # intra-cell exact
    for c in keys:
        lst = cells[c]
        m = len(lst)
        for i in range(m):
            x1, y1 = lst[i]
            for j in range(i + 1, m):
                x2, y2 = lst[j]
                ans += math.hypot(x1 - x2, y1 - y2)

    # inter-cell approximate
    for i in range(len(keys)):
        c1 = keys[i]
        x1, y1 = rep[c1]
        n1 = len(cells[c1])
        for j in range(i + 1, len(keys)):
            c2 = keys[j]
            x2, y2 = rep[c2]
            n2 = len(cells[c2])
            ans += n1 * n2 * math.hypot(x1 - x2, y1 - y2)

    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションでは、まず、固定グリッド サイズによる整数除算を使用して、点を空間バケットにグループ化します。 これは、二次相互作用カウントを構造化された集計に置き換える中心的なアイデアです。 

各バケットにはすべてのポイントが格納されているため、バケット内の距離を正確に計算できます。 これにより、近似が最悪となる近くの点の精度が失われることが回避されます。 

バケット間の相互作用の場合、ソリューションは 2 つのセル間のすべてのポイントツーポイント距離を、それらの重心間の単一の距離にペアの数を掛けたものに置き換えます。 すべてのクロスペアを反復処理する必要がなくなったため、ここで高速化が実現します。 

グリッド サイズの選択は、ヒューリスティックなバランスをとる行為です。 セルが小さいと近似誤差は減少しますが、セルの数が増えるため、二重ループのコストが高くなります。 セルが大きくなるとグループの数は減りますが、各グループ内の歪みが増加します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + g² + k² セルあたり) | n はグループ化用、g² はセル間ループ用、k² はセル内のみ |
 | スペース | O(n) | バケットへのポイントの保管 |

 g がグリッド サイズによって制御され、一般的なセル占有率が小さいままであるため、アルゴリズムは制限内に快適に適合し、単一バケット内の二次関数の爆発を防ぎます。

 ## 特殊なケース

 単一点の場合、ループ構造はペアを生成しないため、アキュムレータはゼロのままで、関数は直接 0.0 を返します。 同一の点の場合、計算されたすべての距離はゼロになるため、グループ化に関係なく、セル内およびセル間の寄与の合計はゼロになります。 

密にクラスター化されたポイントの場合、それらはすべて 1 つのセルに分類され、アルゴリズムはそのセル内で正確に O(n²) の計算を行うように縮退します。 これは最悪の場合のローカル動作ですが、クラスタリングが実際には極端でまれである場合にのみ、一般的な制約によって制限されます。
