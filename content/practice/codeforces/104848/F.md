 ## 解決策
 ## 問題の理解

 1 から n までの番号が付けられた頂点上に接続された単純な無向グラフを構築するように求められます。 グラフはサボテンであってはなりません。つまり、少なくとも 2 つの頂点で重なる単純なサイクルが少なくとも 2 つ含まれている必要があります。 自己ループと複数のエッジは禁止されています。 このようなすべてのグラフの中で、エッジの数を最小限に抑え、有効な構成を出力する必要があります。 

重要なオブジェクトは、サイクルが厳密に制御されたグラフです。 サボテンはサイクルを許可しますが、その方法は限られており、異なるサイクルは最大 1 つの頂点を共有できます。 ここでは、2 つのサイクルに少なくとも 2 つの頂点を共有させることで、そのルールに違反することが明示的に要求されています。 

入力サイズ n は最大 1000 であるため、線形時間での構築は十分です。 決定論的な構造を構築する以外に検索や最適化を行う必要はありません。 重要なのは、禁止された構成を強制するために必要なエッジの最小数を特定することです。 

素朴な試みとしては、ツリーから開始して、違反が現れるまで任意にエッジを追加するというものがあります。 問題は、1 つのエッジを追加すると 1 つのサイクルしか作成されず、少なくとも 2 つの頂点の交差サイズで 2 つのサイクルを保証するには、追加のエッジがいくつ必要かが明らかではないことです。 不用意に構築すると、存在するものの 1 つの頂点のみに接触する 2 つのサイクルが生成される可能性がありますが、それでもサボテンのプロパティを満たしているため、無効になります。 

エッジケースは非常に小さい n で現れます。 n = 2 または n = 3 の場合、2 つの異なるサイクルを作成する方法はまったくありません。 n = 4 の場合、解は存在しますが、重複せずにサイクルを分離するのに十分な頂点がないため、慎重に構造化する必要があります。 

## アプローチ

 n 個の頂点を持つ接続されたグラフには、常に少なくとも n − 1 個のエッジがあります。 これは、サイクルを含まないツリーの構造です。 サイクルを導入するには、余分なエッジを追加する必要があります。 エッジを追加するたびに、スパニング ツリーに対して少なくとも 1 つの新しいサイクルが作成されるため、最終グラフに 2 つのサイクルが必要な場合は、ツリーを越える追加のエッジが少なくとも 2 つ必要になります。 これにより、n + 1 エッジの下限がすでに与えられています。 

残りの問題は、n + 1 個のエッジが非サボテン構造を強制するのに十分であるかどうかです。 難しいのは、サイクルを作成することではなく、サイクルのうちの 2 つが少なくとも 2 つの頂点を共有していることを確認することです。 サイクルが独立して形成される場合、それらは 1 つの頂点でのみ交差するか、まったく交差しない可能性がありますが、それでもサボテンの条件は満たされます。 

オーバーラップを強制する便利な方法は、2 つの異なる終了エッジ間でサイクルの長いプレフィックスを意図的に共有することです。 パス 1 から n を選択し、同じ最初のセグメントを介してサイクルを閉じる 2 つのコードを追加すると、複数の連続する頂点を共有する 2 つのサイクルが作成されます。 これにより、制御された方法で違反が保証されます。 

このアイデアは、単純なパス バックボーンで十分であり、必要な構造を強制するには慎重に選択された 2 つの追加エッジで十分であることを示しています。 n = 4 の場合、パスが小さすぎて縮退せずに 2 つの異なる弦の端点をホストするには少し異なる構築が必要ですが、エッジを共有する 2 つの三角形を直接構築できます。

 ## アルゴリズムのチュートリアル

 ### 一般的なケース n ≥ 5

1. エッジ (i, i+1) を使用して単純なパス 1、2、3、...、n を構築します。 これにより、n − 1 エッジとの接続が保証され、サイクルを接続するためのきれいな構造が得られます。 パスを使用する理由は、パスによって独自の単純な構造が保証され、追加されたエッジによってサイクル形成が完全に制御されるためです。 
2. 1 と 4 の間にエッジを追加します。これにより、1 → 2 → 3 → 4 → 1 のサイクルが作成されます。 
3. 1 と 5 の間にエッジを追加します。これにより、別のサイクル 1 → 2 → 3 → 5 → 1 が作成されます。 
4. 両方のサイクルが頂点 {1, 2, 3} を共有していることに注目してください。これは少なくとも 2 つの頂点であるため、サボテンの条件に違反しています。 

### 特殊なケース n = 4

 1. エッジ (1,2)、(2,3)、(3,1) を使用して、頂点 1、2、3 に三角形を構築します。 
2. エッジ (1,2)、(2,4)、(4,1) を使用して、頂点 1、2、4 に別の三角形を構築します。 
3. これら 2 つのサイクルは頂点 1 と 2 を共有するため、オーバーラップ条件が満たされます。 

### なぜ効果があるのか

 サイクルがゼロのツリーから開始します。 余分なエッジごとに 1 つの独立したサイクルが導入されます。 エッジが 2 つ追加されているため、少なくとも 2 サイクルを保証できます。 この構造により、両方のサイクルが基本構造の同じ内部セグメントを強制的に再利用することになり、その頂点の交差部分が大きくなります。 共有セグメントには少なくとも 2 つの頂点があるため、結果のグラフはサボテン制約を満たすことができません。 

この最小性は、1 つの追加エッジが 1 サイクルのみを提供するという事実から来ており、2 サイクルを必要とする定義に違反することはありません。 したがって、ツリーの向こう側に少なくとも 2 つの追加のエッジが必要です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())

    if n < 4:
        print(-1)
        return

    edges = []

    if n == 4:
        edges.append((1, 2))
        edges.append((2, 3))
        edges.append((3, 1))
        edges.append((1, 2))
        edges.append((2, 4))
        edges.append((4, 1))
    else:
        for i in range(1, n):
            edges.append((i, i + 1))
        edges.append((1, 4))
        edges.append((1, 5))

    print(len(edges))
    for u, v in edges:
        print(u, v)

if __name__ == "__main__":
    solve()
```コードはまず、n が 4 未満の場合の不可能性を処理します。n が 4 に等しい場合、エッジを共有する 2 つの三角形を明示的に構築します。 n が大きい場合は、パスを構築し、頂点 1 から頂点 4 および 5 までの 2 つのコードを追加します。パスにより接続が確保され、コードによって 2 つの重複サイクルが導入されます。 

微妙な点は、パスの最初のセグメントによってすでに固定されている頂点 1、2、および 3 を両方のサイクルが強制的に通過することによって、サイクルの重複が保証されていることです。 

## 実用的な例

 ### 例 1: n = 5

 パスを構築してから 2 つのコードを追加します。 

| ステップ | アクション | これまでのエッジ | コメント |
 | --- | --- | --- | --- |
 | 1 | パスのエッジを追加する | (1,2)、(2,3)、(3,4)、(4,5) | 木の幹 | 写真 木の幹
 | 2 | (1,4) を加算 | + (1,4) | 最初のサイクルが作成されました |
 | 3 | (1,5) を追加 | + (1,5) | 2 番目のサイクルが作成されました |

 最初のサイクルは 1-2-3-4-1 で、2 番目のサイクルは 1-2-3-5-1 です。 これらは頂点 1、2、3 を共有しており、サボテンではない構造が確認されています。 

### 例 2: n = 4

 | ステップ | アクション | これまでのエッジ | コメント |
 | --- | --- | --- | --- |
 | 1 | トライアングル 1-2-3 を構築する | (1,2)、(2,3)、(3,1) | 最初のサイクル |
 | 2 | トライアングル 1-2-4 を構築 | + (1,2)、(2,4)、(4,1) | 2 番目のサイクル |

 両方のサイクルは頂点 1 と 2 を共有しており、要件を満たしています。

 ## 特殊なケース

 n = 2 および n = 3 の場合、2 つの異なるサイクルを含む単一の構造を形成することさえ不可能であるため、アルゴリズムは正しく -1 を返します。 エッジを追加しようとすると、単純性の制約に違反するか、最大でも 1 つのサイクルが生成されます。 

n = 4 の場合、一般的なパスベースの方法では存在しない方法で頂点 4 と 5 を使用しようとするため、特別な構築が必要です。 アルゴリズムはエッジを共有する 2 つの三角形に切り替わり、2 つのオーバーラップするサイクルが明示的に保証されます。 

n = 5 の場合、この構築は意図したパターンを明確に示しています。共有バックボーン 1-2-3 により、両方のサイクルが複数の頂点で交差することが保証され、サイクルが頂点 1 でのみ接触する可能性がある微妙な失敗のケースが回避されます。
