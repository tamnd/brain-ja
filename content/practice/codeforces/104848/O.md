 ## 解決策
 ## 問題の理解

 私たちは2本の独立した木によって形成される製品空間を扱っています。 状態は頂点のペアであり、1 つは最初のツリーから選択され、もう 1 つは 2 番目のツリーから選択されます。 州から$(u, v)$、別の状態にジャンプすることができます$(u', v')$間の距離が離れている場合に限り、一度の動きで$u$そして$u'$最初のツリー内の距離は、間の距離と正確に等しくなります。$v$そして$v'$2本目の木の中にあります。 したがって、各移動はグラフ積の意味では局所的ではなく、2 つの異なる計量空間における経路長の厳密な等しいことによって制約されます。 

クエリごとに、頂点の開始ペアと頂点のターゲット ペアが与えられ、開始状態をターゲット状態に変換するために必要な同期距離移動の最小数を決定する必要があります。 有効な動きのシーケンスが存在しない場合は、次のように出力する必要があります。$-1$。 

この制約により、ツリーとクエリ数の両方を 200,000 個の頂点と 200,000 個のクエリまで大きくすることができます。 クエリごとにパスを個別に推論しようとしたり、頂点ペア間の可能な距離を列挙しようとしたソリューションは、すぐに失敗します。 ツリー内にすべてのペアの距離を格納するだけでも、サイズがすでに 2 次になり、時間とメモリの制限の下では不可能です。 

ローカルで考えると微妙な問題が見えてきます。 素朴な直観としては、木には固有のパスがあるため、各移動を「距離 d を選択し、両方のコンポーネントを距離 d だけ移動する」ものとして扱うことができるのではないかと考えられます。 ただし、これでは、距離制約だけではエンドポイントが一意に決定されないことが無視されます。 多くの頂点のペアが同じ距離を共有しているため、状態グラフは構造化された方法で非常に密になっています。 

典型的な失敗例は、単一の手が各ツリー内で独立して「並べ替えられる」可能性があると想定することから生じます。 たとえば、チェーンのような形のツリーでは距離は厳密ですが、星形のツリーでは多くの端点が中心からの距離が同じであるため、単純なマッチング戦略では対称性の仮定が崩れます。 

中心となる問題は、積グラフのエッジに沿って移動するのではなく、エッジが 2 つの無関係なツリーの等距離ペアを表すメトリック同期グラフに沿って移動することです。 

## アプローチ

 この問題を考える強引な方法は、ノードがすべてペアである状態グラフを明示的に構築することです。$(u, v)$、距離等しい条件が成立する場合は 2 つのノードを接続します。 このグラフには、$n_1 \cdot n_2$ノード、すでに$4 \cdot 10^{10}$最悪の場合。 何らかの方法で明示的に構築することを避けたとしても、クエリに答えるには、隣接する状態を探索する必要があります。 単一ノードからの有効な移動の数は膨大です。これは、あらゆる可能な距離に対して行われるためです。$d$、遠く離れた両方のツリーにエンドポイントのペアが多数存在する可能性があります。$d$。 したがって、クエリごとに 1 つの BFS を使用することは完全に不可能です。 

重要な観察は、移動の定義はグローバルに見えますが、ツリー内の距離によってのみ支配され、ツリー内の距離は最下位共通祖先によって決定されるということです。 これは、エンドポイントについて考える代わりに、各コンポーネントが現在の位置からツリーの距離に基づいてどれだけ離れるかを考える必要があることを示唆しています。 

2 番目の構造的洞察は、移動によって「ルートの分解に沿った深さの違い」が制御された方法で保存されるということです。 両方のツリーをルート化し、深さと LCA 構造の観点から距離を考慮すると、移動は本質的に、同一のパス長をカバーする必要がある 2 つの独立したツリー ウォークを同期させます。 これにより、問題は、2 つの頂点ペア間の変換を両方のツリーにわたる等しい長さのセグメントに分解できるかどうかという問題に変わります。 

これは短縮につながります。答えは、各ツリーの開始点と終了点の間の距離と、これらの距離が一連の同期されたステップを通じて一致できるかどうかによってのみ決まります。 再定式化すると、この問題ははるかに小さい暗黙の構造上の最短経路問題になり、状態は実際の頂点ではなく残りの距離のペアによって支配されます。 

最終的なソリューションは、頂点の列挙を完全に回避し、ツリー メトリックと LCA 前処理から導出された距離とパリティのような制約のみを処理します。

 ## アルゴリズムのチュートリアル

 ### 1. 両方のツリーをルート化し、LCA 構造を前処理します。 

両方のツリーに対して任意のルートを選択し、親のジャンプと深さを計算することで、2 つの頂点間の距離のクエリに O(log n) 時間で答えることができます。 すべての推論は繰り返し距離に帰着するため、これが必要です。 

### 2. クエリごとに、2 つの固有距離を計算します。 

お問い合わせの場合$(s_1, s_2, t_1, t_2)$、次を計算します。 

距離$d_1 = dist_1(s_1, t_1)$最初の木で、そして

 距離$d_2 = dist_2(s_2, t_2)$2番目の木で。 

これら 2 つの数値は、各ツリーで独立して実行する必要がある「作業」の量を表します。 有効な一連の動きでは、等しいステップ サイズを通じてこれら 2 つの量を調整する必要があります。 

### 3. パリティと同期制約を使用して実現可能性を確認する

 有効な一連の動きは両方を分割します$d_1$そして$d_2$ステップ長の同じマルチセットに変換します。 これは、残りの合計距離が段階的に進化する必要があり、特に両方の距離を同一の正の整数の合計として表現できなければならないことを意味します。 

これにより、必要な条件が強制されます。つまり、到達する構造のパリティが一致している必要があり、より厳密には、距離間の差が等しいセグメントへの分解を妨げてはなりません。 より大きな距離をより小さな距離に一致するセグメントに分解できない場合、シーケンスは存在しません。 

### 4. 同期ステップの数を最小限に減らす

 実現可能性が確立された場合、最適な戦略は、両方のツリーがオーバーシュートすることなくターゲットに向かって移動し続けるように、可能な限り最大の同期ステップを常に実行することです。 これは、ツリーのジオメトリを尊重しながら、両方の距離の等しい長さの短縮を貪欲に一致させることに対応します。 

各ステップで両方の距離がまったく同じ量だけ減少するため、答えはペアのパーティション内のセグメントの最小数になります。$(d_1, d_2)$これは、ツリー内で許可されたパス分解によって引き起こされる最大共通構造の関数に単純化されます。 

### 5. クエリごとに結果を返す

 実現可能性が失敗した場合は出力$-1$。 それ以外の場合は、計算された同期セグメントの最小数を出力します。 

### なぜ効果があるのか

 重要な不変条件は、実際の頂点が変化したとしても、移動するたびに両方のツリーの現在位置からターゲットまでの残りの距離が経路長の観点から同じ量だけ減少するということです。 これは、問題が同期された残留距離のペアを通じてのみ発展することを意味します。 有効なパスはすべて、両方の初期距離を正の整数の同一のシーケンスに分解したものに対応します。また、そのような分解は、ツリーの移動の有効なシーケンスに対応します。これは、ツリーを使用すると、一意の単純なパスに沿った所定の距離にある任意の終点を実現できるためです。 この等価性により、貪欲な分解により可能な限り最短のシーケンスが得られ、ツリー内での再ルーティングによって実行不可能なケースを人為的に修正できないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

LOG = 20

def build_lca(n, g):
    parent = [[-1] * n for _ in range(LOG)]
    depth = [0] * n
    stack = [(0, -1)]
    order = []

    while stack:
        v, p = stack.pop()
        parent[0][v] = p
        order.append(v)
        for to in g[v]:
            if to == p:
                continue
            depth[to] = depth[v] + 1
            stack.append((to, v))

    for i in range(1, LOG):
        for v in range(n):
            if parent[i - 1][v] != -1:
                parent[i][v] = parent[i - 1][parent[i - 1][v]]

    def lca(a, b):
        if depth[a] < depth[b]:
            a, b = b, a
        diff = depth[a] - depth[b]
        for i in range(LOG):
            if diff & (1 << i):
                a = parent[i][a]
        if a == b:
            return a
        for i in range(LOG - 1, -1, -1):
            if parent[i][a] != parent[i][b]:
                a = parent[i][a]
                b = parent[i][b]
        return parent[0][a]

    def dist(a, b):
        c = lca(a, b)
        return depth[a] + depth[b] - 2 * depth[c]

    return dist

n1, n2, q = map(int, input().split())
g1 = [[] for _ in range(n1)]
g2 = [[] for _ in range(n2)]

for _ in range(n1 - 1):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    g1[u].append(v)
    g1[v].append(u)

for _ in range(n2 - 1):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    g2[u].append(v)
    g2[v].append(u)

dist1 = build_lca(n1, g1)
dist2 = build_lca(n2, g2)

out = []

for _ in range(q):
    s1, s2, t1, t2 = map(int, input().split())
    s1 -= 1
    s2 -= 1
    t1 -= 1
    t2 -= 1

    d1 = dist1(s1, t1)
    d2 = dist2(s2, t2)

    if d1 == d2:
        out.append(str(d1))
    else:
        out.append("-1")

print("\n".join(out))
```この実装は、LCA クエリの各ツリーの前処理を中心に構築されています。 機能`build_lca`バイナリ リフティング テーブルを構築し、対数時間で木の距離を計算する距離関数を公開します。 

クエリごとに、必要な 2 つのツリー距離を個別に計算します。 コードで使用される決定的な観察は、有効な変換は両方の距離が正確に一致する場合にのみ存在するということです。これは、すべての移動でステップ長の等価性が維持され、したがってパス分解全体のマルチセット構造が維持されるためです。 不均衡があるとすぐに完全な調整ができなくなります。 等しい場合、木の端に沿った各単位ステップは両方の木にわたってペアにできるため、最適な移動数は共通の距離に収まります。 

残りの解決策は、0 インデックスへの変換、隣接リストの使用、大きな入力サイズに対する高速 I/O の維持など、慎重なブックキーピングです。

 ## 特殊なケース

 最小限のエッジ ケースは、両方のツリーが単一のノードで構成されている場合です。 両方のツリー内のノードからノード自体へのクエリにより距離が得られます。$0$そして$0$。 両方の距離が一致し、移動が必要ないため移動数がゼロになるため、アルゴリズムはこれをすぐに受け入れます。 

もう 1 つの微妙なケースは、一方のツリーがチェーンなど非常にアンバランスで、もう一方が星である場合です。 スターは中心から 0 または 1 の距離しか認識できないのに対し、チェーンは任意の距離をサポートするため、両方のツリーで等しい距離を必要とするクエリは失敗することがよくあります。 このアルゴリズムは、計算された距離が異なる場合には常にそのようなケースを正しく拒否し、LCA ベースの計算はこの不一致を即座に明らかにします。 

最後のケースは、両方のツリーが同一であるが、クエリ エンドポイントが 1 つのツリー内で交換される場合に発生します。 距離は対称であるため、アルゴリズムは依然として等しい値を計算し、正しい最小移動数を返します。これにより、移動の方向性は無関係で、メトリックの同等性のみが重要であることが確認されます。
