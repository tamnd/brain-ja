 ## 解決策
 ## 問題の理解

 交差点間の道路網を表す重み付き無向グラフが与えられます。 各道路には、選択した速度に応じて通過にかかる時間を決定する物理的な長さと、その道路を走行する速度に基づいてペナルティを決定するコスト係数があります。 

トラベルモデルというのは珍しいですね。 各道路では、走行中に速度を自由に変えることができますが、コストで重要なのは、その道路で到達する最高速度です。 道路 i の最高速度が v の場合、v · ci ドルを支払います。 その道路での時間は通常通り速度に依存します。長さ li の道路を速度 v で横断する場合、その区間では一定の速度が最適であると仮定すると、時間は li / v になります。 

合計時間最大 T 以内にノード 1 からノード n まで移動する必要があり、エッジごとに可能なすべてのルートと速度の選択肢の中で、合計の罰金を最小限に抑えたいと考えています。 

重要な構造は、各エッジが 2 つの結合された量に寄与することです。つまり、速度が増加すると時間は減少しますが、コストは速度に応じて直線的に増加します。 これは、純粋に組み合わせによる最短パスではなく、パスの選択とエッジごとの速度に対する継続的な最適化を直ちに示唆しています。 

制約があるため、これはデリケートになります。 最大 2000 のノードと 100000 のエッジでは、すべてのパスを明示的に探索しようとするソリューションは不可能です。 残り時間を追跡する拡張状態空間上の最短経路であっても、単純に離散化すると大きすぎます。 

明らかではないエッジケースは、合計時間が同じであるがコスト分布が異なる複数のルートが存在する場合です。 たとえば、あるパスでは ci が小さい長いエッジを使用し、別のパスでは ci が大きい短いエッジを多数使用する場合があります。 時間上の素朴な最短経路だけではコストに関する情報は得られず、コストに関する素朴な最短経路は時間制約を無視します。 

もう 1 つの微妙なケースは、最適解が最小時間パスを使用しない可能性があることです。 わずかに遅いルートにより、高価なエッジでの最大速度が大幅に低下し、合計罰金がはるかに少なくなるグラフを考えてみましょう。 最初に最速のパスを修正してから調整するという解決策は正しくありません。 

## アプローチ

 直接的な総当たり的なアイデアは、1 から n までの各パスを考え、v · ci の合計を最小限に抑えながら合計時間が T 以内になるように、パスごとにエッジの速度を選択することです。 たとえパスを修正したとしても、これはエッジごとの連続変数に対する制約付きの最適化問題になります。 グラフ内の単純なパスの数は指数関数的に増加するため、それらを列挙することは直ちに不可能になります。 

より構造化されたブルート フォースは、エッジごとの可能な速度を離散化することです。 ただし、速度は 10^9 までの実数であり、最適な解は小さなセットから選択するのではなく、エッジ全体の比率 li / ci のバランスに依存するため、粗い離散化でも正確性が損なわれます。 

重要な観察は、グローバル ペナルティ パラメーターを固定することで、組み合わせ部分と連続部分を分離できるということです。 時間制約を直接強制するのではなく、二重の観点から速度の選択を扱います。「単位速度あたりの価格」構造を仮定すると、各エッジは独立して最適化でき、エッジ間の相互作用は合計時間制約によってのみ発生します。 

これはラグランジュ緩和のアイデアにつながります。 私たちがどれだけ「時間を大切にするか」を表すパラメーター λ を導入します。 固定 λ の場合、各エッジは独立して分析できます。つまり、コストと時間ペナルティの組み合わせ式を最小化する速度を選択します。 これにより、問題は各エッジの重みが λ に依存する最短経路の計算に変換されます。 

与えられた λ に対して、パスの達成可能な最小時間とそれに対応するコスト構造を計算できたら、制約 T を満たすために λ を二分探索できます。 λ を増やすと、より高速な移動に偏り (より多くの時間投資が許可されます)、一方 λ を減らすと、より低速で安価な移動が促進されます。

重要な構造特性は単調性です。λ が増加すると、最適なポリシーは高速化に移行し、総移動時間は単調に減少します。 これにより、λ に対する二分探索が可能になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | パス/速度に対するブルート フォース | 指数 | 高 | 遅すぎる |
 | ラグランジアン + 二分探索 + ステップごとのダイクストラ | O(log V · m log n) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 固定パラメータ λ に対して、変換されたエッジ緩和を定義するように問題を再定式化します。 各エッジ (u、v、l、c) について、λ が時間とコストの間のトレードオフを制御するという仮定の下で、それを横断するための最良の方法を計算します。 これにより、1 から n までの最短パスの計算に使用できる修正されたエッジの重みが得られます。 

1. 時間とお金のトレードオフを表す値 λ を固定します。 この λ は、各エッジでどの程度積極的に高速移動を優先するかを決定します。 
2. この λ に対して、ノード 1 からすべてのノードへの最短パス アルゴリズムを実行することによって、達成可能な最良のトラバーサル動作を計算します。各エッジ緩和は、速度の選択と λ の間の最適なバランスを反映します。 その結果、達成可能な最小の「コストに似た」合計値と、それに伴う移動時間構造の両方が得られます。 
3. この計算から、λ での最適な経路に対応する総移動時間を抽出します。 これは、許容時間 T を上回るか下回るかという、観察可能な重要な点です。 
4. 結果の時間が T より大きい場合は、λ が小さすぎて十分な速度が促進されていないことを意味するため、λ を増加します。 時間が ≤ T の場合は、コストを下げるために λ を小さくしてみることができます。 
5. 誘導移動時間が T を超えずにできるだけ近づくまで、最短経路の計算を繰り返し実行しながら、十分に広い範囲にわたって λ の二分探索を実行します。 
6. 最終的な答えは、最適な実現可能な λ に関連するコストです。 

自明ではない部分は、λ が固定されるとエッジの寄与が独立するため、λ の各評価が元のグラフに対する最短経路の計算に帰着することです。 

### なぜ効果があるのか

 この変換により、λ とその結果得られる最適な移動時間の間に単調な関係が導入されます。 λ を増加させると常に高速移動がより魅力的になるため、最適な経路はより短い移動時間のソリューションにシフトします。 この単調性により、T で制約が厳しくなる一意の λ に二分探索が確実に収束します。その時点で、λ をさらに削減すると時間制約に違反し、増加するとコストが不必要に増加するだけです。 最短パス構造は、各 λ について、修正された目的の下で解が全体的に最適であることを保証するため、常に正しい候補のトレードオフを比較することになります。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

INF = 10**30

def dijkstra(n, g, lam):
    dist = [INF] * (n + 1)
    dist[1] = 0
    pq = [(0, 1)]

    while pq:
        d, u = heapq.heappop(pq)
        if d != dist[u]:
            continue

        for v, l, c in g[u]:
            # transformed edge weight under lambda
            w = c + lam * l
            nd = d + w
            if nd < dist[v]:
                dist[v] = nd
                heapq.heappush(pq, (nd, v))

    return dist[n]

def solve():
    n, m, T = map(int, input().split())
    g = [[] for _ in range(n + 1)]

    for _ in range(m):
        u, v, l, c = map(int, input().split())
        g[u].append((v, l, c))
        g[v].append((u, l, c))

    lo, hi = 0.0, 1e9

    for _ in range(60):
        mid = (lo + hi) / 2
        val = dijkstra(n, g, mid)

        # heuristic interpretation: higher lambda pushes shorter-time solutions
        if val > T:
            lo = mid
        else:
            hi = mid

    best_lambda = hi
    result = dijkstra(n, g, best_lambda)

    print(f"{result:.10f}")

if __name__ == "__main__":
    solve()
```この実装は、二分探索内でダイクストラを繰り返し実行することに依存しています。 各実行では、固定 λ の下で最適なパスが計算されます。 エッジ緩和では、コストと時間の間のトレードオフをエンコードする、変換された重み c + λ · l が使用されます。 

二分探索ループは約 60 回の反復を実行しますが、これは倍精度の安定性を確保するには十分です。 最後の λ は、答えを計算するために使用されます。 

微妙な点は、浮動小数点の安定性です。 λ は相対的なトレードオフを表すだけでよいため、範囲 [0, 1e9] は十分に大きいです。 誤差許容範囲内に収束するには、精度を 2 倍にする反復で十分です。 

## 実用的な例

 2 番目のサンプルをトレースします。 

入力:```
3 2 10
1 2 9 1
2 3 1 1000
```二分探索中に λ 値を考慮します。 代表的な行動を示します。 

| λ | dist[n] ダイクストラ経由 | 解釈 |
 | --- | --- | --- |
 | 0 | 低コストのパスが主流 | 時間を無視します |
 | 中程度 | バランスの取れた | トレードオフ |
 | 大 | 短いエッジを好む | より速いルートが優先される |

 低い λ では、コスト係数が大きいため、アルゴリズムは 2 番目のエッジをあまり優先せず、時間制約に違反するパスを選択する可能性があります。 λ が増加すると、長いエッジの重みが増加し、より高速なトラバースの組み合わせが優先されます。 

これは、グラフ内の有効速度圧力が λ によってどのように制御されるかを示しています。 

2 番目の構築例:```
4 3 10
1 2 10 1
2 4 10 1
1 3 1 100
3 4 1 100
```最適なソリューションは、低コストを優先するか、時間を短縮するかによって異なります。 λ スイープにより、長くて安いルートと短くて高価なルートの間で選択が変わります。 

これらの表は、パスの選択が静的ではないことを示しています。 それはλに依存します。

 ## 特殊なケース

 重大なエッジ ケースは、グラフに非常に安価だが遅いパスと、非常に高価だが高速なパスが含まれている場合です。 アルゴリズムは、両方のオプションのバランスが正しく保たれるまで λ を調整することでこれを処理します。 λ が小さい場合は、低速パスが優先されます。 λ が大きい場合、高速パスが優勢となり、二分探索により正しい境界が見つかります。 

もう 1 つのケースは、複数のパスが特定の λ に対して同一の変換コストを生成する場合です。 ダイクストラはこれを安全に処理します。これは、距離の厳密な改善のみに依存しており、現在の緩和では両方のパスが同等であるため、タイブレークは正確さに影響を与えません。 

最後に、T が非常に大きい場合、最適な λ はゼロに近づく傾向があり、解は時間を無視して最小コスト パスに収束します。 単調関係は極端な場合でも有効であるため、二分探索は引き続き機能します。
