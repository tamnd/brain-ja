 ## 解決策
 ## 問題の理解

 私たちには次のシーケンスが与えられています`n`ブロック、それぞれに色が付いています`1`に`n`。 それらを 2D グリッド上に 1 つずつ配置する必要があります。 最初のブロックは常に次から始まります`(0, 0)`。 後続のすべてのブロックは、前のブロックに対して左、右、または上のいずれかに移動できますが、下に移動したり、すでにブロックが含まれている位置を占めたりすることはできません。 ブロックが配置されると、色ごとに、その色のブロックの連続する最大の垂直スタック、つまり、その色のブロックのみを使用する最も高いタワーを見つけるように求められます。 

入力は最大です`10^5`テスト ケースごとのブロック数、すべてのテスト ケースの合計は次のようになります。`2 * 10^5`。 1 秒の時間制限では、テスト ケースごとに線形または線形対数よりも悪いものを許容することはできません。 ブロックに対する二次演算は遅すぎます。 

エッジ ケースは、色が 1 回だけ表示される場合、または配置ルールに違反せずに垂直方向に整列できない位置に表示される場合に発生します。 たとえば、ブロックが`[1, 2, 1, 2, 1]`、の出現数の単純なカウント`1`ある程度の大きさのタワーをお勧めします`3`ただし、配置制限により、これより大きい垂直スタックはできない可能性があります。`2`。 同様に、まったく表示されない色も正しく返されるはずです。`0`。 

微妙なのは、同じ色の連続するブロック間の「垂直方向の分離」が重要であるということです。 間にあるブロックを考慮せずに自由に垂直に積み重ねることはできないため、水平方向の移動が強制される可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、各ブロックをグリッド上に配置するシミュレーションを試み、すべての可能な座標を追跡し、各色の垂直タワーの高さをチェックします。 これは正しいですが、非常に遅いです。 各ブロックについて、複数の可能な配置を検討する場合があります。`10^5`ブロック。 最悪の場合、これにより指数関数的な動作が発生し、制限時間内に実行できなくなります。 

重要な洞察は、絶対座標は重要ではないということです。 特定の色のタワーの高さに影響する唯一のことは、同じ色の次のブロックを配置するために水平に「ジャンプ」する必要がある頻度です。 同じ色の 2 つのブロックがシーケンス内で連続している場合、間のブロックを水平に配置することで、それらを垂直に積み重ねることができます。 したがって、問題を、同じ色の連続するブロック間の「ギャップ」の最小数を数えることと、これらのギャップがどのように水平方向の移動を強制するかをカウントすることに帰着できます。 

特定の色が発生する一連の位置を考慮することで、これを形式化できます。 2 つの出現の間に、異なる色のブロックが他にある場合は、少なくとも 1 回水平方向に移動する必要があります。 したがって、色の最大垂直スタックは基本的に次のようになります。`1 + the number of times that color appears with other blocks in between`。 

これを効率的に実装する簡単な方法は、ブロックを反復処理し、各色の最後に表示されたインデックスを追跡し、それらの間の「セグメント」を数えるということです。 これにより、問題が各テスト ケースの配列にわたる線形スキャンに変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n^2) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を初期化する`max_tower`サイズの`n`ゼロ付き。 これにより、色ごとに結果が保存されます。 
2. 各色について、最後に出現したインデックスを維持します。 から始める`-1`まだ見られていないことを示します。 
3. ブロックを順番に繰り返します。 色のブロックごとに`c`:

 ａ． これが初めての発生である場合、`c`、から数えて新しいタワーセグメントを開始します。`1`。 

b. 以前に出現したことがある場合は、前回の出現からの間隔を確認してください。 間に他のブロックがある場合は、必要な垂直セグメントの数を増やします。`c`。 これは、この色に対して実行できる「垂直移動」の数を効果的にカウントします。 

c. 色の最終出現インデックスを更新します。`c`。 
4. ブロックをスキャンした後、各色の最大垂直セグメントが答えになります。 
5. 配列を出力する`max_tower`。 

これが機能する理由は、各ブロックが垂直の塔を継続するか、別のブロックが介入した場合に強制的に水平方向に移動する必要があるためです。 同じ色の連続出現間のブロック数をカウントすることで、必要な垂直セグメントの最小数を取得します。 これにより、配置ルールに基づいてタワーの最大高さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    c = list(map(int, input().split()))
    
    last_pos = [-1] * (n + 1)
    max_tower = [0] * (n + 1)
    
    for idx, color in enumerate(c):
        if last_pos[color] == -1:
            max_tower[color] += 1
        else:
            if idx - last_pos[color] > 1:
                max_tower[color] += 1
        last_pos[color] = idx
    
    print(" ".join(str(max_tower[i]) for i in range(1, n + 1)))
```このコードは、各色が出現した最後のインデックスを追跡し、ブロックが介在する新たな出現に遭遇したときにタワーの数を増分します。 サイズリストの使用`n+1`オフバイワンエラーを回避します。 の`if idx - last_pos[color] > 1`check は、間に少なくとも 1 つの他のブロックがある場合にのみ増分することを保証し、配置に必要な水平方向のシフトを反映します。
