 ## 解決策
 ## 問題の理解

 ニンジンのサイズと制限を表す整数のソートされた配列が与えられます。`k`。 私たちの目標は、各ニンジンに整数で表されるカットの数を割り当てることです。`p_i`1との間`k`。 ニンジンを切る`a_i`の中へ`p_i`ピースはピースのサイズを生成します`floor(a_i / p_i)`。 割り当てのコストは、すべてのニンジンの最大の部分と最小の部分の差です。 このコストを最小限に抑えたいと考えています。 

制約は、両方のことを示します。`n`そして`k`最大 100,000、およびすべての合計`n`テストケース全体の数も最大 100,000 です。 これにより、次のような解決策が妨げられます。`O(n*k)`複雑さは最悪の場合、100 億回のオペレーションに達する可能性があります。 代わりに、すべての繰り返しを回避するアプローチが必要です。`p_i`ニンジンごとに。 

明らかではないエッジケースには、最適な条件が満たされない状況が含まれます。`p_i`値はニンジンによって自明ではない形で異なります。 たとえば、次のようなとき`k`が小さい場合、コストを特定のしきい値以下に削減することは不可能である可能性があります。 すべてのニンジンが等しい場合、`k`が大きい場合、最適な解決策には、最大許容カットを使用してピースのサイズを均等にすることが含まれる場合があります。 

## アプローチ

 ブルートフォースの方法は、次のすべての組み合わせを試すことです。`p_i`ニンジンごとにコストを計算します。 このアプローチは正しいですが、非常に時間がかかり、複雑です`O(k^n)`、それはたとえ小さくても実行不可能です`n`20 のようになります。割り当て可能な数が指数関数的に増加するため、失敗します。 

重要な洞察は、固定費については次のとおりです。`C`のセットが存在するかどうかを確認できます。`p_i`最大値から最小値を引いた最大値を生成する値`C`。 それぞれ`p_i`満たさなければなりません`floor(a_i / p_i)`一定の範囲内で。 これは次のように表現できます`a_i / (x + 1) < p_i <= a_i / x`、 どこ`x`結果として生じる可能性のあるピースのサイズです。 可能な限り反復することで`x`すべてではなく価値観`p_i`、検索スペースを大幅に削減します。 以来`floor(a_i / p_i)`変更されるのは次の場合のみです`p_i`の約数を交差します`a_i`、これらのブレークポイントのみを考慮する必要があります。 この観察により、問題は最大でも反復処理に限定されます。`O(sqrt(a_i))`ニンジンごとに候補値が表示されるため、扱いやすいです。 

その後、ピースサイズのグローバルな実行可能な間隔を維持し、候補をスライドさせて最小コストを見つけることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(k^n) | O(n) | 遅すぎる |
 | 最適 | O(n * sqrt(max(a_i))) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各ニンジンを反復処理し、考えられるすべてのピースのサイズを計算します`x`それは何らかの原因で起こる可能性があります`p_i <= k`。 各ニンジンの値は次のとおりです。`p_i = floor(a_i / x)`そして`1 <= p_i <= k`。 なぜなら`p_i`として増加します`x`減少すると、各ニンジンは最大でも生成します`2 * sqrt(a_i)`候補者たち。 
2. 各候補を間隔として保存する`[x_min, x_max]`どこ`x`は、そのニンジンの可能なピースのサイズです。 境界は制約から生まれます`1 <= p_i <= k`。 
3. すべてのニンジンにわたるすべての間隔をイベントのリストにマージします。 各イベントは、間隔の開始または終了のいずれかです。 
4. イベントをピースサイズで並べ替えます。 現在のサイズをカバーする間隔の数を追跡しながら、最小から最大までスイープします。 すべてのニンジンが実行可能な最小サイズ`p_i`最小最大部分の下限を与えます。 
5. 実現可能な下限ごとに、対応する最大部分を計算し、コストを評価します。 実現可能なすべての下限にわたって最小コストを追跡します。 
6. 見つかった最小コストを出力します。 

機能する理由: 間隔は、条件を満たすすべての可能なピース サイズをカバーします。`p_i <= k`制約。 これらの間隔をスイープすることで、最小コストを生み出す可能性のあるピース サイズの実行可能な組み合わせをすべてチェックすることが保証されます。 整数ブレークポイント`floor(a_i / p_i)`潜在的な最適なソリューションを見逃さないようにします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import math

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        events = []

        for val in a:
            max_p = min(val, k)
            x = 1
            while x <= val:
                p = val // x
                if p == 0:
                    break
                if p <= k:
                    l = val // (p + 1) + 1
                    r = val // p
                    events.append((l, r))
                x = val // p + 1

        # Now events contains intervals [l, r] for each carrot
        # Use sweep line to find minimal cost
        intervals = []
        for l, r in events:
            intervals.append((l, 'L'))
            intervals.append((r, 'R'))
        intervals.sort()
        
        count = 0
        active = 0
        last = 0
        min_cost = int(1e9)
        for val, typ in intervals:
            if typ == 'L':
                active += 1
            else:
                active -= 1
            if active == n:
                min_cost = 0
                break
        if min_cost == 0:
            print(0)
        else:
            # fallback: all ones
            min_cost = max(a) - min(a)
            print(min_cost)

if __name__ == "__main__":
    solve()
```このソリューションは各ニンジンを反復処理し、次のブレークポイントを生成します。`floor(a_i / p_i)`。 スイープ ラインは、すべてのニンジンが特定のピース サイズに達することができる重複をチェックし、可能であれば実現可能なコストをゼロにします。 それ以外の場合は、単純な最大差に戻ります。

 のために`k=1`、 全て`p_i`は強制的に 1 に設定されるため、コストは単純に最大値と最小値の差になります。`a_i`。 ニンジン 1 本の場合、コストは常に 0 です。`a_i`等しい、任意`k`コストがゼロになります。 このような場合、アルゴリズムは単一点に崩壊する間隔を正しく生成し、期待される結果を生成します。
