 ## 解決策
 ## 問題の理解

 私たちに与えられるキャンディーの数と従業員の数は決まっています。 各従業員は、ちょうど 2 個のキャンディー、またはちょうど 3 個のキャンディーを受け取る必要があります。 従業員がキャンディーを 3 個受け取った場合、従業員は幸せとみなされます。 そうでなければ、彼らはキャンディーを 2 つ受け取りますが、幸せではありません。 課題は、すべての従業員が有効なキャンディーを入手できるようにすべてのキャンディーを配布しながら、幸せな従業員の数を最大化することです。 

入力には、キャンディーの総数と従業員数という 2 つの大きな整数が含まれます。 制約により、次の値まで許容されます。$10^9$キャンディーまで$5 \cdot 10^8$そのため、ソリューションはテスト ケースごとに一定時間または対数時間で実行する必要があります。 従業員やキャンディーに対する線形スキャンは、境界が小さい複数のテスト ケースがある場合にのみ許容されますが、ここではスケールがすでに直接的な算術構造を示唆しています。 

微妙な点は、キャンディーの総数が少なくとも従業員の数の 2 倍であることです。 これにより、全員に 2 つのキャンディーを割り当てることが常に実行可能であることが保証されるため、一部の従業員が必要最小限の量を受け取れないという実行不可能な状況に直面することはありません。 問題は純粋に、余剰金を再分配することによって一部の従業員を 2 個のキャンディーから 3 個のキャンディーにアップグレードすることです。 

エッジケースはパリティと余剰構造から生じます。 

もし$n = 2m$、その後、すべての従業員はちょうど 2 つのキャンディーを受け取る必要があります。 誰かを 3 つのキャンディーに昇格させる余地はないため、答えは 0 です。たとえば、次のようになります。$n = 10, m = 5$、総額分配が強制され誰も幸せになれません。 

もし$n = 3m$、すると、すべての従業員が 3 つのキャンディーを受け取ることができるので、全員が幸せになり、答えは次のようになります。$m$。 

これらの両極端の間で、実現可能性を損なうことなく、キャンディー 1 個のアップグレードが何回可能であるかを慎重に検討する必要があります。 

## アプローチ

 強引なアプローチでは、従業員ごとにキャンディーを割り当て、それぞれに 2 つまたは 3 つのキャンディーを選択し、すべての組み合わせをチェックしようとします。 と$m$従業員、これは次のことにつながります$2^m$可能な割り当てですが、それはたとえ$m = 40$、ましてや、$5 \cdot 10^8$。 

より構造化されたビューは、全員が 2 つのキャンディーを受け取るベースラインから開始することです。 これは消費します$2m$キャンディー。 残り$n - 2m$キャンディーは、一部の従業員を 2 個から 3 個のキャンディーにアップグレードするために使用できる追加ユニットを表します。 このようなアップグレードごとにちょうど 1 個の追加のキャンディーがかかり、幸せな従業員の数が 1 人増えます。 

ただし、従業員の数を超えないようにする必要があるため、残りのキャンディーをすべてアップグレードすることが必ずしも答えに直接的に等しいとは限りません。 お菓子がたくさん余っても、これ以上は持てません。$m$幸せな従業員たち。 したがって、答えは余剰と従業員数の両方によって制限されます。 

これは直接的な解釈につながります。幸せな従業員はそれぞれ、ちょうど 3 個のキャンディーを消費します。$x$幸せな従業員と$m - x$不幸な従業員、必要なキャンディーの総量は$$3x + 2(m - x) = 2m + x.$$最大でもこれでなければなりません$n$、 それで$x \le n - 2m$。 また$x \le m$。 実現可能な最大限の$x$したがって、 はこれら 2 つの限界の最小値になります。

 ## アルゴリズムのチュートリアル

 ### 最適な推論手順

 1. すべての従業員が可能な限り最小限のキャンディー 2 個を受け取ると想像することから始めます。 これは正確に消費します$2m$キャンディー、この構成は制約により常に有効です。$n \ge 2m$。 
2. このベースライン割り当て後のキャンディーの残りの数を計算します。 これをそのままにしておきます$r = n - 2m$。 幸福感を高めるために利用できる唯一のキャンディーです。 
3. 従業員のキャンディーを 2 個から 3 個に増やすと、追加のキャンディーがちょうど 1 個消費され、その従業員が幸せな従業員に変わることを観察します。 したがって、幸せな各従業員は、から 1 単位を支出することに相当します。$r$。 
4. せいぜい次のとおりであると結論付ける$r$余ったキャンディーを使って従業員を幸せにすることができます。 
5. また、幸せな従業員の数が従業員の総数を超えてはいけないことにも注意してください。$m$、各従業員は最大 1 回までカウントできるためです。 
6. これら 2 つの制約の最小値を取得します。$r$そして$m$、最終的な答えとして。 

### なぜ効果があるのか

 すべての有効な割り当ては、幸せな各従業員からキャンディ 1 個を減算することによって、キャンディ 2 個の従業員全員のベースライン割り当てに変換できます。 これは、次のようなソリューション間の 1 対 1 対応を示しています。$x$幸せな従業員とまさにそのような構成$x$余ったキャンディーはベースラインの上に分配されます。 ベースラインは固定されており、可能な限り最小限のキャンディーを消費するため、有効な構成は次の条件を満たす必要があります。$x \le n - 2m$。 各ハピネスユニットには、基本要件を超える追加のキャンディーの固定コストが 1 つあるため、この制限を回避することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    base = 2 * m
    surplus = n - base
    if surplus < 0:
        surplus = 0
    print(min(m, surplus))

if __name__ == "__main__":
    solve()
```実装は推論を直接エンコードします。 変数`base`は、全員に 2 つのキャンディーが与えられる必須の割り当てを表します。 の`surplus`変数は、配布できる追加の 1-candy インクリメントの数をキャプチャします。 最終的な答えは、この余剰と従業員数の両方によって制限されます。 負の余剰に対する保護は、制約の下では技術的には不要ですが、制約が緩和されたり誤読されたりした場合でも、正しさが保たれます。

 ## 特殊なケース

 場合の場合$n = 2m$、すべての従業員はちょうど 2 つのキャンディーを受け取り、アップグレードは不可能です。 たとえば、入力`10 5`ベースを生成します$2m = 10$アルゴリズムは次のように設定します。`surplus = 0`そして戻ってきます`min(5, 0) = 0`、強制分配と正しく一致します。 

いつ$n$すべての従業員が 3 個のキャンディーを受け取るのに十分な大きさです。`6 2`、計算により進数 4 と剰余 2 が得られます。結果は次のようになります。`min(2, 2) = 2`、つまり従業員全員が幸せになれるということです。 アルゴリズムは自然に飽和します。$m$, 余剰が多い場合でも過剰カウントを防止します。
