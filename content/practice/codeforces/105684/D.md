 ## 解決策
 ## 問題の理解

 スティックの長さの複数セットが与えられています。 各スティックは、四角形の全辺として正確に使用できます。 これらの棒から、明確な二等辺台形が何個形成できるかを数えたいと思います。 

有効な台形では、選択された 4 本のスティックが使用されます。 そのうちの 2 つは等しい脚を形成し、残りの 2 つはベースを形成します。 脚は同じ長さでなければなりませんが、ベースは異なる長さでなければなりません。 縮退した図形を形成することは許可されていないため、台形には正の面積が必要です。これは幾何学的に、底辺の違いに比べて脚が短すぎてはいけないことを意味します。 

2 つの台形は、同じ複数の辺の長さを使用している場合、同じ長さの棒は区別できないため、同じとみなされます。 

拘束は最大 5,000 スティックまで、長さは最大 10 億までです。 これにより、n の 3 次はすぐに除外され、足の選択ごとに単純な O(n² √n) またはそれより悪い構築さえも遅すぎます。 この構造は、実際の値は順序と違いによってのみ重要となるため、長さによって圧縮し、周波数を処理する必要があることを示唆しています。 

微妙な問題は、有効な底辺のペアと等しい脚のペアを選択したとしても、台形が幾何学的に有効であることを確認する必要があることです。 不注意な解決法を使用すると、存在条件を無視して、形状を実現できない無効な 4 倍数を過剰にカウントする可能性があります。 

## アプローチ

 この問題を考える直接的な方法は、スティックの 4 倍をすべて試してみることです。 脚として 2 本、ベースとして 2 本のスティックを選択し、選択した 2 つのベースが異なるかどうか、およびジオメトリが非縮退等脚台形を許可するかどうかを確認します。 これはすでに O(n⁴) の可能性をもたらしますが、これは実現可能性をはるかに超えています。 

脚と台座の役割を分離することでこれを軽減できます。 共通の脚の長さ c を固定すると、脚を選択する方法の数は、長さ c のスティックが何本存在するか、つまり C(freq[c], 2) によってのみ決まります。 脚を固定した後、残る問題は純粋に 2 つの異なる基底長 a と b を選択することです。 

したがって、構造は次のようになります。個別の値 c ごとに、脚の長さ c で台形の実現可能性条件を満たす個別の値の順序のないペア (a、b) がいくつあるかを数えます。 

底辺 a と b、脚 c を持つ二等辺台形の幾何学的条件は、底辺間の差が厳密に脚の長さの 2 倍未満でなければならないということです。 直感的には、ベースが離れすぎると、高さをゼロに折りたたまずに脚を接続することができません。 これは |a − b| に変換されます。 < 2c。 

したがって、各 c について、差が 2c によって制限されるマルチセット内の値のペアをカウントする必要があります。 これは、古典的な「ソートされた配列のスライディング ウィンドウ内のペアをカウントする」問題です。 

配列を頻度を含むソートされた一意の値に圧縮します。 固定 c の場合、ソートされた値に対して 2 つのポインター スイープを実行します。各左端点 j について、V[k] − V[j] < 2c を維持しながら、右端点 k を可能な限り拡張します。 すべての有効な k は、j から始まる (k − j) ペアに寄与します。 j を合計すると、有効な塩基対の数が得られます。 

最後に C(freq[c], 2) を掛けて、すべての c を合計します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 4回転以上のブルートフォース | O(n⁴) | お(1) | 遅すぎる |
 | 脚とベース上の 2 本のポインターを固定します。 O(㎡) | O(m) | 承認済み |

 ここで、m は個別の長さの数であり、最大でも n です。 

## アルゴリズムのチュートリアル

 V を個別の長さのソートされたリストとし、その数を freq とします。

1. すべてのスティックの長さの周波数マップを作成し、ソートされた固有の値 V を抽出します。これにより、すべての有効な構成で同じ長さが交換可能であるため、繰り返しの作業が軽減されます。 
2. V の各値 c について、freq[c] が 2 未満の場合は、そこから 2 つの等しい脚を形成できないため、それをスキップします。 これにより、不可能なレッグ選択に対する不必要な計算が防止されます。 
3. 固定 c の場合、L = 2c を計算します。 ここで、a < b で b − a < L を満たす順序のないペア (a, b) がいくつあるかを数えます。 
4. V 上で 2 ポインター スキャンを実行します。右ポインター k を維持します。 各左ポインタ j について、V[k] − V[j] < L が成立する限り k を進めます。 これにより、ウィンドウ [j, k) 内のすべての要素が j の有効なパートナーであることが保証されます。 
5. 各 j について、有効な塩基対の数に (k − j − 1) を加算します。 この式は、j と有効な順序なしペアを形成する j と k の間のすべてのインデックスを厳密にカウントします。 
6. c のスイープが終了したら、有効な塩基対の数に C(freq[c], 2) を掛けて、それを答えに加算します。 
7. 最終的な累積合計を出力します。 

2 つのポインター スイープ中の重要な不変条件は、固定左端点 j ごとに、ポインター k が最小のインデックスであり、[j + 1, k − 1] のすべてのインデックスが V[x] − V[j] < 2c という制約の下で j と有効なペアを形成することです。 両方のポインターは前方にのみ移動するため、左端点を処理するときに各ペアが 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def comb2(x):
    return x * (x - 1) // 2

def main():
    n = int(input())
    a = list(map(int, input().split()))

    freq = {}
    for x in a:
        freq[x] = freq.get(x, 0) + 1

    vals = sorted(freq.keys())
    m = len(vals)

    ans = 0

    for c in vals:
        fc = freq[c]
        if fc < 2:
            continue

        limit = 2 * c

        k = 0
        cnt_pairs = 0

        for j in range(m):
            if k < j + 1:
                k = j + 1

            while k < m and vals[k] - vals[j] < limit:
                k += 1

            cnt_pairs += max(0, k - j - 1)

        ans += comb2(fc) * cnt_pairs

    print(ans)

if __name__ == "__main__":
    main()
```同じ長さの辺を選択する場合は多重度のみが重要となるため、実装は入力を周波数に圧縮することから始まります。 各候補脚長 c について、ソートされた個別の値に対する 2 ポインター スイープを使用して、互換性のある塩基対の数を計算します。 

内部式 k − j − 1 は書き間違えやすいです。 これは、厳密に j の右側にあるが、許容差ウィンドウ内にある有効なパートナーの数を表します。 C(freq[c], 2) を乗算すると、2 つの同一の脚を選択するすべての方法が説明されます。 

## 実用的な例

 ソートされた一意の値が V = [1, 2, 3] であり、繰り返されるレッグを除いてすべての頻度が 1 に等しい入力を考えてみましょう。 

freq[2] = 2 で c = 2 に焦点を当て、脚を選択する 1 つの方法を形成できると仮定します。 

c = 2 の場合、制限は 4 です。 

| j | V[j] | 展開後の k | 有効なパートナー | 貢献 |
 | --- | --- | --- | --- | --- |
 | 0 | 1 | 3 | 2 (2,3) | 2 |
 | 1 | 2 | 3 | 1 (3) | 1 |
 | 2 | 3 | 3 | 0 | 0 |

 塩基対の合計 = 3、freq[2] = 2 により C(2,2) = 1 が得られるため、寄与度は 3 になります。 

このトレースは、スライディング ウィンドウがすべての有効な塩基対を左のエンドポイントごとに 1 回ずつ正確に蓄積する方法を示しています。 

ここで、脚の選択のみに影響する値が繰り返されるケース、つまり a = [5, 5, 1, 3] を考えてみましょう。 

c = 5 の場合、freq[5] = 2 となるため、C(2,2) = 1 となります。基本値は [1, 3, 5] です。 

制限は 10 であるため、すべてのペアが有効です。 

| j | V[j] | k | 有効なパートナー | 貢献 |
 | --- | --- | --- | --- | --- |
 | 0 | 1 | 3 | 2 | 2 |
 | 1 | 3 | 3 | 1 | 1 |
 | 2 | 5 | 3 | 0 | 0 |

 合計は 3 で、1 を掛けると 3 つの台形になります。

 ## 特殊なケース

 すべてのスティックの長さが同じ場合、明確な塩基がないため、アルゴリズムはすぐに 0 を返します。 周波数条件だけでは計算はトリガーされません。一意の値が 1 つしかないため、ベースペア掃引は何も寄与しません。 

異なる長さが正確に 2 つあり、3 番目の値がない場合、底辺が異なり、脚が 1 つの値から取得されなければならないため、有効な台形は存在できません。 厳密な不等式制約の下では、2 要素配列に対する 2 つのポインターのスイープでは有効な個別のペアが生成されないため、アルゴリズムは正しくゼロを生成します。 

繰り返される値が多数ある場合、レッグからの寄与は C(freq[c], 2) を介して二次関数的に増加しますが、基本構造は独立して計算されます。 この分離により、多重度が幾何学的実現可能性チェックに干渉しないことが保証され、各構成は正確に 1 回カウントされます。
