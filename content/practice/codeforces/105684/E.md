 ## 解決策
 ## 問題の理解

 一連のディプロマ レベルと一連の賞品タイプが与えられており、ディプロマ レベルごとにグループ化された参加者に賞品を割り当てる一貫した方法がいくつ存在するかを数えなければなりません。 

がある$m$卒業証書のカテゴリー。 カテゴリ$i$まさに$i$参加者、および同じカテゴリ内のすべての参加者は、同じ種類の賞品を受け取る必要があります。 賞品の種類には次の番号が付けられています。$1$に$n$、数値が小さいほど、厳密に優れた賞品に対応します。 

各賞品タイプの定員も指定されています: 賞品タイプ$j$量的に存在する$j + a - 1$。 すべての参加者は賞品を 1 つ受け取る必要があり、未使用の賞品を残すことは許可されています。 

課題では、単調な品質ルールを尊重する必要があります。つまり、より良い卒業証書を取得した参加者が、より悪い賞を受け取ってはなりません。 賞金指数は小さい方が良いので、ディプロマグループの場合$i$グループよりも優れています$j$、グループに割り当てられた賞品$i$グループに割り当てられた賞品以下のインデックスが必要です$j$。 

したがって、事実上、各卒業証書グループに 1 つの賞の種類を割り当て、長さが減少しないシーケンスを形成することが決定されます。$m$供給制約を尊重しながら。 グループ$i$消費する$i$受け取った賞品の種類を問わずコピー。 

制約が意味するのは、$n \le 5000$、したがって、周りの解決策$O(n^2)$または$O(n^2 \log n)$もっともらしいですが、立方体的なものは何でも$n$遅すぎます。 以来$m \le n$、両方の次元のプレフィックスに対する動的プログラミング ソリューションを期待する必要があります。 

微妙な点は、各卒業証書グループがその規模に応じて異なる重みを提供していることです。 これにより、これを標準の重み付けされていないパーティションの問題として扱うことが直ちにできなくなり、プレフィックスの合計を注意深く追跡する必要が生じます。 

よくある間違いは、各グループが 1 つのユニットに貢献すると考えることであり、これが誤った貪欲または単純な組み合わせモデルにつながります。 たとえば、グループの場合$1,2,3$、それらすべてを 1 つの賞品タイプに割り当てると、$6$単位ではなく、$3$、実現可能性が大きく変わります。 

もう 1 つの失敗例は、単調性を無視することです。 恣意的な割り当てを許可すると、より良い卒業証書グループに、より悪い賞を割り当てるなどの構成が過大にカウントされることになります。 たとえば、グループ 1 をタイプ 3 に割り当て、グループ 2 をタイプ 2 に割り当てると、容量が許容する場合でもルールに違反します。 

## アプローチ

 強引な解釈は簡単です。各卒業証書グループに対して、昇順で賞の種類を選択し、すべての容量制約が満たされていることを確認します。 これはすべてのシーケンスを調査します$t_1 \le t_2 \le \dots \le t_m$、各シーケンスについて、種類ごとに消費される賞品の数を計算します。 

このようなシーケンスの数は、おおよそ、繰り返しとの組み合わせのオーダーです。$\binom{n+m-1}{m}$、これはすでに大きいです$n,m \approx 5000$。 実現可能性をチェックする前であっても、これらのシーケンスを列挙することは不可能です。 

ボトルネックは、実現可能性のチェックでは賞品の種類ごとに重み付けされたグループ サイズを集計する必要があるため、各候補者にコストがかかり、全体の複雑さが限界をはるかに超えていることです。 

重要な構造的観察は、単調性により、同じ賞品タイプに割り当てられたすべてのグループがシーケンスの連続したセグメントを形成することを強制することです。$1 \dots m$。 より大きな番号の賞品タイプを割り当てると、より小さい賞品タイプに戻ることはありません。そのため、この割り当てはプレフィックスを分割することと同じです。$1 \dots m$連続したセグメントに分割します。 各セグメントは 1 つの賞品タイプに対応し、セグメントは賞品タイプ インデックスの昇順に割り当てられます。 

これにより、問題はセグメントの境界を選択し、各セグメントの合計重量がその賞品タイプの利用可能な容量内に収まるように各セグメントを賞品タイプに割り当てることに変わります。 

ここで問題は、グループのプレフィックスと賞品タイプのプレフィックスに対する DP になり、遷移は有効なセグメント範囲に依存します。 グループ サイズのプレフィックス合計を使用すると、一定時間でセグメントの重みをチェックでき、2 つのポインターを使用して有効な範囲を効率的に事前計算できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 割り当てのブルートフォース列挙 | 指数関数的$m$|$O(m)$| 遅すぎる |
 | 2 つのポインターを持つセグメント上の DP |$O(n^2)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは、各賞の種類が卒業証書グループの単一の連続したブロックに役立つという考えに基づいてソリューションを構築します。 

1. グループ サイズのプレフィックスの合計を計算します。 させて$S[i] = 1 + 2 + \dots + i = i(i+1)/2$。 これにより、任意のセグメントの参加者の総数を計算できます。$[l, r]$として$S[r] - S[l-1]$。 実現可能性はセグメントの合計のみに依存するため、これは不可欠です。 
2.賞品種類ごとに$j$、その容量を計算します$c_j = j + a - 1$。 グループのどのセグメントをカバーできるかは今後決定します。 
3. 開始位置ごとに$l$セグメントの最大終了位置を決定します$r$セグメントの合計が容量内に収まるように$c_j$。 これは、2 ポインタ スキャンを使用して行われます。$r$、 以来$S[r]$増加しています。 
4. 動的プログラミング テーブルを定義します。$dp[j][i]$最初の部分をカバーする方法の数です$i$賞品タイプを使用する卒業証書グループ$j$、順序を尊重します。 
5. 移行: 賞品の種類を決定した場合$j$セグメントをカバーする$[l, r]$、その後、最初にカバーするための有効な方法$l-1$までのタイプを使用するグループ$j-1$最初にカバーするまで拡張できます$r$を使用するグループ$j$。 
6. すべてを繰り返すのではなく$l$それぞれに$j$、範囲更新を使用します。 それぞれについて$l$、それが有効であることがわかったら、$r$、追加します$dp[j-1][l-1]$すべての州へ$dp[j][l..r]$。 
7. 効率的に実装するために、DP 層ごとに差分配列を使用します。そのため、各寄与は定数時間範囲の加算となり、その後、次の DP 行のプレフィックス和の再構成が続きます。 

### なぜ効果があるのか

 核となる不変条件は、すべての有効な代入がシーケンスのパーティションに一意に対応することです。$1..m$各セグメントが 1 つの賞品タイプに昇順で割り当てられます。 DP により、各プレフィックスについて考えられるすべての最後のセグメント境界が考慮されることが保証され、範囲更新により、実行可能なすべてのセグメント割り当てが正しい以前の状態から 1 回だけカウントされることが保証されます。 容量はセグメントが形成された瞬間に適用されるため、無効な割り当てが前方に伝播することはなく、すべての遷移で順序が保持されるため、有効な割り当てが失われることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n, a = map(int, input().split())
    m = int(input().strip())

    # prefix sums of group sizes: S[i] = 1+...+i
    S = [0] * (m + 1)
    for i in range(1, m + 1):
        S[i] = S[i - 1] + i

    dp_prev = [0] * (m + 1)
    dp_prev[0] = 1

    for j in range(1, n + 1):
        cap = j + a - 1

        diff = [0] * (m + 2)

        r = 0
        for l in range(1, m + 1):
            if r < l - 1:
                r = l - 1

            while r < m and S[r + 1] - S[l - 1] <= cap:
                r += 1

            if r >= l:
                add = dp_prev[l - 1]
                if add:
                    diff[l] = (diff[l] + add) % MOD
                    diff[r + 1] = (diff[r + 1] - add) % MOD

        cur = [0] * (m + 1)
        run = 0
        for i in range(m + 1):
            run = (run + diff[i]) % MOD
            cur[i] = run

        for i in range(m + 1):
            cur[i] = (cur[i] + dp_prev[i]) % MOD

        dp_prev = cur

    print(dp_prev[m] % MOD)

if __name__ == "__main__":
    solve()
```遷移は前の DP 層のみに依存するため、実装では 2 つの DP 層のみが保持されます。 2 ポインタ ロジックにより、各ペアが確実に一致します。$(j, l)$は、全体の複雑さを二次関数に保ちながら、右のエンドポイントを単調に進めます。 

差分配列は、固定からのすべての遷移を圧縮するため、非常に重要です。$j$直線的な時間オーバーへ$m$の余分な要素を回避します。$m$セグメントエンドポイントの単純な列挙から。 

インデックス作成には注意が必要です: セグメント$[l, r]$国家に貢献する$r$、前の状態は$l-1$通常、ここで off-by-one エラーが発生します。

私たちは賞品の種類を超えて DP を追跡します。

| ステップ | dp_prev | 新しい有効なセグメント | dp_cur |

 ## 特殊なケース

 主要なエッジケースは、容量が十分に大きく、複数のグループ化パターンが可能になる場合、特に単一の賞品タイプですべての卒業証書グループをカバーできる場合に発生します。 その場合、DP は単純な 1 セグメントの解決策だけでなく、セグメントを形成するすべての方法を正しくカウントする必要があります。 2 ポインター ステップはすべての開始位置を拡張するため、アルゴリズムがこれを処理します。$l$差分配列は、到達可能なすべてのエンドポイントに寄与を伝播します。 

別の特殊なケースは、容量が非常に小さい場合に発生し、すべてのグループが独自のセグメントを占有することを余儀なくされます。 ここだけ、$r = l$移行は存続し、DP は単一の強制された構造に退化します。 範囲が単一点更新に縮小されるため、この実装は引き続き機能しますが、これは差分配列で自然にサポートされます。 

3 番目の微妙なケースは、容量不足により一部の賞品タイプが実質的に使用できない場合です。 DP は引き続きそれらを反復処理しますが、制約を満たすセグメントがないため、その層からの遷移はゼロになり、新しいカウントを追加することなく以前の有効なカウントが正しく引き継がれます。
