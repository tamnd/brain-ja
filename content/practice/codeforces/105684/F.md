 ## 解決策
 ## 問題の理解

 一定の人数に対する順次配布プロセスをシミュレートしています。 がある$m+1$総参加者：特別参加者1名、インターン生、$m$同じ正社員です。 のリスト$n$ギフトは順番に到着し、それぞれのギフトにはプラスの価値が含まれます。 各ギフトはただちに 1 人の参加者に割り当てられます。 

割り当てを管理するルールは貪欲です。各ステップで、次のギフトは、参加者全員の中で現在収集された合計値が最小である人に贈られます。 複数の人がこの最小値を共有する場合は、そのうちのいずれかを選択できます。 このタイブレークの自由が、プロセスにおける変動の唯一の原因です。 

インターンは最初の贈り物を受け取ることを強制されます。 その後、残りのすべてのギフトに対して同じルールに基づいてプロセスが続行されます。 問題は、1 回の実行をシミュレートすることではなく、同点がどのように解決されるかによって、インターンの最終的な合計がどのくらい小さくなるか、または大きくなるかを判断することです。 

制約が到達する$n \le 2 \cdot 10^5$、二次方程式や偶数式は即座に除外されます。$O(n \sqrt n)$意思決定分岐のシミュレーション。 プロセス自体は本質的に逐次的なものであるため、$O(n \log n)$または$O(n \log m)$シミュレーションが当然の目標です。 

微妙な難しさは同点の状況から生じます。 複数の参加者が最小値を共有している場合、1 つを選択することで、インターンが将来ギフトにアクセスできるかどうかが変わる可能性があります。 同点を恣意的に解決する単純なシミュレーションでは単一の結果が計算されますが、ここでは敵対的な同点解消の下での極端な結果が必要です。 

重要なエッジ ケースの 1 つは、すべての従業員が平等にスタートし、しばらくの間平等のままである場合です。 たとえば、すべてのギフトが同一であれば、最初の割り当ての後、システムは完全にバランスを保つことができます。 このような場合、インターンはタイの選択に応じて連続ギフトを受け取る場合と受け取らない場合があり、これらの決定は、インターンが他の人たちとタイを維持するか遅れをとるかに影響します。 

インターンが厳密に遅れている、または厳密に先行している場合には、別の特殊なケースが発生します。 彼の合計が他のすべてよりも厳密に小さい場合、彼は次の贈り物を受け取ることを強制されます。 彼の合計が厳密に大きい場合、彼は確実にスキップされます。 これによりシステムから自由が奪われ、最適化には平等な状況のみが重要になります。 

## アプローチ

 直接シミュレーションでは、各参加者の合計が維持され、最小値が繰り返し選択されます。$m+1$価値観。 プロセスはこれらの最小値によって正確に定義されるため、これは概念的に機能します。 ただし、最善のタイブレークと最悪のタイブレークを探索する必要性を導入すると、ブルート フォースではすべての平等イベントで分岐する必要があります。 最悪の場合、多くの参加者が同じ最小値を繰り返し共有する可能性があり、考えられる決定パスの数が指数関数的に増加する可能性があります。 すべてのタイの選択を試みる、より構造化された総当り攻撃でさえ、実行可能な限界をはるかに超えて退化します。 

重要な観察は、インターンと現在の最小グループの間の相対的な順序のみが重要であるということです。 インターン以外の従業員はすべて交換可能であるため、従業員の ID は必要ありません。各合計値を現在保持している従業員の数だけが必要です。 

システムを従業員合計の複数セットとして維持できます。$m$正規労働者とインターンを個別に追跡します。 各ステップで、インターンの価値と正社員の最低値を比較します。 インターンが厳密に小さい場合、彼は固有の最小値であり、贈り物を受け取る必要があります。 彼が厳密に大きい場合、彼は決定から除外されます。 唯一興味深い状況は、彼の値が他の値の中で最小値に等しい場合です。 

このような同点の状況では、極端な戦略は分岐します。 インターンの最終的な合計を最大化するために、私たちは常にインターンが最小グループに含まれるときに彼を選択します。 それを最小限に抑えるために、別の最小限の従業員がいるときは常に彼に贈り物を与えることを避けます。 

割り当てごとに 1 人の参加者の合計が更新され、その従業員がより価値の高いバケットにシフトされる可能性があります。 これは、値とカウントのヒープを使用して効率的に追跡できます。

 ## アルゴリズムのチュートリアル

 インターンの現在の合計、インターンの合計のマルチセットの 3 つの状態を維持します。$m$正社員を対象とし、正社員の中で最小の合計を高速に検索できる仕組みを構築しました。 

最初は全従業員が合計ゼロからスタートします。 インターンはすぐに最初の贈り物を受け取るため、彼の価値は次のようになります。$a_1$。 各正規従業員はまだゼロなので、マルチセットは次のように始まります。$m$ゼロ。 

残りのプレゼントにつきましては順次対応させていただきます。 

1. 正社員のうち最小の合計を算出しています。 
2. インターンの現在の合計と比較します。 
3. インターンの合計額が最低額よりも厳密に小さい場合、そのインターンは固有の最低額となり、現在のギフトを受け取る必要があります。 
4. インターンの合計が厳密に大きい場合は、正規の従業員がギフトを受け取る必要があり、それに応じてその従業員のバケットを更新します。 
5. インターンの合計が最小値に等しい場合、結果の最大値を計算しているか最小値を計算しているかに応じて、これを異なる方法で解決します。 
6. 最大の場合、ギフトをインターンに割り当て、合計を増やします。 
7. 最小のケースでは、最小レベルの正規従業員にギフトを割り当て、その従業員をより高い合計バケットに移動します。 

各割り当ての後、マルチセット構造内の影響を受ける合計を更新します。 これにより、次のステップで最小値を効率的にクエリできるようになります。 

正しさは、すべての正社員が対称的であるという事実に基づいています。 将来の決定に影響を与える唯一の状態は、合計の複数セットと、現在インターンが最小値と一致しているかどうかです。 正社員間のタイブレークは合計のセットを変更せず、どの同一要素が更新されるかのみを変更します。 

不変条件は、各ステップの後、データ構造が正規従業員間の合計の複数セットとインターンの正確な現在の合計を正しく表すことです。 今後のすべての決定はこれらの値のみに依存するため、これらの値を保存すると、有効なタイブレーク結果がすべてシミュレーションに反映されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import heapq
from collections import defaultdict

def simulate(n, m, gifts, maximize):
    # multiset for regular employees: value -> count
    cnt = defaultdict(int)
    heap = []

    # all regular employees start at 0
    cnt[0] = m
    heapq.heappush(heap, 0)

    # intern gets first gift
    intern = gifts[0]

    def get_min_other():
        while heap and cnt[heap[0]] == 0:
            heapq.heappop(heap)
        return heap[0]

    for i in range(1, n):
        ai = gifts[i]
        mn = get_min_other()

        if intern < mn:
            # intern is unique minimum
            intern += ai

        elif intern > mn:
            # must assign to some regular min
            cnt[mn] -= 1
            if cnt[mn] == 0:
                cnt.pop(mn)
            newv = mn + ai
            cnt[newv] += 1
            heapq.heappush(heap, newv)

        else:
            # intern == mn
            if maximize:
                intern += ai
            else:
                cnt[mn] -= 1
                if cnt[mn] == 0:
                    cnt.pop(mn)
                newv = mn + ai
                cnt[newv] += 1
                heapq.heappush(heap, newv)

    return intern

def main():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))

    # intern gets first gift
    min_val = simulate(n, m, a, maximize=False)
    max_val = simulate(n, m, a, maximize=True)

    print(min_val, max_val)

if __name__ == "__main__":
    main()
```この実装では、2 つの極端な動作が、フラグによって制御される 1 つのシミュレーション関数に分離されます。 正社員の複数セットは、最小値を効率的に取得するためにヒープと組み合わせた頻度マップとして保存され、遅延削除を使用して古いヒープ エントリを処理します。 

インターンは単一のエンティティであるため、その値は直接更新されます。 唯一の分岐は、その値が現在の最小値と一致する場合に発生します。これは、まさにタイブレークが結果に影響を与える場所です。 

よくある間違いは、複数セットの追跡が必要なのは正社員だけだということを忘れていることです。 もう 1 つの微妙な点は、ヒープの一貫性を維持することです。カウントが 0 に低下する値は有効な最小値として信頼してはいけないため、値が見つかった場合は遅延して削除されます。

 ## 特殊なケース

 すべての従業員が同じ値で開始すると、システムは完全に結合された状態でいくつかのステップを費やします。 この体制では、インターンの運命は、関係が彼に有利に解決されるか不利に解決されるかによって完全に左右され、アルゴリズムは、グローバル ミニマムとの平等性を明示的にチェックすることでこれを捕捉します。 

インターン生が他の人たちに大きく遅れをとった場合、同等性が回復するまで、その後のすべての贈り物を受け取ることを余儀なくされます。 シミュレーションではこれを自然に処理します。`intern < mn`すぐに強制割り当てをトリガーします。 

インターンが厳密に先行している場合、他の人が追いつくまで彼は決して選ばれないため、最大のケースでの偶発的な過剰割り当てが防止されます。 等価性ブランチは、制御が実行される唯一の場所です。 

これらの行動はすべて、現在の最低バケットに対するインターンの相対的な位置のみが重要であり、正社員の社内配置は重要ではないという不変条件と一致しています。
