 ## 解決策
 ## 問題の理解

 いくつかの隠れた数の約数であると主張される整数のマルチセットが与えられます。 隠された各番号は異なる従業員に属します。 各従業員について、選択した数字のすべての正の約数が共通のバッグに入れられましたが、その後、これらの数字の一部が失われてしまいました。 残りの表示される数値が与えられ、表示される各数値は、隠れた数値の少なくとも 1 つの約数であることが保証されます。 

私たちの仕事は、元の数値を一意に再構築することではありません。 代わりに、目に見えるすべての数値が少なくとも 1 つの選択された数値の約数として説明でき、これらの選択された数値の合計ができるだけ小さくなるように、目に見える各約数セットをいくつかの未知の数値に割り当てる必要があります。 従業員の数は不明であるため、観測されたすべての約数がカバーされている限り、使用する隠れた数値の数を自由に決定できます。 

重要な問題は、1 つの数値がそのすべての約数を同時に寄与することです。 数値 x を選択すると、x を「支払う」ことを強制され、必要かどうかに関係なく、x のすべての約数が自動的にカバーされます。 これにより、強力な乗算構造を持つ整数に関するカバー問題が発生します。 

n が 2 × 10^5 まで、値も 2 × 10^5 までという制約は、O(N log N) または O(N √N) に近い値が必要であることを示唆しています。 約数の各サブセットについて、考えられるすべての隠れた数値を単純に検索することは不可能です。 

単純な考えは、各約数を独立して扱い、それを含む数値に貪欲に割り当てようとすることです。 これは、異なる候補番号間で約数が大きく重複しているため、失敗します。また、番号の選択が早すぎると、別の番号にもっと効率的に詰め込むことができたはずの約数のカバレッジが「無駄になる」可能性があります。 

2 番目の単純な考えは、各観測値自体が隠れた数値であると仮定することです。 これも間違っています。1 つの数値で観測された複数の約数を同時に説明でき、それらを分割すると常に答えが過大評価されてしまうからです。 

たとえば、1、2、3、6 を観察した場合、単純なアプローチでは 6 (良い) を選択するか、2、3 を個別に選択する (悪い)、あるいは 1、2、3、6 を個別に選択する (非常に悪い) 可能性があります。 最適な解決策は、明らかに 6 ですべてが説明されるという認識にかかっています。 

中心に欠けている構造は、各隠れ数の候補がそのすべての約数のセットに正確に対応しているため、観測された約数を約数が閉じたセットにグループ化するという観点から考える必要があるということです。 

## アプローチ

 総当り攻撃を試みる場合は、整数の一部のサブセットを隠れた数値の候補として選択し、その約数セットが指定されたすべての値をカバーしているかどうかを確認することを想像できます。 候補を最大 2 × 10^5 の数値に制限したとしても、サブセットの数は指数関数的に増加します。 除数を事前に計算できるため、1 つのサブセットを検証することは管理可能ですが、サブセットを列挙することはすぐに不可能になります。 

もう 1 つの乱暴な観点は、観察された各数値 d を考慮し、どの隠れた数値がその数値を「所有」しているかを決定しようとすることです。 各 d を x に割り当て、d で x を除算し、コストを最小化するために x を選択しようとすると、本質的に、割り算チェーンに対する組み合わせの最適化に直面することになります。 1 つの約数が多くの倍数に属しているため、分岐係数が大きすぎます。 

重要な観察は、視点を逆転させることです。 隠れた数字を選択して約数を生成する代わりに、大きな数字から小さな数字まで処理し、各数字を何回「支払う」必要があるかを決定します。 数値 x が選択されると、これまでに見てきた x のすべての倍数が自動的に説明されます。これらの倍数は、x が完全な約数セットの中に約数として存在する必要があることを意味するからです。 この逆転により、問題が扱いやすくなります。

観測された各数値 d は、約数セットに d が含まれる隠れた数値が少なくとも 1 つ存在することを示す信号と考えることができます。 つまり、最終的に選択する d の複数の x が存在する必要があります。 x が責任のある数であると判断した場合、x は多くの観測されたものを含むそのすべての約数をカバーし、より小さな冗長構造に対する支払いを避けることができます。 

大きいものから小さいものへと処理し、各値で「カバーされていない」ままの観察された数値の数を維持します。 x を使用することに決めた場合、観測された x のすべての約数をプールから差し引きます。これは、それらについて説明したためです。 コストは x であり、すでに選択されているより大きな数では説明できない残りの約数をカバーする必要があるときは常に、そのような x を貪欲に選択します。 

これにより、各値がそのすべての約数を説明する潜在的な「ルート」とみなされる、倍数にわたるふるいのような累積が生じます。

 ## アルゴリズムのチュートリアル

 maxA = 200000 までの値を処理するものとして問題を扱い、周波数配列 freq を維持します。ここで、freq[d] は入力に d が現れる回数です。 

1. 指定されたすべての値に対して周波数を構築します。 これにより、各整数が観測された約数の数がわかります。 
2. ブール配列 used[x] を事前計算します。初期値は false です。これは、まだ x を隠し数値として選択していないことを意味します。 
3. x を maxA から 1 まで繰り返します。大きな数値はより小さな約数をカバーできるため、下方向に進みます。また、小さな数値の支払いが時期尚早になるのを避けたいためです。 
4. 各 x について、x を選択した場合に現在まだ解明されていない観測値がいくつ説明されるかを計算します。 具体的には、以前に選択したより大きな数ではまだカバーされていない x のすべての約数 d と合計 freq[d] を考慮します。 
5. この寄与が正の場合、x を選択する必要があります。 答えに x を追加します。 
6. x を選択するとき、freq[d] をゼロに減らすか、カバレッジを個別に追跡することによって、x のすべての約数 d をカバーされるものとしてマークします。これは、それらが x によって説明されるためです。 
7. 1 に達するまで続けます。 

重要な技術的トリックは、x の約数を効率的に反復することです。 maxA は 2e5 であるため、すべての数値の約数を事前に計算することも、倍数にわたるふるいを使用して O(N log N) で反復することもできます。 

### なぜ効果があるのか

 このアルゴリズムは貪欲不変条件を適用します。数値 x を処理するとき、x より大きい数値からのすべての寄与はすでに最適に解決されています。 x で観察された約数がまだ明らかにされていない場合、それを説明する唯一の方法は、x を約数として持つ隠れた数を選択することです。 このようなすべての候補の中で、x 自体を選択することは、x とそのすべての構造を説明できる最も安価な選択です。 この選択を延期しようとすると、後で小さい数字を選択することになり、より大きな構造依存性を説明できなくなり、総コストが増加します。 

したがって、選択される各 x は必然的に強制され、少なくとも 1 つの残りの観測をカバーする必要がない限り、数値を選択することはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXA = 200000

def solve():
    n = int(input())
    arr = list(map(int, input().split()))
    
    freq = [0] * (MAXA + 1)
    for x in arr:
        freq[x] += 1

    # divisor lists
    divs = [[] for _ in range(MAXA + 1)]
    for i in range(1, MAXA + 1):
        for j in range(i, MAXA + 1, i):
            divs[j].append(i)

    covered = [False] * (MAXA + 1)
    ans = 0

    for x in range(MAXA, 0, -1):
        need = False

        # check if x is still needed
        for d in divs[x]:
            if freq[d] > 0:
                need = True
                break

        if not need:
            continue

        ans += x

        # mark all divisors of x as covered
        for d in divs[x]:
            freq[d] = 0

    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、制限値までのすべての数値のすべての約数が事前計算され、各候補 x がその約数セットを迅速に検査できるようになります。 下方向にスキャンして、数値が選択されると、その数値がカバーするすべての小さい数値が重複した選択をトリガーしないようにします。 

微妙な点は、x が選択されると約数の周波数を完全に消去することです。 これにより、これらの観測にはまだカバーが必要であると誤って想定される数が少なくなることがなくなります。 

## 実用的な例

 ### 例 1

 入力:```

```周波数を構築します: freq[1]=1、freq[3]=1、freq[6]=1。 

6から下に向かってスキャンしていきます。 

x=6 では、その約数は {1,2,3,6} になります。 freq[1]、freq[3]、freq[6]はゼロ以外なので、6 を選択してクリアします。 

x が小さい場合は何も残りません。 

| × | 貢献する約数 | 前の頻度 | 選ばれた | アクション |

 | 5..1 | なし | ゼロ化 | いいえ | スキップ |

 出力は6です。 

これは、すべての約数を最大の一貫した数の下にグループ化すると、総コストが最小化されることを示しています。

 ## 特殊なケース

 観測されたすべての数値が 1 の場合、微妙なエッジ ケースが発生します。アルゴリズムは最後に x=1 を処理し、freq[1] が正であることを確認し、1 を選択します。これは正しいです。約数セットに 1 が含まれる隠れた数値は少なくとも 1 でなければならないため、必要なグループごとに可能な最小合計は正確に 1 になります。 

もう 1 つのケースは、観測値に 2、3、5 などの素数のみが含まれる場合です。不必要な約数を導入せずにこれ以上の数が異なる素数を同時にカバーできないため、各素数は独立してそれ自体の選択をトリガーします。 アルゴリズムは 5、次に 3、次に 2 を正しく選択し、合計は 10 になります。 

より構造化されたケースは、1 と 6 を観察する場合です。6 を処理すると、まず 1 が自動的にカバーされ、アルゴリズムが 1 を個別に支払うことがなくなります。これは、下方処理とカバーされた約数を直ちにクリアすることが重要であることを示しています。そうしないと、1 が誤って追加の選択をトリガーします。
