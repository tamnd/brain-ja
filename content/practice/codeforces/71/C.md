 ## 解決策
 ## 問題の理解

 騎士たちは円を描いて等間隔に座ります。 各位置には次のいずれかがマークされます。`1`ご機嫌の騎士とか、`0`機嫌が悪い騎士のために。 少なくとも 3 つの頂点を持つ正多角形の頂点を形成するように、ご機嫌の良い騎士を選択できるかどうかを判断する必要があります。 

すべてのナイトは円の周りに等間隔に配置されているため、すべての正多角形は固定ステップ サイズで位置をとることに対応します。 たとえば、次の場合`n = 12`そして 3 人おきのナイトを選択すると、正方形の頂点が得られます。 2 番目ごとにナイトを選択すると、六角形が得られます。 

タスクは次のようになります。そのステップによって繰り返しジャンプするような、あるステップ サイズが存在するかどうか。`1`、そしてサイクルには少なくとも 3 つの異なる位置が含まれていますか?

 制約`n ≤ 10^5`三次時間に近いものはすぐに除外されます。 フルでも`O(n^2)`Codeforces 用の Python では、特に時間制限が非常に短い場合、このソリューションは危険です。 線形に近いものが必要です。`n log n`。 

微妙な点は、優れた騎士のすべてのサブセットが有効な多角形を形成するわけではないということです。 頂点は円の周りに等間隔に配置する必要があります。 不注意な解決策は、数を数えるだけかもしれません`1`が存在し、少なくとも 3 人の優れた騎士があれば十分であると結論付けています。 

考慮する：```
6
1 1 1 0 0 0
```正しい答えは、`NO`。 

優れた騎士が 3 人いますが、それらは連続しており、等間隔ではありません。 正多角形は作れません。 

ポリゴンがすべてのナイトを使用する場合、別の注意が必要なケースが発生します。```
5
1 1 1 1 1
```答えは`YES`。 

五角形全体はそれ自体が正多角形です。 の適切な約数をチェックするだけの実装`n`間違ってこれを見逃してしまいます。 

もう 1 つの特殊なケースには、小さすぎるサイクルが含まれます。```
4
1 0 1 0
```答えは`NO`。 

2 つおきのナイトを選択すると、頂点は 2 つだけ作成されます。多角形には少なくとも 3 つの点が含まれている必要があるため、これは有効な多角形ではありません。 

## アプローチ

 ブルートフォースのアイデアはジオメトリに直接従います。 あらゆる可能なポリゴン サイズに対して`k`、可能なすべての開始位置を試し、そのポリゴンのすべての頂点に次の要素が含まれているかどうかを確認します。`1`。 

ポリゴンが`k`頂点。 この場合、連続する頂点間のステップは次のようになります。`n / k`、 それで`k`分けなければなりません`n`。 各約数について`k ≥ 3`、すべてをテストできます`n`開始位置とサイクル全体を歩きます。 

これが機能するのは、等間隔の点上のすべての正多角形がこれらのサイクルの 1 つに正確に対応するためです。 

問題は走行時間です。 最悪の場合、多くの約数を調べ、それぞれの約数についてほぼすべてのポジションをスキャンする可能性があります。 単純な実装では次の方向に進む可能性があります。`O(n^2)`が遅すぎる`n = 10^5`。 

重要な観察は、実際にはポリゴンのサイズを直接気にしていないということです。 重要なのはジャンプ距離です。 

何か一歩ジャンプしたら`d`、訪問した位置は次のような長さのサイクルを形成します。$$\frac{n}{\gcd(n,d)}$$少なくともサイクルの長さだけを気にします`3`。 すべての有効な正多角形は、そのような 1 つのサイクルに対応します。 

次に約数を考えてみましょう`k`の`n`、 どこ`k ≥ 3`。 ポリゴンの頂点は正確に次のとおりです。$$i,\ i + \frac{n}{k},\ i + 2\frac{n}{k},\dots$$したがって、任意のサブセットをチェックする代わりに、次の約数をテストするだけで済みます。`n`。 

各約数について`k ≥ 3`、 させて：$$step = \frac{n}{k}$$次に、すべての剰余クラスのモジュロをテストします。`step`。 1 つの剰余クラス内のすべての要素が`1`、有効なポリゴンが見つかりました。 

各ポジションは限られた数の除数チェックのみに参加するため、全体の複雑さは効率的に保たれます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | 遅すぎる |
 | 最適 | O(n log n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 騎士の数とムード配列を読み取ります。 
2. すべての約数を列挙します`k`の`n`そのような`k ≥ 3`。 

正多角形`k`頂点は次の場合にのみ可能です`k`分割する`n`頂点は円の周囲に等間隔に配置されている必要があるためです。 
3. 有効なそれぞれについて`k`、次を計算します。```
step = n // k
```飛び越えて`step`あるポリゴンの頂点から次のポリゴンの頂点に移動します。 
4. 可能なすべての開始オフセットを試してください。`0`に`step - 1`。 

各オフセットは、等間隔の位置の 1 サイクルを表します。 
5. 固定オフセットの場合は、次のサイクルを実行します。```
offset, offset + step, offset + 2*step, ...
```モジュロ`n`。 
6. そのサイクル内のすべての位置に次のものが含まれているかどうかを確認します。`1`。 

1 つのサイクルでも完全に構成されている場合`1`s、印刷`YES`すぐに。 
7. すべての除数設定が失敗した場合は、次のように出力します。`NO`。 

### なぜ効果があるのか

 等間隔の円点上の正多角形は、一定の角距離で区切られた頂点を使用する必要があります。 ナイトは等間隔に配置されているため、これは固定インデックス ジャンプに直接変換されます。 

ポリゴンが`k`頂点の場合、連続する頂点は正確に異なります`n / k`ポジション。 アルゴリズムはすべての可能な約数をチェックします`k`そしてその間隔の可能なすべての開始位置。 

すべての有効な多角形はこれらのチェックのいずれかに表示され、チェックされたすべてのサイクルは有効な正多角形に対応します。 アルゴリズムは、サイクル内のすべての頂点に次の要素が含まれる場合にのみ受け入れられるため、`1`、誤検知が発生することはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    divisors = []

    d = 1
    while d * d <= n:
        if n % d == 0:
            if d >= 3:
                divisors.append(d)

            other = n // d
            if other != d and other >= 3:
                divisors.append(other)

        d += 1

    for k in divisors:
        step = n // k

        for start in range(step):
            ok = True

            for pos in range(start, n, step):
                if a[pos] == 0:
                    ok = False
                    break

            if ok:
                print("YES")
                return

    print("NO")

solve()
```最初の部分では、次のすべての約数を計算します。`n`それはポリゴンのサイズを表すことができます。 より小さい約数は無視します`3`頂点が 3 つ未満のポリゴンは無効であるためです。 

各約数について`k`、コードは次を使用してポリゴンの頂点間の間隔を導出します。`step = n // k`。 これは、ポリゴン構造から配列インデックスへの重要な幾何学的変換です。 

ネストされたループオーバー`start`同じポリゴン パターンのさまざまな回転を処理します。 たとえば、`step = 3`、で始まるシーケンス`0`、`1`、 そして`2`異なるサイクルです。 

最も内側のループは 1 つの完全なサイクルをチェックします。 使用する`range(start, n, step)`位置はモジュラー間隔を通じて円構造の周りを自然に包み込むため、これで十分です。 その剰余クラス内のすべての位置は、同じポリゴンに属します。 

早期の復帰はパフォーマンスにとって重要です。 有効なポリゴンが 1 つ見つかった時点で、それ以上の作業は必要ありません。 

よくある実装上の間違いは、約数をチェックすることです。`step`約数の代わりに`n`。 もう 1 つの簡単なバグは、ポリゴンがすべてを使用していることを忘れていることです。`n`頂点は有効です。

 ## 特殊なケース

 次の入力を考えてみましょう。```
6
1 1 1 0 0 0
```アルゴリズムは除数をチェックします`k = 3`、与える`step = 2`。 

サイクルは次のとおりです。```
0,2,4
1,3,5
```最初のサイクルには、`0`位置で`4`。 2 番目のサイクルには次の内容が含まれます`0`位置にある`3`そして`5`。 有効なポリゴンが存在しません。 

この事例は、アルゴリズムが単に十分な優れたナイトを必要とするのではなく、等間隔を必要とすることを検証します。 

次に、次のことを考えてみましょう。```
5
1 1 1 1 1
```除数`k = 5`生成する`step = 1`。 

唯一のサイクルは次のとおりです。```
0,1,2,3,4
```すべての位置には以下が含まれます`1`したがって、アルゴリズムは完全な五角形を正しく受け入れます。 

最後に、以下を調べます。```
4
1 0 1 0
```不注意な実装は受け入れられる可能性があります。`0`そして`2`等間隔に配置されています。 チェックされる除数のみが次のとおりであるため、アルゴリズムはこれを拒否します。`k ≥ 3`。 

のために`n = 4`、有効な約数は次のとおりです。`4`、生産`step = 1`。 すべてのポジションがそうではないので、`1`、答えは次のようになります`NO`。
