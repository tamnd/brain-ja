 ## 解決策
 ## 問題の理解

 各エッジが正または負のゼロ以外の重みを持つツリーが与えられます。 面白いのは、任意の 2 つのエッジを繰り返し選択してその重みを交換できるため、最終的には複数の重みセットをエッジ全体で任意に並べ替えることができることです。 

この再配置の後、少なくとも 1 つのエッジを使用するツリー内のすべての単純なパスを調べます。 パスが有効であるとみなされるのは、パスを通過するときに、連続するエッジの符号が正と負の間で厳密に交互になる場合のみです。 このようなパスの値は、そのエッジの重みの合計です。 すべての有効なパスの中で、可能な最大の合計に興味があり、最初にエッジの並べ替えを選択して、この可能な最良の値をできるだけ大きくしたいと考えています。 

重要な点は、固定されたツリーのラベル付けを最適化しているわけではないということです。 エッジに重みを割り当てる方法を最適化し、その後で最適な交互符号パスを検討します。 

制約は最大 200,000 ノードに達し、すべてのパスを明示的に試行したり、割り当てをシミュレートしたりするソリューションは即座に除外されます。 チェーンにはすでに O(n²) 個のサブパスがあるため、ツリー内のすべてのパスを列挙することさえ、最悪の場合は 2 次になります。 

ローカルで考えると微妙な問題が見えてきます。 グローバル構造を無視して、いくつかの「重要な」エッジに貪欲に大きな重みを割り当てようとすると、スワップによってグラフが完全に対称になることを見落とす可能性があります。重要なのは重みの複数セットのみであり、どのエッジが最初にどの重みを持っていたかは問題ではありません。 

もう 1 つのよくある落とし穴は、ツリー構造によって答えが大きく制約されると想定していることです。 スワップ後は、選択した任意のパスに沿って任意の重みのシーケンスを配置できるため、ツリーは可能な最大パス長を通じてのみ重要になります。 

単純ですが危険な例は、1 つの負の重みを除いてすべての重みが正である場合です。 単純な戦略ではネガティブを分離しようとするかもしれませんが、任意に再配置できるため、そのネガティブは選択したパスに沿ったどこにでも配置でき、どのパスが最適になるかを変更できます。 

## アプローチ

 ブルート フォースの観点では、エッジへの重みの割り当てを修正し、通常はすべての単純なパスを考慮して交互条件をチェックすることによって、ツリー内の最適な交互パスを計算します。 たとえ 1 つの割り当てを効率的に評価できたとしても、割り当ての数はエッジの数の因数分解となるため、すぐには実現できません。 

重要な観察は、スワップによって割り当ての問題がツリー構造から完全に独立したものになるということです。 パス内にいくつのエッジがあるか、そしてそれらのエッジにどのような重みを置くかだけを考慮します。 長さ k のパスが固定されると、ツリーはそのようなパスが存在しなければならないという制約のみに寄与します。つまり、k はツリーの直径を超えることができません。 

したがって、問題は 2 つの独立した部分に分かれます。 まず、ツリー内の最長の単純パスを決定します。これが、候補パスで使用できるエッジの最大数だからです。 次に、パスに沿って任意の k 個のエッジを選択できることを考慮して、マルチセットから重みを割り当てて、交互の合計を最大化します。 

固定長 k の場合、ソートの観点から考えると、最適な構成は直感的にわかります。 大きな正の値がプラスに寄与するようにし、大きな負の値が交互の要件によって強制される位置に配置されるようにします。 最善の戦略は、正の重みを降順にソートし、負の重みを絶対値で降順に並べ替え (同等に最も負の重みが最初)、パスに沿ってこれらのプールから交互に選択することです。 

ソートされた正を pos として、負を neg として表す場合、長さ k エッジのパスの場合、最適な値は、より良い選択から始めて、正の値のおよそ半分と負の値の半分を交互に取得することによって得られます。 これにより、プレフィックスの合計に基づく直接的な式が得られます。

最後に、木の直径までのすべての実現可能なパス長 k を評価し、最適な値を選択します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 割り当てとパスに対するブルート フォース | 指数関数 / O(n³) 以上 | O(n) | 遅すぎる |
 | 重み + 直径 + プレフィックス評価をソート | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 木の直径を計算します。 これにより、単純なパス内のエッジの最大数が得られます。 これは 2 回の DFS 実行で実行できます。最初に最も遠いノードを見つけ、次にそのノードから最も遠い距離を見つけます。 
2. すべてのエッジの重みを正と負の 2 つの配列に分割します。 陽性は降順に並べ替えられます。 負の値は、負の側の絶対値の最大の要因であるため、昇順 (最も負の値が最初) に並べ替えられます。 
3. 両方の配列の接頭辞の合計を作成して、上位要素の合計をすばやく計算できるようにします。 
4. 固定パス長 k (エッジの数) について、交互パターンに理想的に埋められる正の位置と負の位置の数を計算します。 正のエッジから開始する場合は、ceil(k/2) の正と Floor(k/2) の負を使用します。 負のエッジから始めると、役割が入れ替わります。 両方を評価し、最大値を採用します。 
5. k を 1 から min(直径、エッジの総数) まで繰り返し、プレフィックスの合計を使用して各 k に対して達成可能な最良の値を計算し、最大値を追跡します。 
6. すべての k にわたる最良の値を出力します。 

すべての k を評価することが安全である理由は、パスが長い方が必ずしも良いとは限らないためです。エッジを 1 つ追加すると、符号配置パターンが悪化する可能性があるため、パスが長くても、より短い長さで最適化が行われる可能性があります。 

### なぜ効果があるのか

 エッジの重みを任意に変更できるようになると、ツリー構造は単純なパスで連続して使用できるエッジの数を制限するだけになります。 交互符号条件は、選択されたパスに厳格なパターンを強制します。つまり、選択された重みの順序のみが重要になり、元の配置は問題になりません。 ソートにより、利用可能な最大の正の寄与が利用可能なスロットと常に一致することが保証され、直径制約により、ツリーが実現できるよりも長いパスが想定されることがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def diameter(n, adj):
    from collections import deque

    def bfs(start):
        dist = [-1] * (n + 1)
        q = deque([start])
        dist[start] = 0
        far = start

        while q:
            u = q.popleft()
            for v in adj[u]:
                if dist[v] == -1:
                    dist[v] = dist[u] + 1
                    q.append(v)
                    if dist[v] > dist[far]:
                        far = v
        return far, dist[far]

    far, _ = bfs(1)
    _, d = bfs(far)
    return d

def solve():
    n = int(input())
    adj = [[] for _ in range(n + 1)]

    pos = []
    neg = []

    for _ in range(n - 1):
        u, v, w = map(int, input().split())
        adj[u].append(v)
        adj[v].append(u)
        if w > 0:
            pos.append(w)
        else:
            neg.append(w)

    if n == 2:
        print(w)
        return

    d = diameter(n, adj)

    pos.sort(reverse=True)
    neg.sort()

    P = [0]
    for x in pos:
        P.append(P[-1] + x)

    N = [0]
    for x in neg:
        N.append(N[-1] + x)

    p = len(pos)
    q = len(neg)

    ans = -10**18

    maxk = min(d, p + q)

    for k in range(1, maxk + 1):
        a = (k + 1) // 2
        b = k // 2

        best = -10**18

        if a <= p and b <= q:
            best = max(best, P[a] + N[b])

        a2 = k // 2
        b2 = (k + 1) // 2
        if a2 <= p and b2 <= q:
            best = max(best, P[a2] + N[b2])

        ans = max(ans, best)

    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションは、ツリー処理を重みの最適化から分離します。 DFS ベースの直径計算は、重要な唯一の構造特性であるため、分離されています。 

実装の微妙な詳細の 1 つは、負のプレフィックス合計を正しく処理することです。 ネガは昇順に格納されるため (負の値が大きいほど)、拡張するにつれてプレフィックスの合計は負の値になります。これは、害の少ないネガを最初に選択するという目標と一致します。 

もう 1 つの重要な点は、パスには少なくとも 1 つのエッジが含まれている必要があるため、1 から始まる k の処理です。 計算では、交互シーケンスの考えられる両方の開始パリティが慎重に評価されます。 

## 実用的な例

 最初のサンプルを考えてみましょう。 

入力:```
6
1 2 3
2 -1
3 4
4 -1
4 -130
```重みを分割すると、正の値は [3, 2]、負の値は [-1, -1, -130] になります。 直径は 4 なので、k を 1 ～ 4 で評価します。 

k = 1 の場合、3 または -1 のいずれかを選択できますが、3 が最適です。 

k = 2 の場合、最良の交互合計は 3 + (-1) = 2 です。 

k = 3 の場合、最適な値は 3 + 2 + (-1) = 4 です。 

k = 4 の場合、より多くの負を強制するとゲインが減少します。 

| k | 使用済みのポス | 使用済みでない | 値 |
 | --- | --- | --- | --- |
 | 1 | 1 | 0 | 3 |
 | 2 | 1 | 1 | 2 |
 | 3 | 2 | 1 | 4 |
 | 4 | 2 | 2 | 1 |

 最大値は 4 です。 

これは、最適なソリューションは必ずしも可能な最長のパスではなく、利用可能な正の重みと負の重みの間の最適なバランスであることを示しています。

 ## 特殊なケース

 重要なエッジケースは、すべての重みが負の場合です。 その状況では、交互に追加のネガを含めることが強制されるため、最良の答えは単純に最も少ないネガの単一エッジになります。 k = 1 が常に考慮され、pos 寄与がゼロになり、最良の負のプレフィックスのみが残るため、アルゴリズムはこれを処理します。 

もう 1 つのケースは、ポジティブが存在するものの、長い交互パターンに必要な数よりも少ない場合です。 たとえば、負が多く、正が 1 つだけの場合、パスを拡張すると有害な負のプレフィックス和が蓄積されるため、たとえ直径が大きくても最適な k は小さくなります。 

最後の構造エッジ ケースは、直径が 2 の星型ツリーです。アルゴリズムは評価を正しく k ≤ 2 に制限し、ツリーがサポートできるよりも長いパスを構築しようとしないようにします。
