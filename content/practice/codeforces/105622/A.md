 ## 解決策
 ## 問題の理解

 ツリーが与えられます。これは、サイクルのない接続されたグラフを意味します。 タスクは、以前は接続されていなかった 2 つのノード間に新しいエッジを 1 つだけ追加することです。 このエッジを追加した後、サイクルが出現する必要があり、そのサイクルには少なくとも 3 つの異なるノードが含まれている必要があります。 

ツリーでは、ノードのペア間には単純なパスが 1 つだけ存在します。 2 つのノード u と v の間に追加のエッジを追加すると、そのエッジはそれらの間の一意のパスを閉じ、u と v の間のパス上のエッジの数に新しいエッジの 1 を加えたものとまったく同じ長さのサイクルを作成します。 したがって、u と v の間の元のパスに少なくとも 2 つのエッジが含まれている場合に限り、サイクル長は少なくとも 3 になります。つまり、ツリー内の u と v の間の距離が少なくとも 2 であることを意味します。 

入力は、n 個のノードと n − 1 個のエッジを持つツリー構造を表します。 出力は、ツリー内のエッジによって直接接続されていない有効なノードのペアです。そのようなペアでは、距離が少なくとも 2 であることが保証されます (そうでない場合、ノードは距離 1 で隣接します)。 このようなペアの間にエッジを追加すると、少なくとも 3 の長さのサイクルが作成されます。 

制約は非常に小さく、n は最大でも 100 です。これにより、線形または二次に近い作業を超えるものは即座に排除されますが、問題の構造はそれよりも単純です。非エッジ ペアを見つける必要があるだけです。 

木がスターである場合、微妙なエッジケースが現れます。 スターでは、多くのノードのペアがリーフであり、直接接続されていません。 たとえば、ノード 1 が他のすべてのノードに接続されている場合、どのリーフのペアも機能します。 次数 > 1 のノードのみを選択しようとしたり、長いパスが存在すると仮定したりする単純なアプローチは、実装が間違っていると失敗する可能性があります。これは、直径が 2 のままである可能性があるためです。 

もう 1 つの特殊なケースは、最小の有効なツリー n = 3 です。ツリーは常に長さ 2 のパスです。唯一の有効な追加エッジは 2 つの端点の間にあります。 誤ってリーフを回避したり、ローカルでのみ隣接性をチェックしたりすると、依然として正しい答えがエンドポイントであることを見逃しがちです。 

## アプローチ

 ブルートフォースの方法は、すべてのノードのペア (u、v) を試し、それらがエッジで接続されているかどうかを確認し、接続されていない場合は出力することです。 グラフには最大 100 個のノードがあるため、すべてのペアをチェックするのは最大 10,000 の組み合わせであり、各ペアについて、隣接行列またはノードごとのセットを使用して隣接性をテストできます。 これはすでに時間的に余裕があります。 

重要な観察は、非隣接ノードが常に機能するという事実以外に、実際には距離やサイクル構築を気にしていないということです。 したがって、問題は、間にエッジのない頂点のペアを見つけることになります。 これにより、問題はグラフ推論から単純な隣接性チェックに移ります。 

もう少し構造的な見方をすると、n ≥ 3 のツリーでは補グラフが空になることはなく、常に少なくとも 1 つの欠落エッジが存在することになります。 したがって、有効なペアが常に存在します。 これにより、単純なスキャンが成功することが保証されます。

 | --- | --- | --- | --- |
 | 隣接関係チェックによるすべてのペアのブルート フォース | O(n²) | O(n²) または O(n) | 承認済み |
 | 隣接セットを使用した最適なスキャン | O(n²) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. ツリーを読み取り、エッジの存在を高速にチェックできる構造に隣接情報を保存します。 ノードごとのセットまたはブール行列の両方が機能します。 決定はエッジが既に存在するかどうかのみに依存するため、これが必要になります。 
2. u < v であるノードのすべてのペア (u, v) を繰り返します。順序付けにより重複が回避され、出力が確定します。 
3. 各ペアについて、u と v がエッジによって直接接続されているかどうかを確認します。 接続されていない場合は、このペアをすぐに出力します。 
4. 最初の有効なペアが見つかった後に停止します。これは、そのようなペアは接続時に少なくとも 3 つの長さのサイクルを保証するためです。 
5. 隣接セットを使用して実装された場合、存在チェックは平均 O(1) であるため、スキャンは高速のままです。 

最初の有効なペアを選択する背後にある理由は、問題が最適化要件を課さず、存在のみを課すためです。 

### なぜ効果があるのか

 ツリーでは、ノードのペアは 1 つの単純なパスによって接続されます。 2 つのノード間にエッジを追加すると、そのパスと新しいエッジで構成されるサイクルが作成されます。 ノードが隣接している場合、そのパスの長さは 1 になり、サイクルの長さは 2 になりますが、これは無効です。 隣接していない場合、パスの長さは少なくとも 2 であるため、サイクル長は少なくとも 3 になります。少なくとも 3 つのノードを持つすべてのツリーには常に少なくとも 1 つの非エッジ ペアが含まれるため、検索は成功することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
adj = [set() for _ in range(n + 1)]

for _ in range(n - 1):
    u, v = map(int, input().split())
    adj[u].add(v)
    adj[v].add(u)

found = False

for u in range(1, n + 1):
    for v in range(u + 1, n + 1):
        if v not in adj[u]:
            print(u, v)
            found = True
            break
    if found:
        break
```隣接リストは、エッジの存在チェックを一定時間行うためにセットとして保存されます。 二重ループにより、最終的に非エッジ ペアに遭遇することが保証されます。 有効な回答は複数存在し、必要なのは 1 つだけであるため、早めの休憩が重要です。 

よくある実装上の間違いは、隣接関係にリストを使用し、次にメンバーシップをチェックすることです。`in`、最悪の場合、O(n³) に劣化します。 n ≤ 100 の場合でも合格する可能性はありますが、不必要なリスクとなります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from sys import stdout
    import sys

    input = sys.stdin.readline

    n = int(input())
    adj = [set() for _ in range(n + 1)]

    for _ in range(n - 1):
        u, v = map(int, input().split())
        adj[u].add(v)
        adj[v].add(u)

    for u in range(1, n + 1):
        for v in range(u + 1, n + 1):
            if v not in adj[u]:
                return f"{u} {v}"
    return ""

# sample 1
assert run("3\n1 2\n2 3\n") == "1 3"

# sample 2
assert run("4\n1 2\n1 3\n3 4\n") == "1 4"

# minimum case
assert run("3\n1 2\n2 3\n") in {"1 3", "3 1"} or run("3\n1 2\n2 3\n") == "1 3"

# star tree
assert run("5\n1 2\n1 3\n1 4\n1 5\n") != ""

# path tree
assert run("5\n1 2\n2 3\n3 4\n4 5\n") != ""
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 3 ノード パス | 1 3 | 有効な最小ケース、エンドポイント |
 | 4 ノードのサンプル ツリー | 1 4 | 分岐ツリーの正確性 |
 | スターツリー | 任意の非エッジ ペア | 密な隣接の場合 |
 | 5 のチェーン | 隣接しないペア | スキャンで深いペアが確実に見つかる |

 ## 特殊なケース

 星型ツリーでは、ノード 1 が他のすべてのノードに接続します。 アルゴリズムは (2, 3) のようなペアを早期にチェックし、エッジを検出せず、すぐに出力します。 これにより、高度な中心が正しさに影響を与えないことが確認されます。 

パス形状のツリーでは、隣接関係はローカルであるため、最初の隣接しないペアは通常、少なくとも 1 つの中間ノードによって分離されたエンドポイントまたはノードになります。 スキャンでは、(1, n) または別の有効なペアが自然に見つかります。 

最小のケース n = 3 では、唯一の非エッジ ペアはエンドポイントです。 ループは中間の隣接関係を正しくスキップし、正しい答えを返します。
