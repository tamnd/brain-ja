 ## 解決策
 ## 問題の理解

 いくつかのアイテムタイプが与えられています。 各タイプには供給量が限られているため、すべてのタイプの合計で正確に固定数のアイテムを選択する必要があります。 問題は、タイプからの利益がアイテムごとに一定ではないことです。 代わりに、同じタイプからすでに取得したアイテムの数によって決まります。 

これを解釈する便利な方法は、型から別の項目を取得するたびに、`i`、その値は、そのタイプからすでに選択されている項目の数に応じて直線的に増加します。 type の最初の項目を取ると`i`、それはある程度の基本ゲインを与え、2 番目はそれ以上、3 番目はさらに大きく、というように、そのタイプの利用可能な制限まで増加します。 合計利益は、すべてのタイプにわたって選択されたすべての限界利益の合計です。 

したがって、このタスクは正確に配布することと同じです。`m`横切る`n`シーケンスを増やし、タイプごとに 1 つのシーケンスを選択し、`m`利用可能な最大の限界寄与。 

入力により、タイプの数と必要なピック数が提供されます。 次に、長さの 2 つの配列が与えられます。`n`: 最初の配列は各タイプで利用可能なアイテムの数を表し、2 番目の配列はそのタイプの利益の成長率を表します。 出力は、達成可能な最大の総利益です。 

この制約は、両方のことを意味します。`n`そして`m`十分な大きさがあるため、考えられるすべてのアイテムの寄与を明示的に生成し、それらを並べ替えるのは安全ではありません。 単純な拡張では、すべてのタイプのアイテムの合計数まで生成される可能性がありますが、すべてをフラット化するとメモリと時間が大きすぎる可能性があります。 

素朴な考え方による微妙な失敗例は、あるタイプの成長率は非常に高いが項目が少ない場合、別のタイプの項目数は多いが成長率が低い場合に現れます。 たとえば、タイプ A に限界利得が高いアイテムが 2 つあり、タイプ B に限界利得がわずかに小さいアイテムが 1000 個ある場合、常に最初に B から取得するか、グローバル限界値ではなくタイプごとに貪欲に取得すると、次善の結果が得られます。 

主な問題点は、アイテムを追加するたびに、同じタイプ内の将来のアイテムの値が変わるため、タイプ内のローカルな決定は、すでに取得されているアイテムの数に依存することです。 

## アプローチ

 強引なアプローチでは、合計が以下になる有効な分布ごとに、各タイプから取得したアイテムの数を列挙しようとします。`m`。 ベクトルごとに`(x1, x2, ..., xn)`と`0 ≤ xi ≤ ai`そして合計額`m`、最初の値を合計して利益を計算します。`xi`それぞれのタイプの貢献。 このような分布の数は組み合わせになります。`m`そして`n`、おおよその作曲数と同じように増加します。`m`, これは、中程度の値であっても天文学的に大きくなります。 プルーニングを行ったとしても、各構成の評価にはすでにコストがかかるため、このアプローチは実行不可能です。`O(n)`。 

重要な観察は、各タイプの利益構造が限界利益によって完全に決定されるということです。 成長価値のあるタイプの場合`b_i`、その後、その寄与が一連の限界値を形成します`b_i * 1, b_i * 2, ..., b_i * a_i`。 ここで問題は、ソートされたシーケンスが複数あるので、最大のものを選択する必要があるということです。`m`それらすべてにわたる要素。 

これにより、問題は古典的な「増加する k 個のシーケンスをマージする」選択問題に変換されます。 すべてを生成するのではなく、各タイプから現在利用可能な最良の候補のみを維持し、最大値を繰り返し抽出して、そのタイプの次の候補を更新します。 これにより、各ステップで常にグローバルに最適な限界ゲインが選択されるようになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | m単位の指数 | O(n) | 遅すぎる |
 | 最適 (限界以上のヒープ) | O(m log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各タイプを限界利益のシーケンスとして再解釈します。ここで、k 番目の項目はタイプから取得されます。`i`貢献する`b_i * k`。 すべてのシーケンスを明示的に構築することはなく、各シーケンスの現在の「フロンティア」を追跡するだけです。 

1. 種類ごとに`i`、次のことを実現できるというアイデアから始めます。`a_i`アイテム。 最初に利用可能な最良の限界ゲインは、そのタイプの最後のゲインです。`b_i * a_i`。 これをタイプインデックスとともに候補として保存します。 
2. すべての初期候補を最大ヒープに挿入します。 各ヒープ要素は、型からの次に最適な未使用の限界ゲインを表します。 
3. 正確に繰り返します`m`回。 各反復で、現在利用可能な最大の限界ゲインを抽出します。 これは、すべてのタイプの中から可能な限り最適な次の項目を選択することに相当します。 
4. type から値を抽出したとします。`i`、そしてそれはその k 番目の項目を取得することに対応しました (暗黙的に追跡されます)。 使用後、タイプから次に利用可能な限界ゲイン`i`になる`b_i * (k - 1)`。 
5. この次の値がまだ正の場合 (そのタイプの項目をすべて使い尽くしていないことを意味します)、それをヒープに戻します。 これにより、タイプは残りの限界ゲインを降順で寄与し続けることが保証されます。 
6. 抽出された値を最終的な答えに累積します。 

重要な実装の詳細は、型ごとにすべての k 値を明示的に追跡することは決してないということです。 代わりに、残りの項目数を示すタイプごとのポインターを維持し、ヒープからポップするたびにその数をデクリメントします。 

### なぜ効果があるのか

 いつでも、ヒープには、あらゆる種類の未使用の最良の限界ゲインが正確に含まれています。 各タイプの限界ゲインは厳密に減少するシーケンスを形成するため、あるタイプから現在の最良のものを取得すると、同じタイプから次の最良のものは完全に決定され、より小さくなります。 限界ゲインはタイプ間で独立しており、そのタイプからすでに取得された項目の数にのみ依存するため、常にグローバル最大限界ゲインを取得するという貪欲な選択は有効です。 これにより、今後の選択が現在スキップする値を超えることができないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import heapq

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    # max heap using negative values
    heap = []
    
    # store current remaining count per type
    # and push initial best marginal gain b_i * a_i
    for i in range(n):
        if a[i] > 0:
            # store: (-value, type_index, current_k)
            heap.append((-b[i] * a[i], i, a[i]))

    heapq.heapify(heap)

    ans = 0

    for _ in range(m):
        val, i, k = heapq.heappop(heap)
        val = -val
        ans += val

        k -= 1
        if k > 0:
            heapq.heappush(heap, (-b[i] * k, i, k))

    print(ans)

if __name__ == "__main__":
    solve()
```実装では最大で次のヒープが維持されます。`n`現役候補者たち。 各エントリは、現在の残りのアイテム数を追跡します。`k`そのタイプの場合。 値をポップすると、すぐに同じタイプの次の限界ゲインに置き換えて、すべての中間値を保存せずにそのシーケンスの連続性を確保します。 

ここでよくある間違いは、完全なシーケンスを再計算または再生成することですが、これは不必要かつ遅すぎます。 もう 1 つの微妙な点は、Python の関数を使用して最大ヒープをシミュレートするためにヒープに負の値が格納されていることです。`heapq`。

## テストケース```python
import sys, io
import heapq

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    heap = []
    for i in range(n):
        if a[i] > 0:
            heap.append((-b[i] * a[i], i, a[i]))
    heapq.heapify(heap)

    ans = 0
    for _ in range(m):
        val, i, k = heapq.heappop(heap)
        val = -val
        ans += val
        k -= 1
        if k > 0:
            heapq.heappush(heap, (-b[i] * k, i, k))

    return str(ans)

 ## 特殊なケース

 特殊なケースは、あるタイプの可用性が非常に大きいものの、成長率が非常に小さい場合に発生します。 たとえば、次のようなタイプ`a = 100000`そして`b = 1`を持つタイプと競合します`a = 1`そして`b = 100000`。 最初の限界ゲインが最初のタイプからのその後のすべてのゲインを支配するため、正しい動作は常に 2 番目のタイプを最初に優先することです。 ヒープは、現在の限界ゲインをグローバルに常に比較することでこれを保証するため、単一の大きなスパイクは、低い値が蓄積される前に消費されます。 

もう一つのケースは次のような場合です。`m`種類数より少ないです。 そのような状況では、私たちは最高のものだけを選びます`m`どのタイプも使い果たすことなく、最初の候補を絞り込むことができます。 実行するだけなので、アルゴリズムはこれを自然に処理します。`m`ヒープがポップし、シーケンスが完全に消費されるとは決して想定されません。
