 ## 解決策
 ## 問題の理解

 単一の実行値に適用される操作の固定シーケンスが与えられています。 シーケンス内の各演算は、定数による加算、定数による減算、または定数による乗算の 3 つのタイプのいずれかです。 シーケンスは左から右の順に適用されます。 

シーケンスが定義された後、複数のクエリを受け取ります。 各クエリは開始値と範囲を指定します。$[l, r]$。 そのクエリでは、開始値を取得し、位置からの演算のみを適用します。$l$を通して$r$、順番に、最終結果を生成します。 すべての計算は、指定された数値を法として実行されます。 

微妙な点は、操作順序が厳密であることです。 乗算と加算は相互作用しますが、演算を任意に並べ替えたりグループ化したりすることはできません。 シーケンスは与えられたとおりに正確に尊重される必要があります。 

この制約は、操作とクエリの数が十分に大きいため、クエリごとに各操作を適用することが不可能な、標準的な競技プログラミング方式を意味します。 までを想定すると$10^5$操作と$10^5$クエリを実行すると、単純なシミュレーションには最大で$10^{10}$制限時間をはるかに超えた作戦。 これにより、高速範囲評価をサポートする前処理アプローチが強制されます。 

単純な実装では、特に負の値を生成する可能性のある減算でモジュラー演算で間違いが発生する危険性もあります。 もう 1 つのよくあるエッジ ケースは、低レベル言語で誤って処理された場合にモジュロを取得する前にオーバーフローを引き起こす大きな乗算ですが、Python ではこの問題が回避されます。 

より構造的なエッジケースは、順序付けルールを誤解していることです。 たとえば、与えられた操作$+2, \times 3, -1$から始まる$x$、結果は$((x + 2) \times 3) - 1$、 ない$x + 2 \times 3 - 1$。 順序を維持せずに操作をマージしようとすると、誤った結果が生成されます。 

## アプローチ

 ブルート フォースのアイデアは単純です。クエリごとに、初期値を取得し、クエリからのすべての操作を繰り返します。$l$に$r$、値を段階的に更新します。 これは定義を直接反映しているため、これは正しいです。 ただし、各クエリには最大で$O(n)$操作、および多くのクエリを使用すると、これは次のようになります$O(nq)$、大きすぎます。 

重要な点は、各操作が現在の値に対するアフィン変換であるということです。 加算と減算はシフト、乗算はスケーリングです。 すべての操作は次の形式で記述できます。$x \mapsto ax + b$。 このような変換の合成もアフィン関数です。 これは、操作シーケンスの任意のプレフィックスまたはセグメントを単一のペアとして表現できることを意味します。$(a, b)$セグメントを適用する$x$収量$ax + b$。 

問題は、乗算と加算が交換できないため、演算の順序を変更できないことですが、アフィン関数の合成では順序が正確に尊重されます。 プレフィックス変換を維持する場合、逆スタイルのセグメント変換を構成することで範囲クエリに答えることができます。$[l, r]$プレフィックスを組み合わせて得られます$r$プレフィックス付き$l-1$。 

これにより、線形前処理後の各クエリが一定数のモジュラー算術演算に削減されます。

 ## アルゴリズムのチュートリアル

 各操作を現在の値を変換するものとして解釈します$x$の中へ$x \cdot m + c$、ここで:

 演算が加算の場合$v$、 それから$m = 1$、$c = v$。 

引き算の場合$v$、 それから$m = 1$、$c = -v$。 

乗算の場合$v$、 それから$m = v$、$c = 0$。 

プレフィックス変換を維持します。 

1. 次のコマンドを使用してプレフィックス配列を初期化します。$A_0 = 1$、$B_0 = 0$、恒等変換を表す$x \mapsto x$。 このベースラインは、空のセグメントが正しく動作するために必要です。 
2. 各操作ごとに$i$、そのローカル変換を計算します$(m_i, c_i)$。 これは、その 1 つの操作が入力値にどのように作用するかを正確にエンコードします。 
3. 合成を使用してプレフィックス変換を更新します。$$A_i = A_{i-1} \cdot m_i$$

$$B_i = B_{i-1} \cdot m_i + c_i$$これはプレフィックスを適用しているため機能します$i-1$続いて操作$i$算術連結ではなく、関数の合成です。 
4. 質問に答えるため$(l, r, x)$、最初に接頭辞の変換を計算します$r$、マップします$x \mapsto A_r x + B_r$。 
5. プレフィックスの変換も必要です$l-1$、範囲の前の操作を表します。 
6. セグメントを分離するには$[l, r]$、接頭辞を「削除」します$l-1$逆モジュラーを使用すると、次のようになります。$$A_{l,r} = A_r \cdot A_{l-1}^{-1}$$

$$B_{l,r} = (B_r - B_{l-1}) \cdot A_{l-1}^{-1}$$このステップが機能するのは、アフィン変換が線形係数に基づいて乗算的に構成され、それに応じて変換が調整されるためです。 
7. セグメント変換を適用します。$x$:$$result = A_{l,r} \cdot x + B_{l,r}$$すべての操作はモジュロで取得されます$M$、および逆数は、次の場合にフェルマー スタイルのべき乗を使用して計算されます。$M$プライムです。 

### なぜ効果があるのか

 すべてのプレフィックスで$i$、ペア$(A_i, B_i)$最初の式を適用して得られる正確な関数を表します。$i$順番に操作を行います。 これは帰納法によって維持されます。各新しい演算は、以前の正しいアフィン関数を使用して正しいアフィン関数を構成し、アフィン関数の合成は閉じられます。 

範囲抽出ステップは、接頭辞関数が構成チェーンを形成するという事実に依存しています。 関数合成は線形係数の乗算に対応するため、逆モジュラーを使用してプレフィックス効果を分割することでセグメントを分離できます。 これにより、演算の順序を変更することはなく、代数的に因数分解するだけなので、順序が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def modinv(x):
    return pow(x, MOD - 2, MOD)

t = int(input())
for _ in range(t):
    n = int(input())
    
    op = [None] * (n + 1)
    val = [0] * (n + 1)

    for i in range(1, n + 1):
        op[i], val[i] = map(int, input().split())

    A = [1] * (n + 1)
    B = [0] * (n + 1)

    for i in range(1, n + 1):
        if op[i] == 1:
            m, c = 1, val[i]
        elif op[i] == 2:
            m, c = 1, -val[i]
        else:
            m, c = val[i], 0

        A[i] = (A[i - 1] * m) % MOD
        B[i] = (B[i - 1] * m + c) % MOD

    q = int(input())
    for _ in range(q):
        l, r, x = map(int, input().split())

        inv = modinv(A[l - 1])

        a = A[r] * inv % MOD
        b = (B[r] - B[l - 1]) * inv % MOD

        ans = (a * x + b) % MOD
        print(ans)
```実装の中核はプレフィックス アフィン表現です。 配列`A`そして`B`すべてのプレフィックスの変換を保存します。 各操作では、構成ルールを使用してこれらの配列を更新し、順序の正確さを維持します。 

クエリの処理は、事前にプレフィックス効果を削除するかどうかに依存します。`l`。 これは、モジュラー逆関数を使用して行われます。`A[l-1]`これは、乗算ステップが単一の係数に累積されるため有効です。 

計算時の引き算には注意が必要`B[r] - B[l-1]`モジュロ調整前にマイナスになる可能性があるためです。 Python は大きな整数を安全に処理しますが、それでもモジュロ演算によって暗黙的に正規化します。

import sys, io

MOD = 10**9 + 7

def solve():
    input = sys.stdin.readline
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        op = [0]*(n+1)
        val = [0]*(n+1)
        for i in range(1, n+1):
            op[i], val[i] = map(int, input().split())

        A = [1]*(n+1)
        B = [0]*(n+1)

        for i in range(1, n+1):
            if op[i]==1:
                m,c=1,val[i]
            elif op[i]==2:
                m,c=1,-val[i]
            else:
                m,c=val[i],0
            A[i]=(A[i-1]*m)%MOD
            B[i]=(B[i-1]*m+c)%MOD

        q=int(input())
        for _ in range(q):
            l,r,x=map(int,input().split())
            inv=pow(A[l-1],MOD-2,MOD)
            a=A[r]*inv%MOD
            b=(B[r]-B[l-1])*inv%MOD
            out.append(str((a*x+b)%MOD))
    print("\n".join(out))

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    return solve()

 ## 特殊なケース

 第 1 のエッジ ケースは、最初の操作から始まる範囲です。 この場合$l = 1$、 それで$A_{l-1} = A_0 = 1$。 逆のステップは簡単になり、除算の問題を回避できます。 アルゴリズムは完全なプレフィックスをセグメントとして正しく処理します。 

2 番目のエッジ ケースは、単一の操作で構成されるセグメントです。 それから$l = r$、プレフィックスの減算により 1 つのアフィン変換がきれいに分離されます。 たとえば、演算がゼロの乗算である場合、セグメントはすべての入力を正しくゼロに折りたたみます。$a = 0$そして$b = 0$。 

3 番目のエッジ ケースには、負の中間値を生成する減算が含まれます。 たとえば、変換により次のような結果が生成される場合があります。$B_r - B_{l-1} < 0$。 すべての演算が有限体で実行され、最終結果が剰余化されるため、モジュラー正規化ステップにより正確さが保証されます。$M$。
