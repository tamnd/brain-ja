 ## 解決策
 ## 問題の理解

 各テスト ケースには目標数値が与えられており、それが慎重に構築された整数とその桁の合計として表現できるかどうかを判断する必要があります。 より正確には、負でない整数を探しています。$x$その 10 進数の合計を計算し、それを加算し直すと、$x$、結果は指定された数値と等しくなります。 

そのような場合$x$存在する場合は、任意の有効な構造を使用できます。 この条件を満たす整数がない場合は、-1 を出力する必要があります。 

入力サイズは複数の独立したクエリを示唆しており、それぞれのクエリは検索ではなく迅速な決定を必要とします。 出力は算術特性のみではなく桁構造に依存するため、ターゲットが大きい場合、すべての候補値に対するブルートフォースは不可能です。 全部試してみる$x$まで$n$テスト ケースごとにすでに線形になっていますが、テスト ケースの合計が大きい場合はすぐに壊れます。 

逆に考えると、微妙なエッジケースが現れます。 多くの素朴な試みはターゲットから「桁の合計を減算」しようとしますが、桁の合計は数値自体に依存するため、任意の減算では有効性が維持されません。 

具体的な失敗例がこれを説明するのに役立ちます。 ターゲットが 1 であるとします。$x = 1$、 それから$x + S(x) = 1 + 1 = 2$、オーバーシュートします。 試しています$x = 0$与える$0 + 0 = 0$。 1 に到達する方法はないため、正しい出力は -1 です。 これは、すべての整数が表現できるわけではないことを示しています。 

もう 1 つの隠れた落とし穴は、すべての数値が桁の合計を任意に使用して形成できると想定していることです。これは誤りです。桁の合計は、数値の桁数とその最大寄与によって厳密に制限されるからです。 

## アプローチ

 ブルートフォース戦略では、考えられるすべての候補に対して反復処理が行われます。$x$0から目標値まで変化し、$x + S(x)$目標に等しい。 桁の合計を計算するには次の時間がかかります$O(\log x)$したがって、テストケースごとの合計コストは次のようになります。$O(n \log n)$最悪の場合。 もし$n$サイズが大きくなる可能性があるため、特に多数のクエリにわたって繰り返される場合には、非常に遅すぎます。 

重要な観察は、有効な数値は非常に厳格な構造を持っているということです。 方程式を整理し直すと$$x + S(x) = n,$$私たちはそれを見てます$n - x = S(x)$。 右側は桁の合計で、桁が制御された方法で最大化される場合、常に 9 の倍数の構造になります。 

建設的な洞察とは次のことを想定することです$x$9の繰り返しで構成されています。 もし$x$で構成されています$k$数字がすべて 9 に等しい場合、$$x = 10^k - 1, \quad S(x) = 9k.$$方程式に代入すると、$$n = (10^k - 1) + 9k = 10^k + 9k - 1.$$これは、すべての有効な回答が桁の長さの選択に対応することを意味します$k$、すべて 9 の数を構築し、それがターゲットと一致するかどうかを確認します。 すべての整数を検索するのではなく、狭い範囲のみをテストします。$k$の桁数によって制限されます。$n$。 

これにより、問題は値の検索から少数の構造化された候補のチェックに軽減されます。

 ## アルゴリズムのチュートリアル

 各テスト ケースについて、有効な数値はすべて 9 で構成されなければならないという事実を利用して、答えを再構築しようとします。 

1. ターゲット番号を読み取ります$n$。 これは、次を使用して照合する値です。$x + S(x)$。 
2. 可能な桁長を反復処理します。$k$、1 から始まり、18 や桁数などの適切な境界まで。$n$。 境界が大きいため、この境界で十分です$k$すでに一般的な制約を超える値が生成されています。 
3. 候補番号を作成する$x$からなる$k$すべて 9 に等しい数字。これは以下に相当します。$x = 10^k - 1$。 
4. 必要な式を計算します$x + S(x)$、 どこ$S(x) = 9k$すべての数字が 9 であるためです。 
5. この値が次の場合$n$、すぐに戻ります$x$有効な答えとして。 
6. の値がない場合は、$k$一致する場合は -1 を返します。 

### なぜ効果があるのか

 有効な解決策はすべて次の条件を満たす必要があります$n - x = S(x)$。 桁の合計は桁数に応じて直線的に増加しますが、数値自体は指数関数的に増加します。 これら 2 つの量を、どの桁の長さでも安定して予測可能な方法で同期し続けることができる唯一の方法は、桁が最大化され、すべて 9 の構造が強制される場合です。 これにより、解の空間が数え切れないほどの小さなファミリに制限されます。 このファミリーのすべての候補が直接テストされるため、有効な解が見逃されることはなく、無効な構築が誤って合格することもありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_one(n):
    # try k-digit all-9 numbers
    x = 0
    s = 0

    # we build 9, 99, 999... incrementally
    for k in range(1, 20):
        x = x * 10 + 9
        s = 9 * k
        if x + s == n:
            return x
    return -1

def main():
    t = int(input())
    for _ in range(t):
        n = int(input())
        print(solve_one(n))

if __name__ == "__main__":
    main()
```このソリューションでは、10 のべき乗を再計算するのではなく、9 の繰り返しで構成される数値の実行中の構成が維持されます。 反復ごとに桁の長さが 1 ずつ増加し、桁の合計は次のように分析的に更新されます。$9k$、桁ごとの計算を回避します。 

ループ境界は 20 で十分です。$10^{19}$すでに一般的な制約を超えており、それを超えると、構築された値が大きすぎて妥当な入力に一致しなくなります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    def solve():
        t = int(input())
        out = []
        for _ in range(t):
            n = int(input())
            found = False
            x = 0
            for k in range(1, 20):
                x = x * 10 + 9
                if x + 9 * k == n:
                    out.append(str(x))
                    found = True
                    break
            if not found:
                out.append("-1")
        return "\n".join(out)

    return solve()

# edge-like simple cases
assert run("3\n18\n117\n1\n") == "9\n99\n-1", "basic cases"
assert run("1\n18\n") == "9", "single valid k=1"
assert run("1\n19\n") == "-1", "no solution"
assert run("1\n117\n") == "99", "k=2 case"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |

 ## 特殊なケース

 1 のような小さな入力は、非常に低いターゲットに到達することが不可能であることを明らかにします。 アルゴリズムを実行すると、最初の候補は次のとおりです。$x = 9$、すでに 18 が生成されているため、これより小さい候補は存在せず、結果は正しく -1 になります。 

19 などの中程度の到達不能な数値の場合、アルゴリズムは以下をチェックします。$k=1$そして$k=2$、それぞれ 18 と 117 を生成しましたが、どちらも目標に一致しませんでした。 それ以上の構造体が存在しないため、出力は -1 のままです。 

117 のような有効な複数桁の数値の場合、反復回数は次のとおりです。$k=2$、構築します$x=99$、検証します$99 + 18 = 117$、値をさらに探索することなく、すぐに正しい答えが得られます。
