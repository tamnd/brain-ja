 ## 解決策
 ## 問題の理解

 ボードは、黒い石、白い石、空の交差点の 3 種類のマスを含むグリッドです。 直交して接する同じ色の石は、つながった 1 つのグループを形成します。 このようなグループごとに、グループ内の石に 4 つの基本方向で直接隣接する空のセルがいくつあるかを判断する必要があります。 これらの隣接する空のセルは自由を表しており、石ごとではなくグループごとに数えられます。 

タスクは、黒と白に分けて、接続されたグループの数が正確に 1 つの異なる自由セルを持っているかを計算することです。 

グリッド サイズは、二次走査を快適に行うのに十分な大きさです。 ボードの各次元が最大数千である場合でも、セルごとに一定量の作業を実行し、フラッド フィルを使用するソリューションは制限内に収まります。 これにより、到達可能性や隣接性を石ごとに繰り返し再計算するアイデアは除外されます。これは、密度の高いケースでは立体的な動作に向かう可能性があるためです。 

素朴だが重要な失敗モードは、グループごとではなく石ごとに自由を数えることから生まれます。 2 つの黒い石が並んでおり、その両方に隣接する 1 つの空のマスがあるとします。 石ごとに数えると、各石には 1 つの自由があると考えられ、両方が独立してアタリであると誤って結論付けることになります。 正しい解釈は、両方の石が、リバティ セットのサイズが 1 である 1 つのグループに属しているということです。 

同じ空のセルがグループ内の複数の石に触れた場合、別の微妙な問題が発生します。 隣接ごとに 1 回ではなく、1 回カウントする必要があります。 たとえば、1 つの空の中心を囲むプラスの形をしたグループには、4 つではなく 1 つの自由があります。 

## アプローチ

 ブルートフォースアプローチでは、すべての石を検査し、外側へのローカル検索を実行して、そのグループ内で接続されているすべての石を特定し、次に隣接する石を再度スキャンすることでその自由度を再計算します。 グループ内のすべての石が同じコンポーネントの完全な走査をトリガーするため、同じ作業がすぐに何度も繰り返されます。 ボードが完全に埋まってしまった最悪のケースでは、広い領域を繰り返し探索することになり、3 倍または 3 倍に近い数の操作が発生します。 

重要な観察は、グループがグリッド グラフ内の互いに素な連結コンポーネントであるということです。 コンポーネントを特定すると、自由セットを含む、コンポーネントに関するすべての必要な情報を 1 回だけ計算できます。 これは、同じ色のセルに対する標準的な塗りつぶしを示唆しており、その間に隣接するすべての空のセルをセットに蓄積します。 各セルは 1 回だけ処理され、各エッジは最大でも一定の回数検査されます。 

これにより、問題は補助集約を使用した接続コンポーネントのトラバースに変換されます。

 | --- | --- | --- | --- |
 | ブルートフォース | O(n²・k) 最悪の場合 | O(n²) | 遅すぎる |
 | 最適なフラッドフィル | O(n²) | O(n²) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. グリッド内のすべてのセルを走査します。 セルに石が含まれており、まだ訪問されていない場合は、それを新しい接続コンポーネントの開始点として扱います。 
2. 同じ色のセルに限定して幅優先検索または深さ優先検索を実行します。 訪問したすべての石にマークを付けて、二度と加工されないようにします。 これにより、各石が正確に 1 つのコンポーネント トラバースに属することが保証されます。 
3. コンポーネントを探索しているときに、隣接するセルが空の場合は常に、このコンポーネントに関連付けられたセットにその座標を記録します。 このセットは、複数の石から到達した同じ空の交差点が 1 回だけカウントされるようにするために必要です。 
4. トラバースが終了したら、収集された自由セットのサイズを確認します。 ちょうど 1 つの場合は、その石の色のカウンターをインクリメントします。 
5. すべてのセルが処理されるまで続行し、2 つのカウンターを出力します。

トラバースと自由のコレクションを明確に分離する理由は、自由は個々の石ではなく、接続された構造全体の特性であるためです。 ストーンごとのロジックを混合すると、作業の重複が再び発生します。 

### なぜ効果があるのか

 各洪水埋め立てでは、石の接続されたコンポーネントが 1 つだけ発見されます。 隣接関係は 4 方向であり、同じ色の展開に制限されているため、走査中にコンポーネントが誤って分割または結合されることはありません。 コンポーネントに隣接するすべての空のセルは、その境界石の 1 つを通じて少なくとも 1 回検出され、セットの使用により一意性が保証されます。 したがって、自由の最終セットはまさにグループの真の自由セットであり、「自由が 1 つだけ」という条件が分類に適しています。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    n = int(input().strip())
    grid = [list(input().strip()) for _ in range(n)]

    visited = [[False] * n for _ in range(n)]

    dirs = [(1, 0), (-1, 0), (0, 1), (0, -1)]

    black_atari = 0
    white_atari = 0

    def bfs(sr, sc):
        stack = [(sr, sc)]
        visited[sr][sc] = True
        color = grid[sr][sc]
        liberties = set()

        while stack:
            r, c = stack.pop()
            for dr, dc in dirs:
                nr, nc = r + dr, c + dc
                if nr < 0 or nr >= n or nc < 0 or nc >= n:
                    continue
                if grid[nr][nc] == 'E':
                    liberties.add((nr, nc))
                elif not visited[nr][nc] and grid[nr][nc] == color:
                    visited[nr][nc] = True
                    stack.append((nr, nc))

        return color, len(liberties)

    for i in range(n):
        for j in range(n):
            if grid[i][j] != 'E' and not visited[i][j]:
                color, lib_count = bfs(i, j)
                if lib_count == 1:
                    if color == 'B':
                        black_atari += 1
                    else:
                        white_atari += 1

    print(black_atari, white_atari)

if __name__ == "__main__":
    solve()
```この実装では、グローバル ビジット配列が保持されるため、各ストーンが 1 回処理されます。 大規模な接続領域でのスタック オーバーフローを回避するために、再帰の代わりにスタック ベースの DFS が使用されます。 

セット`liberties`複数の石が共有する空マスの二重カウントを防ぐ重要な構造です。 空のセルへの境界が見つかるたびに、その境界がセットに挿入され、重複は自動的に無視されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n²) | DFS では各セルが 1 回アクセスされ、各エッジが一定の回数チェックされます。 
| スペース | O(n²) | 訪問された配列と再帰スタック、および最悪の場合の自由セット |

 グリッドはそのサイズに比例して線形時間で移動され、各ストーンは正確に 1 つのコンポーネント探索に属します。これにより、ソリューションが制限内の最大ボード サイズを快適に処理できるようになります。

 ## 特殊なケース

 重要なエッジケースは、複数の石が同じ単一のリバティセルを共有する場合です。 この状況では、石ごとのアプローチではその自由度が誤って複数回カウントされてしまいますが、セットベースの集計により、それが 1 回カウントされることが保証されます。 たとえば、隣接する空のセルが 1 つある石の 2x2 ブロックでは、コンポーネント全体に対してサイズ 1 のリバティ セットが生成されます。 

もう 1 つのケースは、石がボードの境界線上にある場合です。 ボード内の空のセルのみがカウントされるため、境界外の位置を自由として扱ってはなりません。 DFS の境界チェックは無効な座標を明示的にスキップし、ファントムの自由を防ぎます。 

最後のケースは、隣接する空のセルがない孤立した石です。 これらは自由のないグループを表しており、アタリとして数えてはなりません。 リバティ セットは空のままであり、1 に正確に等しいサイズのみが受け入れられるため、アルゴリズムはこれを自然に処理します。
