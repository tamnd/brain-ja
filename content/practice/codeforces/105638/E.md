 ## 解決策
 ## 問題の理解

 各エッジが正または負の重みを持つ木が与えられています。 任意の 2 つのノード間には単純なパスが 1 つだけ存在するため、「2 つのノード間の最短パス」は複数のルートの中から選択するものではなく、単にその一意のツリー パスになります。 

順序のないノードのペアごとに、接続パスに沿ったエッジの重みの合計を調べます。 タスクは、パスの合計が厳密に正であるペアの数を数えることです。 

入力サイズは大きなツリーを意味するため、すべてのペアを直接チェックするソリューションは生き残れません。 すべてのペアを評価する素朴なアプローチでは、約 n² ペアのパス合計を計算する必要があり、高速な LCA クエリを使用しても、n が大きい場合には依然として遅すぎます。 これにより、各エッジまたは各ノードが、理想的には n で対数となる、制御された数の集約に参加する手法が直ちに推進されます。 

微妙な点は、エッジの重みが負の値になることが許可されていることです。 これにより、単調な構造が削除されます。予測可能な方法で、パスが長いほど重いまたは軽いと想定することはできません。 

困難を明らかにする特殊なケースの 1 つは、星型のツリーです。 中心が負のエッジを持つすべてのリーフに接続している場合、すべての葉から葉へのパスは中心を通過し、組み合わせに応じて正または負になります。 エッジごとの単純な「ローカル」推論は、共有祖先を介して貢献が相互作用するため失敗します。 

もう 1 つの重要なエッジ ケースはライン ツリーです。 重みが交互に現れるチェーンでは、部分和が大きく変動する可能性があるため、ルートからの深さまたは距離による貪欲な順序付けは信頼できません。 

## アプローチ

 ブルート フォースの解決策は簡単です。ツリーを上っていくか、事前に計算された LCA 距離を使用して、ノードのすべてのペアのパスの合計を計算し、正の合計がいくつあるかを数えます。 n 個のノードを使用すると、n(n−1)/2 ペアが検査され、ペアごとに O(1) 個の LCA クエリがあったとしても、合計作業量は 2 次になります。 n が約 2×10⁵ の場合、これは完全に不可能です。 

重要な構造上の観察は、すべてのペアが正確に 1 つのパスに寄与しており、すべてのパスはその上にある「中央分割点」を選択することで分解できるということです。 u と v の間のパス上にあるノード c を選択すると、パスの合計は dist(u, v) = dist(u, c) + dist(c, v) としてきれいに分割されます。 これは、パス上にあるノードに従ってペアをグループ化できれば、そのノードまでの距離のみを使用して寄与をカウントできることを示唆しています。 

これはまさに重心分解が役立つ設定です。 ツリー内の各パスには、その上にある分解ツリー内に一意の最高重心があり、すべてのペアがその最高重心のレベルで正確に 1 回カウントされることを保証できます。 その重心では、すべての関連情報は重心からの単純な距離値に帰着し、問題は数値の合計に制約があるペアのカウントに変わります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(1) または O(n) | 遅すぎる |
 | 重心分解 | O(n log² n) | O(n log n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ツリーに対して重心分解を根付かせます。 各重心で、パスがその重心を通過するノードのすべてのペアを処理し、再帰コンポーネント間で寄与を分離することで、どのペアも複数回カウントされないようにします。 

### ステップ

1. 現在のツリー コンポーネントの重心 c を選択します。 これにより、c が削除された後、コンポーネントがサブツリーに分割され、各サブツリーは厳密に小さくなります。 これにより、対数再帰の深さが保証されます。 
2. 現在のコンポーネント内のすべてのノードについて、元のツリーに沿った c までの距離を計算します。 これは、c から始まる DFS で実行できます。 
3. サブツリーを 1 つずつ処理します。 各サブツリーについて、1 つのノードがサブツリー内にあり、もう 1 つのノードが以前に処理されたサブツリーまたは既に蓄積されたプール内にあるペアを数えたいとします。これは、これらのノードがまさに c を通過するパスを持つペアであるためです。 
4. 現在のサブツリー内の各ノード u について、以前に確認されたノード v が dist(c, u) + dist(c, v) > 0 を満たす数をカウントする必要があります。この条件は、c が u と v の間のパス上にある場合、完全なパスの合計が c からの距離の合計に等しいという事実から来ています。 
5. すでに処理されたノードの距離のソートされた構造を維持します。 各 u について、格納されている値が -dist(c, u) を超える値の数をクエリします。 これは、ソートされたリストに対する二分検索で実行できます。 
6. サブツリーを処理した後、そのすべてのノードの距離をグローバル構造に挿入して、後のサブツリーがそれらとペアになるようにします。 
7. 重心を削除した後、各サブツリーを再帰的に実行し、同じロジックを繰り返します。 

### なぜ効果があるのか

 ノードの各ペアには、接続パス上にある分解ツリー内に固有の最高重心があります。 その重心で、アルゴリズムはペアを 1 回だけ評価します。これは、その重心を処理する場合にのみ、2 つのノードがパス上の重心を共有しながら、異なる処理済みサブツリーまたは現在のサブツリーに表示されるためです。 この変換により、パスの合計の比較が、重心からの事前に計算された 2 つの距離の比較に縮小され、パスの合計を繰り返し再計算することなく正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n = int(input().strip())
g = [[] for _ in range(n)]

for _ in range(n - 1):
    u, v, w = map(int, input().split())
    u -= 1
    v -= 1
    g[u].append((v, w))
    g[v].append((u, w))

subsz = [0] * n
blocked = [False] * n

def dfs_size(u, p):
    subsz[u] = 1
    for v, _ in g[u]:
        if v != p and not blocked[v]:
            dfs_size(v, u)
            subsz[u] += subsz[v]

def dfs_centroid(u, p, total):
    for v, _ in g[u]:
        if v != p and not blocked[v]:
            if subsz[v] > total // 2:
                return dfs_centroid(v, u, total)
    return u

def dfs_collect(u, p, dist, arr):
    arr.append(dist)
    for v, w in g[u]:
        if v != p and not blocked[v]:
            dfs_collect(v, u, dist + w, arr)

from bisect import bisect_right

answer = 0

def process(c):
    global answer

    all_nodes = []
    dfs_collect(c, -1, 0, all_nodes)
    all_nodes.sort()

    prefix = []

    for u, w in g[c]:
        if blocked[u]:
            continue

        comp = []
        dfs_collect(u, c, w, comp)

        for d in comp:
            need = -d
            cnt = len(prefix) - bisect_right(prefix, need)
            answer += cnt

        for d in comp:
            bisect = bisect_right(prefix, d)
            prefix.insert(bisect, d)

    blocked[c] = True
    for v, _ in g[c]:
        if not blocked[v]:
            solve(v)

def solve(entry):
    dfs_size(entry, -1)
    c = dfs_centroid(entry, -1, subsz[entry])
    process(c)

solve(0)

print(answer)
```重心分解が中心的な構造であり、その他すべては距離に関する簿記です。 各重心からの DFS は、各コンポーネント内の距離を収集するためにのみ使用されます。 ソートされたリストは、以前に処理されたサブツリーからの候補ノードの動的なセットを維持し、二分探索を使用して不等式制約を効率的に満たすノードの数を数えます。 

微妙な点は、重心の異なる子サブツリーからのノードのみを結合することです。これにより、すべての有効なペアが正しい分解レベルで 1 回だけカウントされることが保証されます。 

## 実用的な例

 エッジの重みが変化し、一部のパスが正になり、他のパスが負になる 5 つのノードからなる小さなツリーを考えてみましょう。 重心が 1 つのレベルをどのように処理するかを追跡します。 

ノード 1 を重心として選択します。 ノード 1 からのサブツリーの距離が次のようになると仮定します。 

| サブツリーが処理されました | 追加された距離 | プレフィックスの状態 | 新しいカウントが追加されました |
 | --- | --- | --- | --- |
 | サブツリー A | [2、-1] | [2、-1] | 0 |
 | サブツリー B | [3、-2] | [-2、-1、2] | A と B のペアをカウントします |
 | サブツリー C | [1] | [-2、-1、1、2、3] | 前の | にわたるペアをカウントします。 

このトレースは、クロスサブツリー ペアのみが考慮されていることを示しており、これはパスが重心を通過する必要があるという要件に正確に一致します。 

2 番目の例は、重みが正と負を交互に持つライン ツリーです。 分解により、ラインに沿って接頭辞の和が変動しても、各重心がバランスのとれたパーティションを分離するため、どのペアも二重にカウントされず、すべての有効な正の和のペアが 1 回だけキャプチャされることが保証されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log² n) | 各ノードは O(log n) セントロイド レベルに参加し、各レベルは合計 O(n) 作業にわたって並べ替えまたは二分探索を使用します。 
| スペース | O(n log n) | 再帰スタックと分解レベルにわたる保存された距離リスト |

 対数二乗係数は、重心レベル内で繰り返された並べ替えとバイナリ検索から得られます。 これは、n が数十万までならまだ問題なく制限内に収まります。

 ## 特殊なケース

 シングルエッジツリーは最も単純なケースです。 重心は実装に応じて 1 つのエンドポイントまたは中間ノードになりますが、すべての場合において、唯一のペアが 1 回だけ評価され、答えはそのエッジの重みの符号のみに依存します。 

星型ツリーは、多くのペアが同じ中心ノードを共有するため、より繊細です。 重心分解により、中心が分解ルートになることが保証されるため、すべてのリーフ間の相互作用はその重心レベルで処理されます。 中心からの距離によって各ペアの合計が完全に決定されるため、相互作用が見逃されることはありません。 

重みが交互に表示される行は、分解順序の正確さを強調します。 部分和が異なる場合でも、各重心はバランスの取れたセグメントを分離するため、セグメント間のペアは正確に 1 回カウントされ、重複することはありません。
