 ## 解決策
 ## 問題の理解

 整数の配列が与えられ、その要素が元の配列のサブシーケンスとして現れる連続したサブ配列の数を **正確に 1 回**カウントするように求められます。 簡単に言うと、要素を再配置せずに配列内の他の場所で部分配列を見つけようとするときに、それらの位置を選択する方法が 1 つしかない場合、部分配列は適切です。 例えば、`[1, 2]`で`[1, 2, 1]`シーケンスなので良いです`1, 2`最初の 2 つの位置にのみ表示されます。 しかし`[1]`それは悪いので`1`は複数回発生するため、サブシーケンスとして選択する方法は複数あります。 

入力は複数のテスト ケースで構成されます。 各テスト ケースには最大の配列があります。`10^5`要素、すべての合計`n`テストケース全体で最大`2*10^5`。 これにより、どのような解法もおおよそよりも遅いことがすぐにわかります。`O(n log n)`テストケースごとに実行すると遅すぎます。 すべてのサブ配列を列挙する素朴なアプローチは次のようになります。`O(n^2)`テストケースごとに、これは明らかに実行不可能です。 

エッジ ケースは、すべての要素が同一である場合、サイズ 1 の配列、または値が繰り返し切り替わる配列の場合に発生します。 例えば、`[1, 1, 1]`単一の要素が許可されている場合、長さ 1 の有効なサブ配列は 1 つだけありますが、それより長いサブ配列はすべて無効です。`[1, 2, 1]`サブ配列があります`[1, 2]`、`[2, 1]`、`[1, 2, 1]`それは異なる動作をします。 重複はサブシーケンスが一意であるかどうかを制御するため、重複を慎重に処理することが重要です。 

## アプローチ

 ブルートフォースアプローチは、考えられるすべてのサブ配列を反復処理し、各サブ配列について、それがサブシーケンスとして何回発生するかをチェックすることです。 単純にサブシーケンスをチェックすると`O(n)`各サブ配列の時間、`O(n^2)`サブ配列なので、全体的な複雑さは次のようになります。`O(n^3)`テストケースごとに。 これは明らかに機能しません`n`まで`10^5`。 

The key insight is that a subarray`[a_l, ..., a_r]`**サブ配列内の要素が現在の位置以外の場所で矛盾する順序で出現する場合**、サブシーケンスとして複数回発生します。 これを正確に行うために、各値について、配列内の最初と最後の出現を追跡できます。 サブ配列は、そのすべての要素が **配列全体の中でその位置の外側に 1 回だけ出現する**場合、サブシーケンスとして一意です。 これを考えるもう 1 つの方法は、ウィンドウ内の要素が同じ領域または重複する領域内で別の要素を持たないようにスライディング ウィンドウを維持することです。 これにより、問題は 2 ポインタの問題に縮小され、ウィンドウ内の各要素が最大 2 回表示されるようにしながら、右側の境界を拡張します。1 回はウィンドウ内に、もう 1 回はおそらく外側に表示されます。 

適切な観察は、「悪い」要素とは、最初または最後に出現する要素が現在のウィンドウの内側にあるだけでなく、外側でも出現する要素であるということです。 2 つのマップを使用して最初と最後の出現を追跡し、左ポインタを移動して競合を除外することで、有効なウィンドウの数を効率的にカウントできます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n3) | O(n) | 遅すぎる |
 | 最適なツーポインタ | テスト ケースあたり O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. まず、配列内の各一意の値について、最初と最後の出現のインデックスを事前計算します。 これにより、候補部分配列内の要素が他の場所で競合する位置に出現するかどうかを迅速に確認できます。 
2. 左ポインタを初期化する`l`0 で右ポインタを反復します`r`0からn-1まで。 有効なサブ配列を効果的に維持しようとしています`[l, r]`ここで、すべての要素は複数のサブシーケンスを作成しない位置に出現します。 
3. 現在のウィンドウに各要素が表示される回数をカウントするマップを維持します。 すでにウィンドウ内に表示されている要素、または一意性制約に違反している要素を含めようとする場合は、左ポインタを移動します。`l`条件が再び満たされるまでウィンドウを縮小します。 
4. それぞれのポジションについて`r`、で終わる有効なサブ配列の数`r`は`(r - l + 1)`。 この数を合計に加えます。 これは拡張するため機能します`r`1 つ分には、で終わるすべての新しいサブ配列が含まれます。`r`左側の端点が異なります。 
5. まで続けます`r`配列の最後に到達します。 

不変条件は、すべてのステップで、`[l, r]`**で終わる最大の部分配列です`r`これはサブシーケンス**として一意であるため、その中のすべてのサブ配列をカウントすることで、すべての正常なサブ配列を正確に 1 回カウントすることができます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        last_occurrence = {}
        left = 0
        result = 0
        count = {}
        
        for right in range(n):
            val = a[right]
            count[val] = count.get(val, 0) + 1
            while count[val] > 1:
                count[a[left]] -= 1
                left += 1
            result += right - left + 1
        
        print(result)

solve()
```私たちは辞書を使います`count`現在のウィンドウ内の発生を追跡します。 ウィンドウ内で複製に遭遇するたびに、私たちは移動します`left`ウィンドウが有効になるまで。 それぞれで終わるサブ配列の数`right`単にウィンドウの長さです`right - left + 1`。 

境界の処理は微妙です。ウィンドウが左から縮小し始めた場合、off-by-one エラーを避けるためにカウントを慎重に減分する必要があります。
