 ## 解決策
 ## 問題の理解

 数字が円の中に配置されているデバイスでは、4 桁の PIN を入力するように求められます。`0`に`9`。 カーソルは次から始まります`1`。 毎秒、現在の桁を押すか、カーソルを隣接する桁に移動します。 ある数字から直接隣接していない別の数字に移動するには、円内を時計回りまたは反時計回りのいずれかの方向に連続的に移動する必要があります。 

入力は複数のテスト ケースで構成され、それぞれが PIN を表す 4 桁の文字列を提供します。 出力は、各テスト ケースの PIN の入力に必要な最小秒数です。 課題は、円形キーパッドの周りを移動するとショートカットができることです。`0`に`9`他の桁をすべて移動するのではなく、1 秒しかかかりません。 

制約は寛大です: まで`10^4`テスト ケースには 4 桁の PIN が含まれています。 これは、操作の合計数が 40,000 に達する可能性があり、これはわずかであるため、ソリューションは非常に高速である必要があり、理想的にはテスト ケースごとに O(1) である必要があることを意味します。 エッジケースには、円形の境界を越える移動が含まれます。`0`に`9`、および繰り返される数字、例:`1111`、動きを最小限に抑える必要があります。 

不注意なアプローチでは、円形の隣接性を考慮せずに動きを線形に計算する可能性があります。 たとえば、からの移動`0`に`9`単純に、1手ではなく9手と数えてしまうかもしれません。 

## アプローチ

 強引なアプローチでは、押下と移動を 1 秒ごとにシミュレートすることになります。 PIN の各桁について、カーソルを一度に 1 ステップずつ段階的に移動させ、秒数を数え、目標に達したら押します。 これは正しいですが、2 つの数字の間の距離は円上の位置によって完全に決まるため、やりすぎです。 段階的なシミュレーションは必要ありません。 

重要な洞察は、円形キーパッドの 2 つの数字の間の距離は次のとおりであるということです。`min(abs(a-b), 10-abs(a-b))`。 これにより、時計回りと反時計回りのパスが測定され、短い方のパスが選択されます。 距離がわかったら、数字を押すのに常に 1 秒かかります。 したがって、長さが 4 の PIN の場合、合計時間は、押すごとに 1 に、連続する数字間の最小距離の合計を加えたものになります。`1`。 

これにより、問題が各テスト ケースの単純な算術計算に変換され、循環シーケンス上のループが排除され、テスト ケースごとの解が O(1) になります。

 ## アルゴリズムのチュートリアル

 1. 桁のカーソルを初期化します。`1`。 
2.各桁ごとに`d`PIN 文字列で、最小円周距離を計算します。`d`使用して`min(abs(d - current), 10 - abs(d - current))`。 これは時計回りまたは反時計回りの移動を表します。 
3. 計算された距離を合計時間に加算します。 
4. 数字を押すために 1 秒を追加します。 
5. カーソルを`d`(現在位置を更新)。 
6. PIN のすべての桁についてこの手順を繰り返します。 
7. テスト ケースの合計秒数を返します。 

機能する理由: 円形距離の計算により、常に桁間の最短経路が確保されます。 数字を入力するという必須アクションを考慮して、押す時間を 1 秒追加します。 アルゴリズムは、PIN を順番に繰り返すことで、各動作を個別にシミュレートすることなく、合計時間が最小限に抑えられることを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    pin = input().strip()
    current = 1
    total = 0
    for ch in pin:
        target = int(ch)
        move = min(abs(target - current), 10 - abs(target - current))
        total += move + 1
        current = target
    print(total)
```このソリューションはテスト ケースの数を読み取り、各 PIN に対して反復処理を行います。 数字ごとに円形の距離を計算し、押すと 1 を加算して、カーソルを更新します。 使用する`min(abs(...), 10-abs(...))`のような難しいトランジションを含む円運動を自動的に処理します。`0`に`9`。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    t = int(input())
    results = []
    for _ in range(t):
        pin = input().strip()
        current = 1
        total = 0
        for ch in pin:
            target = int(ch)
            move = min(abs(target - current), 10 - abs(target - current))
            total += move + 1
            current = target
        results.append(str(total))
    return "\n".join(results)

 ## 特殊なケース

 円形の境界の場合、PIN`0`で開始した後`1`:

 - 1 から開始 → 0 に移動: 距離 = min(|0-1|, 10-1)=1
 - 押す：+1 → 合計 2
 - 次の桁 0 → 0 ステップ移動 → 押す → 合計 +1 = 3

 このアルゴリズムは、9 歩を数えるのではなく、この最小限の動きを正確に考慮します。 数字の繰り返し。例:`1111`、結果は 4 回押して移動せず、合計 4 となり、これは正しいです。
