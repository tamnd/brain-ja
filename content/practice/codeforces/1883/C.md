 ## 問題の理解

 配列と小さな整数が与えられます$k$、 どこ$2 \le k \le 5$。 1 回の操作で任意の要素を選択し、それを 1 つ増やすことができます。 ここでのタスクは、すべての配列要素の積が次で割り切れるように必要な演算の最小数を見つけることです。$k$。 

重要な観察は、私たちは正確な製品を決して気にしていないということです。 私たちが気にするのは、製品に必要な主要な要素が含まれているかどうかだけです。$k$。 以来$k$せいぜい$5$の可能な値は 4 つだけです。$k$:$2$、$3$、$4$、 そして$5$。 これにより、問題は最初に見えたよりもはるかに小さくなります。 

すべてのテスト ケースにわたる配列要素の合計数は最大で$2 \cdot 10^5$。 各要素を一定の回数だけ検査するソリューションは、簡単に十分に高速です。 大規模な状態にわたる動的プログラミングや操作の繰り返しシミュレーションを伴うアプローチは不要です。 

微妙なエッジケースが現れるのは、$k=4$。 による割り算$4$による割り算とは異なります$2$、積には次の 2 つの要素が含まれている必要があるため、$2$。 例えば：```
n = 2, k = 4
a = [1, 3]
```1 つの要素を次の 4 の倍数に増やすには、1 回の操作が必要です。```
[1, 4]
```答えは$1$。 偶数のみをカウントするソリューションでは、この可能性が失われます。 

もう 1 つの重要なケースは、いくつかの要素が一緒に 2 の係数に寄与する可能性がある場合です。```

a = [1, 5, 9]
```1 つの数値を 4 つのコストで割り切れるようにする$3$操作:```

```ただし、2 つの数字を偶数にするのはコストだけです$2$操作:```

```この積には 2 の 2 つの因数が含まれるため、正解は次のようになります。$2$。 

最後のエッジケースは、積が既に次の値で割り切れる場合に発生します。$k$。 例えば：```
n = 4, k = 5
a = [5, 4, 1, 2]
```答えは$0$。 どのアルゴリズムでも、さらなる計算を実行する前にこれをチェックする必要があります。

 ## アルゴリズムのチュートリアル

 1. 配列を読み取ります。 
2. 現在の積の割り算を間接的に計算します。 

すべての要素について、剰余モジュロを確認します。$k$。 一部の要素がすでに割り切れる場合$k$そして$k \in \{2,3,5\}$、答えはすぐにわかります$0$。 
3. もし$k$は$2$、$3$、 または$5$、計算する$$\min_i (k - a_i \bmod k) \bmod k.$$これは、要素を次の倍数に移動するためのコストです。$k$。 

1. もし$k=4$、まず、ある要素を次の要素で割り切れるようにするための最小コストを計算します。$4$:$$\min_i (4 - a_i \bmod 4) \bmod 4.$$1. 配列内の 2 つの現在の因数を数えます。 

各要素について:

 - で割り切れる場合$4$、 貢献する$2$。 
- 偶数の場合は貢献します$1$。 
- それ以外の場合は貢献する$0$。 
2. 2 つの因数の合計がすでに少なくとも$2$、答えは$0$。 
3. それ以外の場合は、2 の因数がさらに何個必要かを決定します。 
4. 要素を均一にするコストを計算します。 奇数要素の場合、コストは次のとおりです。$1$。 偶数要素の場合、コストは次のようになります。$0$。 
5. これらのコストを並べ替え、不足している 2 つの因数を取得するために必要な最小数の要素を取得します。 
6. 最終的な答えは、次の間の最小値です。 

- 1 つの要素を次の要素で割り切れるようにする$4$。 
- 複数の要素から 2 の因数を十分に収集します。 

### なぜ効果があるのか

 のために$k=2$、$3$、 そして$5$、積の割り算には、対応する素数の 1 つの因数だけが必要です。 で割り切れる単一の要素$k$十分であり必要です。 

のために$k=4$、積には 2 の因数が少なくとも 2 つ含まれている必要があります。 すべての有効な構成は、4 で割り切れる 1 つの要素、または結合した寄与が 2 の 2 倍に達する複数の偶数要素を通じてこれを実現します。 アルゴリズムは両方の可能性を明示的に評価し、安価な方を選択します。 すべての操作は要素を増やすだけなので、必要な割り算条件を取得する最も安価な方法は常に、要素を最も近い適格な値に移動することです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())

for _ in range(t):
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    if k in (2, 3, 5):
        ans = min((k - x % k) % k for x in a)
        print(ans)
        continue

    # k == 4
    ans = min((4 - x % 4) % 4 for x in a)

    twos = 0
    for x in a:
        if x % 4 == 0:
            twos += 2
        elif x % 2 == 0:
            twos += 1

    if twos >= 2:
        ans = 0
    else:
        costs = []
        for x in a:
            costs.append(x % 2)

        costs.sort()

        need = 2 - twos
        ans = min(ans, sum(costs[:need]))

    print(ans)
```解決策は簡単なケースを区別する$k=2$、$3$、 そして$5$専用ケースから$k=4$。 

のために$k=2$、$3$、 そして$5$、最も近い複数のみが重要です。 表現$$(k - x \bmod k) \bmod k$$次の場合にゼロを返します$x$はすでに割り切れます$k$それ以外の場合は、必要な正確な増分数を返します。 

のために$k=4$、最初の候補の答えは、1 つの要素を 4 で割り切れるようにするコストです。 次に、コードは配列内にすでに存在する 2 の因数をカウントします。 少なくとも 2 つが利用可能な場合、その積はすでに 4 で割り切れます。 

それ以外の場合、コードは奇数の要素を偶数にすることを考慮します。 奇数の要素には 1 回の操作が必要ですが、偶数の要素には操作は必要ありません。 これらのコストを並べ替えると、不足している 2 つの因数を取得するために必要な最も安価な要素を選択できます。 

積自体は計算されないため、整数オーバーフローの問題は発生しません。

## テストケース```python
import sys
import io

def solve():
    input = sys.stdin.readline

    t = int(input())
    out = []

    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))

        if k in (2, 3, 5):
            out.append(str(min((k - x % k) % k for x in a)))
            continue

        ans = min((4 - x % 4) % 4 for x in a)

        twos = 0
        for x in a:
            if x % 4 == 0:
                twos += 2
            elif x % 2 == 0:
                twos += 1

        if twos >= 2:
            ans = 0
        else:
            costs = sorted(x % 2 for x in a)
            ans = min(ans, sum(costs[:2 - twos]))

        out.append(str(ans))

    return "\n".join(out)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    return solve()

assert run("1\n2 5\n7 3\n") == "2"
assert run("1\n5 5\n5 4 1 2 3\n") == "0"
assert run("1\n3 4\n1 5 9\n") == "2"
assert run("1\n3 4\n6 3 6\n") == "1"
assert run("1\n2 2\n1 1\n") == "1"
assert run("1\n2 5\n10 10\n") == "0"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`2 5 / 7 3`|`2`| 基本的な最近接複数ロジック |
 |`5 5 / 5 4 1 2 3`|`0`| すでに割り切れる |
 |`3 4 / 1 5 9`|`2`| 2 つの偶数が 4 の倍数に勝つ |
 |`3 4 / 6 3 6`|`1`| 既存の係数 2 に増分 1 を加えた値 |
