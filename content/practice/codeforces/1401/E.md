 ## 解決策
 ## 問題の理解

 いくつかの水平線分と垂直線分を描いた後、大きな正方形が何個の部分に分割されるかを計算するように求められます。 正方形のサイズは固定されています$10^6 \times 10^6$、セグメントは部分的または完全に正方形を横切ることができますが、常にそのエッジの少なくとも 1 つと交差します。 水平セグメントは y 座標と x 範囲で指定され、垂直セグメントは x 座標と y 範囲で指定されます。 2 つのセグメントが同じ線上に存在することはありません。 

出力は、すべてのセグメントを追加した後に正方形内に残る接続領域の数を表す単一の整数です。 概念的には、各セグメントはその線に沿って既存の領域を 2 つに分割できる可能性があります。 水平セグメントは領域を水平に分割します。 垂直セグメントは領域を垂直に分割します。 セグメント間の交差により、結果として得られる部分の数が増加します。 

制約は、両方のことを示します。$n$そして$m$まで可能です$10^5$。 ブルートフォースグリッドベースのソリューションには、少なくとも次のものが必要です。$10^{12}$正方形のすべての点をマークしようとすると、2 秒では明らかに不可能です。 したがって、正方形のすべての単位を反復するアプローチは避けなければなりません。 代わりに、ソリューションではセグメント自体とその交差部分のみを処理する必要があります。 

主なエッジ ケースは、セグメントが正方形の幅または高さ全体に及ばないが、辺に接触している場合です。 たとえば、次の水平セグメントは、$(0,2)$に$(4,2)$で$10^6 \times 10^6$正方形は、たとえ向こう側に到達しなくても、ピースの分割にカウントされます。 単純なアプローチでは、軸を完全に超えていないセグメントが無視され、アンダーカウントが生成される可能性があります。 もう 1 つの注意が必要なケースは、異なる軸でセグメントが重なっている場合です。 垂直セグメントと水平セグメントが交差する場合、その交差部分によって新しいピースが作成されます。 交差を無視すると、ピースの総数が過小評価されてしまいます。 

## アプローチ

 強引な方法は単純です。正方形を表す 2D 配列を想像し、その上のすべての水平および垂直セグメントをマークします。 次に、フラッド フィルを実行して、接続された領域をカウントします。 これが機能するのは、マーキングと接続性がピースの数に直接対応しているためです。 問題は、$10^6 \times 10^6$セルは不可能であり、それを反復することは許容範囲をはるかに超えています$2\cdot 10^9$1秒あたりの操作数。 したがって、総当たりアプローチはメモリと時間の制約により失敗します。 

最適なアプローチは、完全な正方形を表す必要がないという観察を活用します。 必要なのはセグメントとその交差部分だけです。 各水平セグメントは、それが交差するすべての垂直領域を切断すると考えることができ、各垂直セグメントは、それが交差するすべての水平領域を切断すると考えることができます。 交差を注意深くカウントすると、組み合わせ引数を使用できるようになります。新しいセグメントごとに、1 に他の方向と形成する交差の数を加えたものに等しい部分が追加されます。 これにより、セグメントの並べ替えと重複のカウントを効率的に行うという問題が軽減されます。これは、座標が大きいもののセグメントの数が適度であるため、スイープ ラインと座標圧縮を使用して実行できます。 このアプローチでは、完全なグリッド表現を回避し、$n+m$セグメントとその交差数。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(10^12) | O(10^12) | 遅すぎる |
 | 最適 | O((n+m) log(n+m)) | O(n+m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 座標を維持したまま、セグメントを水平リストと垂直リストに分割します。 水平セグメントは次のように保存されます。`(y, x_start, x_end)`そして垂直方向として`(x, y_start, y_end)`。 
2. 水平セグメントと垂直セグメントのすべての x 座標を座標圧縮し、同様に y 座標を圧縮します。 これにより、すべてのセグメント座標が 0 から最大までのより小さい整数範囲にマッピングされるようになります。$2\cdot 10^5$メモリに収まり、効率的な処理が可能になります。 
3. 水平セグメントの場合は、y 座標で並べ替えます。 垂直セグメントの場合は、X 座標で並べ替えます。 この並べ替えは、交差点を効率的にカウントするためのスイープ ライン アルゴリズムを準備します。 
4. 圧縮軸に沿ってフェンウィック ツリー (バイナリ インデックス付きツリー) を初期化します。 水平スイープの場合、ツリーは x 軸全体でアクティブな垂直セグメントを追跡し、水平線が交差する垂直セグメントの数を数えます。 垂直セグメントに出入りするときにツリーを更新します。 
5. y 座標を増加させながら、すべての水平セグメントを反復します。 水平セグメントごとに、その x 範囲全体でフェンウィック ツリーをクエリして、垂直セグメントとの交差をカウントします。 交差点ごとにピース数が 1 つずつ増えます。 水平セグメント自体が横断する領域を常に分割するため、水平セグメント自体に 1 つを追加します。 
6. ツリーに保存されている水平セグメントを使用して、x 軸に沿ってスイープする垂直セグメントを対称的に繰り返します。 すべてのセグメントの寄与の合計から、カウントされた交差を差し引いたもの (交差は 2 回カウントされるため) が、ピースの総数になります。 
7. 結果を元の正方形を表す 1 で初期化します。 処理されるセグメントごとに、上記のルールに従ってその寄与を追加します。 最終結果を出力します。 

重要な不変条件は、すべての新しいセグメントが既存のピースを分割するか、他の向きのセグメントと交差し、交差部分に新しいピースが作成されることです。 このアルゴリズムでは、各交差がセグメント タイプごとに 1 回だけカウントされることが保証されるため、合計は結果として得られるすべての部分を正確に表します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class FenwickTree:
    def __init__(self, n):
        self.n = n
        self.bit = [0]*(n+1)
    
    def update(self, i, val):
        i += 1
        while i <= self.n:
            self.bit[i] += val
            i += i & -i
    
    def query(self, i):
        i += 1
        res = 0
        while i > 0:
            res += self.bit[i]
            i -= i & -i
        return res
    
    def range_query(self, l, r):
        return self.query(r) - self.query(l-1)

def main():
    n, m = map(int, input().split())
    horiz = []
    vert = []
    x_coords = set()
    y_coords = set()
    
    for _ in range(n):
        y, lx, rx = map(int, input().split())
        horiz.append((y, lx, rx))
        x_coords.add(lx)
        x_coords.add(rx)
        y_coords.add(y)
    
    for _ in range(m):
        x, ly, ry = map(int, input().split())
        vert.append((x, ly, ry))
        y_coords.add(ly)
        y_coords.add(ry)
        x_coords.add(x)
    
    x_list = sorted(x_coords)
    y_list = sorted(y_coords)
    x_map = {x:i for i,x in enumerate(x_list)}
    y_map = {y:i for i,y in enumerate(y_list)}
    
    horiz_mapped = [(y_map[y], x_map[lx], x_map[rx]) for y, lx, rx in horiz]
    vert_mapped = [(x_map[x], y_map[ly], y_map[ry]) for x, ly, ry in vert]
    
    horiz_mapped.sort()
    vert_mapped.sort()
    
    BIT = FenwickTree(len(x_list))
    
    res = 1
    events = []
    for x, ly, ry in vert_mapped:
        events.append((ly, 1, x))
        events.append((ry+1, -1, x))
    events.sort()
    
    j = 0
    for y, lx, rx in horiz_mapped:
        while j < len(events) and events[j][0] <= y:
            _, delta, x = events[j]
            BIT.update(x, delta)
            j += 1
        res += 1 + BIT.range_query(lx, rx)
    
    # symmetric for vertical segments
    BIT = FenwickTree(len(y_list))
    events = []
    for y, lx, rx in horiz_mapped:
        events.append((lx, 1, y))
        events.append((rx+1, -1, y))
    events.sort()
    
    j = 0
    for x, ly, ry in vert_mapped:
        while j < len(events) and events[j][0] <= x:
            _, delta, y = events[j]
            BIT.update(y, delta)
            j += 1
        res += 1 + BIT.range_query(ly, ry)
    
    print(res)

if __name__ == "__main__":
    main()
```コードはまず座標を圧縮インデックスにマップし、フェンウィック ツリーを効率的に使用できるようにします。 水平セグメントが最初に処理されます。各セグメントは 1 つの部分に寄与し、垂直セグメントとの交差がフェンウィック ツリーによってカウントされます。 次に、垂直セグメントも同様に処理されます。 各セグメントに 1 つを追加すると新しい分割が処理され、範囲クエリでは交差が考慮されます。 使用する`events`スイープ ラインが端点で垂直セグメントを正しく追加または削除することを保証します。 この方法は二重カウントを回避し、メモリ制限内で大きな座標を処理します。
