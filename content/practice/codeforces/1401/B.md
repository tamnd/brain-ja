 ## 解決策
 ## 問題の理解

 数値の 2 つのマルチセットが与えられ、それぞれの数値は 0、1、または 2 のみです。各シーケンスの合計カウントが一致することが伝えられるため、両方のマルチセットのサイズは同じです。 両方のシーケンスを任意に並べ替えることができ、要素を位置ごとにペアにします。 

各ペアは、選択された 2 つの数値の相対的な順序に応じた値を提供します。 最初のシーケンスの数値が大きい場合、寄与は正であり、積と等しくなります。 それらが等しい場合、寄与はゼロです。 小さい場合、やはり製品に基づいて、寄与は負になります。 

タスクは、すべてのペアの合計が最大になるように両方のシーケンスを配置することです。 

カウントされる制約は 10^8 まで大きくなる可能性がありますが、テスト ケースの数は最大 10^4 まで可能であり、要素ごとのシミュレーションは即座に除外されます。 配列を構築したり、明示的にマッチングを行ったりすることはできません。 すべては純粋にカウントだけで決定されなければなりません。 

一般的な失敗モードは、値が 0、1、2 のみであるという事実を利用せずに、これを一般的なソートおよびマッチングの問題のように扱うことから発生します。たとえば、最大値と最大値を貪欲に一致させようとするかもしれませんが、スコアリングは非対称であり、方向に依存するため、単純なソート ロジックでは 0 と 2 を誤って配置し、マイナスの寄与を回避することで得られる潜在的な利益を失う可能性があります。 

0のバランスをとるときに具体的な落とし穴が現れます。 0からのペアリング`a`からの 2 が付いている`b`は強い負の値ですが、1 または 0 と組み合わせると害ははるかに少なくなります。 これらの非対称なペナルティを無視する単純な戦略は、常に損失を過大評価することになります。 

## アプローチ

 ブルートフォースのアイデアは単純です。両方のシーケンスを展開し、ペアリングのすべての順列を試し、最適な合計を計算します。 これは、並べ替え後に可能な一致をすべて調査するため、正しいです。 ただし、各シーケンスは最大 10^8 要素と非常に大きくなる可能性があるため、配列を並べ替えることはおろか、配列を保存することさえ不可能です。 たとえ記憶を無視したとしても、順列の階乗増加により、このアプローチは考えられなくなります。 

重要な洞察は、周波数のみが重要であり、相互作用はペアのタイプによって完全に決定されるということです。 値は小さな固定セット {0,1,2} からのものであるため、0-0、0-1、0-2、1-2 などのペアをいくつ選択するかという観点から考えることができます。 

私たちはプラスの貢献を最大化し、マイナスの貢献を避けたいと考えています。 採点ルールの遵守:

 - 1 と 0 の 2 拍（2 が入っている場合は正）`a`、反転するとマイナス）
 - 1 は 0 に勝ちますが、2 には負けます
 - 0は常に弱い

 したがって、最適な戦略は、価値の高い対戦相手とのマッチアップで価値の低い要素が強制的に負けるのを防ぎながら、価値の高い勝利を最初に使用する方法で貪欲にマッチングすることです。 

これは古典的な貪欲なペアリングの問題になります。常に最初に最も有益なペアを一致させようとし、次に残りのカウントを注意深く追跡しながら、次に最適な利用可能なインタラクションに進みます。 

カウントのみを使用してこれをシミュレートし、カテゴリを優先順位で繰り返し照合します。 

最初に2を使用します`a`対1インチ`b`、次に 2 対 0、次に 1 対 0 というように、常にできるだけ多く消費します。 

この構造化されたマッチングにより、プラスの利益が得られるたびに、将来のより大きな利益が犠牲にならないことが保証されます。

 ## アルゴリズムのチュートリアル

 両方の配列のカウント (0、1、2) のみを処理します。 

1. 最初にできるだけ多くの 2 と一致します。`a`1が入っている`b`できるだけ。 このような各ペアは +2 を与えます。 

これは最も強力なポジティブな相互作用です。`a > b`。 
2. 次の試合残り 2 秒`a`0が入っている`b`。 それぞれが +0 に貢献しますか? 実際には、2 > 0 であるため、寄与は +0 積 = 0 であるため、これらは中立ですが、後で最悪のペアリングを回避するのに役立ちます。 
3. 次に、1 を一致させます`a`0が入っている`b`。 それぞれ +0 にも貢献し、中立ですが戦略的に役立ちます。 

現時点では、ポジティブまたはニュートラルな機会はすべて使い果たしています。`a > b`。 

ここで、避けられない損失を処理します。 

1.残り2秒`b`傷つきやすいでしょう`a`0を犠牲にできない限り`a`。 0で一致します`a`2インチ付き`b`、これは寄与度が -0 ですが、将来のペアリングの悪化を防ぎます。 これは事実上中立です。 
2. 次に 1 対 2 を処理します。`a < b`、ペアごとに -2 が生成されます。 残りの 1 を一致させます`a`2秒入り`b`。 
3. 最後に、残りの不一致ペアは等しいか無害であり、寄与は 0 です。 

重要な考え方は、常に最も価値のあるポジティブなペアを最初に消費し、次に最も有害なネガティブなペアをできるだけ早く排除するということです。 

### なぜ効果があるのか

 値が 3 つしかないため、すべてのペアは一定数の相互作用タイプのいずれかに属します。 各タイプには固定の寄与があります。 貪欲な順序では、より高い限界ゲインの相互作用が最初に優先されます。 価値の高いペアがスキップされると、対応する要素は同等かそれより悪い結果にのみ関与するため、後で復元することはできません。 これにより、交換引数が作成されます。この順序からの逸脱は、合計を減らさずに元に戻すことができ、最適性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    
    for _ in range(t):
        x1, y1, z1 = map(int, input().split())
        x2, y2, z2 = map(int, input().split())
        
        # a: 0->x1, 1->y1, 2->z1
        # b: 0->x2, 1->y2, 2->z2
        
        # Step 1: 2 in a vs 1 in b => +2 each
        take = min(z1, y2)
        z1 -= take
        y2 -= take
        score = 2 * take
        
        # Step 2: 2 in a vs 0 in b => 0 contribution
        take = min(z1, x2)
        z1 -= take
        x2 -= take
        
        # Step 3: 1 in a vs 0 in b => 0 contribution
        take = min(y1, x2)
        y1 -= take
        x2 -= take
        
        # Step 4: 1 in a vs 2 in b => -2 each
        take = min(y1, z2)
        y1 -= take
        z2 -= take
        score -= 2 * take
        
        # remaining pairs contribute 0
        out.append(str(score))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このコードは、貪欲な相互作用の順序を直接反映しています。 価値を蓄積する唯一の場所は、最初と 4 番目のステップです。これは、合計に影響を与える形でゼロ以外の寄与を生み出す唯一の相互作用であるためです。 中間のステップは、後でより悪いペアが誤って形成されないように、競合から要素を純粋に削除するために存在します。 

微妙な点は、ペアの位置を明示的にシミュレートすることは決してないということです。 最適性は順序ではなくカウントのみに依存するため、これは安全です。

import sys, io

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    res = []
    for _ in range(t):
        x1, y1, z1 = map(int, input().split())
        x2, y2, z2 = map(int, input().split())

        y1 -= take
        z2 -= take

        res.append(str(score))

 ## 特殊なケース

 特殊なケースとしては、1 つのシーケンスにゼロのみが含まれる場合があります。 その場合、どのような組み合わせであっても、組み合わせはゼロになります。 アルゴリズムは、すべての意味のある貢献を即座にスキップします。`min`正のカウントが含まれる場合はゼロになり、合計スコアはゼロになります。 

もう 1 つのエッジ ケースは、一方のシーケンスが 2 に大きく偏り、もう一方のシーケンスが 1 に大きく偏った場合に発生します。アルゴリズムはすべての肯定的なものを抽出します。`2 vs 1`最初に一致し、残りの不均衡が解決される前に最大のゲインが確保されます。 残った要素は中立または不可避の負のペアに分類されますが、貪欲な順序付けによってすでに最小化されています。 

最後のエッジ ケースは、両方のシーケンスの値にわたってカウントが同一である場合です。 すべての貪欲なステップは対称的な量を消費し、純利益または純損失は生成されないため、出力はゼロのままです。
