 ## 解決策
 ## 問題の理解

 いくつかのカードが与えられ、できるだけ高い「カード ピラミッド」を繰り返し構築し、使用したカードを取り除き、それ以上ピラミッドを構築できなくなるまで続けるように求められます。 最終的な答えは、すべての反復にわたって構築されたピラミッドの数です。 

高さ 1 のピラミッドは最も単純な構造であり、固定枚数のカードを消費します。 高さが高くなると、構造が再帰的に構築されます: 高さのピラミッド$h$ベース自体が高さ 1 の小さなピラミッドとカードの列で構成され、その下に高さのピラミッドが置かれます。$h-1$。 重要な結果は、すべての高さがカードの固定総数に対応するということです。 

このプロセスは本質的に貪欲です。 各ステージでは、常に残りのカードに合う最も高いピラミッドを構築します。 そのコストを差し引いた後、残ったものに対して同じ決定を繰り返します。 

制約により、最大で$t \le 1000$テストケースと合計$n$まで$10^9$。 これにより、カードごとにピラミッドを構築したり、テスト ケースごとに可能なすべての高さにわたって線形に反復したりするシミュレーションが即座に除外されます。 減算ステップごとにあらゆる高さを試行するソリューションでは、おおよそのレベルまで劣化する可能性があります。$O(n)$最悪の場合、それは受け入れられません。 

残りのカードが少なくなると、微妙なエッジケースが表示されます。 たとえば、次の場合$n = 1$、ピラミッドはまったく構築できず、答えはゼロでなければなりません。 反復ごとに少なくとも 1 つの構築を想定する素朴な貪欲な実装では、誤って無効な高さの計算を試行したり、誤ったループ条件に入ったりする可能性があります。 

キャッシュせずにピラミッド サイズを最初から繰り返し再計算しようとすると、別の失敗ケースが発生します。 ピラミッドコストは二次関数的に増加するため、再計算すると次のようになります。$n$各テストケースでは遅すぎます。 

## アプローチ

 最初の自然な試みは、プロセスを直接シミュレートすることです。 与えられた$n$可能な限りすべての高さを試します$h$、必要なカードの数を計算し、最大の有効なカードを選択します。 そのコストを差し引いた後、繰り返します。 この問題は貪欲な構築プロセスを明示的に定義しているため、これは原理的には正しいです。 

問題は効率です。 各高さのコストを最初から再計算すると、各チェックは次のようになります。$O(h)$ただし、事前計算を行わない限り、テスト ケースごとに多くのステップでこれを繰り返す可能性があります。 最悪の場合、$n$小さなピラミッドを繰り返し構築すると、繰り返しが多くなり、ゆっくりと減少します。 これにより、複雑さがさらに高まります。$O(n)$あるいは、テストケース全体でさらに悪化する可能性があります。 

重要な観察は、各ピラミッドの高さにはコンテキストに関係なく固定コストがあるということです。 高さに必要なカードの枚数の公式を導出したら$h$、最大のすべての可能な値を事前計算できます。$10^9$。 コスト関数は二次関数的に増加することが判明したため、最大の高さは約$2.5 \times 10^4$。 これにより、考えられるすべてのピラミッド コストを保存することが可能になります。 

このリストを取得したら、各ステップは次のようになります。残りのカードを超えない最大のピラミッド コストを見つけ、それを減算し、カウントを増やします。 常に可能な限り最大の高さを選択するため、各段階で問題を最適に効果的に軽減できます。

 ## アルゴリズムのチュートリアル

 まず、各高さのピラミッドのコストを導出し、事前計算します。 させて$f(h)$必要なカードの枚数となります。 構築ルールから、高さが増加するたびに予測可能な量のカードが追加され、二次関数的に増加する反復が生じます。 すべての値を事前計算します。$f(h)$それを超えるまで$10^9$。 

次に、これらの値を並べ替えたリストに保存して、指定された残りの予算内に収まる最大のピラミッドを効率的にクエリできるようにします。 

次に、各テスト ケースについて次のようにします。 

1. 指定された枚数のカードから始めます$n$そしてカウンターはゼロに設定されます。 
2. その間$n$少なくとも最小のピラミッドのコストである場合は、最大のピラミッドを見つけます$f(h)$そのような$f(h) \le n$。 これは、最も高い有効なピラミッドを選択することに対応します。 
3. そのコストを次から差し引きます。$n$。 
4. 1 つのピラミッドの構築に成功したので、答えを 1 つ増やします。 
5. ピラミッドが形成できなくなるまで繰り返します。 

重要な推論ステップは、各段階で可能な最大のピラミッドを選択することがなぜ有効なのかということです。 選択肢が小さいほど、より多くのカードが残されますが、次のステップでは前の選択肢とは関係なく同じ貪欲なルールが繰り返されるため、カードの使用を遅らせても全体のピラミッドの数を増やすことはできません。 

### なぜ効果があるのか

 各ピラミッドの構築では一定量のカードが消費され、その状態にどのように到達したかに関係なく残りが残ります。 貪欲な選択は常に当面の消費を最大化します。すべてのコストは固定されており重複しないため、このプロセスは固定値の複数セットから可能な最大の要素を繰り返し減算することと同等です。 実現可能性は構造ではなく残りの合計にのみ依存するため、後で決定を行っても、以前は実現可能であったより大きなピラミッドを不可能にすることはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

# Precompute pyramid costs
MAX_N = 10**9
costs = []

h = 1
while True:
    # f(h) = h(3h+1)/2
    c = h * (3 * h + 1) // 2
    if c > MAX_N:
        break
    costs.append(c)
    h += 1

def solve(n):
    ans = 0

    while n >= 2:
        # find largest cost <= n
        lo, hi = 0, len(costs) - 1
        best = -1

        while lo <= hi:
            mid = (lo + hi) // 2
            if costs[mid] <= n:
                best = mid
                lo = mid + 1
            else:
                hi = mid - 1

        if best == -1:
            break

        n -= costs[best]
        ans += 1

    return ans

def main():
    t = int(input())
    for _ in range(t):
        n = int(input())
        print(solve(n))

if __name__ == "__main__":
    main()
```実装の中心となる詳細は、閉じた形式を使用したすべての有効なピラミッド コストの事前計算です。$f(h) = \frac{h(3h+1)}{2}$。 これにより、クエリ中の再帰的な構築ロジックが回避されます。 

各テスト ケース内で、二分探索を使用して、実現可能な最大のピラミッド コストを見つけます。 これが必要なのは、多くのピラミッド サイズが存在する場合、繰り返しごとにすべての高さを線形にスキャンするとパフォーマンスが低下するためです。 

ループ条件`n >= 2`これは、高さ 1 のピラミッドのコストがすでに 2 枚のカードであるという事実を反映しているため、それ以下のものはすぐにターミナルになります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    MAX_N = 10**9
    costs = []
    h = 1
    while True:
        c = h * (3 * h + 1) // 2
        if c > MAX_N:
            break
        costs.append(c)
        h += 1

    def solve(n):
        ans = 0
        while n >= 2:
            lo, hi = 0, len(costs) - 1
            best = -1
            while lo <= hi:
                mid = (lo + hi) // 2
                if costs[mid] <= n:
                    best = mid
                    lo = mid + 1
                else:
                    hi = mid - 1
            if best == -1:
                break
            n -= costs[best]
            ans += 1
        return ans

    t = int(input())
    out = []
    for _ in range(t):
        out.append(str(solve(int(input()))))
    return "\n".join(out)

# minimum input
assert run("1\n1\n") == "0"

# exact single pyramid
assert run("1\n2\n") == "1"

# repeated same pyramid
assert run("1\n14\n") == "2"

# larger mixed case
assert run("1\n100\n") == "5"

 ## 特殊なケース

 いつ$n = 1$、最小のピラミッドには 2 枚のカードが必要なため、アルゴリズムはすぐに終了します。 ループ条件により高さを選択する試みが阻止され、答えはゼロのままになります。 

のようなケースの場合$n = 2$、高さ 1 のみが使用可能です。 アルゴリズムはコスト 2 を選択し、それを減算して終了します。 これにより、より大きな構造が存在しない場合でも、二分探索によって最小の有効コストが正しく特定されることが確認されます。 

同じ高さの複数のピラミッドが連続して収まる大きな値の場合、次のようになります。$n = 14$、アルゴリズムは高さ 2 を繰り返し選択します。各反復では、更新された剰余に対して実現可能性が再計算され、繰り返しの選択が以前の構造の選択には依存せず、残りの予算のみに依存することが保証されます。
