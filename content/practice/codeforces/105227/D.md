 ## 解決策
 ## 問題の理解

 常に最近の会話が最初に表示される動的なチャット サイドバーをシミュレートしています。 Polycarp が友人にメ​​ッセージを送信するたびに、その友人のチャットが最も最近アクティブになり、リストの一番上に移動します。 友人がこれまでに連絡したことがない場合は、上部に新しいチャット エントリが作成されます。 友人がリストにすでに存在する場合、その既存のエントリは現在の位置から削除され、先頭に再挿入されます。 

入力は、メッセージが送信される順序の一連の受信者名です。 出力は、すべての操作を処理した後の、最近メッセージを送信したものから最も最近メッセージを送信したものまでの一意の友達の最終的な順序です。 

この制約により、最大 200,000 のメッセージが許可され、各名前の長さは最大 10 になります。これにより、メッセージごとにリストを繰り返しスキャンまたはシフトするソリューションは即座に除外されます。 Python のリストまたは配列から途中で要素を削除する単純なアプローチでは、操作ごとに線形時間がかかり、最悪の場合は 2 次の動作が発生します。 

同じ友人に繰り返しメッセージを送信する場合、微妙な特殊なケースが発生します。 たとえば、入力が次の場合、`a b a`、処理後:

 - 後`a`、リストは`a`- 後`b`、リストは`b a`- 後`a`、リストになります`a b`古いオカレンスを削除せずに単純に先頭に挿入する単純な実装では、次のような重複が誤って生成されます。`a b a`、これは各フレンドが最大 1 回登場するという要件に違反します。 

もう 1 つの特殊なケースは、すべてのメッセージが同じ人に送信される場合です。 送信されたメッセージの数に関係なく、リストは常に 1 つのエントリ (その人物) で終わる必要があります。 

## アプローチ

 ブルート フォース シミュレーションでは、現在のチャットのリストが保持されます。 受信した名前ごとにリストをスキャンして、その名前がす​​でに存在するかどうかを確認します。 存在する場合は、そのエントリを削除し、その名前を先頭に挿入します。 そうでない場合は、単に前から挿入します。 

これは、説明されている動作を正確に反映しているため、正しいです。 ただし、各操作には、位置を見つけるための線形検索と、要素を削除またはシフトするための別の線形操作が必要です。 すべてのメッセージが異なる最悪のケースでは、増え続けるリストを繰り返しスキャンすることになり、およそ 1 + 2 + 3 + ... + n 回の操作 (O(n²)) が発生します。 n が最大 200,000 であるため、これは遅すぎます。 

重要な観察は、名前が存在するかどうかとその現在の位置のみを考慮しており、検索と並べ替えの両方で高速な更新が必要であるということです。 これは、存在追跡のためのハッシュ ベースの構造と、前面での高速挿入をサポートする構造を組み合わせることを示唆しています。 セットだけでは順序を維持できず、リストだけではメンバーシップの更新が遅すぎます。 解決策は、メンバーシップのセットと順序付けの deque のような構造を維持することですが、さらに単純には、セットと逆方向に構築されたリストを使用してシミュレートすることもできます。または、よりクリーンに、セットを使用して最後から処理し、最終的な順序を 1 回構築することもできます。 

特に明確な洞察は、メッセージを逆にたどることです。 最後のメッセージから最初のメッセージまでスキャンするときに、最初に名前に遭遇したとき、それが応答内のそのチャットの最後の位置である必要があります。 後の出現は転送プロセスで以前の出現をオーバーライドするため、以前の出現は無関係です。 したがって、逆方向に反復して最初に見た名前を収集することで結果を構築できます。

 | セット付き逆スキャン | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 メッセージ リストを最後の受信者から最初の受信者まで処理し、応答にすでに含まれている名前のセットと最終的な順序のリストを維持します。 

1. 空のセットと空のリストから始めます。 

セットは、どの友人がすでに最終的な順序に配置されているかを追跡します。 
2. メッセージ受信者をリストの末尾から先頭に向かって繰り返します。 

この逆転は、最終的な最新性を決定する際に、後のメッセージが以前のメッセージをオーバーライドするため機能します。 
3. それぞれの名前について、それがすでにセットに含まれているかどうかを確認します。 

すでに存在する場合は、最終的な位置がすでに決定されているため、スキップします。 
4. セットにない場合は、結果リストに追加し、既知としてマークします。 

逆の順序で最初に名前に遭遇したときは、元の順序で最後に出現した名前に対応します。 
5. すべてのメッセージが処理されるまで続行します。 
6. 最後に、最終的な出現順とは逆の順序で名前を収集したため、作成したリストを逆にします。 

### なぜ効果があるのか

 各友人の最終的な位置は、入力シーケンス内の最後の出現によってのみ決定されます。 最後から処理することで、最初に名前に遭遇したときが、それが順方向で最後に出現したときであることが保証されます。 その後のすべての遭遇をスキップすることで、各友人が正確に 1 回だけ、正しい最新順に含まれるようになります。 このセットは一意性を強制する一方で、逆走査は「最近の勝利」ルールをエンコードします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    arr = [input().strip() for _ in range(n)]
    
    seen = set()
    res = []
    
    for i in range(n - 1, -1, -1):
        name = arr[i]
        if name in seen:
            continue
        seen.add(name)
        res.append(name)
    
    print("\n".join(res))

if __name__ == "__main__":
    solve()
```このソリューションでは、最初にすべての名前を読み取るので、それらを逆方向にたどることができます。 の`seen`set を指定すると、各名前が 1 回だけ出力されるようになります。 名前を逆から最終の順序で追加し、その順序で直接出力します。構造を正しく解釈する場合は逆にする必要がないためです。最初に名前を後ろから見たときがその最終位置であり、その順序で追加します。 

重要な実装の詳細は、入力行を適切に削除することです。 これがないと、末尾の改行文字によってセット内の等価性チェックが壊れてしまいます。 また、パフォーマンスを低下させる可能性のあるリストの先頭での削除や挿入も避けます。

 ## 特殊なケース

 同一のメッセージが繰り返される場合、次のようになります。`a a a a`、アルゴリズムは後ろから処理し、すぐに最初の部分を取得します。`a`遭遇すると、他のすべてをスキップします。 このセットは重複を防止するため、出力は単一のままになります。`a`、チャットが一意であるという要件に一致します。 

次のような交互パターンの場合`a b a b a`、逆スキャンの遭遇`a`まず、それから`b`、以前の発生を無視して、`a b`。 これは、友人ごとの最後のメッセージのみが最終的な順序を決定することを直接反映しています。 

一意の名前を厳密に増やす場合は、すべての名前が逆スキャン順序で 1 回追加され、入力の逆が生成されます。これは、すべての個別のチャットのシーケンスにおける「最新が一番上」の動作と一致します。
