 ## 解決策
 ## 問題の理解

 各クエリは整数のセグメントを与え、そのセグメント内のいくつの数値が変換関数 g の下で特定の値を共有するかを尋ねます。 関数 g は数値を受け取り、値が 1 桁になるまでその数値をその桁の積に繰り返し置き換えます。 最後の 1 桁は g(x) の結果です。 たとえば、47 は 4 × 7 = 28、次に 2 × 8 = 16、次に 1 × 6 = 6 となるため、g(47) = 6 となります。 

このタスクは、最大 20 万件のそのようなクエリに答えることです。各クエリでは、最大 100 万の範囲内の範囲 [l, r] と、1 から 9 までのターゲット数字 k が要求されます。各クエリの出力は、乗算デジタル ルートが k に等しい、その範囲内の整数の数です。 

この制約により、すぐにクエリごとのシミュレーションから遠ざけられます。 [l, r] 内のすべての x について g(x) を再計算する単純なアプローチでは、最悪の場合、クエリごとに最大 100 万回の操作が必要となり、全体で約 2 × 10^11 回の操作が必要になりますが、これは実現可能性をはるかに超えています。 

微妙な点は、x は 10^6 まで増加しますが、g(x) は常に 1 桁に急速に減少することです。 つまり、考えられる結果は 9 つだけであるため、ドメイン全体で繰り返される構造を事前に計算できます。 

エッジケースは、桁の乗算の動作から発生します。 ゼロを含む数値はすぐにゼロになりますが、k は 1 ～ 9 であることが保証されているため、これらの値はカウントには関係ありません。 もう 1 つの特殊なケースは、10 や 1000 のような数値です。これらは乗算するとゼロになるため、誤って正の k にカウントしてはなりません。 

## アプローチ

 ブルート フォース手法では、各クエリの数値ごとに g(x) を独立して評価します。 すべての x について、1 桁に達するまで繰り返し桁を乗算します。 これには、数値ごとにせいぜい数桁の乗算のコストがかかりますが、各クエリは最大 100 万の数値にまたがる可能性があり、最大 20 万のクエリがあるため、すべてのクエリにわたってこれは大きすぎます。 

重要な観察は、変換 g(x) がクエリには依存せず、x のみに依存するということです。 最大 100 万までの x ごとに g(x) がわかれば、各クエリは事前に計算された配列に対する単純な計数問題になります。 

各位置に g(x) が格納される配列を事前計算します。 次に、1 から 9 までの各数字 k について、g(x) = k となるように、すべての x にわたるプレフィックスの合計を構築します。 その後、各クエリはプレフィックスの違いを使用して一定時間内に応答されます。 

これにより、繰り返される再計算が単一の前処理パスに変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(Q · N · log N) | お(1) | 遅すぎる |
 | 最適 (事前計算 + プレフィックスの合計) | O(N log N + Q) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、1 から 1,000,000 までのすべての x について g(x) を計算します。 これは、数値が 1 桁になるまで、数値をその桁の積に繰り返し置き換えることによって行われます。 一度計算されると、すべてのクエリでこれらの値が再利用されるため、この手順が必要です。 

次に、1 から 9 までの各可能な数字を生成する数値の数を保存します。生の頻度のみを保存する代わりに、範囲クエリに効率的に答えることができるようにプレフィックスの合計を構築します。 

次に、元のクエリ [l, r, k] をプレフィックスの合計の差に変換します。答えは、prefix[k][r] から prefix[k][l − 1] を引いたものになります。 これが機能するのは、プレフィックス配列が 1 から各位置までカウントを累積するためです。 

最後に、各クエリの結果を出力します。 

### なぜ効果があるのか

 正確さは、g(x) が x の純粋な関数であり、クエリ構造から独立しているという事実から得られます。 計算されると、x が出現するたびに、正確に 1 つの単位が正確に 1 桁のバケットに寄与します。 プレフィックス合計はこれらのカウントを累積的に保存するため、どの間隔クエリでも、寄与を失ったり二重にカウントしたりすることなく、2 つの累積合計を減算するだけで済みます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXN = 10**6

def prod_digits(x):
    while x >= 10:
        p = 1
        while x > 0:
            x, d = divmod(x, 10)
            p *= d
        x = p
    return x

g = [0] * (MAXN + 1)
for i in range(1, MAXN + 1):
    g[i] = prod_digits(i)

prefix = [[0] * (MAXN + 1) for _ in range(10)]

for i in range(1, MAXN + 1):
    val = g[i]
    for k in range(1, 10):
        prefix[k][i] = prefix[k][i - 1]
    prefix[val][i] += 1

q = int(input())
out = []

for _ in range(q):
    l, r, k = map(int, input().split())
    out.append(str(prefix[k][r] - prefix[k][l - 1]))

print("\n".join(out))
```この解決策は、乗算桁数削減関数を定義することから始まります。 数値が 1 桁になるまで繰り返し乗算されるため、39 や 88 などの複数の中間段階を通過する入力でも正確さが保証されます。 

次に、100 万までのすべての値について g(x) を事前計算します。 これは高価な部分ですが、一度だけ実行されます。 

その後、1 から 9 までの各桁のプレフィックス配列を構築します。各プレフィックス配列は、指定された g 値を持つインデックス i までの数値の数を追跡します。 

クエリはプレフィックス範囲の減算を使用して回答されるため、再計算が回避されます。 

## 実用的な例

 g(x) を前処理した後、いくつかの間隔でクエリを実行する小さな例を考えてみましょう。 

狭い範囲で簡略化されたバージョンをトレースしてみましょう。 

| 私 | g(i) | 接頭辞[4][i] | 接頭辞[6][i] |
 | --- | --- | --- | --- |
 | 1 | 1 | 0 | 0 |
 | 2 | 2 | 0 | 0 |
 | 3 | 3 | 0 | 0 |
 | 4 | 4 | 1 | 0 |
 | 5 | 5 | 1 | 0 |
 | 6 | 6 | 1 | 1 |
 | 7 | 7 | 1 | 1 |
 | 8 | 8 | 1 | 1 |
 | 9 | 9 | 1 | 1 |

 クエリ [4, 7, 6] の場合、prefix[6][7] − prefix[6][3] = 1 − 0 = 1 を計算します。 

ここでクエリ [1, 9, 4] について考えます。この範囲では数値 4 のみが 4 にマップされるため、prefix[4][9] − prefix[4][0] = 1 − 0 = 1 を計算します。 

これらのトレースは、プレフィックス配列が構築されると、各クエリが 2 つのテーブル検索と 1 つの減算に減少することを示しています。 

## 複雑さの分析

Python では 100 万整数を超える N log N 回の操作が許容され、クエリは一定時間内に応答されるため、前処理は制限内に問題なく収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    MAXN = 200  # small bound for testing

    def prod_digits(x):
        while x >= 10:
            p = 1
            while x > 0:
                x, d = divmod(x, 10)
                p *= d
            x = p
        return x

    g = [0] * (MAXN + 1)
    for i in range(1, MAXN + 1):
        g[i] = prod_digits(i)

    prefix = [[0] * (MAXN + 1) for _ in range(10)]
    for i in range(1, MAXN + 1):
        for k in range(1, 10):
            prefix[k][i] = prefix[k][i - 1]
        prefix[g[i]][i] += 1

    q = int(input())
    out = []
    for _ in range(q):
        l, r, k = map(int, input().split())
        out.append(str(prefix[k][r] - prefix[k][l - 1]))

    return "\n".join(out)

# minimum range
assert run("1\n1 1 1\n") == "1", "single element"

# zero-producing numbers behavior
assert run("3\n10 10 1\n10 10 9\n10 10 2\n") == "0\n0\n0", "zeros collapse to 0"

# small mixed range
assert run("2\n1 9 4\n1 9 6\n") == "1\n1", "basic digit roots"

# full range check
assert run("1\n1 200 1\n") == run("1\n1 200 1\n"), "consistency check"

 | --- | --- | --- |
 | 単一要素 | 1 | 基本ケースの正確性 |
 | 10 取り扱い | すべてゼロ | 数字積の折りたたみ動作 |
 | 狭い範囲 | 1、1 | 配布の正確性 |

 ## 特殊なケース

 重要なエッジケースは、ゼロを含む数値です。 たとえば、x = 105 は、最初の桁の積の直後に 0 になります。 k は常に 1 から 9 の間であるため、そのような数値が答えに寄与することはありません。 前処理により、それらは g(x) = 0 で保存され、k ≥ 1 の prefix[k] 配列には決して入力されないことが保証されます。 

もう 1 つのケースは、桁崩れが繰り返される場合です。 39 のような数値は、27、14、4 になります。中間ステップが誤って早い段階で切り捨てられた場合、最終的なマッピングは間違ったものになります。 ループ構造により、1 桁が残るまで完全に削減されるため、必要なステップ数に関係なく、最終的な分類が安定します。 

最後に、[1, 1e6] のような均一範囲は、ドメイン全体にわたってプレフィックスの合計が正しく蓄積されているかどうかをテストします。 すべての x には 1 つの g(x) が割り当てられるため、k = 1 ～ 9 の合計カウントは N と一致し、前処理の正確さの健全性チェックとして機能します。
