 ## 問題の理解

出力はすべてのリストです。$k$から$1$に$n$したがって、ウィンドウ サイズが大きくなるにつれて、この「普遍的に存在する最小値」がどのように変化するかが実質的に問われます。 

制約は十分に厳しいので、二次関数はすべて許容されます。$n$テストケースごとには不可能です。 各要素は多くのウィンドウに参加しており、最大で$3 \cdot 10^5$テスト全体の要素の合計を計算するため、目的の解決策は線形または線形演算に近いものでなければなりません。 それぞれについて独立して情報を再計算するソリューション$k$ざっくりと作業を繰り返します$n$すぐに制限を超えてしまいます。 

微妙な点は、値が全体的に頻繁に表示される場合でも、一部のウィンドウでは値が表示されない場合があることです。 たとえば、`1 2 1 2 1`、番号`1`は何度も表示されますが、特定のウィンドウ サイズではそれのないセグメントが存在するため、グローバル条件を満たしません。 これにより、単純な周波数推論が崩れます。

 ## アルゴリズムのチュートリアル

 配列を出現リストに変換し、値ごとに制約を計算して、すべてのクエリに答えます。$k$。 

1. 各値のすべての位置を配列に保存します。 これにより、ウィンドウを繰り返しスキャンするのではなく、ギャップを直接推論することができます。 
2. 値ごとに、その出現インデックスのリストを作成し、その位置に仮想境界を追加します。$0$そして$n+1$。 これにより、エッジ ギャップが内部ギャップで均一に処理されるようになります。 
3. 各値について、この拡張リスト内の連続する位置間の最大差を計算します。 この最大ギャップは、その値を「回避」できなくなる最小のウィンドウ サイズを表します。 
4. これをしきい値として解釈します。値はすべての場合に有効です。$k$この最大ギャップ以上であるため、そのギャップより短いウィンドウは完全にギャップ内に配置され、値が完全に失われる可能性があるためです。 
5. 次に、すべての項目について計算する必要があります。$k$、しきい値が最大である最小値$k$。 しきい値を昇順に処理します。$k$、これまでに確認された最良の候補値を維持します。 
6. アレイを構築する`best[k]`ここで、各しきい値から開始してすべての位置を更新します。 小さいものから大きいものまで直線的にスイープ$k$有効となるグローバル最小値を維持します。 

### なぜ効果があるのか

 重要な不変条件は、各値について計算された最大ギャップが、その値をすべてのウィンドウに表示する正確な最小ウィンドウ サイズであるということです。 このギャップより短いウィンドウは、値を完全に回避して、オカレンス間の最大のギャップ内に配置できます。 少なくともこの大きさのウィンドウはすべてのギャップ チェーンと交差し、すべてのウィンドウに少なくとも 1 つのオカレンスが表示されるようにする必要があります。 このしきい値は有効性を完全に特徴付けるため、しきい値ごとに値を集計し、プレフィックスの最小値を取得します。$k$正しい答えを生み出します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        pos = [[] for _ in range(n + 1)]
        for i, v in enumerate(a, 1):
            pos[v].append(i)

        # threshold[k] = best candidate value that activates at k
        INF = 10**18
        threshold = [INF] * (n + 2)

        for v in range(1, n + 1):
            if not pos[v]:
                continue

            arr = [0] + pos[v] + [n + 1]
            mx_gap = 0
            for i in range(1, len(arr)):
                mx_gap = max(mx_gap, arr[i] - arr[i - 1])

            threshold[mx_gap] = min(threshold[mx_gap], v)

        ans = [-1] * (n + 1)
        best = INF

        for k in range(1, n + 1):
            best = min(best, threshold[k])
            if best != INF:
                ans[k] = best
            else:
                ans[k] = -1

        print(*ans[1:])

if __name__ == "__main__":
    solve()
```このソリューションは、各値の出現リストを構築します。これが、ウィンドウ カバレッジを推論するために必要な唯一の構造です。 拡張された境界線`0`そして`n+1`特別なケースを使用せずにエッジ ギャップが確実に処理されるようにします。 最大ギャップの計算により、各値の臨界しきい値が直接生成されます。 

配列`threshold`ウィンドウ サイズを、そのサイズで正確に有効となる最小値にマップします。 次に、プレフィックス最小スイープにより、これらのアクティベーション ポイントがすべてのアクティベーション ポイントの答えに変換されます。$k$値が有効になると、それより大きなすべての値の候補であり続けることが保証されます。$k$。 

よくある落とし穴は、境界ギャップを忘れることです。 追加せずに`0`そして`n+1`、エッジ近くに表示される値は、実際よりも安定しているように誤って表示されます。

 ## 特殊なケース

 次のような単一要素配列の場合`[7]`、拡張された位置は次のようになります。`[0,1,2]`、最大ギャップが生じます`2`。 これは、サイズ 1 のウィンドウのみが値を自明に含むことを正しくエンコードしますが、概念的なギャップが大きい場合はそれを回避する方法がないため無関係です。$k=1$。 

のような配列の場合`[1,2,1,2,1,2]`、出現が頻繁で等間隔であるため、両方の値の最大ギャップは小さくなります。 アルゴリズムは両方の小さなしきい値を割り当て、プレフィックス最小値により最小値がすべてのしきい値を支配するようにします。$k$、一定の答えを正しく生成します。 

エッジの多いパターンの場合`[1,2,3,1]`、 価値`2`そして`3`小さなウィンドウでスキップできる大きなギャップがある一方で、値`1`内部の間隔が狭くなります。 強化された境界ギャップにより、最初と最後の発生が正しく考慮され、安定性の過大評価が防止されます。
