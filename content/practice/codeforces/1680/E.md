 ## 解決策
 ## 問題の理解

 私たちに与えられているのは、$2 \times n$ボードでは、一部のセルには「*」で表されるチップが含まれており、その他のセルには「.」で表される空のセルがあります。 私たちの仕事は、ボード上にちょうど 1 つのチップが残るようにチップを移動することです。 各移動は、任意のチップを選択し、それを水平または垂直に直接隣接するセルに移動することで構成されます。 チップが別のチップのあるセルに移動すると、移動先のチップが削除されます。 各ボードの出力は、すべてのチップを 1 つのチップに減らすために必要な最小移動数です。 

制約が意味するのは、$n$到達できる$2 \cdot 10^5$と合計$n$テストケース全体では最大でも$2 \cdot 10^5$これにより、すべての動きに対してすべての可能なチップ位置を反復したり、一連の動きをブルートフォース検索しようとしたりするソリューションは即座に除外されます。 テスト ケースごとに線形または線形に近いソリューションが実現可能です。 各ボードには少なくとも 1 つのチップがあるため、空のボードを処理する必要はありません。 

エッジ ケースは、すべてのチップが 1 列にある場合、チップが両方の列で非連続セグメントを形成している場合、または基板が非常に小さい場合に発生します。 たとえば、次の場合$n=1$チップが 1 つあり、答えは$0$動きます。 もし$n=2$上の列には左側にチップがあり、下の列には右側にチップがあります。チップは中央で接触する必要があり、2 つの移動が必要です。 チップが水平方向にのみ移動すると仮定した単純な実装は、ここでは失敗します。 

## アプローチ

 ブルートフォース ソリューションでは、すべてのチップの動きをシミュレートし、1 つだけが残るまでどのチップをどこに移動するかを選択します。 これは原理的には正しいですが、ボードの長さが長くても実現不可能です。$10^5$多くのチップを使用すると、天文学的な数の移動シーケンスが生成されます。 

重要な観察は、どのチップが生き残るかは気にせず、すべてのチップを統合するのに必要な手の数だけを気にするということです。 これにより、水平および垂直の動きを最小限に抑えながら、すべてのチップ位置を訪問するパスを見つけるという問題が軽減されます。 同じ列のチップは水平方向の移動で結合できますが、異なる列のチップを結合するには少なくとも 1 回の垂直方向の移動が必要です。 

少なくとも 1 つのチップを含む列のセグメントを定義する場合、水平移動の最小数は、最初と最後のそのような列の間の距離になります。 列の両方の行にチップがある位置では垂直方向の移動が必要となり、スイッチがもう一方の行にチップを収集するように強制されます。 この問題は、セグメントの数を数えることと、行を途中で切り替えるかどうかを決定することに帰着できます。 

これは、単純な貪欲戦略で定式化できます。 「アクティブ」チップが現在上の行または下の行にある場合は、必要な移動数を維持しながら、ボードを左から右にスキャンします。 各列で、その列の 1 行にのみチップが含まれている場合は、その行で続行します。 列の両方の行にチップが含まれている場合、もう一方の行にいた場合は垂直方向に移動する必要があり、水平方向の移動回数に 1 を加えます。 この動的追跡により、すべてのシーケンスをシミュレートすることなく、最小限の動きを確実に蓄積できます。

 ## アルゴリズムのチュートリアル

 1. 少なくとも 1 つのチップを含む左端と右端の列を特定します。 この範囲外の列は、そこにあるチップが水平に移動する必要がないため、無関係です。 
2. 最後のアクティブなチップが上の行または下の行にある場合、最小移動を表す 2 つのカウンターを初期化します。 最初は両方ともゼロです。 
3. 関連する列を左から右に繰り返します。 各列のチップ構成を確認します。1 つの行にのみチップがある場合は、他の行のチップは無視できます。 両方の行にチップがある場合、現在アクティブな行がもう一方の行である場合、垂直方向の移動が必要になる場合があります。 
4. 各列について、次のように上部カウンタと下部カウンタを更新します。新しい上部カウンタは、以前の上部カウンタに 1 を加えた値 (水平移動)、または以前の下部カウンタに 2 を加えた値 (垂直 + 水平) の最小値になります。 対称的に、下部のカウンターを更新します。 
5. 反復の最後に、最上部と最下部のカウンターの最小値が答えになります。これは、すべてのチップを 1 つの最終チップに統合するために必要な最小の移動を表します。 

機能する理由: アルゴリズムは、列の処理後に不変条件を維持します。$i$、カウンターは、一番上の行または一番下の行で終わるその列までのすべてのチップを収集するために必要な最小限の手を保存します。 すべての列が順番に処理され、必要な垂直方向の移動が更新によって考慮されるため、最終的な最小値によって最適なソリューションが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def min_moves(s1, s2, n):
    left = 0
    right = n - 1
    while left < n and s1[left] == '.' and s2[left] == '.':
        left += 1
    while right >= 0 and s1[right] == '.' and s2[right] == '.':
        right -= 1

    if left > right:
        return 0

    top_moves = 0
    bottom_moves = 0

    for i in range(left, right + 1):
        top_has = s1[i] == '*'
        bottom_has = s2[i] == '*'

        if top_has and bottom_has:
            new_top = min(top_moves + 1, bottom_moves + 2)
            new_bottom = min(bottom_moves + 1, top_moves + 2)
        elif top_has:
            new_top = min(top_moves, bottom_moves + 1)
            new_bottom = min(bottom_moves, top_moves + 1)
        elif bottom_has:
            new_top = min(top_moves, bottom_moves + 1)
            new_bottom = min(bottom_moves, top_moves + 1)
        else:
            new_top = top_moves
            new_bottom = bottom_moves

        top_moves = new_top
        bottom_moves = new_bottom

    return min(top_moves, bottom_moves)

t = int(input())
for _ in range(t):
    n = int(input())
    s1 = input().strip()
    s2 = input().strip()
    print(min_moves(s1, s2, n))
```最初の部分では、チップを含む列の範囲を検索し、不要な空の列をトリミングします。 動的カウンター`top_moves`そして`bottom_moves`各行で終わる最小限の動きを追跡します。 各列でそれらを更新すると、垂直方向の遷移と水平方向の移動が同時に処理されます。 使用する`min`最適なパスが選択されるようにします。
