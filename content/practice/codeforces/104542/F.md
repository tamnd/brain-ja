 ## 解決策
 ## 問題の理解

 孤立したノードのセットが与えられ、各ノードは固定の小さな文字列を保持します。 時間の経過とともにエッジが追加されるため、ノードは徐々に接続されたコンポーネントを形成します。 これらのコンポーネントは、結合が実行されるにつれて成長するグループのように動作します。 

このグラフの進化とともに、私たちは二つのことを繰り返し問いかけられます。 まず、2 つのノードを接続し、それらのコンポーネントをマージします。 次に、ノードとテキスト文字列が与えられるので、そのノードの接続されたコンポーネント全体の内部を調べる必要があります。 そのコンポーネント内のすべてのノードについて、関連付けられた文字列を取得し、クエリ テキスト内の部分文字列として出現する回数をカウントします。 最終的な答えは、コンポーネント全体にわたるこれらのカウントの合計です。 

主な問題は、グラフ構造とクエリ テキストの両方が相互作用することです。 コンポーネントは時間の経過とともに変化し、各クエリは、コンポーネントによって定義された潜在的に大規模なパターンのセットに対するパターン マッチングについて尋ねます。 

制約は可能性を強く形作ります。 すべてのノード文字列の合計の長さは最大 50 万にすぎません。これは、入力文字列の各文字が全体で少数の回数しか処理できないことを示唆しています。 同様に、すべてのクエリ文字列の合計長にも制限があるため、文字ごとの作業がほぼ一定である限り、各クエリ文字列を複数回スキャンしても許容されることがわかります。 ただし、クエリとユニオンの数が多いため、クエリごとに重い構造を最初から繰り返し再構築するアプローチは、すぐに遅すぎます。 

単純な解釈では、クエリごとにコンポーネント内のすべてのノードを反復処理し、ノードごとにクエリ テキストの部分文字列検索を実行します。 これにより、コンポーネントのサイズとクエリの長​​さがすでに乗算されていますが、両方が大きい場合は実行不可能になります。 

ノードごとに独立して答えを事前計算しようとすると、さらに微妙な失敗が発生します。 これでは、コンポーネントが動的にマージされるという事実が無視され、結合のたびに集合構造を再計算すると、完全な再構築が繰り返されることになります。 

注目に値する最後のエッジケースは、異なるノード間で同一の文字列が繰り返されることです。 それらを慎重に集計しないと、共有構造として扱わずに、重複してカウントしたり、同一のパターンを個別に照合することを繰り返したりして時間を無駄にする可能性があります。 

## アプローチ

 直接的なブルート フォース ソリューションは、クエリ対象のノードの接続コンポーネント内のすべてのノードを反復処理することにより、各クエリを処理します。 このようなノードごとに、クエリ テキスト内のその文字列の部分文字列検索が実行されます。 コンポーネントのサイズが大きく、クエリ文字列が長い場合、最悪の場合、クエリあたりおよそ O(n * |t|) になります。 最大 200,000 クエリの場合、これは天文学的に大きくなります。 

重要な点は、各クエリが基本的に単一のテキストに対するパターン セット全体のパターン マッチングを要求していることです。 パターンは、接続コンポーネント内のノードに接続された文字列です。 これはまさに、Aho-Corasick オートマトンが役立つ種類の問題です。Aho-Corasick オートマトンを使用すると、テキスト長の線形時間で多くのパターンを同時に照合できるからです。 

残りの問題は、エッジの挿入によりパターンのセットが動的に変化することです。 これは、結合コンポーネントごとに、マージをサポートするパターン辞書を維持することを示唆しています。 自然な構造は、Aho-Corasick オートマトンに強化されたトライです。 

2 つのコンポーネントが結合されると、それらのパターン セットも結合されます。 常に小さいオートマトンを大きいオートマトンにマージする場合、各文字列はマージ間で対数回だけ移動します。 マージ後、結合された構造の障害リンクを再構築します。

次に、各クエリはクエリ文字列に対して単一の Aho-Corasick トラバーサルを実行し、すべてのパターン一致を蓄積します。 すべてのパターンはクエリ時に 1 つのコンポーネントにのみ属するため、そのコンポーネントのオートマトンが答えを完全に表します。

 ## アルゴリズムのチュートリアル

 素セット結合と、コンポーネントごとに動的に維持される Aho-Corasick オートマトンを組み合わせます。 

### アルゴリズムのチュートリアル

 1. 各ノードが独自のコンポーネントである DSU を初期化し、各コンポーネントには最初にパターン文字列が 1 つだけ含まれます。 ノードごとに、その文字列を表す単一ノードのトライ構造を構築します。 このトライは、そのコンポーネントの最初のオートマトンでもあります。 
2. 各 DSU ルートについて、現在のトライ構造のルートへのポインタを維持します。 このトライは、そのコンポーネント内のすべての文字列を表します。 
3. u と v の間のユニオン クエリを処理するときに、それらの DSU ルートを見つけます。 それらがすでに同じコンポーネント内にある場合は、何もしません。 それ以外の場合は、常に小さいトライを大きいトライに接続します。 これにより、すべてのトライの各ノードがすべてのマージにわたって対数回のみ移動することが保証されます。 
4. 2 つのトライをマージするには、小さいトライのすべてのノードを大きいトライに再帰的に挿入し、可能な場合は構造を共有します。 同一のプレフィックスが存在する場合、ノードを複製するのではなく再利用します。 
5. トライをマージした後、結果のトライの Aho-Corasick 障害リンクを再構築します。 これは、トライ上の BFS によって行われ、障害ポインターを設定して出力リンクを伝播し、各ノードがどのパターンで終了するか、どのパターンが通過するかを認識できるようにします。 
6. タイプ 2 のクエリの場合、指定されたノードの DSU ルートを取得し、そのオートマトンを取得して、クエリ文字列に対して標準の Aho-Corasick トラバーサルを実行します。 オートマトン内のノードに到達するたびに、そのノードで終わるパターンの数を答えに追加します。 
7. 各クエリの累積合計を出力します。 

### なぜ効果があるのか

 常に、すべての接続コンポーネントは、そのコンポーネントに属する文字列のセットを正確に含む 1 つの Aho-Corasick オートマトンによって表されます。 ユニオン操作は、2 つのオートマトンを 1 つの一貫した構造にマージすることで、この不変性を維持します。 すべての文字列はマージ レベルごとに 1 回だけ挿入され、常により大きな構造に挿入されるため、総再構築コストは少額で償却されます。 クエリの正確性は、Aho-Corasick の特性に従っています。テキスト内のあらゆるパターンの出現は、その終端ノードと伝播された出力リンクを通じて 1 回だけレポートされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

class Node:
    __slots__ = ("next", "link", "out", "cnt")
    def __init__(self):
        self.next = {}
        self.link = 0
        self.out = 0
        self.cnt = 0

def build_ac(nodes):
    q = deque()
    for c, v in nodes[0].next.items():
        q.append(v)
        nodes[v].link = 0

    while q:
        v = q.popleft()
        nodes[v].out = nodes[nodes[v].link].out + nodes[v].cnt
        for c, u in nodes[v].next.items():
            q.append(u)
            f = nodes[v].link
            while f and c not in nodes[f].next:
                f = nodes[f].link
            nodes[u].link = nodes[f].next[c] if c in nodes[f].next else 0

def merge_trie(big, small, nodes):
    stack = [(big, small)]
    while stack:
        a, b = stack.pop()
        nodes[a].cnt += nodes[b].cnt
        for c, nb in nodes[b].next.items():
            if c in nodes[a].next:
                stack.append((nodes[a].next[c], nb))
            else:
                nodes[a].next[c] = nb

def add_string(nodes, s):
    v = 0
    for ch in s:
        if ch not in nodes[v].next:
            nodes[v].next[ch] = len(nodes)
            nodes.append(Node())
        v = nodes[v].next[ch]
    nodes[v].cnt += 1
    return nodes

class DSU:
    def __init__(self, n):
        self.p = list(range(n))
        self.sz = [1] * n

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return a
        if self.sz[a] < self.sz[b]:
            a, b = b, a
        self.p[b] = a
        self.sz[a] += self.sz[b]
        return a, b

def query_ac(nodes, s):
    v = 0
    res = 0
    for ch in s:
        while v and ch not in nodes[v].next:
            v = nodes[v].link
        if ch in nodes[v].next:
            v = nodes[v].next[ch]
        res += nodes[v].out
    return res

def main():
    n = int(input())
    roots = [None] * n
    nodes_list = []

    def new_trie(s):
        nodes = [Node()]
        v = 0
        for ch in s:
            if ch not in nodes[v].next:
                nodes[v].next[ch] = len(nodes)
                nodes.append(Node())
            v = nodes[v].next[ch]
        nodes[v].cnt = 1
        build_ac(nodes)
        return nodes

    for i in range(n):
        s = input().strip()
        roots[i] = i
        nodes_list.append(new_trie(s))

    dsu = DSU(n)

    q = int(input())
    for _ in range(q):
        tmp = input().split()
        if tmp[0] == '1':
            u = int(tmp[1]) - 1
            v = int(tmp[2]) - 1
            ru = dsu.find(u)
            rv = dsu.find(v)
            if ru == rv:
                continue
            if len(nodes_list[ru]) < len(nodes_list[rv]):
                ru, rv = rv, ru
            merge_trie(nodes_list[ru], nodes_list[rv], nodes_list)
            dsu.p[rv] = ru
            build_ac(nodes_list[ru])
        else:
            u = int(tmp[1]) - 1
            t = tmp[2].strip()
            r = dsu.find(u)
            print(query_ac(nodes_list[r], t))

if __name__ == "__main__":
    main()

2 番目のタイプの各クエリは、テキスト文字列に対して 1 回のスキャンを実行し、オートマトンの遷移に従い、出力の伝播を通じてパターン カウントを蓄積します。

 ## 特殊なケース

 複数のノードが同一の文字列を共有する場合、微妙なエッジ ケースが発生します。 このような状況では、トライ圧縮により、パスが重複するのではなく、繰り返される端末カウントとして表現されることが保証されます。 たとえば、3 つのノードがそれぞれ`"a"`同じコンポーネント内で、`"a"`クエリテキスト内で。 各ターミナルノードがインクリメントされるため、アルゴリズムはこれを処理します。`cnt`、 そして`out`伝播では、Aho-Corasick 構築中にこれらのカウントが正しく合計されます。 

もう 1 つのケースは、結合が繰り返されて大きなチェーンを形成する場合です。 小から大へのマージを行わないと、大きな構造を大きな構造に繰り返し接続すると、二次的な動作が発生します。 サイズベースのマージ ルールにより、各ノードは制限された回数だけ移行することが保証され、敵対的なユニオン シーケンスでも償却効率が維持されます。
