 ## 問題の理解

 配列が与えられ、その配列の任意の部分配列を候補配列として選択することができます。$b$。 問題は、私たちがチェックしていないということです$b$元の配列のみに対してではなく、派生配列のファミリーに対しても同様です。 

どのポジションでも$i$、削除します$a_i$配列から取得し、概念的にはこの短縮された配列を何度も繰り返します。$n$コピーを連結したもの。 これにより長いシーケンスが作成されます$c$長さの$n(n-1)$。 要件は、少なくとも 1 つのサブシーケンスが存在することです。$b$元の配列の、何らかの選択に対して$i$、$b$この繰り返し構造内のサブシーケンスとしては見つかりません$c$。 

したがって、タスクは構築することではありません$b$、しかし、そのような「区別できる部分列」がそもそも存在するかどうかを判断すること。 

制約は大きく、合計すると$n$テストケース全体で最大$2 \cdot 10^5$。 サブシーケンスの数は指数関数的であるため、すべてのサブシーケンスをテストしようとする解決策は直ちに不可能です。 単一の候補部分列をすべてに対してチェックする場合でも$i$サブシーケンスのチェック自体は配列サイズにおいて線形であるため、素朴に選択を行うと依然としてコストがかかりすぎます。 

これにより、私たちは構造的な観察に向かうことになります。これは、サブシーケンスが出現しない唯一の方法です。$c$に何らかの値がある場合$b$変更された配列では「まれ」すぎる場合、または順序の制約により、繰り返されるコピー間で不可能な位置合わせが強制される場合。 

いくつかの微妙なエッジの状況が自然に発生します。 

たとえば、すべての要素が同一の場合、$a = [1,1,1]$、任意の 1 つの要素を削除すると、定数配列が残ります。 任意のサブシーケンス$b$は単なる 1 のシーケンスであり、常にコピーが繰り返されます。 これは「NO」の結果を示唆します。 

1 回だけ出現する値が存在する場合は、次のようにします。$a = [1,2,3]$、一意の要素を削除すると、シンボルの可用性が大幅に変化する可能性があり、多くの場合、特定のサブシーケンスをすべてのコピーに同時に埋め込むことができなくなります。 

重要な難点は、$c$同じマルチセットを繰り返します$n$回なので、大きな冗長性があります。 唯一の意味のある制限は、反復の前に 1 つの位置が削除されるという事実から生じます。 

## アプローチ

 ブルートフォースアプローチでは、すべてのサブシーケンスが試行されます$b$、それぞれについて$i$、 建てる$c$そしてチェックしてください$b$の続きです$c$。 指数関数的な部分列を無視しても、構築とスキャン$c$費用$O(n^2)$、これは大きすぎます。 

私たちは何を再解釈する必要がありますか？$b$の続きです$c$” というのは本当に意味があります。$c$ちょうどです$n$1 つの要素を削除した配列の繰り返し、サブシーケンスの埋め込み$b$複数のコピーに配布できます。 これは、繰り返しがマッチングプロセスを制限するのではなく、マッチングプロセスに役立つことを意味します。 

重要な洞察は、視点を逆転させることです。 何かあるかどうかを尋ねるのではなく、$b$いくつかの点で失敗する$c$のすべての後続がいつであるかを尋ねます。$a$このような繰り返し構造のすべてに埋め込み可能です。 これは、単一の要素を削除しても、サブシーケンス パターンをブロックするほどシーケンスの表現力が低下しない場合に発生します。 

これにより、問題は「重要な構造」が存在するかどうかを確認することになります。$a$そしてその構造は、すべての要素が同一であるかどうかによって完全に決定されることがわかります。 少なくとも 2 つの異なる値が存在する場合、インデックスが削除されたときに不一致を強制するサブシーケンスをいつでも構築できます。 すべての値が同一の場合、繰り返しにより、すべてのサブシーケンスがどこでも有効であることが保証されます。

 ## アルゴリズムのチュートリアル

 1. 配列をスキャンし、すべての要素が等しいかどうかを確認します。 

少なくとも 2 つの異なる値がある場合、有効なサブシーケンスが存在することがすぐにわかります。 
2. すべての要素が同一である場合、そのような区別できる部分列は存在し得ないと結論付けます。 

ステップ 1 の背後にある理由は、値の多様性により、相対的な順序やさまざまなシンボルの利用可能性に依存するサブシーケンスを構築できるためですが、慎重に選択したインデックスを削除すると中断される可能性があります。 

ステップ 2 が続きます。これは、定数配列が削除と繰り返しの下でも不変のままであるため、すべてのサブシーケンスが構築されたすべてのサブシーケンスで表現可能なままであるためです。$c$。 

### なぜ効果があるのか

 配列に少なくとも 2 つの異なる値が含まれている場合は、異なる値を持つ 2 つの位置を選択します。 これら 2 つの値の間の遷移をエンコードするサブシーケンスは、慎重に選択したインデックスの削除に敏感にすることができます。これは、1 つの要素を削除すると、配列の繰り返しコピー間で必要な位置合わせが崩れる可能性があるためです。 の繰り返し$c$欠落している位置を除いてすべてのコピーが同一であるため、この脆弱性は除去されません。そのため、慎重に選択されたサブシーケンスが常に埋め込まれるとは限りません。 

すべての値が同一の場合、すべてのサブシーケンスは同一の要素の単なる文字列になります。 1 つの位置を削除しても、すべてのシンボルが同じであるという事実は変わりません。繰り返しは可用性を高めるだけです。 したがって、次のすべてのサブシーケンスは、$a$あらゆる可能なことの一部として残ります$c$、したがって無効です$b$存在します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        # check if all elements are the same
        first = a[0]
        ok = False
        for x in a:
            if x != first:
                ok = True
                break
        
        print("YES" if ok else "NO")

if __name__ == "__main__":
    solve()
```実装は、少なくとも 2 つの異なる値があるかどうかをチェックするリダクションを直接エンコードします。 不一致が見つかるとループは早期に終了し、テスト ケースごとの直線的な時間を確保します。 

ここでよくある間違いは、サブシーケンスのマッチングをシミュレートしようとしてロジックを複雑にしすぎてしまうことです。 重要なのは、その構造です。$c$唯一の意味のある特性は、要素の配置ではなく、要素の多様性になります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        first = a[0]
        ok = any(x != first for x in a)
        out.append("YES" if ok else "NO")
    return "\n".join(out)

# provided samples
assert run("3\n2\n1 1\n3\n1 2 1\n4\n5 4 1 1\n") == "NO\nYES\nYES"

# all equal minimum
assert run("1\n2\n7 7\n") == "NO"

# single deviation
assert run("1\n5\n9 9 9 1 9\n") == "YES"

# strictly increasing
assert run("1\n4\n1 2 3 4\n") == "YES"

# large uniform
assert run("1\n5\n5 5 5 5 5\n") == "NO"
```| テスト入力 | 期待される出力 | 検証内容 |

 ## 特殊なケース

 次のような完全に均一な配列$a = [4,4,4,4]$常にNOにつながります。 アルゴリズムは最初の値を 4 として読み取り、不一致を検出しないため、`ok`false のままで、正しく NO が生成されます。 

次のようなほぼ均一な配列$a = [10,10,10,11,10]$4 番目の要素で早期終了をトリガーします。 フラグはすぐに true になり、構造をさらに検査する必要なく YES が保証されます。 

長さ 2 の配列も正しく処理されます。 のために$a = [3,3]$、違いは存在しないため、答えはNOです。 のために$a = [3,5]$の場合、最初の比較ですでに区別性が検出され、YES が返されます。
