 ## 解決策
 ## 問題の理解

 英小文字の文字列が与えられます。 各操作により、2 つの異なる位置を選択し、同時に両方の文字をアルファベットで 1 つ後ろにシフトすることができます。シフトとは、次のことを意味します。`b`になる`a`、`c`になる`b`、など周期的に行われるため、`a`になる`z`。 

目標は、文字列内のすべての文字を次のように変換することです。`a`できるだけ少ない操作で。 各操作は常に 2 つのインデックスに影響を与え、影響を受ける各文字は 2 つのインデックスに一歩近づきます。`a`循環アルファベットで。 

重要な問題は、単一のキャラクターだけを操作することができないことです。 すべての減分は、文字列内の別の場所にある別の減分と組み合わせる必要があり、これにより、必要なすべての変換間にグローバルな結合が作成されます。 

入力サイズはすべてのテスト ケースで最大 200,000 文字に達するため、文字に対する操作を段階的にシミュレートするソリューションは除外されます。 正しい解決策は、テスト ケースごとに線形時間で問題をカウントとパリティ推論に削減する必要があります。 

必要な減少量の合計が奇数である場合、微妙なエッジケースが発生します。 各操作は正確に 2 つのデクリメントを実行するため、奇数の合計要求を満たすことはできません。 たとえば、文字列が次の場合、`"ab"`、各キャラクターに 1 つのデクリメントが必要なので、合計作業量は 2 で問題ありません。 しかし、文字列が`"aab"`、0 + 0 + 1 = 1 の合計減少量が必要ですが、これはペアにすることができないため、答えは次のようになります。`-1`。 

もう 1 つの明白ではないケースは、ペアリングは全体としては可能だが、分散により無駄な操作を避けることができない場合です。ただし、この問題ではインデックス間でどのようなペアリングも許可されるため、全体的な実現可能性のみが問題になります。 

## アプローチ

 ブルートフォース戦略では、プロセスを直接シミュレートします。 各ステップで、まだ作成されていない 2 つのインデックスを選択します。`a`そして両方の文字をデクリメントします。 すべての文字がなるまで繰り返します`a`。 これは操作定義を正確に反映しているので正しいですが、すぐに実行不可能になります。 

キャラクターが初期状態の場合`k`～から数歩離れたところ`a`、その場合は正確にデクリメントする必要があります`k`回。 すべての文字を合計すると、必要なデクリメントの合計数が得られます。 各操作はちょうど 2 つのデクリメントに寄与するため、操作の数はこの合計の約半分になります。 ブルート フォース アプローチは、このペアリングを明示的に効果的に実行するため、操作ごとに必要なデクリメントの合計数に比例する最悪の場合の複雑さが生じ、病理学的シミュレーションでは二次関数になる可能性があります。 

重要な点は、問題は文字の位置に関するものではなく、合計でどれだけのデクリメント単位が必要かということだけであるということです。 各操作は正確に 2 単位の減分を提供するため、唯一の障害は合計要件が偶数であるかどうかです。 これが成立すると、どのインデックスを一緒に選択できるかについての制約がないため、いつでもポジション間でデクリメントを任意に組み合わせることができます。 

したがって、問題はすべての文字の合計距離を計算することになります。`a`循環的な順序で実行可能性をチェックし、2 で割ります。

 ## アルゴリズムのチュートリアル

 1. キャラクターごとに、到達するまでに必要な歩数を計算します。`a`。 これは`(ord(c) - ord('a')) mod 26`。 

これは、キャラクターが必要とする正確なデクリメント数を測定します。 
2. これらの値を文字列全体で合計します。 

この合計は、すべてのキャラクターにわたって必要なユニット減少アクションの合計数を表します。 
3. この合計が偶数であるかどうかを確認します。 

各演算はちょうど 2 つの減分に寄与するため、奇数の合計を完全に一致させることはできません。 
4. 合計が奇数の場合は戻ります`-1`すぐに。 

必要な減分数の奇数に一致するように操作をペアにする方法はありません。 
5. それ以外の場合は、合計を 2 で割って、答えとして出力します。 

各操作で正確に 2 単位の要件が削除されるため、これが操作の最小数になります。 

### なぜ効果があるのか

 各操作により、必要な「距離」の合計が常に減少します。`a`どのインデックスが選択されているかに関係なく、正確に 2 で計算されます。つまり、合計は不変 mod 2 であり、すべての有効な操作シーケンスは、必要な減少の合計をペアに分割することに対応します。インデックスの組み合わせに制限がないため、残りの 2 つの非ゼロ要件は、すべての要件がなくなるまで常にまとめて削減できます。これにより、合計が重要な唯一の状態変数となり、プロセスはその値によって完全に決定されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input().strip())
        s = input().strip()

        total = 0
        for c in s:
            total += (ord(c) - ord('a'))

        if total % 2 == 1:
            print(-1)
        else:
            print(total // 2)

if __name__ == "__main__":
    solve()
```コードは各テスト ケースを個別に処理し、すべての文字を次のように変換するために必要な後方シフトの合計数を計算します。`a`。 各文字は、そのアルファベットの距離に影響します。`a`。 

パリティ チェックは中心的な正確性条件です。 合計が奇数の場合、すべての操作で 2 ユニットが消費されるため、ペアリングは不可能です。 偶数の場合、2 で割ると、必要な操作の正確な数が得られます。 

操作はインデックス間で完全に対称であるため、シミュレーションや貪欲なペアリングは必要ありません。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        s = input().strip()

        total = sum(ord(c) - ord('a') for c in s)
        if total % 2 == 1:
            out.append("-1")
        else:
            out.append(str(total // 2))

    return "\n".join(out)

# provided samples

assert run("1\n3\nabc\n") == "-1", "odd total requirement"
assert run("1\n4\nbbbb\n") == "4", "uniform distance case"
assert run("1\n5\naaaaa\n") == "0", "already done"

 ## 特殊なケース

 最小限だがトリッキーなケースは次のとおりです。`"ab"`。 ここで合計距離は 1 なので、答えは次のようになります。`-1`。 アルゴリズムは合計を 1 として正しく計算し、パリティのため直ちに拒否します。これは、必要な単一の減分をペアにすることができないという事実と一致します。 

2つ目のケースは、`"ba"`、合計距離も 1 です。たとえ 1 人のキャラクターがすでに近くにいたとしても、`a`、同じパリティ制約によって進行がブロックされ、アルゴリズムは再びリターンします。`-1`。 

のようなケース`"cc"`合計距離は 4 になります。アルゴリズムは 2 を出力します。これは、両方の文字が到達するまで繰り返しペアリングすることに対応します。`a`。 各操作では両方が同時に減少し、合計作業量がちょうど 2 だけ減少するという不変条件が完了するまでの各ステップで保持されます。
