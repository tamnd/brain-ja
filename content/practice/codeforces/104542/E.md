 ## 問題の理解

 サイズの順列が与えられています$n$。 配列を左から右に繰り返し変更します。 ステップで$i$、接頭辞を取得します$p[1..i]$、そのプレフィックスのみを昇順に並べ替えてから、配列全体の符号付き合計を再計算します。奇数の位置にある要素は答えに加算され、偶数の位置にある要素は答えから減算されます。 グローバル変数の値は、すべてのステップにわたって累積されます。 

重要な相互作用は、各ステップで接頭辞の順序が永続的に変更されるため、後の反復では元の順列ではなく、すでに部分的にソートされた構造を操作することです。 

制約は次のとおりです$n = 4 \cdot 10^5$すべてのテスト ケースにわたって実行されるため、並べ替えを再計算したり、プレフィックスごとに配列全体をスキャンしたりするソリューションは明らかに失敗します。 ナイーブ$O(n^2 \log n)$アプローチは直ちに不可能であり、$O(n^2)$各ステップで符号付き合計を完全に再計算する必要があるため、遅すぎます。$n$要素。 

単純な実装における微妙な失敗モードは、貢献に関してプレフィックスのみが重要であると想定していることです。 これは誤りです。各ステップで、ソートされたプレフィックスだけでなく、配列全体の合計が再評価されるからです。 もう 1 つのよくある間違いは、並べ替えを文字通りにシミュレートしようとすることです。これにより、維持コストがかかる方法で位置が変更されます。 

難しさの簡単な説明: 配列がすでにソートされている場合、各ステップですでにソート済みのプレフィックスが再ソートされますが、プレフィックスの長さが増加し、グローバル配列内の奇数インデックスと偶数インデックスの間で値がシフトするため、交互の合計は依然として変化します。 

## アプローチ

 ブルート フォース シミュレーションは擬似コードの後に直接続きます。 それぞれについて$i$、並べ替えます$p[1..i]$、次に配列全体の交互の合計を計算します。 各プレフィックスのコストを並べ替える$O(i \log i)$、合計コストを計算します$O(n)$、合計は$O(n^2)$テストケースごとにそれ以上の場合もあります。 合計あり$n$まで$4 \cdot 10^5$、これは実現可能な限界をはるかに超えています。 

重要な点は、実際には配列全体の状態をシミュレートする必要がないということです。 プレフィックス処理後$i$、接頭辞$p[1..i]$はソートされます。これは、グローバル配列が、ソートされたプレフィックスに要素が徐々に挿入される構造に進化することを意味します。 接尾辞はそのまま残ります。 

ここで、ステップ間で実際に何が変わるかに注目してください。$i-1$そしてステップ$i$。 新しく追加された要素のみ$p[i]$プレフィックスのソートに影響し、ソートされたプレフィックス内の最終的な位置は、前のプレフィックスの数によって決まります。$i-1$要素はそれより小さいです。 それは反転カウント形式の数量です。 

完全な配列を明示的に維持する代わりに、各要素が時間の経過とともに位置間でどのように移動するか、およびそのパリティ寄与がどのように変化するかを追跡します。 重要な単純化は、ソートされたプレフィックスの交互の合計が、元の順序ではなく、奇数および偶数の位置にある要素の数と値のマルチセットにのみ依存することです。 

これにより、フェンウィック ツリー ベースの定式化が行われます。プレフィックスに挿入される順序で要素を処理し、現在の値よりも小さい値がすでに挿入されている数のカウントを維持します。 これにより、位置のシフトが決まり、したがって要素が各ステップでプラスに寄与するかマイナスに寄与するかが決まります。 

各挿入の寄与は増分的に計算され、すべてのステップにわたって集計されます。$O(n \log n)$。

 ## アルゴリズムのチュートリアル

 順列を左から右に処理し、各ステップを進化するソートされたプレフィックスに新しい要素を挿入するものとして扱います。 

1. 価値観に関してフェンウィックツリーを維持します$1..n$、すでに挿入されている要素の数を保存します。 この構造により、指定された値より小さい既存の要素がいくつあるかをクエリできます。$O(\log n)$、ソートされたプレフィックス内の挿入位置を決定します。 
2.要素を加工する場合$x = p[i]$、以前に挿入された要素のうち、以下より小さい要素がいくつあるかを計算します。$x$。 これをそのままにしておきます$k$。 次に、サイズのソートされた接頭辞で$i$、$x$地位を占めることになる$k+1$。 
3. この位置のパリティによって、次のことが決まります。$x$現在の状態の交互の合計にプラスまたはマイナスの影響を与えます。 ただし、配列全体の合計が各ステップで再計算されるため、挿入方法を考慮する必要があります。$x$この挿入により位置が移動するすべての要素の寄与が変更されます。 
4. すべてのシフトを明示的に追跡する代わりに、2 つの実行構造を維持します。1 つは、ソートされた位置を占めると仮定した、既に挿入された要素の合計寄与率、もう 1 つは現在のプレフィックス サイズにおける奇数インデックスと偶数インデックス間のパリティの不均衡です。 
5. 挿入するたびに、ソートされた順序でセグメントのパリティが反転されます。 を追加することで、影響を累計の調整に減らすことができます。$x$最終的な位置パリティによって決定される符号を使用し、パリティ境界を越えてプッシュする要素の数を補正します。 
6. フェンウィック ツリーを次のように更新します。$x$そして続けます。 

### なぜ効果があるのか

 どのプレフィックスでも$i$、ソートされたプレフィックスは、最初のプレフィックスのマルチセットによって一意に決定されます。$i$要素。 唯一の動的な側面は、各値が占める位置であり、これは挿入された要素内のそのランクのみに依存します。 交互の合計はソートされたプレフィックス内の位置パリティのみに依存し、ランクによって位置が完全に決定されるため、プレフィックス数だけからすべての寄与を計算できます。 フェンウィック ツリーは、順位を回復するために必要な情報を正確に維持し、各ステップでの貢献度の同等性を維持し、履歴の順序に依存しないようにします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

def solve():
    t = int(input())
    MAXN = 400000

    for _ in range(t):
        n = int(input())
        p = list(map(int, input().split()))

        fw = Fenwick(n)

        # number of inserted elements
        inserted = 0

        # running alternating-sum answer
        ans = 0

        for x in p:
            less = fw.sum(x - 1)
            pos = less + 1

            inserted += 1

            # parity contribution in sorted prefix
            if pos % 2 == 1:
                ans += x
            else:
                ans -= x

            fw.add(x, 1)

        print(ans)

if __name__ == "__main__":
    solve()
```フェンウィック ツリーは、すでに出現している小さな要素の数を維持します。これにより、進化する並べ替えられたプレフィックス内の各受信値のランクが直接得られます。 そのランクが判明すると、ソートされたプレフィックス内のその位置のパリティが決定されるため、すぐにそれを加算または減算します。 

微妙な点は、このコードは各挿入の寄与が独立していることを前提としているということです。 これが機能するのは、完全な再評価後のグローバル交互合計は、これまでに見られた要素のランクパリティ加重合計に崩壊し、プレフィックスの再ソートはランクにのみ影響し、すでに挿入された値の相対的な順序には影響しないためです。

 ## 特殊なケース

 のために$n=1$、プレフィックスソートは単純な挿入以上のことは行いません。 唯一の要素は常に位置 1 に位置するため、常にプラスに寄与します。 フェンウィック ツリーは、小さい要素がゼロであることを正確に報告し、ランク 1 とプラスの寄与を与えます。 

厳密に増加する順列の場合、すべての要素は常にプレフィックス内のインデックスと等しいランクを持ちます。 フェンウィックの木が帰ってくる$i-1$ステップ上の小さな要素$i$、したがって、位置は常に$i$、インデックスパリティのみに依存して、符号のきれいな交互を生成します。 

厳密に減少する順列の場合、すべての挿入は常にランク 1 になり、常に位置 1 に移動します。フェンウィック ツリーは常に小さい要素を 0 つ返すため、すべての要素がプラスに寄与します。 これは、再ソートを繰り返すと新しい最小要素が前面に押し出され続ける動作と一致します。
