 ## 解決策
 ## 問題の理解

 パン屋には限られた量の生地と数種類の詰め物があります。 詰め物のないパンは生地のみを消費し、一定のお金を与えます。 詰めパンは生地と 1 つの詰め物の種類の固定量を消費し、詰め物の種類ごとに独自の残りの数量と利益があります。 

タスクは、合計の利益ができるだけ大きくなるように、各種類のパンを何個焼くかを決定することです。 最終的に使われずに残った素材は廃棄できるため、目標は収益の最大化のみです。 

入力により、生地の総量、詰め物の種類の数、および空のパンのレシピが得られます。 それぞれの詰め物の種類には、利用可能な詰め物の量、1 つのパンで消費される詰め物と生地の量、およびそのパンがどれだけの収入を得るのかが記載されています。 アウトプットは可能な限りの金額です。 

制限は動的プログラミングにとって十分小さいものです。 生地の量は最大 1000 で、詰め物の種類の数は最大 10 です。生地の量と詰め物の数に応じた解決策は簡単に当てはまりますが、すべての詰め物の種類に対して可能な限りの数のバンズを試行すると爆発的になります。 たとえば、各スタッフィング タイプで約 100 個の選択肢が許可されている場合、すべての組み合わせを直接列挙すると、ほぼ 100 個の選択肢が得られる可能性があります。$100^{10}$、それは不可能です。 

難しいケースは、リソースの制限と、異なるパンの種類間の相互作用に関連しています。 詰めるタイプは利益が大きくても生地代が高すぎてダメかもしれません。 例えば：```
10 1 2 1
100 1 20 1000
```正しい出力は次のとおりです。```
5
```パン 1 個あたりの利益のみを比較する不注意な解決策では、詰めたパンを選択することになりますが、生地の要件は 20 で、生地は 10 個しか存在しません。 選択できるのは空のパンが 5 つだけです。 

もう 1 つのエッジ ケースは、生地がなくなる前に詰め物の種類がなくなる場合です。 例えば：```
10 1 2 1
3 1 1 100
```正しい出力は次のとおりです。```
301
```3 つの詰め物バンズには 3 つの生地と 3 つの詰め物が使用され、3 つの空のバンズには残りの 7 つの生地が使用されます。 詰め物を無制限として扱う実装では、高価な詰め物パンが誤って追加され続けます。 

3 番目のケースは、複数の種類の詰め物が同じ生地をめぐって競合する場合です。 例えば：```
5 2 5 10
5 1 2 6
5 1 3 100
```正しい出力は次のとおりです。```
100
```2 番目の詰め物を選択すると、高価なパンが 1 個得られますが、残りの生地では別の空のパンを作るのに十分ではありません。 生地単位あたりの利益のみに基づいた貪欲な選択は、利用可能な数量によって制限された選択の問題が生じるため、失敗する可能性があります。 

## アプローチ

 簡単なアイデアは、考えられるベーキングの選択肢をすべてシミュレートすることです。 詰め物の種類ごとに、バンズを 0 つ、バンズを 1 つ、バンズを 2 つと、詰め物または生地がなくなるまで焼いてみることができます。 すべての詰め物の種類の量を選択した後、残りの生地を空のバンズに変換できます。 これが機能するのは、考えられる有効なベーキング プランがすべて考慮されているためです。 

問題は組み合わせの数です。 10 種類のスタッフィングのそれぞれで約 100 の可能な数量が許可されている場合、総当たり検索では大まかに検査されます。$100^{10}$combinations. 詰める種類の数は少ないとはいえ、制限時間内に実行できる量をはるかに超えています。 

重要な観察は、生地が共有リソースであるということです。 いくつかの種類の詰め物を処理した後、以前の選択に関して必要な情報は、どれだけの生地が残っているか、およびその使用済み生地の量から得られる最大の利益だけです。 これはまさにナップザック動的プログラミングの構造です。 

考えられる各ぬいぐるみパンをアイテムとして扱うことができますが、同じアイテムのコピーが多数存在する可能性があります。 生地の制限は 1000 個のみなので、すべての詰め物の種類を個別のバンズに拡張できます。 100 グラムの詰め物を含む詰め物タイプと 5 グラムの詰め物を必要とするレシピでは、最大 20 部のコピーが作成されます。 すべてのタイプにわたって、これは小さいです。 

すべての詰め物をしたバンズを境界付きナップサックで処理したら、残った唯一の決定事項は、空のバンズに残った生地をどのように使うかです。 これは、DP 移行中に、またはその後に可能なすべての残量をチェックすることによって行うことができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(100^{m})$最悪の場合 |$O(m)$| 遅すぎる |
 | 最適 |$O(n \cdot \sum count_i)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 動的プログラミング配列を作成します。`dp[x]`正確に使用した後に達成可能な最大利益を表します`x`これまでに加工された詰めパン用の生地のグラム数。 最初は、生地を使用しないと利益がゼロになり、他のすべての状態は不可能になります。 
2. 詰め物のタイプごとに、利用可能な詰め物からこのタイプのバンズをいくつ作成できるかを計算します。 この番号は`a_i // b_i`。 これらのパンのそれぞれの消費量は、`c_i`生地のグラム数と収入`d_i`お金。 
3. 可能な限りすべてのぬいぐるみパンをナップサックに加えます。 同じパンのコピーを複数回使用できないように、コピーごとに生地の状態を逆の順序で更新します。 
4. すべての種類の詰め物を加工した後、詰め物バンズに使用する生地の可能な量を考慮します。 からの利益を追加します`dp[x]`残りの生地を空のパンに変えて得たお金。 最良の値が答えです。 

逆反復が使用される理由は、個々の饅頭の詰め物が個別に利用可能なオブジェクトであるためです。 少量の生地から更新した場合、1 回の遷移中に同じオブジェクトがすぐに複数回再利用される可能性があります。 

これが機能する理由: 動的プログラミングの不変条件は、いくつかの饅頭を処理した後、`dp[x]`あらゆる方法の中で可能な限り最高の利益を正確に保存します`x`それらのバンズを使った生地。 すべてのぬいぐるみのパンは無視されるか、一度追加されます。これは、境界のあるナップサック アイテムの 2 つの可能性です。 すべての詰めたバンズが考慮された後、空のバンズは詰め物の決定に影響を与えないため、残りの生地を最終的にスキャンして、可能な限り最良の組み合わせが選択されます。 すべての有効なベーキング プランは 1 つの DP 選択シーケンスに対応し、すべての DP の選択は有効なベーキング プランを表すため、見つかった最大値が最適になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, c0, d0 = map(int, input().split())

    buns = []
    for _ in range(m):
        a, b, c, d = map(int, input().split())
        cnt = a // b
        for _ in range(cnt):
            buns.append((c, d))

    neg = -10**18
    dp = [neg] * (n + 1)
    dp[0] = 0

    for cost, value in buns:
        for dough in range(n, cost - 1, -1):
            if dp[dough - cost] != neg:
                dp[dough] = max(dp[dough], dp[dough - cost] + value)

    ans = 0
    for used in range(n + 1):
        if dp[used] != neg:
            remaining = n - used
            ans = max(ans, dp[used] + (remaining // c0) * d0)

    print(ans)

if __name__ == "__main__":
    solve()
```入力セクションでは、まず各詰め物の種類を個別の詰めパンに展開します。 レシピは詰め物が残っている間のみ使用できるため、コピーの数は生地ではなく、利用可能な詰め物によって制限されます。 

DP 配列は、到達不可能な状態に対して非常に負の値を使用します。 遷移では、新しいパンを追加する前に、前の状態が存在するかどうかがチェックされます。 詰められたバンズは綴じられたコピーであるため、生地上のループは下向きになります。 この指示がなければ、1 つのコピーが複数回貢献する可能性があります。 

最後のループでは、空のパンを個別に処理します。 すでに詰められたバンズに費やされた一定量の生地の場合、残りの生地の用途は 1 つだけです。それは、できるだけ多くの空のバンズを作ることです。 

Python の整数はオーバーフローしないため、大きな負のセンチネルは、不可能な状態をマークする場合にのみ必要です。 生地のインデックスは次のとおりです。`0`に`n`、つまり遷移境界`range(n, cost - 1, -1)`負のインデックスへのアクセスを回避します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(n \cdot k)$|`k`は拡張後の個々の詰めパンの総数ですが、各詰め込み量は最大 100 個で、種類も最大 10 個であるため少ないです。 
| スペース |$O(n)$| DP 配列には、使用可能な生地の量ごとに 1 つの値が格納されます。 

最大生地量は1000個のみなので、1次元のナップザックが快適にメモリに収まります。 スタッフィング数が制限されているため、遷移の総数も少なくなり、動的プログラミング手法を制約内で簡単に実行できます。 

## テストケース```python
import sys
import io

def solution(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)

    n, m, c0, d0 = map(int, sys.stdin.readline().split())
    buns = []

    for _ in range(m):
        a, b, c, d = map(int, sys.stdin.readline().split())
        for _ in range(a // b):
            buns.append((c, d))

    neg = -10**18
    dp = [neg] * (n + 1)
    dp[0] = 0

    for c, d in buns:
        for x in range(n, c - 1, -1):
            if dp[x - c] != neg:
                dp[x] = max(dp[x], dp[x - c] + d)

    ans = 0
    for x in range(n + 1):
        if dp[x] != neg:
            ans = max(ans, dp[x] + (n - x) // c0 * d0)

    sys.stdin = old_stdin
    return str(ans) + "\n"

## 特殊なケース

 手頃な価格の詰め物ケースの場合:```
10 1 2 1
100 1 20 1000
```拡張された詰め物パンには 20 個の生地が必要ですが、生地の制限が 10 であるため、DP はそれを使用してもどの状態にも到達できません。到達可能な状態は、パンが 5 つで利益 5 を与える空のバンズの決定のみです。 

限定スタッフィングケースの場合：```
10 1 2 1
100 1 20 1000
```詰め込みが制限されている重要なバージョンは次のとおりです。```
10 1 2 1
3 1 1 100
```DP はぬいぐるみパンのコピーを 3 部作成します。 3 つすべてを使用すると、生地の使用量が 3 になり、利益が 300 になります。残りの 7 つの生地から 3 つの空のパンが作成され、レシピで正確な解釈が可能であれば、最終値は 303 になります。 前の例では、計算は空のパンのコストに依存するため、アルゴリズムは固定の組み合わせを仮定するのではなく、残りの生地の量をすべて直接評価します。 

競合するスタッフィングの選択肢については、次のとおりです。```
5 2 5 10
5 1 2 6
5 1 3 100
```DP は、2 種類の饅頭の有効な組み合わせをすべて比較します。 生地の使用ごとにより良い利益を維持し、最終的には高価な 2 番目のタイプのパンを 1 つ選択します。 生地ごとの利益に基づく貪欲な方法では、特定の量しか入手できないという事実を正しく処理できません。
