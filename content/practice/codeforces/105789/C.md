 ## 解決策
 ## 問題の理解

 私たちは毎日の気温の順序と、限られた範囲でのみ使用できるコートを与えられています。 何日も着続けると汚れてしまい、洗わないと二度と使えなくなります。 必要に応じて早めに洗濯するなど、洗濯日は自由に選択できますが、コートを着ない日は天候にさらされます。 

目標は、コートを塗らない日数やそのような付加的なものを最小限に抑えることではありません。 その代わりに、私たちはコートを着ない日の中で最悪の日を気にします。 コートなしで直面する最も寒い日をできるだけ暖かく過ごせるように、着用と洗濯をスケジュールしたいと思います。 

目標を捉えるもう 1 つの方法は、温度しきい値 T を最大化して、温度が T 未満の毎日は安全にコートで覆われ、T より高い日は、洗濯の制約を考慮して制御されたバーストでのみコートなしでよいことを保証できるようにすることです。 

主要な構造上の制約は、コートの使用制限 C に由来します。コートを着用しない日が C 日を超えて連続して続くことは、洗濯も中断もせずに連続 C 日を超えてコートを着用することを意味するため、維持することは不可能です。 

入力は、単純に N 日間の気温のリストと、最大連続コート使用量を表す整数 C です。 出力は、最適な戦略の下でコートのない日の中で達成可能な最高の最低気温を表す単一の整数です。 

主な困難は、個々の日を独立して選択できないことです。 この制約は連続する日数を組み合わせているため、コートを着ない日についてのローカルな決定によって、世界的に実行不可能になる可能性があります。 

連続した構造をチェックせずに、すべての「悪い」（暖かい）日を貪欲にコートなしとしてマークしようとすると、微妙な失敗例が現れます。 

たとえば、N = 6、C = 2、および温度を考えてみましょう。`[5, 5, 5, 5, 5, 5]`。 しきい値 T = 5 を決定すると、すべての日がコートレスになり、長さ 6 の単一セグメントが形成されます。C = 2 であるため、これは無効です。 コートを着ていない日数の合計のみをカウントする単純なアプローチでは、この構成が誤って受け入れられてしまいます。 

コートのない日が複数のセグメントに分割される場合、別の特殊なケースが発生します。 例えば、`[10, -100, 10]`C = 1 およびしきい値 T = 10 の場合、コートレス パターンが生成されます`[1, 0, 1]`これは、コートレス数の合計が 2 であっても、長さ 1 を超えるセグメントがないため有効です。連続性を無視した解決策は、実現可能性を誤って評価することになります。 

これらの観察は、実現可能性が全体的なカウントではなく、連続するランレングスに完全に依存することを示しています。 

## アプローチ

 直接的なアプローチは、しきい値 T を推測し、連続したコートのない期間の制約に違反することなく、すべてのコートのない日の気温が少なくとも T になるように強制できるかどうかを確認することです。 固定 T の場合、気温が少なくとも T の毎日をコートなしとしてマークします。 次に、配列をスキャンして、そのような日の最長連続実行を測定します。 その実行が C を超える場合、しきい値は不可能です。 

この総当り攻撃が機能するのは、条件が毎日がしきい値を超えるかどうかのみに依存するためです。そのため、各候補 T が配列の 2 値分類を誘導します。 ただし、考えられるすべての T 値を試すには、最大 101 回のチェックが必要です (温度は -50 ～ 50 度の範囲にあるため)。それぞれのスキャンに N 日かかります。 これにより、約 100N 回の操作が行われ、N が 10^5 まで許容されます。 

気温に制限がない場合は、代わりに一意の値を並べ替えたり、二分探索 T を使用したりできます。実現可能性のチェックは単調です。しきい値 T が機能する場合、それよりも低いしきい値も機能します。これは、コートのない日が減り、実行期間が長くなることはないためです。 この単調性により、O(N log N) での二分探索が可能になります。 

別の観点から見ると、しきい値が完全に回避されます。 サイズ C + 1 のウィンドウを配列上でスライドさせることができます。 コートは C 日を超えて継続的に着用できないため、そのようなウィンドウでは、有効なスケジュール戦略の下で少なくとも 1 日はコートを着ないことが保証されます。 窓ごとに最高温度を計算します。これは、その窓でコートを着ない日が続く場合の最悪の暴露を表します。 答えは、これらの最大値のすべての窓にわたって最小値になります。 これにより、問題は古典的なスライディング ウィンドウの最小値と最大値の構造に変換され、単調デキューで解決できます。 

この構造を理解するもう 1 つの方法は、完全にコートのない世界から始めて、最も寒い日を最初に徐々に「保護」することです。 最低温度から上向きに保護を再導入するにつれて、連続したコートのないセグメントを追跡します。 すべてのセグメントが最大 ℃ の長さに収縮した瞬間に、最適なカットオフ温度に到達します。 

これらのビューはすべて同等です。 スライディング ウィンドウとしきい値シミュレーションは、最も直接的で実装が簡単です。

 ## アルゴリズムのチュートリアル

 スライディング ウィンドウ解釈を使用します。これにより、明示的なしきい値の列挙が回避され、制限構造が直接計算されます。 

### ステップ

 1. 配列内の長さ C + 1 のすべての連続セグメントを考慮します。 このウィンドウ サイズの理由は、コート制約の違反は、コートの使用量が C (正確に C + 1 連続コートなし日数に相当する) を超えるブロック内に現れる必要があるためです。 
2. このような窓ごとに、その中の最高温度を計算します。 この値は、そのウィンドウ全体に少なくとも 1 日コートを着ない日が強制的に含まれた場合の「最悪の暴露ポイント」を表します。 
3. これらすべてのウィンドウ最大値を超える実行最小値を維持します。 すべての有効なスケジュールはすべてのローカル制約ウィンドウを尊重する必要があるため、この集計により、可能な限り最良のグローバル保証が得られます。 
4. 要素のインデックスを温度の降順に格納する単調デキューを使用して、ウィンドウの最大値を効率的に計算します。 ウィンドウをスライドさせると、古いインデックスが削除され、フロントが最大値として維持されます。 
5. すべてのウィンドウを処理した後、記録された最小値と最大値を出力します。 

各ステップは、実現可能性がグローバルな分布ではなく、最悪の連続違反によって制御されるという観察に基づいて推進されます。 

### なぜ効果があるのか

有効な戦略では、長さ C + 1 のすべてのセグメントで、少なくとも 1 日はコートのない日が保証される必要があります。 そうしないと、コートを C 日以上継続して使用することになり、これは不可能です。 これにより、そのようなすべてのセグメントが少なくとも 1 つの温度を「露出」するようになります。 避けられない最高の暴露を考慮しているため、セグメント内の最悪の暴露温度はその最大値によって決まります。 すべてのセグメントを最小化することで、アレイ内のどこでも避けられない過度の低温暴露を回避するしきい値を確実に選択できます。 

これにより、グローバル スケジューリング問題が、制限要因が最悪のウィンドウとなるローカル ウィンドウ制約問題に変換されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n, c = map(int, input().split())
    a = list(map(int, input().split()))
    
    if c >= n:
        print(max(a))
        return

    k = c + 1
    dq = deque()
    best = float('inf')

    for i, x in enumerate(a):
        while dq and dq[-1][1] <= x:
            dq.pop()
        dq.append((i, x))

        while dq and dq[0][0] <= i - k:
            dq.popleft()

        if i >= k - 1:
            best = min(best, dq[0][1])

    print(best)

if __name__ == "__main__":
    solve()
```実装では、サイズ C + 1 のスライディング ウィンドウごとに候補最大値のデックが維持されます。各要素はインデックスとともに保存されるため、現在のウィンドウの外にある要素は破棄できます。 デキューは温度の降順に保持されるため、フロントは常に現在のウィンドウの最大値を示します。 

特殊なケース C >= N は個別に処理されます。 その場合、連続使用制限によってコートが使用できなくなることはありません。そのため、制限的な方法で洗濯しないことを効果的に選択できます。また、別の選択をしない限りコートなしになることを回避できるため、答えはアレイの最高温度に下がります。 

最も微妙な部分は、ウィンドウのメンテナンスです。状態`i >= k - 1`これにより、最初の完全なウィンドウが形成された後にのみ有効なウィンドウの記録が開始され、インデックスのプルーニングによってスライド時の正確さが保証されます。 

## 実用的な例

 ### 例 1

 入力:`N = 5, C = 1, A = [3, 1, 4, 1, 5]`ウィンドウ サイズ C + 1 = 2 を使用します。 

| 私 | 値 | デキュー (インデックス,値) | ウィンドウ最大 | 最高 |
 | --- | --- | --- | --- | --- |
 | 0 | 3 | (0,3) | - | インフ |
 | 1 | 1 | (0,3),(1,1) | 3 | 3 |
 | 2 | 4 | (2,4) | 4 | 3 |
 | 3 | 1 | (2,4),(3,1) | 4 | 3 |
 | 4 | 5 | (4,5) | 5 | 3 |

 最終的な答えは 3 です。 

これは、5 が最高温度であっても、長さ 2 のウィンドウ内での避けられない暴露は可能な限り最小のウィンドウ最大値によって決まり、達成可能な最良のカットオフはより緊密な局所構造によって制限されることを裏付けています。 

### 例 2

 入力:`N = 4, C = 2, A = [2, 2, 2, 2]`ウィンドウサイズは3です。 

| 私 | 値 | デク | ウィンドウ最大 | 最高 |
 | --- | --- | --- | --- | --- |
 | 0 | 2 | (0,2) | - | インフ |
 | 1 | 2 | (0,2),(1,2) | - | インフ |
 | 2 | 2 | (0,2),(1,2),(2,2) | 2 | 2 |
 | 3 | 2 | (1,2)、(2,2)、(3,2) | 2 | 2 |

 最終的な答えは 2 です。 

これは、すべての値が同一の場合、すべてのウィンドウの最大値が同じであり、制約によって強制的に縮小が行われないことを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N) | 各要素は、ウィンドウの最大値を維持しながら、両端キューに 1 回出入りします。 
| スペース | O(C) | Deque は最大で C + 1 要素を格納します。 

このアルゴリズムは、N の最大 10^5 の制限内で快適に実行されます。 各操作は一定の償却時間であり、メモリ使用量は配列全体ではなくウィンドウ サイズ内で線形です。

 ## 特殊なケース

 特殊なケースの 1 つは、C が 0 の場合です。これは、連続した日にコートをまったく着ることができないことを意味します。 入力用`N = 6, C = 0, A = [1, 2, 3, 4, 5, 6]`、アルゴリズムはウィンドウ サイズ 1 を使用します。各ウィンドウの最大値は要素そのものであるため、すべてのウィンドウの最小値は 1 です。両端キューは各要素を個別に処理し、すべてのウィンドウが分離されているため、隣接関係の問題は発生しません。 これは、毎日がコートなしで強制的に露出されるという事実と一致します。 

もう 1 つのエッジ ケースは、C が非常に大きい場合です。`N = 5, C = 10, A = [3, 1, 4, 1, 5]`。 ここでは、条件は決してバインドされないため、サイズ C + 1 のウィンドウは配列内に完全に存在しません。 アルゴリズムは最高温度 (5) を直接返します。特別なチェック`if c >= n`空のウィンドウロジックを実行しないようにします。 

3 番目のケースは、次のような均一な配列です。`A = [7, 7, 7, 7]`すべてのウィンドウの最大値は 7 であるため、実行中の最小値は 7 のままです。両端キューは常に 1 つの代表的なインデックスに折りたたまれ、セグメンテーションに関係なく出力は安定したままになります。
