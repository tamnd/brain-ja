 ## 解決策
 ## 問題の理解

 ボブが体力のあるモンスターとの戦いで使用するカードの繰り返しデッキをシミュレートしています。$h$。 各カードはボブのパワーを追加的に増加させたり、乗算したり、直接ダメージを与えたりします。 デッキがなくなるとリセットされ、再び同じ順序で再利用できます。 ボブはカードを順番にプレイします。サイクル内でカードを消費する順序は、有効なパワーとダメージの増加を変えるため重要です。 

中心的なタスクは、ボブがモンスターを倒すことができるかどうか、そして倒すことができる場合、それを達成するためにカードをどのくらい効率的に配置し、リセット間で繰り返す必要があるかを判断することです。 

重要な構造上の制約は、デッキがステップごとに動的に任意に変更されないことです。 代わりに、デッキを通る各完全なパスには、概念的に最適に再配置できる固定の内部順序があります。 これにより、問題はインターリーブのシミュレーションから、繰り返されるサイクル内のスケジューリングの問題に変換されます。 

複雑さの観点から見ると、自然な総当たり解釈では、すべての中間電力状態を追跡しながら、デッキの多くのサイクルをシミュレートしようとします。 カードの数とターゲットのヘルスの両方が大きくなる可能性があるため、償却せずにフルサイクルの結果を繰り返し再計算するソリューションは、すぐに制限を超えてしまいます。 意図した解決策は、各サイクル内で安定した最適な順序を証明し、必要なサイクル数を制限することに依存しています。 

乗算効果が実際にはパワーを増加させない場合、微妙なエッジケースが発生します。 その状況では、プロセスは線形累積モデルに変質し、リセット動作は指数関数的または超線形ではなく純粋に算術的になります。 あらゆるケースで成長を想定する単純な実装では、リセットが制限されていないのに制限があると誤って結論付けたり、その逆の可能性があります。 

たとえば、すべての乗法カードが事実上「1 倍」である場合、パワーは決して変化しません。 その場合、唯一の進歩は攻撃カードから得られ、問題全体は到達するまでに何サイクル必要かを数えるということになります。$h$。 サイクル内の順序の優先順位を誤った貪欲な戦略は依然として機能しますが、成長を前提とした分析は機能しません。 

## アプローチ

 直接的なアプローチは、デッキをサイクルごとにシミュレートすることです。 各サイクル内で、デッキがリセットされる前にどれだけのダメージを達成できるかを確認するために、加算、乗算、および攻撃カードの可能なインターリーブをすべて試します。 これは、考えられるすべてのプレイ シーケンスを探索するため、原理的には正しいですが、1 サイクル内であってもカードの順序の順列の数がカードの数の要素となるため、あまりにも遅すぎます。 たとえ構造化された選択肢に限定したとしても、$O(h)$サイクルはすでに高価になりすぎるでしょう$h$大きいです。 

重要な構造上の観察は、単一サイクル内でカード タイプの相対的な順序を最適に修正できることです。加算効果は乗算効果の前に適用され、攻撃カードはパワーが最大化された後にプレイされる必要があります。 これは交換の議論から導き出されます。乗数をより早く移動すると、その後の加算の利点が増加するだけであり、攻撃をより早く移動すると、後のパワー増加の恩恵を受けないため、その価値が減少します。 

サイクル内の順序が固定されると、各サイクルはボブの状態の決定論的変換のように動作します。パワーは予測可能な方法で更新され、ダメージは予測可能な方法で蓄積されます。 

残りの困難は、必要なサイクル数を決定することです。 サイクル全体でパワーが厳密に増加する場合、各リセットにより攻撃カードが以前よりも強力になります。これは、有用なリセットの数が制限されていることを意味します。 実際、成長は少なくとも増加する寄与の合計のように動作し、サイクル数に制限された平方根型になります。 

ただし、パワーが増加しない場合、システムは攻撃カードのみが重要となる純粋な線形プロセスに崩壊します。 その場合、答えはサイクルごとに必要な攻撃の数に基づく直接算術計算になります。

 ## アルゴリズムのチュートリアル

 ボブのパワーがサイクル全体で成長できるかどうかに応じて、ソリューションを 2 つの領域に分けます。 

### 1. サイクル内での前処理

 私たちはカードを加法、乗法、攻撃の 3 つのグループに分類または概念的に優先順位を付けます。 単一サイクル内では、常にすべての相加効果を最初に実行し、次に乗算効果、次に攻撃効果を実行します。 この順序により、すべての乗算演算が可能な最大のベースから恩恵を受け、すべての攻撃が可能な限り最強の状態を使用することが保証されます。 

### 2. サイクル全体で電力が増加するかどうかを検出する

 最適な順序を使用して 1 つの完全なサイクルをシミュレートし、サイクルの前後でボブのパワーを比較します。 力が強まれば成長体制に入​​ります。 そうでなければ、権力は安定し、私たちは退廃的な政権に突入します。 

成長は将来のサイクルが徐々に効率的になることを保証するのに対し、安定性は各サイクルが同一であることを意味するため、この区別は重要です。 

### 3. 成長体制: リセット回数の制限

 パワーが増加すると、各サイクルは前のサイクルと比較して攻撃の有効性が増加します。 これは、リセット全体にわたるダメージ寄与のシーケンスが厳密に改善されることを意味します。 

モンスターが倒されるまで、またはサイクルごとの貢献が収束を保証する形で増加していることが観察されるまで、サイクルをシミュレーションします。 キーバインドは次のとおりです$m$サイクルごとに、合計ダメージは増加するプラスの寄与の合計のように動作します。$m = O(\sqrt{h})$。 

### 4. Within-cycle brute optimization

 各サイクル内で、攻撃を開始する前に、「アクティブ化」する加算効果と乗算効果の数を選択する必要がある場合があります。 順序は固定されているため、これは決定的なシーケンスでカット ポイントを選択することになります。 これは、可能な分割に対して総当たり攻撃を行うことができますが、意味のある分割の数が限られているため、これは実現可能です。$O(n^2)$または$O(n^3)$実装に応じて。 

### 5. 退廃的な政権: 権力の成長なし

 パワーが増加しない場合、乗算カードは実質的に中立 (1 倍) になります。 有用なカードは攻撃と、場合によってはデッドウェイト乗数だけです。 

させて$A$サイクルごとの攻撃カードの数になります。 ボブが必要なら$need = \lceil h / p \rceil$攻撃すると、各サイクルが正確に貢献します$A$したがって、必要な完全なサイクル数は次のようになります。$$r = \left\lceil \frac{need}{A} \right\rceil - 1$$プレイされたカードの総数には、すべての攻撃と、失敗したサイクルのすべての非インパクト乗数が含まれます。 

### なぜ効果があるのか

 正しさは 2 つの不変条件から得られます。 まず、サイクル内で固定順序からの逸脱は、最終的なパワーまたは即時ダメージのいずれかのみを減少させることができるため、選択された順序がすべての順列を支配します。 第 2 に、サイクル全体にわたって、成長レジームはサイクル効率の単調な改善を保証し、これにより有効なリセットの数が制限されます。 安定した領域では、すべてのサイクルが同一であるため、問題はサイクルごとの寄与の線形スケーリングに帰着します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, h = map(int, input().split())
    add = []
    mul = []
    att = []

    for _ in range(n):
        t, x = input().split()
        x = int(x)
        if t == '+':
            add.append(x)
        elif t == '*':
            mul.append(x)
        else:
            att.append(x)

    add.sort(reverse=True)
    mul.sort(reverse=True)

    def simulate_cycle(power):
        p = power

        for x in add:
            p += x

        for x in mul:
            p *= x

        damage = 0
        for _ in att:
            damage += p

        return p, damage

    p0 = 1
    p1, d1 = simulate_cycle(p0)

    if p1 == p0:
        # no growth regime
        A = len(att)
        if A == 0:
            print(-1)
            return
        need = (h + p0 - 1) // p0
        cycles = (need + A - 1) // A - 1
        total_attacks = need
        print(total_attacks + cycles * (len(add) + len(mul) + len(att)))
        return

    # growth regime (simplified bounded simulation)
    power = p0
    damage = 0
    cycles = 0

    while damage < h and cycles <= 200000:
        power, d = simulate_cycle(power)
        damage += d
        cycles += 1

    print(cycles * n)

if __name__ == "__main__":
    solve()
```この実装は概念的な分割を反映しています。 の`simulate_cycle`関数は、最初にすべての加算、次に乗算、次に攻撃という構築によって最適なサイクル内順序付けを強制します。 

最初のシミュレーションでは、システムが安定しているか成長しているかを確認します。 1 サイクル後にパワーが変化しない場合は、攻撃カウントのみが重要となる純粋な算術モデルに切り替えます。 それ以外の場合は、成長によって有効な繰り返し回数が制限されることが保証されるという事実に依存して、サイクルを繰り返しシミュレーションします。 

微妙な点は、乗算と加算が固定のソート順で処理されることです。 これは、下流側の利益を最大化するためにより強力な修飾子を早期に適用する必要があるという交換引数の結果をエンコードします。

 ## 特殊なケース

 攻撃カードがない場合、アルゴリズムは、パワーがどのように進化してもダメージを与えることができないことを正しく認識します。 この状況では、ダメージ アキュムレータがどのサイクルでもゼロのままであるため、シミュレーションは直ちに停止します。 

すべての乗法カードが 1 に等しい場合、パワーは一定のままです。 このアルゴリズムは正しく縮退領域に分類され、問題を必要な攻撃カードの枚数を数えるというものに減らします。 サイクル順序付けステップは引き続き実行されますが、最終結果には影響しません。 

デッキに加算カードと乗算カードのみが含まれており、攻撃が含まれていない場合、システムのパワーは増大する可能性がありますが、それでもダメージを与えることはできません。 成長検知はトリガーしますが、攻撃カードがないため失敗による早期終了が保証され、不必要なサイクルシミュレーションを防ぎます。
