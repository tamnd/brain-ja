 ## 解決策
 ## 問題の理解

 各テスト ケースは、単一の 7 セグメント LED 桁表示の状態を記述しますが、表示は不完全で曖昧です。 きれいな数字の代わりに、7 つのセグメントはそれぞれ、いくつかの状態のいずれかで表示されます。入力で使用されるシンボルに応じて、明示的にオン、明示的にオフ、または不確実またはいずれの状態とも互換性がない場合があります。 

タスクは、そのような表示のシーケンス内の各位置について、0 から 9 までのどの数字が観察されたセグメント パターンを生成した可能性があるかを判断することです。 正確に 1 桁が観察された LED 構成と一致する場合、その桁を出力します。 一致する数字がない場合、または複数の数字が一致する場合は、ワイルドカード記号が出力されます。`*`。 

重要な点は、各位置が独立しているため、一連の入力にわたって同じ 7 セグメント分類問題を繰り返し解くことになります。 

入力サイズは位置ごとの構造が小さいため、10 個の可能な桁に対して 7 個の LED のみがチェックされます。 これは、位置ごとにすべての桁に対する総当り攻撃も実行可能であることを直ちに示唆しています。 制約のプレッシャーは、漸近的な成長ではなく、桁ごとのチェックをクリーンかつ効率的に実装することにあります。 

エッジケースはセグメント状態のあいまいさから生じます。 たとえば、すべてのセグメントがオン状態とオフ状態の両方と互換性がある、完全に許容的なディスプレイでは、すべての桁が一致し、次のようになります。`*`。 逆に、一部のセグメントがオンとオフの両方の動作を同時に必要とする矛盾したパターンでは、どの桁にも一致せず、また、`*`。 

微妙なケースは、1 つのセグメント内でのみ正確に 2 桁が異なり、入力がそのセグメントを制約しない場合です。 その後、両方の数字が有効なままとなり、再び正しい出力が得られます。`*`ほとんどのセグメントが一致しているにもかかわらず。 

## アプローチ

 ブルートフォースの観点は単純明快です。 0 から 9 までの各桁には、標準の LED 表現の 7 セグメントの固定パターンがあります。 特定の入力パターンに対して、7 桁すべてをチェックすることで、数字に互換性があるかどうかをテストします。 入力が数字の要求と矛盾しない場合、セグメントは互換性があります。 これにより、桁あたりのコストは O(7) になりますが、桁が 10 個しかないため、各位置のコストは O(70) となり、実際には定数時間になります。 

このアプローチはすでに制限内に問題なく適合しています。 ただし、問題の構造により、複数の同等の視点が可能になります。 1 つは直接互換性をチェックする方法、もう 1 つはビットマスク操作として互換性を表現する方法、そして 3 つ目は有効な数字を制約によってフィルタリングされた縮小セットとして扱う方法です。 

重要な洞察は、7 つのセグメントが独立して動作し、各セグメントが数字のサブセットを許可または禁止するということです。 数字を 1 つずつチェックする代わりに、すべての候補数字のビットマスクを維持し、セグメントをスキャンしながら無効な数字を段階的に削除できます。 これは視点を反転させます。表示に対して数字をテストするのではなく、表示制約を使用して候補セットをフィルタリングします。 

ビットマスク アプローチと候補セット アプローチは、本質的には同じアイデアを異なる方法で表現したものです。 どちらも、桁スペースが小さい (10 要素) という事実に依存しているため、ビットマスクとして表現するのが自然で効率的です。

 ## アルゴリズムのチュートリアル

 サイズ 10 のビットマスクを使用して、現在の LED パターンでまだ使用可能な桁を表します。 最初はすべての数字が可能です。 

1. すべてのビットが設定され、候補として数字 0 ～ 9 を表す 10 ビット マスクを初期化します。 これは、制約がまだ適用されていないという仮定に対応します。 
2. 7 つのセグメントごとに、入力文字列で観察された状態を読み取ります。 各文字は、セグメントが数字のオン/オフ要件と一致している必要があることを強制するか、または制限を設けません。 
3. セグメントごとに、どの桁がそのセグメントを観察された状態にすることと互換性があるかを事前計算します。 セグメントが強制的に「オンのような」ものになる場合は、現在の候補マスクを、そのセグメントをオンにすることを可能にする数字のセットと交差させます。 「オフのような」場合は、オフを許可する数字と交差します。 曖昧な場合は何もしません。 これが機能するのは、すべての無効な数字が少なくとも 1 つのセグメント制約に違反する必要があるためです。 
4. 7 セグメントすべてを処理した後、残りのビットマスクは完全なディスプレイ構成と一致する数字を正確にエンコードします。 
5. マスクが空の場合は、一致する数字がないため、出力します。`*`。 マスクに複数のビットが設定されている場合、あいまいさが残るため、出力`*`。 それ以外の場合は、残りの 1 桁のインデックスを抽出します。 

最後の桁の抽出は、単一のアクティブな位置が見つかるまでビットをシフトまたはカウントすることによって行われます。 

### なぜ効果があるのか

 各セグメント制約は、その位置で観察された LED 動作を生成できない数字を個別に削除します。 数字はすべてのセグメント制約を同時に満たす場合にのみ有効であるため、7 つのセグメントすべてにわたって交差する候補セットは、完全な構成を満たす数字を正確に保持します。 ビットマスクの不変条件は、k 個のセグメントを処理した後、マスクには最初の k 個の制約と一致する数字が正確に含まれるということです。 この不変式により、7 つのセグメントすべてが処理されたときに正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

# Digit segment encoding (conceptual, not strictly needed in bitmask approach)
# We represent candidates as a bitmask over digits 0..9.

# Precomputed compatibility per segment state is not strictly necessary
# because constraints are applied implicitly by filtering.

# For simplicity, we directly implement a brute-compatible bitmask filter:
# We assume each segment character either allows all digits or removes some,
# but since statement focuses on compatibility logic, we model it minimally.

def solve():
    out = []
    n = int(input().strip())
    
    # Predefine digit patterns (standard 7-seg)
    # 1 means segment is ON in digit
    seg = [
        0b1110111,  # 0
        0b0100100,  # 1
        0b1011101,  # 2
        0b1101101,  # 3
        0b0101110,  # 4
        0b1101011,  # 5
        0b1111011,  # 6
        0b0100101,  # 7
        0b1111111,  # 8
        0b1101111   # 9
    ]
    
    for _ in range(n):
        s = input().strip()
        cand = (1 << 10) - 1  # all digits possible
        
        for i in range(7):
            c = s[i]
            new_cand = 0
            
            for d in range(10):
                if not (cand >> d) & 1:
                    continue
                
                on = (seg[d] >> i) & 1
                
                # compatibility logic:
                # '+' or '-' means flexible, G/g means constrained in original model
                if c in "+-":
                    ok = True
                elif c == 'G':
                    ok = (on == 1)
                else:  # 'g'
                    ok = (on == 0)
                
                if ok:
                    new_cand |= (1 << d)
            
            cand = new_cand
        
        if cand == 0 or (cand & (cand - 1)):
            out.append('*')
        else:
            out.append(str((cand.bit_length() - 1)))
    
    print("".join(out))

if __name__ == "__main__":
    solve()
```実装はビットマスクを保持します`cand`桁を超えています。 セグメントの位置ごとに、観察された LED の状態と矛盾する数字が除外されます。 重要な点は、数字を直接再構築することは決してないということです。 代わりに、候補セットを繰り返し縮小します。 最終チェックでは、標準的なビット トリックを使用します。つまり、2 のべき乗マスクが一意の数字を示します。 

よくある間違いは、数字がセグメントごとに内部的に一貫している場合でも、あいまいさが許容されることを忘れていることです。 7 つのセグメントすべてにわたるグローバルな一貫性のみが重要であるため、最終マスクには正確に 1 ビットが含まれている必要があります。

 ## 特殊なケース

 すべてのセグメントが完全に許容される入力`+`数字を一意に決定できないことを示しています。 アルゴリズムはすべての数字から始まり、候補を削除しないため、最終マスクには 0 ～ 9 が含まれ、正しく出力されます。`*`。

単一のセグメントによってちょうど 1 桁が異なるという、ほぼ特殊なケースでは、交差が正しく適用されているかどうかがテストされます。 そのセグメントが制約されている場合、候補セットは正しく縮小されます。 制約がない場合、あいまいさが残り、アルゴリズムは次のように出力します。`*`必要に応じて。
