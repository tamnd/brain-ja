 ## 解決策
 ## 問題の理解

 各列が現在の高さを持つ 1 次元のボードが与えられます。 一連の操作により、列の連続セグメントに影響を与える部分が配置されます。 各操作はセグメント上の「ドロップ」のように動作します。つまり、そのセグメントの高さが均一に変更され、ブロックとして増加します。 

移動が安全かどうかを決定する重要なルールは、ローカルの一貫性のみに依存します。 ピースが列の範囲に適用される場合、注意する必要があるのは、その範囲内のすべての列が現在同じ高さであるかどうかだけです。 それらが等しい場合、ピースを適用するときれいな層状構造が維持されます。 それらが異なる場合、操作を適用した後、少なくとも 1 つの列で充填されたセルの下に内部ギャップが生じ、構造が破壊され、状態が安全でなくなります。 

したがって、各クエリは、配列に対する 2 つのアクションに減ります。つまり、範囲内のすべての値が同一かどうかをチェックし、チェックに合格した場合は、その範囲内のすべての値を 1 ずつ増やします。 

入力サイズは十分に大きいため、この問題ファミリーの一般的なバージョンでは、列数と演算数の両方が最大約 200,000 に達する可能性があります。 これにより、クエリごとに範囲をスキャンするソリューションは即座に除外されます。単純なチェックでは、操作ごとに線形の時間がかかり、最悪の場合は 2 次の動作が発生するためです。 

直接シミュレーションでは、座標が大きいかまばらな場合にボードを明示的に拡張しようとすると、メモリの問題も発生します。 意図された困難は、概念的に単純な構造上で多くの範囲チェックと範囲の増加を効率的に処理することです。 

微妙なエッジケースの 1 つは、長く交互するパターンから生じます。 高さが頻繁に変化する場合、境界を適切に分割しない単純な間隔マージ手法では、誤った均一性チェックが静かに伝播してしまいます。 もう 1 つのエッジ ケースは、全範囲更新が繰り返される場合です。この場合、不適切なマージ ロジックにより個別のセグメントが崩壊し、後で均一性が誤って報告される可能性があります。 

## アプローチ

 ブルートフォース解釈は簡単です。 高さの配列を保存します。 セグメント上の各操作について$[l, r]$, まず、その範囲内のすべての値をスキャンして、それらが等しいかどうかを確認します。 それらが等しくない場合、操作は拒否されます。 それらが等しい場合、範囲内のすべての値が 1 ずつ増加します。 

これは問題定義に正確に従っているため機能します。 影響を受けるすべての列の状態を直接検証しているため、正確性はすぐにわかります。 失敗点はパフォーマンスです。 1 回の操作でかかる時間$O(n)$時間と$m$操作を行うと、最悪のケースが発生します。$O(nm)$。 両方が 200000 に達すると、これは実現可能な限界をはるかに超えます。 

重要な観察は、配列の構造が実際には任意ではないということです。 私たちがテストする唯一のことは、セグメントが均一であるかどうかであり、セグメントを均一にインクリメントすることだけです。 これは、配列が定数値のブロックに進化し、操作ではこれらのブロックの分割またはマージのみが行われることを意味します。 均一セグメント内の個々の値を知る必要はなく、セグメントの境界とその値だけを知る必要があります。 

これは、各セグメントが一定の高さを格納する最大のセグメントへの配列のパーティションを維持することを示唆しています。 範囲の更新は、これらのセグメントの局所的な分割と結合になります。 あるいは、遅延伝播を備えたセグメント ツリーは、範囲の増分を維持し、最小値と最大値の追跡を使用して均一性クエリをサポートできます。 

どちらの観点も同等です。1 つは明示的な間隔セットであり、もう 1 つは暗黙的な平衡バイナリ分解です。

 ## アルゴリズムのチュートリアル

 問題の構造を最も直接的に反映するため、間隔ベースの解決策について説明します。 

1. ボード全体をカバーする一連の素な間隔を維持します。各間隔には、左境界、右境界、および一定の高さの値が格納されます。 

この表現は有効です。なぜなら、2 つの隣接する領域が同じ高さを共有するときはいつでも、それらは即座にマージされ、最大のセグメントが保証されるからです。 
2. セグメントに対する各操作について$[l, r]$, まず、この範囲と交差するすべての間隔を見つけます。 

このステップが必要なのは、更新によって既存の均一ブロックが切断される可能性があり、正確かどうかは境界で正確に分割するかどうかに依存するためです。 
3. 部分的に重なる区間$[l, r]$は、左の残り、中央の影響を受ける部分、右の残りの最大 3 つの部分に分割されます。 

分割により、更新領域が間隔の境界に確実に揃えられるため、調整されていないセグメントに更新を適用することはありません。 
4. 分割後、影響を受ける領域が 1 つの区間で構成されているか、複数の区間で構成されているかを確認します。 

対象期間が複数ある場合$[l, r]$の場合、範囲内のどこかで高さが異なるため、操作は安全ではなく、更新をスキップします。 
5. 領域が均一の場合、その高さを 1 つ増やし、間隔を表す間隔を置き換えます。$[l, r]$、同じ値を共有している場合は、隣接する間隔とのマージを試みます。 

マージにより最大限のセグメンテーションが復元され、不必要な断片化が防止されます。 
6. 各操作は一定数の間隔のみを操作し、すべての検索と更新は順序付けされた構造操作を使用して実行されます。 

### なぜ効果があるのか

 どの時点でも、構造は、同じ高さの最大の連続セグメントへの配列の分割を維持します。 範囲が均一であるかどうかを尋ねるクエリは、その範囲が単一のセグメント内に完全に含まれているかどうかを確認することと同じです。 複数のセグメントにまたがる場合は、範囲内に少なくとも 1 つの境界が存在することになり、2 つの異なる高さが存在する必要があります。 分割ではセグメントがクエリ境界に正確に位置合わせされ、マージでは重複した隣接する等しいセグメントが決して保持されないため、更新ではこの不変性が維持されます。 これにより、均一性チェックの正確性と増分更新の正確性の両方が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Seg:
    __slots__ = ("l", "r", "v")
    def __init__(self, l, r, v):
        self.l = l
        self.r = r
        self.v = v

def solve():
    n, q = map(int, input().split())
    
    segs = []
    segs.append(Seg(1, n, 0))

    def find(pos):
        lo, hi = 0, len(segs) - 1
        while lo <= hi:
            mid = (lo + hi) // 2
            s = segs[mid]
            if s.l <= pos <= s.r:
                return mid
            if pos < s.l:
                hi = mid - 1
            else:
                lo = mid + 1
        return -1

    def split(idx, x):
        s = segs[idx]
        if s.l == x:
            return idx
        if s.r == x:
            return idx + 1
        if s.l < x < s.r:
            left = Seg(s.l, x - 1, s.v)
            right = Seg(x, s.r, s.v)
            segs[idx] = left
            segs.insert(idx + 1, right)
            return idx + 1
        return idx

    def normalize(i):
        if i > 0 and segs[i].v == segs[i - 1].v:
            segs[i - 1].r = segs[i].r
            segs.pop(i)
            return i - 1
        if i + 1 < len(segs) and segs[i].v == segs[i + 1].v:
            segs[i].r = segs[i + 1].r
            segs.pop(i + 1)
        return i

    for _ in range(q):
        l, r = map(int, input().split())

        i = find(l)
        i = split(i, l)

        j = find(r)
        j = split(j, r + 1)

        # now segments fully align with [l, r]
        vals = segs[i:j + 1]

        ok = True
        base = vals[0].v
        for s in vals:
            if s.v != base:
                ok = False
                break

        if not ok:
            continue

        segs[i].v += 1
        segs[i].r = segs[j].r

        for _ in range(j - i):
            segs.pop(i + 1)

        normalize(i)

    print(len(segs))

if __name__ == "__main__":
    solve()
```コードは、位置によってソートされた最大セグメントのリストを維持します。 の`find`関数は、境界を分割する前に使用される指定されたインデックスを含むセグメントを特定します。 の`split`関数は、クエリ エンドポイントが正確なセグメント境界になることを保証します。これは、均一性に関するすべての推論がクエリ範囲に合わせて配置されるセグメントに依存するため、不可欠です。 

アラインメント後、間隔範囲はセグメント リストの連続したスライスに対応します。 コードは、そのスライス内のすべてのセグメントが同じ値を共有しているかどうかをチェックします。 そうでない場合、操作は無視されます。 それ以外の場合は、スライスをインクリメントされた値を持つ単一のセグメントにマージします。 

の`normalize`この関数は、値が等しい場合に隣接するものとマージすることで更新後に最大値を復元し、時間の経過による断片化を防ぎます。 

実装の微妙な点は、均一性をチェックする前に両端で分割を行う必要があることです。 1 つの境界だけが分割されている場合、クエリ範囲が誤って部分的に重複するセグメントをカバーし、誤った複数セグメントの検出が行われる可能性があります。

 ## 特殊なケース

 重要なケースの 1 つは、更新が 2 つのセグメント間の境界に正確に一致する場合です。 たとえば、次のような構造の場合、$[1,2,0],[3,5,0]$そして更新します$[2,3]$、分割により生成される$[1,1,0],[2,2,0],[3,3,0],[4,5,0]$。 中央の領域は複数のセグメントにまたがっているため、操作は正しく拒否されます。 

別のケースでは、崩壊する構造を誤ってマージすることが繰り返されます。 更新後に取得した場合$[1,2,1],[3,4,1]$、その後の操作でそれらが 1 つのセグメントにマージされ、将来の均一性チェックが確実に行われます。$[1,4]$正しく true を返します。 マージしない場合、アルゴリズムは境界を誤って検出し、有効な操作を拒否します。 

3 番目のケースは、次のようなシングルポイント更新です。$[p,p]$。 これらは、正しい分割動作に大きく依存します。 分割でポイントを分離できない場合、更新がより大きなセグメントに誤って影響を及ぼし、後続のチェックが破損する可能性があります。
