 ## 解決策
 ## 問題の理解

 私たちは、エッジが文字でラベル付けされた有向グラフを使用しています。 このタスクは、通常の意味での到達可能性を答えることではなく、一連のエッジ ラベルが回文を形成するウォークによって接続できる頂点のペアをすべて発見することです。 

回文条件は、パスの両端を結合します。 からの回文ウォークがあることがわかっている場合は、`u`に`v`の場合、そのウォークの最初と最後の文字は一致する必要があり、それらを削除すると、次の頂点ペアの間に内側に向かって別の回文ウォークが残ります。 これは、回文接続が単一のパスに局所的ではなく、両端からの対称的な展開を通じて伝播することを示唆しています。 

入力グラフが大きくなり、すべてのパスを反復処理することが不可能になる場合があります。 すべての頂点のペアを列挙するだけでもすでに 2 次関数であり、ステートメントで説明されているアルゴリズムはペアに対するプロセスを明示的に構築します。`(u, v)`個々の頂点やエッジではなく。 これは、状態空間が頂点ペアのセットであることを直ちに示唆しています。`O(n^2)`。 

素朴な解釈は、すべての回文ウォークを明示的に構築しようとするか、状態全体にわたって BFS を実行しようとすることです。`(u, v)`ここで、遷移は一致するエッジ ラベルに依存します。 各ペアが多数の新しいペアを生成する可能性があるため、これはすでに最悪のケースの爆発を示唆しています。 

微妙なエッジ ケースの 1 つは、自己ループと簡単なパスから発生します。 すべての頂点`(u, u)`空のウォークは回文であるため、最初は有効です。 もう 1 つのエッジ ケースは、複数のエッジが同じラベルを共有する場合です。これは、複数の同一の遷移が生成される可能性があるためです。 不用意に実装すると、作業が重複したり、すでに処理されたペアが再度追加されたりして、大混乱が発生する可能性があります。 

たとえば、頂点が 2 つあるグラフがあるとします。`1 -> 2`ラベルが貼られた`a`そして`2 -> 1`ラベルが貼られた`a`、 それから`(1, 1)`そして`(2, 2)`些細なことであり、`(1, 2)`そして`(2, 1)`すぐに接続されます。 そこから、拡張ルールは入力エッジと出力エッジを通じて同じペアを繰り返し確認しますが、すでに確認されたペアを再処理しないようにする必要があります。 

出力は単に個別の頂点ペアの数です。`(u, v)`と`u != v`この閉鎖プロセスによって発見されるもの。 

## アプローチ

 ブルートフォースの観点は、各ペアを処理することです`(u, v)`状態としてプロセスを直接シミュレートしてみてください。 みんなで始めましょう`(u, u)`そしてすべてのエッジ`(u, v)`初期状態として。 次に、現在のペアごとに拡張を繰り返し試みます。`(u, v)`、すべての入力エッジを調べます。`u`そして、からのすべての出力エッジ`v`。 ラベルが一致する場合、新しいペアを生成します`(a, b)`。 

これは回文ウォークの再帰的分解を正確に反映しているため、これは正しいです。外側の文字を一致させると、問題が内部の小さな回文ウォークに縮小されます。 ただし、このシミュレーションでは、同じペアの同じ隣接情報を繰り返しスキャンすることができ、潜在的に`O(n^2)`ペア。 各ペアの拡張コスト`deg_in(u) * deg_out(v)`、密集したグラフでは壊滅的な繰り返しにつながります。 

重要な観察は、アルゴリズムが本質的に頂点上の二項関係に対する閉包計算であるということです。 各ペア`(u, v)`は最大 1 回挿入され、処理されるときは新しいペアの生成のみが試行されます。 大変な作業は、同じラベルを持つ入力エッジと出力エッジを照合することにあります。 パスという観点から考えるのではなく、2 つの半歩を組み合わせるという観点から考えます。`u`そしてそこから一歩前進`v`、ラベルの等価性によって同期されます。 

これにより、問題はラベルごとにグループ化されたグラフのエッジに対する 2 ポインターの展開に変わります。 各エッジは、次数の寄与によってのみペアリングに参加し、すべてのペアにわたって、総作業量は、次数のすべての頂点の合計によって制限されます。`indeg(u)`回`outdeg(v)`構造全体で凝集し、崩壊します。`O(M^2)`最悪のケースではありますが、実際にはペアの状態ではなくエッジ ペアの相互作用をカウントすることによって制御されます。 

重要な構造的変化は、パスを列挙しているのではなく、互換性のあるエッジのペアを列挙していること、および成功した各一致がクロージャ内の固有の生成イベントに対応していることを認識することです。

 ## アルゴリズムのチュートリアル

 頂点ペアのキューを維持します`(u, v)`回文ウォークによって接続されていることが知られています。 ブール値テーブルも維持します`seen[u][v]`各ペアが 1 回処理されるようにします。 

1. すべてのペアでキューを初期化します。`(u, u)`。 頂点に留まると有効な自明なウォークが形成されるため、これらは空の回文に対応します。 
2. すべての有向エッジを使用してキューも初期化します。`(u, v)`。 単一のエッジは長さ 1 の回文を形成するため、これらはすぐに有効になります。 
3. キューが空でない間に、ペアをポップします。`(u, v)`。 これを、`u`に`v`。 
4. このペアについて、すべての入力エッジを反復処理します。`(a -> u)`ラベル付き`c1`。 同時に、すべての出力エッジを反復処理します。`(v -> b)`ラベル付き`c2`。 
5.いつでも`c1 == c2`、から新しい回文ウォークを形成できます。`a`に`b`既存の回文ウォークをラップすることにより`(u, v)`両端に一致するエッジが付いています。 これにより候補ペアが生成されます`(a, b)`。 
6. もし`(a, b)`以前に見られていない場合は、既知としてマークし、キューに追加します。 
7. 新しいペアが生成できなくなるまで続けます。 最終的な答えは、個別のペアの数です。`(u, v)`と`u != v`これまでに見たことがあるマークが付いているもの。 

### なぜ効果があるのか

 すべての回文ウォークには、外側の一致するエッジと内側の回文サブウォークへの自然な分解があります。 から散歩するなら`a`に`b`、その最初のエッジ`(a -> u)`最後のエッジと一致する必要があります`(v -> b)`ラベルと方向性において。 これらのエッジを削除すると、有効な回文ウォークが残ります。`u`に`v`。 これにより、すべての有効なペアが既知の有効なペアを繰り返し拡張することによって生成されることが確立されます。 逆に、生成されたすべてのペアは有効なラッピング ステップに対応するため、無効なペアが導入されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import deque, defaultdict

def solve():
    n, m = map(int, input().split())
    
    in_edges = [[] for _ in range(n)]
    out_edges = [[] for _ in range(n)]
    
    edges = []
    
    for _ in range(m):
        u, v, c = input().split()
        u = int(u) - 1
        v = int(v) - 1
        in_edges[v].append((u, c))
        out_edges[u].append((v, c))
        edges.append((u, v))
    
    seen = [[False] * n for _ in range(n)]
    q = deque()
    
    for i in range(n):
        if not seen[i][i]:
            seen[i][i] = True
            q.append((i, i))
    
    for u, v in edges:
        if not seen[u][v]:
            seen[u][v] = True
            q.append((u, v))
    
    while q:
        u, v = q.popleft()
        
        for a, c1 in in_edges[u]:
            for b, c2 in out_edges[v]:
                if c1 == c2:
                    if not seen[a][b]:
                        seen[a][b] = True
                        q.append((a, b))
    
    ans = 0
    for i in range(n):
        for j in range(n):
            if i != j and seen[i][j]:
                ans += 1
    
    print(ans)

if __name__ == "__main__":
    solve()
```この実装はクロージャ プロセスを直接反映しています。 隣接関係は受信リストと送信リストに分割されるため、各拡張ステップで効率的にエッジをペアにすることができます。 の`seen`マトリックスは、同じ状態の繰り返し処理を防ぎます。マトリックスがないと、同じペアが異なる拡張パスを通じて繰り返し生成される可能性があるため、これは不可欠です。 

最後のカウントステップでは、対角ペアが除外されます。`(u, u)`は自明であり、出力定義には含まれません。 

## 実用的な例

 3 つの頂点とラベル付けされたエッジを持つ小さなグラフを考えてみましょう。`1 -> 2 (a)`、`2 -> 3 (a)`、 そして`3 -> 2 (a)`。 

で初期化します`(1,1)`、`(2,2)`、`(3,3)`およびダイレクトエッジ`(1,2)`、`(2,3)`、`(3,2)`。 

| ステップ | ペア (u,v) | アクション | 新しいペア |
 | --- | --- | --- | --- |
 | 初期化 | (1,1)、(2,2)、(3,3) | 対角線をエンキューする | なし |
 | 初期化 | (1,2)、(2,3)、(3,2) | エッジをエンキュー | なし |
 | プロセス | (2,3) | ラベル a | を介して受信/送信を照合します。 (1,2) 1->2 および 3->2 経由 |
 | プロセス | (3,2) | 対称展開 | 新しいものはありません |
 | プロセス | (1,2) | これ以上一致するものはありません | なし |

 これは、回文構造がどのように前後方向に同時に伝播し、直接エッジではないパスをリンクするかを示しています。 

次に、すべてのエッジが同じラベルを共有するグラフを考えます。`a`: 完全な双方向チェーン`1 <-> 2 <-> 3`。 

どの入力エッジもどの出力エッジとも一致するため、繰り返しラッピングすることですべてのペアに到達可能になります。 キューはすぐにすべてが飽和状態になります`n^2`のペアで、アルゴリズムが重複排除に依存しなければならない理由を示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(平方メートル) | 各展開では、入力エッジと出力エッジが比較されます。 ペアごとのエッジ相互作用の合計は、二次エッジの組み合わせによって制限されます。 
| スペース | O(n²) | ブール値テーブルには、各頂点ペアが検出されたかどうかが格納されます。 

アルゴリズムの構造により、各ペアが最大 1 回キューに入れられ、各エンキューがローカル次数積に比例して動作をトリガーすることが保証されます。 エッジ相互作用の総数はエッジの組み合わせによって制限されるため、プロセス全体はエッジ数の二次境界内に収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque, defaultdict

    n, m = map(int, sys.stdin.readline().split())
    in_edges = [[] for _ in range(n)]
    out_edges = [[] for _ in range(n)]
    edges = []

    for _ in range(m):
        u, v, c = sys.stdin.readline().split()
        u = int(u) - 1
        v = int(v) - 1
        in_edges[v].append((u, c))
        out_edges[u].append((v, c))
        edges.append((u, v))

    seen = [[False]*n for _ in range(n)]
    q = deque()

    for i in range(n):
        seen[i][i] = True
        q.append((i, i))

    for u, v in edges:
        if not seen[u][v]:
            seen[u][v] = True
            q.append((u, v))

    while q:
        u, v = q.popleft()
        for a, c1 in in_edges[u]:
            for b, c2 in out_edges[v]:
                if c1 == c2 and not seen[a][b]:
                    seen[a][b] = True
                    q.append((a, b))

    return str(sum(1 for i in range(n) for j in range(n) if i != j and seen[i][j]))

 ## 特殊なケース

 エッジ ケースの 1 つは、初期化を介して暗黙的に自己ループのみを含むグラフです。 アルゴリズムは、すべてを挿入することで開始します。`(u, u)`たとえエッジが存在しなくても。 出力には対角ペアが除外されるため、次のグラフが表示されます。`n`孤立した頂点が返されるはずです`0`。 キューのプロセス`(u, u)`ただし、一致する入力エッジと出力エッジが見つからないため、新しいペアは生成されません。 

もう 1 つのエッジ ケースは、複数のエッジが同一のエンドポイントとラベルを共有する場合です。 たとえば、平行なエッジが多数ある場合、`u -> v`ラベルが貼られた`a`、それぞれが繰り返し拡張をトリガーする可能性があります。 の`seen`表はそれを保証します`(u, v)`は 1 回だけ処理されるため、重複エッジによる二次増幅の繰り返しが防止されます。 

最後のエッジ ケースは、すべてのエッジが同じラベルを共有する、強く接続されたグラフです。 この状況では、各ステップですべての入力エッジがすべての出力エッジとペアになる可能性があります。 各ペアが`(u, v)`は 1 回だけ挿入され、ペアの総数は次のように制限されます。`n^2`、中間のマッチング作業が密であるにもかかわらず。
