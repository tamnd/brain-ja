 ## 解決策
 ## 問題の理解

 交差点がノード、道路がエッジである無向加重グラフとしてモデル化された都市が与えられます。 各交差点には危険値があり、各道路は 2 つの交差点を接続します。 目標は、ネットワークを通過することがどの程度「危険」であるかに基づいて、すべての交差点の最終スコアを計算することです。ここで、2 つの交差点間のリスクは、それらの間の最良の接続に沿って遭遇する最も危険なポイントによって決まります。 

最大の難点は、「最適な接続」が単純な最短経路ではないことです。 代わりに、ノードの任意のペアについて、パス コストはパスに沿った最大危険値に依存し、すべてのパスの中でこの最大値を最小化するパスに注目します。 

これにより、私たちはすぐに標準的な最短経路の考え方から遠ざかってしまいます。 エッジに沿って重みを蓄積するのではなく、パスに沿って最大値を取得し、すべての可能なルートにわたってその最大値を最小化します。 

制約が十分に大きいため、ペア間のすべてのパスを評価しようとするソリューションは不可能です。 単一ソースのマルチターゲット BFS またはすべての状態に対するダイクストラのようなアプローチでさえ、密なグラフでは少なくとも 2 次の動作にまで爆発します。 ソリューションでは、グラフ構造をツリーのようなものに縮小し、ペアごとの相互作用が管理できるようにする必要があります。 

元のグラフを再構築せずに元のグラフで最適パスを直接計算しようとすると、微妙な失敗のケースが発生します。 たとえば、ノード危険度が 1、100、および 50 である三角グラフについて考えてみましょう。100 と 1 の間の直接エッジは最大 100 を与えますが、50 を通過すると最大 100 も与えられるため、複数の同等のパスが存在します。 エッジの重みを誤って集計する単純な最短パスのアプローチでは、誤って局所的に小さいエッジの重みを優先し、正確性が損なわれる可能性があります。 

重要な問題は、問題がローカル エッジの決定ではなく、パスのグローバル構造に依存することです。 

## アプローチ

 直接的なブルート フォース アプローチでは、ノードのすべてのペアについて、それらの間のパスに沿った最小限の最大の危険性を評価しようとします。 これは本質的にミニマックス パスの問題です。 パスコストがパスに沿った最大エッジ重みとして定義されているすべてのノードから修正されたダイクストラを実行できます。 各実行のコストは O(M log N) となり、結果として O(N M log N) になりますが、これは大きなグラフには遅すぎます。 

重要な観察は、エッジの重みがノードの危険値の観点から再解釈できるということです。 各エッジの重みをそのエンドポイントの最大危険度として定義すると、パスのコストがそのパスに沿った最大ノード危険度になります。 この変換の下では、問題は、これらの重みで構築された最小スパニング ツリー構造を操作することと同等になります。 

ここで、Kruskal のアルゴリズムが中心となります。 エッジを重みでソートし、コンポーネントをマージすると、増加する危険しきい値の下でグラフの 2 つの部分がいつ接続されるかを正確に捕捉する結合の階層を効果的に構築することになります。 任意のパスの観点から考える代わりに、グラフをツリーに圧縮し、各マージが接続が可能になった瞬間を表します。 

このツリーは DSU マージ ツリーと呼ばれることがあり、関連するすべてのパス情報をエンコードします。 このツリー内の最下位の共通祖先は、ミニマックス パス定義と一致する 2 つのノード間のボトルネック値を直接与えます。 

このツリーを作成したら、残りのタスクは、サブツリーのサイズとマージの重みに基づいて各ノードからの寄与を計算することです。 ペアごとの寄与を再計算する代わりに、集計されたカウントをツリー内で上下に伝播します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (マルチソース ミニマックス検索) | O(N M log N) | O(N + M) | 遅すぎる |
 | DSU マージ ツリー + DFS 集約 | O(M log M + N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

増加する危険しきい値の下で接続性を表すツリーを徐々に構築する構造を構築し、それを使用して寄与率を効率的に計算します。 

1. すべてのエッジを重みで並べ替えます。重みは、そのエンドポイントの最大の危険性として定義されます。 並べ替えることにより、制御された順序で許容される危険レベルの増加をシミュレートできます。 
2. 各ノードが独自のコンポーネントとして開始される Disjoint Set Union 構造を初期化します。 各コンポーネントは最初は 1 つの交差点に対応します。 
3. エッジを昇順に処理します。 エッジが 2 つの異なるコンポーネントを接続すると、それらの結合を表す新しい人工ノードが作成されます。 このノードは 2 つのコンポーネントの親になります。 

直接マージせずに新しいノードを導入する理由は、マージの履歴を保存したいためです。 各内部ノードは、接続が変化する「しきい値イベント」を表します。 
4. 新しい内部ノードのそれぞれに、その子のサイズの合計に等しいサイズを割り当てます。 このサイズは、サブツリー内に元の交差がいくつあるかを表します。 この数は、特定のマージ イベントによって影響を受けるペアの数を後で決定します。 
5. すべてのノードが 1 つのルートに属するまで続行します。 結果として得られる構造は、元のノードを葉として、マージ ノードを内部頂点として持つバイナリ ツリーになります。 
6. ルートから DFS を実行して、寄与値を伝播します。 各内部ノードでは、サブツリーのサイズに基づいてその寄与を子に分配します。 この遷移では、ツリーを下に移動すると、現在のマージの重みに依存するペアの数が変化するという事実を利用します。 
7. ルートからリーフまでのパスに沿って発生する寄与を合計することにより、元のノードの結果を蓄積します。 

重要な考え方は、すべての内部ノードがそのマージ レベルで「カットオフ」されたペアの数に比例する値を提供し、DSU ツリー構造により、そのような各ペアが 1 回だけカウントされるようにするということです。 

### なぜ効果があるのか

 DSU マージ ツリーは、増加するエッジしきい値の下で 2 つの元のノードが接続される正確な瞬間をエンコードします。 すべての内部ノードは、2 つのコンポーネントがマージされるクリティカルしきい値に対応し、それらのコンポーネント間で分割されたすべてのペアのボトルネックがそのノードの重みに等しい必要があります。 

サブツリーのサイズは、各マージの下に元のノードがいくつあるかをカウントするため、すべての寄与は、親子遷移にわたる累積ペア数の差として表すことができます。 DFS 再帰により、マージ ツリー内の各エッジが正確な量の「残りのペア」を下方向に転送し、二重カウントを防止します。 ノードの各ペアには一意の最低マージ ポイントがあるため、各ペアは 1 回だけ考慮されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.p = list(range(n))
        self.sz = [1] * n

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return -1
        return a, b

def solve():
    n, m = map(int, input().split())
    danger = list(map(int, input().split()))

    edges = []
    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        w = max(danger[u], danger[v])
        edges.append((w, u, v))

    edges.sort()

    dsu = DSU(2 * n)
    parent = [-1] * (2 * n)
    weight = [0] * (2 * n)
    sz = [1] * (2 * n)

    tot = n

    def find(x):
        while parent[x] != -1:
            x = parent[x]
        return x

    for w, u, v in edges:
        ru = find(u)
        rv = find(v)
        if ru == rv:
            continue

        cur = tot
        tot += 1

        parent[ru] = cur
        parent[rv] = cur
        weight[cur] = w
        sz[cur] = sz[ru] + sz[rv]

    root = tot - 1

    adj = [[] for _ in range(tot)]
    for i in range(tot):
        if parent[i] != -1:
            adj[parent[i]].append(i)

    res = [0] * tot

    def dfs(u):
        for v in adj[u]:
            res[v] = res[u] + (sz[u] - sz[v]) * weight[u]
            dfs(v)

    res[root] = 0
    dfs(root)

    out = []
    for i in range(n):
        out.append(str(res[i]))
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```実装は、各エッジをエンドポイントの危険性に基づいた重みに変換することから始まり、これによりエッジのコストがパスのミニマックス解釈に合わせられます。 DSU 構造は、結合操作ごとに新しいノードを導入し、親リンクとサブツリーのサイズを保存することによって、マージ ツリーに拡張されます。 

微妙な点は、完全なマージ履歴が必要なため、トラバーサルに標準の DSU 親ポインターに依存できないことです。 明示的な親配列はその履歴を保存します。 

DFS は、累積された値を親から子にプッシュすることによって寄与度を計算します。 表現`(sz[u] - sz[v]) * weight[u]`サブツリーに移動することによって新しく分離された元のノードの数を表します`v`、マージの重みによってスケーリングされます。`u`。 

## 実用的な例

 危険が存在する場所に 3 つのノードがある小さなグラフを考えてみましょう。`[1, 3, 2]`そしてエッジ`(1-2), (2-3)`。 

まずエッジの重みを計算します。 

ノード 1-2 は 3 を与え、ノード 2-3 は 3 を与えます。ソートによって順序は変わりません。 

| ステップ | アクション | DSU のマージ | 現在のノードが作成されました | サブツリーのサイズ |
 | --- | --- | --- | --- | --- |
 | 1 | プロセスエッジ1-2 | マージ 1、2 | ノード 3 | サイズ2 |
 | 2 | プロセスエッジ2-3 | (1,2) と 3 | をマージします。 ノード 4 | サイズ3 |

 最後のルートはノード 4 です。DFS 伝播により次が得られます。 

ルート 4 は、すべての分割にわたって重み 3 に寄与します。 下に移動すると、サブツリーのサイズに比例して寄与が分割されます。 

これは、すべてのパスにボトルネック 3 があるため、両方のエッジが均等に寄与していることを示しています。 

次に、危険を伴う偏ったケースを考えてみましょう`[5, 1, 4, 2]`そしてチェーングラフ`1-2-3-4`。 

エッジの重みは次のようになります。`[5,5,4]`鎖に沿って。 

| ステップ | マージ | 重量 | 結果の構造 |
 | --- | --- | --- | --- |
 | 1 | 1-2 | 5 | ノードA |
 | 2 | A-3 | 5 | ノード B |
 | 3 | B-4 | 4 | ルート |

 これは、後のマージによって寄与範囲がどのように削減または調整されるか、DFS によって正しい再配分が保証されるかを示しています。 

各トレースは、マージ順序がボトルネックの進化を正しく捉えていること、および各ノードの寄与が純粋にサブツリー遷移から得られていることを確認します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(M log M + N) | ソートエッジが優勢で、DSU 構築と DFS は線形です。 
| スペース | O(N) | マージ ツリーと補助配列はノード数に応じて線形にスケールします。 

この構造により、大きなグラフでもすべてのエッジが 1 回処理され、マージごとに 1 つの新しいノードが導入されるため、ソート後の総作業量が線形に保たれます。 これは、最大 2e5 までの N および M の一般的な制限内に問題なく収まります。

 ## 特殊なケース

 単一ノードのグラフは、少なくとも 1 つのマージが存在することを前提とした実装の最も単純な障害点です。 この場合、DSU ツリーにはルートとリーフの両方であるノードが 1 つだけ含まれます。 DFS が初期化されます`res[root] = 0`、子がないため、出力はゼロのままで、正解と一致します。 

すべてのマージ前の接続されていないグラフも重要です。 エッジが存在しない場合、結合操作は行われず、各ノードは初期フォレスト内の独自のルートのままになります。 マージ ノードが作成されず、各ノードが独立して処理されるため、アルゴリズムは引き続きゼロ寄与を割り当てます。 

完全に接続された密なグラフは、DSU マージ順序の正確さを強調します。 多くのエッジは同じ重みを持つ可能性があるため、複数のマージが同じしきい値で発生します。 ソートにより決定論的な処理が保証され、サブツリー サイズの集約により、すべての等重みマージが寄与の伝播に曖昧さのない有効なツリー構造が生成されることが保証されます。
