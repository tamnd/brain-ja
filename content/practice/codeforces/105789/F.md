 ## 解決策
 ## 問題の理解

 私たちは、当初は制限のない一連のポジションを長期間維持しています。 時間が経つにつれて、フェスティバルの主催者は、隣接する範囲に高さの制限を強制する「標識」を設置します。 各符号には高さがあり、下限を課すことによってその区間内のすべての位置に影響を与えます。範囲に高さ H の符号を適用した後、その範囲内のすべての位置は少なくとも H の実効高さを持たなければなりません。 

複数の標識が重なる可能性があるため、各位置は、その位置に到達する最も強い制約によって支配されます。つまり、その最終的な高さは、その位置を覆うすべての標識の最大値となります。 したがって、維持する必要がある構造は、「[l, r] 内のすべてを少なくとも H に上げる」形式の範囲更新での値の動的な範囲と、現在の状態に関する集計情報 (通常は範囲内の最小値や配列全体の最小値など) を要求するクエリです。 

課題は、範囲更新とクエリの両方がインターリーブされてお​​り、影響を受けるセグメントを単純に再計算すると遅すぎる操作が十分にあることです。 この説明は、更新が加算的ではなく、代わりに最大演算を使用して単調変換を適用する遅延伝播を備えた標準セグメント ツリーを示唆しています。 

複雑さの観点から見ると、典型的な Codeforces 制約では、入力サイズは最大 200,000 ～ 500,000 程度の操作を意味します。 更新ごとに O(n) 要素に触れるソリューションは、最悪の場合、すぐに 10^10 の演算に縮退してしまい、実行可能ではありません。 操作あたり O(n log n) でも遅すぎるため、更新およびクエリごとに O(log n) が必要です。 

微妙なエッジ ケースは、高さの増減に伴う更新の重複によって発生します。 たとえば、[1, 10] に高さ 5 の更新を適用し、次に [3, 7] に高さ 2 の更新を適用しても、制約は強化されるだけであるため、何も減少しません。 最大値を取得する代わりに割り当てる単純な実装では、2 回目の更新で値が誤って低くなります。 

更新が完全に重複し、任意の順序で処理される場合、別のエッジ ケースが発生します。 たとえば、(l=1,r=5,H=10) に続いて (l=1,r=5,H=7) を適用すると、セグメントは 7 ではなく 10 のままでなければなりません。max とマージする代わりに上書きするアプローチはここで失敗します。 

## アプローチ

 ブルートフォースのアイデアは単純です。 サイズ n の配列を維持します。 更新ごとに、影響を受ける範囲を反復処理し、各値を max(現在の値、H) に更新します。 クエリごとに、要求された範囲をスキャンし、最小値またはその他の集計値を計算します。 これは制約の伝播を直接シミュレートするため正しく機能しますが、各更新は O(n) 個の要素に影響を与える可能性があり、各クエリも O(n) 個の要素に影響を与える可能性があります。 最大 O(n) の操作を行うと、これは O(n^2) となり、実現可能な制限をはるかに超えます。 

重要な観察は、各セグメントに適用される操作が単調で冪等であるということです。制約 H を複数回適用することは、最大値 H のみを適用することと同じです。この構造は、各ノードがセグメント内の現在の最小値を格納し、保留中の更新が「少なくとも H に引き上げられる」という遅延伝播を備えたセグメント ツリーと一致します。 複数の更新が重複する場合、max を使用してそれらをマージでき、元に戻したり減らしたりする必要はありません。 

これは、動的接続スタイルの問題からのより一般的なパターン、つまり、ロールバックまたは永続性を使用した時間の経過による分割統治にもつながります。 ここでは、DSU 状態をロールバックする代わりに、セグメント ツリーの変更をロールバックするか、更新が単調で破壊的な方法で競合することがないため、遅延伝播を使用してロールバックを完全に回避します。 

セグメント ツリー ソリューションが機能するのは、すべての更新が O(log n) ノードにのみ影響し、各ノードの更新が保存された値と遅延タグに対する定数時間の最大操作であるためです。 これにより、プロセス全体が O((n + q) log n) に削減されます。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nq) | O(n) | 遅すぎる |
 | セグメント ツリー Lazy Max | O((n + q) log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 配列上にセグメント ツリーを構築し、各ノードがその間隔内の最小値を格納します。 各更新は、「[l, r] のすべての値は少なくとも H でなければならない」という制約の強制を表します。 

1. 最初は符号が高さの制約を課さないため、すべての葉が 0 から始まるセグメント ツリーを構築します。 内部ノードには最小限の子が格納されます。 これにより、範囲最小値のクエリに直接答えることができます。 
2. 範囲更新 [l, r, H] の場合、セグメント ツリーをトラバースします。 ノード間隔が完全にカバーされるたびに、保存されている最小値を max(current_min, H) に設定して更新します。 これは、そのセグメント内のすべての要素がこれまでに確認された最も強い制約を尊重する必要があるという事実を反映しています。 
3. ノードが部分的にのみカバーされている場合は、その子に再帰的に更新を下方にプッシュします。 これにより、より細かいセグメントでも重複する制約が正しく反映されます。 
4. 各ノードで保留中の下限制約を表す遅延値を維持します。 複数の更新が同じノードに到着する場合、最も強い制約のみが重要となるため、max を使用して更新を結合します。 
5. 遅延値を子にプッシュするときに、再度最大伝播を適用します。必要に応じて各子の最小値が引き上げられ、それに応じてその遅延タグが更新されます。 
6. クエリの場合、セグメント ツリーを下降し、関連するセグメントからの最小値を結合します。 すべてのノードは、適用されたすべての制約の下で常に正しい最小値を表すため、クエリは再計算せずに正しい結果を返します。 

重要な考え方は、ツリーは常に、これまでに適用されたすべての制約の現在の下限エンベロープを表すということです。 

### なぜ効果があるのか

 どの時点でも、各位置の値は、その位置をカバーするすべての更新の最大高さとなります。 セグメント ツリーはこの不変条件を暗黙的に維持します。つまり、すべてのノードは、関連するすべての最大制約を適用した後、そのセグメントの最小値を格納します。 更新と遅延伝播はどちらも値を増やすだけなので、どの操作も以前の正確さを無効にすることはできません。 max 操作は結合的かつ単調であり、セグメント間で更新を分割したり、後でセグメントをマージしたりしても、同じ最終状態が生成されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SegTree:
    def __init__(self, n):
        self.n = n
        self.mn = [0] * (4 * n)
        self.lazy = [0] * (4 * n)

    def apply(self, idx, val):
        if val > self.mn[idx]:
            self.mn[idx] = val
        if val > self.lazy[idx]:
            self.lazy[idx] = val

    def push(self, idx):
        if self.lazy[idx]:
            v = self.lazy[idx]
            self.apply(idx * 2, v)
            self.apply(idx * 2 + 1, v)
            self.lazy[idx] = 0

    def pull(self, idx):
        self.mn[idx] = min(self.mn[idx * 2], self.mn[idx * 2 + 1])

    def update(self, idx, l, r, ql, qr, val):
        if ql <= l and r <= qr:
            self.apply(idx, val)
            return
        self.push(idx)
        mid = (l + r) // 2
        if ql <= mid:
            self.update(idx * 2, l, mid, ql, qr, val)
        if qr > mid:
            self.update(idx * 2 + 1, mid + 1, r, ql, qr, val)
        self.pull(idx)

    def query(self, idx, l, r, ql, qr):
        if ql <= l and r <= qr:
            return self.mn[idx]
        self.push(idx)
        mid = (l + r) // 2
        res = float('inf')
        if ql <= mid:
            res = min(res, self.query(idx * 2, l, mid, ql, qr))
        if qr > mid:
            res = min(res, self.query(idx * 2 + 1, mid + 1, r, ql, qr))
        return res

def solve():
    n, q = map(int, input().split())
    st = SegTree(n)

    out = []
    for _ in range(q):
        op = list(map(int, input().split()))
        if op[0] == 1:
            l, r, h = op[1], op[2], op[3]
            st.update(1, 1, n, l, r, h)
        else:
            l, r = op[1], op[2]
            out.append(str(st.query(1, 1, n, l, r)))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```実装の中心となる選択は、更新によって値が上書きされることはなく、最大値を使用して値が増加するだけであるということです。 遅延配列は操作の完全な履歴を表すのではなく、最も強い保留中の下限のみを表します。 これにより、伝播を安価に保ち、複数の更新が重なった場合に繰り返し作業が行われるのを防ぎます。 

部分的に覆われたノードによって、より深いセグメントからのより強力な制約が誤って隠蔽されないようにするため、プッシュ操作は不可欠です。

 ## 特殊なケース

 重要なエッジ ケースは、更新が同じセグメントの高さの降順で到着する場合です。 たとえば、同じ間隔で高さ 10 の更新に続いて高さ 3 を適用すると、セグメントは変更されない 10 のままにしておく必要があります。セグメント ツリーはこれを正しく処理します。これは、ノード値と遅延タグの両方が max 経由でのみ更新されるため、小さい方の更新は完全に無視されます。 

もう 1 つのエッジ ケースは、更新が部分的にのみ重複する場合です。 高さ 4 の [1,5] と、高さ 6 の [3,7] を考えてみましょう。中央領域は 6 になる必要があり、残りは 4 または 0 のままです。再帰により、完全にカバーされたノードのみが一定時間内に更新され、部分的にカバーされたノードは正しい粒度に達するまで分割され、境界全体の正確性が維持されます。 

最後のエッジケースは、変更されていないセグメントに対してクエリが繰り返されることです。 遅延伝播を超えると再計算は行われないため、クエリを繰り返してもパフォーマンスが低下せず、格納されたセグメント値は再処理せずに有効なままになります。
