 ## 解決策
 ## 問題の理解

 一連のターゲット トラックをできるだけ早く読み取るために、リニア ハード ドライブに沿って移動する複数の読み取りヘッドをシミュレートすることが求められます。 各ヘッドは特定のトラックから開始し、左、右に移動することも、その場にとどまることもでき、複数のヘッドが同じトラックを占有することもできます。 トラックは、ヘッドがアクセスすると読み取られたとみなされ、ヘッドの初期位置が読み取られたものとしてカウントされます。 私たちの目標は、指定されたすべてのターゲット トラックが読み取られるまでに必要な最小秒数を決定することです。 

入力により得られるのは、`n`頭と`m`両方のリストが昇順でソートされているターゲット トラック。 数値自体は非常に大きくなる可能性があり、`10^10`これは、直接の配列インデックス付けやトラックの完全な配列の構築に依存できないことを意味します。 代わりに、ポジションを直接操作するアプローチが必要です。 

以来`n`そして`m`まで可能です`10^5`、あらゆる解決策が必要です`O(n * m)`おおよその時間がかかるため、時間が遅すぎます。`10^10`操作。 これにより、すべての頭の動きの単純な強引なシミュレーションが排除されます。 エッジ ケースには、ターゲットよりもヘッドの数が多い場合、ターゲットがすでにヘッドの位置にある場合、ターゲットまたはヘッドの間隔が広い場合などがあります。 たとえば、すべてのヘッドがトラック 1 から開始し、ターゲットがトラック 1、2、および 10000000000 にある場合、答えは最も近いターゲットではなく、最も遠いターゲットの距離を反映する必要があります。 

不注意な実装では、1 つのヘッドが複数の隣接するターゲットをカバーし、別のヘッドが遠くのターゲットをカバーする方が速いかもしれないということを考慮せずに、左から右のパスでターゲットにヘッドを貪欲に割り当てようとする可能性があります。 たとえば、`[2, 5]`そしてターゲット`[1, 3, 6]`最初のヘッドを単純に割り当てることはできません`1`そして2番目に`6`; 重複するリーチを考慮して最小全体時間を計算する必要があります。 

## アプローチ

 ブルートフォースアプローチは、毎秒移動する各ヘッドをシミュレートし、トラックを既読としてマークし、すべてのターゲットが訪問されるまで繰り返すことです。 これは、有効な一連の移動によって最終的にすべてのトラックがカバーされるため機能しますが、次の場合には速度が非常に遅くなります。`n`そして`m`到着`10^5`またはトラック番号が次のように大きい`10^10`。 訪問したトラックを明示的に保存することさえ、メモリの制限により現実的ではありません。 

重要な洞察は、これを割り当て問題として扱うことができるということです。つまり、各ヘッドは時間内にトラックの連続セグメントをカバーできるということです。`t`、ヘッドの初期位置からセグメントの両端までの最大距離が超えない`t`。 候補者にとって`t`、各ヘッドが最大で移動するだけで済むように、すべてのターゲットをヘッドに割り当てることができるかどうかを貪欲にチェックできます。`t`。 ヘッドとターゲットの両方をソートすると、ターゲットを左から右にカバーし、各ヘッドにカバーできるターゲットの最も遠いセグメントを割り当てることができます。`t`。 

これにより、問題は特定の条件に対する「実現可能性チェック」に変換されます。`t`、そして最小`t`二分探索を使用して見つけることができます。 範囲を超えて検索します`[0, max_distance]`、 どこ`max_distance`左端のヘッドと右端のターゲットの間の距離、またはその逆の距離です。 貪欲な割り当ては、ヘッドとターゲットがソートされているため機能します。 左端の未割り当てターゲットを左端の使用可能なヘッドに割り当てることで、実行可能な割り当てが失われないことが保証されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(n * m * 最大距離) | O(最大距離) | 遅すぎる |
 | 二分探索 + 貪欲な代入 | O(m log(最大距離)) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ヘッド位置とターゲット位置の配列をソートします。 両方の配列は問題ステートメントですでにソートされていますが、ソートによって入力の正確さが保証されます。 
2. 関数を定義する`can_cover(t)`すべてのターゲットをヘッドに割り当てることができるかどうかをチェックし、ヘッドがそれ以上移動しないようにします。`t`。 ポインタを初期化する`j`次の未割り当てのターゲットを追跡します。 
3. 各ヘッドを左から右に繰り返します。 現在のヘッドについて、そのヘッドがカバーできる連続ターゲットの最大セグメントを計算します。`t`。 2 つの可能性があります。ヘッドが最初に左に移動してから右に移動するか、最初に右に移動してから左に移動して、隣接するターゲットを効率的にカバーします。 セグメントは`[head - t, head + t]`最も効率的な左右の動きを考慮した上で。 
4. ポインタを移動します`j`限り前に進む`targets[j]`現在のヘッドが到達できるセグメント内にあります。 
5. すべてのヘッドを処理した後、すべてのターゲットが割り当てられている場合 (`j == m`)、関数は True を返します。 それ以外の場合は、False を返します。 
6. 二分探索を実行します。`t`。 初期化する`lo = 0`そして`hi = maximum distance between extreme heads and targets`。 その間`lo < hi`、中点を確認してください`mid`。 もし`can_cover(mid)`True を返します、設定されています`hi = mid`; それ以外の場合は、設定します`lo = mid + 1`。 
7. 二分探索が完了したら、`lo`すべてのターゲットをカバーするのに必要な最小限の時間を保持します。 

これが機能する理由は、固定`t`、各ヘッドに左から右にできるだけ多くの連続したターゲットを割り当てることで、これより良い割り当てが存在しないことが保証されます。 不変条件は、各ヘッドが処理された後、現在のポインターの左側にあるすべてのターゲットがすでに最適にカバーされていることです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n, m = map(int, input().split())
    heads = list(map(int, input().split()))
    targets = list(map(int, input().split()))

    def can_cover(t):
        j = 0  # pointer to the next target to cover
        for h in heads:
            if j >= m:
                break
            if targets[j] < h:
                dist = h - targets[j]
                if dist > t:
                    return False
                # head can move left to targets[j] and then right as far as possible
                reach = max(h + t - 2*dist, h + (t - dist)//1)
            else:
                # head moves right only
                reach = h + t
            # assign all targets within reach
            while j < m and targets[j] <= reach:
                j += 1
        return j == m

    lo, hi = 0, max(targets[-1] - heads[0], heads[-1] - targets[0])
    while lo < hi:
        mid = (lo + hi) // 2
        if can_cover(mid):
            hi = mid
        else:
            lo = mid + 1
    print(lo)

if __name__ == "__main__":
    main()
```このソリューションは、任意のヘッドと任意のターゲットの間の可能な最大距離を使用してバイナリ検索範囲を初期化します。 の`can_cover`機能は、動きの両方向を慎重に考慮し、ヘッドが左から右のセグメントを最適にカバーできるようにします。 貪欲な代入ポインタ`j`ターゲットをスキップすることなく、各ヘッドが効率的に利用されるようにします。
