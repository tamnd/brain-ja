 ## 解決策
 ## 問題の理解

 私たちには、すべてのノードが水を含むことも空にすることもできる貯水池のように動作する根の生えた木が与えられています。 ルートはノード 1 に固定されており、すべてのエッジは概念的にノード 1 から離れる方向に向けられています。 水の操作は任意の経路ではなく、祖先と子孫の関係に沿って伝播するため、ツリーの構造は重要です。 

操作には3種類あります。 1 つの操作でノードが満たされ、そのサブツリー内のすべてのノードが強制的に満たされます。 別の操作ではノードを空にし、空の状態をそのノードからルートまで上向きに強制的に伝播させ、すべての祖先をクリアします。 最後の操作では、ノードが現在埋まっているかどうかを単純に尋ねます。 

課題は、どちらのタイプの伝播も非対称であることです。 1 つの方向は、DFS 走査順序で連続するサブツリーに作用し、もう 1 つの方向は、ツリーを変換しない限り連続しないルート パスに作用します。 

制約が十分に大きいため、操作ごとに 1 つずつノードにアクセスするソリューションは失敗します。 最大 500,000 のノードと 500,000 のクエリでは、二次関数の最悪のケースは不可能です。 クエリごとの線形伝播でも、敵対的なケースでは最大 10^11 の操作が発生します。 これにより、対数時間での範囲の更新とポイント クエリをサポートするデータ構造が必要になります。 

ノードごとにブール値だけを維持しようとして、エッジに沿って直接更新しようとすると、微妙な落とし穴が発生します。 サブツリーを埋めるにはすべての子孫をマークする必要があり、これによりほぼすべてのノードを繰り返し訪問することになる可能性があります。 同様に、上向きに空にする場合は、ウォーキング親ポインターが必要ですが、これはクエリごとに線形になり、深いツリーではすぐに中断されます。 

## アプローチ

 直接シミュレーションでは、各ノードのブール配列が維持されます。 ノードを埋めると DFS が実行されてサブツリー全体がマークされ、ノードを空にすることで親の走査が繰り返されて祖先がクリアされます。 これは概念的には単純で正しいですが、最悪の場合、各操作が O(n) ノードに接触する可能性があります。 多くのクエリを使用すると、これは O(nq) にまで低下し、実現可能な限界をはるかに超えます。 

重要な構造上の観察は、オイラー ツアー順序でツリーを表現すると、両方の操作が単純になるということです。 ノードのサブツリーは、DFS 順序で連続するセグメントに対応します。 ただし、ルートへの上向きのパスは単一のセグメントに対応しませんが、先祖に影響を与える最新の「ブロック」操作を追跡することによって暗黙的に処理できます。 

2つのアイデアを紹介します。 まず、オイラー ツアー時間を使用してツリーを平坦化し、すべてのサブツリーがセグメントになるようにします。 次に、2 つのタイムスタンプ付き構造を維持します。1 つはノードに影響を与える最新のサブツリーフィルを追跡し、もう 1 つはノードに影響を与える最新の先祖空操作を追跡します。 ノードは、そのサブツリーに影響を与える最新のフィルが、そのルート パスに影響を与える最新の空よりも新しい場合にフィルされます。 

これにより、問題は、ツリー順序に対する 2 つのタイプの更新の間の優越性の回答に変換されます。いずれも、セグメント ツリーとフェンウィック スタイルのプレフィックス構造で長期的に処理できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース DFS/親トラバーサル | O(nq) | O(n) | 遅すぎる |
 | オイラー ツアー + セグメント ツリー + タイムスタンプ | O(q log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ツリーを 1 でルートし、各ノード u に開始時間 tin[u] と終了時間 tout[u] が割り当てられるようにオイラー ツアーを計算します。 u のサブツリーは、区間 [tin[u], tout[u]] に正確に対応します。 

このオイラー次数に関するセグメント ツリーを維持し、サブツリー フィル操作が適用された最新の時刻を保存します。 fill(v) タイプの各更新では、タイムスタンプ t がセグメント全体 [tin[v], tout[v]] に書き込まれます。

最大タイムスタンプ セマンティクスによる高速範囲割り当てをサポートするために、各セグメント ツリー ノードは値を格納し、これまでに確認された最大タイムスタンプで更新が上書きされる遅延伝播を使用します。 

別に、祖先ベースのクリアリングを処理する必要があります。 各ノードについて、最後に「上向きにクリア」された時刻を維持します。 ノード v で空の操作を実行すると、v からルートまでのパス上のすべてのノードに影響します。 そのパスを明示的にたどる代わりに、v が u の祖先である場合にノード u が影響を受けることを観察します。 この条件はオイラー倍を使用してチェックできます。 tin[v] ≤ tin[u] ≤ tout[v] の場合に限り、v は u の先祖になります。 

したがって、empty(v) は、v が u の祖先となるようなすべてのノード u にわたる範囲割り当てになりますが、これも祖先閉包の逆の意味で v の部分木になります。 重要な単純化は、クリアを v にグローバルな「空き時間」を設定するものと解釈することであり、ノード u の場合、有効な空き時間は u のすべての祖先の中での最大空き時間になります。 これは、v でのポイント更新と、オイラー順序付けによるルートからノードへのパス上の範囲最大クエリと 2 番目の構造をサポートする 2 番目のセグメント ツリーを使用して維持できます。 

より単純で標準的な削減では、深さエントリ イベントによってノードをソートした後、プレフィックス最大クエリをサポートする tin order 上の 2 番目のセグメント ツリーを使用することで、重いパス クエリを回避します。 空き時間を保存する tin 上で BIT またはセグメント ツリーを維持し、祖先の tin 位置の値を維持することによってすべての祖先の最大空き時間をクエリします。 

ノード v のクエリ時に、以下を計算します。 

1. best_fill = オイラー間隔でのセグメント ツリーからの v のサブツリーにわたる最大フィル タイムスタンプ。 
2. best_empty = 2 番目のオイラー トリックを使用した逆のサブツリー上の範囲伝播による空の操作の tin 位置での更新を格納する BIT からの v の祖先の中での最大の空のタイムスタンプ。 

最後に、best_fill > best_empty の場合、ノード v が埋められます。 

これにより、すべての操作が対数時間の更新とクエリに減ります。 

正確さは、fill 操作が下方向に伝播し、empty 操作が上方向に伝播するという事実にかかっており、タイムスタンプが使用されると、両方の方向がオイラー空間での区間優位性チェックになります。 

不変条件は、すべてのノード u について、そのサブツリーに影響を与える最新の fill と、その先祖のいずれかに影響を与える最新の empty を常に維持し、これら 2 つの値が状態を完全に決定するということです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n = int(input())
g = [[] for _ in range(n + 1)]

for _ in range(n - 1):
    a, b = map(int, input().split())
    g[a].append(b)
    g[b].append(a)

tin = [0] * (n + 1)
tout = [0] * (n + 1)
parent = [0] * (n + 1)
depth = [0] * (n + 1)

timer = 0

stack = [(1, 0, 0)]
order = []

while stack:
    v, p, state = stack.pop()
    if state == 0:
        timer += 1
        tin[v] = timer
        parent[v] = p
        stack.append((v, p, 1))
        for to in g[v]:
            if to == p:
                continue
            depth[to] = depth[v] + 1
            stack.append((to, v, 0))
    else:
        tout[v] = timer

class BIT:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 2)

    def update(self, i, v):
        while i <= self.n:
            self.bit[i] = max(self.bit[i], v)
            i += i & -i

    def query(self, i):
        res = 0
        while i > 0:
            res = max(res, self.bit[i])
            i -= i & -i
        return res

bit = BIT(n)

q = int(input())
t = 0

fill_seg = [0] * (4 * (n + 2))
lazy = [0] * (4 * (n + 2))

def update_range(idx, l, r, ql, qr, val):
    if ql <= l and r <= qr:
        fill_seg[idx] = max(fill_seg[idx], val)
        lazy[idx] = max(lazy[idx], val)
        return
    mid = (l + r) // 2
    if lazy[idx]:
        for ch in (idx*2, idx*2+1):
            fill_seg[ch] = max(fill_seg[ch], lazy[idx])
            lazy[ch] = max(lazy[ch], lazy[idx])
        lazy[idx] = 0
    if ql <= mid:
        update_range(idx*2, l, mid, ql, qr, val)
    if qr > mid:
        update_range(idx*2+1, mid+1, r, ql, qr, val)
    fill_seg[idx] = max(fill_seg[idx*2], fill_seg[idx*2+1])

def query_range(idx, l, r, ql, qr):
    if ql <= l and r <= qr:
        return fill_seg[idx]
    mid = (l + r) // 2
    if lazy[idx]:
        for ch in (idx*2, idx*2+1):
            fill_seg[ch] = max(fill_seg[ch], lazy[idx])
            lazy[ch] = max(lazy[ch], lazy[idx])
        lazy[idx] = 0
    res = 0
    if ql <= mid:
        res = max(res, query_range(idx*2, l, mid, ql, qr))
    if qr > mid:
        res = max(res, query_range(idx*2+1, mid+1, r, ql, qr))
    return res

for i in range(1, q + 1):
    c, v = map(int, input().split())
    if c == 1:
        update_range(1, 1, n, tin[v], tout[v], i)
    elif c == 2:
        bit.update(tin[v], i)
    else:
        best_fill = query_range(1, 1, n, tin[v], tout[v])
        best_empty = bit.query(tin[v])
        print(1 if best_fill > best_empty else 0)
```この実装は、明示的な状態反転ではなく、タイムスタンプの順序に依存しています。 各フィル操作はサブツリー間隔に時間を書き込み、各空操作は単一ノードの BIT に時間を書き込みます。これは、プレフィックス最大クエリを通じてすべての子孫に影響を与えるものとして解釈されます。 

微妙な部分は、BIT がオイラー順序のプレフィックスを超えて最大空時間を格納することです。これは、ここで使用されるオイラー番号付けでは祖先ノードが常に子孫の前に現れるため、機能します。 これにより、祖先クエリを明示的なパス クエリではなくプレフィックス クエリに折りたたむことができます。 

## 実用的な例

 1 が 2 と 3 に接続され、2 が 4 に接続されている小さなツリーを考えてみましょう。 

一連の操作: fill(1)、empty(2)、query(4)、query(3) の場合、状態は次のように変化します。 

| ステップ | 操作 | セグメント最大値を埋める | 錫での最大ビット | 答え |
 | --- | --- | --- | --- | --- |
 | 1 | 1 を埋める | [1,1] | 0 | - |
 | 2 | 空の2 | [1,1] | 2 に更新されました | - |
 | 3 | クエリ 4 | 1 | 祖先が空 = 2 | 0 |
 | 4 | クエリ 3 | 1 | 祖先が空 = 0 | 1 |

 ノード 4 のクエリは、空のノード 2 のサブツリー内にあり、空のタイムスタンプがフィル タイムスタンプよりも優先されるため、失敗します。 

ここで、充填前に空が発生する 2 番目のケースを考えてみましょう。 

| ステップ | 操作 | セグメント最大値を埋める | 錫での最大ビット | 答え |
 | --- | --- | --- | --- | --- |
 | 1 | 空の2 | 0 | 1 | - |
 | 2 | 塗りつぶし 2 | 2 | 1 | - |
 | 3 | クエリ 4 | 2 | 1 | 1 |

 ここでは、フィルは空のものよりも新しいものであるため、サブツリーは再びアクティブになります。 

これらのトレースは、完全なノード状態を明示的に維持することなく、タイムスタンプ ドミナンスが上書き動作を正しくキャプチャしていることを確認します。

 ## 特殊なケース

 主なエッジ ケースは、空の操作がルートで発生する場合です。 その場合、その後にサブツリーが入力されない限り、その後のサブツリーの入力に関係なく、すべてのノードは事実上空になります。 tin[1] での空の BIT 更新がすべてのプレフィックス クエリを支配し、すべてのノードを同じ大きな空時間と比較させるため、タイムスタンプ公式はこれをきれいに処理します。 

もう 1 つのケースは、ネストされたサブツリーで塗りつぶしが繰り返される場合です。 サブツリーの更新は最大のタイムスタンプを使用して上書きされるため、後の小さなサブツリーの塗りつぶしが以前の大きな塗りつぶしを誤って消去することはなく、単調な正確性が維持されます。
