 ## 解決策
 ## 問題の理解

 1 つは「プラス」、もう 1 つは「マイナス」と呼ばれる 2 本のワイヤが、デバイスの左側から右側に走るときにどのように重なるかを説明するシーケンスが与えられます。 パスに沿った各位置では、ワイヤの 1 つが物理的に他のワイヤよりも上にあります。 「+」文字は、その位置でプラス線がマイナス線の上にあることを意味し、「-」はマイナス線がプラス線の上にあることを意味します。 

左側は固定されています。プラスのワイヤは上部の接点から始まり、マイナスのワイヤは下部の接点から始まります。 ワイヤを切断したり端点を切り離したりしない限り、ワイヤを平面内で自由に移動できます。 問題は、終点を維持しながらワイヤーがまったく絡まらないように、つまり交差が残らないようにワイヤーを継続的に変形できるかどうかです。 

入力の長さは最大 100,000 まで可能です。これにより、ワイヤ ジオメトリを明示的にモデル化するシミュレーションや、高価な更新によって動的に変化する交差の構造を維持しようとするシミュレーションが除外されます。 文字数が 2 次の場合は、遅すぎます。 

微妙な点は、シーケンスが独立した交差点を記述していないことです。 連続的な三つ編みのような相互作用を描写しています。 一方のワイヤが他方のワイヤに完全に「巻き付く」ことは、特定の交互パターンとしてエンコードされるため、連続する 2 つの同一のシンボルは、必ずしも分離されたシンボルと同じように動作するとは限りません。 

単純な間違いは、隣接する反対側の交差を単にキャンセルしたり、シーケンスを括弧と同様のスタック削減問題のように扱えると想定することです。 たとえば、「+」を開始イベントとして解釈し、「-」を終了イベントとして解釈すると、すぐに失敗します。 

入力:```
-+
```単純なキャンセルの考えでは、交差がキャンセルされると思われるかもしれませんが、これはエンドポイントを移動しないと削除できない完全なツイストを表すため、正しい答えは「いいえ」です。 

もう 1 つの失敗例は、各「+」を独立して処理し、カウントのバランスが取れているかどうかを単にチェックすることです。 シーケンス「+-+-」は、カウント ロジックの下では誤って無害に見えますが、単一のグローバル制約として解釈する必要がある自明ではない編組構造を表す可能性があります。 

## アプローチ

 この問題を考える強引な方法は、平面内の 2 つの曲線の実際の変形をシミュレートすることです。 ワイヤをポリラインとしてモデル化し、交差点を追跡しながらセグメントを局所的に真っ直ぐにすることを繰り返し試行することができます。 交差点を削除するたびに、別の場所に新しい交差点が現れる可能性があるため、このプロセスでは構造全体を何度も再検討する必要がある可能性があります。 最悪の場合、各ローカル調整はそれまでのすべての調整と相互作用し、シーケンス全体で 2 倍以上の更新回数が発生します。 

重要な観察は、実際にはジオメトリを気にするのではなく、シーケンスが一方のワイヤを他方のワイヤに巻き付ける重要な「巻き付け」をエンコードするかどうかだけを気にするということです。 これにより、問題は、プレフィックス構造が不可能な状態を強制するかどうかを追跡することになります。 

重要な単純化は、シーケンスが方向変更のスタックのように動作することです。重要なのは、もう一方のエンドポイント拘束を介してワイヤーを持ち上げる必要があるような方法で交差を「オーバーキャンセル」するかどうかです。 このプロセスは、プラス線が上か下かに応じて増加または減少する単一の整数のバランスを追跡していると解釈できますが、重要な制約があります。つまり、固定エンドポイントを強制的に逆転させるような方法でバランスがしきい値を超えた場合、構成は不可能になります。 

これにより、現在の相対的な巻き状態を表すカウンターを維持する貪欲な線形スキャンが行われます。 シンボルが表示されるたびにカウンターを調整しますが、同時にカウンターが固定エンドポイントによって引き起こされる制約に違反しないように強制します。 最終状態によって、編組が自明であるかどうかが決まります。 

この特定の問題では、条件は、シーケンスが完全な回転をエンコードしたかどうかをチェックすることに帰着します。 これは、一度に複数のアクティブな不均衡の「層」を必要としないことを保証することで検出できます。これは、ラップを強制する方法で実行状態が絶対値で 1 を超えないことを保証するのと同じです。

 ## アルゴリズムのチュートリアル

 単一の整数の状態を維持しながら、シーケンスを左から右に処理します。`bal`。 

1.初期化`bal = 0`。 これは、交差が考慮される前に、システムが固定エンドポイントと一致するニュートラル構成にあることを表します。 
2. シーケンス内の各文字をスキャンします。 文字が「+」の場合、構成を上に押し上げるものとして扱うため、インクリメントします。`bal`1.「-」の場合はデクリメントします`bal`by 1。これは、各ローカル交差点が相対的な順序にどのように寄与するかをモデル化します。 
3. 更新するたびに、状態が不可能な体制に陥っていないかどうかを確認します。 どこかの時点でその大きさが`bal`が 1 を超えると、その構成は固定エンドポイントでは元に戻すことができない完全なツイストを表していると即座に結論付け、拒否します。 
4. 制約に違反することなくスキャンが完了した場合は、構成を継続的に解くことができるため、受け入れます。 

しきい値チェックの背後にある重要な考え方は、不均衡を 1 単位以上蓄積しようとすると、一方のワイヤがもう一方のワイヤに「巻き付く」ことになり、エンドポイントの順序を変更しない限り元に戻すことはできないということです。 

### なぜ効果があるのか

 このプロセスは、終点が固定され順序付けされているという制約の下で、2 本のワイヤ間の正味の巻線を暗黙的に追跡します。 有効なもつれ解除は、どのプレフィックスでも複数のローカル優勢を決して導入しない変形に対応します。 実行中のアンバランスがこの限界を超えると、一方のワイヤがもう一方のワイヤの周りを完全に回転することになります。これは、平面変形だけでは除去できないトポロジー的な障害となります。 したがって、このアルゴリズムは、そのような回転を強制するシーケンスを正確に拒否し、不均衡が局所的に解決可能なままであるその他すべてを受け入れるため、安全です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

s = input().strip()

bal = 0
for ch in s:
    if ch == '+':
        bal += 1
    else:
        bal -= 1
    
    if abs(bal) > 1:
        print("No")
        sys.exit()

print("Yes")
```このコードは単一の実行カウンターを維持し、それを文字ごとに一定時間で更新します。 構成が不可能になると、それ以降の処理では有効性を復元できないため、早期に終了することが重要です。 

唯一の微妙な点は、最後だけでなく、各更新の直後に制約をチェックする必要があることです。 チェックが遅れると、無効な中間構成が誤って受け入れられる可能性があります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    try:
        s = input().strip()
        bal = 0
        for ch in s:
            if ch == '+':
                bal += 1
            else:
                bal -= 1
            if abs(bal) > 1:
                return "No"
        return "Yes"
    finally:
        sys.stdin = old_stdin

# provided sample
assert run("-++-") == "Yes"

# minimum size
assert run("+") == "Yes"

# immediate invalid wrap
assert run("--") == "No"

# alternating safe case
assert run("+-+-") == "Yes"

# longer valid neutral sequence
assert run("-+-++-") == "Yes"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | + | はい | 有効な最小限の構成 |
 | -- | いいえ | 即時違反検出 |
 | +-+- | はい | 交互シーケンスは制限されたままです |
 | -+-++- | はい | オーバーフローのない混合シーケンス |

 ## 特殊なケース

 「+」や「-」などの 1 文字の入力は、完全なラップを作成できないため、常に有効です。 アルゴリズムは 1 つの更新を処理し、しきい値を超えることなく直ちに終了します。 

「--」などの 2 文字のシーケンスは、最も早い段階での失敗を示します。 2 番目のステップの後、バランスは -2 になり、すぐに制約に違反します。 アルゴリズムはその時点で正しく拒否し、さらにスキャンする必要はありません。 

「+-+-」のような交互シーケンスでは、不均衡が 1 単位以上蓄積されることはありません。 実行状態は -1、0、および 1 の間で変動します。これは、エンドポイントの順序を変更せずに、一方のワイヤをもう一方のワイヤ上にスライドさせることで削除できるローカル交差に対応します。 

「-+-++-」のような長い混合シーケンスは、プレフィックスに両方向が含まれている場合でも、実行中の不均衡が許容範囲を超えない限り、構造は絡み合っていないことを示しています。 このアルゴリズムは、最終的な合計に依存するのではなく、すべてのプレフィックスで制約を適用することで正確さを維持します。
