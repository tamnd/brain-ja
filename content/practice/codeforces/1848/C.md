 ## 解決策
 ## 問題の理解

 一連の商品の古い価格と新しい価格を表す 2 つの配列が与えられます。 Vika は、これらの配列の対応する要素間の絶対差を繰り返し計算し、配列を交換し、このプロセスを繰り返します。 目標は、この反復プロセスによって最終的に old-price 配列のすべての要素がゼロになるかどうかを判断することです。 各テスト ケースでは、配列のペアがそのような状態に達する場合は「YES」、そうでない場合は「NO」と答えるように求められます。 

この制約は、テスト ケースごとに最大 10^5 の項目、および最大 10^4 のテスト ケースを含めることができることを意味しますが、すべてのテスト ケースにわたる項目の合計数は 10^5 に制限されます。 これは、二次アルゴリズムでは遅すぎるため、各配列をほぼ線形時間で処理する必要があることを示しています。 

古い配列が最初にすべて 0 である場合、明らかではないエッジ ケースが発生します。 このシナリオでは、新しいアレイに関係なく、ペアは明らかに鈍くなります。 新しい配列の要素が対応する古い配列の値よりも小さいが、すべての違いによって古い配列がゼロになるわけではない場合には、別の微妙なケースが発生します。 各操作のプロセスを直接シミュレートしようとすると、これらの構成の判断を誤ったり、制限時間を超過したりする可能性があります。 

## アプローチ

 ブルート フォース アプローチでは、配列変換を明示的にシミュレートします。 各ステップで、絶対差として新しい配列を計算し、配列を交換します。 これは問題を直接モデル化するため機能します。 ただし、長さが 10^5 の配列の最悪のケースでは、差がゆっくりと減少する可能性があるため、各操作は O(n) であり、反復回数も O(n) になる可能性があります。 これにより、テスト ケースごとに O(n^2) の時間計算量が発生しますが、入力限界を考慮すると遅すぎます。 

解を高速化するための重要な洞察は、操作によって最大の差分構造が維持されることを観察することで得られます。 具体的には、このプロセスは、配列内のすべての要素から最大公約数を法として最小の要素を繰り返し減算するものとして解釈できます。 より具体的には、古い配列のすべての要素が新しい配列の対応する要素を超えず、ソート順で前の要素よりも小さい要素がないように差異が一貫している場合に限り、配列は鈍くなります。 両方の配列をソートし、各旧価格要素が対応する新価格要素を超えていないこと、およびそれらの差が減少していないことを確認することで、ソート後の線形時間の鈍さを判断できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、配列の長さを読み取り、次に古い価格配列と新しい価格配列を読み取ります。 
2. 古い配列がすでにすべて 0 である場合は、「YES」を出力して続行します。 これにより、些細な特殊なケースが処理されます。 
3. 両方の配列をソートします。 並べ替えにより、構造化された方法で要素を比較できるようになり、配列間で相違点チェックが一貫していることが保証されます。 
4. ソートされた配列の対応する最大要素間の初期差を計算します。 この違いは、その後のチェックの参考になります。 
5. 最大の要素から最小の要素まで繰り返します。 ポジションごとに、新価格要素と旧価格要素の差を計算します。 
6. 差が負の場合、演算でゼロを生成することはできません。 「NO」を出力して停止します。 
7. 基準に対して差が大きくなった場合は、くすみ条件に違反するため「NO」を出力します。 
8. すべてのチェックに合格した場合は、「YES」を出力します。

機能する理由: 配列をソートすると、対応する位置が正しい大小関係で比較されることが保証されます。 参照差分は、より小さな要素に伝播するために許容される最大の減少量を取得します。 差分を降順でチェックすることにより、負の値を生成したり差分構造に違反したりすることなく、操作で古い配列を単調にゼロに減らすことができることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        if all(x == 0 for x in a):
            print("YES")
            continue
        a.sort()
        b.sort()
        diff = b[-1] - a[-1]
        if diff < 0:
            print("NO")
            continue
        ok = True
        for i in range(n):
            if b[i] - a[i] > diff or b[i] - a[i] < 0:
                ok = False
                break
        print("YES" if ok else "NO")

if __name__ == "__main__":
    solve()
```コードは、すべてゼロの古い配列という単純なケースを処理することから始まります。 違いを一貫して比較するには、並べ替えが重要です。 参照差は最大の要素を使用して設定され、すべての位置の一貫性と非負性がチェックされます。 Python の高速 I/O を使用すると、大きな入力サイズによるオーバーヘッドが回避されます。 

## 実用的な例

 ### 例 1

 入力配列:

 | --- | --- | --- | --- | --- |
 | イニシャル | [0,0,0,0] | [1,2,3,4] | - | すべてゼロ → はい |

 アルゴリズムは些細な鈍さを即座に検出します。 

### 例 2

 a = [1,2,3]

 b = [1,2,3]

 | ステップ | (ソート済み) | b (ソート済み) | 差分 | チェック |
 | --- | --- | --- | --- | --- |
 | 並べ替え済み | [1,2,3] | [1,2,3] | 0 | b[i]-a[i] = 0 ≤ diff → YES |

 すべての差は一貫していて負ではないため、アルゴリズムは YES を返します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | テストケースごとのコストの大部分を占めるのは並べ替えです。 チェックのリニア スキャンは O(n) |

 ## 特殊なケース

 古い配列がすでにすべて 0 である場合、解はそれ以上の計算を行わずにすぐに YES を出力します。 古い要素が対応する新しい要素を超える配列の場合、アルゴリズムは負の差を識別し、NO を出力します。 古い値と新しい値が等しい配列の場合、参照の差はゼロであり、すべてのチェックに合格し、結果は YES となります。 各ケースでは差の単調性が尊重され、くすみの状態が正しく評価されることが保証されます。
