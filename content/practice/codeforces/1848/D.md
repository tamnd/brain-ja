 ## 解決策
 ## 問題の理解

 ヴィカが化粧品店のボーナス システムから得られる割引総額を最大化するように求められます。 彼女は現在、`s`ボーナスがもらえる`k`さらに購入。 購入するたびに、現在のボーナス数に等しい割引を受けるか、現在の合計額の下一桁だけボーナスを増やすことができます。 目標は、後で収集できる割引の最大合計を計算することです。`k`購入品。 

入力は複数のテスト ケースです。 各テスト ケースが提供するのは、`s`そして`k`、これは非常に大きくなる可能性があります。`s`まで$10^9$そして`k`まで$10^9$。 これにより、すべての購入を個別にシミュレーションするアプローチは即座に除外されます。なぜなら、単純なシミュレーションには最大で$10^9$テスト ケースごとの操作数は、数秒で実行できるものをはるかに超えています。 

エッジケースには、最初のボーナスがゼロである場合、つまりすべての割引がゼロである場合、およびボーナスの最後の桁がゼロである場合が含まれます。 たとえば、次の場合`s = 0`または`s = 10`、ボーナスを増加しても最後の桁は増加しないため、一連のボーナスが停滞する可能性があります。 もう 1 つの注意が必要なケースは、購入数が`k`は非常に大きいため、単純な反復ではタイムアウトになるため、計算を高速化するために最後の桁のパターンについて推論する必要があります。 

## アプローチ

 ブルートフォースアプローチは、割引を適用するか、ボーナスを最後の桁だけ増分して、各購入をシミュレートすることです。 各ステップで、どの選択が最終的な割引を最大化するかを確認します。 これは小規模な場合には機能しますが、`k`、 のために`k`まで$10^9$このアプローチには次のことが必要です$O(k)$テストケースごとに操作が必要になるため、実用的ではありません。 

重要な洞察は、最後の数字の追加は決定論的な操作であり、最後の数字の範囲は 0 ～ 9 であるため、最後の数字のシーケンスは繰り返しパターンに従っていることです。 最後の数字のシーケンスを観察したら、それを使用して、割引が最適になるまでに何回増分できるかを計算できます。 基本的に、問題を等差数列に落とし込みます。最後の桁がゼロでない限り、購入ごとのボーナス増分は一定であるため、実行できる増分数を計算できます。`k`購入した金額を数式を使用して合計し、最終的な割引を適用します。 

下一桁ごとに`d`で`1..9`、その後のボーナス`m`インクリメントはステップの算術シーケンスに従います。`d`。 到達するまでに実行できる全歩数を計算できます。`k`購入後、残りの購入を割引として直接追加します。 これにより、最初の最後の桁を決定した後、O(k) アプローチがテスト ケースごとに O(1) に変わります。

 ## アルゴリズムのチュートリアル

 1. テスト ケースごとに、次の内容を抽出します。`s`そして`k`。 もし`s`がゼロの場合、割引総額はゼロになります。 すぐに 0 を出力して続行できます。 
2. の最後の桁を計算します。`s`。 ゼロの場合、それ以上増加してもボーナスは増加しません。 私たちは割引を受けるべきです`k`倍、合計の割引額は`s * k`。 
3. それ以外の場合は最後の桁`d = s % 10`はゼロではありません。 最終的な割引が最適になるまでに実行できる増分回数を計算します。 増分数を次のように表すと、`m`、各増分によりボーナスが増加します`d`、シーケンスを形成します`s, s + d, s + 2d, ..., s + md`。 
4. これらの合計割引額`m`増分は、次から始まる算術シーケンスの合計です。`s + d`まで`s + m*d`。 これは、等差数列の合計の公式を使用して計算できます。`sum = m/2 * (2*s + (m+1)*d)`m 個の増分を合計すると、
 5. 段階的なステップから最大割引を計算した後、残りの購入からの割引を追加します。`m < k`。 大型用`k`、最後の桁がゼロになると、その後のすべての割引が適用されるため、シーケンスが安定するまでに一定のステップ数を考慮するだけで済みます。`s + m*d`。 
6. 各テスト ケースについて計算された合計割引を出力します。 

重要な特性は、最後の桁が繰り返しの算術シーケンスを決定するということです。 最後の桁がゼロになると、それ以上増分してもボーナスは変わらないため、残りの割引をすべて一度に受け取ることができます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def max_total_discount(s, k):
    if s == 0:
        return 0
    total = 0
    while k > 0:
        last_digit = s % 10
        if last_digit == 0:
            total += s * k
            break
        # Determine how many steps we can take before last digit repeats or becomes 0
        m = min(k, 10)  # last digit cycles every at most 10 steps
        total += m * s + last_digit * (m * (m - 1) // 2)
        s += last_digit * m
        k -= m
    return total

t = int(input())
for _ in range(t):
    s, k = map(int, input().split())
    print(max_total_discount(s, k))
```このソリューションでは、まず次のことを確認します。`s`はゼロです。 while ループは、最後の桁のシーケンスが 10 回の加算ごとに繰り返されるため、最大 10 ステップを使用して等差数列を処理します。 式`m * s + last_digit * (m*(m-1)//2)`以上の増分割引を正しく合計します`m`購入品。 加工後`m`ステップ、更新します`s`そして減少します`k`それに応じて。

 ## 特殊なケース

 もし`s = 0`そして`k`大きい場合、すべての割引はゼロです。 アルゴリズムはすぐにゼロを返します。 

もし`s`たとえば、ゼロで終わる`s = 10`、すべての増分はゼロです。 アルゴリズムが増殖する`s`による`k`ワンステップで合計割引が受けられます。 

もし`k`非常に大きく、`s`最後の桁がゼロでない場合、アルゴリズムは算術公式を使用して最大 10 回循環し、一定時間内に残りの割引を適用します。 これにより、上限の場合でもソリューションが効率的になることが保証されます。`k`。
