 ## 解決策
 ## 問題の理解

 私たちの大学にはいくつかの学部があります。 各部門が一定数のバスケットボール選手を貢献します。 ワファ氏の所属部門`h`、そして彼はすでに最終チームへの出場を保証されています。 

チームには正確に含まれている必要があります`n`ワファ自身を含む選手たち。 Wafa を含む有効なチームはすべて、同様の可能性があります。 Wafa のチームメイトの少なくとも 1 人が彼の部門の出身である確率が必要です。 

部門を想定します`h`含まれています`s[h]`Wafaを含む合計プレイヤー数。 それから、`s[h] - 1`彼のチームメイトになる可能性のある彼の部門の他の選手。 

利用可能なプレイヤーの総数は、すべてのプレイヤーの合計です。`s[i]`。 この合計が以下の場合`n`、完全なチームを形成することは不可能なので、答えは次のとおりです。`-1`。 

制約は十分に小さいため、組み合わせ計算が実行可能です。 部門の数は 1000 に達し、各部門のサイズは 100 に達する可能性があるため、プレーヤーの総数は最大で 100 人になります。`100000`。 組み合わせの数は指数関数的に増加するため、考えられるすべてのチームを列挙することはできません。 1000 人の選手から 50 人の選手を選ぶだけでも、すでに天文学的に多くの可能性が生まれます。 

重要な観察は、必要なのは確率だけであり、実際のチームではないということです。 これは、組み合わせを数学的に数えることを強く示唆しています。 

素朴な実装を静かに破壊する可能性のあるエッジケースがいくつかあります。 

次の入力を考えてみましょう。```
5 2 1
2 2
```大学にはプレーヤーが 4 人しかいませんが、チームのサイズは 5 人です。正しい出力は次のとおりです。```
-1
```不注意な実装では、無効なパラメータとの組み合わせを計算しようとする可能性があります。 

Wafa が彼の部門の唯一のプレーヤーである場合、別の注意が必要なケースが発生します。```
3 3 2
5 1 5
```プレイヤーの総数は十分ですが、部門 2 からチームメイトになる可能性のある人はいません。正しい確率は次のとおりです。```
0
```実装によっては、誤ってゼロで除算したり、すべての部門が少なくとも 2 人のプレイヤーに貢献していると想定したりする場合があります。 

3 番目の微妙なケースは、大学全体を選択する必要がある場合に発生します。```
4 2 1
2 2
```4 人のプレーヤー全員を選択する必要があります。 部門 1 には Wafa を含む 2 人のプレイヤーがいますので、答えは次のようになります。```
1
```反復確率に基づく浮動小数点近似は、不注意に記述すると、ここでエラーが蓄積する可能性があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 Wafa は常に選択されているため、残りを選択するだけで済みます。`n - 1`他の皆からのプレイヤー。 サイズの可能なすべてのサブセットを列挙することができます`n - 1`、選択したプレーヤーの少なくとも 1 人が Wafa の部門の出身であるかどうかを確認し、条件を満たすサブセットの数を数えます。 

Wafa を含むすべての有効なチームが同じ確率で存在するため、これは概念的に機能します。 確率は単純に次のようになります。$$\frac{\text{favorable teams}}{\text{all teams}}$$問題はサブセットの数です。 プレイヤーが約 100,000 人いて、その中から 50 人でも選択しなければならない場合、組み合わせの数は膨大になります。 網羅的に列挙することは完全に不可能です。 

重要な点は、チームを明示的に生成する必要がないということです。 それらを数えるだけで済みます。 

Wafaをチームに修正すると、次のようになります。$$\text{total players} - 1$$残りの候補者は次のとおりです。$$n - 1$$彼らのうち。 

有利なチームを直接カウントするよりも、補完イベントをカウントする方が簡単です。 

悪い出来事は、Wafa のチームメイトの中に彼の部門の出身者がいないことです。 部門以来`h`もっている`s[h] - 1`Wafa 以外の他のプレイヤーは全員避けなければなりません。 

つまり、次のようになります。$$(\text{total players} - 1) - (s[h] - 1)$$自分の部門外の適格なプレーヤー。 

悪いイベントの確率は次のようになります。$$\frac{\binom{\text{outside}}{n-1}} {\binom{\text{total}-1}{n-1}}$$その場合、必要な答えは次のとおりです。$$1 - \text{bad probability}$$これにより、問題は指数列挙からいくつかの組み合わせ計算に変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | 指数 | 遅すぎる |
 | 最適 | O(n) または O(1) の組み合わせ論 | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む`n`、`m`、 そして`h`。 
2.部門サイズ配列を読み取ります。`s`。 
3. プレーヤーの総数を計算します。$$total = \sum s[i]$$4. もし`total < n`、印刷`-1`。 

大学には十分な選手がいないため、有効なチームを編成することは不可能です。 
5. 次のようにしましょう。$$own = s[h-1]$$これはワファ自身を含むワファの部門の選手の数です。 
6. Wafa のチームメイトを選択する方法の合計数を計算します。$$\binom{total-1}{n-1}$$ワファはすでにチームに固定されているため、1 減算します。 
7. Wafa の部門のチームメイトが 1 人もいない不良チームの数を計算します。 

がある：$$total - own$$自分の部門外のプレーヤーの数は次のようになります。$$\binom{total-own}{n-1}$$8. 悪い確率は次のとおりです。$$\frac{\binom{total-own}{n-1}} {\binom{total-1}{n-1}}$$9. 印刷:$$1 - \text{bad probability}$$### なぜ効果があるのか

 Wafa を含むすべてのチームの可能性は等しいため、確率は組み合わせを数えることになります。 

分母は、考えられるすべてのチームメイトの選択をカウントします。 補完イベントの分子は、すべてのチームメイトが別の部門の出身である場合の選択を正確にカウントします。 これら 2 つのセットはすべての可能性を「良い」と「悪い」に分けるため、1 から悪い確率を引くと必要な答えが得られます。 

各チームは正確に 1 つのサブセットに対応するため、アルゴリズムはケースを過剰にカウントしたり見逃したりすることはできません。`n - 1`チームメイト。 

## Python ソリューション```python
import sys
from math import comb

input = sys.stdin.readline

def solve():
    n, m, h = map(int, input().split())
    s = list(map(int, input().split()))

    total = sum(s)

    if total < n:
        print(-1)
        return

    own = s[h - 1]

    total_ways = comb(total - 1, n - 1)
    bad_ways = comb(total - own, n - 1)

    ans = 1.0 - (bad_ways / total_ways)

    print(ans)

solve()
```最初の部分は入力を読み取り、プレイヤーの総数を計算します。 

不可能なケースは、組み合わせ計算の前に処理する必要があります。 もし`total < n`、のような組み合わせ`C(3, 5)`無効になります。 

表現`comb(total - 1, n - 1)`ワファ自身がすでにチームに固定されているため、考えられるチームメイトのセットをすべて数えます。 

表現`comb(total - own, n - 1)`微妙です。 Wafa の部門の他のメンバーも含め、すべてのプレイヤーを Wafa の部門から削除します。 Wafa はすでに個別に修正されているため、部門外のプレーヤーのみが不良イベントの対象になります。 

最終的な答えは浮動小数点除算を使用します。 Python の整数は、任意の大きな組み合わせ値を安全に処理できるため、オーバーフローのリスクはありません。 

インデックス作成`s[h - 1]`部門には 1 から番号が付けられますが、Python リストには 0 から始まるインデックスが付けられるため、間違いやすいです。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io
from math import comb

def solve():
    input = sys.stdin.readline

    n, m, h = map(int, input().split())
    s = list(map(int, input().split()))

    total = sum(s)

    if total < n:
        print(-1)
        return

    own = s[h - 1]

    total_ways = comb(total - 1, n - 1)
    bad_ways = comb(total - own, n - 1)

    ans = 1.0 - (bad_ways / total_ways)

    print(ans)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue().strip()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out

# provided sample
assert run("3 2 1\n2 1\n") == "1.0", "sample 1"

# impossible case
assert run("5 2 1\n2 2\n") == "-1", "not enough players"

# Wafa alone in department
assert run("3 3 2\n5 1 5\n") == "0.0", "no teammate possible"

# all players selected
assert run("4 2 1\n2 2\n") == "1.0", "forced inclusion"

# symmetric departments
res = float(run("3 3 1\n2 2 2\n"))
assert abs(res - 0.4) < 1e-9, "probability check"

 ## 特殊なケース

 不可能なシナリオを考えてみましょう。```
5 2 1
2 2
```プレイヤーの総数はわずか 4 人ですが、チームのサイズは 5 人です。アルゴリズム チェックは次のとおりです。`total < n`すぐに印刷します`-1`。 組み合わせ式は評価されないため、無効な状態は安全に回避されます。 

次に、ワファが自分の部門に一人でいる場合を考えてみましょう。```
3 3 2
5 1 5
```ここ`own = 1`。 つまり、彼の部門から追加の選手はゼロということになる。 

アルゴリズムは以下を計算します。$$\binom{10-1}{2} = \binom{9}{2}$$考えられるすべてのチームメイトの選択について、および:$$\binom{10-1}{2} = \binom{9}{2}$$チームメイトになる可能性のある人はすべて自分の部門外にいるため、選択が間違っていた場合も同様です。 結果の確率は次のようになります。$$1 - 1 = 0$$それは正しいです。 

最後に、強制選択の場合を考えてみましょう。```
4 2 1
2 2
```チームのサイズはプレーヤーの総数と同じです。 すべてのプレイヤーは選ばれなければなりません。 

アルゴリズムは以下を計算します。$$\binom{3}{3} = 1$$チーム全体、および:$$\binom{2}{3} = 0$$悪いチーム。 悪いチームは存在しないので、答えは正確になります`1`。
