 ## 解決策
 ## 問題の理解

 私たちは持っています`n`座席と`n`教授たち。 教授`1`最年長の教授です`n`一番年下です。 一部の座席のペアには順序の制約があります。 もし`(a, b)`と言われて教授が席に座る`a`席に座っている教授よりも上級でなければなりません`b`。 

座席配置は、座席に割り当てられた教授の並べ替えにすぎません。 教授数が少ないほど年功序列が高いことを意味するため、制約は`(a, b)`は次のようになります:```
perm[a] < perm[b]
```割り当てられた教授番号の中にあります。 

有効な配列はすべて辞書順に並べ替えられます。 2001 年は最初の有効な取り決めを使用し、2002 年は 2 番目の有効な取り決めを使用します。 年に使用される配列を出力する必要があります`y`。 

これは、`(y - 2001)`-th 辞書順での有効な順列。 

最も重要な観察は、制約は教授に関するものではなく座席に関するものであるということです。 座席値間の相対的な順序は固定されています。 半順序を満たす順列を数えています。 

制約`n ≤ 16`問題の性質が完全に変わります。 すべての順列にわたる階乗検索は次の理由から不可能です。```
16! ≈ 2 * 10^13
```数秒間順列を生成したとしても、それには及びません。 

同時に、`2^16 = 65536`、非常に管理しやすいです。 これはサブセット DP を強く示唆しています。 

年は次のように大きくなります。`10^18`つまり、有効な取り決めの数は膨大になる可能性があります。 アレンジメントを一つ一つ列挙することはできません。 部分的な代入から有効な補完がいくつ存在するかをカウントし、それらのカウントを使用して置換のブロックをスキップする必要があります。 

単純な実装を壊すいくつかのエッジケースがあります。 

矛盾する一連の制約により、有効な取り決めがゼロになる可能性があります。 

例：```
2 2001 2
1 2
2 1
```シート`1`座席よりも小さい教授番号を含める必要があります`2`、そして同時により大きなもの。 取り決めは存在しません。 正しい出力は次のとおりです。```
The times have changed
```不注意な実装では、依然として DP 遷移が試行され、誤ってガベージ カウントが生成される可能性があります。 

もう 1 つの微妙なケースは、要求された年が有効な取り決めの数を超える場合です。 

例：```
2 2003 0
```あるのは`2! = 2`手配:```
1 2
2 1
```2001 年と 2002 年が有効です。 2003 年は存在しません。 正しい出力は次のとおりです。```
The times have changed
```よくあるバグは、ゼロベースのインデックスを誤って使用し、2001 年をインデックスとして扱うことです。`1`の代わりに`0`。 

重複した制約も入力に表示されます。 

例：```
3 2001 3
1 2
1 2
1 2
```これらの重複は何も変更しないはずです。 制約が不適切に保存されると、度数が膨張したり、遷移が中断されたりする可能性があります。 

## アプローチ

 ブルートフォースの解決策は簡単です。 教授のすべての順列を生成し、それがすべての制約を満たしているかどうかを確認し、有効なものを収集し、辞書順に並べ替えて、必要な年を選択します。 

有効性テストが簡単なため、これが機能します。 あらゆる制約に対して`(a, b)`、単純に次のことを確認します。```
perm[a] < perm[b]
```問題は順列の数です。 と`n = 16`、以下を検査する必要があります。```
16! ≈ 2 * 10^13
```順列。 1 秒あたり 10 億の順列をチェックするだけでも、まだ数時間かかります。 

重要な観察は、辞書編集には完了のカウントのみが必要であるということです。 配置を左から右に構築しているとします。 ある位置に、可能な限り小さな未使用の教授を配置してみます。 その選択の後に有効な補完がいくつ存在するかがわかれば、ターゲットの配置がそのブロックの内側にあるのか、それともブロックの後にあるのかを判断できます。 

これにより、問題は部分的な状態からの有効な割り当てをカウントすることに変換されます。 

サブセット DP は完全に適合します。`n ≤ 16`。 どの教授がすでに割り当てられているかをビットマスクで表します。 その状態から、座席制限に違反することなく次に配置できる教授を決定します。 

座席には制約がありますが、教授は年功序列で割り当てられます。 これにより、非常に有用な解釈が作成されます。 

教授なら`k`次に小さい未使用の教授、次に割り当てられている教授です`k`席に着く`s`席を意味します`s`空席の中で次のランクを獲得します。 

拘束用`(a, b)`、座席`a`座席よりも小さい教授番号を受け取る必要があります`b`。 それで座ってください`a`席に着く前に記入する必要があります`b`。 

これにより、問題はシート上の DAG のトポロジー次数をカウントすることに変換されます。 

これで、状態がかなりきれいになりました。```
dp[mask] = number of ways to fill exactly the seats in mask first
```前提条件となる座席がすべてすでにマスク内にある場合にのみ、座席を追加できます。 

これにより、`O(n * 2^n)`これは簡単に十分に高速なソリューションです。

 | ブルートフォース | O(n! * m) | お(ん!) | 遅すぎる |

 ## アルゴリズムのチュートリアル

 1. すべての制約を解釈する`(a, b)`シート間の依存関係として。 

教授番号が小さいほど上級者となるため、席は`a`席より早く教授を受けなければならない`b`。 これは座席を意味します`b`席によります`a`。 
2. すべての座席の前提条件となるビットマスクを作成します。`pre[i]`席の前にすでに埋まっている必要があるすべての席を格納します`i`埋めることができます。 
3. サブセット DP を使用して、有効なトポロジー次数をカウントします。 

させて：```
dp[mask]
```は、ちょうど座席の後に残りの座席を埋める有効な方法の数を示します。`mask`すでに割り当てられています。 
4. トランジションを定義します。 

から`mask`、座席を選択する場合があります`i`もし：```
i is not in mask
and
all prerequisites of i are already in mask
```正式には:```
(pre[i] & mask) == pre[i]
```5. メモ化された DFS を使用して DP を計算します。 

すべての座席が埋まっている場合、完了は 1 つだけです。 

それ以外の場合は、すべての有効な次の座席の数を合計します。 
6. 次のようにしましょう。```
k = y - 2001
```これは、目的の配置の 0 から始まるインデックスです。 
7. 次の場合:```
dp[0] <= k
```この場合、要求された年が有効な取り決めの数を超えます。 印刷:```
The times have changed
```8. 配列を辞書編集的に再構築します。 

私たちは最小の教授から最大の教授までを割り当てます。 辞書編集上の順序は、どの席に現在最小の教授が割り当てられるかによって決まるため、各ステップで候補席を昇順に試してみます。 
9. 各候補席について、現在の教授をそこに配置した場合にいくつの完了が存在するかを計算します。 

完了数が以下の場合`k`、これらの配置をすべてスキップし、そのカウントをから引きます。`k`。 

それ以外の場合は、その席にコミットして続行します。 
10. 座席の埋まり順を決定したら、それを最終的な順列に変換します。 

席の場合`s`ステップで満たされています`t`、それから教授を受け取ります`t + 1`。 

### なぜ効果があるのか

 DP は、シート依存関係グラフの有効なトポロジー順序を正確にカウントします。 すべての有効な配置は、座席が増加する教授番号を受け取る 1 つの固有の順序に対応します。 

再構築中、小さい教授番号が最初に割り当てられるため、辞書編集上の順序が維持されます。 候補議席を昇順に試すと、辞書順列比較と同じ順序での配置が調べられます。 

各ステップで、DP カウントは、特定のプレフィックスで始まるアレンジメントの数を示します。 これらのカウントを使用してブロック全体をスキップすることは、ターゲットの辞書編集配列に直接ジャンプすることと同じです。 

## Python ソリューション```python
import sys
from functools import lru_cache

input = sys.stdin.readline

INF = 10**18 + 5

def solve():
    n, y, m = map(int, input().split())

    pre = [0] * n

    for _ in range(m):
        a, b = map(int, input().split())
        a -= 1
        b -= 1
        pre[b] |= (1 << a)

    full = (1 << n) - 1

    @lru_cache(None)
    def dp(mask):
        if mask == full:
            return 1

        res = 0

        for i in range(n):
            if (mask >> i) & 1:
                continue

            if (pre[i] & mask) != pre[i]:
                continue

            res += dp(mask | (1 << i))

            if res > INF:
                res = INF

        return res

    k = y - 2001

    total = dp(0)

    if total <= k:
        print("The times have changed")
        return

    order = []
    mask = 0

    for _ in range(n):
        for seat in range(n):
            if (mask >> seat) & 1:
                continue

            if (pre[seat] & mask) != pre[seat]:
                continue

            cnt = dp(mask | (1 << seat))

            if cnt <= k:
                k -= cnt
            else:
                order.append(seat)
                mask |= (1 << seat)
                break

    ans = [0] * n

    for professor, seat in enumerate(order, start=1):
        ans[seat] = professor

    print(*ans)

solve()
```最初の部分では、入力制約を前提条件マスクに変換します。 もし`(a, b)`存在する場合は座席に座ります`b`席によります`a`なので、内部に対応するビットを設定します`pre[b]`。 

メモ化された DP は、すでに埋まっている座席のサブセットに対して機能します。 移行条件:```
(pre[i] & mask) == pre[i]
```座席のすべての前提条件を意味します`i`すでに埋まっています。 

DP 値は非常に大きくなり、要求された年の範囲を超える可能性があります。 上限は次のとおりです`INF`との比較だけが必要なので、`10^18`。 

再構築フェーズは微妙な部分です。 順列値を直接構築しているわけではありません。 代わりに、教授を受け入れる席の順序を構築します。`1, 2, 3, ...`。 

席を想定します`2`が最初に選ばれます。 つまり教授`1`そこに座っています。 席の場合`0`2番目に選ばれました、教授`2`そこに座っている、など。 

昇順でシートを試すと、辞書編集上の横断が保証されます。 候補者が貢献するたびに`cnt`配列では、それらの配列が 1 つの連続した辞書編集ブロックを形成します。 もし`k >= cnt`、ブロック全体をスキップします。 

よくある間違いは、座席の順序ではなく教授によって再構成することです。 DP は当然、教授の割り当てに直接対応する座席補充注文をカウントします。
