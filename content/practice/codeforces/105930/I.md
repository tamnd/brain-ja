 ## 解決策
 ## 問題の理解

 3 × 3 のグリッドの 2 つの構成が与えられており、各セルには 1 から 9 までの個別の数字が含まれています。したがって、各グリッドは実際には、行優先の順序で配置された 1 から 9 までの数字の並べ替えです。 タスクは、許可された一連の操作を使用して最初のグリッドを 2 番目のグリッドに変換し、使用される操作の数を最小限に抑えることです。 それが不可能な場合は、-1 を報告する必要があります。 

主な問題は、グリッドがセルごとに編集されていないことです。 代わりに、これを変更する唯一の方法は、行、列、またはグリッド全体に適用されるグローバル変換の小さな固定セットを使用することです。 サンプル ヒントでは、行の循環シフト、列の循環シフト、グリッド全体の時計回りの回転などの操作が示されているため、各移動ではグリッドが常に 1 ～ 9 の順列のままであるという事実が維持されます。 

すべての状態は 9 個の要素の順列であるため、可能な状態の総数は 9!、つまり 362880 です。これは、すべての状態をグラフで完全に走査できるほど十分小さいですが、クエリごとの検索で最大 2 × 10^5 までの T を独立して処理できるほど小さくはありません。 

単純なアイデアは、ターゲット構成に到達するまで、すべてのテスト ケースの初期構成から BFS を実行することです。 362880 ノード上の単一の BFS でも高価であり、それを最大 200,000 回繰り返すことは完全に不可能であるため、これはすぐに失敗します。 

テスト ケースごとに個別にグリッドをハッシュし、毎回最短パスを実行しようとすると、微妙な問題が発生します。 たとえ各 BFS が「制限されている」としても、繰り返しによりそれは不可能になります。 

エッジケースは主にアイデンティティと到達可能性に関するものです。 両方のグリッドがすでに同一である場合、答えは 0 でなければなりません。許可された変換の下でソースからターゲットを生成できない場合 (操作によって完全な置換グループが生成されない場合は可能です)、正しい答えは -1 です。 不注意な解決策では、多くの場合、すべての順列が到達可能であると想定され、到達不可能な状態の距離が暗黙的に生成されてしまいます。 

## アプローチ

 ブルート フォース アプローチでは、各グリッドをグラフ内のノードとして扱い、クエリごとに開始状態からターゲット状態までの最短パス検索を実行します。 各ノードには、許可された操作の 1 つの適用に対応する発信エッジがいくつかあります。 362880 の状態があり、各状態の遷移の数は一定であるため、BFS は 1 回だけ実行可能です。 

失敗のポイントは繰り返しです。 テスト ケースごとに BFS をやり直すと、クエリごとに数十万の状態を探索することになり、最悪の場合、10^11 のオーダーの操作が必要になります。 

重要な観察は、状態のグラフが固定されており、テスト ケースから独立していることです。 同じ重み付けされていないグラフに対して最短パス クエリを繰り返し実行しています。 これは、すべての最短パス距離を一度前処理することを示唆しています。 

ただし、メモリの関係で、すべてのペアの最短パスを保存することは不可能です。 重要な構造特性は、すべての操作が可逆的であり、9 つのタイルにわたる順列グループを形成することです。 つまり、任意の状態ペア間の距離は必要ありません。 代わりに、状態 A から状態 B までの距離は、合成 A^{-1} ∘ B にのみ依存します。したがって、すべてのクエリは、アイデンティティ状態から単一の派生状態までの距離に短縮できます。 

これにより、9 つすべてのグラフを構築するという問題が軽減されます。 状態を確認し、ID 構成から単一の BFS を実行し、相対的な置換をハッシュすることで O(1) の各クエリに応答します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとの BFS | O(T・9!) | お(9!) | 遅すぎる |
 | ID から BFS を事前計算する | O(9! · K + T) | お(9!) | 承認済み |

 ここで、K は状態ごとの操作の数であり、定数です。 

## アルゴリズムのチュートリアル

 ## ステップ 1: 各グリッドを順列としてエンコードする

各 3 × 3 グリッドを行優先の順序で長さ 9 のタプルに変換します。 これにより、すべての状態の正規表現が得られるため、それらを効率的に保存して比較できるようになります。 

## ステップ 2: エンコードされた状態に対する 3 つの操作を定義する

 許可された動きを 9 要素配列の変換として実装します。 行シフトは 3 つの固定位置を回転し、列シフトは別の 3 つの固定位置を回転し、完全な回転は固定マッピングに従って 9 つの位置すべてを並べ替えます。 各操作は、1 つの有効な状態を別の有効な状態にマップします。 

これが重要な理由は、ノードが順列でエッジがこれらの変換である明示的なグラフを構築しているためです。 

## ステップ 3: ID 構成から BFS を実行する

 ソートされたグリッド 1 ～ 9 をアイデンティティ状態として選択します。 到達可能なすべての順列に対して BFS を実行し、各状態に到達するために必要な最小限の操作数を保存します。 

状態をポップするたびに、すべての操作を適用し、より短い距離が見つかった場合は隣接を緩和します。 すべてのエッジの重みが 1 であるため、BFS は最短パスを保証します。 

## ステップ 4: 距離を辞書に保存する

 dist[state] を、恒等式からその順列に到達するために必要な操作の最小数として記録します。 

状態が一度も訪問されない場合、その状態は到達不可能となり、暗黙的に距離が -1 になります。 

## ステップ 5: 各クエリを 1 つのルックアップに減らす

 テスト ケースごとに、ソース グリッド A とターゲット グリッド B を読み取ります。置換空間で A を B にマッピングする変換を計算します。これは、A の逆行列を B で合成するのと同じです。 

次に、この派生状態を正規タプルに変換し、その BFS 距離を直接読み取ります。 その値が答え、または到達できない場合は -1 です。 

### なぜ効果があるのか

 状態空間は、可逆演算によってエッジが定義されるグラフを形成します。 これは、A から B へのパスが、アイデンティティから A^{-1} ∘ B へのパスに正確に対応することを意味します。アイデンティティからの BFS は、到達可能なすべてのグループ要素に正しい最短距離を割り当て、グループの不変性により、左の合成の下で距離が一貫していることが保証されます。 したがって、すべてのクエリは、正確さを失うことなく、事前に計算された単一の最短パス値に帰着します。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def apply_row_shift(a, r):
    a = list(a)
    base = r * 3
    a[base], a[base + 1], a[base + 2] = a[base + 2], a[base], a[base + 1]
    return tuple(a)

def apply_col_shift(a, c):
    a = list(a)
    a[c], a[c + 3], a[c + 6] = a[c + 6], a[c], a[c + 3]
    return tuple(a)

def rotate(a):
    a = list(a)
    b = a[:]
    b[0], b[1], b[2] = a[6], a[3], a[0]
    b[3], b[4], b[5] = a[7], a[4], a[1]
    b[6], b[7], b[8] = a[8], a[5], a[2]
    return tuple(b)

# build BFS once
start = (1, 2, 3, 4, 5, 6, 7, 8, 9)

dist = {start: 0}
q = deque([start])

while q:
    cur = q.popleft()
    d = dist[cur]

    for r in range(3):
        nxt = apply_row_shift(cur, r)
        if nxt not in dist:
            dist[nxt] = d + 1
            q.append(nxt)

    for c in range(3):
        nxt = apply_col_shift(cur, c)
        if nxt not in dist:
            dist[nxt] = d + 1
            q.append(nxt)

    nxt = rotate(cur)
    if nxt not in dist:
        dist[nxt] = d + 1
        q.append(nxt)

def read_state():
    arr = []
    for _ in range(3):
        arr.extend(input().strip())
    return tuple(map(int, arr))

def inverse_map(a):
    pos = [0] * 10
    for i, v in enumerate(a):
        pos[v] = i
    return pos

def compose(inv_a, b):
    # state representing A^{-1} ∘ B in positional form
    res = [0] * 9
    for i in range(9):
        res[i] = b[inv_a[i]]
    return tuple(res)

t = int(input())
for _ in range(t):
    A = read_state()
    B = read_state()

    invA = inverse_map(A)
    target = compose(invA, B)

    print(dist.get(target, -1))
```BFS セクションは完全な状態グラフを 1 回構築します。 各操作は直接インデックスの置換として実装され、遷移を一定時間に保ちます。 辞書`dist`ID 構成からの最短距離を保存します。 

クエリごとに、グリッドが平坦化され、順列に変換されます。 の`inverse_map`step は A の逆順列を構築し、`compose`相対状態 A^{-1} ∘ B が生成されます。これが、実際に BFS テーブルで検索される状態です。 

実装でよくある落とし穴は、順列が値をマップするか位置をマップするかを混同することです。 ここでは一貫して状態を「位置の値」として扱い、反転によってそれを正しい合成に必要な「値の位置」に変換します。

 ## 特殊なケース

 エッジ ケースの 1 つは、ソース グリッドとターゲット グリッドが同一である場合です。 その場合、合成された順列は距離 0 で BFS テーブルに存在する恒等状態になるため、遷移がなければ答えは正確に 0 になります。 

もう 1 つのエッジ ケースは、許可された操作で ID から合成された順列に到達できない場合です。 この場合、BFS ディクショナリには表示されず、検索では -1 が返されます。 これにより、操作セットが完全な対称グループを生成すると誤って想定されるのを防ぎます。 

最後の微妙なケースは、構成方向が間違っていることです。 A^{-1} ∘ B の代わりに B ∘ A^{-1} を誤って計算すると、異なる順列が得られ、したがって間違った検索が行われることになります。 逆構築により、変換が BFS ルートに正しく調整され、距離クエリの正確さが維持されます。
