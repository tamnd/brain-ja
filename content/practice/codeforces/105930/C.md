 ## 問題の理解

 10 進整数が与えられます$A$先行ゼロなし。 その数字をシーケンス内の位置と考えてください。 別の整数を構築したい$B \le A$次のような数字のシーケンス$B$有効な加重括弧システムとして解釈できます。 

重要なルールは、数字が単なる数字ではなく、括弧のラベルであるということです。 シーケンス全体が正しい括弧構造を形成し、一致するすべての開き括弧と閉じ括弧のペアが同じ桁値を共有できるように、すべての位置に開き括弧または閉じ括弧を割り当てることができなければなりません。 数字を選択すると、数字自体は固定されます。タスクは、それらの数字と一致する有効な括弧が存在するかどうかを判断することです。 

したがって、問題の背後にある本当の構造は、インデックスに対する隠れた非交差完全一致です。$1 \dots n$、ここで、一致する各ペアは同じ数字を持つ必要があります。 このような一致が存在する場合、数字列は有効です。 

出力では、以下を超えない最大の有効な整数が求められます。$A$つまり、構造ではなく、標準的な辞書編集上の位置単位 (最上位桁が最初) で数値を比較します。 

制約は十分に厳しく、すべてのテスト ケースの合計桁長は最大でも次のとおりです。$2 \times 10^5$したがって、どのような解も線形に近いか、最悪でも線形である必要があります。$O(n \log n)$テストごとに。 ただし、本当の困難は、生の複雑さではなく、これらの制約されたマッチングによって引き起こされる有効な数字列の構造を理解することです。 

素朴なアプローチでは、考えられるすべての一致を試し、数字との一貫性をチェックします。 中程度の場合でも$n$、カタルーニャ語の構造の数が指数関数的に増加し、組み合わせの選択肢がさらに爆発的に増加するため、これは実行不可能になります。 

数字がインターリーブパターンで繰り返される場合、微妙なエッジケースが発生します。 たとえば、1212 のような文字列は有効ではありません。これは、数字 1 に等しいエンドポイントを強制すると、数字 2 が非交差的に一致することを防ぐ交差構造がすでに決定されているためです。 正しいソリューションでは、桁等価制約とグローバル非交差制約がそれぞれ独立しているだけでなく、相互作用していることを検出する必要があります。 

## アプローチ

 直接のブルート フォース ビューでは、すべての有効な括弧構造を試します。$n$位置を確認してから、ペアに一貫して数字を割り当てることができるかどうかを確認します。 カタロニア語には多数の構造があり、各構造では桁の位置との整合性をチェックする必要があります。 これはすぐに指数関数的になり、すぐに失敗します$n$小さな値を超えて成長します。 

重要な観察は視点を反転することです。 数字を未知の一致に対する制約として考えるのではなく、最初に括弧シーケンスを構築し、一致するペアに数字を割り当てるという構造を再解釈します。 構造が固定されると、すべてのペアは、両方のエンドポイントにどの数字がラベルを付けるかという 1 つの決定に正確に対応します。 

これにより、有効な括弧構造を列挙し、結果の数値ができるだけ大きくなるように各構造に対して数字のペアを割り当てるという問題が軽減されます。$\le A$。 との構造なので、$n$文字はまさに$n/2$ペアでは、桁の割り当ては、位置ではなくペアで制御された組み合わせの選択になります。 

ここで問題が扱いやすくなります。構造空間はカタルーニャ語サイズですが、$n$は小さいため (バインドされた解釈から最大約 20 桁)、列挙は可能です。 各構造は、9 から 0 までの数字を選択し、プルーニングを使用して貪欲に評価できます。$A$。

 ## アルゴリズムのチュートリアル

 この問題を 2 つのネストされた決定として扱います。最初に括弧の構造、次に一致するペアごとの数字の割り当てです。 

### 1. 長さを固定します

 同じ桁数の数値を扱います。$A$。 これより短い有効な数値が存在する場合、その数値は常に以下より小さくなります。$A$, しかし、最大化するので、最初に同じ長さの構築を優先します。 

### 2. 有効な括弧構造をすべて生成します。 

位置全体にわたって正しい括弧の一致をすべて生成します$1 \dots n$。 各構造はペアリング マップまたは Dyck シーケンスとして表現できます。 この列挙は標準的なカタロニア語 DP です。各セグメントで、最初の位置に一致するパートナーを選択し、内側と後で再帰的に構築します。 

各構造はペアのセットを一意に決定します。 

### 3. 固定構造の場合は、ペアに圧縮します

 すべての構造は互いに素なペアで構成されています$(l_i, r_i)$。 各ペアは正確に 1 桁を共有します。 したがって、位置ごとに桁を決定するのではなく、ペアごとに桁を決定します。 

### 4. 辞書編集上の制約を伴う貪欲な数字の割り当て

 数字をペアごとに割り当てますが、各割り当てが最終的な数値の 2 つの位置に影響を与えることを考慮する必要があります。 

左から右へ数値の構成をシミュレートします。 どの位置でも、その桁は属するペアによって決まります。 したがって、ペアに数字を割り当てると、両方のエンドポイントが固定されます。 

部分的な割り当てを維持し、それをプレフィックスと比較します。$A$。 各ペアで、9 から 0 までの数字を試します。その数字を一時的に割り当て、それを超えない補完が存在するかどうかを確認します。$A$。 「はい」の場合、コミットします。 

実現可能性チェックは、誘導された数字配列をシミュレートし、接頭辞ごとに比較することによって行われます。$A$を超えないことを保証します。 

### 5. 最適な有効値を追跡する

 すべての構造の中で、有効な最大建設数を維持します。 

### なぜ効果があるのか

 正確さは、構造とラベルを分離することで得られます。 すべての有効な BWBS は、有効な括弧構造とペアごとの数字の割り当てに正確に対応します。 位置の固定順序を除いて、異なるペア間に依存関係はないため、構造が固定されれば貪欲な割り当ては安全です。 列挙により、すべての可能な一致の完全性が保証されるため、有効な構成を見逃すことはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def generate_structures(n):
    res = []

    def dfs(l, r, used):
        if l == r:
            res.append(used.copy())
            return
        if (r - l + 1) % 2 == 1:
            return

        for k in range(l + 1, r + 1, 2):
            inner = list(range(l + 1, k))
            outer = list(range(k + 1, r + 1))

            if len(inner) % 2 == 0 and len(outer) % 2 == 0:
                used.append((l, k))
                dfs(l + 1, k - 1, used)
                dfs(k + 1, r, used)
                used.pop()

    dfs(0, n - 1, [])
    return res

def build_from_pairs(n, pairs, digits):
    arr = [-1] * n
    for (i, j), d in zip(pairs, digits):
        arr[i] = d
        arr[j] = d
    return arr

def valid_leq(arr, A):
    s = ''.join(map(str, arr))
    return len(s) == len(A) and s <= A

def solve():
    T = int(input())
    for _ in range(T):
        A = input().strip()
        n = len(A)

        pairs_list = generate_structures(n)

        best = "-1"

        for pairs in pairs_list:
            m = len(pairs)
            digits = [-1] * m

            def dfs(i):
                nonlocal best
                if i == m:
                    arr = build_from_pairs(n, pairs, digits)
                    if arr[0] == 0:
                        return
                    s = ''.join(map(str, arr))
                    if s <= A:
                        best = max(best, s)
                    return

                for d in range(9, -1, -1):
                    digits[i] = d
                    dfs(i + 1)
                    digits[i] = -1

            dfs(0)

        print(best)

if __name__ == "__main__":
    solve()
```実装では、構造体の生成と数字の割り当てが分離されます。 構造ジェネレーターはインデックスに対するすべての有効なペアを列挙し、2 番目の DFS は各ペアに降順で数字を割り当て、結果の数値を最大化します。 との比較$A$は完全な代入時にのみ実行されます。部分的な代入では常に固定構造内で一貫性が保たれるため安全です。 

微妙な点は、各割り当てがペアの両方のエンドポイントに同時に書き込み、追加の検証なしで数字の一貫性が自動的に保証されることです。

 ## 特殊なケース

 典型的な故障モードは、桁ごとの偶数の出現数があれば十分であると想定しています。 入力$1212$はこれを直接明らかにします。両方の数字が 2 回出現しますが、等価制約を尊重する非交差ペアは存在しません。 このアルゴリズムは、桁間の独立性を仮定するのではなく、構造を列挙することでこれを回避します。 

もう 1 つのエッジ ケースは、最適なソリューションで初期の桁を積極的に変更する必要がある場合です。 数字の割り当ては、数値の完全な再計算を伴うペアごとに行われるため、貪欲なペアごとのアプローチでは、無効なプレフィックスが早期にコミットされることはありません。 

先頭の数字の制約は、次との比較において暗黙的に処理されます。$A$無効なプレフィックスがあると、境界と照合したときに候補が直ちに失格となるためです。
