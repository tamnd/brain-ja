 ## 解決策
 ## 問題の理解

 各入力テスト ケースでは、固定形式 (大文字の後に数字が続く) で記述された 2 つの優れた分類が提供されます。 この文字は、O、B、A、F、G、K、M のように、最も熱いものから最も冷たいものへと並べられた大まかな温度クラスを表します。各クラス内では、0 から 9 までの数字が温度を調整し、0 がより熱く、9 がより冷たくなります。 

したがって、すべての分類は事実上、70 個の可能な離散値を持つ 1 次元の温度スケール上の点になります。 課題は、そのような 2 つの点を比較し、最初の星が 2 番目の星よりも熱いか、冷たいか、またはまったく同じ温度であるかを判断することです。 

制約は小さく、それぞれの比較には定数時間の処理が含まれ、最大 1000 回の比較が可能です。 これは、各ペアを解析して O(1) で比較するソリューションで十分である一方、並べ替えや複雑なシミュレーションを伴うものは不要なオーバーヘッドであることを直ちに示唆しています。 

微妙な失敗例は、文字列として辞書編集的に比較する場合に発生します。 たとえば、「A9」と「B0」を文字列として比較すると、文字の順序が ASCII の順序と一致するため、ここでは誤って機能しますが、これに依存すると脆弱で、エンコードや表現が変更されると壊れる可能性があります。 もう 1 つの潜在的な間違いは、数字の比較の意味が逆であることを無視していることです。つまり、数字が小さいほど、温度が低く、温度が低いことを意味します。 

エッジケースは主に境界の文字と数字に関するものです。 たとえば、O0 と O0 を比較すると同じ結果が得られます。 M9 が可能な限り最も低温で、O0 が最も高温であるため、M9 と O0 を比較すると、最初の方が低温になるはずです。 

## アプローチ

 問題を解釈する強引な方法は、すべての分類を 0 ～ 69 の範囲の温度数値に明示的にマップすることです。O0 を 0、O1 を 1、...、O9 を 9、次に B0 を 10 として割り当て、M9 が 69 になるまで同様に割り当てます。両方の入力が変換されると、比較は整数比較に減少します。 

これが機能するのは、分類システムが最初に文字クラスごとに、次にクラス内の数字ごとに厳密に順序付けされているためです。 ブルート フォース マッピングはすでに一定サイズなので効率的ですが、少し間接的です。 

順序が辞書順になっており、文字にはカスタムのアルファベットが使用され、各文字内の数字の順序が逆になっていることに注目すると、さらに単純化できます。 完全なマッピング テーブルを構築する代わりに、文字のインデックスを計算し、それを数字と組み合わせることができます。 

文字ランク O、B、A、F、G、K、M を 0 ～ 6 に対応させると、星は次のように表されます。`rank(letter) * 10 + digit`。 これにより、全体の順序が 1 つの整数に直接エンコードされ、正確さが保たれます。 

ブルート フォース アプローチでは文字ごとの辞書検索が使用されますが、最適なアプローチではそれが直接算術エンコーディングに置き換えられます。 どちらもテスト ケースごとに O(1) ですが、後者の方がクリーンで、余分なデータ構造が回避されます。

 ## アルゴリズムのチュートリアル

 比較が単純な整数比較になるように、各分類を直接数値で表現する必要があります。 

1. 各テスト ケースの 2 つの分類文字列を読み取ります。 各文字列の長さは正確に 2 であるため、解析は定数時間で行われます。 
2. 温度シーケンス O、B、A、F、G、K、M 内の位置に従って、文字を 0 ～ 6 のランクに変換します。この順序は固定されており、大まかな温度レベルを定義します。 
3. 数字文字を 0 ～ 9 の整数に変換します。この数字は、その文字クラス内の温度を絞り込みます。 
4. 単一の整数値を次のように計算します。`rank * 10 + digit`。 これが機能するのは、各文字クラスがちょうど 10 個の値にまたがっており、各クラス内で数字の順序が一貫しているためです。 
5. 両方の星に対してこれを繰り返し、2 つの整数を生成します。 
6. 2 つの整数を比較します。 最初の値が小さい場合、O0 が最小値であるため、より熱い星に対応します。 大きいほうが涼しいですね。 等しい場合、両方の分類は同一です。 

この変換が有効である主な理由は、元の順序がすでに辞書順の積として構造化されているためです。主キーは文字クラス、副キーはホットネスの逆順の数字です。 

### なぜ効果があるのか

 文字クラスは温度において厳密に単調であり、各クラスには均一に順序付けされた細分割が正確に 10 個含まれるため、マッピングでは順序が維持されます。 10 を掛けるとクラスが互いに素な間隔に分割されるため、クラス間に重複は存在しません。 クラス内では、桁の比較は温度の方向と一致するため、結合された整数は曖昧さなく元の順序を完全にエンコードします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

order = {
    'O': 0,
    'B': 1,
    'A': 2,
    'F': 3,
    'G': 4,
    'K': 5,
    'M': 6
}

def encode(s):
    return order[s[0]] * 10 + (ord(s[1]) - ord('0'))

t = int(input())
out = []

for _ in range(t):
    a, b = input().split()
    va = encode(a)
    vb = encode(b)

    if va < vb:
        out.append("hotter")
    elif va > vb:
        out.append("cooler")
    else:
        out.append("same")

print("\n".join(out))
```この解決策は、スペクトル クラスの固定順序を定義することから始まります。 これにより、比較中に条件付きロジックが繰り返されることがなくなります。 各分類文字列は、文字の寄与と数字の寄与を個別に分離するエンコード関数を使用してコンパクトな整数に変換されます。 

よくある間違いは、文字列を直接比較することです。 一部のデータセットを渡すことはできますが、ASCII 順序に依存しており、科学的な順序を明示的にエンコードしません。 もう 1 つの微妙な問題は、より小さいエンコード値がより高温の星に対応するということを忘れていることです。そのため、比較の方向をマッピングの意味に注意深く合わせる必要があります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    order = {'O':0,'B':1,'A':2,'F':3,'G':4,'K':5,'M':6}

    def encode(s):
        return order[s[0]] * 10 + (ord(s[1]) - ord('0'))

    t = int(input())
    out = []
    for _ in range(t):
        a, b = input().split()
        va = encode(a)
        vb = encode(b)
        if va < vb:
            out.append("hotter")
        elif va > vb:
            out.append("cooler")
        else:
            out.append("same")

    return "\n".join(out)

# provided samples
assert run("5\nO2 O7\nM9 M2\nG2 G2\nA0 B9\nF8 K1") == "hotter\ncooler\nsame\ncooler\nhotter"

# custom cases
assert run("1\nO0 O0") == "same"
assert run("1\nO0 M9") == "hotter"
assert run("1\nM9 O0") == "cooler"
assert run("1\nG9 G0") == "cooler"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | O0 O0 | 同じ | 同一の極端な境界 |
 | O0 M9 | もっと暑い | フルレンジ比較 |
 | M9 O0 | クーラー | 反転フルレンジ |
 | G9 G0 | クーラー | クラス内での桁順序の反転 |

 ## 特殊なケース

 エッジケースの 1 つは、次のような同一の星を比較することです。`M9 M9`。 エンコードでは両方とも 6*10+9=69 となり、等価性が正確に保たれるため、アルゴリズムは同じ値を正しく出力します。 

もう 1 つのエッジ ケースは、クラス間の境界です。`B0 A9`。 エンコードにより、B0 = 1_10+0=10 および A9 = 2_10+9=29 が得られるため、他のクラスでは桁範囲が小さいにもかかわらず、B0 がよりホットであると正しく識別されます。 

最後のケースは、次のようなクラス内逆転です。`F8 F1`。 エンコードではそれぞれ 38 と 31 が与えられるため、38 > 31 となり、出力は最初のスターの方が冷たくなります。これは、クラス内で数字が大きいほど冷たさを意味するという事実と一致します。
