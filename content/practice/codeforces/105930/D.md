 ## 解決策
 ## 問題の理解

 私たちには次のようなシステムが与えられています`n`円形に配置されたワーカー ノード。インデックスは次のとおりです。`0`に`n-1`。 各タスクは単一のノードに送られるのではなく、連続したサブタスクのシーケンスを生成します。 タスクは 2 つの値で説明されます。`a`そして`b`。 タスクが作成するのは、`a`サブタスク、インデックス付き`0`を通して`a-1`、およびサブタスク`j`ノードに割り当てられています`(b + j) mod n`。 

したがって、各タスクはノードのリング上の循環間隔に寄与します。 長い文章で寄稿を書くことを想像してみると、`n`配列、各タスクが追加する`+1`インデックスについて:`b, b+1, ..., b+a-1`モジュロをラップアラウンドする`n`。 

目標は、すべてのノードについて、すべてのタスクを処理した後にノードに到達するサブタスクの数を計算することです。 

制約は大きく、すべてのテスト ケースにわたって、`n`そして`q`せいぜい`2 × 10^5`。 これにより、各サブタスクを個別に処理するソリューションは即座に除外されます。 単一のタスクには次のものを含めることができます`a`まで`10^9`したがって、そのサブタスクを明示的に反復することは不可能です。 

主な困難は、各タスクが循環する可能性のある大きな周期的な間隔を表しており、それらすべてを効率的に集約する必要があることです。 

素朴な考えを打ち破るいくつかの特殊なケース:

 タスクは円全体を複数回カバーする場合があります。`a >= n`。 例えば、`n = 5`、`a = 12`、`b = 1`。 その後、各ノードが少なくとも 2 回訪問され、一部のノードは状況に応じて追加の訪問を受けます。`12 mod 5`。 単純な「間隔を 1 回マークする」アプローチでは、繰り返される全サイクルを見逃してしまいます。 

タスクは、折り返しにより 2 つのセグメントに分割される場合もあります。 例えば、`n = 7`、`a = 4`、`b = 5`ノードを生成します`5, 6, 0, 1`。 これを単一の範囲として扱う`[5, 8)`モジュラー処理を行わないと、不正なインデックス作成が発生します。 

最後に、なぜなら、`a`が大きい場合は、部分的な残りから完全なサイクルを分離する必要があります。 そうしないと、実装がオーバーフローするかタイムアウトになります。 

## アプローチ

 直接シミュレーションでは、すべてのタスクを反復して各タスクを処理します。`a`サブタスクと増加するカウンター。 これは定義に正確に従っているため、概念的には正しいです。 ただし、コストはサブタスクの総数に比例し、その数は最大になる可能性があります。`q × max(a)`、実現可能な限界をはるかに超えているとき、`a`到達する`10^9`。 

演算の構造は、古典的な循環差分配列のアイデアを示唆しています。 各タスクは、リング全体に一定の寄与を複数回追加し、さらに最後の部分セグメントを追加します。 分解したら`a`として`a = k·n + r`、その後、すべてのノードが正確に受信します`k`全サイクルからの貢献。 この部分は均一であり、個々のノードに触れることなくグローバルに追加できます。 

残るのは、長さの単一の線形区間です。`r`から始まる`b`円形アレイ上で。 これは、巡回配列における標準的な範囲更新の問題です。 差分配列を使用してこれを処理できます。つまり、各間隔を 2 つのポイント更新に変換し、最後にプレフィックスの合計を取得します。 

この分離が機能するのは、円形構造が規則的であるためです。 すべての全回転は同一であるため、どこでも一定のオフセットに寄与します。 残りのみが位置に依存します。

 | --- | --- | --- | --- |
 | ブルートフォース | O(∑a) | O(n) | 遅すぎる |
 | 最適 (サイクル分解 + diff 配列) | O(n + q) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### 1. 配列を初期化する`diff`サイズの`n + 1`そして変数`base = 0`差分配列には部分的なセグメントのみが蓄積されます。 の`base`変数には、すべてのタスクにわたる全サイクルからの寄与が格納されます。 

### 2. タスクごとに`(a, b)`、計算する`k = a // n`そして`r = a % n`値`k`円を一周する回数を表します。 各ラウンドで正確に加算されます`1`すべてのノードに適用するため、適用を遅らせます。 

たまる`base += k`タスクごとに。 

### 3. もし`r == 0`、次のタスクに進みます

 剰余がない場合、タスクは全サイクルのみで構成されるため、均一に寄与し、範囲の更新は必要ありません。 

### 4. それ以外の場合は、長さの周期的な範囲更新を適用します。`r`から始まる`b`間隔がラップするかどうかに応じて、これを 2 つのケースに分割します。 

もし`b + r - 1 < n`、セグメントは連続しているため、次のようにします。`diff[b] += 1`、`diff[b + r] -= 1`。 

ラップアラウンドする場合は、次の時点で終了するとします。`t = (b + r - 1) % n`、次に更新します:`diff[b] += 1`、`diff[n] -= 1`、`diff[0] += 1`、`diff[t + 1] -= 1`。 

これは増分を正しく表しています`[b, n-1]`そして`[0, t]`。 

### 5. 変換する`diff`プレフィックス合計を使用して最終配列に変換する

 累計を計算します`diff`、各ポジションごとに`i`、最終的な答えは`base + prefix_sum[i]`。 

### なぜ効果があるのか

 すべてのタスクは次のように分解されます。`k`全回転と 1 つの部分円弧。 全回転はすべてのノードに同様に寄与するため、それらを単一のスカラーに格納します。`base`正しさを保ちます。 差分配列は部分的なアークを正確にキャプチャし、プレフィックスの合計により各ノードでの合計のオーバーラップが再構築されます。 すべての寄与はグローバルに均一であるか、単一の間隔であるため、タスク間の相互作用によってこの分解が崩れることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    diff = [0] * (n + 1)
    base = 0

    for _ in range(q):
        a, b = map(int, input().split())
        k = a // n
        r = a % n

        base += k

        if r == 0:
            continue

        l = b
        rr = (b + r - 1)

        if rr < n:
            diff[l] += 1
            diff[rr + 1] -= 1
        else:
            rr %= n
            diff[l] += 1
            diff[n] -= 1
            diff[0] += 1
            diff[rr + 1] -= 1

    ans = [0] * n
    cur = 0
    for i in range(n):
        cur += diff[i]
        ans[i] = cur + base

    print(*ans)

t = int(input())
for _ in range(t):
    solve()
```この解決策は、グローバルな貢献をローカルな貢献から分離することから始まります。 の`base`変数は、すべてのタスクからの全サイクルを蓄積します。 これにより、概念的にはすべてのノードに均等に影響を与える操作のために配列に触れることがなくなります。 

の`diff`配列には部分的な円弧の調整のみが保存されます。 各更新は、ラッピングが発生するかどうかに応じて、最大 2 つまたは 4 つのポイント操作に変換されます。 次に、プレフィックス合計の再構築により、これらが最終的なノードごとのカウントに変換されます。 

微妙な点は、ラップアラウンドを正しく処理することです。 モジュロ演算を継続的にシミュレートしようとする代わりに、実装では循環区間を最大 2 つの線形セグメントに分割し、すべての演算を標準の差分配列ロジック内に保ちます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + q) | 各タスクは O(1) 個の更新に寄与し、最終パスは O(n) |
 | スペース | O(n) | サイズ n の差分配列と結果配列

 制約により、最大で次のことが許可されます。`2 × 10^5`合計`n + q`したがって、テスト ケースごとの線形ソリューションで十分です。 このアルゴリズムは、タスクごとに一定の作業とテスト ケースごとに 1 回のスイープのみを実行し、制限内に快適に収まります。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    def solve():
        n, q = map(int, input().split())
        diff = [0] * (n + 1)
        base = 0

        for _ in range(q):
            a, b = map(int, input().split())
            k = a // n
            r = a % n
            base += k

            if r == 0:
                continue

            rr = b + r - 1
            if rr < n:
                diff[b] += 1
                diff[rr + 1] -= 1
            else:
                rr %= n
                diff[b] += 1
                diff[n] -= 1
                diff[0] += 1
                diff[rr + 1] -= 1

        ans = [0] * n
        cur = 0
        for i in range(n):
            cur += diff[i]
            ans[i] = cur + base

        return " ".join(map(str, ans))

    t = int(input())
    out = []
    for _ in range(t):
        out.append(solve())
    return "\n".join(out)

 ## 特殊なケース

 主なエッジケースは次のような場合です`a`の倍数です`n`。 そのような状況では、`r = 0`、つまり、寄付金全体が吸収されます。`base`。 アルゴリズムは差分更新をスキップし、すべてのノードが正確に受信します。`a / n`増加します。 各完全な回転ですべてのノードがサイクルごとに 1 回正確にカバーされるため、これは定義と一致します。 

もう 1 つのエッジ ケースは、間隔が配列の終わりで折り返される場合です。 のために`n = 5`、`a = 3`、`b = 4`、影響を受けるノードは次のとおりです。`4, 0, 1`。 アルゴリズムはこれを次のように分割します。`[4,4]`そして`[0,1]`2 つの差分更新を使用し、プレフィックスの合計によりこれら 3 つの位置が正確に再構築されます。 

最後に、非常に大きな`a`値は、整数分解が正しく適用されているかどうかをテストします。 重労働はすべて軽減されるので、`a // n`そして`a % n`、アルゴリズムは反復を回避します`a`完全に、従って、以下の値まで`10^9`パフォーマンスを低下させることなく安全に取り扱えます。
