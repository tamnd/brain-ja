 ## 問題の理解

 各セルに整数値が含まれるグリッドが与えられます。 左上隅から右下隅に到達するまでは、右または下にのみ移動できます。 このような動きはすべて単調なパスを形成し、すべてのパスが通過するセルの値を収集します。 

選択したパスについて、そのパスに現れる値のセットを調べ、そのパス上のどこにも現れない最小の非負の整数を意味する mex を計算します。 タスクは、この mex をできるだけ小さくするパスを選択することです。 

したがって、問題は値のカバレッジを最大化することではなく、少なくとも 1 つの有効なパスに小さな整数が強制的に存在しないようにすることです。 値 0 を完全に回避するパスが存在する場合、mex 0 を達成できます。すべてのパスに必ず 0 が含まれる場合、mex は少なくとも 1 でなければならず、値 1 が何らかのパスによって回避できるかどうかの確認に進み、以下同様です。 

この制約は、すべてのテスト ケースにわたるセルの総数が最大 100 万であることを意味します。 これにより、テスト ケースごとに多くの候補値を個別に完全なグリッド トラバースを再計算するソリューションは即座に除外されます。 各整数値に対してフルパス検索を実行する単純なアプローチでは、最大で次の値まで繰り返しスキャンすることになります。$10^6$細胞の損傷により、許容できない事態が引き起こされる$10^{12}$最悪の場合はスケールアップ。 

重要なエッジケースは、避けようとしている値が非常に一般的であるか、グリッド全体に「障壁」を形成している場合に現れます。 たとえば、次のような単一行グリッドの場合`1 x 5`、特定の値がすべての列に出現する場合、どのパスにもその値が含まれている必要があるため、たとえ移動が些細であっても、その値を避けることは不可能です。 

もう 1 つの微妙なケースは、開始セルまたは終了セル自体に、回避しようとしている値が含まれている場合です。 この場合、すべてのパスに両方のエンドポイントが含まれている必要があるため、有効なパスはこれを回避できません。 

## アプローチ

正確さは mex の定義から得られます。パスには mex が含まれます。$k$回避するときは正確にそれより小さい$k$mex は最初に欠落している整数によってのみ決定されるため、$k$欠落している整数が最大でも以下であることを保証します$k$。 

ボトルネックは、各チェックがグラフの到達可能性の問題であることです。$n \times m$グリッド、原価計算$O(nm)$。 最悪の場合、多くの値を試行する可能性があり、これを繰り返し行うと遅くなりすぎます。 

重要な観察は、固定値の場合、複雑な動作をシミュレートする必要がないことです。$k$、唯一関連する操作は、値を持つすべてのセルを削除するかどうかです。$k$開始と終了の間のグリッドを切断します。 これにより、各チェックがフィルタリングされたグリッドでの標準的なグリッド到達可能性テストに減ります。

 ## アルゴリズムのチュートリアル

 0 から始まる値を処理します。 

1. 候補値が固定の場合$k$、値が等しいすべてのグリッド セルをマークします。$k$ブロックされたように。 これらのセルはパスでは使用できません。 
2. BFS または DFS を実行します。$(1,1)$、ただし、グリッド内にありブロックされていない右および下に隣接するもののみを通過します。 
3. 辿り着くことができたら$(n,m)$の場合、値を回避するパスが存在します。$k$、したがってメキシコは最大でも可能です$k$。 出力します$k$そしてやめてください。 
4. ターゲットに到達できない場合、すべての有効なパスには、次のものが少なくとも 1 回含まれている必要があります。$k$、ということで、次へ移動します。$k+1$そして繰り返します。 

正確さは、各チェックを実現可能性テストとして解釈することで得られます。値を持つすべてのノードを削除した後に、グリッド グラフに単調なパスが存在するかどうかを尋ねています。$k$。 

### なぜ効果があるのか

 有効なパスはすべて、一連の右および下への移動によって完全に決定され、グリッドは有向非巡回グラフを形成します。 値を含むすべてのセルを削除する$k$それらのノードをグラフから正確に削除します。 始点から終点までのパスがまだ存在する場合は、値のセットに以下が含まれないパスが存在します。$k$、これは直接的に最大でも mex を意味します。$k$。 逆に、そのようなパスが存在しない場合、すべての単調パスは少なくとも 1 つを通過する必要があります。$k$-valued セル、mex を強制的により大きくする$k$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve_one(n, m, grid):
    start_val = grid[0][0]
    
    # We try k starting from 0 upward until a feasible path exists.
    # In practice, we only need to consider values that appear in the grid.
    vals = set()
    for row in grid:
        for x in row:
            vals.add(x)
    vals = sorted(vals)
    
    # If 0 is not in grid, mex is 0 immediately.
    if 0 not in vals:
        return 0

    # Precompute list of candidates starting from 0 upward
    # but only those that matter (present values or 0)
    # We still conceptually test k in increasing order.
    max_val = vals[-1]

    def reachable(blocked_val):
        if grid[0][0] == blocked_val or grid[n-1][m-1] == blocked_val:
            return False
        
        q = deque()
        vis = [[False] * m for _ in range(n)]
        q.append((0, 0))
        vis[0][0] = True
        
        while q:
            i, j = q.popleft()
            if i == n - 1 and j == m - 1:
                return True
            
            for di, dj in ((0, 1), (1, 0)):
                ni, nj = i + di, j + dj
                if ni < n and nj < m and not vis[ni][nj]:
                    if grid[ni][nj] != blocked_val:
                        vis[ni][nj] = True
                        q.append((ni, nj))
        return False

    # try candidates in increasing order
    k = 0
    while True:
        if reachable(k):
            return k
        k += 1

def main():
    T = int(input())
    out = []
    for _ in range(T):
        n, m = map(int, input().split())
        grid = [list(map(int, input().split())) for _ in range(n)]
        out.append(str(solve_one(n, m, grid)))
    print("\n".join(out))

if __name__ == "__main__":
    main()
```このソリューションは、候補値に等しいすべてのセルを削除した後に単調パスが存在するかどうかをテストする小さな BFS ルーチンを構築します。 メイン ループは、実現可能性が達成されるまでこの値を増分します。これにより、達成可能な最小の mex が直接得られます。 

実装の微妙な詳細は、開始セルまたは終了セルのいずれかがブロックされた値と等しい場合、パスが存在できないため、早期に拒否されることです。 これにより、不必要なトラバースが回避されます。

## テストケース```python
import sys, io
from collections import deque

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    input = _sys.stdin.readline

    def solve():
        T = int(input())
        res = []
        for _ in range(T):
            n, m = map(int, input().split())
            g = [list(map(int, input().split())) for _ in range(n)]

            def reachable(k):
                if g[0][0] == k or g[n-1][m-1] == k:
                    return False
                q = deque([(0, 0)])
                vis = [[False]*m for _ in range(n)]
                vis[0][0] = True
                while q:
                    i, j = q.popleft()
                    if i == n-1 and j == m-1:
                        return True
                    for di, dj in ((0,1),(1,0)):
                        ni, nj = i+di, j+dj
                        if 0 <= ni < n and 0 <= nj < m and not vis[ni][nj]:
                            if g[ni][nj] != k:
                                vis[ni][nj] = True
                                q.append((ni, nj))
                return False

            k = 0
            while not reachable(k):
                k += 1
            res.append(str(k))
        return "\n".join(res)

    return solve()

 ## 特殊なケース

 クリティカルなエッジ ケースは、開始セル自体が候補値と等しい場合です。 この状況では、パスを開始できないため、BFS は候補を即座に拒否します。 これにより、アルゴリズムが次の値に正しく移動します。 

もう 1 つのケースは、グリッドが単一の行または単一の列である場合です。 このような場合、その行にブロックされた値が表示されるとすぐにグラフが切断されるため、到達可能性チェックは特に敏感になりますが、同じ BFS ロジックによって正しく処理されます。 

最後に、グリッド内のどこにも値が表示されない場合、BFS は常に成功するため、最初のそのような値がすぐに答えになります。 最初に欠落している整数がすべてのパスにすでに存在していないため、これは mex の定義と一致します。
