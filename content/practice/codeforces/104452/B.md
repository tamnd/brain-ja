 ## 解決策
 ## 問題の理解

 線に沿った植物の高さのリストと一連のクエリが与えられます。 各クエリは切断高さを示します$L$、そしてそのカットの上にどれだけの材料が残っているかを計算する必要があります。 

高さのある各ブッシュについて$a_i$、上記の部分のみ$L$貢献するのは、それがポジティブな場合のみです。 したがって、各ブッシュが貢献します$\max(a_i - L, 0)$。 タスクは、クエリごとにすべてのブッシュにわたるこの寄与を合計することです。 

したがって、各クエリは独立しています。高さに水平カットを配置することを想像します。$L$、それより下のすべてを破棄し、残った垂直方向の長さを合計します。 

制約$N, K \le 10^5$これにより、クエリごとに合計を最初から再計算する必要がなくなりました。 直接シミュレーションすると費用がかかります$O(NK)$、それは約です$10^{10}$最悪の場合、動作が遅すぎます。 これは、各クエリが対数時間または定数時間で応答できるように高さを前処理することを直ちに示唆します。 

ここでよく見られる単純な間違いは、要素のみを再計算することです。$a_i > L$前処理なしで。 たとえば、高さが次の場合、$[10^9, 10^9, \dots]$クエリは多数の小さな値であり、すべてのクエリは配列全体をスキャンするため、ほとんどの値がクエリ間で同様に動作する場合でもタイムアウトが発生します。 

もう 1 つの微妙な落とし穴は、寄与が要素の数が超過するかどうかに依存することを忘れていることです。$L$そしてそれをどれだけ超えているか。 上記の要素の単なるカウントとして扱う$L$大きさの情報が失われ、不正確な答えが生成されます。 

## アプローチ

 ブルート フォース アプローチでは、各クエリが個別に評価されます。 与えられた$L$、すべてを反復します$a_i$、蓄積する$a_i - L$いつ$a_i > L$、合計を出力します。 これは定義に直接従っているため正しいですが、同じスキャンを繰り返します。$K$回、結果として$O(NK)$時間。 

重要な観察は、固定された$L$、より大きい要素のみ$L$そして、それらの寄与は、カウントと合計を分離する方法で書き換えることができます。 配列をソートしてプレフィックスの合計を維持すると、超過した要素の数をすぐに計算できます。$L$とその合計額。 これにより、各クエリが二分検索と算術演算に削減され、効率的な評価が可能になります。 

式を変形します。$$\sum \max(a_i - L, 0)
= \sum_{a_i > L} a_i - L \cdot (\text{count of } a_i > L)$$配列がソートされると、単一のバイナリ検索とプレフィックス合計ルックアップで両方の用語を取得できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(NK)$|$O(1)$| 遅すぎる |
 | 並べ替え + プレフィックスの合計 |$O(N \log N + K \log N)$|$O(N)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 高さの配列を降順でない順に並べ替えます。 これにより、二分探索を使用して、指定されたクエリ値より大きいすべての要素を分離できます。 
2. プレフィックス合計配列を構築します。`pref[i]`最初の合計を格納します`i`ソートされた配列内の要素。 これにより、一定時間の範囲合計クエリが可能になります。 
3. 各クエリ値について$L$、二分探索を使用して最初のインデックスを見つけます`pos`そのような`a[pos] > L`。 からのすべて`pos`に$N-1$答えに貢献します。 
4. 以下より大きいすべての要素の合計を計算します。$L$として`total = pref[n] - pref[pos]`。 
5.超過する要素の数を計算します$L$として`cnt = n - pos`。 
6. 失われたベースの高さを減算します。$L \cdot cnt$から`total`最終的な答えを得るために。 
7. 各クエリの結果を個別に出力します。 

重要な考え方は、しきい値によって配列が分割されると、寄与分は残りの要素の数の一次関数になるため、必要な両方の統計が前処理から直接得られるということです。 

### なぜ効果があるのか

 ソートにより、すべての有効な貢献者が配列の連続したサフィックスを形成することが保証されます。 接頭辞の合計は累積合計をエンコードするため、接尾辞の合計は一定時間で計算できます。 変換により元の非線形 max-expression がそのサフィックスにわたる 2 つの線形量の差に書き換えられるため、すべてのクエリは 1 つの区間計算に減ります。 すべての用語はプレフィックスまたは除外されたサフィックスのいずれかで 1 回だけ考慮されるため、情報が失われることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    k = int(input())
    
    a.sort()
    
    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + a[i]
    
    from bisect import bisect_right
    
    for _ in range(k):
        L = int(input())
        pos = bisect_right(a, L)
        cnt = n - pos
        total = pref[n] - pref[pos]
        ans = total - L * cnt
        print(ans)

if __name__ == "__main__":
    solve()
```並べ替え後、各クエリしきい値を超える要素のサフィックスをすぐに分離できます。 プレフィックス合計配列は、そのサフィックスを定数時間合計クエリに変換します。 二分探索により、寄与する要素と寄与しない要素の間の境界が特定されます。 次に、各クエリは、元の定義から直接導出された固定算術式を使用して評価されます。 

よくある実装上の間違いは、`bisect_left`の代わりに`bisect_right`に等しい要素が誤って含まれています。$L$。 もう 1 つの微妙な問題は、要素ごとではなく、サフィックス全体の合計を計算した後に減算を適用する必要があることを忘れていることです。そうしないと、整数演算が不必要なループに劣化します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))
    k = int(input())
    a.sort()

    pref = [0]
    for x in a:
        pref.append(pref[-1] + x)

    from bisect import bisect_right

    out = []
    for _ in range(k):
        L = int(input())
        pos = bisect_right(a, L)
        cnt = n - pos
        total = pref[n] - pref[pos]
        out.append(str(total - L * cnt))
    return "\n".join(out)

 ## 特殊なケース

 重要なエッジケースは、すべての要素が以下の場合です。$L$。 この状況では、サフィックスは空であり、答えはゼロでなければなりません。 アルゴリズムはこれを処理します。`pos = n`したがって、接尾辞の合計とカウントは両方ともゼロとなり、数式は当然ゼロを返します。 

もう一つのケースは次のような場合です。$L = 0$。 次に、すべての要素が完全に寄与し、答えは配列の合計になります。 二分検索で返されるのは、`pos = 0`したがって、サフィックスは配列全体であり、減算は何も行いません。 

すべての要素が等しい場合、各クエリは 1 つのステップですべてを保持するか、すべてを削除します。 接尾辞の合計とカウントの両方が一緒にスケーリングされ、次の場合に正確なキャンセルが維持されるため、式はこの突然の遷移を正確に捕捉します。$L$値を超えています。
