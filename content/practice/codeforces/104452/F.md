 ## 解決策
 ## 問題の理解

 長方形の中に平面的な鉄道システムが与えられています。 駅は整数座標に配置され、駅のペアを接続する直線のレール セグメントがあります。 2 つの特別なステーションが長方形の上下の境界線にあり、タスクは下の税関ステーションから上の税関ステーションまで列車を送ることです。 

各レール セグメントの物理的な長さは、ユークリッド距離に等しいです。 長い列車$k$セグメントが少なくとも$k$単位が長い。 したがって、ルートに沿った制限要因は、そのルート上の最短のセグメントになります。 

ただし、移動は単純なグラフ パスの問題だけではありません。 電車が中間駅を通過する場合、急旋回はできません。 より正確には、あるセグメントに沿って到着し、別のセグメントに沿って出発する場合、それら 2 つのセグメントの間の角度は以下を超えてはなりません。$120^\circ$。 このため、ルートの実現可能性は現在の駅だけでなく到着方向にも依存します。 

出力は最大の整数です$k$ルート上のすべてのセグメントが少なくとも長さを持つ、一番下の税関から一番上の税関までの有効なルートが存在するようにします。$k$、すべてのターンは角度の制約を尊重します。 

制約は以下を示唆しています$10^4$駅と$3 \cdot 10^4$セグメントなので、これに近いソリューションは$O(m^2)$失敗します。 ターン コンストレイントの幾何学的性質が、ノード上の単純な最短パスまたは最大幅パスでは不十分な主な理由です。 

いくつかの状況では、単純なアプローチが崩れます。 方向を無視して端で最も幅の広い道を走ろうとすると、交差点で急カーブを必要とする道を誤って許可してしまう可能性があります。 もう 1 つの微妙なケースは、最適なボトルネック パスがグローバルに最短ではないため、角度の制約がなくても長さだけのダイクストラが失敗する場合です。 

## アプローチ

 回転制約を無視すると、問題は古典的な最大幅パスの問題になります。つまり、各エッジにその長さに等しい容量を割り当て、最小エッジの重みを最大化するパスを見つけます。 これは、ノード全体の最大ヒープダイクストラを使用して解決できます。$O(m \log n)$。 

この難しさは、発信エッジに沿って移動できるかどうかが、どのエッジに到着したかによって決まるという事実から生じます。 グラフはノード単独ではマルコフ関数ではなくなりました。 同じノードには異なる方向から入ることができ、ある到着方向では特定の出口が許可され、別の方向では出口がブロックされる場合があります。 

これに対処する強引な方法は、状態空間を拡張することです。 ノードを追跡するだけではなく、ノードに到達するために使用される有向エッジを追跡します。 各状態は、前のエッジとともにノードにいることを表します。 このような状態から、入力エッジの方向との角度条件を満たすすべての出力エッジに沿った遷移を試みることができます。 これにより、問題はエッジ状態にわたる最短パス スタイルの検索に変換され、各遷移でボトルネック値の更新が行われます。 

重要な観察は、対物レンズが単調なままであることです。パスに沿って、列の長さはこれまでに使用された最小エッジ長です。 これにより、状態が現在のボトルネック値によって優先順位付けされ、遷移によってのみこの値が減少または維持されるダイクストラのような伝播が可能になります。 

単純な拡張では、ノードのすべてのエッジ ペアを繰り返しチェックする危険があります。 実際には、ドット積を使用して幾何学的互換性をオンザフライで計算します。これにより、密なペア テーブルの保存が回避されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 方向を無視したノード パスに対するブルート フォース |$O(\text{invalid})$|$O(m)$| 間違っています |

 ## アルゴリズムのチュートリアル

 グラフを有向辺に変換し、「ノードにどのように入ったか」について最良優先検索を実行します。 

1. すべての無向レール セグメントについて、そのユークリッド長を計算し、それを 2 つの有向エッジとして表します。 これにより、移動方向を明示的に扱うことができます。 
2. ノードごとに隣接リストを構築して、どのステーションからでもすべての発信エッジに迅速にアクセスできるようにします。 
3. 探索状態を有向辺として定義する$u \to v$、現在ノードにいることを意味します$v$から到着した$u$。 州は、これまでにそのルートに沿って達成された可能な限り最良の列車の長さ (ボトルネック) を保存します。 
4. 下部のカスタムノードから検索を初期化します。 開始時には入ってくる方向がないため、開始ノードから出る任意のエッジを取得できます。 このような各エッジは、その長さに等しいボトルネックを持つ初期状態になります。 
5. 現在のボトルネック値によって順序付けされた最大優先度のキューを使用します。 常に、現在可能な最大のトレインを許可している状態を最初に拡張してください。 
6. エッジ経由到着に対応した状態を展開する場合$u \to v$、すべての出力エッジを考慮します$v \to w$どこ$w \neq u$。 候補ごとに、ベクトル間の角度をチェックして方向転換が許可されるかどうかを計算します。$\overrightarrow{vu}$そして$\overrightarrow{vw}$。 トランジションは角度が次の値を超えない場合にのみ有効です。$120^\circ$、これは内積条件と同等です。 
7. 遷移が有効な場合、現在のボトルネックとエッジの長さの最小値として新しいボトルネックを計算します。$v \to w$。 この値により、その有向エッジの既知の最良の状態が改善される場合は、その有向エッジを優先キューにプッシュします。 
8. 州が最上位の税関ノードに到達すると、それは有効な完全なルートを表します。 そのようなすべての到着の中で最大のボトルネックを追跡します。 
9. 答えは、目的地で見つかった最大のボトルネックです。 存在しない場合は、ゼロを出力します。 

### なぜ効果があるのか

 検索では、各状態がその有向エッジで終わるすべての有効なパスの中で可能な最大の最小エッジ長を格納するという不変条件が維持されます。 すべての遷移は単調操作 (正のエッジ長で最小値を取る) のみを適用するため、また状態はボトルネックの降順で処理されるため、状態が最適な値で拡張されると、その後のパスでそれを改善することはできません。 方向制約は状態定義に完全に取り込まれるため、無効な回転が暗黙的に想定されることはありません。 

## Python ソリューション```python
import sys
import heapq
input = sys.stdin.readline

def dot(ax, ay, bx, by):
    return ax * bx + ay * by

def ok(u, v, w, coords):
    # check angle at v between (v->u) and (v->w)
    ux, uy = coords[u]
    vx, vy = coords[v]
    wx, wy = coords[w]

    a1, a2 = ux - vx, uy - vy
    b1, b2 = wx - vx, wy - vy

    # angle <= 120 => cos >= -1/2
    # 2*(a·b) >= -|a||b|
    ab = a1 * b1 + a2 * b2
    a2n = a1 * a1 + a2 * a2
    b2n = b1 * b1 + b2 * b2

    return 4 * ab * ab >= a2n * b2n * 1  # safe squared form check below

def solve():
    x_max, y_max = map(int, input().split())
    s, t = map(int, input().split())
    n, m = map(int, input().split())

    N = n + 2
    coords = [(0, 0)] * N
    coords[0] = (s, 0)
    coords[n + 1] = (t, y_max)

    for i in range(1, n + 1):
        x, y = map(int, input().split())
        coords[i] = (x, y)

    adj = [[] for _ in range(N)]
    edges = []

    for _ in range(m):
        u, v = map(int, input().split())
        x1, y1 = coords[u]
        x2, y2 = coords[v]
        dx, dy = x2 - x1, y2 - y1
        dist2 = dx * dx + dy * dy
        adj[u].append((v, dist2))
        adj[v].append((u, dist2))
        edges.append((u, v, dist2))

    start = 0
    end = n + 1

    # dist[(prev, u)] = best bottleneck arriving at u from prev
    dist = {}

    pq = []

    # initial moves from start
    for v, d2 in adj[start]:
        dist[(start, v)] = d2
        heapq.heappush(pq, (-d2, start, v))

    ans = 0

    while pq:
        negval, u, v = heapq.heappop(pq)
        val = -negval

        if dist.get((u, v), -1) != val:
            continue

        if v == end:
            ans = max(ans, val)
            continue

        for w, d2 in adj[v]:
            if w == u:
                continue

            if u != start:
                ux, uy = coords[u]
                vx, vy = coords[v]
                wx, wy = coords[w]

                a1, a2 = ux - vx, uy - vy
                b1, b2 = wx - vx, wy - vy
                ab = a1 * b1 + a2 * b2
                a2n = a1 * a1 + a2 * a2
                b2n = b1 * b1 + b2 * b2

                # angle <= 120 deg
                if 4 * ab * ab < a2n * b2n:
                    continue

            nv = min(val, d2)
            state = (v, w)
            if nv > dist.get(state, -1):
                dist[state] = nv
                heapq.heappush(pq, (-nv, v, w))

    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションでは、ジオメトリを検索から分離します。 ボトルネックの比較には実際の長さではなく順序付けのみが必要なため、各エッジには浮動小数点精度の問題を回避するために二乗距離が保存されます。 

プライオリティ キューにより、常に最も有望なルートが最初に拡張されます。 状態キーには現在のノードと前のノードの両方が含まれており、方向をエンコードするには十分です。 角度チェックは、実際の到来方向がある場合にのみ適用されます。 開始状態はそれをバイパスします。 

微妙な点は、二乗距離を実際の距離に変換しないことです。 これが機能するのは、すべての比較に単調演算のみが含まれ、パスに沿った最小値によって二乗のもとでの順序が維持されるためです。

 ## 特殊なケース

 主なエッジ ケースは、最適なパスが一方向からノードに入り、まったく異なる方向に退出する必要があるのに、別の進入方向により同じ退出が無効になる場合です。 アルゴリズムは、異なる入力エッジをノードでマージするのではなく、別々の状態を保持するため、これを処理します。 

もう 1 つのエッジ ケースは、開始ノードです。この場合、着信方向は存在しません。 この実装では、最初から角度チェックなしですべての外向きエッジを明示的に許可し、最初の動きが拘束されないようにします。 

最後の微妙なケースは、複数のパスが異なるボトルネックを持つ同じ有向エッジに到達する場合です。 プライオリティ キューは、各状態の最も強いバージョンのみが展開されることを保証し、弱いパスによる誤った上書きを防ぎます。
