 ## 解決策
 ## 問題の理解

 整数のリストが与えられ、リスト内の最小値と最大値に応じたルールに従って 1 つの要素を選択する必要があります。 

配列全体をソートして従来の中央値を取得する代わりに、最初に最小要素と最大要素の算術平均である参照値を計算します。 次に、この基準値に最も近い配列内の要素を探します。 距離は通常の絶対差の感覚で測定されます。 複数の要素が同等に近い場合は、その中で最小の値が選択されます。 

したがって、タスクはソートされた配列内の位置の順序付けに関するものではなく、極値の中点への近さに関するものです。 

入力サイズは最大 100,000 要素で、値の大きさはおよそ 2 · 10^9 です。 これにより、候補ごとに高価なものを再計算したり、すべてのペアを試したりするソリューションは即座に除外されます。 すべての要素を他のすべての要素と比較したり、入れ子になったループ内で並べ替えたりするなど、二次的な処理は遅すぎます。 単純な前処理後のリニア スキャンが唯一の実行可能な方向です。 

ここではいくつかの特殊なケースが重要です。 

すべての要素が等しい場合、最小値と最大値は一致するため、基準値はまさにその数値になります。 すべての要素は等しく近いため、答えは同じ値になるはずです。 浮動小数点の中点計算や結合を誤って処理するソリューションは、依然としてこのケースを破る可能性があります。 

[1, 3] や [1, 2, 3] など、中点を中心に対称的に配置された値が配列に含まれている場合、複数の要素が距離で結びつく可能性があります。 タイブレーク ルールにより、これらの候補のうち最小のものを選択することが強制されるため、最も近い値を維持するだけでなく、明示的に同点を追跡する必要があります。 

最後に、値が大きくなる可能性があるため、mid = (min + max) / 2 を浮動小数点数として計算すると、不用意に実行すると精度の問題が発生する可能性があります。 ただし、距離を代数的に比較する場合、浮動小数点はまったく必要ありません。 

## アプローチ

 直接解釈すると、配列の最小値と最大値を計算し、すべての要素をチェックして中点にどれだけ近いかを確認することを示唆しています。 ブルートフォースのアイデアは単純です。最小値と最大値を計算し、中間点を計算し、すべての要素を反復処理して、その中間点までの絶対差が最小の要素を追跡します。 

これにより、すでに O(n) の解が得られるため、並べ替えやネストされた比較は必要ありません。 唯一の微妙な点は、浮動小数点エラーを発生させずに距離を比較する方法と、一貫して同点を処理する方法です。 

重要な観察は、最小値と最大値が判明すると中点が固定されるため、問題は単一パスの選択問題に帰着します。つまり、|a[i] - (min + max)/2| を最小化する要素を選択します。 定数しきい値との比較は除算なしで書き換えることができるため、2 * a[i] を (min + max) と比較することで浮動小数点数を完全に回避できます。 これにより、すべてが整数に保たれ、正確な順序が維持されます。 

グローバル極値と配列の 1 回のパスのみが必要なため、ブルートフォース メンタル モデルは機能します。 単純な浮動小数点中間点計算で実装されている場合、またはタイブレークが明示的に処理されていない場合にのみ失敗します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (最小/最大 + スキャン) | O(n) | お(1) | 承認済み |
 | 最適 (整数安全な比較と同じ) | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

1. すべての数値を読み取り、配列内の最小値と最大値の両方を計算します。 これにより、ターゲットの中間点を定義する基準間隔のエンドポイントが確立されます。 
2. これらの終点の合計を計算します。これは、中間点の 2 倍に相当します。 実際の中間値ではなく比較のみが必要なため、除算を避けます。 
3. 最適な候補を保存する変数と、これまでに確認された最適な距離を保存する変数を初期化します。 最適な距離は無限から始まります。 
4. 配列内のすべての要素を反復処理します。 各要素について、|2 * a[i] - (min + max)| を比較して、スケーリングされた整数形式で中点からの絶対距離を計算します。 これは、真の中点までの距離と同じ順序を測定します。 
5. この距離がこれまでの最良の距離よりも小さい場合は、最良の距離と最良の候補値の両方を更新します。 
6. 距離が最適距離と等しい場合、現在の値が小さい場合にのみ候補を更新します。 これにより、タイブレーク ルールが適用されます。 
7. すべての要素を処理した後、保存された候補を出力します。 

### なぜ効果があるのか

 グローバル最小値と最大値から導出される中点は、配列構造に依存しない固定定数です。 すべての要素は純粋にこの定数までの距離によって評価されるため、問題は決定論的な関数ではなくグローバル argmin を選択することに帰着します。 2 倍の値への変換では、2 による乗算は単調で比較に影響を与えないため、順序が維持されます。 タイブレーク ルールはスキャン中に明示的に適用され、等距離の候補の中から確実に選択されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    mn = min(a)
    mx = max(a)
    target_sum = mn + mx

    best_val = None
    best_dist = None

    for x in a:
        dist = abs(2 * x - target_sum)
        if best_dist is None or dist < best_dist or (dist == best_dist and x < best_val):
            best_dist = dist
            best_val = x

    print(best_val)

if __name__ == "__main__":
    solve()
```解決策は、基準の中点を暗黙的に定義するグローバル極値を抽出することから始まります。 中点を直接計算する代わりに、倍加された式を使用して、すべての算術演算を整数かつ正確に保ちます。 ループは実行中の最良の候補を維持し、厳密に優れた距離が見つかった場合、またはより小さい値によって同点が破られた場合にのみ更新します。 

よくある実装上の間違いはコンピューティングです。`(mn + mx) / 2`浮動小数点演算を使用してから、float を使用して距離を比較します。 値が大きい場合、これにより丸め誤差が発生する可能性があります。 もう 1 つの微妙な間違いは、タイブレーク ルールを厳密に適用できていないことです。これにより、複数の値が等距離にある場合に誤った出力が発生します。

 ## 特殊なケース

 すべての値が同一の場合、最小値は最大値と等しく、ターゲットの中点は同じ値に縮小されます。 アルゴリズムセット`target_sum = 2 * x`, したがって、すべての要素は距離ゼロを生成します。 タイブレーク ルールでは小さい値が優先され、すべての値が等しいため、最初に見つかった要素は有効のままで、最終的な答えはその繰り返された値になります。 

中点から等距離にある 2 つの要素がある場合、次のようになります。`[1, 3]`、どちらも中点 2 からの距離 2 を生成します。アルゴリズムは最初に 1 を比較し、次に 3 を比較します。1 を処理した後、best_val は 1 になります。3 を処理すると、距離は等しくなりますが、3 は 1 より小さくないため、無視されます。 出力は 1 のままで、必要なルールに一致します。
