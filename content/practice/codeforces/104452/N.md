 ## 解決策
 ## 問題の理解

 分単位で測定される固定のコンテスト期間と、解くのに必要な時間が既知の小さな問題のコレクションが与えられます。 チームは順番に作業します。問題を開始すると、次の問題に移る前にそれを終了し、問題を解決する順序は完全に私たちが制御します。 

選択した順序に関係なく、解決された各問題は 2 つのことに貢献します。 まず時間がかかるので、進めていくと累積時間が増えていきます。 第二に、問題が終了した時間に等しいペナルティが追加されます。 最終ペナルティは直接適用されません。ペナルティが丸 1 日 (1440 分) を超えると、コンテスト システムは 1440 の倍数を減算し、ペナルティを効果的にモジュール範囲にまとめます。 

課題は、コンテスト期間内に完了する問題の数を最大化するように、問題の一部を解決する順序を選択することです。また、そのようなすべての最適な選択肢の中で、ラップアラウンド ルールの適用後に生じるペナルティを最大化することです。 

制約は非常に小さく、最大でも 10 個の問題です。 このことから、たとえ 10 であっても、順列に対する指数関数的な探索が実現可能であることがすぐに分かります。 州の数はわずか数百万ですが、枝刈りや慎重な順序付けを行うことで Python では許容されます。 これにより、大規模な州に対する貪欲なヒューリスティックや DP の必要性も排除されます。 

選択したすべての完了時間がペナルティを 1440 を超えると、微妙なエッジ ケースが発生します。その場合、生の合計が大きくても、実効ペナルティは 0 になります。 これは、生のペナルティを増やすとゼロに戻るため、場合によっては実際には悪影響を与えることを意味します。 

## アプローチ

 単純なアプローチでは、タスクのすべてのサブセットのすべての順列を試行します。 サブセットごとに、すべての順序をテストし、完了時間をシミュレートし、時間 K 内に収まるタスクの数を数え、ペナルティを計算します。 これは正しいですが、コストがかかります。2^N 個のサブセットと N! 最適な順序で構造を観察できるため、順列は不要になります。 

重要な観察は、解決可能な問題の数が減少するような大規模なタスクの早い段階で時間を無駄にしたくないということです。 数を最大化するには、常に最小のタスクを最初に選択する必要があります。 解決可能なタスクの最大数が決まったら、選択したタスクの順列を考慮するだけで済みます。 

N ≤ 10 であるため、タスクをソートしてからプレフィックスのみを考慮することができます。最小の M タスクを取得することが、数を最大化するには常に最適です。 次に、各 M について、ペナルティの最適な順序を計算します。これにより、最大 10 個の要素の順列の試行が減り、それでも管理可能になります。 

したがって、問題は次のようになります。時間 K に適合する並べ替えられたタスクの最大のプレフィックスを見つけ、そのプレフィックスのすべての順列の中で、ラップされたペナルティを最大化します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 完全な総当たりサブセット + 順列 | O(N! · 2^N) | O(N) | 構造が遅すぎる |
 | プレフィックスでの並べ替え + 順列検索 | O(N! N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### 重要なアイデア

 私たちは問題を 2 つの層に分割します。解決されたタスクの数を最大化することと、その固定サイズでのペナルティの順序を最適化することです。 

### ステップ

 1. タスクを時間の昇順に並べ替えます。 

これにより、タスクの数を最大化したい場合は、常に小さいタスクを最初に優先することが保証されます。 
2. 最初の M 個のタスクの合計が K を超えないように、最大プレフィックス長 M を決定します。 

これにより、解決可能なタスクの最大数が得られます。 
3. このプレフィックスを候補セットとして修正します。 

最適なソリューションでは、これら M 個のタスクを正確に選択する必要があります。これは、いずれかをより大きなタスクに置き換えても、実現可能性が低下するだけであるためです。 
4. これら M 個のタスクのすべての順列を列挙します。 

M ≤ 10 であるため、これは計算上実現可能です。 
5. 各順列について、実行をシミュレートします。

時間を蓄積し、合計時間が K を超えた場合は、早めに停止します。 
6. 完了時間の合計としてペナルティを計算します。 
7. ラップアラウンドを適用します: ペナルティ %= 1440。 
8. すべての順列にわたる最大ペナルティを追跡します。 

### なぜ効果があるのか

 正しさは、実現可能性と最適化を分離することから生まれます。 接頭辞引数は、M を増加させる可能性のある解を見逃さないことを保証します。固定セット内では、順列列挙により、制約の下で可能な最大のペナルティを見つけることが保証されます。 モジュラーラップは最終的な値にのみ影響し、実現可能性や順序構造には影響しないため、検索の正確性には影響しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from itertools import permutations

def solve():
    K, N = map(int, input().split())
    t = list(map(int, input().split()))

    t.sort()

    # find max number of tasks we can take
    total = 0
    M = 0
    for x in t:
        if total + x <= K:
            total += x
            M += 1
        else:
            break

    if M == 0:
        print(0, 0)
        return

    tasks = t[:M]

    best_cnt = 0
    best_penalty = 0

    for perm in permutations(tasks):
        cur = 0
        penalty = 0
        cnt = 0

        for x in perm:
            if cur + x > K:
                break
            cur += x
            penalty += cur
            cnt += 1

        penalty %= 1440

        if cnt > best_cnt or (cnt == best_cnt and penalty > best_penalty):
            best_cnt = cnt
            best_penalty = penalty

    print(best_cnt, best_penalty)

if __name__ == "__main__":
    solve()
```ソート後、ソリューションは実現可能な最大のプレフィックスを構築します。 次に、そのプレフィックスの有効な順序をすべて調査し、累積時間をシミュレートしてペナルティを計算します。 モジュロ演算は最後にのみ適用され、候補間の正しい比較が保証されます。 

微妙な点は、順列シミュレーション内で早期に停止することです。時間が K を超えると、残りのタスクは無関係になり、不必要な計算が削減されます。

 ## 特殊なケース

 非常に小さいタスクを除き、すべてのタスクが K を超える入力の場合、アルゴリズムは M を 0 または 1 に正しく制限し、置換エラーが発生しないようにします。 たとえば、K = 5 でタスクが [10, 20, 30] の場合、並べ替えでは有効なプレフィックスが得られないため、出力は直接 (0, 0) となり、予想される動作と一致します。
