 ## 解決策
 ## 問題の理解

 私たちには、アイテムの単一の連続的な流れを操作するデバイスの指向性ネットワークが与えられています。 このシステムはルート構造です。単一の入力フローがデバイス 1 に入り、フローは変換され、中間コンポーネントのコレクションを介してルーティングされ、最終的に -1 と -2 というラベルが付いた 2 つのシンクから出ます。 

各デバイスはスプリッターまたはマージャーのいずれかです。 スプリッターは 1 つの受信フローを受け取り、それを最大 3 つの送信エッジに均等に分配します。 1 つまたは 2 つの出力のみが接続されている場合、フローはアクティブな出力間で均等に分割されるため、その割合は実際に使用される発信接続の数のみに依存します。 マージでは、3 つの潜在的な入力ストリームを取得し、それらを 1 つの発信エッジに転送し、総量を変えることなく、到着するものを 1 つのフローに結合します。 

この構造は有効であることが保証されています。デッドデバイスはなく、ソースからすべてに到達可能であり、最終的には両方の出力に到達します。 タスクは、最終的に出力 -1 と出力 -2 に達する合計フローの正確な比率を計算することです。 

ネットワークには分割が含まれていますが、重要な観察は、すべての変換が流量に関して線形であるということです。 これは、個々のアイテムをシミュレートする必要がなく、各ノードに到達するフローの量を追跡するだけであることを意味します。 

k ≤ 32 という制約は非常に小さいため、サブセットに対する指数推論や有理算術でも受け入れられることがわかります。 ただし、DAG のような流れシステムである構造は、線形時間での決定論的な伝播ソリューションも示唆しています。 

スプリッターに未使用の出力 (0) がある場合、微妙なエッジ ケースが発生します。 単純なアプローチでは、すべてのスプリッターが常に 3 で除算されると誤って仮定する可能性がありますが、正しい除数はアクティブな発信接続の数です。 もう 1 つの落とし穴は、マージを純粋なフロー集約ではなく算術演算として扱うことです。これにより、受信フローを合計する代わりに誤って正規化または平均化してしまいます。 

## アプローチ

 ブルート フォース解釈では、フローが個別のパケットとしてシミュレートされます。 スプリッターに入る各パケットは、スケーリングされた重みを使用して最大 3 つのコピーにクローン化され、各マージではすべての受信パケットがマージされます。 各スプリッターにより追跡されるフロー ブランチの数が増加するため、これはすぐに指数関数的になります。 多数のスプリッターの最悪のケースでは、パスの数が 3^k のように増加しますが、これは k = 32 の場合でも実行不可能です。 

重要な観察は、システムが線形であるということです。すべてのエッジには、そこに到達する初期の流れの割合を表す有理値が含まれています。 パスを追跡する代わりに、各デバイスの寄与を単一の有理数として計算します。 各スプリッターは入力値をアクティブな発信エッジ全体に均等に分配し、各マージは入力からの寄与を単純に合計します。 

これにより、問題は重みの有向非巡回伝播の評価に変換されます。 すべてのデバイスは接続構造内の以前のデバイスにのみ依存し、グラフの形式が保証されているため、順伝播または逆依存関係の解決を使用して値を処理できます。 k が小さいため、共通の分母を持つ整数を使用するか、有理算術を使用して正確な分数を安全に計算できます。 

最も安定したアプローチは、各デバイスに到達する総フローの割合をペア (分子、分母) として保存することです。 これらの分数は、分母にアクティブな出力の数を乗算することによってスプリッターを介して伝播され、分数を共通の分母で合計することによってマージを通じて伝播されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 ## アルゴリズムのチュートリアル

すべてのデバイスは、そこに到達する初期ユニット フローの一部を保持しているものとして扱われます。 デバイス 1 は値 1/1 で始まります。 

1. 各デバイスの値ペア (分子、分母) を初期化します。 デバイス 1 を 1/1 に設定し、その他すべてを 0/1 に設定します。 
2. 依存関係を考慮した任意の順序でデバイスをスキャンします。 k ≤ 32 であり、構造が非環状であるため、緩和を繰り返すだけで十分です。 
3. スプリッタを処理するとき、その出力のうちのいくつが非ゼロのターゲットであるかを数えます。 これをdとします。 スプリッタでの電流フローは均等に分割されるため、各出力エッジは current_flow / d を受け取ります。 
4. このコントリビューションを各ターゲット デバイスに追加します。 ターゲットにすでに値がある場合は、交差乗算によって分数を合計します。 
5. マージを処理するときは、蓄積された入力フローを変更せずに出力に渡すだけです。 
6. 値が変化しなくなるまで伝播を続けるか、最長の依存関係チェーンが k によって制限されるため k 回繰り返します。 
7. 最後に、出力 -1 と -2 にはそれぞれ、元のフローの一部が蓄積されます。 それらを公分母に変換し、分子を整数比形式で出力します。 

重要な考え方は、パスを明示的に追跡しないということです。 すべてのデバイスは、そのデバイスに至る可能性のあるすべての部分パスの圧縮表現を保存します。 

### なぜ効果があるのか

 すべてのデバイス変換は、フロー量に対して線形です。 スプリッターは 1/d による乗算とエッジ間の複製を実行し、マージャーは加算を実行します。 加算とスカラー乗算は線形性を維持するため、ネットワーク全体が DAG 上の線形変換のように動作します。 したがって、最終値を計算することは、一次方程式系を評価することと同等であり、サイクルが存在せず、すべての寄与が前方にのみ流れるため、反復伝播は正確に収束します。

def solve():

    typ = [None] * (k + 1)

        typ[i] = parts[0]

        else:
            x = int(parts[1])
            out[i] = x
            nxt[i].append(x)

    val[1] = Fraction(1, 1)

    # propagate multiple rounds (safe since k <= 32)
    for _ in range(k):
        new_val = [Fraction(0, 1) for _ in range(k + 1)]
        new_val[1] = val[1]

        for i in range(1, k + 1):
            if typ[i] == 'S':
                targets = [x for x in out[i] if x != 0]
                if not targets:
                    continue
                share = val[i] / len(targets)
                for x in targets:
                    if x > 0:
                        new_val[x] += share
            else:
                x = out[i]
                if x > 0:
                    new_val[x] += val[i]

        val = new_val

    # outputs
    a = val[-1] if False else None  # placeholder safe
    # actually outputs are -1 and -2, not indexed in array

    f1 = Fraction(0, 1)
    f2 = Fraction(0, 1)

    # recompute by final propagation (since -1, -2 are sinks)
    # we track them during propagation instead
    val = [Fraction(0, 1) for _ in range(k + 1)]
    val[1] = Fraction(1, 1)

    out1 = Fraction(0, 1)
    out2 = Fraction(0, 1)

    for _ in range(k):
        new_val = [Fraction(0, 1) for _ in range(k + 1)]
        new_val[1] = val[1]

        o1 = Fraction(0, 1)
        o2 = Fraction(0, 1)

        for i in range(1, k + 1):

                targets = [x for x in out[i] if x != 0]
                if not targets:
                    continue
                share = val[i] / len(targets)
                for x in targets:
                    if x == -1:
                        o1 += share
                    elif x == -2:
                        o2 += share
                    elif x > 0:
                        new_val[x] += share

                if x == -1:
                    o1 += val[i]
                elif x == -2:
                    o2 += val[i]
                else:
                    new_val[x] += val[i]

        val = new_val
        out1 += o1
        out2 += o2

    # reduce ratio
    num1 = out1.numerator
    den1 = out1.denominator
    num2 = out2.numerator
    den2 = out2.denominator

    # bring to common denominator
    lcm_den = den1 * den2
    a = num1 * den2
    b = num2 * den1

    # reduce gcd
    import math
    g = math.gcd(a, b)
    a //= g
    b //= g

    print(a, b)

```この実装では、最大 k ラウンドにわたる繰り返し緩和としてシステムをモデル化します。 各ラウンドは、スプリッターとマージのルールに従ってフローを進めます。 2 つのシンク出力は小数として別々に累積されます。 最後のステップでは、分母をクリアし、gcd で削減することにより、両方の結果を単一の整数比に変換します。 

微妙な部分は、非アクティブ出力がゼロのスプリッターを処理することです。 コードは明示的に 0 エントリを除外するため、除算は常に正しいアクティブ度によって行われます。 もう 1 つのデリケートな点は、シンクが複数の伝播層からフローを受け取る可能性があるため、繰り返しにわたって出力を上書きするのではなく蓄積することです。

 ## 特殊なケース

 主なエッジケースは、スプリッターにアクティブな出力が 1 つしかない場合です。 この場合、分割は発生しないはずです。 たとえば、ノードが`S 2 0 0`、すべての受信フローは完全にデバイス 2 に渡される必要があります。常に 3 で割る単純な実装では、合計フローが誤って 3 分の 1 に縮小されてしまいます。 

もう 1 つの微妙なケースは、マージが以前に分割された複数のパスからフローを受け取る深いチェーンです。 すべての寄与は加算的なものであるため、アルゴリズムは上書きではなく蓄積する必要があります。 たとえば、2 つの異なる分割パスが同じ合併に到達する場合、それらの寄与を正確に合計する必要があります。そうしないと、1 つの分岐が失われ、最終的な比率が不正確になります。 

最後に、シンク -1 と -2 はターミナル アキュムレータとして扱う必要があります。 それらに到達するフローは決して再配布しないでください。 実装では、これらの値が最終的なままであることを保証するために、伝播中にこれらの値を明示的に蓄積します。
