 ## 解決策
 ## 問題の理解

 長さが 2 の累乗である文字列が与えられているとします。$2^n$であり、非常に構造化された変換を繰り返し適用した結果であることが知られています。 変換はラウンド単位で機能します。 最初のラウンドでは、文字列全体が逆になります。 次のラウンドでは、文字列が 2 つの等しい半分に分割され、それぞれの半分が独立して反転されます。 次のラウンドでは、各半分が再び分割されて 4 つの四半期が与えられ、各四半期は独立して逆転されます。 これは、サイズ 1 のブロックを反転するまで続きます。 

入力はこれらすべての操作の後の最終結果であり、タスクは、変換が適用される前の元の文字列を再構築することです。 

重要な問題は、このプロセスが単純な全体的な反転や単一レベルの並べ替えではないことです。 各ラウンドは異なる粒度で反転を適用し、後の操作は以前の操作によって作成された内部構造に影響を与えます。 

制約$n \le 13$最大長が次であることを意味します$2^{13} = 8192$。 これは十分小さいので、$O(N \log N)$あるいは慎重に構造化された$O(N)$再構成は簡単に高速ですが、単純な文字列のスライスや完全な反転をあらゆるレベルで繰り返しシミュレートするアプローチには大きすぎます。 

プロセスを文字通り逆方向にシミュレートしようとする単純なアプローチでは、ネストされた一連の反転を反転する必要があります。 各レベルで部分文字列を再計算することによって直接実行すると、危険が生じます。$O(N^2)$繰り返しのコピーによる動作。 と$N = 8192$、それはまだ境界線にありますが、不必要で壊れやすいです。 

再帰構造を認識せずに変換を最後から「元に戻そう」とすると、微妙な落とし穴が現れます。 各ステップは、セグメント境界の正しい位置合わせに依存します。 貪欲な逆転やグローバルな操作は、この構造を破壊します。 

## アプローチ

 順方向プロセスでは、文字列を繰り返し小さく均等なセグメントに分割し、各セグメントを反転します。 インデックスがどのように移動するかを考えると、各レベルでセグメントが反転されるかどうかに応じて、すべての文字が繰り返し異なる位置に送られます。 

ブルートフォース反転の試行では、配列上で順方向プロセスをシミュレートし、変換を追跡し、レベルごとに反転を元に戻すことで各ステップを反転しようとします。 ただし、これには正確なセグメンテーション ツリーを再構築し、部分文字列の反転またはコピーを繰り返し適用する必要があります。 部分文字列の各反転のサイズは線形であり、すべてのレベルにわたって、同じ文字に対して何度も作業を繰り返すことになります。 総コストは次のように比例します。$N \log N$注意深く実行すれば、単純な実装では劣化してしまいます。$O(N^2)$。 

重要な観察は、プロセスがバイナリ再帰構造を定義しているということです。 各レベルで、文字列は 2 つの半分に分割され、各半分は次のステージで独立して変換されます。 これは、変換が文字列インデックス上にバイナリ ツリーを構築することと同等であることを意味します。各ノードは、特定の深さで反転されたセグメントに対応します。 

反転をシミュレートする代わりに、対称性を利用して元の文字列を再帰的に再構築できます。 各ステップで、最終的な文字列は、そのセグメントに影響を与えた反転の数に応じて、反対方向に独立して変換された 2 つの半分に対応します。 セグメントが現在反転されているかどうかを正しく追跡すると、実際の文字列反転操作を実行することなく、文字列を分割して再帰的に文字を割り当てることができます。 

これにより、問題は、各レベルがセグメントを 1 回だけ分割して割り当てる分割統治型の再構築に帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべての逆転のブルート フォース シミュレーション | O(N log N) から O(N^2) | O(N) | 危険/遅すぎる |
 | セグメント追跡による再帰的再構成 | O(N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 分割の各レベルで向きを切り替える再帰的プロセスの結果として、最終的な文字列を再解釈します。 

1. 暗号化された文字列の部分文字列に対応する元の文字列のセグメントを再構築する再帰関数を定義します。 この関数は、現在のセグメント境界と、セグメントが変換履歴によって論理的に反転されているかどうかを示すブール値フラグを受け取ります。 
2. サイズ 1 のセグメントでは、文字を出力バッファに直接配置します。 これは正しいです。このレベルの下にはそれ以上の構造は存在しないため、あいまいさは残りません。 
3. サイズが 1 より大きいセグメントの場合は、同じサイズの 2 つの半分に分割します。 変換履歴は、各半分がより深いレベルで独立した反転を経験していることを意味しますが、それらの相対的な順序は現在の反転パリティに依存します。 
4. 現在のセグメントが通常の方向にある場合、元の構造の左半分を現在の間隔の前半にマッピングし、右半分を後半にマッピングします。 逆の場合は、このマッピングを交換します。 このスワップは、より高いレベルのフルセグメントの反転の効果を捉えています。 
5. 同じロジックを両方の半分に再帰的に適用し、配向状態を伝播します。 各分割により問題のサイズが半分に減り、対数再帰の深さが確保されます。 
6. 最終出力は、すべてのリーフレベルの割り当てをインデックス順に結合することによって埋められます。 

これが機能する理由: 各反転操作は、特定の粒度で順序を反転するだけです。これは、バイナリ分解ツリーのセグメントの方向の切り替えに正確に対応します。 プロセスのすべてのレベルが独立したセグメントに影響を与えるため、向きを再帰ノードごとの単一のブール状態として扱うことができます。 これにより、各文字が正しい元の位置に 1 回だけ配置されることが保証され、再帰は変換の正確な階層を反映するため、後の操作によって以前の割り当てが無効になることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)
    res = [''] * n

    def build(l, r, seg, rev):
        if l == r:
            res[l] = seg[0]
            return

        mid = (l + r) // 2
        half = len(seg) // 2

        left = seg[:half]
        right = seg[half:]

        if not rev:
            build(l, mid, left, rev ^ False)
            build(mid + 1, r, right, rev ^ False)
        else:
            build(l, mid, right, rev ^ False)
            build(mid + 1, r, left, rev ^ False)

    build(0, n - 1, s, False)
    print("".join(res))

if __name__ == "__main__":
    solve()
```この実装では、暗号化された文字列を再帰的に分割し、そのセグメントを結果の配列に割り当てることによって、元の文字列を構築します。 重要な点は、セグメントが反転方向にあるときのスワップであり、層状の反転構造が説明されています。 

機能`build`は常に、現在の作業文字列スライスの連続セグメントを消費し、それを応答の連続セグメントにマップします。 再帰により、各文字が正確に 1 回配置されることが保証され、結果の配列では文字列の繰り返しの連結が回避されます。 

微妙な点の 1 つは、部分文字列を物理的に反転することは決してないということです。 の`rev`flag は純粋に論理的なものであり、再帰中に正しい順序決定が保証されます。

 ## 特殊なケース

 単一文字の文字列は分割が発生しないため、最も単純なケースです。 再帰はすぐに基本ケースに到達し、文字を出力に直接書き込むため、セグメントの順序が間違ってしまうリスクはありません。 

2 文字の文字列の場合、再帰は 1 回分割されます。 入力が逆の場合、スワップ ロジックにより左半分と右半分が正しく配置され、元の順序が復元されます。 

完全に反転した入力の場合`"dcba"`、トップレベルの反転は半分を交換し、より深い構造により各文字が正しい位置に戻ることが保証されます。 再帰的代入により、反転が単一のグローバル反転としてではなく、各レベルで構造化されたスワップのシーケンスとして扱われることが保証され、正しく再構築されます。`"abcd"`。
