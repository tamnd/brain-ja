 ## 解決策
 ## 問題の理解

 バイナリ文字列が与えられます`s`長さの`n`そして別のバイナリ文字列`r`長さの`n-1`。 この問題は、繰り返し短縮するゲームについて説明しています。`s`隣接する異なるビットのペアを次の文字に置き換えることにより、`r`。 各ターンでインデックスを選択する必要があります`k`そのような`s[k] != s[k+1]`そして交換してください`s[k]s[k+1]`と`r[i]`。 そのようなペアが存在しない場合は、すぐに負けます。 目標は、すべての操作を許可する一連の操作があるかどうかを判断することです。`n-1`交換が実行されます。 

重要な洞察は、次の場合にはゲームを開始できないということです。`s`隣接する異なるビットは含まれません。 もし`s`最初はすべてです`0`またはすべて`1`つまり、最初の動きは不可能です。 もし`s`少なくとも 1 つの異なる隣接ペアがあり、各置換が減少するため、ゲームは最後の文字まで常に継続できます。`s`の長さを 1 つ増やし、どのペアを置き換えるかの選択は将来の手を制限しません。`s`最後には単一の文字に折りたたまれます。 

この制約により、すべてのテスト ケースで合計最大 100,000 文字が許可されるため、各文字列を線形時間で処理するアルゴリズムが必要になります。 考えられるすべての置換シーケンスをシミュレートすることはできず、指数関数的になります。 エッジ ケースには、最初は均一な文字列、交互の文字を含む文字列、長さ 2 の最小長の文字列が含まれます。`s = "11"`そして`r = "0"`戻らなければなりません`NO`移動が不可能だからです。 

## アプローチ

 ブルートフォース手法では、考えられるあらゆる一連の動きをシミュレートします。 操作ごとに、有効なすべてのものを探します。`k`どこ`s[k] != s[k+1]`、置換を試し、再帰的に続行します。 これはゲームを正しくモデル化していますが、シーケンスの数が指数関数的に増加するため、実行不可能です。`n`。 最悪の場合、最大で`2^(n-1)`シーケンスを考慮する必要がありますが、これは完全に非現実的です。`n`100,000まで。 

最適なアプローチは単純な構造観察に基づいています。すぐに負ける唯一の方法は、文字列に隣接する異なるビットが含まれていない場合です。 少なくとも 1 つの異なるペアが存在すると、文字列が 1 文字にならない限り、どの操作でも長さが 1 つ減り、少なくとも 1 つの異なるペアが残ります。 したがって、次の場合に限り、ゲームに勝つことができます。`s`少なくとも 1 つ含まれています`01`または`10`部分文字列。 この条件のチェックは文字列に対する 1 回のパスで実行できるため、ソリューションは線形になります。`n`。

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る`t`。 各テストケースを個別に処理します。 
2. 各テスト ケースについて、次の内容を読んでください。`n`、`s`、 そして`r`。 必要ありません`r`特定の置換値は手が存在するかどうかに影響を与えないため、決定に役立ちます。 
3. 反復処理`s`インデックス 0 から`n-2`。 連続する文字が異なっていないか確認してください。 もし`s[i] != s[i+1]`、すぐにこのテスト ケースを勝利可能としてマークします。 
4. 異なるペアが見つからずに反復が完了した場合は、テスト ケースを勝利不可能としてマークします。 
5. 印刷`YES`勝てる案件については、`NO`勝てない事件の場合。 

機能する理由: 少なくとも 1 つの異なるペアが存在すると、確実に移動できるようになります。 移動するたびに長さが短くなります`s`1 つずつ追加されますが、最後の文字に到達するまで選択できる有効なペアは常に残ります。 不変条件は、異なるペアが存在する場合でもゲームを続行できるということです。 すべて同一の文字を含む文字列のみがこのチェックに合格しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    s = input().strip()
    r = input().strip()
    can_win = any(s[i] != s[i+1] for i in range(n-1))
    print("YES" if can_win else "NO")
```このソリューションは、次を使用して入力を効率的に読み取ります。`sys.stdin.readline`そして、ジェネレーター式を使用して条件を直接チェックします。 ストリッピング`s`そして`r`末尾の改行を削除します。 使用する`any()`異なるペアが見つかるとすぐにチェックを停止します。 0 から 0 まで反復するため、off-by-one エラーはありません。`n-2`比較するとき`s[i]`と`s[i+1]`。 

## 実用的な例

 入力のトレース`s = "11"`、`r = "0"`:

 | 私 | s[i] | s[i+1] | s[i] != s[i+1] |
 | --- | --- | --- | --- |
 | 0 | 1 | 1 | 偽 |

 異なるペアが見つからないため、出力は次のようになります。`NO`。 

入力のトレース`s = "01"`、`r = "1"`:

 | 私 | s[i] | s[i+1] | s[i] != s[i+1] |
 | --- | --- | --- | --- |
 | 0 | 0 | 1 | 本当 |

 異なるペアが存在します。出力は次のとおりです。`YES`。 

これらのトレースは、アルゴリズムが勝てる条件を正しく検出していることを確認します。
