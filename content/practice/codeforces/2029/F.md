 ## 解決策
 ## 問題の理解

 次のサイクルグラフが与えられます。$n$ラベル付きの頂点$0$に$n-1$。 サイクルの各エッジには、赤または青の色が付いています。 任意の 2 つの頂点について$i$そして$j$からのルートが存在するかどうかを知りたいのです。$i$に$j$エッジの色のシーケンスが回文を形成するように、サイクルに沿って配置します。 ルートは頂点を再訪することができ、各ステップで時計回りまたは反時計回りに進むことができます。 

入力により複数のテスト ケースが提供されます。 各テスト ケースが提供するのは、$n$と長さの文字列$n$サイクル内のエッジの色を表します。 このタスクは、サイクル内のすべての頂点のペアが回文ルートを許可する場合は「YES」を出力し、そうでない場合は「NO」を出力します。 

とすれば$n$まで可能です$10^6$と合計$n$すべてのテストケースで次を超えない$10^6$、頂点のすべてのペアを直接検査するソリューション (これは次のようになります)$O(n^2)$）は不可能です。 解は線形でなければなりません$n$おそらくサイクルの構造と回文の性質を利用することによって、テスト ケースごとに実行されます。 

微妙なエッジ ケースは、サイクルに交互の色がある場合です。たとえば、「RBRBRB」と偶数色が交互に表示される場合です。$n$。 このような場合、一部の頂点ペアについて回文ルートが存在しない可能性があります。 もう 1 つのエッジ ケースは、すべてのエッジが同じ色を持つ場合です。その場合、ルートが頂点を再訪する場合でも、シーケンスは自明に回文になります。 不注意なアプローチでは、すべてのペアを単純にチェックしようとしたり、頂点を再訪するルートの必要性を無視したりする可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、頂点のすべてのペアをチェックしようとします。$(i,j)$回文ルートを構築してみます。 各ペアについて、時計回りまたは反時計回りの動作をシミュレートし、エッジの色を一致させようと試みることができます。 このアプローチは原理的には正しいですが、確認が必要です$O(n^2)$ペアを作成し、パスのシミュレーションには最大で時間がかかる可能性があります$O(n)$各ペアのステップ。 これは次のことにつながります$O(n^3)$最悪の場合、遅すぎる場合もあります。 

重要な点は、任意の 2 つの頂点間に回文ルートが存在するには、そのサイクルに 2 つの連続するエッジが同じ色を持つ場所が少なくとも 1 つ含まれている必要があるということです。 そのような位置が存在する場合、その「ミラー ポイント」を使用して回文ルートを構築できます。$i$ミラー ポイントまで一方向に進み、ミラー ポイントから$j$逆に、エッジの色を反映します。 サイクルに同じ色の連続したエッジがない場合、エッジは厳密に交互になり、偶数長のサイクルの場合、一部のペアは回文ルートを形成できません。 言い換えれば、問題は、同じ色の連続するエッジのペアが少なくとも 1 組存在するかどうかをチェックすることになります。

 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、次の内容を読んでください。$n$とエッジの色の文字列$c$。 
2. 次のことを確認します。$n=3$。 もし$n=3$、3 つの頂点のどのサイクルでも回文ルートが自明に許可されるため、「YES」を出力して続行します。 これにより、最小限のサイクル エッジのケースが処理されます。 
3. 頂点 0 から頂点 0 までのサイクルを繰り返します。$n-1$、各エッジを比較します$c_i$次のエッジで$c_{(i+1)\bmod n}$。 
4. 連続するエッジの少なくとも 1 つのペアが同じ色である場合、そのペアは回文ルートのミラー ポイントを提供するため、このテスト ケースに対して「YES」と出力します。 
5. 同じ色の連続するエッジが見つからずに反復が完了した場合は、「NO」と出力します。 

機能する理由: ミラー ポイントにより、回文のプロパティに一致するようにあらゆるパスを両方向に拡張できます。 連続するエッジが同じでない場合、サイクルは完全に交互になります。 交互サイクルでは、特にサイクル長が偶数の場合、エッジの色が対称に反映できないため、一部の頂点ペアは回文ルートを持つことができません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        c = input().strip()
        found = False
        for i in range(n):
            if c[i] == c[(i+1)%n]:
                found = True
                break
        print("YES" if found else "NO")

solve()
```このソリューションは、次を使用して入力を効率的に読み取ります。`sys.stdin.readline`for large test cases. 各テスト ケースでは、サイクルを 1 回繰り返し、モジュラー演算を使用してサイクルをラップして連続エッジをチェックします。 変数`found`ミラーポイントの存在をフラグします。 それが存在する場合、回文特性を実現できます。 それ以外の場合、出力は「NO」になります。 

微妙なポイントは、`(i+1) % n`最後のエッジから最初のエッジまでのラップアラウンドを処理します。これは、サイクルの連続性を正しくチェックするために不可欠です。

## 特殊なケース

 最小限のサイクル$n=3$3 つのエッジでは常に回文ルートが許可されるため、これは自動的に処理されます。 均等な長さの交互サイクルは、連続する等しいエッジの存在が重要である理由を示しています。 「RBRBRB」のような長さ 6 のサイクルには、連続する等しいエッジがないため、反射のためのミラー ポイントがなく、「NO」が生成されます。 アルゴリズムは、エッジをモジュロで反復処理することにより、これを正しく識別します。$n$そして平等性をチェックします。 すべてのエッジが同じであるサイクルはすぐに「YES」を返します。これは均一な色の場合をカバーします。
