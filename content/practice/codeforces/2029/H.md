 ## 解決策
 ## 問題の理解

 各エッジが特定の日に出現する確率を持つ小さな無向グラフが与えられます。 最初は、頂点 1 だけがメッセージを知っています。 毎日、頂点が前日にメッセージをすでに受信していた場合、またはその日に隣接する頂点の少なくとも 1 つがメッセージを受信して​​接続エッジが表示されていた場合、頂点はメッセージを受信します。 タスクは、すべての頂点がメッセージを認識するまでの予想日数を計算することです。 

グラフには最大 21 個の頂点があるため、頂点のサブセットの総数は最大で$2^{21} \approx 2 \times 10^6$。 これは、すべてのサブセットに対するビットマスクベースの動的プログラミング ソリューションが実現可能であることを示すため、非常に重要です。 各エッジには、分数として与えられる関連する確率があります。$\frac{p}{q}$、計算はモジュロで実行する必要があります$998\,244\,353$。 

エッジ ケースには、頂点が 1 つだけのグラフ (メッセージは既知であるため、答えは 0)、エッジが 1 つだけあるグラフ、またはいくつかの頂点が非常に低い確率でエッジで接続されているシナリオが含まれます。 予想される日数が非常に長くなる可能性があり、異なるランダム エッジ構成の数が指数関数的であるため、日ごとの伝播の単純なシミュレーションは実現できません。 

## アプローチ

 ブルートフォース手法では、エッジの出現の可能性のあるすべてのシーケンスを列挙し、それぞれのケースでメッセージが拡散するまでの日数をカウントします。 毎日、$2^m$可能なエッジ構成ですが、小規模な場合でも実行不可能です。$m$なぜなら$m$最大210まで可能$n=21$。 

重要な洞察は、メッセージを認識する頂点サブセットのセットに対するマルコフ過程として問題をモデル化できるということです。 頂点の数が少ないため、各サブセットをビットマスクとして表すことができます。 させて$f[S]$サブセットからフルセットに到達するまでの予想日数を示します$S$。 それぞれについて$S$の場合、期待値は総期待値の法則から導出された次の線形方程式を満たします。$$f[S] = 1 + \sum_{T \supseteq S} P(S \to T) \cdot f[T]$$どこ$P(S \to T)$翌日、メッセージを知っている頂点のセットが次のように拡張される確率です。$T$。 全体の合計$T$外側の頂点を反復処理することで効率的に計算できます$S$そして、現在のセットからメッセージを受信する確率を計算します。 これは次のようなシステムにつながります。$2^n$の線形方程式$2^n$変数。 なぜなら$n\le 21$、ビットマスク動的プログラミングでそれを解決できます。$O(3^n)$近隣に対する包含-排除の原理を使用した時間。

 ## アルゴリズムのチュートリアル

 1. 頂点の各サブセットを長さのビットマスクとして表現します。$n$。 初期サブセットには頂点 1 セットのみがあります。 目標は、すべてのビットが設定されたサブセットです。 
2. 各頂点の事前計算$v$特定のサブセット内の近隣からメッセージを**受信しない**確率$S$。 これは$\prod_{u \in S} (1 - g_{u,v})$、 どこ$g_{u,v}$エッジが発生する確率です$(u,v)$が表示されます。 
3. サブセットの場合$S$、 させて$P_{\text{stay}} = \prod_{v \notin S} \text{probability that } v \text{ does not get message}$。 次に、から始まる予想日数$S$を満たす:$$f[S] = \frac{1 + \sum_{T \supset S} P(S \to T) f[T]}{1 - P_{\text{stay}}}$$これは再発を解決することから生まれます$f[S] = 1 + P_{\text{stay}} \cdot f[S] + \sum_{T \supset S, T \neq S} P(S \to T) f[T]$。 

1. サイズを小さくしながらサブセットを反復処理して、すべてのサブセットが確実に$f[T]$と$T \supset S$はすでに計算されています。 事前に計算されたモジュラー逆数を使用したモジュラー算術を使用して、分数を法として処理します。$998\,244\,353$。 
2. 出力$f[\{1\}]$モジュロ$998\,244\,353$。 

機能する理由: すべてのサブセットの予想時間は、確率によって重み付けされた、考えられる翌日の拡張をすべて考慮しています。 グラフは接続されており、すべての確率は厳密に 0 と 1 の間にあるため、連立方程式には一意の解が存在します。 順序を降順にすると、必要な依存値がすべてすでに計算されていることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modinv(x):
    return pow(x, MOD - 2, MOD)

n, m = map(int, input().split())
edges = [[0]*n for _ in range(n)]
for _ in range(m):
    u, v, p, q = map(int, input().split())
    prob = p * modinv(q) % MOD
    edges[u-1][v-1] = prob
    edges[v-1][u-1] = prob

full = (1 << n) - 1
dp = [0] * (1 << n)
for mask in range(full, -1, -1):
    if mask == full:
        dp[mask] = 0
        continue
    stay = 1
    for v in range(n):
        if not (mask & (1 << v)):
            prob_not = 1
            for u in range(n):
                if mask & (1 << u):
                    prob_not = prob_not * (MOD + 1 - edges[u][v]) % MOD
            stay = stay * prob_not % MOD
    inv = modinv((MOD + 1 - stay) % MOD)
    val = 1
    for v in range(n):
        if not (mask & (1 << v)):
            prob_get = 1
            for u in range(n):
                if mask & (1 << u):
                    prob_get = prob_get * (MOD + 1 - edges[u][v]) % MOD
            prob_get = (MOD + 1 - prob_get) % MOD
            dp[mask] = (dp[mask] + prob_get * dp[mask | (1 << v)]) % MOD
    dp[mask] = dp[mask] * inv % MOD
print(dp[1])
```このコードは、分数を変換するために逆モジュラーを事前計算します。`edges[u][v]`エッジの確率を格納します$(u,v)$。 サブセットごとに、`stay`新しい頂点がメッセージを受信しない確率を計算します。`inv`による除算を処理します$1 - P_{\text{stay}}$。 内側のループは、メッセージを取得して更新する新しい各頂点の期待される寄与を計算します。`dp[mask]`それに応じて。
