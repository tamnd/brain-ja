 ## 解決策
 ## 問題の理解

 文字列の最も長い連続部分文字列を見つけるように求められます。`s`これにより、特定の「退屈な」部分文字列が回避されます。 つまり、文字列が与えられると、`s`禁止パターンの小さなリスト`b1, b2, ..., bn`の最長セグメントを特定する必要があります。`s`これらの禁止された部分文字列が含まれず、その長さと開始インデックスが報告されます。 

入力文字列`s`長さは最大 100,000 文字で、各禁止文字列の長さは最大 10 です。禁止文字列の数は少なく、最大 10 です。この制約の組み合わせは、次のすべての部分文字列をチェックするアルゴリズムを用意する余裕がないことを示しています。`s`部分文字列の数は最悪の場合でもおよそ 5 * 10^9 であるため、すべての禁止文字列に対して単純に計算できます。 ただし、禁止された文字列の長さが短いということは、部分文字列の包含チェックが小さなスライディング ウィンドウ内で制限される可能性があることを示唆しています。 

いくつかの特殊なケースは微妙です。 次のすべての部分文字列が`s`少なくとも 1 つの禁止文字列が含まれている場合、答えは 0 ですが、この問題では任意の有効な開始インデックスが許可されます。 もし`s`それ自体が最も短い禁止文字列よりも短い場合、文字列全体は自明に有効です。 もう 1 つの注意が必要なシナリオは、禁止された文字列の重複です。 たとえば、次の場合`s = "aaa"`そして`b = ["aa"]`、長すぎる有効な部分文字列が誤って報告されないように、重複する一致を慎重に処理する必要があります。 

## アプローチ

 ブルートフォースアプローチは簡単です。すべての可能な開始インデックスを反復処理します。`s`、それぞれについて、考えられるすべての終了インデックスを反復処理して、部分文字列に禁止された文字列が含まれているかどうかを確認します。 これは、最終的に最長の有効な部分文字列を見つけるため、原理的には機能しますが、複雑さは O(|s|^2 * n * max_len_bi) です。 |s| 付き 最大 10^5 の場合、これは約 10^11 回の操作に相当し、2 秒の制限をはるかに超えています。 

重要な洞察は、禁止された文字列のサイズが小さいことから得られます。 各禁止文字列は最大 10 文字であるため、次の位置ごとに事前計算できます。`s`その位置またはその前で始まる禁止された部分文字列の最も古い終了インデックス。 その後、1 回ずつ繰り返すことができます`s`禁止された部分文字列の右端の境界を維持します。 これにより、問題は 1 回のリニア スキャンに軽減され、現在の「安全な」ウィンドウが追跡されます。 このアプローチは、長さにおいて線形です。`s`そして、n と禁止された文字列の最大長だけを乗算します。これは、n と max_len_bi が最大 10 であるため実現可能です。 

観察によると、すべての無効な部分文字列は禁止された文字列の最初の出現によって制限されており、禁止された文字列は短いため、文字列全体ではなく、数文字先を調べるだけで済みます。 これにより、線形スイープが可能になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O( | s | ^2 * n * max_len_bi) |
 | スライディング ウィンドウ / リニア スキャン | O( | s | * n * max_len_bi) |

 ## アルゴリズムのチュートリアル

 1. 配列を初期化する`forbidden_end`長さ |s| 位置ごとに保存する`i`、以降で終わる禁止された部分文字列が含まれる右端のインデックス`i`が発生します。 すべての要素を -1 に初期化します。 
2. 各禁止文字列を反復処理します。`b`。 発生するたびに、`b`で`s`( |b| ≤ 10 のため、単純な部分文字列検索を使用)、関連するセグメントを更新します。`forbidden_end`このインデックスとそれがカバーするすべての位置が禁止された部分文字列の一部であることをマークします。 具体的には、位置で始まる禁止された文字列の場合、`j`そして長さ`len_b`、 アップデート`forbidden_end[j] = max(forbidden_end[j], j + len_b - 1)`。 
3. 2 つのポインターを初期化します。`start = 0`現在のセーフウィンドウの始まりと`max_len = 0`、`best_start = 0`これまでに見つかった最適な部分文字列を追跡します。 
4. 反復処理する`s`インデックス付き`i`。 もし`i`現在の禁止境界を超えている場合は、移動してください`start`に`i`。 Otherwise, maintain`start`最後の禁止された部分文字列の次の位置。 
5. それぞれに`i`、現在のセーフ ウィンドウの長さを次のように計算します。`i - start + 1`。 この長さがこれより大きい場合は、`max_len`、 アップデート`max_len`そして`best_start`。 
6. すべてのポジションを処理した後、`max_len`そして`best_start`最長の有効な部分文字列の長さと開始インデックスを表します。 

**機能する理由**: 維持される不変条件は次のとおりです。`start`は常に、禁止された部分文字列を含まないウィンドウの先頭を指します。 禁止された部分文字列に到達する前にウィンドウを可能な限り拡張し、最大値を記録することで、有効な部分文字列が見逃されないことが保証されます。 すべての禁止された部分文字列は 1 回だけ考慮され、線形スイープの使用により効率が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

s = input().strip()
n = int(input())
b_list = [input().strip() for _ in range(n)]

forbidden_end = [-1] * len(s)

for b in b_list:
    len_b = len(b)
    for i in range(len(s) - len_b + 1):
        if s[i:i+len_b] == b:
            forbidden_end[i] = max(forbidden_end[i], i + len_b - 1)

max_len = 0
best_start = 0
start = 0
current_forbidden = -1

for i in range(len(s)):
    if forbidden_end[i] > current_forbidden:
        current_forbidden = forbidden_end[i]
    if i <= current_forbidden:
        start = current_forbidden + 1
    if i - start + 1 > max_len:
        max_len = i - start + 1
        best_start = start

print(max_len, best_start)
```このソリューションは、禁止された部分文字列がどこで終了するかを事前に計算し、有効なウィンドウを維持しながら文字列全体をスイープします。 微妙なのは重複の処理です。複数の禁止された部分文字列が交差する場合、`current_forbidden`それを保証します`start`右端の境界を飛び越えます。 Off-by-one エラーは、包括的なインデックスを慎重に使用することで回避されます。
