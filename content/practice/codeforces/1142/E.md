 ## 解決策
 ## 問題の理解

 完全な無向グラフが与えられます。$n$ノードですが、各エッジには方向が割り当てられており、トーナメントになります。 これらのエッジのサブセットはピンク色で色付けされており、その方向は既知です。 残りのエッジは緑色であり、その方向は最初は不明です。 私たちの目標は、同じ色のエッジで構成されるパスを介して他のすべてのノードに到達できる単一のノードを特定することです。 

クエリを使用すると、緑色のエッジの方向を学習できますが、最大でも次の方向に厳密に制限されます。$2 \cdot n$クエリ。 課題は、トーナメントの構造と既知のピンク エッジを活用して、非常に少ないクエリを使用して正しいノードを効率的に決定することです。 

制約が意味するのは、$n$と同じ大きさにすることができます$100{,}000$。 考えられるすべてのパスを検査したり接続性を素朴にチェックしたりするソリューションには、$O(n^2)$実行不可能な操作。 ノードの各ペアが正確に 1 つの有向エッジによって接続されており、トーナメントで高い出次数を持つノードが、私たちが探している「ドミネーター」である可能性が高いという事実を利用する必要があります。 

ピンク色のエッジがない場合、エッジ ケースが発生します。 この状況では、支配ノードを決定するにはグリーン エッジのクエリに完全に依存する必要があります。 ピンク色のエッジが存在するか、クエリを徹底的に実行できると仮定する不用意なアプローチは失敗します。 

もう 1 つの微妙なケースは、複数のノードがピンク色のパスを介して同様に到達可能であるように見える場合です。 ここで、クエリ戦略では、最初の候補が正しいと仮定するのではなく、ノードを注意深く比較して真の支配ノードを特定する必要があります。 

## アプローチ

 素朴なアプローチは、完全な隣接行列を構築し、すべての緑のエッジをクエリしてその方向を決定し、次にピンクと緑のエッジに対して BFS を個別に実行してすべてのノードの接続をチェックすることです。 このアプローチは正しいですが、次のことが必要です。$O(n^2)$クエリをはるかに超えています。$2 \cdot n$限界。 さらに、ノードあたりの BFS は、$O(n^2)$そのため、大きなグラフではタイムアウトになります。 

重要な洞察はトーナメントの特性から得られます。 どのトーナメントにも、他のすべてを直接的または間接的に支配するノードが存在します。 ピンクのエッジの場合、ピンクのエッジに沿った最大の出次数を持つノードが有力な候補となります。 線形数のクエリを使用して緑のエッジの中から支配的なノードを特定することで、問題をさらに軽減できます。 具体的には、候補ノードを維持し、グリーン エッジ クエリを使用して他のノードと比較できます。 候補が他のノードに直接到達できない場合は、候補を他のノードに置き換えます。 後$n-1$比較すると、ある色で他の候補ノードを圧倒することが保証された 1 つの候補ノードが残ります。 

このアプローチでは、トーナメントの構造を活用して、必要なクエリの数と、二次から線形への比較の数の両方を削減します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n^2) | 遅すぎる |
 | トーナメント候補者 | O(n) クエリ + O(n) 処理 | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 候補ノードをノード 1 として初期化します。このノードがドミネーターの現在の推定になります。 
2. 2 から n までの他のすべてのノードを繰り返します。 各ノードについて、現在の候補とこのノードの間の緑のエッジの方向をクエリします。 候補が緑のエッジに沿って、またはピンクのパスを介してノードを支配する場合、候補を保持します。 それ以外の場合は、候補を新しいノードに更新します。 これにより、どのステップでも、候補が以前に検査されたすべてのノードを潜在的に支配できることが保証されます。 
3. すべてのノードを処理した後、候補ノードは、あるカラー パスに沿って他のすべてのノードを支配することが保証されます。 この時点では、それ以上のクエリは必要ありません。 候補ノードを出力します。 

機能する理由: トーナメントでは、任意の 2 つのノードに対して、それらを接続する有向エッジが 1 つだけ存在します。 現在の候補を各ノードと繰り返し比較し、負けた場合は置き換えることで、最終候補が直接比較で他のすべてのノードに勝つことが保証され、単一色のパスに沿って他のすべてのノードに到達できることが保証されます。 線形比較により、次の値を決して超えないことが保証されます。$2 \cdot n$クエリ制限。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import os

def query(a, b):
    print(f"? {a} {b}")
    sys.stdout.flush()
    res = int(input())
    if res == -1:
        sys.exit()
    return res

def main():
    n, m = map(int, input().split())
    pink_edges = {}
    
    for _ in range(m):
        u, v = map(int, input().split())
        pink_edges[(u, v)] = True

    candidate = 1
    for node in range(2, n + 1):
        # Check if candidate can reach node via pink edges
        if (candidate, node) in pink_edges:
            continue
        if (node, candidate) in pink_edges:
            candidate = node
            continue
        
        # Query green edge direction
        res = query(candidate, node)
        if res == 0:
            candidate = node
    
    print(f"! {candidate}")
    sys.stdout.flush()

if __name__ == "__main__":
    main()
```このソリューションでは、まずピンク色のエッジを読み取り、高速検索のために辞書に保存します。 次に、候補をノード 1 として初期化します。後続の各ノードが候補と比較され、最初にピンクのエッジが既に方向を定義しているかどうかがチェックされ、次に必要に応じてクエリが実行されます。 候補は、新しいノードを支配できない場合にのみ更新されます。 すべてのノードが処理された後、候補は他のすべてのノードよりも優位であることが保証されます。 

微妙な部分は、緑色のエッジをクエリする前にピンクのエッジをチェックすることです。これにより、不必要なクエリが回避され、クエリ制限が尊重されます。 辞書では許可されています$O(1)$ピンクのエッジにアクセスします。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各ノードは 1 回だけ比較され、比較ごとに最大 1 つのクエリが実行されます。 
| スペース | O(m) | 定数時間ルックアップのためにすべてのピンクのエッジを保存します。 

ソリューションのパフォーマンスは最大でも$n-1$クエリ、決して超過しない$2 \cdot n$限界。 線形時間計算量は、次の制約内に簡単に収まります。$n \le 100{,}000$。

 ## 特殊なケース

 グラフにノードが 1 つしかない場合、候補は自明に 1 になります。ノードが 2 つある場合、ピンクのエッジが存在する場合、候補はピンクのエッジのソースになります。 ピンク色のエッジが存在しない場合は、単一のクエリによって候補が決定されます。 大きなグラフでは、複数のノードが最初は有効に見えるかもしれませんが、線形比較により、他のノードすべてを支配するノードのみが残ることが保証されます。 このアルゴリズムは、クエリ制限を超えることなく、これらのシナリオを適切に処理します。
