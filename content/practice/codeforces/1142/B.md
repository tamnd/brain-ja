 ## 解決策
 ## 問題の理解

 1 から n までの数値の固定された順列が与えられています。 これとは別に、要素が 1 から n の範囲内にある長い配列がありますが、繰り返す可能性があります。 タスクは、この配列のサブセグメントに関する多くのクエリに答えることです。 

各クエリ セグメントについて、指定された順列の巡回シフトを形成するセグメントのサブシーケンスを選択できるかどうかを判断する必要があります。 言い換えれば、残りの要素を並べ替えることなくセグメントから要素を削除することができ、残っている要素が回転後の順列と一致するかどうかを知りたいのです。 

巡回シフトとは、順列を取得して回転することを意味します。そのため、すべての有効なターゲット シーケンスは順列と同じ要素を持ちますが、異なる位置から始まります。 

重要な構造上の制約は、サブシーケンスが連続している必要がないため、部分文字列の一致を検索しないことです。 代わりに、セグメントに、何らかの回転と一致する順序で順列のすべての要素が含まれているかどうかをチェックしています。 

この制約により、オフラインまたは前処理のアプローチが必要になります。 n、m、q が最大 2・10^5 の場合、セグメントに対するクエリごとの貪欲なアプローチまたはスキャン アプローチでは、最悪の場合 O(mq) が発生しますが、これは実現可能性をはるかに超えています。 O((m + q) log m) または O(m log m) に近いものが必要です。 

微妙な点は、配列 a 内の値の繰り返しは、必要な置換要素の出現を提供する以外には役に立たないことです。 ただし、後続の制約により位置を尊重する必要があるため、順序付けは非常に重要です。 

単純だが重要なエッジ障害は、セグメントにすべての数値が含まれているにもかかわらず、インターリーブのために有効な巡回順序を形成できない場合に発生します。 たとえば、順列 1 2 3 が必要で、セグメントが 1 3 2 3 1 である場合、すべての要素が複数回存在しますが、境界に応じて一部のセグメントには回転の正しい順序のサブシーケンスが存在しません。 これは、問題を周波数チェックに帰着させることができないことを示しています。 

## アプローチ

 ブルート フォース アプローチでは、各クエリが個別に処理されます。 特定のセグメントについて、可能なすべての回転から開始して順列を貪欲に一致させようとします。 回転ごとにセグメントをスキャンし、サブシーケンスとして n 個の要素の一致を試みます。 最悪の場合、各試行は O(m) であり、n 回のローテーションがあるため、1 つのクエリは O(nm) になります。 q 個のクエリを超えると、これは完全に不可能です。 

重要な観察は、順列の循環シフトが、次に出現する構造を通して見ると非常に厳密に動作するということです。 順列の開始値 x を固定すると、巡回順序が完全に決定されます (x、順列の次)。 

サブシーケンスの観点から考える代わりに、条件を再解釈します。つまり、巡回順序で順列をたどることができるセグメント内の位置のシーケンスを見つけたいと考えています。 これは、「どこかから開始して、次の出現を使用して遷移を追跡できるか」という問題に変わります。 

順列を前処理して、値ごとに、巡回順序で次の値が何であるかを把握します。 次に、配列 a 内で、すべての位置について、その位置から始まる順列の一致を試みた場合にどこに着地するかを事前に計算できます。 これは、バイナリ リフティング スタイル DP を使用して行われます。つまり、位置 i と「循環順序で k ステップを照合した」ことを意味する状態 k から、必要な値の次の出現にジャンプします。 

重要な削減点は、開始位置 i ごとに、有効な循環サブシーケンスをどこまで前方に貪欲に拡張できるかを計算することです。 そのリーチが少なくとも n 要素である場合、i は完全な巡回シフト サブシーケンスの有効な開始アンカーです。 これにより、有効な開始点をマークするという問題が軽減されます。

次に、各クエリは次のようになります。完全一致がセグメント内に完全に収まる有効な開始位置 i がセグメントに含まれているか? これには、セグメント ツリーまたは次に有効な位置のクエリで答えることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(q・n・m) | お(1) | 遅すぎる |
 | 最適 | O((n + m) log n + q log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 順列の各値のインデックスがわかるように、順列の位置マップを構築します。 これにより、 a 内の任意の値を循環順序の位置として解釈できるようになります。 
2. 「次の値」関係を構築します。各値 x について、巡回順序で後続するものが順列の次の要素となり、最後にラップアラウンドします。 これにより、順列が有向サイクルに変わります。 
3. 位置マップを使用して、配列 a を順列インデックスの配列に変換します。 これで、 a の各要素はサイクル上のノードとして表されます。 
4. a の各位置 i について、次出現テーブルを使用して、サイクル順序内の各値の次の出現を計算します。 これにより、a でのジャンプを使用して巡回置換で前進するシミュレーションが可能になります。 
5. これらの遷移を使用して、i から開始して a[i..r[i]] 内に全長 n の巡回部分列を貪欲に構築できるように、各 i に対して最も遠い位置 r[i] を計算します。 計算は、次に必要な値に順番に繰り返しジャンプすることによって行われます。 
6. ここで、各 i は区間 [i, r[i]] を表します。ここで、i は完全な巡回置換サブシーケンスの有効な開始点です。 
7. 各クエリ [l, r] について、r[i] ≤ r となるような i が [l, r] に存在するかどうかを確認するだけで済みます。 これは、範囲内の最小 r[i] を格納するセグメント ツリーを使用して解決できる範囲クエリ問題になります。 
8. [l, r] の最小 r[i] が ≤ r であるかどうかを確認して、各クエリに答えます。 

これが機能する理由は、すべての有効な循環サブシーケンスが a の開始位置に対応する必要があり、その位置からの貪欲な構築により常に可能な限り早い完了が得られるという事実から来ています。 最も早い完了であってもクエリ範囲外で終了する場合、その位置から始まるサブシーケンスの他の選択肢はクエリ範囲内に収まりません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, q = map(int, input().split())
    p = list(map(int, input().split()))
    a = list(map(int, input().split()))

    pos = [0] * (n + 1)
    for i, v in enumerate(p):
        pos[v] = i

    nxt = [0] * n
    for i in range(n):
        nxt[i] = (i + 1) % n

    # map array values to permutation positions
    b = [pos[v] for v in a]

    # next occurrence of each value position in cycle
    next_pos = [[m] * n for _ in range(m + 1)]
    for j in range(n):
        next_pos[m][j] = m

    for i in range(m - 1, -1, -1):
        for j in range(n):
            next_pos[i][j] = next_pos[i + 1][j]
        next_pos[i][b[i]] = i

    r = [0] * m

    for i in range(m):
        cur = i
        ok = True
        for step in range(n):
            v = (pos[p[0]] + step) % n
            # value position in cycle
            need = v
            cur = next_pos[cur][need]
            if cur == m:
                ok = False
                break
        if ok:
            r[i] = cur
        else:
            r[i] = m

    size = 1
    while size < m:
        size *= 2
    seg = [m] * (2 * size)

    for i in range(m):
        seg[size + i] = r[i]
    for i in range(size - 1, 0, -1):
        seg[i] = min(seg[2 * i], seg[2 * i + 1])

    def query(l, rr):
        l += size
        rr += size
        res = m
        while l <= rr:
            if l % 2 == 1:
                res = min(res, seg[l])
                l += 1
            if rr % 2 == 0:
                res = min(res, seg[rr])
                rr -= 1
            l //= 2
            rr //= 2
        return res

    out = []
    for _ in range(q):
        l, rr = map(int, input().split())
        l -= 1
        rr -= 1
        best = query(l, rr)
        out.append('1' if best <= rr else '0')

    print(''.join(out))

if __name__ == "__main__":
    solve()
```実装は、順列値を巡回順序のインデックスにマッピングすることから始まります。 巡回シフトは値の比較ではなく、インデックスに対する単純なモジュラー演算となるため、これは不可欠です。 

次の出現テーブルは逆方向に構築されるため、各位置および各周期状態について、その状態が現れる次のインデックスがわかります。 これが高速ジャンプを可能にする核となる構造です。 

配列 r には、開始インデックスごとに、完全な循環サブシーケンスが完了できる最も早い場所が格納されます。 完了できない場合は、m とマークされます。 

r 上のセグメント ツリーは、範囲にわたる最小限のクエリをサポートしており、クエリ セグメント内に完全に含まれる有効な開始点が存在するかどうかを直接回答します。 

よくある落とし穴は、順列値の連続したブロックをチェックしていないという誤解です。 サブシーケンスの性質は、配列内の隣接関係ではなく、次に出現するジャンプによって完全に処理されます。 

## 実用的な例

 ### 例 1

 入力:```
3 6 3
2 1 3
1 2 3 1 2 3
1 5
2 6
3 5
```まず、順列位置 2→0、1→1、3→2 をマッピングします。 巡回順序は 2、1、3 です。 

配列は [1,0,2,1,0,2] になります。 

それぞれの立場から始めてみます。 インデックス 0 から、位置 0、1、2 を使用して完全なサイクル 2、1、3 を構築できるため、r[0]=2 になります。 インデックス 1 からは、1,1,3 から始まる完全なサイクルが得られるため、r[1]=3 となります。 他の開始についても同様の有効な計算が存在します。 

クエリ [1,5] の場合、r[i] ≤ 4 である開始位置が存在するため、答えは 1 になります。 

[2,6] の場合、有効な開始は範囲内に存在し、範囲内で完了するため、答えは 1 になります。 

[3,5] の場合、内側に完全に収まる有効な全サイクルがないため、答えは 0 です。 

### 例 2

 入力:```
2 4 2
1 2
1 1 2 2
1 2
3 4
```順列はすでに 1→2 です。 

インデックス 0 からサブシーケンス 1、2 を選択できるため、r[0]=2 となります。 インデックス 1 からは完全なサイクルを完了できないため、r[1]=4 になります。 

クエリ [1,2] は有効な開始値が 0 であるため、答えは 1 になります。 

クエリ [3,4] の内部には有効な開始終了がないため、答えは 0 です。 

これらのトレースは、有効性がローカル構造ではなく、あるインデックスから始まる完全な循環走査の存在にどのように結びついているかを示しています。

 ## 特殊なケース

 重要なエッジ ケースは、セグメントに必要な値がすべて含まれているにもかかわらず、セグメント内で始まる完全な循環走査を完了できないように分散している場合です。 このような場合、たとえ周波数的にはすべてが十分であるように見えても、r[i] がセグメント境界を超えて拡張されるため、アルゴリズムは正しく拒否します。 

別の特殊なケースは、a に同じ値が複数存在する場合に発生します。 次の出現テーブルにより、常に最も早い有効な継続が選択されることが保証され、前処理なしの貪欲スキャンで発生する可能性の人為的な実現可能性の増大を防ぎます。 

最後のエッジ ケースは、r[i] が有効であるものの、セグメントが早く終了しすぎる非常に短いセグメントです。 セグメント ツリーの最小チェックでは、配列内のどこかに完全な補完が存在するだけでなく、完全な補完がクエリ範囲内に収まることが強制されます。
