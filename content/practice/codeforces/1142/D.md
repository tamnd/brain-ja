 ## 解決策
 ## 問題の理解

 いくつかの整数を区切り文字なしで連続して書くことによって形成された長い数字列が与えられます。 この文字列の連続する各部分文字列は、整数として解釈できます (部分文字列が正確に「0」でない限り、先頭にゼロはありません。ただし、ここでは入力により完全な文字列がゼロで始まらないことが保証されます)。 

すべての正の整数の中には、再帰的な数字ベースのルールに従って「不適切」とラベル付けされるものもあります。 1 から 9 までの 1 桁の数字は常に不適切です。 より大きな数値の場合、妥当性は最後の桁を除いた数値の妥当性に依存します。また、以前に構築された不適切な数値の順序とその位置を法とする 11 に関する制約にも依存します。制約は、桁を追加するときに数値に含めることができる子の数を決定します。 

このタスクは、指定された文字列の部分文字列が不適切な数値と評価される個数を数えることです。数値が異なる位置で繰り返される場合でも、各出現箇所を個別に数えます。 

文字列の長さは最大 100,000 であるため、すべての部分文字列を整数に解析して個別に条件をチェックしようとするソリューションは不可能です。 ナイーブ$O(n^2)$部分文字列の列挙はすでに境界線に達しており、たとえ部分文字列の解析が可能だったとしても$O(1)$、「不適切な」メンバーシップをテストする効率的な方法がまだ必要です。 

さらに微妙な制約は、「不適切な数値」は割り算やパターン マッチングのような単純な数字のプロパティでは定義されないことです。 それらは、構造化された組み合わせ成長ルールによって定義されます。 これは、各ノードがグローバル列挙内の位置に応じて限られた数の子を持つ、桁上のプレフィックス ツリーを扱っていることを強く示唆しています。 

重要なエッジケースは、部分文字列の先頭にゼロがあることです。 たとえば、「01」や「001」のような部分文字列は、意図した意味での正の整数の有効な表現ではないため、有効な不適切な数値として扱ってはなりません。 もう 1 つの微妙な問題は、同じ数値を表す部分文字列が重複していることです。これらは個別にカウントする必要があるため、値によって重複を排除できません。 

## アプローチ

 ブルートフォース手法は簡単です。すべての部分文字列を反復処理し、各部分文字列を整数に変換し、再帰定義を使用してそれが不適切かどうかを確認します。 部分文字列の数は$O(n^2)$、各チェックが一定時間だったとしても、これはすでに約$5 \cdot 10^9$最悪の場合の動作$n = 10^5$。 部分文字列を整数に変換するとオーバーヘッドも増加するため、このアプローチは完全に実行不可能です。 

定義の構造は、より強力なものを示唆しています。不適切性は、数字を桁ごとに繰り返し拡張することによって定義されます。各接頭辞は、有効な子の数を「認識」しています。 これはまさにトライの構造であり、各ノードはプレフィックス番号に対応し、各ノードには次の桁の許容範囲があります。 

部分文字列を列挙する代わりに、視点を逆転させます。 文字列をスキャンし、現在のプレフィックスが依然として不十分であるかどうかを追跡しながら、各開始位置から貪欲に数値を拡張しようとします。 各ステップで、不適切な数値のグローバルな順序付けにおいて現在のプレフィックスのインデックスを維持します。これは、そのインデックスによって次に許可される桁数が決定されるためです。 「最後の桁 < k mod 11」という制約は分岐を効果的に制限します。これは、ほとんどのパスがすぐに消滅することを意味します。 

重要な観察は、多くの部分文字列があるにもかかわらず、各開始位置が無効になる前に少数の有効な拡張子のみを生成することです。 これにより、実際にはすべてのスタートにわたるトランジションの総数が線形またはほぼ線形に減少します。 

トラバース中に暗黙的に順序構造を事前計算またはシミュレーションします。 有効なプレフィックスを 1 桁拡張するたびに、不適切な数値の間でその「ランク」を更新し、その桁がそのランクから導出されたモジュロ 11 境界によって許可されるかどうかを確認します。

 | 最適 |$O(n \cdot 10)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての開始インデックスを反復処理します。$i$文字列の中で。 各 start は、その位置から始まる候補番号を表します。$i$。 
2. これまでに形成されたプレフィックスを表す現在の状態を初期化します。 この状態には、数値 (小さいプレフィックスの場合) が含まれますが、さらに重要なことに、現在の「不適切なインデックス」も含まれます。$k$、このプレフィックスが不適切な数値のグローバル順序付けのどこにあるかを追跡します。 
3. 数値を 1 桁ずつ右に拡張し、部分文字列を形成します$s[i:j]$。 各ステップで、数値プレフィックスを更新します。 
4. 現在の数字が 0 で、部分文字列の最初の位置にいる場合は、先頭にゼロが付いている数字は無効であるため、すぐに停止します。 
5. プレフィックスの長さが 1 の場合、常に不十分であるため (数字 1 ～ 9)、それに応じてランクを初期化します。 
6. 長いプレフィックスの場合は、親プレフィックスのランクを計算し、有効な子の数を決定します。$k \bmod 11$。 この値は、許可される最後の桁の上限として機能します。 
7. 現在の桁が許容される上限よりも厳密に小さいかどうかを確認します。 そうでない場合は、これ以上拡張しても数値が増加するだけで無効なままになるため、この開始位置のループを中断します。 
8. 有効な場合、この部分文字列を 1 つの不適切な数値の出現としてカウントします。 
9. 制約が失敗するか、文字列の終わりに達するまで延長を続けます。 

### なぜ効果があるのか

 重要な不変条件は、すべての有効な部分文字列が桁拡張ツリー内の有効なパスに対応し、各ノードに不適切な数値のグローバルな順序付けにおける決定的な位置が割り当てられることです。 モジュロ 11 ルールにより、許可される次の状態の数の定義と正確に一致する方法で各ノードの子が制限されるようになります。 この順序はすべてのプレフィックスにわたって一貫しているため、部分文字列が何らかの拡張子で結合された数字に違反すると、それ以上の拡張子は有効性を回復できません。 これにより、早期に停止しても有効な部分文字列がスキップされたり、無効な部分文字列が含まれたりすることがないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)
    ans = 0

    for i in range(n):
        if s[i] == '0':
            continue

        k = 0
        for j in range(i, n):
            d = ord(s[j]) - 48

            if j == i:
                if d == 0:
                    break
                k = d
                ans += 1
                continue

            # compute allowed range based on k
            c = k % 11

            if d >= c:
                break

            k = k * 10 + d
            ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```このコードは、開始位置と終了位置にわたる二重ループを実装します。 外側のループは部分文字列の開始を修正します。 内側のループは、現在構築されている値を維持しながら、一度に 1 桁ずつ数値を拡張します。`k`。 

変数`k`数値として、および不適切な順序付けのインデックスの代用として使用されます。 モジュロ 11 条件は拡張ごとに適用され、次の数字が許可されるかどうかが決定されます。 

早期のブレークは不可欠です。数字が制約に違反すると、同じインデックスで始まる部分文字列は有効性を回復できなくなります。これは、許可される数字のしきい値がプレフィックスの状態によって固定されている一方で、数字を追加しても数字が増えるだけであるためです。

import sys, io

def run(inp: str) -> str:

    import sys

    s = input().strip()
    n = len(s)

        if s[i] == '0':
            continue

 ## 特殊なケース

 主なエッジケースは、部分文字列がそれ以上の拡張を直ちに無効にする数字で始まる場合です。 たとえば、最初の桁が大きい位置から開始しても有効ですが、後続の桁はすぐにモジュロ 11 制約に失敗する可能性があります。 アルゴリズムは、拡張子ごとに制約をチェックし、違反した場合は直ちに停止することでこれを処理し、無効な部分文字列がカウントされないようにします。 

もう 1 つの特殊なケースは、1 桁の部分文字列です。 1 から 9 までのすべての数字は自動的に有効になり、アルゴリズムは遷移ルール​​を適用する前にこれらを明示的にカウントし、状態変数の正しい初期化を保証します。`k`。 

先頭のゼロは、開始位置をスキップすることによって処理されます。`s[i] == '0'`、ルート レベルでの無効な数値解釈を防ぎます。
