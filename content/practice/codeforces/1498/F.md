 ## 解決策
 ## 問題の理解

 私たちは、木の上で 2 人用のゲームを分析するように頼まれました。 ツリーの各ノードには一定数のプレゼントが含まれており、プレイヤーは順番にプレゼントをノードから自分のノードに移動します。$k$- 番目の先祖。 行動できなかったプレイヤーが負けとなります。 タスクは、ルートとみなされるすべてのノードについて、両方が最適にプレイした場合に最初のプレイヤーであるアリスが勝利を保証できるかどうかを判断することです。 

入力は最大のツリーで構成されます。$10^5$ノードとパラメータ$k$各ノードには、次のような数のプレゼントがあります。$10^9$。 ツリーのエッジは整数のペアとして指定され、現在の配列は個別に指定されます。 出力は長さのリストです$n$、そのノードがルートであるときにアリスが勝った場合は 1、それ以外の場合は 0 になります。 

なぜなら$n$までです$10^5$そして$k$が小さいため、おおよそ次のようなアルゴリズムが必要です。$O(n k)$または$O(n \log n)$テストケースごとに。 すべての可能な動きを単純に反復するソリューションでは、潜在的に次のような問題が発生します。$O(n^2)$動作が遅すぎます。 プレゼントの可能な値が大きいため、各プレゼントを明示的にシミュレートするソリューションも除外されます。 

素朴なソリューションを壊す可能性のあるエッジケースは次のような場合です。$k$一部のノードの深さよりも大きいです。 この状況では、それらのノードはプレゼントをまったく上に移動できません。 もう 1 つの注意が必要なケースは、ノードに存在するものがゼロの場合です。 不注意なアプローチでは、すべてのノードがゲームに貢献していると想定する可能性がありますが、これは正しくありません。 

## アプローチ

 ブルートフォースアプローチでは、両方のプレーヤーのあらゆる可能な動きをシミュレートしようとします。 各ルートに対して、少なくとも深さのノードを繰り返し選択します。$k$好きな数のプレゼントを彼らの場所に移動します$k$- 番目の先祖。 各段階で、考えられるすべての一連の動きを評価する必要がありますが、これは組み合わせ爆発的です。 このアプローチは原理的には正しいですが、次のような場合には明らかに不可能です。$n=10^5$なぜなら、状態の数は計算できる範囲をはるかに超えて増加するからです。 

重要な洞察は、これを公平な組み合わせゲームとして見ることによって得られます。少なくとも各ノードの深さは$k$プレゼントの数と同じサイズのヒープとして扱うことができます。 プレゼントを～に移動する$k$-th の祖先は、ヒープ サイズの分割またはシフトと見なすことができます。 Sprague-Grundy 理論を使用すると、同等の番号を表す各ノードに Grundy 番号を割り当てることができます。 すべてのノードのグランディ数の XOR によって勝者が決まります。0 の場合は 2 番目のプレーヤー (ボブ) が勝ちます。 それ以外の場合は、最初のプレイヤー (アリス) が勝ちます。 

なぜなら$k$が小さい場合は、深さ優先検索を実行して、葉から上に向かってグランディ数を計算できます。 ノードのグランディ数は、距離にあるノードのすべてのグランディ数の XOR です。$k$その下にノードに存在する数を正確に加えたもの$k$下に。 次に、標準のツリー DP 手法を使用してツリーを再ルートすることで、すべてを最初から再計算することなく、考えられるすべてのルートの結果を効率的に計算できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(n^2 * max(a_i)) | O(n) | 遅すぎる |
 | DFS + リルートを使用した Sprague-Grundy | O(n k) | O(n k) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力を解析して隣接リストとしてツリーを構築し、現在の配列を読み取ります。 深さ、親、およびサブツリーの情報を格納するために配列を初期化します。 
2. 任意のルート (ノード 1 など) から DFS を実行して、各ノードの深さと$k$各ノードの - 番目の祖先。 これにより、ノードがプレゼントを移動できる場所をすばやく特定できます。 
3. 各ノードに対して、DP 配列を定義します。`dp[u][d]`ノードからのプレゼントの XOR を正確に表現します`d`以下の距離`u`。 葉の場合、これは現在の数にすぎません。 
4. DFS から戻るときに、ノードの DP 配列を更新します。`u`離れた場所にある子供からの DP 値を XOR 演算することによって`d-1`。 こちらです、`dp[u][d]`ノードからのすべての関連する貢献を深層に蓄積します`d`下に`u`。 
5. ルートのグランディ数を、距離の倍数にあるすべてのノードの XOR として計算します。`k`根元の下。 ゼロ以外の場合、アリスが勝ちます。 そうでなければ、ボブが勝ちます。 
6. すべてのルートの答えを計算するには、ツリーを再ルートします。 ルートを親から移動する場合`p`子供に`c`、以前に計算された情報を使用してパスに沿った DP 値を更新します。 これにより、最初から再計算する必要がなくなり、`O(n k)`複雑。 
7. すべてのルートの結果を収集し、出力します。 

機能する理由: すべてのノードで、DP 配列は移動可能なプレゼントの XOR 寄与を正確に表します。$k$レベルアップします。 深さの蓄積と再ルートを備えた DFS を使用することにより、グランディ数を不変に維持します。 Sprague-Grundy 理論は、これらの数値の XOR により、最適なプレイの下で勝者を正確に予測することを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(1 << 20)

n, k = map(int, input().split())
edges = [[] for _ in range(n)]
for _ in range(n-1):
    x, y = map(int, input().split())
    edges[x-1].append(y-1)
    edges[y-1].append(x-1)
a = list(map(int, input().split()))

dp = [[0]*(k+1) for _ in range(n)]
res = [0]*n

def dfs(u, parent):
    dp[u][0] = a[u]
    for v in edges[u]:
        if v == parent:
            continue
        dfs(v, u)
        for i in range(k):
            dp[u][i+1] ^= dp[v][i]

dfs(0, -1)

def reroot(u, parent):
    g = dp[u][k]
    res[u] = 1 if g != 0 else 0
    for v in edges[u]:
        if v == parent:
            continue
        # remove v's contribution from u
        for i in range(k):
            dp[u][i+1] ^= dp[v][i]
        # add u's contribution to v
        new_dp_v = dp[v][:]
        for i in range(k):
            new_dp_v[i+1] ^= dp[u][i]
        old_dp_u = dp[u][:]
        dp[v] = new_dp_v
        reroot(v, u)
        dp[v] = old_dp_u
        for i in range(k):
            dp[u][i+1] ^= dp[v][i]

reroot(0, -1)
print(' '.join(map(str, res)))
```最初の DFS 計算`dp[u][d]`ノードでの現在の XOR として`d`以下の距離`u`。 これにより、プレゼントを伝播する動きのグランディ数が正しく累積されます。`k`上にステップします。 の`reroot`この関数は体系的にルートを変更し、DP 配列を更新して、最初から再計算することなく正しい XOR 寄与を維持します。 最終的な配列`res`アリスが勝てる場合は 1、勝てない場合は 0 が入ります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n k) | 各 DFS と再ルートにより、ノードごとに最大 k 個のエントリが更新されます。 |
 | スペース | O(n k) | dp 配列には、ノードごとに k+1 エントリが格納されます。 |

 ソリューションは、ノード数と小さな定数 k の積に応じて線形にスケールします。 n=10^5 および k≤20 の場合、これは 2 秒および 256 MB 以内に快適に収まります。
