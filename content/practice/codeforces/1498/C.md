 ## 解決策
 ## 問題の理解

 私たちは持っています`n`一列に並んだ平面。 粒子は左側の外側から始まり、崩壊年齢とともに右側に移動します`k`。 

粒子が平面を横切るときは常に同じ方向に移動し続けます。 その年齢が 1 より大きい場合、平面は年齢が 1 つ小さく、方向が反転した新しい粒子も作成します。 パーティクルは互いに相互作用することがないため、すべてのパーティクルは独立して進化します。 

タスクは、プロセス全体が終了した後に存在する粒子の数をカウントすることです。 数値は急速に増加するため、答えは法で求められます`10^9+7`。 

制限は非常に小さいです。 すべての合計`n`値は最大でも`1000`、およびすべての合計`k`値も最大です`1000`。 これはすでに、動的プログラミング ソリューションがおおよそ次のようなものであることを示唆しています。`O(nk)`状態は簡単に十分に高速です。 たとえ`O(nk(n+k))`解は通るかもしれませんが、粒子自体の数が膨大になるため指数関数的なシミュレーションは不可能です。 

誤って対処しやすい状況がいくつかあります。 

いつ`k = 1`、パーティクルは決してコピーを作成しません。 例えば、```
1
3 1
```生成する```
1
```すべての平面で反射パーティクルをやみくもに作成するシミュレーションでは、誤ってさらに多くのパーティクルが生成されます。 

平面が 1 つしかない場合、その方向にもう平面がないため、反射された粒子はすぐにシステムから離れます。 例えば、```
1
1 3
```生成する```
2
```パーティクルが常に繰り返し繰り返しバウンスすることを前提とした再帰的な実装では、カウントがオーバーカウントされます。 

方向性も重要です。 考慮する```
1
2 3
```答えは```
4
```年齢 2 の反射粒子は左に移動し、離れる前に 1 つの飛行機にのみ遭遇します。 すべてのパーティクルを常にすべてを通過するかのように扱う`n`飛行機は間違ったカウントを返します。 

## アプローチ

 最も直接的なアイデアは、すべての粒子をシミュレートすることです。 粒子が平面に到達するたびに、元の粒子が継続され、場合によっては、年齢が 1 ずつ減って反対方向に移動する新しい粒子が作成されます。 

粒子は決して衝突したり、相互に影響を与えたりすることがないため、このアプローチは正しいです。 問題は、粒子の数が指数関数的に増加することです。 中程度の値であっても、`k`、合計数が非常に多くなります。 

重要な観察は、粒子は、現在の位置、方向、残りの年齢という 3 つの情報によって完全に記述されるということです。 これらの量が同じ値を持つ 2 つのパーティクルは、まったく同じ数の子孫を生成します。 

粒子が現在平面上にあると仮定します`i`、年齢とともに右に移動`j`。 平面を通過した後、元の粒子は平面に移動します`i+1`、まだ年齢とともに`j`。 もし`j > 1`、反射された粒子は平面に向かって移動します`i-1`年齢とともに`j-1`。 

The same description works for particles moving left. This creates overlapping subproblems, which makes dynamic programming natural.

 方向を明示的に保存する代わりに、対称性を利用できます。 定義する`dp[i][j]`age の粒子によって生成される粒子の数として`j`飛行機から始まる`i`そして一番近い端に向かって進んでいきます。 平面インデックスには次の番号が付けられます。`1`に`n`。 

このような粒子が平面を横切るとき`i`、元の粒子は境界に向かって進み、寄与します。`dp[i-1][j]`一方、反射されたパーティクルは方向を反転し、ミラーリングされた位置から開始するパーティクルとまったく同じように動作します。`n-i+1`年齢とともに`j-1`。 

これにより、```
dp[i][j] = dp[i-1][j] + dp[n-i+1][j-1]
```ベースケース付き```
dp[0][j] = 1
dp[i][1] = 1
```なぜなら、境界に到達するということは、現在の粒子だけが残り、古い粒子が分割されることがないことを意味するからです。

 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | 指数 | 遅すぎる |
 | 最適 | O(nk) | O(nk) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 2次元テーブルを作成する`dp`サイズの`(n+1) × (k+1)`。 
2. 間隔を設定する`dp[i][1]`に`1`なぜなら、古い粒子は新しい粒子を作成できないからです。 
3. 間隔を設定する`dp[0][j]`に`1`なぜなら、すでにすべての平面を通過した粒子は単に生き残り、それ自体に寄与するからです。 
4. プロセス年齢`2`まで`k`。 
5. 年齢ごとに、以下のポジションを処理します。`1`に`n`。 
6. コンピューティング```
dp[i][j] = dp[i-1][j] + dp[n-i+1][j-1]
```モジュロ`10^9+7`。 

第 1 項は、境界に向かって続く元の粒子に対応します。 第 2 項は、方向が逆転し、年齢が 1 つ減少する反射粒子に対応します。 
7. 必要な答えは次のとおりです`dp[n][k]`これは、最初の平面の前で開始し、右に移動する初期パーティクルを表します。 

### なぜ効果があるのか

 州`dp[i][j]`常に、ある年齢の粒子によって生成された粒子の総数を表します`j`それはまだ正確にあります`i`現在の方向で利用可能な飛行機。 

最も近い平面を横切ると、未来が 2 つの独立した部分に分離されます。 一つの枝が年齢を保つ`j`残りの飛行機は 1 機減りました。 もう一方のブランチは方向を反転し、年齢の 1 単位を失い、相補的な平面のセットが表示されます。 考えられるすべてのパーティクルの進化は、これら 2 つのブランチのいずれかに正確に属するため、反復ではすべてのパーティクルが 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

t = int(input())
queries = []
max_n = 0
max_k = 0

for _ in range(t):
    n, k = map(int, input().split())
    queries.append((n, k))
    max_n = max(max_n, n)
    max_k = max(max_k, k)

dp = [[0] * (max_k + 1) for _ in range(max_n + 1)]

for i in range(max_n + 1):
    dp[i][1] = 1

for j in range(1, max_k + 1):
    dp[0][j] = 1

for j in range(2, max_k + 1):
    for i in range(1, max_n + 1):
        dp[i][j] = (dp[i - 1][j] + dp[max_n - i + 1][j - 1]) % MOD

ans = []

for n, k in queries:
    cur = [[0] * (k + 1) for _ in range(n + 1)]

    for i in range(n + 1):
        cur[i][1] = 1

    for j in range(1, k + 1):
        cur[0][j] = 1

    for j in range(2, k + 1):
        for i in range(1, n + 1):
            cur[i][j] = (cur[i - 1][j] + cur[n - i + 1][j - 1]) % MOD

    ans.append(str(cur[n][k]))

print("\n".join(ans))
```テーブルには、残りの飛行機と残りの年齢によってインデックス付けされた状態が保存されます。 年齢 1 のパーティクルは子孫を生成しないため、最初の列は 1 に初期化されます。 境界に到達すると粒子が単に終了することを意味するため、0 番目の行も 1 になります。 

遷移にはシステムの対称性が使用されます。 最も近い平面を通過した後、反射された粒子は反対側の平面を正確に認識します。これにより、指数が説明されます。`n - i + 1`。 

ループの順序は重要です。 年`j`年齢によって異なります`j-1`, したがって、年齢は小さいものから大きいものまで処理されます。 同じ年齢内では、位置は左から右に処理されます。`dp[i]`に依存します`dp[i-1]`。 

オーバーフローを避けるために、モジュロ演算は加算の直後に適用されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

MOD = 10**9 + 7

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []

    for _ in range(t):
        n, k = map(int, input().split())

        dp = [[0] * (k + 1) for _ in range(n + 1)]

        for i in range(n + 1):
            dp[i][1] = 1

        for j in range(1, k + 1):
            dp[0][j] = 1

        for j in range(2, k + 1):
            for i in range(1, n + 1):
                dp[i][j] = (dp[i - 1][j] + dp[n - i + 1][j - 1]) % MOD

        out.append(str(dp[n][k]))

    return "\n".join(out)

# provided samples
assert run("4\n2 3\n2 2\n3 1\n1 3\n") == "4\n3\n1\n2"

# minimum case
assert run("1\n1 1\n") == "1"

# single plane, large age
assert run("1\n1 5\n") == "2"

# k = 1, many planes
assert run("1\n7 1\n") == "1"

# off-by-one direction test
assert run("1\n2 3\n") == "4"

# larger symmetric case
assert run("1\n3 3\n") == "7"

 ## 特殊なケース

 検討してください```
1
3 1
```アルゴリズムが初期化されます`dp[i][1]=1`あらゆる人にとって`i`。 依存できるより小さい年齢がないため、移行は実行されません。 答えは`1`これは、コピーが作成されないという事実と一致します。 

考慮する```
1
1 3
```テーブルは次のようになります

 | 私 | j | 値 |
 | --- | --- | --- |
 | 0 | 1 | 1 |
 | 1 | 1 | 1 |
 | 1 | 2 | 2 |
 | 1 | 3 | 2 |

 最初の交差後の反射パーティクルにはその方向にプレーンが残っていないため、カウントは 2 のままです。 

考慮する```
1
2 3
```再帰式を計算します```
dp[1][2]=2
dp[2][2]=3
dp[1][3]=2
dp[2][3]=4
```反射された年齢 2 のパーティクルは、左に移動している間、使用できる平面が 1 つだけあります。 使用する`n-i+1`はこの非対称性を正確に捉え、過剰なカウントを回避します。
