 ## 解決策
 ## 問題の理解

 この問題では、与えられた整数を見つけるように求められます。$n$、最小の整数$x$以上$n$の最大公約数が$x$そしてその桁の合計が 1 より大きくなります。 言い換えれば、私たちが望んでいるのは、$x \ge n$と$gcd(x, s(x)) > 1$、 どこ$s(x)$の桁の合計です$x$。 入力は複数のテスト ケースで構成され、それぞれが 1 つの数値を与えます。$n$、出力は、この条件を満たすテスト ケースごとに 1 つの整数です。 

制約により許可されるのは、$n$まで$10^{18}$そして最大まで$10^4$テストケース。 ～を繰り返す素朴なアプローチ$n$上向きに計算します$gcd(x, s(x))$各候補のチェックが非常に高速であれば、実現可能である可能性があります。 以来$10^{18}$が大規模であるため、最悪の場合、広範囲の数値を線形にスキャンするソリューションを提供することはできません。 各チェックには、桁の合計と gcd の計算が含まれます。どちらも単一の数値に対して高速です。 

エッジケースには次のような数字が含まれます。$n$それ自体が既に条件を満たしている、桁の合計が素数である数値、または「適切な」候補のすぐ下の数値です。 たとえば、次の場合$n = 75$、75と12のgcdは3なので、答えは75そのものです。 もし$n = 11$、$gcd(11,2) = 1$なので、12 に移動する必要があります。$gcd(12,3) = 3$。 不用意に実装すると、次のチェックがスキップされる可能性があります。$n$それ自体が最初に増加し、間違った答えが生成されます。 

## アプローチ

 ブルートフォースアプローチは簡単です。$n$、桁の合計を計算し、その数値で gcd を計算し、それが 1 より大きいかどうかを確認します。そうでない場合は、数値をインクリメントして繰り返します。 これが機能するのは、各数値が独立しており、gcd の計算が非常に高速であるためです。 ただし、最悪の場合、有効な番号を見つける前に、多数の連続する番号をチェックする必要がある場合があります。$x$。 制約を考慮すると、数値が少ない場合は不運になる可能性がありますが、実際には桁の合計は最大 162 (18 桁の数値の場合) であるため、ほとんどの場合、数ステップ以内に桁の合計が 1 より大きい gcd が得られます。 これにより、実際には単純な線形スキャンが可能になります。 

問題を扱いやすくする重要な洞察は、連続する数値に対して gcd 条件に違反することはほとんどないということです。 桁の合計はゆっくりと変化し、多くの数値は桁の合計に公約数を共有します。 したがって、単純にインクリメントすると、$n$条件が満たされるまでは、問題の制限を考慮すると正しく、効率的です。 リニア スキャンでは各テスト ケースで数回の反復のみが必要なため、複雑な数式や事前計算は必要ありません。

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る$t$。 
2. 各テスト ケースについて、整数を読み取ります。$n$。 
3.初期化$x = n$候補番号として。 
4. 有効な値が得られるまで、次の手順を繰り返します。$x$が見つかりました:

 1. 次の桁の合計を計算します。$x$。 これは変換することで行われます$x$文字列に変換し、各文字の整数値を合計します。 
2. コンピューティング$gcd(x, \text{sum of digits})$。 Pythonの組み込み`math.gcd`関数はこれを効率的に処理します。 
3. gcd が 1 より大きい場合、出力$x$このテスト ケースのループを停止します。 
4. それ以外の場合はインクリメントします$x$1 ずつ増やしてループを継続します。 
5. 次のテスト ケースに移動します。 

機能する理由: ループの不変条件は、チェックされる各数値が gcd 条件を満たすか、次の整数にインクリメントされることです。 整数は離散的で厳密に増加するため、最初の数値は`gcd(x, s(x)) > 1`最小限であることが保証されています。 アルゴリズムは常に入力を考慮します$n$それ自体なので、有効なソリューションをスキップしません。 

## Python ソリューション```python
import sys
import math
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    x = n
    while True:
        s = sum(int(d) for d in str(x))
        if math.gcd(x, s) > 1:
            print(x)
            break
        x += 1
```コードは最初にテスト ケースの数を読み取ります。 各テスト ケースについて、次のようになります。$n$からチェックを開始します$x = n$。 桁の合計は、数値の文字列表現を反復するジェネレーター式を使用して計算されます。 の`math.gcd`関数は 2 つの数値の gcd を効率的に計算します。 条件を満たしていれば印刷します$x$そしてやめてください。 それ以外の場合は増分します$x$そして続けます。 有効なため、ループは終了することが保証されています。$x$常に存在しており、すぐに見つかります。

 制約を考慮すると$t \le 10^4$そして$n \le 10^{18}$、ソリューションは 1 秒の制限内に問題なく収まります。 Python は、これらの操作で大きな整数を効率的に処理します。 

## テストケース```python
import sys, io
import math

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = io.StringIO()
    sys.stdout = output
    t = int(input())
    for _ in range(t):
        n = int(input())
        x = n
        while True:
            s = sum(int(d) for d in str(x))
            if math.gcd(x, s) > 1:
                print(x)
                break
            x += 1
    return output.getvalue().strip()

# provided samples
assert run("3\n11\n31\n75\n") == "12\n33\n75", "sample 1"

# custom cases
assert run("2\n1\n2\n") == "2\n2", "minimum values"
assert run("1\n10\n") == "12", "edge just below solution"
assert run("1\n99\n") == "99", "sum of digits gcd already >1"
assert run("1\n1000000000000000000\n") == "1000000000000000002", "large n case"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1、2 | 2、2 | 最小入力 |
 | 10 | 12 | オフバイワン増分処理 |
 | 99 | 99 | 入力自体が gcd 条件を満たします |

 ## 特殊なケース

 入力用`n = 1`、アルゴリズムがチェックします`gcd(1,1) = 1`、2に増分し、次の値を見つけます。`gcd(2,2) = 2 > 1`。 出力は正しく 2 です。`n = 10^18`、桁の合計は 1、`gcd(10^18,1) = 1`、10^18 + 1 (`gcd(10^18 + 1,1) = 1`)、その後 10^18 + 2、`gcd(10^18 + 2,2) = 2`、10^18 + 2 が正しく生成されます。Python の整数は任意の精度であるため、アルゴリズムはオーバーフローすることなく境界と大きな値を処理します。 また、入力自体が gcd 条件を満たす場合も正しく識別します。`n = 75`、入力をすぐに印刷します。
