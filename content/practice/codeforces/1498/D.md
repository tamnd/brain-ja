 ## 解決策
 ## 問題の理解

 ゼロから数字を積み上げていくプロセスをシミュレートしています。 それぞれで$n$時間ステップでは、部分的に繰り返すことができる操作が与えられます。 各操作には制限があります$y_i$、適用する回数をゼロからその制限まで選択します。 

操作には2種類あります。 現在の値を一定量増加させます$x_i$上限を適用する前に、もう一方は現在の値に次の値を乗算します。$x_i$天井を適用する前に。 上限があるため、小数の変更でも整数状態で離散的なジャンプが発生する可能性があります。 

重要な特徴は、各ステップで操作を一度だけ適用する必要はなく、連続して複数回繰り返すことができ、各繰り返しは同一であることです。 これは、各ステップが最大の「ブロック」であることを意味します。$y_i$同一の変換。 

タスクは、最終値を見つけることではなく、すべての目標値を決定することです。$1$に$m$、ゼロから開始して正確にその値に到達できる最も早い時間ステップ。 

制約は非常に重要です。 オペレーションは最大 200 件ありますが、$10^5$目標値。 これは、すべての操作シーケンスを明示的にシミュレートすることはできないことを直ちに示唆しています。 この構造は、代わりに、次の値の状態空間における最短到達可能性の問題です。$0$に$m$ここで、各層は時間ステップに対応し、各ステップは到達可能なすべての値に小さな変換グラフを適用します。 

微妙な問題は、各操作が単一の遷移ではなく、上限のある非線形関数の制限された繰り返しであるため、繰り返されるすべてのアプリケーションを単純に拡張すると爆発する可能性があることです。 

いくつかの特殊なケースが重要です。 

もし$k = 0$乗算型の演算がある場合、動作は完全に次のいずれかに依存します。$x_i > 1$。 小さな分数乗数であっても、上限後に 0 から正の整数にジャンプする可能性がありますが、繰り返し適用するとすぐに安定する可能性があります。 

加算演算の場合は、1 回$x_i < 1$、天井効果により 1 に到達するには繰り返し適用する必要がある場合がありますが、制御された増分成長のように動作します。 

単純な間違いは、各ステップを 1 つのアプリケーションとして扱うことです。 たとえば、操作で最大で許可される場合、$y_i = 3$、考えられるすべての繰り返しを考慮するのではなく、これを 1 回適用すると、中間の到達可能な状態を見逃す可能性があります。 

もう 1 つの間違いは、演算数が単調であると仮定することです。 シーリングによって離散化が導入されるため、演算を 2 回適用することは、2 倍のパラメーターを適用することと同等ではありません。 

## アプローチ

 ブルート フォース アプローチでは、各ステップの後に考えられるすべての値がシミュレートされます。 ステップで$i$、到達可能なすべての値から$k$、すべて試してみます$a \in [0, y_i]$、変換を適用します$a$回。 各アプリケーション自体は上限があるため非線形であるため、反復的に計算する必要があります。 

これにより、各ステップですべての状態のすべての値が試行される状態の拡張が行われます。 までを想定すると$m$州と$y_i$まで$m$、ステップごとの最悪の場合の遷移は次のようになります。$O(m^2)$、以上$n \le 200$これはステップが大きすぎます。 

重要な洞察は、視点を逆転させることです。 「操作を何回適用するか」を考える代わりに、各操作が値をマッピングすることを観察します。$k$までの後の可能な結果の小さなセットに$y_i$繰り返しのアプリケーション。 機能が単調なので、$k$、固定値から到達可能な値のセット$k$ステップで$i$短い増加連鎖を形成します。 

これにより、各ステップをグラフ展開として扱うことができます。現在の値ごとに、最大で到達可能なすべての値を計算します。$y_i$アプリケーションですが、値が超過すると、積極的にプルーニングします。$m$、それらを破棄することができ、繰り返し適用すると整数領域ですぐに安定するか線形になります。 

値に関しては BFS のような構造を維持しますが、タイム ステップごとに階層化されます。 各ステップで、以前に到達可能なすべての値を伝播し、現在の操作を任意の回数繰り返すことで取得できるすべての新しい値を計算します。 各ステップは独立しているため、ステップごとの遷移を伴う値に対する前方 DP のみが必要です。 

重要な最適化は、固定値からいずれかの操作を繰り返し適用すると、すぐに安定するか予測どおりに増加する厳密に増加するシーケンスを生成するため、次のいずれかが発生するまでシミュレーションするだけです。$y_i$または変化が起こらなくなるまで。

 ## アルゴリズムのチュートリアル

 配列を維持します`best[v]`最も早い時間ステップをどの値で保存するか$v$到達可能です。 また、私たちは到達可能な価値の現在のフロンティアを維持します。 

### ステップ

 1. を除くすべての値を到達不能として初期化します。$0$、時間に到達可能$0$。 

これは、操作前の開始構成を反映しています。 
2. 各時間ステップを反復します。$i$1から$n$。 

各ステップで、これまでに到達可能なすべての値を拡張します。 
3. 各値について$k$ステップの前に到達可能なもの$i$までの操作の適用をシミュレートします。$y_i$回。 

タイプ 1 の操作の場合、各アプリケーションは次のように変換します。$k$の中へ$\lceil k + x_i \rceil$。 これは単調であるため、繰り返し適用すると、安定するか超えるまで厳密に増加するシーケンスが形成されます。$m$。 

タイプ 2 の操作の場合、各アプリケーションは次のように変換します。$k$の中へ$\lceil k \cdot x_i \rceil$、これも単調増加します。$x_i > 1$。 
4. シミュレーション中に、最大で得られるすべての中間結果$y_i$アプリケーションは時間に到達可能としてマークされます$i$ただし、それより早く到達していない場合に限ります。 

最初に値に到達したときにのみ更新されるため、最も早い時間の割り当てが重要です。 
5. 以前のすべての値を処理した後、次の反復のために到達可能なセットを更新します。 
6. すべてのステップが処理されるまで続行します。 

### なぜ効果があるのか

 アルゴリズムは、ステップの処理後に不変条件を維持します。$i$、`best[v]`最小のインデックスに等しい$t \le i$そのような$v$までの操作を使用して取得できます$t$。 ステップからのすべての移行$i-1$に$i$は、現在の操作の可能なすべての有効な繰り返しを考慮するため、到達可能な値が失われることはありません。 値は最初に検出されたときにのみ更新されるため、最初のステップのプロパティが保持されます。 両方の更新ルールの単調性により、繰り返しの適用によってサイクルが発生しないことが保証されるため、ステップごとのすべての値の拡張は有限であり、明確に定義されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def apply_type1(k, x, m):
    # returns next value after one application
    return (k + x + 10**5 - 1) // 10**5

def apply_type2(k, x, m):
    return (k * x + 10**5 - 1) // 10**5

def solve():
    n, m = map(int, input().split())
    ops = []
    for _ in range(n):
        t, x, y = map(int, input().split())
        ops.append((t, x, y))

    INF = 10**9
    best = [INF] * (m + 1)
    best[0] = 0

    for i, (t, x, y) in enumerate(ops, 1):
        new_best = best[:]

        for k in range(m + 1):
            if best[k] != i - 1:
                continue

            cur = k
            for _ in range(y):
                if t == 1:
                    nxt = (cur + x + 10**5 - 1) // 10**5
                else:
                    nxt = (cur * x + 10**5 - 1) // 10**5

                if nxt > m:
                    break
                if new_best[nxt] == INF:
                    new_best[nxt] = i
                cur = nxt
                if cur == nxt:
                    break

        best = new_best

    print(" ".join(str(-1 if best[i] == INF else best[i]) for i in range(1, m + 1)))

if __name__ == "__main__":
    solve()
```このソリューションは、グローバルな最先到達配列を保持し、時間ステップに応じてレイヤーごとにそれを更新します。 重要な実装上の選択は、`best`配列に`new_best`各ステップで、ステップ内の汚染を防ぎます: ステップ内のすべての遷移$i$ステップで有効な状態から発生する必要があります$i-1$。 

内側のループオーバー$y_i$値のシーケンスは天井の丸めによりすぐに安定するため、繰り返しは安全です。 ブレーク条件により、状態の変化が停止するか超過した場合に不必要な繰り返しをシミュレートしないことが保証されます。$m$。

 ## 特殊なケース

 微妙なケースとしては、繰り返し適用するとすぐに安定する場合があります。 たとえば、次の場合$k = 1$そして$x_i$とても小さいので、$\lceil k + x_i \rceil = 2$、再度適用しても値が変わらない可能性があります。 この状況ではアルゴリズムが早期に中断され、正確性を維持しながら不必要な反復を防止します。 

もう 1 つのケースは、値が超過した場合です。$m$早い。 遷移によって上記の値が生成されると、$m$、これらの状態は出力とは無関係であるため、さらに追跡する必要はありません。 早期のブレークにより、DP が範囲外の値で汚染されることがなくなります。 

最後のケースは到達可能性の順序付けです。 同じステップ内で複数の方法で値に到達できる場合がありますが、重要なのは最初の検出のみです。 の`new_best`配列により、後の重複によって以前のタイムスタンプが上書きされず、最初のステップの要件の正確さが維持されます。
