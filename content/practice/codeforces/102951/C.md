 ## 解決策
 ## 問題の理解

 同じ要素を異なる順序で含む 2 つのシーケンス (通常は長さの 2 つの順列) が与えられます。$n$。 タスクは、値が連続している必要なく、同じ相対順序で両方の順列に現れる最も長い値のシーケンスの長さを決定することです。 

具体的には、ある棚にラベルのリストが同じ順序で配置されており、別の棚には同じラベルが再配置されていると想像してください。 左から右の順序を維持して最初の棚からいくつかのラベルを選択できますが、2 番目の棚からも同じ順序で選択できる可能な限り長いシーケンスが必要です。 

出力は単一の整数、つまりこの方法で照合できる要素の最大数です。 

解決策を推進する重要な制約は、入力が順列であること、つまり、すべての値が各配列に 1 回だけ出現することです。 と$n$あたりまで$10^5$、位置のすべてのペアを比較する二次アプローチでは、次のオーダーが必要になります。$10^{10}$最悪の場合、2 秒の実行時間で実行可能な限界をはるかに超えた操作が可能になります。 これにより、LCS を明示的に計算する動的プログラミング ソリューションが即座に除外されます。$O(n^2)$。 

いくつかのエッジな状況は、誤って対処しやすいものです。 

2 つの順列が同一の場合、たとえば次のようになります。 

入力:$A = [1, 2, 3, 4]$、$B = [1, 2, 3, 4]$シーケンス全体が一致するため、正解は 4 です。 順序ではなく位置の平等性のみをチェックする単純なアプローチはここでも機能しますが、これでは間違った解決策を誤って安心させる可能性があります。 

1 つの順列が逆の場合:

 入力:$A = [1, 2, 3, 4]$、$B = [4, 3, 2, 1]$相対的な順序を維持する 2 つの要素はないため、正解は 1 です。 インデックスの一致を前提としたり、順序付けの制約を忘れたりするソリューションは、多くの場合、ここで過大評価されます。 

もう 1 つの微妙な失敗例は、値は正しいが位置がずれている場合に発生します。 

入力:$A = [2, 3, 1, 4]$、$B = [1, 2, 3, 4]$両方の配列で順序が保持されるのは一部のサブシーケンスだけであるため、正解は 3 ではなく 2 です。 

## アプローチ

 この問題を直接考える方法は、最初の順列のすべての部分列を試し、各部分列が同じ順序で 2 番目の順列に現れるかどうかを確認することです。 これは、共通のサブシーケンスの一部である可能性のあるすべての候補シーケンスを明示的にテストするため、原理的には正しいです。 ただし、部分列の数は、$n$-要素配列は$2^n$、そして 2 番目の配列に対してそれぞれをチェックするだけでも直線的な時間がかかり、中程度の配列であっても不可能になる指数関数的な爆発につながります。$n$。 

構造上のブレークスルーは、2 番目の順列がすべての値の固定位置を定義することを認識することから生まれます。 値を直接比較する代わりに、最初の順列を、各要素が 2 番目の順列のどこに出現するかを表すインデックスのシーケンスに変換できます。 この変換が完了すると、問題の性格が完全に変わります。もはや 2 つの順列を照合するのではなく、単一のインデックス配列内で最も長く増加する部分列を見つけます。 

これが機能するのは、両方の置換で相対的な順序を保持することは、2 番目の置換で位置の昇順を保持することと同じであるためです。 最初の順列のサブシーケンスは、2 番目の順列のインデックスのシーケンスに対応し、そのサブシーケンスは、それらのインデックスが厳密に増加している場合にのみ有効です。 

LIS 問題は次のように解決できます。$O(n \log n)$二分探索による貪欲な構築を使用します。これは、以下の場合に十分効率的です。$n = 10^5$。

 | --- | --- | --- | --- |
 | ブルート フォース サブシーケンス |$O(2^n \cdot n)$|$O(n)$| 遅すぎる |

 ## アルゴリズムのチュートリアル

 ## ステップ

 1. 2 番目の順列の位置マップを構築し、各値のインデックスを保存します。 これにより、2 番目のシーケンスのどこに要素が到達するかを定数時間で検索できるようになります。 
2. 最初の順列の各要素を 2 番目の順列の対応するインデックスで置き換え、新しい位置の配列を生成します。 
3. この変換された配列の厳密に増加する最も長いサブシーケンスの長さを計算します。 
4. 配列を維持する`dp`どこ`dp[i]`長さが増加するサブシーケンスの可能な最小の終了値を格納します`i + 1`。 
5. 変換された配列内の各位置の値について、二分探索を使用して、それがどこに収まるかを見つけます。`dp`。 最長のサブシーケンスを拡張する場合は、それを追加します。 それ以外の場合は、最初の要素を置き換えます`dp`それ以上です。 
6. 最終的な長さ`dp`が答えです。 

交換ステップは、柔軟性を維持するための重要なアイデアです。 値を上書きしても`dp`、特定の長さのサブシーケンスに対して可能な限り最良の末尾のみを保持しており、特定のサブシーケンスにはコミットしません。 

### なぜ効果があるのか

 どの時点でも、`dp[k]`長さが増加するサブシーケンスの可能な最小の終了位置を表します`k + 1`。 この不変条件により、より長い増加サブシーケンスが存在する場合、常にこれらの最小の終了の上に構築できることが保証されます。 常に小さい有効な候補に置き換えるので、最適な解に拡張する可能性を失うことはなく、互換性のない要素を使用してサブシーケンスの長さを人為的に拡大することもありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from bisect import bisect_left

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    pos = [0] * (n + 1)
    for i, v in enumerate(b):
        pos[v] = i

    seq = [pos[v] for v in a]

    dp = []
    for x in seq:
        i = bisect_left(dp, x)
        if i == len(dp):
            dp.append(x)
        else:
            dp[i] = x

    print(len(dp))

if __name__ == "__main__":
    solve()
```コードの最初の部分は、最初の順列の各値を一定時間内に 2 番目の順列の位置にマッピングできるように、直接参照テーブルを構築します。 これにより、スキャンを繰り返す必要がなくなります。 

変換ステップでは、順序制約をエンコードする単一の数値シーケンスが作成されます。 これが完了すると、元の問題構造はなくなり、単調性についてのみ推論するようになります。 

LIS の計算では、二分探索による貪欲な戦略が使用されます。 の`dp`配列は実際のサブシーケンスを保存しませんが、正しい長さを回復するには十分な、各長さの可能な最小限の終了を維持します。 

## 実用的な例

 ### 例 1

 入力:$A = [2, 3, 1, 4]$、$B = [1, 2, 3, 4]$でのポジション$B$:$1 \to 0, 2 \to 1, 3 \to 2, 4 \to 3$変換されたシーケンス:$[1, 2, 0, 3]$| ステップ | × | 前の dp | |後の dp 説明 |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | [] | [1] | 新しいサブシーケンスを開始 |
 | 2 | 2 | [1] | [1、2] | 拡張子を増やす |
 | 3 | 0 | [1、2] | [0, 2] | 最初の要素を置き換える |
 | 4 | 3 | [0, 2] | [0、2、3] | 最長延長 |

 最終的な答えは 3 です。 

これは、置換によって以前の大きな値から回復し、後でさらに長いサブシーケンスを構築できることを示しています。 

### 例 2

 入力:$A = [1, 2, 3]$、$B = [3, 2, 1]$ポジション:$3 \to 0, 2 \to 1, 1 \to 2$変換済み:$[2, 1, 0]$| ステップ | × | 前の dp | |後の dp
 | --- | --- | --- | --- |
 | 1 | 2 | [] | [2] |
 | 2 | 1 | [2] | [1] |
 | 3 | 0 | [1] | [0] |

 最終的な答えは 1 です。 

これは、1 より長い増加サブシーケンスが存在しない完全に逆の順序をアルゴリズムが正しく処理していることを示しています。

 ## 特殊なケース

 単一要素の置換は、最も単純な健全性チェックです。 比較する代替構造がないため、アルゴリズムはサイズ 1 の位置マップを構築し、単一要素 LIS を生成します。 

同一の順列は、LIS 実装が不必要な置換なしで完全な増加構造を保持しているかどうかをテストします。 あらゆる要素が拡張されます`dp`したがって、長さは次のように直線的に増加します。$n$、正解と一致します。 

逆順列は、厳密な順序付け要件を強調します。 すべての新しい要素は、変換された配列の前の要素よりも小さいため、LIS 構造は長さ 1 に折りたたまれ続け、非増加シーケンスが正しく処理されることがわかります。 

混合パターンは、局所的な減少が全体的な部分配列の検出を妨げないことを確認します。 要素が分散している場合でも、置換戦略により、初期の次善の末尾が後の有効な拡張をブロックしないことが保証されます。
