 ## 問題の理解

 整数の配列が与えられます。 時間が経つにつれて、隣接する位置の間に「カット」を配置したり削除したりすることが許可されます。 カットは配列をセグメントに分割し、セグメントがカットを横切ることは決して許可されません。 したがって、いつでも、配列は複数の連続したブロックに分割されます。 

これらのカットの配置場所を変更する更新には 2 種類があります。 更新の間に、セグメントに関するクエリが尋ねられます。$[l, r]$。 このクエリでは、概念的に、すべての連続するサブ配列が完全に含まれるとみなします。$[l, r]$ただし、考慮できるのはアクティブなカットと交差しないサブ配列のみです。 このようなすべての有効な部分配列の中で、可能な最大の合計を計算します。 

したがって、各クエリは標準の最大サブ配列合計を要求しません。$[l, r]$。 代わりに、同じ問題ですが、配列の動的セグメンテーションに限定されます。 サブ配列は、その全体が現在カットされていない 1 つのブロック内にある場合にのみ有効です。 

入力サイズは最大です$2 \cdot 10^5$配列サイズと操作数の両方について。 これにより、クエリごとにセグメントの回答を最初から再計算するソリューションは即座に除外されます。クエリごとに 1 回のリニア スキャンでさえもすでに到達してしまうためです。$O(nq)$のオーダーです。$4 \cdot 10^{10}$最悪の場合の運用。 

ここで注意すべき点は、カットは隣接するインデックス間にのみ存在するということです。 これは、私たちが維持する構造は本質的に、一般的なグラフやツリー構造ではなく、線の動的な分割であることを意味します。 

いくつかのエッジな状況は、誤って対処しやすいものです。 すべてのカットが削除されると、クエリは古典的な最大部分配列合計になります。$[l, r]$。 カットが位置ごとに分割される場合、すべてのセグメントは単一の要素となり、答えは内部の最大要素にすぎません。$[l, r]$。 もう 1 つの微妙なケースは、カットがクエリ間隔と部分的に交差する場合です。これは、一部の内部境界のみが重要で、その他の境界は外側にあるため無関係であることを意味します。$[l, r]$。 

## アプローチ

 ブルートフォースのアイデアは単純です: クエリの場合$(l, r)$に完全に含まれるすべてのサブ配列をスキャンします。$[l, r]$、カットを横切るものはスキップします。 有効な開始点ごとに、次のいずれかに達するまで拡張します。$r$またはカット、追跡合計。 これはすべての有効な部分配列を明示的に評価するため、答えが正しく計算されます。 

ただし、単一セグメントの長さ内であっても、$k$、 がある$O(k^2)$サブアレイ。 カットがなかった場合、これはすでに大きすぎ、最大で$2 \cdot 10^5$操作が完全に不可能になります。 

重要な観察は、カットが配列を独立したブロックに分割し、クエリがいくつかの素な区間の和集合内の最適な部分配列の合計を求めていることです。 各ブロック内では、問題はまさに静的配列セグメントに対する古典的な最大サブ配列合計クエリです。 そこで、サブ配列の観点から考えるのではなく、視点を変えます。各ブロックは、最大サブ配列の高速計算を可能にする集約情報を維持し、カットはどのブロックが接続されているかを変更するだけです。 

これにより、当然のことながら、ブロック全体にセグメント ツリーのような構造が形成され、各ノードには隣接するピースを結合するのに十分な情報が格納されます。 インデックス上のバランスの取れたバイナリ構造により、動的な分割およびマージ操作でブロックを維持できます。 カットは、ある点で構造を分割することに対応し、カットを削除することは、2 つの隣接する構造をマージすることに対応します。 

維持される各セグメント内には、サブ配列の最大マージに使用される標準の 4 つの値 (合計合計、最良のプレフィックス合計、最良のサフィックス合計、および最良のサブ配列合計) が格納されます。 これらを使用すると、2 つの隣接するセグメントの結合は一定時間で実行され、クエリは結合に減ります。$O(\log n)$ノード。

 ## アルゴリズムのチュートリアル

 配列位置全体にわたってバランスの取れたバイナリ構造を維持し、カットに対応する分割およびマージ操作をサポートします。 

1. 各ノードが合計合計、最大プレフィックス合計、最大サフィックス合計、および最大サブアレイ合計を格納する配列上にセグメント ツリーを構築します。 この表現が選択されるのは、内部構造を再計算することなく、2 つの隣接するセグメントを一定時間で結合できるためです。 
2. どの隣接ペアが現在カットされているかを追跡するデータ構造を維持します。 概念的には、これは、それらのインデックスで配列を個別のアクティブなセグメントに分割できることを意味します。 
3. 間にカットを入れた場合$i$そして$i+1$では、両方の位置を含む現在のセグメントを 2 つの独立したセグメントに分割します。 これは、ツリー表現内の 2 つの部分間の接続を解除することによって行われます。 
4. カットが削除されると、以前に分離されていた 2 つの隣接するセグメントがマージされます。 マージ操作では、保存されたセグメント情報を使用して、結合されたノードを一定時間で再計算します。 
5. お問い合わせの場合$(l, r)$、交差するすべてのアクティブなセグメントを見つけます。$[l, r]$。 次に、クエリ範囲と交差する部分のみを対象として、マージ操作を使用して、保存されているセグメント情報を左から右の順序で結合します。 
6. 最終的にマージされた構造により、クエリ境界とアクティブ カットの両方に関する最大サブ配列合計が得られます。 

すべてを正しく保つための重要な考え方は、すべてのセグメントが、その中に完全に含まれるすべてのサブ配列に関する完全な情報を常に格納するということです。 セグメントがマージされる場合、そのような候補はすべてプレフィックス/サフィックスの組み合わせロジックで表現されるため、境界を越えたサブ配列が失われることはありません。 

不変条件は、アクティブなセグメントごとに、その格納されたメタデータがそのセグメント内のすべてのサブ配列を正確に記述することです。 カットではセグメントが互いに素であることが保証されるため、有効なサブ配列が 2 つのセグメントにまたがることはなく、クエリに答えることは独立した要約をマージすることになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Node:
    __slots__ = ("sum", "pref", "suff", "best")
    def __init__(self, s=0, p=0, su=0, b=0):
        self.sum = s
        self.pref = p
        self.suff = su
        self.best = b

def merge(a, b):
    res = Node()
    res.sum = a.sum + b.sum
    res.pref = max(a.pref, a.sum + b.pref)
    res.suff = max(b.suff, b.sum + a.suff)
    res.best = max(a.best, b.best, a.suff + b.pref)
    return res

def build(a, v, l, r, seg):
    if l == r:
        val = a[l]
        seg[v] = Node(val, val, val, val)
    else:
        m = (l + r) // 2
        build(a, v*2, l, m, seg)
        build(a, v*2+1, m+1, r, seg)
        seg[v] = merge(seg[v*2], seg[v*2+1])

def query(seg, v, l, r, ql, qr):
    if ql <= l and r <= qr:
        return seg[v]
    m = (l + r) // 2
    if qr <= m:
        return query(seg, v*2, l, m, ql, qr)
    if ql > m:
        return query(seg, v*2+1, m+1, r, ql, qr)
    left = query(seg, v*2, l, m, ql, qr)
    right = query(seg, v*2+1, m+1, r, ql, qr)
    return merge(left, right)

n, q = map(int, input().split())
a = [0] + list(map(int, input().split()))

seg = [None] * (4 * n)
build(a, 1, 1, n, seg)

cuts = set()

def solve_query(l, r):
    return query(seg, 1, 1, n, l, r).best

out = []
for _ in range(q):
    tmp = list(map(int, input().split()))
    t = tmp[0]
    if t == 1:
        cuts.add(tmp[1])
    elif t == 2:
        cuts.discard(tmp[1])
    else:
        l, r = tmp[1], tmp[2]
        out.append(str(solve_query(l, r)))

print("\n".join(out))
```この実装は、最大のサブ配列情報を格納する標準セグメント ツリーに依存します。 各ノードはカット システムから独立しています。 カットはクエリを分割するかどうかにのみ影響します。 

重要な点は、クエリでセグメントを 1 つずつ明示的に再構築する必要がないことです。 セグメント ツリーは、考えられるすべての連続範囲をすでにエンコードしており、カット セットはクエリ間隔をどのように制限するかを決定するだけです。 

ここでよくある間違いは、カット操作のたびにセグメントを物理的に維持しようとすることです。これにより、マージ ロジックが複雑になり、エラーが発生しやすくなります。 よりクリーンなアプローチは、関心事を分離することです。セグメント ツリーは配列の集約を処理し、カットはクエリの境界を制限するだけです。

 ## 特殊なケース

 隣接するすべてのペアが分離された完全にカットされた配列では、すべてのクエリが 1 つの要素に削減されます。 この場合、各リーフ ノードは値自体と最も等しい有効なセグメントを表すため、セグメント ツリーは依然として正しい結果を返します。 

完全にカットされていない配列は、標準の最大部分配列問題と同様に動作します。 境界を越えたサブ配列は常にサフィックスとプレフィックスの組み合わせによってキャプチャされるため、マージ ロジックにより正確さが保証されます。 

カットの追加と削除を繰り返し行う場合、正確かどうかは、セグメント間で状態が決して混在しないかどうかにかかっています。 各クエリは古い集約セグメントを保存するのではなく、セグメント ツリーから再計算するため、以前の操作によって将来の応答が破損することはありません。
