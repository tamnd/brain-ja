 ## 解決策
 ## 問題の理解

 文字列として書かれた数値が与えられ、それがすでに厳密な構造規則を満たしていることがわかります。 桁は、位置パリティに応じて 2 つの固定値の間で切り替わります。つまり、位置 1、3、5 などのすべての桁は同一であり、位置 2、4、6 などのすべての桁は同一です。 これら 2 つの数字は一致する可能性があるため、1111 のような定数文字列も有効です。 

タスクは、まったく同じ交互構造と同じ長さを維持しながら、指定された数値よりも厳密に大きい最小の数値を構築することです。 

重要な制約は、長さが最大 ​​100000 までであることです。これにより、単純な方法で候補を列挙したり、文字列の構築を繰り返し実行しようとするソリューションは直ちに排除されます。 有効なアプローチはどれも線形時間で機能する必要があります。重い定数を含む O(n log n) であっても許容されますが、二次関数は遅すぎるためです。 

単純な解釈では、数値を標準の整数として扱い、それを増分し、結果が交互の制約を満たしているかどうかを確認することになります。 このアプローチは 2 つの点ですぐに破綻します。 まず、大きな文字列ベースの数値を繰り返しインクリメントすることは、操作ごとに線形であり、何度も繰り返される可能性があります。 第 2 に、ほとんどの増分は交互構造に違反する数値を生成するため、無効な候補をチェックするのに無駄な労力を費やすことになります。 

長さ n の有効な数値をすべて辞書順に生成しようとすると、より微妙な失敗モードが発生します。 有効な数値はそれぞれ 2 桁のみで決定されますが、考えられる桁のペアは 100 通りあり、それらすべてを元の数値と比較すると O(100 · n) にまで低下する可能性がありますが、これは問題ありませんが、慎重に実行した場合に限ります。 本当の問題は、構造化された移行ルールがないと、大きな文字列を繰り返し再構築する危険性があることです。 

## アプローチ

 数字の構造により、問題全体は 2 つの数字 (奇数の位置に 1 つと偶数の位置に 1 つ) を選択することになります。 これらを A と B とします。その後、奇数のインデックスで A を繰り返し、偶数のインデックスで B を繰り返すことによって、数値が完全に決定されます。 

ブルートフォース手法は、指定された数値を (A, B) として解釈し、辞書編集上の昇順ですべての可能なペア (A', B') を試し、対応する交互の数値を構築し、元の数値よりも厳密に大きい最初の数値を返すことになります。 すべての有効な数値がそのようなペアの 1 つに正確に対応するため、これは正しいです。 

ただし、構築コストは候補あたり O(n) で、ペア数は最大 100 なので、O(100n) になります。 これは通るかもしれませんが、不必要に無駄であり、ペア間の順序付けの構造がわかりにくくなります。 

重要な観察は、2 つの交互する数値の比較は、それらが異なる最初の位置のみに依存するということです。 パリティは固定されているため、辞書順に 1 位と 2 位に配置された数字を繰り返してペアを比較できます。 これは、元の文字列によって定義された特定の誘導順序の下で、辞書編集的に次に大きいペア (A、B) を見つけることとして問題を処理できることを意味します。 

すべてのペアを列挙する代わりに、暗黙的なペア表現で「次の順列」のアイデアを直接シミュレートできます。 文字列の末尾からスキャンして、パリティ制約との一貫性を保ちながら桁を増やせる位置を探し、サフィックスを最小限に再構築します。 

これにより、問題は、各位置で少数の一定数の変更候補をチェックするだけになります。

 ## アルゴリズムのチュートリアル

 この数値は、0 から始まる交互の位置として扱われます。

1. 数字パターンを抽出します。すべての偶数インデックスは 1 つの数字を共有し、すべての奇数インデックスは別の数字を共有する必要があります。 これらを入力から A および B として読み取ります。 これにより、現在の構成が得られます。 
2. 構造を維持しながら数を増やす方法を見つけようとします。 初期の位置を増やすと、後で変更するよりも大きな数値が得られるため、位置を右から左にスキャンして、安全に桁を増やすことができる右端の位置を見つけます。 
3. 各候補位置 i について、パリティに応じて、それが A によって制御されるか B によって制御されるかを決定します。 その桁を可能な限り小さい上位の桁まで増やそうとします。 
4. 位置 i の桁を増やすと、それ以前の位置はすべて固定されたままになります。 i 以降のすべての位置について、交互構造と一致する最小の接尾辞を構築する必要があります。 これは、残りの各位置をパリティと一致する最小許容値 A または B のいずれかに設定しますが、すでに固定されている選択された桁を尊重することを意味します。 
5. 右から左への最初の成功した変更により最小性が保証されるため、結果の文字列を構築してすぐに返します。 

### なぜ効果があるのか

 このアルゴリズムは、辞書編集的な順序付けの位置優位特性に依存しています。 より重要なインデックスでの変更は、重要でないインデックスでの変更よりも厳密に大きな数値を生成します。 最後からスキャンすることで、増加を許可する最も重要性の低い位置のみを変更することが保証されます。 その位置が最小限に増加したら、サフィックスを貪欲に埋めることで、それ以上不必要な増加が発生しないようにします。 これは次の辞書順列のロジックを反映していますが、2 値の周期構造に制限されています。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    s = input().strip()

    # Try all positions from right to left
    for i in range(n - 1, -1, -1):
        cur = ord(s[i]) - ord('0')

        # try increasing this digit
        for nd in range(cur + 1, 10):
            # build candidate
            res = list(s[:i] + chr(ord('0') + nd))

            # fill suffix respecting alternating structure
            for j in range(i + 1, n):
                if j % 2 == 0:
                    res.append(res[0])  # even index uses first position's digit
                else:
                    res.append(res[1])  # odd index uses second position's digit

            cand = "".join(res)

            if cand > s:
                print(cand)
                return

    # fallback (theoretically unnecessary for valid inputs)
    print(s)

if __name__ == "__main__":
    solve()
```コードは、可能な限り右端の数字を増やし、最小の一貫した方法でサフィックスを再構築しようとします。 接尾辞の構築では、接頭辞が固定されると構造の残りの部分が決定的になるという事実に基づいて、交互規則を直接使用します。 

微妙な点は、既に選択されている接頭辞の数字を使用して接尾辞が埋められることです。 これにより、元の A と B を個別に追跡することなく、交互制約との一貫性が確保されます。

 ## 特殊なケース

 重要なエッジ ケースは、文字列全体が、以前の構造に影響を与えずに増やすことが不可能な位置に 9 で構成されている場合です。 たとえば、99999 のようなパターンは、複数の位置を変更しないと増やすことができません。 アルゴリズムは、右から左にスキャンすることでこれを処理し、最終的に有効な増分が見つからない場合、フォールバックとして元の文字列を返します。 

もう 1 つのエッジ ケースは、最適な変更が文字列の先頭近くで発生する場合です。 このような場合、サフィックスの再構築は最小限の完了を保証し、常に最も早い有効な増加ポイントから再構築することにより、不正確で必要以上に大きな結果が生じることを防ぎます。
