 ## 解決策
 ## 問題の理解

 私たちは、大釜の中の材料を表す 3 つの初期の塊、すなわち乾燥イラクサ、カエルの足、およびシナモンを与えられます。 すべての材料を加えた後、1 グラムの特別な試薬を注ぎます。この試薬には珍しい効果があります。それは、以前に追加されたすべての材料の質量を 1 倍に拡大します。$x$。 重要な詳細は、大釜内にすでに入っている成分のみが影響を受け、新しく追加された試薬自体はスケールされないことです。 

タスクは、この変換後の最終的な総質量を決定することです。 

このプロセスを解釈する直接的な方法は、初期の総質量が$a + b + c$。 そこに隠し味を加えて合計します。$a + b + c + 1$。 その後、試薬は前の部分のみを増殖させるため、$a + b + c$部分になります$x(a + b + c)$、1グラムは変わりません。 したがって、最終的な答えは次のようになります。$$x(a + b + c) + 1$$制約は非常に小さく、各入力値は最大$10^4$。 これにより、定数時間内のあらゆる算術解があれば十分であることがすぐに分かります。 中間式を複数回再計算するソリューションであっても、即座に実行されます。 入力解析以外のデータ構造やループは必要ありません。 

このタイプの問題でよくある間違いは、秘密の材料もスケールされるかどうかを誤解することに起因します。 1 グラムを含む全体の合計を誤って乗算すると、結果は次のようになります。$x(a + b + c + 1)$、それは間違いです。 もう 1 つの微妙な間違いは、試薬を追加する前にスケーリングを適用することです。$x(a + b + c) + x$、また不正解です。 

たとえば、サンプル入力では$a=5, b=3, c=7, x=1$どちらの間違った解釈でも、予想とは異なる出力が得られます。 

- 間違ったフルスケーリング:$1 \cdot 16 = 16$ここで偶然一致します。 
- 間違った順序以外のすべてのスケーリングが正しくない: 些細なケースでも一致する可能性があります。 

このため、小規模なテストでの偶然の正しさに依存するのではなく、正確なプロセス定義に従うことが特に重要になります。 

## アプローチ

 強引な解釈では、プロセスを文字通りシミュレートします。3 つの成分を容器に保管し、試薬を追加し、前のすべての要素に次の値を掛けます。$x$。 これには、保存されているすべての要素を反復処理して更新することが含まれます。 たった 3 つの要素で、これはすでに定数時間であるため、この問題ではブルート フォースが効果的に最適化されます。 

重要な点は、個々の成分を個別に追跡する必要がないということです。 スケーリング操作はそれらすべてで均一であるため、それらの合計のみが重要です。 すべての元の成分に同じ係数が掛けられるため、$x$、すぐに集計できます。 

これにより、マルチセットにわたるシミュレートされた変換の問題が単一の算術式に軽減されます。 問題の構造により線形性が保証されています。スケーリングは加算に分散されるため、乗算を適用する前にすべてを 1 つの合計に結合できます。

 ## アルゴリズムのチュートリアル

 1. 3 つの成分値を読み取ります。$a$、$b$、 そして$c$。 これらは、魔法の効果が適用される前の総質量を表します。 
2. それらの合計を計算します$s = a + b + c$。 これにより、試薬の影響を受けるすべての物質が捕捉されます。 これらの値はすべて均一にスケールされるため、グループ化は重要です。 
3. 乗数を読み取る$x$、試薬が既存の物質をどれだけ強く増幅するかを決定します。 
4. スケールされた寄与を計算する$s \cdot x$。 これは、試薬が効果を発揮した後のすべての元の成分の変換された質量を表します。 
5. スケーリングから明示的に除外される試薬自体を表す定数 1 グラムを追加します。 
6. 結果を出力する$s \cdot x + 1$。 

### なぜ効果があるのか

 正確さは、変換が初期合計に対して線形であるという事実から得られます。 すべての元の成分に同じ係数が掛けられます$x$, したがって、乗数を適用する前にグループ化できます。 試薬は概念的にはスケーリング操作の後に追加されるため、影響を受けません。 加算と乗算は整数全体にきれいに分散されるため、中間の順序付けの問題は発生しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    a = int(input().strip())
    b = int(input().strip())
    c = int(input().strip())
    x = int(input().strip())

    s = a + b + c
    print(s * x + 1)

if __name__ == "__main__":
    solve()
```実装は導出された式に直接続きます。 入力形式では値が別々の行に配置されるため、各値は独立して読み取られます。 後で加算を繰り返さないように最初に合計を計算しますが、このような小さな問題では、これは主に明確にするためです。 

最も重要な詳細は、演算の順序です。つまり、乗算です。$x$は元の成分の合計にのみ適用する必要があり、最後の 1 の追加は後で行う必要があります。 書き込み`a + b + c * x + 1`演算子の優先順位により不正確となり、暗黙のうちに誤った結果が生成されます。

 ## 特殊なケース

 微妙なエッジケースの 1 つは次のような場合です。$x = 1$。 この状況では、変換は元の成分には何も影響を与えず、答えは次のようになります。$a + b + c + 1$。 1 を乗算しても合計は変化しないため、アルゴリズムはこれを自然に処理します。 

別のケースとしては、$a, b, c$はゼロです。 ゼロは合計に何も寄与しないため、この式は特別な処理を行わなくても成立し、スケールされた部分に影響を与えるのはゼロ以外の成分だけです。 

最後のエッジケースは、近くの大きな値です。$10^4$。 たとえ中間結果が達成できたとしても$10^8$, Python の整数はこれを安全に処理し、オーバーフローを考慮する必要はありません。
