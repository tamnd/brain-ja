 ## 解決策
 ## 問題の理解

 個別の整数の配列が与えられ、連続するセグメントを 1 つだけ選択して、それを反転することができます。 タスクは、反転によって配列全体が厳密に増加するシーケンスになるセグメントが存在するかどうかを判断し、存在する場合はそのようなセグメントを 1 つ出力することです。 

入力は、単純に配列の長さに配列自体が続くものです。 出力は、セグメント境界とともにそれが可能であることを確認するか、単一の反転では配列をソートできないというステートメントです。 

主要な構造上の制約は、配列サイズが最大 100,000 になる可能性があるため、考えられるすべてのセグメントを試行するソリューションは直ちに実行不可能であることです。 単純な O(n³) または O(n²) のアプローチでもタイムアウトになり、O(n²) の反転シミュレーションでさえ、繰り返し実行すると遅すぎます。 これにより、ほぼソートされた配列の構造特性に基づいて、O(n) または O(n log n) の推論が必要になります。 

配列がすでにソートされている場合、微妙なエッジケースが発生します。 この場合、長さ 1 のセグメントの反転は有効であり、受け入れられる必要があります。 もう 1 つの重要な例外ケースは、ソートされていない部分が非常に小さい場合です。たとえば、次のような単一の反転です。`[2, 1, 3, 4]`、スワップに相当するセグメントが 1 つだけ存在します。 最後に、配列がローカルで「ほぼソートされている」ように見えても、1 回の反転では修正できない場合があります。`[3, 1, 2, 4]`、反転すると注文の他の部分が混乱します。 

## アプローチ

 ブルートフォース戦略は、考えられるすべてのインデックスのペアを試すことです`l, r`、そのセグメントを反転し、配列がソートされるかどうかを確認します。 各チェックには O(n) が必要で、O(n²) 個のセグメントがあり、全体で O(n³) になります。 事前計算を使用してチェックを最適化しても、候補の 2 次数は削除されないため、n = 100,000 では遅すぎます。 

重要な洞察は、「すべての反転を試す」から「有効な反転がどのようなものであるかを特徴付ける」ことに移行することです。 セグメントを反転することで配列がソートされる場合、そのセグメントの外側では配列がすでに正しい順序でソートされている必要があります。 セグメント内では、ソートされた配列に対して順序が正確に逆になっている必要があります。つまり、セグメントは元の配列内で厳密に減少しているように見える必要があります。 

これは構造的な観察につながります。解が存在する場合、配列はちょうど 1 つの連続したブロックでソートされたバージョンと異なり、そのブロックは厳密に減少しています。 そのブロックの外側では、配列はソートされた順序とすでに一致している必要があります。 

したがって、操作を試行する代わりに、配列をソートされたバージョンと比較し、不一致の境界を特定します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (すべてのセグメントを試す) | O(n3) | お(1) | 遅すぎる |
 | 並べ替え + 単一セグメント検証と比較 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 並べ替えられた配列のコピーを作成します。 これは、反転が成功した後のターゲットの最終構成を表します。 
2. 最初のインデックスを見つける`l`ここで、元の配列はソートされた配列とは異なります。 これは、それ以前のすべてがすでに正しいため、反転セグメントに含める必要がある最も古い位置です。 
3. 最後のインデックスを見つける`r`ここで、元の配列はソートされた配列とは異なります。 これは、それ以降のすべてがすでに正しいため、反転する必要があるセグメントの最も遠い境界です。 
4. サブ配列を元に戻す`l`に`r`元の配列のコピーにあります。 
5. この変更された配列がソートされた配列と正確に一致するかどうかを確認します。 存在する場合、セグメントは`[l, r]`有効です。 そうしないと、一度の反転で配列を修正できなくなります。 

この単一の候補セグメントに安全に焦点を当てることができる理由は、有効な解は配列とそのソートされたバージョンの間の不一致間隔と正確に一致する必要があるためです。 有効な反転が存在するが、この間隔と異なる場合は、不一致の外側の部分が変更されていることを意味し、他の場所でソート順序が即座に破壊されます。 

### なぜ効果があるのか

 正確かどうかは、1 回の反転による並べ替えでは、反転されたセグメントの外側に正しく順序付けされた新しい要素を導入できないという事実にかかっています。 選択したセグメントの外側のすべての位置は固定されたままになります。 したがって、ソートされた配列に既に一致するすべての位置はセグメントの外側にある必要があり、すべての不一致はセグメントの内側にある必要があります。 これにより、反転されたセグメントが、すべての不一致をカバーする連続した区間になります。 この間隔が決定されると、テストする反転候補は 1 つだけになり、それが有効か無効かのどちらかになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    b = sorted(a)

    l = 0
    while l < n and a[l] == b[l]:
        l += 1

    if l == n:
        print("yes")
        print(1, 1)
        return

    r = n - 1
    while r >= 0 and a[r] == b[r]:
        r -= 1

    segment = a[:]
    segment[l:r+1] = reversed(segment[l:r+1])

    if segment == b:
        print("yes")
        print(l + 1, r + 1)
    else:
        print("no")

if __name__ == "__main__":
    solve()
```このコードは、まずソートされた参照配列を構築し、次に最初と最後の不一致位置を分離します。 これらのインデックスは、配列を修正できる唯一の妥当なセグメントを定義します。 有効な解はこの不一致ウィンドウと一致する必要があるため、コピー内のそのセグメントを反転するだけで十分です。 

よくある間違いは、グローバルな一貫性を検証せずに、減少するセグメントが有効であると想定することです。 ローカルの単調性ではセグメント外の正確性が保証されないため、ソートされた配列に対する最終的な等価性チェックが不可欠です。 

## 実用的な例

 ### 例 1

 入力:```
3
3 2 1
```ソートされた配列は`[1, 2, 3]`。 最初の不一致はインデックス 0 にあり、最後の不一致はインデックス 2 にあります。 

| ステップ | l | r | 逆引き後の配列 |
 | --- | --- | --- | --- |
 | イニシャル | 0 | 2 | 3 2 1 |
 | 逆 | 0 | 2 | 1 2 3 |

 反転後、配列はソートされたバージョンと一致するため、答えは次のようになります。`yes 1 3`。 

これにより、配列全体が厳密に減少している場合に反転できることが確認されます。 

### 例 2

 入力:```
4
3 1 2 4
```ソートされた配列は`[1 2 3 4]`。 不一致間隔はインデックス 0 から 2 までです。 

| ステップ | l | r | 逆引き後の配列 |
 | --- | --- | --- | --- |
 | イニシャル | 0 | 2 | 3 1 2 4 |
 | 逆 | 0 | 2 | 2 1 3 4 |

 結果はソートされていないため、単一の反転は機能しません。 

これは、すべての不一致が連続している場合でも、反転後に内部構造が完全に整列している必要があることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | 並べ替えが優先され、他のすべての操作は線形です。 
| スペース | O(n) | ソートされたコピー用の追加の配列 |

 この規模では並べ替えと 1 回のスキャンの両方が効率的であるため、これは最大 100,000 までの n の制約内に問題なく収まります。

 ## 特殊なケース

 配列がすでにソートされている場合、不一致間隔は空であり、アルゴリズムはそれを自明な有効なケースとして扱います。 戻る`[1, 1]`長さ 1 のセグメントを反転すると配列は変更されないままになるため、これは正しいです。 

配列が完全に減少している場合、不一致間隔は配列全体に及びます。 これを逆にすると、完全に増加するシーケンスが生成され、ソートされた配列に対するチェックによって正確さが確認されます。 

不一致によって連続ブロックが形成されるが、内部構造が厳密には反転されていない場合。`[3, 1, 2, 4]`の場合でも、アルゴリズムは正しい間隔を選択しますが、最終検証は失敗します。 これにより、配列をグローバルに並べ替えることができない部分的な反転が誤って受け入れられるのを防ぎます。
