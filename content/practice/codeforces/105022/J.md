 ## 解決策
 ## 問題の理解

 数字のみで構成される文字列が与えられます`1`そして`2`、限られた予算のコインを使用して変更することが許可されています。 目標は、この文字列を辞書順で可能な限り小さい数値に変換することです。つまり、できるだけ多くの数値が必要です。`1`s を可能な限り先頭に配置し、同じプレフィックスの中で、前の位置をできるだけ小さくする必要があります。 

操作には 2 種類あります。 任意の位置をどちらかの数字で上書きできます`1`または数字`2`、書き込む桁に応じて固定コストを支払います。 また、インデックス距離に等しいコストを支払って、任意の 2 つの位置を交換することもできます。 予算`K`すべての操作の総コストを制限します。 

主な問題点は、スワップが固定コスト 1 のローカル隣接スワップではなく、コストが距離に依存する任意の長距離スワップであることです。 これにより、問題は重み付けされた制約による並べ替えと選択的な書き換えの組み合わせのように感じられます。 

制約は私たちを`O(N log N)`または`O(N)`解決。 と`N`最大200,000および`K`10^9 までは、二次ペアリングや流れの定式化は不可能です。 平`O(N^2)`ポジションの貪欲なマッチングが大きすぎます。 

素朴な解釈では、文字列をソートするためにスワップをシミュレートするか、プレフィックスと残りのバジェットに対して動的プログラミングを試行することになります。 どちらも失敗するのは、国家がポジションの取り決めと残りのコインの両方を追跡する必要があり、それが大きすぎるためです。 

いくつかの微妙なエッジケースは、貪欲なローカル推論が失敗する理由を明らかにします。 文字列がすでにほとんどの場合`1`ほんの少しだけ`2`が早く出現した場合、単純な戦略では、それらを遠いものと交換しようとする可能性があります。`1`ただし、ロング スワップのコストは、単純に数字を上書きするコストを超える可能性があります。 逆に、ポジションが近いためにスワップが安い場合は、書き換えが無駄になる可能性があります。 スワップ距離のコストと上書きコストの間のトレードオフが中心的な緊張関係です。 

## アプローチ

 ブルートフォースのアイデアは、操作のすべてのシーケンスを考慮することです。どの位置を書き換えるか、どのペアを交換するか、およびその順序を選択します。 順序の問題を無視し、最初に順列にスワップしてから書き換えると仮定しても、依然として予算内でスワップと置換のサブセットを選択していることになります。 すべての位置のペアを交換することも交換しないこともでき、すべての位置を 2 つの方法で書き換えることもできるため、可能性の数は指数関数的に増加します。 これは非常に小さいものを超えると完全に実行不可能です`N`。 

重要な観察は、スワップは値ではなく順序のみを変更し、そのコストは最終的なペアリングの距離のみに依存するということです。 スワップをインデックスを並べ替える方法として解釈すると、あらゆる並べ替えをスワップに分解でき、並べ替えを実現するための最小コストはその反転のようなコスト構造になります。 ただし、この問題では、任意の並べ替えは必要ありません。 辞書編集上最小限の文字列を生成することだけを考慮します。つまり、プッシュしたいということです。`1`できるだけ左にあります。 

これにより、問題はどのポジションになるかを選択することに変わります。`1`最後の文字列で。 最終的に次のようなポジションのセットを決定したら、`1`、最適な配置は、左端の可能な位置に昇順に配置することです。 これを実現するためのコストは、オリジナルのマッチングに依存します`1`s、そしておそらく変換する`2`に入る`1`上書き操作の使用に加えて移動コストもかかる`1`再書き込みではなく再配置することを選択した場合は、スワップを介して。 

重要な単純化は、`1`位置: すでに`1`スワップを使用してそこに移動するか、現在の数字を次のように変換します。`1`リライトコストを使用する`c1`。 同様に、`1`に`2`によって統治されています`c2`。 ターゲットは辞書編集的に最小限であるため、余分なものは必要ありません`2`早いので、支配的な決定は何人かです`1`■最小限のコストでフロントに配置できます。 

これは既存のペアリングに帰着します`1`ターゲットのプレフィックス位置を順番に並べます。 最適な戦略は貪欲です。左から右にスキャンして、各位置が次のようになることを確認します。`1`そのままにしておくより安ければ`2`、近くの未使用のいずれかを使用します`1`スワップまたは直接上書きを介して。 スワップは、既存のものを移動する場合にのみ役立ちます。`1`その位置に新しいものを作成するよりも安価です。 

したがって、利用可能な状態を維持します`1`距離コストと書き換えコストに基づいて、常に最も安価なソースが優先されます。

 ## 段階的なプロセス

### なぜ効果があるのか

 あらゆる位置で、「既存の使用可能なもの」間のローカル割り当て問題を解決しています。`1`「ソース」と「必要なプレフィックス スロット」。スワップ コストは距離に応じて直線的に増加するため、貪欲な選択は有効であり、貪欲でないペアリングは総移動距離が増加するか、後で追加の書き換えを強制することになります。これにより単調な構造が作成されます。前の位置は常に後の位置よりも安いか同等であるため、割り当てを遅らせてもコストが向上することはありません。不変条件は、位置の処理後であるということです。`i`、プレフィックスに関するすべての決定`[0, i]`残りの未使用を考慮するとコスト的に最適です`1`ソース。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    N, K, c1, c2 = map(int, input().split())
    s = list(input().strip())

    ones = [i for i, ch in enumerate(s) if ch == '1']
    used = [False] * N

    ptr = 0
    res = ['2'] * N

    for i in range(N):
        if ptr < len(ones):
            j = ones[ptr]
            cost_swap = abs(i - j)
            if cost_swap <= c1:
                res[i] = '1'
                used[j] = True
                ptr += 1
            else:
                if c1 <= c2:
                    res[i] = '1'
                else:
                    res[i] = '2'
        else:
            if c1 <= c2:
                res[i] = '1'
            else:
                res[i] = '2'

    print("".join(res))

if __name__ == "__main__":
    solve()
```実装ではまず、次のすべての位置を収集します。`1`これにより、それらを再利用可能なリソースとして扱うことができます。 ポインタ`ptr`常に最も近くにある未使用のものを消費するようにします`1`この順序は、先ほどの貪欲な仮定と一致します。`1`は、より早い段階での目標ポジションを提供する必要があります。 

ポジションごとに、スワップコストと書き換えコストを比較します。`c1`。 スワップの方が安い場合は、それを割り当てます`1`現在の位置に。 それ以外の場合は、有益であれば直接上書きします。 変数`used`オリジナルの消費を反映するために含まれています`1`ただし、ポインタは単調な消費によってすでに正確さを保証しています。 

微妙な詳細は、`c2`重要なのは、その職を離れることを好むかどうかを決定する場合のみです。`2`または変換しますが、最終的な目標は辞書編集的に最小限であるため、比較するだけです。`c1`スワップを使用しない場合。
