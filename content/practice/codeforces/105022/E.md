 ## 解決策
 ## 問題の理解

 一連の計画された旅行が与えられ、それぞれに開始時刻と終了時刻が指定されています。 チャドはこれらの旅行を指定された順序で実行します。 重要な仕組みは、彼が以前の遅れた旅行を終えるのにまだ忙しい間に旅行が始まった場合、その旅行は元の時間に開始されないということです。 代わりに、それは前に押し出され、まさに彼が自由になったときに始まります。 

この連鎖効果により、後続の旅行が元々重なっていない場合でも、遅れて長い旅行が発生すると、後続のすべての旅行に遅延が伝播する可能性があります。 

チャドは出発前に K 回までの旅行をキャンセルできます。 残りの旅行は元の相対的な順序で処理され、同じ遅延ルールが適用されます。 

目標は、遅延伝播ルールを使用して残りのスケジュールを処理した後、最終的な終了時間ができるだけ短くなるように、最大​​ K 個のトリップを削除するかを選択することです。 

出力は単一の値、つまり残りのすべての移動が完了する最も早い時刻です。 

N ≤ 4000 という制約は、O(N²) または O(N²K) 動的プログラミング ソリューションが受け入れられることを強く示唆しています。 すべてのサブセットを考慮したり、すべてのキャンセルを直接シミュレートしたりする 3 次またはそれより悪いアプローチは、サブセットの数が指数関数的に増加するため実行できません。 小さな削除バジェットとしての K の存在は、通常、プレフィックスと削除に対する DP を示します。 

貪欲な直感を働かせると、微妙な失敗例が現れます。 たとえば、最大の即時遅延を引き起こすトリップを常に削除すると、失敗する可能性があります。これは、初期の小さなオーバーラップを削除することで、後でより大きなコストがかかるカスケードを防ぐことができるためです。 遅延の伝播が将来のすべての決定を結合するため、キャンセルが間隔ごとに独立して決定できると仮定すると、別の失敗が発生します。 

具体的な問題のパターンは次のとおりです。 

入力:```
3 1
1 10
2 3
3 4
```最初のインターバルが広いので外すと早く終わってしまいます。 しかし、代わりに小さな間隔の 1 つを削除すると、重なりの構造は異なった変化をします。 正しい解決策は、ローカルな間隔コストではなく、グローバルな相互作用に依存します。 

## アプローチ

 強引なアプローチは、少なくとも N-K 回の旅行のすべてのサブセットを試し、各サブセットのスケジュールをシミュレートし、その結果の終了時間を計算することです。 サブセットごとに、残りのトリップを並べ替えたり反復処理したりして、線形時間で伝播ルールを適用します。 これにより、およそ O(2^N · N) の動作が行われますが、これは 4000 どころか、N = 40 の場合でも完全に実行不可能です。 

重要な点は、プロセスが基本的に逐次的であるということです。 旅行のサブセットを修正すると、結果として得られるスケジュールは決定的になります。単に前方をシミュレートして完了時間を累積するだけです。 これは、ソートされたシーケンスのプレフィックスと使用される削除の数に対する動的プログラミングを示唆しています。 

この問題を次のように再解釈します。旅行を順番に処理し、各ステップで旅行を保持する (必要に応じて現在の時刻を延長する) か、削除する (K 個の削除のうち 1 つを消費する) かを決定します。 難しいのは、旅行を維持するとその期間が追加されるだけでなく、max(current_time, s_i) + (e_i - s_i) を介して現在時刻と相互作用することです。 この依存関係により、状態遷移を注意深く構造化しない限り、単純な DP では不十分になります。 

常に遷移をシミュレートすることで現在の完了時間を暗黙的に繰り越しながら、インデックスと削除に対して DP を定義すると、正しい構造が現れます。 N は十分に小さいため、DP 状態を「最初の i 個のトリップを処理し、そのうち j 個を削除した後の可能な限り最良の完了時間」として扱うことができますが、前の状態からの実行可能な時間遷移のみを伝播することによって正確性を保証する必要もあります。 

これにより、時間の直接シミュレーションを使用して、スキップまたは移動することによって各状態が次のインデックスに拡張される階層化された DP が得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース サブセット | O(2^N・N) | O(N) | 遅すぎる |
 | DP over プレフィックスと削除 | O(N²K) または O(NK) の最適化 | O(NK) | 承認済み |

 ## アルゴリズムのチュートリアル

 最初の i 個の旅行を考慮し、それらのうちちょうど j 個をキャンセルした後の、dp[i][j] が可能な限り最も早い完了時間を表す DP テーブルを維持します。 

1. トリップの前に時間 0 で終了しているため、dp[0][0] = 0 を初期化します。他のすべての状態はまだ到達できないため、無限大に設定されます。 
2. 1 から N までの順序でトリップを繰り返します。各トリップ (s_i, e_i) について、その期間を d_i = e_i - s_i として計算します。 この分離により、遅延ルールをきれいに適用できるようになります。 
3. 各 dp[i-1][j] について、2 つの遷移を考慮します。 
4. 最初の遷移はキャンセルです。 旅行 i をキャンセルすると、現在時刻を変更せずに dp[i-1][j] から dp[i][j+1] に移動します。 これは、旅行を完全にスキップし、1 回のキャンセルを消費するモデルです。 
5. 2 番目の移行はトリップを維持することです。 このままにすると、予定された開始時間後に到着するか開始するまで待機するため、実際の開始時間は max(dp[i-1][j], s_i) になります。 終了時間は max(dp[i-1][j], s_i) + d_i となり、それに応じて dp[i][j] を更新します。 
6. すべての遷移を処理した後、最大で K 個のキャンセルを使用できるため、答えはすべての j ≤ K にわたる最小 dp[N][j] になります。 

重要な点は、dp が実際の時間値を格納するため、遅延伝播が個別にシミュレートされるのではなく、遷移内で暗黙的にエンコードされることです。 

### なぜ効果があるのか

すべてのステップ i で、dp[i][j] は、最初の i 回の旅行のうち正確に j 個のキャンセルを使用して、達成可能な最良の完了時間を取得します。 最初の i 回の旅行における有効なスケジュールは、旅行ごとに削除するか処理するかを決定することで作成できます。 トリップを維持するための遷移は、遅延伝播の下での現実世界の時間の変化と正確に一致します。これは、どの瞬間のシステム状態も現在の完了時間によって完全に記述されるためです。 追加の履歴は必要ありません。 したがって、すべての有効なスケジュールが DP で表され、最終状態に対する最小値が最適になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    N, K = map(int, input().split())
    trips = [tuple(map(int, input().split())) for _ in range(N)]
    
    INF = 10**30
    dp = [[INF] * (K + 1) for _ in range(N + 1)]
    dp[0][0] = 0

    for i in range(1, N + 1):
        s, e = trips[i - 1]
        d = e - s

        for j in range(K + 1):
            if dp[i - 1][j] == INF:
                continue

            cur = dp[i - 1][j]

            # skip
            if j + 1 <= K:
                dp[i][j + 1] = min(dp[i][j + 1], cur)

            # take
            start = cur if cur > s else s
            finish = start + d
            dp[i][j] = min(dp[i][j], finish)

    print(min(dp[N]))

if __name__ == "__main__":
    solve()
```DP テーブルは行ごとに構築され、各行は旅行のプレフィックスを処理したことに対応します。 スキップ遷移により、時間に影響を与えることなく削除数が増加します。 テイク トランジションは、必要に応じてトリップの開始を待機し、その期間を追加することを明示的にモデル化します。 

よくある落とし穴は、開始時間が現在の累積時間に依存することを忘れることです。 期間を計算する代わりに e_i を直接使用すると、遅延によってスケジュール全体が変化するため、正確さが失われます。 

もう 1 つの微妙な点は、「最大 K」の削除を許可することです。これは、j = K を強制するのではなく、すべての dp[N][j] の最小値を取ることで処理されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(NK) | 各状態は、旅行ごとに 2 つの選択肢を介して遷移します。 
| スペース | O(NK) | DP テーブルはすべてのプレフィックスと削除の状態を保存します。 

N ≤ 4000 の場合、これは約 1,600 万の状態となり、最適化されたループを使用する Python に快適に適合します。

 ## 特殊なケース

 特殊なケースの 1 つは、すべての旅行が重なり合う場合です。 例えば：```
3 1
1 10
2 11
3 12
```キャンセルなしでシミュレーションすると、完全伝播により最終時間は 12 になります。 DP は、可能な各間隔のスキップを正しく評価し、最初のトリップを削除すると、最初の大きなアンカーがすべてを前方に押し出すのを防ぐため、はるかに小さいチェーンが生成されることがわかります。 

もう 1 つのエッジ ケースは、K = 0 の場合です。この場合、DP はすべてのトリップが実行される単一のシミュレーション パスに縮退します。 すべてのスキップ遷移が無効になっているため、アルゴリズムはこれを自然に処理します。 

最後のエッジケースは、キャンセルが大きくて長いアンカーをすべて削除する場合です。 DP は、すべてのプレフィックス状態が取得とスキップの両方を独立して考慮するため、組み合わせを正しく探索し、明示的なサブセット列挙を必要とせずにサイズ N-K の最適なサブセットが確実に出現するようにします。
