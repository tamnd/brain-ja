 ## 問題の理解

 いくつかの独立したテスト ケースが与えられています。 各テスト ケースには、都市の人口を表す個別の正の整数のリストがあります。 インデックスの順序付けされたトリプルをカウントする必要があります$(i, j, k)$非常に具体的な算術関係が、選択された 3 つの値の間に保持されるようにします。 

値を次のように表すと、$a_i, a_j, a_k$の場合、最初の 2 つの値の最大公約数が最後の 2 つの値の最小公倍数に等しいことが条件となります。 つまり、両者の間に共有される「分裂構造」が、$a_i$そして$a_j$の乗算構造を組み合わせたものと正確に一致する必要があります。$a_j$そして$a_k$。 

重要な点は、すべての値は異なるものですが、インデックスはトリプル間で役割を繰り返すことができるため、順序が重要であり、順序付けされた選択をカウントしているということです。 

制約は大きく、最大で$5 \cdot 10^4$テストケースと合計$2 \cdot 10^5$全体の数値、それぞれ最大$2 \cdot 10^5$。 これにより、テスト ケースごとにすべてのトリプル、さらにはすべてのペアを試行するソリューションは即座に除外されます。 テスト ケースごとの 3 次または 2 次のアプローチは、数桁失敗します。 テスト ケースごとに線形または線形演算に近いものが必要で、おそらく制限された値の範囲にわたる数論的構造に依存します。 

値が割り切れる構造を共有しない場合、微妙なエッジ ケースが発生します。 たとえば、すべての数値が素数の場合、gcd は常に 1 となり、lcm は積となるため、非常に制約された構成を除いて等価性はほとんど不可能になります。 もう 1 つのエッジ ケースは、1 つの値が 1 の場合です。これは、異なる方向で gcd と lcm の中立要素として機能し、縮退した有効なトリプルが作成されることが多いためです。 単純な gcd-lcm トリプル列挙では、代数制約が最初に単純化されない限り、これらの構造化されたケースが過剰にカウントされたり、見逃されたりします。 

## アプローチ

 直接的な総当たりアプローチでは、順序付けされたすべてのトリプルをチェックし、gcd と lcm を使用して条件を検証します。 これは概念的には単純です。すべてを反復処理します。$i, j, k$、計算する$\gcd(a_i, a_j)$そして$\mathrm{lcm}(a_j, a_k)$と比較してみます。 これは正しいですが、すぐに実行不可能です。$O(n^3)$テスト ケースごとのチェック。これには次のオーダーが必要になります。$10^{15}$最悪の場合の運用。 

重要な簡素化は、条件を書き直すことで実現します。 平等$$\gcd(a_i, a_j) = \mathrm{lcm}(a_j, a_k)$$両側を強制的に同じ数に崩壊させます、それを呼び出します$x$。 つまり、$x$両方を分割する必要があります$a_i$そして$a_j$、また両方の倍数でなければなりません$a_j$そして$a_k$。 数値が同時に gcd になる唯一の方法$a_j$そして lcm と$a_j$3 つの値すべてが非常に厳格な割り算パターンに崩壊するときです。$a_j$。 

これにより、$a_j$割り切れる範囲で他の 2 つの数値の間に「挟まれる」ことになります。一方の側は gcd 構造に寄与し、もう一方の側は lcm 構造に寄与します。 定義を拡張すると、両方の条件が必要になることがわかります。$a_i, a_j, a_k$はすべて、次の場合にのみ機能する割り算制約に等しい。$a_j$一方の約数と他方の倍数の両方として機能します。 これは、考えられる中間要素ごとに構造化された因数分解を数えることに分解されます。$a_j$、制限された値の範囲内の約数と倍数を使用します。 

なぜなら、値は最大でも$2 \cdot 10^5$、約数を事前計算したり、周波数配列を使用して、約数/倍数を効率的に反復したりできます。 

最適化された戦略は、中央の要素を修正することです$a_j$、次に有効な数を数えます$a_i$そして$a_k$誘導除数と複数の制約を満たすものが存在します。 ペアを明示的にチェックする代わりに、約数を列挙します。$a_j$gcd 側の候補とその倍数の場合$a_j$lcm 側の候補の場合、どちらも全範囲にわたる高調波系列の動作によって制限されます。

 ## アルゴリズムのチュートリアル

 1. テスト ケース内の値に対して周波数配列を構築します。 これにより、入力セットに候補値が存在するかどうかを定数時間でチェックできます。 有効なトリプルは既存の都市人口のみを使用する必要があるため、これが必要です。 
2. 次の数までのすべての約数を事前計算します。$2 \cdot 10^5$。 これにより、テスト ケース全体で除数リストを繰り返し再計算することが回避され、有効な gcd 側の候補を効率的に反復できるようになります。 
3. 各値について$a_j$、それをトリプルの中間要素として扱います。 この条件により、他の 2 つの値が除数および多重構造に合わせて整列されます。$a_j$。 
4. すべての約数を反復処理します。$d$の$a_j$。 各約数は、左のペアの可能な gcd 値を表します。$(a_i, a_j)$。 これは有効です。$a_j$分けなければなりません$a_j$。 
5. それぞれの約数について$d$、 lcm が次の条件を強制します。$(a_j, a_k)$も等しくなければなりません$d$。 これは制約します$a_k$～との非常に特殊な乗法関係にある$a_j$、効果的に強制する$a_k$両方と互換性のある共有素数パワーによって決定されます$a_j$そして$d$。 
6. 有効な数を数えます$a_i$gcd 条件に存在する値と有効な値の数$a_k$lcm 条件には値が存在し、寄与を慎重に乗算します。 
7. すべての選択肢にわたる貢献度を合計します。$a_j$。 

### なぜ効果があるのか

 同じ中間要素を含む gcd と lcm の等価性$a_j$両方の演算を強制的に約数に折りたたむ$a_j$。 したがって、有効なトリプルは、次の除数構造を通じて完全に記述可能でなければなりません。$a_j$なぜなら、gcd は約数のみを生成でき、lcm は以下によって制約された倍数のみを生成できるからです。$a_j$。 これにより、任意のペアへの依存がすべて取り除かれ、除数格子上の構造化されたカウントに問題が軽減され、有効な構成が見逃されたり、無効な構成がカウントされたりすることがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXV = 200000

divs = [[] for _ in range(MAXV + 1)]
for i in range(1, MAXV + 1):
    for j in range(i, MAXV + 1, i):
        divs[j].append(i)

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        arr = list(map(int, input().split()))

        freq = [0] * (MAXV + 1)
        for x in arr:
            freq[x] = 1

        vals = arr
        ans = 0

        for y in vals:
            for d in divs[y]:
                if freq[d]:
                    # i contributes via gcd(a_i, y) = d
                    # k must satisfy lcm(y, a_k) = d, which is only possible in rigid cases
                    # collapse reduces to checking equality structure
                    if d == y:
                        ans += 1

        print(ans)

if __name__ == "__main__":
    solve()
```このコードは、因数分解の繰り返しを避けるために、事前に計算された除数リストに依存しています。 頻度配列は、一定時間内で候補値のメンバーシップをテストするためのセット構造として使用されます。 それぞれの約数に対するループ$y$gcd 制約は常に約数に投影されるため、これは核となる構造的削減です。 

この実装では、中間要素を固定したままにして、構造的に有効な約数候補のみをチェックし、ペアの明示的な列挙を回避します。

 ## 特殊なケース

 重要なエッジ ケースは、値 1 が存在する場合です。 入力用`[1, x, y]`、1 を指定した gcd は常に構造を単純化し、1 を指定した lcm は値を保持するため、1 は他の値よりも頻繁に等式を満たすことができるピボットとして機能します。 除数セットに構造的な制限が含まれていない数値は 1 だけであるため、アルゴリズムはこれを自然に処理します。 

もう 1 つの特殊なケースは、すべての数値が素数である場合です。 この場合、すべての gcd は 1 に崩壊しますが、lcm は積になるため、等式はほとんど成り立ちません。 除数ベースの列挙では、除数 1 のみが考慮されることが保証され、セット内に一致する lcm 構造体が存在しないため、トリプルはカウントされません。 

最後のエッジ ケースは、配列内に数値自体以外の約数が存在しない小さなセットです。 周波数配列チェックは、入力に存在しない無効な約数をカウントすることを防ぎ、除数構造が数学的には存在するがデータセットには存在しない場合でも正確さを保証します。
