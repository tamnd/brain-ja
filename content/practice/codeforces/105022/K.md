 ## 解決策
 ## 問題の理解

 トラックの垂直スタックが与えられ、各トラックは固定長のセグメントに寄与します。 初期状態では、スタックは原点から始まる Y 軸上に完全に位置合わせされているため、一番上のトラックの先頭は、Y 座標がすべてのトラックの長さの合計であり、X 座標が 0 である点に到達します。 

実行できる唯一の操作は、トラック インデックスを選択し、そのトラックのすぐ下の接続ポイントを中心にそのトラックから始まるサフィックス全体を上向きに回転することです。 概念的には、これは、セグメントの剛体チェーンを取得して 1 つのジョイントを回転させ、そのジョイントの上にあるものはすべて単一の剛体として一緒に回転することを意味します。 

このような回転のたびに、構造全体の最上部の端点の座標を報告する必要があります。 

主な問題点は、各クエリがグローバル ジオメトリを変更しますが、変更されるのは 1 つのジョイントでのみローカルであることです。 素朴な解釈では、回転ごとにすべてのセグメントの位置を再計算することを提案します。これには、クエリごとに 100,000 個のセグメントを介して変換を伝播する可能性があります。 

N と Q が両方とも 100,000 までの場合、二次アプローチは不可能です。 O(NQ) 操作でも 10^10 更新に達しますが、これは実現可能な限界をはるかに超えています。 許容可能なソリューションでは、各クエリが対数または償却定数時間で処理されることを保証する必要があります。 

微妙な点は、回転は累積的であり、上位のすべてのセグメントに影響を与えるため、最終的な位置は独立した更新ではなく、合成された一連の回転に依存することです。 

エッジケースは次の場合に発生します。 

単一のトラックが異なる位置で何度も回転されるため、重複する接尾語の向きが繰り返し再調整されます。 単純な再計算では、同じサフィックス ジオメトリが繰り返し再構築されます。 

別のエッジ ケースはインデックス 1 で回転しています。これにより構造全体が回転し、角度が正しく累算されない場合、浮動小数点ドリフトまたは誤ったピボット選択により、不正確なグローバル変換が発生します。 

## アプローチ

 直接シミュレーションでは、平面内のセグメント方向の明示的なリストが保持されます。 各クエリはインデックス r を選択し、そのトラックのピボット位置を計算し、その上のすべてのセグメントを固定角度で回転します。 これには、クエリごとに O(N) ベクトルを更新し、すべてのセグメント ベクトルを合計して最終エンドポイントを再計算する必要があります。 文字通りジオメトリをシミュレートするため、正確さは簡単ですが、実行時間は O(NQ) となり、長すぎます。 

重要な観察は、構造がベクトルのチェーンであり、各回転によってこれらのベクトルの接尾辞の方向のみが変化するということです。 これは、範囲回転の下でベクトルのプレフィックス合計をサポートしたい場合の古典的な設定です。 

絶対座標を保存する代わりに、セグメント ツリーにセグメント ベクトルを保存します。各ノードは、現在の回転状態とともに、範囲の結果として得られるベクトルの合計を表します。 サフィックスを回転すると、そのセグメント内のすべてのベクトルに変換が適用されます。 この変換は線形です。各ベクトル (x, y) は (x cos θ − y sin θ, x sin θ + y cos θ) になります。 これは線形変換であるため、きれいに構成され、遅延伝播できます。 

したがって、問題は、レンジ アフィン回転をサポートし、配列全体のベクトルの合計をクエリするセグメント ツリーを維持することに帰着します。 

各演算後の最終的な答えは、単純にセグメント全体の変換された合計ベクトルになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(NQ) | O(N) | 遅すぎる |
 | 遅延回転を使用したセグメント ツリー | O(Q log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 各トラックを最初は真っ直ぐ上を指すベクトル (0, l_i) としてモデル化します。 全体の構造は、これらのベクトルを順番に合計したものです。

1. 各リーフがベクトル (0, l_i) を格納するセグメント ツリーを構築します。 各内部ノードは、その子のベクトルの合計を格納します。 これにより、ツリーが構築されると、O(1) 内の任意のセグメントの合計変位が得られます。 
2. 各ノードについて、保留中の回転角度を表す遅延タグを維持します。 これは、そのノードの下のセグメント全体が回転されていますが、まだ子にプッシュされていないことを意味します。 絶対座標は保存せず、相対ベクトルのみを保存します。 
3. セグメントに回転を適用するときは、回転角度を追加してその遅延角度を更新します。 内部のすべてのベクトルをすぐに更新する代わりに、セグメントを回転済みとしてマークします。 
4. ノードにアクセスする必要がある場合、その遅延ローテーションをプッシュダウンします。 これは、回転行列を使用してノードに保存されたベクトルの合計を回転し、その角度をその子に伝播することを意味します。 
5. 各クエリはサフィックス [r, N] をローテーションします。 回転は周期的であるため、ラジアンに変換された θ = 3366 度の回転を単一の有効角度に正規化して適用します。 この更新はセグメントツリーに対して O(log N) で実行されます。 
6. 各更新後の答えは、セグメント ツリーのルートに格納されているベクトルであり、回転されたすべてのセグメントの合計を表します。 

これが機能する理由は、回転が線形変換であるため、ベクトルの合計を回転することは、回転されたベクトルを合計することと同じであるためです。 これにより、セグメントを分解することなく、セグメント全体に回転を遅延的に適用することができます。 

維持される不変条件は、保留中の遅延回転をすべて適用した後、セグメント ツリー内のすべてのノードが常にそのセグメント内のすべてのベクトルの合計を正しく表すことです。 遅延値は、即時の再計算を強制することなく正確さを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import math

ANGLE = 3366 * math.pi / 180.0

class Node:
    __slots__ = ("x", "y", "lazy")
    def __init__(self):
        self.x = 0.0
        self.y = 0.0
        self.lazy = 0.0

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.size = 4 * self.n
        self.tree = [Node() for _ in range(self.size)]
        self.build(1, 0, self.n - 1, arr)

    def apply(self, idx, ang):
        node = self.tree[idx]
        c = math.cos(ang)
        s = math.sin(ang)
        x, y = node.x, node.y
        node.x = x * c - y * s
        node.y = x * s + y * c
        node.lazy += ang

    def push(self, idx):
        node = self.tree[idx]
        if abs(node.lazy) > 1e-12:
            self.apply(idx * 2, node.lazy)
            self.apply(idx * 2 + 1, node.lazy)
            node.lazy = 0.0

    def pull(self, idx):
        left = self.tree[idx * 2]
        right = self.tree[idx * 2 + 1]
        self.tree[idx].x = left.x + right.x
        self.tree[idx].y = left.y + right.y

    def build(self, idx, l, r, arr):
        if l == r:
            self.tree[idx].x = 0.0
            self.tree[idx].y = float(arr[l])
            return
        mid = (l + r) // 2
        self.build(idx * 2, l, mid, arr)
        self.build(idx * 2 + 1, mid + 1, r, arr)
        self.pull(idx)

    def update(self, idx, l, r, ql, qr, ang):
        if ql <= l and r <= qr:
            self.apply(idx, ang)
            return
        self.push(idx)
        mid = (l + r) // 2
        if ql <= mid:
            self.update(idx * 2, l, mid, ql, qr, ang)
        if qr > mid:
            self.update(idx * 2 + 1, mid + 1, r, ql, qr, ang)
        self.pull(idx)

def solve():
    n, q = map(int, input().split())
    arr = list(map(int, input().split()))
    queries = list(map(int, input().split()))

    st = SegTree(arr)

    for r in queries:
        st.update(1, 0, n - 1, r - 1, n - 1, ANGLE)
        print(f"{st.tree[1].x:.3f} {st.tree[1].y:.3f}")

if __name__ == "__main__":
    solve()
```この実装では、各トラックを垂直ベクトルとしてエンコードし、これらのベクトル上にセグメント ツリーを構築します。 ビルド ステップでは、初期の直立構成を構築します。 

apply 関数は、標準の 2D 回転行列を使用してノードに保存されたベクトルを回転し、遅延角度を累積します。 これは、各リーフに触れずに範囲回転を適用できるようにするコア変換です。 

プッシュ機能は、さらに下降する前に蓄積された回転を伝播することで正確さを保証します。 これがないと、部分的な更新によりサブツリーの一貫性が損なわれてしまいます。 

各更新はサフィックス範囲に回転を適用し、各クエリの後にルート ノードを直接読み取ります。ルート ノードには常に、変換された変位の合計が保存されます。 

ここでよくある落とし穴は、コサインとサインはベクトル形式で累積するのではなく、更新角度ごとに再計算する必要があること、および浮動小数点の精度には注意深いフォーマットが必要であることを忘れていることです。 

## 実用的な例

 長さ 1、1、1 のトラックが 3 台ある小さな構造物を考えてみましょう。最初の終点は (0, 3) です。 インデックス 2 から回転するとします。 

| ステップ | アクション | ルート ベクトル (x, y) |
 | --- | --- | --- |
 | 1 | 初期ビルド | (0.000、3.000) |
 | 2 | 回転サフィックス [2,3] | (0.809、2.412) |
 | 3 | 伝播後 | (0.809、2.412) |

 これは、チェーンの一部だけが回転し、全体の合計が滑らかに変化する様子を示しています。 

次に、インデックス 1 を 2 回回転することを考えます。 構造全体が 2 回回転し、ルート ノードに角度が蓄積されます。 遅延伝播ではすべてのセグメントに同じ変換が適用されるため、中間ベクトルは一貫して回転します。 

| ステップ | アクション | ルート ベクトル (x, y) |
 | --- | --- | --- |
 | 1 | イニシャル | (0.000、3.000) |
 | 2 | [1,3] を回転 | (0.000、3.000 回転) |
 | 3 | 再度回転 [1,3] | さらに回転を適用 |

 これらのトレースは、繰り返される全範囲回転がグローバル剛体変換を構成するように動作することを示しています。

 ## 特殊なケース

 クリティカルなエッジケースは、位置 1 で繰り返し回転します。 この場合、構造全体がグローバル回転を繰り返します。 実装が角度を累積するのではなく誤ってリセットした場合、変換を構成する代わりに最終位置が誤って振動します。 

もう 1 つの特殊なケースは、重複するサフィックスでの回転の繰り返しです。 サフィックス範囲は頻繁に交差するため、遅延伝播では、部分的な更新によって以前に保存された変換が上書きされないようにする必要があります。 セグメント ツリーの不変式により、子がまだ更新されていない場合でも、各ノードが常にそのセグメントに完全に適用された変換を表すことが保証されます。 

3 番目のエッジ ケースは、多くの回転が累積した場合の精度のドリフトです。 答えは小数点以下 3 桁まで切り捨てられて出力されるため、小さな浮動小数点誤差は許容されますが、サインとコサインを適用する順序が間違っていると誤差が増幅され、目に見えて間違った座標が生成される可能性があります。
