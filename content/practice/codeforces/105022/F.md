 ## 解決策
 ## 問題の理解

 数直線上に配置されたトラックのセットが与えられ、それぞれの開始位置と一定の速度が指定されます。 すべてのトラックは直進しており、2 台のトラックが同時に同じ地点で出会うと必ず衝突します。 衝突によって何も破壊されることはありません。代わりに 2 台のトラックは単に速度を交換するだけです。これは、あたかもお互いを通り過ぎたかのように、アイデンティティが交換された状態で将来の動きが継続されることを意味します。 

このタスクは、動きを直接シミュレートすることではなく、k 台のトラックの同時衝突を k(k−1)/2 個のペアごとの衝突として数えて、全期間にわたって合計で何回のペアごとの衝突が発生するかを計算することです。 プロセスが衝突の生成を停止しない場合は、-1 を出力する必要があります。 

重要な制約は N が最大 5000 であり、これによりリアルタイムのシミュレーションが即座に除外されます。 単純な衝突シミュレーションでは、次のイベントの検索、状態の更新、スワップの処理を繰り返し行う必要がありますが、これでは非常に時間がかかります。 O(N^2) 推論でさえ境界線にありますが、時間をシミュレートする代わりに問題を組み合わせ数に変換すれば可能です。 

複数のトラックが速度を共有したり、相互作用を繰り返すサイクルを形成したりする場合、微妙なエッジケースが発生します。 たとえば、3 台のトラックが継続的にカスケード スワップを引き起こし、後で新しい会議が生成され続ける場合、システムは安定せず、答えは無限になります。 

もう 1 つの重要なケースは同時到着です。 たとえば、3 台のトラックが同時に同じ地点に到着した場合、1 つのイベントではなく 3 つのペアごとの衝突をカウントする必要があるため、ペアごとの集合時間のみに基づくソリューションでは、衝突時間の均等性を慎重に処理する必要があります。 

## アプローチ

 このプロセスを直接シミュレートしようとすると、隣接するトラックのすべてのペアの間で次の衝突を時間順に繰り返し計算することになります。 各イベントには O(N) 個のスキャンまたは優先キューが必要であり、最悪の場合は O(N^2) 個の衝突が発生する可能性があります。 これにより、およそ O(N^2 log N) かそれより悪い結果が得られます。これは、特に速度スワップにより衝突順序が動的であるため、N = 5000 には遅すぎます。 

重要な洞察は、衝突のアイデンティティ交換の性質は、衝突後に実際にトラックを追跡する必要がないことを意味するということです。 代わりに、トラックが互いに通過するかのようにシステムを再解釈できますが、2 つの軌道が交差するたびに衝突をカウントします。 これは古典的な変換です。速度を交換すると、ラベル付きシステムがラベルなし交差システムと等価になります。 

この視点を採用すると、問題は次のようになります。トラックが直線に沿って独立して移動する場合に、同時に同じ位置を占めるペアのトラックの数を数え、さらに複数のラインが同時に交差する場合の縮退を処理します。 

ある時点 t で位置が等しくなった場合、2 台のトラック i と j が衝突します。 

xi + vi t = xj + vj t、vi ≠ vj の場合、t = (xj − xi) / (vi − vj) となります。 有効な衝突には t ≥ 0 が必要です。そのような有効な各ペアは、厳密に 1 つの衝突イベントに寄与します。

ただし、無限の衝突も検出する必要があります。 これは、等しい速度と相対的な順序により、時間の経過とともに同じ位置で継続的に相互作用する等速度グループのチェーンを通じて交差が繰り返される構成が存在する場合に発生します。 この定式化では、無限衝突が発生する唯一の方法は、同一速度の少なくとも 2 台のトラックが存在し、複数のトラックの同時衝突が無限に発生し続ける縮退オーバーラップ パターンを引き起こす方法で発進した場合です。 実際には、これは、システムが繰り返し同時交差点カスケードに崩壊する可能性があるかどうかを検出することになります。これは、3 台以上のトラックが位置と速度の両方の構造で相互に整列しているときに発生し、永続的なあいまいさを引き起こします。 より単純で標準的な特徴付けは、いずれかのペアが等しい速度を持ち、同一の位置の順序付けにより無制限のスワッピング サイクルが可能になる場合に無限衝突が発生するというものです。これは、位置がすでに同一でない限り、等しい速度だけでは決して衝突しないことを観察することで検出できます。 

したがって、問題は、有効なペアごとの交差を数えることと、縮退した無限のケースが存在しないことを確認することに帰着します。

 ## アルゴリズムのチュートリアル

 1. 左から右への相互作用を一貫して推論できるように、トラックを初期位置で並べ替えます。 この順序により、ペアの二重カウントを回避し、構造化された方法で各ペアが 1 回考慮されるようになります。 
2. i < j のすべてのペア (i, j) をソート順に繰り返します。 これにより、衝突後にラベルを交換しても基礎となる幾何学的交差が変更されないため、潜在的な衝突を 1 回だけカウントすることが保証されます。 
3. 各ペアについて、速度を比較します。 vi が vj に等しい場合、トラックは同じ位置から開始しない限り決して収束しませんが、位置が異なるためこれは不可能です。 したがって、このペアは衝突ゼロに貢献します。 
4. 速度が異なる場合は、交差時間 t = (xj − xi) / (vi − vj) ​​を計算します。 負の時間は交差が過去に発生したことを意味するため、t が負でない場合にのみこのペアを受け入れます。 
5. それぞれの有効なペアは、1 つの衝突イベントにのみ影響します。 これをグローバルカウンターに蓄積します。 
6. 処理中に、潜在的な無限衝突状態がないか確認します。 いずれかの構造が永続的に繰り返される交差を示している場合は、-1 を返します。 この問題の簡略化された形式では、別個の位置と等質量弾性スワップの下ではそのような構成は発生しないため、このステップは一貫性を検証するだけです。 

### なぜ効果があるのか

 重要な不変条件は、衝突時に速度を交換しても、トラックの軌道の時空交点のセットは変更されないということです。 各トラックは位置と時間の平面内の直線をたどっており、衝突はこれらの線の交点に正確に対応します。 等しい質量間の弾性衝突はラベル交換の下で軌道を保存するため、すべての物理的衝突は正確に 1 つの幾何学的交差に対応し、その逆も同様です。 したがって、ペアごとの有効な交差をカウントすると、システム内の正確な衝突数が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    trucks = [tuple(map(int, input().split())) for _ in range(n)]
    
    trucks.sort()  # sort by position
    
    ans = 0
    
    for i in range(n):
        xi, vi = trucks[i]
        for j in range(i + 1, n):
            xj, vj = trucks[j]
            
            if vi == vj:
                continue
            
            # solve xi + vi t = xj + vj t
            # t = (xj - xi) / (vi - vj)
            num = xj - xi
            den = vi - vj
            
            # we only care about t >= 0
            if num * den >= 0:
                ans += 1
    
    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションは、各ペアが一貫した左から右の順序で処理されるように、トラックを位置ごとに分類することから始まります。 これにより、交差点時間が非負であるかどうかを判断する際の符号処理のあいまいさが回避されます。 

各ペアについて、除算を完全に回避し、代わりに符号条件 num * den >= 0 を使用します。これにより、(xj − xi) / (vi − vj) ​​が浮動小数点誤差なしで非負であるかどうかがチェックされます。 速度と位置は 10^9 まで大きくなり、除算によって精度の問題が発生する可能性があるため、これは重要です。 

有効な各ペアは、動線の一意の交差に対応して、答えを 1 回だけインクリメントします。

 ## 特殊なケース

 重要なエッジケースは、速度が等しい場合です。 入力を考慮してください:```
2
1 5
10 5
```計算された時間の分母はゼロになるため、ペアをスキップする必要があります。 アルゴリズムはこれを算術演算の前に明示的に処理し、除算や無効なカウントが発生しないようにします。 

もう 1 つの微妙なケースは、後ろのトラックの方が速いにもかかわらず、順序付けのために計算された交差点時間がマイナスになる場合です。 例えば：```
2
1 10
2 1
```ここでは、num = 1、den = 9 なので有効です。 逆の場合:```
2
1 1
2 10
```現在、num = 1、den = -9、積は負であり、過去の交差を正しく拒否します。
