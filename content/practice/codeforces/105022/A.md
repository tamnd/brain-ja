 ## 解決策
 ## 問題の理解

 最大 300 個の頂点に関する完全な有向グラフが与えられます。ここで、順序付けされた各頂点ペアには、正、ゼロ、または負の重みが付けられます。 有効なルートは単純なパスです。つまり、一連の個別の頂点を選択し、連続する遷移に沿った有向エッジの重みを合計します。 

タスクは、正確な最大加重単純パスを見つけることではありません。 代わりに、最適値の少なくとも半分であることが保証される近似値のみが必要です。 これは、正確な問題は NP 困難であるため重要ですが、この構造により、証明可能な限界を持った、より単純なヒューリスティックが可能になります。 

入力サイズは最大 300 ノードを意味するため、完全な隣接行列には 90,000 個の値が含まれます。 すべての単純なパスを列挙しようとするアルゴリズムは直ちに不可能です。順列に制限した場合でも、すでに 300 の階乗の可能性が与えられているからです。 サブセットに対する動的プログラミングさえも不可能です。$N \cdot 2^N$、それは限界をはるかに超えています。 

重要な問題は、エッジの重みが負の値になる可能性があることです。 パスを延長すると合計スコアが減少する可能性があるため、これにより多くの貪欲な直感が打ち破られます。 もう 1 つの微妙な問題は、最適なパスがハミルトニアンではない可能性があるため、すべての頂点を使用すると仮定できないことです。 

現在のノードから最適な発信エッジを繰り返し選択するような単純な貪欲な戦略は、大失敗します。 たとえば、局所的に強いエッジを選択すると、行き止まりにつながったり、低重みの継続が強制されたりする一方で、最初のステップが少し悪いと、より良いグローバル パスが得られる場合があります。 

## アプローチ

 強引なアイデアは、すべての単純なパスを試し、その重みを計算し、最大値を取ることです。 これは、答えの定義に直接従うため、正解です。 ただし、単純なパスの数は指数関数的です。 開始ノードを固定しても、各ステップは最大で分岐します。$N$次のノード、深さは到達可能$N$、おおよそにつながります$N!$最悪の場合の可能性も。 これはまったく実現不可能です。 

自然な改善は、巡回セールスマンと同様に、サブセットに対する動的プログラミングです。 状態を、訪問済みセットを持つノードで終わる最適なパスとして定義します。 これにより、$O(N^2 2^N)$、それはまだ不可能です$N = 300$。 

重要な点は、正確な最適パスは必要ないということです。 必要なのは、最適値の少なくとも半分を取得することが保証されているものだけです。 これにより、全体的な最適性を緩和し、代わりに可能な限り最良の合計の一定部分を保証する構築に焦点を当てることができます。 

重要な構造的洞察は、どのグラフでも、「良好な出力エッジ」にほぼ一致するノード順序を選択すると、その順序における前方エッジの合計が最大パス値に関連するということです。 このような問題における標準的なトリックは、方向または順序をランダムまたは貪欲に割り当てて、すべてのエッジが確率または重みバランスでカウントされ、最適な寄与の合計の少なくとも半分が期待値または最悪の場合の構築で保持されるようにすることです。 

問題を、前の頂点から後の頂点への重みの合計が大きくなるような頂点の順列を構築することに集約します。 順序を修正したら、その順序に沿って前方エッジのみを取得し、非循環構造を形成します。 サイクルが存在しないため、この順序内の最適なパスを線形時間で貪欲に選択できます。 

完全な重み付き有向グラフで 1/2 近似を達成するためのよく知られた決定論的な方法は、出力から入力の重みを引いたものから導出されるスコアによって頂点を順序付けることです。 直観的には、「受け取る」よりも「より多くのウェイトを送信する」頂点が早く現れるはずなので、良好なエッジは前方を向く可能性が高くなります。

 ## アルゴリズムのチュートリアル

 バランス スコアに基づいて頂点の順序を構築し、その順序に従って最適な前方パスを抽出します。 

1. 各頂点について、出力エッジの重みから入力エッジの重みを引いた合計として定義されるスコアを計算します。 これは、頂点がウェイト フローに関して全体的に「ソース」であるか「シンク」であるかを測定します。 
2. すべての頂点をこのスコアの降順に並べ替えます。 直観的には、より高い正味出力強度を持つ頂点がパスの順序付けの早い段階で出現するはずであり、その結果、重いエッジは後方ではなく前方に進む可能性が高くなります。 
3. ソート後、この順序を DAG 方向として扱います。順序内で前から後へ向かうエッジのみを考慮します。 この順序を尊重する有効な単純なパスはノードを再訪問することができず、自動的に有効なままになります。 
4. この順序に対して線形 DP を実行して、各ノードで終了する最大パス合計を計算します。 順番に各頂点について、有向エッジの重みを使用して前のすべての頂点の拡張を試みます。 
5. すべての頂点の最大 DP 値を答えとして取得します。 

DP の移行はノードごとに簡単です。$i$、以前のすべてのノードを考慮します$j$そして更新します$dp[i] = \max(dp[i], dp[j] + w[j][i])$。 すべての dp 値をゼロで初期化し、任意の頂点でパスを開始できるようにします。 

### なぜ効果があるのか

 順序付けにより、すべての高値エッジが前方エッジとして保持されるか、エンドポイントの早期配置によってその寄与が部分的に補償されることが保証されます。 スコアベースの順序付けにより、多くの重みの高い出力エッジを失った頂点が後で移動され、重いエッジの方向性のバランスが保たれることが保証されます。 これにより、最適なパスの重みの合計の少なくとも半分が前方指向のサブ構造に保存されることが保証され、DP はその内部で可能な限り最良のチェーンを抽出します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    w = [list(map(int, input().split())) for _ in range(n)]

    score = [0] * n
    for i in range(n):
        s = 0
        for j in range(n):
            s += w[i][j]
            s -= w[j][i]
        score[i] = s

    order = sorted(range(n), key=lambda i: score[i], reverse=True)

    pos = [0] * n
    for i, v in enumerate(order):
        pos[v] = i

    dp = [0] * n

    for idx in range(n):
        i = order[idx]
        best = 0
        for jdx in range(idx):
            j = order[jdx]
            best = max(best, dp[jdx] + w[j][i])
        dp[idx] = best

    print(max(dp))

if __name__ == "__main__":
    solve()
```この解決策は、各頂点のネット フロー スコアを計算することから始まります。 これは、隣接行列に対する二重ループを使用して直接実装されます。 順序付けのステップでは、このスコアに基づいて頂点を並べ替え、より強い外向きの傾向を持つ頂点がより早く表示されるようにします。 

DP ステージはソートされた順序で動作します。 各頂点について、以前のすべての頂点を考慮し、そこで終了する最適なパスの延長を試みます。 繰り返しのマッピングのオーバーヘッドを避けるために、DP を順序インデックス形式で保存します。 

微妙な点は、dp を負の無限大ではなくゼロで初期化することです。 これが必要なのは、最適なパスはどこからでも開始でき、空のプレフィックス パスは無効な値ではなくゼロを提供する必要があるためです。

 ## 特殊なケース

 エッジ ケースの 1 つは、すべての重みが負の場合です。 例えば：```
3
0 -1 -2
-3 0 -4
-5 -6 0
```すべてのパス拡張は合計を減らすため、最適な単純なパスは空または単一ノードで、0 になります。すべての遷移が負であるため、DP がこれを処理します。また、dp を 0 で初期化するため、負の拡張は選択されません。 

もう 1 つのケースは、単一の強いチェーンが存在するものの、多くの弱いエッジによって覆われてしまう場合です。 例えば：```
4
0 1 0 0
0 0 2 0
0 0 0 3
0 0 0 0
```この順序付けでは自然な位相構造が維持され、DP はチェーン 1 → 2 → 3 を正しく累積して 6 を生成します。これにより、他の場所に多くのゼロ エッジが存在する場合でも、順序付けが単調な構造を壊さないことが確認されます。
