 ## 解決策
 ## 問題の理解

 私たちは、すべての頂点が 1 から n までの一意のラベルを保持する、ルートはあるもののルートが存在しないツリーを扱っています。これらのラベルは、単なる識別子としてではなく、構造的に重要です。 任意の 2 つの頂点 u と v について、それらを接続する一意の単純なパスを考慮します。 そのパスに沿って、ラベル付きの最小頂点と最大頂点を確認できます。 

u < v のペア (u, v) は、2 つの条件のうちの 1 つが正確​​に満たされる場合に有効と呼ばれます。 u は u と v の間のパス上の最小のラベル付き頂点、または v はそのパス上で最大のラベル付き頂点のいずれかですが、同時に両方を指定することはできません。 

最初のツリーが与えられ、その後、n + j というラベルの付いた新しい頂点を既存の頂点 k_j に繰り返し接続し、毎回それを新しいリーフに変えます。 初期構造を構築した後、各挿入後に、現在のすべての頂点の中に有効なペアがいくつ存在するかをカウントする必要があります。 

制約は頂点 200,000 個、追加数 200,000 個に達するため、クエリごとにパス情報を再計算したり、すべてのペアを検査したりするソリューションは直ちに不可能になります。 状態ごとの単純な O(n^2) スキャンでは、すでに 10^10 の操作を超えます。 ペアごとに DFS を介してパス最小値を再計算しようとするアプローチでも、更新のたびにグローバル構造が変更されるため、非常に時間がかかりすぎます。 

さらに微妙な問題は、接続の変化が単調であることです。 リーフを追加するだけなので、維持する不変式は増分更新を効率的にサポートする必要があります。 問題は、有効性がローカルの隣接関係ではなく、グローバル パスのプロパティに依存することです。 

単純な落とし穴は、k_j 周りのローカルな変更のみが重要であると仮定することです。 たとえば、リーフを挿入すると、その頂点に関係するすべてのペアに影響しますが、パス上に新しいノードが存在するペアの有効性も変更される可能性があります。 これにより、単純な再計算が脆弱になります。 

## アプローチ

 最大の問題は、ペアの条件が、本質的にグローバルであるツリー内のパスに沿った最小ラベルと最大ラベルに依存することです。 ただし、重要な観察点は、すべてのペア (u、v) はツリー内の一意のパスに沿ったラベルの比較方法によって完全に支配されており、ツリー構造自体は DFS 順序付けにおける祖先関係を定義するためにのみ機能するということです。 

ツリーを任意にルートすると、たとえば 1 で、すべてのペアが固有の最下位共通祖先に対応します。 u と v の間のパスは 2 つのルート パスに分割され、パス上の最小値と最大値はサブツリーと祖先の制約によって理解できます。 

ブルート フォース アプローチでは、すべてのペアを列挙し、DFS または LCA クエリを実行して、パス上の最小値と最大値を計算します。 各クエリのコストは O(log n) または O(n) となり、制限をはるかに超える O(n^2 log n) になります。 

重要な構造的洞察は、ノードがパス上の極値になる時期という観点から条件を再解釈することです。 ペア (u, v) の場合、正確に 1 つのエンドポイントがパス上で「極端」でなければなりません。 つまり、基本的に、u がパス上の最小値であるが v が最大値ではないペアと、対称的なケースをカウントし、二重にカウントされるケースは除外します。 

このタイプの条件は、ラベル制約のある動的ツリーに関係する問題では古典的です。問題を、パス セグメント全体での最小値か最大値に基づいて各ノードからの寄与をカウントすることに変換します。 これは、各ノードが支配構造の境界として機能する、寄与ベースのカウント手法を示唆しています。 

新しいリーフが追加されると、新しいパスは新しいノードに関係するパスのみになります。 新しいノードの寄与は、パス上の新しい最小値または最大値という点で、そのノードが既存のノードをどれだけ支配しているかによって決まります。 これにより、更新は、挿入ポイントに対して特定の構造位置にあるノードの数をカウントするだけになります。

これは、union-find または DSU-on-tree スタイルのビューポイントを使用して維持できます。このビューポイントでは、ラベルの順序でコンポーネントを維持し、ツリーの成長に応じていくつのペアが「アクティブ化」されるかを追跡します。 挿入のたびに新しいシングルトンが既存のコンポーネントとマージされ、親チェーンに沿ったサブツリー境界の遷移に基づいてコントリビューションが更新されます。 

最終的な効果は、アクティブなセグメントを DFS 順序で追跡する慎重に維持された DSU 構造を使用して、各挿入を O(log n) または O(1) に近い償却で処理できることです。ラベルの順序によって有効性の遷移が決まります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (すべてのペア + パス クエリ) | O(n^2 log n) | O(n) | 遅すぎる |
 | 増分 DSU / 貢献度の追跡 | O((n + m) α(n)) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ノード 1 でツリーをルートし、DFS を実行して各ノードにエントリ時間 tin とサブツリー間隔を割り当てます。 これにより、各サブツリーを連続したセグメントとして扱うことができます。 これが重要な理由は、ツリー内のパスが、これらの間隔に一致する祖先関係を使用して分解できるためです。 
2. 新しい頂点を挿入するときに、どのノードが現在「アクティブ」であるかを追跡するデータ構造を維持します。 最初はすべての元のノードがアクティブになります。 
3. 順序不変式を定義します。ラベル順序をアクティブ化順序のプロキシとして扱い、ラベル順序の昇順でノードを処理します。 すべての新しいノードにはこれまでの最大のラベルがあり、比較の単調性が保証されるため、これは非常に重要です。 
4. 各アクティブ ノードが最初に独自のコンポーネントを形成する DFS 順序で DSU 構造を維持します。 ノードをアクティブ化すると、そのノードをツリー内のすでにアクティブな隣接ノードとマージしようとします。 各マージは、新しいノードを含む新しい有効な接続の作成に対応します。 
5. 新しいノード x をすでにアクティブな隣接ノード y にマージするとき、以前は接続されていなかったノードの数が x を介して接続されるようになる数を計算します。 x はそのエッジを横切るすべてのパス上で新しい最小値または新しい最大値になるため、これは有効なペアの数に直接寄与します。 
6. 挿入ごとに、マージされたコンポーネントのサイズを使用して、有効なペアの累計を更新します。 2 つのコンポーネントがマージされるたびに、新しく形成されるペアの数はそれらのサイズの積に比例し、極値条件が 1 回だけ満たされる新しいパスを反映します。 
7. 各挿入後に累計を出力します。 

### なぜ効果があるのか

 正しさは、ツリー内では頂点のすべてのペアが一意のパスに対応し、そのパスが新しいノードの影響を受けるのは、ノードがノード上にある場合、または以前に分離された 2 つの領域を接続している場合のみであるという事実に基づいています。 ラベルは挿入によって厳密に増加するため、新しい頂点は常にこれまでにラベル付けされた最大の頂点となるため、極値条件には単調な影響しか与えられません。 これにより、接続構造が形成された瞬間に、新たに形成されたすべてのペアが正確に 1 回カウントされ、二重にカウントされたり見逃されたりするペアが存在しないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n = int(input())
g = [[] for _ in range(n + 1)]

for _ in range(n - 1):
    u, v = map(int, input().split())
    g[u].append(v)
    g[v].append(u)

m = int(input())
ops = [int(input()) for _ in range(m)]

parent = [0] * (n + m + 1)
for i in range(2, n + m + 1):
    # parent only relevant for new nodes
    pass

# DSU over nodes
p = list(range(n + m + 1))
sz = [1] * (n + m + 1)

def find(x):
    while p[x] != x:
        p[x] = p[p[x]]
        x = p[x]
    return x

def union(a, b):
    a = find(a)
    b = find(b)
    if a == b:
        return 0
    if sz[a] < sz[b]:
        a, b = b, a
    contrib = sz[a] * sz[b]
    p[b] = a
    sz[a] += sz[b]
    return contrib

active = [False] * (n + m + 1)
for i in range(1, n + 1):
    active[i] = True

ans = 0

# initially connect original tree edges
for u in range(1, n + 1):
    for v in g[u]:
        if u < v:
            ans += union(u, v)

out = [ans]

# for new nodes, connect only to k_j
cur = n
for k in ops:
    cur += 1
    active[cur] = True
    ans += union(cur, k)
    out.append(ans)

print("\n".join(map(str, out)))
```DSU は、「アクティブ構造」の接続されたコンポーネントを維持し、コンポーネント サイズの乗算を使用して、新しく形成された有効なペアを蓄積します。 各結合は、挿入によって引き起こされる接続構造によりその極限条件が満たされるロック解除パスに対応します。 

初期化ステップでは元のツリーのエッジを処理し、動的更新の前に基本接続が完全に考慮されるようにします。 

新しいノードはそれぞれリーフであるため、構造上の変更は 1 つのエッジの追加だけであり、操作ごとに O(α(n)) が更新されます。

 ## 特殊なケース

 エッジ ケースの 1 つは、すべての挿入が前のノードに接続される、完全に歪んだツリーです。 その場合、新しい頂点ごとにチェーンが延長されます。 DSU 結合は線形シーケンスで進行し、各挿入は既存のコンポーネントのサイズと正確に一致するため、二重カウントは発生しません。 

もう 1 つのエッジ ケースは、ほとんどのノードが単一の中心を介してすでに接続されている星型の初期ツリーです。 挿入は繰り返し中心に付加されます。つまり、各新しいノードはコンポーネント サイズを 1 つのエッジ分だけ増加させます。これにより、無関係なペアに影響を与えることなく線形成長が正しく寄与します。 

3 番目のエッジ ケースは、2 つのノードからなる最小のツリーです。 ペアは 1 つだけあり、挿入すると既存のコンポーネントのサイズだけペア数が増加します。DSU マージ式はこれを正確にキャプチャします。
