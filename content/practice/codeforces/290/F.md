 ## 解決策
 ## 問題の理解

 最大 20 個の頂点と最大 400 個のエッジを持つ無向グラフが与えられ、すべての頂点を 1 回だけ訪れる単純なパスが存在するかどうかを判断する必要があります。 これは、決定形式におけるハミルトニアン パス問題です。パスを構築することは求められません。連続する頂点がエッジで接続されている場所に、そのような頂点の順序が少なくとも 1 つ存在するかどうかを尋ねるだけです。 

重要な詳細はグラフのスケールです。 頂点が最大 20 個であれば、指数関数的な手法が実行可能になりますが、頂点のすべての順列を直接列挙するようなことはすでに境界線に達しています。$20!$は大きすぎます。 ただし、頂点のサブセットに対する状態圧縮を伴うソリューションは、次のとおりです。$2^n \cdot n^2$、快適に実行可能です。 

微妙な点の 1 つは、グラフには自己ループまたは複数のエッジが含まれている可能性がありますが、これらはハミルトニアン パスの存在に影響を与えないことです。 自己ループは、異なる頂点間を移動する必要があるパスでは決して役立ちません。また、重複したエッジは接続のために冗長です。 

よく見られる単純な間違いは、これを接続の問題として解釈することです。 たとえば、グラフが接続されていて、すべての頂点に少なくとも 1 つの次数があることを確認するだけでは十分とは言えません。 20 個の頂点を持つ星のような接続されたグラフには、すべてのリーフに接続された中心がありますが、ハミルトニアン パスはありません。これは、中心に入るパスは 1 回しか中心から離れることができないため、単一のチェーンですべてのリーフを訪問することが不可能であるためです。 

もう 1 つの失敗例は、貪欲なトラバーサルに起因します。 ランダムなノードから開始し、常に未訪問の隣接ノードに向かうと、有効なハミルトニアン パスが存在する場合でも、早期にスタックする可能性があります。 ローカルな選択はグローバルな制約をエンコードしません。 

## アプローチ

 ブルート フォース アプローチでは、頂点のすべての順列を試し、連続する頂点がエッジで接続されているかどうかを確認します。 各順列について、次の隣接性を検証します。$O(n)$、そして、あります$n!$順列により、全体的な複雑さは次のようになります。$O(n! \cdot n)$。 でさえ$n = 20$、これはまったく不可能です。 

頂点のどのサブセットが訪問されたか、およびパス内の最後の頂点のみを気にすることがわかると、問題の構造は大きく変わります。 同じ頂点セットを訪れ、同じ頂点で終了する 2 つの異なる置換は、将来の拡張性の観点からは同等です。 これは、サブセットに対する動的プログラミングの定式化を示唆しています。 

訪問した頂点のサブセットとパスの終点をキャプチャする状態を定義します。 どの州からでも、未訪問の隣人までパスを延長しようとします。 これにより、順列からサブセット遷移への検索スペースが削減され、扱いにくい列挙が管理可能な列挙に変わります。$2^n \cdot n$状態空間。 

これは標準的なハミルトニアン パス DP であり、ここでは完全に適合します。$n \le 20$、作る$2^n \approx 10^6$、十分小さいです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (順列) |$O(n! \cdot n)$|$O(n)$| 遅すぎる |
 | パス上のビットマスク DP |$O(n^2 \cdot 2^n)$|$O(n \cdot 2^n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 動的プログラミング テーブルを構築し、頂点の特定のサブセットが特定の頂点で終わる有効なパスを形成できるかどうかを追跡します。 

1. 長さのビットマスクを使用して頂点の各サブセットを表します$n$。 ビットマスクは、どの頂点が部分パスに既に含まれているかを正確にエンコードします。 トランジションでは一度に 1 つの頂点しか追加されないため、この表現は自然です。 
2. DP 配列を定義します。`dp[mask][v]`の頂点を正確に訪れるパスが存在する場合は true です。`mask`そして頂点で終わります`v`。 この状態では、パスをさらに拡張するために必要なすべての情報が取得されます。 
3.設定によりDPを初期化します`dp[1 << v][v] = True`頂点ごとに`v`。 各頂点だけで、長さ 1 の自明なパスが形成されます。 
4. すべてのマスクを小さいものから大きいものまで繰り返します。 マスクごとに、考えられるすべてのエンドポイントを試します`v`。 もし`dp[mask][v]`が true の場合、パスを延長しようとします。 
5. 状態を拡張するには`(mask, v)`、すべての隣人を試します`to`の`v`。 もし`to`入っていない`mask`、設定しました`dp[mask | (1 << to)][to] = True`。 このステップは、現在のパスに新しい頂点を追加することに正確に対応します。 
6. すべての状態を処理した後、頂点が存在するかどうかを確認します`v`そのような`dp[(1 << n) - 1][v]`それは本当です。 そうであれば、ハミルトン経路が存在します。 

正確さは、すべての有効なハミルトニアン パスに最後の頂点があるという事実にかかっており、DP は最終的に、そこに至るサブセットのシーケンスを正確に構築します。 

### なぜ効果があるのか

 不変条件とは、`dp[mask][v]`の頂点を正確に訪問する単純なパスが存在する場合にのみ true になります。`mask`そしてで終わります`v`。 未訪問の頂点にのみ移動し、有効なパスのあらゆる可能な拡張が考慮されるため、すべての遷移では単純さが保たれます。 すべてのハミルトニアン パスはサブセットの追加の順序に対応するため、この状態空間に出現する必要があり、無効な状態が導入されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    adj = [[False] * n for _ in range(n)]
    
    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        adj[u][v] = True
        adj[v][u] = True

    if n == 1:
        print("Yes")
        return

    size = 1 << n
    dp = [[False] * n for _ in range(size)]

    for i in range(n):
        dp[1 << i][i] = True

    for mask in range(size):
        for v in range(n):
            if not dp[mask][v]:
                continue
            if mask == (1 << n) - 1:
                continue
            for to in range(n):
                if not adj[v][to]:
                    continue
                if mask & (1 << to):
                    continue
                dp[mask | (1 << to)][to] = True

    full = (1 << n) - 1
    for v in range(n):
        if dp[full][v]:
            print("Yes")
            return

    print("No")

if __name__ == "__main__":
    solve()
```隣接行列は、エッジ チェックが一定時間になるように使用されます。 DP はすでにすべてのサブセットとエンドポイント上で実行されており、遷移ごとに対数オーバーヘッドが発生するとコストが高すぎるため、これは重要です。 

サブセットの反復は自然な外部ループであるため、DP テーブルには最初にビットマスクによってインデックスが付けられます。 各状態は実際のエッジに沿ってのみ拡張され、パスの有効性を確保するために、すでに訪問した頂点への遷移を明示的にスキップします。 

最終スキャン終了`dp[full]`すべての頂点を訪問した後にエンドポイントが到達可能かどうかを確認します。 

## 実用的な例

 ### 例 1

 入力グラフ:```
3 2
1 2
2 3
```1 → 2 → 3 のようなハミルトニアン パスが予想されます。 

| マスク | エンドポイント v | dp 状態 | 遷移 |
 | --- | --- | --- | --- |
 | 001 | 1 | 本当 | 開始 |
 | 010 | 2 | 本当 | 開始 |
 | 100 | 3 | 本当 | 開始 |
 | 011 | 2 | 本当 | 1→2 |
 | 110 | 3 | 本当 | 2→3 |
 | 111 | 3 | 本当 | 1→2→3 |

 最後のマスクでは、少なくとも 1 つのエンドポイントに到達できるため、答えは「はい」です。 

このトレースは、サブセットが増加するにつれて部分パスがどのように自然にマージされるかを示しています。 

### 例 2

 入力:```
4 2
1 2
3 4
```グラフが切断されているため、ハミルトニアン パスは存在しません。 

すべての DP 状態はコンポーネント内に限定されたままであり、{1,2} から {3,4} に遷移することはできません。 したがって、マスク 1111 に到達する状態はありません。 

DP は完全なマスク状態を決して生成しないため、サブセット内の接続だけでは十分ではないことがわかります。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(n^2 \cdot 2^n)$| 各サブセット状態は次のことを試みます$n$エンドポイント以降$n$隣人 |
 | スペース |$O(n \cdot 2^n)$| 各マスクとエンドポイントの状態を格納する DP テーブル |

 と$n \le 20$、$2^n \approx 10^6$、および周囲の定数因子$n^2$、このソリューションは、隣接行列の最適化により、Python の制限内に快適に適合します。

 ## 特殊なケース

 エッジ ケースの 1 つは単一頂点グラフです。 DP が初期化されます`dp[1<<0][0] = true`、これはすでに完全なマスクに対応しているため、アルゴリズムはすぐに成功し、正しく「Yes」を出力します。 

もう 1 つのケースは、孤立した頂点を持つグラフです。 たとえば、頂点 5 にエッジがない場合、それはスタンドアロン パスとしてのみ表示されます。 5 から始まる状態は拡張できず、フルマスク状態に到達できないため、DP はこれを正しく処理します。 

より微妙なケースは、完全な順序付けをブロックする重要なエッジが欠落している密なグラフです。 ほとんどの頂点が高度に接続されている場合でも、DP は正確な隣接性制約を尊重するため、互換性のない部分パスを誤って結合することはありません。
