 ## 解決策
 ## 問題の理解

 私たちには、ジョーク言語の HQ ファミリーからインスピレーションを得た非常に小さなアルファベットから作られた 1 つの文字列が与えられています。 タスクは、この文字列が言語本部の規則に基づいて「有効」であるかどうかを判断し、確認または拒否を出力することです。 

重要な問題は、元のステートメントが正式な文法規則を提供していないことです。 サンプルとともに残っているのは、この言語が通常の意味での文字数のカウントやパターンのマッチングに関するものではないという重要なシグナルです。 代わりに、文字列が単一の繰り返し構造単位に還元できる方法で構成されているかどうかが重要です。 

サンプル入力から`"HHHH"`生産する`"Yes"`の場合、同じコマンド記号が繰り返し出現するだけで構成される文字列は有効であると推測できます。 ステートメント内に他に有効な例が存在しないことは、異なる文字を混合したり、追加の構造を導入したりすることが言語規則に違反することを強く示唆しています。 

この制約により、長さ 10^6 までの文字列が許可されます。 これにより、部分文字列に対する二次シミュレーションや三次シミュレーション、または入れ子構造の再帰解析が即座に除外されます。 どのソリューションでも、文字列を線形時間と一定の追加メモリで処理する必要があります。 

注意すべき主なエッジケースは、文字列に複数の異なる文字が含まれている場合です。 例えば、`"HHQH"`これは明らかに均一な構造を破壊するものであり、拒否される必要があります。 厳密な均一性ではなく周期性のみを検証する場合、プレフィックス パターンまたは部分的な繰り返しのみをチェックする単純なアプローチでは、そのような文字列が誤って受け入れられる可能性があります。 

## アプローチ

 強引な解釈では、HQ 文法の考えられるすべての導出を検証しようとします。 これは通常、再帰的な生成ルールによって生成されたかのように文字列を解析し、多くのセグメント化や変換をチェックすることを意味します。 各チェックが線形であっても、長さ n の文字列の可能な分解の数は指数関数的に増加するため、中程度の入力サイズでもこのアプローチは実行不可能になります。 

重要な観察は、サンプルと一致する唯一の構造と追加のルールがないこと、つまり妥当性はシンボルの均一性のみに依存するということです。 この言語は、単一の繰り返し文字のみが許可される単純なサブセットに折りたたまれます。 これにより、問題は単純なスキャンに変わります。文字列内のすべての文字が同一であるかどうかを確認するだけで済みます。 

これにより、問題は、潜在的な組み合わせ解析タスクから最初の文字に対する単一パスの比較に軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース文法解析 | 指数 | O(n) | 遅すぎる |
 | 均一性チェック | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力文字列を読み取ります。 これは、検証する必要がある HQ プログラムのインスタンス全体です。 
2. 文字列の最初の文字を参照記号として使用します。 有効な文字列はすべての位置でこの記号と一致する必要があります。 
3. 文字列を左から右に繰り返し、各文字を参照記号と比較します。 不一致が見つかった場合は、ただちに文字列が無効であると判断します。 
4. 不一致が見つからずにスキャンが完了した場合は、すべての文字が同一であり、文字列が有効であると判断されます。 

最初の不一致で安全に停止できる理由は、均一性からの逸脱は、この言語で有効なプログラムを定義する構造的制約にすでに違反しているためです。 

### なぜ効果があるのか

 この削減された設定における有効な HQ 文字列の定義特性は、単一のコマンド シンボルの繰り返しによる閉包です。 この言語には、複数の異なるトークンの分岐、変更、または順序付けを導入するメカニズムはありません。 これは、すべての有効な文字列が、単一文字 c に対する ccc...c 形式の文字列の等価クラスに属している必要があることを意味します。 アルゴリズムは、検査されるすべての文字が最初の文字と等しい必要があることを維持することにより、この不変条件を正確に適用します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    first = s[0]
    for ch in s:
        if ch != first:
            print("No")
            return
    print("Yes")

if __name__ == "__main__":
    solve()
```このソリューションは文字列を 1 回読み取り、最初の文字を参照ポイントとして保存します。 ループはすべての文字をそれに対してチェックします。 早期リターンにより、最初の違反で停止することが保証されます。これは、長さが 10^6 の最悪の文字列にとって重要です。 

微妙な実装の詳細は、`strip()`これにより、改行文字が文字列の一部として扱われなくなります。 これがないと、均一な文字列が末尾の空白により誤って失敗する可能性があります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各文字は参照に対して 1 回チェックされます |
 | スペース | お(1) | 参照文字は 1 つだけ格納されます |

 正確さを保証するにはすべての文字を少なくとも 1 回検査する必要があるため、リニア スキャンが最適です。 n が最大 10^6 であるため、これは Python の一般的な 2 秒の制限内に問題なく収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from __main__ import solve
    return sys.stdout.getvalue() if False else _run(inp)

def _run(inp: str) -> str:
    import sys, io
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout
    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()
    solve()
    out = sys.stdout.getvalue()
    sys.stdin = backup_stdin
    sys.stdout = backup_stdout
    return out

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、次のような単一文字列です。`"H"`。 アルゴリズムは最初の文字を参照として設定し、不一致条件に入らずにすぐに終了し、正しく返します。`"Yes"`。 

もう 1 つのエッジ ケースは、最後の文字で不一致が発生する文字列です。たとえば、`"HHHHHQ"`。 このループは、先行するすべての同一文字をスキャンし、最終ステップでのみ拒否します。これは、アルゴリズムが初期の構造仮定に依存していないことを示しています。 

3 番目のケースは、最大長の均一入力です。 長さが 10^6 の場合でも、アルゴリズムは定数メモリを使用して単一の線形パスを実行し、特別な処理や最適化のトリックなしで制限内に収まることを確認します。
