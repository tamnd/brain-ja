 ## 解決策
 ## 問題の理解

 大文字と小文字の両方の英字で構成される文字列と、0 から 26 までの「大文字の予算」を表す整数が与えられます。タスクは、この予算を超えない範囲で、できるだけ多くの小文字を大文字に変換して文字列を変換することです。 大文字の変換ごとに、予算から 1 単位が消費されます。 すでに大文字になっている文字は予算にカウントされず、変更されないままになります。 

入力文字列の長さは最大 50 文字です。 これは非常に小さいため、各文字を個別に処理するソリューションは効率的です。 0 ～ 26 の整数制約は重要です。これにより、変換できる文字数が制限されます。つまり、文字列に 26 を超える小文字が含まれる場合は選択する必要があります。 

エッジケースがいくつかの場所で発生します。 予算が 0 の場合、コンバージョンは発生しません。 文字列に含まれる小文字が予算よりも少ない場合は、すべての小文字が変換され、残りの予算は使用されません。 大文字のみで構成される文字列は、予算に関係なく影響を受けません。 文字を盲目的に変換したり数え間違いをしたりする不用意な実装は、簡単に予算を超過したり、すでに大文字を変更しないままにしておくことができなくなる可能性があります。 

## アプローチ

 ブルート フォースのアプローチは簡単です。文字列を 1 文字ずつ反復処理します。 各文字について、小文字であるかどうか、予算が残っているかどうかを確認します。 両方の条件が当てはまる場合は、大文字に変換して予算を減算します。 それ以外の場合は、文字を変更しないでください。 この方法は、問題のルールを明示的に実装しているため、正しいです。 その複雑さは O(n) です。n は文字列の長さで、最悪の場合は 50 です。50 文字であっても、この操作数はわずかです。 このコンテキストにおけるブルート フォースは、入力サイズが小さいため、すでに最適です。 

このアプローチを改良するための重要な洞察は、追加のデータ構造や並べ替えが必要ないことを認識することです。 すべての小文字は変換に等しく価値があるため、単純な左から右へのスキャンにより、予算を超過することなく予算を最大限に活用することが保証されます。 この観察により、優先順位付けや複雑な選択戦略の観点から考えることを避けることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n) | O(n) | 承認済み |
 | 最適化されたスキャン | O(n) | O(n) | 承認済み |

 どちらも O(n) であり、n ≤ 50 であるため、スキャン方法で十分です。 

## アルゴリズムのチュートリアル

 1. 入力文字列とバジェット整数を読み取ります。 
2. 空の結果リストを初期化します。 文字列は不変であるため、Python では文字ごとの変更にはリストが推奨されます。 
3. 入力文字列内の各文字を繰り返し処理します。 
4. 各文字について、それが小文字であるかどうかを確認します。 小文字で予算が 0 より大きい場合は、大文字に変換して予算を減らします。 それ以外の場合は、文字を変更しないでください。 
5. 処理された各文字を結果リストに追加します。 
6. すべての文字を処理した後、リストを 1 つの文字列に結合して出力します。 

これが機能する理由は単純です。アルゴリズムは、どの時点でも、変換された小文字の数がバジェットを超えないという不変条件を維持します。 各小文字は予算が残っている場合にのみ変換され、大文字は変更されません。 これにより、結果の文字列が有効であることが保証され、大文字変換が最大化されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

s = input().strip()
k = int(input().strip())

result = []

for ch in s:
    if 'a' <= ch <= 'z' and k > 0:
        result.append(ch.upper())
        k -= 1
    else:
        result.append(ch)

print("".join(result))
```このソリューションは、次を使用して入力を効率的に読み取ります。`sys.stdin.readline`そして末尾の改行文字を取り除きます。 この反復では、各文字が小文字の ASCII 範囲に対して明示的にチェックされるため、次のような間違いが回避されます。`str.islower()`非 ASCII 文字で誤動作する。 コンバージョンが発生した場合にのみ予算を減らすことで、不変条件が確実に保持されます。 結果の構築にリストを使用すると、Python では速度が低下する文字列連結の繰り返しを回避できます。

 | 測定 | 複雑さ | 説明 |

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    s = input().strip()
    k = int(input().strip())
    result = []
    for ch in s:
        if 'a' <= ch <= 'z' and k > 0:
            result.append(ch.upper())
            k -= 1
        else:
            result.append(ch)
    return "".join(result)

# provided sample
assert run("AprilFool\n14\n") == "APRILFOOL", "sample 1"

# custom cases
assert run("xyz\n0\n") == "xyz", "zero budget"
assert run("abcXYZ\n2\n") == "ABcXYZ", "partial budget usage"
assert run("abcdef\n26\n") == "ABCDEF", "full budget usage"
assert run("ABCDEFGHIJKLMNOPQRSTUVWXYZ\n10\n") == "ABCDEFGHIJKLMNOPQRSTUVWXYZ", "all uppercase input"
assert run("aAaaA\n3\n") == "AAAaA", "mixed letters with limited budget"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | "xyz\n0" | "xyz" | 予算ゼロの場合 |
 | "abcXYZ\n2" | "ABcXYZ" | 大文字と小文字が混在した部分的な予算の使用 |
 | "abcdef\n26" | "ABCDEF" | 予算が小文字の数を超えています |
 | "ABCDEFGHIJKLMNOPQRSTUVWXYZ\n10" | "ABCDEFGHIJKLMNOPQRSTUVWXYZ" | すべて大文字で入力 |
 | "aAaaA\n3" | 「ああああ」 | 限られた予算での混合文字 |

 ## 特殊なケース

 バジェットがゼロの文字列の場合、アルゴリズムはすべての文字を変更しないままにします。 予算では変換が許可されていないため、「xyz\n0」と入力すると「xyz」が生成されます。 「abc\n5」など、予算よりも小文字の数が少ない文字列の場合、すべての小文字が変換され、残りの予算は使用されません。 大文字のみを含む文字列の場合、バジェットは無関係であり、文字列がそのまま返されます。 これらのシナリオは、反復内の条件チェックによって自動的に処理されます。
