 ## 問題の理解

 バイナリで表現された整数と、ビット数に基づく単純な変換を使用しています。 

すべての整数に対して$k$1 から最大までの範囲$2^n - 1$, 数値をバイナリ表現で設定されたビット数に繰り返し置き換える処理を実行します。 これが機能です$f(k)$。 その過程で、訪問したすべての値が配列内の寄与を受け取ります。$a$。 まず、から始めると、$k$に 1 を加えます$a[k]$、次にジャンプします$f(k)$、再度 1 を追加し、適用される定点に達するまで続行します。$f$値は変更されなくなりました。 

なぜなら$f(k)$はポップカウントであり、すべての正の整数には少なくとも 1 つの設定ビットがあり、ポップカウント 1 が 1 であるため、繰り返し適用すると常に値が減少するか小さく保たれ、最終的には 1 で安定します。 

配列$a$1 から 2 までのすべての値に対してインデックスが付けられます。$2^n - 1$。 ただし、変換の構造は、大きなインデックスが均一に動作することを意味します。つまり、値が超過すると、$n$、彼らの貢献は些細なものになり、事実上予測可能なパターンに崩壊します。 タスクは、の最終値を計算することです。$a[i]$のために$i \le n$すべてを明示的にシミュレートせずに、$2^n - 1$出発点。 

制約$n \le 60$がキー信号です。 までのすべての数値を反復するソリューション$2^n$さえ不可能なので、$2^{60}$計算の範囲をはるかに超えています。 代わりに、ビット数に関する組み合わせ論の観点から完全に作業する必要があります。 

小さなインデックス間のドメイン分割の誤解から微妙なエッジケースが発生する$\le n$そして大きなインデックス$> n$。 たとえば、次のようなとき$n = 3$数値の範囲は最大 7 です。単純に寄与をシミュレートすると、遷移を二重にカウントし、すべての大きな値が小さなセットのポップカウント状態に集中するという事実を見逃してしまいます。 各数値がその最終固定点にのみ寄与すると仮定すると、別の問題が発生します。 チェーンに沿った中間の貢献は不可欠であり、答えの構造を支配します。

 ## アルゴリズムのチュートリアル

 個々の数値について考えることから、各「ポップカウント レイヤー」にいくつの数値が存在するかについて考えることに切り替えます。 

させて$C[n][k]$内の整数の数を示します$[0, 2^n - 1]$それはまさに$k$ビットを設定します。 これは単純に、$\binom{n}{k}$。 

それぞれについても必要です$k$、内の整数の数$[1, n]$そのバイナリ表現には正確に次のものが含まれます$k$もの。 これは、固定された上限を超える標準のビット単位の数字 DP を使用して計算されます。$n$。 

これら 2 つの要素がわかったら、ポップカウント レベルを大から小まで処理して答えを再構築します。 

### ステップ

 1. すべての二項係数を計算します。$C[n][k]$のために$0 \le n \le 60$。 これにより、次の合計数が得られます。$n$-bit 整数と各ポップカウント値。 
2. コンピューティング$\text{cntBad}[k]$、内の整数の数$[1, n]$そのバイナリ表現は正確に$k$ビットを設定します。 これは、整数のビットに対する数字 DP を使用して行われます。$n$、制限されたまま配置したものの数を追跡します。 
3. 配列を初期化する$a$サイズの$n+1$ゼロ付き。 これにより、関心のあるインデックスへの寄与が蓄積されます。 
4. プロセス値$k$から$n$各ステップで、これをすべてのバイナリ文字列からの寄与を正確に分配すると解釈します。$k$もの。 
5. それぞれについて$k$、有効なソースの有効数を次のように計算します。$C[n][k] - \text{cntBad}[k]$。 これにより、制限されたプレフィックス範囲に該当し、問題の小さいインデックスの部分ですでに考慮されている構成が削除されます。 
6. この値を$a[k]$なぜなら、そのような構成はすべて、対応するポップカウント層で 1 つのユニットに寄与するからです。 

### なぜ効果があるのか

 繰り返し適用することで定義される変換$f(k)$あらゆる数値をポップカウント削減の決定論的なチェーンに分割します。 すべての整数はチェーン内のステップごとに 1 回だけ寄与し、チェーンは連続するポップカウントのみに依存します。 

すべての整数を初期ポップカウントでグループ化することで、各グループがその開始層に均一に寄与するようにします。 補正項は、制限された範囲に属する数値のサブセットを分離します。$[1, n]$、個別に処理される寄付を二重にカウントしないようにします。 ポップカウントは固定点を除いて厳密に減少するため、大きい値からの後方累積は$k$小さくする$k$すべてのフローを循環や欠落なく正確に集約します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXB = 60

# binomial coefficients
C = [[0] * (MAXB + 1) for _ in range(MAXB + 1)]
for i in range(MAXB + 1):
    C[i][0] = 1
    for j in range(1, i + 1):
        C[i][j] = C[i - 1][j] + C[i - 1][j - 1]

def count_up_to_n_by_popcount(x, n_bits=MAXB):
    # returns array cnt[k] = numbers in [0, x] with popcount k
    bits = list(map(int, bin(x)[2:]))
    m = len(bits)

    from functools import lru_cache

    @lru_cache(None)
    def dp(i, tight, used):
        if i == m:
            return [1] + [0] * n_bits

        res = [0] * (n_bits + 1)
        limit = bits[i] if tight else 1

        for b in range(limit + 1):
            sub = dp(i + 1, tight and (b == limit), used + b)
            for k in range(n_bits + 1):
                res[k] += sub[k]

        return res

    return dp(0, True, 0)

def solve():
    n = int(input().strip())

    cnt_bad = [0] * (n + 1)
    cnt = count_up_to_n_by_popcount(n)

    for k in range(n + 1):
        if k <= n:
            cnt_bad[k] = cnt[k]

    a = [0] * (n + 1)

    for k in range(n, 0, -1):
        total = C[n][k]
        bad = cnt_bad[k]
        a[k] = total - bad

    print(*a[1:n + 1])

if __name__ == "__main__":
    solve()
```すべての遷移は最終的に 1 の数でグループ化されたバイナリ文字列のカウントに依存するため、二項テーブルは一度事前計算されます。 数字 DP は、境界までの整数の数を計算します。$n$これは、ソリューションの唯一の非組み合わせ部分です。 

からの逆ループ$n$1 に設定すると、ポップカウントのより高い寄与がより低いポップカウントの寄与の前に解決され、繰り返されるポップカウント操作によって値が崩壊する方向と一致します。 

よくある間違いは治療することです$n$数値の境界としてではなく、ビット長の制限として$[1, n]$。 DP は数値境界を明示的に処理します。これは正確さを保つために不可欠です。

def run(inp: str) -> str:

    for i in range(MAXB + 1):
        C[i][0] = 1
        for j in range(1, i + 1):
            C[i][j] = C[i - 1][j] + C[i - 1][j - 1]

    def solve():

        cnt_bad = [0] * (n + 1)

            bits = list(map(int, bin(x)[2:]))

            from functools import lru_cache

            @lru_cache(None)

 ## 特殊なケース

 エッジケースの 1 つは非常に小さなものから発生します$n$、範囲は$[1, n]$完全な組み合わせ宇宙とほぼ完全に重複します。 のために$n = 1$、唯一の数値は 1 であり、これはすぐに満たされます。$f(1)=1$。 グローバル カウントと制限されたカウントの両方が正確に一致するため、このアルゴリズムではどこでも寄与がゼロになります。 

もう 1 つのエッジケースは次のような場合です$n$二項係数が自明ではなくなるほど十分に大きいですが、それでもはるかに下回ります$2^n$。 この体制では、素朴な直観は一様な分布を示唆しますが、数字 DP は、数が$[1, n]$低いポップカウント値に偏ります。 引き算$C[n][k] - \text{cntBad}[k]$はこの不均衡を正しく保存し、実際には小さな整数に属する質量を上位層が誤って蓄積しないようにします。
