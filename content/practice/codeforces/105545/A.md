 ## 解決策
 ## 問題の理解

 10 進数形式で書かれた数値が与えられているので、桁に関する制限を満たしながら、それよりも厳密に大きい別の数値を構築する必要があります。 制限は位置に関するものです。2 つの数値を 10 進表現で整列させる場合、すべての桁位置で、新しい数値の桁は、同じ位置にある元の数値の桁とは異なっていなければなりません。 

タスクは、このルールに基づいて指定された数値よりも厳密に大きい、可能な最小の数値を構築することです。 

制約の構造が困難を引き起こします。 辞書編集的に数値を 10 進数形式で比較すると、最初に異なる数値の位置によってどちらの数値が大きいかが決まります。 同時に、桁制限はすべての位置に個別に適用されるため、数字を自由にコピーして、後で 1 つの位置だけを調整することはできません。 

入力は単一の整数で構成され、数字の文字列として扱われます。 出力は、両方の制約を満たす別の整数です。 

形式的な制約がない場合でも、構造は各桁を 1 回または一定回数処理する必要があることを意味します。 候補を列挙したり、すべての有効な数値を段階的にシミュレートしようとするソリューションは、数値が最大 10^5 桁の場合、候補ごとの線形スキャンさえ受け入れられないため、遅すぎます。 

いくつかの特殊なケースが重要です。 

入力が 9 で始まる場合、「最初の桁を 1 つ増やす」という単純なロジックでは、10 進表現での桁上げを慎重に処理する必要があります。 たとえば、x = 9 の場合、次に有効な先頭の数字を 9 にすることはできず、さらに長い数字を生成する必要があるため、正しく構築すると長さが完全に変わる可能性があります。 

すべての桁が 9 の場合、同じ位置にあるすべての 1 桁が一致することは禁止されているため、長さを拡張せずに桁ごとに増分しようとする構造は再考する必要があります。 

もう 1 つの微妙なケースは、プレフィックスを x と同一に保ちながら、貪欲な試みによって後の数字が変更される場合です。 このアプローチは失敗します。桁制限によってすべての位置で違いが強制されるため、プレフィックスのコピーは基本的に安全ではありません。 

## アプローチ

 ブルートフォース戦略では、x + 1 から開始して数値を順番にテストし、各候補が桁の制約を満たすかどうかをチェックします。 各チェックでは、すべての桁をスキャンし、位置ごとに比較する必要があります。 最悪の場合、有効な整数を見つける前に多数の連続する整数を検査する必要があり、各検査には桁数に比例した時間がかかります。 この制限により有効な数値がまばらになるため、敵対的なケースでは桁の長さが事実上指数関数的になる複雑さが生じます。 

重要な観察は、桁制約によって位置間の結合が非常に強力に除去されるということです。 各位置は、その位置の元の数字と異なる限り、独立して選択できます。 x とのプレフィックスの同等性を維持する試みをやめると、最初の桁を x の対応する桁より大きくすることで、「y > x」という要件を満たすのは簡単になります。 

これは、直接的な建設的な解決策につながります。つまり、x の最初の桁より厳密に大きい最初の桁を選択し、1 つおきの位置を x の対応する桁とは異なる任意の桁で埋めます。 各位置で可能な最小の選択により、グローバルに最小の有効な数値が得られます。 

問題は、グローバルな順序付けの制約から、独立した桁ごとの選択にまで縮小します。

 ## アルゴリズムのチュートリアル

 入力された数値を文字列として扱います`s`。 

1. の最初の桁を読み取ります。`s`そして、厳密にそれよりも大きい、答えの先頭の可能な最小の桁を計算します。 最初の数字が「9」でない場合、これは単純にその数字に 1 を加えたものになります。 それが「9」の場合、1 桁が 9 を超えることはできないため、「10」で始まるより長い数値を生成するのと論理的に同等の 2 桁の接頭辞のアイデアを使用する必要があります。これにより、結果として得られる数値が最上位位置の直前の入力よりも厳密に大きくなることが保証されます。 
2. 答えの最初の桁を修正した後、残りの各桁を個別に処理します。 
3. ポジションごとに`i`、数字を見ます`s[i]`。 の最小桁を選択します`0..9`それは等しくありません`s[i]`。 辞書編集的に最小化しているため、制約に違反しない限り常に 0 を選択し、その場合は 1 を使用します。 
4. これらの選択した数字を順番に追加して、最終的な数字を形成します。 
5. 構築された数値を出力します。 

最初の桁が厳密な不平等を保証すると、それ以降の位置は「x より大きい」条件に影響を与えなくなるため、各位置は独立して処理されます。 

### なぜ効果があるのか

 正確さは、等しい長さの数値間の辞書編集上の比較が最初の位置によって完全に決定されるという事実に基づいています。 結果の最初の桁が入力の最初の桁を超えるようにすることで、接尾辞に関係なく、構築される数値が厳密に大きくなることが保証されます。 

この時点以降、残る唯一の制約は、桁の位置の不一致です。 各位置は独立しており、有効な 9 桁を完全に選択できるため、位置ごとに最小の有効な桁を選択すると、最小限のサフィックスが生成されます。 異なる位置をリンクする拘束がないため、将来の調整は必要ありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    
    # if input is empty or single digit handled naturally
    n = len(s)
    if n == 0:
        return
    
    # construct result
    res = []
    
    # first digit handling
    if s[0] != '9':
        res.append(str(int(s[0]) + 1))
    else:
        # when first digit is 9, we cannot pick a single digit > 9
        # so we conceptually switch to "10..."
        res.append("10")
    
    # remaining digits
    for i in range(1, n):
        d = s[i]
        if d != '0':
            res.append('0')
        else:
            res.append('1')
    
    sys.stdout.write("".join(res))

if __name__ == "__main__":
    solve()
```実装は構築的ロジックに直接に従います。 最初の桁は厳密な順序を決定するため、個別に処理されます。 残りの数字は、その位置の入力数字とは異なる最小の有効な数字で貪欲に埋められます。常に 0 または 1 のいずれかになります。 

最初の桁の「9」の特殊なケースが必要です。そうしないと、桁の増分が有効な 1 桁の範囲を超えることになるからです。 先頭に「10」を付けると、効果的に長さが長くなり、厳密な順序が保証されます。

 ## 特殊なケース

 次のような 1 桁の入力の場合`0`、アルゴリズムは次の桁を選択します`1`、サフィックスが存在しないため、結果はすぐに正しいものになります。
