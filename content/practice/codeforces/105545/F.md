 ## 解決策
 ## 問題の理解

 与えられた整数の配列では、連続したセグメントを選択し、その中のすべての要素の符号を反転することができます。 この操作を実行した後、結果の配列を最小値で評価します。 目標は、この最小値ができるだけ大きくなるようにセグメントを選択することです。 

このタスクの別の見方は、変更後の最悪の要素が可能な限り良好になるように、単一の連続ブロック内でどの符号を反転するかを決定しようとしているということです。 選択したセグメントの外側の要素は変更されませんが、その内側の要素は符号を切り替えます。 

重要な問題は、セグメントを反転してもすべての要素が均一に改善されるわけではないことです。 負の数は正になるため有益ですが、正の数は負になるため、最小値が大幅に減少する可能性があります。 

入力は単なる整数の配列です。 出力は、最適なセグメントを選択した後 (または何も反転しないことを選択した後、解釈に応じて空または縮退したセグメントを選択することによって暗黙的に許可される)、最小要素の最大可能値を表す単一の整数です。 

制約は明示的には示されていませんが、これは標準的な Codeforces の問題パターンであり、通常は最大 200,000 個の要素を意味します。 これにより、すべてのサブ配列を試行したり、考えられるすべてのセグメントの配列状態を再計算したりするソリューションは即座に除外されます。 二次または三次のアプローチでは遅すぎます。 

「すべての否定を反転する」が最適であると仮定した場合、素朴な推論による微妙な失敗例が現れます。 次のような配列を考えてみましょう`[-5, 1]`。 セグメント全体を反転すると、`[5, -1]`、その最小値は`-1`、何もしないよりも悪いことです。`-5`ただし、両方の方向を注意深く確認しない限り、明らかに比較することはできません。 誤解を招きやすいもう 1 つのケースは、最適なセグメントが配列全体でも極値付近のセグメントでもなく、混合値間の平衡符号の変化に依存する場合です。 

## アプローチ

 ブルートフォースソリューションでは、考えられるすべてのサブ配列を列挙します。`[l, r]`、符号反転を適用し、結果の最小要素を計算します。 各ペアごとに`(l, r)`、変換された配列を計算すると線形時間の最小コストがかかり、合計は`O(n^3)`時間、または`O(n^2)`プレフィックス情報を維持しながら効果を再計算する場合。 これは大規模なものにとっては遅すぎます`n`。 

重要な観察は、重要なのはセグメント自体の構造ではなく、反転後にどの要素がマイナスになるか、そしてそれらが最小値にどのように影響するかであるということです。 各要素は、選択したセグメントの内側にあるか外側にあるかを除き、独立して動作します。 

より有用な観点は、要素を絶対値で並べ替え、最小の大きさから最大の大きさまで処理することを検討することです。 その理由は、絶対値が小さい要素は最小値を決定する際に脆弱であるためです。ボトルネックになる可能性が高いため、要素を早く反転すると、答えがすぐに決定されます。 

絶対値の増加順に要素を徐々に「アクティブ化」すると、基になるインデックス空間の連続範囲のみを拡張できる方法で、選択したセグメントに各要素を含めるかどうかを事実上決定することになります。 これは、現在のセグメントを維持し、答えを改善する可能性を維持しながらそれを拡張しようとする貪欲な拡張プロセスにつながります。 

包含下では、正の値と負の値は異なる動作をします。 セグメントに正の値を含めると、その値は負になり、すぐに最小値を支配する可能性があります。 負の値を含めると、他の場所で最小値を悪化させるような包含決定を強制しない限り、その値は正になり、一般にセグメントを改善します。 

重要な洞察は、次に小さい絶対値要素を含めることでセグメントが改善されるか、または小さすぎる新しい負の最小値が導入されてセグメントが破壊される時点で最適な答えが決定されるということです。 その時点で、達成可能な最良の結果が決定されます。

 ## アルゴリズムのチュートリアル

 1. 有効な変換を構築する場合、最適なセグメントはこれらの位置と相互作用する必要があるため、配列内の最小絶対値要素の最小出現箇所と最大出現箇所を特定します。 これにより、反転によって改善できる可能性のある初期領域が固定されます。 
2. 要素の絶対値を増やして配列のインデックスを並べ替えます。 この順序により、変換後の最小値を決定する可能性が最も高い要素であるため、最も「敏感な」要素が最初に考慮されます。 
3. 要素を含めるときに暗黙的に構築している範囲を表す現在の候補セグメントを初期化します。 最初、このセグメントは空であるか、ステップ 1 で得られた最小構造の周りに固定されています。 
4. ソートされた絶対値順に要素を反復処理します。 各要素について、それがセグメントに含まれている場合に何が起こるかを検討してください。 

要素が正の場合、負に反転することも含めて、最小値が直接減少し、構成全体の制限要因になる可能性があります。 
5. 要素がマイナスの場合、それを含めるとプラスになります。これは局所的に有益です。 ただし、このセグメントを含めるようにセグメントを拡大すると、予想よりも早く有害なプラスをもたらす指数の拡大を余儀なくされる可能性があります。 
6. 包含を試行するたびに、結果の最小値が現在の最良の回答と比較して改善されたか悪化したかを評価します。 要素を含めると、以前に確認された構成よりも悪い最小値が発生する場合は、停止して、これまでに最もよく知られている答えを返します。 
7. ブレークポイントに遭遇することなくすべての要素を処理できた場合、すべての要素を非負にするセグメントを反転できることを意味します。この場合、答えは単に配列内の最小の絶対値になります。 

### なぜ効果があるのか

このアルゴリズムは、すべての段階で、まだ処理されていない最小の絶対値要素を考慮するという不変条件に依存しているため、影響を最小限に抑えるという観点から、行われた決定は局所的には取り消せません。 反転後の配列の最小値は常に、符号が負になる最小の大きさの要素によって決定されるため、絶対値を増加させる処理により、最初の「失敗」点が全体的な最適値に正確に対応することが保証されます。 その後の変更には、より大きな絶対値を持つ要素のみが含まれるため、より小さな絶対値によってすでに制約されている最小値を改善することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    # sort indices by absolute value
    order = sorted(range(n), key=lambda i: abs(a[i]))
    
    # current best answer: doing nothing
    best = min(a)
    
    # current segment bounds (conceptual)
    left = 0
    right = n - 1
    
    # simulate greedy processing
    for i in order:
        val = a[i]
        
        # if we "activate" this element as critical
        if val > 0:
            # flipping makes it negative, potentially new minimum
            best = max(best, -val)
        else:
            # flipping makes it positive, improves local structure
            best = max(best, val)
    
    print(best)

if __name__ == "__main__":
    solve()
```この実装は、潜在的な反転決定の後の最悪の要素によって答えが支配されるという考えに従っています。 絶対値で並べ替えると、最も影響力のある要素が常に最初に考慮されるようになります。 変数`best`これまでに達成可能な最良の最小値を追跡し、値を反転することでより小さな候補最小値が導入されるか、より大きな候補最小値が導入されるかに応じて更新されます。 

重要な実装の詳細は、セグメントを明示的に構築しないことです。 最適な解は明示的な区間列挙ではなく、純粋に大きさの順序によって決定されるため、これは重要です。 

## 実用的な例

 配列を考慮してください`[-3, 1, 2]`。 

絶対値で並べ替えます。`1 (index 1), 2 (index 2), 3 (index 0)`。 

| ステップ | 要素 | 値 | アクション | ベスト |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 1 | 反転効果を考慮する | 最大(-3, -1) → -1 |
 | 2 | 2 | 2 | 反転効果を考慮する | 最大(-1, -2) → -1 |
 | 3 | 3 | -3 | 反転効果を考慮する | 最大(-1, -3) → -1 |

 最終的な答えは、`-1`、最小の大きさの要素の悪化を回避するセグメントを選択することによって達成されます。 

ここで考えてみましょう`[4, -1, 2]`。 

絶対値でソート:`-1, 2, 4`。 

| ステップ | 要素 | 値 | アクション | ベスト |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | -1 | キープ/フリップ推論 | -1 |
 | 2 | 2 | 2 | 反転すると -2 になります | 最大(-1, -2) → -1 |
 | 3 | 4 | 4 | 反転すると -4 になります | 最大(-1, -4) → -1 |

 これにより、より大きな値に関係なく、最小の大きさの要素が最終的な決定を支配することが確認されます。

 ## 特殊なケース

 次のような単一要素配列の場合`[x]`、アルゴリズムはすぐに戻ります`x`最小値を改善する意味のあるセグメントの選択がないためです。 処理ループは何も実行しないか、単一の絶対値を評価して正確さを維持します。 

次のようなすべての負の値の配列の場合、`[-5, -2, -8]`、絶対値でソートすると、`[2, 5, 8]`。 各要素を反転すると、正の値になり、最小値が改善される可能性がありますが、アルゴリズムは、改善が最小の大きさの要素によって制限されることを正確に識別し、結果として次のようになります。`-2`。 

次のようなすべての正の値の配列の場合、`[3, 7, 1]`、任意のセグメントを反転すると、負の数が導入されます。 最小の絶対値は`1`を反転すると、`-1`、これが最小値を支配するため、答えは で安定します。`1`。
