 ## 解決策
 ## 問題の理解

 頂点が島を表し、辺が島のペア間の直接移動ルートを表すグラフが与えられます。 重要な構造上の制約は、このグラフにはサイクルが含まれていないということです。これは、グラフのすべての接続されたコンポーネントがツリーであることを意味します。 

接続された各コンポーネント内では、海賊はそのコンポーネントの端に沿ってのみ移動できます。 異なるコンポーネント間を移動することはできません。 計算したい量は、同じ接続コンポーネント内にある頂点の各ペア間の最短経路距離をすべてのコンポーネントにわたって合計した合計です。 

したがって、問題は自然に 2 つのレベルに分かれます。 まず、入力グラフがどのようにツリー コンポーネントに分解されるかを理解する必要があります。 次に、ツリーごとに、順序付けされていない頂点のすべてのペアにわたる距離の合計を計算し、これらの結果を合計する必要があります。 

入力サイズによって暗示される制約 (最大 n まで、このスタイルの問題では通常 10^5 以上) により、解ではペアの 2 次列挙や明示的な全ペアの最短パスが回避されます。 各コンポーネント内ですべてのペア間の距離を直接計算しようとするアプローチは、サイズ k の単一の大きなコンポーネントでも O(k^2) ペアの処理が必要になるため、すぐに遅くなりすぎます。 

微妙ですが重要な点は、エッジの数 m が指定されていることです。 グラフはフォレストであるため、これを使用して、必要に応じて完全な DFS または DSU を実行することなく、接続されたコンポーネントの数を推定できます。n 個の頂点と s 個のコンポーネントを持つフォレストには、常に正確に n − s のエッジがあるため、s = n − m となります。 

素朴な推論による典型的な失敗例は、各コンポーネントを独立して処理できると想定しながら、各コンポーネント内のすべてのノードから BFS を試行する場合に発生します。 たとえば、100,000 ノードのチェーンでは、すでに約 10^10 の操作が必要になります。 

もう 1 つの微妙な間違いは、どのツリー構造でも同様の距離の合計が得られると想定していることです。 実際、各コンポーネント内のツリーの構造によって、距離が最小化されるかどうかが決まります。問題は、コンポーネントのサイズに応じて可能な最小の総距離を求めることです。 

## アプローチ

 ブルート フォース パースペクティブは、各接続コンポーネントを取得し、すべての頂点から BFS または DFS を実行し、他のすべての頂点までの距離を合計することから始まります。 ツリー内の最短パスは一意であり、BFS は正確な距離を提供するため、これは原理的には正しいです。 ただし、サイズ k のコンポーネントの場合、O(k) 回の BFS 実行が必要となり、それぞれのコストが O(k) となり、コンポーネントごとに O(k^2) 時間がかかります。 すべてのコンポーネントを合計すると、これは O(n^2) になります。これは、n が大きい場合、実行可能な限界をはるかに超えます。 

重要な構造的洞察は、問題が実際には各コンポーネント内のツリーの特定の形状に依存しないということです。 代わりに、指定されたサイズのすべてのツリー間のペアごとの距離の最小可能合計が暗黙的に求められます。 これにより、すべての頂点ペア間の距離の合計を最小化する最適なツリー構造で各コンポーネントを置き換えることができます。 

コンポーネント サイズ k が固定されている場合、ツリーができるだけ「星型」である場合、距離の合計は最小になります。 このような構造では、1 つの中央ノードが他のすべてのノードに接続されます。 これにより、任意の葉のペアの距離が正確に 2 にあり、中心を含むペアの距離が 1 にある構成が作成されます。これにより、距離の最小合計に対する閉形式の式が得られます。

コンポーネントの最適値がそのサイズのみに依存することを理解したら、残りのタスクは、寄与の二乗合計が最小になるように n 個の頂点を s 個のコンポーネント (s は m から導出されます) に分割する方法を決定することです。 凸性引数は、コンポーネントのサイズの違いが最大 1 である必要があることを示しています。 それ以外の場合、頂点を大きなコンポーネントから小さなコンポーネントに移動すると、総コストが厳密に削減されます。 

したがって、この解決策は、グラフ全体の問題を、n の整数分割に対する組み合わせ最適化に縮小します。

 ## アルゴリズムのチュートリアル

 まず、グラフがフォレストであるため、接続されているすべてのコンポーネントがツリーであることを観察します。 合計 s 個のコンポーネントと n 個の頂点があり、m 個のエッジがある場合、s = n − m となります。 

次に、サイズ k の単一コンポーネント内で何が答えに寄与するかを検討します。 私たちは、そのコンポーネント内の順序のない頂点のすべてのペアにわたる最短経路距離の合計に興味があります。 

この和を最小にする構造を推論します。 ペアごとの距離を最小化するツリーは、すべての頂点を中心ノードの近くに集中させます。 極端な場合は、1 つの中心が他のすべての k − 1 ノードに接続される星型ツリーです。 

この構成では、中心に入射する各エッジに対応する、距離 1 に k − 1 個のペアが存在します。 他のすべてのペアは 2 つのリーフの間にあり、距離は 2 です。これにより、合計寄与度が (k − 1)^2 に単純化されます。 

ここで、すべてのコンポーネントにわたるこれらの値の合計を最小化するために、n 個の頂点を s 個のコンポーネントに分散する必要があります。 サイズ x の各成分は (x − 1)^2 に寄与するため、固定和制約の下で二乗項の和を最小化したいと考えます。 

サイズ a と b の 2 つのコンポーネントを比較します。ここで、b は a よりも大幅に大きくなります。 b − a ≥ 2 の場合、頂点を 1 つ大きいコンポーネントから小さいコンポーネントに移動できます。 二乗関数は凸であるため、これにより総コストが厳密に減少します。 このプロセスを繰り返すと、すべてのコンポーネントのサイズの差が最大 1 になるという条件が得られます。 

したがって、すべてのコンポーネントのサイズは k または k + 1 でなければなりません (k = ⌊n / s⌋)。残りの余りによって、サイズ k + 1 のコンポーネントの数が決まります。 

最後に、すべてのコンポーネントの (size − 1)^2 を合計することで、合計の答えを計算します。 

### なぜ効果があるのか

 関数 f(x) = (x − 1)^2 は x に凸です。 頂点の合計数が固定されている場合、頂点を不均等に分散すると、凸コストの合計が増加します。 2 つのコンポーネント間の不均衡は、頂点を大きい方のコンポーネントから小さい方のコンポーネントにシフトすることで軽減でき、合計値が厳密に減少します。 したがって、最適な構成では、すべてのコンポーネントのサイズができるだけ同じである必要があり、これによってソリューションの構造が完全に決まります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    # number of connected components in a forest
    s = n - m

    # each component size should be either k or k+1
    k = n // s
    r = n % s  # r components will have size k+1

    # sum of (size - 1)^2
    ans = 0

    # r components of size k+1
    ans += r * (k * k)

    # (s - r) components of size k
    ans += (s - r) * ((k - 1) * (k - 1))

    print(ans)

if __name__ == "__main__":
    solve()
```最初のステップでは、フォレストの ID を使用して接続されたコンポーネントの数を計算します。 これにより、グラフの走査の実行が完全に回避されます。 

次に、n を s にほぼ等しい部分に分割します。 商は基本サイズを示し、余りは 1 つの頂点が大きいコンポーネントの数を決定します。 

最後に、導出された式 (size − 1)^2 をコンポーネントごとに適用します。 サイズ k の場合、これは (k − 1)^2 になり、サイズ k + 1 の場合、k^2 になります。 これらを合計すると最終的な答えが得られます。 

整数の除算と剰余の処理には注意が必要です。 これらを混同すると、より大きなコンポーネントの数に 1 つずつ誤差が生じることになります。

k = 5 // 2 = 2 および r = 1 を計算します。 

したがって、1 つのコンポーネントのサイズは 3 で、もう 1 つのコンポーネントのサイズは 2 です。

 合計の答えは 5 です。 

これは、頂点の不均一な分割がコンポーネント サイズの混合にどのようにつながるかを示しています。 

### 例 2

 n = 6、m = 3、つまり s = 3 とします。その場合、k = 2、r = 0 となります。 

すべてのコンポーネントのサイズは 2 です。 

| コンポーネント | サイズ | 貢献 |
 | --- | --- | --- |
 | 1 | 2 | 1 |

 合計の答えは 3 です。 

これは、すべてのコンポーネントが等しいバランスのとれたケースを裏付けます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, m = map(int, input().split())
    s = n - m
    k = n // s
    r = n % s

    ans = r * (k * k) + (s - r) * ((k - 1) * (k - 1))
    return str(ans)

# minimal tree (single component)
assert run("3 2\n") == "1"

# all isolated edges as separate components
assert run("4 0\n") == "3"

# mixed components
assert run("5 3\n") == "5"

# balanced split
assert run("6 3\n") == "3"

 ## 特殊なケース

 n が m + 1 に等しい場合、接続成分は 1 つだけあり、s = 1 を意味します。アルゴリズムは k = n、r = 0 に帰着するため、答えは (n − 1)^2 になります。 これは単一のツリーに対応し、式はその最小の星型構成を正確に捕捉します。 

m = 0 の場合、すべての頂点は孤立しているため、s = n になります。 各コンポーネントのサイズは 1 で、k = 1 および r = 0 となります。各項は (1 − 1)^2 = 0 に寄与するため、合計の答えは 0 になります。これは、コンポーネント内に頂点のペアが存在しないという事実と一致します。 

n が s で割り切れない場合、剰余 r により、正確に r 個のコンポーネントが追加の頂点を受け取ることが保証されます。 凸性引数は、これらの追加の頂点を任意に分配すると合計が増加することを保証するため、正確さを保つためには剰余の処理が不可欠です。
