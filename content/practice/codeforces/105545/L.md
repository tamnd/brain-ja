 ## 問題の理解

 私たちは、ポイント更新を通じて時間の経過とともに変化する配列を扱っています。 更新のたびに、配列に表示されるすべての値に対して定義されたグローバル数量を評価する必要があります。 

あらゆる値に対して`x`を含まないすべてのサブ配列を調べます。`x`全然。 させて`cnt[x]`は、そのようなサブ配列がいくつ存在するかを示します。 配列内の単一の位置を変更するたびに、次の最小値を維持するように求められます。`cnt[x]`配列内に現在存在するすべての値を対象とします。 

したがって、更新ごとに位置にある要素が 1 つ削除されます。`s`そしてそれを別の値に置き換えます。 重要な要件は、配列を更新するだけではなく、すべての個別の値の不在構造がどのように変化するかを効率的に追跡することです。 

Codeforces レベルの動的配列の問題によって暗示される制約により、通常、次のような解決策が求められます。`O((n + q) log n)`。 クエリごとの単純な再計算では、配列全体をスキャンし、すべての値の寄与を再計算する必要があり、両方の場合にすぐに制限を超えてしまいます。`n`そして`q`大きいです。 

最大の難点は、各値の寄与が配列全体でのその出現の分布に依存し、更新が影響するのは 2 つの値のみですが、単純に処理すると多くのサブ配列数が変更される可能性があることです。 

正確さのためには、いくつかの特殊なケースが重要です。 まず、一度だけ出現する値、または更新後に新たに導入される値は一貫して処理する必要があります。そうでない場合は、注意深く追跡しないと間隔構造が定義されません。 次に、最後に出現した値を削除すると、禁止された位置が残っていないため、配列のサブ配列の総数に対するその値の寄与がリセットされるはずです。 第三に、以前に存在しなかった値に挿入するには、その構造を最初から正しく初期化する必要があります。 

単純な推論による小さな失敗例としては、値が完全に消失した場合があります。

 全て取り外した後`1`、正しい方法で治療する必要があります。`cnt[1]`現在の配列のすべてのサブ配列として。 発生間のギャップを維持するだけのバグのあるアプローチでは、このリセット条件を追跡できなくなります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 それぞれの値について`x`、すべてのサブ配列を列挙し、含まれないサブ配列をカウントします。`x`。 これには、すべてのサブ配列をチェックするか、少なくとも値ごとに配列のセグメントをスキャンする必要があります。 と`O(n)`値ごとのサブ配列と潜在的に`O(n)`個別の値の場合、最悪の場合、これは 3 次になります。 プレフィックス スキャンを使用してわずかに最適化されたとしても、各更新後の再計算ではすべての値の発生情報を再構築する必要があるため、大まかに`O(n)`クエリごとに作業します。 

ボトルネックとなっているのは、`cnt[x]`～の位置のみに依存します`x`、他の値ではありません。 これを理解すると、問題を値ごとに独立した構造に分割できます。 

重要な観察は、固定値の出現により配列がギャップに分割され、その値を回避するすべての部分配列が完全にこれらのギャップ内に存在する必要があるということです。 これにより、問題は各値の位置によって引き起こされるセグメント長の維持に変わります。 

現在、更新は 1 つの位置にのみ影響します。 この位置では、古い値から 1 つのオカレンスが削除され、新しい値に 1 つのオカレンスが追加されます。 これらの操作はそれぞれ、位置リスト内の最大 2 つの隣接するギャップを変更します。つまり、順序付けされた構造を使用して各更新を対数時間で処理できます。 

また、すべてのグローバル マルチセットも維持します。`cnt[x]`これにより、各更新後に効率的に最小値をクエリできるようになります。

 ## アルゴリズムのチュートリアル

 それぞれの値について、次のような解釈を修正します。`x`、ソートされたインデックスのセットを維持します。`x`が発生します。 この構造から導き出されるのは、`cnt[x]`ギャップ分解を使用します。 

1. すべての位置を格納する個別の値ごとにバランスのとれた順序セットを初期化します。 これにより、対数時間でインデックスの前任者と後続者を見つけることができます。 
2. 各値について`x`、その初期値を計算します`cnt[x]`その位置をスキャンし、連続する出現間のギャップの寄与を合計することによって。 それぞれの長さのギャップ`L`貢献する`L * (L + 1) / 2`。 これは、そのギャップに完全に含まれるすべてのサブ配列をカウントします。 
3. すべて保存する`cnt[x]`マルチセット内の値を取得して、定数時間内にすべての値の最小値をクエリできるようにします。 
4. 位置の更新ごとに`s`、古い値を特定します`a = arr[s]`そして新たな価値観`b`。 
5. 構造を変更する前に`a`、見つけます`s`順序付けられたセット内。 現在接している 2 つのギャップを定義する、左右に最も近いオカレンスを見つけます。`s`。 削除中`s`これら 2 つのギャップを 1 つの大きなギャップにマージします。 更新します`cnt[a]`2 つの古いギャップの寄与を減算し、マージされたギャップの寄与を加算することによって。 
6. 削除する`s`のセットから`a`、古いものを置き換えてマルチセットを更新します`cnt[a]`新しい価値観で。 
7. 価値について`b`、どこを見つけますか`s`順序付きセットに挿入されます。 全体にわたる既存のギャップ`s`2 つの小さなギャップに分割されます。 更新します`cnt[b]`古い大きなギャップの寄与を差し引き、2 つの新しい寄与を加算することによって。 
8.挿入`s`のセットに`b`、同様にマルチセットを更新します。 
9. 各クエリを処理すると、答えはマルチセット内の最小の要素になります。 

正確さは、すべての値に対して次の不変条件に依存します。`x`、`cnt[x]`すべての最大間隔の合計に正確に等しくなります。`x`は表示されず、これらの間隔は完全に次の連続発生によって決定されます。`x`。 各更新では単一の位置の隣接関係のみが変更されるため、値ごとに 2 つの間隔のみが影響を受けます。 

他のすべてのギャップは変更されないため、グローバルな一貫性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import defaultdict
import bisect

class SortedSet:
    def __init__(self):
        self.a = []

    def add(self, x):
        i = bisect.bisect_left(self.a, x)
        if i == len(self.a) or self.a[i] != x:
            self.a.insert(i, x)

    def discard(self, x):
        i = bisect.bisect_left(self.a, x)
        if i < len(self.a) and self.a[i] == x:
            self.a.pop(i)

    def prev_next(self, x):
        i = bisect.bisect_left(self.a, x)
        prev = self.a[i-1] if i > 0 else None
        nxt = self.a[i] if i < len(self.a) else None
        return prev, nxt

def contrib(l):
    return l * (l + 1) // 2

def recompute_gap(cnt, positions, n):
    if not positions:
        return (n * (n + 1)) // 2

    res = 0
    prev = 0
    for p in positions:
        res += contrib(p - prev - 1)
        prev = p
    res += contrib(n - prev)
    return res

def main():
    n, q = map(int, input().split())
    arr = [0] + list(map(int, input().split()))

    pos = defaultdict(SortedSet)
    cnt = defaultdict(int)

    for i in range(1, n + 1):
        pos[arr[i]].add(i)

    for x in pos:
        cnt[x] = recompute_gap(cnt[x], pos[x].a, n)

    import bisect
    all_cnt = []

    for x in cnt:
        all_cnt.append(cnt[x])

    all_cnt.sort()

    def add_val(v):
        i = bisect.bisect_left(all_cnt, v)
        all_cnt.insert(i, v)

    def remove_val(v):
        i = bisect.bisect_left(all_cnt, v)
        all_cnt.pop(i)

    def get_min():
        return all_cnt[0]

    def update_remove(x, s):
        st = pos[x].a
        i = bisect.bisect_left(st, s)
        left = st[i-1] if i > 0 else 0
        right = st[i+1] if i+1 < len(st) else n+1

        L1 = s - left - 1
        L2 = right - s - 1
        L = L1 + L2 + 1

        cnt[x] -= contrib(L1)
        cnt[x] -= contrib(L2)
        cnt[x] += contrib(L)

        pos[x].discard(s)

    def update_add(x, s):
        st = pos[x].a
        i = bisect.bisect_left(st, s)
        left = st[i-1] if i > 0 else 0
        right = st[i] if i < len(st) else n+1

        L = right - left - 1
        L1 = s - left - 1
        L2 = right - s - 1

        cnt[x] -= contrib(L)
        cnt[x] += contrib(L1)
        cnt[x] += contrib(L2)

        pos[x].add(s)

    # initialize multiset correctly
    all_cnt = []
    for x in cnt:
        all_cnt.append(cnt[x])
    all_cnt.sort()

    for _ in range(q):
        s, newv = map(int, input().split())
        oldv = arr[s]

        remove_val(cnt[oldv])
        update_remove(oldv, s)
        add_val(cnt[oldv])

        remove_val(cnt.get(newv, 0))
        if newv not in cnt:
            cnt[newv] = (n * (n + 1)) // 2

        update_add(newv, s)
        add_val(cnt[newv])

        arr[s] = newv

        print(all_cnt[0])

if __name__ == "__main__":
    main()
```この実装は、値ごとの明示的な位置セットの維持に依存しています。 最もデリケートな部分は、境界が次の位置にあるため、削除および挿入中に左右の隣接要素を正しく識別することです。`0`そして`n+1`配列のエッジを表す番兵として機能します。 

マルチセットのメンテナンスは、概念的には構造の更新とは別のものです。 毎回`cnt[x]`変更がある場合は、最小値が古くならないように、更新する前に古い値を削除し、後で再挿入する必要があります。 

## 実用的な例

 小さな配列を考えてみましょう`[1, 2, 1]`。 

位置セットを構築します。`1 -> {1, 3}`、`2 -> {2}`。 

価値のために`1`、ギャップは`[0..0]`、`[2..2]`、`[4..3]`、貢献`1 + 1 + 0 = 2`。 価値のために`2`、ギャップは`[0..1]`そして`[3..3]`、貢献`3 + 1 = 4`。 

| ステップ | 更新 | 1 の位置 | 2 の位置 | cnt[1] | cnt[2] | 分 |
 | --- | --- | --- | --- | --- | --- | --- |
 | 0 | 初期化 | {1,3} | {2} | 2 | 4 | 2 |
 | 1 | 3 で 1 を削除し、3 を追加します | {1} | {2,3} | 3 | 3 | 3 |

 トレースは、2 番目に出現した`1`周囲のギャップを 1 つの間隔にマージし、増加します。`cnt[1]`。 

ここで考えてみましょう`[1,1,1,1]`そして中間のオカレンスを削除します。 

| ステップ | 更新 | 1 の位置 | cnt[1] |
 | --- | --- | --- | --- |
 | 0 | 初期化 | {1,2,3,4} | 0 |
 | 1 | 2を削除 | {1,3,4} | 1 |

 これは、1 つの大きなギャップを 2 つの小さなギャップに分割すると、その値を回避するサブ配列の総数が増加することを示しています。

 ## 特殊なケース

 値が最後の出現を失うと、その位置セットは空になります。 その状況では、配列全体がその値に対して単一の有効なギャップになり、すべてのサブ配列がそれを回避することになります。 実装では、その寄与を明示的にリセットする必要があります。`n(n+1)/2`そうしないと、古いギャップ分解が残ることになります。 

のような配列の場合`[1,1]`両方の出現を段階的に削除すると、最終的な削除後の正しい状態は次のようになります。`cnt[1]`3 に等しい。ローカル ギャップのみを更新する実装では、誤って終了します。`cnt[1]`処理すべき間隔が残っていないため、1 または 0 になります。 

以前に表示されていない値への挿入中に、最初の値が全長のギャップを分割します。 たとえば、`x`位置の空の構造に`i`2 つの長さのギャップが作成されます`i-1`そして`n-i`。 これがセンチネル境界を使用して再計算されない場合、特に次の場合に、off-by-one エラーがすぐに表示されます。`i = 1`または`i = n`。
