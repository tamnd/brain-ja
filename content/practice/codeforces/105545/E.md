 ## 解決策
 ## 問題の理解

 通路によって接続された位置を表す無向グラフが与えられます。 タスクは、完全に探索してエントリ ポイントに戻ることができる領域に繰り返し入った場合に、このグラフのどの部分が引き続き使用できるかを判断することですが、グラフの残りの部分に戻る方法のない場所で立ち往生するわけにはいきません。 

重要な考え方は、一部の頂点は事実上行き止まりであるということです。頂点に入ると、他の未踏のエッジを通って戻るパスは保証できません。 問題の出力は、そのような「安全でない」頂点をすべて削除した後の残りのサブグラフです。ここで、残りのすべての頂点は、閉じ込められることなく出入りできる構造の一部です。 

入力サイズは、最悪の場合、最大約 200,000 個の頂点とエッジを持つグラフを意味します。 これにより、考えられるすべての走査をシミュレートしようとするアプローチや、すべての頂点から独立して検索を実行しようとするアプローチが即座に除外されます。 O(n²) でさえすでに遅すぎるため、どのようなソリューションも、グラフのサイズ (通常は O(n + m)) で線形または線形に近い時間で実行する必要があります。 

微妙なケースは、グラフがほぼサイクルのように見えても、ぶら下がった木が付いている場合に発生します。 2 つの頂点のチェーンが 1 つのノードにアタッチされている 4 つの頂点のサイクルを考えてみましょう。 チェーンの頂点はどのサイクルにも含まれていないため、一方の側からの到達可能性のみをチェックする場合、単純な直感で誤って頂点が保持される可能性があります。 ただし、これらの頂点に入ると、同じパスに沿って後戻りする必要があるため、行き止まりになります。 

もう 1 つの注意が必要なケースは、2 つの頂点の間に 1 つのエッジがある場合です。 両方の頂点は技術的には接続されていますが、どちらの頂点も、より大きな構造内で意味のある「入口と出口」の動作を許可していないため、解釈によっては、定義で 2 ノードのサイクルのような構造が明示的に許可されていない限り、反復枝刈りに耐えられないはずです。 

## アプローチ

 この問題を考える強引な方法は、探索のアイデアを直接シミュレートすることです。 すべての頂点について、その頂点に入り、別の場所で探索を続けながらそこに戻ることができるかどうかを確認しようとします。 これは、各ノードから DFS または BFS を実行し、最後のエッジをリトレースせずに戻ることができるサイクルまたは代替ルートが存在するかどうかを確認することを示唆しています。 

このような各チェックには O(n + m) のコストがかかる可能性があり、すべての頂点に対してこれを実行すると O(n(n + m)) となり、制限をはるかに超えているため、これはすぐにコストが高くなります。 

重要な構造上の観察は、「入って戻る」機能は、強制エンドポイントとなる頂点がないコンポーネントに属することと同等であるということです。 グラフ用語で言えば、安全な頂点とは、反復枝刈りプロセスの意味で葉ではない頂点です。頂点の次数が 1 である場合、その頂点は、後戻りせずに再訪できるようなサイクルのような構造の一部になることはできません。 このような頂点が削除されると、その隣接頂点も同様に葉になり、効果が内側に伝播する可能性があります。 

これにより、安定するまで次数 1 の頂点を繰り返し削除するという問題が軽減されます。 残るのは、すべての頂点が少なくとも 2 次を持つサブグラフです。これは、グラフのすべてのサイクルを含む部分の和集合に対応し、多くの場合、グラフの 2 コアと呼ばれます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n(n + m)) | O(n + m) | 遅すぎる |
 | 葉の剪定（2芯） | O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

1. グラフの隣接リスト表現を構築し、すべての頂点の次数を計算します。 これが必要なのは、プロセス全体が各頂点が現在持っているエッジの数のみに依存するためです。 
2. 次数が正確に 1 であるすべての頂点を含むキューを初期化します。これらは、そこに入ると単一の出口パスを強制的に戻されるため、即行き止まりになります。 
3. キューから頂点を繰り返し削除します。 頂点が削除されると、概念的にはその頂点がグラフから削除され、そのすべての近傍の次数が減少します。 これは、行き止まりを切断し、新しい行き止まりになるものを更新することをシミュレートします。 
4. その結果、いずれかの近隣の次数が 1 に下がった場合は、それをキューに追加します。 これは、1 つの葉を剪定することで別の葉がどのように作成されるかを示す伝播ステップです。 
5. キューに次数 1 の頂点がなくなるまで続行します。 この時点で、縮小されたグラフでは、残りのすべての頂点の次数が少なくとも 2 になります。 
6. このプロセス中に削除されなかったすべての頂点を出力します。 

この貪欲な削除が機能する主な理由は、プロセス中にリーフになる頂点は、リターンが保証されたトラバースを可能にする構造に属せないためです。 サイクル内の頂点は常にサイクル内に少なくとも 2 つの入射エッジを維持するため、これを削除しても有効なサイクルベースの構造は破壊されません。 

### なぜ効果があるのか

 不変条件は、すべてのステップにおいて、すべての頂点が残りの構造内に少なくとも 2 つの近傍を持つ場合、削除されたすべての頂点がサブグラフの一部ではないことが保証されるということです。 現在の縮小グラフでは、削除された頂点の次数は最大 1 です。これは、代替リターン パスを許可するサイクルや構造上に頂点を置くことができないことを意味します。 サイクルは、サイクル内のすべての頂点が少なくとも次数 2 を持つという特性を失うことがないため、有効な解の頂点が削除されることはありません。 プロセスが停止すると、残りのすべての頂点の内部次数が少なくとも 2 になるため、それ以上の枝刈りはできず、残りのセットはこのプロパティに関して最大​​になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n, m = map(int, input().split())
    g = [[] for _ in range(n)]
    deg = [0] * n

    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)
        deg[u] += 1
        deg[v] += 1

    q = deque()
    removed = [False] * n

    for i in range(n):
        if deg[i] == 1:
            q.append(i)
            removed[i] = True

    while q:
        u = q.popleft()
        for v in g[u]:
            if removed[v]:
                continue
            deg[v] -= 1
            if deg[v] == 1:
                removed[v] = True
                q.append(v)

    res = [str(i + 1) for i in range(n) if not removed[i]]
    print(len(res))
    if res:
        print(" ".join(res))

if __name__ == "__main__":
    solve()
```この実装では、端点の 1 つが削除された場合にのみ各エッジが処理されるように、隣接リストと次数配列が維持されます。 キューは頂点が自然な剥離順序で処理されることを保証し、常に新しく形成されたリーフを即座に処理します。 

微妙な点は、頂点が処理されるときではなく、キューに入るときに頂点を削除済みとしてマークすることです。 これにより、異なる近傍によって次数が低下した場合に、同じ頂点に対する複数のエンキュー操作が防止されます。 

## 実用的な例

 1 つのノードに尾部が付いている 4 つの頂点のサイクルのような形状のグラフを考えてみましょう。 尾部は 2 つの頂点で構成されます。 

初期度数を以下に示します。 

| ステップ | 削除されたキュー | 度 (A、B、C、D、E、F) |
 | --- | --- | --- |
 | 開始 | [E、F] | A=3、B=2、C=2、D=2、E=1、F=1 |
 | E | を削除します。 [F] | A=2、B=2、C=2、D=2、F=1 |
 | F | を削除します。 [] | A=2、B=2、C=2、D=2 |

 剪定後はサイクルだけが残ります。 これは、チェーン頂点が最初に削除され、その削除がコア サイクル構造に影響を与えないことを示しています。 

ここで、5 つの頂点からなる単純な折れ線グラフを考えてみましょう。 

| ステップ | 削除されたキュー | 度 (1 ～ 5) |
 | --- | --- | --- |
 | 開始 | [1,5] | 1=1、2=2、3=2、4=2、5=1 |
 | 1 を削除 | [5] | 2=1、3=2、4=2、5=1 |
 | 5 を削除 | [2] | 2=1、3=2、4=2 |
 | 2 を削除 | [] | 3=2、4=2 |
 | 暗黙的に安定した 3,4 を削除 | [] | コアが空です |

 これは、ツリーではすべての頂点が最終的​​に葉として露出するため、最終的にはすべてが消滅することを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + m) | 各頂点は最大 1 回キューに入れられ、各エッジは次数の更新中に最大 2 回処理されます。 
| スペース | O(n + m) | 隣接リストと次数と削除の追跡のための補助配列 |

 線形の複雑さは、最大数十万のノードとエッジのグラフの制約に一致し、ソリューションが制限内で快適に実行されることを保証します。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque

    n, m = map(int, input().split())
    g = [[] for _ in range(n)]
    deg = [0] * n

    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)
        deg[u] += 1
        deg[v] += 1

    q = deque()
    removed = [False] * n

    for i in range(n):
        if deg[i] == 1:
            q.append(i)
            removed[i] = True

    while q:
        u = q.popleft()
        for v in g[u]:
            if not removed[v]:
                deg[v] -= 1
                if deg[v] == 1:
                    removed[v] = True
                    q.append(v)

    res = [str(i + 1) for i in range(n) if not removed[i]]
    return str(len(res)) + ("\n" + " ".join(res) if res else "")

 ## 特殊なケース

 2 つの頂点間の 1 つのエッジにより、両方の端点が即時に削除されます。 それぞれの次数が 1 であるため、キューには最初は両方の頂点が含まれています。最初の頂点を削除すると、表現に応じて隣接する頂点の次数が 0 または 1 に減少し、それも削除されます。 最終出力は空であり、どの頂点もリターン可能な走査をサポートできないという考えと一致しています。 

純粋なサイクルは最初から安定性を示します。 すべての頂点の次数は 2 であるため、最初のキューは空であり、削除は発生しません。 アルゴリズムはすぐにすべての頂点を返し、サイクルが枝刈りプロセスの固定点であることを示します。 

木が完全に倒壊している様子を示しています。 すべてのリーフが最初に削除され、頂点がなくなるまで内側に伝播します。 各ステップでは、安定したコアを作成することなくツリーのサイズが縮小され、ツリーにはサイクルベースの存続可能な構造が含まれていないことが確認されます。
