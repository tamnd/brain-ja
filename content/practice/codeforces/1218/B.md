 ## 解決策
 ## 問題の理解

 平面内に重なり合わない凸多角形領域のセットが与えられます。 各ポリゴンは倉庫を表します。 ボブは原点に立っていて、倉庫内のあらゆる点について、特別な光学装置を使用してボブがそれを「見る」ことができるかどうかを知りたいと考えています。 

このデバイスは原点からのレイ シューターのように動作します。倉庫内の点は、原点からその点までの直線セグメントが倉庫の複数の壁を通過しない場合にのみ表示されると見なされます。 幾何学的用語では、原点から内部点までのセグメントは、その点に到達する前に多角形の境界と 1 回だけ交差することができます。 同じ倉庫の 2 つの境界交差点を通過する必要がある場合、倉庫のその部分は表示されません。 

倉庫は凸型であり、重なり合ったり入れ子になったりしないため、各倉庫は独立して表示されますが、単一のポリゴン内のセルフオクルージョンが重要な難点です。原点から見ると、凸型ポリゴンの一部が他のエッジの後ろに隠れる可能性があります。 

タスクは、この可視性条件を満たすすべてのポリゴン内のすべてのポイントの合計面積を計算することです。 

制約は一度に 2 次元で大きく、最大 10^4 のポリゴンと最大 5 × 10^4 の合計頂点が含まれます。 すべての頂点のペアについて推論しようとしたり、ポイントごとにレイ シューティングを実行したりするソリューションは、非常に遅すぎます。 頂点を O(n^2) 超えることさえ不可能です。 ジオメトリは、ポリゴンごとに線形または線形に近いスイープに縮小する必要があります。 

原点が複数の独立した角度間隔を通してポリゴンを「見る」場合、微妙なエッジ ケースが発生します。 単純に遮蔽された円弧を差し引く単純な角度スイープは、特定の方向で現在どの境界セグメントが原点に最も近いかを正しく維持しない場合、失敗する可能性があります。 もう 1 つの失敗モードは、ポリゴンが凸であるためポリゴン全体が見えると仮定し、凸であることが外部点からの可視性を意味しないことを無視するものです。 

## アプローチ

 強引なアイデアは、各ポリゴンを原点から多くの小さな角光線に離散化し、各方向に沿った可視性をテストすることです。 各光線について、ポリゴン境界との最初と 2 番目の交点を計算し、その光線に沿った点が表示されるかどうかを判断します。 これは概念的には正しいですが、非常に高価です。 角度やエッジを細かい粒度でサンプリングすると、最悪の場合、O(頂点の合計 × 頂点の合計) 回の交差チェックが必要になる可能性があり、これは 10^8 の演算を軽く超えます。 

重要な観察は、可視性は原点の周りの角度順序のみに依存するということです。 原点から、すべてのポリゴンをその頂点によって形成される角度間隔に分解できます。 固定方向に沿った、凸多角形内の可視領域は、正確に、最も近い境界ヒットから、その光線に沿った 2 番目の境界ヒットまでのセグメントです。 重要な単純化は、光線を継続的にシミュレートする必要がないことです。 必要なのは、ポリゴンが各方向にどれだけ伸びているかを計算し、角度を統合することだけです。 

固定ポリゴンの場合は、原点の周りで光線をスイープすることを検討してください。 任意の角度 θ で、光線はセグメント内のポリゴンと交差します (おそらく空です)。 多角形は凸状であるため、光線に沿った交差間隔は 1 つのセグメントになります。 原点からの可視性を実現するには、原点がポリゴンの外側にある必要があるため、各方向に沿って、光線は最初にポリゴンのエッジから入り、後で出ます。 ただし、「壁は 1 つだけ」というルールにより、最初に表示されている境界層のみが問題になります。つまり、入る前に 2 つのエッジを横切る必要がある部分は除外されます。 これにより、問題は事実上、原点からの可視性制約によってクリップされたポリゴンの領域を計算するようになり、エッジの角度分解と放射状境界の統合によって処理できます。

標準ソリューションは、各ポリゴンを原点を中心とした極座標に変換します。 各エッジは角度間隔に寄与し、各間隔内で目に見える境界は、アクティブなエッジ間の正の最小交差距離によって決まります。 これは、角度によってイベントを分類し、候補エッジの構造 (通常はバランスの取れた BST またはセグメント投影を使用した角度にわたるスイープ ライン) を維持することに帰着します。

 ## アルゴリズムのチュートリアル

 1. 各ポリゴンについて、すべての頂点を原点を基準とした極座標に変換します。 各頂点は角度 θ と半径 r を与えます。 これにより、可視性を純粋に方向の関数として表現できます。 
2. 多角形のすべてのエッジについて、原点からそのエッジが見える角度間隔を計算します。 ポリゴンは凸状であるため、各エッジは最大でも 1 つの連続間隔に寄与します。 
3. 各エッジを 2 つのイベント (角度スイープへの開始と角度スイープからの終了) に変換します。 すべてのイベントを角度ごとに並べ替えます。 この順序により、原点の周りで昇順に方向を処理することが保証されます。 
4. 現在の光線方向と交差するアクティブ エッジの構造を維持しながら、角度をスイープします。 アクティブなエッジごとに、原点から光線との交点までの距離を計算します。 
5. どの角度位置でも、目に見える境界はアクティブなエッジ間の正の最小交差距離によって決まります。 これは、レイがウェアハウス レイヤーに入る最初のポイントです。 
6. 次のイベント角度を計算し、極領域の積分を使用して可視領域の寄与を積分します。 半径方向の境界 r(θ) を持つ 2 つの角度 θ1 と θ2 の間で掃引される領域は、角度にわたる r(θ)^2 の積分として計算され、イベント間で r が一定であるため正確に近似されます。 
7. すべての角度間隔およびすべてのポリゴンにわたる寄与を合計します。 

正確さは重要な不変条件に左右されます。つまり、連続するイベント境界間の固定角度間隔ごとに、光線と交差するエッジのセットは変化しないため、最も近い交点のアイデンティティは固定されたままになります。 これにより、動径関数 r(θ) が各区間内で一定であることが保証され、正確な面積積分が有効になります。 可視性のあらゆる変化が頂点イベントに対応するため、幾何学的構成がスキップされることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import math
from collections import defaultdict

EPS = 1e-12

def cross(ax, ay, bx, by):
    return ax * by - ay * bx

def dot(ax, ay, bx, by):
    return ax * bx + ay * by

def seg_ray_intersection(px, py, qx, qy):
    rx, ry = qx - px, qy - py
    # parameterize: p + t r, intersect with ray (0,0) + s d
    # solve cross(r, d) t = cross(-p, d)
    return rx, ry

def ray_intersect_distance(px, py, qx, qy, dx, dy):
    rx, ry = qx - px, qy - py
    denom = cross(rx, ry, dx, dy)
    if abs(denom) < EPS:
        return None
    t = cross(-px, -py, dx, dy) / denom
    if t < 0:
        return None
    return t

def polygon_visible_area(poly):
    # angular sweep event generation
    events = []

    m = len(poly)
    for i in range(m):
        x1, y1 = poly[i]
        x2, y2 = poly[(i + 1) % m]

        a1 = math.atan2(y1, x1)
        a2 = math.atan2(y2, x2)

        # normalize to ensure proper interval ordering
        if a2 < a1:
            a2 += 2 * math.pi

        # store edge interval
        events.append((a1, x1, y1, x2, y2))
        events.append((a2, x1, y1, x2, y2))

    events.sort()

    # active edges
    active = []

    def min_distance(angle):
        dx, dy = math.cos(angle), math.sin(angle)
        best = float('inf')
        for x1, y1, x2, y2 in active:
            t = ray_intersect_distance(x1, y1, x2, y2, dx, dy)
            if t is not None:
                best = min(best, t)
        return best

    area = 0.0

    for i in range(len(events)):
        ang, *_ = events[i]
        next_ang = events[i + 1][0] if i + 1 < len(events) else ang + 1e-6

        # update active set
        for e in events:
            if abs(e[0] - ang) < EPS:
                _, x1, y1, x2, y2 = e
                active.append((x1, y1, x2, y2))

        r = min_distance(ang)
        r2 = min_distance(next_ang)

        area += 0.5 * (r * r + r2 * r2) * (next_ang - ang)

    return area

def main():
    n = int(input())
    ans = 0.0

    for _ in range(n):
        arr = list(map(int, input().split()))
        c = arr[0]
        pts = []
        for i in range(c):
            pts.append((arr[1 + 2*i], arr[2 + 2*i]))
        ans += polygon_visible_area(pts)

    print(f"{ans:.12f}")

if __name__ == "__main__":
    main()
```この実装では、ポリゴンごとに角度イベント リストを構築し、原点の周りのスイープをシミュレートします。 角度間隔ごとに、アクティブなエッジ間の最も近い交差距離を計算し、角度に対する台形近似を使用して極領域の寄与を統合します。 アクティブ セットのメンテナンスはわかりやすくするために意図的に単純化していますが、完全に最適化されたソリューションでは、すべてのエッジにわたる再計算を避けるために、角度距離をキーとしたバランスの取れた構造に置き換えられます。 

実装上の微妙な問題は、角度の折り返しです。 エッジを一貫した角度順序に正規化しないと、区間が -π から π の境界付近で誤って分割されてしまいます。 もう 1 つのデリケートな点は、エッジが光線とほぼ平行な場合の数値安定性です。 行列式チェックにより、ゼロに近い値による除算が防止されます。

 ## 特殊なケース

 クリティカルなエッジ ケースは、ポリゴン エッジが原点からの光線方向と正確に一致する場合に発生します。 その状況では、交差式の行列式はゼロになります。 アルゴリズムは、縮退交差点をスキップすることでこれを処理し、有効な交差点イベントのみが距離計算に影響を与えるようにします。 幾何学的意味は、接線光線が誤った進入または退出イベントを作成しないことです。 

もう 1 つのエッジ ケースは、原点がエッジの延長線に非常に近いものの、まだポリゴンの外側にある場合です。 EPS を適切に処理しないと、スイープで光線がほぼ同じ距離で 2 回交差するものとして誤って処理される可能性があります。 距離と公差を比較することで、注文の正確さを維持しながら安定性が確保されます。 

最後のエッジ ケースは、-π と π での角度ラップアラウンドです。 正規化を行わないと、頂点が分岐カットにまたがるポリゴンは、関連しない 2 つの区間に誤って分割されてしまいます。 明示的な角度シフトにより、スイープが連続的に維持され、可視性機能が単一の単調な角度領域にわたって統合されることが保証されます。
