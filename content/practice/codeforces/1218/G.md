 ## 解決策
 ## 問題の理解

 私たちは、無向のシャトルルートで接続された宇宙港のネットワークを与えられています。 各宇宙港は、X、Y、または Z とラベル付けされた 3 つの惑星のうちの 1 つに正確に属します。すべてのシャトルは 2 つの異なる宇宙港を接続しており、異なる惑星間の接続のみが存在します。 

すべての接続に対して、ラベル 1、2、または 3 を割り当てる必要があります。唯一の制約は、2 つの宇宙港が接続されている場合、割り当てはエンドポイントの惑星に関連付けられた一貫性ルールを尊重する必要があることです。 サンプル出力は実際の状態を明らかにしています。割り当てがエンドポイントの惑星のみに依存するようにエッジが色付けされており、接続されたグラフ全体にわたる妥当性を保証する構造化された方法ですべてのエッジに 3 つの値のいずれかが与えられます。 

重要な隠れた構造は、グラフが 3 つの部分からなり、接続されていることです。 これにより、各パーティションで選択した参照ノードからの距離に基づいて値を割り当てるという問題を軽減できます。 

制約は大きく、最大 100,000 のノードとエッジがあります。 これにより、二次的なものやクエリごとの BFS/DFS の繰り返しが即座に排除されます。 線形または線形に近いトラバーサルが必要です。これは、O(N + M) が唯一の実行可能な複雑さクラスであることを意味します。 

単純な試みでは、グローバル構造を使用せずにエッジごとに貪欲にラベルを割り当てようとする可能性があります。 これは、ローカルな決定によってサイクル間で簡単に不一致が生じる可能性があるため、失敗します。 

2 番目の単純な試みでは、エンドポイントのタイプに基づいて各エッジを個別に処理しようとします。 複数のエッジが頂点を共有し、グローバルに一貫性を保つ必要があるため、これも失敗します。 

小さな失敗例は、3 つの惑星グループ間の三角形のような相互作用で発生します。 エッジ ラベルを個別に割り当てると、サイクル周りでパリティ制約が矛盾する結果になり、以前のエッジが有効に見えたとしても後で不可能な構成が生成される可能性があります。 

## アプローチ

 重要な観察は、問題は独立したエッジに関するものではなく、頂点構造から派生した値の割り当てに関するものであるということです。 

エッジは異なる種類の惑星を接続するだけなので、固定の 3 部グラフを扱います。 目標は、すべての頂点が一貫して参加するように、エッジにラベル付け関数を構築することです。 

強引なアイデアは、各エッジに {1, 2, 3} の値を割り当てて、一貫性制約をグローバルにチェックすることです。 これは 3^M 通りの可能性をもたらし、これは天文学的に大きくなります。 

別の強引なアプローチでは、制約を反復的に伝播し、収束するまでエッジ ラベルを調整します。 ただし、サイクルによりこれが不安定になり、動作が非終了または指数関数的に変化する可能性があります。 

重要な洞察は、エッジ ラベルを頂点ポテンシャルのモジュロ 3 の差として再解釈することです。各頂点に、惑星ごとに慎重に選択されたソースからの BFS レイヤ化から派生した「状態」を割り当てると、各エッジは自然にそれらの状態によって決定される値を受け取ります。 グラフは接続されており、惑星をまたぐエッジのみを持つため、誘導された構造内で一貫した BFS 距離を定義し、エッジ値をエンドポイント レベルの決定論的関数としてエンコードできます。 

より具体的には、惑星ごとに代表的な頂点を 1 つ選択し、それらの頂点から BFS 距離を計算し、これらの距離を組み合わせて、常に {1,2,3} に収まり、全体的に一貫性を満たす決定的なエッジ ラベルを定義します。 

これにより、問題は数回の BFS トラバーサルとエッジ上の 1 回のパスに軽減されます。

 ## アルゴリズムのチュートリアル

 3 つの BFS ツリーを構築します。1 つは各惑星グループの任意のノードにルートします。

1. X、Y、Z に属する任意のノードをルートとして選択します。 グループに複数の候補がある場合は、最初に出現したものを選択します。 
2. 各ルートから BFS を実行し、すべての頂点の距離 distX、distY、distZ を計算します。 各 BFS は、ノードがその惑星の基準からどれだけ離れているかを反映します。 
3. すべてのエッジ (u、v) について、相対距離の差のペアを計算します。 u と v は異なる惑星グループに属しているため、3 つの BFS 距離の差のうちの 1 つが、エッジを区別する一貫した方法で動作します。 
4. これらの距離の決定論的な関数としてエッジ ラベルを定義します。 有効な構造の 1 つは次のとおりです。 

ラベルの割り当て = 1 + (dist[planet(u)](v) - dist[planet(v)](u) mod 3)

 {1,2,3}の範囲に調整されます。 
5. 計算されたラベルを使用して、入力と同じ順序でエッジを出力します。 

これが機能する理由は、BFS 距離がグラフを層状構造に分割し、惑星間のエッジが常に予測可能なパリティ関係で頂点を接続するためです。 モジュール調整により、すべての制約が一貫したグローバルな割り当てにまとめられることが保証されます。 

### なぜ効果があるのか

 各 BFS は、頂点にわたる一貫した整数ポテンシャルを定義します。 エッジは異なるパーティションのみを接続するため、エッジのエンドポイントは常に 3 つの距離システムの少なくとも 1 つで異なります。 ラベルの構造は、サイクルに関する互換性を維持しながら、これらの一貫した可能性をエッジ ラベルに変換します。 グラフ内のすべてのサイクルは、BFS レイヤー全体のバランスの取れた距離の変化に対応し、矛盾する割り当てを防ぎます。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def bfs(start, adj, n):
    dist = [-1] * n
    q = deque([start])
    dist[start] = 0
    while q:
        u = q.popleft()
        for v in adj[u]:
            if dist[v] == -1:
                dist[v] = dist[u] + 1
                q.append(v)
    return dist

def main():
    n = int(input())
    m = int(input())
    color = input().strip()

    adj = [[] for _ in range(n)]
    edges = []

    for _ in range(m):
        u, v = map(int, input().split())
        adj[u].append(v)
        adj[v].append(u)
        edges.append((u, v))

    # pick one root per planet
    rx = ry = rz = -1
    for i, c in enumerate(color):
        if c == 'X' and rx == -1:
            rx = i
        if c == 'Y' and ry == -1:
            ry = i
        if c == 'Z' and rz == -1:
            rz = i

    dx = bfs(rx, adj, n)
    dy = bfs(ry, adj, n)
    dz = bfs(rz, adj, n)

    # map planet to distance array
    def get_dist(c):
        if c == 'X':
            return dx
        if c == 'Y':
            return dy
        return dz

    out = []
    for u, v in edges:
        du = get_dist(color[u])
        dv = get_dist(color[v])

        # construct label from relative distances
        val = (du[v] - dv[u]) % 3
        if val <= 0:
            val += 3
        out.append(val)

    for (u, v), w in zip(edges, out):
        print(u, v, w)

if __name__ == "__main__":
    main()
```この実装は 3 つの BFS トラバーサルに依存しており、それぞれが一貫した距離フィールドを計算します。 エッジ処理ステップではエッジごとに定数時間演算のみを使用し、ソリューションを線形に保ちます。 

微妙な点は、モジュール正規化を正しく処理することです。 式は負の値を生成する可能性があるため、{1,2,3} に戻ります。 もう 1 つの重要な点は、BFS を再計算したりエッジを再検討したりしないことで、ソリューションを時間制限内に維持できることです。

 ## 特殊なケース

 2 つの惑星の間に 1 つのエッジがある最小限のグラフは、BFS の初期化によってラベルが曖昧さなく正しく割り当てられるかどうかをテストします。 エッジが 1 つだけ存在するため、{1,2,3} 内の任意の有効なラベルが機能し、構築は常に一貫した値を返します。 

3 つの惑星タイプすべての間の密な相互接続構造により、BFS 距離が複数の相互作用パス全体で一貫した状態に保たれます。 距離フィールドはルートごとにグローバルに固定されるため、同じ頂点が繰り返し発生すると常に同じラベルが生成されるため、アルゴリズムはこれを処理します。 

2 つの惑星タイプを交互に繰り返す長いチェーンにより、BFS 深度の差がオーバーフローやドリフトなしに正しく蓄積されていることを確認します。 モジュラー計算により、チェーンの長さに関係なく安定性が保証されます。
