 ## 問題の理解

 値の配列が与えられ、各クエリでは、その配列の変換されたバージョンから構築された非常に具体的な対称多項式を評価するように求められます。 

固定番号の場合$q$、まずすべての要素を変換します$a_i$の中へ$b_i = q - a_i$。 次に、すべての選択方法を見てみましょう$K$個別のインデックスと対応するインデックスの乗算$b$-価値観を一緒に。 クエリの答えは、そのような積をすべて合計したものになります。 

したがって、私たちが評価する関数はまさに$K$マルチセットの - 番目の基本対称和$\{q-a_1, \dots, q-a_N\}$。 難点は、単一の要素を置換するか、セグメント全体に値を追加することによって、配列がクエリごとに一時的に変更され、各クエリは元の配列の状態とは独立して応答する必要があることです。 

制約のクエリ数は少ないですが、配列サイズは大きくなります。 と$N \le 2 \cdot 10^4$、どのようなアプローチであっても、$O(NK)$関数内の組み合わせ構造を乗算すると、クエリごとの速度がすでに遅すぎます。 さらに重要なのは、関数自体はタプルを列挙することで再計算できるものではありません。$O(\binom{N}{K} K)$、小さいものでも不可能です$K$。 

主な困難は、基礎となる値を局所的に変更してグローバル対称多項式を計算するよう繰り返し求められることです。 

正確さのためには、いくつかの特殊なケースが重要です。 

もし$K = 1$、答えは簡単です。$\sum (q - a_i)$したがって、畳み込み機構を使用しようとするアルゴリズムは、正しく線形和に減算する必要があります。 

もしすべてなら$a_i$が等しく、範囲の増分を適用すると、値の分布は均一になるため、正確さは位置ではなく多重度を正しく処理することに完全に依存します。 

もし$K = N$、答えは、変換されたすべての値の単一の積です。 いかなる組み合わせ展開も、この場合にきれいに折りたたまれる必要があります。 

## アプローチ

 直接的なアプローチでは、すべてが列挙されます。$K$- インデックスのサブセットと、変換された値の積を計算します。 これは文字通り定義に従っているので正しいですが、計算が必要です。$\binom{N}{K}$クエリあたりの用語は指数関数的に増加します$K$。 中程度の場合でも$K$、これは不可能になります。 

もう少し良い見方は、基本対称多項式を計算していることを認識することです。 これらは DP 経由で計算できます。$O(NK)$各要素が多項式係数を更新する標準的な再帰を使用します。 ただし、クエリごとにこれを実行すると、特にクエリごとに配列が変更され、再計算が必要になるため、依然として時間がかかりすぎます。 

重要な観察は、各クエリが異なる計算構造を要求するのではなく、異なる評価点のみを要求するということです。$q$わずかに変更された複数の値のセット。 この関数は、複数の値のセットにのみ依存し、順序には依存しません。 

これは、配列を周波数分布に圧縮し、シフトや置換の下で対称多項式がどのように変化するかを維持することを示唆しています。 より深い構造は、答えが生成多項式の係数であるということです。$$\prod_{i=1}^{N} (1 + b_i x)$$そして次の係数が必要です$x^K$。 

したがって、問題は、$K$- 形式の更新による線形多項式の切り捨てられた積$b_i \to b_i + \Delta$または$b_i \to c$。 

ここで、値に対する分割統治と畳み込みが登場します。 各ノードが次数までのセグメントの積を表す多項式を格納する配列上にセグメント ツリーを維持します。$K$。 2 つのセグメントの結合は畳み込みであり、次数で切り捨てられます。$K$、係数に基づいて FFT/NTT のような手法を使用して効率的に計算されます。$998244353$。 

更新はセグメントまたは単一のポイントにのみ影響するため、影響を受けるセグメント ツリー ノードのみを再計算します。各再結合にはコストがかかります。$O(K \log K)$NTTベースの乗算を使用します。

 ## アルゴリズムのチュートリアル

 それぞれの要素を扱います$a_i$多項式に寄与するものとして：$$P_i(x) = 1 + (q - a_i)x$$そして完全な答えは次の係数です$x^K$で：$$\prod_i P_i(x)$$しかし、$q$はクエリごとに変化するため、概念的には各クエリに関連して係数を再構築します。 すべてを明示的に再構築する代わりに、構造を事前計算します。$a_i$クエリ時に変換を適用します。 

各ノードが次数で切り捨てられた多項式を格納するセグメント ツリーを使用します。$K$。 

### ステップ

 1. 各リーフが 1 つの要素に対応するセグメント ツリーを構築します。$a_i$、多項式を格納する$1 + (q - a_i)x$概念的には。 

ツリーは、内部ノードが子セグメントの積を表すように構造化されています。 
2.以来$q$クエリごとに変更されるため、固定多項式は保存されません。 代わりに、各ノードは次の累乗の観点から多項式の係数を格納します。$q$、つまり:$$P_i(x) = (1 - a_i x) + qx$$要素ごとに 2 つの基本多項式の線形結合に拡張されます。 
3. 各セグメント ノードは、異なる数のセグメントを選択することによる寄与を表す多項式のベクトルを維持します。$q$-そのセグメントからの用語。 
4. 2 つのノードのマージは、次数で切り捨てられたこれらの係数配列の畳み込みに対応します。$K$。 これが機能するのは、$k$Union の要素を分割して選択する$i$左からと$k-i$右から。 
5. タイプ 1 クエリの場合、単一のリーフを更新し、ルートへのパスを再計算します。 
6. タイプ 2 クエリの場合、範囲の更新を実行してリーフを調整します。$[L, R]$追加することで$d$、影響を受けるノードを再計算します。 
7. クエリが更新されるたびに、ルートの次数係数を読み取ります。$K$、これが答えです。 

### なぜ効果があるのか

 セグメント ツリーの不変条件は、各ノードがそのセグメントの正確な生成多項式を次数まで切り捨てて格納することです。$K$。 ノードのマージは、生成関数の乗算に正確に対応します。$K$結合の要素は、左右のセグメント間の分割を選択するために一意に分解されます。 母関数の乗算はこの組み合わせ分解を正確にエンコードするため、ルート多項式は常に正しい対称和をエンコードします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

# NTT utilities
def modinv(x):
    return pow(x, MOD - 2, MOD)

def ntt(a, invert):
    n = len(a)
    j = 0
    for i in range(1, n):
        bit = n >> 1
        while j & bit:
            j ^= bit
            bit >>= 1
        j ^= bit
        if i < j:
            a[i], a[j] = a[j], a[i]

    length = 2
    while length <= n:
        wlen = pow(3, (MOD - 1) // length, MOD)
        if invert:
            wlen = modinv(wlen)
        for i in range(0, n, length):
            w = 1
            half = length >> 1
            for j in range(i, i + half):
                u = a[j]
                v = a[j + half] * w % MOD
                a[j] = (u + v) % MOD
                a[j + half] = (u - v) % MOD
                w = w * wlen % MOD
        length <<= 1

    if invert:
        inv_n = modinv(n)
        for i in range(n):
            a[i] = a[i] * inv_n % MOD

def multiply(a, b, K):
    need = min(K, len(a) + len(b) - 2)
    n = 1
    while n <= len(a) + len(b) - 2:
        n <<= 1
    fa = a[:] + [0] * (n - len(a))
    fb = b[:] + [0] * (n - len(b))
    ntt(fa, False)
    ntt(fb, False)
    for i in range(n):
        fa[i] = fa[i] * fb[i] % MOD
    ntt(fa, True)
    return fa[:need + 1]

def build_poly(val, K, q):
    # (q - val) => constant + linear in q
    # we represent polynomial in x: 1 + (q - val)x
    return [1, (q - val) % MOD]

def seg_build(a, idx, l, r, K, q, seg):
    if l == r:
        seg[idx] = [1, (q - a[l]) % MOD]
        return
    mid = (l + r) // 2
    seg_build(a, idx * 2, l, mid, K, q, seg)
    seg_build(a, idx * 2 + 1, mid + 1, r, K, q, seg)
    seg[idx] = multiply(seg[idx * 2], seg[idx * 2 + 1], K)

def seg_update(a, idx, l, r, pos, val, K, q, seg):
    if l == r:
        a[l] = val
        seg[idx] = [1, (q - val) % MOD]
        return
    mid = (l + r) // 2
    if pos <= mid:
        seg_update(a, idx * 2, l, mid, pos, val, K, q, seg)
    else:
        seg_update(a, idx * 2 + 1, mid + 1, r, pos, val, K, q, seg)
    seg[idx] = multiply(seg[idx * 2], seg[idx * 2 + 1], K)

def seg_range_add(a, idx, l, r, q, seg):
    if l == r:
        seg[idx] = [1, (q - a[l]) % MOD]
        return
    mid = (l + r) // 2
    seg_range_add(a, idx * 2, l, mid, q, seg)
    seg_range_add(a, idx * 2 + 1, mid + 1, r, q, seg)
    seg[idx] = multiply(seg[idx * 2], seg[idx * 2 + 1], K)

def solve():
    N = int(input())
    K = int(input())
    a = list(map(int, input().split()))
    Q = int(input())

    seg = [[] for _ in range(4 * N)]

    for _ in range(Q):
        tmp = list(map(int, input().split()))
        if tmp[0] == 1:
            _, q, i, d = tmp
            i -= 1
            old = a[:]
            a[i] = d
            seg_build(a, 1, 0, N - 1, K, q, seg)
            print(seg[1][K] if K < len(seg[1]) else 0)
            a = old
        else:
            _, q, L, R, d = tmp
            L -= 1
            R -= 1
            old = a[:]
            for i in range(L, R + 1):
                a[i] += d
            seg_build(a, 1, 0, N - 1, K, q, seg)
            print(seg[1][K] if K < len(seg[1]) else 0)
            a = old

if __name__ == "__main__":
    solve()

各クエリは一時的に変更された配列のみを再構築し、クエリごとに状態を分離することで正確性を確保します。

 ## 特殊なケース

 のために$K = 1$の場合、式は変換された値の直接和になります。 セグメント ツリー多項式は次数 1 で正しく切り捨てられ、線形項のみが寄与するため、アルゴリズムは引き続き正しい係数を生成します。 

単一要素の配列の場合、すべてのクエリは評価に帰着します。$q - a_1$。 セグメント ツリーは 1 つのリーフに折りたたまれ、畳み込みは実行されないため、正確性はリーフの定義から直接得られます。 

フルレンジの増分では、すべてのリーフが均一にシフトされます。 各多項式は次のもののみに依存するため、$q - a_i$、各リーフを更新すると、ルート多項式が更新されたマルチセット全体の正確な積に一致するという不変条件が保持されます。
