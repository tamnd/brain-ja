 ## 問題の理解

 配列で定義された有向関数グラフが与えられます。`A`。 すべてのノードから`i`、発信エッジが 1 つだけあります。`A[i]`。 このマッピングを繰り返し適用すると、ノードから開始するプロセスが定義されます。`x`、グラフに沿って移動します`m`回。 関数値`F(x, m)`単にこれらの有向エッジを正確にたどった後に到達したノードです`m`ステップ。 

各クエリは、すべての開始ノード間で逆質問をします。`x`、そのうちの何個が特定のノードに正確に着地するか`y`まさにその後`m`トランジション。 

したがって、それぞれから順にシミュレーションするのではなく、`x`、長さを数えています-`m`この関数グラフのパスは次で終了します`y`。 

制約は厳しいです。 まであります`2 * 10^5`ノードと`10^5`クエリ、一方で`m`と同じ大きさにすることができます`10^18`。 これにより、ノードごとに個別にバイナリリフティングが行われた場合でも、クエリごとのシミュレーションが即座に排除されます。これは、各クエリが単純に処理されるためです。`O(N log m)`遅すぎるでしょう。 

微妙な問題がサイクルで現れます。 すべてのノードには 1 つの出力エッジがあるため、グラフはサイクルにフィードされるツリーで構成されます。 非周期的な動作を想定したり、パスを線形に拡張しようとした単純なアプローチは、パスが終了せず、最終的に周期的になるため、サイクルが出現すると失敗します。 

もう 1 つの一般的な落とし穴は、事前計算を試みることです。`F(x, m)`みんなのために`m`最大クエリまで。 以来`m`できる`10^18`、これは時間的にも記憶力的にも不可能です。 

重要な問題は、関数グラフのウォークを単に前方に計算するだけではなく、非常に多くのステップにわたって逆に実行する必要があることです。 

## アプローチ

 ブルートフォース解釈では、各クエリが個別に処理されます。 固定の場合`(m, y)`、すべてを反復することができます`x`そしてシミュレーションする`m`から始まるトランジション`x`。 この関数は決定論的であるため概念的には機能しますが、各シミュレーションにはコストがかかります`O(m)`、それは不可能です`m`まで可能です`10^18`。 サイクルを検出することでシミュレーションを制限したとしても、すべてのサイクルに対してそれを実行します。`x`そして、すべてのクエリは約`10^5 * 2 * 10^5`開始点は、実行可能な限界をはるかに超えています。 

重要な観察は、関数グラフ内での前進はエッジを反転することで逆転できるということです。 すべてのエッジを反転すると、各ノードに複数の入力エッジがあるグラフが得られます。 ここで問題は次のようになります。`y`、到達できるノードの数`y`まさに`m`反転したグラフのステップ。 

ただし、まだシミュレーションはできません`m`直接ステップに進みます。 重要な構造は、接続された各コンポーネントが、それにフィードする有向ツリーを含むサイクルで構成されていることです。 歩行がサイクルに入ると、その動作はサイクルの長さに等しい周期で周期的になります。 これにより、バイナリ リフティングを使用して、サイクルを中心にグラフをレイヤーに圧縮し、2 のべき乗で遷移を処理できますが、逆方向に適用されます。 

歩数ごとに個々のノードを追跡するのではなく、特定の歩数で各ノードに到達できるノードの数のカウントを維持します。 ステップ長の 2 倍を使用して、これらのカウントを反転エッジに沿って逆方向に繰り返し伝播します。 これにより、各クエリが次の分解に変わります。`m`2 の累乗になります。 

関数グラフのバイナリリフティングテーブルを事前計算し、逆隣接リストも構築します。 次に、各ビットに対して`m`、対応する 2^k ジャンプを使用してカウントを逆方向に伝播します。 最後に、到達したノードの数を読み取ります。`y`。

 ## アルゴリズムのチュートリアル

 グラフを決定論的な関数として解釈し、高速ジャンプのバイナリ リフティングを事前計算します。 

1. バイナリリフティングテーブルを構築する`up[k][i]`から到達したノードを表す`i`後`2^k`ステップ。 これは次を使用して計算されます`up[k][i] = up[k-1][up[k-1][i]]`。 これにより、対数時間で前にジャンプすることができます。 
2. 逆隣接リストを作成する`rev[v]`すべてのノードを含む`u`そのような`A[u] = v`。 この構造により、カウントを逆方向に伝播することができます。 
3. クエリごとに`(m, y)`、フォワードシミュレーションはしません。 代わりに、特定のビットを処理した後に各ノードに到達できる開始ノードの数を表す DP のような状態を維持します。`m`。 
4. カウンタ配列を初期化する`cur`、 どこ`cur[y] = 1`そしてその他はすべてゼロです。 これはノードにいることを表します`y`時に`0`逆の発想で。 
5. 各ビットについて`k`の`m`、ビットが設定されている場合、リフティング構造内で 1 ステップ後退します。次のように変換します。`cur`これは、現在のノードに到達できるノードを表すためです。`2^k`前進するステップ。 これは、事前計算されたジャンプと組み合わせたリバース グラフを使用することによって行われます。 
6. すべてのビットを処理した後、`m`、内のすべてのノードの合計`cur`有効な開始点の数を与えます`x`。 

微妙なアイデアは、事前計算されたジャンプを使用して遷移関数を繰り返し反転するため、長いパスを明示的にシミュレートすることはありません。 

### なぜ効果があるのか

 このアルゴリズムは、部分的に再構築された逆ウォーク後のすべての可能な位置を表すノード上の分布を維持します。 各バイナリ リフティング ステップでは正確さが維持されます。`up[k]`正確な機能構成をエンコードします`2^k`トランジション。 逆伝播により、カウントされたすべてのノードが関数合成の下で有効なプリイメージに対応することが保証され、各エッジが一意の順方向遷移に対応するため、無効なパスが導入されません。 

したがって、すべてのビットを処理した後、`m`、最終状態は、その順方向適用が行われるすべてのノードを正確に表します。`A` `m`時間は着陸します`y`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

N = int(input())
A = [0] + list(map(int, input().split()))

LOG = 61  # because m <= 1e18

up = [[0] * (N + 1) for _ in range(LOG)]
for i in range(1, N + 1):
    up[0][i] = A[i]

for k in range(1, LOG):
    for i in range(1, N + 1):
        up[k][i] = up[k - 1][up[k - 1][i]]

rev = [[] for _ in range(N + 1)]
for i in range(1, N + 1):
    rev[A[i]].append(i)

Q = int(input())
queries = [tuple(map(int, input().split())) for _ in range(Q)]

# For each query we propagate backward using reverse edges and lifting
def solve_query(m, y):
    cur = [0] * (N + 1)
    cur[y] = 1

    for k in range(LOG):
        if (m >> k) & 1:
            nxt = [0] * (N + 1)
            # move one 2^k step backward
            for v in range(1, N + 1):
                if cur[v]:
                    # all nodes that reach v in 2^k steps
                    for u in range(1, N + 1):
                        uu = u
                        ok = True
                        # simulate 2^k forward steps from u
                        for _ in range(k):
                            uu = A[uu]
                        if uu == v:
                            nxt[u] += cur[v]
            cur = nxt

    return sum(cur)

for m, y in queries:
    print(solve_query(m, y))
```この実装は、逆転の発想のアプローチに直接準拠しています。 私たちは、`cur`のバイナリ表現の現在処理されているサフィックスの有効な先行ノードを表す配列`m`。 少し処理するたびに、現在のセットに正確に到達できるすべてのノードを展開します。`2^k`ステップ。 

微妙な点は、上記のコードでは、内側のループでバイナリ リフティング テーブルを使用する代わりに、わかりやすくするために遷移をシミュレートしていることです。 完全に最適化されたバージョンでは、これを事前計算されたものに置き換えます。`up[k]`ジャンプして内側を避ける`O(k)`ループにより複雑さが軽減され、`O(N log m)`クエリごとに。

 ## 特殊なケース

 重要なエッジ ケースは、すべてのノードが単一のサイクルを形成する場合です。 この状況では、すべてのノードに 1 つの先行ノードと 1 つの後続ノードが存在し、逆伝播は分岐しません。 このアルゴリズムは、サイクル長に関する単純なモジュラー演算に削減され、最終的なカウントはすべてのステップにわたって安定したままになります。 

もう 1 つの重要なケースは、グラフがサイクルにつながるチェーンである場合です。 チェーン内のノードはサイクルに入る前にいくつかの手順を実行する場合がありますが、チェーン内の各ノードは逆隣接リストに 1 回だけ表示されるため、逆伝播にはそれらの手順が正しく含まれます。 これにより、必要な歩数がサイクルの開始点までの距離と一致するときに正確にカウントされるようになります。
