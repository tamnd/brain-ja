 ## 解決策
 ## 問題の理解

 整数のリストが与えられ、選択した要素を繰り返し 1 ずつ増やすことができます。 目標は、増分をできるだけ少なくしながら、すべての値が区別できるように配列を変換することです。 

言い換えると、各数値は整数直線上の開始位置を表します。 ポイントを右にのみ移動することができ、移動ごとに 1 単位の距離がかかります。 すべてのポイントを再配置して、2 つのポイントが同じ整数に到達しないようにして、全体の動きを最小限に抑えたいと考えています。 

制約$n \le 2 \cdot 10^5$衝突ごとに段階的に増分をシミュレートしようとするアプローチは直ちに除外されます。 各要素に必要な移動数が少ない場合でも、最悪の場合、配列のほぼ全体にわたるカスケード シフトが発生し、単純に処理すると二次的な動作が発生する可能性があります。 

多くの値が同一であるか密集している場合、微妙な失敗が発生します。 たとえば、入力が次の場合、$[5, 5, 5, 5]$、貪欲な「重複をローカルで修正する」アプローチでは、5、6、7、8 のような値が割り当てられる可能性がありますが、以前の割り当てを考慮せずに、一意になるまで現在の重複を常にインクリメントする不注意な実装では、カウントしすぎたり、順序付けを誤って処理したりする可能性があります。 もう 1 つの落とし穴は、構造化された順序ではなく任意の順序で処理することです。これにより、以前の決定が後の決定を制約するため、最適性が損なわれる可能性があります。 

## アプローチ

 ブルート フォースの見方は簡単です。配列を繰り返しスキャンし、衝突が存在するたびに、一意になるまで重複の 1 つをインクリメントします。 これが機能するのは、各増分操作が許可された移動を直接モデル化しているためです。 ただし、増分ごとにすでに処理された値との新たな衝突が発生する可能性があるため、最悪の場合、多くの要素に変更を繰り返し伝播することになります。 すべて等しい値のような入力の場合、各要素は最大で増分される可能性があります。$O(n)$回、与える$O(n^2)$行動。 

重要な構造的観察は、相対的な順序のみが重要であるということです。 配列をソートすると、どの値を最初に修正する必要があるかについてのあいまいさがすべてなくなります。 ソートが完了すると、最適な戦略は貪欲で局所的なものになります。各数値は、前に選択した値より少なくとも 1 大きいだけで済みます。 これにより、グローバルな衝突問題が単純な線形スイープに変換され、単調性が強制されます。 

任意の増分という観点から考えるのではなく、タスクを最終値の割り当てとして再解釈します。$b_i$そのような$b_i > b_{i-1}$そして$b_i \ge a_i$を最小限に抑えながら、$\sum (b_i - a_i)$。 ソートにより、コストを増加させることなく、最適なソリューションを降順でない順序に並べ替えることができます。

 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション |$O(n^2)$|$O(n)$| 遅すぎる |
 | ソート + 貪欲なスイープ |$O(n \log n)$|$O(1)$または$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 配列を昇順に処理することで、以前の決定を後の要素で修正する必要がなくなりました。 

1. 配列を降順でない順に並べ替えます。 これにより、小さな値が最初に処理されるようになり、大きな値によって人為的にブロックされることがなくなります。 最終構成で 2 つの要素を交換しても、必要な増分を削減または保持することしかできないため、最適な構造ではソート順序を尊重する必要があります。 
2. 変数を初期化する`current`次に割り当てることができる最小値を追跡します。 これは、変換された配列内で最後に選択された最終値を表します。 
3. ソートされた配列を反復処理します。 要素ごとに`x`、最終的な値を次のように決定します。`max(x, current)`。 これにより、値が少なくとも元の値と同じ大きさになり、必要に応じて以前に選択した値よりも厳密に大きくなることが保証されます。 
4. 追加してコストを累積します。`final_value - x`答えに。 これは、この要素に適用された増分の数を直接カウントします。 
5.アップデート`current`に`final_value + 1`、次の要素に厳密な区別を強制します。 

各ステップでは、グローバルな実現可能性を維持しながら、ローカルで最小限の調整を実施します。 ソートのステップにより、値を上げたときに、以前の決定を再検討する必要が生じるような、より小さい元の値が後で発生することがなくなります。 

### なぜ効果があるのか

 核となる不変条件は、i 番目の要素をソート順に処理した後、元の配列によって課されたすべての下限を尊重して、最初の i 要素に対して可能な限り最小の厳密に増加するシーケンスを構築したことです。 最適なソリューションは、元の値でソートしたときに昇順で値を割り当てる必要があります。 そうしないと、2 つの隣接する順序が狂った割り当てを交換しても、コストは増加せず、順序が復元されます。 この交換引数により、各値を最も早い利用可能なスロットに貪欲に固定しても、後の最適なソリューションがブロックされないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    a.sort()

    current = -10**18
    ans = 0

    for x in a:
        if x <= current:
            ans += current + 1 - x
            current = current + 1
        else:
            current = x
        # next must be strictly larger
        current += 1

    print(ans)

if __name__ == "__main__":
    solve()
```実装は貪欲な構造を反映しています。 並べ替えにより、最後に選択した値とのみ比較する必要があることが保証されるため、並べ替えは不可欠です。 変数`current`次の空き整数スロットを表します。 現在の入力値がすでに十分に大きい場合は、追加コストなしで直接入力値を配置できます。 それ以外の場合は、次のように進めます。`current`、差額を正確に支払います。 

よくある微妙な点は更新です`current`割り当て後。 常に次の場所に移動する必要があります`final_value + 1`、だけではありません`final_value`なぜなら、一意性を実現するには、連続して選択された値を厳密に分離する必要があるからです。 

## 実用的な例

 インプットを考慮する`[1, 1, 1]`。 

並べ替えても残る`[1, 1, 1]`。 

| 要素 | | 前の現在 | 選択された値 | 追加コスト | 後の現在 |
 | --- | --- | --- | --- | --- |
 | 1 | -∞ | 1 | 0 | 2 |
 | 1 | 2 | 2 | 1 | 3 |
 | 1 | 3 | 3 | 2 | 4 |

 総コストは3です。 

このトレースは、各重複がどのように次の利用可能な整数にプッシュされ、連続したチェーンを形成するかを示します。 

ここで考えてみましょう`[2, 2, 3]`。 

| 要素 | | 前の現在 | 選択された値 | 追加コスト | 後の現在 |
 | --- | --- | --- | --- | --- |
 | 2 | -∞ | 2 | 0 | 3 |
 | 2 | 3 | 3 | 1 | 4 |
 | 3 | 4 | 4 | 1 | 5 |

 2 はすでに使用されているため、2 番目の 2 を増やす必要があり、衝突を避けるために 3 も上にシフトする必要があります。 

これらの例は、アルゴリズムが常に実行可能な最小の個別の値を順番に割り当てることを確認します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(n \log n)$| ソートが優先され、その後に 1 回のリニア スキャンが続きます。 
| スペース |$O(1)$または$O(n)$| インプレースソートの実装に応じて |

 ## 特殊なケース

 重要なエッジケースは、すべての要素が同一である場合です。`[5, 5, 5, 5]`。 ソート後、アルゴリズムはコスト 0、1、2、3 を持つ 5、6、7、8 をそれぞれ割り当てます。 の`current`ポインターは、新しい割り当てが衝突を避けるのに十分な量だけプッシュされることを保証し、それ以上プッシュされることはありません。 

もう 1 つのエッジ ケースは、次のような厳密に増加する配列です。`[1, 2, 3, 4]`。 各要素はすでに条件を満たしているため、アルゴリズムは変更されない値を割り当てます。`current`制約。 これにより、貪欲ルールによって不必要な増分が決して導入されないことが確認されます。 

みたいな混合クラスター`[1, 1, 2, 2, 3]`異なる値間の重複がどのように相互作用するかを示します。 アルゴリズムはソートされたシーケンスを均一に扱います。`current`グローバル制約を引き継いで、後の構造を壊すことなくローカル重複を解決します。
