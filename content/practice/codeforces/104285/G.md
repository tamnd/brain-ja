 ## 解決策
 ## 問題の理解

 任意の ASCII アルファベット上の 2 つの長い文字列が与えられます。 1 つの文字列は検索するパターンであり、もう 1 つはそのパターンにほぼ一致する文字列を検索するテキストです。 

タスクは、テキスト上でパターンをスライドさせ、配置のたびに、パターンを同じ長さのテキストの対応する部分文字列と比較することです。 異なる位置がいくつあるかを数え、この不一致数が最大でも 1 つであれば位置合わせを受け入れます。 最後に、有効なアライメントがいくつ存在するかを報告し、それらの開始インデックスを昇順にリストする必要があります。 

制約は非常に大きく、どちらの文字列も最大 100 万文字になる可能性があります。 これにより、アライメントごとに単純に不一致を再計算するソリューションは即座に除外されます。これは、n 個の位置ごとに最大 n 個の文字を比較する必要があり、二次関数の動作につながるためです。 

微妙な点は、アルファベットは DNA 文字に限定されないということです。 これにより、小さなアルファベットに基づいた周波数圧縮トリックの可能性が排除され、構造的な文字列比較方法が推進されます。 

単純な間違いは、不一致数をシフトごとに個別に再計算することです。 たとえば、パターンが次のような場合`"abc"`そしてテキストは`"abXabc"`、すべての位置でブルートフォース比較を行うと、同じプレフィックスが繰り返しスキャンされるため、冗長な作業が発生します。 もう 1 つの落とし穴は、ローリング ハッシュの等価性が不一致ゼロを意味すると仮定しており、これは「最大 1 つの不一致」条件には適用されません。 

## アプローチ

 ブルートフォース ソリューションでは、テキスト内のパターンの配置をすべて試し、文字を直接比較します。 各位置 i について、パターンのすべての m 文字をスキャンし、不一致をカウントします。 これは定義に正確に従っているので正しいですが、最悪の場合、O(nm) 回の操作が必要になります。 n と m が 10^6 までになると、これは完全に不可能になります。 

重要な観察は、実際にはすべての不一致を知る必要はないということです。 不一致数が 0 か 1 であるかのみを考慮し、それを超えるものはすべて同等と見なされます。 これは、不一致を直接カウントするのではなく、構造化情報の正確な一致を効率的に検出できる問題に問題を変換することを示唆しています。 

重要なトリックは、等価性チェックをプレフィックス ハッシュの観点から表現し、「最大 1 つの不一致」条件を少数の完全一致クエリに減らすことです。 2 つの文字列がちょうど 1 つの位置 k で異なる場合、それらは k より前のプレフィックスで同一であり、k の後のサフィックスで同一です。 これにより、比較が 1 つのブレークポイントを中心とした 2 つの独立した等価性チェックに分割されます。 ハッシュを通じて暗黙的にすべての可能なブレークポイントを試すことにより、明示的に文字をスキャンしなくても、不一致が存在するかどうかをテストできます。 

両方の文字列のローリング ハッシュを構築して、O(1) 内の任意の部分文字列を比較できるようにします。 次に、アラインメントごとに、部分文字列全体が一致するかどうか (不一致ゼロ) をチェックし、一致しない場合は、プレフィックスとサフィックスの両方が一致する分割点が存在するかどうかを判断します。 

これにより、各位置合わせチェックが O(1) に削減され、全体として線形のソリューションが得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nm) | お(1) | 遅すぎる |
 | ハッシュベースの分割チェック | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 パターンの長さを m、テキストの長さを n とします。 

1. ローリング ハッシュを使用して、両方の文字列のプレフィックス ハッシュを計算します。 これにより、任意の部分文字列を一定時間で比較できるようになります。 これが必要な理由は、直接比較を繰り返すとコストがかかりすぎるためです。 
2. 部分文字列ハッシュを迅速に正規化できるように、ハッシュ ベースの検出力を事前計算します。 これがなければ、部分文字列抽出は依然として線形になります。 
3. 0 から n - m までの各アライメント i について、部分文字列 t[i:i+m] と s を比較します。 
4. まず、ハッシュ比較を使用して部分文字列全体が正確に一致するかどうかを確認します。 存在する場合、これは不一致がゼロの有効な出来事です。 
5. 等しくない場合は、不一致が 1 つだけ存在するかどうかをテストします。 これを行うには、次のような分割位置 k を特定しようとします。 

接頭辞 s[0:k] は t[i:i+k] に等しく、接尾辞 s[k+1:m] は t[i+k+1:i+m] に等しい。 

すべての k を明示的に試す代わりに、そのような k が存在する場合、位置 k にある 1 文字を削除すると残りの文字列が等しくなるはずであるという事実を利用します。 プレフィックスとサフィックスのハッシュ比較を使用して、この状況をシミュレートします。 
6. 可能性のある不一致構造に対する二分探索を使用して候補の不一致位置をチェックし、プレフィックスの等価性を利用して最初の不一致の位置を特定します。 最初の不一致位置が見つかったら、その位置以降のすべてが一致することを確認します。 
7. この条件が当てはまる場合、i を有効として記録します。 

### なぜ効果があるのか

 正確さは、最大 1 つの不一致を含む文字列の構造特性によって決まります。 2 つの文字列が最大 1 つの位置で異なっている場合は、その前と後のすべてが同一であるという一意の境界が存在します。 有効なペアはすべて、そのような分解を許容しなければなりません。 ハッシュ スキームにより、文字をスキャンせずにこれらのプレフィックスとサフィックスの等価性を効率的にテストできるため、有効なアライメントが失われることも、無効なアライメントが受け入れられることもありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

BASE = 91138233
MOD = (1 << 61) - 1

def mod_mul(a, b):
    return (a * b) % MOD

def build_hash(s):
    n = len(s)
    h = [0] * (n + 1)
    p = [1] * (n + 1)
    for i, c in enumerate(s):
        h[i + 1] = (h[i] * BASE + ord(c)) % MOD
        p[i + 1] = (p[i] * BASE) % MOD
    return h, p

def get_hash(h, p, l, r):
    return (h[r] - h[l] * p[r - l]) % MOD

s = input().rstrip()
t = input().rstrip()

m, n = len(s), len(t)

hs, ps = build_hash(s)
ht, pt = build_hash(t)

def equal_sub(ti):
    return get_hash(ht, pt, ti, ti + m) == get_hash(hs, ps, 0, m)

def check_one_mismatch(ti):
    if equal_sub(ti):
        return True

    lo, hi = 0, m - 1
    while lo < hi:
        mid = (lo + hi) // 2
        if get_hash(hs, ps, 0, mid + 1) == get_hash(ht, pt, ti, ti + mid + 1):
            lo = mid + 1
        else:
            hi = mid

    k = lo

    if get_hash(hs, ps, k + 1, m) != get_hash(ht, pt, ti + k + 1, ti + m):
        return False

    return True

ans = []
for i in range(n - m + 1):
    if check_one_mismatch(i):
        ans.append(i + 1)

print(len(ans))
if ans:
    print(*ans)
```このソリューションは、ローリング ハッシュを利用して、一定時間内に部分文字列を比較します。 の`equal_sub`関数は完全一致を検出します。 の`check_one_mismatch`この関数は、完全一致はすでに処理されているため、まず完全一致を拒否し、次にプレフィックスの等価性に関する二分探索を使用して最初の不一致位置を特定します。 その位置が見つかると、それ以降のサフィックスが両方の文字列で同一であるかどうかが検証されます。 これにより、正確に 1 つの不一致が許容されることが保証されます。 

の部分文字列の境界には注意が必要です`get_hash`包含インデックスと排他インデックスを切り替えるときに、off-by-one エラーが発生しやすいためです。 二分探索は、不一致の位置だけでなく、最初の分岐点で停止する必要があります。そうしないと、複数の不一致が誤って受け入れられる可能性があります。

 ## 特殊なケース

 重要なエッジケースは、パターンが不一致なしで一致する場合です。 その場合、アルゴリズムは分割点検索を必要としてはなりません。 たとえば、次の場合`s = "abc"`そして`t = "abc"`、直接ハッシュの等価性はすぐに受け入れをトリガーし、二分探索は実行されません。 

もう 1 つの特殊なケースは、最初の文字で不一致が発生する場合です。 もし`s = "abc"`そして`t = "xbc"`、バイナリ検索により、位置 0 で最初の不一致が特定されます。その後、サフィックス比較により検証されます。`"bc"`等しい`"bc"`、有効性を確認します。 

3 番目のケースは、複数の不一致が存在する場合です。 もし`s = "abc"`そして`t = "axd"`、バイナリ検索ではインデックス 1 で最初の不一致が見つかりますが、サフィックスの比較は失敗します。`"c"`一致しません`"d"`。 これにより、アライメントが正しく拒否されます。
