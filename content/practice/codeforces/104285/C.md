 ## 解決策
 ## 問題の理解

 頂点に 1 から n までの番号が付けられたツリーから始めます。 最初は、各頂点 i は個別の色 i を持っているため、構成はノードに配置された恒等順列にすぎません。 

許可される唯一の操作は、エッジを選択し、その端点で 2 つの色を交換し、そのエッジを完全に削除することです。 エッジは一度しか使用できないため、すべての操作シーケンスは、エッジの一部を選択し、それらを使用する順序を決定することに対応しますが、ツリー構造により、選択したエッジが有効である限り、順序が最終的に到達可能な構成に影響を与えないことが保証されます。 

最終状態は、使用されたエッジに沿って色を移動することによって生成される、ノード間の色の並べ替えです。 質問は、色の最終的な順列をいくつ取得できるかを尋ねます。 

入力サイズ n は最大 150000 まで可能で、エッジの順列またはサブセットに対する指数関数的な探索が除外されます。 どのような解決策であっても、ほぼ線形またはほぼ線形の時間内で問題をツリー全体の構造カウントに削減する必要があります。 スワップをシミュレートしたり、到達可能な状態を列挙しようとする解決策は、順列の数さえ n! であるため、直ちに実行不可能になります。 

ローカルで考えると、微妙な問題が生じます。 各エッジが独立してスワップを許可するかスワッピングを許可しないため、2^(n−1) の結果が得られると考える人もいるかもしれません。 これは、スワップが相互作用するため間違っています。1 つのエッジを使用すると、色がサブツリーに移動し、将来のスワップの動作が変わります。 もう 1 つの間違ったアプローチは、スワップを隣接ノード上の任意の転置として扱い、独立性を前提とするもので、ツリー内のパスによって課せられるグローバルな一貫性制約を無視します。 

2 番目のエッジ ケースは、ツリーが単純なパスである場合に発生します。 ここでも、パリティ制約が正しく処理されない限り、到達可能な順列はセグメントのすべての順列ではありません。 パリティや二部性を無視した単純なモデルは、小さなパス グラフでは失敗します。 

## アプローチ

 主な難点は、操作がエッジ上でのローカルなスワップであるにもかかわらず、その影響がラベルのグローバルな移動となることです。 エッジは使用後に削除されるため、各エッジはその入射成分に沿って最大 1 つの転置に寄与します。 

プロセスを再解釈する便利な方法は、各エッジを、2 つのエンドポイント ラベルを交換するか、コンポーネントを効果的にマージして順列を伝播させる、潜在的な一致操作として考えることです。 エッジの使用後、2 つのエンドポイントは切断されますが、交換された情報はすでに伝播されています。 

スワップ用に選択されたエッジの固定サブセットに注目すると、結果として、それらのエッジによって形成される各連結コンポーネント内で、そのコンポーネントのエッジに沿った転置によって生成されたグループに従って色が完全に置換されます。 ツリーにはサイクルがないため、選択されたエッジによって誘導される各連結成分はそれ自体がツリーであり、どのツリーでも、その二部構造によって誘導されるパリティ制約と一致するすべての順列を正確に生成できます。 

重要な単純化は視点を反転することです。交換するエッジを選択する代わりに、各ノードが「固定ルート」として機能するか、可逆的な交換コンポーネントに参加する構造を構築することを検討します。 到達可能な構成は、いくつかのエッジを削除することによって形成されるコンポーネントへのツリーのパーティションに正確に対応し、各コンポーネント内で実現可能な順列の数はそのサイズと構造によってのみ決定されます。

グループ理論のより深い観察は、サイズ k のツリー コンポーネント上で、コンポーネントが 2 部構成 (すべてのツリーがそうである) の場合、エッジに沿ったスワップによって k 要素上の交互グループが正確に生成されますが、使用後にエッジが削除されるためパリティ制約がなくなり、接続性が尊重される限りパスに沿った任意の転置が可能になることが示されています。 これは重要な単純化につながります。接続されているすべてのコンポーネントがそのノード上の階乗自由度に寄与します。 

したがって、プロセスは次のようになります。各最終状態は、いくつかのエッジを削除することによって形成されたコンポーネントへのノードの分割に対応し、サイズ s の各コンポーネントは s! に寄与します。 そのコンポーネント内で可能なラベル割り当て。 答えはすべてのエッジ サブセットの合計になりますが、それらを列挙する代わりに、ツリー構造上の DP を使用します。 

私たちは木を根付かせ、ボトムアップで処理します。 各ノードについて、上向きに接続するかどうかに応じて、そのサブツリーを何通り配置できるかを計算します。 この遷移は、親と子の間のエッジを「カット」するか「維持」するかを選択する方法を数えたり、結果として生じるコンポーネントの要因寄与を組み合わせたりすることに似ています。 

これにより、各ノードに対して、組み合わせ係数を使用して子サブツリーをマージする多項式のような寄与を計算し、最終的にはサブツリー サイズで正規化された寄与の積が得られる、古典的なツリー DP が得られます。 最終的な閉じた形式は大幅に単純化されます。答えは n! 特定の乗算 DP に蓄積されたサブツリー サイズ寄与の逆数のすべてのノードにわたる積を乗算します。 

この構造は、頂点のすべての順序を、各サブツリーがいつ分離されるかの選択肢に一意に分解できるために現れます。 

結果として得られる最適なソリューションは、サブセットの列挙を完全に回避し、DFS を使用して線形時間で実行されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | エッジサブセットに対するブルートフォース | O(2^n · n) | O(n) | 遅すぎる |
 | サブツリー組み合わせ論上のツリー DP | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ノード 1 でツリーをルートします。ノードごとに、サブツリーのサイズと、そのサブツリーによって提供される有効な内部構成の数を表す DP 値の 2 つの量を計算します。 

1. ルートから DFS を実行して、サブツリーのサイズを計算します。 各ノードは、その子のサイズにそれ自体のサイズを 1 加えたものを累積します。 これが必要なのは、すべての寄与が各エッジ決定の下でグループ化されるノードの数に依存するためです。 
2. 同じ DFS 中に、子からの寄与を集計する各ノードの DP 値を計算します。 リーフ ノードの場合、単一の要素を配置する方法は 1 つしかないため、DP 値は 1 です。 
3. 子 v1、v2、...、vk を持つノード u を処理するとき、各子サブツリーは接続されたままになるか、接続エッジを介して分離される可能性があると考えられます。 重要なのは、子サブツリーのマージは、それらのノードの置換のインターリーブに対応し、これにより多項係数が導入されるということです。 
4. 子の貢献を繰り返し結合します。 合計サイズが S で DP 値が dp_u の子をすでにマージしているとします。 サイズ sz[v] と dp[v] の子 v を追加する場合、マージする方法の数は C(S + sz[v], sz[v]) と dp[v] の積で乗算されます。 これは、結合された順序付けの中から子サブツリーの位置を選択することを説明します。 
5. すべての子を処理した後、dp[u] は、u をルートとするサブツリーの有効な構成の数を表します。 
6. 最終的な答えは、998244353 を法とした dp[1] です。 

組み合わせ係数は、n までの階乗およびモジュラー逆関数を使用して計算されます。 階乗と逆階乗を事前計算して、O(1) の二項係数を評価します。 

### なぜ効果があるのか

維持される不変条件は、dp[u] が、エッジスワップ操作によって引き起こされる相対的な順序が尊重されるように、u のサブツリー内のすべてのノードを配置する方法の数をカウントすることです。 子サブツリーをマージするたびに、そのノードがすでに処理されたノードとどのようにインターリーブするかを効果的に選択することになります。このインターリーブは、素のサブツリーを保証するツリー構造により、子間で独立しています。 すべての有効な最終構成はそのようなマージのシーケンスに一意に対応するため、構成が 2 回カウントされることはなく、欠落する構成もありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

MOD = 998244353

def solve():
    n = int(input())
    g = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)

    fact = [1] * (n + 1)
    invfact = [1] * (n + 1)
    for i in range(1, n + 1):
        fact[i] = fact[i - 1] * i % MOD
    invfact[n] = pow(fact[n], MOD - 2, MOD)
    for i in range(n, 0, -1):
        invfact[i - 1] = invfact[i] * i % MOD

    def C(a, b):
        if b < 0 or b > a:
            return 0
        return fact[a] * invfact[b] % MOD * invfact[a - b] % MOD

    parent = [0] * (n + 1)
    sz = [0] * (n + 1)
    dp = [1] * (n + 1)

    def dfs(u, p):
        parent[u] = p
        sz[u] = 1
        dp[u] = 1
        for v in g[u]:
            if v == p:
                continue
            dfs(v, u)
            sz[u] += sz[v]

            dp[u] = dp[u] * dp[v] % MOD
            dp[u] = dp[u] * C(sz[u] - 1, sz[v]) % MOD

    dfs(1, 0)
    print(dp[1])

if __name__ == "__main__":
    solve()
```この実装では、階乗と逆階乗を事前計算して、定数時間の二項係数計算をサポートします。 DFS はサブツリーのサイズを計算し、DP をボトムアップで構築します。 

移行`C(sz[u] - 1, sz[v])`親のサブツリーの順序付けにおいてすでに蓄積されたノードの中から子サブツリーの位置を選択することをエンコードします。 乗算`dp[v]`子内部の取り決めを統合し、子全体の掛け算で独立性を強化します。 

ルート結果は、有効なグローバル構成の合計数です。 

## 実用的な例

 チェーン内の 3 つのノードからなる小さなツリーを考えてみましょう: 1 が 2 に接続され、3 に接続されます。 

階乗を暗黙的に計算し、DFS を 1 から実行します。 

| ノード | 子が処理されました | sz[u] | dp[u] | 説明 |
 | --- | --- | --- | --- | --- |
 | 3 | 葉 | 1 | 1 | 基本ケース |
 | 2 | v=3 | 2 | 1 * C(1,1)=1 | サブツリーを挿入する唯一の方法 |
 | 1 | v=2 | 3 | 1 * C(2,2)=1 | 最終集計 |

 結果は 1 です。これは、マージのこの解釈の下では、この構造内で 1 つの異なる構成のみに到達できることを意味します。 

このトレースは、構造を超えた余分な組み合わせ分岐を導入することなく、サブツリーのマージがどのように線形チェーンを処理するかを示しています。 

ここで、中心 1 と葉 2、3、4 を持つ星を考えてみましょう。 

ノード 1 では、リーフを順次マージします。 

最初のリーフの後: sz=2、dp=1

 2 番目のリーフの後: sz=3、dp=1 * C(2,1)=2

 3 番目の葉の後: sz=4、dp=2 * C(3,1)=6

 これは、葉を 3 つにインターリーブできるという事実と一致します。 センター注文を回避する方法。 

このトレースは、分岐ノードがサブツリーの多項挿入を通じて組み合わせ爆発に寄与していることを強調しています。

 ## 特殊なケース

 単一ノードの場合、スワップを実行するためのエッジがないため、可能な画像は最初の画像のみです。 DP は dp[1] = 1 に正しく初期化され、すぐに戻ります。 

パス グラフの場合、すべてのサブツリーのマージが順番に発生し、二項係数構造が 1 の連鎖に崩壊して、人為的な分岐が導入されないことが保証されます。 DFS は、各ノードが 1 回だけマージされることを保証し、正確性を維持します。 

スター グラフの場合、すべての葉は中心に接続された独立したサブツリーです。 リーフの挿入ごとに二項係数に従ってインターリーブの数が乗算され、アルゴリズムはリーフの取り付け順序の順列に対応する階乗増加を正しく累積します。
