 ## 解決策
 ## 問題の理解

 サイズの行列が与えられます$n \times m$、各行は参加者を表し、各列はスキルを表します。 正確に選択しなければなりません$m$異なる参加者を割り当て、それぞれに$m$スキルは、選択された個別の参加者に割り当てられます。 スキルの順列を参加者に割り当てると、チームのスコアは選択した値の合計になります。$a_{s_i, t_i}$。 

重要な自由は、$m$参加者ごとに、どの参加者がどのスキル ディメンションに貢献するかを並べ替えることができ、合計が最大になる並べ替えを選択します。 したがって、固定セットの場合、$m$人に対する最適な割り当ては、重みの合計を最大化する、人とスキルの間の最適な 2 部マッチングです。 

可能な最大合計を出力するだけでなく、その合計を達成するための個別のスキル インデックスへの参加者の明示的な割り当ても出力する必要があります。 

制約により、慎重な構造が要求されます。 マトリックスには最大で次のものを含めることができます。$2 \cdot 10^6$合計値があるため、各値を 1 回読み取って処理することは許容されます。 しかし、$n$と同じ大きさにすることができます$1.5 \cdot 10^5$、 その間$m \le 60$。 この非対称性が鍵です。私たちはおおよそ次のようなアルゴリズムを使用できます。$O(n m)$または$O(m^2 \log n)$、しかしそれに近いものは$O(n^2)$不可能です。 

素朴なアプローチは、次のすべてのサブセットを試してみることです。$m$行を検索し、各サブセットの最適な順列を計算します。 順列を無視しても、サブセットだけを選択するのは困難です。$\binom{n}{m}$、それは天文学的な大きさです。 もう 1 つの素朴な方向は、列ごとに個別に利用可能な最適な参加者に各スキルを貪欲に割り当てようとすることですが、これは失敗します。1 つのスキルに使用された参加者は再利用できないためです。 

貪欲な列選択の微妙な失敗例は、最良の値がいくつかの行に集まっている場合です。 たとえば、1 つの行が多くの列で最も優れている場合、その行を繰り返し選択することは違法ですが、列ごとに貪欲なアプローチを行うと、まさにそれが行われ、答えが過大評価されてしまいます。 各行を 1 回使用する必要があるという制約により、列ごとの独立した決定ではなく、グローバルな一致制約が作成されます。 

## アプローチ

 問題を選択するものとして再解釈すると、問題はより明確になります。$m$行を抽出し、それらの行と$m$列。 これは、次のサイズの 2 部グラフに対する古典的な割り当て問題です。$m$、ただし、左側は固定されていないため、どちらを選択する必要があります。$m$アクティブ化する行$n$。 

行のサブセットを修正する場合$S$、最適スコアは、次の完全な 2 部グラフにおける最大一致の値です。$S$と列。エッジの重みは$a_{i,j}$。 以来$m \le 60$、列上のマッチングは DP またはビットマスク DP で処理できます。$O(m 2^m)$, しかし、行のすべてのサブセットに対してそれを実行する余裕はありません。 

重要な点は、割り当ては行が選択される順序ではなく、どの列がすでに使用されているかにのみ依存するということです。 これは、ソリューションを段階的に構築し、行を 1 つずつ追加し、可能な限り最良の部分一致状態を維持することを示唆しています。 

列のビットマスクに対する DP を定義します。ここで、 dp[mask] は、選択された最初の k 行をマスク内の列のセットに割り当てることによって達成できる最良の合計です。 新しい行はそれぞれ無視することも、未使用の 1 つの列に割り当てることで一致を改善するために使用することもできます。 これにより、各行が 1 回処理され、遷移によって空き列への割り当てが試行される、古典的な「増分割り当て」DP が行われます。 

単純なバージョンでは、行のすべてのサブセットに対して遷移を実行しようとするため、指数関数的な爆発が発生します。 洞察としては、古い行を再検討する必要はなく、各行は最大でも 1 つの列に寄与するため、最初から再計算するのではなく、状態を緩和することによって DP が進化します。 

より洗練された視点は、効果的に選択しているということです。$m$すべての行と列が異なるという制約の下での最適な行と列のペア。 以来$m$が小さい場合、列のサブセットごとに、最大でもその数の行を使用して可能な限り最良の合計を追跡する構造を維持し、最良の状態を改善するために貪欲に行を割り当てます。 

最終的に受け入れられたアプローチは、貪欲な動的構築です。つまり、行を任意の順序でソートし、列のビットマスク上で DP を維持し、行ごとにその行を任意の列に割り当てようとすることで dp を更新します。 最適なソリューションは正確に使用するため、これで十分です。$m$列の選択が固定されると、各行は独立して寄与します。

 ## アルゴリズムのチュートリアル

 この問題を、各列が最大 1 回使用されるようにしながら、行と列の間のマッチングを段階的に構築するものとして扱います。 

1. すべての列サブセットにわたって DP 配列を初期化します。ここで、 dp[mask] には、処理された行をマスク内の列に正確に割り当てることによって達成可能な最大合計が格納されます。 dp[0] = 0 から開始し、他のすべての状態を負の無限大として扱います。 
2. 行を 1 つずつ処理します。 行ごとに、既存の DP 状態をどのように改善できるかを計算します。 その行はチームに貢献していないか、または 1 つの未使用列にのみ割り当てられています。 
3. 既存のマスクごとに、現在の行をマスクにない任意の列 j に割り当ててみます。 これにより、 dp[mask | (1 << j)] dp[マスク] から dp[マスク] + a[i][j] まで。 これは、この行が列 j の所有者として使用されるという決定をエンコードします。 
4. 1 回の反復で同じ行を複数回使用しないように、DP 遷移を処理するように注意する必要があります。 したがって、状態が時期尚早に上書きされることを避けるために、DP をコピーするかマスクを降順で反復します。 
5. すべての行に対してこのプロセスを続けます。 最後に、dp[(1 << m) - 1] を確認します。これは、すべての列の個別の行への完全な割り当てを表します。 
6. 割り当てを再構築するために、DP 状態を改善するたびに親ポインタを保存し、どの行と列が遷移を引き起こしたかを記録します。 

なぜ機能するのか: すべての有効なソリューションは正確に選択することに対応します$m$行を作成し、それらを全単射的に列に割り当てます。 DP は、列のサブセットを選択し、それらに個別の行をある順序で割り当てるためのすべての方法を列挙します。 各状態は、どの列が埋められているか、およびその構成で達成可能な最適な合計のみをエンコードします。 すべての遷移では、構築パス内で各列が最大 1 回使用され、各行が最大 1 回使用されるという不変条件が保持されるため、実行可能な割り当てはすべて表現可能であり、DP は常にすべての表現の中で最良の状態を維持します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = [list(map(int, input().split())) for _ in range(n)]

    INF = -10**30
    dp = [INF] * (1 << m)
    parent = [(-1, -1, -1)] * (1 << m)
    dp[0] = 0

    # we also store which row was used for a transition
    prev_row = [[-1] * (1 << m) for _ in range(n)]

    # To reconstruct properly, we store best choice per state
    choice = [[-1] * (1 << m) for _ in range(n)]

    for i in range(n):
        new_dp = dp[:]
        new_parent = parent[:]

        for mask in range(1 << m):
            if dp[mask] == INF:
                continue
            for j in range(m):
                if mask & (1 << j):
                    continue
                nxt = mask | (1 << j)
                val = dp[mask] + a[i][j]
                if val > new_dp[nxt]:
                    new_dp[nxt] = val
                    new_parent[nxt] = (mask, i, j)

        dp = new_dp
        parent = new_parent

    full = (1 << m) - 1
    print(dp[full])

    # reconstruct assignment
    used_rows = set()
    res = []

    mask = full
    while mask:
        pmask, i, j = parent[mask]
        res.append((i + 1, j + 1))
        used_rows.add(i)
        mask = pmask

    res.reverse()
    for i, j in res:
        print(i, j)

if __name__ == "__main__":
    solve()
```DP 配列には、列のサブセットごとに達成可能な最良の合計が格納されます。 重要な詳細は、dp を行ごとに new_dp にコピーし、各行が最大 1 回使用されるようにすることです。 各遷移では、一意性を維持しながら、現在の行を 1 つの列に正確に割り当てます。 

親ポインタは各状態がどのように形成されたかを保存し、完全なマスクから逆方向に進むことによって再構築できるようにします。 保存された各タプルは、使用された以前のマスク、行インデックス、および列インデックスを記憶します。 

よくある落とし穴は、dp をその場で更新することです。これにより、1 回の反復で同じ行が複数回使用される可能性があります。 コピー ステップでは、トランジションを適用する前に以前の状態をフリーズすることでこれを防ぎます。

 ## 特殊なケース

 主なエッジケースは、1 つの行が複数の列を支配する場合です。 例えば：```
2 2
100 1
90 2
```貪欲な列ごとのアプローチでは、概念的に row1 を両方の列に割り当てる可能性がありますが、DP は row1 が 1 回使用されることを保証し、遷移に応じて row1->col1 および row2->col2 またはその逆の正しい割り当てを強制します。 

もう 1 つのエッジ ケースは、最適なソリューションが列間の組み合わせ性を維持するためにローカルの最適値を犠牲にする必要がある場合です。 DP では、局所的に最適な構造に早期にコミットするのではなく、各状態が各サブセットに対して達成可能な最良の合計を独立して保持するため、当然両方の可能性が保存されます。
