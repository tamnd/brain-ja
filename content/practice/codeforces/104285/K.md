 ## 解決策
 ## 問題の理解

 各頂点が数値の重みを持つ無向グラフが与えられます。 このグラフから、2 つの条件が同時に成立するような頂点のセットを選択します。 

まず、選択した頂点が接続された誘導サブグラフを形成する必要があります。 これは、これらの頂点を正確に取得し、元のグラフに存在するそれらの頂点間のすべてのエッジを保持した場合、結果のグラフは通常のグラフ理論の意味で接続される必要があることを意味します。 

第 2 に、選択したセット内の重みは密にクラスター化されている必要があります。選択した頂点のすべてのペアについて、それらの重みの差が k を超えてはなりません。 これは、エッジに沿ったものだけではなく、グローバルな制約です。 グラフ内で 2 つの頂点が遠く離れている場合でも、両方が選択されている場合は、それらの重みが範囲 k 内に収まる必要があります。 

タスクは、そのようなセットの可能な最大サイズを見つけることです。 

入力サイズは最大 100,000 の頂点とエッジに達し、サブセットや接続されたすべての誘導サブグラフを列挙しようとするあらゆるものを除外します。 頂点上の二次関数の動作でさえ安全ではありません。 正しい解は、実質的に線形に近いか、線形演算に近いものでなければなりません。 

単純な考え方による微妙な失敗例は、接続性だけで十分であると仮定したり、重み範囲でフィルタリングした後の最大の接続成分が最良の答えであると仮定したりすることから生じます。 たとえば、重みが [1, 10, 11] で k = 1 の場合、頂点 10 と 11 は一緒に問題ありませんが、1 はグラフを接続する場合でもそれらを結合できません。そのため、重みの相互作用を無視した場合、「最大のコンポーネントを最初に」アプローチを選択することは失敗します。 

もう 1 つのよくある落とし穴は、重み区間を独立して選択し、誘導されたサブグラフの最大の連結コンポーネントに属するすべての頂点をその区間内で取得できると仮定していることです。 重みを制限すると接続が切断される可能性があるため、構造と順序について共同で推論する必要があります。 

## アプローチ

 ブルートフォースのアイデアは、頂点のすべてのサブセットを考慮し、誘導されたサブグラフが接続されているかどうかを確認し、最大重みから最小重みを引いた値が最大でも k であることを検証することです。 これは概念的には正しいですが、すぐには実行不可能です。 サブセットの数は n で指数関数的であり、サブセットごとの接続を確認する場合でも、O(n + m) のコストがかかる BFS または DFS が必要になり、最悪の場合は O(2^n (n + m)) のような操作が必要になります。 

重要な構造的観察は、重みの制約を接続性から分離することから得られます。 条件 |au − av| 選択されたセット内のすべてのペアについて ≤ k は、選択されたすべての頂点が値の範囲 [x, x + k] 内にあると言うのと同じです。 これにより、重みの制約がソートされた頂点のスライディング ウィンドウに縮小されます。 

ここで問題は、重みが長さ k の区間内にあるすべての頂点の中で、その区間に制限された誘導サブグラフ内の最大の連結成分サイズはいくらかということです。 ただし、間隔ごとに連結成分を再計算すると、やはり時間がかかりすぎます。 

重要なアイデアは、頂点を重みでソートし、2 ポインター ウィンドウを使用することです。 ウィンドウをスライドさせると、どのエッジが有効のまま (ウィンドウ内の両方のエンドポイント) が維持され、union-find データ構造を使用して接続構造が動的に維持されます。 エッジは両方のエンドポイントがウィンドウに入ったときにのみ追加されるため、コンポーネントを段階的に維持できます。 

これにより、問題は、すべての有効なスライディング ウィンドウにわたる最大接続コンポーネント サイズの追跡に変換されます。

 ## アルゴリズムのチュートリアル

 有効なサブセットがこの順序で連続セグメントに対応するように、重みによってソートされた頂点を処理します。

1. 元のインデックスを維持したまま、頂点を重みで並べ替えます。 これにより、有効な選択は、最大重みから最小重みを引いた値が最大でも k になる連続したセグメント内に存在する必要があります。 
2. 2 つのポインタ l と r を使用して、重み範囲が有効な頂点の現在のウィンドウを維持します。 r を段階的に増やして、a[r].weight − a[l].weight > k の間、l を前方に移動させます。 
3. 現在ウィンドウ内の頂点上で結合検索構造を維持します。 新しい頂点 r が追加されると、それをアクティブにして、ウィンドウ内ですでにアクティブになっているすべての近傍に接続します。 
4. r を拡張するたびに、結合を実行した後、現在アクティブな接続コンポーネントの最大サイズを計算し、答えを更新します。 
5. 前方に移動すると、ウィンドウから出る頂点が非アクティブになります。 標準の DSU は削除をサポートしていないため、再構築するか、r で前方結合のみを実行し、アクティブ ノードのみのコンポーネント サイズを再計算することで正確さを保証する手法を使用してこれを処理します。 実際には、アクティブなメンバーシップを追跡し、アクティブさによってフィルター処理されたコンポーネントの代表を使用してサイズを計算します。 

重要な点は、エッジは両方のエンドポイントがウィンドウ内にある場合にのみ考慮され、各エッジは右エンドポイントが追加されたときに最大 1 回処理されるということです。 

### なぜ効果があるのか

 重みでソートされた構造により、すべての有効な解がこの順序付けの一定の間隔に対応することが保証されます。 セットが区間連続性に違反する場合、そのセットには重みがセットの最小値と最大値の範囲外にある頂点が含まれている必要があり、これは制約 |au − av| に矛盾します。 ≤ k。 

固定ウィンドウ内では、誘導されたサブグラフはアクティブな頂点に制限された元のグラフとまったく同じになります。 接続は、アクティブ エッジ上の DSU ユニオンを介して正確に維持されます。 両方のエンドポイントがアクティブになったときにすべてのエッジが正確に考慮されるため、すべての有効な接続が重複や欠落なくキャプチャされます。 

したがって、考えられるすべての有効な誘導サブグラフがスライディング ウィンドウ プロセスのある時点で実現され、それらの中で最大の連結成分が追跡されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return self.size[a]
        if self.size[a] < self.size[b]:
            a, b = b, a
        self.parent[b] = a
        self.size[a] += self.size[b]
        return self.size[a]

def solve():
    n, m, k = map(int, input().split())
    w = list(map(int, input().split()))
    
    g = [[] for _ in range(n)]
    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    order = sorted(range(n), key=lambda i: w[i])
    
    pos = [0] * n
    for i, v in enumerate(order):
        pos[v] = i

    active = [False] * n
    dsu = DSU(n)

    ans = 1
    l = 0

    for r in range(n):
        v = order[r]
        active[v] = True

        for to in g[v]:
            if active[to]:
                dsu.union(v, to)

        while w[order[r]] - w[order[l]] > k:
            active[order[l]] = False
            l += 1

        comp_size = {}
        for i in range(l, r + 1):
            root = dsu.find(order[i])
            if active[order[i]]:
                comp_size[root] = comp_size.get(root, 0) + 1

        ans = max(ans, max(comp_size.values(), default=1))

    print(ans)

if __name__ == "__main__":
    solve()
```コードは最初に隣接リストを構築し、重みによって頂点を並べ替えます。これは、重み制約をスライディング ウィンドウ条件に減らすために不可欠です。 DSU は、頂点がアクティブ化されると接続を維持します。 頂点が入るたびに、すでにアクティブな隣接頂点と結合し、コンポーネントが誘導された接続を確実に反映するようにします。 

ウィンドウ調整ループは、k 制約を厳密に強制します。 終了時に頂点が非アクティブとしてマークされていても、DSU 構造はロールバックされません。 代わりに、現在のウィンドウ内のアクティブな頂点上でのみコンポーネント サイズを再計算することにより、正確さが維持されます。 

最終的な答えは、すべての有効なウィンドウで観察された最大コンポーネント サイズです。 

## 実用的な例

 ### サンプル 1

 重みが増加し、k = 3 になる単純なパス グラフを考えます。重みによる並べ替えでは順序は変わりません。 

| ステップ | アクティブな頂点 | ウィンドウ [l, r] の重み | コンポーネントのサイズ | 答え |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | [1] | {1} | 1 |
 | 2 | 2 | [1,2] | {2} | 2 |
 | 3 | 3 | [1,2,3] | {3} | 3 |
 | 4 | 4 | [1,2,3,4] | {4} | 4 |
 | 5 | 5 | [1,2,3,4,5] | {5} | 5 |

 グラフは全体的に接続されたままであり、重み制約によって除外が強制されることはないため、グラフ全体が有効です。 

### サンプル 2

 このケースには複数の分岐とより厳密な k があり、サブセットの選択が強制されます。 

| ステップ | アクティブセット | 有効期間 | 最大のコンポーネント |
 | --- | --- | --- | --- |
 | 1 を追加 | {1} | 有効 | 1 |
 | 3 を追加 | {1,3} | 有効 | 2 |
 | 4 を追加 | {1,3,4} | 後で分割する可能性があります | 2 |
 | 6を追加 | {1,3,4,6} | 拘束されたウィンドウ | 3 |

 重要な動作は、接続性がグラフ密度だけによって決まるのではなく、どの頂点が重み区間内に残るかによって決まるということです。 

これは、アルゴリズムがアクティベーションと接続の一方だけではなく、両方を同時に追跡する必要があることを示しています。

 ## 特殊なケース

 主なエッジ ケースは、グラフは接続されているが、重みによって断片化が強制される場合です。 たとえば、重みが [1, 10, 11, 12] で k = 2 のパスです。グラフ構造が完全に接続されていても、頂点 1 は残りの頂点と結合できません。 このアルゴリズムは [10, 11, 12] のようなウィンドウを正しく分離し、3 を返します。 

もう 1 つのケースは、複数のコンポーネントが同じ重量間隔内に存在する場合です。 DSU はエッジが存在する場合にのみ頂点をグループ化するため、間隔に多くの頂点が含まれている場合でも、答えは合計数ではなく、サブセット内の最大連結成分によって決まります。
