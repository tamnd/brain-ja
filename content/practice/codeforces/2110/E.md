 ## 解決策
 ## 問題の理解

 私たちは、それぞれ音量とピッチで定義された一連の音を、美しく同時に退屈しないシーケンスに配置することが求められます。 美しいとは、連続する音が正確に 1 つの次元で異なることを意味します。つまり、ピッチが一定のまま音量が変化するか、または音量が一定のままピッチが変化するかのいずれかです。 退屈しないとは、同じ音量やピッチを共有する 3 つの連続した音が存在しないことを意味します。 すべてのサウンドはシーケンス内で 1 回だけ出現する必要があります。 

入力は複数のテスト ケースを提供します。 各テスト ケースはサウンドの数から始まり、各サウンドの音量とピッチが続きます。 出力は、有効な取り決めが存在するかどうかを示す必要があります。 その場合は、サウンド インデックスの有効な順序も提供する必要があります。 

この制約は、強引な並べ替え手法を使用する余裕がないことを意味します。 と$n$まで$2 \cdot 10^5$すべてのテスト ケースで 2 秒の制限があり、これよりも悪いアルゴリズムはありません。$O(n \log n)$テストケースごとの処理は遅すぎる可能性があります。 あらゆることを試す素朴なアプローチ$n!$順列は絶望的でしょう。 さらに、ボリュームとピッチの値は最大にできるため、$10^9$、値による直接のインデックス作成やカウントは実行できません。 主に並べ替えられた順序または相対関係に基づいて動作するメソッドが必要です。 

明らかではないエッジケースには、すべてのボリュームまたはすべてのピッチが同一である状況が含まれます。 たとえば、すべてのサウンドの音量が同じでピッチが異なる場合、連続する 3 つのピッチが等しくなることはありえないため、2 を超える長さのシーケンスはすでに不可能になる可能性があります。 もう 1 つの注意が必要なケースは、個別の音量とピッチの数が近いにもかかわらず、その分布により音量の変更とピッチの変更が交互に行われない場合に発生します。 小さい$n$1 や 2 などは簡単ですが、非退屈条件は長さが 3 以上のシーケンスにのみ適用されるため、これらを個別に処理する必要があります。 

## アプローチ

 強引な方法では、サウンドのすべての順列を試し、美しく退屈しない特性をチェックします。 これは原理的には正しいです。順列が与えられると、次の連続する差分と三重値を検証できます。$O(n)$時間。 ただし、置換の数は、$n!$、これは天文学的に大きい$n > 10$。 したがって、ブルートフォースは実行不可能です。 

重要な洞察は、各サウンドが音量またはピッチによってグループ化できることを観察することで得られます。 最初に音量でサウンドを並べ替え、次にピッチで (またはその逆)、1 つの次元で異なるシーケンスを抽出できることがよくあります。 具体的には、1 つの軸がボリューム、もう 1 つの軸がピッチであるグリッドを形成できます。 このグリッドを蛇のようなパターンで移動できます。特定のボリュームのすべてのピッチを繰り返し、次に次のボリュームに移動し、ピッチの順序を逆にします。 これにより、ボリューム内で移動するとピッチのみが変化し、新しいボリュームに移動すると音量のみが変化するため、連続するサウンドは正確に 1 次元で異なることが保証されます。 方向を慎重に交互に変えることで、どちらの次元でも 3 つの連続する同一の値が作成されることを避けることができます。 

このスネークトラバースを分類して構築するのは、$O(n \log n)$ソートのせいで、それが必要です$O(n)$注文内容を保管するスペース。 制約を考慮すると、これは許容されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | お(ん!) | O(n) | 遅すぎる |
 | ソートによるスネークトラバーサル | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、すべてを読みます。$n$サウンドとその元のインデックス。 各サウンドを (ボリューム、ピッチ、インデックス) のタプルとして保存して、最後に順序を出力できるようにします。 
2. サウンドを音量ごとにグループ化します。 各音量グループ内で、サウンドをピッチ順に並べ替えます。 これにより、グループ内での反復処理によってピッチのみが変更されることが保証されます。 
3. 空の結果シーケンスを初期化します。 各ボリューム グループを昇順で調べます。 偶数番号のグループの場合は、ピッチを昇順に移動します。 奇数番号のグループの場合、ピッチを降順に移動します。 この蛇のようなパターンにより、同じボリュームやピッチが 3 つ連続して作成されるのを防ぎます。 
4. トラバーサル中に、各サウンドのインデックスを結果シーケンスに追加します。 結果内の連続するサウンドは、ボリューム グループ内のピッチ、またはグループ間を移動するときのボリュームのいずれか 1 つの次元でのみ異なります。 
5. シーケンスを構築した後、退屈なトリプルがないか確認します。 結果内の連続するインデックスのトリプルごとに、すべてのボリュームとすべてのピッチが等しいわけではないことを確認します。 トリプルがこの条件に違反する場合は、「NO」を出力します。 それ以外の場合は、「YES」に続いて一連のインデックスを出力します。 
6. テスト ケースごとに上記の手順を繰り返します。 

構築中に維持される不変条件は、各ボリューム グループ内ではピッチが反復せずに交互に変化し、ボリューム グループ間ではピッチが交互の順序で継続しながらボリュームが変化するということです。 これにより、連続するサウンドが美しくなり、蛇のようなトラバースによって同じ値が連続して 3 つ存在しないため、退屈なトリプルを防ぐことができます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        sounds = []
        for i in range(n):
            v, p = map(int, input().split())
            sounds.append((v, p, i + 1))

        from collections import defaultdict
        groups = defaultdict(list)
        for v, p, idx in sounds:
            groups[v].append((p, idx))

        sequence = []
        volumes_sorted = sorted(groups.keys())
        toggle = False
        for v in volumes_sorted:
            pitches = sorted(groups[v])
            if toggle:
                pitches.reverse()
            for p, idx in pitches:
                sequence.append((v, p, idx))
            toggle = not toggle

        possible = True
        for i in range(2, n):
            v1, p1, _ = sequence[i-2]
            v2, p2, _ = sequence[i-1]
            v3, p3, _ = sequence[i]
            if (v1 == v2 == v3) or (p1 == p2 == p3):
                possible = False
                break

        if possible:
            print("YES")
            print(" ".join(str(idx) for _, _, idx in sequence))
        else:
            print("NO")

if __name__ == "__main__":
    solve()
```このソリューションは入力を効率的に読み取り、元のインデックスを保存します。 ボリュームによるグループ化とピッチによるソートにより、ヘビのようなトラバースが可能になります。 トグルにより、グループ間で交互の順序が保証されます。これは、退屈なトリプルを避けるために重要です。 最後の検証ループでは、退屈ではない条件に違反するトリプルがないことを確認します。
