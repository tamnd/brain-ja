 ## 解決策
 ## 問題の理解

 バランスの取れた一連のかっこを表す文字列が与えられました。そして、結果の文字列のバランスが崩れるように、開始括弧と閉じ括弧を 1 つだけ削除できるかどうかを判断する必要があります。 バランスの取れたシーケンスは、通常のルールに従います。つまり、すべての開始括弧には対応する終了括弧があり、括弧は適切にネストされます。 

入力は複数のテスト ケースで構成され、各文字列のバランスが保証されています。 各文字列の長さは最大 200,000 であり、すべてのテスト ケースにわたるすべての文字列の合計も 200,000 を超えることはありません。 これは、二次アルゴリズムや三次アルゴリズムでは遅すぎるため、各テスト ケースを文字列長に対してほぼ直線的な時間で解決する必要があることを意味します。 

可能な限り最小のバランスの取れたシーケンスは「()」と「((...))」であり、これにより、エッジケースについての洞察が得られます。 たとえば、「()」のようなシーケンスは、開始括弧と終了括弧を 1 つ削除しても分割できません。両方を削除すると、空の文字列が残り、バランスが保たれます。 同様に、「(())」など、個別のバランスの取れたブロックが連結されていない完全にネストされたシーケンスも、各タイプの括弧の 1 つを削除しても分割できません。 一方、「(())()()」のような、バランスの取れたサブシーケンスが連結されたシーケンスは、隣接するブロックの最後の左括弧と最初の閉じ括弧を削除することで分割できます。 

明らかではないエッジ ケースは、シーケンスが "(())" などの単一のネストされたブロックである場合に発生します。この場合、異なる位置から 1 つの開始括弧と 1 つの終了括弧を削除しても、不均衡が生じることはありません。 素朴に無作為に削除しようとすると、壊れる可能性があると思われるかもしれませんが、慎重に調べれば壊れないことがわかります。 

## アプローチ

 ブルートフォースアプローチでは、1 つの開始括弧と 1 つの終了括弧のすべてのペアを考慮し、それらを削除し、結果の文字列のバランスが取れているかどうかを確認します。 バランスをチェックするには、文字列をスキャンし、正味の開き括弧のカウンターを維持する必要があります。 このアプローチは正しいですが、ある長さの文字列の場合です$n$、それには関係するでしょう$O(n^3)$最悪の場合の動作:$O(n^2)$ペアと$O(n)$バランスを確認するため。 と$n$200,000 までは不可能です。 

重要な観察は、バランスの取れたシーケンスが破壊に耐えられるのは、それが連結されていない完全にネストされた単一ブロックである場合のみであるということです。 シーケンスの前半がすべてオープニングで、後半がすべてクローズの場合、最初から 1 つのオープニングを削除し、最後から 1 つのクロージングを削除しても、バランスの取れたシーケンスが残ります。 この構造は、連結されていない "((...))" 形式の文字列と同等です。 他のバランスのとれたシーケンスには、隣接する少なくとも 2 つの「ブロック」があります。 最初のブロックの最後の開口部と次のブロックの最初の閉じ部を削除すると、不均衡が生じるため、ブロックが壊れる可能性があります。 

したがって、問題は、シーケンスが完全にネストされたブロックであるかどうかをチェックすることに帰着します。 そうであれば、「NO」を出力します。 それ以外の場合は「YES」を出力します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^3) | O(n) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースごとに、文字列を読み取ります。$s$。 文字列のバランスが保証されているため、開き括弧の数は閉じ括弧の数と同じになります。 
2. 文字列の先頭から最初の閉じ括弧までの連続する開き括弧の数を数えます。 これに電話してください`prefix_open`。 
3. 文字列の末尾から最初の左括弧までの連続する閉じ括弧の数を逆に数えます。 これに電話してください`suffix_close`。 
4. 比較する`prefix_open + suffix_close`文字列の全長になります。 それらが文字列の長さと等しい場合、すべての左括弧が先頭にあり、すべての閉じ括弧が末尾にあることを意味します。 これは単一のネストされたブロックです。 
5. 単一のネストされたブロックの場合は、開始括弧と終了括弧を 1 つずつ削除してもバランスの取れたシーケンスが残るため、「NO」を出力します。 それ以外の場合は、隣接する 2 つのブロックから括弧を削除してバランスを崩す方法が少なくとも 1 つあるため、「YES」を出力します。 

機能する理由: ここでの不変条件は、単一のネストされたブロックではないバランスのとれたシーケンスには、2 つのブロック間に少なくとも 1 つの境界が含まれるということです。 あるブロックの終わりから 1 つのブラケットを削除し、次のブロックの先頭から 1 つを削除すると、常に一致しないブラケットが生成され、バランスが崩れます。 逆に、単一のネストされたブロックは、各タイプのブラケットの 1 つだけを使用して分割することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    t = int(input())
    for _ in range(t):
        s = input().strip()
        n = len(s)
        prefix_open = 0
        while prefix_open < n and s[prefix_open] == '(':
            prefix_open += 1
        suffix_close = 0
        while suffix_close < n and s[n - 1 - suffix_close] == ')':
            suffix_close += 1
        if prefix_open + suffix_close == n:
            print("NO")
        else:
            print("YES")

if __name__ == "__main__":
    main()
```最初のループは、最初の連続する開始括弧をカウントします。 2 番目のループでは、後続の連続する閉じ括弧をカウントします。 それらの合計を全長と比較すると、単一のネストされたブロック構造が直接チェックされます。 「()」や「((()))」などのエッジケースは正しく処理されます。`prefix_open + suffix_close`は文字列の長さに等しいため、正しい「NO」が生成されます。

 ## 特殊なケース

 「()」の場合、アルゴリズムはカウントします`prefix_open = 1`そして`suffix_close = 1`。 それらの合計は文字列の長さである 2 に等しいため、「NO」が正しく出力されます。 100,000 '(' の後に 100,000 ')' が続くような大きなネストされたブロックの場合、カウンターは単一のネストされたブロックを正しく検出し、「NO」を返します。 「(())()()」のような連結されたブロックの場合、プレフィックスとサフィックスの合計が全長より小さくなり、「YES」がトリガーされ、アルゴリズムがブロック間の境界を正しく処理していることがわかります。
