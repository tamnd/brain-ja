 ## 解決策
 ## 問題の理解

 私たちはロボットを一連のチェックポイントを通過するように誘導するように求められます。 各チェックポイントにはロボットが収集できる一定数のバッテリーがあり、いくつかのチェックポイントを結ぶ一方通行の通路があります。 各通路を通過するには、ロボットが少なくとも一定数のバッテリーを運ぶ必要があります。 ロボットはバッテリーがゼロの状態で最初のチェックポイントからスタートし、できるだけ少ないバッテリーで最後のチェックポイントに到達したいと考えています。 すべてのチェックポイントで、ロボットはそこで利用可能な任意の数のバッテリーを拾うことができ、以前に収集されたすべてのバッテリーは各チェックポイントで完全に充電されます。 

課題は、ロボットが最終チェックポイントに到達する際に搭載できるバッテリーの最小数を計算するか、最終チェックポイントに到達することが不可能であると報告することです。 

この制約は、チェックポイントの数が$n$到達できる$2 \cdot 10^5$そして通路の数$m$到達できる$3 \cdot 10^5$、一方、合計は$n$と合計$m$すべてのテスト ケースがこれらの範囲内に収まります。 これにより、すべてのパスを列挙したり、任意のパスを実行しようとする単純なソリューションが除外されます。$O(n^2)$通路での操作。 ほぼ直線的なものを目指す必要があります$n + m$または、対数的なオーバーヘッドが含まれる場合など$O((n+m) \log n)$。 

エッジケースは、一部の経路でロボットが収集できる以上のバッテリーを必要とするシナリオに発生します。 たとえば、最初のチェックポイントのバッテリーがゼロで、最初の出口にバッテリーが 1 つ必要な場合、ロボットは移動できません。 もう 1 つの微妙なシナリオは、バッテリー数が異なるチェックポイントへの複数の経路が存在する場合に発生します。この場合、早めにより多くのバッテリーを取得すると、後で要求の厳しい通路を通過できる可能性があります。 これらのオプションの管理を誤ると、簡単に誤った答えが得られる可能性があります。 

## アプローチ

 ブルート フォース アプローチでは、チェックポイント 1 からチェックポイントまでのすべてのパスを検討します。$n$、ロボットが各経路に沿って運ぶバッテリーの数を追跡します。 各チェックポイントで、すべての可能な数のバッテリーを試し、各出口通路を再帰的または反復的に探索できます。 このアプローチは原理的には正しいですが、パスの数は次のように指数関数的に増加します。$n$そして$m$。 チェックポイントとバッテリー数によってキー化されたメモ化を使用しても、バッテリー数自体の範囲は最大で$10^9$、状態空間を扱いにくくします。 

重要な洞察は、問題が、実現可能性チェックと組み合わせた最終的な最小バッテリー数に対する二分探索に帰着できるということです。 電池の目標数を決めたら$B$最後のチェックポイントで、チェックポイントに到達できるかどうかを確認できます$n$それ以上のものを決して持ち込まないで$B$いつでもバッテリー。 実現可能性チェックは、ダイクストラにヒントを得た貪欲なアプローチを使用して実行できます。つまり、各チェックポイントで、通過要件を尊重しながらロボットが保持できる最大バッテリー数を追跡します。 通路は前にしか進まないから($s_i < t_i$)、グラフは非周期的であり、チェックポイント 1 からチェックポイントまでの動的プログラミングの伝播を可能にします。$n$直線的な順序で。 これにより、二分探索が実行可能な最小の最終バッテリー数に効率的に収束することが保証されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n * max(b_i)) | 遅すぎる |
 | 最適 (二分探索 + DP/実現可能性) | O((n+m) log S) | O(n + m) | 承認済み |

 ここ$S$パスに沿ったすべてのバッテリーの合計、または最大値です。$w_i$、二分探索範囲を制限します。 

## アルゴリズムのチュートリアル

 1. 複数のテスト ケースの入力を読み取ります。 テスト ケースごとに、チェックポイントの数を解析します。$n$、通路の数$m$、バッテリーアレイ$b$、およびパッセージのリスト$(s_i, t_i, w_i)$。 
2. 考えられる最終的なバッテリー数に対する二分探索を定義します。$B$。 下限は 0 で、上限は単一のパス要件を超える大きな数値です。たとえば、$10^{15}$。 
3. 候補者の実現可能性チェックを実施する$B$。 バッテリーカウントが最大の状態でチェックポイント 1 から開始します。$B$。 トポロジ順に、またはキューを使用してグラフ内を伝播します。 各チェックポイントで、ロボットが各往路に沿って持ち運べるバッテリーの最大値を計算します。$B$通過要件を満たしながら$w_i$。 
4. チェックポイントからの通過ごとに$u$チェックポイントへ$v$要件付き$w$、ロボットが到達できるかどうかを確認します$u$少なくとも$w$電池。 「はい」の場合、次の場所で新しいバッテリー数を計算します。$v$最小限として$B$そしてバッテリーの合計は$u$および回収されたバッテリーは、$v$。 これが以前に記録されたバッテリー数よりも大きい場合は、$v$、更新して追加します$v$行列に。 
5. 伝播後、チェックポイントがチェックポイントかどうかを確認します$n$実現可能なバッテリー数が以下であること$B$。 「はい」の場合、候補者は$B$実現可能です。 そうでない場合は低すぎます。 
6. 二分探索では、実現可能性に基づいて探索範囲を調整します。 収束後、それが不可能な場合$B$存在する場合は -1 を返します。 それ以外の場合は、最小値を返します$B$見つかった。 

機能する理由: 各チェックポイントでのロボットのバッテリー状態は単調です。より多くのバッテリーを集めても最後まで到達できなくなることはなく、バッテリーの数が少ないと一部の通路がブロックされる可能性があります。 二分探索はこの単調性を利用します。 グラフは非周期的であり、各ノードで最大バッテリーを伝播するため、最適なパスを見逃すことはありません。 不変条件は、各チェックポイントの処理開始時に、現在の候補に対してロボットが保持できる最大バッテリーがわかっていることです。$B$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque, defaultdict

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        b = list(map(int, input().split()))
        edges = [[] for _ in range(n)]
        for _ in range(m):
            s, t_, w = map(int, input().split())
            edges[s-1].append((t-1, w))

        left, right = 0, 10**15
        answer = -1

        def can_reach(final_battery):
            max_batt = [-1]*n
            max_batt[0] = min(b[0], final_battery)
            queue = deque([0])
            while queue:
                u = queue.popleft()
                for v, w in edges[u]:
                    if max_batt[u] < w:
                        continue
                    new_batt = min(final_battery, max_batt[u] + b[v])
                    if new_batt > max_batt[v]:
                        max_batt[v] = new_batt
                        queue.append(v)
            return max_batt[-1] != -1

        while left <= right:
            mid = (left + right) // 2
            if can_reach(mid):
                answer = mid
                right = mid - 1
            else:
                left = mid + 1

        print(answer)

if __name__ == "__main__":
    solve()
```このソリューションは、複数のテスト ケースを読み取り、グラフを構築し、実現可能な最小最終バッテリー数に対して二分探索を実行します。 の`can_reach`関数は、キューを使用して BFS のような伝播を実行します。 の選択`max_batt`不必要にチェックポイントを再訪問しないようにします。 使用する`min(final_battery, max_batt[u] + b[v])`候補者を決して超えないようにします`B`。 これにより、通過要件を尊重しながら正確性が維持されます。
