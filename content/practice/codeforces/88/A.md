 ## 解決策
 ## 問題の理解

 3 つの音符が与えられ、その音符が形成するコードをメジャー、マイナー、または「ストレンジ」のいずれかに分類するという課題があります。 音は C、C#、D、D#、E、F、F#、G、G#、A、B、H の 12 音の半音階で表され、音階は循環するため、H の後には再び C が来ます。 コードはトライアド、つまり順序​​のない 3 つの音のセットです。 最初の音程が 4 半音、2 番目の音程が 3 半音になるように音符を並べることができる場合、メジャー トライアドが発生します。 最初の間隔が 3 半音、2 番目の間隔が 4 半音の場合、マイナー トライアドが発生します。 そうでない場合、そのコードは「奇妙な」ものとみなされます。 

入力サイズは固定されており、ちょうど 3 つの音符です。 これにより、すべての順列をチェックしたり、すべての距離を計算したりするアルゴリズムが非常に高速に実行されることが保証されます。 = 6 個の順列は無視できます。 このような小さな入力に対しては、時間とメモリの制限は十分にあります。 

スケールの周期的な性質により、エッジケースが発生します。 たとえば、「B C# F」のようなコードは慎重に扱う必要があります。距離を正しく計算するには、スケールをラップする必要がある場合があります。 単純にノート インデックスを減算すると、負の値または過度に大きな値が得られる可能性があるため、モジュロ 12 演算を使用する必要があります。 もう 1 つの微妙な点は、コードに順序がないため、すべて 3 であることです。 分類の前に順列を考慮する必要があります。 

## アプローチ

 最も簡単な方法はブルートフォースです。 各音符を半音階内の位置を表す整数インデックスに変換します。 3 つの音符のすべての順列について、連続する音符間の距離を 12 を法にして計算します。 距離が一致する場合 (4, 3)、メジャーとして分類されます。 それらが (3、4) に一致する場合、マイナーとして分類されます。 すべての順列をチェックした後、一致するものがない場合は、奇妙なものとして分類されます。 

この総当たり攻撃が機能するのは、入力サイズが 3! と小さいためです。 各順列には数回の算術演算のみが必要です。 この問題の制約により、パフォーマンスを懸念することなくあらゆる順序を検討できるようになります。 ここでは、より高速な漸近アプローチは必要ありませんが、すべてのメジャー トライアドとマイナー トライアドを事前に計算して、セット内のメンバーシップをチェックすることもできます。 実際にはこの方法の方が若干速くなりますが、3 つの音符の場合、その差は無視できます。

 | ブルート フォース (すべての順列をチェック) | O(3!) = O(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各音符をその半音階インデックスにマッピングする辞書を作成します。 たとえば、C=0、C#=1、D=2、...、H=11 となります。 これにより、音名から整数への素早い変換が可能になります。 
2. 3 つの入力ノートを読み取り、辞書を使用して対応するインデックスに変換します。 
3. 3 つのインデックスの 6 つの順列すべてを生成します。 それぞれの順列は、コードの可能な順序を表します。 
4. 各順列について、モジュロ 12 算術を使用して、最初と 2 番目の音符の間、および 2 番目と 3 番目の音符の間の距離を計算します。`(second - first) % 12`そして`(third - second) % 12`。 これは、スケールの周期的な性質を説明します。 
5. 距離が正確に (4, 3) である場合、コードをメジャーとして分類して終了します。 
6. 距離が正確に (3, 4) である場合、コードはマイナーとして分類され、終了します。 
7. いずれのパターンにも一致する順列がない場合、そのコードは奇妙なコードとして分類されます。 

この方法が正しいかどうかは、すべての順序をチェックするかどうかにかかっています。 コードには順序がなく、ノートが 3 つしかないため、徹底的な検索では、コードがメジャーかマイナーの場合、少なくとも 1 つの順列で検出されることが保証されます。 

## Python ソリューション```python
import sys
import itertools
input = sys.stdin.readline

note_to_index = {
    "C": 0, "C#": 1, "D": 2, "D#": 3, "E": 4, "F": 5, "F#": 6,
    "G": 7, "G#": 8, "A": 9, "B": 10, "H": 11
}

notes = input().strip().split()
indices = [note_to_index[n] for n in notes]

for perm in itertools.permutations(indices):
    d1 = (perm[1] - perm[0]) % 12
    d2 = (perm[2] - perm[1]) % 12
    if d1 == 4 and d2 == 3:
        print("major")
        break
    if d1 == 3 and d2 == 4:
        print("minor")
        break
else:
    print("strange")
```コードはまず音名を数値インデックスに変換し、次にすべての順列をチェックしてモジュラー距離を計算します。 の使用`% 12`H から C までのような回り込み距離を処理する場合に重要です。`else`で`for`ループにより、ブレークが発生しない場合、そのコードは奇妙であると分類されます。 

## 実用的な例

 **サンプル 1:「C E G」**

 | ステップ | 順列 | d1 | d2 | 分類 |
 | --- | --- | --- | --- | --- |
 | 1 | C E G (0, 4, 7) | 4 | 3 | 専攻 |
 | 2 | C G E (0, 7, 4) | 7 | 9 | - |

 最初の順列は (4,3) に一致するため、コードはメジャーです。 

**サンプル 2:「C# B F」**

 | ステップ | 順列 | d1 | d2 | 分類 |
 | --- | --- | --- | --- | --- |
 | 1 | C# B F (1, 10, 5) | 9 | 7 | - |
 | 2 | B C# F (10, 1, 5) | 3 | 4 | マイナー |

 2 番目の順列は (3,4) に一致するため、コードはマイナーです。 これは、循環距離の処理を示しています。

## テストケース```python
import sys, io
import itertools

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    note_to_index = {
        "C": 0, "C#": 1, "D": 2, "D#": 3, "E": 4, "F": 5, "F#": 6,
        "G": 7, "G#": 8, "A": 9, "B": 10, "H": 11
    }
    notes = input().strip().split()
    indices = [note_to_index[n] for n in notes]
    for perm in itertools.permutations(indices):
        d1 = (perm[1] - perm[0]) % 12
        d2 = (perm[2] - perm[1]) % 12
        if d1 == 4 and d2 == 3:
            return "major"
        if d1 == 3 and d2 == 4:
            return "minor"
    return "strange"

# provided sample
assert run("C E G\n") == "major", "sample 1"
# custom cases
assert run("C# B F\n") == "minor", "wrap around minor"
assert run("F# A C#\n") == "major", "another major triad"
assert run("D F A\n") == "minor", "classic minor triad"
assert run("C D E\n") == "strange", "no valid triad"
assert run("H C D\n") == "strange", "wrap around strange"

 | C#BF | マイナー | ラップアラウンドマイナートライアド検出 |
 | F# と C# | 専攻 | 標準メジャートライアド |
 | DFA | マイナー | クラシックマイナートライアド |
 | CDE | 奇妙な | 非トライアドコード |
 | ＨＣＤ | 奇妙な | 奇妙なコードによるラップアラウンド検出 |

 ## 特殊なケース

 入力「B C# F」の場合、単純なアプローチでは次のように計算できます。`C# - B = -9`そして`F - C# = 4`、負の距離を与えます。 モジュロ 12 を使用すると、次のようになります。`(1 - 10) % 12 = 3`そして`(5 - 1) % 12 = 4`、コードをマイナーとして正しく識別します。 同様に、「H C D」のようなラップアラウンドが必要なコードは、どの順列も必要な (4,3) または (3,4) の半音パターンを生成しないため、正しく奇妙として分類されます。
