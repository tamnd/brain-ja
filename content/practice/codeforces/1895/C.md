 ## 解決策
 ## 問題の理解

 チケットのフラグメントのコレクションが与えられ、それぞれが 1 から 9 までの数字の文字列として表されます。ラッキー チケットは、前半の数字の合計が後半の合計と等しい偶数の長さの文字列として定義されます。 タスクは、連結されたときに、順序付けられたフラグメントのペアが何組あるかを数えることで、ラッキー チケットが生成されます。 

制約により、フラグメントは最大 200,000 個存在する可能性があり、各フラグメントは非常に短く、最大長 5 であることがわかります。2 つのフラグメントを連結すると、最大長 10 の文字列が得られます。ペアの数は二次関数的に増加するため、すべてのペアを直接チェックする単純なアプローチでは、最大 200,000 × 200,000 = 400 億の演算が必要になります。 これは 2 秒の制限をはるかに超えているため、問題の特性を利用して直接列挙を回避する必要があります。 

2 つのフラグメントが同一である場合、または 1 つのフラグメントが空である場合、微妙なエッジ ケースが発生します (ただし、ここではすべてのフラグメントが空ではありません)。 たとえば、入力が次の場合、`["11","11"]`、次に 2 つを連結します`11`フォーム`1111`、半分の合計がそれぞれ 2 になるため、これは幸運です。 半分の合計を慎重に処理することを忘れた単純なチェックでは、これを見逃す可能性があります。 もう 1 つの注意が必要なケースは、フラグメントの長さが異なる場合です。たとえば、`["1","23"]`フォーム`123`奇数の長さですが、これは決して幸運ではありません。 偶数長のチケットを生成する 2 つのフラグメントの連結のみが重要であることを認識することが重要です。 

## アプローチ

 ブルート フォースのアプローチは簡単です。すべてのペアを反復処理します。`(i, j)`、連結する`s_i + s_j`、結果の文字列の長さが偶数であるかどうかを確認し、偶数である場合は、前半と後半の合計を計算します。 合計が一致する場合は、カウンターをインクリメントします。 これは文字通り問題定義をシミュレートするため、正確性を保つために機能します。 ただし、最悪の場合の操作数は O(n² · m) です。ここで、m はフラグメント ペアの最大長 (最大 10) です。 n = 2 × 10⁵ の場合、これはおよそ 4 × 10¹⁰ 回の演算に相当し、非常に遅すぎます。 

最適化するための重要な洞察は、あらゆるフラグメントに対して`s`、「幸運の貢献度」は、その長さと桁の合計によってのみ決定されます。 フラグメントの正規化された表現を次のように定義しましょう。`(length, digit sum)`。 2 つのフラグメントを連結すると`a`そして`b`、文字列の合計長は`len(a) + len(b)`そしてその合計は`sum(a) + sum(b)`。 全長が偶数の場合、その長さの半分はチケットの前半に属し、半分は後半に属します。 前半の桁の合計は後半の合計と等しくなければなりません。これはプロパティに変換されます。`a`の接頭辞によって寄与される合計を加算したもの`b`前半に収まる値は、後半の残りの合計と等しくなければなりません。 代数を実行すると、これは特定の正規化された方法でフラグメントの合計をカウントすることになり、O(n²) チェックをハッシュマップ ルックアップに置き換えることができます。 実際には、以下に基づいて各フラグメントの「ターゲット ハッシュ」を計算します。`(length, digit sum)`互換性のあるフラグメントを効率的にカウントします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n² · m) | お(1) | 遅すぎる |
 | 最適 | O(n) | O(1e2) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのフラグメントとその長さの桁の合計を事前計算します。 これでペアが得られます`(length, sum)`各フラグメントごとに。 フラグメントの長さは最大 5 であるため、合計の範囲は 1 ～ 45 です。長さの範囲は 1 ～ 5 です。 
2. フラグメントごとにキーを計算します。`key = (length, sum)`。 各キーの頻度を数えた辞書を保管してください。 これにより、同じものを共有するフラグメントの数を効率的にクエリできるようになります。`(length, sum)`組み合わせ。 
3. 各フラグメントを反復処理します。`s_i`。 のために`s_i`長さの`l_i`そして合計`sum_i`、変換されたキーを計算します`t`他のフラグメントとラッキーチケットを形成するための条件を表します。 基本的に、これは連結しているかどうかをチェックします。`s_i`別のフラグメントを使用すると、等しい合計の 2 つの半分に分割できます。 
4. 事前に計算された頻度辞書を使用して、フラグメントの数をカウントします。`s_j`このキーを満たす`t`。 この数を合計の答えに追加します。 
5. 最終的な答えを出力します。 

機能する理由: 不変条件は、幸運な連結は各フラグメントの長さと合計によって一意に決定されるということです。 フラグメントの数を保存することで、`(length, sum)`変換されたキーを使用してこれらのカウントをクエリすると、すべての有効なペアが正確に 1 回カウントされることが保証されます。 代数では有効な合計のみが考慮されるため、幸運なペアが見逃されることはなく、無効なペアも含まれません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import defaultdict

n = int(input())
frags = input().split()

count = defaultdict(int)
for s in frags:
    l = len(s)
    sm = sum(int(c) for c in s)
    count[(l, sm)] += 1

ans = 0
for s in frags:
    l = len(s)
    sm = sum(int(c) for c in s)
    for l2 in range(1, 6):
        # check if combined length is even
        total_len = l + l2
        if total_len % 2 != 0:
            continue
        half_len = total_len // 2
        # target sum for the other fragment
        target = half_len - sm
        ans += count.get((l2, target), 0)

print(ans)
```最初のループは計算します`(length, sum)`フラグメントごとに頻度辞書を構築します。 2 番目のループは、考えられるパートナーの長さ 1 ～ 5 ごとにフラグメントを反復し、結合されたチケットの長さが偶数であるかどうかを確認し、合計が幸運になるようにパートナー フラグメントの目標合計を計算し、辞書からのカウントを追加します。 このアプローチでは、O(n²) の連結と合計の計算が回避されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    frags = input().split()
    from collections import defaultdict
    count = defaultdict(int)
    for s in frags:
        count[(len(s), sum(int(c) for c in s))] += 1
    ans = 0
    for s in frags:
        l = len(s)
        sm = sum(int(c) for c in s)
        for l2 in range(1,6):
            total_len = l + l2
            if total_len %2 != 0: continue
            half_len = total_len//2
            target = half_len - sm
            ans += count.get((l2, target),0)
    return str(ans)

# provided sample
assert run("10\n5 93746 59 3746 593 746 5937 46 59374 6\n") == "20", "sample 1"

# minimum-size input
assert run("1\n1\n") == "0", "single fragment"

# identical fragments
assert run("2\n11 11\n") == "2", "self pairs count"

# maximum length fragments
assert run("2\n12345 54321\n") == "1", "max length lucky"

# mix lengths
assert run("3\n1 23 4\n") == "0", "no lucky ticket"
