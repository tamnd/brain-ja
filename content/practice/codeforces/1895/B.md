 ## 解決策
 ## 問題の理解

 以下のマルチセットから始めます$2n$整数。 タスクは、すべての数字を 1 回だけ使用し、それらをペアにして形成することです。$n$注文したペア。 各ペアは平面内の点となり、2 つの値がそのペアとして解釈されます。$x$そして$y$コーディネート。 

ポイントが固定されたら、それらをパス上に配置することができます。 パスはすべてのポイントを少なくとも 1 回訪れる必要があり、連続するポイント間のマンハッタン距離を使用してその長さを測定します。 選択したポイントのどこからでも開始および終了できます。 

つまり、本当の自由は 2 つの決断にあります。 まず、数値をペアに分割する方法です。 2 番目に、結果として得られるポイントをパス内で順序付ける方法です。 目標は、マンハッタンの総移動距離を最小限に抑えることです。 

制約は小さいです。$n \le 100$したがって、テストあたり最大 200 個の数値になります。 これは、指数関数的なペアリング戦略やサブセットに対する動的プログラミングなどを除外するため、重要です。 ただし、ペアリングに対するブルートフォースは理論的には可能ですが、小規模なペアでは$n$、完全一致の数が増加するため、非常に速く増加します。$2n$要素は$(2n)! / (2^n n!)$、中程度でも手に負えなくなる$n$。 

多くの値が同一である場合、微妙なエッジケースが発生します。 すべての数字が同じ場合、どの組み合わせでも同じ点が生成され、答えはゼロになります。 もう 1 つの特殊なケースは、値が極端に分割される場合です。これは、最適なソリューションは、隣接する要素を任意にペアにするのではなく、座標全体で大きい値と小さい値のバランスをとることに大きく依存するためです。 

## アプローチ

 ブルートフォースアプローチでは、考えられるすべての組み合わせを列挙します。$2n$数字を入力する$n$次に、ペアごとに、結果として得られる点のすべての順列を計算して、可能なパスをシミュレートします。 順列を無視し、後で点を最適に順序付けると仮定した場合でも、単純にペアを列挙するだけですでに複雑さが支配的になります。 各ペアリングによって点のセットが決定され、各セットに対して最適なパスを計算する必要がありますが、これ自体がマンハッタン距離での巡回セールスマンの問題です。 これはすぐに実行不可能になります。 

重要な構造的観察は、パスの構造は点の形成方法と比較すると無関係であるということです。 任意の固定点セットの場合、最小限のマンハッタン移動ですべての点を訪れる最適なパスは、単調な順序で点を接続するものとして理解でき、コストは基本的に座標の広がり具合によって決まります。 これにより、問題は「経路の検索」から「座標の不均衡を最小限に抑える点の構築」に変わります。 

現在の中心的なアイデアは、並べ替えを活用することです。 私たちは数値をペアにしており、各数値は次のいずれかとして独立して寄与します。$x$または$y$、最良の戦略は、極端な動作を制御することです。つまり、制御された対称的な方法で小さいものと大きいものを組み合わせることで、合計の広がりを最小限に抑えたいと考えています。 具体的には、配列をソートすると、最小値と最大値を一致させることができるため、座標のバランスが取れ、両方の座標が大きい、または両方が小さい点の作成が回避されます。 

並べ替えたら、最初のものを割り当てます$n$1 つの座標グループと最後の値の最小値$n$他の座標グループの最大値。 これらを順番にペアにすると、座標が「均等に広がる」点が生成され、ソートされた順序で走査したときにマンハッタンの距離が最小になります。 

この構造は、マンハッタンの距離が座標において加算的であるため機能し、総パス コストは、経路に沿った独立した寄与の合計として解釈できます。$x$そして$y$。 各座標次元の不均衡を最小限に抑えることで、総走査コストを最小限に抑えます。

 ## アルゴリズムのチュートリアル

 ソートを通じて座標の割り当てを制御することにより、解を構築します。 

1. 配列をソートする$a$。 これにより、小さい値と大きい値が明確に分離され、座標の広がりのバランスをとるために不可欠です。 
2. ソートされた配列を 2 つの半分に分割します。 前半には最小のものが含まれます$n$値が含まれており、後半には最大の値が含まれます。$n$価値観。 
3. 要素を対称的にペアにします。$i$前半の - 番目の要素とペアにします。$i$後半の - 番目の要素。 各ペア1点となります$(x_i, y_i)$。 

このペアリングにより、各ポイントが 1 つの小さい値と 1 つの大きい値を組み合わせて、極端な座標のクラスタリングが防止されます。 
4. 構築された順序でポイントを出力します。 コストを増加させることなく最適なパスが常にこの単調な構造に従うことができるため、一貫した順序が機能します。 

機能する理由: マンハッタンの距離目標は、事実上、座標が点のセット全体にどれだけ離れているかによって決まります。 小-小、または大-大を組み合わせた場合、平面の領域に集中したポイントが作成されるため、クラスター間で必要な移動距離が増加します。 最小値と最大値を組み合わせると、各点がバランスのとれた位置に配置され、座標の差異が最小限に抑えられます。 両方の座標は同じソートされた構造から派生するため、結果として得られる構成により、あらゆる方向への不必要な拡散が回避されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        a.sort()

        # split into two halves
        left = a[:n]
        right = a[n:]

        points = []
        for i in range(n):
            points.append((left[i], right[i]))

        # output
        for x, y in points:
            print(x, y)

if __name__ == "__main__":
    solve()
```この実装は、ソートとそれに続く直接ペアリングに完全に依存しています。 ソートされた配列はきれいに分割され、各インデックスが 1 つのポイントを生成します。 ここでよくある間違いは、半分の間でインデックスを間違って混合したり、値をインターリーブしようとしたりすることです。 どちらも意図したバランスを崩し、スプレッドが最適化されていません。 

もう 1 つの微妙な点は、パスを明示的に構築または最適化する必要がないことです。 この問題により、ポイントが固定されればいつでもパスを選択できることが保証され、この構造により、合理的な走査順序によって最小限のコストが得られることが保証されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    def solve():
        t = int(input())
        out = []
        for _ in range(t):
            n = int(input())
            a = list(map(int, input().split()))
            a.sort()
            left = a[:n]
            right = a[n:]
            for i in range(n):
                out.append(f"{left[i]} {right[i]}")
        return "\n".join(out)

    return solve()

 ## 特殊なケース

 すべての値が同一の場合、並べ替えにより 2 つの同一の半分が生成されます。 それらをペアにすると同一の点が得られ、すべてのマンハッタン距離がゼロになります。 各座標の割り当てでは同等性が維持されるため、アルゴリズムはこれを自然に処理します。 

値が厳密に減少している場合、並べ替えによって値が昇順に反転されますが、ペアリングによってバランスのとれた極端な結果が得られます。 例えば、$[6,5,4,3,2,1]$左になる$[1,2,3]$そして正しい$[4,5,6]$, 特別な筐体を使わなくてもペアリングはスムーズに進みます。 

重複が存在する場合は、並べ替え後に半分に均等に分散されます。 これにより、座標が過度に集中することがなくなり、繰り返しパターンに関係なくペアリングが安定したままになります。
