 ## 解決策
 ## 問題の理解

 数直線には 3 つの重要な位置が含まれています。 Monocarp は位置から開始します`0`、胸の位置は`x`、キーは の位置にあります`y`。 

宝箱を開けるには、Monocarp は最終的に鍵を持った状態で宝箱と同じ位置に立たなければなりません。 歩行には単位距離あたり 1 秒のコストがかかります。 チェストと鍵を持ち上げたり置いたりするのには費用はかかりません。 

問題は、チェストを持ち運べるのはせいぜい`k`合計で秒。 鍵がまだチェストに到達していない場合、Monocarp はチェストを鍵に近づける必要があるかもしれませんが、運ぶ距離はこれを超えることはできません`k`。 

入力には最大 100 個のテスト ケースが含まれ、すべての座標は最大 100 です。制約は小さいですが、本当の目標は、答えを即座に与える数学的観察を見つけることです。 

よくある間違いは、Monocarp は胸に触れる前に必ずキーに到達しなければならないと考えることです。 彼はチェストを運ぶことが許されているので、それは真実ではありません。 

考慮する：```
x = 5, y = 7, k = 2
```彼は位置 5 のチェストに到達し、それを 2 ユニット分移動して位置 7 まで運び、鍵を拾ってチェストを開けます。 答えは12ではなく7です。 

もう 1 つの簡単な間違いは、常に答えてしまうということです`max(x, y)`鍵が胸の向こう側にあるとき。 

考慮する：```
x = 5, y = 8, k = 2
```鍵となるのはチェストの先の3ユニットですが、モノカープはチェストを2ユニット分しか運ぶことができません。 彼はそれを 7 の位置まで運び、キーを求めて 8 まで歩いてから、7 に戻ります。答えは 8 ではなく 9 です。 

3 番目のエッジ ケースは、キーがチェストの前にある場合に表示されます。```
x = 10, y = 5, k = 0
```モノカープは宝箱に向かう途中で鍵を拾うだけです。 答えは 10 です。ここでチェストを運ぶロジックは不要です。 

## アプローチ

 強引な見方では、Monocarp が鍵を持っているかどうか、胸が現在どこにあるか、そして携行スタミナがどのくらい残っているかなど、Monocarp のあらゆる可能な位置をモデル化します。 次に、結果の状態空間に対して最短パス検索を実行できます。 

これが機能するのは、すべてのアクションのコストが負ではなく、状態空間が有限であるためです。 座標を 100 で区切れば、そのような解決策も実装できます。 問題は、数直線の構造とそれに含まれる非常に単純な幾何学を完全に無視していることです。 

重要な観察は、2 つの相対的な順序のみが重要であるということです。 

キーが胸またはその前にある場合 (`y < x`)、Monocarp は胸に向かって歩きながらキーに到達します。 彼はそれを無料で受け取り、続けます`x`。 胸を動かす必要はありません。 答えは単純です`x`。 

興味深いケースは、鍵が胸の向こう側にある場合です (`y > x`）。 

Monocarp はまずチェストに到達し、消費する必要があります。`x`秒。 

チェストとキーの間に残っている隙間は次のとおりです。```
d = y - x
```もし`d <= k`、彼は胸を鍵まで運ぶことができます。 合計時間は`x + d = y`。 

もし`d > k`、彼は胸をできるだけ遠くまで運びます、正確に`k`単位。 胸がその位置で止まる`x + k`。 

まだ残り距離があります:```
r = d - k
```単鯉の散歩`r`ユニットをキーに合わせてから、`r`ユニットを胸に戻します。 それには費用がかかります`2r`余分な秒数。 

合計は次のようになります。```
x + k + 2(d - k)
= x + 2d - k
```以来`y = x + d`、これは次のように書くこともできます。```
y + (d - k)
```コンパクトな式は次のとおりです。```
x,                     if y < x
y + max(0, y - x - k), otherwise
```| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(S) | O(S) | 不要 |
 | 最適 | テスト ケースごとに O(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む`x`、`y`、 そして`k`。 
2. もし`y < x`、宝箱に到達する前に鍵に遭遇します。 途中で鍵を拾い、宝箱へ進みます。 出力`x`。 
3. それ以外の場合はギャップを計算します`d = y - x`。 
4. もし`d <= k`、チェストはキーまで運ぶことができます。 出力`y`。 
5. それ以外の場合、胸部は移動することしかできません。`k`単位。 残りの距離は`d - k`。 
6. Monocarp は残りの距離を歩いて鍵を取得し、同じ距離を歩いて胸まで戻らなければなりません。 出力`y + (d - k)`。 

### なぜ効果があるのか

 いつ`y < x`、すべての有効な解決策は最終的に位置に到達する必要があります`x`、そして鍵はそのパスにあります。 胸に届くのは、`x`すでに十分なので、`x`が最適です。 

いつ`y > x`, Monocarpは最初に費やす必要があります`x`胸に届くまでの数秒。 チェストをキーに向かって運ぶことは、キーとキーの間の将来の分離を減らすため、常に有益です。 最善の戦略は、できるだけ長い距離を運ぶことです。`k`またはチェストがキーに到達するまで。 残りの分離は 2 回通過する必要があります。1 回目は鍵を回収し、もう 1 回目は宝箱に戻ります。 上記の式はこれらの避けられない動きを正確に考慮しているため、より短いルートは存在しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())

for _ in range(t):
    x, y, k = map(int, input().split())

    if y < x:
        print(x)
    else:
        print(y + max(0, y - x - k))
```最初のブランチは、宝箱の前で鍵が見つかった場合を処理します。 背負う必要はないので、答えは単純に胸の位置です。 

2 番目の分岐では、鍵は胸の先にあります。 値`y - x - k`は、チェストを運ぶことでカバーできない胸とキーの隙間の部分を表します。 この数量が負の場合、チェストはキーに直接到達するため、追加コストはゼロになります。 それ以外の場合、その残りの距離は、その先の答えに 1 回だけ寄与します。`y`、式を生成します`y + max(0, y - x - k)`。 

すべての計算は標準の整数型内に快適に収まり、数式が自然に処理するため、難しい境界条件はありません。`k = 0`そして`d = k`。

### 例 2

 入力:```
x = 5, y = 8, k = 2
```| 変数 | 値 |
 | --- | --- |

 | y | 8 |

これらのトレースは、キーの不変条件を示しています。つまり、利用可能な移動距離をすべて使用した後、残りの胸とキーの間隔を 2 回通過する必要があります。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | テスト ケースごとに O(1) | 算術演算はわずか数個だけ |
 | スペース | お(1) | 余分なデータ構造は不要 |

 テスト ケースの数が最大であっても、プログラムはケースごとに少数の操作しか実行しません。 時間とメモリの制限内に簡単に収まります。 

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline
    t = int(input())
    ans = []

    for _ in range(t):
        x, y, k = map(int, input().split())

        if y < x:
            ans.append(str(x))
        else:
            ans.append(str(y + max(0, y - x - k)))

    return "\n".join(ans)

# provided sample
assert run(
"""3
5 7 2
10 5 0
5 8 2
"""
) == "7\n10\n9"

# key before chest
assert run(
"""1
8 3 5
"""
) == "8"

# exactly enough carrying distance
assert run(
"""1
4 9 5
"""
) == "9"

# no carrying allowed
assert run(
"""1
4 9 0
"""
) == "14"

# maximum coordinate values
assert run(
"""1
100 99 100
"""
) == "100"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`8 3 5`|`8`| 鍵は胸の前にあります | 写真
 |`4 9 5`|`9`| 飛距離はギャップに正確に一致 |
 |`4 9 0`|`14`| 持ち込み不可 |
 |`100 99 100`|`100`| 胸の前に大きなコーディネートと鍵 |

 ## 特殊なケース

 次のことを考慮してください。```
1
10 5 0
```アルゴリズムはそれを認識します`y < x`そしてすぐに戻ります`10`。 モノカープは胸に向かって歩きながら鍵を拾います。 持ち運びの必要はありません。 出力は正しいです。 

考慮する：```
1
5 7 2
```ここ`y > x`、ギャップは`2`。 以来`2 <= k`、アルゴリズムは戻ります`y = 7`。 チェストはキーに直接運ぶことができます。 余分なバックトラッキングは発生しません。 

考慮する：```
1
5 8 2
```ギャップは`3`、より大きい`k`。 覆われていない部分は、`3 - 2 = 1`。 アルゴリズムは戻ります`8 + 1 = 9`。 この追加ユニットは、再配置されたチェストからキーまで、そしてその後ろに移動することに正確に対応します。 

考慮する：```
1
4 9 0
```ギャップは`5`、持ち運びはできません。 式は次のようになります`9 + 5 = 14`。 Monocarp は 4 秒で胸部まで歩き、その後 4 から 9 に移動し、さらに 10 秒を加えて 4 に戻る必要があります。 合計は 14 で、式と正確に一致します。
