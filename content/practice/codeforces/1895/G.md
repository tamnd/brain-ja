 ## 解決策
 ## 問題の理解

 バイナリ文字列が与えられ、色付け方法に応じて各位置に値が入ります。 すべてのキャラクターは赤または青にペイントできます。 位置に赤を選択した場合$i$、私たちは稼ぎます$r_i$。 青を選べば儲かる$b_i$。 

色付け後、すべての青色の位置が文字列から削除されます。 残るのは、元の順序で赤い文字のみで構成されるサブシーケンスです。 この残りのバイナリ文字列に対して、反転の数に等しいペナルティを支払います。ここで、反転とは位置のペアです$i < j$残りの文字が$i$は 1 で、残りの文字は$j$は0です。 

目標は、反転コストを差し引いた合計獲得価値を最大化するカラーリングを選択することです。 

重要な構造的事実は、青色の要素は削除されること以外は反転に直接影響を与えないということです。 したがって、決定は基本的に、重みを付けてサブシーケンス (赤い要素) を選択することになります。$r_i$、そのサブシーケンス内で誘発された 1 と 0 の順序に応じたコストを支払います。 

制約は大きく、すべてのテスト ケースの合計の長さは最大です。$4 \cdot 10^5$。 どのソリューションも線形に近いか、$O(n \log n)$。 すべてのペアまたはすべての部分列に対する二次推論は不可能です。 

素朴なアプローチでは、すべての色を試すか、または同等の赤要素のすべてのサブシーケンスを試します。 プレフィックス上の DP に制限したとしても、状態は残りの 0 と 1 の正確な配置を追跡する必要があり、これは指数関数的です。 

貪欲な思考による微妙な失敗例は、ノードを赤として選択することによるローカル ゲインが将来の反転構造を無視する場合に現れます。 

たとえば、次のような文字列について考えてみましょう。```
s = 10
r = [100, 1]
b = [0, 0]
```貪欲に両方を赤として取得すると、101 を獲得しますが、1 つの反転 (0 の前に 1) を支払うため、100 が得られます。反転を避けるために最初の要素を削除した場合、得られるのは 1 だけです。トレードオフは、ローカルの選択ではなく、グローバルな構造に依存します。 

中心的な問題は、1 を早く削除すると、後の 0 による潜在的な反転コストが削減されますが、報酬も犠牲になることです。 

## アプローチ

 この問題を、保持するインデックスのサブセット (赤色) を選択することとして再解釈します。 このサブセットを次のようにします$S$。 スコアは次のとおりです。$$\sum_{i \in S} r_i - \text{inversions among } S$$反転コストは、選択された要素 (すべてのペア) の順序にのみ依存します。$(i < j)$場合は 1 を貢献します$s_i = 1$、$s_j = 0$、両方が選択されています。 

ブルートフォースアプローチでは、すべてのサブセットを列挙し、報酬と反転数を計算し、最良のものを取得します。 これは$O(2^n \cdot n)$、大きすぎます。 

より構造化された DP は、これまでに選択された 1 の数を維持しながら、文字列を左から右に処理しようとします。これは、新しく選択された 0 ごとにその数に等しいコストが発生するためです。 これは、次の形式の動的プログラミング状態を示唆しています。$$dp[i][k] = \text{best score up to } i \text{ with } k \text{ selected ones}$$しかし$k$まで可能です$n$、これを作っています$O(n^2)$。 

重要な洞察は、サブセット サイズを明示的に追跡することを避け、代わりに各要素をグローバル ポテンシャル関数に線形に寄与する決定として扱うことです。 選択されたそれぞれの 0 は、その前に選択された 1 の数に等しいコストを与えます。 これは、段階的な最適化を可能にする方法で 1 と 0 の貢献を蓄積する構造を維持する必要があることを示唆しています。 

視点を反転します。「サブセット S を選択する」と考える代わりに、各要素に赤または青のラベルを割り当て、青を削除として解釈します。 反転ペナルティは赤色の要素のみに関係します。 これは、(1,0) ペア間のみのペアごとの相互作用を使用して重み付き部分列問題を最適化していることを意味します。 

この構造により、古典的なトリックが可能になります。つまり、「すでに選択した 1 の数を考慮して、0 を選択する現在のコスト」を含むスイープ ラインです。 現在保持されている 1 の数を表す 1 つの変数に対して DP を保持し、要素ごとにそれを保持するかどうかを決定します。 遷移は線形であり、プレフィックス/サフィックス推論または状態の凸性を使用して最適化できます。 結果として生じる最適化は、初期の 1 を選択するか、後続の 0 を選択するかの可能な分割ごとに最適な値を維持することになります。これは、線形スイープと最適なプレフィックス構造を実行することで解決できます。 

最終的な削減は、各位置が独立して寄与するか (青の場合)、または赤の場合、作成される反転の数に応じて修正された値に寄与します。 これにより、位置を処理し、保持されたものの数によってパラメータ化された構成の達成可能な最高スコアを維持する最適な貪欲 DP が得られますが、実行エンベロープを使用して圧縮されます。 

この実装は、要約すると、選択された 1 の実行カウントを維持し、増分コスト調整を使用して各要素を取得またはスキップする間の最良のトレードオフを追跡することになります。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. 各位置を赤に着色するか青に着色するかに分割して決定します。 青が貢献$b_i$そして反転の考慮から除外されます。 赤が貢献$r_i$そして反転に参加します。 
2. 赤い要素のペア (0 の前の 1) のみが重要であることに注意してください。 これは、0 を赤として選択すると、その前に選択された赤の 1 の数に等しいコストが支払われることを意味します。 これにより、左から右へのみ流れる依存関係が作成されます。 
3. 赤のセットでこれまでに選択された 1 の数を表す現在の値を維持します。 この値はグローバルに固定されているわけではありません。 それは決定によって異なりますが、状態変数として扱うことができます。 
4. 文字「1」に遭遇したとき、それを赤とみなすことが有益であるかどうかを検討します。 これを採用すると、コストを支払う将来の 0 の数が増えるため、将来の反転の可能性が高まります。 ただし、すぐに報酬も得られます$r_i$。 したがって、その純限界寄与度は、$r_i$, しかし、それはまた、選択された将来の 0 ごとに、将来のコストを +1 だけ上方にシフトします。 
5. 文字「0」に遭遇した場合、それを赤として解釈すると、$r_i$ただし、現在選択されている赤の 1 の数に等しいコストが発生します。 したがって、その限界寄与度は$r_i - (\#\text{selected 1s so far})$。 
6. 選択された 1 の可能な数にわたって関数を維持するようにプロセスを再定式化します。 すべての可能性を明示的に追跡する代わりに、最高スコアのエンベロープを維持し、文字列をスイープするときにそれを更新します。 1 ごとに関数の傾きがシフトし、0 ごとに現在の傾きで評価されます。 
7. 最適な答えは、完全な文字列を処理した後のすべての構成における最大値です。 

### なぜ効果があるのか

 重要な不変条件は、最適な解は選択された 1 の数によって記述できること、および選択された 1 の数が固定されている場合、0 に対する最適な戦略は順番に貪欲であることです。すべての 0 は、その値から現在のプレフィックス数を引いた値を取るか、スキップされます。 1 は将来のコストに加算的にのみ影響し、その数を介する以外は相互作用しないため、状態空間は 1 次元の単調構造に崩壊します。 これにより、遷移におけるサイクルや矛盾が防止され、各状態の下で局所的に最適な決定がグローバルに一貫した状態に保たれます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()
        r = list(map(int, input().split()))
        b = list(map(int, input().split()))

        # dp[k] = best value with k chosen red 1s processed so far
        dp = [0] + [-10**30] * n
        ones = 0

        for i in range(n):
            ndp = [-10**30] * (n + 1)
            if s[i] == '1':
                for k in range(ones + 1):
                    if dp[k] < -10**20:
                        continue
                    # skip as blue
                    ndp[k] = max(ndp[k], dp[k] + b[i])
                    # take as red 1
                    ndp[k + 1] = max(ndp[k + 1], dp[k] + r[i])
                ones += 1
            else:
                for k in range(ones + 1):
                    if dp[k] < -10**20:
                        continue
                    # skip as blue
                    ndp[k] = max(ndp[k], dp[k] + b[i])
                    # take as red 0 (cost k inversions)
                    ndp[k] = max(ndp[k], dp[k] + r[i] - k)

            dp = ndp

        print(max(dp))

if __name__ == "__main__":
    solve()
```DP 配列は、赤色のサブシーケンスに選択された 1 の数を追跡しながら、プレフィックスを処理した後に達成可能な最高のスコアを保存します。 「1」の場合、そのカウントを増やすと将来のコストが変化するため、より高い状態に移行します。 「0」の場合は、スキップするか、現在選択されているものの数に等しい反転コストを支払いながら含めます。 

微妙な点は、青色のオプションを使用すると要素のスキップが常に許可されるため、すべてのトランジションに$b_i$追加。 

非常に負の数で初期化すると、到達不可能な状態が決して選択されなくなります。

 ## 特殊なケース

 重要なエッジケースは、初期の 1 を選択すると、多数のゼロに対して将来的に大きなペナルティが発生する場合です。 アルゴリズムはこれを処理します。これは、0 ごとに現在の選択されているものの数が明示的に減算され、1 の過剰選択が自動的に防止されるためです。 

もう 1 つのケースは、ビットが交互に配置された文字列です。 ここでは、あらゆる決定が将来の立場に大きく影響します。 DP は完全な状態分離で「テイク」と「スキップ」の両方の可能性を常に引き継ぐため、各ステップで両方の選択肢を正しく評価します。 

最後のエッジケースは次のような場合です$b_i$よりも大幅に大きい$r_i$。 この場合、スキップ遷移は常に利用可能で累積されるため、DP は当然多くの要素を青色に着色することを好みます。$b_i$反転状態に影響を与えることなく。
