 **評価:** 2600

 **確認済み:** いいえ

 ## 解決策
 ## 問題の理解

 各モンスター タイプには 1 つ以上の分割ルールがあります。 ルールを適用すると、そのタイプのモンスター 1 匹が消費され、次の 2 つのものが生成されます。 

まず、いくつかのダイヤモンド。 

2 つ目は、新しいモンスターのマルチセットです。 

1匹のモンスターから始めて、出現するモンスターごとにルールを選択し、最終的にモンスターがなくなるまで繰り返します。 収集されたダイヤモンドの総数は、すべてのルール適用によって生成されたダイヤモンドの合計です。 

モンスターのタイプごとに 2 つの値を計算する必要があります。 

すべての終了戦略の中で取得できるダイヤモンドの最小数。 

すべての終了戦略の中で取得できるダイヤモンドの最大数。 

終了が不可能な場合、両方の答えが次のようになります。`-1`。 

最終的に終了する前に任意の数のダイヤモンドを生成できる場合、最大の答えは次のようになります。`-2`。 

入力は自然に有向ハイパーグラフを形成します。 ルール```
A -> diamonds + {B, C, D}
```モンスターの価値を意味します`A`すべてに依存します`B`、`C`、 そして`D`。 

制約は重要な観察事項です。 まであります`10^5`モンスターの種類と`10^5`ルール要素の合計。 すべてのモンスターからグラフ全体を繰り返し探索するアルゴリズムは不可能です。 合計入力サイズにおいて線形時間に近い値が必要です。 

危険なケースは周期的なケースです。 

考慮する：```
1 -> 1 + monster 1
1 -> 1
```モンスター`1`2 番目のルールにより、終了することができます。 また、最終的に 2 番目のルールを選択する前に、最初のルールを何度でもループすることもできます。 最低限の答えは、`1`、最大の答えは無限です。 

別の微妙なケースは次のとおりです。```
1 -> monster 2 + 1
2 -> monster 1 + 1
```どちらのモンスターにも終了ルールはありません。 どちらの答えも`-1`両方のタイプの場合。 サイクルだけを探す単純な DFS は、最大値が無限であると誤って結論付けますが、終了が不可能な場合は無限のダイヤモンドは無関係です。 

3 番目の落とし穴は、あるモンスターから到達可能だが、そのモンスター自体の一部ではないサイクルです。```
1 -> monster 2 + 1
2 -> monster 3 + 1
3 -> monster 2 + 1
2 -> 1
3 -> 1
```モンスター`1`サイクルに参加し、任意の期間そこに留まり、終了ルールに従って終了することができます。 その最大の答えも無限です。 

## アプローチ

 ブルート フォース ソリューションでは、考えられるすべてのルール選択シーケンスを試し、結果として得られるモンスターを再帰的に評価します。 すべての終端導出は有限展開ツリーに対応するため、これは概念的には正しいです。 

問題は、可能な導出の数が指数関数的に増加することです。 たとえ小さなサイクルであっても、無限に多くの異なる戦略が可能になります。 と`10^5`モンスターの種類が多いため、明示的な探索は絶望的です。 

ルールの構造により、より良い観点が得られます。 

させて`min[i]`モンスターから入手できる最小のダイヤモンドであること`i`。 

ルールとしては```
i -> d diamonds + children
```ルールが貢献する```
d + sum(min[child])
```なぜなら、生み出されたすべてのモンスターは最終的には解決されなければならないからです。 

同じ考え方が最大値にも当てはまります。 

これにより、問題は有向ハイパーグラフ上の方程式の評価に変わります。 ルールは、そのすべての子が終了可能であることがすでにわかっている場合にのみ使用可能になります。 

最初のタスクは、どのモンスターが終了できるかを判断することです。 これは AND-OR 到達可能性の問題です。 

少なくとも 1 つのルールのすべての子が終了可能である場合、モンスターは終了可能です。 

終端可能セットがわかったら、最小値は最短ハイパーパスの問題になります。 最大値は、正のゲインを持つサイクルが無限の答えに対応することを除いて、最長ハイパーパス問題になります。 

重要な観察は、すべてのルールが少なくとも 1 つのダイヤモンドを生成するということです。 通過して後で終了できるサイクルは任意に何度でも繰り返すことができ、無制限のダイヤモンドを生成できます。 したがって、無限状態はまさに、使用可能なルールのグラフ内で有向サイクルに到達できる終了可能なモンスターです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | 指数 | 遅すぎる |
 | 最適 | O(n + ルールの合計サイズ) | O(n + ルールの合計サイズ) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### 1. ルールハイパーグラフを構築する

 すべてのルール ストアについて:

 オーナーモンスター。 

ルールによって生成されるダイヤモンドの数。 

子モンスターの一覧です。 

また、すべての子から、それを含むルールへの逆参照も構築します。 

### 2. 終了可能なモンスターを計算する

 ルールは、そのすべての子モンスターが終了可能であることがすでにわかっている場合に満たされます。 

すべてのルールについて、終了可能であることがまだ確認されていない子モンスターの数に等しいカウンターを維持します。 

子がゼロのルールはすぐに満たされます。 

モンスターが終了可能になるたびに、それに依存するすべてのルールを参照し、カウンターを減らします。 

ルールカウンターがゼロになると、そのオーナーモンスターは終了可能になります。 

これは、AND-OR グラフの標準的な伝播です。 

### 3. 最小ダイヤモンドを計算する

 子がすべて終了可能であるルールのみが貢献できます。 

各ルールに必要なのは```
diamonds(rule) + sum(min[child])
```方程式は単調であり、すべてのコストは正です。 

ダイクストラのようなハイパーグラフ緩和でそれらを処理します。 すべての子の値がわかっている場合、ルールは評価可能になります。 その時点で、その所有者の候補値が生成されます。 

使用可能なすべてのルールの中で最小の候補が答えになります。 

### 4. 使用可能な依存関係のグラフを作成する

 使用可能なルールごとに```
u -> children
```通常の有向エッジを追加する```
u -> child
```すべての子供たちのために。 

このグラフは、どのモンスターの値が他のどの値に依存するかを示しています。 

### 5. 無限状態を見つける

 使用可能な依存関係グラフに対して SCC 分解を実行します。 

複数の頂点を持つ SCC はすべてサイクルです。 

単一の頂点 SCC も、自己ループがある場合には循環的になります。 

すべてのルールで少なくとも 1 つのダイヤモンドが生成されるため、このようなサイクルに到達すると、すべての走査でプラスのダイヤモンドを獲得できることになります。 

すべての周期的 SCC をマークします。 

次に、逆グラフ トラバーサルを実行し、これらの SCC の 1 つに到達できるすべての終了可能なモンスターをマークします。 

それらのモンスターには最大の答えがあります`-2`。 

### 6. 有限の最大ダイヤモンドを計算する

 無限モンスターをすべて取り除く。 

残りの使用可能な依存関係グラフは非循環です。 

残りのモンスター1体につき、```
max[i] =
max over usable rules (
    diamonds(rule) + sum(max[child])
)
```グラフは DAG になっているため、これらの値を逆のトポロジー順序で評価します。 

### 7. 大きな有限の答えをクランプする

 より大きい任意の有限値`314000000`として印刷されます`314000000`。 

### なぜ効果があるのか

 終了伝播は、条件の最小不動点を正確に計算します。```
monster is terminable
⇔
some rule has all children terminable
```ルールは、生成されたすべてのモンスター自体を終了できる場合にのみ、有効なダイヤモンドの数を提供します。 最小方程式と最大方程式は、まさにゲーム結果の再帰的定義です。 

各ルールが少なくとも 1 つのダイヤモンドを作成するため、使用可能なグラフ内のすべてのサイクルは厳密に正のゲインを持ちます。 そのようなサイクルに達することができる終了可能なモンスターは、何度でもそのサイクルを通過し、その後終了戦略を通じて終了し、任意に大きな有限の合計を生成することができます。 まさにそれが答えの意味です`-2`。 

無限状態を削除した後、依存関係グラフは非循環になるため、最大方程式には DAG での動的プログラミングによって取得される固有の有限解が含まれます。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

CAP = 314000000

def solve():
    m, n = map(int, input().split())

    rules = []
    owner_rules = [[] for _ in range(n)]
    rev_rules = [[] for _ in range(n)]

    for rid in range(m):
        arr = list(map(int, input().split()))
        owner = arr[0] - 1
        l = arr[1]

        diamonds = 0
        children = []

        for x in arr[2:2 + l]:
            if x == -1:
                diamonds += 1
            else:
                children.append(x - 1)

        rules.append((owner, diamonds, children))
        owner_rules[owner].append(rid)

        for v in children:
            rev_rules[v].append(rid)

    # terminable monsters
    need = [len(ch) for _, _, ch in rules]
    can = [False] * n
    q = deque()

    for rid, (owner, _, ch) in enumerate(rules):
        if not ch and not can[owner]:
            can[owner] = True
            q.append(owner)

    while q:
        u = q.popleft()

        for rid in rev_rules[u]:
            need[rid] -= 1
            if need[rid] == 0:
                owner = rules[rid][0]
                if not can[owner]:
                    can[owner] = True
                    q.append(owner)

    # usable rules
    usable = [False] * m
    for rid, (_, _, ch) in enumerate(rules):
        ok = True
        for v in ch:
            if not can[v]:
                ok = False
                break
        usable[rid] = ok

    g = [[] for _ in range(n)]
    rg = [[] for _ in range(n)]

    for rid, (u, _, ch) in enumerate(rules):
        if not usable[rid]:
            continue
        for v in ch:
            g[u].append(v)
            rg[v].append(u)

    # SCC (Kosaraju)
    used = [False] * n
    order = []

    sys.setrecursionlimit(300000)

    def dfs1(v):
        used[v] = True
        for to in g[v]:
            if not used[to]:
                dfs1(to)
        order.append(v)

    for i in range(n):
        if can[i] and not used[i]:
            dfs1(i)

    comp = [-1] * n

    def dfs2(v, c):
        comp[v] = c
        for to in rg[v]:
            if comp[to] == -1:
                dfs2(to, c)

    cid = 0
    for v in reversed(order):
        if comp[v] == -1:
            dfs2(v, cid)
            cid += 1

    sz = [0] * cid
    for i in range(n):
        if comp[i] != -1:
            sz[comp[i]] += 1

    cyc = [False] * cid

    for u in range(n):
        if comp[u] == -1:
            continue
        if sz[comp[u]] > 1:
            cyc[comp[u]] = True
        for v in g[u]:
            if u == v and comp[u] == comp[v]:
                cyc[comp[u]] = True

    inf = [False] * n
    dq = deque()

    for i in range(n):
        if can[i] and cyc[comp[i]]:
            inf[i] = True
            dq.append(i)

    while dq:
        v = dq.popleft()
        for p in rg[v]:
            if can[p] and not inf[p]:
                inf[p] = True
                dq.append(p)

    # finite max via memo DAG
    min_dp = [-1] * n
    max_dp = [-1] * n

    def get_min(v):
        if min_dp[v] != -1:
            return min_dp[v]

        best = 10**18
        for rid in owner_rules[v]:
            if not usable[rid]:
                continue

            _, d, ch = rules[rid]
            cur = d
            for x in ch:
                cur += get_min(x)

            if cur < best:
                best = cur

        min_dp[v] = min(best, CAP)
        return min_dp[v]

    def get_max(v):
        if max_dp[v] != -1:
            return max_dp[v]

        best = 0
        for rid in owner_rules[v]:
            if not usable[rid]:
                continue

            _, d, ch = rules[rid]

            bad = False
            cur = d

            for x in ch:
                if inf[x]:
                    bad = True
                    break
                cur += get_max(x)

            if not bad:
                best = max(best, cur)

        max_dp[v] = min(best, CAP)
        return max_dp[v]

    out = []

    for i in range(n):
        if not can[i]:
            out.append("-1 -1")
        else:
            mn = get_min(i)

            if inf[i]:
                out.append(f"{mn} -2")
            else:
                mx = get_max(i)
                out.append(f"{mn} {mx}")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```実装はアルゴリズムにほぼ直接に従います。 

最初の伝播では、最終的に消滅する可能性のあるモンスターのセットを計算します。 すべてのルールは、未解決の子の数を維持します。 このカウントがゼロになると、ルールが使用可能になります。 

SCC フェーズは、無限応答検出の中心です。 サイクルだけでは十分ではありません。 サイクルは終了可能なサブグラフ内に存在する必要があります。 そのため、SCC 分解は使用可能な依存関係に対してのみ実行されます。 

周期的 SCC からのリバース BFS は、そのようなサイクルに入ることができるすべてのモンスターをマークします。 すべての走査で少なくとも 1 つのダイヤモンドが得られるため、これらの状態は無制限の最大値を持ちます。 

最小値と有限の最大値は、再帰方程式の通常のメモ化された評価になります。 

上限は、必要に応じて、有限の回答にのみ適用されます。

 ## 特殊なケース

 出口のある自己ループを考えてみましょう。```
2 1
1 2 1 -1
1 1 -1
```最初のルールはダイヤモンドを 1 つ生成し、モンスターを再作成します。`1`。 2 番目のルールは、ダイヤモンド 1 つですぐに終了します。 

SCC 分解により、モンスターを含む循環 SCC が検出されます。`1`。 モンスター以来`1`2 番目のルールによって終了することもできるため、サイクルは生産的になります。 逆到達可能性フェーズはモンスターをマークします`1`無限のように。 

最小限の答えは、終了ルールを直ちに採用することで得られます。`1`。 最大の答えは、`-2`。 

ここで純粋なサイクルを考えてみましょう。```
1 1
1 2 1 -1
```終了の伝播はモンスターをマークしません`1`すべてのルールはモンスターに依存するため、終了可能`1`自体。 モンスターは、SCC 推論が使用される前に除外されます。 答えは次のようになります。```
-1 -1
```これはまさにこのステートメントが要求していることです。 

最後に、生産サイクルにのみ到達するモンスターについて考えてみましょう。```
1 -> 2 + diamond
2 -> 2 + diamond
2 -> diamond
```モンスター`1`それ自体はサイクルの中にありません。 周期的 SCC からの逆走査がモンスターに到達`1`したがって、無限の最大値を持つものとして正しくマークされます。 このアルゴリズムは、SCC フェーズおよび逆到達可能性フェーズ以降、特別なロジックを使用せずにこのケースを処理します。
