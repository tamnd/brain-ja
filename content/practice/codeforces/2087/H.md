 ## 解決策
 ## 問題の理解

 私たちは、古典的な 2 プレイヤーの公平なゲームである Nim の変種を扱っています。 標準の Nim では、ゲームの状態は石の山によって定義されます。 自分の番では、プレイヤーは空でない山を選択し、1 つ以上の石を取り除きます。 最後に移動できたプレイヤーが勝ちです。 すべてのパイル サイズの XOR (番号) を使用して、勝者を効率的に決定できます。 XOR が 0 の場合、2 番目のプレーヤーが勝利戦略を持っています。 それ以外の場合は、最初のプレイヤーが行います。 

この問題では、動きに動的制限があります。 「特別な番号」のセットがあります$S$、最初は空です。 この制限は次のように機能します。プレイヤーがパイルを減らそうとした場合、$x$に$y$そして数が存在します$s \in S$そのような$x > s > y$、この動きは禁止されています。 事実上、プレイヤーはセット内のどの数字も飛び越えることはできません$S$。 クエリは数字を次のように切り替えます。$S$または、特定の山のセットを指定して勝者を尋ねます。 タイプ 2 クエリの出力は、最初のプレーヤーが勝利を強制できる場合は「First」、そうでない場合は「Second」になります。 

制約は厳しいです。それぞれのクエリには最大 3 つのパイルが含まれ、パイル サイズと特殊番号は最大 300,000 個まで指定できます。 これにより、考えられるすべてのゲーム状態を明示的に列挙するアプローチは除外されます。 代わりに、変化するセットを処理しながら効率的に数値を計算する方法が必要です。$S$。 

エッジケースは、山が非常に小さい場合、山が次の数値と一致する場合に発生します。$S$、または数字を切り替えるとき$S$以前の仮定に影響を与えます。 たとえば、次の場合$S = \{2\}$パイルのサイズが 3 の場合、許可される唯一の動きはそれを 2 または 1 に減らすことです。 直接 0 に減らすことは禁止されています。 この制約を無視した単純なアプローチでは、間違った勝者を予測することになります。 

## アプローチ

 ブルートフォース手法では、各山を独立したゲームとしてモデル化し、グランディ数を再帰的に計算します。 サイズの山の場合$x$、すべての正当な手を生成し、結果として得られるポジションのグランディ数を計算し、mex を取得します。 それは正しいことですが、これは実行不可能です。最大 300,000 のパイル サイズと 300,000 のクエリでは、再帰計算の数が爆発的に増加し、妥当な制限をはるかに超える最悪の場合の複雑さにつながります。 

重要な洞察は、禁止された数値が非負の整数を連続した間隔に分割しているということです。 各インターバル内で$[l, r]$、インターバル内のパイルからより小さいサイズへのすべての移動が許可されます。 間隔をまたぐ移動は制限されます。 特定のセットに対して$S$、これらの間隔を利用することで、考えられるすべてのパイル サイズの番号を効率的に事前計算できます。 Specifically, if we sort the special numbers and consider intervals between consecutive numbers, each interval behaves like standard Nim, but shifted by the lower bound. The Grundy number of any pile is then its position inside its interval modulo 2, because each interval behaves like a small 1-pile Nim heap that alternates Grundy numbers. 更新中$S$動的に必要なのは間隔境界の更新だけです。 

これにより、問題は、特別な数値のソートされたリストを維持し、その間隔に基づいて一定時間で各山の数値を計算することに軽減されます。 これらの数値の XOR により勝者が得られます。

 ## アルゴリズムのチュートリアル

 1. 並べ替えられたリストまたは数値のセットを維持します。$S$。 ソートまたはバランスの取れた BST を使用すると、どの山の間隔も確実に見つけることができます。$O(\log |S|)$。 
2. 切り替えるクエリの場合$s_i$、どうかを確認してください$s_i$セットの中に存在します。 存在する場合は削除します。 それ以外の場合は、挿入します。 セットを更新すると、間隔が自動的に更新されます。 
3. タイプ 2 クエリの場合、各パイルを反復処理します。$a_j$。 より小さいまたは大きい最も近い特殊な数字を見つけます。$a_j$間隔を特定するには$[l, r]$含む$a_j$。 
4.次の数値を計算します。$a_j$として$a_j - l$。 モジュロ 2 パターンを処理するように間隔が構築されている場合、制限された動きを反映した正しいグランディ数が得られます。 
5. クエリ内のすべての杭の番号を XOR します。 結果がゼロの場合は、「Second」を出力します。 それ以外の場合は、「最初」を出力します。 
6. すべてのクエリに対して繰り返します。 

機能する理由: パイルを特別な数値で定義された間隔にマッピングすることで、複雑な禁止移動ルールを間隔内の標準 Nim に削減します。 各間隔は独立して動作し、間隔オフセットから計算された数値は制約に従います。 これらの数字の XOR は勝者を正確に予測します。これは、間隔が独立したサブゲームを形成し、公平なゲーム構造が維持されるためです。 

## Python ソリューション```python
import sys
import bisect
input = sys.stdin.readline

q = int(input())
S = []

for _ in range(q):
    tmp = list(map(int, input().split()))
    if tmp[0] == 1:
        s = tmp[1]
        idx = bisect.bisect_left(S, s)
        if idx < len(S) and S[idx] == s:
            S.pop(idx)
        else:
            S.insert(idx, s)
    else:
        k = tmp[1]
        piles = tmp[2:]
        xor_sum = 0
        for pile in piles:
            idx = bisect.bisect_right(S, pile)
            l = S[idx - 1] if idx > 0 else 0
            xor_sum ^= pile - l
        print("First" if xor_sum != 0 else "Second")
```このコードは、挿入、削除、間隔の検索に二分検索を使用して、特殊な数値の並べ替えられたリストを維持します。 各山について、間隔は最も近い小さい特別な数値によって決定されます。 下限を減算すると数値が得られ、XOR は独立したサブゲームを結合します。 パイルが特別な数よりも小さいエッジ ケースは、左側の境界として 0 を使用して処理されます。
