 ## 解決策
 ## 問題の理解

 それぞれが左または右を指す、一列に配置された一連の矢印が与えられます。 各矢印には、矢印を赤く塗るための整数の報酬も関連付けられており、これは正、負、ゼロのいずれかになります。 最初はすべての矢印が青色です。 このゲームでは、任意の矢印から開始して一連の再描画操作を実行でき、その後の各移動では、前の矢印の方向に矢印を選択する必要があります。 つまり、前の矢印が左を向いていた場合、次の矢印はより小さいインデックスにある必要があります。 それが右を向いていた場合、次の矢印はより大きなインデックスにある必要があります。 矢印は隣接している必要はありません。 

目標は、赤く塗り直されたすべての矢印の報酬の合計を最大化することです。 各クエリは、最大で 1 つのテスト ケースに対応します。$3 \cdot 10^5$すべてのテスト ケースにわたるすべての矢印の合計が次を超えないこと$3 \cdot 10^5$。 この制約は、どのソリューションも各テスト ケースを矢印の数に対して線形時間で処理する必要があることを直ちに示唆しています。 

一部の報酬はマイナスになる可能性があるため、エッジケースは微妙です。 このような場合、矢印を完全にスキップすることが最適な場合があります。 たとえば、すべての報酬が負の場合、達成可能な最大スコアはゼロになります。 すべての矢印が同じ方向を向いている場合、別の特殊なケースが発生します。 最適なシーケンスには、方向性チェーンの途中から開始するのではなく、方向性チェーンの最後で最大の報酬のみを選択することが含まれる場合があります。 

## アプローチ

 ブルートフォースアプローチでは、各矢印から開始して、有効な再描画シーケンスをすべて再帰的にシミュレートすることを検討します。 開始インデックスごとに、アルゴリズムは現在の矢印の方向に従って分岐し、考えられる有効な次の矢印をすべて考慮します。 このアプローチは正しいですが、最悪の場合、限界をはるかに超える指数関数的な数の配列を探索することになるため、明らかに実行不可能です。$n \approx 3 \cdot 10^5$。 

重要な観察は、同じ方向を指す矢印の各シーケンスが独立したチェーンを形成し、そこで報酬の選択を貪欲に実行できるということです。 矢印を左から右に移動すると、右向きの矢印の場合は現在の最大合計を伝播でき、同様に左向きの矢印の場合は右から左に伝播できます。 実際、この問題は、各矢印について、矢印が含まれている場合にはその矢印から開始して得られる最大の寄与を計算し、次にすべての矢印に対する最大の寄与を選択するものとみなすことができます。 これにより、2 つの配列を計算することで解が線形時間に短縮されます。1 つは '>' 矢印の最大合計を右側に伝播し、もう 1 つは '<' 矢印の最大合計を左側に伝播します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、矢印の数を読み取ります。$n$、道順の文字列、報酬の配列。 
2. 2 つの配列を初期化する`dp_right`そして`dp_left`長さの$n$、ゼロで埋められます。 これらには、各方向の各矢印から開始して取得可能な最大合計が格納されます。 
3. 矢印を左から右に移動します。 現在の矢印が右を向いている場合 ('>')、`dp_right[i] = reward[i] + max(0, dp_right[i-1])`。 それ以外の場合は、設定します`dp_right[i] = 0`。 これにより、連続する右向き矢印のシーケンスが蓄積され、負の和のシーケンスがスキップされます。 
4. 矢印を右から左に移動します。 現在の矢印が左向き ('<') の場合は、`dp_left[i] = reward[i] + max(0, dp_left[i+1])`。 それ以外の場合は、設定します`dp_left[i] = 0`。 これにより、連続する左向き矢印のシーケンスが蓄積されます。 
5. テストケースの答えは、すべての値のうちの最大値です。`dp_right[i]`そして`dp_left[i]`、どの矢印からでもシーケンスを開始できるためです。 また、すべての矢印をスキップするために、最大値に 0 を含めます。 
6. 結果を印刷します。 

これが機能する理由: 方向性伝播により、各矢印について、その指す方向に進み続けることで得られる最大合計が考慮されます。 すべての開始位置の最大値を取ることで、考えられるすべての操作シーケンスを取得します。 マイナスの報酬は自動的に除外されます。`max(0, ...)`ロジック。ゼロ操作を実行する選択をモデル化します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()
        c = list(map(int, input().split()))
        
        dp_right = [0] * n
        dp_left = [0] * n
        
        # propagate for '>' arrows
        for i in range(n):
            if s[i] == '>':
                dp_right[i] = c[i]
                if i > 0:
                    dp_right[i] += max(0, dp_right[i-1])
        
        # propagate for '<' arrows
        for i in reversed(range(n)):
            if s[i] == '<':
                dp_left[i] = c[i]
                if i < n-1:
                    dp_left[i] += max(0, dp_left[i+1])
        
        ans = 0
        for i in range(n):
            ans = max(ans, dp_right[i], dp_left[i])
        
        print(ans)

if __name__ == "__main__":
    solve()
```このコードは、配列を 2 回 (1 回は左から右に、もう 1 回は右から左に) スキャンすることにより、線形な時間計算量を維持します。 使用する`max(0, ...)`負の寄与を持つシーケンスを自動的に破棄し、不必要な操作を回避します。 境界条件は、伝播前に配列インデックスをチェックすることで慎重に処理されます。 

## 実用的な例

 入力例:`3, <> >, 5 4 6`| 私 | s[i] | c[i] | dp_right | dp_左 |
 | --- | --- | --- | --- | --- |
 | 0 | < | 5 | 0 | 5 |
 | 1 | > | 4 | 4 | 0 |
 | 2 | > | 6 | 10 | 0 |

 そのうちの最大値`dp_right`そして`dp_left`は 10 です。これは予想される出力と一致します。 

入力例:`2, >>, -1 -2`| 私 | s[i] | c[i] | dp_right | dp_左 |
 | --- | --- | --- | --- | --- |
 | 0 | > | -1 | -1 | 0 |
 | 1 | > | -2 | -2 | 0 |

 最大値は 0 で、すべての矢印をスキップすることに対応します。

 ## 特殊なケース

 すべての矢印が同じ方向を向いているシーケンスの場合、アルゴリズムはその方向に沿って合計を正しく伝播し、最大の連続サブシーケンスを自動的に選択します。 負の報酬を持つシーケンスの場合、`max(0, ...)`ロジックにより、マイナスの寄与が含まれていないことが保証されます。 単一矢印シーケンスでは、最大値は報酬またはゼロのいずれかです。 空の操作の場合、答えはデフォルトで 0 になり、矢印を再描画しない方がよい場合を正しく処理します。
