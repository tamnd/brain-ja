 ## 解決策
 ## 問題の理解

 有向非巡回グラフが与えられます。$n$いくつかの既存の有向エッジを持つ頂点。 タスクは、できるだけ少ない数の新しい有向エッジを追加することです。そうすることで、追加後に結果として得られる有向マルチグラフのすべてのエッジをいくつかのハミルトニアン サイクルに分割できます。各サイクルはすべての頂点を 1 回だけ訪問し、頂点ごとに 1 つの出力エッジと 1 つの入力エッジを正確に使用します。 

重要な構造的解釈は、各ハミルトニアン サイクルが頂点の順列に対応するということです。 そのサイクルでは、すべての頂点に 1 つの出力エッジと 1 つの入力エッジがあります。 もし持っていれば$c$このようなサイクルでは、すべての頂点が正確に$c$出力エッジと正確に$c$最終的なグラフの入力エッジ。 

したがって、本当の問題はパスや DAG 構造に関するものではなくなりました。 隣接行列のすべての行和と列和が等しくなるように有向マルチグラフを完成させ、その行列を順列行列に分解する問題になります。 

DAG 制限は入力においてのみ重要であり、最終的な構築においては重要ではありません。 任意の有向エッジ (自己ループを除く) を追加できるため、非循環性を完全に破壊できます。 

単純なアプローチでは、ハミルトニアン サイクルを直接構築するか、パスを貪欲に拡張しようとしますが、エッジを一貫した順列にグローバルに分割する必要があるため、すぐに失敗します。 単一のローカル サイクル構築では、すべての頂点およびすべてのサイクルにわたる入次数と出力次数のグローバルな一貫性が保証されません。 

さらに微妙な失敗例は、バランスを無視した場合に発生します。 たとえば、1 つの頂点の出次数が大きく、入次数が小さい場合、その頂点は一貫してすべてのサイクルを同時に処理できないため、サイクルを形成しようとする試みは最終的に行き詰まります。 

本当の障害は接続性ではなく、程度の不均衡です。 

## アプローチ

 強引なアイデアは、次の値を増やして、追加されるエッジの最小数を明示的に検索することです。$c$、それぞれについて$c$、グラフを完成できるかどうかを判断しようとしています。$c$- ハミルトン サイクルに分解する通常の有向マルチグラフ。 これは、分解ステップで自明ではない割り当て問題を解決する必要があり、追加されたエッジの可能性をすべて試すと組み合わせ的に増大するため、すぐに実行不可能になります。 

重要な観察は、ハミルトニアン サイクル分解が非常に厳密な条件を課すことです。つまり、最終的なグラフは次の和集合でなければなりません。$c$指示された 1 要素。 行列の観点からは、非負の整数行列が必要です。$A$各行の合計と列の合計が等しくなるように$c$、 そして$A[i][j] \ge B[i][j]$、 どこ$B$は初期隣接行列です。 

これがわかると、問題はきれいに 2 つの部分に分かれます。 まず、実行可能な最小値を決定します$c$。 次に、それを達成するために有効な補完を構築します。$c$、そして最後にそれを分解します$c$標準の 2 部マッチング引数を使用した置換行列。 

DAG 構造では、異なる頂点間にエッジを任意に追加できるため、次数のバランスを超えて実行可能性を妨げる自己一貫性制約がないことが保証されます。

 ## アルゴリズムのチュートリアル

 まずグラフを次数データに変換します。 各頂点について、現在の入次数と出次数を計算します。 

1. コンピューティング$out[v]$そして$in[v]$頂点ごとに。 これらは、各頂点が各方向ですでに参加しているサイクルの数を表します。 
2. 可能な限り最小のサイクル数を選択します$c$すべての頂点の入次数と出次数を等しくできるようにする$c$。 これには必要です$$c \ge \max_v(out[v], in[v])$$既存の学位を減らすことはできないし、$$n \cdot c \ge m$$各サイクルが正確に寄与するため、$n$エッジをすべてカバーする必要があります。 

そこで設定しました$$c = \max\left(\max_v(out[v], in[v]), \left\lceil \frac{m}{n} \right\rceil \right).$$3. 各頂点について、まだ必要な発信エッジと着信エッジの数を計算します。$$needOut[v] = c - out[v], \quad needIn[v] = c - in[v].$$合計は一致するため、追加されたエッジの数は正確に総需要になります。 
4. 出ていく欠損を入ってくる欠損と照合することで追加エッジを構築します。 残りの発信需要ともう 1 つの着信需要を含む複数の頂点セットを維持します。 頂点を繰り返し接続していきます$u$ポジティブで$needOut$頂点へ$v$ポジティブで$needIn$、確保する$u \ne v$。 単純な選択により自己ループが作成される場合は、別の利用可能なペアと交換します。 以来$n \ge 2$、この交換はいつでも可能です。 
5. 追加されたすべてのエッジを構築した後、すべての頂点は正確に入次数と出次数を持ちます。$c$。 
6. 次に、結果の有向マルチグラフを次のように分解します。$c$ハミルトニアンサイクル。 隣接関係を、頂点の左側のコピーと右側のコピーの間の 2 部マルチグラフとして解釈します。 各レイヤーは、入力されるすべての制約が満たされるように、頂点ごとに出力エッジを 1 つだけ選択することに対応します。 

DFS ベースの拡張マッチングを使用して、この 2 部構造で完全なマッチングを繰り返し見つけ、使用されるエッジごとに 1 単位の容量を削除します。 各マッチングは 1 つのハミルトニアン サイクルに対応します。 
7. 抽出された各マッチングは頂点の順列を定義し、それを 1 つのサイクルとして出力します。 すべてのエッジは、そのようなマッチングに 1 つだけ割り当てられます。 

### なぜ効果があるのか

 核となる不変条件は、選択した後、$c$, the construction enforces a doubly stochastic structure at the integer level: every vertex has identical in-degree and out-degree. このような整数行列はいずれも順列行列に分解できます。これは、各ステップでバランスを保ちながら 1 つの完全一致を抽出することで問題が軽減されるためです。 すべての頂点が常に等しい残りのイン/アウト次数を保持するため、マッチング ステップがスタックすることはなく、抽出されたすべてのレイヤーが有効なハミルトニアン サイクルを形成します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    adj = [[0] * n for _ in range(n)]
    outdeg = [0] * n
    indeg = [0] * n

    edges = []
    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        adj[u][v] += 1
        outdeg[u] += 1
        indeg[v] += 1
        edges.append((u, v))

    c = 0
    for i in range(n):
        c = max(c, outdeg[i], indeg[i])
    c = max(c, (m + n - 1) // n)

    need_out = [c - outdeg[i] for i in range(n)]
    need_in = [c - indeg[i] for i in range(n)]

    added = []

    # construct added edges greedily with swap to avoid self-loops
    out_list = [i for i in range(n) for _ in range(need_out[i])]
    in_list = [i for i in range(n) for _ in range(need_in[i])]

    j = 0
    for u in out_list:
        if in_list[j] != u:
            v = in_list[j]
            added.append((u, v))
            j += 1
        else:
            if j + 1 < len(in_list):
                v = in_list[j + 1]
                in_list[j + 1] = in_list[j]
                in_list[j] = v
                added.append((u, v))
                j += 1

    all_edges = edges + added
    E = len(all_edges)

    # build adjacency matrix with capacities
    cap = [[0] * n for _ in range(n)]
    for u, v in all_edges:
        cap[u][v] += 1

    res = [0] * E

    def find_matching():
        match_r = [-1] * n
        used = [0] * n

        def dfs(u):
            for v in range(n):
                if cap[u][v] > 0 and used[v] == 0:
                    used[v] = 1
                    if match_r[v] == -1 or dfs(match_r[v]):
                        match_r[v] = u
                        cap[u][v] -= 1
                        return True
            return False

        for u in range(n):
            used = [0] * n
            dfs(u)

        return match_r

    for c_id in range(1, c + 1):
        match_r = find_matching()
        nxt = [-1] * n
        for v in range(n):
            if match_r[v] != -1:
                nxt[match_r[v]] = v

        for u in range(n):
            v = nxt[u]
            for i, (a, b) in enumerate(all_edges):
                if a == u and b == v:
                    res[i] = c_id
                    all_edges[i] = (-1, -1)
                    break

    print(len(added))
    for u, v in added:
        print(u + 1, v + 1)
    print(c)
    print(*res)

if __name__ == "__main__":
    solve()
```コードの最初の部分は次数を計算し、実行可能な最小サイクル数を選択します。$c$。 次の部分では、単純なローカル スワップによって自己ループを回避しながら、余剰の送信要求と受信要求をペアにすることで追加エッジを構築します。 

その後、グラフを容量マトリックスに変換します。 それぞれの反復`find_matching`DFS ベースの拡張パスを使用して、頂点から頂点への 1 対 1 の割り当てを構築することにより、1 つのレイヤーを抽出します。 抽出された各マッチングは 1 つのハミルトニアン サイクルに対応します。 

最後に、各エッジはそれが使用されるサイクルに割り当てられます。

 ## 特殊なケース

 クリティカルなエッジ ケースは、頂点の入次数がゼロまたは出次数がゼロの場合です。 たとえば、純粋なチェーンでは$1 \to 2 \to 3 \to 4$、エンドポイントにより、アルゴリズムは終了エッジを 1 つだけ追加するように強制されます。 アルゴリズムはこれを処理するために、$c$これにより、両方のエンドポイントが必要な補償を確実に受け取ることができます。 

もう 1 つの微妙なケースは、バランシング中に頂点が自己ループを必要とする場合です。 この構造では、受信リスト内の候補を交換することでこれを明示的に回避し、$i \to i$エッジは、グローバルな実現可能性を維持しながら導入されます。
