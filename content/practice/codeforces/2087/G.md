 ## 解決策
 ## 問題の理解

 私たちは毎日、一連の競争を与えられています。 Monocarp は毎日、競技会に参加するか、トレーニングに一日を費やします。 トレーニングでは、ゼロから始まる単一の整数のスキル値が増加しますが、参加すると、その日と現在のスキルの両方に応じてお金が得られます。 

Monocarp が i 日目に参加すると、固定基本値 a[i] に現在のスキルを加えた値を獲得します。 訓練してもスキルが1上がるだけで何も稼げない。 毎日 1 つのアクションだけが貢献し、アクションの順序によって将来のスキルと将来の収入の両方が決まります。 

タスクは、すべての参加日から得られる合計金額が最大になるように、トレーニングする日のサブセットを選択することです。 すべての最適な選択肢の中で、その最大値を達成する個別のトレーニング サブセットの数をカウントする必要もあります。 

この制約により、テストごとに最大 2⋅10^5 日が許可されるため、どの解も線形または O(n log n) に近づく必要があります。 トレーニング日のすべてのサブセットを試したり、バックトラッキングを使用して決定を貪欲にシミュレートしたりするものは、決定空間が n で指数関数的であるため、すぐに失敗します。 

トレーニングするか参加するかを毎日独立して決定しようとする素朴なアプローチは失敗します。トレーニングによって将来のすべての日のスキルが変化するため、すべての決定が世界的な影響を与えるからです。 たとえば、初期の価値の高い日をスキップすると、その後のすべての寄与が損失を大きく上回るほど増加する可能性があります。 

すべての a[i] が 0 の場合、微妙なエッジ ケースが発生します。 その場合、全体の値はスキルの蓄積によってのみ得られるため、多くの異なるトレーニング スケジュールが同じ最終結果をもたらし、それらを正確にカウントすることが主な困難になります。 

## アプローチ

 直接的なブルート フォースでは、トレーニング日の 2^n 個のサブセットをすべて列挙し、結果として生じるスキルの進化を計算し、総収入を評価します。 これは、すべての有効なスケジュールを明示的にモデル化しているため正しいですが、各評価のコストは O(n) となり、O(n・2^n) になります。これは、2⋅10^5 までの n では不可能です。 

重要な観察は、トレーニングの貢献が時間的に線形であるということです。各トレーニング日は、その後の参加日すべてのスキルを向上させるため、スキップされた日ごとに、将来のすべての選択の限界値が増加します。 これにより、トレーニングの利点が正確なパターンではなく、その時点の後に残る競技の数にのみ依存する構造が生まれます。 

これにより、トレーニング日数 k を選択し、それらを最適な位置に配置するという問題として再解釈できます。 k が固定されると、最適な戦略は決定的になります。つまり、トレーニングを遅らせても、スキルの向上によって恩恵を受ける将来の競技の数が減るだけであるため、トレーニングはできるだけ早い日に行う必要があります。 

したがって、問題は k の選択と計算に帰着します。 

全日にわたる a[i] の合計から参加を遅らせたコストを差し引き、さらに選択した将来のポジションの数を k 倍したもの。 

この構造により、貪欲な順序付けと、最適性に影響を与えることなくトレーニング日を配置する方法の組み合わせカウントが行われます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n・2^n) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ポイントは、「何日練習するか」ではなく、「参加日までにスキルが何倍になるか」に視点を変えることです。

1. Monocarp が合計 k 回のトレーニングを実行した場合、参加時点での彼のスキルは、その日より前に行われたトレーニングの数とまったく同じであることに注目してください。 これは、トレーニングの貢献度が、選択した各参加日の前に行われるトレーニング操作の数によって完全に把握されることを意味します。 
2. 総収入を、参加日数の a[i] の合計とスキル貢献の合計として書き換えます。 第 2 期は、トレーニングと参加日の相対的な順序のみに依存し、日自体の識別には依存しません。 
3. k、トレーニングの総日数を修正します。 固定 k の場合、早期のトレーニングはその後の参加日よりも将来の参加日数に影響を与えるため、トレーニングをできるだけ早く配信すると利点が最大になります。 
4. これは、最適なスケジュールとは、選択した参加日に関して適切にソートされた場合に、トレーニング日がプレフィックスのような構造を形成するスケジュールであることを意味します。 
5. ここで、どの n ～ k 日を参加日とするかを選択することを検討します。 参加インデックスの固定セットの場合、最適な配置の値は一意であり、プレフィックスの合計と、各ポジションの前に行われるトレーニングの数を含む単純な式を使用して、その合計の寄与を計算できます。 
6. すべての k の最大値を効率的に計算するために、目的が段階的に評価できる関数になり、k を 0 から n までスイープすることで最適な構成を追跡できることがわかります。 
7. カウントについては、最適な k 構造がわかれば、有効なスケジュールの数は、最適なプレフィックス プロパティを保存する位置の中からトレーニング スロットとして機能する位置を選択することに対応します。これは、有効なインターリーブに対する二項カウントに帰着します。 
8. 階乗と逆階乗を事前計算して、998244353 を法とする組み合わせを計算し、最適な k ごとに寄与を蓄積します。 

### なぜ効果があるのか

 重要な不変条件は、固定数のトレーニング操作 k について、スコアを下げることなくすべてのトレーニング アクションができるだけ早く行われる最適なスケジュールに変換できることです。 この単調性により、値は k と選択された参加セットのみに依存し、より細かい順序付けの選択には依存しないことが保証されます。 これにより、指数関数的なスケジューリングの問題が、単一のパラメーターと組み合わせ配置に対する多項式の最適化に分解されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    # prefix sums of a
    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + a[i]

    # dp[k] = best value with k trainings
    dp = [-10**30] * (n + 1)
    cnt = [0] * (n + 1)

    dp[0] = 0
    cnt[0] = 1

    for i in range(n):
        ndp = [-10**30] * (n + 1)
        ncnt = [0] * (n + 1)

        for k in range(i + 1):
            if dp[k] < -10**20:
                continue

            # option 1: participate
            val = dp[k] + a[i] + k
            if val > ndp[k]:
                ndp[k] = val
                ncnt[k] = cnt[k]
            elif val == ndp[k]:
                ncnt[k] = (ncnt[k] + cnt[k]) % MOD

            # option 2: train
            val = dp[k]  # no immediate gain
            if val > ndp[k + 1]:
                ndp[k + 1] = val
                ncnt[k + 1] = cnt[k]
            elif val == ndp[k + 1]:
                ncnt[k + 1] = (ncnt[k + 1] + cnt[k]) % MOD

        dp, cnt = ndp, ncnt

    best = max(dp)
    ans = 0
    for k in range(n + 1):
        if dp[k] == best:
            ans = (ans + cnt[k]) % MOD

    print(best, ans)

t = int(input())
for _ in range(t):
    solve()
```この実装では、プロセスの直接的な動的プログラミング解釈が使用されます。 状態 dp[k] は、これまでに使用された正確に k 個のトレーニング アクションで日数のプレフィックスを処理した後に達成可能な最大収入を追跡します。一方、cnt[k] は、その値を達成する方法の数をカウントします。 

毎日、私たちは参加して収入を a[i] に現在のスキル k を加えて増加させるか、トレーニングして k を増加させますが、すぐには報酬は追加されません。 遷移では、998244353 を法とするカウントが慎重に保存されます。 

よくある微妙な点は、スキルによる貢献が以前に行われたトレーニングの数 (DP 状態では正確に k) に依存することです。 これが、参加トランジションによって報酬に k が追加される理由です。

 ## 特殊なケース

 重要なエッジケースは、すべての報酬がゼロの場合です。 この状況では、参加によってスキル依存の価値のみが追加され、すべての DP パスが同一の最大値に崩​​壊するため、どのスケジュールでも同じ合計収入が得られます。 このアルゴリズムは、多くの状態で「train」遷移と「participate」遷移の両方の値が等しいままであるため、最適な遷移を保存するすべてのシーケンスを正しくカウントします。そのため、cnt は枝刈りをせずにすべての有効なパスを蓄積します。 

すべての a[i] が大きな正の値である場合、別のエッジ ケースが発生します。 ここで、最適な戦略はトレーニングを完全に回避することであり、DP は k = 0 に収束します。この遷移により、a[i] の即時の寄与が失われるため、将来の状態ではトレーニング パスが即座に次善の状態になることが保証されるため、トレーニングなしパスのみが dp に残ります。
