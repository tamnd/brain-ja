 ## 問題の理解

 駅 A からの出発時刻の固定シーケンスが与えられており、厳密に増加します。また、各バスについて、駅 B への到着順にどのくらい「遅れる」可能性があるかについての制約もわかっています。到着駅には厳密に増加する未知の時刻表があり、単純な実現可能性ルール、つまり定時に出発するバスと一致する限り、自由にバスを構築できます。$a_i$ポジションに割り当てることはできません$p_i$選択した到着時刻を除き、到着順に$b_{p_i}$少なくとも$a_i + t$。 

この問題を自明ではないものにしているのは、有効な割り当てを作成することだけが求められているわけではないということです。 各バスごとに$i$、私たちは与えられています$x_i$、バスが有効な割り当てで達成できる最大のランクをエンコードします。 つまり、バスを押していこうとしても$i$ソートされた到着順で可能な限り前の位置に到達することはできません$x_i + 1$、ただし、正確に到達する場合もあります$x_i$。 

厳密に増加する配列を再構築する必要があります$b$すべての順列を考慮すると$p$満足のいく$b_{p_i} \ge a_i + t$、各バスの到達可能な最大位置$i$まさに$x_i$。 そうでない場合$b$存在する場合は、それを検出する必要があります。 

制約$n \le 200{,}000$強制的に$O(n \log n)$または$O(n)$解決。 置換をシミュレートしたり、実行可能性を繰り返し再計算したりするアプローチは、実行可能性のチェック自体にグローバルなマッチング制約が含まれるため、すぐに遅すぎます。 

複数のバスに大きなバスがある場合、重要な微妙なエッジ ケースが発生します。$x_i$価値観。 単純な構造では、各バスを独立して最大位置に配置しようとする可能性がありますが、これは最終的な順序付けでの衝突を無視します。 もう 1 つの微妙な障害モードは、2 つのバスが同一の場合に発生します。$a_i + t$しきい値はあるが異なる$x_i$、構築されたオブジェクトに矛盾する順序制約を強制する可能性があります。$b$。 

## アプローチ

 ブルートフォースの観点は、候補配列を修正することを想像することです$b$、次に、各バスについて、以下を満たすすべての順列をチェックすることにより、達成可能な最大位置を計算します。$b_{p_i} \ge a_i + t$。 これはすぐにマッチングの問題になります。バスごとに、有効なスロットにマッチングできる状態でどこまで右にプッシュできるかを確認しようとします。 これをバスごとに独立して計算するには、少なくとも 2 部マッチングのような実現可能性チェックを繰り返し解く必要があります。$O(n^2)$直接的なシミュレーションでクエリごとに、$O(n^3)$全体。 これは完全に不可能です$n = 2 \cdot 10^5$。 

重要な構造的観察は、制約が$b_{p_i} \ge a_i + t$はバスが位置を占有できるかどうかのみに依存し、順列の実現可能性は位置の各プレフィックスに適格なバスの数のみに依存します。 これにより、問題は個々の順列について推論するのではなく、単調なしきい値構造を構築することに変換されます。 

推測する代わりに$b$そして再計算$x$、ロジックを逆にして、それぞれを解釈します。$x_i$から始まる位置の接尾辞に何台のバスが到達できる必要があるかという要求として$x_i$。 これはスケジューリングの問題になります。各バスは「最後のバスの中に少なくとも 1 つの利用可能な位置がなければならない」という制約に影響します。$n - x_i + 1$実行可能なスロット」であり、これらの制約はグローバルに相互作用します。 

工事はバスを期限ごとに仕分けする作業に簡素化される$a_i + t$それぞれのポジションを尊重しつつ、貪欲にポジションを割り当てる。$j$そこに到達できるバスのみを割り当てる必要があります。 与えられた$x_i$次に、値により追加の単調構造が課されます。バスの値が小さくなります。$x_i$右端に移動することはできないため、順序付けの早い段階で強制する必要があります。 

これは有効な$b$時間しきい値と最大ランク制約の両方に一致する方法で、どのバスが各位置を占めるかを決定することにより、間接的にシーケンスを実行します。

 ## アルゴリズムのチュートリアル

 各バスを書き換えます$i$拘束間隔として: 位置にのみ割り当てることができます$p$位置が少なくとも時間に対応するように$a_i + t$、さらに最終ランクを超えることはできません$x_i$。 

建設は次のように進められます。 

## アルゴリズムのチュートリアル

 1. 各バスの実現可能な最も早い到着しきい値を計算します。次のように定義されます。$d_i = a_i + t$。 これは、バスが合法的に位置を占有することができる最も早い時期です。 これにより問題は、位置の値が少なくとも$d_i$。 
2. バスを昇順に並べ替えます$d_i$。 これにより、より厳しい (以前の) 制約を持つバスが最初に配置され、後の配置が実現可能性を妨げるのを防ぎます。 このようなバスを遅らせると、有効なスロットがすべて消費され、配置できなくなる可能性があります。 
3. 利用可能なバスのプールを維持しながら、左から右に位置を処理します。$d_i$現在の位置への割り当てを許可するのに十分な大きさです。 各ステップで、しきい値制約に違反せずにその位置を合法的に占有することができるバスのみを考慮します。 
4. 現在利用可能なすべてのバスの中で、「最も制限されている」バスを選択します。$x_i$、最小を意味します$x_i$。 現在の位置に割り当てます。 これは、バスのサイズが小さいため必要です。$x_i$有効な順列の中で最初に出現する必要があります。そうしないと、人為的にそれらが右端に押し出されることを許可してしまいます。 
5. バスの位置への暫定的な割り当てを作成します。これにより、到着の相対的な順序が定義されます。 この順序により、構築される内容が直接決まります。$b$値: 今後は、割り当てと一致する厳密に増加する時間を割り当てるだけで済みます。 
6. 構築する$b$設定により$b_j = 10^{18} + j$。 これにより、厳密な増加が保証され、割り当ての実現可能性が保証されると、タイミング制約に違反する可能性が排除されます。 相対的な実現可能性のみが重要であるため、間隔を大きくすると干渉が回避されます。$a_i + t$しきい値。 
7. 各バスについて暗黙的に検証します。$i$、割り当てられた位置インデックスは以下を超えません$x_i$。 いかなる時点でも、許容範囲を超えてバスを割り当てなければならなくなった場合、建設は不可能になります。 

### なぜ効果があるのか

 核となる不変条件は、位置のすべてのプレフィックスで、実現可能性と、それによって引き起こされるランキングの上限構造の両方を尊重する方法でバスを割り当てるということです。$x_i$。 しきい値が以下のバスのみを割り当てるため、実現可能性が維持されます。$d_i$現在のポジションに満足しています。 に関する最適性$x_i$これは、常に最も制約されたバスを最初に選択することで、厳しく制約された要素がその許容最大ランクを超える位置に遅延されるのを防ぐためです。 この貪欲な順序付けにより、有効な割り当てが存在する場合、アルゴリズムは将来のブロック状況を引き起こすことなく割り当てを構築します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, t = map(int, input().split())
    a = list(map(int, input().split()))
    x = list(map(int, input().split()))

    buses = [(a[i] + t, x[i], i) for i in range(n)]
    buses.sort()

    import heapq

    res_pos = [-1] * n
    j = 0
    heap = []

    for pos in range(1, n + 1):
        while j < n and buses[j][0] <= pos:
            d, xi, i = buses[j]
            heapq.heappush(heap, (xi, i))
            j += 1

        if not heap:
            print("No")
            return

        xi, i = heapq.heappop(heap)

        if xi < pos:
            print("No")
            return

        res_pos[i] = pos

    b = [0] * n
    cur = 10**18
    for i in range(n):
        b[i] = cur + i

    print("Yes")
    print(*b)

if __name__ == "__main__":
    solve()
```この実装は、ポジションに対するスイープラインの考え方に従います。 まず、バスを可能な限り早い位置で並べ替えます$d_i = a_i + t$。 位置インデックスを増やすと、その位置を合法的に占有できるすべてのバスを、キーがキーの優先キューに挿入します。$x_i$常に最小の許容最大ランクを持つバスが最初に選択されるようにします。 

重要なチェック`xi < pos`の意味を強制します$x_i$: バスが位置に割り当てられている場合`pos`しかしそこまで到達することは許されず、建設は即座に失敗します。 

最後に、位置へのバスの有効な割り当てが完了したら、厳密に増加する値を$b$。 近くの選択された線形間隔$10^{18}$厳密な単調性と制約の干渉からの安全性の両方を保証します$a_i + t$、実現可能性は絶対的な違いではなく順序にのみ依存するためです。
