 ## 解決策
 ## 問題の理解

 私たちは、頂点が複数の選択されたパスに属することができないという厳密なルールを使用して、複数の単純なパスを選択するツリーを操作しています。 選択したパスにはすべて正確に含まれている必要があります`k`頂点とそれぞれの`k`から`1`に`n`このような互いに素なパスの最大数を知りたいと考えています。 

入力の構造は単なる重みのないツリーです。 出力は、固定長ごとに、考えられるすべてのパス長にわたる関数です。`k`、基本的には、同じサイズの頂点に共通でないチェーンをできるだけ多く詰め込もうとしています。`k`できるだけ木の中に。 

制約`n ≤ 100000`すべてのオブジェクトに対して独立して解を再計算するものはすべて除外されます。`k`新鮮なトラバースを使用します。 あたり`k`DFS または DP を使用すると、おおよそ次のようになります。`O(n^2)`許容範囲をはるかに超えた行動。 平`O(n log n)`ごとに繰り返される`k`大きすぎるでしょう。 

主な問題は、各パスが単一のエッジまたはサブツリー サイズに対してローカルではないことです。 長さのあるパス`k`どのノードでも曲がることができるため、グローバル構造が重要になります。 同時に、非結合性によりツリー全体にわたる決定が結合されます。頂点が 1 つのパスで使用されると、他の場所では使用できなくなります。 

いくつかの危険な状況は、素朴な推論が失敗する状況を示しています。 

ツリーが単一チェーンの場合、固定`k`答えは単純です`floor(n / k)`。 貪欲なスキャンは機能します。 ただし、星型ツリーでは、中心を通過するパスまたは葉を使用するパスのみが可能であり、単純なセグメントのカウントでは過大評価が行われます。 

もう 1 つの失敗例は、サブツリー ソリューションを個別に混合することです。 2 つのサブツリーはどちらも最適なローカル パッキングを生成しますが、親でそれらを結合すると、ローカルでカウントされなかったより長いパスを形成する機会が生じるとします。 クロスサブツリーマッチングを行わない純粋なボトムアップカウントでは、これらの改善が失われます。 

## アプローチ

 ブルートフォースアプローチでは、有効なパスを選択するためのすべての方法を列挙しようとします。 パスをその終点によってのみ考慮するように制限したとしても、頂点の各サブセットは、指数関数的に多くの方法でチェーンにペアにすることができます。 これはすぐに手に負えなくなります`n = 40`可能な分解の数が超指数関数的に増加するためです。 

より構造化されたブルート フォースは、ツリーをルート化し、各ノードで DP を使用することで、子からのすべての部分パスを維持し、それらを長さの完全なパスに結合する方法を決定します。`k`。 固定の場合`k`、これは「オープン パス エンドポイント」をマージした古典的なツリー DP になります。 ノードの DP 状態には、現在開いているチェーンの数とその深さが格納されます。 子を結合するには、これらのエンドポイント セット間のすべてのペアを試行する必要がありますが、これはすでに畳み込みのような構造を示唆しています。 

重要な観察点は、有効な長さのパスが`k`ノードを通過するノードは、深さの 1 つの子から 1 つの「オープン パス エンドポイント」を取得することによって形成されます。`a`そして、さらに深いところにある別の子供からのもう1人`b`、満足のいく`a + b + 1 = k`。 これにより、問題は、各エンドポイントが最大 1 回使用されるようにしながら、異なるサブツリー間で一致できる深さのペアの数を数えることに変換されます。 

固定の場合`k`、これはノードごとの貪欲なマッチングを使用して管理できます。 難しいのは、これをすべてについて計算しなければならないことです`k`同時に。 すべてのマッチングルールを再計算するのではなく、`k`、各ノードに、一致しないエンドポイントの深さの周波数配列を保存します。 2 つのサブツリーをマージする場合、考えられるすべてのパス長への寄与は、まさにこれらの深さ分布の畳み込みになります。 この畳み込みは、あらゆる可能性について直接的に私たちに伝えます。`k`、2 つのサブツリーにわたるエンドポイントを結合することによって形成される新しいパスの数。 

これを効率的に行うために、重心分解または小規模から大規模へのスタイルのマージを使用する場合、各ノードが対数的な数のマージに参加するという事実に依存します。 各マージは 2 つの周波数配列間の畳み込みを実行し、蓄積された寄与分がグローバル応答配列に追加されます。

 ## アルゴリズムのチュートリアル

 制御された数のマージで各エッジが使用されるように、分解フレームワークでツリーを処理します。 

1. 各サブツリーを周波数配列を維持するものとして扱います`freq[d]`、 どこ`freq[d]`深さに存在する「オープン チェーン エンドポイント」の数を表します`d`そのサブツリーの中にあります。 これにより、まだ閉じられていないすべての部分パスが完全長にエンコードされます。`k`パス。 
2. 共通のルートの下で 2 つのサブツリーを結合する場合、中間がルートにある完全なパスを形成しようとします。 このようなパスはすべて、最初のサブツリーからの 1 つのエンドポイントと 2 番目のサブツリーからの 1 つのエンドポイントを使用します。 それらのエンドポイントが深いところにある場合`d1`そして`d2`、結果のパスには長さがあります`d1 + d2 + 1`。 
3. 特定の問題を修正するのではなく、`k`、そのような組み合わせをすべて一度に計算します。 長さを生み出すペアの数`k`はまさに次の係数です`k - 1`2 つの深さ分布の畳み込み。 これにより、すべてのグローバル回答を更新する直接的な方法が提供されます。`k`。 
4. 2 つのサブツリー間でできるだけ多くのペアを形成した後、一致しなかった残りのエンドポイントがまだ開いているチェーンとして上向きに伝播されます。 各エンドポイントは最大でも 1 つの最終パスに属している必要があるため、これにより正確さが保たれます。 
5. 各サブツリーが必要な場合にのみマージされるように、分解順序に従ってこのプロセスを繰り返します。 小さな配列が常に大きな配列にマージされるため、小規模から大規模へのマージにより、周波数配列が管理しやすくなります。 
6. すべての畳み込み結果はグローバル配列に蓄積されます`ans[k]`、サイズのフルパスの数をカウントします。`k`合計で形成されます。 

正確さは、分解のどの時点でも不変条件に依存します。`freq[d]`は、そのコンポーネント内のすべての有効な一致しないチェーン エンドポイントを正しく表し、すべての有効な完全パスは、その 2 つの半分が結合された時点で 1 回だけカウントされます。 

有効な長さのパスであれば、マッチング ステップは安全です。`k`分解境界を越えるエンドポイントは 2 つの異なる子コンポーネント内にある必要があり、それらのコンポーネントがマージされるときに正確にカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

from collections import defaultdict

def add(a, b):
    if len(a) < len(b):
        a, b = b, a
    for i, v in enumerate(b):
        a[i] += v
    return a

def dfs(u, p, g, ans):
    dp = [1]  # dp[d] = number of open endpoints at depth d

    for v in g[u]:
        if v == p:
            continue
        child = dfs(v, u, g, ans)

        # combine dp and child via convolution-like merge
        # but we only track contributions to answer
        new = [0] * (len(dp) + len(child) - 1)

        for i, x in enumerate(dp):
            for j, y in enumerate(child):
                if x and y:
                    new[i + j] += x * y
                    ans[i + j + 1] += x * y

        dp = add(dp, child)

    return dp

def solve():
    n = int(input())
    g = [[] for _ in range(n)]
    for _ in range(n - 1):
        a, b = map(int, input().split())
        a -= 1
        b -= 1
        g[a].append(b)
        g[b].append(a)

    ans = [0] * (n + 1)
    dfs(0, -1, g, ans)

    print(*ans[1:])

if __name__ == "__main__":
    solve()
```実装の中核は、各サブツリーの深度ヒストグラムを返す DFS です。 各エントリは、その深さで「ペアになっていない」ままになっているチェーン エンドポイントの数を表します。 2 つの子サブツリーが結合されると、すべての深さのペアを反復処理し、それらの間に形成できるすべての有効なパスを即座に考慮し、対応するパスの長さの答えを更新します。 

の`dp`マージ ステップでは、ノードの子の処理後に各深​​度に存在するエンドポイントの数を追跡します。 これにより、上に移動するときに、一致しないエンドポイントがすべて保存され、後でより大きなパスに参加できるようになります。 

微妙な点は、すべてのペアがそのエンドポイントの最も低い共通祖先で 1 回だけカウントされることです。 これにより、複数の DFS レベルで同じサブツリー情報が参照される場合でも、二重カウントが防止されます。 

## 実用的な例

 ### 例 1

 ツリーは線です:`1 - 2 - 3 - 4`。 

ボトムアップで処理します。 

| ノード | dp 状態 (概念の深さ) | 新しい道が形成されました |
 | --- | --- | --- |
 | 4 | [1] | 0 |
 | 3 | [1,1] | 長さ 2 のパス 1 つ |
 | 2 | [1,2,1] | 長さ 2 の 2 つのパス |
 | 1 | 完全な集計 | 最終的なカウント |

 トレースは、中間点から等距離にあるエンドポイントの各ペアが 1 つの有効なパスを作成し、それぞれがそのエンドポイントの LCA でカウントされることを示しています。 

### 例 2

 中心にある星`1`葉っぱ付き`2,3,4,5`。 

| ノード | dp 状態 | 新しい道 |
 | --- | --- | --- |
 | 葉 | [各1] | 0 |
 | ルート | [4] | ペアは長さ 2 のパスに結合されます。 

これは、すべての有効なパスが中心を通過する必要があり、マージ中にすべての組み合わせが 1 回だけカウントされることを示しています。

 ## 特殊なケース

 チェーン状のツリーでは、すべての有効なパスが連続したセグメントにまたがっており、その中間点で正確に 1 回カウントされる必要があるため、正確性が強調されます。 このアルゴリズムは、エンドポイントのペアが最も低い共通の祖先でのみ形成されるようにして、上位のマージ間での重複を防ぐことでこれに対処します。 

星型ツリーは、サブツリー間のペアリングが正しく処理されるかどうかをテストします。 すべての有効なパスは中心を通過する必要があるため、子コントリビューションをルートでマージするときにリーフのすべての組み合わせが 1 回だけ考慮され、予想される組み合わせ構造と一致します。
