 ## 解決策
 ## 問題の理解

 一連のコンテストがあり、それぞれが特定の日に関連付けられており、各コンテストには難易度があります。 ドレミーは初期 IQ から始まります`q`、これはコンテストに対処する彼女の能力を表しています。 毎日、彼女はコンテストに挑戦するかスキップするかを選択できます。 彼女がコンテストに挑戦し、その難易度が現在の IQ よりも高かった場合、彼女の IQ は 1 減少します。 それ以外の場合は、変更されないままになります。 IQ がゼロの場合、コンテストに挑戦することはできません。 

入力は複数のテスト ケースを提供します。 各テスト ケースでは、コンテストの数、ドレミーの開始 IQ、およびコンテストの難易度のリストを指定します。 出力は、ドレミーが IQ を 0 未満にせずにテストできる合計数を最大化するためにどのコンテストを試行するかを表すバイナリ文字列でなければなりません。 

制約は、以下まで処理する必要があることを意味します。`10^5`すべてのテスト ケースの合計コンテスト数。 テスト ケースごとに O(n log n) のアルゴリズムは許容されますが、O(n^2) では遅すぎます。 IQは最大まで上がるので、`10^9`、考えられる各 IQ 値を明示的にシミュレートすることはできません。 

明らかではないエッジケースには、簡単なコンテストの前にいくつかの難しいコンテストが現れるシーケンスが含まれます。 たとえば、次の場合`q=2`そしてコンテストは`[5,1,1]`、左から右へ貪欲にコンテストを試みる単純なアプローチは、`5`まず、IQを下げる`1`、次に選択します`1`そして`1`、それは問題ありません。 しかし、もし`q=1`そしてコンテストは`[2,1,1]`、最初のコンテストを選択すると、IQ が低下します。`0`、その後のより簡単なコンテストのテストを妨げます。 これは、難易度が以下のコンテストに安全に挑戦できることを示しています。`q`あるいは、IQ がしきい値に低下するまで、難しいコンテストを戦略的に遅らせます。 

## アプローチ

 強引なアプローチにより、ドレミーの選択が日々シミュレートされます。 コンテストごとに、IQ が 0 より大きいかどうかを確認します。 その場合は、コンテストをテストし、難易度が現在の IQ を超えている場合は、IQ を下げます。 それ以外の場合はスキップします。 これはテスト ケースごとに O(n) で機能し、制約を考慮すると、実際には許容可能です。 コンテストのテストは「日」の制限を順に行うため、単純なアプローチは正しいです。 IQを適切に追跡せずに、貪欲にテストを最大化しようとした場合にのみ失敗します。 

最適なアプローチを実現するための重要な洞察は、IQ を脅かす唯一のコンテストは、難易度が開始時の IQ を超えるコンテストであることを認識することです。 以下の難易度のコンテスト`q`いつでもテストできます。 以上の難易度のコンテストの場合`q`, ドレミーは、IQ がまだ陽性である場合にのみテストできます。 コンテストが難しすぎると IQ が 1 だけ減少するため、しきい値の観点から考えることができます。残りのコンテストがすべてしきい値以下になるレベルに IQ が到達すると、すべてのコンテストに安全に挑戦できます。 

したがって、最後から逆方向に繰り返すことができます。 各コンテストの難易度が現在の IQ 以下である場合は、テスト可能としてマークします。 それ以外の場合、IQ が正の場合は、テスト可能としてマークし、IQ を減分します。 IQ がゼロの場合は、テスト不可能とマークします。 逆方向に反復することで、早い段階で簡単なコンテストで IQ を無駄にせず、テストされるコンテストの数を最大化することができます。

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る`t`。 
2. 各テスト ケースについて、次の内容を読んでください。`n`そして`q`、コンテストのさまざまな難易度`a`。 
3. 回答配列を初期化する`ans`長さの`n`すべてゼロで。 
4. コンテストを逆の順序で繰り返します (最終日から最初の日まで)。 

1. コンテストの難易度の場合`a[i]`現在のIQ以下である`q`、 セット`ans[i] = 1`。 
2. それ以外の場合、IQ の場合`q`は正、設定されています`ans[i] = 1`そしてIQを1つ減らします。 
3. それ以外の場合は、その場を離れてください`ans[i] = 0`。 
5. すべてのコンテストを処理した後、以下に対応するバイナリ文字列を出力します。`ans`。 

機能する理由: アルゴリズムは、あらゆる位置で次の不変条件を維持します。`i`、残りの IQ は左側のコンテストで最大化されます。 逆方向に反復することで、IQ がなくなった場合にスキップするコンテストのテストを優先し、難しいコンテストが簡単なコンテストを不必要にブロックしないようにします。 これにより、テストされるコンテストの最大数が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, q = map(int, input().split())
        a = list(map(int, input().split()))
        ans = [0] * n
        for i in reversed(range(n)):
            if a[i] <= q:
                ans[i] = 1
            elif q > 0:
                ans[i] = 1
                q -= 1
        print("".join(map(str, ans)))

if __name__ == "__main__":
    solve()
```このソリューションは、まず高速 I/O を使用して入力を読み取ります。 回答配列を作成し、それを最後から最初まで埋めていき、コンテストが IQ の範囲内にあるかどうか、またはテストによって IQ が低下するかどうかをチェックします。 コンテストの数を最大化するには、後方反復が不可欠です。 IQ がゼロであるなどのエッジ条件は、条件チェックによって自然に処理されます。

 入力を考慮してください:```

| 1 | 1 | 0 | 1 | 1<=0? いいえ、q=0、0 をスキップします。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out
    solve()
    return out.getvalue().strip()

# Provided samples
assert run("5\n1 1\n1\n2 1\n1 2\n3 1\n1 2 1\n4 2\n1 4 3 1\n5 2\n5 1 2 4 3\n") == "\n".join(["1","11","110","1110","01111"]), "sample 1"

# Custom cases

assert run("1\n1 1\n2\n") == "1", "Single contest harder than IQ, decrement"
