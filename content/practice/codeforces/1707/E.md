 ## 解決策
 ## 問題の理解

 整数の配列が与えられます`a`長さの`n`、各要素は 1 ～`n`。 概念的には、これらを一列に配置されたラベル付きタイルとして想像してください。 連続したセグメントに対する「置換」操作を定義します。`(l, r)`: セグメントをペアに折りたたみます。`(min value in the segment, max value in the segment)`。 この操作を繰り返し適用できます。各ステップで現在のマップがマッピングされます。`(l, r)`その範囲によって定義される部分配列の最小値と最大値。 

クエリは次のことを尋ねます: 指定されたものから開始する`(l, r)`、何人の交代要員に達する必要があるか`(1, n)`? それが不可能な場合、つまり、一連の交換が完全にカバーできないサイクルに入ります。`[1, n]`- 私たちは戻ります`-1`。 

制約が教えてくれる`n`そして`q`それぞれ最大 100,000 になる可能性があるため、各クエリのサブ配列に対する単純な反復では遅すぎます。 置換のたびにサブ配列をスキャンして最小値と最大値を再計算する素朴な解決策を考えると、最悪の場合の操作数はおよそ次のようになります。`O(n * q)`クエリごとに複数の置換が必要な場合はさらに高くなります。 これなら届くだろう`10^10`2秒の制限時間をはるかに超えた操作。 スキャンの繰り返しを減らす、よりスマートなアプローチが必要です。 

微妙なエッジケースは、交換が無期限に繰り返される場合です。 たとえば、配列`[2, 1]`クエリ付き`(1, 1)`生成する`(2, 2) → (1, 1) → (2, 2)`永遠に。 最終的には収束することを前提とした不用意な解決策`(1, n)`の代わりに誤って数値を返します`-1`。 開始セグメントがすでに開始されている場合、別のエッジケースが発生します。`(1, n)`; 答えはこうあるべきです`0`。 

## アプローチ

 ブルートフォースアプローチは簡単です。 クエリごとに`(l, r)`、最小値と最大値を繰り返し計算します。`a[l..r]`到達するまで`(1, n)`またはループを検出します。 これは、説明されているプロセスを正確にシミュレートするため正しいですが、遅すぎます。 ステップ数は次のとおりです。`O(n)`クエリごとに最小値と最大値を単純に計算することもできます。`O(n)`、降伏`O(n^2 * q)`操作。 のために`n, q = 10^5`、これは明らかに実行不可能です。 

重要な点は、置換操作ではセグメントが拡張されるだけであるということです。最小値は減少するか同じままであり、最大値は増加するか同じままであるだけです。 この単調な特性は、プロセスが事前に予測できることを示唆しています。 配列を前処理して、ある構造からジャンプできるようにすることができます。`(l, r)`次へ`(l', r')`で`O(1)`または`O(log n)`時間。 具体的には、どのような場合でも、`x`で`[1, n]`、最初と最後の出現`x`達成したい場合に最終的にカバーする必要があるセグメントを定義する`(1, n)`。 連続する番号に対応する重複するセグメントを繰り返しマージすることで、クエリごとに配列をスキャンすることなく、最小の置換数を計算できます。 

その結果、区間拡張とバイナリ リフティングを組み合わせたアプローチが得られます。 まず、各ポジションについて、1 回の交換で到達できる最大間隔を前処理します。 次に、クエリごとに、倍増テーブルを使用してジャンプを繰り返し適用して、`(1, n)`効率的に。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2 * q) | お(1) | 遅すぎる |
 | 最適 (間隔マージ + ダブリング) | O(n log n + q log n) | O(n log n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 以下の各値の最初と最後の出現を事前計算します。`1`に`n`。 させて`first[x]`そして`last[x]`最初と最後のインデックスを示します。`a[i] = x`。 これにより、値のすべての出現をカバーする最小セグメントがわかります。 
2. 初期展開を計算する`b[i]`インデックスごとに`i`。`b[i]`から開始して到達できる最も右のインデックスです。`[i, i]`1回の交換で。 初期化する`b[i] = i`。 値を反復処理する`1..n`順番に、値ごとに展開します。`b[i]`みんなのために`i`セグメント内で最小値と最大値の間隔をカバーします。 このステップの後、`b[i]`から 1 ステップで到達可能な最大セグメントを表します。`[i, i]`。 
3. 倍増表を作成します。 させて`jump[k][i]`から到達可能な最も右のインデックスになります`i`使用して`2^k`交換品。 繰り返しを使用してこのテーブルにデータを入力します`jump[k][i] = jump[k-1][jump[k-1][i]]`。 これにより、次のようなクエリに答えることができます。`O(log n)`by jumping powers of two.
 4. 各クエリについて`(l, r)`、まず次のことを確認してください。`(l, r)`すでにカバーしています`(1, n)`。 だったら返して`0`。 それ以外の場合は展開します`(l, r)`倍加表を使用: 2 の最大累乗から開始し、それが超えないときはいつでもジャンプします。`n`。 やっぱりジャンプしてたどり着くなら`n`そしてカバー`1`左側では、ジャンプの数を返します。 それ以外の場合は戻ります`-1`。 

機能する理由: 2 倍化テーブルにより、同じセグメントの最小値と最大値を繰り返し再計算することがなくなります。 事前に計算された最大リーチは、置換操作を 1 つだけキャプチャします。 セグメント拡張の単調な特性により、適用を繰り返しても間隔が決して短縮されないことが保証されるため、この手順では最小限のステップ数を見逃すことはありません。 サイクルは暗黙的に処理されます: 到達できない場合`(1, n)`、ジャンプ テーブルは最終的にセグメントの拡張に失敗し、`-1`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))
    
    first = [n] * (n + 1)
    last = [-1] * (n + 1)
    for i, val in enumerate(a):
        first[val] = min(first[val], i)
        last[val] = max(last[val], i)
    
    b = list(range(n))
    i = 0
    while i < n:
        r = i
        j = i
        while j <= r:
            val = a[j]
            r = max(r, last[val])
            j += 1
        for k in range(i, r + 1):
            b[k] = r
        i = r + 1

    LOG = 20
    jump = [b]
    for k in range(1, LOG):
        nxt = [0] * n
        for i in range(n):
            nxt[i] = jump[k-1][jump[k-1][i]]
        jump.append(nxt)

    for _ in range(q):
        l, r = map(int, input().split())
        l -= 1
        r -= 1
        if l == 0 and r == n - 1:
            print(0)
            continue
        if b[l] < r:
            print(-1)
            continue
        ans = 0
        cur_l = l
        cur_r = r
        for k in reversed(range(LOG)):
            nxt_r = jump[k][cur_l]
            if nxt_r < n - 1:
                cur_l = nxt_r + 1
                ans += 1 << k
        if cur_l <= 0 and jump[0][cur_l] >= n - 1:
            ans += 1
            print(ans)
        else:
            print(-1)

if __name__ == "__main__":
    solve()
```最初のセクションでは、最初と最後の出現を計算します。 2番目は計算します`b[i]`セグメント拡張を使用します。 次に、高速ジャンプ用の倍増表を準備します。 クエリでは、初期カバレッジ、無効なセグメントをチェックし、ジャンプを繰り返します。 Off-by-one エラーは重大です。Python リストのインデックスは 0 ベースに変換され、セグメント境界は展開に含める必要があります。
