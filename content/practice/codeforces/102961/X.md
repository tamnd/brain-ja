 ## 解決策
 ## 問題の理解

 一連の数値と目標値が与えられます。 このタスクは、合計がターゲットに等しい 3 つの異なる要素がシーケンス内に存在するかどうかを判断し、存在する場合は元の配列内のそれらの位置を返すことです。 

重要な点は、値を単独で選択しているのではなく、インデックスを選択しているということです。そのため、同じ数値が複数回出現する場合でも、トリプルを形成するときに異なる出現を参照していることを確認する必要があります。 通常、出力は有効なインデックスのトリプルであり、必ずしもすべての可能性や存在を超えた最適な組み合わせである必要はありません。 

この従来の設定の制約では、通常、最大約 2×10^5 の要素が許可されます。 これにより、すべてのトリプルにわたる 3 次および 2 次スキャンが即座に除外されます。 3 次 O(n^3) 列挙はすべてのトリプルを明示的にチェックし、最悪の場合には 10^15 回程度の演算を実行しますが、これは実行可能な制限をはるかに超えています。 O(n^2) であってもタイトになる可能性がありますが、ソート後に注意深く 2 ポインター構造を使用することで実行可能になります。 

重複した値が存在し、素朴な解決策がインデックスの代わりに値を扱う場合、微妙な失敗例が発生します。 たとえば、配列がターゲット 9 の [3, 3, 3, 4] である場合、正しい答えは値 3 の 3 つの異なるインデックスです。重複を折りたたむ値ベースのアプローチでは、3 が 1 つだけ存在すると誤って考えられ、インデックス付けされた意味では有効であっても、解を見つけることができない可能性があります。 

もう 1 つのエッジ ケースは、配列が小さい場合 (たとえば、n = 3) です。この場合、どのソリューションでも可能な唯一のトリプルを直接検証する必要があり、慎重な境界処理を行わずに並べ替えや 2 ポインターの移動を前提とするアルゴリズムでは、有効な答えが簡単にスキップされる可能性があります。 

## アプローチ

 ブルートフォースのアイデアは簡単です。インデックス i、j、k のすべてのトリプルを試し、それらの値の合計がターゲットに達するかどうかを確認します。 これが機能するのは、すべての可能性を徹底的に列挙し、有効な組み合わせを決して見逃さないためです。 ただし、n 個の要素の場合、約 n 個の 3 つのチェックを選択する必要があり、これは O(n^3) として増加します。 n が約 10^5 の場合、これは計算上不可能になります。 

最初に 1 つのインデックスを固定し、次に必要な合計を満たすさらに 2 つの値を検索することで、冗長性を減らすことができます。 1 つの要素が修正されると、問題は残りの配列で合計が既知の値になる 2 つの数値を見つけることになります。 この部分問題は古典的な 2 合計問題であり、ソートされた配列と 2 ポインター スキャンを使用して効率的に解決できます。 

重要な観察は、元の位置を引き継いだ場合、ソートによってインデックスを回復する能力が損なわれないということです。 並べ替え後、現在の合計が小さすぎるか大きすぎるかに基づいて、2 つのポインターを内側に移動できます。 これにより、内部検索が固定要素ごとの線形スキャンから線形 2 ポインター スキャンに削減されます。 

ブルート フォースはすべてのトリプルを列挙するため機能しますが、同じ部分和を何度も繰り返すため、n が大きくなると失敗します。 ソート後、2 和を線形時間で解くことができるという観察により、全体的な複雑さが 3 次から 2 次に軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^3) | お(1) | 遅すぎる |
 | 固定 + 2 ポインター | O(n^2) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 最初に配列をソートしますが、出力には元の順序での位置が必要なため、元のインデックスを追跡します。

1. 各値を元のインデックスと組み合わせて、値で並べ替えます。 これにより、後で正しいインデックスをレポートしながら、順序付けロジックを適用できるようになります。 
2. 各位置 i をトリプルの固定の最初の要素として扱い、配列を反復処理します。 目標は、合計がターゲットから固定値を引いたサフィックス内の 2 つの要素を見つけることです。 
3. 固定 i ごとに、2 つのポインターを初期化します。1 つは i+1 に、もう 1 つは配列の最後にあります。 これらは、候補となる 2 番目と 3 番目の要素を表します。 
4. i、左ポインタ、および右ポインタの値の合計を計算します。 この合計がターゲットと一致する場合、有効なトリプルが見つかったことになり、元のインデックスを出力できます。 
5. 合計が小さすぎる場合は、左ポインタを右に移動して合計を増やします。 合計が大きすぎる場合は、右ポインタを左に移動して合計を減らします。 
6. ポインタが交差するか、有効なトリプルが見つかるまで繰り返します。 

これが機能する理由: ソート後の配列は単調な構造になります。 固定要素の場合、任意のペアの合計は、ポインターの動きに関して予測どおりに動作します。 左のポインタを移動すると残りの範囲の合計が増加し、右のポインタを移動すると減少します。 これにより、すべての調整により、実行可能な候補をすべて保持しながら、有効な解を含めることができない範囲が厳密に削除されるため、有効なペアがスキップされないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, x = map(int, input().split())
    arr = list(map(int, input().split()))
    
    a = [(arr[i], i + 1) for i in range(n)]
    a.sort()
    
    for i in range(n):
        target = x - a[i][0]
        l, r = i + 1, n - 1
        
        while l < r:
            s = a[l][0] + a[r][0]
            if s == target:
                print(a[i][1], a[l][1], a[r][1])
                return
            if s < target:
                l += 1
            else:
                r -= 1
    
    print("IMPOSSIBLE")

if __name__ == "__main__":
    solve()
```コア構造は懸念事項をきれいに分離します。 ソートのステップでは、元の位置を見失うことがないようにインデックスを付けます。 外側のループは 1 つの要素を固定し、内側の 2 ポインター ループは相補的なペアの制約付き検索を実行します。 

よくある実装の落とし穴は、ソート後にインデックスが元の位置に対応しなくなることを忘れることです。 もう 1 つの微妙な問題は、ポインターの初期化です。同じ要素の再利用を避けるために、両方のポインターは厳密に固定インデックスの後に開始する必要があります。 最後に、複数の解決策が存在する可能性がありますが、必要なのは 1 つだけであるため、有効なトリプルが見つかった場合は直ちに終了する必要があります。 

## 実用的な例

 n = 5、x = 10、配列が [2, 3, 7, 5, 1] である入力を考えてみましょう。 インデックスと組み合わせて並べ替えると、値で順序付けされた構造が得られます。 

実行を追跡します。 

| i (固定) | l | r | 考慮される値 | 合計 | アクション |
 | --- | --- | --- | --- | --- | --- |
 | 0 | 1 | 4 | 1 + 2 + 3 (概念的) | 小さすぎる | lを移動 |
 | 0 | 2 | 4 | 次のペア | 一致する | 戻る |

 このトレースは、合計が不十分な場合に最小辺を拡張することによってアルゴリズムがどのように迅速に収束するかを示しています。 

ここで、重複がある場合を考えてみましょう: n = 4、x = 9、配列 [3, 3, 3, 4]。 ソート後、アルゴリズムは 3 を 1 つ固定し、残りの要素を検索します。 2 ポインター スキャンではさらに 2 つの 3 が選択され、個別のインデックスの有効なトリプルが生成されます。 

| i (固定) | l | r | 値 | 合計 | アクション |
 | --- | --- | --- | --- | --- | --- |
 | 0 | 1 | 3 | 3 + 3 + 3 | 9 | 見つかりました |

 これにより、ソリューションに重複が必要な場合でも正確さが確認されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n^2) | 各固定要素は、残りのサフィックスに対する線形 2 ポインタ スキャンをトリガーします。 
| スペース | O(n) | 値とインデックスのペアのストレージ |

 二次計算量は、早期終了を使用して Python または C++ で効率的に実装された場合、約 2×10^5 までの一般的な制約では許容されます。

 ## 特殊なケース

 重要なエッジ ケースは、有効なソリューションで繰り返し値が使用される場合です。 入力 n = 4、x = 9、配列 [3, 3, 3, 4] の場合、アルゴリズムは [(3,1), (3,2), (3,3), (4,4)] にソートします。 最初の要素 (3,1) を固定すると、2 ポインター検索が接尾辞に対して実行されます。 ポインタは最終的に (3,2) と (3,3) を選択し、正しい出力を生成します。 ここでの不変条件は、各要素が元の位置を保持するため、ソートを通じて個別のインデックスが保持されることです。 

解決策が存在しない場合には、別の特殊なケースが発生します。 n = 4、x = 100、配列 [1、2、3、4] の場合、ポインターはターゲットの合計に一致することなく、すべての組み合わせを使い果たします。 外側のループは早期終了することなく完了し、アルゴリズムは「IMPOSSIBLE」を正しく出力します。
