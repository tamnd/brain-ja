 ## 解決策
 ## 問題の理解

 数直線上に区間の集合が与えられ、各区間は左端と右端を持つセグメントを表します。 すべての間隔について、ネストの観点から他のすべての間隔に対する相対的な位置を理解する必要があります。 

2 つの間隔は、一方がもう一方の内側に完全に収まる場合、厳密な封じ込めの意味で関連付けることができます。 各間隔について、その間隔が完全に含まれる他の間隔の数と、その間隔に完全に含まれる他の間隔の数を数えなければなりません。 

それで、しばらくの間$[l_i, r_i]$, 事実上、2 つの量を数えていることになります。 1 つは間隔の数です$[l_j, r_j]$そのような$l_j \le l_i$そして$r_i \le r_j$。 もう 1 つは、次のような間隔の数です。$l_i \le l_j$そして$r_j \le r_i$。 

入力は、そのような間隔のリストで構成されます。 出力は 2 つの長さの配列です$n$、入力順序に合わせて配置され、各位置がこれら 2 つのカウントを報告します。 

素朴な解釈では、間隔のすべてのペアを直接比較することが示唆されます。 あたりまでで$10^5$間隔、それはすぐに大まかなことを意味します$10^{10}$最悪の場合の比較は、2 秒の制限で処理できる範囲をはるかに超えています。 すべてのペアを明示的に検査するソリューションは失敗します。 

間隔がエンドポイントを共有する場合、微妙な問題が発生します。 たとえば、2 つの同一の間隔$[1, 5]$そして$[1, 5]$非厳密な不等式の定義に従って、両方向で相互に含まれるものとしてカウントされる必要があります。 このような場合、不注意に厳密に比較すると過小評価されてしまいます。 別の失敗例は、慎重なタイ処理を行わずに 1 つのエンドポイントのみで並べ替えが行われた場合に発生します。これにより、左側のエンドポイントが等しい間隔が、プレフィックス情報を破損する順序で処理される可能性があります。 

## アプローチ

 ブルートフォース手法では、間隔のすべてのペアをチェックし、一方にもう一方が含まれているかどうかを直接テストします。 この定義は純粋にペアごとであり、グローバル構造を必要としないため、これは正しいです。 各間隔について、他のすべての間隔をスキャンし、エンドポイントに基づいて 2 つの比較を実行します。 これはおおよそ次のことにつながります$n^2$一定時間ごとの間隔比較。 

いつ$n$に成長する$10^5$、比較の数が次の値に達しました$10^{10}$これは、通常許容される時間制限には大きすぎます。$10^8$簡単な操作。 ボトルネックは比較ごとの計算ではなく、比較の膨大な数です。 

重要な観察は、間隔間の封じ込めが 2 次元の支配関係における点を数えることに還元できるということです。 それぞれの間隔がポイントになります$(l, r)$、そして両方の座標上の不等式によって定義される領域にいくつの点があるかを数える必要があります。 これはまさに、一方の次元での並べ替えともう一方の次元でのプレフィックス集計で処理できる種類の構造です。 

1 つのエンドポイントによって間隔が並べ替えられると、これまでに確認した適切なエンドポイントの数を追跡するデータ構造を維持できます。 圧縮された右端点上のフェンウィック ツリーを使用すると、条件を満たす間隔の数を数えることができます。$r$対数時間で。 ソート順序を慎重に選択することで、両方の包含方向をこの構造に対する接頭辞または接尾辞のクエリに変換できます。

 ## アルゴリズムのチュートリアル

 同じ基礎となるメカニズムを使用して、2 つのカウントを別々に解決します。 

1. まず、結果を入力順に書き戻せるように、各間隔を元のインデックスとともに保存します。 これは、処理中に間隔を並べ替えるために必要です。 
2. すべての右端点を密な範囲に圧縮します。 これにより、生の値ではなくランクによってインデックス付けされたフェンウィック ツリーを使用できるようになり、メモリと更新の効率が維持されます。 
3. 特定の間隔を含む間隔の数を計算するには、左端点を増加させることによって間隔を並べ替え、右端点を減らすことによって左端点が等しい場合は並べ替えます。 この順序付けにより、間隔を処理するときに、それを含む可能性があり、左側の境界が小さいか等しいすべての間隔が、重複に関して一貫した方法ですでに考慮されることが保証されます。 
4. ソートされたリストを調べて、各正しいエンドポイントとの間隔の数を記録するフェンウィック ツリーを維持します。 現在の間隔については$(l, r)$、少なくとも正しい終点を持つ以前に確認された間隔が何個あるかを数える必要があります。$r$。 これは、フェンウィック ツリーのサフィックス合計クエリに対応します。 
5. 間隔を処理した後、その右のエンドポイントをフェンウィック ツリーに挿入し、今後のクエリで使用できるようにします。 
6. 指定された間隔に含まれる間隔の数を計算するには、対称プロセスを繰り返します。 左端点を減少させることによって間隔を並べ替え、右端点を増やすことによって左端点が等しい場合は並べ替えます。 
7. 再びフェンウィック ツリーを使用して、この順序でスイープします。 さて、各インターバルについて$(l, r)$、以前に確認された間隔のうち、最大で正しい終点がいくつあるかを数えます。$r$、これはプレフィックス合計クエリです。 
8. 両方の結果を別々に保存し、最後に保存したインデックスを使用して元の順序で出力します。 

なぜそれが機能するかは、包含を 2D 平面における支配関係として解釈することに由来します。 1 つの座標で並べ替えると、処理順序によって不等式の半分が自動的に適用されます。 フェンウィック ツリーは 2 番目の座標を維持するため、各クエリはプレフィックスまたはサフィックスに関する 1 次元の計数問題になります。 並べ替えタイブレークにより、同一のエンドポイントを持つ間隔が誤って二重カウントされたりスキップされたりしないことが保証され、縮退した場合でも正確さが維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

def solve():
    n = int(input())
    intervals = []
    rvals = []

    for i in range(n):
        l, r = map(int, input().split())
        intervals.append((l, r, i))
        rvals.append(r)

    rvals = sorted(set(rvals))
    comp = {v: i + 1 for i, v in enumerate(rvals)}

    arr = [(l, r, i, comp[r]) for (l, r, i) in intervals]

    contains = [0] * n
    contained_by = [0] * n

    arr1 = sorted(arr, key=lambda x: (x[0], -x[1]))
    bit = Fenwick(len(rvals))

    for l, r, idx, cr in arr1:
        contained_by[idx] = bit.sum(len(rvals)) - bit.sum(cr - 1)
        bit.add(cr, 1)

    arr2 = sorted(arr, key=lambda x: (-x[0], x[1]))
    bit = Fenwick(len(rvals))

    for l, r, idx, cr in arr2:
        contains[idx] = bit.sum(cr)
        bit.add(cr, 1)

    print(*contains)
    print(*contained_by)

if __name__ == "__main__":
    solve()
```ソリューションは 2 つのスイープに分割され、それぞれが 1 方向の封じ込めを処理します。 フェンウィック ツリーは、処理された右エンドポイントの数を維持するために使用されます。 サフィックス クエリは合計マイナス プレフィックスを使用して実装されますが、プレフィックス クエリは直接使用されます。 

並べ替え順序は正確さの重要な部分です。 最初のスイープでは、「少なくともどこまでの間隔が終了するか」をクエリするときに、有効な左端点を持つすべての候補がすでに構造内にあることが保証されます。 2 番目のスイープではロジックが逆になり、「私より遅くまでに何人が終了するか」が処理済みセット内で有効になります。 

座標圧縮には注意が必要です。 圧縮を行わないと、フェンウィック ツリーは潜在的に大きな座標値を処理する必要があり、メモリ内で実行できなくなります。

 ## 特殊なケース

 等間隔の場合$[1, 2]$何度も繰り返されるため、アルゴリズムはソートのタイブレーク ルールに依存して、安定した順序で処理されるようにします。 最初のスイープ中、各間隔は以前に処理されたすべての同一間隔を有効なコンテナとして認識し、以前の重複の数と一致する増加するカウントを生成します。 

次のような完全にばらばらな間隔の場合$[1,2], [3,4], [5,6]$、フェンウィック ツリーは、優勢条件を満たすような方法で重複する右端点を蓄積することはありません。 いずれの方向においても両方の座標制約を同時に満たす区間はないため、各クエリは正しくゼロを返します。 

次のような完全にネストされたチェーンの場合$[1,10], [2,9], [3,8], [4,7]$、最初のスイープは、各内側の間隔がすべての外側の間隔を有効なコンテナーとして認識する構造を構築し、2 番目のスイープはこの関係を逆転させ、理論的なネス​​トの深さに一致する対称的な減少パターンを生成します。
