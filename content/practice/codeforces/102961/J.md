 ## 解決策
 ## 問題の理解

 コインの値として解釈できる正の整数のコレクションが与えられます。 各値は最大 1 回使用でき、これらのコインのサブセットを選択することで、異なる合計を形成できます。 タスクは、指定されたコインのサブセットを使用して形成できない最小の正の整数を決定することです。 

入力は単にコインの価値のリストです。 出力は、ゼロから始まる達成可能な合計の最初の「ギャップ」を表す単一の整数です。空のサブセットが常にゼロを形成するため、ゼロ自体は無視されます。 

主な問題は、サブセットの数がコインの数に応じて指数関数的に増加するため、配列が小さいサイズを超えて大きくなると、合計を直接推論することが不可能になることです。 最大約 10^5 のコインがある場合、サブセットを列挙したり、合計に対して動的プログラミングを実行したりするアプローチは、状態空間が実用的な制限を超えて爆発するため、時間制限を超えてしまいます。 

単純なアプローチでは、すべてのサブセットの合計を生成し、欠落している最小の整数を検索しようとします。 これは、入力サイズが中程度の場合でも失敗します。 たとえば、コインが`[1, 2, 3, 10]`、サブセット合計は多くの値をカバーしますが、それらを明示的に構築するには、すでに最大 2^n の組み合わせを追跡する必要があります。 

最小のコインが 1 より大きい場合、より微妙な失敗ケースが発生します。たとえば、次のように入力します。`[5, 7]`には 1 を形成する方法がないため、答えはすぐに 1 になります。最初にこの境界を確認せずに合計の計算を開始する方法では、無関係な組み合わせを探索する無駄な計算が行われます。 

もう 1 つの重要なエッジ ケースは、コインが連続またはほぼ連続している場合です。 のために`[1, 2, 3]`、6 までのすべての数値が到達可能であり、欠損値は 7 になります。正しい解決策は、個々のコインの貢献だけでなく、その中間構造を認識する必要があります。 

## アプローチ

 ブルート フォースの観点は定義から始まります。すべてのサブセットの合計を計算し、値が欠落するまで 1 から上方向にスキャンします。 これは、達成可能なすべての構成を網羅的に表しているため、正しいです。 ただし、コインが追加されるたびにサブセットの数は 2 倍になり、およそ 2^n 個の状態になります。 n が 25 または 30 を超えると、これらの合計を保存することさえ不可能になります。 

この画期的な進歩は、達成可能なすべての金額を実際に知る必要はないということを認識することから生まれます。 私たちが気にするのは、1 からある境界までのすべての値が継続的に達成可能かどうかだけです。 のすべての値がすでにわかっている場合は、`[1, x]`到達可能であれば、価値のある新しいコインが得られます`v`ギャップが生じない場合にのみ、この範囲を拡張できます。 具体的には、`v`せいぜい`x + 1`、次に欠落しているセグメントを埋めて、到達可能性を拡張できます。`x + v`。 そうしないと、次の部分に隙間が生じます。`x + 1`すぐに。 

これにより、問題はサブセットの列挙から、ソートされたコインに対する貪欲なスイープへと変わります。 各コインは、連続的に到達可能なプレフィックスを拡張するか、最初の到達不能な整数を明らかにします。

 ## アルゴリズムのチュートリアル

 1. コインを昇順に並べ替えます。 ソートにより、利用可能な最小の内線番号が常に最初に考慮されるようになります。これは、継続的な到達可能な範囲を維持するために不可欠です。 
2. 変数を初期化する`reach = 0`、範囲内のすべての合計を表します`[1, reach]`現在は達成可能です。 最初は、合計 0 のみが達成可能であるため、拡張されない限り、最初に欠落している正の整数は 1 になります。 
3. 並べ替えたコインを 1 つずつ繰り返します。 コインの価値ごとに`v`と比較してください`reach + 1`。 
4. もし`v`より大きい`reach + 1`、すぐにやめてください。 これは、ギャップがあることを意味します`reach + 1`残りのコインはすべてさらに大きいため、残りのコインをどの組み合わせでも埋めることはできません。 
5. それ以外の場合、`v`せいぜい`reach + 1`、 アップデート`reach`に`reach + v`。 これが機能するのは、以下のすべての値が`reach`以前は達成可能でしたが、追加`v`までのすべての値を許可します`reach + v`このコインを含めるか除外することによって形成されます。 
6. すべてのコインを処理するか、途中で停止した後、答えは次のとおりです。`reach + 1`。 

### なぜ効果があるのか

 このアルゴリズムは、すべての整数が含まれるという不変条件を維持します。`[1, reach]`処理されたコインのサブセットを使用して形成できます。 ソートにより、この間隔を延長できる最小のコインが常に考慮されることが保証されます。 コインが超過した場合`reach + 1`、すべての将来の値はさらに大きいため、後のコインの組み合わせはギャップを埋めることができないため、最初の到達不可能な整数は固定されます。 それ以外の場合、到達可能な間隔は中断することなく拡張され、連続性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    arr = list(map(int, input().split()))
    
    arr.sort()
    
    reach = 0
    
    for v in arr:
        if v > reach + 1:
            break
        reach += v
    
    print(reach + 1)

if __name__ == "__main__":
    solve()
```この解決策は、リストを読み取り、常にコインを昇順で処理できるように並べ替えることから始まります。 変数`reach`ゼロから開始して達成可能な最大連続合計を追跡します。 各コインはこの範囲に吸収されるか、不連続性を引き起こします。 

重要な実装の詳細は条件です。`v > reach + 1`。 Off-by-one エラーは通常、次の場所で発生します。`>=`コインが次のギャップを正確に埋めた場合でも、誤って壊れてしまいます。

## 特殊なケース

 最小のコインが 1 より大きい場合、重要なエッジ ケースが発生します。入力の場合`[5, 7, 9]`、ソートによって順序は変更されず、最初のコインはすでにルールに違反しています。`reach + 1`状態。 アルゴリズムは直ちに停止し、1 を返し、正の和を形成できないことを正しく識別します。 

コインが最初は密集しているが、後でまばらになる場合には、別のケースが発生します。 のために`[1, 2, 3, 4, 10, 11]`、到達可能なプレフィックスは 10 までスムーズに増加します。その後、最初のブレークが存在しない場合は 5 ですでに発生しているため、11 のギャップは無関係になります。 ここでは、早期にブレークが発生しないため、最終的な答えは、完全に密なプレフィックスの後の最初の大きなギャップによって決まります。
