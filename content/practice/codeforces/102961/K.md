 ## 解決策
 ## 問題の理解

 個別の数値の順列のような配置を表す整数のシーケンスが与えられます。 このタスクは、すべての数値を昇順に処理するのに何回「ラウンド」が必要かを決定することです。各ラウンドは、シーケンスを左から右にスキャンし、次に必要な順序の位置に数字が現れるたびに数字を取り出すことで構成されます。 

より具体的に考えると、値 1 から n を順番に読み取りたいのですが、配列を左から右に繰り返し走査する必要があるということです。 トラバースするたびに、配列内を逆行することなく、次の順序の値をできるだけ多く選択します。 現在のパスを続行できなくなったら、新しいパスを開始します。 

入力では、n の後に、1 から n までの各整数を 1 回だけ含む長さ n の配列が与えられます。 出力は単一の整数で、シーケンスを昇順に消費するために必要な左から右への完全なパスの数です。 

制約構造は、n が大きくなる可能性があることを意味しており、Codeforces スタイルの問題では通常最大 200,000 または同様の値になります。 これにより、アレイ上の完全なパスを繰り返しシミュレートするアプローチは即座に除外されます。 配列を数値ごとに 1 回スキャンする単純なシミュレーションは、最悪の場合 O(n²) のように動作し、遅すぎます。 

配列がすでにソートされている場合、微妙なエッジケースが発生します。 その場合、すべてが 1 回のパスで消費されます。 逆の極端は逆ソートされた配列です。この配列では、次に必要なすべての数値が前の数値よりも配列内で前に現れるため、各要素が新しいパスを強制します。 

たとえば、n = 5 で配列が [5, 4, 3, 2, 1] の場合、完全なパスが完了するまで 1 を選択することはできないため、すべての数値に独自のパスが必要となり、出力 5 が得られます。単純なパスごとのスキャン手法では、パス間の状態を慎重にリセットしないと、誤って進行状況を誤って再計算する可能性があります。 

## アプローチ

 この強引なアイデアは、文字通りプロセスをシミュレートすることです。 選択しようとしている現在のターゲット値を 1 から維持します。配列を左から右に繰り返しスキャンします。 現在のターゲットに遭遇するたびに、ターゲットをインクリメントします。 配列の最後に到達したら、パスを 1 つカウントし、すべての数値が消費されるまでスキャンを再開します。 

これが機能するのは、プロセスの定義に忠実に従っているためです。 問題はコストです。 最悪の場合、各パスは 1 つの要素のみを消費する可能性があるため、n 個の値のそれぞれについて配列全体をスキャンします。 これにより、約 n 回のパスが発生し、各パスに O(n) がかかり、合計 O(n²) の操作が生成されます。 

重要な観察は、重要なのはスキャン自体ではなく、連続する数値が配列内で相互に相対的に表示される場所であるということです。 数値 x+1 が x の左側に表示される場合、このスキャンですでに x+1 を通過しているため、x に到達したときに現在のパスを続行することはできません。 これが発生するたびに、新しいパスを開始する必要があります。 

したがって、パスをシミュレートする代わりに、配列内の各値の位置を追跡します。 値を 1 から n まで調べて、位置を比較します。 現在の値の位置が前の値の位置よりも小さい場合は、1 回のスキャン内で順序が壊れ、新しいパスが必要であることを意味します。 

これにより、問題は位置シーケンスが何回減少するかを数えることに減ります。

 ## アルゴリズムのチュートリアル

 1. アレイを構築する`pos`どこ`pos[x]`値のインデックスを格納します`x`与えられた順列で。 これにより、問題は配列自体に対する処理から位置に対する処理に変換され、比較が定数時間になります。 
2. カウンタの初期化`rounds = 1`シーケンスの処理を開始するには常に少なくとも 1 つのパスが必要になるためです。 
3. 反復する`x`2 から n までの比較`pos[x]`と`pos[x-1]`。 各比較では、同じスキャン内で現在の増加シーケンスを継続できるかどうかがチェックされます。 
4. もし`pos[x] < pos[x-1]`、増分`rounds`by 1. これは値を意味します`x`前に現れます`x-1`配列内にあるため、左から右へのスキャンでは次のような結果が得られます。`x-1`最初なので処理できません`x`同じパス内で。 
5. ループ終了後、出力`rounds`。 

### なぜ効果があるのか

 このアルゴリズムは、1 回のスキャンではインデックスが昇順に表示される値のみを処理できるという不変条件に依存しています。 連続する値のインデックス シーケンスの減少を検出するたびに、2 つのスキャン間の境界を特定します。 値は厳密に昇順で消費されるため、値間のすべての反転は、`pos[x]`そして`pos[x-1]`新しいトラバースを強制します。 このようなブレークの数は、必要なパスの数と正確に一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input().strip())
a = list(map(int, input().split()))

pos = [0] * (n + 1)
for i, v in enumerate(a):
    pos[v] = i

rounds = 1
for x in range(2, n + 1):
    if pos[x] < pos[x - 1]:
        rounds += 1

print(rounds)
```最初のループでは、各値が O(1) 時間でその位置を認識できるように位置マップを構築します。 これは、繰り返しのスキャンを単純な比較に変換するため、非常に重要です。 

2 番目のループは、核となる観察を実装します。つまり、連続する値がインデックスの昇順で出現するかどうかだけを考慮します。 1 への初期化は、完全に順序付けされた配列であっても少なくとも 1 回のパスが必要であるという事実を反映しています。 

よくある間違いは初期化です`rounds`0 に設定し、ブレーク時にのみインクリメントしようとすると、1 だけアンダーカウントされます。 もう 1 つの微妙な問題は、値とインデックスを混同することです。比較は値自体ではなく、値の位置間で行う必要があります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n = int(input().strip())
    a = list(map(int, input().split()))

    pos = [0] * (n + 1)
    for i, v in enumerate(a):
        pos[v] = i

    rounds = 1
    for x in range(2, n + 1):
        if pos[x] < pos[x - 1]:
            rounds += 1

    return str(rounds)

# provided samples
assert run("5\n3 1 2 5 4\n") == "3"

# minimum size
assert run("1\n1\n") == "1"

# already sorted
assert run("4\n1 2 3 4\n") == "1"

# reverse sorted
assert run("4\n4 3 2 1\n") == "4"

# random permutation
assert run("6\n4 1 3 2 6 5\n") == "4"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 要素 | 1 | 最小境界の場合 |
 | ソートされた配列 | 1 | 休憩なしの場合 |
 | 逆配列 | n | 最悪の断片化 |
 | 混合順列 | 4 | 一般的な正しさ |

 ## 特殊なケース

 次のような単一要素の配列`[1]`可能な限り最も単純なシナリオです。 位置配列には値が 1 つだけ含まれており、連続するペアに対するループは実行されず、そのまま残ります。`rounds = 1`。 アルゴリズムは、特別なケースを使用せずにこれを正しく処理します。 

次のような逆ソートされた配列`[4, 3, 2, 1]`それぞれが次の位置を生成します。`pos[x] < pos[x-1]`が当てはまります。 ループはインクリメントします`rounds`すべてのステップで 4 つのパスが発生します。 これは、次に必要なすべての値が配列内で前に現れるため、各数値を個別の走査で処理する必要があるという直観と一致します。 

のような部分的に注文されたケース`[3, 1, 2, 4]`位置順序で 2 から 3 に移動するときに 1 つのブレークが生成されます。 アルゴリズムは正確に 1 つの減少を検出して 2 を出力し、シーケンスを 2 つのスキャンに正しく分割します。
