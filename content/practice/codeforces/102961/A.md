 ## 解決策
 ## 問題の理解

 このタスクは、一連の整数を取得し、その中に出現するさまざまな値の数を決定することです。 数値のリストが与えられ、出力はこれらの数値で形成されるセットのサイズを表す単一の整数です。つまり、重複は無視され、一意の値のみがカウントされます。 

計算の観点から見ると、入力サイズがソリューションの選択を決定します。 シーケンスの長さが約 10^5 以上に達すると、各要素を他のすべての要素と比較するメソッドはどれも遅くなりすぎます。これは、一般的な時間制限をはるかに超える n² 回の演算が必要になるためです。 これにより、各要素が一定時間またはほぼ一定時間で処理されるソリューションが求められます。 

重複が頻繁に発生する場合、またはすべての値が同一である場合には、微妙な問題が発生します。 たとえば、入力が次の場合、`5 5 5 5 5`、正解は`1`。 適切な追跡を行わずに、誤って比較をカウントしたり、要素ごとのカウンターをリセットしたりする単純なアプローチでは、誤った結果が返される可能性があります。`5`。 もう 1 つのエッジ ケースは、すべての要素がすでに個別である場合です。`1 2 3 4 5`、ここで、答えは入力サイズと等しくなります。 どのソリューションでも、特別なケースを使用せずに、両方の極端な問題を一貫して処理する必要があります。 

## アプローチ

 問題を解決する最も直接的な方法は、すべての要素を他のすべての要素と比較し、それが以前に出現したかどうかをマークすることです。 このブルート フォース戦略は概念的には単純です。数値ごとに、配列の残りの部分をスキャンして、それが以前に発生したかどうかを確認します。 これは正しいです。これは、すべてのペアの等価性を明示的にチェックし、重複が確実に検出されるようにするためです。 ただし、長さ n のシーケンスの場合、要素ごとにおよそ n 回のチェックが必要となり、合計で n² 回の比較が行われることになります。 n が大きい場合、これは計算上不可能になります。 

重要な点は、実際には要素をペアごとに比較する必要がないということです。 必要なのは、すでに見たものを記憶する構造だけです。 問題が純粋にメンバーシップの追跡に関するものであることがわかれば、繰り返しのスキャンをハッシュベースの構造に置き換えることができます。 セットは自然に一意の要素を維持し、平均一定時間での挿入とメンバーシップのチェックをサポートします。 各要素を以前のすべての要素と比較するのではなく、単純に要素をセットに挿入し、構造に基づいて重複を破棄します。 

これにより、繰り返しの比較による問題が、要素ごとの定数時間演算による配列の 1 回のパスに軽減されます。

 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | 遅すぎる |

 ## アルゴリズムのチュートリアル

 すでに検出した値のコレクションを維持しながら、シーケンスを 1 回処理します。 

1. これまでに確認されたすべての個別の値を格納する空のセットを初期化します。 まだ要素を処理していないため、このセットは空で始まります。 
2. 入力シーケンス内の各数値を左から右に繰り返します。 各要素は 1 回だけ考慮されるため、線形処理が保証されます。 
3. それぞれの番号をセットに挿入します。 番号がすでに存在する場合、セットは変更されません。 この動作は、追加のロジックを使用せずに重複を自動的に処理するため、非常に重要です。 
4. すべての要素を処理した後、セットのサイズを計算します。 このサイズは、走査中に見つかった一意の値の数を表します。 

### なぜ効果があるのか

 反復中のどの時点でも、セットには、それまでに処理された配列のプレフィックスに出現した要素が正確に含まれます。 新しい要素が読み取られるとき、それをセットに追加すると、この不変条件が維持されます。セットは常に、処理されたプレフィックスの一意の要素を反映します。 すべての要素は 1 回だけ処理されるため、ループの終わりまでに、セットには完全な配列内のすべての個別の値が含まれ、他には何も含まれません。 したがって、最終的なサイズは入力内の固有の値の数と等しくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    data = input().strip().split()
    if not data:
        return
    
    # If format is: n followed by array
    # we try to detect and handle both common variants safely
    try:
        n = int(data[0])
        arr = list(map(int, data[1:1+n]))
        if len(arr) != n:
            arr = list(map(int, data))
    except:
        arr = list(map(int, data))
    
    seen = set()
    for x in arr:
        seen.add(x)
    
    print(len(seen))

if __name__ == "__main__":
    solve()
```単純な問題に対するコンテストの入力形式は、明示的に n を与える場合と単に生のリストを与える場合とで異なる場合があるため、実装は柔軟な方法で入力を読み取ります。 解析後のコア ロジックは単純です。セットは、検出されたすべての値を蓄積します。 

唯一重要な点は、入力構造を誤って誤って処理しないようにすることです。 セットの挿入では重複が自動的に処理されるため、条件チェックや手動の簿記は必要ありません。

 ## 特殊なケース

 次のような単一要素入力の場合`7`、セットは空で始まり、挿入します`7`、サイズ 1 で終了します。ループは自然に単一の反復を処理するため、アルゴリズムでは特別な分岐は必要ありません。 

次のような完全に均一な入力の場合`9 9 9 9`、最初の挿入により追加されます`9`セットに追加すると、それ以降の挿入はすべて無効になります。 処理されたプレフィックスの一意の要素がセットに含まれるという不変条件は、各ステップ後に保持され、最終的なサイズは正しく 1 のままになります。 

次のような完全に異なる入力の場合`1 2 3 4`、挿入するたびにセット サイズが 1 ずつ増加し、重複がプロセスを妨げることはありません。 最終的なセット サイズは入力長と正確に一致し、アルゴリズムが新しい値を誤って抑制しないことが確認されます。
