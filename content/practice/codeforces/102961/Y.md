 ## 問題の理解

 一連の数値とターゲット値が与えられます。そのタスクは、シーケンス内に 4 つの異なる位置が存在し、それらの位置の値の合計がターゲットに正確に一致するかどうかを判断することです。 このような 4 倍体が存在する場合は、そのインデックスを出力する必要があります。 それ以外の場合は不可能であると報告します。 

入力は、ライン上に配置された重みの集合として理解できます。 合計が必要な合計と一致する 4 つの異なる重みを選択できるかどうかを尋ねられます。選択できる場合は、それらの重みがどこから来たのかも特定する必要があります。 たとえその値が合計に達するのに役立つ場合でも、同じ要素を再利用することはできないため、個別のインデックスの要件は重要です。 

複雑さの観点から見ると、この問題の自然な入力サイズは十分に大きいため、すべての 4 倍数を直接調べるアプローチは実行不可能になります。 4 つの指数を単純に列挙しただけでも、すでに$O(n^4)$、これは、中程度の値であっても天文学的に大きくなります。$n$。 これにより、すべてのクアドルプルに対するブルートフォース検索が即座に排除されます。 問題の構造は、要素のペア間の関係を事前に計算することによって、何らかの方法で検索空間を圧縮する必要があることを示唆しています。 

複数の要素が同じ値を共有する場合、微妙なエッジケースが発生します。 たとえば、配列が次の場合、$[1, 1, 1, 1]$そしてターゲットは$4$、4 つの異なる位置すべてを使用して正解が存在します。 インデックスなしで値を追跡するだけの不注意なソリューションでは、同じ出現を誤って複数回再利用する可能性があります。 重複する 2 つのペアを形成するなど、ペアの組み合わせでインデックスを再利用するときに別の問題が発生します。 これは明示的に防止する必要があります。 

## アプローチ

 ブルートフォース手法では、4 つの異なるインデックスのすべての組み合わせを試し、それらの合計がターゲットと等しいかどうかを確認します。 これは、解空間全体を網羅的に列挙しているため、正しいです。 ただし、各 4 回転では一定の作業が実行され、4 回転の数は増加するにつれて増加します。$\binom{n}{4}$に比例します。$n^4$。 いつでも$n$わずか数千なので、制限時間内に実行するには遅すぎます。 

重要な観察は、クアドルプルは 2 つのペアに分割できるということです。 4 つの要素を一度に検索する代わりに、すべてのペアの合計を事前に計算します。 各ペアはインデックスとともに合計を提供し、その合計がターゲットに達する 2 つの互いに素なペアを照合しようとします。 これにより、問題は 4 次元での検索から 2 次元での検索に軽減されます。 

強制しなければならない主な制約は、2 つのペアがインデックスを共有しないことです。 これは、各ペアの合計と一緒にインデックスを保存し、素性を確保しながら相補的な合計を持つペアのすべての組み合わせをチェックすることによって処理されます。

 ## アルゴリズムのチュートリアル

 私たちは、ペアの合計と、高速な補数クエリを可能にするルックアップ構造を中心にソリューションを構築します。 

1. インデックスのすべてのペアを生成します$(i, j)$と$i < j$、それらの合計を計算します$a[i] + a[j]$。 各ペアを合計からインデックス ペアのリストへのマッピングに保存します。 これが必要なのは、複数のペアが同じ合計を共有する可能性があり、すべての可能性を保存する必要があるためです。 
2. 各ペアの合計を反復処理します。$s$構造中に存在します。 それぞれについて$s$、必要な補数を計算します$t - s$、 どこ$t$が目標金額です。 
3. ペアごとに$(i, j)$sum の下に保存される$s$、それぞれのペアとペアリングしてみてください$(k, l)$sum の下に保存される$t - s$。 これにより、2 つの素のペアが必要な合計を形成できるかどうかがチェックされます。 
4. 候補者を受け入れる前に、4 つのインデックスがすべて異なることを確認してください。 これにより、同じ要素を複数のロールで再利用することがなくなります。 
5. 有効な構成が見つかったら、4 つのインデックスを出力し、すぐに終了します。 

最初の一致で安全に停止できる理由は、問題には有効な解決策のみが必要であり、すべての解決策が必要であるわけではないためです。 

### なぜ効果があるのか

 すべての有効なソリューションは、2 つの互いに素なペアに分割できる 4 つのインデックスで構成されます。 すべてのペアを一度列挙し、それらを合計でグループ化することにより、有効な 4 つが構造内の 2 つのエントリに対応することが保証されます。 相補的な合計間の徹底的なペアリングにより、有効な組み合わせが失われることがなくなり、明示的なインデックス非結合チェックにより要素の無効な再利用が防止されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, target = map(int, input().split())
    arr = list(map(int, input().split()))

    pairs = {}

    for i in range(n):
        for j in range(i + 1, n):
            s = arr[i] + arr[j]
            if s not in pairs:
                pairs[s] = []
            pairs[s].append((i, j))

    # search for complement pairs
    for s in list(pairs.keys()):
        t = target - s
        if t not in pairs:
            continue

        list1 = pairs[s]
        list2 = pairs[t]

        for i1, j1 in list1:
            for i2, j2 in list2:
                if i1 != i2 and i1 != j2 and j1 != i2 and j1 != j2:
                    print(i1 + 1, j1 + 1, i2 + 1, j2 + 1)
                    return

    print("IMPOSSIBLE")

if __name__ == "__main__":
    solve()
```解決策は、ペアの合計の辞書を構築することから始まります。各キーには、その合計を生成するすべてのインデックス ペアが格納されます。 異なるインデックスのペアが同じ合計を生成する可能性があり、その多重度が失われると解が見つからなくなる可能性があるため、これは不可欠です。 

第 2 フェーズでは、これらの合計を繰り返し、相補的な合計を検索します。 格納されたペアに対するネストされたループによって正確さが保証される一方、明示的な不等号チェックによってインデックスが明確であることが強制されます。 1 ベースのインデックスへの変換は出力時にのみ行われ、クリーンな内部ロジックが維持されます。 

## 実用的な例

 配列が存在する入力を考えます。$[2, 7, 4, 0, 9, 5]$そしてターゲットは$20$。 有効な解決策の 1 つは、$7 + 4 + 0 + 9$。 

| ステップ | ペア (i, j) | 合計 | 補体が必要です | 一致が見つかりました |

 | 2 | (2, 3) | 11 | 9 | はい |

 このトレースは、ペアがどのように動作するかを示しています。$(2, 3)$合計11と組み合わせることができます$(1, 5)$または$(3, 5)$構造に応じてタイプの組み合わせを変更し、正しい 4 回転を生成します。 

ここで、値が繰り返される場合を考えてみましょう。$[1, 1, 1, 1]$そしてターゲット$4$。 

| ペア | 合計 | 補足 | 有効性 |

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、複数のペアが同じ合計を共有し、インデックスの再利用につながる可能性がある場合です。 たとえば、次のような配列では、$[3, 3, 3, 3, 3]$ターゲット付き$12$、多くのペアの組み合わせは和を生成します$6$。 このアルゴリズムは、一致を受け入れる前にインデックスの区別性を明示的にチェックすることで正確さを保証し、無効な再利用を防ぎます。 

もう 1 つのケースは、有効な解が存在するが、重複する合計グループ内にのみ存在する場合です。 たとえば、同じ値が複数の位置に出現する場合、ペア合計マップには多数の同一の合計が含まれる可能性があります。 このアルゴリズムは、合計ごとに 1 つの代表ペアだけでなく、すべてのインデックス ペアを格納するため、すべての組み合わせを探索し、集計中に有効な 4 倍が失われないようにします。
