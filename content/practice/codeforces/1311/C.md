 ## 解決策
 ## 問題の理解

 固定文字列が与えられています`s`これは、格闘ゲームのコンボにおける一連のボタン押しを表します。 プレーヤーは、この文字列全体を左から右に繰り返し入力しようとします。 

ただし、プロセスは中断されます。 最初の間`m`各試行は特定の位置までしか成功しません`p_i`, その後、プレーヤーはすぐに最初から再開します。 最後の試行では、プレーヤーは中断することなく文字列全体を正常に完了します。 

したがって、実際に押す順序は単に次のとおりではありません。`s`何度も繰り返されました。 代わりに、次のプレフィックスを連結したものです。`s`失敗した試行によって決定され、その後に次の 1 つの完全なコピーが続きます。`s`。 課題は、からの各手紙が何回あるかを数えるということです。`a`に`z`このプロセス全体で が押されます。 

主な問題点は、試行の総数と文字列の長さが両方とも大きくなり、最大で`2 * 10^5`テストケースの合計。 試行ごとに部分文字列を追加する直接シミュレーションでは、文字列のプレフィックスを繰り返しスキャンする可能性があり、最悪の場合は 2 次の動作が発生する可能性があるため、速度が非常に遅くなります。 

単純な間違いは、失敗した試行をそれぞれ独立して扱い、プレフィックスのみをカウントすることから発生することがよくあります。`s[0:p_i]`重複するプレフィックスが周波数の寄与を蓄積することに気づかずに。 もう 1 つの微妙な問題は、文字列の最後に成功した完全な走査を含めるのを忘れていることです。 

たとえば、次の場合`s = "abc"`そして`p = [1, 1, 2]`、正しいシーケンスには以下が含まれます`"a" + "a" + "ab" + "abc"`。 単純なアプローチでは、寄与度を累積せずに誤って再計算したり上書きしたりして、不正確な頻度が発生する可能性があります。 

## アプローチ

 ブルート フォース シミュレーションでは、プレフィックス長を反復処理して各試行を処理します。`p_i`そして、そのプレフィックス内のすべての文字のカウントが増加します。 失敗した試行をすべて処理した後、完全な文字列をもう一度処理します。 

これは実際のプロセスを正確に反映しているため、これは正しいです。 ただし、その複雑さには問題があります。 それぞれの`m`試行には最大で`O(n)`最悪の場合でも機能します。`n`そして`m`到達できる`2 * 10^5`、最悪の場合のトータルオペレーションアプローチ`O(nm)`単一のテストまたはケース全体で行うと、遅すぎます。 

重要な点は、文字列を明示的に再構築する必要がないということです。 代わりに、失敗した試行全体で各プレフィックス位置が何回訪問されたかを知る必要があるだけです。 インデックスの頻度がわかっている場合`i`がプレフィックスに含まれている場合は、貢献を直接蓄積できます。 

これにより、問題はプレフィックス範囲にわたる周波数累積問題に変換されます。 配列を維持します`cnt[i]`位置の何倍かを表す`i`失敗した試行には含まれます。 試行が失敗するたびに、すべてのインデックスが +1 されます。`1..p_i`。 これは、差分配列を使用して効率的に処理できます。 すべてのクエリを処理した後、プレフィックスの合計を計算します。`cnt`最終実行前に各ポジションが何回訪問されたかを知るため。 

最後に、最終的に成功した試行のために、完全な文字列内のすべての文字の出現を 1 つ追加します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nm) | O(1) おまけ | 遅すぎる |
 | 最適 | O(n + m) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースごとに、文字列を読み取ります。`s`およびプレフィックス長のリスト`p`。 

目標は、各ポジションが何回行われるかを計算することです。`s`最後の完全な試行の前にアクセスされます。 
2. 整数配列を作成する`cnt`サイズの`n + 1`、ゼロに初期化されます。 

この配列には、各インデックスが失敗した試行によってカバーされた回数の差分表現が格納されます。 
3. 各値について`p_i`、増分`cnt[0]`1 ずつ減分`cnt[p_i]`1までに。 

これは、からのすべての位置をエンコードします。`0`に`p_i - 1`この失敗した試行によって一度影響を受けます。 差分配列により、プレフィックスの明示的な反復が回避されます。 
4.変換`cnt`プレフィックス合計を使用して実際のカバレッジ カウントに換算します。 

このステップの後、`cnt[i]`位置を含む失敗した試行の数を表します`i`。 
5. サイズ 26 の応答配列をゼロで初期化します。 

これにより、各文字の合計頻度が保存されます。 
6. 各ポジションについて`i`文字列に追加します`cnt[i] + 1`の周波数に`s[i]`。 

の`+1`最後に成功した試行を考慮しており、常に完全な文字列を 1 回走査します。 
7. 26 個の累積値を出力します。 

### なぜ効果があるのか

 失敗した各試行は、そのプレフィックス内のすべてのインデックスに対して 1 回の訪問に寄与します。 差分配列は、明示的に反復処理することなく、これらの間隔寄与の合計をエンコードします。 プレフィックスの合計後、すべての位置は、失敗した試行が何回含まれているかを正確に把握します。 1 つ追加すると、最終的な完全な走査が行われます。 寄与は位置ごとに加算的で独立しているため、インデックスごとに合計すると、各文字の正しい合計頻度が得られます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    def solve():
        t = int(input())
        for _ in range(t):
            n, m = map(int, input().split())
            s = input().strip()
            p = list(map(int, input().split()))

            cnt = [0] * (n + 1)
            for x in p:
                cnt[0] += 1
                cnt[x] -= 1

            cur = 0
            freq = [0] * 26
            for i in range(n):
                cur += cnt[i]
                freq[ord(s[i]) - 97] += cur + 1

            print(*freq)

    solve()
    return sys.stdout.getvalue().strip()

 ## 特殊なケース

 エッジケースの 1 つは、すべてが`p_i = 1`つまり、失敗した試行はすべて最初の文字のみに寄与します。 この状況では、差分配列の増分はインデックス 0 で大量にスタックされ、他のすべての位置は影響を受けません。 このアルゴリズムは、最初の文字を複数回と 1 回の完全な走査のみを正しく蓄積します。 

もう 1 つの特殊なケースは、すべてが`p_i = n - 1`つまり、失敗するたびに文字列がほぼ完成します。 ここでは、すべてのインデックスが重点的にカバーされており、プレフィックスの合計によって文字列全体にわたって均一な寄与が保証されます。 決勝戦`+1`正しくフルパスを 1 つ追加します。
