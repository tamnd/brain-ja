 ## 問題の理解

 3 つの正の整数が減少しない順序で与えられます。 それらを数直線上の 3 つのノブと考えてください。 1 回の操作で、任意の 1 つのノブを正確に 1 単位左右にシフトできますが、1 未満のノブを押すことはできません。目標は、中央の値が最初の値の倍数になり、最後の値が中央の値の倍数になるように、トリプルを新しい順序のトリプルに再形成することです。 

出力は、そのような構成に到達するために必要な最小移動数だけでなく、この最小値を達成する 1 つの具体的な最終構成でもあります。 

主な難点は、私たちが求める構造が非常に厳格であることです。最小値が固定されると、中央値はその倍数に強制され、最大値も中央値の倍数に強制されます。 これにより、密な整数グリッド内で有効なトリプルの空間が疎になります。 

制約は十分に小さいため、考えられるすべての最終トリプルを直接検索することが可能です。 各値は最大 10^4 であるため、検索スペースを制御しておけば、候補に対するネストされた反復も許容されます。 構造を持たずに考えられるすべてのトリプルを単純に構築しようとするソリューションでも、ドメインが厳密に境界付けされているため、合格します。 

3 つの数値すべてを同じ値に変換するなど、最適解が値をまとめて折りたたむ場合、微妙なエッジ ケースが発生します。 たとえば、回転する`100 100 101`の中へ`100 100 100`は最適ですが、厳密にトリプルの増加のみを考慮するアプローチでは、これを見逃す可能性があります。 もう 1 つの例外的なケースは、値を増やすよりも減らす方がコストが低い場合です。これは、1 のような小さな約数への縮小を許可する場合によく発生します。 

## アプローチ

 ブルートフォースアプローチは、可能な最後のトリプルをすべて試すことができるという考えから始まります$A \le B \le C$。 選択肢ごとに、絶対差の合計としてコストを計算します。$|a-A| + |b-B| + |c-C|$、ただし満足のいくトリプルのみを維持します$B \bmod A = 0$そして$C \bmod B = 0$。 

これは正しいです。すべての有効なターゲット構成が明示的にテストされ、コスト関数が必要な移動数と正確に一致するからです。 問題は候補者の数だ。 各変数は最大約 10^4 になる可能性があるため、完全な検索スペースは次のオーダーになります。$10^{12}$、それは不可能です。 

重要な観察は、有効なトリプルの構造が階層的であるということです。 選択したら$A$、意味のある唯一の選択肢$B$の倍数です$A$、そして選択したら$B$、意味のある唯一の選択肢$C$の倍数です$B$。 これにより、各ステップで分岐係数が任意の整数から等差数列によって制約された約数に縮小されるため、検索スペースが大幅に減少します。 

すべてのトリプルを試す代わりに、すべてのもっともらしい候補を試します。$A$、それぞれについて$A$、の倍数を列挙します$B$、それぞれについて$B$、の倍数を列挙します$C$。 実際に最適なシフトを実現するには、値はおよそ 2 × 10^4 で制限されるため、この列挙は小さいままです。 

また、2 番目の重要なアイデアにも依存しています。それは、最適なソリューションは元の値に近い傾向にあるということです。 したがって、近くの候補者のみを考慮する必要があります。$a$、$b$、 そして$c$遠くに移動することは、近くの有効な構成を調整するよりも常にコストがかかるため、通常は小さな境界ウィンドウ内で行われます。

 ## アルゴリズムのチュートリアル

 最初の要素を固定し、有効なチェーンを上向きに構築することで、可能な最終値を反復処理します。 

1. の候補値を固定します。$A$オリジナルを中心とした範囲で$a$、通常は 1 から 2 × 10^4 などの小さな境界までです。 このようにするのは、不必要なコストを発生させずに、最適解を任意に元の値から遠ざけることはできないためです。 
2. それぞれについて$A$、候補を選択します$B$の倍数として$A$。 乗算器を反復処理することでこれらを生成します$k$そのような$B = kA$。 これにより、割り算の制約が保証されます。$B \bmod A = 0$。 
3. それぞれについて$B$、候補を選択します$C$の倍数として$B$、再び乗算器を反復処理することによって$m$そのような$C = mB$。 これにより、強制的に$C \bmod B = 0$。 
4. 有効なトリプルごとに$(A, B, C)$、合計コストを次のように計算します。$|a - A| + |b - B| + |c - C|$。 これまでに確認された最小コストを追跡します。 
5. この最小値を達成するトリプルを保存します。 

これが機能する理由は、すべての有効な最終構成が厳密な可分性チェーンを満たさなければならないためです。 任意の選択ではなく乗算によって候補を構築することにより、有効な構造を見逃すことなく、正確に実行可能なセットを生成します。 

検索スペースは小さいため、$A$が固定されている場合、その倍数は$A$境界以下は制限されており、同様に$B$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXV = 20000

def solve():
    t = int(input())
    for _ in range(t):
        a, b, c = map(int, input().split())

        best = 10**18
        best_triple = (a, b, c)

        # Try A
        for A in range(1, MAXV + 1):
            # Try B as multiple of A
            for B in range(A, MAXV + 1, A):
                # Try C as multiple of B
                for C in range(B, MAXV + 1, B):
                    cost = abs(a - A) + abs(b - B) + abs(c - C)
                    if cost < best:
                        best = cost
                        best_triple = (A, B, C)

        print(best)
        print(*best_triple)

if __name__ == "__main__":
    solve()
```実装の中核は、構造によって可分性を強制する 3 層のループ構造です。 トリプルの生成後に条件をチェックするのではなく、有効なトリプルのみを生成します。 

定数`MAXV`すべての有用な候補を快適にカバーするのに十分な大きさが選択されます。 この値を増やしても正確性は変化せず、実行時間のみが変化します。 

よくある間違いは、C を独立変数としてではなく B の倍数として反復する必要があることを忘れていることです。 もう 1 つは、倍数に対して非整数ステップを誤って許可しており、割り算の保証を破る可能性があります。 

## 実用的な例

 2 つのケースを追跡します。 

### 例 1:`1 2 3`小さな値から始めて候補チェーンを探索します。 

| あ | B | C | コスト = |1-A| + |2-B| + |3-C| |

 |---|---|---|---|

 | 1 | 1 | 1 | 3 |

 | 1 | 1 | 2 | 2 |

 | 1 | 1 | 3 | 1 |

 | 1 | 2 | 2 | 1 |

 | 1 | 2 | 4 | 3 |

 最良の値は (1, 2, 2) または (1, 1, 3) で得られます。どちらも可分性連鎖の解釈に応じた制約の下で有効であり、最小コストは 1 です。 

これは、最適なソリューションでは、厳密に元の値に近づけることによって順序構造を保存するのではなく、3 つの座標すべてにわたるコストのバランスをとることによって順序構造を保存する可能性があることを示しています。 

### 例 2:`100 100 101`近くの崩壊解を評価します。 

| あ | B | C | コスト |
 | --- | --- | --- | --- |
 | 100 | 100 | 100 | 1 |
 | 100 | 100 | 200 | 99 |
 | 101 | 101 | 101 | 3 |

 最良の選択は、(100, 100, 100) に折りたたむことです。多くの場合、1 つの座標だけを減らす方が、3 つすべてをシフトするよりもコストがかからないことがわかります。 

このトレースは、なぜ下向きの動きを許可することが重要であるかを示しています。

import sys, io

    sys.stdin = io.StringIO(inp)

    out = []

        best = 10**18

        out.append(str(best))
        out.append(" ".join(map(str, best_triple)))

 ## 特殊なケース

 重要なエッジケースは、3 つの数値がすべて同じ値に折りたたまれる場合です。 のような入力の場合`100 100 101`、アルゴリズムは次のチェーンを考慮します。$A = B = C = 100$、コスト 1 を生成します。最大値のみを下方に調整する貪欲なアプローチでは、中間値を増やすことで誤って割り算を一致させようとし、コストの上昇につながる可能性があります。 

もう 1 つのエッジ ケースは、最適な構成に値の大幅な縮小が含まれる場合です。`1 22 29`。 ここでは、次のような小さな約数構造に移行します。`(1, 22, 22)`上向きに揃えようとするよりも安価です。 アルゴリズムは、小さいものから始めてすべての可分性チェーンを列挙するため、これらを正確に調査します。$A$、崩壊するソリューションが常に考慮されるようにします。
