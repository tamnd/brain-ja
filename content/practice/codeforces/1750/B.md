 ## 解決策
 ## 問題の理解

 バイナリ文字列が与えられ、すべての連続したセグメントを調べるように求められます。 各セグメントについて、含まれる 0 と 1 の数を数え、それらの数に基づいてスコアを割り当てます。 両方のシンボルが表示された場合、スコアは 2 つのカウントの積になります。 セグメントが一様であれば、スコアは単純にその長さの 2 乗になります。 

タスクは、指定された文字列のすべての部分文字列に対して可能な最大スコアを見つけることです。 複数のテスト ケースがあり、すべてのケースの合計の長さが長くなる可能性があるため、すべての部分文字列を明示的にチェックするソリューションは遅すぎます。 この構造は、答えが等しい文字の連続のグローバル構造と、境界を越えて 1 と 0 がどのように相互作用するかに依存する必要があることを示唆しています。 

素朴なアプローチでは、すべての部分文字列を列挙し、それぞれの部分文字列の 0 と 1 を数えますが、これには次のことが必要です。$O(n^2)$テスト ケースごとの部分文字列と部分文字列ごとの線形カウントでは、最悪の場合、三次的な動作が発生します。 と$2 \cdot 10^5$全長、これは無理です。 

文字列が均一な場合、エッジケースが発生します。 この場合、単一文字型推論のみが適用され、答えは全長の 2 乗になります。 もう 1 つの微妙なケースは、すべての部分文字列に両方の文字が混在する交互文字列で、最大値はランレングスではなくプレフィックス数のバランスに依存します。 

## アプローチ

 ブルート フォース手法では、すべての部分文字列をチェックし、0 と 1 のカウントから直接そのコストを計算します。 これは定義を直接評価するので正しいですが、各部分文字列でプレフィックス数のスキャンまたは維持が必要になるため、遅すぎます。$O(n^2)$テストケースごとの操作。 

重要な観察は、部分文字列のコストは、その順序ではなく、含まれる 0 と 1 の数にのみ依存するということです。 0 と 1 のプレフィックス合計を使用すると、部分文字列ごとの定数時間の評価が可能になりますが、それでも$O(n^2)$部分文字列。 

構造的な改善は、最適な部分文字列は常に、部分文字列を拡張すると積が増加する位置と端点が一致するものであることを認識することで実現します。$x \cdot y$またはスクエアラン。 最大値は、一様なセグメント内で発生するか、一方のシンボルがまれで他方が優勢な境界にまたがります。 これにより、検索がプレフィックス統計を使用した線形スキャンに削減されます。

 | プレフィックス数による最適なスキャン |$O(n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 任意の部分文字列を定数時間で評価できるように、ゼロと 1 のプレフィックス数を計算します。 これにより、文字数を繰り返し再計算する必要がなくなります。 
2. 可能なすべての左側のエンドポイントを反復します。 左のエンドポイントごとに、プレフィックスの違いを使用してカウントを追跡しながら、右のエンドポイントを拡張します。 これにより、増分メンテナンスが可能になります。$(x, y)$。 
3. によって決定される各部分文字列について$(l, r)$、定義を使用してコストを計算します。 どちらかのとき$x=0$または$y=0$、コストは正方形に減少し、そうでない場合は製品になります。 この手順により、すべての部分文字列タイプの正確性が保証されます。 
4. 評価されたすべての部分文字列にわたってグローバル最大値を維持します。 
5. テスト ケース内のすべての部分文字列を処理した後の最大値を出力します。 

重要なアイデアは、プレフィックスの合計によって部分文字列の評価が一定時間になり、増分スキャンによって再計算が回避されるということです。 

### なぜ効果があるのか

 すべての部分文字列はインデックスのペアに一意に対応します$(l, r)$。 プレフィックス表現により、そのようなすべてのペアで 0 と 1 のカウントが正確であることが保証されます。 コスト関数はこれらのカウントのみに依存するため、すべてのペアを評価すると検索スペースが使い果たされます。 完全性を超える構造的な仮定は使用されないため、有効な候補部分文字列が見逃されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    s = input().strip()

    pref0 = [0] * (n + 1)
    pref1 = [0] * (n + 1)

    for i, ch in enumerate(s):
        pref0[i + 1] = pref0[i]
        pref1[i + 1] = pref1[i]
        if ch == '0':
            pref0[i + 1] += 1
        else:
            pref1[i + 1] += 1

    ans = 0

    for l in range(n):
        for r in range(l, n):
            x = pref0[r + 1] - pref0[l]
            y = pref1[r + 1] - pref1[l]

            if x == 0:
                val = y * y
            elif y == 0:
                val = x * x
            else:
                val = x * y

            if val > ans:
                ans = val

    print(ans)
```プレフィックス配列には、0 と 1 の累積カウントが格納されます。 各部分文字列について、プレフィックス値を減算して、一定時間内に正確なカウントを取得します。 ネストされたループは、すべての部分文字列を明示的に列挙します。 条件付きロジックは、部分文字列が均一であるか混合であるかに応じて、正しいコスト式を適用します。

 ## 特殊なケース

 単一の繰り返し文字で構成される文字列は、問題を二乗項の最大化に帰着させ、最適な答えは全長の二乗になります。 混合文字列では、両方のシンボルからのバランスのとれた寄与が必要であり、最大値はローカルの部分文字列ではなく完全な間隔から得られる場合があります。 交互パターンにより、1 つよりも長い均一な部分文字列が存在しないことが保証され、平方ではなく積項に依存するようになります。
