 ## 解決策
 ## 問題の理解

 小さな順列が与えられています。これは、1 から n までのすべての数値が 1 回だけ現れることを意味します。 ここでのタスクは、3 つのインデックス i < j < k を含む非常に特殊な操作を使用して、この配列を並べ替えられた順序に変換できるかどうかを判断することです。 

各操作は、位置 i と k の値の比較に応じて 2 つの方法のいずれかで動作します。 i の値が k の値より大きい場合、それに a[j] を追加することで i の値を増やすことができます。 それ以外の場合は、位置 j と k の要素を交換できます。 

目的は、固定された並べ替えアルゴリズムをシミュレートすることではなく、この操作を繰り返し使用することによって、最終的に並べ替えられた順列に到達することが可能かどうかを判断することです。 

制約は非常に小さく、n は最大 10 です。これは、ブルートフォース状態検索が一見すると魅力的に見えるかもしれないことを示唆しています。 ただし、インデックスのすべてのトリプルが潜在的な動きであり、位置だけでなく値も変化する可能性があるため、操作の分岐要素は大きくなります。 このように小さい n であっても、完全な状態に対する単純な BFS は厄介になります。これは、最初のタイプの操作の後、値が制限された順列ではなくなるためです。 

重要な微妙なエッジ ケースは、最初の操作で値が変更され、順列構造が壊れるということです。 たとえば、有効な順列から開始して「加算」ステップを適用すると、n より大きな値が生成される可能性があるため、直接シミュレートしようとすると状態の追跡が大幅に困難になります。 

もう 1 つの重要なシナリオは、スワップが一見利用可能であるように見えても、実際には a[i] と a[k] の条件によってブロックされている場合です。 たとえば、最小の要素が正しく配置されていない場合、たとえ構文的にスワップが存在していても、有用な再配置が妨げられる可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、各アレイ構成を状態として扱い、可能なすべての操作を調査します。 与えられた状態から、すべてのトリプル i < j < k を試し、スワップまたは値の変更を生成し、ソートされた配列に到達するか可能性をすべて使い果たすまで検索を続けます。 

これはルールを正確にモデル化しているため、原則的には正しいです。 ただし、州の数はすぐに爆発的に増加します。 加算による価値の増加を無視しても、n! があります。 順列になり、各状態は O(n^3) 個の遷移に分岐します。 値が変更されると、状態空間は順列によっても制限されなくなり、検索は基本的に制御されなくなります。 

重要な観察は、この操作の内部に非常に強力な構造的制約が隠されているということです。 スワップ操作は、a[i] ≤ a[k] の場合にのみ有効になります。 この 1 つの条件によって、要素を並べ替えることができるかどうかが決まります。 他のすべての値に対して常にこの条件を満たすポジションが存在する場合、それはスワップの普遍的なイネーブラーになります。 

これは、値 1 が特別な役割を果たしているという重要な洞察につながります。 すべての値は正で別個であるため、a[i] = 1 の場合、1 との比較は常に a[i] ≤ a[k] を満たします。最初のインデックスに 1 を配置できれば、それはその後のすべての位置間での交換の恒久的な促進剤として機能し、事実上サフィックスの任意の再配置が可能になります。 

これが起こると、トリプル演算を使用して配列内のどこでも隣接するスワップをシミュレートできるため、並べ替えが簡単になります。 

したがって、問題全体は、最初にこの「交換可能アンカー」がすでに存在するかどうかを確認することに集約されます。

 ## アルゴリズムのチュートリアル

 ### 核となるアイデア

 配列の最初の要素が 1 に等しいかどうかを確認します。 

### ステップ

1. 現在のテスト ケースの配列を読み取ります。 
2. 位置 1 (0 からインデックスされた位置 0) の値を確認します。 
3. 1 に等しい場合は、「Yes」を出力します。 
4. それ以外の場合は「いいえ」を出力します。 

このチェックの背後にある理由は、1 が最初の位置にある場合にのみ、すべてのトリプル操作で固定ヘルパー要素として使用できるということです。 これを行わないと、スワップ操作はより大きな値を含む比較によって制限され、完全な再配置ができなくなります。 

### なぜ効果があるのか

 この操作では、a[i] ≤ a[k] となるように左側に i が存在する場合にのみ、j と k を交換できます。 最初の要素が 1 の場合、i = 1 を選択すると、1 が可能な最小値であるため、この条件がどの k に対しても常に当てはまります。 これは、任意のペア (j, k) を自由に交換できるため、配列をソート順に任意に並べ替えることができることを意味します。 

1 が最初の位置にない場合、それをスワップの普遍的な最小ピボットとして機能させる方法はありません。また、i の制限により、要素を自由に並べ替えることができなくなります。 配列は、完全な並べ替えが保証できない構造に閉じ込められます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        if a[0] == 1:
            print("Yes")
        else:
            print("No")

if __name__ == "__main__":
    solve()
```このソリューションは、各テスト ケースを個別に読み取り、ケースごとに一定時間のチェックを実行します。 唯一の微妙な点はインデックス付けです。無制限のスワップが可能かどうかを判断するために重要な位置は最初の要素だけであるため、最初の要素を直接検査します。 

決定は値 1 の位置に完全に帰着するため、操作のシミュレーションは必要ありません。

 ## 特殊なケース

 最小の要素が最初の位置にない場合、それが配列内のどこかに存在しても、グローバル スワップ イネーブラーとして機能することはできません。 i の条件には i < j < k が必要であるため、ピボットは常にすべてのスワップ操作から厳密に残されている必要があります。 1 がインデックス 1 で始まる場合にのみ、他のすべてのペアのピボットとして一貫して機能できます。 

たとえば、`[2,1,3,4,5]`、値 1 は存在しますが、すべての位置の左側で使用できないため、ユニバーサル ヘルパーとして使用できません。 アルゴリズムは正しく「いいえ」を出力し、一連の操作では任意の並べ替えを完全にロック解除できないという事実と一致します。
