 ## 問題の理解

 同じ長さの 2 つのバイナリ文字列が与えられています。 1 回の操作でセグメント ([l,r]) が選択されます。 セグメント内の文字列 (a) のすべてのビットが反転され、セグメント外の文字列 (b) のすべてのビットが反転されます。 

目標は、ある文字列を別の文字列に変換することではありません。 目標はより強力です。一連の操作を適用した後、両方の文字列のすべての文字がゼロになる必要があります。 最大 (n+5) 個の演算を使用してそのようなシーケンスを構築するか、解が存在しないことを証明する必要があります。 

すべてのテスト ケースにわたるすべての文字列の長さは最大 (2 \cdot 10^5) です。 すべてのキャラクターに対するすべての操作を明示的にシミュレートするソリューションは、コストが高すぎます。 総仕事量が入力サイズに線形となる構造が必要です。 

微妙な点は、この操作が両方の文字列に同時に影響することです。 1 つの文字列だけを見ると、問題の構造が見えなくなります。 もう 1 つの簡単な間違いは、文字列のすべてのペアが解決できると仮定することです。 一部のペアは基本的に不可能です。 

考慮する：```
n = 2
a = 11
b = 10
```答えは「ノー」です。 (a) をゼロにすることだけに焦点を当てた構築は、誤って成功したと主張する可能性があります。 

もう 1 つの興味深いケースは次のとおりです。```
n = 3
a = 010
b = 101
```ここではそれぞれの立場が異なります。 文字列は互いに補い合っていますが、答えは「YES」です。 

3 番目のエッジケースは次のとおりです。```
n = 3
a = 111
b = 111
```文字列は同一であり、答えは「YES」ですが、(a) の調整操作をクリアした後、いくつかの追加の調整操作が必要です。

したがって、すべての操作により、すべてのポジションの均等ステータスが同時に切り替わります。

 ## アルゴリズムのチュートリアル

 1. すべての位置が(a_i=b_i)を満たすかどうかを確認します。 
2. すべての位置が (a_i\neq b_i) を満たすかどうかを確認します。 
3. どちらの条件も当てはまらない場合は、印刷します。`NO`。 
4. それ以外の場合は、空の操作リストから開始します。 
5. (a_i=1) のすべての位置 (i) に対して、演算 ((i,i)) を追加します。 

長さ 1 の演算は、(a) の 1 ビットだけを反転します。 これをすべての 1 について繰り返すと、(a) はすべて 0 になります。 
6. (cnt) を元の文字列 (a) 内の 1 の数とします。 
7. 文字列が最初は等しい場合:

 ・（cnt）が偶数であれば、すでに完了している。 
- (cnt) が奇数の場合、次の 3 つの操作を追加します。 
[
 (1,n)、\ (1,1)、\ (2,n)。 
】
 8. 文字列が最初は補数だった場合:

 ・(cnt)が奇数の場合は、すでに完了しています。 
- (cnt) が偶数の場合、同じ 3 つの操作を追加します。 
[
 (1,n)、\ (1,1)、\ (2,n)。 
】
 9. 記録されたすべての操作を出力します。 

### なぜ効果があるのか

 (a_i=1) のすべての位置に対して長さ 1 の演算を実行するとします。 

このような各操作では (a) の 1 ビットが反転されるため、最終的に (a) はすべて 0 になります。 

残る疑問は(b)の状態だけだ。 答えは、実行された操作の数の同等性によって異なります。 

すべての操作で、文字列間のグローバルな関係が切り替わります。 等しい文字列から開始した場合、偶数回の演算の後でもそれらは等しいままであり、奇数回の演算の後では補数になります。 (a) はすでにすべて 0 であるため、等価性は (b) もすべて 0 であることを意味します。 

相補的な文字列から開始する場合は、逆のパリティが必要です。 

3 つの追加の操作はパリティ調整ガジェットです。 これらを組み合わせた文字列への影響は中立ですが、演算の数が 3 つ変わり、必要なパリティが反転します。 これにより、すべての場合において正しい最終関係を満たすことができます。 

存在条件は必要かつ十分であるため、構築は常に正しいです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        a = input().strip()
        b = input().strip()

        same = all(a[i] == b[i] for i in range(n))
        comp = all(a[i] != b[i] for i in range(n))

        if not same and not comp:
            out.append("NO")
            continue

        ops = []

        ones = 0
        for i, ch in enumerate(a, start=1):
            if ch == '1':
                ops.append((i, i))
                ones += 1

        need_flip = False

        if same:
            need_flip = (ones % 2 == 1)
        else:
            need_flip = (ones % 2 == 0)

        if need_flip:
            ops.append((1, n))
            ops.append((1, 1))
            ops.append((2, n))

        out.append("YES")
        out.append(str(len(ops)))
        for l, r in ops:
            out.append(f"{l} {r}")

    sys.stdout.write("\n".join(out))

solve()
```最初の部分では、ターゲット状態に到達できる唯一の 2 つの構成 (同一の文字列と相補的な文字列) をチェックします。 

次のループでは、(a) の単一位置演算ごとに 1 つの単一位置演算を記録します。 これは、(a) を強制的にすべてゼロにする最も簡単な方法です。 

パリティ ロジックは構築の中心です。 すべての 1 をクリアした後は、グローバルな等価性/補数関係のみが重要になります。 開始関係に応じて、偶数または奇数の操作が必要になります。 

(n \ge 2) のため、最後の 3 つの操作は常に有効です。 これらを組み合わせた効果により、操作数のパリティを変更しながら、達成された構成が維持されます。
