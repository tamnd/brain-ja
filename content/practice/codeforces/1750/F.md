 ## 問題の理解

 長さのバイナリ文字列がいくつあるかを数えるように求められます$n$「電気拡散」と呼ばれる特別な操作を使用して完全にオンにすることができます。 各文字列はサーバーの行を表します。`1`サーバーがオンラインであることを意味し、`0`オフラインであることを意味します。 この操作により、たとえば位置などの 2 つのオンライン サーバーを選択できるようになります。$i$そして$j$、その範囲内のオンライン サーバーの数が少なくともオフライン サーバーの数と同じである場合は、その間にあるすべてのサーバーをオンにします。 言い換えれば、1 の数がセグメントの長さの少なくとも半分である場合、セグメントは完全に 1 になります。 

目標は、この操作を繰り返し使用して、最終的にすべて 1 の文字列に変換できるすべての文字列をカウントすることです。 

制約は次のとおりです。$1 \le n \le 5000$そして$10 \le m \le 10^9$。 文字列の長さが最大 ​​5000 であることは、$O(n^3)$解決策はおそらく遅すぎるでしょう。$10^{11}$操作。 これにより、私たちは次のような方向に向かうことになります。$O(n^2)$またはより良いアプローチ。 弾性率$m$大きいため、すべての算術演算はモジュロで実行する必要があります$m$。 

単純なソリューションが失敗する可能性のあるエッジ ケースには、演算が適用できない可能性がある非常に短い文字列、孤立した 1 または 0 を含む文字列、およびすでにすべて 0 またはすべて 1 である文字列が含まれます。 たとえば、$n = 2$、唯一評価された文字列は`11`。 間違って考えてしまうと`10`または`01`評価どおり、私たちは過大評価するでしょう。 

## アプローチ

 ブルートフォースアプローチでは、すべてが列挙されます。$2^n$バイナリ文字列を作成し、各文字列に広がる電気のシミュレーションを試みます。 各文字列について、すべての 1 のペアをチェックし、それ以上の変更が発生しなくなるまで繰り返しスプレッドをシミュレートします。 これは正しい答えを与えますが、次の場合には完全に不可能です。$n = 5000$、 以来$2^{5000}$天文学的に大きいです。 

重要な観察は、この演算にはローカルな特性があるということです。つまり、セグメント内の 1 の数がその長さの少なくとも半分であれば、セグメントは完全に 1 になることができます。 これは、組み合わせ制約に変換できます。文字列は、連続する演算が徐々に増加して文字列全体をカバーする一連の演算が存在する場合に評価されます。 これにより、すべてのセグメントに拡散を伝播するのに十分な 1 が含まれるように、指定された数の 1 が分散されたシーケンスをカウントするという問題が軽減されます。 

この観察により、動的プログラミング ソリューションが可能になります。 定義する`dp[n]`評価された長さの文字列の数として`n`。 最初の文字列の位置とプレフィックスに含まれる文字列の数を考慮して、左から右に文字列を構築できます。 組み合わせ再帰には二項係数が含まれ、具体的には、すべてのプレフィックスが局所的に多数決条件を満たすように二項係数を配置する方法を数えます。 これにより、複雑さが指数関数的に軽減され、$O(n^2)$、それは実現可能です。

 ## アルゴリズムのチュートリアル

 1. すべての階乗とモジュラー逆関数を最大で事前計算します。$n$二項係数モジュロの高速計算を可能にする$m$。 これが必要なのは、分散のための組み合わせを頻繁に計算する必要があるためです。 
2. 動的プログラミング配列を初期化する`dp`どこ`dp[i]`評価された長さの文字列の数を格納します`i`。 
3.セット`dp[0] = 1`基本ケースとして、空の文字列を表します。 
4. 以下の文字列長を反復処理します。`1`に`n`。 それぞれの長さごとに`i`、1の数を考えてください`k`最初のセグメントで。 ある長さのセグメントに必要な 1 の最小数`i`は`(i + 1) // 2`過半数の条件を満たすこと。 
5. 有効なそれぞれについて`k`、選択する方法の数を計算します。`k`からのポジション`i`事前に計算された二項係数を使用して位置を決定します。 これを乗算します`dp[i - k]`評価されたサフィックスの数を表します。 和の剰余を累積する`m`の中へ`dp[i]`。 
6.充填後`dp[n]`、結果は`dp[n]`モジュロ`m`。 

不変条件は、各ステップで、`dp[i]`長さの文字列の数を正確にカウントします`i`ここで、最初のセグメントは電力拡散を使用して完全に伝播できます。 長さを積み上げ、すべてのセグメントが過半数の条件を満たしていることを確認することで、正確性を保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n, m = map(int, input().split())

    # Precompute factorials and inverses modulo m
    fac = [1] * (n + 1)
    inv = [1] * (n + 1)
    for i in range(1, n + 1):
        fac[i] = fac[i - 1] * i % m

    inv[n] = pow(fac[n], m - 2, m)
    for i in range(n - 1, -1, -1):
        inv[i] = inv[i + 1] * (i + 1) % m

    def C(a, b):
        if b < 0 or b > a:
            return 0
        return fac[a] * inv[b] % m * inv[a - b] % m

    dp = [0] * (n + 1)
    dp[0] = 1

    for length in range(1, n + 1):
        total = 0
        for ones in range((length + 1) // 2, length + 1):
            total = (total + C(length - 1, ones - 1) * dp[length - ones]) % m
        dp[length] = total

    print(dp[n] % m)

solve()
```階乗事前計算により、高速な計算が可能になります。`C(a, b)`一定時間内に。 外側のループは、最大の長さ全体にわたって反復されます。`n`。 内側のループは、長さごとに、有効な多数決の 1 をすべて繰り返します。 使用する`C(length - 1, ones - 1)`最初のものを先頭に配置し、残りのものを分配するアカウント。 乗算`dp[length - ones]`評価されたサフィックスを正しくカウントします。
