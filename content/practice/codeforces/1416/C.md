 ## 解決策
 ## 問題の理解

 負ではない整数の配列が与えられているので、数値を選択する必要があります$x$したがって、配列内のすべての要素を次のようにXORすると、$x$、結果の配列には反転ができるだけ少なくなります。 反転はインデックスのペアです$i < j$ここで、最初の数値は 2 番目の数値よりも大きくなります。 複数の値がある場合、$x$同じ最小反転数を与える場合、最小のものを選択します。 

配列のサイズは最大 300,000、数値は 10 億に達することがあります。 あらゆる可能性を試みる素朴なアプローチ$x$があるので明らかに不可能です$2^{30}$可能$x$最大の数値の値$10^9$、それは天文学的な大きさです。 各候補に対して直接反転を計算することも可能$x$だろう$O(n^2)$、大まかに言うと$10^{11}$最大の入力に対する操作。 したがって、数値の範囲ではなく、要素の数とビット数に応じてスケールするソリューションが必要です。 

微妙なケースの 1 つは、すべての数値が等しい場合です。 ゼロとの XOR 演算では配列が同じに保たれ、反転は生じませんが、ゼロ以外の数値との XOR 演算では順序が変更され、反転が生じます。 もう 1 つのエッジ ケースは、配列が厳密に増加または減少している場合です。 ビットごとの効果を考慮せずに XOR の後で値を並べ替える不注意なアプローチでは、反転のカウントを誤る可能性があります。 

## アプローチ

 強引なアイデアはシンプルです。あらゆる可能性を試してください。$x$0 から配列内の最大値まで、XOR された配列を計算して、反転をカウントします。 単純なネストされたループを使用して反転をカウントするのは、$O(n^2)$、さらに各候補に対してマージソートベースの反転カウンターを使用することもできます。$x$は$O(n \log n \cdot 2^{30})$、それは不可能です。 ブルートフォースが機能するのは、正確性が保証されているためです。$x$チェックされていますが、検索スペースが膨大なため失敗します。 

効率的なソリューションのための重要な洞察は、XOR がビットにどのような影響を個別に与えるかを観察することで得られます。 それぞれのビット$x$配列要素内の対応するビットのみを反転します。 これは、構築について考えることができることを意味します$x$最も重要なものから最も重要でないものまで、少しずつ。 各ステップで、このビットを反転するかどうかを決定できます。$x$これにより、2 つの数値グループ (このビットに 0 を持つグループと 1 を持つグループ) の間の反転が減少します。この分割全体で反転をカウントすることは効率的に行うことができ、上位ビットを修正すると、各ビットでの決定は独立します。 これにより、反転カウントのマージ ソートと同様に、問題がビットの分割統治に縮小されます。

 ## アルゴリズムのチュートリアル

 1. 最大数値の最上位ビット (最大の数値の場合はビット 29) から開始します。$10^9$) 配列内のすべての数値を考慮します。 
2. 現在のビットに従って配列を 2 つのグループに分割します。そのビットに 0 が含まれる数値は左に移動し、1 が含まれる数値は右に移動します。 
3. 2 つのグループ、つまり元の配列で左側のグループの要素が右側のグループの要素の後に現れるペアにわたる反転の数を数えます。 このカウントは、このビットを残した場合にどれだけの反転が存在するかを示します。$x$0として。 
4. 同様に、グループを交換します（このビットを反転します）。$x$) このクロスグループ数を反転します。 2 つのオプションを比較します。 反転によって反転が減少する場合は、このビットを$x$1に; それ以外の場合は 0 のままにします。 
5. 次の下位ビットの各サブグループに同じプロセスを再帰的に適用し、反転カウントを蓄積します。 
6. すべてのレベルからの反転カウントを合計し、選択したビットを記録して最小値を構築します。$x$。 

機能する理由: XOR は各ビットで独立して動作するため、1 つのビットを修正します。$x$そのビットが異なる数値間の反転にのみ影響します。 各位置で最適なビットを貪欲に選択することで、総反転が最小限に抑えられるようにします。 再帰的分割により、サブグループ内の反転も個別に最小化されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def count_inversions(a):
    if len(a) <= 1:
        return 0
    mid = len(a) // 2
    left = a[:mid]
    right = a[mid:]
    inv = count_inversions(left) + count_inversions(right)
    i = j = k = 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            a[k] = left[i]
            i += 1
        else:
            a[k] = right[j]
            inv += len(left) - i
            j += 1
        k += 1
    while i < len(left):
        a[k] = left[i]
        i += 1
        k += 1
    while j < len(right):
        a[k] = right[j]
        j += 1
        k += 1
    return inv

def solve(a, bit=29):
    if bit < 0 or len(a) <= 1:
        return 0, 0
    left = []
    right = []
    for num in a:
        if (num >> bit) & 1:
            right.append(num)
        else:
            left.append(num)
    inv_left, x_left = solve(left, bit-1)
    inv_right, x_right = solve(right, bit-1)
    cross = 0
    l_idx = r_idx = 0
    while l_idx < len(left) and r_idx < len(right):
        if left[l_idx] <= right[r_idx]:
            l_idx += 1
        else:
            cross += len(left) - l_idx
            r_idx += 1
    if cross > (len(left)*len(right) - cross):
        x = (1 << bit)
        total_inv = inv_left + inv_right + len(left)*len(right) - cross
    else:
        x = 0
        total_inv = inv_left + inv_right + cross
    return total_inv, x | x_left | x_right

def main():
    n = int(input())
    a = list(map(int, input().split()))
    inv_count, x = solve(a)
    print(inv_count, x)

if __name__ == "__main__":
    main()
```この解決策は、最初に数値をビットごとに最高位から最低位まで再帰的に分割します。 各再帰内で、マージ ソートと同様にグループ間の反転をカウントします。 ビットを反転するかどうかの選択は、どの構成が反転を少なくするかによって決まります。 選択したビットの OR の組み合わせにより再構築されます。$x$。
