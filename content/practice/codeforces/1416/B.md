 ## 問題の理解

 正の整数の配列が与えられ、最初の要素のインデックスに依存する線形演算を使用して要素のペア間で値を再分配できます。 具体的には、インデックスを選択できます$i$そして$j$および負でない整数$x$そして移動します$x \cdot i$からの単位$a_i$に$a_j$。 目標は最高のパフォーマンスを発揮することです$3n$これらの操作を実行して、すべての要素を等しくします。 この問題では、そのようなシーケンスを構築するか、不可能であることを報告するかを求められます。 

重要な制約は、すべての演算ですべての配列要素が非負に保たれなければならないということです。 また、配列のサイズ$n$まで到達できます$10^4$そしてそれがあるかもしれません$10^4$テストケース、合計$n$すべてのテスト ケースにわたって、$10^4$。 これにより、アルゴリズムが線形または線形に近いものになることが保証されます。$n$テスト ケースごとに、二次再分布シミュレーションを除外します。 個々の価値観$a_i$到達できる$10^5$したがって、Python では整数のオーバーフローは問題になりませんが、インデックスベースの乗算を考慮した演算を行うには慎重な算術演算が必要です。 

エッジ ケースには、すべての要素がすでに等しい配列、不可分性の制約により要素を均等に再分配できない配列、および最初の要素が後の要素に比べて小さいため、単純に任意の量を転送しようとすると一部の再分配が不可能になる配列が含まれます。 

たとえば、入力配列`[1, 2, 3, 4, 5, 6]`合計がバランスできないので、$21$で割り切れない$6$、複数のインデックスを移動する操作ではそれを修正できません。 割り算をチェックせずに単に単位を転送しようとする単純なアルゴリズムでは、誤って負の数が生成されたり、不可能性を検出できなかったりする可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、配列が等しくなるか、すべてのペアが使い果たされるまで、すべてのペア間で値を少しずつ移動させようとします。$3n$操作。 これは、各操作で合計が保持されるため、原理的には正しいですが、大規模な操作では実行不可能になります。$n$なぜなら、移動数はすべての要素の合計のオーダーになる可能性があるためです。$10^9$。 

重要な洞察は、超過値を最初の要素に向かって体系的に移動し、最初の要素から他のすべての要素にターゲット値を再分配する操作を構造化できることです。 具体的には、それぞれを作ることができます$a_i$から十分に移動することでインデックスで割り切れる$a_1$、それぞれの残りを転送します$a_i$に$a_1$、配列の合計を 1 つの場所に効果的に統合します。 最後に、正確な平均をすべての要素に広げます。 この決定論的な手順により、最大でも次のことが保証されます。$3n$操作: 1 つは割り算可能にする操作、もう 1 つは移動する操作$a_1$、すべての要素に配布するもの。 

この構造が機能するのは、演算がインデックス内で線形であるため、常に乗数を求めることができるためです。$x$剰余をゼロモジュロにする$i$。 まず要素を分割可能にし、次に再分配するという問題に単純化することで、潜在的に指数関数的な検索を線形な一連の操作に変換します。

 ## アルゴリズムのチュートリアル

 1. 合計を計算する$S$配列の。 もし$S$で割り切れない$n$、印刷$-1$均等化は不可能だからです。 
2. 空の操作リストを初期化します。 
3. インデックスごとに$i$から$2$に$n$の残りを確認してください。$a_i$モジュロ$i$。 ゼロでない場合は計算します$x = i - (a_i \% i)$そして操作を実行します$1 \to i$これで$x$、移動$x$からの単位$a_1$に$a_i$となることによって$a_i$で割り切れるようになる$i$。 この操作を記録します。 
4. それぞれについて$i$から$2$に$n$、今では$a_i$で割り切れます$i$、計算する$x = a_i // i$そして操作を実行します$i \to 1$これで$x$、分割可能な部分全体をに転送します。$a_1$。 この操作を記録します。 
5. この時点で、$a_1$合計額とその他すべてが含まれます$a_i$はゼロです。 目標値を計算する$t = S // n$。 それぞれについて$i$から$2$に$n$、操作を実行します$1 \to i$と$x = t$最終的に等しい値を各要素に分配します。 各操作を記録します。 
6. 操作の数と操作自体を出力します。 

この手順では、すべての要素が等しいことが保証されます$t$そして最大でも使用します$3n$操作: 1 つは分割性の調整、1 つは統合、もう 1 つは要素ごとの分配です。 

機能する理由: この操作では合計の合計が保存され、インデックスを乗算した転送により割り切れる単位を正確に制御できます。 各要素はそのインデックスの整数倍で増加または減少し、統合と再分配のステップで端数や負の値が生成されないようにします。 モジュロ ステップでは、要素を割り算するときに負になる要素がないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        total = sum(a)
        if total % n != 0:
            print(-1)
            continue
        ops = []
        target = total // n
        # Step 1: Make all a[i] divisible by i using a[0]
        for i in range(1, n):
            rem = a[i] % (i + 1)
            if rem != 0:
                x = (i + 1) - rem
                a[0] -= x
                a[i] += x
                ops.append((1, i + 1, x))
            # Now transfer a[i] to a[0]
            x = a[i] // (i + 1)
            a[i] -= x * (i + 1)
            a[0] += x * (i + 1)
            if x > 0:
                ops.append((i + 1, 1, x))
        # Step 2: Distribute target from a[0]
        for i in range(1, n):
            ops.append((1, i + 1, target))
        print(len(ops))
        for op in ops:
            print(*op)

if __name__ == "__main__":
    solve()
```このソリューションでは、まず割り算をチェックして不可能なケースを検出し、次にそれぞれを$a_i$からの転送を使用してインデックスで割り切れます。$a_1$。 その後、すべての可算金額を次の時点で統合します。$a_1$、次にターゲット値をすべての要素に広げます。 の選択$x$どちらのステップでも、要素が負になることはありません。 最後のループでは、操作の制約を考慮して常に平均を分配します。
