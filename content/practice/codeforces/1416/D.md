 ## 解決策
 ## 問題の理解

 無向グラフ上の動的接続の問題を次のように扱っています。`n`頂点と`m`エッジ。 各頂点は、最初は次の間の異なる整数を保持します。`1`そして`n`。 クエリには 2 つの種類があります。まず、指定された頂点から到達可能なすべての頂点の中で最大値を持つ頂点を特定し、その値をゼロに設定する必要があります。 次に、グラフからエッジを削除する必要があります。 出力は、最初のタイプのクエリに対する回答が表示される順序で構成されます。 

制約を考慮すると、`n`最大200,000まで可能です、`m`最大 300,000、クエリ数`q`500,000まで。 タイプ 1 のクエリごとに幅優先検索または深さ優先検索を実行する単純なソリューションでは、各検索に O(n + m) 時間がかかる可能性があるため、非常に遅くなります。 同様に、削除ごとに単純にグラフを変更すると、再構築にコストがかかる可能性があります。 この問題により、頂点の初期値が明確であることが保証されるため、最大値を追跡するときに一意性に依存するデータ構造を使用できるようになります。 

到達可能なすべての頂点がすでにゼロに設定されている場合、微妙なエッジ ケースが発生します。 この場合、クエリは値を返す必要がありますが、接続されたコンポーネント内の頂点にはすべて 0 が含まれているため、どの頂点でも返すことができます。 もう 1 つのエッジ ケースは、エッジとクエリの順序が繰り返し削除されることで、接続されたコンポーネントが動的に分割される可能性があります。 不注意な実装により削除が効率的に処理されない場合、誤った最大値が報告される可能性があります。 

## アプローチ

 ブルート フォース アプローチは、グラフをシミュレートし、クエリ頂点から開始して DFS または BFS を実行することによってタイプ 1 クエリを実行し、エッジを削除することによってタイプ 2 クエリを実行することです。 タイプ 1 のクエリごとに O(n + m) 時間がかかる可能性があります。 最大 500,000 のクエリを想定すると、このアプローチでは最悪の場合、10^11 のオーダーの操作が必要になる可能性がありますが、これは実行不可能です。 

最適なアプローチは、問題を逆に効率的に解決できるという事実を利用することです。 順方向クエリ処理中にエッジを削除する代わりに、最終的に削除されるエッジをマークし、グラフの最終状態 (すべての削除後) から開始することができます。 逆に、タイプ 2 のクエリはエッジの追加に対応します。 クエリを逆方向に処理し、Disjoint Set Union (DSU) データ構造で接続コンポーネントを維持することにより、接続コンポーネントを効率的に追跡できます。 各コンポーネントは、それに含まれる頂点値を保存するデータ構造 (ソートされたセットなど) を維持するため、O(log n) 時間で最大値を抽出できます。 タイプ 2 のクエリをリバースするときは、2 つのコンポーネントをマージし、値のセットを更新します。 タイプ 1 のクエリを逆方向に処理すると、最大値を記録し、それを調整しながら最終的に正しい答えを順方向に再現できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(q*(n+m)) | O(n+m) | 遅すぎる |
 | 逆クエリを使用した DSU | O((n+q) log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力を解析し、エッジ、初期頂点値、およびクエリのリストを保存します。 順方向処理中にどのエッジが削除されるかをマークする配列を維持します。 
2. 各頂点が独自のコンポーネントとして開始される DSU を初期化します。 各コンポーネントは、ソートされたセットを保持します。`p_i`その頂点の値。 これにより、コンポーネント内の最大値を迅速に取得できます。 
3. クエリを逆に処理します。 タイプ 1 のクエリの場合、頂点の現在のコンポーネントの最大値を記録します。`v`別の回答配列で。 タイプ 2 のクエリの場合、「追加」されるエッジのコンポーネントをマージし、最大値を維持するように値のセットを更新します。 
4. すべてのクエリを逆に処理した後、元のクエリの順序と一致するように、タイプ 1 のクエリの応答配列を逆にします。 頂点値が最大値として使用される場合は常に、対応するコンポーネントのセットから頂点値を削除して、前方処理で頂点値をゼロに設定することをシミュレートします。 
5. すべてのタイプ 1 クエリに対する回答を順番に出力します。 

これが機能するのは、DSU がリバース処理のどの時点においても、各頂点が 1 つのコンポーネントに確実に属することを保証するためです。 各コンポーネントに関連付けられたセットは、そのコンポーネント内のすべての頂点の値を正しく追跡します。 クエリを逆にすることで、動的なエッジ削除の複雑さを回避しながら、最大値の選択と頂点のゼロ化を正確にシミュレートします。 

## Python ソリューション```python
import sys
import bisect
input = sys.stdin.readline

class DSU:
    def __init__(self, n, values):
        self.par = list(range(n))
        self.size = [1]*n
        self.values = [{values[i]} for i in range(n)]
    
    def find(self, x):
        while x != self.par[x]:
            self.par[x] = self.par[self.par[x]]
            x = self.par[x]
        return x
    
    def merge(self, x, y):
        x = self.find(x)
        y = self.find(y)
        if x == y:
            return
        if self.size[x] < self.size[y]:
            x, y = y, x
        self.par[y] = x
        self.size[x] += self.size[y]
        self.values[x].update(self.values[y])
        self.values[y].clear()

def solve():
    n, m, q = map(int, input().split())
    p = list(map(int, input().split()))
    edges = [tuple(map(lambda x:int(x)-1, input().split())) for _ in range(m)]
    queries = []
    deleted = [False]*m
    for _ in range(q):
        line = input().split()
        if line[0] == '1':
            queries.append((1, int(line[1])-1))
        else:
            idx = int(line[1])-1
            queries.append((2, idx))
            deleted[idx] = True

    dsu = DSU(n, p)
    for i, (a, b) in enumerate(edges):
        if not deleted[i]:
            dsu.merge(a, b)
    
    ans = []
    for typ, val in reversed(queries):
        if typ == 1:
            root = dsu.find(val)
            if dsu.values[root]:
                mx = max(dsu.values[root])
                ans.append(mx)
                dsu.values[root].remove(mx)
            else:
                ans.append(0)
        else:
            a, b = edges[val]
            dsu.merge(a, b)
    
    for val in reversed(ans):
        print(val)

if __name__ == "__main__":
    solve()
```DSU は接続されたコンポーネントを効率的に維持し、各コンポーネントは現在の値セットを追跡します。 クエリを逆に処理すると、動的削除の複雑さが回避されます。 最大値の削除は、順方向クエリの実行中に頂点をゼロに設定することをシミュレートします。
