 ## 解決策
 ## 問題の理解

 長さ _n_ の正の整数のシーケンスが与えられます。ここで、最初の要素は最初は不明で、残りの _n - 1_ 要素が提供されます。 「cow プログラム」は、_x_ = 1 と _y_ = 0 で始まる 2 つの整数変数 _x_ と _y_ を定義します。プログラムは、2 つの操作を繰り返し実行します。まず、_x_ の位置にある現在の要素によって _x_ と _y_ の両方をインクリメントし、次に同じ値で _y_ を再度インクリメントし、同時にその値だけ _x_ をデクリメントします。 _x_ が [1, n] の範囲外に移動するとプログラムは停止します。 

このタスクは、シーケンスの考えられる最初の要素 (1 から n - 1) ごとに、プログラムの実行後の _y_ の最終値、またはプログラムが終了しない場合は -1 を決定することです。 これは基本的に、開始値が前方ジャンプと後方ジャンプの両方に影響を与えるシーケンス内の動的パスをシミュレートし、サイクルの可能性を生み出します。 

主な制約は、_n_ が最大 2・10^5 まで可能であり、シーケンスの値が最大 10^9 まで可能であることです。 各実行をステップごとにシミュレートしようとするアルゴリズムでは、開始値ごとに O(n) ステップが必要となる可能性があり、したがって全体では O(n^2) ステップが必要になります。 これでは遅すぎます。 したがって、サイクルを正しく検出しながら完全なシミュレーションを回避するアプローチが必要です。 

明らかでないエッジ ケースには、ジャンプが有効範囲からすぐに抜けるシーケンス、無限振動を引き起こすシーケンス、または複数のジャンプ後に最終的に大きな _y_ 値が蓄積されるシーケンスが含まれます。 たとえば、_x_ = 1 から始まる _a_ = [3, 1] の場合、最初のステップでは _x_ が 4 に増分され (終了)、_y_ = 3 になりますが、より小さい開始値は無限にループする可能性があります。 単純なシミュレーションでは、これらのサイクルを見逃したり、検出するのに時間がかかりすぎたりします。 

## アプローチ

 ブルートフォース手法では、各開始位置からプログラムをシミュレートします。 各ステップで、2 つの操作に従って _x_ と _y_ を更新し、_x_ が範囲外になった場合、または以前に訪問した状態 (サイクルを示す) を検出した場合に終了します。 このアプローチは正しいですが、各シミュレーションがシーケンスを何度も横断する可能性があるため、最悪の場合は O(n^2) になります。 n が 2・10^5 までの場合、これは 4・10^10 の演算に達する可能性がありますが、これは実行不可能です。 

最適化のための重要な洞察は、問題の構造により、メモ化を伴う動的プログラミングを使用して結果を計算できるということです。 各位置 _i_ は別の位置からの結果 (前方ステップの場合は _i + a[i]_、後退ステップの場合は _i - a[i]_) にのみ依存するため、計算された各位置の結果を保存できます。 すでに計算されている位置が見つかった場合は、その値を再利用します。 現在の再帰スタック内に位置が見つかった場合、サイクルが検出されたことになるため、結果は -1 になります。 これにより、各位置が計算で 1 回、メモ化の伝播で 1 回ずつ、最大 2 回アクセスされるため、全体の複雑さが O(n) に軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | メモ化を伴う DP | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を初期化する`dp`サイズ n+1 の`None`、各開始位置の _y_ の計算値を保存します。 値 -1 は、サイクルが検出されたことを示します。 
2. 再帰関数を定義する`solve(i)`これは、インデックス _i_ で始まるプログラムの最終 _y_ を返します。 _i_ が範囲外の場合、_y_ の累積が停止されるため、0 を返します。 
3. で`solve(i)`、どうかを確認してください`dp[i]`はすでに計算されています。 「はい」の場合は、再計算を避けるためにそれを返します。 
4. 現在のインデックスをマークします`i`設定により「進行中」として`dp[i]`-2 などのセンチネル値に設定します。 これにより、サイクル検出が可能になります。 
5. 次の前進ステップのインデックスを計算します。`j = i + a[i]`。 もし`j`範囲外の場合、プログラムは即座に終了し、`dp[i] = a[i]`。 
6. それ以外の場合は、バックワード ステップ インデックスを計算します。`k = j - a[j]`。 再帰的に解決する`solve(k)`そこから結果を取得します。 もし`solve(k)`が -1 である場合、-1 を次の値に伝播します。`dp[i]`。 
7. それ以外の場合は更新します`dp[i] = a[i] + a[j] + solve(k)`。 これにより、両方のステップと下流の累積における _y_ への増分が考慮されます。 
8. 戻る`dp[i]`位置 _i_ の結果として。 
9. 開始位置 1 から n-1 までを繰り返し、呼び出します。`solve(i)`をクリックし、結果を出力します。 

不変条件とは、`dp[i]`_y_ の最終値、またはサイクルが存在する場合は -1 が含まれます。 再帰呼び出しは常にシーケンスによって厳密に決定された位置に移動するため、不正な値が伝播することはありません。 サイクル検出はセンチネル マーカーによって処理され、O(n) でのアルゴリズムの終了が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(1 << 20)

n = int(input())
a = [0] + list(map(int, input().split()))  # 1-based indexing
dp = [None] * (n + 1)  # memoization array

def solve(i):
    if i <= 0 or i > n:
        return 0  # program terminates
    if dp[i] == -2:  # cycle detected
        return -1
    if dp[i] is not None:
        return dp[i]
    
    dp[i] = -2  # mark as in progress
    j = i + a[i]
    if j > n:
        dp[i] = a[i]
    else:
        k = j - a[j]
        res = solve(k)
        if res == -1:
            dp[i] = -1
        else:
            dp[i] = a[i] + a[j] + res
    return dp[i]

for i in range(1, n):
    print(solve(i))
```このソリューションでは、問題の _x_ 定義に直接マッピングするために 1 から始まるインデックスを設定します。 の`solve`関数は、センチネル値 -2 を使用して、再帰呼び出しスタック内のサイクルを検出します。 範囲外の位置は直ちにゼロを返し、終了に相当します。 _y_ の累積は、現在位置と再帰的な下流の結果の合計として処理されます。
