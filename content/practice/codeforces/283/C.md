 ## 解決策
 ## 問題の理解

 私たちは持っています`n`コインの種類。 コインの種類`i`価値がある`a[i]`、そしてそのタイプの任意の非負数のコインを受け取ることができます。 

選択したすべてのコインの合計価値は正確に一致する必要があります`t`。 

さらに、次の形式の不等式制約が与えられます。`count[b] > count[c]`制約は特殊です。 すべてのインデックスは、制約の左側に最大 1 回、右側に最大 1 回出現します。 この構造が重要な観察結果であることがわかります。 

ベクトルの数を数えなければなりません`(count[1], count[2], ..., count[n])`すべての不平等を満たし、合計価値を生み出す`t`。 答えは必須です`1,000,000,007`。 

制約が大きいため、直接列挙することは不可能です。 目標金額達成`10^5`、コインの種類の数が達するまで、`300`。 考えられるコインの数を反復しようとするソリューションは、すぐに爆発します。 目標合計は、複雑さが次の値にほぼ比例する動的プログラミング ソリューションを示唆しています。`n * t`、 なぜなら`300 * 100000 = 3 * 10^7`操作は最適化されたコードで引き続き管理できます。 

不等式により、いくつかの微妙な状況が生じます。 

考慮する```
2 2 10
1 1
1 2
2 1
```制約が必要とするのは、```
x1 > x2
x2 > x1
```それは不可能です。 正しい答えは、`0`。 

制約をローカルでのみ処理する不用意な実装では、この矛盾を検出できない可能性があります。 

別の例は、より長いサイクルです。```
3 3 20
1 1 1
1 2
2 3
3 1
```これには必要です```
x1 > x2 > x3 > x1
```それも不可能です。 

不平等により、すでに超過している最小貢献額が強制される場合、別の落とし穴が発生します。`t`。 

例えば：```
2 1 1
5 5
1 2
```以来`x1 > x2`、最小の有効な代入は次のとおりです。`(1,0)`、 価値`5`。 合計値に達しました`1`それは不可能ですので、答えは`0`。 

ソリューションでは、これらすべての状況を自動的に検出する必要があります。 

## アプローチ

 ブルートフォース手法では、コインの種類ごとに可能なすべてのカウントを試し、合計値が等しいかどうかを確認します。`t`そしてすべての不平等は成り立ちます。 

たとえすべてのコインの価値が`1`、単一の変数には最大で`100000`異なる価値観。 と`300`変数の場合、検索空間は天文学的になります。 

不等式は、カウントが独立していないことを示唆しています。 すべてのノードはソースとして最大 1 回、宛先として最大 1 回しか表示されないため、制約グラフの形状は非常に制限されています。 

有向エッジを作成します。```
b -> c
```意味```
count[b] > count[c]
```すべての頂点には最大でも次数があるため、`1`最大でも出次数`1`、すべての接続されたコンポーネントはチェーンまたはサイクルのいずれかです。 

サイクルが発生するとシステムは即座に不可能になります。```
x1 > x2 > ... > xk > x1
```したがって、重要なのはチェーンだけです。 

ここで 1 つのチェーンを考えてみましょう。```
v1 -> v2 -> ... -> vk
```つまり```
x1 > x2 > ... > xk
```カウントを直接保存する代わりに、新しい非負の変数を定義します。```
y1 = x1 - x2 - 1
y2 = x2 - x3 - 1
...
y(k-1) = x(k-1) - xk - 1
yk = xk
```すべての有効な割り当ては、非負の 1 つの選択肢に正確に対応します。`y`価値観、そしてその逆も同様です。 

置換後、チェーンは次のような影響を及ぼします。```
constant + Σ(weight_i * yi)
```定数は必須から来ています`+1`厳密な不平等によって必要とされるギャップ。 

すべての変数は独立した非負の変数になります。 すべてのチェーンを処理すると、問題全体は次のようになります。 

の非負の解の数を数えます。```
Σ(weight_i * yi) = remaining_target
```これはまさに古典的な完全なナップザック カウンティング DP です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | 指数 | 遅すぎる |
 | 最適 | O(n・t) | O(t) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各制約を適用した有向グラフを構築します。`b > c`エッジになる`b -> c`。 
2. すべてのノードの入次数と出力近傍を保存します。 入力保証のため、各ノードは最大でも次数を持ちます。`1`最大でも出次数`1`。 
3. indegree を使用してすべてのノードから開始します`0`。 このようなノードはチェーンの先頭です。 
4. 各チェーンを頭から尾までトラバースし、頂点を順番に収集します。 
5. 頂点を持つチェーンの場合```
v1, v2, ..., vk
```プレフィックスの合計を計算する```
pref[i] = a[v1] + ... + a[vi]
```6.追加```
pref[1] + pref[2] + ... + pref[k-1]
```世界的な義務的貢献に向けて`base`。 

これは、厳密な不等式によって強制される最小値です。 
7. 変換された変数ごとに 1 つの DP 重みを作成します。 

のために`i < k`、の係数`yi`は`pref[i]`。 

のために`yk`、係数は`pref[k]`。 
8. チェーン内のすべての頂点を訪問済みとしてマークします。 
9. すべてのルートを処理した後、すべての頂点が訪問されたかどうかを確認します。 

未訪問の頂点はすべてサイクルに属します。 その場合の答えは、`0`。 
10. しましょう```
T = t - base
```もし`T < 0`、出力`0`。 
11. 完全なナップザックのカウント DP を実行します。 

初期化:```
dp[0] = 1
```12. 生成されたウェイトごとに`w`、 実行する：```
for s from w to T:
    dp[s] += dp[s - w]
```13. 出力`dp[T]`。 

### なぜ効果があるのか

 連鎖の中の変容```
yi = xi - x(i+1) - 1
```厳密な不等式を削除し、単純な非負の変数に置き換えます。 

有効な間のマッピング`x`代入と非負`y`割り当ては単射的です。 ソリューションが失われることも、無効なソリューションが導入されることもありません。 

置換後、すべてのチェーンは固定の必須値に加えて、独立した非負変数の線形結合を提供します。 すべてのチェーンを結合すると、単一の方程式が得られます。```
Σ(weight_i * yi) = T
```このような方程式の非負の解を数えることは、まさに完全なナップザック数え問題です。 サイクルは不可能な厳密な不等式系に対応するため、それらを拒否するのは正しいことです。 したがって、カウントされたすべての DP 状態は 1 つの有効なコイン構成に対応し、その逆も同様です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 1000000007

def solve():
    n, q, t = map(int, input().split())
    a = list(map(int, input().split()))

    nxt = [-1] * n
    indeg = [0] * n

    for _ in range(q):
        b, c = map(int, input().split())
        b -= 1
        c -= 1
        nxt[b] = c
        indeg[c] += 1

    visited = [False] * n
    weights = []
    base = 0

    for i in range(n):
        if indeg[i] == 0:
            chain = []
            cur = i

            while cur != -1 and not visited[cur]:
                visited[cur] = True
                chain.append(cur)
                cur = nxt[cur]

            k = len(chain)
            pref = [0] * k

            for j in range(k):
                pref[j] = a[chain[j]]
                if j:
                    pref[j] += pref[j - 1]

            for j in range(k - 1):
                base += pref[j]
                weights.append(pref[j])

            weights.append(pref[k - 1])

    if not all(visited):
        print(0)
        return

    target = t - base
    if target < 0:
        print(0)
        return

    dp = [0] * (target + 1)
    dp[0] = 1

    for w in weights:
        if w > target:
            continue
        for s in range(w, target + 1):
            dp[s] += dp[s - w]
            if dp[s] >= MOD:
                dp[s] %= MOD

    print(dp[target] % MOD)

solve()
```グラフの構築では、各ノードが最大 1 つの入力エッジと 1 つの出力エッジを持つという特殊なプロパティを使用します。 これにより、すべてのコンポーネントを単純なチェーンまたはサイクルとして表すことができます。 

の`base`変数には、厳密な不等式によって強制される最小値が格納されます。 この最小値がすでに超えている場合`t`、解決策は存在しません。 

生成された`weights`は、変換された非負変数に正確に対応します。 対応する変数は負でない値を取ることができるため、各重みは何度でも使用できます。 そのため、完全なナップサック遷移では合計が昇順に反復されます。 

周期の検出は微妙です。 すべてのチェーンは、次数を持つノードから始まります`0`。 いくつかの頂点がその後訪問されないままになっている場合、その頂点はチェーンに属することができず、サイクル内に存在する必要があります。 このようなコンポーネントには有効な割り当てがありません。

 ## 特殊なケース

 矛盾するサイクルを考えてみましょう。```
2 2 10
1 2
1 2
2 1
```どのノードにも次数がありません`0`, そのため、チェーントラバースは開始されません。 両方の頂点は未訪問のままになります。 アルゴリズムはトラバーサルフェーズ後にこれを検出し、すぐに戻ります。`0`。 これは次の事実と一致します`x1 > x2 > x1`不可能です。 

より長いサイクルを考えてみましょう。```
3 3 20
1 1 1
1 2
2 3
3 1
```繰り返しますが、すべての頂点には次数があります`1`。 ルートが存在しません。 すべての頂点は未訪問のままであり、答えは次のとおりです。`0`。 

必須の最小値を下回る目標を検討してください。```
2 1 1
5 5
1 2
```チェーンにはプレフィックス合計があります`[5,10]`。 義務的な寄付金は、`5`, したがって、残りのターゲットは次のようになります。`-4`。 アルゴリズムは戻ります`0`DPを実行する前に。 

これらのケースは、まさに単純な実装が失敗することが多いケースですが、チェーン分解と最小寄与変換によって自然に処理されます。
