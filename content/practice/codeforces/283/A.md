 ## 解決策
 ## 問題の理解

 単一の要素を含むシーケンスから始めます。`0`、次のシーケンスを実行します。`n`操作。 操作では、次の 3 つの方法でシーケンスを変更できます。`a`ある値による要素`x`、末尾に新しい番号を追加するか、最後の要素を削除します。 各操作の後に、シーケンス内のすべての要素の平均が必要になります。 出力は、少なくとも 6 桁の精度を持つ浮動小数点数です。 

重要な制約は次のとおりです。`n`は最大 2・10⁵ まで可能で、シーケンスは要素を追加することで拡張できます。 最初にすべてを明示的に変更する単純なアプローチ`a`タイプ 1 の各演算は O(n) 個の要素に影響する可能性があるため、加算演算中の要素は合計で最大 O(n²) を必要とする可能性があります。 2 秒の制限時間を考えると、これは遅すぎます。 関係する整数は小さい (絶対値 ≤ 103) ため、Python では数値オーバーフローは問題になりませんが、浮動小数点平均を計算する場合は注意が必要です。 

単純な実装が誤って処理する可能性のあるエッジ ケースには、要素が 2 つだけある場合にタイプ 3 の操作 (最後の要素を削除) を実行すること、および元のシーケンスの一部ではなく動的に追加された要素に対してタイプ 1 の追加を実行することが含まれます。 たとえば、シーケンスが次の場合、`[0, 2]`そして私たちはパフォーマンスします`1 2 3`(最初の 2 つの要素に 3 を加算します)、結果は次のようになります。`[3, 5]`。 最初の要素のみを更新するか、追加された値を考慮しない不注意なアプローチでは、誤った平均が生成されます。 

## アプローチ

 ブルートフォース手法はシンプルです。シーケンス全体をリストとして維持します。 タイプ 1 の操作ごとに、最初の操作を繰り返します。`a`要素と追加`x`。 タイプ 2 の場合は追加します`k`。 type-3 の場合は、最後の要素を削除します。 各演算の後、シーケンスを合計し、その長さで割ります。 これは小規模な場合に機能します`n`、しかし、`n ≈ 2·10⁵`O(n) 要素に影響を与えるタイプ 1 演算を繰り返すと、演算回数は O(n²) になり、これはおよそ 4・10¹⁰ となり、許容時間を大幅に超えます。 

重要な洞察は、すべての要素の正確な値を個別に知る必要はないということです。 必要なのは平均値だけです。 タイプ 1 の操作は常にシーケンスのプレフィックスに影響します。 プレフィックス長ごとの増分を格納するセカンダリ アレイを使用して、これらの更新を効率的に追跡できます。 させて`increment[i]`最初に適用される追加価値の合計を表します`i+1`要素。 シーケンスの累計を保持することによって (`total_sum`)、タイプ 1 操作の場合、この合計を O(1) で更新できます。`x`最初に`a`要素は合計を増加させます`a * x`。 タイプ 2 およびタイプ 3 の操作は、最後の要素を個別に保存し、それに応じて合計を維持することによって処理できます。 これにより、全体の複雑さが O(n) に軽減され、入力範囲に適したものになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | プレフィックス増分 + 累計 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.初期化`seq`として`[0]`、`increments`として`[0]`、 そして`total_sum`0として。`increments[i]`に適用される追加の値を保存します`seq[i]`タイプ 1 の操作によるものです。 
2. 各操作について、そのタイプを読み取ります。`t`。 
3. もし`t`は 1、読み取ります`a`そして`x`。 アップデート`increments[a-1]`追加することで`x`。 アップデート`total_sum`追加することで`a * x`。 これは追加の効果をキャプチャします。`x`最初に`a`各要素を個別に変更することなく、要素を編集できます。 
4. もし`t`は 2、読み取ります`k`。 追加`k`に`seq`そして追加します`0`に`increments`。 アップデート`total_sum`追加することで`k`。 
5. もし`t`3 の場合、最後の要素を削除します`last_val`から`seq`。 その増分値を次から取得します。`increments[-1]`そしてそれを最後から 2 番目の要素から減算します。`increments`そのため、プレフィックスの合計は一貫したままになります。 アップデート`total_sum`引き算して`last_val + increments[-1]`。 最後の要素を削除します`increments`。 
6. 各操作の後、次のように平均を計算します。`total_sum / len(seq)`それを 6 桁の 10 進数で出力します。 

**なぜ効果があるのか**

 の`increments`配列により、シーケンスの各プレフィックスがタイプ 1 演算からの累積加算を正確に追跡することが保証されます。 タイプ 2 およびタイプ 3 の操作は合計を明示的に更新し、正しい累計を維持します。 から計算された平均`total_sum`長さで割ったもの`seq`シーケンスが完全に再構築されない場合でも、常に現在のシーケンスを反映します。 これにより、操作ごとに O(1) の正確さが維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
seq = [0]
increments = [0]
total_sum = 0

for _ in range(n):
    op = list(map(int, input().split()))
    t = op[0]
    
    if t == 1:
        a, x = op[1], op[2]
        increments[a-1] += x
        total_sum += a * x
    elif t == 2:
        k = op[1]
        seq.append(k)
        increments.append(0)
        total_sum += k
    else:
        last_val = seq.pop()
        inc = increments.pop()
        total_sum -= last_val + inc
        if increments:
            increments[-1] += inc
    print(total_sum / len(seq))
```ソリューションが初期化されます`seq`0 を付けます。`increments`アレイミラー`seq`長さ的には。 タイプ 1 操作は、最後に影響を受けたプレフィックスを更新します。`increments`そして`total_sum`。 Type-2 は、新しい値と対応する 0 を追加します。`increments`。 Type-3 は最後の要素をポップし、その値を正しく伝播するためにプレフィックスの増分を調整し、合計を更新します。 使用する`total_sum`平均が O(1) 時間で計算されることを保証します。
