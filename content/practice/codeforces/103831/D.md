 ## 解決策
 ## 問題の理解

 この問題は、グリッド上に配置された迷路をナビゲートするものとみなすことができます。 グリッドの各セルは、歩くことができる空きスペース、または立ち入ることができないブロックされたセルのいずれかを表します。 開始位置と目標位置が与えられます。タスクは、開始位置から目標位置まで移動するために必要な最小移動数を決定することです。各移動は、グリッド内の 4 つの隣接するセルの 1 つにステップすることで構成されます。 

入力は、開始位置と終了位置をマークする特別なセルとともに、グリッド レイアウトを行ごとに記述します。 移動はグリッド境界内でのみ許可され、ブロックされていないセルを通過する場合にのみ許可されます。 出力は、最短パス長を表す単一の整数、または有効なパスが存在しない場合はターゲットに到達できないことを示す信号です。 

複雑さの観点から見ると、グリッドが大きくなりすぎて、すべてのパスを明示的に列挙しようとするソリューションが実行不可能になる可能性があります。 すべての可能なルートを探索する単純な DFS は、同じ状態を指数関数的に何度も再訪する可能性があります。 合計で最大約 10^5 セル以上のサイズのグリッドでは、BFS またはマルチソース BFS などの線形時間グラフ走査手法のみが実行可能であるとすぐに予想する必要があります。 これにより、同じセルに対して繰り返し再計算を行うアプローチが効果的に排除されます。 

正確さのためには、いくつかの特殊なケースが重要です。 開始セルとターゲットが同じセルの場合、答えはゼロとなり、トラバースは必要ありません。 開始点またはターゲットのいずれかが四方をブロックされたセルで囲まれている場合は、両方の終点が有効であってもパスは存在しません。 グリッドに長くて狭い廊下が含まれている場合、微妙なケースが発生します。 ナイーブな DFS は、最適なトラバーサル戦略で各セルが概念的に 1 回だけアクセスされる場合でも、異なる再帰的ブランチからコリドー セルを繰り返し再訪問し、タイムアウトになる可能性があります。 

## アプローチ

 自然な出発点は、各セルがノードであり、直交して隣接する通過可能なセルの間にエッジが存在するグラフとしてグリッドを考えることです。 ブルートフォースのアイデアは、開始セルからターゲットまでの可能なパスをすべて試し、最短のものを追跡することです。 これは、DFS または再帰的バックトラッキングを介して実行でき、異なるパスに沿ってセルを訪問済みまたは未訪問としてマークします。 

このアプローチは、最終的にすべての有効なルートを列挙するため、原理的には正しいですが、その実行時間は爆発的に増加します。 最悪の場合、各セルは最大 4 つの方向に分岐する可能性があり、パスごとの訪問追跡を行ったとしても、グリッド内の個別の単純なパスの数はセルの数で指数関数的に増加する可能性があります。 これは、中程度のサイズのグリッドでもすぐに不可能になります。 

重要な観察は、すべての移動には等しいコストがかかるということです。 これを認識すると、問題は重み付けされていないグラフの最短経路問題になります。 このようなグラフでは、ソースからの距離が大きい順にノードを探索するため、幅優先検索が最適です。 初めてセルに到達したときに、そこへの最短経路がすでに見つかっているため、再度そのセルにアクセスする必要はありません。 

これにより、問題全体がソース セルから始まる単一の BFS に縮小され、ターゲットに到達するか、到達可能なすべてのセルが使い果たされるまで、層ごとに外側に拡張されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | パス上のブルート フォース DFS | 指数 | O(n) 再帰 | 遅すぎる |
 | グリッド グラフ上の BFS | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. グリッドを、各セルを最大 4 つの隣接セルを持つノードとして扱うことができるトラバーサル構造に変換します。 このメンタル モデルにより、グラフ トラバーサル手法を直接適用できるようになります。 
2. キューを初期化し、開始セルを距離 0 とともに挿入します。 また、各セルが最大 1 回処理されるように、訪問された構造も維持します。 
3. キューの先頭を繰り返し抽出します。 現在のセルが対象セルであるかどうかを確認します。 そうである場合、BFS は最小距離の順序付けを保証するため、現在の距離が答えになります。 
4. それ以外の場合は、隣接する 4 つの方向すべてを考慮します。 各近隣について、それがグリッド境界内にあるか、ブロックされていないか、まだ訪問していないかを確認します。 これらの条件を満たしている場合は、訪問済みとしてマークし、距離を 1 つ増やしてキューにプッシュします。 
5. キューが空になるまで続行します。 目標が決して達成できない場合は、不可能であると返します。 

### なぜ効果があるのか

 正確さは、BFS が開始点からの距離が減少しない順序でセルを処理するという不変条件から得られます。 セルが最初にキューに入れられると、代替パスには少なくとも同じかそれ以上の手順が必要であり、BFS 順序の後半でのみ検出されるため、セルは可能な限り最短のパスを通じて到達されます。 すべてのエッジの重みが等しいため、後の発見によってすでに訪問したセルへのより短いパスが得られるというシナリオはありません。 これにより、初めてターゲット セルに到達したときに、移動回数がすでに最小限に抑えられていることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n, m = map(int, input().split())
    grid = []
    for _ in range(n):
        grid.append(list(input().strip()))

    start = end = None

    for i in range(n):
        for j in range(m):
            if grid[i][j] == 'S':
                start = (i, j)
            if grid[i][j] == 'E':
                end = (i, j)

    if start == end:
        print(0)
        return

    dist = [[-1] * m for _ in range(n)]
    sx, sy = start
    ex, ey = end

    q = deque()
    q.append((sx, sy))
    dist[sx][sy] = 0

    dirs = [(1, 0), (-1, 0), (0, 1), (0, -1)]

    while q:
        x, y = q.popleft()

        if (x, y) == (ex, ey):
            print(dist[x][y])
            return

        for dx, dy in dirs:
            nx, ny = x + dx, y + dy
            if 0 <= nx < n and 0 <= ny < m:
                if dist[nx][ny] == -1 and grid[nx][ny] != '#':
                    dist[nx][ny] = dist[x][y] + 1
                    q.append((nx, ny))

    print(-1)

if __name__ == "__main__":
    solve()
```このソリューションはグリッドを構築し、開始位置と終了位置を特定してから、両端キューを使用して BFS を実行します。 距離配列は 2 つの役割を同時に果たします。訪問したセルをマークし、開始点からの最短距離を保存します。 これにより、別の訪問配列が必要なくなります。 

よくある微妙な間違いは、ノードをキューからポップするときにのみノードを訪問済みとしてマークすることです。 これにより、同じセルの複数のエンキューが発生し、実行時間が大幅に増加する可能性があります。 プッシュ時にすぐにマークすると、各セルが最大 1 回キューに入ることが保証されます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、開始セルと終了セルが同じセルである場合です。 通常、BFS は開始をキューに入れてすぐに終了しますが、明示的なチェックがなければ、依然として近隣ノードを不必要に処理する可能性があります。 このソリューションは、すぐにゼロを返すことでこれを処理します。 

もう 1 つのケースは、ターゲットが完全に壁で囲まれている場合です。 この状況では、BFS は到達可能なすべてのセルを探索しますが、ターゲットには到達せず、その位置の距離配列は -1 のままになります。 最後の空のキュー条件では、正しく -1 が生成されます。 

3 番目のケースは、長くて狭い廊下です。 視覚的にはアルゴリズムが繰り返し行ったり来たりしているように見えても、各セルは 1 回だけアクセスされるため、BFS は依然として正しく動作します。 訪問済みマーキングにより、循環が発生せず、線形の複雑さが維持されます。
