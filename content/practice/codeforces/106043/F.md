 ## 解決策
 ## 問題の理解

 接続された無向重み付きグラフが与えられます。 頂点から開始`s`そして頂点で終わる`t`、必ずしも単純な道ではなく、どんな道でも歩くことができます。 頂点とエッジは任意に何度でも再訪できます。 

すべてのウォークには合計の重みがあり、これは通過したすべてのエッジの重みを合計することによって得られます。 私たちはその合計モジュロだけを気にします`k`。 

タスクは、モジュロの個別の剰余がいくつあるかを決定することです。`k`からのすべての可能なウォークの中に出現する可能性があります`s`に`t`。 

グラフには最大で次のものを含めることができます`10^5`頂点と`2·10^5`テストケースごとのエッジ。 単純なパスの数でさえすでに指数関数的に増加する可能性があるため、歩行を列挙しようとする解決策は絶望的です。 達成可能なすべてのパス合計の構造的特徴付けが必要です。 

最も危険なエッジケースは木です。 木では 2 つの頂点の間に単純なパスが 1 つだけありますが、エッジを横切ってすぐに戻ってくる可能性があるため、歩行は依然として一意ではありません。 

例えば：```
2 1 4 1 2
1 2 1
```直歩は重みがある`1`。 

また、次のことも行う場合があります。```
1 -> 2 -> 1 -> 2
```体重は誰ですか`3`。 

達成可能な剰余モジュロ`4`は`{1,3}`、したがって、答えは次のとおりです`2`、 ない`1`。 

もう 1 つの微妙なケースは、グラフに総重みが適合しないサイクルが含まれている場合です。`k`。 

考慮する：```
k = 6
cycle weight = 4
```そのサイクルを繰り返し挿入すると、残りは次のように変化します。`4 mod 6`によって生成されたサブグループのみを生成します。`gcd(4,6)=2`。 すべてのサイクルですべての残基が作成されると仮定したソリューションでは、過剰にカウントされてしまいます。 

最後のエッジケースは、`k = 1`。 すべての数字は一致します`0 mod 1`したがって、答えは常に次のようになります。`1`。 

## アプローチ

 強引なアイデアは、四球を生成することです。`s`に`t`、重みを法的に計算します。`k`、到達可能な残基をマークします。 グラフにサイクルが含まれる可能性があるため、これはすぐに問題に陥ります。 歩行の数は無限であり、グラフのサイズが上限に達してしまうため、短い歩行に制限しても役に立ちません。`10^5`。 

重要な観察は、すべてのウォークは、挿入された閉じたウォークだけが互いに異なるということです。 閉じた歩行によってどのような体重変化が生じるかがわかっていれば、`s -> t`walk は、単純に固定の基本値にそれらの変更を組み合わせたものです。 

任意のスパニング ツリーを選択して、`dist[v]`ルートから木までの距離になります。`v`。 

非ツリーエッジの場合`(u,v,w)`、ルートからのツリー パスを比較します。`v`ルートから`u`そしてこのエッジを使用します。 不一致```
dist[u] + w - dist[v]
```そのサイクルを使用して歩行にどれだけの重量を注入できるかを測定します。 

木の端は別のタイプのジェネレーターに貢献します。 たとえ純粋な木であっても、端を横切ってすぐに戻ることがあります。 それは歩行重量を正確に変化させます`2w`。 

2 つの間の考えられるすべての相違点`s -> t`ウォークは、以下によって生成される整数の加法サブグループを形成します。```
2w                           for every edge
dist[u] + w - dist[v]        for every edge
```させて```
G = gcd(all generators above)
```すべての歩行体重は以下に一致します```
base + x·G
```ある整数に対して`x`。 

モジュロ`k`、によって生成されたサブグループ`G`正確に含まれています```
k / gcd(k, G)
```明確な残留物。 

その値が答えです。

 ## アルゴリズムのチュートリアル

 1. DFS または BFS を使用してスパニング ツリーを構築します。 
2. ツリーをトラバースしながら、次の計算を行います。`dist[v]`、根から頂点までの木の総重量`v`。 
3.初期化`G = 0`。 
4. グラフのエッジごとに`(u,v,w)`、 アップデート：```
G = gcd(G, 2w)
```これは、エッジを横切ってすぐに戻ってくることを説明します。 
5. 同じエッジに対して、次を更新します。```
G = gcd(G, abs(dist[u] + w - dist[v]))
```これにより、サイクルによって生じる不一致が捉えられます。 
6. すべてのエッジが処理された後、次を計算します。```
d = gcd(G, k)
```7. 出力:```
k / d
```### なぜ効果があるのか

 木の距離は潜在的な関数を与えます。 すべてのエッジトラバーサルは、伸縮寄与と不一致項として記述することができます。 

完了したら`s -> t`ウォークがこのように拡張されると、伸縮部分は次の条件にのみ依存して一定の定数に折りたたまれます。`s`そして`t`。 唯一の自由は、不一致値と`2w`バックトラッキング操作。 

すべての歩行重みの差のセットは、まさにそれらの値によって生成された加算的なサブグループです。 整数の加法サブグループは、その gcd によって生成されます。`G`。 

モジュロ`k`、到達可能な残基は、によって生成される環状サブグループを形成します。`G mod k`。 によって生成される循環サブグループ`G`サイズがあります`k / gcd(k,G)`、必要なカウントを与えます。 

## Python ソリューション```python
import sys
from math import gcd

input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n, m, k, s, tt = map(int, input().split())

        adj = [[] for _ in range(n)]
        edges = []

        for _ in range(m):
            u, v, w = map(int, input().split())
            u -= 1
            v -= 1

            adj[u].append((v, w))
            adj[v].append((u, w))
            edges.append((u, v, w))

        dist = [0] * n
        vis = [False] * n

        stack = [0]
        vis[0] = True

        while stack:
            u = stack.pop()

            for v, w in adj[u]:
                if not vis[v]:
                    vis[v] = True
                    dist[v] = dist[u] + w
                    stack.append(v)

        g = 0

        for u, v, w in edges:
            g = gcd(g, 2 * w)
            g = gcd(g, abs(dist[u] + w - dist[v]))

        print(k // gcd(k, g))

solve()
```DFS は、任意のルートからのツリーの距離を計算します。 後で gcd 値のみが使用されるため、ルートの選択は重要ではありません。 

最初の gcd アップデートには、エッジを横断してすぐに戻る機能が組み込まれています。 この用語がないと、木は誤って扱われてしまいます。 

2 回目の gcd 更新では、サイクルの不一致がキャプチャされます。 木のエッジについては以下があるため、木のエッジは自動的にゼロを寄与します。```
dist[v] = dist[u] + w
```そして式はゼロになります。 

すべての算術演算は 64 ビット整数に快適に収まります。 到達できる距離はおおよそ次のとおりです。```
10^5 × 10^9 = 10^14
```これは Python の整数の範囲内に十分収まります。

def run(inp: str) -> str:

    input = sys.stdin.readline

    t = int(input())
    out = []

    for _ in range(t):
        n, m, k, s, tt = map(int, input().split())

        adj = [[] for _ in range(n)]
        edges = []

        for _ in range(m):
            u, v, w = map(int, input().split())
            u -= 1
            v -= 1

            adj[u].append((v, w))
            adj[v].append((u, w))
            edges.append((u, v, w))

        dist = [0] * n
        vis = [False] * n

        st = [0]
        vis[0] = True

        while st:
            u = st.pop()

            for v, w in adj[u]:
                if not vis[v]:
                    vis[v] = True
                    dist[v] = dist[u] + w
                    st.append(v)

        g = 0

        for u, v, w in edges:
            g = gcd(g, 2 * w)
            g = gcd(g, abs(dist[u] + w - dist[v]))

        out.append(str(k // gcd(k, g)))

    return "\n".join(out)

 ## 特殊なケース

 次のツリーについて考えてみましょう。```
1
2 1 4 1 2
1 2 1
```サイクルのみを調べるソリューションでは、グラフにはサイクルがないため自由がないと結論付けられます。 それは間違いです。 散歩```
1 -> 2 -> 1 -> 2
```追加します`2`総重量に。 私たちのアルゴリズムは明示的に挿入します`2w`gcd 計算に組み込んで、`G = 2`そして正解`2`。 

次に、次のことを考えてみましょう。```
1
2 1 1 1 2
1 2 100
```すべての整数は以下に合同です`0 mod 1`。 アルゴリズムは以下を計算します。```
answer = 1 / gcd(1, G) = 1
```それが唯一可能な結果です。 

最後に、サイクル不一致 gcd がすでに`1`。 一度`G = 1`、 我々は持っています：```
gcd(k, G) = 1
```そして答えは次のようになります`k`。 アルゴリズムは、すべての剰余モジュロを正しく認識します。`k`生産することができます。
