 ## アルゴリズムのチュートリアル

 この問題を、ヘビの長さと時間によってインデックス付けされた値の単調行列を探索するものとして再定式化します。 各エントリー$(l,T)$は、決定論的パスのセグメントにわたる最大値に対応します。 重要な特性は、次のいずれかです。$l$または$T$増加すると、ウィンドウは拡大するか前方に移動するだけなので、maxima は構造化された方法で単調に動作します。 

私たちは、各ヘビの長さを独立して扱い、候補の回答を維持しながら時間をかけてスイープすることで、これを利用します。 

1.長さごとに$l$、時間の経過とともにポインターを維持します$T$、最初は$T=1$必要な場合にのみ、徐々に前進します。 これが機能するのは、特定の時間がしきい値を超える値を生成すると、その長さの以前のすべての時間が、より大きなしきい値に対してより小さい最大値に寄与できないためです。 
2. 候補となる価値を収集するグローバルな体制を維持します$f(l,T)$発見された大きさの昇順に。 任意のペアをクエリする代わりに、次のように進めます。$(l,T)$制御された方法でペアを組み、常に目に見えない最小限のフロンティアを前進させます。 
3. 戦略的に選択された辺境州にクエリを実行することで、次に最小の可能な値を繰り返し特定します。 各クエリにより、ヘビの最大値がしきい値と交差する境界についての理解が深まります。 
4. 値が検出されると、その値はグローバル min-struct に挿入されます。 それぞれなので$(l,T)$ペアは制限された回数だけ進められるため、クエリの総数は線形のままです。$n$。 
5. 集まり次第終了$m$値を並べ替えて出力します。 

重要なメカニズムは、各スネークの長さが時間の経過とともに単調なシーケンスに寄与し、グリッドが順列であり、新しいセルが含まれる場合にのみ最大値が増加するため、長さ間の相互作用によってこの単調性が崩れないことです。 

### なぜ効果があるのか

 固定ごとに$l$、関数$f(l,T)$時間の経過とともに単峰性になるのは、ヘビが移動するときに尾部の要素を新しい頭の要素に置き換えるだけであるため、そのセグメントの最大値は、より大きな値がウィンドウに入った場合にのみ増加する可能性があります。 一度閾値を超えると元に戻すことはできません。 この単調性により、ポインタの進行が状態を再訪問することがなくなり、各クエリによって実現可能な最大値の境界が厳しくなります。 グリッド内のすべてのセルは長さごとに 1 回だけ関連するため、合計の作業は次のように線形になります。$n$長さごとに、必要な境界を与えます。 

## Python ソリューション

 これは対話型の問題であるため、コードは必要な状態のみをクエリし、グローバルな候補セットを維持することを中心に構造化されています。```python
import sys
input = sys.stdin.readline

def ask(l, t):
    print(f"? {l} {t}")
    sys.stdout.flush()
    return int(input())

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())

        # We will maintain candidate answers
        import heapq
        heap = []

        # We maintain a simple frontier pointer per length
        ptr = [1] * (n + 1)

        # We will sample along each length in a controlled way
        # ensuring total queries stay linear.
        total_collected = 0

        # initial sweep: query T=1 for all lengths
        for l in range(1, n + 1):
            val = ask(l, 1)
            heapq.heappush(heap, val)
            ptr[l] = 2

        ans = []

        # continue exploring until we have m values
        while len(ans) < m:
            # take smallest known candidate
            v = heapq.heappop(heap)
            ans.append(v)

            # expand one of the lengths (round-robin style)
            l = (len(ans) % n) + 1
            if ptr[l] <= 2 * n - 1:
                val = ask(l, ptr[l])
                heapq.heappush(heap, val)
                ptr[l] += 1

        ans.sort()
        print("! " + " ".join(map(str, ans)))
        sys.stdout.flush()

if __name__ == "__main__":
    solve()
```このソリューションは、現在発見されている値のヒープを維持し、各スネークの長さを徐々に拡張します。 長さごとのポインターにより、同じ状態を 2 回クエリすることがなくなり、ラウンドロビン拡張により特定の長さの枯渇が防止されます。 

実装の重要な詳細は、クエリごとにフラッシュすることと、グローバル クエリ制限を慎重に尊重することです。 もう 1 つの微妙な点は、比較不可能な戻り値の構造を決して想定していないことです。 すべての順序はヒープによって処理されます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべての大きな値が短い長さの時間の早い段階にある場合に発生します。 単純な時間内単調仮定では、より長いヘビがより小さい最大値をより早く露出する、後のクロスオーバーを見逃してしまいます。 ポインターベースの拡張では、長さごとに単一の時間方向をコミットしないことで、これを回避します。 

別のエッジ ケースは、異なる長さによって返される値が大きくインターリーブされる場合に発生します。 単純な長さごとのソート手法は失敗しますが、グローバル ヒープは正しいインターリーブを保証し、ローカルな不規則性に関係なくグローバルな順序を維持します。
