 ## 解決策
 ## 問題の理解

 2 つの閉じた整数区間が与えられます。 1 つの間隔は、整数の取り得る値を表します。$a$、もう 1 つは整数の取り得る値を記述します。$b$。 これらの範囲から任意のものを選択できます$a$そしてどれでも$b$、それらの合計を形成し、その合計の小数表現を確認します。 任意の整数の場合$x$、関数$f(x)$は、10 進表現で表示される最大の桁として定義されます。 課題は選択することです$a$そして$b$この最大の桁は$a + b$できるだけ大きいです。 

出力は合計そのものではなく、可能な合計の 10 進表現のどこにでも現れることができる、達成可能な最大の桁値だけです。 

制約により、最大で$10^3$テスト ケースと範囲の各エンドポイントは次のように大きくできます。$10^9$。 これにより、すべてのペアを試行するソリューションは即座に除外されます。$(a, b)$、各テスト ケースには既に最大の値が含まれているため、$10^{18}$組み合わせ。 1 つの範囲を反復処理し、それを他の範囲のエンドポイントと貪欲にペアリングしても、依然として大きすぎます。 

問題の構造は普通ではありません。合計そのものやその大きさを最適化しているのではなく、合計の桁レベルの特性を最適化しているのです。 これは、和の小さな局所的な変化、特にキャリー伝播が重要であることを示唆しています。 

いくつかの特殊なケースは分離する価値があります。 

たとえば、両方の範囲が単一点の場合、$a = 1$、$b = 8$の場合、答えは単純にその固定合計の最大の桁になります。$9$。 どのソリューションでもこれを簡単に処理する必要があります。 

両方の範囲が大きく、10 の累乗境界に近い値が含まれる場合、キャリーによって桁構造が大幅に変更される可能性があります。 たとえば、次のような値を選択すると、$999$対$1000$最大桁を完全に反転できます$9$に$1$。 合計を最大化したり、先頭の桁を個別に最大化しようとする単純な貪欲な戦略は、内部桁上げを制御しないため失敗する可能性があります。 

もう 1 つの微妙なケースは、最適な答えが最大化から得られない場合です。$a + b$。 たとえば、合計がわずかに小さい場合、数字を作成するキャリー パターンが生成される可能性があります。$9$、一方、可能な最大合計は、より低い最大桁を生成する可能性があります。 

## アプローチ

 ブルートフォース解釈は簡単です。 可能な限りあらゆることを繰り返します$a$で$[l_a, r_a]$そして可能な限りの$b$で$[l_b, r_b]$、計算する$a + b$、それを文字列に変換し、見つかった最大の数字を追跡します。 これは、すべての有効な構成を明示的に評価するため、正しいです。 

ただし、テスト ケースごとのペアの数は次のとおりです。$10^{18}$。 桁抽出ができても$O(1)$、列挙が完全に支配的であるため、このアプローチは実行不可能になります。 

重要な観察は、この関数が合計の 10 進数表現のみに依存し、桁上げ伝播を除いて加算の下で数字が局所的に動作することです。 重要な単純化は、任意の桁を最大化するには、9 がグローバルな最大桁であるため、9 を作成する特定の位置でキャリーを強制できるかどうかを考慮するだけでよいことです。 

そこで問題は、到達可能な区間内で任意の合計を構築できるかということです。$[l_a + l_b, r_a + r_b]$どこかに数字の9が含まれていますか？ 「はい」の場合、答えは 9 です。そうでない場合は、8、次に 7 などを試します。 

これにより、問題は桁の実行可能性チェックに集約されます: 候補桁の場合$d$が存在するかどうかを尋ねます。$a, b$そのような$f(a+b) \ge d$。 同等に、桁に少なくとも 1 桁が含まれる合計が存在するかどうか$\ge d$。 最大桁のみを考慮しているため、9 から下方向に検索できます。 

固定候補桁の実現可能性をチェックするために、合計範囲で標準桁 DP スタイルの構築を利用します。 ペアを明示的に列挙する代わりに、考えられるすべての合計が連続した区間を形成することを観察します。$[L, R]$、 どこ$L = l_a + l_b$そして$R = r_a + r_b$。 したがって、問題を次のように要約します。整数は存在しますか?$x \in [L, R]$最大桁が少なくとも$d$?

 これは、桁に単純な制約を備えた、単一の数値範囲に対する古典的な桁 DP になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O((r_a-l_a)(r_b-l_b))$|$O(1)$| 遅すぎる |
 | 範囲にわたる桁の実現可能性 |$O(T \cdot \log N \cdot 10)$|$O(\log N)$| 承認済み |

 ## アルゴリズムのチュートリアル

 各テスト ケースを単一の数値間隔に変換します。$[L, R]$、 どこ$L = l_a + l_b$そして$R = r_a + r_b$。 

次に、この範囲内の任意の数値に現れる最大の桁を決定します。 

### ステップ

 1. コンピューティング$L = l_a + l_b$そして$R = r_a + r_b$。 

これは有効です。なぜなら、すべての合計が$a + b$はこの範囲内にあり、この範囲内のすべての整数は達成可能です。$a$そして$b$範囲が連続している。 
2. 候補桁の場合$d$9 から 0 まで、数字が存在するかどうかを確認します$x \in [L, R]$少なくとも数字が含まれる$d$。 

最初の有効な桁が最適になるように、下方向に反復します。 
3. 修正の実現可能性を確認するには$d$、間隔にわたって数字 DP を使用します。 

範囲内にその桁に値が含まれる数値が存在するかどうかを数えます$\ge d$。 そのような数値が存在する場合は true を返します。 
4. 数字 DP は、位置、下限の厳しさ、上限の厳しさ、およびすでに数字を見たかどうかを追跡します。$\ge d$。 

このような数字を配置したら、残りの位置は範囲内であれば何でも構いません。 
5. 最初の桁$d$どちらの実現可能性が成功するかが答えです。 

### なぜ効果があるのか

 可能なすべての値があるため、アルゴリズムは正しいです。$a + b$は連続した区間に含まれており、数字の実現可能性は、その区間内の少なくとも 1 つの数字にしきい値を満たす数字が含まれているかどうかによってのみ決まります。 9 から下の数字をチェックすることで、最初に成功した数字がすべての有効な合計で達成可能な最大の数字であることを確認します。 数字 DP は、明示的に構築することなく、区間内のすべての有効な数値を正確に列挙し、指数関数的な列挙を回避しながら正確さを維持します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from functools import lru_cache

def has_digit_at_least(x, d):
    s = str(x)
    for ch in s:
        if int(ch) >= d:
            return True
    return False

def exists(L, R, d):
    # simple digit DP over range
    sL = str(L)
    sR = str(R)

    # pad
    n = max(len(sL), len(sR))
    sL = sL.zfill(n)
    sR = sR.zfill(n)

    @lru_cache(None)
    def dp(i, tightL, tightR, ok):
        if i == n:
            return ok

        lo = int(sL[i]) if tightL else 0
        hi = int(sR[i]) if tightR else 9

        for dig in range(lo, hi + 1):
            n_ok = ok or (dig >= d)
            if dp(
                i + 1,
                tightL and dig == lo,
                tightR and dig == hi,
                n_ok
            ):
                return True
        return False

    return dp(0, True, True, False)

def solve():
    t = int(input())
    for _ in range(t):
        la, ra, lb, rb = map(int, input().split())
        L = la + lb
        R = ra + rb

        for d in range(9, -1, -1):
            if exists(L, R, d):
                print(d)
                break

if __name__ == "__main__":
    solve()
```コードはまず問題を単一の合計区間に圧縮します。 の`exists`関数は、その間隔にわたって数字 DP を実行し、その間の有効な数値のみを考慮するようにします。$L$そして$R$。 DP 状態は、現在の桁の位置、下限と上限にまだ制限されているかどうか、およびしきい値を満たす桁がすでに確認されているかどうかを追跡します。 しきい値に達すると、残りの桁は受け入れ条件にとって重要ではなくなるため、早期に成功を伝播することが可能になります。 

外側のループは、単純に 9 から下に向かって数字のしきい値を試行し、明示的に合計を比較する必要なく最適性を確保します。

 ## 特殊なケース

 重要なエッジ ケースは、両方の範囲が同一のシングルトンである場合に発生します。 入力用$a = b = 1$、私たちは得ます$L = 2$、$R = 2$。 DP は、他の分岐を探索せずに、ただ 1 つの数値のみを評価し、数字 2 を見つけてそれを返します。 

もう 1 つのケースは、上限付近のキャリー相互作用によってのみ最良の桁が表示される場合です。 例えば$la=90, ra=99, lb=90, rb=99$合計を与える$[180,198]$。 数字 198 には数字 9 が含まれており、これは極端なエンドポイントを選択した場合にのみ到達できます。 DP は境界にタイトなパスを正しく含み、この構成を検出します。 

3 番目のケースは、範囲が広いにもかかわらず、高い桁が生成されない場合です。$la=10, ra=12, lb=10, rb=12$、合計を与える$[20,24]$。 どの合計にも 4 を超える数字は存在せず、上位の候補を使い果たした後、アルゴリズムは正しく 4 に落ち着きます。
