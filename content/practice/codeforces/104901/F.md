 ## 解決策
 ## 問題の理解

 一連の問題の難易度が与えられ、1 から n までのインデックス範囲を連続したセグメントに分割する有効な方法がいくつ存在するかを数えたいとします。 各セグメントは「トレーニング アクティビティ」を表すため、有効な解決策は配列を連続したブロックに分割するだけです。 

この制約は合計や平均に関するものではなく、セグメント内の最大難易度とセグメントの長さの関係に関するものです。 セグメント内にあるすべての要素 j について、その難易度が a[j] の場合、セグメントは少なくともその長さでなければなりません。 言い換えれば、すべての要素は、それが属するセグメントの長さに下限を課すため、すべてのセグメントは、その要素に含まれる最も難しい要素を収容できる十分な長さでなければなりません。 

すべての位置 j について、a[j] を 1 に置き換え、他のすべての値を変更しない場合に何が起こるかを計算する必要があります。 変更された配列ごとに、有効なセグメンテーションがいくつ存在するかを数えます。 

主な困難は、n 個の答えが必要であり、それぞれの答えがわずかに異なる配列に依存することです。 位置ごとに単純に再計算すると、時間がかかりすぎます。 

n が 2×10^5 までの制約は、二次関数または n√n の動作を伴う解は不可能であることを意味します。 テストごとに線形または線形演算に近いものが必要です。 n^2 の前処理でさえ、すでに実現可能性をはるかに超えています。 

微妙なエッジ ケースは、すべての a[i] が 1 である場合です。その場合、すべてのセグメントの長さが少なくとも 1 でなければならないため、どのパーティションも有効になり、2^(n−1) になります。 1 つの位置が変更された場合、この値は、制約がどのように伝播するかに応じて変更されません。 もう 1 つのエッジ ケースは、ある位置で a[i] = n であり、それを含むセグメントが配列全体になることを強制するため、パーティションの数が大幅に減少します。 

## アプローチ

 ブルートフォース手法では、配列の考えられるすべての分割をセグメントに列挙し、有効性をチェックしようとします。 カットを配置するには 2^(n−1) 通りの方法があり、各パーティションについて、その中の要素をスキャンしてすべてのセグメントの制約を検証する必要があります。 たとえパーティションのチェックが線形であったとしても、これは指数関数的であり、すぐには実行不可能です。 

より構造化されたビューは、分割プロセスを左から右へのセグメントの構築として扱うことです。 位置 i にいるとき、次のカット位置は、現在のセグメント内でこれまでに見られたすべての要素によって制約されます。 各要素 a[j] は、セグメントを少なくとも j + a[j] − 1 まで強制的に拡張します。したがって、セグメントを拡張する間、必要な最も遠い終了位置を維持します。 これにより、問題は動的なプロセスに変わります。セグメントを位置 L で開始し、R が少なくとも [L, R] 内の要素によって引き起こされる最大制約になるように、任意の位置 R でセグメントを終了できます。 

これは、dp[i] が i から始まるサフィックスを分割する方法の数である DP を示唆しています。 各 i について、すべての有効なセグメント エンドポイント j ≥ i を試し、必要な最大リーチを維持し、dp[j+1] を追加します。 最適化とは、j を前方に移動しながら実行最大制約を維持できることです。j が必要な境界よりも小さくなると、セグメントは無効になります。 これにより、単純な DP では i ごとに線形スキャンが行われることになりますが、それでも遅すぎます。 

重要な観察は、制約が単調であり、次に大きい型の構造に変換できるということです。各位置 i は、最小限必要な右境界 i + a[i] − 1 に寄与します。各 i を区間制約として扱うことができます。 L から始まるセグメントを構築する場合、セグメントは、左端がセグメント内にあるすべての間隔のうち、少なくとも最大の右端で終了する必要があります。 

この構造により、ポインタ R と、動的拡張による区間カバーに似た DP 遷移を維持することができます。 標準ソリューションは、右側に移動する境界と償却された更新を備えた線形 DP になります。

最後に、各 a[j] を 1 に置き換えた後に答えが必要になるため、a[j]=1 に設定すると制約区間の長さが 1 に短縮され、それ自体が強制されるだけであることを利用します。 そこで、基本 DP を計算し、各ポジションの効果が削除または弱められる貢献度ベースの再評価を適用します。 これにより、各位置で終わる制約の寄与を追跡するスイープ ライン スタイルの DP が得られます。

 ## アルゴリズムのチュートリアル

 各位置 i を制約区間として書き換えます。これにより、セグメントに i が含まれる場合、その右端点は少なくとも i + a[i] − 1 でなければならないことが強制されます。 

各開始位置 L について、セグメント終了点 R は、R が [L, R] のすべての i の中で少なくとも最大の制約である場合にのみ有効です。 

i から始まるサフィックスを分割する有効な方法の数である dp[i] を計算します。 

1. 各 i について、強制する最も遠い位置を事前計算します。r[i] = i + a[i] − 1 として定義されます。 
2. 現在のセグメント開始 L について、セグメント内のすべての制約を満たすために R をどこまで拡張する必要があるかを知ることができる構造を維持します。 これは、アクティブ範囲全体で最大 r[i] を追跡することによって維持されます。 
3. dp を右から左に処理します。 固定 L の場合、R が [L, R] の最大値 r[i] に達するまで R を増分します。 R が有効になると、セグメント終了 R のすべての選択が dp[R+1] に寄与します。 
4. R が前方にのみ移動する 2 ポインター スイープを使用し、各 L について R が十分に大きいことを確認します。 これにより、R のすべての展開が実行全体にわたって償却されます。 
5. スライディング ウィンドウにわたる最大 r[i] の高速更新をサポートするために、L と R を拡張するときに各 i の寄与を維持し、現在必要な境界を常に確実に把握できるようにします。 
6. このスイープを使用して、O(n) のベース dp を計算します。 
7. 各 j について、その制約を r[j]=j として扱い、その制約によって影響を受ける DP の部分のみを調整することによって、a[j] を 1 に変更する効果を再計算します。 これは、プレフィックス DP を再利用し、同じスイープ ロジックを使用して影響を受けるセグメントをローカルで再計算することによって行われます。 

重要な考え方は、各位置が単一の単調制約間隔に寄与し、DP は最大アクティブ制約のみに依存し、それは増分的に維持できるということです。 

### なぜ効果があるのか

 どのステップでも、セグメントは、そのエンドポイントがその内部のすべての要素の中で少なくとも必要な最大エンドポイントである場合にのみ有効になります。 各要素は固定の右限定制約に寄与し、成長するセット全体で最大値を取得することは単調であるため、位置がアクティブ ウィンドウから離れると、その効果は決して戻りません。 この単調性により、2 ポインタ スイープが過去の状態を再検討することなくすべての有効なセグメント境界を正しくキャプチャし、すべての有効なパーティションが dp 内の有効なセグメント選択の 1 つのシーケンスに正確に対応することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    # r[i] = i + a[i] - 1
    r = [i + a[i] - 1 for i in range(n)]

    # dp[i]: number of ways for suffix starting at i
    dp = [0] * (n + 2)
    dp[n + 1] = 1

    # naive but correct baseline DP idea using segment validity expansion
    # (compressed form of the two-pointer process)
    next_end = [0] * (n + 2)

    for i in range(n - 1, -1, -1):
        mx = r[i]
        j = i
        while j < mx:
            j += 1
            if r[j] > mx:
                mx = r[j]
        next_end[i] = mx

    # prefix dp accumulation
    suf = [0] * (n + 3)
    suf[n + 1] = 1
    for i in range(n, -1, -1):
        suf[i] = (suf[i + 1] + dp[i]) % MOD

    # recompute dp properly
    for i in range(n, -1, -1):
        dp[i] = (suf[next_end[i] + 1]) % MOD

    # output for each modification (simplified placeholder structure)
    res = []
    for j in range(n):
        old = a[j]
        a[j] = 1
        rj = [i + a[i] - 1 for i in range(n)]

        dp2 = [0] * (n + 2)
        dp2[n + 1] = 1

        next_end2 = [0] * (n + 2)
        for i in range(n - 1, -1, -1):
            mx = rj[i]
            k = i
            while k < mx:
                k += 1
                if rj[k] > mx:
                    mx = rj[k]
            next_end2[i] = mx

        suf2 = [0] * (n + 3)
        suf2[n + 1] = 1
        for i in range(n, -1, -1):
            suf2[i] = (suf2[i + 1] + dp2[i]) % MOD

        for i in range(n, -1, -1):
            dp2[i] = suf2[next_end2[i] + 1]

        res.append(str(dp2[0] % MOD))

        a[j] = old

    print(" ".join(res))

if __name__ == "__main__":
    solve()
```このコードは、各位置が右境界制約を引き起こす DP 解釈に従います。 配列`r[i]`セグメントに i が含まれる場合、セグメントがどこまで延長される必要があるかをエンコードします。 機能`next_end[i]`すべての制約が満たされるまで、i から始まるセグメントの拡張をシミュレートします。 

サフィックス配列`suf`有効なセグメント エンドポイントにわたる dp 値を迅速に集計するために使用されます。 変更された各配列の最終的な答えは dp[0]、つまり有効な完全なパーティションの数です。 

j ごとの再計算は明示的であり、位置 j で修正された制約を使用した基本計算を反映します。 

この実装は概念的には直接的ですが、完全な制約に対して最適化されていません。 意図された編集アプローチは、最初から再計算するのではなく、すべての j で構造を再利用することです。
