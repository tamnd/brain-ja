 ## 解決策
 ## 問題の理解

 ツリーが与えられているので、残りの接続されたコンポーネントがすべて非常に特定のサイズになるように、いくつかのエッジを「カット」したいとします。各コンポーネントには正確に含まれている必要があります。`k`または`k + 1`頂点。 すべての有効な答えは、削除したエッジのセットによって定義され、結果として得られるパーティションが似ていても、異なるエッジ セットを削除した場合、2 つの答えは異なります。 

したがって、基礎となるオブジェクトは単なる頂点のパーティションではなく、サイズが厳しく制限された接続されたサブツリーへのパーティションです。 入力グラフはツリーであるため、エッジを削除すると常に 1 つのコンポーネントが 2 つに分割されるため、有効な解決策は、ツリーを許可されたブロックに「分割」するエッジのセットを選択することに正確に対応します。 

制約により、最大で次のことが許可されます。`n = 10^5`テストケースごと、合計`3 × 10^5`。 これにより、エッジのサブセットを考慮したり、カットを明示的にシミュレートしようとするソリューションは即座に除外されます。 エッジで指数関数的なもの、あるいは二次関数でさえも`n`手の届かないところにある。 ツリー構造は、各エッジを一定回数処理するルートベースの動的プログラミング ソリューションを強く示唆しています。 

素朴な考え方による微妙な失敗例は、探索中にコンポーネントを貪欲に形成できると仮定することです。 たとえば、次の 6 つのノードのチェーンでは、`k = 2`、コンポーネントをできるだけ早く閉じる貪欲な戦略では、次のようなパーティションが生成される可能性があります。`[1,2],[3,4],[5,6]`ただし、サブツリーの選択は結合されているため、初期の決定が異なると、後で行き詰まりを強いられる可能性があります。 もう 1 つの問題は、各サブツリーがそのパーティション サイズを独立して決定すると想定していることですが、サブツリーが上向きに接続するか閉じるかがコンポーネント サイズのグローバルな一貫性に依存するため、これは失敗します。 

## アプローチ

 ブルートフォース解釈は簡単です。エッジのすべてのサブセットを試し、連結成分を計算し、すべての成分にサイズがあるかどうかを確認します。`k`または`k + 1`。 これは、定義を直接テストするため、正しいです。 ただし、エッジサブセットの数は`2^(n-1)`、サブセットごとの接続性を評価する場合でも直線的な時間がかかり、指数関数的な爆発につながり、小さなツリーを超えるとこのアプローチが不可能になります。 

重要な観察は、ツリー内の切断エッジが階層構造を誘発するということです。すべてのコンポーネントはそれ自体がサブツリーであり、すべての決定はノードをその子の 1 つに接続するエッジに対してローカルです。 任意のエッジ サブセットを選択する代わりに、ツリーをルート化し、サブツリー構造に基づいてエッジごとにカットするか保持するかを決定できます。 これにより、問題はコンポーネントをボトムアップで「組み立てる」有効な方法を数えることになります。 

主な困難は、ノードを処理するときに、現在形成中のコンポーネントがどのくらいの大きさであるかを知る必要があることです。コンポーネントは、そのサイズが正確に一致した場合にのみ完成することができるためです。`k`または`k + 1`。 これにより、現在開いているコンポーネントのサイズを状態が上向きに追跡するツリー DP が生成されます。 

各サブツリーは 2 つの根本的に異なる方法で貢献します。 サブツリー内で完全に自己完結する (つまり、親へのエッジが切断される) か、親の開いたコンポーネントにマージする (つまり、上向きのノードに寄与する) かのいずれかです。 この二分法により、ナップサックのマージと同様に、子に対する構造化された DP 遷移が可能になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | エッジサブセットに対するブルートフォース | O(2^n · n) | O(n) | 遅すぎる |
 | コンポーネント サイズに関するツリー DP の状態 | O(n・k) | O(n・k) | 承認済み |

 ## アルゴリズムのチュートリアル

 たとえば、任意のノードでツリーをルートします。`1`。 各ノードについて`u`では、次の 2 種類の情報を定義します。`dp[u][s]`のサブツリーを分割する方法の数です。`u`そのような`u`現在のサイズの「開いている」コンポーネントに属します`s`。 このオープンコンポーネントはまだ最終化されておらず、親に拡張されます。 

メンテナンスも行っております`closed[u]`、サブツリーを完全に分割する方法の数`u`そのような`u`親に接続しない、つまり`u`サイズの完全なコンポーネントに属します`k`または`k + 1`そのサブツリーの内部。 

子が親の前にすでに計算されるように、ノードを事後順序で処理します。 

1. 各ノードの初期化`u`となることによって`dp[u][1] = 1`。 これは、次のもののみから構成されるコンポーネントを表します。`u`子をマージする前に。 
2. それぞれの子どもに対して`v`の`u`、そのDPをマージします`u`。 一時的な DP 配列を作成します。`u`各状態に対して 2 つの可能性を処理します。 
3. 最初の可能性はエッジを切ることです`(u, v)`。 この場合、次のサブツリーは`v`は完全に独立するので、次のように乗算します。`closed[v]`そして去ります`dp[u]`変わらない。 これは治療に相当します`v`すでに内部で完全なコンポーネントが形成されているためです。 
4. 2 番目の可能性は接続です`v`現在開いているコンポーネントへ`u`。 この場合、次の状態を取ります。`v`それ自体は上向きに接続されており、サイズをマージします。`u`現在オープンサイズです`a`そして`v`オープンサイズに貢献`b`、新しい状態になります。`a + b`を超えない限り、`k + 1`。 
5. すべての子を処理した後、次の計算を行います。`closed[u]`コンポーネントが開いているかどうかを確認することで、`u`完成させることができます。 もし`dp[u][k]`または`dp[u][k+1]`存在する場合、これらはルートをルートとする有効な完了したコンポーネントに対応します。`u`なので、それらを追加します`closed[u]`。 
6. 木全体の答えは次のとおりです。`closed[root]`。 

正確さは、任意のノードにおける構造的不変条件に依存します。`u`、そのサブツリーのすべての有効な部分構成は、以下を含む開いたコンポーネントの大きさによって完全に記述されます。`u`であり、サブツリーの他のすべての部分はすでに有効に次のサイズのコンポーネントに閉じられています。`k`または`k + 1`。 すべてのエッジの決定は、マージ中にカット (子サブツリーを閉じる) またはマージ (開いたコンポーネントを展開する) として 1 回だけキャプチャされます。 コンポーネントはサイズに達したときにのみファイナライズされるため、`k`または`k + 1`、無効なコンポーネントを途中で閉じたり、許容範囲を超えて拡張したりすることはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n, k = map(int, input().split())
    g = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)

    sys.setrecursionlimit(10**7)

    parent = [0] * (n + 1)
    order = []

    stack = [1]
    parent[1] = -1

    while stack:
        u = stack.pop()
        order.append(u)
        for v in g[u]:
            if v == parent[u]:
                continue
            parent[v] = u
            stack.append(v)

    dp = [None] * (n + 1)
    closed = [0] * (n + 1)

    for u in reversed(order):
        dp_u = [0] * (k + 2)
        dp_u[1] = 1

        for v in g[u]:
            if v == parent[u]:
                continue

            dp_v = dp[v]
            new_dp = [0] * (k + 2)

            for su in range(1, k + 2):
                if dp_u[su] == 0:
                    continue

                # cut edge u-v
                new_dp[su] = (new_dp[su] + dp_u[su] * closed[v]) % MOD

                # merge v into u component
                if dp_v is not None:
                    for sv in range(1, k + 2 - su):
                        if dp_v[sv]:
                            new_dp[su + sv] = (new_dp[su + sv] +
                                               dp_u[su] * dp_v[sv]) % MOD

            dp_u = new_dp

        dp[u] = dp_u
        closed[u] = (dp_u[k] + dp_u[k + 1]) % MOD

    print(closed[1])

T = int(input())
for _ in range(T):
    solve()
```コードはまず、親の前に子が処理されるように反復走査順序を構築します。 DP 配列は、ノードごとに、そのノードを含む開いたコンポーネントのさまざまなサイズに対して存在するウェイの数を追跡します。 マージのステップでは、各子を切り取るか開いたコンポーネントに接続することによって慎重に結合します。これはまさにツリー パーティションにおける 2 つの構造の可能性です。 

各ノードの最終値は、開いているコンポーネントが有効に終了可能になる状態から抽出されます。これは、コンポーネントのサイズがいずれかの許可されたターゲットに達することを意味します。 

微妙な実装の詳細は、DP サイズの上限を次のとおりにします。`k + 1`より大きなコンポーネントは無効であり、決して必要ではないためです。 これにより、遷移が制限されます。 

## 実用的な例

 ### 例 1

 小さな木について考えてみましょう`1 - 2 - 3 - 4`と`k = 2`。 

それぞれが`dp[leaf][1] = 1`。 

ノードで`2`、子を組み合わせる`3`、どちらかを維持できます`3`分離するか結合します。 DP の`2`次のように進化します。 

| ノード | dp[2][1] | dp[2][2] | 閉店[2] |
 | --- | --- | --- | --- |
 | 初期化 | 1 | 0 | 0 |
 | 3以降 | 1 | 1 | 1 |

 ここ`closed[2] = dp[2][2] = 1`、ルートとなるサブツリーを意味します`2`サイズの有効なコンポーネントを形成できる`2`。 

これは、DP がグローバルな一貫性を維持しながら、ローカルで切り取りとマージの両方の選択肢を取得する方法を示しています。 

### 例 2

 中心のある星形の木を取ります`1`に接続されています`2,3,4`、 そして`k = 2`。 

各葉はサイズに影響します`1`。 ノードで`1`、子を 1 つずつ結合します。 2 つのリーフを結合すると、有効なサイズに達します`2`、これは閉じることができ、残りの葉は独自のコンポーネントに切り取られます。 

DP テーブルは次のように進化します。 

| ステップ | dp[1][1] | dp[1][2] | dp[1][3] |
 | --- | --- | --- | --- |
 | 開始 | 1 | 0 | 0 |
 | 2以降 | 1 | 1 | 0 |
 | 3以降 | 1 | 2 | 1 |
 | 4以降 | 1 | 3 | 3 |

 州のみ`2`そして`3`サイズのコンポーネントに対応する有効なクロージャに貢献します`k`または`k+1`。 

これは、グループ化リーフの複数の組み合わせがどのように個別の有効なエッジ カット セットを生成するかを示しています。

 ## 特殊なケース

 主なエッジケースは次のような場合です`k`に近いです`n`。 それなりの大きさの木に`n = k`、唯一の有効な構成は、すでに一致している場合にツリー全体をそのまま維持することです。`k`、そうでない場合は失敗します。 DP はこれを自然に処理します。なぜなら国だけが行うからです。`dp[root][n]`存在し、一致する場合にのみ有効です`k`または`k + 1`。 

別のケースは、木が線であり、`k = 1`。 すべてのノードは独自のコンポーネントになる必要があります。つまり、すべてのエッジがカットされます。 DP は「カット」トランジションを繰り返し選択するように劣化し、すべてのマージトランジションは許容サイズを超えるため無効になります。 

最後の微妙なケースは、複数の子が異なる順序でマージされる場合です。 DP は、子にわたるすべての可能性を対称的に集約し、マージのシーケンスが最終カウントに 1 回だけ寄与することを保証するため、順序に依存しません。
