 ## 解決策
 ## 問題の理解

 長さの配列を意味する順列が与えられています。$n$～のすべての整数を含む$1$に$n$ある順序で 1 回だけ。 私たちのタスクは、連続セグメントを変更する特定の操作を使用して、この配列を昇順に変換することです。 

各操作は次のように機能します。2 つのインデックスを選択します。$l < r$左端の値が右端の値よりも厳密に大きくなるようにして、部分配列全体を次からソートします。$l$に$r$昇順で。 この操作を適用できるのは最大でも$\lfloor n^2 / 2 \rfloor$最終的な配列がソートされることを保証する有効な一連の操作を出力する必要があります。 

制約は小さいです。$n \le 100$、合計$n$すべてのテストケース全体で最大でも$10^4$。 これにより、テスト ケースごとに任意の 2 次法が受け入れられることがすぐにわかりますが、操作自体は任意ではないため、注意が必要です。 セグメントを自由に並べ替えることはできません。エンドポイントが反転を形成するセグメントのみです。 

微妙な点は、この操作が常に任意の間隔で使用できるわけではないことです。 たとえば、セグメントが大幅にソートされていない場合でも、左の端点が右の端点よりも大きくない限り、セグメントを選択することはできません。 「配列全体をソートし続ける」ような素朴な考えは無効です。なぜなら、配列全体の端点は、たとえ中間がそうでなくても、すでに昇順になっている可能性があるからです。 

もう 1 つの失敗モードは、大規模なセグメント ソートを使用して各数値の位置を貪欲に直接「修正」できると想定していることです。 これは条件が原因で壊れます$a_l > a_r$セグメントの内部に明らかに反転が含まれている場合でも、失敗する可能性があります。 

したがって、主な困難は、操作に制約があることです。グローバルな並べ替えを確保しながら、その制約内で作業する必要があります。 

## アプローチ

 ブルートフォースの考え方は、許可された操作を使用して強力な並べ替えプロセスをシミュレートし、並べ替えにより乱れが軽減される有効なセグメントを繰り返し検索することです。 すべてのペアをスキャンしようとすることもできます$(l, r)$、実現可能性を確認し、並べ替えを適用し、並べ替えられるまで繰り返します。 これは、各操作によって反転が減少したり構造が再編成されたりするため、概念的には正しいですが、計算的には無駄が生じます。 操作の確認と適用を繰り返すと、$O(n^3)$または、多くのステップにわたって動作が悪化する可能性があり、プロセスは操作数の明確な制限を保証するのに十分な構造になっていません。 

重要な観察は、長さが 2 のセグメントに適用すると、操作が非常に単純かつ信頼性の高いものになるということです。 隣接するインデックスを選択すると$i$そして$i+1$、次に条件$a_i > a_{i+1}$これはまさに近隣間の反転の定義です。 この問題が発生した場合、セグメントを並べ替えると、$[i, i+1]$2 つの要素を交換することと同じです。 これにより、問題は標準的な隣接交換ソート プロセスに変換されます。 

長さ 2 のセグメントに対して許可されるすべての操作が、反転した隣接するペアの単なる交換であることが認識されたら、バブル ソートを回復します。 バブル ソートでは、スワップとして最大でも反転数を使用して順列を並べ替えることが保証されており、順列には最大でも$n(n-1)/2$反転、これは許容制限に一致します。 

したがって、「強力な」セグメント ソート操作を複雑な方法で活用しようとするのではなく、その最も単純な有効な使用方法に限定します。これで、必要な範囲内で配列をソートするのにすでに十分です。

 ## アルゴリズムのチュートリアル

 バブル ソートをシミュレートしますが、明示的に交換する代わりに、長さ 2 のセグメントに対して許可された操作を使用します。 

1. 配列を左から右に繰り返しスキャンして、隣接する反転を探します。 
2. インデックスを見つけるたびに$i$そのような$a_i > a_{i+1}$で演算を適用します。$l=i$そして$r=i+1$。 

操作に必要な条件が正確に満たされているため、これは有効です。 
3. セグメントをソートする操作$[i, i+1]$これは、2 つの要素を単純に交換し、小さい方の要素を左側に配置します。 
4. この交換によって前の要素との新しい反転が作成された可能性があるため、スキャンを続けます。 
5. 隣接する反転がなくなるまで、アレイ上のパスを繰り返します。 

演算の数は、順列における反転の数によって当然制限されます。 各操作では、隣接する要素間の反転が 1 つだけ削除され、バブル ソートにより、隣接するスワップによってすべての反転が最終的に削除されることが保証されます。 

### なぜ効果があるのか

 重要な不変条件は、すべての演算で配列の総反転数が厳密に減少するということです。 各操作は隣接する反転ペアを交換するため、そのペアはその後反転ではなくなり、そのペアに関係する新しい反転が同じ方向に導入されることはありません。 反転カウントは有限で負ではないため、プロセスは終了する必要があります。 隣接する反転が残っていない場合、配列はグローバルにソートされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    ops = []
    
    # Bubble-sort using allowed operations
    for _ in range(n):
        for i in range(n - 1):
            if a[i] > a[i + 1]:
                # valid operation since a[i] > a[i+1]
                ops.append((i + 1, i + 2))
                
                # applying "sort segment of length 2"
                a[i], a[i + 1] = a[i + 1], a[i]
    
    print(len(ops))
    for l, r in ops:
        print(l, r)

def main():
    t = int(input())
    for _ in range(t):
        solve()

if __name__ == "__main__":
    main()
```この実装では、隣接するすべての反転スワップが操作として直接記録されます。 重要な点は、後の比較は現在の状態に依存するため、操作を記録した直後に配列を更新する必要があるということです。 

ネストされたループは、最大でも次の範囲のバブル ソートを実装します。$n$パスごとに最大でスキャン$n$要素はこれで十分です$n \le 100$。
