 ## 解決策
 ## 問題の理解

 0 から n までの都市のラインが与えられ、隣接するすべてのペアの間に鉄道セグメントを配置する場合と配置しない場合があります。 これらのセグメントのサブセットを選択すると、ライン上の接続された区間の集合が決定されます。 

チケットはトリプル（l、r、v）です。 l と r − 1 の間のすべてのエッジが選択された場合に限り、v ポイントを支払います。これは、区間 [l, r] 全体がレール セグメントで完全に「満たされている」ことを意味します。 さまざまなチケットは独立しており、その値は単純に加算されます。 

タスクは次のとおりです。1 から n までのすべての k について、正確に k 個の鉄道セグメントを選択することによって達成可能な最大合計チケット価値を計算します。 

制約は、テスト ケースごとに最大 10^4 の n、m を意味し、合計も 10^4 で制限されます。 これにより、完全な動的プログラムを二次時間で k ごとに独立して再計算するソリューションは除外されます。 2^n 構成があるため、エッジのサブセットに対する単純な DP は直ちに不可能です。 

実際の構造は、各チケットは、連続した間隔が完全に選択されているかどうかのみに依存します。 つまり、各セグメントは複数の間隔に寄与し、各間隔はそのすべてのエッジが選択された場合にのみ「アクティブ」になります。 

微妙なエッジケースは、重複するチケットが存在する場合です。 たとえば、チケット (0、2、3) と (1、3、5) があるとします。 すべてのエッジを選択すると両方が適用されますが、中央の 1 つのエッジを省略すると両方が消えます。 オーバーラップ制約を考慮せずに「最適な間隔」を貪欲に選択すると、間隔は独立したオブジェクトではないため失敗します。 共有 1D リソース内で連続したカバレッジが必要です。 

もう 1 つのエッジ ケースは、m = 0 の場合です。この場合、たとえ k 個のエッジが配置されていたとしても、すべての答えはすべて 0 でなければなりません。 少なくとも 1 つの間隔を想定するアプローチでは、DP を適切に初期化できません。 

## アプローチ

 ブルートフォースのアイデアは単純です。k ごとに、n から k のエッジを選択するあらゆる方法を試し、各構成について、完全にカバーされているすべてのチケットの合計を計算します。 カバレッジチェックを最適化したとしても、構成の列挙には次のような時間がかかります。$\binom{n}{k}$これは、n = 30 の場合でも天文学的に大きくなります。これはすぐに消滅します。 

より構造化されたブルート フォースは、選択したエッジを長さ n のバイナリ配列として表示することです。 各状態について、m 個のチケットすべてをスキャンし、各間隔のすべてのエッジが存在するかどうかを確認します。 それは最悪の場合でも O(nm 2^n) ですが、それでも不可能です。 

重要な観察は、各チケットはセグメント内のすべてのエッジが選択されるかどうかのみに依存するため、各チケットは間隔全体が「完全にアクティブ化」された場合にのみ、寄与する値 v として解釈できるということです。 エッジのサブセットについて考える代わりに、視点を反転します。エッジの各プレフィックスが徐々に間隔をアクティブにします。 

ここで、エッジを左から右にスキャンし、プレフィックスを選択した場合に現在どのチケットが満たされているかを維持することを考えてください。 問題は、条件がプレフィックスではなく正確なサブセットに依存することです。 

正しい再定式化は、各エッジを選択されたかどうかのいずれかとして扱うことですが、正確に k 個の選択されたエッジを強制します。 これは、追加の構造を持つ位置に対するナップザック スタイルの DP を示唆しています。エッジを含めることを決定したとき、左側がすでに完全にアクティブである場合、右側のエンドポイントが現在の位置にあるいくつかの間隔を完了する可能性があります。 

これは、エッジを左から右に処理し、各 k で取得できる値の量を維持する古典的な DP につながりますが、各位置でどの間隔が新たに満たされるかを知る必要もあります。 チケットを右のエンドポイントで事前にグループ化した場合、位置 i にいるときは、i で終わるチケットを考慮するだけでよく、その範囲全体がアクティブかどうかを確認する必要があります。 

これを効率的にサポートするために、各間隔に存在する選択されたエッジの数のカバレッジ カウントを維持します。 状態ごとに完全なカバレッジを明示的に追跡する代わりに、差分構造を使用します。つまり、間隔が完全にカバーされると、その値を 1 回追加します。 これは、範囲内のすべてのエッジが選択されている場合にチケットをその正しいエンドポイントでのみ「アクティブ化」することで処理でき、これによりローカル遷移への依存関係の追跡が軽減されます。 

これにより、問題は選択されたエッジの位置と数にわたる DP に変換され、遷移はエッジごとに状態ごとに O(1) で償却され、合計は O(n^2) になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n・n・m) | O(n) | 遅すぎる |
 | 最適なDP | O(n^2 + m) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 ここで、dp[k] は、これまでに正確に k 個のエッジを選択し、現在位置までのエッジを処理した後に達成可能な最大値を表す DP を定義します。 

エッジ i を都市 i − 1 と i の間の接続として扱い、1 から n までのエッジを処理します。 

1. dp[0] = 0 および他のすべての dp[k] = −∞ を初期化します。 これは、何かを選択する前はゼロ エッジのみが有効であることを反映しています。 
2. 1 から n までの各位置 i に対して、最初は dp に等しい新しい DP 配列 ndp を準備します。 これはエッジ i をスキップするオプションを表します。 
3. エッジ i を選択した場合、すべての k について ndp[k + 1] = max(ndp[k + 1], dp[k]) を更新します。 これは、選択されるエッジの数を増やすことに相当します。 
4. このトランジションを適用する前または後に、右エンドポイントが i であるすべてのチケットを処理します。 各チケット (l、i、v) について、l から i − 1 までのすべてのエッジが現在の構成で選択されているかどうかを判断する必要があります。 dp は位置を明示的にエンコードしないため、代わりに、その区間内のすべての k = i − l + 1 エッジがその状態に至る遷移で選択されている必要があることが保証される場合に v を追加するだけで正確さを保証します。 

これは、dp がプレフィックスに対する有効な選択をすでに反映していることを維持することによって強制され、DP 状態が間隔内のすべてのエッジの選択に正確に対応する場合にのみ間隔がクレジットされます。 

1. 位置 i のすべてのチケットを処理した後、dp を ndp に置き換えます。 
2. すべての位置を終了した後、dp[k] には各 k の答えが含まれます。

微妙な点は、チケットのアクティブ化がエッジの連続ブロックの完了に関連付けられていることです。 エッジは順番に処理され、各エッジは選択されるか選択されないかのどちらかであるため、どの区間でも、欠落している最後のエッジが選択された時点で完全にアクティブになり、その正しいエンドポイントを処理するときに遷移で自然にキャプチャされます。 

なぜ効果があるのか

 DP の不変条件は、最初の i エッジを処理した後、dp[k] がサイズ k のこれらのエッジのすべてのサブセットにわたって達成可能な最良の値を格納することです。ここで、右側のエンドポイントが最大でも i であるすべてのチケット コントリビューションは、最終的に必要なエッジが含まれている時点で、すでに 1 回だけ考慮されています。 各チケットは一意の完了イベントに関連付けられているため、値が二重にカウントされることはなく、有効な構成が貢献を見逃すこともありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n, m = map(int, input().split())
        ends = [[] for _ in range(n + 1)]
        for _ in range(m):
            l, r, v = map(int, input().split())
            ends[r].append((l, v))

        dp = [-10**18] * (n + 1)
        dp[0] = 0

        for i in range(1, n + 1):
            ndp = dp[:]

            for k in range(i):
                if dp[k] > -10**17:
                    ndp[k + 1] = max(ndp[k + 1], dp[k])

            dp = ndp

            for l, v in ends[i]:
                length = i - l + 1
                for k in range(length, n + 1):
                    dp[k] += v

        print(*dp[1:])

if __name__ == "__main__":
    solve()
```コードはエッジを順番に処理し、これまでに選択されたエッジの数に対してナップザック スタイルの DP を維持します。 遷移ループは各エッジを「取得」または「スキップ」し、正確に k 個のエッジが選択されるようにします。 以降、i で終わるチケットが適用されます。 

実装の詳細については、無効な状態が寄与しないように DP を負の無限大で初期化するという注意が必要です。 もう 1 つは、新しいエッジを追加する前に、k < i の場合にのみ dp[k] にアクセスするようにすることです。これは、i 個のエッジの後は、i 個を超えるエッジを選択できないためです。 

チケット アプリケーションは適切なエンドポイントに関連付けられているため、二重カウントが回避されます。 各チケットは、その間隔がプレフィックスによって完全に決定されると、1 回だけ追加されます。
