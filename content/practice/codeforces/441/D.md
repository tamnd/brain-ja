 ## 解決策
 ## 問題の理解

 順列が与えられます。これは番号付きの位置の行として考えることができ、各位置には 1 から n までの個別の値が含まれます。 スワップ操作では 2 つの位置が交換され、一連のスワップの後、別の順列が得られます。 

任意の順列 q について、f(q) を、q をソートされた恒等順列に変換するために必要なスワップの最小数として定義します。 長さ L の各サイクルは正確に L-1 個のスワップに寄与するため、この量は q のサイクル構造によって完全に決定されます。 

タスクは、指定された順列を並べ替えることではありません。 代わりに、f(q) が指定されたターゲット m に等しくなるように、最初の順列から到達可能な別の順列 q を構築する必要があります。 可能な最小数のスワップを使用して初期順列をそのような q に変換するすべてのスワップ シーケンスの中で、辞書編集的に最小のスワップ シーケンスを出力する必要があります。 

重要な制約は n ≤ 3000 であるため、O(n²) または O(n² log n) の解は実現可能ですが、3 次以下のものは境界線になります。 難しいのは、f(q) を計算することではなく、サイクル構造を厳密に制御しながら、それに到達するために必要なスワップの数を最小限に抑え、スワップ シーケンスの辞書編集上の最小性を維持する方法で q を構築することです。 

最初の順列の f(p) がすでに m に等しい場合、微妙なエッジ ケースが発生しますが、辞書編集的な順序により特定の構築パスが強制されるため、最適に到達するには依然として自明ではないスワップが必要です。 もう 1 つの重要なケースは、m が 0 の場合です。これは、q が同一であることを強制しますが、p から同一への辞書編集上の最小のスワップ シーケンスは、単なる任意のサイクル固定ではありません。これは、サイクルの異なる分解が異なる辞書編集的な結果を生み出すためです。 

## アプローチ

 直接的なブルート フォース ビューは、p から到達可能なすべての置換 q を生成し、それぞれについて f(q) を計算し、各エッジがスワップである置換空間に対して BFS またはダイクストラを実行することになります。 状態空間が n! であるため、これは直ちに不可能であり、スワップに対するローカル検索でも O(n! · n²) として爆発的に増加します。 

より構造化された観察は、あらゆる順列はサイクルに分解でき、スワップはこれらのサイクルの分割と結合に対応するということです。 f(q) = n −number_of_cycles(q) であるため、値 f(q) は q のサイクルの数とサイズにのみ依存します。 これにより、ターゲット条件が、最終的な置換で必要なサイクル数に関する制約に変換されます。つまり、正確に n − m サイクルが必要になります。 

したがって、問題は次のようになります。p から q へのスワップを最小限に抑えながら、p をちょうど n − m サイクルを持つ q に変換します。 2 つの順列間のスワップの最小数は n −number_of_cycles(p⁻¹ ∘ q) です。これは、構造的に p に近いが、制御されたサイクル分割を備えた順列 q を効果的に選択していることを示唆しています。 

重要な洞察は、恣意的な並べ替えについて考えないようにすることです。 代わりに、必要なサイクル数に達するまで、p のサイクルをより小さなサイクルに選択的に「分割」することによって q を構築します。 各中断は、構築プロセスのスワップに対応します。 辞書編集的に最小限のスワップ シーケンスを実現するために、サイクルを中断する場所を選択するときは常に可能な限り小さいインデックスを好みます。これにより、当然のことながら、昇順で位置を処理し、コンポーネントを維持するために DSU のような構造を使用することになります。 

インデックスの連結成分を追跡しながら、p から q を構築することをシミュレートします。 構造をマージまたは分割することを決定するたびに、2 つのインデックスが q の同じサイクルに属するかどうかを事実上決定することになります。 正確に n − m 個のコンポーネントを保証し、それに応じて q を構築します。 最後に、最小限のインデックス スワップを使用して要素を常に最終位置に配置する貪欲な構造を使用して、p を q に変換するスワップを出力します。

辞書編集上の制約により、一貫したルールが強制されます。不一致を修正する必要がある場合は常に、まだ正しくない可能な限り最小のインデックス i を選択し、それをターゲット位置を解決する最小の j と交換します。

 ## アルゴリズムのチュートリアル

 構築を 2 つのフェーズに分けます。正しいサイクル数を使用してターゲットの順列 q を構築し、次に p から q までの辞書編集上最小のスワップ シーケンスを生成します。 

1. p のサイクルを抽出して、p の初期順列構造を計算します。 これにより、ベースラインのサイクル数 c₀ が得られます。 各サイクルは、順列グラフのコンポーネントに対応します。 
2. 最終的な置換 q は正確に c = n − m サイクルを持たなければならないことがわかっています。 c > c₀ の場合、さらにマージしてもこれを達成することは不可能なので、代わりにこの構築を p のサイクルの分割として解釈します。 c < c₀ の場合、代表を接続することによってサイクルをマージし、サイクル数を効果的に削減します。 
3. インデックス 1 から n までの DSU コンポーネントを維持します。 最初は、各インデックスは別々です。 c コンポーネントが正確に残るまでコンポーネントをマージします。 私たちは常に、可能な限り最小のコンポーネントのペアを最初にマージし、結果として得られる構造の辞書編集上の最小性を確保します。 
4. DSU 構造が q のコンポーネントを定義したら、各コンポーネント内のマッピングによって q を構成する値を割り当てます。 各コンポーネント内では、連続する要素をインデックスの昇順にリンクすることで単純なサイクルを形成します。 
5. これで q ができました。 2 番目のフェーズでは、スワップを使用して p を q に変換します。 1 から n までの位置をスキャンします。 各位置 i について、p[i] がすでに q[i] に等しい場合は、何も行いません。 それ以外の場合は、p[j] が q[i] に等しくなる位置 j > i を見つけ、i と j を交換します。 
6. 各スワップは応答シーケンスに追加され、それに応じて p を更新します。 この貪欲なマッチングにより、辞書編集上可能な限り最小の方法で各位置が確実に固定されます。これは、可能な限り最小のパートナーとの最も早いミスマッチを常に解決するためです。 
7. すべての位置が q と一致するまで続けます。 

なぜ効果があるのか

 DSU の構造では、各コンポーネントが 1 サイクルになり、コンポーネントの数を明示的に制御するため、q が正確に必要なサイクル数を持つことが保証されます。 貪欲な固定フェーズは正しいです。各スワップでは少なくとも 1 つの正しい値が最終位置に配置され、常に最小の i が最初に選択され、最小の有効な j が選択されます。これにより、スワップ シーケンスの辞書編集上の最小性が保証されます。 一度処理されると、すでに固定された要素を正しい位置から移動することはないため、後の操作で以前の配置を無効にすることはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
p = list(map(int, input().split()))
m = int(input())

# build target permutation q

parent = list(range(n))

def find(x):
    while parent[x] != x:
        parent[x] = parent[parent[x]]
        x = parent[x]
    return x

def union(a, b):
    ra, rb = find(a), find(b)
    if ra != rb:
        parent[rb] = ra
        return True
    return False

# initial cycle count of p
vis = [False] * n
cycles = 0
for i in range(n):
    if not vis[i]:
        cycles += 1
        cur = i
        while not vis[cur]:
            vis[cur] = True
            cur = p[cur] - 1

target_cycles = n - m

# reset DSU
parent = list(range(n))

# merge until target cycles
comp = n
edges = []

for i in range(n):
    for j in range(i + 1, n):
        if comp == target_cycles:
            break
        if union(i, j):
            edges.append((i, j))
            comp -= 1
    if comp == target_cycles:
        break

adj = [[] for _ in range(n)]
for a, b in edges:
    adj[a].append(b)
    adj[b].append(a)

# build q by DFS on components
q = [0] * n
vis = [False] * n

for i in range(n):
    if not vis[i]:
        stack = [i]
        comp = []
        vis[i] = True
        while stack:
            u = stack.pop()
            comp.append(u)
            for v in adj[u]:
                if not vis[v]:
                    vis[v] = True
                    stack.append(v)
        comp.sort()
        k = len(comp)
        for idx in range(k):
            q[comp[idx]] = comp[(idx + 1) % k] + 1

# greedy transform p -> q
pos = [0] * (n + 1)
for i in range(n):
    pos[p[i]] = i

ops = []

for i in range(n):
    if p[i] == q[i]:
        continue
    val = q[i]
    j = pos[val]

    ops.append(i + 1)
    ops.append(j + 1)

    # swap in p
    p[i], p[j] = p[j], p[i]
    pos[p[j]] = j
    pos[p[i]] = i

print(len(ops) // 2)
print(*ops)
```DSU セクションは、q のサイクル構造をエンコードするコンポーネントのフォレストを構築します。 各結合演算によりコンポーネントの数が減り、正確に n − m で停止することで、最終的な置換のサイクル数が確実に正確になります。 

隣接リストは、q の 1 サイクルとなる連結成分を抽出するために使用されます。 各コンポーネント内では、ソートされた順序で値を決定的にローテーションします。これにより、最小限のラベル付けと一貫した構造が保証されます。 

最後の貪欲フェーズは、位置配列 pos に依存しており、これにより、必要な各値が現在存在する場所の O(1) ルックアップが可能になります。 各スワップは p と pos の両方に即座に反映され、後続の操作の正確性が保証されます。

 ## 特殊なケース

 最小のケースは n = 1 です。この場合、置換はすでに固定されており、m は 0 でなければなりません。q が p に等しく、すべてのインデックスがすでにそのターゲットと一致しているため、アルゴリズムは結合も交換も生成しません。 

順列が 3 1 2 などの単一の大きなサイクルである場合、DSU ステップでは過剰なマージを避ける必要があります。これは、すでに 1 つのサイクルがあり、マージではなく分割が必要になる可能性があるためです。 この構築では、新しい隣接エッジを定義することによって q に制御されたサイクル構造が生成され、グリーディ スワップ フェーズでは位置が線形ステップで正確に解決されます。 

m = 0 の場合、q は恒等順列になります。 このアルゴリズムは、最小の i と j を辞書編集的に優先する標準的なスワップによる並べ替え手順のように動作し、位置マップにより、各スワップが少なくとも 1 つの要素を永続的に修正することが保証され、最大でも n−1 個のスワップで終了することが保証されます。
