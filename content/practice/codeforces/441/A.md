 ## 解決策
 ## 問題の理解

 ヴァレラは、一連の販売者からアンティーク アイテムを 1 つだけ購入したいと考えています。 各出品者は、現在のオークション価格で複数のアイテムを提供しています。 ヴァレラは、商品の現在の価格を厳密に上回る価格を提示し、予算が固定されている場合にのみ取引を確保できます。`v`。 目標は、少なくとも 1 つの商品を正常に購入できるすべての販売者を見つけることです。 

入力により販売者の数が提供されます`n`そしてヴァレラの予算`v`。 各販売者から、販売者が所有する商品の数と現在の価格のリストを受け取ります。 出力には、Valera が対応できる販売者の数と、1 から始まるインデックスが昇順で示されている必要があります。 

制約は小さいです。`n`販売者ごとの商品数`k_i`価格と Valera の予算は最大 10^6 です。 これは、最悪の場合の価格チェックの総数は 50 × 50 = 2500 であり、最新の CPU では 1 秒以内にわずかな量であるため、各販売者のすべてのアイテムにわたる単純な検索が実行可能であることを意味します。 

微妙なエッジケースは、売り手のすべての商品の価格がヴァレラの予算よりも高い場合です。 商品を持っている売り手を選択できると想定する単純なアプローチでは、商品が誤って含まれてしまう可能性があります。 もう 1 つのエッジケースは、複数の商品がより安い場合です。`v`; 販売者ごとに 1 回のアウトビッドの成功のみで十分ですが、不注意な実装では複数回カウントされる可能性があります。 

## アプローチ

 ブルート フォース アプローチは、入力サイズが小さいため、本質的に最適なアプローチでもあります。 各販売者を反復処理し、次に各商品を反復処理して、価格が Valera の予算を下回っているかどうかを確認します。 この条件を満たす最初のアイテムにより、Valera がこの販売者と取引できることが確認され、次の販売者に進むことができます。 これは正しいです。この問題では、販売者ごとに少なくとも 1 つのアイテムが手頃な価格であることのみが必要であり、選択された正確なアイテムは重要ではないからです。 最悪の場合は実施させていただきます`n * k_i`比較、最大入力の場合は最大 2500 です。 

この問題を効率的に解決できる観察結果は、以下のすべての項目を追跡する必要がないということです。`v`各売り手ごとに; 1 つの存在を検出するだけで済みます。 これにより、不必要な計算が回避され、ソリューションが簡単かつ効率的になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース / 最適 | O(n * 最大 k_i) = O(2500) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む`n`そして`v`入力から。 
2. 空のリストを初期化する`deal_sellers`Valera と取引できる売り手のインデックスを保存します。 
3. 販売者ごとに`i`1から`n`:

 1. アイテム数を読み取る`k_i`そしてその価格。 
2. 各商品の価格を順番に確認します。 
3. 商品の価格が厳密に以下の場合`v`、追加`i`に`deal_sellers`そしてこの売り手のループを断ち切りましょう。 
4. 販売者の数を出力します。`deal_sellers`。 
5. これらの販売者のインデックスを昇順で出力します。 

なぜ機能するのか: 不変条件は、売り手が追加されるたびに、`deal_sellers`, ヴァレラは、その売り手から少なくとも 1 つのアイテムを買う余裕があります。 各アイテムを反復処理することで売り手を見逃さないことが保証され、早めに中断することで冗長なチェックを回避できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, v = map(int, input().split())
deal_sellers = []

for i in range(1, n + 1):
    data = list(map(int, input().split()))
    k_i, prices = data[0], data[1:]
    for price in prices:
        if price < v:
            deal_sellers.append(i)
            break

print(len(deal_sellers))
print(' '.join(map(str, deal_sellers)))
```コードは売り手の数とヴァレラの予算を読み取ります。 各販売者について、商品を読み取り、少なくとも 1 つが手頃な価格であるかどうかを確認します。 手頃な価格の商品が見つかると、販売者のインデックスを記録して次に進みます。 出力には、必要な形式に一致する売り手の総数とそのインデックスが出力されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n * 最大 k_i) | 手頃な価格の商品が見つかるまで、各販売者の各商品をチェックします。 |
 | スペース | O(n) | Valera が取引できる販売者のインデックスを保存します。 |

 n ≤ 50 および k_i ≤ 50 の場合、合計操作は 2500 未満であり、これは 1 秒以内に簡単に収まります。 メモリ使用量は、256 MB の制限に比べれば無視できます。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, v = map(int, input().split())
    deal_sellers = []
    for i in range(1, n + 1):
        data = list(map(int, input().split()))
        k_i, prices = data[0], data[1:]
        for price in prices:
            if price < v:
                deal_sellers.append(i)
                break
    out = f"{len(deal_sellers)}\n{' '.join(map(str, deal_sellers))}"
    return out

# Provided samples
assert run("3 50000\n1 40000\n2 20000 60000\n3 10000 70000 190000\n") == "3\n1 2 3", "sample 1"
assert run("2 10000\n2 20000 30000\n1 15000\n") == "0\n", "sample 2"

# Custom cases
assert run("1 5000\n1 4999\n") == "1\n1", "minimum-size input"

assert run("3 10000\n2 10000 10000\n2 9999 10001\n2 10001 10002\n") == "1\n2", "all-equal prices and boundary check"
```| テスト入力 | 期待される出力 | 検証内容 |

 | 最大サイズのアイテムを持つ 2 人の出品者 | 1\n2 | 可能な最大の入力サイズの処理 |
