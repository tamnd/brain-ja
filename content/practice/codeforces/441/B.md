 ## 解決策
 ## 問題の理解

 ヴァレラには多くの果樹が植えられた庭園があり、それぞれの果樹が特定の日に特定の数の果物を実らせます。 それぞれの果物は熟した日に収集可能になり、新鮮さを保つのは次の日だけです。 ヴァレラは 1 日に最大でも固定数の果物を収穫でき、それをさまざまな木に分割できます。 課題は、ヴァレラが最適な計画を立てた場合に収集できるフルーツの最大数を決定することです。 

入力では、木の数と 1 日の収集制限が提供され、その後に各木がその果実が熟す日とその木が生産する果実の総数で表される木のリストが表示されます。 出力は単一の整数、つまり収集されたフルーツの最大数です。 

問題の限界は控えめです。ツリーの数と 1 日の収集制限はどちらも最大 3000 です。これは、これらのパラメーターで時間計算量がほぼ 2 次のアルゴリズムは実現可能ですが、3 次以上のものでは遅すぎる可能性が高いことを示唆しています。 果物は 2 日間しか持たないため、重要な日数は暗黙的に、最後に成熟した日 + 1 によって制限されます。 

複数の木が同じ日に熟す場合、または入手可能な果物の合計が 1 日の収集制限を超える場合、微妙な特殊なケースが発生します。 たとえば、2 本の木が 1 日目にそれぞれ 5 個と 7 個の果実を実らせ、ヴァレラが 1 日に 6 個しか収集できない場合、任意の順序で果実を収集する単純なアプローチでは、2 日目に一部が収集されずに残り、合計が減少する可能性があります。 正しく出力するには、新しい果物を収穫する前に、前日の残りの果物を優先する必要があります。 

もう 1 つのエッジ ケースは、入力内の可能な最後の日に果物が熟す場合です。 果物は熟した日と翌日しか存続しないため、アルゴリズムはこの日の範囲を超えて果物を収穫しようとしてはなりません。果物はゼロになりますが、単純なループで誤って処理される可能性があります。 

## アプローチ

 ブルートフォース手法は簡単です。毎日繰り返し、その日に入手可能な果物を追跡し、1 日の制限まで収穫します。 これには、毎日すべての木をチェックし、まだ入手可能な果物の数を計算し、それに応じて残りの果物を更新することが含まれます。 これは論理的には正しいですが、3,000 日と 3,000 個のツリーを使用すると、1 日あたり最大 900 万回の操作がチェックされることになり、これは許容できますが不要です。 

最適な解決策の重要な観察は、果物が連続 2 日間しか持たないということです。 これにより、単一の配列を維持できるようになります。`day_fruits`日ごとにインデックスが付けられ、その日に熟した果物の総数が保存されます。 毎日、ヴァレラはまず前日の残りの果物を集め、次に新しく熟した果物を限界まで集める必要があります。 1 日あたりの制限が遵守されていれば、個々の割り当ては収集される合計に影響を与えないため、果実が日ごとに集計されると、木を個別に検討する必要がなくなります。 これにより、問題は数日にわたる単純なリニア スキャンに軽減され、残り物を追跡できます。

 | ブルートフォース | O(n * 最大日) | O(n) | 機能しますが、簡素化することもできます。 
| 最適 | O(最大日) | O(最大日) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を初期化する`fruits_on_day`すべての熟成日数プラス 1 日をカバーするのに十分な大きさです。 各インデックスは 1 日を表し、その日に熟す果物の数を保存します。 
2. 人口を投入する`fruits_on_day`入力を使用して。 それぞれの木ごとに熟す日が表示されます`a`そして`b`フルーツ、追加`b`に`fruits_on_day[a]`。 
3. 変数を初期化する`leftover`前日に収集されなかった果物を追跡します。 
4. 1 日から可能な最後の日 (最大熟成日 + 1) まで毎日繰り返します。 毎日、ヴァレラが 1 日の制限と合計の合計の間で最小として収集できるフルーツの数を計算します。`leftover`そして熟したばかりの果実。 
5.アップデート`leftover`ゼロと合計の間の最大値として`leftover`熟したばかりの果物から1日の制限量を差し引いたもの。 これにより、収集されなかった果物のみが次の日に持ち越されることが保証されます。 
6. 収集したフルーツを累計して累計します。 
7. 収集したフルーツの合計を出力します。 

ここで不変なのは、ヴァレラが一日の制限を決して超えず、常に前日の残りの果物を優先し、避けられる損失がないことを保証することです。 果物は 2 日間しか保存できないため、1 日分の残り物を追跡すれば十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, v = map(int, input().split())
max_day = 0
fruits_on_day = [0] * 3002  # Enough for day 1..3001

for _ in range(n):
    a, b = map(int, input().split())
    fruits_on_day[a] += b
    max_day = max(max_day, a)

total_collected = 0
leftover = 0

for day in range(1, max_day + 2):
    today_fruits = leftover + fruits_on_day[day]
    collected = min(today_fruits, v)
    total_collected += collected
    leftover = max(0, today_fruits - v)

print(total_collected)
```まず、木の数と 1 日あたりの収集制限を読み取ります。`fruits_on_day`果実を熟した日ごとに集約します。 日々のループにより、残った果物が常に最初に考慮されるようになります。 のサイズ`fruits_on_day`最後の日に 1 を加えたときのインデックス エラーを避けるため、最大日よりわずかに大きくなります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, v = map(int, input().split())
    fruits_on_day = [0] * 3002
    max_day = 0
    for _ in range(n):
        a, b = map(int, input().split())
        fruits_on_day[a] += b
        max_day = max(max_day, a)
    total_collected = 0
    leftover = 0
    for day in range(1, max_day + 2):
        today_fruits = leftover + fruits_on_day[day]
        collected = min(today_fruits, v)
        total_collected += collected
        leftover = max(0, today_fruits - v)
    return str(total_collected)

# Provided samples
assert run("2 3\n1 5\n2 3\n") == "8", "sample 1"
assert run("1 2\n1 4\n") == "4", "sample 2"

# Custom cases
assert run("1 1\n1 1\n") == "1", "minimum input"
assert run("3 10\n1 5\n2 15\n3 10\n") == "30", "all fruits collectible each day"
assert run("2 2\n1 3\n1 4\n") == "4", "daily limit smaller than total ripening fruits"
assert run("3 2\n1 2\n2 2\n3 2\n") == "6", "exact daily collection possible"
assert run("3 5\n2 7\n2 3\n3 8\n") == "18", "carryover from previous day handled"
```| テスト入力 | 期待される出力 | 検証内容 |
