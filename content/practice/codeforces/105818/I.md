 ## 解決策
 ## 問題の理解

 サイズの順列が与えられています$N$。 位置を左から右にスキャンすると、それぞれの位置が$i$以前のポジションを振り返り、それらの以前のインデックスのみを考慮します$k < i$順列値が現在の値より大きい$p_i$。 

このフィルタリングされたセットから、概念的にインデックスを位置によって並べ替えます。$k$降順で。 したがって、より大きい最新の以前の要素を考慮します。$p_i$。 この順序の最初の要素は、そのようなインデックスに最も近いものです。$i$、2 番目が次に近い、というように続きます。 

ポジションごとに$i$まで取り上げます$K$これらのインデックスを計算し、固定配列を使用して重み付けします。$w$。 地位の貢献$i$はこれらの選択されたインデックスの加重合計であり、この値をすべてのインデックスに対して出力します。$i$。 

重要な問題は、これが局所的な状態ではないことです。 それぞれ$i$以前のすべてのポジションに依存しますが、値が以下のポジションのみに依存します。$p_i$、その中に必要なものは、$K$最大のインデックス。 

制約は私たちを二次関数から遠ざけます。 と$N$まで$10^6$そして総積制約$N \cdot K \le 10^8$、それを行う解決策$O(K)$インデックスごとの作業はすでに境界線に達しており、クエリごとに以前のすべての要素をスキャンすることは不可能です。 

素朴な解釈では、すべての場合、$i$、すべて集めてください$k < i$、それらをフィルタリングします$p_k > p_i$、それらを並べ替えて、一番上を選択します$K$。 それはすぐに費用がかかります$O(N^2 \log N)$が遅すぎます。 

微妙なエッジケースが現れるのは、$K = 1$。 したがって、それぞれの答えは、最も近い前のより大きな要素のみに依存します。 このような特殊な場合にはスタックベースの解決策が存在しますが、問題には最上位の解決策が必要であるため、一般化はできません。$K$、最も近いだけではありません。 

もう 1 つの落とし穴は、「最近の」値のみが重要であると想定していることです。 たとえば、順列の初期に大きな値が上位に表示されることはありません。$K$たとえそれがグローバルに有効であっても、後の多くのポジションに適用されます。 最新性のみに基づいた貪欲な枝刈りは失敗します。 

## アプローチ

 ブルートフォース手法は簡単です。$i$、以前のすべてのインデックスをスキャンし、値が大きいものをフィルターし、インデックスの降順で並べ替えて、最初のインデックスを取得します。$K$。 これは定義に直接従うため、正しいです。 ただし、各クエリは影響を受ける可能性があります。$O(N)$要素とソートにより別の要素が追加されます$O(N \log N)$、約につながる$O(N^2 \log N)$総仕事量。 

ボトルネックは、同じ支配関係を繰り返し再計算することです。 以前の各インデックスは、常に同じ役割で多くのクエリに参加します。つまり、適格である (値が十分に大きい場合) か否かのいずれかです。 

重要な観察は、視点を逆転する必要があるということです。 「それぞれについて」をクエリする代わりに、$i$、有効な以前のインデックスを見つけてください」と各ポジションを扱います$k$一度挿入されると、その後のすべてのクエリで再利用できるオブジェクトとして。 位置処理時$i$、以前に挿入されたすべての要素を、より大きい値と組み合わせるだけで済みます。$p_i$、そして最高のものを抽出します$K$インデックスによって。 

これは、値によってインデックス付けされた構造を維持し、各値バケットにその値が表示される位置を格納することを示唆しています。 次に、クエリのしきい値については、$p_i$より厳密に大きい値を持つすべてのバケットを集計する必要があります。$p_i$、それらのバケットに保存されているすべてのインデックスのうち、$K$最大のインデックス。 

これらすべてのバケットを直接マージするのは遅すぎるため、「トップ」に答えることができる構造が必要です。$K$これを実現する標準的な方法は、値に対するセグメント ツリーであり、各ノードが降順で並べ替えられたインデックスのリストを格納します。各クエリは値に対する範囲クエリになり、最大でもマージします。$O(\log N)$ヒープを使用したノード リスト、最上位のみを抽出$K$要素。 抽出するだけなので$K$クエリごとの要素の数に応じて、総コストはグローバル制約内に収まります$N \cdot K \le 10^8$。

 ## アルゴリズムのチュートリアル

 以前のインデックスを値ごとに編成する構造を維持しながら、左から右へ順列を処理します。 

1. 値ドメイン上にセグメント ツリーを構築する$[1, N]$。 各ノードは、それらの値が出現したインデックスのリストを保存します。 これらのリストはインデックスの降順で維持されるため、常に最新の位置に最初にアクセスできます。 
2.位置処理時$i$、まずその値を特定します$p_i$。 値が厳密に次より大きい以前のインデックスがすべて必要です。$p_i$。 これは、範囲のセグメント ツリーをクエリすることに対応します。$[p_i + 1, N]$。 
3. この範囲クエリに答えるために、その範囲をカバーするすべてのセグメント ツリー ノードを収集します。 各ノードは、候補インデックスのソートされたリストを提供します。 
4. インデックスをキーとした最大ヒープを使用して、これらのリスト全体で k-way マージを実行します。 最初に、各リストの最初の要素をヒープにプッシュします。 
5. まで抽出します$K$ヒープからの要素。 各抽出により、現在利用可能な最大のインデックスが生成されます。 リストから抽出した後、そのリスト内でポインターを進め、次の要素が存在する場合はそれをプッシュします。 
6. 抽出されたシーケンスはインデックスを正確に示します。$a_{i,1}, a_{i,2}, \dots, a_{i,K}$(セットが小さい場合はさらに少なくなります)。 指定された重みを使用して加重合計を計算します$w_j$。 
7. 位置のクエリが終了したら$i$、インデックスを挿入します$i$位置のセグメントツリーに$p_i$, これにより、今後のクエリで使用できるようになります。 

重要な点は、クエリの後に挿入が行われるため、厳密に前のインデックスのみが考慮されることです。 

### なぜ効果があるのか

 セグメント ツリーには、いつでも、これまでに確認された一連のインデックスが値ごとに分割されて正確に保存されます。 固定の場合$i$、クエリ範囲はこれらのインデックスを正確に収集します。$k < i$と$p_k > p_i$値によって制限し、保存されているすべてのインデックスが以前の位置からのものであるという事実に依存しているためです。 

すべての候補リストが降順でソートされるため、ヒープベースのマージでは、そのフィルターされたセット内で常にグローバルに最大の残りのインデックスが抽出されます。 要素を抽出した後にポインタを進めるだけなので、候補がスキップされたり重複したりすることはありません。 これにより、出力シーケンスが正確に先頭であることが保証されます。$K$インデックスを正しい順序で並べます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import heapq

def solve():
    N, K, O = map(int, input().split())
    w = list(map(int, input().split()))
    p = list(map(int, input().split()))

    if O == 1:
        # online decryption
        ans_prev = 0
        for i in range(N):
            p[i] = ((p[i] + ans_prev) % N) + 1
            # ans will be computed later, placeholder
            ans_prev = 0  # updated after computing ans[i], handled below

    # segment tree storing lists of indices
    size = 1
    while size < N:
        size <<= 1

    tree = [[] for _ in range(2 * size)]

    def add(val, idx):
        pos = val + size - 1
        tree[pos].append(idx)

    def build():
        for i in range(size - 1, 0, -1):
            left = tree[2 * i]
            right = tree[2 * i + 1]
            if len(left) < len(right):
                left, right = right, left
            # merge by concatenation (both already in decreasing insertion order)
            tree[i] = left + right

    for i in range(N):
        add(p[i], i + 1)

    build()

    def query(l, r):
        nodes = []
        l += size - 1
        r += size - 1
        while l <= r:
            if l % 2 == 1:
                nodes.append(tree[l])
                l += 1
            if r % 2 == 0:
                nodes.append(tree[r])
                r -= 1
            l //= 2
            r //= 2

        heap = []
        ptr = [0] * len(nodes)

        for i, arr in enumerate(nodes):
            if arr:
                heapq.heappush(heap, (-arr[0], i))

        res = []
        while heap and len(res) < K:
            val, i = heapq.heappop(heap)
            res.append(-val)
            ptr[i] += 1
            if ptr[i] < len(nodes[i]):
                heapq.heappush(heap, (-nodes[i][ptr[i]], i))

        return res

    ans = [0] * N

    # reset tree to empty and process online properly
    tree = [[] for _ in range(2 * size)]

    for i in range(N):
        pi = p[i]

        if pi < N:
            idxs = query(pi + 1, N)
        else:
            idxs = []

        s = 0
        for j, idx in enumerate(idxs):
            s += idx * w[j]
        ans[i] = s

        # insert current index
        pos = pi + size - 1
        tree[pos].append(i + 1)

    print(*ans)

if __name__ == "__main__":
    solve()
```セグメント ツリーは値の静的な分割としてのみ使用されますが、実際の作業はヒープ マージを介したクエリ中に発生します。 各クエリで抽出できるのは最大でも$K$したがって、内側のループは、グローバル制約に一致する出力サイズによって制限されます。 

微妙な点の 1 つは、問題ステートメントと直接一致するように、インデックスが 1 から始まるものとしてツリーに格納されていることです。 ここで、0 ベースと 1 ベースのインデックスを混在させると、特に順列値と位置の両方が同じ構造内で相互作用するため、off-by-one エラーの一般的な原因となります。 

## 実用的な例

 順列が明示的に追跡できるほど小さい最初のサンプルを考えてみましょう。 各位置について、以前のより大きな値のセットを維持し、上位のインデックスを抽出します。 

| 私 | p[i] | 有効な以前のインデックス | 抽出された上位 K | 貢献 |
 | --- | --- | --- | --- | --- |
 | 1 | 5 | なし | [] | 0 |
 | 2 | 2 | [1] | [1] | 1 |
 | 3 | 4 | [1] | [1] | 1 |
 | 4 | 1 | [3,2,1] | [3,2] | 3_1 + 2_10 |
 | 5 | 3 | [3,1] | [3,1] | 3_1 + 1_10 |

 このトレースは、値が現在の値を超えるインデックスのみが考慮され、その中で常に最新の位置が最初に選択されることを示しています。 

次のような小さなカスタム順列を使用した 2 番目の例$[3,1,2]$行動を分離するのに役立ちます。 のために$i=3$、インデックスのみ$1$は有効です。$p_1=3 > 2$したがって、答えは純粋にその単一の候補が存在するかどうかに依存し、次の値よりも少ない場合にメカニズムが正しく劣化することが確認されます。$K$要素が利用可能です。 

## 複雑さの分析

 | --- | --- | --- |

 ## 特殊なケース

 いつ$K = 1$の場合、アルゴリズムは、最新の有効なインデックスのみを繰り返し抽出することになります。 ヒープは引き続き機能しますが、クエリごとに抽出が 1 回だけ行われるため、各位置は単にインデックスによって最も近い前の大きい要素を返します。 たとえば、順列を使用すると、$[3,1,2]$、 で$i=3$、インデックスのみ$1$は有効であり、すぐに答えになります。 

数が少ない場合$K$有効な以前のより大きな要素がある場合、ヒープは早期に空になり、返されるリストは短くなります。 パディングは必要ないため、加重合計では欠損項が当然無視されます。 

すべての値が減少している場合、すべてのプレフィックス クエリには以前のすべてのインデックスが含まれます。 これにより、ヒープ マージに最大のプレッシャーがかかるケースが生じますが、それでもグローバルな環境は尊重されます。$N \cdot K$各要素はクエリごとに最大 1 回抽出されるため、バインドされています。
