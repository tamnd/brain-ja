 ## 解決策
 ## 問題の理解

 速度が遅くならない順にロボットを配置しています。 ロボットの連続セグメントごとに、ロボットがトラックを離れる前に各グループを異なる秒数で停止できるように、ロボットを分割できるグループの最大数を知りたいと考えています。 

スピードのあるロボット`a`2秒目まで生き残れる`floor(L / a)`。 グループが2番目に撃たれた場合`t`、そのグループ内のすべてのロボットには少なくとも生存時間が必要です`t`。 後のグループは後で撃たれるため、速いロボットほど危険なので、早めに配置する必要があります。 

重要な観察は、サブ配列の場合、最良の戦略は常にそのサブ配列のプレフィックスを別個のグループとして取るということです。 させて`d[i] = floor(L / a[i])`ロボットにとって最後の瞬間になる`i`。 速度はソートされているため、期限は`d[i]`は増加しないため、配列内の後のロボットは、前のロボットよりも保存が簡単ではありません。 

で始まる部分配列の場合`l`、長さの接頭辞`k`ロボットが所定の位置にある場合に動作します`l + k - 1`2秒目まで生き残れる`1`、前の 1 つ目まで`2`、 等々。 これは次のように記述できます。`d[i] >= l + k - i`そのプレフィックス内のすべてのインデックスに対して。 並べ替えると次のようになります。`d[i] + i >= l + k`したがって、プレフィックス全体には次のすべての値が含まれている必要があります。`d[i] + i`少なくとも`l + k`。 

制約により許可されるのは、`N`到達する`200000`。 すべてのサブ配列をチェックしてグループ化をシミュレートするソリューションには、次のものが必要になります。`N^3`最悪の場合でも機能しますが、それは可能性をはるかに超えています。 リニアスキャンですべてのサブアレイをチェックしても、`O(N^2)`この操作はすでに大規模なテストには遅すぎます。 

主なエッジケースは、最適なグループ化と元の順序を混同したり、サブ配列全体が常に分離できると想定したりすることから発生します。 

例えば：```
Input:
4 10
1 3 6 10
```答えは次のとおりです。```
17
```最後の2台のロボットはスピードがあるため分離できません。`10`生き残れるのは1秒だけです。 ロボットごとに常に 1 つのグループを作成する貪欲なソリューションでは、このサブ配列がスコアがあるものとして誤ってカウントされます。`4`。 

もう 1 つのエッジ ケースは、単一のロボットです。```
Input:
1 100
50
```答えは次のとおりです。```
1
```ロボットは数秒間生き残ることができますが、考えられるグループは 1 つだけです。 スコアは使用可能な秒数ではなく、グループをカウントします。 

3 番目のよくある間違いは、prefix プロパティが開始インデックスに依存することを忘れていることです。```
Input:
3 10
1 10 10
```サブアレイ`[10, 10]`スコアがある`1`、 ない`2`, なぜなら、2番目のロボットは2番目の秒で保存できないからです。 答えは次のとおりです。```
5
```有効なスコアは次のとおりです。`1, 1, 1, 1, 1`3 つの単一要素と 2 要素のサブ配列に加え、完全なサブ配列スコア`2`。 

## アプローチ

 直接的なアプローチは、すべてのサブアレイを調べ、そのロボットの期限をシミュレートし、可能な限り最新のロボットを最も早い秒数に貪欲に割り当てることです。 これは、期限のあるジョブの標準的なスケジュール設定の考え方であるため、これは正しいです。 ただし、`N * (N + 1) / 2`サブ配列なので、`O(length)`部分配列ごとの計算は次のようになります`O(N^3)`。 

重要な観察は、開始位置の答えが正しい境界に複雑に依存しないことです。 計算するとします`best[l]`で始まるサフィックスを取得した場合に可能なグループの最大数。`l`残りのすべてのロボットの使用を許可します。 次に、次から始まる任意の部分配列`l`長さのある`len`正確にスコアがある`min(best[l], len)`。 

計算するには`best`、 定義する：`value[i] = i + floor(L / a[i])`1 から始まるインデックスを使用します。 有効な長さのプレフィックス`k`から始まる`i`そのプレフィックス内のすべての値は少なくとも次の値である必要があります`i + k`。 

右から左に処理すると単純な反復が得られます。 もし`best[i + 1]`ロボットは位置決め後に分離可能`i`、次に位置を決めます`i`自身の値が十分に大きい場合にのみ、有効なプレフィックスを 1 つ拡張できます。 新しい値は次のとおりです。`best[i] = min(best[i + 1] + 1, value[i] - i)`少なくとも 1 つは必要です。 

その後、各開始位置は単純な算術合計に寄与します。 残りの長さがある場合は、`m`の場合、貢献度は次の合計になります。`min(best[i], 1) + min(best[i], 2) + ... + min(best[i], m)`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N^3) | お(1) | 遅すぎる |
 | 最適 | O(N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのロボットの生存期限を計算します。 ロボット用`i`、計算します`d[i] = L // a[i]`そして保管する`value[i] = i + d[i]`。 値の変換により、グループ化条件がプレフィックス最小条件に変わります。 
2. 位置を右から左に処理して計算します`best[i]`。 最後のロボットは常に 1 つのグループを形成できるため、初期値は 1 です。 以前のすべてのロボットの場合、プレフィックスは、その後に始まる最適なプレフィックスより最大 1 つ長くすることができ、また次の制限もあります。`value[i] - i`。 
3. すべての開始位置について`i`、 させて`length = N - i + 1`。 もし`best[i]`少なくとも`length`、考えられるすべてのプレフィックス長が有効であるため、寄与率は次のようになります。`length * (length + 1) / 2`。 
4. それ以外の場合は、最初の`best[i]`通常、長さは増加し、サブ配列が長くなるたびに同じスコアが維持されます。 最初の部分の算術合計と残りの部分の定数寄与を加算します。 
5. すべての寄与を合計し、結果を出力します。 

なぜ効果があるのか:

 貪欲なグループ化が機能するのは、新しいロボットの期限が短いためです。そのため、選択したプレフィックスの右側からグループが最初に取得されるように、最適なスケジュールを再配置できます。 つまり、重要なのは、有効なプレフィックスをどれだけ長く構築できるかということだけです。 

繰り返しではこのプロパティが保持されます。 後のサフィックスの場合、`i`サポートします`k`グループ、ロボットの追加`i`長さのプレフィックスのみを作成できます`k + 1`ロボットなら`i`新しい最後の秒まで存続します。 残りのロボットがすでに最大有効サフィックスを形成しているため、これ以上プレフィックスは使用できません。 したがって、すべての`best[i]`は正しく、最終的な合計ではすべての部分配列が正確にカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, L = map(int, input().split())
    a = list(map(int, input().split()))

    best = [0] * (n + 2)

    for i in range(n - 1, -1, -1):
        deadline = L // a[i]
        extend = deadline
        best[i] = min(best[i + 1] + 1, extend)

    ans = 0

    for i in range(n):
        length = n - i
        k = best[i]
        if k >= length:
            ans += length * (length + 1) // 2
        else:
            ans += k * (k + 1) // 2
            ans += (length - k) * k

    print(ans)

if __name__ == "__main__":
    solve()
```配列`best`位置の値は右から左に計算されるため、`i`すでに計算された次の値に依存します`i + 1`。 再帰では、現在のロボットの期限と次のサフィックス結果のみが使用されるため、データ構造は必要ありません。 

貢献度の計算では、最初の合計の計算式が使用されます。`k`正の整数。 サブ配列が最大有効プレフィックスよりも長くなる場合、追加のロボットはスコアを変更しないまま維持します。そのため、残りの部分が貢献します。`(length - k) * k`。 

すべての計算は Python 整数を使用して実行され、32 ビット範囲を超える可能性のある大きな合計が自動的に処理されます。

import sys, io

def run(inp: str) -> str:
    old = sys.stdin
    sys.stdin = io.StringIO(inp)
    
    n, L = map(int, input().split())
    a = list(map(int, input().split()))

    best = [0] * (n + 2)

 ## 特殊なケース

 単一ロボットの場合:```
Input:
1 100
50
```アルゴリズムは計算します`best[1] = 1`。 唯一の部分配列の長さは 1 なので、寄与は 1 です。 1 台のロボットが常に 1 つのグループを形成するため、結果は正しいです。 

同等の速度のロボットの場合:```
Input:
4 10
10 10 10 10
```どのロボットにも期限がある`1`。 計算された`best`価値観がすべて`1`。 各開始位置は有効なグループを 1 つだけ提供するため、答えは次のようになります。`4`。 常に等しい速度を分離できると仮定したソリューションでは、オーバーカウントになります。 

混合ケースの場合:```
Input:
4 10
1 3 6 10
```最初のロボットには長い期限があり、配置が遅れる可能性があります。 最後のロボットには期限がある`1`そして直ちに撃たれなければなりません。 反復では、有効なプレフィックス長を作成することでこれをキャプチャします。`[3, 2, 1, 1]`、最終的な合計は必要なグループ化動作と一致します。
