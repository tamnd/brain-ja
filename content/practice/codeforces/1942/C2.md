 ## 解決策
 ## 問題の理解

 正多角形があります`n`円上に配置された頂点。 いくつかの`x`頂点はすでに使用可能です。 追加で最大でも選択できます`y`頂点が増えます。 

頂点を選択した後、選択したセットに端点が属する交差しない対角線を描くことができます。 このような三角形分割によって作成されたすべての三角形領域は、有効なケーキのピースとしてカウントされます。 目標は、三角形の数を最大化することです。 

重要な観察は、正多角形の実際の幾何学形状は無関係であるということです。 選択した頂点の循環順序のみが重要です。 

制約は、ソリューションが次のものに依存する必要があることを直ちに示唆します。`x`、オンではありません`n`。 それでも`n`と同じ大きさにすることができます`10^9`、すべての合計`x`テスト ケース全体の値は最大でも`2 · 10^5`。 に比例する任意のアルゴリズム`n`不可能です。 選択した頂点と頂点間のギャップのみを処理する必要があります。 

微妙な点は、頂点を追加しても三角形が自動的に作成されないことです。 新しい頂点は、すでに選択されている頂点間の大きなギャップを分割できる場合にのみ役立ちます。 ギャップがどれだけの利益をもたらすかを正確に理解することが最も重要な課題です。 

選択した頂点が連続している多角形について考えてみましょう。 他の場所に未使用の頂点がどれだけ存在しても、それらが適切なギャップに挿入されなければ、何も貢献しません。 

もう 1 つの簡単な間違いは、すべてのギャップを独立して扱い、そこから可能なすべての三角形を常に抽出できると仮定することです。 ギャップに未使用の頂点が多数含まれているが、予算が少ないと仮定します。`y`。 そうなると、その可能性の一部しか実現できないため、貪欲な割り当て戦略が必要になります。 

例えば：```
n = 10
chosen = {1, 5}
y = 1
```ギャップには 3 つの中間頂点が含まれています。 追加の頂点は 1 つしか選択できないため、ギャップの利点を最大限に活用することはできません。 

2 番目の落とし穴はパリティにあります。```
chosen = {1, 4}
```それらの間には未使用の頂点が 2 つあります。 

中間頂点を 1 つだけ追加すると、すぐに追加の三角形が作成されます。 奇数のギャップ サイズと偶数のギャップ サイズでは動作が異なり、その違いを利用することが、難しいバージョンと簡単なバージョンを区別します。 

## アプローチ

 ブルートフォースアプローチでは、追加の頂点のすべてのサブセットを試し、最適な三角形分割を計算し、最大の答えを維持します。 

中程度の値であっても、これは爆発的に増加します。 あれば`n - x`利用可能な頂点の数は次のとおりです。$$\sum_{k=0}^{y}\binom{n-x}{k}$$それは完全に不可能です。 

次のアイデアは、何が答えを幾何学的に決定するのかを理解することです。 

選択した頂点がすべてすでにわかっていると仮定します。 それらを循環的な順序で接続します。 これらは、選択した点を頂点とする多角形を形成します。 

あれば`m`選択した頂点、そのポリゴンの完全な三角形分割には正確に次のものが含まれます$$m - 2$$三角形。 

したがって、最初の答えは、選択された頂点の数によって決まります。 残る唯一の問題は、連続して選択された頂点間のギャップ内にある未使用の頂点から追加の三角形をいくつ抽出できるかということです。 

選択した 2 つの連続する頂点に`g`その間の未使用の頂点。```
A ... g vertices ... B
```最終的にこれらの頂点をすべて使用すると、このギャップが寄与します。`g`余分な三角形。 

重要な観察は、それらの三角形がどれほど高価であるかです。 

奇数のギャップの場合:```
g = 2k + 1
```私たちは得ることができます`k + 1`のみを使用した追加の三角形`k`頂点を追加しました。 

均等なギャップの場合:```
g = 2k
```私たちは得ることができます`k`追加の三角形を使用して`k`頂点を追加しました。 

厳密には、奇数のギャップの方が優れています。 彼らは追加の三角形を「無料」で 1 つ提供します。 

これにより、問題はリソース割り当ての問題に変わります。 

あらゆるギャップがパッケージを提供します:

 奇数のギャップの場合:```
cost = g // 2
gain = g // 2 + 1
```均等なギャップの場合:```
cost = g // 2
gain = g // 2
```奇数のギャップは同じコストで 1 つの追加の三角形を与えるため、最初にすべての奇数のギャップをコストの増加順に処理する必要があります。 

余裕のあるすべての収益性の高い奇数ギャップを取得した後、残りの予算は、やはりコストの増加順に偶数ギャップに費やされます。 

ギャップを完全に完了できない場合でも、追加の選択頂点ごとにさらに 2 つの境界エッジが生成され、したがってさらに 1 つの三角形が生成されます。 残りの予算は直線的に寄与します。 

この貪欲な戦略は、まさに公式ソリューションが利用しているものです。

 ## アルゴリズムのチュートリアル

 1. 最初に選択した頂点を並べ替えます。 
2. 連続して選択された頂点間のすべての周期的なギャップを計算します。 

連続して選択された頂点が`a`そして`b`、 それから```
gap = b - a - 1
```ラップアラウンドギャップ用```
gap = n - last + first - 1
```3. によって形成される多角形`x`最初に選択された頂点はすでに寄与しています```
x - 2
```三角形。 
4. ギャップを奇数グループと偶数グループに分けます。 
5. 奇数のギャップごとに`g`:```
cost = g // 2
gain = g // 2 + 1
```これらのギャップを保存し、コスト別に並べ替えます。 
6. 奇数のギャップをコストの増加順に処理します。 

十分な予算が残っている場合は、必要なコストを費やし、利益の全額を追加して続行します。 

余分な`+1`ゲインを使用すると、これらのギャップは偶数のギャップよりも厳密に優れたものになります。 
7. ギャップをコストの増加順に処理します。 

均等なギャップの場合:```
cost = g // 2
gain = g // 2
```可能な限り完全に完了します。 
8. その後、ある程度の予算が残っている場合は、未使用の選択された頂点ごとに 1 つの追加の三角形を作成できます。 

追加```
2 * remaining_budget
```潜在的な境界寄与は、利用可能な残りの頂点の合計によって制限されます。 

標準的な実装では、これは同じギャップ処理公式によって当然説明されます。 
9. 結果として得られる三角形の数を出力します。 

### なぜ効果があるのか

 すべての三角形は、選択した連続する頂点間のギャップを分割することで作成されます。 

サイズのギャップに`g`、そのギャップを完全に活用するには、`⌊g/2⌋`追加の頂点。 奇数のギャップは、同じコストの偶数のギャップと比較して、1 つの余分な三角形を生成します。 すべてのコストは加算され、ギャップ間で独立しているため、問題はすべてのアイテムにユニット効率があり、奇数のアイテムに 1 つのボーナス三角形があるというナップザックになります。 

最初に奇数のギャップを選択すると、収集されるボーナス三角形の数が最大になります。 すべてのボーナスが使い果たされた後、どの偶数ギャップが受け取るかに関係なく、残りの予算単位はすべて同じ限界利益を生み出します。 必要なコストで並べ替えると、予算がなくなる前に収益性の高いギャップの最大数が完了することが保証されます。 

すべてのギャップは独立しており、ギャップ内に生成されるすべての三角形は、そのギャップに投入される頂点の数にのみ依存するため、貪欲な割り当てが最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n, x, y = map(int, input().split())
        a = sorted(map(int, input().split()))

        ans = x - 2

        odd = []
        even = []

        for i in range(x):
            j = (i + 1) % x

            if j:
                gap = a[j] - a[i] - 1
            else:
                gap = n - a[i] + a[0] - 1

            if gap == 0:
                continue

            if gap % 2:
                odd.append(gap)
            else:
                even.append(gap)

        odd.sort()
        even.sort()

        for g in odd:
            need = g // 2

            if y >= need:
                y -= need
                ans += g // 2 + 1
            else:
                ans += 2 * y
                y = 0
                break

        if y:
            for g in even:
                need = g // 2

                if y >= need:
                    y -= need
                    ans += g // 2
                else:
                    ans += 2 * y
                    y = 0
                    break

        print(ans)

solve()
```このソリューションは、実際のポリゴンの頂点に対して反復されることはありません。 選択した頂点間のギャップのみを検査するため、次のような場合でも高速なままです。`n`と同じくらい大きいです`10^9`。 

最も重要な実装の詳細は、循環ギャップの計算です。 最終的なギャップは、選択した最大の頂点から最小の頂点まで回り込みます。 このラップアラウンド ギャップが欠けていると、有用な頂点が頂点間の境界をまたいでいる場合に常に誤った答えが発生します。`n`そして頂点`1`。 

もう 1 つの微妙な点は、部分的に処理されたギャップの処理です。 ギャップが残りのバジェットよりも多くのバジェットを必要とする場合、追加で選択された各頂点は依然として 2 つの新しい境界セグメントに寄与し、これは 2 つの追加の三角形の機会に変換されます。 だからこそ貢献度は`2 * y`予算がなくなる前に。 

Python の整数は、関係するすべての値を簡単に処理できるため、オーバーフローは心配ありません。
