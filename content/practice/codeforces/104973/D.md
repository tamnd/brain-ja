 ## 問題の理解

 配列から始めます`a`最大化したい総和に寄与する要素。 要素を削除することが許可されています`a`ただし、削除は任意ではありません。各削除は 2 番目の配列から位置を選択することによってトリガーされます。`b`、および対応するインデックス付き要素を現在の状態から削除します。`a`。 削除するたびに配列が縮小し、すべてのインデックスが左に移動します。 

重要な制限は、最大でも実行できることです。`k`合計で削除があり、それぞれの削除はいくつかを選択することによって行われる必要があります。`b[i]`これは現在の配列内でまだ有効なインデックスです。 以来`b`は厳密に増加しており、それぞれの値は`b[i]`元の配列内の徐々に深い位置を指しますが、削除後、これらの位置は動的になります。 

目標は、最大でも次のシーケンスを選択することです。`k`このような削除は、残りの要素の最終的な合計を最大化します。 

制約は十分小さいので、`n ≤ 2000`したがって、二次またはわずかに超二次的な解は許容されます。 ただし、立方体以上のものは`n`考えられるすべての操作数と位置に対して繰り返すと遅すぎます。 微妙な問題は、削除が独立していないことです。要素を削除すると、その後のすべてのインデックスがシフトされるため、構造なしで繰り返し実行すると単純なシミュレーションが複雑になります。 

一般的な障害モードは、削除が値によって貪欲に処理できると想定した場合に発生します。 たとえば、許可された位置の中で常に最小の利用可能な要素を削除するのは誤りです。小さな早期削除はシフトする可能性があるためです。`b[i]`後で配列のより良い部分または悪い部分に配置します。 

別の微妙なケースが発生する場合`k`に比べて大きいです`m`。 多くの操作が許可されていても、必ずしもすべてを使用できるわけではありません。`b[i] > |a|`、そのインデックスは使用できなくなります。 したがって、実際の削除数は状態に依存し、固定されません。

主な観察は、削除された要素のアイデンティティは、停止する前に実行する削除の回数と、そのプレフィックスによってのみ重要であるということです。`b`引き続き使用可能です。 任意の順序で削除をシミュレートする代わりに、プレフィックスから「消費」される削除の数を選択するという観点からプロセスを再解釈できます。`b`さまざまな時間に。

 ## アルゴリズムのチュートリアル

 動的プログラミング状態を定義します`dp[i][j]`最初の条件を考慮して取得できる最大の合計として`i`の要素`a`正確に実行した後`j`削除。 

複雑なのは、削除が許可されるのは、次のような場合のみであることです。`b[i]`現在の縮小された配列サイズの下で有効になります。 現在のサイズを明示的にモデル化する代わりに、位置でそれを観察します。`i`、削除した場合`j`これまでの要素の場合、有効な元のインデックスは次のようになります。`i + j`。 これにより、`b`この時点までの制約は「利用可能」になっています。 

それぞれについて事前計算します`i`インデックスはいくつありますか`b`≤`i`、現在位置にいる場合に、削除オプションがいくつ存在するかを示します。`i`元の配列で。 これをそのままにしておきます`cnt[i]`。 

ここでプロセスを再解釈します: 位置に着いたとき`i`、すでに使用された削除の数`j`を超えてはなりません`cnt[i]`、利用可能な有効な数を超える削除を実行することはできないためです。`b`それまでのインデックス。 

次に、トランジションを実行します。 

1.初期化`dp[0][0] = 0`要素を処理する前には合計がないため、他のすべての状態は負の無限大になります。 
2. ポジションごとに`i`から`0`に`n - 1`、可能なすべての状態を更新します`j`まで`k`、以前の結果を引き継ぎます。 これは、現在の要素のスキップまたは処理を表します。 
3. 州ごとに`(i, j)`、私たちは維持することを検討しています`a[i]`に遷移します。`(i + 1, j)`付加価値のあるもの`a[i]`。 
4.削除も検討します`a[i]`に遷移します。`(i + 1, j + 1)`ただし、その場合に限り`j + 1 ≤ cnt[i + 1]`。 これにより、有効な制約のみが尊重されるようになります。`b`ポジションはシフト後に使用できます。 
5. 最大合計を維持しながら、すべての有効な遷移を伝播します。 

すべての位置を処理した後の答えは最大値です`dp[n][j]`全体`j ≤ k`。 

重要な不変条件は次のとおりです`dp[i][j]`ある長さのプレフィックスを処理した後に達成可能な最良の合計を正しく表します`i`まさに`j`削除が有効な位置に対応するという制約の下で、削除。`b`シフト後。 によって強制される条件`cnt[i]`の構造を超える削除操作を決して使用しないようにします。`b`任意のプレフィックスで許可します。 すべての遷移は実現可能性と一致する方法で現在の要素を保持または削除するため、すべての有効なシーケンスが表現され、無効なシーケンスが導入されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    cnt = [0] * (n + 1)
    ptr = 0
    for i in range(1, n + 1):
        while ptr < m and b[ptr] <= i:
            ptr += 1
        cnt[i] = ptr

    NEG = -10**30
    dp = [[NEG] * (k + 1) for _ in range(n + 1)]
    dp[0][0] = 0

    for i in range(n):
        for j in range(k + 1):
            if dp[i][j] == NEG:
                continue

            # keep a[i]
            dp[i + 1][j] = max(dp[i + 1][j], dp[i][j] + a[i])

            # delete a[i]
            if j < k and j + 1 <= cnt[i + 1]:
                dp[i + 1][j + 1] = max(dp[i + 1][j + 1], dp[i][j])

    ans = max(dp[n])
    print(ans)

if __name__ == "__main__":
    solve()
```DP テーブルは行ごとに構築されるため、同じレイヤーの状態を誤って再利用することはありません。 の`cnt`配列はポインタを使用して計算されます`b`、元の配列の各プレフィックスまでの許容される削除インデックスの数を示します。 

微妙な点はコンディションです`j + 1 ≤ cnt[i + 1]`。 これにより、処理後に次のことが強制されます。`i + 1`要素があるため、有効な数を超える削除を実行することはできません。`b`適用できそうな指標。 この制約がないと、DP は不可能な削除シーケンスを過剰にカウントしてしまいます。
