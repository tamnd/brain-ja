 ## 解決策
 ## 問題の理解

 文字列の固定辞書が与えられています。 各文字列は文字ツリー内のパスとして考えることができ、すべての文字が次の分岐につながります。 この構造を構築した後、複数の質問に答えるように求められます。 各クエリ自体は文字列であり、クエリごとに辞書内の有効なプレフィックスに対応するかどうかを判断する必要があります。 存在する場合、構造内でそのプレフィックスが終了する位置に関連付けられた事前計算された値を出力する必要があります。 どのプレフィックスにも一致しない場合、答えは -1 です。 

重要な点は、プレフィックスの存在を確認するだけではないということです。 トライの各プレフィックス ノードには追加情報が格納されます。そのノードを通過するすべての辞書単語のうち、そのノードから下にある完全な辞書単語を完成させるためにまだ必要な最小文字数が考慮されます。 言い換えれば、すべての接頭辞において、その接頭辞にコミットした場合に、ある単語の完成にどれだけ「近づく」かを知りたいのです。 

この制約は、辞書のすべての語長の合計とすべてのクエリの長​​さの合計の程度の合計入力サイズを意味します。 これにより、トライのサイズにおける線形時間にクエリ走査における線形時間を加えたものになるでしょう。 クエリごとまたはプレフィックスごとに文字を繰り返し再処理するソリューションは遅すぎます。 すべての辞書単語に対する単純なクエリごとのスキャンでは、辞書のサイズに比例して作業が繰り返されることになりますが、辞書とクエリの両方が大きい場合、これは直ちに実行不可能になります。 

クエリ文字列がトライ内に存在するプレフィックスと一致するが、それ自体は情報を保存したノードに対応しない場合、微妙なエッジ ケースが発生します。 たとえば、辞書に「abc」と「abcd」が含まれている場合、単語がそこで終わっていなくても「ab」は有効なプレフィックス ノードであるため、「ab」のクエリは引き続き機能します。 終端ワードの情報のみを記録する不用意なアプローチでは、そのようなクエリが誤って拒否されたり、初期化されていない値が返されたりする可能性があります。 

もう 1 つの特殊なケースは、複数の辞書単語が接頭辞を共有しているものの、残りの長さが大きく異なる場合です。 たとえば、「a」と「abcde」です。 プレフィックス「a」では、保存された正しい値は、任意のパスではなく、最短の完了パスを反映している必要があります。 

## アプローチ

 各クエリに答える直接的な方法は、クエリ文字列ごとに辞書のすべての単語を調べて、そのクエリをプレフィックスとして持つ単語があるかどうかを確認することです。 その場合、一致するすべての単語と比較して、残りの最小長を計算します。 

これは、答えの定義を明示的にテストするため論理的に機能しますが、コストが法外に高くなります。 クエリごとに、辞書のすべての単語と比較し、それらの単語内の文字をスキャンして接頭辞の関係を確認する可能性があります。 同じようなサイズの単語やクエリが多数ある場合、文字操作全体では 2 次またはさらに悪化します。 

重要な観察は、接頭辞の関係が自然にトライとして構造化されていることです。 プレフィックス チェックを繰り返し再計算する代わりに、すべてのノードがプレフィックスを表す単一のツリーを構築します。 この構造が存在すると、プレフィックスの存在とそのプレフィックスを共有するすべての単語の集計の両方が、すべての文字列に対するグローバル スキャンではなく、ノードのローカル プロパティになります。 

すべての単語をトライに保存したら、残りの最小長で各ノードに注釈を付けて、そこを通過する単語を完成させることができます。 これは挿入中に計算できます。単語を下に進んでいくと、単語が終わるまでに何文字残っているかがわかり、これまでに確認された最小の値で訪問した各ノードを更新します。 その後、クエリは単にクエリ文字列に従ってトライをたどり、最終ノードで保存された値を読み取るだけになります。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(Q・S・L) | お(1) | 遅すぎる |
 | 前処理で試してみる | O(S + R) | O(S) | 承認済み |

 ここで、S は辞書の単語の合計長、R はクエリ文字列の合計長です。 

## アルゴリズムのチュートリアル

 各ノードで追加のメタデータを維持しながら、すべての辞書の単語に対してトライを構築します。 

1. 空のプレフィックスを表すルート ノードを作成します。 各ノードには、文字と大きな数値に初期化された整数値の子リンクが格納されます。 この値は、このノードを通過する単語を終了するために必要な残りの最小文字を表します。 
2. 辞書内のすべての単語について、文字ごとに検索します。 単語内の位置 i での残りの長さは、i から単語の終わりまでの残りの文字数です。 訪問した各ノードで、保存されている値が現在保存されている値より小さい場合は、この残りの長さで保存値を更新します。 これにより、各プレフィックス ノードは、通過するすべての単語の中で可能な限り最適な補完を認識できるようになります。 
3. すべての単語を処理した後、トライ内の各ノードは、その接頭辞を含むすべての辞書単語の最小接尾辞長を正しく格納しました。 
4. 各クエリ文字列について、その文字に続くルートからトライをたどります。 どこかの時点で次の文字が欠落している場合、その接頭辞は辞書構造に存在しないため、すぐに -1 が出力されます。 
5. クエリ全体のトラバーサルが成功した場合は、保存された値が最終ノードに出力されます。 この値は、そのプレフィックスの可能な限り最適な完全長をすでに表しています。 

これを正しくする重要な特性は、すべての辞書の単語がそのパスに沿ったすべてのプレフィックス ノードにその接尾辞の長さを寄与し、各ノードはそのような寄与すべてに対して最小値のみを保持することです。 これは、クエリ時にグローバル検索が必要ないことを意味します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**18

class Node:
    __slots__ = ("nxt", "best")
    def __init__(self):
        self.nxt = {}
        self.best = INF

def solve():
    n = int(input())
    root = Node()

    for _ in range(n):
        w = input().strip()
        cur = root
        length = len(w)

        for i, ch in enumerate(w):
            rem = length - i
            if ch not in cur.nxt:
                cur.nxt[ch] = Node()
            cur = cur.nxt[ch]
            if rem < cur.best:
                cur.best = rem

    q = int(input())
    out = []

    for _ in range(q):
        s = input().strip()
        cur = root
        ok = True

        for ch in s:
            if ch not in cur.nxt:
                ok = False
                break
            cur = cur.nxt[ch]

        if not ok:
            out.append("-1")
        else:
            out.append(str(cur.best))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```トランジションをコンパクトかつ柔軟に保つために、トライはノードごとに辞書を使用して実装されます。 各ノードは、`best`最初の更新で常に意味のあるベースラインが設定されるように、値は無限大に初期化されます。 

挿入中に重要な詳細が更新されます`best`ターミナルノードだけでなく、すべてのプレフィックスノードでも。 残りの長さ`len(word) - i`単語を完成させるためにその接頭辞から何ステップ必要かが直接キャプチャされます。 

クエリ中のトラバーサルは純粋に構造的なものです。 後続のエッジを超えて集計や計算は行われません。 答えは、保存されている値、またはパスが壊れている場合は -1 です。 

## 実用的な例

 単語が載った小さな辞書を考えてみましょう`"abc"`そして`"abd"`そしてクエリ`"ab"`、`"abc"`、 そして`"a"`。 

挿入の場合、プレフィックス ノードと残りの長さを追跡します。 

| 単語 | プレフィックス | ノードに到達しました | 残りの長さ | 更新後の Node.best |
 | --- | --- | --- | --- | --- |
 | ABC | | | 3 | 3 |
 | ABC | アブ | アブ | 2 | 2 |
 | ABC | ABC | ABC | 1 | 1 |
 | アブド | | | 3 | 3 |
 | アブド | アブ | アブ | 2 | 2 |
 | アブド | アブド | アブド | 1 | 1 |

 今すぐクエリ`"ab"`:

 | ステップ | キャラクター | ノードが存在します | 現在のノード | アクション |
 | --- | --- | --- | --- | --- |
 | 1 | | はい | | 移動 |
 | 2 | b | はい | アブ | 移動 |

 出力は`ab.best = 2`、接頭辞「ab」からの最短の補完が 2 文字であることを意味します。 

クエリ`"abc"`ノードに従う`abc`そして戻ってきます`1`。 クエリ`"a"`返品`3`。 

これらのトレースは、保存された値が、接頭辞を共有するすべての単語の中で最も短い拡張子を常に反映していることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(S + R) | 各辞書文字はトライ挿入中に 1 回処理され、各クエリ文字はトラバーサル中に 1 回処理されます。 
| スペース | O(S) | トライ内のそれぞれの一意のプレフィックス ノードは、辞書文字ごとに最大 1 つの文字遷移に対応します。 

入力内のすべての文字は、構築中またはクエリ走査中に一定量の作業に寄与するため、複雑さは制約構造と一致します。 クエリ間での再計算は行われません。

 ## 特殊なケース

 重要なエッジ ケースは、クエリが終端単語ではない内部ノードで終了する場合です。 たとえば、辞書`"abcd"`そしてクエリ`"ab"`。 のトライノード`"ab"`存在しますが、そこで終わる言葉はありません。 アルゴリズムは引き続き有効な値を割り当てます。`best`挿入中に、`"abcd"`ノードで残りの長さ 2 を提供します`"ab"`なので、クエリは正しく返されます。`2`。 

もう 1 つのケースは、複数の単語が接頭辞を共有しているものの、長さが大幅に異なる場合です。`"a"`そして`"aaaaa"`。 ノードで`"a"`、アルゴリズムは残りの長さを比較します`0`そして`4`そして保管します`0`、すぐに終わる完全な単語が、長い単語補完よりも優先されるようにします。 

最後のケースは、部分的に一致するが、早期に分岐するクエリです。 辞書用`"apple"`そしてクエリ`"apx"`、トラバースは失敗します`'x'`エッジが存在しないため`"ap"`、アルゴリズムはすぐに戻ります`-1`それ以上の計算は試行せずに。
