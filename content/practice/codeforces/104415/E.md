 ## 解決策
 ## 問題の理解

 頂点が一意の整数ラベルによって識別されるグラフが与えられます。 1 から最大値までの範囲のラベルの中には、実際の頂点に対応しないものもあります。 グラフには、これらのラベル付き頂点間の無向エッジも含まれています。 

私たちがシミュレートするプロセスは段階的に行われます。 ラベルを昇順に検討します。 ラベルに到達すると、対応する頂点が存在する場合はそれをアクティブ化し、接続できるようにします。 頂点がアクティブになると、その頂点をすでにアクティブな頂点にリンクするすべてのエッジを介して頂点も接続します。 それぞれの瞬間に、すべてのアクティブな頂点によって引き起こされるサブグラフを効果的に調べています。 

タスクは、アクティブなサブグラフが完全に接続されるすべてのラベル値を決定することです。これは、現在アクティブなすべての頂点が単一の接続されたコンポーネント内に存在することを意味します。 スイープ中にどの頂点にも対応しないラベルに到達した場合、それ以上意味のあるアクティブ化が行われないため、プロセスは直ちに停止します。 

この制約は、頂点とエッジの数が十分に大きいため、接続性を最初から繰り返し再計算するアプローチでは遅すぎることを意味します。 挿入のたびに単純な BFS または DFS を実行すると O(n(n + m)) のコストがかかりますが、n が大きい場合は実行不可能になります。 これにより、ユニオン操作がほぼ一定時間で行われる DSU ベースの増分接続メンテナンス アプローチが推進されます。 

ラベルが欠落している場合、微妙な特殊なケースが発生します。 頂点 {1, 2, 4, 5} があるとします。 ラベル 3 に到達すると、アクティブ化する頂点がなくなり、スイープが終了します。 欠落しているラベルを無視する単純な実装では、誤って 4 および 5 に進み、プロセス定義では無効な回答が生成される可能性があります。 

もう 1 つのエッジ ケースは、グラフが早期に接続されたものの、以前の結合を保持せずに誤って最初から再計算した場合、後の追加で仮定が崩れる場合に発生します。 これは通常、DSU によって回避されますが、反復的なトラバーサル アプローチによっては回避されません。 

## アプローチ

 ブルートフォースのアイデアは単純です。 ラベルごとにプロセスをシミュレーションします。 各ラベル i について、アクティブな頂点のセットを維持し、DFS または BFS を使用して頂点間の接続を再構築します。 i までのすべての頂点をアクティブ化した後、すべてのアクティブな頂点が単一の接続コンポーネントに属しているかどうかを確認します。 そうであれば、i を有効な回答として記録します。 

これは、すべてのステップで接続を直接チェックするため、正しく機能します。 ただし、コストはグラフの走査の繰り返しによって大きく左右されます。 O(n) 個のステップがあり、各ステップが O(n + m) 個のエッジをスキャンする場合、合計の複雑さは O(n(n + m)) になり、これは一般的な制約には大きすぎます。 

重要な観察は、接続性が段階的に進化しているということです。 i から i + 1 に移行するときに、接続を最初から再計算する必要はありません。 新しい頂点を追加し、それをすでにアクティブな隣接頂点と結合するだけです。 DSU (Disjoint Set Union) は、まさにこの種の増分マージ用に設計されています。 

重要な構造特性は、エッジは接続性の観点からのみ追加され、決して削除されないことです。 したがって、2 つの頂点が同じコンポーネント内にあると、それらはそのまま残ります。 この単調性により、接続情報を効率的に維持できるようになります。 

ラベルを昇順にスイープします。 頂点をアクティブ化するたびに、すでにアクティブになっているすべての隣接頂点と結合します。 アクティブな頂点間で接続されたコンポーネントの数を維持します。 このカウントが 1 になると、現在のラベルが記録されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (各ステップで BFS/DFS を再計算) | O(n(n + m)) | O(n + m) | 遅すぎる |
 | DSU インクリメンタル スイープ | O((n + m) α(n)) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

DSU 構造と、頂点がアクティブかどうかを追跡するブール配列を維持します。 有効成分のカウンターも保管しています。 

1. 最小のラベルから開始して上に移動します。 アクティベーションは識別子を増やすことによって厳密に定義されるため、この順序は重要です。 
2. ラベル i に到達したら、まずこのラベルを持つ頂点が存在するかどうかを確認します。 そうでない場合は、この時点以降の状態変更は定義されていないため、プロセスは直ちに終了します。 
3. 頂点が存在する場合は、それをアクティブ化し、最初はそれを独自の接続コンポーネントとして扱います。 これにより、コンポーネント数が 1 つ増加します。 
4. この頂点の近隣すべてを反復処理します。 すでにアクティブになっている各ネイバーについて、DSU セットをマージします。 以前は別々だった 2 つのコンポーネントがマージされる場合、コンポーネント数は 1 つ減ります。 これにより、アクティブなノード間に存在する接続されたコンポーネントの数の正確な数が維持されます。 
5. すべての近傍を処理した後、アクティブなコンポーネントの数が 1 に等しいかどうかを確認します。 そうであれば、すべてのアクティブな頂点が他のすべてのアクティブな頂点から到達可能であることを意味するため、現在のラベルが有効な答えになります。 

このローカル マージで十分な理由は、すべての接続情報がエッジを通過し、各エッジは後のエンドポイントがアクティブ化されるときに 1 回だけ処理されるためです。 

### なぜ効果があるのか

 DSU は、どの時点においても、すべてのアクティブな頂点が、アクティブな頂点の誘導されたサブグラフ内の接続コンポーネントを表す 1 つのセットに正確に属するという不変条件を維持します。 すべての結合操作は、2 つのアクティブな頂点間にエッジを導入することに正確に対応しており、これがコンポーネントの数を削減できる唯一のイベントです。 エッジを削除したり頂点を非アクティブにしたりすることはないため、すべてのアクティブな頂点が 1 つの DSU セットにマージされると、将来のすべての状態で接続されたままになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    adj = [[] for _ in range(n + 1)]
    exists = [False] * (n + 1)

    for _ in range(m):
        u, v = map(int, input().split())
        adj[u].append(v)
        adj[v].append(u)

    # mark which identifiers exist
    # (if input guarantees all 1..n exist, this loop is harmless)
    for i in range(1, n + 1):
        exists[i] = True

    parent = list(range(n + 1))
    size = [1] * (n + 1)

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    def union(a, b):
        ra, rb = find(a), find(b)
        if ra == rb:
            return False
        if size[ra] < size[rb]:
            ra, rb = rb, ra
        parent[rb] = ra
        size[ra] += size[rb]
        return True

    active = [False] * (n + 1)
    comp = 0

    res = []

    for i in range(1, n + 1):
        if not exists[i]:
            break

        active[i] = True
        comp += 1

        for v in adj[i]:
            if active[v]:
                if union(i, v):
                    comp -= 1

        if comp == 1:
            res.append(i)

    print(*res)

if __name__ == "__main__":
    solve()
```このソリューションは、エンドポイントの処理時にすべてのエッジが利用できるように隣接リストを構築します。 DSU 構造は、アクティブなノード間の接続のみを追跡します。 の`active`array は、スイープの現在のプレフィックスで有効なエッジのみを結合することを保証します。 

の`comp`DSU だけでは、存在するコンポーネントの数を直接知ることができないため、変数は必須です。 代わりに、ユニオンが個別のセットを正常にマージした回数を明示的に追跡します。 

## 実用的な例

 ### 例 1

 頂点 1 ～ 4 とエッジ (1-2)、(2-3)、(3-4) を持つ小さなグラフを考えてみましょう。 順番にアクティベーションをシミュレートします。 

| 私 | アクティブなノード | DSU のマージ | コンポーネント | コンプ == 1 |
 | --- | --- | --- | --- | --- |
 | 1 | {1} | なし | 1 | はい |
 | 2 | {1,2} | 1-2 | 1 | はい |
 | 3 | {1,2,3} | 2-3 | 1 | はい |
 | 4 | {1,2,3,4} | 3-4 | 1 | はい |

 すべてのプレフィックスが接続されているため、すべてのラベルが記録されます。 これは、チェーンが完全に接続されると、その後のすべてのプレフィックスは接続されたままになるという不変条件を示しています。 

### 例 2

 ここで、2 つの切断されたペアを形成するエッジ (1-2) と (3-4) を考えてみましょう。 

| 私 | アクティブなノード | DSU のマージ | コンポーネント | コンプ == 1 |
 | --- | --- | --- | --- | --- |
 | 1 | {1} | なし | 1 | はい |
 | 2 | {1,2} | 1-2 | 1 | はい |
 | 3 | {1,2,3} | なし | 2 | いいえ |
 | 4 | {1,2,3,4} | 3-4 | 2 | いいえ |

 ここでは、新しい分離ブロックが導入されると接続が失われます。 DSU は、システムが完全に接続されていないことを正しく追跡します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n + m) α(n)) | 各エッジは 1 回処理され、各結合/検索はほぼ一定です。 
| スペース | O(n + m) | 隣接リストと DSU アレイ |

 複雑さは、最大 2×10^5 の n の一般的な制限内に問題なく収まります。 DSU は、償却された逆アッカーマン動作により、高密度のエッジ セットであっても効率を維持することを保証します。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、最初の数回のアクティベーションの直後にグラフが接続される場合です。 たとえば、ノード 1 が他のすべてのノードに接続されている場合、i = 2 の時点で、DSU はすでにすべてを 1 つのコンポーネントにマージしています。 最後に必要な結合が発生したときに comp が 1 になり、この状態がその後のすべての i に対して持続するため、アルゴリズムは i = 2 を正しく記録します。 

もう 1 つのエッジ ケースは、欠落している識別子が早期に出現したときに発生します。 ノード {1, 3, 4} のみが存在すると仮定します。 i = 2 に達すると、プロセスは終了します。 アルゴリズムは正しく停止します。`exists[i]`check は、それ以上のアクティブ化または結合操作を防止します。 欠落しているラベルを無視する単純なスイープは、プロセスがすでに停止しているはずであるにもかかわらず、誤って続行し、i = 3 および 4 の結果を生成します。 

最後の微妙なケースは、すでに接続されているコンポーネント間でエッジが繰り返されることです。 この場合、結合演算は false を返すため、コンポーネント数が誤って減少することはありません。 これにより、マージの過剰カウントが防止され、スイープ全体にわたって接続状態の一貫性が確保されます。
