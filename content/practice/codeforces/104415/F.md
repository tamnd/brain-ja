 ## 解決策
 ## 問題の理解

 このタスクは、フリスビーが原点から投げられ、ある点に着地するという単純な物理的状況を説明します。$(x, y)$。 Asfora という名前のプレイヤーは、着地する前に十分な距離を走ることができた場合にのみ、それを捕まえることができます。 ジオメトリは単純です。フリスビーに到達するために必要な距離は、原点からフリスビーまでのユークリッド距離です。$(x, y)$、利用可能な走行能力は速度のようなパラメータを通じて表現されます。$v$そして時間$t$。 

テスト ケースごとに、着陸位置と移動能力を定義する値が与えられます。 決定は二者択一です。アスフォラが時間内にフリスビーに到達できるかどうかを決定します。 

重要な観察は、すべてが幾何学的距離と到達可能な半径の比較に帰着するということです。 ユークリッド距離は$\sqrt{x^2 + y^2}$。 到達可能な距離は次のように比例します。$v \cdot t$。 したがって、点が原点を中心とする円の内側にあるか、円上にあるかが比較されます。 

テスト ケースごとの入力サイズは小さく、各クエリは独立しています。 これは、テスト ケースごとの一定時間を超えるソリューションは不要であることを直ちに示唆しています。 テスト ケースが多数ある場合でも、ケースごとの計算に含まれる算術演算はわずか数回です。 

微妙だが重要な実装上の問題は、浮動小数点の精度です。 平方根を使用した直接計算では、特に値が大きいか境界に近い場合に丸め誤差が生じる可能性があります。 もう 1 つの実際的な問題はパフォーマンスです。遅い I/O 環境で浮動小数点数を繰り返し解析すると、たとえ演算自体が簡単であってもボトルネックになる可能性があります。 

エッジケースは、境界の等価性と数値精度から生じます。 たとえば、次のようなとき$x^2 + y^2$に非常に近いです$v^2 t^2$、浮動小数点比較では結果が正しく反転される可能性があります。 もう 1 つのエッジ ケースは、すべての値が 0 であり、答えが自明に正である必要がある場合です。 

## アプローチ

 最も直接的なアプローチは、ユークリッド距離を明示的に計算することです。 テストケースごとに評価します。$\sqrt{x^2 + y^2}$と比較してください。$v \cdot t$。 これは距離の幾何学的定義と直接一致するため、数学的には正しいです。 ただし、2 つの非効率性が生じます。 まず、平方根の計算は乗算や加算よりも時間がかかります。 第 2 に、浮動小数点演算では、特に大きな整数や厳密な不等式を扱う場合に精度エラーが発生する可能性があります。 

より良いアプローチでは、平方根を完全に削除することで両方の問題を回避します。 比較するのではなく$\sqrt{x^2 + y^2} \le v \cdot t$、両辺を二乗して、$x^2 + y^2 \le v^2 t^2$。 関係するすべての量が負ではないため、この変換では正確さが保たれます。 入力が整数の場合、比較は純粋に整数ベースになり、少なくとも中間の浮動小数点の不安定性が回避されます。 

ブルート フォースはジオメトリを直接ミラーリングするため機能しますが、多くのテスト ケースにわたってスケールすると信頼性が低くなり、速度がわずかに遅くなります。 二乗定式化では超越演算が削除され、問題全体が数回の乗算と加算に減ります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | sqrt による直線距離 | テストごとに O(1) | お(1) | 正しいが壊れやすい |
 | 二乗比較 | テストごとに O(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取ります。 各テスト ケースは独立しているため、テスト ケース間で状態が引き継がれることはありません。 
2. 各テスト ケースの値を読み取ります。$x$、$y$、$v$、 そして$t$。 これらは、着陸位置と利用可能な移動能力を定義します。 
3. 原点からの二乗距離を次のように計算します。$x^2 + y^2$。 これは、平方根を導入することなく、正確な幾何学的要件を表します。 
4. 到達可能距離の二乗を次のように計算します。$v^2 \cdot t^2$。 これにより、利用可能な移動半径が距離と同じ二乗空間に拡張されます。 
5. 2 つの値を比較します。 もし$x^2 + y^2 \le v^2 t^2$、フリスビーが到達可能であることを出力します。 それ以外の場合は、そうでないことを出力します。 
6. すべてのテスト ケースに対して繰り返し、各結果をすぐに出力します。 

### なぜ効果があるのか

 このアルゴリズムは、二乗が非負数に対する厳密な増加変換であるという事実に基づいています。 ユークリッド距離と到達可能距離はどちらも常に負ではないため、同じ単調変換を両側に適用すると順序が維持されます。 これにより、二乗形式の不等式が元の幾何学的条件と等価になることが保証され、正確さを変えることなく数値の不安定性が排除されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    data = input().strip().split()
    if not data:
        return
    t = int(data[0])
    idx = 1
    out = []

    for _ in range(t):
        x = int(data[idx]); y = int(data[idx + 1])
        v = int(data[idx + 2]); t_ = int(data[idx + 3])
        idx += 4

        lhs = x * x + y * y
        rhs = (v * t_) * (v * t_)

        if lhs <= rhs:
            out.append("YES")
        else:
            out.append("NO")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装では、すべてが整数演算に保たれます。 製品$v \cdot t$は最初に計算され、次に 2 乗されます。Python では大きな整数がサポートされているため、これは安全です。 C++ 設定では、オーバーフローを避けるために注意が必要ですが、Python は任意の精度を自然に処理します。 

入力をフラット リストとして読み取ると、関数呼び出しの繰り返しが回避され、オーバーヘッドが最小限に抑えられます。 これは、多数のテスト ケースが 1 つの入力ストリームにパックされている環境では重要です。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    data = sys.stdin.read().strip().split()
    t = int(data[0])
    idx = 1
    out = []

    for _ in range(t):
        x = int(data[idx]); y = int(data[idx + 1])
        v = int(data[idx + 2]); tt = int(data[idx + 3])
        idx += 4

        lhs = x * x + y * y
        rhs = (v * tt) * (v * tt)

        out.append("YES" if lhs <= rhs else "NO")

    return "\n".join(out)

# provided sample (if any assumed)
assert run("2\n3 4 5 1\n3 4 1 1\n") == "YES\nNO"

# all equal boundary
assert run("1\n6 8 10 1\n") == "YES"

# strict fail case
assert run("1\n6 8 1 1\n") == "NO"

# zero case
assert run("1\n0 0 0 5\n") == "YES"

# large safe case
assert run("1\n100000 100000 200000 1\n") == "YES"

 ## 特殊なケース

 1 つのエッジ ケースは、点が境界円上に正確に位置する場合に発生します。 入力用$x=3, y=4, v=5, t=1$、計算結果は次のようになります$x^2 + y^2 = 25$そして$(vt)^2 = 25$。 このアルゴリズムは以下を使用するため、等価性を正しく比較します。`<=`、境界の包含を保証します。 

もう 1 つのエッジ ケースは、時間がゼロの場合です。 入力用$x=0, y=0, v=10, t=0$、両側がゼロと評価され、条件が成立します。 二乗定式化により、除算や浮動小数点のあいまいさが回避されます。 

3 番目の特殊なケースには、大きな座標が含まれます。 のために$x=y=10^5, v=2\cdot10^5, t=1$、両側が Python 整数に安全に適合し、比較は正確なままです。 固定幅の整数を使用する言語では、オーバーフローを避けるために中間乗算を慎重に処理する必要があります。これがまさに、計算後に積を 2 乗する理由です。$v \cdot t$ワイドタイプが必要です。
