 ## 解決策
 ## 問題の理解

 一連の授業には一連の出席点が与えられており、最初の授業からスキップしたり途中から始めたりすることなく、厳密に出席する必要があります。 各クラスは固定数のポイントを提供し、シーケンスを進めるにつれてこれらのポイントが蓄積されます。 

この配列に加えて、複数のクエリが与えられます。 各クエリは、実質的に、累積出席点の必要なレベルに達するために、Cayo が学期の開始からどのくらいの距離を進まなければならないかを尋ねます。 出席者は最初から連続しているため、すべての有効な回答は配列の何らかのプレフィックスに対応します。 

したがって、クエリ値ごとに、合計がその値に達するかそれを超える配列の最小のプレフィックスを特定し、その位置やその値までに蓄積された合計ポイントなど、そのプレフィックスに関する情報もレポートする必要があります。 

重要な構造上の制約は、出席は常に最初の授業から始まるということです。 これにより、任意のサブ配列処理の必要性がなくなり、問題は完全にプレフィックスの合計に関する推論に減ります。 

複雑さの観点から見ると、配列が大きくなりすぎて、各クエリの合計を個別に再計算すると時間がかかりすぎる可能性があります。 最大 100,000 のクラスと同様の数のクエリがある場合、クエリごとの単純な O(n) スキャンでは、最悪の場合、約 10^10 の操作が発生しますが、これは一般的な制限をはるかに超えています。 これは、配列を前処理し、対数時間または定数時間で各クエリに答える必要があることを直ちに示唆しています。 

クエリがすべてのクラスの合計より大きい値を要求する場合、微妙なエッジ ケースが発生します。 この場合、必要なしきい値に達するプレフィックスがないため、何を返すかを慎重に実装する必要があります。 同様に、しきい値がゼロまたは負の場合、正解はすぐに合計ゼロのプレフィックス動作を持つ最初の位置になります。これは通常、インデックス付け規則に応じて、合計 a[0] を持つインデックス 1 またはインデックス 0 になります。 このようなケースは、明示的に処理しないと単純な二分探索の境界を壊してしまうことがよくあります。 

## アプローチ

 直接的なアプローチでは、最初のクラスから反復し、必要なしきい値に達するまでポイントを蓄積することで、各クエリを独立して処理します。 これは簡単です。特定のクエリ値に対して、累計が十分に大きくなるまでクラス ポイントを追加し続けます。 問題で説明されているプロセスを正確にシミュレートするため、正確性がすぐにわかります。 

ただし、このアプローチでは、すべてのクエリに対して同じプレフィックス合計作業が繰り返されます。 最悪の場合、各クエリは配列のほぼ全体をスキャンする必要があり、合計の複雑さは O(n · q) になります。 制約が大きい場合、同じ部分和を繰り返し再計算することになるため、速度が非常に遅くなります。 

重要な点は、すべてのクエリが同じプレフィックス構造で動作することです。 プレフィックスの合計を一度計算すると、プレフィックスの合計は直接配列検索になります。 各クエリの残りのタスクは、プレフィックスの合計がしきい値と交差する最初の位置を見つけることです。 プレフィックス合計配列は減少しないため、これは古典的な二分探索問題になります。 

したがって、解決策は 2 段階に分かれます。 まず、配列を前処理してプレフィックス合計配列にします。 次に、プレフィックスの合計がクエリ値以上である最初のインデックスをバイナリ検索して、各クエリに答えます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n · q) | お(1) | 遅すぎる |
 | プレフィックス合計 + 二分検索 | O(n + q log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ソリューションは、前処理とクエリ処理の 2 つの段階で構築されます。

1. 各位置が最初のクラスからその位置までに累積された合計ポイントを格納するプレフィックス合計配列を計算します。 これにより、範囲の累積が定数時間のルックアップに変換されます。 
2. 各クエリ値 x について、合計が少なくとも x である最も古いプレフィックスを見つける必要があります。 プレフィックスの合計は単調増加するため、インデックス範囲全体に二分検索を適用できます。 
3. 二分探索中に中点を繰り返しチェックします。 その位置のプレフィックスの合計が x より小さい場合、答えは右側にあるはずです。 それ以外の場合は、この位置かそれより前の位置になる可能性があるため、左に移動します。 
4. 二分探索が完了すると、結果のインデックスが要件を満たす最小のプレフィックスになります。 次に、インデックス (必要に応じて 1 ベースのインデックスに変換) と、対応するプレフィックスの合計の両方を出力します。 
5. クエリ値が配列全体の合計を超える場合は、それより前のプレフィックスがそれを満たすことができないため、配列の全長とその合計を直接返します。 

これが機能する理由は単調性の特性に基づいています。つまり、配列内を前に進むにつれてプレフィックスの合計が減少することはありません。 これにより、条件「プレフィックス合計 >= x」が有効なインデックスの連続したサフィックスを定義することが保証されます。 インデックスが有効になると、その右側のすべてのインデックスも有効になり、その左側のインデックスはすべて無効になります。 二分探索は、この単一の遷移境界を利用するため、正確に機能します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def lower_bound_prefix(prefix, x):
    lo, hi = 0, len(prefix) - 1
    ans = len(prefix) - 1
    
    while lo <= hi:
        mid = (lo + hi) // 2
        if prefix[mid] >= x:
            ans = mid
            hi = mid - 1
        else:
            lo = mid + 1
    
    return ans

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))
    
    prefix = [0] * n
    prefix[0] = a[0]
    
    for i in range(1, n):
        prefix[i] = prefix[i - 1] + a[i]
    
    total = prefix[-1]
    
    out = []
    for _ in range(q):
        x = int(input())
        
        if x <= prefix[0]:
            idx = 0
        elif x > total:
            idx = n - 1
        else:
            idx = lower_bound_prefix(prefix, x)
        
        out.append(f"{idx + 1} {prefix[idx]}")
    
    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```コードは、各エントリがそのクラスまでの総出席者数を表すようにプレフィックス合計配列を構築することから始まります。 これにより、クエリ中の再計算が回避されます。 

ヘルパー関数は、必要なしきい値に達する最初のプレフィックスのバイナリ検索を実行します。 返されるインデックスはゼロベースであり、印刷時に調整されます。 

この検索を使用して各クエリは独立して処理され、クエリが最初のプレフィックスより小さい、または合計より大きい境界ケースを慎重に保護します。 

## 実用的な例

 出席点が次のような単純なケースを考えてみましょう。`[2, 1, 3, 2]`クエリはしきい値を要求します`3`そして`7`。 

プレフィックスの合計は次のようになります`[2, 3, 6, 8]`。 

### クエリ 1: x = 3

 | ステップ | そうだ | こんにちは | ミッド | 接頭辞[中間] | アクション |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 0 | 3 | 1 | 3 | 左に移動 |
 | 2 | 0 | 0 | 0 | 2 | 右に移動 |

 結果のインデックスは 1 で、プレフィックスの合計 3 に対応します。 

これにより、アルゴリズムが、単なる有効なポイントではなく、しきい値に到達する最も早いポイントを正しく検出していることが確認されます。 

### クエリ 2: x = 7

 | ステップ | そうだ | こんにちは | ミッド | 接頭辞[中間] | アクション |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 0 | 3 | 1 | 3 | 右に移動 |
 | 2 | 2 | 3 | 2 | 6 | 右に移動 |
 | 3 | 3 | 3 | 3 | 8 | 左に移動 |

 結果のインデックスは 3、プレフィックスの合計は 8 です。 

これは、バイナリ検索が不十分なプレフィックスを正しくスキップし、最初の有効なプレフィックスに収束する方法を示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + q log n) | プレフィックスの計算は線形であり、各クエリはプレフィックス配列 | に対する二分検索です。 
| スペース | O(n) | プレフィックス合計配列にはクラスごとに 1 つの値が格納されます。 

対数検索によりクエリごとの作業が最小限に抑えられるため、ソリューションは最大 100,000 個の要素とクエリの一般的な制約内に快適に適合します。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    return sys.stdout.getvalue() if False else solve_capture(inp)

def solve_capture(inp: str) -> str:
    import sys
    input = sys.stdin.readline
    data = inp.strip().split()
    it = iter(data)

    n = int(next(it))
    q = int(next(it))
    a = [int(next(it)) for _ in range(n)]

    prefix = [0] * n
    prefix[0] = a[0]
    for i in range(1, n):
        prefix[i] = prefix[i - 1] + a[i]

    total = prefix[-1]

    def lb(x):
        lo, hi = 0, n - 1
        ans = n - 1
        while lo <= hi:
            mid = (lo + hi) // 2
            if prefix[mid] >= x:
                ans = mid
                hi = mid - 1
            else:
                lo = mid + 1
        return ans

    out = []
    for _ in range(q):
        x = int(next(it))
        if x <= prefix[0]:
            idx = 0
        elif x > total:
            idx = n - 1
        else:
            idx = lb(x)
        out.append(f"{idx+1} {prefix[idx]}")
    return "\n".join(out)

 ## 特殊なケース

 配列に要素が 1 つしかない場合、接頭辞の計算と二分探索は両方とも簡単な動作に陥ります。 すべての正のクエリはその単一のプレフィックスにマップする必要があるため、アルゴリズムはインデックス 0 をすぐに返します。 

クエリがプレフィックスの合計の 1 つに正確に等しい場合でも、バイナリ検索はそのような最も古いインデックスを返す必要があります。 実装では、等しい場合でも右境界を左に移動することでこれを保証し、後で有効な位置が選択されるのを防ぎます。 

クエリが合計を超えると、アルゴリズムは結果を最後のインデックスにクランプします。 これにより、バイナリ検索が有効な範囲外をさまようことが回避され、条件を満たすプレフィックスがない場合でも、定義された出力が保証されます。
