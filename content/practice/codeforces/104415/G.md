 ## 解決策
 ## 問題の理解

 無向重み付きグラフが与えられます。 このグラフから、最小全域ツリーを構築し、距離がツリーのエッジに沿った最短経路距離である根のない構造としてツリーを考慮するように求められます。 最後のタスクは、MST 内の任意の 2 つの頂点間の可能な最大距離を決定することです。これは、結果として得られるツリーの直径と正確に一致します。 

したがって、パイプラインは概念的には 2 つの層になります。 まず、グラフは最小の総エッジ重みですべての頂点を接続するスパニング ツリーに圧縮されます。 次に、そのツリー内で、一意のパスに沿ってすべてのペアの距離を測定し、それらの間の最大値を抽出します。 

入力サイズの制約 (意図した解の複雑さ O(m log n) によって暗示される) は、グラフに最大 10^5 程度の頂点とエッジを含めることができることを示しています。 これにより、ツリーの構築後にノードのすべてのペア間の距離を計算しようとするソリューションは即座に除外されます。これは、単一の全ペアの走査でも O(n^2) になるためです。 MST 構築用の Kruskal や Prim など、対数オーバーヘッドを伴う線形または線形に近いグラフ アルゴリズムを使用し、その後に直径を求める線形ツリー トラバースを強いられます。 

MST ではなく元のグラフで直径を計算しようとすると、微妙な故障モードが表示されます。 MST は単なるスパニング ツリーではなく、特にどのエッジが存在するかを変更します。 たとえば、エッジ (1-2、重み 1)、(2-3、重み 1)、および (1-3、重み 100) を持つ三角形を考えてみましょう。 重いエッジを誤って許可した場合、元のグラフの直径は 100 になりますが、MST はそれを削除し、長さ 2 のパスを生成します。正しい答えは、元のグラフではなく、MST の構造に完全に依存します。 

もう 1 つのエッジ ケースは、複数のエッジの重みが等しい場合です。 この場合、複数の有効な MST が存在する可能性がありますが、それらはすべて有効なツリーを生成します。 直径はタイブレークによって異なる場合がありますが、この問題は標準的な決定論的な MST 構造を前提としています。 実際には、安定したソートを備えた Kruskal または Prim は、一貫した 1 つの MST を生成します。 

最後に、単純な間違いは、BFS または DFS を使用して MST 内のすべてのノードからの距離を再計算することです。 それは論理的には正しいですが、遅すぎます。 10^5 ノードを持つツリーでは、それぞれのコストが O(n) の 10^5 走査を実行すると、10^10 の操作が行われます。 

## アプローチ

 強引なアイデアは、最も直接的な解釈から始まります。 まず MST を構築し、次にノードのペアごとに DFS または BFS を使用してツリーに沿った距離を計算し、観測された最大値を追跡します。 木の距離は一意のパスであるため、これで正しい答えが得られます。 

このアプローチの問題は、正確さではなく規模です。 MST を O(m log n) で構築した後でも、ソース ノードごとに O(n) の作業が必要となり、合計は O(n^2) になります。 n が 10^5 までの場合、これは完全に不可能です。 

重要な観察は、木の直径はすべてのペアの計算を必要としないことです。 ツリーには、2 回のトラバースのみを使用して最長のパスを見つけることができる構造特性があります。 任意のノードから開始した場合、到達する最も遠いノードは、直径の 1 つの端点であることが保証されます。 その終点から再度開始すると、実際の直径の長さが得られます。 

これにより、第 2 フェーズが 2 次の動作からツリー上の線形走査に縮小されます。 MST 構築と組み合わせると、完全な解は O(m log n) になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (MST のすべてのペア) | O(n^2) | O(n) | 遅すぎる |
 | 最適 (MST + 2 つの BFS/DFS) | O(m log n) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 ソリューションを MST の構築とツリーの直径の計算に分けます。

1. すべてのエッジを重みでソートし、クラスカルのアルゴリズムを使用して昇順に処理し、素集合の結合構造を維持します。 2 つの異なるコンポーネントを接続するエッジに遭遇するたびに、それを MST に含めます。 これにより、サイクルなしで最小の総重みスパニング ツリーを構築できるようになります。 
2. すべてのエッジを処理した後、正確に n − 1 個のエッジを持つツリーを取得します。 距離の計算には高速なトラバーサルが必要なので、これを隣接リストとして表します。 
3. 任意のノード (通常はノード 1) を選択し、BFS または DFS を実行して、MST 内の到達可能なすべてのノードまでの距離を計算します。 開始点から最も遠いノードを記録します。 どのツリーでも、最も遠い最初のトラバースは直径の終点に到達するため、このノードは直径の終点の候補です。 
4. この最も遠いノードから 2 番目の BFS または DFS を開始します。 再度、ツリー内のすべてのノードまでの距離を計算し、発生した最大距離を追跡します。 この最大値がMSTの直径となります。 
5. この最大距離を出力します。 

2 番目のトラバースが必要な理由は、最初のトラバースでは直径の全長ではなく、直径の 1 つの端点のみが保証されるためです。 2 番目のパスでは、計算を真のエンドポイントに固定し、最長のパスを確実に取得します。 

### なぜ効果があるのか

 ツリーでは、任意の 2 つのノードが 1 つの単純なパスによって接続されます。 任意のノードを取得し、そこから最も遠いノードを見つけた場合、その最も遠いノードは少なくとも 1 つの直径パス上に存在する必要があります。 そうしないと、距離を延長することによって、矛盾してより長いパスが構築されてしまう可能性があります。 直径の 1 つの端点に到達すると、そこから最も遠いノードが反対側の端点になる必要があります。これは、逸脱するとパスが短くなるためです。 この不変条件により、グローバル最大距離を回復するには 2 つの BFS パスで十分であることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.rank = [0] * n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return False
        if self.rank[a] < self.rank[b]:
            a, b = b, a
        self.parent[b] = a
        if self.rank[a] == self.rank[b]:
            self.rank[a] += 1
        return True

def bfs(start, adj):
    from collections import deque
    dist = [-1] * len(adj)
    q = deque([start])
    dist[start] = 0
    far = start

    while q:
        u = q.popleft()
        for v, w in adj[u]:
            if dist[v] == -1:
                dist[v] = dist[u] + w
                q.append(v)
                if dist[v] > dist[far]:
                    far = v
    return far, dist[far]

def solve():
    n, m = map(int, input().split())
    edges = []
    for _ in range(m):
        u, v, w = map(int, input().split())
        u -= 1
        v -= 1
        edges.append((w, u, v))

    edges.sort()
    dsu = DSU(n)

    adj = [[] for _ in range(n)]

    for w, u, v in edges:
        if dsu.union(u, v):
            adj[u].append((v, w))
            adj[v].append((u, w))

    start = 0
    far, _ = bfs(start, adj)
    _, diameter = bfs(far, adj)

    print(diameter)

if __name__ == "__main__":
    solve()
```DSU クラスは、Kruskal のアルゴリズム中にサイクル検出を処理します。 パス圧縮により、操作あたりのほぼ一定の償却時間が保証されます。これは、最大 10^5 のエッジを効率的に処理するために必要です。 

隣接リストは、MST 選択後に生き残ったエッジに対してのみ構築されます。 結果として得られる構造は無向ツリーであるため、各エッジは両方向に格納されます。 

BFS 関数は、距離を計算し、最も遠いノードを追跡します。 両端キューを使用すると、ツリー全体の線形時間走査が保証されます。 重要な実装の詳細は、厳密に長い距離が見つかった場合にのみ最も遠いノードを更新することです。 

ソルブ関数は最初に MST を構築し、次に 2 フェーズ BFS を実行して直径を計算します。

 ## 特殊なケース

 エッジ ケースの 1 つは、グラフがすでにツリーになっている場合です。 その状況では、Kruskal は単純にすべてのエッジを受け入れ、MST は入力と同一になります。 BFS は変更せずに元の構造に直接適用されるため、アルゴリズムは引き続き機能します。 2 パス BFS は引き続き直径を正しく検出します。 

もう 1 つのケースは、すべてのエッジの重みが等しい星形のグラフです。 どの MST も有効であり、Kruskal は任意の順序でエッジを選択できますが、結果として得られるツリーは依然としてスターです。 直径は常に 2 であり、BFS はどのエッジが最初に選択されたかに関係なく、2 つのリーフを正しく識別します。 

最後のケースは、MST 構築中の切断された中間状態であり、DSU がサイクルを防止します。 複数のエッジがすでに接続されているコンポーネントを接続している場合でも、それらは安全にスキップされます。 最終的な隣接リストは常にツリーのままであり、直径計算の正確性が維持されます。
