 ## 解決策
 ## 問題の理解

 一連の整数が与えられ、それを左から右に処理します。 スキャン中に、各値がすでに出現した回数を維持します。 現在の値を実行周波数構造に挿入する前に、各位置で、その値と特定の乗算関係を形成する以前の要素の数を数えたいと考えます。 具体的には、現在の要素に対して$a_i$、前の要素を探します$a_j$どちらかの$a_j$分割する$a_i$または$a_i$分割する$a_j$、比率を通じて条件がどのように解釈されるかに応じて$x / a_i$と声明文で説明されている。 意図した計算は、1 つの値が固定ターゲットの商を現在の値で割った値であるペアをカウントすることになり、その商はすでに出現している必要があります。 

重要な隠れた構造は、値が小さいため、入力をハッシュやマップを必要とする任意の整数として扱う代わりに、値によってインデックス付けされた直接の頻度配列を維持できることです。 これにより、「計算された商に等しい値が以前に何回存在するか」に関する各クエリが定数時間ルックアップに変わります。 

制約が意味するのは、$n$十分な大きさにすることができます$O(n^2)$前の要素をスキャンすることは不可能です。 平$O(n \log n)$繰り返しの乗算やマップ操作が含まれる場合、要素ごとの処理は遅すぎます。 唯一受け入れられるアプローチは、各要素が一定量の作業に寄与する、線形時間に近いものです。 

除算が正確ではない場合、微妙な特殊なケースが発生します。 割り算をチェックせずに商を計算しようとすると、分数の結果が誤って有効なインデックスとしてカウントされる可能性があります。 現在の要素がゼロの場合、除算ロジックが未定義になるか、別個の処理が必要になるため、別の問題が発生します。 盲目的に計算する単純な実装$x / a_i$検証を行わないと、クラッシュするか、間違ったペアがカウントされます。 

たとえば、配列が次の場合、$[2, 3, 4]$そして、積が 6 に等しいペアをチェックしています。$4$、コンピューティング$6 / 4$非整数の結果が得られるため、使用しないでください。 正しい答えは整数の商のみを考慮する必要があります。 

もう 1 つの特殊なケースは、値が繰り返されることです。 配列に多くの同一の要素が含まれている場合、単純なペアごとのチェックではカウントが 2 重になったり、順序付けの制約を見逃したりする可能性がありますが、頻度ベースのアプローチでは、左から右に進むにつれて自然に正しいカウントが蓄積されます。 

## アプローチ

 ブルートフォースのアイデアは単純です。 ポジションごとに$i$、以前のすべてのポジションを振り返ります$j < i$乗算または除算を含む条件が成立するかどうかをテストします。 すべてのペアが明示的に 1 回だけチェックされるため、これにより正確さが保証されます。 ただし、これは次のことにつながります$O(n^2)$最悪の場合の比較は不可能になります。$n$大きいです。 

非効率性は、前の要素のほとんどが現在の値に無関係であるにもかかわらず、すべての以前の要素を繰り返しスキャンすることから生じます。 条件の構造から、前の要素の個々の ID は必要なく、各値が何回出現したかだけが必要であることがわかります。 それぞれのチェックが「以前の要素の中に特定の値が存在するかどうか」という点に帰着すると、内側のループを頻度ルックアップに置き換えることができます。 

この観察により、問題は計数配列の維持に変換されます。 反復中に、各要素に必要な補数値を計算し、それが以前に何回出現したかを直接クエリします。 これにより、各ステップが一定時間に短縮されます。

 | ブルートフォース |$O(n^2)$|$O(1)$| 遅すぎる |
 | 周波数配列 |$O(n)$|$O(V)$| 承認済み |

 ## アルゴリズムのチュートリアル

 周波数配列を維持します`cnt`どこ`cnt[v]`何倍の値を保存するか`v`これまで接頭語に登場してきました。 

1.初期化`cnt`ゼロとセット`answer = 0`。 これにより、すべてのクエリが以前の要素のみに依存するようにプレフィックス カウント構造が準備されます。 
2. 配列を左から右に繰り返します。 各インデックスで$i$、現在の値を読み取ります$a_i$。 この値を「新しく到着した」要素として扱い、将来のペアへの寄与は以前の値のみに基づいて計算する必要があります。 
3. 頻度を更新する前に$a_i$、問題の比率条件から導出された必要な補数値を計算します。 これは通常、$x / a_i$、 どこ$x$固定ターゲット値または派生パラメータです。 重要な要件は、この商が整数である必要があることです。そうでない場合は、前の有効な要素に対応できません。 
4. もし$a_i$分割する$x$正確に、追加します`cnt[x // a_i]`答えに。 これは、乗算条件を満たすために、前の要素が現在の要素とペアになることができる数をカウントします。 除算チェックにより、無効な分数インデックス作成が防止されます。 
5. 以前の要素からの寄与を処理した後、インクリメントします。`cnt[a_i]`この値が将来のポジションに使用できることを記録します。 

### なぜ効果があるのか

 どのインデックスでも、`cnt`は、これまでプレフィックスに見られた値の複数セットを正確に表します。 現在の要素と前の要素に関係する有効なペアは、このプレフィックス情報のみを使用する必要があります。 クエリだけなので`cnt`現在の要素を挿入する前に、正しいエンドポイントが処理された時点で、有効な各ペアが 1 回だけカウントされることを確認します。 可分性チェックにより、構造的に有効な補体のみが考慮され、正確さが維持されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, x = map(int, input().split())
    a = list(map(int, input().split()))

    # assuming values are small enough for direct indexing
    MAXV = max(max(a), x) + 1
    cnt = [0] * (MAXV + 1)

    ans = 0

    for v in a:
        if v != 0 and x % v == 0:
            ans += cnt[x // v]
        cnt[v] += 1

    print(ans)

if __name__ == "__main__":
    solve()
```この解決策は、ハッシュ構造のオーバーヘッドを回避する直接周波数配列を構築することから始まります。 2 番目の要素が配列内で後から現れるペアのみをカウントしたいため、反復順序は非常に重要です。 

条件`x % v == 0`非整数の商を使用して周波数配列にインデックスを付けることがないようにします。そうしないと、不正なメモリ アクセスやロジック エラーが発生します。 取り扱い`v == 0`ゼロ除算の問題を個別に回避します。 

アップデート`cnt[v] += 1`寄与をカウントした後に発生するため、現在の要素はそれ自体とペアになりません。 

## 実用的な例

 次のような入力を考えてみましょう。$x = 6$そして配列は$[1, 2, 3, 6]$。 

| 私 | v | x % v == 0 | x // v | 前の | 追加しました | 後のcnt |
 | --- | --- | --- | --- | --- | --- | --- |
 | 0 | 1 | はい | 6 | 0 | 0 | {1:1} |
 | 1 | 2 | はい | 3 | {1:1} | 0 | {1:1,2:1} |
 | 2 | 3 | はい | 2 | {1:1,2:1} | 1 | {1:1、2:1、3:1} |
 | 3 | 6 | はい | 1 | {1:1、2:1、3:1} | 1 | {1:1,2:1,3:1,6:1} |

 この表は、2 番目の要素が到着したときに、有効な各ペアが正確にカウントされることを示しています。 インデックス 2 に寄与するペアは以前の値 2 に由来し、インデックス 3 に寄与するペアは値 1 に由来します。 

ここで考えてみましょう$x = 12$と配列$[2, 3, 4, 6]$。 

| 私 | v | x % v | x // v | 前の | 追加しました | 後のcnt |
 | --- | --- | --- | --- | --- | --- | --- |

 これにより、毎回、処理済みの値のみに依存し、順序付けの制約を維持しながら、有効な乗算一致をすべてカウントすることが確認されます。

 ## 特殊なケース

 次のような繰り返し値の場合、$[2,2,2,2]$と$x = 4$、各新しい要素は、以前のすべての要素とペアになります。 周波数配列はスキャンするにつれて増加します。最初の 2 つの後、`cnt[2]=1`; 2 番目以降は 2 になります。 各ステップでは、有効な補数の現在のカウントが加算され、有効なペアの数と一致する三角形の累積が生成されます。 

などの割り切れない場合には、$[1, 3, 5]$と$x = 4$の場合、すべての要素が割り算チェックに失敗するため、アルゴリズムは検索を実行しません。 周波数配列は引き続き正しく更新されますが、寄与は追加されず、必要に応じてゼロが生成されます。 

最小限の入力の場合$[a_1]$、ループは 1 回実行され、以前の状態がないため検索は実行されず、単に値を頻度配列に挿入します。 答えはゼロのままで、ペアが存在しないことと一致します。
