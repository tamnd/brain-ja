 ## 解決策
 ## 問題の理解

 ステートメントの解釈に応じて、有向または無向の重み付きグラフが与えられます。各エッジはパス コストに加算的に寄与するのではなく、乗算的に寄与します。 パスの総コストは、そのパスに沿ったすべてのエッジの重みの積です。 このタスクは、固定ソース ノードから他のすべてのノードまでの最小可能な製品パス コストを計算し、その答えを対数形式で返すことです。 

生の製品を返す代わりに、値の対数を扱うように求められます。 これは、log(ab) が log a と log b を加えたものになるため、パスに沿った乗算を加算に変換します。 この変換後、問題は、非負の重みをもつ重み付きグラフ上の標準的な単一ソース最短経路問題になります。 

入力構造は通常のグラフ記述です。つまり、一連のノードと重み付けされたエッジの後に、バージョンに応じてクエリまたは単一のソース要件が続きます。 各エッジは正の乗算係数に寄与するため、対数を計算した後、すべてのエッジの重みは負ではない加算コストになります。 

この制約は、通常の Codeforce 方式で最大約 10^5 のエッジを処理する必要があることを意味します。 これにより、二次緩和戦略、さらには O(nm) 緩和戦略が即座に排除されます。 O(m log n) に近い値が必要ですが、これはバイナリ ヒープのダイクストラの特徴です。 変換されたすべての重みは負ではない (正の数の対数) ため、ダイクストラは有効です。 

この設定では、いくつかの特殊なケースが重要になります。 まず、積を直接計算しようとすると、大きな乗算増加を伴うパスが浮動小数点をオーバーフローする可能性があります。 たとえば、エッジが 10^9 で、長さ 10^5 のパスを選択する場合、ログは安定して追加的なままですが、積を保存することはできません。 第 2 に、切断されたノードは到達不能状態を正しく報告する必要があります。これはログ空間では無限大に相当します。 第三に、1 未満の非常に小さなエッジの重みは負の対数を生成します。そのため、非負の条件が実際には「すべてのエッジ ログが非負」になるため、ダイクストラがまだ機能する場合でも、変換された重みが正であると仮定してはなりません。これには、元の重みが少なくとも 1 であるか、問題によってログ ドメインの一貫性が保証される必要があります。 この問題では、目的はログ空間内の標準的な最短パスであるため、重みには互換性があると想定されます。 

素朴なアプローチは、すべてのパスを列挙し、積を計算し、最小値を取ることです。 パスの数が指数関数的に増加するため、これはすぐに失敗します。 パス長を越えた動的プログラミングでも、密なグラフでは O(n^2) かそれ以上のものが必要になります。 

重要な観察は、パスに沿った乗算は対数変換後の加算と構造的に同一であるため、問題は古典的な最短パスの計算に帰着するということです。 

## アプローチ

 この強引なアイデアは、ソースから可能なすべてのパスを探索し、その積を計算することです。 これはすべての候補者を評価するため、原則として正しいです。 ただし、グラフ内のパスの数は分岐に応じて指数関数的に増加するため、n と m が適度な場合でも、これは実行不可能になります。 分岐係数 2、深さ 20 のグラフでは、すでに 100 万を超えるパスがあり、実際の制約はそれをはるかに超えています。 

重複する部分問題の再計算を回避する方法が必要です。 重要な構造は、1 つのエッジによるパスの延長は、中間ノードに到達する方法ではなく、中間ノードまでの既知のコストのみに依存するということです。 対数を取得すると、各エッジが追加コストに寄与するため、負ではない重みを持つグラフ内の最短パスを探します。 

これはすぐにダイクストラのアルゴリズムを示唆します。 優先キューは常に、現在知られている最も安価なノードを拡張し、ノードがポップされるとその最短距離が確定することを保証します。 これが機能するのは、対数空間ではすべてのエッジの重みが負ではなく、貪欲な正確さの条件が維持されるためです。

したがって、すべてのパスを探索する代わりに、最もよく知られている距離配列を維持し、最小ヒープを使用してエッジを緩和します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (すべてのパス) | 指数 | O(n) 再帰スタック | 遅すぎる |
 | 対数重みに関するダイクストラ | O(m log n) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. グラフを読み取り、各エッジの重み w を log(w) に変換します。 これにより、パスに沿った乗算が加算に変換されます。 変換はすぐに適用されるため、以降のすべての計算は加算空間で実行されます。 
2. ソースを除くすべてのノードに対して距離配列を無限大で初期化します。ソースは 0 に設定されます。空のパスの乗算単位が 1 であるため、これは log(1) を表します。 
3. 送信元ノードを距離 0 の優先キューにプッシュします。優先キューには、次に拡張する可能性のあるノードが常に格納されます。 
4. 優先キューから暫定距離が最も小さいノードを繰り返し抽出します。 このノードは、ソースからの現在知られている最短のログコストを表します。 
5. 抽出されたノードの各隣接ノードについて、エッジ対数重みを現在のノードの距離に加算することによって候補距離を計算します。 この候補が以前に記録された距離よりも小さい場合は、それを更新し、近隣候補を優先キューにプッシュします。 
6. 優先キューが空になるまで続行します。 この時点で、すべてのノードの最小ログパス コストが確定します。 
7. 距離配列を出力します。通常は、問題の要件に応じて、到達不能な値を「inf」などのセンチネルに置き換えます。 

### なぜ効果があるのか

 正確さは標準のダイクストラ不変条件から得られます。つまり、ノードが優先キューから抽出されるとき、その現在の距離はすべての未探索のパスの中で可能な限り最小になります。 対数空間内のすべてのエッジの重みは非負であるため、そのノードへの代替パスは、同等以上の暫定距離を持つノードを経由する必要があり、非負のエッジを追加してもそれを減らすことはできません。 これにより、一度確定すると距離を後で改善できないことが保証されるため、アルゴリズムは真の最短対数距離に収束します。 

## Python ソリューション```python
import sys
import math
import heapq

input = sys.stdin.readline

def solve():
    n, m, s = map(int, input().split())
    g = [[] for _ in range(n + 1)]

    for _ in range(m):
        u, v, w = map(int, input().split())
        cost = math.log(w)
        g[u].append((v, cost))
        g[v].append((u, cost))

    INF = float('inf')
    dist = [INF] * (n + 1)
    dist[s] = 0.0

    pq = [(0.0, s)]

    while pq:
        d, u = heapq.heappop(pq)
        if d != dist[u]:
            continue

        for v, w in g[u]:
            nd = d + w
            if nd < dist[v]:
                dist[v] = nd
                heapq.heappush(pq, (nd, v))

    print(*dist[1:])

if __name__ == "__main__":
    solve()
```この解決策は、各エッジの重みがその対数に置き換えられる隣接リストを構築することから始まります。 これにより、パス コストが確実に加算されます。 

距離配列には、最もよく知られている対数コストが格納されます。 プライオリティ キューは、最小の暫定距離の貪欲な選択と古い状態のチェックを強制します。`if d != dist[u]`古いヒープ エントリが冗長な作業を引き起こすのを防ぎます。 

各緩和ステップは、元の問題のエッジの重みを乗算することに直接対応しますが、対数空間では加算として実行されます。

 | 測定 | 複雑さ | 説明 |

## テストケース```python
import sys, io
import math

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import heapq

    n, m, s = map(int, sys.stdin.readline().split())
    g = [[] for _ in range(n + 1)]

    for _ in range(m):
        u, v, w = map(int, sys.stdin.readline().split())
        g[u].append((v, math.log(w)))
        g[v].append((u, math.log(w)))

    INF = float('inf')
    dist = [INF] * (n + 1)
    dist[s] = 0.0
    pq = [(0.0, s)]

    while pq:
        d, u = heapq.heappop(pq)
        if d != dist[u]:
            continue
        for v, w in g[u]:
            nd = d + w
            if nd < dist[v]:
                dist[v] = nd
                heapq.heappush(pq, (nd, v))

    return " ".join(f"{x:.6f}" if x < INF else "inf" for x in dist[1:])

# sample-like tests

assert run("2 1 1\n1 2 2").split()[0].startswith("0.000000")

# custom cases
assert run("1 0 1") == "0.000000", "single node"

assert "0.000000" in run("3 2 2\n2 1 2\n2 3 2"), "center source"
assert run("4 3 1\n1 2 1\n2 3 1\n3 4 1").split()[3].startswith("0.000000")

 | --- | --- | --- |
 | 単一ノード | 0 | 簡単な初期化 |
 | 切断されたグラフ | インフラストラクチャが存在します | 到達不能な処理 |
 | スターソース | 有限距離 | 正しいリラックス |
 | チェーングラフ | ログを増やす | パス累積の正確性 |

 ## 特殊なケース

 次のような切断されたノードのケース`3 1 1 / 1 2 2`距離無限のノード 3 を残します。 ヒープ エントリがヒープ エントリに到達しないため、アルゴリズムは距離を緩和することはなく、その距離は変化せず、到達の不可能性を正確に反映します。 

単一ノード グラフは距離 0 を初期化し、緩和ループに入ることはありません。 優先キューは 1 回ポップされてすぐに終了し、最小入力サイズが正しいことを確認します。 

直接的な重いエッジと小さなエッジの間接的な積など、複数のパスが競合するグラフは、ダイクストラが必要な理由を示しています。 このアルゴリズムにより、緩和を通じて間接パスが検出および比較され、最小対数合計が保存されます。
