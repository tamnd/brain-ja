 ## 解決策
 ## 問題の理解

 私たちにはプレイヤーのセットが与えられており、各プレイヤーは詐欺師か乗組員のいずれかです。 プレイヤーの総数は、$n$, は 3 で割り切れます。 これらのプレイヤーの中には詐欺師の数が多く、$k$、不明ですが、プレイヤー全体の 3 分の 1 から 3 分の 2 の間であることが厳密に保証されています。 課題は、3 人のプレイヤーに繰り返しクエリを実行することで、どのプレイヤーが詐欺者であるかを正確に特定することです。 各クエリは、選択した 3 人のグループに、乗組員よりも偽者が多いか (0 を返す)、または偽者よりも乗組員が多いか (1 を返す) を示します。 

入力は複数のテスト ケースで構成され、それぞれのテスト ケースでは、$n$、各テスト ケースの出力は偽者の正確な数です。$k$およびそのインデックスのリスト。 これを対話的に実行し、クエリを作成し、その応答を読み取る必要があります。$2n$テストケースごとのクエリ。 クエリの数は限られており、陪審は適応的に詐欺師を配置できるため、すべての可能なトリプルをクエリする総当りアプローチは実行不可能です。 すべてのプレイヤーを確実に分類するには、慎重に選択したトリプルから十分な情報を抽出する必要があります。 

主な微妙な点は、応答の適応的な性質から生じます。 たとえば、たまたま全員がクルーメイトであるか全員が詐欺師である 3 人のプレイヤーにクエリを実行した場合、各プレイヤーの身元を個別に知ることはできない可能性があります。 したがって、アルゴリズムはクエリを慎重に選択して、少なくとも 1 人の特定の乗組員と 1 人の特定の詐欺師を早期に特定する必要があります。 それぞれを 1 つずつ取得したら、これらの既知のプレーヤーを含むトリプルを構築することで残りのプレーヤーを分類できます。これは、既知のプレーヤーを含むトリプル内の多数派の応答が予測可能であるためです。 

エッジケースには最小数のプレイヤーが含まれます$n=6$、非常に少数のクエリから最大限の情報を抽出する必要がある場合、および既知の乗組員または詐欺師が複数のトリプルに出現するシナリオでは、アルゴリズムが多数決ルールを正しく考慮していない場合、不注意なロジックにより他のプレイヤーが誤って分類される可能性があります。 

## アプローチ

 素朴なアプローチは、考えられるすべてのトリプルをクエリし、0 と 1 の数から詐欺師を推測しようとすることです。 これが機能するのは、各トリプルが詐欺師と乗組員の部分的な数を示すためです。 ただし、トリプルの数は次のように増加します。$\binom{n}{3}$、大まかに言うと$n^3/6$大型用$n$、このアプローチは完全に非現実的です$n$近く$10^4$。 

最適なソリューションを導き出す重要な観察は、プレーヤーを連続するトリプルに分割し、トリプルごとに 1 つのクエリを実行し、矛盾する結果を生成するトリプルに焦点を当てることです。 隣接するトリプルを比較することで、少なくとも 1 人の特定の詐欺師と 1 人の特定の乗組員を特定できます。 既知の詐欺師と既知のクルーメイトが 1 人いると、既知のプレイヤーを含むトリプルを形成することで残りのプレイヤーをすべて分類できます。 これにより、クエリの数が線形に減少します。$n$、内にうまく収まります$2n$クエリ制限。 

ブルートフォースアプローチは概念的には単純ですが、拡張性が低くなります。 最適なアプローチでは、多数派の回答と保証された制限を活用します。$k$最初に知られている詐欺師と乗組員を体系的に発見し、残りを効率的に推定します。

 | ブルートフォース | O(n3) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのプレイヤーを次のように分割します。$n/3$連続トリプル。 各トリプルをクエリして多数派の応答を取得します (詐欺師が優勢の場合は 0、乗組員が優勢の場合は 1)。 応答を保存します。 
2. 異なる応答を持つ連続したトリプルの最初のペアを特定します。 これらのトリプルを次のようにします$T_i$そして$T_{i+1}$。 定義上、$T_i$過半数を占めており、$T_{i+1}$その逆があります。 
3. からの 3 人を含む 4 人のプレーヤーの組み合わせをクエリします。$T_i$そしてからの1つ$T_{i+1}$4回転すべてで。 これにより、特定の乗組員 1 名と特定の詐欺師 1 名が明らかになります。 具体的には、重複するセット内のどのプレイヤーが多数派を変更するかを確認します。 結果を反転させる責任があるのは、トリプルの少数派です。 
4. 既知のクルーメイトと既知の詐欺師を取得したら、既知のクルーメイト 1 名と未知の 2 名、または既知の詐欺師 1 名と未知の 2 名を含むトリプルを形成して、残りのプレイヤーを分類します。 大多数の回答は、未知のプレイヤーの身元を直接示します。 
5. 詐欺師として分類されたすべてのプレイヤーを集めて数えます。 合計数とそのインデックスを必要な形式で出力します。 

正確性は、既知の乗組員と既知の詐欺師が特定されると、既知のプレーヤーが 1 人いるトリプルの多数決ルールによって未知の選手の正しい分類が保証されるという不変条件に依存します。 各分類クエリには身元が確実である参照が含まれているため、プレイヤーが誤って分類されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case():
    n = int(input())
    triples = []
    results = []
    
    # Step 1: form triples and query them
    for i in range(0, n, 3):
        print("?", i+1, i+2, i+3)
        sys.stdout.flush()
        res = int(input())
        triples.append([i, i+1, i+2])
        results.append(res)
    
    # Step 2: find two consecutive triples with differing results
    for i in range(len(results)-1):
        if results[i] != results[i+1]:
            t0, t1 = triples[i], triples[i+1]
            r0, r1 = results[i], results[i+1]
            break
    
    # Step 3: identify one certain crewmate and one impostor
    known = {}
    for j in range(3):
        print("?", t0[j]+1, t1[0]+1, t1[1]+1)
        sys.stdout.flush()
        res = int(input())
        if res == r1:
            known[t0[j]] = r0
            for k in t0:
                if k != t0[j]:
                    known[k] = r0 ^ 1
            break
    # find a known impostor and crewmate
    crewmate = next(p for p,v in known.items() if v == 1)
    impostor = next(p for p,v in known.items() if v == 0)
    
    # Step 4: classify remaining players
    for i in range(n):
        if i in known:
            continue
        print("?", crewmate+1, impostor+1, i+1)
        sys.stdout.flush()
        res = int(input())
        known[i] = res
    
    # Step 5: output impostors
    impostors = [i+1 for i,v in known.items() if v == 0]
    print("!", len(impostors), *impostors)
    sys.stdout.flush()

t = int(input())
for _ in range(t):
    solve_case()
```このソリューションでは、まずプレーヤーをトリプルに分割して、初期多数情報を収集します。 2 つの連続するトリプル間の不一致を特定すると、少なくとも 1 人の詐欺師と 1 人の乗組員が結合に存在することが保証されます。 これらのトリプル内で慎重にクエリを実行すると、最初に知られている乗組員と詐欺師が抽出されます。 最後の分類フェーズでは、これらの既知のアイデンティティを活用して残りを決定します。 最小値などのエッジケース$n=6$最初の競合するトリプルは境界によって保証されているため、自然に処理されます。$k$。
