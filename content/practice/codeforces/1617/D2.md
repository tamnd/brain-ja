 ## 問題の理解

 私たちに与えられたグループは、`n`プレーヤー、それぞれにラベルが付けられている`1`に`n`、 どこ`n`は常に 3 の倍数です。これらのプレイヤーの中には詐欺師もいますが、残りはクルーメイトです。 詐欺師の数は分かりません`k`事前に、ただし、厳密に次の範囲内であることが保証されます。`n/3`そして`2n/3`。 私たちの仕事は、限られた種類のクエリを実行して、どのプレイヤーが詐欺者であるかを正確に特定することです。 

各クエリでは、3 人の異なるプレイヤーを選択し、その中に詐欺師やクルーの仲間がさらにいるかどうかを尋ねることができます。 応答は`0`詐欺師が大多数を占める場合、`1`乗組員が多数派の場合。 私たちが作れるのはせいぜい`n + 6`そのようなクエリを実行した後、すべての詐欺師インデックスとその合計数を報告する必要があります。 

陪審は適応的であるため、回答がルールと一致している限り、私たちの質問に応じて詐欺師セットが変わる可能性があります。 これにより、単純にすべてのトリプルを順番にクエリするような単純な戦略を防ぐことができます。 アルゴリズムは、固定された詐欺師の位置に依存せず、制御された段階的な方法で機能する必要があります。 

制約が意味するのは、`n`テスト ケースごとに最大約 10,000 に達する可能性があり、すべてのテスト ケースの合計は 20,000 に制限されます。 各クエリは安価ですが、すべてのトリプルを列挙することは不可能です。`O(n^3)`トリプルの可能性。 したがって、大まかに次のことを必要とする戦略が必要です。`O(n)`制限と互換性のあるクエリ`n + 6`。 

明らかではないエッジケースには、連続するトリプルが詐欺師の多いグループと乗組員の多いグループの両方にまたがり、最初に保証された乗組員または詐欺師が隠れる可能性がある状況が含まれます。 最初の過半数のトリプルに常に詐欺師または乗組員が含まれていると仮定した場合、または 3 人全員が詐欺師であるか、3 人全員が乗組員で​​ある場合にトリプルに誤ったラベルを付けた場合、不注意なアルゴリズムは失敗する可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、考えられるすべてのトリプルをクエリし、大部分の結果に基づいて詐欺師を推測しようとします。 これは、各応答が小さなセット内の詐欺師の比率に関する情報を提供するため、原理的には正しいですが、次の理由により完全に非実用的です。`O(n^3)`トリプルはすぐにクエリ制限と計算リソースを超えます。 

重要な観察は、`n`が 3 の倍数である場合、プレイヤーを次のように分割できます。`n/3`素のトリプルを作成し、各トリプルを 1 回クエリします。 これらのトリプルのうち、少なくとも 1 つのトリプルは乗組員多数派でなければならず、少なくとも 1 つは詐欺師多数でなければなりません。`k`。 純粋な、または多数派に知られている乗組員 1 名と多数派に知られている詐欺師 1 名を特定すると、いくつかの追加クエリで残りのプレイヤーを分類できるようになります。 

保証されたクルーメイトと保証された詐欺師を取得したら、これら 2 つの「アンカー」と組み合わせて残りのプレイヤーを体系的にクエリできます。 トリプル メンバーの 1 人を未知のプレーヤーに置き換え、応答が反転するかどうかを観察することで、未知のプレーヤーの役割を決定できます。 これにより問題は次のように縮小されます`O(n)`クエリは制限内に十分収まります。

 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. パーティションを分割します。`n`プレーヤーを`n/3`素のトリプル:`(1,2,3)`、`(4,5,6)`、など。各トリプルをクエリして、その多数のタイプを見つけます。 返される最初のトリプルを追跡する`0`(詐欺師多数) と返される最初のトリプル`1`（乗組員多数）。 これらをそう呼んでみましょう`T_imp`そして`T_crem`。 
2. から`T_imp`そして`T_crem`、少なくとも 1 人の保証された詐欺師と 1 人の保証された乗組員を特定します。 これは、2 人のプレーヤーの混合トリプルを一方のトリプルから、もう一方をもう一方からクエリすることによって行われます。 応答により、どのプレイヤーが詐欺師かクルーメイトであるかを推測することができます。 
3. 詐欺師1名確定`I`そして保証された乗組員1名`C`、他のすべてのプレーヤーを反復処理します。 未知のプレイヤーごとに`X`、トリプルをクエリします`(I, C, X)`。 応答が`0`、 それから`X`詐欺師です。 応答が`1`、 それから`X`乗組員です。 各プレーヤーのタイプを記録します。 
4. すべてのプレイヤーを分類した後、すべての詐欺師のインデックスを収集します。 それらを数えて取得します`k`。 結果を必要な形式で出力します。 

それが機能する理由: 不変条件は、常に少なくとも 1 人の既知の乗組員と 1 人の既知の詐欺師がいるということです。 これらをアンカーとして使用すると、未知のプレーヤーに関するすべてのクエリにより、明確な分類が生成されます。 過半数の乗組員と過半数の詐欺師トリプルの最初の特定は、次の制限によって保証されます。`k`(`n/3 < k < 2n/3`)、どちらのタイプも存在しないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
print_flush = lambda s: (print(s), sys.stdout.flush())

def solve_case(n):
    triples = []
    answers = []
    
    for i in range(0, n, 3):
        a, b, c = i+1, i+2, i+3
        print_flush(f"? {a} {b} {c}")
        r = int(input())
        triples.append((a, b, c))
        answers.append(r)
    
    # find first crewmate-majority and impostor-majority triples
    idx_crem = answers.index(1)
    idx_imp = answers.index(0)
    T_crem = triples[idx_crem]
    T_imp = triples[idx_imp]
    
    # determine one guaranteed crewmate and one guaranteed impostor
    known = [None] * (n+1)
    a,b,c = T_crem
    x,y,z = T_imp
    
    # We query mixed triples to identify at least one known crewmate and impostor
    query_order = [(a,x,y), (b,x,y), (c,x,y)]
    response = []
    for q in query_order:
        print_flush(f"? {q[0]} {q[1]} {q[2]}")
        response.append(int(input()))
    
    if response[0] == 1:
        known[a] = 1
        known[x] = 0
    elif response[1] == 1:
        known[b] = 1
        known[x] = 0
    else:
        known[c] = 1
        known[x] = 0
    
    # pick one known crewmate C and one known impostor I
    C = next(i for i,v in enumerate(known) if v==1)
    I = next(i for i,v in enumerate(known) if v==0)
    
    # classify all players
    for i in range(1, n+1):
        if known[i] is not None:
            continue
        print_flush(f"? {C} {I} {i}")
        r = int(input())
        known[i] = r
    
    impostors = [i for i in range(1, n+1) if known[i]==0]
    k = len(impostors)
    print_flush(f"! {k} {' '.join(map(str, impostors))}")

def main():
    t = int(input())
    for _ in range(t):
        n = int(input())
        solve_case(n)

if __name__ == "__main__":
    main()
```コードの各セクションはアルゴリズムに直接に従います。 まず、両方のタイプのトリプルの候補を特定し、次に混合クエリを通じて特定の乗組員と詐欺師の 1 人を推定します。 最後に、既知のアンカーを使用したクエリを使用して、残りのすべてのプレーヤーを分類します。 プレーヤーのインデックスを作成するときは、off-by-one エラーを避けるように注意する必要があり、対話型プロトコルを尊重するためにすべての print ステートメントがフラッシュされます。
