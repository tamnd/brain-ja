 ## 解決策
 ## 問題の理解

 3 つの異なる正の整数を作成するように求められます$a$、$b$、 そして$c$それらの合計が指定された整数に等しくなるように$n$最初の 2 つの数値の最大公約数は 3 番目の数値と等しくなります。$\gcd(a, b) = c$。 入力は複数のテスト ケースで構成され、それぞれが次の値を指定します。$n$。 各テスト ケースの出力は有効なトリプルです。$a, b, c$。 

制約により許可されるのは、$n$と同じくらい大きくなる$10^9$到達するテストケースの数$10^5$。 これは、複雑さが次の値に比例するソリューションはすべて、$n$遅すぎるでしょう、なぜなら$10^9 \times 10^5$操作は不可能です。 したがって、テスト ケースごとに基本的に一定時間で機能するアプローチが必要です。 

単純なアプローチでは、すべてのトリプルを列挙しようとします。$(a, b, c)$と$a + b + c = n$そしてチェックしてください$\gcd(a, b) = c$。 小型用$n$これは機能しますが、大規模な場合は$n$それは不可能になります。 小規模な場合には、明白ではないエッジケースが発生します$n$のように$n = 10$どこ$c = 1$必要になる可能性がある、またはいつ$n$単純な固定パターンは区別性を維持するために調整が必要な場合があるため、偶数と奇数は区別されます。 

たとえば、次の場合$n = 11$、選択する$c = 1$力$a + b = 10$。 ピッキング$a = 2$、$b = 8$失敗する理由$\gcd(2, 8) = 2 \neq c$。 パリティや小さな要素をチェックせずにパターンを修正する不用意な解決策$n$無効な回答が生成されてしまいます。 

## アプローチ

 ブルートフォース手法では、可能な限りすべてのことを繰り返します$c$1から$n-2$そして、可能な限りすべての$a$1から$n-c-1$、設定$b = n - c - a$。 次に、次のことを確認します。$\gcd(a, b) = c$。 答えは常に存在するため、答えが見つかることが保証されていますが、それには最大で$O(n^2)$テスト ケースごとにチェックが行われますが、制約を考えるとこれは受け入れられません。 

重要な洞察は、選択することです$c$の小さな約数として$n$または 1 を指定して構築します$a$そして$b$の倍数として$c$保証する$\gcd(a, b) = c$。 もし$c$両方を分割します$a$そして$b$、その場合、それらの最大公約数は少なくとも$c$。 選択する$a = c$そして$b = n - 2c$保証します$a + b + c = n$、そしてなぜなら$a$そして$b$の倍数です$c$、$\gcd(a, b) = c$。 確保するだけで十分です$a$、$b$、 そして$c$明確でポジティブなものであり、わずかな調整で実現できます。 多くの場合、設定$c = 1$奇数の場合$n$そして$c = 2$均等に$n$単純で有効なトリプルを生成します。 

このアプローチでは、いくつかの算術演算と GCD 計算のみを実行するため、問題はテスト ケースごとの定数時間の計算に縮小されます。

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る$t$。 
2. 各テスト ケースについて、整数を読み取ります。$n$。 
3. もし$n$2 では割り切れますが、4 では割り切れません。選択してください$c = 2$、$a = n/2 - 1$、$b = n/2 + 1$。 これにより、$a + b + c = n$そして$\gcd(a, b) = c$。 
4. もし$n$は 4 で割り切れます。選択してください$c = n/2$、$a = n/4$、$b = n/4$。 調整する$b$に$b = n/4 * 3$区別性を維持するため。 今$a + b + c = n$そして$\gcd(a, b) = c$。 
5. もし$n$奇妙です、選んでください$c = 1$、$a = (n-1)/2$、$b = (n-1)/2$。 調整する$b = b + 1$区別性を確保するため。 それから$a + b + c = n$そして$\gcd(a, b) = 1$。 
6. トリプルを出力します。$a, b, c$。 

なぜ機能するのか: 重要な特性は、選択することです$a$そして$b$の倍数として$c$それを保証します$\gcd(a, b)$まさに$c$私たちが保証すれば$a \neq b$。 選択する$c = 1$奇数の場合、または小さな偶数の場合、偶数の場合はすべての可能性をカバーします$n \ge 10$、積極性と明確性を確保します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        if n % 2 == 1:
            # odd n: use 1 as gcd
            c = 1
            a = n // 2
            b = n // 2
            b += 1  # make distinct
        elif n % 4 == 0:
            # divisible by 4
            c = n // 2
            a = n // 4
            b = n // 4 * 3
        else:
            # even but not divisible by 4
            c = 2
            a = n // 2 - 1
            b = n // 2 + 1
        print(a, b, c)

if __name__ == "__main__":
    solve()
```このソリューションは高速 I/O を使用し、複数のテスト ケースを効率的に処理します。 各ケースは一定時間で処理されます。 調整により、次のことが保証されます。$a, b, c$ポジティブかつ明確であり、$c$それを保証します$\gcd(a, b) = c$。 整数の除算では、丸め誤差を避けるために注意が必要です。
