 ## 解決策
 ## 問題の理解

 私たちは、それぞれが学校のチャンピオンを代表する n 人の競技者によるトーナメントを与えられます。 すべての競技者について、最初の 2 つのイベントでの順位はすでにわかっています。 ランクは低いほど優れており、各イベントのすべてのランクは 1 から n までの順列を形成します。 

競技者の最終スコアは、各イベントの 3 つのランクの積として定義されます。 勝者は最小の製品を開発した競合者です。 複数の競技者が最小の製品で同点の場合は、それに関係なく、競技者番号 1 であるホグワーツのチャンピオンが勝者と宣言されます。 

タスクは、ホグワーツが勝つような 3 番目のイベントに有効なランクの順列を割り当てることができるかどうかを判断することです。 可能であれば、そのような順列を 1 つ構築する必要があります。 

重要な制約は n ≤ 100 で、これにより O(n²) または O(n³) の推論アプローチが可能になりますが、n! であるため、3 番目の順位のすべての順列に対する指数関数的な検索は除外されます。 n = 100 であっても大きすぎます。 

最初の 2 つのイベントの後、ホグワーツがすでに弱すぎる場合、微妙なエッジケースが発生します。 たとえば、競技者 1 が a と b の両方で非常に悪いランクにあり、他の数人の競技者が両方の種目で 1 近くにランクされている場合、3 番目の種目でホグワーツにランク 1 を与えても、製品がすでに大きすぎるため、それを補うことはできません。 正しい解決策は、盲目的に順列を構築しようとすることなく、そのような不可能性を検出する必要があります。 

## アプローチ

 ブルートフォース戦略では、3 番目のイベントのランキングのすべての順列を試し、ホグワーツが勝つかどうかを確認します。 これは概念的には単純です。順列 c ごとに、すべての積 a[i]・b[i]・c[i] を計算し、インデックス 1 が最小値を持つかどうかを確認します。 ただし、n! があるため、このアプローチは不可能です。 これは、n = 15 の場合でも天文学的に大きくなります。 

重要な観察は、3 番目のランキングが唯一の自由度であり、製品内で直線的に動作するということです。 ホグワーツの候補上限 T を固定すると、次のようになります。 

すべての i について、a1 · b1 · c1 ≤ a[i] · b[i] · c[i]。 

c は順列であるため、多くの競合他社に任意に小さな値を自由に割り当てることはできません。 1 人の競技者のみがランク 1 を獲得し、1 人の競技者がランク 2 を獲得します。 これにより、グローバル結合が強制されます。誰かに小さな c[i] を与えると改善されますが、貴重な低いランクが消費されます。 

これは古典的な「支配制約を満たすためにランクを割り当てる」問題です。 正しい方向は、逆に貪欲に考えることです。c を最初から構築する代わりに、各ランク位置にどの競合他社を配置できるかを決定します。 

条件は次のように書き換えることができます。 

c[i] ≥ ceil((a1・b1・c1) / (a[i]・b[i]))

 ホグワーツの固定目標製品 P を仮定すると、すべての競争相手に必要な最小限の c[i] を導き出すことができます。 次に、タスクは、下限を満たす個別の整数 1 から n を割り当てることができるかどうかを確認するようになります。 これはスケジューリングの問題に帰着します。制約をソートし、利用可能な最小のランクを貪欲に割り当てようとします。 

重要な洞察は、実際にはすべての P を試す必要はないということです。唯一の意味のある候補は、1 から n までの k に対して c1 = k を強制することによって誘導される候補です。 そのような試みごとに、P = a1・b1・k を計算し、実現可能性をテストします。 どれかが機能する場合は、順列を構築します。 そうでなければ不可能です。 

これにより、探索空間が階乗から n 個の候補に減少し、それぞれが O(n log n) で解決されます。

 | --- | --- | --- | --- |
 | ブルートフォース順列 | お(ん!) | O(n) | 遅すぎる |
 | すべての c1 を貪欲な割り当てで試してみる | O(n² log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. c1 の候補値 k を修正します。これは、ホグワーツが 3 番目のイベントでランク k を獲得することを意味します。 

これにより、対象製品Ｐ＝ａ１・ｂ１・ｋが求められる。 
2. すべての競技者 i について、3 番目のイベントで必要な最小ランクを計算します。

a[i]・b[i]・c[i] ≥ P が必要なので、c[i] ≥ ceil(P / (a[i]・b[i])) となります。 
3. 各競合他社の必要な下限をペア ( lower_bound, i) として保存します。 
4. すべての競合他社を下限の昇順に並べ替えます。 
5. 1 から n までのランクを貪欲に割り当ててみます。 

ステップ t で、残りの下限が最小である未割り当ての競合他社にランク t を割り当てます (≤ t)。 

いずれかの時点でそのような競合他社が存在しない場合、この候補 k は失敗します。 
6. すべてのランクの割り当てに成功した場合、この順列を c として出力します。 
7. k について 1 から n まで繰り返します。 どれも動作しない場合は出力できません。 

### なぜ効果があるのか

 正確さは、乗算制約を c[i] の競合他社ごとの最小しきい値に変換することで得られます。 P が固定されると、各競合他社は独立して最小ランクを必要とし、置換制約が唯一の結合になります。 より小さいランクをより厳しい制約に割り当てると、より緩やかな制約の実現可能性が維持されるため、貪欲な割り当てが最適です。 実行可能な割り当てが存在する場合、ソートにより、より大きなランクしか受け入れられない競合他社に対して小さなランクを無駄にしないことが保証されるため、この構築により有効なソリューションが時期尚早にブロックされることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def possible(n, a, b):
    a1, b1 = a[0], b[0]

    for k in range(1, n + 1):
        P = a1 * b1 * k

        req = []
        for i in range(n):
            ai_bi = a[i] * b[i]
            # ceil(P / ai_bi)
            lower = (P + ai_bi - 1) // ai_bi
            if lower > n:
                break
            req.append((lower, i))
        else:
            req.sort()

            c = [0] * n
            used = [False] * n

            ptr = 0
            ok = True

            for rank in range(1, n + 1):
                while ptr < n and (used[req[ptr][1]] or req[ptr][0] > rank):
                    ptr += 1

                if ptr == n:
                    ok = False
                    break

                idx = req[ptr][1]
                used[idx] = True
                c[idx] = rank

            if ok:
                return c

    return None

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    ans = possible(n, a, b)
    if ans is None:
        print("impossible")
    else:
        print(*ans)

if __name__ == "__main__":
    solve()
```このコードは、3 番目のイベントでホグワーツの考えられるすべてのランクを反復します。 選択ごとに、各競技者が満たさなければならない必要なしきい値を計算し、ランクの順列がすべてのしきい値を同時に満たせるかどうかをチェックします。 

貪欲な割り当てでは、並べ替えられた制約のリストと、制約が現在のランクで実行不可能になったときに進むポインターを使用します。 各ランクは、最も古いまだ有効な競合他社に割り当てられ、より厳しい制約が優先されるようになります。 

微妙な点は、必要な下限を計算するときに ceil 除算を使用することです。 ここでオフバイワンエラーが発生すると、無効な代入が許可されるか、有効な代入が拒否されるため、直ちに正確性が損なわれます。 

## 実用的な例

 ### 例 1

 小さなケースを考えてみましょう。 

n = 4

 a = [2、1、3、4]

 b = [2, 1, 4, 3]

 k = 1 とすると、P = 2 * 2 * 1 = 4 となります。 

下限を計算します。 

i = 1: (4 + 4 - 1) // 4 = 1

 i = 2: (4 + 1 - 1) // 1 = 4

 i = 3: (4 + 12 - 1) // 12 = 1

 i = 4: (4 + 12 - 1) // 12 = 1

 ソートされた制約:

 (1,1)、(1,3)、(1,4)、(4,2)

 | ランク | 私が選んだ | 残りの有効な候補者 |
 | --- | --- | --- |
 | 1 | 1 | {3,4,2} |
 | 2 | 3 | {4,2} |
 | 3 | 4 | {2} |
 | 4 | 2 | {} |

 これにより有効な順列が生成されるため、k = 1 が機能します。 

これは、アルゴリズムがどのように低いしきい値を最初に優先し、実現可能性が確実に維持されるかを示しています。 

### 例 2

 n = 3

 a = [2, 3, 1]

 b = [2, 3, 1]

 k = 3 の場合、P = 2 * 2 * 3 = 12 となります。 

下限:

 i = 1: ceil(12/4) = 3

 i = 2: ceil(12/9) = 2

 i = 3: ceil(12/1) = 12 (> n 以降無効)

 したがって、競合他社 3 はすでに実現可能性を破っています。 

これは早期拒否を示しています。必要な下限が n を超える場合、どの置換もそれを満たすことができません。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

| スペース | O(n) | 制約配列と割り当て状態を保存します |

 n ≤ 100 の場合、最悪のケースは約 100 × 100 log 100 の操作であるため、これは制限内に問題なく収まります。

 ## 特殊なケース

 重要なエッジケースは、ホグワーツが両方のイベントですでに非常に悪い順位にある場合です。 a1 = n および b1 = n で、別の競技者が a[i] = 1 および b[i] = 1 であるとします。c1 = 1 を割り当てたとしても、ホグワーツの積は n² ですが、他の競技者は 3 回目のイベントの前にすでに積 1 を持っているため、勝利は不可能になります。 競合他社に必要な下限が ceil(n² / 1) となり、すぐに n を超えて早期に拒否されるため、アルゴリズムはこれを検出します。 

もう 1 つのケースは、複数の競合他社が同じ a[i]・b[i] を持っている場合です。 ここでは、すべての制約が等しいしきい値に集約されるため、貪欲な割り当ては依然として機能するはずです。 並べ替えにより、同順位が一貫して処理され、実行可能性がある限り競合することなく順列が満たされることが保証されます。 

最後に、n = 1 のような境界値は、ランキングに関係なく 1 人の競合他社が自明に勝つため、常に成功し、アルゴリズムは c1 = 1 を正しく割り当てます。
