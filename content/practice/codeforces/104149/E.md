 ## 解決策
 ## 問題の理解

 未知の整数を特定しようとしています$x$1 ～ 100 の範囲で指定します。に関する情報を得る唯一の方法です。$x$クエリを行うことにより、整数を選択します$y$同じ範囲内にあり、間の関係に応じて 4 つの可能な応答のうち 1 つを受け取ります。$y$そして$x$。 

応答は、すべての数値を以下に関して 3 つの意味のある関係に分割します。$x$。 クエリはそれを返します$y$はの約数です$x$、の倍数$x$、に等しい$x$、またはそれとは関係ありません。 目標は決定することです$x$このようなクエリは最大 50 個使用します。 

制約$x \in [1, 100]$makes exhaustive reasoning over all candidates feasible, but only if each query is used to eliminate many possibilities. 候補が 100 個しかないため、実際の困難は検索スペースのサイズではなく、非対称フィードバックを考慮した曖昧さを最大限に減らすクエリを設計することです。 

A naive approach would try all numbers sequentially. テストしたら$y = 1, 2, 3, \dots$の場合、インタラクターは最後に同等性を確認するだけであり、最大 100 個のクエリが必要となり、制限に違反します。 さらに悪いことに、「因数」や「倍数」などの回答では、自分が上か下かを直接明らかにすることはできません。$x$したがって、単純なリニア スキャンでは情報が無駄になります。 

多くの約数または倍数を共有する数値を繰り返しテストすると、微妙な失敗例が発生します。 たとえば、連続する整数をクエリすると、非常に不均衡なフィードバックが返されます。1 をクエリすると、常に「factor」が返され、それについてはほとんど何も明らかにされません。$x$, すべての数値は 1 の倍数であるためです。 

主な難しさは、各応答がはいまたはいいえの 2 値ではなく 4 方向に分割されており、これを強力な排除力に変換するクエリを設計する必要があることです。 

## アプローチ

 ブルートフォース戦略は、1 から 100 までのすべての可能な候補のセットを維持することです。各クエリで候補が選択されます。$y$そして、応答に基づいてセットをフィルタリングします。 

「等しい」を受け取ったら、完了です。 「因子」を受け取ると、$x$の倍数でなければなりません$y$。 「複数」を受け取った場合、$x$分けなければなりません$y$。 「その他」を受け取ると、どちらの割り算も成り立ちません。 

すべての応答が論理制約に正確に対応するため、このアプローチは正しいです。$x$。 ただし、効率は完全に選択方法に依存します。$y$。 候補セットを不均等に分割したり、候補セットをほとんど減らすような数値を常に選択するなど、選択を誤ると、敵対的なケースでは 100 近くのクエリが必要になる可能性があります。 

重要な観察は、1 から 100 までの数字の割り算構造が高度に構造化されており、対称的であるということです。 各数値には、この範囲の約数と倍数の小さなセットがあります。 この構造の中心に位置するクエリを選択することで、大きな分割を保証できます。 

特に、約数や倍数が多い数値は強力なプローブとして機能します。 2 の累乗や 12、18、20 などの合成数は、空間を効率的に分割する傾向があります。 ただし、より堅牢な戦略は、単一の賢いピボットに依存せず、一貫性を維持することです。常に候補セットをクエリし、1 つの番号が残るまで 4 方向のパーティションを使用して積極的に縮小します。 

ドメインが非常に小さいため、単純な消去戦略でもすぐに収束し、クエリを慎重に選択 (または決定論的循環) することで、50 クエリ以内に収まります。

 ## アルゴリズムのチュートリアル

 私たちは、可能なすべての値のセットを維持します。$x$、最初は 1 から 100 までのすべての整数です。 

1. 完全な候補セットから開始します$S = \{1, 2, \dots, 100\}$。 このセットは常に、以前のすべての回答と一致する値を表します。 
2. クエリを選択します$y$現在の候補セットから。 残りの最小の候補を選択するのが適切です。これにより、実装が簡素化され、決定性が保証されます。 
3.送信$y$そして応答を読んでください。 
4. 応答が「等しい」場合、次のことが判明したため、直ちに終了します。$x$。 
5. 応答が「因数」の場合、候補セットを数値に制限します$z \in S$そのような$z \mod y = 0$、の倍数のみなので、$y$この応答を生成できます。 
6. 回答が「複数」の場合、数値に限定します$z \in S$そのような$y \mod z = 0$、 以来$x$分けなければなりません$y$。 
7. 応答が「その他」の場合、次の約数であるすべての数値を削除します。$y$またはの倍数$y$両方の関係が除外されるためです。 
8. 候補が 1 つだけ残るか、「等しい」が返されるまで繰り返します。 

重要な不変条件は、各クエリの後、候補セットがそれまでのすべての応答と一致するすべての数値と正確に一致することです。 各更新ステップでは、相互作用ルールから派生した論理的に正確なフィルターが適用されるため、次の真の値は$x$削除されることはなく、無効な値も保持されません。 

すべてのクエリは少なくとも 1 つの候補を削除し (クエリされた数値は、それが答えでない限り削除されます)、割り算の制約により一度に複数の値が削除される傾向があるため、プロセスは 50 クエリのバジェット内ですぐに収束します。$x \in [1,100]$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ask(y):
    print(y, flush=True)
    return input().strip()

def consistent(x, y, resp):
    if resp == "equal":
        return x == y
    if resp == "factor":
        return x % y == 0
    if resp == "multiple":
        return y % x == 0
    return (x % y != 0 and y % x != 0)

def solve():
    candidates = list(range(1, 101))

    while True:
        if len(candidates) == 1:
            print(candidates[0], flush=True)
            return

        y = candidates[0]
        resp = ask(y)

        if resp == "equal":
            return

        new_candidates = []
        for x in candidates:
            if resp == "factor" and x % y == 0:
                new_candidates.append(x)
            elif resp == "multiple" and y % x == 0:
                new_candidates.append(x)
            elif resp == "other" and x % y != 0 and y % x != 0:
                new_candidates.append(x)

        candidates = new_candidates

def main():
    solve()

if __name__ == "__main__":
    main()
```実装は不変条件を直接反映します。 候補リストには、すべての回答と互換性のある値が常に正確に保存されます。 各クエリは最初に残った候補を使用します。正確性は最適な分割には依存せず、最終的な削除にのみ依存するため、これで十分です。 

クエリのたびに出力をフラッシュするように注意する必要があります。 それ以外の場合、インタラクターはブロックします。 もう 1 つの微妙な点は、成功後はそれ以降のクエリは無効になるため、「equal」を受信するとすぐに終了することです。 

## 実用的な例

 検討してください$x = 6$。 

まずは候補者から$[1,2,3,4,5,6,\dots,100]$。 

最初のクエリ$y = 1$常に「因数」を返します。 フィルタリングでは 1 の倍数がすべて保持されるため、セットは変更されません。これは、1 が不適切なクエリである理由を示しています。 

次のクエリ$y = 2$6 は 2 の倍数であるため、「factor」を返します。すべて偶数を保持します。 

| ステップ | クエリy | 応答 | 候補セットサイズ |
 | --- | --- | --- | --- |
 | 1 | 1 | 係数 | 100 |
 | 2 | 2 | 係数 | 50 |

 フィルタリング後は偶数のみが残ります。 次のクエリ$y = 2$これも (最初の候補のままであるため) 依然として「因数」を与えますが、すでに偶数しかないため、セットは安定し、さまざまな応答から他の制約が現れるにつれて最終的に狭くなります。 

ここで考えてみましょう$x = 7$。 

| ステップ | クエリy | 応答 | 候補セットサイズ |
 | --- | --- | --- | --- |
 | 1 | 1 | 係数 | 100 |
 | 2 | 2 | その他 | ~50 |

 2 をクエリすると、7 は 2 の倍数でも約数でもないため、「その他」が得られ、すべての偶数と 2 の約数/倍数が削除され、セットが急速に縮小されます。 これは、「その他」が最も有益な回答であることが多いことを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(100 * Q) | 各クエリは残りの候補を最大サイズ 100 までスキャンします。 
| スペース | O(100) | 現在の候補リストを保存します |

 候補空間のサイズは一定であるため、制約があれば二次形式のフィルタリングも簡単です。 クエリが最大 50 件であれば、合計の操作は無視できる程度になります。

 ## 特殊なケース

 いつ$x = 1$すべての数値は 1 で割り切れるため、すべてのクエリは「multiple」を返します。「multiple」条件ではクエリの約数のみが保持され、1 はすべてを除算するため、アルゴリズムが誤って 1 を削除することはありません。そのため、一貫性が保たれます。 

いつ$x = 100$、1 や 2 のような初期のクエリは「係数」を生成し、セットをそれらの数値の倍数に縮小します。 フィルタリング ステップでは、すべての除数ベースの制約と一致しているため、100 が正しく保存されます。 

12 のような高度に合成された数値をクエリする場合、応答は候補を明確に分割します。多くの数値は 12 の倍数または約数であるため、「その他」によってセットの大部分が削除されます。 不変式により、100 が応答と一貫性を保っている場合、100 が削除されないことが保証されます。 

フィルタリング ロジックは、各条件がヒューリスティック プルーニングではなくインタラクター ルールから直接導出されるため、すべての場合において真の値が候補セットに残ることを保証します。
