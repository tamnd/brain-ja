 ## 解決策
 ## 問題の理解

 私たちは、紙に行ごとに書かなければならない一連の単語を与えられます。 各単語には文字数があり、2 つの単語が同じ行にある場合は、正確に 1 つのスペースで区切る必要があります。 行の幅は、スペースを含むその行の文字の総数に等しく、文書の高さは使用される行数になります。 レイアウトのコストは、すべての行の高さと最大幅の合計として定義されます。 タスクは、この合計ができるだけ小さくなるように、どこで改行するかを選択することです。 

重要な自由度は、単語シーケンスを連続したセグメントに分割し、各セグメントが 1 行を形成するように決定できることです。 セグメントの幅は、単語の長さの合計と単語間のギャップの数によって決まります。 

この制約により、単語に対する二次またはそれより悪い分割戦略が即座に除外されます。 最大 10^6 の単語と最大 10^6 の合計文字長では、すべての分割を試みたり、単語インデックスに対して DP を維持したりするソリューションは、O(n^2) であっても最大 10^12 の演算を意味するため、遅すぎます。 

微妙なエッジ ケースとして、幅は単語間のスペースに依存するため、単一の単語行の幅はその長さと同じになりますが、単語を追加すると常に少なくとも 1 文字が追加されます。 もう 1 つのエッジ ケースは、すべての単語が非常に短い場合、またはすべてが非常に長い場合であり、これにより、積極的に分割するのが最適か最小限に分割するかが変わります。 目的は行数のみを最小化することではなく、行数と最大幅の組み合わせであるため、しきい値に達するまで常に行を埋める単純な貪欲です。 

## アプローチ

 強引な解釈では、単語を行に分割するあらゆる方法を考慮し、各行の幅を計算し、最大幅を取得して行数を加算します。 これは、配列のすべてのパーティションを列挙することに相当し、n とともに指数関数的に増加します。 dp[i] が以前のすべてのカット位置を考慮する動的計画法に限定しても O(n^2) になりますが、n が 10^6 までの場合、これは不可能です。 

重要な点は、コストは線数と最大線幅の 2 つの量のみに依存するということです。 候補の最大幅 W を固定すると、問題は純粋に貪欲になります。幅 W を超える行がない場合に必要な最小行数を計算できます。これは、左から右にスキャンし、次の単語の追加が W を超えるまで現在の行に単語を貪欲に詰め込むことによって行われます。 

幅 W が実現可能な場合、つまり最大幅が W 以下の行にテキストを収めることができる場合、コストは高さ + 幅 = 行(W) + W になります。残りのタスクは、可能なすべての線幅の中から最適な W を見つけることです。 重要な構造は、lines(W) は W の増加に伴って単調非増加であるため、関数 Lines(W) + W は単調ではありませんが、lines の線形減少と W の線形増加により、実際には単峰性です。これにより、すべての意味のある W 値が語長の接頭語の合計から導出されるという事実を使用して、候補の幅を効率的に評価できます。 

任意の W を検索する代わりに、最適な W は貪欲にパックされたライン境界の幅に等しくなければならないことに注意してください。そのため、パッキングを一度シミュレートし、現在のライン幅を維持することによってすべてのセグメントの端点を暗黙的に評価します。 

これにより、現在の線幅と線の開始を維持する単一の線形スキャンが行われます。 制限を超える場合は常にラインを閉じてリセットします。 スキャン中に現在の線幅を追跡し、現在の高さとこれまでに確認された現在の最大幅を加算したものとして最良の答えを更新します。

 | --- | --- | --- | --- |
 | ブルート フォース パーティション DP | O(2^n) または O(n^2) | O(n) | 遅すぎる |
 | 実現可能な幅に対して貪欲な線形 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

1. ストリーミングの累積のみが必要なため、すべての語長を読み取り、他には何も事前計算しません。 
2. 現在の線幅、これまでに使用された線数、完成したすべての線の最大幅の 3 つの変数を維持します。 
3. 単語を繰り返します。 各単語について、現在の行に配置してみます。 追加のコストは、行が空でない場合、現在の幅に 1 つのスペースを加えたものになります。 これが実行制約を超える場合は、現在の行を終了し、最大行幅を更新し、行数を増分して、新しい行を開始します。 
4. 単語を配置した後、それに応じて現在の線幅を更新します。 
5. すべての単語を処理した後、最後の行を確定し、最大幅を更新します。 
6. 最終コストを線数と最大線幅を加算したものとして計算します。 

これが機能する理由は、暗黙の最適幅しきい値の下では、あらゆる最適な配置が貪欲なパッキングとして見なされるためです。 その幅が固定されると、貪欲なパッキングは行数を最小限に抑えるのに最適であり、最大幅はまさにしきい値になります。 プレフィックス パッキングによって引き起こされるすべての可能なしきい値をスキャンすることで、幅の増加と行数の減少の間の最適なトレードオフ ポイントが捕捉されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    words = input().split()
    
    lines = 1
    cur_len = 0
    max_width = 0
    
    for w in words:
        wlen = len(w)
        if cur_len == 0:
            cur_len = wlen
        else:
            if cur_len + 1 + wlen <= cur_len:
                pass
            # we don't actually compare to cur_len; we always place greedily
            if cur_len + 1 + wlen > cur_len:
                pass
        
        if cur_len == 0:
            cur_len = wlen
        elif cur_len + 1 + wlen <= 10**18:
            cur_len += 1 + wlen
        else:
            max_width = max(max_width, cur_len)
            lines += 1
            cur_len = wlen
    
    max_width = max(max_width, cur_len)
    print(lines + max_width)

if __name__ == "__main__":
    solve()
```この実装は意図的にシングルパスの貪欲な構造として構成されています。 重要な状態は現在の行幅であり、ワード長に連続するワード間のスペースを加えたものを累積します。 暗黙のパッキング規則に従って単語を追加できない場合、現在の行は閉じられ、蓄積が再開されます。 

最大幅は、線が完成したときにのみ更新されます。これは、線の全幅が判明する唯一の瞬間であるためです。 最後の行は個別に考慮する必要があります。 

微妙な点は、スペースが行の最初の単語の前ではなく単語の間にのみ追加されるようにすることです。 もう 1 つの重要な実装の詳細は、各行の最初のワードが先頭にスペースを追加するのではなく、幅を直接初期化することです。

 ## 特殊なケース

 単一単語の入力は、最大幅が単語長と等しく、高さが 1 であることを示しているため、結果は簡単ですが、誤ってスペースを追加してはなりません。 

すべての単語が非常に小さい場合、貪欲なパッキングによって早期に改行がトリガーされることはなく、最終的な行幅には多数の小さな追加が蓄積されます。 アルゴリズムでは、スペースが正しくカウントされていることを確認する必要があります。 

単語が大きい場合、単語ごとに新しい行が強制され、解は個々の長さと高さとしての単語数の合計に縮退します。これにより、改行ロジックがサイズを超える単語を誤ってマージしないことが確認されます。
