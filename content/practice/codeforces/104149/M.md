 ## 解決策
 ## 問題の理解

 一連の色付きビー玉を管理します。 最初に色の固定リストがあり、その後一連の操作を処理します。 各操作では、現在のシーケンス内の指定された位置に 1 つのビー玉が挿入されます。 挿入するたびに、少なくとも長さに達する同じ色の最大の連続セグメント`k`はすぐに消え、シーケンスの残りの部分がギャップを埋めます。 この削除はカスケードすることができます。セグメントを削除した後、2 つの隣接するブロックが結合して、新しい削除可能なセグメントが作成される可能性がありますが、これも削除する必要があり、少なくともその長さのセグメントがなくなるまで続きます。`k`残っています。 

タスクは、各挿入とその結果として生じるすべてのカスケード削除の後のシーケンスの最終的な長さを出力することです。 

この制約により、私たちは単純なシミュレーションから遠ざけられます。 最大 200,000 の挿入と最初の大きなシーケンスでは、各操作の後に配列全体をスキャンするアプローチは遅すぎます。 単純なリストを維持し、取り外し可能なセグメントを繰り返しスキャンしても、大規模なカスケードが繰り返し発生すると、二次的な動作に低下する可能性があります。 

単純なソリューションの微妙な失敗モードは、カスケード マージの不適切な処理です。 たとえば、次のように考えてみましょう`k = 3`そして次のようなシーケンス`1 2 2 2 1`。 挿入すると`2`最初の間`2`そして`1`、私たちが作成します`1 2 2 2 2 1`これにより、4 つの要素が完全に削除されます。`2`はい、出発します`1 1`。 マージされた境界を再チェックせずに、最初に検出されたブロックのみを削除する単純なアプローチでは、誤って余分なビー玉が残されてしまいます。 

もう 1 つの問題は、削除後の位置の移動です。 構造が連続ブロックではなくインデックスを追跡する場合、削除により格納されているすべての位置が無効になり、慎重に設計しないと一貫した更新が困難になります。 

## アプローチ

 ブルートフォース戦略は単純です。シーケンスを配列に保存し、新しいマーブルを挿入し、配列を繰り返しスキャンして、少なくとも一定の長さのランを見つけます。`k`、消去し、安定するまで繰り返します。 それぞれのスキャンは、`O(n)`、最悪の場合、単一の挿入によってシーケンスの長さに比例して繰り返しスキャンがトリガーされる可能性があります。 と`q`200,000 までの場合、これは実質的に`O(nq)`、これは実現可能な限界をはるかに超えています。 

重要な点は、削除は常に同じ色の連続したランに対して行われるということです。 個々のビー玉を追跡する代わりに、シーケンスを次の形式のブロックに圧縮できます。`(color, count)`。 各挿入は最大でも 1 つのブロックと、場合によってはその隣接ブロックにのみ影響します。 挿入後は、挿入ポイント周辺のローカルな変更のみがマージまたは削除をトリガーできます。 これは、ブロックの動的構造を維持し、スタック状または二重リンク表現と同様に、影響を受ける隣接ブロックのみを処理することを示唆しています。 

シーケンスをブロックレベルでシミュレートします。 挿入のたびに必要に応じてブロックが分割され、隣接するブロックが更新されます。 その後、マージが発生する可能性のあるローカル領域のみを繰り返しチェックします。 ブロックがサイズに達したとき`k`、それは消え、その左右の隣接ブロックが新しいブロックにマージされる可能性があり、これもチェックする必要があります。 この局所的な伝播により、各ブロックは挿入ごとに最大 1 回作成および削除されることが保証され、償却された線形動作が実現されます。

 ## アルゴリズムのチュートリアル

 現在の大理石のチェーンをブロックのリストとして表現します。`(color, length)`、順番に維持されます。 また、変更された位置に隣接するブロックに効率的にアクセスできる構造を維持します。 

1. 挿入位置を含むブロックを見つけます。 概念的には、挿入が中央で行われる場合、そのブロックを 2 つの部分に分割します。 新しい大理石が既存のランを壊す可能性があり、正確さは正確な隣接関係を維持することに依存するため、これが必要です。 
2. 新しいブロックを挿入します`(mx, 1)`分割によって作成された左側と右側の部分の間。 この時点で、ローカル構造には同じ色の隣接するブロックが含まれる場合があります。 
3. 隣接するブロックが同じ色を共有している場合は、それらを結合します。 これにより、常に最大のブロックが維持されるため、今後の操作では断片化されたものではなく、クリーンな実行のみが処理されます。 
4. 挿入されたブロック、またはマージの影響を受けたブロックで処理キュー (またはスタック) を初期化します。 このブロックは現在、`k`制約。 
5. 処理構造が空ではない間に、ブロックを取得します。 そのサイズが少なくとも`k`、完全に削除します。 この削除により、左右の隣りの間にギャップが生じます。 
6. 削除後、左右の隣接ブロック間の新しい隣接関係を確認します。 それらの色が同じである場合は、それらを 1 つのブロックにマージし、結果のブロックを処理構造にプッシュして戻します。 このステップは、カスケード効果を捉えるため、非常に重要です。 
7. プロセスが安定したら、残りのすべてのブロックのサイズを合計して全長を計算します。 

重要な考え方は、ブロックを削除するたびに、完全な構造ではなく、そのすぐ隣のブロックのみを考慮する必要があるということです。 

### なぜ効果があるのか

 この構造は、シーケンスが常に最大均一ブロックとして表現されるという不変条件を維持します。 すべての操作は 1 つの局所のみを変更します。挿入は 1 つの点で分割し、削除はブロック全体を削除します。 削除後にマージできるのは隣接するブロックのみであるため、将来のすべての変更は最後の変更の近傍によって完全に決定されます。 これにより、シーケンス内の他の場所での隠れた相互作用が防止され、削除やマージが見逃されることがなくなります。 

各ブロックはマージによって作成され、最大 1 回破棄されるため、すべてのクエリにわたる操作の合計数は、これまでに形成されたブロックの数に比例します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Node:
    __slots__ = ("c", "l", "p", "n")
    def __init__(self, c, l):
        self.c = c
        self.l = l
        self.p = None
        self.n = None

def merge(a, b):
    a.l += b.l
    a.n = b.n
    if b.n:
        b.n.p = a
    return a

def remove(node):
    if node.p:
        node.p.n = node.n
    if node.n:
        node.n.p = node.p
    return node.p, node.n

def solve():
    n, k, q = map(int, input().split())
    arr = list(map(int, input().split()))

    head = None
    prev = None

    i = 0
    while i < n:
        j = i
        while j < n and arr[j] == arr[i]:
            j += 1
        node = Node(arr[i], j - i)
        if not head:
            head = node
        if prev:
            prev.n = node
            node.p = prev
        prev = node
        i = j

    total = n

    for _ in range(q):
        px, mx = map(int, input().split())

        # find block position
        cur = head
        pos = px

        while cur and pos > cur.l:
            pos -= cur.l
            cur = cur.n

        left = right = None

        if cur:
            if pos == 0:
                left = cur.p
                right = cur
            else:
                # split cur
                right = Node(cur.c, cur.l - pos)
                cur.l = pos

                right.n = cur.n
                if cur.n:
                    cur.n.p = right
                cur.n = right
                right.p = cur

                left = cur

        # insert new node
        new = Node(mx, 1)

        if not head:
            head = new
        else:
            if not left:
                new.n = head
                head.p = new
                head = new
            else:
                new.n = right
                new.p = left
                left.n = new
                if right:
                    right.p = new

        total += 1

        # merge neighbors
        cur = new
        while cur.p and cur.p.c == cur.c:
            left = cur.p
            left.l += cur.l
            left.n = cur.n
            if cur.n:
                cur.n.p = left
            cur = left

        while cur.n and cur.n.c == cur.c:
            right = cur.n
            cur.l += right.l
            cur.n = right.n
            if right.n:
                right.n.p = cur

        # process deletions
        stack = [cur]
        while stack:
            node = stack.pop()
            if node.l < k:
                continue

            total -= node.l
            p, n = node.p, node.n

            if p:
                p.n = n
            else:
                head = n
            if n:
                n.p = p

            if p and n and p.c == n.c:
                p.l += n.l
                p.n = n.n
                if n.n:
                    n.n.p = p
                stack.append(p)

        print(total)

if __name__ == "__main__":
    solve()
```この実装では、シーケンスを均一色のブロックの二重リンク リストに圧縮します。 挿入ステップでは、正しいブロックを特定し、必要に応じてブロックを分割して、新しいビー玉が常にきれいな境界に位置するようにします。 マージ ループにより、同じ色の隣接するブロックが決して維持されなくなります。これは、ランを正しく検出するために不可欠です。 

削除フェーズでは、スタックを使用して削除を伝播します。 ブロックが消えるたびに、隣接するブロックを再接続し、それらが新しいマージ可能なブロックを形成するかどうかをすぐに確認します。 これにより、構造全体を再スキャンすることなくカスケードが処理されることが保証されます。 

の`total`変数は現在のシーケンスの長さを直接追跡するため、各クエリの後に構造を走査する必要がなくなります。 

## 実用的な例

 ### 例 1

 入力:```
n=7, k=3, q=2
1 2 2 1 3 3 1
(4,3)
(3,2)
```ブロックを構築すると、次のようになります。 

| ステップ | ブロック | 合計 |
 | --- | --- | --- |
 | 初期化 | (1,1)(2,2)(1,1)(3,2)(1,1) | 7 |
 | 挿入 (4,3) | (1,1)(2,2)(1,1)(3,1)(3,1)(3,1)(1,1) | 8 |
 | 削除後 | (1,1)(2,2)(1,1)(1,1) | 4 |

 最初の挿入では 3 つが作成されます`3`s、すぐに消えます。 これにより近隣の`1`s は分離されたままとなり、それ以上のマージは行われません。 

2 回目の挿入では、より小さなカスケードをトリガーする別のローカル構成が作成されますが、完全な折りたたみは行われません。

```トレース:

 | ステップ | ブロック | 合計 |

 これらのトレースは、挿入ごとにローカルな近傍のみが変化し、各カスケードの後に​​すぐに全体的な安定性に達することを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + q) 償却 | 各ブロックは、すべての操作にわたって最大 1 回作成および削除されます。 
| スペース | O(n + q) | 挿入ごとに最大 1 つの新しいブロックが作成される可能性があります。 

この表現により、すべての操作がローカルであることが保証され、シーケンス全体の再スキャンが回避されます。 最悪の場合のカスケードであっても、各ビー玉は制限された数のマージと削除に参加します。

 ## 特殊なケース

 重要なエッジ ケースは、2 つの同じ色のブロックの境界での挿入です。 たとえば、大きなランの途中に挿入する場合は、ランを正しく分割する必要があります。 そうしないと、アルゴリズムが無関係なセグメントを誤ってマージしたり、有効な削除トリガーを見逃したりする可能性があります。 

もう 1 つの特殊なケースは、完全崩壊の連鎖反応です。 削除を繰り返すと、離れた同じ色の 2 つのブロックが連続して複数回隣接するようになったとします。 アルゴリズムはこれを処理します。これは、削除のたびに新しい境界のみが即座に再評価され、マージが失われないことが保証されるためです。 

最後に考えてみましょう`k = 2`、どのペアも即座に消えます。 これにより、非常に頻繁にカスケード削除が発生します。 リンクされた構造により、各マージと削除がブロックごとに一定の償却時間で処理されることが保証され、最大のチャーン下でも爆発が防止されます。
