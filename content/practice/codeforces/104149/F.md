 ## 解決策
 ## 問題の理解

 私たちには、一組の生徒と生徒間の友人関係のリストが与えられました。 それぞれの友情には方向性がありません。 重要なひねりは、魔法のプロセスが実行されることです。生徒 A が B と友達になり、B が C と友達になるたびに、呪文によって A と C も友達になります。 これは一度だけではなく、新しい友情が追加できなくなるまで広がり続けます。 

グラフの用語では、無向グラフから始めて、接続性に対して推移閉包を適用します。つまり、すべての接続されたコンポーネントが完全なグラフになります。 タスクは、最終的なグラフを構築することではなく、元の入力と比較して新しいエッジがいくつ出現するかをカウントすることです。 

制約は最大 200,000 ノードと 200,000 エッジまで適用されます。 これにより、サイズ n の密なコンポーネントでも最終状態に n² エッジが含まれる可能性があるため、クロージャを繰り返しシミュレートしたり、エッジを明示的に追加しようとするアプローチは即座に除外されます。 コンポーネント内のすべての潜在的なペアを暗黙的に反復するアルゴリズムは失敗します。 

微妙な失敗のケースは、何をカウントする必要があるかを誤解していることに起因します。 コンポーネントにすでにいくつかのエッジが含まれている場合、それらを再度カウントしてはなりません。 

たとえば、入力がエッジ (1,2)、(2,3)、(1,3) を持つ 3 つのノードである場合、グラフはすでに完成しているため、答えは 0 になります。既存のエッジを減算せずに「完全なグラフ内の欠落エッジの数」のみを計算する単純なアプローチでは、誤って正の値が報告されます。 

もう 1 つのエッジ ケースは、疎な接続されていないグラフです。 エッジ (1,2) と (3,4) がある場合、各ペアは独自のコンポーネントを形成し、コンポーネント間の新しいエッジは追加されません。 答えはグローバルではなく、コンポーネントごとに個別に計算する必要があります。 

## アプローチ

 問題を直接解釈すると、a が何らかの b を介して c に接続されるたびにエッジ (a, c) を追加し続けるというルールをシミュレートすることになります。 これは基本的に、グラフの推移閉包を計算しています。 素朴な方法は、新しい接続が見つかるたびにエッジを追加しながら、すべてのトリプルを繰り返しスキャンするか、すべてのノードから BFS/DFS を使用することです。 

問題は、コンポーネントに k 個のノードがあることが判明した後、クロージャはすべての k 個の選択 2 エッジが存在する必要があることを意味することです。 すべての欠落ペアを明示的に構築またはチェックしようとすると、コンポーネントごとに O(k²) の操作が必要になり、最悪の場合は O(n²) に縮退します。 n が最大 2 × 10⁵ であるため、これは実現可能な限界をはるかに超えています。 

重要な観察は、最終状態は接続されたコンポーネントのみに依存するということです。 接続されているすべてのコンポーネントがクリークになります。 したがって、エッジの追加をシミュレートする代わりに、コンポーネントごとに必要な情報は 2 つだけです。コンポーネントのサイズと、内部にすでに含まれているエッジの数です。 

これは、素集合共用体構造を使用してノードをコンポーネントにグループ化し、さらに各コンポーネント内にあるエッジの数を追跡することを示唆しています。 コンポーネントが判明すると、サイズ k の完全なグラフ内のエッジの数は k × (k − 1) / 2 になります。そのコンポーネント内の元のエッジの数を減算すると、作成された新しい友情の数が得られます。 

これにより、問題は動的なグラフのクロージャからコンポーネントにわたる静的な集約へと軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース クロージャ シミュレーション | O(n²) | O(n²) | 遅すぎる |
 | コンポーネント集約を備えた DSU | O(n α(n)) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 エッジの処理中に接続されたコンポーネントを維持するために、素の集合結合構造を使用します。

1. 各生徒が独自のコンポーネントで開始する DSU を初期化します。 これは、まだ友情が結合されていない初期状態を表します。 
2. コンポーネント ルートごとに、現在そのコンポーネントに属しているエッジの数を追跡する配列またはマップを維持します。 最初はエッジが処理されていないため、これはどこでもゼロです。 
3. すべての友情エッジ (a、b) について、まず a と b を含む 2 つのコンポーネントを結合します。 結合操作により、エッジが生徒のグループを接続するときに正しいコンポーネント構造が維持されます。 
4. a と b が同じ最終コンポーネント構造内にあることを確認した後、そのコンポーネントのエッジ数を 1 つ増やします。 これが機能する理由は、たとえエンドポイントが以前のユニオン中にマージされたとしても、すべての入力エッジが 1 つの最終接続コンポーネントに属している必要があるためです。 
5. すべてのエッジを処理した後、すべてのノードを反復処理し、それらを DSU ルートに圧縮して、個別のコンポーネントを識別します。 
6. 一意のルートごとに、コンポーネントのサイズを計算します。 サイズが k で、保存されたエッジの数が m の場合、このコンポーネント内で形成される新しい友情の数は k × (k − 1) / 2 − m です。 
7. すべてのコンポーネントのこの値を合計して、最終的な答えを取得します。 

重要な考え方は、新しいエッジを明示的にシミュレートしないということです。 完全なグラフで必要な数をカウントし、すでに存在するものを差し引くだけです。 

### なぜ効果があるのか

 ルールはすでに到達可能なノード間にエッジを追加するだけであるため、友情ルールを繰り返し適用しても、元のグラフの下の各接続コンポーネントは同じままになります。 最終的には、接続されたコンポーネント内のすべてのノードのペアが直接接続され、クリークを形成します。 コンポーネントは相互に作用しないため、新しいエッジの総数は、「完全なグラフ エッジからコンポーネント内の既存のエッジを差し引いた」コンポーネントの合計となります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        ra = self.find(a)
        rb = self.find(b)
        if ra == rb:
            return ra
        if self.size[ra] < self.size[rb]:
            ra, rb = rb, ra
        self.parent[rb] = ra
        self.size[ra] += self.size[rb]
        return ra

def solve():
    n, m = map(int, input().split())
    dsu = DSU(n)
    edge_count = [0] * n

    for _ in range(m):
        a, b = map(int, input().split())
        a -= 1
        b -= 1
        ra = dsu.find(a)
        rb = dsu.find(b)
        if ra == rb:
            edge_count[ra] += 1
        else:
            root = dsu.union(ra, rb)
            edge_count[root] += 1

    # finalize sizes and compress roots
    for i in range(n):
        dsu.find(i)

    comp_edges = {}
    comp_size = {}

    for i in range(n):
        r = dsu.parent[i]
        comp_size[r] = comp_size.get(r, 0) + 1

    for i in range(n):
        r = dsu.parent[i]
        comp_edges[r] = comp_edges.get(r, 0)

    # recompute edge counts correctly
    # safer: recompute by scanning edges again is avoided; we adjust via union logic already handled

    # Instead, rebuild edge counts properly
    comp_edges = {i: 0 for i in range(n) if dsu.parent[i] == i}

    # second pass over edges is needed? no stored edges lost, so we reprocess
    # but we didn't store them; so fix: store edges list

    return

def main():
    n, m = map(int, input().split())
    dsu = DSU(n)
    edges = []
    for _ in range(m):
        a, b = map(int, input().split())
        a -= 1
        b -= 1
        edges.append((a, b))

    edge_count = [0] * n

    for a, b in edges:
        ra = dsu.find(a)
        rb = dsu.find(b)
        if ra == rb:
            edge_count[ra] += 1
        else:
            root = dsu.union(ra, rb)
            edge_count[root] += 1

    for i in range(n):
        dsu.find(i)

    comp_size = [0] * n
    for i in range(n):
        comp_size[dsu.find(i)] += 1

    ans = 0
    for i in range(n):
        if dsu.find(i) == i:
            k = comp_size[i]
            m_edges = edge_count[i]
            ans += k * (k - 1) // 2 - m_edges

    print(ans)

if __name__ == "__main__":
    main()
```この実装は、DSU に依存してノードをグループ化し、同時に各コンポーネント内に最終的に存在する元のエッジの数を蓄積します。 微妙な点は、結合操作の後にエッジのカウントをルートに関連付ける必要があるため、マージされたコンポーネントの代表値を常にインクリメントすることです。 

パス圧縮は以下で使用されます。`find`ほぼ一定時間の動作を保証します。 すべての結合の後、すべてのノードを反復処理し、ノードをルートにマッピングすることで、最終的なコンポーネントのサイズを再計算します。

 ## 特殊なケース

 完全に接続されたコンポーネントは、追加のエッジを必要としないため、最も直接的なエッジ ケースです。 このような場合、アルゴリズムはすべてのノードを 1 つのルートに割り当て、k に等しいエッジをカウントして 2 を選択するため、減算の結果はゼロになります。 

エッジのない完全に切り離されたグラフも境界条件の 1 つです。 各ノードはサイズ 1 の独自のコンポーネントになり、k 選択 2 はそれぞれ 0 であるため、合計の答えは 0 のままで、何もないところからは友情を推測できないという事実と一致します。 

1 つのコンポーネントが大きく、他のコンポーネントが小さい混合構造では、集計がグローバルではなくコンポーネントごとに行われるかどうかがテストされます。 DSU ベースのグループ化により、各コンポーネントが独立して評価されるようになり、コンポーネント間でのエッジ数の漏洩が防止されます。
