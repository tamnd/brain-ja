 ## 解決策
 ## 問題の理解

 ダンジョンは、いくつかの原始的な回廊を繰り返し組み合わせて構築されたシステムとして説明されています。 各プリミティブ コリドーは入口と出口を接続し、ある終点から別の終点へ向かう方向のない単一の通路のように動作します。 より複雑なシステムは、より小さなシステムを 2 つの方法で組み合わせることで形成されます。 連続した構成では、最初のシステムの出口が 2 番目のシステムの入口に接着されているため、動きは一方のシステムを通過してからもう一方のシステムに到達する必要があります。 並列構成では、2 つのシステムが入口と出口の両方を共有するため、旅行者はどちらかの分岐を選択できます。 

タスクは動きをシミュレートすることではありません。 代わりに、グローバル入口からグローバル出口までのあらゆる可能なルートが少なくとも 1 人の教師によって遮断されることが保証されるように、ダンジョン内に配置される「教師」の最小数が求められます。 各教師は自分が占有するルートに沿った通行を阻止し、入口から出口までの経路が完全に無防備な状態にならないようにすることが目標です。 

入力は、2 つの二項演算子を使用してダンジョンがどのように構築されるかを記述する完全に括弧で囲まれた式です。 1 つのオペレータは逐次合成に対応し、もう 1 つは並列合成に対応します。 その表現は常に、独特の入り口と出口を持つ単一のシステムに還元されます。 

出力は、すべての入口から出口までのパスが遮断されることを保証するために必要な教師の最小数を表す単一の整数です。 

式の長さは 100 万文字に達する可能性があるため、どのような解も基本的に線形である必要があります。 ネストの深さが中程度であっても、既に指数関数的に多くのパスが生成されるため、構造を明示的なグラフに拡張したり、パスを列挙しようとすると、すぐに爆発してしまいます。 表現自体は、私たちが利用できる唯一の構造です。 

ローカルな決定が独立しているかのように構造を扱う場合、一般的な故障モードが発生します。 たとえば、すべてのコリドーが独立して寄与すると仮定すると、直列の 2 つのセグメントがボトルネックを共有するため、順次構成での過大カウントが発生します。 

2 番目の微妙な落とし穴は、並列合成を合計ではなく最小値のように動作するかのように扱うことです。 たとえば、 ( () * () ) のような構造では、2 つの互いに素なルートがあり、両方をブロックする必要があるため、答えは減少するのではなく増加する必要があります。 

最後に、(((() + ()) * ())) のような式は、両方の演算を深く混合します。 括弧で囲まれた構造を完全に尊重せずに貪欲な評価を試みるソリューションは、リダクションの順序が重要なネストされた組み合わせでは失敗します。 

## アプローチ

 ブルートフォースアプローチでは、式によって暗示されるグラフを明示的に構築し、グローバルな入口と出口の間の最小カットを計算します。 各プリミティブ コリドーがエッジになり、合成ルールがグラフのマージに拡張されます。 グラフを作成した後、ユニット容量を使用した最大流量または最小カット アルゴリズムによって問題が解決されます。 

これは概念的には正しいですが、完全に実行不可能です。 この式は、最悪の場合、特に並列合成が繰り返される場合にサイズが指数関数的に増大するグラフを記述することができます。 構築を回避してフローを直接実行したとしても、最大数百万のノードを含む構造が必要ですが、これはよく言っても境界線であり、Python の制約の下では不可能です。

重要な観察は、グラフが直並列ネットワークのクラスに属していることです。 このようなグラフでは、ソースとシンクを切断するために削除する必要があるエッジの最小数は、単純な代数構造に従います。 各プリミティブ コリドーの基本値は 1 です。 2 つのシステムが直列に接続されている場合、すべての有効なパスは両方を通過する必要があるため、ボトルネックは 2 つのうちの弱い方、つまり値が最小値を介して結合されることになります。 2 つのシステムが並列接続されている場合、パスが分割され、すべての分岐をブロックする必要があるため、寄与が増加します。 

これにより、問題全体が、葉が 1 で、1 つの演算子が加算として機能し、もう 1 つが最小値として機能する式を評価することに変わります。 式は完全に括弧で囲まれているため、算術式の評価と同様に、スタックを使用して 1 回の左から右へのスキャンで評価できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 明示的なグラフ + 最大フロー | O(N^2) から指数 | O(N^2) | 遅すぎる |
 | 直並列式のスタック評価 | O(N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 式を 1 文字ずつ処理し、部分的な結果または構造マーカーを保管するスタックを維持します。 

1. グループ化のみを示す構造的な開き括弧を無視して、式を左から右にスキャンします。 空のかっこのペアで表されるプリミティブ コリドーに遭遇した場合、それを値 1 として扱い、スタックにプッシュします。 
2. 2 つの部分式の間に演算子が見つかった場合は、それをスタックに保存して、後で両方のオペランドが使用可能になったときに適用できるようにします。 この演算子は、順次合成ルールまたは並列合成ルールのいずれかです。 
3. 右括弧に到達すると、形式 (A op B) の完全な部分式が完了したことを示します。 この時点で、右側のオペランド、次に演算子、次に左側のオペランドをスタックからポップします。 
4. 部分式の結果を計算します。 演算子が順次合成に対応する場合、有効なパスは両方のコンポーネントを通過する必要があり、ボトルネックが優先されるため、2 つの値の最小値がとられます。 演算子が並列合成に対応する場合は、すべての分岐を独立してブロックする必要があるため、2 つの値を加算します。 
5. 計算結果をスタックにプッシュして、上位レベルの合成に参加できるようにします。 
6. 文字列全体を処理した後、スタックにはダンジョン全体の答えとなる 1 つの値が含まれます。 

正確性は、すべてのスタック エントリが完全に縮小された部分式の正しい答えを表すという不変条件に基づいています。 括弧で囲まれたブロックを縮小するたびに、すべての内部構造を忠実に要約した単一の同等の「エッジ カット値」に折りたたまれます。 式は完全に括弧で囲まれているため、リダクションが不完全な部分式に干渉することはありません。 

これにより、最終的な削減が実行されるときに、考えられるすべてのパスの組み合わせがすでに 1 回だけ考慮されており、最終値が必要な教師の真の最小数を表すことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    stack = []

    for ch in s:
        if ch == '(':
            continue
        if ch == ')':
            right = stack.pop()
            op = stack.pop()
            left = stack.pop()

            if op == '+':
                stack.append(min(left, right))
            else:  # '*'
                stack.append(left + right)
        else:
            if ch == '1':
                stack.append(1)
            else:
                stack.append(ch)

    print(stack[0])

if __name__ == "__main__":
    solve()
```この実装は、すべての完全な部分式が閉じ括弧に遭遇したときに常に正確に削減されるという事実に依存しています。 スタックは値と演算子を交互に切り替えます。 右括弧が表示される場合、スタックの最上位は右オペランド、その後に演算子、その後に左オペランドである必要があります。 この順序は、入力の厳密な構造によって保証されます。 

微妙な詳細の 1 つは、プリミティブ コリドーが空の括弧で表されるため、定数値 1 が与えられることです。 解析では、これらはリーフ構造として検出されるたびにベース値としてプッシュされます。 

## 実用的な例

 表現を考えてみる`(()+(()*(()+())))`。 私たちは削減のみを追跡します。 

最も低いレベルでは、それぞれ`()`貢献 1. 最内部構造`(()+())`になる`min(1,1)=1`。 それから`(()*1)`になる`1+1=2`。 最後にトップレベルの結合`1 + 2`連続した構成として、`min(1,2)=1`。 

| ステップ | スタック | アクション |
 | --- | --- | --- |
 | プッシュ | [1, 1] | 2つのベース廊下 |
 | + | を減らす [1] | 分(1,1) |
 | プッシュ * ブランチ | [1, 1] | 並列展開 |
 | * | を減らす [1、2] | 合計 |
 | 最終リデュース + | [1] | 分 |

 このトレースは、逐次構造がボトルネックに崩壊する一方で、並列分岐がどのようにコストを蓄積するかを示しています。 

次に、純粋な並列構造を考えてみましょう。`( () * () * () )`ネストされたバイナリとして解釈されます。 各リーフは 1 であり、加算を繰り返すと 3 が得られます。アルゴリズムはすべての独立したパスを正しく累積します。 

| ステップ | スタック | アクション |
 | --- | --- | --- |
 | プッシュ | [1、1、1] | 三つ葉 | 写真 三つ葉
 | * | を減らす [2、1] | 最初のマージ |
 | * | を減らす [3] | 2 番目のマージ |

 これは、すべての独立したブランチを個別に考慮する必要があることを示しています。

 ## 特殊なケース

 単一の要素からなる最小限の入力`()`リーフ解析によってスタックが値 1 で正しく初期化され、リダクションが途中でトリガーされないことが保証されます。 

次のような深くネストされたシリーズの場合`((((() + ()) + ()) + ()))`、アルゴリズムは最小の削減を繰り返し適用します。 各削減により 2 つの単位値が 1 つに集約され、最終的な答えは 1 のままになります。これは、連続チェーンがボトルネック動作を正しく伝播することを示しています。 

次のような深くネストされた並列チェーンの場合、`((((() * ()) * ()) * ()))`、減少するたびに累積額が増加します。 スタックは予測どおりに拡大および縮小し、縮小を繰り返してもブランチが失われないことが確認されます。 

のような混合構造では、`((() + ()) * (() + ()))`、左右のサブツリーは結合される前に個別に 1 つに減らされ、最後の加算により 2 つが生成され、階層構成全体にわたって分岐の独立性が維持されることがわかります。
