 ## 解決策
 ## 問題の理解

 正の整数の期間を選択する必要があります`T`。 メッセージは次の倍数ごとに発生します`T`, しかし、メッセージの所有者は交代します。 最初の複数は光太郎、2 番目は茜、3 番目は再び光太郎、というように続きます。 の値`T`必要なメッセージ時間がすべて、送信者のアクティブな間隔内にある場合にのみ有効です。 

入力すると 1 日の長さがわかります`N`、続いて光太郎のアクティブインターバルとアカネのアクティブインターバル。 タスクは期間の数を数える事です`T`から`1`に`N`すべてのメッセージ時間要件を満たします。 

限界`N <= 10^9`あらゆる可能性をチェックすることを即座に除外します`T`。 たとえ`O(N)`10 億回の反復では制限時間内に収まらないため、ソリューションは大きすぎます。 間隔の数は少なく、1 人あたり最大 300 個のみです。これは、ソリューションでは時間単位ごとに反復するのではなく、間隔構造を使用する必要があることを示唆しています。 

よくある間違いは、ピリオドで作成できるメッセージは 1 つだけであることを忘れていることです。 もし`T > N/2`、必要な時間は`T`それ自体が問題であり、Kotaro が利用できるかどうかだけが重要です。 もう 1 つの間違いは、インターバルをハーフオープン レンジとして扱うことです。 間隔には両方のエンドポイントが含まれるため、正確にエンドポイントにあるメッセージは有効です。 

たとえば、次のことを考えてみましょう。```
3
1
3 3
1
1 1
```答えは`1`なぜなら`T = 3`は、時間 3 に 1 つのメッセージを作成し、Kotaro が送信できるようにします。 間隔の内部点のみをチェックするソリューションでは、誤って拒否されてしまいます。 

別の例:```
5
1
1 5
1
1 3
```のために`T = 2`、メッセージはタイム 2 と 4 で発生します。タイム 4 は茜に属し、無効であるため、`T = 2`数えてはいけません。 最初のメッセージのみをチェックする不注意な解決策は、間違った結果をもたらす可能性があります。 

## アプローチ

 直接的な解決策は、すべてを試します`T`から`1`に`N`。 各候補について、次の倍数を生成します。`T`そして、各倍数が正しい人の間隔内にあるかどうかを確認します。 これは定義に正確に従っているため、正しいです。 問題は候補者の数だ。 最悪の場合、これには約`N + N/2 + ...`メッセージチェック、大まかに言うと`N log N`。 と`N = 10^9`、これは不可能です。 

重要な観察は、困難な候補者が 2 つのグループに分かれていることです。 小さい`T`値には多くのメッセージが含まれていますが、そのような値はほとんどありません。 大きい`T`値にはメッセージがほとんどないため、値の代わりにメッセージ数を調べることで処理できます。`T`。 

させて`S = floor(sqrt(N))`。 のために`T <= S`、候補者は約 31623 人しかいません。 不良間隔に次の値が含まれているかどうかを尋ねることで、それぞれを効率的にテストできます。`T`必要なパリティを備えています。 

のために`T > S`、メッセージの数は最大です`S`。 繰り返す代わりに`T`、可能なセットを維持します。`T`最初の条件を満たす値`k`メッセージ。 を追加すると、`k`- 番目のメッセージ制約では、このセットを次の間隔で交差させます。`k*T`有効です。 現在のセットは互いに素な間隔として保存されるため、すべてのステップは単なる間隔の交差になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N log N) | お(1) | 遅すぎる |
 | 最適 | O(sqrt(N) * (X+Y)) | O(X+Y) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 可能な値を分割します。`T`を使用して 2 つのグループに分けます`S = floor(sqrt(N))`。 からの値`1`に`S`個別に対応させていただきます。 より大きい値`S`作成されるメッセージの数をカウントすることで処理されます。 
2. あらゆる小さなことに対して`T`、必要な奇数倍数が光太郎の間隔の外にあるか、必要な偶数倍が茜の間隔外にあるかを確認します。 しばらくの間`[L, R]`、の倍数`T`その内部は次の乗数値に対応します。`ceil(L/T)`に`floor(R/T)`。 その範囲に奇数が含まれるか偶数が含まれるかを知る必要があるだけです。 
3.大型の場合`T`、すべてを表す間隔リストを保持します。`T`より大きい値`S`これまでに処理されたメッセージを満たしているもの。 最初はすべての値が`(S, N]`可能です。 
4. プロセスメッセージ番号`k = 1, 2, ...`。 メッセージ番号の場合`k`、すべてのアクティブな間隔を変換します`[L, R]`送信者の可能な値を`T`:`ceil(L/k) <= T <= floor(R/k)`。 

この新しいセットを現在の可能なセットと交差させます。 
5. メッセージの処理後`k`の値を数えます。`T`正確にどこの範囲で`k`メッセージが存在します:`floor(N/(k+1)) < T <= floor(N/k)`。 

これらはまさに大きな値であり、その最終メッセージは`k`- 番目のもの。 

なぜ効果があるのか:

 小型用`T`を使用すると、送信できないメッセージが見つかった場合、アルゴリズムは値を拒否します。 そのようなメッセージが存在しない場合、必要なメッセージ時間はすべて有効であるため、その期間は受け入れられます。 

大型用`T`、メッセージの処理後`k`、維持される間隔には、最初の期間が正確に含まれます。`k`メッセージはすべて有効です。 ピリオドは正確にバケットに属します。`k`値が次の範囲にある場合にのみメッセージを送信します`floor(N/(k+1))+1`そして`floor(N/k)`。 これら 2 つの条件が交差すると、有効な長い期間が正確にカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def contains(intervals, x):
    lo, hi = 0, len(intervals)
    while lo < hi:
        mid = (lo + hi) // 2
        if intervals[mid][0] <= x:
            lo = mid + 1
        else:
            hi = mid
    idx = lo - 1
    return idx >= 0 and intervals[idx][1] >= x

def has_bad_multiple(T, bad, parity):
    for l, r in bad:
        a = (l + T - 1) // T
        b = r // T
        if a <= b:
            if a % 2 != parity:
                a += 1
            if a <= b:
                return True
    return False

def intersect(a, b):
    res = []
    i = j = 0
    while i < len(a) and j < len(b):
        l = max(a[i][0], b[j][0])
        r = min(a[i][1], b[j][1])
        if l <= r:
            res.append((l, r))
        if a[i][1] < b[j][1]:
            i += 1
        else:
            j += 1
    return res

def scaled(intervals, k):
    res = []
    for l, r in intervals:
        a = (l + k - 1) // k
        b = r // k
        if a <= b:
            if res and res[-1][1] + 1 >= a:
                res[-1] = (res[-1][0], max(res[-1][1], b))
            else:
                res.append((a, b))
    return res

def count_in(intervals, l, r):
    if l > r:
        return 0
    ans = 0
    for a, b in intervals:
        if b < l:
            continue
        if a > r:
            break
        ans += min(b, r) - max(a, l) + 1
    return ans

def solve():
    N = int(input())
    X = int(input())
    kotaro = [tuple(map(int, input().split())) for _ in range(X)]
    Y = int(input())
    akane = [tuple(map(int, input().split())) for _ in range(Y)]

    bad_k = []
    last = 0
    for l, r in kotaro:
        if last + 1 <= l - 1:
            bad_k.append((last + 1, l - 1))
        last = r
    if last < N:
        bad_k.append((last + 1, N))

    bad_a = []
    last = 0
    for l, r in akane:
        if last + 1 <= l - 1:
            bad_a.append((last + 1, l - 1))
        last = r
    if last < N:
        bad_a.append((last + 1, N))

    ans = 0
    S = int(N ** 0.5)

    for t in range(1, S + 1):
        if not has_bad_multiple(t, bad_k, 1) and not has_bad_multiple(t, bad_a, 0):
            ans += 1

    cur = [(S + 1, N)]
    k = 1
    while k <= N // (S + 1) and cur:
        allowed = scaled(kotaro if k % 2 else akane, k)
        cur = intersect(cur, allowed)

        left = N // (k + 1) + 1
        right = N // k
        ans += count_in(cur, left, right)
        k += 1

    print(ans)

solve()
```最初の部分では、両方の人の欠落時間間隔を構築します。 使用できない範囲を使用すると、無効なメッセージが 1 つ存在するとすぐに候補が拒否されるため、後のチェックが容易になります。 

小さな-`T`ループはメッセージを列挙しません。 代わりに、乗数範囲に必要なパリティを持つ乗数が含まれているかどうかをチェックします。 これにより、間隔の数に比例した作業が維持されます。 

大きな-`T`部分は、可能な期間を間隔として保存します。 送信間隔からの換算`[L, R]`可能な期間にはメッセージインデックスによる除算を使用します`k`、これは乗算の逆数です`k*T`。 すべての計算では、間隔のエンドポイントが含まれるよう、整数の除算が慎重に使用されます。 

Python の整数はオーバーフローしないため、大きな値は`N`安全です。 の使用`floor`そして`ceil`部門は、オフバイワンの間違いが発生する可能性のある主な場所です。

 ## 特殊なケース

 いつ`T`の半分より大きい`N`, there is only one message. アルゴリズムは、最初の大きな期間のバケットを通じてこれを処理します。`k = 1`。 たとえば、`N = 10`とコタローでしか手に入らない`[10,10]`、値`T = 10`メッセージ時間のみが有効であるため、カウントされます。 

最初のメッセージではなく後のメッセージで障害が発生した場合でも、追加の各メッセージ インデックスが現在の間隔セットと交差するため、アルゴリズムは引き続き障害を捕捉します。 例では、`N = 5`, コタローは、`[1,5]`、そしてあかね`[1,3]`、期間`T = 2`最初のメッセージ チェックでは存続しますが、次の場合に削除されます。`k = 2`必要`2T = 4`あかねの合間に所属すること。 

メッセージが間隔エンドポイントに正確に到着すると、包含間隔ロジックによってメッセージが有効に保たれます。 小型ケースと大型ケースの両方の天井と床の分割により、これらの境界が維持されるため、いつでもメッセージを伝えることができます。`L`または`R`誤って破棄されることはありません。
