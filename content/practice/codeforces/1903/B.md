 ## 解決策
 ## 問題の理解

 ビット単位の構築規則を通じて、隠し配列から取得されたと主張される対称行列が与えられます。 隠し配列には、$n$それぞれ以下の非負の整数$2^{30}$。 個別のインデックスのすべてのペアに対して$i$そして$j$、行列のエントリ$M_{i,j}$非表示の値のビット単位の OR に等しい$a_i$そして$a_j$。 対角線のエントリは常にゼロです。 

タスクは、有効な配列を再構築することです。$a$指定された行列を生成することも、そのような配列が存在しないと判断することもできます。 

主な問題点は、直接の値が与えられず、ペアごとの OR の結果のみが与えられることです。 各制約は 2 つの未知数を結合し、行列内のすべてのビットが両方のエンドポイントのビットに関する部分情報をエンコードします。 

この制約は、検索問題ではなく、厳密な再構成の問題を意味します。 以来$n$テストごとに最大 1000 にすることができ、テスト全体の合計も 1000 になります。$O(n^3)$または、すべてのトリプルに対してビットごとの一貫性チェックを繰り返すことを含むものは、依然として境界線にありますが、小さな定数でのみ許容されます。 ただし、意図した解決策では、三重に入れ子になった推論を回避する必要があります。 

素朴に再構築を試みると、当然のことながらいくつかの失敗例が現れます。 

よくある間違いの 1 つは、次のように仮定することです$a_i = \bigwedge_{j \ne i} M_{i,j}$。 OR はそのように分解されないため、これは誤りです。 たとえば、次の場合$a_i = 1$そして$a_j = 2$、 それから$M_{i,j} = 3$、単一の交差は元のビットを回復しません。 

もう 1 つの微妙な問題は、トリプル間の不一致です。 たとえば、次の場合$M_{1,2} = 3$、$M_{1,3} = 3$、$M_{2,3} = 0$の場合、有効な割り当ては存在しません。 最後の値は、2 と 3 の互いに素なビットセットを意味しますが、どちらも 1 とビットを共有する必要があり、OR 構造では矛盾します。 

実際の構造は、行列の各行を隠れたビットセットの「和集合シグネチャ」として解釈することから得られる必要があります。 

## アプローチ

 強引なアイデアは、考えられるすべての配列を試すことです$a$、ただし、各要素には$2^{30}$可能性があるので、これは不可能です。 ペアごとの制約に基づいて値を制限しても、依然として指数関数的な検索スペースが残ります。 

より構造化された総当たり的なアプローチは、それぞれを処理することです。$a_i$未知のビットマスクとして、ペアごとに制約を適用します。 収束するまで値を繰り返し調整することもできますが、各更新は他のすべての更新に依存し、最悪の場合は全体に伝播します。$n^2$制約により多項式コストが高くなります。 

重要な観察は、OR 関係を逆転させることです。 もし$M_{i,j} = a_i \mid a_j$、次に、以下を含むすべてのペアワイズ OR でゼロであるすべてのビット$i$欠席しなければなりません$a_i$。 逆に、一部にビットが表示される場合は、$M_{i,j}$、次の少なくとも 1 つに属している必要があります。$a_i$または$a_j$。 

これを利用するきれいな方法は、候補値を貪欲に構築することです。つまり、それぞれの値が$a_i$すべての OR 制約と一致している必要があります。 固定の場合$i$、ビットの場合を考慮してください$b$すべてに欠けています$M_{i,j}$、 それから$a_i$ビットを含めることはできません$b$。 これにより上限が決まります$a_i$。 

次に、一貫性をチェックします。候補配列が構築されたら、すべてのペアごとの OR が行列と一致するかどうかを検証します。 そうでない場合、その構築は無効です。 

より直接的な建設的単純化が存在します。つまり、有効な OR 行列の場合、行列は任意のトリプルの条件を満たさなければなりません。$i, j, k$、$$M_{i,j} \mid M_{i,k} = M_{j,k} \mid M_{i,k}$$構造は間接的に一貫性を強制しますが、慎重に再構築すれば明示的な三重チェックは必要ありません。 

標準的に受け入れられているアプローチは驚くほど単純です。$$a_i = M_{i,1} \& M_{i,2} \& \cdots \& M_{i,n}$$それは間違っていますが、正しい建設的なトリックは次のとおりです。$$a_i = M_{i,1} \& M_{i,2} \& \cdots \& M_{i,n} \text{ is not valid}$$したがって、代わりに補数推論を使用します。 

ビット位置ごとに、どの行にそのビットを安全に含めることができるかを検討します。 多少は許される$a_i$すべての場合にのみ$j$、 どちらか$M_{i,j}$すでにそのビットが設定されているか、一貫して 1 つのエンドポイントに割り当てることができます。 この問題の既知の単純化は次のようになります。 

セット$$a_i = \bigwedge_{j \ne i} M_{i,j}$$候補としてだけでは十分ではありませんが、正しい構造は次のとおりです。$$a_i = \bigwedge_{j \ne i} (M_{i,j})$$そして検証してください。 有効な解が存在する場合、OR マトリックス構造により強制ビットの一貫性が保証されるため、この構造はそのうちの 1 つと一致します。 

残りのステップは検証です。すべてを再計算します。$a_i \mid a_j$そして比較してください$M$。 すべて一致する場合は出力します。 そうでなければ、解決策は存在しません。 

これが機能するのは、有効な OR 分解では、ビットがすべてのペアごとの相互作用に強制的に出現するためです。$i$に属さなければなりません$a_i$。 無関係なビットは、少なくとも 1 つのペア制約に違反します。

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、マトリックスを読み取ります。$M$。 整合性を検証するため、変更しないでおきます。 
2. インデックスごとに$i$、候補値を計算します$a_i$すべてのビットごとの AND をとることによって$M_{i,j}$のために$j \ne i$。 これにより、関連するすべての関係にわたって一貫して存在するビットが抽出されます。$i$、安全に属することができる唯一のビットです$a_i$OR 制約を破ることなく。 
3. すべての候補値を作成したら、それらをマトリックスと照合して検証します。 すべてのペアについて$i, j$、計算する$a_i \mid a_j$そしてそれが等しいかどうかを確認してください$M_{i,j}$。 不一致が発生すると、その構築では指定された行列を表現できなくなります。 
4. すべてのペアが一致する場合は、YES を出力し、続いて配列を出力します。$a$。 それ以外の場合は NO を出力します。 

### なぜ効果があるのか

 行の AND で生き残る各ビット$i$あらゆるものに存在します$M_{i,j}$。 有効な分解では、そのようなビットが欠落することはありません。$a_i$、そうでない場合は、いくつかのものが存在します。$j$OR がそのビットの由来を必要とする場所$a_j$、すべてのペアでの存在と矛盾します。 逆に、一貫して存在しないビットは安全に割り当てることができません。$a_i$一部のパートナー行との OR 不一致が作成される危険性があるためです。 これにより、構築された$a_i$インデックスごとの最大限の安全な割り当て、および最後の検証ステップで、ビットのあいまいな分布が誤って受け入れられていないことを確認します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        M = [list(map(int, input().split())) for _ in range(n)]

        a = [0] * n

        for i in range(n):
            val = (1 << 30) - 1
            for j in range(n):
                if i != j:
                    val &= M[i][j]
            a[i] = val

        ok = True
        for i in range(n):
            for j in range(n):
                if i == j:
                    if M[i][j] != 0:
                        ok = False
                        break
                else:
                    if (a[i] | a[j]) != M[i][j]:
                        ok = False
                        break
            if not ok:
                break

        if not ok:
            print("NO")
        else:
            print("YES")
            print(*a)

if __name__ == "__main__":
    solve()
```構築フェーズではそれぞれを計算します。$a_i$そのインデックスに関係するすべての制約を交差させることによって。 すべてのビットを設定して初期化すると、すべてのペアワイズ OR で一貫してサポートされているビットのみが存続します。 

構築は必要ですが、グローバルな一貫性をチェックしなければ必ずしも十分ではないため、検証ステップは不可欠です。 すべてのペアにわたる二重ループにより、隠れた矛盾が残らないようにします。

 ## 特殊なケース

 重要なエッジケースは、すべての非対角エントリがゼロである場合です。 その状況では、すべてのペアごとの OR はゼロになるため、すべての$a_i$ゼロでなければなりません。 この構造ではゼロの AND が計算され、正しくゼロが生成され、検証はすぐに合格します。 

別のケースは、同じ値の完全に接続された行列です。たとえば、すべての非対角エントリが 7 に等しい場合です。各行の AND は 7 を生成するため、すべての行が 7 になります。$a_i = 7$、そして OR の一貫性は自明に成立します。$7 \mid 7 = 7$。 

より微妙なケースは、トリプル間でのビット配分の一貫性のなさです。 たとえば、ある行がビットが存在する必要があることを示唆している一方で、別のペアがそれを禁止している場合、AND 構造により少なくとも 1 つのエンドポイントからそのビットが削除され、OR 値の再計算中に検証によって矛盾が検出されます。
