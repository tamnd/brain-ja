 ## 解決策
 ## 問題の理解

 私たちは 2D 平面上の 2 人用ゲームについて推論するように求められます。 ゲームは固定点から始まり、与えられた点のセットから点を 1 つずつ選択することで構成されます。 点が選択されるたびに、以前に選択された点からのユークリッド距離の 2 乗が累計に加算されます。 ゲーム終了時にこの合計が均等であれば最初のプレーヤーが勝ち、それ以外の場合は 2 番目のプレーヤーが勝ちます。 課題は、先手でプレーするか後手でプレーするかを決定し、勝利を保証するために最適なポイントを選択する方法を決定することです。 

入力は複数のテスト ケースで構成されます。 テスト ケースごとに、点の数、開始点の座標、および点のリストを受け取ります。 出力はインタラクティブである必要があります。まずプレイヤーの順序を選択し、次に自分のターンでポイントを選択し、相手のターンでどのポイントを選択したかを読み取ります。 制約により、最大で次のことが許可されます。$10^5$テストケースごとのポイントですが、合計$n$すべてのテストケース全体で最大でも$10^5$したがって、各ポイントを 1 回処理するソリューションでも問題ありません。 座標は非常に大きくなる可能性があり、最大で$10^9$ただし、実際の距離にはパリティのみが必要なので、整数のオーバーフローを心配する必要はありません。 

明らかではないエッジケースは、合計が二乗距離のパリティのみに依存するという事実から生じます。 正確な距離を合計しようとする単純な実装では、大きな整数の演算が行われる危険があり、偶数または奇数の値のみが重要であるという単純化が失われます。 もう 1 つの微妙な点は、最適なプレーヤーが常に最初のプレーヤーであるとは限らないことです。 ポイントの構成によっては、後手から開始すると、動きを一致させたり、対抗したりすることでパリティを制御できる可能性があります。 たとえば、開始点からの距離がすべて偶数である場合、最初のプレーヤーは奇数の合計を強制することはできず、2 番目のプレーヤーを選択する必要があります。 

## アプローチ

 ブルートフォース ソリューションでは、すべての一連の動きをシミュレートし、それぞれの最終的な合計を評価しようとします。 これにはコンピューティングが必要になります$n!$点の順列、これは中等度の人でも不可能$n$以来$10^5!$天文学的に大きいです。 ゲーム ルールが決定的であるためブルート フォースは機能しますが、シーケンスの数が階乗的に増加するため失敗します。 

重要な観察は、正確な距離は気にせず、和のパリティだけを気にするということです。 整数を 2 乗するとパリティが維持されます。つまり、数値が偶数の場合は 2 乗は偶数となり、数値が奇数の場合は奇数となります。 点間のユークリッド距離の二乗$(x_1, y_1)$そして$(x_2, y_2)$は$(x_2-x_1)^2 + (y_2-y_1)^2$。 この式のパリティは、座標の差のパリティによってのみ決定されます。 具体的には、両方の差が偶数であるか、両方が奇数である場合、合計は偶数になります。 一方が奇数でもう一方が偶数であれば、合計は奇数になります。 

これにより、問題は純粋にパリティベースのゲームに縮小されます。 各点は、その座標のモジュロ 2 の合計が開始点の座標のモジュロ 2 と一致するかどうかに応じて色を持ちます。最初から同じパリティのポイントは「偶数手」、反対のパリティの点は「奇数手」です。 先手プレイヤーは、先手スタート時、または後手スタート時でも奇数手ポイントのカウントが奇数であれば勝利を保証でき、常に適切なパリティのポイントを選択することで累計のパリティを制御できます。 この洞察により、問題はカウントとパリティ、つまり線形時間操作に帰着します。

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、次の内容を読んでください。$n$、$s_x$、$s_y$、およびポイントのリスト。 各点について、開始点に対するパリティを計算します。$(x_i - s_x) \% 2$そして$(y_i - s_y) \% 2$。 2 を法とする二乗距離は、パリティの座標が 1 つだけ異なる場合は 1、それ以外の場合は 0 になります。 
2. 最初から選択した場合に、奇数の二乗距離に寄与する点の数を数えます。 このカウントを次のようにします`odd_count`。 
3. プレイヤーの順番を決めます。 もし`odd_count`奇妙です。最初にプレイすることを選択してください。 もし`odd_count`が偶数の場合は、2 番目にプレーすることを選択します。 この選択により、最終的な合計のパリティを確実に制御できます。 
4. ゲーム中、利用可能なポイントのリストを管理します。 次の順番では、現在の合計パリティを反転する必要がある場合は奇数の二乗距離に寄与する点を選択し、それを保持したい場合は偶数の二乗距離に寄与する点を選択します。 これは、パリティ数が事前にわかっており、交互にターンを行うため、常に可能です。 
5. 相手のターンでは、相手の動きを読み、利用可能なポイントのリストからそれを削除します。 
6. すべての点が選択されるまで繰り返します。 この時点で、合計平価は選択したプレーヤーの戦略によって制御され、勝利が保証されます。 

これが機能する理由: 不変条件は、最初または 2 番目のプレーヤーが常にポイントを選択して累計のパリティを制御できることです。 事前に奇数と偶数の貢献を数えてターンを交互に行うことで、選択したプレイヤーは勝利条件に応じて合計が偶数または奇数になるようにすることができます。 2 を法とする二乗距離は座標パリティのみに依存するため、この不変式は実際の位置に対して堅牢であり、あらゆる構成に機能します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
flush = sys.stdout.flush

def parity(x):
    return x % 2

t = int(input())
for _ in range(t):
    n = int(input())
    sx, sy = map(int, input().split())
    points = [tuple(map(int, input().split())) for _ in range(n)]
    
    odd_points = []
    even_points = []
    for idx, (x, y) in enumerate(points):
        dx = parity(x - sx)
        dy = parity(y - sy)
        if dx ^ dy:
            odd_points.append(idx + 1)
        else:
            even_points.append(idx + 1)
    
    if len(odd_points) % 2 == 1:
        print("First")
        flush()
        my_turn_points = odd_points + even_points
    else:
        print("Second")
        flush()
        my_turn_points = even_points + odd_points

    used = set()
    for turn in range(n):
        if turn % 2 == 0:  # our turn
            for j in my_turn_points:
                if j not in used:
                    print(j)
                    flush()
                    used.add(j)
                    break
        else:  # opponent's turn
            j = int(input())
            if j == -1:
                exit()
            used.add(j)
```まず、点をパリティを反転する点 (奇数) と反転しない点 (偶数) に分けます。 プレーヤーの順序の選択は、奇数ポイントのカウントに基づいて行われます。 各ターン中に、パリティの制御を維持するために、事前に計算されたリストから利用可能なポイントを選択します。 の`used`set を使用すると、すでに選択されている点を決して選択しないことが保証されます。 相手のターンでは、相手の選択を読み取って更新します`used`。 の`^`演算子は XOR を効率的に計算してパリティの差を決定します。 

## 実用的な例

 サンプル 1:

 | ターン | 現在の合計パリティ | 残りポイント (奇数/偶数) | アクション | 結果 |
 | --- | --- | --- | --- | --- |
 | 1 | 0 | 奇数: 4 偶数: 2 | 最初に奇数を選択します | 合計パリティが 1 に反転します。 
| 2 | 1 | 奇数: 3 偶数: 2 | 相手は偶数を選択します | 合計パリティは 1 のままです |
 | 3 | 1 | 奇数: 3 偶数: 1 | 最初に奇数を選択します | 合計パリティが 0 に反転します。 
| ... | ... | ... | ... | ... |

 このトレースは、奇数/偶数のピックを交互に行うことで、選択したプレイヤーが合計のパリティを操作して、必ず偶数で終わるようにできることを示しています。 

サンプル 2: n = 3、すべての点が開始点から等距離にあります。 

| ターン | 現在の合計パリティ | アクション |
 | --- | --- | --- |
 | 1 | 0 | 2 番目は偶数を選択します |
 | 2 | 0 | 最初に偶数を選択します |
 | 3 | 0 | 2 番目は偶数を選択します |

 たとえ対戦相手が最適なプレーをしたとしても、最終的には合計が均等になるため、2 番目のプレーヤーが不戦勝となります。
