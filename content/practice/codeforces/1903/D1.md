 ## 解決策
 ## 問題の理解

 整数の配列と演算のバジェットが与えられ、各演算で 1 つの要素を 1 ずつ増やすことができます。異なるバジェットを提供するクエリごとに、最大でその数の演算を使用した後、すべての配列要素のビット単位の AND を取得することで達成可能な最大値が必要になります。 配列自体はクエリ間で変更されないため、各クエリは独立しています。 

入力サイズはかなり大きく、配列には最大 100,000 個の要素を含めることができ、最大 100,000 個のクエリを含めることができます。 の合計積`n * q`これは、ネストされたループ内のすべてのクエリのすべての要素を検査するアルゴリズムを用意する余裕がないことを意味します。 各要素は 10^6 までの大きさになる可能性があるため、ビット単位の表現は最大 20 ビットになります。 これは、ビットレベルの操作が可能であり、おそらく必要であることを示唆しています。 操作数`k`最大 10^18 と巨大になる可能性があるため、各増分を個別にシミュレートすることはできません。 

単純なアプローチでは、操作を実行するためにあらゆる方法を試行したり、結果として得られる配列をすべて試行したりする可能性があります。 たとえば、配列が次の場合、`[1, 2, 3]`そして`k=3`、要素全体で最大 3 つの合計ユニットを追加するすべての組み合わせを試すことができます。 これは組み合わせ的に爆発的であり、たとえ小規模であっても実行不可能です。`n`。 

重要な微妙な点は、一部の要素にはすでに高ビットが設定されている可能性がある一方で、他の要素には一致させるために大幅なビットの増加が必要であるということです。 たとえば、次のように考えてみましょう`[1, 2, 7]`と`k=1`。 最大の AND は次のとおりです。`0`, because increasing any single element by 1 cannot make all elements share a common high bit. A careless solution that just sums the increments or tries greedy additions from left to right may report the wrong AND. We must carefully evaluate which bits can be “turned on” across all elements under the given budget.

 ## アプローチ

 The brute-force solution would attempt every combination of distributing`k`ANDを最大化する演算。 これは原理的には正しいです。すべての可能性を試すことができれば、最終的に最善のものを見つけることができるからです。 しかし、のために`n=10^5`そして`k`10^18 までは不可能です。 巧妙なロジックを使用せずにクエリごとにすべての配列要素を反復処理した場合でも、最悪の場合、O(n*q) = 10^10 の演算が行われます。 

重要な洞察は、絶対的な数値ではなくビットの観点から考えることです。 数値のビット単位の AND は、**all** 要素に設定されている最上位ビットの位置によって支配されます。 AND をできるだけ大きくしたい場合は、ビットを最上位からチェックし、利用可能な演算を使用して要素を増やしてそのビットを設定できるかどうかを確認できます。 ビットごとに、ビットが少なくともその値に設定されていないすべての数値を引き上げるための合計コストを計算します。 コストが現在のクエリの範囲内である場合`k`、最後の AND にビットを保持します。 

この観察により、問題は、正確な数値の追跡から、高値から低値までの貪欲なビットごとのチェックに軽減されます。 ビットの総数は小さい (10^6 までの数値の場合は 20) ため、各クエリでは、すべての要素にわたって最大 20 ビットを評価するだけで済みます。 これにより、クエリごとに実行可能な O(n * 20) が得られます。これは、n*q ≤ 10^5 制約を考慮すると許容されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(k * n) | O(n) | 遅すぎる |
 | ビットごとの貪欲な | クエリごとに O(n * 20) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 任意の要素の可能な最上位ビット (数値 ≤10^6 の場合は 20 番目のビット) から開始して、対象のビットを降順に並べ替えます。 上位ビットほど AND に寄与するため、最上位ビットから最下位ビットまで一度に 1 ビットずつ処理します。 
2. 答えを 0 に初期化します。この変数には、現在の予算で達成できる AND が格納されます。 
3. 各ビットについて、すべての要素でそのビットを設定するためのコストを計算します。 まだビットが設定されていない各要素について、すでに設定されている上位ビットを変更せずにそのビットをオンにするためにどれだけ追加する必要があるかを計算します。 これは`(1 << bit) - (a[i] & (1 << bit - 1))`このビットが 1 である次の数値に到達するために必要な量に単純化されます。 
4. 現在のビットの合計コストが以下の場合`k`からこの費用を差し引きます`k`ビットごとの OR を使用して、そのビットを応答に含めます。 
5. 次の下位ビットに進み、すべてのビットが評価されるまでこのプロセスを繰り返します。 
6. クエリに対する最終的な回答を出力します。 

機能する理由: このアルゴリズムは、各ステップで、現在の答えがそれまでに費やした操作を使用して達成可能な最高の AND を表すという不変条件を維持します。 最上位ビットから開始し、すべての要素でオンにできるビットのみをコミットすることで、機会を逃すことがなくなり、すべての要素に適用できない場合にはビットが設定されなくなります。 これにより、結果が真の最大値であり、かつ指定された予算内で達成可能であることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, q = map(int, input().split())
a = list(map(int, input().split()))

queries = [int(input()) for _ in range(q)]

max_bit = 0
for num in a:
    max_bit = max(max_bit, num.bit_length())

for k in queries:
    ans = 0
    remaining = k
    for bit in reversed(range(max_bit + 1)):
        cost = 0
        mask = 1 << bit
        for num in a:
            if not (num & mask):
                increment = mask - (num & (mask - 1))
                cost += increment
        if cost <= remaining:
            remaining -= cost
            ans |= mask
    print(ans)
```このソリューションでは、最初にすべての要素にわたって最も関連性の高いビットが計算されます。 次に、クエリごとに上位ビットから下位ビットまで反復し、すべての要素でそのビットをオンにするのにかかるコストを計算します。 総コストがクエリの予算内に収まる場合のみ`k`答えを更新しますか？ 微妙な点は、すでに下位ビットが設定されている数値の増分を正しく計算することです。これにより、誤ってオーバーシュートが発生することを回避できます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n * max_bit * q) ≈ O(n * 20 * q) | 各クエリは、すべてのビットとすべての要素を反復処理します。 |
 | スペース | O(n + q) | 配列とクエリを保存します。 |
