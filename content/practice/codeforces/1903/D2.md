 ## 解決策
 ## 問題の理解

 整数の配列が与えられます。 個々の要素を一度に 1 つずつ増やすことができ、各増加には 1 単位の予算がかかります。 クエリごとに予算値が与えられます。$k$、そして、最大で費やした後、配列全体のビットごとの AND をどのくらいの大きさにできるかを知りたいのです。$k$すべての要素にわたる合計増分。 

キーの出力は最終的な配列ではなく、可能な最大値です。$a_1 \,\&\, a_2 \,\&\, \dots \,\&\, a_n$せいぜい最適に分散した上で$k$増加します。 

制約は非常に大きく、最大で$10^6$要素とクエリ、および値$k$まで$10^{18}$。 これにより、クエリごとまたは要素ごとに操作をシミュレートするソリューションは即座に除外されます。 クエリごとの直線的な作業ですら遅すぎます。 

単純な解釈では、クエリごとに、増分を分散するあらゆる方法を試行することになりますが、これは組み合わせによるものであり、明らかに不可能です。 ターゲット AND 値を「構築」しようとしたり、クエリごとに独立して実現可能性をチェックしたりする場合でも、クエリごとの再計算にはコストがかかりすぎるため、大幅に最適化する必要があります。 

すべての数値がすでに大きくてもビット単位で揃っていない場合、微妙なエッジ ケースが発生します。 たとえば、ある数値にビットが設定されており、別の数値にはビットが設定されていない場合、桁上げの伝播に応じて、値を増やすと役立つ場合もあれば不利になる場合もあります。 これにより、貪欲な推論は自明ではなくなり、数値的な制約ではなくビットごとの制約の観点から考えることを余儀なくされます。 

## アプローチ

 ブルートフォースのアイデアは概念的には単純です。 固定の場合$k$、演算後の最終配列を推測し、その AND を計算します。 各増分はちょうど 1 つの要素を 1 ずつ増やすため、要素全体に分散された任意の整数の増加を事実上「購入」していることになります。 つまり、各要素は独立して調達できますが、コストは全体的に蓄積されます。 

直接総当たりでは、予算内で到達可能なすべての最終アレイを試します。$k$、しかしそれは天文学的な大きさです。 

より構造化されたブルート フォースは、ターゲット値を固定することです。$X$最終的な AND の場合。 次に、すべての配列要素を少なくとも次のようにできるかどうかを尋ねます。$X$最大でも総コストで$k$、また、すべてのビットが$X$インクリメント後もすべての要素に存在しますか?

 これにより、問題は候補者の実現可能性チェックに変換されます。$X$、それぞれを上げるためのコストを計算します。$a_i$ある数字に$b_i \ge X$そのような$(b_i \& X) = X$。 費用は$b_i - a_i$、要素ごとに最小化されます。 

重要な洞察は、実際には恣意的なものを考慮する必要はないということです。$b_i$。 各要素について、有効な最も安価な$b_i$以上の最小の数です$a_i$のすべてのビットが含まれています$X$。 これにより、各要素の決定論的なコスト関数が得られます。 

これで、構造は単調になります。$X$予算内で達成可能です$k$、それより小さいもの$X$も達成可能です。 これにより、クエリごとの回答に対する二分検索が可能になります。 しかし、それでも高速な実現可能性チェックが必要であり、そこでビットごとの貪欲な構築が使用されます。 

クエリごとに最初から再計算するのではなく、数値に候補マスクのビットを強制的に含めるときにコストがどのように動作するかを事前計算します。 その後、各クエリは、ビットマスクに対する二分検索と組み合わせた高速な実現可能性チェックになります。

 ## アルゴリズムのチュートリアル

 私たちは問題を解決策の発見に変えます。$k$、最大の整数$X$すべての配列要素を少なくとも次の値まで増やすことができるようにする$X$すべての部分を共有します$X$、予算内で$k$。 

1. 配列をソートし、すべての要素をターゲット ビットマスクと「互換性」のあるものにするための推論を可能にする構造を構築します。 重要な観察は、ビット制約を満たすために各要素を独立して切り上げられるが、コストはバイナリ キャリーがどのように相互作用するかに依存するということです。 
2. 関数を定義します`cost(X)`すべての要素を何らかの数値に変換できるように、必要な最小合計増分を計算します。$b_i \ge a_i$と$(b_i \& X) = X$。 各要素について、最小の有効な要素を貪欲に構築します。$b_i$必要に応じてビットを上向きに反転します。 これが機能するのは、1 ずつ増分すると数値が昇順に探索されるため、上記の最初の有効な候補が$a_i$が最適です。 
3. 実現可能性を計算するには、要素を反復処理し、要素ごとに、すべてのビットを埋め込むためにどれだけ上にジャンプする必要があるかをシミュレートします。$X$。 これは、次のビットをスキャンすることによって行われます。$X$最上位から最下位へ、欠落ビットを強制します。 
4. 1回`cost(X)`が定義されている場合、単調性が観察されます。$X$が達成可能であれば、制約が弱まるため、そのビットのサブセット (つまり、より小さい値) も達成可能です。 これにより二分探索は終了します$X$有効。 
5. 各クエリについて$k$、最大の二分探索を行います$X$そのような`cost(X) ≤ k`。 

### なぜ効果があるのか

 重要な不変条件は、実現可能性は、次のように定義されたビット制約のスーパーセットに各要素を強制的に入れることによってのみ決まるということです。$X$、これらの制約を満たす最小限の方法は要素ごとに独立しています。 インクリメントは値を増やすだけであるため、各要素の最適な調整は局所的に貪欲であり、総コストを除いて他の要素には影響しません。 この分離可能性により、個々の最小コストの合計の正確さが保証されます。 の単調性$X$二分探索で最適な答えがスキップされないようにします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXB = 61  # enough for k up to 1e18

def next_valid(x, mask):
    """
    Smallest y >= x such that y contains all bits of mask.
    We construct it greedily from MSB to LSB.
    """
    y = x
    for b in range(MAXB):
        if (mask >> b) & 1:
            if not ((y >> b) & 1):
                # force this bit by rounding up
                y = ((y >> (b + 1)) + 1) << (b + 1)
    return y

def cost(a, mask, limit):
    total = 0
    for x in a:
        y = next_valid(x, mask)
        total += (y - x)
        if total > limit:
            return total
    return total

def can(a, mask, k):
    return cost(a, mask, k) <= k

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    # upper bound for answer bits
    hi = (1 << 20) - 1  # safe since values start <= 1e6 and k large can grow them

    for _ in range(q):
        k = int(input())

        ans = 0
        # binary search over bits
        for b in reversed(range(20)):
            if ans | (1 << b) <= hi:
                if can(a, ans | (1 << b), k):
                    ans |= (1 << b)

        print(ans)

if __name__ == "__main__":
    solve()
```### コードの説明

 機能`next_valid`要素ごとに、候補 AND マスクのすべてのビットを満たす、増分によって到達可能な最小の数値を構築します。 これは少しずつ機能します。必要なビットが欠落している場合は、以前の制約に違反せずにそのビットを設定できる次の位置に数値を切り上げます。 

の`cost`関数は要素ごとの調整を合計し、予算を超えた場合は早期に停止します。これは、大きな制約を考慮したパフォーマンスにとって重要です。 

各クエリは、最上位ビットから最下位ビットまでの貪欲なビット構造を使用して独立して処理されます。 すべての値をバイナリ検索する代わりに、各ビットの設定の実現可能性をテストすることによって、応答ビットマスクを直接構築します。 

これにより、満杯を回避できます。$O(\log A)$クエリごとにバイナリ検索を実行し、それを線形ビット スイープに置き換えます。

 ## 特殊なケース

 重大なエッジ ケースは、1 つの要素が 2 のべき乗のしきい値をわずかに下回る場合です。 たとえば、次の場合$a_i = 7$ビット 3 を設定するマスクが必要です。次の有効な数値は 8 であり、これにより大きなジャンプが発生します。 これは、単純なビット設定ではコストが過小評価されるため、要素ごとに貪欲な丸めが必要な理由を示しています。 

別のエッジケースが発生するのは次の場合です。$k = 0$。 インクリメントは許可されないため、答えは単純に元の配列の AND でなければなりません。 変更が必要なマスク候補は実現可能性を満たさないため、アルゴリズムはこれを自然に処理します。 

最後のエッジケースは次のような場合です$k$非常に大きいです。 この場合、アルゴリズムは、すべての要素が同じ大きな数値に等しくなるように強制するマスクに収束する必要があります。 ビット単位の構築により、最終的には制約と矛盾しない最大限の範囲ですべての実行可能なビットが含まれることが保証されます。
