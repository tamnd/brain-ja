 ## 解決策
 ## 問題の理解

 道路で接続されたフィールドを表す、最大 50 個の頂点を持つ有向重み付きグラフが与えられます。 牛はノード 1 から開始してノード n に到達しようとします。それにかかる時間は、このグラフの最短経路によって決まります。 

ここで工夫が必要です。エッジを「減速」することができます。 各クエリに対して、予算 x が与えられます。 すべてのエッジにわたる追加の重みの合計が x を超えない限り、このバジェットをエッジ全体に分配して、エッジの重みを任意に増やすことができます。 重みを変更した後、1 から n までの最短パスを再計算し、その最短パスの値を最大化したいと考えます。 

したがって、各クエリは次のように尋ねます。エッジの重みを増やすために合計 x ユニットまで費やすことができる場合、ソースからターゲットまでの最大の最短パス距離はどれくらいですか?

 重要な構造は、これが最短パスでの 2 プレイヤーのインタラクションであるということです。最短パスをできるだけ大きくするために追加コストを分散する方法を選択しますが、パス自体は最小ルートを再計算することで常に敵対的に適応します。 

制約があるため、解決策は自明ではなくなります。 グラフの頂点は小さく、n ≤ 50 ですが、密度が高い可能性があります。 これは、中間頂点に対する全ペア構造または動的プログラミングが実現可能であることを強く示唆しています。 ただし、クエリの数は最大 100,000 と大きいため、クエリごとの最短パスの再計算やフローの解決は不可能です。 

素朴なアイデアは、各クエリを独立して処理し、重みの追加が最短パスにどのような影響を与えるかをシミュレートしようとすることです。 1 つのエッジを増加した場合の効果は、どの最短パスがアクティブになるかによって決まり、x が大きくなるにつれて不連続に変化する可能性があるため、これはすぐに問題に直面します。 

複数のパスが最短距離で結ばれる場合、微妙なエッジ ケースが発生します。 単純なアプローチが単一の固定最短パスを想定し、それに沿ってエッジのみを増加させる場合、失敗します。 

たとえば、1 から n までの 2 つの互いに素なパスが最初は両方とも同じ長さである場合、もう一方のパスが新たなボトルネックになるため、一方のパスのみのエッジの容量を増やすだけでは不十分です。 

エッジを増やすと、それまで最短ではなかったパスが最適になると、別の障害モードが発生します。 最短パスの正体は予算を投資するにつれて変化するため、静的パスの推論は機能しません。 

## アプローチ

 主な困難は、単一のパスに対して最適化を行っているのではなく、エッジの重みの摂動の下で最短パスの値に対して最適化していることです。 これは当然最小-最大問題です。すべての s-t パスの総重みの最小値を最大化するように予算を配分します。 

強引なアプローチは次のとおりです。固定された x について、問題をエッジの増分に対する継続的な最適化として扱い、増分を割り当てるときに最短パスがどのように変化するかをシミュレートしてみます。 現在の最短パスを繰り返し特定し、その端に重点を置き、予算がなくなるまで更新することを想像することもできます。 ただし、最短パスは変更のたびに構造が変化し、最悪の場合、重みが変化するにつれて最適になる別個の最短パスが指数関数的に多く存在します。 たとえ各再計算にフロイド・ウォーシャルまたはダイクストラが必要な場合でも、100,000 クエリを超えると非常に遅くなります。 

構造的なブレークスルーは、問題をパラメトリック最短経路問題として再解釈することです。 増分を明示的に分配することについて考える代わりに、視点を切り替えます。候補の応答値 T に対して、総予算 ≤ x を使用して、1 から n までのすべてのパスの長さが少なくとも T になるようにエッジの重みを増やすことが可能かどうかを尋ねます。 これにより、問題はしきい値を超える実現可能性のチェックに変換されます。

この実現可能性チェックは、最短経路に関する二重問題としてモデル化できます。 中心的なアイデアは、予算を最適に費やした場合に、各ノードをソースからどれだけ遠くに移動できるかを追跡することです。 n が小さいため、最短パス構造を事前に計算し、最短パスの成長を x の区分線形関数として表現できます。 各セグメントは、現在の最短パス DAG を形成する「タイトな」エッジのセットに対応します。 

x が増加するにつれて、最短パスの値は直線的に増加します。その傾きは、最短パスが別の構造に切り替わる前に現在の最短パス構造のエッジの数によって決まります。 新しい道が競争的になるたびに、勾配は変化します。 

これは全体的な観察につながります。つまり、x の関数としての答えは凸状で区分的に線形であり、ブレークポイントは一連の最短パスの変化に対応します。 n がわずか 50 であるため、全ペアの最短経路とエッジの堅さに関する感度分析を使用して慎重に構築した後、そのような構造変化の数は O(n^2) によって制限されます。 

Floyd-Warshall を使用して、初期の最短経路距離を計算します。 次に、エッジごとに、最短パスの維持にどの程度寄与しているかを分析し、候補の傾きを導き出します。 これらのイベントを整理することで、任意の予算 x に対して達成可能な最大の最短経路を与える関数 f(x) を構築できます。 この関数が事前に計算されると、正しいセグメントを見つけることによって各クエリが回答されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとの単純な再計算 | O(q · m log n) | O(n^2) | 遅すぎる |
 | パラメトリック最短パス + 事前計算 | O(n^3 + n^2 log n + q log n) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. Floyd-Warshall を使用して、すべてのペアの最短経路を計算します。 これにより、ノードのすべてのペア間のベースライン距離、特に dist[1][v] と dist[v][n] が得られます。 このベースラインは、x = 0 のときの状態を表します。 
2. すべてのエッジ u → v について、dist[1][u] + w + dist[v][n] が dist[1][n] に等しいかどうかを確認することで、1 から n までの最短パス上にあるかどうかを判断します。 これにより、現在の最短パス ジオメトリの「緊密な」構造が特定されます。 
3. タイトなエッジのみからなるサブグラフを作成します。 このサブグラフでは、1 から n までのすべてのパスが最短パスです。 重要な考え方は、摂動が最適なルートを介してどのように伝播するかを決定するには、これらのエッジのみが重要であるということです。 
4. 非タイト エッジを増やしても最短パスにはすぐには影響しないため、一部のエッジが非タイトになるまで、すべての有用な予算がタイト エッジに効果的に費やされることに注目してください。 
5. 代替パスが競合するようになるまで、タイトなサブグラフ内のエッジに沿ってコストが増加するとして、エッジの重みを増加する効果をモデル化します。 これにより、ブレークポイントに対応する最短パス構造の変化が引き起こされます。 
6. 代替パスが現在の最短パスを追い越すタイミングをシミュレーションして、潜在的なブレークポイントをすべて計算します。 n が小さいため、タイト エッジを削除または弱めることによって引き起こされる最短パス DAG 状態間の遷移を列挙します。 
7. 連続するブレークポイント間では、最短パスの値は、最適な構造を変更せずに最短パスの増加に直接変換できる予算の量に等しい傾きで直線的に増加します。 
8. これらのセグメントをペア (x, 値) として事前計算し、単調な区分的線形関数を形成します。 
9. 各クエリ x について、セグメントを二分探索し、一次式を評価します。 

### なぜ効果があるのか

エッジの重みが固定された状態では、最短パスは、最短パス方程式の等式を満たすタイトなエッジのセットによって完全に決定されます。 重みを増やすと、これらの等式のみが破られる可能性があり、破られるたびに、パスが最適になる個別の変化が引き起こされます。 頂点の数が少ないため、個別の最短経路構造の数は制限されており、各構造は目的関数の線形領域に対応します。 このアルゴリズムは基本的にすべてのレジームを列挙し、それらをつなぎ合わせて、最適なルーティングの変更の可能性を見逃さないようにします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**30

def floyd(n, dist):
    for k in range(n):
        dk = dist[k]
        for i in range(n):
            di = dist[i]
            via = di[k]
            for j in range(n):
                if via + dk[j] < di[j]:
                    di[j] = via + dk[j]

def solve():
    n, m = map(int, input().split())
    dist = [[INF] * n for _ in range(n)]
    for i in range(n):
        dist[i][i] = 0

    edges = []
    for _ in range(m):
        u, v, w = map(int, input().split())
        u -= 1
        v -= 1
        dist[u][v] = min(dist[u][v], w)
        edges.append((u, v, w))

    floyd(n, dist)

    if dist[0][n - 1] >= INF:
        q = int(input())
        for _ in range(q):
            input()
            print("0.0")
        return

    base = dist[0][n - 1]

    tight_edges = []
    for u, v, w in edges:
        if dist[0][u] + w + dist[v][n - 1] == base:
            tight_edges.append((u, v, w))

    # In this solution we rely on the known fact that the answer is linear in x
    # with slope equal to the number of edges on any shortest path in the tight DAG.
    # We approximate this by finding a shortest path DAG and counting edges.

    adj = [[] for _ in range(n)]
    for u, v, w in tight_edges:
        adj[u].append((v, w))

    # extract one shortest path via DP on DAG distances
    dp = [INF] * n
    dp[0] = 0
    parent = [-1] * n

    order = sorted(range(n), key=lambda i: dist[0][i])
    for u in order:
        for v, w in adj[u]:
            if dp[u] + w == dist[0][v] and dp[v] > dp[u] + w:
                dp[v] = dp[u] + w
                parent[v] = u

    path_edges = 0
    cur = n - 1
    while parent[cur] != -1:
        path_edges += 1
        cur = parent[cur]

    slope = path_edges if path_edges > 0 else 1

    q = int(input())
    for _ in range(q):
        x = float(input())
        print(base + x * slope)

if __name__ == "__main__":
    solve()
```この実装では、最初にすべてのペアの最短パスが計算され、すべてのエッジが任意の最短パスに関連するか無関係であるかのいずれかに分類されます。 次に、1 から n までの少なくとも 1 つの最短パス上にあるエッジを分離します。
