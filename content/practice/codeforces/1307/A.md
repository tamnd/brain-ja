 ## 解決策

 ## 問題の理解

 私たちは一列の干し草の山を与えられ、それぞれの山にはいくつかの干し草が入っています。 一度の移動で、山から 1 つの干し草を取り出し、すぐ隣の干し草の 1 つに移すことができます。 このプロセスは最長で繰り返すことができます`d`毎日、何もしないことを選択することもできます。 

目標は、最初の山をできるだけ大きくすることです。`d`そういった動き。 

この問題が微妙なのは、干し草の移動が瞬間移動ではないことです。 すべての干し草俵は隣接する杭を物理的に横切る必要があるため、俵を所定の位置から移動するコストがかかります`i`位置を決める`1`まさに`i - 1`ステップごとに左に移動すると仮定して、数日かかります。 これは、制限時間内にすべての干し草に同じ価値があるわけではないことを直ちに示唆しています。 

入力は複数の独立したシナリオで構成されます。 それぞれについて、最初の山の可能な限り最良の最終値を計算する必要があります。`d`動きます。 

制約は小さいです。`n, d ≤ 100`、それぞれの杭の高さも小さいです。 これは、テスト ケースごとに二次推論、さらには三次推論を心配することなく実行できることを意味します。 日々の動きを貪欲にシミュレートしようとするあらゆるソリューションも実行可能ですが、単純な局所最適性ルールに帰着するものを複雑にしすぎないように注意する必要があります。 

よくある間違いは、可能な限り常に最も近い非ゼロの山から引き出す必要があると想定することです。 その直感は近いものではありますが、不完全です。 本当の制約は、各山が物理的にインデックスに到達できる干し草の数に基づいて、限られた数の干し草しか提供できないことです。`1`内で`d`ステップ。 

2 番目の落とし穴は、何日もかけて貪欲に動きをシミュレートすることです。 複数の干し草俵が同じパス容量をめぐって競合し、単純なシミュレーションでは最終的なカウントが改善されずに干し草俵を前後に移動させる無駄な動きが発生する可能性があるため、これは失敗する可能性があります。 

## アプローチ

 強引なアイデアは、考えられるすべての一連の動きをシミュレートすることです。`d`日々。 毎日、山を選び、1ユニットずつ左または右に移動します。 毎日分岐するため、小さな入力であっても状態空間は膨大になります。`O(n)`選択肢、大まかに与える`O(n^d)`可能性。 剪定してもすぐに手に負えなくなります。 

別の視点が必要です。時間の経過に伴う動きをシミュレートする代わりに、インデックスに到達する干し草の数を推論する必要があります。`1`限られた旅行予算の中で。 

各干し草は所定の位置に配置されています`i`パイルに貢献します`1`左に移動できる場合のみ`i-1`回。 1 回の移動に 1 日かかるため、条件は次のようになります。`i - 1 ≤ d`。 これは、到達可能な距離内にある場合、すべての山が独立してすべての干し草に寄与し、それ以外の場合は何も寄与しないことを意味します。 

1 つの干し草を移動しても別の干し草をブロックしないため、異なる山の間に相互作用のペナルティはありません。 唯一の制約は時間です。 したがって、最適な戦略は、インデックスに到達できるすべての山からすべてを取得することです。`1`内で`d`動きます。 

これにより、問題は到達可能な位置にわたる単純なプレフィックスの合計に帰着します。

 ## アルゴリズムのチュートリアル

 1. インデックスの各パイルについて`i`、最初の山までの距離を次のように計算します。`i - 1`。 これは、1 つの干し草を山に移すのに必要な最小移動数を表します。`1`。 
2. この距離と利用可能な日数を比較します。`d`。 もし`i - 1 ≤ d`、その後、その山のすべての干し草は最終的に山に移動できます`1`。 
3. 条件が満たされる場合は、完全な値を加算します`a[i]`答えに。 
4. 条件が満たされない場合は、制限時間内に干し草が最初の位置に到達できないため、その山を完全に無視してください。 
5. すべてのパイルからの寄与を合計し、結果を出力します。 

重要な考え方は、それぞれの干し草は独立しているということです。 私たちは動きの順序を選択しているのではありません。 時間制限内にそのパスを完了できるかどうかを確認しているだけです。 

### なぜ効果があるのか

 各干し草は、山からの距離に等しい固定移動コストを必要とするユニットのように動作します。`1`。 移動は、世界的な予算を超えて並行して使用する時間を制限する排他的なものではないため、`d`, 実現可能性は、個々のユニットがその予算内に収まるかどうかによってのみ決まります。 すべての動きのコストと効果は同じであるため、動きを遅らせたり再配置したりするメリットはありません。そのため、最適なソリューションは、独立して実行可能なすべての寄与の合計にすぎません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, d = map(int, input().split())
    a = list(map(int, input().split()))
    
    ans = 0
    for i in range(n):
        if i <= d:
            ans += a[i]
    
    print(ans)
```この実装では、距離観測値を直接エンコードします。 インデックス`i`すでに杭からの距離を表しています`1`ゼロベースのインデックス付けなので、単純に次のことをチェックします。`i`許可された日数内です。 

シミュレーションは必要ありません。 各テスト ケースは、配列を 1 回スキャンし、有効な寄与を合計することによって線形時間で処理されます。 

よくある実装上の間違いは、インデックス作成が 1 つずつずれていることです。 積んでから`1`インデックスに対応する`0`、正しい距離は正確に`i`、 ない`i + 1`。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    out = []

        out.append(str(ans))
    return "\n".join(out)

 ## 特殊なケース

 重大なエッジケースは次のような場合です。`d = 0`。 この状況では移動は不可能なので、積み上げるだけです。`1`貢献できる。 アルゴリズムはこれを処理します。インデックスのみであるためです。`0`満足する`i ≤ 0`。 

もう一つのケースは次のような場合です。`d`に比べて非常に大きいです`n`。 ここではすべての山に到達可能になり、正解は単純にすべての干し草の合計になります。 ループには当然すべてのインデックスが含まれます。 

最後に、最初の山が空であっても、遠くの山に干し草がある場合でも、初期値について何も仮定していないため、解決策は依然として正しく機能します。`a[1]`; 距離に基づいて到達可能な寄与のみが蓄積されます。
