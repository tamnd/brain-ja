 ## 解決策
 ## 問題の理解

 道路によって接続されたフィールドを表す、無向接続グラフが与えられます。 旅行者はノード 1 から出発し、最短ルートを使用してノード n に到達したいと考えています。 既存のネットワーク上に、新しい無向エッジを 1 つだけ追加できますが、この新しいエッジの両方のエンドポイントは、特定の特別なノードのセットから選択する必要があるという制限があります。 

この 1 つのエッジを追加すると、グラフが変化し、1 から n までの最短パス距離が減少するか、変わらない可能性があります。 私たちの仕事は、この最終的な最短パスができるだけ大きくなるような方法で、追加されたエッジを選択することです。 

修正を加えた後の最短パスを見つけようとしているわけではないので、問題の構造は微妙です。 代わりに、最終的な最短経路を可能な限り悪くする変更自体を選択しています。 

制約により、線形または線形に近いグラフ処理に関する解決策が強制されます。 最大 200,000 のノードとエッジを使用すると、最短パスを再計算するアプローチ (候補エッジごとに BFS またはダイクストラを実行するなど) は遅すぎます。 k が最大 n になる可能性もあり、O(n^2) 個の可能性があるため、特別なノードのすべてのペアを試してみることさえ不可能です。 

いくつかの重要なエッジケースは、素朴な思考が失敗する理由を明らかにします。 1 と n がすでに一意の最短パスで接続されており、すべての特別なノードがそこから遠く離れたところにある場合、それらの間にエッジを追加しても何も変わらない可能性があります。 一方、特別なノードが最短パスに沿って、またはその近くにある場合、追加されたエッジによってグラフの大部分をバイパスする強力なショートカットが作成され、予期しない方法で距離が大幅に短縮される可能性があります。 

もう 1 つの注意が必要な状況は、1 から n までの複数の最短パスが存在する場合に発生します。 素朴なアプローチでは、ブロックする必要があるのは 1 つのパスのみであると想定されるかもしれませんが、実際には、追加されたエッジによって、元の最短パス ツリーの一部ではなかった、まったく新しい短いルートが作成される可能性があります。 

## アプローチ

 ブルートフォースのアイデアは簡単です。特殊ノードの考えられるすべてのペアを試し、それらの間にエッジを追加し、BFS を使用して 1 から n までの最短パスを再計算します (エッジは重み付けされていないため)。 これは問題ステートメントを直接シミュレートしているため、これは正しいです。 

しかし、これはすぐに実行不可能になります。 最大 k 個の特殊ノードがあるため、k² 個のエッジが考えられます。 各エッジについて、200,000 ノードのグラフにわたる BFS の再計算には O(n + m) のコストがかかります。 合計の複雑さは O(k² (n + m)) となり、最悪の場合は天文学的に大きくなり、通過できなくなります。 

重要な点は、追加されたすべてのエッジを実際にシミュレートする必要はないということです。 代わりに、追加された 1 つのエッジが最短パスにどのような影響を与えるかを理解する必要があります。 

distA[v] をノード 1 から v までの最短距離、distB[v] を v から n までの最短距離とする。 これらは 2 回の BFS 実行で計算できます。 

次に、2 つの特別なノード u と v の間にエッジを追加することを考えます。このエッジを使用する 1 から n へのパスは次の形式になります。1 から u に移動し、新しいエッジを v に移動し、次に v から n に移動するか、その逆の方向に移動します。 これにより、次の候補パス長が得られます。 

distA[u] + 1 + distB[v]

 または対称的に

 distA[v] + 1 + distB[u]

 したがって、選択したエッジからの最良の改善は、完全にこれらの距離値によって決まります。 

問題は、エッジを追加した後の最短パスを最大化するために 2 つの特別なノード u および v を選択することです。 エッジの追加は最短パスを減少または維持することしかできないため、最短パスの改善を最小限に抑えるペアを選択する必要があります。つまり、distA が小さく、distB が小さい領域間に強力なショートカットを作成することは避けたいと考えています。 

これは、distA によって特別なノードをソートし、distB 値に対する 2 ポインターまたはプレフィックス最大戦略を使用して可能な限り最良の組み合わせを追跡しながら、それらを貪欲にペアリングすることになります。

ソリューションのロックを解除する構造は、特別なノード間の唯一の意味のある相互作用がそれらの (distA、distB) ペアを介するものであることを認識することです。 最短距離を前処理するとグラフ自体が消えてしまいます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(k² (n + m)) | O(n + m) | 遅すぎる |
 | 最適 | O(n + m + k log k) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 グラフ問題を 2 つの距離の最適化問題に変換します。 

1. ノード 1 から BFS を実行して、すべてのノード v の distA[v] を計算します。 

これは、各ノードが開始から最短ルートに沿ってどのくらい早く表示されるかをキャプチャします。 
2. ノード n から BFS を実行して、すべてのノード v の distB[v] を計算します。 

これは、各ノードが目的地にどれだけ近いかを捕捉します。 
3. 特別なノードごとに、ペア (distA[s]、distB[s]) を構築します。 

これにより、すべてのグラフ構造が特別なノードごとに 2 つのスカラー値に圧縮されます。 
4. 特殊ノードを distA で昇順にソートします。 

この順序付けは、最初からどれだけ早くノードに到達できるかによってノードを整列させます。これは、初期ノードと後期ノード間の相互影響を推論するために重要です。 
5. これまでに確認された最大 distB 値を維持しながら、ソートされたリストをスイープします。 

各位置 i で、ノード i を以前のノード j とペアにすることを検討します。 最良の候補は、パスの後半を最大化するため、前のノードの中で最大の distB によって制御されます。 
6. 分割点ごとに、以下を使用して答えの候補を計算します。 

i より前の j の distA[j] + 1 + distB[i]

 可能な最大の最短パスを追跡します。 
7. 最終的な答えは、元の最短パス distA[n] とエッジの追加後に得られた最良の値の間の最小値です。 

これが機能する理由は、追加された最適なエッジでは、distA と distB に関して極端な位置にある特別なノード間の端点のみを考慮する必要があるためです。 ソートにより、明示的に試行することなく、構造的に関連するすべてのペアを確実に検査できます。 

### なぜ効果があるのか

 新しいエッジを使用するすべての最短パスは、そのエッジによって接続された 2 つの独立した最短パス セグメントに分解されます。 コストは、エンドポイントの distA および distB の値によって完全に決定されます。 これらの距離は元のグラフ内のすべての最適なルートをすでにエンコードしているため、追加の構造情報は必要ありません。 

distA でソートすることで、ノードを 2 番目のエンドポイントとみなすときに、結合された式を最大化できるすべての有効な最初のエンドポイントがすでに処理されていることを確認します。 distB に対して最大値が維持されるため、常に最良の補完パートナーをテストすることが保証されます。 

これにより、1 つの追加エッジを使用するすべての最適パス候補がスイープ内で 1 回だけ表現されることが保証されます。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def bfs(start, n, adj):
    dist = [10**18] * (n + 1)
    q = deque([start])
    dist[start] = 0
    while q:
        v = q.popleft()
        for to in adj[v]:
            if dist[to] == 10**18:
                dist[to] = dist[v] + 1
                q.append(to)
    return dist

def solve():
    n, m, k = map(int, input().split())
    special = list(map(int, input().split()))

    adj = [[] for _ in range(n + 1)]
    for _ in range(m):
        a, b = map(int, input().split())
        adj[a].append(b)
        adj[b].append(a)

    distA = bfs(1, n, adj)
    distB = bfs(n, n, adj)

    base = distA[n]

    pts = [(distA[s], distB[s]) for s in special]
    pts.sort()

    best = 0
    max_db = -10**18

    for da, db in pts:
        if max_db != -10**18:
            best = max(best, da + 1 + max_db)
        max_db = max(max_db, db)

    print(min(base, best))

if __name__ == "__main__":
    solve()
```BFS セクションは、重み付けされていないグラフにおける標準の最短パス前処理です。 これを 2 回実行すると、グラフ検索を再実行することなく、追加されたエッジの候補を評価するために必要なすべての距離が得られます。 

核となる圧縮ステップは、特別なノードの (distA, distB) ペアの構築です。 これが完了すると、グラフは直接使用されなくなります。 

スイープ ロジックは、並べ替えられたリストの左側で可能な限り最良のパートナーを維持することに依存しています。 変数`max_db`処理されたノード間で最大の distance-to-n が格納されます。これは、パス式の後半を最大化することに対応します。 

最後に、元の最短パスと比較します。これは、追加されたエッジは事実上オプションであり、最短距離を増やす方法で最適パスを改善できない可能性があるためです。 

## 実用的な例

 ### 例 1

 入力:```
5 5 3
1 3 5
1 2
2 3
3 4
3 5
2 4
```距離を計算します。 

| ノード | distA (1から) | distB (5 から) |
 | --- | --- | --- |
 | 1 | 0 | 3 |
 | 3 | 2 | 1 |
 | 5 | 3 | 0 |

 特別なノードは次のようになります。 

(0,3)、(2,1)、(3,0)

 distA で並べ替え:

 (0,3)、(2,1)、(3,0)

 スイープ:

 | ステップ | ノード | 最大データベース | 候補者 |
 | --- | --- | --- | --- |
 | 1 | (0,3) | 3 | なし |
 | 2 | (2,1) | 3 | 2 + 1 + 3 = 6 |
 | 3 | (3,0) | 3 | 3 + 1 + 3 = 7 |

 最良 = 7、元の距離 = 3、答え = 3。 

トレースは、特別なノードを通る大きな候補パスが存在するにもかかわらず、元のボトルネックを超えて実際の最短パスを改善しないことを示しています。 

### 例 2

 単純な折れ線グラフ:```
1 - 2 - 3 - 4 - 5
special: 2, 4
```距離:

 | ノード | 距離 | 距離B |
 | --- | --- | --- |
 | 2 | 1 | 3 |
 | 4 | 3 | 1 |

 エッジ経由の候補 (2,4):

 1 → 2 → 4 → 5 は 1 + 1 + 1 = 3 となります。 

本来の最短経路は4なので、答えは3になります。 

これは、追加されたエッジが最短パスのみを削減し、アルゴリズムが最適な削減を正確に捕捉する方法を示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + m + k log k) | 2 つの BFS 実行は O(n + m) を支配し、特別なノードのソートコストは O(k log k)、スイープは線形です。 
| スペース | O(n + m) | 隣接リストと距離配列 |

 この制約では最大 200,000 のノードとエッジが許可されるため、線形 BFS が不可欠です。 ソート ステップは制限内に十分収まる程度に小さいため、エッジごとの再計算は実行されません。

    from collections import deque

    def bfs(start, n, adj):
        dist = [10**18] * (n + 1)
        q = deque([start])
        dist[start] = 0
        while q:
            v = q.popleft()
            for to in adj[v]:
                if dist[to] == 10**18:
                    dist[to] = dist[v] + 1
                    q.append(to)
        return dist

    def solve():
        n, m, k = map(int, sys.stdin.readline().split())
        special = list(map(int, sys.stdin.readline().split()))
        adj = [[] for _ in range(n + 1)]
        for _ in range(m):
            a, b = map(int, sys.stdin.readline().split())
            adj[a].append(b)
            adj[b].append(a)

        distA = bfs(1, n, adj)
        distB = bfs(n, n, adj)

        base = distA[n]

        pts = [(distA[s], distB[s]) for s in special]

            if max_db != -10**18:
                best = max(best, da + 1 + max_db)
            max_db = max(max_db, db)

        return str(min(base, best))

    return solve()

 ## 特殊なケース

 重要なエッジ ケースは、エッジを追加した後でも最適な答えが変わらない場合です。 その場合、すべての候補式 distA[u] + 1 + distB[v] は元の最短パスよりも大きくなり、最終的な最短パスは`min(base, best)`より大きな値を誤って報告しないようにします。 

もう 1 つのケースは、特別なノード自体に 1 または n が含まれる場合です。 その後、distA または distB はゼロになり、これらのノードとのペアリングは境界で始まるパスまたは境界で終わるパスを直接反映するため、スイープはそれを正しく処理します。
