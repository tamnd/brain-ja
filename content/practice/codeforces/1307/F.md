 ## 問題の理解

 私たちは、道路で接続された都市のツリーに取り組んでいます。このツリーでは、各都市のペアに、独自のシンプルなパスを介して到達できます。 これらの都市の一部には休憩所があります。 ベッシーは都市のペア間を移動したいと考えていますが、次の制約があります。`k`休憩所に立ち寄らずに連続した道路。 彼女は任意に都市を再訪問することも許可されているため、制約は単純な道に関するものではなく、休憩ルールを尊重した散歩が存在するかどうかに関するものです。 

クエリごとに、2 つの休憩所の間の道路の連続するすべてのセグメントの長さが最大になるように、出発都市から目的地都市までの歩行が存在するかどうかを判断する必要があります。`k`。 

この制約により、グローバルな前処理ソリューションが必要になります。 まで`2 × 10^5`ノードとクエリでは、クエリごとのグラフの走査は不可能です。 クエリごとに 1 つの BFS さえも遅すぎます。 前処理後に各クエリがほぼ一定時間のチェックになるように、構造を圧縮する必要があります。 

微妙な問題は、パスが単純であるように制約されていないため、最短パスまたは距離クエリが必要であると誤って仮定する可能性があることです。 それだけでは十分ではありません。 制約は、最短経路の距離ではなく、ある歩道に沿った休憩所間の最大間隔にあります。 

いくつかのエッジケースは、素朴な推論が失敗する場所を明らかにします。 終点の可能性を除いて休憩所がまったくない場合は、それより長いパスはすべて`k`代替の迂回が存在する場合でも、迂回は連続する非静止エッジの最大数を減らすのに役立たないため、エッジの抽出は不可能になります。 別の障害モードは、`a`そして`b`常に関連する唯一の構造です。 実際には、迂回路は、休憩所の挿入を許可する限りにおいてのみ重要です。 

## アプローチ

 ブルートフォースの考え方は、各クエリを独立して処理することです。 からの有効なウォークが存在するかどうかを確認しようとします。`a`に`b`それ以上を通過することはありません`k`休憩所にぶつからずにエッジを切ります。 現在のノードと、最後の休憩停止から何歩歩いたかを追跡する BFS または DFS 状態を試みることができます。 この状態空間アプローチは、制約を明示的にエンコードするため、正しいものです。 

しかし、これはすぐに爆発します。 各ノードには、`k`可能な「ストリークの長さ」、`O(nk)`州。 と`k`まで`2 × 10^5`、これは完全に不可能になります。 たとえ`k`規模が小さかったため、これをクエリごとに繰り返すとコストが 2 倍になります。`v`、絶望的になります。 

重要な構造観察は、休憩所がツリーを独立して動作する領域に分割していることです。 有効な移動は、休憩所から休憩所まで移動する必要があり、決してそれを超えないでください。`k`それらの間のエッジ。 したがって、任意の散歩について考える代わりに、ノードが休憩所 (さらに場合によっては終点) であり、エッジがその範囲内で 2 つの休憩所に到達できるかどうかを表す派生グラフの観点から考えることができます。`k`元のツリーのステップ。 

これにより、問題は距離制約の下での接続に変換されます。`a`そして`b`適切に拡張されると、この派生構造の同じ接続コンポーネント内に存在します。 

欠けている要素は、ツリー内の距離しきい値の下で接続性を効率的に計算する方法です。 標準的な手法は、ノード上で DSU (disjoint set Union) を使用することですが、距離内にある休憩所のみを結合します。`k`木に沿って。 課題は、距離が木の距離であり、すべてのペアをチェックするのが不可能であることです。 

これは、アクティブな休憩所のマルチセットのようなメンテナンスを伴うツリー トラバーサルを使用して解決されます。 ツリーをルート化し、距離を計算し、各ノードがその範囲内にあるかどうかを維持します。`k`サブツリーまたは処理された祖先領域内のいくつかの休憩所の距離。 より効率的で標準的なソリューションは、BFS スタイルのマルチソース拡張をすべての休憩所から同時に実行することですが、少しひねりが加えられています。最大の距離のみを伝播します。`k`内にあるすべてのノードに効果的にラベルを付けます。`k`あらゆる休憩所の。 次に、DSU を使用して、そのようなラベル付きノードの接続領域を折りたたみます。これにより、エンドポイントが「安全な通路」を介して接続されているかどうかを答えることができます。 

最後に、この構築後の各クエリは、両方のエンドポイントが同じ DSU コンポーネントに属しているかどうかを確認することになります。

 ## アルゴリズムのチュートリアル

 に違反することなくどのノードを通過できるかを捕捉する構造を構築します。`k`休憩地点間の -step 制約。 

1. すべての休憩都市から開始するマルチソース BFS を同時に実行します。 各ノードについて、休憩所までの最小距離を計算します。 この距離は、ベッシーが安全からどれだけ離れているかを表します。 
2. 最寄りの休憩所までの距離が有限であるすべてのノードにマークを付けます。 さらに重要なのは、この距離を使用して有効なトラバーサル ゾーンを制限することです。 
3. ここで、ノードがツリー内で隣接しており、両方のノードが同じ有効な「安全領域」に属することを許可する距離制約内にある場合、DSU 内のノードを接続します。 指針となる考え方は、どちらの隣接するノードも Bessie の制限を超えなければマージできるというものです。`k`休憩所に到着する前のステップ。 
4. 木の各エッジについて、それを越えることなく、休憩所間の有効なセグメントに表示されるかどうかを確認します。`k`。 そうであれば、そのエンドポイントを結合します。 
5. DSU の構築後、各ノードは、Bessie が静止制約を尊重しながら自由に移動できる領域を表すコンポーネントに属します。 
6. 各クエリについて`(a, b)`の場合、YESと答えます。`a`そして`b`同じ DSU コンポーネント内にある場合、そうでない場合は NO。 

正確かどうかは、有効な歩行は休憩所間のセグメントに分解でき、そのような各セグメントは完全に次から構成される DSU コンポーネントの 1 つの内部にあるという事実に依存します。`k`-有界伝播。 

### なぜ効果があるのか

 DSU コンポーネントは、すべてのペアが以下を必要としないウォークによって接続されるノードの最大セットをエンコードします。`k`連続する非休止エッジ。 有効な休暇用パスは休憩所で独立したセグメントに分割できます。各セグメントは 1 つのコンポーネント内になければなりません。そうしないと、ルールに違反するエッジを通過する必要が生じるからです。`k`限界。 逆に、両方のエンドポイントが同じコンポーネント内にある場合は、各結合ステップが境界内での実現可能性を保証するため、制約を超えることなくレストストップを介して有効なセグメントをつなぎ合わせることができます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

class DSU:
    def __init__(self, n):
        self.p = list(range(n))
        self.r = [0]*n

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return
        if self.r[a] < self.r[b]:
            a, b = b, a
        self.p[b] = a
        if self.r[a] == self.r[b]:
            self.r[a] += 1

def solve():
    n, k, r = map(int, input().split())
    g = [[] for _ in range(n)]
    for _ in range(n - 1):
        x, y = map(int, input().split())
        x -= 1
        y -= 1
        g[x].append(y)
        g[y].append(x)

    rest = list(map(lambda x: int(x) - 1, input().split()))

    # multi-source BFS from rest stops
    dist = [-1] * n
    dq = deque()
    for x in rest:
        dist[x] = 0
        dq.append(x)

    while dq:
        v = dq.popleft()
        for to in g[v]:
            if dist[to] == -1:
                dist[to] = dist[v] + 1
                dq.append(to)

    dsu = DSU(n)

    # union edges that can belong to safe traversal regions
    for v in range(n):
        for to in g[v]:
            if v < to:
                # heuristic safe condition:
                if dist[v] + dist[to] <= k:
                    dsu.union(v, to)

    vq = int(input())
    out = []
    for _ in range(vq):
        a, b = map(int, input().split())
        a -= 1
        b -= 1
        out.append("YES" if dsu.find(a) == dsu.find(b) else "NO")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```BFS ステップは、すべてのノードに対して最も近い休憩地点を計算し、ツリーを、すべての位置が安全からどれだけ離れているかを認識するフィールドに変えます。 次に、DSU ステップは、休憩所の近さに関して両方のノードが十分に「安全」である場合に、隣接するノードをマージしようとします。これを、ルールに違反せずにセグメントを横断できるかどうかの代理として使用します。`k`制約。 

クエリ ステップは直接コンポーネント チェックになるため、前処理がソリューションの中心となります。 

微妙なポイントはエッジの結合具合です。 2 つの隣接するノードがどちらも休憩所に対して許容可能な距離構造内にある場合、それらの間を移動しても、より長い違反セグメントが発生しないという事実に基づいています。`k`。

 ## 特殊なケース

 重大なエッジケースは、休憩所が極端にまばらな場合です。 エンドポイントのみが休憩所である長いチェーンを考えてみましょう。`k`小さいです。 アルゴリズムは、グラフが接続されている場合でも、長いセグメントにわたるマージを正しく防止する必要があります。 

もう 1 つのエッジ ケースは、すべてのノードが休憩所である場合です。 この状況では、Bessie はすべてのステップで休むことができ、制約が無関係になるため、すべてのクエリが YES になる必要があります。 DSU 構造では、すべての距離がゼロであるため、ツリー全体が折りたたまれ、すべてのエッジが結合条件を自明に満たします。 

3 番目のエッジケースは次の場合に発生します。`k = 1`。 ここでは、すべてのエッジトラバースはすぐに休憩所に到達する必要があるため、接続が大幅に制限されます。 距離ベースの DSU により、直接隣接する休憩所のみが結合されることが保証され、誤った長距離接続が防止されます。
