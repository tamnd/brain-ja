 ## 解決策
 ## 問題の理解

 英小文字の文字列が与えられます。 メッセージは、選択されたインデックスが等差数列を形成する任意のサブシーケンスです。 進行には、長さ 1 の特殊な場合を含め、任意の正の差を含めることができます。 

タスクはメッセージ自体を見つけることではありません。 代わりに、最も頻繁に表示される隠しメッセージが何回表示されるかを判断する必要があります。 

一見すると、これは等差数列を伴う部分数列の問題のように見え、何か複雑なことを示唆しています。 重要な観察は、文字列の ID ではなく、すべての非表示文字列の最大頻度のみが必要であるということです。 

文字列の長さは次のとおりです$10^5$。 等差数列、部分列、または候補メッセージを明示的に列挙する解決策は、直ちに不可能です。 平$O(n^2)$大きすぎます。 線形時間に近いものが必要です。 

いくつかの特殊なケースは見落とされがちです。 

考慮する：```
a
```唯一の隠されたメッセージは、`"a"`、これは 1 回発生します。 答えは次のとおりです。```
1
```長さが 2 以上のメッセージのみをカウントするソリューションでは、誤ってゼロが返されます。 

考慮する：```
aaaa
```メッセージ`"a"`4回発生します。 メッセージ`"aa"`発生する$\binom{4}{2}=6$回。 答えは次のとおりです。```
6
```1 文字だけを追跡するソリューションでは、2 文字のメッセージがより頻繁に発生する可能性があることを見逃してしまいます。 

考慮する：```
abab
```メッセージ`"ab"`4 回発生します:$$(1,2),(1,4),(3,4),(3,2\text{ is invalid because order matters})$$より体系的に、より早い段階で`a`後ですべてとペアリングできます`b`。 答えは、必ずしも等しい文字ではなく、順序付けられた文字のペアから得られます。 

重要な教訓は、最大頻度は 1 文字の文字列または 2 文字の文字列から得られる可能性があるということです。 

## アプローチ

 ブルートフォース手法では、隠されたメッセージを列挙し、その出現数をカウントしようとします。 等差数列に限定しても役に立ちません。 指数関数的に多くの部分列があり、一定の長さの文字列内の等差数列の数は$10^5$巨大です。 これはまったく実現不可能です。 

突破口は、問題の中に隠された定理を理解することから生まれます。 

隠しメッセージの長さが少なくとも 3 であると仮定します。 そのメッセージが出現するたびに、最初の文字と最後の文字が含まれます。 中央の文字を忘れた場合、各出現箇所は、それらのエンドポイントによって形成される 2 文字のメッセージの出現箇所にマップされます。 

このマッピングは単射的です。 長いメッセージが異なると、異なるエンドポイントのペアが生成されます。 つまり、少なくとも 3 文字の長さのメッセージの出現数は、2 文字のメッセージの出現数を超えることはできません。 

その結果、最も頻繁に表示される隠しメッセージは長さ 1 または長さ 2 でなければなりません。 

問題ははるかに単純になります。 

長さ 1 の場合、必要なのは各文字の頻度だけです。 

長さ 2 の場合、順序付けされた文字のペアごとにカウントする必要があります。$(a,b)$、インデックスのペアは何組ですか$i<j$満足する：$$s_i=a,\quad s_j=b.$$小文字は 26 個しかないので、$26^2=676$注文したペア。 

文字列を左から右に処理できます。 キャラクターを見るとき$c$、以前に見たすべてのキャラクター$x$ペアの新しいオカレンスを作成します$(x,c)$。 

これにより、線形時間の解決策が得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | 指数 | 遅すぎる |
 | 最適 |$O(26n)$|$O(26^2)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を維持する`cnt[26]`どこ`cnt[x]`文字の回数です`x`これまで登場してきました。 
2. マトリックスを維持する`pairs[26][26]`どこ`pairs[x][y]`文字で構成される 2 文字のメッセージの出現回数を格納します。`x`続いて手紙`y`。 
3. 文字列を左から右にスキャンします。 
4. 現在のキャラクターが`c`。 
5. すべての文字について`x`から`a`に`z`、 追加`cnt[x]`に`pairs[x][c]`。 

これまでに発生したすべての`x`現在発生しているものと組み合わせることができます`c`、メッセージが 1 つ新しく発生します`xc`。 
6.増加`cnt[c]`1つずつ。 
7. 文字列全体を処理した後の答えは、次のすべてのエントリの最大値になります。`cnt`およびすべてのエントリ`pairs`。 

### なぜ効果があるのか

 1文字のメッセージの場合は、`cnt[c]`は、まさにそのメッセージの発生数です。 

2 文字のメッセージの場合、有効な出現箇所はすべて位置のペアに対応します。$i<j$。 位置決め時$j$処理される、位置$i$すでに内部でカウントされています`cnt`。 このアルゴリズムは、そのペアの寄与を 1 つだけ追加し、それを再度カウントすることはありません。 

残りの疑問は、なぜ長いメッセージが無視できるのかということです。 メッセージを送りましょう$t$文字で始まる少なくとも 3 つの長さ$a$そして手紙で終わる$b$。 あらゆる出来事が起こる$t$2 文字のメッセージの一意の出現を決定します$ab$最初と最後に選択した位置を使用します。 特有の現象$t$異なるエンドポイントのペアを生成します。 したがって、次のようになります。$$\text{occurrences}(t) \le \text{occurrences}(ab).$$したがって、少なくとも 3 文字の長さのメッセージは、最高の 1 文字または 2 文字のメッセージに勝るものはありません。 アルゴリズムはそのような候補をすべてチェックするため、返される最大値が正解になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

s = input().strip()

cnt = [0] * 26
pairs = [[0] * 26 for _ in range(26)]

for ch in s:
    c = ord(ch) - ord('a')

    for x in range(26):
        pairs[x][c] += cnt[x]

    cnt[c] += 1

ans = max(cnt)

for i in range(26):
    for j in range(26):
        ans = max(ans, pairs[i][j])

print(ans)
```配列`cnt`すべての 1 文字のメッセージを追跡します。 マトリックス`pairs`すべての 2 文字のメッセージを追跡します。 

更新順序は重要です。 最初に以前に見たキャラクターからの寄与を追加し、その後でのみ現在のキャラクターのカウントをインクリメントする必要があります。 そうしないと、文字が同じ位置で誤ってそれ自体とペアになる可能性があります。 

すべてのカウントは 64 ビット整数内に快適に収まります。 最悪の場合、次のような 2 文字のメッセージが表示される可能性があります。$$\binom{10^5}{2} \approx 5 \times 10^9,$$これは 32 ビットの制限をはるかに超えています。 Python の整数はこれを自動的に処理します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(26n)$| 文字ごとに、26 文字すべてを繰り返し処理します。 
| スペース |$O(26^2)$| ペア数行列には 676 個のエントリがあります。 

以来$26$が定数である場合、実行時間は文字列の長さに対して実質的に線形になります。 のために$n=10^5$、アルゴリズムは約 260 万回の更新を実行しますが、これは制限内に簡単に収まります。 

## テストケース```python
# helper: run solution on input string, return output string
import io
import sys

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    s = sys.stdin.readline().strip()

    cnt = [0] * 26
    pairs = [[0] * 26 for _ in range(26)

    ]

    for ch in s:
        c = ord(ch) - ord('a')

        for x in range(26):
            pairs[x][c] += cnt[x]

        cnt[c] += 1

    ans = max(cnt)

    for i in range(26):
        for j in range(26):
            ans = max(ans, pairs[i][j])

    return str(ans)

# provided sample

# minimum size
assert solve("a\n") == "1"

# all equal
assert solve("aaaa\n") == "6"

# distinct letters
assert solve("abc\n") == "1"

# alternating pattern
assert solve("abab\n") == "3"

# large repetition structure
assert solve("aabb\n") == "4"

 ## 特殊なケース

 次のことを考慮してください。```
a
```配列`cnt`になる`[1,0,...]`。 ペア数は作成されません。 最大値は 1 ですが、これは正しいです。 

考慮する：```
aaaa
```更新により以下が生成されます。$$pairs[a][a] = 1+2+3 = 6.$$単一文字の数は 4 つだけです。アルゴリズムは正しく 6 を返します。 

次のことを考慮してください。```
abab
```2番目のとき`b`処理されていますが、すでに 2 つあります`a`その前に 2 つの新しい文字があるので、`ab`出現箇所が追加されます。 最終的な値は、`pairs[a][b]`は 3 になり、次のペアに対応します。$$(1,2),\ (1,4),\ (3,4).$$このアルゴリズムは、有効な順序付きペアをそれぞれ 1 回だけカウントします。 

考慮する：```
abcdefghijklmnopqrstuvwxyz
```どのキャラクターも一度ずつ登場します。 2 文字のメッセージはすべて最大 1 回表示されます。 保存されているすべての値の最大値は 1 のままで、これが正解です。
