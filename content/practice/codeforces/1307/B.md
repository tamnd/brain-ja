 ## 解決策
 ## 問題の理解

 ウサギは飛行機の原点から出発し、その点に正確に着陸したいと考えています$(x, 0)$。 彼は一連のジャンプを行うことで移動し、各ジャンプは任意の方向を指定できますが、その長さは入力で指定された許容値のいずれかに一致する必要があります。 同じジャンプ長は何度でも再利用できます。 

タスクは、ウサギが X 軸上の目標点で正確に終了できるように、必要なジャンプの最小数を決定することです。 

重要な難点は、目的地は直線上にあるにもかかわらず、ウサギは 2 次元で移動できることです。 これは、中間ステップで垂直方向の変位を「無駄に」し、後で修正できることを意味します。これにより、問題は単純な 1D 演算ではなく、根本的にベクトルの加算に関するものになります。 

制約は、$O(n)$すべてのテスト ケースで許可されるジャンプ長の合計数は最大でもテスト ケース ソリューションごとに最大です。$10^5$。 ジャンプの組み合わせをシミュレートしたり、ジオメトリを明示的に探索しようとするアプローチは、考えられるシーケンスの数が答えとともに指数関数的に増加するため、遅すぎます。 

素朴な間違いは、常に最大のジャンプを繰り返し使用するか、貪欲に分解することが最善の戦略であると考えることです。$x$許容される長さの合計として。 これは、方向の自由により、複数の短いジャンプを組み合わせてより長い正味変位が可能になるため、失敗します。 

たとえば、許可される長さが次の場合、$[1, 3]$そして$x = 4$、貪欲なら提案します$3 + 1$しかし、最適な解決策は、長さ 3 の 2 つのジャンプで、水平方向の投影の合計が正確に 4 になるような角度で配置されます。 

もう 1 つの微妙な失敗例は、単一ジャンプの使用が可能であるのは、$a_i = x$。 2 つ以上のベクトル ステップにより、以下に等しい直線変位が形成される可能性があるため、これは不正確です。$x$たとえ単一のジャンプがそれに匹敵しないとしても。 

問題は、ライン上で目標の合成振幅を達成するために、指定された長さのベクトルがいくつ必要かという推論に帰着します。 

## アプローチ

 強引なアイデアは、許容される各長さをベクトルとして扱い、ある深さまでの可能なジャンプのシーケンスをすべて試してみることです。$k$、ターゲットが形成できるかどうかを確認します。 各ステップでは、次のいずれかを選択します。$n$長さと方向の角度により、状態空間が連続的かつ無限になります。 離散化しても組み合わせの数はおおよそ次のように増えます。$n^k$、非常に小さいものでも管理できなくなります$k$。 このアプローチはすぐに実行不可能になります。 

重要な観察は、実際には個々の方向を気にするのではなく、各ジャンプが X 軸に到達するためにどの程度の「正味変位能力」に寄与するかだけを気にするということです。 長さのジャンプ$a$せいぜい貢献できる$a$x 方向に、そして異なる角度で複数のジャンプを組み合わせることで、水平方向の寄与を最大化しながら垂直方向の成分が相殺されるように常にジャンプを配置することができます。 

本質的な単純化は、最適な戦略は常に、合計 (使用可能な最大投影として) がカバーできる長さのサブセットを選択するように効果的に動作する方法でジャンプを使用することです。$x$ただし、最大ジャンプまでに残った不一致は、多くのジャンプではなく 2 つのジャンプを使用して修正できるという幾何学的事実が追加されています。 

これは古典的な構造につながります。つまり、単一のジャンプが必要な場合は、$a_i = x$、そうでない場合は、問題をカバーすることに縮小します。$x$各セグメントが利用可能な最大のジャンプに寄与できるセグメントを使用します。 と表すと$M = \max(a_i)$、その場合、各ジャンプは最大で貢献します$M$最適な配置で水平方向に進むため、少なくとも$\lceil x / M \rceil$ジャンプします。 ただし、2 番目に大きなジャンプを使用すると、オーバーシュートの非効率性が軽減される可能性があるため、これは常に厳しいわけではありません。 正確な最適解は、次の条件にのみ依存することがわかります。$x$割り切れるか、最大 2 つのジャンプを使用して正確に表現できます。 正しく単純化すると、答えは常に次のようになります。 

- あれば 1$a_i = x$- さもないと$\left\lceil \frac{x}{\max(a_i)} \right\rceil$、ただし、次のように調整されています$x \le 2 \cdot \max(a_i)$、答えは 2 です (三角形ジオメトリを使用して最大長の 2 倍までの変位を構築するには、常に 2 つのジャンプで十分であるため)。 

これにより、利用可能な最大のジャンプに基づいて直接的な貪欲な分類が得られます。

 ## アルゴリズムのチュートリアル

 1. 許可されているすべてのジャンプ長を読み取り、最大値を特定します。$M$。 この値は、あらゆる方向における最も強力な 1 ステップ変位能力を表します。 
2. 許可された長さがターゲットと等しいかどうかを確認します。$x$。 そうであれば、単一のジャンプを X 軸に沿って直接方向付けることで目的地に正確に到達できるため、答えはすぐに 1 になります。 
3. シングルジャンプが一致しない場合$x$、2回のジャンプで十分かどうかを検討してください。 最大 2 つの長さのベクトル$M$それらの結果が半径の円盤内のどこにでも収まるように常に配置できます。$2M$、任意のターゲット距離を意味します$x \le 2M$正確に 2 つのステップで達成できます。 
4. もし$x > 2M$の場合、最適に調整されたジャンプでも、それより短い時間で距離をカバーすることはできません。$\lceil x / M \rceil$ステップ、各ステップが貢献できるのはせいぜい$M$正味の水平的進歩。 
5. これらのケースに基づいて計算された最小値を返します。 

### なぜ効果があるのか

 各ジャンプはベクトルであり、最終的な変位への寄与はその長さによって制限されます。 1 回の移動あたりの希望の方向への最大の寄与は次のとおりです。$M$、およびジオメトリは、半径内の結果を実現するために 2 つのベクトルを常に方向付けることができることを保証します。$2M$。 これにより、タイトなパーティションが作成されます。ターゲットは次のとおりです。$2M$最大でも 2 回のジャンプが必要で、より大きなターゲットでは最大効率のジャンプを積み重ねる必要があるため、$\lceil x/M \rceil$避けられない。 いかなる代替配置もこれらの幾何学的境界を超えることはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, x = map(int, input().split())
        a = list(map(int, input().split()))
        
        mx = max(a)
        
        if x == 0:
            print(0)
            continue
        
        if x in a:
            print(1)
            continue
        
        # two jumps are enough if target is within twice max reach
        if x <= 2 * mx:
            print(2)
        else:
            # otherwise we need ceil(x / mx)
            print((x + mx - 1) // mx)

if __name__ == "__main__":
    solve()
```解決策は、最大許容ジャンプ長を抽出することから始まります。これは、ターゲットに到達するために単一の移動ができる最大の貢献を決定するためです。 

に対する直接の等価性チェック$x$単一のジャンプで十分な場合を処理します。 幾何学的組み合わせが存在する場合でも、直接一致することが常に最適であるため、これは重要です。 

次の分岐では、長さが最大 ​​2 つのベクトルであるという幾何学的事実を使用します。$M$までのあらゆる変位を実現できます$2M$したがって、その範囲内のすべての目標は、正確に 2 つのステップで達成可能です。 

最終的に目標を超えたとき$2M$、各ジャンプは最大で貢献します$M$X 軸に沿って効果的に進行するため、天井を使用した単純な除算に戻ります。

 ## 特殊なケース

 いつ$x$が許可された長さのいずれかと正確に等しい場合、アルゴリズムはすぐに 1 を返します。入力の場合$n=3, x=5, a=[2,5,7]$、小切手`x in a`最大値の組み合わせのみに依存するアプローチでは、複数ステップの構築を誤って試行することになります。 

いつ$x$最大値に比べて小さい、など$x=6$と$a=[10, 12]$、条件$x \le 2M$出力が 2 であることを保証します。単純な計算ではオーバーシュートの問題が示唆される場合でも、幾何学的な構築により 2 つのベクトルで十分であることが保証されるため、アルゴリズムはここでは除算を試みません。 

いつ$x$など大きいです$x=100$と$a=[30, 40]$、アルゴリズムは 40 による天井除算に戻り、3 を生成します。これは、最大長のジャンプを繰り返し使用することに対応します。これは、2 つのジャンプがそれを超えることはできないためです。$2M = 80$、追加の手順が避けられなくなります。
