 ## 解決策
 ## 問題の理解

 というラベルの付いたカードを含むスタックがあります。`1`を通して`n`、いくつかの順列で表示されます。 マジシャンはラベルの昇順にカードを捨てなければなりません。`1`最初にカードを捨ててからカードを捨てる必要があります`2`、 等々。 

捨てることができるのは一番上のカードのみです。 どのカードが一番上にあるかを変更するには、マジシャンは現在の一番上のカードを一番下に移動するか、現在の一番下のカードを一番上に移動します。 カードを移動するには、そのラベルのコストがかかります。 カードを捨てるのに費用はかかりません。 

タスクは、スタック全体を削除するための最小合計ローテーション コストを見つけることです。 公式入力にはいくつかのテスト ケースが含まれています。`n`まで`10^5`それぞれのケースとすべてのラベルについて`1`を通して`n`ちょうど 1 回出現します。 元のコンテストの声明と公式の問題レビューにより、順列構造、サンプル ケース、および意図されたフェンウィック ツリー アプローチが確認されています。 

の`10^5`バウンドでは、すべての回転を明示的にシミュレートすることは除外されます。 過ごしたら`O(n)`1枚のカードのコストを見つけて、それをすべてのカードについて繰り返します`n`カード、最悪のケースは約`10^10`基本的な操作。 公式レビューでも同様のことが書かれています`O(n^2)`推定し、これが遅すぎると判断します。 各カードのコスト計算を対数時間に短縮する必要があります。 

誤って処理されやすい境界ケースがいくつかあります。 必要なカードがすでに一番上にある場合、コストはゼロです。 例えば、```
2
1 1
2 1 2
```出力があります```
0
0
```2つのケースの場合。 不用意に実装すると、必要なカード自体に料金がかかる可能性がありますが、一番上のカードを破棄する場合には費用はかかりません。 

一番下にカードを入れることも可能です。 例えば、```
1
3 3 2 1
```出力があります```
3
```カード`1`は一番下にあるため、それ自体を下から上に移動する必要があり、コストがかかります`1`。 捨てた後、カード`2`一番下にありコストがかかります`2`上部に移動します。 カード`3`はすでにトップにあり、合計は`3`。 下から持ってくるカードも移動する必要があることを忘れるのは、よくある間違いです。 

最初と最後の位置も 1 つの円形の境界を形成します。 例えば、```
1
4 2 3 4 1
```出力があります```
5
```カード`1`は一番下にあるため、一番上に直接移動するとコストがかかります`1`。 この後、カード`2`が一番上にあり、その後に続きます`3`そして`4`、したがって、残りの除去コストは`0`。 実際、これは合計を与えます`1`、 ない`5`これは、円形構造が元の最初の位置ではなく現在の上部から推論されなければならない理由を示しています。 正しく実装するには、削除のたびに先頭の位置を更新する必要があります。 

のために`n = 1`、唯一のカードがすでに一番上にあり、答えはゼロです。 この問題ではすべてのラベルが一意である必要があるため、これは、空虚な意味で「すべてが等しい」唯一の法的事例でもあります。 次のような入力`3 2 2 2`は、この問題の有効なテスト ケースではありません。 

## アプローチ

 直接的な解決策では、すべてのラベルの元の位置が維持されます。 次に必要なカードを削除するには、現在のスタックをどちらかの方向にスキャンして、移動する必要があるすべてのカードのラベルを追加します。 まであるので、`n`カード、1 つの除去が可能`O(n)`時間。 これを全員で繰り返すと`n`削除が与える`O(n^2)`近づくことができる時間`10^10`操作時の操作`n = 10^5`。 これは、3 秒のコンテスト ソリューションが対応できる範囲をはるかに超えています。 公式コンテストのレビューでは、この強引な戦略とその二次関数の実行時間が正確に説明されています。 

それでもブルートフォースが有用である理由は、それが貪欲な構造を暴露するからです。 次に除去する必要があるカードを決定したら、それを公開する方法は 2 つしかありません。カードを上から下に繰り返し移動するか、カードを下から上に繰り返し移動することです。 どちらの方向のコストが低いかを選択する必要があります。 必要なカードが捨てられた後、使用された方向に関係なく、残りのカードは同じ循環順序になります。 どちらの選択をしても、残りのカードの順序がまったく同じになってローテーションが行われるため、より長い方法で周回することは、将来のより良い配置を生み出すことはできません。 公式レビューでも、この貪欲な選択について同じ見解が述べられています。 

高価な部分は、貪欲な決定そのものではありません。 コストがかかる部分は、移動されるラベルの合計を計算することです。 考えられるローテーション コストはすべて、元の位置の連続セグメントの合計であり、削除されたカードの寄与は単純にゼロになります。 これはまさにフェンウィック ツリーでサポートされている操作です。カードが削除されたときにポイントが更新され、プレフィックスまたは範囲の合計がカードに追加されます。`O(log n)`。 

保管もしております`pos[x]`、カードの元の位置`x`。 スタックは回転と削除によってのみ変更されるため、カードが残りのカード間で相対的な位置を変更することはありません。 したがって、その元のインデックスは、そのカードと以前に削除されたカードの間にどのカードが残っているかを判断するのに十分です。

 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのカードの元の位置を次の場所に保存します。`pos`。 また、現在アクティブなすべてのカードの値を元の位置に含むフェンウィック ツリーを構築します。 ツリーは削除されたカードをゼロで表すため、範囲の合計ではすでに削除されたすべてのカードが自動的に無視されます。 
2. 必要なカードを順番に処理します`1, 2, ..., n`。 保つ`prev`、以前に捨てられたカードの元の位置。 カードが捨てられる前に、`prev = 0`。 これは最初のカードの直前の位置を表すため、入力の最初のカードが現在のトップになります。 
3. しましょう`q = pos[x]`現在必要なカードの元の位置になります。 まずカードを上から下に移動することを検討してください。 もし`q > prev`、移動されたカードは正確に からの位置になります。`prev + 1`を通して`q - 1`。 もし`q < prev`、パスは最後まで回り込むため、移動したカードは位置になります。`prev + 1`を通して`n`、その後にポジションが続きます`1`を通して`q - 1`。 
4. フェンウィック ツリーにこれらのカードの合計を問い合わせます。 これに電話してください`forward`。 これらはまさに、カードを作成する前に上から下に移動する必要があるカードです。`x`頂上に到達します。 
5. 他の方向はさらに簡単です。 現在アクティブなカードはすべて順方向パスまたは逆方向パスのいずれかに属しており、2 つのパスが到達に関係するカードを分割します。`x`。 したがって、反対方向に進むコストは次のようになります。`total - forward`、 どこ`total`現在アクティブなカードすべての合計です。 これには以下が含まれます`x`それ自体いつ`x`は下から上に移動する必要があり、これはまさにルールが要求していることです。 
6.追加`min(forward, total - forward)`答えに。 どちらの方向でも、削除後に残りのカードの循環順序が同じになるため、この削除には安価な方向が最適です。`x`は破棄されます。 
7. 削除する`x`追加することでフェンウィックツリーから`-x`位置で`q`、減算`x`から`total`、と設定します`prev = q`。 次に必要なカードは、この新しい開始点を基準にして評価されるようになりました。 

### なぜ効果があるのか

 不変条件は、各削除の後、フェンウィック ツリーには元の位置に残っているカードが正確に含まれるということです。`prev`循環順序の現在の先頭の直前の元の位置を識別します。 次のターゲットに向けて`x`、間のカード`prev`そして`pos[x]`円を描く方向にあるカードは、公開するために移動する必要があるカードです。`x`その方向から。 反対方向には、最初のパスでカウントされなかった残りのカードがすべて含まれます。`x`下から上に移動する必要がある場合は、それ自体が必要になります。 したがって、計算された 2 つのコストは、まさに、暴露するための 2 つの法的な方法です。`x`、そしてそれらの最小値を取ることが最適です。 削除後`x`、他のすべてのカードの相対的な循環順序は変更されないため、次のターゲットに対しても不変条件は true のままです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(a):
    n = len(a)

    # pos[x] = original position of card x, using 1-based positions.
    pos = [0] * (n + 1)

    # Fenwick tree.
    bit = [0] * (n + 1)

    for i, x in enumerate(a, 1):
        pos[x] = i
        bit[i] = x

    # O(n) Fenwick construction.
    for i in range(1, n + 1):
        j = i + (i & -i)
        if j <= n:
            bit[j] += bit[i]

    def prefix_sum(i):
        result = 0
        while i > 0:
            result += bit[i]
            i -= i & -i
        return result

    total = n * (n + 1) // 2
    answer = 0
    prev = 0

    for x in range(1, n + 1):
        q = pos[x]

        # Cost when rotating top -> bottom.
        if q > prev:
            forward = prefix_sum(q - 1) - prefix_sum(prev)
        else:
            forward = (
                total
                - prefix_sum(prev)
                + prefix_sum(q - 1)
            )

        backward = total - forward
        answer += min(forward, backward)

        # Discard x.
        i = q
        while i <= n:
            bit[i] -= x
            i += i & -i

        total -= x
        prev = q

    return answer

def main():
    t = int(input())
    out = []

    for _ in range(t):
        data = list(map(int, input().split()))
        n = data[0]
        a = data[1:1 + n]
        out.append(str(solve_case(a)))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    main()
```の`pos`配列は、アルゴリズムで必要な位置追跡に対応して、カード ラベルから元の位置までの逆検索を実装します。 ローテーションによって生き残るカードの相対的な順序は変わらないため、Python リストを物理的にローテーションする必要はありません。 

フェンウィック ツリーには、カードがまだ存在している間、元の位置にカードの値が含まれています。 カードが破棄されると、その値はちょうど 1 つのインデックスで減算されます。 プレフィックスの合計は、残っているカードの連続したセクションのコストを与えます。`O(log n)`時間。 

初期のフェンウィック ツリーは次のように構築されます。`O(n)`パフォーマンスするのではなく`n`別`O(log n)`更新情報。 これは漸近解には必要ありませんが、Python での初期化のオーバーヘッドが軽減されます。 

の表現`forward`意図的に排他的なエンドポイントを使用します。 もし`q > prev`、`prefix_sum(q - 1) - prefix_sum(prev)`ポジションが含まれています`prev + 1`を通して`q - 1`, 以前に削除されたカードと対象のカードの両方を除きます。 もし`q < prev`、パスが折り返されるため、コードは後にサフィックスを追加します。`prev`前のプレフィックスに`q`。`total`スタックに残っているすべてのカードの合計です。 2 つの可能な回転方向がアクティブ カードを分割するため、逆コストは単純に次のようになります。`total - forward`。 下から到達した場合に対象カードがリバースコストに含まれるのもこのためです。 

すべてのコストは 32 ビット整数よりもはるかに大きくなる可能性があります。 のために`n = 10^5`、総コストは次のとおりになります。`n^3`, そのため、Python の任意精度の整数は必要な範囲を簡単に処理できます。

## 特殊なケース

 シングルカードの場合、```
1
1 1
```対象のカードはすでに一番上にあります。 転送間隔は空であるため、そのコストは次のようになります。`0`。 その後、カードが取り出され、アルゴリズムが終了します。 答えは、`0`。 

一番下のカードについては、```
1
3 3 2 1
```最初の目標は`1`の位置で`3`。 前進方向には移動が必要です`3`そして`2`、反対方向に一番下のカードが移動します。`1`そのまま頂上へ。 後者の費用は`1`、だからカード`1`費用のために削除されます`1`。 残りのスタックには、`3, 2`、カード`2`コストをかけて下から上に移動できます`2`。 カード`3`そのときはすでにトップになっています。 合計は`3`。 

ターゲットが元の配列内で以前に削除された位置より前にある場合、パスは末尾で折り返されます。 以前に削除されたカードがその位置にあったと仮定します`5`そして次のターゲットはその位置にいます`2`。 前進パスは、ポジション以降に残っているカードで構成されます`5`、その後に生き残ったカードが位置の前に表示されます`2`。 Fenwick クエリはこれを 2 つの範囲として処理しますが、反対方向はアクティブな合計からそのコストを減算することによって取得されます。 

ターゲットが以前に削除された位置の直後にある場合、前方間隔は空になります。 たとえば、すでにソートされたスタックで、カードを削除した後、`2`、カード`3`すぐに上にあります。 フェンウィックの表情`prefix(q - 1) - prefix(prev)`両方の端点が同じ境界を表すため、 はゼロになります。 これにより、隣接するカードの特殊なケースが回避されます。 

カードがなくなっても、削除された位置は座標系に残る必要があります。 フェンウィック ツリーは、削除された位置にゼロを格納することでこれを自然に処理します。 削除のたびに配列を物理的にシフトすると、元の位置情報が破壊され、解が 2 次の動作に戻ります。 

最後に、ラベルの重複は有効な問題の特殊なケースではありません。 次のような入力```
1
3 2 2 2
```からのすべてのラベルは法的スタックを表しません。`1`を通して`n`は 1 回だけ発生する必要があります。 位置ルックアップ`pos[x]`もこの独自性に依存しています。 テスト スイートは、そのような入力をアルゴリズムの判断に使用するのではなく、拒否する必要があります。
