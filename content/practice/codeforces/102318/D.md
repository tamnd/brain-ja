 ## 解決策
 ## 問題の理解

 数行からなるテキスト ファイルがあります。 各行については、その長さのみが重要です。 カーソル位置は行番号と列番号で表されます。列 0 は最初の文字と列の直前です。`s[i]`は最後の文字の直後にあります。 

カーソルは4つの矢印キーで移動できます。 通常、左と右は列を 1 つずつ変更しますが、行の境界で隣接する行と交差します。 現在の列を保持しながら、上下に行を変更します。 宛先行が短い場合、カーソルはその行の終わりに固定されます。 最初または最後の行で、ファイル外への垂直方向の移動を試みても効果はありません。 

すべてのシナリオについて、行の長さ、現在のカーソル位置、および目的のカーソル位置が与えられます。 目的の位置に到達するために必要な最小限の矢印キーの押下回数が必要です。 

行数は最大 120 行、各行の文字数は最大 80 文字です。 したがって、1 行には、両方のエンドポイントを含めて最大 81 個の可能なカーソル列があります。 ファイル全体で最大でも`120 * 81 = 9720`有効なカーソルの状態。 この境界は、状態空間を明示的に検索できるほど十分に小さいです。 状態ごとに一定数の遷移を使用してすべての状態を探索するソリューションは、1 秒の制限を十分に満たす速度になります。 対照的に、矢印キーの可能なシーケンスを列挙することは、答えが増えるにつれて指数関数的に増加し、数十手でも役に立たなくなります。 

間違いの主な原因は、カーソル位置を通常のものとして扱うことです。`(row, column)`動きに制限のないポイント。 有効な列範囲は行によって異なります。 

たとえば、次のように考えてみましょう```
2
1 0
1 0
2 0
```ファイルには 2 つの行があり、最初の行は空で、2 番目の行は空です。 カーソルは 1 行目の先頭から始まり、2 行目の先頭に到達する必要があります。答えは次のとおりです。`1`1 回の Down キーを押すと 2 行目に直接移動するためです。現在の列が文字位置として存在する場合にのみ垂直方向の移動を許可する不注意な実装では、列 0 が各行で有効であるにもかかわらず、移動が誤って拒否される可能性があります。 

もう一つの境界ケースは、```
2
5 2
1 5
2 2
```答えは`1`。 カーソルは 1 行目の末尾にあり、下を押すと 2 行目の 2 列目に移動します。これは、そこには 5 列目が存在しないためです。 クランプせずに列 5 を保持しようとする実装では、無効な状態が作成されます。 

線を横切って水平に移動すると、別の境界が発生します。 のために```
2
1 0
1 1
2 0
```答えは`1`。 カーソルは 1 行目の末尾にあるため、Right を押すとカーソルが 2 行目の先頭に移動します。各行を独立して扱い、改行をまたぐことを拒否すると、間違った答えが生成されます。 

最後に、ドキュメントを超えて移動しようとしても、新しい状態を作成してはなりません。 のために```
1
5
1 0
1 5
```答えは`5`。 右に 5 回押すと、唯一の行の最後に到達します。 6 回目の右押しは何も行わないため、効果のない押しを有用な遷移としてカウントする実装では、人工的な状態を通る短いパスが誤って報告される可能性があります。 

## アプローチ

 最も直接的な総当り攻撃のアイデアは、ターゲットに到達するまで矢印キーの可能なすべてのシーケンスを試すことです。 どの位置でも 4 つのキーを押すことができるため、`k`までのプレスが可能です`4^k`シーケンス。 多くのシーケンスが同じカーソル位置に到達しても、このメソッドはそれらの繰り返しを個別に調査します。 有効な状態の最大数は 9720 であるため、原則として最短パスの長さは数千手になる可能性があります。 列挙する`4^9720`可能なシーケンスは完全に実行不可能です。 

これらの繰り返しシーケンスが無駄である理由は、カーソルの将来はその現在の位置のみに依存するためです。 2 つの異なるキー シーケンスが同じに到達した場合`(line, column)`、その後に起こる可能性のあることはすべて同じです。 これら 2 つの履歴を 1 つの状態にマージできます。 

この観察により、エディターが重みのないグラフに変わります。 有効なカーソル位置はすべて頂点であり、矢印キーを 1 つ押すと、結果のカーソル位置にエッジが作成されます。 各エッジには 1 回のキー入力が必要となるため、幅優先検索では、現在の位置から到達可能なすべての位置までの最短のキー入力回数が得られます。 

グラフを明示的に作成する必要はありません。 各状態について、その 4 つの近傍を線の長さから直接計算できます。 状態の数は最大 9720 で、各状態の遷移は最大 4 つであるため、BFS は数万の遷移のみを検査します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |`O(4^D)`どこ`D`| は最短経路の長さです。`O(D)`再帰パスごと | 遅すぎる |
 | 最適なBFS |`O(F * 81)`|`O(F * 81)`| 承認済み |

 ここ`F`行数です。 各カーソル状態には 4 つの可能な矢印キーがあるため、BFS の定数係数は 4 です。 

## アルゴリズムのチュートリアル

 1. すべての有効なカーソル位置を処理します。`(r, c)`グラフの状態として。 ライン用`r`、有効な列は次のとおりです。`0`を通して`s[r]`、包括的。 空行には有効な位置が 1 つだけあるため、この表現では空行が自動的に処理されます。`(r, 0)`。 
2. 現在のカーソル位置で BFS を開始し、距離 0 を割り当てます。 状態の距離は、その状態に到達するために必要なキー入力の最小回数を表します。 
3. 左の動きの場合、`c > 0`、次の状態は`(r, c - 1)`。 もし`c == 0`そして`r > 0`、カーソルが改行を越えて移動します。`(r - 1, s[r - 1])`。 最初の行では、Left は効果がありません。 
4. 右の動きの場合、`c < s[r]`、次の状態は`(r, c + 1)`。 もし`c == s[r]`そして`r + 1 < F`、カーソルが改行を越えて移動します。`(r + 1, 0)`。 最後の行では、Right は効果がありません。 
5. 上への移動の場合、次の場合`r > 0`、前の行に移動し、列をその長さに合わせてクランプします。 目的地は`(r - 1, min(c, s[r - 1]))`。 カーソルがすでに最初の行にある場合、Up は効果がありません。 
6. 下移動の場合、`r + 1 < F`、次の行に移動し、同じ方法で列をクランプします。`(r + 1, min(c, s[r + 1]))`。 カーソルがすでに最終行にある場合、Down は効果がありません。 
7. 有効なネイバーが訪問されていない場合は常に、そのネイバーに現在の状態より 1 大きい距離を割り当て、BFS キューに入れます。 初めて州を訪問するときは、すべてのエッジに 1 コストがかかるため、その州の最短距離になります。 
8. 目的のカーソル位置に到達したら停止するか、必要に応じて BFS を終了させます。 ターゲットに対して保存される距離は、必要な最小キー入力数です。 

### なぜ効果があるのか

 不変条件は、状態が BFS キューから削除されるとき、その状態に保存される距離は、そのカーソル位置に到達するために必要なキー入力の最小回数であるということです。 最初は、これは距離がゼロの開始位置に当てはまります。 すべての遷移は、正確に 1 回の正当な矢印キーの押下を表すため、新しく発見された状態は、その前の状態への最短経路よりも 1 大きい距離を受け取ります。 BFS は距離が減少しない順序で状態を処理するため、最初にその状態を訪れたときに、その状態への未発見の短いパスが存在することはありません。 すべての正当なカーソル移動は、生成された 4 つの遷移の 1 つによって表されるため、エディターを通過するすべての可能なルートがグラフ内に存在します。 したがって、ターゲットの BFS 距離は正確に最小キー押下数になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n = int(input())

    for _ in range(n):
        f = int(input())
        length = list(map(int, input().split()))

        rc, cc = map(int, input().split())
        rm, cm = map(int, input().split())

        rc -= 1
        rm -= 1

        dist = [[-1] * (length[r] + 1) for r in range(f)]
        q = deque()

        dist[rc][cc] = 0
        q.append((rc, cc))

        while q:
            r, c = q.popleft()
            d = dist[r][c]

            if r == rm and c == cm:
                print(d)
                break

            # Left
            if c > 0:
                nr, nc = r, c - 1
                if dist[nr][nc] == -1:
                    dist[nr][nc] = d + 1
                    q.append((nr, nc))
            elif r > 0:
                nr, nc = r - 1, length[r - 1]
                if dist[nr][nc] == -1:
                    dist[nr][nc] = d + 1
                    q.append((nr, nc))

            # Right
            if c < length[r]:
                nr, nc = r, c + 1
                if dist[nr][nc] == -1:
                    dist[nr][nc] = d + 1
                    q.append((nr, nc))
            elif r + 1 < f:
                nr, nc = r + 1, 0
                if dist[nr][nc] == -1:
                    dist[nr][nc] = d + 1
                    q.append((nr, nc))

            # Up
            if r > 0:
                nr, nc = r - 1, min(c, length[r - 1])
                if dist[nr][nc] == -1:
                    dist[nr][nc] = d + 1
                    q.append((nr, nc))

            # Down
            if r + 1 < f:
                nr, nc = r + 1, min(c, length[r + 1])
                if dist[nr][nc] == -1:
                    dist[nr][nc] = d + 1
                    q.append((nr, nc))

if __name__ == "__main__":
    solve()
```入力は、独立したエディターのシナリオの数から始まります。 各シナリオでは、行数、各行の長さ、および 2 つのカーソル位置が提供されます。 入力では 1 から始まる行番号が使用されるため、実装ではすぐに 0 から始まるインデックスに変換されます。 

の`dist`構造体の各行の長さは異なります。 一定の長さの線の場合`s`、まさにあります`s + 1`有効なカーソル位置。 これは、無効な位置を誤ってエンキューすることが不可能になるため、固定の 81 列の配列を割り当てるよりも望ましい方法です。 

4 つのトランジション セクションは、エディターの正確な移動ルールを実装します。 水平方向の移動には、列 0 と行末で特別な処理が必要です。これらは、Left と Right が改行と交差する点であるためです。 垂直移動の用途`min(c, length[nr])`これは、カーソルが短い行の末尾に移動するというエディターのルールを実装します。 

条件`dist[nr][nc] == -1`2 つの目的を果たします。 これは、状態が訪問されたかどうかをマークし、BFS が同じカーソル位置を繰り返し処理するのを防ぎます。 すべての遷移には単位コストがあるため、状態に割り当てられる最初の距離はすでに最適です。 

ターゲットは、キューから状態を削除した直後にチェックされます。 BFS は距離の増加順に状態を処理するため、ターゲットがポップされると、その距離が答えとなります。 コードはキューが空になるまで続行することもできますが、早期に停止することで不必要な作業を回避できます。 

ここでは、Python の整数には固定幅のオーバーフローの問題がありません。 さらに重要なのは、有効な最大距離は有効な状態の数から 1 を引いた値によって制限されますが、これは Python の整数の範囲と比較すると非常に小さいです。

## テストケース```python
import sys
import io
from collections import deque

def solve(inp: str) -> str:
    data = io.StringIO(inp)

    def read():
        return data.readline

    input = read
    n = int(input())
    out = []

    for _ in range(n):
        f = int(input())
        length = list(map(int, input().split()))

        rc, cc = map(int, input().split())
        rm, cm = map(int, input().split())

        rc -= 1
        rm -= 1

        dist = [[-1] * (length[r] + 1) for r in range(f)]
        q = deque([(rc, cc)])
        dist[rc][cc] = 0

        while q:
            r, c = q.popleft()
            d = dist[r][c]

            if r == rm and c == cm:
                out.append(str(d))
                break

            neighbors = []

            if c > 0:
                neighbors.append((r, c - 1))
            elif r > 0:
                neighbors.append((r - 1, length[r - 1]))

            if c < length[r]:
                neighbors.append((r, c + 1))
            elif r + 1 < f:
                neighbors.append((r + 1, 0))

            if r > 0:
                neighbors.append((r - 1, min(c, length[r - 1])))

            if r + 1 < f:
                neighbors.append((r + 1, min(c, length[r + 1])))

            for nr, nc in neighbors:
                if dist[nr][nc] == -1:
                    dist[nr][nc] = d + 1
                    q.append((nr, nc))

    return "\n".join(out) + "\n"

1 5
2 2
```カーソルは 1 行目の 5 列目から始まります。Down は 5 列目を保持しようとしますが、2 行目は 2 列目で終了するため、結果の状態は次のようになります。`(2,2)`。 キーを 1 回押すだけで目標に到達し、`1`。 

ライン境界を水平に横切る場合も特殊なケースです。 と```
1
2
1 0
1 1
2 0
```カーソルは行 1 の終わりから始まります。行の長さは 1 であるため、右では列を増やすことができず、次の行に移動します。`(2,0)`その代わり。 答えは`1`。 

ファイルの外側の境界では、矢印は何の効果もありません。 のために```
1
1
5
1 0
1 5
```BFS は 5 回の右クリックでターゲットに到達できます。 カーソルが`(1,5)`、次の行がないため、もう一度右押ししても新しい位置は作成されません。 実装では、存在しない遷移が生成されないだけです。 

最も微妙なエッジケースは、最短ルートが欲張って見える必要はないということです。 線の長さを指定したサンプルでは`39, 20, 57, 54, 14, 38, 31`の場合、カーソルがその行の終端に固定されるため、現在の列が次の行に存在しない場合でも、最短パスは垂直方向に移動することで恩恵を受けます。 現在の行または列とターゲットの行または列の差を常に減少させる戦略では、そのようなルートを見逃す可能性があります。 BFS は、到達可能なすべての状態を実際のキー押下数に基づいて比較することで、その仮定を完全に回避します。
