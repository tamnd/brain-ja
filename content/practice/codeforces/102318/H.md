 ## 解決策
 ## 問題の理解

 この問題では、整数配列を処理し、(k) のすべての可能な値について、増加する部分列のコレクションに選択できる配列要素の数を決定するように求められます。 

選択したすべてのサブシーケンスには、少なくとも (k) 個の要素が含まれている必要があります。 選択した 2 つのサブシーケンスは、元の配列内で重複してはなりません。 1 つのサブシーケンスが (i) から (j) までの位置を使用する場合、別のサブシーケンスは、その位置自体が選択されていない場合でも、(i) と (j) の間の位置を使用できません。 目的は、すべてのサブシーケンスにわたって選択された要素の合計数を最大化することです。 必要な出力には、(1) から (n) までの (k) ごとに 1 つの回答が含まれます。 これは、元の UCF ローカル問題で使用される正確な定式化であり、(n\le100) および最大 50 個のテスト ケースが存在します。 

小さな値 (n\le100) により、アルゴリズムのターゲットが大幅に変わります。 3 次アルゴリズムは、1 つのテスト ケースに対して約 (100^3=10^6) 個の基本演算を実行します。これは、コンパイルされた実装で 50 のケースすべてに対して繰り返された場合でも、まったく合理的です。 (2^{100}) は約 (1.27\times10^{30}) であるため、指数アルゴリズムは (n=100) ですでに絶望的です。 したがって、意図したソリューションでは、(O(n^3)) 個の作業を伴う動的プログラミングが使用されます。 公式コンテストのレビューでは、すべての間隔 LIS 値に対する (O(n^3)) 個の前処理フェーズと、それに続く別の (O(n^3)) 個の動的プログラムについても説明しています。 

単純な実装が正しくない可能性があるいくつかの特殊なケースがあります。 たとえば、配列に要素が 1 つある場合、`1 5`、唯一の有効な答えは`1`なぜなら、(k=1) の場合、その要素はそれ自体で部分列を形成するからです。 (k>1) の場合、有効なサブシーケンスはありませんが、(n=1) の場合、(k) のような値は存在しないため、出力は単純に次のようになります。`1`。 単一要素間隔を処理せずにすべての答えをゼロに初期化する実装は、ここで失敗します。 

値の繰り返しは、サブシーケンスが厳密に増加する必要があるため、もう 1 つの境界ケースです。 入力用`3 / 1 1 1`、正しい出力は次のとおりです。`3 0 0`。 (k=1) の場合、個々の要素はそれぞれ独自のサブシーケンスを形成し、3 つの選択された要素を与えることができます。 ただし、(k=2) の場合、厳密に増加する部分列を形成する 2 つの等しい要素は存在しません。 を使用した不注意な LIS 移行`<=`の代わりに`<`これは、配列に長さ 3 の増加するサブシーケンスが含まれていると誤って主張することになります。 

3 番目のエッジ ケースは、最適なコレクションが最後の配列要素を使用しない場合に発生します。 考慮する`5 / 2 9 1 3 4`。 (k=2) の場合、部分列は`[2, 9]`そして`[3, 4]`4 つの要素を選択しますが、最後の要素はすでに`[3,4]`ここ。 より一般的には、プレフィックスの最適な解決策では、その最終位置が未使用のままになる場合があります。 したがって、プレフィックス DP は移行を許可する必要があります。`dp[i] = dp[i-1]`。 最後の要素が最後のサブシーケンスに属することを要求する実装では、有効なソリューションが失われる可能性があります。 

最後に、異なるサブシーケンスは、選択されたインデックスにおいて単純に素であることはできません。 インデックス範囲全体が互いに素である必要があります。 で`2 1 9 3 4 4 5 6`(k=2) の場合、最適解は次のようになります。`[2,9]`、`[3,4]`、`[4,5,6]`、選択された 7 つの要素を示します。 の 2 つの発生`4`異なるサブシーケンスに属しますが、それらのインデックス範囲は重複しません。 これが、DP が任意の素のインデックス セットを個別に選択するのではなく、配列を連続した領域に分割し、選択した各領域から 1 つの増加するサブシーケンスを取得する必要がある理由です。 

## アプローチ

 直接的な総当たりの解決策では、配列位置のすべてのサブセットを列挙し、非オーバーラップ条件も考慮しながら、選択した位置を少なくとも (k) の長さの有効な増加サブシーケンスに分割できるかどうかを判断できます。 特定のサブセットが有効かどうかを確認する前に、(2^n) 個のサブセットが存在します。 妥当性チェックで選択した位置と可能な境界を検査する場合、多項式時間がかかるため、合計作業量は少なくとも (O(2^n n^2)) になります。 (n=100) では、サブセット数だけでも約 (1.27\times10^{30}) となり、網羅的な検索は不可能になります。 

総当り攻撃は、ポジションのすべての選択肢を他のすべての選択肢と無関係なものとして扱うため、失敗します。 有用な構造は、オーバーラップしないことで自然な左から右への分解が得られることです。 最後のサブシーケンスが固定されると、その開始位置より前のすべては独立した小さなインスタンスになります。 

次の観察は、1 つのサブシーケンスが位置 (l) から位置 (r) までの間隔を占めると判断した場合、その間隔内で最も長く増加するサブシーケンスより小さいものを選択する理由はまったくないということです。 その間隔に長さ (L) および (L\ge k) の LIS がある場合、すべての (L) 個の要素を使用できます。 使用する要素の数を減らしても、目的が減少するだけであり、間隔内に他のサブシーケンスが許可されないため、間隔と別のサブシーケンスとの互換性が向上することはありません。 

これにより、問題は 2 つの動的プログラミング層に縮小されます。 まず、計算します`lis[l][r]`、(l) から (r) までの連続区間内に完全に含まれる最長の増加サブシーケンスの長さ。 (O(n^2)) 個の間隔があり、単純な LIS DP は (O(n^3)) 時間ですべての間隔を計算します。 これはまさに公式レビューで説明されている前処理戦略です。 

次に (k) を修正します。 させて`dp[r]`位置のみを使用して選択された要素の最大数になります`0..r`。 可能性は 2 つあります。 位置 (r) を未使用のままにしておくことができます。`dp[r-1]`。 Or the final subsequence starts at some position (l), occupies the whole interval`[l,r]`、貢献します`lis[l][r]`要素。 これは次の場合にのみ許可されます`lis[l][r] >= k`。 (l) より前のすべてが寄与します`dp[l-1]`。 したがって、移行は次のようになります

 [
 dp[r]=\max\left(dp[r-1],\max_{0\le l\le r,;lis[l][r]\ge k}
 \left(dp[l-1]+lis[l][r]\right)\right)。 
】

 (k) には (n) 個の可能な値、(n) 個の可能な右端点、(n) 個の可能な開始点があるため、この 2 番目のフェーズにも (O(n^3)) 時間がかかります。 公式の編集スタイルのレビューでは、同じ分解が示されており、最後に選択されたサブシーケンスが、以前のブレークポイントの後のサフィックスの LIS として表示されます。

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(a):
    n = len(a)

    # lis[l][r] = LIS length inside a[l..r].
    lis = [[0] * n for _ in range(n)]

    for l in range(n):
        ending = [0] * n
        best = 0

        for r in range(l, n):
            cur = 1
            ar = a[r]

            for p in range(l, r):
                if a[p] < ar and ending[p] + 1 > cur:
                    cur = ending[p] + 1

            ending[r] = cur
            if cur > best:
                best = cur

            lis[l][r] = best

    answer = [0] * n

    # Solve the non-overlapping interval problem independently for
    # every required minimum subsequence length k.
    for k in range(1, n + 1):
        dp = [0] * n

        for r in range(n):
            # Leave position r unused.
            if r > 0:
                best = dp[r - 1]
            else:
                best = 0

            # Make [l, r] the interval occupied by the last subsequence.
            for l in range(r + 1):
                length = lis[l][r]

                if length >= k:
                    before = dp[l - 1] if l > 0 else 0
                    value = before + length

                    if value > best:
                        best = value

            dp[r] = best

        answer[k - 1] = dp[n - 1]

    return answer

def main():
    t = int(input())

    out = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        ans = solve_case(a)
        out.append(" ".join(map(str, ans)))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    main()
```最初のネストされたセクションは、間隔 LIS テーブルを構築します。 固定の場合`l`、`ending[r]`正確にその位置で終了する最長の増加するサブシーケンスを保存します`r`。 いつ`a[p] < a[r]`、で終わる増加するサブシーケンス`p`によって延長できます`a[r]`。 変数`best`は、これまでに発生したすべての終了長の最大値であり、正確に現在の間隔の LIS です。 

2 番目の主要セクションは、次の 1 つの値を処理します。`k`一度に。 からの課題`dp[r - 1]`は任意の簿記ではありません。 最適な収集がその前に停止する可能性を表します。`r`、これは誤った解決策の一般的な原因です。 

表現`dp[l - 1] if l > 0 else 0`センチネル要素を必要とせずに最初の間隔を処理します。 これにより、off-by-one の特殊なケースが回避されます。`lis`漸化式をその数学的形式に近づけながら、テーブルを作成します。 

比較`a[p] < ar`厳しくなければなりません。 等しい値を、増加するサブシーケンスの連続する要素にすることはできません。 Python の整数にも任意の精度があるため、整数オーバーフローの問題はありません。 

実装ではすべての値を計算します。`k`(n\le100) なので別途。 これにより、状態定義が単純に保たれ、正当性の議論が透明になります。 プレフィックス遷移の総数は (O(n^3)) ですが、間隔 LIS 前処理によりさらに (O(n^3)) が寄与します。

def solve_case(a):
    n = len(a)

    lis = [[0] * n for _ in range(n)]

    for l in range(n):
        ending = [0] * n
        best = 0

        for r in range(l, n):
            cur = 1
            ar = a[r]

            for p in range(l, r):
                if a[p] < ar and ending[p] + 1 > cur:
                    cur = ending[p] + 1

            ending[r] = cur
            if cur > best:
                best = cur

            lis[l][r] = best

    for k in range(1, n + 1):

        for r in range(n):

 ## 特殊なケース

 単一要素入力の場合```
1
42
```間隔テーブルには、`lis[0][0] = 1`。 (k=1) の場合、DP は次のように考慮します。`[0,0]`、長さ 1 の LIS を参照し、次の値を取得します。`dp[0] = 1`。 出力は`1`。 人為的な長さゼロのサブシーケンスは含まれません。 

すべて等しい入力の場合```
3
1 1 1
```比較は厳密に行われるため、長さが少なくとも 2 のすべての間隔は LIS 長さ 1 になります。`<`。 (k=1) の場合、DP は各シングルトン間隔を独立して選択でき、次のようになります。`3`。 いつ (k=2`or`k=3`, every interval has LIS shorter than the required threshold, so the answer is zero. The output is `3 0 0`。 

重複しない例の場合```
8
2 1 9 3 4 4 5 6
```(k=2) の場合、DP は最初に次の値を取ることができます。`[2,9]`、2つの要素に貢献します。 その後、その間隔の後に開始して、`[3,4]`、さらに2つを貢献しました。 ついに、`[4,5,6]`3つ貢献します。 合計は7つです。 DP のプレフィックス状態は、各開始位置の前に最良の結果を記録するため、これらの間隔は、前のサブシーケンスが後の間隔に侵入することを許可せずに結合されます。 

最大サイズ増加入力の場合```
100
1 2 3 ... 100
```配列全体が増加しているため、その LIS は 100 になります。すべての (k\le100) について、長さが少なくとも (k) であるため、配列全体自体は有効なサブシーケンスです。 100 個を超えるすべての要素を選択できるソリューションはないため、すべての答えは正確に 100 になります。このケースでは、最大の DP 次元を実行すると同時に、正確さの単純な上限チェックも提供します。
