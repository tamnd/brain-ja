 ## 解決策
 ## 問題の理解

 この問題では、26 文字すべての小文字を含む小さなカスタム キーボードが使用されます。 文字は 3 行に配置されます。```
a b c d e f g h i
j k l m n o p q r
s t u v w x y z
```各テスト ケースには 2 つの単語が与えられます。 このペアを 3 つのカテゴリのいずれかに分類する必要があります。 同じ長さで、対応するすべての文字が等しい場合、これらは **同一** です。 それらが同じ長さであり、同一ではなく、対応する文字のペアがすべて等しいか、キーボード上の隣接する位置を占めている場合、それらは **類似** します。 どちらの条件も当てはまらない場合、それらは**異なります**。 

元のコンテスト ステートメントでは 1 から 20 までの長さの単語が指定され、最初の入力値は後に続く単語のペアの数を指定します。 

語長が短いということは、高度なデータ構造や漸近的に複雑なアルゴリズムが必要ないことを意味します。 すべての文字をリニア スキャンしても非常に小さく、1 つのテスト ケースで最大 20 文字の比較が行われます。 唯一意味のある設計上の選択は、2 つの文字がキーボードの隣接文字であるかどうかをいかに効率的に判断するかです。 キーボードには 26 個の固定文字しかないため、すべての文字の行と列を直接エンコードして、一定時間内にその質問に答えることができます。 

不注意な実装により誤った分類が与えられるケースがいくつかあります。 異なる長さのものがすぐに生成される必要があります`3`。 例えば：```
1
ab abc
```正しい出力は次のとおりです。```
3
```重なっている文字をチェックするだけのプログラムでは、次のようになります。`a`対`a`そして`b`対`b`似ている単語を誤って呼ぶ可能性があります。 

同じ長さで同じ文字を持つ 2 つの単語は、次の結果を生成する必要があります。`1`、 ない`2`。 例えば：```
1
cool cool
```正しい出力は次のとおりです。```
1
```すべてのペアが等しいか隣接しているかをチェックして返すプログラム`2`最初に単語全体が同一かどうかを確認しないと、このケースは誤って分類されてしまいます。 

隣接性は、斜めの隣を含むキーボードのジオメトリに基づきます。 例えば：```
1
knq bxz
```正しい出力は次のとおりです。```
2
```ここ`k`隣にあります`b`、`n`隣にあります`x`、 そして`q`隣にあります`z`。 水平方向および垂直方向に接触しているキーのみを隣接キーとして扱うと、このペアが誤って拒否されます。 

## アプローチ

 単純な総当たりソリューションでは、各位置を個別に処理できます。 対応する文字のペアごとに、26 個のキーボード文字すべてをスキャンして、2 番目の文字が最初の文字の近傍に属しているかどうかを確認できます。 単語には最大 20 文字が含まれるため、1 つのテスト ケースに対して最大 (20 \times 26 = 520) 個の文字チェックが実行されます。 (n) 個のテスト ケース全体で、最悪のケースは、通常の入力処理に加えて (520n) 回のこのようなチェックです。 このアプローチは類似性の定義を直接テストするので正しいですが、固定の 26 文字キーボードを繰り返し検索するのは不必要な作業です。 

重要な点は、キーボードが決して変更されないことです。 すべての文字には固定の行と列があるため、アルファベットのインデックスを使用して文字をその座標にマッピングできます。 アルファベットインデックス付き文字の場合`p`、その行は`p // 9`そしてその列は`p % 9`。 最初の 2 行にはそれぞれ 9 文字が含まれ、最後の行には 8 文字が含まれます。 

行の差が最大 1、列の差が最大 1 の場合、2 つの文字は正確に隣接します。 等しいという条件も満たされるため、アルゴリズムはまず単語全体が同一かどうかを判断します。 それらが同一でない場合は、すべての位置で隣接条件を検証するだけで済みます。 

これにより、各テスト ケースの作業が単語の 1 回のスキャンに減ります。 この強引な解決策は、キーボードが小さいため機能しますが、その形状が固定されているという事実を利用できません。 繰り返される検索を直接座標演算に置き換えると、分類が単純な線形パスに変わります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | テスト ケースごとに O(26L) | お(1) | 正しいが不必要な繰り返し作業 |
 | 最適 | テスト ケースごとの O(L) | お(1) | 承認済み |

 ここで (L) は語長であり、(L \le 20) となります。 

## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取り、現在のテスト ケースに属する 2 つの単語を読み取ります。 分類はペアごとに独立しているため、すべてのケースを個別に処理できます。 
2. 2 つの単語の長さが異なる場合、出力`3`。 類似性を得るには単語全体にわたる文字間の対応が必要であるため、長さが異なると同一性と類似性の両方が不可能になります。 
3. 2 つの単語が完全に等しい場合、出力`1`。 同一の単語は、対応する文字が等しいか隣接しているという弱い条件も満たすため、このチェックは類似性テストの前に行う必要があります。 
4. それ以外の場合は、同じ位置にある 2 つの単語をスキャンします。 各文字をゼロから始まるアルファベットのインデックスに変換します。`ord(ch) - ord('a')`。 このインデックスから、キーボードの行と列を計算します。 
5. 対応するすべてのペアについて、行の絶対差が最大 1 であり、列の絶対差が最大 1 であるかどうかを確認します。 どちらかの差が 1 を超える場合、ペアには隣接しない位置が含まれるため、出力`3`すぐに。 
6. 悪い位置が見つからずにスキャン全体が終了した場合、出力`2`。 単語は異なるものであることがすでにわかっており、対応するすべてのペアは等しいか隣接しています。これがまさに類似性の定義です。 

### なぜ効果があるのか

 文字スキャン中の不変条件は、これまでに処理されたすべての位置に、等しい文字または 2 つの隣接するキーボード キーが含まれていることです。 位置がこのプロパティに違反する場合、単語は類似することができないため、次の値が返されます。`3`は正しいです。 すべての位置がこのプロパティを満たす場合、単語の長さは等しく、完全な類似条件を満たします。 最初に単語が等しいかどうかがチェックされたため、それらは同一ではないため、正しい結果は次のようになります。`2`。 したがって、3 つの可能な出力は重複することなく区別されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def position(ch):
    p = ord(ch) - ord('a')
    return p // 9, p % 9

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        a, b = input().split()

        if len(a) != len(b):
            ans.append("3")
            continue

        if a == b:
            ans.append("1")
            continue

        similar = True

        for x, y in zip(a, b):
            rx, cx = position(x)
            ry, cy = position(y)

            if abs(rx - ry) > 1 or abs(cx - cy) > 1:
                similar = False
                break

        ans.append("2" if similar else "3")

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```の`position`関数は、アルファベットのインデックスをキーボードの座標に変換します。 による除算`9`最初の 2 行にはそれぞれ 9 文字が含まれているため、これは正しいです。`a`を通して`i`、 それから`j`を通して`r`。 残りの文字`s`を通して`z`最終列を形成します。 

長さのチェックが最初に行われるため、`zip(a, b)`それ以外の場合は、短い単語で停止し、余分な文字は無視されます。 これは、次のような入力の場合は正しくありません。`ab`そして`abc`。 

等価性の方がより強力な分類であるため、等価性チェックは近隣スキャンの前に行われます。 それがなければ、次のようなペア`cool`そして`cool`隣接条件を満たし、出力を誤って受信する可能性があります`2`。 

近隣テストで使用されるのは、`abs(row_difference) <= 1`そして`abs(column_difference) <= 1`。 これには、水平方向、垂直方向、および斜め方向に隣接するものが含まれます。 これには同じキーも含まれていますが、等しい場合はすでに個別に処理されています。 

すべての座標は 0 から 8 の間であり、Python の整数はとにかく無制限であるため、整数オーバーフローの懸念はありません。 初期の`break`また、無効な位置が 1 つあるだけで、単語が似ているのではなく異なるものであることを証明できるので便利です。

import sys
import io

def position(ch):
    p = ord(ch) - ord('a')
    return p // 9, p % 9

def solve():
    input = sys.stdin.readline

    t = int(input())
    ans = []

    for _ in range(t):
        a, b = input().split()

        if len(a) != len(b):
            ans.append("3")
            continue

        if a == b:
            ans.append("1")
            continue

        similar = True

        for x, y in zip(a, b):
            rx, cx = position(x)
            ry, cy = position(y)

            if abs(rx - ry) > 1 or abs(cx - cy) > 1:
                similar = False
                break

        ans.append("2" if similar else "3")

    sys.stdout.write("\n".join(ans))

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

# Examples from the original statement
assert run("1\ncool cool\n") == "1", "identical words"
assert run("1\nmoon done\n") == "2", "similar words"

# Minimum-size input
assert run("3\na a\na b\na c\n") == "1\n2\n3", "single-character cases"

# Maximum word length, identical
assert run("1\n" + "a" * 20 + " " + "a" * 20 + "\n") == "1", \
    "maximum length identical words"

# Diagonal and vertical neighbors
assert run("2\nknq bxz\naaa bkk\n") == "2\n2", \
    "diagonal and multi-position adjacency"

# Different lengths and a non-neighboring pair
assert run("3\nab abc\nab cb\naz za\n") == "3\n3\n3", \
    "length and boundary failures"

 ## 特殊なケース

 最初のエッジケースは、語長が異なることです。 考慮する：```
1
ab abc
```アルゴリズムは最初に長さを比較し、`2 != 3`。 すぐに生産します`3`。 文字スキャンは実行されないため、余分な`c`誤って無視することはできません。 

2 番目のエッジ ケースは同一の単語です。```
1
cool cool
```長さが一致し、等価性テストが成功したため、アルゴリズムは次のように生成します。`1`すぐに。 類似性テストには決して到達しません。 すべての同一のペアは、対応する文字が等しいか隣接しているという弱い要件も満たすため、この順序は重要です。 

3 番目のエッジ ケースは、斜めの隣接ケースです。```
1
knq bxz
```最初のペアは`k`で`(1,1)`そして`b`で`(0,1)`、垂直に隣接しています。 2番目のペアは`n`で`(1,4)`そして`x`で`(2,5)`、斜めに隣接しています。 3番目のペアは、`q`で`(1,7)`そして`z`で`(2,7)`、垂直に隣接しています。 すべてのペアが合格するため、答えは次のとおりです。`2`。 

The final edge case is a pair that looks close alphabetically but is not adjacent geometrically:```
1
ab cb
```最初の位置が比較されます`a`で`(0,0)`と`c`で`(0,2)`。 それらの行の差は 0 ですが、列の差は 2 であるため、これらは隣接しません。 アルゴリズムはすぐに中断され、出力されます。`3`。 このため、数値の差が最大 1 であるかどうかを確認するなど、アルファベットのインデックスを比較すると、キーボード レイアウトの誤った解釈となります。
