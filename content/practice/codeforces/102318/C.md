 ## 解決策
 ## 問題の理解

 CDの内容は、`t`から番号が付けられたトラック`1`を通して`t`、周期的に配置されます。 Anya は、正確にその順序で再生する必要がある一連のトラックを指定します。 最初にリクエストされたトラックはすでに頭出しされているため、ボタンを押す必要はありません。 トラックの後`k`終了すると、プレイヤーは自然に列に並びます`k + 1`、ラッピングから`t`に戻る`1`。 

Arup は 2 つのボタンを使用して、キューに入れられたトラックを変更できます。 前方に押すとキューにあるトラックが 1 つ進み、後方に押すと 1 つ戻ります。 トラックは円を形成するため、連続して要求されたトラックの各ペア間の目標は、単純にその円の周りの短い方向を選択することです。 出力は、連続するすべてのトランジションに必要なボタンの最小押下回数の合計です。 元のコンテストの声明では次のように指定されています`t <= 10^9`そしてせいぜい`1000`テストケースごとに要求されたトラック。 

大きな限界`t`が重要な制約です。 CD には 10 億のトラックが含まれるため、個々のボタンの押下をシミュレートするには、1 回のトランジションで数億回の操作が必要になる場合があります。 リクエストされたトラックが最大 1000 個ある場合、このようなシミュレーションはおよその範囲に達します。`1000 * 5 * 10^8`、または約`5 * 10^11`最悪の場合、ボタンレベルの操作が可能になります。 要求されたトラックのペアごとに定数時間の計算が必要です。 テスト ケースの数はステートメント内の大きな値によって制限されませんが、合計入力自体は十分に小さいため、`O(s)`ケースごとの解決策が容易に適切になります。 

最初の微妙なケースは、要求されたトラックがまさに自然に再生されるトラックである場合です。 例えば：```
1
5 2
3 4
```正しい出力は次のとおりです。```
0
```アフタートラック`3`フィニッシュ、トラック`4`はすでにキューに入れられています。 不用意に実装すると、現在位置がトラックとして扱われる可能性があります`3`の距離を計算します`1`、ボタンを押す前に CD がすでに自然に進んでいることを忘れてしまいます。 

2 番目の微妙なケースは、CD の終わりに巻き付いています。 例えば：```
1
5 2
5 1
```正しい出力は次のとおりです。```
0
```追跡`1`自然にトラックをたどります`5`なのでボタンは必要ありません。 通常の絶対差分を使用した実装`5`そして`1`誤って取得してしまう`4`。 

3 番目の微妙なケースは、同じトラックを 2 回続けてリクエストすることです。 例えば：```
1
3 3
3 1 1
```正しい出力は次のとおりです。```
1
```アフタートラック`1`フィニッシュ、トラック`2`列に並んでいます。 後方に 1 回押すとトラックに戻ります`1`。 要求された 2 つのトラック番号を単純に比較すると、距離はゼロになりますが、自然なトランジションによってプレーヤーはすでに前方に移動しているため、これは誤りです。 この正確なケースは、3 番目の公式サンプルとして表示されます。 

## アプローチ

 直接的な総当たりソリューションは、文字通り CD プレーヤーをシミュレートできます。 リクエストされた各トラックが終了したら、自然にキューに入れられた次のトラックから開始し、目的のトラックに到達するまで進むボタンまたは戻るボタンを繰り返し押します。 両方の方向を試してプレス回数を数え、小さい方の回数を選択することもできます。 

このアプローチは正しいです。ボタンを押すたびに、キューに入れられたトラックが円形 CD の周囲で 1 つずつ正確に変更されるからです。 ただし、CD には最大 10 億トラックを含めることができるという事実は完全に無視されています。 最悪の場合、要求されたトラックに到達するまでに約`t / 2`、 または`5 * 10^8`、を押します。 リクエストされたトラックが約 1000 曲あると、これはほぼ`5 * 10^11`1 秒間のコンテスト制限をはるかに超えたシミュレーション操作です。 コンテストのレビューでは、CD には最大 10 億トラックが含まれる可能性があり、個々のトランジションをカウントすることは現実的ではないことが明確に指摘されています。 

シミュレーションを削除する観察結果は、すべての遷移が同じ円形構造上で発生するということです。 以前にリクエストされたトラックが`a`。 一度`a`終了すると、プレーヤーはすでにキューに入れられています```
a + 1
```と`t + 1`と解釈される`1`。 キューに入れられたトラックから前方または後方に移動することは、長さのサイクルに沿った移動にすぎません。`t`。 

キューに入れられたトラックを`cur`要求された宛先は`b`。 直線距離は`abs(cur - b)`。 反対方向に移動するとラップアラウンドを通過するため、時間がかかります。`t - abs(cur - b)`を押します。 最適な数値は、これら 2 つの値のうち小さい方です。 

これにより、潜在的に数億回のシミュレートされたプレスから少数の算術演算へのすべての移行が削減されます。 問題全体は、要求されたシーケンスに対する 1 回のパスになります。 公式コンテストのレビューでも同様の削減について説明しており、前の曲が終了した後にキューに入れられたトラックを開始点として使用する必要があると強調しています。

 ## アルゴリズムのチュートリアル

 1. トラック数を読み取る`t`そして要求されたシーケンス。 最初に要求されたトラックは、プレーヤーが最初にキューにあるため、ボタンを押す必要はありません。 
2. 最初に要求されたトラックを前のトラックとして設定します。 以降のすべての遷移は、この値を基準にして計算されます。 
3. 次にリクエストされたトラックごとに`target`、その後自然にキューに入れられるトラックを計算します。`previous`終わります。 1 から始まるトラック番号を使用すると、これは次のようになります。`(previous % t) + 1`。 

このステップでは、ラップアラウンドが自動的に処理されます。 もし`previous == t`、式は生成します`1`、CD の周期的な動作と正確に一致します。 
4. 自然に並んだトラックとトラックの間の通常の距離を計算します。`target`:```
direct = abs(current - target)
```5. 逆方向の距離を計算します。```
wrap = t - direct
```まさにあります`t`完全なサイクルの前後の位置なので、移動した後`direct`片道ステップ、残りのルートには以下が含まれます`t - direct`ステップ。 
6.追加`min(direct, wrap)`答えに。 これは、このトランジションに必要なボタンを押す最小回数です。 
7. 交換`previous`と`target`要求されたすべてのトラックが処理されるまで続行します。 

### なぜ効果があるのか

 不変条件は、遷移を処理する直前に、`previous`は再生が終了したばかりのトラックです。 その結果、`(previous % t) + 1`まさに、何も押さなくてもキューに入れられるトラックです。 その時点から可能なすべてのボタン戦略は、長さのサイクルに沿って移動することです`t`したがって、現在のトラックとターゲットの間に関連する方向は 2 つだけです。 それらの長さは`direct`そして`t - direct`、短い方が最適です。 各遷移は、キューに入れられたトラックの開始が判明すると独立するため、これらの最小遷移コストを合計すると全体的な最小値が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    out = []

    for _ in range(n):
        t, s = map(int, input().split())
        tracks = list(map(int, input().split()))

        ans = 0
        previous = tracks[0]

        for target in tracks[1:]:
            current = previous % t + 1
            direct = abs(current - target)
            ans += min(direct, t - direct)
            previous = target

        out.append(str(ans))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```入力は、元の問題形式と一致するテスト ケースの数から始まります。 各ケースでは、CD サイズ、要求されたトラックの数、および要求されたシーケンスが提供されます。 

最初に要求されたトラックは次の場所に保存されます。`previous`そして答えには何も貢献しません。 これは、プレーヤーがすでにそのトラックにキューされているという初期条件から直接導き出されます。 

その後の各トラックでは、`previous % t + 1`自然にキューに入れられたトラックを計算します。 の`% t`明示的なものよりも好ましい`if previous == t`通常のトラックとラップアラウンドの両方を 1 つの式で処理するため、確認してください。 

値`direct`せいぜい`t - 1`、 それで`t - direct`は常に、円の反対側の周囲の有効な非負の距離です。 Python の整数には任意の精度があるため、2 番目の公式サンプルの答えは次のようになります。`3000000000`特別な整数型は必要ありません。 固定幅の整数型を使用する言語では、累積された応答には 64 ビット整数を使用する必要があります。 コンテストのレビューでも、回答が 32 ビット整数を超える可能性があることについて同様の見解が示されています。 

操作の順序が重要です。 ターゲットと比較する前に、自然にキューに入れられたトラックを計算します。 比較する`previous`直接`target`曲が完了するたびに自動的に 1 トラック進む機能を見逃してしまいます。
