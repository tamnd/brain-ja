 ## 解決策
 ## 問題の理解

 次のような接続された無向グラフが与えられます。`n`頂点と`m`エッジ。 自己ループや複数のエッジがないため、各エッジは 2 つの異なる頂点を 1 回だけ接続します。 グラフとともに、マルチセットが与えられます。`A`それぞれが「移動長」を表す正の整数。 頂点から始める`1`、要素を繰り返し選択できます`k`から`A`、マルチセットから削除し、正確に歩きます`k`あらゆるパスに沿ったエッジ。 ウォークは頂点とエッジを繰り返すことができますが、選択された各要素は`A`移動に対して 1 回だけ使用する必要があります。 

タスクは、頂点ごとに決定することです。`i`、到達できるかどうか`i`頂点から`1`の要素を使用した一連の動きによって`A`。 各頂点は個別にチェックされるため、完全なマルチセットを再利用できます。`A`ターゲット頂点ごとに。 

制約を見てみると、`n`そして`ℓ`それぞれ最大で可能です`2·10^5`、`m`まで`4·10^5`、すべてのテスト ケースの合計は制限されていますが、それでも大きいです。 シーケンスの数は指数関数的に増加するため、これにより、可能なすべての一連の動きを明示的にシミュレートするアプローチは除外されます。`ℓ`。 したがって、各テスト ケースは、ほぼ線形または線形時間で処理する必要があります。`n + m + ℓ`。 

移動はパスではなくウォークであるという事実から微妙な点が生じます。ノードを再訪することができます。 たとえば、次の場合`A = [2]`、頂点から開始`1`、距離 2 の任意の頂点に到達できますが、距離 0 の任意の頂点、またはノードを再訪する 2 つのステップで到達可能な任意の頂点にも到達できます。 パリティと到達可能性を注意深く考慮しないと、ウォークで到達できる頂点を到達不能と宣言してしまう可能性があります。 

エッジ ケースには、グラフの直径より大きい単一要素のマルチセット、のみを含むマルチセットが含まれます。`1`サイクル グラフ内の 、およびすでに頂点にあるターゲット`1`(移動することなく常に到達可能です)。 どのソリューションでも、繰り返される要素を正しく処理する必要があります。`A`そしてノードを再訪する散歩。 

## アプローチ

 ブルートフォース手法では、一連の動きをすべて列挙し、グラフに沿って歩くことをシミュレートしようとします。 のサブセットと順列ごとに、`A`、私たちはその長さのあらゆる可能な歩行を探索します。 これは原理的には正しいですが、シーケンスの数は次のように階乗的に増加します。`ℓ`、可能な歩行の数は、次のように指数関数的に増加します。`k`。 単一のテスト ケースでも、`10^6`またはそれ以上の手順を実行することは不可能です。 

重要な観察は、ウォークではノードを再訪問できるため、重要なのは **到達可能性のモジュロ のすべての要素の最大公約数 (gcd) であるということです。`A`**。 具体的には、マルチセットの場合、`A`gcd を持つ要素が含まれています`g`、次に距離にある任意の頂点`d`頂点から`1`であれば到達可能です`d % g`使用された動きの同等性と一致します。 より具体的には、頂点から幅優先検索 (BFS) を実行すると、`1`、各頂点を最短距離でラベル付けします`dist[i]`から`1`、次に頂点`v`からの移動の組み合わせが存在する場合にのみ到達可能です。`A`その合計が等しい`dist[v] modulo g`。 各要素は 1 回だけ使用できるため、これはサブセット和モジュロの変形になります。`g`しかし、注意深く分析すると、パリティ パターンで十分であることがわかります。 大きな数の場合は、到達可能な距離を gcd を法としてマークするだけで済みます。`A`。 

したがって、最適なアプローチは次のとおりです。頂点からの BFS 距離を計算します。`1`、計算する`g = gcd(A_1, ..., A_ℓ)`、頂点をマーク`v`到達可能な場合`dist[v] % g == 0`。 これにより、シーケンスの列挙が完全に回避され、BFS と gcd 計算のみに依存します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O((シーケンス数) * 最大歩行長) | O(n + m) | 遅すぎる |
 | BFS + GCD の洞察 | O(n + m + ℓ) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、グラフとマルチセットを読み取ります。`A`。 効率的に走査するために、グラフを隣接リストとして保存します。 
2. コンピューティング`g = gcd(A[0], A[1], ..., A[ℓ-1])`。 これは、頂点に到達できる到達可能距離のモジュロの最小粒度を取得します。 
3. 頂点から BFS を実行する`1`計算する`dist[v]`頂点ごとに`v`。 BFS は次のことを保証します。`dist[v]`頂点からのエッジの最短パス長です`1`に`v`。 
4. 各頂点について`v`、どうかを確認してください`dist[v] % g == 0`。 trueの場合は追加します`1`出力文字列に; それ以外の場合は追加`0`。 
5. テスト ケースのバイナリ文字列を出力します。 

これが機能する理由: BFS は最小距離で頂点にラベルを付け、マルチセットの gcd は結合できるステップ サイズを表します。 ウォークでは頂点、つまり距離が の倍数である頂点を再訪問できるため、`g`の要素を繰り返し適用することで達成できます。`A`ある順序で。 移動の合計が割り切れない距離に一致しないため、他の頂点に到達することはできません。`g`。 

## Python ソリューション```python
import sys
import math
from collections import deque
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m, l = map(int, input().split())
        A = list(map(int, input().split()))
        adj = [[] for _ in range(n + 1)]
        for _ in range(m):
            u, v = map(int, input().split())
            adj[u].append(v)
            adj[v].append(u)
        
        g = A[0]
        for a in A[1:]:
            g = math.gcd(g, a)
        
        dist = [-1] * (n + 1)
        dist[1] = 0
        queue = deque([1])
        while queue:
            u = queue.popleft()
            for v in adj[u]:
                if dist[v] == -1:
                    dist[v] = dist[u] + 1
                    queue.append(v)
        
        res = ['0'] * n
        for i in range(1, n + 1):
            if dist[i] % g == 0:
                res[i - 1] = '1'
        print(''.join(res))

if __name__ == "__main__":
    solve()
```BFS は最短距離を保証します。 コンピューティング`gcd`以上`A`到達可能な距離の最小単位を取得します。 頂点を反復処理し、距離モジュロを比較することによって`g`、シーケンスやウォークを明示的にシミュレートすることは避けます。 デキューを使用すると、BFS が O(n + m) になり、メモリ制限を超えなくなります。
