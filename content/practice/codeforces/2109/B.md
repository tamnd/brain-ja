 ## 解決策
 ## 問題の理解

 次のサイズの長方形グリッドが与えられます。$n \times m$、および最初にセルに配置された単一のトークン（モンスター）$(a, b)$。 2 人のプレイヤーが交互に決定を行いますが、通常の意味で交互にターンを行うのではなく、各ターンは 2 つのフェーズで構成されます。まず、行または列のライン全体に沿って現在の長方形を切り取り、次に残りの長方形内の任意の場所にモンスターを再配置します。 

カットは基板サイズを縮小する唯一の操作です。 各カットの後、対戦相手は残りの四角形内でモンスターの位置を自由に変更できます。これは事実上、次のターン以降、モンスターの位置が以前の動きによって制限されなくなることを意味します。 ゲームは長方形が単一のセルになるまで続きます。目標は、一方のプレイヤーがカット数を最小限に抑えようとし、もう一方のプレイヤーがカット数を最大化しようとする最適なプレイでこのプロセスに何ターンかかるかを決定することです。 

重要な観察は、最初のカットの後、モンスターは任意に移動できるため、正確な初期位置は長期的には重要性を失うということです。 これにより、各カットが選択した点を含む部分を維持することしか保証できない場合、基本的に長方形をどれだけ早く縮小できるかが問題になりますが、対戦相手は常に再配置して将来のカットをできるだけ非効率にします。 

制約$n, m \le 10^9$グリッドまたは段階的な削減のシミュレーションを直ちに除外してください。 実行可能なソリューションでは、対数推論または閉じた形式の式を使用して、テスト ケースごとに一定時間で答えを計算する必要があります。 

たとえば、1 つの次元がすでに小さい場合、微妙なエッジ ケースが発生します。$1 \times m$または$n \times 1$。 このような場合、切断は一方向のみ可能であり、両方の寸法が同時に縮小することを前提とした貪欲な対称性の議論は過大なカウントにつながる可能性があります。 

もう 1 つの注意が必要なシナリオは、開始位置が端に近い場合です。 たとえば、$2 \times 7$列 2 にモンスターを配置したグリッドでは、初期の最適なカットにより、モンスターが中央で開始された場合よりもはるかに小さなサブグリッドが分離される可能性があります。 無視した素朴なアプローチ$(a, b)$最初の動きは特殊であり、非対称性に依存するため、このような場合は完全に失敗します。 

## アプローチ

 ブルートフォース解釈では、ゲーム状態を長方形としてシミュレートし、対戦相手がモンスターの位置を変更することを常に想定して、可能な限りの水平方向または垂直方向のカットを繰り返し試行します。 各状態は次のように定義されます。$(n, m)$、トランジションでは、モンスターを片側の内側に保ちながら長方形を分割するために可能なすべての方法が試行されます。 ただし、すべての状態を表す場合でも、すでに次のようになります。$O(nm)$各トランジションは可能なカット位置のスキャンに依存するため、完全に実行不可能になります。 

重要な洞察は、最初の動きの後、モンスターの自由により位置の制約が取り除かれるため、問題は最悪の形で繰り返し半分の次元に崩壊するということです。 最適な戦略は次のようになります。カットごとに行または列の数が減り、対戦相手はカット後の残りの部分が常に可能な限り大きなセグメントになるようにします。 

2 ターン目以降、このプロセスは長方形を繰り返し切断するように動作し、移動するたびに次のいずれかの値が減少します。$n$または$m$進行を最小限に抑える分割を選択することによって。 これにより、問題は各次元の対数縮小プロセスに変わります。 唯一厄介なのは最初の動きです。最初の位置は$(a, b)$潜在的に非対称な最初のカットが可能になり、1 つの次元をすぐに次のいずれかに縮小できます。$a$または$n-a+1$、列についても同様です。 

したがって、解決策は、最初のカットによって得られた 4 つの開始長方形の候補を評価し、結果として得られる各長方形を次のサイズに縮小するのに必要なカットの数を計算することになります。$1 \times 1$、常に寸法の最適な交互収縮を仮定します。

 ## アルゴリズムのチュートリアル

 最初の動きは、モンスターの初期位置がカットを制限する唯一の瞬間であるため、最初の動きは別個に扱います。 

1. 水平方向の最初のカットを検討します。 モンスターの上または下をカットして、高さのグリッドを残すことができます$a$または$n-a+1$、幅は残ったまま$m$。 最小化するプレーヤーがより良いカットを選択するため、結果として小さい方の高さを採用します。 
2. 同様に、垂直方向のファーストカットを考えます。 これにより、次のサイズのグリッドが生成されます。$n \times b$または$n \times (m-b+1)$、再び小さい幅を維持します。 
3. 次に関数を定義します$f(x, y)$これは、ターン数を減らすために必要なターン数を表します。$x \times y$長方形に$1 \times 1$モンスターが常に最適な位置に移動できるとき。 
4. 1 ターンで、プレイヤーはカットを選択することでどちらかの次元を減らすことができますが、対戦相手は結果として生じる有効な位置が常に最悪の場合の将来の削減を強制することを保証します。 これは、必要な半分化ステップの数に関して、各次元が独立して動作することを意味します。 
5. したがって、$f(x, y)$は両方の次元を 1 に減らす必要がある回数に等しく、各移動で 1 つの次元を可能な限り減らしますが、それは 2 つの部分に分割し、大きい方の次元を維持することによってのみです。 

実際には、各次元はカット後に大きい方の半分を繰り返し取得するように動作します。これは、最悪の場合、繰り返し 2 で除算することに相当します。 

次のように計算します。 

-$f(x, y) = \lceil \log_2(x) \rceil + \lceil \log_2(y) \rceil$最後に、4 つの初手結果すべてを評価し、最初のカットを含む最小合計ターン数を取得します。 

### なぜ効果があるのか

 最初のカットの後、モンスターは将来のカットのために常に最悪の位置に再配置される可能性があります。 これにより、位置メモリが削除され、各寸法が独立した縮小プロセスに変換され、各カットではその寸法の最大で 1 つのバイナリ スケール レベルが縮小されます。 カットでは 1 回転につき 1 つの軸のみを分割できるため、回転の合計数は、両方の軸に沿って必要な半分のステップ数を累積します。 初期位置は最初の縮小にのみ影響し、その後、プロセスは完全に対称で状態に依存しなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ceil_log2(x):
    # smallest k such that 2^k >= x
    k = 0
    v = 1
    while v < x:
        v <<= 1
        k += 1
    return k

def solve_case(n, m, a, b):
    # first cut horizontally
    h1 = min(a, n - a + 1)
    v1 = m

    # first cut vertically
    h2 = n
    v2 = min(b, m - b + 1)

    def f(x, y):
        return ceil_log2(x) + ceil_log2(y)

    # we already spend 1 turn on the first cut
    ans = 10**18

    ans = min(ans, 1 + f(h1, v1))
    ans = min(ans, 1 + f(h2, v2))

    return ans

t = int(input())
out = []
for _ in range(t):
    n, m, a, b = map(int, input().split())
    out.append(str(solve_case(n, m, a, b)))

print("\n".join(out))
```最初の動きはモンスターの位置が重要な唯一のポイントであるため、実装では最初の動きを明示的に分離します。 ヘルパーさん`ceil_log2`次元が 1 に達するまでに何回半分にする必要があるかを計算します。これは、敵対的な再配置の下での最悪のケースの貪欲な分割を直接モデル化します。 

機能`solve_case`最初のカットの可能な両方の方向を評価します。 方向ごとに、結果として得られる長方形を計算し、それを完全に縮小するコストを追加します。 最終的な答えは、これら 2 つの可能性の最小値です。 

実装の微妙な点は、交互の選択肢を明示的にシミュレートしないことです。 対戦相手の最適な動作は、対数モデルで結果として得られるより大きなセグメントを常に取得することによってすでにエンコードされているため、分岐するゲーム ツリーを回避します。

 ## 特殊なケース

 あ$1 \times m$または$n \times 1$グリッドは 1 つの自由度を即座に削除します。 対数項の 1 つがゼロになり、最初のカットが直接 1 次元の問題に帰着するため、アルゴリズムはこれを正しく処理します。 

例えば、$1 \times 8$どれでも$b$得られるもの:

 横方向のカットは不可能なので縦方向のみで製作します。$1 \times 4$、 それから$1 \times 2$、 それから$1 \times 1$、3ターンを与えます。 式によって生成されるのは、$\lceil \log_2 8 \rceil = 3$、正確に一致します。 

モンスターが境界付近からスタートした場合$(1, m)$、水平方向の最初のカットは非常に非対称であり、高さがすぐに 1 に減少するため、将来のコストを大幅に削減できます。 アルゴリズムはこれを次のように取得します。$\min(a, n-a+1)$、対称性を前提とするのではなく、カットの最適な側が常に選択されるようにします。 

次のような完全に対称な中心スタート$(\frac{n}{2}, \frac{m}{2})$両方のファーストカットオプションを同等にします。 アルゴリズムは両方を自然に評価してより良い方を選択し、恣意的なタイブレークに依存しないようにします。
