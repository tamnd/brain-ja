 ## 解決策
 ## 問題の理解

 プレイヤーの列が与えられ、各プレイヤーはすぐ隣のプレイヤーと決闘に参加します。プレイヤー 1 はプレイヤー 2 と決闘し、プレイヤー 2 はプレイヤー 3 と決闘し、プレイヤーが決闘するまで続きます。$n-1$デュエルプレイヤー$n$。 結局$n-1$決闘では、各プレイヤーは少なくとも 1 つの決闘に勝ったかどうかを報告します。 レポートは 2 値です。プレイヤーが決闘に勝てなかったと主張する場合は 0、少なくとも 1 つで勝利したと主張する場合は 1 です。 

タスクは、少なくとも 1 つのレポートが虚偽である必要があるかどうかを判断することです。 言い換えれば、0 と 1 のシーケンスが、各決闘で 1 人のプレイヤーが勝つというルールと一致しているかどうかを確認する必要があります。 矛盾がある場合、たとえば、連続する 2 人のプレイヤーが両方とも 0 を報告する (どちらも決闘に勝てない)、または連続する 2 人のプレイヤーが両方とも少なくとも 1 回の決闘に勝つことが不可能な方法で 1 を報告するなど、少なくとも 1 つの報告は虚偽です。 

制約は小さく、テスト ケースは最大 100 件、各テスト ケースには最大 100 人のプレイヤーが含まれます。 これにより、次のようなアルゴリズムが可能になります。$O(n)$テストケースごとに快適に、そして均一に$O(n^2)$おそらく実行されますが、これは 1 回のパスで解決できます。 

ラインの端では、明らかではないエッジケースが発生します。 たとえば、最初のプレイヤーと 2 番目のプレイヤーが両方とも 0 の場合、最初のデュエルには勝者が必要なので不可能です。 同様に、最後の 2 人のプレイヤーが両方とも 0 の場合、それは不可能です。 0 と 1 が交互に続くようなシーケンスは一般に一貫性がありますが、どこにでも 2 つ連続する 0 がある場合は、すぐに嘘つきであることを暗示します。 2 つ連続した 1 は必ずしも嘘つきを意味するわけではありません。それぞれが異なる決闘で勝った可能性があるからです。 

## アプローチ

 ブルートフォースアプローチでは、ライン構造と一致する可能性のあるすべての決闘結果をシミュレートし、各プレイヤーの報告を検証しようとします。 これには、勝者のすべての割り当てを生成することが含まれます。$n-1$決闘し、0/1 レポートと一致するかどうかを確認します。 正しいですが、これは不必要であり、次のような場合には指数関数的です。$n$。 たとえ$n=100$、それは計算上不可能です。 

重要な洞察は、すべての決闘をシミュレートする必要はないということです。 各決闘は 2 人の参加者のみに影響を及ぼし、唯一不可能な構成は、連続する 2 人のプレイヤーが両方とも 0 を主張する場合です。これは、プレイヤー間の決闘であるためです。$i$そして$i+1$、少なくともどちらかが勝たなければなりません。 したがって、もし$a_i = 0$そして$a_{i+1} = 0$、両方の報告が真実であることは不可能であり、すぐに嘘つきがいると結論付けることができます。 

他のすべてのシーケンスは一貫しています。 単一の 1 は、そのプレイヤーが関与する何らかの決闘で勝利したことを保証します。1 で区切られた 0 は、隣接する決闘の 1 つの勝利を表すことができるため許容されます。 したがって、最適な解決策は、配列をスキャンして連続する 0 のペアを見つけることになります。

 | ブルートフォース | O(2^(n-1)) | O(n) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、プレーヤーの数を読み取ります。$n$そして一連のレポート$a$。 
2. 最初のプレーヤーから最後から 2 番目のプレーヤーまで配列を反復処理します。 インデックスごとに$i$、どうかを確認してください$a[i] = 0$そして$a[i+1] = 0$。 
3. そのようなペアが見つかった場合は、少なくとも 1 人のプレーヤーが嘘をついていると直ちに結論付け、「YES」を出力します。 
4. 連続する 0 が見つからずに反復が完了した場合、すべてのレポートは何らかの決闘結果と一致するため、「NO」を出力します。 

それが機能する理由: 不変条件は、すべての決闘で 1 人の勝者が生み出されなければならないということです。 2 人の連続プレイヤーが 0 を報告すると、この不変条件に直接矛盾します。 決闘のその他の構成はレポートに違反できないため、嘘つきを検出するには連続した 0 をスキャンするだけで十分です。 他のすべてのシーケンスは、勝者の割り当ての下で可能です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    liar_found = False
    for i in range(n - 1):
        if a[i] == 0 and a[i + 1] == 0:
            liar_found = True
            break
    print("YES" if liar_found else "NO")
```解決策は、テスト ケースの数を読み取ることから始まります。 各テストケースについて、次のように読みます。$n$そして一連のレポート。 次に、最初のプレーヤーから最後から 2 番目のプレーヤーまでループして、連続する 0 をチェックします。 見つかった場合はフラグを設定し、不必要なチェックを避けるために早めに休憩します。 最後に、嘘つきが存在する場合は「YES」を出力し、そうでない場合は「NO」を出力します。 高速 I/O を使用すると、複数のテスト ケースでのタイミングの問題が回避されます。

 ## 特殊なケース

 最初のエッジ ケースは、先頭に連続するゼロです。たとえば、`0 0 1`。 アルゴリズムはペアをチェックします`(0,1)`、つまり`(0,0)`ここに、セット`liar_found = True`、そしてYESを出力し、嘘つきを正しく識別します。 もう 1 つのエッジ ケースは、末尾にゼロが連続する場合です。たとえば、`1 0 0`。 アルゴリズムは最後のペアまで反復されます`(0,0)`また、YES も正しく出力されます。 次のような交互シーケンス`0 1 0 1`連続するゼロがスキャンされますが、何も見つからないため、アルゴリズムは NO を出力し、勝利がラインに沿って分散される有効なシナリオを正しく許可します。 これらのエッジ ケースは、ソリューションが境界を適切に処理していることを確認します。
