 ## 解決策
 ## 問題の理解

 バイナリ文字列が与えられます`s`長さの`n`そして整数`k`。 私たちの任務は正確に実行することです`k`それぞれの操作は、現在の文字列内のゼロを選択し、先頭からそのゼロまでのすべてのビットを反転します。 目標は、次の異なるシーケンスが何個あるかを数えることです。`k`操作が存在します。 いずれかのステップで異なるインデックスを選択した場合、2 つのシーケンスは異なるものとみなされます。 

制約は中程度です。`n`最大 500 まで上げることができ、`k`せいぜい`n`。 これにより、指数関数的に複雑なソリューションは除外されます。`n`または`k`。 理想的には多項式が必要です`O(n * k)`または`O(n^2)`テストケースごとに。 の合計`n`すべてのテスト ケースの上限は 500 であるため、入れ子になったループを許容できます。`n`必要に応じて。 

明らかではないエッジ ケースには、すべて 0 またはすべて 1 の文字列が含まれます。 たとえば、次の場合`s = "000"`そして`k = 3`、単純なカウントでは、同じプレフィックスを複数回反転するシーケンスを過剰にカウントする可能性があります。 もう 1 つの注意が必要なケースは次のような場合です。`k`最初は文字列内のゼロの数よりも大きくなります。 インデックスを選択することはできません。`1`, したがって、反転履歴が重要です。 小さな文字列のような`"0"`と`k=1`または`"1"`と`k=1`オフバイワンの間違いも明らかにします。 

## アプローチ

 ブルートフォースアプローチは簡単です。 すべてのインデックスを再帰的に試すことができます`i`どこ`s[i]`がゼロの場合、接頭辞を反転して再帰します`k-1`もっと何度も。 これは操作のすべてのシーケンスを調査するので正しいですが、遅すぎます。 最悪の場合、各操作で選択できるのは次のとおりです。`n`インデックスがあり、`k`操作、与える`O(n^k)`複雑さは、たとえ小さいものであっても天文学的に大きくなる`n`。 

重要な洞察は、重要なのは各反転後の文字列内のゼロの数とそれらの相対位置だけであることを認識することです。 プレフィックスを反転すると、そのプレフィックス内のすべてのビットが切り替わり、次の操作で使用できるゼロが変わります。 ゼロの数と残っている演算の数に関する動的プログラミングを使用して、これをモデル化できます。 具体的には、DP テーブルを維持できます。`dp[i][j]`実行方法の数を表す`i`最初のことを考慮した操作`j`現在の文字列構成ではゼロ。 これにより、問題はフリップのすべてのシーケンスの探索から有効なサブシーケンスのカウントに軽減され、複雑さの多項式になります。 

ゼロの数は最大でも`n`これにより、DP テーブルに文字列の位置ではなくゼロでインデックスを付けることができるようになり、状態の数が大幅に減少します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^k) | O(n*k) | 遅すぎる |
 | ゼロの DP | O(n*k) | O(n*k) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.文字列を変換する`s`ゼロの位置のリストに変換します。 プレフィックスを反転すると、今後の操作で使用できるゼロが変わるため、ゼロの順序は重要です。 このリストを次のように示します`zeros`。 
2. DP テーブルの初期化`dp`寸法付き`(k+1) x (len(zeros)+1)`。 ここ、`dp[i][j]`は実行方法の数を表します`i`最初のものを使用した操作`j`ゼロ。 セット`dp[0][0] = 1`基本ケースとして、ゼロゼロを使用したゼロ操作は 1 つの有効なシーケンスです。 
3. 反復する`i`1から`k`、これまでに実行された操作の数を表します。 
4. それぞれについて`j`1から`len(zeros)`、最初のものを表します`j`ゼロ、更新`dp[i][j]`合計することで`dp[i-1][p]`みんなのために`p < j`。 このモデルは、`j`-番目のゼロをターゲットとして`i`実行後の - 回目の操作`i-1`最初の操作`p`ゼロ。 プレフィックスを選択することで、各操作が有効であることが保証されます。 
5. DP テーブルに記入すると、答えは次の合計になります。`dp[k][j]`みんなのために`j`1から`len(zeros)`。 これは、正確に実行されたすべてのシーケンスをカウントします。`k`操作。 

機能する理由: 各 DP 状態は、考慮される操作の数とゼロのサブセットによってシーケンスを正しくカウントします。 トランジションは、ゼロで終わるプレフィックスのみを反転できるという制限を反映しています。 モジュラー演算は大きなカウントを処理します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        s = input().strip()
        zeros = [i for i, ch in enumerate(s) if ch == '0']
        m = len(zeros)
        if k > m:
            print(0)
            continue

        dp = [[0]*(m+1) for _ in range(k+1)]
        dp[0][0] = 1

        for i in range(1, k+1):
            prefix_sum = [0]*(m+1)
            for j in range(m+1):
                prefix_sum[j] = (prefix_sum[j-1] + dp[i-1][j]) % MOD if j else dp[i-1][j]
            for j in range(1, m+1):
                dp[i][j] = prefix_sum[j-1]

        ans = sum(dp[k][1:]) % MOD
        print(ans)

if __name__ == "__main__":
    solve()
```最初のセクションは入力を読み取り、ゼロの位置を構築します。 DP テーブルはディメンションで初期化されます`(k+1) x (number of zeros +1)`。 プレフィックス合計配列を使用して、DP 遷移の前のすべての状態の合計を効率的に計算します。 最終的な答えは、正確に対応する DP テーブルの最後の行の合計です。`k`操作。 Off-by-one エラーは、慎重にインデックスを作成することで回避されます。`dp[i][j]`最初に対応します`j`文字列内の位置ではなく、ゼロです。 の`if k > m`チェックは不可能なケースにも迅速に対応します。 

## 実用的な例

 トレースサンプル 1:`s = "010"`、`k=1`。 

| i (操作) | j (ゼロを考慮) | dp[i][j] |
 | --- | --- | --- |
 | 0 | 0 | 1 |
 | 1 | 1 | 1 |
 | 1 | 2 | 1 |

 ゼロは位置にあります`[0, 2]`。 単一の操作ではいずれかのゼロを選択できます。 の合計`dp[1][1:]`= 1+1 = 2、これは予想される出力と一致します。 

トレースサンプル 2:`s = "000"`、`k=2`。 

ゼロ`[0,1,2]`。 DP テーブルは次のように更新されます。 

| 私 | dp[i][1] | dp[i][2] | dp[i][3] |
 | --- | --- | --- | --- |
 | 1 | 1 | 1 | 1 |
 | 2 | 0 | 1 | 2 |

 答え = sum(dp[2][1:]) = 0+1+2=3、予想される出力と一致します。 

これらのトレースは、アルゴリズムがオーバーカウントすることなくすべてのシーケンスをカウントしていることを確認します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n*k) | k 個の演算のそれぞれについて、最大 n 個のゼロにわたる DP 行を計算します。 プレフィックス合計により、内部合計が O(1) に減ります。 |
 | スペース | O(n*k) | DP テーブルには、(k+1)*(ゼロの数 +1) 個のエントリがあります。 |

 n ≤ 500、k ≤ 500 の場合、これは 2 秒以内、256MB 以内に収まります。
