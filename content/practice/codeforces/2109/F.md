 ## 解決策
 ## 問題の理解

 私たちは次のことに取り組んでいます$n \times n$各セルが 2 つの属性を持つグリッド: 重み$a_{i,j}$そして色は黒か白のどちらかです。 2 人のプレーヤーはグリッドの左側の異なる位置からスタートし、どちらも右端の列の同じ出口セルに到達することを目指します。 パスのコストはその合計ではなく、訪問したすべてのセルの最大値です。 

これにより、各パスの問題がミニマックス最短パス問題に変わります。つまり、途中で発生する最悪のセル値を最小化しようとします。 

Mouf (左上の開始) と Fouad (左下の開始) にはそれぞれ、出口までの最適なミニマックス パス コストがあります。 これらは$\mathrm{dis}_M$そして$\mathrm{dis}_F$。 

移動する前に、Mouf は黒セルの値を最大まで増やすことができます。$k$合計増分は、黒のセル全体に任意に配分されます。 白血球は不変です。 重要な制約は微妙です。変更後、Mouf 自身の最適パス コストは変更前とまったく同じでなければなりませんが、Fouad の最適コストはできるだけ大きくなければなりません。 

したがって、このタスクは、ミニマックス最短パス構造上の制約付き敵対的変更問題です。 

グリッドのサイズは最大です$300 \times 300$、テスト全体のセルの合計は約$9 \cdot 10^4$。 これは次のことを強く示唆しています$O(n^3)$または、値ごとの最短パスの計算を繰り返すものは境界線にありますが、慎重に最適化すれば許容できる可能性があります。 BFS/0-1 スタイルの伝播によるテストごとの最短パスが 1 つあれば問題ありませんが、変更ごとにフローを再計算することは不可能です。 

最も危険な落とし穴は、すべての黒セルを貪欲に増やしたり、各パスを個別に最適化できると仮定することです。 Mouf の最短ボトルネック パスは変更されないままでなければならないという制約により、すべての変更がグローバルに結合されます。 

2 番目の微妙な失敗例は、セルを増やすことが常に Fouad に役立つと考えていることです。 そのセルが現在のボトルネックを回避する、Mouf の可能な代替パス上にある場合、そのセルを増やすと、Mouf の最適なパスが誤ってより悪いパスに変更される可能性があります。 

最小限の図:

 Mouf に 2 つのパスがある場合を考えてみましょう。 

- パス A の最大値は 5 です
 - パス B の最大値は 6

 それで$\mathrm{dis}_M = 5$。 パス A の黒セルを 5 より大きくすると、パス A はコスト 5 で無効になり、ムフはパス B に強制的に移動し、増加します。$\mathrm{dis}_M$、これは禁止されています。 

したがって、いかなる変更も、Mouf のミニマックス パスのしきい値構造全体を尊重する必要があります。 

## アプローチ

 最初の自然な試みは、可能な増分セットごとに Mouf と Fouad のミニマックス パス コストを再計算することです。 たった 1 つの増分でも最短パスがグローバルに変更されるため、この問題はすぐに爆発します。$k$できる$10^6$。 

2 番目の試みは計算です$\mathrm{dis}_M$一度、それをしきい値として扱います$T$そして、Mouf がどのパスでもこのしきい値を超えることなく、任意の黒セルを自由に増やすことができると仮定します。 これは正しい値に近づいていますが、セルを上に上げるとまだ不完全です。$T$以前に達成されたすべてのパスを削除することで、Mouf の現在の最適な構造を無効にする可能性があります$T$、厳密に悪いパスを強制します。 

重要な構造的洞察は次のとおりです。$\mathrm{dis}_M$はミニマックス パス値であるため、実現可能性条件によって定義されます。つまり、からのパスが存在します。$(1,1)$に$(r,n)$最大でも値を持つセルのみを使用する$T$、 どこ$T = \mathrm{dis}_M$ですが、これより小さいしきい値に対するパスは存在しません。 これは、グリッドをすべてのノードが含まれるグラフとして表示できることを意味します。$a_{i,j} \le T$ソースとターゲットの間に接続構造を形成します。 

Mouf は黒セルを増やすことができますが、少なくとも 1 つの有効な黒セルの存在を維持する必要があります。$T$- 境界のあるパス。 したがって、いくつかの場所にある黒セルは、$T$- 境界のあるパスは「危険」です: それ以上に増やします$T$接続にとって重要な場合、そのようなパスはすべて遮断される可能性があります。 

これにより、問題が到達可能性と最小カット スタイルの構造に変換されます。少なくとも 1 つのセルを維持するためにどのセルが不可欠であるかを特定します。$T$-Mouf の境界付きパス。 これらの細胞はこれ以上増やすことはできません$T$。 他のすべての黒セルは自由に増やすことができます。 

禁止されたセットが決定されると、Mouf は残りの演算を使用して Fouad のボトルネックを最大化します。 Fouad のコストもミニマックスしきい値の問題ですが、修正されたグリッドでは、Mouf の制約に違反することなく、いくつかの黒セルが可能な限り増加されています。 

したがって、問題を次のように整理します。 

最初の計算$\mathrm{dis}_M$ミニマックス形式の標準最短パス経由。 次に、しきい値以下の少なくとも 1 つの最適な実行可能パスに参加するセルのセットを計算します。$T$。 次に、どの黒セルを増やしても安全かを判断します。 最後に、増分を最悪の場合に割り当てて、Fouad のミニマックス パスを再計算します。 

重要な削減点は、増分を明示的にシミュレートしないことです。 代わりに、セルを制約付きと制約なしに分類し、制約されていない黒セルを Fouad のパス計算用に任意の大きさとして扱います。 

これは基本的に、最短パスのしきい値処理と、制約されたサブグラフの下での到達可能性の組み合わせです。

 ## アルゴリズムのチュートリアル

 1. コンピューティング$\mathrm{dis}_M$状態コストがパスに沿った最大セル値である最良優先検索を使用します。 各ステップでは、最大遷移ルール​​を使用して近傍を緩和します。 これにより最小しきい値が生成されます$T$ムフが届くように$(r,n)$から$(1,1)$。 
2. 「Mouf 最適しきい値の下で許可」というバイナリ条件グリッドを構築します。ここで、セルは次の場合に通過可能です。$a_{i,j} \le T$。 
3. からの前方到達可能性を実行します。$(1,1)$このフィルタリングされたグリッド上で、値制約の下で到達可能なすべてのセルをマークします。$T$。 
4. から後方到達可能性を実行します。$(r,n)$同じ制約の下で。 
5. これら 2 つの到達可能性セットを交差させます。 交差点内のセルはいずれも、少なくとも 1 つの有効な最適パス上にあり、$\mathrm{dis}_M$。 これらのセルは、Mouf の最適な値を維持するために構造的に必要です。 
6. これらの交差セルのうち、黒いセルを特定します。 これらはすべての実現可能な最適な構造上にあるため、恣意的な大幅な増加は禁止されています。 
7. 他のすべての黒セルは、可能な値よりも大きな値まで増やすことができます。$\mathrm{dis}_F$ムフの実現可能性に影響を与えることなく候補者を決定します。 
8. 以下の場合に、Fouad の変更されたグリッドを構築します。 

- 禁止された黒セルは元の値を保持します。 
- 安全な黒セルは非常に大きな値として扱われます。 
- 白セルは変化しません。 
9. コンピューティング$\mathrm{dis}_F$この変更されたグリッド上で、同じミニマックス最短パス法を使用します。 

### なぜ効果があるのか

 値$\mathrm{dis}_M$によって引き起こされるサブグラフ内のパスの存在によって完全に決定されます。$a_{i,j} \le T$。 そのようなパスに参加していないセルは、達成の可能性とは無関係です。$T$。 これらのセルを増やしてもすべてを削除することはできません$T$- 代替パスがすでにバイパスしているため、実行可能なパス。 前方到達可能性と後方到達可能性の交差により、少なくとも 1 つの有効なノードに属するすべてのノードの結合が正確にキャプチャされます。$T$-制限されたパスなので、これらのノードを維持することで、$\mathrm{dis}_M$は変わらないままです。 このセットの外側にあるものはすべて、しきい値での到達性に影響を与えることなく任意に変更できます。$T$これにより、Mouf の制約が Fouad の最適化から明確に分離されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import heapq

INF = 10**18

def dijkstra_minimax(sr, sc, grid):
    n = len(grid)
    dist = [[INF] * n for _ in range(n)]
    pq = []
    dist[sr][sc] = grid[sr][sc]
    heapq.heappush(pq, (dist[sr][sc], sr, sc))

    while pq:
        cost, r, c = heapq.heappop(pq)
        if cost != dist[r][c]:
            continue
        for dr, dc in ((1,0),(-1,0),(0,1),(0,-1)):
            nr, nc = r + dr, c + dc
            if 0 <= nr < n and 0 <= nc < n:
                ncost = max(cost, grid[nr][nc])
                if ncost < dist[nr][nc]:
                    dist[nr][nc] = ncost
                    heapq.heappush(pq, (ncost, nr, nc))
    return dist

def solve():
    t = int(input())
    for _ in range(t):
        n, r, k = map(int, input().split())
        r -= 1

        a = [list(map(int, input().split())) for _ in range(n)]
        c = [input().strip() for _ in range(n)]

        distM = dijkstra_minimax(0, 0, a)
        T = distM[r][n-1]

        passable = [[a[i][j] <= T for j in range(n)] for i in range(n)]

        def bfs(sr, sc):
            vis = [[False]*n for _ in range(n)]
            q = [(sr, sc)]
            vis[sr][sc] = True
            for r0, c0 in q:
                pass
            from collections import deque
            dq = deque(q)
            while dq:
                x, y = dq.popleft()
                for dx, dy in ((1,0),(-1,0),(0,1),(0,-1)):
                    nx, ny = x + dx, y + dy
                    if 0 <= nx < n and 0 <= ny < n:
                        if not vis[nx][ny] and passable[nx][ny]:
                            vis[nx][ny] = True
                            dq.append((nx, ny))
            return vis

        reachS = bfs(0, 0)
        reachT = bfs(r, n-1)

        safe_black = [[False]*n for _ in range(n)]
        for i in range(n):
            for j in range(n):
                if reachS[i][j] and reachT[i][j]:
                    if c[i][j] == '1':
                        safe_black[i][j] = True

        BIG = 10**18
        mod_grid = [[a[i][j] for j in range(n)] for i in range(n)]

        for i in range(n):
            for j in range(n):
                if c[i][j] == '1' and not safe_black[i][j]:
                    mod_grid[i][j] = BIG

        distF = dijkstra_minimax(n-1, 0, mod_grid)

        print(T, distF[r][n-1])

if __name__ == "__main__":
    solve()
```コードはまず、パス コストが合計ではなく最大値として定義されるダイクストラのような伝播を使用して、Mouf の最小しきい値を計算します。 結果として得られる距離行列は、すべてのセルに可能な最小限のボトルネック値を与えます。 

固定後$T$、グリッドは、Mouf が使用できるセルにフィルタリングされます。 このフィルタリングされたグリッド内の両方のエンドポイントからの BFS は、どのセルが最適なセルの一部であるかを正確に特定します。$T$-実現可能なルート。 

この交差点の外側にある黒いセルは完全にアップグレード可能として扱われるため、非常に大きな値に置き換えられます。 これにより、Fouad の最短のボトルネック パスが可能であれば回避せざるを得なくなり、最適コストが増加します。 

最後に、Fouad の最小距離がこの変更されたグリッド上で計算されます。 

実装の微妙な点は、「安全な黒セル」のマークは、到達可能性と色の両方に依存する必要があることです。 白いセルは変更できないため、Mouf の予算と相互作用しないため、交差点内の黒いセルのみが制約されます。

 ## 特殊なケース

 重要なエッジケースは、Mouf の最適パスが一意である場合です。 その状況では、前方と後方の到達可能性の交差点は単一の狭い通路に崩壊します。 その廊下にある黒いマスはすべて完全に凍結されます。 BFS 交差により単一のチェーンが自然に識別されるため、アルゴリズムはこれを正しく処理します。 

複数の互いに素な最適パスが存在する場合、別のエッジ ケースが発生します。 単純な解決策では、任意のパスに出現するすべての黒セルをロックする可能性がありますが、正しいアプローチでは、パス内の前方到達可能性と後方到達可能性の交差点に存在する黒セルのみがロックされます。$T$-有界グラフ。 これにより、本当に避けられないセルのみが保護され、Fouad の最適化の柔軟性が維持されます。
