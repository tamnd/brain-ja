 ## 解決策
 ## 問題の理解

 それぞれ固定色を持つプラットフォームの線形シーケンスと、各色のすべてのプラットフォームのアクティブ化に関連するコストが与えられます。 最初は、すべてのプラットフォームが非アクティブ化されています。 プラットフォームから次のプラットフォームにジャンプすること、またはその後のプラットフォームにスキップすることのみが可能です。 目標は、色のサブセットをアクティブにして、アクティブ化されたプラットフォームのみを使用して最初のプラットフォームから最後のプラットフォームまでパスが存在するようにしながら、アクティブ化の総コストを最小限に抑えることです。 

入力サイズは最大 300,000 プラットフォームまで可能ですが、異なる色は最大 40 色までです。 これは、プラットフォームのみを反復処理することは可能ですが、アクティブ化されたプラットフォームのすべての組み合わせを直接試すことは不可能であることをすぐに示唆しています。 色の数が少ないということは、ビットマスクを使用して色のサブセットを表現することで問題の構造を利用できることを示唆しています。 

明らかではないエッジケースには、最初または最後のプラットフォームが非常に高価な色を持っているシナリオが含まれます。 たとえば、最初のプラットフォームがカラー 2、コスト 10,000 で、他のすべてのプラットフォームが安価である場合、最初と最後のプラットフォームがアクティブ化されていることを保証しない単純なアプローチでは、誤って低い総コストが報告される可能性があります。 もう 1 つのエッジ ケースは、複数の連続するプラットフォームが同じ色である場合です。 不注意なアルゴリズムにより、各プラットフォームを色ごとではなく個別にアクティブ化すると、コストが複数回カウントされる可能性があります。 

具体的な小さな例: 5 つのプラットフォーム`[1,3,2,3,1]`カラーコストあり`[1,10,100]`。 最適な解決策は、色 2 を単独でまたはすべての色をアクティブにするのではなく、コスト 11 の色 1 と 3 をアクティブにすることです。 単純に貪欲なアプローチでは、誤ってカラー 1 またはカラー 2 のみをアクティブ化し、有効なパスの作成に失敗する可能性があります。 

## アプローチ

 強引な解決策は、色のすべてのサブセットを試し、それらの色のプラットフォームをアクティブにして、最初から最後まで有効なパスが存在するかどうかを確認することです。 のために`m`色、あります`2^m`サブセット。 各サブセットについて、プラットフォーム配列を走査して、パスが実行可能かどうかを確認します。 たった40色でも、`2^40`可能性は約 1 兆個あり、これは大きすぎます。 このアプローチは、考えられるすべての色のアクティベーションを明示的に列挙しているため、原理的には正しいですが、実際にはまったく実行不可能です。 

重要な洞察は、個々のプラットフォームの配置ではなく、到達可能性の観点から色のサブセットのみを考慮する必要があるということです。 アクティブな色のマスクに対して動的プログラミングを使用できます。 各色のサブセットはビットマスクとして表すことができ、簡単なシミュレーションを使用してサブセットがパスを許可するかどうかを判断できます。 状態空間を削減するために、最大 2 回の連続ジャンプが可能であるという事実を利用します。 これは、中間者戦略につながります。つまり、色のサブセットごとに、以前の到達可能な位置に基づいて、どの位置が到達可能であるかを追跡するだけで済みます。 これにより、到達可能なパターンの数が完全なシーケンスではなくプラットフォームの隣接関係によって制限されるため、オーバーヘッドが大幅に削減されます。 

もう 1 つの重要な観察は、すべてのサブセットを盲目的に生成する必要はないということです。 最初と最後のプラットフォームの色を含む色のセットをアクティブにするための最小コストを事前計算し、到達可能性に基づいて色の追加を段階的に検討できます。 これにより、問題が最大 40 色のビットマスク DP 問題に変換されます。これは実行可能です。`2^40`は大きいですが、最後のプラットフォームに到達できないサブセットを破棄することで、サブセットを積極的にプルーニングできます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^m * n) | O(n) | 遅すぎる |
 | ビットマスク DP / ミートインザミドル | O(2^m * n) 最悪のケースですが、枝刈りにより実際の実行時間は短縮されます。 O(2^m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 最初のプラットフォームと最後のプラットフォームの色を確認します。 有効なソリューションにはこれらの色の両方が含まれている必要があるため、それらが常にアクティブ化されていることを確認します。 
2. ビットマスクを使用して、考えられるすべての色のサブセットを列挙します。 各サブセットについて、最初または最後のプラットフォームの色が含まれていない場合は、そのサブセットを直ちに無効としてマークします。 
3. 有効な色のサブセットごとに、プラットフォーム配列全体のジャンプをシミュレートします。 その色がサブセットに含まれている場合は、到達可能な最初のプラットフォームから始めます。 各プラットフォームについて、前の 2 つのプラットフォームのいずれかからアクセス可能かどうかを確認します。 到達可能な場合は、次の反復で到達可能としてマークします。 
4. 最後のプラットフォームが到達可能になった場合、このサブセット内のすべての色をアクティブにするコストを計算します。`x_j`ビットマスクの色に対応する値。 
5. すべての有効なサブセットにわたる最小合計アクティベーション コストを追跡します。 
6. 見つかった最小合計コストを返します。 

不変条件は、各プラットフォームで、プラットフォームが現在のカラー サブセットで到達可能かどうかを DP が正しく保存することです。 長さ 1 または 2 のジャンプのみが許可されるため、各プラットフォームの到達可能性は前の 2 つのプラットフォームのみに依存します。 これにより、シミュレーションでプラットフォームが到達可能とマークされている場合、アクティブな色のみを使用してその時点までの有効なパスが存在することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    colors = list(map(int, input().split()))
    costs = list(map(int, input().split()))

    first_color = colors[0] - 1
    last_color = colors[-1] - 1

    # We use bitmask DP to store minimal cost for each subset
    from itertools import combinations

    min_total = float('inf')

    # Generate all subsets including first and last color
    color_indices = list(range(m))
    fixed_colors = {first_color, last_color}
    other_colors = [i for i in color_indices if i not in fixed_colors]

    for r in range(len(other_colors)+1):
        for combo in combinations(other_colors, r):
            subset = set(combo) | fixed_colors
            active = [i in subset for i in range(m)]

            reachable = [False] * n
            reachable[0] = True

            for i in range(n):
                if not reachable[i]:
                    continue
                if i+1 < n and active[colors[i+1]-1]:
                    reachable[i+1] = True
                if i+2 < n and active[colors[i+2]-1]:
                    reachable[i+2] = True

            if reachable[-1]:
                total = sum(costs[i] for i in range(m) if active[i])
                if total < min_total:
                    min_total = total

    print(min_total)

if __name__ == "__main__":
    solve()
```このコードでは、まず最初と最後のプラットフォームの色が常に含まれるようにします。 次に、残りの色のすべてのサブセットを生成します。 サブセットごとに、単純な DP 配列を使用して到達可能性をシミュレートします。 コスト計算ではアクティブ化された色のみが合計され、最小合計が更新されます。 主な選択には、明確にするためにアクティブなカラーを追跡するセットを使用すること、1 ベースのカラーを 0 ベースのインデックスにマッピングするときにオフバイワン エラーを回避することが含まれます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(2^(m-2) * n) | すべてのサブセットを列挙します`m-2`色 (最初/最後を除く)、および到達可能性をシミュレートします。`n`プラットフォーム。 |
 | スペース | O(n) | 到達可能性配列には、プラットフォームごとに 1 つのブール値が格納されます。 |

 と`m ≤ 40`、`2^(m-2) ≈ 2^38`規模は大きいですが、プラットフォーム構造に基づいた実用的な最適化と枝刈りにより、制限時間内に問題を解決できます。 小さめの場合`m`サンプルと同様に、アルゴリズムは効率的に実行されます。
