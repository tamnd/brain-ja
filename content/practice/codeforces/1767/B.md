 ## 解決策
 ## 問題の理解

 いくつかのタワーが与えられ、それぞれに特定の数のブロックが含まれています。 目標は、他のタワーよりも多くのブロックがあるタワーからブロックを移動して、最初のタワーのブロックの数を最大化することです。 移動は、より多くのブロックがあるタワーからブロックを取り出し、それをより少ないブロックのタワーに配置する場合にのみ許可されます。 移動するたびに、1 つのタワーが 1 ブロック減少し、別のタワーが 1 ブロック増加します。 

入力は複数のテスト ケースで構成されます。 各テスト ケースでは、タワーの数とすべてのタワーのブロック数のリストが提供されます。 出力は、テスト ケースごとに、一連の有効な移動を実行した後の最初のタワー上のブロックの最大数である必要があります。 

塔の数という大きな制約があります。$n$到達できる$2 \cdot 10^5$、との合計$n$すべてのテストケースで次を超えない$2 \cdot 10^5$。 最悪の場合、ブロックを個別に移動するには最大で$10^9$10億個のブロックを持つ単一のタワーの操作は、制限時間をはるかに超えています。 ブロック自体は非常に大きくなる可能性があるため、ソリューションは総当たりシミュレーションではなく算術演算で機能する必要があります。 

明らかではないエッジ ケースには、1 つのタワーに大量のブロックがあり、残りは最小限である場合、またはすべてのタワーが同じ数のブロックで始まる状況が含まれます。 たとえば、入力が次の場合、`[1, 1000000000]`、考えられるそれぞれの動きを繰り返しチェックする単純なアルゴリズムでは、絶望的に遅くなるでしょう。 もう 1 つのエッジ ケースは、次のようにすべてのタワーが等しい場合です。`[5, 5, 5]`。 ここでは移動は不可能であり、タワー 1 の最大値は単にその開始値です。 

## アプローチ

 ブルートフォース手法は簡単です。すべてのタワーを繰り返しスキャンし、最初のタワーよりも多くのブロックを持つタワーを見つけ、そこから 1 ブロックを 1 番目のタワーに移動します。 そのような動きが不可能になるまで繰り返します。 この方法は正しいです。なぜなら、各移動は合法であり、タワー 1 をそれ以上増やすことができない場合にのみ停止するからです。 問題はパフォーマンスです。最悪の場合、タワー間の差の合計に達する可能性があります。$10^9$テストケースごとの操作。 これは実現可能な限界を超えています。 

最適なアプローチは、動きの順序が重要ではないことを観察することから生まれます。 必要なのは、ブロックの総数と、合法的にタワー 1 に到達できるブロックの数だけです。 タワー 1 は他のすべてのタワーからブロックを受け取ることができますが、ブロックを移動するときにタワー 1 の現在の数を下回るタワーはありません。 したがって、タワー 1 の最大ブロック数は、すべてのブロックを切り上げた整数平均になります。 正式には、すべてのブロックの合計をタワーの数で割った値が、ブロックを最適に再分配するときにタワーが到達できる適切な最大値を示します。 これは、ブロック数が平均よりも少ないタワーでは、その数と平均の差以上のものを与えることができないためです。 したがって、式は次のようになります`max_possible = ceil(total_blocks / n)`、次のように整数演算を使用して安全に計算できます。`(total + n - 1) // n`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(合計(a_i)) | O(n) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る`t`。 
2. 各テスト ケースについて、タワーの数を読み取ります。`n`とブロック数のリスト`a`。 
3. すべてのタワーにわたるブロックの合計数を計算します。`total = sum(a)`。 
4. 達成できる塔の最大ブロック数を計算します。 タワー 1 はブロックの平均の上限を超えることはできないため、次のように計算します。`(total + n - 1) // n`。 
5. 各テスト ケースについて計算された最大値を出力します。 

この方法が正しいかどうかは、移動ルールに違反することなく、タワーが公平な割合を超えてブロックを受け取ることができないという不変条件に依存します。 平均の天井を取得することで、他のタワーの相対的な高さを尊重しながら、タワー 1 ができるだけ多くのブロックを受け取ることができるようになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    total = sum(a)
    max_blocks = (total + n - 1) // n
    print(max_blocks)
```このソリューションは、入力を効率的に読み取ります。`sys.stdin.readline`、複数のテスト ケースを処理し、ブロックを合計し、整数演算を適用して浮動小数点演算を行わずに上限を計算します。 使用する`(total + n - 1) // n`丸め誤差を回避し、最大で大きな合計を処理します。$2 \cdot 10^{14}$Python で安全に。 

## 実用的な例

 **例 1**

 入力:`[1, 2, 3]`| タワー | イニシャル | 合計額 | 天井(平均) |
 | --- | --- | --- | --- |
 | 1 | 1 | 6 | 3 |
 | 2 | 2 | | |
 | 3 | 3 | | |

 合計は 6、タワーの数は 3 であるため、タワー 1 で可能な最大値は次のとおりです。`(6 + 3 - 1) // 3 = 8 // 3 = 3`。 これは予想される出力と一致します。 

**例 2**

 入力:`[1, 2, 2]`| タワー | イニシャル | 合計額 | 天井(平均) |
 | --- | --- | --- | --- |
 | 1 | 1 | 5 | 2 |
 | 2 | 2 | | |
 | 3 | 2 | | |

 合計は 5、タワー = 3、タワー 1 の最大可能数は`(5 + 3 - 1) // 3 = 7 // 3 = 2`。 

これらの例は、数式が平均の上限、つまり達成可能な最大のタワーを正しく計算していることを確認します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | すべてのブロックを合計するには、テスト ケースごとに直線的な時間がかかります。 |
 | スペース | お(1) | 合計と入力リストのみが一時的に保存されます。 |

 の合計を考えると、`n`すべてのテストケース全体で最大でも$2 \cdot 10^5$、アルゴリズムはほんの数秒で実行され、2 秒の制限内に十分収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = io.StringIO()
    sys.stdout = output
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        total = sum(a)
        max_blocks = (total + n - 1) // n
        print(max_blocks)
    return output.getvalue().strip()

 ## 特殊なケース

 すべてのタワーのブロック数が同じ場合、合計を次の値で割ります。`n`は整数であり、上限によって値は変わりません。 例えば、`[5, 5, 5]`収量`(15 + 3 - 1) // 3 = 17 // 3 = 5`。 アルゴリズムはタワー 1 の開始番号を出力します。これは、どの移動によっても増加できないため、正しいものです。 

あるタワーに他のタワーと比べて膨大な数のブロックがある場合、`[1, 1000000000]`、合計は`1000000001`、塔の数 = 2、与える`(1000000001 + 2 - 1) // 2 = 1000000002 // 2 = 500000001`。 このアルゴリズムは、可能な最大の分布を効率的に取得し、反復的な動きを回避します。
