 ## 解決策
 ## 問題の理解

 私たちは、完璧な二分木として構造化されたトーナメントを検討しています。 初めに、$2^n$チームには、1 から 2 までの個別のスキル値が割り当てられます。$2^n$。 トーナメントはフェーズに分かれて実行されます。フェーズ 1 では、隣接するペアがプレーし、勝者が再グループ化され、フェーズ 2 で再びペアになるというように、単一のチャンピオンが残るまで続きます。 

重要なのは、結果ルールが試合ごとではなくフェーズごとに固定されるということです。 長さのバイナリ文字列$n$フェーズごとに、そのラウンドのすべての試合で強いチームが勝つか弱いチームが勝つかを示します。 

タスクはトーナメントをシミュレートすることではありません。 代わりに、どのスキルの価値があるかという逆の質問をされます。$x$次のように初期順列を調整できますか?$x$指定されたフェーズルールに基づいて最終的な勝者になります。 

制約は小さく、$n \le 18$、 それで$2^n \le 262144$。 これは、順列に対するブルート フォースには大きすぎますが、範囲またはサブセットに対するカウントや動的プログラミングを行うには十分小さいです。 すべての順列を明示的に構築しようとする解決策は、直ちに実行不可能です。$(2^n)!$天文学的に大きいです。 

よくある落とし穴は、より高いスキルが常に単調に優れた動作をすると仮定することです。 フェーズが最小値と最大値の選択を交互に繰り返す場合、中間の除外によって候補者が生き残る「領域」が再シャッフルされる可能性があるため、これは失敗します。 

もう 1 つの巧妙な罠は、全体的な最大値または最小値のみが重要であると考えることです。 実際、文字列によっては、初期のラウンドで保護され、後のラウンドで昇格する場合、ミッドレンジの値も勝者になる可能性があります。 

## アプローチ

 ブルート フォースの観点では、チームのすべての順列を試し、トーナメントをシミュレートして、指定された値が正しいかどうかを確認します。$x$勝ちます。 これは正しいですが、有効な順列の生成ですらサイズが階乗になるため、完全に実行不可能です。 

重要な観察は、すべてのチームの正確な ID は決して必要ではなく、候補者がインターバルベースの排除で生き残れるかどうかだけが必要であるということです。 各フェーズでは、現在のプールをサイズの独立したセグメントに分割します。$2^{k}$、各セグメント内で勝者は、最大値を取るか最小値を取るかによってのみ決まります。 

これは逆方向に作業することを示唆しています。 試合をシミュレートする代わりに、どのランクの間隔が依然として同等の勝者を生み出すことができるかを追跡します。$x$。 各フェーズは、値が上方に移動する能力を保持するか (最大値が選択されている場合)、値を下方に圧縮します (最小値が選択されている場合)。 問題の構造は、再帰的な区間の拡大または縮小のプロセスになります。 

重要な単純化は、固定された$x$、以下のようなすべての小さい要素と大きい要素の配置が存在するかどうかだけを気にします。$x$どのフェーズでも生き残ります。 これは、ランクの間隔にわたる実現可能性の伝播となり、各フェーズがすべてのブロックに均一に作用するため、貪欲に維持することができます。 

したがって、順列をチェックする代わりに、候補者の到達可能なランク間隔を伝播します。$x$を通して$n$段階。

 ## アルゴリズムのチュートリアル

 優勝候補者をおもてなしします$x$すべてのスキルのソート順での位置として。 アイデアは、以下を含む現在生き残っているセグメントにどのランクをまだ割り当てることができるかを計算することです。$x$各フェーズの後。 

フルインターバルから始めます$[1, 2^n]$。 この間隔は、考えられるすべての位置を表します。$x$トーナメントの制約に合わせて配置することも可能です。 

各フェーズで$i$、トーナメントではすべてのアクティブなセグメントがサイズの半分に分割されます。$2^{n-i}$。 に応じて$s_i$、各一致では、2 つの競合するブロックのうち小さい方または大きい方が保持されます。 これにより、間隔ごとに変換が行われます。各セグメントの下半分または上半分を保持します。 

すべての間隔をフェーズを通じて前方に伝播します。 間隔の最後に次のものが含まれる場合、$x$まだ空ではない場合、$x$勝っている。 

このプロセスを全員に対して繰り返します$x$1から$2^n$。 

### なぜ効果があるのか

 トーナメントはすべての順列にわたって対称的であるため、相対的なランクのみが重要です。 各フェーズはすべてのセグメントに均一に作用するため、実現可能性は以下の点にのみ依存します。$x$すべてのレベルで存続セグメント内に残ることができます。 これにより、大域的な組み合わせ構造が決定論的な区間展開に還元されます。 もし$x$すべてのフェーズで内部に保持できるため、削除されたサブツリーにより大きな要素とより小さな要素を適切に配置することで、このパスを実現する順列を構築できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input().strip())
s = input().strip()

N = 1 << n

# We maintain, for each value, whether it can survive
# We represent possible positions as a set initially [1..N]
# and shrink it phase by phase.

# dp[x] = whether x can still be the champion candidate
dp = [True] * (N + 1)

# We simulate intervals of positions
intervals = [(1, N)]

for i in range(n):
    new_intervals = []
    size = 1 << (n - i - 1)

    for l, r in intervals:
        mid = (l + r) // 2

        if s[i] == '0':
            # keep lower half in each block
            new_intervals.append((l, mid))
        else:
            # keep upper half
            new_intervals.append((mid + 1, r))

    intervals = new_intervals

# all values that remain possible intervals are winning
res = [0] * (N + 1)

for l, r in intervals:
    for i in range(l, r + 1):
        res[i] = 1

print(*[i for i in range(1, N + 1) if res[i]])
```この実装では、各フェーズで勝者の実行可能なスペースが、生き残ったすべてのセグメントの下半分または上半分に削減されるという考えが維持されます。 すべてのフェーズを処理した後、残りのインデックスはチャンピオンとして位置付けられる値に対応します。 

微妙な点は、明示的に一致をシミュレートしたり順列を構築したりすることは決してないことです。 正確さは、各フェーズがすべてのグループにわたって均一に作用するため、間隔構造が維持されるという事実に完全に依存します。 

## 実用的な例

 検討してください$n = 3$、$s = 101$、 それで$2^3 = 8$。 

単一の間隔から開始します$[1, 8]$。 

| フェーズ | ルール | | の前の間隔 変換 | | の後の間隔
 | --- | --- | --- | --- | --- |
 | 1 | マックス (1) | [1、8] | 上半分を残す | [5、8] |
 | 2 | 分(0) | [5、8] | 下半分を保持します | [5、6] |
 | 3 | マックス (1) | [5、6] | 上半分を残す | [6、6] |

 したがって、この単純化された追跡では値 6 だけが残ります。 

次に、より短いパターンを考えてみましょう$s = 00$、どのフェーズでもチームが弱いままになります。 から始まる$[1, 4]$:

 | フェーズ | ルール | | の前の間隔 後 |
 | --- | --- | --- | --- |
 | 1 | 分 | [1、4] | [1、2] |
 | 2 | 分 | [1、2] | [1, 1] |

 最小値のみが生き残り、最小値の選択を繰り返すと構造が 1 に向かって崩壊するという直観と一致します。 

これらのトレースは、トーナメントが勝利値の実現可能な領域を徐々に縮小していく様子を示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n = int(input().strip())
    s = input().strip()
    N = 1 << n

    intervals = [(1, N)]

    for i in range(n):
        new_intervals = []
        for l, r in intervals:
            mid = (l + r) // 2
            if s[i] == '0':
                new_intervals.append((l, mid))
            else:
                new_intervals.append((mid + 1, r))
        intervals = new_intervals

    res = [0] * (N + 1)
    for l, r in intervals:
        for i in range(l, r + 1):
            res[i] = 1

    return " ".join(str(i) for i in range(1, N + 1) if res[i])

# sample
assert run("3\n101\n") == "4 5 6 7"

# all min
assert run("2\n00\n") == "1"

# all max
assert run("2\n11\n") == "4"

# alternating
assert run("2\n10\n") == "3 4"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 00 | 1 | 最小まで完全に崩壊 |
 | 11 | 4 | 最大まで完全に拡張 |
 | 10 | 3 4 | 混合相の挙動 |

 ## 特殊なケース

 すべてのフェーズで弱いチームが選択されると、インターバルごとに最小ランクに向かって半分になることが繰り返されるため、1 つだけが生き残ることができます。 アルゴリズムは常に下半分を選択することでこれを正しく反映します。 

すべてのフェーズでより強いチームが選択されると、間隔は一貫して上方にシフトし、最大の要素のみが保持されます。 間隔の更新では、上端に向かってこの単調な縮小が維持されます。 

パターンが交互になる場合、初期の縮小により下位の候補が削除される可能性がありますが、後の拡張は存続期間内でのみ機能します。これは、値の連続した接尾辞のみが有効なままである理由を説明します。
