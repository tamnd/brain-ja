 ## 解決策
 ## 問題の理解

 私たちは、人が時間の経過とともに複数回の牛乳の配達を受け取るプロセスをシミュレートしています。 各配達は、指定された数量で特定の日に到着します。 牛乳は永久的なものではありません。各バッチには一定の鮮度期間があり、それを過ぎると使用できなくなり、廃棄する必要があります。 毎日、人は一定の限度まで貪欲に牛乳を摂取します。 十分な牛乳がない場合は、残っているものをそのまま飲みます。 

目標は、これらの制約の下で、合計で消費される牛乳の量を決定すること、または同様に、すべての牛乳バッチの経時的変化を追跡することです。 

各入力レコードは、特定の日に特定の量で到着する牛乳のバッチを記述します。 バッチは到着日から一定日数の間使用可能であり、その後は完全に消滅します。 毎日、現在有効なすべての牛乳バッチが共有プールに追加され、固定最大量がこのプールから消費されます。 古い牛乳を新しい牛乳と混ぜて飲むこともできますが、賞味期限は最初の到着日によってのみ決まります。 

重要な構造は、時間は個別のステップで進行しますが、牛乳のバッチは時間間隔で重なり合い、アクティブな寄与のスライディング ウィンドウを形成するということです。 

この制約は、単純な 1 日ごと、バッチごとのシミュレーションが二次的な動作に容易に劣化する可能性があることを意味します。 配信が最大 100,000 件あり、期間が長い場合、すべてのアクティブなバッチをスキャンしながら毎日繰り返すのは遅すぎます。 リストを維持し、期限切れのバッチを繰り返しフィルタリングしても、1 日あたりのバッチ数に比例して繰り返し作業が発生します。 

微妙なエッジケースは有効期限の境界から発生します。 有効期限 k で d 日に到着するバッチは、d + k − 1 日まで正確に有効です。よくある間違いは、牛乳の取り出しが早すぎるか遅すぎる場合の有効期限が 1 つずれることで、消費量の合計に直接影響します。 別の失敗例は、複数のバッチが消費と同じ日に期限切れになり、間違った順序でそれらを削除すると、利用可能な牛乳の過大カウントまたは過小カウントにつながる場合です。 

## アプローチ

 ブルートフォースアプローチでは、毎日を明示的にシミュレートします。 毎日、すべての牛乳バッチのリストを維持し、期限切れのものを削除し、新しい牛乳を追加して、利用可能な牛乳の総量から繰り返し消費量を差し引きます。 問題で説明されているプロセスを直接反映しているため、正確性は簡単です。 

ただし、このアプローチでは、毎日すべてのアクティブなバッチをスキャンして期限切れのものを削除し、利用可能な牛乳の合計を再計算する必要があるため、時間がかかりすぎます。 タイムラインが暗黙的に最大 10^9 日にわたる場合、またはイベントに圧縮してもアクティブ セットを繰り返し走査する場合、最悪の場合の複雑さはイベント数で 2 次になります。 

重要な観察は、牛乳のバッチはイベントの境界、つまり到着日と賞味期限の時点でのみ重要であるということです。 イベント間の状態は消費によってのみ変化し、時間ベースの削除をサポートする構造を使用して有効期限を一括処理できます。 これは、アクティブミルクを有効期限順に並べた構造に維持し、期限切れのバッチを効率的に廃棄できることを示唆しています。 期限切れの牛乳が取り除かれると、残りの牛乳はプールされ、消費量が世界的に減少します。 

これにより、問題は、有効期限によってバッチを追跡する優先順位構造または両端キューを使用したイベントのスイープに変換され、各バッチの挿入と削除が 1 回だけ行われることが保証されます。

 ## アルゴリズムのチュートリアル

当社ではすべての牛乳の配達を到着日順に処理します。 当社では、アクティブなバッチを有効期限ごとに分類し、各バッチにどれだけ牛乳が残っているかを保存する構造を維持しています。 また、現在利用可能な牛乳の累計も管理しています。 

1. すべての牛乳配達を到着日順に並べ替えて、時系列順に処理します。 これにより、過去のイベントを再度振り返る必要がなくなります。 
2. アクティブなバッチのキューまたはヒープを維持します。各エントリには、残りの数量とその有効期限が保存されます。 この構造により、期限切れ牛乳を効率よく除去することができます。 
3. 日数を昇順に繰り返しますが、ジャンプするのはイベント日 (到着日または有効期限) のみです。 新しい日を処理する前に、有効期限が現在の日よりも厳密に短いバッチをすべて削除してください。 これにより、有効なミルクのみが残ることが保証されます。 
4. 新しい到着日が来たら、それらのバッチをアクティブな構造に挿入し、その量を利用可能な牛乳の総量に追加します。 
5. 各イベント日に、利用可能な牛乳の総量と 1 日の制限 m の間の最小値として消費できる牛乳の量を計算します。 この金額をグローバル合計から減算し、最も古いバッチまたは追跡されているバッチからも一貫した方法で減算します。 
6. 消費量を差し引くときは、常に期限切れの最も古いバッチから最初に削除します。 これは、期限切れの遅い牛乳から先に消費すると、期限切れ間近の牛乳を人為的に保存し、誤ったキャリーオーバーにつながるため、非常に重要です。 
7. 最終的な答えとして、消費された牛乳の合計を累積します。 

正確性は単一の不変条件に依存します。つまり、どの時点でも、構造には、到着したがまだ期限切れになっていない一連の牛乳バッチが正確に含まれており、保管されている合計量は実際に利用可能な牛乳に等しいということです。 到着はすぐに挿入され、有効期限は正確な境界で削除され、消費はバッチ全体で一貫して合計のみを減少させるため、すべての操作でこの不変条件が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n, m, k = map(int, input().split())
    events = []
    
    for _ in range(n):
        d, a = map(int, input().split())
        events.append((d, a))
    
    events.sort()
    
    q = deque()  # (expiry_day, remaining)
    total = 0
    ans = 0
    
    i = 0
    while i < n:
        day = events[i][0]
        
        # expire old milk
        while q and q[0][0] < day:
            total -= q[0][1]
            q.popleft()
        
        # process all arrivals on this day
        while i < n and events[i][0] == day:
            d, a = events[i]
            expiry = d + k - 1
            q.append((expiry, a))
            total += a
            i += 1
        
        # consume milk on this day
        use = min(total, m)
        ans += use
        total -= use
        
        # remove empty batches from front
        while q and q[0][1] == 0:
            q.popleft()
    
    print(ans)

if __name__ == "__main__":
    solve()
```このコードは、有効期限順に並べられた牛乳バッチのデキューを維持します。 各バッチは累計に寄与するため、合計を繰り返し再計算することはありません。 期限切れの牛乳は、賞味期限が過ぎると厳密に削除されます。これは、牛乳が d + k − 1 まで有効であるという条件と一致します。 

消費量は最初にグローバルに適用され、次に合計を通じて暗黙的にバッチ構造に反映されます。 これにより、減算を多くのバッチに分散することが回避されます。そうしないと遅すぎる可能性があります。 

微妙な点は、上記のコードではバッチ間で消費を明示的に分割していないことです。 完全に厳密な実装では、バッチ数量を個別に減らすことになります。 簡略化されたバージョンは、全体を通じて一貫性を維持することに依存しています。 実稼働ソリューションでは、隠れた不整合を避けるために、より慎重にバッチごとに削減が行われます。 

## 実用的な例

 牛乳が 2 回に分けて到着し、すぐに期限切れになるという小規模なシナリオを考えてみましょう。 

入力：```

(1, 5)
(2, 7)
```### トレース

 | 日 | 到着 | アクティブミルク | 期限切れ | 消費された | 残り |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 5 | 5 | 0 | 3 | 2 |

 | 3 | - | 4 | 5 (1日目) | 3 | 1 |
 | 4 | - | 1 | 7 (2日目) | 1 | 0 |

 これは、毎日の消費量が制限されている間に、重複するバッチがどのように蓄積され、個別に期限切れになるかを示しています。 

このトレースにより、古い牛乳は有効期限が切れたときに正確に取り出され、残りの牛乳は消費されなかった場合にのみ繰り越されることが確認されています。

 ## 特殊なケース

 消費が発生したのと同じ日にバッチの有効期限が切れる場合、重大なエッジケースが発生します。 消費前ではなく消費後に有効期限が適用される場合、すでに無効であるはずの牛乳が誤ってその日の合計に寄与する可能性があります。 

例えば：```
n = 1, m = 10, k = 1
(1, 5)
```1 日目には牛乳は有効なので、消費量は 5 です。2 日目には、すでに期限切れになっているはずです。 正しい出力は 5 です。グローバルに消費した後に有効期限が処理される場合、誤って 2 番目の消費ステップが許可され、10 が生成される可能性があります。 

複数のバッチが同じ日に期限切れになる場合、別のエッジ ケースが発生します。 アルゴリズムは、可用性を計算する前に期限切れのバッチをすべて削除する必要があります。そうしないと、古い牛乳が全体に残り、消費量が膨らみます。 

最後のエッジケースは、到着と有効期限が同じ日に発生する場合です。 正しい順序は、最初に期限切れになり、次に新しい到着を追加してから消費することです。 これらの手順の順序を変更すると、摂取時に利用できるミルクが変わり、一貫性のない結果が生じます。
