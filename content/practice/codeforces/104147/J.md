 ## 解決策
 ## 問題の理解

 各テスト ケースは次のコレクションを提供します。$N$独立したペア。 から$i$- 番目のペアでは、次のいずれかの値を 1 つだけ選択する必要があります。$A_i$または$B_i$。 すべての選択が行われた後、選択されたすべての値が XOR 演算されて、Salkan と呼ばれる 1 つの数値が生成されます。 

さらに工夫があります。Hanz はしきい値を導入します。$K$。 可能な限り最高のサルカンが厳密に超えている場合$K$、その後、システムはホブズの欺瞞を受け入れることを拒否し、最終的に報告されたサルカンを強制的にゼロにします。 それ以外の場合、Hobz は達成可能な最良の XOR 値を報告することができます。 

したがって、タスクは、ペアごとに 1 つの値を選択することによって取得できる最大の XOR を計算し、最終的なクランプを適用することです。つまり、最大でもその値を出力します。$K$それ以外の場合はゼロを出力します。 

制約により、テスト ケースごとに線形または線形に近い解決策が求められます。 まで$10^5$ペアと値まで$2^{30}$、サブセットを列挙したり、すべての組み合わせを試したりするアプローチは直ちに実行不可能です。$2^{N}$たとえ$N = 30$、ましてや$10^5$。 XOR 相互作用はグローバルで非線形であるため、各ペアを個別に反転しようとする素朴な欲張りでも失敗します。 

微妙な失敗例は、局所的な改善が全体的な最適化を誤解させる場合に発生します。 たとえば、次のことを選択するとします。$A_i$位置ごとには優れているように見えますが、2 つの「見た目が悪い」選択肢を組み合わせると、XOR 空間でのビットキャンセルとキャリーにより、より高い XOR が生成されます。 ペアを独立して評価する戦略はここで破綻します。 

2 番目のエッジ ケースは、すべてのペアが同一である場合です。たとえば、$A_i = B_i = 0$。 答えは自明のことながらゼロですが、すべてのペアが意味のある自由度に寄与していると想定する実装の健全性チェックにもなります。 

## アプローチ

 ブルートフォースソリューションでは、各ペアを二者決定として扱い、すべてを試します。$2^N$組み合わせて、毎回 XOR を計算します。 これは問題の定義を直接評価するので正しいですが、非常に小さい値を超えると不可能になります。$N$。 たとえ$N = 40$、これはすでに約 1 兆の州を意味します。$N$までです$10^5$。 

重要な観察は、選択構造が線形化できるということです。 1 つのベースライン選択を修正する場合、常に選択するとします。$A_i$の場合、他の構成は、いくつかのペアを反転することによってのみ異なります。$A_i$に$B_i$。 反転ペア$i$合計 XOR を正確に変更します$A_i \oplus B_i$、他のペアとは独立して。 

これにより、問題は XOR を介した古典的な線形代数構造に変換されます。ベース値から開始し、デルタ値のサブセットを XOR することができます。$D_i = A_i \oplus B_i$。 このタスクは、独立したジェネレーターのマルチセットを使用した XOR の下で数値を最大化することになります。これはまさに 2 進線形基底が解決するものです。 

すべての基礎を計算したら$D_i$、最上位ビットから下に向かって貪欲に現在の値を増加させようとします。 達成可能な最大の XOR を取得した後、制約を適用します。$> K \Rightarrow 0$。

 ## アルゴリズムのチュートリアル

 問題を基本 XOR と独立した XOR 調整に変換します。 

1. 次のようにベースライン XOR を計算します。$X = A_1 \oplus A_2 \oplus \dots \oplus A_N$。 これは、反転を適用する前に、すべてのペアの最初の面を選択することに対応します。 
2. 各ペアについて、差の値を計算します。$D_i = A_i \oplus B_i$。 これは、スイッチングの効果を表します。$i$- 番目の選択$A_i$に$B_i$なぜなら、XOR は同一部分をキャンセルし、変更部分だけを残すからです。 
3. すべてからバイナリ線形基底を構築します。$D_i$。 ビットを上位から下位まで反復して、各数値を基底に挿入します。 数値にまだ使用されていないピボット ビットがある場合、それは基底ベクトルになります。 それ以外の場合は、既存の基底ベクトルを使用して削減されます。 
4. 最上位ビットから開始して、値が増加するたびに基底ベクトルと XOR 演算して、現在の XOR 値を改善しようとします。 この貪欲なプロセスは、すべての範囲から到達可能な最大の XOR を構築します。$D_i$。 
5. 結果の値を次のようにします。$X_{\max}$。 もし$X_{\max} \le K$、出力します。 それ以外の場合はゼロを出力します。 

この貪欲な最大化が機能する理由は、基礎がビット方向の独立性を保証しているためです。 各基底ベクトルは XOR 空間に新しい自由度を導入するため、それを使用するかどうかを決定しても、上位ビットに関する以前の決定が無効になることはありません。 

### なぜ効果があるのか

 到達可能なすべての XOR 値は、デルタ値によって生成された GF(2) 上のベクトル空間を形成します。$D_i$。 線形基底は、まったく同じスパンを保持するその空間の圧縮表現です。 達成可能な XOR 構成は基底ベクトルのサブセットの選択に対応し、貪欲なビットごとの最大化により、その空間内で辞書編集上最大のベクトルが構築されます。 XOR 順序は最上位ビットから下に向かって比較する場合の整数順序に対応するため、これにより可能な最大のサルカンが生成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def insert_basis(basis, x):
    for b in range(29, -1, -1):
        if (x >> b) & 1 == 0:
            continue
        if basis[b] == 0:
            basis[b] = x
            return
        x ^= basis[b]

def maximize_with_basis(basis, x):
    for b in range(29, -1, -1):
        if basis[b] and (x ^ basis[b]) > x:
            x ^= basis[b]
    return x

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        base = 0
        for i in range(n):
            base ^= a[i]

        basis = [0] * 30

        for i in range(n):
            d = a[i] ^ b[i]
            insert_basis(basis, d)

        best = maximize_with_basis(basis, base)

        if best > k:
            print(0)
        else:
            print(best)

if __name__ == "__main__":
    solve()
```ソリューションは、すべてを使用して決定論的なベースライン XOR を構築することから始まります。$A_i$。 これは、他のすべての設定が XOR 調整として表現される基準設定を修正するため、重要です。 

挿入関数は、各ビット位置に最大 1 つの代表ベクトルを格納する縮小基底を構築します。 消去プロセスにより、基底内のすべてのベクトルが一意の最上位ビットに寄与することが保証され、これにより、後の貪欲な再構成が有効になります。 

最大化ステップでは、基底ベクトルを切り替えるとその値が増加するかどうかをチェックして、現在の XOR を改善しようとします。 小切手`(x ^ basis[b]) > x`XOR がビットを反転し、有益な反転のみが受け入れられるため機能します。 

最後に、しきい値チェックでは、達成可能な最適な XOR を計算した直後に Hanz のルールが適用されます。 

## 実用的な例

 次のような小さなケースを考えてみましょう。$A = [1, 2]$、$B = [3, 4]$、 そして$K = 10$。 

ベースライン XOR を計算します。$X = 1 \oplus 2 = 3$。 

次にデルタ:$D_1 = 1 \oplus 3 = 2$、$D_2 = 2 \oplus 4 = 6$。 

私たちは基礎を構築します$\{2, 6\}$。 これらから組み合わせを生成できます。$0, 2, 6, 2 \oplus 6 = 4$。 

ベースから始めます$3$そして最大化してみてください:

 再構成表:

 | ステップ | 現在の XOR | アクション |
 | --- | --- | --- |
 | 開始 | 3 | 基本値 |
 | 6 を試してみる | 3 ⊕ 6 = 5 | 改善する |
 | 試して 2 | 5 ⊕ 2 = 7 | 改善する |

 最終的なベストは 7 です。$\le K$なので、出力は 7 になります。 

次に 2 番目のケースを考えてみましょう。$A = [5, 5]$、$B = [5, 5]$、$K = 0$。 

ベースライン XOR は$5 \oplus 5 = 0$。 すべてのデルタはゼロなので、基底は空です。 ベストは 0 のままです。$0 \le K$、出力は 0 です。 

これは、意味のある反転が存在しない場合、構造がベースラインに正しく折りたたまれることを示しています。

| スペース |$O(30)$| 基底はビットごとに最大 1 つのベクトルを格納します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque

    input = sys.stdin.readline

    def insert_basis(basis, x):
        for b in range(29, -1, -1):
            if (x >> b) & 1 == 0:
                continue
            if basis[b] == 0:
                basis[b] = x
                return
            x ^= basis[b]

    def maximize_with_basis(basis, x):
        for b in range(29, -1, -1):
            if basis[b] and (x ^ basis[b]) > x:
                x ^= basis[b]
        return x

    t = int(input())
    out = []
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        base = 0
        for i in range(n):
            base ^= a[i]

        basis = [0] * 30
        for i in range(n):
            insert_basis(basis, a[i] ^ b[i])

        best = maximize_with_basis(basis, base)
        out.append("0" if best > k else str(best))

    return "\n".join(out) + "\n"

assert run("1\n1 5\n3\n7\n") == "4\n"

# all identical
assert run("1\n3 10\n1 1 1\n1 1 1\n") == "0\n"

# small mixed
assert run("1\n2 10\n1 2\n3 4\n") == "7\n"

# forced zero by K
assert run("1\n2 3\n1 2\n3 4\n") == "0\n"

 ## 特殊なケース

 すべてのペアが満足するとき$A_i = B_i$、すべてのデルタはゼロになり、基底は空のままになります。 アルゴリズムは、すべての XOR を計算することになります。$A_i$、値がキャンセルされると、それ自体がゼロになります。 最終的な比較と$K$どの操作も結果を増やすことができないため、依然として正しく動作します。 

すべてのデルタが線形独立である場合、基底は 30 ビットを超えるフルランクまで増加します。 その状況では、貪欲な最大化はベースから到達可能な可能な最大の 30 ビット整数を効果的に構築し、しきい値チェックが唯一の制限要因になります。
