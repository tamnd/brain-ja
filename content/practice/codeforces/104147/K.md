 ## 解決策
 ## 問題の理解

 バイナリ文字列が与えられ、そこから任意の数の文字を削除することができますが、おそらく少なくとも 1 文字を除いてすべての文字を残す必要があります。 削除後、残りのサブシーケンスは、元の文字列ではなくサブシーケンス自体内の位置に基づいてパリティ条件を満たす必要があります。 

より正確には、保持された文字列に 1 から始まるインデックスを付けると、奇数の位置に配置されたすべての文字と偶数の位置に配置されたすべての文字が調べられます。 要件は、`1`奇数の位置に出現する文字は、`1`均等な位置に出現する文字。 長さを最大化したり、明示的に何かを構築したりする必要はなく、少なくとも 1 つの有効な空でないサブシーケンスが存在するかどうかを判断するだけで済みます。 

この制約により、合計文字列長が 200,000 で、最大 100,000 のテスト ケースが許可されます。 これにより、サブシーケンスを列挙しようとしたり、テスト ケースごとにすべての削除を個別にシミュレートしようとしたりするアプローチは即座に除外されます。 テスト ケースごとの線形時間を超えると遅すぎるため、テスト ケースごとの線形であっても、全体としては慎重に処理する必要があります。 

貪欲な選択について考えると、微妙な問題が生じます。 相対的な構造を保持する必要がある、またはパリティは元のインデックスに依存すると仮定したくなります。 位置は削除後に再番号付けされるため、これは不正確です。 もう 1 つのよくある間違いは、元の文字列の奇数インデックスと偶数インデックスに同じ数の 1 が必要であると想定することですが、これも問題を反映していません。 

最小のエッジケースは単一の文字列です。 そうであれば`1`、それを取得でき、位置は奇数の位置 1 なので、奇数は 1、偶数は 0 となり、条件は満たされません。 そうであれば`0`、それを取ることもでき、両方のカウントがゼロであるため、有効です。 これは、ゼロは無害であり、意味のある唯一の寄与者は 1 であることをすでに示しています。 

## アプローチ

 ブルートフォースの考え方は、すべてのサブシーケンスを試して、条件を満たすかどうかを確認することです。 各サブシーケンスについて、その構築をシミュレートし、奇数と偶数の位置にあるものを数えます。 指数関数的に多くのサブシーケンスがあるため、このアプローチは次のようになります。$O(2^n)$テストケースごとに、これは小さな文字列であっても完全に実行不可能です。 

単純化するために、実際に重要なことに焦点を当てる必要があります。 条件は、選択されたサブシーケンス内の交互のパリティ位置にどのように分散できるかによってのみ決まります。 ゼロは条件にはまったく寄与せず、位置を埋め、奇数スロットと偶数スロットの間で 1 をシフトできるようにすることによってのみ役立ちます。 

重要な点は、すべての文字を使用する必要はないということです。 少なくとも 1 つの有効な構造が存在するかどうかを知る必要があるだけです。 2 つを選択できた場合は、いつでもそれらをサブシーケンスの位置 1 と 2 に配置して、1 つを奇数の位置に、もう 1 つを偶数の位置に配置することで、等式を満たすことができます。 1 つだけを選択すると、常に変な位置に座って状態が崩れてしまいます。 1 を選択しない場合、サブシーケンスは完全に 0 で構成されなければなりません。これは、奇数位置と偶数位置の両方に 0 が含まれるため、常に条件を満たします。 

したがって、問題は、文字列に少なくとも 2 つの 1 が含まれているか、または 1 がまったく含まれていないかをチェックすることになります。 

1 の数がちょうど 1 の場合、答えは不可能です。 0 または 2 つ以上であれば可能です。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1.次の文字数を数えます。`1`文字列の中で。 0 は制約に影響を与えず、1 の配置だけが問題となるため、これで十分です。 
2. 1 の数がちょうど 1 の場合、すぐに出力します。`NO`。 単一の場合、それを含むサブシーケンスはそのサブシーケンスの位置 1 または奇数の位置に配置され、偶数の位置でバランスをとる 2 番目のシーケンスはありません。 
3. それ以外の場合は出力`YES`。 1 が 0 個ある場合は、任意の 1 つの 0 を保持でき、1 の奇数カウントと偶数カウントは両方とも 0 になります。 少なくとも 2 つある場合は、いつでもそのうちの 2 つを選択し、サブシーケンス内で交互の位置に配置して、1 つが奇数の位置に、もう 1 つが偶数の位置に配置され、平等を満たすことができます。 

### なぜ効果があるのか

 サブシーケンス構造は、削除後に割り当てられるパリティ位置によってのみ重要になります。 ゼロは常に柔軟な区切り文字として使用できます。つまり、選択された 2 つのゼロを、サブシーケンスの順序付けで異なるパリティ クラスに配置できることを意味します。 唯一の障害は、1 が 1 つだけ存在する場合に発生します。これは、パリティ バランスには、奇数位置と偶数位置の両方にまたがる 1 からの寄与をペアにする必要があり、単一の要素が両方の側に寄与することができないためです。 他のすべてのケースには 1 がないか、少なくとも 2 つあり、どちらも有効な解釈が認められます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        s = input().strip()
        ones = s.count('1')
        if ones == 1:
            print("NO")
        else:
            print("YES")

if __name__ == "__main__":
    solve()
```実装では、テスト ケースごとに直接カウントされます。 ロジックは単一の条件に完全に含まれているため、サブシーケンスをシミュレートしたりパリティを明示的に追跡したりする必要がなくなります。 重要な点は、削除によってインデックス付けが完全に再定義されるため、元の文字列内の位置について推論しようとしないことです。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    input = _sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        s = input().strip()
        ones = s.count('1')
        out.append("NO" if ones == 1 else "YES")
    return "\n".join(out) + "\n"

# provided samples
assert run("3\n0\n1\n01\n") == "YES\nNO\nYES\n"

# single zero
assert run("1\n0\n") == "YES\n"

# single one
assert run("1\n1\n") == "NO\n"

# two ones
assert run("1\n11\n") == "YES\n"

# mixed large
assert run("1\n101010\n") == "YES\n"

 ## 特殊なケース

 単一文字の場合が最も敏感です。 入力用`0`、アルゴリズムは 0 の 1 を数えてすぐに出力します。`YES`これは、文字列全体を有効なサブシーケンスとして取得することに対応します。 

入力用`1`、カウントは正確に 1 であるため、アルゴリズムは次のように出力します。`NO`。 この文字を保持しようとすると、サブシーケンスの位置 1 に残り、奇数位置の 1 が 1 つと偶数位置の 1 が 0 個生成され、条件に違反します。 

もう 1 つのエッジ ケースは、すべての文字がゼロである場合です。`000000`。 1 の数はゼロであるため、アルゴリズムは次のように出力します。`YES`。 任意の 0 を 1 つ取ることができ、どちらのパリティ クラスにも 0 がないため、条件は満たされます。 

最後に、次のように、複数の 1 が含まれるがゼロで区切られた文字列を考慮します。`10001`。 1 の数は 2 であるため、アルゴリズムは次のように出力します。`YES`。 ゼロを削除して 2 つの 1 を保持し、次のサブシーケンスを生成できます。`11`、奇数位置と偶数位置のバランスを自動的に調整します。
