 ## 解決策
 ## 問題の理解

 数直線上にいくつかの整数区間が与えられます。 各間隔はカバーされる整数の連続ブロックを表し、セグメントはいかなる形でも重なったり接触したりしません。 すべてのセグメントを結合すると、カバーされる整数点のセットが形成されます。システムの「値」は、単に合計でカバーされる個別の整数の数です。 

言い換えれば、各セグメント内のすべての整数をペイントすることを想像すると、値はペイントされた整数ポイントの合計数になります。 

1 回の操作で、任意の 1 つのセグメントを取得し、それを左または右に 1 単位だけ拡張することができます。 左に拡張すると左端点が 1 つ減り、右に拡張すると右端点が 1 つ増加します。 各操作により、カバーされる合計の長さは 1 だけ増加しますが、セグメント間のギャップによっては、拡張によって最終的に隣接するコンポーネントがマージされる可能性があり、それによってカバレッジの重なり方が変化します。 

タスクは、カバーされる整数点の最終的な合計数が k で割り切れるようになるために必要なそのような単位拡張の最小数を決定することです。 

制約があるため、私たちは効率的な解決策に向かうことになります。 最大 100,000 セグメントでは、すべての拡張ステップをシミュレートするソリューションは不可能です。 セグメントごとに拡張のすべての組み合わせを試す戦略であっても、組み合わせ的に爆発的に増加します。 重要なのは、すべての中間構成の正確な形状ではなく、カバーされる全長と、拡張ごとにそれがどのように変化するかのみを考慮することです。 

セグメントがちょうど 1 つのギャップだけ離れている場合、微妙なエッジ ケースが発生します。 たとえば、[1,2] と [3,4] は互いに素ではありますが、近いものです。 いずれかのセグメントを拡張すると、最終的にギャップが閉じてそれらがマージされる可能性があります。つまり、カバーされる合計の長さは、マージ後の拡張の生の数以上に増加します。 各操作が常に合計値をちょうど 1 だけ増やすと仮定する単純なアプローチでは、このような場合に数え間違いが発生します。 

もう 1 つのエッジ ケースは、現在の全長がすでに k で割り切れる場合です。 その場合、たとえ拡張するとすぐに割り切れなくなり、さらなる調整が必要になるとしても、答えはゼロです。 

## アプローチ

 直接的なアプローチは、プロセスをシミュレートすることです。すべての可能な単一展開を繰り返し試行し、和集合の長さを再計算し、いつ割り算が達成されるかを追跡します。 間隔をマージする場合、各変更後の和集合の長さの計算は O(n) であり、考えられるすべての操作シーケンスに対してこれを行うと、指数関数的な検索スペースが得られます。 k ステップまでの貪欲なシミュレーションでも、k が大きい場合は遅すぎます。 

重要な観察は、重要な数量はカバーされる全長だけであり、各操作によってこの合計が 1 単位だけ増加するということです。 展開後にセグメントが結合したとしても、その結合によってアカウンティングが減少したり複雑になったりすることはありません。以前に検出された新しい整数を常に 1 つ追加しているため、結合の長さは操作ごとに 1 ずつ増加します。 

したがって、問題は純粋な算術の問題に帰着します。 S を、(r_i - l_i + 1) のすべてのセグメントの合計として計算された、最初にカバーされる合計長さとします。 S + x が k で割り切れる最小の非負の整数 x が必要です。 

これは単純なモジュール調整問題です。 S mod k を計算します。 すでにゼロであれば、答えはゼロです。 それ以外の場合は、k - (S mod k) の演算が必要になります。 

互いに素なセグメントの構造により、隠れた相互作用が全長に影響を与えないことが保証されるため、最初の合計を超えてジオメトリを追跡する必要はありません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(k・n) 以上 | お(1) | 遅すぎる |
 | 算術縮約 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

1. すべてのセグメントを読み取り、各セグメントの (r - l + 1) を合計することで、カバーされる全長 S を計算します。 

これが機能するのは、互いに素なセグメントではオーバーラップ補正を行わずに直接加算できるためです。 
2. 剰余 rem = S mod k を計算します。 

これは、S が次の k の倍数からどれだけ離れているかを捕捉します。 
3. rem == 0 の場合は、すぐに 0 を返します。 

条件はすでに満たされているため、変更する必要はありません。 
4. それ以外の場合は、k - rem として答えを計算します。 

これは、S を次の k の倍数に移動する最小の正の増分です。 

各演算は、ちょうど 1 つの整数だけカバレッジを増やすことに対応するため、k - rem 演算を追加することは、割り切れるには必要かつ十分です。 

### なぜ効果があるのか

 重要な不変条件は、どのセグメントが選択されるか、または後でセグメントがどのように相互作用するかに関係なく、共用体の長さが操作ごとに 1 つずつ決定的に変化することです。 セグメントは最初は互いに素であるため、オーバーラップが総数に無関係になるまで、各演算はちょうど 1 つの新しいカバーされた整数を和集合に導入します。 したがって、プロセスは S の単純な線形増加から逸脱することはなく、最終条件は純粋にモジュール式になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    total = 0

    for _ in range(n):
        l, r = map(int, input().split())
        total += (r - l + 1)

    rem = total % k
    if rem == 0:
        print(0)
    else:
        print(k - rem)

if __name__ == "__main__":
    solve()
```このソリューションは、セグメントを保存せずに、カバーされる全長を直接計算します。 各セグメントはその長さを独立して提供しますが、これは重複しないことが保証されているため有効です。 モジュロ ステップは、k の倍数からどれだけ離れているかを決定し、最後の減算により必要な最小限の増分が得られます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque

    n, k = map(int, sys.stdin.readline().split())
    total = 0
    for _ in range(n):
        l, r = map(int, sys.stdin.readline().split())
        total += (r - l + 1)

    rem = total % k
    if rem == 0:
        return "0\n"
    return str(k - rem) + "\n"

 ## 特殊なケース

 エッジ ケースの 1 つは、全長がすでに k で割り切れる場合です。 入力の場合:```
1 4
1 4
```合計は 4 なので、rem は 0 となり、アルゴリズムは直ちに 0 を出力します。 操作は必要なく、拡張しても有効な倍数から合計が増加するだけです。 

もう 1 つのエッジ ケースは、すべてのセグメントが単一点である場合です。```
3 5
1 1
3 3
5 5
```合計は 3 です。余りは 3 mod 5 = 3 なので、2 つの演算が必要です。 各操作でカバーされるカウントが 1 つずつ増加するため、5 に到達するのは最小限であり、一貫性があります。 

最後のエッジケースは、n が最大である大きな入力です。 このアルゴリズムはセグメントを保存せず、合計のみを蓄積するため、メモリ使用量は一定に保たれ、時間は直線的なままとなり、インターバル処理による構造的なオーバーヘッドが回避されます。
