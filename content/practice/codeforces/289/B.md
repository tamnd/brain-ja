 ## 解決策
 ## 問題の理解

 整数の長方形グリッドが与えられ、単一のセルを選択して固定値を加算または減算するという非常に特殊な操作を実行できます。`d`それに。 このような操作ごとに 1 回の移動がかかります。 目標は、できるだけ少ない移動で、すべてのセルにまったく同じ数字が含まれるようにグリッド全体を変換することです。そうでない場合は、これが不可能であると判断します。 

最初から重要な点は、この操作では値を任意に変更できないということです。 すべてのセル値は、その等差数列モジュロ内でのみ移動できます。`d`。 値が次から始まる場合`x`、その後、任意の数の操作の後、次の形式の数値のみになります。`x + k·d`。 これは直ちに構造上の制約を意味します。つまり、すべてのセルが合同モジュロである必要があります。`d`そうでない場合、一連の操作を整列させることはできません。 

制約は小さく、最大でも 100 x 100 グリッドなので、値は最大 10,000 個です。 これにより、`O(nm log(nm))`すべての値を複数回並べ替えたりスキャンしたりするのはコストがかからないため、快適にアプローチできます。 ここではセルごとに 2 次または 3 次でも問題ありませんが、それに近いものは必要ありません。 

いくつかの特殊なケースは見落とされがちです。 

すべての数値が合同モジュロではない場合`d`、即答は不可能です。 たとえば、次の場合`d = 2`グリッドには両方が含まれます`1`そして`2`、 それから`1`奇数にしか到達できませんが、`2`偶数にしか到達できません。 共通のターゲットは存在しません。 

すべての値がすでに等しい場合、答えはゼロになります。 これは些細なことですが、実装時に無視してはなりません。 

もう 1 つの微妙なケースは、値は異なるがモジュロが整列している場合です。`d`、 例えば`[1, 5, 9]`と`d = 4`。 これらはすべて同等のモジュロ 4 であるため、値が大きく離れていても、解は存在します。 「すべてを平均と等しくする」という単純な直感はここでは失敗します。制約された手の下では平均化は無意味だからです。 

## アプローチ

 強引なアイデアは、考えられるすべての最終値を試し、すべての要素をその値に変換するコストを計算することです。 各操作で値が正確に変更されるため、`d`、有効な最終値はすべての要素と同じモジュロ クラスに存在する必要があります。 したがって、潜在的なターゲットとしてグリッドから各候補値を選択し、すべてのセルをそのターゲットに変換するために必要な合計ステップ数を計算できます。 

選ばれたターゲットに対して`t`、各要素`a[i][j]`貢献する`|a[i][j] - t| / d`割り算が成り立つと仮定して動きます。 これをすべてのセルで合計します。 すべての変換が独立しているため、これにより正確さが得られます。 

ただし、候補は最大 10,000 個、セルは最大 10,000 個あるため、これは約 1 億回の操作となり、まだ境界線にありますが、不要です。 さらに重要なのは、多くの同等の候補に対して基本的に同じ計算を繰り返していることです。 

重要な洞察は、すべての値が 1 つの等差数列モジュロ クラス内にあるということです。`d`ので、それらを正規化することができます。 すべての値を次の値で割ると、`d`共通剰余でシフトした後、問題は、絶対偏差を最小化する単一の整数ターゲットを選択することになります。 これは古典的な「絶対差の和を最小化する」問題であり、中央値によって最適に解決されます。 

したがって、各値を次のように変換します`b[i] = a[i] // d`（実現可能性を確保した上で）。 最適なターゲットは次の中央値です。`b`これは、絶対偏差の合計が中央値で最小化されるためです。 中央値を選択すると、答えは単純にそこまでの合計距離になります。

 | --- | --- | --- | --- |
 | ターゲットに対するブルートフォース | O(n²m²) | お(1) | 遅すぎる |
 | 並べ替え + 中央値の削減 | O(nm log(nm)) | O(nm) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. マトリックスを読み取り、すべての値を 1 つのリストに平坦化します。 これにより、行と列の構造が必要なくなるため、推論が簡素化されます。 
2. すべての値が同じ剰余モジュロを共有していることを確認して、実現可能性をチェックします。`d`。 値が 1 つでも異なる場合は、すぐに戻ります`-1`なぜなら、一連の ±d 演算は異なる残基クラスを橋渡しできないからです。 
3. 各値を次の値で割って正規化します。`d`。 これにより、問題が直線上の整数ステップに変換され、各演算は ±1 になります。 
4. 正規化された値を並べ替えます。 最適なミーティングポイントは算術平均ではなく注文統計に依存するため、並べ替えが必要です。 
5. ターゲットとして中央値を選択します。 これは、すべての点を中央値に移動すると、1D 配列の絶対偏差の合計が最小化されるため機能します。 
6. 中央値との差の絶対値を合計して総コストを計算します。 

### なぜ効果があるのか

 それぞれの移動により、正規化された空間内で 1 つのセルが正確に 1 単位だけシフトされるため、すべてのセルがラインに沿って独立して進化します。 総コストは、選択したポイントまでの距離の合計です。 1 次元では、絶対偏差によって形成される関数は凸状で区分的に線形であり、その最小値は常に中央値にあります。 共有制約の下でグリッドを独立した 1D ポイントに縮小したため、セル間の相互作用は最適性に影響を与えず、中央値を選択することで全体的な移動量が最小限に抑えられます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, d = map(int, input().split())
    vals = []

    for _ in range(n):
        row = list(map(int, input().split()))
        vals.extend(row)

    # feasibility check: all must share same mod d
    r = vals[0] % d
    for v in vals:
        if v % d != r:
            print(-1)
            return

    # normalize
    vals = [v // d for v in vals]
    vals.sort()

    median = vals[len(vals) // 2]

    ans = 0
    for v in vals:
        ans += abs(v - median)

    print(ans)

if __name__ == "__main__":
    solve()
```この解決策は、すべての推論を単一の配列で実行できるように行列を平坦化することから始まります。 モジュロ チェックにより、不可能な変換が試行されることがなくなります。 による除算`d`操作スペースを削減して、各移動が単位ステップに対応するようにします。これは、中央値の引数を適切に適用するために不可欠です。 

並べ替えは重要なステップです。順序付けがなければ、中央値を効率的に特定することはできません。 最後のループは合計距離を計算します。これは、正規化された空間で必要な ±1 ステップの数に直接対応します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    return sys.stdin.readline  # placeholder, replaced below

def solve():
    input = sys.stdin.readline
    n, m, d = map(int, input().split())
    vals = []
    for _ in range(n):
        vals.extend(map(int, input().split()))

    r = vals[0] % d
    for v in vals:

    return solve()

 ## 特殊なケース

 次のような完全に均一なグリッド`[[7,7],[7,7]]`は、アルゴリズムが正規化後に正しく短絡していることを示しています。すべての値が一致し、中央値が値に等しく、コストの合計がゼロです。 

次のような互換性のない残基を含むグリッド`[[1,2],[3,4]]`いつ`d=2`即時拒否を引き起こします。 モジュロ チェックは並べ替えの前にこれを検出し、不必要な計算を回避します。 

単一セル グリッドは、中央ステップがきれいに縮退していることを示しています。唯一の要素がすでにターゲットであり、アルゴリズムは標準ロジックを超える特別なケースを使用せずに正しくゼロを返します。
