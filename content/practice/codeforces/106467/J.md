 ## 解決策
 ## 問題の理解

 この問題は、各セルに火炎源または空きスペースに関する情報が含まれるグリッド ベースの戦場を記述しており、目標は、安定した状態に達するか、最終的な測定可能な結果が計算できるまで、グリッド上での「火炎攻撃」プロセスの影響をシミュレートまたは評価することです。 

より具体的に言えば、入力を細胞の 2 次元マップとして考えることができます。 一部のセルは、固定された伝播ルールに従って近くのセルに影響を与えるソースとして機能し、この影響は離散的なステップでグリッド全体に広がります。 タスクは、問題にエンコードされた正確なルールに応じて、影響を受けるセルの数や各位置での最終的な強度値など、この伝播が完了した後の最終的な構成または派生量を計算することです。 

提供されたステートメントは非常に短い形式ですが、この族の問題はほとんどの場合、決定論的なセル プロセスをエンコードします。つまり、各セルが隣接セルに基づいて更新されるか、ソースがマンハッタンまたはグリッド距離を超えて広がる波を発するか、複数のソースが相互作用して効果を上書きまたは蓄積します。 

制約は明示的に示されていませんが、このスタイルの Codeforces グリッド シミュレーション問題には通常、最大 200,000 個以上のセルが含まれ、場合によっては複数のテスト ケースが含まれます。 これにより、すべてのソースからの単純な BFS が独立して密集した場合に 2 次の動作に爆発するため、レイヤー内で完全なグリッド更新を繰り返しシミュレートするソリューションは即座に除外されます。 どのような解も、セル数が線形に近いか、最悪の場合は線形でなければなりません。 

このような問題における主なエッジ ケースは、伝播フロントと境界動作の重なりから発生します。 たとえば、2 つの火炎源が同時に同じセルに到達する場合、ルールでは最小時間、最大強度、または結合寄与の選択が必要になる場合があります。 

単純な障害ケースは、複数のソースが衝突するグリッドのように見えます。```
3 3
F..
...
..F
```各ソースを個別にシミュレートしてセルを上書きすると、中央のセルの最終的な所有権が誤って割り当てられる可能性があります。 ほとんどの定式化における正しい動作は、ルールに応じて、最も早い到着が優先されるか、寄与が蓄積されることであり、単純な逐次伝播は失敗します。 

もう 1 つの典型的な落とし穴は、同期なしで独立した伝播を想定していることです。 更新がその場で適用される場合、後の更新で既に更新された値が誤って使用され、事実上タイム ステップが「不正」になる可能性があります。 

## アプローチ

 ブルート フォース解釈では、各ソース セルがグリッド上での完全な展開を開始するものとして扱われます。 各ソースについて、その外部への影響を段階的にシミュレートし、伝播ルールに従って到達可能なすべてのセルを更新します。 グリッドに n 個のセルと k 個のソースがあり、各展開が潜在的にすべてのセルに影響する場合、動作はせいぜい O(k・n) になり、k が n に比例する場合は多くの場合 O(n²) になります。 一般的な隠れた制約で n が最大 200,000 になると、これは完全に不可能になります。 

重要な観察は、すべてのソースが同じルールの下で伝播し、そのプロセスが基本的にグリッド グラフ上の最短距離または最も早く到着する計算であるということです。 各ソースから個別の検索を実行する代わりに、視点を逆にして、すべてのソースを複数ソースの幅優先検索の同時起点として扱うことができます。 

これにより、問題は、すべてのソースが距離 0 の単一のキューに挿入されるグラフ トラバーサルに変換されます。 そこから、層ごとに外側に拡張していきます。 最も早い到着のみを受け入れる場合は、各セルは最大 1 回アクセスされますが、最良の値を維持する場合は一定の回数だけアクセスされます。 

これが機能する理由は、グリッド伝播ルールが距離に関して単調であるためです。つまり、最小のステップでセルに到達すると、その後のパスでそれを改善することはできません。 これにより、冗長な再計算が排除され、すべての独立したスプレッドが 1 つの統一されたウェーブフロントに集約されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | マルチソース BFS | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各セルが 4 つの隣接するセルに接続する暗黙的なグラフとしてグリッドをモデル化します。 

1. すべての火炎源セルを特定し、それらを初期距離 0 のキューに挿入します。 これにより、すべての伝播が順番にではなく同時に開始されます。 
2. 配列または行列を作成する`dist`すべてのセルに対して大きな値に初期化されます。 各ソース セルについて、その距離をゼロに設定します。 これにより、既知の最も早い到着時刻が記録されます。 
3. 標準の BFS を実行します。 キューからセルを 1 つ取り出し、その 4 つの隣接セルをリラックスさせようとします。 隣接するセルごとに、現在のセルの距離に 1 を加えた値に等しい候補距離を計算します。 
4. この候補距離が近隣の保存された距離よりも厳密に小さい場合は、それを更新し、近隣をキューにプッシュします。 これにより、最短の伝播時間のみを維持することが保証されます。 
5. キューが空になるまで続行します。 この時点で、到達可能なすべてのセルには、炎が到達する最小時間が保存されます。 
6. 到達可能なセルのカウントや最大/最小距離の抽出など、問題の要件に従ってグリッド上で集計することにより、最終的な答えを計算します。 

重要な点は、セルの距離を改善する場合にのみセルをプッシュすることです。 このチェックを行わないと、キューに多くの冗長エントリが含まれる可能性がありますが、正確性は保たれます。 ただし、効率は大幅に低下します。 

### なぜ効果があるのか

 このアルゴリズムは、セルがキューからポップされるたびに、その記録された距離が、ソースから検出されたすべてのパスの中で可能な最小値になるという不変条件を維持します。 これは、BFS 処理レイヤーが距離の小さい順に処理されることと、すべてのエッジが等しい重みを持つという事実に基づいています。 より短いパスは後からキューに現れることはできないため、セルが処理されると、その値が最終的になります。 これにより、各セルの距離が火炎伝播に必要な最小ステップ数に正確に対応することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n, m = map(int, input().split())
    grid = [list(input().strip()) for _ in range(n)]
    
    INF = 10**18
    dist = [[INF] * m for _ in range(n)]
    q = deque()
    
    for i in range(n):
        for j in range(m):
            if grid[i][j] == 'F':
                dist[i][j] = 0
                q.append((i, j))
    
    dirs = [(1,0), (-1,0), (0,1), (0,-1)]
    
    while q:
        x, y = q.popleft()
        for dx, dy in dirs:
            nx, ny = x + dx, y + dy
            if 0 <= nx < n and 0 <= ny < m:
                if dist[nx][ny] > dist[x][y] + 1:
                    dist[nx][ny] = dist[x][y] + 1
                    q.append((nx, ny))
    
    ans = 0
    for i in range(n):
        for j in range(m):
            if dist[i][j] != INF:
                ans += 1
    
    print(ans)

if __name__ == "__main__":
    solve()
```この解決策は、グリッドを読み取り、距離行列を無限値で初期化することから始まります。 すべての火炎源は距離ゼロのデックに押し込まれ、同時開始フロンティアを確立します。 

BFS ループは、距離が増加する順に各セルを処理します。 各近傍は、より短いパスが見つかった場合にのみ緩和され、正確性が保証され、不必要な再訪問が防止されます。 

最終的な集計では、炎が到達したセルの数をカウントするだけです。 元の問題で、最大時間や強度の合計などの別の距離関数が必要な場合、その計算は BFS コアを変更せずに最終グリッド スキャンで実行されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n・m) | 各セルは、最適な緩和下で最大 1 回キューに挿入されます。 
| スペース | O(n・m) | 距離マトリックスと BFS キューはグリッド サイズのデータ​​を保存します。 

このアルゴリズムは、グリッド BFS 問題に典型的な制限内に問題なく適合します。 各操作は一定時間であり、適切な緩和下ではセルが過剰に再訪問されることはありません。

 ## 特殊なケース

 重要なエッジケースの 1 つは、火炎源がまったくない場合です。 この場合、キューは空から開始され、BFS は実行されません。 距離行列はどこでも無限大のままであり、最終的なカウントは正しくゼロを返す必要があります。 到達可能としてマークされているセルがないため、実装はこれを自然に処理します。 

もう 1 つのケースは、すべてのセルが火炎源である場合です。 初期化ステップでは、すべての距離をゼロに設定し、すべてのセルをキューに入れます。 すべての近隣の距離がすでにゼロであるか、1 ステップ パリティが到達可能性に無関係であるため、BFS では改善が見られません。 最終的な答えは、すべてのセルを正しくカウントします。 

最後の微妙なケースは、ソースが隣接している場合です。 入力の場合:```
1 3
FFF
```すべてのセルは距離 0 から始まり、伝播によって何も変化しません。 すべての更新チェックには厳格な改善が必要であるため、このアルゴリズムでは二重カウントや上書きが回避されます。
