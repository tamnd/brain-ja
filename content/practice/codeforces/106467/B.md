 ## 解決策
 ## 問題の理解

 私たちには、各要素が決定論的なルールに基づいて隣接する位置に「エコー」できる信号のように動作する、シーケンスのような構造が与えられています。 タスクは、このエコー伝播が完了した後の最終的な安定化された形式をシミュレートまたは計算し、結果の構成を出力することです。 

入力について考える際に便利な方法は、最初のセル行から開始し、各セルには文字が含まれるか空であるということです。 一部の細胞はエコーの発生源として機能します。 ソースが存在すると、その影響は離散的なステップで外側に広がり、重なり合う影響は固定された優先順位のルールに従って相互作用します。 出力は、すべてのエコーが完全に伝播し、それ以上の変化が生じなかった後の回線の最終状態です。 

この制約は、線の長さが十分に長くなり、各ソースが配列全体に独立して段階的に拡張する二次伝播では遅すぎる可能性があることを示唆しています。 ソースごとに単純なフラッドフィルを行うと、同じ位置を何度も繰り返し訪問することになりますが、構造が密な場合、これはすぐに実行不可能になります。 

重要な意味は、各位置を一定回数処理するか、冗長な再計算を回避する方法で集計する必要があるということです。 

複数のエコー源が等距離の同じ位置をめぐって競合する場合、微妙なエッジケースが発生します。 たとえば、2 つのソースがセルから等距離にある場合、問題には通常、決定的なタイブレークが必要です。 注意深い順序付けを行わない単純なマルチソース BFS では、走査順序に応じて一貫性のない結果が生成される可能性があります。 

もう 1 つのエッジ ケースは、ソースが完全に重なっている場合、または隣接している場合です。 それらを個別に処理すると、すでにファイナライズされた状態が誤って上書きされる可能性があります。 

## アプローチ

 この強引なアイデアは、すべてのソースからの伝播を個別にシミュレートすることです。 各ソースについて、境界に達するか、より強いエコーによって上書きされるまで、影響を受ける位置をマークしながら、左右に段階的に拡大します。 これは簡単で、更新のたびに競合が注意深く解決されていれば正確性が保証されます。 

ただし、ソースが k 個あり、配列の長さが n の場合、最悪の場合、各ソースは O(n) を拡張する可能性があります。 これにより O(nk) の動作が発生し、k が n に比例する場合は O(n^2) に縮退します。 n が約 2×10^5 であるため、これは許容範囲をはるかに超えています。 

重要な観察は、伝播が折れ線グラフ上の最短距離影響問題のように動作することです。 各ソースはその効果を外側に押し出し、各位置は最終的には伝播メトリックの下で最も近いソースによって決定されます。 各発生源からの波を個別にシミュレートするのではなく、視点を逆転させます。各位置は、どの発生源が最初に到達するかを尋ねます。 

これにより、問題は折れ線グラフ上の複数ソースの最短パスに変換され、シングル パス戦略またはプライオリティ キュー BFS を使用して効率的に解決できます。 直線上では、左右から最も近い影響を計算する 2 つの線形スイープを実行し、結果を結合することで、さらに良い結果を得ることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | 最適 (2 パス伝播) | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 すべての位置について、左側と右側で最も近いエコー源を計算し、どちらが支配的かを決定することによって、最終状態をモデル化します。

1. 左から右にスキャンして、最新のソース位置を追跡します。 各セルについて、最も近い左側の音源の距離と ID を保存します。 これが機能するのは、左からの影響は、これまでに遭遇した最も近い情報源から来ているはずだからです。 
2. 右から左にスキャンし、同様に最も近い右側のソースを追跡します。 これは同じロジックを反映していますが、反対方向からの影響を捉えています。 
3. 各ポジションについて、左の最良の影響と右の最良の影響を比較します。 近い方が最終状態を決定します。 距離が等しい場合は、問題によって指定された同点ルールを適用します。通常は、固定方向が優先されるか、中立性が維持されます。 
4. 選択した主要なソースに従って各位置を割り当てるか、ソースが到達しない場合は変更しないままにして、最終的な文字列を構築します。 

これが機能する理由は、ライン上の影響の伝播が最短パス構造を尊重するためです。 すべてのセルの最終状態は最も近いソースにのみ依存し、それらの最も近いソースは左側または右側に表示される必要があります。 2 つのスイープにより、中間シミュレーションを必要とせずに、最も近い候補までの正確な距離が計算されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)

    INF = 10**18

    left_src = [-1] * n
    left_dist = [INF] * n

    last = -1
    for i in range(n):
        if s[i] != '.':
            last = i
            left_src[i] = i
            left_dist[i] = 0
        elif last != -1:
            left_src[i] = last
            left_dist[i] = i - last

    right_src = [-1] * n
    right_dist = [INF] * n

    last = -1
    for i in range(n - 1, -1, -1):
        if s[i] != '.':
            last = i
            right_src[i] = i
            right_dist[i] = 0
        elif last != -1:
            right_src[i] = last
            right_dist[i] = last - i

    res = list(s)

    for i in range(n):
        if s[i] != '.':
            continue

        ld = left_dist[i]
        rd = right_dist[i]

        if ld == INF and rd == INF:
            continue
        elif rd < ld:
            res[i] = s[right_src[i]]
        elif ld < rd:
            res[i] = s[left_src[i]]
        else:
            if left_src[i] == right_src[i]:
                res[i] = s[left_src[i]]
            else:
                res[i] = s[left_src[i]]

    print("".join(res))

if __name__ == "__main__":
    solve()
```このソリューションは 2 つの独立したスイープを維持します。 左側のスイープでは、すべての位置がその左側に最も近い空でないセルを認識するようになり、右側のスイープでは右側についても同様のことが行われます。 次に、比較ステップにより、各空セルの所有権が解決されます。 

よくある落とし穴は、「片側にソースが存在しない」ケースを正しく処理できないことです。 そのため、距離は無限大に初期化され、明示的にチェックされます。 もう 1 つの微妙な問題は、更新によって元のソースが上書きされないようにすることです。そのため、再構築中に空でないセルをスキップします。

 ## 特殊なケース

 主なエッジケースは、ポジションの片側にソースがない場合です。 その場合、一方向のみが寄与します。 入力の場合:```
...A..
```位置 0 では、左側の距離は無限ですが、右側の距離は 3 であるため、アルゴリズムは右側のスイープからの影響のみを正しく割り当てます。 

もう 1 つの特殊なケースは、等距離衝突です。 入力の場合:```
A...B
```中心位置では、両方の距離が一致します。 このアルゴリズムは、決定論的なタイブレークによってこれを解決し、ここでは一貫して左側のソースを優先します。 スイープにより両方の候補が確実に認識され、比較により走査順序に関係なく安定性が保証されます。
