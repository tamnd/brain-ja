 ## 解決策
 ## 問題の理解

 それぞれが別個の座標を持つ平面内の一連の点が与えられ、すべてのエッジが平面内で下向きでなければならないという追加の幾何学的制約を付けて、それらを有向根付き二分木に接続するように求められます。 より具体的には、ノード _u_ が座標を持っている場合$(x_u, y_u)$ノード _v_ には座標があります$(x_v, y_v)$、_u_ から _v_ までのエッジは、次の場合にのみ存在できます。$y_u > y_v$。 すべてのエッジの合計ユークリッド長を最小化するようなツリーを構築するか、レポートするように求められます。`-1`それが不可能な場合。 

入力サイズは最大 400 ノードです。 この規模では、次のようなアルゴリズムが必要になります。$O(n^4)$あるいはさらに悪いことに複雑さが遅すぎるのですが、$O(n^3)$または$O(n^2 \log n)$3 秒の制限は許容されます。 各ノードは最大 2 つの子を持つことができるため、組み合わせの制約が生じますが、下向きの方向により、利用できる自然な順序が提供されます。 

素朴なエッジ ケースは、完全なバイナリ ツリーを下向きに作成できるルートを選択できないような方法でポイントが位置合わせされている場合です。 たとえば、水平線内の 3 つの点は、他の 2 つの点より厳密に上にないため、下向きのツリーを形成することはできません。 このような場合、正しい出力は次のとおりです。`-1`。 各ノードをその最も近い下位ノードに接続するだけの不注意なアプローチでは、3 つ以上の子を持つサイクルまたはノードが生成される可能性があります。 

## アプローチ

 ブルート フォース ソリューションでは、考えられるすべてのルート、各親の子ノードのすべてのサブセットを試行し、バイナリ制約を強制しながらノードを再帰的に接続します。 のために$n = 400$、木の数が超指数関数的に増加するため、これは不可能です。$n$。 

重要な観察は、下向き制約が半順序を誘発するということです。エッジは、より大きな y 座標を持つノードからより小さな y 座標を持つノードにのみ進むことができます。 これは、ノードを y 座標で降順に並べ替え、サブツリーを段階的に構築しようとする動的プログラミング アプローチを示唆しています。 すべてのノードは最大 2 つの子を持つことができるため、問題を最小コスト フロー問題としてモデル化できます。ノードを頂点として、潜在的なエッジをユークリッド距離に対応する容量とコストを持つ円弧として表現し、容量を介して二分木制約を適用できます。 

具体的には、フローグラフ内の各ノードを「インノード」と「アウトノード」に分割します。 各親は、2 つの子エッジを表す、最大 2 つのフロー ユニットを子ノード内に送信できます。 ルート ノードは特別であり、着信フローを受け取りません。 このネットワーク上で最小コスト フローを解くと、有効なバイナリ ツリーが存在する場合、その最小全長が得られます。 ノードの制約に従って最小コストのフローがネットワークを飽和させることができない場合、ツリーは不可能です。

 ## アルゴリズムのチュートリアル

 1. すべてのノードの座標を読み取り、それらを点のリストに保存します。 フロー グラフで参照できるように、各ノードにインデックスのラベルを付けます。 
2. 有向二部フロー ネットワークを構築します。 

- 各ノードは「インノード」と「アウトノード」に分割されます。 
- 潜在的な親 _u_ と子 _v_ ごとに、次の場合にのみ _u_ の出力ノードから _v_ の入力ノードにアークを追加します。$y_u > y_v$。 円弧のコストはユークリッド距離です$\sqrt{(x_u - x_v)^2 + (y_u - y_v)^2}$。 このアークの容量を 1 に設定します。 
3. サブツリーに送信できる子の最大数を表す容量 2 のルート候補の出力ノードに接続するソース ノードを追加します。 同様に、容量 1 のノード内から接続するシンク ノードを追加して、各ノードがちょうど 1 つの親を受信する必要があることをモデル化します (ルートは除き、親は受信しません)。 
4. このネットワーク上で最小コスト最大フロー アルゴリズムを実行します。 フローがすべてのノードを正しく飽和させる場合、フローのコストはバイナリ ツリーの最小全長になります。 フローが実行不可能な場合は、印刷してください`-1`。 
5. 計算された最小全長を返します。 

機能する理由: 親子割り当てを発信アークの容量 2 のフローとしてモデル化することにより、ネットワークは自然にバイナリ ツリー プロパティを強制します。 下向きの状態は円弧の方向にエンコードされます。 最小コスト フローにより、容量を考慮しながらエッジ長の合計が確実に最小化されます。これがまさに問題の目的です。 

## Python ソリューション```python
import sys
import math
import heapq
input = sys.stdin.readline

class Edge:
    def __init__(self, to, rev, cap, cost):
        self.to = to
        self.rev = rev
        self.cap = cap
        self.cost = cost

class MinCostFlow:
    def __init__(self, N):
        self.N = N
        self.graph = [[] for _ in range(N)]

    def add(self, fr, to, cap, cost):
        self.graph[fr].append(Edge(to, len(self.graph[to]), cap, cost))
        self.graph[to].append(Edge(fr, len(self.graph[fr])-1, 0, -cost))

    def flow(self, s, t, maxf):
        N = self.N
        prevv = [0]*N
        preve = [0]*N
        INF = float('inf')
        res = 0
        h = [0]*N

        while maxf > 0:
            dist = [INF]*N
            dist[s] = 0
            que = [(0, s)]
            while que:
                c, v = heapq.heappop(que)
                if dist[v] < c:
                    continue
                for i, e in enumerate(self.graph[v]):
                    if e.cap > 0 and dist[e.to] > dist[v] + e.cost + h[v] - h[e.to] + 1e-10:
                        dist[e.to] = dist[v] + e.cost + h[v] - h[e.to]
                        prevv[e.to] = v
                        preve[e.to] = i
                        heapq.heappush(que, (dist[e.to], e.to))
            if dist[t] == INF:
                return -1
            for v in range(N):
                h[v] += dist[v]
            d = maxf
            v = t
            while v != s:
                d = min(d, self.graph[prevv[v]][preve[v]].cap)
                v = prevv[v]
            maxf -= d
            res += d * h[t]
            v = t
            while v != s:
                e = self.graph[prevv[v]][preve[v]]
                e.cap -= d
                self.graph[v][e.rev].cap += d
                v = prevv[v]
        return res

def main():
    n = int(input())
    points = [tuple(map(int, input().split())) for _ in range(n)]

    S = 2*n
    T = 2*n+1
    mcf = MinCostFlow(2*n+2)

    for i in range(n):
        mcf.add(S, i, 2, 0)
        mcf.add(i+n, T, 1, 0)
    for i in range(n):
        xi, yi = points[i]
        for j in range(n):
            if i == j:
                continue
            xj, yj = points[j]
            if yi > yj:
                dist = math.hypot(xi - xj, yi - yj)
                mcf.add(i, j+n, 1, dist)

    res = mcf.flow(S, T, n-1)
    if res < 0:
        print(-1)
    else:
        print(res)

if __name__ == "__main__":
    main()
```コードはまず、親子の制約、容量、コストをエンコードするフロー ネットワークを構築します。 ノードは、各ノードが最大 1 つの親を受け取るようにするために、入力ノードと出力ノードに分割されます。 ソースはすべての潜在的なルート出力ノードに接続しますが、シンクは各ノードが 1 回だけ割り当てられるようにします。 min-cost フロー呼び出しは、最小合計エッジ長を返すか、`-1`実行可能な二分木が存在しない場合。
