 ## 解決策
 ## 問題の理解

 Vasya はいくつかの問題を抱えたプログラミング ラウンドに参加しており、それぞれが小さい入力と大きい入力に分かれています。 問題の小さな入力を完了すると、一定の時間内に保証されたポイント数が得られます。 大量の入力を完了するにはさらに時間がかかりますが、これは確率論的なものです。一定の確率で失敗する可能性があり、その場合はポイントは付与されません。 Vasya はすべてのスコア、時間、失敗の確率を事前に知っています。 ラウンドは一定期間継続し、提出は終了直後に行われる場合があります。 

課題は、制限時間内に Vasya が獲得できる予想合計ポイントを最大化することです。 複数のスケジュールが同じ予想ポイントを与える場合、予想タイムペナルティが最も低いスケジュールが優先されます。 時間ペナルティは、最後に成功した送信の時刻として定義され、小さい入力と成功した大きい入力にのみ関係します。 

制約により、問題数は最大 1000 件、合計時間は最大 1560 分であることが示されています。 これでは、問題の次数のすべての順列を試行するソリューションができなくなります。なぜなら、1000 個だからです。 天文学的に大きいです。 したがって、どのアプローチもおおよそ次のようにスケールする必要があります。$O(n \cdot t)$これは、これらのパラメーターの標準的な動的プログラミングの範囲に適合します。 

明らかではないエッジ ケースには、失敗の可能性が非常に高い大きな入力に時間を費やすと、期待されるポイントが複数の小さな入力を解決することで達成できる値よりも低くなる可能性があるシナリオが含まれます。 たとえば、大きな入力のポイントが 100 であるものの、失敗する可能性が 99% である場合、小さな問題を確実に解決する時間があれば、最初にそこに焦点を当てると、期待されるポイントが減る可能性があります。 同様に、小さな入力がポイントに比べて非常に時間がかかる問題は、小さな問題の方が 1 分あたりのポイント数の比率が高い場合、完全にスキップされる可能性があります。 

## アプローチ

 ブルート フォース アプローチでは、小さい入力と大きい入力を解決するすべての可能な順序が考慮され、各順列に対して予想されるポイントと予想されるペナルティが計算されます。 それぞれ 2 段階の問題が最大 1000 個あるため、順列の数はおよそ$(2n)!$、それは完全に不可能です。 

重要な観察は、小さい入力が最初に解決される限り、大きい入力の期待点は他の問題を解く順序とは無関係であるということです。 さらに、予想される時間ペナルティは、小さい入力が完了するか、大きい入力が成功した場合にのみ累積されます。 これら 2 つの観察により、費やした合計時間にわたって問題を動的計画問題に帰着させることができます。 

これを 2 次元の DP 問題として扱うことができます。`dp[time]`正確な場合、達成可能な最大予想ポイントを追跡します`time`分が経過しました。 各問題について、考えられる累積時間を逆方向に反復し、小さい入力のみを解決するか、小さい入力と大きい入力の両方を解決するという 2 つのオプションを検討します。 Large 入力からの期待ポイントは、その成功確率によって重み付けされます。 予想時間ペナルティは、予想の線形性を使用してそれに応じて更新されます。 

これを扱いやすくする洞察は、小規模と大規模の寄与を分離し、時間の経過とともに後方反復を使用して、他の決定に必要な状態の上書きを避けることで、ナップザックのような DP で各問題を個別に処理する機能です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O((2n)!) | O((2n)!) | 遅すぎる |
 | 最適なDP | O(n * t) | O(t) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. サイズの 2 つの配列を初期化します。`t + 1`。 1 つのアレイ`dp`各合計時間で達成可能な最大予想ポイントを追跡します。 別の配列`penalty`それらのポイントに対応する最小予想タイムペナルティを追跡します。 
2. 各問題を繰り返します。 現在の問題については、Small 入力からの保証ポイント、Large 入力からの期待ポイント (次の値で重み付け) を定義します。`1 - probFail`)、および小さい入力と大きい入力の時間。 
3. DP 配列を逆方向に処理します。`t`ゼロまで下げる。 それぞれについて`current_time`、Small input の追加のみが合計時間内に収まるかどうかを確認します。 そうであれば、新しい予想ポイントと新しい予想タイムペナルティを計算します。 アップデート`dp`そして`penalty`新しい予想ポイントが大きい場合、またはポイントが等しく予想ペナルティが小さい場合にのみ。 
4. 同様に、Small 入力と Large 入力の両方を追加しても適合するかどうかを確認します。 Large 入力の重み付けされた寄与を含む期待ポイントを計算します。 最後に成功した送信の時刻として予想されるペナルティを計算します。小さい入力は常に成功し、大きい入力は成功確率によって重み付けされた時間を寄与します。 アップデート`dp`そして`penalty`同じルールを使用します。 
5. すべての問題を処理した後、`dp`予想される最大ポイントとそれに対応する予想される最小タイムペナルティの配列。 これにより最終結果が得られます。 

機能する理由: DP は、合計時間ごとに、達成可能な最高の予想ポイントと、それに対応する予想される最小ペナルティを追跡することを保証します。 逆方向に処理することで、同じ問題からの寄与を二重にカウントすることを回避します。 逆方向反復では、現在の問題の前のすべての状態が修正され、達成可能なポイントとペナルティが正しく表現されるという不変条件が維持されます。 各問題は独立して考慮され、合計時間のすべての組み合わせが限界まで調査されるため、`t`、ソリューションは全体的に最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, T = map(int, input().split())
problems = []
for _ in range(n):
    scoreSmall, scoreLarge, timeSmall, timeLarge, probFail = input().split()
    scoreSmall = int(scoreSmall)
    scoreLarge = int(scoreLarge)
    timeSmall = int(timeSmall)
    timeLarge = int(timeLarge)
    probFail = float(probFail)
    problems.append((scoreSmall, scoreLarge, timeSmall, timeLarge, probFail))

dp = [0.0] * (T + 1)
penalty = [0.0] * (T + 1)

for scoreS, scoreL, timeS, timeL, fail in problems:
    expL = scoreL * (1 - fail)
    for t in range(T, -1, -1):
        # Small input only
        if t + timeS <= T:
            new_exp = dp[t] + scoreS
            new_pen = penalty[t] + timeS
            if new_exp > dp[t + timeS] or (abs(new_exp - dp[t + timeS]) < 1e-12 and new_pen < penalty[t + timeS]):
                dp[t + timeS] = new_exp
                penalty[t + timeS] = new_pen
        # Small + Large
        if t + timeS + timeL <= T:
            new_exp = dp[t] + scoreS + expL
            new_pen = penalty[t] + timeS + timeL * (1 - fail)
            if new_exp > dp[t + timeS + timeL] or (abs(new_exp - dp[t + timeS + timeL]) < 1e-12 and new_pen < penalty[t + timeS + timeL]):
                dp[t + timeS + timeL] = new_exp
                penalty[t + timeS + timeL] = new_pen

max_points = max(dp)
idx = dp.index(max_points)
min_penalty = penalty[idx]

print(f"{max_points:.10f} {min_penalty:.10f}")
```DP 配列には、費やした合計時間ごとに予想されるポイントとペナルティが保存されます。 同じ問題を複数回再利用しないように、後方に反復処理します。 大規模な入力からの期待ポイントに成功確率が乗算されます。 時間ペナルティは直線的に蓄積され、大量の入力が成功に応じて加重されます。 精度誤差を処理す​​るために、浮動小数点と許容誤差を比較する際に注意が払われます。 

## 実用的な例

 サンプル 1:

 | 0 | 0 | 0 |
 | 1 | 1 | 1 |

 | 4 | 1 | 1 |
 | 5 | 1 | 1 |

 | 最終回 | 24 | 18.875 |

 これにより、最初に小さい小さい入力を選択し、次に大きい入力を選択すると、予想される時間ペナルティを最小限に抑えながらポイントが最大化されることが確認されます。 

カスタムの小さな入力:```
2 10
5 10 5 5 0.5
3 6 3 3 0.1
```DP には、まず 2 番目の問題の小さな入力 (時間 3、ポイント 3)、次に最初の問題の小さな入力 (時間 5、ポイント 5)、そして大きな入力のための時間があるかどうかを確認します。 部分的な大きな入力のみが合計時間に適合し、DP は期待されるポイントが最大化され、ペナルティが最小限に抑えられることを保証します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

| スペース | O(T) | サイズ T+1 の 2 つの配列には DP とペナルティが格納されます。特別に大きな構造はありません。 

n ≤ 1000 および T ≤ 1560 の場合、このソリューションは最新の CPU で 2 秒未満で実行されます。
