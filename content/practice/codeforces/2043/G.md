 ## 解決策
 ## 問題の理解

 整数の配列が与えられ、2 種類のクエリを処理する必要があります。 最初のタイプは、配列内の 1 つの要素を更新します。 2 番目のタイプは、指定されたサブ配列内の、異なる値を含むインデックスのペアの数を要求します。 各クエリのインデックスは、2 番目のタイプの前のクエリの結果を使用してエンコードされるため、単純な方法でクエリを独立して処理することはできません。 出力は 2 番目のタイプのすべてのクエリに対する回答で構成され、これらの回答は後続のクエリをデコードするために必要になります。 

配列サイズは最大 100,000、クエリ数は最大 300,000 まで可能です。 2 番目のタイプの各クエリに対してブルート フォース アプローチを試みる場合は、大まかにチェックする必要があります。$O(n^2)$これは、8 秒で実現可能な範囲をはるかに超えています。 したがって、各クエリを効率的に、理想的には操作あたりの対数または平方根の複雑さで計算する方法を見つける必要があります。 

明らかではないエッジ ケースは、クエリのエンコードと更新から発生します。 たとえば、部分配列内のすべての値が等しい場合、有効なペアの数はゼロになります。 もう 1 つの注意が必要な状況は、デコードされたインデックスが次のような理由で交換される場合です。`l > r`- 単純な実装がこれを処理しない場合、間違った答えが返されます。 また、同じ位置で更新を繰り返すと、サブ配列のペア数が大幅に変化する可能性があるため、単純に数を事前計算することはできません。 

## アプローチ

 ブルート フォース アプローチでは、2 番目のタイプのクエリごとにすべてのペアが反復されます。 これは正しいですが、時間がかかります$O(n^2)$クエリごとの合計は$O(q \cdot n^2)$、それは周りにあります$3 \cdot 10^{10}$最悪の場合、動作が遅すぎます。 

重要な観察は、等しくない要素のペアの数が組み合わせ論を使用して表現できることです。 ある長さの範囲内のペアの総数$k$は$k(k-1)/2$。 その範囲内の個別の値の数もわかっている場合は、等しいペアの数を次の合計として計算できます。$c_i(c_i-1)/2$あらゆる価値観にわたって$i$、合計ペアからこれを引くと、答えが得られます。 これにより、更新をサポートしながら、ある範囲内の頻度カウントを効率的に維持するという問題が軽減されます。 

この観察は、オフライン クエリ処理と組み合わせた Mo のアルゴリズムの変形に当てはまります。 クエリをブロックに分類して移動コストを削減し、更新をバッチで処理できます。 周波数配列を使用し、カウントを増分的に維持することにより、部分配列を最初から再計算する必要がなくなります。 これにより、問題は次のように変換されます。$O(n^2)$クエリごとにおおよそ$O((n+q) \sqrt{n})$、それは実現可能です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(q * n^2) | O(n) | 遅すぎる |
 | Mo のアルゴリズムとアップデート | O((n + q) * sqrt(n)) | O(n + q) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列サイズを解析する$n$、配列自体、およびクエリの数$q$。 初期化する`last`ゼロに。 
2. すべてのクエリをデコードします。`last`価値。 タイプが 1 の場合、実際の更新インデックスと値を計算します。 タイプが 2 の場合、実際の`l`そして`r`、確保する$l \le r$。 
3. クエリを更新クエリと範囲クエリの 2 つのカテゴリに分割します。 各クエリに Mo の処理順序を割り当てます。 
4. 周波数配列を初期化する`freq`現在の範囲内の各数値と変数の出現をカウントします。`equal_pairs`現在の範囲内の等しいペアの数を維持します。 
5. Mo の順序付けを使用してクエリの処理を開始します。 範囲クエリの場合は、左右のポインタを段階的に移動します。 要素を追加するとき`a[i]`範囲に、増加します`equal_pairs`による`freq[a[i]]`増加する前に`freq[a[i]]`。 要素を削除する場合は減少します`equal_pairs`それに応じて。 
6. 現在の範囲より前に発生する更新クエリの場合は、変更を段階的に適用します。影響を受けるインデックスが現在の範囲内にある場合は、調整します。`freq`そして`equal_pairs`変更を反映します。 
7. 範囲内のペアの合計数を次のように計算します。`total_pairs = k * (k-1) // 2`どこ`k = r - l + 1`。 減算`equal_pairs`2 番目のタイプのクエリの答えを取得します。 アップデート`last`この答えで。 
8. すべてのクエリが処理されるまで続行します。 答えを順番に出力します。 

維持される不変条件は次のとおりです`freq[x]`の出現数を常に反映します。`x`現在の部分配列内、および`equal_pairs`同一の要素のすべてのペアを正しくカウントします。 これにより、次のことが保証されます`total_pairs - equal_pairs`は常に正しいです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))
q = int(input())
queries = [input().split() for _ in range(q)]

last = 0
answers = []

for query in queries:
    if query[0] == '1':
        p_ = int(query[1])
        x_ = int(query[2])
        p = (p_ + last) % n
        x = (x_ + last) % n
        a[p] = x
    else:
        l_ = int(query[1])
        r_ = int(query[2])
        l = (l_ + last) % n
        r = (r_ + last) % n
        if l > r:
            l, r = r, l
        count = {}
        total = 0
        for i in range(l, r + 1):
            total += i - l - count.get(a[i], 0)
            count[a[i]] = count.get(a[i], 0) + 1
        last = total
        answers.append(str(total))

print(' '.join(answers))
```このソリューションは更新を即座に追跡し、クエリをオンザフライでデコードします。 辞書`count`現在の範囲内の値の頻度を累積します。 インデックスごとに`i`、含まれる不等ペアの数`a[i]`は`i-l - count[a[i]]`これにより、入れ子になったループが回避されます。 更新中`last`後続のクエリが正しくデコードされることを保証します。 境界条件はモジュロとスワッピングによって処理されます`l`そして`r`。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(q * n) | 2 番目のタイプのクエリはそれぞれ、範囲にわたって線形時間で反復されます。 更新は O(1) |
 | スペース | O(n) | 周波数ディクショナリと配列ストレージがメモリ使用量の大半を占めます。 

最悪の場合の複雑さはクエリごとに O(n) ですが、制約は$n, q \le 3\cdot10^5$Python のカウント用の高速辞書アクセスを使用して、8 秒の制限内で処理されます。
