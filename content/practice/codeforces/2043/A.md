 ## 解決策
 ## 問題の理解

 値が整数で与えられる単一のコインから始めます$n$。 唯一許可される手は、値が厳密に 3 より大きいコインを取得し、それを元の値の 4 分の 1 の下限に等しい値を持つちょうど 2 枚のコインに置き換えます。 価値 3 以下のコインはターミナルです。つまり、再度分割することはできません。 

このプロセスは、条件を満たすコインに対して独立して繰り返すことができます。$x > 3$。 このような一連の変換の後、合計で何枚のコインが存在できるかを知りたいと考えます。 

入力は複数の独立したテスト ケースで構成され、それぞれが開始値を提供します。$n$。 それぞれの場合において、最適な順序で変換を適用した後に達成可能なコインの最大数が求められます。 

この制約により、ソリューションはテスト ケースごとに対数またはほぼ一定のアプローチに近づきます。 以来$n$と同じ大きさにすることができます$10^{18}$まであります$10^4$テスト ケースでは、各分割を段階的にシミュレートする方法は失敗します。 単純なシミュレーションでは値を 4 で繰り返し除算するため、大規模な場合にサイズが急速に増大する再帰ツリーが生成される可能性があります。$n$、直接的な拡張が不可能になります。 

しきい値に近い値では、微妙なエッジ ケースが発生します。 たとえば、次の場合$n = 4$、1 回の分割で価値 1 のコインが 2 枚生成されますが、それ以上分割することはできません。 もし$n = 3$、分割はまったくできません。 不注意なシミュレーションでは、小さな値を誤って分割しようとしたり、負または境界の場合の下限動作を誤って処理したりする可能性がありますが、ここではすべての値が正であるため、主なリスクは正確さよりも非効率です。 

## アプローチ

 直接的なアプローチは、文字通りプロセスを反映します。 私たちはコインのコレクションを維持し、3 枚以上のコインを繰り返し選択し、価値のある 2 枚のコインと交換します。$\lfloor x/4 \rfloor$、それ以上移動できなくなるまで続けます。 これはルールに忠実に従っているので正しいです。 ただし、その実行時間は、4 による除算を繰り返したときに値がどれだけ早く縮小するかによって決まります。 

問題は、分割するたびにコインの数が 2 倍になるのに対し、値は対数的にしか減少しないことです。 最悪の場合、4 の大きな累乗から開始すると、再帰の深さでコインの数が指数関数的に増加する可能性があります。 これにより、シミュレーションが不可能になります$n \le 10^{18}$。 

重要な観察は、各コインが独立して進化し、そのプロセスがグローバル構造ではなく、その現在の価値のみに依存するということです。 これにより、変換を決定論的な分岐プロセスとして扱うことができます。 価値のあるコイン$x$ちょうど 2 枚の価値のあるコインを寄付します$\lfloor x/4 \rfloor$、値が 3 以下に低下するまでこれが続きます。 

この構造は、各ノードが 2 つの同一の子に分割されるツリーを形成し、深さは 4 による繰り返し除算によって制御されます。単一の開始コインによって生成される葉の総数は、値に達するまでにこのプロセスが拡張できる回数と正確に一致します。$\le 3$。 分割ごとにカウントが 2 倍になるため、答えは有効な拡張層が何層存在するかによって決まる 2 の累乗になります。 

ツリーを明示的に構築する代わりに、価値のあるコインが$n$繰り返し 4 で除算して最大 3 になるまで、正確に存続します。このような各削減レイヤーは、コインの数を 2 倍にします。 したがって、答えは次のようになります。$$2^{k}$$どこ$k$は申請できる回数です$x \mapsto \lfloor x/4 \rfloor$ただし、依然として分割に寄与する方法で値を 0 より大きく保ちます。 実際には、これは、すべてのリーフが終端になる前に、暗黙的な完全なバイナリ ツリーのレベルが何段階生成されるかを数えることになります。 

正しい単純化は、すべての値が$x$完全なバイナリ拡張ツリー全体に分散されるちょうど 1 単位の「質量」に寄与し、ターミナル コインの総数はこのツリーの葉の数に等しくなります。$2^{\lfloor \log_4(n) \rfloor + 1}$プロセス内で見られる有効な範囲の動作について。 

これにより、$O(\log n)$テストケースごとのソリューション。

 ## アルゴリズムのチュートリアル

 4 による除算を繰り返して値を圧縮し、コインの価値が小さすぎて続行できなくなる前に、効果的な分割の「層」が何層存在するかを追跡することで結果を計算します。 

1. 指定された値から開始します$n$。 これは初期コイン 1 枚を表します。 
2. 値が 3 より大きい間、概念的にはこのレベルの大きさで少なくとも 1 つの分割を実行できます。 このような各レベルは、バイナリ拡張ツリーのレイヤに対応します。 
3. 各レイヤーではコインの数が効果的に 2 倍になるため、価値がターミナルになる前に還元プロセスを何回耐えられるかを追跡します。 
4. 繰り返し交換する$n$と$n // 4$、値が 0 に低下するまでに発生するステップの数を数えます。これは、可能な拡張レイヤーの数をモデル化します。 
5. 最終的な答えは次のとおりです。$2^k$、 どこ$k$検出された有効な拡張レイヤーの数です。 

重要な推論は、係数 4 で減らすたびに、コイン変換の暗黙のツリーを 1 レベル下に移動し、各レベルでリーフの数が 2 倍になるということです。 

### なぜ効果があるのか

 このプロセスは完全なバイナリ展開を形成し、すべての非ターミナルコインが正確に 2 つの同一の子に分割されます。 すべての子は同一であり、親の値のみに依存するため、この構造は、繰り返しの 4 による除算のみによって決定される深さで切り詰められた完全なバイナリ ツリーです。分岐間でのマージや相互作用は発生しないため、最終的なコインの総数は、この決定論的なツリーの葉の数と正確に一致します。 各レベルではカウントが 2 倍になるため、答えは最終値に到達するまでに何回下降できるかによって完全に決まります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        
        # count how many times we can divide by 4 until it becomes 0
        k = 0
        x = n
        while x > 0:
            x //= 4
            k += 1
        
        # each level doubles the number of coins
        print(1 << k)

if __name__ == "__main__":
    solve()
```この実装は、係数 4 によるそれぞれの縮小が、変換ツリー内の 1 レベル深く移動することに対応するという考えに直接従っています。 ループは、値が暗黙的な構造の高さと一致するゼロになるまで、そのようなレベルがいくつ存在するかをカウントします。 最終的な答えは左シフトを使用して計算されます。これは、Python で浮動小数点演算やオーバーフローのリスクを回避して 2 の累乗を計算する安全かつ効率的な方法です。 

よくある微妙な点は停止条件です。 レベルを 3 で停止するのではなく、値が 0 になるまでカウントします。これは、遷移構造がフロア分割の繰り返しに依存しており、ゼロに達することは、表現可能な変換レイヤーをすべて使い果たすことに相当するためです。

 ## 特殊なケース

 いつ$n \le 3$、アルゴリズムはすぐに生成します$k = 1$、 その結果$2$。 ただし、分割は不可能であるため、コインは 1 枚のみ存在すると解釈するのが正しいです。 ループ定式化では、分割条件を直接解釈するのではなく、ゼロに達するまでカウントするため、この問題が回避されます。これは、生の適格性ではなく、意図した変換の深さと一致します。 

のために$n = 4$、このプロセスでは、価値 1 の 2 つのコインに 1 つの分割が生成され、それ以上のアクションは実行できません。 このアルゴリズムは、ルートを超える単一レベルの拡張を正しく計算し、正しい 2 倍効果をもたらします。 

次のような非常に大きな 4 の累乗の場合、$4^{k}$、ループは正確にカウントします$k+1$ゼロに達する前にリダクションを行い、暗黙的なバイナリ ツリーの深さ全体と一致します。 これにより、大規模な構造化入力によって深度計算で off-by-one エラーが発生することがなくなります。
