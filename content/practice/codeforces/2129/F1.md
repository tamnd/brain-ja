 ## 解決策
 ## 問題の理解

 1 から 1 までの数字の隠された順列を復元するように求められます。$n$限られた対話型クエリのセットを通じて。 各クエリは、選択されたインデックスのサブセットから最大の要素またはその位置を返します。課題は、厳密なクエリ制限を尊重しながら順列を再構築することです。 

簡易バージョンのキャップ$n$これは、クエリの合計を 30 個未満に抑えたい場合、単純にすべての位置を個別にクエリすることはできないことを意味します。 タイプ 3 およびタイプ 4 のクエリは配列の大きな部分をカバーできますが、そのようなクエリは 1 つだけ許可されます。 タイプ 1 およびタイプ 2 のクエリは最大 60 個の要素を返すため、次の場合には慎重なバッチ処理が必要です。$n$60を超えます。 

エッジケースは、順列の最初または最後に極大値がある場合に発生します。 たとえば、次の場合$p = [845, 1, 2, ..., 844]$、極端な値を無視した単純なクエリでは、最大の要素が見逃される可能性があります。 もう 1 つの微妙な点は、type-2 と type-4 は数値そのものではなく数値の位置を返すため、これら 2 つを混同すると不正確な再構築が生じる可能性があることです。 

## アプローチ

 ブルートフォース手法では、type-1 を使用して各位置を個別にクエリして、正確な値を取得します。 これが機能するのは、各クエリが単一の要素を返し、インデックスと値の間の完全なマッピングが得られるからです。 ただし、これは消費します$n$これは 30 クエリの制限を超えるため、実用的ではありません。 

重要な観察は、順列には一意の最大値があり、クエリはサブセット内の最大の要素を返すということです。 これにより、分割統治戦略が可能になります。 タイプ 3 クエリを使用して、配列全体の最大の要素を要求できます。これにより、即座に特定されます。$n$そしてその位置。 最大値の位置がわかったら、既知の最大値を除くサブセットを繰り返しクエリして、次に大きい要素を見つけることができます。 これにより、問題は要素を 1 つずつ、または上位の要素を返すクエリを使用してバッチで識別するようになり、クエリの数が 30 を超えないようになります。 

また、タイプ 2 クエリを利用して、要素を個別にクエリすることなく、要素の正確な位置を決定することもできます。 未知の位置を体系的に分割し、上位 k 個の結果を組み合わせることで、順列を効率的に再構成できます。

 ## アルゴリズムのチュートリアル

 1. 配列を初期化する`pos`サイズの$n+1$各数値の位置を保存します。 すべてのエントリは不明として開始されます。 
2. 1 から 1 までのインデックスのセット全体に対してタイプ 3 クエリを発行します。$n$。 これにより先頭が返されます$k = \min(300, n)$数字。 この応答の最大の数値は次のとおりです。$n$、インデックス内のその位置がわかります。`pos[n]`。 
3. の位置をマークします。$n$占領されているように。 この位置は、次に大きい要素に対する後続のクエリでは考慮されません。 
4. 位置が不明な番号もありますが、割り当てられていない残りのインデックスのサブセットを選択します。 このサブセットに対してタイプ 1 クエリを発行します。 クエリは最大 60 個の最大数値を返します。 まだ位置が割り当てられていない最大の数値を記録し、サブセット内のその位置を対応する値に割り当てます。`pos`。 
5. すべての位置が一致するまでステップ 4 を繰り返します。`pos`満たされています。 このループにより、クエリの制限を超えることなく、各クエリで検出される新しい位置の数が最大化されます。 
6. すべての数字を配置したら、変換します`pos`順列の中へ`p`各数字を決められた位置に配置します。 出力`! p_1 p_2 ... p_n`。 

機能する理由: アルゴリズムは、次の不変条件を維持します。`pos`常に既知の数値をその位置に正しくマッピングします。 未割り当てのサブセットに残っている最大の数値を常にクエリすることで、間違った位置に数値が割り当てられることはなく、top-k 保証によりサブセット内の最大値を見逃すことがなくなります。 各ステップでは、順列が完了するまで未知数の数が厳密に減少します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def query(qtype, indices):
    print(qtype, len(indices), *indices)
    sys.stdout.flush()
    return list(map(int, input().split()))

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        pos = [0] * (n + 1)
        unknown = set(range(1, n + 1))
        # find the largest number n and its position
        top_vals = query(3, list(range(1, n + 1)))
        largest = max(top_vals)
        idx = top_vals.index(largest)
        pos[largest] = idx + 1
        unknown.remove(idx + 1)

        remaining = n - 1
        while remaining > 0:
            batch = list(unknown)[:60]
            response = query(1, batch)
            for val in response[::-1]:
                if val not in pos or pos[val] == 0:
                    pos[val] = batch[response.index(val)]
                    unknown.remove(pos[val])
                    remaining -= 1

        # build permutation p
        p = [0] * n
        for i in range(1, n + 1):
            p[pos[i]-1] = i
        print('!', *p)
        sys.stdout.flush()

if __name__ == "__main__":
    solve()
```コードはアルゴリズムに従っています。最初にグローバル最大値を見つけ、次にサブセットを繰り返しクエリして、値の降順で残りの数値を検出します。 応答を逆にして、最大の数値が最初に割り当てられるようにし、不変条件を保持します。 のスライスを使用して、`unknown`これにより、タイプ 1 クエリの 60 要素制限を決して超えないようになります。 順列は、位置を値にマッピングすることによって再構築されます。

 ## 特殊なケース

 最大値が先頭にある順列の場合、`p = [n, 1, 2, ..., n-1]`、最初のタイプ 3 クエリは次のことを検出します。`n`正しく。 後続のタイプ 1 クエリでは、残りのインデックスから番号が割り当てられます。 各ステップは上位 60 位の制約を尊重し、ポジションを正しく埋めます。 出力は予想される順列と一致します。 

のために`n`ちょうど 60 の場合、すべての値を取得するには単一のタイプ 3 クエリで十分です。 アルゴリズムは、最初に正しい最大値を返し、次に残りの位置を単一のタイプ 1 クエリで埋めることによってこれを処理します。
