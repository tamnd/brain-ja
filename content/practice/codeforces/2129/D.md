 ## 解決策
 ## 問題の理解

 1 から 1 までの数字の順列が与えられます。$n$、これらの数字を順列順に 1 つずつ色付けする処理です。 各セルはスコア 0 で白から始まります。 セルが黒色になったとき$i$、将来自分自身に色を付けるすべてのセルは、最も近い黒の隣のセルのスコアに 1 を加えます。 セルのスコアは、その後の色付けで最も近い黒のセルになった回数をカウントします。 

この問題では、部分的に満たされたスコア配列が提供されます$s$、一部のスコアは既知ですが、その他は未指定 (-1 で示されます)。 私たちの仕事は、次の順列が何回あるかを数えることです。$1 \ldots n$指定されたスコア配列と一致するスコア配列を生成できます。 結果はモジュロ 998244353 である必要があります。 

主な制約は、$n \le 100$の合計で$n^2$に限定されたテストケース全体で$10^4$。 これは、およそ次の時間計算量までのアルゴリズムを許容できることを意味します。$O(n^3)$テストケースごとに。 どれでも$O(n!)$そうでない場合は、単純な置換の生成が遅すぎる可能性があります。 

重要な点は、同点の場合は、最初に最小距離に基づいて、次に最小インデックスに従って最も近い黒セルが選択されることです。 これは、特定のシーケンスが不可能であることを意味し、単純にスコアを恣意的に分配しようとすると、無効なカウントが生成されることがよくあります。 たとえば、シーケンスに次のようなものがある場合、$s = [0,0,0,0,4]$の場合、最後のスコアが、セルが最も近い黒の隣接セルになり得る最大可能回数を超えているため、これを達成することはできません。 

## アプローチ

 単純なブルートフォースアプローチでは、すべてのものが生成されてしまいます。$n!$順列を作成し、色付けプロセスをシミュレートして、結果のスコアが一致するかどうかを確認します。$s$。 これはプロセスを正確にモデル化するため、原則として正確性に関しては機能しますが、次の点については失敗します。$n = 100$なぜなら$100!$天文学的に大きいです。 たとえ$n=10$、ランタイムは実用的ではなくなります。 

重要な観察は、各ステップで、黒セルが残りの白セルを連続したブロックに分割していることです。 次の黒セルは、同じブロック内の最も近い黒セルのスコアのみを増加させることができます。 したがって、問題は、最も近い黒の近傍によって定義されるツリー構造内の親子関係を尊重する順列をカウントすることに帰着します。 

具体的には、セルをスコアで並べ替える場合、最高スコアのセルは他のセルから増分を受け取るため、後で色を付ける必要があります。 各スコアは基本的に、この最も近いブラック ツリーの「深さ」を定義します。 このツリーが定義されると、ブロック内の順序は最近傍関係を変更しないため、有効な順列の数は、連続する子の各ブロックのサイズの階乗の積になります。 

これにより、元の階乗爆発が、セルのブロックとそのスコアに関する動的計画問題に変換されます。これは、次の場合に実行可能です。$n \le 100$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n! * n^2) | O(n) | 遅すぎる |
 | DP / ツリーブロック | O(n^3) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取り、それらを繰り返します。 テスト ケースごとに、次の内容を読んでください。$n$そして配列$s$。 
2. すべての -1 エントリを置き換えます。$s$不明な部分にはプレースホルダーを付けます。 DP はそれらを柔軟な値として扱います。 
3. DP テーブルの初期化$dp[l][r]$インデックスからのセルのセグメントの有効な並べ替えの数を表します。$l$に$r$彼らのスコアと一致しています。 
4. 各セグメントについて、最大スコアを持つセルを特定します。 そのセルは、このセグメントの最後に色付けされる必要があります。 複数の最大値が存在する場合は、最も左の値を使用して、最も近い黒セルのタイブレーク ルールを満たすようにします。 
5. この最大セルの周囲でセグメントを左右の連続ブロックに分割します。 これらのブロックの DP を再帰的に計算します。 結果を乗算し、組み合わせ係数を使用して結合し、最大値を正しい位置に保ちながら左右のブロックをマージするすべての方法を考慮します。 
6. すべてのセグメントの結果をメモ化します。 テストケースの最終的な答えは次のとおりです。$dp[0][n-1]$モジュロ 998244353。 
7. すべてのテスト ケースを処理した後、結果を印刷します。 

機能する理由: 各ステップで、アルゴリズムはセグメント内で最大のスコアを持つセルが最後に配置されることを保証します。これは、そうすることでのみ正しい増分数を累積できるため、必須です。 このセルの周囲で分割すると、最も近い黒の関係が保存され、DP の結果を乗算することで、左右のサブセグメントのすべての有効なインターリーブが説明されます。 DP テーブルは、スコア制約に違反する順列がカウントされず、有効な順列がすべて 1 回だけカウントされることを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

# precompute factorials and inverse factorials
def prepare_factorials(n):
    fact = [1]*(n+1)
    ifact = [1]*(n+1)
    for i in range(1,n+1):
        fact[i] = fact[i-1]*i % MOD
    ifact[n] = pow(fact[n], MOD-2, MOD)
    for i in range(n-1, -1, -1):
        ifact[i] = ifact[i+1]*(i+1) % MOD
    return fact, ifact

def comb(n,k,fact,ifact):
    if k<0 or k>n: return 0
    return fact[n]*ifact[k]%MOD*ifact[n-k]%MOD

def solve_case(n, s):
    fact, ifact = prepare_factorials(n)
    # replace unknowns with -1
    a = s[:]
    dp = [[0]*n for _ in range(n)]
    
    for length in range(1,n+1):
        for l in range(n-length+1):
            r = l+length-1
            # find maximum score in segment
            mx = -1
            mx_idx = -1
            for i in range(l,r+1):
                if a[i] > mx:
                    mx = a[i]
                    mx_idx = i
            # check if impossible
            if mx > length-1:
                dp[l][r] = 0
                continue
            left = dp[l][mx_idx-1] if mx_idx > l else 1
            right = dp[mx_idx+1][r] if mx_idx < r else 1
            dp[l][r] = left * right % MOD
            dp[l][r] = dp[l][r] * comb(length-1, mx_idx-l, fact, ifact) % MOD
    return dp[0][n-1]

t = int(input())
for _ in range(t):
    n = int(input())
    s = list(map(int,input().split()))
    print(solve_case(n,s))
```階乗事前計算により、左右のサブセグメントをマージするときに効率的な組み合わせ計算が可能になります。 セグメント境界によってインデックス付けされた DP テーブルを使用します。 各セグメントについて、左端の最大スコア セルがピボットとして選択され、有効な順列の数が再帰的に計算されます。 組み合わせ要因により、このピボットの周囲に残りのセルが分散されます。
