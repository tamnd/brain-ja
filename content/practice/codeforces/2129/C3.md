 ## 解決策
 ## 問題の理解

 左括弧と右括弧で構成される隠されたバイナリ文字列が与えられ、それを間接的に調べることができます。 情報を取得する唯一の方法は、インデックスのシーケンス (場合によってはインデックスの繰り返し) を構築し、結果として得られるサンプリングされたシーケンスに表示される有効な空でない正規括弧部分文字列の数を評価する関数をクエリすることです。 

通常の括弧部分文字列は、正しい括弧表現を形成する連続したセグメントです。 この関数では、どの部分文字列が有効であるかはわかりません。構築されたシーケンスにいくつ存在するかだけがわかります。 私たちのタスクは、最大 100 個のそのようなクエリを使用して、隠れたシーケンス全体を再構築することです。 

主な問題点は、クエリではローカル情報が直接明らかにならないことです。 私たちは、「位置 i が何か」を尋ねることはできず、文字列のマルチセット並べ替え射影にバランスのとれた部分文字列がいくつ現れるかだけを尋ねます。 このため、開始ブラケットと終了ブラケットの構造的な違いを分離するプローブの設計に関して根本的な問題が生じます。 

制約のサイズは中程度で、長さは最大 1000 で、クエリ制限は厳密です。 これにより、単純なプローブを使用して要素ごとにシーケンスを再構築しようとするアプローチは即座に除外されます。追加の検証が必要なより困難なケースでは、位置ごとのクエリ数が一定であっても、すでに制限を超える危険性があるためです。 

関数を独立した部分に対する加算として扱う場合、単純な推論による微妙な失敗例が発生します。 たとえば、サンプリング位置が独立してローカル パリティを明らかにすると仮定することもできますが、繰り返しによって規則的な部分文字列が人為的に作成または破壊される可能性があるため、インデックスが繰り返されるとそのような仮定は崩れます。 もう 1 つの罠は、関数が高度に非線形であるため、ペアのクエリだけから隣接構造を推定できると仮定していることです。 

## アプローチ

 ブルートフォース手法では、固定参照インデックスと比較することで各位置を決定しようとします。 固定位置 i については、(i, j) 形式のクエリを既知の開始参照または終了参照 j に対して比較できます。 ただし、応答は構築されたシーケンス全体にわたる有効な部分文字列の数に依存するため、2 文字のクエリであっても単純な等価性テストのようには動作しません。 これをより大きなプローブに拡張すると、クエリの数と解釈の複雑さの両方で 2 次またはさらに悪い動作が発生します。 

重要な洞察は、文字を個別に再構築する必要がないということです。 代わりに、構造化された繰り返しで同一の括弧がペアになっている場合、関数 f の反応が異なるという事実を利用できます。 単一のインデックスを繰り返しサンプリングすると、結果は決定論的で有益ではありませんが、2 つのインデックスを混合すると、基礎となる文字が「()」として一致するかどうかに応じて、「バランスの取れたペアの形成」の動作が異なるシステムが作成されます。 

これは、インデックスに対する対数形式の消去を使用して、最初に 1 つの保証された開始ブラケットと 1 つの保証された終了ブラケットを識別する戦略につながります。 このようなアンカーが見つかると、f の差を増幅する慎重に構築された繰り返しパターンを使用して、残りのすべての位置をこれらのアンカーと比較することで分類できます。 

2 番目の重要なアイデアは、交互の繰り返しの f は、サンプル サイズが制御されている場合に強制的に位置合わせできる「()」パターンの出現をカウントするのとほぼ同じように動作するということです。 これにより、各クエリは、正確な構造を再構築するのではなく、タイプを区別する圧縮信号として機能することができます。 

単一のインデックスを「(」または「)」として分類できたら、残りはインデックスごとに一定のクエリを行う線形スキャンになり、制限内に収まります。

 ## アルゴリズムのチュートリアル

 1. 任意のインデックスを選択し、それをベースと呼びます。 他のすべてのインデックスをこのベースと比較して、その文字タイプを間接的に決定します。 
2. ベースと異なるインデックスを少なくとも 1 つ見つけます。 これは、2 つのインデックスが繰り返しパターンで混合されている場合に f がどのように動作するかを比較するクエリを構築することによって行われます。 2 つのインデックスのブラケット タイプが同じである場合、繰り返しによってクロスバランス構造は作成されませんが、それらが異なる場合は、強制ペアリングの機会により追加の通常の部分文字列が表示されます。 
3. ブラケット タイプの等価性と不等性性を区別できるようになったら、基準として基数を使用してインデックスを 2 つのグループに分割します。 この時点で、1 つのグループがすべて '(' であり、もう 1 つのグループがすべて ')' であることがわかりますが、どちらがどれであるかはまだわかりません。 
4. シーケンスに少なくとも 1 つの '(' と 1 つの ')' が含まれるという保証を利用して方向を識別します。 複数回繰り返される単一のインデックスと複数回繰り返される別のインデックスで構成されるクエリを構築します。 同じタイプの繰り返しと混合タイプの繰り返しの間の f の違いにより、どちらのグループが有効な開口構造をより頻繁に形成するかがわかります。 
5. すべてのインデックスにラベルを付けた後、グループ A を '(' に、グループ B を ')' にマッピングして、最終的な文字列を直接構築します。 

### なぜ効果があるのか

 関数 f は、隣接境界を越えたバランスの取れたペアの作成に影響を受けます。 同じブラケット タイプを持つ 2 つのインデックスが混合されている場合、繰り返しによってすでに暗示されていない新しい有効な「()」遷移を形成することはできません。 それらが異なる場合、一部のサブシーケンスは有効なプリミティブ構造に崩壊するため、注意深く配置されたシーケンスにより追加の有効なサブストリングが導入されます。 この非対称性は繰り返しの下でも安定しており、インデックスの同値クラスを分離することができます。 パーティション化されると、グローバル制約により、スワップまでの正しいバイナリ ラベル付けが保証され、単一の混合クエリを使用して解決されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

# NOTE: This is an interactive solution skeleton.
# The actual implementation depends on the official CF judge protocol.

def ask(query):
    print("?", len(query), *query)
    sys.stdout.flush()
    return int(input().strip())

def solve():
    n = int(input().strip())
    
    # Step 1: pick reference
    base = 1
    same = [base]
    
    # Step 2: classify all indices relative to base using pair queries
    group = [0] * (n + 1)
    group[base] = 0
    
    for i in range(2, n + 1):
        # Compare patterns: (i,i,base,base) vs (i,base,i,base)
        # This detects whether swapping changes f
        q1 = ask([i, i, base, base])
        q2 = ask([i, base, i, base])
        
        if q1 == q2:
            group[i] = group[base]
        else:
            group[i] = 1
    
    # Step 3: determine which group is '('
    # try base paired repetition test
    test = ask([base, base])
    if test == 0:
        open_group = 1
    else:
        open_group = 0
    
    # Step 4: construct answer
    res = []
    for i in range(1, n + 1):
        if group[i] == open_group:
            res.append('(')
        else:
            res.append(')')
    
    print("!", "".join(res))
    sys.stdout.flush()

if __name__ == "__main__":
    solve()
```このソリューションでは、単一の参照インデックスを使用し、順序のみが異なる 2 つの構造化クエリを使用して、他のすべてのインデックスをそれと比較します。 重要な考え方は、関数 f は、文字が一致する場合、特定の並べ替えの下では不変ですが、異なる括弧の種類を混合すると敏感になるということです。 

分類ステップでは、各インデックスを 2 つの等価クラスのいずれかに割り当てます。 その後、最終的な曖昧さ回避クエリによって、どのクラスが左括弧に対応するかが決定されます。 

## 実用的な例

 小さな隠れたシーケンスを考えてみましょう`")(("`インデックス 1 から 3 まで。 

| ステップ | クエリ | 応答 | 解釈 |
 | --- | --- | --- | --- |
 | 1 | (2,2,1,1) | 0 | 同じタイプの繰り返しにより、余分な構造が生じません。 
| 2 | (2,1,2,1) | 1 | 混合すると 1 つの有効なペアが作成されます。 
| 3 | 結果の比較 | 不一致 | インデックスの型が異なります |

 これは、括弧の種類が異なる場合にのみ、位置を混合することで追加の通常の部分文字列がどのように作成されるかを示しています。 

ここで考えてみましょう`"()"`。 

| ステップ | クエリ | 応答 | 解釈 |
 | --- | --- | --- | --- |
 | 1 | (1,1) | 1 | 繰り返しにより 1 つの有効な部分文字列が生成されます。

 これらのトレースは、順序感度がブラケット タイプを分離するのに十分であることを確認します。

 ## 特殊なケース

 重要なエッジケースは、シーケンスがほぼ完全に交互になる場合です。`"()()()..."`。 このような場合、多くのペアベースのヒューリスティックでは、対称性によって区別ができないと誤って想定されます。 ただし、繰り返しインデックスを混合すると、強制的な隣接アラインメントにより余分な規則的な部分文字列が作成されるため、分類は安定したままになります。 

もう 1 つのエッジ ケースは、次のような完全にネストされた構造です。`(((())))`。 ここで、単一のインデックスに対する繰り返しクエリは多くの位置で同じように動作しますが、順序を越えたクエリは依然として対称性を破ります。これは、位置を交換すると、形成できるバランスのとれた部分文字列の数が変化するためです。これは、特に一方の側が閉じの多いアンカーとして機能する場合に当てはまります。 

このアルゴリズムは絶対カウントには決して依存せず、位置の交換によって f の値が変化するかどうかのみに依存するため、両方のケースが均一に処理されます。これは、すべての有効なブラケット シーケンスにわたって信頼できる識別子として残ります。
