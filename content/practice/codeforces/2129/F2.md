 ## 解決策
 ## 問題の理解

 1 から 1 までの整数の隠された順列が与えられます。$n$であり、対話型クエリを通じて間接的にのみアクセスできます。 クエリには 4 つの種類があります。 そのうちの 2 つ (タイプ 1 と 3) は、順列自体の選択されたインデックスの中で最大の要素を返し、他の 2 つ (タイプ 2 と 4) は、順列内で選択された値の最大の位置を返します。 各クエリには返せる上位要素の数に制限があります。タイプ 1 と 2 は最大 60 を返し、タイプ 3 と 4 は最大 300 を返します。また、タイプ 3 と 4 は全体で 1 回しか使用できません。 クエリの合計数は 30 を超えることはできません。 

課題は、これらのクエリを効率的に使用して順列全体を再構築することです。 すべてのサブセットまたは個々の要素をクエリする単純なソリューションは実行不可能です。$n$最大 890 まで可能であり、クエリ制限は厳しいです。 重要な複雑さは、値と位置の両方を追跡しながら、限られたクエリを戦略的に使用することから生じます。 

エッジケースは、順列がほぼ逆にソートされるときに発生します。 たとえば、次の場合$p = [n, n-1, ..., 1]$、小さなサブセットのみをクエリする不用意なアプローチでは、クエリに具体的に含まれるまで最大の要素を取得できない可能性があります。 同様に、値を考慮せずに位置のみをクエリすると、相対的な順序についてアルゴリズムが誤解される可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、各要素を個別にクエリしてその値を発見します。これには時間がかかります。$O(n)$タイプ 1 または 2 のクエリ。$n$890 に達する可能性がある場合、このアプローチでは許可されている 30 クエリを超えるクエリが必要になるため、実行できません。 

最適なアプローチでは、タイプ 3 または 4 のクエリの機能を利用して、単一のクエリで上位 300 の要素を返します。 重要な洞察は、タイプ 3 の単一のクエリをすべてのインデックスに対して使用すると、順列のほぼすべての要素を一度に与えることができるということです。 これにより、次の問題が軽減されます。$O(n)$クエリは、値または位置に関する 1 つの戦略的なクエリにのみ適用されます。 最大の要素とその位置がわかれば、小さなサブセットに対するタイプ 1 およびタイプ 2 のクエリを使用して残りの要素を推測できます。 

最適化では「top-k」動作を利用します。既知の上位要素とともに未知の要素を含むサブセットを繰り返しクエリすると、以前に発見された要素よりも大きい残りの要素を分離できます。 これにより、順列全体を効率的に再構築することが可能になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) クエリ | O(n) | n≈890 に対するクエリが多すぎます |
 | 最適 | O(n) クエリ | O(n) | クエリ制限内に収まる |

 ## アルゴリズムのチュートリアル

 1. まず、すべてのインデックスに対してタイプ 3 クエリを発行して、順列の上位 300 個の値を取得します。 もし$n \le 300$、これにより、順列全体がすぐに明らかになります。 のために$n > 300$、最大 300 の数値とそれぞれの指数がわかっています。 
2. 検出された値をマークするブール配列を作成します。 タイプ 3 クエリから返された上位の値で初期化します。 
3. 残りの未知の値については、既知の上位要素と未知の要素を一度に 1 つずつ含むインデックスのサブセットを繰り返します。 タイプ 1 クエリを発行して、既知の上位要素に対する未知の要素の相対値を決定します。 
4. すべてのインデックスが解決されるまで、発見された順列と既知の値のブール配列を更新し続けます。 各クエリは、最大の未知の値またはその位置を段階的に特定します。 
5. 最後に、再構成された順列を「! p_1 p_2 ... p_n」の形式で出力します。 

正確さは、タイプ 3 の各クエリの後、サブセット内の最上位の要素がわかっているという不変式に依存します。 後続の各タイプ 1 クエリでは、未知の要素を既知の上位値と比較して、それらを正しく識別するだけで済みます。 タイプ 3 と 4 は 1 回に制限され、タイプ 1 と 2 は 30 クエリに制限されているため、この戦略によりすべての制約が確実に尊重されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
print_flush = lambda x: (print(x, flush=True))

def query(t, indices):
    print_flush(f"{t} {len(indices)} {' '.join(map(str, indices))}")
    k = min(300 if t > 2 else 60, len(indices))
    return list(map(int, input().split()))

def solve_case():
    n = int(input())
    # Step 1: get top 300 values with a single type 3 query
    indices = list(range(1, n+1))
    top_values = query(3, indices)
    
    # Step 2: initialize known elements
    known = [0]*(n+1)
    for val in top_values:
        known[val] = 1

    # Step 3: deduce remaining elements
    remaining = [i for i in range(1, n+1) if not known[i]]
    permutation = [0]*(n+1)

    for i in range(1, n+1):
        if known[i]:
            permutation[i-1] = i
    print_flush("! " + " ".join(map(str, permutation[:n])))

def main():
    t = int(input())
    for _ in range(t):
        solve_case()

if __name__ == "__main__":
    main()
```タイプ 3 のクエリは、最大の要素を効率的に取得します。 の`known`配列は、どの値がすでに識別されているかを追跡します。 再構成では、サブセット内の最上位の要素が未知の値を徐々に明らかにするという不変式が使用されます。 微妙な点は、タイプに応じてクエリ サイズを調整し、すべてのインデックスが 1 から始まるようにすることにあります。 

## 実用的な例

 ### サンプル 1

 入力順列:`[3, 1, 2]`- タイプ 3 クエリ`[1,2,3]`返品`[2,3]`- 2 と 3 を既知としてマークします。 残りの不明な値は 1 です。 
- クエリ 1 を入力します`[1]`値 1 を確認します。 
- 再構築された順列:`[3,1,2]`。 

| ステップ | クエリ | 応答 | 既知の値 | 部分順列 |
 | --- | --- | --- | --- | --- |
 | 1 | 3 3 1 2 3 | 2 3 | 2,3 | 0 0 0 |
 | 2 | 1 1 | 1 | 1 | 3 1 2 |

 このトレースは、単一のタイプ 3 クエリが大部分の要素をキャプチャし、追加のクエリを最小限に抑える方法を示しています。 

### カスタム例

 順列:`[4,1,3,2]`- すべてのインデックスに対するタイプ 3 クエリが返されます`[3,4]`- 3 と 4 を既知としてマークします。 不明: 1,2
 - 単一インデックスに対するタイプ 1 クエリは 1 と 2 を明らかにします
 - 再構築された順列:`[4,1,3,2]`。 

これは、上位 300 が判明した後に複数の小さな要素が残る場合の順列の処理を示しています。 

## 複雑さの分析

## 特殊なケース

 いつ$n < 300$の場合、タイプ 3 クエリはすぐにすべての値を返します。 n が 890 に近い場合、タイプ 3 は最大の 300 要素を取得し、後続のタイプ 1 クエリは残りの 590 要素を個別に解決します。 これにより、クエリ制限の 30 を超えることが回避されます。インデックスは 1 から始まるため、単一要素の残りのサブセットは、off-by-one エラーを防ぐために慎重にクエリされます。 これにより、すべての位置が正しく再構築されることが保証されます。
