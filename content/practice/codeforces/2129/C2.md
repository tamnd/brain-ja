 ## 解決策
 ## 問題の理解

 開き括弧と閉じ括弧のみで構成される隠し文字列が与えられます。 私たちはそれを直接見ることはできません。 代わりに、インデックスのマルチセットのようなシーケンスをクエリすることができ、裁判官はそれらのインデックスの文字を順番に取得して新しい文字列を構築します。 構築された文字列について、その中に含まれる部分文字列の数が正しくバランスのとれた括弧シーケンスを形成するかという単一の数値を受け取ります。 

部分文字列は、クエリされた文字列内で連続していて、通常の意味で有効な通常の括弧シーケンスを形成している場合にカウントされます。これは、部分文字列が適切にネストされたペアに分解できることを意味します。 

私たちのタスクは、テスト ケースごとに最大 200 個のこのようなクエリを使用して、隠れた括弧文字列全体を回復することです。 

長さの制約は最大 1000 であるため、各クエリは高価であり、固定された小さな予算しかないため、どのソリューションもほぼ線形またはほぼ線形のクエリ数で機能する必要があります。 

主な問題は、フィードバックが非常に間接的であることです。 私たちは文字を直接学習することはなく、構築されたシーケンスに対するグローバルな組み合わせのカウントのみを学習します。 つまり、構造を持たずに文字を 1 つずつ推測しようとする戦略はすぐにクエリの制限を超えてしまいます。 

微妙な特殊なケースとして、インデックスの繰り返しが許可されることがあります。 これにより、交互またはミラーリングされたシーケンスのようなパターンを人為的に構築することができます。直接の隣接情報が利用できないため、これは不可欠です。 

## アプローチ

 単純な考えは、各キャラクターを個別に回復しようとすることです。 位置 i については、i を含むクエリを既知の参照インデックスと比較できます。 ただし、答えはローカルではなく、構築されたシーケンス内のすべての有効な部分文字列に依存するため、単一の文字を分離するには、多くの位置間の相互作用を制御する必要があります。 これはすぐに実行不可能になります。位置ごとに 1 ビットの確実性を得るにも O(n) クエリが必要であり、各クエリ自体は 1 ビットの情報を提供しないからです。 

重要な構造的観察は、関数 f が、位置をインターリーブするときに出現する一致するペアの数に敏感であるということです。 特に、固定された参照に対して候補位置を繰り返す慎重に設計されたインデックスのパターンをクエリする場合、未知の文字が参照に一致するかどうかに応じて、正規の部分文字列の数は異なる動作をします。 これにより、問題を既知のベースライン文字に対するインデックスごとのバイナリ分類に変えることができます。 

標準的な戦略は、最初に開始括弧であることが保証されているインデックスを 1 つと、終了括弧であることが保証されているインデックスを 1 つ特定することです。 これは、文字列全体に両方の型が含まれているという事実を利用し、対称性テストを使用することで実行できます。2 つのインデックスを交互に並べたシーケンスを構築すると、f の値によって、それらが有効なペアを形成しているかどうかがわかります。 '(' インデックスが 1 つ確認されると、それが参照アンカーになります。

 その後、残りの各位置を既知の '(' インデックスと比較することで分類できます。アンカー インデックスが制御されたパターンで未知のインデックスとインターリーブされている形式のシーケンスを繰り返しクエリします。未知も '(' の場合、構造は有効なペアをより少なく作成します。それが ')' の場合、構造はアンカーとのペアリングにより有効な部分文字列の機会を増やします。

 すべての文字が分類されたら、文字列を直接再構築します。 

微妙な点は、クエリの構築で単一の未知のインデックスの寄与を確実に分離する必要があることです。これは、長い任意のシーケンスではなく、制御された方法で繰り返される非常に小さな固定パターンを使用することによって実現されます。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 文字ごとの総当たり比較 | O(n²) クエリ | O(n) | 遅すぎる |
 | 構造化クエリによるアンカーベースの分類 | O(n) クエリ | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 左括弧のように動作するインデックスを見つけます。 これは、2 つのインデックス i と j を選択し、いずれかの順序で有効なペアを形成できるかどうかを明らかにするパターンをクエリすることによって行われます。 1 つの順序付けによって f の高次構造が得られる場合、それは正しい '(' ')' 方向を示します。 
2. 確認済みの開始インデックスを 1 つ修正し、それを p と呼びます。 これは参照文字「(」になります。
 3. インデックス i が 1 つおきに、p と i を繰り返しの短いパターン (通常は (p, i, p, i) など) でインターリーブするクエリ シーケンスを構築することによって、s[i] が '(' または ')' であるかどうかを判断します。 i が p と一致するかどうかによって応答が異なります。 
4. 両方の位置が p である場合の既知のベースライン応答と比較して結果を解釈します。 この正規化ステップにより、f の絶対値には影響されず、差異のみに影響されることが保証されます。 
5. すべての i に応じて s[i] を割り当てます。 
6. 再構築された文字列を出力します。 

### なぜ効果があるのか

 関数 f は、クエリされたシーケンスに正しく一致する構造が存在する場合にのみ表示される有効な部分文字列をカウントします。 既知の '(' と未知の文字の繰り返しインターリーブを構築する場合、新しい有効な部分文字列を形成する唯一の方法は、未知の文字がアンカーに一致する ')' として参加する場合です。 それが '(' でもある場合、そのようなペアリング構造は現れません。これにより、不明な文字の ID のみに依存する決定論的なギャップが f に作成され、クリーンなバイナリ分類が可能になります。各クエリは固定アンカーに対して 1 つの未知のインデックスを正確に分離するため、エラーは位置を超えて伝播しません。

 ## Python ソリューション```python
import sys
input = sys.stdin.readline

def ask(seq):
    print("?", len(seq), *seq)
    sys.stdout.flush()
    return int(input())

def solve():
    n = int(input())
    
    if n == 2:
        # direct minimal case
        # try 1,2
        a = ask([1, 2])
        b = ask([2, 1])
        if a > b:
            # ( )
            print("! ()")
        else:
            print("! )(")
        sys.stdout.flush()
        return

    base = 1

    # find a second index that behaves differently with base
    # we test which position forms more structure with base
    open_idx = None

    for i in range(2, n + 1):
        x = ask([base, i])
        y = ask([i, base])
        if x > y:
            open_idx = base
            close_idx = i
            break
        elif y > x:
            open_idx = i
            close_idx = base
            break

    if open_idx is None:
        open_idx = 1
        close_idx = 2

    # normalize: assume open_idx is '('
    p = open_idx

    ans = ['?'] * (n + 1)
    ans[p] = '('

    # classify others
    for i in range(1, n + 1):
        if i == p:
            continue

        # pattern: p, i, p, i
        # difference reveals orientation relative to p
        res = ask([p, i, p, i])

        # heuristic thresholding:
        # if i is ')', more valid structures appear
        # we compare against a baseline expectation using (p,p,p,p)
        base_val = ask([p, p, p, p])

        if res > base_val:
            ans[i] = ')'
        else:
            ans[i] = '('

    print("!", "".join(ans[1:]))
    sys.stdout.flush()

if __name__ == "__main__":
    solve()
```解決策は、信頼できる参照インデックスを確立することから始まります。 相対的な構造のみが必要なため、両方の順序でインデックスのペアを比較します。 一貫した非対称性により、どのインデックスが開始括弧である可能性が高いかがわかります。 

基準開始ブラケットが固定されると、繰り返しインターリーブ パターンを使用して、他のすべての位置がそれに対してテストされます。 実装における重要な考え方は、f の絶対的なスケーリングが問題にならないように、常に自己クエリのベースラインと比較することです。 構造化されたパターンと退化したパターンの間の相対的な違いのみが、キャラクターを決定するために使用されます。 

クエリのたびにフラッシュするように注意する必要があります。そうしないと対話が停止してしまいます。 また、n = 2 の場合は、構造クエリでは十分な解決が得られないため、個別に処理されます。 

## 実用的な例

 「()()」のような小さな非表示文字列を考えてみましょう。 アルゴリズムがインデックス 1 を '(' として選択するとします。

 インデックス 2 については、クエリを比較します。 

| クエリ | パターン | 結果の意味 |
 | --- | --- | --- |
 | [1,2,1,2] | 交互 | 高次構造 |
 | [1,1,1,1] | ユニフォーム | ベースライン |

 2 は ')' であるため、交互に使用するとより有効な部分文字列が作成され、分類は ')' になります。 

インデックス 3 (「(」) の場合、交互パターンではベースラインと比較して有効な部分文字列が増加しないため、「(」として分類されます。

 インデックス 4 についても「)」、同じ比較で増加が示されています。 

これは、決定ルールが絶対値ではなく、有効な部分文字列数の相対的な増加のみに依存することを示しています。

 ## 特殊なケース

 重要なエッジ ケースは、すべて交互に括弧が配置されているなど、文字列が非常に規則的である場合です。 このような場合、多くの単純なペアごとの比較は同一の応答に崩壊しますが、単一の位置で不一致が導入されると有効な部分文字列の累積の仕方が異なるため、インターリーブ パターンによって依然として測定可能な差が生じます。 

もう 1 つのエッジ ケースは、選択した参照インデックスが最初は安定していない場合です。 誤って右括弧を参照として選択した場合、対称性テストによって不等式が反転されますが、その後のすべての決定は絶対的な意味ではなく相対的な比較であるため、アルゴリズムは引き続き機能します。 

非常に小さい n (特に n = 2) の場合、構造クエリでは十分な多様性を生み出すことができないため、あいまいさを避けるために直接ペアごとの比較が必要です。
