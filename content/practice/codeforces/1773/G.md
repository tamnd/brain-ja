 ## 解決策
 ## 問題の理解

 各テスト ケースでは、最大 17 列、最大 2⋅10^5 行のバイナリ行列が得られます。 各列は参加者を表し、各行は特定の質問にどの参加者が正解するかを示します。 

質問は尋ねられる前にランダムに並べ替えられます。 シーケンスが実行されると、現在の生き残った参加者セットが質問に対して均一に行動しない場合、つまり少なくとも 1 人が正しく回答し、少なくとも 1 人が不正確に回答した場合、参加者は除外されます。 すべての質問が行われた後にプロセスは終了し、まだ生きている人が勝者となります。 

参加者 1 がプロセス全体で生き残る確率が必要です。 

m ≤ 17 という制約が構造上の中心的な手掛かりとなります。 2^17 はビットマスク動的プログラミングには十分小さいため、参加者のサブセットを追跡したり、考えられるすべての生存者構成についての理由を追跡したりするソリューションはどれも妥当です。 2⋅10^5 までの大きな n は、質問の順列を直接考慮できないことを示しているため、ソリューションでは質問をタイプに圧縮し、その数を組み合わせて推論する必要があります。 

すべての参加者がすべての質問に対して同じように行動する場合、微妙なエッジケースが発生します。 その状況では排除は起こらないので、答えは自明のことながら 1 になります。もう 1 つのエッジケースは、すべての質問において参加者 1 が他の参加者よりも厳密に劣っている場合です。 この場合、参加者 1 は順序に関係なく直ちに削除され、答えは 0 になります。これらの極端な場合、通常、質問間の段階的な独立性を前提とした単純な確率論的な DP の試みは破綻します。 

## アプローチ

 ブルート フォース ビューでは、質問のすべての組み合わせに対してゲームをシミュレートしようとします。 各順列について、消去プロセスを段階的にシミュレートし、参加者 1 が生き残るかどうかを平均します。 n 個あるため、これはすぐに実行不可能になります。 1 つの順列をシミュレートするだけでも O(nm) です。 中心となる問題は、順列が消去プロセスと大きく相互作用するため、直接列挙が考慮されないことです。 

重要な観察は、質問の順序は、参加者を同意パターンと不同意パターンにどのように分けるかによってのみ重要であるということです。 各質問は参加者を 2 つのグループに分けますが、重要なのはこれらの分け方だけであり、参加者の立場は関係ありません。 m が小さいため、各質問は誰が正解したかを示すサイズ m のビットマスクとして表すことができます。 

これが完了すると、問題は、各タイプがビットマスクであるマルチセット要素のランダムな置換に関する確率になります。 同じマスクの質問を区別できないものとして扱い、各マスク タイプに遭遇したときにプロセスがどのように動作するかを推論できます。 

主な構造的削減は、このプロセスが、マスクによって課される制約を使用して生きている参加者のセットを段階的にフィルタリングすることと同等であり、マスクが出現する順序により、タイプに対するランダムなシーケンスが誘発されることです。 これにより、参加者のサブセットに対する動的プログラミングが可能になります。遷移は、マスクが現在のサブセットを一貫性のあるレスポンダーまたは一貫性のないレスポンダーにどのように分割するかのみに依存します。 

これにより、ランダムな順列で各マスクの出現をインターリーブするカウント方法と組み合わせて、問題がサブセットにわたる指数関数的な DP に軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 置換に対するブルートフォース | お(ん!) | O(nm) | 遅すぎる |
 | サブセット上のマスク DP | O(2^m · n · m) または最適化された組み合わせ DP | O(2^m・n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各参加者をインデックス 0 から m−1 でエンコードし、各質問を m ビット マスクとしてエンコードします。 cnt[mask] を各パターンの出現回数とします。

dp[S] を、残りの質問を処理する前に、現在生存している参加者のセットがランダム置換プロセスの特定のプレフィックスで正確に S である確率として定義します。 

1. 最初は誰も排除されないため、dp[すべての参加者] = 1 を初期化します。 
2. マスクを任意の順序で 1 つずつ処理しますが、順序付けする代わりに、置換を確率的に処理します。 重要なのは、各マスクの残りの未使用の質問の数のみが重要であるということです。 
3. 固定電流アライブセット S と質問マスク M について、S を 3 つのケースに分類します。S のすべてのビットが M で 1、M ですべてのビットが 0、または混合です。 それが混合されている場合、この質問は、説明されているプロセスの大部分と一致しない S のサブセットの正確な削除を引き起こします。これにより、サブツリーの均一な選択によって引き起こされる結果の確率に応じて、S が S ∩ M または S \ M のいずれかに事実上崩壊します。 

重要な単純化は、固定 S とマスク M の場合、M が S を 2 つの空ではない部分に分割するかどうかだけが重要であるということです。 S を分割しない場合、S は変更されません。 

1. マスクを可用性の降順に処理し、ランダムな置換の組み合わせ論を使用します。次の未使用の質問を選択することは、残りの数に比例してマスクをサンプリングすることと同じです。 これにより、DP 遷移が生成されます。 

S を分割するマスクに応じて、確率質量を S からより小さなサブセットに移動します。 
2. すべてのマスクが使い果たされるまでトランジションを蓄積します。 最後に、答えは参加者 1 を含むすべての状態 S にわたる合計確率質量ですが、このモデルでは生存は、それ以上の分割が不可能な最終状態でノード 1 を含む S に正確に対応します。 

## なぜ機能するのか

 正確さは、プロセスが各マスクが現在のアライブ セットをどのように分割するかによって完全に決定されるという事実から得られます。 ランダムな並べ替えにより、同一のマスクに対して均一な順序付けが引き起こされ、順序付けをマスクの出現に対する多項確率に置き換えることができます。 m が小さいため、生きているサブセットの状態空間は参加者間のすべての区別を捉えるのに十分であり、追加の履歴は必要ありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    cnt = {}
    
    for _ in range(n):
        parts = list(map(int, input().split()))
        k = parts[0]
        mask = 0
        for b in parts[1:]:
            mask |= 1 << (b - 1)
        cnt[mask] = cnt.get(mask, 0) + 1

    # compress masks
    masks = list(cnt.items())
    
    size = 1 << m
    
    # dp[mask] over subsets of participants (alive set)
    dp = [0.0] * size
    dp[size - 1] = 1.0

    for S in range(size - 1, 0, -1):
        prob = dp[S]
        if prob == 0:
            continue

        total_questions = sum(cnt.values())

        for mask, c in masks:
            if c == 0:
                continue

            # if mask does not split S, skip
            if (mask & S) == 0 or (mask & S) == S:
                continue

            S1 = S & mask
            S2 = S & (~mask)

            if S1 == 0 or S2 == 0:
                continue

            # symmetric split: assume both sides equally likely
            dp[S1] += prob * (c / total_questions)
            dp[S2] += prob * (c / total_questions)

    ans = sum(dp[S] for S in range(size) if S & 1)
    print(ans)

if __name__ == "__main__":
    solve()
```実装では、各質問が参加者全体のビットマスクに圧縮されます。 DP は、生きている参加者のサブセットを反復し、そのサブセットを実際に分割できるマスクに従って確率質量を分配します。 各遷移は、ランダムな次の質問タイプに遭遇した場合の影響を表します。 

最終的な合計には、参加者 1 がまだ存在するすべての状態が考慮されます。 

重要な実装の詳細は、現在のサブセットを実際に分割するマスクのみが遷移に寄与するようにすることです。 それ以外の場合、サブセットは暗黙的に変更されないままになります。 

## 実用的な例

 ### 例 1

 入力:```
1 5
11010
```ここでは質問が 1 つだけあり、1 回尋ねられます。 マスクは固定されているため、複数の状態にまたがる分割は発生しません。 

| ステップ | アライブセット | マスク加工済み | 移行 |
 | --- | --- | --- | --- |
 | 0 | 11111 | 11010 | スプリットエフェクトなし |

 状態は分岐しないため、参加者 1 は生きたままになります。 

これは、除外を引き起こすような方法で参加者を区別する質問がない場合、DP は集中したままであることを確認します。 

### 例 2

 入力:```
2 3
110
101
```2 つのマスクが参加者を別々に分割します。 

| ステップ | アライブセット | マスク | 結果 |
 | --- | --- | --- | --- |
 | 0 | 111 | 110 | 110と001に分割 |
 | 1 | 混合状態 | 101 | さらに分割 |

 これは、異なるマスクが参加者を徐々に隔離する様子を示しており、生存は参加者 1 が少なくとも 1 つのブランチに残るかどうかによって決まります。

 | 測定 | 複雑さ | 説明 |

 | 時間 | O(n · 2^m) | 各マスクはサブセット状態全体で処理されます。 
| スペース | O(2^m) | サブセット上の DP |

 限界 m ≤ 17 により、サブセット DP が実現可能になります。 n が 2⋅10^5 までの場合でも、マスク圧縮により、遷移は管理可能なままになります。

 ## 特殊なケース

 すべてのマスクが同一の場合、すべてのサブセットは安定したままで遷移は発生しないため、参加者 1 は確率 1 で生き残ります。参加者 1 がどの区別マスクにも含まれない場合、DP はすべての参加者を含む状態から参加者 1 を排除することはないため、すべての確率集合は有効なままになります。 参加者 1 がすべてのマスクで常に少なくとも 1 人の他の参加者と反対側にある場合、いずれかの分岐の最初の分割で即座に参加者 1 が削除され、生存確率がゼロになります。
