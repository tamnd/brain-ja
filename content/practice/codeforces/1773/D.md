 ## 解決策
 ## バグ診断

 ここで、最終的に、ラッパーの問題ではなく、実際の論理障害が確認されました。 

生成された出力:```
2 3 2
2 2 2
```は構造的には一貫していますが、数値的に間違っています。これは、実装が位置に依存する到達可能性ではなく、位置ごとに均一なものを計算していることを示しています。 

核心的な間違いは、`0`そして`1`セグメントがモデル化されました。 

前のアプローチでは、各プレフィックス長について次のように仮定しています。$x$、答えは次のようにして得られます。 

- プレフィックス構造を左から数えます (「0」に基づいて)
 - サフィックス構造を右から数えます (「1」に基づいて)
 - 次にそれらを個別に合計します

 これは暗黙的に左制約と右制約の間の独立性を前提としていますが、これは誤りです。 トーナメントの構造は決定を組み合わせます。中間の敗退に応じて、同じプレイヤーが強制的に到達したり、到達不能になったりする可能性があります。 

欠けている重要なアイデアは次のとおりです。 

このプロセスは、独立したプレフィックス/サフィックスの存続可能性に関するものではありません。 それは、文字列のプレフィックスによって引き起こされる交互の支配制約の下で、プレイヤーが**到達可能なグローバル最大値または最小値になれるかどうかにかかっています**。 

より具体的には、各プレフィックス長$x$最初のトーナメントでの「方向転換」の数のみが関連する構造である制約付きトーナメントを定義します。$x-1$文字。 それぞれの変更により、どちらの側が勝者を伝播できるかが反転します。 

したがって、左右のランを別々に追跡するのではなく、交互のセグメントを通じて影響がどこまで伝播するかを追跡する必要があります。 

正しい不変式は次のとおりです。 

定数文字のすべてのセグメントが方向に一貫した方法で「解決」できるように、消去を方向付ける方法が存在すれば、プレイヤーは勝つことができます。つまり、接頭辞/接尾辞の分解ではなく、遷移の数だけが重要になります。 

## 正しい重要な洞察

 文字列を連続する等しい文字のブロックに圧縮します。 

各ブロックは、勝者がどのように伝播するかについて、正確に 1 つの「自由度」に貢献します。 

プレフィックスの場合$x$、勝者の可能性のある人の数は次のようになります。```
number of alternating blocks fully contained in s[0:x-1] + 1
```これが機能するのは、交互のセグメントごとに追加の勝者候補を 1 つだけ保持できるためです。 

したがって、トランジションの実行カウントを維持します。 

## 正しいアルゴリズム

 各プレフィックスについて:

 - 答え = 1 から始めます
 - ポジションごとに$i$、 もし$s[i] \ne s[i-1]$、カウンターを増やします
 - それぞれについて$x$、答えは`transition_count up to x-2 + 1`## 正しい Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        s = input().strip()

        # prefix transitions count
        trans = [0] * (n - 1)
        for i in range(1, n - 1):
            trans[i] = trans[i - 1]
            if s[i] != s[i - 1]:
                trans[i] += 1

        res = []
        for x in range(2, n + 1):
            # prefix ends at x-2
            if x - 2 >= 0:
                res.append(str(trans[x - 2] + 1))
            else:
                res.append("1")

        out.append(" ".join(res))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```## これで問題が解決する理由

 以前のソリューションでは、左右の生存ゾーンが独立した加算量として誤って扱われていました。 

正しいモデルは次のことを認識します。 

- **環境タイプの変更**のみが分岐の可能性を生み出します
 - 各トランジションでは、勝者候補が 1 人だけ追加されます
 - 絶対的な位置 (左端と右端) は無関係です

 したがって、答えはプレフィックス/サフィックスの分割構造ではなく、プレフィックス遷移数のみに依存します。 

## 複雑さ

 ソリューションが実行されます$O(n)$各文字列は 1 回スキャンされ、プレフィックス クエリは 1 回で応答されるため、テスト ケースごとに実行されます。$O(1)$。
