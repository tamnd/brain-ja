 ## 解決策
 ## 問題の理解

 固有の番号が付けられたブロックが垂直に積み重なったものがいくつか与えられます。 各スタックは上から下に順序付けされており、2 つの操作を使用してこれらのブロックを物理的に再編成できます。プレフィックスまたはサフィックス セグメントを取得して新しいスタックに変換することでスタックを 2 つに分割するか、内部順序を維持しながら一方をもう一方のスタックの上に完全に配置することで 2 つのスタックをマージできます。 

目標は、数値ラベルによって上から下へ昇順にソートされたすべてのブロックを含む 1 つのスタックで終了することです。 コストは分割およびマージの操作の数であり、最適な計画で使用される分割の数とマージの数を報告して、操作の合計数を最小限に抑える必要があります。 

主な問題点は、ブロックが最初は任意のスタックにグループ化されており、再配置できるのは連続するプレフィックスを切り取ってスタックを連結することだけであることです。 個々のブロックを恣意的に並べ替えることはできません。 

制約はデータの合計サイズが小さく、全体で最大 10,000 ブロックです。 これにより、重いデータ構造や高度なグラフ アルゴリズムが必要なくなります。 ソートとリニア スキャンを中心としたソリューションで十分です。 O(n log n) よりも悪いものはすべて安全であり、O(n^2) でさえ生き残る可能性がありますが、不要です。 

素朴だが重要な失敗例は、ブロックがすでに正しいグローバル順序にある​​にもかかわらず、多くのスタックに分散している場合に発生します。 グローバルな順序を考慮せずに常に隣接するスタックをマージする貪欲なマージ戦略では、不必要な分割またはマージが発生する可能性があります。 

たとえば、スタックについて考えてみましょう。`[1, 4]`、`[2, 3]`。 単純な戦略ではそれらを直接マージする可能性がありますが、順序制約により、ソートされた順序に一致するセグメントを分離するために分割する必要があります。そうしないと、スタック内の相対的な順序付けによって正しい構築が妨げられます。 これは、スタックを単に独立して扱うのではなく、グローバルな順序がスタック境界と一致する場所を推論する必要があることを示しています。 

もう 1 つのエッジ ケースは、ブロックが単一のスタック内ですでにソートされたシーケンスを形成している場合です。 その場合、分割やマージはまったく必要ありません。 常に少なくとも 1 つの操作を実行するアルゴリズムは正しくありません。 

## アプローチ

 ブルートフォースアプローチでは、プロセス全体をシミュレートしようとします。 私たちは、スタックの各構成を状態として扱い、分割とマージのあらゆる可能なシーケンスを考慮します。 各状態から、すべての有効な分割とマージを生成し、ソートされた単一スタック構成に到達するまで最短パス検索を実行します。 

これは正しいです。なぜなら、構造空間ではすべての操作が可逆的であり、すべての可能性を探索しているからです。 しかし、国家空間は膨大です。 10,000 ブロックの場合でも、順序付けされたスタックへのブロックの分割数は組み合わせによって増加するため、このアプローチは 20 ブロックでも実行不可能になります。 

重要な点は、実際には任意の構成をシミュレートする必要がないということです。 最終的な構成は完全に決定され、値によってソートされた単一のスタックになります。 すべてのブロックは、最終的には昇順で他のブロックと相対的に配置される必要があるため、唯一の問題は、初期スタックがソートされた順序とどのように交差するかということです。 

すべてのブロックを値でソートすることを想像すると、各初期スタックは、このソートされた順列に現れるシーケンスですが、セグメントに分割されます。 唯一有用な構造プロパティは、並べ替えられた順序で連続する要素が同じスタック内に正しい隣接関係ですでに表示されているかどうかです。 グローバルにソートされた順序で連続する 2 つの要素が正しい隣接性を持って同じスタックに存在していない場合は常に、マージ境界交差を実行する必要があり、スタックに異なるソートされたセグメントに属する要素が含まれている場合は必ず分割する必要があります。 

したがって、問題は、ソートされた順序が初期スタック全体でどのように分割されているかを追跡し、連続するソートされた要素間にいくつの「ブレーク」が存在するかをカウントすることに帰着します。

 ## アルゴリズムのチュートリアル

 1. 各ブロックがどの元のスタックから来たのかを思い出しながらすべてのブロックを平坦化し、値で並べ替えます。 

これにより、達成したい正しい最終順序が得られます。 また、元の構成で隣接構造を比較できるように、スタック ID も保持します。 
2. ソートされたリストをスキャンし、元のスタック ID によって隣接する要素を比較します。 

ソートされた順序で連続する 2 つの要素が異なるスタックから取得される場合は常に、境界を記録します。 これらの境界は、マージ操作を行わないと隣接関係を直接維持できない場所を表します。 
3. 並べ替えられた順序で隣接する要素が異なるスタックから取得された回数を数えます。 この値を呼び出します`k`。 

このような各境界により、異なる元のスタックに属するセグメントを接続するために少なくとも 1 つのマージ操作が強制されます。 
4. 次に、分割について考えます。 元のスタックごとに、そのブロックをソートされた順序で調べます。 

スタックがグローバルなソート順で複数の互いに素なセグメントを提供する場合、そのスタックは少なくともその回数から 1 を引いた回数分割する必要があります。 各スタックについて、その要素がソート順に形成する連続セグメントの数を計算し、必要な分割を蓄積します。 
5. 最終的な答えは、必要な分割と必要なマージの合計です。 

重要な設計上の選択は、操作を明示的にシミュレートしないことです。 最初のパーティションとターゲットの並べ替え順序の間の構造的な不一致のみをカウントします。 

### なぜ効果があるのか

 ソートされた順序により、一意のターゲットの線形配置が定義されます。 有効な構築プロセスは、最終的にはこの正確なシーケンスを組み立てる必要があります。 すべての初期スタックは、このシーケンスの連続セグメントに寄与するか、寄与しません。 そうでない場合は、セグメントを分離するために分割が必要です。 並べ替えられた順序で連続する 2 つの要素が異なるスタックに由来する場合、それらのスタックをブリッジするマージ操作を行わないと隣接することはできません。 操作は連続したブロックを連結または切り取るだけであるため、これら 2 種類の修正は必要かつ十分であり、明示的に対処しない限り、一度に複数のこのような構造的不一致を修正できる操作はありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    arr = []
    stack_id = []
    
    for i in range(n):
        tmp = list(map(int, input().split()))
        k = tmp[0]
        for x in tmp[1:]:
            arr.append(x)
            stack_id.append(i)
    
    # sort by value
    order = sorted(range(len(arr)), key=lambda i: arr[i])
    
    # count merge boundaries
    merges = 0
    for i in range(len(order) - 1):
        if stack_id[order[i]] != stack_id[order[i + 1]]:
            merges += 1
    
    # count splits per stack via segment counting
    pos_in_sorted = [[] for _ in range(n)]
    for idx in order:
        pos_in_sorted[stack_id[idx]].append(idx)
    
    splits = 0
    for i in range(n):
        if not pos_in_sorted[i]:
            continue
        # count number of contiguous runs in sorted index space
        cnt = 1
        for j in range(1, len(pos_in_sorted[i])):
            if pos_in_sorted[i][j] != pos_in_sorted[i][j - 1] + 1:
                cnt += 1
        splits += cnt - 1
    
    print(splits, merges)

if __name__ == "__main__":
    solve()
```実装は、各要素がどの元のスタックに属しているかを保存しながら、すべてのスタックを 1 つのリストにフラット化することから始まります。 ブロック値による並べ替えにより、最終的なターゲット順序が再構築されます。 

マージ数は、この並べ替えられた順序で隣接する要素をスキャンし、それらが異なるスタックからのものであるかどうかを確認することによって計算されます。 このような各遷移は、必要なマージ境界を示します。 

分割は、ソートされた配列インデックス空間内でその要素が出現する場所を調べることにより、スタックごとに計算されます。 スタックの要素がこの空間内で連続していない場合は常に、スタックが最終順序にわたって断片化されていることを意味し、分割によって連続する各セグメントが強制的に分離されます。 

微妙な点は、実際の動作をシミュレートしようとしていないことです。 正確さは純粋に、誘導された順列における構造的不連続性を数えることによって得られます。

 ### 例 1

 入力:```
2
3 3 5 8
2 9 2
```平らにした後:

 | 値 | スタック |
 | --- | --- |
 | 3 | 0 |
 | 5 | 0 |
 | 8 | 0 |
 | 9 | 1 |
 | 2 | 1 |

 値で並べ替えると次のようになります。`2(1), 3(0), 5(0), 8(0), 9(1)`隣接するスタック遷移:`1→0`、`0→0`、`0→0`、`0→1`したがって、マージ = 2 となります。 

スタック 0 は連続したセグメントとして表示されます`[3,5,8]`、分割は必要ありません。 

スタック 1 は次のように表示されます`[2]`そして`[9]`ソート順に並べられるため、2 つのセグメントが形成され、1 つの分割が必要になります。 

したがって、答えは`1 2`。 

### 例 2

 入力:```
3
1 4
1 2
1 3
```フラット化された順序でソート:`2(1), 3(2), 4(0)`隣接するトランジションはすべて異なるスタックであり、2 つのマージが行われます。 

各スタックには単一の要素があるため、分割はありません。 

結果は`0 2`。

 ## 特殊なケース

 エッジケースの 1 つは、すべてのブロックがすでに完全にソートされた単一のスタックを形成している場合です。 ソートされた順序と元の順序が一致するため、すべての要素が正しいスタック内で隣接し、遷移は発生しません。 ソートされた隣接スキャンではスタックの変更がなく、各スタックが 1 つの連続セグメントに寄与するため、このアルゴリズムでは分割もマージも発生しません。 

もう 1 つのエッジ ケースは、すべてのブロックが独自のスタック内にある場合です。 この場合、ソート順の各隣接関係は異なるスタックからのものであるため、マージ数は n マイナス 1 になります。各スタックには要素が 1 つだけあるため、内部フラグメントはなく、分割は 0 のままです。 このアルゴリズムは、問題をマージのチェーンの構築に正しく落とし込みます。 

最後の微妙なケースは、単一のスタックがソート順に他のスタックと大量にインターリーブされる場合です。 入力内では連続しているように見えても、その要素はソートされた順列全体に散在し、複数の分割が強制される可能性があります。 セグメントをカウントするステップでは、ソートされたインデックス リスト内の各不連続性が検出され、必要な分割操作が正しく考慮されます。
