 ## 問題の理解

 一連の整数と固定長が与えられます。$k$。 タスクは、シーケンスに正確な長さの連続ブロックが含まれないように、シーケンスの変更をできるだけ少なくすることです。$k$that is monotone. ブロックが完全に減少していないか、完全に増加していない場合、そのブロックは単調です。 

キー オブジェクトは任意のサブシーケンスではなく、連続したセグメントです。 あらゆる長さのウィンドウを効果的にスキャンしています$k$ここで、値の方向は決して変わりません。 このようなウィンドウが存在する場合、そのシーケンスは「退屈」であるとみなされ、できるだけ少ない要素を変更して、そのような単調なウィンドウをすべて破棄する必要があります。 

出力は変更の数だけでなく、完全に構築された変更された配列でもあります。 変更されたすべての位置は元の位置とは異なる必要があり、長さが一致しないことを確認する必要があります。$k$モノトーンセグメントは生き残る。 

制約は極端です。$n$まで上がります$10^6$。 これにより、二次関数またはわずかに超線形の方法ですべてのウィンドウを個別に検査するソリューションは即座に除外されます。 正しいアプローチはすべて線形またはほぼ線形でなければなりません。$O(n \log n)$この規模では重い定数を使用するのは危険です。 

単純なアプローチでは、一定のサイズのウィンドウをスライドさせることになります。$k$配列全体で各ウィンドウの単調性をチェックします。$O(k)$、につながる$O(nk)$。 と$n = 10^6$、これは完全に不可能になります。 

厳密に増加するシーケンスなど、配列がすでにどこでも「ほぼ単調」になっている場合、微妙なエッジ ケースが発生します。 このような場合、すべてのウィンドウに問題があり、単純な戦略では重複するウィンドウを個別に修正しようとするため、冗長な変更が発生します。 もう 1 つの注意が必要な状況は、一部のウィンドウのみがモノトーンである交互シーケンスです。これは、貪欲なローカル修正を誘惑して、別の場所に新しいモノトーン ウィンドウを誤って作成する可能性があります。 

本当に難しいのは、変更がグローバルに影響することです。1 つのウィンドウを修正すると、他の多くのウィンドウに影響を及ぼします。 

## アプローチ

 ブルートフォース戦略では、長さのすべてのサブ配列を検査します。$k$そしてそれが減少していないか増加していないかを確認します。 不正なウィンドウが見つかった場合は、その中の 1 つの要素を変更してみることができます。 ただし、これはすぐに曖昧になります。1 つの要素を変更すると、現在のウィンドウは修復される可能性がありますが、新しいウィンドウが作成され、すべてを繰り返し再計算すると、カスケード的な再計算コストが発生します。 

すべての禁止パターンを明示的にチェックするため、総当りの正確性は簡単ですが、パフォーマンスと、重複するウィンドウ間の相互作用の制御では失敗します。 各ポジションは最大で参加します$k$Windows なので、修正を繰り返すとすぐに爆発してしまいます。 

重要な洞察は、ウィンドウの観点から考えるのをやめ、代わりにローカル構造での長い単調な実行を防ぐ観点から考えることです。 長さ-$k$モノトーンセグメントは、それらの中で$k-1$隣接する比較では、すべての符号が同一です。 これは、連続する「同じ方向」の比較のシーケンスを実際に制御していることを意味します。 

すべてのウィンドウを明示的に追跡する代わりに、連続する非減少または非増加の関係が長さに達する前に強制的に破られるようにすることができます。$k-1$。 これにより、問題は、派生した比較シーケンスでの実行の管理に変換されます。 

最適な戦略は貪欲になります。左から右にスキャンし、現在の方向の実行長を維持し、到達しようとするたびに実行します。$k-1$では、現在の要素を変更して単調性を壊すことで配列に強制的な変更を加えます。 常に違反が発生する直前にブレークするため、禁止されたウィンドウが形成されないことが保証されます。

 ## アルゴリズムのチュートリアル

 左から右にスキャンしながら、最後の移動方向と現在の単調な走行がどのくらい続いたかを追跡しながら、最終的な配列を構築します。 

1. 作業配列を初期化する$a$入力のコピーとして取得し、現在のモノトーン ランレングスのカウンターを設定します。 

ランレングスは、方向が変わらない連続した比較を測定します。 
2. ポジションごとに$i$1から$n-1$かどうかを計算します。$a[i]$前の方向を継続します（以前と比較して増加または減少）$a[i-1]$）。 
3. 方向が前のステップと一致している場合は、ランレングスを増加させます。 それ以外の場合は 1 にリセットします。 

これは、単調なセグメントの形成にどれだけ近づいているかを追跡しています。 
4. ランレングスが次の値に達した場合$k-1$、危険な状態にあります。次のステップでは、長さの単調なセグメントが作成される可能性があります。$k$。 
5. これを防ぐために、次のように変更します。$a[i]$現在の方向を壊すように。 単調性が継続しないように、隣接する値とは異なる値を選択します。 修正後はランレングスを再設定してください。 
6. 最後までスキャンを続けます。 

この構造により、厳密に必要な場合にのみ要素を変更することが保証され、これによりミニマルさが生まれます。 

### なぜ効果があるのか

 このアルゴリズムは、次のシーケンスが存在しないという不変条件を強制します。$k-1$連続した比較は同じ符号を共有します。 長さの任意の単調セグメント$k$は、比較においてまさにそのような実行を意味するため、長い実行を防ぐことは、禁止されたセグメントを直接防ぐことになります。 可能な限り最後の瞬間にのみ介入するため、各変更は不必要な追加の変更を導入することなく、潜在的な違反を 1 つだけ排除します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    changes = 0

    # we will track run length of monotone direction
    run = 1
    direction = 0  # 1 increasing, -1 decreasing, 0 unknown

    for i in range(1, n):
        cur_dir = 1 if a[i] > a[i-1] else (-1 if a[i] < a[i-1] else 0)

        if cur_dir == direction and cur_dir != 0:
            run += 1
        else:
            direction = cur_dir
            run = 1

        if run >= k - 1 and direction != 0:
            # force break monotonicity at position i
            changes += 1

            # pick a value that breaks both sides if possible
            left = a[i-1]
            right = a[i+1] if i + 1 < n else left + 1

            # ensure a[i] is different and breaks direction
            if direction == 1:
                a[i] = min(left, right) - 1
            else:
                a[i] = max(left, right) + 1

            # reset state after modification
            run = 1
            direction = 0

    print(changes)
    print(*a)

if __name__ == "__main__":
    solve()
```この実装では、配列上の単一パスが維持されます。 実行ロジックは、単調なトレンドを延長しているかどうかを追跡します。 禁止されたしきい値に達しそうな実行を検出すると、現在の要素がただちに上書きされます。 

微妙な点は、置換値の選択です。 それが元のものと異なり、隣接するものと比較して単調性が壊れていることを確認する必要があります。 両方の隣接値よりも小さい値、または両方の隣接値よりも大きい値を使用すると、少なくとも 1 つの隣接する比較の方向が反転することが保証され、実行が安全にリセットされます。 

また、ローカル構造が意図的に破壊されているため、変更後の状態もリセットします。

 ## 特殊なケース

 重要なエッジ ケースは、次のような完全に単調なシーケンスです。$1,2,3,4,5$小さいもので$k$。 介入がなければ、すべてのウィンドウは無効になります。 アルゴリズムは、ランレングスが到達する寸前に正確にブレークを挿入することでこの問題を修正します。$k-1$、密な単調シーケンスであっても早期に断片化されるようにします。 

もう 1 つの特殊なケースは、値が繰り返されることです。 等しいことは増加方向にも減少方向にも寄与しないため、実行は自然にリセットされ、誤検知が防止されます。 このアルゴリズムは、等しいセグメントをニュートラル ブレークとして正しく処理するため、不必要な変更が削減されます。 

最後の微妙なケースは、変更によって制約が近隣に伝播される場合です。 各修正はローカル方向の状態をリセットするため、修正チェーンが誤って蓄積されることはなく、強制された各ブレークにより将来の決定が分離されます。
