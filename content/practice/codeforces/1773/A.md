 ## 問題の理解

 順列が与えられています$a$サイズの$n$、からのすべての数字を意味します$1$に$n$は 1 回だけ表示されます。 2 つの順列を適用することができます$q$最初にそしてそれから$p$、最終的な位置が$i$元の位置の値を受け取ります$p[q[i]]$。 言い換えれば、配列は位置再マッピングによって 2 回並べ替えられます。 

目標は選択することです$p$そして$q$両方の置換の後、結果の配列は位置を意味する恒等置換になります。$i$値が含まれています$i$。 両方$p$そして$q$錯乱しているに違いないので、どちらも立場を修正することはできません。 

変換は順列を選択するものとして解釈できます。$r = p \circ q$、それをポジションに適用します。 制約というのは、$r$2 つの混乱に分解できなければなりません。これが、このステートメントに隠れている本当の構造上の制限です。 

制約により強制的に$O(n)$または$O(n \log n)$テストごとのソリューション。 合計以来$n$すべてのテストケースにわたって$10^5$、テスト ケースごとの二次構築またはグラフ検索は失敗します。 

微妙な問題が現れるのは、$n = 1$。 順列は 1 つだけあり、それは自明のことですが固定点であるため、いかなる狂いもあり得ません。 のために$n = 2$、両方の順列で 2 つの要素を交換する必要があるため、構造は非常に制限されます。 もう 1 つの脆弱なケースは、構築が完全にサイクル構造に依存するため、順列にすでに多くの固定点または単一サイクルがある場合です。 

素朴な考えは、構築してみることです$p$そして$q$位置ごとに貪欲に配置し、固定点を回避しながら最終的なマッピングの正確さを確保します。 これは、決定がグローバルであるため失敗します。$p_i$ローカルでは将来の位置を固定点に強制的に入れることができます。$p$または$q$有効なグローバル割り当てが存在する場合でも。 

## アプローチ

 直接的な総当たりアプローチは、すべての混乱のペアを試みることになります。$p$そして$q$、そしてどうかを確認してください$p(q(i)) = a^{-1}(i)$（または同等に、その構成がアイデンティティを生み出すかどうか）。 錯乱の数はおおよそ$n! / e$、つまり、ペアは次の順序になります。$(n!/e)^2$でさえ天文学的な大きさです。$n = 8$。 1足チェックするだけでもコストがかかる$O(n)$、これは完全に不可能になります。 

重要な洞察は、2 つの任意の順列の観点から考えるのをやめ、代わりに問題をサイクルの分解制約として解釈する必要があるということです。 

させて$b = a^{-1}$。 私たちが望んでいるのは:$$p(q(i)) = b(i)$$定義する$r = p \circ q$。 それから$r = b$、したがって、固定順列を表現する必要があります$b$二つの錯乱の複合体として。 

重要な構造的事実は、任意の順列は、長さのサイクルがない場合に限り、2 つの乱数に分解できるということです。$1$。 これは、固定点があるためです。$b$強制するだろう$p(q(i)) = i$、両方の理由からこのようなことは起こり得ません。$p$そして$q$固定点を禁止しており、その構成は内部のどこかに固定点を導入しない限り、単一要素サイクルを「修復」できません。 

以来$b$はただの順列です$a$の場合、条件は次のことを確認するのと同じになります。$a$ID マッピング コンテキストに固定点が含まれていることは無関係です。 代わりに、本当の条件は、小さなサイクルとペアリング構造の処理に帰着します。 

この構築は、制御された方法で要素をグループ化し、サイクル内で回転することによって機能し、構成が一致している間、両方の中間の置換が固定点を回避することを保証します。$b$。 標準的な方法は、次のサイクルを処理することです。$b$各サイクルを 2 つのシフトされたレイヤーに分割すると、当然 2 つの混乱が生じます。 

サイクルが処理されたら、$q$各サイクル内の回転として、$p$相補的な回転として。 どちらの回転もすべての要素をシフトするため、どちらも固定点を持ちません。

 ## アルゴリズムのチュートリアル

 順列を使用して作業します$b = a^{-1}$、各値を正しい位置にマッピングし直す必要があるためです。 

1. 逆順列を計算する$b$、 どこ$b[a[i]] = i$。 これにより、最終的な要件がインデックスへの直接マッピングに変換されます。 
2.分解する$b$ばらばらのサイクルに。 各要素は正確に 1 つのサイクルに属し、以下に続きます。$b$繰り返しそのサイクルの中に留まります。 これは私たちが尊重しなければならない自然な構造です。$p$そして$q$グローバルな一貫性を維持する必要があります。 
3. サイクルに長さがある場合$1$、すぐに「Impossible」と出力されます。 長さ 1 のサイクルは、一部の要素がそれ自体にマップされることを意味します。$b$、そして、少なくとも 1 つの順列で固定点を作成せずに、2 つの錯乱の合成によってこれを実現する方法はありません。 
4. 長さのサイクルごとに$k \ge 2$、その要素に順番にラベルを付けます$c_0, c_1, \dots, c_{k-1}$。 
5. 定義する$q$各サイクル内で順方向回転として:$$q(c_i) = c_{(i+1) \bmod k}$$これにより、$q$すべての要素が移動するため、固定点はありません。 
6. 定義する$p$逆回転として:$$p(c_i) = c_{(i-1) \bmod k}$$これにより、固定点がないことも保証されます。 
7. 構成が一致していることを確認します$b$:$$p(q(c_i)) = p(c_{i+1}) = c_i$$したがって、構築は有効です。 

### なぜ効果があるのか

 不変条件は、次の各サイクル内で$b$、 両方$p$そして$q$同じ順序で循環シフトとして機能します。 これにより、すべてのインデックスが置き換えられるため、要素がそれ自体にマップされることがなくなります。 同時に、それらの構成はシフトを正確にキャンセルし、各サイクルで同一性を生み出します。$b$、これは必要なマッピングに対応します。 

サイクル間に相互作用は発生しないため、正確性はサイクルごとに独立して保持され、したがってグローバルに保持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    # inverse permutation b
    b = [0] * (n + 1)
    for i, x in enumerate(a, start=1):
        b[x] = i

    vis = [False] * (n + 1)
    p = [0] * (n + 1)
    q = [0] * (n + 1)

    for i in range(1, n + 1):
        if not vis[i]:
            cycle = []
            cur = i
            while not vis[cur]:
                vis[cur] = True
                cycle.append(cur)
                cur = b[cur]

            if len(cycle) == 1:
                print("Impossible")
                return

            k = len(cycle)
            for j in range(k):
                q[cycle[j]] = cycle[(j + 1) % k]
                p[cycle[j]] = cycle[(j - 1) % k]

    print("Possible")
    print(*p[1:])
    print(*q[1:])

if __name__ == "__main__":
    t = int(input())
    for _ in range(t):
        solve()
```コードはまず、ターゲット構造が一連のサイクルになるように逆順列を構築します。 次に、訪問した配列を使用して各サイクルを抽出します。 サイズ 1 のサイクルが現れた瞬間に、有効な混乱に基づく分解は存在できないため、サイクルは停止します。 

各サイクル内で、順方向および逆方向の回転が直接割り当てられます。 インデックス付けはサイクル長を法として慎重に処理されるため、サイクルの両端での境界の問題が回避されます。 

実装の微妙な詳細は、両方とも$p$そして$q$値のマッピングとして保存されます$1..n$、サイクル内の位置ではありません。 これにより、循環インデックス作成と順列インデックス作成の間の混同が回避されます。

 ## 特殊なケース

 単一要素サイクルは、元の配列が派生マッピングの正しい最終位置に既に値を配置している場合に発生します。 その状況では、サイクル分解により長さ 1 のサイクルが生成され、アルゴリズムはそれを即座に拒否します。$p$または$q$要素を混乱させたまま固定したままにすることができます。 

2 つの要素の交換の場合、次のようになります。$a = [2,1]$、サイクルは有効で、長さは 2 です。 アルゴリズムはそれを反対方向に回転させ、2 つの有効な狂いを生成します。 それをトレースすると、すべての要素が移動し、合成が正しくキャンセルされることが明示的に示されます。 

順列が 1 つの大きなサイクルを形成する場合でも、回転がグローバルに明確に定義されているため、構築は引き続き機能します。 すべての要素がシフトされ、混乱条件が確実に満たされると同時に、合成はシフトのキャンセルによって同一性を回復します。
