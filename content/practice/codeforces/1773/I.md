 ## 解決策
 ## 問題の理解

 隠れた整数を操作しています$n$, しかし、それを直接見ることはできません。 代わりに、次の形式で最大 10 個の質問をすることができます。$k$右から - 番目の桁$n!$階乗が短すぎるためにその桁が存在しない場合、システムは 0 を返します。 

私たちの仕事は、の正確な値を決定することです。$n$これらの数字クエリを使用して各テスト ケースに対応します。 の値$n$は 1 ～ 5982 の範囲にあることが保証されており、階乗の 10 進表現は 20000 桁以内に収まります。 

重要な問題は、私たちが観察していないことです。$n!$直接。 ランダム アクセス クエリのみをその数字配列に取得しますが、それは最下位側からのみであり、長さを超えるとゼロに切り捨てられます。 これは、次のようにしてその大きさが非常に急速に増大する大きな整数を効果的に調査していることを意味します。$n$、最大 10 桁の読み取りを使用して、最大約 6000 個の可能な値を区別する必要があります。 

制約$n \le 5982$重要な構造上のヒントです。 これは、階乗の直接シミュレーションや再構築が不可能であることを意味します。 均等に保管$n!$階乗は 20000 桁を超えるため、すべての候補に対してはすでに大きすぎます。また、多くの候補間で文字列を繰り返し比較すると、最大 100 個のテスト ケースでは時間がかかりすぎます。 

素朴な試みでは各候補者を試すことになるだろう$n$、計算する$n!$、クエリとの一貫性を確認します。 5982 までの階乗の計算はすでにコストが高く、テスト ケースごとに繰り返し実行するのは現実的ではないため、これはすぐに失敗します。 

2 番目の単純なアイデアは、クエリを使用して完全な階乗を桁ごとに再構築することです。 ただし、取得できるクエリは 10 件のみで、可能な桁数は 20000 であるため、完全な数値を復元することはできません。 代わりに、一意に識別する小さな署名を抽出する必要があります。$n$。 

微妙なエッジケースは、末尾のゼロから発生します。 階乗では、2 と 5 の因数により多くの末尾のゼロが蓄積されます。これは、多くの位置で最下位桁がほとんどゼロであることを意味するため、数値の終わり近くを単純に調査しても情報は得られません。 0、1、2 のような小さなインデックスのみをクエリする不用意な戦略では、大きなインデックスを区別できなくなります。$n$, すべての階乗は長いゼロの連続で終わるためです。 

## アプローチ

 ブルートフォースの観点は、十分な量の計算またはクエリができると想像することから始まります。$n!$一意に識別するためです。 完全な数値があれば、1 から 598​​2 までのすべての階乗を事前計算し、数字列を比較できます。 階乗は厳密に大きさが増加するため、これは論理的に機能します。$n$ユニークな数字パターンを生成します。 

ただし、完全な階乗を対話的に構築したり比較したりできないため、これはうまくいきません。 オフラインで事前計算したとしても、対話モデルではテストごとに 10 桁のクエリしか許可されないため、完全な文字列と一致するのに十分な情報を取得できません。 

重要な観察は、階乗は後続のゼロのパターンの構造と下位桁の分布が大きく異なるということです。 インデックス 0 付近では末尾のゼロは有益ではありませんが、数値をもう少し詳しく調べると、全体で異なる安定した非ゼロの数字が明らかになります。$n$。 課題は、それぞれに固有の署名を形成する少数の桁位置のセットを見つけることになります。$n$。 

以来$n$範囲が最大約 6000 までしかないため、すべての階乗をオフラインで 1 回事前計算し、その桁配列を保存して、どの桁位置が値を最もよく区別するかをシミュレートできます。 次に、対話中にそれらの位置を正確にクエリし、候補と照合します。 

これにより、問題は桁の位置に関する決定ツリーの構築に変わります。 クエリごとに候補セットが減ります。 各桁のクエリは候補セットを最大 10 個のグループに分割するため、10 個のクエリを使用すると、6000 個の候補を 1 つの値に減らすことができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | ブルート フォースでテストごとに階乗を再計算する |$O(T \cdot n)$階乗仕事 |$O(1)$| 遅すぎる |
 | 階乗の事前計算 + クエリ駆動のフィルタリング |$O(10 \cdot n)$テストごと |$O(n \cdot d)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1 から 5982 までの階乗をローカル配列で 1 回事前計算し、数字を逆順で格納するため、インデックスはクエリ インデックスに直接対応します。 

次に、次のように相互作用をシミュレートします。 

1. 各エントリが逆順に数字を格納するリスト内の 5982 までのすべての階乗を事前計算します。 

これにより、考えられるすべての隠れた数値に関する完全な決定的な知識が得られます。 
2. すべての値を含む候補セットから開始します$n \in [1, 5982]$。 
3. 最大 10 個のクエリごとに、桁の位置を選択します$k$現在の候補セットを最もよく分割する方法です。 

目標は、候補値がゼロに支配されず、多様な数字を生成する位置を選択することです。 
4. 裁判官に数字を尋ねる$k$、値を受け取る$d$。 
5. 候補セットのみを保持してフィルタリングします。$n$位置にある事前計算された数字が$k$で$n!$等しい$d$。 
6. 候補セットのサイズが 1 になるまで繰り返します。 
7. 残りの候補を答えとして出力します。 

重要な設計上の選択はクエリの選択です。 どの桁のインデックスを尋ねるかを制御するため、残りの候補全体でエントロピーを最大化するインデックスを選択します。 最下位桁に近い初期の位置は、末尾にゼロがあるため、多くの場合役に立ちません。 より良いポジションは、階乗が安定し、ゼロ以外の数字が頻繁に現れるポイント付近にあります。 

### なぜ効果があるのか

 正確さは、マッピングが次のとおりであるという事実に依存します。$n$十分な位置が選択されると、選択された位置の数字のベクトルへの単射的変換が行われます。 各クエリは、正確な桁の等価性によって候補空間を分割します。階乗は別個の整数であるため、それらの桁表現は少なくとも 1 つの位置で異なります。 インデックスを適応的に選択することで、候補が 1 つだけ残るまで、各クエリのあいまいさが軽減されます。 候補スペースのサイズが最大 6000 であり、各クエリを選択して有意義に分割できるため、プロセスは 10 クエリ以内に終了することが保証されています。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXN = 5982

# Precompute factorial digits (reversed)
fact = [[1]]
for i in range(2, MAXN + 1):
    prev = fact[-1][:]
    carry = 0
    for j in range(len(prev)):
        x = prev[j] * i + carry
        prev[j] = x % 10
        carry = x // 10
    while carry:
        prev.append(carry % 10)
        carry //= 10
    fact.append(prev)

def digit(n, k):
    if k < len(fact[n - 1]):
        return fact[n - 1][k]
    return 0

def pick_best(cands, used):
    best_k = 0
    best_score = -1

    for k in range(20000):
        if k in used:
            continue
        seen = set()
        for n in cands:
            seen.add(digit(n, k))
            if len(seen) > 5:
                break
        score = len(seen)
        if score > best_score:
            best_score = score
            best_k = k
        if best_score == 10:
            break

    return best_k

def solve_case():
    cands = list(range(1, MAXN + 1))
    used = set()

    for _ in range(10):
        if len(cands) == 1:
            break

        k = pick_best(cands, used)
        used.add(k)

        print("?", k, flush=True)
        d = int(input().strip())

        cands = [n for n in cands if digit(n, k) == d]

    print("!", cands[0], flush=True)

def main():
    t = int(input())
    for _ in range(t):
        solve_case()

if __name__ == "__main__":
    main()
```このソリューションは、階乗桁を 1 回事前計算し、各クエリを候補をフィルターする制約として扱うことに依存しています。 の`pick_best`関数は、残りの候補間で観測された変動を最大化する桁位置を貪欲に選択します。 

階乗桁が決定論的に事前に計算されるため、フィルタリング ステップは正確です。そのため、すべてのクエリで、隠れた数値と一貫して候補セットが削減されます。 

逆桁ストレージを使用すると、次のような直接インデックス作成が保証されます。$k$、最初に最下位桁の対話型定義と一致します。

 ## 特殊なケース

 重要なエッジ ケースは、クエリされたすべての位置が末尾のゼロの内側にある場合です。 たとえば、多くの候補に対して k = 0 または k = 1 をクエリすると、同じ答えが得られます。 このアルゴリズムは、観察された分散に基づいてインデックスを選択することでこれを回避し、最終的には意味のある数字領域に確実に移動します。 

小規模な場合には別の特殊なケースが発生します$n$、階乗長が短い場合。 このような場合、数値の長さを超えるクエリは 0 を返しますが、小さな階乗は初期の桁ですぐに異なるため、候補セットは最初のいくつかのクエリの後でも正しく縮小されます。 

大型用$n$、数字は中間の位置で安定します。 このアルゴリズムは、クエリ インデックスを徐々に上方にシフトすることでこれを処理し、階乗表現が候補間で大きく異なる領域に少なくとも 1 つのクエリが到達するようにします。
