 ## 解決策
 ## 問題の理解

 次のような整数のグリッドが与えられます。`n`行と`m`列。 各行はサボテンを表し、各列はトーラスを表します。 目標は、特定の制約が満たされるように、各サボテンをトーラスとペアにすることです。具体的には、各サボテンには高さがあり、各トーラスにはしきい値があり、サボテンはその高さがトーラスのしきい値を超える場合にのみトーラスとペアにできます。 出力は、このルールに従って形成できるサボテンとトーラスのペアの最大数です。 

入力はサイズを提供します`n`そして`m`、 に続く`n`サボテンの高さを表す整数、および`m`トーラスのしきい値を表す整数。 出力は、有効なペアの最大数を示す単一の整数です。 

次のような制約が与えられると、`n, m ≤ 2 * 10^5`整数の高さまで`10^9`、すべてをチェックするソリューションをすぐに除外できます。`n * m`明示的にペアリングします。 ブルートフォースアプローチでは、最大で`4 * 10^10`最悪の場合の操作は、2 秒の制限時間には遅すぎます。 

すべてのサボテンがすべてのトーラスよりも短い場合、エッジ ケースが発生します。この場合、ペアは存在しません。 もう 1 つの微妙なケースは、複数のサボテンの高さが同じで、複数のトーラスのしきい値が同じである場合です。 どのアルゴリズムでも、それらを過剰にカウントしたり不一致にしたりしてはなりません。 たとえば、サボテンの高さ`[2, 2, 3]`とトーラスのしきい値`[2, 2, 3]`最大 3 つのペアが生成されるはずですが、不注意で貪欲な割り当てを行うと正しくペアにならない可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、各サボテンを反復処理し、それをすべてのトーラスと一致させようとします。 これは有効なペアを正しく識別するため機能しますが、ネストされた反復により次のような結果が生成されるため、実際には失敗します。`O(n * m)`複雑なので、大規模な入力には遅すぎます。 たとえば、`n = m = 2 * 10^5`、私たちはパフォーマンスします`4 * 10^10`操作。 

最適なアプローチでは、並べ替えと 2 ポインター手法を活用します。 サボテンの高さとトーラスのしきい値の両方を昇順に並べ替えると、それらを同時に反復処理できます。 重要な観察は、サボテンがトーラスのしきい値より高くなると、そのトーラスとペアになり、次のサボテンと次のトーラスに移動できるということです。 並べ替えにより、小さいサボテンが最初に一致することが保証され、容量の無駄が回避され、ペアの最大数が確保されます。 

ストーリーは、ブルートフォースは論理的に機能しますが、遅すぎるということです。 並べ替えられた貪欲なアプローチが機能するのは、この問題には自然な単調な特性があるためです。背の高いサボテンは、その下にある任意のしきい値とペアになる可能性があります。 これにより、`O(n*m)`問題に入る`O(n log n + m log m)`並べ替えにより、ペアを形成するための直線パスが発生します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * m) | O(n + m) | 遅すぎる |
 | 最適 | O(n log n + m log m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. サボテンの数を読み取る`n`そしてトリ`m`、その後に配列`cactus`そして`torus`。 
2. 両方を並べ替える`cactus`そして`torus`昇順で。 これにより、最小の不対サボテンと最小の不対トーラスを効率的に一致させることができます。 
3. 2 つのポインタを初期化します。`i`サボテン用と`j`トーラスの場合、どちらも 0 から始まります。カウンターを初期化します。`pairs`0で。 
4. 両方とも`i < n`そして`j < m`、 比較する`cactus[i]`と`torus[j]`。 
5. もし`cactus[i] >= torus[j]`、このサボテンはこのトーラスとペアになることができます。 インクリメント`pairs`、両方を移動します`i`そして`j`フォワード。 
6. それ以外の場合は移動します`i`前方に進み、同じトーラスに対して次のサボテンを試します。 
7. いずれかのアレイを使い果たすまで繰り返します。 
8. を出力します。`pairs`カウンタ。 

機能する理由: ソートにより、利用可能な最小のサボテンと利用可能な最小のトーラスを常に組み合わせようとします。 この貪欲な戦略は有効です。なぜなら、より大きなサボテンは、より小さなサボテンでは不可能なトーラスと常にペアリングできるため、潜在的なペアリングが見逃されることがないからです。 不変条件は、すべてのステップで、`pairs`現在のポインターまでのすべての有効なペアをカウントします。カウントされない有効なペアはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    cactus = list(map(int, input().split()))
    torus = list(map(int, input().split()))
    
    cactus.sort()
    torus.sort()
    
    i = j = 0
    pairs = 0
    
    while i < n and j < m:
        if cactus[i] >= torus[j]:
            pairs += 1
            j += 1
        i += 1
    
    print(pairs)

if __name__ == "__main__":
    t = int(input())
    for _ in range(t):
        solve()
```最初のブロックは入力を読み取り、2 つの配列を並べ替えます。 リニア・グリーディ・パスを機能させるにはソートが必要です。 の`while`ループは、ポインタを慎重に移動することによってペアを形成します。有効なペアが形成された場合にのみトーラス ポインタをインクリメントし、常にサボテン ポインタをインクリメントします。 移動することを忘れる`i`ペアが失敗すると、無限ループまたは不正なカウントが発生します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n + m log m) | 並べ替えが優先されます。 線形パスでは O(n + m) が追加され、吸収されます。 |
 | スペース | O(n + m) | 配列は入力を格納します。 余分な大きな構造物はありません。 |

 という制約を考慮すると、`n, m ≤ 2*10^5`、ソートとリニアパスは制限時間内に快適に収まります。 メモリ使用量も通常の 512 MB 制限内に収まります。
