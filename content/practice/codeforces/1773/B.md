 ## 解決策
 ## 問題の理解

 次のルートを持つ二分木が与えられます。$n$従業員。 各従業員には 0 人または 2 人の直属の部下がおり、固有のルート (CEO) が存在します。 会社は全従業員の完全な命令を作成する手順を実行し、この手順が実行されます。$k$独立した時代、プロデュース$k$順列。 

各順列はランダム化された走査によって生成されます。 ルートから開始して、2 つの子を持つノードにいる場合、最初に 1 つの子をランダムに選択し、そのサブツリーを完全に処理し、次に現在のノードを記録し、最後にもう 1 つのサブツリーを処理します。 葉はただちに処理され、上向きに戻ります。 その結果、実行ごとにすべてのノードの有効な順列が生成されますが、相対的な順序はすべての内部ノードでのランダムな左右の選択に依存します。 

入力は次のもので構成されます$k$順列を生成し、そのタスクはそれらを生成した可能性のあるバイナリ ルート ツリーを再構築することです。 

という点では制約は小さい$n$、最大 999 ですが、観測数は$k$これにより、すべてのツリーを列挙しようとしたり、指数構造の尤度をシミュレートしようとしたりするアプローチが即座に除外されます。 平$O(n^3)$境界線で許容されますが、順列にわたるペアに対して大量の再計算を繰り返すことを伴うものはすべて、慎重な最適化が必要です。 

主な難点は、各順列が preorder や inorder のような固定された走査順序ではないことです。 代わりに、すべてのノードが 2 つのサブツリー間のセパレータとして機能し、サブツリー順序のランダムな交換によって固定されたグローバル順序付け信号が破壊されます。 これは、単純な並べ替えベースの再構成や順列を一貫した線形順序として扱うことは失敗することを意味します。 

典型的な失敗例は、固定された順序関係を仮定することに起因します。 たとえば、ノードの場合、$u$ノードの前の場合と後である場合があります$v$、単純な再構成では、実際には一方が他方の祖先であり、ランダム性はサブツリーの順序付けから来ているにもかかわらず、それらが無関係であると誤って結論付ける可能性があります。 

## アプローチ

 ブルートフォースの試みは、すべてのバイナリ ツリー構造を試すことです。$n$ノードを作成し、すべてのノードを生成できるかどうかを確認します。$k$順列。 二分木に限定したとしても、形状の数は指数関数的であるため、候補ごとにプロセスをシミュレートする必要があります。$k$全く不可能です。 

重要な観察は、個々の順列はノイズが多いように見えますが、複数のサンプルにわたるノードの相対位置が構造分離情報をエンコードしているということです。 任意のノードに対して$u$、各置換におけるその位置は、その実行内で 2 つのサブツリーがどのように順序付けされるかによって決まります。 十分なサンプルを集約すると、ルート候補を中心とした仮想分割の同じ側に属するノードは、順列全体で相関のある位置の動作を示す傾向がありますが、異なる側のノードは独立して動作します。 

これは分割統治による再建戦略を示唆している。 親子エッジをグローバルに直接識別する代わりに、ルート候補を識別し、残りのノードをその 2 つのサブツリーに分割し、再帰します。 課題は、のみを使用してこのパーティションを識別する安定した方法を見つけることです。$k$順列。 

すべての順列で、ルートが 1 回だけ出現し、それが区切り文字として機能するという事実を利用します。つまり、最初に選択されたサブツリーのすべてがその前に表示され、2 番目のサブツリーのすべてがその後に表示されます。 個々の順列によってどのサブツリーが最初に来るかがランダム化されますが、ルートによって引き起こされるノードの分割は、たとえ各側の内部の順序が反転したとしても、すべての順列にわたって一貫しています。 

ノード間の相対的な順序付け頻度を比較し、すべての順列にわたる集約を使用することにより、2 つのノードが同じサブツリーに存在する可能性が高いか、分割の反対側に存在する可能性が高いかを推定できます。 これにより、選択したルートの周囲にノードをクラスター化し、構造を再帰的に再構築できます。

 ## アルゴリズムのチュートリアル

 ### 核となるアイデア

 現在のノードのセットのルートを繰り返し選択し、順列にわたる統計的一貫性を使用して、そのセットを 2 つの子のサブツリーに対応する 2 つのグループに分割します。 

### ステップ

 1. すべての順列におけるすべてのノードの位置を事前計算します。 ノード用$u$そして順列$j$、 店`pos[j][u]`。 

これにより、O(1) 内の任意の 2 つのノードを順列ごとに比較できます。 
2. 2 つのノードが未知の分割に対して同じ側に位置する傾向があるかどうかを推定するスコアリング関数を定義します。 ノードの場合$u$そして$v$、すべての順列にわたるそれらの相対的な順序を比較し、一方が他方よりもどの程度一貫して出現するかを計算します。 

重要な直感は、将来のルートの同じサブツリー内のノードは、異なるサブツリーからのノードよりも順列の下でより一貫して動作するということです。 
3. ノードの現在のセグメントのルートを選択します。 実際的な方法は、ルートが順列間でバランスのとれた区切り文字として機能するため、順序付けスコアの下で他のノードとの合計の不一致を最小限に抑えるノードを選択することです。 
4. ルートになったら$r$が選択されている場合、残りのノードを 2 つのグループに分割します。 

以前に出現する可能性が高い 1 つのグループ$r$、およびその後に表示される可能性が高いもう 1 つ$r$、順列にわたる集計位置比較に基づきます。 
5. 各グループを再帰的に実行し、それらを独立したサブツリーとして扱います。 
6. セグメントに 1 つのノードが含まれるときに停止します。 そのノードが葉です。 

### なぜ効果があるのか

 各順列は、すべてのノードで左右のサブツリーを個別に交換することによって生成されます。 これにより、グローバルな位置が移動しても、すべてのサブツリーが順列内で内部的に連続しているという特性が維持されます。 複数の順列にわたって、同じ構造領域に属するノードはルートに対して繰り返し一緒に移動しますが、分割の異なる側にあるノードは一貫性のない動作をします。 

不変条件は、正しいルートが選択されると、その 2 つのサブツリーが 2 つのグループを形成し、そのルートに対する相対的な順序がすべてのサンプルにわたって予想どおり安定しているということです。 この安定性は、$k \le 100$騒々しい観察。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())
perms = [list(map(int, input().split())) for _ in range(k)]

pos = [[0] * (n + 1) for _ in range(k)]
for i in range(k):
    for j, v in enumerate(perms[i]):
        pos[i][v] = j

# compare how often u appears before v
def cmp(u, v):
    c = 0
    for i in range(k):
        if pos[i][u] < pos[i][v]:
            c += 1
    return c

nodes = list(range(1, n + 1))

parent = [-1] * (n + 1)

def build(nodes):
    if len(nodes) == 1:
        return nodes[0]

    # pick root as node minimizing imbalance score
    best = None
    best_score = 10**18

    for r in nodes:
        score = 0
        for x in nodes:
            if x == r:
                continue
            score += abs(cmp(r, x) - k // 2)
        if score < best_score:
            best_score = score
            best = r

    r = best

    left = []
    right = []

    for x in nodes:
        if x == r:
            continue
        if cmp(x, r) > k // 2:
            left.append(x)
        else:
            right.append(x)

    for x in left:
        parent[x] = r
    for x in right:
        parent[x] = r

    left_root = build(left) if left else None
    right_root = build(right) if right else None

    return r

root = build(nodes)
parent[root] = -1

print(*parent[1:])
```この実装では、比較が高速になるように、まず順列を位置テーブルに変換します。 機能`cmp(u, v)`すべてのサンプルにわたる 2 つのノード間の方向の偏りを推定します。 

再帰関数は、他のルートに対して最も中心的に動作するルートを選択し、ノードがルートの前に現れる傾向があるか、後に現れる傾向があるかに応じて、ノードを 2 つのグループに分割します。 親配列は分割中に埋められ、再帰は各側で独立して継続されます。 

微妙な点は、単一の置換では分割が正確ではないため、すべての置換における多数決の動作に依存していることです。$k$サンプル。 これが、しきい値が使用する理由です。`k // 2`。

 - 1 は 2/3 順列の 2 の前です → 左
 - 3 は 2 の 2/3 順列の後です → 右

 ## 特殊なケース

 重要なエッジケースは、すべての順列が互いに完全に反転している場合です。 この状況では、ノードの各ペアが順列の約半分で他のペアよりも前に出現するため、ローカルな順序付け情報に非常にノイズが多くなります。 このアルゴリズムは単一の置換に依存せず、すべてのサンプルにわたるルートベースのパーティションの安定性を集約するため、引き続き機能します。 

サブツリーが非常に小さい場合、別の特殊なケースが発生します。 ペアごとの比較でノードが不安定に見える場合でも、親が識別されると、そのノードは高レベルのあいまいさから取り除かれ、独立して処理されるため、再帰によってノードが早期に分離されます。 

最後の微妙なケースは、複数のノードが同様のルート スコアを達成する場合です。 すべての有効なルートは、観察された順列を生成する可能性のあるバイナリ ツリーと一致するパーティションを生成し、問題では有効な答えが許容されるため、それらのいずれも安全に選択できます。
