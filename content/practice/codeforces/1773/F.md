 ## 解決策
 ## 問題の理解

 一連の試合にわたるサッカー チームの集計統計が提供されます。 個々の試合結果を知る代わりに、私たちが知っているのは 3 つの数字だけです。つまり、行われた試合数、全試合でチームが得点した合計ゴール数、そして失点した合計数です。 

タスクは、これらの合計が正確に一致する一致スコアラインの有効なシーケンスを再構築することです。 あらゆる可能な再建の中で、引き分けの数を最小限に抑える必要があります。引き分けとは、両チームのゴールが同じで試合が終了することを意味します。 複数の再構成がこの最小値を達成する場合、それらのいずれか 1 つが許容されます。 

問題を再解釈する便利な方法は、整数のペア、つまり得点と失点の合計を n 個の順序付きペアに分割することです。 各ペアは一致スコアを表します。 最初の成分の合計は a に等しく、2 番目の成分の合計は b に等しくなければなりません。 目標は、2 つのコンポーネント間の同等性を満たすペアをできるだけ少なくするようにこれらのペアを構築することです。 

制約は小さく、n は最大 100、合計目標数は最大 1000 です。これは、二次関数または慎重な三次関数の動作を伴う任意の解が問題なく、一致分布に対する指数関数的な検索は不要であることをすぐに示唆しています。 本当の課題は、計算の複雑さではなく、制御された数の等しいペアを使用して有効な分解を構築することです。 

一方または両方の合計がゼロの場合、微妙なエッジ ケースが発生します。 a が b に等しい場合、すべての試合を引き分けとして割り当てたくなるかもしれませんが、分割不可能な制約によって強制されない限り、それは決して最適ではありません。 もう 1 つのエッジ ケースは、n が合計ゴールに比べて大きい場合です (例: a = 1、b = 0、n = 100)。多くの一致は少なくとも 1 つの座標で 0:0 のようなものになるのは避けられず、不用意に貪欲な分散を行うと、誤って不必要な引き分けが発生する可能性があります。 

主な困難は、引き分けが構造的にどのように発生するかを理解することです。引き分けは 1 回の試合で同量の得点と失点を消費するため、引き分けを最小限に抑えるということは、合計を尊重しながら可能な限り均等な割り当てのペアを避けることを意味します。 

## アプローチ

 強引な解釈では、n 試合にわたるゴールの可能なすべての分布を割り当て、各構成の引き分けをカウントしようとします。 試合ごとのゴールを離散化したとしても、各試合には得点と失点の可能性が最大 1000 ある可能性があるため、状態空間は 1000^(2n) のオーダーで天文学的に大きくなります。 これはまったく実現不可能です。 

重要な観察は、一致間の順列や複雑な相互作用を最適化していないということです。 グローバル合計制約を除いて、各一致は独立しています。 これは、合計が満たされていることを確認しながら、貪欲に一致を構築できることを意味します。 引き分けを作成する唯一の方法は、ペア (x, x) を意図的に割り当てることです。そのため、できるだけ多くの一致での平等を回避できれば、引き分けを最小限に抑えることができます。 

構造はさらに単純化されます。すべての一致を異なる (x, y) に割り当てることができれば、引き分けはゼロになります。 引き分けに追い込まれるのは、残った対称制約により x = y を回避できない場合だけです。 ただし、試合全体でゴールを任意に配分できるため、両方の合計がローカルで強制されない限り、常に等しいペアの作成を避けることができます。 

クリーンで建設的な戦略は、必要な場合を除き、一致を決して対称にしないようにしながら、すべての一致を貪欲に割り当てることです。 私たちは一度に 1 試合ごとにゴールを配分し、得点と失点に常に異なる値を割り当てるよう努めています。 いずれかの時点で残りの合計が等しくなる場合は、引き分け試合を使用します。 

これにより、問題は、等しくないペアを優先して、2 つの合計を n 個のペアに制御された貪欲な分割に帰着します。

 ## アルゴリズムのチュートリアル

 残りのゴールを追跡しながら、試合を順番に構築します。 

1. 残りの得点数が a、失点数が b で開始し、n 試合を割り当てます。 各一致を 1 つずつ構築し、合計が実行可能な状態に保たれるようにします。 
2. 最初の n − 1 試合のそれぞれについて、引き分けを回避しようとします。 残りの合計を実行可能に保ちながら、x が y と厳密に異なり、両方が負ではないスコア (x, y) を選択します。 簡単な方法は、可能な最小限の値を割り当てることです。たとえば、a > 0 の場合は x = 1、それ以外の場合は 0 に設定し、可能であれば y を別の方法で分配します。 重要なのは、合計を間違って計算しないようにしながら、x ≠ y を確実にすることです。 
3. 引き分け以外の試合を割り当てた後、a から x を減算し、b から y を減算します。 これにより、残りの合計が残りの一致に分散できるという不変条件が維持されます。 
4. 最後の試合では、残ったものをすべて使用しなければなりません。 残り a が残り b と等しい場合、この試合は引き分けです。 それ以外の場合は、正確に (a, b) を使用した非描画代入になります。 

両方の合計を正確に満たす必要があるため、最後のステップが強制されます。 あらゆる不均衡はそこで解決されなければなりません。 

### なぜ効果があるのか

 維持される不変条件は、各割り当ての後、残りの合計ゴール (a、b) が非負性を侵害することなく残りの試合に分配できるということです。 私たちは平等を時期尚早に強制することは決してないので、最後の残りがそれを必要とする場合にのみ引き分けを作成します。 したがって、どの描画も残りの状態で非対称割り当てが不可能な状況に正確に対応するため、描画の数は最小限に抑えられます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = int(input())
    b = int(input())

    res = []

    # We try to distribute greedily
    for i in range(n - 1):
        if a > b:
            x = 1 if a > 0 else 0
            y = 0
        else:
            x = 0
            y = 1 if b > 0 else 0

        # fallback if both zero
        if a == 0 and b == 0:
            x, y = 0, 0

        res.append((x, y))
        a -= x
        b -= y

    # last match takes everything
    res.append((a, b))

    draws = sum(1 for x, y in res if x == y)

    print(draws)
    for x, y in res:
        print(f"{x}:{y}")

if __name__ == "__main__":
    solve()
```この構築では単純な貪欲バイアスを使用します。つまり、常に大きい方の残りの合計を最初に減らそうとし、分布を可能な限り非対称に保つようにします。 最後の試合では、残っている不均衡がすべて吸収されます。 描画カウントは等価性チェックから直接計算されます。 

微妙な点は、中間の一致では非常に小さな調整 (0 または 1) が強制されるため、偶発的に合計がオーバーシュートすることが防止されることです。 n は最大 100、合計は最大 1000 であるため、この段階的な削減は安全です。

 ## 特殊なケース

 n = 1 の場合、柔軟性はありません。単一の一致は合計を表す必要があり、a が b と等しい場合に引き分けが発生します。 ループがスキップされ、最終一致が (a, b) であるため、アルゴリズムはこれを自然に処理し、等価性が正しく検出されます。 

a = b = 0 で n が大きい場合、すべての一致は (0, 0) になります。 すべての試合は引き分けですが、ゴールを消費せずに非対称を導入する方法はないため、これは避けられません。 

a または b のいずれかが 0 の場合、構築では単純にすべてのゴールが一方の側に割り当てられます。 両方の合計がゼロでない限り等価性は導入されないため、描画カウントは最小限のままになります。 

合計が小さくても n が大きい場合、多くの一致の寄与はゼロになります。 貪欲な割り当ては可能な場合にのみ減算され、残りの分配は最終一致に対して常に有効であるため、引き続き機能します。
