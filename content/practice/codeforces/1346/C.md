 ## 解決策
 ## 問題の理解

 私たちは一列の本棚を与えられ、それぞれの本にある程度の数の本が入っています。 目標は、すべての棚に最大でも`k`本。 2 つの操作を使用して構成を変更できます。 最初の操作はローカルです。棚を 1 つ選択し、その棚にあるすべての書籍をコストをかけて削除できます。`x`。 2 番目の操作はグローバルです。すべての本を取り出し、費用をかけてすべての棚にできるだけ均等に再配布します。`y`、値が最大 1 だけ異なる構成が生成されます。 

タスクは、最終構成が上限を遵守するようにしながら、総コストを最小限に抑えるためにこれらの操作のシーケンスを選択することです。`k`。 

重要な制約は、`n`すべてのテスト ケースで最大でも`2 * 10^5`したがって、テスト ケースごとに 2 次的な解は失敗します。 たとえ`O(n log n)`慎重に集計した場合にのみテストごとに許容されますが、操作のシミュレーションを繰り返したり、サブセットを探索したりすることは不可能です。 各テスト ケースを線形または線形演算に削減するソリューションが必要です。 

グローバルな再配分によって依然として値を超える値が生成される場合、微妙なエッジ ケースが発生します。`k`。 その場合は運用だけでは不十分なので除去と組み合わせる必要があります。 もう 1 つの注意が必要な状況は、再配布が一見無駄に見えても、最初にグローバル再配布を行うよりも、いくつかの大きな棚を削除する方がコストがかかる場合です。 

たとえば、ほとんどの値がわずかに上回っている場合を考えてみましょう。`k`, ただし、1 つの値が非常に大きくなります。 単純なアプローチでは常に最大の要素が削除される可能性がありますが、単一のグローバル再配布によってすべての値が十分に小さくなり、コストのかかる削除が不要になる場合があります。 

## アプローチ

 ブルート フォース戦略では、シェルフのすべてのサブセットが最初の操作を適用することを考慮し、サブセットごとに 2 番目の操作を前後に適用するかどうかを決定します。 サブセットを削除した後、再配布が必要かどうかを計算し、シミュレーションします。 これが検討につながります`2^n`たとえ「悪い」棚の削除のみに制限したとしても、組み合わせの数は最悪の場合でも指数関数的に増加します。 

重要な観察は、2 番目の操作が決定論的に動作することです。適用された後、すべての値は次のいずれかになります。`floor(S/n)`または`ceil(S/n)`どこ`S`is the total sum. これは、任意の状態をシミュレートする必要がないことを意味します。 棚の数が何個を超えるかを知る必要があるだけです`k`、そして、再配布が有益かどうかを決定する前に、それらのうちのいくつかを削除する必要があるかもしれません。 

任意のサブセットを選択する代わりに、配列を並べ替えます。 これにより、削除を「最大の要素の切り取り」として扱うことができます。 を削除すると、`i`最大の棚では、残りの合計を計算し、再配布によってどのような結果が生じるかを確認できます。 これにより、テスト ケースごとの決定空間が指数関数的な候補から線形候補に減少します。 

次に、すべての値が k ≤ になるまで削除のみを行う方法と、最大の要素の接尾辞を削除した後に再分配を実行する方法の 2 つの戦略を比較します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース サブセット | O(2^n) | O(n) | 遅すぎる |
 | ソート + サフィックスの削除を試行 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは問題を、再配布を適用する前に最大の要素をいくつ削除するかを決定することに集約します。 

1. 配列を非降順でソートします。 これにより、削除された要素のセットが配列のサフィックスに対応することが保証されます。 
2. 接頭辞の合計を計算して、接尾辞を削除した後に残りの要素の合計をすぐに取得できるようにします。 
3. しましょう`i`削除する最大の要素の数を表します。 最初に検討するのは、`i = 0`。 
4. それぞれについて`i`から`0`に`n`、残りの合計と残りの数を計算します。`m = n - i`。 
5. 現在の構成がすでに条件を満たしているかどうかを確認します`max ≤ k`。 最大の要素を削除したため、これはチェックすることと同じです。`a[m-1] ≤ k`。 true の場合、コストを使用して回答を更新します`i * x`。 
6. それ以外の場合は、削除後にグローバル再配布を実行することを検討してください。 再配分された最大値を計算します。`ceil(sum / m)`。 この値が ≤ k の場合、状態はコストで固定できます。`i * x + y`。 
7. 有効なすべての最小値を取得します`i`。 

重要な考え方は、削除は最大の要素のみをターゲットにするということです。これは、両方の操作が位置に関しては対称ですが、値に関しては対称であるため、最適な戦略では、大きい要素を保持したまま小さい要素を削除することは決してないからです。 

### なぜ効果があるのか

 このアルゴリズムは、2 番目の操作で順序付けが破壊され、配列が合計によってのみ決定されるほぼ一様な分布に置き換えられるという事実に基づいています。 これにより、再配布後に個々の要素を追跡する必要がなくなります。 したがって、破棄する要素の数を選択した後、関連する唯一の状態は次のとおりです。`(remaining count, remaining sum, maximum remaining element before redistribution)`。 並べ替えにより、すべての意味のある削除構成がサフィックスで表されることが保証されるため、最適なソリューションを見逃すことはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k, x, y = map(int, input().split())
        a = list(map(int, input().split()))
        
        a.sort()
        
        pref = [0] * (n + 1)
        for i in range(n):
            pref[i + 1] = pref[i] + a[i]
        
        ans = float('inf')
        
        for rem in range(n + 1):
            i = n - rem  # number of removed largest elements
            if rem == 0:
                sum_rem = 0
            else:
                sum_rem = pref[rem]
            
            if rem > 0 and a[rem - 1] > k:
                continue
            
            cost = i * x
            
            if rem > 0:
                max_after = (sum_rem + rem - 1) // rem
                if max_after <= k:
                    ans = min(ans, cost + y)
            else:
                ans = min(ans, cost)
        
        print(ans)

if __name__ == "__main__":
    solve()
```この解決策は、ソートすることから始まり、最大の要素の削除が逆インデックス付けのプレフィックスカットになるようにします。 プレフィックス合計を使用すると、残りの合計を定数時間で計算できます。 このループは、削除後に残る要素の数を列挙します。 部門`(sum_rem + rem - 1) // rem`再分配後の最悪の場合の値を計算します。 

微妙なディテールの処理`rem = 0`、これはすべての要素を削除することに相当します。 この場合、再配布は無意味であり、削除のコストのみが問題となります。

 ## 特殊なケース

 重要なエッジケースは、すべての要素がすでに ≤ k である場合です。 この状況では、すべてのループ反復でコストゼロを許可する必要があり、少なくとも 1 つの操作を強制する実装では誤ってコストが追加されてしまいます。 アルゴリズムはこれを処理します。`rem = n`削除も再配布も行われません。 

1 つの要素だけが k を超える場合、別のエッジ ケースが発生します。 ここで、正しい決定は完全に次の点に依存します。`x`よりも小さいです`y`、アルゴリズムは直接の削除と削除後の再配布の両方を評価することでこれを捕捉します。 

最後の微妙なケースは、平均が小さいにもかかわらず、再分配によって k をわずかに超える値が生成される場合です。 整数除算だけでは分配後の真の最大値が過小評価されてしまうため、上限演算は不可欠です。
