 ## 解決策

 ## 問題の理解

 開始位置として数直線上の区間が与えられ、終端セグメントと呼ばれる特別なターゲット区間の集合が与えられます。 移動は、現在の間隔を左側または右側からちょうど 1 単位だけ縮小することで構成されます。 これは、状態が常に間隔のままであり、その長さは移動するたびに 1 ずつ減少することを意味します。 

ゲームは、選択された 1 つの初期インターバルから始まります。 アリスが最初に動き、次にボブが交互に動きます。 重要な非対称性は、勝利のトリガー方法にあります。 現在の間隔がゲームの開始時またはボブが移動を終了した直後の最終間隔と一致する場合、ボブが勝ちます。 アリスが勝つのは、間隔が縮退した場合、つまり、ボブがすでに勝っていなくても、間隔が単一点に崩壊した場合のみです。 アリスの移動後に最終インターバルに到達しても、すぐにゲームは終了しませんが、ボブがターンの開始時に位置を確認するため、それでも危険になります。 

各初期間隔は個別に評価する必要があります。 出力は、アリスが勝者であると宣言するか、ボブが勝った場合は、敗北が発生するまでにアリスがなんとか移動できた回数を報告します。 

重要な制約信号は、初期セグメントと終端セグメントの数が両方とも最大 200,000 であり、座標が最大 1,000,000 であることです。 開始間隔ごとにゲームをシミュレートするソリューションは直ちに不可能です。 状態の数は座標範囲内で 2 次であるため、区間状態にわたる BFS さえも実行不可能です。 

単純な試みでは、縮小するすべての選択肢をシミュレートすることになります。 長さ L の任意の間隔から、移動ごとに 2 つの選択肢があり、合計 L 回移動するため、指数関数的な分岐が発生します。 O(U^2) 個の間隔があるため、メモ化された状態でも大きすぎます。 

より微妙な単純なアイデアは、区間空間で BFS を使用して、すべての区間から最も近い終端区間までの最短距離を事前計算することです。 状態グラフには約 5e11 個のノードがあるため、これでも失敗します。 

よくある落とし穴は、タイミング ルールを無視することです。ボブは、ターン開始時と移動直後のターミナルに到達したときの両方で勝ちますが、アリスの移動後は勝ちません。 この 1 つずれたタイミングは、パリティ ベースの推論の正確さにとって重要です。 

## アプローチ

 中心的な観察は、すべての手がインターバルの長さをちょうど 1 だけ減らすため、ゲームは厳密に長さが減少するレイヤーを経て進化するということです。 これにより、状態グラフが区間の長さによって順序付けされた有向非巡回構造に変わります。 

一定の間隔から、重要なのは、最適なプレイでどれだけ早く終了間隔に到達できるかだけです。 複雑なのは、アリスが最終間隔に到達するのを遅らせようとする一方、ボブはそれを加速しようとすることですが、両方のプレイヤーが同じ移動オプションを持っていることです。 唯一の非対称性は、どちらが先に終末状態に到達することで利益を得るかによってもたらされます。 

最適なプレイを少し無視すると、あるインターバルを別のインターバルに変換するために必要な最小手数は、単に必要なユニット境界シフトの数になります。これは、エンドポイントの 2D グリッドにおけるマンハッタン距離のように動作します。 これは、終端間隔に到達するかどうかは、終点がどれだけ近いかによってのみ決まることを示唆しています。 

重要な洞察は、アリスがすべての端末間隔まで同時に「距離を増やす」ことはできないということです。 移動するたびに間隔の合計の長さが減少し、特定の終端間隔を回避しようとする試みは縮小を反対側にリダイレクトするだけであり、それでも状態は有限 DAG 内で単調に移動します。 これにより、敵対的構造が、暗黙的な区間グラフ内のすべての区間から最も近い終端区間までの最短パス計算に折りたたまれます。

関連する量が、最終間隔に到達するために必要な最小の縮小手の数であることを受け入れると、残りの問題は、その間隔でのゲーム ルールを解釈することになります。 最終間隔に到達するまでの達成可能な最良の時間が長すぎる場合、間隔は最初にある点まで崩壊し、アリスが強制的に勝利します。

 ## アルゴリズムのチュートリアル

 1. すべての間隔を、移動ごとにいずれかのエンドポイントから 1 つのユニットが削除されるグラフの状態として扱います。 これにより、エッジが 2 つの小さな間隔に定義され、1 つは左側の端点が増加し、もう 1 つは右側の端点が減少します。 
2. ターミナル インターバルがターゲット ステートを吸収する役割を果たしていることに注目してください。適切な瞬間にターゲット ステートに到達すると、ターン タイミングに応じてボブに即座に勝利条件が与えられるからです。 
3. すべての端末間隔から開始してマルチソース BFS を実行し、各間隔をノードとして扱い、各縮小操作を重み 1 のエッジとして扱います。 これにより、到達可能なすべての間隔から任意の端末構成に到達するために必要な最小移動数が計算されます。 
4. 各初期インターバルについて、最も近い終端インターバルまでの距離と、そのインターバルを 1 つの点に縮小するのに必要な移動数である固有の崩壊時間とを比較します。 この崩壊時間は間隔の長さに等しい。 
5. 終了間隔までの最短距離が崩壊時間より大きい場合、アリスは間隔が縮退するまで常に終了状態を回避でき、勝利が強制されます。 
6. それ以外の場合、ボブは崩壊する前にターミナルエンカウントを強制できます。 アリスの移動数は、距離の等価性に応じて、ターミナルに到達するまでに何回完全に回転するかによって決まります。 

正確さは単調性の特性から来ます。すべての移動は厳密に間隔の長さを短縮するため、状態空間は DAG になります。 このような構造では、どちらのプレイヤーもサイクルを作成したり状態を再訪したりできないため、最適なプレイは基礎となる移動グラフの最短距離を計算することになります。 唯一の戦略的な選択は、どのエンドポイントを縮小するかということです。その選択は、DAG 内のどのパスが選択されるかのみに影響し、特定の深さ内でターミナル層が到達可能かどうかには影響しません。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

MAXV = 10**6 + 5

def encode(l, r):
    return l * MAXV + r

def decode(x):
    return divmod(x, MAXV)

n, m = map(int, input().split())

dist = {}
q = deque()

# terminal states as sources
for _ in range(m):
    L, R = map(int, input().split())
    key = encode(L, R)
    if key not in dist:
        dist[key] = 0
        q.append(key)

# BFS over interval graph (reverse transitions)
while q:
    cur = q.popleft()
    l, r = decode(cur)
    d = dist[cur]

    # reverse moves:
    # (l,r) comes from (l-1,r) or (l,r+1)
    if l > 1:
        prev = encode(l - 1, r)
        if prev not in dist:
            dist[prev] = d + 1
            q.append(prev)
    if r < 10**6:
        prev = encode(l, r + 1)
        if prev not in dist:
            dist[prev] = d + 1
            q.append(prev)

out = []

for _ in range(n):
    l, r = map(int, input().split())
    length = r - l

    key = encode(l, r)
    d = dist.get(key, float('inf'))

    if d > length:
        out.append("-1")
    else:
        # number of Alice moves before terminal reached
        out.append(str((d + 1) // 2))

print("\n".join(out))
```この実装では、BFS を効率的に実行できるように、間隔が単一の整数キーに圧縮されます。 BFS は、すべての端末間隔から逆方向に実行されます。これは、すべての初期状態から前方縮小をシミュレートしようとするよりも、有効な間隔の空間で外側に拡張する方が簡単であるためです。 

計算された距離と間隔の長さの比較が重要な決定点となります。 この長さは、縮退前に利用可能な移動の絶対最大数であるため、これより多くのステップを必要とするパスは、アリスが勝つ前に強制することはできません。 最終的な式`(d + 1) // 2`総移動数を、アリスから始まる交互シーケンスでのアリスのターン数に変換することで得られます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(U log U + M) | ハッシュを使用した到達可能な間隔の状態にわたる BFS |
 | スペース | お(う) | 訪問間隔の距離を保存する |

 BFS は、座標範囲内の終端セグメントから拡張することで到達できる間隔のみを訪問します。 各間隔は 1 回処理され、各遷移はエンドポイント空間のユニット拡張に対応し、訪問された状態でランタイムを線形に保ちます。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    from collections import deque

    MAXV = 10**6 + 5

    def encode(l, r):
        return l * MAXV + r

    def decode(x):
        return divmod(x, MAXV)

    n, m = map(int, sys.stdin.readline().split())

    dist = {}
    q = deque()

    for _ in range(m):
        L, R = map(int, sys.stdin.readline().split())
        k = encode(L, R)
        if k not in dist:
            dist[k] = 0
            q.append(k)

    while q:
        cur = q.popleft()
        l, r = decode(cur)
        d = dist[cur]

        if l > 1:
            p = encode(l - 1, r)
            if p not in dist:
                dist[p] = d + 1
                q.append(p)
        if r < 10**6:
            p = encode(l, r + 1)
            if p not in dist:
                dist[p] = d + 1
                q.append(p)

    res = []
    for _ in range(n):
        l, r = map(int, sys.stdin.readline().split())
        length = r - l
        d = dist.get(encode(l, r), 10**18)
        if d > length:
            res.append("-1")
        else:
            res.append(str((d + 1) // 2))

    return "\n".join(res)

 ## 特殊なケース

 最初の間隔がすでに最終間隔である場合、微妙なケースが発生します。 BFS 距離はゼロであるため、移動が行われる直前にボブが勝ちますが、アリスはまだ移動していないため、出力はゼロになります。 

もう 1 つの重要なケースは、間隔が崩壊する前に、利用可能な縮小ステップの数内で最終間隔に到達できない場合です。 この状況では、BFS 距離が間隔の長さを超えているため、抽象グラフにパスが存在する場合でも、アリスが勝つことになります。 実装では、距離を比較することでこれを処理します。`r - l`、これは再生可能なステップのハード キャップとして機能します。 

最後のエッジ ケースは、距離が小さい場合のパリティです。 アリスは常に開始するため、奇数ステップでターミナルに到達するか偶数ステップで到達するかによって、アリスの移動回数がカウントされ、式は次のようになります。`(d + 1) // 2`合計移動数をアリスの移動数に正しく変換します。
