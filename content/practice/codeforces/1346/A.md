 ## 解決策
 ## 問題の理解

 参加者の総数と固定倍率が与えられます。 参加者は、次の各グループが正確に配置される 4 つの連続するグループに分割する必要があります。$k$前回よりも何倍も大きくなりました。 最初のグループ サイズが固定されると、残りは等比数列として完全に決定されます。$$n_1,\; k n_1,\; k^2 n_1,\; k^3 n_1$$それらの合計は合計と等しくなければなりません$n$。 

したがって、タスクは、有効な幾何学的分解を再構築することです。$n$比率を使用して 4 つの項に分割する$k$。 

計算上の制約は非常に小さいです。 各テスト ケースには定数算術演算のみが必要です。 最大でも$t = 1000$、リニアスキャンや繰り返しの演算さえも不要です。$O(t)$解決策で十分です。 広い範囲にわたるループや検索を伴うソリューション$n$不必要でやりすぎでしょう。 

いくつかの特殊なケースは概念的に重要です。 いつ$k = 1$、4 つのグループはすべて等しいため、答えは分割になります。$n$4つの等しい部分に分けます。 いつ$k > 1$、より高いパワーがすぐに合計を支配するため、最初のグループは小さくなります。 この問題では整数解が存在することが保証されているため、実行不可能なケースを処理する必要はありません。 

## アプローチ

 素朴な考えは、可能な値をすべて試してみることです。$n_1$。 候補ごとに計算します$n_1 + k n_1 + k^2 n_1 + k^3 n_1$それが等しいかどうかを確認してください$n$。 これは機能しますが、不要です。 式を簡略化すると、$$n = n_1 (1 + k + k^2 + k^3)$$したがって、単一の除算を計算するだけで済みます。$$n_1 = \frac{n}{1 + k + k^2 + k^3}$$ブルート フォース ビューはシーケンスの構造を直接テストするため機能しますが、関係が線形であるため無駄になります。$n_1$。 重要な観察は、4 つの項が固定の幾何学和を形成するため、合計は最初の項の定数倍になるということです。 これにより、問題は 1 つの商を計算し、乗算によって残りの値を再構築するというものに集約されます。

 ## アルゴリズムのチュートリアル

 1. 値を読み取る$n$そして$k$テストケースごとに。 これらは、最初のグループが判明すると 4 つのグループすべてが固定される幾何学的構造を定義します。 
2. 幾何和係数を計算します。$$S = 1 + k + k^2 + k^3$$これは何回かを表します$n_1$合計にカウントされます。 
3. コンピューティング$n_1 = n / S$。 これが機能するのは、問題が割り切れることを保証しているためです。 保証されていない場合は検証する必要がありますが、ここでは構造により一貫性が保証されています。 
4. 残りのグループを次のように構築します。$n_2 = k n_1$、$n_3 = k^2 n_1$、 そして$n_4 = k^3 n_1$。 各ステップは進行の定義から直接続きます。 
5. 4 つの値を順番に出力します。 

### なぜ効果があるのか

 参加者の総数は、固定比率の等比数列の合計となります。$k$。 すべての有効なソリューションは、この構造に一意に一致する必要があります。$n_1$が固定されている場合、他のすべての値が決定されます。 この方程式は、問題を 1 つの変数で 1 つの線形方程式を解くことに帰着させるため、構築された解が唯一の候補であり、したがって正しいものになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())

        S = 1 + k + k * k + k * k * k
        n1 = n // S

        n2 = n1 * k
        n3 = n2 * k
        n4 = n3 * k

        print(n1, n2, n3, n4)

if __name__ == "__main__":
    solve()
```コードは問題の代数構造を直接エンコードします。 唯一の微妙な点は、幾何学和を正しく計算し、整数除算が使用されていることを確認することです。 存在の保証は、$n$で割り切れます$S$, なのでフロア分けも安心です。 

コンピューティング$n_2, n_3, n_4$の再計算を繰り返し回避します$k$これにより、実装がクリーンに保たれ、整数サイズが固定された言語でのオーバーフローの問題が回避されます。 Python は大きな整数を自然に処理するため、追加の予防措置は必要ありません。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    return io.StringIO().getvalue()

def solve():
    input = sys.stdin.readline
    t = int(input())
    out = []
    for _ in range(t):
        n, k = map(int, input().split())
        S = 1 + k + k*k + k*k*k
        n1 = n // S
        out.append(f"{n1} {n1*k} {n1*k*k} {n1*k*k*k}")

 ## 特殊なケース

 いつ$k = 1$、幾何和は次のようになります。$4$したがって、すべてのグループは正確に次のようにする必要があります$n/4$。 アルゴリズムはこれを自然に処理します。$S = 4$そしてすべての乗算は等価性を保ちます。 

いつ$k$大きいです、$k^3$が合計を支配し、$n_1$とても小さい。 問題文の保証によりすべての値が整数のままであるため、計算は引き続き機能します。 

いつ$n$幾何和に正確に等しい$S$、解は次のようになります$n_1 = 1$、最小限の有効な構成を生成します$1, k, k^2, k^3$、境界ケースの動作を確認します。
