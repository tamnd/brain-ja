 ## 解決策
 ## 問題の理解

 この問題では、長期間続くプログラミング ブート キャンプ中に最大数の講義をスケジュールするように求められます。`n`日々。 毎日が講義が行われる通常日か、講義が行われない遠足日です。 通常の日は、それ以上のスケジュールを設定することはできません`k_1`1 日の講義、または連続する 2 日間の講義の合計がこの上限を超えることはできません。`k_2`。 目標は、これらの制約を尊重しながら、全日にわたって割り当てることができる講義の最大合計数を決定することです。 

入力は複数のテスト ケースで構成されます。 各テスト ケースには、日数、1 日あたりおよび 1 ペアあたりの講義制限、および遠足の日を表すバイナリ文字列が提供されます。 出力はテスト ケースごとに 1 つの整数であり、可能な最大合計レクチャー数です。 

重要な制約は次のとおりです。`n`5000 まで大きくすることができます。`k_1`そして`k_2`最大 200,000 まで可能で、最大 50 のテスト ケースが存在する可能性があります。 これは、アルゴリズムが複雑であることを示唆しています。`O(n^2)`テストケースごとに実行すると、最悪の場合、遅すぎる可能性があります。`5000^2 * 50`オペレーションは10億ドル規模です。 テスト ケースごとに線形または線形演算時間で機能するアプローチが必要です。 

微妙な点は、連続した日々が相互に影響を与えるということです。`k_2`制約。 単純なアプローチでは、次のように割り当てようとする可能性があります。`k_1`講義は遠足のない日には行われますが、これはペアごとの合計制約に違反する可能性があります。 別の特殊なケースは、いくつかの旅行日が連続する場合、または端にある場合に発生します。 アルゴリズムは、そのようなセグメントの講義の蓄積を正しくリセットする必要があります。 

たとえば、`n = 4`、`k_1 = 3`、`k_2 = 4`そして日の文字列は`1101`次に、素朴なアプローチで代入します。`k_1`どこでも収穫できるだろう`[3, 3, 0, 3]`、 しかし`3 + 3 = 6`を超える`k_2 = 4`。 正しい割り当ては`[2, 2, 0, 3]`、合計7が得られます。 

## アプローチ

 強引なアプローチでは、遠足以外の日をすべて繰り返し、考えられる講義回数をすべて試してみます。`0`に`k_1`、連続日数合計制約を確認しながら。 毎日、可能な累積合計と有効な前日のカウントを追跡します。 これは、次の動的プログラミング ソリューションとして実装できます。`dp[i][x]`その日までの講義の最大合計を表します`i`もしその日なら`i`もっている`x`講義。 更新ごとにすべてをチェックする必要があります`x`そして`y`連続したペア。 最悪の場合、`n = 5000`そして`k_1 = 200,000`、このアプローチは実行不可能です。`O(n * k_1^2)`操作。 

重要な洞察は、次のことを観察することによって得られます。`k_2`制約は、近隣と比較して 1 日にどれだけの時間がかかるかの上限として表すことができます。 もし`k_2 >= 2 * k_1`の場合、連続制約は決してバインドされず、単純に割り当てることができます。`k_1`遠足以外の日は毎日。 それ以外の場合は、`k_2 < 2 * k_1`とすると、連続する非遠足日のペアごとに、それぞれに割り当てることができる最大値は次のように制限されます。`floor(k_2 / 2)`。 これにより、ブートキャンプを非遠足日の連続したブロックに分割し、どちらかを割り当てるという問題が軽減されます。`k_1`または`floor(k_2 / 2)`1 日あたり、必要に応じて交互に実行されます。これは、隣人が互いに制約する「フェンスのペイント」問題に似ています。 

この観察により、線形時間の解決策が可能になります。 一連の日をスキャンし、連続する非遠足日のセグメントを特定し、各セグメントに対して、許容される最大値を決して超えないように交互に入力することにより、最大講義数を計算できます。`k_2`任意の連続したペアで。 遠足の日は、交代をリセットする自然な区切りとして機能します。

 | ブルートフォース | O(n * k_1^2) | O(n * k_1) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取ります。 
2. 各テストケースについて、解析します。`n`、`k_1`、`k_2`そして日の文字列。 
3. コンピューティング`max_pair = min(k_1, k_2 // 2)`。 これは、連続日数の制限を考慮した場合に、1 日に安全に割り当てることができるレクチャーの最大数を表します。 
4. 総講義数のカウンタを初期化します。 
5. 日の文字列を左から右にスキャンします。 連続した非遠出日の実行期間を維持します。 
6. エクスカーション日または文字列の終わりに達するたびに、連続する非エクスカーション日の先行セグメントを処理します。 ある長さのセグメントの場合`L`、最大合計講義数は`L * max_pair + (L // 2) * (k_2 - 2 * max_pair)`もし`k_2 < 2 * k_1`、または単に`L * k_1`もし`k_2 >= 2 * k_1`。 
7. 各遠足日にセグメントカウンターをリセットして続行します。 
8. すべてのセグメントを処理した後、蓄積された合計講義を出力します。 

不変条件は、連続する非遠足日のどのセグメントでも、割り当てられた講義が 1 日あたりの制限に違反しないことです。`k_1`および連続日の合計限度額`k_2`。 遠足日は自然にセグメントを分けるため、境界を越えた違反を考慮する必要はありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, k1, k2 = map(int, input().split())
    s = input().strip()
    
    max_pair = min(k1, k2 // 2)
    total = 0
    count = 0
    
    for ch in s + '0':
        if ch == '1':
            count += 1
        else:
            if count > 0:
                # maximum lectures in this segment
                segment_total = count * max_pair + (count // 2) * (k2 - 2 * max_pair)
                total += segment_total
                count = 0
    print(total)
```このソリューションは、毎日 1 回だけスキャンし、連続する非外出日のセグメントを処理します。 追加中`'0'`最後に、最後のセグメントが特別な境界チェックなしで処理されるようにします。 整数除算を使用すると、追加のレクチャーを分割するときに連続日数の制限が確実に尊重されます。
