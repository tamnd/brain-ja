 ## 解決策
 ## 問題の理解

 ゲームの世界は最大 15 の場所からなる有向グラフであり、各場所には固定数のペレットが含まれています。 どの場所からでも他の場所にアクセスできるため、グラフは強く結びついています。 

パックマンは特定のノードから開始され、ノードに到着すると、そこに現在存在するすべてのペレットをすぐに収集します。 世界中のすべてのペレットが収集されると、すべてのノードが元の量に再充填され、プロセスは無期限に継続できます。 私たちが気にする唯一の「コスト」は、通過する有向エッジの数です。 ペレットの収集は無料で、端に沿って移動するだけで困難になります。 

各クエリは、潜在的に多くの補充サイクルにわたる最適な再生を想定して、少なくとも指定された数のペレットを収集するために必要なエッジ トラバーサルの最小数を要求します。 

主な難しさは、プレイヤーがサイクル全体でさまざまな順序でペレットを収集するように動きを構築できることです。完全に収集するたびに世界がリセットされ、以前に収集したノードが再び価値のあるものになることができます。 目標は、単一の最適なルートを見つけることだけではなく、繰り返される「収集サイクル」を効率的に組み合わせて、ペレットの総数を大量に達成することです。 

制約はグラフ サイズに関しては非常に厳しいですが、クエリとターゲット値に関しては大きくなります。 ノードが最大 15 個の場合、n が指数関数的な解は妥当ですが、クエリ数やターゲット C が指数関数になることは不可能です。 これは、最短パスの事前計算と組み合わせたノード上のサブセット DP を強く示唆しています。 

微妙なエッジケースはリセットのメカニズムから生じます。 単純なアプローチで、ペレットがグローバルでノードごとに 1 回しか収集できないと仮定すると、達成可能な合計が過小評価されてしまいます。 たとえば、すべてのノードがサイクル内で 1 回アクセスされると、合計報酬はリセットされ、再度獲得できるため、最適なソリューションはサイクルを何度も繰り返すことがよくあります。 

別の障害モードは、各走査をコレクション状態から独立したものとして扱うことです。 実際には、ノードを訪問する利点は、そのノードが現在のサイクルですでに収集されているかどうかに依存するため、状態は、最後のリセット以降にどのノードが訪問されたかを追跡する必要があります。 

## アプローチ

 ブルートフォース戦略では、グラフ上で可能なすべてのウォークをシミュレートし、最後のリセット以降にどのノードが収集されたか、および蓄積されたペレットの数を追跡します。 ノードが訪問されるたびに、現在のサイクルでまだ収集されていない場合はその値が提供され、すべてのノードが収集されると状態がリセットされます。 これにより、訪問ノードのサブセットと累積合計を組み合わせた位置の状態空間が得られます。 大きなターゲット C を無視しても、すべてのウォークの探索はパスの長さに応じて指数関数的に増加し、サイクルによって探索は無制限になります。 

重要な観察は、n が最大 15 であるため、サイクル内の唯一の意味のある構造は、最後のリセット以降にノードのどのサブセットが訪問されたかであるということです。 サイクル内で同じノードを 2 回訪問しても追加の利点はありません。そのため、各サイクルは、特定のエンドポイントから始まるノードのサブセットの順列に縮小できます。 これにより、問題は移動スタイルのサブセット DP に変わり、固定された開始点から始まり、任意の場所で終了するノードのサブセットを収集する最適な方法が計算されます。 

任意のサブセット S について、1 サイクルで正確に S を収集するための最小走査コストと総報酬を計算できると、グローバル プロセスは一連の独立したサイクルになります。 各完全なサイクルは、すべての a[i] の合計に等しい固定報酬を提供し、部分的なサイクルはサブセット報酬を提供します。 クエリの答えは、繰り返される完全なサイクルと最後の 1 つの部分サイクルの組み合わせになります。

 ## アルゴリズムのチュートリアル

 まず問題を「完全なサイクル」と「部分的なサイクル」に分けます。 

1. Floyd-Warshall を使用してノード間のすべてのペアの最短パスを計算します。 これにより、中間構造に関係なく、任意の 2 つのノード間の最小トラバース コストが得られます。 サブセット DP ではノード間を任意の順序で移動するため、これが必要になります。 
2. サブセットにわたる DP を定義します。ここで、 dp[S][v] は、最初のノード s から開始し、サブセット S 内のすべてのノードを 1 回だけ訪問し (最初に到着したときにペレットを収集します)、ノード v で終了するために必要なエッジ トラバーサルの最小数を表します。 
3. 開始ノードのみを含めて dp を初期化します。 S = {s} の場合、そこから開始してすぐにペレットを収集するため、dp[S][s] = 0 になります。 
4. S にない新しいノード u を 1 つ追加して遷移します。 dp[S ∪ {u}][u] を計算するには、S 内のすべての可能な以前のエンドポイント v を考慮し、事前に計算された最短パス距離を使用して v から u までのパスを延長します。 トランジションによりコスト dp[S][v] + dist[v][u] が追加されます。 
5. S 内のすべての i にわたる a[i] の合計として報酬 [S] を計算します。これは、そのサイクルで収集されたペレットの数です。 
6. ここで、各サブセットの状態を可能な「サイクル」として解釈します。これにより、いくつかのエンドポイント v に対してコスト dp[S][v] で報酬 [S] ペレットを収集する方法が提供されます。サイクルを反復可能にするために、概念的には、最短パスを再び使用して最初に戻ることができますが、分解の場合は完全な完了を個別に扱うだけで十分です。 
7. A をすべての a[i] の合計とします。 完全なサイクルは S = すべてのノードに対応し、報酬 A を与えます。完全なサイクルの最小コストは、返される最良の dp[ALL][v] に dist[v][s] を加えたものです。 
8. クエリ C の場合、それを C = k·A + r に分割します。 各全サイクルは独立して繰り返すことができるため、全サイクルのコストの k 倍を支払います。 
9. 残りの r については、s から始まる部分サイクルが 1 つだけ必要です。 すべてのサブセット S とエンドポイント v を考慮し、reward[S] ≥ r となる最小 dp[S][v] を取得します。 

### なぜ効果があるのか

 重要な不変条件は、最適なウォークはリセット間の最大セグメントに分解できるということです。 同じセグメント内のノードを 2 回訪問してもメリットがないため、各セグメントは、最後のリセット以降に 1 回訪問したノードのサブセットに正確に対応します。 したがって、すべての実現可能な戦略はサブセット サイクルの連結であり、すべてのサブセット サイクルは (S, エンドポイント) によって完全に特徴付けられます。 この分解が強制されると、全体的な最適化は、何回の完全なサイクルを実行するか、およびどの最終サブセット サイクルで残りを完了するかを選択することになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**18

n, m, q, s = map(int, input().split())
s -= 1

a = list(map(int, input().split()))
A = sum(a)

dist = [[INF] * n for _ in range(n)]
for i in range(n):
    dist[i][i] = 0

for _ in range(m):
    v, u = map(int, input().split())
    v -= 1
    u -= 1
    dist[v][u] = 1

for k in range(n):
    for i in range(n):
        for j in range(n):
            if dist[i][k] + dist[k][j] < dist[i][j]:
                dist[i][j] = dist[i][k] + dist[k][j]

size = 1 << n

# dp[mask][v] = min cost starting at s, visiting mask, ending at v
dp = [[INF] * n for _ in range(size)]

dp[1 << s][s] = 0

for mask in range(size):
    if not (mask & (1 << s)):
        continue
    for v in range(n):
        if dp[mask][v] == INF:
            continue
        for u in range(n):
            if mask & (1 << u):
                continue
            nmask = mask | (1 << u)
            nd = dp[mask][v] + dist[v][u]
            if nd < dp[nmask][u]:
                dp[nmask][u] = nd

# full cycle cost
full_mask = (1 << n) - 1
full_cost = INF
for v in range(n):
    if dp[full_mask][v] < INF:
        full_cost = min(full_cost, dp[full_mask][v] + dist[v][s])

# best partial for each reward threshold
best = [INF] * (A + 1)

for mask in range(size):
    reward = 0
    for i in range(n):
        if mask & (1 << i):
            reward += a[i]
    if reward == 0:
        continue
    for v in range(n):
        if dp[mask][v] < INF:
            best[reward] = min(best[reward], dp[mask][v])

# suffix min so best[r] = min cost achieving at least r
for i in range(A - 1, 0, -1):
    best[i] = min(best[i], best[i + 1])

for _ in range(q):
    C = int(input())
    k = C // A
    r = C % A

    ans = k * full_cost
    if r > 0:
        ans += best[r]
    print(ans)
```実装は、ノード間のマルチステップのトラバースを単一のコストとして処理できるように、最短パスを構築することから始まります。 次に、サブセット DP は、開始ノードから開始してノードのセットを収集するすべての方法を構築し、エンドポイントと訪問済みマスクの両方を追跡します。 

フルサイクル計算では、最初に戻ることによってすべてのノードをカバーするサブセットが閉じられ、リセット後のゲームの繰り返し構造がキャプチャされます。 最後に、報酬テーブルはサフィックス最小配列に変換されるため、各クエリは少なくとも残りのペレット要件を達成する最も安価なサブセットを迅速に見つけることができます。 

全サイクルと最後の部分サイクルに分割することで、前処理後に最大 10¹5 までのクエリに一定時間内に応答できるようになります。 

## 実用的な例

 異なるパスにより異なる順序でノードにアクセスできる 3 つのノードを含むサンプル グラフを考えてみましょう。 DP テーブルは、開始ノードから開始してサブセットを徐々に拡張することによって進化し、常に直接エッジではなく最短パス距離を使用して拡張します。 

のようなサブセットの場合`{1,3}`の場合、アルゴリズムは訪問ノードの両方の順序を考慮し、走査コストの観点から安い方を維持します。 グラフには方向性があり、ノード間の最短パスはサブセット内にない中間ノードを通過する可能性があるため、これは不可欠です。 

フルサイクル計算では、すべてのノードが含まれると、DP は可能な限り安価な方法で開始ノードに戻り、事実上サイクルを終了します。 

次に、クエリ処理ステップでは、繰り返された全サイクルを、残りの要件を満たす最終的な部分サブセットと結合します。

 ## 特殊なケース

 最適な戦略が最後のサイクルを除いて部分的なサイクルをまったく必要としない場合、重大なエッジ ケースが発生します。 このような場合、ソリューションでは完全なサイクルの間に部分的なサブセット サイクルをインターリーブしようとしてはなりません。そうすることはリセット構造に違反するためです。 完全なサイクルと 1 つのサフィックス サイクルへの分解により、中間のリセットは必ずすべてのノードの完了を意味するため、このようなことが起こらないことが保証されます。 

もう 1 つのエッジ ケースは、残りの最適なサブセットが最大の報酬サブセットではなく、より安価な中程度のサブセットである場合です。 サフィックスの最小変換は、より大きな報酬サブセットがより小さな報酬サブセットよりも安い場合でも、それがすべての小さなしきい値に対して考慮されることを保証するものです。
