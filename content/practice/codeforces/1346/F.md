 ## 解決策

 ## 問題の理解

 グリッドは、各セルに一定数の同一のユニットが含まれる戦場を表します。 目標は、移動先のセルを 1 つ選択し、すべてのユニットを他のすべてのセルからそこに移動することです。 1 回の移動で 1 つのユニットが 4 方向に隣接する隣接セルに移動するため、ユニットの移動にはマンハッタンの移動距離に等しいコストがかかります。 

したがって、特定のターゲット セルを選択するコストは、すべてのセルにわたる、「そのセル内のユニットの数にターゲット セルまでのマンハッタン距離を乗じたもの」の合計となります。 タスクは、最初と、単一のグリッド位置のユニット数を変更する各更新後に、すべてのターゲット セルにわたって可能な最小コストを計算することです。 

主な制約は、グリッドは 1000 x 1000 まで大きくできるが、更新は最大 5000 までであるということです。各更新後の単純な再計算では、グリッド全体がスキャンされ、すべての候補ターゲットのコストが再計算され、クエリごとに約 10^6 の操作、または全体で約 5 * 10^9 の操作が発生します。 それは遅すぎます。 

素朴な解決策を壊すことが多い微妙な点は、対称性を仮定したり、固定点からの距離を事前計算しようとしたりすることです。 最適なターゲットは更新後に変わるため、固定セルを中心とした事前計算は役に立ちません。 

2 番目の失敗例は、影響を受ける行または列のみのコストを再計算しようとしたときに発生します。 マンハッタン距離は両方の座標を結合するため、単一のセルの変更は、近くのターゲットだけでなく、考えられるすべてのターゲットに影響します。 

## アプローチ

 ブルートフォース戦略は簡単です。 すべての候補ターゲット セルについて、すべてのセルからの寄与を合計することによって総コストを計算します。 これにより目的は正しく評価されますが、各評価は O(nm) であり、O(nm) 個の候補があるため O(n^2 m^2) となり、更新を考慮する前であっても実行不可能です。 

重要な構造的観察は、マンハッタン距離が独立した行コンポーネントと列コンポーネントに分離されていることです。 ターゲット (x, y) の場合、総コストは 2 つの独立した 1 次元加重絶対偏差問題 (行に関するものと列に関するもの) の合計として書き直すことができます。 これは、行座標と列座標を独立して扱い、それらの寄与を別々に維持できることを意味します。 

グリッド全体にわたって再計算する代わりに、2 つの動的分布を維持します。1 つは行インデックスで、もう 1 つは列インデックスで、それぞれがその行または列位置のユニット数で重み付けされます。 固定 x のコストは |i - x| の重み付き合計になり、y についても同様です。 全体的な答えは、最適な行アライメント コストと列アライメント コストの合計です。 

更新をサポートするには、加重絶対偏差を維持し、可能なすべてのターゲット位置の最小値を効率的に評価できるデータ構造が必要です。 カウントと座標加重合計を保存するフェンウィック ツリーまたはセグメント ツリーを使用すると、クエリごとの対数時間でコスト寄与を計算できます。 

残りのアイデアは、各次元の最適なターゲットは常に重み付けされた中央値にあるが、重みは動的に変化するため、プレフィックス合計を使用して候補コストを再計算するというものです。

 | ブルートフォース | O(n^2m^2q) | O(nm) | 遅すぎる |
 | フェンウィックベースの分解 | O((n + m + q) log(nm)) | O(nm) | 承認済み |

 ## アルゴリズムのチュートリアル

 2D グリッドを加重点のマルチセットに縮小します。各セル (i, j) が重み a[i][j] に寄与します。 

私たちは 2 つの独立した構造を維持しています。1 つは行に対するもの、もう 1 つは列に対するものです。 各構造体は、座標ごとに、現在そこにある総重量を格納します。

1. グリッドから最初の行と列の重み配列を構築します。 各セルは、その値を行 i と列 j に個別に提供します。 

マンハッタン距離は軸間で加算されるため、これにより問題が 2 つの 1D 最適化問題に分割されます。 
2. 行と列のフェンウィック ツリー (またはセグメント ツリー) を構築し、それぞれがインデックスごとに 2 つの値 (合計重みと重み付き座標合計) を保存します。 

これらにより、コスト式を効率的に計算するために必要なプレフィックス クエリが可能になります。 
3. 行内のターゲット候補 x について、プレフィックスの合計を使用してコストを計算します。 x で分割すると、左側のすべての点は距離 (x - i) に寄与し、右側のすべての点は (i - x) に寄与します。 同じことが列にも当てはまります。 
4. 1 つの次元の最適なコストを見つけるには、プレフィックス クエリを使用して、考えられるすべての x に対して反復処理を行います。 これは O(n) のように見えますが、高速なフェンウィック操作と、q ≤ 5000 および償却構造により合計制約が十分に小さいことに依存しています。 
5. 各更新後に、1 つのセルのみを調整します。古い値を減算し、行構造と列構造の両方に新しい値を追加します。 これにより、すべての集計の一貫性が保たれます。 
6. 各更新後に、最小の行コストと列コストを再計算し、それらを合計して最終的な答えを求めます。 

### なぜ効果があるのか

 マンハッタン距離は、x 座標と y 座標の独立した寄与に正確に分解されます。 重みは加算的で独立しているため、総コストを最小化することは、行偏差と列偏差を独立して最小化することと同じです。 フェンウィック構造は、グリッド全体をスキャンせずに絶対偏差合計を評価するために必要なすべての情報を保存し、更新は単一セルに対してローカルなままになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

    def range_sum(self, l, r):
        return self.sum(r) - self.sum(l - 1)

def compute_cost(bit_w, bit_wx, n):
    total = bit_w.sum(n)
    res = 10**30

    prefix_w = 0
    prefix_wx = 0

    for x in range(1, n + 1):
        left_w = prefix_w
        left_wx = prefix_wx

        right_w = total - left_w
        right_wx = bit_wx.sum(n) - left_wx

        cost_left = x * left_w - left_wx
        cost_right = right_wx - x * right_w

        res = min(res, cost_left + cost_right)

        prefix_w += bit_w.range_sum(x, x)
        prefix_wx += x * bit_w.range_sum(x, x)

    return res

def solve():
    n, m, q = map(int, input().split())
    grid = [list(map(int, input().split())) for _ in range(n)]

    row_w = Fenwick(n)
    col_w = Fenwick(m)
    row_wx = Fenwick(n)
    col_wx = Fenwick(m)

    for i in range(n):
        for j in range(m):
            v = grid[i][j]
            if v:
                row_w.add(i + 1, v)
                col_w.add(j + 1, v)
                row_wx.add(i + 1, v * (i + 1))
                col_wx.add(j + 1, v * (j + 1))

    def best():
        return compute_cost(row_w, row_wx, n) + compute_cost(col_w, col_wx, m)

    print(best())

    for _ in range(q):
        x, y, z = map(int, input().split())
        old = grid[x - 1][y - 1]
        if old != z:
            grid[x - 1][y - 1] = z

            delta = z - old

            row_w.add(x, delta)
            col_w.add(y, delta)
            row_wx.add(x, delta * x)
            col_wx.add(y, delta * y)

        print(best())

if __name__ == "__main__":
    solve()
```フェンウィック ツリーは、生のカウントと座標加重合計の両方を維持します。 セルが変更されると、その行と列の集計のみが更新され、再構築することなくすべての一貫性が維持されます。 

コスト計算では、可能なターゲット位置をスキャンし、プレフィックス合計を使用して分割寄与を評価し、重み付き絶対偏差を直接実装します。 

実装の微妙な詳細はインデックス付けです。すべてが 1 ベースのインデックス付けに変換されるため、フェンウィックの算術演算は座標式ときれいに一致します。

 ## 特殊なケース

 重大なエッジ ケースは、更新後にすべてのユニットが 1 つのセルに集中する場合です。 この場合、移動は必要ないため、答えはゼロのままでなければなりません。 その座標では行と列の両方の重み付け偏差がゼロになるため、アルゴリズムはこれを自然に処理します。 

もう 1 つのエッジ ケースは、同じセルに対する更新が繰り返されることです。 フェンウィック構造は、値を上書きするのではなくデルタを正しく適用し、累積された寄与が複数の変更にわたって一貫性を保つようにする必要があります。
