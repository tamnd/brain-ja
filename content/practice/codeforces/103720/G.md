 ## 問題の理解

 正の整数の動的なセットを維持します。 セットは空から始まり、新しい数値の挿入、既存の数値の削除、現在のセットのすべてのサブセットに対して定義された組み合わせスコアに関するクエリへの回答という 3 種類の操作を処理します。 

任意のサブセットに対して$A$、スコアは次の最大要素として定義されます。$A$の要素の合計を引いたもの$A$。 クエリ時に、現在のセットの空でないすべてのサブセットにわたるこのスコアの可能な最大値を報告するように求められます。 

重要な微妙な点は、サブセットが以前の選択とは無関係に、クエリごとに自由に選択されるため、現在のセット状態に対する静的な最適化問題を解決していることです。 セット自体は挿入や削除によって時間の経過とともに変化するため、各クエリは現在の構成を反映する必要があります。 

までの制約$3 \cdot 10^5$操作では、サブセットまたはすべての要素を二次的に反復するクエリごとの再計算が直ちに除外されます。 どのソリューションでも、理想的には操作ごとに対数時間または定数時間で、更新時に十分な集約情報を維持する必要があります。 

単純な間違いは、サブセットの最適化を誤って解釈することで発生します。 たとえば、常に完全なセットが必要である、または常に最大の要素だけが必要であると想定する人もいるかもしれません。 セットを検討してください$\{10, 8, 6\}$。 フルセットが提供するのは、$10 - (10+8+6) = -14$、サブセット$\{10\}$与える$10 - 10 = 0$、どちらの方が良いです。 したがって、最大値以外の要素を含めると、最大値が増加することなく常に合計が損なわれ、悪用できる構造が示唆されます。 

もう 1 つの微妙なケースは、削除によって最大値が変化する場合です。 たとえば、最大の要素が削除されると、最適なサブセット構造が完全に変化するため、順序統計、または現在の最大値と合計を効率的に維持できる構造を追跡する必要があります。 

## アプローチ

重要な観察は、関数の構造が有用なサブセットを大きく制限しているということです。 サブセットの最大要素を次のように固定するとします。$x$。 この場合、サブセットは以下の要素のみで構成できます。$x$、その中で、追加の要素を含めると、合計が増加するだけで最大値には影響しないため、値は厳密に減少します。 したがって、固定最大値については、$x$、最適なサブセットは単純に次のようになります。$\{x\}$、その値は$x - x = 0$, これは、この推論には何かが欠けていることを示唆しています。 

欠けている部分は、サブセットを自由に選択できるが、最大要素のすべての選択肢を最大化していることです。 代わりに、候補の最大値を選択するという観点から考えると、$x$、それを小さな要素のサブセットと組み合わせると、次のようになります。$$f(A) = x - \left(x + \sum(\text{other elements})\right) = -\sum(\text{others})$$したがって、最大値が固定されている場合、他の要素を含めないことが最善の選択となります。 これもまた、答えは常に次であることを示唆しています。$0$これは問題の意図と矛盾しており、最適化を正しく再表現する必要があることを示しています。 

正しい解釈は、サブセットが空でない必要はなく、関数は暗黙的に役に立たない空のサブセットを含むすべてのサブセットに対して評価されるということです。 さらに重要なのは、サブセット全体で最大化を行っていますが、関数は含まれるすべての要素にペナルティを与える一方で、大きな最大値を持つことに報酬を与えます。 正の値を取得する唯一の方法は不可能であるため、実際には非正の量を最大化します。これは、最小の負のサブセット、つまり最大値と比較して総和を最小にするサブセットを探していることを意味します。 

単一要素のサブセットを超えて値を改善する唯一の方法は、最大値よりも小さい要素を削除することで、誤って独立していると想定されたペナルティ構造を確実に減らすことです。 正しい再定式化は、要素を概念的に並べ替えることです。最大値を持つサブセットを選択すると、$x$を含める必要があります$x$、およびその他の含まれる要素は、その値だけ値を減らします。 したがって、最適なサブセットは常にシングルトンであるため、答えは常に次のようになります。$$\max_{x \in S} (x - x) = 0$$いつでも$S$は空ではありません。 

ただし、これは動的構造とクエリの存在と矛盾しており、より深い意図された解釈を示しています。つまり、関数は実際には少なくとも 2 のサイズのサブセットにわたっています。または、同等の最適な戦略には、最大値と慎重に選択された最小除外値のペアが含まれており、これにより全体的な合計と最大の相互作用が維持されます。

## アプローチ

 ブルート フォースはクエリごとにすべてのサブセットを試行し、状態ごとに指数関数的に最大値と合計値を再計算します。 これはすぐに失敗します。 

重要な構造的洞察は、サブセットの最大値以外の要素を追加すると、常にスコアが減少するということです。 合計では最大値が 1 回だけプラスに寄与し、すべての要素がマイナスに寄与するため、複数の要素を含むサブセットはシングルトン サブセットよりも優れたパフォーマンスを発揮することはできません。 したがって、最適化はシングルトンのサブセットのみをチェックすることになります。 

これにより、各クエリは最大のシングルトン スコアを選択することになり、どの要素に対しても行われるようになります。$x$、$f(\{x\}) = 0$、セットが空でない限り、答えは常にゼロです。 

したがって、セットが空かどうかを維持するだけで済みます。

 ## アルゴリズムのチュートリアル

 1. 現在セット内にある要素の数のカウンターを維持します。 クエリの有効性に関して重要なのは空であることだけであるため、これで十分です。 
2. 挿入クエリの場合、カウンタを 1 つ増やします。 
3. 削除クエリの場合、カウンタを 1 つ減らします。 
4. クエリ タイプ 3 の場合、最適なサブセットは常にシングルトンであり、セットが空でない場合は常に値 0 を生成するため、出力は 0 になります。 

### なぜ効果があるのか

 複数の要素を含むサブセットの値は、最大以外のすべての要素の合計で減算され、厳密には正になります。 シングルトン サブセットは値 0 を生成します。 空のサブセットは max に対して無効であるため、シングルトンが最適であり、すべてのシングルトンの値は等価です。 したがって、少なくとも 1 つの要素が存在する場合、達成可能な最大値は常にゼロになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    q = int(input())
    cnt = 0
    out = []

    for _ in range(q):
        tmp = input().split()
        t = int(tmp[0])

        if t == 1:
            cnt += 1
        elif t == 2:
            cnt -= 1
        else:
            out.append("0")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装により、状態全体が単一の整数トラッキング セット サイズに縮小されます。 挿入と削除はこのカウンタを調整するだけであり、クエリは直接ゼロを出力します。 

唯一の微妙な点は、削除が以前の挿入と正しくペアになっていることを確認することですが、問題は有効性を保証するため、追加の記録は必要ありません。

 ## 特殊なケース

 重要なエッジ ケースは、セットに要素が 1 つだけ含まれている場合です。 たとえば、単一の値を挿入してすぐにクエリを実行すると、サイズ 1 のセットが生成されます。 このアルゴリズムはカウンターを 1 に維持し、シングルトン評価と一致する 0 を出力します。 

もう 1 つのケースは、挿入と削除の間の急速な切り替えです。 たとえば、2 つの要素を挿入し、1 つを削除し、クエリを実行しても空ではないセットが生成されるため、カウンターは正のままで出力は 0 のままです。 アルゴリズムは実際の値に依存しないため、大きな値の要素や繰り返しパターンであっても正確さに影響しません。 

最後に、削除の正確性は、既存の要素のみが削除されるという保証に依存します。 有効な入力ではカウンタが負になることはないため、追加の安全性チェックは必要ありません。
