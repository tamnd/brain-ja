 ## 解決策
 ## 問題の理解

 私たちは N 番のコテージを管理していますが、最初はすべて空室でした。 時間が経つにつれて、予約リクエストとキャンセルという 2 種類のコマンドを受け取ります。 予約リクエストでは、M 個の連続した無料コテージを割り当てるように求められますが、恣意的ではなく、システムは左から右にスキャンするときに常に可能な限り最も早いブロックを選択する必要があり、その制約内ですべての M 個のコテージを連続して収容できる左端の有効なブロックを優先する必要があります。 各予約は一意のグループ名に関連付けられているため、各グループにどのコテージが割り当てられたかを正確に覚えておく必要があります。 

キャンセル コマンドは、以前に予約したグループを参照し、そのグループに割り当てられていたすべてのコテージを解放します。 キャンセルは有効な時系列構造で行われます。つまり、すでにキャンセルされたものをキャンセルすることはなく、常に予約と一致する順序でキャンセルします。 

予約が完了するたびに、割り当てられたコテージの正確なインデックスを出力する必要があります。 最後に、残りのすべての空きコテージをソート順に出力する必要があります。 

この制約により、最大 10^5 のコテージと 10^5 の操作が許可され、割り当てられたコテージの合計も 10^6 で制限されます。 これにより、クエリごとに配列全体をスキャンするソリューションは即座に除外されます。 予約ごとのリニア スキャンは O(NK) に低下しますが、これは 10^10 の演算のオーダーで大きすぎます。 

主な困難は、十分な長さの左端のセグメントに対する高速クエリと、以前に割り当てられたセグメントの削除をサポートしながら、動的な空きセグメントを維持することです。 

キャンセル後に無料セグメントがマージされる場合、微妙なエッジケースが発生します。 たとえば、コテージ 1 ～ 3 と 5 ～ 7 が空きで、キャンセル後に 4 が空きになる場合、個々の空き位置のみを追跡する単純な構造では、1 ～ 3 と 5 ～ 7 が誤って永久に別個のものとして扱われ、それらが単一の長い間隔 1 ～ 7 にマージされることを見逃してしまう可能性があります。 もう 1 つのエッジ ケースは、複数の予約がセグメント境界を正確に埋めており、キャンセルによって大きな連続ブロックが再作成され、後の予約で再利用する必要がある場合に発生します。 

## アプローチ

 ブルート フォース ソリューションでは、占有を表すサイズ N のブール配列が維持されます。 予約リクエストごとに、1 から N までスキャンし、連続する空きセルをカウントし、長さ M のブロックが見つかったときに停止します。これは問題ステートメントを直接シミュレートしているため、これは正しいです。 ただし、最悪の場合、特に M が小さく、空きセルがまばらな場合、予約ごとにほぼすべての N 位置をスキャンする必要がある可能性があります。 これは O(NK) につながり、10^5 の演算では実行不可能になります。 

この改善は、連続する空きセグメントのクエリと更新を繰り返し行っていることを認識することで得られます。 個々のセルについて推論する代わりに、空き領域の間隔を維持します。 各予約は、十分な長さの最も早いセグメントをインターバルにわたって検索することになり、各キャンセルは隣接する空きインターバルを結合することになります。 

キー構造は、自由範囲を表す、互いに素な間隔の順序付けられたセットです。 予約するときは、一番左の間隔から繰り返し、M を収容できる間隔が見つかるまでその寄与を差し引きます。その後、その間隔を分割します。 キャンセルする場合、新しい間隔を挿入し、隣接する場合は隣接するものとマージします。 

これにより、順序構造操作による間隔管理の問題が軽減され、バランスの取れたツリーまたは順序付きマップを使用してイベントごとの対数時間ですべて達成可能になります。

 ## アルゴリズムのチュートリアル

私たちは自由セグメントのバランスの取れた順序構造を維持し、各セグメントは連続範囲 [l, r] です。 また、キャンセル時にグループ名を復元できるように、グループ名を割り当てられたセグメントにマッピングする辞書も維持します。 

1. 単一の空き間隔 [1, N] を使用してシステムを初期化します。 これは、最初はすべてのコテージが 1 つの連続したブロックで利用可能であることを表します。 
2. サイズ M のグループ名の予約リクエストを処理するために、開始位置の順序で空き区間を左から右にスキャンします。 各間隔 [l, r] について、その長さを計算します。 間隔の長さが M より短い場合は、M からそれを減算し、次の間隔に移動します。 間隔の長さが少なくとも M の場合、この間隔から最初の M 個のコテージを割り当てます。つまり、[l, l+M-1] を取得し、まだスペースが残っている場合は間隔を [l+M, r] に更新します。 

この問題では、可能な限り早いコテージを選択する必要があることが明示されているため、この貪欲な左から右への消費は正しいです。 

1. このグループ名に割り当てられたセグメントを保存します。 一般に、キャンセルにより以前に領域が断片化された場合にのみ、グループが複数の互いに素なセグメントを占有する可能性があるため、グループごとに間隔のリストを保存します。 
2. グループのキャンセルを処理するには、割り当てられているすべてのセグメントを取得し、空きインターバル構造に 1 つずつ再挿入します。 各セグメントを挿入した後、隣接する空きセグメントとのマージを試みます。 セグメントが前または次の間隔に隣接している (つまり、境界に接触している) 場合、それらを 1 つのより大きな間隔にマージします。 

このマージが不可欠なのは、そうしないと構造によって空きスペースが人為的に断片化され、将来の貪欲な割り当てが中断されてしまうためです。 

1. すべてのクエリを処理した後、明示的なコテージ インデックスに展開された残りのすべての空き間隔を出力します。 

### なぜ効果があるのか

 不変条件は、常に自由区間のセットが素であり、自由コテージを完全に正確に表すということです。 すべての割り当てでは、一定の間隔のプレフィックスが削除されるか、きれいに分割され、正確性が維持されます。 すべてのキャンセルでは、以前に占有されていた正確なセグメントが再導入され、隣接するセグメントとマージされるため、人為的な断片化は残りません。 間隔は常にソート順に維持され、重複しないため、左から右にスキャンすることで、常に最も早い実行可能な配置が正確に特定されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n, k = map(int, input().split())
    
    # free intervals stored as sorted list of [l, r]
    import bisect

    starts = [1]
    ends = [n]
    
    # map name -> list of allocated intervals
    alloc = {}

    def merge_at(i):
        # merge interval i with neighbors if adjacent
        nonlocal starts, ends

        # merge left
        if i > 0 and ends[i-1] + 1 >= starts[i]:
            i -= 1

        # merge forward
        while i + 1 < len(starts) and ends[i] + 1 >= starts[i+1]:
            ends[i] = max(ends[i], ends[i+1])
            del starts[i+1]
            del ends[i+1]

        if i > 0 and ends[i-1] + 1 >= starts[i]:
            ends[i-1] = max(ends[i-1], ends[i])
            del starts[i]
            del ends[i]

    def add_interval(l, r):
        nonlocal starts, ends

        # insert by order
        i = bisect.bisect_left(starts, l)
        starts.insert(i, l)
        ends.insert(i, r)
        merge_at(i)

    def take(m):
        nonlocal starts, ends
        res = []
        i = 0
        while m > 0:
            l, r = starts[i], ends[i]
            length = r - l + 1
            if length <= m:
                res.append((l, r))
                m -= length
                del starts[i]
                del ends[i]
            else:
                res.append((l, l + m - 1))
                starts[i] = l + m
                m = 0
        return res

    out = []

    for _ in range(k):
        parts = input().split()
        if parts[0] == "Order":
            name = parts[1]
            m = int(parts[2])
            segs = take(m)
            alloc[name] = segs
            # expand for output
            arr = []
            for l, r in segs:
                arr.extend(range(l, r + 1))
            out.append(" ".join(map(str, arr)))
        else:
            name = parts[1]
            for l, r in alloc.get(name, []):
                add_interval(l, r)
            alloc[name] = []

    # final free cells
    final = []
    for l, r in zip(starts, ends):
        final.extend(range(l, r + 1))

    print("\n".join(out))
    print()
    print(" ".join(map(str, final)))

if __name__ == "__main__":
    main()
```このソリューションは、間隔の開始と終了をソート順に格納する 2 つの並列配列として空きセグメントを維持します。 の`take`関数は、左からの間隔を貪欲に消費し、間隔を完全に削除するか、左側から間隔を縮小します。これは、可能な限り早いコテージを割り当てるという要件に正確に一致します。 の`add_interval`この関数は、解放されたセグメントを再導入し、それらを即座にマージして最大の連続した構造を復元します。 

実装の微妙な点は、キャンセルにより前後の間隔の両方との隣接関係が作成される可能性があるため、挿入のたびにマージを行う必要があることです。 もう一つの微妙な点は、`take`現在の間隔が削除される可能性があるため、インデックス管理は常に最初の要素にとどまる必要があります。

 ## 特殊なケース

 1 つの重要なエッジ ケースは、キャンセルにより、すぐにマージされる必要がある 2 つの間隔が復元されるときに発生します。 空き区間 [1,2] と [4,5] があり、[3,3] を占有しているグループをキャンセルするとします。 正しい動作は、すべてを [1,5] にマージすることです。 [3,3] を挿入すると両方の近隣との隣接関係チェックがトリガーされ、それらが 1 つの間隔に集約されるため、アルゴリズムはこれを処理します。 

もう 1 つのケースは、割り当て中に 1 つの間隔の部分的な消費が繰り返されることです。 間隔が[1,100]で、小さなグループをたくさん割り当てると、左から繰り返し分割されます。 縮小によってソート順序が保持され、ローカル調整を超えた再バランスが必要ないため、構造は有効なままです。 

3 番目のケースでは、予約とキャンセルを交互に行い、大きな連続セグメントを複数回再構築します。 すべての境界は制限された回数だけ作成または削除されるため、間隔が常にマージされるという不変条件により、断片化によるパフォーマンスの低下が保証されます。
