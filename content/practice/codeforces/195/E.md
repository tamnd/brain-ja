 ## 解決策
 ## 問題の理解

 各頂点が最大 1 つの外向きエッジを持ち、各エッジが重みを持つ特別な種類の有向フォレストを構築するように求められます。 頂点は 1 つずつ追加されます。 頂点を追加する場合、オプションで、既存の頂点と番号で構成されるペアのセットが与えられます。 各ペアについて、既存の頂点のルートから新しく追加された頂点まで新しいエッジを作成します。このエッジの重みは、既存の頂点の深さ (頂点からルートまでの累積重み) と指定された数値の合計になります。 ペアが指定されていない場合、新しい頂点はフォレスト内の新しいルートとして単純に追加されます。 

入力では、追加する頂点の数を指定し、その後に追加する各頂点の説明が続きます。 出力はすべてのエッジ重みのモジュロの合計です。$10^9+7$。 

この制約により、ルートや深さを計算するためにパスを繰り返し通過する単純なソリューションでは遅すぎることが明らかです。 と$n$まで$10^5$エッジの総数も最大です$10^5$、エッジごとに線形トラバーサルを実行するアルゴリズムでは、次のような結果が得られます。$O(n^2)$操作は 2 秒以内には実行されません。 

明らかではないエッジ ケースには、接続がゼロの頂点の追加、フォレスト内の複数のルートに接続する頂点、および負の重みが含まれます。 不注意なアプローチでは、すべての重みが正であるか、各頂点が直前の 1 つの頂点に接続していると想定する可能性があり、誤った合計が生成される可能性があります。 たとえば、入力が次の場合:```
3
0
0
2 1 -1 2 -2
```頂点 3 は、負の重みを持つ 1 および 2 のルートからエッジを受け取ります。 重みの正しい合計は次のとおりです。$(-1)+(-2)=-3$ただし、ルートを考慮せずに親から単純に深さを計算すると、0 または間違った正の値が生成される可能性があります。 

## アプローチ

 ブルートフォースアプローチは簡単です。 頂点を追加するたびに、出力エッジのない頂点が見つかるまで親ポインターを繰り返したどることによって、指定された各既存の頂点のルートを見つけます。 次に、そのルートの深さと指定されたウェイトを合計し、エッジを追加します。 これは概念的には機能しますが、各ルート検索操作には最大で$O(n)$、最悪の場合の時間が複雑になります$O(n^2)$。 これは明らかに上限では実行不可能です。 

最適化のための重要な洞察は、フォレスト構造により、パス圧縮を備えた素セット (結合検索) データ構造を使用して、頂点のルートを迅速に見つけることができるということです。 また、各頂点の深さの配列も維持し、頂点からルートまでの累積重みを表します。 前の頂点のルートから新しい頂点にエッジを追加する場合、そのルートに対する新しい頂点の深さは、既存のルートの深さに指定された重みを加えたものになります。 これにより、各ルート ルックアップがほぼ一定の時間に短縮され、全体の複雑さが軽減されます。$O(n \alpha(n))$、これは実際の目的では事実上線形です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | 深さの結合検索 | O(n α(n)) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 親配列を初期化する`parent[i]`ここで、各頂点は最初にそれ自体を指し、各頂点がそれ自体のルートであることを表します。 深さ配列を初期化する`depth[i]`変数を0に初期化します。`total_weight`0にします。 
2. を定義します。`find_root(v)`パス圧縮を使用した関数。 頂点の根元を求める場合`v`、再帰的に走査します`parent[v]`それ自体の親である頂点に到達するまで。 帰りに更新`parent[v]`ルートを直接指すようにします。 これにより、後続のルート クエリがほぼ一定の時間になることが保証されます。 
3. 頂点を順番に処理します。 頂点の場合`i`と`k`ペア`(vj, xj)`:

 ａ． 各ペアについて、次を見つけます。`root_v = find_root(vj)`。 

b. 新しいエッジの重みを次のように計算します。`depth[root_v] + xj`。 

c. この重みを加えると、`total_weight`モジュロ$10^9+7$。 

d. セット`parent[root_v] = i`コンポーネントをマージし、不変条件を維持します。`i`は、後続の操作の新しいルートになります。 

e. セット`depth[i] = weight`、からの累積深さを表します。`i`新しいルート (それ自体) に。 
4. すべての頂点を処理した後、印刷します。`total_weight % 10^9+7`。 

機能する理由: すべてのステップで、深度配列は頂点からルートまでの累積重みを正確に表し、union-find を使用すると、ツリーを繰り返し走査することなく効率的にルートを見つけることができます。 各頂点は順番に追加されるため、サイクルのリスクはなく、パス圧縮により操作がほぼ一定の時間に保たれます。 これにより、重みの合計が正しいことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
MOD = 10**9 + 7

sys.setrecursionlimit(1 << 25)

def main():
    n = int(input())
    parent = list(range(n + 1))
    depth = [0] * (n + 1)
    total_weight = 0

    def find_root(v):
        if parent[v] != v:
            orig_parent = parent[v]
            parent[v] = find_root(parent[v])
            depth[v] += depth[orig_parent]
        return parent[v]

    for i in range(1, n + 1):
        line = list(map(int, input().split()))
        k = line[0]
        total = 0
        if k == 0:
            continue
        for j in range(k):
            vj = line[1 + 2*j]
            xj = line[2 + 2*j]
            root_v = find_root(vj)
            weight = (depth[root_v] + xj) % MOD
            total_weight = (total_weight + weight) % MOD
            parent[root_v] = i
            depth[root_v] = weight

    print(total_weight % MOD)

if __name__ == "__main__":
    main()
```このソリューションでは、union-find を深さで初期化し、各頂点を順番に処理します。 各エッジについて、既存の頂点の現在のルートを見つけ、深さを含むエッジの重みを計算し、合計を更新して、深さを更新しながら古いルートを新しい頂点に接続します。 オーバーフローを避けるために、加算のたびにモジュラー演算が適用されます。
