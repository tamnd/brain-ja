 ## 解決策
 ## 問題の理解

 私たちは、番号の付いたサッカーボールを特定の順序に従ってバスケットの列に分配するプロセスをシミュレートするように求められます。 新しいボールはそれぞれ、現在最も少ないボールが入っているバスケットに入らなければなりません。 複数のバスケットが最小のボールで同点の場合は、列の中心に最も近いバスケットを選択します。 それでも同点の場合は、インデックスが小さいバスケットを選択します。 

入力により、ボールの総数という 2 つの整数が得られます。`n`バスケットの総数`m`。 出力は長さのシーケンスです`n`、ここで、`i`-番目の数字はボールを受けるバスケットのインデックスです`i`。 新しいボールはそれぞれ現在のバスケットの構成に依存するため、シーケンスはボールが追加された順序で計算する必要があります。 

制約は重要です。 両方`n`そして`m`最大 100,000 まで可能です。 すべてのボールをすべてのバスケットでスキャンする単純なアプローチでは、`n*m`操作は最悪の場合 10^10 に達する可能性があり、2 秒で実行するには大きすぎます。 これは、フル スキャンを回避し、選択ルールの予測可能な構造を活用する戦略が必要であることを意味します。 

ボールの数がバスケットの数よりも少ない場合、微妙なエッジケースが発生します。 たとえば、次の場合`n = 2`そして`m = 5`、最初のボールは中央のバスケットに入るはずです (`3`) そして 2 番目のボールは、次に中心に近いバスケットに移動する必要があります (`2`または`4`）。 すべてのバスケットが常に少なくとも 1 回は満たされると想定する不注意な実装は、このような希なケースでは失敗します。 

## アプローチ

 ブルートフォースの解決策は簡単です。 長さの配列を維持できます`m`各バスケット内のボールの数を表します。 各ボールについて、配列をスキャンして最小カウントのバスケットを見つけ、次に中心までの距離によって、次にインデックスによって同点を破ります。 このアプローチは正しく機能しますが、次のことが必要です。`O(n * m)`これは、大きな入力に対しては現実的ではありません。 のために`n = m = 10^5`、それには約 100 億回の操作が含まれることになります。 

重要な洞察は、選択基準によって非常に構造化されたシーケンスが生成されるということです。 最初のボールは常に中央のバスケットに送られます。 2 番目のボールはセンターのすぐ隣にある 2 つのバスケットのうちの 1 つに送られます。 3球目はセンターの向こう側へ。 このジグザグ パターンを続けると、いつでも次のボールを空か、ボールの数が最も少なく、中心に最も近いバスケットに入れることが保証されます。 配置順序は正確なボール番号には依存せず、バスケットのパターンのみに依存するため、バスケットの順序を事前に計算できます。`O(m)`時間を指定し、それを繰り返し反復してすべてを割り当てます。`n`ボール。 

これにより、複雑さが軽減されます。`O(n)`小さなもので`O(m)`前処理ステップ。これは、指定された制約に対して十分に高速です。

 ## アルゴリズムのチュートリアル

 1. バスケットの列の中心を次のように計算します。`(m + 1) // 2`。 これは、問題定義によれば、中央に最も近いバスケットです。 
2. 中心から始まり、左右に交互に外側に広がる一連のバスケット インデックスを生成します。 これは、ルールに従って一度に 1 つのボールを入れる場合に、ボールを受け取るバスケットの正確な順序を示します。 パターンは、center、center-1、center+1、center-2、center+2 などです。 
3. ボールの割り当て結果を保存する配列を初期化します。 
4. 1 から 1 までのすべてのボールを繰り返します。`n`。 事前計算されたシーケンス内の次のバスケットに各ボールを割り当てます。 シーケンスの最後に到達した場合 (次の場合に発生します)`n > m`)、各バスケットには複数のボールが入っているため、シーケンスを繰り返します。 
5. 各ボールのバスケット インデックスを、割り当てられた順序で印刷します。 

これが機能する理由: ここでの不変条件は、事前計算されたシーケンスが常に最小のボール数を持ち、中心に最も近いバスケットを選択するということです。 このシーケンスを繰り返すことで、ヴァレリックのスキームを正確に複製します。 すべてのバスケットが正しい順序で再検討されるため、タイは自動的に処理され、最小インデックスのタイ ブレーカーも、中心付近で左から右へシーケンスを生成することによって自然に満たされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())

center = (m + 1) // 2
order = [center]

# expand left and right alternately
for d in range(1, m):
    if center - d >= 1:
        order.append(center - d)
    if center + d <= m:
        order.append(center + d)

# assign balls
res = []
for i in range(n):
    res.append(str(order[i % m]))

print("\n".join(res))
```コードは最初に中央のバスケットを計算し、次に外側に拡張する事前計算されたバスケット シーケンスを構築します。 ループ`for i in range(n)`各ボールを順番に割り当て、ボールの数がバスケットの数を超えるとシーケンスが循環されます。 包括的チェックを使用することでオフバイワンエラーを回避`>= 1`そして`<= m`。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 順序の事前計算には O(m) かかり、n 個のボールの割り当てには O(n) かかります。 
| スペース | O(m) | 事前に計算されたバスケット シーケンスを保存します。 

与えられた`n, m <= 10^5`、アルゴリズムは、シーケンスを構築するために最大 200,000 の操作と 100,000 の割り当てを実行しますが、これは 2 秒の時間制限と 256 MB のメモリ制限内に十分収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, m = map(int, input().split())
    center = (m + 1) // 2
    order = [center]
    for d in range(1, m):
        if center - d >= 1:
            order.append(center - d)
        if center + d <= m:
            order.append(center + d)
    res = []
    for i in range(n):
        res.append(str(order[i % m]))
    return "\n".join(res)

# provided samples
assert run("4 3\n") == "2\n1\n3\n2", "sample 1"

# custom tests
assert run("1 1\n") == "1", "single ball, single basket"
assert run("2 5\n") == "3\n2", "fewer balls than baskets"
assert run("7 5\n") == "3\n2\n4\n1\n5\n3\n2", "more balls than baskets"
assert run("5 5\n") == "3\n2\n4\n1\n5", "balls equal baskets"
assert run("10 2\n") == "1\n2\n1\n2\n1\n2\n1\n2\n1\n2", "two baskets repeated"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1 1`|`1`| 最小入力 |
 |`2 5`|`3\n2`| バスケットよりもボールの数が少ない |
 |`7 5`|`3\n2\n4\n1\n5\n3\n2`| バスケットよりもボールの方が多い、サイクリングのシーケンス |

 ## 特殊なケース

 いつ`n < m`、 のような`n = 2, m = 5`、アルゴリズムは最初のボールを中心に割り当てます (`3`) と次に近いバスケットから 2 番目 (`2`）。 残りのバスケットは、到達するのに十分なボールがないため無視されます。 事前に計算されたシーケンスにより、最小数のボールの同点が中心に近づくと自動的に破られ、順序が自動的にインデックスされます。 これにより、単純な実装における微妙なバグの一般的な原因である手動の最小カウント スキャンが回避されます。
