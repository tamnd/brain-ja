 ## 解決策
 ## 問題の理解

 各テスト ケースは、空飛ぶ自動車に必要な 3 つのコンポーネント (エンジン、ハンドル、スペア タイヤ) を購入する単一の店舗を選択するというフアンの試みを説明しています。 どの店舗も 3 つのアイテムをすべて提供していますが、店舗ごとに価格が異なります。 フアンは店舗間で混合して購入することはできないため、店舗を選択した場合は、そこで 3 つのアイテムすべてを購入する必要があります。 

タスクは、テスト ケースごとに、3 つの価格を合計したときにどのストアの総コストが最小になるかを計算することです。 店舗は入力に表示される順序で考慮され、複数の店舗が同じ最小総コストを達成する場合は、最も早い店舗を選択する必要があります。 

この制約は十分に大きいため、ソリューションはすべてのテスト ケースにわたって合計で最大 1,000 万のストアを処理する必要があります。 これにより、n が繰り返し 100 万に達すると、O(n log n) でも遅すぎるため、テスト ケースごとの線形時間よりも悪いアプローチは直ちに除外されます。 唯一の実行可能な方向は、ストアごとの合計を一定時間で計算し、実行最小値を維持することです。 

この定式化では、いくつかの微妙な特殊なケースが自然に現れます。 1 つは、すべての店舗の総コストが同じである場合です。 その状況では、答えは最後の出現ではなくストア 1 でなければなりません。これは、タイの処理が最初に確認された最小値に偏らなければならないことを意味します。 もう 1 つは、リストの後半で最小値が複数回出現する場合です。 「現在の合計が以下の場合に更新する」などの不注意な更新ルールは、最初の最小値ではなく最後の最小値に誤ってドリフトする可能性があります。 

## アプローチ

 問題を解決する直接的な方法は、すべての店舗の総コストを計算し、それらの値を配列に格納し、最小値をスキャンすることです。 これは正しいです。なぜなら、各店舗は独立しており、合計コストは単純に 3 つの価格の合計になるからです。 ただし、最初にすべての値を保存すると、この単純なアイデアでも実装が非効率になる可能性があり、追加のメモリと複数のパスが必要になります。 

各ストアでは 3 つの加算のみが必要なため、ボトルネックとなるのはストアごとの計算ではなく、大きな入力の保存と再処理のオーバーヘッドです。 全体で最大 1,000 万のストアがあるため、保存されたデータを 2 回目に通過するだけでも、キャッシュの効率が低下し、メモリが圧迫される危険があります。 

重要な観察は、すべての店舗を記憶する必要はないということです。 必要なのは、現在の最良のストア インデックスとそのコストだけです。 各ストアを調査する際に、その合計コストを計算し、これまでに確認された最良のストアとすぐに比較します。 これにより、問題は単一のストリーミング パスに軽減されます。 

これが機能するのは、ストアの決定が将来の価値に依存しないためです。 最小値は段階的に維持できます。どの時点でも、現在のストアが既知の最良の答えを改善するかどうかのみを気にします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (すべての合計を保存してからスキャン) | テスト ケースあたり O(n) | O(n) | 遅すぎる/不要なメモリ |
 | ストリーミングの最小値 | テスト ケースあたり O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、ストア数 n を読み取ります。 これは、実行する独立した比較の数を定義します。 
2. 2 つの変数を初期化します。best_cost を無限大、best_index を 1 に初期化します。ストアの番号付けは 1 から始まり、最初のストアがデフォルトの候補であるため、インデックスは 1 から始まります。 
3. i = 1 から n までストアを繰り返します。 店舗ごとに 3 つの価格を読み取り、その合計を計算します。 この合計は、そのストアを選択するための総コストを表します。 
4. 計算された合計を best_cost と比較します。 現在の合計が厳密に小さい場合は、best_cost をこの合計に更新し、best_index を i に更新します。 同点の場合に最も古いインデックスを保持するため、厳密な不等式が不可欠です。 
5. テストケース内のすべてのストアを処理した後、best_index を出力します。

正確さは、i 番目のストアを処理した後、best_cost と best_index が最初の i ストアの最小合計コストに対応し、best_index がその最小値に達する最も早い位置であるという不変条件を維持することに依存します。 各ステップで新しい候補が 1 つだけ導入され、過去のストアを再訪問することはないため、この不変条件はスキャン全体にわたって保持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    
    for _ in range(t):
        n = int(input())
        
        best_cost = 10**30
        best_idx = 1
        
        for i in range(1, n + 1):
            a, b, c = map(int, input().split())
            total = a + b + c
            
            if total < best_cost:
                best_cost = total
                best_idx = i
        
        out.append(str(best_idx))
    
    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```このソリューションは各ストアを 1 回だけ読み取り、そのコストを即座に評価します。 厳密な比較を使用することで、同順位が以前の最適なインデックスを上書きすることがなくなります。 出力をリストに蓄積し、最後に 1 回書き込むと、繰り返しの I/O オーバーヘッドが回避されますが、これは入力サイズが大きい場合に重要になります。

 ## 特殊なケース

 主なエッジケースは、複数の店舗が同じ最小総コストを共有する場合です。 例えば：```
1
3
2 2 2
1 3 3
4 1 2
```すべての合計は 6 です。アルゴリズムは最初のストアで best_cost を初期化し、厳密に小さい値のみを更新します。 最初のストアでは、best_cost は 6 になり、best_idx は 1 になります。2 番目と 3 番目のストアでも 6 が生成されますが、6 は 6 未満ではないため、更新は行われません。 出力は 1 のままで、必要なタイブレーク ルールに一致します。 

もう 1 つのエッジ ケースは、最適なストアが最初のストアであり、後からそれを改善するストアがない場合です。 不変式により、不必要な更新が発生しないことが保証され、アルゴリズムは特別なケースを使用せずに自然に 1 を返します。
