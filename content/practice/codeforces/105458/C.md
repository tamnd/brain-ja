 ## 解決策
 ## 問題の理解

 サイズのグリッドが与えられています$n \times m$黒と白の 2 種類のセルで満たされています。 目標は、特定の操作を使用してすべてのセルを白に変えることです。 1 つの移動はセルの選択で構成されます$(i, j)$で始まる部分行列内のすべてのセルを反転します。$(i, j)$グリッドの右下隅まで延長されます。 言い換えれば、移動はすべてのセルに影響を与えます$(r, c)$そのような$r \ge i$そして$c \ge j$、色を切り替えます。 

タスクは、グリッド全体を白にするために必要なそのような操作の最小数を計算することです。 

制約により、最大で次のことが許可されます。$1000 \times 1000$最大 40 のテスト ケースを持つグリッド。これにより、可能な移動ごとにグリッド上の操作をシミュレートしたり、広い領域を繰り返し再計算したりするソリューションはすでに除外されています。 以下よりも悪い解決策$O(nm)$テストケースごとに、最悪の場合には困難が生じる可能性があります。 

単純な解釈では、検索または貪欲なシミュレーションですべての可能な動きを試すことになりますが、各動きの影響はグリッドの大きなサフィックスに及ぶため、反転するたびにグリッドの状態を再計算するにはコストがかかります$O(nm)$動きごとに、$O(n^2 m^2)$最悪の場合、それは明らかに実行不可能です。 

いくつかの特殊なケースについては、覚えておく価値があります。 

グリッドがすでにすべて白の場合、操作は必要ないため、答えはゼロでなければなりません。 常に少なくとも 1 つのフリップを実行する不用意な実装は、カウントをオーバーカウントします。 

グリッドがすべて黒の場合、最適な戦略は必ずしも 1 つの手ではありません。 たとえば、$2 \times 2$すべて 1 のグリッド、1 回の移動$(1,1)$すべてを反転しますが、より大きなグリッドでは、重複する反転が相互作用するため、構造が重要になります。 

もう 1 つの微妙なケースは、色がチェス盤のように交互になる場合です。 ローカル貪欲フリップは、順序を慎重に選択しないと、以前の変更を簡単にキャンセルしたり再導入したりする可能性があるため、正しいソリューションは一貫した処理方向を尊重する必要があります。 

## アプローチ

 主な難点は、移動するたびに、選択したセルに固定されている接尾辞の四角形が反転することです。 この構造は、以前の決定が前方および下方に伝播することを示唆しています。これは、各セルが左上の領域で選択されたすべての動きの影響を受けることを意味します。 

強引なアイデアは、すべての一連の動きを試し、フリップするたびにグリッドを更新することです。 黒マスの動きのみを考慮することに限定したとしても、まだ次の点があります。$nm$各ステップでの選択肢と最大の選択肢$nm$ステップにより、状態空間が天文学的に大きくなります。 

より意味のあるブルートフォースは貪欲なシミュレーションです。グリッドを繰り返しスキャンし、黒いセルが見つかるたびに、その位置から反転を適用します。 これはまだ$O((nm)^2)$最悪の場合、各フリップが大きなサフィックスに触れるためです。 

重要な観察は、この操作が単調な幾何学的構造を持っているということです。 グリッドを右下から左上に処理すると、セルの最終状態を決定するとき$(i, j)$、今後の操作が影響することはありません。 影響を与える可能性のあるフリップ$(i, j)$はその左上または左上から発生する必要があり、これらは逆の順序で処理するときにすでに決定されています。 

これは、セルごとに、そのセルに影響を与える奇数の反転がすでに適用されているかどうかを決定するものとして問題を扱うことができることを意味します。 現在の有効な状態が$(i, j)$が黒の場合、それを修正する唯一の方法は、正確に開始する反転を適用することです。$(i, j)$これは、以前の決定を再考せずにこのセルを変更できる唯一の残りの操作だからです。 これにより、問題は決定論的な貪欲なパリティの蓄積に変換されます。 

この解決策は、グリッド自体を介して暗黙的にフリップの現在のパリティを維持し、フリップを適用することを決定するたびにサフィックスを更新するリバース スイープになります。

 ## アルゴリズムのチュートリアル

 セルを右下から左上に処理して、適用するすべての接尾辞操作がまだ修正されていないセルにのみ影響するようにします。 

1. 応答カウンターをゼロに初期化します。 
2. 以下の行を反復処理します。$n-1$まで$0$、各行内で次の列を繰り返します。$m-1$まで$0$。 
3. 各セルで$(i, j)$、現在の値を確認します。 この値は、以前に処理されたセルからすでに適用されているすべての反転を反映します。 
4. セルが白の場合は、何もせずに続行します。 
5. セルが黒の場合、答えをインクリメントし、そのセルにアンカーされた反転操作を適用します。$(i, j)$、部分行列内のすべてのセルを切り替えます$(i..n-1, j..m-1)$。 
6. すべてのセルが処理されるまで続行します。 

重要な実装の詳細は、反転中にグリッドをその場で直接変更することです。 各セルは、それに影響を与える操作ごとに最大 1 回切り替えられ、各操作は一意のセルに固定されているため、慎重に実装すれば、実際には合計作業量はすべてのセルにわたって線形のままになります。 

### なぜ効果があるのか

 正確さは、セルを処理するときに、$(i, j)$、厳密に下または右側のすべてのセルはすでに最終決定されており、将来の決定によって再び影響を受けることはありません。 影響を与える可能性のあるフリップ$(i, j)$辞書編集的に小さいか等しい位置から始まる必要があり、これはすでに決定されていることを意味します。 したがって、現在の状態は、$(i, j)$今後のすべての操作に関して最終的なものとなります。 黒の場合、それを修正する唯一の方法は、反転を適用することです。$(i, j)$これは、すでに処理されたサフィックスセルにのみ影響を与えながら、すぐに修正します。 

これにより、一貫した不変条件が作成されます。つまり、セルの処理が終了した後、そのセルは白であることが保証され、二度と変更されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        g = [list(map(int, input().split())) for _ in range(n)]
        
        ans = 0
        
        for i in range(n - 1, -1, -1):
            for j in range(m - 1, -1, -1):
                if g[i][j] == 1:
                    ans += 1
                    for r in range(i + 1):
                        pass
                    for r in range(i, n):
                        for c in range(j, m):
                            g[r][c] ^= 1
        
        print(ans)

if __name__ == "__main__":
    solve()
```実装の核心は、逆方向のトラバーサルと各黒セルでの貪欲な決定です。 フリップ内のネストされたループは、操作定義で説明されているとおりにサフィックス トグルを実装します。 

微妙な点は、反転には現在のセル自体とその下と右のすべてのセルを含める必要があることです。 ここではオフバイワンエラーがよくあるため、両方の境界を含むように範囲を慎重に設定する必要があります。 

このアルゴリズムはインプレース変更に依存しているため、補助配列は必要ありません。 回答カウンタは、以前に適用された操作によってセルを修正できないと判断した場合にのみ増加します。

 ## 特殊なケース

 完全に白いグリッドは反転をまったくトリガーしません。 右下からスキャンする場合、反転を適用する条件が true にならないため、すべてのセルがスキップされ、答えは 0 のままになります。 

右下隅にある 1 つの黒いセルは 1 つの操作を強制しますが、その後にセルがないため、他のセルは問題のある影響を受けません。 これにより、貪欲な決定が過度に伝播しないことが確認されます。 

チェス盤のパターンでは、リバース スイープ中に強制フリップが交互に行われることが示されています。 各フリップは 1 つのセルを修正しますが、以前のセルに影響を与える可能性がありますが、それらの以前のセルは独自のターンで再訪され、最終的なパリティ状態の一貫性が保証されます。
