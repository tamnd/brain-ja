 ## 解決策
 ## 問題の理解

 いくつかの独立したタイピングセッションが与えられます。 各セッションで、オーク教授は、固定キーボード上で非常に特殊な 2 本指タイピング モデルを使用して長いテキストを作成します。 スペースと改行を除く、印刷可能な各文字はキーボード グリッド上に配置され、隣接するキー間で指を移動するたびに 1 秒かかります。 2 本の指は固定位置から始まり、1 つは F キー、もう 1 つは J キーに配置されます。 キーを押すのに指が上にある限り時間はかからず、スペースや改行もキーボードなしで処理されるため自由です。 

このタスクは、両方の指を 1 秒間に同時に動かす能力など、両方の指が最適に調整されていると仮定して、テキスト全体を作成するのに必要な最小時間を計算することです。 

この問題の構造は基本的に、状態が 2 本の指の位置によって決定される状態空間上の最短経路問題です。 テキスト内の各文字は、入力する前に指の 1 本をその位置に移動する必要がある場合があり、全体の動きを最小限に抑えながら各ステップでどの指を使用するかを決定することが課題となります。 

この制約は、テキストの長さがテストごとに約 1000 文字に達する可能性があり、テスト ケースが最大 10 個あることを意味します。 指へのすべての文字の割り当てを考慮する単純なシミュレーションでは、各文字をどちらかの指に割り当てることができるため、指数関数的に複雑になり、結果として 2^n 通りの可能性が生じます。 フルキーボード状態で両方の指の位置を明示的に追跡する動的プログラミング ソリューションであっても、慎重に構造化されていない場合は大きすぎますが、ここではキーボードが固定されており小さいため、キー間の距離は事前計算可能です。 

頻繁に繰り返される文字や交互する文字からは、微妙な特殊なケースが発生します。 たとえば、「A A A A ...」のようなシーケンスは、将来の位置を考慮せずに常に最も近い指を使用するという貪欲なアプローチを誘惑する可能性がありますが、これは失敗する可能性があります。 もう 1 つの注意が必要なケースは、両方の指がターゲットに到達できるが、どちらかの指を選択すると、その後の動きが大幅に増加する場合です。 たとえば、1 つの指がすでに今後のキャラクターのクラスターの近くにある場合、その指に少し離れた現在のキャラクターを割り当てると、後で総コストが削減される可能性があります。 

重要な問題は、最適な決定が現在のキャラクターだけでなく、指の位置と将来の使用パターンの両方にも依存することです。 

## アプローチ

 ブルート フォース ソリューションは、(i, a, b) で定義される状態にわたる最短パス検索としてプロセスをモデル化します。ここで、i はテキスト内の位置、a、b は左右の指の現在のキーボード位置です。 各状態から、次の文字を左指または右指のどちらで入力するかを決定し、その指を必要なキーに移動し、マンハッタンまたはグラフの距離コストを支払います。 

これは、文字を指に割り当てる有効な方法をすべて明示的に検討しているため、これは正しいです。 ただし、状態の数は O(n · K²) です。ここで、K はキーボードのキーの数です。 状態ごとの遷移は一定ですが、複数の位置で繰り返される状態と組み合わせると、メモリと時間が大幅に増加します。 実際の非効率性は、位置全体で構造を効率的にキャッシュせずに両方の指を対称的に処理することから生じます。 

重要な点は、キーボードが固定されており小さいため、任意の 2 つのキー間の距離を 1 回で事前計算できることです。 次に、問題はテキストの位置と指の位置に関する動的プログラミングに帰着します。 各状態遷移は前の文字と選択した指にのみ依存するため、状態をメモ化するか、DP テーブルを繰り返し更新することで、冗長な計算を減らすことができます。

効果的な解決策は、位置 a と b で指を使ってテキストのプレフィックスを処理した後の最小コストを dp[a][b] で表す DP です。 各キャラクターは両方の指の選択を試すことでこのテーブルを更新します。 これにより、問題が指数関数的分岐から小さな固定状態空間にわたる多項式遷移に軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 割り当てに対するブルート フォース検索 | O(2^n · n) | O(n) | 遅すぎる |
 | 指の位置上の DP | O(n · K²) | O(K²) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各キーボード文字からそのグリッド座標へのマッピングを構築します。 これにより、グリッド上の最短パスを使用して任意の 2 つのキー間の距離を計算できます。 これが必要な理由は、移動コストがテキスト自体ではなくジオメトリのみに依存するためです。 
2. すべてのキーのペア間の距離を事前計算します。 これにより、繰り返されるパスファインディングが一定時間のルックアップに変わります。 このステップにより、DP 遷移中の最短パスの再計算が防止されます。 
3. 最初の文字の DP テーブルを初期化します。 初期状態では 1 本の指が F に、もう 1 本の指が J に配置されるため、コストがゼロの単一の状態から開始します。 
4. テキスト内の各文字について、考えられるすべての以前の指の位置を考慮して DP テーブルを更新します。 各状態 (a、b) について、2 つの遷移を計算します。つまり、現在のキャラクターを左の指または右の指に割り当てます。 
5. 指に割り当てるときは、その指の現在位置からターゲット キャラクターの位置に、事前に計算された距離を加算します。 もう一方の指は変化しません。 両方の指が独立して動くことができるため、これは最適な動きをモデル化します。 
6. すべての文字を処理した後、すべての最終的な指の位置の最小値を取得します。 これは、最終的な手の位置の可能な限り最良の配置を表します。 

### なぜ効果があるのか

 DP 状態は、関連するすべての履歴を完全にキャプチャします。将来の決定において重要となるのは、2 本の指の現在の位置のみです。 同じ指の位置で終わる 2 つの異なる履歴は同等です。将来のコストは、指がどのようにそこに到達したかではなく、指がどこにあるかによってのみ決まるからです。 この最適な部分構造により、最適なプレフィックスを拡張することで最適な完全なソリューションが得られることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

# keyboard layout (standard CF version)
layout = [
    "qwertyuiop",
    "asdfghjkl;",
    "zxcvbnm,./"
]

pos = {}
for i in range(3):
    for j, c in enumerate(layout[i]):
        pos[c] = (i, j)

# precompute distances
keys = list(pos.keys())
dist = {}
for a in keys:
    dist[a] = {}
    x1, y1 = pos[a]
    for b in keys:
        x2, y2 = pos[b]
        dist[a][b] = abs(x1 - x2) + abs(y1 - y2)

def solve_case(s):
    INF = 10**18
    # initial finger positions
    left = 'f'
    right = 'j'
    
    # dp over current positions
    dp = { (left, right): 0 }

    for ch in s:
        if ch in " \n":
            continue
        
        ndp = {}
        for (a, b), cost in dp.items():
            # use left finger
            na, nb = ch, b
            nc = cost + dist[a][ch]
            if (na, nb) not in ndp or nc < ndp[(na, nb)]:
                ndp[(na, nb)] = nc

            # use right finger
            na, nb = a, ch
            nc = cost + dist[b][ch]
            if (na, nb) not in ndp or nc < ndp[(na, nb)]:
                ndp[(na, nb)] = nc

        dp = ndp

    return min(dp.values()) if dp else 0

def main():
    t = int(input())
    out = []
    for _ in range(t):
        s = ""
        while True:
            line = input()
            s += line
            if "-" in line:
                break
        s = s.replace("-", "")
        out.append(str(solve_case(s)))
    print("\n".join(out))

if __name__ == "__main__":
    main()
```この実装では、最初にキーボードを座標としてエンコードして、すべての文字をグリッド セルにマップします。 距離テーブルには、キー間の最小移動ステップに対応するマンハッタン距離が格納されます。 

DP ディクショナリには、各プレフィックスの処理後に到達可能なフィンガー構成のみが保存されます。 各更新ステップでは、次のキャラクタに対して可能な両方の指の割り当てを試して、現在の状態をすべて拡張します。 これにより、到達不可能な状態や支配された状態を明示的に追跡することが回避されます。 

入力ループは、終了ダッシュまで慎重に行を連結し、処理前にダッシュを削除します。 テキストが複数行にまたがり、スペースや句読点が含まれる可能性があるため、これが必要です。

 ## 特殊なケース

 重要なエッジ ケースは、テキストが A と L などの 2 つの離れたキーの間で繰り返し切り替わる場合です。貪欲なアプローチでは 1 本の指を前後にバウンドさせることになり、大きなコストが発生しますが、DP では責任を分割できるため、各指が 1 つの領域を処理できます。 

もう 1 つのケースは、連続する多くの文字が同一である場合です。 正しい動作では、最初に押した後は指がその位置に留まるため、追加コストはかかりません。 同じ指を再利用しても追加の動きがゼロになるため、DP はこれを保持します。 

最後に、主にスペースと句読点で構成される入力で、非移動文字が正しく無視されるかどうかをテストします。 アルゴリズムはそれらを明示的にスキップし、自由な文字に対して状態拡張が発生しないようにします。
