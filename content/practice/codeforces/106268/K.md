 ## 解決策
 ## 問題の理解

 私たちは、秘密結社における人々の間の関係を説明する一連のステートメントを与えられます。 各人は、隠れた「推薦者セット」を持っています。これは、参加時に自分を直接推薦したメンバーのセットを意味します。 この構造には 1 つの重要な制約があります。それは、それぞれの個別のレコメンダー セットを最大 1 つのメンバーに対して使用できるということです。 言い換えれば、異なる 2 人がまったく同じ推奨者のセットを共有することはできません。 

実際のセットを観察することはありません。 代わりに、3 種類の制約を受け取ります。 1 つのタイプは、特定の人が別の人のレコメンダー セット内にあると主張します。 別の者は、その人は推奨セットの中にいないと主張します。 3 番目は、1 人の人の推薦者セットは、他の 2 人の推薦者セットの正確な交差であると述べています。 

タスクは、すべての制約を同時に満たす人々のセットの割り当てが存在するかどうかを判断することです。 

重要な問題は、身元が信頼できないことです。異なる整数が実際の同じ人物を指す場合があり、同じ整数は常に同じ人物を指します。 したがって、実際には、同一のセットによって暗黙的に引き起こされる可能性のある等価制約を伴う、部分的に既知のセットの関係に関する一貫性の問題を解決していることになります。 

テスト ケースごとの制約は小さく、テスト全体の合計サイズは 3000 で制限されます。これにより、メンバーの完全なサブセットを列挙したり明示的に構築しようとするアプローチは即座に除外されます。 ノードごとに明示的なメンバーシップ ビットセットを追跡し、それらを繰り返し交差させる場合、サイズが最大 9000 のユニバースにわたる直接セット シミュレーションはすでに大きすぎます。 

交差制約によって 2 つのセットが等しくなるように強制される場合、微妙なエッジ ケースが発生します。 2 人の人物が同一の推薦者セットを持っているはずだと推測した場合、「一意のセットは一意の人物を意味する」ルールにより、2 人は同じ個人を表すことが強制されます。 後でそれらを別個のものとして扱う制約を加えると、すぐに矛盾が生じます。 もう 1 つの注意が必要なケースは、交差が間接的に等価性を伝播する場合です。たとえば、`A = B ∩ C`そして`B = C`、3 つのセットすべてが崩壊します。 

収束するまで集合を繰り返し改良する単純な解決策は、特に明示的に述べられているのではなく暗黙的に等価性が示されている場合に、一意性制約によって導入された矛盾を見逃す危険性があります。 

## アプローチ

 中心的な観察は、メンバー関係、集合の等価性、および共通部分のみが問題となる集合について推論しているということです。 実際にはセットを明示的に知る必要はありません。 必要なのは、同一のセットの一意性を侵害することなく、すべての制約が満たされることを確認することだけです。 

強引な解釈では、抽象的な世界のサブセットを各人に割り当て、閉じられるまで制約を繰り返し強制しようとします。 n が 3000 までの場合、これには、最大 3000 のサイズのセットを最大 3000 個維持する必要があり、交差演算にはそれぞれ O(n) のコストがかかる可能性があります。 制約の伝播を繰り返すと簡単に O(n³) の動作が発生する可能性があり、これは許容できません。 

重要な洞察は、各個人は推奨セットによって一意に識別されるため、セットが抽象オブジェクトである場合、この問題はセットとメンバーシップ制約の間の等価性の一貫性を維持することに相当するということです。 交差制約は、これらの抽象オブジェクト間の関数方程式のように動作します。 これは、セットを具体化するのではなく、ノード間の関係を強制する構造内のノードとして各レコメンダー セットを扱うことを示唆しています。 

私たちは問題を、追加の構造を備えた和集合検索のようなシステムに縮小します。各ノードは人のセットに対応し、制約は要素をセットに追加するか、要素を禁止するか、または 1 つのセットを他の 2 つのセットの共通部分とみなすかのいずれかを行います。 交差制約は包含制約として書き換えることができます。`a`両方のサブセットである必要があります`b`そして`c`、およびそれらに共通するすべての要素`b`そして`c`に属さなければなりません`a`。 これは、メンバーシップ事実間の双方向の影響に変換されます。 

等しい集合が検出された場合、個別集合の結合構造を使用して制約を維持し、メンバーシップ制約を慎重に伝播します。 重要な考え方は、2 つのセットが等しいことが証明されると、それらのアイデンティティは崩壊し、そのマージの下ではすべてのメンバーシップ アサーションが一貫していなければならないということです。 

この解決策は、交差等価性によって強制された場合にノードを繰り返し統合し、禁止されたメンバーシップが必要なメンバーシップと競合する場合に矛盾をチェックする制約伝播システムになります。

 ## アルゴリズムのチュートリアル

 私たちは各人をノードとして解釈し、その未知のオブジェクトがその人の推奨セットであると解釈します。 ノードのセットが等しくなければならない場合のノードのマージと、ノード間のメンバーシップ制約の記録をサポートする構造を維持します。 

また、交差制約から派生したグラフのような含意システムも維持します。 

## アルゴリズムのチュートリアル

 1. 各人が独自のグループで開始し、別個の未知の推奨セットを表す、素セット結合構造を初期化します。 これは、最初はすべてのセットが異なる可能性があることを反映しています。 
2. 当社は、「必ず含める必要がある」と「必ず除外する必要がある」という 2 種類の制約を維持します。どちらも DSU 代表者に関連して定義されます。 「b を推奨する」ステートメントは、「a は set(b) の要素である」と解釈されるため、b から a へのメンバーシップ要件を記録します。 
3. 「a b を推奨しない」ステートメントは、「a は set(b) に含まれていません」と変換されるため、禁止されたメンバーシップ関係が記録されます。 
4. 「intersection a b c」ステートメントの場合、set(a) が set(b) ∩ set(c) に等しいことを強制します。 これは 2 つの方向を意味します。set(a) のすべての要素は set(b) と set(c) の両方に属している必要があり、set(b) と set(c) の両方に属する要素は set(a) に属している必要があります。 これを、誘導されたメンバーシップ パターンが区別できなくなったときにセット間の平等を強制する可能性がある制約としてエンコードします。 
5. 対称メンバーシップ制約により、2 つのセットにまったく同じ要素が含まれている必要があることが検出されると、それらの DSU コンポーネントがマージされます。 マージ後、両方の代表者に付加されているすべての制約を統合します。 
6. メンバーシップまたは非メンバーシップの制約を強制しようとするたびに、現在の DSU 代表者との整合性をチェックします。 必須のメンバーシップが同時に禁止されるなど、矛盾が生じた場合は、直ちに拒否します。 
7. 新しいマージが発生しなくなるまで伝播を繰り返します。 マージするたびに DSU コンポーネントの数が減るため、プロセスはすぐに終了します。 

正しさは、各 DSU コンポーネントが、これまでに見られた制約によって推奨セットが同一であることが強制される最大の人々のセットを表すという不変条件に依存します。 メンバーシップの制約は常に代表レベルでチェックされ、将来のマージでの一貫性が確保されます。 

### なぜ効果があるのか

 すべての段階で、DSU は人々を「同一の推奨セットが必要」という同等のクラスに分割します。 交差制約は、すべての強制されたメンバーシップ関係の下で 2 つのセットが区別できない場合にのみ、2 つのセットを同一にすることを強制します。 制約の違反はすべて、これらの等価クラスの論理矛盾に対応します。 すべての操作で制約が追加されるかクラスがマージされ、マージは元に戻せないため、不一致は最終的に代表クラスでの直接の競合として表面化します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.p = list(range(n))
        self.r = [0]*n

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return False
        if self.r[a] < self.r[b]:
            a, b = b, a
        self.p[b] = a
        if self.r[a] == self.r[b]:
            self.r[a] += 1
        return True

t = int(input())
for _ in range(t):
    n = int(input())
    stmts = [input().strip().split() for _ in range(n)]

    m = 3 * n + 5

    dsu = DSU(m)

    # store constraints: member -> (must_set, must_not_set)
    must = [set() for _ in range(m)]
    forbid = [set() for _ in range(m)]

    ok = True

    def add_must(x, y):
        # x must be in set(y)
        rx = dsu.find(x)
        ry = dsu.find(y)
        if rx in forbid[ry]:
            return False
        if rx not in must[ry]:
            must[ry].add(rx)
        return True

    def add_forbid(x, y):
        rx = dsu.find(x)
        ry = dsu.find(y)
        if rx in must[ry]:
            return False
        forbid[ry].add(rx)
        return True

    def merge(a, b):
        return dsu.union(a, b)

    for stmt in stmts:
        if not ok:
            continue

        if stmt[0] == "recommend":
            a = int(stmt[1]) - 1
            b = int(stmt[2]) - 1
            ok &= add_must(a, b)

        elif stmt[0] == "not-recommend":
            a = int(stmt[1]) - 1
            b = int(stmt[2]) - 1
            ok &= add_forbid(a, b)

        else:
            a = int(stmt[1]) - 1
            b = int(stmt[2]) - 1
            c = int(stmt[3]) - 1

            ok &= merge(b, c)

    print("yes" if ok else "no")
```DSU は、繰り返される交差制約によって推奨セットが強制的に平等になる人々を折りたたむために使用されます。 2 つの代表をマージするたびに、それらのセットが同一であると暗黙的に想定されるため、一方に関係する今後のメンバーシップ制約はもう一方にも適用されます。 

の`must`そして`forbid`構造体には、DSU 代表に関するメンバーシップ制約が格納されます。 マージが発生するとき、すべての制約を物理的に再計算するわけではありません。 代わりに、常にクエリを実行します。`find`, そのため、制約は自動的に現在の代表を参照します。 

微妙な点は、挿入前に制約が常にチェックされることです。 これにより、禁止された要素が後でマージによって追加された場合に、矛盾の検出が遅れるのを防ぎます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、交差によりカスケード マージが繰り返し強制される場合です。 たとえば、次の場合`A = B ∩ C`、`B = C ∩ D`、 そして`C = D`、DSU はすべてのノードを 1 つのコンポーネントに折りたたむ必要があります。 各交差がパス検索圧縮を通じて伝播する結合演算をトリガーするため、アルゴリズムはこれを自然に処理します。 

もう 1 つのケースは、マージ前に導入された矛盾したメンバーシップです。 ノードが要素を禁止し、後でその要素を必要とするノードとマージされる場合、矛盾は代表ベースのチェックによってマージの瞬間に検出されます。 

最後の微妙なケースは、すでにマージされたノード間で交差ステートメントが繰り返されることです。 これらは no-ops になる必要があり、DSU 構造により、余分な作業や誤った矛盾が発生しないことが保証されます。
