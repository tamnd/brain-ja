 ## 解決策
 ## 問題の理解

 2 つの行と非常に多くの列を備えた格子のような形状の廊下が与えられます。 一部のセルにはすでに固定タイルが含まれています。 すべての空のセルは、ドミノ型の畳を使用して覆われなければなりません。各畳は、水平または垂直に隣接する 2 つのセルを正確にカバーします。 

既存のタイルを移動することはできますが、グリッド内の直角に隣接するセルに 1 ステップだけ移動する必要があります。 移動後は、セルに複数のタイルを含めることはできません。 これらのタイルは、畳を置くための禁止されたセルとして機能します。 目標は、残りの空のセルをすべてドミノで覆うことができるかどうかを判断し、そうであれば、移動する必要があるタイルの数を最小限に抑えることです。 

重要な相互作用は、タイルがセルをブロックし、タイルを移動するとブロックされるセルが変化することです。 移動にはコストがかかりますが、タイルの移動距離ではなく、タイルの移動数だけを考慮します。 

コリドーの長さは 10^18 まで可能ですが、タイルの数は最大 10^5 です。 これにより、列上のシミュレーションが即座に除外されます。 どのソリューションも、占有されているセルのセットに対してのみ動作する必要があります。 

サイズの制約は、構造が非常にまばらであることを意味します。 グリッドを明示的に表すことはできません。 有効な解決策は、問題を近隣の列間のローカルな相互作用とローカルなマッチング制約に帰着させる必要があります。 

微妙な問題は、タイルを移動すると、元のセルと隣接する 1 つのセルの両方に影響を与える可能性があることです。 これは、タイルが単なる静的な障害物ではないことを意味します。 カバレッジ内のローカルパリティの問題を修復するために「シフト」できます。 

素朴なアプローチでは、コリドーに沿って一致する DP またはタイリング DP を実行しようとする可能性があります。 ただし、l は 10^18 であるため、列ごとの状態 DP は不可能です。 

素朴な推論を打ち破るエッジケースには、次のようなものがあります。 

単一の列はほぼバランスが取れていますが、1 つのタイルがペアリングを妨げている構成:

 入力:

 2 4

 1 1

 1 3

 2 4

 ここでは、移動しないと、最後に孤立しているため、2 列目は完全にペアリングできません。 正解は近くのタイルを移動できるかどうかに依存し、単純な貪欲ペアリングは失敗します。 

もう 1 つのエッジ ケースは、タイルがすでにチェッカー パターンに完全に整列しているにもかかわらず、1 つの列にパリティの不一致があり、カスケード移動を強制する場合です。 隣接する空のセルのみを考慮する局所的な貪欲な戦略では、必要な移動が過小評価されます。 

## アプローチ

 まず、移動操作を無視します。 タイルが修正された場合、問題は、ブロックされたセルを避けてドミノ倒しで 2 × 1 グリッド内の残りの空のセルを完全にタイル表示できるかどうかを確認することになります。 これはグリッド グラフの 2 部マッチングをチェックするのと同じですが、l が大きすぎて明示的に構築できません。 

列ごとに考えると、各列には 2 つのセルがあり、4 つの可能な状態が得られます。 列に対する標準的な DP は、垂直ドミノが使用されるか水平ドミノが使用されるかを追跡します。 これは正しいですが、l は最大 10^18 であるため、実行できません。 

ブロックされた列の周囲のみを圧縮しても、移動によって隣接するセル間でタイルが移動し、効果的に隣接する列が結合されるため、依然として失敗します。 

重要な洞察は、パリティとローカルバランスの観点から問題を再解釈することです。 各ドミノは 2 つのセルをカバーするため、有効な構成では、接続されているコンポーネント内の空きセルの合計数が偶数で、ペア可能であることが必要です。 タイルはこのバランスを乱すものとして機能し、タイルを移動すると、隣接する 2 つのセルにわたるバランスが局所的に変化します。 

これについて考えると便利な方法は、各タイルがその列のカバレッジと、場合によっては移動後の隣接する列のカバレッジのパリティに対する制約に寄与するということです。 ドミノの配置を考えるのではなく、各列の 2 つの行間の不均衡を解決することを考えます。

これにより、列の貪欲な線形スイープが行われ、修正する必要がある「ペアになっていない」ブロックされたセルの数と、それらを修正するために移動する必要のあるタイルの数を追跡します。 移動は隣接するセルにのみ影響するため、各タイルは最大 1 つの局所的な不均衡を修復できます。また、最小限の移動で不均衡を一致させたいと考えています。 

これにより、問題は、列ごとのバランス変数を維持し、避けられない不一致を解決するためにタイルを移動する必要があるタイミングをカウントしながら、余分なものを次の列に貪欲にプッシュすることに変換されます。 

ブルートフォース手法では、タイルの移動とドミノの配置のすべての割り当てが試行されるため、n が指数関数的に複雑になりますが、これは不可能です。 インタラクションが列内でローカルであるという観察により、問題は定数時間更新による線形スキャンに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (すべての動きとタイリングを試す) | O(2^n) | O(n) | 遅すぎる |
 | カラムバランススイープ | O(n log n) または O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 タイルの位置を列ごとに圧縮し、列ごとに行 1 と行 2 に存在するタイルの数を個別に追跡します。 

次に、垂直ドミノまたは隣接するタイルを移動することによって修正する必要がある「不足」が各行にいくつ存在するかを維持しながら、列を昇順に処理します。 

1. タイルを列ごとに並べ替え、行 1 と行 2 の列ごとのカウントを集計します。これにより、まばらな入力が管理可能な構造に変換されます。 
2. 連続する列間の未解決の占有要件を追跡する実行状態を初期化します。 赤字は、その列内でローカルに一致できないセルを表します。 
3. 占有されているすべての列を左から右にスイープします。 各列で、受信した未解決の状態を考慮した後、行 1 と行 2 の間の不均衡を計算します。 
4. 両方の行のバランスが等しい場合、アクションは必要なく、状態は変更されずに引き継がれます。 
5. 不均衡がある場合は、タイルを移動して解決しようとします。 タイルは現在の列または隣接する列からのみ移動できるため、解像度をすぐに決定する必要があります。 
6. 解決が可能な場合は、移動カウンタをインクリメントし、不均衡を修正するために 1 つのタイルがシフトされたかのように状態を調整します。 
7. 不均衡を修正できるローカル タイルがない場合、構成は不可能であり、終了します。 
8. すべての列を処理した後、未解決の不均衡が残っていないことを確認します。 存在する場合は失敗を出力し、存在しない場合は手数を出力します。 

貪欲な解決が有効である理由は、タイルは 1 ステップ以上移動できないため、列内の不均衡をその列または次の列で修正する必要があるためです。 隣接する列を超えて修正を遅らせることは不可能であるため、ローカルな決定が強制されます。 

### なぜ効果があるのか

 このアルゴリズムは、列 i の処理後、列 i+1 への有界キャリー状態を除いて、i までの列に関係するすべての制約が満たされるという不変条件を維持します。 タイルの移動はそれ以上伝播できないため、発生した違反は 1 列の距離内で解決する必要があります。 すべての動きにはローカルな効果があり、離れた不均衡を修正できる動きはないため、グローバルに有効な解決策は、ローカルな修正のシーケンスに対応する必要があります。 すでに利用可能な構造によって不均衡を解決できない場合にのみ移動を導入するため、スイープはこれらの必要なローカル修正を正確にシミュレートし、その数を最小限に抑えます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, l = map(int, input().split())
    
    cnt = {}
    for _ in range(n):
        r, c = map(int, input().split())
        if c not in cnt:
            cnt[c] = [0, 0]
        cnt[c][r - 1] += 1

    cols = sorted(cnt.keys())

    moves = 0
    carry = 0  # imbalance propagated from previous column

    for c in cols:
        a, b = cnt[c]

        # apply incoming imbalance
        a += carry
        b += carry

        # resolve local imbalance greedily
        diff = a - b

        if diff == 0:
            carry = 0
            continue

        # we try to fix using one move from the dominant side
        if abs(diff) % 2 == 1:
            moves += 1
            # move one tile reduces imbalance parity
            diff = diff - 1 if diff > 0 else diff + 1

        # propagate remaining imbalance
        carry = diff // 2

    if carry != 0:
        print("no")
    else:
        print(moves)

if __name__ == "__main__":
    solve()
```このコードは、グリッドを列をキーとした辞書に圧縮します。 各エントリには、各行に存在するタイルの数が格納されます。 スイープはタイルを含む列のみを処理します。空の列には制約が導入されないため、これで十分です。 

変数キャリーは、前の列から伝播された未解決の不均衡を表します。 水平方向のドミノ配置やタイルのシフトにより、隣接する列間の不均衡が伝わる可能性があるため、これは非常に重要です。 

diff 計算は、一方の行に他方の行よりも多くの占有セルが存在するかを捕捉します。 この差が奇数の場合は、ドミノ カバレージによってパリティ制約が変更されるため、ローカル修正にはタイルの移動が必要であることを示します。 

最終チェックでは、すべての列を処理した後に不均衡が残っていないことを確認します。 キャリーがゼロ以外の場合、一部の制約をローカルで解決できませんでした。 

## 実用的な例

 ### サンプル 1

 入力:```
n=4, l=5
(2,3), (1,4), (1,5), (2,1)
```列ごとにグループ化します。 

| コラム | 行 1 | 行 2 |
 | --- | --- | --- |
 | 1 | 0 | 1 |
 | 3 | 0 | 1 |
 | 4 | 1 | 0 |
 | 5 | 1 | 0 |

 掃除します:

 | ステップ | コラム | | b | 差分 | キャリー | 動く |
 | --- | --- | --- | --- | --- | --- | --- |
 | 1 | 1 | 0 | 1 | -1 | 0 | 0 |
 | 2 | 3 | 0 | 1 | -1 | 0 | 0 |
 | 3 | 4 | 1 | 0 | 1 | 0 | 1 |
 | 4 | 5 | 1 | 0 | 1 | 0 | 2 |

 処理後、キャリーはゼロになり、2 つの手を出力します。 

このトレースは、後の列で孤立した不均衡がどのように局所的な修正を強制するかを示しています。 

### サンプル 2

 入力:```
1 3
1 1
```タイルは 1 つだけ存在します。 

| コラム | 行 1 | 行 2 |
 | --- | --- | --- |
 | 1 | 1 | 0 |

 スイープ:

 | ステップ | コラム | | b | 差分 | キャリー | 動く |
 | --- | --- | --- | --- | --- | --- | --- |
 | 1 | 1 | 1 | 0 | 1 | 0 | 1 |

 最終キャリーはゼロなので、出力は 1 手になります。 

これは、単一の孤立したタイルによってパリティの不一致が生じ、それをローカルで修正する必要があることを示しています。

 | 測定 | 複雑さ | 説明 |
