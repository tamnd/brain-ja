 ## 問題の理解

 We are given a single large integer$N$、 まで$10^{17}$。 2 つの正の整数に分割することができます$a$そして$b$そのような$a + b = N$。 このような分割ごとに、次の 10 進表現を連結して新しい数値を形成します。$a$直後に次の 10 進数表現が続きます$b$。 可能なすべての分割の中で、可能な最大の連結値が必要です。 

ここでの連結は純粋に 10 進数の文字列の連結であるため、次の場合$a = 92$そして$b = 10$、結果の数値は次のようになります。$9210$、算術式ではありません。 

入力サイズは値としては非常に大きくなりますが、数値が 1 つしか取得されないため、構造としては非常に小さくなります。 これにより、それに比例するものを列挙または構築しようとするアプローチは即座に除外されます。$N$。 平$O(N)$分割を繰り返すことは不可能であるため、$N$できる$10^{17}$。 代わりに、最適な分割の構造について推論する必要があります。 

微妙な特殊なケースは、最良の分割が必ずしも数値の中央近くにあるわけではない、または桁のバランスに関係しているわけではないという事実から生じます。 たとえば、102 のような小さい数では、92 + 10 として分割すると、51 + 51 や 60 + 42 などのバランスのとれた分割よりもはるかに大きな連結が生成されます。これは、連結の最大化が、数値の近さよりも桁の長さの相互作用に大きく依存することを示しています。 

もう 1 つのエッジケースは次のような場合です$N$は 10 の累乗境界のすぐ上です。 桁の長さを変更する分割$a$または$b$連結の大きさを大幅に変えることができます。 たとえば、99 から 100 に移動すると、桁数がシフトするため、連結構造が完全に変わります。 

## アプローチ

 ブルートフォース手法では、すべての有効な分割が試行されます。$a$1から$N-1$、計算します$b = N - a$、文字列変換によって連結された値を構築します。 すべての可能性を直接評価するため、これは正しいですが、$O(N)$反復、これは不可能です$N$まで$10^{17}$。 その範囲を概念的に反復することさえ不可能です。 

重要な観察は、連結の値は主に桁数に依存するということです。$a$そして$b$算術的な意味での正確なバランスではありません。 桁長の点で固定分割位置の場合、最適な候補$a$を超えない桁の長さで可能な最大の数値です。$N-1$。 一度$a$固定されており、$b = N - a$が決定され、連結された値が完全に決定されます。 

これは、可能なすべての値を反復する代わりに、削減を示唆しています。$a$、次のような候補のみを考慮する必要があります。$a$特定の桁長を持ちます。 可能な長さごとに$k$を最大化しようとします$a$という制約のもとで$1 \le a < N$、結果の連結を計算します。 以来$N$最大 17 桁の場合、桁長境界の数は一定であるため、一定数の候補のみを評価します。 

連結関数が各桁長クラス内で単調であるため、最適化が機能します。$a$。 もし$a$が固定桁長内で増加すると、プレフィックスと結果の連結の両方が辞書編集的に増加するため、最大値は常にその桁長の実現可能性の境界で発生します。

 ## アルゴリズムのチュートリアル

 私たちはこの問題を、桁数を選択する意味のあるすべての方法を探索するものとして扱います。$a$を貪欲に最大化します$a$それぞれの選択の下で。 

1.変換$N$文字列に変換すると、桁の境界を直接推論できるようになります。 これにより、算術オーバーフローが回避され、連結が自然になります。 
2. しましょう$s$の文字列表現になります$N$、そしてさせてください$d$その長さになります。 候補の分割を検討します。$a$もっている$k$数字、すべて$1 \le k < d$。 ケース$k = d$は無効です。$b$ゼロまたは負になります。 
3. 各桁の長さについて$k$、候補を構築します$a_k$最大の数として$k$そのような数字$a_k < N$。 これは事実上、次の接頭辞です。$N$プレフィックスが等しいかそれを超える場合は、わずかに小さい数値$N$。 このステップにより、プッシュ中の実現可能性が保証されます。$a$できるだけ高く。 
4. 1回$a_k$決定される、計算する$b_k = N - a_k$。 これにより、分解制約の正確さが保証されます。 
5. 両方の数値を文字列に変換して結合することにより、連結された値を形成します。 すべての候補の最大値を追跡します。 
6. 最大連結値を出力します。 

唯一の微妙な決定は、どのように調整するかです$a_k$ナイーブプレフィックスが次と等しいとき$N$または積極性を侵害する$b$。 その場合はデクリメントします$a_k$桁の長さを維持しながら、短縮されるため、$a$わずかに増加する$b$しかし、実現可能性は保たれます。 

### なぜ効果があるのか

 このアルゴリズムは、固定桁長の場合、次の事実に基づいています。$a$、連結は厳密に増加しています$a$、に関して実現可能になるまで$b = N - a$休憩します。 したがって、最適解は実現可能な最大値にある必要があります。$a$各桁長クラス内で。 桁の長さは$O(\log N)$可能性を検討し、クラスごとに 1 人の代表者を調べて、全体的な最適値を取得します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    s = str(n)
    d = len(s)

    best = 0

    for k in range(1, d):
        # largest k-digit number
        a = int("9" * k)
        if a >= n:
            a = n - 1

        b = n - a
        if b <= 0:
            continue

        cand = int(str(a) + str(b))
        if cand > best:
            best = cand

    print(best)

if __name__ == "__main__":
    solve()
```コードは、可能な桁長にわたって反復されます。$a$、それぞれについて実行可能な最大の候補を構築し、結果の連結を評価します。 値は最大 17 桁で制限されるため、文字列操作は安全です。 

微妙な点は、次の場合の処理​​です。$9^k$超えるか等しい$N$。 そのような状況では、クランプします$a$に$N-1$有効性を維持するため。 これにより、$b$は正の値を維持し、列挙の正確性が維持されます。

 ## 特殊なケース

 のために$N = 2$、唯一の分割は$1 + 1$。 アルゴリズムが考慮するのは、$k = 1$、構築します$a = 1$、計算します$b = 1$、連結を出力します$11$、唯一の有効な構成と一致します。 

のために$N = 10$、桁長ループは次のように評価します。$k = 1$。 候補者$a = 9$与える$b = 1$、生産$91$。 単純なアプローチでバランスの取れた分割のみを試みた場合、誤って考慮される可能性があります。$5 + 5$、それは与える$55$、真の最大値が欠落しています。 

のために$N = 100000000000000000$、アルゴリズムは 17 回のみ反復します。 各反復では最大 18 桁の数値に対して定数時間の文字列操作が実行されるため、メモリの圧迫やオーバーフローのリスクが発生することなく即座に完了します。
