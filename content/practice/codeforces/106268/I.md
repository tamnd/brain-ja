 ## 解決策
 ## 問題の理解

 文字列として表される 1 次元のボードが与えられます。 各位置には、アリスのマーク、ボブのマークがすでに含まれているか、空であるかのいずれかです。 ゲームはアリスから始まるターン制です。 ターンでは、プレーヤーは空のポジションを選択し、そこに自分のマークを書きます。ただし、隣接するプレーヤーのどちらも同じプレーヤーのマークをまだ持っていない場合に限ります。 この制限では相手のマークは関係ありません。 

プレイヤーが有効な手を持っていない場合、ゲームは終了し、そのプレイヤーは負けます。 両方が最適にプレーすると仮定して、勝者を決定する必要があります。 

ボード サイズはテスト ケースごとに最大 200,000 まで可能で、合計で最大 200,000 のテスト ケースがあり、すべての長さの合計も 200,000 で制限されます。 これにより、移動ごとのシミュレーションや各配置後のボードの繰り返しスキャンが即座に除外されます。 ゲームを段階的にシミュレートしようとするソリューションは、最悪の場合、二次的な動作に低下します。 

制約の構造は、各テスト ケースを線形時間で独立して処理する必要があることも意味しており、理想的には文字列の 1 回のパスで処理する必要があります。 

このルールの微妙な点は、隣接関係の制約がプレーヤー固有であることです。 セルは、少なくとも 1 人の隣人がアリスのマークである場合にのみ、アリスに対して禁止されます。 ボブの存在はアリスの引っ越しの合法性に影響を与えませんし、その逆も同様です。 この分離が構造の簡素化の鍵となります。 

素朴な考えを打ち破る特殊なケースの 1 つは、空白が既に配置されたマークの交互または混合構成で囲まれている場合です。 たとえば、次のようなパターンで`.a.`, アリスを中央に配置することは、自分のマークに隣接しているため禁止されていますが、ボブは影響を受けず、まだ移動できる可能性があります。 もう 1 つの注意が必要なケースは、孤立したマークの間にドットが長く伸びている場合です。 ローカルで有効な動きは、グローバル密度ではなく、最も近い同じ色の制約にのみ依存します。 

## アプローチ

 直接的な総当たりアプローチは、ゲームをシミュレートすることです。 各ターンで文字列全体をスキャンし、現在のプレイヤーの有効な動きをすべて収集します。 セルが空で、隣のセルにそのプレイヤーのマークが含まれていない場合、移動は有効です。 次に、任意の手を選択し (戦略の列挙ではなく勝者を決定するだけであるため)、文字列を更新し、手がなくなるまでターンを繰り返します。 

これはルールに正確に従い、徹底したシミュレーションを通じて暗黙的に最適なプレイを強制するため、これは正しいです。 ただし、各ターンでは最大 n 個のセルをスキャンする必要があり、最悪の場合は O(n) 移動する可能性があります。 これにより、テスト ケースあたりの時間は O(n²) となり、n が 2×10⁵ の場合、これは制限をはるかに超えます。 

重要な観察は、制約が純粋にローカルであり、重要な点で静的であるということです。 アリスに対するセルの有効性は、そのすぐ隣にアリス マークがあるかどうかによってのみ決まり、セルが一度満たされると、再び空になることはありません。 これは、ポジションが無効になる唯一の方法は、同じプレーヤーの既存のマークに近づくことによってであり、これらのマークはボードを独立した領域に分割することを意味します。 

次に、1 人のプレーヤーの有効なポジションの構造を考えてみましょう。 対戦相手を完全に無視すると、アリスは既存の「a」に隣接しないセグメントでのみプレイできます。 すべての「a」は、アリスが動作できる独立した間隔にラインを分割するブロッカーのように機能します。 各間隔内では、アリスとボブは複雑な方法で隣接制約を介して対話しません。これは、アリスの制約がボブの配置ではなく、アリス自身の配置にのみ依存するためです。 

これにより、ゲームが既存の文字で区切られた独立したセグメントに分離され、結果は利用可能なスペースのセグメントにわたるパリティのような蓄積になります。 各セグメントは、構造から事前に計算できる固定の手数に寄与し、プレイヤーが交代するため、合計の手数が奇数か偶数かによって勝者が決まります。 

したがって、我々は問題を、最適なプレイ等価性の下での初期状態における有効な手の総数を計算することに帰着させ、これは線形時間で導出することができる。

 ## アルゴリズムのチュートリアル

1. 既存の「a」と「b」の文字を固定バリアとして使用して、概念的にボードを分割します。 これらの文字は決して変更されず、どの空のセルが潜在的にプレイ可能であるかを決定します。 
2. ドットのみで構成される最大セグメントごとに、自分の既存のマークの隣に配置することを禁止するルールの下で、どちらかのプレイヤーがそのセグメント内で何回移動できるかを決定します。 重要な考え方は、クリーンなドット セグメント内では、プレーヤーがその中に最初のマークを作成した場合にのみ隣接制約が関係するということです。 
3. プレイヤーがセグメント内に最初に配置すると、そのプレイヤーの隣接プレイヤーが即座に制限されますが、対戦相手には影響しないことに注目してください。 これは、セグメント間の相互作用が既存の文字によってブロックされるため、各セグメントが実質的に総移動数に独立して寄与することを意味します。 
4. 長さ L の各セグメントを有効な移動数に減らします。 このようなセグメントでは、プレーヤーが 1 つおきのポジションを占めると、隣接ルールによりそれ以上の密な詰めが妨げられるため、最適なプレイにより、そのセグメントで最初に行動するプレーヤーのプレイ可能な動きはほぼ天井 (L/2) になります。 
5. すべてのセグメントの寄与をアリスとボブに分けて合計しますが、プレイはアリスからグローバルに交互に行われるため、必要なのはボード全体で利用可能な手の合計数だけです。 
6. パリティによって勝者を決定します。有効な手の合計数が奇数の場合、アリスが最後の手を行って勝ちます。 そうでなければボブが勝ちます。 

中心となるアイデアは、ゲームがセグメント全体に分散された独立した動きの山のように動作し、最適なプレイとは、ベスト プレイのプレッシャーの下で合法的な配置の合計が何回存在するかを数えるということです。 

### なぜ効果があるのか

 不変条件は、すべての有効な移動が将来の検討から 1 つのセルだけを永久に削除し、将来の移動をローカルでのみ制限できるということです。 隣接制約はプレイヤー固有で単調であるため (マークの追加は同じプレイヤーの可能性を取り除くだけです)、各プレイヤーの将来の動きのセットは単調に縮小します。 この単調性により、合計の手数は独立したセグメントに分割された初期構成によって確実に固定され、最適なプレイでは合計数は変更できず、誰が最後の手を行うかのみが変更されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input().strip())
        s = input().strip()

        # We count available moves in segments of '.'
        # bounded by 'a' or 'b'
        total_moves = 0

        i = 0
        while i < n:
            if s[i] != '.':
                i += 1
                continue

            j = i
            while j < n and s[j] == '.':
                j += 1

            length = j - i

            # check boundaries
            left_block = s[i - 1] if i > 0 else None
            right_block = s[j] if j < n else None

            # If segment is fully isolated from same-player constraints,
            # effective moves behave like independent placements.
            # Each cell contributes one potential move in optimal play,
            # but adjacency reduces every second placement.
            total_moves += (length + 1) // 2

            i = j

        # parity decides winner
        if total_moves % 2 == 1:
            print("alice")
        else:
            print("bob")

if __name__ == "__main__":
    solve()
```コードは、文字列を 1 回スキャンし、最大の連続したドット ブロックを抽出することによって、各テスト ケースを処理します。 各ブロックは、式 (長さ + 1) // 2 を使用して有効移動数に変換されます。これは、自由間隔内で、自己隣接制限の下で配置が 2 番目ごとの位置を効果的に占有することを反映しています。 

アリスは常にスタートし、プレーヤーは交互に手を動かすため、累積された合計はパリティによって勝者を決定するために使用されます。 

実装の微妙な点は、隣接関係の変更を明示的にシミュレートしないことです。 我々は、隣接性は同一のマークに関してのみ重要であるという事実に依存しており、最初は空のセグメント内では、これは移動順序とは独立した固定パッキング制約に帰着します。 

## 実用的な例

 ### 例 1

 入力:`s = ".."`長さ 2 のセグメントが 1 つあります。 

| セグメント | 長さ | 貢献 |
 | --- | --- | --- |
 | ".." | 2 | 1 |

 アリスが先攻で、有効な手が 1 つだけあるため、アリスが勝ちます。 

### 例 2

 入力:`s = ".a."`ドット セグメントは固定の「a」によって分割されます。 

| セグメント | 長さ | 貢献 |
 | --- | --- | --- |
 | 「。」 | 1 | 1 |
 | 「。」 | 1 | 1 |

 合計移動数 = 2 なので、ボブが勝ちます。 

これは、固定文字が遊びを完全に排除するのではなく、ゲームを独立した貢献に分割することを示しています。

 ## 特殊なケース

 次のような単一のドット入力`"."`は長さ 1 のセグメントを 1 つだけ生成し、1 つの移動に貢献するため、アリスが即座に勝ちます。 アルゴリズムが重要`(1 + 1) // 2 = 1`、これは強制シングルアクションと一致します。 

完全に空のボードのような`"......."`長さ 7 の 1 つのセグメントが生成され、4 つの移動に寄与します。 同等の結果はボブに勝利をもたらし、これは、最適なプレーの後、2 番目ごとのポジションが利用できなくなる交互の強制配置と一致します。 

のようにしっかりと区切られたボード`"a.b.a..b"`複数の独立したセグメントに分割されます。 各セグメントは個別に処理され、それらの寄与は相互作用なしで合計され、隣接制約によって固定バリアを超えるセグメント間の依存関係が作成されないことが確認されます。
