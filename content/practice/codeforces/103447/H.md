 ## 解決策
 ## 問題の理解

 各クエリは 2 つの整数シーケンスとパラメータを与えます。$k$。 許可される操作は開始位置を選択することです$a$連続する 2 つの同じ長さのブロックを交換します$k$: セグメント$S[a..a+k-1]$と交換されます$S[a+k..a+2k-1]$。 この操作は何度でも繰り返すことができます。問題は、これらの交換を使用して一方のシーケンスをもう一方のシーケンスに変換できるかどうかです。 

主な問題点は、スワップが単一要素の単純な隣接スワップではなく、構造化されたチャンクの交換であり、これらのチャンクがさまざまな選択肢にわたって重複することです。$a$。 制約により、最大で$10^5$すべてのクエリにわたる要素の合計であるため、変換を段階的にシミュレートするソリューションはすぐに遅すぎます。 単一のクエリでも長さがある場合があります$10^5$したがって、クエリごとに線形または線形に近いものより悪いものは生き残れません。 

操作がサイズのブロックの任意の並べ替えのように動作すると仮定すると、微妙な落とし穴が現れます。$k$。 ブロックは重複しており、相互作用はブロック レベルで独立していないため、これだけでは十分ではありません。 

たとえば、次の場合$k = 2$、操作は長さ 4 のスライディング ウィンドウ内の要素のペアを交換します。単純な解釈では、ペアを並べ替えることしかできないと思われるかもしれませんが、実際には、操作を繰り返すことで、位置構造によって制約されたより深い混合が可能になります。 

2 番目の故障モードは、シーケンスに同一のマルチセットがあるが、シーケンスと比較して構造が異なる場合に発生します。$k$。 たとえば、グローバルに同じ値を持つ 2 つの配列は、構造分解によって引き起こされる値の位置がずれている場合、依然として変換できない可能性があります。$k$。 

したがって、タスクは、操作によって保存された不変構造を特定することです。 

## アプローチ

 ブルートフォースのアイデアでは、シーケンスをモデル化し、考えられるすべての操作を適用して、到達可能な状態を探索しようとします。 それぞれの操作が影響する$2k$要素があり、$O(n)$の選択肢$a$, そのため、探索の単一レイヤーでも大きく分岐します。 状態空間は以下の順列です$10^5$要素があるため、これは完全に不可能になります。 

重要な観察は、連続したブロックの観点から考えるのをやめ、代わりにインデックスがどのように動くかを追跡することです。 位置で演算を適用すると$a$のすべてのインデックス$[a, a+k-1]$の対応するインデックスと交換します$[a+k, a+2k-1]$。 それは位置を意味します$i$位置とのみ対話します$i+k$また、インデックスが割り切れないものによって異なる位置を持つことは決してありません。$k$。 

これにより、厳密な分解が作成されます。インデックスは、モジュロ値に基づいて独立したチェーンに分割されます。$k$。 各チェーン内で、重複する長さの交換が繰り返されます。$k$ブロックでは任意の並べ替えが可能です。 この操作により直感的に、インデックスの各剰余クラスに沿って要素をバブルすることができ、重複により各クラス内で完全な再配置が可能になります。 

したがって、問題は、すべての剰余クラスのモジュロについて、$k$、それらの位置に現れる値の複数セットは両方の文字列で同一です。 

この構造が認識されると、解決策は各剰余クラス内でのソートまたは頻度マッチングになります。

 ## アルゴリズムのチュートリアル

 1. 各シーケンスのインデックスを次のように分割します。$k$インデックスモジュロに従ったグループ$k$。 このステップは、スワップによって異なる残基クラス間で要素が移動されることがないため、これらのグループは独立したユニバースであるという事実を反映しています。 
2. 各残基クラスについて$r$、すべての値を収集します$S[i]$そのような$i \bmod k = r$、同じことを行います$T$。 このグループ化の正しさは、許可されたすべての操作が関係するすべての位置の残差を保存することを追跡することで得られます。 
3. 両方のシーケンスの各残基クラス内で収集された値を並べ替えます。 ソートが使用されるのは、この操作によりクラス内での任意の再配置が可能になり、順序ではなく複数セットのみが重要となるためです。 
4. 各残基クラスのソートされたリストを比較します。$S$そして$T$。 すべてのクラスが正確に一致する場合、変換は可能です。 そうでなければ不可能です。 
5. すべてのクラスが一致する場合は「TAK」を出力し、そうでない場合は「NIE」を出力します。 

### なぜ効果があるのか

 この操作では、要素が異なるモジュロ間で移動されることはありません。$k$インデックス クラスなので、各クラスは不変サブシステムです。 クラス内では、重複するブロック スワップは派生シーケンス上の隣接するスワップのように動作し、そのクラス上に完全な対称グループを生成します。 つまり、クラス内の値の順列はすべて到達可能であり、保持される唯一のプロパティは各クラス内の値の複数セットです。 これらのマルチセットがすべてのクラスで一致する場合、2 つのシーケンスは正確に等価です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    for _ in range(n):
        parts = list(map(int, input().split()))
        lS = parts[0]
        S = parts[1:]
        
        parts = list(map(int, input().split()))
        lT = parts[0]
        T = parts[1:]
        
        k = int(input())
        
        groupsS = [[] for _ in range(k)]
        groupsT = [[] for _ in range(k)]
        
        for i, v in enumerate(S):
            groupsS[i % k].append(v)
        for i, v in enumerate(T):
            groupsT[i % k].append(v)
        
        ok = True
        for r in range(k):
            if len(groupsS[r]) != len(groupsT[r]):
                ok = False
                break
            if sorted(groupsS[r]) != sorted(groupsT[r]):
                ok = False
                break
        
        print("TAK" if ok else "NIE")

if __name__ == "__main__":
    solve()
```実装は分解引数の直後に続きます。 各シーケンスはインデックスモジュロによって分割されます$k$これにより、スワップ操作によってもたらされる不変条件が確実に尊重されます。 バケット内ではブロックの交換が繰り返されても順序が完全に柔軟になるため、各バケットを並べ替えるだけで十分です。 

よくある実装上の間違いは、グループ化を定義するのが値ではなくインデックスであることを忘れていることです。 もう 1 つはスワップをシミュレートしようとすることですが、これはすぐに実行不可能になります。 

## 実用的な例

 2 つのシーケンスがモジュロ クラス内の並べ替えによってのみ異なる場合を考えてみましょう。 させて$k = 2$、$S = [1, 2, 3, 4]$、$T = [3, 4, 1, 2]$。 

| インデックス | S値 | S mod クラス | T値 | T mod クラス |
 | --- | --- | --- | --- | --- |
 | 0 | 1 | クラス0 | 3 | クラス0 |
 | 1 | 2 | クラス1 | 4 | クラス1 |
 | 2 | 3 | クラス0 | 1 | クラス0 |
 | 3 | 4 | クラス1 | 2 | クラス1 |

 クラス 0 を並べ替えると、$[1, 3]$両方のシーケンスで、クラス 1 は次のようになります。$[2, 4]$どちらのシーケンスでも同じなので、答えは肯定的です。 

ここで考えてみましょう$S = [1, 1, 2, 2]$、$T = [1, 2, 1, 2]$、$k = 2$。 

| インデックス | S値 | クラス | T値 | クラス |
 | --- | --- | --- | --- | --- |
 | 0 | 1 | 0 | 1 | 0 |
 | 1 | 1 | 1 | 2 | 1 |
 | 2 | 2 | 0 | 1 | 0 |
 | 3 | 2 | 1 | 2 | 1 |

 クラス0の試合$[1,2]$、ただしクラス 1 は異なります: S は$[1,2]$一方、Tは$[2,2]$。 この不一致は、グローバル マルチセットが類似しているにもかかわらず、変換が不可能であることを示しています。
