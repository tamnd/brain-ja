 ## 解決策
 ## 問題の理解

 少数の分数が与えられ、それぞれが整数のペアで表されます。$p$そして$q$。 許可される珍しい操作は、両方の数値の 10 進表現から数字を削除することですが、ペアでのみです。両方の数字に数字が出現する場合は常に、その数字の出現を選択し、分子と分母の両方からそれらを削除できます。 削除後の各数値の残りの桁は新しい整数を形成し、分数の値は桁キャンセルのトリックの古典的な意味で数学的に等しい必要はありませんが、この問題では、この演算が唯一許可される変換として定義されます。 

一致する数字のマルチセットを削除するすべての可能な方法の中で、各部分では複数の縮小ペアが生成されます。 目標は、可能な限り小さい分子値を持つ結果のペアを選択することです。 複数の演算で同じ分子が得られる場合、それとペアになった対応する有効な分母は受け入れられます。 

キーの構造は、数字が位置ではなくマルチセットとして扱われることです。 これは、桁の位置を一致させるのではなく、グローバルに削除する各桁のコピーの数を決定することを意味します。 

制約$n \le 10$は非常に小さいため、分数ごとに徹底的な検索または組み合わせ検索を実行する必要があることがわかります。 各数値は最大 63 ビット、つまり最大約 19 桁の 10 進数を持つことができるため、検索スペースは簡単ではありませんが、枝刈りや構造化された列挙によって管理可能です。 

微妙なエッジケースとして、削除後の先頭にゼロが付きます。 たとえば、「007」のような縮小された分子を形成する場合、それは 7 として解釈されなければなりません。正規化を行わない単純な文字列ベースの比較では、そのような文字列が辞書編集順に応じて大きいか小さいかとして誤って扱われてしまいます。 

もう 1 つの注意が必要な状況は、数値のゼロ以外のすべての桁を削除する場合です。 たとえば、「1000」と「1000」は、すべてのゼロを削除することで削減でき、空の文字列が残る可能性があります。 正しい解釈は、空の文字列またはすべてゼロの文字列が整数 0 に対応するということです。 

2 番目のエッジ ケースは、異なる削除の選択によって同じ数値が得られるが、桁の構成が異なる場合です。 数字のマルチセットを追跡するだけで文字列を辞書編集的に比較する単純なアプローチは失敗します。これは、文字列の順序ではなく数値が答えを決定するためです。 

## アプローチ

 強引な解釈では、0 から 9 までの各数字について、両方の数字の出現によって制限され、削除するコピーの数を選択するものとして問題を扱うことになります。 各桁について、0 から最小出現数までの削除数を選択します。$p$そして$q$。 これは、次のサイズの検索スペースを定義します。$\prod_{d=0}^9 (min(cnt_p[d], cnt_q[d]) + 1)$。 

最悪の場合、各数字が何度も出現し、検索スペースが桁数で指数関数的に増加します。 10 桁であっても、各桁が複数回存在する場合、直接列挙するには大きすぎます。 

重要な観察は、削除計画に関して重要なのは、結果として得られる分子と分母の残りの桁のマルチセットだけであるということです。 削除を直接構築するという観点から考える代わりに、逆に考えることができます。両方の点で実現可能性を確保しながら、元の数値から数字のサブセットを形成したいと考えています。$p$そして$q$。 以来$n \le 10$、各分数を独立して処理し、両方の元のカウントと一致する桁のサブセットから導出された有効な結果の分子をすべて列挙できます。 

代わりに、次のようにプロセスをモデル化できます。 キャンセル後にどちらかの数字に存在する以上の数字のコピーを使用できないことを考慮して、元の分子と分母から同時に維持する数字のサブセットを選択するあらゆる方法を検討します。 これは自然に、残りの可能なすべての桁数を生成し、結果として得られる最小の分子を計算する、桁 DP スタイルまたは有界マルチセット列挙につながります。 

各数値は最大でも 19 桁までなので、カウントをコンパクトに表現し、枝刈りを使用して実行可能な残りの桁分布を列挙できます。 この構造は十分に小さいため、メモ化を伴う桁数の DFS で十分です。

 ## アルゴリズムのチュートリアル

 各分数を個別に処理します。 

1. 両方を変換する$p$そして$q$これにより、各数字の中に各数字のコピーが何個存在するかが直接わかります。 この表現により、順序付けの問題が完全に解消されます。 
2.各桁ごとに$d$、キャンセル後に両方の数値で保持できる最大回数を計算します。 これは、2 つの数値間の最小出現数によって制限されます。 
3. 0 ～ 9 の数字に対する再帰的検索を定義します。各数字で$d$のコピー数を決定します。$d$キャンセル後の最後の分子と分母には残ります。 残りのコピーの数は、元の可用性を超えてはなりません。 
4. 各ステップで、2 つの部分マルチセットを維持します。1 つは分子の数字用、もう 1 つは分母の数字用です。 また、一貫性も保証します。削除される桁数は両側で一貫しています。これは、何らかの有効な取り消しから生じる可能性のある状態のみを構築することを意味します。 
5. すべての数字が処理されたら、数字を昇順に並べ替えて連結することによって、両方のマルチセットを整数に変換します。 
6. 結果を比較し、最小の分子値を持つペアを維持します。 同点の場合は、対応する分母を保持します。 

重要な簡素化は、削除を明示的にシミュレートしないことです。 代わりに、両方の元の数値と一致する、最後に残った桁のマルチセットを直接構築します。 

### なぜ効果があるのか

 不変条件は、数字の各再帰深さでの$d$、以下の桁のコピーを何部行うかは完全に決定されています。$d$分子と分母の両方に残り、これらの選択は元の桁数に関して常に実行可能です。 カウントが固定されると、桁の選択は位置全体で独立するため、完全な割り当ては有効な削除マルチセットに対応します。 これにより、到達可能なすべての最終状態が 1 回だけ考慮され、無効な状態が生成されないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def digits_of(x):
    cnt = [0] * 10
    if x == 0:
        cnt[0] = 1
        return cnt
    while x > 0:
        cnt[x % 10] += 1
        x //= 10
    return cnt

def build_number(cnt):
    s = []
    for d in range(10):
        s.append(str(d) * cnt[d])
    res = "".join(s).lstrip('0')
    return 0 if not res else int(res)

def solve_one(p, q):
    cp = digits_of(p)
    cq = digits_of(q)

    best = None

    def dfs(d, up, uq, vp, vq):
        nonlocal best
        if d == 10:
            num = build_number(up)
            den = build_number(uq)
            if best is None or num < best[0]:
                best = (num, den)
            return

        max_keep = min(cp[d], cq[d])

        for keep in range(max_keep + 1):
            rem_p = cp[d] - keep
            rem_q = cq[d] - keep

            up[d] += rem_p
            uq[d] += rem_q

            dfs(d + 1, up, uq, vp, vq)

            up[d] -= rem_p
            uq[d] -= rem_q

    dfs(0, [0]*10, [0]*10, None, None)
    return best

def main():
    n = int(input())
    for _ in range(n):
        p, q = map(int, input().split())
        x, y = solve_one(p, q)
        print(x, y)

if __name__ == "__main__":
    main()
```このソリューションでは、まず数値を桁の頻度配列に変換し、順序付けの問題を完全に排除します。 DFS は、すべての有効なキャンセル パターンを桁ごとに列挙します。 状態配列`up`そして`uq`はそれぞれ分子と分母のキャンセル後の残りの桁を表します。 

実装の微妙な詳細は、変換ステップです。 先頭のゼロは次を使用して明示的に削除されます。`lstrip('0')`、空の文字列の場合はゼロにマップされます。 これにより、完全なキャンセルやゼロヘビーの結果などのケースが確実に正しく処理されます。 

## 実用的な例

 ### 例 1: 1000 / 1000

 まずはカウントから始めます。 

- 分子: {1:1、0:3}
 - 分母: {1:1、0:3}

 最初に数字の 0 を検討します。 

| 数字 | 両方に保存してください | 残りの分子 | 残りの分母 |
 | --- | --- | --- | --- |
 | 0 | 0 | 000 | 000 |
 | 0 | 1 | 00 | 00 |
 | 0 | 2 | 0 | 0 |
 | 0 | 3 | | |

 DFS はすべての有効なキャンセルを調査し、暗黙的な正規化を除いてすべての桁が削除され、1 / 1 が得られたときに分子が最小になります。 

これは、空の文字列につながる完全なキャンセルがゼロとして扱われ、正規化によって対称ケースが正しく折りたたまれることを示しています。 

### 例 2: 2232 / 162936

 桁数:

 - 2232: {2:3、3:1}
 - 162936: {1:1、2:1、3:1、6:2、9:1}

 桁 2 と桁 3 は部分的にのみキャンセルできます。 

DFS は、有効な一致をすべて試行します。 

- 0 2 と 0 3 をキャンセルします
 - 1 2 をキャンセル
 - 1 2 と 1 3 をキャンセルします

 最良の結果は、数字 2 を 1 つ削除し、分子 232 を残すことです。 

このトレースは、最適なソリューションが最大のキャンセルではなく選択的なキャンセルに依存していることを示しています。

 ## 特殊なケース

 最初のエッジケースは完全なキャンセルです。 1000 / 1000 のような入力の場合、単純な文字列ベースのアプローチでは、すべての数字を削除した後に空の文字列が生成される可能性があり、無効であると誤って解釈される可能性があります。 このアルゴリズムは空の結果を明示的に 0 に変換し、数値解釈との一貫性を確保します。 

2 番目の特殊なケースは、先行ゼロです。 たとえば、取り消しによって "007 / 123" が生成される場合、桁構築ステップ lstrip('0') により、分子が 7 になることが保証されます。この正規化がなければ、比較で同じ整数の異なる表現が別のものとして誤って扱われてしまいます。 

3 番目のエッジ ケースは、周波数が異なるために一方が他方よりも多くの桁を失う可能性がある非対称キャンセルです。 DFS は、数字レベルの実現可能性を強制し、いずれかの数字に出現する数字よりも多く削除される数字がないことを保証します。
