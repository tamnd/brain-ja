 ## 解決策
 ## 問題の理解

 正の整数の配列が与えられます。 目標は、一連の操作を使用してすべての値をゼロに減らすことです。 1 回の操作でインデックスのリストを選択します$B_1, B_2, \dots, B_m$。 の$i$このリストの - 番目の位置は、次の減算に寄与します。$2^{i-1}$対応する配列要素に$A_{B_i}$。 同じ配列インデックスは同じ操作内で複数回出現する可能性があり、各出現箇所には、選択したシーケンス内の位置に応じて異なる 2 のべき乗が与えられます。 

重要な自由度は、各操作で重みのセットを分散できることです。$1, 2, 4, 8, \dots, 2^{m-1}$配列全体で任意の順序で配置されますが、各重みは操作ごとに 1 回だけ使用されます。 

タスクは、すべての配列値がゼロになるように、必要なそのような操作の数を最小限に抑えることです。 

制約により、最大で$10^5$テスト スイートあたりの要素の合計数 (最大値は次のとおり)$10^9$。 これは、操作を段階的にシミュレートするアプローチは不可能であることを直ちに示唆しています。 The structure of powers of two strongly hints at a bitwise or binary decomposition viewpoint, since each operation is essentially providing a “budget” of one copy of each power of two.

 単純な推論が失敗する理由を明らかにする微妙なケースは、ある数値が大きく、他の数値が小さい場合です。 For example, if we try to greedily fix large elements first, we may waste small powers inefficiently, even though reassigning which element receives which power would reduce the number of operations. 正しいソリューションでは、すべての要素にわたって 2 の各べき乗が使用される頻度をグローバルにバランスさせる必要があります。 

## アプローチ

 ブルートフォース解釈では、操作を直接シミュレートします。 各操作で、シーケンスを割り当てようとします。$1, 2, 4, \dots$すべての値がゼロになるまで配列を更新しながら、何らかの順序でインデックスを作成します。 割り当ての選択について賢明だったとしても、各操作は構造化された値のセットを削除するだけであり、潜在的に$O(\max A_i)$減少の合計はオペレーション全体に広がります。 値が到達できるので、$10^9$、このアプローチは直ちに実行不可能です。 

ターニングポイントは、オペレーションが実際に何を提供するのかを再解釈することです。 各操作は、2 の累乗のそれぞれのコピーを 1 つだけ提供します。$2^k$すべて有効な$k$選択した長さまで。 すべての操作にわたって、各電力の回数を効果的に決定しています。$2^k$が使用され、各使用法は操作ごとに 1 つの配列インデックスに正確に割り当てられる必要があります。 

これにより、問題がスケジュール ビューに変換されます。 ビット位置ごとに$k$、使用するたびに$2^k$あらゆる分解において$A_i$、操作の「ビット層」で 1 単位の容量を消費します。 各操作は各ビット層の最大 1 つのユニットを提供するため、操作の数は少なくともすべてのビット層の最大負荷でなければなりません。 残りの疑問は、この境界が厳しくなるようにすべての数値の分解を常に選択できるかどうかです。答えは自然なバイナリ分解を使用することで「はい」です。これにより、下位ビットの混雑を増大させるだけの不要な分割が回避されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | 指数 | O(n) | 遅すぎる |
 | ビット層のカウント | O(n log A) | O(log A) | 承認済み |

 ## アルゴリズムのチュートリアル

 各数値を 2 のべき乗の寄与に再定式化します。 

1. あらゆる値について$A_i$、それをバイナリ表現に分解します。 位置に設定された各ビット$k$のインスタンスが 1 つ必要であることを意味します$2^k$インデックスに割り当てられる$i$。 
2. ビット位置全体にわたって周波数配列を維持します。 ビット位置ごとに$k$、そのビットを必要とするインデックスの数を数えます。 
3. 答えは、これらすべてのビット周波数の最大値です。 

この最大値は、アレイ全体で最も「要求される」ビット レベルを表します。 各操作はビット位置ごとに 1 単位の要求しか満たせないため、その層がボトルネックになります。 

### なぜ効果があるのか

 各操作では、2 の累乗ごとに 1 つの利用可能なスロットが提供されます。 列ごとに考えると、各ビット位置は、演算数に等しい容量を持つ並列リソースのように動作します。 配列を分解すると、その電力の使用回数に等しい負荷が各列に発生します。 どの操作も同じ列で複数のユニットにサービスを提供できないため、操作の数は少なくとも最大列負荷である必要があります。 

バイナリ表現を使用すると、列の負荷を軽減せずに列の負荷を増加させる、より小さい累乗の不必要な重複を作成することがなくなります。 したがって、バイナリ分解によって引き起こされるカラム負荷はすでに最小限であり、最大周波数が必要かつ十分になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        cnt = [0] * 31
        
        for x in a:
            b = 0
            while x:
                if x & 1:
                    cnt[b] += 1
                x >>= 1
                b += 1
        
        print(max(cnt))

if __name__ == "__main__":
    solve()
```コードは各テスト ケースを独立して処理します。 すべての数値について、そのバイナリ表現をスキャンし、対応するビット位置のカウンターをインクリメントします。 最終的な答えは、すべてのビット位置にわたる最大カウンター値です。 

実装の微妙な点は、操作自体をシミュレートしようとしていないことです。 ソリューション全体は、ビットごとの周波数のみが重要であるため、カウントの追跡で十分であるという観察に基づいています。 ループは最大 30 ビットで実行されます。これは、以下の値には十分です。$10^9$。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべての数値が同一である場合です。 たとえば、入力の場合`A = [7, 7, 7]`、すべてのビット位置が完全に飽和しています。 このアルゴリズムは各ビットを個別にカウントし、すべての位置で同じ値を返します。 実行するとカウントが生成されます`[3, 3, 3]`したがって、答えは 3 で、各ビットに寄与する要素の数と一致します。 

もう 1 つの特殊なケースは、数値が純粋な 2 の累乗である場合です。 入力用`[1, 2, 4, 8]`、各数値は異なるビット位置をアクティブにするため、複数の要件を蓄積する列はありません。 アルゴリズムは最大 1 を生成し、各操作は競合することなくすべての寄与を独立して処理できます。
