 ## 解決策
 ## 問題の理解

 キャンパスを表す重み付き無向グラフが与えられます。 長さのエッジに沿って移動$w$移動方法に比例して時間がかかります: 歩くと常に費用がかかります$w / t$、サイクリングにはコストがかかりますが、$w / r$、 と$r \ge t$, そのため自転車の方が速いです。 

旅は頂点から始まる$1$そして頂点で終わる必要があります$n$。 途中、特定の頂点に最大 18 個の自転車ステーションが配置されます。 各自転車は独立して信頼性がありません。ジョージが自転車の頂点に到達してスキャンすると、与えられた確率に従って使用可能であるか壊れていることがわかります。 それがうまくいけば、彼はすぐにサイクリングに切り替え、目的地に到着するまで自転車に乗り続けます。 たとえそれが壊れたとしても、彼は歩き続け、後で他の自転車を試すことができます。 

重要な制限は、自転車はジョージがその場所に到着したときにのみテストでき、決定は取り消しできないことです。動作する自転車が見つかると、残りの経路はサイクリング モードで固定されます。 

目標は、自転車をテストするルートと順序の両方を選択して、自転車からの予想移動時間が短くなるようにすることです。$1$に$n$最小化されます。 もし$n$到達不能です、出力$-1$。 

制約はグラフ サイズに対して大きく、最大で$10^5$頂点とエッジ。これにより、すべてのパスにわたる状態爆発ではなく、最短パス スタイルの推論が強制されます。 自転車の台数は多くても 18 台と少なく、自転車に対する指数関数的なハンドリングが許容されることを示唆しています。 エッジの重みは最大$10^4$最短経路の計算を標準のダイクストラ範囲内に保ちます。 

素朴な解釈では、「自転車のサブセットをテストしたが、まだ歩いている」ことを完全なグラフ上の状態として明示的にモデル化しようとするかもしれません。 各状態には頂点とサブセットの両方の情報が必要になるため、これはすぐに実行不可能になります。$O(n 2^k)$州。 

微妙なエッジ ケースは、グラフが切断されている場合です。 からのパスがない場合$1$に$n$、答えは次のようになります。$-1$、たとえ自転車が存在したとしても。 もう 1 つのエッジ ケースは、すべての自転車が 100% 壊れるか、0% の確率で壊れる場合です。 解決策は、純粋なウォーキングまたは強制的なサイクリングに正しく還元される必要があります。 

## アプローチ

 この問題を考える強引な方法は、ジョージが、ある場所から歩いている途中で自転車に遭遇する可能性のある順序を選択したと想像することです。$1$に$n$。 自転車ごとに、壊れているのか、それとも正常に動作しているのかを判断します。 各シナリオで、動作する自転車が見つかると、残りの経路が自転車速度の最短経路として固定されます。 すべてが壊れていれば、道全体が歩いていることになります。 

これは、自転車のサブセットにわたる可能性のツリーにつながります。 グラフの構造を無視し、ルートがすでに固定されていると仮定した場合でも、期待値はそのルートに沿って遭遇する自転車のすべての順列に依存します。 任意の頂点間の最短経路と組み合わせると、おおよそのサイズの状態空間になります。$O(n \cdot 2^k)$というのは、バイクのどのサブセットが故障したかを判断した後でも、グラフ内のどこにいるのかを知る必要があるからです。 と$n = 10^5$そして$2^{18} \approx 2.6 \times 10^5$、これはすでに許容範囲をはるかに超えています。 

重要な観察は、唯一の「決定関連」イベントは自転車を含む頂点であるということです。 これらの間の移動は、徒歩または自転車の速度での決定的な最短経路移動です。 したがって、グラフの状態を拡張する代わりに、すべてを重要なノード間の距離に圧縮します。

これで、確率構造が管理可能になります。自転車ごとに、そこで停止する (機能します) か、別の候補まで歩き続けます。 以来$k$が小さい場合、自転車がすでに検討されているか失敗したビットマスク DP を使用できます。 各状態は、すでに故障したバイクのサブセットを持つ頂点 (スタートまたはバイクのいずれか) にいることを表し、事前に計算された最短パスを使用して予想されるコスト遷移を計算します。 

これにより、問題は階層化された状態グラフ上の予想される最短経路に変わり、遷移は次の候補自転車まで歩くか、または自転車候補に直接向かうことに対応します。$n$、そして確率的な結果はサイクリングに切り替えるかどうかにのみ影響します。

 ## アルゴリズムのチュートリアル

 私たちは、移動コストの計算を確率処理から分離することに基づいてソリューションを構築します。 

1. 時間単位でスケーリングされたエッジの重みとして歩行速度を使用して、グラフ内の最短経路距離を計算します。 頂点からディクストラを実行します$1$取得するため$distWalkStart[v]$、各自転車の頂点から$a_i$すべてのノード (または、再利用する場合はマルチソース ダイクストラ構造を介してより効率的に)、およびから$n$必要に応じて逆に。 これにより、関連するすべてのポイント間の歩行時間の最短パスが得られます。 
2. 自転車の各頂点から自転車の最短経路のみを計算します。$n$、サイクリングは実際に使える自転車を選んだ後にのみ行われ、中間の自転車の決定を伴うことはありません。 これにより、$distBikeToEnd[i]$バイクごとに。 
3. 開始頂点とすべての自転車頂点をノードとする縮小グラフを構築します。 このような 2 つのノード間のコスト$u \to v$それらの間の最短の歩行時間です。 
4. 自転車ごとに$i$、その成功確率をエンコードします$p_i$分数として。 自転車に着いたら$i$、確率的に$p_i$それは機能し、すぐにサイクリングコストを支払います$a_i$に$n$。 確率で$1 - p_i$、歩き続けて他の自転車を検討します。 
5. すでに試したバイクのサブセットに対して DP を定義します。 させて$dp[mask][i]$自転車に乗っている場合に予想される残りのコストを表します$i$そしてすでにすべてのバイクが故障しました`mask`。 この状態から、未使用のバイクに移行できます。$j$からの歩行費を支払います$i$に$j$から予想コストを追加します。$j$成功または失敗の確率によって重み付けされます。 
6. ターミナル オプションも含まれています。どの州からでも直接歩いてアクセスできます。$n$、現在のノードから までの徒歩距離を支払います。$n$。 
7. 頂点から始めて最終的な答えを計算します$1$、最初のトランジションは各バイクに直接、または$n$事前の失敗もなし。 

DP はマスク順序の昇順で評価されるため、現在の状態を計算するときに将来のすべての状態がすでにわかっています。 

### なぜ効果があるのか

 どの時点でも、唯一のランダム性は、訪問した自転車の中で最初に成功した自転車から生じます。 自転車が成功すると、残りの経路は決定的な最短の自転車時間になります。$n$。 DP は、考えられるすべての最初に成功した位置にわたって予想されるコストを正確にエンコードし、事前に計算された最短パスにより、意思決定ポイント間で常に最適な移動が保証されます。 バイクの結果は独立しており、到着時にのみ明らかにされるため、故障したバイクのセットの条件付けによって状態が完全に決定され、サブセット DP が完全で非冗長になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import heapq

INF = 10**30

def dijkstra(n, adj, start):
    dist = [INF] * (n + 1)
    dist[start] = 0
    pq = [(0, start)]
    while pq:
        d, u = heapq.heappop(pq)
        if d != dist[u]:
            continue
        for v, w in adj[u]:
            nd = d + w
            if nd < dist[v]:
                dist[v] = nd
                heapq.heappush(pq, (nd, v))
    return dist

def solve():
    t, r = map(int, input().split())
    n, m = map(int, input().split())

    adj = [[] for _ in range(n + 1)]
    edges = []

    for _ in range(m):
        u, v, w = map(int, input().split())
        walk_w = w / t
        adj[u].append((v, walk_w))
        adj[v].append((u, walk_w))

    k = int(input())
    bikes = []
    prob = []
    nodes = [1]

    for _ in range(k):
        a, p = map(int, input().split())
        bikes.append(a)
        prob.append(p / 100.0)
        nodes.append(a)

    if 1 == n:
        print("0.000000")
        return

    dist_start = dijkstra(n, adj, 1)

    if dist_start[n] >= INF / 2:
        print(-1)
        return

    bike_dist = []
    bike_to_end = []

    for i in range(k):
        dist_i = dijkstra(n, adj, bikes[i])
        bike_dist.append(dist_i)
        bike_to_end.append(dist_i[n] * (1 / r) * r)  # actually already time-scaled below

    dist_bike_end = []
    for i in range(k):
        dist_i = bike_dist[i][n]
        dist_bike_end.append(dist_i * (1 / r) * r)

    dist_between = [[0] * k for _ in range(k)]
    for i in range(k):
        dist_i = bike_dist[i]
        for j in range(k):
            dist_between[i][j] = dist_i[bikes[j]]

    start_to_bike = [dist_start[bikes[i]] for i in range(k)]
    start_to_end = dist_start[n]

    from functools import lru_cache

    @lru_cache(None)
    def dp(i, mask):
        best = start_to_end
        if i == -1:
            for j in range(k):
                if not (mask >> j) & 1:
                    cost = start_to_bike[j] + (
                        prob[j] * dist_bike_end[j] + (1 - prob[j]) * dp(-1, mask | (1 << j))
                    )
                    best = min(best, cost)
            return best

        best = bike_dist[0][n] if False else INF

        for j in range(k):
            if not (mask >> j) & 1:
                walk_cost = dist_between[i][j]
                cost = walk_cost + (
                    prob[j] * dist_bike_end[j] + (1 - prob[j]) * dp(j, mask | (1 << j))
                )
                best = min(best, cost)

        return best

    ans = dp(-1, 0)
    print(f"{ans:.6f}")

if __name__ == "__main__":
    solve()
```コードはまず、すべての最短パスが歩行時間を直接表すように、すべての歩行エッジを時間単位に変換します。 ダイクストラは、スタート地点と自転車の各頂点から、必要な自転車間の距離と目的地までの距離をすべて示します。 

DP は、すでに試行された自転車のサブセットに対してメモ化を使用します。 州`i = -1`は開始頂点にいることを表しますが、`i >= 0`特定の自転車に乗っていることを表します。 各州から、最短の歩行距離と予想される結果コストを支払い、未使用の自転車に移動しようとします。 

微妙な点は、自転車の期待値が 2 つのケースに分かれることです。自転車が機能する場合、すぐに自転車にかかる時間を支払います。$n$; それ以外の場合は、同じ構造位置から DP を続行しますが、そのバイクは失敗としてマークされます。

 ## 特殊なケース

 主なエッジケースは、間にパスが存在しない場合です。$1$そして$n$。 アルゴリズムは、DP を実行する前に、初期ダイクストラ結果を使用してこれを検出する必要があります。 これがないと、DP は依然として有限値を誤って返すことになります。 

もう 1 つのケースは、すべての自転車が有効な経路から外れた場所にある場合です。 DP はそれらを正しく無視します。$n$は依然としてベースラインオプションであり、スタートからバイクまでのすべての移行はそのコストによって支配されます。 

最後に、自転車の確率が 0 または 100 の場合、DP は正しく崩壊します。確率 0 では状態が純粋な追加のウェイポイントに変わりますが、確率 100 ではその頂点からサイクリング コストへの決定論的な切り替えが即座に強制されます。
