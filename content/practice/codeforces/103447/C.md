 ## 解決策
 ## 問題の理解

 私たちには根の生えた木が与えられており、最終目標にとって重要なのは葉だけです。 すべてのリーフにはすでに必要な最終色が設定されていますが、内部ノードにはターゲット カラーがまったくありません。 最初は何も塗られていません。 ノードを選択する操作を繰り返し実行できます。`x`そして色`c`次に、サブツリー内のすべての葉を再描画します。`x`色を付ける`c`、以前に存在したものはすべて上書きされます。 私たちの仕事は、すべての葉が必要な色になるように、できるだけ少ない操作を使用することです。 

重要な点は、操作は単一のリーフに限定されず、サブツリー全体にフラッディングされますが、影響を受けるのはリーフのみであるということです。 内部ノードは、どのリーフがグループ化されるかを定義する単なる構造です。 

制約`n ≤ 10^5`本質的に線形または線形に近いものが必要であることを意味します。 操作をシミュレートしたり、リーフのサブセットを明示的に考慮したりしようとするソリューションは、すぐに遅すぎます。 各エッジまたはノードが少数回のみ処理される、ツリー DP または DSU-on-tree スタイルのアプローチが必要です。 

貪欲な直感が微妙に失敗するケースは、同じ色の複数の葉が木の異なる部分に広がっている場合に現れます。 

たとえば、ルートに 3 つの子ブランチがあり、それぞれに色付きの葉が含まれているとします。`1`、しかしそれらの枝は根までつながっていません。 各葉を個別に扱う場合、3 つの操作が必要であると想定できます。 実際には、ルートでの 1 回の操作で、それらすべてを一緒にペイントできます。 したがって、木の中で同じ色が現れる構造は、葉の数と同じくらい重要です。 

もう 1 つのよくある落とし穴は、サブツリー結合を取得することで各色を個別に解決できると仮定していることです。 これは、1 回の操作でサブツリー全体が描画されるため、ツリー構造内の重複を通じて色が相互作用するためです。 

## アプローチ

 直接的な総当たり的なアイデアは、考えられるすべての操作シーケンスを考えることです。 各ステップでノードと色を選択して適用し、目標の構成に到達することを試みます。 単一のパスにも多くの選択肢があり、各操作がツリーの大部分に影響を与える可能性があるため、これはすぐに爆発します。 分岐因子は、`O(n)`ステップごとに深さを指定することもできます`O(n)`、これは完全に不可能になります。 

より構造化された強引な方法は、逆に考えることです。 色を先に構築する代わりに、各リーフに最後の操作を割り当てることを想像できます。 各リーフは、祖先ノードでの操作によって正しい色で「カバー」される必要があります。 ただし、異なるリーフが同じサブツリー内にあり、最終的な色が同じであれば、異なるリーフでも同じ操作を共有できます。 問題は、同じ色の葉を再利用可能なサブツリー操作にグループ化することになります。 

重要な観察は、重要なのは個々の葉ではなく、同じ色の葉がツリー構造を通じてどのように接続されているかであるということです。 同じ色の 2 つの葉が、あるノードの異なる子枝にある場合でも、そのノード以上で 1 回の操作でそれらを統合できます。 それらがルートの前で決して交わることのない木の完全に別個の部分にある場合、それらはより上位の祖先を除いて統合することはできません。 

これにより、明確な再定式化が行われます。色ごとに、その色を持つ葉だけを見て、それらがツリー内で形成される連結コンポーネントの数を考慮します。 このような各コンポーネントには少なくとも 1 つの操作が必要です。単一のサブツリー操作では、他の色に誤って影響を与えることなく、切断された異なる部分の葉に同時に影響を与えることはできないからです。 

答えは、葉によって形成される連結成分の数のすべての色の合計になります。 

これを効率的に計算するために、ボトムアップのトラバーサルを実行し、ノードごとに、そのサブツリーにどの色が表示されるかを維持します。 子サブツリーを結合するときに、複数の子に同じ色が表示される場合、それらの出現は、このノードでマージされる個別のコンポーネントに対応するため、必要な操作が軽減されます。 

各ノードについて、色からその色を含む子サブツリーの数までのマップを維持します。 色が複数の子に現れるたびに、マージをカウントします。 これは、小規模から大規模のセットを結合することで効率的に実装できます。

 ## アルゴリズムのチュートリアル

 1. ツリーをルート化し、事後走査を実行して、子が親の前に処理されるようにします。 これにより、ノードを処理するときに、各子サブツリーにどのような色が存在するかをすでに知ることができます。 
2. 各ノードについて、リーフ間のサブツリーに表示される色のセットを維持します。 このセットは、リーフレベルの詳細を保存せずに、「このノードの下でどの色がアクティブであるか」を表します。 
3. 各ノードで周波数マップも維持します。`freq[c]`色を含むさまざまな子サブツリーの数を数えます`c`。 葉の数ではなく、子サブツリーにその色が少なくとも 1 回含まれているかどうかだけを数えます。 
4. ノードの各子を処理し、小規模から大規模の戦略を使用してそのカラー セットを親にマージします。 マージ中に、子から挿入されたすべての色について、現在のノード内のその色の頻度カウントを更新します。 
5. すべての子がマージされたら、ノードの周波数マップをスキャンします。 各色ごとに`c`に表示されている場合は、`k`さまざまな子サブツリー、次にこれら`k`出現はに対応します`k`このノードで出会う別々のコンポーネント。 私たちは説明しなければなりません`k - 1`それらを統合するためにマージするので、`k - 1`答えに。 
6. ノードの結果の色のセットは、すべての子セットの単純な結合です。 これはその親に上向きに渡されます。 
7. 最終的な答えは、すべてのノードにわたるこれらすべての「マージ コスト」の合計です。 

これが正しい理由は、各色の葉が元の木に限定されると森を形成するためです。 同じ色の 2 つのコンポーネントがノードで出会うたびに、そのノードがそれらを統合できる最初の場所となり、追加の各コンポーネントを最初のコンポーネントにマージするには 1 回の操作を支払う必要があります。 アルゴリズムはこれらの必要なマージを正確にカウントしますが、それ以上はカウントしません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

from collections import defaultdict

def solve():
    n = int(input())
    p = list(map(int, input().split()))
    c = list(map(int, input().split()))

    g = [[] for _ in range(n)]
    for i, par in enumerate(p):
        g[par - 1].append(i + 1)

    # DSU on tree: store set of colors in subtree
    sets = [set() for _ in range(n)]
    freq = [defaultdict(int) for _ in range(n)]
    ans = 0

    def dfs(u):
        nonlocal ans

        # initialize leaf color
        if c[u] != 0:
            sets[u].add(c[u])

        for v in g[u]:
            dfs(v)

            # small-to-large merge
            if len(sets[u]) < len(sets[v]):
                sets[u], sets[v] = sets[v], sets[u]
                freq[u], freq[v] = freq[v], freq[u]

            # merge child v into u
            for col in sets[v]:
                if col not in sets[u]:
                    sets[u].add(col)
                freq[u][col] += 1

        # count merges needed at this node
        for col, cnt in freq[u].items():
            ans += max(0, cnt - 1)

    dfs(0)
    print(ans)

if __name__ == "__main__":
    solve()
```DFS はサブツリー情報をボトムアップで構築します。 の`sets[u]`構造は下にどの色が存在するかを追跡します`u`、 その間`freq[u]`各色に寄与する子サブツリーの数を追跡します。 各色は対数的に何度もセット間を移動するだけであるため、全体の複雑さを線形に近い状態に保つには、小から大への交換が非常に重要です。 

微妙な点は、インクリメントのみであることです。`freq[u][col]`葉ごとではなく、色ごとに子サブツリーごとに 1 回。 これにより、多重度ではなく構造の存在をカウントしていることが保証されます。 

## 実用的な例

 ルートに 2 つの子があり、それぞれが色を持つ葉である木を考えてみましょう。`1`そして`2`。 

最初に左の葉を処理し、次に右の葉を処理します。 

| ノード | マージされた子セット | ノードの周波数 | 回答に追加されました |
 | --- | --- | --- | --- |
 | 葉1 | {} → {1} | {1:0 内部} | 0 |
 | 葉2 | {} → {2} | {2:0 内部} | 0 |
 | ルート | {1} + {2} | {1:1、2:1} | 0 |

 複数の子サブツリーには色が表示されないため、マージコストは追加されません。 ただし、リーフごとに 1 つずつ、合計 2 つの操作がまだ必要です。 これは、各リーフが独自のシングルトン コンポーネントを形成するという事実から来ています。 

次に、3 つの子を持つルートを考えます。各サブツリーには色の葉が含まれています。`1`。 

| ノード | マージされた子セット | ノードの周波数 | 回答に追加されました |
 | --- | --- | --- | --- |
 | 葉A | {1} | {1:0} | 0 |
 | 葉B | {1} | {1:0} | 0 |
 | 葉C | {1} | {1:0} | 0 |
 | ルート | {1}+{1}+{1} | {1:3} | 2 |

 根元にカラーを`1`は 3 つの異なる子サブツリーに出現するため、追加します`3 - 1 = 2`。 これは 3 つの別々のコンポーネントを 1 つにマージすることに相当し、2 つの操作が必要になります。 

これは、アルゴリズムが、同じ色が上位ノードでのみ接続されるタイミングを捕捉することを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | 小さいものから大きいものへのマージにより、各色はセット間で限られた回数だけ移動されます。 
| スペース | O(n) | 各ノードは、最大でもそのサブツリーに存在する色を格納します。 

制約`n ≤ 10^5`実際には各操作はほぼ線形であるため、この複雑さの範囲内に快適に収まります。

 ## 特殊なケース

 重要なエッジケースは、すべての葉が同じ色を共有しているが、異なる枝にまたがっている場合です。 このアルゴリズムは、内部ノードでの複数の子サブツリーの出現を正確に識別し、それらがより高いレベルで統合されるまで必要なマージを蓄積し、効果的な操作が 1 つだけ残ることを保証します。 

もう 1 つの重要なケースは、すべての葉が異なる色を持つ場合です。 この状況では、どのノードでも頻度カウントが 1 を超えないため、マージはカウントされず、答えはリーフの数に等しくなります。これは、グループ化が不可能であるため、各リーフを独立して処理する必要があることを反映しています。 

最後に、歪んだ木は鎖のように動作します。 チェーンでは、各ノードには子が 1 つだけあるため、兄弟間のマージは発生しません。 周波数マップは 1 を超える値を生成しません。これは、線形構造ではブランチ間の最適化が不可能であるという事実と一致します。
