 ## 解決策
 ## 問題の理解

 数値の長方形グリッドが与えられます。 各セルについて、セル自体も含め、そのセルと同じ行または同じ列にあるすべての値を調べます。 これらすべての値の中で、現在のセルの値が最小であるかどうかを確認します。 タスクは、この条件を満たすセルの数を数えることです。 

別の考え方としては、すべてのセルがその行と列で構成される「十字」を定義しているということです。 その十字内の最小値を取得し、その最小値に等しいセルの数を数えたいとします。 

グリッド サイズは 1000 x 1000 まで大きくでき、最大 100 万セルになります。 行と列全体を直接スキャンして各セルを検査するソリューションでは、セルごとに約 2n または 2m の作業が行われる可能性があり、最悪の場合はおよそ 10^12 の操作が必要になります。 これは 1 秒の制限をはるかに超えています。 

行または列内で最小値が繰り返されると、微妙なエッジ ケースが発生します。 たとえば、行が`1 2 1`、両方のセルに次の内容が含まれています`1`行の観点からは候補ですが、列を考慮するとそのうちの 1 つが失敗する可能性があります。 

もう 1 つの注意が必要な状況は、行の最小値と列の最小値が一致しない場合です。 セルは行では最小値であっても列では最小値ではない場合や、その逆の場合があるため、両方の制約の結合を常に正しく考慮する必要があります。 

## アプローチ

 素朴な考えは単純です。 細胞ごとに`(i, j)`、行全体をスキャンします`i`最小値を見つけるために、列全体もスキャンします。`j`最小値を見つけます。 次に、セル値をこれら 2 つの結果の最小値と比較します。 一致した場合はカウントされます。 

これは正しいです。行と列の和集合の最小値は、単に行の最小値と列の最小値の最小値であるからです。 ただし、セルごとにこれらの最小値を再計算するのは無駄です。 各行スキャンのコストは O(m)、各列スキャンのコストは O(n)、すべての n·m セルに対してこれを行うと O(n·m·(n+m)) になります。これは最悪の場合、定数に応じて約 2x10^9 ～ 2x10^12 の演算となり、遅すぎます。 

重要な点は、行の最小値と列の最小値がクエリ セルに依存しないことです。 それらはグリッド構造のみに依存します。 したがって、各行と各列の最小値を 1 回事前計算できます。 その後、各セルを行の最小値と列の最小値の小さい方と比較することで、一定時間内にチェックできます。 

これにより、前処理後のグリッド上の 1 回のパスで問題が軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n・m・(n+m)) | お(1) | 遅すぎる |
 | 最適 | O(n・m) | O(n+m) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず 2 つの補助配列を計算します。1 つは各行の最小値を格納し、もう 1 つは各列の最小値を格納します。 

1. 配列を初期化する`rowMin`サイズの`n`、非常に大きな値で埋められています。 これにより、各行に表示される最小値が保存されます。 
2. 配列を初期化する`colMin`サイズの`m`、これも非常に大きな値で埋められています。 これにより、各列に表示される最小値が保存されます。 
3. マトリックス全体を 1 回スキャンします。 細胞ごとに`(i, j)`、 アップデート`rowMin[i] = min(rowMin[i], a[i][j])`そして`colMin[j] = min(colMin[j], a[i][j])`。 このステップでは、すべてのセルにわたって線形時間ですべての行と列の正確な最小値を構築します。 
4. 前処理後、マトリックスを再度スキャンします。 細胞ごとに`(i, j)`、計算する`t = min(rowMin[i], colMin[j])`。 もし`a[i][j] == t`、答えを増やします。 
5. 最終的なカウントを出力します。 

私たちが採用する理由`min(rowMin[i], colMin[j])`それは行内の値の和集合です`i`そしてコラム`j`行または列のいずれかに最小値があります。 すべての要素はこれら 2 つのセットのいずれかですでに考慮されているため、これより小さい値を取得するソースは他にありません。 

### なぜ効果があるのか

 あらゆる細胞に対して`(i, j)`、クロスで考慮されるすべての値はいずれかの行に属します`i`または列`j`。 その和集合の最小値は、行内の最小要素のいずれかでなければなりません`i`または列内の最小の要素`j`、どちらか小さい方。 前処理ステップにより、これらの値が全体的に正しいことが保証されます。 したがって、比較すると、`a[i][j]`と`min(rowMin[i], colMin[j])`セルがクロスで最小値に達しているかどうかを正確にチェックし、誤って分類されるセルはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = [list(map(int, input().split())) for _ in range(n)]
    
    INF = 10**18
    rowMin = [INF] * n
    colMin = [INF] * m

    for i in range(n):
        for j in range(m):
            v = a[i][j]
            if v < rowMin[i]:
                rowMin[i] = v
            if v < colMin[j]:
                colMin[j] = v

    ans = 0
    for i in range(n):
        for j in range(m):
            if a[i][j] == min(rowMin[i], colMin[j]):
                ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```この解決策は、グリッドをメモリに読み取ることから始まります。データを 2 回渡す必要があるため、これが必要になります。 最初のパスでは、行と列の最小値を独立して構築します。 これにより、後でスキャンを繰り返す必要がなくなります。 

2 番目のパスでは、実際の状態のチェックが実行されます。 表現`min(rowMin[i], colMin[j])`は O(1) で計算されるため、各セルは一定の作業に貢献します。 これは、コストのかかる総当たり検索に代わるステップです。 

よくある実装上の間違いは、2 番目のループ内で行または列の最小値を再計算しようとすることです。 これにより、n または m の余分な係数が暗黙的に再導入され、パフォーマンスが低下します。

 ## 特殊なケース

 1×1 グリッドは最も単純な境界です。 行と列は同じ単一要素であるため、両方の最小値が値に等しいため、単一セルをカウントする必要があります。 アルゴリズムが初期化されます`rowMin[0]`そして`colMin[0]`その値に設定すると、最終チェックはすぐに合格します。 

すべてのエントリが同一である均一行列では、すべての行の最小値と列の最小値は同じ値になります。 あらゆる細胞に対して`(i, j)`、`min(rowMin[i], colMin[j])`はセル値と等しいため、すべてのエントリがカウントされます。 2 番目のパスでは、例外なくすべての位置が正しくインクリメントされます。 

1 つの行に非常に小さな値が含まれているのに列には含まれていない場合、ほとんどの比較では行の最小値が優先されます。 このアルゴリズムは、評価前に常に正しいグローバルな行と列の最小値を再計算し、ローカル構造や走査順序に依存しないようにするため、引き続き機能します。
