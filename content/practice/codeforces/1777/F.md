 ## 解決策
 ## 問題の理解

 負ではない整数のシーケンスが与えられ、すべての連続したセグメントを調べるように求められます。 セグメントごとに、セグメント内のすべての要素のビット単位の XOR と、同じセグメント内の最大要素の 2 つの値を計算します。 セグメントの「しびれ」は、これら 2 つの値の XOR として定義されます。 

タスクは、すべてのサブアレイにわたって可能な最大の無感覚を見つけることです。 

この制約は、すべてのテスト ケースにわたる配列サイズが最大 2⋅10^5 であることを意味するため、テスト ケースごとに 2 次の動作を伴うソリューションは不可能です。 サブ配列の直接 O(n^2) 列挙をクエリごとに O(1) または O(log n) と組み合わせても、すべてのテストでおよそ 2⋅10^10 個のサブ配列が必要になるため、最悪の場合でも依然として遅すぎます。 

この困難は、XOR と最大という 2 つのグローバル サブ配列統計の相互作用によって生じます。 XOR はプレフィックス操作では適切に動作しますが、最大値は動作しません。 この不一致が主要な障害です。 

また、単純な実装では、エンドポイントを修正したり部分配列を貪欲に拡張して「最適化」しようとした場合、微妙な点で失敗します。これは、最大値を増やすと XOR 構造が単調でない方法で変更されることが多いためです。 

たとえば、次のように考えてみましょう`[1, 2, 3]`。 サブアレイ`[2, 3]`最大 3 と XOR 1 があり、3 ⊕ 1 = 2 となります。`[1, 2, 3]`max を 3 に増やしますが、XOR は 0 になり、3 ⊕ 0 = 3 となります。`[3]`3 ⊕ 3 = 0 となります。部分配列のサイズと結果の間には単調な関係はないため、拡張や固定最大値に基づく貪欲な戦略は失敗します。 

## アプローチ

 ブルート フォース アプローチでは、すべてのサブ配列を列挙し、それらの XOR と最大値を計算し、最良の結果を追跡します。 プレフィックス XOR を使用すると、XOR 部分は O(1) になりますが、前処理しない限り、最大コストは依然として O(n) になります。 疎テーブルの場合でも、前処理はクエリに役立ちますが、それでも O(n^2) 個の部分配列があり、これは制限をはるかに超えています。 

重要な構造的洞察は、視点を逆転させることです。サブ配列を反復処理して最大値を計算する代わりに、最大値の候補値を固定し、その値が最大であるサブ配列のみを考慮します。 部分配列の最大値が値 x に等しいことがわかっている場合、部分配列内のすべての要素は最大でも x であり、少なくとも 1 つの要素は x に等しいことになります。 これは、要素が x を超える位置を中心に配列を分割することを示唆しています。 

これは、最大値に対する標準的な分割統治の考え方につながります。 グローバルな最大位置によって配列を再帰的に分割します。 その最大値を含まないサブ配列は完全に一方の側に属し、それを含むサブ配列はそれを最大制約アンカーとして扱う必要があります。
