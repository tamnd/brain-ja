 ## 解決策
 ## 問題の理解

 この問題は、重み付き有向グラフを提供し、オプションでエッジを反転することによって、あるノードから「強く到達可能」にするように要求します。 反転のコストは、反転することを選択した最も重いエッジの重みであり、私たちの目標は、この最大値を最小限に抑えることです。 グラフがすでに何らかのノードから強力に到達可能である場合、コストはゼロであり、エッジを反転した後でも完全な到達可能性を達成することが不可能な場合、答えは -1 になります。 

入力には複数のテスト ケースが含まれており、各テスト ケースには最大 200,000 個のノードと 200,000 個のエッジがありますが、すべてのテスト ケースにわたるノードとエッジの合計が 200,000 を超えることはありません。 この制約は、テスト ケースごとに線形よりも遅いアルゴリズム、理想的には線形または対数係数を伴う線形を許容できないことを意味します。 大きなエッジの重量は次のとおりです。$10^9$重量による直接のカウントを除外する。 考えられるすべての重みを反復処理するのではなく、それらを抽象的な数値として扱う必要があります。 

ナイーブ エッジ ケースは、単一の反転シーケンスによってどのノードからも到達できない形でグラフが切断されたときに発生します。 たとえば、エッジのない 2 つのノードで構成されるグラフでは、存在しないエッジを反転する必要がありますが、これは不可能です。 もう 1 つのエッジ ケースは、すでに順方向に完全に接続されているグラフです。この場合、正解はゼロでなければならず、不注意な実装により誤って正の重みが追加される可能性があります。 

## アプローチ

 ブルートフォース手法では、エッジのすべてのサブセットの反転を試み、各ノードからの到達可能性をチェックし、最小の最大重みを持つサブセットを選択します。 これは明らかに実行不可能です。$2^m$サブセット、および$m$200,000 に達する可能性があります。 サブセットごとに各ノードの到達可能性をテストすると、この値はさらに倍増します。 

重要な洞察は、強く接続されたコンポーネントとエッジ到達可能性のしきい値の観点から問題を捉えることです。 エッジのすべてのサブセットを試す代わりに、反転するエッジの可能な最大重みに対して二分探索を実行できます。 特定の候補の最大重みについて$W$、エッジがより重いグラフを構築します。$W$を反転することはできません。重みのあるエッジのみを反転するときに、他のすべてのノードに到達できるノードが存在するかどうかを確認します。$\le W$。 

候補に対するすべてのノードからの到達可能性を確認する$W$2 パスの深さ優先検索を使用して最適化できます。 元のエッジと反転が許可されているエッジを介して到達可能なノードのセットを計算し、いずれかのノードが他のすべてのノードに到達するかどうかをテストします。 これにより、検索スペースが減少します。$\log(\text{max weight})$線形時間 DFS の反復。 

エッジの重みに対する二分探索と線形時間到達可能性チェックを組み合わせることで、効率的なソリューションが生成されます。 単純な方法は、エッジの数に応じて組み合わせが爆発的に増加するため失敗しますが、二分探索では実現可能性の単調性が利用されます。つまり、指定された最大の重みが機能する場合は、より大きな重みも機能します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^m * (n+m)) | O(n+m) | 遅すぎる |
 | 二分探索 + DFS | O((n+m) * log(最大重量)) | O(n+m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取り、それぞれを繰り返し実行します。 テスト ケースごとに、グラフのノード、エッジ、および重みを読み取ります。 エッジをタプル (u、v、w) のリストに保存します。 
2. すべてのエッジの重みを並べ替えて重複を削除します。 これにより、二分探索に使用する候補最大反転重みのセットが得られます。 実現可能性は既存のエッジの重みでのみ変化するため、一意の重みを使用します。 
3. 二分探索用に 2 つのポインターを初期化します。`low`0として、そして`high`グラフ内の最大エッジの重みとして使用されます。 
4. ながら`low <= high`、 選ぶ`mid`を反転エッジの最大重みの候補として使用します。 より重いエッジが含まれる隣接リストを作成します。`mid`元の方向とエッジを保持します$\le mid$反転することもできます (これらのエッジについては両方向をモデル化します)。 
5. 現在の隣接リストについては、任意のノードから DFS を実行します。 到達可能なノードの数が等しい場合`n`、候補の重みが機能します。 二分探索を調整します。成功した場合は移動します。`high`に`mid - 1`より小さい実現可能な重みを検索します。 それ以外の場合は移動する`low`に`mid + 1`。 
6. 二分探索の後、次の場合`low`エッジの最大重みを超えているか、実行可能な重みが見つからない場合、出力は -1 です。 それ以外の場合は出力`low`反転の最小最大ウェイトとして。 

なぜ機能するのか: この問題には単調な実現可能性の特性があります。つまり、最大の重みでエッジを反転するすべてのノードに到達することができれば可能です。$W$、それならどれでも可能です$W' > W$。 二分探索はこの単調性を利用します。 DFS は、現在の候補最大重みの下で到達可能なノードのみを考慮し、正しい実現可能性チェックを生成します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(1 << 25)

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        edges = []
        weights = set()
        for _ in range(m):
            u, v, w = map(int, input().split())
            edges.append((u-1, v-1, w))
            weights.add(w)
        weights = sorted(weights)

        def can_reach(max_w):
            adj = [[] for _ in range(n)]
            for u, v, w in edges:
                if w > max_w:
                    adj[u].append(v)
                else:
                    adj[u].append(v)
                    adj[v].append(u)
            visited = [False]*n
            stack = [0]
            visited[0] = True
            while stack:
                node = stack.pop()
                for nei in adj[node]:
                    if not visited[nei]:
                        visited[nei] = True
                        stack.append(nei)
            return all(visited)

        if can_reach(0):
            print(0)
            continue

        l, r = 0, len(weights)-1
        ans = -1
        while l <= r:
            mid = (l+r)//2
            if can_reach(weights[mid]):
                ans = weights[mid]
                r = mid - 1
            else:
                l = mid + 1
        print(ans)

solve()
```このソリューションでは、最初に元のグラフが完全な到達可能性を許可しているかどうかを確認します。 次に、一意のエッジの重みに対して二分探索を実行します。 隣接リストは、現在の候補重み内でエッジの反転を可能にするように構築されます。 DFS は到達可能なノードを調査し、実現可能性の結果に応じてバイナリ検索が実行されます。 最悪の場合のツリーで深い DFS 呼び出しを処理するために、再帰制限が増加しました。 

## 実用的な例

 ### 例 1

 グラフ: 2 ノード、1 エッジ 1→2 重み 3。 

| ステップ | アクション | DFS 結果 | 説明 |
 | --- | --- | --- | --- |
 | イニシャル | 逆転せずに到達可能性をチェック | ノード 1 がノード 2 に到達 | すでに到達可能、コスト 0 |

 出力: 0

 ### 例 2

 グラフ: 4 つのノード、2 つのエッジ 4→2 (5)、4→3 (20)。 

| ステップ | 中程度の体重 | DFS に到達可能 | 二分探索 |
 | --- | --- | --- | --- |
 | 0 | 5 | ノード 4 はすべてのノードに到達します | 可能です、もっと小さくしてみてはいかがでしょうか？ これ以上の重み、ans=5 |
 | 結果 | 5 | | 最小最大反転ウェイト |

 出力: 5

 これらの例は、重要な不変条件、つまり最大反転ウェイトが増加した場合の単調な実現可能性を示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n+m) * log m) | エッジの重みに対する二分探索とチェックごとの線形 DFS |
 | スペース | O(n+m) | 隣接リストと訪問先配列 |

 すべてのテスト ケースにわたって sum(n)+sum(m) ≤ 2*10^5 という制約がある場合、この解は効率的です。 DFS と隣接リストの構築は n+m で線形であり、バイナリ検索は最大 m 個の一意の重みに対して反復されます。
