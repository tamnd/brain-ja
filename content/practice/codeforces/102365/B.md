 ## 解決策
 ## 問題の理解

 最大100人の戦闘機がいます。 各戦闘機は名前と 3 つの統計 (健康、攻撃、防御) で説明されます。 2 人の戦闘機が出会うと、各ラウンドで両側に固定ダメージが与えられます。 ファイターが受けるダメージは、相手の攻撃から自分の防御を引いたもので、ゼロに固定されます。 両方のダメージ値が同時に適用されます。 

タスクは、ペアごとの結果が有向サイクルを形成する 3 人の戦闘機のすべてのセットを見つけることです。 3 人のファイター A、B、C の場合、これは、1 人のファイターが 2 番目のファイターに勝ち、2 番目のファイターが 3 番目のファイターに勝ち、3 番目のファイターが最初のファイターに勝つことを意味します。 引き分けは勝利としてカウントされないため、サイクル内のすべてのエッジは実際の勝利を表す必要があります。 

最初の入力行は N を示し、その後に N 戦闘機の説明が続きます。 出力は有効なトリプルの数で始まり、その後にそのようなトリプルごとに 1 行が続きます。 トリプルの順序と各トリプル内の 3 つの名前の順序には制限がありません。 

制約 N <= 100 は O(N^3) にとって十分小さいので、考えられるすべての 3 つのグループを検査できることを意味します。 私たちには、すべてのトリプル内のすべてのペアについて何千もの戦闘ラウンドを繰り返しシミュレートする余裕はありません。 100 人の戦闘機の場合、C(100, 3) = 161,700 のトリプルが存在し、すべての戦闘を直接シミュレートした場合、潜在的に数百万または数十億のラウンド操作が行われます。 したがって、有用な目標は、すべてのペアごとの戦闘を一定時間にし、トリプルのチェックにのみ O(N^3) を費やすことです。 

体力、攻撃力、防御力の値は最大でも 10,000 です。 Python の整数は、関連するすべての積を簡単に処理できるため、オーバーフローの問題はありません。 さらに重要なのは、最大体力は、プラスのダメージが与えられた後に戦闘機​​を倒すのに必要な弾数を制限しますが、その事実に基づいて直接シミュレーションを行うのは、依然としてコストがかかりすぎます。 

不注意な実装が間違っている可能性があるいくつかの特殊なケースがあります。 1つ目は、どちらの戦闘機も相手にダメージを与えられない戦いです。 例えば、```
1
Solo 500 500 500
```には対戦相手がいないので、答えは単純にゼロです。 より一般的には、両方のダメージ値がゼロの場合、戦いは決して終わらず、引き分けとして扱われなければなりません。 ダメージがゼロであることを確認せずに、1 つの健康値が正でなくなるのを待つシミュレーションは、永久にループすることになります。 

2 番目のエッジケースは同時死亡です。 次の統計を持つ 2 人の戦闘機について考えてみましょう。```
2
A 4 6 1
B 10 3 1
```A は B にラウンドごとに 5 ダメージを与え、B は A にラウンドごとに 2 ダメージを与えます。B は 2 ラウンド後に死亡し、A も 2 ラウンド後にゼロになります。 結果はA勝利ではなく引き分け。 勝利条件は厳格です。殺害ラウンドの後、勝者はまだ健康状態が良好でなければなりません。 

3 番目のエッジケースは、一方の戦闘機が他方の戦闘機を倒すのに数ラウンドが必要な場合に発生します。 A が B にラウンドごとに 5 ダメージを与え、B の HP は 10 から始まり、B は A にラウンドごとに 2 ダメージを与えるとします。A の HP が 5 の場合、両方の戦闘機は 2 ラウンド後に死亡します。 A の HP が 6 であれば、A はそのラウンドを生き延びて勝ちます。 次のような非厳密な比較を使用する`<=`最終的なヘルステストでは、最初のケースが誤って成功として分類されてしまいます。 

最後に、引き分けが戦闘機の結果のグラフで誤ってエッジになってはなりません。 引き分けを含むトリプルは、たとえ他の 2 つのペアの試合が勝ったとしても自動詞トリプルになることはできません。 

## アプローチ

 直接的なアプローチは、戦闘機のすべてのトリプルを列挙し、自動詞かどうかを判断するために必要な 3 つの戦闘をシミュレートすることです。 自動詞トリプルの定義はこれら 3 つのペアごとの結果のみに依存するため、これは正しいです。 戦闘が一度に 1 ラウンドずつシミュレートされる場合、1 人の戦闘機が死亡するか戦闘が引き分けと認識されるまで、各ラウンドで両方の体力値が更新されます。 

問題は繰り返し作業です。 N が 100 の場合、可能なトリプルは 161,700 通りあります。各トリプルには 3 回の戦闘が必要で、ラウンドあたりのダメージが 1 ポイントのみの場合、戦闘には最大 10,000 ラウンドが必要になる場合があります。 これにより、最悪の場合の上限は約 48 億 5,000 万のシミュレーションラウンドとなります。 多くの入力では実際の数値はこれより小さくなる可能性がありますが、これは 1 秒の制限には決して適しません。 

重要な観察は、戦闘には実際にはラウンドごとのシミュレーションが必要ないということです。 固定された対戦相手に対して、両方の戦闘機は毎ラウンドまったく同じダメージを受けます。 各戦闘機が何ラウンド死ぬ必要があるかを計算し、これら 2 つの数値を直接比較できます。 

A が B と戦っているとします。`damage_to_A = max(0, AT_B - DF_A)`そして`damage_to_B = max(0, AT_A - DF_B)`。 

もし`damage_to_B`が陽性の場合、B はその後死亡します`ceil(HP_B / damage_to_B)`ラウンドします。 まさにそのラウンドで、A の残りの体力がプラスになったときに、A が勝ちます。 したがって、次の場合に A が B に勝ちます。`ceil(HP_B / damage_to_B) * damage_to_A < HP_A`。 

B が A の相手にダメージを与えることができない場合、つまり`damage_to_B`がゼロの場合、B は決して死ぬことができないため、A は勝つことができません。 同じ推論で逆の方向も処理できます。 

これにより、すべてのペアごとの戦闘が O(1) になります。 すべての順序付きペアの勝者を 1 回事前計算し、結果をブール行列に保存できます。 その後、トリプルをチェックするには、いくつかのブール演算のみが必要になります。 強引なアイデアは外側のレベルではまだ残っていますが、高価な部分は削除されています。 

したがって、2 つのアプローチ間の関係は単純です。 このブルートフォース ソリューションは、すべてのトリプルを個別にチェックできるため機能しますが、同じ戦闘シミュレーションを繰り返し実行するため失敗します。 戦闘ではラウンドごとに一定のダメージがあるという観察により、すべてのシミュレーションを算術計算に置き換えることができます。 すべてのペアごとの結果がキャッシュされたら、O(N^3) 内のすべてのトリプルをチェックするのは十分に高速です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N^3・H) | お(1) | 遅すぎる |
 | 最適 | O(N^2 + N^3) = O(N^3) | O(N^2) | 承認済み |

 ここで、H はシミュレートされたラウンドの最大数で、最大 10,000 までの可能性があります。 

## アルゴリズムのチュートリアル

 1. すべての戦闘機を読み取り、名前、健康状態、攻撃力、防御力を保存します。 ファイターを入力順に維持して、インデックスの各組み合わせが`i < j < k`まさに 3 人の戦闘機の 1 セットを表します。 
2. N 行 N 列のブール行列を作成します`win`。 値`win[i][j]`ファイターIがファイターJに勝つことを意味します。 欠損値または false 値は、i が勝てないことを意味します。これには、負けと引き分けの両方が含まれます。 
3. 異なる戦闘機 A と B の順序付けされたペアごとに、A が B から受けるダメージと B が A から受けるダメージを計算します。これらの値は戦闘中に決して変化しないため、個々のラウンドをシミュレートする理由はありません。 
4. B の A に対するダメージがゼロの場合、A の体力は決してゼロにはならないため、A が B を倒すことはできません。 それ以外の場合は、B が死ぬ必要があるラウンド数を次のように計算します。`(HP_B + damage_to_B - 1) // damage_to_B`。 これらのラウンド中に A が受けるダメージが A の開始時の体力よりも厳密に小さい場合に、A が勝ちます。 
5. 結果を次の場所に保存します`win[A][B]`。 注文したペアごとにこれを繰り返します。 戦いの結果は必ずしも対称的ではないため、両方の方向を考慮する必要がありますが、実際には 1 つのペアの計算で両方を決定で​​きます。 
6. すべてのトリプルを列挙する`i < j < k`。 結果がいずれかの向きでサイクルを形成する場合、トリプルは有効です。 チェックします`i beats j`、`j beats k`、`k beats i`、または逆のサイクル`i beats k`、`k beats j`、`j beats i`。 

出力ではどの戦闘機が最初に出現する必要があるかが規定されていないため、両方の方向を確認することが重要です。 有向サイクルを形成する 3 人の戦闘機の場合、これら 2 つの方向のうちの 1 つが正確​​に一致します。 
7. 有効なトリプルをすべて保存し、最後にそのカウントとそれに続く 3 つの対応するファイター名を出力します。 インデックスのみを考慮しているため、`i < j < k`、同じ戦闘機のセットを 2 回出力することはできません。 

なぜ機能するのか: 前処理後、`win[A][B]`これは、B のヘルスがゼロになったラウンドの後に、A のヘルスがプラスになったときに正確に真となります。 B はラウンドごとに同じ正の金額を失うため、ラウンド数の計算式は正確です。 B がダメージを受けることができない場合、保存された結果は false となり、引き分けまたは A が勝てない状況を正しく表します。 したがって、すべてのエッジは、`win`マトリックスはまさに本当の勝利を表しています。 アルゴリズムは、3 つのインデックスごとに、これら 3 つのエッジが有向サイクルを形成するタイミングを正確に受け入れます。これはまさに自動詞トリプルの定義です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    fighters = []
    for _ in range(n):
        name, hp, atk, defense = input().split()
        fighters.append((name, int(hp), int(atk), int(defense)))

    win = [[False] * n for _ in range(n)]

    for i in range(n):
        name_a, hp_a, atk_a, def_a = fighters[i]

        for j in range(n):
            if i == j:
                continue

            name_b, hp_b, atk_b, def_b = fighters[j]

            damage_to_a = max(0, atk_b - def_a)
            damage_to_b = max(0, atk_a - def_b)

            if damage_to_b == 0:
                continue

            rounds_to_kill_b = (
                hp_b + damage_to_b - 1
            ) // damage_to_b

            if rounds_to_kill_b * damage_to_a < hp_a:
                win[i][j] = True

    answer = []

    for i in range(n):
        for j in range(i + 1, n):
            for k in range(j + 1, n):
                cycle_1 = (
                    win[i][j]
                    and win[j][k]
                    and win[k][i]
                )

                cycle_2 = (
                    win[i][k]
                    and win[k][j]
                    and win[j][i]
                )

                if cycle_1 or cycle_2:
                    answer.append(
                        (fighters[i][0], fighters[j][0], fighters[k][0])
                    )

    print(len(answer))
    for a, b, c in answer:
        print(a, b, c)

if __name__ == "__main__":
    solve()
```入力ループは各戦闘機を次のように格納します。`(name, HP, AT, DF)`。 3 つの統計をすぐに整数に変換すると、後の算術が単純になります。 

ペアごとの前処理は、4 番目と 5 番目のアルゴリズム ステップに続きます。 A 対 B の場合、`damage_to_b`B が各ラウンドで失う金額です。 ゼロの場合、B の HP は決してゼロにはならないため、A は勝つことができず、行列のエントリは false のままになります。 

いつ`damage_to_b`が正の場合、天井除算は、B の健康状態が正でない正確な最初のラウンドを計算します。 表現`(hp_b + damage_to_b - 1) // damage_to_b`は、上限除算の標準的な整数のみの形式です。 Python の任意精度の整数でも乗算が可能`rounds_to_kill_b * damage_to_a`特別な取り扱いをしなくても安全です。 

比較は意図的に厳密に行われています。 製品が等しい場合`hp_a`, そのラウンドではAもゼロになるため、戦いは引き分けとなります。 勝利に必要なのは`rounds_to_kill_b * damage_to_a < hp_a`。 

トリプルループは使用します`i < j < k`したがって、順序のない 3 人の戦闘機のセットはすべて 1 回だけ表示されます。 2 つのサイクル式は、有向 3 サイクルの可能な両方の方向をカバーします。 ドローはどちらの式も満たさない。これは、ドローは誤ったエントリによって表されるためである。`win`。 

最終的なプログラムには戦闘シミュレーションは登場しません。 すべてのペアは数回の算術演算に削減され、すべてのトリプルは 6 つのブール検索に削減されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N^3) | O(N^2) ペアごとの前処理と O(N^3) のトリプル列挙 |
 | スペース | O(N^2) | 勝者行列には、順序付きペアごとに 1 つの結果が格納されます。 

N = 100 の場合、トリプル列挙では 161,700 の組み合わせのみが検査されます。 ペアごとの前処理では 10,000 個の順序付きペアが検査され、それらのループ内のすべての操作は定数時間です。 これは、明記された制限内に十分収まります。 

## テストケース```python
import sys
import io

def solve():
    input = sys.stdin.readline

    n = int(input())
    fighters = []

    for _ in range(n):
        name, hp, atk, defense = input().split()
        fighters.append((name, int(hp), int(atk), int(defense)))

    win = [[False] * n for _ in range(n)]

    for i in range(n):
        _, hp_a, atk_a, def_a = fighters[i]

        for j in range(n):
            if i == j:
                continue

            _, hp_b, atk_b, def_b = fighters[j]

            damage_to_a = max(0, atk_b - def_a)
            damage_to_b = max(0, atk_a - def_b)

            if damage_to_b == 0:
                continue

            rounds = (hp_b + damage_to_b - 1) // damage_to_b

            if rounds * damage_to_a < hp_a:
                win[i][j] = True

    answer = []

    for i in range(n):
        for j in range(i + 1, n):
            for k in range(j + 1, n):
                if (
                    (win[i][j] and win[j][k] and win[k][i])
                    or
                    (win[i][k] and win[k][j] and win[j][i])
                ):
                    answer.append((
                        fighters[i][0],
                        fighters[j][0],
                        fighters[k][0]
                    ))

    result = [str(len(answer))]
    for a, b, c in answer:
        result.append(f"{a} {b} {c}")

    return "\n".join(result)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    try:
        return solve()
    finally:
        sys.stdin = old_stdin

 サンプル テストでは、次によって生成される決定論的な順序が使用されます。`i < j < k`。 この問題は任意の順序を受け入れるため、別の有効な実装では同じトリプルを別の順序で出力する可能性があります。 

## 特殊なケース

 ダメージゼロの場合は天井分割前に処理されます。 A が B にダメージを与えることができない戦いを考えてみましょう。`AT_A <= DF_B`。 それから`damage_to_b`はゼロなので、B の健康状態は決して減少しません。 アルゴリズムはすぐに記録します`win[A][B] = False`。 たとえば、`A 100 10 100`そして`B 100 10 100`, ダメージ値は両方ともゼロなので、戦いは引き分けです。 このアルゴリズムは、無限のシミュレーションを試みることはありません。 

同時死亡事件は厳重に処理されます。`<`比較。 と```
2
A 4 6 1
B 10 3 1
```お得`6 - 1 = 5`Bがダメージを与える間、Bにダメージを与える`3 - 1 = 2`Aへのダメージ。Bがゼロになるまで`ceil(10 / 5) = 2`ラウンドします。 Aが取った`2 * 2 = 4`ダメージ、まさにその初期状態。 以来`4 < 4`は誤りです、`win[A][B]`偽のままです。 逆方向も false なので、結果は正しく引き分けとして扱われます。 

正確な最終ラウンド境界は、反対側からの同じ比較です。 この例で A の HP が 4 ではなく 5 であれば、A は次のようになります。`5 - 4 = 1`B死亡後のHPなので`4 < 5`は true となり、A が勝ちます。 Changing one HP changes the result exactly where the game rules say it should.

 A fighter that takes no damage from an opponent is also handled correctly. Suppose A has defence 100 and B has attack 1. Then A's incoming damage is`max(0, 1 - 100) = 0`。 A は無限に生き残ることができますが、それだけでは A が勝つことを意味しません。 アルゴリズムは、A が最終的に B を倒すことができるかどうかを個別にチェックします。A が与えるダメージもゼロの場合、結果は引き分けになります。 A がプラスのダメージを与えた場合、A が生き残ったまま B は最終的に死亡するため、A が勝ちます。 

最後に、トリプルが両方の方向でチェックされます。 結果が次のようになったとします。`A beats B`、`B beats C`、 そして`C beats A`。 インデックスがたまたま A、C、B の順序になっている場合、最初のサイクル式はそのインデックスの順序と一致しませんが、その逆の式は一致します。 両方向をチェックすると、結果は戦闘機の入力順序から独立したものになります。 すべてのトリプルは依然として 1 回だけ生成されるため、`i < j < k`、これにより出力が重複することはありません。
