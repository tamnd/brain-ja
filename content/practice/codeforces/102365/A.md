 ## 解決策
 ## 問題の理解

 シーザー暗号を使用して小文字の単語を変換する必要があります。 入力は最初に、エンコードするかデコードするかを指示します。 エンコーディングはすべての文字を固定シフトで前方に移動します`s`一方、デコードではすべての文字が同じ量だけ後方に移動します。 アルファベットは循環するので、過去に移動します`z`から続く`a`、そしてその前に移動します`a`から続く`z`。 

たとえばシフトの場合`4`、手紙`x`になる`b`エンコード中は前方の 4 つの位置が次のとおりであるため、`y`、`z`、`a`、`b`。 デコード中に、`b`になる`x`逆も同じ理由です。 

最初の入力行は次のいずれかです`E`または`D`、2 番目にはシフトが含まれます`s`、3番目には単語が含まれています。 単語には 1 ～ 100 個の小文字が含まれます。 単語が非常に短いため、単純な文字ごとのシミュレーションでも十分に高速です。 シフトは最大 25 であるため、一度に 1 つのアルファベット位置を移動する実装であっても、最大でパフォーマンスが向上します。`100 * 25 = 2500`キャラクターの動き。 

興味深いのはパフォーマンスではなく、巡回アルファベットを正しく処理することです。 次のような直接的な文字比較`ord(c) + s`結果が合格した場合、小文字の範囲外の値が生成される可能性があります`z`。 文字を 0 ～ 25 の数値に変換し、モジュロ 26 を使用すると、境界の問題を完全に回避できます。 

単一文字の単語は、最小サイズの場合に便利です。 入力用`E`、 シフト`1`、そして単語`a`、答えは`b`。 誤って 1 を超える長さの単語のみを処理する実装は、ここで失敗します。 

どちらかの端での折り返しが主な境界ケースです。 たとえば、エンコーディング`z`による`1`与える`a`の後の文字ではありません`z`ユニコードで。 同様にデコードすると、`a`による`1`与える`z`。 モジュロ 26 を使用せずに文字コードに単純に加算または減算する不注意な実装では、無効な文字が生成されます。 

シフトは、アルファベットの境界までの距離よりも大きくなる場合もあります。 と`E`、 シフト`25`、そして単語`b`、結果は`a`。 シフトを循環演算を行わない通常の整数の加算として考えると、これらのケースは誤って処理されやすくなります。 

## アプローチ

 直接のブルートフォース実装では、各文字をアルファベットの 1 つの位置に繰り返し移動することで処理できます。 すべての文字について、一度に 1 ステップずつシフトを実行し、次から折り返します。`z`に`a`またはから`a`に`z`必要に応じて。 これは正しいです。1 つの有効なアルファベット遷移を繰り返し適用すると、要求されたシーザー シフトが正確に生成されるからです。 

最大 100 文字と最大 25 のシフトにより、最大 2500 の単一位置の移動が実行されます。 これは 1 秒のプログラムの限界には遠く及ばないため、このアプローチは実際には所定の制約に対して受け入れられます。 その弱点は、不必要な作業を実行し、演算の単純な数学的構造を曖昧にしてしまうことです。 

重要な観察は、アルファベットにはちょうど 26 の位置があり、それらの位置がサイクルを形成しているということです。 代表する`a`0として、`b`1 として、スルー`z`25. エンコードは次のようになります。`(value + s) % 26`、デコード中は`(value - s) % 26`。 Python のモジュロ演算は負の値を正しく処理するため、デコード`a`シフト付き`1`自然に位置 25 が生成されます。`z`。 

ブルートフォース手法が機能するのは、1 ステップの移動を繰り返すと最終的には同じ目的地に到達するためです。 アルファベットが固定サイクルであるという観察により、これらすべての個々の動きを 1 つのモジュラー算術演算に置き換えることができます。 結果として得られるアルゴリズムでは、文字ごとに 1 つの変換が必要になります。

 ## アルゴリズムのチュートリアル

 1. 演算種類、シフトを読み取る`s`、そしてその言葉。 演算タイプによって、シフトをすべての文字に加算するか減算するかが決まります。 
2. 次のコマンドを使用して、各文字をゼロから始まるアルファベットの位置に変換します。`ord(c) - ord('a')`。 これにより、アルファベットが便利な数値範囲にマップされます。`0`を通して`25`。 
3. 操作がエンコードである場合は、次の値を追加します。`s`位置まで。 操作がデコードの場合は、減算します。`s`。 方向は 2 つの操作の定義と直接一致します。 
4. 申請する`% 26`結果の位置に移動します。 これによりアルファベットが循環するため、25 を超える値は先頭に折り返され、負の値は末尾に折り返されます。 
5. 結果の位置を小文字に変換し直します。`chr(position + ord('a'))`を答えに追加します。 
6. 変換された単語を出力します。 各入力文字は個別に変換されるため、すべての文字を処理すると、完全な暗号化または復号化された単語が生成されます。 

### なぜ効果があるのか

 反復ごとに、現在の応答文字は、対応する入力文字のシーザー変換を正確に表します。 ゼロから始まるアルファベットの位置は次のように増加します。`s`エンコードの場合、または次のように減少します。`s`モジュロ 26 は、その移動後の巡回アルファベット上の固有の位置を識別します。 変換は各文字に対して独立して正しいため、変換されたすべての文字を連結すると、必要な単語が正確に得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

operation = input().strip()
s = int(input())
word = input().strip()

result = []

for c in word:
    pos = ord(c) - ord('a')

    if operation == 'E':
        pos = (pos + s) % 26
    else:
        pos = (pos - s) % 26

    result.append(chr(pos + ord('a')))

print(''.join(result))
```最初の 3 行は、入力形式と同じ順序で演算、シフト、およびワードを読み取ります。`strip()`実際の小文字の単語を保持しながら、各行から改行を削除します。 

各キャラクターごとに、`ord(c) - ord('a')`は 0 から 25 までの値を生成します。モジュロ演算がアルファベットの位置に正確に対応するため、ASCII 値を直接操作するよりもこの方法が適しています。 

エンコード ブランチは、モジュロ 26 を取得する前にシフトを追加します。デコードでは、代わりに減算が使用されます。 パイソンの`%`演算子は、負の結果を 0 ～ 25 の範囲にマッピングし直します。`(0 - 1) % 26`は`25`。 これはデコードを処理します`a`の中へ`z`特別な境界条件はありません。 

Python では文字列は不変であるため、結果はリストに蓄積されます。 各文字を追加して 1 回結合するのは簡単で、直線的な時間で実行されます。 

関与する最大位置は小さいため、整数オーバーフローの懸念はありません。 重要な実装の詳細は、アルファベットの境界でのラップアラウンドを忘れるのではなく、加算または減算の後にモジュロ 26 を取得することです。

## テストケース```python
import sys
import io

def solve():
    input = sys.stdin.readline

    operation = input().strip()
    s = int(input())
    word = input().strip()

    result = []

    for c in word:
        pos = ord(c) - ord('a')

        if operation == 'E':
            pos = (pos + s) % 26
        else:
            pos = (pos - s) % 26

        result.append(chr(pos + ord('a')))

    print(''.join(result))

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()
    output = sys.stdout.getvalue().strip()

    sys.stdin = old_stdin
    sys.stdout = old_stdout

    return output

assert run("E\n3\nhello\n") == "khoor", "sample 1"
assert run("D\n3\njreeohghbjrrn\n") == "gobbledeygook", "sample 2"

assert run("E\n1\na\n") == "b", "minimum-size encoding"
assert run("D\n1\na\n") == "z", "minimum-size decoding with wraparound"
assert run("E\n1\nzzzzzzzzzzzzzzzzzzzz\n") == "aaaaaaaaaaaaaaaaaaaa", "all-equal boundary case"
assert run("D\n25\nabcdefghijklmnopqrstuvwxyz\n") == "bcdefghijklmnopqrstuvwxyza", "maximum shift and full alphabet"
assert run("E\n25\nb\n") == "a", "large shift crossing the alphabet boundary"

 ## 特殊なケース

 最小サイズの入力`E`、 シフト`1`、 言葉`a`生成する`b`。 アルゴリズムは変換します`a`位置 0 に 1 を追加し、位置 1 を取得します。これは、次のように変換されます。`b`。 単語に複数の文字が含まれるという想定はありません。 

順方向ラップアラウンドについては、次のことを考慮してください。`E`、 シフト`1`、 言葉`z`。 キャラクター`z`位置は 25 です。シフトを追加すると 26 になり、`26 % 26`は 0 なので、結果は次のようになります`a`。 文字コードを直接追加すると、この動作は起こりません。 

逆方向ラップアラウンドについては、次のことを考慮してください。`D`、 シフト`1`、 言葉`a`。 位置は 0 であり、シフトを減算すると次のようになります。`-1`。 Python が評価する`-1 % 26`25 なので、結果は次のようになります`z`。 これは、正しいモジュラー演算と非負の位置のみを処理する実装を区別する主なケースです。 

大きなシフトの場合は、次のことを考慮してください。`E`、 シフト`25`、 言葉`b`。 の位置`b`は 1 なので、変換された位置は次のようになります。`(1 + 25) % 26 = 0`。 出力は`a`。 これにより、アルファベットの境界に近いシフトに対してのみ特別なルールを誤って使用する実装が捕捉されます。 

最後に、のみを含む単語を考えてみましょう。`z`キャラクターなど`E`、 シフト`1`、 言葉`zzzz`。 すべての文字は独立して位置 25 から位置 0 にマップされ、`aaaa`。 文字ごとの不変式は、すべての文字が同じ境界条件を適用する場合でも有効です。
