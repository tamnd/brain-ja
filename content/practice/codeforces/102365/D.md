 ## 解決策
 ## 問題の理解

 1 から (N) までの番号が付けられた惑星があり、フェスティバルはまさにそのうちの 1 つで開催されます。 Astrodavid は惑星 1 から開始します。(d>0) 惑星によるジャンプには (f_d) のコストがかかり、(d<0) 惑星によるジャンプには (f_d) のコストがかかります。入力により、(J) までの変位ごとにこれらのコストが与えられます。 

着陸するたびに、Astrodavid は道を尋ねることができます。 答えは、隠された祭りの惑星が現在の惑星より小さいか、同じか、それより大きいかを示します。 目標は、可能なすべてのフェスティバルの場所に最終的に到達できるように、ジャンプを適応的に選択し、すべての可能な場所で消費される最大総燃料を最小限に抑えることです。 

情報を間隔として考えるのが便利です。 ある惑星 (p) をクエリすると、フェスティバルがより高いという応答は、考えられる惑星を接尾辞に制限しますが、より低い応答はそれらを接頭辞に制限します。 したがって、この戦略は、ノードがクエリ対象の惑星であるデシジョン ツリーとなり、2 つのクエリ間の移動には方向に依存するコストがかかるというさらなる複雑さが伴います。 

公式の制約には (2\le N\le4000) と (1\le J\le N/2) があります。 3 次動的プログラムでは、すでに約 (4000^3=64) 億の基本遷移が必要となり、1 秒の制限をはるかに超えています。 意図した解は (O(N^2)) 付近にとどまる必要があります。 ジャンプ コストは最大 (10^4) であるため、Python 整数を使用するとオーバーフローの懸念がなくなりますが、合計の答えは 64 ビット整数に快適に収まります。 

簡単な境界ミスが 2 つあります。 まず、惑星 1 はすでに無料でクエリされています。 たとえば、```
2 1
7
3
```答えは 0 ではなく 7 です。フェスティバルは惑星 2 で行われる可能性があり、ジャンプできるのは (+1) だけだからです。 次に、惑星 1 はすでにチェックされているため、最初の有用な間隔には惑星 1 ～ (N) ではなく惑星 2 ～ (N) が含まれます。 

さらに微妙な問題は、最適な戦略がフェスティバルに向けて単調に進む必要はないということです。 例えば、```
4 2
100 0
0 0
```燃料をゼロで使用するシーケンス (1\to3\to2\to4) が可能になります。 3 から 2 へのジャンプは、3 よりも高いことが知られているフェスティバルから遠ざかりますが、船は最後の 4 へのジャンプが自由になる位置に配置されます。 すべてのジャンプがターゲットに向かって移動する必要があると仮定する解決策はどれも正しくありません。 

## アプローチ

 ダイレクト インターバル ダイナミック プログラムは自然な開始点です。 現在考えられる惑星が間隔を形成しており、船がその間隔の一端のすぐ外側にあると仮定します。 区間の (k) 番目の惑星を次のクエリとして選択すると、1 つの答えは (k-1) 個の候補を残し、もう 1 つの答えは残りの候補を残します。 ジャンプ後に必要な燃料は、これら 2 つの分岐の要件の最大値です。 

次のクエリに移動するコストがわかっている場合、これにより正しいミニマックス反復が得られます。 問題は、アストロダビッドが方向がすでにわかっているにもかかわらず、純粋に船の位置を変更するためにそれらのジャンプを使用して、いくつかのジャンプを行う可能性があることです。 前のセクションの例は、このような再配置を無視すると間違った答えが生成される理由を示しています。 

重要な観察は、次の有用な比較の前に行われる一連のジャンプを可能な限り最小限の燃料コストに圧縮できるということです。 コストは変位のみに依存するため、この再配置問題自体は、1 次元の並進不変グラフ上の最短経路問題になります。 これらの有効な移動コストが判明すると、検索部分は区間ミニマックス DP になります。 

正味変位 (d) の場合、(g_d) を正確に (d) 個の惑星によって移動するのに必要な最小燃料とし、任意の中間ジャンプを許可します。 単一の有用なクエリに関連するディスプレイスメントのみが必要です。 これらの実効コストは、(-J) から (J) までの変位に対する最短経路計算を使用して計算されます。 変位 (x) から (x+i) への移行には (f_i) のコストがかかります。 

結果として得られる有効コストにより、間隔 DP は再位置決めシーケンス全体を 1 つの動作として扱います。 検索の繰り返しでは、次の比較が行われる位置を考慮するだけで済みます。 

ブルート フォース インターバル DP は、(O(N^3)) 時間を与えて、インターバルごとに考えられるすべての分割を検査します。 最適化された定式化には、有効コストの計算後に (O(NJ)) 個の検索遷移があり、(J\le N/2) 個あるため、これは (O(N^2)) になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース インターバル DP | (O(N^3)) | (O(N^2)) | 遅すぎる |
 | 有効移動コスト + 間隔 DP | (O(NJ+J^2)) | (O(N+J)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 変位状態 (-J、-J+1、\ldots,J) で有向移動グラフを構築します。 状態 (x) から (i) のジャンプは (x+i) に移動しますが、その結果生じる変位が考慮された範囲内に留まり、コスト (f_i) がかかることが条件となります。 変位 0 から最短パス計算を実行します。変位 (d) までの結果として得られる距離は、正味変位 (d) を実現する最も安価な方法です。 
2. それらの最短経路距離から有効な上りおよび下りの移動コストを抽出します。 有用なクエリは、(d) 右側の惑星のコスト (g_d) に達しましたが、(d) 左側の惑星のコスト (g_{-d}) に達しました。 
3. (L[m]) を、船がすぐ左側にある場合に、(m) 個の連続する候補惑星の間で祭りを見つけるために必要な最小限の最悪の場合の燃料として定義します。 船がすぐ右側にある場合、(R[m]) を対称的に定義します。 空の間隔の値はゼロです。 
4. (L[m]) を計算するには、次にクエリされる惑星を左から (k) 番目の候補として選択します。 それに到達するには (g_k) の費用がかかります。 フェスティバルがその惑星の下にある場合、(k-1) 人の候補者が残っており、船はそのすぐ右側にあり、コストは (R[k-1]) になります。 フェスティバルがその上にある場合、(m-k) 人の候補者があり、船はそのすぐ左側にあり、コストは (L[m-k]) になります。 最悪の分岐は、これら 2 つの値の最大値にコストがかかります。 
5. すべての実行可能値 (k) の最小値を取得します。 したがって、

 \min_{1\le k\le\min(J,m)}
 \左(
 g_k+\max(R[k-1],L[m-k])
 \右）。 
]

1. (R[m]) を対称的に計算します。 右から数えて (k) 番目の惑星の場合、ジャンプのコストは (g_{-k}) になります。 より低いフェスティバルでは、右側に船が表示される (m-k) 人の候補者が残り、より高いフェスティバルでは、左側に船が表示される (k-1) 人の候補者が表示されます。 したがって、

 \min_{1\le k\le\min(J,m)}
 \左(
 g_{-k}+\max(R[m-k],L[k-1])
 \右）。 
]

 1. 惑星 1 は、燃料を消費する前にチェックされることがすでに知られています。 祭りがあれば終わりです。 それ以外の場合、残りの候補は惑星 2 から (N) であり、船はそのすぐ左側にあります。 したがって、必要な初期燃料は (L[N-1]) となります。 

### なぜ効果があるのか

 DP は、間隔ごとに、次の有益な比較を行うことができるすべての可能な惑星を考慮します。 方向応答は残りの候補を正確に 2 つの小さな間隔に分割し、敵はより多くの燃料を必要とする方の分岐を強制することができ、これにより各遷移の最大値が説明されます。 有益な比較間の再配置は可能な限り最短の移動コストに圧縮されるため、そのようなシーケンスを実効移動コストに置き換えることによって戦略が失われることはありません。 考えられるすべての次の比較とすべての結果の分岐が反復によって表されるため、すべての選択肢の最小値がまさに最悪の場合の燃料要件の最小値になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**30

def shortest_displacement_cost(up, down, J):
    size = 2 * J + 1
    offset = J

    dist = [INF] * size
    used = [False] * size
    dist[offset] = 0

    for _ in range(size):
        u = -1
        best = INF

        for i in range(size):
            if not used[i] and dist[i] < best:
                best = dist[i]
                u = i

        if u == -1:
            break

        used[u] = True
        pos = u - offset

        lo = max(-J, pos - J)
        hi = min(J, pos + J)

        for nxt in range(lo, hi + 1):
            if nxt == pos:
                continue

            d = nxt - pos
            if d > 0:
                w = up[d - 1]
            else:
                w = down[-d - 1]

            v = nxt + offset
            nd = best + w
            if nd < dist[v]:
                dist[v] = nd

    return dist

def solve():
    N, J = map(int, input().split())
    up = list(map(int, input().split()))
    down = list(map(int, input().split()))

    dist = shortest_displacement_cost(up, down, J)
    offset = J

    effective_up = [INF] * (J + 1)
    effective_down = [INF] * (J + 1)

    for d in range(1, J + 1):
        effective_up[d] = dist[offset + d]
        effective_down[d] = dist[offset - d]

    left = [0] * N
    right = [0] * N

    for m in range(1, N):
        best_left = INF
        limit = min(J, m)

        for k in range(1, limit + 1):
            cost = effective_up[k]
            branch = max(right[k - 1], left[m - k])
            value = cost + branch
            if value < best_left:
                best_left = value

        left[m] = best_left

        best_right = INF

        for k in range(1, limit + 1):
            cost = effective_down[k]
            branch = max(right[m - k], left[k - 1])
            value = cost + branch
            if value < best_right:
                best_right = value

        right[m] = best_right

    print(left[N - 1])

if __name__ == "__main__":
    solve()
```コードの最初の部分では、変位グラフを構築します。 変位状態は、有用な比較シーケンスが開始された位置から船がどのくらい離れているかを表します。 すべての合法的なジャンプは、正確に対応する入力燃料コストとともに、その排気量を最大 (J) だけ変化させます。 

(2J+1) 個の変位状態しか存在しないため、密なダイクストラ実装が適切です。 (J\le2000) の場合、状態は最大 4001 個あり、可能なすべてのジャンプ長を緩和すると (O(J^2)) の仕事が得られます。 

2 つの有効コスト配列には、各正味変位の最も安いコストが含まれています。 これらは、間隔 DP が再配置シーケンスの内部詳細を無視できるようにするものです。 

配列`left`そして`right`2 つの間隔方向を保存します。 それらのゼロエントリは、すでに識別されたフェスティバルを表すため、候補が残っていないブランチは燃料をゼロに貢献します。 

ループオーバー`m`すべての遷移が以下の間隔のみを参照するため、増加しています。`m`候補者たち。 ループオーバー`k`に止まります`J`ジャンプ力を超える 1 回のジャンプでは有用なクエリに到達できないためです。 

最終的な答えは、`left[N - 1]`、 それよりも`left[N]`なぜなら、惑星 1 は燃料が消費される前に無料でクエリされるからです。 

Python の整数には任意の精度があるため、大きなセンチネル値や蓄積された燃料値がオーバーフローすることはありません。

 ## 特殊なケース

 最小サイズのケースには惑星が 2 つだけあります。 と```
2 1
7
3
```惑星 1 はすぐにチェックされます。 フェスティバルが存在しない場合、それは惑星 2 にあるはずで、唯一可能なジャンプは (+1) で、コストは 7 です。アルゴリズムは次から始まります。`left[0] = right[0] = 0`、計算します`left[1] = 7`、およびプリント`left[1]`。 

コストが等しいと対称的な問題が発生します。 と```
5 2
5 5
5 5
```最良の戦略は、有用なジャンプごとに 5 を支払いながら、残りのインターバルを繰り返し分割することです。 計算された答えは 15 です。両方の移動方向のコストが同じであるため、左右の DP 配列は同じように進化します。 

ゼロコスト移動は、もう 1 つの有用な境界条件です。 と```
4 2
0 0
0 0
```すべての合法的なジャンプは無料です。 DP は間隔サイズごとにゼロを伝播するため、`left[3]`はゼロであり、最終的な答えはゼロです。 

非対称の場合は実装が維持される理由です`left`そして`right`別に。 下向きのジャンプは上向きのジャンプよりもはるかに低コストである可能性があるため、クエリ後の 2 方向の分岐のコストは大きく異なる可能性があります。 隠れたフェスティバルはどちらのブランチにも存在する可能性があるため、反復では常に 2 つのブランチ要件の最大値が選択されます。 

最後に、ジャンプ制限は間隔サイズとは独立して適用する必要があります。 間隔に含まれる候補が (J) 個よりも少ない場合、それらの候補のみが次の有益なクエリとして到達できます。 (J) 個を超える候補が含まれる場合、1 回のジャンプで現在の境界から最大 (J) 個の位置を考慮できます。 の`min(J, m)`limit は両方のケースを off-by-one エラーなしで処理します。
