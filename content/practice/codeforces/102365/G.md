 ## 解決策
 ## 問題の理解

 計数プログラムは、固定された秩序ある宇宙の中を私たちがどれだけ遠くまで移動するかを記述します。 空のプログラムは何も変更しません。`+`次の未使用の要素を取得し、連結により 2 つのプログラムを次々に実行します。`[P]`繰り返す`P`無限に何度でも。 すべてのプログラムは空のセットから開始してユニバースの初期セグメントを生成するため、2 つのプログラムを比較することは、未使用のまま残されている最初の要素の位置を比較することと同じです。 

これらの最初のセグメントを序数として考えると便利です。 有限シーケンス`+`演算により通常の自然数が生成されます。 繰り返し`+`無限は最初の無限序数を与え、通常は (\omega) と書かれます。 (\alpha) を表すプログラムを無限に繰り返すと (\alpha\cdot\omega) が生成されますが、プログラムを次々に実行することは序数加算に相当します。 

例えば、`[+]`(\omega) を表し、`[+]+`(\omega+1) を表し、`[+][+]`(\omega\cdot2) を表します。 表現`+++[+++]`は (3+\omega=\omega) を表します。制限序数の前に有限数を追加しても結果は変わらないためです。 まさにこれが、ここで通常の整数の直感が危険である理由です。 

入力には最大 100 個のプログラムが含まれ、各プログラムの長さは最大 100 です。これは、各式を再帰的に解析し、サイズが式に比例する表現に対してシンボリック操作を実行するのに十分な小ささです。 問題は入力サイズではなく、一部のプログラムが真に無限のオブジェクトを記述しているため、それらを明示的に実行することが正しい一般的な解決策には決してならないという事実です。 

出力は、それらが表す序数によってソートされた元のプログラム文字列です。 同じ序数を表すプログラムは、任意の相対順序で出現できます。 

最初のエッジ ケースは空のループです。 例えば：```
2
[]
+
```正しい出力は次のとおりです。```
[]
+
```

`[]`は空のプログラムを永遠に繰り返しますが、空のプログラムは何も追加しないため、ゼロを表します。 すべての括弧のペアをカウントを進めるものとして扱うと、誤ってその後に配置されてしまいます。`+`。 

もう 1 つのエッジ ケースは、無限ループの前の有限作業です。```
2
+++
+++[+++]
```正しい出力は次のとおりです。```
+++
+++[+++]
```最初のプログラムは (3) を表し、2 番目のプログラムは (3+\omega=\omega) を表します。 目に見えるものだけをカウントする単純な実装`+`文字は 2 番目の式を 3 つの有限ステップ分大きいものと誤ってみなし、ループが限界順序に達するという事実を見逃してしまう可能性があります。 

特に微妙なケースは次のとおりです。```
3
[+]
+[+]
+[+]+
```値はそれぞれ (\omega,\omega,\omega+1) であるため、最初の 2 つは等しく、どちらの順序でも出現でき、その後に続きます。`+[+]+`。 理由`+[+]`(\omega+1) ではありません`[+]`最初の後に永久に実行されます`+`、無限シーケンスは、その最初の要素の後のすべての要素を埋めます。 

## アプローチ

 最も直接的なアプローチは、プログラムによって生成されたセットをシミュレートすることです。 有限シーケンスの場合、`+`操作は簡単ですが、`[P]`無限に多くの繰り返しが必要です。 ある回数 (K) 回繰り返した後ですべてのループを切り捨て、結果として得られる有限のプレフィックスを比較することもできますが、これを正確にする有限 (K) はありません。 プログラム`[+]`そして`[+]+`すべての自然数がすでに生成された後にのみ異なります。 有限の数の操作のみを実行するシミュレーションでは、両方が同じ有限のプレフィックスとして認識されます。 

ネストされたループは明示的な展開をさらに悪化させます。 深さ (d) 式がループ レベルごとに (K) 回繰り返し展開される場合、展開には (\Theta(K^d)) の実行が必要になる場合があります。 長さ 100 の文字列では、ネストの深さは 50 に近づく可能性があるため、(K=100) であっても、(100^{50}=10^{100}) 拡張操作に関して形式的な最悪のケースが発生します。 より根本的には、限界動作自体を記号的に表現する必要があるため、固定有限 (K) は正しいアルゴリズムを提供しません。 

重要な観察は、生成されたすべてのセットが整った順序の初期セグメントであるため、順序タイプとして序数を持っているということです。 使用できる演算は、まさに序数の後続演算、序数の加算、および (\omega) による乗算です。 これらの演算によって生成されるすべての序数は、カントール正規形式で保存できます。 

関連するすべての序数には一意の表現があります

 [
 \omega^{\beta_1}c_1+\omega^{\beta_2}c_2+\cdots+\omega^{\beta_k}c_k,
 ]

 ここで、指数は厳密に減少し、すべての係数は正の有限整数です。 指数自体は序数であり、同じ方法で再帰的に表すことができます。 

これにより、非常に小さな記号オブジェクトが得られます。 あ`+`演算により有限項が 1 ずつ増加します。 2 つのプログラムを連結すると、順序加算が実行されます。 ゼロ以外の序数に先行項 (\omega^\beta c) がある場合、それに (\omega) を乗算すると、先頭の指数を除くすべてが破棄され、(\omega^{\beta+1}) が生成されます。 したがって`[P]`無限反復を 1 回も実行せずに評価できます。 

プログラムを実行すると実際に序数接頭辞が構築されるため、総当り攻撃のアイデアが機能します。 有限シミュレーションでは限界序数に到達できないため、失敗します。 これらのプログラムが序数算術の代数を正確に備えているという観察により、無限実行をカントール正規形の有限操作に置き換えることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 境界がなく、正確な有限カットオフはありません。 無制限 | 遅すぎて一般的には正しくありません |
 | 最適 | (O(M\log M\cdot L^2)) | (O(ML)) | 承認済み |

 ここで、(L\le100) はプログラムの最大長、(M\le100) です。 

## アルゴリズムのチュートリアル

 1. 序数を項のタプルとしてカントール正規形で表現します。 それぞれの用語は、`(exponent, coefficient)`、 どこ`exponent`は別の順序表現です。 空のタプルはゼロを表します。 たとえば、(7) は指数 0 と係数 7 を持つ 1 つの項として表されますが、(\omega+3) には 2 つの項があり、1 つは指数 1、もう 1 つは指数 0 です。 
2. 一致するまで、各プログラムを一連の式として解析します。`]`または文字列の終わり。 あ`+`は序数に寄与しますが、括弧で囲まれた式は再帰的に評価され、(\omega) で乗算されます。 
3. シーケンスの解析中に序数加算を実装します。 右のオペランドがゼロの場合は、何も変わりません。 それ以外の場合は、先頭の指数を (\beta) とします。 左側のオペランドでは、指数が (\beta) より小さいすべての項が破棄されます。これは、より大きな次数の序数が追加されると、より低い次数の項が飲み込まれるためです。 左のオペランドに指数が正確に (\beta) の項がある場合、その係数は右のオペランドの係数だけ増加します。 次に、右オペランドの残りの項が追加されます。 
4. 後継者を別途実装する`+`。 序数が有限の場合、その係数を増加させます。 有限の最後の項がない場合は、係数 1 を持つ新しい (\omega^0) 項を追加します。 この区別は重要です。`+`は 1 つの後続操作ですが、`[+]`は (\omega) を生成する制限演算です。 
5. のために`[P]`、最初に評価します`P`。 それがゼロを表す場合、結果は依然としてゼロです。 それ以外の場合は、その先頭項を (\omega^\beta c) とします。 序数全体 (\alpha) を無限に何度も繰り返すと (\alpha\cdot\omega=\omega^{\beta+1}) になります。 係数とすべての下位項が消えるため、結果として得られる CNF は、指数 (\beta+1) と係数 1 を持つ 1 つの項だけで構成されます。 
6. CNF タプルの自然な辞書編集的な比較を使用します。 まず主要な指数を比較します。 それらが異なる場合は、先行指数が大きい方の順序数が大きくなります。 それらが等しい場合、それらの係数を比較します。 それらも等しい場合は、次の項に進みます。 適切なプレフィックスは、長いタプルよりも小さくなります。 指数は同じ再帰構造で表されるため、Python のタプル比較はまさにこの比較を再帰的に実行します。 
7. 元の各プログラムを正規の序数表現とともに保存し、その表現で並べ替えて元の文字列を出力します。 等しい表現は等しいカウント プログラムに対応するため、その順序は制限されません。 

### なぜ効果があるのか

 不変条件は、任意のプログラム フラグメントを解析した後、その格納されたタプルがそのフラグメントによって表される序数のカントール正規形とまったく同じであるということです。 

あ`+`演算は正確に順序後続であるため、不変式を保持します。 実装された演算はカントール正規形の順序加算の定義であるため、シーケンス連結ではそれが保持されます。 括弧で囲まれた式の場合、本体は序数 (\alpha) を表します。 無限の繰り返しは (\alpha\cdot\omega) を表し、ゼロ以外のすべての (\alpha) について、その積は正確に (\omega^{\beta+1}) になります。ここで、(\beta) は (\alpha) の先頭の指数です。 したがって、再帰的な解析ステップごとに正しい序数が生成されます。 

最後に、カントール標準形は独特であり、その辞書編集的な順序付けは序数順です。 これらの正規表現をソートすると、必要な関係によってプログラムがソートされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

ZERO = ()
ONE = ((ZERO, 1),)

def succ(a):
    """Return a + 1."""
    if not a:
        return ONE

    terms = list(a)

    # If the last term is omega^0 * c, increase c.
    if terms[-1][0] == ZERO:
        exp, coeff = terms[-1]
        terms[-1] = (exp, coeff + 1)
    else:
        # Append omega^0.
        terms.append((ZERO, 1))

    return tuple(terms)

def add(a, b):
    """Return the ordinal sum a + b in CNF."""
    if not a:
        return b
    if not b:
        return a

    beta = b[0][0]

    # Keep terms of a whose exponent is strictly greater
    # than beta. If beta occurs, keep that term too.
    i = 0
    while i < len(a) and a[i][0] > beta:
        i += 1

    result = list(a[:i])

    if i < len(a) and a[i][0] == beta:
        result.append((beta, a[i][1] + b[0][1]))
        i += 1
    else:
        result.append(b[0])

    result.extend(b[1:])
    return tuple(result)

def loop(a):
    """Return a * omega."""
    if not a:
        return ZERO

    # If a starts with omega^beta * c, then
    # a * omega = omega^(beta + 1).
    beta = a[0][0]
    return ((succ(beta), 1),)

def parse_program(s):
    n = len(s)

    def parse(pos, closing):
        cur = ZERO

        while pos < n and (not closing or s[pos] != ']'):
            if s[pos] == '+':
                cur = succ(cur)
                pos += 1

            elif s[pos] == '[':
                inside, pos = parse(pos + 1, True)
                cur = add(cur, loop(inside))

            else:
                # The caller consumes matching ']'.
                break

        if closing and pos < n and s[pos] == ']':
            pos += 1

        return cur, pos

    value, _ = parse(0, False)
    return value

def solve():
    m = int(input())
    programs = [input().strip() for _ in range(m)]

    values = [(parse_program(p), p) for p in programs]
    values.sort(key=lambda x: x[0])

    sys.stdout.write("\n".join(p for _, p in values))

if __name__ == "__main__":
    solve()
```この表現では不変タプルを使用するため、序数に他の序数を指数として安全に含めることができます。 これにより、Python には無料で便利な特性が与えられます。つまり、タプルの等価性と辞書編集的な比較により、完全な CNF 構造が再帰的に比較されます。`succ`有限の尾を慎重に扱います。 最後の指数がゼロの場合、序数にはすでに有限成分が含まれており、その係数は増加します。 それ以外の場合、序数には有限の末尾がないため、後続関数は新しい (\omega^0) 項を作成します。`add`順序加算の CNF ルールに従います。 右オペランドの最初の項が (\omega^\beta c) であるとします。 指数 (\beta) の下にある左側のすべての項が消えます。 (\beta) に等しい指数を持つ項が残り、その係数が右オペランドの係数と結合されます。 右オペランドの残りの部分は変更されずにコピーされます。 

比較`a[i][0] > beta`指数自体が正規の順序タプルであるため、これは有効です。 Python は、まったく同じ順序に従ってこれらのタプルを再帰的に比較します。 巨大な整数への変換は必要なく、整数のオーバーフローの可能性もありません。`loop`重要な無限演算です。 もし`a`がゼロ以外で (\omega^\beta c) で始まる場合、

 [
 a\cdot\omega=\omega^{\beta+1}。 
]

 限界内では下位部分全体が消滅します。 たとえば、((\omega+1)\omega=\omega^2)、(7\omega=\omega) などです。 

パーサーは、括弧で囲まれた完全な式を再帰的に消費します。 再帰シーケンスには演算が含まれていないため、空の括弧は当然ゼロを生成します。 本体を解析した後、`loop`周囲の括弧のセマンティクスを適用し、結果として得られる序数がその前に解析されたすべてのものに追加されます。

### サンプル 1

 関連する標準値を以下に示します。 

| プログラム | 解析された値 | CNFの解釈 |
 | --- | --- | --- |
 |`[][[][]][]`| (0) | 空 |
 |`+`| (1) | (1) |
 |`+++++++`| (7) | (7) |
 |`+++[+++]`| (\オメガ) | (3+\オメガ) |
 |`[+]+`| (\オメガ+1) | (\オメガ+1) |
 |`[+][+]`| (\omega\cdot2) | (\オメガ+\オメガ) |
 |`+[+[+]+]+`| (\オメガ^2+1) | (1+(\オメガ+1)\オメガ+1) |

 パーサーが到達する`+++[+++]`最初に(3)を構築し、次に評価することによって`+++`(3) のように括弧内を変更し、括弧で囲まれた部分を (3\omega=\omega) に変更します。 最初の 3 つを追加すると (3+\omega=\omega) になります。 

のために`+[+[+]+]+`、内側`+[+]+`(\omega+1) を表します。 そのループは ((\omega+1)\omega=\omega^2) であり、周囲の後続ループは (\omega^2+1) を与えます。 表現`[+][[+]][+]`代わりに次で終わります`[+]`、(\omega) のコピー全体を追加し、(\omega^2+\omega) を与えます。 これにより、一見似ているように見える 2 つの表現が区別されます。

## 特殊なケース

 空のプログラムは、空の CNF タプルで表されます。 したがって`[]`空の本体をゼロに評価します。`loop(0)`ゼロを返し、それを別の式と連結しても効果はありません。 のために`[][[][]][]`、括弧で囲まれたすべての本体は空であるか、空のプログラムのみで構成されているため、最終的な値はゼロのままです。 これは、通常の再帰リターンを超える特別なパーサー ケースを使用せずに、任意にネストされた空の括弧を処理します。 

有限プレフィックスの後に無限ループが続く場合、ループが限界順序を生成するときに、有限プレフィックスを通常の加算オフセットとして扱ってはなりません。 で`+++[+++]`、最初の部分は (3) を示し、括弧で囲まれた部分は (3\cdot\omega=\omega) を示します。 加算ルーチンは (3+\omega) を受け取り、右側のオペランドに先頭の指数 (1) があることを確認し、左側のオペランドの指数ゼロの項を削除します。 結果はまさに (\omega) になります。 

表現`+[+]`同じルールをより小さな形式で実行します。 最初`+`(1) を与え、そして`[+]`(\オメガ)を表します。 左からの指数ゼロの項が破棄されるため、加算 (1+\omega) は (\omega) になります。 通常の整数演算に基づくパーサーでは、先頭の整数が誤って保持されてしまいます。 

間の区別`[+]`そして`[+]+`反対側の境界をテストします。`[+]`(\omega) を生成しますが、最後の`+`で`[+]+`は実際の後継者であるため、結果は (\omega+1) になります。 表現では、`[+]`は`((1, 1),)`、その後継はゼロ指数項を追加し、`((1, 1), (0, 1))`。 

ネストされたループは、先頭の指数が正しく更新されているかどうかをテストします。 のために`[[+]]`、内側`[+]`(\オメガ)を表します。 したがって、外側のループは (\omega\cdot\omega=\omega^2) を計算します。 CNF では、(\omega) の先頭の指数は (1) であるため、`loop`当てはまる`succ`その指数に代入して単一の項 (\omega^2) を生成します。 この構文を繰り返すことで、自然と次のようなより深い表現が可能になります。`[[[+]]]`、これは (\omega^3) を表します。 

最後に、同じプログラムを特定のテキスト順序に強制してはなりません。 などの表現`[+]`そして`+[+]`構文は異なりますが、両方とも (\omega) を表します。 並べ替えキーは正規の順序表現であるため、等しい値は等しいと比較されます。 Python の安定した並べ替えでは入力順序が保存されますが、これは問題によって許可されています。
