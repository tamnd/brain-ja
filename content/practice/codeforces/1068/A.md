 ## 解決策
 ## 問題の理解

 私たちは、異なる種類のコインの固定された世界を扱っています。`N`合計で異なるコインも可能です。 イワンはすでに所有しています`K`この世界からの特別なコイン。 今`M`友達はそれぞれ彼にギフトを与え、各友達は同じ数のコインを寄付する必要があります。 

ギフトされたすべてのコインは、すべての友人間で区別できる必要があります。つまり、ギフトのセット全体でコインの種類が複数回出現することはできません。 友人たちはイワンがどのコインをすでに所有しているかを知らないため、最悪の場合、イワンの未知のコレクションに関する「新しいコイン」に関する要件を満たさなければなりません。 

重要な要件は、すべてのギフトコインのうち、少なくとも`L`それらの中には、イワンが以前に所有していなかったコインが含まれているに違いありません。 私たちはイワンのコレクションを知らずにこれを保証しなければならないので、彼のコレクションがどのようになったとしても、私たちはそれを保証する必要があります。`K`コインが選択されている場合、ギフトセットには常に少なくとも次のものが含まれます`L`新しいコイン。 

出力では最小値が求められます`x`各友人が正確に与えるように`x`異なるコインであり、すべての制約を満たすことができます。 そうでない場合`x`存在するので戻ります`-1`。 

制約は非常に大きく、最大で`10^18`これにより、シミュレーションや反復的な構築が直ちに除外されます。 すべての解決策は、重複や最悪の場合の交差に関する推論に基づいた純粋な算術的でなければなりません。 

いくつかの微妙な特殊なケースがすぐに現れます。 

もし`N < M`そうすると、たとえそれぞれが 1 つのコインしか与えなかったとしても、すべての友達が個別のコインを与えることは不可能です。`M`各友達の最初のコインだけの異なるコインタイプ。 

もし`L > N - K`場合、たとえイワンのコレクション以外のすべてのコインを贈ったとしても、宇宙には要件を満たすのに十分な「新しい」コインが入手可能ではありません。 

より微妙な失敗例は次のような場合に発生します。`M * x > N`、ギフトされたコインはすべてグローバルに区別される必要があるためです。 たとえ各友達が小さな数字をあげたとしても、プールの合計はそれを超えることはできません`N`。 

## アプローチ

 単純なアプローチでは、次の値を増加させようとします。`x`から始まる`1`、候補ごとに割り当て可能かどうかをシミュレートします。`M * x`少なくとも保証しながら、明確なコイン`L`イワンの未知の外のコイン`K`-セット。 このチェックには、最悪の場合の重複について推論する必要があります。Ivan の場合を想定します。`K`コインはギフトセットとの交差を最大化するように選択されます。 

固定の場合`x`、プレゼントします`M * x`合計で異なるコイン。 最悪の場合、イワンは、`K`コインはこれらのギフトと可能な限り重複するため、保証される「新しい」コインの数は最小限に抑えられます。 新しいコインの最小数は次のとおりです。`max(0, M * x - K)`少なくともこれが必要です`L`。 したがって、次のものが必要です。`M * x - K >= L`、これを単純化すると、`M * x >= K + L`。 

ただし、宇宙の合計サイズに関する実現可能性も必要です。`M * x <= N`。 

とてもブルートフォースオーバー`x`これらの不平等を繰り返しチェックします。 しかしそれ以来`x`まで行くことができます`10^18`、これは依然として概念的に最悪の解釈で O(N) であり、実行不可能です。 

重要な観察は、実現可能性は完全に 2 つの線形制約によって決定されるということです。`M * x >= K + L`そして`M * x <= N`。 

これらの制約は、単純な間隔を定義します。`x`、最小の整数を求められます`x`この間隔で。 

したがって、次のように計算します。 

下限:`ceil((K + L) / M)`上限:`floor(N / M)`下限が上限を超える場合、有効な解決策はありません。 

これにより、問題全体が整数演算に単純化されます。

 ## アルゴリズムのチュートリアル

 1. 少なくとも保証するために必要なギフトコインの最小合計数を計算します。`L`最悪の場合は新しいコイン。 この要件は次のようになります`M * x >= K + L`。 
2. これを下限に変換します。`x`上限のある整数除算を使用する:`(K + L + M - 1) // M`。 
3. ユニバース制約によって許可される合計ギフト コインの最大可能数を計算します。`M * x <= N`、上限を与える`N // M`。 
4. 下限が上限を超えた場合、有効な代入が存在しないと判断し、出力します。`-1`。 
5. それ以外の場合は、友人あたりの実行可能な最小コイン数として下限を出力します。 

### なぜ効果があるのか

 重要な不変条件は、有効な構成はギフトされたコインの総数のみに依存するということです。`T = M * x`、友達の間での配布ではありません。 区別性がすべてを強制する`T`贈られたコインは世界的に一意であるため、構造はサイズのサブセットを選択することになります。`T`から`N`。 

最悪の場合はイワンの未知の状況と重なる`K`-サブセットは常に最大化されるため、新しいコインの最小保証数は正確に`max(0, T - K)`。 これにより、実現可能条件は完全に線形になります。`T`、したがって線形です`x`。 この縮小が行われると、隠れた構造は残りません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    N, M, K, L = map(int, input().split())

    # upper bound: cannot exceed total available coins
    hi = N // M

    # lower bound: ensure enough guaranteed new coins
    need = K + L
    lo = (need + M - 1) // M  # ceil division

    if lo > hi:
        print(-1)
    else:
        print(lo)

if __name__ == "__main__":
    solve()
```この実装は、派生した境界を直接ミラーリングします。 唯一の微妙な点は、下限の正しい上限分割です。これにより、浮動小数点エラーが回避され、最大の大きな値の正確さが保証されます。`10^18`。 

2 番目の制約`M * x <= N`フロア分割を使用して処理されます。 どちらの計算でも、Python が自然にサポートする 64 ビットの安全な整数演算を使用する必要があります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    N, M, K, L = map(int, sys.stdin.readline().split())

    need = K + L
    lo = (need + M - 1) // M

 ## 特殊なケース

 主なエッジケースは次のような場合です`M > N`。 たとえば:

 入力:`N = 5, M = 10, K = 1, L = 1`ここ`hi = 5 // 10 = 0`, つまり、友達1人につき1コインを与えることさえ不可能です。 アルゴリズムはすぐに戻ります`-1`有効ではないので`x`満足する`M * x <= N`。 コインの種類が友達よりも少ない場合、友達ごとに 1 つの異なるコインさえ割り当てることができないため、これは現実と一致します。 

もう一つのケースは次のような場合です。`K + L`に比べて非常に大きい`N`。 たとえば:

 入力:`N = 100, M = 10, K = 90, L = 20`ここ`need = 110`、 それで`lo = ceil(110 / 10) = 11`、 しかし`hi = 10`、とても不可能です。 これは、イヴァンの既存のコレクションと必要な新規性との間の相互作用が、たとえ次のような場合であっても不可能を強いられる可能性があることを示しています。`N >= M`。
