 ## 解決策
 ## 問題の理解

 私たちに与えられたのは、根を張った木です。$n$ノード、ラベル付け元$1$に$n$、ノード付き$1$根として。 各ノードについて$u$、数字$a_u$が指定されています。 この数字は先祖の数を表します$v$の$u$（含む$u$必要に応じて、それ自体) に割り当てられる値が$v$順列で$p$数字の$1$を通して$n$に割り当てられた値より小さいです$u$。 私たちの目標は、順列の数を数えることです$p$すべてのノードでこの条件を満たす$u$木の中で。 

入力制約の制限$n \le 5000$と合計$n$すべてのテストケースにわたって$5000$。 これは、$O(n^2)$アルゴリズムは制限時間内に実行される可能性がありますが、$O(n^3)$あるいはさらに悪いことに遅すぎるでしょう。 問題には長さの順列が含まれるため、$n$、すべての総当たりの列挙$n!$中程度の場合でも順列は問題外です$n$。 ツリーの組み合わせ構造と祖先数制約を利用する必要があります。 

明らかではないエッジ ケースには、ゼロ祖先の値が小さいことを必要とするノードや、大きい値を持つノードが含まれます。$a_u$根元付近。 たとえば、木が直鎖の場合、$1 \to 2 \to 3 \to 4$そして$a = [0,1,2,3]$、唯一の有効な置換は、厳密に増加するシーケンスです。$1,2,3,4$。 ツリー上の値の位置を慎重に考慮しない単純なアプローチでは、無効な順列が生成されます。 もう 1 つの微妙なケースは、根のある星形の木です。$1$そしてすべて$a_i = 0$。 最小値をルートに配置する順列はすべて正しいですが、不注意なアルゴリズムでは線形チェーンのみが想定される可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、すべてのものが生成されます。$n!$順列と各ノードのチェック$u$正確かどうか$a_u$その祖先の値は小さくなります。 これは問題の条件を直接実装しているため、理論的には機能しますが、計算上は不可能です。$n=10$、$n! = 3,628,800$、そしてのために$n=5000$、それは不合理です。 

重要な洞察は、$a_u$ツリー構造のため、当然階層構造になっています。 ツリーをルートから下に処理すると、有効な順列を段階的に構築できます。 任意のノードに対して$u$、$a_u$以前に割り当てられた祖先の値のうち、どれだけの値が次の値よりも小さい必要があるかを示します。$p_u$。 これにより、問題は動的プログラミングの問題に変換され、各サブツリーの有効な順列数は、祖先に割り当てられた「より小さい値」の数に依存します。 

具体的には、次のような DP を定義します。`dp[u][k]`をルートとするサブツリーに番号を割り当てる方法の数を数えます。$u$まさにそのようなこと$k$ルートからへのパス内の数値$u$よりも小さい$p_u$。 ツリーのサイズは最大 5000 であり、必要なのは深さまでの祖先の数だけであるためです。$u$、これはで実装できます$O(n^2)$時間。

 ## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取ります。 テスト ケースごとに、次の内容を読んでください。$n$、親配列`fa`、および配列`a`。 
2. 親配列を使用して、隣接リストとしてツリーを構築します。 
3. DP テーブルの初期化`dp[u]`各ノードごとに`u`。 各エントリには、最終的に、ルートとなるサブツリーに値を割り当てる方法の数が格納されます。`u`を尊重して`a`制約。 
4. DFS を使用して、ボトムアップ方式でツリーを処理します。 リーフ ノードの場合、有効な割り当ての数は 1 です。`a_u`はゼロ、それ以外の場合はゼロです。 
5. 内部ノードの場合`u`、その子の DP 結果を結合します。 概念的には、各子サブツリーは複数の方法でインターリーブできます。`u`先祖の数を尊重しながら。 組み合わせ二項係数を使用して、これらのインターリーブを効率的にカウントします。 
6. ルート ノードの処理後、有効な割り当ての合計が`dp[1]`有効な順列の合計数を示します。 結果のモジュロを出力します$998244353$。 

重要な洞察は、`a_u`位置制約を定義します。祖先を走査順にリストすると、`p_u`正確より大きくなければなりません`a_u`この先祖たちのこと。 リーフからルートまで昇順に番号を割り当て、組み合わせ式でカウントを組み合わせることで、順列を列挙することなく、すべての祖先の制約が尊重されます。 

機能する理由: DP は、祖先数の制約が満たされるように、サブツリーに値を割り当てるあらゆる方法を正しくカウントします。 祖先の位置が固定されると、各サブツリーの組み合わせは独立し、組み合わせインターリーブを使用することで、すべての順列が正確に 1 回カウントされることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
MOD = 998244353

def solve():
    import sys
    sys.setrecursionlimit(10000)
    
    t = int(input())
    
    fac = [1] * 5001
    for i in range(1, 5001):
        fac[i] = fac[i-1] * i % MOD
    
    inv = [1] * 5001
    inv[5000] = pow(fac[5000], MOD-2, MOD)
    for i in range(5000, 0, -1):
        inv[i-1] = inv[i] * i % MOD
    
    def comb(n, k):
        if k < 0 or k > n:
            return 0
        return fac[n] * inv[k] % MOD * inv[n-k] % MOD
    
    for _ in range(t):
        n = int(input())
        fa = list(map(int, input().split()))
        a = list(map(int, input().split()))
        
        tree = [[] for _ in range(n)]
        for i, p in enumerate(fa):
            tree[p-1].append(i+1)
        
        def dfs(u):
            total = 1
            size = 0
            for v in tree[u]:
                cnt, sz = dfs(v)
                total = total * cnt % MOD * comb(size + sz, sz) % MOD
                size += sz
            if a[u] > size:
                return 0, size + 1
            return total, size + 1
        
        res, _ = dfs(0)
        print(res % MOD)

if __name__ == "__main__":
    solve()
```このソリューションでは、まず階乗とモジュラー逆行列を事前計算して、組み合わせを効率的に計算します。 DFS は、サブツリーごとに有効な割り当てを再帰的に計算します。 重要なのは、祖先の制約を尊重しながら、各子のカウントに、それらをインターリーブする方法の組み合わせの数を乗算することです。 アルゴリズムは常にゼロを返します`a[u] > size`そのノードの祖先数の要件を満たすことが不可能であるためです。
