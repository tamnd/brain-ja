 ## 解決策
 ## 問題の理解

 私たちは、ダメージ値を持つ一連の剣と、それぞれにライフ値を持つ一連のモンスターを持つダンジョン シナリオをシミュレートするように求められました。 剣のダメージがモンスターのライフ以上であれば、モンスターを倒すことができます。 剣は一度使用すると消費されますが、場合によってはモンスターの攻撃力に応じてより高いダメージを与える可能性のある新しい剣を獲得します。`c_i`価値。 目標は、倒せるモンスターの数を最大化することです。 

入力は複数のテスト ケースを提供します。 各テスト ケースでは、最初の剣、モンスターの健康状態、各モンスターを倒した後に出現する可能性のある新しい剣が提供されます。 出力は、テスト ケースごとに殺されたモンスターの最大数になります。 

制約が厳しい:`n`そして`m`到達できる`2 * 10^5`、すべてのテスト ケースの合計も同様に制限されます。 これにより、操作の数が 2 次またはそれ以上になるため、剣やモンスターのすべての可能な順序を反復する強引なソリューションが排除されます。 単純な O(n * m) アプローチは実現できません。 

注意すべきエッジケースには、すべての状況が含まれます。`c_i`がゼロの場合は、新たな剣が出現しないか、初期の剣がすべて一部のモンスターより弱い場合があります。 たとえば、次の場合`a = [1]`そして`b = [2]`と`c = [0]`、モンスターを殺すことはできず、アルゴリズムは戻らなければなりません`0`。 別の厄介なケースは、最初に間違った剣を選択すると、後でより強力な剣を生み出す可能性のあるモンスターにその剣を使用できなくなる場合です。 

## アプローチ

 ブルートフォースアプローチでは、剣とモンスターの割り当てのあらゆる組み合わせが試行されます。 各モンスターに対して各剣をチェックし、どの剣が消費されたかを追跡し、次のように更新します。`c_i`価値観。 これにより正確性が保証されますが、最大で`n * m`テストケースごとの比較。 と`n, m`2 * 10^5 までの場合、最悪のケースでは 4 * 10^10 の演算が発生しますが、これは実行不可能です。 

最適なアプローチでは、並べ替えと貪欲な選択を活用します。 まず、剣とモンスターの両方を分類します。 剣を分類すると、モンスターを倒すことができる最小の剣が常にわかります。これは、剣を効率的に消費したい場合に非常に重要です。 ライフごとにモンスターを分類すると、弱いモンスターから順に処理できます。 重要な洞察は、モンスターを倒した後に得られる新しい剣は常に、少なくとも使用した剣と同じくらいのダメージを与えるということです。 これにより、残っている最も弱いモンスターに対して十分な最小の剣を使用するという貪欲なアプローチにより、合計キル数が最大化されることが保証されます。 利用可能な剣を格納するために最小ヒープ (優先キュー) を使用すると、モンスターを倒すことができる最小の剣を効率的に見つけることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * m) | O(n + m) | 遅すぎる |
 | ソート + ヒープで貪欲 | O((n + m) log(n + m)) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テストケースについて、剣の数を読み取ります。`n`そしてモンスター`m`。 剣のダメージリストを読む`a`、モンスターの体力リスト`b`、および剣の獲得リスト`c`。 
2. 剣を昇順に並べ替えます。 モンスターをペアリングします`c_i`値を調べて、健康状態によって昇順に並べ替えます。 これにより、弱いモンスターに最初に対処することが保証されます。 
3. すべての初期剣ダメージで最小ヒープを初期化します。 この山からは常にモンスターを倒すことができる最小の剣が得られ、より強力な剣を後で保存できる可能性が最大限に高まります。 
4. カウンタの初期化`kills`ゼロに。 並べ替えられたモンスターのリストを繰り返し処理します。 各モンスターについて:

 ａ． 少なくともモンスターの体力と同じダメージを持つ剣を見つけるまで、山から剣を取り出します。 

b. そのような剣が存在しない場合、このモンスターをスキップします。 

c. 剣が見つかった場合は増加します`kills`。 使用済みの剣を山から取り出します。 

d. もし`c_i > 0`、ダメージのある新しい剣を押します`max(sword_used, c_i)`ヒープに戻ります。 これにより、新しい剣が常に少なくとも消費された剣と同じくらい強いことが保証されます。 
5.全てのモンスターを処理したら出力`kills`。 

維持される不変条件は、各ステップでヒープに現在利用可能なすべての剣が含まれており、現在最も弱いモンスターを殺すことができる最小の剣を常に選択するということです。 これにより、より強力なモンスターのためにより強力な剣が保存されることが保証されます。 

## Python ソリューション```python
import sys
import heapq
input = sys.stdin.readline

T = int(input())
for _ in range(T):
    n, m = map(int, input().split())
    swords = list(map(int, input().split()))
    monsters = list(map(int, input().split()))
    gains = list(map(int, input().split()))
    
    swords.sort()
    monsters = sorted(zip(monsters, gains))
    
    heap = swords[:]
    heapq.heapify(heap)
    kills = 0
    
    for life, gain in monsters:
        while heap and heap[0] < life:
            heapq.heappop(heap)
        if not heap:
            continue
        sword = heapq.heappop(heap)
        kills += 1
        if gain > 0:
            heapq.heappush(heap, max(sword, gain))
    
    print(kills)
```このソリューションでは、まず剣とモンスターを分類します。 最小ヒープは、現在のモンスターを倒すことができる最小の剣を効率的に選択するために使用されます。 操作の順序が重要です。最初に弱い剣をポップし、増加させます。`kills`、そして取得した新しい剣を押します。 使用する`max(sword, gain)`新しい剣が常に少なくとも使用済みの剣と同じ強度であることを保証します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n + m) log(n + m)) | 剣とモンスターのソートは O(n log n + m log m)、すべてのモンスターにわたるヒープ操作の合計は O((n + m) log(n + m)) |
 | スペース | O(n + m) | ヒープには最大 n + m の剣と入力配列が格納されます。 

これは制約内に快適に収まります`n + m ≤ 2 * 10^5`テスト ケースごと、合計合計 ≤ 2 * 10^5。
