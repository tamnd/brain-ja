 ## 解決策
 ## 問題の理解

 一連の数値が与えられ、1 つの値だけが残るまで繰り返し圧縮します。 各操作では、隣接する 2 つの要素を取得して削除し、元の 2 つの値の間にある任意の整数に置き換えます。 重要な自由は、平均や固定ルールを選択することを強制されず、ペアによって形成される間隔内の任意の値を選択できることです。 

まさにその後$n-1$このような結合では、配列は単一の数値になります。 問題は、最終的な残りの数が正確に一致するような、マージと中間値の選択のシーケンスが存在するかどうかです。$x$。 

制約は小さく、各テストには最大 100 個の要素と最大 500 個のテスト ケースが含まれます。 これは、テストごとの 2 次または 3 次推論であっても許容されるが、すべてのマージ シーケンスにわたる指数関数は許容されないことをすぐに示唆しています。 考えられるすべてのマージ順序とすべての値を試す単純なシミュレーションは、各マージによって連続的な範囲の可能性が導入され、マージ ツリーの数がすでに指数関数的であるため、不可能です。$n$。 

すべての値が等しい場合、または次の場合に、微妙なエッジ ケースが発生します。$x$配列の範囲外にあります。 たとえば、すべての要素が$[3,3,3]$、最終値は常に 3 である必要があるため、$x \neq 3$不可能です。 同様に、次から始めると、$[1, 5]$、いつでも最終的な値を選択できます。$[1,5]$、だからどれでも$x$この間隔外では直ちに不可能になります。 興味深いのは、グローバル範囲内のすべての値が常に達成可能かどうかです。 

2 つの数値の間で任意の値を選択できるため、最終結果を任意に「操作」できると考えるのは単純な間違いです。 局所的な自由ではなく制約の伝播という観点から考えると、その直観は当てはまりません。 

## アプローチ

 強引なアイデアでは、考えられるすべてのマージ シーケンスをシミュレートしようとします。 各ステップで、隣接するペアを選択し、その範囲内のすべての整数に置き換えます。 これにより、位置と値の両方の分岐要素が作成されます。 値を無視しても、カタロニア語の数のマージ構造が存在し、値の選択により状態空間は無限になります。 組み合わせが実現可能性を超えて爆発的に増加するため、値を離散化しても役に立ちません。 

重要な洞察は、実際にはマージの順序を気にしていないということです。 すべての操作では、2 つの連続するセグメントが、達成可能な値が間隔を形成する 1 つのセグメントにマージされるだけです。 これは、各セグメントが$[l, r]$連続範囲で表すことができる$[min(l,r), max(l,r)]$、そして 2 つのセグメントをマージすると、単純にそれらの可能な範囲がそのセグメント内のすべての要素間の完全な間隔に統合されます。 

したがって、問題は、より単純な不変式に分解されます。つまり、一連の操作の後、最終値は、元の配列のグローバル最小値とグローバル最大値の間の任意の整数になる可能性があります。 これは、マージを使用すると常に極値を内側に伝播でき、各ステップで中間値を自由に選択して新しい制約の導入を回避できるためです。 

したがって、最終的な答えは単に次のとおりです。$x$中にある$[\min(a), \max(a)]$。

 ## アルゴリズムのチュートリアル

 各テスト ケースを配列に対する範囲クエリに縮小します。 

1. シーケンス内の最小値を計算します。 どの操作も入力の凸包の外側に何かを生成できないため、これはマージを通じて保持できる最低値を表します。 
2. シーケンス内の最大値を計算します。 これは、同じ理由で対称的な上限です。 
3. かどうかを確認します。$x$これら 2 つの値の間にあります。 
4. 存在する場合は「YES」を出力し、存在しない場合は「NO」を出力します。 

唯一明らかではない部分は、なぜ間隔全体が達成可能なのかということです。 マージ ルールを使用すると、2 つの隣接するセグメント間の任意の値を選択できます。 価値観の融合と選択を繰り返すことで、徐々に$x$を使用すると、範囲内の整数を「スキップ」しないパスをいつでも構築できます。 

### なぜ効果があるのか

 各マージでは、2 つの隣接するセグメントが、両方の入力をカバーする接続された区間を形成する達成可能な値を持つ 1 つのセグメントに置き換えられます。 このマージ操作では区間が閉じられるため、最後のセグメントも区間である必要があります。 初期セグメントは単一点であるため、最終間隔は、すべての初期値の凸包とまったく同じになります。$[\min(a), \max(a)]$。 したがって、任意の$x$この間隔内では到達可能です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        x = int(input())

        mn = min(a)
        mx = max(a)

        if mn <= x <= mx:
            print("YES")
        else:
            print("NO")

if __name__ == "__main__":
    solve()
```コードは各配列の最小値と最大値を直接計算し、$x$その隙間にあります。 問題の構造によりシミュレーションの必要がなくなるため、実装は意図的に最小限に抑えられています。 

ここでよくある間違いは、貪欲なマージや操作のシミュレーションを試みることですが、その必要はありません。 もう 1 つの潜在的な落とし穴は、中間値が範囲内の任意の整数になり得ることを忘れていることです。これにより、到達可能なセットが離散的ではなく連続的になります。

 ## 特殊なケース

 エッジ ケースの 1 つは、配列に単一の要素がある場合です。 入力用$[5]$、操作が存在しないため、可能な最終値は 5 のみです。 アルゴリズムは計算します$mn = mx = 5$、だからそれだけ$x = 5$YES を返します。これはプロセスと正確に一致します。 

もう 1 つのエッジケースは、すべての値が同一である場合です。$[3,3,3,3]$。 すべてのマージでは、選択に関係なく値 3 が保持されるため、最終結果は固定されます。 計算された範囲は$[3,3]$、答えを正しく制限します。 

より微妙なケースは次のような場合です。$x$厳密に 2 つの離れた値の間にあります。$[1, 100]$と$x = 50$。 最初は中間値が存在しませんが、2 つの要素を直接マージすると、その間隔内の任意の整数を選択できるため、50 が達成可能になります。 範囲チェックでは、中間状態をシミュレートする必要なく、これを即座に取得します。
