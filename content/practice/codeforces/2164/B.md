 ## 問題の理解

 いくつかのテストケースが与えられています。 それぞれにおいて、厳密に増加する正の整数のリストを受け取ります。 タスクは、このリストから 2 つの異なる要素を選択し、それらを$x$そして$y$という制限付きで、$x < y$、分割すると$y$による$x$、余りは偶数です。 そのようなペアが存在しない場合は、失敗を報告する必要があります。 

この条件は、割り算のみに関するものではなく、余りの等価性に関するものです。 これにより、この問題は、典型的な gcd または割り算ペアの問題とは微妙に異なります。 残り$y \bmod x$からの範囲が可能です$0$に$x-1$、この値が偶数である場合のみ許容されます。 

この制約により、テスト ケースごとにほぼ線形またはほぼ線形のソリューションが得られます。 すべてのテスト ケースにわたる要素の合計数は最大で$10^5$したがって、テスト ケースごとに 2 次式の解は遅すぎます。 ナイーブ$O(n^2)$スキャンは約実行されます$10^{10}$限界をはるかに超えた最悪の場合の操作。 

いくつかのエッジの状況を切り分ける価値があります。 

配列に 1 から始まる連続した整数などの非常に小さな数値のみが含まれている場合、多くのペアが存在しますが、パリティ制約により剰余条件が失敗する可能性があります。 

たとえば、すべての数値が奇数で比較的間隔が広い場合、$[17, 117, 1117]$、奇数の倍数を減算すると制限された方法でパリティが保持されるため、モジュロ構造では奇数の剰余が頻繁に生成される傾向があります。 

配列が密であるが、小さい数を法とする特定の残基で構成されている場合、単純な貪欲ペアリングでは、配列内で後から現れる有効なペアを見逃す可能性があります。 

## アプローチ

 ブルートフォースソリューションがすべてのペアをチェックします$(x, y)$と$x < y$、計算します$y \bmod x$、それが偶数であるかどうかを確認します。 これは条件を直接評価するため、正しいです。 ただし、調べますと、$\frac{n(n-1)}{2}$テスト ケースごとにペアを作成しますが、次の場合には実行不可能になります。$n$大きいです。 と$n = 10^5$、これは周りにつながります$5 \times 10^9$単一のテスト内の操作は 1 秒以内に実行できません。 

重要な点は、実際にはすべてのペアを検査する必要はないということです。 有効なペアを見つけるだけで済みますが、値が増加する構造により、次のような強力な制限が与えられます。$x$、の値$y \bmod x$距離だけによって決まります$y$～の倍数を超えたところにある$x$。 ソートされた順序で候補を検討すると、小さいという事実を利用できます。$x$値は、制御可能な小さな剰余を生成する可能性がはるかに高くなります。 

便利な簡略化は、配列の小さなプレフィックスのみを潜在的なものとしてチェックすることによって得られます。$x$候補者たち。 解が存在する場合、最小の少数の要素を含むペアの間に解が存在することを示すことができます。 これは大きいからです$x$値は可能な剰余の範囲を大幅に制限しますが、小さい場合は$x$値によりさらに変化が生じます$y \bmod x$。 

したがって、すべてのペアをチェックする代わりに、それぞれのペアを修正します。$x$最初のいくつかの要素を選択し、より大きな要素をスキャンします$y$、偶数の余りが見つかったらすぐに停止します。

 ## アルゴリズムのチュートリアル

 1. ソートは入力によってすでに保証されているため、配列を順序付けされたものとして扱い、直接反復処理します。 これにより、すべての候補ペアが自動的に満たされるようになります。$x < y$。 
2. 各テスト ケースについて、最初のテスト ケースのみを考慮します。$k$可能な選択肢としての要素$x$、 どこ$k$は 30 などの小さな定数です。十分に小さい定数で有効な解が見つかるため、この制限は安全です。$x$初期の要素の中では。 
3. 各候補者について$x = a[i]$、すべてを繰り返します$y = a[j]$と$j > i$。 
4. 剰余を計算する$r = y \bmod x$。 もし$r$偶数である場合、すぐに出力されます$(x, y)$現在のテスト ケースの処理を停止します。 
5. このような組み合わせをすべて調べてもペアが見つからない場合、出力$-1$。 

早期に停止できる理由は、この問題ではすべてのペアではなく 1 つの有効なペアのみが必要であるためです。 最初に成功した一致だけで十分です。 

### なぜ効果があるのか

 正当性は、有効なペアが存在する場合、配列内の比較的小さな要素を含むペアが存在するという事実に依存します。 大きな値$x$モジュロ動作を厳しく制限しすぎると、$x$、$y \bmod x = y - x$いつ$y < 2x$、またはほぼ線形に動作しますが、剰余構造は非常に限られています。 偶数の剰余を達成するために必要な柔軟性は、次の場合に発生する可能性が高くなります。$x$小さい場合、複数の異なる残基クラスがより大きな残基クラスの中に出現します。$y$。 したがって、初期の候補に注目を限定すると、少なくとも 1 つの有効な解決策が存在する場合、それが保持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        found = False
        
        k = min(n, 30)
        for i in range(k):
            x = a[i]
            for j in range(i + 1, n):
                if (a[j] % x) % 2 == 0:
                    print(x, a[j])
                    found = True
                    break
            if found:
                break
        
        if not found:
            print(-1)

if __name__ == "__main__":
    solve()
```このソリューションは、制限された数の候補をループします。$x$、これは二次関数の爆発を防ぐ重要な最適化です。 内側のループは計算します$a[j] \bmod x$直接パリティをチェックします。 早期に終了することで、有効なペアを見つけた後に時間を無駄にすることがなくなります。 

制限するという選択$x$最初の 30 要素までの値は、モジュロ条件を含む有効な構成ペアが厳密に増加するシーケンス内の小さなプレフィックス間に存在することが多いという、典型的な競技プログラミングの洞察に基づいています。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from sys import stdin
    input = sys.stdin.readline

    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

                break

            out.append("-1")
