 ## 問題の理解

 文字列から始めます`s`それを別の文字列に変換したい`t`、どちらも同じ長さです。 唯一許可される移動は、キャラクターを直接編集しません。 代わりに、非常に制限されたルールを使用して文字列全体を一度に再構築します。 

1 回の操作で新しい文字列を構築します`s'`同じ長さの。 の最初の文字`s'`現在の文字列の最初の文字と強制的に等しくなります。 それ以降のポジションごとに`i`現在のキャラクターをコピーするか選択できます`s[i]`または前の文字をコピーする`s[i-1]`。 構築後`s'`、上書きします`s`それと一緒に。 

したがって、各操作では限定的な「左方向への伝播」が可能です。文字はその場に留まるか、すぐ左隣の値で置き換えられますが、同じ操作ステップ内でのみ可能です。 

正確に到達したい`t`できる限り少ない操作を使用しますが、次の操作を超えないようにします。`k_max`。 制限内で無理な場合は出力します`-1`。 それ以外の場合は、中間文字列のシーケンスを出力する必要があります。 

この制約は、テスト ケース全体の長さが最大約 100 万であることを意味します。 これにより、テスト ケースごとに二次関数が即座に除外されます。 どのソリューションもほぼ直線的に動作する必要があります。`n`操作ごとに文字列を再構築することがすでに主要なコストとなっているためです。 

不一致が「方向性伝播」を必要とする場合、微妙な問題が発生します。 のキャラクター`t`の右側から来る必要があるかもしれません`s`、しかし、この操作は情報を左方向に伝播するだけです。 この非対称性が重要な難点です。 

いくつかのエッジな状況には注意が必要です。 

もし`s == t`、答えはゼロオペレーションです。 

のすべての文字が`t`すでに一貫している位置からコピーする必要がある`s`、1回の操作で成功するかもしれません。 

厄介なケースは、`t`～の複数の異なる文字に依存します`s`ローカルに調整されていないもの。 たとえば、変形する`s = "acba"`に`t = "aaac"`調整された伝播が必要です。 単純な貪欲な位置修正は、ローカル修正によって以前は正しいプレフィックスが壊れる可能性があるため、失敗します。 

## アプローチ

 ブルートフォース解釈では、考えられるすべての操作をシミュレートしようとします。 各ステップで、各ポジションは次のいずれかを選択します`s[i]`または`s[i-1]`、与える`2^(n-1)`操作ごとに可能な文字列。 積極的に剪定を行ったとしても、これは指数関数的に増加します。`n`そしてすぐに実行不可能になります。 

A more structured brute-force is to think backwards: for each position in`t`、のどの位置から決定しますか`s`ある程度の操作を行った後に発生する可能性があります。 ただし、各操作で許可されるのは 1 ステップの左コピーのみであるため、`k`各位置の操作は、同じサイズのウィンドウからのみプルできます`k+1`元の文字列で。 この観察はすでに方向性を示しています。実現可能性は、`t[i]`の到達可能なセグメントから調達できる`s`。 

重要な洞察は、個々の操作をキャラクターごとの選択肢として考えるのをやめ、代わりに左から右への影響力の拡大として見ることです。 各操作により、キャラクターは「右に 1 歩広がる」ことができます。 操作を繰り返すと、これは制御された拡散プロセスになります。 

したがって、構築は、間のインデックスの不一致の観点から、値をどれだけ左に移動する必要があるかによって決まります。`s`そして`t`。 それぞれの不一致は基本的に、どのくらいの「距離」を埋める必要があるかを定義し、各操作によって構造的な方法で残りの距離が減少します。 

貪欲に修正します`s`向かって`t`ただし、伝播制約を考慮した方法で、左から右に移動します。文字が正しく配置されると、その後の操作で将来の位置のソースとして使用できます。 これにより、各操作がすでに一致するプレフィックスを拡張しようとする反復的な構築が行われます。`t`。 

プロセスは次のようになります。各操作で、次の最長のプレフィックスを構築します。`t`現在の状態を考慮して形成できる`s`、許可されたコピー ルールを使用して更新します`s`。 これにより進行が保証され、操作の数が正しい値を完全に伝播するために必要な「レイヤー」の数になります。

 ## アルゴリズムのチュートリアル

 現在の文字列を維持します`s`。 各操作で新しい文字列が構築されます`s'`。 

1. もし`s`すでに等しい`t`、すぐにやめます。 すでに目標に到達しているため、これ以上の操作は必要ありません。 
2. 操作ごとに、`s'`左から右へ。 最初の文字は常に`s[0]`、それは変えることができないからです。 
3. ポジションごとに`i > 0`を設定するかどうかを決定します。`s'[i] = s[i]`または`s[i-1]`。 より適切に整合するオプションを選択します`t[i]`もし可能なら。 

指針となる原則は単純です。つまり、可能な限り長いプレフィックスを作成しようとします。`s'`マッチ`t`。 ある位置で一致の拡張に失敗した場合でも、文字列は一貫して完成しますが、この操作ではそれ以上の位置合わせは期待できません。 

1.施工後`s'`、交換します`s`と`s'`。 
2.どちらかになるまで繰り返します`s == t`または私たちは到達します`k_max`。 

各操作内の構造は、位置ごとに任意に貪欲なものではありません。 これは、各位置がそれ自身または前の状態の左隣にのみ依存するという制約の下で、正しい文字が左から右にどこまで伝播できるかを効果的にシミュレートします。 これにより、各操作が正確性の制御された拡張になります。 

### なぜ効果があるのか

 核となる不変条件は、各操作の後に次の接頭辞が付加されることです。`s`それは一致します`t`減っていない。 位置が正しく安定すると、以降の操作でその位置が無効になることはありません。`s'`それ自体からコピーされるか、その左隣からコピーされます。どちらもすでに一致しています`t`一致するプレフィックスに含まれます。 これにより回帰が防止されます。 

各操作は、完全な調整が達成されるまで、またはそれ以上の改善が不可能になるまで、一致するプレフィックスを増やします。その場合、操作構造では変換は不可能です。 各ステップはプレフィックスの長さまたは終了を厳密に改善するため、プロセスは最長で 2 時間以内に完了します。`n`効果的な拡張、さらに制限される`k_max`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_next(s, t):
    n = len(s)
    s = list(s)
    res = [''] * n
    res[0] = s[0]

    # track how far we match prefix with t during this operation
    for i in range(1, n):
        take_same = s[i]
        take_left = s[i - 1]

        # prefer matching target if possible
        if take_same == t[i]:
            res[i] = take_same
        elif take_left == t[i]:
            res[i] = take_left
        else:
            # cannot match here; still must choose something
            # choose same to preserve locality
            res[i] = take_same

    return ''.join(res)

def solve():
    n, kmax = map(int, input().split())
    s = input().strip()
    t = input().strip()

    if s == t:
        print(0)
        return

    ops = []
    for _ in range(kmax):
        if s == t:
            break
        s = build_next(s, t)
        ops.append(s)

    if s != t:
        print(-1)
        return

    print(len(ops))
    for x in ops:
        print(x)

if __name__ == "__main__":
    solve()
```コードは、許可されたコピー ルールを使用して次の文字列を繰り返し構築します。 ヘルパー関数`build_next`操作定義を直接エンコードします。各位置は次の間を選択します。`s[i]`そして`s[i-1]`。 

タイブレーク戦略はターゲット文字列によって導かれ、一致に向けて伝播にバイアスがかかります。`t`。 このアルゴリズムは、文字が将来の位置の一致に役立つと、それを左方向にコピーしても実現可能性が損なわれないという事実に基づいています。 

次の場合、ループは早期に停止します。`s`と等しくなる`t`、この貪欲な進行の下で最小限の操作を保証します。

 ## 特殊なケース

 単一文字の文字列が最も単純な境界です。 のために`s = "a", t = "a"`の場合、変換は必要なく、演算も生成されないため、アルゴリズムはゼロ演算で即座に終了します。 

構造の不一致などにより変形できない場合`s = "abc", t = "def"`、すべての操作では依然として既存の文字が再配置されるだけです。 新しい文字を導入できないため、プロセスが到達することはありません`t`。 ループが枯渇する`k_max`そして正しく出力されます`-1`。 

より微妙なケースは、すべての文字が同一になる必要がある場合です。たとえば、`s = "abca", t = "aaaa"`。 アルゴリズムは繰り返し伝播します`'a'`連続操作により左方向と右方向に移動します。 ステップごとに領域が拡大します。`'a'`そして、コピーは常に自分自身または左隣から行われるため、一度`'a'`プレフィックスに出現し、消えることはなく、最終的には文字列全体をカバーします。
