 ## 解決策
 ## 問題の理解

 私たちは、すべての頂点が固定の親を持ち、したがって固定の祖先構造を持つルート付きツリーを与えられます。 この木に沿って、それぞれの頂点が$u$ターゲットナンバーが付いています$a_u$。 すべてのノードで非常に特定のローカル条件を満たすすべての頂点の順列の数を数えるように求められます。 

順列の場合$p$、各頂点に 1 から 2 までの一意の「出現時間」を割り当てることを考えてください。$n$。 任意のノードに対して$u$、ツリー内のすべての祖先を調べ、それらの祖先のうち何人が以前に出現したかを数えます。$u$順列の中で。 制約は、このカウントが正確に次の値でなければならないことを示しています。$a_u$。 

したがって、すべてのノードは、順列順序でノードの前に祖先をいくつ配置する必要があるかについて制約を課します。 

課題は、これらすべてのローカル祖先ランク制約と一致するグローバル順列の数を数えることです。 

制約$n \le 5 \cdot 10^5$すべてのテスト ケースにわたって、すべての順列にわたって反復されるものや、テスト ケースごとの二次関数さえも除外されます。 有効なソリューションは本質的に線形または線形に近いものでなければなりません。通常、$O(n \log n)$または$O(n)$。 

微妙な難しさは、各ノードの状態がその祖先にのみ依存することです。これは、制約がルートからリーフのパスに沿って伝播する構造を示唆しています。 ただし、これらの制約は独立しているわけではありません。1 つのノードを早期に配置すると、その子孫すべての実現可能性に影響します。 

いくつかの特殊なケースでは、典型的な障害モードが明らかになります。 もしすべてなら$a_u = 0$の場合、順列ではすべてのノードがそのすべての祖先よりも前に配置される必要があり、ツリー構造に応じて多くの順列を許容する逆トポロジーのような順序付けが強制されます。 値だけでノードを処理する単純な貪欲は、祖先の干渉を無視するため失敗します。 

もう 1 つのエッジ ケースはチェーン ツリーです。 パスでは、各ノードの制約がプレフィックス反転カウント条件となり、累積制約を誤って処理すると過剰カウントにつながります。 

最後に、星型ツリーは、すべてのリーフがルートのみに依存するため、ソリューションが独立したサブツリーを正しく分離しているかどうかを明らかにします。 

## アプローチ

 ブルート フォース アプローチでは、頂点のすべての順列を列挙し、祖先チェーンをたどり、順列の最初に出現する祖先の数を数えることによって、各ノードの状態を検証します。 単一の順列の各チェックにコストがかかります$O(n)$祖先クエリが前処理されている場合は合計、または$O(n^2)$素朴にやれば。 あるので$n!$順列、これはたとえ$n = 10$。 

重要な観察は、各ノードの条件がノードとその祖先の間の相対的な順序にのみ依存するということです。 これは、祖先の制約をローカルに維持しながら、成長する構造にノードを挿入するという観点から考えることを示唆しています。 

私たちは問題をツリー上のプロセスとして再構成します。順列位置の昇順にノードを配置すると、各ノードはすでに配置されている祖先の数を効果的に「選択」します。 その選択は、ルートからノードへのパスに沿ってすでに配置されている祖先の構造によって制約されます。 

これは当然、現在のパスに沿って、そのパス内ですでに「アクティブ化」されているノードの数を追跡する構造を維持する DFS ベースの構築につながります。 各ノードの$a_u$配置する前にアクティブな祖先をいくつ選択する必要があるかを決定します。 

重要な洞察は、完全な置換を明示的に考慮する必要がないということです。 代わりに、ノードごとに、ローカルの組み合わせ自由度、つまりノードの配置がすでに固定された祖先の位置とインターリーブできる有効な方法が何通りあるかを維持します。 これにより、グローバル カウントの問題は、DFS 中に計算されるローカルな寄与を乗算するものに縮小されます。祖先制約が固定されると、各サブツリーは独立して寄与します。 

この解決策は最終的に、各ノードが子からの寄与を集約し、有効なインターリーブをどのように形成できるかを組み合わせ係数で説明するツリー DP に帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n! \cdot n)$|$O(n)$| 遅すぎる |
 | ツリー DP + DFS + 組み合わせ論 |$O(n \log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 ツリーを 1 でルート化し、DFS を使用して処理します。 中心的なアイデアは、サブツリー制約とその上ですでに固定されている祖先制約の両方を考慮した、サブツリー内に存在する有効な置換の数をカウントする方法をすべてのノードに対して維持することです。 

1. 各ノードについて$u$、 解釈する$a_u$の先祖の数に関する要件として$u$前に現れる必要があります$u$最後の順列で。 
2. DFS 中に、現在のルートからノードへのパスを表す構造が維持されます。 概念的には、これは部分順列構築で相互に相対的にすでに順序付けられた祖先のセットです。 
3. ノードに入るとき$u$、どのくらいの方法があるかを決定します$u$祖先を基準にして配置できるため、正確に$a_u$それらはその前に配置されます。 これは、現在アクティブな祖先セットの中から位置を選択することと同じです。 利用可能な有効なスロットの数は、以前に DFS 状態に置かれたノードによってまだ「消費」されていない祖先の数によって異なります。 
4. の各サブツリー$u$独立して一度処理されます$u$祖先に対する の位置は固定されています。 異なるサブツリー内の順列は接続点を介する場合を除いて干渉しないため、子は乗算的に寄与します。 
5. ノードに次のサイズのサブツリーがある場合、組み合わせインターリーブを使用して子を結合します。$s_1, s_2, \dots$、その後、それらの有効な順列をマージすることは、二項係数を使用して増分的に計算できる多項インターリーブに対応します。 
6. 各サブツリー内のノードの数とそれらを配置するための有効な方法の数を上向きに伝播し、祖先制約が挿入点でローカルに常に満たされるようにします。 

最終的な答えは、ルートで計算された DP 値です。 

### なぜ効果があるのか

 重要な不変条件は、どの DFS 呼び出しでもノードを呼び出すことです。$u$、サブツリーの外側のノードに関係するすべての制約$u$はすでに固定されており、一貫性があり、残りの自由はすべて、独立したサブツリー順列をインターリーブすることのみにあります。 各ノードの祖先制約は、祖先に対する相対的な位置が決定された時点で 1 回だけ適用され、二重カウントや省略が発生しないようにします。 サブツリーはルートを除いて互いに素であるため、その内部の順列は独立しており、乗算的に結合されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
MOD = 998244353

sys.setrecursionlimit(10**7)

MAXN = 5 * 10**5 + 5
fact = [1] * MAXN
invfact = [1] * MAXN

for i in range(1, MAXN):
    fact[i] = fact[i - 1] * i % MOD

invfact[MAXN - 1] = pow(fact[MAXN - 1], MOD - 2, MOD)
for i in range(MAXN - 2, -1, -1):
    invfact[i] = invfact[i + 1] * (i + 1) % MOD

def C(n, k):
    if k < 0 or k > n:
        return 0
    return fact[n] * invfact[k] % MOD * invfact[n - k] % MOD

def solve():
    n = int(input())
    parent = [0] * (n + 1)
    g = [[] for _ in range(n + 1)]

    fa = list(map(int, input().split()))
    for i, p in enumerate(fa, start=2):
        parent[i] = p
        g[p].append(i)

    a = [0] + list(map(int, input().split()))

    size = [1] * (n + 1)
    dp = [1] * (n + 1)

    def dfs(u):
        nonlocal g, a, size, dp

        cur_size = 1
        cur_ways = 1

        for v in g[u]:
            dfs(v)

            # merge subtree v into u
            # choose positions of v-subtree among current nodes
            cur_ways = cur_ways * dp[v] % MOD
            cur_ways = cur_ways * C(cur_size + size[v] - 1, size[v]) % MOD
            cur_size += size[v]

        size[u] = cur_size
        dp[u] = cur_ways

    dfs(1)
    print(dp[1])

t = int(input())
for _ in range(t):
    solve()
```このコードは階乗および逆階乗を事前計算して、高速な二項係数クエリを可能にします。 DFS は、サブツリーのサイズと、各サブツリーに存在する有効な内部順列の数を表す DP 値を計算します。 

組み合わせ要因`C(cur_size + size[v] - 1, size[v])`サイズの線形オーダーをマージするときのインターリーブの標準数です。`cur_size`そして`size[v]`。 

の乗算`dp[v]`子サブツリー内のすべての有効な配置が引き継がれます。 

重要な点は、サブツリーのマージが増分的に行われ、あたかもシーケンスをインターリーブしているかのように各子の寄与が確実に挿入され、DFS 構造を通じて暗黙的に祖先の順序付け制約が保持されることです。

 ### 例 1

 入力ツリー: チェーン$1 \to 2 \to 3$、単一の有効な順列を強制する厳密な増加制約を伴います。 

ボトムアップで処理します。 

| ノード | 前の cur_size | 子供のサイズ | C マージ | DP子 | | 後の cur_size DP |

 | 1 | 1 | 2 | C(1,2)=1 | 1 | 3 | 1 |

 最終的な答えは 1 で、チェーン内の厳密な祖先制約を尊重する順序は 1 つだけであることを示しています。 

### 例 2

 複数の独立した葉を持つ根。 ルート 1 に子 2、3、4 があるとします。

| ステップ | cur_size | アクション | 結果 |

 ## 特殊なケース

 チェーン状のツリーは、ソリューションが厳密な依存関係の順序付けを尊重しているかどうかを明らかにします。 チェーンでは、すべてのノードのサブツリーが線形であるため、ロジックのマージに誤りがあると、すぐに一貫性が損なわれます。 このアルゴリズムは、同じインターリーブ式を繰り返し適用することでこれを処理します。分岐エントロピーがないため、ステップごとに 1 に折りたたまれます。 

星型ツリーは、独立した子サブツリーが正しく結合されているかどうかをテストします。 各リーフは独立しており、唯一の構造は同一のシングルトン サブツリーをマージすることです。 DFS は、子の順列のカウントに帰着する二項係数を使用して各リーフをマージし、ルート制約に違反することなく期待される階乗構造を生成します。
