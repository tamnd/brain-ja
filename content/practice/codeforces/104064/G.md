 ## 問題の理解

 辞書順にソート済みのファイル名のリストと最大ターミナル幅が与えられます。 これらの名前を Unix と同様の列レイアウトで出力する必要があります。`ls`ただし、重要な違いが 1 つあります。すべての列に同じ行数を強制するのではなく、列ごとに異なる列の高さを選択できます。 

各列は、その列に配置される最長の文字列に等しい固定幅を持ち、列は 1 つのスペースで区切られます。 列内では、エントリが上から下にリストされます。 グリッド全体は端子の幅制限を遵守する必要があります。 グリッドを列ごとに読み取るには、元の辞書編集順を再現する必要があります。 

必要な行の総数が最小限になるように、使用する列の数、各列に効果的に含まれる行の数、および並べ替えられたリストを列に分割する方法を選択することがタスクとなります。 

制約が十分に厳しいため、$O(n^2)$あるいはさらに悪い解決策$n=5000$各移行にコストがかかる場合は、TLE になる可能性があります。 しかし、$n^2$状態遷移は、事前計算によりそれぞれが一定時間またはほぼ一定である場合に許容されます。 

素朴なアプローチにおける微妙な障害モードは、列数を増やすと常に行数が減ると仮定することから生じます。これは誤りです。列グループごとに多くの要素を詰め込むと列幅が増加するためです。 

もう 1 つのよくある間違いは、列の高さを均等にすることを強制することです。これにより、実現可能性が完全に変わってしまいます。 たとえば、単語のパーティションがわずかに異なると、同じ幅の制約の下で最大行数が減少するため、貪欲な列のフィルは最適性に違反する可能性があります。

 ## アルゴリズムのチュートリアル

 考えられる各行数を扱います$r$を候補として挙げ、実現可能性を確認します。 

1. 各実行可能性チェックでは入力文字列を線形にスキャンするため、入力文字列以外は何も事前計算しません。 これにより、各チェックが単純になり、オーバーヘッドが回避されます。 
2. 固定の場合$r$、左から右に柱の構築をシミュレートします。 インデックスから開始$i = 0$。 各列について、最大で$r$で始まる連続した文字列$i$、それらの間の最大長を計算します。 この最大値によって列幅が決まります。 
3. 合計幅は、列幅と隣接する列間の 1 つのスペースの合計として追跡されます。 どこかの時点でこれを超えた場合$w$の場合、構成は失敗します。 
4. すべての文字列が消費されるまで続行します。 成功すると、選択された$r$実現可能です。 
5. 実行可能な最小の二分探索$r$1との間$n$。 これにより、必要な最小限の行数が得られます。 
6. 最適な値を決定した後$r$、同じ貪欲なグループ化を使用して列を再構築します。 各列のセグメント境界と幅を保存します。 
7. 印刷$r$、列数、列幅を指定してから、グリッドを行ごとに出力し、欠落しているエントリを空白で埋めます。 

構造上の重要な点は、行数が固定されている場合、欲張りな左から右へのパッキングにより、その行制限に対して可能な最小の幅使用量が得られることです。 グループ化を遅らせる代替パーティションは、順序や行の制約に違反せずにセグメント内の最大長を減らすことができないため、列幅を増やすか保持することしかできません。 

### なぜ効果があるのか

 固定の場合$r$、境界が選択されると各列は独立し、そのコストはそのセグメント内の最大文字列長によってのみ決定されます。 配列を順番に処理し、すべての列が次のように制限されているため、$r$アイテムの場合、実行可能なソリューションは最大でもサイズのセグメントへの何らかのパーティションに対応します。$r$。 貪欲な構造により、特定のセグメンテーション パターンの列数が最小限に抑えられるため、スペースの使用量が最小限に抑えられます。 二分探索が機能するのは、実行可能性が単調であるためです。$r$: レイアウトが一部で機能する場合$r$、それはさらに大きなものでも機能します$r$より高い列を許可しても実現可能性が制限されることはないためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def feasible(words, n, w, r):
    cols = []
    i = 0
    total_width = 0

    while i < n:
        mx = 0
        j = i
        cnt = 0
        while j < n and cnt < r:
            mx = max(mx, len(words[j]))
            j += 1
            cnt += 1
        cols.append((i, j, mx))
        i = j

    # compute width with spaces
    total_width = sum(c[2] for c in cols) + (len(cols) - 1)
    return total_width <= w

def build(words, n, r):
    cols = []
    i = 0
    while i < n:
        mx = 0
        j = i
        cnt = 0
        while j < n and cnt < r:
            mx = max(mx, len(words[j]))
            j += 1
            cnt += 1
        cols.append((i, j, mx))
        i = j
    return cols

def main():
    n, w = map(int, input().split())
    words = [input().strip() for _ in range(n)]

    lo, hi = 1, n
    while lo < hi:
        mid = (lo + hi) // 2
        if feasible(words, n, w, mid):
            hi = mid
        else:
            lo = mid + 1

    r = lo
    cols = build(words, n, r)
    c = len(cols)

    widths = [x[2] for x in cols]

    print(r, c)
    print(*widths)

    grid = []
    for row in range(r):
        line = []
        for (l, rr, _) in cols:
            if l + row < rr:
                line.append(words[l + row].ljust(_))
        grid.append(line)

    for line in grid:
        print(" ".join(line))

if __name__ == "__main__":
    main()

グリッド構築ステップは、各列がすでに連続セグメントとして定義されているという観察に基づいているため、行にアクセスすることはできません。$i$単に、オフセットで各セグメントにインデックスを付けることを意味します$i$存在する場合。 スペースをパディングすると、事前計算された列幅に確実に揃えられます。

 ## 特殊なケース

 単一のファイル名は、アルゴリズムが不必要な分割なしで 1 つの行と 1 つの列を正しく返すかどうかをテストします。 貪欲なパッキングでは 1 つのセグメントが生成され、二分探索では次のセグメントに落ち着くはずです。$r=1$。
