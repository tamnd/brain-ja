 ## 解決策
 ## 問題の理解

 システムは、数字と英字で構成される 1 から 20 までの長さの秘密のパスワードを隠します。 候補文字列を繰り返し送信することができます。 送信するたびに、インタラクターは推測が正しいかどうかを教えてくれます。 それが間違っている場合は、単純な文字ごとの文字列の等価性チェックから導出された固定タイミング モデルに従って、比較手順の評価に費やした正確な時間も明らかになります。 

重要な点は、パスワード チェックが瞬時に行われず、タイミングによって構造情報が漏洩してしまうことです。 不一致が検出されると比較はただちに停止し、チェック内の各操作は既知のミリ秒数に影響します。 これは、最初の不一致が発生する前に隠しパスワードと一致する先頭文字の数に応じて、推測が異なると実行時間も異なることを意味します。 

目標は、最大 2500 回の推測を使用してパスワードを再構築することです。 

長さとアルファベットの制約は、62^20 でも天文学的に大きいため、すべての文字列を完全に網羅する検索は不可能であることを意味します。 使用できる唯一の信号はタイミングであるため、ソリューションではパスワードに関する情報を 1 文字ずつ抽出する必要があります。 

単純なアプローチでは、ランダムな推測またはすべての文字列の体系的な列挙を試みます。 位置あたりの長さを 20 文字、62 文字に制限しても、許容されるクエリ数をはるかに超える検索スペースが得られるため、どちらも失敗します。 

微妙なエッジケースは、等しい長さの比較と不一致な長さの比較のタイミングが異なるという事実から生じます。 長さの決定を無視すると、固定長のプレフィックス再構成戦略を誤って想定し、パスワードが予想より短いか長い場合に失敗する可能性があります。 もう 1 つの問題は、早期終了によりタイミングが非線形になるため、慎重に構造化しない限り、複数の推測にわたる単純な時間の平均では直接位置を回復できないことです。 

## アプローチ

 ブルートフォースの観点では、これをブラックボックスのパスワード推測問題として扱うことです。 すべての文字列を辞書順に列挙し、それぞれをクエリすることができます。 これは正しいですが、絶望的です。たとえ長さを 1 位置あたり最大 20 シンボル、62 シンボルに制限したとしても、最悪の場合の試行回数は 20 で指数関数的に増加し、2500 をはるかに超えます。 

重要な観察は、インタラクターがタイミングを通じてプレフィックス一致の長さを漏洩するということです。 指定されたパスワードの比較は、最初の不一致で停止するループのように動作します。 一致する文字ごとに、予測可能な量だけ実行時間が延長されます。 したがって、推測されるプレフィックスを制御すると、チェックの実行時間を観察することで、先頭の文字が何文字正しいかを測定できます。 

これにより、問題はパスワードを一度に 1 桁ずつ再構築することに変わります。 各位置で、すでに検出されたプレフィックスを修正し、考えられるすべての次の文字を試します。 正しい文字は一致比較の継続を最長にします。したがって、その位置のすべての候補の中で観察された時間が最大になります。 

短縮されるのは、完全な文字列に対する指数関数的検索から位置に対する線形検索であり、それぞれ最大 62 回の試行が必要です。 パスワードの長さは最大 20 であるため、クエリの総数は最大 20 × 62 = 1240 であり、制限内に安全に収まります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース列挙 | O(62^L) | O(L) | 遅すぎる |
 | プレフィックス タイミングの再構築 | O(62・L) | O(L) | 承認済み |

 ## アルゴリズムのチュートリアル

 指定された推測文字列の測定時間を返す関数へのアクセスを想定します。

1. 空のプレフィックス文字列から始めます。 これは、すでに再構築されたパスワードの一部を表します。 この段階では、パスワードについては何も想定しません。 
2. 1 ～ 20 の各位置について、現在のプレフィックスを 1 文字拡張してみます。 許可されているアルファベットのすべての文字を反復処理します。 各候補は、文字を追加する完全な推測を形成し、必要に応じてパディングするか、単にインタラクターの長さ比較動作に依存します。 
3. 候補文字ごとに、現在知られているプレフィックスとその文字で構成される文字列を送信します。 戻ってきた時間を記録します。 正確性に関する洞察は、実際のパスワードと一致する最初の文字が多いほど、失敗または完了するまでの比較の実行時間が長くなるということです。 
4. 観察された最大時間をもたらす文字を選択します。 比較中に正しい拡張子のみが一致する最長のプレフィックスを保持するため、この文字はパスワードの正しい次の文字である必要があります。 
5. 選択した文字をプレフィックスに追加します。 
6. いずれかの時点でインタラクターが「ACCESS GRANTED」と応答した場合は、パスワードが完全に一致しているため、直ちに終了します。 
7. さらに文字を追加してもタイミングが有意に増加しない場合、または試行を繰り返しても完了が示される場合は、早めに中止します。 実際には、パスワードが完全に一致すると、ループは自然に終了します。 

### なぜ効果があるのか

 パスワード チェックは順次比較を実行し、最初の不一致で停止します。 固定プレフィックス推測の場合、実行時間は、隠しパスワードと共有される正しいプレフィックスの長さに応じて厳密に増加します。 既知の正しいプレフィックスのすべての 1 文字拡張のうち、次の正しい文字だけがこのプレフィックスを保持するため、終了前に実行される成功した比較の数が最大になります。 これにより、単調な信号が作成されます。正しい選択は、誤ったものよりも厳密に高い観測実行時間に対応し、各位置での貪欲な選択が有効になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import string

alphabet = string.ascii_letters + string.digits

def query(s):
    print(s, flush=True)
    resp = input().strip()
    if resp.startswith("ACCESS GRANTED"):
        sys.exit(0)
    # format: ACCESS DENIED (t ms)
    # time is embedded but not strictly needed
    return resp

def main():
    prefix = ""

    for _ in range(20):
        best_char = None
        best_time = -1

        for c in alphabet:
            guess = prefix + c
            resp = query(guess)

            # extract time
            # format: ACCESS DENIED (t ms)
            try:
                t = int(resp.split("(")[1].split()[0])
            except:
                t = 0

            if t > best_time:
                best_time = t
                best_char = c

        prefix += best_char

        # optional early stop: if last query was already full match,
        # interactor would have exited

    print(prefix, flush=True)

if __name__ == "__main__":
    main()
```このソリューションでは、増加するプレフィックスを維持し、各ステップで考えられるすべての次の文字を試します。 インタラクション ループは厳密です。出力されたすべての推測は直ちにフラッシュされなければなりません。そうしないと、インタラクターが応答せず、プログラムがデッドロックしてしまいます。 

時間抽出は、候補を比較するためにのみ使用されます。 実際の数値は順序付け以外には必要ないため、たとえ解析に多少のノイズがあったとしても、相対最大値は一貫したままになります。 

パスワードの長さは最大 20 であるため、ループの反復回数は 20 回に制限されています。各反復では、最悪の場合でも 62 個のクエリが実行されます。 

## 実用的な例

 隠しパスワードを検討する`"A7b"`。 

先頭ではプレフィックスは空です。 すべての文字を試してみます。 のみ`"A"`パスワードの最初の文字と一致するため、一貫してより高いタイミングで応答が生成されます。 それで`"A"`が選択されます。 

2 回目の反復では、接頭辞は次のようになります。`"A"`。 試してみます`"Aa"`、`"Ab"`、`"A7"`、などのみ`"A7"`は 2 番目の文字と一致するため、最大の時間が得られます。 

3 回目の反復では、接頭辞は次のようになります。`"A7"`。 すべての拡張機能を試すと表示されます`"A7b"`最大時間が生成され、受け入れられます。 

| ステップ | プレフィックス | 試した文字 | 最高のイワナ | 観察された効果 |
 | --- | --- | --- | --- | --- |
 | 1 | "" | すべて | あ | A は最長のプレフィックス一致を生成します。 
| 2 | "A" | すべて | 7 | A7 は一致を拡張します |
 | 3 | 「A7」 | すべて | b | 完全一致に達しました |

 これは、プレフィックスの正確さを測定可能な実行時の差に増幅することによって、タイミングがどのように各位置で正しい文字を分離するかを示しています。 

次にパスワードを検討します`"0Z"`。 

プレフィックスで`""`、すべての最初の文字の推測が比較されます。`"0"`。 のみ`"0"`最長の比較チェーンが生成されます。 プレフィックスで`"0"`、 のみ`"0Z"`完全一致を生成します。 

これは、この方法が文字タイプの分布やアルファベットの順序に依存せず、前方一致の長さだけに依存していることを示しています。

 ## 特殊なケース

 長さ 1 のパスワードの場合`"G"`、アルゴリズムは空のプレフィックスから始まり、すべての文字を試します。 のみ`"G"`は、不一致の前に最初の文字とすぐに一致するため、最大のタイミングが得られます。 選択した文字が完全なパスワードとなり、プロセスは 1 回の反復で完了します。 

多くの文字が他の候補と長いプレフィックスを共有するパスワードの場合。`"abcXYZ"`、すべての推測を共有`"abc"`位置 4 までは同様に動作します。その時点では、正しいものだけが`"X"`拡張子は追加の一致比較を生成するため、以前のあいまいさにもかかわらず、正しい分岐を明確に分離します。
