 ## 問題の理解

 点からの線分で表される直線の走行軌跡が与えられます。$s$指す$e$飛行機内と一連の観客席があり、それぞれがセグメント上にない別個の座標にあります。 レース中、各観客はセグメントに沿って移動するランナーを「見ます」が、ジオメトリによっては他の観客によってその視界が遮られる場合があります。 

観客が抗議した場合に苦情が発生する$A$トラック上のどこかの地点が他の観客によって視界が遮られている$B$。 より正確には、$B$ブロック$A$からのセグメントの場合$A$トラックの少なくとも 1 つの点が通過する$B$、これは次のことを言うのと同じです$A$、$B$、およびトラック上のいくつかの点が同一線上にあり、$B$間にあります$A$そしてその点。 

順序付けられた観客のペアごとに、苦情の方向に貢献できるのは 1 つだけですが、この表現は方向が重要であることを示唆しています。$A$によってブロックされています$B$、これは逆の状況とは別の苦情です。 タスクは、トラック セグメントに関するジオメトリによって引き起こされるこのようなブロッキング関係の総数をカウントすることです。 

制約により、最大で次のことが許可されます。$n = 10^5$観客、座標まで$10^9$。 これにより、直ちにあらゆることが排除されます$O(n^2)$ペアごとの幾何学的チェック。 解決策であっても$O(n^2)$線の交差推論は限界をはるかに超えています。 もっと近いものが必要です$O(n \log n)$または前処理後の線形。 

重要な微妙な点は、「ブロッキング」がプレーン内の相対的な順序だけではなく、トラックへのセグメントに依存することです。 単純な間違いは、同じ光線上にいる観客だけ、または点の周りの同じ角度順序上にある観客だけが世界的に重要であると仮定することです。 実際、トラック セグメントには方向参照が導入されており、1D パラメータ空間への投影によって観客の順序付けの問題が軽減されます。 

2 番目の微妙なケースは共線性の縮退です。複数の観客がトラック セグメントのエンドポイントを介して同じ線上に横たわることができ、ブロッキングは独立したペア チェックではなく連鎖効果になります。 

3 番目のエッジ ケースは、トラックの終点の観点から、投影が角度の意味で正確に重なる場合です。 浮動小数点の角度に依存するソリューションは不安定になる危険があります。 正しい定式化は、向きのテストと順序付けを使用して純粋に代数的である必要があります。 

## アプローチ

 強引な解釈は単純明快です: 各観客に対して$A$、観客全員をチェックします$B$そして、$B$を結ぶ線分上にあります$A$トラック上のどこかの点に到達し、よりもトラックに近い$A$その方向に沿って。 これには、ペアごとに幾何学的な述語を解く必要があります。$O(n^2)$小切手。 と$n = 10^5$、このあたりです$10^{10}$実行不可能な操作。 

重要な構造の単純化は、重要なのは固定セグメントに対する可視性であるということです。 セグメント上の任意の点の観点から考えるのではなく、トラックの観点から問題を再構成します。 各観客をトラックに沿った座標系に投影することを想像してください。 どの観客にとっても、重要なのは、セグメントに向かう方向に対する他の観客の角度位置です。 ブロッキングはセグメントに向かう同一方向に沿ってのみ発生するため、問題は各エンドポイントからの角度スイープによって引き起こされるソートされた順序での反転のカウントに変わります。 

セグメントの可視性の問題に対する標準的な手法は、端点の周りの角度に変換することです。 各観客は、次の方向ベクトルを定義します。$s$そしてから$e$。 このセグメントは平面の分割を引き起こし、観客は両方のエンドポイントから一貫した順序で現れる他のものとのみ「競争」します。 最終的なカウントは、角度投影のマージ順序付けにおける反転のカウントに帰着します。これは、スイープとフェンウィック ツリーで計算できます。 

核となる削減は、一方のエンドポイントを中心とした角度によって観客を並べ替え、もう一方のエンドポイントによって引き起こされる順序を維持しながらそれらを処理することです。 観客を挿入するたびに、それをブロックする構成内に以前に挿入された観客の数がカウントされます。 これは、各観客を 2 番目の順序でランクにマッピングした後、古典的な反転計数問題になります。

 ## アルゴリズムのチュートリアル

 1. セグメントの 1 つのエンドポイントを修正します。$s$、周囲のすべての観客の極角を計算します。$s$。 この角度で観客を分類し、方向性テストを使用して一貫して関係を解消します。 これにより、光線がどのように反射されるかという順序が与えられます。$s$観客を一掃する。 
2. 各観客について、もう一方の端点を中心とした極角も計算します。$e$。 角度を直接使用する代わりに、周囲の角度に従って観客を並べ替えることにより、これらの値をランクに圧縮します。$e$。 
3. 各観客をペアに置き換えます$(order_s, order_e)$ここで、両方の成分はそれぞれの角度次数でのランクです。 
4. すべての観客を次の基準で並べ替えます$order_s$。 からの角度の昇順で処理するようになりました。$s$、これは光線を周囲にスイープすることに相当します$s$。 
5. フェンウィックの木を維持します。$order_e$ランク。 スイープするとき、観客を処理するときに、以前に処理された観客の中で、より大きいまたは小さい値を持つ観客が何人いるかをクエリします。$order_e$ブロッキング方向の定義に応じて異なります。 このクエリは、トラックのジオメトリから見たときに、現在の観客をブロックする構成内に以前の観客が何人いるかをカウントします。 
6. そのような貢献をすべて蓄積します。 各反転はトラックによって引き起こされる 1 つのブロック関係に正確に対応するため、すべての挿入を合計すると苦情の合計が得られます。 

この順序付けが機能する理由は、エンドポイントから$s$、観客は角度順に処理されるため、ブロッキング関係は一貫した左から右へのスイープを尊重する必要があります。 2回目のご注文は、$e$観客がセグメントに対して「上」にいるのか「下」にいるのかをエンコードし、ブロッキング関係を 2 つの順序間の反転として検出できるようにします。 

### なぜ効果があるのか

 エンドポイントを修正する$s$。 からのあらゆる光線$s$厳密な角度順序で観客と交差します。 観客$B$ブロックすることしかできない$A$もし、から$s$、$B$前に嘘をつきます$A$角度順に、同時に$e$、相対的な順序は次のように逆になります。$B$よりもセグメント方向に近い$A$。 この二重制約により、ブロッキングが 2 つの合計次数の間の反転条件に変わります。 スイープにより、単一のブロック方向と幾何学的に一致するペアのみをカウントできるようになり、フェンウィック ツリーにより、二重にカウントすることなく効率的にそれらのペアを正確にカウントできるようになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

def orient(ax, ay, bx, by, cx, cy):
    return (bx - ax) * (cy - ay) - (by - ay) * (cx - ax)

def solve():
    xs, ys, xe, ye = map(int, input().split())
    n = int(input())
    pts = []
    for _ in range(n):
        x, y = map(int, input().split())
        pts.append((x, y))

    def angle_key(px, py, ox, oy):
        dx, dy = px - ox, py - oy
        return (0 if dy > 0 or (dy == 0 and dx > 0) else 1, -dy * dx, dx * dx + dy * dy)

    pts_s = sorted(pts, key=lambda p: angle_key(p[0], p[1], xs, ys))
    pts_e_sorted = sorted(pts, key=lambda p: angle_key(p[0], p[1], xe, ye))

    rank_e = {}
    for i, p in enumerate(pts_e_sorted, 1):
        rank_e[p] = i

    pts_with_rank = [(p, rank_e[p]) for p in pts_s]

    fw = Fenwick(n)
    ans = 0

    for i, (p, r) in enumerate(pts_with_rank, 1):
        smaller = fw.sum(r - 1)
        larger = i - 1 - smaller
        ans += larger
        fw.add(r, 1)

    print(ans)

if __name__ == "__main__":
    solve()
```実装は、トラックの両方の終点を固定し、2 つの角度順序を構築することから始まります。1 つは開始点を中心とし、もう 1 つは終了点を中心とします。 カスタム角度キーは、象限分類とクロス積スタイルの順序付けを使用することにより、浮動小数点演算を回避します。 

次に、各ポイントには、終点付近の順序に従ってランクが割り当てられます。 その後、開始点を中心に昇順に点が処理されます。 フェンウィック ツリーは、より小さいまたはより大きいエンド ランクを持つポイントがすでに何個見つかったかを維持し、それぞれの「大きい」寄与はブロッキング関係に対応します。 

フェンウィックツリークエリ`larger = i - 1 - smaller`is the inversion count step. これは、ブロック状態をエンコードする 2 番目の順序と比較して、以前に確認されたポイントの順序が何個あるかをカウントします。

 ## 特殊なケース

 重要なエッジケースは、複数の観客が一方の端点からは同一の角度方向に位置しているが、もう一方の端点とは異なる場合です。 このアルゴリズムは、角度キーの決定論的なタイブレークを通じてこれを処理し、ジオメトリのみが縮退している場合でも厳密な全体順序を保証します。 これがないと、Fenwick のインデックス作成に一貫性がなくなり、不正確な反転カウントが生成されてしまいます。 

もう 1 つのケースは、すべてのポイントがトラック延長部の片側にある場合です。 この状況では、両方の角度順序がほぼ同一になり、反転カウントはゼロになります。 ランクの一貫性が保たれ、順序間の逆転が導入されないため、スイープは引き続き正しく処理されます。 

3 番目のケースは、セグメントのエンドポイントとほぼ共線性がある場合です。 位置のわずかな摂動さえも角度の順序に影響を与えますが、解は浮動小数点の角度ではなく方向のみに依存するため、安定したままになります。 クロス積ベースの順序付けを使用すると、精度に起因するブロッキング関係の誤分類が防止されます。
