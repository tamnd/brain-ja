 ## 解決策

 ## 問題の理解

 24 時間時計の読み取り値が時と分の形式で与えられているので、次の午前 0 時 (時計が 00:00 にリセットされる瞬間) まで残り何分かを判断したいと考えています。 

時間と分を別々に考える代わりに、現在時刻を 1 日の始まりから分単位で測定される直線的なタイムライン上の位置として解釈すると役立ちます。 丸 1 日には 24 × 60 = 1440 分が含まれます。 次に、タスクは、現在の位置が 1440 分からどのくらい離れているかを測定することですが、日の境界を囲みます。 

制約は非常に小さいです。 各テスト ケースは独立しており、最大 1439 のケースがあります。 テスト ケースごとに定数時間の演算を実行するソリューションでも十分です。 数分にわたるシミュレーションや反復的なステップ実行を伴うものはすべて簡単に通過しますが、不必要でクリーンではなくなります。 

微妙な点は、真夜中および真夜中近くの時間帯の境界条件を処理することです。 たとえば、時刻が 23:59 の場合、00:00 までは 1 分しか残っていないため、答えは 1 になります。 時刻が 0:01 の場合、真夜中までほぼ丸一日残っているため、答えは 1439 になるはずです。 もう 1 つの重要なケースは、残り 60 分の 23:00 です。 不注意なアプローチは、合計分に換算するのではなく、時間と分を誤って個別に扱い、失敗することがよくあります。 

もう 1 つの潜在的な間違いは、00:00 が明示的に除外されていることを忘れていることです。 それが許可される場合、答えは 0 になりますが、ここではそのケースを処理する必要はありません。 

## アプローチ

 ブルートフォース解釈では、現在時刻から 00:00 に達するまで分ごとにシミュレートされ、各ステップでカウンターが増加します。 時間は 1 分の移行ごとに決定的に進むため、これは正しいです。 ただし、最悪の場合、時刻が 00:01 の場合、これには 1439 ステップが必要となり、多くのテスト ケースにわたって不必要なオーバーヘッドとなります。 制約の下では技術的にはまだ実現可能ですが、これは意図された推論パスではありません。 

重要な観察は、クロックが 1440 分の固定サイクルで周期的であるということです。 任意の時刻 (h, m) は、午前 0 時からのオフセットを表す単一の整数 (h × 60 + m) に直接マッピングできます。 この線形表現が得られると、次の午前 0 時までの残り時間は単純にサイクル内の補数となり、1440 − (h × 60 + m) として計算されます。 

これにより、シミュレーションの必要がなくなります。 問題の構造は固定サイクルでの純粋なモジュラー演算であり、答えは次の 1440 の倍数との差が直接得られます。

 ## アルゴリズムのチュートリアル

 1. h × 60 + m を使用して、指定された時間 (h、m) を午前 0 時からの合計分数に変換します。 これにより、クロック状態の単一の線形表現が作成されます。 
2. 1 日の合計分数 (1440 分) を計算します。 
3. 1440 から現在の分オフセットを減算して、午前 0 時までの残り時間を取得します。 
4. この値をテスト ケースごとに個別に出力します。 

時間と分を別々に処理すると午前 0 時までの直線距離が維持されないため、変換手順が必要です。 統一された分ベースの表現のみが、減算を意味のあるものにします。 

### なぜ効果があるのか

一日全体は 1440 分のサイクルを形成します。 すべての有効な時間は、このサイクル上の固有のポイントに対応します。 h × 60 + m の演算により、00:00 から始まるそのサイクル上の正確な位置が得られます。 時間は 1 分単位の固定増分で進むため、次の 00:00 までの残り時間は、現在位置からサイクルの終わりまでの距離となります。 00:00 がサイクルの原点であるため、1440 から減算すると、ゼロ以外のすべての状態に対する正しいラップアラウンド距離が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        h, m = map(int, input().split())
        current = h * 60 + m
        print(1440 - current)

if __name__ == "__main__":
    solve()
```ソリューションの核心はコンバージョンラインです`current = h * 60 + m`。 これにより、2 次元の時計表現が単一のスカラーに圧縮され、距離の計算が簡単になります。 

引き算`1440 - current`一日の残りの部分を直接反映します。 入力によって 00:00 に開始しないことが保証されるため、条件付きロジックは必要ありません。したがって、結果は常に正になります。 

高速入力の使用はオプションですが、競技プログラミング テンプレートでは標準となっており、最大テスト数でも一貫したパフォーマンスが保証されます。
