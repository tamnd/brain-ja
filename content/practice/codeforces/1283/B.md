 ## 問題の理解

 一定数の子どもたちに、一定数の同じキャンディーを配布します。 各子供は負ではない整数のキャンディーを受け取る必要があり、いくつかのキャンディーを未使用のままにしておくことが許可されています。 分布は、子に割り当てられた値が厳密にバランスされている場合にのみ有効であると見なされます。つまり、割り当てられた最大値と最小値の違いは最大でも 1 であるため、すべての子はいずれかの値を受け取ります。$a$または次の値$a+1$。 その上、価値が高いほど、$a+1$あまりにも一般的であることはできません。具体的には、端数を切り捨てて、最大でも半分の子供に出現する可能性があります。 

目標は、有効な配布自体を見つけることではなく、これらの制約を尊重しながら実際に配布されるキャンディーの数を最大化することです。 

入力サイズが大きく、最大$5 \cdot 10^4$テストケースと値$n$そして$k$まで$10^9$。 分布をシミュレートしたり、テスト ケースごとに可能な割り当てを反復しようとしたソリューションは、遅すぎます。 正しいソリューションでは、各テスト ケースを定数時間の演算に削減する必要があります。 

素朴だが魅力的なアイデアは、子供の数を固定してみることです。$a+1$キャンディーを作成し、それぞれの選択の実現可能性を計算します。 これは、より価値の高い子の数の制約が残りのキャンディーと相互作用するという特殊なケースでは破綻します。 たとえば、$k = 5$、平均分布を貪欲に最大化しようとすると、割り当てが多すぎる可能性があります。$a+1$価値観、違反$\lfloor k/2 \rfloor$たとえわずかに異なる分割によってより多くのキャンディーの総数が許可されるとしても、上限に達します。 

別の失敗モードは、すべてのキャンディーが均等に分配されていると仮定することから生じます ($n/k$) は常に最適です。 いつ$k = 3$そして$n = 8$、均一な分割により、$[2,2,2]$6 つのキャンディーが使用されていますが、より有効な構成では、$a/a+1$慎重に構造化します。 

## アプローチ

 ブルートフォースアプローチは、可能な値をすべて試してみることです。$a$、それぞれについて、何人の子供を連れて行けるかを決定します。$a+1$、使用したキャンディーの総数が以下に達するかどうかを確認します。$n$以下で、最も有効な合計を選択します。 それぞれについて$a$場合は、より高く割り当てられた子の可能性のある数をスキャンし、合計を再計算し、制約を検証します。 これには、最大の値を反復処理する必要があります。$n$、そしてそれぞれの試みについて$k$分裂し、実行不可能な事態につながる$O(nk)$またはさらに悪いプロセス。 

重要な観察は、有効な分布はすべて、次の 2 つの整数によって完全に決定されるということです。$a+1$、何人が受け取りますか$a$。 より価値の高い子供の数を修正したら$x$、残りは強制されます。 制約$x \le \lfloor k/2 \rfloor$ブーストできる子の数は直接制限されます。 固定の場合$x$、最大のキャンディーは次のように計算できます。$$(k-x)\cdot a + x \cdot (a+1) = k\cdot a + x.$$キャンディーの合計を最大化したいので、両方を最大化したいと考えています。$a$そして$x$ただし、キャンディーの合計が以下を超えないという要件によって結合されます。$n$。 

これにより、選択の問題が軽減されます$x$最適に導き出す$a$残りの予算から。 構造は線形になり、最適な構成は常に制約によって決定される境界で発生します。$x$。

 ## アルゴリズムのチュートリアル

 分布を 2 つのグループに関して書き直します。$k-x$子供たちが受け取ります$a$、 そして$x$子供たちが受け取ります$a+1$、 どこ$0 \le x \le \lfloor k/2 \rfloor$。 

1. 候補番号を確定する$x$、受け取る子供の数$a+1$。 残りのすべての子は受け取る必要があるため、これにより、分布の構造が即座に決定されます。$a$。 
2. 使用したキャンディーの合計数を次のように表します。$k \cdot a + x$。 これは次のことから始まります$a$子供1人につきキャンディーを1つ追加し、それぞれにキャンディーを1つ追加します。$x$選ばれた子供たち。 
3.固定の場合$x$、最大化する$a$の対象となる$k \cdot a + x \le n$。 これにより、$a = \left\lfloor \frac{n-x}{k} \right\rfloor$。 
4. 代入して、次のように使用されるキャンディーの合計を計算します。$$\text{candies}(x) = k \cdot \left\lfloor \frac{n-x}{k} \right\rfloor + x.$$5.以来$x$によって制約されています$0 \le x \le \lfloor k/2 \rfloor$の場合、問題はこの関数の境界動作のみをチェックすることになります。 増加中$x$1 ずつ除算の基本項を減らすことができるので、両方の極端な値をテストします。$x = 0$そして$x = \lfloor k/2 \rfloor$、最大値を取ります。 

エンドポイントのみが重要である理由は、関数が区分的に線形であり、次の倍数で周期的に低下するためです。$k$、許容範囲内$x$、最大値は、実行可能な間隔の境界の 1 つで発生する必要があります。 

### なぜ効果があるのか

 分布は、より大きな値を取得する子の数にのみ依存し、実行可能なすべての構成は単一の整数パラメータに集約されます。$x$。 それぞれについて$x$、可能な限り最高の$a$各子を貪欲にできるだけ多く満たすことによって一意に決定されます。$k$- 可能な限りキャンディーのグループ。 増えてからは$x$基本商を段階的に減少させながら剰余項をシフトするだけであり、内部値はありません。$x$両方のエンドポイントを同時に厳密に支配できます。 これにより、境界ケースのみを評価することが保証されます。$x$最適解を導き出します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())

        x = k // 2

        def calc(x):
            a = (n - x) // k
            return a * k + x

        ans = max(calc(0), calc(x))
        print(ans)

if __name__ == "__main__":
    solve()
```このコードは、受け取る子の数の 2 つのキー候補をエンコードします。$a+1$。 ヘルパー関数は、固定値に対して達成可能な最良の合計を計算します。$x$、最初に可能な最大の基本値を決定します。$a$、そして合計を再構築します。 

チェックだけするという選択$x = 0$そして$x = k//2$これは、中間値が基本割り当てとボーナス割り当ての両方を同時に改善できないという制約構造から導き出されます。
