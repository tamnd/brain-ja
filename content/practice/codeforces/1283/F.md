 ## 解決策
 ## 問題の理解

 私たちに与えられた木は、$n$各頂点はランプを表します。 これらのランプの 1 つは電源に直接接続されており、そこから電力が木のワイヤーによって形成された有向接続を介して広がります。 各ワイヤには暗黙の方向があります。一方の端点は光源 (メイン ランプ) に近く、もう一方の端点は遠方 (補助ランプ) にあります。 

各ランプ$i$重みがある$2^i$そのため、インデックスの高いランプは、インデックスの低いランプよりも指数関数的に重要になります。 ワイヤを削除すると、ツリーは 2 つのコンポーネントに分割され、そのワイヤの「重要度」は、ワイヤが切断されたときに電源から切断されるコンポーネント内のすべての頂点の重みの合計として定義されます。 言い換えれば、エッジが削除されたときにルートへのアクセスを失うサブツリーの合計の重みです。 

難しいのは、私たちには木が与えられていないということです。 代わりに、シーケンスが与えられます。$a_1, a_2, \dots, a_{n-1}$、 どこ$a_i$の主要エンドポイントです$i$- 番目に重要なワイヤ。重要度が厳密に降順にソートされています。 この順序付けとこれらの「メインエンドポイント」から、そのような順序付けを生成できる有効なルートツリーを再構築する必要があります。 

制約は大きく、$n \le 2 \cdot 10^5$したがって、可能なツリーを列挙したり、サブツリーの重みを明示的に再計算しようとするアプローチは、非常に遅すぎます。 直線または直線に近い構造が必要です。 

重要な構造上の難点は、重みが 2 のべき乗であることです。 これにより、サブツリーの合計はバイナリ表現のように動作します。すべてのサブツリーの合計は、その内部の頂点のセットによって一意に決定され、サブツリーの合計間の比較は、辞書編集的に最大のラベルを最初に比較することに対応します。 

素朴なアプローチは、考えられるすべてのルートを試し、誘導された重要度の順序を検証しながら貪欲にエッジを再構築しようとすることです。 これには、各仮エッジの後でサブツリーの合計を再計算することが含まれます。$O(n^2)$またはそれ以上の行為は不可能です$2 \cdot 10^5$。 

次のシーケンスを想定すると、微妙な失敗例が発生します。$a_i$親子関係を直接エンコードします。 そうではありません。 たとえば、同じ頂点が複数回出現する可能性があります。$a$これは、複数のエッジのメイン エンドポイントであり、これらのエッジがツリー構造の異なる部分に属していることを意味します。 治療するあらゆるアプローチ$a_i$このような場合、親配列はすぐに壊れます。 

## アプローチ

 この問題を解決する鍵は、指数関数的な重みを持つツリー内での重要度の動作を逆転させることです。 

なぜなら重みは$2^i$、2 つのサブツリーの合計を比較することは、各サブツリーに存在する最大のインデックスを比較することと同じです。 これは、各カット エッジの重要性が主に、分離されたコンポーネント内の最も高いラベルが付けられた頂点によって決定されることを意味します。 

与えられたシーケンスを解釈します$a_i$「切断された側」の最大ラベルの降順でエッジを記述します。 サブツリーに出現する最大のラベルがその寄与を完全に支配するため、構築では、より高いラベルが分離プロセスの「より早く」出現する必要がある階層を尊重する必要があります。 

これは貪欲な再構成戦略を示唆しています。つまり、頂点が主要なエンドポイントとして表示されるときに、それが新しく形成されたアタッチメント領域の代表となることを保証しながら、頂点を昇順に徐々にアタッチします。 

アタッチメントを受け入れることができる頂点で表される一連の「アクティブ コンポーネント」を維持します。 最初は、最も高いインデックスの頂点が、それを含むすべてのサブツリーの合計を支配するため、自然なアンカーとして機能します。 

値を処理するたびに$a_i$、新しい頂点が下にアタッチされる新しい接続を強制すると解釈します。$a_i$、利用可能な「スロット」を 1 つ消費します。$a_i$。 この順序により、頂点に遭遇したときに、その頂点が出現した回数だけ親として機能するのに十分な容量が事前に作成されていることが保証されます。 

これにより、問題は根のあるツリー上の度数バランスの構築に帰着しますが、根が与えられていないという点が複雑です。 ルートは、後で強制的にアタッチされるような方法で「子要件」として決して表示されない頂点、つまり、事実上、すべての割り当て後に残りの容量を持つ頂点として決定されます。 

成功した構築は、親の要求の複数のセットと一致するツリーを構築することに帰着します。$a_i$その頂点の下に割り当てられている 1 つの子スロットに対応します。 順序付けは、容量が残っている以前の頂点に新しいノードを常に接続できる場合に限り、実現可能性を保証します。

 ## アルゴリズムのチュートリアル

 シーケンスを、親をノードに割り当てる構築プロセスに変換します。 

1. 各頂点が配列内に何回出現するかを数えます。$a$。 これは、再構築されたツリー内で各頂点が最終的​​に持つ子の数を表します。 これは、すべての外観が 1 つのエッジに対応し、その頂点が主要なエンドポイントであるため機能します。 
2. 子を段階的に割り当てられるように並べ替えられたすべての頂点のリストを作成します。 最初は空の「利用可能な親」のキューを使用します。 
3. 構築制約によって暗示される範囲を超えて、子としてアタッチする必要のない頂点としてルート候補を特定します。 実際には、すべての割り当て後に、必ず 1 つの頂点が未使用の容量になることを保証します。 
4. ラベルの昇順で頂点を繰り返し、新しい頂点をそれぞれ、以前に使用可能な親にアタッチする必要があるものとして扱います。 
5. 導入する各頂点について、まだ容量が残っている現在利用可能な親に接続します。 親の選択はシーケンスの順序によって決まります。常に最も早い未解決の要件を消費し、重要度の低い順序を確実に尊重します。 
6. 子を親に割り当てた後、その親の残りの容量を減らします。 まだ容量が残っている場合は、今後の添付ファイルに引き続き使用できます。 それ以外の場合は、利用可能なセットから削除されます。 
7. 任意の時点で親を割り当てる必要があるが、使用可能な親がない場合、構築は不可能であり、出力されます。$-1$。 

すべての頂点が処理された後、エッジは有効なルート ツリーを定義し、強制的に子として設定されなかったがまだ容量が残っている頂点はルートとして機能できます。 

### なぜ効果があるのか

 正しさは、各頂点が次のように出現するという事実から得られます。$a$メインエンドポイントとして機能するエッジの正確な数を定義します。 重みは 2 の累乗であるため、エッジの順序付けは、分離されたコンポーネント内の最大ラベルの降順で制約を適用することと同じです。 これにより、貪欲な消費モデルが強制されます。つまり、下位のラベルの頂点が構造に影響を与える前に、上位のラベルの頂点がアタッチメントを「吸収」する必要があります。 

このアルゴリズムは、すべてのステップで、必要な親周波数に違反することなく、未処理の頂点をすべてアタッチできるという不変条件を維持します。 次の頂点を常に現在実行可能な親にアタッチするため、シーケンスによって暗示される必要な次数制約を破ることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    if n == 2:
        print(1)
        print(1, 2)
        return
    
    cnt = [0] * (n + 1)
    for x in a:
        cnt[x] += 1

    import heapq

    # available parents: (-remaining_capacity, node)
    heap = []
    edges = []

    # we will process nodes 1..n, maintaining a pool of available parents
    # initially, no edges are assigned; we add nodes gradually
    ptr = 1

    # function to push node into heap if it has capacity
    def add_node(u):
        if cnt[u] > 0:
            heapq.heappush(heap, (-cnt[u], u))

    # start by adding the first possible parent candidates
    for i in range(1, n + 1):
        add_node(i)

    # we will construct a spanning tree by greedily connecting nodes
    # ensure we always have a parent available different from current node
    for v in range(1, n + 1):
        # remove self from being parent candidate if present
        while heap and heap[0][1] == v:
            heapq.heappop(heap)

        if not heap:
            print(-1)
            return

        negc, u = heapq.heappop(heap)
        edges.append((u, v))
        cnt[u] += negc + 1  # decrement capacity

        if cnt[u] > 0:
            heapq.heappush(heap, (-cnt[u], u))

    # check connectivity (implicitly n-1 edges built)
    if len(edges) != n - 1:
        print(-1)
        return

    # choose root as node that never appears as child in this construction
    is_child = [False] * (n + 1)
    for u, v in edges:
        is_child[v] = True

    root = 1
    for i in range(1, n + 1):
        if not is_child[i]:
            root = i
            break

    print(root)
    for u, v in edges:
        print(u, v)

if __name__ == "__main__":
    solve()
```このコードは、貪欲な容量の解釈を実装しています。 各頂点は、リストに表示される回数に等しいクォータから始まり、それを親として割り当てるたびに、そのクォータの 1 ユニットが消費されます。 

ヒープには、親として機能するすべての頂点が維持されます。 新しい頂点ごとに$v$、有効な親を選択します$u$それは違います$v$自体。 これにより、自己ループが回避され、有効なツリー構造が保証されます。 親を使用した後、残りのクォータを更新し、まだ子を受け入れることができる場合は再挿入します。 

微妙な点は、ルートが事前にわからないことです。 子として決して表示されない頂点としてエッジを構築した後、それを再構築します。これは、その頂点がその上に何も接続されていない必要があるためです。

 ## 特殊なケース

 重要なエッジ ケースは、1 つの頂点が複数回出現する場合に発生します。$a$木が支えられるものと比べて。 たとえば、次の場合$n=3$そして$a = [1,1]$、頂点 1 には 2 つの発信親ロールが必要ですが、他の頂点は 2 つだけ存在します。 容量を使い果たした後、ヒープが十分な個別の添付ファイルを提供できなくなり、障害が発生する場合、アルゴリズムはこれを検出します。 

もう 1 つの微妙なケースは、あるステップで使用可能な唯一の親が現在のノード自体である場合です。 これにより、ツリー内では無効な自己ループが作成されます。 候補ヒープから現在のノードを明示的に削除すると、この状況が防止され、構造が非循環のままになります。 

最後の構造的なケースは、ルートが明らかでない場合です。 複数の頂点が子になることがない構成では、アルゴリズムはそのような頂点をルートとして選択します。 最終出力ではすべてのエッジが方向付けされていないため、そのような選択により、元のプロセスと一致する有効な根付きの解釈が得られます。
