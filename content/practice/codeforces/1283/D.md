 ## 解決策
 ## 問題の理解

 数直線上の一連の不動点が与えられ、それぞれがクリスマス ツリーを表します。 また、人を表す別の点のセットを配置するように求められますが、これには工夫が必要です。各人は最も近い木までの距離に等しいコストを寄与し、総コストを最小限に抑えるためにすべての人の位置を選択したいと考えています。 

重要な解釈は、私たちは人間と木を個別に対応させているわけではないということです。 代わりに、すべての整数位置には「最も近い木の距離」があり、それらの距離の合計ができるだけ小さくなるように、人を配置するために m 個の異なる整数位置を選択しています。 木と人は位置を共有できませんが、それ以外の場合は、整数線上のどこにでも自由に人を配置できます。 

制約 n, m ≤ 2 × 10^5 は、およそ O((n + m) log n) または O(n + m) の動作が必要であることを意味します。 ライン上の二次関数や位置ごとのスキャンは直ちに不可能になります。 考えられるすべてのポジションを個別に評価したり、拡張を段階的にシミュレートしたりする単純な試みは拡張できません。 

ツリーがまばらで m が大きい場合、微妙な失敗のケースが発生します。 たとえば、位置 0 で m = 5 に木が 1 本だけある場合、最適な解決策は、±1、±2、±3 などに人を配置することです。一方向にのみ拡張する貪欲な場合、対称性が失われ、過剰な負担が発生します。 

もう 1 つの重要なエッジ ケースは、重複する影響領域を作成する複数のツリーです。 たとえば、0 と 10 のツリーは、中間点を中心に距離が対称である平らな「谷」を作成します。単一のツリーから単純に貪欲に拡張すると、一方の側に誤ってバイアスがかかります。 

## アプローチ

 ブルートフォースアプローチでは、広い範囲内のすべての整数点を考慮し、人物を配置するために次に最適な位置を繰り返し選択します。 各候補位置 y について、すべての木をスキャンして最も近い木の距離 (O(n)) を計算します。 整数の位置は無限にありますが、実際には、ツリーの周囲の範囲、たとえば m で拡張された min(x) と max(x) の間の範囲に制限されます。 それでも、O(m) 個の位置を評価し、それぞれのコストが O(n) となり、O(nm) が得られますが、これは 2 × 10^5 には大きすぎます。 

重要な観察は、各ツリーが独立して、近くの整数点までの距離値が増加する波を「生成」していることです。 すべての整数の位置は、最も近いツリーによって制御される 1 つの領域にのみ属し、その領域内では、隣接するツリーとの中点境界に達するまで、ツリーから遠ざかるにつれて距離は直線的に増加します。 

そこで、位置の観点から考えるのではなく、視点を反転します。各ツリーは、拡大するレイヤーで候補を生成します。 任意のツリーに最も近い、占有されていない位置は、距離 1 の隣接位置、次に距離 2 というように、隣接するツリーとの境界によってさらなる成長がブロックされるまで続きます。 

これは当然、整数ライン上のマルチソース BFS を示唆しています。 すべてのツリー位置から同時に開始して外側に拡張します。各拡張ステップは 1 ずつ増加する距離に対応します。新しく発見されたすべての整数点には、明確に定義された最も近いツリー (最初に到達したツリー) があり、その距離は正確に BFS レベルです。 

m 個のポジションが集まるまでこの拡張を続けます。 BFS は常に距離が減少しない順序で探索するため、最初に発見された m 個の有効な位置がまさに最適な選択となります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nm) | お(1) | 遅すぎる |
 | マルチソース BFS | O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 すべてのツリー位置を整数座標上の BFS 内のソースとして扱います。

1. すべてのツリー位置でキューを初期化し、それぞれ距離 0 でマークします。また、ツリー位置に人を配置できないように、それらを訪問済みとしてマークします。 これにより、最初から制約が確実に尊重されます。 
2. 数直線上で BFS を実行します。 距離 d のポップされた位置 x ごとに、その 2 つの近傍 x − 1 および x + 1 を試します。 
3. 近隣が訪問されておらず、ツリー位置でもない場合は、それに距離 d + 1 を割り当て、訪問済みのマークを付けてキューにプッシュします。 また、このポジションが人に選ばれたことも記録します。 
4. m 人のポジションを集めるまで BFS を続けます。 BFS は距離の増加順にノードを処理するため、最初の m 個の有効な位置は、合計への寄与が最も小さいものに対応します。 
5. 最後に、選択した m 個の位置の記録された距離を合計して、答えを出します。 

### なぜ効果があるのか

 BFS は、重み付けされていないグラフ上のすべてのソース (ツリー) から最短パス ツリーを構築します。このツリーでは、各整数点が隣接する整数点に接続されます。 BFS では、最初にノードに到達するときは、ソースから可能な限り最短のパスを経由することが保証されるため、各ノードに割り当てられる距離は、まさにツリーまでの最小距離となります。 常に次に利用可能なノードを距離の増加順に選択するため、最初の m 個のノードを選択すると、貪欲交換引数によって距離の合計が最小化されます。選択したノードを後のノードに置き換えても、総コストが増加するだけです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import deque

def solve():
    n, m = map(int, input().split())
    xs = list(map(int, input().split()))

    visited = set(xs)
    q = deque()

    for x in xs:
        q.append((x, 0))

    ans_sum = 0
    ans = []

    while q and len(ans) < m:
        x, d = q.popleft()

        for nx in (x - 1, x + 1):
            if nx not in visited:
                visited.add(nx)
                q.append((nx, d + 1))
                ans.append(nx)
                ans_sum += d + 1
                if len(ans) == m:
                    break
        if len(ans) == m:
            break

    print(ans_sum)
    print(*ans)

if __name__ == "__main__":
    solve()
```このソリューションでは、すべてのツリーの場所からマルチソース BFS を構築します。 の`visited`set は、位置を再利用しないことを保証し、ツリーが有効な位置として選択されることをブロックします。 各 BFS 拡張では、その親より正確に 1 だけ大きい距離が割り当てられます。これは、最も近いツリーまでの距離に直接対応します。 

グラフは両方向に無限であるため、早期停止条件が重要です。 m 回の選択後に停止することなく、BFS は無期限に継続します。 最初の m 個の生成された位置が最適であることが保証されます。 

## 実用的な例

 ### 例 1

 入力:```
2 6
1 5
```距離 0 の 1 と 5 から BFS を開始します。 

| ステップ | キューポップ | 新しいポジションが追加されました | 追加された距離 | これまでに選ばれた |
 | --- | --- | --- | --- | --- |
 | 1 | 1 (0) | 0、2 | 1、1 | 0、2 |
 | 2 | 5 (0) | 4、6 | 1、1 | 0、2、4、6 |
 | 3 | 0 (1) | -1 | 2 | 0、2、4、6、-1 |

これは、BFS が両方のツリーから自然に対称的に拡張し、最初に最適な近くの位置をキャプチャしていることを示しています。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + m) | 各整数位置は最大 1 回訪問され、BFS は各エッジを 1 回処理します。 
| スペース | O(n + m) | キューおよび訪問セットは、生成された位置と初期ツリーのみを格納します。 

この制約では最大 2 × 10^5 要素が許可されるため、線形時間 BFS は十分に制限内に収まります。 ツリーセットを超えて最大 m 拡張までの訪問位置のみを保存するため、メモリの使用も安全です。 

## テストケース```python
import sys, io
from collections import deque

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque

    n, m = map(int, sys.stdin.readline().split())
    xs = list(map(int, sys.stdin.readline().split()))

    visited = set(xs)
    q = deque((x, 0) for x in xs)

    ans_sum = 0
    ans = []

    while q and len(ans) < m:
        x, d = q.popleft()
        for nx in (x - 1, x + 1):
            if nx not in visited:
                visited.add(nx)
                q.append((nx, d + 1))
                ans.append(nx)
                ans_sum += d + 1
                if len(ans) == m:
                    break
        if len(ans) == m:
            break

    return str(ans_sum) + "\n" + " ".join(map(str, ans))

# provided sample
assert run("2 6\n1 5\n") == "8\n-1 2 6 4 0 3"

# minimum case
assert run("1 1\n0\n") == "1\n-1" or run("1 1\n0\n") == "1\n1"

# symmetric expansion
assert run("1 4\n0\n") == "6\n-1 1 -2 2"

# two far trees
out = run("2 2\n-100 100\n")
assert "1\n" in out

# larger cluster sanity
assert len(run("3 5\n0 10 20\n").splitlines()[1].split()) == 5
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 1/0 | ±1コスト1 | シングルステップの正確さ |
 | 1 4 / 0 | 対称展開 | 残高とBFS注文 |
 | -100 100 | 2 か所 | 遠方の情報源からの独立性 |
 | 3本の木 | 5出力 | 一般的な妥当性 |

 ## 特殊なケース

 BFS は両方向に均等に拡張されるため、単一ツリーのケースはきれいに処理されます。 入力用`1 3 0`、アルゴリズムは 0 から始まり、最初にコスト 1 の -1 と 1 をそれぞれ生成し、次にコスト 2 の -2 または 2 を生成して、合計が最小になるようにします。 

木が隣接している場合など`0 1`、訪問済みセットは重複を防ぎます。 BFS フロンティアは両方のソースから外側に拡張しますが、内部ポイントは最初に到達したソースによって要求され、正しい最近接ツリー割り当てが維持されます。 

m が非常に大きい場合、BFS は偏りなく層ごとに外側に拡張し続けます。 すべての整数点は最終的に 1 回だけ到達するため、アルゴリズムは有効な候補を見逃すことはなく、常に距離の増加順序を尊重します。
