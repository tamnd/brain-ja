 ## 解決策
 ## 問題の理解

 ローマは正の整数のコレクションを持っており、10 進数が 4 と 7 だけで構成される数字に魅了されています。これらはラッキー ナンバーと呼ばれます。 課題は、彼のコレクションから最大で _k_ 個の幸運な数字が含まれる数字がいくつあるかを判断することです。 入力により、コレクションのサイズ _n_、幸運の数字の最大許容数 _k_、そして _n_ の数値自体が与えられます。 出力は単一の整数、つまり幸運の数字の制約を満たす数値の数です。 

制約は中程度です。_n_ と _k_ は両方とも最大 100、各数値は 10^9 までです。 これは、パフォーマンスを懸念することなく、各数値を個別に処理し、すべての桁を検査する余裕があることを意味します。 最悪の場合、最大 10 桁の 100 個の数値では約 1,000 回の演算が必要になるため、素朴な桁ごとの検査が可能です。 エッジケースには、幸運の数字がない数字、幸運の数字だけで構成される数字、または _k_ が最大の数字の桁数よりも大きい状況が含まれます。 たとえば、_n_ = 3、_k_ = 1 で数字が 4、7、47 の場合、47 には幸運の数字が 2 つあり、_k_ を超えるため、正しい出力は 2 になります。 不用意に実装すると、桁数を数え間違えたり、_k_ との比較を忘れたりして、間違った合計が得られる可能性があります。 

## アプローチ

 ブルートフォースアプローチは簡単です。 ローマの各数字を反復処理し、各数字について幸運な桁の数を数えます。 カウントが _k_ を超えない場合は、累計を増分します。 これが機能するのは、各番号の桁数が最大 10 桁であり、番号の数が最大 100 個であるため、およそ 1,000 桁の検査が行われることになります。 このアルゴリズムは、明示的に幸運の数字を数えてしきい値と比較するため、構造的には正しいです。 入力制限が小さいため、パフォーマンスは問題になりません。 

ブルートフォースアプローチはすでに制約を満たしているため、これより高速な漸近的な解決策は必要ありません。 可能な唯一の最適化はスタイルに関するものです。ループを使用する代わりに、数値を文字列に変換し、ジェネレータ式を使用して幸運の数字を 1 行で数えることができますが、基礎となるロジックは変わりません。 この問題は本質的に、アルゴリズムの複雑さではなく、慎重な反復とカウントに関するものです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * d) ここで、d は桁数 ≤ 10 | お(1) | 承認済み |
 | 最適 | O(n * d) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力から整数 _n_ と _k_ を読み取り、数値のリストを読み取ります。 
2. カウンタの初期化`result`ゼロに。 これは、幸運の数字の条件を満たす数字のカウントを保持します。 
3. リスト内の各数値を繰り返し処理します。 
4. 数値ごとに、ローカルカウンターを初期化します。`lucky_count`ゼロに。 
5. 現在の番号の各桁を調べます。 数字が 4 または 7 の場合はインクリメントします`lucky_count`。 
6. すべての桁を調べた後、比較します。`lucky_count`_k_へ。 もし`lucky_count`≤ _k_、増分`result`。 
7. すべての数値が処理された後、次の値を出力します。`result`。 

機能する理由: 各ステップで、数字ごとに幸運の数字を明示的に数え、それらが許可されたしきい値内にあるかどうかを確認します。 不変条件とは、`result`条件を満たすこれまでに処理された数の数を常に正確に反映します。 すべての桁が検査され、_k_ との比較が正確であるため、数値を数え間違えることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())
numbers = list(map(int, input().split()))
result = 0

for num in numbers:
    lucky_count = sum(1 for digit in str(num) if digit == '4' or digit == '7')
    if lucky_count <= k:
        result += 1

print(result)
```このソリューションは、次を使用して入力を効率的に読み取ります。`sys.stdin.readline`標準的な競技プログラミングの入力速度を処理します。 各数字は文字列に変換されるため、数字を個別に検査できます。 ジェネレータ式`sum(1 for digit in str(num) if digit == '4' or digit == '7')`幸運の数字を正確に数え、手動ループを回避します。 との比較`k`条件を満たす数値のみが最終結果に寄与するようにします。 整数を使用するとオーバーフローのリスクが回避され、数値のサイズが小さいためパフォーマンスのボトルネックが発生しません。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, k = map(int, input().split())
    numbers = list(map(int, input().split()))
    result = 0
    for num in numbers:
        lucky_count = sum(1 for digit in str(num) if digit == '4' or digit == '7')
        if lucky_count <= k:
            result += 1
    return str(result)

# provided samples
assert run("3 4\n1 2 4\n") == "3", "sample 1"
assert run("3 2\n447 4 77\n") == "2", "sample 2"

# custom cases
assert run("1 0\n4\n") == "0", "single number exceeds k"
assert run("1 1\n4\n") == "1", "single number equals k"
assert run("5 3\n4 7 44 77 447\n") == "4", "mixed small numbers"
assert run("3 10\n4444 7777 4747\n") == "3", "all numbers below high k"
```| テスト入力 | 期待される出力 | 検証内容 |

 | 1 1\n4 | 1 | 単一の数値が k | に等しい
 | 5 3\n4 7 44 77 447 | 4 | 小さな数が混合されており、一部は k を超えます。

 ## 特殊なケース

 _k_ を超える単一の数値の場合、次のようになります。`n=1, k=0, numbers=[4]`の場合、アルゴリズムは 1 つの幸運な数字を正しく数え、それを 0 と比較し、結果のインクリメントをスキップして、出力 0 を生成します。`n=100, k=100, numbers=[777777777]*100`, 各数字は 9 桁で、すべて幸運です。 各数値の合計は 9 (≤ 100) であるため、すべての数値がカウントされ、出力は 100 となります。アルゴリズムは、オフバイワン エラーを発生させることなく、ゼロ、境界、および最大入力を正しく処理します。
