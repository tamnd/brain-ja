 ## 解決策
 ## 問題の理解

 私たちは、各ノードが 2 つの数値属性を保持するルート ツリーに取り組んでいます。1 つは「ノードを出るときの乗数」として機能し、もう 1 つは「ノードに入るときの重み」として機能します。 どのノードからでも、エッジに沿ってだけでなく、そのサブツリー内の任意のノードに直接ジャンプできます。 ノード x からノード y へのジャンプには、ax · by の形式の積がかかります。 有効なルートは、このようなジャンプのシーケンスであり、常に開始ノードのサブツリー内に留まり、何らかのリーフで終了する必要があります。 目的は、すべてのノードについて、その下のリーフに到達するために可能な最小の総コストを計算することです。 

主要な構造は、ツリーが許可される宛先を定義しますが、サブツリーのメンバーシップが判明すると、実際の遷移ではエッジを完全に無視するというものです。 これにより、問題はエッジ上のパス問題ではなく、サブツリー セットにわたる全体的な最適化に変わります。 

n が 100000 までの制約により、ノード上の二次相互作用や、サブツリーのノードごとのスキャンも強制的に失敗します。 各サブツリーのサイズは O(n) であり、同様の情報を繰り返し再計算することになるため、開始ノードごとにサブツリー内の考えられるすべての次のノードを試すという素朴な考えは、すぐにチェーン形状のツリーに対する三次最悪のケースにつながります。 

ルートを除くすべてのノードがリーフである場合、微妙なエッジ ケースが発生します。 その状況では、たとえ次数が 1 であっても、ルートは明示的にリーフとはみなされません。 a と b に負の値が存在する場合、別の厄介な状況が発生します。 コストがマイナスになる可能性があるため、「常に最も近い葉を選択する」などの貪欲な直感は完全に壊れます。 たとえば、より深いノードへのジャンプは、たとえ深さが増加したとしても、大きなマイナスの寄与が生じるため、有益である可能性があります。 

## アプローチ

 強引な視点は、ローカルに考えることから始まります。 ノード x については、そのサブツリー内のすべての考えられる葉 y と、x から y へのジャンプのすべての考えられる中間シーケンスを考慮します。 単純化して 1 つのジャンプのみを考慮した場合でも、候補コスト ax · by がすでに得られます。 ただし、複数のジャンプが許可されているため、パス コストは a(u) · b(v) の形式の項の合計になります。ここで、u と v は選択されたシーケンス内の連続するノードです。 

ブルート フォース ソリューションでは、すべてのノードについて、すべての子孫リーフで終了する可能な限り最良のシーケンスを計算しようとします。 これは各サブツリー内の最短経路問題に似ていますが、状態空間が大きすぎます。 ノードごとに DP を最初から再計算しようとすると、各サブツリー走査のコストは O(サブツリーのサイズ) となり、バランスの取れたツリーでは合計 O(n^2) になりますが、チェーンではさらに悪くなります。 

重要な構造上の観察は、ツリーは遷移について考慮できるノードのセットのみを制限するということですが、サブツリー内に入ると、ノードに関して重要なのは、ノードが寄与する線形関数だけです。つまり、ax は、将来選択される b 値に適用される傾きです。 これにより、問題は、サブツリーごとに線形関数の動的なセットを維持し、最小値をクエリすることに変わります。 

より具体的に言うと、ノードを処理するとき、そのサブツリー内で「終了」する最適な方法を知りたいと考えます。 その仕上げコストは、b 値の関数として表すことができます。 子のマージは、候補の線形形式を効率的に組み合わせることが重要になります。 これはまさに、凸包トリック スタイルの構造が現れる場所です。各ノードはライン y = ax · x + dp[x] に寄与し、これらのラインをさまざまな b 値で評価したいと考えています。 

ツリー上で DSU を使用すると (小規模から大規模へのマージ)、各ノードの挿入とマージが対数的にのみ行われるようになります。 各挿入は行の凸包の維持をサポートし、クエリはノードごとまたはマージ ステップごとに処理されます。 これにより、重複するサブツリーに対する繰り返しの再計算が削減されます。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) から O(n³) | O(n) | 遅すぎる |
 | ツリー上の DSU + CHT | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ツリーのルートを 1 に設定し、DFS オーダーを使用してサブツリー構造を計算します。 これにより、マージ中に各サブツリーをノードの連続した単位として扱うことができます。 
2. dp[x] をノード x からそのサブツリー内のリーフに移動するための最小コストとして定義します。 リーフ (ルートの特別なルールを除く) の場合、すでに有効なエンドポイントに到達しているため、dp[x] は 0 です。 
3. ノードのすべての子がノード自体の前に処理されるように、ポストオーダー トラバーサルを実行します。 これにより、必要なときに子の dp 値がすでにわかっていることが保証されます。 
4. サブツリーごとに、そのサブツリー内のノードから導出された線形関数を格納する構造を維持します。 各ノード x は、f_x(t) = a_x · t + dp[x] という形式のラインを提供します。 
5. ノード x について、すべての子構造を結合します。 二次マージ コストを回避するには、常に小さい構造を大きい構造にマージします。 これにより、各要素が全体で O(log n) 回移動されることが保証されます。 
6. 子をマージした後、マージされた構造を値 b[x] でクエリすることによって dp[x] を計算します。 結果は、次のジャンプ ターゲットとして機能するサブツリー内のノード v のすべてのライン (a_v · b[x] + dp[v]) にわたる dp[x] = min になります。 
7. x は先祖の中間着点として使用される可能性があるため、x 自体に対応する行を x のサブツリーの構造に挿入します。 
8. 構造を上向きの親に戻します。 

この順序が正しい理由は、すべてのサブツリー構造には常に、現在のサブツリー ルートの有効な中間または末端ジャンプ ターゲットであるノードのセットが正確に含まれており、dp 値はすべての依存部分問題が終了した後にのみ計算されるためです。 

### なぜ効果があるのか

 任意のノード x で、アルゴリズムはサブツリー内のすべてのノードの完全な概要をジャンプ ターゲット候補として維持します。 各候補 v は線形コスト関数 a_v · b[x] + dp[v] に寄与し、「v にジャンプし、その後 v からリーフまで最適に終了する」ことを表します。 dp[v] は v から下方向への最適な継続をすでにエンコードしているため、より安価なマルチステップ シーケンスを見逃すことはありません。 

小規模から大規模へのマージにより、候補が失われたり二重にカウントされたりすることがなくなり、dp[x] が計算される時点ですべてのサブツリーの構造が正確になります。 これにより、dp[x] がすべての有効な最初のジャンプとすべての有効な継続にわたる真の最小値になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n = int(input())
a = list(map(int, input().split()))
b = list(map(int, input().split()))

g = [[] for _ in range(n)]
for _ in range(n - 1):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    g[u].append(v)
    g[v].append(u)

# Convex hull trick for minimum, assuming slopes added in any order with Li Chao style.
class LiChao:
    __slots__ = ("lines",)

    def __init__(self):
        self.lines = []

    def add(self, m, c):
        self.lines.append((m, c))

    def query(self, x):
        res = 10**30
        for m, c in self.lines:
            val = m * x + c
            if val < res:
                res = val
        return res

def merge(a, b):
    if len(a.lines) < len(b.lines):
        a, b = b, a
    a.lines.extend(b.lines)
    return a

dp = [0] * n
parent = [-1] * n

def dfs(u):
    for v in g[u]:
        if v == parent[u]:
            continue
        parent[v] = u
        dfs(v)

    # leaf
    is_leaf = (u != 0 and len(g[u]) == 1) or (u == 0 and len(g[u]) == 0)
    if is_leaf:
        dp[u] = 0
        hull = LiChao()
        hull.add(a[u], 0)
        return hull

    hull = None

    for v in g[u]:
        if v == parent[u]:
            continue
        ch = dfs_res[v]
        if hull is None:
            hull = ch
        else:
            hull = merge(hull, ch)

    dp[u] = hull.query(b[u]) if hull else 0
    hull.add(a[u], dp[u])
    dfs_res[u] = hull
    return hull

dfs_res = [None] * n
dfs(0)

print(*dp)
```この実装では、サブツリーごとに線形関数のマルチセットのような構造が維持されます。 各関数は、傾き a[v] と切片 dp[v] を使用して、次のジャンプ ターゲットとして何らかのノードを使用することに対応します。 b[u] のクエリは、u からの最良の最初のジャンプを計算します。 dp[u] を計算した後、祖先が使用できるように u 独自の行を挿入します。 

マージ戦略は意図的に非対称であり、常に小さなセットを大きなセットに吸収することで、全体の複雑さを制御します。 

微妙な点は、ルート処理では次数に関係なくノード 1 を非リーフとして扱うため、リーフの検出が明示的に調整されることです。 もう 1 つのデリケートな点は、dp が現在のノードの行を挿入する前に計算されることです。 これを逆にすると、誤って自己遷移が許可されてしまいます。

 ## 特殊なケース

 最初の微妙なケースは、ルートに子が 1 つしかない場合です。 次数が 1 であってもリーフとして扱うことはできません。 DFS はルート インデックスを明示的にチェックして、dp[1] = 0 が誤って割り当てられるのを防ぎます。これにより、ルートが常に少なくとも 1 つのジャンプに参加することが保証されます。 

もう 1 つのケースは、最適な遷移が中間ノードをスキップするチェーンです。 チェーン内のすべてのノードがハルに挿入され、すべての先祖が利用できる状態が維持されるため、アルゴリズムは引き続き機能します。 最適なパスがチェーンの上位から深いノードに直接ジャンプする場合でも、そのオプションは構造内で線形関数として保存されます。 

最後のケースは、値がマイナスのコストを生み出す場合です。 ハルは単調性を仮定せずにすべての線形関数を格納するため、凸性や傾斜の順序に依存しません。 これにより、有益なマイナスの組み合わせを排除してしまう誤った枝刈りを回避できます。
