 ## 解決策
 ## 問題の理解

 すべての位置が非常に特殊な循環方法で動作するように、1 から N までの数値の順列を構築するように求められます。 順列は決定論的なウォークを定義します。位置 i から開始して順列マッピングを繰り返し適用し、初めて i に戻るまでに何ステップかかるかを観察します。 各 i のステップ数は A または B のいずれかでなければなりません。 

グラフ用語では、順列は素の有向サイクルに分解されます。 各サイクルは独立しており、サイクル内のすべての要素は、そのサイクルが終了すると正確にそれ自体に戻ります。 したがって、値 g(i) は、i を含むサイクルの長さに他なりません。 このタスクは、サイクル長が A または B のみであるサイズ N の順列を構築することに帰着します。 

入力制約では N が 10^6 まで許可されるため、解は線形または線形に近いものでなければなりません。 O(N^2) の動作は最悪の場合、最大 10^12 の演算を意味するため、要素ごとに順列のチェックやマッピングのシミュレーションを行うと、すぐに遅くなりすぎます。 

A と B が等しい場合、またはそれらのいずれかが 1 の場合、微妙な失敗のケースが発生します。A = B の場合、問題はすべてのサイクルがその正確な長さを持つ順列を構築することに帰着します。これは、N が A で割り切れる場合にのみ可能です。A = 1 および B > 1 の場合、より長いサイクルを混合した多くの固定点を作成する必要がありますが、固定点はすでに長さ 1 のサイクルを消費しているため、残った要素の不一致によってすぐに実現可能性が損なわれます。 もう 1 つの脆弱な状況は、貪欲な分割が表面的には機能しているように見えても、A も B も互換性のある組み合わせで N を分割しない場合です。 

## アプローチ

 ブルートフォース手法では、集合 {1..N} をグループに分割し、各グループにサイクル長 A または B を割り当て、有効な順列が形成できるかどうかをテストします。 パーティションごとにサイクルを明示的に構築し、正確さを検証します。 N を A と B のサイズのグループに分割する方法の数は、N において指数関数的になります。これは、各ステップでいずれかのサイズを選択できるため、最悪の場合、およそ 2^(N / min(A, B)) の可能性が生じるからです。 中程度の N であっても、これは完全に不可能になります。 

重要な観察は、サイクル長が選択されると、順列構造によりほとんどすべての自由が失われるということです。 それぞれの有効な解決策は、使用する長さ A のサイクル数と長さ B のサイクル数を選択することにのみ対応します。 これらのカウントが固定されると、順列の構築は機械的に行われます。単に連続したブロックを割り当て、それらをサイクルに配線するだけです。 

これにより、問題は線形ディオファントス制約を解くことに帰着します。 

x * A + y * B = N、x と y は負ではない整数です。 有効なペア (x, y) が見つかると、構築は簡単になります。 

強引なアイデアは個々の要素のレベルで推論するため失敗しますが、正しいビューはサイクル分解のレベルにあります。 順列の構造により、問題は整数分割に分解されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | O(N) | 遅すぎる |
 | 最適 | O(N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

1. A と B が一貫した順序で処理されていることを確認します。 B が A より小さい場合は、それらを交換します。 これにより、有効性に影響を与えることなく、検索スペースが削減され、ディオファントスの解決ステップが簡素化されます。 
2. 長さ A のサイクル数を繰り返します。考えられる値 x ごとに、サイズ A の x サイクルを使用した後の残りの要素を計算します。これは、N - x * A です。残りは B で割り切れなければなりません。そうでない場合、この分割では有効なパーティションを生成できません。 
3. 余りが B で割り切れる場合、y = (N - x * A) / B を計算します。y が負でない場合、N のサイクルへの有効な分解が見つかりました。 
4. (x, y) が見つかったら、連続するブロックを繰り返し取得して順列を構築します。 サイズ A のブロックごとに、要素を有向サイクルで接続します。 サイズ B のブロックについても同じことを行います。 
5. ペア (x, y) が機能しない場合は、有効な順列が存在しないため、-1 を出力します。 

この構築ステップが機能するのは、サイクルを独立して形成できるためです。ブロック [i..i+k-1] 内で、各要素を次の要素にマッピングし、最後の要素を最初の要素にマッピングするだけです。 

### なぜ効果があるのか

 重要な不変条件は、すべての要素が正確に 1 つのサイクルに属し、そのサイクルの長さは、要素を割り当てるブロックのサイズによって完全に決定されるということです。 サイズ A または B のサイクルのみを作成するため、構造上、すべての g(i) は A または B のいずれかに等しくなります。 Diophantine ステップでは、すべての要素が 1 回だけ使用されることが保証されるため、割り当てられていない残りの要素は存在しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build(n, k, start):
    arr = list(range(start, start + k))
    for i in range(k - 1):
        arr[i], arr[i] = arr[i], arr[i]  # placeholder clarity
    for i in range(k - 1):
        p[arr[i] - 1] = arr[i + 1]
    p[arr[-1] - 1] = arr[0]
    return start + k

n, A, B = map(int, input().split())

if A > B:
    A, B = B, A

p = [0] * n

found = False
for x in range(n // A + 1):
    rem = n - x * A
    if rem >= 0 and rem % B == 0:
        y = rem // B
        found = True
        idx = 1
        for _ in range(x):
            arr = list(range(idx, idx + A))
            for i in range(A - 1):
                p[arr[i] - 1] = arr[i + 1]
            p[arr[A - 1] - 1] = arr[0]
            idx += A
        for _ in range(y):
            arr = list(range(idx, idx + B))
            for i in range(B - 1):
                p[arr[i] - 1] = arr[i + 1]
            p[arr[B - 1] - 1] = arr[0]
            idx += B
        break

if not found:
    print(-1)
else:
    print(*p)
```コードはまず、A が B より大きくならないように 2 つのサイクル サイズを正規化します。これにより、検索ループの反復数がわずかに減少します。 次に、A サイズのサイクルの有効な数を検索します。 有効な分割が見つかると、左から右へ貪欲にサイクルを構築します。 各サイクルは順列配列に直接書き込まれます。 

微妙な点は、インデックス付けは構築中に 1 から始まる形式で処理され、0 から始まる配列に書き込むときにのみ暗黙的に変換されることです。 これにより、サイクル配線におけるオフバイワンの間違いを回避できます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、A が 1 に等しい場合です。この場合、固定点を作成する必要があります。 いくつかの固定点を選択した後、B が残りの要素を分割しない場合、解は存在しません。 ディオファンティン チェックは無効な分割に対して直ちに失敗するため、アルゴリズムはこれを自然に処理します。 

もう 1 つのケースは、A が B に等しい場合です。その後、ループは N が A で割り切れるかどうかをチェックすることに戻ります。この構造により均一なサイクルが生成され、混合は必要ありません。 有効な分割が 1 つだけ存在するため、アルゴリズムは引き続き機能します。 

N が小さい場合、特に N = A または N = B では、解は単一サイクルに縮退します。 すべての要素をカバーする 1 つのブロックを作成するだけなので、構築ステップは引き続き機能します。
