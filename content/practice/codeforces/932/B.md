 ## 解決策

 ## 問題の理解

 正の整数に対して定義された関数が与えられています。この関数は、数字の積を取得し、1 つの数字が残るまで再帰的にそれを折りたたむことによって数値を繰り返し変換します。 その最後の数字を私たちはそう呼んでいます$g(x)$。 この値は、乗算デジタルルートとしてよく知られています。数字を乗算することで数字が減り、このプロセスは 1 桁の数字に達するまで続きます。 

各クエリは範囲を指定します$[l, r]$とターゲット桁$k$。 タスクは整数の数を数える事です$x$その間隔で満足する$g(x) = k$。 

この制約により、クエリごとのブルート フォースが不可能であることが明確になります。 範囲には最大 100 万の数値を含めることができ、最大 20 万のクエリを含めることができます。 すべてのクエリのすべての数値に対する数字と積のプロセスを直接シミュレーションするには、およそ次のものが必要になります。$2 \times 10^{11}$実行可能な制限時間をはるかに超えた最悪の場合の評価。 クエリごとに範囲全体を 1 回通過するだけでも、すでに大きすぎます。 

より微妙な問題は、その方法に現れます。$g(x)$振る舞います。 これは単純な算術関数ではないため、桁がわずかに変化すると結果が非線形に変化する可能性があります。 数字の合計やモジュロ パターンのように動作するという単純な仮定は、すぐに間違った答えにつながります。 たとえば、10、100、1000 などの数値は中間生成物ではすぐにゼロになるため、分布は非常に不均一で直感的ではありません。 

エッジ ケースは、ゼロまたは多数の小さな因数を含む数値から発生します。 たとえば、ゼロの桁を含む数値はすぐにゼロの桁積を生成します。つまり、最終値は常に 0 になります。もう 1 つの微妙なケースは、11 や 111 のような数値であり、この場合、積は再帰を通じて安定しています。 これらの不規則性により、前処理なしではクエリごとの推論が不可能になります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 クエリごとに、次のすべての整数を反復処理します。$l$に$r$、計算する$g(x)$残りの 1 桁になるまで数字を繰り返し乗算し、カウントが一致する$k$。 これは関数の定義に直接従うため、正しいです。 

ただし、数字の積を繰り返し計算するとコストがかかります。 コンピューティングしても$g(x)$これには約 10 ～ 20 回の操作が必要で、これを最長で$2 \times 10^5$最大範囲のサイズにわたるクエリ$10^6$不可能な数の操作が必要になります。 

重要な観察は、ドメインが小さく、固定されているということです。 すべての数字は 1 と 2 の間にあります$10^6$、事前計算できるようになります。$g(x)$すべての値に対して 1 回。 その後、各クエリは、サイズの静的配列に関する範囲カウントの問題に帰着します。$10^6$。 これにより、各桁の接頭辞の合計がすぐに示唆されます。$k$、インデックスまでの数を格納する周波数プレフィックス配列を構築します。$i$持っている$g(i) = k$。 次に、各クエリは減算によって一定時間内に応答されます。 

この関数は整数ごとに独立しており、クエリ構造に依存しないため、繰り返しの再計算から前処理への変換は機能します。

 | 最適 (事前計算 + プレフィックスの合計) |$O(N \log N + Q)$|$O(N)$| 承認済み |

 ## アルゴリズムのチュートリアル

 まず計算します$g(x)$あらゆる人にとって$x \le 10^6$。 

1. 各整数について$x$、その桁の積を計算します。 製品に複数の桁がある場合は、1 桁が残るまで製品に対してこのプロセスを繰り返します。 この最後の数字は次のように保存されます。$g(x)$。 事前計算を行う理由は、関数がクエリには依存せず、数値自体のみに依存するためです。 
2. プレフィックス頻度テーブルを作成します。 各桁ごとに$k$1 から 9 まで、prefix[k][i] が範囲内の数値の数を表す配列を維持します。$[1, i]$満足する$g(x) = k$。 これにより、繰り返されたカウントがプレフィックスの差に変換されます。 
3. クエリごとに$(l, r, k)$、prefix[k][r]からprefix[k][l - 1]を引いたものとして答えを計算します。 これが機能するのは、プレフィックス配列が連続した範囲にわたってカウントを蓄積するためです。 
4. 各クエリの結果を即座に出力します。 

重要な構造上の変更は、範囲にわたって繰り返される再計算を、すべての答えを累積形式でエンコードするグローバルな前処理ステップに置き換えることです。 

### なぜ効果があるのか

 正確さは 2 つの特性に依存します。 初め、$g(x)$によって完全に決定されます$x$のみなので、前処理によってクエリに必要な情報が失われることはありません。 第 2 に、すべての値が順番に 1 回だけ追加されるため、プレフィックス合計は間隔にわたって正確なカウントを保持します。 したがって、すべてのクエリは 2 つの正確なカウントの減算となり、すべての範囲の正確性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXN = 10**6

def digit_product(x):
    while x >= 10:
        prod = 1
        while x > 0:
            x, d = divmod(x, 10)
            prod *= d
        x = prod
    return x

g = [0] * (MAXN + 1)
for i in range(1, MAXN + 1):
    g[i] = digit_product(i)

prefix = [[0] * (MAXN + 1) for _ in range(10)]

for i in range(1, MAXN + 1):
    for k in range(1, 10):
        prefix[k][i] = prefix[k][i - 1]
    prefix[g[i]][i] += 1

q = int(input())
out = []
for _ in range(q):
    l, r, k = map(int, input().split())
    out.append(str(prefix[k][r] - prefix[k][l - 1]))

print("\n".join(out))
```前処理ステップでは次のように計算します。$g(x)$一度限りの値は最大 100 万です。 数字の積ループは、数値が 1 桁になるまで繰り返し縮小します。これは、問題の関数の定義とまったく同じです。 

プレフィックス テーブルは、単純な累積的な方法で構築されます。 各インデックスには、その時点までのすべての桁の頻度カウントが保存されます。 クエリの答えは、この事前計算された構造を直接減算したものになります。 

微妙な点はインデックスです。 プレフィックス配列は 1 から始まるため、次のように減算されます。$l - 1$場合でも有効です$l = 1$。 もう 1 つの重要な詳細は、数字 0 がクエリでは無視されることです。$k$1 ～ 9 の間であることが保証されます。

 ## 特殊なケース

 微妙なエッジ ケースは、ゼロを含む数値です。そのような数値は、桁の積の下ですぐにゼロに折りたたまれます。 アルゴリズムはこれを自然に処理します。$g(x)$0 を割り当て、プレフィックス配列は単純にカウントにそれを含めません。$k \in [1, 9]$。 

もう 1 つのケースは 1 桁の数字です。$g(x) = x$直接。 これらの値に対して前処理ループは直ちに終了し、特別な処理を行わなくても正確性が保証されます。 

最後に、次のような大きな連続範囲$[1, 10^6]$範囲サイズに関係なく、答えは 1 つのプレフィックスの差に帰着するため、効率的に処理されます。
