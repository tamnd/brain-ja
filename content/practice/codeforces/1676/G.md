 ## 解決策
 ## 問題の理解

 頂点 1 がルートであるルート付きツリーが与えられます。 すべての頂点は黒または白のいずれかに色付けされます。 どの頂点についても、そのサブツリーは頂点自体と、ルートまでのパス上にある頂点を含むすべてのノード、つまりルート構造内のすべての子孫で構成されます。 

タスクは、「バランスの取れた」サブツリーを持つ頂点の数を数えることであり、バランスがとれているとは、そのサブツリー内の黒い頂点の数が白い頂点の数と等しいことを意味します。 

したがって、問題は任意の接続されたサブセットに関するものではなく、厳密には各ノードによって定義されるルート化されたサブツリーに関するものです。 

各テスト ケースは親形式のツリーを提供するため、ルートを除くすべてのノードについて、その直接の親がわかります。 この構造は、有効なルート付きツリーであることが保証されています。 

制約は、テスト ケースごとに線形または線形に近い解決策を強く示唆する方法で構造化されています。 各テスト ケースには最大 4000 個のノードを含めることができますが、すべてのテスト ケース全体でノードの合計数は最大 200000 です。これにより、ツリー上の入れ子になったループ内でノードごとに負荷の高い作業を行うソリューションは除外されます。これは、テスト ケースごとに O(n²) であっても、すべてのテストを合計するとすでに遅すぎるためです。 

主要な構造上の制約は、各サブツリー計算を効率的に再利用する必要があるということです。 すべてのノードのサブツリー統計を最初から再計算するアプローチでは、作業が大幅に繰り返されます。 

素朴なアプローチは、各ノードについて、そのサブツリー全体を走査し、黒と白のノードを数えるというものです。 歪んだツリー (チェーン) では、ルート サブツリーのサイズは n、次のサブツリーのサイズは n−1 などとなり、テストごとに合計約 n²/2 の操作が生成されます。 これは、多くのテスト ケースで n = 4000 にはすでに大きすぎます。 

一般的に単純な推論を打ち破るエッジケースには、次のようなものがあります。 

鎖状の木のようなもの`1 - 2 - 3 - ... - n`。 ここで、すべてのサブツリーはチェーンのサフィックスであり、各サブツリーを個別に再計算すると二次関数の動作が生じます。 

ルート 1 が他のすべてのノードを子として持つ星型ツリー。 ここで、ルートを除く各サブツリーはサイズ 1 で、ルートはサイズ n です。 単純な解決策では、正確さは問題ありませんが、最初から再計算し、すべてのリーフを繰り返しチェックすることで時間を無駄にする可能性があります。 

単色のツリー (すべて B またはすべて W)。n = 0 でない限り、答えは常に 0 ですが、これは不可能です。 これにより、実装が誤って両方の色が存在すると想定していないかどうかがチェックされます。 

## アプローチ

 ブルート フォース手法では、各ノードが個別に処理されます。 固定ノード u の場合、DFS または BFS を使用してそのサブツリーを走査し、出現する B ノードと W ノードの数を数えます。 カウントが一致する場合、答えをインクリメントします。 これは正しいです。各サブツリーが明示的に列挙され、条件に対して評価されるからです。 

問題は、これにより作業が頻繁に繰り返されることです。 各ノードのサブツリーは、特にツリーの上位で他のノードと重複します。 チェーンの最悪のケースでは、サブツリーのサイズは n、n−1、n−2 などとなり、総作業量は n² に比例します。 複数のテスト ケースを使用すると、すぐに制限時間を超えてしまいます。 

重要な観察は、サブツリー構造がポストオーダートラバーサルに完全に適しているということです。 DFS を使用してノードごとにサブツリー情報を 1 回計算すると、親の結果を再利用できます。 サブツリー数を繰り返し再計算する代わりに、各ノードはその子からの結果を集約します。 

各ノードは色に応じて +1 または -1 のいずれかを寄与し、サブツリーの合計は、そのサブツリー内のすべてのノードにわたるこれらの寄与の合計になります。 この合計がゼロの場合、サブツリーは正確にバランスが取れています。 

したがって、問題は、サブツリーの合計を返す単一の DFS を計算し、合計がゼロになるノードの数をカウントすることに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 最悪の場合、テストごとに O(n²) | O(n) | 遅すぎる |
 | DFS サブツリー DP | テストあたり O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ツリーを隣接リストに変換し、ルートから開始して深さ優先検索を実行します。 

1. 親配列から隣接リストを構築します。 これにより、親ポインターに依存する代わりに、子を効率的に走査できるようになります。 

ツリーはルート化されていますが、エッジには方向がないため、DFS 中に親に戻らないようにする必要があります。 
2. 各ノードの値を定義します。白の場合は +1、黒の場合は -1 です。 これにより、問題はサブツリーの合計の計算に変換されます。 
3. DFS をルートから実行します。 各ノードについて、そのサブツリーの合計を独自の値で初期化します。 
4. すべての子を再帰し、返された各子のサブツリーの合計を現在のノードの合計に加算します。 

これにより、各ノードがサブツリー全体からの寄与を 1 回だけ蓄積することが保証されます。 
5. ノードのすべての子を処理した後、そのサブツリーの合計がゼロかどうかを確認します。 「はい」の場合、答えを増やします。 
6. サブツリーの合計を親に返し、上位レベルの計算に含めることができるようにします。 

### なぜ効果があるのか

 各ノードの DFS 呼び出しは、そのサブツリー内のすべての寄与の合計に等しい値を計算します。 再帰はすべての子が完全に処理された後にのみ返されるため、ノードが二重にカウントされたり欠落したりすることはありません。 すべてのエッジは再帰によって下方向に 1 回、上方向に 1 回トラバースされるため、各ノードの寄与は各祖先の計算に 1 回だけ含まれます。 ゼロサム条件は、黒と白のカウントが等しいことと正確に一致します。 

## Python ソリューション```python
import sys
sys.setrecursionlimit(10**7)
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        parent = list(map(int, input().split()))
        s = input().strip()

        g = [[] for _ in range(n + 1)]
        for i, p in enumerate(parent, start=2):
            g[p].append(i)
            g[i].append(p)

        color = [0] * (n + 1)
        for i in range(1, n + 1):
            color[i] = 1 if s[i - 1] == 'W' else -1

        ans = 0

        def dfs(u, p):
            nonlocal ans
            total = color[u]
            for v in g[u]:
                if v == p:
                    continue
                total += dfs(v, u)
            if total == 0:
                ans += 1
            return total

        dfs(1, -1)
        print(ans)

if __name__ == "__main__":
    solve()
```隣接リストの構築により、親ポインターのみが与えられているにもかかわらず、ツリーを自然にたどることができます。 DFS 関数は、各ノードのサブツリーの合計を返します。 重要な点は、無向表現での親ノードの再訪を避けるために親ノードを渡すことです。 

±1 へのカラーエンコードにより、個別のカウンターが回避され、問題がノードごとの 1 つの整数の累積に軽減されます。 答えはノードの子を完全に処理した後にのみ更新され、完全なサブツリーの合計を確実に評価します。
