 ## 解決策
 ## 問題の理解

 各単語が同じ長さの単語のコレクションが与えられます。 私たちの仕事は、2 つの単語を同一にするために必要な 1 文字の変更の最小数という観点から、それらがどれだけ「離れているか」を測定することです。 許可される各変更は、文字をアルファベット内の隣接する文字に移動することに制限されます。 たとえば、「c」を「f」に変えるには、「c」→「d」→「e」→「f」という 3 つの移動が必要です。 2 つの単語の差は、これらの文字ごとの移動数を合計することによって計算されます。 すべての単語のペアの中で、最小の違いを見つけたいと考えています。 

入力は複数のテスト ケースであり、それぞれが単語の数とその長さを提供し、その後に単語自体が続きます。 出力は、各テスト ケースの最小の差を表す整数です。 

制約を見ると、テスト ケースごとに最大 50 単語があり、各単語の長さは最大 8 文字です。 これは、すべての単語のペアを直接比較するソリューションを可能にするのに十分小さいです。これは、ペアの数が最大 50 × 49 / 2 = 1225 であり、2 つの単語の差の計算が最大 8 回の演算であるためです。 これにより、テスト ケースごとの合計作業量が 10,000 操作未満に抑えられ、制限時間内での管理が容易になります。 

明らかではないエッジ ケースには、すべての単語が同一である場合、差がゼロである必要がある場合、または文字がアルファベットの両端にある場合 (「a」や「z」など) が含まれ、文字あたりのコストが最大になります。 単純なアプローチで文字間の絶対的な違いが無視されたり、アルファベット内の文字の位置を考慮せずに文字の直接比較のみが使用されたりすると、不正確な結果が生じる可能性があります。 

## アプローチ

 最も単純なアプローチはブルートフォースです。 単語の各ペアについて、すべての位置を反復処理し、対応する文字間の絶対的な差を合計することにより、その差を計算します。 単語数が少なく、最大長も小さいため、この強引な方法は実行可能です。 差の定義が各キャラクターにローカルであり、位置間で独立しており、すべてのペアを比較することで確実に最小値を見つけることができるため、総当り攻撃が機能します。 

この場合、制約が非常に厳しいため、これ以上の最適化は必要ありません。 文字ごとの絶対的な違いを計算する以外に悪用できる隠された構造やパターンはありません。 たとえば、単語を事前計算したり並べ替えたりしようとすると、単純なアプローチではすでにテスト ケースあたり 10,000 回未満の操作しか実行されないため、最悪の場合の実行時間は改善されずに複雑さが増すことになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²・m) | お(1) | 承認済み |
 | 最適 | O(n²・m) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取ります。 出力が別々であるため、各テスト ケースを個別に処理します。 
2. 各テストケースについて、単語数を読み取ります。`n`そして単語の長さ`m`を読んでから、`n`単語をリストに追加します。 
3. これまでに見つかった最小の違いを追跡するために変数を初期化します。 最初は大きな数値に設定します。たとえば、`float('inf')`。 
4. すべての単語のペアを反復処理します。`(i, j)`と`i < j`。 各ペアについて、累計を初期化します。`diff`ゼロに。 
5. 文字位置ごとに`k`0から`m-1`、その位置にある 2 つの単語間のアルファベットの位置の絶対的な差を計算します。 この値を追加します`diff`。 
6. 計算された場合`diff`現在の最小差よりも小さい場合は、最小差を更新します。 
7. すべてのペアをチェックした後、現在のテスト ケースの最小の差を出力します。 

機能する理由: このアルゴリズムは、考えられるすべての単語のペアを徹底的に考慮し、問題のルールに従って文字ごとの違いを合計します。 文字間の絶対的な差により、必要な手の数が正確にカウントされ、すべてのペアをチェックすることで最小値が見つかることが保証されます。 スキップされたショートカットはないため、結果は正しいと考えられます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        words = [input().strip() for _ in range(n)]
        min_diff = float('inf')
        for i in range(n):
            for j in range(i + 1, n):
                diff = 0
                for k in range(m):
                    diff += abs(ord(words[i][k]) - ord(words[j][k]))
                if diff < min_diff:
                    min_diff = diff
        print(min_diff)

if __name__ == "__main__":
    solve()
```コードは入力を効率的に読み取ります。`sys.stdin.readline`そして単語から改行を取り除きます。 単語インデックスに対するネストされたループはブルート フォース ペア チェックを実装し、文字に対する内側のループは ASCII コードを使用して移動コストを計算します。 使用する`ord`「a」から「z」までが整数の位置に正しくマップされるようにします。 の`min_diff`変数は最小の差を追跡し、より小さな差が見つかるたびに更新されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n²・m) | n 個の 2 つのペアが選択され、文字の違いを計算するにはそれぞれ m 回の操作が必要です。 |
 | スペース | O(n・m) | 長さ m の n ワードを格納するには、入力サイズに線形スペースが必要です。 |

 n ≤ 50 および m ≤ 8 の場合、テスト ケースあたりの最大約 50²·8 = 20,000 操作は、2 秒の制限時間内に簡単に収まり、メモリ使用量は 256 MB の制限に比べて無視できます。

 ## 特殊なケース

 すべての単語が同じ場合、次のように`["abc","abc"]`、アルゴリズムはゼロ差分を正しく計算します。 「a」や「z」など、文字が両端にある場合、`abs(ord(...))`計算では手数が正確にカウントされます (この場合は 25)。 考えられるペアが 1 つしかない場合、ループは引き続きその 1 つのペアを処理するため、アルゴリズムは失敗しません。 これらの例では、ソリューションがすべての微妙なケースを正しく処理していることを確認しています。
