[CF 1676E - クエリを食べる](https://codeforces.com/problemset/problem/1676/E)

 **評価:** 1100
 **タグ:** 二分探索、貪欲、ソート
 **解決時間:** 1 分 25 秒
 **確認済み:** はい

 ## 解決策
 ## 問題の理解

 複数の独立したシナリオが与えられ、それぞれが一定量の砂糖を含むキャンディーのコレクションを説明します。 すべてのクエリについて、ティムールが摂取する砂糖の総量が少なくとも目標値に達するように、ティムールが食べなければならないキャンディーの最小数を決定したいと考えています。 彼は各クエリに対してキャンディーのサブセットを自由に選択できますが、クエリ内で各キャンディーを使用できるのは最大 1 回だけです。 

重要な観察は、キャンディーを食べる順序が固定されていないため、どのようなターゲットに対しても、効果的に可能な限り最適なサブセットを選択していることです。 必要な合計に達しながらキャンディーの数を最小限に抑えるための最良の戦略は、常に最大の値を最初に取得することです。 

制約が十分に大きいため、クエリごとに最適なサブセットを再計算しようとするソリューションは失敗します。 合計で最大 150,000 個のキャンディーと 150,000 個のクエリがあるため、O(nq) アプローチは直ちに不可能になります。 クエリあたり O(n log n) のソリューションであっても、遅すぎます。 これにより、各クエリが対数時間または定数時間で応答できるようにする前処理戦略が推進されます。 

すべてのキャンディーの合計がクエリ値よりも小さい場合、微妙なエッジ ケースが発生します。 この状況では、どのキャンディーを選択しても要件を満たすことができないため、答えは -1 でなければなりません。 もう 1 つの特殊なケースは、1 つのキャンディーがすでに目標を超えている場合で、答えは 1 であるはずです。 

## アプローチ

 ブルートフォース手法では、キャンディーの組み合わせをテストすることで、すべてのサブセット サイズを暗黙的に試行します。 配列をソートし、クエリごとに合計が目標に達するまでキャンディーを最大から最小まで貪欲に選択することを想像することもできます。 これは正しいですが、しきい値に達する前に多くの要素をスキャンする必要がある可能性があるため、最悪の場合でもクエリごとに O(n) のコストがかかります。 最大 150,000 のクエリでは、約 2.25 × 10^10 の操作が必要となり、これは実行可能な制限をはるかに超えています。 

重要な構造的洞察は、キャンディーが降順にソートされると、あらゆるクエリに対する最適な戦略は常に、このソートされた配列のプレフィックスになるということです。 これにより、各クエリがプレフィックス合計のしきい値問題に変換されます。 プレフィックスの合計を事前計算すると、各クエリはプレフィックスの合計が目標に達するかそれを超える最小のインデックスを見つけることになります。 これは二分探索を使用すると効率的に実行できます。 

そこで問題は次のようになります。並べ替えた後、各位置に可能な限り最良の k 個のキャンディーの合計糖分を格納する配列を構築します。 各クエリは、この累積合計が十分である最初の位置を検索します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとのブルート フォース 貪欲 | O(nq) | お(1) | 遅すぎる |
 | ソート + プレフィックス合計 + 二分検索 | O(n log n + q log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. キャンディーを降順に並べ替えます。 これにより、最初の k 個のキャンディーを摂取するたびに、常にその k の総糖分が最大化されることが保証されます。 他の注文では、同じ数のキャンディーの合計が減るだけです。 
2. ソートされたリストに対してプレフィックス合計配列を構築します。 各接頭辞の値は、正確に k 個のキャンディーを使用して達成できる最大の砂糖を表します。 
3. 各クエリ値 x について、まず x がすべてのキャンディーの合計より大きいかどうかを確認します。 そうであれば、どの選択も要件を満たすことができないため、答えは -1 になります。 
4. それ以外の場合は、プレフィックス合計配列に対して二分検索を実行して、prefix[k] ≥ x となる最小のインデックス k を見つけます。 このインデックスは、必要なキャンディーの最小数を表します。 
5. そのクエリに対して k を出力します。 

### なぜ効果があるのか

正確さは、並べ替えによって導入される単調性の特性に依存します。 降順に並べ替えた後、プレフィックスの合計は減少しないシーケンスを形成し、k 個のキャンディーを選択しても、最初の k 個のキャンディーの合計を超えることはできません。 これは、任意の固定 k に対して可能な最良の結果がプレフィックスによって一意に決定されることを意味します。 実現可能性は k において単調であるため、二分探索では、有効な構成を見逃すことなく条件を満たす最小の k が見つかります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, q = map(int, input().split())
        a = list(map(int, input().split()))
        
        a.sort(reverse=True)
        
        pref = [0] * (n + 1)
        for i in range(n):
            pref[i + 1] = pref[i] + a[i]
        
        total = pref[n]
        
        for _ in range(q):
            x = int(input())
            if x > total:
                print(-1)
                continue
            
            lo, hi = 1, n
            ans = n
            while lo <= hi:
                mid = (lo + hi) // 2
                if pref[mid] >= x:
                    ans = mid
                    hi = mid - 1
                else:
                    lo = mid + 1
            
            print(ans)

if __name__ == "__main__":
    solve()
```この解決策は、最も価値のある選択肢が最初に来るように、キャンディーを降順に並べ替えることから始まります。 次に、プレフィックス合計配列が構築され、任意のプレフィックス合計を定数時間で計算できるようになります。 

各クエリは独立して処理されます。 不必要な検索を避けるために、最初にターゲットと合計値を比較します。 次に、二分探索がプレフィックスの合計に対して実行され、その単調構造を利用して、必要な合計に到達する最初の位置が特定されます。 

よくある落とし穴は、降順で並べ替えることを忘れることです。 これがないと、プレフィックスの合計は最適な選択を表さず、バイナリ検索は誤った結果を返します。 もう 1 つの微妙な問題は、プレフィックス配列のインデックス付けが 1 つずつずれていることです。これが、サイズ n+1 で構築される理由です。 

## 実用的な例

 ### トレース例 1

 入力:```
n = 5
a = [1, 3, 2, 5, 4]
queries = [3, 10]
```並べ替え後:```
[5, 4, 3, 2, 1]
```プレフィックスの合計:

 | k | 接頭辞[k] |
 | --- | --- |
 | 1 | 5 |
 | 2 | 9 |
 | 3 | 12 |
 | 4 | 14 |
 | 5 | 15 |

 クエリ 1: x = 3

 prefix[k] ≥ 3 → k = 1 で最小の k を検索します。 

クエリ 2: x = 10

 prefix[3] = 12 ≥ 10 → k = 3 がわかります。 

これは、貪欲な順序付けにより、小さな k であっても大きなターゲットをどのように満たすことができるかを示しています。 

### トレース例 2

 入力:```
n = 4
a = [2, 2, 2, 2]
queries = [1, 9]
```ソートされた配列は残ります:```
[2, 2, 2, 2]
```プレフィックスの合計:

 | k | 接頭辞[k] |
 | --- | --- |
 | 1 | 2 |
 | 2 | 4 |
 | 3 | 6 |
 | 4 | 8 |

 クエリ 1: x = 1 → k = 1

 クエリ 2: x = 9 → 不可能、答え = -1

 これは、総和を使用したグローバルな実現可能性チェックの正しさを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n + q log n) | テストケースごとにソートが優先され、各クエリは二分検索を使用します。 
| スペース | O(n) | プレフィックス合計配列ストレージ |

 すべてのテスト ケースにわたる n と q の合計が 1.5 × 10^5 で制限されるとすると、この規模では並べ替えと二分探索の両方が効率的であるため、この複雑さは時間制限内に問題なく収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n, q = map(int, input().split())
        a = list(map(int, input().split()))
        a.sort(reverse=True)
        pref = [0]
        for v in a:
            pref.append(pref[-1] + v)
        total = pref[-1]
        for _ in range(q):
            x = int(input())
            if x > total:
                out.append("-1")
                continue
            lo, hi = 1, n
            ans = n
            while lo <= hi:
                mid = (lo + hi) // 2
                if pref[mid] >= x:
                    ans = mid
                    hi = mid - 1
                else:
                    lo = mid + 1
            out.append(str(ans))
    return "\n".join(out)

 ## 特殊なケース

 ターゲットがすべてのキャンディーの合計を超える場合、アルゴリズムは検索せずにすぐに -1 を返します。 たとえば、キャンディー [2, 2, 2] の場合、合計は 6 であるため、7 を求めるクエリは不可能です。 プレフィックスサムチェックは、これを一定時間で検出します。 

単一のキャンディーで十分な場合、プレフィックス配列により、バイナリ検索で 1 が返されることが保証されます。たとえば、[10, 1, 1] の場合、クエリ 5 は最初の要素によってすぐに満たされ、検索ではより大きな k 値が誤って考慮されません。 

すべてのキャンディーが同一の場合、プレフィックスは直線的に増加し、二分探索では引き続きしきい値が正しく検出されます。 [3, 3, 3, 3] の場合、最初の 2 つの要素のみがターゲットに到達し、プレフィックス合計の単調構造と一致するため、6 のクエリは 2 を返します。
