 ## 解決策
 # 問題の理解

 Diane には、出場者 ID の順列で表される出場者の列があります。 彼女は、公正なコイントスを使用して、残っている左端または右端の出場者を繰り返し除去します。 元の行の隣接する位置が 2 つだけ残った時点で、プロセスは停止します。 タスクは、残りの 2 つの ID の予想される XOR を計算し、次の値を乗算することです。$2^{N-2}$モジュロ$10^9+7$。 

の乗算$2^{N-2}$が重要な詳細です。 まさにあります$N-2$除去、および左右の除去のすべての可能なシーケンスには確率があります。$1 / 2^{N-2}$。 分数を扱う代わりに、各最終ペアに至る消去シーケンスの数を数えて、スケーリングされた期待値を直接計算できます。 

制約により許可されるのは、$N$二次解は受け入れられますが、ランダムなプロセスをシミュレートしたり、すべての可能な間隔で確率を維持したりするアプローチは、不必要に高価になります。 あるのは$N-1$したがって、目標は、それらを列挙することなく、それらの重みを発見することです。$2^{N-2}$可能な削除シーケンス。 

最初のエッジケースは可能な限り最小の行です。 入力あり:```
2
2 1
```消去法はありません。 唯一の可能なペアはすでに行全体であるため、出力は次のようになります。```
3
```少なくとも 1 つの削除が存在しない遷移にアクセスすることを常に想定するソリューションです。 

もう 1 つの特殊なケースは、エンド近くにある出場者のペアです。 例えば：```
4
3 1 2 4
```最終的なペアは次のとおりです。`(3,1)`、`(1,2)`、 または`(2,4)`残りの出場者は元の列で隣接していなければならないためです。 不注意なアプローチでは、次のような隣接しないペアに確率を割り当てる可能性があります。`(3,2)`端から脱落する構造を考慮するのではなく、どの出場者が生き残るかだけを考慮することによって。 

## アプローチ

 直接的な総当たりアプローチは、考えられるコイン投げのあらゆるシーケンスをシミュレートすることです。 あるので$N-2$消去法、あります$2^{N-2}$可能なシーケンス。 すべてのシーケンスについて、残りの 2 人の出場者を決定し、その XOR を答えに加算し、シーケンスの数で割ることができます。 すべてのシーケンスの確率は同じですが、シーケンスの数は指数関数的に増加するため、これは正しいです。 で$N=2000$、可能性の数を書き出すことさえ不可能です。 

有益な観察は、残りの出場者の形状を観察することで得られます。 両端のみを削除するということは、残りのセグメントは常に元の行の連続したセグメントであることを意味します。 競技者が 2 人だけ残っている場合、それらの 2 つのポジションは元の順列で隣接している必要があります。 

ポジションでのペアを検討します$i$そして$i+1$。 このペアを離れるには、すべての出場者が順位の前に$i$左側と、ポジション以降のすべての競技者から削除する必要があります$i+1$右側から取り外す必要があります。 がある$i-1$左の削除と$N-i-1$適切な除去を任意の順序で組み合わせます。 有効な削除シーケンスの数は次のとおりです。$$\binom{N-2}{i-1}$$可能な削除シーケンスの合計数は次のとおりです。$$2^{N-2}$$必要な答えは期待値に次の値を乗算したものであるため、$2^{N-2}$、分母が消えます。 必要なのは、隣接する各 XOR に二項係数を乗算して加算することだけです。 

ブルートフォース手法は、すべてのランダムな結果を個別にカウントするため機能しますが、結果が指数関数的に多いため失敗します。 隣接する元の位置のみが生き残ることができるという観察により、問題は単純な加重和に帰着します。$N-1$ペア。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(2^N)$|$O(N)$| 遅すぎる |
 | 最適 |$O(N)$|$O(N)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 順列を読み取り、考えられる最終的なペアに必要な二項係数を計算します。 

ペアの係数$i, i+1$は$\binom{N-2}{i-1}$。 これらすべての値のモジュロが必要です$10^9+7$。 パスカルの三角形の最初の行はそれらを生成するのに十分であるため、必要なシーケンスを繰り返し構築できます。 

1. 隣接するすべての出場者のペアを繰り返します。 

隣接した位置のみが一緒に残ることができるため、答えへのすべての寄与は次のとおりです。`c[i] XOR c[i+1]`。 

1. 各 XOR 値に、そのペアを生成する除去シーケンスの数を乗算し、それを答えに加算します。 

係数は、最終的なペアを生成するコイン投げシーケンスの数を正確にカウントします。 要求された出力はすでにスケールされているため、$2^{N-2}$、分割は必要ありません。 

1. 累積値のモジュロを出力します。$10^9+7$。 

XOR の値は小さいですが、係数と累積された答えは大きくなる可能性があるため、モジュラー演算が全体に適用されます。 

これが機能する理由: 任意の数の削除の後、残りの出場者は常に元の順列の 1 つの連続した間隔を形成します。 プロセスが停止すると、その間隔の長さは 2 になるため、答えは次のいずれかから得られる必要があります。$N-1$隣接するペア。 固定された隣接ペアの場合、唯一の要件は、その外側のすべての出場者がそれぞれの側から除外されることです。 これらの削除の順序は任意であり、正確に$\binom{N-2}{i-1}$有効なシーケンス。 これらのカウントは、考えられるすべての消去シーケンスを分割するため、加重合計により、期待される XOR を乗算した値が得られます。$2^{N-2}$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10 ** 9 + 7

def solve():
    n = int(input())
    c = list(map(int, input().split()))

    if n == 2:
        print(c[0] ^ c[1])
        return

    coeff = [1]
    for _ in range(n - 2):
        nxt = [1]
        for i in range(len(coeff) - 1):
            nxt.append((coeff[i] + coeff[i + 1]) % MOD)
        nxt.append(1)
        coeff = nxt

    ans = 0
    for i in range(n - 1):
        ans = (ans + coeff[i] * (c[i] ^ c[i + 1])) % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```特別な場合`n == 2`不要な Pascal 行の作成を回避し、唯一の可能な XOR 値を直接返します。 また、一般式には二項係数の 0 番目の行が必要となるため、混乱も避けられます。 

の`coeff`配列にはパスカルの三角形の 1 行が格納されます。 構築した後、$N-2$レベル、`coeff[i]`等しい$\binom{N-2}{i}$、これはまさにインデックスから始まるペアに必要な乗数です。`i`。 

最後のループは隣接するゼロベースの位置を使用します。`i`そして`i + 1`。 最初のペアは必要があるため、係数インデックスは一致します。$\binom{N-2}{0}$、2番目のペアには次のものが必要です$\binom{N-2}{1}$、 等々。 すべての加算と乗算の後にモジュロを維持すると、整数の制限が小さい言語でのオーバーフローが回避され、Python の整数が制限されます。

 このプロセスにはランダムな選択肢がないため、考えられる唯一の結果は 2 人の出場者の XOR です。

def run(inp: str) -> str:

 ## 特殊なケース

 最小の入力の場合:```
2
2 1
```アルゴリズムは直ちに特殊なケースに入ります。 除去はないので、重量 1 で生き残るペアのみです。 出力は`2 XOR 1 = 3`。 

最初の 2 人の出場者などのエンド ペアの場合:```
4
3 1 2 4
```最初のペアでは、右側の両方の出場者が削除される必要があります。 これらの除去の可能な順序は 1 つだけであるため、その係数は次のとおりです。$\binom{2}{0}=1$。 アルゴリズムにより、可能な限り最小の重みが与えられます。 

中央のペアの場合:```
4
3 1 2 4
```ペア`(1,2)`出場者が左側と右側から 1 人ずつ排除されても生き残ることができます。 2 つの削除はどちらの順序でも発生し、係数が与えられます。$\binom{2}{1}=2$。 アルゴリズムは、中央のパスカル係数を使用してこれを取得します。 

同等の出場者の場合:```
5
7 7 7 7 7
```隣接するすべての XOR はゼロです。 アルゴリズムは引き続きすべての重みを計算しますが、寄与はすべてゼロであるため、特別な処理を必要とせずに正しい結果が得られます。
