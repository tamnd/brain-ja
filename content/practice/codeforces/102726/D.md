 ## 解決策
 # 問題の理解

 この問題は、ビデオ通話中の人々の列をモデル化しています。 全員が振り向いた後、各人はキャラクターによって表されます。`L`彼らが左を向いていたら、`R`彼らが右を向いていたら。 クランプとは、同じ方向を向いている最大の連続した人々のグループです。 タスクは、最後の行にそのようなグループがいくつ存在するかを数えることです。 

たとえば、次の行`R L L R`3 つの塊が含まれています。`R`、真ん中`LL`、そして最後`R`。 

入力には、人の数とその指示が順に含まれています。 出力は、セグメント内のすべての文字が同一である、このシーケンス内の連続セグメントの数です。 

この制約により、最大 100,000 人が許可されます。 つまり、ソリューションは線形時間で機能する必要があります。 多数のポジションのペアを繰り返し比較したり、考えられるすべてのセグメントを試行したりするアルゴリズムは、簡単に約 10^10 の演算に達する可能性がありますが、これは一般的なコンテストの制限時間内で可能な値をはるかに超えています。 すべての人が回答に影響を与える必要があるのは 1 回だけであるため、行を 1 回スキャンするだけで十分です。 

主なエッジ ケースは、クランプ間の遷移から生じます。 1 人だけが含まれる行でも 1 つの塊を作成する必要があります。 入力の場合:```
1
L
```正しい出力は次のとおりです。```
1
```隣接する人々の間の変化のみをカウントするソリューションでは、遷移がないためゼロが返されますが、最初の塊はカウントされる必要があります。 

もう 1 つのよくある間違いは、隣接する等しい方向が同じ束に属していることを忘れていることです。 のために：```
4
L
L
L
L
```正しい出力は次のとおりです。```
1
```列全体が 1 つの塊になります。 発生するたびにカウントする`L`または`R`別々に実行すると、誤って 4 つが生成されてしまいます。 

最後の境界ケースは、隣接するすべてのペアが異なる場合です。```
4
L
R
L
R
```正しい出力は次のとおりです。```
4
```すべての人が新しい塊を始めるので、答えは人の数です。 

## アプローチ

 ブルートフォース手法では、考えられるすべての連続グループを調べて、それが塊であるかどうかを判断します。 考えられるセグメントは O(N^2) あり、セグメントのチェックには O(N) かかるため、合計作業量は O(N^3) に達する可能性があります。 各セグメントの隣接する位置のみをチェックするわずかに改善されたブルート フォースでも、依然として O(N^2) 範囲が考慮されますが、N が 100,000 に達すると速度が遅すぎます。 

重要な観察は、方向が変わる位置で凝集塊が正確に分離されていることです。 セグメント全体の内容を知る必要はありません。 現在の人が以前のグループを継続するか、新しいグループを開始するかを知る必要があるだけです。 

行には常に少なくとも 1 つの塊が含まれます。 最初の人には 1 つの塊から始めて、その人が直前の人と異なる方向を向くたびに答えを増やします。 これにより、問題は 1 回の左から右へのスキャンに減ります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N^2) 以上 | お(1) | 遅すぎる |
 | 最適 | O(N) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての人の指示を元の順序で読みます。 
2. 最初の人は常に塊に属するため、答えを 1 に初期化します。 
3. 2人目以降の行をスキャンします。 現在の方向が前の方向と異なる場合は常に、塊の数を増やします。 方向の変更は、新しい塊を作成できる唯一のイベントです。 
4. 最終的なカウントを出力します。 

なぜ効果があるのか:

 スキャン中の現在の回答は、これまでに処理された人々の最大グループの数を正確に表します。 最初の人が最初のグループを作成します。 後の各人は、方向が一致した場合は前のグループに参加するか、方向が変わった場合は新しいグループを開始します。 塊間の考えられるすべての境界が 1 回だけチェックされるため、最終的なカウントは正確です。 

## Python ソリューション```python
import sys

input = sys.stdin.readline

def solve():
    n = int(input())
    prev = input().strip()
    
    ans = 1

    for _ in range(n - 1):
        cur = input().strip()
        if cur != prev:
            ans += 1
        prev = cur

    print(ans)

if __name__ == "__main__":
    solve()
```このコードは、行全体を保存するのではなく、前の方向のみを保持します。 新しい塊は隣接する 2 人の人物を比較することによってのみ作成できるため、これで十分です。 

変数`ans`入力には少なくとも 1 人の人物が含まれることが保証されているため、1 から始まります。 ループは 2 人目から始まり、方向が変わるたびに答えが増えます。 

使用する`strip()`各入力行から改行文字を削除します。 このコードは、指示を読み取ったときに処理することで、不必要なメモリ使用を回避します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N) | 各人は 1 回ずつ処理されます。 |
 | スペース | お(1) | 前回の方向と現在のカウントのみが保存されます。 |

 線形ソリューションは、入力文字ごとに一定量の作業を実行するため、100,000 人を簡単に処理できます。 

## テストケース```python
import sys
import io

def solve():
    import sys
    input = sys.stdin.readline

    n = int(input())
    prev = input().strip()
    ans = 1

    for _ in range(n - 1):
        cur = input().strip()
        if cur != prev:
            ans += 1
        prev = cur

    print(ans)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout
    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    output = sys.stdout.getvalue()

    sys.stdin = old_stdin
    sys.stdout = old_stdout
    return output

assert run("4\nR\nL\nL\nR\n") == "3\n", "sample 1"
assert run("1\nL\n") == "1\n", "single person"
assert run("5\nL\nL\nL\nL\nL\n") == "1\n", "all equal values"
assert run("4\nL\nR\nL\nR\n") == "4\n", "alternating directions"
assert run("6\nR\nR\nL\nL\nR\nR\n") == "3\n", "multiple boundaries"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1 L`|`1`| 最小サイズと初期数の処理 |
 |`L L L L L`|`1`| すべての値は等しい |
 |`L R L R`|`4`| すべての人は新しい塊を作ります |
 |`R R L L R R`|`3`| いくつかの遷移の正しい処理 |
