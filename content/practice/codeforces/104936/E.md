 ## 解決策
 ## 問題の理解

 一連の数値が与えられ、少なくとも 2 つの長さの連続するすべてのセグメントを調べます。 このようなセグメントについては、その中の個別のインデックスのすべてのペアを考慮し、それらのビットごとの XOR を計算します。 セグメントの「スコア」は、それらすべてのペアの中で最も小さい XOR 値です。 

このタスクは、指定された値 K とまったく同じスコアを持つセグメントがいくつあるかを数えるというものです。 

スコアについて考えると便利な方法は、スコアが XOR メトリックの下でセグメント内の最も近いペアのみに依存するということです。 1 つのペアでも小さな XOR がある場合、そのペアがスコアを支配します。最小値が固定されると、他のすべては無関係になるためです。 

この制約により、おおよそ O(N log N) または O(N log² N) の解決策が求められます。 N は最大 100000 なので、最悪の場合でも部分配列が約 10¹⁰ あるため、セグメント上の二次関数は直ちに不可能になります。 セグメントごとにすべてのペアごとの XOR 値を維持することすら不可能です。 

微妙な点は、セグメントの延長に関して単純に楽譜が単調になっていないことです。 セグメントを拡張すると、新しい非常に小さな XOR ペアが導入され、スコアが大幅に低下する可能性があります。 これは、単一の統計の単調性に依存する単純なスライディング ウィンドウのアイデアを打ち破ります。 

これを明らかにする小さなエッジケースは、次のような配列です。`[8, 1, 9]`。 セグメント`[8, 9]`には XOR 1 がありますが、`[8, 1, 9]`XOR 値を持つペアがあります`8 XOR 1 = 9`、`1 XOR 9 = 8`、`8 XOR 9 = 1`したがって、スコアは 1 のままです。要素を追加しても、構造化された方法で最小ペア XOR が増加または維持されるとは限りません。そのため、単純なプレフィックス プロパティに依存するのではなく、ペアの相互作用を明示的に制御する必要があります。 

## アプローチ

 ブルート フォース ソリューションでは、すべてのサブ配列を考慮し、その中のすべてのペアごとの XOR を計算し、最小値を取得します。 長さ L の固定セグメントの場合、すべてのペアの計算コストは​​ O(L²) ですが、セグメントが O(N²) あり、最悪の解釈では O(N⁴)、部分的な作業を再利用した場合はよくても O(N³) になります。 いずれにせよ、それは実現可能な限界をはるかに超えています。 

重要な観察は、実際にはすべてのペアごとの XOR 値を気にするのではなく、最小値がしきい値を下回るか、等しいか、上回るかだけを気にするということです。 これは、最小値の明示的な計算ではなく、ペアに対する制約の観点から問題を再構成することを示唆しています。 

しきい値 T を固定し、その中の要素のすべてのペアが少なくとも T の XOR を持つ場合にセグメントが有効であるとみなします。そのようなセグメントでは、スコアは少なくとも T です。これにより、元の問題が、グローバルなペアごとの制約を満たすセグメントをカウントする問題に変換されます。 特定の T についてこれらのセグメントを数えることができたら、差を使用して K について正確な等しい値を回復できます。 

正確にスコアが K のセグメントとは、スコアが K 以上であるが、K+1 以上ではないセグメントです。 

したがって、問題は、XOR(x, y) < T という形式の条件に違反するペアがないスライディング ウィンドウを維持することに帰着します。 

残りの課題は、新しい要素が違反ペアを作成するかどうかを維持する方法です。 これは、値の挿入と、指定された x に対する x と現在構造内にある任意の要素の間の最小 XOR のクエリをサポートするバイナリ トライ内で現在のウィンドウを維持することによって処理されます。 このクエリは、x が不正なペアを形成しているかどうかを直接示します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N3) から O(N4) | お(1) | 遅すぎる |
 | スライディング ウィンドウ + バイナリ トライ | O(N log 23⁰) | O(N log 23⁰) | 承認済み |

 ## アルゴリズムのチュートリアル

 要素のすべてのペアが少なくとも T で XOR を持つ部分配列をカウントするヘルパー関数 f(T) を定義します。 

1. スライディング ウィンドウ [l, r] と、現在ウィンドウ内にあるすべての要素を格納するバイナリ トライを維持します。 このトライは、挿入、削除、および値の最小 XOR パートナーのクエリをサポートします。 この構造は、アクティブなセグメントを正確に表します。 
2. r を左から右に展開し、トライに a[r] を挿入します。 挿入後、現在のウィンドウがしきい値 T に関して有効であるかどうかを確認します。 
3. 有効性をチェックするために、トライを使用して a[r] とウィンドウ内の前の要素の間の最小 XOR を計算します。 この最小値が T より小さい場合、新しい要素はウィンドウ内に禁止されたペアを作成します。 
4. ウィンドウが無効な間、トライから a[l] を削除し、l をインクリメントすることで、左から縮小します。 1 つの要素を削除すると、唯一の違反ペアが削除されたり、同じ新しい要素が関与する別のペアが明らかになったりする可能性があるため、削除するたびに有効性条件を再計算します。 
5. ウィンドウが再び有効になると、r で終わり l から r までのすべての部分配列がしきい値 T に対して有効になり、(r - l + 1) が f(T) に寄与します。 
6. f(K) と f(K+1) を計算します。 XOR 値は整数であり、最小ペア XOR が正確に K であるセグメントが分離されるため、答えは f(K) - f(K+1) です。 

重要な不変条件は、各ステップでウィンドウ [l, r] に T 未満の XOR のペアが含まれておらず、これが r で終わる最小のウィンドウであることです。 トライにより、最新の要素によって導入された違反を効率的に検出できます。また、すべての禁止されたペアにはウィンドウ内の何らかの要素が含まれている必要があり、要素を削除するとペアが単調に削除されるため、左から縮小すると最終的に有効性が回復します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class TrieNode:
    __slots__ = ("child", "cnt")
    def __init__(self):
        self.child = [None, None]
        self.cnt = 0

class BinaryTrie:
    def __init__(self):
        self.root = TrieNode()
        self.B = 30

    def insert(self, x):
        node = self.root
        node.cnt += 1
        for b in reversed(range(self.B)):
            bit = (x >> b) & 1
            if not node.child[bit]:
                node.child[bit] = TrieNode()
            node = node.child[bit]
            node.cnt += 1

    def remove(self, x):
        node = self.root
        node.cnt -= 1
        for b in reversed(range(self.B)):
            bit = (x >> b) & 1
            node = node.child[bit]
            node.cnt -= 1

    def min_xor(self, x):
        node = self.root
        res = 0
        for b in reversed(range(self.B)):
            bit = (x >> b) & 1
            # prefer same bit to minimize xor
            if node.child[bit] and node.child[bit].cnt > 0:
                node = node.child[bit]
            else:
                res |= (1 << b)
                node = node.child[bit ^ 1]
        return res

def count_at_least(T, arr):
    n = len(arr)
    trie = BinaryTrie()
    l = 0
    ans = 0

    for r in range(n):
        x = arr[r]
        trie.insert(x)

        while l <= r:
            if trie.min_xor(x) >= T:
                break
            trie.remove(arr[l])
            l += 1

        ans += (r - l + 1)

    return ans

def main():
    N, K = map(int, input().split())
    a = list(map(int, input().split()))

    def f(T):
        return count_at_least(T, a)

    print(f(K) - f(K + 1))

if __name__ == "__main__":
    main()
```トライはコアコンポーネントです。 それぞれの挿入と削除は 30 ビットのパスをたどってカウントを維持するため、サブツリーがまだアクティブであるかどうかを安全に判断できます。 の`min_xor`関数は、最初に一致するビットを貪欲に追跡します。これはまさに、固定要素に対する最小の XOR パートナーを生成するものです。 

スライディング ウィンドウは、どのペアもしきい値に違反しないという条件によって完全に駆動されます。 左から縮小するループにより、違反が存在する場合は必ず、寄与をカウントする前に削除されます。

    import sys

        def __init__(self):
            self.child = [None, None]
            self.cnt = 0

    class BinaryTrie:
        def __init__(self):
            self.root = TrieNode()
            self.B = 30

        def insert(self, x):
            node = self.root
            node.cnt += 1
            for b in reversed(range(self.B)):
                bit = (x >> b) & 1
                if not node.child[bit]:
                    node.child[bit] = TrieNode()
                node = node.child[bit]
                node.cnt += 1

        def remove(self, x):
            node = self.root
            node.cnt -= 1
            for b in reversed(range(self.B)):
                bit = (x >> b) & 1
                node = node.child[bit]
                node.cnt -= 1

        def min_xor(self, x):
            node = self.root
            res = 0
            for b in reversed(range(self.B)):
                bit = (x >> b) & 1
                if node.child[bit] and node.child[bit].cnt > 0:
                    node = node.child[bit]
                else:
                    res |= (1 << b)
                    node = node.child[bit ^ 1]
            return res

    def count_at_least(T, arr):
        trie = BinaryTrie()
        l = 0
        ans = 0
        for r, x in enumerate(arr):
            trie.insert(x)
            while l <= r and trie.min_xor(x) < T:
                trie.remove(arr[l])
                l += 1
            ans += (r - l + 1)
        return ans

    def solve(inp):
        N, K = map(int, inp.split()[0:2])
        a = list(map(int, inp.split()[2:]))
        return str(count_at_least(K, a) - count_at_least(K + 1, a))

 ## 特殊なケース

 すべての要素が同一である場合、まれなケースが発生します。 入力用`[7, 7, 7, 7]`K = 0 の場合、すべてのペアの XOR は 0 であるため、長さが 2 以上のすべての部分配列のスコアは 0 になります。アルゴリズムはウィンドウを常に有効に保ちます。`min_xor`は常に 0 を返し、f(0) はすべての部分配列をカウントします。 

もう 1 つの状況は、次のように値がバイナリ空間で大きく分離されている場合です。`[1, 2, 4, 8]`。 多くの XOR 値は大きいため、小さい T に対する違反は決して発生しません。 ウィンドウは決して縮小せず、寄与分は完全な三角形カウントとして蓄積され、スライディング ウィンドウが正しく生成します。 

よりデリケートなケースは、単一の低値要素が遅れて出現する場合です。たとえば、`[8, 8, 8, 1]`。 要素`1`前の要素と多数の小さな XOR ペアを作成し、繰り返し縮小を強制します。 削除するたびにトライ カウントが一貫して減少し、競合する要素がすべて削除されるとウィンドウが再び安定し、カウントが再開されるため、アルゴリズムがこれを処理します。
