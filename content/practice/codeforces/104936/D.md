 ## 解決策
 ## 問題の理解

 各ノードが建物で、各エッジが 2 つの建物間のトンネルであるグラフが与えられています。 すべてのトンネルには 2 つの値が関連付けられています。1 つはトンネルに入るのに必要なコインでのコスト、もう 1 つはトンネルを通過した後に受け取れるコインでの報酬です。 それぞれの通過には方向性がなく、トンネルを使用するたびに、私たちは再びそのコストを支払い、その報酬を受け取ります。 

初期数のコインを持った建物 1 から開始し、建物 N に到達したいと考えています。問題は、コイン残高がゼロを下回ることなく N に到達できる一連のトンネル通過が存在するように、コインの最小開始量を決定することです。 

重要な問題は、エッジの重み付けが 1 回だけではないことです。 エッジを何度も再利用でき、トンネルがコストよりも多くのコインを生み出した場合、循環可能な追加の資金源のように効果的に機能します。 

制約は大きく、最大 100,000 の建物と 200,000 のトンネルです。 これにより、パスごとのコイン残高のシミュレーションやパスの列挙に依存するソリューションは即座に除外されます。 単純な方法でさまざまなコイン量を使用してノードごとの状態を追跡するアプローチは、組み合わせ論的に爆発します。 線形または線形に近い時間、通常は O(M log N) または O(M) が必要です。 

いくつかの微妙な失敗例は自然に発生します。 

1 つの問題は、正または負の純利得サイクルです。 たとえば、サイクル全体でコインが増加する場合、一度エントリーできれば、任意の大きな資金を生成できます。 反復的な走査を無視した単純な最短パスでは、この効果を完全に見逃してしまいます。 

もう 1 つの問題は、接続性の観点からパスが存在する場合でも、初期のエッジでは、後のエッジが補うとしても、一時的に利用可能なものよりも多くの先行資本が必要になる可能性があるため、少額の初期コインでパスを通過することが不可能な場合があることです。 

最後に、「最小コストのエッジ パス」という貪欲な選択が失敗するケースもあります。これは、早期により高価なエッジを選択することで、必要な開始資本全体を削減する収益性のサイクルが解放される可能性があるためです。 

## アプローチ

 強引なアイデアは、これを各状態 (ノード、現在のコイン) が存在する状態グラフとして扱うことです。 各状態からすべての送信トンネルを試し、コストを差し引いて報酬を追加することでコイン残高を更新します。 目標は、非マイナスのコインでノード N に到達することであり、これを可能にする最小の開始コインが必要です。 

ただし、コインの価値には制限がないため、状態の数は事実上無限です。 人為的に上限を設けたとしても、遷移によってコインが増加する可能性があるため、有用な限界が有限であることを保証することはできません。 これにより、拡張状態に対する BFS またはダイクストラは実行不可能になります。 

重要な観察は、重要なのは、旅中の絶対的なコインの量ではなく、選択したパスに沿った実現可能性を確保するために必要な最小限の初期資本であるということです。 固定パスの場合、プレフィックス制約をシミュレートすることで必要な開始コインを計算できます。すべてのステップで、決してマイナスにならないようにする必要があります。 必要な初期値は、パスに沿って発生する最大不足値です。 

これにより、問題は、各エッジが「コスト調整」効果を持つ最短経路問題に変換されます。 潜在的な変換を定義すると、エッジの動作を標準的な緩和に減らすことができます。つまり、現在のコインを追跡する代わりに、各ノードに到達するために必要な最小の初期コインを追跡します。 コスト c と報酬 r でエッジ u から v をトラバースするとき、要件 x で u に到達すると、エッジをトラバースした後、v での要件は max(0, x + c − r) になりますが、これはその時点で c に余裕がある場合に限ります。これは累積された余剰に依存します。

これを考えるためのより堅牢な方法は、答えを二分探索して実現可能性をチェックすることです。 候補開始値 S について、現在のコイン残高を常に維持し、使用可能なエッジを貪欲に取得することによって N に到達できるかどうかをシミュレートします。 Nまで到達できればSも実現可能です。 

実現可能性を効率的にするために、現在のバランス ≥ コストの場合にのみトラバースが許可される緩和としてエッジを扱います。 現在最高のコイン余剰を維持しながら、到達可能な状態を繰り返し伝播します。 これはダイクストラのようなプロセスとなり、「距離」はコストの最小化ではなく、現在のコイン余剰の最大化になります。 

私たちは視点を逆転させます。開始コインを直接最小化する代わりに、与えられた開始額が十分であるかどうかを尋ね、二分探索を使用して最適化します。 各チェックでは、常に現在のコイン残高が最も高いノードを展開する修正された最良優先検索が実行され、最も有望な状態を最初に探索することが保証されます。 

これにより、単調な実現可能性条件が得られ、S に対する二分探索が可能になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース状態の拡張 | O(無限) | O(N · コイン) | 遅すぎる |
 | 二分探索 + 最良優先の実現可能性 | O(M log M log V) | O(N + M) | 承認済み |

 ## アルゴリズムのチュートリアル

 最小初期コイン S を二分探索します。 

各候補 S について、S コインから始めてノード N に到達できるかどうかをテストします。 

各ノードで現在のコイン残高によって順序付けされた優先キューを維持し、常に利用可能な最も高いコインを最初に持つ状態を拡張します。 

また、ノード v に到達したときにこれまでに達成した最大のコイン残高を格納する配列 best[v] も維持します。これにより、より弱い状態が再び訪れるのを防ぎます。 

best[1] = S を初期化し、(S, 1) を優先キューにプッシュします。 

そして、コイン残高が最も多い状態を繰り返し抽出します。 

現在のコイン x を持つノード u から、各トンネル (u、v、c、r) を試します。 x < c の場合、それを横断してスキップすることはできません。 

x ≥ c の場合、走査後、x − c + r コインで v に到達します。 この値が best[v] より大きい場合、best[v] を更新し、新しい状態をプッシュします。 

キューが空になるか、ノード N に到達するまで続行します。 

best[N] が定義されている場合、S は実行可能です。 

### なぜ効果があるのか

 開始値 S が固定されている場合、アルゴリズムは常に、利用可能なコインの降順で状態を探索します。 エッジの実現可能性は少なくともコスト c が存在するかどうかに依存するため、コインの少ない状態では、将来のオプションはより少ないか同等しか生成できません。 したがって、より高いコイン残高を持つノードに到達すると、同じノードへのすべての弱いアクセスが優先されます。 最良の配列では、支配的な状態のみを維持することが保証され、指数関数的な爆発を避けながら正確性が維持されます。 

有効なトラバーサルではコイン残高がマイナスになることはなく、すべての遷移で実現可能性の制約が維持されるため、S の下で到達可能な構成はすべてこのプロセスによって検出されます。 したがって、実現可能性チェックは正確であり、二分探索は最小 S を正確に見つけます。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def can(start, n, g):
    best = [-1] * (n + 1)
    pq = [(-start, 1)]
    best[1] = start

    while pq:
        neg_x, u = heapq.heappop(pq)
        x = -neg_x

        if x < best[u]:
            continue

        if u == n:
            return True

        for v, c, r in g[u]:
            if x < c:
                continue
            nx = x - c + r
            if nx > best[v]:
                best[v] = nx
                heapq.heappush(pq, (-nx, v))

    return False

def solve():
    n, m = map(int, input().split())
    g = [[] for _ in range(n + 1)]
    for _ in range(m):
        a, b, c, r = map(int, input().split())
        g[a].append((b, c, r))
        g[b].append((a, c, r))

    lo, hi = 0, 10**18
    ans = hi

    while lo <= hi:
        mid = (lo + hi) // 2
        if can(mid, n, g):
            ans = mid
            hi = mid - 1
        else:
            lo = mid + 1

    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションは、各トンネルとそのコストと報酬を格納する無向隣接リストを構築します。 実現可能性チェック関数は、コインの状態に対して最良優先の伝播を実行し、常に最もリッチな到達可能な状態を最初に拡張します。 

二分探索ではこのチェックがラップされ、指定された初期コイン量が十分であるかどうかに基づいて回答空間が縮小されます。 重要な実装の詳細は、最大ヒープ (負の値で実装) を使用して、より大きなコイン残高を優先することです。 

微妙な点は、支配力チェック best[v] です。 これがないと、検索ではより悪いコイン価値を持つ同じノードが繰り返し再訪され、TLE が発生します。

 ## 特殊なケース

 直接的な例外ケースは、すべてのエッジのコストと報酬がゼロの場合です。 キューはコイン 0 から開始され、すべての走査が常に許可されるため、アルゴリズムは S = 0 ですぐに成功します。 

もう 1 つの微妙なケースは、コインを増やすサイクルが存在するが、N への直接パス上にない場合です。最良優先伝播により、そのサイクルが到達可能になると、それが利用されてコイン残高が増加し、以前は使用できなかったエッジのロックが解除される可能性があります。 貪欲な最短経路の解釈ではこれを見逃してしまいますが、状態支配メカニズムにより完全に捕捉されます。 

最後のケースは、唯一の有効なルートで一時的にコインを「失う」必要があるが、後でコインを回復する必要がある場合です。 実行可能性チェックでは、現在の状態がエッジ コストを下回らない限り、一時的な減少が正しく許可されます。これは、各状態が独自のコイン残高で独立して評価され、遷移によって実行可能性がローカルに強制されるためです。
