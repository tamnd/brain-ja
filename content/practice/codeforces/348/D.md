 ## 解決策
 ## 問題の理解

 サイズ _n_ × _m_ の長方形グリッドが与えられます。各セルはフリーまたはブロックされています。 2 匹のタートルが左上隅のセル (1,1) から開始し、どちらも右下隅のセル (_n_,_m_) に到達しようとしています。 カメは各ステップで下または右にしか移動できず、ブロックされたセルを通過することはできません。 タートルには制限があります。タートルのパスは、開始セルと終了セルを除くどのセルでも交差してはなりません。 タスクは、10^9 + 7 を法とするこのような非交差パスのペアの数を数えることです。 

この制約は、グリッドが 3000 x 3000 までの大きさになる可能性があることを示しています。すべてのパスを明示的に列挙しようとするソリューションは、パスの数が _n_ と _m_ とともに指数関数的に増加するため、絶望的に遅くなります。 このため、総当たりではなく動的計画法や組み合わせ計数という観点から考える必要があります。 

微妙なエッジ ケースには、フリー セルの狭い通路に沿って 1 つのパスが強制的に沿って移動するシナリオが含まれます。 たとえば、中央の行が 1 つの列を除いてブロックされている場合、タートルの相対位置を追跡しない単純なアプローチでは、交差するパスを過剰にカウントする可能性があります。 もう 1 つのエッジ ケースは、障害物の周囲でパスが「側を交換」する必要がある場合に発生します。 アルゴリズムは、交差するパスのカウントを慎重に回避する必要があります。 

## アプローチ

 ブルートフォースアプローチは、各タートルに対して (1,1) から (n,m) までの可能なパスをすべて生成し、どのペアが交差していないかをチェックすることです。 10x10 グリッドの場合でも、パスの数はタートルごとに数千のオーダーであり、数百万のペアになります。 n=m=3000 の場合、これは天文学的に大きくなります。 このアプローチは原理的には正しいですが、計算的には実行不可能です。 

重要な洞察は、各パスが一連の右方向と下方向の動きで構成されているという観察から得られます。 タートルが各セルに到達する方法の数を追跡すると、開始点から各セルまでのパスの数と、各セルから終了点までのパスの数を個別に事前計算できます。 これらのカウントを使用すると、包含-除外を利用できます。つまり、順序付けされていないパスのペアの総数は、パスの総数の 2 乗から、開始点または終了点以外のセルで交差するペアを引いたものになります。 この問題を、特定の中間セルで交差するパスをカウントすることに帰着させます。これは、DP テーブルを使用して実行できます。 

最適なソリューションでは、動的プログラミングを使用して 4 つのテーブルを計算します。 させて`dp_start[x][y]`(1,1) から (x,y) までのパスの数、および`dp_end[x][y]`(x,y) から (n,m) までのパスの数になります。 この場合、(x,y) で交差するパスのペアの数は次のようになります。`dp_start[x][y]^2 * dp_end[x][y]^2`。 開始と終了を除くすべてのセルについてこれを合計し、二乗パスの合計から減算すると答えが得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^{n*m}) | O(2^{n*m}) | 遅すぎる |
 | 最適なDP | O(n*m) | O(n*m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 2 つの DP テーブルを初期化する`dp_start`そして`dp_end`サイズ n x m のゼロで埋められたもの。`dp_start[x][y]`(1,1) から (x,y) までのパスをカウントします。`dp_end[x][y]`(x,y) から (n,m) までのパスをカウントします。 これにより、到達可能なすべての位置が効率的にキャプチャされます。 
2.セット`dp_start[0][0] = 1`そして`dp_end[n-1][m-1] = 1`なぜなら、開始セルと終了セルには常にそれ自体への自明なパスが 1 つあるからです。 
3. 埋める`dp_start`繰り返して。 空きセル (x、y) ごとに、上に隣接するセルが存在し、空いている場合はそのセルからのパスを追加し、存在し、空いている場合は左の隣接セルからパスを追加します。 これにより、最初から各セルに到達する方法の合計数が計算されます。 
4. 埋める`dp_end`逆に繰り返します。 空きセル (x、y) ごとに、下に隣接するセルが存在し、空いている場合はそのセルからのパスを追加し、セルが存在し、空いている場合は右の隣接セルからパスを追加します。 これにより、各セルから終点に到達する方法の数が計算されます。 
5. 開始から終了までのパスの総数を計算します。`total_paths = dp_start[n-1][m-1]`。 
6.初期化`intersect_sum = 0`。 開始と終了を除く各中間セル (x,y) に空きがある場合は、次の値を追加します。`(dp_start[x][y] * dp_end[x][y])^2`モジュロ 10^9+7 から`intersect_sum`。 これにより、そのセルで交差するすべてのペアがカウントされます。 
7. 減算`intersect_sum`から`total_paths^2`10^9+7 を法として、交差しないパスのペアの数を取得します。 
8. 結果を出力します。 

機能する理由: DP カウントを 2 乗することで、順序付けされていないパスのペアをすべて列挙し、各中間セルで交差するパスの数を正確にカウントします。 これらを二乗パスの合計から差し引くと、問題の要件に一致する、開始点と終了点のみで一致するペアのみが残ります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

n, m = map(int, input().split())
grid = [input().strip() for _ in range(n)]

dp_start = [[0] * m for _ in range(n)]
dp_end = [[0] * m for _ in range(n)]

dp_start[0][0] = 1
for i in range(n):
    for j in range(m):
        if grid[i][j] == '#':
            dp_start[i][j] = 0
            continue
        if i > 0:
            dp_start[i][j] = (dp_start[i][j] + dp_start[i-1][j]) % MOD
        if j > 0:
            dp_start[i][j] = (dp_start[i][j] + dp_start[i][j-1]) % MOD

dp_end[n-1][m-1] = 1
for i in reversed(range(n)):
    for j in reversed(range(m)):
        if grid[i][j] == '#':
            dp_end[i][j] = 0
            continue
        if i + 1 < n:
            dp_end[i][j] = (dp_end[i][j] + dp_end[i+1][j]) % MOD
        if j + 1 < m:
            dp_end[i][j] = (dp_end[i][j] + dp_end[i][j+1]) % MOD

total_paths = dp_start[n-1][m-1]
intersect_sum = 0
for i in range(n):
    for j in range(m):
        if (i == 0 and j == 0) or (i == n-1 and j == m-1) or grid[i][j] == '#':
            continue
        intersect_sum = (intersect_sum + dp_start[i][j] * dp_end[i][j] % MOD * dp_start[i][j] % MOD * dp_end[i][j] % MOD) % MOD

answer = (total_paths * total_paths - intersect_sum + MOD) % MOD
print(answer)
```このソリューションは、順方向パス数と逆方向パス数の DP テーブルを初期化します。 境界チェックにより、境界外へのアクセスが防止されます。 交差合計では、オーバーフローを避けるために慎重にモジュラー演算が使用されます。 減算ステップでは、負の結果を避けるためにモジュロを取得する前に MOD を追加します。
