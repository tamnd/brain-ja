 ## 解決策
 ## 問題の理解

 私たちは、繰り返しゲームをプレイする友人のグループを与えられました。 ゲームの各ラウンドでは、スーパーバイザーとして機能するのは 1 人だけであり、残りは$n-1$人々はプレイヤーとして参加します。 

人それぞれに$i$、プレーヤーとして何ラウンド参加したいかを伝えられます。 スーパーバイザーになるたびにその人は 1 ラウンドから除外されるため、ラウンドの合計数によって各人が何回プレイできるかが決まります。 

総ラウンド数が$R$、次に人$i$まさにの選手になります$R - x_i$ラウンド、どこで$x_i$監督者として選ばれた回数です。 各ラウンドにはスーパーバイザーが 1 人だけ存在するため、すべてのラウンドの合計は$x_i$等しい$R$。 

タスクは、可能な最小限のものを決定することです$R$ラウンド全体にスーパーバイザーを割り当てて、すべての人が少なくとも必要な回数だけプレイできるようにします。 

制約により、私たちはより早く解決策に向かうことができます。$O(n^2)$。 と$n$まで$10^5$および最大値$10^9$、ラウンドをシミュレートしたり、あらゆる可能性を試したりするような構築は不可能です。 問題を単純な数値チェックまたは単調な条件に対する最適化に削減する定式化が必要です。 

すべての要求が非常に大きいがバランスが取れている場合、または、ある人がほぼすべてを要求しているのに他の人はほとんど要求していない場合、微妙なエッジ ケースが発生します。 たとえば、すべてが$a_i = 1$の場合、各人は 1 人を除いて 1 回スーパーバイザーになれるため、2 ラウンドで十分であり、最後の制約は自然に満たされます。 このような場合、監督のバランスを無視した素朴な考えでは、誤って過大評価または過小評価してしまう可能性があります。 

もう 1 つの注意が必要な状況は、1 つの値が支配的な場合です。 例えば、$a = [10^9, 1, 1, \dots]$。 要件を単純に合計したり平均したりする単純な推論は失敗します。監視能力は不均等に分布しているものの、ラウンドごとに制限されているためです。 

## アプローチ

 強引なアイデアは、次の値を増やしてみることです。$R$そして実現可能性をチェックします。 固定の場合$R$を割り当てることができるかどうかを決定する必要があります。$R$スーパーバイザ スロット$n$あの人みたいな人$i$最大でも除外されます$R - a_i$ラウンドします。 同様に、彼らは最大でもスーパーバイザーである必要があります$R - a_i$回。 

特定の条件の実現可能性を確認するには$R$、容量を計算します$c_i = R - a_i$。 もしあれば$c_i < 0$、 それ$R$不可能です。 それ以外の場合は、スーパーバイザ スロットの総数を確保する必要があります。$R$容量を超えずに割り当てることができます。 重要な条件は次のようになります$\sum \min(c_i, R)\ge R$しかし、より単純な観察も存在します。各ラウンドには 1 人のスーパーバイザーが必要であるため、複数のスーパーバイザーを分散する必要があります。$R$上限がある人々の間で同じタスクを行う$c_i$。 

これは標準的な実現可能性チェックになります。容量の合計は少なくとも次のとおりである必要があります。$R$。 それは与える$\sum (R - a_i) \ge R$これは、閉じた形式の条件に直接単純化されます。 

ブルートフォースオーバー$R$費用がかかるだろう$O(n \cdot \max a_i)$、これは大きすぎます$a_i$まで$10^9$。 

重要な観察は、実現可能性が単調であるということです。$R$。 多少なら$R$作品、それより大きいもの$R$ラウンドを増やすだけで監視能力が向上するため、これも機能します。 これは、二分探索ができることを意味しますが、代数では探索がまったく必要ないことがわかります。 

以下から開始します:$$\sum (R - a_i) \ge R$$拡張します:$$nR - \sum a_i \ge R$$

$$(n-1)R \ge \sum a_i$$それで：$$R \ge \frac{\sum a_i}{n-1}$$したがって、答えは最小の整数になります$R$この不等式を満たすこと。

 | R に対するブルート フォース |$O(n \cdot \max a_i)$|$O(1)$| 遅すぎる |
 | 代数的還元 |$O(n)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 合計を計算する$S = \sum a_i$。 これは、すべてのプレイヤーが集合的に参加を主張した合計回数を捕捉します。 
2. 各ラウンドが「必要な参加ギャップ」の合計を正確に減少させることを観察します。$n-1$, 毎回1人が除外されるため。 これにより、スケジューリングの問題が線形のリソース バランスに変換されます。 
3. 条件を導出する$(n-1)R \ge S$、つまり、「作成されたプレイヤー スロット」の合計が、必要な参加をすべてカバーする必要があることを意味します。 
4. 最小の整数を計算する$R$天井分割を使用してこの不等式を満たします。 
5. この値を最小ラウンド数として出力します。 

### なぜ効果があるのか

 各ラウンドは正確に貢献します$n-1$1 人を除く全員が参加するためです。 以上$R$ラウンド、利用可能な参加枠の合計は$R(n-1)$。 人それぞれが求めるもの$a_i$参加者総需要は$S$。 参加が唯一の制約であるため、実現可能性は参加枠の総供給が総需要を満たしているかどうかにのみ依存します。 ラウンドごとの除外以外に 1 人あたりの上限がないため、柔軟性が制限されるため、総容量が十分である限り、スーパーバイザをどのように配置しても、自動的に有効な 1 人あたりの割り当てが生成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    arr = list(map(int, input().split()))
    
    s = sum(arr)
    # minimal R such that (n-1)*R >= s
    r = (s + n - 2) // (n - 1)
    print(r)

if __name__ == "__main__":
    solve()
```実装は、導出された不等式を直接変換したものです。 唯一の微妙な点は、次のように実装される整数の上限除算です。$(S + n - 2) // (n - 1)$、浮動小数点エラーを回避します。 

Python では任意精度の整数を使用できるため、合計の計算は安全です。 シミュレーションは必要なく、個々のスーパーバイザーの割り当てを追跡する必要もありません。

 ## 特殊なケース

 すべての値が最小の場合、たとえば$n=3, a=[1,1,1]$、式は次のようになります$R = 1$。 1 ラウンドでは、時間の経過とともに 1 人プールあたり 2 つの参加スロットがすでに提供されており、単一ラウンドの割り当ては機能します。 

たとえば、1 つの値が優勢な場合、$a=[100,1,1,1]$、私たちは得ます$S=103$、$n=4$、 それで$R = \lceil 103/3 \rceil = 35$。 各ラウンドは 3 つの参加スロットを提供し、35 ラウンドでは 105 のスロットが生成されます。これは、監視の制約を軽い参加者に分散しながら、重い需要を満たすのに十分です。 

すべての値が等しい場合、需要と容量の両方が直線的に増加し、天井分割は特別な場合を除いて非割り算を処理するため、ソリューションはスムーズに拡張されます。
