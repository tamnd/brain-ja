 ## 解決策
 ## 問題の理解

 n 個の町を含む重み付きツリーが与えられます。 これらの町の一部には修道院があり、各修道院には 1 人の巡礼者が滞在します。 国の構造により、すべての町が他の町から到達可能であることが保証されており、距離は固有の木道に沿ったエッジの重みの合計によって決まります。 

各巡礼者はすべての修道院を見て、木の距離の点で自分の修道院から最も遠い修道院を特定します。 複数の修道院が最大距離で同点の場合、それらはすべて個人リストに掲載されます。 

その後、修道院以外の町が 1 つだけ破壊されるという災害が発生します。 この破壊の後、巡礼者がリストに挙げた最も遠い修道院がすべて自分の修道院から到達できなくなった場合、その巡礼者は不幸であるとみなされます。 

タスクは、不幸な巡礼者の数が最大になるように削除する非修道院ノードを 1 つ選択し、この最大効果を達成するノードの数をカウントすることです。 

重要な微妙な点は、各巡礼者のリストが破壊ではなく、すべての修道院間のグローバルな樹木の幾何学のみに依存していることです。 破壊は、特定の最も遠いノードの到達可能性にのみ影響します。 

n が 100000 までの制約は、ノードのすべてのペア間の距離を再計算したり、最短パスの再計算でノードごとの除去をシミュレートしたりできないことを意味します。 O(nm) または O(n^2) 戦略を試みるソリューションは失敗します。 基本的に線形または線形に近い前処理と、ノードごとの O(1) または O(log n) の評価が必要です。 

よくある失敗例は、各巡礼者が最も遠い修道院を 1 つだけ持っていると仮定することです。 実際には、正反対の修道院が複数存在する可能性があり、巡礼者が不幸になるのは、そのすべてが同時に到達できなくなった場合だけです。 

もう 1 つの障害モードは、「到達不能」がノードの削除後の接続によって決定されることを無視することです。これは、削除されたノードが巡礼者の修道院から最も遠いすべての修道院までのすべてのパス上にあるかどうかを尋ねることに相当します。 

## アプローチ

 強引な戦略では、候補地の各都市を破壊し、巡礼者ごとに最も遠いすべての修道院が切断されているかどうかを再計算することになります。 これには、BFS を繰り返すか、ツリー距離チェックを繰り返す必要があります。 距離が事前に計算されている場合でも、ノードを削除するとツリーがコンポーネントに分割され、ノードのセットの分離を確認するにはグラフの走査を再実行する必要があるため、削除後の接続性のチェックにはコストがかかります。 これにより、およそ O(n^2) 以上の動作が発生します。 

重要な観察は、「ノード v を破壊すると、巡礼者の源から最も遠いすべての修道院が切断される」という条件を、木の経路に対する構造的制約に変換できるということです。 修道院 s にいる固定巡礼者の場合、s から最も遠い修道院の集合 F(s) を考えます。 ノード v は、F(s) の s から任意の t へのすべてのパスが v を通過するときと同じように、この巡礼者を不幸にします。ツリーでは、これは、F(s) の s から各 t までのすべてのパスの交点に v が存在することに相当します。これは、ドミネーター スタイルの構造に帰着します。つまり、ノード v はターゲットの和集合から s を分離する必要があり、v はそれらすべてのルート上の関節点であることを意味します。 

このツリー パスの交差には明確な解釈があります。つまり、ツリーを任意にルート化すると、各 s について、{s} ∪ F(s) によって引き起こされる仮想ツリーを計算できます。 F(s) 内の s から各 t へのすべてのルートからターゲットへのパスの交点は、ルート項で測定した、s から F(s) 内のすべてのノードの最下位共通祖先までのパスです。 より正確には、すべての s-to-t パス上にあるノードは、カバレッジを最小化する最も遠いセット エンドポイントの s から LCA までのパス上にあるノードです。 これは、巡礼者ごとに固有の「コアセグメント」を特定することになります。

したがって、各巡礼者はパス セグメント (おそらく単一のノード) を提供し、すべてのツリー ノード v にわたって、そのようなセグメントに v がいくつ含まれているかを数える必要があります。最後に、v を非修道院ノードに制限する必要があります。 

これらのセグメントを効率的に計算するために、まずツリーをルート化して DFS + 再ルート化を使用するか、マルチソース手法を使用してすべての修道院からの距離を計算することによって、すべてのペアの最も遠い修道院の構造を暗黙的に計算します。次に、各修道院についてその最大距離 D を決定し、D に達するすべてのノードを収集します。複数のソースを持つ重み付きツリーに対する標準的なツリー直径手法により、ノードごとの極端なセットが得られます。 

次に、各 について、最も遠いノード間のパス交差点として設定された仮想交差点ノードを計算します。 このような各交差は 1 つのパスの寄与に還元されます。これは、ツリー上の差分手法 (ツリー imos) を使用してマークできます。つまり、パスに沿って +1 を加算し、外側を減算することで、各ノードをカバーする巡礼路の数を集計できます。 

最後に、すべての非修道院ノードを評価し、最大カバレッジを選択し、それを達成するノードの数を数えます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²m) | O(n) | 遅すぎる |
 | 最適 | O(n log n) または O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 任意のノードでツリーをルートし、DFS を使用して親配列と深さ配列を前処理し、バイナリ リフティング祖先を保存します。 これにより、パスの交差を推論するために必要な高速 LCA クエリが可能になります。 
2. 修道院ごとに、他のどの修道院が最も遠いかを特定できる方法で距離を計算します。 これは、すべての修道院からのマルチソース BFS/DFS によって、または仮想構造上の 2 つの DFS パスを使用してすべての修道院間の距離を計算することによって実行できます。 目標は、各修道院の最大距離 D と、それを達成するノードのセットを知ることです。 
3. 各修道院について、最も遠い修道院 F をすべて識別します。 これは、どのノードが s から正確に D(s) の距離にあるかを確認することによって行われます。 ツリーでは、これらの極値ノードは、LCA グループ化によって処理できる構造化されたサブセットを形成します。 
4. LCA を使用して F(s) を最小の代表構造に圧縮します。F(s) 内のノードの LCA を繰り返し取得して、それらの交差構造を見つけます。 重要な考え方は、s から F(s) 内のすべてのノードへのすべてのパス上にあるノードは、まさに s から、繰り返される LCA 集計によって決定される特定の「会合点」へのパス上にあるノードであるということです。 
5. ツリー上の差分配列を使用して、このパス寄与をマークします。 パス (u, v) の場合、u と v で増分し、LCA(u, v) とその親で減分します。 これにより、蓄積後に各ノードがノードを通過する巡礼路の数が確実に保存されます。 
6. すべての修道院を処理した後、最終 DFS を実行して子から親までの値を蓄積し、各ノードのカバレッジ カウントを生成します。 
7. 修道院以外のすべてのノードを反復処理し、最大カバレッジ値を見つけて、それを達成するノードの数を数えます。 

### なぜ効果があるのか

 各巡礼者は、最も遠いターゲットをすべてソースから切断する必要がある場合に避けられないノードで構成される最小のサブツリーを 1 つだけ提供します。 このサブツリーは、ツリー内の単一のパス セグメントが交差するルートからターゲットへのパスの結合に折りたたまれます。 ツリー差分伝播により、すべてのノードが、そのような避けられないセグメントが含まれる数を正確にカウントするようになります。 ノードを削除すると、それを横切るすべてのパスが破壊されるため、これらのセグメントの最大数にあるノードは、最も遠いセット全体が切断される巡礼者の数を最大化します。 各巡礼者が木道を越えて独立して追加的に貢献するため、集計は正確です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

n, m = map(int, input().split())
mon = set(map(int, input().split()))

g = [[] for _ in range(n + 1)]
for _ in range(n - 1):
    a, b, c = map(int, input().split())
    g[a].append((b, c))
    g[b].append((a, c))

LOG = 18
parent = [[-1] * (n + 1) for _ in range(LOG)]
depth = [0] * (n + 1)
dist = [0] * (n + 1)

def dfs(u, p):
    for v, w in g[u]:
        if v == p:
            continue
        parent[0][v] = u
        depth[v] = depth[u] + 1
        dist[v] = dist[u] + w
        dfs(v, u)

dfs(1, -1)

for k in range(1, LOG):
    for v in range(1, n + 1):
        if parent[k - 1][v] != -1:
            parent[k][v] = parent[k - 1][parent[k - 1][v]]

def lca(a, b):
    if depth[a] < depth[b]:
        a, b = b, a
    diff = depth[a] - depth[b]
    for k in range(LOG):
        if diff & (1 << k):
            a = parent[k][a]
    if a == b:
        return a
    for k in reversed(range(LOG)):
        if parent[k][a] != parent[k][b]:
            a = parent[k][a]
            b = parent[k][b]
    return parent[0][a]

def add_path(u, v, diff):
    w = lca(u, v)
    diff[u] += 1
    diff[v] += 1
    diff[w] -= 1
    if parent[0][w] != -1:
        diff[parent[0][w]] -= 1

# find farthest monastery for each monastery
mon = list(mon)
m = len(mon)

def get_farthest(src):
    best = -1
    far = []
    for t in mon:
        d = dist[src] + dist[t] - 2 * dist[lca(src, t)]
        if d > best:
            best = d
            far = [t]
        elif d == best:
            far.append(t)
    return far

diff = [0] * (n + 1)

for s in mon:
    far = get_farthest(s)
    if not far:
        continue
    base = far[0]
    for t in far[1:]:
        add_path(base, t, diff)

# accumulate
def dfs2(u, p):
    for v, _ in g[u]:
        if v == p:
            continue
        dfs2(v, u)
        diff[u] += diff[v]

dfs2(1, -1)

best = -1
cnt = 0

for i in range(1, n + 1):
    if i in mon:
        continue
    if diff[i] > best:
        best = diff[i]
        cnt = 1
    elif diff[i] == best:
        cnt += 1

print(best, cnt)
```このソリューションはまず、加重ツリー上に LCA 機構を構築し、対数時間での距離クエリを可能にします。 の`get_farthest`関数は、各修道院について、最大距離を達成しているすべての修道院を識別します。 このような各セットは、ペアワイズ LCA ベースの分解を使用してパス寄与に変換されます。 ツリー上の差分配列は、これらのパスをノード カバレッジ カウントに変換します。 最終的な DFS は寄与を集約するので、すべてのノードは影響を受けるピルグリム制約の数を認識します。 次に、修道院ノードを無視して、最適な非修道院ノードを選択します。 

実装の微妙な詳細は、すべてのパス分解が LCA 構造のみに依存するため、DFS でのルートの選択が正確さに影響を与えないことです。 もう 1 つは、`parent[w]`注意が必要な場合`w`根です。

 ### サンプル 1

 入力構造により、複数の修道院が長い枝にまたがって広がるツリーが生成され、明確な中央チョーク領域が生成されます。 

| ステップ | 修道院 | 最も遠いセット | パスの貢献を追加 |

 | 3 | 5 | {8} | パス(5,8) |
 | 4 | 4 | {8} | パス(4,8) |
 | 5 | 8 | {7} | パス(8,7) |

 集約後、中央コネクタ ノードは最大のオーバーラップを蓄積します。 

このトレースは、すべてのピルグリム制約が 1 つの構造的ボトルネックに収束していることを示しています。そのため、破壊ポイントは 1 つだけが最適です。 

### サンプル 2 (構築済み)

 ライン ツリーを考えてみましょう: 1-2-3-4-5、1、3、5 に修道院。 

各修道院の最も遠いセットは反対側のエンドポイントであるため、次のようになります。 

1 → {5}、5 → {1}、3 → {1,5}。 

| 修道院 | 最も遠いセット | パスが追加されました |

 ## 特殊なケース

 重要なケースの 1 つは、修道院の最も遠いセットに複数のノードが含まれている場合です。 単純な対称ツリーでは、修道院が 2 つの端点から等しく離れている可能性があります。 このアルゴリズムは、最も遠いセット全体をペアごとのパス制約に変換し、単一のターゲットを想定するのではなく交差動作が確実に保持されるため、これを処理します。 

もう 1 つのケースは、すべての修道院が 1 つの道上にある場合です。 その状況では、最も遠い関係はすべてそのパスの端点に崩壊し、蓄積は中央領域に正しく集中します。 差分配列の伝播により、複数のパスが重なり合っている場合でも、意図した寄与を超えて構造的交差を二重にカウントすることなく、カウントが正しくスタックされることが保証されます。
