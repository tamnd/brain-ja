 ## 解決策
 ## 問題の理解

 整数の配列とサブセットのコレクションが与えられ、それぞれが配列内のインデックスを参照します。 サブセットの要素の合計をクエリする操作と、サブセットのすべての要素に値を追加する操作の 2 種類の操作が繰り返し実行されます。 目標は、一連の加算後に合計クエリに効率的に応答することであり、クエリは任意の順序で混在することができます。 

入力制約は重要です。配列内の要素は最大 100,000 個、サブセットは最大 100,000 個、クエリは最大 100,000 個です。 各サブセットは配列内の要素を参照し、すべてのセットにわたるサブセット要素の合計数が 100,000 を超えることはありません。 これは、一部のサブセットが大きい可能性はあるものの、平均してほとんどのサブセットは小さいことを意味します。 各クエリのサブセットを反復処理する素朴なアプローチでは、最悪の場合の複雑さがサブセットのサイズに比例するため、各クエリの大きなサブセットを直接合計するのは遅すぎます。 具体的には、クエリごとにすべての要素を反復すると、最悪の場合、10^10 の操作が発生する可能性があります。これは、3 秒の実行時間の実行可能な制限をはるかに超えています。 

サブセットが複数のクエリに表示され、他のサブセットと重複する場合、微妙なエッジ ケースが発生します。 不注意な解決策では、追加クエリごとに各要素に値を個別に追加し、毎回合計を再計算する可能性があります。 これにより、特にサブセットが大きく、頻繁に交差する場合、繰り返し作業が発生し、過剰な実行時間が発生する可能性があります。 たとえば、サブセット S1 にインデックス [1,2,3,4,5] が含まれ、サブセット S2 に [3,4,5,6,7] が含まれる場合、両方に対して別々に加算を実行する単純なアプローチでは、重複する要素が不必要に複数回発生する可能性があります。 正しい出力には、すべての累積加算が反映されている必要があります。 

## アプローチ

 ブルートフォース手法では、クエリごとにサブセットのインデックスを反復処理します。 合計クエリの場合、参照されているすべての要素を直接合計します。 追加クエリの場合、サブセット内の各要素がインクリメントされます。 これは正しく動作しますが、クエリごとの複雑さが O(|S_k|) であるため、大規模なサブセットまたは頻繁なクエリの場合は法外に遅くなります。 最大 100,000 のクエリと重要なサイズのサブセットを使用すると、10^10 の操作を軽く超える可能性があります。 

最適化のための重要な洞察は、ほとんどのサブセットが小さく、すべてのサブセットにわたって参照される要素の総数が制限されているという事実を利用することです。 サブセットは、サイズに基づいて「重い」カテゴリと「軽い」カテゴリに分類できます。 重いサブセットは十分に大きいため、毎回それを反復処理するとコストがかかります。 重いサブセットの場合、遅延加算値を維持します。個々の要素には触れずに、サブセット全体にどれだけ追加されたかを保存します。 軽いサブセットの場合は、コストが小さいため、個々の要素を直接更新し続けます。 さらに、軽いサブセットが重いサブセットの一部である要素に影響を与える場合に合計を正しく調整するために、重いサブセットとすべてのサブセットの間の交差を事前計算します。 

大きなサブセットは少なく、小さなサブセットは安価であるという観察により、重いサブセットの数が少なく、軽いサブセットのクエリごとの作業がサブセット サイズにおいて線形のままであるため、すべてのクエリを約 O(√n) 時間で処理できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(q * max( | S_k | )) |
 | ヘビーライトの最適化 | O(q * √(n)) | O(n + m * √(n)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 閾値を計算する`B`重いサブセットを分類します。 実際の選択は、サブセット要素の総数の平方根です。たとえば、`B = int(sqrt(sum_of_sizes))`。 サイズ ≥ B のサブセットは重いとみなされ、その他は軽いと見なされます。 
2. 各サブセットについて、その初期合計を事前計算します。 重いサブセットの場合は、この合計を個別に保存します。 要素ごとに、どの重いサブセットにその要素が含まれているかのリストを保持します。 これにより、要素が変更されたときに、大きなサブセットの合計を効率的に調整できるようになります。 
3. 配列を初期化する`lazy`重いサブセットの場合、`lazy[k]`は、k 番目の重いサブセットに適用される累積加算を表します。 これにより、重いサブセットに対する追加クエリの O(1) 更新が可能になります。 
4. クエリごとに、サブセット タイプを決定します。 

- 重いサブセットに対する合計クエリの場合は、保存されている合計と遅延加算にサブセット サイズを乗算した値を返します。 また、要素が個別に更新された交差するライトのサブセットからの寄与も追加します。 
- 軽いサブセットに対する合計クエリの場合は、各要素を直接合計し、遅延値を介して交差する重いサブセットからの寄与を追加します。 
5. 追加のクエリの場合:

 - サブセットが軽い場合は、その要素を反復して増分し、事前に計算された交差を使用して、交差する重いサブセットに保存されている合計も更新します。 
- サブセットが重い場合は、その遅延値をインクリメントします。 これにより、個々の要素に触れることがなくなり、合計クエリでは遅延値を使用してこの増分が考慮されます。 
6. すべての合計クエリは、保存された合計と遅延寄与を使用して、各クエリが O(B) または O(√n) 時間で応答されることを保証し、全体的なアルゴリズムを効率化します。 

機能する理由: このアルゴリズムは、重いサブセットが累積合計と遅延加算を追跡する一方で、軽いサブセットが実際の要素を更新するという不変条件を維持します。 重いサブセットと軽いサブセットの間の交差は事前に計算されるため、軽いサブセットに対する変更は、交差する重いサブセットの合計に正しく反映されます。 これにより、サブセットが重複している場合でも、合計クエリが常に以前のすべての追加を反映することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from math import sqrt

n, m, q = map(int, input().split())
a = list(map(int, input().split()))

sets = []
sizes = []
total_size = 0
for _ in range(m):
    line = list(map(int, input().split()))
    k = line[0]
    s = [x-1 for x in line[1:]]
    sets.append(s)
    sizes.append(k)
    total_size += k

B = int(sqrt(total_size)) + 1

heavy = []
heavy_idx = {}
light = []
for i, s in enumerate(sets):
    if sizes[i] >= B:
        heavy_idx[i] = len(heavy)
        heavy.append(i)
    else:
        light.append(i)

heavy_sums = [0] * len(heavy)
lazy = [0] * len(heavy)

element_heavy = [[] for _ in range(n)]
for idx, h in enumerate(heavy):
    for x in sets[h]:
        element_heavy[x].append(idx)
        heavy_sums[idx] += a[x]

intersect = [dict() for _ in range(m)]
for li in light:
    for h_idx, h in enumerate(heavy):
        cnt = sum(1 for x in sets[li] if x in sets[h])
        if cnt:
            intersect[li][h_idx] = cnt

for _ in range(q):
    tmp = input().split()
    if tmp[0] == '?':
        k = int(tmp[1]) - 1
        res = 0
        if k in heavy_idx:
            h_idx = heavy_idx[k]
            res = heavy_sums[h_idx] + lazy[h_idx] * sizes[k]
            for li, cnt in intersect[k].items():
                res += lazy[li] * cnt if li < len(lazy) else 0
        else:
            res = sum(a[x] for x in sets[k])
            for h_idx, cnt in intersect[k].items():
                res += lazy[h_idx] * cnt
        print(res)
    else:
        k = int(tmp[1]) - 1
        x = int(tmp[2])
        if k in heavy_idx:
            h_idx = heavy_idx[k]
            lazy[h_idx] += x
        else:
            for idx in sets[k]:
                a[idx] += x
            for h_idx, cnt in intersect[k].items():
                heavy_sums[h_idx] += x * cnt
```このソリューションは、重いサブセットと軽いサブセットを個別に処理し、大きなサブセットを不必要に反復することなく更新が正しく伝播されるようにします。 重いサブセットの合計は遅延して更新されますが、軽いサブセットは個々の要素に直接触れます。 交差は事前に計算されるため、正確な合計クエリが可能になります。
