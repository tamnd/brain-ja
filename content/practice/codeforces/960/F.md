 ## 解決策

 ## 問題の理解

 各エッジに関連する重みと、入力内の順序によって与えられる暗黙的な位置を持つ有向グラフが与えられます。 有効なパスは単純である必要はありません。 頂点は繰り返される可能性があり、エッジの方向に従っている限り、エッジを複数回横断する可能性があります。 

主な制限は、パスで使用されるエッジのシーケンスです。 ウォークに沿って使用されるエッジをリストする場合、それらの重みは厳密に増加する必要があり、また、後で使用されるエッジは以前に使用されたエッジよりも入力の後に現れる必要があるという意味で、入力順序も尊重する必要があります。 タスクは、そのような有効なウォークに含めることができるエッジの最大数を見つけることです。 

この制約により、ほぼ線形または対数的なエッジごとの処理が求められます。 最大 100,000 のエッジで、$O(m^2)$すべてのエッジ ペアにわたる動的プログラミング アプローチは不可能です。$10^{10}$最悪の場合は移行します。 平$O(m \log m)$は許容されるため、構造はおそらく最長増加サブシーケンス スタイルの DP に縮小されますが、グラフ接続性の制約があります。 

エッジがエンドポイントを共有しているものの、順序の制約により順番に使用できない場合、微妙な障害が発生します。 たとえば、より小さい重みを持つエッジが入力の後半に現れた場合、グラフの接続性によってそれが可能であっても、以前のエッジから構築されたチェーンを拡張することはできません。 

次の小さな入力を考えてみましょう。```
3 3
1 2 5
2 3 10
1 2 1
```正解は 2 です。エッジ (1→2、重み 5) と (2→3、重み 10) を使用します。 重みによってのみソートし、入力順序を無視する単純な戦略では、3 番目のエッジ (1→2、重み 1) が接頭辞として誤って使用しようとする可能性があります。たとえそれが入力シーケンスの順序付け制約内で後から出現し、法的に前のエッジより前に存在することはできないにもかかわらずです。 

本当の課題は、パスの到達可能性とエッジ上のグローバルな順序付け制約を組み合わせることです。 

## アプローチ

 強引なアイデアは、すべてのエッジを可能な開始点とみなして、後のすべてのエッジをスキャンして、グラフ構造を通じてそれらを接続できるかどうか、および重みが増加するかどうかを確認することによって拡張しようとすることです。 これにより、エッジ全体に DP が効果的に構築されます。$i$、すべてのエッジを試します$j > i$そしてチェックしてください$b_i = a_j$そして$w_i < w_j$。 これは正しいですが、これはすでにエッジ互換性によって定義された DAG 上の最長増加パスに似ていますが、遷移の数は依然として到達する可能性があります。$O(m^2)$。 

ボトルネックは、ほとんどの遷移が無関係であるにもかかわらず、エッジごとに後のすべてのエッジを繰り返しスキャンすることです。 重要な観察は、エンドポイントを共有する遷移のみを考慮しており、各頂点で終了する最適なチェーンを維持できるということです。 

エッジがエッジを拡張するという観点から考えるのではなく、視点を反転します。 各頂点について、これまでに処理されたエッジを使用して、その頂点で終了する最良の達成可能なチェーンを維持します。 次に、エッジを処理するときに$a \to b$で、最もよく知られているチェーンの拡張を試みることができます。$a$1つずつ。 ただし、エッジの重みは厳密に増加しなければならないという制約を尊重する必要があるため、以前に計算されたすべての状態を構造なしで自由に再利用することはできません。 

これにより、エッジが重みによってグループ化されます。 重みの昇順にエッジを処理する場合、以前の重みから現在の重みへのすべての遷移は、重み制約の観点から有効です。 残りの制約は入力順序です。エッジはインデックスの昇順でも使用する必要があるため、同じ重みグループ内では、同じグループ内のエッジが間違って連鎖しないようにする必要があります。 

したがって、重みによってグループ化されたエッジを処理します。 各重みグループについて、最初に以前の DP 状態を使用してすべての候補更新を計算し、グループの終了後にのみ更新を適用します。 これにより、同じ重さのエッジ間の汚染が回避されます。 

遷移を高速化するために、頂点に対して辞書または配列 DP を使用します。$dp[v]$頂点で終わる最良のチェーンです$v$。 各エッジについて$u \to v$、候補を検討します$dp[u] + 1$ただし、同じ体重グループからの更新を時期尚早に使用していないことを確認する必要があります。

 ## アルゴリズムのチュートリアル

 私たちはこの問題を最長の有効なエッジのチェーンを構築するものとして扱いますが、その有効性は重みの順序付けと入力処理の制約の両方に依存します。 

1. すべてのエッジを重みでソートしますが、元の入力インデックスは付けたままにします。 ソートにより、重みを処理すると、より小さな重みがすべてすでに確定していることが保証されます。 これが必要なのは、厳密に増加する重みの順序がグローバルであり、グラフ構造に依存しないためです。 
2. 頂点に対する DP 配列を初期化します。$dp[v]$頂点で終わる有効なチェーン内のエッジの最大数を表します$v$すでに処理された重みのみを使用します。 
3. エッジを同じ重みのグループに分けて処理します。 各グループについて、最初に、DP をすぐに更新せずに、現在の DP 値を使用してすべての候補遷移を計算します。 この分離が必要なのは、そうしないと同じ重量のエッジが誤って相互に延長され、厳密な重量増加要件に違反する可能性があるためです。 
4. 各エッジについて$u \to v$グループ内で候補値を計算します$dp[u] + 1$。 この候補を頂点の一時配列に保存します$v$。 
5. グループ内のすべてのエッジを処理した後、保存されている最適な更新候補を DP 配列に適用します。 これにより、同じウェイトのすべてのエッジが平行レイヤーとして扱われるようになります。 
6. すべての DP 値にわたるグローバル最大値を答えとして保持します。 

重要な考え方は、DP は重みを厳密に増加させることによってのみ前方に伝播し、等しい重みによるバッチ処理によりその制約の正確性が維持されながら、グラフ接続による連鎖が可能になるということです。 

### なぜ効果があるのか

 すべての重みを厳密に小さく処理した後の任意の時点で、$w$、$dp[v]$で終わる最適な有効なチェーンを保存します$v$それらのエッジのみを使用します。 ウェイトのエッジを処理するとき$w$、拡張はこれらのすでに完了した状態からのものでなければなりません。 同じ重みグループ内で更新を遅らせるため、重みのエッジがありません$w$重みの別のエッジに依存する可能性があります$w$、厳密な増加を維持します。 すべてのエッジが重み順に 1 回だけ処理されるため、すべての有効なチェーンが考慮され、DP は常に頂点ごとに到達可能な最適なチェーン長を保存します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n, m = map(int, input().split())
    edges = []
    for _ in range(m):
        a, b, w = map(int, input().split())
        edges.append((w, a, b))

    edges.sort()

    dp = [0] * (n + 1)
    ans = 0

    i = 0
    while i < m:
        j = i
        updates = []

        while j < m and edges[j][0] == edges[i][0]:
            w, a, b = edges[j]
            updates.append((a, b, dp[a] + 1))
            j += 1

        for a, b, val in updates:
            if val > dp[b]:
                dp[b] = val
                if val > ans:
                    ans = val

        i = j

    print(ans)

if __name__ == "__main__":
    main()
```このソリューションでは、潜在的な遷移をグローバルに一貫した順序で処理できるように、まず重みによってエッジを並べ替えます。 DP 配列には、各頂点で終わる最適なチェーンが格納されます。 

一時的な`updates`リストは非常に重要です。 これにより、厳密な増加条件を破ることになる、同じ反復内で同じ重みのエッジが相互に使用されることが防止されます。 各グループは凍結された DP 状態から計算され、一緒に適用されます。 

DP の改善が発生するたびに、答えは更新されます。これは、何らかの改善は、ある頂点で終了するより長い有効なエッジ シーケンスに対応するためです。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、複数のエッジが同じ重みを共有しているが、接続を通じてチェーンを形成できる場合です。 例えば：```
1 2 5
2 3 5
```グラフの接続性では長さ 2 のパスが許可されていますが、重みは厳密には増加していないため、正解は 1 です。 バッチ処理のステップにより、両方のエッジで同じ凍結された DP 状態が認識されるため、どちらも他方のメリットを享受できなくなります。 

もう 1 つの微妙なケースは、高重みのエッジが入力の早い段階で出現するが、ソート後もまだ使用できる場合に発生します。 重みでソートするため、重みが主な順序付けキーになると、入力順序は DP トランジションには無関係になります。 これは、単一のグローバルな重みタイムラインを強制することによって、アルゴリズムが入力順序と重み順序の間の緊張を正しく解決していることを確認します。
