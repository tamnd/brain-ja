 ## 問題の理解

 整数の配列があります。 操作により、2 つの異なる位置を選択し、一方の位置からもう一方の位置に値をコピーできます。 この操作は何度でも繰り返すことができるため、配列全体で値が重複する可能性があります。 

テスト ケースごとに、すべての要素の最終合計が奇数になるように配列を変換できるかどうかを判断する必要があります。 

制約は非常に小さいです。 すべてのテスト ケースの要素の合計数は最大 2000 であるため、比較的非効率なソリューションでも問題なく適合します。 本当の課題は、操作で何が変更でき、何が変更できないかを理解することです。 

重要な観察は、値をコピーしても新しい数値は作成されないということです。 和のパリティにとって重要なのは、要素が奇数か偶数かだけです。 すべての操作で 1 つの要素が別の既存の要素に置き換えられるため、配列には常に最初に出現した値のみが含まれます。 

奇数の合計を取得するには、最終的な配列に奇数の奇数の要素が含まれている必要があります。 和のパリティは正確に奇数の数のパリティであるため、問題は実際の大きさではなく、奇数と偶数の値に関する問題になります。 

いくつかの特殊なケースは見落とされがちです。 

考慮する：```
1
4
2 2 8 8
```答えは`NO`。 すべての値は偶数であり、偶数の値をコピーしても奇数の値を作成することはできません。 操作が可能かどうかだけを確認する不注意な解決策では、誤った答えが返されます。`YES`。 

考慮する：```
1
4
5 5 5 5
```答えは`NO`。 すべての値は奇数であり、それらが 4 つあるため、合計は偶数になります。 配列には偶数の値がないため、一連の演算の後、すべての位置は常に奇数のままになります。 奇数要素の数は同じままです`n`, したがって、合計が奇数になることはありません。 

考慮する：```
1
2
2 3
```答えは`YES`。 元の合計はすでに奇数であるため、演算は必要ありません。 少なくとも 1 つの操作を実行する必要があることを前提としたソリューションは、ここでは失敗します。 

## アプローチ

 ブルートフォースの考え方は、操作を直接考えることから始まります。 到達可能な配列を生成し、それらの合計が奇数であるかどうかを確認してみることができます。 各操作は 2 つのインデックスを選択し、無限に繰り返すことができるため、状態空間は非常に急速に爆発します。 控えめな値であっても、`n`、可能な配列の数は膨大になります。 このアプローチはすべての可能性を検討するため、原理的には正しいですが、完全に非現実的です。 

ブルートフォースのアイデアが難しく感じる理由は、それが正確な値に焦点を当てているためです。 この操作で実際に保存される情報は、見た目よりもはるかに少ないです。 最終的な答えに関係するのはパリティだけです。 

奇数の合計は、奇数の要素の数が奇数の場合にのみ発生します。 

現在の合計がすでに奇数であると仮定します。 そうすれば、単にゼロ操作を実行して答えることができます。`YES`。 

ここで、現在の合計が偶数であると仮定します。 パリティを変更できますか?

 配列に奇数値と偶数値の両方が含まれている場合は、一方のパリティをもう一方のパリティの位置にコピーできます。 これにより、奇数要素の数を変更できるようになります。 特に、奇数のカウントを常に奇数にすることができ、その結果、合計が奇数になります。 

すべての数値が偶数である場合、出現する可能性のあるすべての値は偶数であるため、合計は常に偶数になります。 

すべての数値が奇数の場合、すべての位置に常に奇数が含まれます。 奇数要素の数は永続的に次と等しくなります。`n`。 合計が奇数になるのは次の場合のみです。`n`奇数です。 今は和が偶数の場合を考えているので、これは、`n`は偶数であり、答えは`NO`。 

これにより、次のような非常に単純な基準が得られます。 

現在の合計が奇数の場合は答えます`YES`。 

それ以外の場合は答えてください`YES`配列に少なくとも 1 つの奇数と少なくとも 1 つの偶数が含まれる場合のみ。

 ## アルゴリズムのチュートリアル

 1. すべての要素の合計を計算します。 
2. 合計が奇数の場合は、次のように出力します。`"YES"`。 

すでに目的の条件を満たしているため、操作は必要ありません。 
3. 配列に少なくとも 1 つの奇数要素が含まれているかどうかを数えます。 
4. 配列に少なくとも 1 つの偶数要素が含まれているかどうかを数えます。 
5. 両方のパリティが存在する場合は、次のように出力します。`"YES"`。 

両方のパリティがあるということは、コピー操作を通じて奇数の要素の数を変更でき、奇数の合計を達成できることを意味します。 
6. それ以外の場合は、印刷します`"NO"`。 

すべての値が同じパリティを持つ場合、将来のすべての値もそのパリティを持つため、偶数の合計を奇数の合計に変えることはできません。 

### なぜ効果があるのか

 合計のパリティは、奇数要素の数のパリティのみに依存します。 初期合計がすでに奇数の場合、目標はすぐに達成されます。 

奇数と偶数の両方の値が存在する場合、コピーにより要素をあるパリティ クラスから別のパリティ クラスに変換し、奇数要素の数を変更できます。 これにより、奇数の奇数カウント、つまり奇数の合計を取得することが可能になります。 

すべての値が偶数の場合、到達可能なすべての配列は完全に偶数で構成されます。 すべての値が奇数の場合、到達可能なすべての配列は完全に奇数で構成されます。 どちらの場合も、パリティ構造は変更できないため、偶数の合計は永遠に偶数のままです。 まさにこれらの状況が答えです`NO`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())

for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))

    if sum(a) % 2 == 1:
        print("YES")
        continue

    has_odd = any(x % 2 for x in a)
    has_even = any(x % 2 == 0 for x in a)

    if has_odd and has_even:
        print("YES")
    else:
        print("NO")
```最初のチェックは最も簡単なケースを処理します。 合計がすでに奇数である場合、演算について推論する必要はまったくありません。 

変数`has_odd`そして`has_even`各パリティが配列に現れるかどうかを記録します。 実際のカウントは不要です。 両方のパリティが存在することのみが重要です。 

最終条件は証明から直接得られます。 偶数の合計を奇数の合計に変更できるのは、配列内のどこかで奇数と偶数の値の両方が利用可能な場合のみです。 

考えられる最大の合計は次のとおりであるため、オーバーフローの懸念はありません。`2000 × 2000 = 4,000,000`、これは Python の整数に簡単に適合します。
