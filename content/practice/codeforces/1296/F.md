 ## 解決策
 ## 問題の理解

 私たちには、接続されたネットワークが与えられています。$n$で接続されている駅$n-1$鉄道セグメント、つまり構造が木であることを意味します。 このツリーの各エッジには、1 から 2 までの範囲の未知の整数の重みがあります。$10^6$。 乗客からもいくつかの意見が寄せられています。 各観測値は 2 つのステーションを指定し、それらの 2 つのステーション間の一意のパスに沿った最小エッジ重みに等しい値を主張します。 

タスクは、すべての乗客の観測が同時に真になるように、すべてのエッジに整数の重みを割り当てることです。 すべての観察を満足できる割り当てがない場合は、不可能であることを報告する必要があります。 

中心となる問題は、各観測値が単一のエッジを制約するのではなく、パス全体にわたる最小値を制約することです。 これにより、異なるパス間で重複する制約が作成され、グローバルに一貫性を持たせる必要があります。 

制約$n, m \le 5000$許可する$O(n^2)$または$O(n \log n)$スタイルのソリューションですが、構造を持たずにクエリごとにパス情報を単純に再計算しようとするとリスクが生じます。$O(nm)$または、さらに悪いことに、各操作が非常に軽い場合に限り、まだ合格します。 ただし、正しい解決策は、実際には、反復的なトラバースではなく、パス間の関係に関する推論に依存します。 

貪欲な直観によって、いくつかの微妙な失敗例が現れます。 

失敗例の 1 つは、エッジを含む最初のパスを使用して各エッジを独立して割り当てることができると想定している場合です。 たとえば、2 つのクエリがエッジを共有しているが、重なり合うパス上で異なる最小値を要求する場合、値をローカルに割り当てると、後でのみ現れる矛盾が生じます。 

もう 1 つの失敗例は、各クエリで値を取得するためにパス上の 1 つのエッジだけが必要であると仮定した場合です。$g_j$。 これは、複数のクエリによって同じエッジが同時に互換性のない値の最小値になるように強制される可能性があるという事実を無視しています。 

本当の課題は、各制約が事実上、パス上で少なくとも 1 つのエッジが正確に値を持たなければならないことを示していることです。$g_j$、そのパス上のすべてのエッジには少なくとも値が必要です$g_j$。 これらはツリー パスに対するグローバル制約です。 

## アプローチ

 ブルートフォースの観点は、1 から 2 までのエッジ値のすべての割り当てを考慮することです。$10^6$。 各割り当てについて、各パスに沿った最小エッジ値を計算することにより、すべてのクエリを検証します。 パスクエリに答えるために LCA を事前計算したとしても、$O(\log n)$、の検索空間$10^{n}$割り当てではこれが不可能になります。 

クエリを任意の順序で処理したり、エッジの下限を更新したりするなど、クエリごとに建設的な貪欲なアプローチを試みたとしても、制約が非ローカルに相互作用するため、依然として失敗します。 重要な問題は、クエリが単一のエッジを割り当てないことです。 パス全体にわたって最小値が強制されるため、制約は構造化された方法で伝播します。 

重要な洞察は、視点を逆転させることです。 各クエリを最小値を定義するものとして考えるのではなく、パス上の少なくとも 1 つのエッジが正確にその最小値を達成する必要があり、そのパス上のすべてのエッジが少なくともその値でなければならないという要件として考えます。 これは、最初にすべてのエッジが値 1 で始まると仮定し、次に下限を強制する必要があることを示唆しています。 

制約をエッジ上の不等式としてモデル化できます。 あらゆるクエリに対して$(a, b, g)$、パス上のすべてのエッジは次の条件を満たす必要があります。$f_e \ge g$、さらに、パス上の少なくとも 1 つのエッジが次の条件を満たす必要があります。$f_e = g$。 最初の条件は、下限のパス最大制約を使用して簡単に強制できます。 2 番目の条件は、クエリを結合する条件です。 

この問題は、まずパス上の差分形式の伝播を使用して、ツリー内のすべての下限をプッシュすることで解決します。 次に、各クエリに、最終的に割り当てられた値が必要な最小値に等しいエッジが少なくとも 1 つ残っていることを検証します。 そうでない場合、設定は不可能です。 

残りの課題は、パス制約を効率的に適用してチェックすることです。 これは、親情報と深さ情報を前処理し、DFS ベースの LCA パス ウォーキングを使用することによって処理されます。

 | ブルートフォース | 指数 | O(n) | 遅すぎる |
 | 最適 |$O((n+m)\log n)$| O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 たとえばノード 1 でツリーを任意にルート化し、ノード間のパスを横断できるように親配列と深さ配列を計算します。 

1. すべてのエッジの下限を 1 として初期化します。これは、制約を考慮する前に考えられる最も弱い有効な割り当てを表します。 
2. クエリごとに$(a, b, g)$からの道を横断します。$a$に$b$(LCA 分解後) 親リンクを使用し、このパス上のすべてのエッジについて、その下限を少なくとも以下になるように更新します。$g$。 これにより、パス上の最小値がこれより小さくならないという条件が強制されます。$g$、すべてのエッジが少なくとも$g$。 
3. すべてのクエリを処理した後、これらの下限として最終エッジ値を計算します。 この時点では、すべて「$\ge g$」制約は構築によって満たされます。 
4. 各クエリを検証するには、次のパスが$a$に$b$割り当てられた値が等しいエッジを少なくとも 1 つ含む$g$。 いずれかのクエリがこの条件を満たさない場合、有効な割り当てが存在しないと結論付けられます。 
5. すべてのクエリが検証に合格した場合、割り当てられたエッジ値が出力されます。 

重要な点は、ステップ 2 は下限を強制するだけで、各クエリが最小値に達することをまだ保証していないことです。 このため、ステップ 4 が必要であり、スキップすることはできません。 

### なぜ効果があるのか

 各クエリはパスに対して単調な制約を課します。すべてのエッジは少なくとも次の条件を満たす必要があります。$g$、少なくとも 1 つのエッジはしっかりと固定されている必要があります。$g$。 下限を伝播することで、一方向の実現可能性が保証されます。つまり、エッジが最小要件に違反することはありません。 検証ステップでは、「タイトエッジ」要件も満たされていることを確認します。 

すべての制約は下限制約であるため、エッジ値を増やしても実現可能性が損なわれることはありません。そのため、必要な下限をすべて強制すると、有効な解はその下限以上になる必要があります。 解が存在する場合、タイトエッジ条件がまだ達成可能であれば、制約に違反することなくエッジが正確にこれらの下限になる解に変換できます。 検証ステップでは、この必要な構造が存在するかどうかを確認します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n = int(input())
adj = [[] for _ in range(n)]
edges = []

for i in range(n - 1):
    x, y = map(int, input().split())
    x -= 1
    y -= 1
    adj[x].append((y, i))
    adj[y].append((x, i))
    edges.append((x, y))

m = int(input())
queries = []
for _ in range(m):
    a, b, g = map(int, input().split())
    queries.append((a - 1, b - 1, g))

parent = [-1] * n
depth = [0] * n
edge_to_parent = [-1] * n

def dfs(v, p):
    for to, idx in adj[v]:
        if to == p:
            continue
        parent[to] = v
        depth[to] = depth[v] + 1
        edge_to_parent[to] = idx
        dfs(to, v)

dfs(0, -1)

def get_path_edges(u, v):
    res = set()
    while u != v:
        if depth[u] < depth[v]:
            u, v = v, u
        res.add(edge_to_parent[u])
        u = parent[u]
    return res

f = [1] * (n - 1)

for a, b, g in queries:
    path_edges = get_path_edges(a, b)
    for ei in path_edges:
        f[ei] = max(f[ei], g)

def path_has_value(a, b, g):
    while a != b:
        if depth[a] < depth[b]:
            a, b = b, a
        if f[edge_to_parent[a]] == g:
            return True
        a = parent[a]
    return False

ok = True
for a, b, g in queries:
    if not path_has_value(a, b, g):
        ok = False
        break

if not ok:
    print(-1)
else:
    print(*f)
```DFS はルート付きツリーを構築し、各ノードに親エッジを割り当てて、任意のパスに沿った上向きのトラバースを可能にします。 機能`get_path_edges`より深いノードを繰り返しリフトすることでパス上のすべてのエッジを収集します。これで十分です。$n \le 5000$。 

配列`f`各エッジの現在の下限を 1 から保存します。各クエリはパス全体にわたってその最小値を強制します。 

検証関数は、クエリに必要な最小値と正確に等しいエッジが少なくとも 1 つあるかどうかをチェックします。 これは、パスを再度歩き、エッジ値を確認することによって行われます。 

微妙な点は、隣接エッジを繰り返し再構成するのではなくエッジ インデックスを保存することで、無向表現でも正確性が保証されることです。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input())
    adj = [[] for _ in range(n)]
    edges = []

    for i in range(n - 1):
        x, y = map(int, input().split())
        x -= 1
        y -= 1
        adj[x].append((y, i))
        adj[y].append((x, i))
        edges.append((x, y))

    m = int(input())
    queries = [tuple(map(int, input().split())) for _ in range(m)]

    parent = [-1] * n
    depth = [0] * n
    edge_to_parent = [-1] * n

    def dfs(v, p):
        for to, idx in adj[v]:
            if to == p:
                continue
            parent[to] = v
            depth[to] = depth[v] + 1
            edge_to_parent[to] = idx
            dfs(to, v)

    dfs(0, -1)

    def path(u, v):
        res = set()
        while u != v:
            if depth[u] < depth[v]:
                u, v = v, u
            res.add(edge_to_parent[u])
            u = parent[u]
        return res

    f = [1] * (n - 1)

    for a, b, g in queries:
        a -= 1
        b -= 1
        path_edges = path(a, b)
        for ei in path_edges:
            f[ei] = max(f[ei], g)

    def ok(a, b, g):
        while a != b:
            if depth[a] < depth[b]:
                a, b = b, a
            if f[edge_to_parent[a]] == g:
                return True
            a = parent[a]
        return False

    for a, b, g in queries:
        a -= 1
        b -= 1
        if not ok(a, b, g):
            return "-1"

    return " ".join(map(str, f))

 ## 特殊なケース

 重要なエッジ ケースは、クエリごとに異なる「タイトな」エッジが期待される一方で、複数のクエリが同じエッジの下限の増加を強制する場合です。 単純なチェーンでは、あるクエリがパス全体で最小 10 を要求し、別のクエリが同じエッジに重なるサブパスで最小 5 を要求するとします。 アルゴリズムは境界を正しく引き上げますが、検証により、5 クエリのどこかに 5 に等しいエッジが残り、どこでも 10 で上書きされないことが確認されます。 

別のエッジ ケースは、クエリされたパス上のすべてのエッジが他のクエリによって必要な最小値を超える場合に発生します。 その場合、すべての制約が不等式として満たされていても、必要な最小値と正確に等しいエッジが存在しないことが失敗の原因となりますが、これはパスをスキャンすることによる検証中に正しく検出されます。 

最後のケースは、制約が一貫した階層を形成する場合です。 たとえば、g 値が減少するネストされたパスは依然として成功します。これは、各パスの少なくとも 1 つのエッジが、より強力な制約によって解除される前に独自のしきい値に留まるためです。
