 ## 解決策
 ## 問題の理解

 小文字の文字列があります。 すべての位置には、0 または 1 の 2 つの色のいずれかを割り当てる必要があります。 

色を選択した後、色が異なる場合にのみ、隣接する文字を交換することができます。 このようなスワップは何度でも実行できます。 目的は、何らかの色付けによって文字列をアルファベットの降順でない順序に並べ替えることができるかどうかを判断することです。 

出力は一連のスワップではありません。 有効なカラーリングが存在する場合のみ、それを印刷する必要があります。 

キー制限はスワップ ルール内に隠されています。 同じ色の 2 つの隣接する文字を直接交換することはできません。 さらに重要なのは、それらの相対的な順序がまったく変わることはありません。 交換のたびに異なる色の文字が交換されるため、同じ色のクラスに属する文字は常に元の順序を維持します。 

長さは最大でも 200 です。これは、$O(n^2)$または$O(n^3)$溶液は完全に安全です。 小さな制約は、位置に関するグラフを明示的に構築して分析できることを示すヒントです。 

よくある間違いは、キャラクター自体のことだけを考えて、位置を無視することです。 色付けは文字値ではなくインデックスに割り当てられます。 2 つの同じ文字が異なる色になる場合があります。 

次の文字列を考えてみましょう。```
ba
```ソートされた文字列は、`"ab"`。 2 つの文字の順序を変更する必要があります。 同じ色の文字は相対的な順序を変更できないため、異なる色を受け取る必要があります。 有効な答えは次のとおりです。```
YES
01
```別の微妙なケースは次のとおりです。```
cba
```ソートされた文字列は、`"abc"`。 すべての位置のペアが反転されます。 位置 1 は位置 2 および 3 と競合し、位置 2 は位置 3 と競合します。これにより、競合の三角形が形成され、2 色だけで色を付けることはできません。 正しい答えは次のとおりです。```
NO
```文字値のみに基づいて不用意に貪欲に色付けを行うと、解決策が存在すると誤って主張する可能性があります。 

もう 1 つの特殊なケースは、多くの文字が等しい場合です。```
aaaa
```文字列はすでにソートされています。 制約がまったくないので、あらゆるカラーリングが機能します。 出力は次のとおりです。```
YES
0000
```等しい文字を反転として扱うと、不必要な制限が誤って導入されてしまいます。 

## アプローチ

 強引なアプローチは、可能なすべての色付けを試すことです。 各ポジションには 2 つの選択肢があるため、$2^n$着色料。 色分けごとに、ソートされた文字列が到達可能かどうかを確認できます。 たとえ$n=200$、$2^{200}$天文学的に大きいので、これは不可能です。 

より良いものを見つけるには、スワップ操作で実際に何が可能になるかを理解する必要があります。 

2 つの位置を想定します$i<j$同じ色を持っています。 許可されたすべての交換は異なる色間で行われるため、相対的な順序は決して変更されません。 その結果、各カラー クラス内で、文字のサブシーケンスは元の順序を永久に維持する必要があります。 

ここで反転を見てみましょう: 位置$i<j$と$s_i>s_j$。 

最終的にソートされた文字列では、これら 2 つの文字が逆の順序で出現する必要があります。 同じ色の位置は相対的な順序を決して逆転できないため、各反転の終点は異なる色を受け取る必要があります。 

この観察は問題を完全に特徴づけています。 文字列の位置を頂点とするグラフを作成します。 2 つの位置が反転を形成する場合は接続します。 すべてのエッジでは、その端点が異なる色を持つ必要があります。 

問題は、反転グラフを 2 色で着色できるかということです。 

これはまさに 2 部グラフの定義です。 

グラフが 2 部構成の場合、2 部構成により有効な色が付けられます。 2 部構成でない場合は、何らかの奇妙なサイクルによって矛盾する色の要件が強制され、解決策は存在しません。 

簡易バージョンは、反転グラフ全体を手頃な価格で構築できるように設計されています。 あるのは$200$位置なので、すべてのペアをチェックするには時間がかかります$O(n^2)$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(2^n)$|$O(n)$| 遅すぎる |
 | 最適 |$O(n^2)$|$O(n^2)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 文字列の位置ごとに 1 つの頂点を持つグラフを作成します。 
2. インデックスのペアごとに$i<j$、どうかを確認してください$s_i>s_j$。 
3. 反転が存在する場合は、間に無向エッジを追加します。$i$そして$j$。 

このエッジは、2 つの位置が異なる色を受け取る必要があり、そうでないと順序を修正できないことを意味します。 
4. DFS または BFS を使用して、標準の 2 部構成チェックを実行します。 
5. エッジをトラバースするときは常に、隣接する頂点に反対の色を割り当てます。 
6. 端点がすでに同じ色を持つエッジに遭遇した場合、グラフは 2 部ではありません。 印刷する`"NO"`。 
7. すべての接続されたコンポーネントが正常に色付けされたら、印刷します。`"YES"`割り当てられた色をバイナリ文字列として出力します。 

### なぜ効果があるのか

 すべての反転は、最終的にソートされた順序で解決される必要があります。 色を共有する 2 つの位置は、その相対的な順序を永久に保持するため、すべての反転の終点は異なる色を持つ必要があります。 反転グラフはこれらの要件を正確に記録します。 

グラフが 2 部構成の場合、2 部構成に従って色を割り当てると、すべての反転制約が満たされます。 次に、各カラー クラスは、内部的に順序付けられたままのサブシーケンスを形成します。 すべての反転ペアは 2 つのカラー クラスにまたがっているため、問題のあるすべてのペアは、許可されたスワップによって並べ替えることができ、文字列を並べ替えられた順序に変換できます。 

グラフが 2 部構成でない場合、反転制約の一部のセットでは、位置が同時に両方の色になる必要があります。 有効な色が存在しません。 したがって、アルゴリズムは次の値を返します。`"YES"`まさに解決策が存在するとき。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
s = input().strip()

g = [[] for _ in range(n)]

for i in range(n):
    for j in range(i + 1, n):
        if s[i] > s[j]:
            g[i].append(j)
            g[j].append(i)

color = [-1] * n

def dfs(v, c):
    color[v] = c

    for to in g[v]:
        if color[to] == -1:
            if not dfs(to, c ^ 1):
                return False
        elif color[to] == c:
            return False

    return True

for i in range(n):
    if color[i] == -1:
        if not dfs(i, 0):
            print("NO")
            sys.exit()

print("YES")
print("".join(map(str, color)))
```最初のネストされたループは、反転グラフを構築します。 すべての位置のペアが 1 回だけ検査されます。 左側の文字が右側の文字より大きい場合は常に、それらの位置に反対の色を受け取る必要があるため、エッジを作成します。 

の`color`配列には 2 部構成のカラーリングが格納されます。 の値`-1`頂点がまだ訪問されていないことを意味します。 

DFS は、グラフの端に沿って交互に色を割り当てます。 すでに色付けされている隣接点が現在の頂点と同じ色を持っている場合、矛盾が見つかりました。 この時点でグラフは 2 部構成になっておらず、答えは次のようになります。`"NO"`。 

グラフには複数の接続されたコンポーネントがある場合があるため、未訪問の頂点が見つかるたびに、外側のループは新しい DFS を開始します。 

微妙な詳細の 1 つは、`c ^ 1`。 カラーのみなので、`0`そして`1`、それらの間で 1 つのフリップを使用した XOR がきれいに行われます。 

もう 1 つの詳細は、等しい文字ではエッジが作成されないことです。 厳密な反転のみが重要です。 同じ文字を含む位置は、ソートされた文字列内で相対的な順序を維持できるため、制約は必要ありません。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(n^2)$| 反転グラフの構築が実行時間に影響を及ぼします。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    n = int(input())
    s = input().strip()

    g = [[] for _ in range(n)]

    for i in range(n):
        for j in range(i + 1, n):
            if s[i] > s[j]:
                g[i].append(j)
                g[j].append(i)

    color = [-1] * n

    def dfs(v, c):
        color[v] = c
        for to in g[v]:
            if color[to] == -1:
                if not dfs(to, c ^ 1):
                    return False
            elif color[to] == c:
                return False
        return True

    for i in range(n):
        if color[i] == -1:
            if not dfs(i, 0):
                return "NO\n"

    return "YES\n" + "".join(map(str, color)) + "\n"

# provided sample
out = run("9\nabacbecfd\n")
assert out.startswith("YES\n")

# minimum size
assert run("1\na\n") == "YES\n0\n", "single character"

# already sorted
assert run("4\naaaa\n") == "YES\n0000\n", "all equal"

# impossible triangle
assert run("3\ncba\n") == "NO\n", "complete graph K3"

# simple inversion
out = run("2\nba\n")
assert out.startswith("YES\n"), "one inversion"

# maximum-style stress pattern
s = "".join(chr(ord('z') - (i % 26)) for i in range(200))
out = run(f"200\n{s}\n")
assert out.startswith("YES\n") or out == "NO\n"

 | --- | --- | --- |
 |`1 / a`|`YES`| 最小サイズ |

 |`3 / cba`|`NO`| 反転グラフの奇数サイクル |

 ## 特殊なケース

 ### 単一文字

 入力:```
1
a
```位置のペアは存在しないため、反転グラフには 1 つの孤立した頂点があります。

```すべての接続されたコンポーネントが独立して処理されるため、アルゴリズムは孤立した頂点を自然に処理します。 

### すべての文字が等しい

 入力:```
4
aaaa
```すべての比較で条件が満たされません`s[i] > s[j]`, したがって、エッジは追加されません。

アルゴリズムは次を出力します。```
YES

```等しい文字は反転を生じません。これはまさに私たちが望んでいることです。 

### 厳密に減少する文字列

 入力:```

```すべてのペアは反転です。

```三角形は二部構成ではありません。 DFS 中に、頂点 1 と 2 は同じ色を受け取りますが、頂点 1 と 2 の間にエッジが存在します。 競合はすぐに検出されます。
