 ## 解決策
 ## 問題の理解

 私たちには、一定の順序で立っているモンスターのシーケンスが与えられています。 各モンスターには一定の体力があり、左から右に順番に倒さなければなりません。 モンスターとの戦いはターン制です。まずあなたが攻撃し、次に相手が攻撃し、モンスターの体力がゼロ以下になるまで繰り返します。 

あなたの攻撃は常に一定量のダメージを与え、あなたの攻撃がモンスターを終わらせるたびに、そのモンスターに対して 1 ポイントを獲得します。 相手も自分のターンに固定ダメージを与えますが、得点には寄与しません。 面白いのは、すべての戦闘で限られた回数だけ相手のターンをキャンセルでき、キャンセルするたびに相手の攻撃が 1 回だけスキップされることです。 

目標は、あなたが個人的に終わらせるモンスターの数を最大化することです。これは、あなたの攻撃がモンスターの体力をゼロ以下にする攻撃の回数を最大化するのと同じです。 

制約は大きく、体力が 10^9 までのモンスターが 200,000 体までであり、スキップの数も多くなります。 これにより、ターンごとの各攻撃のシミュレーションが即座に除外されます。 完全な戦闘をシミュレートするモンスターごとのループでさえ、単純に実装すると遅すぎる可能性があります。これは、単一のモンスターに最大 10^9 / ターンが必要になる可能性があるためです。 

重要な問題は、相手の攻撃をスキップすることがグローバルなリソースであることです。 1 つのモンスターにスキップを使用すると、他のモンスターに必要なヒット数が変わるため、モンスター間でスキップを分散する方法を決定する必要があります。 

常に最大のモンスターに対してスキップを使用したいと仮定すると、単純な間違いが発生します。 たとえば、体力が非常に高いモンスターの場合は、何度スキップしても「ポイントに変換」することは不可能ですが、小型のモンスターの場合は、確実に最後の一撃を与えるために数回のスキップだけで済む場合があります。 スキップのメリットは、生の健康状態だけではなく、現在の交代パターンによって決まります。 

もう 1 つの微妙な失敗例は、貪欲な戦略が利用可能になるとすぐにスキップを使用する場合に発生します。 これにより、ポイントを確保するために必要のない初期のモンスターのスキップが無駄になり、わずかな調整で利益が得られたであろう後のモンスターのスキップが不十分になる可能性があります。 

## アプローチ

 各モンスターを直接シミュレートすると、モンスターが死ぬまでに「自分、次に対戦相手」のサイクルが何回必要になるかを計算できます。 特定のモンスターについては、スキップなしで、必要なヒット数は固定されていますが、対戦相手は必要なサイクル数を増やす追加のダメージターンを挿入する可能性があります。 対戦相手が行動するたびに k スキップを消費して、戦闘を段階的にシミュレートしてみることもできます。 

この強引なアイデアは、ルールを正確に反映しているため、正しいです。 ただし、体力が大幅に低下する可能性があります。体力が大きいモンスターの場合、何百万もの交互ターンが必要になる可能性があり、すべてのモンスターにわたってこれは許容範囲をはるかに超えています。 

重要な点は、各モンスターに、相手のターンを何回除去する必要があるかという「コスト」を割り当てることができるということです。そうすれば、相手が最終攻撃を効果的に遅らせる前に、キルを得ることができます。 ターンをシミュレートする代わりに、モンスターがあなたのターンで死亡することを保証するためにキャンセルしなければならない相手の攻撃の数をモンスターごとに計算します。 次に問題は、最大で合計 k 回のスキップを使用してコストを支払うことができるモンスターの最大数を選択することになります。

固定モンスターの場合、その体力がゼロになるまでに（自分の攻撃、相手の攻撃）のサイクルが何回発生するかを考慮します。 倒すのに必要な攻撃の回数を t とすると、通常のプロセスでは、敵は最後の攻撃を行うまでに t−1 回行動することになります。 あなたに最後の一撃を与えてほしい場合は、敵があなたのターンの調整を超えてキルを押し上げるクリティカルサイクルに干渉できないようにする必要があります。 これは、あなたのフィニッシュ攻撃までに相手が何回行動するかに応じて、スキップされる相手のターンの必要数に変換されます。 

したがって、各モンスターはコスト値に貢献し、殺害に成功するたびに 1 単位の報酬が貢献します。 総予算 k の範囲内で許容できるコストの数を最大化したいと考えています。 すべてのモンスターが同じ報酬を与えるため、これらのコストを昇順に並べ替え、できるだけ安価なものを選択することが最適です。そのため、常に安価な変換を最初に優先します。

 ## アルゴリズムのチュートリアル

 モンスターごとに、確実にポイントを獲得するために必要な対戦相手のスキップの最小数を計算します。 

1. モンスターごとに、必要なヒット数を計算します。`t = ceil(h / a)`。 これは、中断されなかった場合にそれを倒すために必要な攻撃の数です。 
2. 最後のヒットまでに、通常何ターンの敵ターンが発生するかを決定します。 標準的な交互パターンでは、相手は`t - 1`モンスターが死ぬ前に攻撃します。 
3. これをコストに変換します。戦闘が最終的な攻撃の調整を「オーバーシュート」しないようにするには、どれだけ多くの敵の攻撃を除去する必要があるかです。 導出されるコストは、`cost = max(0, t - 1)`。 

これは、各対戦相手のターンが攻撃シーケンスに比べてキルを効果的に遅らせ、敵を除去することでとどめの一撃を与えるまでの進行が加速されることを反映しています。 
4. すべてのコストを配列に収集します。 
5. 配列を昇順に並べ替えます。 
6. 分類されたコストを調べて、実行予算に累積します。 追加コストが k を超えないたびに、そのモンスターを取り出し、そのコストを k から引き、答えを 1 増やします。 
7. 次のコストを支払えない場合は終了します。 

### なぜ効果があるのか

 各モンスターは、選択された場合に正確に 1 ポイントを獲得し、スキップされた相手のターンに関して固定の独立したコストを必要とします。 このプロセスでは、すべての値が等しい単一のナップザック制約の下でできるだけ多くの項目を選択します。 このような場合、選択した高価なアイテムを選択されていない安価なアイテムに置き換えても、数を減らすことなく実現可能性を向上させることができるため、コストの高い順にアイテムを選択することが最適です。 この交換引数により、最適なソリューションを損失なく貪欲なソリューションに変換できることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, a, b, k = map(int, input().split())
    h = list(map(int, input().split()))
    
    costs = []
    
    for hp in h:
        t = (hp + a - 1) // a
        cost = t - 1
        costs.append(cost)
    
    costs.sort()
    
    ans = 0
    for c in costs:
        if c <= k:
            k -= c
            ans += 1
        else:
            break
    
    print(ans)

if __name__ == "__main__":
    solve()
```コードはまず、各モンスターを、除去する必要がある敵の妨害の数を表す単一のスカラー コストに減らします。 天井区分は、必要なヒット数を計算します。 1 を引くことで、最終的な攻撃位置までに何回敵ターンが発生したかがわかります。 

ソートにより、常に最初に最も安価なモンスターにスキップを費やすことができます。 次に、貪欲ループは単純な予算消費プロセスを実行します。 

微妙な実装ポイントは、整数の除算です。`(hp + a - 1) // a`浮動小数点エラーを回避し、上限を正しく計算します。 もう 1 つの詳細は、ターンを明示的にシミュレートしないことです。 すべてのダイナミクスはコスト式に圧縮されます。

 ## 特殊なケース

 最小限の単一モンスターのケースでは、選択肢間に競合がない場合でも、式が正しく減少することがわかります。 モンスター1体と十分なパワーがあれば、コストは0になり必ず取られます。 

ゼロスキップ シナリオにより、アルゴリズムがフリー変換を誤って想定することがないことが確認されます。 コストがゼロのモンスターのみがカウントされます。 

ヘルス値が非常に大きいケースでは、コストが大きくなる可能性があることが強調されますが、ソートと貪欲な選択により、オーバーフローやパフォーマンスの問題が生じることなく安全に処理されます。
