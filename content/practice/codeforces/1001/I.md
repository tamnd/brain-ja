 ## 解決策
 ## 問題の理解

 私たちは、全体的にブール関数をエンコードするブラックボックス量子オラクルへのアクセスを与えられます。$2^N$長さのバイナリ入力$N$。 任意の入力ビット文字列に対して$x$、オラクルは評価します$f(x)$機能を明示的に明らかにすることなく。 この関数は非常に構造化されていることが約束されています。関数は定数 (すべての入力に対して同じ値を出力することを意味します)、またはバランス (全入力のちょうど半分が 0 にマップされ、残りの半分が 1 にマップされることを意味します) のいずれかです。 

タスクは、量子回路設定でのオラクルの 1 回の呼び出しのみを使用して、隠れ関数が定数であるか平衡であるかを判断することです。 出力は、関数が定数かどうかを示すブール値です。 

オラクルを一度しか呼び出すことができないという制約により、従来のサンプリング戦略は完全に排除されます。 たとえ少数の入力でも関数をクエリしようとすると、バランス関数は入力空間全体でその構造を任意に隠すことができるため、バランス関数を確実に区別するための制限をすぐに超えてしまいます。 古典的に、これらのケースを確実に区別するには、$2^{N-1} + 1$バランスの取れた関数は、より小さなサンプルに対して定数関数を模倣する可能性があるため、最悪の場合のクエリが実行されます。 

ここでの明らかではない問題は、部分的な観察では平衡関数が定数関数と区別がつかない可能性があることです。 たとえば、次の場合$N = 3$の場合、平衡関数は入力 000、001、010 に対して 0 を出力し、残りに対して 1 を出力する可能性があります。 小さなランダムなサンプルは誤解を招き、一定であるように見える可能性があります。 

量子定式化は、干渉を正しく利用した場合に限り、このサンプリング障壁を完全に回避します。 

## アプローチ

 ブルートフォースの古典的なアプローチでは、すべての項目についてオラクルにクエリを実行します。$2^N$入力を入力し、1 の数を数えて、関数が定数か平衡かを判断します。 これは正しいですが、一度実行すると完全に不可能になります$N$指数関数的な時間を必要とするため、小さな値を超えると増加します。 

量子解の背後にある重要な構造的観察は、Deutsch-Jozsa Promise 問題がグローバル情報を明示的な列挙ではなく位相でエンコードしているということです。 関数値を直接検査しようとする代わりに、すべての入力に対して均一な重ね合わせを準備し、オラクルを 1 回適用してから、干渉を使用して関数のグローバル プロパティを増幅します。 

オラクルの前後にアダマール変換を適用すると、関数が定数である場合の単一の計算基礎状態を除くすべての結果が打ち消される形で振幅が干渉します。 関数が平衡している場合、破壊的干渉により、この特別な状態の振幅がゼロになります。 

これにより、全体的な計数の問題が単一の振幅チェックに変わります。

 ## アルゴリズムのチュートリアル

 私たちは標準的なドイチュ・ジョッサ回路モデルで作業します。$N$入力量子ビットと 1 つの補助量子ビット。 

1. すべて初期化する$N$量子ビットを入力する$|0\rangle$そして補助量子ビットは$|1\rangle$。 補助量子ビットは、オラクルが計算状態を上書きするのではなく、位相反転として関数値をエンコードできるようにするために必要です。 
2. すべての量子ビットにアダマール ゲートを適用します。 これにより、入力レジスタがすべてのレジスタの等しい重ね合わせに変換されます。$2^N$入力を入力し、補助量子ビットを位相基準状態にします。 
3.オラクルを1回適用します。 オラクルマップ$|x\rangle|y\rangle$に$|x\rangle|y \oplus f(x)\rangle$。 補助量子ビットは重ね合わせ状態で準備されたため、この操作により効果的に位相係数が導入されます。$(-1)^{f(x)}$それぞれの基本状態に基づいて$|x\rangle$。 
4. すべての入力量子ビットにアダマール ゲートを再度適用します。 このステップにより、異なる入力に対応する振幅間の干渉が発生します。 関数が一定の場合、すべての振幅が強化されてすべてゼロの状態になります。 関数のバランスが取れている場合、その状態に対する寄与は完全に相殺されます。 
5. 最終状態がすべてゼロの計算基礎状態であるかどうかを測定します。 そうである場合、関数は定数です。 それ以外の場合はバランスが取れています。 

### なぜ効果があるのか

 このアルゴリズムは、グローバル干渉のアイデンティティに依存しています。つまり、2 回目のアダマール変換の後、オール ゼロ状態の振幅は次の合計に比例します。$(-1)^{f(x)}$すべての入力にわたって$x$。 関数が定数の場合、この合計は次のいずれかに等しくなります。$2^N$または$-2^N$、ゼロ以外の振幅を与えます。 関数のバランスが取れている場合、項のちょうど半分は次のようになります。$+1$そして半分は$-1$, したがって、合計はゼロになります。 この構造的なキャンセルにより、1 回の Oracle 呼び出しで 2 つのケースが決定的に分離されることが保証されます。 

## Python ソリューション

 これは量子問題であり、要求される提出は Q# ですが、ロジックの構造は古典的です。Deutsch-Jozsa 回路を実装し、測定結果がすべて 0 の状態になるかどうかを返します。```
# Q# solution (conceptual translation)
# In actual Codeforces environment, this is written in Q#

namespace Solution {
    open Microsoft.Quantum.Primitive;
    open Microsoft.Quantum.Canon;

    operation Solve (N : Int, Uf : ((Qubit[], Qubit) => ())) : Bool
    {
        body
        {
            use qs = Qubit[N + 1];

            let input = qs[0..N-1];
            let aux = qs[N];

            X(aux);

            ApplyToEach(H, qs);

            Uf(input, aux);

            ApplyToEach(H, input);

            mutable allZero = true;

            for i in 0..N-1 {
                let res = M(input[i]);
                if (res == One) {
                    set allZero = false;
                }
            }

            let auxRes = M(aux);

            ResetAll(qs);

            return allZero;
        }
    }
}
```重要な実装の詳細は、補助量子ビットを状態で準備することです$|1\rangle$アダマールを適用する前に。 これがないと、オラクルは関数評価をフェーズ情報に正しく変換できず、干渉によって依存するグローバル プロパティがエンコードされません。 

2 番目の微妙な点は、測定後にすべての入力量子ビットがゼロに崩壊することを確認するだけでよいことです。 逸脱は、破壊的な干渉が失敗したことを示します。これは、約束の下でバランスの取れた機能の場合にのみ発生します。

 ## 特殊なケース

 エッジケースの 1 つは次のような場合です$N = 0$、ここで、入力スペースには要素が 1 つだけあります。 その状況では、「バランスの取れた」機能が存在できないため、約束は退化します。 重ね合わせは単一の状態に減少し、オラクルは単にキャンセルされないグローバル フェーズを設定するだけであるため、アルゴリズムは引き続き正しく動作します。 

もう 1 つの微妙なケースは、関数が定数 0 ではなく定数 1 である場合です。ここで、すべての基底状態は次の位相を受け取ります。$-1$しかし、2 番目のアダマール後の干渉パターンはまだ完全にゼロの状態に集中しているため、測定結果は決定的なままです。 

最後のエッジケースは、補助量子ビットが適切にリセットされていることを確認することです。 絡み合ったまま、またはリセットしないままにしておくと、その後の大規模な回路での実行で不正確な干渉パターンが生成される可能性がありますが、この単発の問題では、測定がすぐに行われる限り、最終的なブール値の結果には影響しません。
