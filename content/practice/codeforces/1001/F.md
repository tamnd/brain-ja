 ## 解決策
 ## 問題の理解

 量子ビットの配列が与えられていますが、重要な約束は量子フレーミングが示唆するよりも単純です。システムは 2 つの古典的な計算基底状態のいずれかにあることが保証されています。 各基底状態はブール配列で記述されます。`bits0`そして`bits1`、これらは 2 つの異なる長さのビット文字列に対応します。`N`。 

より具体的に言えば、量子ビットは任意の重ね合わせではありません。 レジスタ全体はすでにクリーンな古典的な構成になっており、次のいずれかに完全に等しいです。`bits0`または正確に等しい`bits1`。 タスクは、現在どれが存在するかを判断し、返すことです。`0`または`1`それに応じて。 

私たちが使用を許可されている唯一のツールは、提供された量子ビットの量子測定です。 一度測定されると、状態は崩壊しますが、必要なのは単一の決定だけであるため、それは無関係です。 

制約はプロンプトには明示的に示されていませんが、このタイプの典型的な対話型量子問題では、最大で大規模な制約が想定されます。`N`(多くの場合、テスト全体で 10^5 以上になります)。 これにより、二次関数や状態進化の繰り返しシミュレーションを伴うものは除外されます。 各量子ビットは最大 1 回検査できるため、有効なソリューションは量子ビットの数にわたって線形時間で動作する必要があります。 

微妙なエッジケースは次のような場合です`bits0`そして`bits1`1 つの位置だけが異なります。 その場合、その位置を確認せずに「早めに推測」しようとするソリューションは失敗する可能性があります。 たとえば、異なるインデックスが最後にあり、アルゴリズムが早期に停止する場合、等価であると誤って結論付けられる可能性があります。 

もう 1 つの特殊なケースは、測定が破壊的であることを忘れていることです。 ソリューションで量子ビットを測定し、後で非ローカルな方法で比較ロジックにそれらを再利用しようとすると、無効な状態で推論する危険性があります。 この問題では、測定を完全なビット文字列の 1 回限りの抽出として扱うことで、この問題を完全に回避します。 

## アプローチ

 強引な解釈は、すべての可能性をシミュレートするか構造を繰り返し照会して、量子状態について直接推論しようとすることです。 これは不必要なオーバーヘッドにつながり、概念的に問題の保証と一致しません。 この状態はすでに計算上の基礎状態であることが約束されているため、シミュレーションする分岐進化はありません。 これを一般的な量子識別問題として扱う試みは、指数関数的推論または少なくとも反復測定戦略に堕落することになりますが、これは不必要です。 

重要な観察は、計算ベースで各量子ビットを測定すると、隠されたビット列全体が即座に明らかになることです。 観察された文字列を取得したら、問題は単純な等価性チェックに帰着します。`bits0`そして`bits1`。 少なくとも 1 つの位置が異なるため、正確に 1 つの比較が一致します。 

これにより、タスクが「量子状態の識別」から「バイナリ配列の読み取りと比較」に減ります。

 ## アルゴリズムのチュートリアル

 1. 計算ベースで各量子ビットを測定し、結果の古典ビットを配列に格納します`obs`。 このステップでは、入力がすでに基底状態であることが保証されているため、隠れた古典状態を直接抽出します。 
2. 比較する`obs`と`bits0`。 すべての位置が一致していれば、状態は正確に`bits0`、だから戻ってください`0`。 正しさは、状態が指定された 2 つの文字列のいずれかである必要があるという約束から得られます。 
3.そうでない場合は、戻ります`1`、残っている唯一の可能性があるため、`bits1`。 という保証は、`bits0`そして`bits1`少なくとも 1 つの位置が異なっていれば、曖昧さがなくなります。 

### なぜ効果があるのか

 不変条件は、測定後、`obs`量子ビット レジスタの真の基礎となる計算基礎状態と同一です。 入力状態は正確にどちらかであることが保証されているため、`bits0`または正確に`bits1`、観察された文字列はそれらのいずれかに正確に一致する必要があります。 2 つの候補は異なるため、等価比較により、確率論的推論を必要とせずに正しい候補を一意に特定します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve(qs, bits0, bits1):
    obs = [False] * len(qs)
    
    for i in range(len(qs)):
        # In actual Q# this would be: M(qs[i])
        # Here we assume qs already encodes classical info in simulation form
        obs[i] = qs[i]
    
    if obs == bits0:
        return 0
    return 1
```この実装は、唯一の意味のある操作が各量子ビットから古典的な情報を抽出することであるという事実を反映しています。 実際の Q# 環境では、これは測定を適用することに相当します。`M`各量子ビット上で。 その後のロジックは純粋に古典的です。 

この問題では排他性が保証されているため、比較ステップは安全です。つまり、2 つのビット文字列のうちの 1 つが測定結果と正確に一致します。

## 複雑さの分析

 任意の位置で異なる 2 つの任意のビット列を区別するには、すべての量子ビットを少なくとも 1 回検査する必要があるため、線形複雑度は最適です。 これは、量子シミュレーションまたは測定問題の典型的な制約内に快適に適合します。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    
    # simple simulation wrapper
    data = list(map(int, sys.stdin.read().split()))
    n = data[0]
    bits0 = data[1:1+n]
    bits1 = data[1+n:1+2*n]
    qs = data[1+2*n:1+3*n]
    
    def solve(qs, bits0, bits1):
        return 0 if qs == bits0 else 1
    
    return str(solve(qs, bits0, bits1))

# sample-like cases
assert run("3 0 1 0 1 1 0 1 1 0") == "1"

# all equal to bits0
assert run("2 0 0 1 1 0 0") == "0"

# differs in last bit
assert run("4 0 0 0 0 0 0 0 1") == "1"

# single bit
assert run("1 0 1 1") == "1"
```| テスト入力 | 期待される出力 | 検証内容 |

 ## 特殊なケース

 エッジケースの 1 つは次のような場合です`bits0`そして`bits1`最後のインデックスのみが異なります。 測定は早期終了に依存しないため、アルゴリズムは引き続き機能します。 配列全体は常に比較前に読み取られるため、識別ビットがスキップされることはありません。 

もう一つのエッジケースは、`N = 1`。 ここで量子ビットは次のいずれかです`0`または`1`、両方の候補は単一ビット文字列です。 測定により 1 要素の配列が生成され、等価比較により曖昧さなく正しい状態が一意に識別されます。 

最後のエッジ ケースは、2 つのビット文字列が単一の共有プレフィックスを除いて補数である場合です。 このアルゴリズムは、違いがどこにあるのかには依存せず、文字列全体の同一性にのみ依存するため、位置の偏りが正確さに影響することはありません。
