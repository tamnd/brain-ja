 ## 解決策
 ## 問題の理解

 私たちは、長さの初期パターンを決定するプロセスを扱っています。$K$の決定論的な規則によって繰り返し拡張されます。$C$段階的に、非常に大規模な最終シーケンスを生成します。 最終的なシーケンス内の各位置は、最終的には元のパターン内の位置の小さなウィンドウに依存しますが、正確なマッピングはランダムではなく構造化されています。 

この拡張が完了した後は、検査のみが許可されます$S$最終シーケンス内の位置。 各検査では、完全に展開された構造から 1 つの特徴が明らかになります。 課題はそれらを選択することです$S$これにより、観察された文字から、特定の元の位置に特定の構成が含まれている必要があるかどうかを推測できます。 この問題群の古典的な解釈では、目的は、元のパターンに関する不確実性を一意に解決するのに十分なように、最終的に展開された文字列内の一連のインデックスを決定するか、または指定された数のチェックでは解決できないことを報告することです。 

最大の難点は、拡張が指数関数的に増大することです。$C$そのため、最終的な文字列を明示的に構築することは不可能になります。 すべての最終位置は、複数の元の位置からの混合寄与をエンコードします。このエンコードの構造により、多くの元のインデックスを 1 つのクエリに「圧縮」できます。 

制約の観点から見ると、重要な意味は次のとおりです。$K$二次関数や$O(KC)$完全な拡張のシミュレーションは不可能です。 唯一の実行可能な解決策は、展開ルールの構造に直接作用する必要があります。 以来$C$サイズも大きくなる可能性があるため、位置ごとにすべての展開レベルを反復するメソッドは、依然として線形を維持する必要があります。$K$最悪の場合。 

明らかではない失敗のケースは、クエリされた 1 つの位置に含まれる情報の量の誤解から生じます。 

最初のエッジケースが発生するのは次の場合です$S \cdot C < K$。 この状況では、許可されるチェックには元の位置をすべてカバーするのに十分な「自由度」がないため、答えは不可能です。 たとえば、次の場合$K = 5$、$C = 2$、 そして$S = 2$、少なくとも必要になります$\lceil 5/2 \rceil = 3$チェックするため、単純なアプローチでいくつかのインデックスを出力しようとしても、正しい出力は不可能です。 

2 番目のエッジ ケースは次の場合に発生します。$K = 1$。 最終的な文字列は、構造化された方法で繰り返された単一の元の位置にのみ依存するため、展開は簡単になります。 有効なソリューションは、次の条件に関係なく、ただちに 1 つのクエリを返す必要があります。$C$そして$S$。 不用意にグループ化すると、これが複雑になり、不要なインデックスや無効なインデックスが生成される可能性があります。 

## アプローチ

 この強引なアイデアは、拡張プロセスを明示的にシミュレートすることです。 元の長さの文字列から開始$K$、変換ルールを繰り返し適用します$C$最終的な文字列を構築するのに何回もかかります。 完全に展開されたシーケンスが構築されたら、考えられるすべてのセットを調べます。$S$位置を確認し、元の構成を一意に決定するかどうかを確認します。 

このアプローチはプロセスの定義に直接従うため、原理的には正しいです。 問題は規模だ。 拡張により長さが倍になる場合$K$各ステップで、最終的な文字列のサイズが決まります。$K^C$。 次のような中程度の値であっても、$K = 10$そして$C = 5$、これはすでに到達しています$10^5$、そしてより大きな制約はすぐに実行不可能になります。 考えられるすべてのクエリ セットを列挙すると、さらに組み合わせの爆発が追加されます。 

重要な構造的観察は、各最終位置が塩基をエンコードしていることです。$K$拡張ツリーを通るパス。 文字列の観点から考える代わりに、各最終インデックスを基底の数値として考えることができます。$K$ここで、各桁は 1 つの拡張レベルでの選択に対応します。 これは、クエリされた単一の位置が実際には圧縮されたビューを表すことを意味します。$C$オリジナルのインデックス。 

この構造のため、展開された文字列全体を探索する必要はありません。 各クエリは、最大のグループから情報を集約するように構築できます。$C$元の位置。 元のインデックスをサイズのブロックにグループ化することによって$C$、そして各ブロックを単一のベースにエンコードします。$K$の位置にある場合、のみを使用して元のシーケンス全体をカバーできます。$\lceil K / C \rceil$クエリ。 

したがって、最適な解決策は、拡張のシミュレーションではなく、これらのエンコードされたインデックスを直接構築することです。

 ## アルゴリズムのチュートリアル

 元のインデックスのブロックを基数の数値として扱うことにより、答えを構築します。$K$。 

1. 元のシーケンスの最初の位置から開始し、サイズごとに処理します。$C$。 各チャンクは、最終的な回答の 1 つのクエリに対応します。 
2. 各チャンクについて、その要素を基数の数字として解釈します。$K$番号。 チャンクの数が以下の場合$C$要素では、欠落している位置を中立の数字として扱います$0$。 このパディングにより、すべてのクエリが展開ツリー内の有効なパスに対応することが保証されます。 
3. 塩基を変換します。$K$最終的に展開された文字列内の 1 から始まるインデックスの位置に数値を挿入します。 これは、累積値に繰り返し乗算することによって行われます。$K$そして現在の数字を追加します。 
4. この計算された位置をクエリのリストに追加します。 
5.チャンク数を超えた場合$S$、元の位置をすべてカバーするのに十分な検査を行う余裕がないため、出力は不可能です。 

このグループ化が機能する理由は、展開パスがレベル​​間の選択肢の組み合わせをエンコードする方法を利用して、各クエリが複数の元のインデックスを単一のチェックに効果的に「バンドル」するためです。 

### なぜ効果があるのか

 拡張プロセスにより、完全な$K$-深さのアリーツリー$C$ここで、各リーフは最終位置に対応します。 すべての葉は、次のシーケンスによって一意に識別されます。$C$それぞれの範囲内の選択肢$[0, K-1]$。 したがって、単一のクエリは、複数の元の位置をこのシーケンスに埋め込むことによってエンコードするリーフを選択するものとして解釈できます。 このエンコーディングでは、元の各位置を正確に 1 桁の位置にマッピングできるため、それらをグループ化しても情報が失われることはありません。 構築されたインデックスにより、すべての元の位置が少なくとも 1 つのクエリ結果に影響を与え、区別性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    K, C, S = map(int, input().split())

    # Minimum number of checks needed
    need = (K + C - 1) // C
    if S < need:
        print("IMPOSSIBLE")
        return

    res = []
    idx = 0

    while idx < K:
        val = 0
        for i in range(C):
            pos = min(idx, K - 1)
            val = val * K + pos
            idx += 1
        res.append(val + 1)

    print(*res)

if __name__ == "__main__":
    solve()
```実装はグループ化戦略に直接従います。 変数`idx`次にエンコードしている元の位置を追跡します。 各クエリは、最大で累積して構築されます。`C`ベースに配置します-$K$に保存されている番号`val`。 乗算`K`加算しながら前の数字をシフトします`pos`次の数字を追加します。 

を使用した減算なしの境界の処理`min(idx, K - 1)`不完全な最終グループに最後の有効なインデックスが安全に埋め込まれるようにします。 これにより、パディングはエンコード スキームの識別性に影響を与えないため、正確さを維持しながら範囲外の動作が回避されます。 

決勝戦`+1`内部で使用されるゼロベースのインデックス付けから、必要な 1 ベースの出力形式に変換します。 

## 実用的な例

 ## 特殊なケース

 のために$K = 1$の場合、アルゴリズムはただちに 1 つのクエリを生成します。 ループは 1 回実行され、長さの 1 桁のシーケンスをエンコードします。$C$ただし、すべての桁が事実上ゼロであるため、出力は位置に折りたたまれます。$1$。 すべてのパスが同じ元のインデックスに収束するため、展開構造は重要ではありません。
