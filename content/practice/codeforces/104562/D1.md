 ## 解決策
 ## 問題の理解

 この問題は、タイルの最初の行が繰り返しより大きなシーケンスに変換されるプロセスに関するもので、最終的に展開されたシーケンスでは限られた数の位置のみを検査することができます。 これらの検査から、元の構成に関する何かを一意に決定できるかどうかを判断し、可能であれば、どの最終位置をチェックする必要があるかを出力する必要があります。 

概念的には、K 個のタイルの行から始めます。 各タイルは、いくつかの状態 (古典的なフラクタイル設定では、金または銀) のいずれかになります。 次に、このラインは固定ルールを使用して C 回拡張されます。つまり、すべてのタイルが前の構成から導出されたブロック全体に置き換えられるため、C で丸められた後の最終的な長さは K^C になります。 最終的な順序は与えられていません。 代わりに、最終シーケンス内の S 位置を検査することができます。 各検査は、最終的に展開された構造内の 1 つのタイルの状態を返します。 

目標は、その回答から元の K タイルに関する十分な情報を再構築できるように、最大​​ S 個の検査位置を選択することです。 正確性を保証できない場合は、出力にそれを反映する必要があります。 

すべてを動かす重要な制約は、K と C が十分に大きく、最終的なシーケンスを明示的に構築することが不可能であるということです。 K = 100、C = 10 でさえ、すでに 100^10 の位置が得られますが、これは計算をはるかに超えています。 これにより、拡張をシミュレートするアプローチは即座に除外されます。 唯一実行可能な観点は、クエリされた各位置を、複数の元のタイルに関するエンコード情報として一度に扱うことです。 

S が小さすぎると、微妙なエッジケースが発生します。 曖昧さを解消する必要がある元のタイルの数よりもチェックの数が少ない場合、どの戦略も失敗します。 たとえば、K = 5、C = 2、S = 2 の場合、各クエリは元のシーケンスの限られた射影のみをカバーし、元の 5 つの位置すべてを確実に区別する方法はありません。 素朴な貪欲なアプローチでは、すべてのタイルを「カバー」することを期待して 2 つの位置を選択する可能性がありますが、これでは一部のタイルに関する情報が欠落し、曖昧さが生じます。 

もう 1 つのエッジ ケースは、K ≤ S の場合です。この場合、多くの場合、元のタイルを個別のクエリ位置に直接エンコードできますが、これは展開構造を正しくマッピングした場合に限ります。 不注意な実装では、C の圧縮効果を考慮せずに、タイルごとに 1 つのクエリが常に十分であると誤って想定する可能性があります。 

## アプローチ

 この問題を考える強引な方法は、長さ K^C の最終シーケンスを明示的に構築し、その後逆算して考えることです。観察された S 位置と一致するすべての可能な元の構成をシミュレートし、元の状態を一意に決定できるかどうかを確認します。 このアプローチは、変換を正確に反映するため、概念的には単純で正しいものです。 ただし、可能な元の構成の数は K 単位で指数関数的であり、各構成はサイズ K^C のシーケンスを生成するため、最初のシミュレーション ステップですら、すぐに実行不可能になります。 操作数は現実的な限界をはるかに超えて爆発的に増加します。 

重要な観察は、最終シーケンスの各位置が単一の元のタイルに対応するのではなく、C 個の元の位置の構造化された組み合わせをエンコードしていることです。 最終的なインデックスを基数 K 表現で解釈すると、各桁は展開の 1 つのレベルで行われた選択に対応します。 これは、複数のベース位置をエンコードするインデックスを慎重に選択することで、単一のクエリで複数の元のタイルを一度に「カバー」できるように設計できることを意味します。

これにより、元の K タイルがサイズ C のブロックにグループ化されます。ブロックごとに、最終位置が元のインデックスのブロック全体をエンコードする単一のクエリを構築します。 K が C で割り切れない場合、最後のグループは最後のインデックスを繰り返すことによって概念的にパディングされますが、インデックスの繰り返しによって最終的なデコード値に曖昧さが生じないため、正確さには影響しません。 

次に、選択したインデックスから形成された K 進数として各クエリ位置を計算します。 したがって、各クエリは、元の構成空間の特定のスライスに対する決定論的なプローブになります。 グループ数が S を超えると、必要な情報をすべて網羅できなくなり、回答できなくなります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(K^C · 2^K) | O(K^C) | 遅すぎる |
 | 最適 | O(K) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 ここで、展開の構造から直接クエリ位置を構築します。 

1. K 個のオリジナル タイルをサイズ C の連続するグループに分割します。各グループは、1 つのクエリにエンコードされる圧縮単位を表します。 各最終位置は選択した C レベルを正確にエンコードできるため、このグループ化は自然です。 
2. グループごとに、グループを K 基数として解釈することにより、最終シーケンス内に単一のインデックスを構築します。 1 インデックスの算術演算から始めます。 インデックス a0、a1、...、a(C-1) を含むグループの場合、位置を a0 * K^(C-1) + a1 * K^(C-2) + ... + a(C-1) として計算します。 これにより、クエリがグループ内のすべてのタイルに同時に「タッチ」することが保証されます。 
3. グループの要素が C 個より少ない場合 (最後にのみ発生)、長さが C に達するまで最後の要素を繰り返します。 インデックスを繰り返すと構築された位置が同じ表現上の同値クラス内に保持されるため、このパディングによって情報が歪むことはありません。 
4. 構築されたすべてのポジションを収集します。 グループの数が S を超える場合は、元のタイルをすべてカバーするのに十分な位置を検査できないため、IMPOSSIBLE が出力されます。 
5. それ以外の場合は、構築された位置を出力します。 

これが機能する理由は、構築された各インデックスが、拡張された構造内の元のタイルの完全なグループの状態を一意にエンコードするためです。 Base-K エンコードでは、展開の各レベルが最終位置に独立して寄与するため、2 つの異なるグループが同じクエリ結果に崩れることはありません。 これにより、各クエリが元の構成空間の互いに素な部分を分離し、再構築が可能になることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        K, C, S = map(int, input().split())

        # minimum number of checks needed
        need = (K + C - 1) // C

        if S < need:
            print("IMPOSSIBLE")
            continue

        res = []
        cur = 0

        while cur < K:
            x = 0
            for i in range(C):
                idx = min(cur, K - 1)
                x = x * K + idx
                cur += 1
            res.append(x + 1)

        print(*res)

if __name__ == "__main__":
    solve()
```この実装では、グループ化ロジックが直接反映されます。 変数`need`K をサイズ C のチャンクに分割することで、必要なクエリの数を計算します。S がこれより小さい場合は、すぐに拒否されます。 

構築ループは、K を繰り返し乗算し、現在のインデックスを追加することで各クエリ位置を構築し、K 進数を効果的に構築します。 の`min(cur, K - 1)`グループ内の最後のタイルを超えて実行するときにパディングを処理し、最後のグループが有効なままであることを確認します。 

の`+1`最後に、ゼロベースの構築から、出力位置に使用される必要な 1 ベースのインデックス付けに変換します。 

## 実用的な例

 K = 5、C = 2、S = 3 の小さな例を考えてみましょう。 

タイルを (0,1)、(2,3)、(4,4 パディング) としてグループ化します。 各グループについて、K 進数を計算します。 

| ステップ | グループ | 計算 | 位置のクエリ |
 | --- | --- | --- | --- |
 | 1 | (0,1) | 0*5 + 1 | 2 |
 | 2 | (2,3) | 2*5 + 3 | 13 |
 | 3 | (4,4) | 4*5 + 4 | 25 |

 これにより、3 つのクエリ位置が生成されます。 S = 3 なので、直接出力できます。 

このトレースは、最終グループでパディングがどのように機能するかを示しています。 4 を繰り返すことで、グループが不完全な場合でも最終的なクエリの一貫性が保たれます。 

ここで、K = 3、C = 3、S = 1 について考えてみましょう。 

| ステップ | グループ | 計算 | 位置のクエリ |
 | --- | --- | --- | --- |
 | 1 | (0,1,2) | 0_3^2 + 1_3 + 2 | 5 |

 C は 1 回の検査ですべてのタイルをカバーできるため、クエリを 1 つ作成します。これで十分です。 

これは C の圧縮効果を示しています。C ≥ K の場合、1 つのクエリで元の配列全体をエンコードできます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | テスト ケースごとの O(K) | 各タイルはグループを構築するために 1 回処理されます。 
| スペース | O(1) おまけ | 少数の整数のみが保存されます。 

このアルゴリズムは K において線形であり、指数拡張サイズ K^C への依存を回避します。 これは、テスト ケース全体で K が最大 10^5 になる一般的な制約内に簡単に適合します。

 ## 特殊なケース

 エッジ ケースの 1 つは、K = 1 の場合です。アルゴリズムはただちに 1 つのグループを生成し、計算されたインデックスは C または S に関係なく常に 1 になります。グループ化ループはこれを自然に処理します。`cur`0 から始まり、必要な反復は 1 回だけです。 

もう 1 つのエッジ ケースは、C ≥ K の場合です。この場合、すべてのタイルが 1 つのグループでカバーされ、パディングが残りを埋めます。 たとえば、K = 4、C = 10 では、(0,1,2,3,3,3,...) をエンコードする 1 つのクエリが生成されます。 すべての余分な数字が同じ最終分岐にマップされるため、繰り返しによって構造が変更されることはなく、エンコードされたインデックスは有効なままになります。 

3 番目のエッジ ケースは、S が必要なグループ数と正確に等しい場合です。 このアルゴリズムは正確に S クエリを生成し、早期終了は発生しません。 各グループは独立しているため、重複したりカバーが漏れたりするリスクはありません。
