 ## 解決策
 ## 問題の理解

 一連の整数が与えられます。各整数は 10 進数形式で書かれ、先頭にゼロが含まれる場合があります。 すべての数字について、使用する前にその桁を自由に並べ替えることができます。 各数値の桁の順列を選択した後、結果の整数をシーケンスとして扱い、厳密に増加する部分シーケンスの長さを最大化したいと考えます。 

重要な難点は、各要素が固定されていないことです。 静的配列の代わりに、各位置は可能な値のセット全体、つまりその桁のすべての順列を表します。 タスクは、結果のシーケンスが可能な限り長く厳密に増加するサブシーケンスになるように、位置ごとに 1 つの値を選択することです。 

最大約 10^5 の数値がある場合、n への 2 次または 3 次依存性は直ちに遅すぎます。 定数によっては O(n^2) でもすでに厳しい場合がありますが、ここでは桁操作も考慮する必要があります。 各数値は最大約 18 桁になる可能性があるため、各遷移に対して単純に桁の順列を再計算するソリューションは高価になりすぎます。 

数値に繰り返しの数字や先頭のゼロが含まれる場合、微妙な特殊なケースが発生します。 

たとえば、入力番号 102 と 210 を考えてみましょう。これらを固定値として貪欲に解釈すると、それらを 102 と 210 として扱い、特定の LIS を与える可能性があります。 しかし、順序を変更すると、解釈によっては 102 が 120 または 201 になり、210 が 012、021、102、120、201 になる可能性があり、順序関係が大幅に変わります。 元の値に対する単純な LIS は、許可された変換を無視するため、正しくありません。 

別の障害モードは、1 つのステップに対して局所的に最適な桁配置が将来のより良い拡張を妨げる場合に発生します。 たとえば、数値に対して可能な限り最小の順列を選択すると、たとえわずかに大きい順列が有益であっても、後でより長いサブシーケンスを拡張するには小さすぎる可能性があります。 

## アプローチ

 ブルート フォース戦略では、各数値のすべての桁の並べ替えを試み、結果の配列に対して LIS を実行します。 これは、完全なソリューション空間を探索するため、原則として正しいです。 ただし、数字が B 桁の場合は、B までです。 これは B = 10 の場合でも実現不可能です。たとえ数字の繰り返しによる重複を減らしたとしても、カウントは指数関数的なままです。 各候補シーケンスを生成した後の LIS の計算は O(n log n) ですが、シーケンスの数が完全に支配します。 

順列を明示的に列挙することは避ける必要があります。 重要な観察は、実際には、考えられるすべての順列を保存する必要がないということです。 LIS の場合、標準の貪欲 DP 状態は、すべての情報をサブシーケンス長ごとに可能な限り最適な「最後の値」に圧縮します。 これは、長さ j の増加するサブシーケンスの可能な最小の最後の値である dp[j] を維持することを示唆しています。 

課題は遷移の計算です。現在のしきい値 dp[j] が与えられた場合、厳密に dp[j] より大きい次の数値の桁の可能な最小の順列を知る必要があります。 これは、組み合わせ検索ではなく、数字に関する制約付きの構築問題です。 

順列を生成する代わりに、利用可能な桁を使用して、指定された下限より大きい最小数を構築します。 左から右に桁ごとに下限を照合しようとします。 各位置で同じ数字を照合するか、照合できない最初の位置に必要な数字よりも厳密に大きい利用可能な最小の数字を配置し、残りの位置を可能な限り小さい数字で埋めます。 

これにより、桁の並べ替えの問題が、桁数が線形となる貪欲な辞書編集構造に変わります。 

これを長さにわたる LIS DP と組み合わせ、数値ごとにすべての可能なサブシーケンス長 j を試し、それに応じて dp を更新します。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 順列 + LIS に対するブルート フォース | O(n · B! · n log n) | O(n) | 遅すぎる |
 | LIS 上の DP + 貪欲な数字の構築 | O(n^2・B) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 動的プログラミング配列 dp を維持します。ここで、 dp[j] は、長さ j の増加するサブシーケンスの最後の要素となり得る最小の整数値 (文字列または同等の数値表現として) を表します。 

数値を左から右に処理します。 

1. 現在の数値について、その桁を抽出して並べ替えます。 並べ替えると、利用可能な数字の複数セットのビューが得られます。数字は自由に並べ替えることができるため、重要なのはそれだけです。 
2. 現在の最大値から 0 までの可能なサブシーケンスの長さ j ごとに、dp[j] で終わるサブシーケンスの拡張を試みます。 この逆の順序は、この反復でまだ使用する必要がある状態の上書きを避けるために重要です。 
3. 固定 dp[j] の場合、厳密に dp[j] より大きい、現在の桁の可能な最小の順列を構築します。 これは貪欲に行われます。 dp[j] を使用して桁ごとに比較し、できるだけ長く一致するように努めます。 これ以上一致できない位置に達したら、dp[j] の対応する桁より大きい最小の桁を選択し、残りを残りの桁で昇順に埋めます。 
4. dp[j] より大きい有効な順列がない場合、この j をスキップします。 それ以外の場合は、候補値を取得し、その長さに対して可能な最小の最後の値を維持しながら、それを使用して dp[j + 1] を更新しようとします。 
5. 現在の番号のすべての j を処理した後、次の番号に進みます。 

答えは、dp[j] が定義される最大の j です。 

機能する理由: dp 配列は、以前のすべての選択をサブシーケンスの長さごとに最適な代表値に圧縮します。 各長さについて、最後の値が大きくなると将来の拡張の可能性が減少するだけであるため、可能な限り最小の最後の値のみが重要になります。 貪欲な数字の構築は、固定の複数セットの数字を使用して、指定された境界よりも厳密に大きい辞書編集上の最小の数を生成するため最適です。これは、有効な順列の中で数値を最小化することに正確に対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = "9" * 50

def build_next_greater(digits, limit):
    """
    digits: sorted list of characters
    limit: string or INF-like upper bound constraint
    returns smallest permutation > limit or None
    """
    n = len(digits)
    used = [False] * n
    res = []

    def backtrack(pos, tight_equal):
        if pos == n:
            return "".join(res)

        if not tight_equal:
            # fill remaining with smallest
            for i in range(n):
                if not used[i]:
                    res.append(digits[i])
            return "".join(res)

        cur_digit = limit[pos] if pos < len(limit) else "0"

        prev = None
        for i in range(n):
            if used[i]:
                continue
            d = digits[i]

            if prev == d:
                continue
            prev = d

            if d < cur_digit:
                continue

            used[i] = True
            res.append(d)

            if d == cur_digit:
                ans = backtrack(pos + 1, True)
            else:
                # strictly greater at this position
                remaining = [digits[k] for k in range(n) if not used[k]]
                res.extend(sorted(remaining))
                ans = "".join(res)
                for _ in range(len(remaining)):
                    res.pop()
                used[i] = False
                return ans

            if ans is not None:
                return ans

            res.pop()
            used[i] = False

        return None

    return backtrack(0, True)

def solve():
    n = int(input())
    arr = input().split()

    dp = [""] + [None] * n
    best = 0

    for s in arr:
        digits = sorted(s)

        new_dp = dp[:]

        for j in range(best, -1, -1):
            if dp[j] is None:
                continue

            cand = build_next_greater(digits, dp[j])
            if cand is None:
                continue

            if new_dp[j + 1] is None or cand < new_dp[j + 1]:
                new_dp[j + 1] = cand
                best = max(best, j + 1)

        dp = new_dp

    print(best)

if __name__ == "__main__":
    solve()
```コアの実装は、dp の維持と、サブシーケンスの長さごとに遷移を繰り返し試行することを中心に展開します。 j に対する逆ループは、新しく作成された状態が同じ反復で再利用されるのを防ぐことで正確さを保証します。 文字列の比較が機能するのは、構築されたすべての候補が等しい長さの正規化された数字の並べ替えであるため、辞書編集上の順序が数値の順序と一致するためです。 

桁構築機能は最もデリケートな部分です。 これは、マルチセットを使用して制約付きの辞書編集の後続構築を効果的に実行し、厳密に境界を超える最小の有効な数値を常に取得できるようにします。 

## 実用的な例

 3 つの数値 (12、21、103) を入力するとします。 

サブシーケンスの長さにわたって dp を追跡します。 

12 の場合、桁は [1,2] になります。 dp[0] から 12 を形成できます。したがって、dp[1] は 12 になります。 

| ステップ | 番号 | dp[0] | dp[1] | アクション |
 | --- | --- | --- | --- | --- |
 | 1 | 12 | "" | 12 | サブシーケンスの開始 |

 21 の場合、桁は再び [1,2] になります。 dp[1] = 12 から、より大きい 21 を形成できるため、dp[2] は 21 になります。 

| ステップ | 番号 | dp[1] | dp[2] | アクション |
 | --- | --- | --- | --- | --- |
 | 2 | 21 | 12 | 21 | 長さ 2 まで延長 |

 103 の場合、数字は [0,1,3] です。 dp[1] = 12 からは、dp[2] を改善する長さ 2 への拡張に意味のある方法で 12 を超える 3 桁の数値を形成することはできませんが、dp[0] からは 103 を形成できるため、dp[1] は有効なままで、dp[1] は表現に応じて更新される可能性がありますが、dp[2] は 21 のままです。 

これは、以前の最適なサブシーケンスが保存され、新しい数値は有益な場合にのみ拡張されることを示しています。 

ここで、桁の再配置を強調したケース (102、90) を考えてみましょう。 

102、数字 [0,1,2] の場合、最も使用可能な形式には 102、120、201 が含まれます。 dp に応じて最小限の有効な遷移を選択します。 

| ステップ | 番号 | dp[0] | dp[1] | dp[2] | アクション |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 102 | "" | 102 | - | 開始 |
 | 2 | 90 | "" | 90 | - | 102 | を拡張できません

 これは、数字の置換によって LIS 拡張の実現可能性がどのように変化するかを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n^2・B) | n 個の数値のそれぞれについて、最大 n 個の DP 状態を試行し、O(B) | の桁順列を構築します。 
| スペース | O(n) | 各長さの最適なエンドポイントを格納する DP 配列 |

 この制約は、桁処理用の小さな定数 B を使用した n 上の 2 次 DP と互換性があります。 B は整数の桁数によって制限されているため、内部作業は管理可能なままです。

 ## 特殊なケース

 7 のような単一の数値の場合、dp は dp[0] = 空から始まります。 唯一の遷移では dp[1] = 7 が生成されるため、答えは 1 になります。どの順列も同一であるため、曖昧さは生じません。 

999 のように繰り返される数字の場合、すべての順列は同じ値になります。 厳密に増加する遷移が存在しないため、dp 更新は長さ 1 を超えて改善されることはありません。 

10、01、001 などの数値の場合、桁の並べ替えは先行ゼロの解釈に応じてすべて 1 または 10 のような値に集約されますが、アルゴリズムは文字列比較を通じてそれらを一貫して扱い、有効な厳密に増加する遷移のみが受け入れられます。 

102、201、120、210 のような完全に柔軟なチェーンの場合、拡張をサポートするためにすべての数値を再配置することができ、厳密な増加を維持する順列を慎重に選択することで、DP が長く増加するサブシーケンスを蓄積できるようになります。
