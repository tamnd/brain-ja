 ## 解決策
 ## 問題の理解

 円形の「パスワード ロック」上の位置を表す整数のコレクションとモジュラス値が与えられます。$k$。 タスクは、指定されたすべての数値を 1 つのシーケンスに並べ替えて、そのシーケンス内の隣接する要素を確認するときに、モジュロの下で隣接するペアが「悪い相互作用」を生じないようにすることです。$k$。 問題の構造から、各数値で重要なのは、次の値で割ったときの余りだけであることがわかります。$k$。 

2 つの隣接する値が問題になるのは、それらの剰余が合計で次のような相補的なペアを形成する場合です。$k$、または両方の剰余が係数を中心とした特殊な対称ケースである場合。 言い換えれば、剰余は、禁止された隣接関係が現れないように調整する必要がある型のように動作します。 

出力は、これらの隣接制約を満たす入力値の有効な並べ替え、またはそのような配置は存在しないというステートメントのいずれかです。 

元の値が大きくても、剰余を法とした頻度分布だけが得られます。$k$重要です。 これにより、生の整数の処理から、サイズの周波数配列の処理に問題が軽減されます。$k$、これが重要な構造の簡素化です。 

この制約は、解が要素数に加えてほぼ線形の時間で動作する必要があることを意味します。$k$。 すべての並べ替えに対する総当りの順列チェックは不可能です。$n$、順列の数は階乗的に増加します。 すべての配置をシミュレートしたり、リストに対して繰り返し並べ替え操作を実行したりするソリューションは失敗します。 

モジュロ対称の構造から、いくつかのエッジケースがすぐに現れます。 

特殊なケースの 1 つは、異なる剰余が 2 つだけ存在し、それらが相補的である場合です。 たとえば、すべての数値が次のように一致する場合、$1$または$k-1$の場合、すべての隣接関係が無効になる可能性があり、隣接関係を区切る 3 番目の残りが存在しません。 このような場合、たとえカウントのバランスが取れていたとしても、それらを安全にインターリーブする方法はありません。 

残りの場合、別のエッジケースが表示されます$0$大量に存在する。 以来$0 + 0$で割り切れます$k$、2 つのゼロを隣接して配置することは禁止されているため、ゼロは他の剰余で区切る必要があります。 

同様に、$k$偶数、余り$k/2$は自己補完的であるため、2 つの出現が隣接することはできません。 このような要素が多すぎると、それらを分離することができなくなります。 

微妙な失敗例は、両方の剰余が存在する場合に発生します。$x$とその補足$k-x$大きなブロックで存在します。 剰余を単純にソートされた順序で配置すると、注意深いインターリーブによって有効な再配置が存在する場合でも、剰余が隣接して禁断の合計を作成する可能性があります。 

## アプローチ

 直接的なアプローチは、これを順列生成問題として扱うことです。 配列の可能な順序をすべて構築して、隣接条件を満たすものがあるかどうかを確認することもできます。 これは、検索空間全体を探索するため、原理的には正しいですが、順列の数が膨大になるため、すぐに使用できなくなります。$n!$、これは実行可能な計算をはるかに超えて成長します。$n = 20$。 

重要な観察は、隣接性制約がモジュロの剰余のみに依存するということです。$k$、実際の値ではありません。 要素を剰余ごとにグループ化すると、個別の番号を配置するのではなく、同じタイプのバケットを配置することになります。 

要素を剰余でソートし、その順序で配置しようとすると、非相補的な剰余は干渉しないため、ほとんどの隣接する競合は自動的に解消されます。 残りの競合は 3 つの特定の状況からのみ発生します。ゼロ、中間点の剰余です。$k$偶数であり、相補的なペア$x$そして$k-x$。 

これらの対立の構造は、探索ではなく構築アプローチを示唆しています。 まず「通常の」剰余に焦点を当て、それらを昇順に並べてみます。 これは、相補的なペアが隣接する場合を除いて機能します。 これを解決するために、シーケンス内の特別な剰余または境界要素が区切り文字として機能することを利用します。 

特別な残り$0$そして$k/2$これらは異なる補数と組み合わせることができないため、異なる動作をします。 相互間の隣接性違反を避けるために、それらは慎重に配布する必要があります。 

したがって、問題は、剰余ごとの頻度をカウントし、特殊でない剰余を制御された順序で配置し、隣接関係の衝突を回避する方法で特殊なケースを挿入することに帰着します。 このようなブロックは十分に分離できないため、実行可能条件は最終的には、自己相補的な剰余が全体サイズの半分を超えて現れるかどうかに帰着します。

 | 周波数ベースの構築 |$O(n + k)$|$O(k)$| 承認済み |

 ## アルゴリズムのチュートリアル

 残りの頻度のみについて推論し、問題のあるクラスを慎重にインターリーブすることで答えを構築します。 

1. 各剰余モジュロの周波数を計算します。$k$。 これにより、問題は順列問題ではなく周波数配置タスクに変換されます。 
2. 剰余を 3 つのカテゴリに分類します: 通常のペア$x$そして$k-x$、特別な剰余$0$、および特別な剰余$k/2$いつ$k$は均等です。 これらは隣接制約の下では異なる動作をするため、分離が必要です。 
3. まず、特殊でない剰余のみを昇順に使用して基本シーケンスを構築してみます。 アイデアは、各残りをブロックに配置することです。 これにより、相補的なペア間の潜在的な隣接競合を除いて、ほぼ有効な順序付けが得られます。 
4. ペアに出会ったとき$x$そして$k-x$、連続して配置しないようにしてください。 競合が発生した場合は、使用可能な区切り文字を挿入することに依存します。 セパレータは、それ自体が新しい禁止された隣接関係を導入しない、別のクラスの残りの部分である場合があります。 これが、恣意的な挿入を避け、境界または特殊な要素のみを使用する理由です。 
5.基本的な順序を構築した後、残りを処理します$0$。 ゼロが存在する場合は、それらを交互の位置に配置し、理想的にはシーケンスの先頭から開始します。 これにより、2 つのゼロが隣接しないことが保証されます。 使用可能な区切り文字と比較してゼロが多すぎる場合、構築は失敗します。 
6. もし$k$偶数なので余りを扱います$k/2$同じように交互に。 その数が安全に配置できる合計スロットの半分を超える場合は、有効な配置が存在しないと判断します。 
7. 最後に、すべての部分を単一のシーケンスにマージして戻します。 いずれかの時点で、隣接ルールに違反せずに要素を配置できない場合は、その配置は不可能であると返されます。 

構築全体を通して重要な不変条件は、すべてのステップで、禁止された隣接関係が出現しない部分シーケンスを維持し、新たな競合が発生しないことが保証された位置にのみ要素を挿入することです。 これにより、すべての制約が純粋にペアごとに行われるため、ローカルの安全性がグローバルな正確性を意味することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    freq = [0] * k
    for x in a:
        freq[x % k] += 1

    res = []

    used = [False] * k

    def add_block(r):
        while freq[r] > 0:
            res.append(r)
            freq[r] -= 1

    # handle pairs r and k-r
    for r in range(1, (k + 1) // 2):
        while freq[r] > 0:
            if freq[k - r] > 0:
                res.append(r)
                freq[r] -= 1
                res.append(k - r)
                freq[k - r] -= 1
            else:
                res.append(r)
                freq[r] -= 1

    # middle element when k even
    if k % 2 == 0:
        mid = k // 2
        if freq[mid] > (n + 1) // 2:
            print("NO")
            return

    # zeros check
    if freq[0] > (n + 1) // 2:
        print("NO")
        return

    # insert remaining zeros and mid carefully
    def interleave(value, count):
        i = 1
        for _ in range(count):
            if i >= len(res):
                res.append(value)
            else:
                res.insert(i, value)
                i += 2

    if freq[0]:
        interleave(0, freq[0])
        freq[0] = 0

    if k % 2 == 0 and freq[k // 2]:
        interleave(k // 2, freq[k // 2])
        freq[k // 2] = 0

    print("YES")
    print(" ".join(str(x) for x in res))

if __name__ == "__main__":
    solve()
```実際の値はモジュロクラスを超えて無関係であるため、解決策は入力を剰余周波数に圧縮することから始まります。 ペアリングループ$r$そして$k-r$両方が存在する場合は常に相補的な値を交互に配置することで、ほとんどの対称的な競合をすでに回避するベースライン順序を構築します。 

残りの実現可能性チェック$0$そして$k/2$自己相補的な値がシーケンスを支配するような不可能なインターリーブを試行しないようにしてください。 

インターリーブ機能は、これらの特別な値を構築されたバックボーン シーケンスの交互の位置に配置し、分離を維持します。 2 番目の位置ごとに挿入するという選択により、同じ問題のある残りが決して隣接しないことが保証されます。 

## 実用的な例

 ### 例 1

 仮定してください$n = 6$、$k = 5$、残りは次のとおりです。$$[1, 4, 1, 4, 2, 3]$$相補的なペアの構築を追跡します。 

| ステップ | アクション | シーケンス |
 | --- | --- | --- |
 | 1 | ペア 1 と 4 | 1、4 |
 | 2 | ペア 1 と 4 | 1、4、1、4 |
 | 3 | 残りの 2 と 3 を追加します | 1、4、1、4、2、3 |

 特別な剰余は存在しないため、シーケンスはすでに有効です。 

これは、自己相補的な剰余が優勢でない場合には、単純なペアリングで十分であることを示しています。 

### 例 2

 しましょう$n = 7$、$k = 4$、および剰余:$$[0, 0, 2, 2, 2, 1, 3]$$ここ$2$自己補完的であるため、$k/2 = 2$。 

| ステップ | アクション | シーケンス |
 | --- | --- | --- |

 | 3 | ゼロを交互に挿入 | 1、0、2、0、3、2 |

 これは、自己相補的な剰余をどのようにインターリーブする必要があるか、および交互に配置することで隣接性違反が回避される理由を示しています。

 ## 特殊なケース

 エッジケースの 1 つは、すべての数値が同じ余りを共有する場合です。 その残りが自己補完的な場合、次のようになります。$0$または$k/2$、すべての隣接が条件に違反するため、1 より大きいサイズの配置は直ちに失敗します。 このアルゴリズムは、周波数しきい値チェックを通じてこれを処理し、問題のある単一の剰余が配列の半分を超えるケースを拒否します。 

もう 1 つの特殊なケースは、2 つの相補的な剰余のみが存在する場合です。 例えば、$k=6$余りだけで$1$そして$5$。 構造ではそれらが交互になりますが、カウントが大幅に異なる場合は、一方が累積して隣接が強制されます。 ペアリング ループはこの不均衡を自然に明らかにし、実現可能条件によりセパレーターなしで片側が過剰に充填されるのを防ぎます。 

最後のエッジ ケースは、ゼロまたは中点要素が交互の配置がかろうじて収まるしきい値に正確にある場合に発生します。 インターリーブ関数はそれらを 2 つおきの位置に配置し、挿入をステップ実行すると、最後の要素が隣接関係を壊さずに有効なスロットを見つけていることが示され、実現可能性の境界で正確であることが確認されます。
