 ## 解決策
 ## 問題の理解

 最大 7 つの頂点を持つ非常に小さなグラフと、21 個のドミノからなる固定の「パレット」が与えられます。 各ドミノは 1 から 6 までの順序のない値のペアに対応するため、ドミノは実際には (1,1)、(1,2)、…、(6,6) のようなペアであり、各ペアのコピーが 1 つだけ利用可能です。 

これらのドミノのいくつかをグラフの端に配置したいと思います。 各エッジは最大 1 つのドミノを取ることができ、各ドミノ タイプは最大 1 回使用できます。 ドミノをエッジに配置するとき、ドミノの向きを設定します。つまり、エッジの 1 つの端点がドミノの一方の面を受け取り、もう一方の端点がもう一方の面を受け取ります。 

重要な制約は、頂点におけるローカルな一貫性です。頂点が複数のドミノの半分を受け取った場合、それらの半分はすべて同じ番号を示さなければなりません。 したがって、すべての頂点は事実上、すべてのインシデントに配置されたエッジによって強制される単一の「必須値」を持ちます。 

タスクは、グローバル制限 (各ドミノ タイプが 1 回使用される) と頂点の一貫性制約 (各頂点は、選択されたすべてのインシデント エッジのうち 1 つの数字のみを認識します) の両方を尊重しながら、ドミノを受け取るエッジの数を最大化することです。 

制約は非常に小さく、n ≤ 7、m ≤ 21 です。これは、頂点またはエッジを含む状態の指数関数的検索が実行可能であることを直ちに示唆しています。 分岐を制御し続ける限り、割り当てまたはサブセットの探索に依存する解決策はどれも妥当です。 

選択したサブグラフ内の複数のエッジに頂点が接している場合、微妙な失敗のケースが発生します。 たとえば、頂点が選択した 2 つのエッジに接続している場合、両方のエッジがその頂点に同じ番号を割り当てる必要があります。 エッジを独立して扱う単純なアプローチでは、異なる番号が誤って割り当てられ、実現可能性が損なわれる可能性があります。 

もう 1 つの明白ではない問題は、ドミノ タイプの再利用です。頂点制約が満たされていても、同じ順序なしペアを 2 回割り当てることはできません。 たとえば、向きが一貫している場合でも、2 つの異なるエッジで (1,2) を使用することは違法です。 

これら 2 つの制約、頂点の一貫性とグローバルなドミノの一意性は強く相互作用し、貪欲なエッジごとの割り当てを排除します。 

## アプローチ

 単純な試みとしては、エッジのサブセットを選択してから、ドミノを貪欲に割り当ててみることです。 各エッジに対して、すでに固定された頂点ラベルと一致する未使用のドミノを割り当てようとします。 問題は、グローバル割り当てが存在する場合でも、初期の貪欲な選択によって将来の割り当てがブロックされる可能性があることです。 各エッジは 2 つの頂点値に依存するため、ローカルな決定はサイクル内で制約を伝播し、貪欲な割り当ては基本的にすべての可能性を探索しないと効率的にバックトラックできません。 

最初に頂点ラベルの観点から考えると、構造は管理しやすくなります。 各頂点には 1 から 6 までの値が割り当てられます。これらのラベルが固定されると、すべてのエッジにエンドポイント値の決定されたペアが設定されるため、特定のドミノ タイプ (順序付けされていないペア) が必要になります。 さて、問題は次のとおりです。頂点のラベル付けが与えられた場合、有効で個別のドミノ要件を生成するエッジはいくつあるでしょうか?

 固定頂点ラベルの場合、必要なドミノ タイプがすべて異なるエッジを貪欲に選択できます。 タイプごとの「1 回使用」ルールに従って、利用可能なドミノ タイプに対応するエッジの数を単純に数えます。 

これにより、指数部分が完全に頂点の割り当てにシフトされます。 最大で 6^7 の可能性、つまり約 280,000 の州が完全に実現可能です。 割り当てごとに、最大 21 個のエッジをスキャンし、必要なドミノ タイプを計算し、取得できるエッジの数を数えます。 

重要な洞察は、頂点ラベルが固定されると、エッジの決定は結合されなくなるということです。 すべての制約が決定的になり、組み合わせの選択肢は頂点のラベル付けだけになります。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース エッジ選択 + マッチング | O(2^m · m!) (バックトラッキングを使用すると実質的に指数関数的) | O(2^m · m!) O(m) | 遅すぎる |
 | 頂点ラベルの列挙 | O(6^n・m) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. グラフのエッジを読み取り、ペアとして保存します。 n ≤ 7 なので、0 から n−1 まで直接頂点にインデックスを付けることができます。 
2. 各頂点に対する値 1 ～ 6 の可能な割り当てをすべて列挙します。 これは、再帰または反復的な基数 6 のカウントによって行われます。 目的は、頂点制約を完全に修正することです。 
3. 指定された割り当てについて、各エッジを処理し、そのエンドポイントによって形成される順序なしのペアを計算します。 このペアは (min(a,b), max(a,b)) などの正規化された方法で表現され、ドミノ タイプと一致します。 
4. どのドミノタイプがすでに使用されているかを追跡するために、サイズ 7×7 のブール配列 (またはセット) を維持します。 
5. ドミノ タイプがまだ使用されていない場合は、エッジをトラバースし、貪欲にエッジを取得します。 そのドミノ タイプを使用済みとしてマークし、カウントを増やします。 
6. すべての頂点割り当ての最大数を記録します。 

### なぜ効果があるのか

 頂点値が固定されると、各エッジは独立して 1 つのドミノ タイプを暗黙的に表します。 残りの唯一の制約は、各タイプが最大 1 回出現できることです。 個別の項目の最大カーディナリティの選択のみが必要なため、貪欲なスキャンが最適です。2 つのエッジが同じドミノ タイプを必要とする場合、どちらかを取得すると他方も同等にブロックされるため、これ以上の構造は必要ありません。 頂点割り当ての列挙により、エッジの選択が開始される前に、すべてのグローバルな一貫性制約がすでに満たされていることを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
edges = [tuple(map(int, input().split())) for _ in range(m)]

# convert to 0-based
edges = [(u-1, v-1) for u, v in edges]

best = 0

def dfs(i, color):
    global best

    if i == n:
        used = [[False] * 7 for _ in range(7)]
        cnt = 0

        for u, v in edges:
            a, b = color[u], color[v]
            if a > b:
                a, b = b, a
            if not used[a][b]:
                used[a][b] = True
                cnt += 1

        best = max(best, cnt)
        return

    for c in range(1, 7):
        color[i] = c
        dfs(i + 1, color)

dfs(0, [0] * n)

print(best)
```この実装では、頂点カラーリングに対して完全な DFS が実行されます。 配列`color`現在の割り当てをエンコードします。 すべての頂点が割り当てられたら、その割り当ての下でいくつのエッジを実現できるかを評価します。 

主要な実装の詳細は、可用性を確認する前に、各エッジをソートされたペアに正規化することです。 これにより、(a,b) と (b,a) が同じドミノ タイプにマッピングされるようになります。 有効な状態が 21 個だけであっても、7×7 のブール行列で十分です。 余分なエントリは無害です。 

## 実用的な例

 ### 例 1

 入力:```
4 4
1 2
2 3
3 4
4 1
```成功した 1 つのカラーリングを追跡します。すべての頂点に値 3 が割り当てられています。 

| ステップ | エッジ | ペア (値) | 使用済み？ | アクション | カウント |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 1-2 | (3,3) | いいえ | 取る | 1 |
 | 2 | 2-3 | (3,3) | はい | スキップ | 1 |
 | 3 | 3-4 | (3,3) | はい | スキップ | 1 |
 | 4 | 4-1 | (3,3) | はい | スキップ | 1 |

 この割り当てはエッジには最適ではありませんが、すべての割り当てにわたって最適な構成では頂点ラベルが整列され、各エッジが個別のドミノ タイプを生成し、4 つのエッジすべてを使用できるようになります。 

これは、ソリューションがエッジ構造のみではなく、グローバル頂点のラベル付けに大きく依存していることを示しています。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(6^n・m) | すべての頂点のラベルを列挙します。 それぞれについて、すべてのエッジを 1 回スキャンします。 
| スペース | O(n + 1) | 再帰スタックと小規模な隣接ストレージ |

 n ≤ 7 および m ≤ 21 の場合、最悪のケースはおよそ 6^7 × 21 ≈ 600 万回の操作となり、これは制限内に問題なく収まります。 

## テストケース```python
import sys, io

def solve():
    import sys
    input = sys.stdin.readline

    n, m = map(int, input().split())
    edges = [(int(a)-1, int(b)-1) for a, b in (input().split() for _ in range(m))]

    best = 0

    def dfs(i, color):
        nonlocal best
        if i == n:
            used = [[False]*7 for _ in range(7)]
            cnt = 0
            for u, v in edges:
                a, b = color[u], color[v]
                if a > b:
                    a, b = b, a
                if not used[a][b]:
                    used[a][b] = True
                    cnt += 1
            best = max(best, cnt)
            return

        for c in range(1, 7):
            color[i] = c
            dfs(i+1, color)

    dfs(0, [0]*n)
    print(best)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    return io.StringIO().write and (solve() or "")

# provided sample
assert run("4 4\n1 2\n2 3\n3 4\n4 1\n") == "4", "sample 1"

# chain
assert run("3 2\n1 2\n2 3\n") in ["2", "1"], "small chain"

# triangle
assert run("3 3\n1 2\n2 3\n3 1\n") == "3", "triangle"

# single edge
assert run("2 1\n1 2\n") == "1", "min case"

# empty graph
assert run("3 0\n") == "0", "no edges"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 4 4 サイクル | 4 | フルサイクルの実現可能性 |
 | 3 3 トライアングル | 3 | 個別のラベルで使用量を最大化 |
 | 2 1 エッジ | 1 | 自明な基本ケース |
 | 3 0 | 0 | 空のグラフの処理 |

 ## 特殊なケース

 頂点ラベルが固定されるとエッジは独立して評価されるため、グラフが切断されていても問題はありません。 たとえば、コンポーネントが 2 つある場合、同じ頂点ラベル付けロジックがグローバルに適用され、各コンポーネントのエッジがカウントに寄与するだけです。 

多くのエッジが頂点を共有するグラフは、その頂点のラベルが評価前に固定されているため、正しく処理されます。 たとえば、頂点 1 が他のすべての頂点に接続している場合、値 4 を割り当てると、すべてのインシデント エッジに 4 を含むドミノが必要になります。また、アルゴリズムは、ドミノの一意性を考慮して、異なる隣接ペアごとに最大 1 つを一貫してカウントします。 

同一の必要なドミノ タイプを形成する複数のエッジなど、繰り返し構造を含むグラフは、貪欲な割り当てごとのステップが正しい理由を示しています。重複を両方取得することはできず、ドミノ タイプを一度マークすると、後続の同一エッジはすべて自動的に拒否されます。
