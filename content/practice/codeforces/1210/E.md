 ## 問題の理解

 私たちは小さなデッキを持っています$k$1 から 1 までの番号が付けられたカード$k$そしてヴォイテクは知っている$n$デッキのさまざまな決定論的なシャッフル (順列)。 各シャッフルは、各カードがどこに終わるかを正確に指定します。 Wojtek は、連続する一連のシャッフルを覚えた場合に作成できるすべてのデッキに興味を持っています。$l$に$r$それらを任意の順序で何度でも適用できます。 具体的には、可能なすべての連続範囲を合計したいと考えています。$l$に$r$Wojtek がこれらのトリックで生成できる個別のデッキの数。 

入力により得られるのは、$n$順列、それぞれの長さ$k$。 制約というのは、$n$最大200,000まで可能ですが、$k$は非常に小さく、最大でも 5 です。この組み合わせは、すべてのペアを反復するアルゴリズムを意味します。$(l,r)$で$O(n^2)$時間が遅すぎます。 ただし、以来、$k$は小さいため、考えられるすべてのデッキ状態を明示的にモデル化できます。個別のデッキ状態の数は最大でも$k!$。 この小さな数により、カードの順列を網羅的に推論することが可能になります。 

エッジケースには、1 回のシャッフルですべての可能なデッキがすでに生成されているシーケンスが含まれます。 たとえば、$k=3$(2,3,1) のようなシャッフル サイクルを繰り返し適用すると、あらゆる順列が生成されます。 もう一つのエッジケースは、$k=1$、すべてのシャッフルは些細なものであり、考えられるデッキは 1 つだけです。$n$。 不注意な実装では、同じシャッフルの繰り返し適用を無視したり、一連の置換によって完全な対称グループが生成されると、追加のシャッフルではカウントが増加しないことを見逃したりする可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、すべてのサブ配列に対して反復処理が行われます。$l$に$r$、シャッフル アプリケーションのすべてのシーケンスをシミュレートし、個別のデッキをカウントします。 と$n$最大200,000まであります$O(n^2)$サブ配列ごとに、シーケンスのシミュレーションは指数関数的です。$k$。 それでも$k \le 5$、$O(n^2 \cdot k!)$遅すぎます。 小規模な場合はブルートフォースが機能します$n$正しく計算します$f(l,r)$順列によって生成されたグループを探索することによって実行されますが、大規模な場合は失敗します。$n$。 

重要な洞察は次のとおりです$k!$小さいです。 のために$k=5$、$k! = 120$つまり、任意の範囲の到達可能なデッキのセットをビットマスクまたは整数のセットとして表すことができます。 さらに、置換のグループに新しい置換を追加しても、到達可能なデッキが拡張されるだけです。 それは決してそれらを減らすことはありません。 したがって、固定左端点の場合、$l$、一番右のインデックスがあります$r$それを超えると、さらに順列を追加しても、到達可能なデッキのセットは変わりません。 2 つのポインターまたはスライディング ウィンドウ アプローチを使用すると、合計を効率的に計算できます。$l$、延長します$r$到達可能なデッキのセットが飽和するまで、その後は以下のすべての範囲を考慮します。$l$それに対して$r$。

 ## アルゴリズムのチュートリアル

 1. 計算を簡素化するために各シャッフル順列をゼロインデックス形式に変換し、配列に格納します。`P`。 
2. 長さのすべての順列を列挙します。$k$それぞれに一意の ID を割り当てます。 これにより、デッキの状態を 0 から 0 までの整数として表すことができます。$k!-1$。 
3. 順列の乗算表を事前計算します: 任意の 2 つの順列に対して$A$そして$B$、`mul[A][B]`適用に対応する順列を与えます$A$に続く$B$。 これにより、複合シャッフルの迅速な計算が可能になります。 
4. 左側のエンドポイントごとに$l$、セットを維持する`reachable`恒等順列から始まるデッキ ID の。 右ポインタを初期化する`r=l`。 
5. インデックスに順列を段階的に含める`r`、セットを更新しています`reachable`既存の到達可能な順列のすべての構成を新しい順列で計算することによって。 まで続ける`reachable`拡大が止まります。 
6. しましょう`R`左のエンドポイントで到達した最大インデックスになります`l`。 全範囲`[l, r']`のために`r'`から`r`に`R`同じものを持っています`f(l,r')`。 貢献度の合計を答えに加算して増分します`l`。 
7. すべてに対して繰り返します`l`。 合計はすべての範囲にわたって累積されます。 

機能する理由: アルゴリズムは、次の不変条件を維持します。`reachable`現在のウィンドウで記憶されたシャッフルのシーケンスを適用することで取得できるすべてのデッキ ID が含まれます`[l, r]`。 順列の構成は結合的であり、順列を追加しても到達可能なデッキが減ることはなく、拡張されるためです。`r`飽和してすべての範囲が正しくカウントされるまで。 

## Python ソリューション```python
import sys
from itertools import permutations
input = sys.stdin.readline

n, k = map(int, input().split())
P = [list(map(lambda x: int(x)-1, input().split())) for _ in range(n)]

# Enumerate all permutations and assign IDs
all_perms = list(permutations(range(k)))
perm_id = {p: i for i, p in enumerate(all_perms)}

# Precompute multiplication table
mul = [[0]*len(all_perms) for _ in range(len(all_perms))]
for i, a in enumerate(all_perms):
    for j, b in enumerate(all_perms):
        c = tuple(a[b[x]] for x in range(k))
        mul[i][j] = perm_id[c]

ans = 0
n_states = len(all_perms)

for l in range(n):
    reachable = set([perm_id[tuple(range(k))]])
    r = l
    while r < n:
        new_reach = set(reachable)
        p_idx = perm_id[tuple(P[r])]
        for state in reachable:
            new_reach.add(mul[state][p_idx])
        if len(new_reach) == len(reachable):
            break
        reachable = new_reach
        r += 1
    ans += len(reachable) * (r - l + 1)

print(ans)
```このコードでは、まずすべての順列にインデックスを付けて、定数時間合成を可能にします。 左側の境界ごとに、新しいデッキに到達できなくなるまで右側の境界を拡張します。 アルゴリズムで説明されているように、到達可能なデッキの数に有効な右エンドポイントの数を乗算することによって貢献度が蓄積されます。
