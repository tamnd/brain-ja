 ## 解決策
 ## 問題の理解

 Allen が引き出したい金額の合計を表す 1 つの整数が与えられます。 銀行は、固定額面 (1、5、10、20、および 100) を使用して現金のみを払い出します。タスクは、使用される紙幣の総数を最小限に抑えながら、これらの紙幣の値を使用して指定された金額を正確に表すことです。 

これは任意のコインのパーティションの問題ではありません。 額面のセットは固定されており、小さいため、合計が目標値に達する最小の個数が求められます。 各宗派ごとに回数無制限でご利用いただけます。 

入力制約により、最大 10 億の量が許可されます。 n に関する線形 DP でも最大 10^9 の状態が必要になるため、これは実行不可能であるため、値の範囲にわたる動的計画法は即座に排除されます。 有効なソリューションはすべて一定時間内に機能する必要があります。 

素朴な試みとしては、たとえば各宗派の枚数を選択するあらゆる方法を試みるなど、紙幣の組み合わせを調査しようとする場合があります。 5 種類の紙幣の枚数だけを考慮する場合でも、1 ドル紙幣の枚数は最大 10^9 まで変化する可能性があるため、100 枚、20 枚、10 枚、5 枚、および 1 枚の可能な枚数を総当たり的に列挙することはすぐに制限がなくなります。 組み合わせを制限しても、依然として非実用的な検索空間が生じます。 

高額な額面よりも小さい額面が過剰に使用されると、微妙な特殊なケースが発生します。 たとえば、100 枚の紙幣で合計枚数が減るのに 20 枚を取りすぎると、構築が最適化されなくなります。 正しいソリューションでは、局所的に最適ではない選択を回避する必要があります。 

## アプローチ

 ブルートフォース手法では、合計が n に等しい紙幣の可能な組み合わせをすべて試し、有効な組み合わせの中から紙幣の最小枚数を追跡します。 概念的には、これは解空間全体を列挙するため正しいです。 ただし、1 ドル紙幣の枚数は n まで独立して変化する可能性があるため、組み合わせの数は n 自体に応じて増加します。 宗派ごとに離散化した場合でも、検索空間は最悪の次元で n/1 の選択肢に比例し、状態ごとの探索が線形またはさらに悪化することになります。 これは、10^9 までの n の制限をはるかに超えています。 

重要な観察は、額面が正規システムで構造化されていることです。各大きな紙幣は小さな紙幣の倍数または倍近くであり、各ステップで可能な限り最大の紙幣を貪欲に取得しても、最適な解決策が妨げられることはありません。 これは、100、20、10、5 が並んでおり、大きい紙幣を 1 枚小さい紙幣に交換すると、常に紙幣の枚数が増えるためです。 たとえば、20 ドル紙幣 1 枚は 10 ドル紙幣 2 枚よりも常に優れており、10 ドル紙幣 1 枚は 5 ドル紙幣 2 枚よりも常に優れています。 

この構造により、残額から最大枚数の高額紙幣を取り出して次の金種に移すという作業を繰り返すという問題が軽減されます。 このプロセスは、単純な整数の除算のシーケンスになります。

 ## アルゴリズムのチュートリアル

 当社は額面を最大額から最小額まで処理し、常に現在の額面の紙幣をできるだけ多く抽出します。 

### ステップ

1. 最大額面の 100 から始めて、整数除算を使用して残りの金額に 100 ドル紙幣が何枚収まるかを計算します。 合計金額を金額から差し引きます。 
2. 20 ドル紙幣に移動し、残りについても同じ操作を繰り返します。 100 秒を削除した後の残りは厳密に 100 未満であるため、この手順は正しいです。そのため、その縮小された範囲内では 20 秒を使用することが局所的に最適です。 
3. 10 ドル紙幣についても同じ貪欲な抽出を繰り返します。 
4. 5 ドル札についても同じ手順を繰り返します。 
5. 最後に、残ったものは 1 ドル紙幣を使用して支払わなければならないため、残り自体が 1 ドル紙幣の数となります。 

### なぜ効果があるのか

 正しさは、各額面が小額紙幣の観点からその価値を表す最良の方法であるという事実から来ています。 大きな紙幣を小さな紙幣と交換しようとする試みは、同一の代替品を使用する場合にのみ厳密に紙幣の数を増加または維持しますが、枚数は決して改善されません。 これにより、単調な構造が形成されます。一度、できるだけ多くの高額紙幣を取得すると、その後、より小さな紙幣を組み合わせても、使用される紙幣の総数を減らすことができなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input().strip())

bills = [100, 20, 10, 5, 1]
ans = 0

for b in bills:
    ans += n // b
    n %= b

print(ans)
```このソリューションは、額面を降順に反復処理し、各金額の紙幣の最大枚数を繰り返し抽出します。 変数`ans`使用した紙幣の合計枚数を集計します。 ステップごとに減少します`n`高額な額面では表現できない残額まで。 

処理の順序は重要です。 小さい額面が最初に処理されると、合計枚数が減っても、大きい紙幣は決して使用されない可能性があります。 

すべての値が Python の整数の範囲内に収まり、精度の問題が発生しないため、整数の除算とモジュロ演算はここでは安全です。

計算は、ループの深さや再帰に関して n に依存しません。 n が 10^9 までの場合でも、アルゴリズムは一定数の算術演算を十分に制限内で実行します。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(sys.stdin.readline().strip())
    bills = [100, 20, 10, 5, 1]
    ans = 0
    for b in bills:
        ans += n // b
        n %= b
    return str(ans)

# provided sample
assert run("125\n") == "3"

# minimum input
assert run("1\n") == "1"

# exact large denomination
assert run("100\n") == "1"

# multiple of 20
assert run("80\n") == "4"

# mixed case
assert run("68\n") == "7"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 | 1 | 最小境界の場合 |
 | 100 | 1 | 正確な高額額面 |
 | 80 | 4 | 複数の中宗派の取り扱い |
 | 68 | 7 | 混合貪欲分解 |

 ## 特殊なケース

 主なエッジ ケースは、金額が高額額面のすぐ下の場合です (例: n = 99)。アルゴリズムは 100 ドル紙幣を 0 枚取り、次に 20 ドル紙幣に進み、20 が 4 つ (80) 残り 19 が残り、次に 10 が 1 つ、5 が 1 つ、1 が 4 つになります。 合計は 4 + 1 + 1 + 4 = 10 枚の紙幣です。 100ドル紙幣を強制的に発行しようとする試みは無効となり、より早い段階で少額紙幣を乱用しようとする試みはカウントを増やすだけです。 

もう 1 つのケースは、n が 200 などの大きな額面で正確に割り切れる場合です。アルゴリズムはすぐに 2 枚の 100 ドル紙幣を選択し、余りを残さずに終了します。これにより、貪欲な抽出により、小さな紙幣を必要とせずに厳密な最適表現が生成されることが確認されます。
