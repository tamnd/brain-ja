 ## 問題の理解

 いくつかの入り口がサイクル状に配置されており、各入り口にはすでに待つ人の列ができています。 毎分、各キューの先頭からちょうど 1 人が処理されます。つまり、ファン ゾーンに入り、キューから離れます。 アレンは入口 1 の列の最後尾から開始します。時間は同期したステップで進み、毎分アレンは決定論的に行動します。現在列の先頭にいない場合は、現在の入り口を離れ、次の入り口の列の最後尾に加わります。 彼の入場が処理されるときに彼がすでに最前にいた場合、彼はファンゾーンに入り、プロセスは停止します。 

課題は、アレンが最終的にどの入り口から入るかを決定することです。 完全なプロセスを時間内に段階的にシミュレートすることは求められませんが、キューが処理されるときにアレンが最初になる最終的なキューの位置を正確に特定することだけが求められます。 

この制約により、最大 100,000 の入場と最大 1e9 のキュー サイズが許可されます。 リアルタイムでの直接シミュレーションでは、1 分ごとに人の総数が最大でも n+1 ずつしか減らないため、非常に遅くなり、Allen は安定するまでに多くのサイクルを通過する必要がある可能性があります。 長期にわたる単純なシミュレーションでは、すべてのキューがクリアされるまですべての減分を合計する必要が生じる可能性があり、最悪の場合、1e9 ステップを超えます。 

一部のキューが最初は空である場合、微妙なエッジ ケースが発生します。 たとえば、列に人がいない場合、アレンは到着後すぐに先頭になる可能性があり、タイミングに応じて同じ分または次のサイクルに入ることができます。 もう 1 つのエッジ ケースは、すべてのキューが等しい場合です。この場合、対称性があいまいさを示唆する可能性がありますが、決定論的な「入力しない限り、1 分ごとに右に移動する」ルールにより、正確なサイクル位置が強制されます。 

## アプローチ

 強引なアイデアは、プロセスを分ごとにシミュレートすることです。 各ステップで、すべてのキューを 1 つ減らし (肯定的な場合)、Allen が現在のキューの先頭にいるかどうかを確認します。 そうでない場合は、彼を次のキューに移動します。 これは厳密なルールに従っているため、概念的には単純で正しいものです。 

ただし、キューを減らすには 1 分ごとに O(n) 回の更新が必要であり、Allen は多くのサイクルにわたってシステムに留まる可能性があります。 最悪の場合、すべての a_i が大きい (最大 1e9) 場合、すべてのキューが空になるまでの分数も長くなり、合計操作は 1e14 程度になりますが、これは不可能です。 

重要な洞察は、完全なシミュレーションという観点から考えるのをやめ、代わりにアレンが到着時に列の先頭になる瞬間を計算することです。 アレンが現在、ある時刻 t に入口 i にいると仮定します。 彼が到着したとき、先頭になった時点でその列に残っている彼の前に残っている人数がちょうど 0 人であれば、i から入場します。 重要な観察は、アレンの到着パターンが周期的かつ決定的であるということです。彼はキューを 1、2、3、... の順序で周期的に訪問し、入場しない限り 1 回の移動にちょうど 1 分を費やします。 

時間を追跡する代わりに、より単純な質問をします。各キュー i について、アレンはどのくらい早い時間に到着しますか。また、そこに到着したらすぐに入ることができますか? キュー i 内の人の数は、全サイクルごとに 1 人ずつ減少します。 Allen が k サイクル後にキュー i に到着すると、有効なキュー サイズは max(0, a_i - k) になります。 アレンは、先頭に並んだ瞬間にこの値が 0 になった場合に入場します。 

したがって、各 i について、Allen が誰にも遅れをとらないように a_i が十分に削減されるように、必要な完全なサイクルの数を計算します。 より具体的には、アレンは最初の i で入力し、k 個の完全なサイクルを完了した後に i に到達すると、a_i ≤ k となり、タイブレークは正確な到着順序によって決定されます。 減少する実効しきい値を追跡することで、これを論理的にシミュレートします。

これを線形スキャンに変換できます。各位置 i について、必要な最も早いサイクル カウントは、アレンが到着したときにすでに完了している完全なラウンドの数によって決まります。 アレンが k 回目に i にいる時刻は、k * n + (i - 1) です。 彼が最初にキューに入る時間の最小値が必要です。これは、a_i ≤ k かどうかを確認することに相当します。 

したがって、各 i について、k ≥ a_i となる最小の k を計算します。 つまり、k = a_i となり、時間は a_i * n + (i - 1) となります。 答えは、この値を最小にする i です。

 ## アルゴリズムのチュートリアル

 1. 各入口 i について、a_i を、Allen がそのキューを「追い越す」前に必要な完全なサイクル数として解釈します。 これは、各フル サイクルですべてのキューが 1 つの有効なレイヤーだけ削減されるという事実から来ています。 
2. アレンの入口 i への到着候補時刻を t_i = a_i * n + i として計算します。 i オフセットは、アレンがサイクル内で各キューに到達する決定的な順序を表します。 
3. アレンが最初になった最も早い時刻が、そのような最も早い完了イベントに対応するため、最小の t_i を与える入口を追跡します。 
4. その入口のインデックスを出力します。 

この式の背後にある直感は、アレンのポジションが入口を通じて決定論的に循環し、各完全なサイクルですべてのキューが均一に減少するということです。 キューの唯一の違いは、Allen が到着した瞬間にキューが空になるまでに必要なサイクル数です。 

### なぜ効果があるのか

 固定された入口 i に、アレンは予測可能なパターンで n 分に 1 回到着します。 訪問と訪問の間に、すべてのキューが完全なサイクルごとに 1 つずつ同時に減少します。 したがって、アレンが i に入る条件は、k 回目の到着までに、少なくとも a_i の完全なサイクルが経過することを要求することと同じです。 そのような最も早い k は正確に a_i であるため、実行可能な最も早いエントリ時間は a_i * n + i によって一意に決定されます。 この定式化ではすべての入り口が独立しているため、最小値を選択すると、Allen が最初に実際に使用できる入り口が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    best_time = 10**30
    best_idx = 1

    for i, ai in enumerate(a, start=1):
        t = ai * n + i
        if t < best_time:
            best_time = t
            best_idx = i

    print(best_idx)

if __name__ == "__main__":
    solve()
```このコードは、キューの展開をシミュレートせずに、各入口の直接の候補時間を計算します。 n による乗算はサイクル全体をキャプチャし、インデックス シフトはサイクル内の順序付けを考慮します。 比較により、最も古い有効なエントリ ポイントが選択されます。 

微妙な点は、到着タイミングが入口 1 から始まるキュー位置の順序に依存するため、i に 1 ベースのインデックスを使用することです。もう 1 つの重要な点は、値は任意の精度の範囲内で最大 1e14 に達する可能性があるため、Python の整数で十分であることです。

 ## 特殊なケース

 すべてのキューがゼロの場合、アレンは常に即時に適格になります。 この式では t_i = i が生成されるため、最小値は i = 1 になります。これは、サイクル遅延を必要とせずに最初の入り口から入るプロセスと一致します。 

[10, 10, 10] のようにキューが等しい場合、+i 項により到着時間は厳密に i とともに増加します。 論理的にはキューが同一であっても、アレンは依然として小さいインデックスでわずかに早く到着し、これが結果を決定します。 

a_i が非常に大きい場合、乗算が優先され、アルゴリズムは自然にそれらのインデックスをはるか将来に押し上げ、より小さいキューのみが重要になるようにします。
