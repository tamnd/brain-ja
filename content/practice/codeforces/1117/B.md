 ## 解決策
 ## 問題の理解

 私たちには、それぞれプラスの幸福値を持つ一連の感情表現が与えられています。 エモートの使用回数は決まっていますが、単一のエモートを連続して指定回数を超えて繰り返すことはできません。 課題は、これらのルールの下で相手に届けられる幸福の合計を最大化することです。 

正式には、`n`エモート、整数`m`許可される使用の合計と整数`k`連続使用制限について。 各エモートには幸福度があります`a_i`。 次のシーケンスが必要です`m`エモートは最大でも同じエモートが表示されるように使用します`k`連続した回数と合計`a_i`あらゆる用途で最大化されます。 

限界が私たちに与えてくれる`n`まで`2 * 10^5`そして`m`まで`2 * 10^9`。 それぞれを繰り返す素朴な解決策`m`個別に使用することは不可能です。 O(m) アルゴリズムは遅すぎます。 これは、実際のシーケンス シミュレーションではなく数学的計算を使用したソリューションが必要であることを示しています。`a_i`は最大 10^9 になる可能性があるため、任意精度の整数を持たない言語を使用している場合は、オーバーフローを避けるために整数演算を慎重に使用する必要があります。 

微妙な点は連続使用制限`k`。 疲れ果てるまで常に最大限の幸福感を持ってエモートを使用するだけの単純なアプローチは、次の場合に失敗します。`m`よりも大きいです`k`他のエモートを挟む必要があるためです。 たとえば、最も高い幸福エモートが 10 の場合、2 番目に高いエモートは 1 です。`m=5`、 そして`k=2`、最適な順序は次のとおりです。`[10,10,1,10,10]`。 無視する`k`生み出すだろう`[10,10,10,10,10]`、これは無効です。 

もう 1 つのエッジ ケースは、すべてのエモートが同じ幸福度を持っている場合です。 ここで、連続使用制限は幸福度の合計を減少させるものではありません。 最適なシーケンスでは、任意のエモートを任意の順序で使用できます。 

## アプローチ

 ブルートフォースアプローチは、連続使用制限を尊重しながら、利用可能な最大のエモートを繰り返し選択することです。 現在の連続したエモートの数を追跡し、制限に達した場合に次善のエモートに切り替えます。 これは小規模な場合に機能します`m`そして`n`、しかし、`m`2*10^9 までは O(m) 回の操作が必要となり、制限時間をはるかに超えます。 

重要な洞察は、繰り返されるパターンに気づくことです。 最適な戦略では常に最大のエモートが使用されます`k`回、次に 2 番目に大きいエモートを 1 回、このブロックを繰り返します。 最大の幸福値を`first`そして2番目に大きいのは`second`。 それぞれの完全なブロックが貢献します`first*k + second`幸せで長さがある`k+1`。 完全なブロックがいくつ収まるかを計算できます。`m`整数除算を使用します。 フルブロック後の残りの使用は、連続した制約により許可されるため、最大のエモートに使用されます。 これにより、シミュレーションによる問題が軽減されます`m`2 つの最大のエモートだけを使用して定数時間の算術計算に進みます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(m) | お(1) | 大きい m には遅すぎる |
 | 最適 (最大 2 つの数学) | ソートの場合は O(n log n) + O(1) の算術演算 | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 整数の読み取り`n`、`m`、 そして`k`。 次に配列を読み取ります`a`幸福の価値観。 
2. 並べ替え`a`降順ではない順に。 これにより、最大の 2 つの値に簡単にアクセスできます。 
3. しましょう`first = a[-1]`（最大のエモート）と`second = a[-2]`（2番目に大きい）。 
4. 完全なブロックの数を計算します。`k+1`ぴったり合うエモート`m`使用します:`blocks = m // (k+1)`。 各ブロックが貢献します`first*k + second`幸せ。 
5. 残りの使用量を計算します。`remainder = m % (k+1)`。 これらはすべて可能です`first`連続制限はブロックごとにリセットされるため、エモートを使用できません。 
6. 幸福度の合計を計算します。`total = blocks * (first*k + second) + remainder * first`。 
7. 出力`total`。 

機能する理由: すべてのブロックは、連続制限を尊重しながら幸福度を最大化します。 最大のエモートを以上使用する`k`times consecutively is forbidden, and using any emote smaller than the second-largest in the block would reduce total happiness. これにより、合計が最適であることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m, k = map(int, input().split())
a = list(map(int, input().split()))

a.sort()
first = a[-1]
second = a[-2]

blocks = m // (k + 1)
remainder = m % (k + 1)

total = blocks * (first * k + second) + remainder * first
print(total)
```このソリューションでは、配列を並べ替えて、最大の 2 つの値を簡単に識別します。 整数の除算と係数を使用して完全なブロックと残りの使用を効率的に計算し、シーケンス シミュレーションの必要性を回避します。 並べ替えは唯一の O(n log n) ステップです。 算術演算は定数時間です。 大規模な環境でのパフォーマンスを確保するために高速 I/O を使用します。`n`。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, m, k = map(int, input().split())
    a = list(map(int, input().split()))
    a.sort()
    first = a[-1]
    second = a[-2]
    blocks = m // (k + 1)
    remainder = m % (k + 1)
    total = blocks * (first * k + second) + remainder * first
    return str(total)

# provided samples
assert run("6 9 2\n1 3 3 7 4 2\n") == "54", "sample 1"

# custom cases
assert run("3 5 1\n10 5 2\n") == "40", "alternating k=1"
assert run("2 10 3\n5 5\n") == "50", "all equal values"
assert run("5 8 2\n1 2 3 4 5\n") == "34", "general case"
assert run("2 1 1\n1000000000 1\n") == "1000000000", "minimal m=1"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`3 5 1\n10 5 2`| 40 | 交互の k=1 の場合 |
 |`2 10 3\n5 5`| 50 | すべて等しい値、連続制限は無関係 |
 |`5 8 2\n1 2 3 4 5`| 34 | 一般的なケースの計算 |
 |`2 1 1\n1000000000 1`| 1000000000 | 最小 m エッジ ケース |

 ## 特殊なケース

 もし`k >= m`、連続制限によって制限されることはありません。 例えば、`n=3, m=2, k=5, a=[1,2,3]`。 アルゴリズムは計算します`blocks=0`、`remainder=2`、 そして`total=2*3=6`、それは正しいです。 

すべての値が等しい場合、たとえば、`n=4, m=7, k=3, a=[5,5,5,5]`、 それから`first=5, second=5`、ブロック計算では次のようになります。
