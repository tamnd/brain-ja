 ## 解決策
 ## 問題の理解

 文字列が与えられています`t`長さの`n`これは、未知の一連のスワップを元の文字列に適用した結果です`s`。 各交換では 2 つの文字の位置が交換されます`a_i`そして`b_i`で`s`。 一連のスワップには、操作がゼロまたは最大で 2 回含まれる可能性があります。`n`操作が実行され、スワップが順番に適用されます。 元の文字列がわかりません`s`またはスワップ自体。 

文字列を指定してシステムに最大 3 回クエリを実行できます。`s'`長さの`n`、システムは未知のスワップシーケンスを適用した結果を返します。`s'`。 私たちの目標は、元の文字列を推定することです`s`このようなクエリは最大 3 つ使用します。 

制約`n ≤ 10^4`これは、アルゴリズムが最大で動作する必要があることを意味します。`O(n log n)`または`O(n)`クエリごとに、`n^2`操作には数億ステップが必要になる可能性があり、これでは 2 秒の制限には遅すぎます。 エッジ ケースには、長さ 1 の文字列や多くの文字が同一である文字列が含まれており、単純な位置エンコード方法を混乱させる可能性があります。 

たとえば、次の場合`t = yzx`そして`s = xyz`スワップあり`(1,2)`それから`(2,3)`、次のようなクエリ文字列`abc`スワップ後に暗号化されたバージョンが返されるため、位置の変更を推測できるようになります。 文字は繰り返され、システムはスワップ インデックスではなく変換された文字列のみで応答するため、文字値のみに依存すると不注意なメソッドは失敗する可能性があります。 

## アプローチ

 ブルートフォースアプローチは、可能なすべての置換を試みることです。`n`文字が生成されるまで`t`未知の交換後。 これは明らかに実行不可能です。`n!`順列は天文学的に増加します`n = 10^4`。 

重要な観察は、スワップのシーケンスが **位置の並べ替え** を定義しているということです。 各位置を一意にエンコードできれば、`s'`個別の値を使用すると、未知の交換後に、並べ替えられた値を読み戻すことができます。`t'`元の位置を再構築します。 

各位置のエンコードは、文字を含む **base-26 表現** を使用して行うことができます。または、より一般的には、各クエリが位置を異なる係数でエンコードする 3 つの独立したクエリを使用して行うことができます (中国剰余定理を使用するなど)。 最初のクエリは 26 を法とする位置をエンコードし、2 番目のクエリは 26 のより高い累乗をエンコードします。 3 回のクエリの後、各インデックスには一意の署名が付けられるため、順列を反転して復元できます。`s`。

 ## アルゴリズムのチュートリアル

 1. 各ポジションの割り当て`i`で`s`一連の小文字にエンコードできる一意の識別子。 以来`n ≤ 10^4`、base-26 の 3 文字を使用すると、次のようになります。`26^3 = 17576 > 10000`、それで十分です。 
2. 最初のクエリ文字列を準備します`s1`ここで、最初の文字は、base-26 の最下位桁をエンコードします。`i`。 2 番目のクエリを準備する`s2`Base-26 エンコーディングの中央の桁を使用します。 3 番目のクエリを準備する`s3`最上位桁を使用します。 
3. 各クエリをシステムに送信して、`t1`、`t2`、`t3`。 それぞれ`t_k`は、未知のスワップ後のエンコードされた位置を表します。 
4. 各インデックスについて`j`で`t`の文字を組み合わせます。`t1[j]`、`t2[j]`、`t3[j]`一意のエンコードされた位置を再構築します。 これを元のインデックスにマッピングし直します。`s`。 
5. 暗号化された位置から元のインデックスへのマッピングを使用して、対応する文字を配置します。`t`元の位置に戻し、`s`。 

**機能する理由**: 各位置には一意の識別子が与えられるため、任意の交換後でも識別子をクエリから読み取ることができます。 3 つのクエリで十分です。`26^3`文字列の最大長を超えています`n = 10^4`。 マッピングは全単射であり、正確性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    t = input().strip()
    n = len(t)
    
    def encode_positions(n):
        s1 = []
        s2 = []
        s3 = []
        for i in range(n):
            s3.append(chr(ord('a') + i // (26*26)))
            s2.append(chr(ord('a') + (i // 26) % 26))
            s1.append(chr(ord('a') + i % 26))
        return ''.join(s1), ''.join(s2), ''.join(s3)
    
    s1, s2, s3 = encode_positions(n)
    
    # Query the system
    print("?", s1)
    sys.stdout.flush()
    t1 = input().strip()
    
    print("?", s2)
    sys.stdout.flush()
    t2 = input().strip()
    
    print("?", s3)
    sys.stdout.flush()
    t3 = input().strip()
    
    # Recover original positions
    pos_map = {}
    for idx, (c1, c2, c3) in enumerate(zip(t1, t2, t3)):
        code = (ord(c3)-ord('a'))*26*26 + (ord(c2)-ord('a'))*26 + (ord(c1)-ord('a'))
        pos_map[code] = idx
    
    # Reconstruct original string
    s = [''] * n
    for i, char in enumerate(t):
        s[pos_map[i]] = char
    
    print("!", ''.join(s))
    sys.stdout.flush()

if __name__ == "__main__":
    main()
```このコードは、エンコーディングを 3 つのクエリに分割し、返された文字をその位置にマップし直します。 オフバイワンの間違いは、次のようにすることで回避できます。`0`ベースのインデックスを一貫して作成します。 使用する`ord('a')`小文字以内に収まるようにするため、すべてのクエリに対して 3 つのクエリで十分です。`n ≤ 10^4`。

 ## 特殊なケース

 いつ`n = 1`、アルゴリズムはまだ機能します。`s1`、`s2`、`s3`は`'a'`そしてクエリが返されます`'a'`。 マッピングは正しく再構築されます`s = t`。 

すべての文字が同じ場合、次のように`t = "aaaa"`、base-26 エンコードによりクエリの一意性が保証されるため、文字が繰り返される場合でも位置を混乱することはありません。 

スワップ シーケンスが空の場合、クエリは入力文字列自体を返し、マッピングが再構築されます。
