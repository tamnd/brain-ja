 ## 問題の理解

 すべてゼロの計算基底状態で初期化された量子ビットのレジスターから始めます。 これに加えて、次の長さの 4 つの古典的なビット文字列が与えられます。$N$、それぞれがこれらの量子ビット上の 1 つの計算基礎状態を記述します。 各ビット列は、特定の基底ベクトルを取得するためにどの量子ビットを反転する必要があるかを示します。$|00\ldots0\rangle$。 

目標は、古典的な結果を出力することではなく、レジスタの量子状態を変換して、正確にこれら 4 つの基底状態の等振幅の重ね合わせになるようにすることです。 具体的には、最終状態が振幅を伴って現れる 4 つの基底ベクトルの正規化された合計になるようにします。$1/2$。 

なぜなら$N \le 16$、状態空間には最大のサイズがあります$2^{16} = 65536$これは、明示的な基底状態に関して概念的に推論できるほど十分に小さいです。 ただし、実装では依然として量子制約を尊重する必要があります。これは、可逆操作を使用してユニタリ変換を構築していることを意味します。 

微妙な制約は、4 つの基底状態が異なることが保証されているが、それらは 1 量子ビットのみ異なる場合もあれば、多数の量子ビットが異なる場合があることです。 違いが不規則な場合、それらの間の構造的整合を前提とした構築は失敗する可能性があるため、これは重要です。 もう 1 つの重要な点は、振幅を直接「上書き」することはできないということです。 すべての変換は、均一に適用された有効な量子ゲートから得られる必要があります。 

素朴な間違いは、古典的な状態の記述を「分岐」させ、それぞれを独立して準備し、それらを平均化しようとすることです。 これは、量子状態の準備が線形かつ可逆的である必要があり、ユニタリー埋め込みを構築せずに振幅を選択的に注入できないため、失敗します。 

## アプローチ

 ブルートフォースのメンタルモデルは、4 つの基本状態をそれぞれ個別に準備し、それらを組み合わせて均一な重ね合わせを行うことを考えることです。 4 つの状態にインデックスを付ける 2 量子ビット制御システムを作成し、条件付きで準備することを想像するかもしれません。$|\psi_i\rangle$データレジスタ上で。 これにより、フォームの状態が得られます$$\frac{1}{2}\sum_{i=0}^3 |i\rangle |\psi_i\rangle.$$コヒーレンスを維持しながら制御レジスタを何らかの方法で消去できれば、データ レジスタのみで目的の重ね合わせが得られるでしょう。 

難しいのはまさにこの消去ステップです。 制御レジスタを直接破棄または測定すると、重ね合わせが破壊されます。 したがって、重要なアイデアは、構造を逆にして制御システムの計算を解除することですが、それは制御システムがデータ レジスタから切り離されていることを確認した後でのみです。 これは、クリーンな計算基盤から 4 つのターゲット状態への可逆マッピングを構築し、インデックス付け量子ビットに等しい重ね合わせを埋め込むことで実現されます。 

より直接的でクリーンな観点では、基底状態の置換対称性を使用します。 4 つの既知の計算基底ベクトルの等しい振幅のみが必要なため、標準の 2 量子ビットの一様な重ね合わせを 4 つのターゲット ビット列にマッピングするユニタリーを構築します。 2 量子ビット システムは、アダマール ゲートを介して正確に 4 つの等しい振幅を自然に提供します。$$\frac{1}{2}\sum_{i=0}^3 |i\rangle.$$次に、このインデックス レジスタを使用して、すべてゼロのデータ レジスタを条件付きで次のように変換します。$|\psi_i\rangle$ビットパターンに基づいたcontrolled-X操作を使用します。 各ビット フリップは、対応するインデックスが特定の状態を選択する場合にのみ適用されます。 

これは、各基底状態が異なるため機能します。$|0\ldots0\rangle$X ゲートの既知のパターンによって、それらの X ゲートの制御された適用によってマッピングが構築されます。$$|i\rangle|0\rangle \mapsto |i\rangle|\psi_i\rangle.$$マッピングは可逆的であり、計算ブランチ全体で独立しているため、線形性により最終的な重ね合わせが正確であることが保証されます。 

最後に、同じ制御された構造を逆にしてインデックス レジスタを計算解除し、データ レジスタだけを目的の等しい重ね合わせに残します。

 ## アルゴリズムのチュートリアル

 利用可能な量子ビットのうちの 2 つを使用して 2 量子ビットの「セレクター」レジスタを暗黙的に導入し、それを使用して 4 つの基底状態のインデックスを作成することで、ソリューションを構築します。 

1. インデックス システムとして機能する 2 つの量子ビットを特定し、アダマール ゲートを使用してそれらを均一に重ね合わせます。 これにより、4 つの計算ラベルにわたって等しい振幅が作成されます。 正確に 2 つの量子ビットが必要な理由は、4 つの状態には正確に 4 つの直交する古典的ラベルが必要だからです。 
2. 4 つのビット ベクトルのそれぞれについて、変換する X 演算のパターンとして解釈します。$|0^N\rangle$の中へ$|\psi_i\rangle$。 これは、計算基底状態をエンコードする標準的な方法です。 
3. インデックス レジスタからデータ レジスタに制御された X 操作を適用します。 それぞれの基底状態について$i$、量子ビットに X を適用します$j$ビットの場合に限り$bits[i][j]$true であり、インデックスで制御されます。$|i\rangle$。 これにより、重ね合わせの各分岐が独立してターゲットの基底状態に進化することが保証されます。 
4. すべての制御された変換後のジョイントの状態は次のようになります。$$\frac{1}{2}\sum_{i=0}^3 |i\rangle|\psi_i\rangle.$$5. 最初のアダマール層の逆を適用してインデックス レジスタを計算解除します。 アダマール関数はそれ自体の逆関数であるため、これによりインデックスがデータ レジスタから解放されます。 
6. データ レジスタの残りの状態は、正確に所望の等しい重ね合わせです。 

### なぜ効果があるのか

 この構造は、すべての操作が線形であり、重ね合わせブランチ全体で均一に動作するという事実に基づいています。 各制御された X は、その条件が満たされるブランチにのみ影響を与えるため、異なるブランチ間で干渉は発生しません。$|\psi_i\rangle$。 インデックス レジスタはインボリュートリー変換を介して最後に解きほぐされるため、残りの状態は等しい振幅を持つ 4 つの基本状態のクリーンな合計になります。 正確さは、可逆的なユニタリ進化の下での振幅の保存と、制御された操作の下での計算ブランチの独立性から得られます。 

## Python ソリューション

 この問題は Q# スタイルで記述されているため、実際の実装は従来の Python ではなく量子操作です。 重要なアイデアは、2 つの量子ビットをセレクターとして使用し、4 つのインデックスに対して均一な重ね合わせを準備し、ビット パターンに従って条件付きで X ゲートを適用することです。 

以下は、そのロジックに従った Q# 実装です。```python

```
namespace Solution {
    open Microsoft.Quantum.Primitive;
    open Microsoft.Quantum.Canon;

    operation ApplyPattern(qs : Qubit[], bits : Bool[], control : Qubit) : Unit {
        for i in 0 .. Length(bits) - 1 {
            if (bits[i]) {
                CNOT(control, qs[i]);
            }
        }
    }

    operation Solve (qs : Qubit[], bits : Bool[][]) : Unit {
        using (anc = Qubit[2]) {

            // Step 1: create equal superposition over 4 indices
            H(anc[0]);
            H(anc[1]);

            // Step 2: apply controlled state preparation
            for (i in 0 .. 3) {
                if (i == 0) {
                    // control = |00>
                    within {
                        // nothing
                    } apply {
                        for (j in 0 .. Length(qs) - 1) {
                            if (bits[i][j]) {
                                X(qs[j]);
                            }
                        }
                    }
                } elif (i == 1) {
                    X(anc[0]);
                    within {
                        // control on |10>
                    } apply {
                        for (j in 0 .. Length(qs) - 1) {
                            if (bits[i][j]) {
                                CNOT(anc[0], qs[j]);
                            }
                        }
                    }
                    X(anc[0]);
                } elif (i == 2) {
                    X(anc[1]);
                    within {
                        // control on |01>
                    } apply {
                        for (j in 0 .. Length(qs) - 1) {
                            if (bits[i][j]) {
                                CNOT(anc[1], qs[j]);
                            }
                        }
                    }
                    X(anc[1]);
                } else {
                    X(anc[0]);
                    X(anc[1]);
                    within {
                        // control on |11>
                    } apply {
                        for (j in 0 .. Length(qs) - 1) {
                            if (bits[i][j]) {
                                CNOT(anc[0], qs[j]);
                                CNOT(anc[1], qs[j]);
                            }
                        }
                    }
                    X(anc[0]);
                    X(anc[1]);
                }
            }

            // Step 3: uncompute index register
            H(anc[0]);
            H(anc[1]);

            ResetAll(anc);
        }
    }
}
```この構造は、4-way インデックスをエンコードする 2 つの補助量子ビットを中心に構築されています。 アダマール ゲートはインデックス上に均一な重ね合わせを生成します。 各ブランチは、インデックス値を条件として、1 つの基底ベクトルの可逆エンコーディングを適用します。 Controlled-X 構造により、正しい計算ブランチのみが変更され、一貫性が維持されます。 

微妙な点は、任意の制御状態を次のように変換するには、各インデックス ケースを Pauli-X ゲートで挟む必要があることです。$|11\rangle$または制御された操作のための同様の標準形式。 Q# のマルチ制御ゲートは、明示的なマルチ制御述語よりも基底の変更を介して表現する方が簡単であるため、これが必要です。

 ## 特殊なケース

 厄介なケースは、2 つの基底状態が 1 量子ビットだけ異なる場合です。 「フリップをグローバルに蓄積」しようとする単純な実装では、以前の変換が誤って上書きされ、ブランチ間の干渉が発生します。 制御された構造では、計算インデックスごとに変換を分離することでこれを回避し、最小のハミング距離の差さえも正しく処理されるようにします。 

もう 1 つのケースは、ある状態が最後の量子ビットを除いて別の状態とほぼ同一である場合です。 制御が適切に分離されていないと、グローバル X アプリケーションが複数のブランチに誤って影響を及ぼし、意図した重ね合わせ構造が崩れてしまいます。 このアルゴリズムは、すべての操作をビット パターン自体ではなく特定のインデックス状態に結び付けることでこれを防ぎます。
