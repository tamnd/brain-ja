 ## 解決策
 ## 問題の理解

 バイナリベクトルが交互するかどうかをチェックする「量子オラクル」を実装するように求められます。 これは、ビットの入力配列の場合を意味します。`x[0..N-1]`、連続する 2 つのビットが同じかどうかを判断する必要があります。 正式には、この関数は$f(x)$すべての隣接するペアの場合は 1 を出力します`(x[i], x[i+1])`満足する`x[i] != x[i+1]`。 入力`x`は量子ビットを表しますが、概念的には古典的なビット配列として扱うことができます。 出力量子ビット`y`によって切り替えられます`f(x)`： もし`f(x) = 1`、`y`ひっくり返す。 それ以外の場合は同じままです。 

重要な制約は次のとおりです。`1 <= N <= 7`。 これは非常に小さいです。 N が最大 7 の場合、可能な入力パターンは 128 個のみです。 これは、合計の操作が無視できるため、隣接するペアに対するネストされたループを含め、各ビットを明示的に検査するアプローチが受け入れられることを示しています。 

注意が必要なエッジケースには最小の入力が含まれます`N = 1`- 単一ビット配列は常に自明に交互になります。 また、次のような繰り返しビットの配列`[1, 1, 1]`返すべきです`f(x) = 0`しかし、不注意な実装では、隣接するすべてのペアのチェックを忘れて、誤って 1 を出力する可能性があります。 

## アプローチ

 ブルートフォース手法は、配列内の隣接するビットの各ペアを反復処理することです。 いずれかのペアが等しい場合、配列は交互テストに失敗し、0 を返します。 それ以外の場合は 1 を返します。N <= 7 の場合、呼び出しごとの比較の最大数は 6 であるため、これは許容されます。 一般的な量子設定では、controlled-X 操作を使用してこのロジックをエンコードできますが、代替の定義を直接実装するため、概念的にはブルート フォースが機能します。 

この場合の最適なアプローチは本質的に同じです。 入力サイズが小さいため、さらに最適化する必要はありませんが、明確にすることが重要です。 重要な洞察は、交互ビットの場合は連続するペアだけをチェックするだけで十分であるということです。 組み合わせや再帰的な構築は必要ありません。 アルゴリズムの正しさは、有効な交互配列に次の要素を含めることができないという不変式に由来します。`00`または`11`任意の連続したペアで。 違反が 1 つ見つかったら、すぐに終了できます。

 ## アルゴリズムのチュートリアル

 1. ブール変数を初期化する`ok = True`。 これにより、配列が交互になるかどうかが追跡されます。 
2. 配列インデックスを反復処理します。`i = 0`に`N-2`。 それぞれについて`i`、 比較する`x[i]`と`x[i+1]`。 
3. もし`x[i] == x[i+1]`、 セット`ok = False`そしてすぐにループを断ち切りましょう。 アレイは代替テストに合格しないため、それ以上のチェックは必要ありません。 
4. ループ後、`ok`連続するペアが交互プロパティに違反していない場合、True になります。 
5. トグルして関数出力を適用します。`y`もし`ok`は本当です。 古典的なシミュレーションでは、交互の場合は 1 を返し、それ以外の場合は 0 を返すだけです。 

機能する理由: アルゴリズムは、連続するすべてのペアを 1 回だけチェックします。 違反が存在する場合、ループはそれを検出し、早期に停止します。 スキップされるペアはないため、出力は長さ 1 ～ 7 のすべての配列に対して正確になります。ループの不変条件は反復時のものです。`i`、すべてのペア`x[0..i]`交互を満たします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    x = list(map(int, input().strip().split()))
    n = len(x)
    
    ok = True
    for i in range(n - 1):
        if x[i] == x[i + 1]:
            ok = False
            break
    print(1 if ok else 0)

if __name__ == "__main__":
    solve()
```最初の行はビット配列を読み取ります。 連続するインデックスを反復処理して検出します`00`または`11`。 そのようなペアが見つかった場合は、その配列を非交互として直ちにマークします。 最後に、交互配列の場合は 1、非交互配列の場合は 0 を出力します。 ループ境界`n - 1`これにより、これらの問題で一般的な off-by-one エラーである範囲外のインデックスにアクセスすることがなくなります。

 ## 特殊なケース

 シングルビットの場合`[0]`、ループ`range(n - 1)`空いているので、`ok`これは、1 ビット配列が自明に交互することを正しく識別します。 

次のようなすぐに繰り返されるビットを持つ配列の場合`[1, 1]`、最初の比較で等しいことが検出され、設定されます。`ok = False`ループは続行されず、早期終了が機能し、不要な操作が実行されていないことが確認されます。 

最大長の配列の場合`[0, 1, 0, 1, 0, 1, 0]`、すべてのペアは個別です。 ループは 6 つの連続するペアすべてをチェックし、違反は見つからず、1 が生成されます。これは、境界条件が満たされていることを示しています。`n-1`許可される最大の入力を正しく処理します。 

このソリューションは完全に堅牢であり、すべてのエッジ ケースに対応し、N が大きい場合でも簡単に拡張できます。 量子解釈では、連続する各ビット比較が実際の Q# 実装の制御された操作にマップされます。
