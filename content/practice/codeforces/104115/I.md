 ## 解決策
 ## 問題の理解

 英語の小文字で構成される文字列が与えられ、それをちょうど k 個の連続する空でない部分に分割して、すべての部分に同じ数の子音文字が含まれるようにできるかどうかを尋ねます。 ここでの子音とは、a、e、i、o、u、y を除く文字を意味します。 

重要な制約は、分割は文字列を連続したセグメントに切断することによって行う必要があるため、文字を再配置するわけではないということです。 k 個のカット位置のみを選択し、結果として得られる k 個の部分文字列はすべて同じ数の子音を持たなければなりません。 

入力サイズは 200,000 文字に達する可能性があるため、考えられるすべてのパーティションを試したり、すべてのカットの組み合わせをチェックしたりするソリューションは、直ちに実行不可能になります。 分割位置またはセグメントの選択に対する二次または指数関数的なアプローチは、制限時間を大幅に超えるため、解は n において線形または線形に近いものでなければなりません。 

最初の微妙なエッジ ケースは、k が n より大きい場合に現れます。 文字列に多くの母音が含まれている場合でも、すべてのセグメントは空であってはいけないため、文字数より多くのセグメントを持つことはできません。 たとえば、n = 3、k = 4 は文字列に関係なく常に失敗します。 

もう 1 つの重要なエッジ ケースは、子音の総数が k で割り切れない場合です。 各セグメントには同じ数の子音が含まれている必要があるため、子音の合計数が C の場合、各パートには正確に C / k 個の子音が含まれている必要があります。 C が k で割り切れない場合、どのパーティションも機能しません。 たとえば、文字列に子音が 5 つあり、k = 2 の場合、5 を 2 つの整数部分に均等に分割することはできません。 

最後に、たとえ分割可能である場合でも、連続した方法でセグメント化が可能であることを保証する必要があります。 これには、左から右にスキャンして子音を蓄積するときに、セグメントごとのターゲット子音数の倍数に正確にカットを配置できることが必要です。 

## アプローチ

 ブルートフォース戦略では、n − 1 個の可能な位置に k − 1 個のカットを配置し、各パーティションを検証しようとします。 候補となる各パーティションについて、各セグメントの子音数を再計算します。 プレフィックスの合計を使用しても、カットの組み合わせの数は n から k 個の位置を選択するオーダーであり、n が 200,000、k が 200,000 までの場合、組み合わせ的に大きくなります。 このアプローチはまったく実行不可能です。 

重要な観察は、正確な文字の構成ではなく、子音の数のみが重要であるということです。 子音 C の合計数がわかったら、すべての有効な分割で C を k 個の等しい整数部分 (それぞれ C / k に等しい) に分割する必要があります。 これにより、問題が単一の線形スキャンに変換されます。子音を数えて、それらを順番にセグメントに貪欲に割り当てます。 正確に C / k の子音を蓄積するたびに、1 つのセグメントを終了して次のセグメントを開始します。 

文字列の順序が固定されているため、貪欲な性質が機能します。 子音の数は右に移動するにつれて増加するだけであるため、セグメントに必要な割り当てに達した後でカットを遅らせたり、早めに移動したりしてもメリットはありません。

 ## アルゴリズムのチュートリアル

1. 各文字を 1 回スキャンして、文字列内の子音の総数を数えます。 カウントがゼロの場合は、すべてのセグメントのカウントが等しい必要があり、すべてのセグメントの子音がゼロになる必要があるため、これを特別なケースとして扱います。 
2. k が n より大きい場合は、k 個の空でないセグメントを形成できないため、すぐに「いいえ」を返します。 
3. 子音の合計 C が 0 の場合、すべてのセグメントの子音は 0 でなければなりません。これは、文字列を k 個の空でない部分に分割できる限り常に可能です。 どのカットも子音の等価性に影響を与えないため、k ≤ n の場合、答えは「はい」になります。 
4. C が k で割り切れない場合は、整数カウントを均等に分配することは不可能であるため、「いいえ」を返します。 
5. 各セグメントに必要な子音の数である target = C / k を計算します。 
6. 現在のセグメント内の子音の実行カウンタを維持しながら、文字列を左から右にトラバースします。 
7. 子音に遭遇するたびに、実行中のカウンタをインクリメントします。 
8. 実行中のカウンタが目標に達するたびに、カウンタをゼロにリセットし、概念的には 1 つのセグメントを終了します。 また、完了したセグメントの数もカウントします。 
9. 文字列全体を処理した後、正確に k 個のセグメントを形成し、すべての子音が均等に消費されたかどうかを確認します。 「はい」の場合は「はい」を返し、そうでない場合は「いいえ」を返します。 

### なぜ効果があるのか

 正しさは問題の単調な構造に依存します。 子音の数は文字列をスキャンするときに増加するだけなので、セグメントの境界が強制されます。セグメントは、必要なクォータに達したときに正確に終了する必要があります。 それより早い段階でカットするとセグメントに不十分な子音が残り、その後のカットではクォータを超えてしまいます。 したがって、有効なパーティションが存在する場合、それはこの貪欲な構造と一致する必要があります。 可分性条件により、クォータがグローバルに一貫していることが保証され、スキャンによりすべてのステップでローカルな実行可能性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def is_vowel(c):
    return c in "aeiouy"

def solve():
    n, k = map(int, input().split())
    s = input().strip()

    consonants = 0
    for ch in s:
        if not is_vowel(ch):
            consonants += 1

    if k > n:
        print("No")
        return

    if consonants == 0:
        print("Yes")
        return

    if consonants % k != 0:
        print("No")
        return

    target = consonants // k

    cnt = 0
    segments = 0

    for ch in s:
        if not is_vowel(ch):
            cnt += 1
        if cnt == target:
            segments += 1
            cnt = 0

    print("Yes" if segments == k and cnt == 0 else "No")

if __name__ == "__main__":
    solve()
```この実装は、貪欲な構造を直接反映しています。 分かりやすくするために、母音チェックは分離されています。 唯一の微妙な条件は最終検証です。正確に k 個の完全なセグメントが形成され、不完全な最終セグメントを示す残りの子音が残っていないことを確認します。
