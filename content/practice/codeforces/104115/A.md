 ## 解決策
 ## 問題の理解

 テレビ番組を表す一連の時間間隔が与えられています。 各プログラムには開始時刻、終了時刻、および 3 つのタイプのいずれかがあります。 Petya はタイプ 1 プログラムを、Masha はタイプ 2 を、両方が同時にタイプ 3 を好むプログラムです。 

テレビはいつでも、せいぜい 1 つの番組しか表示できませんが、私たちは番組を自由に切り替えたり、番組の断片だけを視聴したりすることができます。 ある時間セグメントで番組を視聴することを選択した場合、番組がタイプ 1 または 3 の場合、ペティアは 1 分あたり 1 単位の幸福度を獲得し、番組がタイプ 2 または 3 の場合、マーシャは 1 分あたり 1 単位の幸福度を獲得します。タイプ 3 の番組は両方に同時に貢献するため、そのような 1 分間の合計貢献度は 2 になります。 

課題は、両方の友人の合計の累積幸福度を最大化するために、どの番組を視聴するかをあらゆる瞬間に選択することです。 

入力制約では、最大 10 億の座標を持つ最大 10 万の間隔が許可されます。 これにより、時間を分ごとに処理しようとするソリューションは即座に排除されます。 時間をかけて直接シミュレーションを行うには、場合によっては数十億単位の反復処理が必要になりますが、制限時間内にこれを行うことは不可能です。 正しい解決策は、アクティブな間隔のセットが変化するイベント境界の観点から推論する必要があります。 

複数の間隔が複雑に重なる場合、微妙なエッジケースが発生します。 たとえば、ある時点で、タイプ 1 とタイプ 2 のプログラムがいくつか重複していて、タイプ 3 のプログラムが存在しない場合、合計で 1 分あたり 2 つのメリットが得られると誤って考えてしまいがちです。 一度に視聴できる番組は 1 つだけなので、これは不正解です。 この場合、正しいゲインは 1 分あたり 1 のままです。 

タイプ 3 の間隔が他の多くの間隔と重複する場合、別の特殊なケースが発生します。 複数のタイプ 1 およびタイプ 2 プログラムが利用可能な場合でも、1 つのタイプ 3 プログラムの存在が優勢です。これは、1 分あたり 2 つの最大の組み合わせ利点が得られるためです。 

## アプローチ

 素朴な戦略は、タイムラインを一連の小さなセグメントとして考慮し、各瞬間でどの間隔がアクティブであるかを判断し、最適な間隔を選択することです。 各瞬間の決定は過去から独立しているため、これは概念的に機能します。 ただし、時間を明示的にシミュレートすると、座標の範囲が 10 億に拡張される可能性があるため、単位時間ステップごとに反復すると、実行不可能な数の操作が必要になります。 

応答が間隔のエンドポイントでのみ変化することを観察することで、これを改善できます。 2 つの連続するエンドポイント間では、アクティブな間隔のセットは一定のままであるため、最適な選択も一定のままです。 これにより、問題は重大なイベントとして最大 2 倍の間隔数に変換されます。 

連続するイベント時間の間の各セグメントでは、タイプ 3 のアクティブなインターバルが少なくとも 1 つ存在するかどうかだけを知る必要があり、それ以外の場合は、タイプ 1 または 2 のアクティブなインターバルが少なくとも 1 つ存在するかどうかを知る必要があります。これにより、ソートされたエンドポイントをスイープする際に、タイプごとにアクティブなインターバルのカウントを維持するという問題が軽減されます。

 ## アルゴリズムのチュートリアル

 すべての間隔のエンドポイントをイベントとして処理し、時間を昇順にスイープします。

1. 各間隔を 2 つのイベントに変換し、1 つは開始をマークし、もう 1 つは終了をマークします。 各イベントには時間と種類があり、それが挿入なのか削除なのかも追跡します。 これにより、現在アクティブなフィルムのセットをいつでも維持できるようになります。 
2. すべてのイベントを時間順に並べ替えます。 複数のイベントが同時に発生した場合、その時点から始まるセグメントからの寄与を評価する前に、すべてのイベントが処理されます。 これにより、アクティブ セットが各時間間隔で常に正しいことが保証されます。 
3. アクティブな間隔について 3 つのカウンタを維持します。現在アクティブなタイプ 1 の数、タイプ 2 の数、およびタイプ 3 の数です。 これらのカウンターを使用すると、一定時間内に最適なフィルムの選択を決定できます。 
4. 2 つの連続するイベント時間の間、たとえば時間 t から t_next まで、アクティブ セットは変化しません。 そのセグメントで 1 分あたりに達成可能な最高の幸福度を計算します。 アクティブなタイプ 3 インターバルが少なくとも 1 つある場合、1 分あたりの最適値は 2 です。そうでない場合、アクティブなタイプ 1 またはタイプ 2 インターバルが少なくとも 1 つある場合、最適な値は 1 です。アクティブなインターバルがない場合は、0 になります。 
5. この最良の値にセグメント t_next から t を引いた長さを乗算し、それを答えに加算します。 
6. t_next で発生するすべてのイベントに従ってアクティブなカウンターを更新し、続行します。 

重要なアイデアは、どの特定の映画を見るかを決める必要はなく、各時間セグメントで達成可能な最大の価値だけを決める必要があるということです。 

### なぜ効果があるのか

 フィルム間の切り替えにコストがかからないため、いつでも、その選択は将来の決定とは無関係です。 したがって、最適戦略はあらゆる時点で局所的に最適になります。 アクティブ セットはイベント境界でのみ変化するため、最適値はイベント間の各間隔内で一定です。 スイープ ラインにより、変化点を見逃すことなく、これらの最大セグメントを正確に評価できるようになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    events = []

    for _ in range(n):
        l, r, t = map(int, input().split())
        events.append((l, t, 1))
        events.append((r, t, -1))

    events.sort()

    cnt1 = cnt2 = cnt3 = 0
    ans = 0

    def value():
        if cnt3 > 0:
            return 2
        if cnt1 > 0 or cnt2 > 0:
            return 1
        return 0

    i = 0
    while i < len(events):
        j = i
        time = events[i][0]

        while j < len(events) and events[j][0] == time:
            j += 1

        if i > 0:
            prev_time = events[i - 1][0]
            ans += value() * (time - prev_time)

        for k in range(i, j):
            _, t, delta = events[k]
            if t == 1:
                cnt1 += delta
            elif t == 2:
                cnt2 += delta
            else:
                cnt3 += delta

        i = j

    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションは、各間隔が 2 つのエンドポイントに寄与するイベント リストを構築します。 これらのイベントを並べ替えることで、すべての変更が時系列順に処理されるようになります。 カウンタ cnt1、cnt2、および cnt3 は、現在存在する各タイプのアクティブな間隔の数を追跡します。 

重要な実装の詳細は、同じタイムスタンプを持つイベントをグループ化することです。 同一のタイムスタンプ内ではなく、異なる時点間の寄与のみを計算します。 関数 value() は、決定ルールをエンコードします。つまり、タイプ 3 がすべてに対して優位性を持ち、それ以外の場合はタイプ 1 またはタイプ 2 が単位の寄与を与えます。 

答えは、セグメントの長さとそのセグメント内で達成可能な最良の値を乗算して累積されます。 

## 実用的な例

 タイプ 1 間隔が 1 から 5 まで実行され、タイプ 2 間隔が 3 から 7 まで実行され、タイプ 3 間隔が 6 から 8 まで実行される入力を考えてみましょう。 

| 時間セグメント | アクティブタイプ1 | アクティブタイプ2 | アクティブタイプ3 | 最高の価値 |
 | --- | --- | --- | --- | --- |
 | 1 ～ 3 | 1 | 0 | 0 | 1 |
 | 3から5 | 1 | 1 | 0 | 1 |
 | 5から6 | 0 | 1 | 0 | 1 |
 | 6から7 | 0 | 1 | 1 | 2 |
 | 7から8 | 0 | 0 | 1 | 2 |

 このトレースは、答えがどの特定の間隔が選択されたかには依存せず、各セグメント内の最適なアクティブ タイプのみに依存する様子を示しています。 

ここで、タイプ 1 とタイプ 2 のみが重複し、タイプ 3 が存在しない場合を考えてみましょう。 両方がアクティブな場合でも、一度に 1 つの番組しか視聴できないため、値は 1 のままです。 

| 時間セグメント | アクティブタイプ1 | アクティブタイプ2 | アクティブタイプ3 | 最高の価値 |
 | --- | --- | --- | --- | --- |
 | 0から10 | 1 | 1 | 0 | 1 |

 これにより、重複する相補型が追加的に結合しないことが確認されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | 並べ替えイベントが支配的で、スキャンは直線的です |
 | スペース | O(n) | 各間隔で 2 つのイベントが生成されます。 

この制約では最大 100,000 の間隔が許可されるため、O(n log n) スイープ ラインは時間制限内に無理なく収まり、メモリ使用量はイベント数に比例したままになります。

 ## 特殊なケース

 重大なエッジケースは、複数のイベントが同じタイムスタンプで発生する場合です。 これらが適切にグループ化されていない場合、アルゴリズムは古いカウントを使用してセグメントを誤って計算する可能性があります。 正しく処理すると、次のセグメントを評価する前に、その時点でのすべての挿入と削除が確実に適用されます。 

もう 1 つのケースは、ある間隔がちょうど別の間隔が終了するときに開始する場合です。 この問題では半開間隔が定義されているため、エンドポイント処理では余分な重複がカウントされないようにする必要があります。 スイープ ラインは前に進む前に同じ座標でイベントを処理するため、隣接する間隔が人為的に重なりません。 

最後のケースは、セグメントにアクティブな間隔がない場合です。 value 関数は正しくゼロを返し、空の時間範囲が答えに寄与しないことが保証されます。
