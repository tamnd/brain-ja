 ## 解決策
 ## 問題の理解

 まず、基本的に 1、2、3、4、5 などの順序で書かれた自然数の無限シーケンスから始めます。 一連の削除操作の後にこのシーケンスがどのように変化するかに興味があります。 

各操作はステップ値 y によって定義されます。 このような操作が適用されると、現在のシーケンスをスキャンし、現在の既に縮小されたシーケンス内で位置が y の倍数であるすべての要素を削除します。 重要なのは、操作のたびに位置が再評価されることです。つまり、後の削除は、元のインデックスではなく、すでに圧縮されたシーケンスに作用します。 

このような操作を x 回実行すると、短縮されたシーケンスが残ります。 タスクは、この最終シーケンスの k 番目の要素の値を決定すること、またはシーケンスが短すぎる場合にはそのような要素が存在しないことを報告することです。 

k と y の制約は最大 10^18 と非常に大きく、演算数 x は最大 10^5 です。 これにより、シーケンス自体に対するシミュレーションが即座に除外されます。 シーケンスは概念的に無限であり、収縮は動的であるため、単一の明示的なシミュレーション ステップですら不可能です。 どのようなソリューションでも、要素をシミュレートするのではなく、削除の影響を数学的に推論する必要があります。 

削除が現在の位置に依存するという事実から、微妙な問題が発生します。 単純に解釈すると、進化するシーケンスではなく、元の番号付けに誤って削除が適用される可能性があり、これが誤った削除パターンにつながる可能性があります。 

もう 1 つのエッジ ケースは、k が結果のシーケンス サイズよりも大きくなる場合です。 シーケンスは最初は無限ですが、時間の経過とともに縮小するため、削除を繰り返すと、位置 k の前に有限数の要素だけが残るように、構造化された方法で無限に多くの位置が削除される可能性があります。 

## アプローチ

 ブルート フォース戦略では、シーケンスを明示的に維持し、y 番目の要素ごとに繰り返し削除します。 各操作の後、リストを再構築して続行します。 これは問題定義と正確に一致するため、概念的には機能します。 ただし、最大 10^18 のサイズのシーケンスの最初の削除でさえ、シーケンスを複数回走査することはおろか、シーケンスを保存することさえできないため、シミュレートすることは不可能です。 

重要な観察は、完全なシーケンスは決して必要ないということです。 私たちが気にするのは、生き残る数値の数と、元のインデックスから生き残るインデックスへのマッピングがどのようになるかだけです。 パラメーター y を使用した各削除では、現在のシーケンス内のすべての y 要素のうち 1 つが正確​​に削除されますが、重要なことに、これにより乗算圧縮効果が生じます。 複数の演算を処理した後の残りのシーケンスは、元の自然数を取得し、動的に変化する密度に従ってそれらをフィルター処理することに相当します。 個々の要素を追跡する代わりに、位置がどのようにスケールされるかを追跡します。 

これは、より単純な解釈につながります。つまり、すべての操作の後、残りのシーケンスは元のシーケンスと同様に動作しますが、「密度乗数」は縮小します。 ステップ y の各操作は、残りの y 番目ごとの要素の削除に関連する係数によって、使用可能なインデックスを効果的にスケールダウンします。 最終シーケンスの k 番目の要素は、圧縮が繰り返されたときに生き残ったランクが k に達する最小の元の数値に対応します。 

したがって、除去をシミュレートする代わりに、各概念フィルタリング段階後に元の位置がいくつ残っているかを追跡し、k に到達できるかどうかを判断します。

 ## アルゴリズムのチュートリアル

1. 元の無限シーケンス内のいくつの要素が最終シーケンス内の 1 つの要素に対応するかを表す変数を初期化します。 最初は 1 で、圧縮がまだ適用されていないことを意味します。 この値は、削除が適用されると変化します。 
2. パラメータ y を使用して各削除操作を順番に処理します。 各操作では、現在のシーケンス内の y 番目の要素がすべて削除されます。これは、すべての y 要素のうち y - 1 だけがローカルに残ることを意味します。 
3. 削除をシミュレートする代わりに、元のインデックスが存続するインデックスにどのようにマッピングされるかを表すスケーリング係数を更新します。 パラメーター y を使用して削除した後、生き残った要素の有効密度は (y - 1) / y で乗算されます。 
4. この圧縮ロジックの逆を繰り返し適用することにより、元の位置の数が k 個の生き残った要素に対応するかどうかの現在の推定値を維持します。 すべての操作を処理した後、k 番目の生き残った要素が元の無限シーケンスの到達可能な範囲内に存在するかどうかを判断します。 
5. k が累積生存率でサポートできる値を超えている場合は、すぐに -1 を返します。 それ以外の場合は、累積されたスケーリングを通じて k 番目の位置を逆変換することにより、k 番目の生き残り要素を計算します。 

### なぜ効果があるのか

 不変条件は、i 個の操作を処理した後、現在の圧縮シーケンスが、最初の i 個の操作から導出された固定乗算生存率に従って元のシーケンスから要素を選択することに正確に対応するということです。 各操作は相対的な位置にのみ依存するため、その効果は個々の要素の識別ではなく、密度をスケールする方法によって完全に把握されます。 シーケンスは単調であり、削除は現在のインデックスに対して周期的であるため、順序は保存され、k 番目の生き残った位置は、一意の元のインデックスが存在する場合には常に一貫してマップバックできます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    x, y, k = map(int, input().split())

    # We simulate how many elements remain as a fraction of original density.
    # Instead of exact floating values, we track upper bounds of reachable k.
    # We repeatedly compute how many elements survive conceptually.

    # We maintain the smallest original index that could produce k survivors.
    # Work backwards: if k-th exists, find smallest n such that after x operations
    # at least k elements survive up to n.

    # Since direct forward simulation is impossible, we reason multiplicatively:
    # each operation keeps (y-1)/y of current positions.

    # We track required expansion of k back to original scale.
    cur = k

    # Apply inverse effect of deletions: expand required index
    for _ in range(x):
        # After deletion by y, every y-th is removed in current sequence.
        # So to get cur surviving elements, we need roughly:
        # cur -> ceil(cur * y / (y-1))
        if y == 1:
            print(-1)
            return
        cur = (cur * y + (y - 2)) // (y - 1)

        if cur > 10**18:
            print(-1)
            return

    print(cur)

if __name__ == "__main__":
    solve()
```コードは逆に動作します。削除を順方向にシミュレートする代わりに、y 番目の要素ごとに繰り返し削除した後でも、その前に少なくとも k 個の要素が残るように、元の位置がどの位置に存在する必要があるかを尋ねます。 ループ内の各ステップは、必要な位置を上方に拡大縮小することによって 1 つの削除を元に戻します。 k が残りのブロックに均等に分割されない場合、天井分割により正確さが保証されます。 元のインデックスは問題の領域によって制限されるため、10^18 の上限により、意味のない値へのオーバーフローが防止されます。 

特殊なケースは y = 1 で、各操作ですべての要素が削除され、シーケンスが即座に破壊されます。 これは明示的に処理されます。 

## 実用的な例

 ### 例 1

 入力:```
2 3 5
```k = 5 から開始して cur を追跡します。 

| ステップ | y | 前に | 計算 | 後は
 | --- | --- | --- | --- | --- |
 | 1 | 3 | 5 | ceil(5 * 3 / 2) = 8 | 8 |
 | 2 | 3 | 8 | ceil(8 * 3 / 2) = 12 | 12 |

 最終的な答えは 12 です。 

このトレースは、各削除を元に戻すにつれて、必要な元の位置がどのように増加するかを示しています。 各操作では、その間に多くの位置が削除されるため、インデックスが増加します。 

### 例 2

 入力:```
20 2 1000000000000000
```cur = 10^15 から開始し、2 倍化を繰り返し適用します (y = 2 であるため)。 

各ステップの後、cur は約 2 * cur になり、すぐに 10^18 を超えます。 プロセスは -1 で早期終了します。 

これは、逆過程における指数関数的な増加と、大きな x がすぐに大きな k の不可能につながる理由を示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(x) | 各演算は一定の算術演算により 1 回処理されます。 
| スペース | お(1) | 少数の整変数のみが維持されます。 

この制約により最大 10^5 の演算が許可されるため、定数時間更新による線形パスオーバー演算は十分に高速になります。 10^18 での早期カットオフにより、算術演算は Python の整数制限内に留まります。

 ## 特殊なケース

 y が 1 に等しい場合、この操作により現在のシーケンスのすべての要素が即座に削除されます。 その状況では、x に関係なく、最初の適用後にシーケンスは空になります。 アルゴリズムはこのケースを明示的にチェックし、-1 を返します。 

k が非常に大きい場合、逆スケーリングを繰り返すと、cur はすぐに 10^18 を超えます。 有効な元のインデックスは問題の暗黙の境界を越えて存在できないため、アルゴリズムはこのオーバーフロー状態を検出し、早期に停止します。 

x が大きく y も大きい場合、ステップごとの増加は遅くなる可能性がありますが、乗算構造により cur の単調増加が保証されるため、シーケンスを明示的にシミュレートする必要がなく、終了条件は有効なままです。
