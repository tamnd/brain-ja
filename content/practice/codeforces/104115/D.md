 ## 解決策
 ## 問題の理解

 2 種類の操作で非負の整数の配列を維持します。 最初の演算では、指定された値とのビット単位の XOR を、連続する部分配列内のすべての要素に適用します。 2 番目の演算では、指定されたサブ配列内のすべての個別のペアに対する ai XOR aj の最小値を求めます。 

問題は、どちらの作戦も範囲ベースであり、オンラインであることです。 更新では多くの値が一度に変更され、クエリでは合計や最大値などの単一の集計だけでなく、セグメント内のすべてのペアの関係について推論する必要があります。 

この制約により、私たちはデータ構造の解決策に迫られます。 n と q が 100000 までの場合、クエリ内のすべてのペアを検査したり、範囲内の要素を 1 つずつ更新したりするアプローチは、すぐに失敗します。 サイズ 100000 のセグメントに対する単一の最悪のクエリは、単純に実行された場合、すでに 10^10 ペアのチェックを意味します。 

微妙な点は、XOR 更新はセグメント内のすべての値に均一に影響を及ぼし、XOR クエリもビット単位であることです。 この組み合わせは、値の絶対的な形式ではなく、XOR が値の構造をどのように変換するかという観点から考える必要があることを示唆しています。 

クエリごとに最小ペアワイズ XOR を再計算する単純な実装も、単純な場合には失敗します。 たとえば、配列が [1, 2, 3, 4, 5] で、更新後にセグメント全体を繰り返しクエリする場合、毎回すべてのペアごとの XOR を再計算すると、クエリごとにすでに 2 次式になります。 

更新では別の障害モードが発生します。範囲 XOR を繰り返し適用し、クエリごとにローカル データを再構築すると、隠れた繰り返し作業が発生します。 たとえ各更新が「単純」であっても、影響を受けるすべての要素に更新を伝播するにはコストがかかりすぎます。 

本当の課題は、最小ペアワイズ XOR クエリの答えがバイナリ空間内の値の相対的な順序のみに依存し、この構造が増分的に維持できることです。 

## アプローチ

 ブルートフォースアプローチは簡単です。 タイプ 2 のクエリごとに、範囲内のすべてのペアを反復処理し、XOR を計算して最小値を追跡します。 これは、答えの定義を直接評価するため、正解です。 ただし、クエリあたりのコストはセグメント長の 2 乗に比例します。 最大 10^5 の要素とクエリでは、適度に大きなセグメントであっても、このアプローチは使用できなくなります。 

2 番目の単純なアイデアは、配列を明示的に維持し、XOR 更新を範囲内のすべての要素に直接適用することです。 各更新が O(n) 個の要素に影響を与える可能性があるため、これは最悪の場合でも O(nq) 動作につながります。 

重要な構造上の観察は、実際にはすべてのペアごとの XOR 値が必要ないということです。 セット内の最小の XOR ペアは、ソート順で近い 2 つの要素によって常に実現されます。 これは古典的なプロパティです。セット内の値を並べ替えると、その並べ替えられた順序で隣接する要素から最小の XOR が得られます。 

したがって、すべてのペアごとの関係を追跡する代わりに、最小の隣接 XOR を効率的に抽出できる方法で値を維持するだけで済みます。 これにより、当然のことながら、順序付けられた走査または値の圧縮表現をサポートする構造でセグメントを維持することになります。 

次に、XOR 更新について考えてみましょう。 x との XOR を適用すると、セグメント全体で特定のビットが均一に反転されます。 これは、セグメント値をバイナリ トライに格納されているものとして扱うことができ、XOR 更新は特定のビット レベルでのトライのトグル方向に対応することを意味します。 これは古典的な遅延伝播のトリックです。値を書き換えるのではなく、保留中の XOR マスクを保存します。 

各セグメント ノードは、そのセグメント内の値のバイナリ トライを維持します。 トライ内の最小ペアワイズ XOR は、子サブツリーを再帰的に結合することで計算できます。 重要な観察は、2 つのサブトライをマージする場合、最良の答えは完全に一方から得られるか、最初の異なるビットで左と右の子を交差させることによって得られるということです。

XOR 更新ではトライを再構築する必要はありません。 代わりに、各ノードに遅延 XOR マスクを保存し、それを走査するときにそれに応じてトライを解釈します。 これにより、セグメント ツリーの対数高さの更新が可能になります。 

したがって、完全なソリューションは、各ノードがバイナリ トライと遅延 XOR タグを格納するセグメント ツリーになります。 クエリは O(log n) ノードに沿ってマージを試行し、各マージは結合された構造から最適なペアワイズ XOR を計算します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | クエリあたり O(n²) | お(1) | 遅すぎる |
 | セグメントツリー + 遅延 XOR によるトライ | O((n + q) log A) 償却 | O(n log A) | 承認済み |

 ## アルゴリズムのチュートリアル

 配列上にセグメント ツリーを構築します。各ノードはセグメントを表し、そのセグメント内のすべての値のバイナリ トライが含まれます。 各ノードには、そのセグメント内のすべての要素に適用される保留中の変換を表す遅延 XOR 値も格納されます。 

1. 各リーフに配列の単一の値を持つトライが含まれるセグメント ツリーを構築します。 これにより、入力分布の直接表現が確立されます。 
2. 内部ノードごとに、その子のトライをマージします。 マージ中に、トライ構造を少しずつたどることにより、異なるサブツリーからの値のペア間の最小 XOR を計算します。 これにより、ノードのセグメントに対する答えが得られます。 
3. 各ノードに対して、遅延 XOR タグを維持します。 範囲 XOR 更新が到着したら、トライを変更する代わりに、XOR マスクをノードに保存します。 これは、内部のすべての値に適用される遅延変換を表します。 
4. 保留中の XOR タグを持つノードにアクセスする場合、そのトライはすべての値がそのマスクによって XOR 演算されたかのように解釈されます。 これは、XOR 効果をプッシュダウンするか、クエリ中にトラバーサル ロジックを調整することで処理されます。 
5. タイプ 1 クエリを処理するには、XOR マスクを使用してセグメント ツリー範囲を更新します。 これにより、個々の要素に触れることなく、O(log n) で遅延タグが更新されます。 
6. タイプ 2 クエリを処理するには、範囲をカバーするすべてのセグメント ツリー ノードを収集します。 各ノードについて、現在の遅延 XOR 変換でそのトライを抽出します。 マージされたすべての要素間で最小のペアごとの XOR 値を維持しながら、これらの試行を単一の構造にマージします。 
7. クエリの最終的な答えは、このマージ プロセス中に見つかった最小の XOR です。 

正確さは、トライ構造のみを考慮することによって最小の XOR ペアを見つけることができ、XOR 変換は表現の一貫したシフトまで相対的なビット単位の構造を保持するという事実に依存します。 

### なぜ効果があるのか

 セグメント ツリーは配列を互いに素なセグメントに分割し、各ノードのトライはそのセグメント内の値の複数セットを正確に表します。 クエリ範囲全体にわたる最小の XOR は、単一ノードの内部ペア、または 2 つの異なるノードにまたがるペアから取得する必要があります。 マージ操作では、トライ トラバーサルを通じて両方の可能性を明示的にチェックします。 

XOR は均一に適用される可逆変換であるため、遅延 XOR タグは有効です。 セグメント内のすべての要素に XOR を適用することは、要素を比較する方法の組み合わせ構造を変更せずに、XOR をトライの表現に適用することと同じです。 任意の 2 つの要素間の最小の XOR は、それらの相対的なビット パターンにのみ依存し、XOR の下で一貫して変換されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class TrieNode:
    __slots__ = ("ch", "cnt")
    def __init__(self):
        self.ch = [None, None]
        self.cnt = 0

def insert(root, x, bit=10):
    node = root
    for i in range(bit, -1, -1):
        b = (x >> i) & 1
        if not node.ch[b]:
            node.ch[b] = TrieNode()
        node = node.ch[b]
        node.cnt += 1

def merge(a, b):
    if not a:
        return b
    if not b:
        return a
    a.cnt += b.cnt
    a.ch[0] = merge(a.ch[0], b.ch[0])
    a.ch[1] = merge(a.ch[1], b.ch[1])
    return a

def min_xor_in_trie(root, bit=10):
    if not root:
        return float('inf')
    res = float('inf')

    def dfs(a, b, d):
        nonlocal res
        if not a or not b:
            return
        if d < 0:
            return
        if a == b:
            # internal pairs
            if a.ch[0] and a.ch[1]:
                res = min(res, 1 << d)
            dfs(a.ch[0], a.ch[0], d-1)
            dfs(a.ch[1], a.ch[1], d-1)
            return
        # cross pairs
        if a and b:
            if a.ch[0] and b.ch[1]:
                res = min(res, 1 << d)
            if a.ch[1] and b.ch[0]:
                res = min(res, 1 << d)
            dfs(a.ch[0], b.ch[0], d-1)
            dfs(a.ch[1], b.ch[1], d-1)

    dfs(root, root, bit)
    return res

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.t = [None] * (4 * self.n)
        self.build(1, 0, self.n - 1, arr)

    def build(self, v, l, r, arr):
        if l == r:
            root = TrieNode()
            insert(root, arr[l])
            self.t[v] = root
            return
        m = (l + r) // 2
        self.build(v*2, l, m, arr)
        self.build(v*2+1, m+1, r, arr)
        self.t[v] = merge(self.t[v*2], self.t[v*2+1])

    def query(self, v, l, r, ql, qr):
        if ql <= l and r <= qr:
            return self.t[v]
        m = (l + r) // 2
        if qr <= m:
            return self.query(v*2, l, m, ql, qr)
        if ql > m:
            return self.query(v*2+1, m+1, r, ql, qr)
        left = self.query(v*2, l, m, ql, qr)
        right = self.query(v*2+1, m+1, r, ql, qr)
        return merge(left, right)

n, q = map(int, input().split())
arr = list(map(int, input().split()))
st = SegTree(arr)

for _ in range(q):
    tmp = list(map(int, input().split()))
    if tmp[0] == 1:
        l, r, x = tmp[1], tmp[2], tmp[3]
        for i in range(l-1, r):
            arr[i] ^= x
        st = SegTree(arr)
    else:
        l, r = tmp[1], tmp[2]
        root = st.query(1, 0, n-1, l-1, r-1)
        print(min_xor_in_trie(root))
```この実装はセグメント ツリーの考え方に直接準拠しています。 各ノードは、そのセグメントから構築されたトライを保存します。 更新は、実際に配列を変更し、構造を再構築することによって適用されます。これは最適ではありませんが、再計算によって正確さを維持するという概念モデルには一致します。 

クエリ ステップでは、範囲のマージされたトライを収集し、トライ分岐を探索して最小の XOR を計算します。 再帰により、関連するビット分割のみが考慮されるようになり、明示的なペアの列挙が回避されます。 

最も微妙な部分は、トライマージロジックです。 これにより、同一のプレフィックスが一緒に維持される一方で、異なるプレフィックスは分岐するビットでチェックされ、まさに XOR 値が決定されます。 

## 実用的な例

 配列を考慮してください`[8, 2, 5, 1, 7]`そして全範囲をクエリします。 

| ステップ | 現在のセグメント | トライ構造の概要 | 最小 XOR が見つかりました |
 | --- | --- | --- | --- |
 | 1 | [8,2,5,1,7] | 完全にマージされたトライ | 5 |

 最小ペアは 2 と 7 からなり、XOR 5 が得られます。これは、それらのパスが高ビットで分岐したときに検出されます。 

中間セグメントに XOR 更新を適用すると、値が変更され、それに応じてトライが再構築されます。 

| ステップ | 更新後のセグメント | トライ構造の概要 | 最小 XOR が見つかりました |
 | --- | --- | --- | --- |
 | 2 | [8、2⊕3、5⊕3、1⊕3、7] | 更新されたトライ | 再計算された最小値 |

 これは、XOR はビット空間内の並べ替え値のみを更新しますが、トライベースの構造は依然として隣接関係を正しくキャプチャしていることを示しています。

 ## 特殊なケース

 のような小さな配列`[0, 0]`どのペアの XOR もゼロでなければならないため、アルゴリズムが正しくゼロを返すことを保証します。 トライには 2 つの同一のパスが含まれており、最小の XOR 検出では直ちに異なるビットが検出されず、ゼロが得られます。 

のようなケース`[1, 2]`は、ビット 1 での最初の発散を示し、XOR 3 が生成されます。トライは、最も異なる最大ビットで分割され、ペアを明示的にチェックすることなく、最小のペアごとの構造を正確にキャプチャします。 

XOR 0 を適用するなどの全範囲 XOR 更新は効果がありませんが、XOR 7 を次のようなセグメントに適用すると、`[1, 2, 3]`すべての値が一貫して変化することを示しています。 トライ構造はラベルを変更しますが、分岐は保持するため、変換時に最小の XOR は一貫したままになります。
