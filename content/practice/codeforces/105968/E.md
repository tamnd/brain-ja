 ## 解決策
 ## 問題の理解

 私たちは、長方形のマップ内で移動が発生するグリッドベースの最短経路問題に取り組んでいます。 各セルは自由または壁でブロックされており、開始点、目的地の出口、バッジの位置などの特別なセルがあります。 プレイヤーは特定の禁止されたセルを避けながらグリッド内を移動でき、シナリオごとに異なる移動制限が課されます。 

タスクは、開始点から出口に到達するまでの最小時間を計算することですが、ちょっとした工夫があります。特別な中間位置が関係するかどうかに応じて、2 つの異なる横断モードがあります。 1 つのモードでは壁とマークされたパスの両方を回避できますが、別のモードでは壁を回避することのみが必要です。 最適な答えは、より厳しい制約の下で出口に直接到達するか、より厳しい制約の下で最初にバッジに到達し、次により緩やかな制約の下でバッジから出口まで継続するかのいずれかです。 

このソリューションはグリッド全体で BFS に依存するため、グリッド サイズは通常、合計で最大数千セルになります。 これにより、セルごとの線形または線形対数よりも悪いものは直ちに排除されます。 定数を超えて多くの状態に対して最短パスを個別に再計算する試みは、各計算が O(NM) である場合にのみ許容されます。 セルごとの立方体または繰り返しのフラッドフィルは、明らかに制限を超えます。 

より厳しい制約ではバッジが到達できないが、より緩やかな制約では到達できる場合、またはその逆の場合、微妙なエッジ ケースが発生します。 もう 1 つのケースは、開始がバッジまたは終了と一致する場合で、これにより 2 つの候補パスのうちの 1 つが崩壊する可能性があります。 たとえば、S が B に等しい場合、第 2 項は壁制約のみの下では単に S から E への最短経路となり、これを考慮しないと不必要な再計算や誤った二重カウントが発生します。 

## アプローチ

 この問題を直接解釈すると、異なる制約セットの下で複数の点ペア間の最短経路を計算することが示唆されます。 単純な考えは、厳格なルールの下で S から E への最短経路探索を実行し、次に厳格なルールの下で S から B へ、最後に緩和されたルールの下で B から E への最短経路探索を実行することです。 移動コストが均一であるため、これらはいずれも BFS で実行できます。 

このブルート フォース アプローチは、構造的にはすでに最適に近づいていますが、クエリごと、または状態変化ごとに動的に BFS を個別に再計算しようとすると、重要な非効率性が生じます。 グリッド上の BFS は O(NM) であるため、一定回数の BFS 実行を行うことで安全は保たれますが、分離せずに単一の BFS 内の制約の組み合わせを探索しようとするアプローチはエラーが発生しやすく、不必要になります。 

重要な観察は、制約が正確に 2 つの独立した最短経路問題にきれいに分割されていることです。1 つは壁とマークされたセルの両方が禁止されているグラフ、もう 1 つは壁のみが禁止されているグラフです。 これを理解すると、問題は 2 つの BFS 距離フィールドを計算することになります。1 つは両方の制限を考慮した S からの制限された BFS、もう 1 つは B または構造に応じてすべてのソースからのマークされたセルによって制限されていない BFS です。 

解決策は、事前に計算された距離を単純な式で組み合わせるだけです。厳密なルールに基づく距離(S, E)と、厳密なルールに基づく距離(S, B) + 壁のみのルールに基づく距離(B, E)です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとに BFS を分けるというアイデア | O(1) BFS 呼び出し、各 O(NM) | O(NM) | 承認済み |
 | 最適なデュアル BFS 事前計算 | O(NM) | O(NM) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 同じマップ表現上に 2 つの論理グリッドを構築します。 最初のグリッドは壁とマークされたパス セルの両方をブロックされたものとして扱いますが、2 番目のグリッドは壁のみをブロックされたものとして扱います。 この分離により、各 BFS が一貫した静的グラフで動作することが保証されます。 
2. 厳密なグリッド上の開始セル S から BFS を実行します。 S から到達可能なすべてのセルまでの最短距離を記録します。 これにより、壁とマークされたセルの両方を回避するすべてのパスがキャプチャされます。 
3. この最初の BFS から 2 つの値を抽出します。厳密なルールに基づく S から E までの距離と、厳密なルールに基づく S から B までの距離です。 これらは、最初の候補パスと 2 番目の候補パスの最初のセグメントに直接対応します。 
4. 壁のみがブロックされているリラックスしたグリッド上のバッジ セル B から 2 番目の BFS を実行します。 B から到達可能なすべてのセルまでの距離を記録します。 これにより、バッジを収集した後の移動時間が最短になります。 
5. 2 番目の BFS から B から E までの距離を抽出します。 これは、制限が弱いルートの 2 番目のセグメントを表します。 
6. S から E への直接の厳密なパスと、S から B (厳密) と B から E (緩和) を組み合わせたパスの間の最小値として最終的な答えを計算します。 これらの距離のいずれかが到達できない場合は、それらを無限として扱い、最小限に抑えて無視します。 

なぜ効果があるのか

 正しさは、有効な最適ルートが B を決して通過してはならないか、非負の一様エッジ重みを持つグリッド内で 1 回だけ B を通過しなければならないという事実に基づいています。 B を通過する場合、BFS は各固定制約グラフ内の最短パスを保証するため、S から B および B から E へのセグメント分解が最適になります。 2 つの制約セットは 2 つの別々の静的グラフを定義するため、最短パスを個別に再計算すると、最適な下部構造が保存され、フェーズ間の干渉が防止されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

INF = 10**18

def bfs(start_r, start_c, grid, n, m, forbid_marked):
    dist = [[INF] * m for _ in range(n)]
    q = deque()
    dist[start_r][start_c] = 0
    q.append((start_r, start_c))

    while q:
        r, c = q.popleft()
        for dr, dc in ((1,0), (-1,0), (0,1), (0,-1)):
            nr, nc = r + dr, c + dc
            if 0 <= nr < n and 0 <= nc < m:
                if grid[nr][nc] == '#':
                    continue
                if forbid_marked and grid[nr][nc] == '*':
                    continue
                if dist[nr][nc] == INF:
                    dist[nr][nc] = dist[r][c] + 1
                    q.append((nr, nc))
    return dist

def solve():
    n, m = map(int, input().split())
    grid = []
    for _ in range(n):
        grid.append(list(input().strip()))

    sr = sc = br = bc = er = ec = -1

    for i in range(n):
        for j in range(m):
            if grid[i][j] == 'S':
                sr, sc = i, j
            elif grid[i][j] == 'B':
                br, bc = i, j
            elif grid[i][j] == 'E':
                er, ec = i, j

    dist_strict = bfs(sr, sc, grid, n, m, forbid_marked=True)
    dist_relaxed = bfs(br, bc, grid, n, m, forbid_marked=False)

    ans = dist_strict[er][ec]
    via_badge = dist_strict[br][bc] + dist_relaxed[er][ec]

    ans = min(ans, via_badge)

    print(ans if ans < INF else -1)

if __name__ == "__main__":
    solve()
```BFS 関数はコア抽象化です。 マークされたセルを壁として扱うかどうかを決定する単一のブール フラグによって、両方の制約システムをエンコードします。 これにより、2 つのグラフ モデルを区別しつつ、ロジックの重複が回避されます。 

最初の BFS は S をルートとしており、両方の制限を強制し、禁止されたマーク付きセルに触れることのないすべての最短パスを生成します。 2 番目の BFS は B をルートとしており、マークされたセルを無視します。これは、バッジを収集した後、壁のみが関連するという事実を反映しています。 

最後の結合ステップは問題の分解を直接反映しています。S から E に直接進むか、B で行程を分割します。 

実装でよくある落とし穴は、到達不可能な状態を適切に処理することを忘れることです。 大きなセンチネル値を使用し、加算する前にそれをチェックすると、無限大の算術演算によって有効ではあるが誤解を招く比較が生成される、Python でのオーバーフローのようなロジック エラーが回避されます。 

## 実用的な例

 S が E に直接行くか、B を迂回するかのどちらかを選択しなければならない小さなグリッドを考えてみましょう。 

### 例 1

 グリッド:```
S . .
* # .
B . E
```S からの厳密な BFS:

 | ステップ | セル | 距離 |
 | --- | --- | --- |
 | 1 | S | 0 |
 | 2 | (0,1) | 1 |
 | 3 | (0,2) | 2 |
 | 4 | (1,0) ブロックされました | - |
 | 5 | B | 2 |
 | 6 | E | 3 |

 B からのリラックスした BFS:

 | ステップ | セル | 距離 |
 | --- | --- | --- |
 | 1 | B | 0 |
 | 2 | (2,1) | 1 |
 | 3 | E | 2 |

 S から E への直接は 3、B 経由は 2 + 2 = 4 なので、答えは 3 です。 

これは、バッジに早く到達できる場合でも、直接ルートが最適なままであるケースを示しています。 

### 例 2

 グリッド:```
S * #
. * .
. B E
```S からの厳密な BFS はブロックされた構造のため E に直接到達できませんが、B には到達できます。 

| セル | 距離 |
 | --- | --- |
 | S | 0 |
 | B | 3 |

 B からのリラックスした BFS:

 | セル | 距離 |
 | --- | --- |
 | B | 0 |
 | E | 1 |

 したがって、答えは 3 + 1 = 4 となります。 

これにより、両方の BFS 結果を組み合わせる必要性が確認されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(NM) | 各 BFS は各セルを最大 1 回訪問し、一定の数の BFS トラバーサルを実行します。 
| スペース | O(NM) | 距離配列には、各 BFS のグリッド セルごとに 1 つの値が格納されます。 

グリッド サイズは BFS コストを直接制限し、走査が 2 回だけ実行されるため、ソリューションはグリッド問題の一般的な制約内に問題なく適合します。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque

    INF = 10**18

    def bfs(sr, sc, grid, n, m, forbid):
        dist = [[INF]*m for _ in range(n)]
        q = deque()
        dist[sr][sc] = 0
        q.append((sr, sc))
        while q:
            r, c = q.popleft()
            for dr, dc in ((1,0),(-1,0),(0,1),(0,-1)):
                nr, nc = r+dr, c+dc
                if 0 <= nr < n and 0 <= nc < m:
                    if grid[nr][nc] == '#':
                        continue
                    if forbid and grid[nr][nc] == '*':
                        continue
                    if dist[nr][nc] == INF:
                        dist[nr][nc] = dist[r][c] + 1
                        q.append((nr, nc))
        return dist

    n, m = map(int, input().split())
    grid = [list(input().strip()) for _ in range(n)]

    sr=sc=br=bc=er=ec=-1
    for i in range(n):
        for j in range(m):
            if grid[i][j]=='S': sr,sc=i,j
            if grid[i][j]=='B': br,bc=i,j
            if grid[i][j]=='E': er,ec=i,j

    ds = bfs(sr, sc, grid, n, m, True)
    db = bfs(br, bc, grid, n, m, False)

    ans = min(ds[er][ec], ds[br][bc] + db[er][ec])
    return str(ans if ans < INF else -1)

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、厳しい制約の下でバッジにアクセスできない場合です。 その場合、`dist_strict[B]`無限大になります。 有限の緩和距離に無限大を追加すると値が無効になり、最小値はそのルートを正しく無視するため、アルゴリズムは引き続き正しく動作します。 

もう 1 つのケースは、S が B に等しい場合です。この場合、厳密な BFS はすでに S から B までの距離をゼロとして計算しています。 この公式は、厳密なルールの下での直接の S から E と、緩和されたルールの下での S から E を比較することになり、アルゴリズムは自然に 2 つのうちのより良い方を選択します。 

3 番目のケースは、E が B に等しい場合です。この場合、宛先が BFS ソースでゼロが与えられるため、2 番目の BFS は自明になり、答えは直接の厳密な距離または B 自体への厳密な距離のいずれかになります。
