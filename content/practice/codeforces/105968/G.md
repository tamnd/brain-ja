 ## 解決策
 ## 問題の理解

 このタスクは、実数値多項式のすべての実数根を固定区間内、具体的には -30 から 30 までの範囲内で高精度に見つけることです。 多項式は入力形式 (通常は係数として) で与えられ、出力ではこの領域内にあるすべての根を報告する必要があります。 

多項式を記号的に解こうとする代わりに、この問題は数値評価に依存しています。 重要な構造上の事実は、この関数が実線上のどこでも連続であるため、区間内の符号の変化はその区間内で少なくとも 1 つの根を保証するということです。 

必要な精度は 10⁻⁶ のオーダーであり、純粋に離散的な答えやグリッドのみの答えは即座に除外されます。 粗いスキャンは、ルートが存在する可能性のある場所を検出する場合にのみ役立ち、最終値には役立ちません。 

また、間隔が十分に大きいため、あらゆる場所で直接詳細にサンプリングするとコストが高くなります。 60 単位で 10⁻⁶ の均一ステップを試した場合、関数は約 6 × 10⁷ 回評価され、各評価自体は多項式次数で O(n) になります。 制約によっては、限界ぎりぎりになったり、遅すぎたりします。 

素朴ではあるが一般的な失敗モードは、スキャン間隔のエンドポイントのみをチェックし、すべての符号変化間隔にルートが 1 つだけ含まれていると想定することです。 これは、多項式が軸に触れ、それを横切らずに回転すると壊れます。 

たとえば、(x − 1)² のような多項式を考えてみましょう。 x = 1 に根がありますが、f(x) はその点の周囲で符号を変更しません。 符号の変化のみに依存する方法では、それを完全に見逃してしまいます。 

もう 1 つの失敗モードは、ルートが整数または固定グリッド境界によってきれいに分離されていると仮定することです。 根は 0.5 や -0.5 などの境界近くに任意に存在する可能性があり、改良しないと近似が不安定になります。 

## アプローチ

 強引な解釈では、[-30, 30] にわたる非常に細かいグリッドで多項式を評価し、符号の変化を検出し、必要な精度に達するまで各候補区間を調整します。 これが機能するのは、グリッドが十分に密であれば、連続性によってサンプル ポイント間に根がどこからともなく現れることがないためです。 

ただし、グリッドの解像度によってコストが発生します。 10⁻⁶ のステップを選択すると、約 6,000 万回の評価が実行されます。 d 次多項式の各評価には O(d) のコストがかかるため、合計は O(6 × 10⁷ · d) となり、これは一般的な制約には遅すぎます。 

改善は、問題を 2 つの段階に分けることで実現します。 まず、正確な位置ではなく、ルートを含む小さな間隔を特定する必要があるだけです。 これには、幅 0.5 の粗い分割で十分です。これは、単一の小さなセグメント内に多数の根をすでに生成していなければ、多項式は任意の速度で振動することができないためです。 

候補区間が見つかると、第 2 段階でその区間に対して二分探索が使用されます。 関数は連続であり、符号の変化が想定される (または有効なルート条件が検出される) ため、二分探索は必要な精度で対数的にルートに収束します。 これにより、高密度のグローバル グリッドの必要性が、少数の対象を絞ったローカル検索に置き換えられます。 

重要な考え方は、ルートが存在することが保証されている場合にのみ、高価な作業が行われるということです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 均一な細かいグリッドのサンプリング | O(60・10⁶・d) | お(1) | 遅すぎる |
 | 粗いスキャン + バイナリ検索の絞り込み | O(120 · d + k · d · log(1/ε)) | お(1) | 承認済み |

 ここで、k は検出されたルートを含むセグメントの数です。 

## アルゴリズムのチュートリアル

 多項式を、ホーナー法を使用して任意の実数 x で評価できる関数 f(x) として扱います。

1. 区間 [-30, 30] を長さ 0.5 のセグメントに分割します。 これらのセグメントは、[-30、-29.5]、[-29.5、-29] などです。 目的は、潜在的な兆候の変化を安価に局所化することです。 
2. 各セグメント [l, r] について、f(l) と f(r) を評価します。 f(l) が正確にゼロの場合、l をルートとして直ちに記録します。 エンドポイントには正確なルートが含まれる可能性があるため、同じことが r にも当てはまります。 
3. f(l) と f(r) の符号が反対の場合、[l, r] 内で二分探索を実行して根を見つけます。 符号の違いにより、連続性により少なくとも 1 つの交差が保証されます。 
4. 符号の変化は存在しないが、値が (わずかな許容範囲内で) ゼロに非常に近い場合は、セグメントを根が含まれている可能性があるものとして扱います。 これは、関数が軸に触れているが交差していない繰り返しルートのようなケースを処理します。 
5. 区間幅が 10⁻⁶ 未満になるまで、各候補区間で二分探索を実行します。 最後の間隔の中点がルートとみなされます。 
6. 検出されたすべてのルートを収集し、出力前にそれらを並べ替えて、決定的な順序を確保します。 

ここで二分探索が適用される理由は、ルートが 1 つだけ含まれる十分に小さい区間にわたる符号の単調性です。 このような区間を分離すると、関数はゼロを 1 回横切る連続曲線のように動作します。 

### なぜ効果があるのか

 正確さは連続関数の中間値特性に基づいています。 多項式は、すべての中間値を通過することなく値を変更することはできません。 f(l) と f(r) の符号が異なる場合、それらの間のどこかにゼロが存在する必要があります。 

0.5 セグメンテーションにより、ルートは境界で直接検出されるか、少なくとも 1 つの小さな間隔内にトラップされることが保証されます。 その区間内では、問題を根の分離に還元します。関数が連続であり、区間を縮小しても符号構造が安定しているため、二分探索は収束します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

EPS = 1e-12

def eval_poly(coeffs, x):
    # Horner's method
    res = 0.0
    for c in coeffs:
        res = res * x + c
    return res

def find_root(coeffs, l, r):
    fl = eval_poly(coeffs, l)
    fr = eval_poly(coeffs, r)

    if abs(fl) < EPS:
        return l
    if abs(fr) < EPS:
        return r

    # assume sign change exists
    for _ in range(60):
        m = (l + r) / 2
        fm = eval_poly(coeffs, m)

        if abs(fm) < EPS:
            return m

        if fl * fm <= 0:
            r = m
            fr = fm
        else:
            l = m
            fl = fm

    return (l + r) / 2

def solve():
    data = sys.stdin.read().strip().split()
    if not data:
        return

    # assumed format:
    # n followed by coefficients c0..cn (or similar)
    it = iter(data)
    deg = int(next(it))
    coeffs = [float(next(it)) for _ in range(deg + 1)]

    roots = []

    L, R = -30.0, 30.0
    step = 0.5

    x = L
    while x < R:
        l = x
        r = min(R, x + step)

        fl = eval_poly(coeffs, l)
        fr = eval_poly(coeffs, r)

        if abs(fl) < EPS:
            roots.append(l)
        if abs(fr) < EPS:
            roots.append(r)

        if fl * fr < 0:
            roots.append(find_root(coeffs, l, r))

        x += step

    roots.sort()

    # print with sufficient precision
    out = []
    for r in roots:
        out.append(f"{r:.10f}")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```このソリューションは、ホーナー法を使用した高速多項式評価器と、有界区間内に根が存在すると仮定する制御された二分探索という 2 つのコア ユーティリティを中心に構成されています。 セグメンテーション ループは検出を担当し、リファインメント関数は精度を担当します。 

実装の微妙な詳細は、エンドポイントをルートとして繰り返し検出することです。 これを行わないと、セグメント境界に正確にあるルートが欠落したり、一貫性なく複製されたりする可能性があります。 どのセグメントが最初にルートを検出するかに応じて、ルートが任意の順序で検出される可能性があるため、最後にソートが必要です。 

二分探索ループは固定反復回数 (約 60) を使用します。これは、浮動小数点ドリフトに関係なく、60 単位間隔を 10⁻⁶ 未満の精度に減らすのに十分です。 

## 実用的な例

 ### 例 1

 f(x) = x − 2 など、範囲内に根が 1 つある単純な多項式を想定します。 

ルートを含む 1 つのセグメントを追跡します。 

| ステップ | l | r | f(l) | f(r) | アクション |
 | --- | --- | --- | --- | --- | --- |
 | セグメントチェック | 1.5 | 2.0 | -0.5 | 0.0 | エンドポイント ルートが検出されました |
 | 洗練 | 1.5 | 2.0 | - | - | 二分探索はスキップされました |

 エンドポイント検出では x = 2 がすぐにキャプチャされ、エンドポイント チェックが必要な理由がわかります。 

### 例 2

 f(x) = (x + 1)(x − 1) を考えます。これは、−1 と 1 に根があります。 

| セグメント | l | r | f(l)・f(r) | アクション |
 | --- | --- | --- | --- | --- |
 | [-1.5、-1.0] | -1.5 | -1.0 | ≤ 0 | -1 の二分探索 |
 | [0.5、1.0] | 0.5 | 1.0 | ≤ 0 | 1 | の二分探索

 各間隔はルートを 1 つだけ分離し、二分探索は独立して収束します。

 ## 特殊なケース

 (x − 1)² のような繰り返し根は、符号変化検出だけでは不十分である理由を示しています。 x = 1 では、関数はゼロですが、両側は正のままであるため、セグメンテーションでは端点と中間点でゼロに近い値がないか明示的にチェックする必要があります。 セグメント ループのエンドポイント チェックにより、符号反転がなくてもルートがキャプチャされることが保証されます。 

x = 0.5 のようにセグメント境界上に正確に位置するルートは、各間隔の両方の終点を評価することによって処理されます。 隣接する両方のセグメントが評価の境界点を共有するため、少なくとも 1 つのチェックでゼロに近い値が登録され、ルート リストに含まれます。
