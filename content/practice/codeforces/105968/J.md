 ## 解決策
 ## 問題の理解

 私たちは 2 種類の演算がサポートされている整数の動的配列を扱っています。 1 つの操作は 1 つの位置の値を変更し、もう 1 つの操作は配列の連続したセグメントに関する情報を要求します。 セグメントに対するクエリは、合計や最大要素のような単純な集計ではありません。 代わりに、そのセグメント内全体で連続する部分配列を選択することによって得られる可能な限り最良の合計を求めます。 

つまり、どのクエリ範囲に対しても$[l, r]$、すべての部分配列がその範囲に完全に含まれているとみなして、それらの間で可能な最大の合計を取得します。 配列は変更可能であるため、更新後、今後のクエリには変更された値が反映される必要があります。 

入力サイズは最大約$10^5$これにより、セグメントをスキャンすることによる各クエリの再計算が即座に除外されます。 クエリごとに単純に再計算すると、次のような結果が得られます。$O(n)$クエリごとに作業し、$O(nq)$全体的な複雑さは実現可能な限界をはるかに超えています。 

主な難点は、セグメント クエリでは、境界を越えて最適なサブ配列を再構築するのに十分な構造を保持する方法で、2 つの半分からの情報を結合する必要があることです。 

いくつかの特殊なケースでは、誤った貪欲またはプレフィックスベースの試行が中断される傾向があります。 

すべての数値が負の場合、1 つの問題が発生します。 たとえば、配列では$[-5, -2, -7]$、範囲クエリの正しい答えは次のとおりです。$-2$空ではない部分配列を選択する必要があるためです。 「空の部分配列は合計 0 で許可される」と想定する単純なアプローチでは、誤って 0 が返されます。 

別の問題は、最適な部分配列が分割の中点を横切るときに発生します。 たとえば、$[2, -1, 3]$、範囲全体に対する最良の答えは次のとおりです。$4$、配列全体から取得されます。 左半分と右半分で最適な回答のみを個別に追跡するアプローチでは、この境界を越えた組み合わせを見逃すことになります。 

3 番目の微妙なケースは、更新時に発生します。 単一の値を変更した後、キャッシュされたセグメント情報は、セグメント ツリー内のすべての祖先にわたって一貫性を保つ必要があります。 すべての派生属性の再計算に失敗すると、プレフィックスまたはサフィックス データが古くなり、その後のクエリが静かに中断されます。 

## アプローチ

 ブルートフォースアプローチは簡単です。 範囲に対するクエリごとに$[l, r]$、範囲内のすべての可能な開始点と終了点を反復処理し、各部分配列の合計を計算します。 発生した最大額を追跡します。 これは正しいです。なぜなら、すべての候補サブ配列を明示的にチェックし、最適なサブ配列を見逃す可能性を残さないからです。 

ただし、実際には 3 つのネストされた層の作業が必要です。 各クエリには、$O(n)$スキャンに時間がかかり、サブ配列の列挙に単純に実装するとさらに劣化します。 まで$10^5$クエリの場合、これは効果的に行われます$10^{10}$最悪の場合は操作ができなくなり、使用できなくなる可能性があります。 

重要な観察は、セグメントの答えがその 2 つの部分に関するコンパクトな情報から構築できるということです。 すべてのサブ配列を保存するのではなく、境界を越える可能性のある最適なサブ配列を再構築するために必要なものだけを保存します。 

各セグメントについて、4 つの値を維持します。 セグメントの合計、セグメント内の任意の場所の最良のプレフィックスの合計、最良のサフィックスの合計、および最良のサブ配列の合計。 結合セグメント内の最適なサブ配列は完全に左半分にあるか、完全に右半分にあるか、境界を越えているため、これら 4 つの値で十分です。 交差格は、左半分の接尾辞と右半分の接頭辞を使用して表現できます。 

これにより、各マージ操作が一定時間に短縮され、更新とクエリの両方が対数時間で動作するセグメント ツリーが可能になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(nq)$|$O(1)$| 遅すぎる |
 | カスタム ノードを含むセグメント ツリー |$O((n + q)\log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 セグメント ツリーの各ノードは配列のセグメントを表し、そのセグメントに対するクエリに答えるのに十分な集約情報を格納します。 

1. 各リーフが単一の配列要素に対応するセグメント ツリーを構築します。 リーフの場合、総和、接頭辞、接尾辞、および最良の部分配列はすべて要素自体と等しくなります。 単一の要素には内部構造がないため、これは基本的なケースです。 
2. 隣接するセグメントを表す 2 つの子ノードを結合するマージ操作を定義します。 この操作は、境界を越えたサブ配列に必要な情報が決して失われないようにするため、ソリューションの中核となります。 
3. 左側のノードをマージする場合$A$そして右のノード$B$、合計を次のように計算します。$A.sum + B.sum$。 合計は互いに素な区間にわたって加算されるため、これは直接的です。 
4. マージされたセグメントの最適なプレフィックスを、次のセグメント間の最大値として計算します。$A.prefix$そして$A.sum + B.prefix$。 これにより、最適なプレフィックスが完全に左側のセグメントに留まるか、右側のセグメントにまで及ぶかがキャプチャされます。 
5. 間の最大値として対称的に最適なサフィックスを計算します。$B.suffix$そして$B.sum + A.suffix$。 これにより、最適なサフィックスが右側のセグメントに留まるか、左側のセグメントに拡張されるかがキャプチャされます。 
6. 3 つの可能性のうちの最大値として最良のサブ配列を計算します。つまり、左側のセグメント全体にある最良のサブ配列、右側のセグメント全体にある最良のサブ配列、または次のように境界を横切る最適なサブ配列です。$A.suffix + B.prefix$。 このステップは、最適なサブアレイのすべての構造的可能性を明示的に列挙するため、中心的なアイデアです。 
7. 更新の場合は、リーフ ノードを変更し、マージ操作を使用してそのすべての祖先を再計算します。 これにより、変更された位置からルートまでの一貫性が保証されます。 
8. クエリの場合、関連するセグメントを正しい順序で再帰的に結合します。 最終的にマージされたノードには、その最良のサブ配列フィールドに答えが含まれています。 

正確さは、すべてのノードが 4 つの値のみを使用してセグメント内のすべてのサブ配列を完全に要約するという不変式に依存します。 セグメント内のすべての部分配列は、1 つの子に完全に含まれるか、境界を 1 回だけ越えます。 マージ操作では 3 つの構造の可能性すべてが考慮されるため、集約中に候補サブ配列が失われることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Node:
    __slots__ = ("sum", "pref", "suff", "best")
    def __init__(self, s=0, p=0, sf=0, b=0):
        self.sum = s
        self.pref = p
        self.suff = sf
        self.best = b

def merge(a, b):
    res = Node()
    res.sum = a.sum + b.sum
    res.pref = max(a.pref, a.sum + b.pref)
    res.suff = max(b.suff, b.sum + a.suff)
    res.best = max(a.best, b.best, a.suff + b.pref)
    return res

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.size = 1
        while self.size < self.n:
            self.size *= 2
        self.t = [Node(-10**18, -10**18, -10**18, -10**18) for _ in range(2 * self.size)]
        for i in range(self.n):
            v = arr[i]
            self.t[self.size + i] = Node(v, v, v, v)
        for i in range(self.size - 1, 0, -1):
            self.t[i] = merge(self.t[2*i], self.t[2*i+1])

    def update(self, idx, val):
        i = self.size + idx
        self.t[i] = Node(val, val, val, val)
        i //= 2
        while i:
            self.t[i] = merge(self.t[2*i], self.t[2*i+1])
            i //= 2

    def query(self, l, r):
        l += self.size
        r += self.size + 1

        left_res = None
        right_res = None

        while l < r:
            if l & 1:
                left_res = self.t[l] if left_res is None else merge(left_res, self.t[l])
                l += 1
            if r & 1:
                r -= 1
                right_res = self.t[r] if right_res is None else merge(self.t[r], right_res)
            l //= 2
            r //= 2

        if left_res is None:
            return right_res.best
        if right_res is None:
            return left_res.best
        return merge(left_res, right_res).best

def main():
    n, q = map(int, input().split())
    arr = list(map(int, input().split()))
    st = SegTree(arr)

    out = []
    for _ in range(q):
        t, a, b = map(int, input().split())
        if t == 1:
            st.update(a - 1, b)
        else:
            out.append(str(st.query(a - 1, b - 1)))

    print("\n".join(out))

if __name__ == "__main__":
    main()
```セグメント ツリーには、各間隔の完全な構造概要が保存されます。 マージ関数は、2 つの半分にまたがる最大の部分配列を形成できるすべての可能な方法をエンコードします。 更新操作ではルートへのパスが再構築されるため、ポイント変更後に影響を受けるすべてのセグメントの一貫性が保たれます。 クエリ関数は標準の反復セグメント ツリー トラバーサルを使用し、順序を維持しながら部分セグメントを左から右に結合します。プレフィックスとサフィックスの情報は方向に依存するため、これは非常に重要です。 

微妙な詳細は、クエリ中の中立要素の動作です。 このコードは、左右の結果の初期化を遅らせることにより、空の累積を慎重に処理します。 これにより、初期化されていないノードとの誤ったマージが回避されます。 

## 実用的な例

 配列を考慮してください$[2, -1, 3]$範囲全体に対するクエリを使用します。 

すでに個々の値を表しているリーフ ノードから始めます。 

| ステップ | 左のノード | 右のノード | 合計 | プレフィックス | サフィックス | ベスト |
 | --- | --- | --- | --- | --- | --- | --- |
 | マージ(2, -1) | 2 | -1 | 1 | 2 | -1 | 2 |
 | マージ(前、3) | 2、-1 | 3 | 4 | 4 | 3 | 4 |

 最終結果は 4 で、セグメント全体から得られます。 これは、どちらの半分だけでも最適な答えが得られないため、境界を越えた組み合わせがいかに必要であるかを示しています。 

ここで考えてみましょう$[-5, -2, -7]$フルレンジ用。 

| ステップ | 左のノード | 右のノード | 合計 | プレフィックス | サフィックス | ベスト |
 | --- | --- | --- | --- | --- | --- | --- |
 | マージ(-5, -2) | -5 | -2 | -7 | -2 | -5 | -2 |
 | マージ(前、-7) | -5、-2 | -7 | -14 | -2 | -2 | -2 |

 結果は -2 ですが、これは単一の要素 -2 を選択した結果です。 これにより、構造体が人為的なゼロを導入することなく、すべて負の配列を正しく処理できることが確認されます。

 ## 特殊なケース

 次のようなすべて負の配列の場合$[-5, -2, -7]$、セグメント ツリーは各リーフを有効な候補セグメントとして初期化します。 マージされると、プレフィックスとサフィックスの値は、最小の負の要素を上方に伝播します。 すべての候補は実際の配列値から導出されるため、最良のフィールドでは人為的なゼロが導入されることはありません。 最終結果は正しく次のようになります$-2$これは、どの複数要素の組み合わせよりも一貫して優れているため、マージを通じて保持されます。 

次のような単一要素クエリの場合$[x]$の場合、クエリはリーフ ノードを直接返します。 マージ ロジックはトリガーされないため、最適な値がそのまま残ります。$x$、基本ケースが正しいことを確認します。 

値を正から負に変更する更新の場合、更新関数はリーフを置換し、ルートへのパスを再構築します。 各祖先はプレフィックス、サフィックス、および最良の値を再計算し、変更された要素によって以前は最適だったセグメントが無効になった場合にそれらのセグメントが正しくダウングレードされることを保証します。
