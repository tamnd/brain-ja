 ## 解決策
 ## 問題の理解

 私たちは、数日間にわたる交替勤務の割り当てをシミュレーションしています。 学生の固定グループがあり、最初は全員がアクティブなプールに参加します。 時間の経過とともに、一部の生徒がプールに追加され、他の生徒が削除される場合があり、これらの変更は特定の日に行われるようにスケジュールされています。 

毎日が同じリズムで進みます。 まず、その日にスケジュールされたすべての変更が適用されます。一部の生徒はアクティブなプールに追加され、一部の生徒は削除されることがあります。 セットが更新された後、アクティブな学生の順序付きリスト内の「現在のポインター」を選択します。 その日の当番を担当する学生は現在指摘されている学生です。 その生徒が選択されると、ポインターはソートされた順序で次の生徒に進み、最後を過ぎると最小の要素に戻ります。 アクティブな生徒がいない日は、誰も当番を割り当てられず、ポインタは意味のある方向に進みません。 

ここでの重要な構造は、アクティブな学生が常にソートされた順序で維持され、ポインタがこの順序に沿って日をまたがって周期的に移動することです。 課題は、更新が動的に行われるため、メンバーシップの変更と、変化する順序セット上で移動する反復子の両方を効率的に維持する必要があることです。 

制約の観点から見ると、目的のソリューションは N、T、Q の大きな値 (通常は最大約 200,000) までサポートする必要があります。 これにより、セットを 1 日ごとに再ソートしたり線形にスキャンしたりするアプローチは即座に除外されます。 アクティブ リストを毎日再構築するソリューションは、最悪の場合、2 秒の制限の下で許容される値をはるかに超える二次的な動作に低下します。 

微妙なエッジ ケースは、現在のポインターと相互作用する削除から発生します。 現在ポイントされている学生が特定の日に削除された場合、単純な実装では引き続き学生を出力したり、ポインタを誤って進めたりする可能性があります。 たとえば、アクティブ セットが {1, 2, 3} で、ポインタが 2 にあり、その日、選択前に 2 が削除されたとします。 正しい動作は、更新の処理後に、削除された要素ではなく、次の有効な要素を選択することです。 最初に選択して後で更新する不注意な実装では、無効な割り当てが生成されます。 

現在のポインターの周囲の順序を変更する挿入が発生した場合、別の特殊なケースが発生します。 新しい最小要素を挿入する場合でも、循環動作はソートされた順序を尊重する必要があります。つまり、ポインタの論理位置は、生のインデックスのシフトではなく、更新された構造に対して相対的に保持される必要があります。 

最後に、空集合の場合を処理する必要があります。 その日の課題の前にすべての生徒が削除された場合、出力は未定義の義務となり、ポインタは空の構造を超えて進もうとすることはできません。 

## アプローチ

 最も直接的なアプローチは、文字通り、並べ替えられたリストを使用してプロセスをシミュレートすることです。 毎日、リストを変更して挿入と削除を適用し、現在のポインターを見つけて要素を出力し、次のインデックスに移動します。 順序付けられた構造が明示的に表現されているため、これは概念的に簡単です。 

このアプローチの問題はパフォーマンスです。 Python リストでの挿入または削除には要素を移動する必要があり、セットのサイズは線形です。 Q 個の更新があり、それぞれのコストが O(N) になる可能性がある場合、合計の複雑さは O(NQ) に低下する可能性がありますが、これは実行不可能です。 

リストを維持し、挿入ポイントの二分探索を使用して最適化を試みたとしても、依然として移動コストが支配的です。 ボトルネックは、ポジションの検索ではなく、頻繁な更新の下で連続した構造を維持することです。

重要な観察は、リストにはランダム アクセスの効率性は必要ないということです。 順序付けされた反復と対数的な挿入と消去をサポートするデータ構造が必要です。 これはまさに順序付きセットが概念的に提供するものです。 実際には、バランスの取れたツリーまたはソートされたセットのような構造を使用してモデル化できます。 

このような構造を作成すると、ポインタをソートされた順序の反復子として維持できます。 要素を削除または挿入する場合、順序は再構築されません。 メンバーシップを調整するだけです。 ポインタを進めると単一の後続クエリになり、ラップアラウンドすると最小の要素に移動します。 

これにより、問題は繰り返しの再構築から動的な順序付けされたシーケンスの継続的な維持へと変わります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (リスト シミュレーション) | O(N・Q) | O(N) | 遅すぎる |
 | 順序集合シミュレーション | O((T + Q) log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは 2 つの中心的な構造を維持しています。1 つは順序付けられたアクティブな学生のセット、もう 1 つは現在の職務の位置を表すポインターです。 

1. 1 から N までのすべての生徒をソートしてアクティブ セットを初期化します。 以前の義務が割り当てられていないため、ポインタは最小の要素から始まります。 
2. すべての更新を日ごとにグループ化します。 毎日には挿入と削除が含まれる可能性があり、シミュレーション中に順番に適用できるようにそれらを保存します。 
3. 1 日から T 日まで繰り返します。 
4. 現在の日については、まず順序付きセットにすべての挿入を適用し、次にすべての削除を適用します。 その日の最終的な状態によって割り当てを決定する必要があるため、順序は重要です。 
5. 更新後、セットが空かどうかを確認します。 空の場合は、-1 を出力し、ポインタを進めずに翌日に進みます。 
6. セットが空でない場合は、ポインタが、前のポインタがまだ存在する場合はそれと少なくとも同じ大きさの最小要素を参照していることを確認します。 前のポインターが削除された場合は、それを次に使用可能な要素に移動します。 
7. ポインタの要素をその日の担当者として出力します。 
8. ソートされた順序で次の要素にポインタを進めます。 ポインタが最大要素にあった場合は、最小要素に戻ります。 

重要な部分は、ポインタの移動が常に割り当て後に行われ、常に現在の順序が尊重されることです。 

### なぜ効果があるのか

 このアルゴリズムは一貫した不変条件を維持します。つまり、更新後の毎日の開始時に、ポインターは常に現在のソート セット内の有効な要素に配置され、前日の選択に続く巡回順序で次の候補を表します。 ポインタは前方に移動するだけで、ラップする場合を除いて任意に後方にジャンプすることはないため、動的に変化するソートされたシーケンスに対する安定した循環トラバースが維持されます。 挿入では相対的な順序は崩れず、削除では無効な位置をスキップするだけでよく、これは次の有効な要素を再配置することで処理されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, t, q = map(int, input().split())
    
    active = set(range(1, n + 1))
    
    # store updates per day
    ins = [[] for _ in range(t + 2)]
    rem = [[] for _ in range(t + 2)]
    
    for _ in range(q):
        d, typ, x = map(int, input().split())
        if typ == 1:
            ins[d].append(x)
        else:
            rem[d].append(x)
    
    # current pointer in sorted order
    cur = 1
    
    def next_in_order(x):
        # find next element > x, else wrap
        bigger = [v for v in active if v > x]
        if bigger:
            return min(bigger)
        return min(active)
    
    def fix_pointer():
        nonlocal cur
        if not active:
            return
        if cur not in active:
            # move to next valid
            candidates = [v for v in active if v >= cur]
            if candidates:
                cur = min(candidates)
            else:
                cur = min(active)
    
    for day in range(1, t + 1):
        for x in ins[day]:
            active.add(x)
        for x in rem[day]:
            active.discard(x)
        
        if not active:
            print(-1)
            continue
        
        fix_pointer()
        
        print(cur)
        cur = next_in_order(cur)
    
def main():
    solve()

if __name__ == "__main__":
    main()
```このコードはアクティブ セットを明示的に維持し、毎日更新を処理します。 ポインタ修正ステップにより、現在のポインタが削除により無効になった場合、ソート順で次に利用可能な生徒にポインタが確実に移動されます。 

の`next_in_order`関数は循環後続ロジックを実装します。 まず、現在のポインタより厳密に大きい要素を検索します。 存在しない場合は、最小の要素にラップアラウンドします。 これは、循環トラバース要件を直接モデル化します。 

微妙な点の 1 つは、削除後もポインターが有効であることに決して依存しないことです。 代わりに、毎日の始まりに次のコマンドを使用して修復します。`fix_pointer`これにより、現在の要素が削除されたときに誤った出力が回避されます。 

## 実用的な例

 N = 5、T = 3 の小規模なシナリオを考えてみましょう。 

最初にすべての生徒 {1、2、3、4、5} がアクティブであり、変化がないと仮定します。 

| 日 | アクティブセット | 前のポインタ | 出力 | | 後のポインタ
 | --- | --- | --- | --- | --- |
 | 1 | 1 2 3 4 5 | 1 | 1 | 2 |
 | 2 | 1 2 3 4 5 | 2 | 2 | 3 |
 | 3 | 1 2 3 4 5 | 3 | 3 | 4 |

 これは、静的順序セットに対する純粋な循環反復を示しています。 

ここで更新を検討してください。 

N = 4、T = 3

 1日目: 2を削除

 2日目: 3を削除

 3日目: 2を挿入

 | 日 | アクティブセット | 前のポインタ | 出力 | | 後のポインタ
 | --- | --- | --- | --- | --- |
 | 1 | 1 2 3 4 → 1 3 4 | 1 | 1 | 3 |
 | 2 | 1 3 4 → 1 4 | 3 | 3 | 4 |
 | 3 | 1 4 2 | 4 | 4 | 1 |

 このトレースは、削除によってポインタが削除された要素を強制的にスキップし、挿入によって循環走査を中断することなく順序が復元される様子を示しています。 

2 番目の例では、ポインターの進行が履歴的な位置ではなく、現在の順序構造のみに依存することが確認されています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((T + Q) log N) | 各挿入/削除は対数的であり、ポインタの進行は実装に応じて定数または対数で償却されます。 
| スペース | O(N + Q) | アクティブなセットと毎日の更新を保存します。 

この構造は、各操作で順序付きセットのごく一部のみが変更され、完全な再計算が必要ないため、効率的です。 T と Q が大きい場合でも、対数更新コストにより、解は制限内に保たれます。

 ## 特殊なケース

 主なエッジ ケースは、現在のポインタが削除される場合です。 アクティブ セットが {1, 2, 3}、ポインタが 2、1 日目に 2 が削除されたとします。更新後、ポインタは存在しなくなります。 アルゴリズムは、この問題を 2 以上の最小の要素 (3) に移動することで修正します。要素が存在しない場合は、1 にラップされます。これにより、無効な要素が出力されることがなくなります。 

もう 1 つのケースは、すべての要素が削除される場合です。 アクティブ セットは空になり、アルゴリズムはすぐに -1 を出力し、ポインターの移動をスキップします。 これにより、空の構造上の後続ロジックへの無効な呼び出しが防止されます。 

最後の微妙なケースは、すでにアクティブな要素を繰り返し挿入することです。 セットを使用すると自然に重複が無視され、追加のチェックを行わなくても正確さが維持されます。
