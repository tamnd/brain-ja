 ## 解決策
 ## 問題の理解

 2 つの文字列シーケンスが与えられます。 最初のシーケンスは元のメッセージのコレクションを表し、2 番目のシーケンスはその後の破損した可能性のあるメッセージ ストリームを表します。 2 番目のシーケンスの一部の文字列は、元のシーケンスの一致する文字列を「無効にする」ことが知られています。 

タスクは、2 番目のシーケンスを処理した後、元のシーケンスのどの文字列が有効のままかを判断することです。 具体的には、文字列が元のリストと変更されたリストの両方に出現する場合、元のリストにあるその文字列はすべて削除されます。 出力は、残りの元の文字列であり、元の順序で出力されます。 

構造は 2 つの点で重要です。 まず、文字列は 2 つのリスト間で何度も比較されるため、メンバーシップ チェックは高速でなければなりません。 第 2 に、出力は元の順序を保持する必要があり、純粋に並べ替えまたはセットの反復によって答えを再構成するソリューションは除外されます。 

このステートメントはソートとセットの使用法をほのめかしていますが、実際の制約は、潜在的に大きなリストに対するメンバーシップ クエリの繰り返しに関するものです。 文字列の総数が約 10^5 に達すると、最悪の場合でも 10^10 個の文字列比較が必要になるため、2 つのリスト間の二次比較は実行できなくなります。 そのため、直ちにセットなどのハッシュベースの構造を使用することになります。 

元のリストに重複が存在する場合、微妙なエッジケースが発生します。 文字列が複数回出現し、後で 2 番目のリストによって無効になった場合は、1 つだけではなく、すべての出現が消える必要があります。 たとえば、元のリストが`["a", "b", "a"]`変更されたリストには以下が含まれます`"a"`、正しい出力は空のリストです。 最初の一致のみを削除する不注意な実装では、誤った出力が発生します。`["b", "a"]`。 

変更されたリストの文字列が元のリストと交差しない場合、別のエッジ ケースが発生します。 その場合、出力は順序と重複を保持して、元のリストと正確に一致する必要があります。 実装を誤ってセットから再構築すると、重複した要素が失われたり、要素の順序が変更されたりする可能性があります。 

## アプローチ

 直接的なアプローチでは、文字通りプロセスをシミュレートします。 変更されたリスト内のすべての文字列を反復処理し、文字列ごとに元のリストをスキャンして、一致する要素を削除できます。 これは、「変更されたリストに表示される元の文字列をすべて削除する」というルールを直接適用するため、単純かつ正確です。 ただし、削除するたびに元のリストをスキャンする必要があり、最悪の場合、両方のリストに n 個の要素が含まれます。 これにより、O(n^2) 個の文字列比較が行われ、n が大きい場合には速度が遅すぎます。 

非効率性は、拡大または縮小するリストに対してメンバーシップのチェックが繰り返されることから発生します。 リスト内の各検索は線形であり、変更された文字列ごとにそれを繰り返すとコストが倍増します。 

重要な点は、繰り返しスキャンする必要がないということです。 変更されたリストに文字列が表示されるかどうかだけを知る必要があります。 変更されたすべての文字列をハッシュ セットに保存すると、メンバーシップ チェックは平均で O(1) になります。 その後、元のリストを 1 回のパスで単純にフィルタリングし、変更されたセットに存在しない文字列のみを保持することができます。 

元のリストは引き続き順番に処理する必要がありますが、走査中に構造を変更する必要はありません。 各要素を出力に追加するかどうかだけを決定します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | スキャンによるブルートフォース削除 | O(n²) | お(1) | 遅すぎる |
 | ハッシュセットフィルタリング | O(n) 平均 | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 元の文字列リストと変更された文字列リストを読み取ります。 目的は、どの元の文字列が 2 番目のリストによって「無効」になっているかを特定することです。 
2. 変更されたリストのすべての文字列をハッシュ セットに挿入します。 これにより、メンバーシップのチェックが平均して一定時間の操作に変換されます。 セットを使用する理由は、頻度ではなく存在のみを考慮するためです。 
3. 元のリストを左から右にたどります。 各文字列について、変更されたセットにその文字列が存在するかどうかを確認します。 
4. 文字列が変更されたセットにない場合は、結果リストに追加します。 存在する場合は完全にスキップし、フィルタリングを通じてすべての出現を効果的に削除します。 
5. 残った要素間の重複を保持しながら、結果のリストを順番に出力します。 

### なぜ効果があるのか

 このアルゴリズムは、元のリストのスキャン中のどの時点でも、変更されたセットが削除する必要があるすべての文字列を完全に表すという不変式に依存しています。 セットのメンバーシップは静的であり、フィルタリングが開始される前に計算されるため、各決定は独立した最終的なものになります。 すべての元の文字列は、削除対象としてマークされていない場合にのみ出力に含まれます。また、重複を並べ替えたり部分的に削除したりすることはないため、生き残った要素の相対的な順序は入力と同じままになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    data = sys.stdin.read().strip().split()
    if not data:
        return
    
    # We assume format: n m, then n strings, then m strings
    it = iter(data)
    n = int(next(it))
    m = int(next(it))
    
    original = [next(it) for _ in range(n)]
    altered = {next(it) for _ in range(m)}
    
    res = []
    for s in original:
        if s not in altered:
            res.append(s)
    
    sys.stdout.write("\n".join(res))

if __name__ == "__main__":
    solve()
```実装では、まず、検索が定数時間になるように、変更されたリストからセットを構築します。 元のリストは、順序を維持するために配列として保存されます。 フィルタリング ループは、セット内のメンバーシップに基づいて含めるかどうかを決定するアルゴリズム ステップを直接変換したものです。 

よくある間違いは、反復中に元のリストから要素をその場で削除しようとすることです。 これにより、要素のスキップやインデックス エラーが発生します。 もう 1 つの問題は、変更されたコレクションにリストを使用することです。これにより、線形メンバーシップ チェックにより、静かにパフォーマンスが低下します。

## 特殊なケース

 重要なエッジ ケースは、元のリスト内で繰り返される文字列であり、変更されたリスト内に存在する場合はすべて削除する必要があります。 のような入力の場合`["a", "a", "b"]`変更された`["a"]`、アルゴリズムはそれぞれを処理します`"a"`メンバーシップは位置ごとではなく要素ごとにチェックされるため、両方を個別に削除します。 セットにより、`"a"`が無効とマークされている場合、すべての出現は一貫してフィルターで除外されます。 

もう 1 つのエッジ ケースは、変更されたリストが空の場合です。 セットは空になるため、すべてのメンバーシップ チェックは失敗し、元のリストが変更されずに順番に返されます。 これにより、アルゴリズムが意図しないフィルタリングを導入しないことが確認されます。
