 ## 解決策
 ## 問題の理解

 整数の配列が与えられ、そこから 2 つの要素を選択することによって形成されるペア積に興味があります。 タスクは、しきい値を決定して、そのしきい値以上の製品を持つペアの数を数え、そのアイデアを使用して、指定された条件を満たす最大の「幸福な製品」を特定することです。 

より具体的には、最大値を効果的に検索します。$x$インデックスペアの数が$(i, j)$、 と$i < j$、 そして$a_i \cdot a_j \ge x$、少なくとも必要な量です$m$。 出力は、この最大の実現可能なしきい値です。 

入力サイズは、すべてのペアを直接チェックすることが不可能になるほど十分に大きい配列を意味します。 もし$n$の順序です$10^5$、ペアの数は$O(n^2)$に達する$10^{10}$実用的な限界をはるかに超えた操作。 これにより、すべてのペアのブルートフォース列挙が即座に排除されます。 

合計ではなく製品の比較から微妙な困難が生じます。 配列が構造化されていない限り、積の制約はインデックスの順序において単調ではなく、それが並べ替えの動機となります。 

負の数値またはゼロが存在する場合、素朴だが危険なエッジ ケースが発生します。 たとえば、配列が次の場合、$[-5, -1, 2]$、製品は符号を反転する可能性があり、最大値のみに基づく単純な推論は失敗する可能性があります。 もう 1 つのエッジ ケースは、すべての要素が同一である場合です。$[3, 3, 3, 3]$、数えることが組み合わせになり、不注意な二重数えたり順序の間違いが簡単に発生する可能性があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。すべてのペアを列挙します。$(i, j)$、その積を計算し、少なくともいくつあるかを数えます。$x$。 これにより、固定された問題に対する正しい答えが得られます$x$、そして可能な限りすべてのことを試みることによって$x$、最大有効なしきい値を見つけることができました。 ただし、これにより 2 つの非効率が生じます。 1つ目は、$O(n^2)$ペア世代。 2 つ目は、考えられるしきい値をスキャンすることです。しきい値自体は、方法によっては大きくなる可能性があります。$x$が選ばれます。 候補者を賢く減らしても$x$、ペアの列挙が優勢です。 

重要な観察は、述語「少なくとも積を含むペアの数」が$x$少なくとも$m$”は単調です$x$。 ある場合$x$達成可能であれば、さらに小さい$x$しきい値を緩和しても有効なペアの数を増やすことしかできないため、これも達成可能です。 この単調性により、二分探索が可能になります。$x$。 

候補が決まったら$x$、残りの問題はペアを効率的に数えることです。 配列を降順にソートした後、各要素の構造を活用できます。$a_i$、要素を見つけるために配列内でどこまで移動できるかを調べたいとします。$a_j$そのような$a_i \cdot a_j \ge x$。 ソートのため、これは要素ごとに 2 ポインターまたはバイナリ検索条件になります。 

したがって、解決策は二分探索に帰着します。$x$、それぞれについて$x$、有効なペアを数えます$O(n \log n)$、全体的な結果が得られます$O(n \log^2 n)$解決。

 ## アルゴリズムのチュートリアル

 ### 最適な戦略

 1. 配列を降順に並べ替えます。 これにより、固定された左端点の場合、有効な右端点が符号の動作に応じて連続したプレフィックスまたはサフィックス領域を形成することが保証されます。 順序付けにより、二分探索に必要な単調構造が得られます。 
2. 関数を定義する`count(x)`を満たすペアの数を返します$a_i \cdot a_j \ge x$。 この機能は実現可能性チェックの中核となります。 
3. インデックスごとに$i$、二分探索を使用します$j > i$製品の状態が保たれている最も遠い位置を見つけます。 配列はソートされているので、一度$a_i \cdot a_j$以下に低下します$x$、それ以降のすべての要素は (正の範囲の場合) 小さくするだけなので、有効なセグメントは連続しています。 
4.全員からの寄付を合計する$i$有効なペアの合計を計算します。 この集計では、考慮することのみを考慮するため、二重カウントが回避されます。$j > i$。 
5. の可能な値に対する二分探索$x$。 検索空間は、任意のペアによって形成される可能な最小積と最大積によって制限されます。 
6. 二分探索の各中間値に対して、次を呼び出します。`count(mid)`そして、必要なペア数を満たしているかどうかに基づいて、検索を上方向に移動するか下方向に移動するかを決定します。 

### なぜ効果があるのか

 正確さは 2 つの構造特性に依存します。 まず、ソートにより、固定左エンドポイントの場合、述語が次のようになります。$a_i \cdot a_j \ge x$と単調に変化します$j$、効率的に境界を見つけることができます。 第二に、実現可能性関数$x$単調です: 増加しています$x$有効なペアの数を減らすか保存することしかできません。 これら 2 つの単調性により、有効な構成を見逃さずに内部バイナリ検索と外部バイナリ検索の両方が正当化されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def count_pairs(a, x):
    n = len(a)
    res = 0
    j = n - 1

    for i in range(n):
        while j > i and a[i] * a[j] < x:
            j -= 1
        if j > i:
            res += (j - i)
    return res

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    a.sort(reverse=True)

    lo = -10**18
    hi = 10**18

    ans = lo
    while lo <= hi:
        mid = (lo + hi) // 2
        if count_pairs(a, mid) >= m:
            ans = mid
            lo = mid + 1
        else:
            hi = mid - 1

    print(ans)

if __name__ == "__main__":
    solve()
```この解決策は、インデックスに沿った積の単調性を推論できるように、降順で並べ替えることから始まります。 の`count_pairs`関数は、指定されたしきい値の実現可能性チェックを実装します。 2 ポインタ スタイルのスイープを使用し、減少するポインタを維持します。`j`それぞれに対して最も遠い有効なパートナーを見つけます`i`。 

二分探索`solve`候補製品のしきい値を調査します。 境界は、負の極値が存在する場合も含め、すべての可能なペア積をカバーするのに十分な大きさが選択されます。 各中間点について、実現可能性を評価し、それに応じて検索境界を調整します。 

微妙な実装の詳細は、ポインタの再利用です。`j`繰り返しにわたって`i`。 これは有効です。`i`増加すると、有効領域`j`拡張できず、カウント関数内の償却された線形動作が維持されます。

 ## 特殊なケース

 最初のエッジ ケースは、すべての要素が同一である場合に発生します。 たとえば、入力の場合`[3, 3, 3, 3]`、すべてのペアには積 9 があります。アルゴリズムはソートされますが、構造は変更されません。 その間`count(x)`、 もし`x ≤ 9`、 全て$\binom{4}{2} = 6$ペアがカウントされます。 もし`x > 9`、どれもカウントされません。 単調な動作は必要に応じて正確に保持されるため、二分探索はきれいに収束します。 

2 番目のエッジ ケースには負の値が含まれます。 考慮する`[-5, -2, 3, 4]`。 ソート後の配列は次のようになります`[4, 3, -2, -5]`。 2 つの負の値、または 1 つの負と正の値を含む積の動作は異なりますが、カウント関数はソートされた構造に基づいて各ペアを明示的に正しく評価します。 二分探索は肯定性を仮定せず、実現可能性の単調性のみを仮定し、符号が変化しても有効なままです。 

3 番目のエッジ ケースは、次のような最小入力サイズです。`n = 2`。 ペアは 1 つだけ存在するため、アルゴリズムはその 1 つの製品がしきい値を満たしているかどうかをチェックすることになります。 この縮退の場合でも count 関数は正確であるため、二分探索は正しく折りたたまれます。
