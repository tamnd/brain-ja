 ## 解決策
 ## 問題の理解

 制限された数字のアルファベットを使用して、固定の偶数長の数字列を構築しています。 この文字列はチケット番号を表しますが、重要な構造規則は、文字列の各半分で許可される各数字が何回使用されるかだけです。 

長さのあるチケット$n$長さが半分に分かれています$n/2$。 左半分の桁の合計が右半分の桁の合計と等しくなるような、有効な完全長の文字列がいくつ形成できるかを数えたいとします。 数字は繰り返すことができ、許可される数字セットにゼロが含まれている場合、先頭のゼロも許可されます。 

組み合わせの観点から見ると、問題は長さのシーケンスに関するものです$n$小さなアルファベットの上に$k \le 10$、前半の合計が後半の合計と等しいという制約付き。 

制約は長さの次元で大きくなります。$n$到達できる$2 \cdot 10^5$。 これにより、各文字列を明示的に処理したり、文字列の半分を列挙したりするソリューションは即座に排除されます。 に依存する単純な DP にすべての可能な半和を格納する場合でも、$n$また、最大合計額は慎重に構成しない限り大きすぎます。 重要な点は、アルファベットが小さいため、合計の範囲は管理可能ですが、各合計に到達する方法の数が膨大であり、多項式または FFT ベースの畳み込みが必要であるということです。 

単純なアプローチでは、すべての左半分と右半分を個別に列挙し、合計を照合しようとします。 それぞれの半分に次のものがあるため、これは失敗します。$k^{n/2}$その可能性は天文学的に大きい。 長さと合計を超えた DP であっても、$O(n \cdot 9n)$州が大きすぎるので、$n^2$周りにいる$4 \cdot 10^{10}$。 

微妙な特殊ケースは、数字 0 が含まれる場合です。 合計は変更されませんが、組み合わせの多重度は増加します。 桁の多重度を無視し、到達可能な合計のみを追跡するソリューションは、深刻な過少カウントになります。 もう 1 つの落とし穴は、対称性が畳み込みを行わずにカウントを直接分割することを暗黙的に想定していることです。これは、桁の分布が異なると同じ合計に対する寄与が異なるため破られます。 

## アプローチ

 問題の構造は、自然に 2 つの同一の部分に分かれます。 わかっていれば、考えられる合計額ごとに$s$、桁の合計で半分の長さのシーケンスを形成する方法は何通りあるか$s$の場合、完全な答えは、同じ和を共有する 2 つの独立した半分をペアにすることによって得られます。 これにより、問題は分布とそれ自体の畳み込みの計算に変換されます。 

ブルートフォースアプローチは、長さのすべてのシーケンスを構築します$n/2$そしてそれらの合計を計算します。 それはすでにコストがかかります$k^{n/2}$、小さいものでも不可能です$n$。 動的プログラミングに切り替えたとしても、次のように定義します。$dp[i][s]$長さを形成する方法の数として$i$合計付き$s$。 移行は簡単ですが、州の数は増加します。$O(n^2)$、および各移行コスト$O(k)$、与える$O(n^2 k)$ですが、それでも遅すぎます。 

重要な構造的洞察は、半分の DP が固定基本多項式の繰り返したたみ込みであるということです。 各位置は、許可されたセットから独立して 1 桁を寄与するため、1 つの位置の生成関数は多項式になります。$x^d$数字の場合は 1$d$許可されています。 の生成関数$n/2$位置はこの多項式の累乗ですか$n/2$。 必要なのはその係数だけです。係数は、モジュロでの FFT ベースの多項式乗算と除算征服の累乗を組み合わせて使用​​して計算できます。$998244353$、NTTに優しいプライムです。 

係数配列を取得したら$A[s]$半分の場合、答えは全体の合計です$s$の$A[s]^2$、同じ合計を持つ左半分と右半分を独立して選択するためです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース列挙 |$O(k^{n/2})$|$O(n)$| 遅すぎる |
 | DP の長さと合計 |$O(n^2 k)$|$O(n^2)$| 遅すぎる |
 | 分割統治 + NTT |$O(S \log n \log S)$|$O(S)$| 承認済み |

 ここ$S$可能な最大合計であり、次の制限があります。$9n/2$。 

## アルゴリズムのチュートリアル

 この問題を、畳み込みによる多項式のべき乗の計算に圧縮します。 

1. 初期多項式を構築する$P(x)$ここで、許可される各数字は$d$位置で係数 1 を提供します$x^d$。 この多項式は、ハーフチケット内の 1 つの位置を表します。 
2. 指数を定義する$t = n/2$。 私たちが欲しいのは$P(x)^t$、ただし次数までの係数のみ$9t$合計がそれを超えることはできないため、重要です。 
3. 多項式で除算累乗を使用します。 再帰的に計算します$P^t$指数を半分に分割します。 各ステップで、2 つの中間多項式を乗算します。 
4. 各乗算は NTT を使用してモジュロで実行されます。$998244353$。 これにより、多項式が大きい場合でも畳み込みの効率が維持されます。 
5. 係数配列を計算した後$A[s]$の$P(x)^t$、 解釈する$A[s]$合計で半分を構築する方法の数として$s$。 
6. 最終的な答えを次のように計算します。$\sum_s A[s] \cdot A[s]$、左半分と右半分は独立していますが、等しい合計を共有する必要があるためです。 

畳み込みが発生する決定的な理由は、位置間の数字の選択が独立しており、合計が線形に加算されるためです。 独立した加算を繰り返すことは、多項式の乗算に正確に対応します。 

### なぜ効果があるのか

 の各係数$P(x)^t$選択方法の数を数えます$t$合計が固定値に等しい数字。 畳み込み構造により、各乗算ステップで互いに素な位置にまたがる独立した選択肢がマージされるため、すべての組み合わせが正確に 1 回カウントされることが保証されます。 最後の二乗ステップでは、2 つの独立した構造からの同一の合計分布を照合することで、左右の合計が等しくなるように強制します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353
G = 3

def ntt(a, invert):
    n = len(a)
    j = 0
    for i in range(1, n):
        bit = n >> 1
        while j & bit:
            j ^= bit
            bit >>= 1
        j ^= bit
        if i < j:
            a[i], a[j] = a[j], a[i]

    length = 2
    while length <= n:
        wlen = pow(G, (MOD - 1) // length, MOD)
        if invert:
            wlen = pow(wlen, MOD - 2, MOD)
        i = 0
        while i < n:
            w = 1
            for j in range(i, i + length // 2):
                u = a[j]
                v = a[j + length // 2] * w % MOD
                a[j] = (u + v) % MOD
                a[j + length // 2] = (u - v) % MOD
                w = w * wlen % MOD
            i += length
        length <<= 1

    if invert:
        inv_n = pow(n, MOD - 2, MOD)
        for i in range(n):
            a[i] = a[i] * inv_n % MOD

def multiply(a, b):
    n = 1
    while n < len(a) + len(b) - 1:
        n <<= 1
    fa = a[:] + [0] * (n - len(a))
    fb = b[:] + [0] * (n - len(b))
    ntt(fa, False)
    ntt(fb, False)
    for i in range(n):
        fa[i] = fa[i] * fb[i] % MOD
    ntt(fa, True)
    return fa[:len(a) + len(b) - 1]

def solve():
    n, k = map(int, input().split())
    digits = list(map(int, input().split()))

    base = [0] * (max(digits) + 1)
    for d in digits:
        base[d] = 1

    poly = base[:]
    exp = n // 2

    def poly_pow(p, e):
        if e == 1:
            return p
        if e % 2 == 0:
            half = poly_pow(p, e // 2)
            return multiply(half, half)
        else:
            return multiply(poly_pow(p, e - 1), p)

    res = poly_pow(poly, exp)

    ans = 0
    for x in res:
        ans = (ans + x * x) % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```NTT 実装は、コアのボトルネックである多項式乗算を高速化するために使用されます。 の`multiply`NTT はその構造を必要とするため、関数は係数配列が 2 のべき乗に拡張されることを保証します。 再帰的`poly_pow`多項式を二乗して累乗を実行します。 

微妙な点は、次数までの係数のみを保持していることです。$9n/2$これにより、配列の不必要な増大が防止されます。 もう 1 つの詳細は、最終的な答えが別の畳み込みを実行するのではなく係数を 2 乗することで、余分な NTT コールが回避されることです。

 ## 特殊なケース

 使用できる桁が 1 つだけの場合、多項式は単項式になります。 べき乗は単一の項に崩壊し、両方の半分が強制されるため、答えは自明に 1 になります。 

ゼロが含まれる場合、合計は変更されませんが、畳み込みの多重度が増加します。 このアルゴリズムは、ゼロ次の係数質量に寄与し、合計構造に影響を与えることなく累乗を通じて伝播するため、これを正確にカウントします。
