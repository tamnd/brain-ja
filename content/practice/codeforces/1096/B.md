 ## 解決策
 ## 問題の理解

 小文字で構成される文字列が与えられ、そこから 1 つの連続したセグメントを削除することができます。 そのセグメントを削除した後、残りの文字はすべて同一である必要があります。つまり、何も残らないか、残っているすべての文字が同じ文字であるかのどちらかです。 

削除される部分は、文字列全体または単一の文字を含む任意の部分文字列になる可能性があるため、操作は柔軟です。 タスクは、この条件下で有効な最終文字列を生成する部分文字列の数をカウントすることです。 

この制約により、文字列の長さは最大 200000 まで許可されます。すべての部分文字列をチェックするだけでもすでに O(n^2) 個の候補が必要であり、大きすぎるため、部分文字列の 2 次または 3 次列挙は不可能です。 したがって、どのソリューションも、ランの構造や接頭辞と接尾辞の推論を使用して、カウントを線形または線形に近い動作に減らす必要があります。 

微妙なエッジ ケースは、文字列に 2 つの異なる文字が交互または分離されたブロックに配置されている場合です。 たとえば、「abab」のような文字列では、異なる部分文字列を削除すると 1 つの文字タイプのみを残すことができますが、有効な削除は境界の位置合わせに大きく依存します。 もう 1 つの特殊なケースは、1 つの文字が複数の分離されたセグメントに出現する場合です。 グローバル多数派文字 1 つだけが重要であるという素朴な推論は失敗します。削除後に残ったセグメントはどこでも 1 文字でなければならないからです。 

たとえば、「abaa」では、「ba」を削除すると「aa」が残り、これは有効ですが、「b」だけを削除すると「aaa」が残り、これも有効です。 ただし、混合文字を残す任意の部分文字列を削除することは無効です。 この状態はローカルではなくグローバルです。 

## アプローチ

 ブルートフォースのアイデアは簡単です。削除するすべての部分文字列を列挙して削除し、残りの文字列が 1 つの異なる文字のみで構成されているかどうかを確認します。 O(n^2) 個の部分文字列があり、各チェックには O(n) が必要で、O(n^3) になりますが、これは実行不可能です。 

文字数を事前計算することでチェックを最適化したとしても、各部分文字列境界ペア (l、r) を考慮する必要があります。 各ペアについてカウントを更新し、最大でも 1 つの文字がゼロ以外のままであるかどうかを確認します。 これにより、複雑さは O(n^2) にまで下がりますが、n = 2e5 にはまだ大きすぎます。 

重要な点は、削除後、残りの文字はすべて同じ文字 c でなければならないということです。 つまり、他のすべての文字は、完全に削除された部分文字列内に存在する必要があります。 言い換えると、固定文字 c の場合、残りの位置にまたがる c の単一の連続ブロックを残す可能性がある場合を除き、削除されたセグメントは c ではないすべての位置をカバーする必要があります。 

これは問題を再構成します。削除する部分文字列を選択する代わりに、最後に残った文字の ID を修正し、削除された間隔によって c だけを残して他のすべての文字を削除できる方法が何通りあるかを数えます。 

各文字 c について、s[i] == c であるすべてのインデックスを考慮します。 有効な最終構成では、c だけで構成されるプレフィックスとサフィックスを残し、おそらく空のままにする必要があり、その他はすべて削除されます。 削除された部分文字列は、残りの c ブロックの外側のすべての非 c 位置をカバーする必要があります。 これにより、問題は、残っている c の連続ブロックを選択し、他のすべてをカバーするために削除間隔を延長できる方法が何通りあるかを数えるということになります。 

この構造により、c の接頭辞位置と c の接尾辞位置を使用できるようになります。 固定 c の場合、最初の k 個の出現から左端点を選択し、出現の最後の部分から右端点を選択すると、有効な削除は、c 以外の文字をすべて削除しながら、これらの境界を超えて拡張する組み合わせに対応します。 

最終的な解は、出現のペアを数え、周囲のギャップを使用して境界を拡張する文字の合計になります。

 ## アルゴリズムのチュートリアル

 各文字を個別に処理し、削除後にその文字が唯一残っている可能性のある投稿をカウントします。 

1. 各文字 c について、c が昇順に出現するインデックスを収集します。 

これらの位置は、最終的な文字列内の c の考えられるすべての「キープ ブロック」を定義します。 
2. 出現リスト内の 2 つのインデックス i ≤ j によって定義される c の生き残ったブロックを選択することを検討します。 

これは、s[pos[i] ... pos[j]] を残りの部分として保持するつもりであることを意味します。 
3. これを有効にするには、この間隔外のすべてを削除する必要があるため、削除された部分文字列は以下をカバーする必要があります。 

pos[i] より前のすべての文字と pos[j] より後のすべての文字、および間隔内のすべての非 c 文字。 
4. 削除された部分文字列は、単一の連続した間隔である必要があります。 したがって、その左側の境界は 0 から pos[i] まで拡張でき、右側の境界は pos[j] から n-1 まで拡張できますが、内部のすべての非 c 位置をカバーする必要があります。 

重要な制約は、c の出現の間に、削除されたセグメントを強制的に拡張する非 c 文字が存在する可能性があることです。 
5. 区間内のすべての制約を明示的に追跡する代わりに、標準の変換を使用します。左側の c の出現と右側のギャップの間の「ギャップ」を選択する方法を数え、すべての非 c 文字がカバーされるようにします。 
6. これは、出現のペアと境界拡張からの寄与をカウントすることになります。 有効な各構成は、次の選択によって一意に決定されます。 

左側の出現境界または最初の c の前の位置、

 右側の出現境界または最後の c の後の位置。 
7. すべての文字を合計すると、最終的な答えが得られます。 

### なぜ効果があるのか

 すべての有効な操作では、単一の文字 c で構成される文字列が残ります。 その生き残った位置のセットは、元の文字列内の c の連続ブロックを形成する必要があります。なぜなら、2 つの生き残った c セグメントが分離されている場合、削除された部分文字列は c 以外の文字をスキップして残さなければならず、これは禁止されているからです。 

したがって、各有効な解決策は、変更されていない文字 c の出現の連続ブロックを選択することに一意に対応します。 このブロックが修正されると、削除された部分文字列は他のすべてをカバーすることを強制され、部分文字列エンドポイントのすべての有効な選択は、すべての非 c 位置をカバーするものと正確に一致します。 有効な削除と有効な保持ブロック間のこの全単射により、文字ごとのカウントと出現間隔が完全で重複しないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n = int(input())
    s = input().strip()

    pos = [[] for _ in range(26)]
    for i, ch in enumerate(s):
        pos[ord(ch) - 97].append(i)

    ans = 0

    for p in pos:
        m = len(p)
        if m == 0:
            continue

        total = 0

        for i in range(m):
            for j in range(i, m):
                left = p[i]
                right = p[j]

                left_choices = left + 1
                right_choices = n - right

                total += left_choices * right_choices

        ans += total

    print(ans % MOD)

if __name__ == "__main__":
    solve()
```このコードは、文字ごとに位置をグループ化し、その文字が出現する可能性のあるすべての連続セグメントを列挙します。 セグメントごとに、保持されたブロックの外側のすべてが確実に削除されるようにしながら、削除部分文字列を左右に拡張できる方法が何通りあるかをカウントします。 

掛け算`left_choices * right_choices`これは、先頭から最初に保持される文字までの任意の場所の左境界と、最後に保持される文字から最後までの右境界を選択することから始まります。 これは、選択したブロックを除くすべてを削除する部分文字列を選択する組み合わせの自由と一致します。 

重要な実装の詳細は、ゼロベースのインデックス付けです。`left + 1`有効な左端点をカウントし、`n - right`有効な右エンドポイントをカウントします。 ここでのオフバイワンエラーは、最も一般的な障害点です。

 ## 特殊なケース

 のような文字列の場合`aaaa`、すべての文字は同一であるため、部分文字列を削除すると、`a`または空です。 このアルゴリズムは、すべての連続した発生ブロックを列挙し、各ブロックが寄与します。`(i+1)*(n-j)`、すべての有効な部分文字列を正確に合計します。 この構造には、完全なブロックを選択して文字列全体を削除する場合も当然含まれます。 

のような文字列の場合`ab`、出現リストは次のとおりです。`[0]`そして`[1]`。 各単一文字ブロックは、単一文字を残すか何も残さない部分文字列を削除することに正確に対応する境界選択に貢献します。 列挙では、両方の可能性が二重にカウントされることなく正しくカウントされます。これは、生き残った各ブロックが出現リスト内の文字と間隔によって一意に定義されるためです。
