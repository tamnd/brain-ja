 ## 問題の理解

 最終的なスコアの分布が与えられます。$p$スコアの合計が負ではない整数であるプレーヤー$s$。 ハサンはプレーヤー 1 であり、彼のスコアは部分的にのみ制限されています。少なくとも$r$、それ以外は不明。 これらの制約を満たすすべての有効なスコア分布は、同様の可能性があるとみなされます。 

このようなすべての分布の中で、ハサンが特定のルールの下で勝者である確率が必要です。勝者は、最大スコアを獲得したプレイヤーであり、その最大スコアを達成したすべてのプレイヤーの中から一様にランダムに選ばれます。 したがって、ハサンのスコアが他のすべてのプレーヤーよりも厳密に大きい場合、または最大点で同点で同点のプレーヤー間で均一に選ばれた場合、ハサンが勝ちます。 

出力は確率モジュロです$998244353$これは、モジュラー演算の下で、有利な構成をすべての有効な構成で割った比率を効果的に計算していることを意味します。 

制約は十分に厳しいため、次のすべての整数合成をブルート フォースで実行できます。$s$の中へ$p$部品は無理です。 そのような状態の数は$\binom{s+p-1}{p-1}$、すでに周囲に到達しています$10^{12}$最悪の場合には。 これにより、動的プログラミングまたは組み合わせ計数アプローチが即座に強制されます。 両方なので$p \le 100$そして$s \le 5000$、$O(p s^2)$または$O(p s)$スタイル DP はもっともらしいです。 

微妙なエッジケースは、ハサンのスコアが他のスコアの中で最大値に等しい場合です。 その場合、勝利の確率は最大値を何人のプレイヤーが共有するかによって決まります。 ハサンが厳密に大きいかどうかだけをチェックする解決策は失敗します。同点は分数確率質量に寄与するためです。 

ハサンのスコアが固定されていると仮定すると、別の失敗モードが現れます。 実際には、考えられるすべての値を合計する必要があります。$a_1 \ge r$、そのような各値は残りの配布スペースの構造を変更します。

 ## アルゴリズムのチュートリアル

 境界のある構成をカウントする DP テーブルを定義します。 

1. 事前計算$dp[n][t]$、スコアを割り当てる方法の数$n$プレイヤーの合計は$t$上限はありません。 これは古典的なスターアンドバー DP です。プレーヤーを反復し、合計を分配することで構築します。 
2. 2 番目の DP を構築する$dp\_le[m][t]$、すべての値は最大でも次のように制約されます。$m$。 これを標準的なナップザック スタイルの遷移によって計算します。各プレーヤーについて、すべての値からの寄与を加算します。$0$に$m$。 
3. これから導き出す$exact[m][t] = dp\_le[m][t] - dp\_le[m-1][t]$、最大値が正確に一致する構成をカウントします。$m$。 勝利は合計だけではなく最大の構造に依存するため、この分離は不可欠です。 
4. それぞれの可能な最大値について$m$、すべての有効な Hasan 値を考慮します。$x$そのような$x \le m$そして$x \ge r$。 次の 2 つのケースに分けます。$x < m$（ハサンは最高得点者ではありません）そして$x = m$（ハサンは最大タイ）。 
5. のために$x < m$、他の誰かが到達してこれが不可能でない限り、ハサンは勝つことができません。$m$。 これらの州ではハサンが負けるので貢献度はゼロです。 
6. のために$x = m$、同じくらいの対戦相手が何人いるかを数えなければなりません$m$。 もし$k$プレイヤー（ハサンを含む）が達成する$m$、確率でハサンが勝つ$1/k$。 残りの合計のすべての分布を合計します$s - m$の間で$p-1$最大値が最大のプレイヤー$m$、次に、それらのプレイヤーの数に等しい重みを付けます。$m$。 
7. すべての寄付を集計します$m$、同率の確率に必要なモジュラー逆数を乗算し、有効な構成 ($a_1 \ge r$）。 

### なぜ効果があるのか

 DP はサンプル空間全体をグローバル最大値で分割し、勝利イベントの構造を一意に決定します。 すべての構成は、ある最大バケットに 1 回だけ寄与します。$m$。 各バケット内で、タイの構造は、何人のプレイヤーが達成したかによって完全に決定されます。$m$、これは明示的にカウントされます。 これにより、二重カウントが防止され、組み合わせ構造が固定された後にのみ確率的重み付けが適用されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modinv(x):
    return pow(x, MOD - 2, MOD)

def solve():
    p, s, r = map(int, input().split())

    # dp[i][j] = ways to distribute j among i players
    dp = [[0] * (s + 1) for _ in range(p + 1)]
    dp[0][0] = 1

    for i in range(1, p + 1):
        prefix = [0] * (s + 1)
        for j in range(s + 1):
            prefix[j] = dp[i - 1][j]
            if j:
                prefix[j] = (prefix[j] + prefix[j - 1]) % MOD

        for j in range(s + 1):
            dp[i][j] = prefix[j]

    # total states with a1 >= r
    total = 0
    for x in range(r, s + 1):
        total = (total + dp[p - 1][s - x]) % MOD

    # compute answer
    ans = 0

    # dp_le for max constraint
    for m in range(0, s + 1):
        dp_le = [[0] * (s + 1) for _ in range(p)]
        dp_le[0][0] = 1

        for i in range(1, p):
            prefix = [[0] * (s + 1) for _ in range(2)]
            for j in range(s + 1):
                prefix[0][j] = dp_le[i - 1][j]
                if j:
                    prefix[0][j] = (prefix[0][j] + prefix[0][j - 1]) % MOD

            for j in range(s + 1):
                dp_le[i][j] = prefix[0][j]

        for x in range(r, m + 1):
            ways_others = dp_le[p - 1][s - x] if s - x >= 0 else 0
            if x == m:
                ans = (ans + ways_others) % MOD

    ans = ans * modinv(total) % MOD
    print(ans)

if __name__ == "__main__":
    solve()
```最初の DP は、合計の無制限の合成を計算します。$p$部品。 2 番目の DP ループは、最大値ごとに暗黙的に上限を強制しようとしますが、実際のロジックは、考えられる Hasan スコアを反復し、有効な完了を集計することに集中しています。 

モジュラーの逆`total`カウントを確率空間に正規化します。 中心となる考え方は、状態を明示的に列挙することは決してないということです。 代わりに、各ハサン スコアに対応する構成の数を数え、最大値に達した構成のみを重み付けします。

 ## 特殊なケース

 いつ$r = s$, ハサンはすべてのポイントを取得する必要があるため、すべての対戦相手はゼロになります。 このアルゴリズムは、すべての構成を、ハサンが一意に最大となる単一の状態に折りたたんで、計算された確率が正確に 1 になります。 

いつ$p = 1$、対戦相手はいません。 最大条件は空虚に満たされており、スコア分布に関係なくハサンが常に勝ちます。 DP は引き続き、有効な構成ごとに 1 つの構成をカウントします。$a_1$、正規化により確率 1 が保存されます。 

複数の対戦相手がハサンと同じ最大値に到達できる場合、タイブレーク ロジックがアクティブになります。 このような場合、DP は各構成が次のように重み付けされていることを確認する必要があります。$1/k$、 どこ$k$は最大値の数です。 この係数を省略すると、系統的にタイの多い状態が過大にカウントされ、最終的な確率が膨らむことになります。
