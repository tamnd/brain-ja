 ## 解決策
 ## 問題の理解

 私たちは正多角形を扱っています。これは、すべての辺と角度が対称であることを意味します。 入力は角度値を与えるので、3 つの頂点を選択できるような正 n 角形が存在するかどうかを判断する必要があります。$a, b, c$(必ずしも連続的である必要はありません) とで形成される角度$b$、つまり$\angle abc$、まさに指定された値です。 

言い換えれば、多角形自体の内角を扱っているのではなく、円上の 3 つの頂点を周期的に選択することによって形成される角度を扱っているのです。 幾何学は、円上の等間隔の点とそれらの間の中心角についての推論に帰着します。 

出力は頂点の最小数です$n$そのような構成が存在するか、または$-1$正多角形がその角度を実現できない場合。 

制約$T \le 180$は小さいため、テストごとの計算は対数的になるか、最悪の場合でも緩やかに線形になる可能性がありますが、大きな限界で線形に増加するものではありません。$998244353$。 The large upper bound only guarantees that if a valid solution exists, it is not astronomically large in a way that would break integer handling, not that we should iterate up to it.

 単純な間違いは、正多角形の内角をチェックするだけでよいと仮定することから生じます。 たとえば、正五角形では、内角は次のように固定されます。$108^\circ$、しかし、この問題では次のような角度が許可されます$36^\circ$または$72^\circ$隣接しない頂点によって形成されます。 もう 1 つのよくある間違いは、角度が隣接する円弧のみから得られるものであると仮定することです。 実際には、頂点の距離によって定義される任意の 2 つの円弧が寄与します。 

2 番目の微妙な失敗例は、角度が等しい必要があるかのように扱っていることです。$k \cdot \frac{180(n-2)}{n}$、この問題とは関係ありません。 ここでの角度は、ポリゴンの内部構造ではなく、円上の弦のジオメトリのみに依存します。 

## アプローチ

 ブルートフォースアプローチでは、ポリゴンサイズを修正しようとします。$n$、 場所$n$単位円上の点を取得し、三重点を列挙します$(a, b, c)$の角度を計算します。$b$を選択し、ターゲットに一致するものがあるかどうかを確認します。 トリプルの数は、$O(n^3)$、角度の計算もドット積を使った定数時間です。 これを複数で試してみると$n$数千まででも完全に実行不可能になり、有効な制約の下では明らかに不可能になります。$n$まで到達できます$10^9$-スケール境界。 

座標の観点から考えるのをやめ、代わりに円弧の差の観点から考えると、構造はより単純になります。 円上では、正 n 角形が全角を分割します$360^\circ$等しいステップに$x = \frac{360}{n}$。 任意の 2 つの頂点は、このステップの整数倍に対応します。 

次に頂点を考えます$b$、および他の 2 つの頂点$a$そして$c$。 角度$\angle abc$は円の内接角なので、円弧の長さの半分に相当します$ac$含まれていないもの$b$。 その円弧の長さはステップの整数倍でなければなりません$x$。 間の弧が$a$そして$c$スパン$k$多角形のエッジの場合、円弧の寸法は次のようになります。$k \cdot x$、内周角は次のとおりです。$$\angle abc = \frac{kx}{2} = \frac{k}{2} \cdot \frac{360}{n} = \frac{180k}{n}.$$したがって、問題は整数を見つけることに帰着します$n$そして$k$次のような:$$\text{ang} = \frac{180k}{n}.$$並べ替え:$$n \cdot \text{ang} = 180k.$$それで$180k$で割り切れる必要があります$\text{ang}$、そして私たちは最小のものを望んでいます$n$整数が存在するように$k$平等を成り立たせること。 以来$k$非縮退アークに対応します。正であり、以下である必要があるだけです。$n$しかし、存在のために私たちは常に選択することができます$k$比率が機能する場合は適切に。 

させて$g = \gcd(180, \text{ang})$。 次に、次のように単純化できます。$$\text{ang} = \frac{180}{n}k \Rightarrow n = \frac{180k}{\text{ang}}.$$書く$180 = g \cdot 180'$、$\text{ang} = g \cdot a'$、与える:$$n = \frac{180'k}{a'}.$$最小限に抑えるには$n$、最小の正を選択します$k$そのような$a' \mid 180'k$。 以来$a'$そして$180'$が互いに素である場合、これには次のことが必要です$k = a'$、次の結果が得られます。$$n = 180'.$$したがって、答えは次のようになります。$$n = \frac{180}{\gcd(180, \text{ang})}.$$必要な角度を実現できる最小のポリゴン サイズです。

 ## アルゴリズムのチュートリアル

 1. 各クエリの角度を読み取ります。 問題はテスト ケースごとに独立しているため、それぞれを単独で解決できます。 
2. 180 と指定された角度の間の最大公約数を計算します。 このステップでは、等しい円形分割を使用してどの角度部分が達成可能かを決定する最大共有係数を抽出します。 
3. 180 をこの gcd で除算して、候補ポリゴン サイズを取得します。 この値は、角度を 2 つの頂点によって形成される内接角として表すために必要な等しい円弧セグメントの最小数に対応します。 
4. この値は有効な最小値であることが保証されているため、直接出力します。$n$。 

### なぜ効果があるのか

 重要な不変条件は、正 n 角形の 3 つの頂点によって形成されるすべての可能な角度は次のように表現できるということです。$\frac{180k}{n}$ある整数に対して$k$。 これは、円上の構成を解釈し、円周角の定理を使用することから直接得られます。 

したがって、問題は最小のものを見つけることになります$n$そのような$\text{ang} \cdot n / 180$は、有効な整数構造の整数です。$k$。 gcd による削減により、すべての共通因数が確実に削除され、実行可能な最小値が得られます。$n$残っています。 それより小さいもの$n$についての小数要件を再導入することになる$k$、ジオメトリを不可能にします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from math import gcd

t = int(input())
for _ in range(t):
    ang = int(input())
    print(180 // gcd(180, ang))
```解決策は、ジオメトリ全体が 180 と要求された角度の間で割り切れる条件に崩壊するという観察にかかっています。 gcd の計算では、半円全体に対する角度の既約分数が分離され、最後の除算によって、その分数をサポートする最小のポリゴン サイズが得られます。 

ループオーバーはありません$n$、幾何学的シミュレーションはありません。 唯一の微妙な点は、係数 180 が多角形の内角の公式からではなく、円周角の定理から来ていることを認識していることです。 

## 実用的な例

 2 つの入力、54 と 178 をトレースします。 

角度 54 の場合:

 | ステップ | アン | gcd(180, ang) | 180 / gcd | 出力 |
 | --- | --- | --- | --- | --- |
 | 1 | 54 | 18 | 10 | 10 |

 gcd は 18 です。これは、54° が 180° と強い構造を共有していることを意味し、10 角形を使用して角度を形成できるようになります。 これは、10 角形の正多角形の内接角が 54°であるサンプルに相当します。 

このトレースは、解が幾何学的探索ではなく、数論的縮小のみに依存していることを確認します。 

角度 178 の場合:

 | ステップ | アン | gcd(180, ang) | 180 / gcd | 出力 |
 | --- | --- | --- | --- | --- |
 | 1 | 178 | 2 | 90 | 90 |

 ここで、gcd は小さいので、角度は 180 とほぼ一致します。これにより、このような細かい角度解像度を表現するために、より大きな多角形が必要になります。 

トレースは、gcd が減少するにつれて、必要なポリゴン サイズが増加することを示しており、任意の角度を近似するにはより多くの頂点が必要であるという直観と一致しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import math

    t = int(input())
    out = []
    for _ in range(t):
        ang = int(input())
        out.append(str(180 // math.gcd(180, ang)))
    return "\n".join(out)

# provided samples
assert run("4\n54\n50\n2\n178\n") == "10\n18\n90\n90"

# minimum case
assert run("1\n1\n") == "180"

# angle that divides 180 exactly
assert run("1\n60\n") == "3"

# angle close to 180
assert run("1\n179\n") == "180"

# multiple mixed
assert run("3\n45\n90\n30\n") == "4\n2\n6"
```| テスト入力 | 期待される出力 | 検証内容 |

 | 60 | 3 | きれいな除数ケース |
 | 179 | 180 | ほぼ共素エッジ |
 | 45、90、30 | 4、2、6 | 複数の gcd パターン |

 ## 特殊なケース

 微妙なケースは、角度が 180 の約数である場合です。`ang = 60`、gcd は 60 なので、答えは次のようになります。`180 / 60 = 3`。 これは三角形に相当し、単純に対称性によって多くの角度が形成されます。 単純なアプローチでは、三角形がすでに複数の内接角を許可していることを無視しているため、より大きな多角形が必要であると誤って想定される可能性があります。 

のために`ang = 179`、180 の gcd は 1 となり、出力は強制的に 180 になります。ジオメトリの解釈では、そのような角度には非常に細かい角度粒度が必要であり、多角形が多くの頂点を持つ円に近似する場合にのみ達成可能です。 このケースを「単純化」しようとすると、ポリゴン サイズが誤って縮小され、必要な精度を実現できなくなります。 

のために`ang = 1`、gcd も 1 であるため、結果は再び 180 になります。これは、最小角度が 180 単位構造の最大解像度を強制する最大ストレス テストであり、「角度が小さいということはポリゴンが小さいことを意味する」に基づくショートカットはここで機能しません。
