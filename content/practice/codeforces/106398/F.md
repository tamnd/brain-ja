 ## 解決策
 ## 問題の理解

 1 から N までの数字の 2 つの順列が与えられ、都市レイアウトの 2 行として記述されます。 各数字は温度ゾーンを表し、各ゾーンはそれぞれの側に 1 回ずつ表示されます。 最初の行のゾーンと 2 番目の行のゾーンの間に「ブリッジ」を構築できますが、ラベルの絶対差が最大 4 である場合に限ります。さらに、各ゾーンは最大 1 つのブリッジに参加でき、2 つの行の上に描かれている場合は橋を渡ることはできません。 

タスクは、そのような非交差有効橋の数を最大化することです。 

入力サイズ N は最大 1000 で、3 次以上の解は直ちに除外されます。 O(N^2) または O(N^2 log N) のアプローチは許容されますが、指数列挙または一致する順列を明示的に伴うものは許容されません。 

重要な問題は、局所制約 |a − b| ではありません。 ≤ 4 ですが、橋が交差してはならないというグローバル制約があります。 これにより、問題は 2 つの順序付けされたシーケンス間の構造化されたマッチング問題に変わります。 

いくつかの特殊なケースは、精神的に隔離する価値があります。 両方の行が同一である場合 (1 2 3 4 と 1 2 3 4 など)、すべての位置が一致する可能性があり、答えは N になります。ローカル互換性のみをチェックする単純な貪欲は、暗黙的に交差を許可する場合でも失敗する可能性があります。 

行が逆の場合 (1 2 3 4 と 4 3 2 1 など)、多くのペアはローカルで有効ですが、ほとんどすべての選択肢が交差制約と競合するため、値の差による欲張りは大きく失敗します。 

最も微妙なケースは、複数の有効な一致がローカルに存在するが、1 つのサブセットのみが単調な順序を維持する場合です。 

## アプローチ

 交差制約を無視すると、問題は簡単になります。 最初の行のすべての要素を 2 行目の互換性のある要素と単純に照合し、絶対的な差の条件をチェックします。 これは、ラベルが最大 4 異なるすべての左位置が任意の右位置に接続できる 2 部マッチングの問題につながります。N が最大 1000 の場合、標準の最大 2 部マッチング アルゴリズムは、実装に応じて O(N^3) または O(N^{2.5}) で機能します。 

ただし、これは構造を無視しています。 横断制限は任意ではありません。 両方の行が順列であるため、問題を 2 つの順序付けされたシーケンス内の一致する位置として再解釈でき、交差は選択された一致するペアの反転に正確に対応します。 

これにより、問題は最長増加構造に変換されます。 上の行の位置 i と下の行の位置 j の間のペアを固定すると、その後のペアは両方の行の順序を尊重する必要があり、そうでない場合は交差が発生します。 

重要な観察は、考えられるすべての有効なペアを 1 つの座標でソートし、変換された空間内で最も長く増加する部分列として非交差一致の最大数を計算できること、または同等の位置に対する動的プログラミングを計算できることです。 

これを確認するきれいな方法は、一番上の行を順番に繰り返すことです。 各位置 i について、それを一番下の行にあるすべての互換性のある位置 j と照合しようとします。 各値は 1 回出現するため、各値のインデックスによって最下位の位置を表すことができます。 次に、問題をインデックスの値の差と単調性の制約の下でペア (i, pos[b[i]]) を選択することに還元します。これは 2D LIS スタイルの DP になります。 

上の行では i まで、下の行では j までのプレフィックスを使用して、dp[i][j] を最良の一致として定義します。 遷移では、値に互換性がある場合にのみ一致が許可されます。 これは本質的に、局所性制約を伴う 2 部順列グラフにおける最大マッチングであり、O(N^2) で解決できます。

ブルート フォースはすべてのペアの組み合わせを試し、交差の有効性を明示的にチェックするため、指数関数的な時間がかかります。 DP は、非交差構成のみを拡張することを保証することで構造を圧縮します。

 ## アルゴリズムのチュートリアル

 互換性チェックを簡素化するために、値を位置に変換します。 pos2[x] を 2 行目の値 x のインデックスとします。 

次に、最初の行を左から右に処理し、形成できる有効な非交差一致の数を追跡する動的プログラミング テーブルを維持します。 

### ステップ

 1. 配列 pos2 を構築します。ここで、pos2[value] は 2 行目の値のインデックスを示します。 これにより、値の一致をインデックスの比較に置き換えることができます。 
2. dp[i][j] を、最初の行の最初の i 要素と 2 行目の最初の j 要素を考慮した有効なブリッジの最大数として定義します。 この公式は、インデックスを増加させると自然に順序が維持されるため、非交差制約をエンコードします。 
3. 要素がないことはブリッジがないことを意味するため、dp[0][_] と dp[_][0] をゼロに初期化します。 
4. i を 1 から N まで繰り返します。各 i について、j を 1 から N まで繰り返します。各状態で、要素の 1 つをスキップするか、現在のペアとの一致を試みるかを決定します。 
5. まず、最もよく知られている値を伝播します。dp[i][j] は、dp[i-1][j] と dp[i][j-1] の最大値を取得します。 これにより、片側をスキップする場合の最適な解決策が引き継がれます。 
6. 最初の行の i 番目の値と 2 番目の行の j 番目の値が接続できるかどうか、つまりラベルの絶対差が最大 4 であるかどうかを確認します。 
7. 互換性がある場合は、dp[i-1][j-1] + 1 から dp[i][j] に遷移してブリッジの形成を試みます。 これにより、各要素が 1 回だけ照合され、順序が維持され、交差が防止されます。 
8. 答えは dp[N][N] です。 

### なぜ効果があるのか

 DP は、インデックス i と j の両方で単調構造を強制します。 どのブリッジも常に増加するプレフィックスを接続するため、選択された 2 つのブリッジが交差することはできません。i1 < i2 で一方が (i1, j1) を使用し、もう一方が (i2, j2) を使用する場合、遷移構造により j1 < j2 が強制されます。 繰り返しでは、一致した場合にのみ斜めに進むことができ、厳密な順序の保持がエンコードされます。 すべての有効な非交差マッチングは、そのような斜めの動きの単調なシーケンスに対応するため、DP はすべての実行可能な解決策を取得し、それらの中から最大数の一致を選択します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    pos2 = [0] * (n + 1)
    for i, v in enumerate(b, 1):
        pos2[v] = i

    dp = [[0] * (n + 1) for _ in range(n + 1)]

    for i in range(1, n + 1):
        ai = a[i - 1]
        for j in range(1, n + 1):
            dp[i][j] = max(dp[i - 1][j], dp[i][j - 1])

            bj = b[j - 1]
            if abs(ai - bj) <= 4:
                dp[i][j] = max(dp[i][j], dp[i - 1][j - 1] + 1)

    print(dp[n][n])

if __name__ == "__main__":
    solve()
```実装は DP 定義に直接準拠します。 ネストされたループは、すべてのプレフィックス ペアを列挙します。 移行`max(dp[i-1][j], dp[i][j-1])`要素をスキップしても最適なソリューションが失われないようにします。 対角線の遷移は、有効なブリッジの選択をエンコードします。 絶対差のチェックは、問題固有の制約が適用される唯一の場所です。 

よくある間違いは、1 つの配列のみの位置に基づいてマッチングを試みることです。 これは、2 行目の順序を無視するため、交差制約を破ります。 もう 1 つの間違いは、可能な限り貪欲に一致させることです。これは、初期の一致によってその後の複数の最適な一致がブロックされる可能性があるため失敗します。

 ## 特殊なケース

 エッジ ケースの 1 つは、差分制約により 1 つのペアリングのみが可能な場合です。 たとえば、a = [1, 10, 20]、b = [100, 2, 21]。 DP では (10, 2) または (20, 21) のみが許可されますが、順序付けの競合が発生した場合は両方は許可されません。 DP を実行すると、有効な一致は一貫したプレフィックス アラインメントでのみ表示され、アルゴリズムは最適な単一チェーンを正しく選択します。 

もう 1 つのエッジ ケースは、すべての値が 1 ～ 5 の範囲内にあり、すべてのペアがローカルで有効になる場合です。 この状況では、ソリューションは交差制約によって完全に制御されます。 DP は、2 つの順列間の最長の非交差マッチングを見つけることに帰着し、反復により単調ペア選択のみが確実に生き残ります。 

最後のエッジ ケースは、複数の位置に一致する可能性がある中央の単一の値など、互換性のあるペアが存在するが分離されている場合です。 DP はこれを自然に処理します。これは、スキップする遷移と対角の一致を比較し、局所的には良好だがグローバルにブロックする一致が決して強制されないことを保証するためです。
