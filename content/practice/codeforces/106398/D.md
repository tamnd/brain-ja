 ## 問題の理解

 次のサイズの長方形グリッドが与えられます。$N \times M$。 ハムスターは左上のセルから開始し、右斜め下に 45 度の角度で移動し、訪問したすべてのセルにマークを付けます。 側壁（左右の境界）に到達すると、完全に跳ね返ったように反射し、反対の斜め方向に沿って移動し続けます。 底部の境界がないため、ハムスターが底部の端に到達するかそれを越えると、グリッドから離れ、プロセスが停止します。 

タスクは、物理学を継続的にシミュレートすることではなく、この跳ねる斜めの歩行中にどのグリッド セルが訪問されるかを正確に判断し、ASCII 描画を出力することです。 訪問したすべてのセルには がマークされます。`*`、未訪問のセルはすべて`#`。 

制約により許可されるのは、$N, M \le 500$したがって、グリッドには最大 250,000 個のセルがあります。 セルごとに段階的に実行する直接シミュレーションはすでに実現可能ですが、不必要な複雑化や無限バウンスする可能性のあるロジックの間違いを避けるために、より慎重な観察が必要です。 

重要なエッジの動作は、左右の境界での反射です。 単純なメンタル モデルは連続的な幾何学的な動きを試みるかもしれませんが、グリッドの性質により、パスは常に整数座標上に留まり、垂直方向の境界にぶつかった場合にのみ方向が変わります。 

微妙なエッジケースが発生する場合$N = 1$または$M = 1$。 このような場合、ハムスターはすぐに下向きに退出するか、退化した方法で反射を繰り返します。 たとえば、次の場合$N = 1, M = 5$, ハムスターは (0, 0) から開始し、斜めに移動すると最初のステップで下から出るため、すぐに終了します。 少なくとも 1 つの反射を前提とした解決策は、ここでは失敗します。 

もう 1 つの例外的なケースは次のような場合です。$N$または$M$が 1 であり、境界反射ロジックが適切に保護されていません。 不用意に実装すると、方向を何度も反転しようとしたり、グリッドの外側にインデックスを付けようとしたりする可能性があります。 

## アプローチ

 ブルートフォースアプローチは、文字通りハムスターの動きを段階的にシミュレートすることです。 現在の位置と方向を維持し、最初は右下に移動します。 各ステップで現在のセルをマークし、斜めに移動しようとします。 次の位置が左右の境界の外側に出る場合は、水平方向を反転して続行します。 次の垂直ステップが超えると停止します。$N - 1$。 

移動ルールは決定論的であり、局所的な境界条件のみに依存するため、このシミュレーションは正しいです。 ただし、各ステップで移動するのは 1 つのセルのみであり、最悪の場合、ハムスターはジグザグ パターンですべてのセルを横断し、潜在的に訪問する可能性があります。$O(NM)$ステップ。 これでも制約には適合しますが、実装では方向反転や終了条件でオフバイワンエラーが発生する傾向があります。 

重要な観察点は、パスが予期せずに分岐したり再訪したりしないことです。 これは、反射を伴う単一の決定論的な対角線のトラバースです。 これは、シミュレーションが複雑さの点ですでに最適化されているにもかかわらず、幾何学的な推論を行わずに方向変更と境界処理を直接エンコードすることで実装を非常にクリーンにできることを意味します。 

したがって、シミュレーションを保持しますが、水平の壁でのみ反転し、底部を通過した場合にのみ終了する方向ベクトルを使用したグリッドウォーキングとして扱います。

 ## アルゴリズムのチュートリアル

 ハムスターを、方向状態を持つ整数座標上を移動する点として扱います。 

1. サイズの 2D グリッドを初期化します。$N \times M$でいっぱい`#`。 これは、触れられていないセルを表します。 訪問したセルを上書きします`*`ハムスターがそこを通過するとき。 
2. 位置から開始$(r, c) = (0, 0)$そして方向$(dr, dc) = (1, 1)$、右下を意味します。 これは、問題で説明されている 45 度の斜めの動きと一致します。 
3. 現在のセルをマークします$(r, c)$に設定して訪問したとき`*`。 これにより、動作の決定が行われる前に、ハムスターが占めるすべての位置が確実に記録されます。 
4. 次のセルに移動してみます$(r + dr, c + dc)$。 移動を開始する前に、水平方向の境界を確認してください。 

もし$c + dc < 0$または$c + dc \ge M$、設定により水平方向を反転します。$dc = -dc$、次の列を再計算します。 

このステップでは、垂直の壁での反射をモデル化します。 バウンスは左右の動きにのみ影響するため、ここでは行の方向を変更しません。 
5. 水平反射を解決した後、次の行の位置が正しいかどうかを確認します。$r + dr$超えるか等しい$N$。 そうなった場合、ハムスターは底から出てシミュレーションが停止します。 
6. 移動が有効な場合は、更新します。$(r, c)$次の位置に移動し、手順 3 から繰り返します。 
7. 終了条件がトリガーされるまで続行します。 

このループは、各反復でハムスターが有効な対角パスに沿って 1 セルずつ前方に移動するか、グリッドを離れるとすぐに終了することを保証します。 

### なぜ効果があるのか

 不変条件は、すべてのステップにおいて、現在のセルが、垂直境界での完全な反射を伴う 45 度のラティス ウォークによって訪問されるセルの 1 つであるということです。 方向ベクトル$(dr, dc)$反射間のパス セグメントの正しいローカル スロープを常にエンコードします。 反射は列の境界のみに依存し、行の増分符号を変更しないため、反転によってモーションが完全にキャプチャされます。$dc$必要なときに。 

移動するたびに行インデックスが厳密に 1 ずつ増加するため、プロセスは最大でも 1 秒後に終了する必要があります。$N$ステップごとに、訪問されたすべての位置が一意の行に対応します。 したがって、セルがスキップされたり、間違って再訪問されたりすることはなく、結果として得られるマーキングは正確です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    grid = [['#'] * m for _ in range(n)]

    r, c = 0, 0
    dr, dc = 1, 1

    while True:
        grid[r][c] = '*'

        nr = r + dr
        nc = c + dc

        if nc < 0 or nc >= m:
            dc = -dc
            nc = c + dc

        if nr >= n:
            break

        r, c = nr, nc

    for row in grid:
        print(''.join(row))

if __name__ == "__main__":
    solve()
```この実装は、前述のシミュレーションを直接反映しています。 グリッドは次のように初期化されます`#`、訪問された各セルは次のように上書きされます。`*`。 

方向変数`dr`そして`dc`斜めの動きをエンコードします。 のみ`dc`これにより、下降移動ロジックの誤った破損が防止されます。 

終了チェックは、暫定的な次の行を計算した後に行われます。 これにより、終了する前に最後の有効な位置がマークされることが保証されます。これは、ハムスターが下の境界に触れるとすぐに離れるため、必要です。

 ## 特殊なケース

 のために$1 \times 1$、アルゴリズムは (0,0) から始まり、それをマークし、すぐに次の行を 1 として計算します。$N$, それで終了します。 反射は発生せず、出力は単一になります。`*`。 

のために$1 \times M$、同じロジックが適用されます。 ハムスターは下にまったく移動できないため、開始セルをマークして終了するだけです。 最初に水平方向の反射を計算しようとする実装は、移動をコミットする前に行の終了がチェックされるため、安全です。 

のために$N \times 1$、水平方向の移動はすぐに方向を反転しますが、結果は同じ列になるため、水平方向の反射は無関係になります。 パスは事実上下向きの直線となり、終了するまで唯一の列のすべてのセルをマークします。
