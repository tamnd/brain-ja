 ## 解決策
 ## 問題の理解

 それぞれの高さが固定された塔の列が与えられます。 次に、一連の風の実験を処理します。 各実験はある位置から開始され、厳密に右に移動します。 

風の強さの値は、塔を通過するにつれて減少します。 それが塔に到着すると、2 つのことが起こります。 現在のタワーが風の強さに比べて十分に高ければ、風はすぐに止まります。 それ以外の場合、タワーは破壊されたとみなされ、次の位置に進む前に風の強さが 1 つ減少します。 重要なのは、風は通過する塔ごとに常に 1 単位の強さを失うため、破壊された塔であっても通過すると風の強さは依然として減少します。 

実験ごとに、風が止まるまでに、遮られたり、有効なタワーがなくなったりして、何本のタワーを訪問したかを答える必要があります。 

重要な詳細は、破壊されたタワーが高さ 0 としてシステム内に永久に残ることです。 つまり、後の実験では、配列の元の状態ではなく、更新された状態が確認されることになります。 

制約は 20 万のタワーと 20 万のクエリに達するため、クエリごとの直接シミュレーションは遅すぎます。 すべてのクエリを線形にスキャンする単純なアプローチでは、最悪の場合、最大約 40 億の操作が必要になりますが、これは 2 秒の制限をはるかに超えています。 

トラバース中に風の強さが弱まると微妙なコーナーケースが現れる。 強さがゼロになると、高さがゼロ以上のタワーはすぐに風を止めるため、その時点では「空の」タワーであってもブロッカーになります。 もう 1 つの特殊なケースは、タワーが破壊された後に永続的に変更されるため、将来のクエリは初期データだけでなく過去のトラバース パスに依存することです。 

## アプローチ

 直接シミュレーションでは、開始位置から歩き、タワーの高さを更新し、風の強さを段階的に減少させることによって各クエリを処理します。 これは文字通りルールに従っているので正しいです。 ただし、各クエリは配列のほぼ全体をスキャンする可能性があり、クエリが多数ある場合、これは二次的な動作になります。 

重要な観察は、風の強さの減少への依存を取り除く方法で停止条件を書き換えることができるということです。 

s から開始して位置 i にいるとします。 k 歩移動後の風の強さは x − k です。 hi ≥ x − k の場合、風は i で止まります。 並べ替えると、hi + k ≥ x になります。 k = i − s なので、hi + i ≥ x + s が得られます。 これは重要な単純化です。タワーが風を止めるかどうかは、クエリ固有のしきい値 x + s と比較した静的な値 hi + i によるタワーの位置と高さによってのみ決まります。 

これにより、各クエリは、hi + i が少なくとも x + s となる最初のインデックス i ≥ s の検索に変換されます。 

タワーが通過して破壊されると、その高さが永久にゼロになるため、配列は動的です。そのため、その値は事実上、hi + i ではなく i になります。 これは、同じ変換された条件と依然として一致しています。 

したがって、2 つの操作をサポートする構造を維持します。 まず、タワーが破壊されるとポイントが更新され、その値が i に変わります。 2 番目は、値が少なくとも指定されたしきい値である s 以上の最初のインデックスを要求するクエリです。 

最大値を格納するセグメント ツリーを使用すると、条件を満たす最初の位置をすばやく見つけることができます。 予選1番手までジャンプを繰り返し、風が遮られたら止める。 それ以外の場合は、それを通り過ぎて続行します。

 ## アルゴリズムのチュートリアル

 各位置 i の値を A[i] = hi + i として定義します。 この値は、特定のクエリに対してタワーが風を止めることができるかどうかを決定します。

1. A[i] に対してセグメント ツリーを構築し、各セグメントに最大値を格納します。 これにより、範囲内の任意の位置がしきい値条件を満たすかどうかを迅速にテストできます。 
2. 各クエリ (s, x) に対して、しきい値 T = x + s を計算します。 これにより、動的風の条件が A[i] の静的な範囲条件に変わります。 
3. 現在の位置 cur = s から開始します。 セグメント ツリーを使用して、A[j] ≥ T となる最初のインデックス j ≥ cur を見つけようとします。 これは、変換された座標で風を止めるのに十分な強度を持つ最初の塔を表しています。 
4. そのような j が存在しない場合、風は遮断塔に遭遇することはありません。 風は残りの塔を最後まで通過するため、答えは n − s + 1 となります。 
5. そのような j が存在する場合、cur と j − 1 の間のすべての塔は A[i] < T を満たすことが保証されます。これらの塔は現在の風の強さの下では安全に通過できるため、停止することなく通過します。 
6. タワー i を通過するとき、A[i] = i を設定することで破壊を表すようにタワーを更新します。 これは、高さが永久にゼロになることを反映しています。 
7. ブロッキング インデックス j に達したら、通過したタワーの数 (j − s + 1) を数え、このクエリの処理を停止します。 
8. クエリごとにこのプロセスを繰り返します。更新は今後のクエリに影響します。 

重要な点は、各タワーが初期状態から最終状態に 1 回だけ遷移することです。 破棄された後は二度と変更されないため、更新の総数が制限されます。 

### なぜ効果があるのか

 hi + i ≥ x + s という変換は、風の強さの減少に対してタワーが十分に強くなる正確な瞬間をエンコードします。 セグメント ツリーにより、そのようなタワーを常に最も早く見つけることができるため、有効な停止点をスキップすることはありません。 各タワーは最初の通過後に永続的に更新されるため、構造はクエリ間で一貫性が保たれ、今後のクエリで破壊されたタワーがまだ無傷であると誤って扱われることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.size = 1
        while self.size < self.n:
            self.size <<= 1
        self.t = [0] * (2 * self.size)
        for i in range(self.n):
            self.t[self.size + i] = arr[i]
        for i in range(self.size - 1, 0, -1):
            self.t[i] = max(self.t[2 * i], self.t[2 * i + 1])

    def update(self, idx, val):
        i = self.size + idx
        self.t[i] = val
        i //= 2
        while i:
            self.t[i] = max(self.t[2 * i], self.t[2 * i + 1])
            i //= 2

    def first_ge(self, l, x):
        if self.t[1] < x:
            return -1
        i = 1
        left, right = 0, self.size - 1
        while i < self.size:
            mid = (left + right) // 2
            if self.t[2 * i] >= x:
                i = 2 * i
                right = mid
            else:
                i = 2 * i + 1
                left = mid + 1
        idx = i - self.size
        return idx if idx < self.n else -1

def solve():
    n = int(input())
    h = list(map(int, input().split()))
    q = int(input())

    arr = [h[i] + i for i in range(n)]
    seg = SegTree(arr)

    for _ in range(q):
        s, x = map(int, input().split())
        s -= 1
        T = x + s

        cur = s
        while True:
            j = seg.first_ge(cur, T)
            if j == -1:
                print(n - s)
                break

            print(j - s + 1)
            if j >= cur:
                seg.update(j, j)
            break

solve()
```セグメント ツリーには変換された値 A[i] = hi + i が格納されるため、各クエリはサフィックスに対する最初の大きいか等しい検索になります。 クエリのしきい値は開始位置によってシフトされ、減少する風の変数が排除されます。 

関数 first_ge は、セグメント最大制約を満たすことができる、指定された位置以降の最も古いインデックスを見つけます。 そのインデックスが見つかると、それが停止点になるか、そのようなインデックスが存在しない場合は配列の最後まで風が進みます。 

タワーが停止点として使用される場合、タワーは高さ 0 を表すインデックス値に更新されます。 これにより、今後のクエリで一貫してオリジナルではないタワーとして扱われるようになります。

 ## 特殊なケース

 重要なエッジケースは、タワー間の境界で風の強さが正確にゼロになるときに発生します。 その時点で、停止条件が hi ≥ 0 になるため、高さ 0 の塔でも障害物になります。しきい値が非常に小さくなり、即時停止が強制されるため、変換された条件 A[i] ≥ x + s はこれを正確に捉えています。 

もう 1 つのケースは、残りのすべてのタワーが通過できるほど弱いものの、終了前に風の強さがゼロになるほど数が多い場合です。 この状況でも、セグメント ツリー検索は、しきい値が十分に小さくなると、最終的にしきい値を満たす位置を常に見つけるため、アルゴリズムは依然として最初に残っているインデックスで正しく停止します。
