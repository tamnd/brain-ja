 ## 解決策
 ## 問題の理解

 私たちには、列に並んだ精霊の列が与えられ、それぞれに初期の高さが設定されています。 2 人のオブザーバーがこのキューを反対側から観察しますが、それぞれが非常に具体的な可視性ルールを持っています。 

ゆうばあばは左端から左から右に目を走らせ、その高さが彼女がこれまでに見たすべての霊よりも厳密に大きい場合にのみ霊に気づきます。 右端から、ハクは同じことを行いますが、右から左にスキャンし、再び、彼がすでに側から見たすべてのものよりも厳密に大きい場合にのみ、霊に気づきます。 

霊はどちらの観察者でも気づくことができ、両方の観察者がそれに気づいたとしても、それは 1 回だけカウントされます。 スピリットを 1 つだけ選択し、その高さを任意の正の整数に変更することができます。 目標は、この 1 回の変更後に 2 人の観察者のうちの少なくとも 1 人が何個の異なる霊に気づくかを最大化することです。 

重要な制約は、n が 200000 まで大きくなる可能性があるため、考えられる変更ごとに可視性を直接再計算しようとするソリューションは遅すぎるということです。 すべての候補にわたる二次または三次シミュレーションは直ちに不可能であり、各変更後の可視性の O(n^2) 再計算でさえ限界をはるかに超えてしまいます。 

素朴な考えによる微妙な失敗例は、答えが単純にプレフィックスの最大値とサフィックスの最大値から重複を引いた数であると仮定することです。 この考えは、1 つの要素を変更すると、接頭辞と接尾辞の両方の最大値チェーンが非ローカルな方法で再形成される可能性があることを無視しています。 たとえば、配列が厳密に増加している場合、最初は 1 つのスピリットのみが表示されますが、慎重に選択した要素を増やすと、両側から複数の新しい可視要素が突然導入される可能性があります。 

もう 1 つの特殊なケースは、最大値が中央にある場合です。 たとえば、`[1, 10, 2, 3, 4]`、どちらの観測者もすでにいくつかの要素を認識していますが、`10`変更方法に応じて、複数の可視性イベントを破棄または作成できます。 

課題は、単一の値の変更がプレフィックス最大値とサフィックス最大値の構造に同時にどのように影響するかを理解することです。 

## アプローチ

 可視性ルールは基本的に、記録的な最高値に関するものです。 左から、Yubaaba には接頭辞 maxima が正確に表示されます。 右から見ると、ハクには接尾語の最大値が正確に表示されます。 したがって、注目されるスピリットの総数は、接頭辞の最大位置と接尾辞の最大位置の和集合のサイズになります。 

変更を加えずに、両方のセットを線形時間で計算できます。 

強引なアプローチは、すべてのインデックスを修正されたスピリットとして試し、可能なすべての新しい高みを試すことです。 このような構成ごとに、O(n) のプレフィックスとサフィックスの最大セットを再計算し、最良の答えを取得します。 インデックスには n 個の選択肢があり、関連する高さの選択肢は潜在的に O(n) 個あるため、意味のある高さに制限したとしても、これはすぐに O(n^2) かそれ以上になり、2e5 には遅すぎます。 

重要な洞察は、実際には任意の高さの選択が必要ないということです。 重要なのは、変更された要素がプレフィックスとサフィックスの最大値チェーンにどのように参加するかです。 それは無関係になるか、以前は別々だった 2 つの可視領域を橋渡しできる新しいレコードになります。 

配列を見ると、プレフィックス maxima は特定の位置で厳密に増加する値のシーケンスを形成し、サフィックス maxima は別のそのようなシーケンスを形成します。 これら 2 つのシーケンスの結合により、現在表示されているすべてのスピリットが定義されます。 この結合を増やす唯一の方法は、選択した要素をプレフィックス セグメント、サフィックス セグメント、またはその両方で新しい最大値にし、2 つの可視性の境界をマージすることです。 

これにより、問題は 1 つの位置に 1 つの新しい値を挿入することによって作成できる新しいプレフィックス最大値とサフィックス最大値の数を理解することになります。 

それぞれの位置について、この要素が左からある点まで、および右から下からある点まで見えるようにする最適な高さを検討できます。 これは特性評価につながります。通常、最良の新しい値は、セグメント内の既存の最大しきい値をわずかに上回る値になります。これは、それを超えて増加しても可視性構造が変化しないためです。 

プレフィックスの最大値とサフィックスの最大値を事前に計算できます。 次に、位置ごとに、この位置をある区間を支配する新しい最大値に強制した場合に、どれだけの新しい可視要素が得られるかを推論します。 

最後の最適化は、可視ポイントの構造によって配列が連続するプレフィックス最大値とサフィックス最大値の間のセグメントに分割され、1 つの要素を変更するだけでそのようなセグメント境界の 1 つをマージまたは拡張できることを認識することです。 したがって、すべての値ではなく、これらの境界から導出された少数の重要な構成のみを評価する必要があります。

 ## アルゴリズムのチュートリアル

 まず 2 つの配列を計算します。 1 つは位置ごとに、それがプレフィックスの最大値であるかどうかを保存し、もう 1 つはそれがサフィックスの最大値であるかどうかを保存します。 これらは、それぞれ単一の前方パスと後方パスで計算できます。 

次に、接頭辞の最大値または接尾辞の最大値である位置の数としてベースラインの答えを計算します。 

次に、単一の位置 i を変更すると何が起こるかを考えます。 重要な観察は、i の右側の接頭辞最大構造と i の左側にある接尾辞最大構造のみがこの変更の影響を受ける可能性があるということです。 すでに割り当てられる値よりも厳密に大きい、遠く離れたものはすべて影響を受けません。 

固定 i の場合、左側のある境界までのすべてのプレフィックス最大値を超えるのに十分な大きさの a[i] を作成することを検討します。 これにより、i が新しいプレフィックスの最大値になることが保証されます。 同様に、右側の接尾辞の最大値と比較して十分な大きさにして、接尾辞の最大値にすることができます。

この影響が両方向にどの程度伝わるかを計算します。 左側では、i より前の最後のプレフィックスの最大値を検索し、右側では、i の後の最初のサフィックスの最大値を検索します。 a[i] を関連する両方のしきい値を超えてアップグレードすると、以前は別々だった 2 つの可視性チェーンが接続される可能性があります。 

i がブリッジ最大値として機能するため、各 i について、表示される新しい位置の数を評価します。 これをベースラインの答えと比較し、最大値を維持します。 

最後に、何も変更しないというオプションも含めて、すべての i にわたる最良の値を出力します。 

なぜ効果があるのか

 目に見えるすべての位置は、少なくとも 1 つの方向からの記録破りの値に対応します。 1 回の変更で導入できるのは、左から 1 つと右から 1 つの新しいレコード チェーンのみであり、これらのチェーンは支配しきい値の点で連続しています。 プレフィックスとサフィックスの最大値は単調な構造であるため、変更された要素によって作成された新しい可視性は i に固定され、次に大きい元の値によってブロックされるまで拡張する必要があります。 この制限により、変更の効果が i 周囲の極大境界によって完全に決定されることが保証されるため、最適なゲインを見つけるには、すべての i をスキャンしてその境界拡張を評価するだけで十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    pref = [False] * n
    suf = [False] * n
    
    mx = -10**18
    for i in range(n):
        if a[i] > mx:
            pref[i] = True
            mx = a[i]
    
    mx = -10**18
    for i in range(n - 1, -1, -1):
        if a[i] > mx:
            suf[i] = True
            mx = a[i]
    
    base = 0
    for i in range(n):
        if pref[i] or suf[i]:
            base += 1
    
    # precompute next greater prefix/suffix boundaries
    # next prefix max to left, previous suffix max to right
    left_bound = [-1] * n
    last = -1
    for i in range(n):
        if pref[i]:
            last = i
        left_bound[i] = last
    
    right_bound = [n] * n
    last = n
    for i in range(n - 1, -1, -1):
        if suf[i]:
            last = i
        right_bound[i] = last
    
    ans = base
    
    for i in range(n):
        gain = 1
        
        if left_bound[i] != -1:
            gain += (i - left_bound[i] - 1)
        else:
            gain += i
        
        if right_bound[i] != n:
            gain += (right_bound[i] - i - 1)
        else:
            gain += (n - i - 1)
        
        ans = max(ans, gain)
    
    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、まず線形スキャンを使用してすべてのプレフィックスとサフィックスの最大位置を特定します。 これらは、各側からどの精霊が最初に見えるかに直接対応します。 

ベースライン数は、これら 2 つのセットを結合することによって計算されます。 

次に、各位置の左側に最も近いプレフィックス最大値と、各位置の右側に最も近いサフィックス最大値を配置するヘルパー配列を構築します。 これらの境界は、既存のより強力なレコードによってブロックされる前に、新しくブーストされた要素が可視性をどこまで拡張できるかを定義します。 

各インデックスについて、それをその領域内で支配的な要素にすることをシミュレートします。 ゲインの式は、この要素が両方向で次の記録破りになった場合に、左右の未表示の要素がいくつ新たに表示されるかをカウントします。 すべての位置の最大値が最終的な答えになります。

 ## 特殊なケース

 次のような単一要素の配列`[5]`は、両方のオブザーバーが同じスピリットを見ていることを示しているため、結合サイズは 1 であり、いかなる変更もそれを増やすことができません。 プレフィックス スキャンとサフィックス スキャンの両方で唯一の位置が最大値としてマークされ、境界からゲインが計算されないため、アルゴリズムはこれを処理します。
