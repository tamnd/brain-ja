 ## 問題の理解

 の行が与えられています$N$ハムスター、どこ$N$は均等です。 各ハムスターは、文字としてエンコードされた、立っているか座っているかの 2 つの状態のいずれかになります。`X`そして`x`。 1 回の操作で 1 匹のハムスターを選択し、その状態を反転できます。 目標は、ちょうど半分のハムスターが立っていて、残りの半分が座っているという構成に達することであり、反転の数を最小限に抑えたいと考えています。 このバランスを達成する結果として得られる有効な構成も出力する必要があります。 

制約から分かる重要な点は次のとおりです。$N$と同じ大きさにすることができます$2 \cdot 10^5$したがって、どのソリューションも線形時間で実行する必要があります。 これにより、すべてのサブセットを試行したり、一連の操作をシミュレートしたりするアプローチは即座に除外されます。 検索プロセスではなく、直接カウントする引数が必要です。 

初期構成ですでにバランスが取れている場合、微妙なエッジケースが発生します。 例えば、`XxXx`すでに同数の`X`そして`x`したがって、答えはゼロであり、文字列は変更されないはずです。 もう 1 つのエッジケースは、すべてのハムスターが同一である場合です。`XXXXxx...`または`xxxxXX...`、答えは正確にここにあります$N/2$最終的な構成は一意ではありません。 有効なバランスの取れた配置はどれでも受け入れられるため、任意に構築できます。 

## アプローチ

 ブルートフォース解釈では、各ハムスターを独立して扱い、正確に到達することを目指して、それをひっくり返すかどうかを決定しようとします。$N/2$立っているハムスター。 これは、最終的なカウント制約が維持されるように、反転する位置のサブセットを選択することと同じです。 原則として、以下のサイズのすべてのサブセットを試すことができます。$N$、しかし、これはおおよそ指数関数的に増加します$2^N$、でもそれは不可能です$N = 40$、ましてや$2 \cdot 10^5$。 

問題の構造では、立場間の相互作用がすべて排除されています。 各反転は 1 匹のハムスターのみを変更し、不均衡の修正に正確に 1 ユニット貢献します。 私たちが必要とする唯一のグローバル情報は、その数です。`X`現在存在しています。 その数値がわかっている場合、最終的な状態は、どれだけ変更する必要があるかによって決まります。`X`に`x`またはその逆。 

あると仮定します$cntX$立っているハムスター。 ターゲットは$N/2$。 もし$cntX > N/2$、正確に変換する必要があります$cntX - N/2$立っているハムスターを座っているハムスターに変える。 もし$cntX < N/2$、変換する必要があります$N/2 - cntX$座っているハムスターを立っているハムスターに変える。 この数に達する選択肢はすべて有効であるため、左から右に貪欲に選択できます。 

したがって、最適な解決策は、単純なカウント パスとそれに続く建設的なパスになります。

 ## アルゴリズムのチュートリアル

 1. の数を数えます`X`入力文字列に。 これにより、立っているハムスターがもっと必要か、座っているハムスターがもっと必要かが決まります。 
2. 目標の差を計算する$need = |cntX - N/2|$。 フリップごとに合計数が変化するため、これが必要なフリップの正確な数です。`X`1つずつ。 
3. もし$cntX == N/2$、文字列はすでに有効であるため、変更する必要はありません。 0 と元の文字列を出力します。 
4. それ以外の場合は、修正の方向を決定します。 多すぎる場合`X`、いくつかを反転する必要があります`X`の中へ`x`。 数が少なすぎる場合は、いくつかを反転する必要があります`x`の中へ`X`。 
5. 文字列を左から右にスキャンし、まだ修正が必要で、現在の文字が変更したい方向と一致する場合は、貪欲に反転を適用します。 
6. 必要な反転をすべて実行したら停止します。 これにより、文字列を過度に変更しないことが保証されます。 

貪欲スキャンで十分な理由は、すべての位置が交換可能であるためです。 位置的な制約がないため、先にインデックスを選択しても後でインデックスを選択しても、実現可能性に影響はありません。 

### なぜ効果があるのか

 このプロセスは単純な不変条件を維持します: プレフィックスをインデックスまで処理した後$i$、必要なフリップの総数を超えることなく、そのプレフィックス間で必要なだけフリップをすでに実行しています。 反転するたびに不均衡がちょうど 1 だけ減少し、不均衡が 0 に達したときに正確に停止するため、最終的な構成は正確に次のようにする必要があります。$N/2$の発生`X`。 どのステップも将来の選択に依存しないため、貪欲な決定によって実現可能性が無効になることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    s = list(input().strip())

    cntX = sum(1 for c in s if c == 'X')
    target = n // 2

    if cntX == target:
        print(0)
        print("".join(s))
        return

    if cntX > target:
        need = cntX - target
        for i in range(n):
            if need == 0:
                break
            if s[i] == 'X':
                s[i] = 'x'
                need -= 1
    else:
        need = target - cntX
        for i in range(n):
            if need == 0:
                break
            if s[i] == 'x':
                s[i] = 'X'
                need -= 1

    print(abs(cntX - target))
    print("".join(s))

if __name__ == "__main__":
    solve()
```解決策は数​​えることから始まります`X`単一のパスで、世界的な不均衡が確立されます。 条件付き分岐は 2 つの対称的なケースを分離します: 過剰の削減`X`またはそれらを増やします。 欲張りループは、正確に必要なフリップ数に達するまで、最初の適切な位置のみを変更し、構築による最小限性を保証します。 

一般的な実装の落とし穴は、必要なフリップが終了した後もループを継続することであり、これにより不必要な変更が導入され、最小性が侵害されます。 早期ブレークにより、演算数が計算された差と正確に一致することが保証されます。

 ## 特殊なケース

 のような入力の場合`N = 2`と`XX`、アルゴリズムは次のように計算します。`cntX = 2`、ターゲット`1`, したがって、1回のフリップが必要です。 左から右にスキャンし、最初の部分を反転します`X`、すぐに止まります。 結果は次のようになります`Xx`、最小限の変更で要件を満たします。 

のために`N = 2`と`xx`、同じロジックが逆に適用されます。 スキャンは最初のスキャンを反転します`x`に`X`、生産`Xx`。 方向の対称性により、アルゴリズムがカウントを超えた初期分布に依存しないことが確認されます。 

すでにバランス入力されている場合`xxXX`、早期チェックにより、いかなる変更も防ぐことができます。 アルゴリズムはすぐに終了し、元の文字列が保存され、コストゼロが保証されます。
