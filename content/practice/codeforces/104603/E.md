 ## 解決策
 ## 問題の理解

 3 つの制約を同時に満たす整数の等差数列がいくつ存在するかを数えるよう求められます。 有効な各進行は正の共通差を持つシーケンスであるため、厳密には増加します。 すべての項は、L から R までの固定間隔内に存在する必要があります。1 つの特定の値 A がシーケンス内のどこかに出現する必要があります。 最後に、シーケンス内のすべての項の合計は正確に S でなければなりません。 

入力では、A、S、L、R の 4 つの値が与えられます。[L, R] 内にあり、A を含み、その合計が S である考えられるすべての等差数列を考慮し、そのような数列がいくつ存在するかを数える必要があります。 

制約は値に関しては非常に厳しいものですが、カウントに関してはそうではありません。 L と R は最大 10^12 まで指定できますが、区間の長さは最大 10^5 です。 合計 S は最大 10^18 になる可能性があり、シーケンスを列挙して合計を直接計算するアプローチは除外されます。 これは、各数列の構造をシミュレーションではなく代数的に利用する必要があることを示唆しています。 

重要なエッジ ケースは、数列の長さが 1 の場合に現れます。その場合、シーケンスは単なる [x] であり、常に合計 x を持ちます。 これは、S が x に等しい場合にのみ有効な解が存在し、A も x に等しくなければならないことを意味します。 もう 1 つの微妙なケースは、累進の長さは長いが、一般的な差が 1 である場合です。これにより、区間内の整数が密にカバーされます。 このようなケースでは、境界や合計の式におけるオフバイワンの間違いが隠れていることがよくあります。 

A を最初または最後の要素として固定しようとすると、別の失敗モードが表示されます。 A はシーケンス内にあることのみが必要であり、必ずしもエンドポイントにある必要はありません。 正しい解は、A が進行中の任意の位置であることを考慮する必要があります。 

## アプローチ

 直接的な総当たりアプローチでは、考えられるすべての開始値、考えられるすべての共通差異、および考えられるすべての長さを試します。 各候補数列について、それが [L, R] 内にあるかどうか、A が含まれているかどうか、その合計が S に等しいかどうかを確認できます。合計は等差数列の公式を使用して定数時間で計算できますが、候補トリプルの数は膨大です。 開始を [L, R] に制限し、差を R − L までに制限したとしても、すでに各次元に最大約 10^5 の選択肢が与えられ、最悪の場合には約 10^15 の構成が必要になりますが、これは完全に実行不可能です。 

等差数列をパラメトリック形式で書くと、問題の構造はより厳密になります。 数列の長さが n、最初の項が x、差分が d > 0 であるとします。その場合、数列は x, x + d, ..., x + (n − 1)d となります。 その和は n/2 · (2x + (n − 1)d) です。 A がシーケンスに現れるという制約は、A = x + k d となるようなインデックス k が存在することを意味します。 これは、x = A − k d を直ちに意味し、また、すべての項が [L, R] 内に留まるように x と d を制約します。 

x、d、n を独立して選択する代わりに、A の位置を中心としてシーケンスを再解釈できます。(n, d, k) を固定的に選択する場合 (k はシーケンス (0 から始まる) の A の位置)、他のすべてが決定されます。 合計制約は、n、d、A に関する線形方程式になります。これにより、問題は、L と R によって引き起こされる境界の下での整数解を数えることに縮小されます。

重要な観察は、n と d が固定されると、有効な k 値が、[L, R] に留まりながら進行が左右にどこまで拡張できるかによって決定される連続範囲を形成するということです。 各固定 (n, d) について、S が和の公式と互換性があるかどうかを確認でき、互換性がある場合は、数列内で有効な A の配置の数を数えます。 R − L ≤ 10^5 であるため、差 d も当然有界であり、n も同様に最大 10^5 です。 これにより、最悪の場合、およそ O((R − L)^2) で実行可能な構造を反復処理できますが、算術制約による枝刈りにより、有効なペアの実際の数は管理可能なサイズまで縮小します。 

主な問題は、和の方程式が (n, d) ペアを強く制限することです。 各ペアについて、合計条件によって x が一意に決定されます。その後は、A が数列内にあり、すべての項が範囲内にあるかどうかを確認するだけで済みます。 これにより、問題は導出式の約数に対する限定された検索に変換されますが、間隔の制約により小さいものになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | (x, d, n) に対するブルート フォース | O((R−L)^2・(R−L)) | お(1) | 遅すぎる |
 | 検証付きの (n, d) の代数列挙 | O((R−L) · sqrt(R−L)) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 等差数列は、その長さ n、最初の項 x、および公差 d によって表されます。 合計条件は x の直接方程式を与えるため、x を完全に削除します。 

1. 長さ n と差 d を固定します。 シーケンスは [L, R] 内に収まらなければならないことがわかっているため、最小の最初の項は L で、最大の最後の項は R です。これは、x ≥ L および x + (n − 1)d ≤ R を意味し、実行可能な x 値を暗黙的に制限します。 
2. 等差数列の公式 S = n/2 · (2x + (n − 1)d) を使用して合計を表します。 並べ替えると、2S = n(2x + (n − 1)d) が得られます。 x は未知であるため、これを x に対する線形制約として扱います。 
3. x を解きます: x = (2S / n − (n − 1)d) / 2. 固定 (n, d) の場合、x は一意に決定されるため、それが整数であり、範囲内にあるかどうかを確認するだけで済みます。 
4. 完全性条件を強制します。 式 2S / n は整数でなければなりません。そうでない場合、この (n, d) ペアは有効な数列を生成できません。 これにより、ほとんどの候補が即座に除外されます。 
5. x が決定されたら、境界制約 L ≤ x および x + (n − 1)d ≤ R を検証します。これらが成立する場合、A も含まれる場合、数列は有効です。 
6. A が等差数列内にあるかどうかをテストして、A が含まれていることを確認します。 これは、A ≥ x かどうか、(A − x) が d で割り切れるかどうか、および商が n より小さいかどうかをチェックすることに帰着します。 
7. すべての制約を満たすすべての有効な (n, d) ペアを数えます。 

これが機能する理由: すべての有効な等差数列は 1 つのトリプル (n、d、x) に対応しており、そのようなトリプルごとに上記の条件が必要かつ十分です。 合計方程式は x の一意性を強制しますが、包含と境界により、許可された間隔内に完全に収まり、A を含むシーケンスのみを受け入れることが保証されます。すべての可能な (n, d) が考慮されるため、有効な進行が見逃されることはありません。また、すべての制約が明示的にチェックされるため、無効な進行はカウントされません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    A, S, L, R = map(int, input().split())
    
    ans = 0
    
    max_len = R - L + 1
    
    for n in range(1, max_len + 1):
        # 2S must be divisible by n
        if (2 * S) % n != 0:
            continue
        
        val = (2 * S) // n
        
        # val = 2x + (n-1)d
        # we try d, derive x
        # rearrange: 2x = val - (n-1)d
        
        # bounds on d from x >= L and x+(n-1)d <= R
        # x = (val - (n-1)d)/2
        
        for d in range(1, max_len):
            rhs = val - (n - 1) * d
            if rhs % 2 != 0:
                continue
            
            x = rhs // 2
            if x < L:
                continue
            
            last = x + (n - 1) * d
            if last > R:
                continue
            
            # check if A is in progression
            if A < x or A > last:
                continue
            
            if (A - x) % d == 0:
                k = (A - x) // d
                if 0 <= k < n:
                    ans += 1
    
    print(ans)

if __name__ == "__main__":
    solve()
```実装は等差数列の構造に直接に従います。 可能な最大長は間隔サイズによって制限されるため、外側のループは長さ n を固定します。 内側のループは、実行可能なすべての差異 d を試行します。これも間隔によって制限されます。 

各ペア (n, d) について、合計式により x が一意に決定されます。 まず、x が整数になるように割り切れることを確認し、次に x を再構築し、数列が [L, R] 内に収まることを検証します。 最後に、モジュラー演算を使用して A が数列の内側にあることを検証します。 

微妙な部分は小切手の順序です。 x を構築する前に常に割り算をテストし、包含性をチェックする前に境界を検証します。 これにより、大きな数値での不要な演算が防止され、中間値が無効な場合の誤ったカウントが回避されます。 

## 実用的な例

 入力 5 15 1 10 を考えてみましょう。考えられる長さと違いをテストします。 n = 2 および d = 5 の場合、合計条件は x = 5 となり、5 を含み合計は 15 になる [5, 10] が生成されます。n = 3 および d = 2 の場合、x = 1 が得られ、[1, 3, 5] が生成されますが、合計が 15 ではないため無効であるため、拒否されます。 正確な合計に一致する構成のみがフィルタリングに残ります。 

| n | d | × | 最後 | A=5 を含む | 有効 |
 | --- | --- | --- | --- | --- | --- |
 | 2 | 5 | 5 | 10 | はい | はい |
 | 3 | 2 | 1 | 5 | はい | いいえ |

 このトレースは、包含がチェックされる前に合計制約が候補を積極的にフィルタリングする方法を示しています。 

ここで 5 5 5 5 を考えてみましょう。可能なシーケンスは 1 つの要素のみです [5]。 ここで、n = 1 であり、d は無関係です。 合計条件により x = 5 が強制され、これは範囲内にあり、A = 5 は自明に含まれます。 アルゴリズムは正確に 1 つの進行をカウントします。 

| n | d | × | 最後 | A=5 を含む | 有効 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 任意 | 5 | 5 | はい | はい |

 これは、縮退した単一要素の場合の正しい処理を示しています。

 ## 特殊なケース

 重要なエッジ ケースは、進行長が 1 の場合です。この場合、合計条件により唯一の要素が正確に S になることが強制され、A の包含が厳密な等価性チェックになります。 入力 5 5 5 5 の場合、アルゴリズムは n = 1 を設定し、x = 5 を計算し、すぐに受け入れます。 

もう 1 つの微妙なケースは、差が 1 の場合で、有効な配置の数が最大になります。 たとえば、A = 5、S = 15、L = 1、R = 10 の場合、シーケンス [1、2、3、4、5] が表示されます。 A − x は d = 1 で割り切れるので、すべての位置が有効であるため、アルゴリズムはこれを正しく処理します。 

単純な実装で発生する失敗モードは、A が最初の項または最後の項であると仮定することです。 入力 5 15 1 10 の場合、[1, 5, 9] や [3, 5, 7] などの有効なシーケンスが失われます。 このアルゴリズムは、A の役割を固定するのではなく、モジュラー演算を介してすべての可能な位置をチェックすることでこれを回避します。
