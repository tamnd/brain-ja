 ## 解決策
 ## 問題の理解

 2 つのチームが交代で長方形のビーチ コートにディスクを投げます。 各スローは 2D 平面上の点であり、同じ長方形内のどこかに固定のターゲット ポイントである「手人」が存在します。 スコアは、このターゲットまでのユークリッド距離によって完全に決定されます。 

両チームのすべての投球が相手チームのすべての投球と比較されますが、このルールでは競技が単純化され、距離の相対的な順位だけが問題となります。 まず、チーム A が達成した最小距離とチーム R が達成した最小距離を見つけます。これら 2 つの距離のうち小さい方のチームが試合に勝ちます。 

勝者を決定した後、そのチームは、負けたチームの最も近い投球よりも厳密にターゲットに近い投球ごとにポイントを獲得します。 距離の関係は存在しないことが保証されているため、同等の比較について心配する必要はありません。 

入力サイズは小さく、チームあたり最大 1000 回のスローです。 必要なポイントは最大 2000 個だけなので、すべての距離を計算するのは簡単です。 ポイントごとに 1 回距離を評価し、線形スキャンを実行するソリューションであれば、すでに十分です。 

微妙な点は、一貫性がない限り、不用意に距離の 2 乗ではなく、距離を比較する必要があることです。 ユークリッド距離には平方根が含まれるため、浮動小数点の問題を避けるために二乗距離を比較するのが標準です。 

エッジケースは数値的なものではなく構造的なものがほとんどです。 

例外的なケースの 1 つは、あるチームのすべてのスローが他のチームのすべてのスローよりも厳密に遠い場合です。 そして、最小距離によって勝者が即座に決定されます。 

もう 1 つのケースは、最も近いスローが一意ではなく、非常に近い座標を持つ別のチームに属している場合です。 この問題では等しい距離が明示的に保証されていないため、同点は処理しません。 

最後の微妙な点は、得点は負けたチームのベストスローに依存するということです。 勝ったチームが非常に優れた投球を複数持っていたとしても、厳密に言うと相手の最高の投球よりも優れた投球だけが貢献します。 

## アプローチ

 直接シミュレーションでは、両方のチームのすべての二乗距離を計算し、スキャンして各チームの最小値を見つけます。 その後、2 つの最小値を比較して勝者を決定します。 勝者が判明したら、そのチームの距離で 2 回目のパスを実行し、相手の最小距離より厳密に短いパスの数を数えます。 

これはすでに制約に快適に一致しています。 単純な集計以外に悪用できる構造がないため、ここでは総当たりのアイデアが本質的に最適です。 完全な計算はスロー数において線形であり、ソート要件やポイント間の組み合わせの相互作用はありません。 

唯一の潜在的な過剰なアプローチは、すべての距離をソートすることですが、必要なのは最小値とカウントしきい値だけであるため、ソートは不要です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (スキャン + 比較) | O(N) | O(N) | 承認済み |
 | 最適 (同じ考え、直接) | O(N) | O(1) おまけ | 承認済み |

 「最適な」解決策とは、実際には、問題が 2 つの最小値とフィルター処理されたカウントの計算に帰着することを認識することです。 

## アルゴリズムのチュートリアル

 ## アルゴリズムのチュートリアル

 1. すべての入力を読み取り、チーム A とチーム R の座標を別々に保存します。 
2. チーム A とチーム R の各スローからターゲット ポイントまでの二乗ユークリッド距離を計算します。比較が保持されるため、二乗距離は浮動小数点精度の問題を回避するために使用されます。 
3. チーム A のすべての距離をスキャンして最小値を見つけ、チーム R についても同じことを行います。これにより、各チームに最適なスローが得られます。 
4. 2 つの最小値を比較します。 最小距離が短いチームが勝者と宣言されます。 
5. しましょう`best_loser`負けたチームの最小距離になります。 勝ったチームの距離をたどり、厳密に以下の距離がいくつあるかを数えます。`best_loser`。 
6. 勝利チームのラベルとカウントを出力します。 

重要な考え方は、得点ルールは相手の最高の投球から導出される 1 つのしきい値のみに依存するため、そのしきい値を特定した後は、問題の残りの部分は単純なフィルタリング操作になるということです。 

### なぜ効果があるのか

 各チームのスコアへの貢献は、投球が相手の最高のパフォーマンスを上回ったかどうかによってのみ決まります。 対戦相手の最小値よりも厳密に優れていない送球は、定義上、スコアに貢献できません。 逆に、厳密に優れたスローはすべて 1 回だけカウントされます。 すべての比較は独立しており、固定点までの距離のみに基づいているため、最小値を特定する以上にスロー間の相互作用は存在しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def dist2(x, y, tx, ty):
    dx = x - tx
    dy = y - ty
    return dx * dx + dy * dy

n = int(input())
w, l, tx, ty = map(int, input().split())

A = []
R = []

for _ in range(n):
    x, y = map(int, input().split())
    A.append(dist2(x, y, tx, ty))

for _ in range(n):
    x, y = map(int, input().split())
    R.append(dist2(x, y, tx, ty))

minA = min(A)
minR = min(R)

if minA < minR:
    winner = "A"
    threshold = minR
    score = sum(1 for d in A if d < threshold)
else:
    winner = "R"
    threshold = minA
    score = sum(1 for d in R if d < threshold)

print(winner, score)
```この実装では、読み取りと距離の計算が明確に分離され、すべての幾何学的作業が整数演算に削減されます。 二乗距離が一貫して使用されるため、平方根は表示されません。 

勝者は最小値を直接比較して決定されます。 その後、得点パスは、勝利チームのリストに対する単一の線形フィルターになります。 

よくある間違いは、距離を複数回再計算したり、生の距離と二乗距離を混合したりすることです。 もう 1 つは、誤って勝者のみではなく、両方のチームからカウントしてしまうことです。

import sys, io

def run(inp: str) -> str:

 ## 特殊なケース

 重要なエッジケースは、両チームが単一のスローを持っている場合です。 勝者は単純に近い方のポイントであり、相手の唯一の投げよりも厳密に近い必要があるため、勝者のスコアは常に 1 になります。 両方の最小値が正しく計算され、フィルターが正確に 1 つの要素をカウントするため、アルゴリズムはこれを自然に処理します。 

もう 1 つのエッジ ケースは、一方のチームのすべてのポイントがターゲットの近くに極端に集中しているのに、もう一方のチームは遠くにある場合です。 その場合、すべての勝利スローが厳密な不等式を満たし、すべてのスローが寄与するため、しきい値の比較は引き続き機能します。 

最後のエッジ ケースは、座標が長方形の境界上に正確に位置する場合です。 距離の計算は境界に依存しないため、これらの点は内部点と同じように動作します。 二乗距離の計算は引き続き有効であり、特別なケースは必要ありません。
