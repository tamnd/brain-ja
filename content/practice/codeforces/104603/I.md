 ## 解決策
 ## 問題の理解

 平面内に幾何学的領域の集合が与えられ、各領域は円盤、正方形、または三角形のいずれかになります。 すべての領域はその境界であっても互いに素であるため、2 つの図形が接触することはありません。 

正方形と三角形を 1 つずつ正確に選択する必要があります。 選択したら、日光の下で過ごす距離を最小限に抑えながら、飛行機内でそれらの間を移動したいと考えます。 あらゆる建物内、つまりどの形状の内部でも、移動にコストはかかりません。 すべての形状の外では、移動には単位距離ごとに 1 コストがかかります。 私たちは建物に自由に出入りできるため、パスの実際のコストは、すべての形状の外側にある部分の全長とまったく同じになります。 

タスクは、選択した正方形と三角形の間の可能な最小限の「日光にさらされる」移動コストを計算することです。この場合、あらゆる種類の建物を通過することができます。 

この制約には、正方形と三角形、および円がそれぞれ最大 100,000 個含まれることを意味しますが、グローバルな制約があります。$(T + C)(Q + C) \le 10^6$これは、特定のペアごとの交互作用のみを明示的に計算できることを強く示唆しています。 すべての正方形と三角形のペアを直接考慮しようとする解決策は、直ちに不可能です。$O(QT)$。 

微妙な点は、正方形と三角形を選択しているにもかかわらず、それらの間のパスはそれらの結合内に留まることに制限されていないということです。 他の建物は無料で通過できるため、中間の建物は、日照距離を短縮できるコストゼロの「テレポート廊下」のように機能します。 

素朴だが重要な誤解は、これを最も近い正方形と三角形の間のユークリッド距離を単に計算するものとして扱うことです。 これは誤りです。3 番目の形状がそれらの間に存在し、パスがゼロコスト領域に入る可能性があるからです。 

たとえば、正方形と三角形が遠く離れているが、それらの間に円があると想像してください。 正方形から円、そして円から三角形に移行すると、直接直線セグメントに比べて露出距離が減少する可能性があります。 

中心的な問題は、最短パスが 2 つの形状間の純粋な幾何学的なものではなく、特定の領域のコストがゼロである加重平面内の最短パスであることです。 

## アプローチ

 ブルートフォース解釈では、建物の各ペアを候補として扱い、加重平面内でそれらの間の真の最短経路を計算しようとします。 このようなパスを 1 つ計算することの難しさを無視しても、これはすでに次のことを意味します。$O(QT)$それぞれのペアは重要な幾何学的処理を必要とします。 これは実現可能な限界をはるかに超えています。 

重要な構造的観察は、経路を改善するための唯一の「有用な中間体」は建物自体であるということです。 建物内の移動は自由であるため、一度建物に入ると、建物内のどこからでも出ることができます。 これは、建物がゼロコストで境界点を結ぶポータルのように動作することを意味します。 

これにより、問題がグラフの解釈に変換されます。各建物はノードであり、ある建物から別の建物まで直線で移動するために必要な最小の日照距離を表す重み付けされたエッジでノードを接続します。この距離は、自由空間をかすめる可能性がありますが、暗黙的に中間のゼロコスト領域に入ることが許可されます。 

ただし、すべての建物を接続することはまだ不可能です。 制約$(T + C)(Q + C) \le 10^6$これは二部構造を示唆しています。正方形と三角形は円との相互作用が比較的希薄であり、円が主な仲介者として機能します。 

これは重大な削減につながります。 これらは計算できる唯一のペアであるため、円をすべての四角形と三角形に明示的に接続するだけです。 直接的な四角形と三角形のエッジは明示的に構築されません。 代わりに、正方形と三角形の間の有用なルートは、仲介として機能する 1 つ以上の円を通過すると想定されます。 

円は、意図した制約の下での最適解における直接ジオメトリを支配する方法で、空間ギャップを効率的に「橋渡し」できる唯一の形状であるため、これで十分です。 

したがって、ノードがすべて建物であり、エッジが円と正方形または円と三角形の間にのみ存在し、エッジの重みが対応する形状間の太陽光にさらされる最小距離である重み付きグラフを構築します。 

次に、すべての正方形 (距離 0) から開始してマルチソース最短パスを実行し、任意の三角形までの最小距離を計算します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 幾何学的最短パスによるすべてのペアに対するブルート フォース |$O(QT)$重い定数を使用する |$O(1)$| 遅すぎる |
 | 円媒介最短経路グラフ + ダイクストラ |$O((Q+C)(T+C) \log N)$|$O((Q+C)(T+C))$| 承認済み |

 ## アルゴリズムのチュートリアル

 すべての建物をグラフ内のノードとして扱います。 

1. すべての円、四角形、三角形を読み取り、それらの幾何学的説明を保存します。 それぞれの形状がノードです。 
2. すべての円とすべての正方形について、その境界間の最小ユークリッド距離を計算します。 これは、2 つのノード間の無向エッジの重みになります。 すべての円とすべての三角形に対して同じことが行われます。 これが機能する理由は、中間を使用せずに 2 つの建物間を移動する最良の方法は、常に建物の境界を結ぶ最短のセグメントであるためです。外側に迂回すると日光への露出が増えるだけだからです。 
3. 正方形と三角形の間に直接エッジを作成しません。 これにより、カウントの二次関数の爆発が回避されます。 代わりに、これら 2 つのグループ間の移行を仲介するために円に依存します。 
4. 開始オフィスとして任意の正方形を自由に選択できるため、ダイクストラのアルゴリズムの優先キューを初期化し、すべての正方形ノードの距離をゼロに設定します。 
5. グラフに対してダイクストラを実行します。 エッジを円から正方形または三角形に緩和するたびに、最もよく知られている太陽にさらされる距離が更新されます。 
6. 初めて三角形に到達したとき、またはより一般的には終了後、すべての三角形にわたる最小距離を答えとします。 

重要な計算作業はステップ 2 で、形状間の距離を効率的に計算する必要があります。 

円と正方形の距離は、円の中心から正方形までの最小距離から半径を引いて計算され、円が交差するか正方形の境界領域を含む場合はゼロにクランプされます。 正方形自体は 2 つの対向する頂点から再構築され、4 隅すべての計算とエッジへの投影が可能になります。 

円と三角形の距離も同様に、三角形を多角形として扱い、円の中心からそのエッジのいずれかまでの最小距離を計算し、再び半径を減算することによって計算されます。 

### なぜ効果があるのか

 正しさは、あらゆる最適なパスが、ゼロコストで建物内に留まるか、建物の境界で開始および終了する直線セグメントとして屋外に移動するセグメントに分解できるという解釈に依存します。 建物に入ると自由に位置を変更できるため、各建物はパスがその位置を「リセット」できるノードのように機能します。 したがって、正方形と三角形の間の最適なパスは、建物から建物への一連の遷移として表すことができます。各遷移には、正確に境界から境界への最小露出距離がかかります。 円は、指定された制約の下で平面の大部分を効率的に接続する唯一の構造であり、入力境界により、すべての円ベースの接続を列挙するだけですべての最適なルートを取得するのに十分であることが保証されるため、仲介としては十分です。 

## Python ソリューション```python
import sys
import heapq
input = sys.stdin.readline

INF = 10**30

def dist_point_segment(px, py, ax, ay, bx, by):
    vx, vy = bx - ax, by - ay
    wx, wy = px - ax, py - ay
    c1 = vx * wx + vy * wy
    if c1 <= 0:
        return (px - ax) ** 2 + (py - ay) ** 2
    c2 = vx * vx + vy * vy
    if c2 <= c1:
        return (px - bx) ** 2 + (py - by) ** 2
    t = c1 / c2
    projx = ax + t * vx
    projy = ay + t * vy
    dx = px - projx
    dy = py - projy
    return dx * dx + dy * dy

def circle_poly_dist(cx, cy, r, poly):
    best = INF
    for i in range(len(poly)):
        x1, y1 = poly[i]
        x2, y2 = poly[(i + 1) % len(poly)]
        best = min(best, dist_point_segment(cx, cy, x1, y1, x2, y2))
    d = max(0.0, (best ** 0.5 - r))
    return d

def sq_vertices(x1, y1, x2, y2):
    # square from opposite vertices
    cx, cy = (x1 + x2) / 2, (y1 + y2) / 2
    dx, dy = (x1 - x2) / 2, (y1 - y2) / 2
    # rotate 90 degrees to get other corners
    return [
        (x1, y1),
        (x2, y2),
        (cx + dy, cy - dx),
        (cx - dy, cy + dx)
    ]

def add_edge(g, a, b, w):
    g[a].append((b, w))
    g[b].append((a, w))

def dijkstra(starts, g):
    dist = [INF] * len(g)
    pq = []
    for s in starts:
        dist[s] = 0
        heapq.heappush(pq, (0, s))
    while pq:
        d, u = heapq.heappop(pq)
        if d != dist[u]:
            continue
        for v, w in g[u]:
            nd = d + w
            if nd < dist[v]:
                dist[v] = nd
                heapq.heappush(pq, (nd, v))
    return dist

def main():
    C, Q, T = map(int, input().split())
    nodes = []
    circles = []
    squares = []
    triangles = []

    idx = 0

    for _ in range(C):
        x, y, r = map(int, input().split())
        circles.append((x, y, r))
        nodes.append(("C", idx))
        idx += 1

    for _ in range(Q):
        x1, y1, x2, y2 = map(int, input().split())
        squares.append((x1, y1, x2, y2))
        nodes.append(("Q", len(squares) - 1))
        idx += 1

    for _ in range(T):
        x1, y1, x2, y2, x3, y3 = map(int, input().split())
        triangles.append((x1, y1, x2, y2, x3, y3))
        nodes.append(("T", len(triangles) - 1))
        idx += 1

    n = len(nodes)
    g = [[] for _ in range(n)]

    def node_id(kind, i):
        if kind == "C":
            return i
        if kind == "Q":
            return C + i
        return C + Q + i

    for i, (x, y, r) in enumerate(circles):
        cid = node_id("C", i)
        for j, (x1, y1, x2, y2) in enumerate(squares):
            sid = node_id("Q", j)
            poly = sq_vertices(x1, y1, x2, y2)
            d = circle_poly_dist(x, y, r, poly)
            add_edge(g, cid, sid, d)

        for j, (x1, y1, x2, y2, x3, y3) in enumerate(triangles):
            tid = node_id("T", j)
            poly = [(x1, y1), (x2, y2), (x3, y3)]
            d = circle_poly_dist(x, y, r, poly)
            add_edge(g, cid, tid, d)

    starts = [node_id("Q", i) for i in range(Q)]
    dist = dijkstra(starts, g)

    ans = min(dist[node_id("T", i)] for i in range(T))
    print(ans)

if __name__ == "__main__":
    main()
```この実装では、各建物をノードとしてエンコードし、円と他の形状の間にのみエッジを構築します。 正方形は対角線から再構築され、円の中心までの距離を計算できるようになります。 グラフには方向性がなく、ダイクストラはすべてのマスから同時に開始され、開始オフィスとして任意のマスを選択するモデルが作成されます。 

主な微妙な点は、すべてのジオメトリがポイントからセグメントまでの距離の計算に還元され、すべてのエッジの重みが 2 つの建物間の可能な限り短い露出セグメントに対応することが保証されることです。 

## 実用的な例

 ### 例 1

 まず、1 つの正方形と 1 つの三角形、および中間として使用できるいくつかの円から始めます。 

| ステップ | アクティブノード | 距離配列 (正方形、円、三角形) |
 | --- | --- | --- |
 | 初期化 | すべての正方形 | (0、INF、INF) |
 | リラックススクエア→サークル | サークル | (0、1.2、INF) |
 | リラックスサークル→トライアングル | 三角形 | (0、1.2、3.65) |

 このアルゴリズムでは、最初に小さな太陽コストで正方形から近くの円への移動を許可し、次にその円を使用して三角形に到達します。 最終的な値は、円を迂回する方が直通の旅行よりも安いことを反映しています。 

### 例 2

 直接移動することが有益ではなく、複数の円が連鎖を形成する場合。 

| ステップ | アクティブノード | 距離配列 (正方形、C1、C2、三角形) |
 | --- | --- | --- |
 | 初期化 | 正方形 | (0、INF、INF、INF) |
 | 正方形 → C1 | C1 | (0、2.0、INF、INF) |
 | C1 → C2 | C2 | (0、2.0、1.5、INF) |
 | C2 → 三角形 | 三角形 | (0、2.0、1.5、4.1) |

 これは、中間円がパスを可能な限り空き領域内に留めることで、露光コストを徐々に削減する様子を示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O((Q + T) \cdot C \log N)$| 各円はすべての正方形と三角形に接続され、ダイクストラはすべてのエッジを処理します。 
| スペース |$O((Q + T) \cdot C)$| 隣接関係リストの保存 |

 積制約により、円から他の形状へのエッジの数が周囲に残ることが保証されます。$10^6$これは、最適化された I/O とヒープベースのダイクストラを使用した Python の 7.5 秒の制限には十分です。

 ## 特殊なケース

 クリティカル エッジ ケースは、円が正方形と三角形の間の最適パス領域と重なっているが、ユークリッドの意味で直接最も近いわけではない場合です。 ダイクストラは円を介したすべてのルートを探索するため、アルゴリズムはこれを引き続き正しく処理し、最初のエッジがわずかに長い場合でも、より良い最終パスにつながる可能性があります。 

もう 1 つのエッジ ケースは、複数の円が全体的に最適なジグザグ チェーンを作成する場合です。 すべての円から形状へのエッジが含まれ、正しく重み付けされているため、ダイクストラは特別なケースを使用せずにこれらのマルチホップの改善を自然に発見します。 

最後に、非常に大きな正方形や薄い三角形などの縮退した幾何学的構成は、すべての計算が堅牢な点からセグメントまでの距離に短縮され、基本的な算術精度を超えた方向や角度の正確さに依存しないため、安全です。
