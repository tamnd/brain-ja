 ## 解決策
 ## 問題の理解

 私たちに与えられているのは、$N \times N$各セルが使用可能 (黒) または禁止 (白) されるグリッド。 タスクは、各ドミノが同じ行内の 2 つの隣接するセルを正確にカバーするように、できるだけ多くの水平方向のドミノを配置することです。 ドミノは、覆われたセルが両方とも黒である場合にのみ有効であり、どのセルも複数のドミノに属することはできません。 

したがって、この問題は、すべての行にわたって、水平方向に隣接する素の黒セルのペアをできるだけ多く選択することと同じです。 

グリッド サイズは最大です$50 \times 50$, したがって、セルは最大でも 2500 個あります。 これにより、プレースメントに対する指数関数的な検索が即座に除外されます。 各行だけで指数関数的な選択肢が生成される可能性があるため、ドミノを配置するか配置しないすべての方法を単純に遡って追跡するだけでも、あまりにも大規模になります。 

重要な点は、列が独立していることです。ドミノが列を横切ることはありません。 したがって、問題は、各行に対して同じサブ問題を解決し、結果を合計することに分解されます。 

微妙なエッジ ケースは、注意しないと貪欲なペアリングが失敗する可能性がある交互パターンの行です。 たとえば、次のような行で`NNNN`、単純で貪欲な左から右のペアリングは 2 つのドミノを正しく生成しますが、次のようなパターンになります。`NNNNN`、実装が厳密に素の使用を強制しない場合、不注意なスキップ ルールはカウントを誤る可能性があります。 別のケースは、次のような孤立した黒を含む行です。`NBNBN`, 黒マスが多いにもかかわらずドミノを置けない場所。 

## アプローチ

 強引な解釈では、グリッド上の水平ドミノの可能な配置をそれぞれ考慮します。 これは、隣接する黒セルの間のエッジを選択し、頂点が再利用されないようにするものとみなすことができます。 これはまさに、各セルがノードであり、同じ行内の水平方向に隣接するセル間にエッジが存在するグラフ上の最大一致の問題です。 

単純な解決策では、エッジのすべてのサブセットを試して有効性をチェックします。 最大 2500 セルの場合、水平エッジに限定してもおおよその結果が得られます。$O(N^2)$エッジとエッジのサブセットは、周囲で指数関数的に増加します。$2^{O(N^2)}$、それは完全に不可能です。 

重要な単純化は構造的なものです。エッジは間にのみ存在します。$(i, j)$そして$(i, j+1)$。 つまり、各行は白いセルで区切られた独立したパス グラフです。 パス グラフでは、最大の一致は簡単です。連続する利用可能な頂点を左から右に貪欲に一致させます。 

これにより、問題はグローバル マッチングの問題から次のように縮小されます。$N$独立したリニアスキャン。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべてのドミノ サブセットに対するブルート フォース |$O(2^{N^2})$|$O(N^2)$| 遅すぎる |
 | 行単位の貪欲ペアリング |$O(N^2)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. ドミノは行の境界を越えないため、グリッドを行ごとに処理します。 これにより、各決定が独立した部分問題に限定されることが保証されます。 
2. 各行について、前のセルをペアにできるかどうかを追跡しながら、左から右にスキャンします。 2 つの連続した黒いセルが表示された場合にのみ、ペアリングを試みます。 
3. 黒いセルが見つかったら、次のセルを確認します。 それも黒の場合は、両方をカバーするドミノを配置し、次の位置をスキップします。 これにより、重複がないことが保証されます。 
4. 次のセルが白であるか、行の最後にいる場合、この位置からドミノを置くことはできないため、前に進みます。 
5. 各行に配置されたドミノの数を合計して全体の合計を計算します。 

### なぜ効果があるのか

 各行は、頂点がセルであり、エッジが連続する黒のセルの間にのみ存在するパスを形成します。 パス グラフ内の互いに素なエッジの最大数は、可能な限り左端の利用可能なエッジを貪欲に選択することによって取得されます。 有効なペアをスキップする代替ソリューションは、将来の選択肢を増やすことはありません。スキップしても、さらに右側に一致する可能性が同じか、より少なくなるだけだからです。 これにより、貪欲な構築により常に行ごとに最適なマッチングが生成されることが確立されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    ans = 0

    for _ in range(n):
        row = input().strip()
        i = 0
        while i < n:
            if row[i] == 'N':
                if i + 1 < n and row[i + 1] == 'N':
                    ans += 1
                    i += 2
                else:
                    i += 1
            else:
                i += 1

    print(ans)

if __name__ == "__main__":
    solve()
```この実装は、行単位の貪欲戦略に直接従います。 インデックスを維持します`i`ドミノを形成するかどうかに応じて、それを前進させます。 2回連続の場合`N`セルが表示されると、すぐに両方を消費し、2 ずつ進めて、非結合的な使用を強制します。 それ以外の場合は 1 ずつ進みます。 

重要な点は、一度スキップまたは使用されたセルを決して再検討しないことです。 これが正確性を保証するものです。すべてのセルは最大でも 1 つの決定に参加するため、重複は起こりません。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

グリッドには最大 2500 個のセルがあるため、すべてのセルに対する 1 回のリニア スキャンは時間制限内であれば簡単です。 このソリューションは 1 秒未満で実行され、メモリの使用量はごくわずかです。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = io.StringIO()
    sys.stdout = output
    solve()
    return output.getvalue().strip()

def solve():
    n = int(input().strip())
    ans = 0
    for _ in range(n):
        row = input().strip()
        i = 0
        while i < n:
            if row[i] == 'N':
                if i + 1 < n and row[i + 1] == 'N':
                    ans += 1
                    i += 2
                else:
                    i += 1
            else:
                i += 1
    print(ans)

# sample-style checks
assert run("5\nBNBNB\nBBNNN\nNNNNN\nBNNNN\nNNBNN\n") == "7"

# minimum size
assert run("1\nN\n") == "0"

# all white
assert run("3\nBBB\nBBB\nBBB\n") == "0"

# full black row
assert run("1\nNNNNN\n") == "2"

# alternating pattern
assert run("1\nNBNBN\n") == "0"

 | 1×1 黒 | 0 | 最小のグリッド動作 |

 ## 特殊なケース

 単一セルグリッドのような`N`可能なドミノ配置はありません。 アルゴリズムは行を処理し、有効なペアを検出せず、正しく 0 を返します。 

真っ黒な列のような`NNNNN`これは、インデックス (0,1) と (2,3) でペアを繰り返し一致させることで処理され、1 つのセルが残ります。 スキャンでは残りの部分が自然にスキップされ、2 つのドミノが生成されます。 

のような交互パターン`NBNBN`有効な隣接ペアをトリガーすることは決してないので、アルゴリズムはカウンターをインクリメントすることはなく、正しく 0 を返します。
