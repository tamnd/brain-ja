 ## 解決策
 ## 問題の理解

 この問題では、一列に配置された刑務所の独房の列が与えられます。各独房には、固定の「危険値」または知能スコアを持つ囚人が含まれています。 これに加えて、いくつかのガードがあり、すべてのセルを 1 つのガードに正確に割り当てる必要があります。 各ガードは、連続するセルのブロックを担当します。つまり、ガードが l から r までセルを監視する場合、間にあるすべてのセルを隙間なく監視する必要があります。 

ブロックを割り当てるコストは、ブロック内に何人の囚人がいるか、およびそれらの囚人の個人スコアという 2 つの要素によって決まります。 看守にサイズ k のセグメントが割り当てられた場合、そのセグメント内のすべての囚人は、スコアに k を乗じた値を合計コストに貢献します。 言い換えれば、より大きなセグメントの囚人はより重く罰せられることになります。 

タスクは、これらすべての重み付けされた寄与の合計が最小化されるように、囚人の配列を正確に G 個の連続セグメントに分割することです。 

入力は、囚人の数 N、看守の数 G、および囚人のスコアを表す N 個の整数のリストで構成されます。 出力は、G セグメントへの最適なパーティションを選択した後の可能な最小総コストを表す単一の整数です。 

制約からNは数千程度まで、Gも数千程度になります。 これにより、すべてのパーティションを明示的に試行するソリューションは即座に除外されます。 配列を G 個のセグメントに分割するすべての方法を単純に列挙すると、組み合わせによって増大し、8000 個はおろか、30 または 40 程度の N であっても実行不可能になります。 

多くの場合、誤った貪欲なアプローチを破る重要なエッジケースは、高価値の要素が低価値の要素によって分離されている場合です。 たとえば、大きなスコアが分散している場合、それらを異なる方法でグループ化すると乗数効果が大幅に変化する可能性があります。 サイズまたはローカル合計によってセグメントの「バランス」を維持しようとする貪欲な戦略は、コストが位置とセグメントの長さの両方に同時に依存するため、失敗します。 

もう 1 つの微妙なケースは、G が 1 に等しい場合、または G が N に等しい場合です。G = 1 の場合、コストは単に配列長係数全体にわたる i * S[i] の合計になります。 G = N の場合、すべてのセグメントのサイズは 1 になるため、コストはすべての S[i] の合計に収まります。 正しいソリューションは、特殊なハックをすることなく、両方の極端な問題を自然に処理できる必要があります。 

## アプローチ

 ブルートフォースアプローチでは、セル間の N - 1 個のギャップの間に G - 1 個のカットを配置するあらゆる可能な方法が試行されます。 各構成は有効なパーティションを定義し、そのコストを直接計算します。 このような構成の数は、N − 1 個から G − 1 個の位置を選択するオーダーであり、これは組み合わせ的であり、非常に急速に増加します。 N = 200 のような中程度の値であっても、これは大きすぎるため、各評価のコストも O(N) となり、全体的なアプローチは完全に実行不可能になります。 

この問題を興味深いものにしているのは、コスト関数の構造です。 セグメントの寄与は、そのサイズとその中の要素の合計に線形的に依存します。 これにより、2 つの隣接するセグメントをマージすると、予測可能な方法で一度に多くの要素に影響を与える依存関係が作成されます。 

重要な観察は、これはプレフィックスを介した古典的な分割 DP ですが、直接 DP は O(N²G) となり、それでも遅すぎるということです。 ただし、この移行には最適化が可能な構造があります。セグメント境界を拡張すると、コストの変化はプレフィックス合計を使用して段階的に表現できます。つまり、セグメント全体のコストを最初から再計算する必要はありません。 

これにより、問題は「dp[k][i] の最適な分割点」という形式の遷移を維持することになります。最適な分割点は単調性を満たすため、分割統治 DP 最適化を使用して最適化できます。

ブルート フォースはすべてのパーティションを正しく評価するため機能しますが、同じセグメント コストを繰り返し再計算するため、N が大きくなると失敗します。 セグメントコストが段階的に更新できるという観察により、計算を再利用し、最適な分割点の検索スペースを制限することができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O( C(N, G) · N ) | O(N) | 遅すぎる |
 | 最適化された DP | O(G・N log N) | O(NG) または O(N) 最適化 | 承認済み |

 ## アルゴリズムのチュートリアル

 dp[g][i] を、最初の i 人の囚人を g 個のセグメントに分割するための最小コストとして定義します。 

また、セグメントコストを効率的に計算するために、S[i] のプレフィックス合計も維持します。 

1. dp[1][i] を初期化します。ガードが 1 つだけあるため、1 から i までのすべてが 1 つのセグメントになります。 すべての要素がセグメントの大きさに基づいて寄与するため、コストはプレフィックスの合計を使用して直接計算されます。 
2. 2 から G までのガード g の数ごとに、すべての i について dp[g][i] を計算します。 
3. dp[g][i] を計算するには、j < i の位置で配列を分割しようとします。これは、最後のセグメントが (j+1 … i) であることを意味します。 遷移は、dp[g−1][j] の j にわたる dp[g][i] = min とコスト(j+1, i) です。 
4. セグメント コストcost(l, r) はプレフィックス合計を使用して計算されるため、セグメントを毎回反復するのではなく、O(1) で評価できます。 そうしないと DP が立方体になってしまうため、これは不可欠です。 
5. すべてを素朴に試す代わりに、分割統治型の最適化を使用します。 固定 g の場合、i の最適な分割位置は i が増加するにつれて単調になるため、検索間隔を再帰的に制限できます。 
6. 最初に dp[g][mid] を再帰的に計算し、次にその最適な分割点を使用して左半分と右半分の検索スペースを狭めます。 

結果は dp[G][N] です。 

機能する理由: コスト関数は、プレフィックスの合計とセグメント サイズに線形に依存するため、四角形の不等式を満たします。 これにより、i が増加しても最適な分割点が後方に移動しないことが保証されます。これは、分割統治 DP 最適化が正しく行われるために必要な不変条件です。 この単調性が成立すると、すべての部分問題は縮小する候補範囲のみを考慮しますが、それでも全体的な最適性は維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    N, G = map(int, input().split())
    a = [0] + [int(input()) for _ in range(N)]

    prefix = [0] * (N + 1)
    for i in range(1, N + 1):
        prefix[i] = prefix[i - 1] + a[i]

    def cost(l, r):
        s = prefix[r] - prefix[l - 1]
        length = r - l + 1
        return s * length

    INF = 10**30

    dp_prev = [0] * (N + 1)
    for i in range(1, N + 1):
        dp_prev[i] = cost(1, i)

    def compute(g, L, R, optL, optR, dp_cur):
        if L > R:
            return
        mid = (L + R) // 2
        best_val = INF
        best_k = -1

        start = optL
        end = min(mid - 1, optR)

        for k in range(start, end + 1):
            val = dp_prev[k] + cost(k + 1, mid)
            if val < best_val:
                best_val = val
                best_k = k

        dp_cur[mid] = best_val

        compute(g, L, mid - 1, optL, best_k, dp_cur)
        compute(g, mid + 1, R, best_k, optR, dp_cur)

    dp_cur = [0] * (N + 1)

    for g in range(2, G + 1):
        compute(g, 1, N, 0, N - 1, dp_cur)
        dp_prev, dp_cur = dp_cur, [0] * (N + 1)

    print(dp_prev[N])

if __name__ == "__main__":
    solve()
```プレフィックス合計配列は、すべてのセグメントのコストを O(1) にするために使用されます。 これがないと、DP 遷移ごとにセグメントのスキャンが必要となり、解決策が非常に遅くなります。 

再帰関数`compute`分割統治の最適化ステップです。 重要な点は、制限された範囲内で最適な分割点のみを検索することです。`[optL, optR]`、再帰が進むにつれて縮小します。 これにより、複雑さを管理しやすくすることができます。 

DP アレイ`dp_prev`そして`dp_cur`ガードの層を交互に配置して、完全な 2D テーブルを回避します。 

## 実用的な例

 5 人の囚人と 2 人の看守がいる小さな事件を考えてみましょう。`[1, 3, 2, 4, 5]`。 

### 1層目（ガード1枚）

 | 私 | セグメント | 費用 |
 | --- | --- | --- |
 | 1 | [1] | 1 |
 | 2 | [1,3] | 8 |
 | 3 | [1,3,2] | 18 |
 | 4 | [1,3,2,4] | 36 |
 | 5 | [1,3,2,4,5] | 60 |

 これにより dp_prev が構築されます。 

### 第 2 層 (ガード 2 人)

 分割してみます。 

| 私 | ベストスプリットj | セグメント | dp値 |
 | --- | --- | --- | --- |
 | 1 | - | 無効 | - |
 | 2 | 1 | [1] + [3] | 1 + 6 = 7 |
 | 3 | 1 | [1] + [3,2] | 1 + 15 = 16 |
 | 4 | 2 | [1,3] + [2,4] | 8 + 16 = 24 |
 | 5 | 2 | [1,3] + [2,4,5] | 8 + 36 = 44 |

 i が増加するにつれて分割点は右にシフトします。これはまさに最適化によって利用される単調性の特性です。 

このトレースは、セグメントが大きくなるとコストが高くなるため、最適なソリューションでは生の合計を最小限に抑えるのではなく、セグメント サイズのバランスを取る傾向があることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N · G log N) | G 層ごとに N 状態にわたる DP を分割統治する |
 | スペース | O(N) | 2 つの DP 配列とプレフィックス合計のみが保存されます。 

N が最大約 8000、G が最大数千であるため、対数係数が小さく、各 DP 状態が 1 回計算されるため、これは制限内に問題なく収まります。

 ## 特殊なケース

 重大なエッジケースは、ガードが 1 人しかいない場合です。 その状況では、配列全体が 1 つのセグメントになるため、アルゴリズムは計算コスト (1, N) まで削減する必要があります。 初期化ステップでは、プレフィックス合計を使用して dp[1][i] を直接設定します。これにより、遷移に依存せずに正確さが保証されます。 

もう 1 つのケースは、看守の数と囚人の数が等しい場合です。 すべてのセグメントのサイズは 1 であるため、各要素は S[i] · 1 に寄与します。各新しいレイヤーではすべての位置での分割が許可され、最終的には単一要素セグメントが強制されるため、DP はこれを自然に処理します。 

より微妙なケースは、大きな値が配列の最後に集中している場合に発生します。 局所的な平均に基づいてカットしようとする単純な貪欲な分割では、これらを誤って分離またはマージする傾向がありますが、DP はすべての有効な分割位置を探索し、分割統治の最適化により冗長性を削減しながらその検索を維持します。
