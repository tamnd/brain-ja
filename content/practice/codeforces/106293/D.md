 ## 解決策
 ## 問題の理解

 整数の配列が与えられ、選択された各セグメントの XOR がゼロになるように、できるだけ多くの素な連続セグメントを抽出するように求められます。 配列の各要素は選択した 1 つのセグメントにのみ属することができるため、セグメントを選択すると、そのインデックスを他のセグメントで再利用することはできません。 

タスクは配列を完全に分割することではなく、最大数の「適切な」セグメントを選択することです。 セグメント内のすべての要素の XOR が正確に 0 である場合、セグメントは良好です。 

制約は次のとおりです$2 \cdot 10^5$これにより、部分配列に対する二次関数またはそれより悪いアプローチが即座に除外されます。 すべてのセグメントを試行したり、多くのエンドポイントのペアに対して XOR を再計算したりするソリューションは、タイムアウトになります。 おそらくプレフィックス構造と動的プログラミングを使用して、線形または線形に近い時間に近いものが必要です。 

重要な点は、セグメントが重複してはいけないということです。 これは、初期の短いセグメントが後の 2 つのセグメントをブロックする可能性があるため、ゼロ XOR 部分配列を貪欲に選択することは明らかに安全ではないことを意味します。 

いくつかの特殊なケースで構造を説明します。 

配列が`[1, 1, 1, 1]`、有効なゼロ XOR セグメントには次のものがあります。`[1,1]`位置 (1-2) と (3-4) で、答え 2 が得られます。インデックス 1 から始まる最も長いセグメントを選択する単純な貪欲型は、XOR 0 を持つ (1-4) を取得する可能性がありますが、その場合、答えは 1 になり、これはさらに悪いことになります。 

配列が`[1, 2, 3]`、配列全体の XOR はゼロであるため、1 つのセグメントを取得できますが、より小さなセグメント化では 1 つ以上のセグメントが得られません。 

すべての要素がゼロの場合、すべての要素が有効なセグメントとなるため、答えは次のようになります。$n$そして、正しい解決策はこれをきれいに処理する必要があります。 

これらの例は、問題が、重複しない最適な方法で多数のゼロ XOR 部分配列を見つけることであることをすでに示唆しています。これは、位置に対する動的プログラミングと組み合わせたプレフィックス XOR 構造を示唆しています。 

## アプローチ

 ブルート フォース アプローチでは、すべてのサブ配列を試し、それぞれの XOR を計算して、重複しない有効な間隔の最大セットを選択します。 各部分配列チェックが O(1) になるようにプレフィックス XOR を使用して XOR を事前計算したとしても、依然として次のような問題に直面します。$O(n^2)$候補間隔。 すべての有効な間隔の中から重複しない間隔の最大セットを選択すると、重み付き間隔スケジュールの問題が発生し、潜在的に次のような問題が発生します。$O(n^2)$エッジが大きすぎます。 

重要な点は、実際にはすべての有効な部分配列を明示的に必要とするわけではないということです。 私たちは、それぞれの立場に対する最良の答えだけを気にします。 これは、左から右にスキャンし、プレフィックス XOR 状態に関する情報を維持することを示唆しています。 

させて`pref[i]`最初の XOR になる`i`要素。 サブアレイ`(l+1 … r)`正確に XOR ゼロがある場合`pref[l] == pref[r]`。 したがって、各プレフィックス値について、それが出現した最後の位置がわかれば、次で終わる可能性のあるゼロ XOR セグメントを検出できます。`r`。 

以前のすべての発生を個別に追跡する代わりに、動的プログラミングを行うことができます。`dp[i]`プレフィックスを使用して形成できる有効なセグメントの最大数になります。`1…i`。 位置で`i`、何もしないか、または次の時点でセグメントを終了します。`i`。 セグメントを終了する場合`(j+1 … i)`XOR ゼロを使用すると、`dp[i] = dp[j] + 1`。 私たちにはそのような最高のものが必要です`j`。 

これを効率的に行うために、各プレフィックス XOR 値を最適なものにマッピングする辞書を維持します。`dp`このプレフィックスが発生したインデックスで見られる値。 これにより、すべての有効な以前のエンドポイントがインデックスごとに O(1) ルックアップに圧縮されます。 

ブルート フォースはすべてのペアを列挙します`(j, i)`、プレフィックス XOR + DP トリックはすべての有効なデータを圧縮します。`j`候補を XOR 値ごとに 1 つの最良の代表にまとめます。

 ## アルゴリズムのチュートリアル

 プレフィックス XOR 値と動的プログラミング テーブルを維持しながら、配列を左から右に処理します。 

1.初期化`dp[0] = 0`とプレフィックス XOR`px = 0`。 地図も保管しております`best`どこ`best[x]`プレフィックス XOR を持つすべての位置の最大 dp 値を表します`x`。 当初は、`best[0] = 0`。 これは、開始前に空のプレフィックスにゼロとゼロの XOR セグメントがあることを反映しています。 
2. ポジションごとに`i`1から`n`、 アップデート`px = px XOR a[i]`。 これにより、で終わるプレフィックスの XOR が得られます。`i`。 
3. 初期設定`dp[i] = dp[i-1]`。 これは、その位置でセグメントを終了しないことに相当します。`i`、事実上離れる`i`セグメント内で使用されていません。 
4. 次に、ゼロ XOR セグメントを次の時点で終了することを検討します。`i`。 もう少し前の位置であれば`j`同じプレフィックス XOR を持つ`px`、次に部分配列`(j+1 … i)`XOR ゼロがあります。 そんな中からのベストチョイス`j`を最大化するものです`dp[j]`、まさにその通りです`best[px]`。 したがって、更新できます`dp[i] = max(dp[i], best[px] + 1)`。 
5. 計算後`dp[i]`、更新します`best[px] = max(best[px], dp[i])`。 これにより、将来のポジションは、プレフィックス XOR 状態で終了した最適な構成を再利用できるようになります。 
6. 最終的な答えは次のとおりです。`dp[n]`。 

### なぜ効果があるのか

 このアルゴリズムは、すべての有効なセグメント末尾をプレフィックス XOR 状態に圧縮することに依存しています。 すべての有効なセグメント`(j+1 … i)`は、等しいプレフィックス XOR 値のペアに一意に対応します。 DP 値は、`j`その時点までの最適なセグメンテーションをキャプチャし、最大値のみを保存します。`dp[j]`プレフィックスごとの XOR により、より優れたトランジションが失われないことが保証されます。 遷移はプレフィックス XOR の等価性にのみ依存するため、追加の履歴構造は必要なく、すべての可能なセグメンテーションがこれらの状態を通じて表現可能です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    dp_prev = 0
    px = 0

    best = {0: 0}

    for i in range(n):
        px ^= a[i]

        dp_i = dp_prev

        if px in best:
            dp_i = max(dp_i, best[px] + 1)

        if px in best:
            best[px] = max(best[px], dp_i)
        else:
            best[px] = dp_i

        dp_prev = dp_i

    print(dp_prev)

if __name__ == "__main__":
    solve()
```このソリューションでは、以前の DP 値とプレフィックス XOR 状態の辞書のみが維持されます。 微妙な点は、更新するということです`best[px]`計算後`dp_i`これにより、将来のセグメントが、このプレフィックス XOR で終わる最もよく知られた構造に基づいて構築できるようになります。 

よくある落とし穴はアップデートです`best`早すぎると、誤ってセグメントが同じ位置で開始および終了し、答えが人為的に膨らむことになります。

 ## 特殊なケース

 重大なエッジ ケースは、多くのプレフィックスが早い段階で同じ XOR を共有する場合です。 このような場合、プレフィックス XOR ごとに最適な DP を保存できないと、アンダーカウントが発生します。 たとえば、`[0, 0, 0]`、すべてのプレフィックス XOR はゼロであり、すべての位置は以前の最適なセグメンテーションを拡張できます。 正しい行動は改善し続けることです`best[0]`DPが増加すると、 そうしないと、アルゴリズムが 1 でフリーズします。 

もう 1 つの微妙なケースは、最適なセグメンテーションで、後の 2 つのセグメントを有効にするために、すぐに有効なセグメントをスキップする必要がある場合です。 DP 定式化ではすでにこれに対応しています。`dp[i]`常に延長する場合と延長しない場合の両方を考慮しますが、それは更新を正しく遅らせた場合に限られます。`best`計算が終わるまで`dp[i]`。
