 ## 解決策
 ## 問題の理解

 本に書かれた整数のシーケンスが与えられ、指定された間隔内に合計が含まれるこのシーケンスの連続するセグメントがいくつあるかを数えたいとします。$[l, r]$。 

連続セグメントは 2 つのインデックスを選択して定義されます$i \le j$そして、からのすべての要素を合計します$a_i$に$a_j$。 このような各セグメントは「呪文」の候補とみなされます。 タスクは、これらのセグメントのうちのいくつが少なくとも合計を生み出すかを数えることです。$l$そしてせいぜい$r$。 

入力サイズは最大で$2 \cdot 10^5$数値、最大値は$10^9$規模的には。 これにより、すべてを明示的にチェックするソリューションは即座に除外されます。$O(n^2)$サブアレイ。 プレフィックス合計を使用して単一の合計が一定時間で計算される場合でも、エンドポイントのすべてのペアを反復処理すると、約$2 \cdot 10^{10}$制限時間を大幅に超えた最悪の場合の作戦。 

これにより、構造化されたペアを列挙するのではなく、問題をカウントするという解決策が導き出されます。 

負の数が存在する場合、微妙な問題が発生します。 プレフィックスの合計は単調ではなくなったため、部分配列の合計の順序に依存する手法は慎重に扱う必要があります。 たとえば、単純なスライディング ウィンドウのアプローチは、ウィンドウの合計が次の値を超えたとしても失敗します。$r$、負の数を追加すると合計が小さくなる可能性があるため、ウィンドウを拡大または縮小すると、予測どおりに動作しません。 

2 つのポインターの小さな失敗例を次に示します。 

入力:```
3 1 2
2 -2 2
```サブアレイは$[2], [2,-2], [2,-2,2], [-2], [-2,2], [2]$。 正しい答えは正確な列挙に依存しますが、2 ポインター法では合計が単調ではないため、誤って縮小または拡大を繰り返す可能性があります。 

中心となる問題は、プレフィックスの合計が任意の実整数である設定で、差が範囲内にあるプレフィックスの合計のペアをすべてカウントする必要があることです。 

## アプローチ

 まずは直接的なアイデアから始めます。 左の端点を固定することで、すべての部分配列の合計を計算できます。$i$、その後延長します$j$から$i$に$n$、累計を維持します。 それぞれについて$i$、これには費用がかかります$O(n)$、につながる$O(n^2)$トータルオペレーション。 すべてのサブ配列が一意に列挙されるため、これは正しいですが、$n$到達する$2 \cdot 10^5$、操作の合計数は約$4 \cdot 10^{10}$。 

これを改善するために、プレフィックス合計を使用して問題を書き直します。 させて$p[0] = 0$そして$p[i] = a_1 + \dots + a_i$。 次に、部分配列の合計$[i+1, j]$は$p[j] - p[i]$。 条件$l \le p[j] - p[i] \le r$は次のように再配置できます。$$p[j] - r \le p[i] \le p[j] - l.$$ここで問題は次のようになります。$j$、値の範囲内にある以前のプレフィックスの合計がいくつあるかを数えます。 これは、古典的な「動的プレフィックス セット内の値の数」の問題です。 

プレフィックスの合計を左から右に処理します。 それぞれのステップで$j$、間隔内に以前のプレフィックスの合計がいくつあるかをクエリする必要があります。 これは、プレフィックス合計の座標圧縮後にフェンウィック ツリー (バイナリ インデックス付きツリー) を使用して解決できます。これは、値が次のように大きくなる可能性があるためです。$10^{14}$中間形態で。 

各プレフィックス合計は構造体に 1 回挿入され、各ステップで構造体に対して範囲クエリが実行されます。 

これにより、問題はソートされた座標系での効率的な動的周波数カウントに変わります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース サブ配列 |$O(n^2)$|$O(1)$| 遅すぎる |
 | プレフィックスの合計 + フェンウィック ツリー |$O(n \log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 すべての部分配列の合計が 2 つのプレフィックス値の差になるように、配列をプレフィックスの合計に変換します。 この変換が必要なのは、区間合計の問題がペアのカウント問題に変わるためです。 

次に、すでに確認したプレフィックスの合計の数を保存するデータ構造を維持します。 新しいプレフィックス合計ごとに、次から導出される特定の数値間隔内に以前のプレフィックス合計がいくつあるかを尋ねます。$l$そして$r$。 

1. 最初の値が 0 で、次の各値が入力配列を累積するプレフィックス合計の配列を構築します。 これにより、すべてのサブ配列がプレフィックス インデックスのペアに対応することが保証されます。 
2. すべてのプレフィックスの合計を収集し、それらを並べ替えて圧縮座標系を構築します。 このステップが必要なのは、プレフィックスの合計が大きく負になる可能性があるためですが、フェンウィック ツリーにはコンパクトなインデックスが必要です。 
3. 圧縮インデックスに対するポイント更新とプレフィックス合計クエリをサポートするフェンウィック ツリーを初期化します。 
4. 初期プレフィックス sum 0 を構造体に挿入します。これは、配列が開始される前の空のプレフィックスを表すためです。 
5. 各プレフィックスの合計を左から右に繰り返します。 現在のプレフィックス値の場合$p[j]$、以前のプレフィックス合計の有効範囲を次のように計算します。$[p[j] - r, p[j] - l]$。 
6. 圧縮された座標に対する二分探索を使用して、この値範囲をインデックス範囲に変換します。 
7. このインデックス間隔にプレフィックス合計がいくつあるかをフェンウィック ツリーにクエリし、このカウントを答えに追加します。 
8. 現在のプレフィックス合計をフェンウィック ツリーに挿入すると、将来のポジションで使用できるようになります。 

重要な考え方は、位置を処理するとき、$j$、すべて有効です$i < j$はすでに挿入されているため、クエリは次で終わる有効なサブ配列を直接カウントします。$j$。 

### なぜ効果があるのか

 あらゆる段階で$j$、フェンウィック ツリーには、プレフィックス合計のマルチセットが正確に含まれています。$p[0] \dots p[j-1]$。 で終わる任意の有効なサブ配列$j$以前のプレフィックス合計の選択に対応します$p[i]$差分制約が成り立つように。 この変換により、すべての有効な部分配列がその右端で 1 回だけカウントされ、クエリ範囲が不等式条件に正確に一致するため、無効な部分配列が含まれないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

    def range_sum(self, l, r):
        if r < l:
            return 0
        return self.sum(r) - self.sum(l - 1)

def solve():
    n, l, r = map(int, input().split())
    a = list(map(int, input().split()))

    pref = [0]
    cur = 0
    for x in a:
        cur += x
        pref.append(cur)

    vals = sorted(set(pref))
    def get_id(x):
        import bisect
        return bisect.bisect_left(vals, x) + 1

    bit = Fenwick(len(vals))

    ans = 0
    bit.add(get_id(0), 1)

    for j in range(1, n + 1):
        x = pref[j]
        left = x - r
        right = x - l

        import bisect
        L = bisect.bisect_left(vals, left) + 1
        R = bisect.bisect_right(vals, right)

        ans += bit.range_sum(L, R)
        bit.add(get_id(x), 1)

    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションは、これまでに確認されたプレフィックス合計のカウントを維持するフェンウィック ツリーを中心に構造化されています。 座標圧縮ステップにより、任意の整数プレフィックスの合計をコンパクトなインデックス空間にマッピングできるようになります。 二分演算は値の制約をインデックスの制約に変換し、フェンウィック クエリは必要な範囲に入る有効なプレフィックスの合計の数をカウントします。 各プレフィックスは、カウントに使用された後にのみ挿入され、各位置で終わるサブ配列の正確性が保証されます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべてのプレフィックスの合計が同一である場合です。 たとえば、すべての配列要素がゼロの場合、すべての部分配列の合計はゼロになります。 プレフィックス配列は繰り返される値のシーケンスになるため、フェンウィック ツリーは一意の値ではなく組み合わせを正確にカウントする必要があります。 アルゴリズムはこれを処理します。これは、同一のプレフィックスがそれぞれ個別に挿入されるため、頻度カウントが自然に蓄積されるためです。 

もう一つのケースは次のような場合です。$l$そして$r$ゼロが含まれていますが、配列には大きな正と負の振動が含まれています。 たとえば、交互に$1, -1$多くの繰り返しプレフィックス値が生成されます。 範囲クエリは、すべての等しいプレフィックス ペアに引き続き正しく一致します。 

最後の微妙なケースは次のような場合です。$l$そして$r$大きな負の境界と正の境界があり、すべての部分配列を効果的にカウントします。 この場合、各クエリ間隔は常にプレフィックス範囲全体をカバーし、アルゴリズムはすべてのペアをカウントすることになります。$i < j$となり、$n(n+1)/2$、累積的なフェンウィック更新を通じて引き続き正しく処理されます。
