 ## 解決策
 ## 問題の理解

 Vasya は、いくつかの解決されたコンテストの問題と、固定数のタスクを含む既存のコンテストから開始します。 彼の目標は、成功率を厳密に半分よりも高くすることです。つまり、彼のアクションの後、解決されたタスクの数がコンテストの総タスクの半分を超えなければなりません。 

彼には進歩を促進する 2 つの方法があります。 1 つ目は、コンテストの既存のタスクを解決することです。これにより、解決済みの数だけが増加します。 2 番目の方法は、構造がより強力です。コンテストに新しいタスクを追加し、すぐにそれを解決します。これにより、解決されたタスクの数とタスクの総数の両方が増加します。 

このプロセスは、解決数とコンテスト サイズという 2 つの数値で表される初期状態から始まります。 各操作には時間のコストがかかります。目標は、費やされる合計時間を最小限に抑えながら、解決された数がタスクの合計数の半分を厳密に超える状態に到達することです。 

制約は初期値で最大 10 万に達します。これは、考えられるすべての操作シーケンスを単純にシミュレートしようとするソリューションは失敗することを直ちに示唆しています。 2 つの演算のすべての組み合わせに分岐するアプローチは、単一パラメーターに対する線形またはほぼ線形の決定に還元する必要があります。そうしないと、最大 10 万ステップにわたる二次探索が必要になる危険があります。 

目標条件自体に微妙な問題が現れます。 条件は解決済みと合計の両方の変数に依存しますが、両方の操作で解決済みが増加しますが、合計が増加するのは 1 つの操作だけです。 これにより、分子を改善すると分母も増加する可能性がある、移動目標が作成されます。 分母がどのように進化するかを考慮せずに、ステップごとに安価な操作を常に優先する単純な貪欲な戦略は、必要なしきい値の増加パターンを減らすためにタスクの追加が必要になる構築されたケースでは失敗します。 

## アプローチ

 ブルートフォースのアイデアは、条件が true になるまで、考えられるすべての操作シーケンスをシミュレートすることです。 現在の解決済みカウントと合計カウントによって定義された状態から、両方の操作を再帰的に、または状態全体にわたる BFS 経由で試行できます。 すべての操作には一定の効果があり、タスクを解決すると解決数が単調増加するため、常に有限ステップで目標に到達できるため、これは論理的に機能します。 

ただし、到達可能な状態の数は急速に増加しています。 最大 O(n) の操作を許可すると、各状態は 2 つの選択肢に分岐し、指数関数的な爆発につながります。 解決済みと合計のバランスがわずかに異なる状態は両方とも関連する可能性があり、最適性を失わずにそれらを安全にマージすることはできないため、コストによる枝刈りでも十分ではありません。 

重要な観察は、問題の構造が単一の不等式制約に崩壊していることです。 各操作は、しきい値を超えたかどうかを決定する線形式に寄与します。 この条件は、どのくらいの「アドバンテージ」を獲得する必要があるかという観点から書き直すことができます。 

最終条件を代数的に書き直してみましょう。 タイプ A の k 回の操作とタイプ B の m 回の操作の後、新しい解決数と新しい合計数が得られます。 要件は k と m の一次不等式になります。つまり、問題は、各操作をどの順序で実行するかではなく、実行する回数を選択することになります。 

この削減を修正すると、問題は単一の線形制約の下でのコストの最小化になります。 この構造により、m が固定されると最適な k が強制されるため、演算間の効率の貪欲な比較や 1 つの変数の直接スキャンが可能になります。

直接的で信頼性の高いアプローチは、タイプ B の操作の数を反復し、タイプ A の操作の最小必要数を計算することです。 これが機能するのは、m を選択するたびに、制約が k に対する単純な 1 次元の境界になり、最適な k が常に実行可能な最小の整数になるためです。

 ## アルゴリズムのチュートリアル

 まず、成功条件を、使用される操作の数のみに依存する形式に変換します。 A 操作を k 回、B 操作を m 回適用するとします。 解決された数は k + m ずつ増加し、タスクの総数は m ずつ増加します。 「解が全体の半分以上である」という条件は、k と m を含む不等式になります。 

次に、すべての定数項を分離して、最初に条件を満たしているところからどの程度離れているかを理解します。 これにより、開始値のみに依存する必要な改善しきい値が得られます。 

次に、分母の増加によってしきい値がどの程度変化するかは m によって完全に決定されるため、m のすべての可能な値に対して反復処理を行います。 固定された m ごとに、不等式を満たすために必要な最小の k を計算します。 各 A 演算は分母に影響を与えることなく分子により強く寄与するため、最小 k は常に残りのギャップを満たす最小の整数になります。 

各ペア (m, k) について、総コストを m 倍 b と k 倍 a として計算し、すべての選択肢の最小値を追跡します。 

最後に、計算された最小のコストを返します。 

### なぜ効果があるのか

 核となる不変条件は、固定数の「高価な構造操作」B に対して、残りの要件が A の線形単調条件になるということです。不等式の境界を越える k の異なる選択間に相互作用はないため、実現可能な最小の k を選択することが常に最適です。 すべての有効な解は m の値とその値から導かれる最適な k に一意に対応するため、m を列挙することにより、省略や重複なく解空間全体がカバーされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = int(input())
    p = int(input())
    a = int(input())
    b = int(input())

    # Need: (s + k + m) * 2 > (p + m)
    # => 2s + 2k + 2m > p + m
    # => 2k + m > p - 2s
    D = p - 2 * s

    # We need 2k + m >= D + 1
    need = D + 1

    INF = 10**30
    ans = INF

    # try all m
    for m in range(need + 1):
        rem = need - m
        if rem <= 0:
            k = 0
        else:
            k = (rem + 1) // 2

        cost = m * b + k * a
        ans = min(ans, cost)

    print(ans)

if __name__ == "__main__":
    solve()
```解決策は、勝利条件を赤字形式に書き換えることから始まります。 変数`D`Vasya が開始時の不等式を満たすまでにどれだけ遠いかを測定します。 次に、条件を演算の線形結合に関する要件に変換します。 

ループオーバー`m`タスクの数と解決された数の両方を変更する操作を Vasya が使用する回数を修正することを表します。 それが修正されると、残りの要件は、必要な純粋な解決操作の数を決定する単純な上限分割になります。 表現`(rem + 1) // 2`を満たす最小の整数 k`2k >= rem`。 

コストは直接累積され、グローバル最小値と比較されます。 m が要件を超えると k はゼロになり、m を追加してもコストが増加するだけであるため、反復範囲は安全です。 

## 実用的な例

 s = 1、p = 5、a = 2、b = 3 の小さなシナリオを考えてみましょう。当初、Vasya はまだ半分以上解決していません。 

D = p - 2s = 5 - 2 = 3 を計算すると、need は 4 になります。 

さまざまな m 値を評価します。 

| メートル | 残り 2,000 個必要 | k | 総費用 |
 | --- | --- | --- | --- |
 | 0 | 4 | 2 | 4 |
 | 1 | 3 | 2 | 7 |
 | 2 | 2 | 1 | 7 |
 | 3 | 1 | 1 | 9 |
 | 4 | 0 | 0 | 12 |

 最小値は m = 0、k = 2 で達成されます。これは、構造演算に比べて解法が十分に効率的であるため、純粋な解法がここでは最適であることを示しています。 

ここで、s = 0、p = 3、a = 10、b = 1 を考えます。D = 3、need = 4 が得られます。 

| メートル | k | コスト |
 | --- | --- | --- |
 | 0 | 2 | 20 |
 | 1 | 2 | 21 |
 | 2 | 1 | 12 |
 | 3 | 1 | 13 |
 | 4 | 0 | 4 |

 最良の解決策は m = 4、k = 0 です。これは、新しいタスクの追加と解決が実効利益あたり大幅に低コストであることを意味します。 

これら 2 つのトレースは、操作間のバランスが相対コストに応じて最適な戦略をどのように変更するかを示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from contextlib import redirect_stdout
    out = io.StringIO()
    with redirect_stdout(out):
        solve()
    return out.getvalue().strip()

def solve():
    s = int(input())
    p = int(input())
    a = int(input())
    b = int(input())

    D = p - 2 * s
    need = D + 1
    INF = 10**30
    ans = INF

    for m in range(need + 1):
        rem = need - m
        if rem <= 0:
            k = 0
        else:
            k = (rem + 1) // 2
        ans = min(ans, m * b + k * a)

    print(ans)

# minimum case
assert run("0\n1\n1\n1\n") == "1"

# only solving is best
assert run("1\n5\n2\n100\n") == "4"

# only adding is best
assert run("0\n3\n100\n1\n") == "4"

# balanced case
assert run("2\n10\n3\n2\n") is not None
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 0,1,1,1 | 1 | 最小境界の場合 |
 | 1,5,2,100 | 4 | 純粋なA優位性 |
 | 0,3,100,1 | 4 | 純粋なBの優位性 |
 | 2,10,3,2 | 有効な最小値 | 混合戦略の安定性 |

 ## 特殊なケース

 初期状態がすでにしきい値に近い場合、必要な値 D は小さくなり、m にわたるループでタイプ A のゼロ操作が必要であることがすぐに判明する可能性があります。 その場合、アルゴリズムは、構造演算の方が安価であれば、構造演算のみを正しく選択します。 

たとえば、s = 4 および p = 7 の場合、すでに 4 > 3.5 であるため、演算は必要ありません。 導出された式では D = -1 が得られ、計算されたニーズはゼロまたは負になり、ループは正しくゼロのコストを返します。 

a が b に比べて極端に小さい場合、各 A は不等式に 2 倍効率的に寄与するため、アルゴリズムは当然 k 個の演算を優先します。 列挙では、明示的な貪欲な推論を必要とせずにこれを捕捉します。 

b が非常に小さい場合、ループは、p を増加しても m を増加させると条件を急速に満たすことがわかり、k が 0 に等しい大きな m で最適解が達成されます。
