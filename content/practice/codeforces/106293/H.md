 ## 解決策
 ## 問題の理解

 非常に広い幅と最大 200,000 行のグリッドが与えられています。 各行では、セルの連続セグメントのみが都市に属し、これらのセグメントは連続する行間で重複することが保証されているため、形状全体が分割される隙間のない 1 つの接続された直交領域を形成します。 

この領域内では、横に隣接するセル間でのみ移動が許可され、許可されたセグメントの外に出ることは禁止されます。 各クエリに対して、開始セルと目的地セルが与えられます。どちらも都市内にあることが保証されており、それらの間を移動するために必要なユニットの移動の最小数が必要です。 

この制約により、グリッドを明示的に探索するアプローチは即座に除外されます。 幅は最大 1e9 であるため、行を配列として保存することさえ不可能です。 行数とクエリ数は両方とも最大 200k であるため、定数または対数のクエリ時間で、ソリューションは行数がほぼ線形またはほぼ線形になる必要があります。 

クエリごとの単純な最短パス検索では、グリッドをグラフとして扱い、BFS またはダイクストラを実行します。 これは、グリッド サイズが巨大であり、各 BFS が暗黙的な間隔を推論する必要があるため、処理が遅すぎるために失敗します。 

2 番目の素朴な考えは、マンハッタンの距離が空のグリッド内の答えであることに気づくことです。 ただし、コリドーの制約により迂回が余儀なくされる場合があります。 単純な反例は、列が通路を狭める場合に現れます。 

入力:

 3 10

 1 10

 4 7

 1 10

 (1,2) から (3,9) までのクエリ

 中央の行では列 4 ～ 7 しか許可されないため、その区間に入るにはパスを水平に迂回する必要があり、マンハッタン距離を超える距離が増加します。 

主な問題は、パスが 2 点間のすべての行によって決定される「ボトルネック間隔」を通過しなければならない場合があることです。 

## アプローチ

 ブルート フォースの観点では、各行間隔をセルのセットとしてモデル化し、クエリごとに最短パス検索を実行します。 列を圧縮したとしても、各行は依然として O(m) 個の位置に接続される可能性があるため、2e5 クエリ全体では BFS が依然として遅すぎる可能性があります。 

重要な構造的観察は、2 点間の有効なパスは行内を単調に移動する必要があるということです。これは、単位重みを持つグリッドでは上下に移動すると利点のないサイクルが作成されるためです。 したがって、最短パスは、途中で発生するすべての行間隔内に収まる x 座標を選択しながら、2 つの行の間を垂直に移動するか、それが不可能な場合は迂回すると見なされます。 

これにより、問題は、行を走査するときに実行可能な x 範囲がどのように変化するかを理解することになります。 行 a と行 c の間の固定垂直セグメントの場合、すべての行 i が許容間隔 [li, ri] に寄与します。 これらすべての間隔の交差によって、垂直方向に移動しながら一定の列を維持できるかどうかが決まります。 交差点が空でない場合、これらの行間を移動する際に水平方向の迂回を完全に回避できます。 それが空の場合、最善の戦略は、交差点にできるだけ近くに留まり、エンドポイントが実行可能領域からどのくらい離れているかによって決定される追加の水平コストを支払うことです。 

これにより、各クエリが間隔にわたる範囲クエリに減ります。行のセグメントにわたる最大の左境界と最小の右境界が必要です。

 ## アルゴリズムのチュートリアル

 ### 1. 行に対する間隔制約を前処理する

列間隔にわたって 2 つの構造を構築します。 1 つはプレフィックスまたは左エンドポイントの範囲の最大値を保存し、もう 1 つは右エンドポイントの範囲の最小値を保存します。 これにより、行の任意のセグメントについて、そのセグメント内のすべての行によって課される最も厳しい水平方向の制限を迅速に計算できます。 

これが機能する理由は、単一列に留まることが可能かどうかは、すべての間隔が重なるかどうかのみに依存するためです。 

### 2. 範囲クエリ構造を構築する

 li の範囲の最大値と ri の範囲の最小値に対してスパース テーブルを構築します。 これにより、あらゆるセグメント クエリに一定時間内に応答できるようになります。 

### 3. 各クエリを個別に処理する

 行 a と行 c の間のクエリの場合、一般性を失うことなく、a が c より大きいと仮定します。 それらの間の行間隔セグメントを取得し、次のように計算します。 

セグメント内のすべての行の最大左境界 L

 セグメント内のすべての行にわたる最小の右境界 R

 これにより、2 点間の垂直コリドー上にグローバル交差制約が与えられます。 

### 4. 垂直移動コストを計算する

 垂直距離は正確に |a - c| に寄与します。 一度に 1 行ずつ移動するためです。 

### 5. 水平方向の調整コストを計算する

 ここで、列 b と列 d をどのように処理するかを決定します。 

間隔 [L, R] が [min(b, d), max(b, d)] と交差する場合、実行可能コリドーの内側と端点の間に位置する列が存在します。 この場合、両方の点を交差点内の同じ列に揃えることができ、水平コストは単純に |b - d| になります。 

それ以外の場合、交差点は完全に端点の片側にあるため、[L, R] の最も近い境界に移動する必要があります。 R が両方の端点の左側にある場合、最適な列は R であり、L が両方の端点の右側にある場合、最適な列は L です。コストは、両方の端点から選択した境界までの距離の合計になります。 

### 6. 貢献を結合する

 最終的な答えは、垂直距離に最適な水平迂回コストを加えたものです。 

### なぜ効果があるのか

 行を再訪してもサイクルが追加されるだけであるため、パスは長さを増やさずに行インデックス内を単調に移動するパスに変換できます。 この単調な垂直移動に沿って、唯一の自由は柱を選択することです。 その列は、アクセスされるすべての行間隔内に存在する必要があるため、それらすべての間隔の交差部分に存在する必要があります。 交差点が空でない場合は、定数列パスが可能です。 そうでない場合、最適な戦略は交点にできる限り近くに留まることであり、そのような最良の選択は、まさに区間にわたる凸絶対値式を最小化することになります。これは、実行可能な範囲への端点の投影で達成されます。 これにより、計算されたコストが制約付きグリッド グラフ内の真の最短パスと確実に一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_sparse_max(arr):
    n = len(arr)
    LOG = (n).bit_length()
    st = [arr[:]]
    j = 1
    while (1 << j) <= n:
        prev = st[-1]
        curr = [0] * (n - (1 << j) + 1)
        half = 1 << (j - 1)
        for i in range(len(curr)):
            curr[i] = max(prev[i], prev[i + half])
        st.append(curr)
        j += 1
    return st

def build_sparse_min(arr):
    n = len(arr)
    LOG = (n).bit_length()
    st = [arr[:]]
    j = 1
    while (1 << j) <= n:
        prev = st[-1]
        curr = [0] * (n - (1 << j) + 1)
        half = 1 << (j - 1)
        for i in range(len(curr)):
            curr[i] = min(prev[i], prev[i + half])
        st.append(curr)
        j += 1
    return st

def query_max(st, l, r):
    length = r - l + 1
    j = length.bit_length() - 1
    return max(st[j][l], st[j][r - (1 << j) + 1])

def query_min(st, l, r):
    length = r - l + 1
    j = length.bit_length() - 1
    return min(st[j][l], st[j][r - (1 << j) + 1])

def solve():
    n, m = map(int, input().split())
    L = [0] * n
    R = [0] * n

    for i in range(n):
        l, r = map(int, input().split())
        L[i] = l
        R[i] = r

    stL = build_sparse_max(L)
    stR = build_sparse_min(R)

    q = int(input())
    out = []

    for _ in range(q):
        a, b, c, d = map(int, input().split())
        a -= 1
        c -= 1

        if a > c:
            a, c = c, a
            b, d = d, b

        Lseg = query_max(stL, a, c)
        Rseg = query_min(stR, a, c)

        if b > d:
            b, d = d, b

        vertical = c - a
        horiz = abs(b - d)

        lo, hi = b, d

        if Rseg < lo:
            horiz = (lo - Rseg) + (hi - Rseg)
        elif Lseg > hi:
            horiz = (Lseg - lo) + (Lseg - hi)
        else:
            horiz = hi - lo

        out.append(str(vertical + horiz))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```実装は、行間隔にわたる範囲の最大値と最小値を表すスパース テーブルを構築することから始まります。これは、垂直方向に移動するにつれてコリドーがどのように狭くなるかを直接エンコードします。 

各クエリは行の順序を正規化し、常に上から下のセグメントを処理します。 次に、そのセグメントに対して可能な限り厳しい水平制約を計算します。 

水平方向の計算では、実現可能なコリドーと完全に重なる、両方のポイントの完全に左側のコリドー、または両方のポイントの完全に右側のコリドーの 3 つの幾何学的構成が処理されます。 各ケースは、異なる最適な投影戦略に対応します。

 ## 特殊なケース

 主要なエッジ ケースは、行セグメント上の交差が 1 つの点に折りたたまれるか、1 つの境界行で正確に空になる場合に発生します。 このような状況では、すべての垂直移動が中間の狭まりを考慮しなければならないということを無視しているため、単純なマンハッタンの仮定は失敗します。 スパース テーブルはセグメント全体にわたる正確な最小制約と最大制約を取得するため、アルゴリズムはこれを正しく処理します。そのため、単一の制約行であっても、計算された交差に即座に影響を与え、正しい迂回コストが強制されます。
