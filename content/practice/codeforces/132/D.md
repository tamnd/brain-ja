 ## 解決策
 ## 問題の理解

 2 進数で与えられた正の整数を 2 のべき乗の合計として表すように求められます。オプションで項の総数が最小になるように負のべき乗を使用することもできます。 形式的には、次の形式の式の合計として数値を書きたいとします。`+2^x`または`-2^x`。 入力は最大 1,000,000 までの長さのバイナリ文字列で、数値自体が非常に大きくなる可能性があり、すべての整数値を反復する余裕がないことがすぐにわかります。 出力は最初に最小合計内の項の数であり、その後に各項が明示的に続きます。 

課題は、項の数を最小限に抑えることにあります。 単純なアプローチでは、各 1 ビットを次のように表すことになります。`+2^x`、バイナリ表現の 1 の数と同じ数の項が生成されます。 これは正しいですが、多くの場合、これは最小限ではありません。 たとえば、バイナリ`1111`(10 進数 15) は次のように表すことができます。`+2^4 - 2^0`、4つの項ではなく2つの項のみを与えます。 

エッジケースには次のような数字が含まれます`1000`(10 進数 8) ここで、単純なメソッドはすでに最小になっています。または、次のような 1 が長く続く数値です。`11111`(10 進数 31)。グループ化して高次の累乗を使用すると、項の数が減ります。 不注意なアプローチではキャリー伝播を無視し、常に 1 ビットごとに 1 つの項を出力することになり、次善の解決策が得られます。 

入力の長さが長いということは、二次関数以上のアプローチでは 2 秒の時間制限を超えるため、バイナリ文字列の長さにおいて線形なアルゴリズムが必要であることを意味します。 

## アプローチ

 ブルート フォースのアプローチは簡単です。バイナリ文字列を反復処理し、1 に設定された各ビットに対して次の値を追加します。`+2^x`用語のリストへ。 これにより、1 の数と同じ数の項が生成されます。 それは正しいですが、最小限からは程遠い場合があります。 長さのバイナリ文字列の場合`n`すべてのビットを 1 に設定すると、単純なメソッドは次の結果を生成します。`n`条項。 と`n`最大 1,000,000 ですが、これは最小性と出力サイズの両方の点で非現実的です。 

重要な洞察は、バイナリ表現を基数 2 の数値のように扱い、加算のように「桁上げ」を考慮することです。 連続する 1 がある場合、それらを 0 に反転し、次に高いべき乗に +1 を追加すると、項の総数が減ります。 これはアイデンティティを効果的に利用しています`2^k + 2^k + ... + 2^k (r times) = 2^(k+1) + ...`必要に応じてキャリーと否定項を使用します。 

最適なアルゴリズムは、2 進数を最下位ビットから最上位ビットまで処理し、1 の連続がより少ない項に折りたたまれるたびに前方に伝播する「キャリー」を維持します。 各ステップで、ビットを残すか、負の項を生成するか、キャリーに寄与するかを決定します。 これにより、文字列を 1 回反復する際に、項の合計数が理論上の最小値まで減ります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n) | O(n) | 正しいが最小限ではない |
 | 最適 | O(n) | O(n) | 正しくて最小限 |

 ## アルゴリズムのチュートリアル

 1. 入力からバイナリ文字列を読み取り、それを反転して最下位ビットから最上位ビットまで処理します。 反転すると、キャリーを追加するときのインデックスの処理が簡素化されます。 
2. キャリー変数を 0 に初期化し、項の空のリストを初期化します。 キャリーは保留中を表します`+2^k`または`-2^k`次に上位のビットに調整します。 
3. 各ビットインデックスを反復処理します。`i`。 現在のビットとキャリーを加算して、この位置の実効値を取得します。 この値は、ビットおよび以前のキャリーに応じて、0、1、2、または 3 になります。 
4. 実効値が 0 または 1 の場合、負の項は必要ありません。 実効値が1の場合は追記`+2^i`用語のリストへ。 キャリーを0に設定します。 
5. 実効値が 2 の場合、これは次と同等です。`0`のキャリーで現在の位置に`+1`次の上位ビットへ。 このビットには用語を追加しないでください。 インクリメントキャリー。 
6. 実効値が 3 の場合、これは次と同等です。`1`のキャリーで現在の位置に`+1`次の上位ビットへ。 追加`-2^i`余分なものを相殺するために`2^i`そしてキャリーをインクリメントします。 
7. すべてのビットを処理した後、キャリーが残っている場合は追加します。`+2^len(binary_string)`それを処理するために。 
8. 各用語に続く用語の合計数を出力します。 用語の順序は関係ありません。 

ここでの不変条件は、各ステップで、現在のビット、前のキャリー、および放出する決定の組み合わせであるということです。`+2^i`または`-2^i`発行されたすべての項の合計とキャリーが元の数値に等しいことを保証します。 これにより、あらゆるビットからの寄与が過大にカウントされたり欠落したりすることがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

binary = input().strip()[::-1]  # reverse to process LSB to MSB
n = len(binary)
carry = 0
terms = []

for i in range(n):
    bit = int(binary[i])
    val = bit + carry
    if val == 0:
        carry = 0
    elif val == 1:
        terms.append(f"+2^{i}")
        carry = 0
    elif val == 2:
        carry = 1
    elif val == 3:
        terms.append(f"-2^{i}")
        carry = 1

if carry:
    terms.append(f"+2^{n}")

print(len(terms))
print("\n".join(terms))
```コードはまずバイナリ文字列を反転して、インデックスが`i`に相当する`2^i`。 各ビットを反復処理して、前の操作からのキャリーと組み合わせます。 のケース`val`すべての可能性を処理します: 項は必要ありません、正の項を追加、キャリーを伝播、またはキャリー付きの負の項を追加します。 残りのキャリーの最終チェックにより、次のような数値の正確性が保証されます。`1111`それは余分な力を伝播します。

 これは、n ≤ 1,000,000 の時間とメモリの制限内に収まります。
