 ## 解決策
 ## 問題の理解

 INTERCAL の奇妙な「チューリング テープ」出力手順によって印刷された最終的なテキストが与えられます。 印刷された各文字は、未知の配列の 1 つの整数から生成されました。 エンコードプロセスは直前に印刷された文字に依存するため、すべてのステップはその前のステップにリンクされています。 

単一の文字の場合、プロセスは次のように機能します。 

まず、前に出力された文字を取得し、その 8 ビット バイナリ表現を反転します。 一番最初の文字の場合、この値は次のように扱われます。`0`。 

次に、現在の配列値を法的に減算します。`256`。 

3 番目に、ビットを再度反転し、その結果を印刷される文字の ASCII コードとして解釈します。 

タスクは、印刷されたテキストから元の配列を再構築することです。 

入力長は最大でも`100`、小さいです。 非効率的なソリューションであっても、簡単に制限内に収まります。 本当の課題は、変換を正しく理解し、ビット反転やモジュロ演算での間違いを避けることです。 

最も間違いが起こりやすいのは、式の方向です。 エンコードでは、逆ではなく、反転された前の文字から配列値が減算されます。 誤って計算してしまうと:```
x = current - previous
```の代わりに```
x = previous - current  (mod 256)
```シーケンス全体が間違ってしまいます。 

もう 1 つのよくある間違いは、正確に 8 ビットではなく、重要なビットのみを反転することです。 

たとえば、キャラクター`'A'`ASCII値を持つ`65`。```
65 = 01000001₂
```8 ビットすべてを反転すると、次のようになります。```
10000010₂ = 130
```不注意な実装は逆効果になる可能性があります`"1000001"`そして手に入れる`"1000001"`またまた、間違って作成しました`65`。 

モジュロ処理も細かい点です。 前回の反転値が次のようになったとします。`0`現在の反転値は`18`。 

必要な配列要素は次のとおりです。```
(0 - 18) mod 256 = 238
```モジュロ演算を忘れた場合は、次のように出力します。`-18`、配列要素は符号なし 8 ビット整数でなければならないため、これは無効です。 

## アプローチ

 ブルートフォースアプローチでは、考えられるすべての配列値を試します。`0`に`255`文字ごとに、生成された文字がターゲット テキストと一致するまでエンコード プロセスをシミュレートします。 

1 つのポジションについては、テストする可能性があります。`256`各テストではビットを反転し、結果の文字をチェックする必要があります。 せいぜい`100`文字、これはおおよそになります`256 × 100 = 25600`試みても、制限内ではまったく問題ありません。 

検索スペースが非常に小さいため、総当たり攻撃が機能します。 すべての配列要素は 8 ビット値であるため、`256`可能性。 

問題は、ブルート フォースが変換の内部に隠された代数を無視することです。 エンコードプロセスは完全に元に戻すことができます。 それを認識すると、推測する必要はなくなります。 

仮定する：```
p = reverse_bits(previous_character)
c = reverse_bits(current_character)
```エンコード規則には次のように書かれています。```
c = (p - a[i]) mod 256
```並べ替えると次のようになります。```
a[i] = (p - c) mod 256
```右側にあるものはすべて、テキスト自体からすでにわかっています。 前の文字もわかっており、現在の文字もわかっています。 つまり、各配列要素は一定時間内に直接計算できます。 

重要な観察は、ビット反転はそれ自身の反転であるということです。 2 回反転すると元の数値に戻ります。 そのため、印刷された文字の ASCII 値を単純に反転し、エンコード中に使用される正確な中間状態を再構築できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(256n) | お(1) | 承認済み |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力文字列を読み取ります。 
2. 変数を維持する`prev`、前に印刷された文字の反転された 2 進値を表します。 に初期化します`0`なぜなら、このステートメントは最初のステップをそのように定義しているからです。 
3. 文字列内の各文字について、その ASCII 値を次のように計算します。`ord()`。 
4. 正確に 8 ビットを使用して、この ASCII 値のビットを反転します。 

反転では先頭のゼロを保持する必要があります。 例えば：```
00010010 -> 01001000
```5. この反転した値を次のようにします。`cur`。 
6. エンコード規則は次のとおりです。```
cur = (prev - a[i]) mod 256
```並べ替えると次のようになります。```
a[i] = (prev - cur) mod 256
```この値を計算して出力します。 
7.アップデート`prev = cur`次の文字を処理する前に。 

### なぜ効果があるのか

 このアルゴリズムは、エンコード中に使用されたものとまったく同じ中間値を再構築します。 

キャラクターごとに、`cur`印刷された文字を反転すると中間状態が復元されるため、元のプロセスのステップ 2 の後に生成された結果と等しくなります。 エンコード方程式は次のとおりです。```
cur = (prev - a[i]) mod 256
```解決する`a[i]`元の配列値を一意に決定します。 不変条件とは、`prev`は常に、次の要素を処理する前にエンコーダーの状態と正確に一致する、直前に印刷された文字の反転表現を保存します。 

すべてのステップは可逆的かつモジュロであるため、`256`算術演算は保持され、再構築された配列は正しいことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def reverse_bits(x):
    res = 0

    for i in range(8):
        if x & (1 << i):
            res |= (1 << (7 - i))

    return res

def solve():
    s = input().rstrip("\n")

    prev = 0

    for ch in s:
        cur = reverse_bits(ord(ch))
        value = (prev - cur) % 256
        print(value)
        prev = cur

solve()
```の`reverse_bits`関数は正確な 8 ビット反転を実行します。 ASCII 文字にはバイナリ形式で先頭にゼロが含まれる場合があるため、この詳細は重要です。 パディングなしで文字列スライスを使用すると、多くの文字に対して不正確な答えが生成されます。 

変数`prev`直前に印刷された文字の反転バイナリ表現を格納します。 最初はそうです`0`、最初の文字に対するステートメントの特別なルールと一致します。 

コードは文字ごとに以下を計算します。```
value = (prev - cur) % 256
```元のプロセスでは符号なし 8 ビット演算が使用されるため、モジュロ演算は不可欠です。 パイソンの`% 256`マイナスの差を正しい範囲にきれいに変換します`0..255`。 

アップデート内容:```
prev = cur
```現在の回答を出力した後に発生する必要があります。 更新が早す​​ぎると、シーケンス全体が 1 位置ずつシフトします。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def reverse_bits(x):
    res = 0

    for i in range(8):
        if x & (1 << i):
            res |= (1 << (7 - i))

    return res

def solve():
    input = sys.stdin.readline

    s = input().rstrip("\n")

    prev = 0
    out = []

    for ch in s:
        cur = reverse_bits(ord(ch))
        out.append(str((prev - cur) % 256))
        prev = cur

    print("\n".join(out))

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    result = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return result

# provided sample
assert run("Hello, World!\n") == (
    "238\n108\n112\n0\n64\n194\n48\n26\n244\n168\n24\n16\n162\n"
), "sample 1"

# minimum size input
assert run("A\n") == "126\n", "single character"

# repeated characters
assert run("AAA\n") == "126\n0\n0\n", "same reversed value repeatedly"

# boundary ASCII values
assert run(" ~\n") == "252\n252\n", "space and tilde"

# alternating pattern
assert run("Hi\n") == "238\n124\n", "state transition correctness"

# maximum size style test
assert len(run(("A" * 100) + "\n").strip().split()) == 100, "length 100"
