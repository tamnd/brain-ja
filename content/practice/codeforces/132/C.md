 ## 解決策
 ## 問題の理解

 タートルは座標から始まります`0`数直線上にあり、最初は正の方向を向いています。 各コマンドは 2 つの方法のいずれかで状態を変更します。 

コマンドが`F`、タートルは現在向いている方向に 1 ユニット移動します。 

コマンドが`T`、カメは向きを変えるので、今後の動きは反対方向に起こります。 

コマンドを正確に変更することができます`n`回。 変更すると 1 文字が反転します。`F`になる`T`、 または`T`になる`F`。 同じ位置が複数回反転される可能性がありますが、2 回反転すると自動的にキャンセルされるため、これは重要です。 すべての変更が適用された後、タートルは結果のコマンド文字列を実行します。 目標は、最終座標の絶対値を最大化することです。 

コマンド文字列の長さは最大でも`100`、 そして`n`せいぜい`50`。 これらの制限は、位置と操作数に対する動的プログラミングには十分小さいものです。 変更された可能性のあるすべての文字列を総当たり検索するには、大まかにチェックする必要があります。`2^100`最悪の場合は可能性もありますが、それは完全に不可能です。 

難しいのは、方向の変更が今後のすべての動きに影響することです。 個々の動きを最大化しようとする貪欲な戦略は失敗します。`T`後に多くの影響を逆転させる可能性がある`F`コマンド。 

いくつかのエッジケースでは、単純な実装が静かに破壊されます。 

考慮する：```
F
1
```可能な唯一の変化は`F`の中へ`T`。 カメは決して動かないので、答えは次のとおりです。`0`。 不注意な解決策は、すべての変更が距離を増加させる可能性があると想定する可能性があります。 

もう 1 つの微妙なケースは、同じコマンドの繰り返しの反転です。```
F
2
```正確に 2 つの変更を実行する必要があります。 1 つの文字を 2 回反転すると元の文字列が復元されるため、タートルは引き続き次の文字列に移動します。`1`。 すべての変更が最終文字列に独立して影響することを前提とした解決策では、誤った結果が得られます。 

パリティも重要です:```
TT
1
```1 つのコマンドを変更すると、次のいずれかが生成されます`FT`または`TF`。 どちらの場合も、タートルは正確に 1 回移動するため、答えは次のようになります。`1`。 有効な変更の数は、次と同じパリティを持つ必要があります。`n`、余分なダブルフリップは何もしないからです。 

最後に、方向の状態を正しく追跡する必要があります。```
TFTF
1
```間違ったコマンドを変更すると、後の動作が完全に逆転する可能性があります。 数を数えるだけのソリューション`F`そして`T`方向を追跡しないと、ここで失敗します。 

## アプローチ

 最も直接的な強引なアイデアは、変更を適用し、結果として得られるコマンド文字列を構築し、タートルをシミュレートし、最適な最終距離を維持するためのあらゆる方法を試してみることです。 

最終的に変更された文字列のみを考慮した場合、各文字は独立して次のいずれかになります。`F`または`T`、あります。`2^m`長さに指定できる文字列`m`。 と`m = 100`、これは天文学的な大きさです。 

さらに悪いことに、このステートメントでは同じ位置を複数回変更することができます。 正確に分配する必要がある`n`パリティを尊重しながらポジション間で演算を行うため、状態空間がさらに大きくなります。 

タートル シミュレーション自体は単純であるため、ブルート フォース アプローチは概念的に機能します。 固定されたコマンド シーケンスが与えられると、現在の位置と方向を維持しながらコマンドを左から右に処理できます。 ボトルネックは、有効な変更されたシーケンスをすべて生成することです。 

重要な観察点は、文字列の処理中にタートルの動作が 3 つの情報のみに依存しているということです。 

コマンドリスト内の現在のインデックス。 

すでに使用されている変更の数。 

現在の方向。 

このような状態から、次のコマンドはいくつかの可能な遷移のみを生成します。 これはすぐに動的プログラミングを示唆します。 

特定の数の変更と特定の方向で文字列の一部のプレフィックスを処理した後、到達可能なすべての座標を表す DP 状態を定義します。 座標の範囲は以下のみであるため、`-100`に`100`、到達可能性を効率的に保存できます。 

各コマンドには 2 つの選択肢があります。 

コマンドを変更しないままにしてもよいでしょう。 

1 つの変更を加えて、それを反転することもできます。 

各選択により、方向と位置が決定的に更新されます。 州の数が少ないため、あらゆる可能性を安全に探索できます。 

最終的な答えは、文字列全体を正確に処理した後に到達可能な最大絶対座標です。`n`修正。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(2^m \cdot m)$|$O(m)$| 遅すぎる |
 | 最適なDP |$O(m \cdot n \cdot 2 \cdot R)$|$O(m \cdot n \cdot 2 \cdot R)$| 承認済み |

 ここ`R`はおおよその座標範囲です`201`。 

## アルゴリズムのチュートリアル

 1. DP 状態を定義する`dp[i][k][d]`最初の処理後に到達可能な座標のセットとして`i`コマンド、正確に使用`k`方向を向いて修正する`d`。 

方向を次のようにエンコードします`0`左用と`1`右です。 
2. 起動状態を初期化します。 

コマンドを処理する前に、タートルは座標にいます`0`そして右を向いています。 

そこで、次のことから始めます。```
dp[0][0][1] = {0}
```3. コマンドを左から右に処理します。 

到達可能な状態ごとに、次の 2 つの可能性を考慮してください。 

現在のコマンドを変更しないでください。 

現在のコマンドを反転して、1 回の変更を行います。 
4. 移動コマンドを処理します。 

有効なコマンドが`F`、タートルは現在の方向に 1 歩移動します。 

右を向くと位置が上がります`1`。 

左を向くと位置が下がります`1`。 
5. ターンコマンドを処理します。 

有効なコマンドが`T`、タートルは同じ座標に留まりますが、方向を反転します。 
6. 結果として得られるすべての状態を保存します。 

複数のパスが同じ状態に到達する可能性がありますが、到達可能性のみを考慮しているため、これは問題ありません。 
7. すべてのコマンドが処理された後、到達可能なすべての座標を正確に検査します。`n`修正。 

答えはその中で絶対値が最大の値です。 

### なぜ効果があるのか

 DP は、ルールと一致するあらゆる可能な変更シーケンスを調査します。 

各コマンドにおいて、アルゴリズムは、コマンドを維持するか反転するかの両方の正当な選択を明示的に考慮します。 すべての有効な変更された文字列は、DP 遷移を通る 1 つのパスに正確に対応します。 

状態には、処理を正しく続行するために必要なすべての情報が保存されます。 今後の動作は、現在の位置、方向、処理されたプレフィックスの長さ、およびすでに使用されている変更の数にのみ依存します。 過去の経歴は関係ありません。 

到達可能なすべての状態が処理され、無効な状態が導入されないため、DP は可能なすべての最終座標のセットを正確に計算します。 これらの座標の絶対値の最大値を取ると、最適な答えが得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = int(input())

    m = len(s)
    OFFSET = 105

    dp = [[set() for _ in range(2)] for _ in range(n + 1)]
    dp[0][1].add(0)

    for ch in s:
        ndp = [[set() for _ in range(2)] for _ in range(n + 1)]

        for used in range(n + 1):
            for d in range(2):
                for pos in dp[used][d]:

                    # keep command
                    if ch == 'F':
                        npos = pos + (1 if d else -1)
                        ndp[used][d].add(npos)
                    else:
                        ndp[used][d ^ 1].add(pos)

                    # flip command
                    if used < n:
                        if ch == 'F':
                            ndp[used + 1][d ^ 1].add(pos)
                        else:
                            npos = pos + (1 if d else -1)
                            ndp[used + 1][d].add(npos)

        dp = ndp

    ans = 0

    for d in range(2):
        for pos in dp[n][d]:
            ans = max(ans, abs(pos))

    print(ans)

solve()
```DP 構造体は、到達可能な座標をセットとして格納します。 これにより、状態の重複が自然に回避され、実装がシンプルに保たれます。 

外側のループはコマンドを 1 つずつ処理します。 到達可能な状態ごとに、コマンドを維持することとコマンドを反転することの両方のアクションを試します。 

方向エンコーディングは間違いやすいです。 ここ`1`右を向いていることを意味し、`0`左向きという意味です。 移動する場合は追加します`+1`右用と`-1`左用。 

回転しても位置は変わりません。 を使用して方向を切り替えるだけです`d ^ 1`。 

よくある間違いは、正確に必要なことを忘れることです`n`変更、せいぜい変更`n`。 最終的な答えは調べるだけです`dp[n]`。 

もう 1 つの微妙なディテールは、フリップの繰り返しです。 コマンドは操作カウントごとに独立して反転される場合と反転されない場合があるため、DP はこれらを自然に処理します。 パリティによって無駄な余分な操作が強制された場合でも、DP は正しい状態に到達します。

## 特殊なケース

 可能な最小の入力を考えてみましょう。```
F
1
```カメは次から始まります`0`右向き。 コマンドの変更のみを反転する`F`の中へ`T`。 カメは回転しますが、決して動きません。 DP は正確に位置に到達します`0`変更を 1 つだけ行うだけで済みます。 

次に、繰り返されるフリップを調べます。```
F
2
```1 回反転すると、コマンドは次のようになります。`T`。 2回目のフリップの後は、次のようになります。`F`また。 DP は最後の文字列だけを追跡するのではなく、正確な変更数を追跡するため、当然ながら元のコマンド シーケンスに戻ることができます。 最終的な順位は、`1`。 

方向に依存する動作は次の場合に発生します。```
TFTF
1
```最初をひっくり返すと`T`の中へ`F`、シーケンスは次のようになります`FFTF`。

0 -> 1 -> 2 -> turn -> 3
```最終的な距離は`3`。

最後に、パリティ制約は次のような場合に重要になります。```

5
```効果的なフリップごとに、`F`の中へ`T`、運動の可能性が低下します。 修正の数が奇数であるため、ペアですべての反転をキャンセルすることはできません。 少なくとも 1 つのコマンドを効果的に変更する必要があるため、考えられる最良の答えは次のとおりです。`9`、 ない`10`。
