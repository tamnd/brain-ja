 ## 解決策
 ## 問題の理解

 アリスは、コイン投げから作成されたバイナリ文字列を持っています。 文字列を与える代わりに、彼女は隣接する各ペアが出現する回数だけを与えます。`00`、`01`、`10`、 そして`11`。 これら 4 つのカウントを正確に生成できる異なるバイナリ文字列の数を数える必要があります。 答えはモジュロで計算されます`10^9+7`。 

4 つの値は隣接する文字間の遷移を表すため、隣接するペアの合計数は次のようになります。`a+b+c+d`、文字列の長さはそれより 1 つ長くなります。 この制約により、テスト ケースのすべての値の合計が次の値に達することが許可されます。`5 * 10^5`、文字列を列挙するもの、またはカウントの積に比例する作業を実行するものはすべて除外されます。 合計入力サイズにおいて線形に近い解決策が必要です。 

間違いの主な原因は、開始文字と終了文字が固定されていないことを忘れることです。 たとえば、入力`1 1 1 1`出力があります`4`。 すべての有効な文字列が次で始まると想定する不用意な解決策`0`で始まる文字列を見逃します`1`。 

もう 1 つのエッジ ケースは、間に変化がない場合です。`0`そして`1`。 入力用`3 0 0 0`、可能な唯一の文字列は次のとおりです。`0000`、したがって、答えは次のとおりです`1`。 遷移ブロックのカウントのみに基づく方法では、誤ってゼロで割ったり、交互の実行があると想定したりする可能性があります。 

最後の厄介なケースは、移行のバランスが不可能であることです。 入力用`0 0 3 0`、答えは`0`。 3つあります`10`トランジションはあるが、ない`01`遷移は、有限のバイナリ文字列では発生しません。`1`に`0`最終的には次のいずれかによって一致する必要があります。`0`または後で元に戻る`0`に`1`。 

## アプローチ

 直接的なアプローチでは、考えられるすべてのバイナリ文字列を構築し、その隣接するペアの数をチェックしようとします。 長さの文字列`n`もっている`2^n`可能性、そしてここ`n`周りにいることができます`500001`, なのでこれは無理です。 

有益な観察は、実行を観察することで得られます。 バイナリ文字列は、等しい文字の連続したグループで構成されます。 ゼロが連続する内部では、隣接するすべてのペアが 1 を提供します`00`。 あれば`r0`ゼロラン、ゼロの総数は`Z`、 それから`Z-r0=a`、 それで`Z=a+r0`。 同じアイデアが与えます`O=d+r1`ワンラン用。 

価値観`b`そして`c`存在する実行の数を決定します。 毎`01`トランジションはゼロランから 1 ランに移行し、`10`トランジションが元に戻ります。 それらの違いにより、文字列が同じ側で始まり、終わるのか、それとも反対側で終わるのかが分かります。 

ゼロランと 1 ランの数がわかったら、残りのタスクは、ゼロと 1 を正の長さのランに分割する方法をカウントするだけです。 分割`x`同一のアイテムを`k`ポジティブグループは以下で行うことができます`C(x-1,k-1)`最終的な式が得られます。 

ブルート フォースは、考えられるすべての文字列を直接モデル化するため機能しますが、文字列の数が指数関数的なため失敗します。 実行観察では、すべての有効な文字列が 2 つの独立した構成に圧縮され、問題が組み合わせ論に帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | 最適 | 合計入力あたり O(a+b+c+d) | O(500000) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての答えは組み合わせを使用して表現されるため、可能な最大値まで階乗および逆階乗を事前計算します。 

これらを使用して、モジュラー演算により定数時間で二項係数を評価します。 
2. バランスを確認します。`b`そして`c`。 

の数`01`そして`10`トランジションの違いは最大 1 つまでです。 差が大きい場合、文字列は存在できません。 
3. ケースを処理する`b = c = 0`。 

異なる文字間には遷移がないため、文字列には 0 のみ、または 1 のみを含める必要があります。 カウントによって、これら 2 つの可能性のいずれかが有効かどうかが決まります。 
4. ケースを処理する`b = c > 0`。 

文字列は同じ文字で始まり、同じ文字で終わります。 可能性は 2 つあります。 

で始まるなら`0`、 がある`b+1`ゼロランと`b`ワンラン。 貢献は次のとおりです。`C(a+b, b) * C(d+b-1, b-1)`で始まるなら`1`、役割が逆になります。`C(a+b-1, b-1) * C(d+b, b)`両方の可能性を追加します。 
5. ケースを処理する`b = c+1`。 

文字列は次で始まります`0`そして次で終わります`1`。 ゼロランもワンランも`b`数的には。 

答えは次のとおりです。`C(a+b-1, b-1) * C(d+b-1, b-1)`6. 対称ケースを処理する`c = b+1`。 

文字列は次で始まります`1`そして次で終わります`0`、与える:`C(a+c-1, c-1) * C(d+c-1, c-1)`これが機能する理由: すべての有効なバイナリ文字列は、ランへの固有の分解を持っています。 遷移カウントは、存在するゼロランとワンランの数を一意に決定します。ただし、開始文字の選択は除きます。`b=c`。 この式では、実行される可能性のある 0 と 1 のすべての正の分割がカウントされるため、有効な文字列はすべて 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10 ** 9 + 7

def solve():
    data = list(map(int, sys.stdin.buffer.read().split()))
    if not data:
        return

    t = data[0]
    queries = []
    mx = 0
    idx = 1
    for _ in range(t):
        a, b, c, d = data[idx], data[idx + 1], data[idx + 2], data[idx + 3]
        idx += 4
        queries.append((a, b, c, d))
        mx = max(mx, a + b + c + d + 1)

    fact = [1] * (mx + 1)
    for i in range(1, mx + 1):
        fact[i] = fact[i - 1] * i % MOD

    inv_fact = [1] * (mx + 1)
    inv_fact[mx] = pow(fact[mx], MOD - 2, MOD)
    for i in range(mx, 0, -1):
        inv_fact[i - 1] = inv_fact[i] * i % MOD

    def comb(n, r):
        if r < 0 or r > n:
            return 0
        return fact[n] * inv_fact[r] % MOD * inv_fact[n - r] % MOD

    ans = []

    for a, b, c, d in queries:
        if abs(b - c) > 1:
            ans.append("0")
            continue

        if b == 0 and c == 0:
            if a > 0 and d == 0:
                ans.append("1")
            elif d > 0 and a == 0:
                ans.append("1")
            else:
                ans.append("0")
            continue

        if b == c:
            x = b
            cur = comb(a + x, x) * comb(d + x - 1, x - 1)
            cur += comb(a + x - 1, x - 1) * comb(d + x, x)
            ans.append(str(cur % MOD))
        elif b == c + 1:
            x = b
            ans.append(str(comb(a + x - 1, x - 1) * comb(d + x - 1, x - 1) % MOD))
        else:
            x = c
            ans.append(str(comb(a + x - 1, x - 1) * comb(d + x - 1, x - 1) % MOD))

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```前処理の前に必要な階乗の最大サイズを知ることができるように、最初に入力が収集されます。 すべての組み合わせでは隣接するペアの合計数から導出される値が使用されるため、テスト ケースごとに 1 つの階乗テーブルで十分です。 

の`comb`関数は無効な選択に対してゼロを返します。 これにより、数式で不可能な数の実行が要求された場合に個別のチェックを行う必要がなくなります。 

の`b=c=0`これらの式には次のような用語が含まれるため、分岐は他の式より前に処理されます。`C(x-1,x-1)`と`x=0`、これは実際の非移行状況を表すものではありません。 

コードの残りの部分は、実行カウントのケースに直接続きます。 数式は乗算モジュロを使用します`10^9+7`、Python 整数はオーバーフローの問題を回避します。

 ## 特殊なケース

 のために`3 0 0 0`、アルゴリズムは非遷移分岐に入ります。 以来`00`ペアが存在する場合、文字列はすべてゼロである必要があります。 ゼロの数は`4`、生産`0000`、したがって、答えは次のとおりです`1`。 

のために`0 0 3 0`、アルゴリズムは最初に遷移バランスをチェックします。 The difference between`b`そして`c`は`3`、1より大きいです。 バイナリ文字列にはそれ以上 3 つを含めることはできません`10`よりも移行`01`遷移するので、答えはすぐにわかります`0`。 

のために`1 1 1 1`、遷移数が等しいということは、可能な開始文字が 2 つあることを意味します。 最初のケースでは 0 が 2 つの実行に分割され、1 が 1 つの実行に分割されますが、2 番目のケースではその逆が行われます。 2 つのケースが寄与する`2`それぞれの正しい合計を求めます。`4`。 

のために`0 2 1 0`、遷移の差は 1 であるため、文字列は 0 で始まり 1 で終わる必要があります。 ゼロランが 2 つと 1 ランが 2 つあり、各シンボル カウントには可能な正の分割が 1 つだけあり、厳密に 1 つの文字列が得られます。
