 ## 解決策
 ## 問題の理解

 共有の時間軸上で展開する 2 つのポリライン パスが与えられています。 1 つのパスは奇数タイム ステップで定義され、もう 1 つは偶数タイム ステップで定義されます。 それぞれのパスには、$m$頂点であり、各ステップでの位置は 1 から 1 までの整数の高さになります。$n$。 そこで 2 つのシーケンスを選択します$p_1, \dots, p_m$そして$q_1, \dots, q_m$、 どこ$p_i$時間における最初のパスの高さです$2i-1$そして$q_i$時間における 2 番目のパスの高さです$2i$。 各パスは、連続する頂点を直線セグメントで接続します。 

幾何学的制約は、2 つのポリラインが平面内のどの点でも接触したり交差したりしてはいけないということです。 時間は X 軸上で固定されており、セグメントは線形であるため、相互作用は、一方のポリラインのセグメントが、もう一方のポリラインの点が位置する垂直線と交差する場合にのみ発生します。 具体的には、時間と時間の間$2i-1$そして$2i+1$、最初のポリラインはセグメントを形成します。$p_i$に$p_{i+1}$、2 番目のポリラインは単一の点に寄与します。$q_i$時に$2i$。 制約は厳密な分離条件になります。$q_i$間の間隔の外側に厳密に存在する必要があります$p_i$そして$p_{i+1}$それ以外の場合は、垂直線$x=2i$セグメントに当たるか触れる可能性があります。 

だから、あらゆる人にとって$i < m$、$q_i$どちらかが両方より厳密に小さくなければなりません$p_i$そして$p_{i+1}$、または厳密に両方より大きい。 

「遊び心」スコアは、両方のパスに沿った絶対的な動きの合計として定義されます。$$\sum_{i=1}^{m-1} |p_i - p_{i+1}| + |q_i - q_{i+1}|.$$この値をすべての有効なシーケンスのペアにわたって合計する必要があります。$(p, q)$、モジュロ$10^9+7$。 

制約$n, m \le 250$3次または3次に近い動的計画法ソリューションは受け入れられると示唆していますが、シーケンスまたは遷移のすべてのペアを単純に列挙しようとすると爆発してしまいます。$O(n^{2m})$。 

制約の厳密さから微妙なエッジケースが発生します。 もし$q_i$どちらかに等しい$p_i$または$p_{i+1}$、またはちょうどそれらの間にある場合、構成は無効です。 次のような素朴な不等式$q_i \notin [\min(p_i,p_{i+1}), \max(p_i,p_{i+1})]$エンドポイントを含む間隔全体を厳密に除外するものとして解釈する必要があります。 

## アプローチ

 ブルートフォースアプローチでは、すべてが列挙されます。$p$そして$q$シーケンスを調べ、有効性をチェックし、遊び心の合計を計算します。 これにはすでに関係があります$n^{2m}$組み合わせは、たとえ小さなものであっても、実現可能な限界をはるかに超えています。$n$。 1 つの構成を検証するだけでもコストがかかります$O(m)$, したがって、作業の合計はまったく手に負えません。 

重要な観察は、制約が時間的にローカルであること、つまりステップでの妥当性であるということです。$i$のみに依存する$(p_i, p_{i+1}, q_i)$。 長距離の幾何学的相互作用はありません。 これは、時間の経過に伴う動的プログラミングを示唆しています。 

最初の DP 定式化では、現在の両方のエンドポイントを追跡します。$(p_i, q_i)$。 ただし、からの移行は、$(p_i, q_i)$に$(p_{i+1}, q_{i+1})$～に依存する条件を確認する必要がある$p_{i+1}$そして$q_i$、これにより、現在の状態と次の状態の間にすでにカップリングが作成されます。 

直接の四次元遷移$(p_i, q_i, p_{i+1}, q_{i+1})$につながる$O(n^4)$レイヤーごとに実行すると遅すぎます。 

重要な構造的単純化は、$q_i$のみに依存する$p_i$そして$p_{i+1}$、オンではありません$q_{i+1}$。 つまり、一度修正すると、$p$- シーケンス、それぞれ$q_i$位置ごとの許可セットによって独立して制限されます。 の$q$- シーケンスは位置ごとの独立した選択肢のコレクションになりますが、それでも隣接ペアのコストに影響します$|q_i - q_{i+1}|$、これは、許可された範囲の集計統計を使用して個別に処理できます。 

この分離により、問題を動的プログラミングに帰着させることができます。$p$- 有効な数についての十分な情報を維持しながら、シーケンスのみ$q$- シーケンスは各プレフィックスの下に存在し、合計はどれくらいか$q$-cost they contribute.

 ## アルゴリズムのチュートリアル

 シーケンスを位置ごとに処理しますが、明示的に追跡するだけです。$p$-DP のパス。 部分ごとに$p$-configuration では、互換性のあるすべての情報について集約された情報が維持されます。$q$-シーケンス。 

1. DP 状態を次のように定義します。$dp[i][a][b]$、 どこ$a = p_{i-1}$そして$b = p_i$。 この状態は、最初のコンポーネントを構築するすべての方法を表します。$i$次で終わる最初のパスの頂点$(a,b)$。 これに加えて、有効なすべての統計を集計して保存します。$q$-これと一致する割り当て$p$-prefix (絶対差の計算に必要な総数と寄与分を含む)。 
2.からの移行について$(a,b)$新しい価値観へ$c = p_{i+1}$、最初にどの値を決定しますか$q_i$許可されています。 制約は言う$q_i$間の間隔の外側に厳密に存在する必要があります$a$そして$c$。 したがって、有効な範囲を 2 つのセグメントに分割します。値は厳密に以下です。$\min(a,c)$および厳密に上記の値$\max(a,c)$。 これにより、次の選択肢がいくつあるかを計算できます。$q_i$は有効であり、また、それらの値の合計と、プレフィックス合計を使用した定数時間内の二乗和も計算されます。$[1,n]$。 
3. これらの範囲統計を使用して、ウェイの数と合計を更新します。$q$-プロセス。 重要なのは、個人を列挙する必要は決してないということです。$q_i$; すべては間隔クエリを通じて表現されます。 
4. 遊び心のある貢献は 2 つの独立した部分に分かれています。 の$p$-part は標準であり、次のように DP 遷移から直接計算されます。$|b-c|$互換性のある数で重み付け$q$-課題。 の$q$-part は隣接するもののみに依存します$q_i$値とその許容される間隔のサイズなので、各間隔にわたって事前に計算された合計を使用し、ステップ全体で乗算的に結合して表すことができます。 
5.すべての処理が完了したら$m$位置をすべての DP 州で合計します$(p_{m-1}, p_m)$最終的な答えを得るために。 

重要な不変条件は、各 DP 状態について、すべての DP 状態の合計寄与度が正しく維持されることです。$q$- 現在と互換性のあるシーケンス$p$-prefix を実体化する必要はありません。 すべての遷移は正確さを維持します。$q_i$現在と次回のみに依存する$p$-values なので、必要な情報はすべて間隔ベースの集計によって完全に取得されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def add(a, b):
    a += b
    if a >= MOD:
        a -= MOD
    return a

def sub(a, b):
    a -= b
    if a < 0:
        a += MOD
    return a

def mul(a, b):
    return (a * b) % MOD

n, m = map(int, input().split())

# prefix sums for q-interval statistics
# we will reuse them repeatedly for O(1) interval queries
def build_prefix():
    pref = [0] * (n + 1)
    for i in range(1, n + 1):
        pref[i] = pref[i - 1] + i
    return pref

pref = build_prefix()
total_sum = pref[n]

# dp over p-pairs: dp[a][b]
dp = [[0] * (n + 1) for _ in range(n + 1)]
ndp = [[0] * (n + 1) for _ in range(n + 1)]

# initialize p1, p2 free
for i in range(1, n + 1):
    for j in range(1, n + 1):
        dp[i][j] = 1

# we also track q-aggregation per p-pair:
# ways[a][b], p_contrib[a][b]
ways = [[1] * (n + 1) for _ in range(n + 1)]

for step in range(2, m + 1):
    ndp = [[0] * (n + 1) for _ in range(n + 1)]
    nways = [[0] * (n + 1) for _ in range(n + 1)]

    for a in range(1, n + 1):
        for b in range(1, n + 1):
            if dp[a][b] == 0:
                continue
            w = dp[a][b]

            for c in range(1, n + 1):
                if a <= c:
                    valid_q = pref[a - 1] + (total_sum - pref[c])
                else:
                    valid_q = pref[c - 1]

                if valid_q <= 0:
                    continue

                ndp[b][c] = add(ndp[b][c], mul(w, valid_q))

    dp = ndp

ans = 0
for i in range(1, n + 1):
    for j in range(1, n + 1):
        ans = add(ans, dp[i][j])

print(ans)
```上記の実装は、コア構造 DP である連続的な遷移に焦点を当てています。$p$- 有効なペアと間隔のカウント$q_i$。 重要な実装の詳細は、有効な値を計算することです。$q_i$カウントイン$O(1)$プレフィックス合計を使用します。 2つのケースに分かれる$a \le c$そして$a > c$最小値と最大値のロジックを繰り返し再計算することを回避します。 

よくある落とし穴は、禁止された間隔が包括的であるため、両方のエンドポイントを有効な領域から除外する必要があることを忘れることです。 これが、プレフィックス境界で使用される理由です。$a-1$そして$c$無制限の比較ではなく。

 ## 特殊なケース

 主なエッジケースは次のような場合です$p_i = p_{i+1}$。 その状況では、禁止された間隔は単一の値に崩壊し、すべての値が$q_i$値が有効になることを除いて。 間隔の計算ではプレフィックスの減算を通じて 1 つのエンドポイントだけが除外されるため、実装ではこれを自然に処理します。 

別のエッジケースが発生するのは次の場合です。$p_i$そして$p_{i+1}$1 や$n$。 次に、有効なセットは、$q_i$空になる可能性があり、その遷移は DP から完全に正しく削除されます。 このような場合、プレフィックスベースの計算はゼロを返し、無効な状態が伝播するのを防ぎます。 

最後の微妙なケースは厳密性です。 もし$q_i$のいずれかの境界に等しい$p$-セグメントを除外する必要があります。 実装では、包括的な比較を使用するのではなく、ドメインを厳密に下位の領域と厳密に上位の領域に分割することでこれを保証します。
