 ## 解決策
 ## 問題の理解

 複数の独立したシナリオが与えられます。 各シナリオには、S のラベルが付いているバルーン、Y のラベルが付いているバルーン、および U のラベルが付いているバルーンの 3 種類のバルーンがあります。これらのバルーンから、SYSU セットと呼ばれる同一の装飾バンドルを繰り返し組み立てたいと考えています。 

有効な SYSU セットは固定パターンの文字を使用します。つまり、2 つの S バルーン、1 つの Y バルーン、および 1 つの U バルーンが必要です。 各バルーンは最大 1 回使用できるため、バルーンがセットに割り当てられると、別のセットで再利用することはできません。 

各テスト ケースのタスクは、利用可能な S、Y、および U バルーンの数から完全な SYSU セットをいくつ形成できるかを決定することです。 

制約は小さく、テスト ケースは最大 100 件、それぞれのカウントは最大 10,000 件です。 これは、テスト ケースごとに一定時間で実行されるソリューションであれば、簡単に十分であることを示唆しています。 テスト ケースごとに O(x + y + z) であってもまだ簡単ではありませんが、直接的な算術解を目指す必要があります。 

このような問題でよくある間違いは、S の 2 倍の要件を無視して、各文字が独立して寄与すると仮定することです。もう 1 つの微妙な問題は、3 つのリソースすべてが同時に利用可能である必要があることを忘れていることです。そのため、制限要因が常に最も制約される要素になります。 

エッジケースはほとんどが縮退カウントです。 x、y、z のいずれかが 0 の場合、集合を形成できません。 もう 1 つの興味深い境界は、S が豊富であるが Y または U が少ない場合、またはその逆の場合です。 たとえば、x = 100、y = 1、z = 1 の場合、S がたくさんあるように見えても、可能なセットは 1 つだけです。 逆に、y と z が大きく S が小さい場合は、1 セットに 2 回必要になるため、S がボトルネックになります。 

## アプローチ

 この問題を考える強引な方法は、構築セットを 1 つずつシミュレートすることです。 試行ごとに、少なくとも 2 つの S バルーン、1 つの Y バルーン、および 1 つの U バルーンが利用可能かどうかを確認します。 そうであれば、それらのカウントを減算し、答えを増分します。 セットを形成できなくなるまで繰り返します。 

このアプローチはプロセスの定義に直接従うため、正しいです。 ただし、そのパフォーマンスは形成されるセットの数に依存します。 最悪の場合、x、y、z が大きい場合、テスト ケースごとに最大 10,000 回繰り返し減算する可能性があります。 テスト ケースが 100 個あるため、これはここでも許容できますが、これは不必要であり、問​​題の実際の構造を隠してしまいます。 

重要な観察は、各セットが以前の選択とは無関係に固定リソースを消費するということです。 ステップ間での結合や再配置の利点はありません。 これは、セットの最大数が純粋に各リソースが必要な使用量をサポートできる回数によって決まることを意味します。 S は x // 2 によって制限され、Y は y によって制限され、U は z によって制限されます。 最終的な答えはすべての制約を同時に満たす必要があるため、これら 3 つの独立した容量の最小値になります。

 ## アルゴリズムのチュートリアル

1. 各テスト ケースについて、値 x、y、z を読み取ります。 これらはそれぞれ、S、Y、U バルーンの利用可能な数量を表します。 目標は、これらの固定電源から完全な SYSU バンドルをいくつ形成できるかを計算することです。 
2. S バルーンが単独でサポートできるバンドルの数を計算します。 各バンドルには 2 つの S バルーンが必要であるため、S からの可能な寄与の数は、整数除算を使用して x を 2 で割った数になります。 これは、他の制約を考慮せずに S が維持できるセットの最大数を表します。 
3. y をセット数の直接の上限として扱います。 各セットには Y バルーンが 1 つだけ必要なため、セット数が y を超えることはできません。 
4. z を別の直接の上限として扱います。 各セットには U バルーンが 1 つだけ必要なため、z は可能なセットの総数も制限します。 
5. すべての有効なセットは 3 つの制約すべてを同時に満たす必要があり、いずれかのリソースを超えるとそれ以上の構築が不可能になるため、最終的な答えはこれら 3 つの値の最小値になります。 

### なぜ効果があるのか

 各 SYSU セットは、リソースを独立して不可逆的に消費します。 これは、k 個のセットを形成する実現可能性は、必要なリソースの合計、つまり 2k 個の S バルーン、k 個の Y バルーン、および k 個の U バルーンが利用可能かどうかによってのみ決まることを意味します。 したがって、実現可能性の条件は 2k ≤ x、k ≤ y、および k ≤ z です。 すべての不等式を満たす最大の k は、まさに x // 2、y、z の最小値であり、シミュレーションを必要とせずに最適性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        x, y, z = map(int, input().split())
        out.append(str(min(x // 2, y, z)))
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装では、数学的な実現可能性の条件がコードに直接変換されます。 整数除算 x // 2 は、S バルーンのペアリング要件を捉えます。 計算された 3 つの制限値の最小値を取ると、すべての制約が同時に適用されます。 リストと結合によるバッファリングされた出力の使用により、繰り返しの I/O オーバーヘッドが回避されますが、この規模では厳密には必要ありません。 

## 実用的な例

 ### 例 1

 入力:

 x = 10、y = 2、z = 4

 | ステップ | x // 2 | y | z | 現在の回答 |
 | --- | --- | --- | --- | --- |
 | 初期計算 | 5 | 2 | 4 | - |
 | 最小値をとる | - | - | - | 2 |

 これは、Y が制限要因である場合を示しています。 S と U はより多くのセットに十分ですが、Y バルーンは 2 つしか存在しないため、合計が 2 つの完全なバンドルに制限されます。 

### 例 2

 入力:

 x = 11、y = 45、z = 14

 | ステップ | x // 2 | y | z | 現在の回答 |
 | --- | --- | --- | --- | --- |
 | 初期計算 | 5 | 45 | 14 | - |
 | 最小値をとる | - | - | - | 5 |

 ここでSがボトルネックになるのは、1セットに2回必要となるためです。 Y と U が豊富であっても、S の完全なペアは 5 つしか形成できません。 

これらのトレースは、答えが常に 3 つの独立したリソースの中で最も厳しい制約によって制御されていることを示しています。 

## 複雑さの分析

 ## 特殊なケース

 x が 2 未満の場合、x // 2 がゼロになるため、アルゴリズムは正しくゼロを生成し、y または z に関係なく、可能な形成を即座にブロックします。 たとえば、「1 10 10」と入力すると、x // 2 = 0 が得られるため、答えは 0 になります。これは、2 つの S バルーンがなければ SYSU セットを形成できないという事実と一致します。 

y または z のいずれかが 0 の場合、S 個のバルーンが豊富であっても、最小限の演算により結果が 0 になることが保証されます。 たとえば、入力 100 0 100 は min(50, 0, 100) = 0 を生成し、すべてのセットが Y と U の両方を同時に必要とすることを正しく反映しています。 

10000 1 1 など、S が非常に大きいがペアの制約が優勢な場合、計算は min(5000, 1, 1) = 1 に減少し、シミュレーションなしでボトルネックが正しく特定されたことがわかります。
