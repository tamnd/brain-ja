 ## 解決策
 ## 問題の理解

 いくつかの独立したテスト ケースが与えられています。 各テスト ケースは一連の整数を記述し、各要素は音楽のスライスの「リズム値」を表します。 固定の下限 L もあります。各要素を個別に減らすことはできますが、L を下回ることはできません。この変更後、部分全体の美しさは、すべての最終値のビット単位の OR として定義されます。 

タスクは、最終的な OR ができるだけ大きくなるように、許容範囲内のすべての要素に対して新しい値を選択することです。 

問題を言い換えると便利な方法は次のとおりです。各位置 i は、制御可能な値の間隔 [L, ai] を与えます。 各間隔から 1 つの数値を選択する必要があり、選択したすべての数値のビット単位の OR を最大化する必要があります。 

制約は大きく、テスト ケース全体の要素の合計数は 2×10^5 に達し、値は最大 2^60 に達します。 これにより、すべての割り当てを試行したり、要素ごとの値のすべての組み合わせを試行したりするソリューションは即座に除外されます。 テストケースごとに二次関数であっても遅すぎます。 

操作の構造も重要です。 OR 演算は、選択した値のビットが 1 になると、最終的な答えでは 1 のままであるという意味で単調です。 したがって、本当の問題は、少なくとも 1 つの選択された数値にどのビットを出現させることができるかを決定することです。 

いくつかの危険な状況については注意する価値があります。 

すべての ai が L に等しい場合、すべての間隔は 1 つの点に集約され、変更は不可能であるため、答えは単純にすべての ai の OR になります。 

L が 0 の場合、すべての間隔は [0, ai] になり、ai までの任意の値を自由に選択できます。 これは最も柔軟なシナリオですが、それでも上限による制約があります。 

L = 8 および ai = 9 など、間隔が狭い場合には、より微妙なケースが発生します。ai が小さい場合でも、間隔が短すぎて望ましいビット パターンに「到達」できない可能性があります。 ここで、「ビットはいつでも個別に調整できる」といった素朴な推論が崩れます。 

## アプローチ

 ブルートフォースの観点は、要素ごとに考えることから始まります。各 AI について、[L, ai] の任意の bi を選択できます。 すべての選択肢を列挙する場合は、OR を計算して最大値を取得します。 各要素がさまざまな可能性をもたらし、サンプリング値であっても組み合わせが爆発的に増加するため、これは明らかに n において指数関数的です。 

より構造化されたブルートフォースは、それぞれのバイを貪欲に決定しようとしますが、その場合でも、OR はすべての選択肢を結合するため、要素間の依存関係を考慮する必要があります。 ビット寄与のすべてのサブセットを試してみると、すぐに O(2^60) スタイルの推論が導かれますが、これは不可能です。 

重要な観察は、完全な数を直接推論する必要がないということです。 各ビットが少なくとも 1 つの選択された値に現れるかどうかだけを気にします。 そこで、視点を値からビットに移します。 

b. ビット位置を固定します。 もっと単純な質問をします。要素 i を少なくとも 1 つ選択し、それに [L, ai] の値を割り当てて、b 番目のビットが 1 になるようにすることはできますか?

 「はい」の場合、このビットが最終的な答えに貢献します。 「いいえ」の場合、このビットは不可能であり、結果では 0 でなければなりません。 

したがって、問題は各ビットをどこかに出現させる実現可能性をチェックすることに帰着します。 

ここで、2進数の構造が重要になります。 固定ビット b の場合、整数上のそのビットのパターンは周期的です。サイズ 2^(b+1) のブロックで、前半が 0、後半が 1 です。この周期構造により、区間 [L, ai] にビット b = 1 の数値が含まれているかどうかを判断できます。 

与えられた i に対して、ビット b が [L, ai] にまったく現れない唯一の方法は、区間全体がビット b が常に 0 である領域内にある場合です。これは、両方の端点が周期ブロックの同じ「ゼロの半分」内にあり、「半分」に交差しない場合に正確に発生します。

したがって、ビットごとに、間隔がゼロのみの領域内に完全に閉じ込められていない i が少なくとも 1 つ存在するかどうかを確認するだけで済みます。 そのような i が存在する場合、そのビットは達成可能です。 

これにより、問題は O(n · 60) に軽減され、十分に高速になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 割り当てに対するブルートフォース | 指数 | お(1) | 遅すぎる |
 | 間隔にわたるビットごとの実現可能性 | O(n log A) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. 0 から 59 までの各ビット位置 b について、最初はこのビットを最終応答の一部にすることはできないと仮定します。 
2. 固定ビット b の場合、ブロック サイズ P = 2^(b+1) を計算します。 これにより、すべての整数が繰り返しセグメントに分割され、各セグメントはゼロの半分 [0, 2^b - 1] と半分の [2^b, 2^(b+1) - 1] で構成されます。 
3. 各要素 i について、区間 [L, ai] がビット b のゼロハーフ領域内に完全に含まれているかどうかを確認します。 これは、L と ai の両方が同じブロック内にある場合 (つまり、L // P == ai // P)、両方がそのブロックの前半にある場合 (つまり、L % P < 2^b および ai % P < 2^b) に当てはまります。 これが発生すると、この間隔から選択できるすべての値のビット b は 0 に等しいため、この要素はビット b の設定に寄与できません。 
4. この条件が満たされないインデックス i が少なくとも 1 つ見つかった場合は、ビット b をアクティブにする値が [L, ai] に存在するため、ビット b を達成可能としてマークします。 
5. このビットのすべての要素を処理した後、それが達成可能であれば、答えに 2^b を追加します。 
6. すべてのビットに対して繰り返し、累積された OR 値を出力します。 

単一の間隔をチェックする背後にある理由は、OR にはビットごとに 1 つの成功要因のみが必要であるためです。 同じビットに対して複数の要素を調整する必要はありません。 

### なぜ効果があるのか

 各要素は、選択可能な値の連続的な間隔に寄与します。 固定ビットの場合、唯一の障害は、その間隔がビットが常に 0 である領域に完全に含まれる場合です。 1 つの要素でもそのビットが設定された到達可能な値を持っている場合は、実現可能性に影響を与えることなく、その値をその要素に割り当て、他の要素に任意の有効な値を割り当てることができます。 したがって、ビットの独立性が保持され、ビットごとの存在をチェックするだけで最適な OR を構築できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n, L = map(int, input().split())
        a = list(map(int, input().split()))
        
        ans = 0
        
        for b in range(60):
            P = 1 << (b + 1)
            half = 1 << b
            
            ok = False
            
            for x in a:
                if (x - L) >= 0:
                    # check if there exists a way to get bit b = 1 in [L, x]
                    # impossible only if both endpoints lie in zero half of same block
                    if (L // P == x // P) and (L % P < half) and (x % P < half):
                        continue
                    ok = True
                    break
            
            if ok:
                ans |= (1 << b)
        
        print(ans)

if __name__ == "__main__":
    solve()
```このコードは、ビットごとの実現可能性テストを反映しています。 各ビットについて、そのビットが設定された値を生成できる 1 つの間隔が見つかるまで、すべての要素がスキャンされます。 そのような要素が見つかった瞬間にビットが確認され、効率化のために早めに停止します。 

重要な実装の詳細は、ビットごとの間隔分類です。数値をサイズ 2^(b+1) のブロックにグループ化し、両方のエンドポイントが同じブロックのゼロ部分に含まれるかどうかを確認します。 

## 実用的な例

 小さなケースを考えてみましょう。 

入力:

 n = 3、L = 4

 a = [6, 5, 9]

 少しずつ評価していきます。 

| ビット | P | 有効な要素はありますか? | 結果 |
 | --- | --- | --- | --- |
 | 0 | 2 | はい (例: 5、9) | 1 |
 | 1 | 4 | はい (例: 6、5) | 1 |
 | 2 | 8 | はい (例: 9) | 1 |
 | 3+ | - | いいえ | 0 |

 したがって、答えは7です。 

これは、異なる要素がどのように異なるビットを独立して提供するかを示しています。 

次に、制限的なケースを考えてみましょう。 

入力:

 n = 2、L = 8

 a = [9, 10]

 ビット 3 (値 8) の場合、可能な値は L より上の小さな間隔のみです。どちらの間隔でも、そのビットの 0 のみの領域を一貫してエスケープすることができないため、ビット 3 は構造によってはブロックされる可能性があります。 ただし、下位ビットは、間隔が周期ブロックの両方の半分にまたがっているため、簡単に達成できます。 

| ビット | 観測された実現可能性 | 結果 |
 | --- | --- | --- |
 | 0-2 | 達成可能 | 1 |
 | 3 | 間隔構造に依存します | 0/1 |

 これは、答えが大きさだけではなく間隔の調整にどのように依存するかを示しています。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、L と ai が上位ビットの同じゼロビット セグメント内にある場合です。 このような状況では、その要素からそのビットをアクティブにすることはできません。 両方のエンドポイントが同じブロックに到達し、どちらも中間点よりも下にあるため、アルゴリズムはこれを正しく処理し、スキップ条件をトリガーします。 

もう 1 つのエッジ ケースは、L = ai の場合です。 ここでは、すべての間隔が単一点に縮退するため、その固定値にすでにビットが含まれていない限り、実行可能性チェックは常に失敗します。 アルゴリズムは当然ながら、元の値の OR をチェックすることになります。 

3 番目のケースは、L が非常に小さく、ai が非常に大きい場合です。 この場合、各間隔が複数の周期ブロックにまたがるため、各間隔の少なくとも 1 つの値が任意のビットをアクティブにするため、ほとんどのビットは自明に達成可能です。 スキャンは有効な要素を迅速に見つけて、すべての下位ビットと中位ビットを設定し、予想される最大の OR に一致します。
