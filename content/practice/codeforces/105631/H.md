 ## 解決策
 ## 問題の理解

 刑務所のような迷路を表すグラフが与えられました。 K が始まる特別な開始ノード、ホッパーと呼ばれるノードのセット、およびドアと呼ばれる別のノードのセットがあります。 残りの構造は、すべてのノードを接続する無向グラフです。 重要な制約は、ドア ノードが鍵のかかった部屋のように動作することです。K は、対応するキーがすでに取得されていない限り、ドア ノードに入ることができません。 

ドアと同じ数の鍵があり、各鍵は 1 つのドアに一意に関連付けられています。 各キーは 1 つのホッパー ノードにのみ配置されます。 K がホッパーに到達すると、そこに保存されているすべてのキーを取得し、それらのキーは対応するドアのロックを永久に解除します。 

このタスクは、K がノード 1 から開始してグラフ内を移動し、訪問したホッパーからキーを収集し、最終的にすべてのドア ノードに到達して開き、グラフ全体を横断可能にすることができるように、m 個の異なるキーを n 個のホッパー ノードに割り当てる方法が何通りあるかを数えるというものです。 

重要な点は、到達可能性は時間の経過とともに変化するということです。 ドア ノードは、そのキーが見つかるまでトラバースをブロックします。また、そのキー自体が他のドアの背後にある可能性があるため、ドアにアクセスできるようになる順序は、グラフ構造とキーが配置される場所の両方に依存します。 

制約は小さく、n と m は最大 11 であるため、ドアのサブセットにわたる状態の総数は最大 2048 です。これは、ドアのサブセットにわたる列挙と順列にわたる動的計画法を含むあらゆる解決策が実行可能であることを強く示唆していますが、m を超える指数関数は大きすぎます。 特に、すべての代入を直接反復すると n^m になりますが、これは概念分岐の観点からは n = 11 および m = 11 であっても大きすぎるため、ソリューションでは代入ごとの推論を明示的に回避し、代わりに組み合わせ的に集約する必要があります。 

よくある失敗例は、ドアのアクセシビリティと以前に開いたドアとの間の依存関係を無視したことに起因します。 

たとえば、ホッパーを含む領域へのすべてのパス上にドアがある場合、「グラフが接続されていればどんな代入も機能する」という単純な仮定はすぐに崩れます。 ノード 2 がドア、ノード 3 がホッパーで、1 が 2 を介してのみ接続されて 3 に到達するグラフでは、ノード 1 から 2 を経由せずに到達可能なホッパーにドア 2 のキーがまだ存在していない場合、構成は無効になります。 ロック効果を無視する単純な到達可能性チェックでは、そのような割り当てが誤ってカウントされてしまいます。 

もう 1 つの落とし穴は、キー間の独立性を前提とすることです。 各キーが独立してホッパーに配置されている場合でも、キーが使用できるかどうかは、そのドアが必要なときにそのホッパーに到達できるかどうかによって決まります。これは、以前に開いたドアに依存します。 これにより、無視できない順序付けの制約が生じます。 

## アプローチ

 ブルートフォース解釈は簡単です。 m 個の異なるキーを n 個のホッパーに割り当てられる可能性があるすべてを試します。 割り当てごとに、K がノード 1 から始まるすべてのドアを開けることができるかどうかをシミュレーションします。そのシミュレーション自体には、いくつかのノードがロックされているグラフ内の到達可能性を繰り返し計算し、キーが見つかったときに動的にロックを解除する必要があります。 到達可能性チェックが最適化されたとしても、割り当ての数だけでも n^m であり、最悪のケースでは 11^11 となり、実現可能な制限をはるかに超えています。 

重要な観察は、プロセスの構造は、どのドアがどのように開かれたかの正確な履歴ではなく、どのドアがすでに開かれたかによってのみ依存するということです。 ドアのサブセットが開くと、ノード 1 から到達可能なノードのセットが明確に定義され、決定論的に計算できます。 これは、すべての動的動作をドアのサブセットにわたる関数に圧縮できることを意味します。

最初に割り当ての観点から考えるのではなく、視点を逆転させます。 ドアが開く順序を修正します。 このような順序の場合、開いたドアのプレフィックスに到達すると、グラフ内の到達可能な領域は固定されます。 ドアのキーは、ドアが注文で処理される時点で、到達可能な領域にあるホッパーに配置する必要があります。 

これにより、問題はドアのすべての順列の合計に変換され、各順列がプレフィックスに依存する到達可能なホッパー数の積に寄与します。 この構造は、順列に対するサブセット動的プログラミングに適しています。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | シミュレーションによる割り当てに対するブルート フォース | O(n^m · (n+m) · r) | O(n+m+r) | 遅すぎる |
 | 到達可能性の事前計算を使用したドア順列のサブセット DP | O(2^m · (r + m·2^m)) | O(2^m + r) | 承認済み |

 ## アルゴリズムのチュートリアル

 各ドアのサブセット S をエンコードし、S のドアが開いているとみなされるときにグラフのどの部分に到達できるかを事前計算します。 

1. ドアのサブセット S ごとに、BFS または DFS を使用してノード 1 から到達可能なノードのセットを計算します。 この横断中、ホッパー ノードは自由に通過できますが、ドア ノードは S に含まれる場合にのみ通過できます。これにより、到達可能領域 R(S) が生成されます。 

これが機能する理由は、どのドアが開いているかを修正すると、グラフがいくつかのブロックされた頂点が削除された標準の無向グラフになるため、到達可能性が明確に定義されるためです。 

1. 各サブセット S について、R(S) 内のホッパー ノードの数 f(S) を計算します。 これは、S のドアがすでに開いた後に、対応するドアが次に開くドアである場合に、キーを配置するための有効な選択肢がいくつ存在するかを表します。 
2. 動的プログラミング テーブル dp[S] を定義します。ここで、S は、何らかの開閉順序ですでに選択されているドアのセットを表します。 dp[S] は、S のドアを正確に開くすべての順列の合計寄与度を格納します。寄与度は、各ステップで到達可能な選択肢に従って蓄積されます。 
3. 空の順序が 1 つだけ存在するため、dp[empty set] = 1 を初期化します。 
4. すべてのサブセット S を繰り返します。S にないドア x ごとに、S2 = S Union {x} を計算します。 S2 で終わる順列は、次のドアとして x を選択して S で終わる順列を拡張することによって形成できます。 x が開かれるとき、正確に S2 のドアはすでに開いているため、この拡張の寄与は f(S2) で乗算されます。 
5. このような遷移ごとに dp[S2] += dp[S] * f(S2) を累積します。 
6. すべての完全な順列が到達可能な選択肢の完全な積に寄与するため、最終的な答えは dp[すべてのドア] です。 

### なぜ効果があるのか

 DP の不変条件は、dp[S] が S のドアを順序付けるすべての可能な方法をすでに集約しており、そのような順序のそれぞれが、すべてのプレフィックスでの到達可能なホッパー数に対応する正しい累積乗算重みを保持していることです。 f(S) はすでに開かれたドアのセットのみに依存し、その順序には依存しないため、新しいドア x によって S の有効な順序を拡張すると、次の因数 f(S ∪ {x}) が曖昧さなく正しく追加されます。 これにより、すべての順列が正しい重みで正確に 1 回カウントされることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n, m, r = map(int, input().split())
    N = n + m
    
    adj = [[] for _ in range(N)]
    for _ in range(r):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        adj[u].append(v)
        adj[v].append(u)

    hoppers = set(range(1, n + 1))
    doors = list(range(n + 1, n + m + 1))
    door_idx = {doors[i]: i for i in range(m)}

    def reachable(mask):
        q = deque([0])
        vis = [False] * N
        vis[0] = True
        
        while q:
            u = q.popleft()
            for v in adj[u]:
                if vis[v]:
                    continue
                if v in hoppers:
                    vis[v] = True
                    q.append(v)
                else:
                    i = door_idx[v]
                    if (mask >> i) & 1:
                        vis[v] = True
                        q.append(v)
        return vis

    f = [0] * (1 << m)
    for mask in range(1 << m):
        vis = reachable(mask)
        cnt = 0
        for i in hoppers:
            if vis[i]:
                cnt += 1
        f[mask] = cnt

    dp = [0] * (1 << m)
    dp[0] = 1

    for mask in range(1 << m):
        if dp[mask] == 0:
            continue
        for i in range(m):
            if not (mask >> i) & 1:
                nmask = mask | (1 << i)
                dp[nmask] += dp[mask] * f[nmask]

    print(dp[(1 << m) - 1])

if __name__ == "__main__":
    solve()
```BFS ルーチンは、開いたドアの固定セットの下で到達可能性を構築します。 実装の重要な詳細は、ドアのビットがマスクに設定されていない限り、ドアをブロックされたノードとして扱うことです。 ホッパーは常にトラバース可能であるため、ホッパーはグラフの永続的な部分として機能します。 

DP 遷移はサブセットを昇順で反復することに依存するため、すべての dp[mask] は使用時にすでに確定されています。 各遷移には、f[mask] ではなく f[nmask] が乗算されます。これは、次のドアが開いたとみなされた後、そのドアのキーが到達可能な領域に存在する必要があるためです。

 | --- | --- | --- |
 | 00 | なし | 初期接続に依存します |
 | 01 | ドア1 | 拡張領域 |
 | 10 | ドア2 | 拡張領域 |
 | 11 | 両方 | フルリーチ |

 DP は 2 つのドアにわたって順列を蓄積します。 空のセットから 2 つの選択肢に分岐します。それぞれの選択肢は、ドアを開けた後に到達可能なホッパーの数によって重み付けされます。 両方の注文を処理した後、最終合計では両方の順列とそれぞれの到達可能性制約が集計され、有効な割り当ての合計が生成されます。 

これは、グラフ構造が同じであっても、ドアの順序が異なると到達可能なセットが異なり、有効なキー配置の数が直接変化することを示しています。 

### 例 2

 入力:```
3 3
1-5-6 structure with multiple cross links
```ここでの重要な動作は、一部のドアは他のドアを開いた後にのみ到達可能になるため、特定の順列は初期にはゼロまたは小さな重みに寄与しますが、後でより大きな重みに寄与することです。 重要なドアが S に含まれると f(S) が急激に増加するため、DP はこれを自動的に捕捉します。 

トレースは、ドアがすべてのホッパーへのアクセスをブロックすると f(S) がゼロまたは小さくなるため、無効な初期開口部が自然に除外されることを確認します。

 ## 特殊なケース

 エッジ ケースの 1 つは、ドアがそれ自体を除くすべてのホッパーへのアクセスを完全にブロックしている場合に発生します。 この状況では、そのドアが順列の早い段階で開かれていない場合、そのプレフィックスに対する到達可能なホッパー セットは空になり、f(S) がゼロになり、それを遅らせるすべての順列が排除されます。 このようなサブセットは重みがゼロであり、それ以上伝播しないため、DP はこれを正しく処理します。 

もう 1 つのエッジ ケースは、特定のドアが開かれない限り、開始ノードがすべてのホッパーから隔離されている場合です。 空のマスクの BFS は、到達可能なホッパーをゼロにし、別のドアで始まる順列の寄与を即座にゼロにし、有効な開始オーダーのみが確実に生き残るようにします。 

最後のエッジケースは、グラフ構造内で複数のドアが交換可能である場合です。 DP では、各順序が個別に扱われるため、当然すべての順列が個別にカウントされますが、それらは同一の f(S) 値を共有するため、過大または過少カウントすることなく正しい乗法対称性が得られます。
