 ## 解決策
 ## 問題の理解

 記入するよう求められます$n \times m$までの正の整数を含む行列$10^9$。 任意の値の代わりに、各行と列は非常に具体的な集計制約を満たす必要があります。 

行ごとに$i$、その行のすべての要素の最小公倍数を取る場合、結果は正確に次のようになります。$a_i$。 列ごとに$j$、その列内のすべての要素の最大公約数を取る場合、結果は正確に次のようになります。$b_j$。 タスクは、そのような行列が存在するかどうかを判断し、存在する場合は構築することです。 

制約$n, m \le 1000$までを暗示$10^6$細胞。 セルごとに値を検索したり、ネストされた因子チェックで候補を繰り返し調整しようとするソリューションは、すでに限界に近づいています。 解決策は、問題を最大でも直接的な構築に帰着させる必要があります。$O(nm)$簡単な算術。 

重要な構造上の制約が、LCM と GCD の定義の中に隠されています。 LCM 制約により、行要素が行ターゲットの約数になるように強制されます。 GCD 制約により、列要素が列ターゲットの倍数になるように強制されます。 これら 2 つの方向は強く交差しており、誤ったアプローチのほとんどは、これらを独立して扱うことで失敗します。 

典型的な失敗例は、候補値が行の制約を満たしているが、列の GCD を破っている場合に発生します。 たとえば、行内のすべてのセルを設定しようとすると、$i$に等しい$a_i$、列の GCD は、次の GCD に折りたたまれます。$a_i$必要な と一致する代わりに$b_j$さんの。 逆に、列を次のように設定すると、$b_j$行がターゲットに到達できないため、行 LCM が中断されます。 

ソリューションは、すべてのセルが行と列の両方の要件に同時に適合するように、両方の制約を調整するかどうかにかかっています。 

## アプローチ

 強引なアイデアは、すべてのセルを変数として扱い、両方の制約を満たす値を同時に試行し、割り当てのたびにすべての行 LCM と列 GCD を繰り返し再計算することです。 セルごとに小さな候補値だけを試しても、再計算にコストがかかります$O(nm)$各セルは 2 つの独立したターゲットの因子の組み合わせに依存するため、検索スペースは爆発的に増加します。 これは、非常に小さなグリッドを超えるとすぐに実行不可能になります。 

重要な構造上の観察は、制約がセルごとに独立しているのではなく、分割可能な条件に分離できるということです。 LCM と GCD の定義から、すべてのセルは行ターゲットで分割する必要があり、列ターゲットで割り切れる必要があることがわかります。 これにより、問題がペアの互換性条件に変換されます。$(a_i, b_j)$。 これが認識されると、構築は簡単になります。列の制約を満たす基本行列から開始し、列構造を壊すことなく行ターゲットを選択的に「注入」します。 

現在の GCD の倍数の値を導入しても GCD が安定しているのに対し、行内の少なくとも 1 つの要素が行ターゲットを達成している限り LCM は安定しているため、この構築は機能します。

 ## アルゴリズムのチュートリアル

 まず、制約を単一セルの算術制限に変換します。$x_{i,j}$。 

1.固定列の場合$i$、行の最小公倍数は次のようになります。$a_i$したがって、その行のすべての要素は分割する必要があります$a_i$。 セルに存在しない素因数を持つ数値が含まれている場合、$a_i$、LCM は次の値を超えます$a_i$。 したがって、すべての$x_{i,j}$分けなければなりません$a_i$。 
2.固定列の場合$j$、GCD は$b_j$したがって、その列内のすべての要素は次の倍数でなければなりません。$b_j$。 エントリが次の要素で割り切れない場合$b_j$、GCD は以下に低下します。$b_j$。 したがって、すべての$x_{i,j}$で割り切れる必要があります$b_j$。 
3. 両方の条件を組み合わせると、すべてのセルが満たされる必要があります。$$b_j \mid x_{i,j} \mid a_i.$$これは直ちに実行可能条件を暗示します。$b_j$分けない$a_i$、その位置には有効な値が存在できないため、行列全体は不可能です。 
4. すべてのペアについて実現可能性が成立したら、すべてのセルをその列要件に設定して基本行列を構築します。$b_j$。 これにより、すべての列 GCD が少なくとも正しい候補であることが自動的に保証されます。 
5.行LCMを行ごとに修正するには$i$、単一の列を選択します$p_i$そのセルを次のように上書きします$a_i$。 これにより、その行が保証されます$i$以下に等しい値が含まれています$a_i$、行の LCM が正確になるように強制します。$a_i$。 
6. この上書きによって列 GCD が破壊されないことを確認する必要があります。 列内$p_i$、今ではほとんどが$b_{p_i}$値と 1 つの値$a_i$。 以来$b_{p_i} \mid a_i$、その列の GCD は残ります。$b_{p_i}$。 
7. 最後に、行列を出力します。 

### なぜ効果があるのか

 この構築では 2 つの不変条件が維持されます。 すべてのセルは常にその列ターゲットの倍数であるため、列の GCD がそれを下回ることはありません。$b_j$、そしてすべての列には依然として以下に等しい値が少なくとも 1 つ含まれています。$b_j$, したがって、GCD は増加できません。 行の場合、各行には以下に等しい値が少なくとも 1 つ含まれます。$a_i$、他のすべての要素が分割されます$a_i$したがって、LCM は超えることはできません$a_i$そしてそれを下回ることができません。 これら 2 つの制約により、行 LCM と列 GCD の両方が正確な値に固定されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    # feasibility check: b[j] must divide every a[i]
    for i in range(n):
        for j in range(m):
            if a[i] % b[j] != 0:
                print("No")
                return

    # start with base matrix filled with column requirements
    mat = [[b[j] for j in range(m)] for _ in range(n)]

    # assign each row one column to place its row LCM target
    for i in range(n):
        mat[i][i % m] = a[i]

    print("Yes")
    for row in mat:
        print(*row)

if __name__ == "__main__":
    solve()
```実現可能性チェックは、導出された条件を直接適用します。$b_j \mid a_i$。 どこかで失敗すると、そのセルは両方の割り算制約に同時に違反するため、構築は不可能になります。 

行列は初期化され、すべての列に正しい GCD 候補が含まれるようになります。 その後、各行は 1 つのオーバーライド配置を受け取ります。$a_i$これにより、列構造を損なうことなく行 LCM が正確になります。 使用する$i \bmod m$これらのオーバーライドを分散して、すべての列に複数の値が含まれるようにします。$b_j$値を調整し、偶発的な GCD のインフレを防ぎます。

 ## 特殊なケース

 微妙なケースの 1 つは、すべてが$a_i = 1$。 次に、すべてのセルを 1 で除算し、すべてのエントリを強制的に 1 にする必要があります。この構造は依然として機能します。$b_j$1 でなければなりません。そうでない場合、実行可能性は直ちに失敗します。 このアルゴリズムは矛盾するケースを正しく拒否し、それ以外の場合は行 LCM と列 GCD が 1 のままの一様行列を出力します。 

別のケースは、すべてが$b_j = 1$。 これにより、列制約がほぼ完全に削除されますが、行制約により、各制約が少なくとも 1 回は強制的に発生します。$a_i$。 1 で満たされた基本行列により、列 GCD が 1 のままであることが保証され、注入$a_i$GCD(1, a_i) は常に 1 であるため、行ごとに 1 つの位置に配置すると正確さが保たれます。 

3 番目のケースは次の場合です。$n$または$m$1 に等しい。構造は単一の行または列に縮退しますが、同じ割り算ロジックが引き続き適用されます。 アルゴリズムは引き続き互換性を正しくチェックし、必要な単一の構造を変更せずに割り当てます。
