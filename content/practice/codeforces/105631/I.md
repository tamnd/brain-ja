 ## 解決策
 ## 問題の理解

 私たちには、一列に配置された一連の色の光が与えられます。 各位置にはカラーラベルがあり、複数の位置が同じ色を共有する場合があります。 この静的配列に基づいて、一連の更新操作を処理します。 各操作は、連続するセグメントに焦点を当て、そのセグメント内の同じ色の位置のペアに応じて値の寄与を割り当てます。 

重要なルールは、セグメントに対する特定の操作では、同じ色を共有するセグメント内のすべてのインデックスのペアが、その色と一致するそれらの間のすべての位置 (両端を含む) に操作の値を与えるということです。 言い換えれば、セグメント内で同じ色の 2 つの出現を選択すると、それらの間の間隔でその色の出現がすべて操作値によって増分されます。 多くのペアが存在する可能性があるため、1 つの操作が異なるペアを通じて位置に複数回影響を与える可能性があります。 

出力には、すべての演算後の各位置での最終累積値 (モジュロ 1e9 + 7) が必要です。 

制約により、n と m は両方とも最大 100,000 になります。 これにより、各クエリ内のすべてのペアを明示的に列挙するソリューションは即座に除外されます。これは、長さ n の単一セグメントに O(n²) 個のペアが含まれる可能性があり、m 個のクエリにわたってこれが壊滅的に大きくなるからです。 

セグメント内では色が何度も出現するが、グローバル配列ではまばらに出現する場合、微妙なエッジ ケースが発生します。 たとえば、色が位置 1、10、20 に表示されるセグメントを考えてみましょう。単純なペア列挙では、(1,20)、(1,10)、(10,20) を独立して扱い、範囲全体に寄与を伝播しようとしますが、二重カウントや重複寄与の欠落を避けるためには慎重な推論が必要です。 

もう 1 つの特殊なケースは、すべてのライトが同じ色である場合です。 その場合、すべてのクエリは基本的にすべてのサブ配列ペアに影響を及ぼし、その影響は非常に反復的になります。 カラー構造によって圧縮しないアプローチは、一般的な場合よりもさらに早くタイムアウトになります。 

## アプローチ

 操作を直接解釈すると、各クエリ範囲内の同じ色の位置のすべてのペアを反復処理することが示唆されます。 ap = aq の各ペア (p, q) について、その色を共有する p と q の間のすべてのインデックスに vi を追加します。 これを範囲更新としてより効率的に再解釈したとしても、ボトルネックは依然として各クエリ セグメント内のペアの列挙です。 最悪の場合、すべての要素が同一である配列全体をカバーするクエリでは O(n²) 個のペアが生成され、m が 1e5 までの場合、これはまったく実行不可能になります。 

重要な点は、この操作が、等しい値の出現と配列内のそれらの相対的な順序のみに依存するということです。 クエリ範囲内の任意のペアという観点から考えるのではなく、色ごとにグローバルに考えることができます。 色 c を固定し、それが表示されるすべての位置を調べます。 クエリ [l, r] 内では、この間隔内にある c の出現のみが問題となり、寄与構造はフィルターされたリスト内の連続した出現にのみ依存します。 

これは視点を反転することを示唆しています。ペアに対してクエリを処理するのではなく、色ごとに、各クエリがその色の連続出現にどのような影響を与えるかを処理します。 各クエリは、[l, r] 内のその色の連続出現のすべてのペアに値 vi を与えます。これらの寄与は、配列の位置を直接扱うのではなく、出現のインデックスを超える範囲の更新に変換できます。

これにより、色ごとに位置の圧縮リストを管理し、そのリストのインデックスに対して範囲加算演算を実行するという問題が軽減されます。 残りの課題は、これらの寄与を元の配列位置に効率的にマッピングし直すことです。 連続した出現間の寄与度ですべてを表現したら、差分配列またはフェンウィック ツリーを使用して効果を O((n + m) log n) に蓄積できます。 

この改善は、真の組み合わせ構造が配列内のすべてのインデックスのペアに及ぶのではなく、各色のソートされたリスト内の隣接する出現に及ぶことを認識することによって得られます。 同じ色のすべてのペア (p、q) は、隣接する出現の連鎖を通じて寄与し、これにより二次ペア構造が色ごとの直線エッジに崩壊します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 各クエリのペアに対するブルート フォース | O(m · n²) | O(n) | 遅すぎる |
 | カラーごとの圧縮 + 範囲の更新 | O((n + m) log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 位置を色ごとにグループ化し、色ごとにその色が表示されるインデックスのソートされたリストを保存します。 これにより、配列全体ではなく、各カラー クラス内でローカルに推論できるようになります。 
2. 色ごとに、その出現位置を表す補助配列を構築します。 i 番目の要素は、元の配列内のその色の i 番目の出現に対応します。 これにより、問題はこれらのリスト内のインデックスの処理に変換されます。 
3. 値 v を持つ各クエリ [l, r] を、色ごとに、どの出現がクエリ間隔内にあるかを識別することによって処理します。 すべての出現ペアを反復処理する代わりに、このクエリが間隔内の連続する出現にどのような影響を与えるかのみを考慮します。 
4. 固定色の場合、[l, r] 内の出現を取得し、それらが色のリストのインデックス i ～ j に対応するとすると、クエリは v をすべての隣接するペア (i, i+1)、(i+1, i+2)、...、(j-1, j) に提供します。 これは、そのようなすべての隣接するペアが、すべての中間の同色位置への寄与を生成する最小セグメントを形成するためです。 
5. これを、色ごとに、その出現リスト上の差分配列を維持することによって適用します。 各クエリについて、二分探索を使用して範囲内の最初と最後の出現箇所を特定し、区間 [i, j-1] の差分構造を v ずつ増分します。 
6. すべてのクエリを処理した後、各色の差分配列のプレフィックスの合計を計算して、隣接する出現ペアごとの寄与の重みを取得します。 
7. 最後に、これらのペアの寄与を実際の配列位置に伝播させます。 隣接する各ペアは、その累積値をそれらの間のすべての出現に寄与します。これは、各色の位置をスイープすることによって、元の配列に対する差分配列を使用して再び処理できます。 

### なぜ効果があるのか

 重要な不変条件は、クエリによって生成されたすべての寄与が、各色の隣接する出現に対する独立した寄与に分解でき、元の有効なペア (p, q) がすべて、p と q の間の隣接する出現の連続チェーンに対応することです。 これらのエッジ上の寄与を合計することで、各ペアを正確に 1 回カウントすると同時に、中間位置での伝播がペア数の二次関数ではなく出現数において線形になることを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
MOD = 10**9 + 7

n, k = map(int, input().split())
a = list(map(int, input().split()))
m = int(input())

pos = [[] for _ in range(k + 1)]
for i, c in enumerate(a):
    pos[c].append(i)

# diff over edges inside each color occurrence list
diff = [[] for _ in range(k + 1)]

for c in range(1, k + 1):
    diff[c] = [0] * (len(pos[c]) + 1)

for _ in range(m):
    l, r, v = map(int, input().split())
    l -= 1
    r -= 1

    # we process per color
    for c in range(1, k + 1):
        lst = pos[c]
        if not lst:
            continue

        # find first occurrence >= l
        import bisect
        i = bisect.bisect_left(lst, l)
        j = bisect.bisect_right(lst, r) - 1

        if i < j:
            diff[c][i] = (diff[c][i] + v) % MOD
            diff[c][j] = (diff[c][j] - v) % MOD

# prefix over each color
edge_val = [[] for _ in range(k + 1)]
for c in range(1, k + 1):
    edge_val[c] = [0] * len(pos[c])
    cur = 0
    for i in range(len(pos[c]) - 1):
        cur = (cur + diff[c][i]) % MOD
        edge_val[c][i] = cur

# propagate to array
ans = [0] * n

for c in range(1, k + 1):
    lst = pos[c]
    if not lst:
        continue

    # contribution sweep
    for i in range(len(lst)):
        p = lst[i]
        add = 0
        if i > 0:
            add += edge_val[c][i - 1]
        if i < len(lst) - 1:
            add += edge_val[c][i]
        ans[p] = add % MOD

print(*ans)
```実装は、インデックスを色ごとにグループ化することから始まり、これにより、後のすべての推論が独立した構造内で動作できるようになります。 各クエリは、二分探索を使用してクエリ間隔内にある各色の出現セグメントを識別することによって処理されます。 差分配列`diff[c]`クエリが連続した発生エッジをアクティブにする方法をキャプチャします。 

すべてのクエリが処理された後、プレフィックス合計によって出現間の実際のエッジの重みが再構築されます。 最後のスイープでは、各出現箇所に接する隣接エッジからの寄与を合計することにより、これらのエッジ寄与を実際の配列位置に分配します。 

実装上の微妙な問題は、差分配列での符号の処理です。 更新には減算が含まれるため、負のドリフトを避けるために値をモジュロ演算で直ちに正規化する必要があります。 もう 1 つの微妙な点は、寄与がオカレンス間のエッジに関連付けられているため、エッジ値を作成するときにインデックス作成で各カラー リストの最後の要素を慎重に除外する必要があることです。

 ## 特殊なケース

 すべての位置が同一である単色の配列の場合、アルゴリズムはすべての出現を単一の長いチェーンにまとめます。 各クエリはこのチェーンの連続セグメントに影響を与え、差分配列はセグメント内のエッジのみを正確にマークします。 逆に伝播する場合、各内部位置は 2 つの隣接するエッジから寄与を受け取りますが、エンドポイントは 1 つだけを受け取り、その位置にまたがるペアの組み合わせ構造と一致します。 

位置 [2、100、1000] のようなまばらな色分布の場合、間隔内に完全に隣接するペアがないため、中央の位置のみをカバーするクエリではエッジがアクティブになりません。 出現の間隔 [i, j] が i == j であり、差分更新条件 i < j によりアクティベーションが妨げられ、その制限されたセグメントに有効なペアが存在しないという事実と一致するため、アルゴリズムは当然寄与度をゼロにします。
