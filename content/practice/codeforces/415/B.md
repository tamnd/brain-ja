 ## 解決策
 ## 問題の理解

 マシュモクは毎日大量のトークンを受け取り、その日の終わりに、固定の変換ルールを使用してトークンの一部をお金に交換できます。 彼が戻ってきたら$w$トークン、彼が受け取るお金は、サイズの完全な「ブロック」がいくつあるかによってのみ決まります$a$の一次関数に含まれる$w$。 正確なマッピングは線形であり、その後フロア化されるため、次の通貨単位に向けた断片的な進歩には価値がありません。 

主な目標は、直接変換されたトークンを最大化することではなく、できるだけ多くのトークンを節約しながら資金を最大化することです。 未使用のトークンは将来に繰り越されないため、毎日は独立しており、可能な最大の金銭的価値に達するためにその日に交換するトークンの数を決定するだけで済みます。 

入力により得られるのは、$n$日数、パラメータ$a$そして$b$、および配列$x_i$毎日利用できるトークンの数を説明します。 毎日の出力は、最適な交換量を選択した後に保存できるトークンの数です。 

制約$n \le 10^5$強制的に$O(n)$または$O(n \log n)$解決。 考えられるすべてのトークンの選択に対して 1 日ごとのシミュレーションを行うと、時間がかかりすぎます。$x_i$と同じ大きさにすることができます$10^9$、ブルートフォースが実行不可能になります。 

微妙なエッジケースが現れるのは、$x_i$に比べて非常に小さいです$a$。 たとえば、次の場合$x_i < a$、式によっては交換が不可能な場合があり、「すべてのトークンを使用する」などの単純な貪欲な仮定は失敗します。 もう 1 つのエッジケースは次のような場合です$x_i$は、交換トークンを増やしてもお金が増えない複数の境界上にあります。つまり、追加のトークンを 1 つ節約することが常に最適です。 

## アプローチ

 直接的なアプローチは、可能な限りすべての数のトークンを試すことです$w$から$0$に$x_i$、結果として得られるお金を計算し、同点の中で残ったトークンを最大化しながら最適なものを選択します。 これは正しいですが、非常に遅いです。 毎日私たちがすることは$O(x_i)$最悪の場合、$O(n \cdot 10^9)$、完全に不可能です。 

貨幣機能の構造は重要な観察です。 お金は～にのみ依存します$\left\lfloor \frac{a \cdot w}{b} \right\rfloor$、したがって、値は離散しきい値でのみ増加します。$w$。 2 つの連続するしきい値の間で増加$w$お金は変わりません。 これは、次のすべての値を考慮する必要がないことを意味します。$w$、最小のものだけ$w$制約の下で可能な最大の整数値を達成する$w \le x_i$。 

固定の場合$x_i$、最適な戦略は、すべてのトークンを使用して取得できる最大金額を計算し、同じ金額レベルを達成するために必要なトークンの最小数を見つけることです。 の違い$x_i$そして、その最小要件はまさに保存できるトークンの数です。 

これにより、問題は 1 日あたりの単純な算術変換に変わります。

 ## アルゴリズムのチュートリアル

 私たちは 1 日を大切にします$x$トークン。 

1. すべてのトークンが使用された場合に達成可能な最大金額を計算します。 これは$k = \left\lfloor \frac{a \cdot x}{b} \right\rfloor$。 この値は、その日の可能な最高の整数報酬レベルを表します。 
2. 通訳する$k$逆方向: トークンの最小数を決定します。$w$そのような$\left\lfloor \frac{a \cdot w}{b} \right\rfloor = k$。 これにより、トークンを無駄にすることなく同じ報酬レベルに達することが保証されます。 
3. 不等式を解く$$k \le \frac{a \cdot w}{b} < k+1$$再配置すると$$\frac{k \cdot b}{a} \le w < \frac{(k+1)\cdot b}{a}$$1. 最小の整数$w$これで満足です$$w_{\min} = \left\lceil \frac{k \cdot b}{a} \right\rceil$$1. 保存されるトークンの数は単純に$x - w_{\min}$。 

毎日は独立しているため、すべての入力に対してこの計算を繰り返します。 

### なぜ効果があるのか

 重要な不変条件は、マネー関数が整数行を連続した区間に分割し、区間内のすべての値が同じ報酬を生成することです。 各間隔内でより多くのトークンを費やしても結果は改善されません。 したがって、最適な戦略は常に、制約の下で達成可能な最大報酬に対応する間隔の左側の境界を選択することです。$w \le x$。 これにより、最大の節約が保証されます。$w$報酬は増加せず、それより小さい場合は$w$それを減らすだろう。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, a, b = map(int, input().split())
    xs = list(map(int, input().split()))
    
    for x in xs:
        k = (a * x) // b
        w_min = (k * b + a - 1) // a
        print(x - w_min, end=' ')
        
solve()
```このソリューションは、達成可能な最高の報酬レベルを計算します。$k$すべてのトークンを使用します。 次に、天井分割トリックを使用して、同じ報酬に到達するために必要な最小数のトークンを再構築します。$(k \cdot b + a - 1) // a$。 これを引くと$x$お金を減らさずに安全に保存できるトークンの最大数を示します。 

整数演算には注意が必要です。 掛け算$a \cdot x$到達できる$10^{18}$ですが、Python はそれを安全に処理します。 天井分割は、off-by-one エラーを避けるために慎重に実装する必要があります。

 ## 特殊なケース

 いつ$x_i$非常に小さいです、例えば$x_i = 1$、計算された報酬レベル$k$ゼロになります。 その場合、最低限の$w$同じ報酬を達成する場合もゼロなので、すべてのトークンを保存できます。 アルゴリズムはこれを正しく処理します。$k = 0$につながる$w_{\min} = 0$、完全な節約を生み出します。 

いつ$x_i$大きく、増加する境界に近い$w$変わらない$\left\lfloor \frac{a w}{b} \right\rfloor$、計算された$w_{\min}$最も近いしきい値まで折りたたまれます。 たとえば、次の場合$a=1, b=4, x=6$、 それから$k=1$、 そして$w_{\min}=4$。 アルゴリズムは正しく保存します$2$トークン、それを超えて支出するという事実と一致する$4$追加の利益は得られません。 

いつ$a$そして$b$が等しい場合、関数は次のようになります$k = x$、 そして$w_{\min} = x$, したがって、トークンは保存されません。 すべてのトークンがちょうど 1 単位の報酬に貢献するため、このアルゴリズムでは当然、節約額はゼロになります。
