 ## 解決策
 ## 問題の理解

 一連の整数が与えられているので、その中の「山」と「谷」を識別する必要があります。 位置に山が発生します`j`数値が両方の隣接値よりも厳密に大きい場合は、谷が発生します。一方、数値が両方の隣接値よりも厳密に小さい場合は、谷が発生します。 一連の山と谷の合計は威圧値と呼ばれます。 シーケンス内の数値を 1 つだけ任意の整数に変更することも、シーケンスを変更しないままにすることもできますが、この 1 つの変更後の威嚇値を可能な限り最小にする必要があります。 

入力は複数のテスト ケースで構成されます。 各テスト ケースは、シーケンスとシーケンス自体の長さを提供します。 出力はテスト ケースごとに 1 つの数値、つまり達成可能な最小威嚇値です。 

制約は、すべてのテスト ケースにわたるすべてのシーケンスの合計長が 300,000 を超えないことです。 各テスト ケースは最大 300,000 要素になる可能性があるため、$O(n^2)$アプローチが遅すぎるでしょう。 各シーケンスのサイズが線形または線形に近いソリューションが必要です。 

エッジ ケースは、シーケンスの要素が非常に少ない場合 (中央の要素のみが山または谷になる可能性のある 3 つの要素、またはすべての数値が等しいシーケンス、つまり山や谷が 0 である場合) に発生します。 不注意な実装では、境界をチェックせずに要素を調整しようとしたり、隣接する変更が無視された場合に山や谷を誤ってカウントしたりする可能性があります。 

## アプローチ

 ブルートフォース手法では、シーケンス内のすべての可能な位置を反復し、すべての可能な整数への変更を試行し、全体の威圧値を再計算して、最小値を維持します。 このアプローチは原理的には正しいですが、完全に非現実的です。 以下の値までのすべての値をテストしようとすると、$10^9$要素ごとに操作の数が爆発的に増加し、実行可能な制限をはるかに超えます。 

最適化のための重要な洞察は、数値を変更すると、そのすぐ近くの山と谷、具体的にはインデックス自体とその 2 つの隣接するインデックスにのみ影響するという観察から得られます。 したがって、毎回シーケンス全体を再計算する必要はありません。 変更された要素の周囲の山と谷の局所的な寄与を考慮するだけで済みます。 

シーケンス全体の最初の山と谷を事前に計算できます。 次に、各候補ポジションについて`i`(最初と最後の要素を除く)、左の隣に一致するように変更する、右の隣に一致するように変更する、または変更しないままにするという 3 つのオプションを検討します。 各オプションについて、局所的な山と谷の変化を計算します (インデックスで)`i-1`、`i`、 そして`i+1`）。 合計威嚇値を最も減らすオプションを採用します。 これを位置ごとに繰り返し、線形時間ソリューションの最小結果を追跡します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * 値の範囲) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取ります。 テスト ケースごとに、次の内容を読んでください。`n`そして配列`a`。 
2. ヘルパー関数を定義する`is_hill_or_valley(i)`それは戻ってきます`1`もし`a[i]`それは丘または谷であり、`0`さもないと。 これは次のことを確認します`a[i] > a[i-1]`そして`a[i] > a[i+1]`または`a[i] < a[i-1]`そして`a[i] < a[i+1]`。 
3. 合計して初期の合計威嚇値を事前計算します。`is_hill_or_valley(i)`みんなのために`2 ≤ i ≤ n-1`。 
4.初期化`best_reduction`ゼロに。 これには、1 回の変更で達成できる威嚇値の最大減少量が保存されます。 
5. インデックスを反復処理する`i`1から`n-2`(0 ベースのインデックス付け、最初と最後の要素は無視):

 1. 位置における山と谷の現在の合計を計算します。`i-1`、`i`、 そして`i+1`。 
2. 変更してみる`a[i]`に`a[i-1]`。 位置の新しい合計を計算します`i-1`、`i`、 そして`i+1`。 古い合計から新しい合計を引いた減少を計算します。 アップデート`best_reduction`これがもっと大きかったら。 
3. 変更して繰り返します`a[i]`に`a[i+1]`。 
6. 最小威嚇値は次のとおりです。`initial_total - best_reduction`。 テストケース用に印刷してください。 

機能する理由: 番号を変更すると、そのすぐ隣の番号にのみ影響します。 関連するすべてのローカル変更を評価し、ローカル合計を最も削減する変更を選択することで、単一変更の最適な削減を確実に見つけることができます。 これらのローカルな近傍を超えてグローバルな再計算は必要ありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def is_hill_or_valley(a, i):
    return (a[i] > a[i-1] and a[i] > a[i+1]) or (a[i] < a[i-1] and a[i] < a[i+1])

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        if n < 3:
            print(0)
            continue
        hills_valleys = [0] * n
        total = 0
        for i in range(1, n-1):
            if is_hill_or_valley(a, i):
                hills_valleys[i] = 1
                total += 1
        best_reduction = 0
        for i in range(1, n-1):
            original = [hills_valleys[j] for j in range(max(0,i-1), min(n,i+2))]
            current_sum = sum(original)
            for new_val in [a[i-1], a[i+1]]:
                old = a[i]
                a[i] = new_val
                new = [1 if 1 <= j <= n-2 and is_hill_or_valley(a, j) else 0 for j in range(max(0,i-1), min(n,i+2))]
                reduction = current_sum - sum(new)
                best_reduction = max(best_reduction, reduction)
                a[i] = old
        print(total - best_reduction)

if __name__ == "__main__":
    solve()
```コードは山と谷を事前に計算します。`hills_valleys`。 ネストされたループオーバー`i`テストの変更`a[i]`隣人の価値観に合わせて。 スライスを使用すると、ローカル効果のみが再計算されます。`i-1`、`i`、`i+1`。 復元中`a[i]`各試行後は、反復にわたる副作用を回避します。 特別な取り扱い`n < 3`インデックスエラーを回避します。
