 ## 解決策
 ## 問題の理解

 頂点に値が含まれるツリーが与えられます。 任意の頂点をルートとして選択できます。 ルートが固定されると、ルートから始まり子孫で終わるすべての単純なパスがルートからノードへのパスになります。 

このようなすべてのルートからノードへのパスにペアごとに異なる値が含まれている場合、そのルートは固有であると呼ばれます。 値はツリー内に何度も現れる可能性がありますが、ルートから始まる単一のパスで同じ値が 2 回出現することは許可されません。 

タスクは、特徴的なルートとして機能できる頂点の数を数えることです。 

最初の観察は、この条件はルート化後の祖先と子孫の関係にのみ依存するということです。 同じ値を持つ 2 つの頂点を含むルートからノードへのパスが存在する場合、ルートは無効です。 

ツリーには以下が含まれます$2 \cdot 10^5$頂点。 すべての頂点でツリーをルート化し、すべてのパスを個別にチェックするような解決策は絶望的です。 各頂点からの単一の DFS であっても、$O(n^2)$仕事、それは周りにあります$4 \cdot 10^{10}$最悪の場合の運用。 線形に近いものが必要です。$O(n \log n)$。 

難しいのは、ルートを変更すると祖先関係がグローバルに変更されることです。 等しい値の頂点のペアは、一部のルートでは同じルートからノードへのパス上に存在する場合がありますが、他のルートではそうではない場合があります。 

チェーンを考えてみましょう。```
1 -- 2 -- 3
values: 5 7 5
```頂点 1 をルートとしてパスが生成されます$1 \to 2 \to 3$、値 5 が 2 回含まれているため、頂点 1 は無効です。 

頂点 2 をルートするとパスが得られます$2 \to 1$そして$2 \to 3$。 どちらにも重複した値が含まれていないため、頂点 2 は有効です。 

一部の固定根回しで同じ値のペアを 1 回だけチェックするソリューションでは、この区別が失われます。 

もう 1 つの微妙なケースは、複数の頂点が同じ値を共有する場合です。```
1
|
2
|
3
|
4

values: 1 2 1 1
```競合は、隣接する同じ値の頂点間だけではありません。 同じ値の頂点のすべてのペアが制限に影響します。 それらの一部を無視すると、有効なルートが過剰にカウントされることになります。 

最後のエッジケースは、すべての値が異なる場合です。 この場合、どのパスにも重複する値を含めることはできないため、すべてのルートが有効になります。 答えは次のとおりです。$n$。 

## アプローチ

 ブルートフォースのアイデアは単純です。 頂点ごとに$r$、ツリーを次の場所にルートします$r$、DFS を実行し、ルートから現在のパスに現在ある値のセットを維持し、値が繰り返されていないことを確認します。 繰り返しが表示される場合は、$r$特徴的ではありません。 

これは定義を直接チェックするので正しいです。 残念ながら、各ルートには次のものが必要です$O(n)$仕事、そして、$n$ルーツ。 全体の複雑さは次のようになります。$O(n^2)$、これは大きすぎます$n=2\cdot10^5$。 

より迅速な解決策を得るには、ルートがいつ無効になるかを正確に理解する必要があります。 

任意のルート、たとえば頂点 1 を修正します。2 つの頂点を考慮します。$u$そして$v$同じ値を持っています。 

根$r$root 化後の場合は無効です。$r$、これらの頂点の 1 つが他の頂点の祖先になります。 次に、からのパス$r$より深いものには、値の両方のコピーが含まれます。 

したがって、問題は次のようになります。 

すべての等しい値のペアに対して$(u,v)$、すべてのルートを決定します$r$誰のために$u$そして$v$ツリーのルートが次の場合、祖先と子孫の関係にあります。$r$。 

ルートを個別にテストするのではなく、各競合ペアによって無効になったすべてのルートにマークを付けます。 

重要な観察は、固定ペアの場合です。$(u,v)$、不良ルートのセットは非常に単純なサブツリー構造を持っています。 

仮定する$u$の先祖です$v$頂点 1 の固定ルートで。 

しましょう$c$の子になる$u$それは～からの道の途中にあります$u$に$v$。 

新しいルートがサブツリー内にある場合($c$）、 それから$u$そして$v$最終的には異なるブランチになり、どちらも他方の祖先にはなりません。 

ルート位置を 1 つおきに、$u$～の先祖として残っている$v$、ルートパス上に複製が作成されます。 

したがって、サブツリーの外側のすべてのルート($c$）悪いです。 

どちらの頂点も固定ルートで他方の頂点の祖先ではない場合、次のようにします。$w=\mathrm{LCA}(u,v)$。 

それから$u$そして$v$新しいルートがサブツリー内にあるとき、正確に祖先関連になります($u$) またはサブツリー($v$）。 

これらもまたサブツリーの更新です。 

残りの課題は、すべての等しい値のペアを効率的に処理することです。 あるかもしれない$O(n^2)$多くの頂点が値を共有する場合、そのようなペアになります。 

重要な削減は、DFS 中に値を処理し、同じ値を持つ最も近い祖先に関係する制約のみを生成することです。 これにより、問題は更新の線形数に変換されます。 

受け入れられた解決策は、DFS を値出現スタックおよびサブツリー上の差分配列とともに使用します。

 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^2)$|$O(n)$| 遅すぎる |
 | 最適 |$O(n \log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 頂点 1 でツリーを任意にルートします。 

DFS を実行して、オイラー ツアーの開始時間と終了時間、親ポインター、およびサブツリー範囲を計算します。 これらの範囲により、サブツリーの更新をオイラー次数の間隔更新として表すことができます。 

すべての値について、現在の DFS パス上でその値を持つ最新の頂点を追跡します。 

DFS 中に頂点にアクセスするとき$v$、同じ値が現在の root-to-$v$パス。 
同じ値を持つ最も近い祖先のうち、$u$、次に子サブツリーの外側にあるすべてのルート$u$に$v$は無効です。 

これは、以前に説明した祖先のケースに続きます。 子サブツリーの外側にあるルートはすべて保持されます。$u$その上$v$、ルート パスに重複した値が生成されます。 

ツリー全体に無効マークを 1 つ追加し、その子サブツリーから 1 つを減算します。 オイラー間隔を使用すると、これは範囲の更新になります。 

次に、頂点の複数の子孫がその値を共有する状況に対処する必要があります。 

頂点ごとに$u$、サブツリーに値の別の出現が含まれるすべての子を収集します。$a_u$。 

2 つの異なる子サブツリーの両方にその値が含まれている場合、それらのサブツリーのいずれかの内部のルートは無効になります。 そこに根を張ることで、ある出現が別の出現の祖先になります。 

これらのサブツリー領域も範囲更新によってマークされます。 

この実装では、値ごとに、すべてのサブツリーに出現する回数が格納され、情報が上方に伝播されます。 競合が検出されるたびに、対応するサブツリー間隔が更新を受け取ります。 

すべての更新が蓄積された後、オイラー次数に対してプレフィックス蓄積を実行します。 

頂点は、最終的な無効カウントが 0 に等しいとき、まさに固有のルートになります。 

そのような頂点を数えます。 

### なぜ効果があるのか

 すべての違反は、単一のルートからノードへのパス上に現れる 2 つの等しい値の頂点から発生します。 

どのような値についても、DFS 中に生成された最も近い等しい値の祖先関係を考慮します。 考えられるすべての重複値パスは、これらの祖先と子孫の競合の 1 つによって表されます。 更新ルールは、再ルート後にそのような祖先関係を保持するルートを正確にマークします。 

更新の 2 番目のファミリーは、同じ値の異なる子ブランチに存在するオカレンスによって生じる競合を処理します。 これらはまさに、再ルート化によって 1 つの出現が別の出現の祖先に変わるルートです。 

すべての無効なルートは少なくとも 1 つの競合によってマークされ、すべてのマークは本物の重複値パスに対応します。 したがって、すべてのルートからノードへのパスに個別の値が含まれている場合に限り、ルートはカウント 0 を受け取ります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    g = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    tin = [0] * n
    tout = [0] * n
    parent = [-1] * n
    timer = 0

    sys.setrecursionlimit(1 << 20)

    def dfs0(v, p):
        nonlocal timer
        parent[v] = p
        tin[v] = timer
        timer += 1
        for to in g[v]:
            if to != p:
                dfs0(to, v)
        tout[v] = timer

    dfs0(0, -1)

    diff = [0] * (n + 1)

    def add_subtree(v, x):
        diff[tin[v]] += x
        diff[tout[v]] -= x

    def add_all(x):
        diff[0] += x
        diff[n] -= x

    last = {}
    bad_child = [set() for _ in range(n)]

    def dfs1(v, p):
        prev = last.get(a[v], -1)
        last[a[v]] = v

        if prev != -1:
            cur = v
            while parent[cur] != prev:
                cur = parent[cur]

            add_all(1)
            add_subtree(cur, -1)

            bad_child[prev].add(cur)

        for to in g[v]:
            if to != p:
                dfs1(to, v)

        if prev == -1:
            del last[a[v]]
        else:
            last[a[v]] = prev

    dfs1(0, -1)

    for v in range(n):
        if len(bad_child[v]) >= 2:
            for ch in bad_child[v]:
                add_subtree(ch, 1)

    cur = 0
    ans = 0

    euler_to_vertex = [0] * n
    for v in range(n):
        euler_to_vertex[tin[v]] = v

    val = [0] * n
    for i in range(n):
        cur += diff[i]
        val[euler_to_vertex[i]] = cur

    for v in range(n):
        if val[v] == 0:
            ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```最初の DFS はオイラー ツアー間隔を計算します。 すべてのサブツリーは連続したセグメントになります$[tin,tout)$これにより、サブツリーの更新を一定時間で実行できるようになります。 

2 番目の DFS は、値ごとに、再帰スタック上で現在最も近い値を保持します。 繰り返される値が出現する場合、新しい出現につながる以前の出現の子を特定します。 「ツリー全体からその子サブツリーを差し引いた」更新は、グローバル間隔更新と補償サブツリー減算によって実装されます。 

の`bad_child`構造体は、頂点のどの子ブランチに同じ値の別の出現が含まれるかを記録します。 DFS の終了後、値が少なくとも 2 つの異なる子ブランチに出現する頂点は、追加の禁止されたルート領域を作成します。 これらのサブツリー間隔は差分配列に追加されます。 

最後に、オイラー次数をスイープして、差分配列を実際の無効数に変換します。 カウントが 0 の頂点は、まさに有効なルートです。 

最もデリケートな部分は、祖先のオカレンスの直下にある子を特定することです。 最も近い同じ値の祖先を使用すると、すべての競合が 1 回処理されることが保証されます。 もう 1 つの簡単な間違いは、サブツリーの更新が半分開いた間隔であることを忘れていることです。$[tin,tout)$; 包括的なエンドポイントを使用すると、off-by-one エラーが発生します。

 ## 特殊なケース

 単一の頂点を考えてみましょう。```
1
10
```ルートからノードへのパスは 1 つだけあり、単一の頂点で構成されます。 重複は発生しません。 DFS は競合更新を実行せず、すべてのカウンターはゼロのままで、答えは 1 です。

3

1 2
2 3
