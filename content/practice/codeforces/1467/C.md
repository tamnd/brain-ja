 ## 解決策
 ## 問題の理解

 3 つの別々のバッグが与えられ、それぞれのバッグには複数の整数セットが含まれています。 特定の操作は何度でも実行できます。つまり、空ではない 2 つのバッグのそれぞれから 1 つの数値を選択し、最初の数値から 2 番目の数値を減算し、最初の数値を結果で置き換えながら 2 番目の数値をバッグから削除します。 目標は、1 つのバッグに 1 つの数字が含まれ、他の 2 つのバッグが空になるまで、これらの操作を繰り返し適用することです。 この最終状態に至る一連の操作の中で、最後に残ったバッグで達成可能な最大数を決定する必要があります。 

入力では、3 つのバッグのサイズと、その後に各バッグ内の実際の整数が提供されます。 この制約では、それぞれ最大 10^9 の合計 300,000 個の数値が許可されます。 これにより、単純に操作をシミュレートするアルゴリズムは排除されます。ブルート フォース アプローチでは、考えられるすべてのペアを繰り返し調べる必要があり、操作数が$n^2$以上。 

明らかではないエッジ ケースには、1 つのバッグに 1 つの大きな数字が含まれている一方で、他のバッグにはより小さな数字が含まれている、またはすべての数字が等しいという状況が含まれます。 減算演算を考慮せずにすべての数値を単純に合計する単純なアプローチでは、最初に小さい合計を削除することでより大きな数値を累積できるというシナリオを見逃す可能性があります。 

たとえば、次の入力を考えてみましょう。```
1 2 2
10
5 5
1 2
```常に最小の数値を組み合わせる不用意なアルゴリズムでは、最終的な数値が 20 未満になる可能性がありますが、最適な戦略は、10 と他のバッグの合計を特定の順序で組み合わせて 20 を達成することです。これは、操作の順序とどのバッグをペアにするかが重要であることを強調しています。 

## アプローチ

 ブルートフォース手法は、考えられるすべての操作をシミュレートすることです。つまり、任意の 2 つのバッグを選択し、それぞれから番号を選択し、操作を適用して、番号が 1 つだけ残るまで再帰的に実行します。 このアプローチは、操作が明確に定義されており、最終的には終了するため、理論上は機能します。 ただし、シーケンスの数は組み合わせによって決まります。 最大 3×10^5 の数値を使用すると、実行時間がはるかに長くなります。 すべてのペアの 1 ラウンドでも、$\mathcal{O}(n^2)$ステップが遅すぎます。 

最適なソリューションのための重要な洞察は、最終状態の分析から得られます。 すべての数値の合計は、非常に制御された方法で減少します。各演算は 1 つの数値を置き換えます。$a$と$a-b$そして削除します$b$, したがって、合計は次のように減少します。$2b$。 これから、達成可能な最終的な最大数の一般式を導き出すことができます。これは、すべての数値の合計から、1 つのバッグまたは 2 つの最小のバッグのいずれか小さい方の数値の合計の 2 倍を引いたものです。 具体的に言うと、$S$は合計であり、$x, y, z$は 3 つのバッグの合計であり、最終的な最大数は次のとおりです。$$\text{max\_final} = S - 2 \times \min(x, y, z, x+y, x+z, y+z)$$これにより、問題はバッグの合計に関する単純な算術に縮小されます。 実際の動作シミュレーションは必要ありません。

 | ブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 3 つの袋それぞれに入っている数字の合計を計算し、それらを呼び出します。`sum1`、`sum2`、`sum3`。 これは各バッグの内容量の合計を表します。 
2. 合計を計算します`S = sum1 + sum2 + sum3`。 これは、操作前のすべてのバッグ内のすべての数値の合計です。 
3. 個々の手荷物の最小合計額を特定する`min_single = min(sum1, sum2, sum3)`。 これは、最初にバッグ全体を削除することになる可能性があるシナリオを表しています。 
4. 最も小さい 2 つのバッグの合計を特定します。`min_pair = min(sum1+sum2, sum1+sum3, sum2+sum3)`。 これは、最適な順序で 2 つのバッグを完全に取り出すことになるシナリオを表しています。 
5. 最終的な答えを次のように計算します。`max_final = S - 2 * min(min_single, min_pair)`。 これは、減算操作によってバッグを最適に除去した後に達成可能な最大合計を計算します。 
6. 出力`max_final`。 

ここで不変なのは、合計が`S`の倍数でのみ減少します`2 * b`数字の場合`b`私たちは削除します。 最小の 1 つのバッグ、または 2 つの最小のバッグの合計を考慮することで、総計の最悪の場合の削減額が得られます。 1 つまたは 2 つのバッグを空にする一連の操作では、合計額を以下に減らすことはできません。`2 * min(min_single, min_pair)`、この式は、可能な最大の最終数値を生成することが保証されています。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n1, n2, n3 = map(int, input().split())
bag1 = list(map(int, input().split()))
bag2 = list(map(int, input().split()))
bag3 = list(map(int, input().split()))

sum1 = sum(bag1)
sum2 = sum(bag2)
sum3 = sum(bag3)

total = sum1 + sum2 + sum3

min_single = min(sum1, sum2, sum3)
min_pair = min(sum1 + sum2, sum1 + sum3, sum2 + sum3)

max_final = total - 2 * min(min_single, min_pair)
print(max_final)
```このソリューションでは、まず入力を効率的に読み取ります。 各バッグの合計を計算して、問題を算術に落とし込みます。 重要なステップはコンピューティングです`min_single`そして`min_pair`、バッグの取り外しによって可能な最小限の削減をすべてキャプチャします。 最後に、合計合計からこの最小限の削減の 2 倍を差し引いて、達成可能な最大数を取得します。 整数演算を使用してオーバーフローを避けるように注意する必要がありますが、Python は大きな整数をネイティブに処理します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n1, n2, n3 = map(int, input().split())
    bag1 = list(map(int, input().split()))
    bag2 = list(map(int, input().split()))
    bag3 = list(map(int, input().split()))
    sum1 = sum(bag1)
    sum2 = sum(bag2)
    sum3 = sum(bag3)
    total = sum1 + sum2 + sum3
    min_single = min(sum1, sum2, sum3)
    min_pair = min(sum1 + sum2, sum1 + sum3, sum2 + sum3)
    return str(total - 2 * min(min_single, min_pair))

# minimum-size input
assert run("1 1 1\n1\n2\n3\n") == "4", "min size"

# single huge number
assert run("1 2 2\n1000000000\n1 1\n1 1\n") == "1000000000", "single large number"

# two bags same sum
assert run("2 2 1\n5 5\n3 7\n2\n") == "20", "two bags same sum"
