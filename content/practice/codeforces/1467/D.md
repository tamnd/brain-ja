 ## 解決策
 ## 問題の理解

 長さのすべてのシーケンスの値の合計を計算するように求められます。`k+1`ロボットが線に沿って横断できること`n`細胞。 各移動は、境界内に留まりながら、左または右に 1 歩正確に移動する必要があります。 パスの値は、`a_i`訪問したセルの値。 最初の計算の後、次のことを実行するように求められます。`q`どこで更新するか`a_i`が置き換えられ、更新のたびに、すべてのパスの合計を剰余として再計算する必要があります。$10^9 + 7$。 

制約は次のことを教えてくれます`n`そして`k`どちらも最大 5000 にすることができ、`q`最大 200,000 まで可能です。 考えられるすべてのパスを列挙するという単純なアプローチは実行不可能です。`n * 2^k`パスは、たとえ中程度の操作であっても、すぐに適切な操作数を超えます。`k`。 また、更新回数が多いため、毎回合計を最初から再計算する必要がなくなります。 各更新を一定時間内に適用できるように、各セルの寄与を個別に計算する方法が必要です。 

注意すべきエッジケースは次のような場合です。`k`に比べて大きい`n`。 たとえば、次の場合`n=2`そして`k=4`、ロボットは 2 つのセルの間を繰り返しバウンドします。 ロボットが常に左右両方に移動できると想定した不注意な実装では、境界外に進むパスが過大にカウントされます。 

## アプローチ

 ブルートフォースアプローチでは、長さのすべてのパスを生成しようとします。`k+1`開始セルごとに。 パスごとに、パスに沿ったセルの値を合計します。 複雑さは指数関数的に増加します`k`(`O(n * 2^k)`）、これは明らかに不可能です`k=5000`。 

重要な洞察は、後で各セルを通過するパスの数です。`t`動的プログラミングを使用して、動きを組み合わせてカウントできます。 定義する`dp[i][j]`セルに到達する方法の数として`i`後`j`動く。 これは当然再発につながります。`dp[i][j] = dp[i-1][j-1] + dp[i+1][j-1]`(境界はクランプされています)。 この DP を使用すると、移動ごとに各セルを訪れるパスの総数を計算できます。 合計に対するセルの寄与は、すべてのパスにわたってそのセルがアクセスされた回数に比例するため、重みを事前に計算できます。`cnt[i]`各セルがその合計寄与率を表します。 その後のアップデートは、`a_i`一定時間で処理できる：総和は次のように変化する`(new_value - old_value) * cnt[i]`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * 2^k) | O(n * 2^k) | 遅すぎる |
 | 貢献のある動的プログラミング | O(n * k + q) | O(n * k) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 2 つの配列を初期化します。`dp_forward[i][j]`そして`dp_backward[i][j]`。`dp_forward[i][j]`セルに到達する方法の数を数えます`i`で`j`最初から動きますし、`dp_backward[i][j]`で終わりに到達する方法の数を数えます`k-j`セルから開始する移動`i`。 
2.セット`dp_forward[i][0] = 1`みんなのために`i`というのは、移動が 0 で各セルに到達する方法が 1 つだけあるからです。 コンピューティング`dp_forward[i][j]`繰り返し使用する`dp_forward[i][j] = dp_forward[i-1][j-1] + dp_forward[i+1][j-1]`インデックスをクランプしながら`[1, n]`。 
3. 同様に設定します`dp_backward[i][0] = 1`そして計算する`dp_backward[i][j]`同じ繰り返しを使用しますが、移動では逆方向に反復します。 
4. 各セルについて`i`、長さのすべてのパスに出現する合計回数を計算します。`k+1`として`cnt[i] = sum(dp_forward[i][j] * dp_backward[i][k-j] for j in range(k+1))`。 これは、合計に対するセルの重みです。 
5. 最初の合計を次のように計算します。`total = sum(cnt[i] * a[i] for i in 1..n)`。 
6. 更新ごとに、新しい値を読み取ります。`x`のために`a[i]`。 合計を次のように更新します`total += (x - a[i]) * cnt[i] % MOD`そして設定します`a[i] = x`。 更新された合計モジュロを出力します`10^9 + 7`。 

なぜ効果があるのか​​:`cnt[i]`セルのすべての出現を正確にカウントします`i`すべての有効なパスで。 乗算`a[i]`そして合計すると合計が得られます。 更新では 1 つだけが変更されます`a[i]`なので、合計に差を乗算して変更します。`cnt[i]`正しい新しい合計が得られます。 DP は、境界を考慮して、すべてのパス数が正しく考慮されることを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
MOD = 10**9 + 7

n, k, q = map(int, input().split())
a = [0] + list(map(int, input().split()))  # 1-indexed

# DP forward: ways to reach cell i in j moves
dp_forward = [[0] * (k + 1) for _ in range(n + 2)]
for i in range(1, n + 1):
    dp_forward[i][0] = 1

for j in range(1, k + 1):
    for i in range(1, n + 1):
        dp_forward[i][j] = (dp_forward[i-1][j-1] + dp_forward[i+1][j-1]) % MOD

# DP backward: ways to reach cell i in k-j moves to complete path
dp_backward = [[0] * (k + 1) for _ in range(n + 2)]
for i in range(1, n + 1):
    dp_backward[i][0] = 1

for j in range(1, k + 1):
    for i in range(1, n + 1):
        dp_backward[i][j] = (dp_backward[i-1][j-1] + dp_backward[i+1][j-1]) % MOD

# Precompute contribution of each cell
cnt = [0] * (n + 1)
for i in range(1, n + 1):
    for j in range(k + 1):
        cnt[i] = (cnt[i] + dp_forward[i][j] * dp_backward[i][k-j]) % MOD

total = sum(cnt[i] * a[i] for i in range(1, n + 1)) % MOD

for _ in range(q):
    idx, val = map(int, input().split())
    total = (total + (val - a[idx]) * cnt[idx]) % MOD
    a[idx] = val
    print(total)
```このコードは、まず DP テーブルを構築して、指定された回数の移動後に各セルに到達するパスをカウントし、次に各セルの重みを計算します。 更新は、事前に計算された重みを使用して合計を調整することにより、一定時間内に効率的に処理されます。 すべてのインデックスは 1 から始まるインデックスとして慎重に処理され、モジュロ演算によりオーバーフローが発生しないことが保証されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n*k + q) | DP の順方向および逆方向の実行にはそれぞれ O(n_k) がかかり、寄与の計算には O(n_k) がかかり、更新には O(q) がかかります。 
| スペース | O(n*k) | サイズ n*(k+1) の 2 つの DP テーブルと 1 つの cnt 配列 |

 n の場合、k ≤ 5000、n*k ≈ 2,500 万回の操作ですが、これは許容範囲内です。 更新はそれぞれ O(1) であるため、q=200,000 が実現可能です。
