 ## 解決策
 ## 問題の理解

 位置から直線に沿って移動する車が与えられます`0`位置を決める`n`。 私たちは、車がいくつかのチェックポイントを通過する正確な時間を知っています。 これらのチェックポイントは位置によって並べ替えられます。`0, a1, a2, ..., ak`、対応する時間も厳密に増加しています。`0, b1, b2, ..., bk`、最終チェックポイントの位置`n`。 

連続する 2 つの既知のチェックポイント間では、車は一定の速度で移動します。 これは、動きが時間に対して区分的に線形であることを意味します。位置は各セグメント内で時間とともに線形に増加しますが、速度は指定された点の境界で変化する可能性があります。 

クエリ位置ごとに`d`、車が到着する時間を計算しなければなりません`d`を入力し、その時の整数部分を出力します。 

主な難点は、`n`、座標は 1e9 まで大きくなる可能性があるため、動きを段階的にシミュレートすることはできません。 ただし、既知のセグメントの数は`k`はテストごとに最大 1e5 であり、テスト全体の合計も 1e5 であるため、テスト ケースごとに対数または線形の前処理を行う余裕があります。 

単純な間違いは、既知のポイント間の補間がどのように機能するかを誤解することから発生します。 時間はインデックスには比例しませんが、セグメント内の距離に比例します。 

For example, if we have points`(0, 0)`そして`(10, 10)`そしてクエリ`d = 5`、答えは`5`。 しかし、2 番目の点を次のように変更すると、`(10, 20)`、速度が2倍になるので、`d = 5`時間に対応する`10`。 グローバル速度が一定であることを前提としたソリューションは失敗します。 

もう 1 つの微妙なエッジ ケースは、既知のチェックポイントで正確にクエリを実行することです。 もし`d = a[i]`、答えは正確でなければなりません`b[i]`。 どの内挿式も境界の一貫性を維持する必要があります。 

最後に、クエリはゼロ後の最初のチェックポイントの前、またはセグメント内に到達する可能性があるため、クエリごとにセグメントを正しく見つける必要があります。 

## アプローチ

 ブルート フォース アプローチでは、各クエリが個別に処理されます。 クエリ位置の場合`d`、セグメントをスキャンします`[a[i], a[i+1]]`、どこを見つけますか`d`嘘をつき、線形補間を使用して時間を計算します。 

車がセグメント内で移動する場合、`(a[i], b[i])`に`(a[i+1], b[i+1])`、そのときの速度は`(a[i+1] - a[i]) / (b[i+1] - b[i])`。 これを逆にして時間を計算します。`d`:```
t = b[i] + (d - a[i]) * (b[i+1] - b[i]) / (a[i+1] - a[i])
```これは正しいですが、クエリごとに最大でスキャンする可能性があります。`k`セグメントが複雑になる`O(kq)`テストケースごとに。 と`k, q`1e5 までは、最悪の場合は 1e10 の動作となり、遅すぎます。 

重要な観察点は、両方とも`a`そして`b`はソートされており、位置から時間へのマッピングは単調で区分的に線形です。 クエリ位置の正しいセグメントが見つかったら`d`、答えは決定的です。 これにより、問題は効率的なセグメントの配置に軽減されます。 

二分探索ができます`a`最後のチェックポイントを見つけるための配列`a[i] ≤ d`。 その後、補間式を使用して一定時間内に答えを計算します。 

したがって、各クエリは次のようになります。`O(log k)`の代わりに`O(k)`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース スキャン | O(kq) | O(k) | 遅すぎる |
 | 二分探索 + 補間 | O(q log k) | O(k) | 承認済み |

 ## アルゴリズムのチュートリアル

 配列を保存することで各テスト ケースを前処理します`a`そして`b`。 

1. 配列の読み取り`a`そして`b`representing position-time checkpoints. These define a piecewise linear function from position to time.
 2. クエリごとに`d`、最大のインデックスを見つけます`i`そのような`a[i] ≤ d`。 これにより、次の内容を含むセグメントが識別されます。`d`関数の位置が単調であるためです。 
3. もし`d`チェックポイントに等しい`a[i]`、直接返します`b[i]`。 これにより、浮動小数点エラーが回避され、既知の点での正確な値が保持されます。 
4. それ以外の場合は、セグメント内で移動した距離の割合を計算します。 

セグメント内の相対位置は`(d - a[i]) / (a[i+1] - a[i])`。 
5. 線形補間を使用して、その部分を時間空間にマッピングします。`t = b[i] + (d - a[i]) * (b[i+1] - b[i]) // (a[i+1] - a[i])`。 

出力には時間の下限が必要なため、整数除算が使用されます。 
6. 計算された時間を出力します。 

### なぜ効果があるのか

 各セグメント内では、速度が一定であるため、位置は時間の一次関数になります。 これは、位置から時間への逆マッピングも同じ間隔で線形であることを意味します。 以来`a`どのポジションでも厳密に増加しています`d`は 1 つのセグメントにのみ存在し、二分探索によりそのセグメントが正確に識別されます。 内挿式は、そのセグメントに限定された逆線形関数を正確に再構築するため、計算された時間は真の連続時間と一致し、それをフロアリングすることで必要な答えが得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k, q = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        for _ in range(q):
            d = int(input())

            if d <= a[0]:
                if a[0] == 0:
                    print(0)
                else:
                    # segment from 0 to a[0]
                    dt = b[0] * d // a[0]
                    print(dt)
                continue

            if d >= a[-1]:
                print(b[-1])
                continue

            lo, hi = 0, k - 1
            while lo < hi:
                mid = (lo + hi) // 2
                if a[mid] <= d:
                    lo = mid + 1
                else:
                    hi = mid
            i = lo - 1

            if a[i] == d:
                print(b[i])
            else:
                dt = (b[i+1] - b[i]) * (d - a[i]) // (a[i+1] - a[i])
                print(b[i] + dt)

solve()
```この実装では、バイナリ検索を利用して正しいセグメントを効率的に見つけます。 エッジケース`d <= a[0]`最初のセグメントは暗黙的にゼロから始まるため、個別に処理されます。 最後のチェックポイントを超えたクエリの場合、答えは直接次のようになります。`b[k-1]`車はすでに目的地に到着しているからです。 

補間は完全に整数で行われ、精度を維持するために乗算は除算の前に実行されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from typing import List

    def solve():
        t = int(input())
        out = []
        for _ in range(t):
            n, k, q = map(int, input().split())
            a = list(map(int, input().split()))
            b = list(map(int, input().split()))

            for _ in range(q):
                d = int(input())

                if d <= a[0]:
                    if a[0] == 0:
                        out.append("0")
                    else:
                        out.append(str(b[0] * d // a[0]))
                    continue

                if d >= a[-1]:
                    out.append(str(b[-1]))
                    continue

                lo, hi = 0, k - 1
                while lo < hi:
                    mid = (lo + hi) // 2
                    if a[mid] <= d:
                        lo = mid + 1
                    else:
                        hi = mid
                i = lo - 1

                if a[i] == d:
                    out.append(str(b[i]))
                else:
                    dt = (b[i+1] - b[i]) * (d - a[i]) // (a[i+1] - a[i])
                    out.append(str(b[i] + dt))

        return "\n".join(out)

    return solve()

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、クエリが最初の既知のチェックポイントの前にある場合です。 その領域では、以下から効果的に補間します。`(0, 0)`に`(a[0], b[0])`。 たとえば、次の場合`a[0] = 10`そして`b[0] = 5`、 それから`d = 2`与える`t = 5 * 2 // 10 = 1`。 前のセグメントがないため、実装では二分探索を行わずにこれを明示的に処理します。 

もう 1 つのエッジ ケースは、チェックポイントでの完全一致です。 もし`d = a[i]`、補間は数値的には機能しますが、丸め誤差や不必要な計算が発生する危険があります。 直接返却`b[i]`正確性を確保し、除算アーティファクトを回避します。 

最後のエッジケースは、最後のチェックポイントを超えてクエリを実行することです。 以来`a[k-1] = n`、 どれでも`d ≥ n`戻らなければなりません`b[k-1]`。 このソリューションはこれを直接処理し、モーションが既知の最終時点を超えて継続しないことを反映しています。
