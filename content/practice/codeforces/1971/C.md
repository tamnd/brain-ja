 ## 解決策
 ## 問題の理解

 時計の時間のように、1 ～ 12 のラベルが付いた 12 個の等間隔の点を円形に配置して作業しています。 各テスト ケースには、4 つの異なるラベル a、b、c、d が与えられます。 アリスは a と b の間に直線のコードを描き、ボブは c と d の間に別のコードを描きます。 タスクは、これら 2 つのコードが円の内側で交差するかどうかを判断することです。 

幾何学的には、これは通常のユークリッドの意味での距離や角度に関するものではなく、円の順序に関するものです。 2 つのコードが交差するのは、円の周りを歩くときにそれらの終点が交互に配置されている場合に限られます。 

制約は小さく、最大 5940 のテスト ケースと 12 ポイントの固定ユニバース サイズです。 これにより、テストごとの大量の計算が即座に排除されますが、テストごとに定数時間または単純な組み合わせチェックが期待されることも示唆されます。 テストごとに O(t) または O(1) を超えるものはすべて簡単に合格しますが、意図されたソリューションは計算集約的ではなく純粋に論理的です。 

数値を線上の点として扱おうとすると、微妙な問題が発生します。 たとえば、コード (1, 8) と (2, 10) は数直線上では交差していないように見えますが、円上では順序に応じて交差します。 もう 1 つのよくある間違いは、コードには方向性がないため、(a, b) は (b, a) と同じであることを忘れていることです。 順序の正規化に失敗すると、間隔推論に一貫性がなくなります。 

## アプローチ

 この問題を考える強引な方法は、幾何学シミュレーションです。 座標を使用して円上の 12 点をモデル化し、両方の弦の線分を描画し、方向テストを使用して線分が交差するかどうかを確認できます。 これは、各コードを 2D のセグメントとして扱い、セグメント交差ロジックを適用することで機能します。 各テストには一定の時間がかかりますが、実装は必要以上に重く、浮動または座標ブックキーピングが導入されます。 

重要な観察は、ジオメトリは決して必要ないということです。 循環順序のみを考慮します。 1 つのコードを修正します (a、b)。 その弦は円を 2 つの円弧に分割します。 他のコード (c、d) は、c と d がこの分割の異なる側にある場合にのみ交差します。 言い換えれば、2 番目の弦の一方の端点は a と b の間の 1 つの円弧上にあり、もう一方の端点は反対側の円弧上にあります。 

これを正確に行うために、最初の弦の一方の端点を選択し、もう一方の端点まで時計回りに歩くことで円を線形化します。 これは、円順列の間隔を定義します。 2 番目のコードは、その端点の 1 つがその区間内にある場合に交差します。 これにより、問題は循環順序付けにおける単純なメンバーシップ チェックに変換されます。 

宇宙のサイズは固定されており小さいため、モジュラー算術を使用するか円を明示的にシミュレートすることによって、「時計回りに a と b の間の x はどれか」を直接計算できます。

 ## アルゴリズムのチュートリアル

 まず、ヘルパー概念を定義します。円上の 2 つの点 a と b が与えられたとき、3 番目の点 x が a から b への時計回りの円弧上に厳密に存在するかどうかを知りたいとします。 

これを行うには、円 1 → 2 → ... → 12 → 1 に沿って a から b に歩き、訪問した領域をマークします。

1. 最初の弦の終点 a と b を固定します。 a から b までの時計回りの円弧を概念的に定義します。 必要に応じて、円を法 12 として扱うことで、一貫した方向を確保します。 
2. a と b 自体を除いて、点 x が厳密にその円弧の内側にあるかどうかを判断するメンバーシップ テストを構築します。 これは、a から b に到達するまで繰り返すことによって行われます。 
3. 2 番目の弦の終点 c と d については、c または d のいずれかが円弧 (a、b) の内側にあるかどうかを確認します。 
4. ちょうど 1 つの端点が内側にある場合、コードは交差する必要があります。 それ以外の場合、それらは交差しません。 

このロジックが機能する理由は、円内で 2 番目のコードと交差するコードが、円形の順序で交互に配置されるエンドポイントと同等であるためです。 1 つのコードの両方の端点が、もう 1 つのコードによって引き起こされた分割の同じ側にある場合、セグメントは交差することなく描画できます。 それらが分割によって分離されている場合、円の内側で直線が実現されると強制的に交差します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def in_arc(a, b, x):
    # check if x is strictly between a and b clockwise
    cur = a
    while True:
        cur = cur + 1
        if cur == 13:
            cur = 1
        if cur == b:
            return False
        if cur == x:
            return True

t = int(input())
for _ in range(t):
    a, b, c, d = map(int, input().split())

    # normalize direction doesn't matter due to symmetric check
    inside_c = in_arc(a, b, c)
    inside_d = in_arc(a, b, d)

    if inside_c ^ inside_d:
        print("YES")
    else:
        print("NO")
```実装の中核となるのは、`in_arc`この関数は、円に沿って a から b まで明示的に歩きます。 円のサイズは 12 に固定されているため、この操作はループとして記述されていても、実際には定数時間になります。 

XOR 条件`inside_c ^ inside_d`正確に 1 つの端点が円弧内に存在するという要件をエンコードします。 これが交差の正確な条件です。 

よくある落とし穴は、間隔を単純な数値範囲として扱おうとすることです。 モジュラー的な意味で a > b の場合、円が回り込むため、これは失敗します。 明示的なトラバーサルにより、このクラスのエラー全体が回避されます。

 | --- | --- |

 円弧の内側にある端点は 1 つだけなので、答えは「YES」です。 

これにより、インターリーブ パターンが確認されます。円の周りの 2、10、9、6 が強制的に交差します。 

### 例 2

 入力: a = 1、b = 2、c = 3、d = 4

 1 から 2 までの円弧には点が含まれていません。 

| × | in_arc(1,2,x) |
 | --- | --- |

 | 4 | 偽 |

 ## 特殊なケース

 重要なエッジ ケースは、a と b が隣接しているなど、最初のコードが非常に短い場合です。 たとえば、入力 a = 1、b = 2、c = 3、d = 4 では、空の内部円弧が生成されます。 アルゴリズムを実行すると、`in_arc(1,2,3)`そして`in_arc(1,2,4)`ループはすぐに b に到達するため、両方とも false を返します。 どちらの端点も内部にないため、XOR は false となり、出力は NO となり、ジオメトリと一致します。 

もう 1 つのケースは、a = 12 や b = 3 などのラップアラウンド動作です。円弧は 12 → 1 → 2 → 3 です。c = 1 および d = 10 の場合、1 は円弧の内側にあり、10 は円弧の外側にあるため、アルゴリズムは YES を返します。 明示的な循環トラバーサルにより、特殊なケースの算術比較を行わずにラップアラウンドが正しく処理されることが保証されます。 

3 番目の微妙なケースは対称性です。コードのエンドポイントを交換しても答えは変わりません。 a と b の間、または c と d の間の順序を想定していないため、メンバーシップ テストは入力順序に関係なく一貫性を保ちます。
