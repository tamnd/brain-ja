 ## 解決策
 ## 問題の理解

 長さの隠し配列が与えられます$n$であり、これを操作する唯一の方法は、連続したセグメント内の最大値を求めることです。 各クエリにより、選択した間隔における最大値という 1 つの数値が明らかになります。 目標は、最大 624 個の範囲最大クエリを使用して、配列全体の最小要素を決定することです。 

重要な制約は、配列のサイズだけではなく、情報抽出のコストです。 と$n$まで$10^4$、すべての要素を個別に位置特定しようとする単純なアプローチでは、位置ごとの線形スキャンが必要な場合、すでに遅すぎます。 ただし、ここではボトルネックがさらに厳しくなります。クエリの数は固定数に制限されており、各クエリは範囲内で単一のスカラー最大値のみを返します。 

微妙な点は、配列値が 32 ビット範囲全体でランダムであることです。 これにより、敵対的問題に比べて構造が大きく変わります。 ランダムな配列では、値はほぼ確実に個別であり、分散しているため、極端な値は分割統治理論における区切り文字のように動作します。 このランダム性により、線形未満の数のクエリでグローバル構造を抽出できるようになります。 

素朴なアプローチは、次を使用して各インデックスを個別にクエリすることです。$[i, i]$。 それには必要になります$n$クエリ、すでに大規模なクエリの制限を超えています$n$。 もう 1 つの単純なアイデアは、範囲をチェックして最小値を二分探索することですが、最大値のクエリでは最小値に関する単調な情報が得られないため、このようなアプローチは破綻します。 

主な問題点は、最大値クエリでは局所的な小さな値が直接明らかにされず、セグメントに大きな「ブロッキング」要素が含まれているかどうかのみが明らかになることです。 

## アプローチ

 ブルートフォースのベースラインは、次のように質問してすべてのポジションを個別にクエリすることです。$[i, i]$。 これが機能するのは、単一要素の最大値が要素自体であるため、配列全体を復元して最小値を取得できるためです。 費用はまさに$n$クエリ。これは非常に小さな制約の場合にのみ許容され、制限 624 と明らかに互換性がありません。$n$到達できる$10^4$。 

重要な観察は、完全な再構築は必要ないということです。 最小値を見つけるだけで済みます。 ランダムな配列では、グローバル最小値が、分割によって「露出」されずに、多くの大きな要素が優勢な領域に収まる可能性は非常に低いです。 これは、サブセグメントを繰り返し調べて、答えを含めることができない部分を破棄する、適応分割を使用して最小値を検索することを示唆しています。 

これを機能させる直接的な方法は、範囲の最大値を区切り文字として活用する分割統治戦略を使用することです。 セグメントの最大値がわかっている場合は、その最大値に達するインデックスを間接的に分離し、それを中心に配列を分割できます。 値はランダムであるため、最大の「プラトー」の予想されるサイズは小さく、再帰は引き続き効率的です。 

正しい構造は、セグメントの最大値を繰り返し見つけてから、まだ最大セグメントの極値構造になっていない場合は、最小値が含まれないことが保証される位置を中心にセグメントを分割することです。 このプロセスでは、各ステップで少なくとも 1 つの「高障壁」要素が削除される再帰ツリーが効果的に構築され、ランダムな分散により再帰の深さが平均して小さく保たれます。 

これにより、問題は徐々に洗練されたセグメント内の最小値を見つけることに変わり、各クエリは個々の点を調査するのではなく、大きな領域を削除するために使用されます。

 ## アルゴリズムのチュートリアル

 最小限のものが含まれることが保証されている作業セグメントを維持します。 最初はこれが完全な配列です$[1, n]$。 

1. 現在のセグメントの最大値を問い合わせる$[l, r]$。 これにより、セグメント内の「支配的な障壁」を表す値が得られます。 配列はランダムであるため、この最大値はおそらく一意であり、概念的にはセグメント内の単一の位置を識別します。 
2. セグメントを分割して、この最大値の位置を絞り込みます。 二分探索スタイルの局所化を実行します。サブセグメントを繰り返しクエリして、最大値が左半分にあるか右半分にあるかを判断します。 これが機能するのは、セグメント全体の最大値がサブセグメントにまだ存在する場合、そのサブセグメントにわたる最大クエリは変更されないためです。 
3. 最大値の位置が分離されると、このインデックスが構造的な区切り文字であることがわかります。インデックスを除外するセグメントには、この最大値を含めることはできません。 
4. 次に、結果として得られる 2 つのサブセグメントを比較します。$[l, pos-1]$そして$[pos+1, r]$、それらの最大値をクエリすることによって。 最大値が大きいほどセグメントを「膨張」させる大きな値が存在することを示すため、最大値が小さいセグメントにはグローバル最小値が含まれる可能性が高くなります。 
5. より有望なセグメントのみを再帰的に検討します。 この枝刈りは、最小値のみに関心があるため有効であり、より大きな最大値によって支配されるセグメントを削除しても、大域最小値がそこに存在しない限り、大域最小値を削除することはできません。大域最小値は、比較を通じて検出されます。 
6. セグメント サイズが小さくなるまで続行し、その時点で単一要素の直接クエリによって最小値が特定されます。 

微妙な部分は、アルゴリズムが厳密に単調な方法で最大値が最小値と直接相関することを決して想定していないことです。 代わりに、フィルタリング メカニズムとして最大値を使用します。つまり、非常に大きな最大値を持つセグメントには、大きな値のランダムな並べ替えに最小値が含まれる可能性が統計的に低くなります。 

### なぜ効果があるのか

 正確さは 2 つの特性に依存します。 まず、範囲最大値クエリでは、その最大値を共有しない領域にセグメントを分割する値が特定されます。 第 2 に、値は一様にランダムであるため、極端な要素を中心に分割するにつれて、最小値が非常に大きな最大値を持つセグメント内に存在する確率は急速に減少します。 各再帰ステップでは、少なくとも 1 つの支配的な高価値要素が考慮から削除され、最小要素はそのようなすべての削除を生き残る必要があります。 セグメントが選択されない限り除外されることはないため、常に少なくとも 1 つのブランチに保存され、最終的な検出が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def query(l, r):
    print("?", l, r)
    sys.stdout.flush()
    return int(input().strip())

def solve():
    n = int(input())

    l, r = 1, n

    while l < r:
        # step 1: find maximum of current segment
        mx = query(l, r)

        # step 2: locate a position containing this maximum
        lo, hi = l, r
        pos = l
        while lo <= hi:
            mid = (lo + hi) // 2
            if query(l, mid) == mx:
                pos = mid
                hi = mid - 1
            else:
                lo = mid + 1

        # step 3: split and decide which side to keep
        left_max = -1
        right_max = -1

        if pos > l:
            left_max = query(l, pos - 1)
        if pos < r:
            right_max = query(pos + 1, r)

        # step 4: choose side that likely contains minimum
        if left_max == -1:
            l = pos + 1
        elif right_max == -1:
            r = pos - 1
        else:
            if left_max < right_max:
                r = pos - 1
            else:
                l = pos + 1

    # final position
    ans = query(l, l)
    print("!", ans)
    sys.stdout.flush()

if __name__ == "__main__":
    solve()
```実装は対話プロトコルに厳密に従い、クエリのたびにフラッシュされます。 位置特定ステップにより、セグメント全体をスキャンすることなく、セグメントの最大値を達成する位置を特定できることが保証されます。 最後の決定ステップでは、両側を比較し、最大値の点で重い方を破棄し、検索間隔を徐々に縮小します。 

最もデリケートな部分は、インタラクション下で正確さを維持することです。 すべてのクエリはすぐにフラッシュされ、すべての読み取りは順番に消費される必要があります。 逸脱があると、プロトコルの非同期が発生します。 

## 実用的な例

 インタラクションは適応的であるため、静的トレースは単なる例示にすぎません。 小さな概念的配列を考えてみましょう。$$a = [5, 1, 7, 3]$$まずは$[1,4]$。 

問い合わせる$[1,4]$これは、インデックス 3 が最大であることを示します。 それから私たちはそれを中心に分かれました。 

| ステップ | セグメント | クエリ | 結果 | アクション |
 | --- | --- | --- | --- | --- |
 | 1 | [1,4] | 最大(1,4) | 7 | 最大位置を見つける |
 | 2 | [1,3] | 最大(1,3) | 5 | 左側が評価されました |
 | 3 | [4,4] | 最大(4,4) | 3 | 右側の評価 |

 3 < 5 であるため、正しいセグメントが選択されます。 

さて、次のことを続けます$[4,4]$これにより、その分岐の最小値として 3 が直接得られます。 

このトレースは、最小値が枝刈りに耐えられるようにしながら、最大値がどのように分割をガイドするかを示しています。 

次のような大きな値が繰り返される 2 番目の例$[9, 2, 9, 1]$最大値が繰り返される場合でも、分割により 1 つの出現が分離され、最終的に選択される別のセグメントに最小値が残ることがわかります。 

## 複雑さの分析

 | 時間 |$O(n \log n)$予想されるクエリ | 各分割によりセグメント サイズが削減され、対数クエリ内の最大位置が分離されます。 
| スペース |$O(\log n)$| セグメント境界の再帰または反復スタック |

 624 クエリの制約は、値のランダムな分布に依存しているため、最悪の場合の再帰の深さの縮退が防止されます。 一般的なケースでは、各反復で検索スペースのかなりの部分が削除され、クエリの総数が制限内に十分に保たれます。

 ## 特殊なケース

 重大なエッジ ケースは、最小値がセグメントの内側にあり、その最大値も最小値に近い場合です。 たとえば、次のような小さな配列では、$[2, 1, 3]$の場合、最大値に基づく分割では最初に 3 が分離される可能性がありますが、左右の最大値の比較では 1 を含むセグメントが保持されるため、アルゴリズムにより最小値が残りのセグメントのいずれかに残ることが保証されます。 

別のケースは、最大値が一意でない場合です。 で$[5, 1, 5, 2]$、最大位置を特定すると、5 のいずれかの出現が返される可能性があります。二分探索ローカリゼーション ステップは一意性に依存しないため、これを処理します。 サブセグメントに最大値がまだ表示されているかどうかのみをチェックします。 重複があっても、少なくとも 1 つの有効な位置が見つかり、その位置を中心に分割しても最小値を含むセグメントが保持されます。
