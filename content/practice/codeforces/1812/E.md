 ## 解決策
 ## 問題の理解

 3 次元空間の座標として解釈される 3 つの整数が与えられます。 タスクは、これら 3 つの値から導出される単一の実数を計算することです。サンプル出力は、この量が何を表すかを明らかにします。これは、原点から点までのベクトルのユークリッド長です。$(x, y, z)$。 

幾何学的には、これはからの直線距離です。$(0, 0, 0)$に$(x, y, z)$。 代数用語では、この距離は完全に 3 次元に拡張されたピタゴラスの定理によって決定されます。 

制約は非常に小さく、各座標は -1000 ～ 1000 の間に制限されています。これにより、平方を含むあらゆる演算が 32 ビット整数の制限内に問題なく収まることがすぐにわかります。 計算は定数時間であるため、パフォーマンスを心配する必要はありません。 

この種の問題の主な微妙な点は、計算の複雑さではなく、数値の精度です。 整数演算を使用した単純な実装は、二乗ステップまでは安全ですが、最後の平方根は浮動小数点で計算する必要があります。 実装が間違っている場合、特に整数の除算や丸めを組み合わせるのが早すぎる場合、結果がずれる可能性があります。 

標識の処理以外に実際の構造的なエッジケースはありません。 二乗すると符号情報が削除されるため、次のように入力します。$(1000, -1000, 0)$～と同じように振る舞う$(1000, 1000, 0)$。 唯一重要な境界ケースは、すべての入力がゼロの場合であり、出力は正確にゼロになるはずです。 

よくある間違いは、手動で、または整数平方根ロジックを使用して値を近似しようとすることです。これにより、必要な精度が失われます。 

## アプローチ

 ブルートフォースの観点は、幾何学の観点から考えることです。つまり、空間内の 2 点間の距離を、直交成分に分解することで測定します。 軸に沿った動きをシミュレートして距離を累積することを想像するかもしれませんが、軸は垂直であるため、正しい集計ルールは固定されており、各座標は二乗を通じて独立して寄与します。 

単純ですがそれでも正しいアプローチは、各座標の二乗を合計し、平方根を取ることによって二乗距離を明示的に計算することです。 これはすでに最適な数学的定式化です。 反復的な幾何学的構築やシミュレーションなど、さらに分解しようとする試みは不必要なオーバーヘッドであり、解決策を複雑にするだけです。 

重要な観察は、3 次元のユークリッド ノルムが次のように直接定義されていることです。$$\sqrt{x^2 + y^2 + z^2}$$このアイデンティティを超えた隠された構造はありません。 問題は本質的に、これが 3D 空間における距離公式の直接の適用として認識されるかどうかをテストすることです。 

したがって、解決策は、二乗和の後に平方根を計算することになります。

 ## アルゴリズムのチュートリアル

 1. 3 つの整数を読み取ります$x, y, z$。 これらは、原点を基準とした 3D 空間内の点を表します。 
2. 各座標の二乗寄与を個別に計算します。 これにより、各軸コンポーネントが結合される前に分離されます。 
3. 二乗値を合計して、原点からの二乗ユークリッド距離を取得します。 
4. この合計の平方根を計算して、実際の幾何学的距離を回復します。 
5. 結果をデフォルトの精度の浮動小数点数として出力します。許容誤差が非常に大きいため、これで十分です。 

### なぜ効果があるのか

 ユークリッド距離の公式は、ピタゴラスの定理を繰り返し適用することで得られます。 まず、中の距離は、$xy$-飛行機は$\sqrt{x^2 + y^2}$。 これを 3 次元に拡張すると、その平面距離は高さのある直角三角形の 1 本の脚として扱われます。$z$、与える$\sqrt{(x^2 + y^2) + z^2}$。 2 乗では方向が排除され、大きさが保存されるため、累算の順序は正確さに影響しません。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

def solve():
    x, y, z = map(int, input().split())
    ans = math.sqrt(x*x + y*y + z*z)
    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションは、一定時間で入力を読み取り、すぐにユークリッド ノルムの公式を適用します。 使用する`math.sqrt`正しい浮動小数点動作を保証します。 効率を上げるために、べき乗の代わりに乗算が使用されますが、ここでは両方とも同等です。 

ループや分岐がないため、実装は最小限で済み、off-by-one または累積エラーのリスクが回避されます。

どちらの場合も、計算は幾何学的な期待に沿って一貫して動作し、特別な場合の処理​​が必要ないことがわかります。

## テストケース```python
import sys, io
import math

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    x, y, z = map(int, sys.stdin.readline().split())
    return str(math.sqrt(x*x + y*y + z*z))

# provided sample
assert abs(float(run("1 1 1\n")) - 1.7320508075688772) < 1e-9

# origin
assert abs(float(run("0 0 0\n")) - 0.0) < 1e-9

# axis-aligned
assert abs(float(run("3 0 0\n")) - 3.0) < 1e-9

# mixed signs
assert abs(float(run("-3 4 12\n")) - 13.0) < 1e-9

# symmetric point
assert abs(float(run("1000 1000 1000\n")) - math.sqrt(3000000)) < 1e-6
```| テスト入力 | 期待される出力 | 検証内容 |

 ## 特殊なケース

 入力用`0 0 0`、アルゴリズムは次のように計算します。$0^2 + 0^2 + 0^2 = 0$であり、平方根はちょうど 0 です。実装では、特別な分岐を行わずにこれを自然に処理します。`math.sqrt(0)`0を返します。 

負の座標の場合、`-3 4 12`、二乗により、集計前に符号が確実に削除されるため、計算は次のように進行します。$9 + 16 + 144 = 169$これにより、方向は大きさに影響せず、符号の条件付き処理が必要ないことが確認されます。 

次のような大きな等しい入力の場合、`1000 1000 1000`の場合、二乗和は 3,000,000 になり、Python の倍精度演算の浮動小数点精度の範囲内に安全に収まります。 アルゴリズムは必要な許容範囲内で精度を失うことはなく、出力は安定したままになります。
