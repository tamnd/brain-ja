 ## 解決策
 ## 問題の理解

 それぞれが小文字の文字列で構成される一連のテスト ケースが与えられます。 タスクは、文字列ごとに、それが非表示のプロパティを満たすかどうかを判断することです。 サンプルの入力と出力を見ると、このプロパティは通常の意味での数値ベースまたはパターンベースではなく、文字の相対的な順序に関係しています。 具体的には、次のような文字列`big`、`clump`、 または`i`で受け入れられます`YES`、 その間`flashing`、`passunder`、 または`bucketpotato`で拒否されます`NO`。 

制約は小さく、各文字列の長さは最大 100、テスト ケースの数は最大 25 です。これは、最悪の場合でも合計 2500 文字を処理するため、必要に応じて O(n²) 解が実現可能であることを示しています。 ただし、この問題には、各文字列の線形パスを可能にする構造的な特性があるようです。 

明らかではないエッジ ケースには、単一文字の文字列や、文字が繰り返されたり、順序が逆になったりする文字列が含まれます。 たとえば、文字列`i`簡単に受け入れられます (`YES`）、 その間`aa`または`zz`繰り返しがプロパティに違反するかどうかを慎重にチェックする必要があります。 

課題は、プロパティが何を決定するかを推測することにあります`YES`対`NO`純粋に例に基づいています。 検査後、パターンが明らかになります。文字列の文字は、位置をスキップすることなく、各文字が前の文字の左または右に 1 ステップとなる「山」パス上に配置できます。 手紙が、現在のパスの終点ではなく、すでに占有されている位置に足を踏み入れる必要がある場合、答えは次のとおりです。`NO`。 

## アプローチ

 強引なアプローチは、行に沿って文字の可能な配置をすべて生成して、競合を回避する配置があるかどうかを確認することです。 具体的には、文字ごとに、文字列内の既存のすべての文字の左または右に配置して、衝突するかどうかを確認できます。 これは文字列が短いため機能しますが、実装するのがすぐに面倒になり、概念的に面倒になります。 最悪の場合の操作数は文字列の長さに対して指数関数的になるため、長さ 100 の文字列では実行できません。 

重要な洞察は、既に配置した文字の左端と右端の位置を追跡するだけでよいことを認識することです。 新しい文字ごとに、それが現在の両端 (左または右に 1 ステップ) に隣接している場合、「山」を拡張できます。 すでに内部のどこかに配置されている場合は、スキップできます。 しかし、それが極端に拡張できない位置に現れた場合、その性質は侵害されます。 これにより、現在のパスとそれまでに配置された文字のセットを覚えていればよいだけなので、問題は文字ごとの定数時間チェックによる文字列の線形スキャンに軽減されます。 

考えられるすべての配置の検討から極端な部分のみの追跡への移行により、単純な O(n) ソリューションが可能になります。

 ## アルゴリズムのチュートリアル

 1. 山道を表すために空の両端リストを初期化し、すでに道上にある文字を追跡するために空のセットを初期化します。 これにより、両端での効率的な拡張が可能になります。 
2. 文字列を 1 文字ずつ繰り返します。 各キャラクターがすでに配置されているかどうかを確認します。 存在する場合は、次の文字にスキップします。 これにより、繰り返される文字が正しく処理されます。 
3. 文字が新しい場合は、現在のパスの左端および右端の文字と比較します。 (辞書編集的に) 左端より 1 つ小さい場合、または右端より 1 つ大きい場合は、対応する末尾に追加します。 それ以外の場合は、プロパティに違反しているため、出力されます。`NO`。 
4. すべての文字を処理した後、違反が発生しなかった場合は、出力`YES`。 

これが機能する理由: 不変条件は、どの時点でも、両端キューに格納されているパスはアルファベットの連続したセグメントを表し、すべての新しい文字はどちらかの端でこのセグメントを拡張する必要があるということです。 文字が現在のセグメントを拡張できない場合は、既存の文字を「飛び越える」必要がありますが、登山者の敷地ではこれが禁止されています。 したがって、文字列を 1 回通過するだけで正確さを判断できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        s = input().strip()
        if len(s) == 1:
            print("YES")
            continue
        path = [s[0]]
        used = {s[0]}
        ok = True
        for c in s[1:]:
            if c in used:
                continue
            if ord(c) == ord(path[0]) - 1:
                path.insert(0, c)
                used.add(c)
            elif ord(c) == ord(path[-1]) + 1:
                path.append(c)
                used.add(c)
            else:
                ok = False
                break
        print("YES" if ok else "NO")

if __name__ == "__main__":
    solve()
```コードの各セクションはアルゴリズムのステップに正確に従っています。 初期化中`path`そして`used`山を築き、手紙を追跡します。 隣接性に基づいて左端または右端に挿入し、偽陰性を避けるためにすでに使用されている文字をスキップします。 慎重な使用`ord`比較により、辞書編集上の隣接性が確実に尊重されます。

## 特殊なケース

 次のような 1 文字の文字列の場合`i`、アルゴリズムが初期化されます`path`そしてすぐに出力します`YES`それ以上のチェックなしで。 次のような繰り返しの文字の場合`aaaaa`、アルゴリズムは重複をスキップし、山のプロパティに違反することはありません。 次のようなトリッキーな文字列の場合`azb`、最初の文字`a`パスを初期化します。`z`どちらの端でもパスを延長できません。`b`もブロックされるため、`NO`。 これにより、不変条件が確認されます。すべての文字は現在のパスの終点に配置されるか、すでに存在する必要があります。
