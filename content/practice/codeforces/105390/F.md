 ## 解決策
 ## 問題の理解

 各ノードが 2 つの独立した情報 (赤または青のいずれかの色と正の重み) を保持するツリーが与えられます。 ツリー全体を見ると、その美しさと呼ばれる単一のスコアを計算できます。これは、すべての赤いノードの合計重みからすべての青いノードの合計重みを引いたものとして定義されます。 

ツリーが有効または「完璧」であると呼ばれるのは、ツリーに少なくとも 1 つの赤いノードと少なくとも 1 つの青いノードが含まれており、その美しさがマイナスではない場合に限られます。 木を取り出してエッジを削除し始めると、それが森に分割されます。 森が不良であるとみなされるのは、その接続されているコンポーネントのどれもが完璧なツリーではない場合、つまり、すべてのコンポーネントが 1 つの色しか持たないか、マイナスの美しさ、あるいはその両方を持っている場合だけです。 

タスクは、削除後に結果として得られるフォレスト内の接続されたコンポーネントが完全なものにならないように、できるだけ少ないエッジを削除することです。 

n が 8000 までという制約は、およそ n 乗または n 対数 2 乗のアプローチは可能ですが、3 次的なものやエッジのすべてのサブセットを列挙することは不可能であることを意味します。 構造はツリーであるため、すべてのエッジの削除を直接試みるソリューションは指数関数的に爆発的に増加します。これは、k 個のエッジを削除するとすでに 2^k 個の可能性が生じるためです。 

コンポーネントが混在すると微妙な問題が発生します。コンポーネントは 3 つの異なる方法で無効になる可能性があります。 モノクロになるかもしれないし、ネガティブな美しさになるかもしれないし、その両方かもしれない。 グローバルな美しさだけ、または接続性だけをチェックする単純なアプローチは、分割によって非ローカルな方法で完全なコンポーネントが破壊されたり作成されたりする可能性があるため、失敗します。 

具体的な失敗例として、構造全体が肯定的な美しさを持っているが、すでに完璧なサブツリーが存在するツリーを考えてみましょう。 ランダムなエッジを削除すると、そのサブツリーが分離され、その完全性が維持される可能性がありますが、別のカットでは、青と赤の分布が異なるように混合されてサブツリーが破壊される可能性があります。 したがって、エッジを独立して扱うことはできません。 

## アプローチ

 ブルートフォースのアイデアでは、エッジのすべてのサブセットの削除を試み、結果として得られるすべてのコンポーネントを計算し、コンポーネントが完璧かどうかを確認します。 k 個のエッジだけを切断しようとしても、それらの切断によって引き起こされるツリーの分割を列挙する必要があります。 エッジの決定ごとに接続がグローバルに変化するため、これは n で急速に指数関数的になります。 

重要な観察は、「完全性」は接続されたサブツリーの特性であり、エッジを削除してもツリーが分割されるだけであるということです。 したがって、任意のフォレストについて考える代わりに、残りのすべてのコンポーネントが両方の条件、つまり両方の色と負でない総重量の差を同時に満たすことを避けるために、最先端の観点から考えることができます。 

これは標準的な再定式化につながります。最終的なフォレスト内のすべての接続コンポーネントが単色になるか、ネガティブな美しさになるようにしたいのです。 最先端のエッジは接続を制限するだけなので、完璧である可能性のあるすべてのサブツリーを「破壊」しようとしています。 

これは、ツリー DP の観点を示唆しています。各サブツリーについて、いくつかのカット後に有効なコンポーネントとして存在できるかどうか、およびそれが完全ではないことを確認するためにどのようなコスト (カット数) が必要かを理解したいと考えています。 赤と青のカウントと和符号の間の相互作用は、サブツリー内の集合的な寄与を維持し、ポジティブな構成を壊すためにエッジをカットするかどうかを決定することを自然に示唆しています。 

最適なソリューションは、ツリーをルート化し、ノードごとに、そのサブツリーが完全なコンポーネントを形成できるか、または完全なコンポーネントに寄与できるかどうかを計算することによって機能します。 サブツリーが潜在的に完璧な構成を形成できる場合は常に、親との接続を切断する必要が生じる可能性があり、そのような強制的な切断を最小限に抑えることが目標となります。 問題は、赤と青の組み合わせが両方の色を含みながらも負ではない最大の「危険な」サブツリーを特定することに帰着します。

 | 有効なサブツリーを強制的にカットしたツリー DP | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ノード 1 でツリーをルート化し、事後 DFS を使用してサブツリー情報を計算します。 

1. 各ノードについて、そのサブツリーから 2 つの集計値を計算します。つまり、赤ノードと青ノードの合計の重みの差と、サブツリーに少なくとも 1 つの赤ノードと少なくとも 1 つの青ノードが含まれるかどうかです。 これら 2 つの値は、サブツリー自体がスタンドアロン コンポーネントとして考慮された場合に完全なツリーであるかどうかを完全に決定します。 
2. DFS 中に、最初はすべてのエッジを保持すると仮定します。 各子サブツリーについて、その子をルートとするサブツリーが、現在のノードに接続されたときに、それ自体で完全なコンポーネントを形成できるかどうかを確認します。 「はい」の場合は、上向きにマージするか、切り取るかの選択があります。 
3. 子サブツリーを現在のコンポーネントにマージすることで色とマイナスでない全体的な美しさの両方が維持される場合、そのマージされた構造は完全な候補となるため「危険」になります。 これを防ぐために、その子エッジをカットすることを好みます。 カットごとに答えが 1 つずつ増えます。 
4. マージによって完全な構造が作成されない場合は、現在のノードの集計値にサブツリーの寄与を追加することで、サブツリーを上方向に安全にマージします。 
5. すべての子を処理した後、現在のサブツリーの集約された状態をその親に返します。これは、以下に完璧なコンポーネントを導入することなく、達成可能な最良の構成を表します。 
6. 最終的な答えは、DFS 中に行われた強制カットの合計数です。 

### なぜ効果があるのか

 核となる不変条件は、ノードの処理後、その親に返されるサブツリーには、まだ内部的に接続されている完全なコンポーネントが含まれていないことが保証されるということです。 完璧なコンポーネントを作成する構成は、それを可能にするエッジを切断することですぐに分離されます。 各カットは、子サブツリーが有効な完全な構造に寄与する場合にのみ行われるため、不必要にカットすることはなく、残りのすべての接続コンポーネントは構築上安全です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    s = input().strip()

    g = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    # color: 0 red, 1 blue
    color = [0 if c == '0' else 1 for c in s]

    # we maintain:
    # sumDiff = sum(red a) - sum(blue a)
    # hasRed, hasBlue
    sys.setrecursionlimit(10**7)

    ans = 0

    def dfs(u, p):
        nonlocal ans
        sum_diff = a[u] if color[u] == 0 else -a[u]
        has_red = (color[u] == 0)
        has_blue = (color[u] == 1)

        for v in g[u]:
            if v == p:
                continue
            c_diff, c_red, c_blue = dfs(v, u)

            new_diff = sum_diff + c_diff
            new_red = has_red or c_red
            new_blue = has_blue or c_blue

            # if merging would make a perfect component, cut
            if new_red and new_blue and new_diff >= 0:
                ans += 1
                continue

            sum_diff = new_diff
            has_red = new_red
            has_blue = new_blue

        return sum_diff, has_red, has_blue

    dfs(0, -1)
    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、ツリー上で単一の DFS が実行されます。 各ノードは、情報を上方にバブリングしている間、符号付き合計の寄与、および蓄積されたサブツリーに赤と青の両方が表示されるかどうかという 3 つの値を維持します。 重要な決定点は、子サブツリーを現在のノードと結合するときに発生します。 マージされた状態がすでに完全なツリーの条件を満たしている場合、そのエッジはマージされずに削除されます。 

微妙な点は、カットされたサブツリーを後で再検討することは決してないということです。 エッジが切断されると、そのサブツリーは分離され、祖先コンポーネントに影響を与えることができないため、これは有効です。 

## 実用的な例

 ### 例 1

 すべてを結合すると完璧な構造が生成される小さな木を考えてみましょう。 

| ノード | 処理された子 | 合計の差分 | は_赤 | 青がある | アクション |
 | --- | --- | --- | --- | --- | --- |
 | 葉1 | - | +2 | た | ふ | 開始 |
 | 葉2 | 葉1 | +2+(-3) | た | た | キープ |
 | ルート | 葉2 | 有効なマージ | た | た | サインに応じて切るか残すか |

 DFS はサブツリーを上向きにマージしようとしますが、マージされた状態が負でない合計で両方に色付けされると、エッジがカットされます。 これは、アルゴリズムがグローバルではなくローカルで完全なコンポーネントの形成をどのように妨げるかを示しています。 

### 例 2

 複数のカットが必要な場合：

 | ステップ | サブツリー | マージされた状態 | 決定 |
 | --- | --- | --- | --- |
 | 1 | 子供A | 完璧 | カット |
 | 2 | 子供B | 完璧 | カット |
 | 3 | ルート | 分離されたコンポーネント | 完了 |

 これは、独立した危険なサブツリーが個別に処理され、それぞれが強制的に 1 回だけカットされることを示しています。

 ## 特殊なケース

 重要なエッジケースは、すべてのノードが同じ色を持つ場合です。 この場合、「両方の色が存在する」という要件を満たすコンポーネントは存在しないため、答えはゼロでなければなりません。 DFS がカットをトリガーすることはありません。`has_red and has_blue`は常に偽です。 

別のエッジ ケースは、すべてのノードが大きな重みを持つチェーンに沿って色を交互に切り替える場合に発生します。 ここでは、マージによって色と非負の和の両方を満たす可能性が徐々に高まるため、複数のレベルでカットが発生する可能性があります。 このアルゴリズムは、マージされた状態が完全になるたびにサブツリーを正しく分離し、隠された完全なコンポーネントが構造の奥深くに残らないようにします。
