 ## 解決策
 ## 問題の理解

 一列に並んで座っている学生の回答を表す整数の配列が与えられます。 各クエリは、1 人の生徒の答えを変更するか、仮説的な正解値とともに連続する生徒のセグメントについて尋ねます。`x`。 

最初のタイプのクエリでは、指定された間隔内の学生のみを想定します。`[l, r]`参加しました。 これらの生徒の中で、各生徒の答えがどれだけ近いかを計算します。`x`絶対差を使用します。 までの距離にある学生のみ`x`セグメント全体の中で最小値が「合格」としてカウントされます。 

したがって、範囲クエリのタスクは、近くの値をカウントすることではありません。`x`ただし、最初に、への可能な最小距離を決定します。`x`セグメント内で、正確にその距離に達する要素の数を数えます。 

2 番目のクエリは、配列内の 1 つの位置を更新し、生徒の回答を新しい値に置き換えます。 

この制約により、合計で最大 20,000 の操作が可能になり、値は動的に変更できます。 これにより、セグメントをスキャンすることによる各クエリの答えの再計算が即座に除外されます。これは、最悪の場合は 2 次計算になるためです。 範囲クエリとポイント更新の両方が高速である必要があるため、クエリごとの対数構造であっても慎重に制御する必要があります。 

微妙な問題は、各クエリがローカルな比較だけではなく、範囲内のグローバルな最小距離に依存することです。 単純な間違いは、次の値に最も近い値だけが必要だと考えることです。`x`グローバルですが、親密さは内部の要素間でのみ測定する必要があります`[l, r]`、クエリごとに変化します。 

もう 1 つのよくある落とし穴は、多重性を忘れることです。 複数の生徒が同じ最も近い値を共有する場合は、全員をカウントする必要があります。 

素朴なソリューションを壊すエッジケースには、すべての値が同一であるセグメントが含まれます。`x`範囲のはるか外側にあり、更新によって後のクエリに関連する新しい極値が導入される場所です。 たとえば、セグメントが`[1, 10, 100]`そして`x = 50`、 両方`10`そして`100`は同等に近いため、両方ともカウントする必要があります。 単一の最も近い値のみを追跡するメソッドは、誤った値を返します。`1`の代わりに`2`。 

## アプローチ

 クエリの直接的な解決策は、次のすべてのインデックスを反復処理します。`[l, r]`、絶対差を計算して、`x`、最小距離を追跡し、それに一致する数を数えます。 これは文字通り定義に従っているので正しいです。 ただし、各クエリには以下の点が含まれる場合があります。`n`要素があるため、最大で`2 · 10^5`クエリの合計作業量は次のようになります。`10^10`、これは実現可能な限界をはるかに超えています。 

重要な観察は、固定セグメントでは、相対的に重要な値のみが重要であるということです。`x`以下の最も近い値です`x`かつ最も近い値以上の値`x`。 他のすべての要素は、これら 2 つの境界候補の少なくとも 1 つよりも厳密に遠いです。 これにより、問題は、ダイナミック レンジ内で、前のものと後のものを見つけることになります。`x`、同じ最小距離に達する場合は、それらの値の出現をカウントします。 

範囲クエリとポイント更新の両方が必要なため、ソートされたコンテナーを含むセグメント ツリーや、より複雑な順序統計構造も可能ですが、効率的に実装するには重くなることがよくあります。 より単純で十分に高速なアプローチは、配列をブロックに分割する平方根分解です。 各ブロックはその要素をソートされた順序で維持し、ブロック内でのバイナリ検索を可能にします。 

クエリでは、範囲と交差する各ブロックを調べます。 各ブロックから、そのローカルの最良の先行および後続候補を相対的に抽出します。`x`。 すべてのブロックにわたって、これらの候補をマージして、その範囲のグローバルな先行および後続を取得します。 最小距離がわかったら、ブロック上で別のパスを実行して、勝利値と等しい要素の数を数えます。 

更新は 1 つのブロックにのみ影響し、古い値を削除し、新しい値をソート順に挿入します。

 | クエリごとのブルート フォース スキャン | O(nq) | お(1) | 遅すぎる |
 | 二乗分解 | O((n + q) √n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列をおよそ √n のサイズのブロックに分割し、元のストレージに加えて各ブロックをソートしたままにします。 並べ替えにより、ブロック内での高速な先行クエリと後続クエリが可能になります。 
2. セグメントに対するクエリの場合`[l, r]`そして価値観`x`、セグメントと交差する各ブロックを処理し、そのブロック内の 2 つの候補 (最大値 ≤ x と最小値 ≥ x) を計算します。 ブロック内の他の要素はブロックから遠く離れているため、これらはそのブロックから可能な最良の一致を表します。`x`。 
3. すべてのブロック候補を結合して、その範囲内でグローバルな先行および後続を決定します。`[l, r]`。 先行者はすべてのローカル先行者の中で最大であり、後継者はすべてのローカル後継者の中で最小です。 
4. 可能な限り最適な距離を、次の小さい方として計算します。`x - predecessor`そして`successor - x`、欠落している候補者を無視します。 
5. どちら側が最適な距離を与えるかを決定します。 両側が同等に優れている場合、対応する両方の値が関連します。 
6. 内部で選択した値の出現をカウントします。`[l, r]`ブロックのスキャンによる: 完全にカバーされたブロックはソートされた配列の二分探索を介して寄与しますが、部分的なブロックは要素ごとにチェックされます。 
7. 更新するには、インデックスを含むブロックを見つけます。`i`、古い値を削除し、ソートされた順序で新しい値を挿入し、メイン配列を更新します。 

正確さは、一連の数値の中で最も近い値が存在するという事実に基づいています。`x`下から最も近い要素、または上から最も近い要素のいずれかである必要があります。 各ブロック内では正確な順序が維持されるため、これらの局所的な極値は十分な代表値となります。 ブロックレベルの極値を集約すると、全範囲にわたって真のグローバル極値が保存されます。 

## Python ソリューション```python
import sys
import bisect
import math

input = sys.stdin.readline

class SqrtDecomposition:
    def __init__(self, arr):
        self.n = len(arr)
        self.arr = arr[:]
        self.B = int(math.sqrt(self.n)) + 1
        self.blocks = []
        
        for i in range(0, self.n, self.B):
            block = arr[i:i+self.B]
            block.sort()
            self.blocks.append(block)

    def rebuild_block(self, b_idx):
        l = b_idx * self.B
        r = min(self.n, l + self.B)
        self.blocks[b_idx] = sorted(self.arr[l:r])

    def update(self, i, val):
        b = i // self.B
        l = b * self.B
        r = min(self.n, l + self.B)

        old = self.arr[i]
        self.arr[i] = val

        block = self.blocks[b]
        block.pop(bisect.bisect_left(block, old))
        bisect.insort(block, val)

    def query_candidates(self, l, r, x):
        B = self.B
        best_le = -10**30
        best_ge = 10**30

        i = l
        while i <= r:
            if i % B == 0 and i + B - 1 <= r:
                b = i // B
                block = self.blocks[b]

                idx = bisect.bisect_right(block, x) - 1
                if idx >= 0:
                    best_le = max(best_le, block[idx])

                idx = bisect.bisect_left(block, x)
                if idx < len(block):
                    best_ge = min(best_ge, block[idx])

                i += B
            else:
                val = self.arr[i]
                if val <= x:
                    best_le = max(best_le, val)
                if val >= x:
                    best_ge = min(best_ge, val)
                i += 1

        return best_le, best_ge

    def count_value(self, l, r, val):
        B = self.B
        res = 0
        i = l

        while i <= r:
            if i % B == 0 and i + B - 1 <= r:
                b = i // B
                block = self.blocks[b]
                res += bisect.bisect_right(block, val) - bisect.bisect_left(block, val)
                i += B
            else:
                if self.arr[i] == val:
                    res += 1
                i += 1

        return res

def solve():
    n, q = map(int, input().split())
    arr = list(map(int, input().split()))
    sd = SqrtDecomposition(arr)

    out = []

    for _ in range(q):
        tmp = input().split()
        if tmp[0] == '1':
            l = int(tmp[1]) - 1
            r = int(tmp[2]) - 1
            x = int(tmp[3])

            le, ge = sd.query_candidates(l, r, x)

            d = 10**30
            if le != -10**30:
                d = min(d, x - le)
            if ge != 10**30:
                d = min(d, ge - x)

            ans = 0
            if le != -10**30 and x - le == d:
                ans += sd.count_value(l, r, le)
            if ge != 10**30 and ge - x == d:
                ans += sd.count_value(l, r, ge)

            out.append(str(ans))

        else:
            i = int(tmp[1]) - 1
            val = int(tmp[2])
            sd.update(i, val)

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装は、先行クエリと後続クエリがブロック内で対数になるように、各ブロックをソートされた順序で維持することを中心に展開されます。 更新操作では、順序を維持するために新しい値を挿入する前に、バイナリ検索を使用して古い値を慎重に削除します。 

クエリ ロジックは、問題を 2 つのフェーズに分けます。まず、`x`、そして実際に勝ちの距離に一致する要素の数を数えます。 この分離により、すべての要素の距離を個別に再計算する必要がなくなります。 

微妙な詳細は、`best_le`そして`best_ge`センチネルを使用すると、欠落している辺が距離の計算に誤って寄与しないことが保証されます。 

## 実用的な例

 単純な配列を考えてみましょう`[1, 10, 100, 1000]`全範囲に対するクエリを使用し、`x = 60`。 

ブロックを処理します (簡単にするために、ここでは 1 つのブロックであると仮定します)。 

| ステップ | ベストル | ベストゲ | アクション |
 | --- | --- | --- | --- |
 | 開始 | -inf | +inf | 初期化 |
 | スキャン値 | 10 | 100 | 10 ≤ 60 および 100 ≥ 60 |
 | 最終 | 10 | 100 | 特定された候補者 |

 距離をチェックすると、両方の距離が等しいことがわかります: 50。出現回数を数えると、10 回で 1 回、100 回で 1 回になるため、答えは 2 になります。 

次に、アップデートを検討します。 から始める`[5, 5, 5, 5]`、クエリ`[1,4], x = 5`。 

| ステップ | ベストル | ベストゲ | アクション |
 | --- | --- | --- | --- |
 | スキャン | 5 | 5 | 完全一致 |
 | 距離 | 0 | 0 | 同一 |
 | カウント | 4 | | すべての要素が貢献します |

 これは、先行と後続の両方が同じ値に折りたたまれるため、等しい値が自然に処理されることを示しています。

 ## 特殊なケース

 重要なエッジケースは、セグメント内のすべての値が同一である場合です。 その状況では、先行者と後続者の両方が同じ値に崩壊し、計算された距離はゼロになります。 両方の分岐が同じ最適値を検出するため、アルゴリズムはすべての出現を正確にカウントします。 

別のケースが発生するのは、`x`セグメント内のすべての値の範囲外にあります。 たとえば、セグメントが`[10, 20, 30]`そして`x = 100`、後継者側のみが貢献します。 先行する値は存在しないままであり、アルゴリズムは最小値を最も近い値として正しく選択します。 

最後の微妙なケースは、アップデートで新しい極端な値が導入された後に発生します。 各ブロックは常にソートされ、増分的に再構築されるため、新しく挿入された値は、グローバルな再構築を必要とせずに、将来の先行計算および後続の計算に直ちに参加します。
