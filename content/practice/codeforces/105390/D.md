 ## 問題の理解

 ターゲット文字列が与えられています$s$固定の秒数$m$。 空の文字列から始める$t$、毎秒、正確に 1 つの操作を適用します。 

1 回の操作で、選択した小文字が末尾に追加されます。$t$、他の操作では、 の最後の文字が削除されます。$t$それが存在する場合。 文字列がすでに空の場合、削除操作は何も行いません。 

まさにその後$m$演算の場合、最後の文字列は次と等しい必要があります$s$。 タスクは、長さの異なる操作シーケンスの数を数えることです。$m$正確に生産する$s$ここで、シーケンスが異なるのは、プッシュしたかポップしたか、どの文字をプッシュしたかなど、少なくとも 1 つのステップが異なる場合です。 

この制約により、すべての文字列とすべての操作数の合計の長さが最大 ​​8000 まで許可されます。 これにより、指数関数的なものはすべて除外されます$m$または、操作シーケンスを列挙しようとするもの。 テスト ケースごとの 2 次であっても、テスト全体でサイズの合計が小さいままである場合にのみ許容されます。 

微妙なエッジケースは、ポップと空虚の間の相互作用から生まれます。 空の文字列からポップしようとすると、操作は引き続き実行されますが、何も変更されません。 これは、先頭の余分なポップだけが異なるシーケンスは有効であり、区別されますが、状態は変更されないことを意味します。 もう 1 つの重要なケースは次のような場合です。$m < n$、長さの文字列を構築することが不可能になるため$n$未満で$n$ステップごとに最大 1 つずつサイズが増加する操作。 パリティや長さの実現可能性を無視した単純な実装では、ここで誤ってゼロ以外の答えが返される可能性があります。 

さらに間違いの原因は、スタックの動作を考慮せずにプロセスを単に「プッシュとポップの位置を選択する」ものとして扱うことです。 ポップは文字列が空でない場合にのみ有効であるため、カウントが一致してもプッシュとポップのすべての配置が有効であるとは限りません。 

## アプローチ

 重要な問題は、このプロセスは最終的な長さだけを重視するものではないということです。 これは、ポップによって最後に追加された文字が削除されるフルスタック プロセスであるため、厳密な LIFO 方式で順序が重要になります。 同時に、プッシュ操作には文字でラベルが付けられ、最終的な文字列は一致する必要があります。$s$その通り。 

強引なアイデアは、次のすべてのシーケンスを生成することです。$m$操作を実行し、スタックをシミュレートし、最終的な文字列が次と等しいかどうかを確認します。$s$。 各ステップには最大 27 の選択肢 (プッシュ用に 26 文字、ポップ用に 1 つ) があるため、これは次のように増加します。$O(27^m)$、それは完全に不可能です。 

有効なシーケンスの構造を圧縮する必要があります。 重要な観察点は、最後の文字列が$s$スタックの「保護された下部セグメント」のように動作します。 かつてのキャラクター$s$効果的に最終位置に配置され、取り外すことはできません。 その上にあるものはすべて、余分なプッシュやポップによって形成される一時的なノイズです。 

これにより、プロセスが 2 つの相互作用するレイヤーに分割されます。 最初の層は最終的な文字列の構築です$s$順番に。 2 番目のレイヤーは、アンダーフローしない限り、自由にプッシュおよびポップできる一時文字の補助スタックです。 最終的な答えは、これら 2 つのレイヤーの有効なインターリーブをすべて数えることによって得られます。$m$ステップ。 

これにより、時間の経過とともに自然に動的プログラミングの定式化が行われ、文字数を追跡することができます。$s$すでに修正されているか、および現在の一時スタックのサイズを確認します。 各ステップは、次の 3 つのアクションのうちの 1 つです。$s$、一時文字をプッシュするか、一時文字をポップします。

 ## アルゴリズムのチュートリアル

 いつでも重要なことを正確に捉える状態を定義します。 させて$i$何文字になるか$s$すでに修正されているので、$h$現在のスタックの合計の高さになります。 現在スタック上にある一時文字の数は暗黙的に$h - i$、底から$i$文字はすでに選択されているプレフィックスに対応します$s$。 

正確に DP を構築します$m$ステップ。 

1. 時間ゼロで何も操作を行わずにシステムを初期化します。$i = 0$そして$h = 0$、ウェイの数は 1 です。 
2. 各ステップで、状態から$(i, h)$では、3 つの可能な遷移を検討します。 1 つ目は、次の文字に対して強制一致プッシュを実行することです。$s$、両方を増加させます$i$そして$h$1つずつ。 これは、次に必要な文字を最終構造に配置することに対応します。 
3. 2 番目のトランジションでは、一時的なキャラクターがプッシュされます。 これでは進まない$i$、増加します$h$任意の小文字を選択できるため、乗算係数は 26 になります。 
4. 3 番目の遷移はポップ操作です。$h$ただし、固定プレフィックスの上に少なくとも 1 つの一時要素がある場合に限ります。つまり、$h > i$。 この制限により、最終文字列に属する文字は決して削除されなくなります。$s$。 
5. これらの遷移を正確に繰り返します$m$回、到達可能なすべての状態のカウントを累積します。 
6. すべてのステップを処理した後、答えは次の状態に到達する方法の数になります。$i = n$そして$h = n$、文字列全体を意味します$s$が構築され、一時的な要素は残りません。 

正しさは、いつでも最下位になるという不変条件から生まれます。$i$スタックの要素は正確に次のプレフィックスを形成します。$s$であり、すべての有効な遷移はこの構造を保持します。 ポップがこのプレフィックスを横切ることは禁止されているため、一時的な操作がこのプレフィックスに干渉することはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    tc = int(input())
    for _ in range(tc):
        n, m = map(int, input().split())
        s = input().strip()

        if m < n or (m - n) % 2 != 0:
            print(0)
            continue

        dp = [[0] * (m + 1) for _ in range(n + 1)]
        dp[0][0] = 1

        for _step in range(m):
            ndp = [[0] * (m + 1) for _ in range(n + 1)]

            for i in range(n + 1):
                for h in range(m + 1):
                    cur = dp[i][h]
                    if not cur:
                        continue

                    if i < n:
                        ni, nh = i + 1, h + 1
                        ndp[ni][nh] = (ndp[ni][nh] + cur) % MOD

                    ni, nh = i, h + 1
                    if nh <= m:
                        ndp[ni][nh] = (ndp[ni][nh] + cur * 26) % MOD

                    if h > i:
                        ni, nh = i, h - 1
                        ndp[ni][nh] = (ndp[ni][nh] + cur) % MOD

            dp = ndp

        print(dp[n][n] % MOD)

if __name__ == "__main__":
    solve()
```DP テーブルには、一定回数の操作後に各構成に到達する方法の数が格納されます。 各反復では 1 秒間のプロセスをシミュレートし、許可された 3 つの操作を使用してすべての状態を進めます。 境界により、高さが超えないことが保証されます$m$、以来$m$超えられないステップ$m$押します。 

微妙な点は、一時的なプッシュの場合に 26 を乗算することですが、これはそのような各操作での文字の選択を考慮しています。 これらの文字は後で削除されることが保証されているため、最後の文字列は影響を受けません。

 ## 特殊なケース

 いつ$m < n$の場合、どの一連の操作もスタック サイズを長さに達するほど速く増や​​すことができないため、アルゴリズムはそのケースを即座に拒否します。$n$。 空の状態で何もしない余分なポップを挿入しようとしても、必要なプッシュの欠落を補うことはできません。 

いつ$m - n$が奇数である場合、DP は、スタックの高さが必要な文字列長と等しい一貫した最終構成に到達することはありません。 すべての有効なシーケンスは、一時的な操作のペアでプッシュとポップのバランスをとる必要があるため、不一致はゼロであることが保証されます。 

次のように文字列が非常に小さい場合$n = 1$、DP では引き続き空のポップと一時的なプッシュの任意のシーケンスが許可されますが、すべての有効なパスは最終的に正しいプレフィックス深さで単一の必要な文字に解決される必要があります。
