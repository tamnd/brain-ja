 ## 問題の理解

 各位置が 0 または 1 であることを意味するバイナリ文字列が与えられ、非常に具体的なローカル変換を繰り返し適用することができます。 変換により中心位置が選択されます$i$(サイズに余裕が必要なので、どちらの端にも近づきすぎないでください)$k$両側）、次に長さのブロックを書き換えます$2k$その周り。 このブロックの左半分はすべて 1 になり、右半分はすべて 0 になります。 このような操作を任意の順序で任意の数だけ実行した後、最終的な文字列に存在する 1 の数を最大化したいと考えます。 

重要な点は、この操作は破壊的であると同時に建設的でもあるということです。 これは領域をすべて 1 に変換できますが、次の領域を即座に 0 に強制します。これは、個々のビットを単に反転するのではなく構造を導入することを意味します。 無限に何度も適用できるため、このプロセスはシーケンスをシミュレートすることではなく、どのような最終的な安定した構成が到達可能で最適であるかを理解することになります。 

制約$n \le 1000$そして$t \le 100$と提案する$O(n^2)$あるいは$O(n^2 \log n)$テストケースごとのアプローチが安全です。 立方体であれば境界線に達しますが、それでも許容できる可能性があります。 ただし、文字列を繰り返しスキャンしてすべての操作を単純にシミュレーションすると、各操作にコストがかかるとすぐに遅くなりすぎます。$O(n)$そして私たちはそれを何度も繰り返します。 

微妙な問題が境界に現れます。 操作に必要なのは$i \in [k, n-k]$つまり、エッジ近くの位置は選択できません。 たとえば、次の場合$k = 1$、すべての位置が有効であり、操作は非常に積極的になります。$i$隣接するものをすぐに上書きします。 もう 1 つの特殊なケースは、どの操作によっても 1 の数が改善されないという意味で文字列がすでに最適であるにもかかわらず、不注意で貪欲なシミュレーションを行うと依然として破壊的な更新を適用し続け、結果が減少する可能性がある場合です。 

小さな落とし穴の例としては、次のような文字列があります。$s = 1010$と$k = 1$。 貪欲にゼロを局所的に「修正」しようとすると、適切な構造が上書きされる可能性があります。 実際、最適なシーケンスでは 1 の数が一時的に増加し、その後安定する可能性があります。これは、グローバル アカウンティングを行わないローカルでの貪欲な決定が安全でないことを示しています。 

## アプローチ

 強引なアイデアは、プロセスを直接シミュレートすることです。 文字列の各状態について、すべての有効な中心を試します$i$、変換を適用し、結果が改善されなくなるまで続行します。 各操作により最大で変更されます$2k$文字があり、$O(n)$～の選択肢$i$。 改善点を繰り返しスキャンすると、最悪のケースでは次のような事態が発生する可能性があります。$O(n)$オペレーションと各オペレーションのコスト$O(n)$文字列をコピーまたは更新します。 これはおおよそ次のことにつながります$O(n^3)$テスト ケースごとの動作。これは不必要であり、たとえ$n = 1000$。 

操作の構造は、任意のシミュレーションよりも厳密なものを示唆しています。 各操作はローカル パターン、つまり左側が 1 に強制的に右側が 0 に強制されるブロックを強制します。そのような構造が出現すると、近くの領域を支配する傾向があります。つまり、ステップをシミュレートするのではなく、最終的な構成を構築する観点から考える必要があります。 

重要な観察は、この操作により、一定の長さのセグメントを効果的に「固定」できるということです。$k$1 秒間、同時に次の秒数を毒する$k$位置を 0 にします。 これにより、スライディング ウィンドウの動作が作成されます。つまり、中心を所定の位置に配置します。$i$連続した領域の運命を決定し、繰り返しの操作は、強制された 1 のブロックがどこから始まるかを選択していると解釈できます。 

遷移をシミュレートする代わりに、合計 1 のカバレッジを最大化するために中心を選択する、ばらばらまたは重複するセグメントの選択として最終的な構成について推論することができます。 これにより、問題は、競合する右半分の上書きによって破壊されることなく、「左半分」の寄与によってカバーできる位置の数を追跡することに集約されます。 動的計画法または貪欲な間隔解釈が出現し、有効な各中心が利得に貢献しますが、構造化された方法で将来の利得もブロックします。 

これにより、問題は状態の発展から重複する影響範囲にわたる最適化に変換されます。

 ## アルゴリズムのチュートリアル

 有効なオペレーション センターをそれぞれ再解釈します$i$2 つの効果を生成します。 左側が貢献する$k$1 に設定された位置は次で終わります$i$、右側は から始まるゼロのブロックを強制します。$i+1$。 これは、それぞれの選択を意味します$i$弦全体に構造化されたゲイン/ロス パターンを作成します。

2. 考えられる各中心について$i$、それを選択した場合の純利益を計算します。 ゲインはポジションの数です。$[i-k+1, i]$これは、1 から破壊される既存の 1 の数を引いたものに変えることができます。$[i+1, i+k]$。 これにより、操作の正確なトレードオフが把握されます。 
3. 各中心を、局所的に答えに影響を与え始めるが、右側の固定範囲をブロックする間隔の決定として扱います。 これにより、DP 状態を維持できるようになります。$dp[i]$までのポジションを考慮すると最良の結果です$i$をスキップするか、で終わる有効な中心を取得します。$i$。 
4. 中心を取るとき$i$、先に進みます$i+k$なぜなら次は$k$位置は構造的に影響を受けるため、同じ方法で個別に最適化することはできません。 これにより、二重カウントが防止され、一貫性が確保されます。

中心的な考え方は、各操作が完全に選択されるか完全に無視される必要がある加重区間のように動作し、影響を受けない次の領域にスキップすることで重複が解決されるということです。 

### なぜ効果があるのか

 各操作は固定ウィンドウ上で決定論的な変更を強制するため、一連の操作を標準形式に並べ替えることができ、一般性を失うことなく、選択された中心が左から右に処理されます。 これにより、任意の順序への依存関係が削除されます。 

DP の不変条件は、位置におけるものです。$i$、センターからのすべての貢献は完全に含まれています$[1, i]$問題は最適に解決されており、将来の決定によって以前のセグメントを遡って改善することはできません。 各操作はその右側の境界付きサフィックスにのみ影響するため、状態遷移はすでに固定されたプレフィックスのみに依存し、選択における循環依存性が保証されません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        s = input().strip()

        pref = [0] * (n + 1)
        for i in range(n):
            pref[i + 1] = pref[i] + (s[i] == '1')

        dp = [0] * (n + 1)

        for i in range(1, n + 1):
            dp[i] = dp[i - 1]

            if i >= k:
                l = i - k
                r = i

                ones_left = pref[r] - pref[l]
                zeros_left = k - ones_left

                if i + k <= n:
                    right_ones = pref[i + k] - pref[i]
                else:
                    right_ones = 0

                gain = zeros_left - right_ones

                dp[i] = max(dp[i], dp[i - k] + gain + (pref[i] - pref[i - k]))

        print(dp[n])

if __name__ == "__main__":
    solve()
```この解決策は、1 のプレフィックスの合計を構築することから始まります。これにより、任意の間隔で定数時間のクエリが可能になります。 これは、各候補中心が変換または破壊する 1 の数を評価する必要があるため、不可欠です。 

DP 配列は、各インデックスまでの達成可能な最良の結果を追跡します。 各位置で、ここで終了する操作をスキップするか、離れたところに中心を配置しようとします。$k$。 中心を配置するとき、左側のセグメントに導入される新しい 1 の数を計算し、右側のセグメントで破壊される既存の 1 の数を減算して、最終的な効果が正しく評価されるようにします。 

移行$dp[i] = max(dp[i], dp[i - k] + \dots)$操作の固定ウィンドウ構造に違反する形で中心が重ならないように強制します。
