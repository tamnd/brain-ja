 ## 解決策
 ## 問題の理解

 最大 100 個の頂点を持つ重み付き無向グラフが与えられます。 各エッジは 2 つの番号付きノードを接続し、負ではないコストを持ちます。 タスクは、ノード 1 から他のすべてのノードまでの可能な最小距離を計算することです。ここで、距離とは、選択したパスに沿ったエッジの重みの合計を意味します。 

入力は、交通費を伴う道路で接続された都市のネットワークとして解釈できます。 都市 1 から始めて、他のすべての都市に到達するための最も安価な方法を知りたいか、または都市にまったく到達できないと判断します。 

制約は十分小さいため、従来の最短パス法で十分です。 ノードが最大 100 個であれば、隣接行列または隣接リストはどちらも快適に適合します。 最悪の場合、エッジの数は約 5000 に達する可能性があるため、ほぼ 2 次またはわずかに超 2 次の動作を持つソリューションは高速に実行されます。 これにより、パス上の指数関数的な検索が即座に排除されますが、さらに重要なのは、バイナリ ヒープを使用した標準のダイクストラが十分以上に高速になることです。 

一部のノードがノード 1 から切断されている場合、微妙なエッジ ケースが発生します。このような場合、正しい出力は 0、無限大、または大きなセンチネル値ではなく、-1 です。 

もう 1 つの重要な例外ケースは、ゼロウェイト エッジです。 重みがゼロになる可能性があるため、単純な BFS に依存するアルゴリズムや厳密に正の重みを仮定するアルゴリズムは失敗します。 たとえば、1-2 (0)、2-3 (5) のようなチェーンがある場合、ノード 3 はコスト 5 で到達可能ですが、単純な BFS ではすべてのエッジが誤って平等に扱われてしまいます。 

3 番目の問題は、同じノードのペア間の複数のエッジから発生します。 グラフは入力解釈において単純であることが保証されていないため、最小重みエッジを維持する代わりに隣接エントリを上書きする不注意な実装により、誤って距離が増加する可能性があります。 

## アプローチ

 ブルートフォースのアイデアは、ノード 1 から他のすべてのノードまでの可能なパスをすべて試し、発生する最小コストを追跡することです。 概念的には、これは正しいです。グラフ内のウォークの検索空間全体を探索するからです。 ただし、パスの数は指数関数的に増加します。 分岐係数が控えめなグラフであっても、最大 n までの長さの個別のウォークの数が爆発的に増加し、実現可能な制限を超える可能性があります。 これは、各ノードが他の多くのノードに接続し、状態を再訪すると無制限の組み合わせ拡張が作成される密なグラフで特に顕著になります。 

重要な構造上の観察は、ノードまでの最短距離がわかれば、そこに到達するためのより長い方法を再検討する必要がないということです。 すべてのエッジの重みが負ではないため、この単調な「終了」特性が維持されます。 これにより、現在最も近い未到達ノードから貪欲に拡張し、常に最適な距離を増加順にロックすることができます。 これはまさにダイクストラのアルゴリズムが適用される設定です。 

この改善は、グローバル パスの列挙をローカルな緩和に置き換えることによって実現されます。 完全なパスを探索する代わりに、すでに到達したノードを残したエッジを使用して、最も既知の距離を繰り返し改善し、常に最小の暫定距離を優先します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースパス | 指数 | O(n) 再帰 | 遅すぎる |
 | ダイクストラ (ヒープ) | O(m log n) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 各ノードが隣接ノードとエッジの重みのペアを格納する隣接リストを作成します。 この表現が必要なのは、緩和中に出ていくエッジを効率的に繰り返し通過するためです。 
2. 0 に設定されているノード 1 を除くすべてのノードに対して、距離配列を無限大で初期化します。これは、コストなしでノード 1 から開始するという事実をエンコードします。 
3. ペア (0, 1) を優先キューにプッシュします。 キューには常に、現在既知の最短距離の順に候補状態が格納されます。 
4. キューから暫定距離が最も小さいノードを繰り返し抽出します。 このノードは、現在の知識では最も近いまだ最終化されていない頂点を表します。 
5. 抽出された距離がそのノードに保存されている距離より大きい場合は、スキップします。 これは、より適切なパスがすでに見つかっており、後でキューにプッシュされたために発生します。 
6. 現在のノードの近隣ノードごとに、このノードを通る候補距離を計算します。 保存された距離が改善される場合は、それを更新し、新しいペアを優先キューにプッシュします。 
7. 優先キューが空になるまで続行します。つまり、到達可能なすべてのノードが距離の増加順に処理されます。 
8. ノード 2 ～ n の最終距離を出力し、到達不能なノード (無限大のまま) を -1 に置き換えます。 

ステップ 5 が不可欠な理由は、同じノードが古い距離でキューに複数回出現する可能性があるためです。 古いエントリをスキップしないと、次善の値を使用して誤ってエッジを緩和し、実行時間が大幅に増加することになります。 

### なぜ効果があるのか

 ノードが距離 d で優先キューからポップされるたびに、d がノード 1 からそのノードまでの可能な最小距離であると主張します。 これは、すべてのエッジの重みが負ではないため当てはまります。そのため、後でこのノードに到達する代替パスには、現在発見されている最良のパスと少なくとも同量のコストが蓄積されている必要があります。 したがって、ノードがポップされると、その距離は確定し、改善されることはありません。 この不変条件により、すべての緩和が正しい最小距離を外側に伝播することが保証されます。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    
    adj = [[] for _ in range(n + 1)]
    for _ in range(m):
        u, v, w = map(int, input().split())
        adj[u].append((v, w))
        adj[v].append((u, w))
    
    INF = 10**18
    dist = [INF] * (n + 1)
    dist[1] = 0
    
    pq = [(0, 1)]
    
    while pq:
        d, u = heapq.heappop(pq)
        
        if d != dist[u]:
            continue
        
        for v, w in adj[u]:
            nd = d + w
            if nd < dist[v]:
                dist[v] = nd
                heapq.heappush(pq, (nd, v))
    
    for i in range(2, n + 1):
        if dist[i] == INF:
            print(-1)
        else:
            print(dist[i])

if __name__ == "__main__":
    solve()
```隣接リストの構築により、各無向エッジが両方向で使用可能になります。 距離配列は、未知の最短パスを表す大きなセンチネルで初期化されます。 優先キューは常に、現在最もよく知られているフロンティア ノードを拡張します。 

古いエントリのチェック`if d != dist[u]`古いキューエントリが不必要な緩和を引き起こすのを防ぎます。 これは、更新が繰り返される場合でもダイクストラの効率を維持する標準の最適化です。 

最後に、到達不能なノードは無限大に残り、出力では -1 に変換されます。

## テストケース```python
import sys, io
import heapq

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    
    n, m = map(int, sys.stdin.readline().split())
    adj = [[] for _ in range(n + 1)]
    
    for _ in range(m):
        u, v, w = map(int, sys.stdin.readline().split())
        adj[u].append((v, w))
        adj[v].append((u, w))
    
    INF = 10**18
    dist = [INF] * (n + 1)
    dist[1] = 0
    
    pq = [(0, 1)]
    while pq:
        d, u = heapq.heappop(pq)
        if d != dist[u]:
            continue
        for v, w in adj[u]:
            nd = d + w
            if nd < dist[v]:
                dist[v] = nd
                heapq.heappush(pq, (nd, v))
    
    out = []
    for i in range(2, n + 1):
        out.append(str(-1 if dist[i] == INF else dist[i]))
    
    return "\n".join(out)

assert run("2 1\n1 2 1\n") == "1"

# disconnected node
assert run("3 1\n1 2 5\n") == "5\n-1"

# zero-weight edges

# multiple edges
assert run("3 3\n1 2 10\n1 2 3\n2 3 1\n") == "3\n4"

 ## 特殊なケース

 切断されたノードのシナリオは、無限がどのように維持されるかを示しています。 考慮する：```
3 1
1 2 5
```ノード 3 には到達しません。 アルゴリズムはそれをキューにプッシュしないため、その距離は INF のままで、-1 として出力されます。 

重みがゼロのエッジケース:```
3 2
1 2 0
2 3 5
```最初に dist[2] は 0 になります。ノード 2 を処理するとき、コスト 5 でエッジを 3 に緩和します。最終結果は、ダイクストラの順序に違反することなくゼロコストのトラバーサルが許可されることを正しく反映しています。 

複数のエッジのケース:```
3 3
1 2 10
1 2 1
2 3 1
```2 番目のエッジは dist[2] を 1 に改善し、その後のすべての緩和ではこの改善された値を使用するため、入力に冗長なエッジや支配的なエッジが含まれている場合でも正確さが保証されます。
