 ## 解決策
 ## 問題の理解

 学校日誌の一連の成績を表す、数字 2、3、4、5 だけで構成される文字列が与えられます。 どの文字でも変更できますが、値を増やすことのみが可能であり、値を減らすことはできません。 たとえば、中間ステップに応じて 2 は 3、4、または 5 になる可能性があり、3 は 5、4、または 5 になる可能性がありますが、キーの制限は単調増加です。 

このようなアップグレードを何度でも実行した後、結果の文字列に部分文字列「54」が出現する回数を最大化したいと考えます。 出現は通常の重複する方法でカウントされるため、単一の位置が複数の出現に寄与する可能性があります。 

重要な構造上の制約は、すべての文字の値が上方向にしか移動できないことです。 これにより、問題が非対称になります。強制的に 5 を増やしたり、4 を増やしたりすることはできますが、競合を修正するために 5 や 4 を減らすことは決してありません。 

入力サイズは明示的には示されていませんが、このタイプの単一文字列問題に対する典型的な Codeforce 制約は、最大約 2·10^5 文字を意味します。 これにより、すべての部分文字列または位置のすべてのペアに対する 2 次アプローチが即座に除外されます。 

素朴な読者は、最終値を各位置に割り当てるあらゆる方法を検討しようとするかもしれませんが、各位置には最大 4 つの選択肢があり、4^n 個の状態が得られ、これは完全に実行不可能です。 

さらに微妙な問題は重複です。 4 つごとに 5 つ、および 5 つごとに 4 つを貪欲に変換すると、アップグレードが隣接する構造に干渉するため、潜在的な「54」ペアを意図せず破壊してしまう可能性があります。 

素朴な貪欲さによる小さな失敗例:

 入力:```
454
```5 と 4 を個別に最大化しようとすると、すべてが 5 に変換される可能性があります。```
555
```より良い計画は次のとおりですが、これにより「54」は 0 回発生します。```
554
```これにより 1 回の出現が生じます。 

したがって、キャラクターごとのローカルな決定では不十分です。 隣接性が重要です。 

## アプローチ

 重要な観察は、すべての「54」は隣接するペアにのみ依存し、すべての文字は増加することしかできないということです。 これは、できるだけ多くの隣接するペアが (5,4) になるように最終的な値を構築するという観点から考える必要があることを示唆しています。 

桁を増やすことしかできないため、4 を生成できるのは元の桁が 4、3、または 2 の場合のみですが、5 を生成することはいつでも可能です。 この非対称性が問題の全体的な構造です。 

各ポジションには 2 つの潜在的な役割があると再解釈できます。つまり、「54」が 5 になった場合は左側として、または 4 になった場合は右側として機能します。ただし、1 つのポジションが両立しない方法で両方の役割を同時に果たすことはできず、隣接する決定が相互作用します。 

最適な戦略は、左から右にスキャンし、そのポジションで 54 エンドを形成するためにポジションを「費やす」かどうかを決定することから生まれます。 位置 i-1 と i で「54」が必要な場合、位置 i が 4 になり、位置 i-1 が 5 になることを確認する必要があります。どちらも増加によって達成可能であるため、唯一の問題は、このペアを強制することで利益が得られるかどうかです。 

微妙な点は、i で終わる「54」を形成すると決めたら、位置 i-1 が 5 に固定されているため、別のペアの右側として使用することを許可すべきではないということです。これは当然、前の位置がペアの 5 として使用されたかどうかを追跡する貪欲な DP につながります。 

ブルート フォースでは、「54」を配置した隣接するエッジのすべてのサブセットが試行され、割り当てに競合がないことが保証されます。 これは、互換性制約のあるパス内のエッジのサブセットを選択することと同等であり、本質的にはライン上の最大一致に似た構造ですが、アップグレードの自由によりすべてのエッジが独立して実行可能であるという工夫が加えられています。 

これにより、問題は、i を 5、i+1 を 4 に設定した場合に各エッジ (i、i+1) を「54」にすることができる、素のまたは重複する機会のセットを選択することになります。どの位置も 4 または 5 に上げることができるため、割り当ての一貫性を超えるコストの相互作用はありません。 

したがって、すべての隣接するペアは独立して「54」に変換でき、最適な答えは単純に隣接するペアの数、つまり n-1 になります。 ただし、これが正しいのは、常にすべてのエッジに同時に一貫して値を割り当てることができる場合に限られます。そのためには、チェーン全体の実現可能性制約をチェックする必要があります。 

実際、一貫性は常に達成可能です。すべての位置 i を、左端点として使用する場合は 5、右端点として使用する場合は 4 と決定すると、ノードが 4 と 5 の両方である必要がある場合にのみ競合が発生します。それは、まさに両方のエッジ (i-1, i) と (i, i+1) を使用しようとしたときに発生します。 したがって、各ポジションは右エンドポイントとして最大 1 つの「54」に参加できますが、優先順位付けによって競合を解決する場合に限り、複数回左エンドポイントになることができます。 

これは、パス上のエッジの古典的な貪欲な選択となり、隣接関係の競合なしにできるだけ多くのエッジを選択し、単純な線形 DP を生成します。

 ## アルゴリズムのチュートリアル

1. 文字列を左から右にスキャンし、すべての隣接するペア (i, i+1) を「54」を形成する候補とみなします。 必要に応じて任意の桁を 5 または 4 に増やすことができるため、これは有効です。 
2. 位置ごとに、「54」の右端として使用するか（4 になる）、左端として使用するか（5 になります）を決定します。 位置は互換性のない割り当てを同時に満たすことができないため、前の位置が形成されたペアの一部としてすでに使用されているかどうかを追跡します。 
3. 位置 i にいるとき、前の位置が右端点として使用されていない場合は、(i, i+1) を使用して「54」を形成しようとします。これは 1 つの出現に寄与し、i を 5 としてマークし、i+1 を 4 としてマークします。 
4. すでに割り当てられている役割と競合するため、i でペアを形成できない場合は、スキップして続行します。 
5. このプロセスを文字列の終わりまで続けて、有効な「54」フォーメーションの最大数を蓄積します。 

### なぜ効果があるのか

 重要な不変条件は、エッジ (i, i+1) を選択するたびに、両方のエンドポイントを固定ロールに完全にコミットし、これらのロールが以前に固定された割り当てと競合しないことです。 グラフはパスであるため、競合しないエッジの有効なセットはマッチングのような構造に対応し、欲張りな左から右への選択により、単調な割り当ての実現可能性の下で常に最大数の重複しない使用可能な制約が得られます。 後の選択では、以前の強制割り当てを破ることなく有効なペアの数を増やすことはできないため、貪欲な構築が最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

s = input().strip()
n = len(s)

used = [False] * n
ans = 0

for i in range(n - 1):
    if not used[i] and not used[i + 1]:
        ans += 1
        used[i] = True
        used[i + 1] = True

print(ans)
```このソリューションは、すでに「54」ペアにコミットされているポジションをマークします。 隣接する空きペアを見つけるたびに、貪欲にそれを取得します。 これは、パス上で最適な最大の一致を選択することに正確に対応します。 

配列`used`矛盾する役割をポジションに割り当てないようにします。 ポジションがペアに参加すると、そのポジションはロックされます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    s = input().strip()
    n = len(s)
    used = [False] * n
    ans = 0
    for i in range(n - 1):
        if not used[i] and not used[i + 1]:
            ans += 1
            used[i] = True
            used[i + 1] = True
    return str(ans)

# sample-like cases
assert run("454\n") == "1"

# all equal
assert run("2222\n") == "2"

# no possible structure
assert run("3333\n") == "2"

# alternating
assert run("245245\n") == "3"

# minimum
assert run("54\n") == "1"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 454 | 1 | 重複するペアの競合 |
 | 2222 | 2 | 均一な文字列の最大パッキング |
 | 3333 | 2 | 完全な変換可能性 |

 ## 特殊なケース

 最小のエッジ ケースは、長さ 2 の文字列です。入力「54」の場合、アルゴリズムは直ちにそのペアを取得し、唯一の可能な出現に一致する 1 を生成します。 

「555」の場合、最初はすべての隣接するペアが有効ですが、最初のペアが取得されると、中央の位置がロックされ、2 番目のペアは禁止されます。 貪欲なアルゴリズムでは 1 が生成され、両方のペアを取得しようとすると、中央の文字に矛盾した割り当てが強制されます。 

「2222」の場合、すべての位置を上げることができ、アルゴリズムは (0,1) と (2,3) を選択し、2 を生成します。代わりに (1,2) を選択しようとしても、素ペアの総数は増加せず、最適性が確認されています。
