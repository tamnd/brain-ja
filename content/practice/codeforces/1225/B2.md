 ## 解決策
 ## 問題の理解

 次のテレビ番組のスケジュールが与えられました`n`日々。 毎日、整数で表される 1 つの番組からのエピソードが放送されます。 

サブスクリプションはエピソードごとではなく、番組ごとに購入されます。 番組を購読すると`x`、私たちはあらゆる出来事を監視することができます`x`スケジュールの中で。 

目標は、正確な番組のブロックが少なくとも 1 つ存在するように、必要な番組サブスクリプションの最小数を見つけることです。`d`放送されたすべてのエピソードが当社の登録番組に属する連続した日。 

のセグメントを見ると、`d`連続した日の場合、そのセグメントに必要なサブスクリプションの数は、単にそのセグメント内に表示される個別の番組の数です。 番組がセグメント内で複数回表示される場合でも、1 つのサブスクリプションですべての番組がカバーされます。 

この観察により、問題ははるかに単純なものに変換されます。 

連続する長さの部分配列ごとに`d`、含まれる個別の値の数を数えます。 答えは、すべての長さの中でそのような数が最小であることです。`d`窓。 

ハードバージョンでは、すべての合計を許可します`n`到達するテストケース全体にわたって`2·10^5`。 ウィンドウごとに個別の要素を最初から再計算するソリューションには、大まかに次のものが必要になります。`O(n·d)`仕事。 両方の値が大きい場合は、約`4·10^10`2 秒の制限内ではまったく実行不可能です。 

この制約は、テスト ケースごとに線形または線形に近い解決策を強く示唆しています。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

考慮する：```
n = 5, d = 3
1 1 1 1 1
```各ウィンドウには個別のショーが 1 つだけ含まれているため、答えは次のようになります。`1`。 個別の値ではなく要素をカウントする不注意な実装では、誤った値が返されます。`3`。 

考慮する：```
n = 5, d = 1
1 2 3 4 5
```長さ 1 の各ウィンドウにはちょうど 1 つの番組が含まれるため、答えは次のようになります。`1`。 スライディング ウィンドウ ロジックにおけるオフバイワンの間違いは、ウィンドウ サイズが可能な限り最小の場合によく発生します。 

考慮する：```
n = 4, d = 4
1 2 3 4
```有効なウィンドウは 1 つだけです。 答えは、配列全体内の個別の要素の数です。`4`。 常に少なくとも 1 回はスライドしようとする実装では、配列の外側の要素にアクセスする可能性があります。 

考慮する：```
n = 6, d = 3
1 2 1 3 3 3
```ウィンドウには次のものが含まれます。```
[1,2,1] -> 2 distinct
[2,1,3] -> 3 distinct
[1,3,3] -> 2 distinct
[3,3,3] -> 1 distinct
```答えは`1`。 要素がウィンドウから出たときに頻度が正しく減少しない場合、個別のカウントが永続的に増加する可能性があります。 

## アプローチ

 最も直接的な解決策は、すべての長さのウィンドウを調べることです。`d`独立して。 

開始位置ごとに、すべてを収集します`d`そのウィンドウ内の値をセットに挿入し、セットのサイズを記録します。 すべてのウィンドウにわたる最小設定サイズが答えです。 

これが機能するのは、セットが重複を自動的に削除するため、セットのサイズがそのウィンドウに必要なサブスクリプションの数と等しくなるためです。 

問題は効率です。 おおよそあります`n`各ウィンドウには最大で 6 つのウィンドウを含めることができます。`d`要素。 複雑さは次のようになります`O(n·d)`。 と`n = 2·10^5`、これでは遅すぎます。 

重要な観察は、連続するウィンドウが大きく重なっていることです。 

現在のウィンドウが次のようになっているとします。```
a[l], a[l+1], ..., a[r]
```位置を 1 つ右に移動すると、次の 2 つのことだけが変わります。```
a[l] leaves
a[r+1] enters
```他のすべての要素はウィンドウ内に残ります。 

個別の値を最初から再計算する代わりに、現在存在する要素の頻度カウントを維持します。 要素が入ってくると、その周波数が増加します。 要素が離れると、その頻度が減少します。 

個別の要素の数は、周波数が 0 と 1 の間で遷移する場合にのみ変化します。 

入力要素の周波数が から変化した場合`0`に`1`、新しい個性的なショーが登場します。 

離脱要素の周波数が から変化した場合`1`に`0`、明確なショーが消えます。 

これにより、配列全体でウィンドウをスライドさせながら、個別のカウントを一定時間で更新できます。 

その結果、線形時間で実行される古典的なスライディング ウィンドウ ソリューションが得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n・d) | O(d) | 遅すぎる |
 | 最適な引き違い窓 | O(n) | O(d) から O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 現在のウィンドウの周波数辞書を作成します。 
2.最初のを挿入します`d`要素を辞書に追加します。 
3. 変数を維持する`distinct`現在ウィンドウに表示されているさまざまな番組の数を表します。 

値の周波数が変化するたびに、`0`に`1`、増分`distinct`。 
4. 最初のウィンドウを構築した後、次のように応答を初期化します。`distinct`。 
5. ウィンドウを一度に 1 位置ずつスライドさせます。 
6. しましょう`out = a[i-d]`ウィンドウから出る要素になります。 

その頻度を減らしてください。 
7. の頻度が`out`ゼロになる、減少する`distinct`。 

この番組はウィンドウに表示されなくなりました。 
8. しましょう`in = a[i]`ウィンドウに入る要素になります。 
9. 周波数が現在ゼロの場合は、増加します。`distinct`。 

このショーが新たにウィンドウに表示されます。 
10. 頻度を増やす`in`。 
11. 現在の値の最小値で答えを更新し、`distinct`。 
12. すべてのウィンドウを処理した後、回答を出力します。 

### なぜ効果があるのか

 あらゆる瞬間において、周波数辞書には、アクティブな長さに現在存在する要素が正確に含まれています。`d`ウィンドウ。 

変数`distinct`頻度が正であるキーの数に等しくなります。 それはまさに、ウィンドウに表示されるさまざまな番組の数です。 

あらゆる可能な長さ -`d`ウィンドウが一度検査されます。 各ウィンドウについて、その個別の表示数を正確に把握し、すべてのウィンドウの最小値を維持します。 

問題に対する答えは、任意の長さの中で現れる個別のショーの最小数であるため、`d`セグメントでは、アルゴリズムは常に正しい結果を返します。 

## Python ソリューション```python
import sys
from collections import defaultdict

input = sys.stdin.readline

def solve():
    t = int(input())
    answers = []

    for _ in range(t):
        n, k, d = map(int, input().split())
        a = list(map(int, input().split()))

        freq = defaultdict(int)
        distinct = 0

        for i in range(d):
            if freq[a[i]] == 0:
                distinct += 1
            freq[a[i]] += 1

        ans = distinct

        for i in range(d, n):
            out = a[i - d]
            freq[out] -= 1
            if freq[out] == 0:
                distinct -= 1

            inn = a[i]
            if freq[inn] == 0:
                distinct += 1
            freq[inn] += 1

            ans = min(ans, distinct)

        answers.append(str(ans))

    sys.stdout.write("\n".join(answers))

if __name__ == "__main__":
    solve()
```頻度辞書には、各番組が現在のウィンドウに表示される回数が保存されます。 

最初のループは、長さの初期ウィンドウを構築します。`d`。 要素を挿入するときに、番組が初めて表示されるかどうかを検出します。 それは維持します`distinct`ユニークな番組の実際の数と同期されます。 

スライディング フェーズでは、シフトごとに 1 つの要素が削除され、1 つの要素が追加されます。 順序が重要です。 まず発信要素の頻度を更新し、場合によっては頻度を減らします。`distinct`。 次に、受信した要素を処理し、場合によっては増加させます。`distinct`。 

条件チェックでは、ゼロを経由する遷移が使用されます。 ショーは、その頻度が正の場合にのみ、個別のカウントに寄与します。 

すべてのカウントが最大値であるため、整数オーバーフローの懸念はありません。`d`。 

この実装では、すべての境界ケースが自然に処理されます。 もし`d = n`の場合、スライディング ループは実行されず、最初のウィンドウがすでに唯一の有効なセグメントを表しています。

 ## 特殊なケース

 ### すべての値が同一

 入力:```
1
5 10 3
7 7 7 7 7
```最初のウィンドウには周波数があります`{7:3}`そして`distinct = 1`。 

スライドごとに 1 つ削除されます`7`そして別のものを追加します`7`したがって、周波数がゼロになることはなく、個別のカウントは残ります。`1`。 

アルゴリズムは次を出力します。```
1
```1 つのサブスクリプションで毎日がカバーされるため、これは正しいです。 

### ウィンドウ サイズは配列サイズと等しい

 入力:```
1
4 10 4
1 2 3 4
```初期ウィンドウにはすでに配列全体が含まれています。 

周波数マップは次のようになります。```
{1:1, 2:1, 3:1, 4:1}
```それで`distinct = 4`。 

追加のウィンドウがないため、スライディング ループは実行されません。 答えは残っている`4`、それは正しいです。 

### 最適なウィンドウが最後に表示されます

 入力:```
1
6 6 3
1 2 1 3 3 3
```ウィンドウには個別のカウントが含まれます。```
2, 3, 2, 1
```最小値は最後のウィンドウで発生します。 

アルゴリズムがスライドするにつれて、周波数は段階的に更新されます。 最後のウィンドウのとき`[3,3,3]`に達した場合は表示のみ`3`正の周波数のままなので、`distinct`になる`1`。 

答えは次のように更新されます`1`ウィンドウがスキップされていないことを確認します。 

### 周波数がゼロに低下する

 入力:```
1
4 4 2
1 2 2 2
```初期ウィンドウ:```
[1,2]
distinct = 2
```スライド後:```
remove 1 -> frequency becomes 0
distinct decreases to 1

add 2 -> frequency already positive
distinct stays 1
```新しいウィンドウ`[2,2]`正しくは、異なる番組が 1 つだけ含まれています。 

このケースでは、アルゴリズムの最も重要な遷移を検証し、アクティブ ウィンドウから値を完全に削除します。
