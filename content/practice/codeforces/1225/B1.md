 ## 解決策
 ## 問題の理解

 私たちは数日間にわたるテレビ番組のスケジュールを与えられています。 毎日 1 つの番組が放送され、番組のサブスクリプションを購入すると、タイムライン全体のすべてのエピソードにアクセスできるようになります。 

タスクは、すべての日をカバーすることではなく、正確に連続するブロックが少なくとも 1 つ存在するような番組のセットを選択することです。`d`そのブロックに表示されるすべての番組が購入したセットに含まれる日。 このようなブロックを可能にするために、購読するさまざまな番組の数を最小限に抑えたいと考えています。 

これを表示する別の方法は、長さのウィンドウを選択できることです。`d`そして、そのウィンドウについては、その中のすべての個別の値が選択したセットによって「カバーされる」ことを確認する必要があります。 セットを選択した後は最適なウィンドウを自由に選択できるため、最適な戦略は個別の数が最小のウィンドウを見つけることに依存します。 

制約は小さいです。`n ≤ 100`テストケースごとおよび合計`n`テスト全体でも ≤ 100 です。これは、`O(n^2)`あるいは`O(n^3)`この解決策は受け入れられ、パフォーマンスを心配することなく、すべてのウィンドウを明示的に安全に検査できます。 

すべての要素がすべてのウィンドウで異なる場合、微妙なエッジ ケースが発生します。 その場合、答えは正確になります`d`、どのサイズのウィンドウでも`d`すべてを購読するよう強制します`d`を示します。 もう 1 つの特殊なケースは、ショーが頻繁に繰り返されるため、ウィンドウに個別のショーが 1 つだけ含まれる場合です。 その場合、そのウィンドウではその 1 つのショーを購入するだけで十分であるため、答えは 1 になります。 

単純な間違いは、配列全体で個別のショーをグローバルに最小化する必要があると考えることです。 この要件はスケジュール全体ではなく、選択した 1 つのウィンドウにのみ適用されるため、これは不正確です。 

## アプローチ

 直接的な総当たりアプローチは、長さのすべての連続したセグメントを考慮することです。`d`。 セグメントごとに、そのセグメントに表示される個別の番組の数を計算します。 まさにそれらの番組のサブスクリプションを購入すると、そのセグメントを視聴できるため、そのセグメントに必要なサブスクリプションの数がそのセグメントの個別の数となります。 すべてのセグメントにわたって最小値を採用します。 

これが機能するのは、選択したセグメントによってどの番組を購読する必要があるかが正確に決まるためです。 ただし、セグメントごとに個別のカウントを最初から再計算することは、各ウィンドウにコストがかかる可能性があるため、不注意に行うと非効率になります。`O(d)`そしてそこにあります`O(n)`窓。 

重要な観察は、グローバル構造や高度なデータ構造は必要ないということです。 以来`n`が小さいため、各ウィンドウの周波数マップを再計算するだけでも十分高速です。 あるいは、スライディング ウィンドウ頻度テーブルを維持し、それを更新することもできます。`O(1)`ステップごとに異なりますが、必須ではありません。 

この問題を単純にする構造は、決定がウィンドウに対して完全にローカルであり、最小値を取る以外には異なるウィンドウ間で相互作用がないことです。

 ## アルゴリズムのチュートリアル

 長さの可能なすべての開始位置を反復します。`d`セグメント化して、その中の個別の要素の数を計算します。 

1. 各テスト ケースについて、次の内容を読んでください。`n`、`k`、 そして`d`、一連の番組とともに。 
2. インデックスごとに`i`から`0`に`n - d`、セグメントを考えてみましょう`[i, i + d - 1]`。 これは、サブスクリプションで「サポート」したい可能性のある連続した日数のブロックを表しています。 
3. セグメントごとに、セットまたは頻度配列を使用して、セグメント内に出現する個別の値の数を数えます。 この数は、このセグメントを選択した場合に購読する必要がある番組の数を表します。 
4. すべてのセグメントにわたるこのような個別のカウントの最小値を追跡します。 
5. この最小値を出力します。 

重要なアイデアは、セグメントを修正すると、最小限のサブスクリプション セットが強制されるということです。つまり、それはまさにそのセグメント内の個別の番組のセットになります。 セグメント外の番組を購読しても、その特定のブロックの条件を満たすことができないため、メリットはありません。 

### なぜ効果があるのか

 選択した長さのセグメントに対して`d`、私たちはその日々をずっと見守ることができなければなりません。 サブスクリプションには番組のすべてのエピソードが含まれるため、唯一の要件は、そのセグメントに表示されるすべての番組が購入したセットに含まれていることです。 したがって、固定セグメントの最適なセットは、まさにその個別の要素です。 最適なセグメントを選択できるため、最終的な答えは、すべてのセグメントにわたる最小個別カウントになります。 これにより、配列の無関係な部分を数えすぎたり考慮したりすることがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, k, d = map(int, input().split())
    a = list(map(int, input().split()))

    ans = float('inf')

    for i in range(n - d + 1):
        seen = set()
        for j in range(i, i + d):
            seen.add(a[j])
        ans = min(ans, len(seen))

    print(ans)
```コアループは、可能な長さのウィンドウをすべてチェックします。`d`。 各ウィンドウ内で、遭遇したショーのセットを構築します。 このセットのサイズは、その期間を選択した場合に必要なサブスクリプションの数と正確に一致します。 

の初期化`ans`無限大の場合、有効なウィンドウによって改善されることが保証されます。 制約が小さいため、毎回セットを再構築するだけで十分であり、増分状態を維持することによる複雑さを回避できます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n, k, d = map(int, input().split())
        a = list(map(int, input().split()))

        ans = float('inf')
        for i in range(n - d + 1):
            seen = set()
            for j in range(i, i + d):
                seen.add(a[j])
            ans = min(ans, len(seen))

        out.append(str(ans))
    return "\n".join(out)

 ## 特殊なケース

 完全に均一な配列は、最も単純な構造を示します。 すべてのウィンドウには単一の値が含まれるため、アルゴリズムは一貫して 1 を返し、これは 1 つの番組を購読すれば十分であるという事実と一致します。 

完全に別個の配列では、すべての長さのウィンドウが強制されます。`d`正確に持つこと`d`ユニークな番組。 設定されたサイズは以下に等しいため、アルゴリズムはこれを正しく反映します。`d`セグメントごとに。
