 ## 問題の理解

 プラスの目標数値が与えられています$n$。 整数も修正します$p$、次の形式の数値ファミリーをシフトします。$2^x + p$、 どこ$x \ge 0$。 このような各値は単一の「構成要素」であり、同じブロックを何度でも再利用できます。 

課題は表現すること$n$可能な限り少ないブロックを使用しながら、これらのブロックの合計として計算します。 そのような表現が存在しない場合は、それは不可能であると報告しなければなりません。 

構造を再解釈する便利な方法は、次の合計を展開することです。$k$選択したブロック:$$(2^{x_1} + p) + (2^{x_2} + p) + \dots + (2^{x_k} + p)$$これは次のようになります。$$(2^{x_1} + 2^{x_2} + \dots + 2^{x_k}) + k \cdot p$$したがって、この問題は、合計が次の値に等しい 2 のべき乗の数を選択することと同じです。$n - k \cdot p$、正確に使用しながら$k$2 項の累乗。 

制約により許可されるのは、$n$まで$10^9$そして$p$狭い範囲で。 これは、大規模な構造の列挙や表現に対する指数関数的な検索の実行に依存するソリューションは失敗することをすでに示唆しています。 重要な観察は、2 の累乗の構造が非常に厳格であり、それらの合計は 2 進数表現によって制御されるということです。 

素朴なアプローチでは、貪欲に 2 のべき乗を選択して調整することによって表現を構築しようとしたり、項数ごとに可能な指数のすべてのサブセットを試したりすることになります。 指数を制限しても失敗するため、$[0,30]$、組み合わせの数は指数関数的に増加します。 

さらに微妙な失敗例は、実現可能性の制約を無視した場合に発生します。 たとえば、次の場合$p$は正で大きいため、項を選択しすぎると、$k \cdot p$超える$n$、2 のべき乗の和として表すことができない負の剰余を強制します。 

## アプローチ

 強引なアイデアは加数の数を固定することです$k$を選択できるかどうかを確認してみます。$k$指数$x_i$結果の合計が一致するように$n$。 固定の場合$k$、これは 2 のべき乗に関する分割問題となり、再帰またはサブセット構築によって調べることができます。 ただし、たとえシングルであっても、$k$、各加数が独立して指数を選択するため、構成の数は膨大になり、指数関数的な検索空間が発生します。$k$。 全部試してみる$k$まで$n$明らかに実行不可能です。 

重要な簡素化は、次の寄与を分離することから生まれます。$p$バイナリ構造から。 修正したら$k$、方程式は次のようになります。$$\sum 2^{x_i} = n - k p = S$$したがって、次のことを判断するだけで済みます。$S$正確に次の合計として表すことができます$k$2 の累乗。 

2 進数の構造から 2 つの事実が得られます。 形成するために必要な 2 のべき乗の最小数$S$まさに$\mathrm{popcount}(S)$、各 1 ビットは 1 つの累乗に対応するためです。 加数の数は、2 の累乗を 2 つの小さな累乗に分割することでいつでも増やすことができます。$k \ge \mathrm{popcount}(S)$些細な上限を超えない限り達成可能です$k \le S$、期間ごとの可能な最小の寄与は次のとおりであるため、$1$。 

これにより、問題は実現可能性のチェックに変わります$k$、ここで最小のものを検索します$k$次のような:$$S = n - k p \ge 0,\quad \mathrm{popcount}(S) \le k \le S$$代数的に解く代わりに、小さな限界を利用することができます。$p$そしてその状態のスムーズな挙動。 として$k$成長し、$n - k p$は線形に変化し、ポップカウントはゆっくりと増加するため、制限された範囲をチェックする必要があります。$k$で十分です。 実際にすべて試してみると、$k$制約がわずかに満たされるか違反される領域にシステムが安定する前に、有効な解が出現する必要があるため、最大数千で十分です。

 ## アルゴリズムのチュートリアル

 1. 可能な数の加数を反復します。$k$、1から始まります。 それぞれ$k$正確に使用すると仮定して表します$k$p の 2 進数。 
2. それぞれについて$k$、残りの値を計算します$S = n - k \cdot p$。 これにより、純粋に 2 のべき乗から形成する必要がある部分が分離されます。 
3. もし$S < 0$、これを破棄します$k$2 の累乗の和は負の値を生成できないためです。 
4. 設定されたビット数を計算します。$S$で示される$\mathrm{popcount}(S)$。 これは、形成するために必要な 2 の累乗の最小数です。$S$。 
5. 実現可能性の条件を確認する: 必要です$\mathrm{popcount}(S) \le k$いつでも権限を分割して任期数を増やすことができるため、$k \le S$、各項が少なくとも 1 に寄与するためです。 
6. 最初の$k$両方の条件を満たすものが答えです。 
7. いいえの場合$k$テストされた範囲で動作し、出力$-1$。 

核となる不変条件は、固定のテストを行うたびに、$k$、問題を純粋なバイナリ分解の質問に還元します。 ポップカウント条件は、次の既約構造を捉えています。$S$、分割すると、合計を変更せずに項の数を常に増やすことができることが保証されます。 つまり、実現可能性は、$k$達成可能な最小分解サイズと最大分解サイズの間にあります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def popcount(x):
    return x.bit_count()

def solve():
    n, p = map(int, input().split())

    # Try possible number of summands
    for k in range(1, 2001):
        S = n - k * p

        if S < 0:
            continue

        if popcount(S) <= k <= S:
            print(k)
            return

    print(-1)

if __name__ == "__main__":
    solve()
```コードは、派生された実現可能性条件を直接実装します。 ループオーバー$k$有効な解は常にどちらかの前の狭い範囲内に現れるため、制限されています。$S$マイナスになったとき（$p > 0$) または、popcount 制約が自明に満たされる場合 (次の場合)$p < 0$）。 の使用`bit_count()`バイナリ構造をきれいに分離し、手動によるビット操作を回避します。 

二重不等式`popcount(S) <= k <= S`は中心的な正確性条件であり、分解不足と不可能な過剰分解の両方を防ぎます。

 ## 特殊なケース

 いつ$p = 0$、問題は表現に帰着します$n$最小カウントでの 2 のべき乗の合計として。 アルゴリズムはすぐにチェックします$k = \mathrm{popcount}(n)$、 以来$S = n$、これが実現可能な最小値です。 

いつ$p > 0$、増加しています$k$減らす$S$。 最終的に$S$マイナスになり、すべてが大きくなります$k$は無効です。 アルゴリズムは当然これらのケースをスキップし、意味のあるプレフィックスのみを評価します。$k$。 

いつ$p < 0$、増加しています$k$増加する$S$により、ポップカウントの制約が満たされやすくなります。 最初に実現可能なのは$k$発生するとき$k$本質的なバイナリの複雑さを超えています$S$、ループは境界より前の早い段階でこの遷移をキャッチします。$S \ge k$関連性が高まります。
