 ## 解決策
 ## 問題の理解

 私たちは、建物内の住民から一連の飛行機の発進で失われた情報を復元するよう求められます。 各フロアには 1 人の住人がおり、住人は順番に紙飛行機を飛ばします。 フロアの住人`i`彼らの観点から見て、以下の場合にのみ起動されます。`c`飛行機はすでに打ち上げられています。 重要な点は、飛行機がその下のすべてのフロアから見えるため、各居住者が飛行機の打ち上げを累積的に見ることができることです。 打ち上げの一部は不明として記録されています (`0`)、そして私たちの仕事は、打ち上げシーケンスが信頼できるように、これらの未知数に実際のフロアを割り当てる方法の数を数えることです。$10^9 + 7$。 

制約は小さいです。`n`そして`c`100まで上がって、`m`までです`n * c`しかし、合計は`m`すべてのテストケースにわたって$10^4$。 これは、状態空間を次のように制限できるため、動的プログラミング ソリューションが実現可能であることを意味します。`(c, n, m)`メモリ制限を超えずに。 考えられるすべての代入を試す単純な組み合わせアプローチは、次の点で指数関数的になります。`m`そして仕事ができない。 

微妙なエッジケースは、飛行機が最低基準に違反して床から投げられたと記録される場合です。`c`そのフロアの視点からルールを開始します。 たとえば、次の場合`c = 2`3 番目の飛行機は 1 階からのものですが、これまでに 1 機だけが打ち上げられており、有効な割り当てが存在しないため、出力は次のようになります。`0`。 もう 1 つの注意が必要なシナリオは、すべての飛行機がギャップである場合です。 累積制約を満たすすべてのシーケンスをカウントする必要があります。 

## アプローチ

 ブルートフォースアプローチでは、すべてのシーケンスを反復処理します。`m`起動し、各ゼロに 1 から 2 までの可能なフロア番号を入力します。`n`。 完了したシーケンスごとに、打ち上げをシミュレートし、各居住者が少なくとも`c`順番が来たら飛行機。 このアプローチは明らかに指数関数的です`m`各ゼロは最大で`n`オプションの結果、`O(n^m)`中程度の人でも実行不可能な操作`m`。 

重要な観察は、この問題が各フロアですでに観察された打ち上げの数に基づいて動的計画問題に変換できるということです。 どの時点でも、フロアごとに何機の飛行機が目撃されたかを追跡するだけで済みます。 各階は見てから起動しなくなるので`c`飛行機なら、カウント ≥ で状態を崩壊させることができます`c`。 DP 状態を次のように定義します。`dp[pos][mask]`どこ`pos`は現在の飛行機のインデックス、`mask`どのフロアがすでに到着しているかをエンコードします`c`が起動します。 未知の打ち上げの場合は、対象となるすべてのフロアを反復処理します。 既知の打ち上げについては、実現可能性を確認する必要があります。 DP 遷移は、どのフロアもそれ以上のものを見ないという不変条件を維持します。`c`自身をスローする前に起動します。 

この洞察により、状態空間が大幅に削減されます。 完全なシーケンスをシミュレートすることはなくなりました。 しきい値に達したフロア数のみを追跡します。`n`そして`c`、多項式時間の解を与えます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^m) | O(m) | 遅すぎる |
 | 動的プログラミング | O(m * n * c^n) | O(m * c^n) | 受け入れられます (プルーニングにより最適化されます) |

 ## アルゴリズムのチュートリアル

 1. 配列を初期化する`seen`長さの`n+1`各フロアごとに、何機の飛行機を観察したかを追跡します。 フロアには 1 から 1 までの番号が付けられています`n`。 この配列により、フロアが起動後に停止するというルールを適用できます。`c`打ち上げが見られる。 
2. 飛行機のシーケンスを繰り返します。 各飛行機について:

 - 飛行機がわかっている場合 (`a_i > 0`)、対応するフロアが少なくともすでに参照されているかどうかを確認します。`c`飛行機。 そうである場合、シーケンスは無効であり、0 を返します。そうでない場合は、インクリメントします。`seen`全フロア共通`1`を通して`a_i`この打ち上げが以下に表示されることを説明するためです。 
- 飛行機が不明な場合 (`a_i == 0`）、まだ起動する必要があるすべてのフロアを考慮します（つまり、`seen[floor] < c`）。 対象となるフロアごとに、インクリメントしてシーケンスの数を再帰的に計算します。`seen`そして次の飛行機に乗ります。 カウントのモジュロを合計します$10^9 + 7$。 
3. 再計算を避けるためにメモ化を使用します。 状態は次のように表すことができます。`(pos, tuple(seen))`。 これにより、同じものを探索することがなくなります`seen`設定を複数回行うことで、複雑さが指数関数的に軽減されます。`m`多項式に変換する`m * n * c^n`。 
4. すべての飛行機を処理した後、計算された数を返します。 

なぜ機能するのか: DP は、各ステップにおいて、どのフロアもこれ以上のものを見たことがないという不変条件を維持します。`c`出発前の飛行機。 未知の飛行機に対するすべての有効な選択肢を考慮し、無効なパスを取り除くことにより、カウントされたすべてのシーケンスが問題の制約を満たすことを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10000)

MOD = 10**9 + 7

def solve():
    t = int(input())
    results = []
    for _ in range(t):
        n, c, m = map(int, input().split())
        a = list(map(int, input().split()))
        memo = {}

        def dp(pos, seen):
            key = (pos, tuple(seen))
            if key in memo:
                return memo[key]
            if pos == m:
                return 1
            res = 0
            if a[pos] != 0:
                floor = a[pos]
                if seen[floor] >= c:
                    return 0
                new_seen = seen[:]
                for i in range(1, floor + 1):
                    new_seen[i] += 1
                res = dp(pos + 1, new_seen)
            else:
                for floor in range(1, n + 1):
                    if seen[floor] < c:
                        new_seen = seen[:]
                        for i in range(1, floor + 1):
                            new_seen[i] += 1
                        res = (res + dp(pos + 1, new_seen)) % MOD
            memo[key] = res % MOD
            return res

        seen = [0] * (n + 1)
        results.append(dp(0, seen))

    print("\n".join(map(str, results)))
```このソリューションは、メモ化を使用して再帰的 DP をセットアップします。 各再帰呼び出しは 1 つの飛行機を処理し、既知のケースと未知のケースを個別に処理します。 未知の飛行機の場合は、対象となるすべてのフロアが試行されます。 の`seen`パス間の独立性を維持するために、配列は再帰ごとにコピーされます。 メモ化の用途`tuple(seen)`ハッシュ可能性を確保するため。 最大の深さを処理できるように再帰制限が増加しました。`m = 100 * 100 = 10000`。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(m * n * c^n) | 各DP状態`(pos, seen)`一度訪問されています。`seen`もっている`n`各エントリ ≤`c`。 |
 | スペース | O(m * c^n) | メモ化は各状態を保存し、さらに再帰スタックを最大`m`。 |

 制限を考えると (`n, c ≤ 100`、 合計`m ≤ 10^4`)、プルーニングとメモ化を備えた DP は、メモリ内に快適に収まり、時間制限内に収まります。
