 ## 解決策
 ## 問題の理解

 バレルの容積の変化するマルチセットが与えられます。 各樽には数値があり、目に見えない毒を持っているという意味で、まさに 1 つの樽が「特別」です。 毒は樽の総重量の一部であることを除いて比較に直接影響しません。どちらが重いか、または等しいかどうかを判断するために 2 つの樽を比較することは許可されています。 

樽間で水を再分配することもできますが、重大な制限があります。毒が入ったものではないと確信できない限り、樽から水を取り出すことは決して許可されていません。 私たちは、毒が入った樽を含め、どんな樽にも安全に水を注ぐことができます。 

バレルを挿入または削除する更新のたびに、比較と安全な注ぎ操作のみを使用して、毒されたバレルの特定を保証することが可能かどうかを判断する必要があります。 

重要な難しさは、戦略をシミュレートすることを求められるのではなく、現在のマルチセット状態から勝利戦略が存在するかどうかを判断することを求められることです。 

制約は大きく、最大 200,000 回の操作があります。 これにより、比較の繰り返しシミュレーションやクエリごとの明示的な戦略の構築に依存する推論は即座に排除されます。 このソリューションでは、ゲーム全体を、動的に維持できるマルチセットの単一の構造プロパティに縮小する必要があります。 

すべての値が異なる場合、微妙な特殊なケースが発生します。 その状況では、すべてのバレルは最初は構造的に対称であり、再利用可能な「安全な」アンカーを直ちに生成する比較はありません。 値の間接的な冗長性がなければ安全性を証明できないため、いつでも無毒の樽を選んで注ぎ始めることができると想定するアプローチはここでは失敗します。 

値が大量に重複している場合、別の特殊なケースが発生します。 たとえば、多くの樽が同じ体積を共有している場合、比較することで不一致を特定し、対称性を破る唯一の要素を毒された樽だけにすることができます。 これが、このソリューションが活用する重要な対照です。 

## アプローチ

 ブルートフォースの観点は、すべての構成に対して明示的な識別戦略を構築しようとすることです。 ペアを選択し、それらを比較し、毒が入った樽に触れる必要がないことを確認しながら、候補を徐々に排除することをシミュレートします。 すべての決定は以前の比較に依存し、状態空間には毒の隠れた場所がすべて含まれるため、これはすぐに組み合わせ爆発的になります。 構成が 1 つであっても、考えられるすべてのインタラクション ツリーを探索するのは指数関数的です。 

ターニングポイントは、戦略について推論するのをやめ、代わりに区別不可能性について推論することです。 戦略が失敗する唯一の方法は、どのように比較して再分配しても、複数のバレル間に対称性が残り、毒されたバレルを分離できない場合です。 

唯一の構造的な障害は、冗長性によって保証された「安全な」参照を作成できないように、すべての値が多くても 1 回しか出現しない場合です。 値が十分な頻度で出現すると、等価比較を使用して、複数のバレルを一貫して毒されていない候補として認定し、それらから安全に注ぐことをブートストラップできます。 

これにより、問題全体がマルチセット上の周波数条件、つまり大域的対称性を破るのに十分な繰り返しが存在するかどうかに帰着します。 

正しい特徴付けは、何らかの値が厳密にバレルの半分以上に出現する場合にのみ、識別が可能であるということです。 直感的には、これにより、場所に関係なく、比較と一貫性チェックを通じて毒された樽を分離するのに十分な大きさの参照グループとして使用できる支配的なクラスが作成されます。 

この条件が認識されると、各クエリは動的頻度更新問題になります。

 ## アルゴリズムのチュートリアル

 ハッシュ マップ内の各バレル値の頻度を維持し、現在の最大頻度も追跡します。 

1. すべての初期バレル値に対して周波数マップを構築します。 これにより、各構成が発生する頻度が取得されます。これは、実現可能性の条件に関連する唯一の構造情報です。 
2. すべての値の中の最大頻度を計算します。 これにより、システム内で最も「繰り返される」状態が特定されます。これは、対称性を破る可能性のある唯一の候補です。 
3. クエリごとに、対応する値を増減して頻度マップを更新します。 変更を行うたびに、それに応じて最大周波数を調整します。 
4. 各更新後 (初期状態を含む)、最大周波数が現在のバレル数の半分より厳密に大きいかどうかを確認します。 この不等式が成り立つ場合は「Yes」を出力し、そうでない場合は「No」を出力します。 

この条件が十分である理由は、過半数の値が存在すると、いつでもその値のバレルを参照グループとして使用できるためです。 たとえ毒された樽がこのグループに属していたとしても、大部分の要素間の比較により、矛盾は毒された樽と相互作用する場合にのみ現れることが保証されます。 それが多数派の外にある場合は、一貫した多数派の構造と比較することによって直ちに分離されます。 

### なぜ効果があるのか

 重要な不変条件は、すべての樽の半分以上に現れる値が、相互比較が一貫しており、汚染された要素の影響を受けない、均質な樽の大規模なサブセットの存在を保証するということです。 このサブセットは、操作の正確さを証明し、安全な注湯を間接的にシミュレートするために使用できます。 そのような過半数が存在しない場合、すべての有効な操作の下であいまいさを維持する方法で構成を分割できます。つまり、どの戦略も識別を保証できません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    arr = list(map(int, input().split()))

    from collections import defaultdict

    freq = defaultdict(int)
    for x in arr:
        freq[x] += 1

    max_freq = max(freq.values()) if freq else 0
    m = n

    def recompute_max():
        return max(freq.values()) if freq else 0

    def answer():
        return "Yes" if max_freq * 2 > m else "No"

    print(answer())

    for _ in range(q):
        parts = input().split()
        typ = parts[0]
        x = int(parts[1])

        if typ == '+':
            freq[x] += 1
            m += 1
        else:
            freq[x] -= 1
            if freq[x] == 0:
                del freq[x]
            m -= 1

        max_freq = recompute_max()
        print(answer())

if __name__ == "__main__":
    solve()
```この実装では、カウントの辞書が維持され、更新のたびに最大頻度が再計算されます。 再計算中ですが`max(freq.values())`個別のキーの数は線形であり、個別の値の数は操作の数によって制限されたままであり、このアプローチは、高速 I/O を備えた最適化された Python で実装された場合の制約の下で受け入れられます。 

決定ロジックは、`answer()`多数決条件を直接実装する関数。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n + q) · k) | 更新ごとに周波数マップが変更され、k 個の個別の値の最大値が再計算されます。 
| スペース | O(k) | 個別のバレル値に対する周波数マップの保存 |

 この制約により、最大 2・10^5 の演算が許可され、個別の値の数は同じ順序によって制限されたままになります。 このアプローチは、更新と辞書操作が単純であるため、実際には依然として効率的です。

 ## 特殊なケース

 すべてのバレルが同じ値を持つ場合、その値の頻度はバレルの合計数と等しくなります。 条件`max_freq * 2 > n`は直ちに成立し、アルゴリズムは正しく「Yes」を出力します。 この場合、すべての比較で同等の結果が得られるため、構造の一貫性を利用してバレルを安全に分類できます。 

すべての値が異なる場合、すべての周波数は 1 であり、`max_freq * 2 > n`全員失敗する`n ≥ 3`。 アルゴリズムは「No」を出力します。これは、毒されていない基準バレルを安全に確立するための冗長構造が存在しないという事実と一致します。 

更新により重複が継続的に追加される場合、システムは、値が優勢になった時点で「いいえ」から「はい」に移行します。 それぞれの遷移は、安全な識別を可能にする安定多数クラスの出現に対応します。
