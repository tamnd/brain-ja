 ## 解決策
 ## 問題の理解

 負ではない整数の配列が与えられ、そこから部分列を選択することができます。 そのサブシーケンスから、非常に具体的な接頭辞と接尾辞の条件がすべての分割点で確実に保持されるようにしながら、できるだけ多くの要素を保持したいと考えています。 

選択したサブシーケンスの接頭辞を見る場合、その接頭辞の最小値は常に、残りの接尾辞の mex 以上である必要があります。 セットの mex は、セット内に現れない最小の非負の整数であるため、ゼロから上の開始値に関してサフィックスがどの程度「完全」であるかを捕捉します。 

この条件により、最小値によって制御される左側と、小さな整数の欠落によって制御される右側との間に緊張が生じます。 サフィックスに 0 や 1 などの小さな数値が欠けている場合、その mex は小さくなるか 0 になるため、条件が容易になります。 ただし、サフィックスに連続した小さな整数が多数含まれている場合、その mex が大きくなり、プレフィックスの最小値も大きくなります。 

入力サイズはテスト ケース全体で大きく、合計要素数が最大 2·10^5 であるため、すべてのサブシーケンスを試行したり、分割ごとに mex を繰り返し再計算したりするソリューションは直ちに実行不可能になります。 テスト ケースごとに O(n^2) であっても遅すぎます。繰り返しの再計算が必要な場合は、要素ごとに O(n log n) であっても危険です。 これにより、頻度や欠損数を注意深く記録して、線形または線形に近い構造を実現することができます。 

配列に大きな値が多数含まれているものの、小さな値がほとんど含まれていない場合、微妙なエッジ ケースが発生します。 例えば、`[1000000000, 1000000000, 1000000000]`0 が出現しない限り、サフィックスの mex は常に 0 であるため、自明なサブシーケンスのみが許可されます。 もう 1 つのエッジ ケースは、0 が完全に欠落している場合です。この場合、接尾辞の mex は常に 0 となり、条件が自明になり、サブシーケンス全体が許可されます。 すべてのサフィックス分割に対して mex を明示的に維持しようとする単純なアプローチでは、欠損値が繰り返し再計算され、制約の下で失敗します。 

## アプローチ

 ブルートフォース戦略では、すべてのサブシーケンスを列挙し、それぞれが魔法であるかどうかをチェックします。 サブシーケンスごとに、すべての分割ポイントをテストし、接頭辞の最小値と接尾辞の mex を再計算する必要があります。 接頭辞の最小値を O(1) に維持したとしても、mex 計算が優勢です。各接尾辞 mex 計算は O(k) で、k は部分列の長さであり、指数関数的に多くの部分列が存在します。 これはまったく実現不可能です。 

より構造化された観察は、条件が実際に何を強制しているかを書き直すことで得られます。 有効なサブシーケンスを修正します。 位置 i での分割の場合、接尾辞 mex は接尾辞に現れる小さな数字によってのみ決定されます。 プレフィックスの最小値は、プレフィックスを拡張するにつれて単調減少します。 したがって、長いサブシーケンスに対して不等式を有効に保つ唯一の方法は、含める小さな整数の数を慎重に制御することです。小さな数が出現するたびに mex の複雑さが軽減され、将来の選択が制限されるためです。 

重要な洞察は、視点を逆転させることです。 接頭辞について考える代わりに、接尾辞の要件を追跡します。残りの部分の mex は、特定の値がすでに含まれているかどうかにのみ依存します。 最適な構築では、プレフィックスの最小制約をサポートするのに十分な大きな要素を確実に残しておきながら、小さな整数の存在をできるだけ遅らせたいと考えています。 

これは、mex の境界を維持できなくなる前に、各値を含める余裕が何回あるかを追跡することで、実現可能性を維持しようとする貪欲な構築につながります。 mex が現在のプレフィックスの最小しきい値を超えないように、サフィックスに常に十分な欠落構造があることを確認しながら、サブシーケンスの構築を効果的にシミュレートします。 

重要な点は、現在の mex 境界までの値 0、1、2、… のみが問題になるということです。 現在の mex しきい値より大きい値は、mex の中立要素として動作しますが、プレフィックスの最小値に影響を与える可能性があります。 したがって、問題は、含める小さな数値の数と、安定して減少するプレフィックスの最小値を維持することのバランスを取ることになります。これは、頻度をカウントし、左から右へ貪欲な選択をシミュレートすることで処理できます。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. 配列内のすべての値の頻度を数えますが、長さ n の構造体では mex が n を超えることはできないため、明示的に考慮するのは n までの値のみです。 n より大きい値は「無限」として扱われ、プレフィックスの最小動作にのみ影響します。 
2. 0 から始まる各値が何回出現するかを計算します。 これにより、要素を仮説的に削除したときにサフィックスの mex がどのように進化するかをシミュレートできます。 
3. mex 条件の実現可能性を維持しながら、どれだけの要素を保持できるかをシミュレーションして、答えを構築します。 私たちは、サフィックスに表示できる個別の小さな値がまだ「利用可能」にいくつあるかについての継続的な概念を維持しています。 
4. 有効性を維持する能力が高い順に要素を貪欲に含めます。 小さい値は mex を決定するため重要です。 大きな値は柔軟性があり、プレフィックスの最小制約に違反しない限り含めることができます。 
5. この構造は実質的に、配列で完全にサポートできる整数 0、1、2、... の最大のプレフィックスを決定することに加え、この構造に干渉しないすべての要素もカウントします。

微妙な点は、維持できる最大 mex レベルを決定すると、そのレベル以上のすべての要素を自由に含めることができますが、そのレベル未満の要素は可用性の制約に対して慎重に照合する必要があるということです。 

### なぜ効果があるのか

 サフィックスの mex は、0 から始まるすべての整数がそのサフィックスに存在するかどうかにのみ依存します。 このアルゴリズムは、mex がプレフィックスの最小値がサポートできるものを超えるサフィックスを作成しないことを暗黙的に保証します。 小さな整数の可用性を追跡し、このチェーンがどこまで拡張できるかを制限することにより、すべての分割が必要な不等式を満たすように強制します。 

mex 進行のサポートから値が除外されると、後で再導入しても以前の分割の実現可能性を向上させることはできないため、貪欲な選択は正しいです。 この単調性により、実現可能な最大 mex しきい値をグローバルに決定することで最適なサブシーケンス長が得られることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        cnt = [0] * (n + 2)
        for x in a:
            if x <= n:
                cnt[x] += 1
        
        mex = 0
        while mex <= n and cnt[mex] > 0:
            cnt[mex] -= 1
            mex += 1
        
        # all elements >= mex can be taken freely
        ans = mex
        for x in a:
            if x >= mex:
                ans += 1
        
        print(ans)

if __name__ == "__main__":
    solve()
```より大きな値は mex の進行に影響を与えることができないため、解決策は、出現回数を n までのみカウントすることから始まります。 次に、0 から始まる最大連続プレフィックスを構築し、各値の 1 つの出現を消費して、mex チェーンがどこまで拡張できるかを決定します。 その値がサブシーケンスの構造的バックボーンになります。 

この mex 境界が固定されると、接尾辞に欠落した下位整数が導入されず、mex の進行が中断されないため、それ以上のすべての要素を安全に含めることができます。 最終的な答えは、この最大チェーンのサイズに、そのような大きな要素をすべて加えたものになります。 

よくある落とし穴は、mex チェーンを拡張するために必要なのは小さな数値ごとに 1 つのコピーだけであり、追加のコピーは後で自由に使用できることを忘れることです。 もう 1 つの微妙な点は、n より大きい値は事実上同等であり、mex ループで処理すべきではないことです。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | テスト ケースあたり O(n) | 周波数カウントとシングルメックススキャン |
 | スペース | O(n) | 最大 n までの周波数配列 |

 合計の複雑さは合計入力サイズに線形であり、すべてのテスト ケースにわたって 2 · 10^5 未満に快適に収まります。 このアルゴリズムは、mex またはプレフィックス minima のネストされた再計算を回避し、すべての操作をシングルパスまたは n によって制限された状態に保ちます。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    t = int(sys.stdin.readline())
    out = []
    for _ in range(t):
        n = int(sys.stdin.readline())
        a = list(map(int, sys.stdin.readline().split()))
        
        cnt = [0] * (n + 2)
        for x in a:
            if x <= n:
                cnt[x] += 1
        
        mex = 0
        while mex <= n and cnt[mex] > 0:
            cnt[mex] -= 1
            mex += 1
        
        ans = mex + sum(1 for x in a if x >= mex)
        out.append(str(ans))
    
    return "\n".join(out)

 ## 特殊なケース

 配列にゼロが含まれていない場合、mex チェーンは開始することさえできません。 その状況では、アルゴリズムは mex を直ちに 0 に設定し、すべての要素はすべて ≥ mex であるため、自由に含めることができるものとして扱われます。 たとえば、入力`[5, 6, 7]`は mex = 0 を生成し、答えは 3 になります。これは、任意の部分列が条件を自明に満たすという事実と一致します。 

配列に小さな整数の完全なプレフィックスが正確に含まれているが、それより大きなブリッジ値は含まれていない場合。`[0,1,2,3]`、mex チェーンは完全に拡張され、追加の要素は寄与しません。 アルゴリズムは各値を 1 回消費し、mex = 4 で停止し、答え 4 を返します。 

重複が存在する場合、次のようになります。`[0,0,1,1,2,2]`、各値の 1 つのコピーのみが mex の拡張に使用されますが、チェーンが修正されると残りの重複は空き要素としてカウントされます。 このアルゴリズムは、チェーンおよびその後の残りのすべての出現についてレベルごとに 1 つを正確にカウントし、最適性を維持します。
