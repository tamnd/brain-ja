 ## 解決策
 ## 問題の理解

 ソートされた順列から始めます`1 2 3 ... n`。 誰かが連続したセグメントを 1 つだけ選択し、それを反転します。 私たちは最終的な順列を与えられ、それがそのような反転によって正確に 1 回生成されたかどうかを判断する必要があります。 

タスクは配列をソートすることではありません。 セグメントを特定するだけで済みます`[l, r]`元のソートされた配列内のそのセグメントを反転すると、指定された順列が生成されます。 そのようなセグメントが存在しない場合は、印刷します。`0 0`。 

制約は小さいですが、`n ≤ 1000`なので、二次アルゴリズムでも許容されます。 アン`O(n^2)`ソリューションは最悪の場合でも約 100 万回の操作を実行しますが、これは 2 秒の制限内ではわずかです。 これは、高度なデータ構造や高度なアルゴリズムが必要ないことを意味します。 クリーンな実装は、微細な最適化よりも重要です。 

難しいのは効率ではなく、エッジケースの正確さです。 

簡単な間違いの 1 つは、反転は中間の並べ替えからではなく、元の並べ替えられた配列から行われなければならないことを忘れていることです。 考慮する：```
5
1 3 2 5 4
```不注意なアプローチでは、2 つの減少セグメントに気づき、それらを何らかの方法で結合しようとする可能性があります。 ただし、1 つの反転で両方を同時に交換することはできません`(2,3)`そして`(4,5)`。 正しい出力は次のとおりです。```
0 0
```順列がすでにソートされている場合には、別の微妙なケースが発生します。```
4
1 2 3 4
```このステートメントでは、異なるエンドポイントを持つセグメントを逆にする必要があります。 長さ 1 のセグメントを反転しない限り、反転によって配列自体が変更されることはありません。これは禁止されています。`l < r`。 正しい答えは次のとおりです。```
0 0
```単純に不一致を検索する単純な実装では、次のような内容が誤って出力される可能性があります。`1 1`。 

3 番目のエッジ ケースは、反転されたセグメントが境界に接触する場合です。```
5
5 4 3 2 1
```ここでは配列全体が逆になっているため、正しい答えは次のようになります。```
1 5
```セグメントは最初の要素で始まり、最後の要素で終わるため、ここではオフバイワンの間違いがよくあります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 元の順列は常に`1 2 3 ... n`、可能なすべてのペアを試すことができます`(l, r)`、そのセグメントを反転し、結果が入力の順列と一致するかどうかを確認します。 

がある`O(n^2)`可能なセグメント。 アレイのコストを逆にして比較する`O(n)`時間がかかるため、全体の複雑さは次のようになります`O(n^3)`。 と`n = 1000`、これは最悪の場合、約 10 億回の操作を意味しますが、これは Python では遅すぎます。 

問題の構造から、より良い観察が得られます。 1 つのセグメントを反転することによって順列が作成された場合、そのセグメントの外側のどこでも、数字は元の位置に表示される必要があります。 

これは、最初のインデックスを意味します。`a[i] != i + 1`は反転セグメントの左端点である必要があります。 同様に、反転セグメントを通過し始めると、値は反転によって生じるのとまったく同じように減少する必要があります。 

例えば：```
1 6 5 4 3 2 7 8
```最初の不一致は位置で発生します`2`。 そこから順位まで数値が減少します`6`。 元のソートされた配列の間隔を逆にすると、順列が正確に再構築されます。 

これにより、タスクが 1 つの候補セグメントの特定と検証に減ります。 配列を一定の回数だけスキャンするだけなので、複雑さは線形になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n3) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 順列を読み取ります。 
2. 最初の位置を見つける`l`どこ`a[l] != l + 1`。 

そのような位置が存在しない場合、順列はすでにソートされているため、有効な反転は存在しません。 印刷する`0 0`。 
3. から始める`l`、 伸ばす`r`一方、シーケンスは厳密に減少しています。 

ソートされた配列から取得された反転セグメントは、最終的な並べ替えで降順に出現する必要があります。 このステップでは、最大の候補セグメントを特定します。 
4. サブ配列を元に戻す`l`に`r`。 

順列のコピーに対して直接反転を実行して、この操作によって並べ替えられた順序が復元されるかどうかをテストします。 
5. 結果の配列が次と等しいかどうかを確認します。`1 2 3 ... n`。 

「はい」の場合、印刷します`l + 1`そして`r + 1`1 から始まるインデックスを使用します。 

それ以外の場合は、印刷します`0 0`。 

### なぜ効果があるのか

 最初の間違った位置は、その前の位置が元の並べ替えられた順列とすでに一致しているため、反転されたセグメントに属している必要があります。 

反転されたセグメント内では、値は降順で表示される必要があります。 元の配列は厳密に増加していたため、連続した部分を反転すると、その順序が 1 回だけ反転されます。 延長中`r`シーケンスが減少する一方で、可能な唯一の候補セグメントが特定されます。 

そのセグメントを反転するとソートされた配列が復元される場合、その順列は 1 回の反転によって生成されたことになります。 そうでない場合、有効なセグメントは最初の不一致から始まり、反転によって作成された減少パターンに従う必要があるため、他のセグメントは機能しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    l = -1

    for i in range(n):
        if a[i] != i + 1:
            l = i
            break

    if l == -1:
        print(0, 0)
        return

    r = l

    while r + 1 < n and a[r] > a[r + 1]:
        r += 1

    b = a[:]
    b[l:r + 1] = reversed(b[l:r + 1])

    if b == list(range(1, n + 1)):
        print(l + 1, r + 1)
    else:
        print(0, 0)

solve()
```最初のループでは、順列と並べ替え順序の間の最も古い不一致を検索します。 これにより、反転セグメントをどこから開始する必要があるかが識別されます。 

不一致が存在しない場合、順列はすでにソートされています。 問題が必要なので、`l < r`、空の演算や長さ 1 の反転は使用できないため、答えは次のようになります。`0 0`。 

2 番目のループは、シーケンスが減少し続ける間に右側の境界を拡張します。 これは、元の順列から増加するセグメントを反転することによって生成された正確な形状をキャプチャします。 

行:```
b[l:r + 1] = reversed(b[l:r + 1])
```疑わしい反転を元に戻した後、配列の修正バージョンを作成します。 

最後に、ソートされた順列と比較します。 減少セグメントだけでは十分ではないため、この検証ステップは不可欠です。 次のような配列:```
1 5 4 3 2 6 8 7
```複数の乱れた領域が含まれており、1 回の反転では修正できません。 

コピーした配列を使用すると、元のデータを誤って変更することがなくなります。 境界では Python のスライス規則が慎重に使用されます。`r + 1`右側のエンドポイントは排他的であるため、必要です。

import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    def solve():
        n = int(input())
        a = list(map(int, input().split()))

        l = -1

        for i in range(n):
            if a[i] != i + 1:
                l = i
                break

        if l == -1:
            return "0 0"

        r = l

        while r + 1 < n and a[r] > a[r + 1]:
            r += 1

        b = a[:]
        b[l:r + 1] = reversed(b[l:r + 1])

        if b == list(range(1, n + 1)):
            return f"{l + 1} {r + 1}"

        return "0 0"

    return solve()

# already sorted

 ## 特殊なケース

 すでにソートされた順列を考えてみましょう。```
4
1 2 3 4
```アルゴリズムは最初の不一致をスキャンしますが、何も見つかりません。`l`残る`-1`。 この時点で、すぐに次のように出力されます。```
0 0
```この問題では個別のエンドポイントを使用した逆転が必要なため、これは正解です。 

次に、両方の境界に触れる反転を考えてみましょう。```
5
5 4 3 2 1
```最初の不一致はインデックスで発生します`0`。 スキャンの減少はインデックス作成まで継続されます。`4`。 そのセグメントを逆にすると、ソートされた順序が正確に復元されるため、アルゴリズムは次のように出力します。```
1 5
```これにより、境界インデックスが正しく処理されることが確認されます。 

最後に、2 つの別々の壊れた領域を持つ順列を調べます。```
5
1 3 2 5 4
```最初の不一致は位置に表示されます`2`。 減少するセグメントは`3 2`。 これを逆にすると次のようになります。```
1 2 3 5 4
```配列はまだソートされていないため、検証は失敗し、アルゴリズムは次のように出力します。```
0 0
```この最後の検証ステップにより、単一のグローバル反転を表さない局所的な減少セグメントによる誤検知が防止されます。
