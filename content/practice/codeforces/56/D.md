 ## 解決策
 ## 問題の理解

 2 つの大文字の文字列が与えられています。`s`そして`t`。 私たちは変身するかも知れません`s`3 つの操作を使用します。 

1. 任意の位置に文字を挿入します。 
2. 任意の位置の文字を削除します。 
3. ある文字を別の文字に置き換えます。 

すべての操作には 1 回の移動が必要です。 タスクは、ターンに必要な最小移動数を計算することだけではありません。`s`の中へ`t`だけでなく、この最小値を達成する 1 つの実際の操作シーケンスも出力します。 

これは古典的な編集距離の問題ですが、操作が再構築されています。 再構築部分では、実装上のミスが最も多く発生します。 

文字列の長さは最大でも 1000 です。分岐要素が膨大であるため、考えられるすべての操作シーケンスに対する総当たり検索は絶望的です。 わずか 20 ステップですべての操作を試しただけでも、すでに指数関数的に爆発的に増加します。 最大 1000 の長さでは、二次時間に近い値が必要になります。 

動的プログラミング ソリューション`O(n * m)`ここでは完全に実現可能です。 どちらの長さも 1000 に等しいため、状態は 100 万個になります。 各状態は一定時間で遷移するため、制限内に簡単に収まります。 

難しいのは、文字列が時間の経過とともに変化するときに、有効な操作インデックスを生成することです。 

次の例を考えてみましょう。```
s = ABC
t = ADBC
```挿入することにした場合`D`後`A`の場合、操作は次のようにする必要があります。```
INSERT 2 D
```挿入後、それ以降のすべての位置が 1 つずつシフトされます。 元の文字列に対する相対的な位置を計算する不用意な再構築は、すぐに矛盾してしまいます。 

もう 1 つの微妙なケースは、複数の最適な答えが存在する場合です。```
s = A
t = B
```次のいずれかが可能です。```
REPLACE 1 B
```または：```
DELETE 1
INSERT 1 B
```2 番目のシーケンスは長いため、再構築は最適性を維持する遷移のみに従う必要があります。 

最後の一般的なバグは、一方の文字列が他方の文字列より先に使い果たされるときに発生します。```
s = ABC
t = ABCDE
```残りの作業は純粋な挿入です。```
INSERT 4 D
INSERT 5 E
```以前の挿入後にインデックスが正しく計算されなかった場合、生成された操作は無効になります。 

## アプローチ

 ブルートフォースアプローチは概念的には単純です。 すべてのステップで、可能なすべての挿入、削除、置換を試み、ターゲット文字列に到達するまですべての変換シーケンスを再帰的に探索します。 すべての操作で文字列が変更されるため、到達可能な状態の数は指数関数的に増加します。 

長さが 20 の文字列であっても、可能性の数は膨大になります。 ステップごとにおよそ 60 の可能な操作を許可し、編集が 15 のみ必要だと仮定します。 それはすでに与えられています`60^15`計算可能なものをはるかに超えた可能性。 

ブルート フォースが概念的に機能する理由は、編集操作によって自然に検索ツリーが形成されるためです。 問題は、多くの異なるシーケンスによって同じ中間プレフィックスが繰り返し発生することです。 同等の部分問題を何度も再計算します。 

重要な観察は、将来は文字列の残りの接尾辞にのみ依存するということです。 

次のように一致するとします。```
s[i:]
t[j:]
```この時点からの最適な答えは、どのようにしてここに到達したかは関係ありません。 つまり、DP 状態を定義できます。```
dp[i][j] = minimum edits needed to transform s[i:] into t[j:]
```現在、すべての状態には意味のある遷移が 3 つだけあります。 

1. 削除`s[i]`2.挿入`t[j]`3. 交換する`s[i]`と`t[j]`それらが異なる場合

 キャラクターがすでに一致している場合は、何も支払わずに単純に斜めに移動します。 

これにより、問題は指数関数的検索からグリッド DP に軽減されます。`n * m`州。 

最小距離を計算した後、DP テーブルを調べ、保存されている最適値と一致する遷移を選択することにより、1 つの最適なパスを再構築します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | 指数 | 遅すぎる |
 | 最適なDP | O(nm) | O(nm) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. しましょう`n = len(s)`そして`m = len(t)`。 
2. DP テーブルの作成`dp`サイズの`(n + 1) × (m + 1)`。`dp[i][j]`接尾辞を変換するために必要な最小限の編集を表します`s[i:]`の中へ`t[j:]`。 
3. 基本ケースを初期化します。 

もし`i = n`、ソース文字列が使い果たされたため、残りの文字をすべて挿入する必要があります。`t`。```
dp[n][j] = m - j
```もし`j = m`、ターゲット文字列が使い果たされたため、残りの文字をすべて削除する必要があります。`s`。```
dp[i][m] = n - i
```4. 表を右下から左上に向かって埋めていきます。 

もし`s[i] == t[j]`、これらの文字に対して操作は必要ありません。```
dp[i][j] = dp[i + 1][j + 1]
```それ以外の場合は、3 つの編集操作を検討します。 

消去：```
1 + dp[i + 1][j]
```入れる：```
1 + dp[i][j + 1]
```交換する：```
1 + dp[i + 1][j + 1]
```最低限のものを採用しております。 
5. 1 つの最適な操作シーケンスを再構築します。 

から開始`(i, j) = (0, 0)`そして変数を維持します`shift`。`shift`挿入と削除によりインデックスが変更されるため、現在の文字列の長さが元の文字列とどの程度異なるかを追跡します。 
6. もし`s[i] == t[j]`そして：```
dp[i][j] == dp[i + 1][j + 1]
```操作を行わずに斜めに移動します。 
7. それ以外の場合は、どの操作が最適性を維持するかを確認します。 

削除の場合:```
dp[i][j] == 1 + dp[i + 1][j]
```出力：```
DELETE position
```現在の位置は次のとおりです。```
i + shift + 1
```次にインクリメントします`i`そして減少します`shift`。 
8. 挿入の場合:```
dp[i][j] == 1 + dp[i][j + 1]
```出力：```
INSERT position character
```挿入位置は再び次のとおりです。```
i + shift + 1
```次にインクリメントします`j`そして増加します`shift`。 
9. 交換の場合:```
dp[i][j] == 1 + dp[i + 1][j + 1]
```出力：```
REPLACE position character
```次に、両方をインクリメントします`i`そして`j`。 
10. 両方の文字列が完全に処理されるまで続行します。 

### なぜ効果があるのか

 DP の不変条件は次のとおりです。`dp[i][j]`変換に必要な真の最小編集数を常に保存します。`s[i:]`の中へ`t[j:]`。 

有効な変換はすべて、次の 4 つの可能性のうちの 1 つで開始する必要があります。 

1. 等しい文字と一致します。 
2. 現在の文字を削除します。`s`。 
3. 現在の文字を挿入します`t`。 
4. 現在の文字を置き換えます`s`。 

繰り返しでは、それらすべてをチェックし、最適なものを選択します。 各遷移はより小さい接尾辞に向かって移動するため、必要な状態はすべてすでに計算されています。 

再構築中、コストが保存された最適値と正確に一致する遷移のみを追跡します。 これにより、選択されたすべての操作がグローバルに最適なソリューションに属することが保証されます。 

の`shift`変数は、文字列の長さが動的に変更された後でも、位置が正しいままであることを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    t = input().strip()

    n = len(s)
    m = len(t)

    dp = [[0] * (m + 1) for _ in range(n + 1)]

    for i in range(n + 1):
        dp[i][m] = n - i

    for j in range(m + 1):
        dp[n][j] = m - j

    for i in range(n - 1, -1, -1):
        for j in range(m - 1, -1, -1):
            if s[i] == t[j]:
                dp[i][j] = dp[i + 1][j + 1]
            else:
                dp[i][j] = 1 + min(
                    dp[i + 1][j],      # delete
                    dp[i][j + 1],      # insert
                    dp[i + 1][j + 1]   # replace
                )

    operations = []

    i = 0
    j = 0
    shift = 0

    while i < n or j < m:
        if i < n and j < m and s[i] == t[j] and dp[i][j] == dp[i + 1][j + 1]:
            i += 1
            j += 1

        elif i < n and dp[i][j] == 1 + dp[i + 1][j]:
            pos = i + shift + 1
            operations.append(f"DELETE {pos}")
            i += 1
            shift -= 1

        elif j < m and dp[i][j] == 1 + dp[i][j + 1]:
            pos = i + shift + 1
            operations.append(f"INSERT {pos} {t[j]}")
            j += 1
            shift += 1

        else:
            pos = i + shift + 1
            operations.append(f"REPLACE {pos} {t[j]}")
            i += 1
            j += 1

    print(len(operations))
    print("\n".join(operations))

solve()
```最初の部分では、小さいサフィックスから大きいサフィックスに向かって DP テーブルを構築します。 すべての遷移はより大きなインデックスを持つ状態を参照するため、後方への反復により、それらの値がすでに存在していることが保証されます。 

再建段階は最も注意が必要な段階です。 

変数`shift`元の文字列を基準にして位置がどのように変化するかを追跡します。 先ほど 2 文字を挿入したとします。 次に、現在の文字列内の将来のすべての位置が次のようにシフトされます。`+2`。 

この調整を行わないと、最初の挿入または削除後に操作の対象となるインデックスが間違ってしまいます。 

再建の順番も重要だ。 編集操作の前に、一致する文字をチェックする必要があります。 そうしないと、アルゴリズムが不必要に等しい文字を置換し、いくつかの同点の状況で数値的に最適性を維持する可能性があります。 

ループ条件:```
while i < n or j < m:
```一方の文字列が他方の文字列より先に終了する可能性があるため、これは重要です。 残りの挿入または削除を出力する必要があります。

 ### 例 1

 入力:```

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(nm) | Every DP state is computed once |
 | スペース | O(nm) | The full DP table is stored for reconstruction |

 どちらの文字列も長さが 1000 に制限されているため、DP テーブルには約 100 万個のセルが含まれます。 これはメモリ制限内に十分収まり、操作数は 2 秒以内で Python にとって十分に少ないものです。

 ## 特殊なケース

 サフィックスの追加だけが原因でターゲット文字列が長くなる場合を考えてみましょう。 

入力：```
ABC
ABCDE
```DP は最終的に以下に到達します。```
dp[3][3] = 2
```ソースサフィックスは空ですが、ターゲットサフィックスは空であるため、`"DE"`。

最後に、等しい文字列について考えてみましょう。
