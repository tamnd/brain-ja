 ## 解決策
 ## 問題の理解

 ヴァシャはバーに入ると数人の客に会いました。 各顧客について、彼が知っている情報は 1 つだけです。その人の年齢か注文した飲み物のいずれかです。 彼は、18 歳未満の飲酒者がいないことを保証するために、さらに何人の検査が必要かを判断したいと考えています。 

顧客は必ず 2 つの状況を確認する必要があります。 1 つ目は、飲み物を確認する必要があるため、顧客が 18 歳未満であることがすでにわかっている場合です。 2 つ目は、年齢を確認する必要があるため、顧客がアルコールを注文したことがすでにわかっている場合です。 

入力は文字列のシーケンスです。 文字列には、年齢を表す数字もあれば、大文字で書かれたドリンク名も含まれます。 タスクは、疑わしいエントリの数を数えるだけであり、検証が必要です。 

制約はわずかです。 顧客は最大 100 人で、各文字列の長さは最大 100 です。非効率なソリューションであっても即座に実行されます。 入力をリニアにスキャンするだけで十分です。 

主な難しさはパフォーマンスではなく、年齢と飲み物の名前を正しく区別することです。 

簡単な間違いの 1 つは、18 歳が合法であることを忘れていることです。 厳密に 18 歳未満の年齢のみチェックが必要です。 

例えば：```
3
17
18
19
```正しい出力は次のとおりです。```
1
```17歳のみチェックが必要です。 

もう 1 つのよくある間違いは、すべての単語をアルコールとして扱うことです。 指定されたリストの飲み物のみがカウントされます。 

例えば：```
4
WATER
JUICE
BEER
COKE
```正しい出力は次のとおりです。```
1
```のみ`BEER`アルコール依存症です。 

数値を解析するときに、さらに微妙なバグが発生します。 入力`"0"`または`"5"`はまだ古いので、文字列のドリンク名としてではなく、数値として処理する必要があります。 

例えば：```
2
5
VODKA
```正しい出力は次のとおりです。```
2
```1人目の客は未成年、2人目の客はアルコールを注文した。 

## アプローチ

 ブルートフォース解釈は非常に直接的です。 すべての顧客について、既知の情報によってその人が法律に違反している可能性があることがすでに証明されているかどうかを判断するよう努めます。 

入力トークンが数値の場合、それを 18 と比較します。年齢が小さい場合、この人物をチェックする必要があります。 

トークンが単語の場合は、それをアルコール飲料のリストと比較します。 単語がそのセットに属している場合は、この人物もチェックする必要があります。 

これはすでに最終的な解決策のように思えますが、最初に単純なバージョンを考えることもできます。 アルコール名をリストに保存し、飲み物ごとにリスト全体を線形にスキャンしたとします。 アルコール名は 11 件しかなく、顧客は最大でも 100 人であるため、合計の作業量は依然として少なく、約 1100 件の比較になります。 

よりクリーンな最適化とは、すべてのアルコール飲料をセットで保管することです。 そうすれば、メンバーシップチェックは平均して一定時間になります。 これにより、ロジックが即時ルックアップによる入力を 1 回通過するように削減されます。 

重要な観察は、各顧客を独立して評価できるということです。 異なる顧客間には対話が存在しないため、並べ替え、動的プログラミング、またはグラフ処理は必要ありません。 疑わしいエントリをカウントするだけです。

 | --- | --- | --- | --- |
 | ブルートフォース | O(n × 11) | お(1) | 承認済み |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのアルコール飲料名をセットで保管します。 

セットを使用すると、飲み物の名前を見つけたときにメンバーシップを迅速に確認できます。 
2. 顧客数を読み取る`n`。 
3. カウンタの初期化`ans = 0`。 
4. それぞれについて`n`入力文字列:

 文字列が数値を表しているのか単語を表しているのかを確認します。 
5. 文字列が数値の場合:

 整数の年齢に変換します。 

18歳未満の場合は加算されます`ans`。 

これらの顧客は違法に飲酒している可能性があるため、検査が必要です。 
6. それ以外の場合、文字列はドリンク名です。 

アルコールセットにドリンクが存在する場合、インクリメントします`ans`。 

これらの顧客は未成年の可能性があるため、確認する必要があります。 
7. 印刷`ans`。 

### なぜ効果があるのか

 すべての顧客は、年齢がわかっているか、飲み物がわかっているかという 2 つのカテゴリのいずれかに正確に当てはまります。 

年齢がわかっていてそれが 18 歳未満である場合は、飲み物を検査して合法性を確認する必要があります。 飲み物がアルコールであることがわかっている場合は、年齢を検査する必要があります。 

18 歳以上のお客様は、お飲み物を問わずすでに安全です。 ノンアルコール飲料をお飲みのお客様にも、年齢を問わず安心してご利用いただけます。 

このアルゴリズムは、情報が不足していると違反が明らかになる可能性がある顧客を正確にカウントします。 各顧客は個別に処理され、疑わしいケースはすべて 1 回カウントされるため、最終的な答えは正しいものになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

alcohol = {
    "ABSINTH",
    "BEER",
    "BRANDY",
    "CHAMPAGNE",
    "GIN",
    "RUM",
    "SAKE",
    "TEQUILA",
    "VODKA",
    "WHISKEY",
    "WINE"
}

n = int(input())
ans = 0

for _ in range(n):
    s = input().strip()

    if s.isdigit():
        if int(s) < 18:
            ans += 1
    else:
        if s in alcohol:
            ans += 1

print(ans)
```解決策は、すべてのアルコール飲料をセットで保管することから始まります。 メンバーシップのチェックは高速かつ簡潔であるため、ここではセットが自然な構造になります。 

ループは一度に 1 人の顧客を処理します。 方法`isdigit()`年齢と飲み物の名前を明確に区別します。 ドリンク名には大文字のみが含まれるため、曖昧さはありません。 

トークンが数値の場合、コードはそれを整数に変換し、それが厳密に 18 未満であるかどうかをチェックします。`< 18`の代わりに`<= 18`18 歳は合法であるため、これは重要です。 

トークンが数値でない場合、コードは飲み物がアルコール セットに属しているかどうかをチェックします。 記載されている飲み物のみがアルコールとしてカウントされます。 

このアルゴリズムではすべての顧客を同時に保存することはないため、メモリ使用量は一定に保たれます。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    alcohol = {
        "ABSINTH",
        "BEER",
        "BRANDY",
        "CHAMPAGNE",
        "GIN",
        "RUM",
        "SAKE",
        "TEQUILA",
        "VODKA",
        "WHISKEY",
        "WINE"
    }

    n = int(input())
    ans = 0

    for _ in range(n):
        s = input().strip()

        if s.isdigit():
            if int(s) < 18:
                ans += 1
        else:
            if s in alcohol:
                ans += 1

    print(ans)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out

    solve()

    sys.stdout = sys.__stdout__
    return out.getvalue().strip()

# provided sample
assert run(
"""5
18
VODKA
COKE
19
17
""") == "2", "sample 1"

# minimum-size input

"""1
18
""") == "0", "minimum case"

VODKA
""") == "3", "all alcoholic"

""") == "2", "boundary ages"

 ## 特殊なケース

 法的な境界年齢を考慮してください。 

入力：```
3
17
18
19
```アルゴリズムは各値を数値的に処理します。`17 < 18`, したがって、答えは 1 になります。`18 < 18`は false なので、答えは 1 のままです。`19 < 18`も誤りです。 

最終的な出力は次のとおりです。```
1
```これは、アルゴリズムが正確に 18 を正当なものとして正しく扱うことを確認します。 

次に、アルコールではない未知の飲み物について考えてみましょう。 

入力：```
4
WATER
COKE
BEER
JUICE
```アルゴリズムは各単語をアルコール セットと照合してチェックします。`WATER`は存在しません。`COKE`は存在しません。`BEER`が存在するので、答えは 1 に増加します。`JUICE`は存在しません。 

最終的な出力は次のとおりです。```
1
```これにより、すべてのドリンク名をアルコールとして扱うというよくある間違いを防ぐことができます。 

最後に、非常に小さい年齢について考えてみましょう。 

入力：```
2
0
VODKA
```トークン`0`は数値なので、整数 0 に変換されます。`0 < 18`の場合、答えは 1 になります。`VODKA`はアルコールセットに属しているため、答えは 2 になります。 

最終的な出力は次のとおりです。```
2
```これにより、アルゴリズムが飲み物の名前ではなく 1 桁の数値文字列を年齢として正しく処理していることが確認できます。
