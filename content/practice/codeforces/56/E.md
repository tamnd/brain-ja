 ## 解決策
 ## 問題の理解

 数直線上にドミノを並べています。 各ドミノは座標に立っています`x[i]`そして高さがある`h[i]`。 ドミノが右に倒れると、そこからすべての点に到達します。`x[i] + 1`まで`x[i] + h[i] - 1`。 

位置がその間隔内にあるドミノも落下し、その後、それ自身の落下範囲が連鎖反応を続ける可能性があります。 

すべてのドミノについて、そのドミノが右に押された場合に最終的に何個のドミノが倒れるかを計算する必要があります。 

位置は任意であり、入力内で必ずしも並べ替えられる必要はありません。 2 つのドミノが同じ座標を共有することはありません。 

ここでの本当の課題は制約です。 最大で`10^5`ドミノのように、二次関数はすでに高価すぎます。 すべての開始ドミノからの直接シミュレーションを簡単に実行できます。`10^10`最悪の場合、2 秒に収まる時間をはるかに超えた操作が行われます。 に近いものが必要です`O(n log n)`。 

難しいのは、連鎖反応が推移的であるということです。 ドミノは別のドミノに直接到達することはできませんが、中間のドミノを介して倒すことはできます。 

次の例を考えてみましょう。```
3
1 2
2 100
50 2
```ドミノ 1 はドミノ 2 に到達し、ドミノ 2 はドミノ 3 に到達します。ドミノ 1 の正解は次のとおりです。`3`、 ない`2`。 

直接到達のみをチェックする単純な実装では、ここでは失敗します。 

もう 1 つの微妙なケースは、ステートメント内の厳密な不平等から生じます。 ドミノが倒れるのは、厳密にベースの上に触れた場合のみです。 

例：```
2
1 2
3 2
```最初のドミノがポジションに到達する`[2, 2]`、その位置でドミノにぶつからない`3`。 

正しい出力:```
1 1
```使用する`x + h`の代わりに`x + h - 1`黙って間違った答えを生み出します。 

また、後のドミノが元のドミノを超えて合計リーチを拡張する連鎖エッジケースもあります。 

例：```
4
1 3
3 3
5 3
100 2
```ドミノ 1 はドミノ 2 に直接到達します。ドミノ 2 はドミノ 3 に到達します。ドミノ 1 の合計の答えは次のとおりです。`3`。 

拡張された範囲を伝播せずに直接隣接するもののみを処理する貪欲なシミュレーションでは、停止が早すぎます。 

## アプローチ

 ブルートフォースのアイデアは単純です。 すべてのドミノについて、連鎖反応をシミュレートします。 

まずドミノを座標で並べ替えます。 それではドミノからスタート`i`、現在到達可能な最も遠い位置を追跡します。 リーチ内のすべてのドミノが倒れ、リーチがさらに伸びる可能性があります。 

落下動作は決定的であるため、このプロセスは正しいです。 新しいドミノが倒れるたびに、その間隔を現在の連鎖反応にマージします。 

問題は複雑さです。 最悪の場合、開始するすべてのドミノが配列のほぼ全体をスキャンする可能性があります。 

例：```
1 1000000
2 1000000
3 1000000
...
```各ドミノは残りのドミノをすべて倒します。 合計作業量は次のようになります。```
n + (n-1) + (n-2) + ...
```それは`O(n^2)`。 

と`n = 10^5`、それはその辺です`5 * 10^9`操作。 

重要な観察は、座標でソートした後、ドミノの効果が連続したセグメントになるということです。 

ドミノを想定してみよう`i`最終的にはドミノ倒しします`i`を通して`r[i]`。 

ドミノの答えがすでにわかっている場合`i+1`、`i+2`など、連鎖反応を最初から再計算するのではなく、その情報を再利用できます。 

これは、右から左への動的プログラミングを示唆しています。 

位置にあるドミノの場合`x[i]`高さのある`h[i]`、最初に、それ自身の落下によって直接触れられた最後のドミノを見つけます。```
x[j] < x[i] + h[i]
```間隔には次までが含まれるため、`x[i] + h[i] - 1`。 

二分探索ではこの境界が得られます。`O(log n)`。 

ここで重要な圧縮ステップが始まります。 

ドミノなら`i`ドミノに直接届く`k`、ドミノ`k`それ自体が最終的に到達する`r[k]`、次にドミノ`i`も届きます`r[k]`。 

したがって、一度に 1 つのドミノを展開するのではなく、計算済みのセグメントに繰り返しジャンプします。 

これにより、ソート後に線形時間伝播が作成されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのドミノを読み取り、元のインデックスを保存します。 
2. ドミノを座標順に並べ替えます。 

連鎖反応は右方向にのみ移動するため、ソートすると問題が配列上の区間拡張に変わります。 
3. ソートされた位置を別の配列に抽出します。`xs`。 

これにより、座標の二分検索が可能になります。 
4. ドミノを右から左に処理します。 

ドミノ効果を計算する場合`i`、その右側にあるすべてのドミノは、最終リーチがすでに計算されています。 
5. ドミノの場合`i`、その直接到達制限を計算します。```
limit = x[i] + h[i]
```座標が厳密に小さいドミノ`limit`直接落ちます。 
6. 二分探索を使用して、直接到達可能な最後のドミノを見つけます。 

Python の場合:```
j = bisect_left(xs, limit) - 1
```7.初期化`reach[i] = j`。 

最低でもドミノ`i`その間隔内ですべてを直接転倒させます。 
8. すでに計算された答えを使用して範囲を拡大します。 

からのセグメントを処理している間、`i`に`reach[i]`、ドミノ自体がさらに遠くまで届くものもあります。 

繰り返し更新します:```
reach[i] = max(reach[i], reach[k])
```現在のセグメント内のすべてのドミノ。 
9. ドミノの答え`i`は：```
reach[i] - i + 1
```10. 回答を元の入力順序に戻します。 

### なぜ効果があるのか

 不変条件は、ドミノを処理するときです。`i`、その右側にあるすべてのドミノは、最終的に倒すことができる最も遠いドミノをすでに知っています。 

当初は、`reach[i]`ドミノが直接ヒットしたすべてのドミノが含まれます`i`。 

ドミノなら`k`その範囲内でそれ自体がチェーンを拡張できます`reach[k]`、その後、からの元の連鎖反応`i`その拡張子も含める必要があります。 

すべての拡張は右に移動するだけであるため、これらの間隔を繰り返しマージすると、最終的には正確な最大到達可能セグメントが生成されます。 

到達可能なドミノが見逃されることも、到達できないドミノが追加されることもありません。 

## Python ソリューション```python
import sys
from bisect import bisect_left

input = sys.stdin.readline

n = int(input())

dominoes = []
for i in range(n):
    x, h = map(int, input().split())
    dominoes.append((x, h, i))

dominoes.sort()

xs = [x for x, _, _ in dominoes]

reach = [0] * n
ans = [0] * n

for i in range(n - 1, -1, -1):
    x, h, _ = dominoes[i]

    limit = x + h
    j = bisect_left(xs, limit) - 1

    reach[i] = j

    k = i + 1
    while k <= reach[i]:
        reach[i] = max(reach[i], reach[k])
        k += 1

    ans[dominoes[i][2]] = reach[i] - i + 1

print(*ans)
```最初のステップでは、各ドミノを元のインデックスとともに保存します。 区間推論には並べ替えが必要ですが、最終的な答えは入力順序と一致する必要があります。 

二分探索は微妙です。 位置にあるドミノ`p`次の場合にのみ該当します。```
p <= x[i] + h[i] - 1
```これは次と同等です。```
p < x[i] + h[i]
```それが私たちが使用する理由です`bisect_left(xs, limit)`。 

伝播ループは最適化の中核です。 開始ドミノごとに個々の転倒を個別にシミュレートする代わりに、すでに計算されたリーチ間隔を再利用します。 

右から左に処理すると、次のことが保証されます。`reach[k]`必要なときにすでに完成されています。 

ループ:```
while k <= reach[i]:
```も間違えやすいです。 反復中に範囲が拡大する可能性があるため、境界を動的にチェックする必要があります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | 並べ替えと二分検索が主流 |
 | スペース | O(n) | 位置、リーチ、および回答の配列 |

 仕分け費用`O(n log n)`、各二分探索コスト`O(log n)`。 各ドミノはすでに計算された間隔ジャンプを通じてのみ寄与するため、伝播ステップは全体として事実上線形です。 

と`n = 10^5`、これは制限内に快適に収まります。

        dominoes.append((x, h, i))

            reach[i] = max(reach[i], reach[k])

    print(*ans)

    backup_stdout = sys.stdout

    sys.stdout = io.StringIO()

    out = sys.stdout.getvalue().strip()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

 ## 特殊なケース

 厳密な境界の場合を考えてみましょう。```
2
1 2
3 2
```ドミノ`1`唯一の位置に達する`2`。 ドミノ`2`所定の位置に立つ`3`なので直立したままになります。 

アルゴリズムは以下を計算します。```
limit = 1 + 2 = 3
```それから：```
bisect_left(xs, 3)
```座標が指定されている最初のインデックスを返します`3`が表示されます。 1 を減算すると、そのドミノが正しく除外されます。 

最終的な答えは次のようになります。```
1 1
```ここで推移的な伝播を考えてみましょう。```
3
1 2
2 100
50 2
```ドミノ`0`ドミノに直接届く`1`。 

ドミノ`1`ドミノに到達`2`。 

ドミノの処理中`0`、伝播ループは次のようにマージします。```
reach[0] = max(reach[0], reach[1])
```これにより、ドミノが含まれるようにセグメントが拡張されます。`2`。 

出力は次のようになります。```
3 2 1
```最後に、ソートされていない入力について考えてみましょう。```
4
100 2
1 100
50 2
2 2
```アルゴリズムは処理前に座標によって並べ替えます。```
(1,100), (2,2), (50,2), (100,2)
```答えを計算した後、元のインデックスを使用して答えを保存します。 

これにより、回答が入力順ではなく並べ替えられた順に印刷されるというよくある間違いを防ぐことができます。
