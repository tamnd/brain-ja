 ## 解決策
 ## 問題の理解

 この問題は、文字列としてエンコードされた企業階層を表します。 各従業員には名前があり、その後にオプションでコロンと部下のカンマ区切りのリストが続き、ドットで終わります。 従業員に部下がいない場合、コロンは省略されます。 複数の従業員が同じ名前を持つことができます。 入力文字列は、最上位レベルのすべての従業員をカンマで区切って表します。 本質的に、これはカスタム シリアル化でエンコードされたルート付きツリーのフォレストです。 

このタスクは、ある人が同じ名前の部下にメッセージを送信できるときに発生する「不快な状況」をカウントすることです。 通信はすべての下位に許可されているため、直接の子に制限されず、サブツリー内の任意のノードに制限されます。 たとえば、MIKE が任意の深さに従属 MIKE を持っている場合、それはそのペアにとって 1 つの不快な状況としてカウントされます。 

入力長は最大 1000 文字です。 これは、従業員の総数が文字列のサイズと名前の長さによって制限されるため、構造を再帰的または反復的に快適に解析できることを意味します。 すべての祖先と子孫のペアを明示的に計算する総当り的なアプローチでは、従業員の数が 2 次になり、ここでは実現可能ですが理想的ではありません。 明らかではないエッジ ケースは、さまざまな深さで名前が繰り返されるツリー、または最上位の複数の独立したツリーです。 例えば、`A:A.,A.`最初の理由により、不快なペアが 1 つ生成されるはずです。`A`2番目に到達できる`A`部下として。 

もう 1 つのエッジ ケースは、同じ名前を持つ従業員が深くネストされている場合です。`X:X:X:X...`。 祖先からすべてのレベルにカウントを伝播できない単純なアプローチでは、これらのチェーン内の複数の不快なペアを見逃してしまう可能性があります。 

## アプローチ

 強引なアプローチは、各従業員のツリーを明示的に構築し、各従業員についてすべての子孫を走査し、同じ名前を持つ従業員の数をカウントすることです。 これは定義に直接従うため機能しますが、ツリーが深く、名前が頻繁に繰り返される場合は遅くなります。 あれば`n`従業員の場合、各ノードについてサブツリー内のすべてのノードを訪問する可能性があるため、最悪の場合の複雑さは O(n^2) です。 

最適なソリューションを得るために重要な洞察は、正確な子孫ノードを知る必要はなく、サブツリー内の各名前の出現数だけを知る必要があるということです。 これにより、ツリーを再帰的に処理できるようになります。 各ノードで、このノードをルートとするサブツリーに各名前が何回出現するかを示すカウンター (辞書のようなもの) を維持します。 ノードを訪問すると、そのノードが生成する不快な状況の数は、そのノード自体を除いた、そのサブツリー内のノード名の数と同じになります。 これにより、各ノードのサブツリーが 1 回だけ処理されるため、二次計算の可能性がある計算が線形計算に変換されます。 

入力形式は階層的であるため、再帰的走査は自然です。 各従業員を再帰的に解析し、すべての部下の名前の数を計算し、不快な状況を合計しながらカウントアップを伝播できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n) | 深度が大きくなると遅すぎる |
 | 最適 | O(n) | O(n) | 効率的で受け入れられる |

 ## アルゴリズムのチュートリアル

 1. 入力文字列をツリー構造に解析します。 コロンまたはドットまで名前を読み上げます。 コロンが表示された場合は、コンマで区切られた従属リストを再帰的に解析します。 ドットが現在の従業員の終わりを示したら、解析を停止します。 
2. 各ノードについて、名前をそのノードをルートとするサブツリー内の数にマッピングする辞書を再帰的に計算します。 このディクショナリには、すべての子孫ノードの数が含まれます。 
3. ノードの処理中に、そのノードの名前がサブツリー辞書に何回出現するかを確認します。 この数は、このノードが同じ名前を持つすべての子孫を表すため、このノードによって生成される不快な状況の数に等しくなります。 
4. 下位の辞書を現在のノードの辞書にマージします。 現在のノード名の数に 1 を加えます。 
5. すべてのノードから蓄積された不快な状況の総数を返します。 

機能する理由: このアルゴリズムは、各ノードで、サブツリー内のすべての名前の数が辞書に反映されるという不変条件を維持します。 その辞書内の現在のノード名の出現をカウントすると、そのノードが送信者として関与するすべての不快な状況が捕捉されます。 各ノードは 1 回だけ訪問され、辞書が効率的にマージされるため、すべての状況が 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def parse_employee(s, i):
    # Parse the name
    name_start = i
    while i < len(s) and s[i].isalpha():
        i += 1
    name = s[name_start:i]
    total_uncomfortable = 0
    counts = {}

    # Parse subordinates if present
    if i < len(s) and s[i] == ':':
        i += 1  # skip colon
        while True:
            sub_counts, sub_uncomfortable, i = parse_employee(s, i)
            total_uncomfortable += sub_uncomfortable
            # Merge subordinate counts
            for k, v in sub_counts.items():
                counts[k] = counts.get(k, 0) + v
            if i < len(s) and s[i] == ',':
                i += 1
            else:
                break

    # Increment current node's name
    total_uncomfortable += counts.get(name, 0)
    counts[name] = counts.get(name, 0) + 1

    i += 1  # skip dot
    return counts, total_uncomfortable, i

def main():
    s = input().strip()
    total_uncomfortable = 0
    i = 0
    while i < len(s):
        _, count, i = parse_employee(s, i)
        total_uncomfortable += count
        if i < len(s) and s[i] == ',':
            i += 1
    print(total_uncomfortable)

if __name__ == "__main__":
    main()
```の`parse_employee`この関数は解析とカウントの両方を処理します。 名前を読み取り、コロンが見つかった場合は再帰的に下位を処理し、辞書を使用してカウントを維持します。 現在のノードの名前を追加する前に不快なカウントを増やすと、子孫のみがカウントされるようになります。 メインループは、カンマで区切られた複数のトップレベルの従業員を処理します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 入力文字列の各文字は 1 回ずつアクセスされます。 辞書の結合には、文字列サイズによって制限される、サブツリー内の一意の名前の数のみが含まれます。 |
 | スペース | O(n) | 再帰スタックの深さはツリーの深さに比例し、辞書には一意の名前ごとにカウントが保存されます。 |
