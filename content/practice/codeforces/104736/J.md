 ## 解決策
 ## 問題の理解

 私たちに与えられた木は、$N$都市。 各都市は 1 から 2 までの整数で識別されます。$N$、そしてこの数字はその富のランクでもあり、指数が大きいほど裕福な都市を意味します。 道路は重み付けされていないツリーを形成するため、都市のすべてのペアは 1 つの単純なパスによって接続され、距離はそのパス上のエッジの数になります。 

開始都市ごとに$i$, ロブは強盗をした後、次に移動する都市を知りたいと考えています。 彼のルールは決定論的です。つまり、インデックスが厳密に大きいすべての都市の間で、$i$、木からの最小距離にあるものを選択します。$i$。 複数の都市が同じように近い場合、その中でインデックスが最も小さい都市を選択します。 そのような都市が存在しない場合、つまり$i = N$、彼は残ります。 

したがって、タスクはすべてのノードについて計算することです$i$、より大きいラベルを持つ最も近いノード$i$、ツリー内の最短パス距離の下で、距離が最初に辞書式タイブレークで、次にラベルが付けられます。 

制約$N \le 10^5$これよりも悪い解決策は存在しないことを意味します。$O(N \log N)$合格する可能性は低いです。 二次アプローチでは、ノードのすべてのペアを考慮する必要があります。これは次のとおりです。$10^{10}$最悪のケースのツリーでの操作は、実現可能性をはるかに超えています。 ノードごとの BFS または DFS でも遅すぎます。 

いくつかの微妙なケースが重要です。 

星形の木がその難しさを明確に示しています。 ノード 1 が他のすべてのノードに接続されている場合、ノード 2 の最も近い上位ノードは距離 1 にあるすべてのリーフであるため、それらの中で最小のラベルを選択する必要があります。 単純な「最初に見つかったものを選択する」BFS は、タイブレーク ルールを適用しないため失敗します。 

パス状のツリーもエッジ ケースです。 木が線なら$1 - 2 - 3 - \dots - N$、ノードの答え$i$いつもです$i+1$。 真の最短パスではなく、任意の走査順序に依存するソリューションは、距離を明示的にエンコードしない場合、ここで機能しません。 

主な問題点は、各ノードの応答が動的に定義されたノードのサブセット (より高いラベルを持つノード) に依存し、このサブセットがクエリごとに変化することです。 

## アプローチ

 固定ノードの直接メソッド$i$BFS を実行することは、$i$より大きいラベルを持つノードに遭遇すると停止します。$i$、最初のそのようなノードを距離によって追跡し、次にラベルによって追跡します。 BFS は距離の増加順にノードを探索するため、これは正しいです。 ただし、これをノードごとに個別に行うとコストがかかります$O(N(N+M))$に退化します。$O(N^2)$以来$M = N-1$。 の上$10^5$ノードではこれは不可能です。 

重要な構造的観察は、ノードの答えは次のとおりであるということです。$i$より大きいラベルを持つノードのみに依存します$i$。 ラベルの降順にノードを処理すると、ノードに到達したとき$i$、すべてのノード$i+1, i+2, \dots, N$すでに「アクティブ」になっています。 問題は次のようになります。各ノードについて$i$、動的に増加するアクティブ ノードのセットの中から、インデックスのタイブレークを使用して、ツリー距離が最も近いノードを見つけます。 

これは古典的な「ツリー内で動的に最も近い色のノード」の問題です。 このための標準ツールは重心分解です。 これにより、アクティブ化されたノードのセットを維持し、最短距離のクエリに応答できるようになります。$O(\log N)$重心祖先に沿った距離を事前計算することにより、操作あたりの時間を短縮します。 

ツリーを重心ツリーに分解します。 各重心について$c$からの距離を事前計算します。$c$そのコンポーネント内のすべてのノードに。 次に、ノードが$j$がアクティブになると、からのパス上のすべての重心を更新します。$j$距離に対応する候補値を挿入して重心ルートに$dist(c, j)$。 各重心について、距離の点で最適なアクティブ ノードと、同点の場合は最小のインデックスを知る必要があるだけです。 

ノードをクエリするとき$i$から重心ツリーを上っていきます。$i$、および各重心について$c$、組み合わせます$dist(i, c)$に保存されている最適なアクティブ ノードを使用して、$c$。 このようなすべての重心の最小値が正しい答えになります。 

これが機能するのは、2 つのノード間のすべての最短パスが、それらの距離分解を正確に捕捉する何らかの重心祖先を通過するためです。

 ## アルゴリズムのチュートリアル

 まず、ツリーの重心分解を構築します。 これにより、元の各ノードが重心祖先のチェーンに属する重心ツリーが得られます。 

また、重心ごとに事前計算も行います。$c$、からの距離$c$セントロイド分解のサブツリー内のすべてのノードに適用されます。 これは、分解中に DFS を使用して行われます。 

ここで、ラベルの降順でノードを処理します。 

1. すべての重心構造を空として初期化します。 各重心にはペアが保存されます$(best\_distance, best\_index)$、その重心に最も近いアクティブなノードを表します。 
2. のために$i = N$まで$1$、ノードを扱います$i$アクティブになるにつれて。 
3. ノードをアクティブ化するには$i$、重心パス上のすべての重心を横断します。 各重心について$c$、計算する$dist(c, i)$。 これが保存されているペアよりも優れている場合は、$c$、更新してください。 比較は辞書順に行われます。距離が小さい方が優先され、距離が等しい場合はインデックスが小さい方が優先されます。 
4. ノードの答えを計算するには$i$、重心パス上のすべての重心を再度横断します。 各重心について$c$、保存されている最良のアクティブ ノードを結合します。$c$、 言う$j$、値を含む回答候補に変換$dist(i, c) + dist(c, j)$。 
5. 最小の合計距離で候補者を追跡し、より短い距離で同点を破ります$j$。 
6. アクティブなノードを提供するセントロイドがない場合、答えは次のようになります。$i$自体。 

重要な詳細は、アクティベーションとクエリの両方が同じセントロイド チェーン上を歩くため、各ノードが$O(\log N)$更新と問い合わせ。 

### なぜ効果があるのか

 重心分解により、ノードの任意のペアに対して次のことが保証されます。$i, j$、重心が存在します$c$の重心パス上$i$最短経路距離になるように$dist(i, j)$次のように表現できます$dist(i, c) + dist(c, j)$どこ$c$は、それらのコンポーネントを分離する最も高い重心です。 すべての重心の祖先を評価するので、$i$、アクティブなノードへの最短パスの可能な分解をすべてカバーします。 したがって、すべての最短経路候補は少なくとも 1 つの重心を正確に通過するとみなされ、すべての重心にわたる最小値が正しいグローバル最小値を生成します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

N = int(input())
g = [[] for _ in range(N)]
for _ in range(N - 1):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    g[u].append(v)
    g[v].append(u)

# Centroid decomposition helpers
sub = [0] * N
blocked = [False] * N
cd_par = [-1] * N
dist = []  # dist[c][v] stored in dict form

centroids = []
cd_tree = []

def dfs_size(u, p):
    sub[u] = 1
    for v in g[u]:
        if v != p and not blocked[v]:
            dfs_size(v, u)
            sub[u] += sub[v]

def dfs_dist(c, u, p, d, cd_id):
    dist[cd_id][u] = d
    for v in g[u]:
        if v != p and not blocked[v]:
            dfs_dist(c, v, u, d + 1, cd_id)

def find_centroid(u, p, n):
    for v in g[u]:
        if v != p and not blocked[v]:
            if sub[v] > n // 2:
                return find_centroid(v, u, n)
    return u

def build(u, p):
    dfs_size(u, -1)
    c = find_centroid(u, -1, sub[u])
    cd_par[c] = p
    blocked[c] = True

    cd_id = len(cd_tree)
    cd_tree.append(c)
    dist.append({})

    dfs_dist(c, c, -1, 0, cd_id)

    for v in g[c]:
        if not blocked[v]:
            build(v, c)

build(0, -1)

# store best (distance, index) per centroid node
best_dist = [10**18] * len(cd_tree)
best_node = [10**18] * len(cd_tree)

# map node -> list of (centroid id, distance to centroid)
node_paths = [[] for _ in range(N)]

for cid, c in enumerate(cd_tree):
    for v in dist[cid]:
        node_paths[v].append((cid, dist[cid][v]))

def add_node(v):
    for cid, d in node_paths[v]:
        if d < best_dist[cid] or (d == best_dist[cid] and v < best_node[cid]):
            best_dist[cid] = d
            best_node[cid] = v

def query(v):
    ans_dist = 10**18
    ans_node = v
    for cid, d in node_paths[v]:
        if best_node[cid] == 10**18:
            continue
        cand_dist = d + best_dist[cid]
        cand_node = best_node[cid]
        if cand_dist < ans_dist or (cand_dist == ans_dist and cand_node < ans_node):
            ans_dist = cand_dist
            ans_node = cand_node
    return ans_node

res = [0] * N

for i in range(N - 1, -1, -1):
    res[i] = query(i)
    add_node(i)

print(*[x + 1 for x in res])
```重心分解により、各ノードが関連する重心までの距離を認識する階層が構築されます。 の`add_node`関数はノードをアクティブ化し、重心サマリーを更新します。 の`query`関数は、すべての重心分割を試して、最も到達可能なアクティブ ノードを再構築します。 

微妙な点は初期化です。アクティブなノードがない状態から開始するため、クエリはデフォルトでノード自体を返します。 もう 1 つはタイブレークです。これは、更新ごとに距離とノード インデックスの両方を比較することで一貫して処理されます。

 ## 特殊なケース

 単一ノード ツリーの場合、ノード 1 には上位のラベル付きノードがありません。 このアルゴリズムは、1 を処理する前にノードをアクティブにすることはありません。`best_node`構造体は空のままであり、クエリは仕様に一致する 1 自体を返します。 

線形チェーンでは、各ノードは次のノードを最も近い上位のノードとしてのみ認識します。 重心分解では引き続き正しい距離が保存されますが、すべてのクエリは距離において他のすべてのクエリよりも優れているため、一貫して隣接するノードに減ります。 アクティベーション順序により、処理時に次のことが保証されます。$i$、ノード$i+1$はすでにアクティブであり、他のどのノードよりも近くにあります。 

スターでは、多くのノードが中心までの距離が等しいため、タイブレークが決定的になります。 中心の重心構造には、距離 1 にある最小のアクティブ インデックスが格納されるため、クエリは等距離の候補の中でより低いラベルを正しく優先します。
