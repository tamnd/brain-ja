 ## 解決策
 ## 問題の理解

 交差点がノード、道路が正の長さのエッジである都市を表す重み付き無向グラフが与えられます。 出発交差点から$P$では、最短経路の距離を実際の移動距離とみなします。 特殊な交差点があります$G$、ここが本当の待ち合わせ場所ですが、ペドロを別の場所に行くように誤解させたいと考えています。 

ペドロは常に最短距離をたどります$P$私たちが彼に与えたどんな目的地にでも。 旅行中、彼は選択したルートの最短距離の合計の半分を移動した時点でちょうど疲れます。 偽の目的地を選びたい$X$2 つのことが同時に起こるように。 

まず、ペドロがどの最短経路をたどろうとも、$P$に$X$、彼は通過しなければなりません$G$。 これにより、次のことが保証されます$G$～からのあらゆる最短経路上にある$P$に$X$、そのうちの1つだけではありません。 

第二に、ペドロが最短距離の途中で疲れたとき。$P$に$X$、その中間点は正確に次の位置にある必要があります。$G$。 疲労は最短距離の合計の半分を移動した後に発生するため、これは$P$に$G$～からの距離のちょうど半分でなければなりません$P$に$X$。 

したがって、すべてのノードを探しています$X$からのすべての最短パスが$P$に$X$通り抜ける$G$、最短経路距離は次の条件を満たします。$$dist(P, X) = 2 \cdot dist(P, G).$$グラフには最大で次のものを含めることができます$10^5$したがって、候補ごとに最短パスを再計算したり、パスを列挙したりするソリューションは不可能です。 一定数の最短パス計算と線形または線形に近いフィルタリングが必要です。 

複数の最短パスが存在する場合、微妙な問題が発生します。 一本の最短経路を通っても$G$、十分ではありません。 回避する別の最短経路が存在する場合$G$そうするとペドロは通れないかもしれない$G$、条件を破ります。 

もう 1 つのエッジケースは次のような場合です$G$いくつかの最短経路上にありますが、すべてではありません。 これは、サイクルと等しい重みの代替を含むグラフでよく発生します。 このような場合、単純な「dist(P,G)+dist(G,X)=dist(P,X) かどうかを確認する」だけでは不十分です。 

たとえば、正方形について考えてみましょう。```
P - A - X
|   |   |
G - B - C
```すべてのエッジが等しくなります。 からの最短パスは複数あります。$P$に$X$、いくつかは通過します$G$そうでない人もいます。 たとえ距離が合っていても、$G$すべての最短パス上にあることは保証されていないため、$X$は無効です。 

## アプローチ

 強引なアイデアとしては、すべてのノードに対して、$X$、から最短パスを計算します。$P$に$X$、そして何らかの方法ですべての最短経路が通過するかどうかを確認します$G$、そして中点条件が成立するかどうか。 「すべてのパス」要件を無視して距離だけを計算したとしても、ノードごとに最短パスの計算を行うことは明らかに不可能です。$O(NM \log N)$、につながる$O(N^2 \log N)$最悪の場合。 

もう少し良い強引な方法は、ディクストラを一度実行することです。$P$、すべての距離を与える$distP$。 からのダイクストラも実行します。$G$、与える$distG$。 次に、チェックすることで中間点条件を強制できます。$distP[X] = 2 \cdot distP[G]$そして$distP[G] + distG[X] = distP[X]$。 これにより、少なくとも 1 つの最短パスが$P$に$X$通り抜ける$G$。 

ただし、これでもすべての最短パスが確実に通過するわけではありません。$G$。 欠けているアイデアは、$G$～からの最短経路では避けられない$P$に$X$。 これは、一時的に削除することでテストできます$G$グラフから距離を再計算します。$P$。 最短距離であれば、$X$厳密に増加する場合、すべての最短パスは使用する必要があります$G$、削除して以来$G$あらゆる最適ルートを破壊します。 

したがって、完全な解は 3 つのダイクストラ実行になります。$P$、 から$G$、そしてから$P$グラフでは$G$削除されました。 最終的な答えは、3 つの距離配列すべてを使用してノードをフィルター処理します。

 ## アルゴリズムのチュートリアル

 3 つの関連するシナリオで最短経路距離を計算し、それらを構造的制約と組み合わせます。 

1. からディクストラを実行します。$P$グラフ全体で計算する$distP[v]$。 これにより、開始点からすべてのノードまでの真の最短距離が得られます。 
2. からディクストラを実行します。$G$グラフ全体で計算する$distG[v]$。 これにより、中間点候補からの距離を測定できるようになります。$G$外側に。 
3. からディクストラを実行します。$P$繰り返しますが、変更されたグラフでは、ノードが$G$削除（またはブロックされたものとして処理）され、$distP^{\neg G}[v]$。 これにより、可能な限り最適な距離を捕らえます。$P$に$v$使わずに$G$。 
4. コンピューティング$d = distP[G]$。 有効なミーティングポイント$X$満たさなければなりません$distP[X] = 2d$、 なぜなら$G$最短経路のちょうど中間点になければなりません。 
5. 各ノードについて$X$、まず中点制約下でも到達可能かどうかを確認します。 もし$distP[X] \neq 2d$、すぐに破棄されます。 
6. 次のことを確認します。$G$～からの少なくとも 1 つの最短経路上にある$P$に$X$チェックすることで$distP[G] + distG[X] = distP[X]$。 これにより、有効な最短パス分解が保証されます。$G$。 
7. 次のことを確認します。$G$～からのあらゆる最短経路上にある$P$に$X$削除するかどうかを確認することで$G$最短経路を悪化させる：$distP^{\neg G}[X] > distP[X]$(または到達不能)。 最短経路がまだ存在する場合$G$、 それから$G$必須ではありませんし、$X$は無効です。 
8. これらの条件を満たすすべてのノードを収集し、昇順に出力します。 存在しない場合は出力`*`。 

### なぜ効果があるのか

 重み付きグラフ内の最短パスは、次の点をルートとする階層構造を形成します。$P$。 条件$distP[X] = distP[G] + distG[X]$それを保証します$G$少なくとも 1 つの最短経路上にあるということは、$X$経由で到達可能です$G$距離を伸ばさずに。 なしのグラフを使用した第 2 条件$G$代替の最短ルートがバイパスされないようにする$G$、強制的に$G$すべての最短経路に存在します。 中点の等価性により、次のことが強制されます。$G$距離的にはちょうど中間にあり、疲労点は正確に位置合わせされます。$G$。 

これらの制約を組み合わせることで、最短パス構造が完全に媒介されるノードが特定されます。$G$そしてその周りの距離が対称です。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline
INF = 10**30

def dijkstra(start, n, adj, banned=None):
    dist = [INF] * (n + 1)
    dist[start] = 0
    pq = [(0, start)]

    while pq:
        d, u = heapq.heappop(pq)
        if d != dist[u]:
            continue
        if banned is not None and u == banned:
            continue

        for v, w in adj[u]:
            if banned is not None and v == banned:
                continue
            nd = d + w
            if nd < dist[v]:
                dist[v] = nd
                heapq.heappush(pq, (nd, v))

    return dist

def main():
    n, m = map(int, input().split())
    P, G = map(int, input().split())

    adj = [[] for _ in range(n + 1)]
    for _ in range(m):
        u, v, w = map(int, input().split())
        adj[u].append((v, w))
        adj[v].append((u, w))

    distP = dijkstra(P, n, adj)
    distG = dijkstra(G, n, adj)
    distP_woG = dijkstra(P, n, adj, banned=G)

    d = distP[G]
    ans = []

    for x in range(1, n + 1):
        if x == G:
            continue
        if distP[x] != 2 * d:
            continue
        if distP[G] + distG[x] != distP[x]:
            continue
        if distP_woG[x] <= distP[x]:
            continue
        ans.append(x)

    if not ans:
        print("*")
    else:
        print(*ans)

if __name__ == "__main__":
    main()
```実装はアルゴリズムに直接に従います。 最初のダイクストラ呼び出しでは、地球規模の距離のランドスケープが構築されます。$P$、両方のフィルタリング条件で再利用されます。 からの2回目の実行$G$最短パスが次のように分解できることを検証する場合にのみ必要です。$G$。 3 回目の実行では除外されます。$G$これは、「すべての最短経路が通過する」を変換する重要なメカニズムです。$G$」条件を単純な距離比較に組み込みます。 

よくある落とし穴は、ダイクストラからの先行関係のみを使用して必須ノードを検出しようとすることです。 これは、最短パス DAG が複数の同等の親を持つ可能性があり、ノードがすべてではなく一部の最短パス ツリーに表示される可能性があるため、失敗します。 削除中$G$パスの多重度に関する推論を明示的に回避します。

| X | 距離P[X] | 距離G[X] | distP_woG[X] | distP[G] + distG[X] | 有効 |

 ノード 4 はすべての条件を満たします。 1 から 4 まで、すべての最短パスは 3 を強制的に通過し、合計距離は 2 になるため、ペドロはちょうどノード 3 で疲れます。

 ## 特殊なケース

 主なエッジケースは次のような場合です$G$すべてではありませんが、いくつかの最短パス上にあります。 たとえば、1 つのサイクルでは、2 つの等しい長さのルートがバイパスできます。$G$。 グラフを使用しない条件$G$これを正確に捉えています。 このような入力では、$distP^{\neg G}[X] = distP[X]$、拒否反応を引き起こします。 

もう 1 つのケースは、複数の最短パスが存在するが、それらがすべて通過する場合です。$G$。 ここで、削除すると、$G$すべてのルートが切断または延長されるため、$distP^{\neg G}[X] > distP[X]$。 ダイクストラ単独からの最短パス ツリーが複数の親を示す場合でも、アルゴリズムはこれらのノードを正しく受け入れます。 

最後に、中点条件により対称性が保証されます。 正しい「スルー」を持つノード$G$構造はあるが距離が間違っている場合は直ちに除外され、構造的には有効でも計量的に間違っている候補による誤検知を防ぎます。
