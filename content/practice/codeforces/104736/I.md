 ## 問題の理解

 小文字で構成される基本文字列が与えられ、概念的にはこの基本文字列を何度も繰り返すことで、より長い文字列を構築します。 タスクは、繰り返される文字列内に出現する倒置の数を数えることです。倒置は位置のペアです。$i < j$の位置にある文字が$i$辞書編集上、その位置の文字より大きい$j$。 

繰り返される文字列は、繰り返し回数が非常に大きくなる可能性があります。$N$まで上がります$10^{12}$なので、明示的に構築することは不可能です。 中心的な課題は、完全な文字列を具体化することなく、構造化された反復連結における反転カウントを計算することです。 

基本文字列の入力サイズは最大です。$10^5$これは、文字列に対する二次アプローチが不可能であることをすでに示唆しています。 ナイーブ$O(|S|^2)$反転回数は単一コピーの場合のみ許容されますが、それを繰り返す場合$N$時代は私たちにシミュレーションではなく代数的に推論することを強いています。 

素朴な推論を打ち破る重要なエッジケースは、文字列に内部反転があり、境界を越えた反転が相互作用する場合です。 たとえば、文字列がすでにソートされている場合は、次のようにします。`"abc"`の場合、それを繰り返しても反転構造は変わらないというのが素朴な期待かもしれません。 実際には、クロスコピー反転が優勢です。 逆に、文字列が次のように逆になっている場合は、`"cba"`、すべての繰り返しが他のすべての繰り返しと最大限に相互作用し、コピー全体の貢献度が 2 次的に爆発的に増加します。 

もう 1 つの微妙なケースは、次のような均一な文字列です。`"aaaa"`。 ここでは反転はまったくなく、誤ってクロスコピーペアをカウントする式は、反転を生じない等価性を明示的に考慮していない場合、誤って寄与を導入してしまいます。 

## アプローチ

 ブルートフォース手法では、次のような長さの繰り返し文字列を明示的に構築します。$|S| \cdot N$フェンウィック ツリーまたはマージ ソートを使用して反転をカウントします。 これは単一の文字列に対して機能します$O(|S| \log |S|)$ですが、文字列を繰り返すと長さは最大になります。$10^{17}$、これは実行可能な計算やメモリをはるかに超えています。 完全に展開された文字列を 2 回通過することさえ不可能です。 

重要な観察は、繰り返される文字列の反転が 2 つの独立したソースから発生しているということです。 1 つ目は、各コピー内の反転です。$S$、すべてのブロックで同じように繰り返されます。 2 つ目は、次の異なるコピー間の反転です。$S$、これは、あるコピー内の文字が別のコピーの文字よりも大きい文字の数と、順序付けられたコピーのペアが何組存在するかによってのみ決まります。 

1 つのコピー内では、反転カウントは固定されており、1 回だけ計算できます。 複数のコピーにわたって、異なる繰り返しの 2 つの位置を考慮します。 コピーを取ったら$a$コピーする前に$b$のすべての文字$a$内のすべての小さな文字で反転を形成します。$b$。 この構造により、クロスコピーのカウントが、位置ではなく頻度の比較に基づいた組み合わせ係数に削減されます。 

したがって、アルファベット全体の文字頻度と接頭辞の合計を事前計算して、文字列内に厳密に小さい文字がいくつ存在するかを文字ごとに決定します。 これにより、あるコピーが別のコピーに対して単一方向に寄与した相互反転の数が得られます。 あるので$\frac{N(N-1)}{2}$順序付けられたコピーのペアの場合、この寄与は二次関数的にスケールされます。$N$。 

最終的な構造は 3 つの部分の合計です: によってスケールされたコピー内の反転$N$、異なるコピー間の反転をスケールしたもの$\frac{N(N-1)}{2}$、およびすべての計算されたモジュロ$10^9+7$。

 ## アルゴリズムのチュートリアル

 1. 文字に対する標準の反転カウント方法を使用して、ベース文字列内の反転をカウントします。 

これにより、反復効果のない単一ブロックの寄与が得られます。 
2. 文字列内の各文字の頻度を計算します。 

これにより、文字列構造が 26 個の値に圧縮されます。順序付けはアルファベットのランクのみに依存するため、これで十分です。 
3. 文字ごとに厳密に小さい文字の数をすぐに判断できるように、文字の頻度に関するプレフィックスの合計を構築します。 

このステップにより、文字間の順序付けに関する定数時間の推論が可能になります。 
4. 文字列の 2 つの異なるコピー間で発生した反転の数を計算します。 

キャラクターの場合$c$、それぞれの出現は、後のコピーですべての厳密に小さい文字の反転に寄与します。 
5. コピー内反転カウントを次のように乗算します。$N$なぜなら、各コピーは独立して内部反転に寄与するからです。 
6. クロスコピーの寄与を乗算します。$\frac{N(N-1)}{2}$なぜなら、個別のコピーの順序付けられたペアはすべて均等に寄与するからです。 
7. 両方の寄与を合計し、剰余を取る$10^9+7$。 

プレフィックスの合計が使用される主な理由は、コピー間の直接的なペアごとの文字比較が引き続き行われるためです。$O(|S|^2)$単純に行う場合は、頻度によって集計すると、一定のアルファベット作業が軽減されます。 

### なぜ効果があるのか

 繰り返される文字列内のすべての反転は、両方のインデックスが同じコピーに存在するか、または異なるコピーに存在するかの 2 つのカテゴリのいずれかに正確に分類されます。 最初のカテゴリはコピー間で不変であるため、次のように線形にスケールされます。$N$。 2 番目のカテゴリは、コピー間の文字の相対的な順序にのみ依存し、コピーは同一であるため、順序付けされたコピーのすべてのペアが同じ量を寄与します。 この対称性により、コピー ペアの数を乗算すると、二重にカウントしたり省略したりすることなく、すべてのクロス インバージョンが正確に 1 回カウントされることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def count_inversions(arr):
    # Fenwick tree over 26 letters
    bit = [0] * 27

    def update(i):
        i += 1
        while i < 27:
            bit[i] += 1
            i += i & -i

    def query(i):
        s = 0
        i += 1
        while i > 0:
            s += bit[i]
            i -= i & -i
        return s

    inv = 0
    # we want number of greater elements to the left
    for x in reversed(arr):
        inv += query(x - 1)
        update(x)
    return inv

def solve():
    s = input().strip()
    n = int(input().strip())

    a = [ord(c) - 97 for c in s]
    k = len(a)

    inv_single = count_inversions(a)

    freq = [0] * 26
    for x in a:
        freq[x] += 1

    prefix = [0] * 26
    for i in range(26):
        prefix[i] = freq[i] + (prefix[i - 1] if i else 0)

    cross = 0
    for i in range(26):
        for j in range(i):
            cross += freq[i] * freq[j]

    cross %= MOD

    inv_within = (inv_single * n) % MOD

    pairs = (n * (n - 1) // 2) % MOD
    inv_cross = (cross * pairs) % MOD

    print((inv_within + inv_cross) % MOD)

if __name__ == "__main__":
    solve()
```単一コピー内の反転カウントは、26 文字のアルファベット上のフェンウィック ツリーを使用して実装されます。 これにより、各位置の右側に表示される小さな文字の数を正確にカウントできるようになります。 

頻度ベースのクロスタームは、満たす文字のペアの数を計算します。$c_i > c_j$、ポジションに依存しません。 その後、その値はコピー ペアの数によって調整されます。$\frac{N(N-1)}{2}$なぜなら、以前のすべてのコピーはその後のすべてのコピーに同様に寄与するからです。 

モジュラー演算には注意が必要です。次のような中間値。$N(N-1)/2$概念的には標準の整数範囲をオーバーフローする可能性がありますが、Python は大きな整数を安全に処理します。 最終結果は縮小剰余です$10^9+7$。

 ## 特殊なケース

 のような文字列の場合`"aaaa"`大きい$N$の場合、単一コピーの反転数とすべての周波数間比較の両方がゼロであるため、アルゴリズムはゼロ反転を計算します。 周波数配列にはゼロ以外のエントリが 1 つだけあるため、クロス項は完全に消えます。 

次のような厳密に減少する文字列の場合`"dcba"`そして$N = 2$、アルゴリズムは最初に計算します$6$コピーごとの反転数。 2部で内部貢献額は$12$。 相互貢献は、コピー全体の文字のすべてのペアをカウントし、追加の貢献度を生成します。$\frac{4 \cdot 3}{2} = 6$コピー ペアごとに、コピーの 1 ペアごとにスケーリングし、さらに 6 を追加します。 最終結果は$18$これは、明示的に構築することなく完全に展開された構造と一致します。
