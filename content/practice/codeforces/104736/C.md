 ## 解決策
 ## 問題の理解

 私たちには一連のキャンディーが与えられ、それぞれにブランド ID が付けられています。 このラインの連続するセグメントを 1 つ選択し、そのセグメント内のすべてのキャンディーを購入することができます。 

K ファミリーのメンバーは正確に存在し、各メンバーはちょうど 1 つのブランドのキャンディーを受け取らなければなりません。 ブランドを 2 人のメンバー間で共有することはできず、各メンバーは同じ数のキャンディーを受け取る必要があります。 これは、セグメントを購入した後、そのセグメント内のキャンディーを家族メンバーごとに 1 つずつ K 個のグループに分割できなければならないことを意味します。各グループには 1 つのブランドのみが含まれ、すべてのグループのサイズは同じになります。 

配列用語で言い換えると、正確に K 個の個別の値を選択でき、それらの値がすべてサブ配列内で同じ回数出現するサブ配列を探しています。 その共通周波数が f の場合、サブ配列の長さは K・f であり、サブ配列内のすべての要素は、それらの K 個の選択された値に属している必要があります。 

タスクは、そのような部分配列の長さを最大化することです。 

この制約により、最大 4·10^5 個のキャンディーが許可されます。 N で 2 次の解は、最悪の場合、10^10 のオーダーで実行されるため、すぐに失敗します。 N log N アプローチでも受け入れられますが、それは厳密なリニア スキャンまたは効率的なウィンドウ メンテナンスを維持する場合に限られます。 この構造は、スライディング ウィンドウまたはツーポインター戦略を強く示唆しています。 

条件を満たすことがまったく不可能な場合には、微妙なエッジケースが発生します。 たとえば、K = 4 であるが、配列にグローバルに 3 つの異なるブランドしか含まれていない場合、どのサブ配列にも同じ頻度で 4 つの異なるブランドを含めることはできないため、答えはゼロでなければなりません。 

別の失敗例は、サブ配列に K 個の異なるブランドが含まれているが、それらの頻度が 1 回でも異なる場合に発生します。 たとえば、K = 2 および部分配列`[1, 1, 2]`にはカウント 2 と 1 があり、両方のブランドが存在するにもかかわらず平等に違反します。 

## アプローチ

 ブルートフォース戦略は簡単です。すべてのサブ配列を列挙し、その中の各ブランドの頻度を計算し、正確に K 個のブランドが表示され、それらすべてのカウントが同じかどうかを確認します。 サブアレイごとに周波数マップを維持すると、開始位置ごとに O(N) の作業が発生し、合計時間は O(N^2) になります。 N が 4・10^5 までの場合、これは非常に遅くなります。 

重要な観察は、実際にはブランドのアイデンティティは気にしておらず、ウィンドウ内の周波数の構造だけを気にしているということです。 有効なウィンドウは、存在するすべての周波数が等しく、正確に K 個の異なる値が存在するという事実によって完全に特徴付けられます。 

これは、各周波数が現在いくつの値を持っているかを追跡しながら、周波数カウントのスライディング ウィンドウを維持することを示唆しています。 いずれかの時点で、すべての K 個の異なる要素が同じ周波数 f を共有する場合、ウィンドウは有効であり、その長さは K・f です。 

難しいのは、ウィンドウを拡大または縮小すると、周波数が動的に変化することです。 等しいことを最初からチェックする代わりに、周波数値を現在その周波数を持つ要素の数にマッピングする二次構造を維持します。 ウィンドウは、この 2 次マップのサイズが 1 で、カウントが K に等しい場合にのみ有効です。 

これにより、ステップごとに O(1) で償却された更新による動的ウィンドウを維持するという問題が軽減されます。

 ## アルゴリズムのチュートリアル

 引き違い窓を維持しております`[l, r]`、辞書`freq`各ブランドのカウントと辞書を格納`freq_count`現在、指定された周波数を持つブランドがいくつあるかを保存します。 

1.初期化`l = 0`、`freq = empty`、`freq_count = empty`、 そして`answer = 0`。 
2. ウィンドウの右端を一度に 1 要素ずつ展開します。 位置にある新しいキャンディーごとに`r`、頻度を更新します`freq`。 以前の周波数が a だった場合、デクリメントします`freq_count[a]`、新しい周波数が b になった場合、インクリメントします。`freq_count[b]`。 

これにより、`freq_count`最初から再計算しなくても、現在のウィンドウと一貫性が保たれます。 
3. 展開するたびに、ウィンドウが制約に違反する可能性があります。 ウィンドウが無効な間、左から縮小していきます。 ウィンドウは、正確に K 個の異なるブランドを含み、それらすべてが同じ周波数を共有する場合にのみ有効です。 に関しては`freq_count`、これは、周波数値が 1 つだけ含まれている必要があり、その値がちょうど K 回出現する必要があることを意味します。 
4.縮めるときは取り除く`s[l]`ウィンドウから、その周波数を更新します`freq`、調整します`freq_count`同様に。 次に増加します`l`。 

ブランドの頻度に一貫性がなくなると、最初に矛盾する構造を除去しなければ、将来の拡張だけでは均一性を回復できないため、縮小が必要です。 
5. 有効性を復元した後、ウィンドウの長さを計算し、答えを更新します。 
6. 右ポインタが最後に到達するまで続けます。 

### なぜ効果があるのか

 すべてのステップで、ウィンドウは次で終わる最小のプレフィックスになります。`r`潜在的に制約を満たす可能性があります。 のメンテナンス`freq_count`周波数均一性が崩れたときに違反が即座に検出されるようにします。 すべての有効なウィンドウは、展開後に有効になった時点で正確に考慮されるため、`r`、候補がスキップされることはありません。 スライディング ウィンドウの不変条件は次のとおりです。`freq_count`は、現在のウィンドウの頻度分布を常に正確に表すため、妥当性チェックはヒューリスティックではなく正確です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    freq = {}
    freq_count = {}
    
    l = 0
    ans = 0

    def add(x):
        old = freq.get(x, 0)
        if old > 0:
            freq_count[old] -= 1
            if freq_count[old] == 0:
                del freq_count[old]

        freq[x] = old + 1
        new = old + 1
        freq_count[new] = freq_count.get(new, 0) + 1

    def remove(x):
        old = freq[x]
        freq_count[old] -= 1
        if freq_count[old] == 0:
            del freq_count[old]

        if old == 1:
            del freq[x]
        else:
            freq[x] = old - 1
            freq_count[old - 1] = freq_count.get(old - 1, 0) + 1

    for r in range(n):
        add(a[r])

        while True:
            if len(freq) != k:
                break
            if len(freq_count) != 1:
                remove(a[l])
                l += 1
                continue

            f = next(iter(freq_count))
            if freq_count[f] != k:
                remove(a[l])
                l += 1
                continue

            break

        if len(freq) == k and len(freq_count) == 1:
            f = next(iter(freq_count))
            ans = max(ans, k * f)

    print(ans)

if __name__ == "__main__":
    solve()
```コードは 2 つの同期されたハッシュ マップを維持します。`freq`ウィンドウ内のブランドごとの数を追跡します。`freq_count`各周波数を共有するブランドの数を追跡します。 内側のループは、ウィンドウが個別カウント条件または等頻度条件のいずれかに違反した場合にのみ縮小します。 

よくある落とし穴は、カウントがゼロになったときに周波数エントリを削除し忘れることです。これにより、無効な状態が誤って保存されてしまいます。`freq_count`。 もう 1 つの微妙な点は、更新が現在の正しいエンドポイントに完全に適用された後にのみ有効性がチェックされることです。

 ## 特殊なケース

 のような最小限のケース`K = 1`すべてのセグメントは 1 つのブランド全体で同じ頻度を持つことが自明であるため、単一要素ウィンドウに対して常に有効です。 アルゴリズムはこれを自然に処理します。`freq_count`になる`{f:1}`、これは有効性条件を直ちに満たします。 

配列に含まれる個別の値がグローバルに K 個未満の場合、すべてのウィンドウが失敗します。`len(freq) == K`そのため、縮小やチェックを行っても有効な状態を生成することはできません。 答えは正しくゼロのままです。 

有効な構成が存在するが、配列の最後にしか存在しない場合、次のような場合です。`1 1 2 2`、スライディング ウィンドウは、両方の周波数が一致するまで徐々に拡大し、その場合にのみ有効性条件がトリガーされ、後から発生する解決策が見逃されないことが保証されます。
