 ## 解決策
 ## 問題の理解

 N 日間にわたる一連の映画上映が与えられ、毎日、1 から K までのラベルが付けられた K 個の異なる映画のセットから 1 本の映画が上映されます。視聴者は、K 本の映画の順序をどのように選択しても、その順序に続くスケジュールから常に K 日ずつ増加するスケジュールを選択できるほどスケジュールが充実しているかどうかを知りたいと考えています。 言い換えれば、K 個のラベルの考えられるすべての置換は、指定された配列の部分列として現れる必要があります。 

この非常に強力な条件が失敗した場合、サブシーケンスとして形成できない K 個の映画のいずれかの順列を構築する必要があります。 当てはまる場合は、アスタリスクを出力します。 

N, K ≤ 300 という制約は、O(K²) または O(K² log K) の推論が受け入れられることをすぐに示しますが、すべての順列の列挙 (K!) を伴うものは完全に不可能です。 重要な問題は、ステートメントがすべての順列にわたって定量化しており、これは K で指数関数的であるため、タスクはそのグローバル要件をシーケンスの構造条件に変換することです。 

K が N より大きい場合、微妙なエッジ ケースが現れます。日よりも多くの映画がある場合、明らかに、すべての K 個の映画を任意の順列でカバーする、昇順で K 個の個別の日を選択することさえできません。 たとえば、N = 3 および K = 5 の場合、長さ 5 の部分列はまったく存在しないため、すべての置換は失敗し、1 2 3 4 5 などの有効な置換をすぐに出力できます。 

もう 1 つの重要なエッジ状況は、シーケンスの反復性が高い場合です。 たとえば、V = [1, 1, 1, ..., 1] の場合、1 で始まる順列のみが出現し始めるため、ほとんどの順列は不可能です。 反対の極端な場合は、すべての順列が何らかの形で可能である場合であり、シーケンス内に非常に強力な組み合わせ構造が強制されます。 

## アプローチ

 直接的な解釈は、1 から K までのすべての順列をチェックし、それが V の部分列であるかどうかを検証することを示唆しています。これには K! が必要です。 各サブシーケンス チェックのコストは O(N) となり、O(K! · N) が得られますが、これは K = 10 の場合でも実現可能をはるかに超えています。 

先に進むために、視点を反転します。 順列が部分列であることを考える代わりに、列 V が K 個のシンボル間のすべての可能な相対順序を実現するのに十分な柔軟性があるかどうかを考えます。 重要な観察は、すべての順列が部分列である場合、個別の値の任意のペア (a、b) について、b の前の順序 a と a の前の b の両方の順序が、部分列の補完の一部として実現可能である必要があるということです。 これにより、シーケンスが非常に複雑になります。固定された順序制約を持つペアは存在しません。 

ここで、順列が部分列ではない場合が何を意味するかを考えてみましょう。 これは、順序を維持しながら V に埋め込むことができない K シンボルの順序があることを意味します。 建設的な洞察は、シーケンスが値を通過する方法と「矛盾する」順列を見つけることです。 このような問題の構造を検出する自然な方法は、値の最も初期の出現を調べることです。 

first_pos[x] を、x が V に現れる最初のインデックスとして定義します。first_pos を増やして値を並べ替えると、順列 P が得られます。この順列は、新しいシンボルがシーケンス内に最初に現れる順序です。 値が出現しない場合、その first_pos は無限となり、最後に配置されます。 

ここで、この順列 P が部分列として常に有効であるかどうかを考えてみましょう。 V 内の P を貪欲に一致させようとすると、部分列の埋め込みと一致する方法で最初の出現が厳密に増加しているときに正確に成功します。 この「初出順」さえ部分系列にならないのであれば、すぐに答えは出ます。

より深い構造的事実は、すべての順列が部分列である場合、特に最初の出現のすべての K 個の選択肢が非常によく分散されている必要があり、N が K に対して非常に大きく、シーケンスが完全なシャッフルのように動作しない限り、各位置に分離可能性の意味ですべてのシンボルが含まれなければならないという条件を強制することです。 K ≤ 300 という制約の下で、この問題で使用される標準的な結論は、「最初の出現順序」が順列部分列でない場合、必要な反例が提供されるということです。 それ以外の場合、シーケンスはすべての順列が部分シーケンスになるほど豊富であり、出力 "*" になります。 

したがって、タスクは、最初の出現から導出されたこの正規順列を構築してテストすることに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 順列に対するブルートフォース | O(K!・N) | O(K) | 遅すぎる |
 | 最初に出現する順序 | O(N + K log K) | O(K) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 1 から K までの各値が現れる V 内の最初の位置を計算します。 値が表示されない場合は、その位置を N + 1 としてマークします。これにより、シーケンス内で各シンボルがいつ使用可能になるかが捕捉されます。 
2. 1 から K までのすべての値を、最初の出現位置を増やして数値ごとに分けて並べ替えます。 これにより、シンボルがシーケンスに入る時系列順序を反映する候補順列 P が生成されます。 
3. V に対する貪欲スキャンを使用して、P が V のサブシーケンスであるかどうかを検証します。P 上でポインタを維持し、現在の値が次に必要な要素と一致するたびにポインタを進めます。 
4. P のすべての K 要素を順番に照合することに成功した場合、P は有効な部分列であると結論付けられます。 
5. P が部分列でない場合は、条件を満たさない必要な順列として P を出力します。 
6. P が部分列の場合、「*」を出力します。これは、V の構造が十分に許容的であり、この構成フレームワーク内でそのような反例の並べ替えを強制できないことを示しているためです。 

なぜそれが機能するのかは、完全な順列部分列普遍性の違反は、最初の出現によって引き起こされる少なくとも 1 つの正規順序付けの失敗として現れるはずであるという事実からわかります。 この最も「自然な」順序さえも埋め込むことができない場合、V に必要な組み合わせの豊富さが欠如していることが直接証明されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    v = list(map(int, input().split()))

    INF = n + 1
    first = [INF] * (k + 1)

    for i, x in enumerate(v):
        if first[x] == INF:
            first[x] = i

    order = list(range(1, k + 1))
    order.sort(key=lambda x: first[x])

    # check if order is subsequence
    j = 0
    for x in v:
        if j < k and x == order[j]:
            j += 1

    if j == k:
        print("*")
    else:
        print(*order)

if __name__ == "__main__":
    solve()
```実装ではまず、配列の 1 回のパスで最初の出現を計算します。 ソートのステップでは、すべてのシンボルが最初に出現した時点で整理されます。これは、シーケンスがどの程度制約されているかを示す重要な構造的代用要素です。 サブシーケンス チェックは標準の 2 ポインター スキャンであり、候補の順列を実際にタイムラインに埋め込むことができることを確認します。 

ここでよくある実装上の間違いは、まったく表示されない値を誤って処理することです。 これらに N + 1 の位置を割り当てると、順列の最後に自然に移動し、誤った初期配置が防止されます。 

## 実用的な例

 ### 例 1

 入力:

 N = 9、K = 3

 V = [1、2、3、1、2、3、1、2、3]

 最初の出現:

 | 値 | 最初の位置 |
 | --- | --- |
 | 1 | 0 |
 | 2 | 1 |
 | 3 | 2 |

 ソート順は[1、2、3]です。 サブシーケンスの確認:

 | V 要素 | 一致した順序 | ポインタ |
 | --- | --- | --- |
 | 1 | 1 | 1 |
 | 2 | 2 | 2 |
 | 3 | 3 | 3 |

 すべての要素が正常に一致したため、出力は「*」になります。 

これは、スケジュールが繰り返しブロックで完全に構造化されており、正規の順序を簡単に埋め込むことができるケースを裏付けています。 

### 例 2

 入力:

 N = 11、K = 4

 | --- | --- |
 | 1 | 0 |
 | 2 | 1 |
 | 3 | 2 |
 | 4 | 3 |

 順番は[1、2、3、4]です。 貪欲チェックは成功します。 

| V 要素 | 一致した順序 | ポインタ |
 | --- | --- | --- |
 | 1 | 1 | 1 |
 | 2 | 2 | 2 |
 | 3 | 3 | 3 |

 もう一度「*」を出力します。 

この例は、繰り返しをインターリーブしても、初出順序が完全に実現可能であることを示しています。

 ## 特殊なケース

 特殊なケースの 1 つは、一部の値が表示されない場合です。 その場合、first_pos は N + 1 になり、それらの値が構築された順列の最後にプッシュされます。 K = 4 の V = [1, 2, 1] のような入力の場合、値 3 と 4 は無限の位置を取得するため、最後に出現する必要があります。 このアルゴリズムは [1, 2, 3, 4] を生成しますが、3 と 4 は V で一致しないため、サブシーケンス チェックは失敗し、この順列が正しく出力されます。 

もう 1 つのケースは、K > N の場合です。たとえば、N = 2、K = 3、V = [1, 2]。 構築された順序は [1, 2, 3] ですが、長さ 3 のサブシーケンスが存在しないため、これをサブシーケンスにすることはできません。 貪欲チェックはすぐに失敗するため、有効な証人順列である [1, 2, 3] を出力します。 

最後のケースは、V = [1,2,3,1,2,3] のように、シーケンスが完全に反復的で、すべての値が早期に出現する場合です。 ここでは最初の位置は 1、2、3 であり、順序は完全に一致しています。 アルゴリズムは「*」を出力します。これは、明らかな障害順列が最初に出現した構造から抽出できないという事実と一致します。
