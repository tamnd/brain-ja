 ## 解決策
 ## 問題の理解

 私たちには一定の本の順序が与えられており、それぞれの本には読書時間と、それを読み終えなければならない最新の許容日が設定されています。 読む順序は柔軟ではありません。本は最初から最後まで指定された順序で読まれます。 各本は 1 日以内に完了する必要があり、1 日に複数の本が連続して含まれる場合があります。 

このタスクは、順序を維持しながら、各本 i を di までのいずれかの日に割り当てる必要があることを考慮して、各本を 1 から m までの日に割り当てることです。 本が割り当てられると、毎日、割り当てられた本の ti の合計に等しい作業負荷がかかります。 すべての有効な割り当ての中で、1 日の最大作業負荷を最小限に抑えたいと考えています。 このような最適なスケジュールを見つけたら、可能な限り最小限の最大作業負荷と、毎日その日に割り当てられた最後の書籍、またはその日が空の場合は 0 の両方を出力する必要があります。 

制約はブックと日の両方で最大 3 · 10^5 になるため、すべてのパーティションを試行したり、日と位置にわたって動的プログラミングを実行したりするソリューションは失敗します。 ソリューションには、通常、答えに対する二分探索と貪欲な実現可能性チェックを伴う、ほぼ線形または線形演算の動作が必要です。 

微妙な問題は、期限が分割と相互作用することです。 シーケンスを制限付き合計のチャンクに分割するだけでは十分ではありません。 たとえチャンクが現在の作業負荷制限内に収まっていても、遅延により書籍の締め切りが過ぎてしまう場合は違法となる可能性があります。 

1 つの特殊なケースは、1 冊の本の ti がテストされた 1 日の制限を超える場合に現れます。 たとえば、本に必要な時間が 10 であるのに、制限 7 をテストする場合、締め切りに関係なく割り当てはできません。 もう 1 つの問題となるケースは、締め切りにより早期の分割が強制される場合です。 本の di 値が小さい場合、合計のみを尊重する単純な貪欲な考えでは、後の容量が存在する場合でも、本を割り当てるのが遅すぎる可能性があります。 

## アプローチ

 強引なアイデアは、これを m 日にわたる分割問題として扱い、シーケンスを m 個のセグメントに分割するあらゆる方法を試し、各セグメントが期限を守っているかどうかを確認し、その最大合計を計算することです。 すべての有効なスケジュールがシーケンスのセグメント化に対応するため、これは正しいです。 ただし、このようなセグメンテーションの数は n と m の組み合わせで増加し、m 個のカットに制限した場合でも、$\binom{n}{m}$実現可能な計算をはるかに超えた可能性があります。 

重要な構造的観察は、私たちが 1 日ごとに任意の割り当てを選択しているのではなく、固定されたシーケンスの単調なセグメントを構築しているということです。 候補となる 1 日の最大作業負荷 S を固定すると、書籍を順番に処理して、可能な限り早い有効な日ブロックを形成できるかどうかを貪欲にチェックできます。 問題の単調な性質は、S が小さすぎる場合は失敗し、S が十分に大きい場合は成功することを意味します。したがって、実現可能性は単調であり、二分探索が可能です。 

貪欲な実現可能性チェックが機能するのは、書籍を順番に割り当てる必要がある場合、1 日以内に書籍を遅らせても、将来の制約が難しくなるだけだからです。 したがって、容量 S に違反しない範囲で毎日をできるだけ埋める必要があり、必要な場合にのみ新しい 1 日を開始します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースパーティショニング | 指数 | お(1) | 遅すぎる |
 | 二分探索 + 貪欲チェック | O(n log A) | O(n) | 承認済み |

 ここで、A はすべての ti 値の合計であり、これが答えの境界となります。 

## アルゴリズムのチュートリアル

 1 日あたりの合計時間 S を超えず、締め切りに違反することなく、注文された m 日に書籍を割り当てることができる最小値 S を検索します。 

1. 最大の単一 ti とすべての ti の合計の間で S を二分探索します。 S を超える書籍を収容できる日はないため、下限が必要です。上限は、制約緩和ごとにすべてを 1 日に配置することで常に実現可能です。 
2. 固定 S の場合、左から右へ本の割り当てをシミュレートします。 現在の日のインデックスとその日の現在の累積時間を維持します。 
3. 本 i を考慮する場合、ti が S を超えている場合、すぐに S は無効であると結論付けます。 これは、有効な割り当てがこの本をどこにも配置できないためです。 
4. 本 i を現在の日に追加しても S を超えず、かつ di を超えていないという制約に違反しない場合は、それを現在の日に割り当てます。 
5. 本 i を追加すると S を超える場合は、当日を終了して次の日に移動する必要があります。 そうする前に、この本の販売が許可されている最終日を過ぎていないことを確認します。 そうしないと、有効な場所がありません。 
6. 一日を終えた後、新しい一日を開始し、そこに本を割り当てます。 新しい日のインデックスが di を超えるかどうかを再度確認します。これにより、S が無効になります。 
7. すべての書籍の処理を m 日以内に完了できれば、S は実現可能です。 
8. 二分探索によって実行可能な最小の S が見つかった後、欲張りシミュレーションをもう一度実行し、それに割り当てられた最後の書籍インデックスを毎日記録します。 

重要な微妙な点は、貪欲な人は常に可能な限り早い終了点を数日間作成するということです。 これは重要です。なぜなら、本を 1 日以内に遅らせるような代替割り当ては、将来の柔軟性を低下させるだけであり、向上させることは決してないからです。 

正確さは不変式に左右されます。つまり、最初の i 冊の書籍を処理した後、貪欲な手順では、期限を守りながら、S に基づくすべての有効な割り当ての中で可能な最小限の日数が使用されます。 何らかの割り当てが存在する場合、この貪欲さはそれを超えることはありません。これは、容量または実現可能性によって強制された場合にのみ新しい日が開かれるためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def check(S, n, m, t, d):
    day = 1
    used = 1
    cur = 0

    for i in range(n):
        if t[i] > S:
            return False

        if cur + t[i] <= S:
            cur += t[i]
        else:
            day += 1
            if day > m:
                return False
            cur = t[i]

        if day > d[i]:
            return False

    return True

def build(S, n, m, t, d):
    day = 1
    cur = 0
    last = [0] * (m + 1)

    for i in range(n):
        if cur + t[i] <= S:
            cur += t[i]
        else:
            last[day] = i
            day += 1
            cur = t[i]

        last[day] = i

    return last

def solve():
    n, m = map(int, input().split())
    t = []
    d = []
    for _ in range(n):
        ti, di = map(int, input().split())
        t.append(ti)
        d.append(di)

    lo = max(t)
    hi = sum(t)

    while lo < hi:
        mid = (lo + hi) // 2
        if check(mid, n, m, t, d):
            hi = mid
        else:
            lo = mid + 1

    ans = lo
    last = build(ans, n, m, t, d)

    print(ans)
    for i in range(1, m + 1):
        print(last[i] if i <= m else 0)

if __name__ == "__main__":
    solve()
```ソリューションは、実現可能性チェッカーと再構築フェーズに分かれています。 チェッカーは、1 日あたりの容量と期限の両方の制約を強制します。 再構築では同じグリーディ パッキング ロジックを使用し、選択された最適な S との一貫性を確保します。 

実装の微妙な詳細は、再構築はチェックと同じ決定構造を反映する必要があるということです。 そうしないと、値 S が正しい場合でも、結果のパーティションが有効な最適解に対応しない可能性があります。

 ## 特殊なケース

 書籍の ti が 1 日あたりの実行可能な制限よりも大きい場合、重大なエッジケースが発生します。 この状況では、ti より下のすべての候補 S は直ちに不合格になる必要があります。 アルゴリズムは、割り当てが行われる前に実現可能性チェックでこれを検出し、無駄なシミュレーションを防ぎます。 

di が非常に小さい場合、たとえばすべての i に対して di = i など、別のエッジ ケースが発生します。 これにより、各本はその位置までに配置されることになり、実質的に 1 日あたり 1 冊に近い行動が必要になります。 貪欲な人は、容量が不十分な場合には自然に新しい日を早めに開き、実行可能条件 day > di により無効な割り当ての漏洩を防ぎます。 

3 番目のケースは、m が n より大きい場合です。 ここでは、未使用のままの日数が多く、再構築では末尾のゼロを正しく出力する必要があります。 貪欲では必要な場合にのみ日数を進めるため、未使用の日数は変更されず、出力配列ではデフォルトでゼロになります。
