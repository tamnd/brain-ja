 ## 解決策
 ## 問題の理解

 それぞれに小文字が含まれるセルの行が与えられます。 トークンは最初のセルから始まり、決定的なルールに従って繰り返し移動します。 現在の位置から、行全体に同じ文字を含む他のセルが少なくとも 1 つ存在する場合、トークンはそれらのセルの 1 つにジャンプします。 それ以外の場合は、1 ステップ右に移動します。 プロセスは、トークンが最後のセルを通過したときにのみ停止します。 

問題は、ランダム性をシミュレートすることではなく、プロセスを永久に継続する方法が存在するかどうかを判断することです。つまり、トークンは、繰り返される文字によって作成されるサイクルに閉じ込められ続けるため、最後の位置を超えて到達することはありません。 

入力サイズは最大 100,000 文字に達するため、多くのステップで段階的に遷移を調査するシミュレーションは除外されます。 検出されずに状態を繰り返し再訪できるアプローチでは、ランタイムが指数関数的または無限になる危険があります。 正しい解決策は、プロセスを文字列の構造特性に還元する必要があります。 

繰り返される文字が順方向インデックスを介してサイクルを形成する場合、微妙な失敗のケースが発生します。 たとえば、`aaa`、位置 1 から 2 に進み、2 から 3 に進み、3 から 1 に戻ることができ、最後まで到達できないループが作成されます。 前方へのみの単純な直観は、「その他の出来事」によって後方へのジャンプが可能であることを見落とすでしょう。 

別のエッジケースは次のような文字列です`abca`。 たとえ文字が繰り返されても、その構造は必ずしも出口をブロックするサイクルを作成するわけではありません。なぜなら、運動は最終的に前方トラップサイクルが存在しない位置に到達する可能性があるからです。 

## アプローチ

 ブルートフォース解釈では、各ポジションを状態として扱い、遷移ルールを繰り返し適用します。 指定されたインデックス i から、出現する s[i] をすべて調べ、そのうちの 1 つを選択して、そこに移動します。 それ以外の場合は、i + 1 に進みます。これにより、位置に関する有向グラフが自然に定義されます。 考えられるすべてのパスをシミュレートすることも、状態 1 から状態 n + 1 までの到達可能性分析を実行することもできます。 

問題は、各ノードが他の多くのノードへの発信エッジを持つ可能性があり、それらのエッジがサイクルを作成する可能性があることです。 各文字グループはその出現の間で密な接続を引き起こすため、到達可能な状態の完全な探索は最悪の場合指数関数的になります。 

重要な観察は、ランダム性は無関係であるということです。 重要なのは、強制遷移の誘導有向グラフにサイクルが存在するかどうかだけです。 あるインデックスから、その左側にある同じ文字を持つ別のインデックスに到達できる場合は、その文字クラスの出現を循環することができ、右の境界に進むことはありません。 

これにより、問題は、移動が同じ文字クラス内で後方に戻ることができるように、位置 i < j < k に少なくとも 2 回出現する文字が存在するかどうかを検出することに限定されます。 実際、構造はさらに単純化されます。任意の文字が少なくとも 2 回出現する場合、その文字の最初の出現からプロセスは後の出現にジャンプすることができ、そこから唯一可能な反復ジャンプによって同じインデックスのセット内に留まり、確実なエスケープが防止されます。 

したがって、問題は文字列に繰り返し文字が含まれているかどうかをチェックすることに帰着します。 すべての文字が 1 回だけ出現する場合、トークンは後方にジャンプしたりループしたりすることはできないため、厳密に右に移動して最終的に終了します。 いずれかの文字が繰り返される場合、到達可能なサイクルが存在します。

 ## アルゴリズムのチュートリアル

 1. 文字列を読み取り、左から右にスキャンしながら各文字の頻度を計算します。 このステップでは、文字によって複数の宛先が考えられるかどうかをキャプチャします。 
2. いずれかの文字が複数回出現した場合は、プロセスがサイクルに閉じ込められる可能性があると直ちに結論付け、NO を出力します。 その理由は、文字が繰り返されると、インデックスを厳密に増加させることからトークンをリダイレクトする可能性がある別の動きが導入されるためです。 
3. すべての文字が異なる場合は、逆方向または横方向のループは不可能であると結論付けられます。そのため、すべてのステップは、厳密に一意の未訪問の位置に移動するか、配列から出て、保証された終了につながります。 

### なぜ効果があるのか

 このプロセスでは、ポジションにその文字が再度出現する場合にのみ、非順方向動作が作成されます。 この状態は、重複文字が存在することと同じです。 重複が存在すると、システムには、等しい文字によって誘導されるインデックス上に強く接続されたコンポーネントが少なくとも 1 つ含まれ、再訪問が可能になり、保証されたエスケープが防止されます。 重複が存在しない場合、すべての位置には正確に一方向の前進があり、代替遷移はなく、終了まで厳密に増加するパスが強制されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

s = input().strip()
cnt = [0] * 26

for ch in s:
    cnt[ord(ch) - 97] += 1

for x in cnt:
    if x > 1:
        print("NO")
        break
else:
    print("YES")
```このソリューションでは、26 個の小文字にわたる固定サイズの周波数配列が維持されます。アルファベットは固定されているため、これで十分です。 各文字は一定時間でカウンターをインクリメントします。 

最後のループでは、文字が繰り返されているかどうかをチェックします。 の`else`ループ上の句により、印刷のみが保証されます。`YES`繰り返しが見つからなかった場合。 これにより、余分な状態の追跡が回避され、ロジックが線形でクリーンな状態に保たれます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    s = input().strip()
    cnt = [0] * 26
    for ch in s:
        cnt[ord(ch) - 97] += 1

    for x in cnt:
        if x > 1:
            return "NO"
    return "YES"

# provided samples
assert run("abc\n") == "YES"
assert run("aaa\n") == "NO"

# custom cases
assert run("a\n") == "YES"
assert run("abac\n") == "NO"
assert run("abcdefghijklmnopqrstuvwxyz\n") == "YES"
assert run("zzzzzz\n") == "NO"
```| テスト入力 | 期待される出力 | 検証内容 |

 ## 特殊なケース

 次のような単一文字列の場合`a`の場合、アルゴリズムはそれを 1 回カウントし、重複が見つからないため、YES を出力します。 このプロセスは簡単に 1 回右に移動し、すぐに終了します。 

のような文字列の場合`abac`、キャラクター`a`が複数回出現します。 周波数配列は重複をマークし、NO をトリガーします。 これは、同じ文字を持つ複数のポジションの存在と一致し、以前のインデックスを再参照して、遷移グラフにサイクルを形成することが可能になります。
