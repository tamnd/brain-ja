 ## 解決策
 ## 問題の理解

 私たちに与えられた長方形の庭園は、$n$行と$m$列。 各セルには、そこに生えている花の種類を表す整数が含まれています。 私たちは庭を 2 回観察します。1 回目は変化のプロセスの前、もう 1 回は変化のプロセス後です。 

仮説は、変換が非常に構造化された方法で動作するということです。 すべての花のタイプは、結果として得られる 1 つのタイプに正確にマッピングされ、このマッピングはグリッド全体で一貫しています。 つまり、2 つのセルが以前に同じ値を持っていた場合、その後も同じ値になる必要があります。 逆に、2 つのセルが以前に異なる値を持っていた場合、それらは同じになることも、異なるままであることも許可されますが、重要な制約は、変換が古い値から新しい値への明確に定義された関数であることです。 

したがって、タスクは関数が存在するかどうかを確認することです$f$すべての細胞に対して$(i, j)$、後の値は次と等しくなります$f(\text{before}[i][j])$、そしてこの関数は、同じ以前の値が出現するすべてにわたって一貫しています。 

制約$n, m \le 1000$までを暗示$10^6$グリッドごとのセル。 セルのすべてのペアを比較したり、ペアごとの整合性チェックを明示的に構築しようとしたりするソリューションは、セルの数が 2 次である場合には遅すぎます。 グリッド上の線形スキャンが必要になることが予想されます。 

同じ初期値が異なる場所にある 2 つの異なる出力にマップされる場合、微妙な失敗のケースが発生します。 たとえば、最初のグリッドの 2 つのセルに値 5 が表示されているが、ある場所では 1 になり、別の場所では 2 になる場合、仮説は直ちに違反します。 もう 1 つの失敗ケースは、ステートメントで必要のない単射性または全単射性を誤って仮定した場合です。 ソース値ごとの一貫性のみが重要です。 

## アプローチ

 この問題を考える強引な方法は、マッピング ルールを明示的に強制することです。 初期グリッドの値ごとに、それが最終グリッドにマップされる値のセットを格納できます。 すべてのセルを反復処理すると、この構造が更新されます。 最終的に、すべてのキーは 1 つの一意の値に正確にマップされる必要があります。 このアプローチは、各セルが 1 回処理されるため、すでに最適に近づいていますが、単純な実装では、値ごとにネストされたチェックや繰り返しスキャンが使用される可能性があり、$O((nm)^2)$実装が不十分な場合、最悪の場合の動作。 

重要な観察は、グリッド構造は対応するセルのペア以外には無関係であるということです。 空間的推論は決して必要ありません。 ペアの一貫性を確保することだけが必要です$(a_{ij}, b_{ij})$。 したがって、問題全体は、観察されたサンプルに基づいて、整数から整数への関数が適切に定義されているかどうかをチェックすることに帰着します。 

したがって、各元の値を割り当てられた変換された値にマッピングする辞書を維持します。 ペアに遭遇したとき、マッピングが新しい場合はそれを保存します。 すでに存在する場合は、整合性が検証されます。 矛盾があれば、仮説は即座に無効になります。

 | ブルート フォース (値ごとの再チェック) |$O((nm)^2)$|$O(nm)$| 遅すぎる |
 | マッピングの整合性チェック |$O(nm)$|$O(k)$、$k \le nm$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 両方のグリッドをセルごとに並行して読み取り、各位置がペアに寄与するようにします。$(x, y)$前後の値を表します。 このペアは、問題の中で唯一意味のある構造です。 
2. 辞書を管理する`mp`元の値から変換された値への必要なマッピングを記録します。 重要な考え方は、元の値は常に同じ結果にマッピングされる必要があるということです。 
3. 各セルペアについて$(x, y)$、どうかを確認してください`x`すでに存在しています`mp`。 
4. もし`x`存在しません。割り当てます`mp[x] = y`。 これにより、この値の最初の出現時に基づいて、この値の変換ルールが修正されます。 
5. もし`x`がすでに存在する場合は、それを確認してください`mp[x] == y`。 そうでない場合は、単一の入力値が複数の出力を生成するため、仮説は偽であると直ちに結論付けます。 
6. すべてのペアがこの整合性チェックに合格した場合、「YES」を出力します。 それ以外の場合は「NO」を出力します。 

### なぜ効果があるのか

 このアルゴリズムは、セルのプレフィックスを処理した後、次の不変条件を維持します。`mp`は、観測されたすべてのペアと一致する部分関数を記述します。 矛盾が現れた場合、それは関数の定義の違反に直接対応します。 逆に、矛盾が現れない場合、すべての入力値には、その出現全体にわたって出力値が 1 つだけ割り当てられており、これがまさに必要な条件となります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    
    before = []
    for _ in range(n):
        before.append(list(map(int, input().split())))
    
    after = []
    for _ in range(n):
        after.append(list(map(int, input().split())))
    
    mp = {}
    
    for i in range(n):
        for j in range(m):
            x = before[i][j]
            y = after[i][j]
            
            if x in mp:
                if mp[x] != y:
                    print("NO")
                    return
            else:
                mp[x] = y
    
    print("YES")

if __name__ == "__main__":
    solve()
```コードはまず両方の行列を完全に読み取り、次に位置合わせされた位置を反復処理します。 辞書`mp`元の花の種類ごとに最初に検出されたマッピングを保存します。 その後の遭遇では、一貫性を強制します。 矛盾を早期に解消することは、条件が崩れた場合に不必要なスキャンを避けることができるため重要です。

 ## 特殊なケース

 エッジ ケースの 1 つは、値が何度も出現するが、一致しないのは 1 つだけである場合です。 たとえば、値 10 が 1000 個のセルに表示され、そのうちの 1 つだけが異なるマッピングをしている場合、辞書検索は定数時間であり頻度に依存しないため、アルゴリズムはその競合するペアが処理されるとすぐにそれを捕捉します。 

もう 1 つのケースは、値が大きい場合です (最大$10^5$）、しかしまばらに分布しています。 辞書はインデックス位置ではなく実際に観測された値によってキー設定されるため、引き続き機能します。そのため、メモリ使用量はグリッド サイズではなく個別の値に依存します。 

最後の微妙なケースは、同じ出力値が異なる入力によって生成される場合です。 たとえば、1→5 と 2→5 は完全に有効です。 このアルゴリズムでは、キーごとの一貫性のみを強制するのではなく、注入性を決して強制しないため、これが自然に可能になります。
