 ## 解決策
 ## 問題の理解

 エッジが明確な整数色を持つ有向グラフがあります。 (S) から開始して、任意の外向きエッジをトラバースすることができ、頂点とエッジを再訪することができます。 唯一の要件は、歩行が最終的に (T) に到達することです。 長さが最大 ​​(10^{100}) であるこのようなすべてのウォークの中で、辞書編集的に最小のエッジ カラーのシーケンスが必要です。 

辞書編集上の順序により、最初の決定がその後のすべての決定よりもはるかに重要になります。 1 つの有効なウォークが色 (3) で始まり、別のウォークが色 (7) で始まる場合、後で何が起こったかに関係なく、最初のウォークが勝ちます。 2 つのウォークが同じプレフィックスを持つ場合、それらが異なる最初の位置を比較します。 短いシーケンスは、長いシーケンスのプレフィックスと正確に一致する場合にも優先されます。 

グラフには、(100,000) 個の頂点と (300,000) 個のエッジを含めることができます。 元の問題の 2 秒の制限により、(O(NM)) または (O(N^2)) のアプローチはすでにコストが高すぎます。 基本的に線形または (O((N+M)\log N)) の作業が必要です。 巨大な (10^{100}) 境界により、可能な最大歩行長に依存するアルゴリズムは除外されます。 幸いなことに、答え自体ははるかに単純な構造になっています。 

不注意で貪欲な実装を行うと失敗するケースがいくつかあります。 1 つ目は、宛先が最終的に (T) に到達できるかどうかを確認せずに、最小の出向きエッジを取得することです。 例えば、```
3 2 1 3
1 2 1
1 3 5
```正しい答えは、`5`。 頂点 (2) は行き止まりであるため、色 (1) を選択すると有効な歩行を生成できません。 最小の色だけを調べる貪欲なアルゴリズムでは、その色が誤って選択されてしまいます。 

2 番目のケースはサイクルです。 考慮する```
3 4 1 3
1 2 1
2 1 2
2 3 7
1 3 5
```正しい出力は次のとおりです`TOO LONG`。 頂点 (1) から見ると、色 (5) よりも色 (1) の方が優先されます。 頂点 (2) から見ると、色 (7) よりも色 (2) の方が好ましいです。 こうして貪欲な選択が繰り返し生み出すのは、```
1, 2, 1, 2, 1, 2, ...
```ウォークは最終的にサイクルを出て (T) に到達する可能性がありますが、その終了を別のサイクルだけ遅らせると、シーケンスが辞書編集的に小さくなります。 許容される最大長は天文学的に長いため、結果として得られる最適なシーケンスは (10^6) よりもはるかに長くなります。 

3 番目のケースは単に到達不能です (T)。 例えば、```
2 0 2 1
```はまったく歩いていないので、答えは次のとおりです。`IMPOSSIBLE`。 

## アプローチ

 直接的な総当たりでは、(S) からのすべての可能なウォークを列挙し、(T) に到達するものを許容長内に保ち、それらのカラー シーケンスを比較します。 これは、すべての候補を明示的に考慮するため、正しいです。 問題は候補者の数だ。 グラフには 2 つの意味のある選択肢が繰り返し存在し、最大 (L) の長さの異なるウォークを (\Theta(2^{L/2})) 個生成できます。 実際にすべてのシーケンスを実体化すると、その作業は (\Theta(L2^{L/2})) になります。 (L=10^{100}) の場合、これは単に遅すぎるだけでなく、基本的に不可能です。 

有益な観察は、辞書編集順により、どの頂点がまだ到達できるか (T) がわかったら、次のエッジを独立して決定できるということです。 現在頂点 (u) にいるとします。 到達できない頂点 (T) につながる出力エッジは、そのエッジを使用するすべてのウォークが無効であるため、無関係です。 残りのすべてのエッジの中で、最小の色を選択する必要があります。 最初の異なる色がすでに辞書編集上の比較を決定しているため、より大きな色を選択した場合、より良い接尾語を付けることで修復することはできません。 

これにより、すべての有用な頂点に対して決定的な貪欲な遷移が得られます。 まず、反転したグラフのトラバーサルを使用して、(T) に到達できるすべての頂点にマークを付けます。 次に、有用な頂点 (u) ごとに、その宛先も有用な最小色の出力エッジを選択します。 

次に、(S) から始まる選択したエッジをたどります。 可能性は 2 つだけです。 最終的には (T) に到達します。この場合、収集した配列が答えになります。 それ以外の場合、頂点は (N) 個しかないため、いくつかの頂点が繰り返され、選択された遷移がサイクルを形成します。 

なぜサイクルが意味するのか`TOO LONG`単に「貪欲なアルゴリズムが行き詰まった」だけではなく？ そのサイクル上のすべての頂点で、選択されたエッジは他のすべての有用な出力エッジよりも厳密に小さい色を持ちます。 色は世界的にユニークなので、ネクタイはありません。 ある時点でサイクルを離れる場合は、選択したサイクルのエッジを厳密に大きな色で置き換える必要があります。 サイクルの別の走査によってその置換を遅らせると、シーケンスが辞書編集的に小さくなります。 このサイクルを膨大な回数繰り返しても、(10^{100}) 個の長さ制限内にとどまることができます。 したがって、辞書編集上の最小有界ウォークは非常に長くなり、確かに (10^6) よりも長くなります。 

色が一意であるという事実は、2 つの異なる出力エッジが同じ色を持つ可能性を排除するため、ここでは役に立ちます。 同じ貪欲な構造をタイを使用して定式化することもできますが、同じ最初の色の中から最適なサフィックスを選択するには追加の注意が必要です。 

結果として得られるメソッドは、オプションの並べ替えを除けば線形です。 すべての隣接リストを 1 回スキャンし、その最小限の有用なエッジを記憶することで、ソートを完全に回避できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 分岐グラフ内の (\Theta(L2^{L/2})) | 指数 | 遅すぎる |
 | 最適 | (O(N+M)) | (O(N+M)) | 承認済み |

 同じ貪欲な特徴付けは、この問題に対する独立して公開された解決策の議論でも示されています。 

## アルゴリズムのチュートリアル

 1. 元のグラフとその反転グラフの両方を作成します。 元のグラフはエッジを選択するために必要ですが、反転したグラフを使用すると、どの頂点が最終的​​に到達できるか (T) を判断できます。 
2. 反転したグラフの (T) から始まるグラフ トラバーサルを実行します。 この走査で到達したすべての頂点を次のようにマークします。`good`。 頂点とは、`good`まさに、その頂点から (T) への有向歩行が存在するときです。 

このフィルタリングは不可欠です。 非常に小さな色のエッジは、(T) が到達できない領域につながっている場合、有効な候補ではありません。 
3. (S) がそうでない場合`good`、印刷`IMPOSSIBLE`。 (S) から (T) への有効なウォークがないため、出力するカラー シーケンスはありません。 
4. すべての頂点 (u) について、その出ていくエッジを検査し、目的地が最小の色のエッジを見つけます。`good`。 目的地と色を保存します。 

毎`good`(T) 以外の頂点には少なくとも 1 つのそのようなエッジがあります。これは、定義により (T) へのパスがあるためです。 
5. (S) から開始し、`visited`配列を参照し、保存された最小有効エッジを繰り返したどります。 目的地に移動する前に、その色を回答に追加します。 

の`visited`配列は、決定論的な貪欲ウォークがサイクルに入ったケースを正確に検出します。 繰り返しを検出するためだけにシーケンス全体を保存する必要はありません。 
6. 現在の頂点が (T) になった場合、収集されたすべての色を印刷します。 頂点が繰り返されていないため、ウォークには最大で (N-1) 個のエッジが含まれます。 特に、その長さは自動的に (10^6) を下回ります。 
7. (T) に到達する前に頂点に 2 回目に遭遇した場合は、次のように出力します。`TOO LONG`。 

繰り返されるすべての頂点で、貪欲なエッジは、(T) につながる可能性のあるすべてのエッジの中で可能な限り最小の色を持ちます。 サイクルを終了する有限のウォークでは、最終的には貪欲なエッジではなく、より大きな色を選択する必要があります。 このサイクルを繰り返すと、その大きな色が延期され、結果として得られるシーケンスが辞書編集的に小さくなります。 許可される最大長は (10^6) よりもはるかに大きい (10^{100}) であるため、必要な答えを出力できません。 

### なぜ効果があるのか

 現在の頂点 (u) を考えてみましょう。 すべての有効な継続は、宛先が (T) に到達できるエッジを取る必要があります。 正確にそれらのエッジの中で、最小の色のエッジは、辞書編集上の最小順序で出現する必要があります。 別の有効なウォークがこの位置でより大きな色を選択した場合、そのシーケンスは、サフィックスに関係なく、すでに大きくなっています。 したがって、最初の貪欲な選択が強制され、同じ引数が後のすべての頂点に再帰的に適用されます。 

貪欲なプロセスが頂点を繰り返さずに (T) に到達した場合、選択されたすべてのエッジがこの引数によって強制されるため、生成されたシーケンスは辞書編集的に最小の有効なシーケンスになります。 

プロセスが頂点を繰り返す場合、その点からの確定的な遷移によってサイクルが形成されます。 すべてのサイクル頂点で、選択されたエッジは、最終的に (T) に到達する可能性のある他のすべてのエッジよりも小さくなります。 最終的にサイクルから離れる有効なウォークは、最初の出口位置でより大きなエッジを選択する必要があります。 その出口を出る前にもう 1 つのサイクルを完了するウォークは、その時点までは同じプレフィックスを持ち、その後はサイクルの色が小さくなるため、辞書順に小さくなります。 この引数を繰り返すと、最適な有界ウォークでは、終了する前に利用可能な最大反復回数が使用されることがわかります。 境界 (10^{100}) はその長さを (10^6) よりもはるかに大きくします。`TOO LONG`は正しい出力です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, s, t = map(int, input().split())

    graph = [[] for _ in range(n)]
    rev = [[] for _ in range(n)]

    for _ in range(m):
        u, v, c = map(int, input().split())
        u -= 1
        v -= 1
        graph[u].append((v, c))
        rev[v].append(u)

    # Find all vertices that can reach T.
    good = [False] * n
    good[t] = True

    stack = [t]
    while stack:
        u = stack.pop()
        for v in rev[u]:
            if not good[v]:
                good[v] = True
                stack.append(v)

    if not good[s]:
        print("IMPOSSIBLE")
        return

    # For every useful vertex, remember its minimum-color
    # outgoing edge whose destination is also useful.
    next_vertex = [-1] * n
    next_color = [0] * n

    for u in range(n):
        best_color = None
        best_vertex = -1

        for v, c in graph[u]:
            if not good[v]:
                continue
            if best_color is None or c < best_color:
                best_color = c
                best_vertex = v

        if best_vertex != -1:
            next_vertex[u] = best_vertex
            next_color[u] = best_color

    # Follow the deterministic greedy transitions.
    visited = [False] * n
    answer = []

    u = s

    while u != t:
        if visited[u]:
            print("TOO LONG")
            return

        visited[u] = True

        v = next_vertex[u]

        # This should not happen because u is good and u != T.
        if v == -1:
            print("IMPOSSIBLE")
            return

        answer.append(next_color[u])
        u = v

    print(*answer)

if __name__ == "__main__":
    solve()
```最初のグラフ構築では、各エッジを順方向グラフに格納し、その前のエッジのみを逆方向グラフに格納します。 したがって、逆グラフの (T) から開始すると、(T) が到達可能な頂点を正確に訪問します。 

の`good`テストは貪欲な選択の前に行われます。 これは、アルゴリズムが行き止まりにつながる小さな色を選択することを防ぐ主な正確性条件です。 

最小の有用な発信エッジは、各隣接リストの 1 回のスキャンによって検出されます。 エッジを並べ替える必要はありません。 このフェーズではすべてのエッジが 1 回だけ検査されるため、合計作業量は (O(M)) になります。 

最後の走査は決定的です。 一度`next_vertex[u]`が計算された場合、貪欲アルゴリズムが選択できるエッジは 1 つだけです (u)。`visited[u]`は次の頂点に移動する前に設定されるため、`visited[u]`後の反復では、サイクルが実際に完了したことを意味します。 (T) は反復頂点テストの前にチェックされるため、(T) に関してオフバイ 1 の問題は発生しません。 

Python の整数は、指定された色の制限 (10^9) を簡単に処理でき、アルゴリズムは (10^{100}) を伴う算術を実行しません。 膨大な歩行距離を表す必要はまったくありません。

### サンプル 2

 入力は```
3 4 1 3
1 2 1
2 1 2
2 3 7
1 3 5
```ここでもすべての頂点は (3) に到達できます。 (1) の最小有効エッジは色 (1) を持ち、(2) の最小有効エッジは色 (2) を持ちます。 

| 現在の頂点 | 良好な発信エッジ | 選択した色 | 次の頂点 | 以前に訪問しました |

import io
from contextlib import redirect_stdout

def solve(data=None):

        input = sys.stdin.readline
    else:
        input = io.StringIO(data).readline

    n, m, s, t = map(int, input().split())

    rev = [[] for _ in range(n)]

    good[t - 0] = True

        u = stack.pop()
        for v in rev[u]:
            if not good[v]:
                good[v] = True
                stack.append(v)

    if not good[s]:
        print("IMPOSSIBLE")
        return

    next_color = [0] * n

        best_color = None
        best_vertex = -1

                best_color = c

            next_color[u] = best_color

    answer = []
    u = s

    while u != t:
        if visited[u]:
            print("TOO LONG")
            return

        visited[u] = True
        v = next_vertex[u]

        if v == -1:
            print("IMPOSSIBLE")
            return

        u = v

    sys.stdin = io.StringIO(inp)
    out = io.StringIO()

    try:
        with redirect_stdout(out):
            solve()
    finally:
        sys.stdin = old_stdin

    return out.getvalue().strip()

## 特殊なケース

 最初のエッジ ケースは、より小さい色の行き止まりです。 考慮する```
3 2 1 3
1 2 1
1 3 5
```(3) からの逆走査では、頂点 (3) と頂点 (1) のみが有用であるとマークされます。 頂点 (2) は (2) から (3) へのパスがないためマークされません。 アルゴリズムが頂点 (1) をスキャンするとき、その宛先が役に立たないため、カラー (1) のエッジは無視され、カラー (5) が最小の有効な選択肢として残されます。 出力は`5`。 

2 番目のエッジ ケースは、到達不能なターゲットです。```
2 0 2 1
```逆走査は頂点 (1) から始まり、他には何も到達しません。 頂点 (2=S) は役に立たないため、アルゴリズムはすぐに出力します。`IMPOSSIBLE`。 

3 番目のエッジ ケースは、貪欲な選択を含むサイクルです。```
3 4 1 3
1 2 1
2 1 2
2 3 7
1 3 5
```(1) からの有効な最小エッジは色 (1)、(2) からの有効な最小エッジは色 (2) です。 したがって、貪欲シーケンスは (1\to2\to1) になります。 頂点 (1) が 2 回目に検出されると、アルゴリズムは次のように出力します。`TOO LONG`。 このサイクルは、より大きな出口色 (5) を取得する前に繰り返すことができるため、辞書編集的に優先される有界ウォークは非常に長いものになります。 

4 番目のエッジ ケースは、グリーディ ウォークがサイクルなしで (T) に到達するグラフです。```
3 3 1 3
1 2 1
2 3 7
1 3 5
```アルゴリズムは頂点 (1) から色 (1) を選択し、次に頂点 (2) から色 (7) を選択し、(3) に到達します。 頂点の繰り返しはありません。 (N) 個の頂点を通過する単純なウォークスルーには最大で (N-1) 個のエッジが含まれるため、結果のシーケンスは自動的に (10^6) 出力しきい値を下回ります。 

最後の境界ケースは、テストで使用される最大サイズのチェーンです。 すべての頂点には出力エッジが 1 つだけあるため、貪欲な選択が強制されます。 このアルゴリズムは、(99,999) 個のエッジ上で 1 回の逆方向トラバーサルを実行し、同じエッジを 1 回スキャンしてから、(99,999) 個の遷移をたどります。 再帰を行わず、(10^{100}) ウォーク境界を表す必要もなく、シーケンス全体が生成されます。
