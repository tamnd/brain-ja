 ## 解決策
 ## 問題の理解

 2 つの順列 (A) と (B) から始めます。どちらも (1) から (N) までのすべての整数を 1 回だけ含みます。 (A) を再配置することもできますが、隣接する要素を交換することによってのみ可能です。 目標は、特定の最大の配置を構築することではありません。 元の (A) を、その値が次のような配置に変換する最小数の隣接スワップが必要です。 

[
 \sum_{i=1}^{N}|a_i-b_i|
 】

 できるだけ大きいです。 

隣接スワップによってあらゆる順列が生成される可能性があるため、実際の問題は、和を最大化するすべての順列を特徴付けてから、隣接スワップ距離で元の (A) に最も近い順列を見つけることです。 

境界 (N\le 250000) は、順列の列挙はもちろんのこと、(N) 内の二次関数をすべて除外します。 (O(N^2)) であっても、最大サイズでは約 (6.25\times10^{10}) 個の基本演算が必要となり、2 秒の制限をはるかに超えます。 本質的に線形時間、または最大でも (O(N\log N)) が必要です。 幸いなことに、(A) と (B) は正確に (1,\ldots,N) の順列であるため、それらの値からすでにランクがわかります。 実際には並べ替えは必要ありません。 

魅力的なソリューションが失敗する小さなケースがいくつかあります。 (N=3)、(A=[1,2,3])、(B=[1,2,3]) の場合、逆順列 ([3,2,1]) が最適ですが、3 つの隣接するスワップが必要です。 ([2,3,1]) と ([3,1,2]) も最適であるため、正解は (2) のみです。 逆順列が一意の最適であると仮定する解決策は、これを誤ります。 

(N=1)、(A=[1]) および (B=[1]) の場合、答えは (0) になります。 交換するものは何もなく、可能な唯一の配置はすでに最適化されています。 値の 2 つの半分を空ではないものとして盲目的に扱う実装では、このケースを個別に処理する必要があります。 

(N=2)、(A=[1,2])、(B=[1,2]) の場合、答えは (1) です。 唯一の最大化配列は ([2,1]) です。 これにより、偶数 (N) に対して不正な中間値ルールを使用する実装が捕捉されます。 

最後に、答えは (N) よりもはるかに大きくなる可能性があります。 (N=250000)、(A=B=[1,2,\ldots,N]) の場合、必要なスワップ数は (125000^2=15625000000) です。 この場合、32 ビット整数はオーバーフローします。 Python の整数には任意の精度があるため、実装には特別な整数型は必要ありません。 

(A) と (B) は順列であり、繰り返し値が含まれていないため、入力を有効に保ちながら、「すべて等しい値」テスト ケースの要求を文字通り満たすことはできません。 最も関連性の高いケースは (N=1) で、順列全体が単一の値 (1) で構成されます。 

## アプローチ

 ブルートフォース手法では、(1,\ldots,N) のすべての順列 (C) を列挙し、計算することができます。 

[
 \sum_i |c_i-b_i|,
 】

 最大値を維持し、すべてのマキシマイザーの中で、(A) からの隣接スワップが最も少ないものを選択します。 これは正しいです。なぜなら、隣接するスワップはすべての順列に到達する可能性があり、2 つの順列間の隣接するスワップの数はそれらの相対順序から計算できるからです。 問題は候補者の数だ。 (N!) 個の順列があり、それぞれを評価するには (N) 回の操作が必要で、(O(N\cdot N!)) 個の作業が必要になります。 (N=10) では、これはすでに約 3,600 万の値の比較であり、階乗増加により、このアプローチは実際の制限に対して役に立たなくなります。 

最初の有用な観察は、目的を書き直すことです。 以来

 [
 |x-y|=x+y-2\min(x,y),
 】

 私たちは持っています

 \sum_i c_i+\sum_i b_i-2\sum_i\min(c_i,b_i)。 
】

 どちらの順列にも (1,\ldots,N) が含まれるため、最初の 2 つの合計は固定されます。 元の式を最大化することは、最小化することとまったく同じです。 

[
 \sum_i\min(c_i,b_i)。 
】

 次に、各最小値をしきい値ごとに拡張します。 

[
 \min(x,y)=\sum_{t=1}^{N}[x\ge t\text{ and }y\get]。 
】

 固定しきい値 (t) の場合、正確に (N-t+1) 個の位置に (C) の少なくとも (t) の値が含まれ、まったく同じ数の位置が (b_i\ge t) を持ちます。 (N) 個の要素セットの 2 つのサブセットが両方とも (k) 個の要素を含む場合、それらの交差部分のサイズは少なくとも

 [
 \max(0,2k-N)。 
】

したがって、すべてのしきい値には (\sum_i\min(c_i,b_i)) への寄与の下限があります。 

重要な閾値は真ん中あたりです。 (N=2m)とします。 (C) の (m) 個の最大値、つまり (m+1,\ldots,2m) は、(B) 値が (m) 個の最小値の中に入る位置を占めていなければなりません。 そうしないと、2 セットの (m) 個の位置が重なり、しきい値の寄与が最小値よりも大きくなります。 

奇数 (N=2m+1) の同じ推論は、値 (m+2,\ldots,2m+1) は (1,\ldots,m) の中で (B) が存在する位置を占めなければならず、値 (1,\ldots,m) は (m+2,\ldots,2m+1) の中で (B) が存在する位置を占めなければならず、中央の値 (m+1) は中央の値とペアでなければならないことを示しています。 (B=m+1)。 

各グループ内での正確な順序は最大値には影響しません。 それが重要な簡素化です。 どの特定の大きな値がどの下位 (B) の位置に入るのかを決める必要はありません。 要素を正しいグループに移動するだけです。 

これにより、元の順列問題がカテゴリ文字列に関するはるかに単純な問題に変換されます。 偶数 (N) の場合、すべての値は下位半分または上位半分のいずれかに属します。 奇数 (N) の場合、ちょうど 1 つの値を含む追加の中間カテゴリが 1 つあります。 すべてのポジションのターゲット カテゴリは、その (B) 値によって直接決定されます。 

あるカテゴリのシーケンスを別のカテゴリに変換するために必要な隣接スワップの最小数は、各カテゴリの最初のオカレンスを最初のターゲット オカレンスと照合し、2 番目のオカレンスを 2 番目のターゲット オカレンスと照合することによって取得できます。 固定カテゴリの場合、同じカテゴリの 2 つの出現を交差させることは役に立たないため、それらを順番に一致させることが最適です。 現在の発生位置が (p_1,p_2,\ldots) で、ターゲット位置が (q_1,q_2,\ldots) である場合、全体の位置移動に対するそれらの寄与は次のようになります。 

[
 \sum_j |p_j-q_j|。 
】

 隣接するスワップごとに 2 つの要素が 1 位置ずつ移動するため、すべてのカテゴリの合計はすべてのスワップを 2 回カウントします。 したがって、答えは全体の位置移動の半分になります。 

したがって、最終的なアルゴリズムは線形になります。 (A) のすべての値を分類し、(B) の値に従ってすべての位置を分類し、カテゴリごとに出現位置を収集し、対応する出現を照合します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(N\cdot N!)) | (O(N)) | 遅すぎる |
 | 最適 | (O(N)) | (O(N)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. (m=\lffloor N/2\rfloor) とします。 (A) の値のカテゴリを定義します。 値 (1,\ldots,m) は低カテゴリに属し、値 (m+2,\ldots,N) は高カテゴリに属し、(N) が奇数の場合、値 (m+1) は中カテゴリに属します。 

この分類は、最適な順列で出現する可能性のある 3 つのグループを正確に捉えます。 
2. (B) の値に従って各位置を分類します。 (B_i\le m) の場合、最適な配置ではそこに高い (A) 値を設定する必要があります。 (B_i>m+1) の場合、そこに低い (A) 値を設定する必要があります。 奇数 (N) の場合、(B_i=m+1) を持つ一意の位置は中央の値を受け取る必要があります。 

偶数 (N) の場合、中間カテゴリがないため、条件は単に下半分と上半分を入れ替えます。 
3. (A) をスキャンし、各カテゴリが現在発生している位置を記録します。 また、(B) によって誘導されたターゲット カテゴリをスキャンし、各カテゴリが出現する必要がある位置を記録します。 

1 つのカテゴリ内の正確な値は重要ではありません。 このため、カテゴリのみを記録するだけで十分です。 
4. カテゴリごとに、現在のオカレンスとターゲットのオカレンスを左から右の順序でペアにします。 すべてのペアの位置間の絶対差を加算します。 

別の順序で出現が一致すると、2 つの等しいカテゴリ要素が強制的に交差します。 これらは目的に関して交換可能であるため、このような交差はスワップを追加するだけであり、結果を改善することはできません。 
5. 位置移動の合計を 2 で割って出力します。 

隣接する各スワップにより、1 つの要素が 1 位置左に移動し、別の要素が 1 位置右に移動します。 したがって、絶対位置変化の合計に正確に (2) 寄与します。 

### なぜ効果があるのか

しきい値引数は、すべての最大化順列がすべての位置で必要なカテゴリを正確に持っていることを証明します。 逆に、これらのカテゴリ要件を満たす順列はすべてのしきい値の下限に同時に到達するため、最大化されます。 カテゴリが固定されると、同じカテゴリに属する​​値は目的に対して交換可能になります。 2 つのカテゴリ シーケンス間の最小隣接スワップ変換は、同じカテゴリの出現を順番に照合することによって取得されます。 したがって、計算された位置の移動は最小スワップ数のちょうど 2 倍となり、アルゴリズムは必要な最小値を返します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    m = n // 2

    # Categories:
    # 0 = low values
    # 1 = middle value, only for odd n
    # 2 = high values
    #
    # Store positions of each category in the current A
    # and in the required target category sequence.
    cur = [[], [], []]
    target = [[], [], []]

    for i, x in enumerate(a):
        if x <= m:
            cur[0].append(i)
        elif n % 2 == 1 and x == m + 1:
            cur[1].append(i)
        else:
            cur[2].append(i)

    for i, x in enumerate(b):
        if x <= m:
            # Small B values need large A values.
            target[2].append(i)
        elif n % 2 == 1 and x == m + 1:
            # The middle value must meet the middle value.
            target[1].append(i)
        else:
            # Large B values need small A values.
            target[0].append(i)

    movement = 0

    for c in range(3):
        for p, q in zip(cur[c], target[c]):
            movement += abs(p - q)

    print(movement // 2)

if __name__ == "__main__":
    solve()
```最初のループでは、(A) の要素を数値で分類します。 偶数 (N) の場合、下位半分は (1,\ldots,N/2) ですが、より大きな値はすべて上位半分に属します。 奇数 (N) の場合、単一の値 ((N+1)/2) が独自のカテゴリを受け取ります。 

2 番目のループでは、同じ分類を反対方向から実行します。 小さい (B_i) には最適な配置で大きい (A) 値が必要ですが、大きい (B_i) には小さい (A) 値が必要です。 奇数 (N) の場合、中間位置は中間の値を受け取る必要があります。 

位置は 0 から始まるインデックスとして保存されます。 2 つの位置間の距離が、それらの間で要素を移動するために必要な隣接するスワップの数と正確に一致するため、これは便利です。 境界調整は必要ありません。 

の`zip`操作は、自然な左から右の順序で出現をペアにします。 (A) と (B) は両方とも順列であるため、両方のリストには同じ出現数が含まれます。 隣接する各スワップによって正確に 2 つの要素の位置が変更されるため、総移動量はすべてのカテゴリにわたって累積され、2 で除算されます。 

答えは (2^{31}-1) を超える可能性がありますが、Python の整数は必要に応じて自動的に拡張されます。 考えられる最大の答えは (N^2) 程度であり、Python の整数演算で簡単に処理できます。 

## 実用的な例

 ### サンプル 1

 入力は```
3
1 2 3
1 2 3
```ここでは (N=3) および (m=1) です。 値は (1) が低、(2) が中、(3) が高です。 

| ポジション | 値 | 現在のカテゴリー | B値 | 対象カテゴリ |
 | --- | --- | --- | --- | --- |
 | 0 | 1 | 低い | 1 | 高 |
 | 1 | 2 | 中央 | 2 | 中央 |
 | 2 | 3 | 高 | 3 | 低い |

 下位カテゴリは現在位置 (0) にありますが、位置 (2) に配置され、(2) に寄​​与する必要があります。 上位カテゴリは位置 (2) から位置 (0) に移動し、別の (2) に貢献します。 中カテゴリーは動かない。 

| カテゴリー | 現在のポジション | 目標位置 | 動き |
 | --- | --- | --- | --- |
 | 低い | [0] | [2] | 2 |
 | 中央 | [1] | [1] | 0 |
 | 高 | [2] | [0] | 2 |

これは、(A) を反転する必要がない理由を示しています。 ターゲットは ([2,3,1]) になる可能性があります。これは同じ最大目標を持ち、スワップを 2 回だけ必要とします。 

### サンプル 2

 入力は```
4
3 4 1 2
3 2 4 1
```ここで (N=4) と (m=2) になります。 値 (1、2) は低く、(3、4) は高くなります。 

| ポジション | 値 | 現在のカテゴリー | B値 | 対象カテゴリ |
 | --- | --- | --- | --- | --- |
 | 0 | 3 | 高 | 3 | 低い |
 | 1 | 4 | 高 | 2 | 高 |
 | 2 | 1 | 低い | 4 | 低い |
 | 3 | 2 | 低い | 1 | 高 |

 現在、高い値は位置 (0,1) を占めていますが、位置 (1,3) が必要です。 彼らの動きは、

 [
 |0-1|+|1-3|=3。 
】

 低い値は位置 (2,3) から位置 (0,2) に移動し、(3) にも寄与します。 

| カテゴリー | 現在のポジション | 目標位置 | 動き |
 | --- | --- | --- | --- |
 | 低い | [2、3] | [0, 2] | 3 |
 | 高 | [0, 1] | [1、3] | 3 |

 総移動量は (6) であるため、スワップの最小数は (6/2=3) となります。 

これは、最終的な高い値をターゲット位置で (3,4) にするか (4,3) にするかを決定する必要がない理由も示しています。 どちらの選択肢も同様に優れており、出現一致では、元の順序 (A) と比較して安価な順序が自動的に選択されます。
