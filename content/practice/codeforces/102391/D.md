### なぜ効果があるのか

 現在のデータ間の一致を修正します。`2`とターゲット`2`s. すべて一致しました`2`は必要な距離を移動する必要があるため、その移動は少なくとも上記の 2 ステップおよび 1 ステップのコストに寄与します。 2つが一致するたびに`2`クロスの場合、1 つの 2 ステップの動きには`122`または`221`の代わりにパターン`112`または`211`、ちょうど 1 つの追加ユニットを追加します。 したがって、DP 目標は、すべての有効なシーケンスの下限になります。 

現在の固定パーティションの場合`2`2 つのターゲット パリティ クラスに分類すると、ソートされたマッチングによって移動の寄与と交差が最小限に抑えられます。 DP は考えられるすべてのパーティションを検査するため、すべての一致に対して最小の下限を見つけます。 

最後に、依存関係グラフは、対応する動作が実際に実行できる順序を示します。 2 つのポジションの動きはすべて (C+4)、残りの 1 つのポジションの動きはすべて (C+3)、および他のポジションと交差するすべての動きが寄与します。`2`DP によってすでにカウントされている追加の 1 単位を提供します。 したがって、構築されたシーケンスは正確に DP 値に達します。 有効なシーケンスはその下限より安くならないため、構築は最適です。

import sys
from bisect import bisect_right
from collections import deque

input = sys.stdin.readline

def solve(data: str) -> str:
    it = iter(data.split())
    n = int(next(it))
    C = int(next(it))
    s = next(it)
    t = next(it)

    a = [i for i, ch in enumerate(s) if ch == '2']
    b = [[], []]

    for i, ch in enumerate(t):
        if ch == '2':
            b[i & 1].append(i)

    m = len(a)
    b0_len = len(b[0])
    b1_len = len(b[1])

    # pref[p][x] = number of target 2s of parity p
    # in positions [0, x).
    pref = [[0] * (n + 1) for _ in range(2)]
    for p in range(2):
        for i in range(n):
            pref[p][i + 1] = pref[p][i]
            if i in set():
                pass

    # Avoid rebuilding sets in the inner loops.
    target_parity = [0] * n
    for p in range(2):
        for x in b[p]:
            target_parity[x] = 1

    for i in range(n):
        pref[0][i + 1] = pref[0][i] + (
            1 if target_parity[i] == 0 and t[i] == '2' else 0
        )
        pref[1][i + 1] = pref[1][i] + (
            1 if target_parity[i] == 1 and t[i] == '2' else 0
        )

    INF = 10**30
    dp = [[INF] * (m + 1) for _ in range(m + 1)]
    choice = [[-1] * (m + 1) for _ in range(m + 1)]
    dp[0][0] = 0

    for i in range(m):
        for j in range(i + 1):
            cur = dp[i][j]
            if cur == INF:
                continue

            # Assign a[i] to the next even target position.
            if j < b0_len:
                x = b[0][j]
                d = abs(a[i] - x)
                move = (d // 2) * (C + 4) + (d & 1) * (C + 3)

                already_used_odd = i - j
                inv = max(0, pref[1][x + 1] - already_used_odd)

                nv = cur + move + inv
                if nv < dp[i + 1][j + 1]:
                    dp[i + 1][j + 1] = nv
                    choice[i + 1][j + 1] = 0

            # Assign a[i] to the next odd target position.
            if i - j < b1_len:
                x = b[1][i - j]
                d = abs(a[i] - x)
                move = (d // 2) * (C + 4) + (d & 1) * (C + 3)

                already_used_even = j
                inv = max(0, pref[0][x + 1] - already_used_even)

                nv = cur + move + inv
                if nv < dp[i + 1][j]:
                    dp[i + 1][j] = nv
                    choice[i + 1][j] = 1

    # Recover the matched target position for every current 2.
    target = [0] * m
    i = m
    j = b0_len

    while i > 0:
        c = choice[i][j]
        if c == 0:
            target[i - 1] = b[0][j - 1]
            j -= 1
        else:
            target[i - 1] = b[1][i - j - 1]
        i -= 1

    # Dependency graph.
    graph = [[] for _ in range(m)]
    indeg = [0] * m

    for i in range(m):
        for j in range(i):
            if target[i] <= target[j]:
                continue

            if a[i] <= target[j]:
                graph[i].append(j)
                indeg[j] += 1

            if a[j] >= target[i]:
                graph[j].append(i)
                indeg[i] += 1

    q = deque(i for i in range(m) if indeg[i] == 0)
    operations = []

    while q:
        u = q.popleft()

        if a[u] < target[u]:
            while a[u] + 2 <= target[u]:
                p = a[u]
                operations.append((p + 1, p + 3))
                a[u] += 2

            if a[u] < target[u]:
                p = a[u]
                operations.append((p + 1, p + 2))
                a[u] += 1

        else:
            while a[u] - 2 >= target[u]:
                p = a[u]
                operations.append((p, p + 2))
                a[u] -= 2

            if a[u] > target[u]:
                p = a[u]
                operations.append((p, p + 1))
                a[u] -= 1

        for v in graph[u]:
            indeg[v] -= 1
            if indeg[v] == 0:
                q.append(v)

    out = [str(len(operations))]
    out.extend(f"{l} {r}" for l, r in operations)
    return "\n".join(out) + "\n"

このトレースは、距離寄与が 2 ポジションの移動に (C+4) を使用し、1 ポジションの移動に (C+3) を使用する理由を示しています。

## テストケース

# Save the solution above as solution.py before running this file.

from solution import solve

def validate(inp: str, out: str):
    data = inp.split()
    n = int(data[0])
    C = int(data[1])
    s = list(data[2])
    target = data[3]

    lines = out.strip().splitlines()
    k = int(lines[0])
    assert len(lines) == k + 1

    cost = 0

    for line in lines[1:]:
        l, r = map(int, line.split())
        assert 1 <= l < r <= n
        assert r - l <= 2

        # Convert to zero-based indexing.
        l -= 1
        r -= 1

        cost += sum(int(s[i]) for i in range(l, r + 1)) + C
        s[l:r + 1] = reversed(s[l:r + 1])

    assert ''.join(s) == target
    return cost

 ## 特殊なケース

 (N=1) の場合、法的な取り消しはありません。 のカウント以来、`1`そして`2`2 つの文字列が一致する場合、文字列はすでに同一である必要があります。 DP には (m=0) があるため、すぐにゼロの操作が生成されます。 

入力が 2 位置だけ異なる場合、たとえば、```
2 5
12
21
```有用な逆転が 1 つだけあります。 DP は現在と一致します`2`位置 (1) とターゲット位置 (0) で、距離 1 とコスト (C+3=8) が与えられます。 復興が発するもの`1 2`。 

次のように、長さ 3 の演算が最適な選択である場合```
3 7
112
211
```の`2`2 つの位置を左に移動する必要があります。 DP は距離 2 を割り当て、(C+4=11) を与えます。 復興が発するもの`1 3`、変化します`112`直接中に`211`。 

すべてのコンテナが等しい場合、たとえば、```
500 1000
111111...111
111111...111
```ありません`2`処理する必要があり、DP にはトランジションがありません。 答えはゼロオペレーションです。 このケースでは、実装によって不必要な反転が誤って作成されないことも検証されます。 

最も微妙なエッジ ケースは、(C) を変更すると最適なマッチング自体が変化する場合です。 サンプル 2 と 3 は同じ 2 つの文字列を使用していますが、(C) の値が異なります。 (C=0) の場合、最適化では 4 つの演算とコスト (14) が使用されます。 (C=2) の場合、長さ 3 の演算を 3 つ使用し、コストが (21) になる方が適切です。 移動されるポジションの数だけ、または操作の数だけを最小限に抑える戦略では、このトレードオフに対処できません。 DP は、移動ペナルティと交差ペナルティの両方を含む完全なコスト式を評価するため、どちらの場合でも正しい一致を選択します。 

注目に値する実装の詳細: 上記の編集コードは内部で 0 から始まる表現を使用し、操作を発行するときにのみ変換します。 これは、この問題で最も一般的な off-by-one エラーを回避する最も安全な方法です。
