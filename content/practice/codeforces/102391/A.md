 ## 解決策
 ## 問題の理解

 私たちは、`N x M`エントリが次のいずれかを示すカードである配列`6`、`7`、`8`、 または`9`。 カードはその場で回転できますが、セル間を移動することはできません。 回転するカードを選択した後、結果の配列は 180 度回転しても変更されない必要があります。 

180 度回転して位置をマップします`(i, j)`に`(N - 1 - i, M - 1 - j)`。 配列が点対称であるためには、回転されたカードが変化するという事実を考慮した上で、これらの位置にある 2 枚のカードも一致する必要があります。`6`の中へ`9`、`9`の中へ`6`、 その間`7`そして`8`変わらないまま。 

タスクは、物理的に回転するカードの数を最小限に抑えることです。 位置のペアが互換性のない数字グループに属している場合、一連の回転によって配列を対称にすることはできないため、次のように出力します。`-1`。 

制約により、両方の次元が達成できるようになります。`500`、せいぜい与えます`250000`細胞。 ここでは、セル数に二次または指数関数的に依存するアルゴリズムは不可能です。 平`O((NM)^2)`は大きすぎるでしょうが、`O(NM)`scan は Python の 1 秒以内に簡単に実行できます。 メモリ制限は十分にあるため、入力行列の保存は問題ありません。 

単純な実装では誤って処理される可能性のあるエッジケースがいくつかあります。 1 つ目は、`6`。 入力```
1 1
6
```生産しなければならない`1`中央のセルは 180 度回転するとそれ自体にマップされるため、その最終値は自己対称である必要があります。 異なるセルを比較するだけの不注意なソリューションは、誤った結果を返す可能性があります。`0`。 

以下を含む単一セルでも同じ問題が発生します。`7`:```
1 1
7
```正しい答えは、`0`、 なぜなら`7`残る`7`回転させたとき。 奇数サイズのマトリックスの中心には明確なパートナーがないため、別個の処理が必要です。 

もう 1 つのエッジケースは、互換性のないペアです。 例えば、```
1 2
67
```ポジションがある`6`そして`7`対称ペアとして。 回転させると、`6`生産することしかできない`6`または`9`を回転させながら、`7`常に生成します`7`。 それらは両立することは決してないので、答えは次のとおりです。`-1`。 

最後によくある間違いは、対称ペアを二重にカウントすることです。 のために```
1 2
69
```どちらかのカードを回転させると一致するペアが得られるため、1 回の回転で十分です。 正しい答えは、`1`、 ない`2`。 両方を処理する`(0, 0)`と`(0, 1)`その後`(0, 1)`と`(0, 0)`同じ決定を 2 回カウントします。 

## アプローチ

 直接的な総当たりアプローチは、`NM`ローテーションされるカードとしてカードを選択します。 がある`2^(NM)`そのようなサブセット。 サブセットごとに、結果の行列を構築または検査し、すべてをチェックします。`NM`180 度対称になる位置。 これにより、最悪の場合の実行時間は次のようになります。`O(NM * 2^(NM))`。 

ローテーションされたカードのすべての可能な選択肢が明示的に考慮されるため、総当り攻撃は正しいため、候補の中から最も有効な選択肢が現れる必要があります。 問題は選択肢の多さです。 最大サイズでは、`NM = 250000`、したがって、検索には次のものが含まれます`2^250000`可能性。 これは実際には遅すぎるだけでなく、列挙できるものをはるかに超えています。 

有益な観察は、180 度回転した位置が独立したペアを形成するということです。 細胞`(i, j)`とのみペアリングされます`(N - 1 - i, M - 1 - j)`。 これら 2 枚のカードの向きを決定すると、その決定は他のペアには影響しません。 その結果、すべてのペアを個別に解決し、最小コストを追加することができます。 

構造上の詳細がもう 1 つあります。 回転されたカードには次のような変化があります。```
6 <-> 9
7 -> 7
8 -> 8
```したがって、数字は自然に 3 つの互換性グループを形成します。`{6, 9}`、`{7}`、 そして`{8}`。 2 つのペアになったセルは、元の数字が同じグループに属している場合、正確に対称にすることができます。 

同じ数字を含むペアの場合、回転は必要ありません。 を含むペアの場合`6`そして`9`、カードを 1 枚だけローテーションする必要があります。 ペアに 2 つの異なる互換性のないグループが含まれている場合、`6`そして`7`、解決策は存在しません。 

もし`N`そして`M`両方とも奇数の場合、ペアになっていない中央セルが 1 つあります。 それ自体にマップする必要があるため、次のものが含まれている必要があります`7`または`8`が含まれている場合は、1 回回転する必要があります。`6`または`9`。 

この総当り方式は、すべての向きを明示的に検索するため機能しますが、向きの選択肢が指数関数的に多いため失敗します。 すべてのセルが独立した対称ペアに属しているという観察により、問題はセルごとの一定の作業量に軽減されます。

 ## アルゴリズムのチュートリアル

 1. を読んでください。`N x M`マトリックスを作成し、次のように回転マッピングを定義します。`6`になる`9`、`9`になる`6`、 その間`7`そして`8`変わらずにいてください。 
2. すべてのセルを反復処理します。`(i, j)`それが対称ペアの最初のメンバーである場合のみ。 そのパートナーは、`(N - 1 - i, M - 1 - j)`。 反復を各ペアの片側に制限すると、二重カウントが防止されます。 
3. 各ペアについて、2 つの数字が同じ互換性グループに属しているかどうかを確認します。 これを表現する最も簡単な方法は正規化することです`6`そして`9`退職中に同じ代表者に`7`そして`8`明確な。 
4. 正規化された値が異なる場合は、戻り値を返します。`-1`。 どちらのカードの向きも互換性グループ間で交差できないため、このペアではマジック マトリックスが不可能になります。 
5. 元の 2 つの数字が等しい場合は、答えに 0 を加えます。 どちらのカードも回転しなくても、それらはすでに必要な関係を満たしています。 
6. ペアが`6`そして`9`、答えに1を追加します。 どちらかのカードを回転させるだけで十分であり、両方を回転させる必要はありません。 
7. すべての個別のペアを処理した後、両方の次元が奇数であるかどうかを確認します。 その場合、中央のセルは次のとおりです。`(N // 2, M // 2)`明確なパートナーはいません。 
8. 中心に次のものが含まれている場合`6`または`9`、自己対称になるように回転する必要があるため、1 つ追加します。 含まれている場合`7`または`8`、何も追加しません。 

### なぜ効果があるのか

 すべての位置は、180 度回転した 1 つの 2 セル軌道に属するか、両方の次元が奇数の場合は 1 つの中央セルに属します。 1 つの軌道に対して行われた選択が別の軌道に影響を与えることはできないため、各軌道を個別に最小化すると、総回転数も最小化されます。 

2 セルの軌道の場合、数字の可能な変換値は、それ自体の値とそのペアの値のみです。`6 <-> 9`。 したがって、2 つのセルが両方とも同じである場合、正確に互換性があります。`{6, 9}`、 両方`7`、または両方`8`。 内で`{6, 9}`、値が異なる場合は 1 回の回転で十分ですが、同じ値では回転する必要はありません。 中心は、その桁が回転によって変更されない場合に正確に互換性があります。これは次の場合に当てはまります。`7`そして`8`; センター`6`または`9`1回転が必要です。 したがって、アルゴリズムによって計算されるすべての寄与は、その独立した軌道に対する可能な最小の寄与であり、それらの合計は全体的に最適になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = [input().strip() for _ in range(n)]

    answer = 0

    # Normalize digits that can become each other by rotation.
    def group(c):
        if c == '6' or c == '9':
            return '6'
        return c

    # Process each pair exactly once.
    for i in range(n):
        for j in range(m):
            ni = n - 1 - i
            nj = m - 1 - j

            # The center of an odd-by-odd matrix is handled separately.
            if i > ni or (i == ni and j >= nj):
                continue

            x = a[i][j]
            y = a[ni][nj]

            if group(x) != group(y):
                print(-1)
                return

            if x != y:
                # The only possible compatible unequal pair is 6 and 9.
                answer += 1

    # An odd-by-odd matrix has one cell that maps to itself.
    if n % 2 == 1 and m % 2 == 1:
        center = a[n // 2][m // 2]
        if center == '6' or center == '9':
            answer += 1

    print(answer)

if __name__ == "__main__":
    solve()
```の`group`関数は、重要な互換性の唯一の違いを捉えます。 両方`6`そして`9`ローテーションにより一方が他方に変わる可能性があるため、同じグループに属します。`7`そして`8`回転しても変更されないため、それぞれが独自のグループを形成します。 

ネストされたループは、次を使用してパートナーを計算します。`n - 1 - i`そして`m - 1 - j`、180 度回転のジオメトリに直接一致します。 条件```
if i > ni or (i == ni and j >= nj):
    continue
```各ペアから正確に 1 つのセルを保持します。 の`j >= nj`2 つの行が同じである場合、この部分が重要になります。そうでない場合、中央の列の周囲でペアが 2 回処理される可能性があるためです。 

有効なペアの場合、`x != y`ペアが次でなければならないことを意味します`6`そして`9`なので、正確に 1 回転する必要があります。 回転のコストは常に 1 であるため、回転を明示的にシミュレートする必要はありません。 

中心はペアループから除外され、後で処理されます。 これにより、誤って中心をそれ自体とのペアとして扱うことがなくなります。 センター`6`または`9`1 回転に貢献しますが、`7`そして`8`貢献度はゼロ。 

Python では整数オーバーフローは発生せず、最大の答えは次のとおりです。`NM`、つまり`250000`。

|`(i,j)`| パートナー | 値 | 最小回転数 |

 |`(0,2)`|`(1,0)`|`6, 6`|`1`|

## テストケース```python
import sys
import io

def solve(inp: str) -> str:
    data = io.StringIO(inp)
    n, m = map(int, data.readline().split())
    a = [data.readline().strip() for _ in range(n)]

    def rotate(c):
        if c == '6':
            return '9'
        if c == '9':
            return '6'
        return c

    answer = 0

    for i in range(n):
        for j in range(m):
            ni = n - 1 - i
            nj = m - 1 - j

            if i > ni or (i == ni and j > nj):
                continue

            x = a[i][j]
            y = a[ni][nj]

            # Both cards must become equal after independent rotations.
            if x == y:
                # 7 and 8 are already unchanged.
                # 6 and 9 must both become the opposite digit, so
                # rotating both would work, but rotating neither does not.
                if x == '6' or x == '9':
                    answer += 1
            elif rotate(x) == y:
                # Rotate exactly one of the two cards.
                answer += 1
            elif rotate(x) == rotate(y):
                # Rotate both cards. This case is needed when both
                # belong to the same rotation class but are equal,
                # and is covered above for 6/9.
                answer += 2
            else:
                print("-1")
                return

    if n % 2 == 1 and m % 2 == 1:
        center = a[n // 2][m // 2]
        if center == '6' or center == '9':
            answer += 1

    return str(answer)
