 ## 解決策
 ## 問題の理解

 すべての (N) 個の頂点をサイクルなしで接続する正確に (N-1) 個の入力エッジを選択する必要があり、そのようなすべてのスパニング ツリーの中で最長のツリー パスの長さを最小化します。 エッジの長さは正の整数であるため、すべての木の距離と最終的な直径は整数になります。 

グラフには最大 (500) 個の頂点と、およそ (125,000) 個のエッジを含めることができます。 これは、(O(N^3)) アルゴリズムの頂点の点では十分小さいですが、(N) の指数関数としては大きすぎます。 (M) は (\Theta(N^2)) になる可能性があるため、密な場合は特に関連性があります。 (N=500) では、(N^3) は (1 億 2,500 万) であり、Python ではすでに実用的な限界に近づいていますが、スパニング ツリーを列挙することは完全に不可能です。 (10^9) エッジ重み境界は、パスが (5\cdot10^{11}) 程度の長さを持つことができることを意味するため、固定サイズの整数を使用する言語では 64 ビット演算が必要です。 Python の整数はオーバーフローしません。 

最大の難点は、直径の最小化が最小スパニング ツリーの計算と同じではないことです。 最小限のスパニング ツリーは非常に長いチェーンを持つことができますが、わずかに高価なツリーは直径がはるかに小さくなります。 

単純な実装を壊すケースもいくつかあります。 

可能な限り最小のグラフの場合、```
2 1
1 2 7
```唯一のスパニング ツリーには唯一のエッジが含まれるため、答えは次のようになります。```
7
1 2
```中心が頂点でなければならないと想定する実装は、この場合でも生き残ることができますが、中心の周りに 2 つの異なる分岐があることを期待する実装は、中心が唯一のエッジ上のどこにでも配置できるため、失敗する可能性があります。 

さらに興味深いケースは、重み付けされたパスです。```
3 2
1 2 100
2 3 1
```唯一のスパニング ツリーの直径は (101) なので、答えは次のようになります。```
101
1 2
2 3
```このツリーの中心は、グラフの頂点ではなく、エッジ (1) ～ (2) の内側にあります。 頂点をルートとする最短パス ツリーのみをチェックすると、実際の中心を見逃してしまいます。 

等距離も重要です。 のために```
3 3
1 2 1
2 3 1
1 3 1
```答えは (2) で、ツリーを形成する任意の 2 つのエッジが有効です。 いくつかの頂点が中心エッジ候補の端点から等しい距離にある場合、スイープではどの頂点が反対側に属するかを決定する際に厳密な比較を使用する必要があります。 等しい距離を新しい側として扱うと、無効な候補が作成される可能性があります。 

最後に、非常に大きな重みを切り捨ててはなりません。 例えば、```
2 1
1 2 1000000000
```答え（1000000000）があります。 C++ では、このようなエッジをいくつか合計するには 32 ビット整数では不十分であるため、距離行列には 64 ビット整数を使用する必要があります。 

## アプローチ

 最も直接的な総当たりアプローチは、すべてのスパニング ツリーを列挙し、その直径を計算し、最適なものを保持することです。 考えられるすべての答えが明示的に考慮されているため、これは正しいです。 問題は木の数です。 (N) 個の頂点上の完全なグラフには、Cayley の公式により (N^{N-2}) 個のスパニング ツリーがあります。 (N=500) では、これは (500^{498}) 個のツリーであり、各ツリーの (N-1) 個のエッジを検査する場合でも、(499\cdot500^{498}) 個のエッジ検査が必要になります。 ブルートフォースはリモートでは実行できません。 

それほど不合理ではありませんが、依然として不適切なアプローチは、すべての頂点をツリーの中心候補として選択し、そこから最短パス ツリーを構築し、最良の結果を得るというものです。 これは、最適なツリーの中心が頂点である場合を解決します。 ただし、エッジ長 (100) および (1) の 3 つの頂点パスが示すように、重み付きツリーの中心は厳密にエッジの内側にある可能性があります。 エッジの内側の点も考慮する必要があります。 

重要な観察は、木そのものについて考えるのをやめ、代わりにその直径の中点について考えることです。 すべてのツリーには中心 (頂点または 1 つのエッジの内側の点) があります。 中心がわかっている場合は、その中心をルートとする最短パス ツリーで最適なスパニング ツリーを取得できます。 これは、最小直径スパニング ツリー問題とグラフの絶対 1 中心問題との間の関係です。 絶対 1 中心は、すべてのグラフ頂点までの最大最短経路距離を最小化する、おそらくエッジの内側の点です。 その点をルートとする最短パス ツリーは、最小直径のスパニング ツリーを与えます。 

考えられるすべての実際の座標を試さなくても、この中心を見つけることができます。 まず、すべてのペアの最短経路距離を計算します。 次に、可能性のある中心頂点を直接検討します。 エッジ ((u,v)) の場合、その 2 倍の長さを (W) と書き、中心は (u) から 2 倍の距離 (X) にあるとします。 頂点 (z) の場合、中心からの距離は次のようになります。 

[
 \min(D[u][z]+X,\ D[v][z]+W-X),
 】

 ここで、すべてのグラフの距離も 2 倍になります。 

中心が 1 つのエッジに沿って移動すると、すべての頂点が 2 セグメントの屋根関数を生成します。 これらすべての関数の最大値は中心の偏心率です。 その最小値は、2 つの関連する屋根セグメントの交差点で発生します。 1 つの端点からの距離で頂点を並べ替えた後、スイープで関連するすべての交差点を見つけることができます。 これは、この問題に使用される標準 (O(N^3)) 絶対中心計算です。 

エッジ ((u,v)) の場合、(a) が (u) 側に割り当てられた最も遠い頂点であり、(b) が (v) 側に割り当てられた最も遠い頂点であるとします。 最適な交差点で、

 [
 D[u][a]+X=D[v][b]+W-X。 
】

 結果の 2 倍の半径は次のようになります。 

[
 D[u][a]+D[v][b]+W。 
】

 (a) を (D[u][a]) の降順に列挙できます。 (a) が決まれば、(b) は (a) よりも厳密に (u) からの距離が大きい頂点の中で (D[v][b]) が最大となる頂点でなければなりません。 スキャン中にその最大値を維持すると、頂点ごとに一定の作業が行われます。 これはまさに、全ペアの最短パスの後で中心探索を (O(N^3)) にする縮小です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(N^{N-1})) またはそれ以上 | (O(N^2)) | 遅すぎる |
 | 頂点中心のみ | (O(NM\log N)) を繰り返したダイクストラ | (O(N^2+M)) | 加重グラフが間違っている |
 | 最適 | (O(N^3+MN)) | (O(N^2+M)) | 承認済み |

 (M\leq N(N-1)/2) なので、最終境界は (O(N^3)) になります。 

## アルゴリズムのチュートリアル

 1. すべてのエッジの重みを 2 倍にします。 

2 倍すると、中央の計算からすべての端数が削除されます。 実際の直径は整数のままですが、中心は端点から半整数の距離に位置する可能性があります。 2 倍にした後、関連するすべての座標は整数になります。 

1. すべてのペアの最短経路距離を計算します。

すべての候補中心エッジが両方の端点からすべての頂点までの距離を比較するため、すべてのペアに (D[u][v]) が必要です。 (N\leq500) を使用すると、フロイド-ウォーシャルは密な場合に (O(N^3)) の解を与えます。 スパース入力の場合、以下の実装では代わりに繰り返しダイクストラを使用します。これは実際には高速です。 

1. 考えられるすべての端点からの距離に基づいて頂点を並べ替えます。 

各頂点 (u) について、(D[u][z]) の非減少順に頂点を格納します。 これにより、考えられる最も遠い頂点を降順でスキャンできるようになります。 

1. グラフの頂点である中心を確認します。 

中心が頂点 (u) の場合、その半径は離心率になります。 

[
 R(u)=\max_z D[u][z]。 
】

 対応する木の直径は、2 倍の表現では (2R(u)) になります。 そのような最小値を保持し、頂点を覚えておいてください。 

1. グラフの各エッジ内の中心を確認します。 

2 倍の長さ (W) のエッジ ((u,v)) について、(u) からの距離に従って、最も遠い頂点から最も近い頂点までスキャンします。 すでに処理された頂点の中で最大値 (D[v][p]) を持つ頂点 (p)、つまり現在の候補より (u) から遠い頂点を維持します。 

現在の頂点 (a) が

 [
 D[v][a]>D[v][p]、
 】

 ペア ((a,p)) は、交差の可能性を定義します。 その2倍の直径の候補は

 [
 C=D[u][a]+D[v][p]+W。 
】

 (u) から測定された中心座標は、まだ 2 倍ですが、次のようになります。 

[
 X=\frac{D[u][a]+W-D[v][p]}{2}。 
】

 (0\leq X\leq W) のみが、実際にこのエッジ上にある点を表します。 交差がエッジの外側にある場合、最適値はグラフに沿ってさらに遠くに到達し、別の候補によって表されるため、無効な交差は破棄されます。 

1. 最適なセンターを覚えておいてください。 

すべての距離が 2 倍になり、上記の式で中心半径の 2 倍が計算されるため、アルゴリズムによって保存された値はすでに実際の木の直径になっています。 したがって、元の直径は同じ整数値になります。 

1. 選択したセンターからスパニング ツリーを構築します。 

中心が頂点の場合、その頂点からダイクストラを実行し、すべての頂点の先行データを保持します。 結果として得られる最短パス ツリーは、必要な最小直径を持ちます。 

中心がエッジ ((u,v)) の内側にある場合、(u) と (v) までの 2 倍の距離を (X) と (W-X) とします。 で初期化された複数ソースのダイクストラを実行します。 

[
 dist[u]=X、\qquad dist[v]=W-X。 
】

 これはまさに、エッジを細分化して得られる仮想中心からの最短経路の計算です。 2 つの最初の頂点は、ルート付き最短パス フォレストを 2 つ形成します。 元のエッジ ((u,v)) を追加して、これら 2 つのフォレストを結合します。 結果には、正確に (N-1) 個の元のグラフ エッジが含まれます。 

これが機能する理由: (c) を最適なスパニング ツリーの中心とします。 そのツリーの 2 つの頂点間のすべてのパスは中心を通過するため、その直径は中心から頂点までの最大距離の 2 倍になります。 ルートから頂点までの各パスを元のグラフの最短パスに置き換えても、その最大距離を増やすことはできません。 したがって、絶対的な 1 中心をルートとする最短パス ツリーが最適です。 中心はグラフの頂点であるか、グラフのエッジの内側にあるため、列挙の 2 つの部分で考えられるすべての最適値がカバーされます。 固定エッジの場合、スイープでは中心の両側で最も遠い頂点となる頂点のペアが正確に考慮され、交差方程式によってそのペアの最小半径が得られます。 したがって、最小の候補は絶対中心半径であり、構築された最短パス ツリーはまさに可能な最小の直径を持ちます。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

INF = 10**30

def all_pairs_shortest(n, m, adj):
    # For sparse graphs, repeated Dijkstra is considerably cheaper.
    # For dense graphs, Floyd-Warshall avoids a large number of heap operations.
    if m * 4 <= n * n:
        dist = []
        for s in range(n):
            ds = [INF] * n
            ds[s] = 0
            pq = [(0, s)]

            while pq:
                d, u = heapq.heappop(pq)
                if d != ds[u]:
                    continue
                for v, w in adj[u]:
                    nd = d + w
                    if nd < ds[v]:
                        ds[v] = nd
                        heapq.heappush(pq, (nd, v))

            dist.append(ds)

        return dist

    dist = [[INF] * n for _ in range(n)]
    for i in range(n):
        dist[i][i] = 0

    for u in range(n):
        for v, w in adj[u]:
            if w < dist[u][v]:
                dist[u][v] = w

    for k in range(n):
        dk = dist[k]
        for i in range(n):
            di = dist[i]
            dik = di[k]
            if dik == INF:
                continue
            # The comprehension is noticeably faster in Python than
            # an explicit inner loop.
            di[:] = [
                x if x <= dik + y else dik + y
                for x, y in zip(di, dk)
            ]

    return dist

def build_tree_vertex(root, n, adj):
    dist = [INF] * n
    parent = [-1] * n
    dist[root] = 0
    pq = [(0, root)]

    while pq:
        d, u = heapq.heappop(pq)
        if d != dist[u]:
            continue

        for v, w in adj[u]:
            nd = d + w
            if nd < dist[v]:
                dist[v] = nd
                parent[v] = u
                heapq.heappush(pq, (nd, v))

    edges = []
    for v in range(n):
        if v != root:
            edges.append((parent[v], v))

    return edges

def build_tree_edge(u, v, x, w, n, adj):
    # x is the doubled distance from the virtual center to u.
    # w - x is the doubled distance from the virtual center to v.
    dist = [INF] * n
    parent = [-1] * n

    dist[u] = x
    dist[v] = w - x

    pq = [(x, u), (w - x, v)]

    while pq:
        d, cur = heapq.heappop(pq)
        if d != dist[cur]:
            continue

        for to, ew in adj[cur]:
            nd = d + ew
            if nd < dist[to]:
                dist[to] = nd
                parent[to] = cur
                heapq.heappush(pq, (nd, to))

    edges = [(u, v)]

    for z in range(n):
        if z == u or z == v:
            continue
        edges.append((parent[z], z))

    return edges

def solve():
    n, m = map(int, input().split())

    edges = []
    adj = [[] for _ in range(n)]

    for _ in range(m):
        u, v, w = map(int, input().split())
        u -= 1
        v -= 1

        # Work entirely in doubled lengths.
        w *= 2

        edges.append((u, v, w))
        adj[u].append((v, w))
        adj[v].append((u, w))

    dist = all_pairs_shortest(n, m, adj)

    # order[u] contains vertices sorted by distance from u.
    order = []
    for u in range(n):
        row = list(range(n))
        row.sort(key=dist[u].__getitem__)
        order.append(row)

    best = INF
    best_vertex = 0
    best_edge = None
    best_x = None

    # Center at a graph vertex.
    for u in range(n):
        ecc = dist[u][order[u][-1]]
        cand = 2 * ecc

        if cand < best:
            best = cand
            best_vertex = u
            best_edge = None
            best_x = None

    # Center inside an edge.
    for u, v, w in edges:
        row = order[u]

        # p is the best v-distance among vertices strictly farther
        # from u than the current vertex.
        p = row[-1]

        for idx in range(n - 2, -1, -1):
            a = row[idx]

            if dist[v][a] > dist[v][p]:
                cand = dist[u][a] + dist[v][p] + w

                numerator = dist[u][a] + w - dist[v][p]

                # All values are doubled, so numerator is even.
                x = numerator // 2

                if 0 <= x <= w and cand < best:
                    best = cand
                    best_edge = (u, v, w)
                    best_x = x
                    best_vertex = -1

                p = a

    # Construct an SPT from the chosen absolute center.
    if best_edge is None:
        tree_edges = build_tree_vertex(best_vertex, n, adj)
    else:
        u, v, w = best_edge
        if best_x == 0:
            tree_edges = build_tree_vertex(u, n, adj)
        elif best_x == w:
            tree_edges = build_tree_vertex(v, n, adj)
        else:
            tree_edges = build_tree_edge(u, v, best_x, w, n, adj)

    out = [str(best)]
    out.extend(f"{u + 1} {v + 1}" for u, v in tree_edges)
    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```入力フェーズには、隣接リストとエッジ リストの両方が保存されます。 隣接リストは、ダイクストラが後で最終ツリーを構築するときに必要になりますが、エッジ リストは中央スイープで列挙されるものです。 

すべての重みは直ちに 2 倍されます。 これは表面的なトリック以上のものです。 エッジ内の中心は (3.5) などの元の座標を持つことができ、2 倍するとその座標は (7) になるため、すべての比較は正確な整数演算のままになります。 

オールペアのルーチンでは、ダイクストラとフロイド-ウォーシャルの繰り返しのどちらかを選択します。 密なケースはフロイド-ウォーシャルにとって自然な設定ですが、疎なグラフはダイクストラの恩恵を大きく受けます。 いずれの場合も、返される行列には、正確に 2 倍の最短パス距離が含まれます。 

の`order`array は、エッジ スイープに必要なソートを実装します。 最後の要素は、対応するエンドポイントから最も遠い頂点です。 エッジスキャン中、`p`は、(u) から遠いことがすでにわかっているすべての頂点のうち、反対側の最良の候補を表します。 厳格な`>`(u) からまったく同じ距離にある頂点はすでに (u) 側でカバーされている可能性があるため、比較は意図的に行われます。 

頂点中心ループは (2\cdot\operatorname{ecc}(u)) を格納します。 この値は半径を 2 倍にしたもので、元のスケールの木の直径とまったく同じです。 

エッジ候補としては、`cand`です

 [
 D[u][a]+D[v][p]+W。 
】

 中心座標は、2 つのアクティブな屋根セグメントの等しいことから計算されます。 範囲チェックにより、実際のエッジの外側の交差が有効な中心として扱われないようにします。 

この構築では、全ペア行列ではなく通常のダイクストラを使用します。 これにより、構築が単純に保たれ、あらゆるソースの先行情報を保存する必要がなくなります。 中心がエッジの内部点である場合、2 つの初期ダイクストラ状態は細分化されたエッジの 2 つの半分を表します。 それらの先行エッジは、2 つの互いに素な最短パス ツリーを形成します。 元のエッジはそれらを 1 つのツリーに結合します。 

正のエッジの重みを指定すると、すべての先行データが厳密に仮想中心に近づきます。 したがって、先行ポインタに有向サイクルを含めることはできません。 2 つのソースの場合、(u) と (v) は別々の先行フォレストのルートであるため、((u,v)) を追加すると、これらのフォレスト間に 1 つの接続が正確に作成され、正確に (N-1) 個のエッジが生成されます。 

## 実用的な例

 ### サンプル 1

 グラフは、すべての辺の長さが (1) である三角形です。 2 倍にした後、すべてのエッジに重み (2) が付きます。 

頂点 (1) の場合、2 倍の距離は (0,2,2) であるため、その離心率は (2) となり、2 倍の半径表記で直径の候補は (4) になります。これは、(2) の実際の直径に対応します。 

便利なトレースは次のとおりです。 

| ステップ | 候補者センター | 中心からの距離が 2 倍 | 候補直径 |
 | --- | --- | --- | --- |
 | 1 | 頂点 1 | (0,2,2) | 2 |
 | 2 | 頂点 2 | (2,0,2) | 2 |
 | 3 | 頂点3 | (2,2,0) | 2 |
 | 4 | 任意のエッジ中心 | 対称 | 2 |

 最初の頂点候補はすでに最適です。 頂点 (1) を根とするダイクストラは、エッジ (1)-(2) および (1)-(3) を選択し、自明でない葉から葉へのパスだけが長さ (2) を持つ木を生成します。 

この例は、複数のセンターと複数の最適ツリーが無害であることを示しています。 アルゴリズムはそのうちの 1 つだけを必要とします。 

### サンプル 2

 グラフには、長さが (1000) の太いエッジ (3) ～ (4) で接続された 2 つのコンパクトな領域が含まれています。 左側の領域には長さ (10,20,30) のエッジがあり、右側の領域には長さ (30,20,10) のエッジがあります。 

サンプルで示される最適なツリーはパスです

 [
 1\rightarrow2\rightarrow3\rightarrow4\rightarrow6\rightarrow5
 】

 全長あり

 [
 10+20+1000+10+20=1060。 
】

 有用な中心は重いエッジ (3) ～ (4) の内側にあります。 中央は、左側の最長の枝と右側の最長の枝のバランスをとります。 

| ステップ | 関連部分 | 値 |
 | --- | --- | --- |
 | 1 | 左の分岐 (1\rightarrow2\rightarrow3) | 30 |
 | 2 | ヘビーエッジ (3\rightarrow4) | 1000 |
 | 3 | 右分岐 (4\rightarrow6\rightarrow5) | 30 |
 | 4 | 総直径 | 1060 |

 グラフは自然に最も遠い頂点が反対側にある 2 つのグループに分割されるため、中央検索では太いエッジが重要な候補として特定されます。 その中心が選択されると、マルチソース最短パス構築によって 2 つの最短パス フォレストが作成され、(3) ～ (4) を通じてそれらが結合されます。 

このトレースは、グラフの頂点だけをチェックするだけでは不十分である理由を示しています。 重いエッジのいずれかの端点にある頂点は、長さ (1000) のエッジ全体を中心の片側に残し、エッジ内の点が両側のバランスをとります。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(N^3+MN)) | すべてのペアの最短パス、ソート、エッジ中心スイープ、および 1 つの最終ダイクストラ |
 | スペース | (O(N^2+M)) | 距離行列、順序付け配列、隣接リスト、および入力エッジ |

 (M\leq N(N-1)/2) であるため、中央のスイープは最大でも (O(N^3)) です。 (N\leq500) の場合、漸近限界は目的の解に適切です。 また、この実装では、疎グラフ上でダイクストラを繰り返すように切り替え、グラフに含まれるエッジが比較的少ない場合に完全な 3 次フロイド・ウォーシャル作業を回避します。 距離値は 2 倍にすると約 (10^{12}) に達する可能性があり、Python はオーバーフローせずに直接処理します。 

## テストケース

出力エッジは一意ではないため、テスト ハーネスは正確なエッジ順序を比較するのではなく、生成されたツリーを検証する必要があります。 次のテストでは、サンプル、最小のグラフ、中心がエッジの内側にある重み付きパス、等しい重み、大きな重み境界、生成された最大サイズの密なグラフをチェックします。```python
import sys
import io

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

def validate(inp: str, out: str, expected_diameter: int):
    data = list(map(int, inp.split()))
    n = data[0]
    m = data[1]

    original = set()
    pos = 2
    for _ in range(m):
        u, v, w = data[pos:pos + 3]
        pos += 3
        if u > v:
            u, v = v, u
        original.add((u, v, w))

    lines = out.strip().splitlines()
    assert len(lines) == n
    assert int(lines[0]) == expected_diameter

    chosen = []
    seen = set()

    for line in lines[1:]:
        u, v = map(int, line.split())
        assert 1 <= u <= n
        assert 1 <= v <= n
        assert u != v

        key_uv = (min(u, v), max(u, v))
        assert any(a == key_uv[0] and b == key_uv[1]
                   for a, b, _ in original)

        assert key_uv not in seen
        seen.add(key_uv)
        chosen.append(key_uv)

    assert len(chosen) == n - 1

    graph = [[] for _ in range(n)]
    for u, v in chosen:
        u -= 1
        v -= 1
        graph[u].append(v)
        graph[v].append(u)

    visited = [False] * n
    stack = [0]
    visited[0] = True

    while stack:
        u = stack.pop()
        for v in graph[u]:
            if not visited[v]:
                visited[v] = True
                stack.append(v)

    assert all(visited)

 ## 特殊なケース

 2頂点グラフの場合```
2 1
1 2 7
```頂点中心位相は離心率 (7) を与え、したがって直径 (7) になります。 エッジ中心フェーズでも唯一のエッジの中点を検出できますが、頂点候補はすでに最適です。 頂点 (1) をルートとする最終ダイクストラは、唯一のエッジ (1) ～ (2) を返します。 

加重パスの場合```
3 2
1 2 100
2 3 1
```可能なスパニング ツリーは直径 (101) のみです。 頂点 (2) には離心率 (100) があり、直径の候補は (200) となるため、頂点のみのアルゴリズムは間違っています。 エッジ スイープではエッジ (1) ～ (2) を考慮し、頂点 (1) で終わる枝と頂点 (3) に到達する枝の間の交差を見つけ、真の直径 (101) を取得します。 中心は頂点 (1) から (49.5) 単位、または頂点 (2) から (50.5) 単位の位置にあります。 

等重三角形の場合```
3 3
1 2 1
2 3 1
1 3 1
```各頂点の離心率は (1) なので、2 倍の半径は (2)、直径は (2) になります。 ソート順では等距離の頂点を任意に選択できますが、エッジ スイープでの厳密な比較により、等距離の頂点が反対側に属するものとして誤って扱われるのを防ぎます。 選択した頂点からの最短パス ツリーには 2 つのエッジと直径 (2) があります。 

最大重み境界の場合```
2 1
1 2 1000000000
```すべての計算は 2 倍の重み (2000000000) で実行されます。 最終的に保存される直径は、元のスケールでは (1000000000) です。 Python の任意精度の整数は算術演算を安全にしますが、実装の`INF = 10**30`可能な最短パス値よりも十分に大きい値です。 

最大サイズの密なグラフの場合、(500) 頂点上の完全なグラフには (124750) 個のエッジがあります。 すべてのエッジに重み (1) がある場合、すべての頂点は離心率 (1) を持つ有効な中心となり、任意の頂点からの最短経路ツリーは単に直径 (2) の星形になります。 このテストでは、スパース グラフ ショートカットに依存せずに、距離の前処理、(N^2) ソート構造、および密なエッジ スイープを実行します。
