 ## 解決策
 ## 問題の理解

 部屋の番号は (0、1、2、\ldots) と無限にあり、どの部屋にも常に 1 人のゲストがいます。 ゲストはグループに所属しています。 最初は、どの部屋にもグループ (0) のゲストが含まれています。 

タイプ 1 の操作では、新しいグループが作成されます。 パラメータが正の整数 (k) の場合、既存のゲストはすべて (k) 部屋右に移動し、新しいグループは部屋 (0,1,\ldots,k-1) を占有します。 パラメータが (0) の場合、既存のすべてのゲストは部屋 (x) から部屋 (2x) に移動し、新しいグループはすべての奇数の部屋を占有します。 

タイプ 2 のクエリは、特定のグループが占有している (x) 番目に小さい部屋を尋ねます。 タイプ 3 のクエリは、特定の部屋を現在どのグループが占有しているかを尋ねます。 

問題は、ホテルが無限であるため、部屋の配列を明示的にシミュレートすることができないことです。 操作の数も (300000) と大きいため、クエリごとに以前のすべての操作をたどることができなくなります。 2 秒クラスの制限時間では、(O(Q^2)) シミュレーションは可能な範囲をはるかに超えています。 クエリごとにほぼ対数の作業が必要です。 

誤答を引き起こしやすい境界例がいくつかあります。 

まず、部屋 (0) は、無限操作下では異なる動作をします。 これは (0) にマップされるため、無限の操作を繰り返し反転しても、部屋 (0) は小さくなりません。 例えば、```
3
1 0
1 0
3 0
```出力があります```
2
```部屋 (0) は最新の無限グループによって占有されたままであるためです。 無限の操作ごとに部屋番号が半分になると想定するリバース シミュレーションは、スタックしたり、グループを誤ってスキップしたりする可能性があります。 

第二に、有限操作では平等性が重要です。 逆の操作にパラメータ (k) がある場合、部屋 (x=k) は新しく挿入されたグループではなく、古いホテル状態に属します。 例えば、```
3
1 5
3 5
3 4
```出力```
0
1
```グループ (1) は部屋 (0) ～ (4) を占有していますが、部屋 (5) は依然としてグループ (0) に属しているためです。 (x<k) の代わりに (x\leq k) を使用すると、部屋 (5) がグループ (1) に誤って割り当てられます。 

第三に、(x) 番目のゲストには 1 つのインデックスが付けられます。 グループが部屋 (0、1、2) を占有している場合、最初のゲストは部屋 (1) ではなく部屋 (0) になります。 例えば、```
2
1 3
2 1 1
```出力```
0
```グループ (1) の最初の部屋は部屋 (0) であるためです。 

## アプローチ

 直接的なアプローチは、すべてのゲストの現在の部屋を維持し、タイプ 1 の操作のたびにすべての部屋を更新することです。 ゲストが無限に多いのでそれは不可能です。 注意を有限のプレフィックスに限定することはできますが、それでも 1 つの操作が関連するすべての部屋に影響を与える可能性があるため、これはまだ拡張できません。 (300000) 回の演算を使用すると、二次アプローチでは (9\times10^{10}) 回程度の更新を簡単に実行できます。 

最初の重要な観察は、既存のゲストに適用されるすべての操作がアフィン変換であるということです。 有限操作とは、

 [
 x\マップから x+k、
 ]

 一方、無限演算は

 [
 x\マップを 2x にします。 
]

 これらの操作を組み合わせた形式は常に次のとおりです。 

[
 F(x)=ax+b、
 ]

 ここで、(a) は 2 の累乗です。 これにより、すべての古いゲストの動きがコンパクトに説明されます。 

累積変換が完了したときにグループ (g) が挿入されたとします。 

[
 F_g(x)=a_gx+b_g。 
]

 後の操作の前に、それ自体の部屋が等差数列を形成します。 有限群の場合、この進行は次のようになります。 

[
 0,1,\ldots,k-1,
 ]

 したがって、その最初の項は (0) であり、その差は (1) です。 無限群の場合は次のようになります

 [
 1、3、5、\ldots、
 ]

 したがって、その最初の項は (1) であり、その差は (2) です。 

現在の累積変換が (F(x)=ax+b) である場合、(F_g) を代数的に元に戻してから (F) を適用できます。 グループの挿入座標から現在の部屋への変換結果もアフィンになります。 (a_g) は 2 の累乗なので、(10^9+7) の可逆モジュロです。 したがって、タイプ 2 のクエリは、グループごとにいくつかの値を保存した後、一定時間内に応答できます。 

2 番目の重要な観察は、タイプ 3 のクエリを処理します。 クエリされた部屋から逆方向に作業します。 パラメータ (k) を使用した有限演算には逆の規則があります

 [
 x\geq k \Rightarrow x\leftarrow x-k,
 ]

 一方 (x<k) は、その部屋がその操作の新しいグループによって占有されたばかりであることを意味します。 

無限操作の場合、奇数 (x) は、部屋がその無限グループによって新たに占有されたことを意味します。 (x) が偶数の場合、古いゲストは部屋 (x/2) から来たことになります。 

連続する 2 つの無限演算の間の有限演算は 1 つのブロックとして処理できます。 それらのパラメータが (k_1,k_2,\ldots,k_m) である場合、それらのプレフィックスの合計を保存します。 ブロック全体を逆方向に進むと減算のみが行われます。 

[
 k_1+k_2+\cdots+k_m。 
]

 クエリされた (x) がこの合計より小さくなった場合、それを捕捉した正確な有限演算を見つけるために必要な二分探索は 1 回だけです。 

無限演算を通過した後、逆ステップが成功すると、正の (x) が (x/2) に変化します。 したがって、そのようなステップは最大で (O(\log x)) 個存在します。 これが、操作シーケンスに (300,000) 個のイベントを含めることができるにもかかわらず、リバース プロセスが高速である決定的な理由です。 

結果の比較は次のようになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(Q^2)) 最悪の場合 | (O(Q)) またはそれ以上 | 遅すぎる |
 | アフィン表現 + 有限演算ブロック | (O(Q(\log Q+\log V))) | (O(Q)) | 承認済み |

 ここで (V\leq10^9) は、タイプ 3 クエリに表示される部屋番号です。 実際には、(2^{30}>10^9) であるため、逆プロセスからの対数係数は最大でも約 (30) です。 

## アルゴリズムのチュートリアル

 1. 既存のゲストに対するすべての操作の影響をアフィン関数で表現します。 

[
 F(x)=ax+b。 
]

 最初は (a=1、b=0)。 パラメーター (k) を使用した有限演算により、これは次のように変更されます。 

[
 a'=a,\qquad b'=b+k,
 ]

 一方、無限操作では次のように変更されます。 

[
 a'=2a、\qquad b'=2b。 
]

 タイプ 2 の回答には、(b) と (a) のモジュロ (10^9+7) のみが必要です。 

1. グループごとに、そのグループがホテルに入った直後のアフィン変換 (F_g(x)=a_gx+b_g) を保存します。 また、その初期等差数列の開始点(s_g)と差分(d_g)を格納します。 

初期グループ (0) には、次を使用します。 

[
 s_0=0、\qquad d_0=1。 
]

 有限のグループで使用する場合

 [
 s_g=0、\qquad d_g=1。 
]

 無限グループの場合は、

 [
 s_g=1、\qquad d_g=2。 
]

挿入時に変換を保存する理由は、その後のすべての動きをその履歴状態から現在の状態への変換によって説明できるためです。 

1. (a) モジュロ (10^9+7) の逆数を維持します。 (a) は常に 2 の累乗であるため、その逆数が常に存在します。 無限演算で (a) と (2) を乗算する場合、代わりにその逆数に (2^{-1}) を乗算します。 
2. グループ (g) のタイプ 2 クエリに答えるには、次のようにします。 

[
 c=a\cdot a_g^{-1}\pmod M.
 ]

 グループ (g) の過去の座標と現在の座標の間の変換は次のとおりです。 

[
 e=b-cb_g。 
]

 過去の座標 (y) に対応する現在の部屋は次のとおりです。 

[
 サイ+エ。 
]

 グループ (g) の (x) 番目のゲストは歴史的な座標を持っていました

 [
 s_g+d_g(x-1)。 
]

 したがって、現在の部屋は

 [
 e+c(s_g+d_g(x-1))\pmod M.
 ]

 これにより、一定時間内に答えが得られます。 

1. タイプ 3 クエリの場合、すべての有限タイプ 1 操作を無限操作で区切られたブロックに分割します。 最初のブロックには、最初の無限演算の前に有限演算が含まれています。 以降のすべてのブロックには、1 つの無限演算の直後に有限演算が含まれます。 

すべてのブロックについて、その有限 (k) 値と対応するグループ番号の累積和を保存します。 

1. クエリされた部屋が (0) の場合は、最新の有限操作のグループ番号をすぐに返します。有限操作が発生していない場合は (0) を返します。 無限操作では部屋 (0) は変更されないため、その占有者を置き換えることができるのは有限の挿入のみです。 
2. それ以外の場合は、最後の有限ブロックから開始して、その有限演算を逆に実行します。 ブロックの合計 (k) が (x) より大きい場合、責任のある操作はこのブロック内にあります。 累積合計に対して二分探索を使用して、サフィックス合計が (x) より大きい最後の有限演算を見つけます。 

合計が最大 (x) の場合は、ブロック全体の合計を減算し、前の無限演算を実行します。 

1. 無限演算の場合、奇数 (x) は新しく挿入されたグループに属するため、そのグループ番号を返します。 (x) が偶数の場合、(x) を (x/2) に置き換えて、前のブロックを続行します。 
2. 完全な有限ブロックを減算して (x=0) になる場合、答えはそのブロックの前の最新の有限グループになります。 それらはすべて部屋 (0) を変更しないままにするため、連続した無限の操作の潜在的に巨大なシーケンスを実行する必要はありません。 

### なぜ効果があるのか

 タイプ 2 クエリの不変条件は、すべてのグループが、そのグループが入ったときにアクティブだったアフィン変換とともに元の等差数列によって表されることです。 逆履歴変換と現在の変換を合成すると、そのグループの各メンバーが現在どこにいるかを正確に表すことができるため、式は正しい (x) 番目の部屋を返します。 

タイプ 3 クエリの場合、ルーム (0,\ldots,k-1) は正確に新しく挿入されたルームであるのに対し、他のすべてのルームは (x-k) からのものであるため、有限操作の反転は正確です。 奇数の部屋は正確に新しく挿入された部屋であり、すべての偶数の部屋は (x/2) から来たものであるため、無限操作を元に戻すことも正確です。 連続する有限演算をグループ化しても、その逆効果はパラメータを逆順に減算するだけであるため、このロジックは変わりません。 無限操作が正の部屋番号と交差するたびに、部屋番号は半分になるため、そのような交差は対数的に多くのみ可能です。 

## Python ソリューション```python
import sys
from bisect import bisect_left

input = sys.stdin.readline

MOD = 1_000_000_007
INV2 = (MOD + 1) // 2

def solve():
    q = int(input())

    # Current global affine transformation:
    # F(x) = A * x + B
    A = 1
    B = 0
    invA = 1

    # Information stored for every group.
    # Group 0 is the initial infinite set 0,1,2,...
    a_hist = [1]
    b_hist = [0]
    inv_hist = [1]
    start = [0]
    step = [1]

    # Blocks of finite operations.
    # blocks[b] contains cumulative sums of k in block b.
    blocks = [[]]

    # The corresponding group ids for the finite operations.
    block_groups = [[]]

    # For every block, the latest finite group strictly before it.
    prev_finite = [0]

    # Group ids of infinite operations.
    # Infinite operation corresponding to block b (b > 0)
    # is inf_groups[b - 1].
    inf_groups = []

    last_finite_group = 0

    # Number of type 1 operations processed.
    groups = 0

    out = []

    for _ in range(q):
        query = input().split()
        typ = int(query[0])

        if typ == 1:
            k = int(query[1])
            groups += 1
            gid = groups

            if k > 0:
                # All old rooms shift by k.
                B = (B + k) % MOD

                # The new group occupies 0,1,...,k-1.
                a_hist.append(A)
                b_hist.append(B)
                inv_hist.append(invA)
                start.append(0)
                step.append(1)

                if blocks[-1]:
                    cumulative = blocks[-1][-1] + k
                else:
                    cumulative = k

                blocks[-1].append(cumulative)
                block_groups[-1].append(gid)

                last_finite_group = gid

            else:
                # All old rooms double.
                A = (2 * A) % MOD
                B = (2 * B) % MOD
                invA = (invA * INV2) % MOD

                # The new group occupies 1,3,5,...
                a_hist.append(A)
                b_hist.append(B)
                inv_hist.append(invA)
                start.append(1)
                step.append(2)

                inf_groups.append(gid)

                # Start a new finite block.
                blocks.append([])
                block_groups.append([])
                prev_finite.append(last_finite_group)

        elif typ == 2:
            g = int(query[1])
            x = int(query[2])

            c = (A * inv_hist[g]) % MOD
            e = (B - c * b_hist[g]) % MOD

            first = (e + c * start[g]) % MOD
            diff = (c * step[g]) % MOD

            answer = (first + diff * (x - 1)) % MOD
            out.append(str(answer))

        else:
            x = int(query[1])

            # Infinite operations leave room 0 fixed.
            if x == 0:
                out.append(str(last_finite_group))
                continue

            block = len(blocks) - 1

            while True:
                cumulative = blocks[block]

                if cumulative:
                    total = cumulative[-1]

                    if x < total:
                        # Find the first prefix sum >= total - x.
                        # Its corresponding finite operation is exactly
                        # the one whose reverse interval contains x.
                        idx = bisect_left(cumulative, total - x)
                        out.append(str(block_groups[block][idx]))
                        break

                    x -= total

                    if x == 0:
                        # Everything in this block was reversed.
                        # Room 0 now belongs to the latest finite group
                        # before this block.
                        out.append(str(prev_finite[block]))
                        break

                if block == 0:
                    # We have reached the initial configuration.
                    out.append("0")
                    break

                # Cross the infinite operation before this block.
                infinite_group = inf_groups[block - 1]

                if x & 1:
                    # Odd rooms were newly occupied by this group.
                    out.append(str(infinite_group))
                    break

                # An even room came from x / 2.
                x //= 2
                block -= 1

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```の`A`、`B`、 そして`invA`変数は、最新のタイプ 1 操作より前に存在していたすべてのゲストに適用される現在のアフィン変換を記述します。 有限の操作は変化するだけです`B`、一方、無限演算は両方を 2 倍にします。`A`そして`B`。 

4 つの履歴配列には、挿入時に各グループに属する変換と等差数列が格納されます。 初期グループは概念的には時間 0 に挿入されるため、その格納値は (A=1,B=0,s=0,d=1) になります。 

タイプ 2 の式では、現在の乗数とグループ挿入時の乗数の比率が使用されます。 すべての乗数は 2 の累乗であるため、モジュラー除算は安全です。 逆乗数は明示的に更新され、クエリごとにコストのかかる累乗剰余演算を回避します。 

タイプ 3 クエリの場合、`blocks`生の (k) 値ではなく累積合計を保存します。 ブロックに (k_1,k_2,k_3) が含まれ、累積合計が (k_1,k_1+k_2,k_1+k_2+k_3) であるとします。 現在の部屋が合計よりも小さい場合は、`bisect_left`最初に到達するプレフィックス合計を見つけます`total - x`。 このインデックスは、新しく挿入された区間に反転されたルームが含まれる有限演算を識別します。 

厳密な比較`x < total`そして、の使用`total - x`どちらも境界に敏感です。 いつ`x == total`、ブロック内のすべての有限演算はすでに反転されており、先行する無限演算を交差する必要があります。 

Python の整数には任意の精度があるため、有限 (k) 値の累積和がオーバーフローすることはありません。 タイプ 2 の回答に使用される値は (10^9+7) を法として縮小されますが、ブロック合計は (x) との比較に使用されるため正確な整数のままです。

 ## 特殊なケース

 部屋 (0) の場合、アルゴリズムはすぐに戻ります。`last_finite_group`。 考慮する```
4
1 5
1 0
1 0
3 0
```2 つの無限操作により、部屋 (0) は部屋 (0) のままになります。 初期状態の後の唯一の有限挿入はグループ (1) であるため、答えは次のようになります。`1`。 このアルゴリズムは、潜在的に無制限のゼロ半分のシーケンスを実行することはありません。 

正確な有限境界については、次のことを考慮してください。```
3
1 5
3 5
3 4
```有限挿入は部屋 (0、1、2、3、4) を占有します。 部屋 (5) を反転すると、条件 (x\geq5) が使用され、先行 (0) が与えられるため、部屋 (5) はグループ (0) に属します。 部屋 (4) を反転すると、代わりに (x<5) が見つかるため、グループ (1) が返されます。 出力は`0`に続く`1`。 

連続した無限の操作については、次のことを考慮してください。```
4
1 0
1 0
3 2
```最初の無限グループは、最初は (1,3,5,\ldots) を占めます。 2 番目の無限操作は、それらのゲストを (2,6,10,\ldots) に移動します。 部屋を反転する (2) は、まず偶数の部屋を見て、それを 2 で割って (1) を取得します。 前の無限操作では奇数の部屋が表示されるため、答えはグループ (1) になります。 

有限ブロックの場合は、パラメーター (3,5) を考慮してください。 現在の部屋が (4) の場合、(k=5) で最新の操作を逆にすると (4<5) がすぐに見つかるため、2 番目の有限グループが部屋を所有します。 現在の部屋が (5) の場合、逆はまず (5) を減算して (0) に達し、その後前の状態に進みます。 実装における厳密な不平等が、まさにこれら 2 つのケースを区別するものです。 

タイプ 2 のインデックス作成の場合、(k=3) で作成された有限グループは (0) から始まり、差は (1) になります。 その部屋は (0,1,2) であるため、(x=1) の答えは (0)、(x=3) の答えは (2) になります。 この式では (x-1) が使用され、一般的な off-by-one エラーが防止されます。 

最後に、モジュラー算術はタイプ 2 の解答にのみ必要です。 実際の有限ブロックの合計は、リバース シミュレーション中に実際の部屋番号と比較されるため、モジュロ (10^9+7) で削減されません。 これら 2 つの役割を混合すると、累積シフトが係数を超えると、不正確なタイプ 3 の回答が生成されます。
