 ## 解決策
 ## 問題の理解

 各ブリッジは半開区間 ([S_i,E_i)] で表すことができます。 連続する点 (i) と (i+1) の間の小さな円弧がこの間隔内にあるとき、その小さな円弧から橋が見えます。 

入力には (N) 個の重み付けされたブリッジが含まれています。 それらのサブセットを選択することもできますが、基本アークごとに、最大 (k) 個の選択されたブリッジがそれをカバーできます。 すべての美的価値はプラスであるため、課題は、選択した橋の合計価値を最大化することです。 この最大値は (k=1,2,\ldots,N) ごとに必要です。 

幾何学的条件は、最初に見えるよりもはるかに強力です。 2 つの橋セグメントは交差できないため、可視間隔が部分的に重なることはありません。 任意の 2 つの間隔について、それらは互いに素であるか、一方が他方を完全に含んでいます。 この層構造が問題の中心的な性質です。 公式編集者は、間隔を対応する括弧のペアとして見なして解析ツリーを形成することによって、同じ縮小を行っています。 

(N) の値は (250,000) に達する可能性があるため、(O(N^2)) 動的プログラムは最悪の場合でも少なくとも (625) 億の州を検査することになります。 これは、2 秒のコンテスト制限が許容できる範囲をはるかに超えています。 座標範囲は (10^6) に達しますが、すべての座標にわたって配列を構築し、座標ベースの DP を実行する必要があるという意味ではありません。 有用な構造は (N) 個のブリッジ自体によって決定されるため、アルゴリズムは (O(N\log N)) に近づく必要があります。 

誤って処理されやすい境界ケースがいくつかあります。 

単一の橋を考えてみましょう。```
1
1 2 7
```ブリッジは 1 つだけなので、許可されているすべての (k\ge1) がそれを選択します。 答えは```
7
```間隔を半開きではなく閉じたものとして扱う不注意な実装により、エンドポイントで接触するブリッジが誤って重複してしまう可能性があります。 例えば、```
2
1 2 5
2 3 7
```表示される 2 つの間隔は ([1,2)) と ([2,3)) であるため、互いに素です。 (k=1) の場合でも両方のブリッジを選択できます。```
12 12
```もう 1 つの重要なケースは、ネストされた間隔のチェーンです。```
3
1 6 10
2 5 20
3 4 30
```(k=1) の場合、値 (30) のブリッジのみを選択できます。 (k=2) の場合は内側の 2 つのブリッジを選択でき、(k=3) の場合は 3 つすべてを選択できます。 正しい出力は次のとおりです```
30 50 60
```単純に最良 (k) 値をグローバルに取得するソリューションは、ネスト制約がブリッジが重なる場所に依存するため、失敗します。 

最後に、間隔は同じ左端点を持つことができます。 例えば、```
3
1 5 10
1 4 20
2 3 30
```正しい収容順序は、([1,5)) を含む ([1,4)) を含む ([2,3)] です。 左側のエンドポイントだけで並べ替えるだけでは、その順序を回復するのに十分ではありません。 左側のエンドポイントが等しい場合、長い間隔が最初に来る必要があります。 

## アプローチ

 直接ツリー DP は当然の最初の試みです。 間隔が包含ツリーに変換されたら、すべてのルートから子孫へのパスに含まれる選択された頂点が最大 (k) 個である場合に、(u) のサブツリーから取得できる最大値として (F_u(k)) を定義します。 すべてのノードとすべての (k) について、(u) 自体が選択されているかどうかを考慮してこの値を計算できます。 

すべての実行可能な選択にはこれら 2 つの可能性のうちの 1 つが含まれるため、この DP は正しいです。 (u) が選択されていない場合、すべての子サブツリーには依然として容量 (k) があります。 (u) が選択された場合、その内部の間隔ごとに 1 単位の容量が消費されるため、すべての子は容量 (k-1) を受け取ります。 問題は州の数です。 可能なペア ((u,k)) は (O(N^2)) 個あり、子の結合に必要な作業を考慮する前に、(N=250,000) の場合に少なくとも (625) 億の状態が得られます。 

ブルートフォース DP が機能するのは、コンテインメント ツリーがブリッジ間のすべての対話をキャプチャするためです。 たとえ連続 (k) の値が強力な構造を持っていたとしても、同じ情報を (k) ごとに別々に保存するため、この処理は失敗します。 

重要な観察は、(k) の関数としての各サブツリーの DP の限界利得が減少していることです。 定義する

 [
 D_u(k)=F_u(k)-F_u(k-1)。 
】

 これらの差は拡大しません。 したがって、すべての DP 値を保存する代わりに、その限界ゲインのマルチセットによって関数全体 (F_u) を表すことができます。 

(u) の子に限界シーケンス (A、B、\ldots) があるとします。 それらの間隔は互いに素であるため、すべての子は同じ (k) レイヤーを独立して使用できます。 2人の子供の限界利益が

 [
 a_1\ge a_2\ge\cdots
 】

 そして

 [
 b_1\ge b_2\ge\cdots、
 】

 この場合、結合されたサブツリーにはわずかな利益が得られます

 [
 a_1+b_1、\ a_2+b_2、\ldots。 
】

 すべての子を結合した後、値 (w_u) を持つブリッジ (u) 自体を検討します。 これを選択すると 1 つのレイヤーが消費されるため、結果として得られる DP は、ソートされたマージナル シーケンスに 1 つの追加のマージナル ゲイン (w_u) を挿入することと同じになります。 

これは、公式のソリューションで説明されている構造とまったく同じです。子関数は、ソートされた導関数をペアごとに加算することによって結合され、ノードを追加することは、その重みをその導関数セットに挿入することに対応します。 

最大ヒープには限界利益が保存されます。 2 つの子ヒープを結合するには、最大の要素を繰り返し削除し、これら 2 つの値を加算し、結果の値を親ヒープに置きます。 私たちは常に小さいヒープを大きいヒープにマージします。 これは、小規模から大規模への標準的な手法であり、公式の分析では、ヒープ プロセス全体の限界 (O(N\log N)) が得られます。 

最終的な仮想ルートの値は 0 で、すべてのブリッジが含まれます。 そのヒープは、(k) を増やすことによって得られる限界の改善を表します。 残りの最大の限界利益を繰り返し取得し、それを蓄積します。 ヒープが空になると、答えはすでに最大値に達しており、それより大きいすべての (k) については変化しません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ナイーブツリーDP | (O(N^2)) | (O(N^2)) または (O(N)) (再計算あり) | 遅すぎる |
 | 最適なヒープ DP | (O(N\log N)) | (O(N)) 個のアクティブなヒープ エントリとツリー | 承認済み |

 ## アルゴリズムのチュートリアル

1. すべての橋を可視間隔 ([S_i,E_i)] で表します。 橋は決して交差しないため、そのような 2 つの間隔は互いに素になっているか、入れ子になっています。 これにより、幾何学的な問題が層間隔の問題に変わります。 
2. 座標範囲全体を含む仮想間隔を追加し、値 0 を与えます。 この仮想ノードがルートとなり、複数のトップレベルの独立したブリッジが 1 つのツリー内に共存できるようになります。 
3. 左端点を増加させて実際の間隔を並べ替え、右端点を減少させることで同点を解消します。 これは封じ込めツリーの予約注文です。 左の端点が等しい場合、それが祖先であるため、より大きい間隔が最初に表示される必要があります。 
4. ソートされた間隔をスタックでスキャンします。 スタックには、仮想ルートから最後に処理された間隔までの現在のパスが含まれています。 新しい間隔 ([S,E)) の場合、右端が (E) より小さい間隔をポップします。 一番上に残っている間隔は、新しい間隔を含む最小の間隔であるため、新しい間隔の親になります。 
5. ツリーをボトムアップで処理します。 すべてのノード (u) について、その DP 関数の限界ゲインを含む最大ヒープを維持します。 リーフは単一の値 (w_u) で始まります。 
6. 内部ノードの場合は、まずそのすべての子のヒープを結合します。 2 つのヒープに限界シーケンス (A) と (B) が含まれている場合は、それらの最大の要素をペアごとに削除し、それらの合計を挿入します。 両方の独立したサブツリーが同じ容量 (k) を受け取るため、これにより (F_A(k)+F_B(k)) の周辺シーケンスが計算されます。 
7. 常に大きい方のヒープを宛先ヒープとして使用します。 現在のヒープにある要素が別の子のヒープよりも少ない場合は、マージする前に要素を交換します。 小さいヒープからの要素のみを削除する必要があるため、小さいものから大きいものまでの境界が与えられます。 
8. すべての子を結合した後、(w_u) をヒープに挿入します。 これは、(u) を選択するという選択を表します。これは、追加のネスト レベルを 1 つ消費し、対応する限界ゲインに正確に (w_u) を与えます。 
9. 仮想ルートで、最大の限界ゲインを繰り返し削除します。 それを実行中の答えに追加し、(k) の次の値についてその実行中の答えを出力します。 ヒープが空の場合は、これ以上ブリッジを行っても解決策を改善できないため、同じ回答を出力し続けます。 

これが機能する理由: すべてのノード (u) について、ヒープ不変条件は、その要素がまさに限界ゲイン (F_u(k)-F_u(k-1)) であり、非増加順に配置されているということです。 独立した子サブツリーは DP 関数を追加するため、その周辺ゲインは位置ごとに追加されます。 (u) を追加すること自体により、DP が (G(k)) から (\max(G(k),w_u+G(k-1))) に変更されます。これは、まさに (G) のソートされた限界ゲインに (w_u) を挿入する操作です。 したがって、不変式は葉から根まで帰納的に保持されます。 ルートでは、最大 (k) の限界ゲインを取得すると、(F_{\text{root}}(k)) が得られます。これは、正確に、容量 (k) の下での最大合計美的価値です。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve(stream=None):
    if stream is None:
        stream = sys.stdin

    read = stream.readline
    n = int(read())

    intervals = []
    for _ in range(n):
        s, e, w = map(int, read().split())
        intervals.append((s, e, w))

    # Increasing left endpoint, decreasing right endpoint.
    intervals.sort(key=lambda x: (x[0], -x[1]))

    # Node 0 is the virtual root.
    # Its interval contains every real interval and its value is zero.
    end = [1_000_001] + [0] * n
    weight = [0] * (n + 1)

    parent = [0] * (n + 1)

    # Children are stored as linked lists to avoid creating
    # N separate Python list objects.
    head = [-1] * (n + 1)
    nxt = [-1] * (n + 1)

    stack = [0]

    for u, (s, e, w) in enumerate(intervals, 1):
        end[u] = e
        weight[u] = w

        # Since left endpoints are processed increasingly,
        # containment is determined by the right endpoint here.
        while e > end[stack[-1]]:
            stack.pop()

        p = stack[-1]
        parent[u] = p

        nxt[u] = head[p]
        head[p] = u

        stack.append(u)

    # Each heap stores negative marginal gains, so heapq acts
    # as a max-heap on the original positive values.
    heaps = [None] * (n + 1)

    # Parent IDs are always smaller than child IDs because the
    # intervals were processed in preorder.
    for u in range(n, -1, -1):
        h = None
        child = head[u]

        while child != -1:
            other = heaps[child]

            if h is None:
                h = other
            else:
                # Always merge the smaller heap into the larger heap.
                if len(other) > len(h):
                    h, other = other, h

                m = len(other)

                # Pair the largest marginal gains.
                merged = [
                    heapq.heappop(h) + heapq.heappop(other)
                    for _ in range(m)
                ]

                # Rebuild once instead of performing m separate pushes.
                h.extend(merged)
                heapq.heapify(h)

            # The child heap has now been completely consumed.
            heaps[child] = None
            child = nxt[child]

        if h is None:
            h = []

        # Selecting u contributes one new marginal gain w[u].
        heapq.heappush(h, -weight[u])
        heaps[u] = h

    # Extract marginal gains from the virtual root.
    h = heaps[0]
    answer = 0
    result = []

    for _ in range(n):
        if h:
            answer -= heapq.heappop(h)
        result.append(str(answer))

    return " ".join(result)

if __name__ == "__main__":
    sys.stdout.write(solve() + "\n")
```入力間隔は、ツリーが構築される前にソートされます。 タイブレーカーは、`-x[1]`したがって、2 つのブリッジが同じポイントで開始する場合、大きい間隔が最初に処理され、小さい間隔の祖先になる可能性があります。 

スタック条件は次を使用します`e > end[stack[-1]]`、 ない`>=`。 右側の端点を共有しながら、1 つの間隔に別の間隔を含めることができるため、等しい右側の端点が許可されます。 可視性の間隔は半分開いているため、ある点で終了するブリッジとその同じ点で始まるブリッジは互いに素であり、これは前の間隔がポップされた後にスタックによって自然に処理されます。 

ツリーは次を使用して保存されます`head`そして`nxt`すべてのノードのリストの代わりに。 これにより、(N) が大きい場合、Python オブジェクトのオーバーヘッドが大幅に削減されます。 ソートされた間隔は事前順序を形成するため、すべての親のノード インデックスはすべての子孫よりも小さいため、ボトムアップ DP には逆数値走査で十分であり、再帰の深さの問題が回避されます。 

ヒープには負の値が格納されます。`heapq`最小ヒープです。 したがって、元の限界ゲインの最大値が保存された最小値になります。 子のマージ中に、最大の要素が両方のヒープから削除され、その負の表現が追加されます。 元のゲインが (a) と (b) である場合、格納される値は (-a) と (-b) で、それらの合計は (-(a+b)) となり、まさにマージされたヒープが必要とする値となります。 

の`merged`リストが最初に構築され、次に宛先ヒープに追加され、その後にリストが追加されます。`heapify`。 繰り返し電話をかける`heappush`新しく結合された値ごとに不必要な対数作業が実行されます。 Python の整数には任意の精度があるため、合計の美的価値は (250,000\cdot10^9=2.5\cdot10^{14}) に達する可能性がありますが、特別なオーバーフロー処理は必要ありません。 

最後の抽出は、ヒープが空になった後も意図的に続行されます。 限界ゲインが欠けているということは、(k) をさらに増やしても答えを改善できないことを意味するため、累計は単に変更されないままになります。

# All 250000 intervals are pairwise disjoint and have value 1,
# so every answer is exactly 250000.
n = 250000
stress_input = str(n) + "\n" + "".join(
    f"{2 * i - 1} {2 * i} 1\n" for i in range(1, n + 1)
)
expected = " ".join(["250000"] * n)

assert run(stress_input) == expected, "maximum-size disjoint input"

 ## 特殊なケース

 単一ブリッジの場合は、その値を含むリーフ ヒープを作成することで処理されます。 のために```
1
1 2 7
```ブリッジヒープは`[7]`の場合、仮想ルートはそのヒープを他の子と結合せず、独自のゼロを挿入します。 最初の抽出では (7) が追加され、必要な出力が得られます。`7`。 

タッチ間隔については、```
2
1 2 5
2 3 7
```最初のブリッジは ([1,2)) に対応し、2 番目のブリッジは ([2,3)) に対応します。 2 番目の間隔が処理されると、最初の間隔にはそれが含まれなくなるため、スタックは仮想ルートに戻ります。 彼らは兄弟になります。 それらの 1 要素の限界ヒープは (5+7=12) として結合され、単一の正の限界ゲイン (12) が得られます。 出力は`12 12`。 間隔を閉じたものとして扱うと、これらのブリッジが (k=1) について誤って競合します。 

ネストされたチェーンの場合、```
3
1 6 10
2 5 20
3 4 30
```木は道です。 最も内側のブリッジはマージナルシーケンスから始まります`[30]`。 その親インサート (20) は、`[30,20]`、およびアウターブリッジインサート (10) により、`[30,20,10]`。 ルートはゼロを加えます。 これらのゲインを抽出すると、`30`、 それから`50`、 それから`60`。 許容されるオーバーラップ単位が追加されるたびに、チェーン内のブリッジをもう 1 つ選択できるため、これはまさに最適です。 

左端点が等しい場合、```
3
1 5 10
1 4 20
2 3 30
```並べ替え`(left, -right)`([1,5)) を ([1,4)) の前に配置します。 その結果、スタックは封じ込めチェーンを正確に識別します。 同点ブレークが逆転した場合、([1,4)) はその真の祖先と無関係であると誤って扱われる可能性があります。 結果として得られる限界数列は次のようになります。`[30,20,10]`、与える`30 50 60`。 

最大サイズの非結合の場合、すべてのブリッジは仮想ルートの個別の子になります。 各子は (1) の 1 つの限界利益に貢献します。 子は互いに素であるため、それらの値は単一の限界ゲイン (250000) に結合されます。 (k) を増やしてもメリットはないので、(250,000) 個の答えはすべて次のようになります。`250000`。 このケースでは、小規模から大規模のヒープへのマージも実行され、実装が (N) に近い座標範囲に依存しないことが確認されています。 

同様の問題を引き起こす中心的なアイデアは、限界ゲイン表現です。層流制約がツリーになると、k 次元 DP 全体が、サブツリーごとに 1 つの順序付けられたゲインの集合に折りたたまれます。
