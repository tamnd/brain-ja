 ## 解決策
 ## 問題の理解

 同じ頂点セット上に 2 つの重み付きツリーがあり、頂点ラベル (1) ～ (N) が付いています。 2 つのラベル (i) と (j) については、それらの距離はどちらのツリー単独でも測定されません。 代わりに、最初のツリー内のそれらの間のパスの長さを、2 番目のツリー内のそれらの間のパスの長さに加算します。 すべての頂点 (i) について、他のすべての頂点 (j) に対する最小の合計が必要です。 

2 つのツリーは、まったく異なる形状とエッジの重みを持つことができます。 最初のツリーで (i) に近い頂点が 2 番目のツリーでは非常に遠くにある可能性があるため、どちらのツリーでも最も近い頂点を個別に見つけても役に立ちません。 答えは、2 つのツリーの積メトリックの最近傍クエリです。 

最大のインスタンスには (250,000) 個の頂点があり、各ツリーには (249,999) 個のエッジがあります。 二次アルゴリズムは、最悪の場合、約 (N(N-1)/2)、およそ (31) 億の頂点ペアを検査します。 これは、12 秒間のコンテストの解決策の実用的な範囲をはるかに超えています。 公式の問題制限は 12 秒および 1024 MiB であるため、(O(N\log^2N)) 方法が適切です。 

また、重要な数値的な詳細が 2 つあります。 個々のツリーの距離はおよそ (2.5\cdot10^{14}) に達する可能性があるため、結合された距離には C++ での 64 ビット演算が必要です。 Python の整数はこれを自動的に処理します。 また、(j=i) は決して使用してはなりません。 その距離はゼロであるため、誤って許可すると、すべての答えが即座にゼロになります。 

可能な限り最小のツリーを考えてみましょう。```
2
1 2 1000000000
1 2 1000000000
```他の頂点として使用できるのはもう一方の端点のみであるため、正しい出力は次のようになります。```
2000000000
2000000000
```クエリされた頂点自体を含む実装では、誤ってゼロが出力されます。 

2 番目の便利なエッジ ケースは、両方のツリーが同じ単純な形状を持ち、すべての重みが等しい場合です。```
3
1 2 1
2 3 1
1 2 1
2 3 1
```すべての頂点には結合距離 (2) の位置に別の頂点があるため、答えは次のようになります。```
2
2
2
```これにより、1 つのツリー内の距離と必要な両方の距離の合計を混同する実装が捕捉されます。 

最後に、木は似たような形状である必要はまったくありません。 例えば、```
3
1 2 1
2 3 100
1 2 100
2 3 1
```は、隣接するペア間の距離 (101) と頂点 (1) と (3) 間の距離 (202) を組み合わせたものです。 正しい出力は次のとおりです```
101
101
101
```これは、最初のツリーのジオメトリを 2 番目のツリーで誤って再利用することを防止するのに役立ちます。 

## アプローチ

 直接的な解決策は簡単です。 両方のツリー内のすべてのペア (i,j) 間の距離を計算し、すべての (i) の合計を最小化します。 ツリーには固有のパスがあるため、各ツリーをルート化し、1 つのソースからのすべての距離を線形時間で取得できますが、すべてのソースからそれを行うには依然として (O(N^2)) のコストがかかります。 同様に、すべてのペアを明示的に考慮すると (N(N-1)/2) 個の比較が実行され、(N=250,000) の場合、約 (312 億 5) 億ペアに達します。 

ブルートフォースは、最小化される量を直接評価するため、正しいです。 その失敗は完全に計算によるものです。 ツリー内の距離はセパレータを中心に分解できるという事実を利用する必要があります。 

便利なセパレータは重心分解です。 重心を削除すると、ツリーは現在のコンポーネントの最大半分のサイズのコンポーネントに分割されます。 これを繰り返すと、対数的な高さの重心ツリーが生成されます。 この標準のバランス プロパティは、まさに、任意の頂点のペアを重心の祖先のペアに置き換えることを可能にするものです。 

(T_1) と (T_2) に対して独立して重心分解を構築します。 頂点 (i) と (j) について、(L_1) を (T_1) の重心ツリー内の最も低い共通祖先とし、(L_2) を (T_2) の重心ツリー内の最も低い共通祖先とします。 ちなみに、重心分解により成分が分離されると、(T_1) の (i) と (j) 間の元のパスは (L_1) を通過し、同様に (T_2) のパスは (L_2) を通過します。 したがって、

 [d_1(L_1,i)+d_2(L_2,i)]
 +
 [d_1(L_1,j)+d_2(L_2,j)]。 
】

 これが重要な代数変換です。 (L_1,L_2) が固定されると、(i) と (j) の寄与は完全に分離します。 

(L_1) と (L_2) は正確に 2 つの重心ツリー LCA でなければならないという厄介な条件がまだあります。 その状態を取り除くことができます。 固定 (i,L_1,L_2) の場合、最初の重心ツリーでは単に (L_1) の子孫であり、2 番目の重心ツリーでは (L_2) の子孫であるすべての頂点 (j) を考慮します。 このセットは、まさにこれら 2 つの LCA を含むセットよりも大きくなります。 

そのような (j) については、

 [
 d_1(L_1,i)+d_1(L_1,j)\ge d_1(i,j)
 】

 そして

 [
 d_2(L_2,i)+d_2(L_2,j)\ge d_2(i,j)
 】

 三角不等式によって。 したがって、緩和された候補が実際の距離よりも小さくなることはありません。 一方、真の最も近い頂点 (j) は、ある正確なペア (L_1,L_2) を持ち、そのペアは緩和ケースに含まれます。 したがって、すべての緩和ケースで最小値を取得しても、正確な答えが得られます。 

2 番目の分解の固定重心 (L_2) の場合、その重心サブツリー内のすべての頂点を訪問できます。 このような頂点 (v) ごとに、最初の分解で (v) のすべての重心祖先 (L_1) を列挙します。 固定 (L_1) の場合、次のように挿入します。 

[
 d_1(L_1,v)+d_2(L_2,v)
 】

 2要素の最小構造にします。 頂点 (v) をクエリする場合、最小値は (v) 自体から得られる可能性があるため、スキップする必要があるため、最小値と 2 番目に小さい値のみが必要です。 

いずれの分解でも、すべての頂点には (O(\log N)) 個の重心祖先しかありません。 したがって、ネストされた列挙には (O(N\log^2N)) 個の組み合わせが含まれます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(N^2)) | (O(N)) | 遅すぎる |
 | 最適 | (O(N\log^2N)) | (O(N\log N)) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 最初のツリーの重心分解を構築します。 重心 (c) が選択されるたびに、その現在のコンポーネントをトラバースし、そのコンポーネント内のすべての頂点 (v) について (d_1(c,v)) を記録します。 (c) は重心ツリー内のすべての頂点の祖先になるため、すべての頂点にその重心祖先のリストと元のツリーの距離が与えられます。 
2. 2 番目のツリーの重心分解も構築しますが、その距離リストを保存する必要はありません。 後の処理中に、重心 (c) が選択されるたびに、その現在のコンポーネントをトラバースして、すべての子孫 (v) の (d_2(c,v)) を直接取得できます。 
3. すべての答えを無限大に初期化します。 2 番目のツリーの重心 (c=L_2) を処理する場合、その現在のコンポーネントは正確に 2 番目の重心ツリーの (c) のサブツリーになります。 したがって、このコンポーネントで訪問されるすべての頂点は、祖先である緩和条件 (L_2) の有効な候補になります。 
4. 訪問した頂点 (v) ごとに、最初のツリーからその保存されている重心の祖先 ((L_1,d_1(L_1,v))) を反復処理します。 それぞれ (L_1) について、計算します。 
[
 x=d_1(L_1,v)+d_2(c,v)。 
】
 各値を生成する頂点とともに、(L_1) ごとに (x) の 2 つの最小値を維持します。 
5. 現在の 2 番目のツリー コンポーネント内のすべての頂点が挿入されたら、それらの頂点を再度繰り返します。 すべての頂点 (v) およびすべての最初のツリーの祖先 (L_1) について、(v) 以外の頂点に属する最小の格納値を取得します。 最小値が (v) によって生成された場合は、代わりに 2 番目に小さい値を使用します。 
6. (v) 自体の値を追加します。 
[
 d_1(L_1,v)+d_2(c,v)+
 \min_{j\ne v}
 [d_1(L_1,j)+d_2(c,j)]。 
】
 (v) の全体的な回答をこの候補で更新します。 これはまさに上記で導出されたリラックスした表現です。 
7. 現在の 2 番目のツリーの重心を削除済みとしてマークし、残りのすべてのコンポーネントを独立して続行します。 すべてのコンポーネントのサイズは最大でも以前の半分であるため、すべての頂点は (O(\log N)) 個の重心レベルにのみ関与します。 
8. 各頂点の結果の最小値を出力します。 自己ペアは、最初の最小値がクエリされた頂点に属する場合は必ず 2 番目の最小値を選択することによって除外されます。 

### なぜ効果があるのか

 2 つの頂点 (i\ne j) を固定し、(L_1,L_2) を 2 つの重心分解における最も低い共通の祖先とします。 これらの重心は (i) と (j) を分離しているため、元のツリーのパスはそれぞれの重心を通過します。 したがって、それらの真の結合距離は次のようになります。 

[
 d_1(L_1,i)+d_2(L_2,i)+d_1(L_1,j)+d_2(L_2,j)。 
】

 両方とも (i) の祖先であり、(j) は両方の対応する重心サブツリーに存在するため、アルゴリズムはこの正確な祖先のペアを考慮します。 したがって、真の最適値は考慮された候補の中にあります。 

リラックスした候補者は全員フォームを持っています

 [
 d_1(L_1,i)+d_1(L_1,j)+d_2(L_2,i)+d_2(L_2,j)。 
】

 各ツリーの三角不等式により、これは少なくとも (d_1(i,j)+d_2(i,j)) になります。 したがって、アルゴリズムは実際の最適値を下回る値を生成することはできません。 実際の最適なペアも考慮されるため、アルゴリズムによって生成される最小値がまさに必要な答えとなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**30

def get_component_centroid(adj, root, removed, parent, size):
    nodes = []
    stack = [root]
    parent[root] = -1

    while stack:
        u = stack.pop()
        nodes.append(u)
        pu = parent[u]

        for v, _ in adj[u]:
            if removed[v] or v == pu:
                continue
            parent[v] = u
            stack.append(v)

    for u in reversed(nodes):
        s = 1
        for v, _ in adj[u]:
            if removed[v]:
                continue
            if parent[v] == u:
                s += size[v]
        size[u] = s

    total = len(nodes)
    centroid = nodes[0]
    best_balance = total + 1

    for u in nodes:
        largest = total - size[u]

        for v, _ in adj[u]:
            if removed[v]:
                continue
            if parent[v] == u and size[v] > largest:
                largest = size[v]

        if largest < best_balance:
            best_balance = largest
            centroid = u

    return nodes, centroid

def build_ancestors(adj, n):
    removed = bytearray(n)
    parent = [-1] * n
    size = [0] * n
    ancestors = [[] for _ in range(n)]

    tasks = [0]

    while tasks:
        root = tasks.pop()

        _, centroid = get_component_centroid(
            adj, root, removed, parent, size
        )

        stack = [(centroid, -1, 0)]

        while stack:
            u, p, d = stack.pop()
            ancestors[u].append((centroid, d))

            for v, w in adj[u]:
                if removed[v] or v == p:
                    continue
                stack.append((v, u, d + w))

        removed[centroid] = 1

        for v, _ in adj[centroid]:
            if not removed[v]:
                tasks.append(v)

    return ancestors

def solve():
    input = sys.stdin.readline
    n = int(input())

    adj1 = [[] for _ in range(n)]
    adj2 = [[] for _ in range(n)]

    for _ in range(n - 1):
        u, v, w = map(int, input().split())
        u -= 1
        v -= 1
        adj1[u].append((v, w))
        adj1[v].append((u, w))

    for _ in range(n - 1):
        u, v, w = map(int, input().split())
        u -= 1
        v -= 1
        adj2[u].append((v, w))
        adj2[v].append((u, w))

    ancestors = build_ancestors(adj1, n)

    removed = bytearray(n)
    parent = [-1] * n
    size = [0] * n

    best1 = [INF] * n
    best2 = [INF] * n
    id1 = [-1] * n
    id2 = [-1] * n
    seen = [0] * n
    token = 0

    ans = [INF] * n
    tasks = [0]

    while tasks:
        root = tasks.pop()

        _, centroid = get_component_centroid(
            adj2, root, removed, parent, size
        )

        nodes_dist = []
        stack = [(centroid, -1, 0)]

        while stack:
            u, p, d = stack.pop()
            nodes_dist.append((u, d))

            for v, w in adj2[u]:
                if removed[v] or v == p:
                    continue
                stack.append((v, u, d + w))

        token += 1

        for v, d2 in nodes_dist:
            for a, d1 in ancestors[v]:
                if seen[a] != token:
                    seen[a] = token
                    best1[a] = INF
                    best2[a] = INF
                    id1[a] = -1
                    id2[a] = -1

                value = d1 + d2

                if value < best1[a]:
                    best2[a] = best1[a]
                    id2[a] = id1[a]
                    best1[a] = value
                    id1[a] = v
                elif value < best2[a]:
                    best2[a] = value
                    id2[a] = v

        for v, d2 in nodes_dist:
            for a, d1 in ancestors[v]:
                if id1[a] == v:
                    other = best2[a]
                else:
                    other = best1[a]

                if other < INF:
                    candidate = d1 + d2 + other
                    if candidate < ans[v]:
                        ans[v] = candidate

        removed[centroid] = 1

        for v, _ in adj2[centroid]:
            if not removed[v]:
                tasks.append(v)

    sys.stdout.write("\n".join(map(str, ans)))

if __name__ == "__main__":
    solve()
```最初の助っ人は、`get_component_centroid`、完全に反復的な走査を実行します。 これにより、(250,000) 頂点を含むパスでの Python 再帰の深さの問題が回避されます。 まず現在のコンポーネントと親の関係を記録し、次にサブツリーのサイズを逆の順序で計算し、最後に残りの最大部分ができるだけ小さい頂点を選択します。`build_ancestors`最初の重心分解を構築します。 元の重み付けされたエッジは決して変更されません。 トラバーサルでは、重心ごとに、その重心から現在のコンポーネント内のすべての頂点までの実際の重み付けされた距離が記録されます。 これはまさに後で必要となる情報であるため、重心ツリー自体を明示的に構築する必要はありません。 

2 番目の分解は、最初の分解が保存された後に処理されます。 各 2 番目の木の重心について、`nodes_dist`その重心サブツリー内のすべての頂点と重心までの距離が含まれます。 このような各頂点は、その最初のツリーの重心の祖先をすべてすでに知っているため、2 つのリストを反復することで、必要な ((L_1,L_2,v)) の組み合わせをすべて列挙します。 

4 つのアレイ`best1`、`best2`、`id1`、 そして`id2`は、それぞれの 2 つの最小値 (L_1) を表します。 の`seen`array は遅延クリアを提供します。 セントロイドが処理されるたびにすべての (N) 個のエントリをリセットするのではなく、そのコンポーネントで実際に検出される (L_1) 個の値のみが初期化されます。 

現在の頂点の厳密な除外は、保存されている頂点 ID によって処理されます。 もし`id1[a] == v`、最小の候補は自己ペアであり、`best2[a]`を使用する必要があります。 最初の候補が別の頂点に属している場合、それはすぐに有効になります。 

すべての算術演算は Python 整数を使用して実行されます。 C++ では、対応する実装が必要です。`long long`2 つの木の距離の合計が (2^{31}-1) を超える可能性があるためです。

 たとえば、頂点 (3) は頂点 (8) に最も近くなります。 (3) から (8) までの最初のツリーのパスのコストは (4268+4810=9078)、2 番目のツリーのエッジのコストは (504) なので、(9582) になります。 分解では、これらのパスに対応する重心と祖先のペアが検出され、そのペアに保存されている最小値が正確にこの値を回復します。

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(N\log^2N)) | 各頂点には、各重心分解に (O(\log N)) 個の祖先があり、第 2 ツリー重心レベルごとに、対応する祖先の組み合わせが処理されます。 |
 | スペース | (O(N\log N)) | 最初の分解では、すべての頂点とすべての最初のツリーの重心祖先ごとに 1 つの距離が保存されます。 2 つの元のツリーと作業配列には、(O(N)) 個の追加スペースが必要です。 |

(N=250,000) の場合、これは問題の 12 秒および 1024 MiB の制限によって必要とされる漸近範囲です。 Python 実装では反復トラバーサルが使用されます。そうしないと、長いツリーでの再帰的 DFS が Python の再帰制限を超えてしまうからです。

 ## 特殊なケース

 (N=2) の場合、有効なペアは 1 つだけです。 のために```
2
1 2 1000000000
1 2 1000000000
```最初の重心分解では、距離 (0) と (10^9) にある 2 つの頂点が保存され、2 番目の分解でも同じことが行われます。 いずれかの頂点を処理する場合、最初の最小値は頂点自体に属するため、アルゴリズムは 2 番目の最小値を選択します。 結果の値は (10^9+10^9=2,000,000,000) となります。 

自己ペアの問題は、重心サブツリーに特定の祖先ペアの頂点が 1 つしか含まれていない場合に特に顕著です。 この場合、2 つの最小構造には有限の値が 1 つだけ含まれます。 実装では次のことがチェックされます。`INF`したがって、存在しない 2 番目の頂点が偽の候補になることはありません。 

等距離も正しく処理されます。 4 つの頂点からなるユニット スターでは、他のいくつかの頂点の結合距離がまったく同じになります。 2 つの最小構造では、値に加えて頂点 ID も格納されるため、個別の頂点からの関連付けられた値は個別の候補のままになります。 すべての頂点について、少なくとも 1 つの他の頂点が値 (2) を持ち、(2) に等しい 4 つの答えが得られます。 

エッジの重みが大きい場合は、分解自体には影響しません。 重心の選択はコンポーネントのサイズのみに依存しますが、重心からの距離を計算する場合、実際のエッジの重みは変更されません。 構造分解と計量計算が相互に干渉しないため、この分離は役立ちます。 

(250,000) 頂点のパスは、通常の深さが (250,000) であるため、Python の再帰 DFS にとって最悪の形状です。 この実装では、コンポーネントの走査、重心距離の走査、分解タスクに明示的なスタックを使用するため、この敵対的な形状でも Python 呼び出しスタックの深さは一定のままです。 

2 つのツリーが完全に無関係なトポロジを持つ場合もあります。 このアルゴリズムは、一方のツリーの重心が、もう一方のツリーの同じラベルを持つ重心に対応するとは決して想定しません。 (L_1) と (L_2) は独立して選択されますが、ラベルを使用して 2 つのツリー全体で同じ点を識別するだけです。 この独立性により、この方法は重み付きツリーの任意のペアに対して機能します。
