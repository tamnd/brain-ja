 ## 解決策
 ## 問題の理解

 関節点と頂点次数に関連付けられた非常に特殊な構造的制約を使用して、1 から n までラベル付けされた頂点上に無向の単純な接続グラフを構築するように求められます。 

1 と n を除くすべての頂点に対して、バイナリ インジケーターが与えられます。 位置 i の値が 1 の場合、頂点 i は最終グラフの関節点でなければなりません。つまり、頂点 i を削除するとグラフが切断されます。 0 の場合、アーティキュレーション ポイントであってはなりません。 頂点 1 は強制的にアーティキュレーション ポイントになり、頂点 n は他に関係なく強制的にアーティキュレーション ポイントではなくなります。 

その構造要件に加えて、グラフは次数に関するグローバルな順序付け制約を満たす必要があります。つまり、頂点がラベルによって並べ替えられるとき、その次数は増加しない必要があるため、次数 1 は次数 2 以上、次数 3 以上、というようになります。 

出力は、これらの条件をすべて満たすグラフ、またはそれが不可能な場合は -1 です。 

この制約により、すべてのテスト ケースにわたって合計頂点の数が 2000 まで許可されます。これは、テスト ケースごとに O(n) または O(n log n) の構築が期待されることを示唆しています。 グラフを大量に検索したり、接続を動的にチェックしたりすると、速度が遅すぎます。 

主な問題点は、アーティキュレーション ポイントがローカルなプロパティではなく、グラフのグローバルなプロパティであることです。 単純な構造では、意図しないカット頂点が簡単に生成されたり、必要な頂点が欠落したりする可能性があります。 

いくつかの失敗パターンがすぐに現れます。 

2 から n-1 までのすべての頂点がアーティキュレーション ポイントである必要がある場合、n を除くすべての頂点はカット頂点でなければなりません。 接続されたグラフでは、これにより少なくとも 2 つの葉が強制されますが、頂点 n だけが唯一の葉になることはできないため、答えは不可能です。 

もう 1 つの微妙な失敗は、アーティキュレーションの要件と次数の順序を混合することによって発生します。 インデックスの小さい頂点が低い次数を持つように強制され、後の頂点がより高い次数を持つように強制される場合、接続性に関係なく、単調な次数の制約に違反します。 

これらの相互作用は、問題が任意のグラフに関するものではなく、調音動作が予測可能な高度に構造化されたファミリーに関するものであることを示唆しています。 

## アプローチ

 強引なアイデアとしては、考えられるすべてのツリーまたはグラフを構築して、各頂点がその関節要件と一致するかどうかを確認してみるというものがあります。 木に限定しても、ラベル付き木の数は n の n 乗マイナス 2 に応じて増加するため、これはまったく実行不可能です。 

重要な単純化は、アーティキュレーション ポイントがツリー内で制御しやすいことに気づくことです。 どのツリーでも、葉以外のすべての頂点は関節点ですが、すべての葉は関節点ではありません。 これは直訳すると、内部頂点のセットが関節点でなければならない頂点と正確に一致するツリーを設計するだけで済みます。 

したがって、問題はツリー構築の問題になります。どの頂点が葉でどの頂点が内部であるかを決定し、それに応じてそれらを接続します。 

この観点を採用すると、調音制約は局所的になりますが、次数順序制約は依然として残ります。 次数条件は、ラベルが小さい頂点の次数が高くなる傾向があることを強く示唆しています。 すべての「重要な」内部頂点を番号付けの最初に配置し、すべてのリーフを最後に配置すると、これは自然に互換性があります。 

これは重要な構造観察につながります。リーフが必要な位置 i (値 0) が存在し、その後の内部ノードが必要な位置 j (値 1) が存在する場合、頂点 i の次数は 1 であるのに対し、頂点 j の次数は少なくとも 2 となり、単調性に違反するため、次数の順序付けは不可能になります。 これにより、必要なすべての内部頂点が順序付けの接頭辞として強制的に表示されます。 

このプレフィックス構造が確立されると、内部頂点上に単純なパスを構築し、残りのすべての頂点をリーフとしてアタッチできます。

 ## アルゴリズムのチュートリアル

 内部でなければならない頂点のセットを、頂点 1 とともに ai = 1 となるすべての頂点 i として定義します。 

1. 頂点 2 から開始して配列を左から右にスキャンし、0 とマークされた頂点が 1 とマークされた頂点の前に現れるかどうかを確認します。これが発生した場合、直ちに不可能であると結論付けます。 このような構成では、後の頂点に前の頂点よりも高い次数が強制され、次数の順序付けの制約に違反するため、これが必要です。 
2. その意味で配列が単調でない場合は、頂点 1 ～ k が内部であり、頂点 k+1 ～ n がリーフであるように、しきい値 k を特定します。 頂点 n はリーフ セグメント内に存在する必要があるため、k が最大でも n マイナス 1 であることが自動的に保証され、実現可能性により k は最大でも n マイナス 2 になることが強制されます。 
3. すべての内部頂点を昇順に接続する単純なパスを構築します。1 は 2 に接続され、2 は 3 に接続され、同様に k まで続きます。 これにより、パスの端点を除き、すべての内部頂点が少なくとも次数 2 を持つことが保証されます。 
4. 次に、すべてのリーフ頂点 (k+1 ～ n) を内部頂点へのアタッチメントとして分配します。 内部パスのエンドポイントがそれぞれ少なくとも 1 つのリーフを受け取るようにし、それ自体がリーフではないようにします。 残りのリーフは任意に、通常は頂点 1 にアタッチされます。 
5. 構築されたすべてのエッジを出力します。 

なぜ効果があるのか:

 構築されたグラフはツリーであるため、関節点はまさに内部頂点になります。 1 とマークされたすべての頂点 (および要件による頂点 1) は内部にあるため、カット頂点ですが、0 と頂点 n をマークしたすべての頂点はリーフであるため、カット頂点ではありません。 プレフィックス条件により、すべての内部頂点がラベル順ですべての葉よりも前に表示されることが保証されるため、以前のすべての頂点は少なくとも後のすべての頂点と同じ大きさの次数を持ちます。 すべての葉の次数は 1 であり、内部頂点の次数は少なくとも 2 であるため、順序付け制約はグローバルに満たされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    s = input().strip()
    
    a = [0] * (n + 1)
    for i, ch in enumerate(s, start=2):
        a[i] = int(ch)
    
    # vertex 1 is always internal, vertex n must be leaf
    # internal set S = {1} ∪ {i: a[i]=1}
    
    # check monotonic structure: no 0 before 1 in 2..n-1
    seen_one = False
    for i in range(2, n):
        if a[i] == 1:
            seen_one = True
        else:
            if seen_one:
                print(-1)
                return
    
    # build S as prefix
    k = 1
    for i in range(2, n):
        if a[i] == 1:
            k = i
        else:
            break
    
    # if there exists any 1 after first 0, already handled
    # ensure at least one leaf besides n
    if k == n - 1:
        print(-1)
        return
    
    S = list(range(1, k + 1))
    leaves = list(range(k + 1, n + 1))
    
    edges = []
    
    # build chain on S
    for i in range(len(S) - 1):
        edges.append((S[i], S[i + 1]))
    
    # attach leaves: ensure endpoints get at least one
    if len(leaves) == 1:
        # only possible leaf is n; impossible since endpoint needs a leaf too
        print(-1)
        return
    
    # attach one leaf to k (endpoint), one to 1, rest to 1
    edges.append((S[0], leaves[0]))
    edges.append((S[-1], leaves[1]))
    
    for i in range(2, len(leaves)):
        edges.append((S[0], leaves[i]))
    
    print(len(edges))
    for u, v in edges:
        print(u, v)

if __name__ == "__main__":
    t = int(input())
    for _ in range(t):
        solve()
```この実装では、最初に、必要なすべての内部頂点がプレフィックスとして表示される必要があるという構造条件が強制されます。 これが満たされると、構築は内部頂点上にバックボーン パスを構築することになります。 

重要な点は葉の扱い方です。 ツリーには少なくとも 2 つの葉が必要なので、内部セットの外側に少なくとも 2 つの頂点があることを確認します。 また、リーフを内部パスの両方の終点に明示的にアタッチして、リーフが非リーフ頂点のままであることを保証し、関節状態を維持します。 

## 実用的な例

 内部頂点が有効なプレフィックスを形成する小さなケースを考えてみましょう。 n = 6、要件文字列を 1110 とします。これは、頂点 2 と 3 が内部であり、頂点 4 がリーフであり、頂点 6 も定義によりリーフであることを意味します。 

私たちは以下のものを持っています:

 | ステップ | 内部セット | 葉 | アクション |
 | --- | --- | --- | --- |
 | イニシャル | {1,2,3} | {4,5,6} | プレフィックス条件を検証する |
 | バックボーンを構築する | 1-2-3 | {4,5,6} | 内部ノード上のパス |
 | 葉を付ける | 写真 1、3 エンドポイント | 葉を配布します | 関節ノードが内部に留まるようにする |

 結果として得られるグラフでは、頂点 1、2、および 3 が内部ノードとして保持され、その他はすべてリーフであり、アーティキュレーション コンストレイントに正確に一致します。 

次に、n = 5 でシーケンスが 101 である無効なケースを考えます。これは、頂点 2 はアーティキュレーション ポイントではなく、頂点 3 はアーティキュレーション ポイントですが、インデックス順では頂点 2 が頂点 3 より前に現れることを意味します。 どのような構成でも、頂点 2 には次数 1 が強制され、頂点 3 には次数が少なくとも 2 になるため、単調な次数順序に直ちに違反します。 アルゴリズムはこのケースを正しく拒否します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    from collections import deque
    
    out = []
    
    def solve():
        n = int(input().strip())
        s = input().strip()
        a = [0] * (n + 1)
        for i, ch in enumerate(s, start=2):
            a[i] = int(ch)

        seen_one = False
        for i in range(2, n):
            if a[i] == 1:
                seen_one = True
            elif seen_one:
                out.append("-1")
                return

        k = 1
        for i in range(2, n):
            if a[i] == 1:
                k = i
            else:
                break

        if k == n - 1:
            out.append("-1")
            return

        S = list(range(1, k + 1))
        leaves = list(range(k + 1, n + 1))

        edges = []
        for i in range(len(S) - 1):
            edges.append((S[i], S[i + 1]))

        if len(leaves) <= 1:
            out.append("-1")
            return

        edges.append((S[0], leaves[0]))
        edges.append((S[-1], leaves[1]))
        for i in range(2, len(leaves)):
            edges.append((S[0], leaves[i]))

        out.append(str(len(edges)))
        for u, v in edges:
            out.append(f"{u} {v}")

    t = int(input().strip())
    for _ in range(t):
        solve()

    return "\n".join(out)

 ## 特殊なケース

 n を除くすべての頂点がアーティキュレーション ポイントである必要がある場合、重大なエッジ ケースが発生します。 この状況では、内部セットには n マイナス 1 個の頂点が含まれ、葉が 1 つだけ残ります。 どのツリーにも少なくとも 2 つの葉がなければならないため、この構成は実現できません。 アルゴリズムは、k が n マイナス 1 に等しいと判断したときにこれを検出し、すぐに -1 を出力します。 

別のエッジケースは、最初のゼロが早く出現するが、後の頂点が内部である必要がある場合に発生します。 これにより、ラベル順序で葉が内部頂点の前に表示されるため、次数単調性制約が破られます。 プレフィックス チェックは 1 回のスキャン中にこれを検出し、無効なツリーの構築を防ぎます。 

3 番目のエッジ ケースは、頂点 1 のみが内部にある場合です。 これは、k が 1 に相当し、他のすべての頂点はリーフに相当します。 構造は頂点 1 を中心とする星形に縮退しますが、他のすべての頂点が最小次数が等しいため、アーティキュレーション要件と次数の順序付けは依然として満たされます。
