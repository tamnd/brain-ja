 ## 解決策
 ## 問題の理解

 この問題は、一連の株価を与えます。$n$日ですが、価格は対数形式でエンコードされます。 当日$i$、実際の価格は$e^{a_i}$、 どこ$a_i$は正の整数です。 これにより、実際の市場における乗算的な利益と損失が、指数空間における加算的な差異に変換されます。 

各クエリは時間間隔を記述します。$[s, t]$。 当日$s$、の融資を受けています。$e^k$お金の単位。 日中は自由に株式を取引できます$s$を通して$t$、端株を購入し、無制限の取引を実行します。 一日の終わりに$t$、すべての保有が清算され、ローンが返済されます。 私たちは、返済後の最終的な資産を可能な限り最大限に増やしたいと考えています。これを再び指数関数で表します。$e^w$、そしてタスクは出力することです$w$。 

したがって、クエリごとの中心的なタスクは次のとおりです。 現金から始める$e^k$、既知の価格シーケンスでの裁定取引後の最終金額を最大化し、結果の指数を出力します。 

重要な変換は、すべてが指数関数的であるため、対数空間での作業により乗算ゲインが加算ゲインに変わることです。 当日からのお取引$i$今日$j$ゲイン係数を与える$e^{a_j - a_i}$、したがって指数空間では寄与します$a_j - a_i$。 

制約は大きく、最大で$10^5$日々と$10^5$クエリ。 これにより、クエリごとに最適な取引を線形時間で個別に再計算するソリューションは即座に除外されます。$10^{10}$操作。 

単純なアプローチでは、各クエリを個別に処理し、内部で最適な取引をシミュレートします。$[s, t]$。 ただし、1 つの間隔に対して最適な戦略を見つける場合でも、注意深く行う場合はセグメントを複数回スキャンする必要があり、すべてのクエリに対してそれを行うのは現実的ではありません。 

より微妙な失敗モードは、答えが区間内の最小価格と最大価格にのみ依存すると考えることから生まれます。 複数の交互の増加が重要であるため、これは誤りです。最適な戦略は必ずしも 1 回の買いと 1 回の売りではなく、一連の収益性の高い動きです。 

## アプローチ

 最初のステップは、ログ空間における「無制限の取引と端株による最適な取引」が何を意味するかを理解することです。 当日に買うとしましょう$i$そして当日販売します$j > i$。 指数のゲインは$a_j - a_i$。 複数の取引を実行する場合、セグメントに分割するとします$i_1 < i_2 < \dots < i_k$、合計ゲインは次のようになります$$(a_{i_2} - a_{i_1}) + (a_{i_3} - a_{i_2}) + \dots + (a_{i_k} - a_{i_{k-1}}),$$どの望遠鏡を使うか$a_{i_k} - a_{i_1}$厳密に買いと売りを交互に強制する場合。 しかし、本当の制約は、厳密に交代することを強制されているわけではないということです。 選択した境界を越えて、より低い価格からより高い価格に移動する場合にのみ利益を得ることができます。 

古典的な単純化は、取引を連続した増加セグメント間のすべてのプラスの上向きの差を蓄積するものとして解釈するときに現れます。 シーケンスが増加する場合、その増加を捕捉します。 下がった場合は無視して、より良いエントリーポイントを待ちます。 これにより、最適ゲインが低下します。$[s, t]$すべての正の隣接差の合計:$$\sum_{i=s}^{t-1} \max(0, a_{i+1} - a_i).$$最終的な答えは単純に次のようになります。$$w = k + \sum_{i=s}^{t-1} \max(0, a_{i+1} - a_i).$$ブルート フォース アプローチでは、間隔をスキャンしながら、クエリごとにこの合計を個別に評価します。 つまり$O(n)$クエリごとに、次のようになります$O(nm)$合計すると通過できません。 

重要な観察は、式が隣接する差異のみに依存するということです。 定義する$d_i = \max(0, a_{i+1} - a_i)$。 次に、各クエリは配列に対する範囲合計クエリに帰着します。$d$。 プレフィックス合計を使用すると、前処理後に一定時間内に各クエリに答えることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(nm)$|$O(1)$| 遅すぎる |
 | 差分のプレフィックス合計 |$O(n + m)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 価格シーケンスを差分寄与配列に変換し、それに対する範囲クエリに答えます。 

1. 補助配列を構築する$d$長さの$n-1$、各要素は$d_i = \max(0, a_{i+1} - a_i)$。 これにより、最適な取引では損失が寄与しないため、収益性の高い上向きの動きのみが分離され、下向きの動きは破棄されます。 
2. プレフィックス合計配列を構築する$p$、 どこ$p[i]$の合計を格納します$d_1$を通して$d_i$。 これにより、一定時間内に任意の間隔の合計を計算できるようになります。 
3. クエリごとに$[s, t]$、区間内の合計ゲインを次のように計算します。$p[t-1] - p[s-1]$というのは、間隔内で完全に遷移するだけが重要だからです。 
4. 底指数を加算します。$k$このゲインに加えて、最終的な指数を生成します$w$。 
5. 出力$w$。 

差分配列が十分である理由は、最終結果を変えることなく、すべての利益が上昇ステップに正確に対応するように、収益性の高いトレーディング戦略を再配置できるためです。 どのような一連の取引も、ローカルな増加分を収集することになります。 

### なぜ効果があるのか

 不変条件は、間隔内のどの時点においても、可能な限り最良の戦略では、現金を保持するか、または最新のローカル ミニマムで購入した株式を保持するという特性が維持されるということです。 シーケンスが増加するたびに、将来の決定に影響を与えることなく、その増加を完全に捉えることができます。 そこにエントリーしても、より低い価格を待つ場合と比較して、その後のエグジットを改善することはできないため、すべての下落は無視されます。 

これにより、すべての最適な戦略が局所的な単調セグメントの独立した寄与に還元され、正の隣接差の合計が必要かつ十分になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
a = list(map(int, input().split()))
k = int(input())

n = len(a)
d = [0] * (n - 1)

for i in range(n - 1):
    if a[i + 1] > a[i]:
        d[i] = a[i + 1] - a[i]

prefix = [0] * (n)
for i in range(n - 1):
    prefix[i + 1] = prefix[i] + d[i]

out = []
for _ in range(m):
    s, t = map(int, input().split())
    gain = prefix[t - 1] - prefix[s - 1]
    out.append(str(k + gain))

print("\n".join(out))
```コードはまず、隣接する差分を 1 回スキャンしてゲイン配列を構築します。 プレフィックス配列は 1 インデックス分シフトされ、範囲クエリが 1 インデックスの入力ときれいに整列します。 

各クエリはプレフィックスの差に直接変換されます。 の追加$k$前処理中の演算の繰り返しを避けるために、クエリ時に実行されます。 

よくある落とし穴は、off-by-one インデックス付けです。ゲイン配列にはサイズがあります。$n-1$、ただしクエリは日数を指します。 このマッピングでは、取引機会は日中に存在します。$i$そして$i+1$、それでクエリ$[s, t]$インデックスをカバーする$[s, t-1]$差分配列内。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    k = int(input())

    n = len(a)
    d = [0] * (n - 1)
    for i in range(n - 1):
        if a[i + 1] > a[i]:
            d[i] = a[i + 1] - a[i]

    prefix = [0] * (n)
    for i in range(n - 1):
        prefix[i + 1] = prefix[i] + d[i]

    out = []
    for _ in range(m):
        s, t = map(int, input().split())
        out.append(str(k + prefix[t - 1] - prefix[s - 1]))

    return "\n".join(out)

# minimal size
assert run("1 1\n5\n3\n1 1") == "3"

# strictly decreasing
assert run("5 1\n5 4 3 2 1\n10\n1 5") == "10"

# strictly increasing
assert run("5 1\n1 2 3 4 5\n10\n1 5") == "14"

# alternating
assert run("4 1\n1 3 2 4\n0\n1 4") == "4"

# sample-style
assert run("6 2\n3 2 4 5 3 6\n2\n2 4\n3 6") == "5\n6"

 ## 特殊なケース

 微妙なケースとしては、区間が上昇セグメント内で開始または終了する場合があります。 たとえば、次のようなシーケンスでは、$1, 5, 10, 2, 3$、クエリ$[2, 4]$のみが含まれます$5, 10, 2$。 アルゴリズムは差の寄与を計算します$+5$間隔内であり、からのドロップを無視します。$10$に$2$、儲からないからです。 プレフィックスの減算により、内部境界のみが正しく分離されます。$5 \to 10$。 

もう 1 つのケースは 1 日のクエリです$[i, i]$。 遷移がないため、差の合計はゼロとなり、答えは正確に次のようになります。$k$。 接頭辞の式では当然ゼロが得られます。$p[i-1] - p[i-1] = 0$慎重に実装すれば、偶発的な範囲外やマイナスのインデックス効果を防ぐことができます。
