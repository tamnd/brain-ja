 ## 解決策
 ## 問題の理解

 この問題では、福建省のプログラミング コンテスト シリーズの 11 回のエディションを説明する固定の履歴テーブルが表示されます。 各版には組織化された大学があり、各大学は英語の短い略語に関連付けられています。 入力は単一の整数です`n`、関心のあるコンテストのエディションを表します。タスクは、コンテストを主催した大学の略称を出力することです。`n`-第 版。 

ステートメントには多くのノイズや文字化けが含まれていますが、実際の構造は単純です。11 個のエントリからなる静的なリストがあり、答えはインデックスによる直接検索です。 

制約`1 ≤ n ≤ 11`は非常に小さいため、前処理、検索、アルゴリズムの最適化の必要性が即座に排除されます。 定数時間の配列インデックス操作を実行するソリューションであればどれでも十分です。 

大きな入力サイズや複数のクエリを伴う隠れたエッジのケースはありません。 不注意な実装で遭遇する可能性のある唯一の微妙な問題は、off-by-one インデックス付けです。プログラミング言語では配列のインデックスが 0 から始まるのに対し、このようなコンテストの問題ではエディションに 1 から始まる番号が付けられることが多いためです。 

たとえば、誰かが誤って初版をインデックス 0 として扱った場合、次のように入力します。`1`この場合、最初の大学ではなく 2 番目の大学に誤ってマッピングされ、ロジックが正しいように見えても間違った略語が生成されます。 

## アプローチ

 問題の構造は基本的に、整数から文字列への静的なマッピングです。 強引な解釈では、大学の完全なテーブルを解析し、毎回略語を抽出することでマッピングを動的に再構築することになりますが、それは不必要なオーバーヘッドです。 テーブルは固定されており小さいため、繰り返し再計算または解析しても、メリットがなく複雑さが増すだけです。 

重要な観察は、テスト ケース間では何も変化せず、正しい既知の値を選択する以外に計算は必要ないということです。 問題が直接インデックス作成タスクであることがわかれば、解決策は 11 個の略語を配列に格納し、`(n-1)`- 番目の要素。 

この強引なアイデアは、速度というよりも優雅さの点で失敗します。構造化テキストを再読み込みしたり、解析ロジックをシミュレートしたりする必要があり、ステートメント内のエンコード ノイズを考慮すると脆弱です。 直接インデックス作成のアプローチは堅牢かつ最小限です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース解析 | クエリごとに O(1) ですが、実装は複雑です | お(1) | 不要 |
 | 直接検索 | お(1) | お(11) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. リストを作成する`abbr`コンテスト版の順に 11 の既知の略語が含まれています。 このリストは問題の表から直接導出されており、各位置が 1 つのエディションに対応しています。 
2. 整数を読み取る`n`入力から。 
3. 出力`abbr[n - 1]`、問題ステートメントの 1 から始まるインデックスから配列表現の 0 から始まるインデックスに変換します。 

### なぜ効果があるのか

 コンテストのエディションは、エントリ間の変換や依存関係のない固定シーケンスを形成します。 各クエリは単に、そのシーケンス内の既知の位置に格納されている値を要求しているだけです。 マッピングは静的でドメイン全体にわたるため、`1..11`、それを明示的に保存すると正確さが保証されます。 必要な変換はインデックス作成の調整だけであり、それが処理されると、検索は正確になります。

重要な実装の詳細は次のとおりです。`n - 1`調整。 Python リストはゼロインデックスですが、問題では初版が次のように定義されているため、`1`1 を引くことに失敗すると、すべての答えが 1 位置ずつシフトします。 

## 実用的な例

 インプットを考慮する`1`。 アルゴリズムは次のように読み取ります`n = 1`そしてアクセス`abbr[0]`、つまり`"FZU"`。 これは初版の主催者と一致します。 

ここで考えてみましょう`2`。 アルゴリズムは次のようにアクセスします。`abbr[1]`、戻る`"FNU"`。 これは表の第 2 版に相当します。 

| ステップ | n | 使用されるインデックス | 値 |
 | --- | --- | --- | --- |
 | 例 1 | 1 | 0 | FZU |
 | 例 2 | 2 | 1 | FNU |

 これらの例では、マッピングが純粋に位置的なものであり、必要な変換はインデックス作成だけであることが確認されています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    abbr = [
        "FZU","FNU","FZU","FZU","FAFU",
        "HQU","MJU","XMUT","QZNU","JMU","FZU"
    ]
    n = int(sys.stdin.readline().strip())
    return abbr[n - 1]

# provided samples
assert run("1\n") == "FZU"
assert run("2\n") == "FNU"

# boundary cases
assert run("11\n") == "FZU"
assert run("5\n") == "FAFU"
assert run("7\n") == "MJU"
assert run("9\n") == "QZNU"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 | FZU | 最初の要素の正確性 |
 | 2 | FNU | 2 番目の要素の正確性 |
 | 11 | FZU | 上限のインデックス付け |
 | 5 | ふぁふ | 中間のマッピングの正確性 |

 唯一意味のあるエッジ ケースは、リストの末尾の境界インデックス付けです。 入力用`1`、アルゴリズムはインデックスを計算します`0`、最初の略語が正しく取得されます。 入力用`11`、インデックスを計算します`10`、最後のエントリを取得します。 

たとえば、次のようなとき`n = 11`、計算は次のようになります。 

リストアクセスは、`abbr[10]`を返します。`"FZU"`。 リストは明示的に正しい順序で構築されるため、範囲外のアクセスは発生せず、インデックス付けのシフトを超える特別な処理も必要ありません。
