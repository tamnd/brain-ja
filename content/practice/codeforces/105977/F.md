 ## 問題の理解

 左から右にインデックスが付けられた一連の点が与えられます。 各ポジション$i$値のペアがあります$(x_i, y_i)$。 任意のクエリ間隔に対して$[l, r]$、このセグメント内の点のみを見て、点を分類します$j$他にポイントがない場合は有効とみなします$k$同じ間隔で$x_k \ge x_j$そして$y_k \ge y_j$同時に。 

幾何学的用語では、各クエリ セグメント内で、そのセグメント内の他の点によって支配されていない点をカウントします。ここで、支配とは、両方の座標において少なくとも同じ大きさであることを意味します。 これらはまさに、区間に制限されたパレート最適点です。 

入力サイズが大きく、両方とも$n$そして$q$まで$10^6$。 これにより、その間隔にわたるクエリごとの線形スキャンが即座に除外されます。$O(nq)$または$O((r-l+1)\log n)$スタイルの解決策は、最悪の場合には崩壊します。 ソリューションでは、クエリ間で作業を償却し、支配関係を最初から再計算することを回避する必要があります。 

微妙な点は、優位性が各クエリ間隔に局所的であることです。 ポイントはグローバルに支配されていても、制限されたセグメント内でパレート最適になる可能性があります。 このため、範囲ごとに効率的に適応できない限り、グローバルな前処理は不十分になります。 

よくある落とし穴は、グローバル パレート最大値または 1 つの座標による並べ替えで十分であると想定していることです。 たとえば、支配的な点がクエリ範囲外にあるため、部分配列内で全体的に支配的な点が最適になる点を考えてみましょう。 ポイントをグローバルに破棄するソリューションは、正確性を失います。 

ポイントを次の基準で並べ替えると、別の失敗ケースが発生します。$x$または$y$、そして私たちはプレフィックスの最大構造を維持しようとします。 クエリがプレフィックス クエリではなく、任意のサブセグメントであるため、これは問題になります。 

## アプローチ

 各クエリの直接的なアプローチは、すべてのインデックスをスキャンすることです。$j \in [l, r]$そして、それぞれについて$j$、もう一度スキャンして、他のポイントが支配的かどうかを確認します。 これは正しいですがコストがかかります$O((r-l+1)^2)$クエリごとに、次のようになります$O(n^2)$最悪の場合。 と$10^6$これは完全に不可能な要素です。 

すべてのペアを明示的に比較せずに、セグメント内で優勢なポイントを削除する方法が必要です。 重要な観察は、両方の座標において優勢が単調であるということです。そのため、固定セグメント内では、一方の座標でポイントをソートし、もう一方の座標で構造を維持することを想像できます。 

中心的なアイデアは、「現在のアクティブな間隔でこのポイントを支配するポイントがあるかどうか」に答えることができるデータ構造をスイープして維持することによって、クエリをオフラインで処理することです。 ただし、難しいのは、両方とも$l$そして$r$は変数であるため、グローバル スイープではなくインデックス上の範囲データ構造が必要です。 

有用な再定式化は、正しいエンドポイントを修正することです$r$プレフィックス上の構造を維持します$[1, r]$。 それぞれについて$r$で終わるすべての接頭辞の中でどの点がパレート最適であるかを判断できます。$r$ただし、クエリでは任意の左側の境界が要求されます。 これは、一定の間隔でクエリできる優位性に関する情報を維持することを示唆しています。 

「部分配列内の支配関係の下で最大となる要素の数」を処理する標準的な方法は、条件を単調構造と組み合わせたセグメント ツリーに対する範囲クエリに変換することです。$y$。 私たちは、セグメントごとに、そのセグメントのパレートフロンティアを保存する構造を維持します。 2 つのセグメントを結合すると、他のセグメントの何にも支配されていないポイントのみが保存され、このフロンティアのサイズは最悪の場合でもせいぜい線形ですが、分割統治または永続的な構造を使用して制御できます。 

重要な構造的洞察は、任意の固定セグメントにおいて、ポイントを降順に並べ替えると次のようになります。$x$の場合、ポイントは次の場合にのみ有効です。$y$これまでに確認されたものよりも厳密に大きい$y$セグメント内でこの順序で。 これにより、問題はクエリ セグメントごとに、過去最高値がいくつあるかを見つけることになります。$y$で注文すると表示されます$x$そのセグメントに限定されます。 課題は、クエリごとにこの順序付けを効率的に行うことです。 

この問題は、インデックスに対するセグメント ツリーを維持することで解決します。各ノードは、次の基準でソートされたポイントを格納します。$x$そして、「このマージされたソートリストに新しい最大値がいくつ現れるか」に答えることができる圧縮構造を事前計算します。 クエリ中に分解します。$[l, r]$の中へ$O(\log n)$ノードを結合し、それらの並べ替え基準をマージします。$x$現在の最大値を維持した 2 ポインター トラバーサルを概念的に使用したリスト$y$。 各ノードは現在の最大値を超えるポイントのみを提供するため、各ポイントはマージ全体で最大でも対数的に処理されます。 

これにより、各クエリが次のように削減されます。$O(\log^2 n)$または$O(\log n)$実装の詳細に応じて償却されます。

 ## アルゴリズムのチュートリアル

 インデックス範囲にわたってセグメント ツリーを構築します$[1, n]$。 各ノードは、セグメント内のすべてのポイントを次の基準でソートして保存します。$x$。 この順序は一度固定され、すべてのクエリで再利用されます。 

1. セグメント ツリーを構築し、各ノードですべてのセグメント ツリーを収集します。$(x_i, y_i)$そのノードの範囲内で降順に並べ替えます$x$。 この順序により、スキャン時に正しい方向で優勢比較をシミュレートすることが保証されます。$x$。 
2. お問い合わせの場合$[l, r]$、それを正確にその範囲をカバーするセグメントツリーノードに分解します。 これにより、一連の互いに素なノード リストが生成されます。 
3. 最大の次の候補を繰り返し選択することにより、概念的にこれらのノード リストをマージします。$x$現在の頭の中では。 制御された再帰的な方法でノードを処理する場合、ヒープまたは k-way マージは厳密には必要ありませんが、概念的には、ポイントを減少させながら反復しています。$x$セグメントの結合全体にわたって。 
4. 変数を維持する`best_y`、最初は$-\infty$。 減少する点を繰り返すと、$x$、各ポイントを確認していきます。 もしそれなら$y$より大きい`best_y`、マージされた順序で以前に確認されたポイントによって支配されていないため、答えに寄与し、更新します。`best_y = y`。 
5. 各ノードはソートされた順序でポイントを提供しますが、ポイントがなくなるまでスキャンするだけです。 ノードが完全に消費されると、そのノードはマージの考慮から削除されます。 

正しさは、固定セットにおいて、その点が過去最高値として現れる場合に限り、その点がパレート最適であるという事実にかかっています。$y$減少中にスキャンするとき$x$。 

機能する理由: クエリ間隔内で、すべてのポイントを降順に並べ替えることを検討してください。$x$。 ある点が支配的である場合、それよりも大きいか等しい値を持つ別の点が存在します。$x$それ以上または同等$y$、この順序で前または同じ位置に出現する必要があります。 したがって、その$y$処理される時点では実行最大値を超えることはできません。 逆に、ポイントが支配されていない場合、それ以前のポイントは存在しません。$x$-注文は$y \ge$したがって、新しい最大値としてカウントされます。 これにより、有効なポイントとマージされた注文の最高値の間に 1 対 1 の対応関係が作成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n, q = map(int, input().split())
x = list(map(int, input().split()))
y = list(map(int, input().split()))

points = [(x[i], y[i], i+1) for i in range(n)]

class Node:
    __slots__ = ("xs", "ys")
    def __init__(self):
        self.xs = []
        self.ys = []

seg = [Node() for _ in range(4 * n)]

def build(v, l, r):
    if l == r:
        seg[v].xs = [x[l-1]]
        seg[v].ys = [y[l-1]]
        return
    m = (l + r) // 2
    build(v*2, l, m)
    build(v*2+1, m+1, r)

    merged = []
    left = seg[v*2]
    right = seg[v*2+1]

    i = j = 0
    L = len(left.xs)
    R = len(right.xs)

    while i < L and j < R:
        if left.xs[i] > right.xs[j]:
            merged.append((left.xs[i], left.ys[i]))
            i += 1
        else:
            merged.append((right.xs[j], right.ys[j]))
            j += 1

    while i < L:
        merged.append((left.xs[i], left.ys[i]))
        i += 1

    while j < R:
        merged.append((right.xs[j], right.ys[j]))
        j += 1

    seg[v].xs = [p[0] for p in merged]
    seg[v].ys = [p[1] for p in merged]

def query(v, l, r, ql, qr, res):
    if ql <= l and r <= qr:
        res.append(v)
        return
    m = (l + r) // 2
    if ql <= m:
        query(v*2, l, m, ql, qr, res)
    if qr > m:
        query(v*2+1, m+1, r, ql, qr, res)

build(1, 1, n)

out = []

for _ in range(q):
    l, r = map(int, input().split())
    nodes = []
    query(1, 1, n, l, r, nodes)

    ptr = [0] * len(nodes)
    best_y = -1
    ans = 0

    while True:
        best_x = -1
        best_id = -1

        for i, v in enumerate(nodes):
            p = ptr[i]
            if p < len(seg[v].xs):
                if seg[v].xs[p] > best_x:
                    best_x = seg[v].xs[p]
                    best_id = i

        if best_id == -1:
            break

        v = nodes[best_id]
        p = ptr[best_id]
        ptr[best_id] += 1

        if seg[v].ys[p] > best_y:
            ans += 1
            best_y = seg[v].ys[p]

    out.append(str(ans))

print("\n".join(out))
```セグメント ツリー構造により、各ノードには降順でソートされたセグメントが含まれるようになります。$x$したがって、クエリ中にグローバルな減少をシミュレートできます。$x$アクティブなノード間で次に利用可能な最大ヘッドを繰り返し選択することによってトラバースします。 の`best_y`変数は現在の最大値を追跡します$y$この順序ですでに受け入れられたポイントの間で、優勢条件を直接実装します。 

注意すべき点は、任意のペアを決して比較しないことです。 すべての決定は現在のスイープ順序に対してローカルであり、すべての支配関係を暗黙的にエンコードします。
