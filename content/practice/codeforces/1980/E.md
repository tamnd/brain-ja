 ## 問題の理解

 数値の 2 つの長方形のグリッドが与えられます。両方のサイズは次のとおりです。$n \times m$、そしてそれらを合わせると、からの数字が正確に含まれます。$1$に$n \cdot m$、それぞれ1回ずつ出現します。 したがって、各行列は同じタイルのセットを再配置したものにすぎません。 

許可される移動は、行全体を交換するか、列全体を交換することだけです。 これは何度でも行うことができます。 タスクは、これらの行と列の交換のみを使用して、最初のグリッドを 2 番目のグリッドに変換できるかどうかを判断することです。 

重要な制約は、行のスワップは行内の順序を変更せず、行の順序を変更するだけであり、列のスワップは列内の順序を変更せず、列の順序を変更するだけであることです。 したがって、グリッドの構造は、行インデックスと列インデックスの独立した並べ替えまで保持されます。 

入力サイズが大きい: すべてのテスト ケースで、セルの合計数は最大でも$2 \cdot 10^5$。 これは、次のことを強く示唆しています。$O(nm)$テスト ケースごと、または線形全体のソリューションごとに。 テストまたは操作のシミュレーションごとに繰り返しソートを行うものは、合計入力サイズが線形である場合にのみ問題ありません。 

単純な誤解は、スワップをシミュレートする必要がある、または貪欲に行と列を「位置合わせ」する必要があると考えることです。 次のような場合には失敗します。 

例:$$a = \begin{pmatrix} 1 & 2 \\ 3 & 4 \end{pmatrix}, \quad b = \begin{pmatrix} 4 & 3 \\ 2 & 1 \end{pmatrix}$$単純な行マッチングのアプローチでは、直接一致する行がないため不一致と結論付けられる可能性がありますが、行と列の両方を交換することで変換が可能になります。 

もう 1 つの微妙な失敗例は、行マルチセットが行ごとに一致する必要があると想定している場合です。 行自体が恣意的に並べ替えられるため、これは誤りです。 

本当の難しさは、行と列の置換がローカルではなくグローバルに相互作用することです。

 ## アルゴリズムのチュートリアル

 両方の行列の値の位置間の直接マッピングを構築し、これらのマッピングによって暗示される行と列の置換が一貫していることを検証します。 

1. すべての値について、両方の行列を読み取り、保存します$x$、その座標は$a$:$(r_a[x], c_a[x])$そしてで$b$:$(r_b[x], c_b[x])$。 

このステップでは、グリッド問題を順列にわたる点マッチング問題に変換します。 
2. 各値について$x$、変換をマッピング行として解釈します$r_a[x]$に$r_b[x]$、および列$c_a[x]$に$c_b[x]$。 

有効なグローバル行順列が存在する場合、行を共有するすべての値が$a$の同じ行構造に一貫してマッピングする必要があります。$b$。 
3. 行ごとに 1 つの代表値を選択することで、行マッピングの一貫性を確保します。$a$そして、その行のすべての値が同じ行の順列にマップされるようにします。$b$。 

行があれば、$a$の複数の行にマッピングしようとします$b$、変身は不可能です。 
4. 列に対して同じロジックを繰り返し、各列が確実に$a$一貫して単一の列にマッピングされます。$b$。 
5. マッピングを確立した後、単射性を検証します。$a$の同じ行にマップします$b$、列についても同様です。 

これにより、マッピングが崩壊ではなく真の順列であることが保証されます。 
6. 行マッピングと列マッピングの両方が有効な順列である場合は、YES を出力します。 それ以外の場合は NO を出力します。 

### なぜ効果があるのか

 行スワップは、行インデックスをグローバルに並べ替えるだけです。つまり、どの値が行を共有するかは、一連の操作の下でも不変です。 列についても同様です。 したがって、行 (および列) によって引き起こされる値の分割は、次の行と次の行の間で保持される必要があります。$a$そして$b$、行インデックスと列インデックスの名前変更まで。 

2 つの値が同じ行にある場合、$a$、それらは同じ行に配置される必要があります。$b$行の置換を適用した後。 これにより、行から明確に定義されたマッピングが強制されます。$a$の列に$b$。 同じ議論が逆に適用され、全単射性が保証されます。 

したがって、アルゴリズムは、値の並べ替えによって引き起こされる行パーティションと列パーティションが一貫して再ラベル付けできるかどうかをチェックします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n, m = map(int, input().split())

        pos_a = {}
        pos_b = {}

        for i in range(n):
            row = list(map(int, input().split()))
            for j, x in enumerate(row):
                pos_a[x] = (i, j)

        for i in range(n):
            row = list(map(int, input().split()))
            for j, x in enumerate(row):
                pos_b[x] = (i, j)

        row_map = {}
        col_map = {}

        ok = True

        for x in pos_a:
            ra, ca = pos_a[x]
            rb, cb = pos_b[x]

            if ra in row_map and row_map[ra] != rb:
                ok = False
                break
            if ca in col_map and col_map[ca] != cb:
                ok = False
                break

            row_map[ra] = rb
            col_map[ca] = cb

        if ok:
            if len(set(row_map.values())) != len(row_map):
                ok = False
            if len(set(col_map.values())) != len(col_map):
                ok = False

        out.append("YES" if ok else "NO")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このソリューションでは、まず両方の行列を位置ルックアップ テーブルに圧縮して、各値がその座標を直接明らかにします。 次に、行用と列用の 2 つの部分マッピングを構築します。 一貫性チェックにより、最初の行列の行が 2 番目の行列の 2 つの異なる行にマッピングされないことが保証されます。これは、グローバルな行の置換の存在と矛盾します。 

最後の単射性チェックでは、行と列の交換の可逆性に違反する多対 1 マッピングではなく、本当に順列があることが確認されます。 

よくある落とし穴は、一貫性は行ごとに個別に適用するのではなく、すべての値にわたってグローバルに適用する必要があることを忘れていることです。

 ## 特殊なケース

 厄介なエッジケースは、行マッピングがローカルでは一貫しているが、グローバルでは衝突する場合です。 たとえば、次の 2 つの異なる行がある場合、$a$どちらも同じ行にマップしようとします$b$、アルゴリズムは単射性チェックを通じてこれを検出します。 

考慮する：```
a:
1 2
3 4

b:
1 2
3 4
```ここでは ID マッピングが有効です。 

次に、次のように変更します。```

このアルゴリズムは、ローカルの行比較に依存するのではなく、マッピング空間全体に一貫性と全単射の両方の制約を適用することで、これを正しく処理します。
