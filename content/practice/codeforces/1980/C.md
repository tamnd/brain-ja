 ## 解決策
 ## 問題の理解

 指定された配列かどうかを判断するように求められます。`b`元の配列から生成された可能性があります`a`ターゲット インデックスは失われますが、順番に割り当てられた値はわかっている場合に、一連の割り当て操作を適用することによって行われます。 各操作では指定された値が割り当てられます`d_j`配列の一部の要素に。 課題は、インデックスのシーケンスが不明であり、変換する有効なシーケンスが存在するかどうかを検証する必要があることです。`a`の中へ`b`。 

入力は複数のテスト ケースを提供し、それぞれに元の配列、ターゲット配列、値のシーケンスが含まれます。`d`。 私たちの仕事は、値を割り当てることができる場合に「YES」と答えることです。`b`、それ以外の場合は「いいえ」。 

制約は重要です。配列には最大 2 · 10^5 の要素を含めることができ、要素の合計は`n`そして`m`すべてのテスト ケースにわたって 2 · 10^5 に制限されます。 これは、ネストされたループで各配列を複数回反復するソリューションは遅すぎることを意味します。 テストケースごとに線形または線形に近いアプローチが必要です。 

複数のポジションが存在する場合、微妙なエッジケースが発生します。`b`同じ値が必要です`d_j`しかし、その例は少ない`d_j`操作リストで使用できるか、または操作リストで値が最後に出現したとき`b`特定の操作によって割り当てる必要があります。 たとえば、次の場合`a = [1,2,1]`、`b = [1,3,2]`、 そして`d = [1,3,1,2]`、割り当ては最後のものを正しくマップする必要があります。`3`で`b`利用可能ないずれかに`3`にいる`d`。 順序を無視して値の数だけをチェックする不用意なアプローチでは、誤検知が発生します。 

## アプローチ

 単純なアプローチでは、代入操作のインデックスのすべての置換を試行します。 これは明らかに実行不可能です。`n^m`最悪の場合に考えられるシーケンス、および`m`最大 2·10^5 まで可能です。 したがって、各順列を総当たりでチェックすることは非現実的です。 

最適なアプローチでは、カウントと組み合わせた貪欲な戦略を活用します。 それぞれのポジションについて、`b`どこ`a_i != b_i`、各値の最後に出現した値を使用して必要な値を割り当てる必要があります。`d`。 各値を位置のスタックにマッピングする辞書を維持できます。`b`それを必要とするものは右から左に処理されます。 次に、次のように繰り返します。`d`順番に並べて、それを適用する有効な位置があるかどうかを確認します。 重要な洞察は、各値が最後に出現した場所が`b`最後に対応するものでカバーされる必要があります`d_j`、以前の割り当てを貪欲に伝播することができます。 これにより、演算の順序と必要なターゲット配列の両方を考慮した線形時間ソリューションが保証されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n! * m!) | O(n + m) | 遅すぎる |
 | スタックを使った貪欲なカウント | O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースごとに、元の配列を読み取ります。`a`、ターゲット配列`b`、および値のシーケンス`d`。 
2. 辞書を作成する`need`各値をマッピングする`b`それは違う`a`必要なインデックスのリストに、逆の順序で保存されます。 これにより、ポジションを右から左に効率的にポップできるようになります。 
3. ポインタを初期化する`last_pos`各値に最後に割り当てられた位置を追跡します。 これにより、常に右端の制約が尊重されるようになります。 
4. シーケンスを反復処理する`d`。 それぞれの値について`val`：

- もし`need[val]`が空の場合は、最後に割り当てられた位置を使用します`val`操作（伝播）を満たすために。 
- それ以外の場合は、最後に必要な位置をポップします。`need[val]`それを割り当てて更新します`last_pos[val]`。 
5.すべての処理が完了したら`d`、値にまだ割り当てられていない位置があるかどうかを確認します。`need`。 もしそうなら、答えは「ノー」です。 それ以外の場合は「はい」。 

機能する理由: 各代入操作は順番に使用されます。 必要な位置を逆順に保存し、右端の要件から割り当てることで、必要なすべての割り当てが行われることを保証しながら、厳密には必要ではない操作を満たす伝播を可能にします。 不変条件は、各ステップで、残りの必要な位置が将来の操作によって常に到達可能であるため、必要な割り当てがスキップされないことです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import defaultdict, deque

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        m = int(input())
        d = list(map(int, input().split()))
        
        need = defaultdict(deque)
        for i in range(n-1, -1, -1):
            if a[i] != b[i]:
                need[b[i]].appendleft(i)
        
        last_pos = {}
        possible = True
        for val in d:
            if need[val]:
                idx = need[val].pop()
                last_pos[val] = idx
            elif val in last_pos:
                pass  # propagate to last used position
            else:
                possible = False
                break
        
        for positions in need.values():
            if positions:
                possible = False
                break
        
        print("YES" if possible else "NO")

solve()
```このソリューションはまず、必要な位置のマッピングを構築します。`b`それぞれの異なる値に対して。 使用する`deque`どちらの端からでも O(1) 個のポップが許可され、右から左への割り当てが可能になります。 の`last_pos`ディクショナリを使用すると、即時の要件が存在しない場合でも値を伝播できます。 全部処理したら`d`、必要な位置が残っている場合は、変換が不可能であることを示します。 

## 実用的な例

 最初のサンプルを考えてみましょう。```
a = [1, 2, 1]
b = [1, 3, 2]
d = [1, 3, 1, 2]
```| ステップ | d | からの val 前に必要 | | の後に必要です 最後の位置 | コメント |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 1 | 3:[1]、2:[2]、1:[2] | 3:[1]、2:[2] | 1:2 | 最後の位置 2 に 1 を代入します。 
| 2 | 3 | 3:[1]、2:[2] | 3:[]、2:[2] | 3:1 | 3 を位置 1 に割り当てます |
 | 3 | 1 | 3:[]、2:[2] | 3:[]、2:[2] | 1:2 | 1 を最後の位置 2 に伝播する |
 | 4 | 2 | 3:[]、2:[2] | 3:[],2:[] | 2:2 | 2 を位置 2 に代入 |

 全て`need`リストが空→はい。 

別のサンプル:```
a = [1, 2, 3, 5]
b = [2, 1, 3, 5]
d = [2, 1, 3, 5]
```アルゴリズムに従って、最初の値 2 は順序に従って正しい位置に割り当てることができません → NO。
