 ## 解決策
 ## 問題の理解

 正の整数の配列が与えられます。 そこから、すべての隣接するペアを最大公約数で置き換えることによって 2 番目の配列を導出できます。 この派生配列は、共有約数に関して隣接する値がどの程度「互換性」があるかを反映します。 

許可される操作は、元の配列から要素を 1 つだけ削除することです。 この削除後、GCD 配列を再計算し、左から右に移動しても減少しないかどうかを確認します。 タスクは、この導出シーケンスを単調非減少にする除去が少なくとも 1 つ存在するかどうかを判断することです。 

主な問題点は、1 つの要素を削除すると 2 つの隣接する GCD 計算がローカルで変更されますが、それらの変更が違反に伝播したり、他の場所で修正される可能性があることです。 配列の長さはすべてのテスト ケースで最大 2×10^5 であるため、各インデックスを削除してすべての GCD を再計算しようとするソリューションは遅すぎます。 単純なアプローチでは、削除の試行ごとに GCD シーケンスが O(n) で再計算され、O(n^2) が得られますが、これは最悪の場合には大きすぎます。 

配列がすでに「ほぼ有効」であるにもかかわらず、GCD シーケンスの 1 つの急激な低下により失敗する場合、微妙なエッジ ケースが発生します。 たとえば、ほとんどの隣接するペアで大きな GCD が生成されるが、中央の 1 つの要素が崩壊を引き起こす場合、その要素を削除すると、2 つの隣接する GCD 計算を一度に修正できる可能性があります。 ただし、間違った要素を削除すると、障害点が削除されずに移動する可能性があるため、局所的な直感だけでは信頼できません。 

もう 1 つの注意が必要な状況は、違反が分離されていない場合です。GCD シーケンスに複数の減少が存在する可能性がありますが、削除が許可されるのは 1 つだけです。 このような場合、削除ではすべての減少する遷移を同時に修復する必要があり、候補位置が強く制約されます。 

## アプローチ

 直接的なアプローチは、各インデックス i を削除して新しい配列を構築し、隣接するすべての GCD を計算して単調性をチェックすることです。 各チェックのコストは O(n) で、選択肢は O(n) あり、最悪の場合、テスト ケースごとに O(n^2) になります。 合計要素数が 2×10^5 であるため、これは制限をはるかに超えています。 

重要な観察は、GCD シーケンスは隣接するペアにのみ依存するため、1 つの要素を削除すると、GCD 配列内の 2 つの位置 (削除されたインデックスの周囲) にのみ影響するということです。 それ以外の場所では、GCD 値は変更されません。 この局所性は、削除のたびにすべてを最初から再計算する必要がないことを示唆しています。 

まず、元の配列 a に対して完全な GCD 配列 b を計算します。 b がすでに非減少である場合、要素を削除しても無秩序は増加しないため、答えは自明に YES です。 

違反がある場合は、b[i] > b[i+1] のインデックス i に違反が現れる必要があります。 このような位置は、単調性が崩れる唯一の場所です。 これを修正するには、a[i] または a[i+1] のいずれかを削除する必要があります。比較に含まれる 2 つの GCD 値に影響を与えるのはこれらのみであるためです。 これにより、候補セットが大幅に減少します。 

各候補の削除について、削除されたインデックスの周囲のローカル GCD 再計算のみをシミュレートし、結果のシーケンスが非減少になるかどうかを検証します。 違反ごとに候補者は最大 2 人であり、事実上重要となる違反は最大 1 つであるため、チェックは全体的に直線的になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. b[i] = gcd(a[i], a[i+1]) として GCD 配列 b を計算します。 これにより、近隣間のすべてのローカル関係がキャプチャされます。 
2. b をスキャンして、すでに減少していないかどうかを確認します。 そうであれば、修正する必要のある減少はないため、答えは「YES」であるとすぐに結論付けることができます。 
3. そうでない場合は、b[p] > b[p+1] となるように最初のインデックス p を見つけます。 これは単調性が失われる最初の点であり、有効な修正はこの領域に対処する必要があります。 
4. 要素 a[p] を削除することを検討し、結果のシーケンスが有効になるかどうかをテストします。 インデックス p−1 と p+1 の周囲の GCD 値のみが変化するため、配列全体を再構築するのではなく、ローカルで再計算します。 他のすべての位置は変更されないため、これで十分です。 
5. 要素 a[p+1] を削除し、同じローカル検証を実行することを検討します。 
6. いずれかの除去によって GCD シーケンスが減少しない場合は、YES を出力します。 それ以外の場合は NO を出力します。 

### なぜ効果があるのか

 単調性条件は、GCD 配列内の隣接するエントリ間の遷移でのみ違反されます。 違反の近傍の外側にある要素を削除しても、これら 2 つの矛盾する GCD 値の相対的な順序には影響しないため、問題を解決できません。 したがって、有効な解決策では、減少するペアの少なくとも 1 つのエンドポイントを削除する必要があります。 ローカル修正が適用されると、影響を受けない領域はすべて変更されないため、グローバル条件は 1 つの変更された境界を確認するだけになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from math import gcd

def check(a, skip_idx):
    n = len(a)
    prev = None
    prev_g = None

    # build GCD sequence on the fly, skipping one index
    for i in range(n - 1):
        # compute actual indices in original array
        x = i if i < skip_idx else i + 1
        y = i + 1 if i + 1 < skip_idx else i + 2

        if y >= n:
            break

        g = gcd(a[x], a[y])

        if prev_g is not None and prev_g > g:
            return False

        prev_g = g

    return True

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    b = [gcd(a[i], a[i+1]) for i in range(n - 1)]

    bad = -1
    for i in range(n - 2):
        if b[i] > b[i+1]:
            bad = i
            break

    if bad == -1:
        print("YES")
        return

    # try removing one of the endpoints
    if check(a, bad):
        print("YES")
        return
    if check(a, bad + 1):
        print("YES")
        return

    print("NO")

if __name__ == "__main__":
    solve()
```コードはまず、隣接するペアの GCD シーケンスを構築します。 次に、非減少順序の最初の違反を特定します。 ヘルパー関数`check`ペアの構築中に 1 つの要素をスキップして削除することをシミュレートします。 これにより、配列を明示的に再構築することが回避されます。 

重要な点は内部のインデックスの再マッピングです`check`。 要素がスキップされると、後続のすべてのインデックスが移動するため、各ペアを慎重に元の位置にマップし直す必要があります。 多くの誤った実装が失敗するのはここです。削除後に正しい隣接関係を維持せずに GCD を再計算します。

    from math import gcd

    def solve():

            if b[i] > b[i+1]:

                prev_g = g

 ## 特殊なケース

 重要なエッジケースは、違反が開始近くで発生する場合です。 たとえば、最初の 2 つの GCD がすでに減少している場合、最初の 3 つの要素のうち 1 つを削除するだけで構造を修正できる可能性があります。 アルゴリズムは最初の違反を選択し、その直接のエンドポイントのみをテストするため、これを処理します。 

もう 1 つのエッジ ケースは、要素を削除すると、以前は有効だった領域が新しい違反に移行する場合です。 でのローカル再計算`check`変更されていない構造を仮定するのではなく、影響を受けるすべての GCD 遷移を再構築するため、これが見逃されることを防ぎます。 

最後のエッジケースは、配列がすでに有効である場合です。 その場合、削除ロジックを完全にスキップすると、不必要なシミュレーションが回避され、直接 YES が出力されます。これは、単一の削除によって、すでに減少していない GCD シーケンスに新しい減少ペアを導入できないという事実と一致します。
