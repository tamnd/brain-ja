## 問題の理解

 私たちは、`n × n`非負の整数のグリッド。 左上隅から開始して、右下隅に到達するまで右または下にのみ移動します。 選択したパスに沿って、訪問したすべての値を掛け合わせます。 目標は、結果として得られる製品の末尾に末尾のゼロをできる限り少なくすることです。 

積に因子が含まれる場合は必ず末尾のゼロが表示されます`10`、そしてすべての`10`一つの要素から形成される`2`1 つの要素と組み合わせる`5`。 つまり、末尾のゼロの数は次のようになります。$\min(\text{count of factor }2,\ \text{count of factor }5)$したがって、グリッド内の実際の値自体は重要ではありません。 重要なのは、各数値が要因に何倍寄与するかです`2`そして`5`。 

グリッドのサイズは次のとおりです`1000 × 1000`、これは100万個の細胞があることを意味します。 有効なパスの数が膨大であるため、明示的にパスを探索するアルゴリズムは絶望的です。 からのパス`(0,0)`に`(n-1,n-1)`正確に含まれています`2n-2`が動き、どれを選ぶか`n-1`そのうち下向きです。 パスの総数は次のとおりです。$\binom{2n-2}{n-1}$のために`n = 1000`, この数字は天文学的な数字です。 理想的には次のような多項式時間の解決策が必要です。`O(n²)`。 

最も微妙なエッジ ケースには、グリッド内のゼロが含まれます。 ゼロを通過するパスは総積を生成します`0`、 そして`0`通常、末尾に少なくとも 1 つのゼロがあるとみなされます。 これにより、ゼロを含むパスが実際にはゼロ以外のすべてのパスよりも優れているという異常な状況が生じます。 

考慮する：```
2
1 10
1 0
```ゼロを回避するパスは積を与えます`10`、末尾にゼロが 1 つあります。 ゼロを通るパスは積を与える`0`、末尾に 0 が 1 つあるものとしても扱われます。 答えはまだあるはずです`1`。 

次に、次のことを考えてみましょう。```
2
10 10
10 0
```ゼロ以外のパスはすべて、`100`、末尾に 0 が 2 つあります。 ゼロを通過すると末尾のゼロは 1 つだけになるため、最適な答えは次のようになります。`1`。 

不注意な実装では、ゼロが次の無限係数に寄与するものとして扱われることがよくあります。`2`そして`5`これにより、ゼロを経由するパスが誤って禁止されてしまいます。 正しい処理は、ゼロが存在するかどうかを記憶し、それを通る特別なパスを潜在的に構築することです。 

もう 1 つの簡単な間違いは、両方向で同じ DP 値が与えられる場合にパスを誤って再構築することです。 親遷移が注意深く保存されていない場合、印刷されるルートが計算された最適値に対応しない可能性があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 左上隅から右下隅まですべての有効なパスを列挙し、そのパスに沿って積を計算し、末尾のゼロを数えて、最良の答えを保持します。 

これが機能するのは、問題の定義がパスに直接関連付けられているためです。 有効なルートはすべて個別にチェックできます。 問題はパスの数です。 パスは次のもので構成されます`n-1`下向きに移動し、`n-1`右方向に移動すると、次のようになります。$\binom{2n-2}{n-1}$のために`n = 20`、これはすでに 300 億のパスを超えています。 ブルートフォース手法は、実際の制限に達するずっと前に使用できなくなります。 

重要な観察は、末尾のゼロは素因数の数のみに依存するということです。`2`そして`5`。 すべてのセルについて、以下を事前計算できます。```
twos[i][j]  = exponent of 2 in grid[i][j]
fives[i][j] = exponent of 5 in grid[i][j]
```パスが溜まると`a`の要因`2`そして`b`の要因`5`の場合、末尾のゼロの数は次となります。`min(a, b)`。 

これにより問題は完全に変わります。 膨大な数を乗算する代わりに、パスに沿った追加コストのみが必要になります。 すべての動きは上または左の隣にのみ依存するため、動的プログラミングは自然になります。 

微妙な点が 1 つ残っています。 最小化`min(a, b)`最小値は同時に 2 つの量に依存するため、直接は厄介です。 秘訣は、2 つの別々の DP 問題を解決することです。```
minimum total factors of 2
minimum total factors of 5
```末尾のゼロが最小限のパスでは、これらのカウントのいずれかを最適化する必要があります。 最適なパスが`k`末尾のゼロ、その後のカウントのいずれか`2`に等しい`k`またはその数`5`に等しい`k`。 

したがって、DP を 2 回実行し、より良い結果を取得します。 

ゼロの場合は特別な処理が必要です。 すべての通常のパスに 1 より大きい答えがある場合、ゼロ セルは後続ゼロを 1 つだけ指定できます。 そのような状況では、意図的にゼロを通過するパスを構築します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | 指数再帰スタック | 遅すぎる |
 | 最適 | O(n²) | O(n²) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのセルについて、その値が何倍で割り切れるかを計算します。`2`そしてによって`5`。 

例えば、`40 = 2³ × 5¹`、つまり、次の 3 つの要素に寄与します。`2`そしてその要因の一つが`5`。 
2. セルに次の内容が含まれている場合`0`、その座標を別に覚えておいてください。 

両方の DP テーブルでゼロが非常に大きなコストに寄与するものとして一時的に処理されるため、後で明示的に必要になる場合を除き、通常の DP パスはゼロを回避します。 
3. 要因の DP テーブルを作成します。`2`。 

させて`dp2[i][j]`因子の最小合計数になる`2`細胞に到達するために必要な`(i,j)`。 

遷移：```
dp2[i][j] = twos[i][j] + min(top, left)
```4. 各セルに到達するために使用される方向を保存します。 

これにより、DP の終了後に実際のパスを再構築できるようになります。 
5. 因数に対して同じプロセスを繰り返します。`5`。 

これにより、別の DP テーブルが得られます`dp5`。 
6. 次のようにしましょう。```
best2 = dp2[n-1][n-1]
best5 = dp5[n-1][n-1]
```最良の通常のパスには次のような答えがあります。```
min(best2, best5)
```7. ゼロセルが存在するかどうかを確認します。 

普通の答えがすでにあるなら`0`、ゼロを使用しても改善できません。 

通常の答えがより大きい場合`1`、その後、ゼロを介してルーティングすると、正確に答えが得られます`1`、どちらの方が良いです。 
8. ゼロを使用する方が良い場合は、手動でパスを構築します。 

0 行に到達するまで下に移動し、0 列に到達するまで右に移動して、右下隅に向かって終了します。 
9. それ以外の場合は、保存されている親の方向を使用して、より適切な DP パスを再構築します。 

### なぜ効果があるのか

 整数積の場合、末尾のゼロは完全な積の数と等しくなります。`(2,5)`ペアを素因数分解します。 すべてのパスはセル間で独立して因子を蓄積するため、`2`と`5`s は加算的になります。 動的プログラミングでは、すべてのパスが`(i,j)`どちらかから来なければなりません`(i-1,j)`または`(i,j-1)`。 

最適なパスが次のとおりであると仮定します。`a`の要因`2`そして`b`の要因`5`。 末尾のゼロは次のとおりです。`min(a,b)`。 もし`a ≤ b`の場合、このパスは次の要因を最小限に抑えるのに最適です。`2`。 別のパスの数が少ない場合`2`s の場合、末尾のゼロも少なくなり、最適性と矛盾します。 対称的な議論は次の場合に当てはまります。`5`s. したがって、2 つの独立した DP 問題を解決すれば十分です。 

ゼロを通過するパスは積を生成するため、ゼロの処理は正しいです。`0`、この問題のコンテキストでは、末尾のゼロが 1 つだけ寄与します。 このようなパスは、すべての通常のパスに少なくとも 2 つの末尾ゼロがある場合にのみ重要になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**9

n = int(input())

twos = [[0] * n for _ in range(n)]
fives = [[0] * n for _ in range(n)]

zero_pos = None

for i in range(n):
    row = list(map(int, input().split()))
    
    for j in range(n):
        x = row[j]

        if x == 0:
            zero_pos = (i, j)
            twos[i][j] = INF
            fives[i][j] = INF
            continue

        cnt2 = 0
        while x % 2 == 0:
            cnt2 += 1
            x //= 2

        cnt5 = 0
        while x % 5 == 0:
            cnt5 += 1
            x //= 5

        twos[i][j] = cnt2
        fives[i][j] = cnt5

def build_dp(cost):
    dp = [[INF] * n for _ in range(n)]
    parent = [[''] * n for _ in range(n)]

    dp[0][0] = cost[0][0]

    for i in range(n):
        for j in range(n):
            if i == 0 and j == 0:
                continue

            if i > 0 and dp[i - 1][j] + cost[i][j] < dp[i][j]:
                dp[i][j] = dp[i - 1][j] + cost[i][j]
                parent[i][j] = 'D'

            if j > 0 and dp[i][j - 1] + cost[i][j] < dp[i][j]:
                dp[i][j] = dp[i][j - 1] + cost[i][j]
                parent[i][j] = 'R'

    return dp, parent

dp2, par2 = build_dp(twos)
dp5, par5 = build_dp(fives)

best2 = dp2[n - 1][n - 1]
best5 = dp5[n - 1][n - 1]

best = min(best2, best5)

if zero_pos is not None and best > 1:
    zi, zj = zero_pos

    path = []
    path.extend('D' * zi)
    path.extend('R' * zj)
    path.extend('D' * (n - 1 - zi))
    path.extend('R' * (n - 1 - zj))

    print(1)
    print(''.join(path))

else:
    if best2 < best5:
        parent = par2
        answer = best2
    else:
        parent = par5
        answer = best5

    path = []

    i = n - 1
    j = n - 1

    while i > 0 or j > 0:
        move = parent[i][j]
        path.append(move)

        if move == 'D':
            i -= 1
        else:
            j -= 1

    path.reverse()

    print(answer)
    print(''.join(path))
```前処理フェーズでは、すべてのグリッド値を因子の数に変換します。`2`そして`5`。 これにより、巨大な積の処理が回避され、乗算が単純な加算に変わります。 

ゼロ処理は通常の DP から意図的に分離されています。 割り当てる`INF`最適化中に誤ってゼロを使用することを防ぎます。 後で、ゼロパスが有益かどうかを明示的に決定します。 

の`build_dp`関数は、各セルがコストに寄与するグリッド上の最短パスを計算します。 親の方向は遷移中に保存されます。 保存された`'D'`これは、現在のセルが上から到達したことを意味するため、再構築すると再構築が上に移動します。 

実装の微妙な詳細の 1 つは、宛先から逆方向に再構築することです。 再構築中:```
'D' means we came from above
'R' means we came from the left
```それで、遡りながら、`'D'`行インデックスを減らし、`'R'`列インデックスを減らします。 

もう 1 つの微妙な点は比較です。```
if zero_pos is not None and best > 1:
```通常の最適値がすでに等しい場合`1`、ゼロを使用しても改善されないため、どちらの答えでも受け入れられます。 特別なゼロパスは、結果を厳密に改善する場合にのみ重要です。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n²) | 各 DP テーブルはすべてのセルを 1 回処理します。 
| スペース | O(n²) | DP テーブルと親テーブルはセルごとに 1 つの値を格納します。 

と`n ≤ 1000`、グリッドには最大 100 万個のセルが含まれます。 グリッド上の 2 つの DP パスは、Python の制限時間内に簡単に収まります。 各テーブルには整数または単一文字の方向のみが格納されるため、メモリ使用量も制限を大幅に下回ったままになります。

# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    INF = 10**9

    n = int(input())

    twos = [[0] * n for _ in range(n)]
    fives = [[0] * n for _ in range(n)]

    zero_pos = None

    for i in range(n):
        row = list(map(int, input().split()))

        for j in range(n):
            x = row[j]

            if x == 0:
                zero_pos = (i, j)
                twos[i][j] = INF
                fives[i][j] = INF
                continue

            cnt2 = 0
            while x % 2 == 0:
                cnt2 += 1
                x //= 2

            cnt5 = 0
            while x % 5 == 0:
                cnt5 += 1
                x //= 5

            twos[i][j] = cnt2
            fives[i][j] = cnt5

    def build(cost):
        dp = [[INF] * n for _ in range(n)]
        par = [[''] * n for _ in range(n)]

        dp[0][0] = cost[0][0]

        for i in range(n):
            for j in range(n):
                if i == 0 and j == 0:
                    continue

                if i > 0 and dp[i - 1][j] + cost[i][j] < dp[i][j]:
                    dp[i][j] = dp[i - 1][j] + cost[i][j]
                    par[i][j] = 'D'

                if j > 0 and dp[i][j - 1] + cost[i][j] < dp[i][j]:
                    dp[i][j] = dp[i][j - 1] + cost[i][j]
                    par[i][j] = 'R'

        return dp, par

    dp2, par2 = build(twos)
    dp5, par5 = build(fives)

    best2 = dp2[n - 1][n - 1]
    best5 = dp5[n - 1][n - 1]

    best = min(best2, best5)

    out = []

    if zero_pos is not None and best > 1:
        zi, zj = zero_pos

        path = []
        path.extend('D' * zi)
        path.extend('R' * zj)
        path.extend('D' * (n - 1 - zi))
        path.extend('R' * (n - 1 - zj))

        out.append("1")
        out.append(''.join(path))

    else:
        if best2 < best5:
            par = par2
            ans = best2
        else:
            par = par5
            ans = best5

        path = []

        i = n - 1
        j = n - 1

        while i > 0 or j > 0:
            move = par[i][j]
            path.append(move)

            if move == 'D':
                i -= 1
            else:
                j -= 1

        path.reverse()

        out.append(str(ans))
        out.append(''.join(path))

    print('\n'.join(out))

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    return sys.stdout.getvalue()

 グリッドについて考えてみましょう。```
2

10 0
```すべての通常のパスには少なくとも 2 つの要素が蓄積されます`2`そして2つの要因`5`、末尾に 2 つのゼロを付けます。 前処理中にゼロセルはコストを受け取ります`INF`、したがって DP はそれを回避して答えを計算します`2`。 

次に、アルゴリズムは以下をチェックします。```
zero exists AND best > 1
```両方の条件が成立するため、ゼロを通るルートが構築されます。```

```製品は、`10 × 10 × 0 = 0`、末尾のゼロが 1 つだけ生成されます。 最終的な答えは正解です。
