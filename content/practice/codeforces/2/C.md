## 問題の理解

 平面上に 3 つの円が与えられます。 各円は中心点と半径を持つスタジアムを表します。 3 つのスタジアムすべてが同じ角度で見えるポイントを見つける必要があります。 

半径のある円の場合$r$ある点から観察した$P$、可視角度は、からの 2 つの接線の間の角度です。$P$サークルへ。 からの距離の場合$P$円の中心までは$d$、その角度は次と等しくなります。$$2\arcsin\left(\frac{r}{d}\right)$$この問題では、3 つの円すべてが同じ視野角を生み出す点を求めます。 そのようなすべての点の中で、最大の角度を持つ点が必要です。 

中心は同一線上にないことが保証されているため、ジオメトリが線ベースのあいまいさに悪化することはありません。 座標と半径は最大でも$10^3$これは、浮動小数点ジオメトリが完全に実現可能であることを意味します。 制限時間はわずかですが、これは強引な数値最適化問題ではありません。 意図したソリューションは、定数時間の計算のみを使用する閉形式ジオメトリです。 

重要な隠された観察は、等しい視野角は非常に強力な代数的条件を意味するということです。 以来$$2\arcsin\left(\frac{r_i}{d_i}\right)$$すべての円で値が等しくなければなりません$$\frac{r_i}{d_i}$$も等しくなければなりません。 並べ替えると$$d_i : d_j = r_i : r_j$$したがって、未知の点は 3 つの中心までの距離が 3 つの半径に比例します。 

これにより、問題が三角関数の最適化タスクから純粋な幾何学構築問題に変換されます。 

ここには簡単な間違いがいくつかあります。 

よくある間違いの 1 つは、反復最適化を使用して角度を直接最大化することです。 角度関数は非線形であり、実行可能領域は凸ではありません。 数値的な山登りは、間違った点に収束したり、完全に失敗したりする可能性があります。 

もう 1 つの間違いは、有効なポイントがない可能性があることを忘れていることです。 考慮する：```
0 0 1
10 0 1
0 10 100
```3 番目の半径は他の半径よりも非常に大きいです。 必要な距離比を幾何学的に満たすことができなくなる。 円をやみくもに交差させる不注意な実装では、NaN またはガベージ座標が生成される可能性があります。 正しい動作は何も出力しないことです。 

すべての半径が等しい場合、さらに微妙な問題が発生します。 この場合、条件は 3 つの中心すべてに等しい距離になります。 答えは、中心によって形成される三角形の外心です。 

例：```
0 0 10
60 0 10
30 30 10
```正しい答えは次のとおりです。```
30.00000 0.00000
```素朴な比率ベースの導出では、半径が別個であると仮定すると、誤ってゼロで除算してしまう可能性があります。 

もう 1 つの罠は、間違ったアポロニウス サークル ブランチを選択することによって発生します。 距離比軌跡は円を生成しますが、中心の各ペアは方向に応じて複数の代数形式を定義できます。 符号の間違いによりミラー化された交点が生成され、3 番目の制約に失敗します。 

## アプローチ

 この強引なアイデアは、平面上を検索し、各点で 3 つの視野角を評価することです。 角度がほぼ等しい場合は、最良の候補を保持します。 

点からの円の可視角度は簡単に計算できるため、これは概念的に機能します。$$\theta = 2\arcsin\left(\frac{r}{d}\right)$$密なグリッドをサンプリングしたり、勾配上昇を実行したりできます。 問題は精度です。 座標は実数値であり、有効な点は平面内のどこにでも配置できます。 間隔のあるグリッドでも$10^{-5}$可能な座標範囲にわたって大まかに必要になります$10^{16}$評価、全く無理です。 

次の改善は、等角条件を代数的に処理することです。 arcsin は厳密に増加しているため、$$2\arcsin\left(\frac{r_1}{d_1}\right) = 2\arcsin\left(\frac{r_2}{d_2}\right)$$暗示する$$\frac{r_1}{d_1}=\frac{r_2}{d_2}$$または同等の$$\frac{d_1}{d_2}=\frac{r_1}{r_2}$$ここで、問題は幾何学的なものになります。3 つの中心までの距離が所定の比率を持つ点を見つけます。 

満足のいく点の軌跡$$\frac{|PA|}{|PB|}=k$$がアポロニウス円の場合$k \ne 1$、および垂直二等分線の場合$k=1$。 

したがって、そのような 2 つの遺伝子座を構築できます。$$\frac{|PA|}{|PB|}=\frac{r_1}{r_2}$$そして$$\frac{|PA|}{|PC|}=\frac{r_1}{r_3}$$それらの交点が候補点になります。 

最適化の基準もシンプルになります。 公比を大きくすると視野角が広がります。$$\frac{r_i}{d_i}$$増加する、つまり距離が縮まるということです。 考えられる交差点のうち、中心に近い方を選択します。 

幸いなことに、ジオメトリはさらに単純化されます。 方程式を二乗して減算すると、システムは線形になります。 円を明示的に交差させる代わりに、2 つの線形方程式を導出し、それらを直接解くことができます。 

ソリューション全体は一定時間で実行されます。

 ## アルゴリズムのチュートリアル

 1. 3 つの円の中心と半径を読み取ります。 

サークルをそのままにしておきます$(x_i,y_i,r_i)$。 
2. 知られざる観測点を紹介$P=(x,y)$。 

視野角が等しいということは、次のことを意味します。$$\frac{r_1}{d_1}=\frac{r_2}{d_2}=\frac{r_3}{d_3}$$どこ$$d_i^2=(x-x_i)^2+(y-y_i)^2$$1. 比率条件を次のように書き換えます。$$\frac{d_1^2}{r_1^2}=\frac{d_2^2}{r_2^2}$$サークルについても同様に$1$そして$3$。 

すべての距離が負ではないため、二乗では等価性を維持しながら平方根が削除されます。 

1. 方程式を展開します。 

サークル向け$1$そして$2$:$$\frac{(x-x_1)^2+(y-y_1)^2}{r_1^2} = \frac{(x-x_2)^2+(y-y_2)^2}{r_2^2}$$1. 方程式を並べ替えます。 

二次項は次のように結合されます。$$ax^2+ay^2+bx+cy+d=0$$どこ$$a=\frac1{r_1^2}-\frac1{r_2^2}$$1. 円を使用して 2 番目の方程式を作成します。$1$そして$3$。 
2. 二次項を削除します。 

方程式を適切に乗算し、減算します。 どちらも同じ内容なので、$x^2+y^2$構造では、減算により非線形部分が削除されます。 

その結果、次のような線形システムが得られます。$x$そして$y$。 
3. 結果として得られる結果を解決します。$2 \times 2$行列式を使ったシステム。 

中心が同一線上にないため、有効な解が存在する場合、行列式は非ゼロになります。 
4. 座標を小数点以下 5 桁で出力します。 
5. 行列式が実質的にゼロの場合は、何も出力しません。 

### なぜ効果があるのか

 重要な不変条件は、等しい視野角が観測点から中心までの比例距離に正確に等しいということです。 

円の視野角は比率のみに依存します$r/d$。 arcsin は有効な領域では厳密に単調であるため、角度が等しいとすべての比率が強制されます。$r_i/d_i$平等であること。 

二乗して展開すると、すべての制約は同じ二次項を共有する二次方程式になります。$x^2+y^2$。 このような 2 つの方程式を減算すると、すべての非線形成分が除去され、元の距離比を満たす固有の点を正確に解とする線形方程式が残ります。 

導出はすべてのステップで代数的に等価であるため、計算された解はすべて元の幾何学的条件を満たします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

EPS = 1e-12

def solve():
    circles = [tuple(map(float, input().split())) for _ in range(3)]

    x1, y1, r1 = circles[0]
    x2, y2, r2 = circles[1]
    x3, y3, r3 = circles[2]

    def build(ca, cb):
        xa, ya, ra = ca
        xb, yb, rb = cb

        ia = 1.0 / (ra * ra)
        ib = 1.0 / (rb * rb)

        a = ia - ib
        b = -2.0 * xa * ia + 2.0 * xb * ib
        c = -2.0 * ya * ia + 2.0 * yb * ib
        d = (xa * xa + ya * ya) * ia - (xb * xb + yb * yb) * ib

        return a, b, c, d

    e1 = build(circles[0], circles[1])
    e2 = build(circles[0], circles[2])

    a1, b1, c1, d1 = e1
    a2, b2, c2, d2 = e2

    A1 = a2 * b1 - a1 * b2
    B1 = a2 * c1 - a1 * c2
    C1 = a2 * d1 - a1 * d2

    det = A1 * (-B1) - B1 * (-A1)

    if abs(A1) < EPS and abs(B1) < EPS:
        return

    if abs(B1) > EPS:
        # A1*x + B1*y + C1 = 0
        # y = (-A1*x - C1)/B1

        # Plug into first quadratic equation
        p = -A1 / B1
        q = -C1 / B1

        aa = a1 * (1 + p * p)
        bb = b1 + 2 * a1 * p * q + c1 * p
        cc = a1 * q * q + c1 * q + d1

        disc = bb * bb - 4 * aa * cc

        if disc < -EPS:
            return

        disc = max(disc, 0.0)
        sq = disc ** 0.5

        xs = [
            (-bb + sq) / (2 * aa),
            (-bb - sq) / (2 * aa)
        ]

        best = None
        bestv = -1

        for x in xs:
            y = p * x + q

            d = ((x - x1) ** 2 + (y - y1) ** 2) ** 0.5
            val = r1 / d

            if val > bestv:
                bestv = val
                best = (x, y)

        x, y = best
        print(f"{x:.5f} {y:.5f}")

    else:
        x = -C1 / A1

        aa = a1
        bb = 2 * a1 * x + c1
        cc = a1 * x * x + b1 * x + d1

        disc = bb * bb - 4 * aa * cc

        if disc < -EPS:
            return

        disc = max(disc, 0.0)
        sq = disc ** 0.5

        ys = [
            (-bb + sq) / (2 * aa),
            (-bb - sq) / (2 * aa)
        ]

        best = None
        bestv = -1

        for y in ys:
            d = ((x - x1) ** 2 + (y - y1) ** 2) ** 0.5
            val = r1 / d

            if val > bestv:
                bestv = val
                best = (x, y)

        x, y = best
        print(f"{x:.5f} {y:.5f}")

```の`build`関数は、1 つの比率制約に対応する二次方程式を構築します。 各方程式の形式は次のとおりです。$$a(x^2+y^2)+bx+cy+d=0$$重要な観察は、両方の方程式に同じ二次構造が含まれていることです。 適切なスケーリング後にそれらを減算すると、非線形項が除去され、直線が生成されます。 

その直線を取得したら、それを 1 つの二次方程式に代入します。 これにより、問題は単一変数の 2 次方程式に帰着します。 

幾何学的に 2 つの候補点が存在する可能性があります。 一方は他方よりも大きな視野角をもたらします。 角度が大きくなるので、$r/d$、単純に最大化します$r_1/d_1$。 

判別処理は微妙です。 浮動小数点誤差により小さな負の値が発生する可能性があるため、実装では平方根を求める前にゼロに近い負の値をゼロにクランプします。 

ラインが縦になる枝も微妙なポイントです。 直接解決する$y$ゼロで除算することになるため、コードはそれを個別に処理します。

 等しい半径を考慮します。```
