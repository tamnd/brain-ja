## 問題の理解

 ゲームは一連のラウンドを記録します。 各ラウンドで、1 人のプレイヤーが一定のポイントを獲得または失います。 最終的に、合計スコアが最も高いプレイヤーが勝利する必要があります。 

難しい部分は、複数のプレイヤーが同じ最高スコアで終了した場合に現れます。 その場合、勝者は恣意的に選ばれるわけではありません。 最終スコアが最大値に等しいすべてのプレイヤーの中から、ゲーム中に最初にそのスコアに到達したプレイヤーを選択します。 

インプットはすでに時系列順に与えられているため、ラウンドの順序が重要になります。 各行にはプレーヤーの名前とそのラウンドのスコアの変化が含まれます。 ゲーム中にスコアがマイナスになる可能性があり、プレイヤーは最終的な勝利スコアを何度も上下する可能性があります。 

制約は十分に小さいため、ほぼすべての適切な実装が合格します。 最大でも 1000 ラウンドなので、$O(n^2)$ソリューションは約 100 万回の操作のみを実行します。 制限時間内に簡単に収まります。 それでも、問題は最適化に関するものではなく、タイブレーク ルールを正しく処理することに関するものです。 

最もよくある間違いは、最終スコアだけで勝者を決めることです。 次の入力を考えてみましょう。```
4
alice 5
bob 5
alice -2
bob -2
```両選手とも勝ち点３で終了。 アリスは、最初の移動後にすでに 5 を持っていたため、最初に 3 に到達しました。ボブは後で 3 に到達しました。 正しい答えは次のとおりです。```
alice
```最終合計をチェックするだけの不注意な解決策では、このケースを区別できません。 

もう 1 つの微妙なケースは、プレーヤーが早期に目標スコアに到達したが、最大スコアで終了しない場合に発生します。```
5
alice 10
bob 3
alice -8
bob 5
bob 2
```最終スコアは次のとおりです。```
alice = 2
bob = 10
```アリスは最初に 10 に到達しましたが、最終スコアが最大値ではないため、資格がありません。 勝者は次のとおりです。```
bob
```実装が間違っていると、最大スコアに到達した最初のプレイヤーが誤って選択される可能性があります。 

負の値との重要な相互作用もあります。```
5
alice 2
bob 3
alice 3
bob -1
alice -2
```最終スコア:```
alice = 3
bob = 2
```最終的な最大スコアは 3 です。以前は一時的に 5 を獲得していましたが、アリスが勝者になります。 このルールは、少なくとも最終的な最大スコアに到達することに基づいており、ラウンド終了時に必ずしもそれと正確に一致するとは限りません。 

## アプローチ

 ブルートフォース ソリューションでは、ゲーム全体をシミュレートし、各ラウンド後にすべてのプレイヤーのスコアを繰り返し再計算できます。 ラウンドごとに、以前のすべてのラウンドをスキャンして現在の合計を決定し、誰かがすでに勝者の資格があるかどうかを判断することができます。 

制約が小さいため、これは機能します。 と$n = 1000$、$O(n^2)$このソリューションは約 100 万回の更新を実行しますが、これは完全に許容可能です。 

このアプローチの問題はパフォーマンスではなく、明確さです。 タイブレーク条件は、スコアに関する 2 つの異なる概念によって異なります。 

まず、全プレイヤーの最終的な最大スコアです。 

2 番目は、最終的にその最大値を達成したプレイヤーがゲーム中にその最大値に到達した最も早い瞬間です。 

両方を同時に計算しようとすると面倒になります。 

より明確な観察は、問題が自然に 2 つのパスに分割されていることです。 

最初のパスでは、すべてのプレイヤーの最終スコアを計算します。 このパスが終了すると、最終的な最大スコアがわかります$mx$。 

タイブレークのルールは非常に簡単になりました。 最終スコアが等しいプレイヤーのみを考慮します$mx$。 その選手の中で、走破点が最低でも1位になった選手が欲しいです。$mx$。 

それは非常にダイレクトなセカンドパスにつながります。 現在の合計を維持しながら、ゲームを時系列順にリプレイします。 プレイヤーが両方の条件を満たすとすぐに:

 1. 最終スコアは等しい$mx$。 
2. 彼らのランニングスコアは少なくとも$mx$。 

そのプレイヤーが答えに違いない。 

2 番目の条件では、「等しい」ではなく「少なくとも」を使用します。これは、プレイヤーが後で正確に終了する前に目標スコアをオーバーシュートする可能性があるためです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 承認済み |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ゲームを 2 回処理する必要があるため、すべてのラウンドを読み取り、リストに保存します。 
2. 最初のパスでは、辞書を維持します。`final_score[name]`すべてのラウンド後の各プレイヤーの合計スコアを保存します。 
3. 各ラウンドの処理後、最大最終スコアを計算します。`mx`。 
4. 時系列順にラウンドの 2 回目のパスを開始します。 別の辞書を管理する`current_score[name]`ゲームプレイ中のスコアを表します。 
5. ラウンドごとに、そのプレーヤーのランニング スコアを更新します。 
6. ランニングスコアを更新した後、次の 2 つの条件を確認します。 

1. プレイヤーの最終スコアは次のとおりです`mx`。 
2. プレーヤーのランニングスコアは少なくとも`mx`。 
7. 両方の条件を最初に満たしたプレイヤーが勝者となります。 名前を印刷し、すぐに停止してください。 

これが機能する理由は、最終スコアを持つプレイヤーだけが`mx`勝つ資格がある。 2 番目のパスでは、ラウンドが時系列順に処理されるため、誰が最も早くターゲットに到達したかがわかります。 

### なぜ効果があるのか

 最初のパスの後、`mx`ゲーム終了時に達成された最高スコアです。 最終スコアが小さいプレイヤーは、一時的なスコアが以前にどれだけ大きくなったとしても、勝つことはできません。 

2回目のパス中に、`current_score[name]`現在のラウンド後のそのプレイヤーのスコアと常に等しくなります。 現在の合計が最低以上になった最初の資格のあるプレーヤー`mx`まさに、ゲーム中に最初に勝利の基準に到達したプレーヤーです。 

ラウンドは順番に処理されるため、後のプレーヤーが先にしきい値に到達することはできません。 それは正確さを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())

rounds = []
final_score = {}

for _ in range(n):
    name, score = input().split()
    score = int(score)

    rounds.append((name, score))

    if name not in final_score:
        final_score[name] = 0

    final_score[name] += score

mx = max(final_score.values())

current_score = {}

for name, score in rounds:
    if name not in current_score:
        current_score[name] = 0

    current_score[name] += score

    if final_score[name] == mx and current_score[name] >= mx:
        print(name)
        break
```このソリューションは 2 パス構造に直接従います。 

最初のループはすべてのラウンドを保存し、最終的な合計を計算します。 2 番目のパスでは時系列順にゲームを再実行する必要があるため、ラウンドをリストに保存することが必要です。 

辞書`final_score`すべてのラウンド後の各プレイヤーのスコアをマップします。 Once the first pass finishes,`mx`が勝利の最終スコアとなります。 

2 番目のループでは、ゲームを段階的に再構築します。 辞書`current_score`最終的な合計ではなく、ゲームプレイ中のスコアを追跡します。 

操作の順序が重要です。 まずランニングスコアを更新し、次にプレーヤーが資格があるかどうかを確認します。 更新前にチェックを行うと、すべてのスコアが 1 ラウンドずれてしまい、不正確な回答が生成されてしまいます。 

条件:```
current_score[name] >= mx
```微妙ですが不可欠です。 勝利スコアが 5 で、プレーヤーが一時的に 7 に到達し、その後 5 で終了したとします。 彼らは依然として、より早く目標に到達したものとしてカウントされます。 

ラウンドは時系列に処理されるため、最初の有効なプレイヤーを見つけた直後にブレイクするのは正しいことです。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各ラウンドは 2 回処理されます。 
| スペース | O(n) | 辞書と格納されたラウンドは線形空間を使用します。 

最大 1000 ラウンドであれば、解は問題なく制限内に収まります。 はるかに遅いアプローチでも合格する可能性がありますが、線形の解決策はよりクリーンで、問題の構造と自然に一致します。 

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    n = int(input())

    rounds = []
    final_score = {}

    for _ in range(n):
        name, score = input().split()
        score = int(score)

        rounds.append((name, score))

        final_score[name] = final_score.get(name, 0) + score

    mx = max(final_score.values())

    current_score = {}

    for name, score in rounds:
        current_score[name] = current_score.get(name, 0) + score

        if final_score[name] == mx and current_score[name] >= mx:
            print(name)
            return

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    output = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return output.strip()

# provided sample
assert run(
"""3
mike 3
andrew 5
mike 2
"""
) == "andrew", "sample 1"

# minimum input size
assert run(
"""1
alice 10
"""
) == "alice", "single round"

# tie resolved by earliest reach
assert run(
"""4
alice 5
bob 5
alice -2
bob -2
"""
) == "alice", "earliest reach wins"

# temporary high score should not matter
assert run(
"""5
alice 10
bob 3
alice -8
bob 5
bob 2
"""
) == "bob", "must finish with maximum"

# negative values and multiple crossings
assert run(
"""6
a 2
b 3
a 3
b 2
a -2
b -1
"""
) == "b", "running totals handled correctly"

# all players equal final score
assert run(
"""6
x 1
y 2
x 1
y 0
x 0
y 0
"""
) == "y", "first to reach maximum among tied players"
```| テスト入力 | 期待される出力 | 検証内容 |

 ## 特殊なケース

 2 人のプレイヤーが同じスコアで終了したが、1 人のプレイヤーが先にそのスコアに到達した場合を考えてみましょう。```
4
alice 5
bob 5
alice -2
bob -2
```最終スコアは次のとおりです。```
alice = 3
bob = 3
```最終スコアの最大値は 3 です。 

2 回目のパス中:```
alice reaches 5 after round 1
bob reaches 5 after round 2
```どちらのランニングスコアも最初に登場した時点ですでに少なくとも 3 ですが、アリスは時系列的には早い段階で登場します。 アルゴリズムはすぐに出力します`alice`。 

次に、一時的にリードしたものの、最初にゴールしなかったプレーヤーを考えてみましょう。```
5
alice 10
bob 3
alice -8
bob 5
bob 2
```最終スコアの最大値は 10 です。リプレイ中、アリスは最初に 10 に到達しますが、最終スコアはわずか 2 です。条件:```
final_score[name] == mx
```彼女を正しく拒否します。 ボブは最終的に 10 に到達し、勝利します。 

最後に、ターゲット スコアを繰り返し通過することを考えてみましょう。```
6
a 2
b 3
a 3
b 2
a -2
b -1
```最終スコア:```
a = 3
b = 4
```勝利の最終スコアは 4 です。 

リプレイ:```
a: 2
b: 3
a: 5
b: 5
```いつ`b`が 5 に達すると、実行スコアは少なくとも 4 で、最終スコアは 4 に等しいため、`b`すぐに勝ちます。 アルゴリズムはそれを気にしません`a`先ほど4を超えたので、`a`合計勝利数に届かなかった。
