 ## 問題の理解

 長さの順列を数えるように求められます`n`その最長の増加サブシーケンスは、要素を 2 回使用することなく、同じ最大長の 2 つの増加サブシーケンスに分割できます。 答えは必須です`998244353`。 入力は順列のサイズのみであるため、タスクは純粋に組み合わせです。このプロパティを持つ順列の数を数えます。 元の制約は次のとおりです`1 ≤ n ≤ 75`、これにより、ソリューションは以下に指数関数的に依存します。`n`不可能ですが、整数分割の数に基づくアルゴリズムは可能です。`n`。 

問題の背後にある重要なオブジェクトは、ロビンソン-シェンステッド対応によって生成される形状です。 順列はヤング図の形状に変換されます`λ`。 最初の行の長さが LIS の長さです。 この問題は、この図形の最初の 2 行が同じ長さになるのはいつかを正確に尋ねます。 この翻訳が行われると、問題は順列ではなくタブローを数えることになります。 

直接実装では、小さいサイズを正しく処理する必要があります。 たとえば、`n = 1`、唯一の順列は`[1]`。 LIS には長さがあります`1`ただし、長さが増加する 2 つの素な部分列を選択する方法はありません。`1`、したがって、答えは次のとおりです`0`。 最初の行が存在するかどうかだけをチェックするソリューションでは、最初の行が誤ってカウントされます。 

のために`n = 2`、順列は`[1,2]`そして`[2,1]`。 最初のものは LIS 長です`2`、つまり、長さの 2 つの素な部分列`2`不可能です。 2 番目は LIS 長です`1`、そして 2 つの要素は 2 つの別々の増加部分列を形成できるため、答えは次のようになります。`1`。 これにより、2 つのサブシーケンスが両方とも最適な長さでなければならないことを忘れる実装が捕捉されます。 

## アプローチ

 ブルートフォースソリューションでは、すべてが列挙されます。`n!`順列を計算し、それぞれの LIS の長さを計算し、2 つの互いに素な LIS が存在するかどうかをテストします。 チェック自体は動的プログラミングで実行できますが、順列列挙が優先されます。 で`n = 10`、これはすでに約について意味します`3,628,800`順列、および`n = 75`その数は実際の計算を超えています。 

重要な観察は、問題が正確な順列順序に依存しないことです。 ロビンソン-シェンステッド対応では、ヤング図の形状によって順列をグループ化します。 固定形状の場合`λ`、それを生成する順列の数は、その形状の標準的な若いタブローの数の 2 乗です。 

LIS の長さは、次の最初の行の長さです。`λ`。 2 つの互いに素な増加サブシーケンスの最大の合計長は、最初の 2 つの行の長さの合計です。 この値が LIS 長の 2 倍に等しい場合、順列は適切です。これは、次のことを意味します。`λ[0] + λ[1] = 2 * λ[0]`したがって、最初の 2 行は等しくなければなりません。 

のパーティションごとに、`n`この条件を満たす場合、フックの長さの公式を使用して標準的なヤング タブローの数を計算します。`f(λ) = n! / product(hook(cell))`形状の寄与は`f(λ)^2`。 

パーティションの数`75`十分に小さいため、すべてのパーティションを反復処理してそのフック積を計算するのは簡単に十分に高速です。

 ## アルゴリズムのチュートリアル

 1. すべての整数パーティションを生成します。`n`昇順ではない順に。 各パーティションは、可能なヤング線図の形状を表します。 
2. 最初の 2 行の長さが等しいパーティションのみを保持します。 パーティションの行数が 2 行未満の場合、適切な順列を表すことができません。 
3. 有効な形状ごとに、フック長の公式を使用して標準的なヤング タブローの数を計算します。 各セルのフックの長さは、その右側のセルの数にその下のセルの数を加えたものに 1 を加えたものになります。 
4. タブロー数を二乗し、それを答えのモジュロに加算します。`998244353`。 
5. 累積値を出力します。 

これが機能する理由は、Robinson-Schensted が固定形状の順列とその形状の標準的なヤング タブローのペアの間の全単射を与えるためです。 したがって、形状は正確に寄与します`f(λ)²`順列。 LIS の長さと 2 つの互いに素な増加サブシーケンスの最大サイズは最初の 2 行によって決まるため、良好であるための条件も形状によって完全に記述されます。 このアルゴリズムは、考えられるすべての形状をチェックし、有効な形状によって表される順列を正確に追加します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

n = int(input())

fact = [1] * (n + 1)
for i in range(1, n + 1):
    fact[i] = fact[i - 1] * i % MOD

ans = 0

def hook_tableau_count(part):
    cells = []
    rows = len(part)
    for i, length in enumerate(part):
        for j in range(length):
            cells.append((i, j))

    prod = 1
    for i, j in cells:
        right = part[i] - j - 1
        below = 0
        for k in range(i + 1, rows):
            if part[k] > j:
                below += 1
        prod = prod * (right + below + 1) % MOD

    return fact[n] * pow(prod, MOD - 2, MOD) % MOD

def generate(rem, last, cur):
    global ans

    if rem == 0:
        if len(cur) >= 2 and cur[0] == cur[1]:
            f = hook_tableau_count(cur)
            ans = (ans + f * f) % MOD
        return

    for x in range(min(last, rem), 0, -1):
        cur.append(x)
        generate(rem - x, x, cur)
        cur.pop()

generate(n, n, [])

print(ans)
```階乗配列は格納します`n!`、すべてのフックの長さの計算に表示されます。 フック積の逆数は、係数が素数であるため、べき乗剰余で計算されます。 

パーティション ジェネレーターは常に、前の行の長さ以下の次の行を選択します。 これにより、同じヤング図を異なる順序で複数回生成することが回避されます。 

条件`len(cur) >= 2 and cur[0] == cur[1]`パーティションに行が 1 つだけある場合を処理します。 このような形状では、必要なサイズの 2 つの互いに素な LIS を提供することはできません。 

式には除算が含まれますが、すべてのフックの長さは係数よりも小さくなります。`n ≤ 75`、したがってモジュラー逆行列は常に存在します。

## テストケース```python
import sys
import io

MOD = 998244353

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n = int(input())

    fact = [1] * (n + 1)
    for i in range(1, n + 1):
        fact[i] = fact[i - 1] * i % MOD

    ans = 0

    def count(part):
        prod = 1
        for i, row in enumerate(part):
            for j in range(row):
                hook = row - j
                for k in range(i + 1, len(part)):
                    if part[k] > j:
                        hook += 1
                prod = prod * hook % MOD
        return fact[n] * pow(prod, MOD - 2, MOD) % MOD

    def gen(rem, last, cur):
        nonlocal ans
        if rem == 0:
            if len(cur) >= 2 and cur[0] == cur[1]:
                x = count(cur)
                ans = (ans + x * x) % MOD
            return
        for x in range(min(last, rem), 0, -1):
            cur.append(x)
            gen(rem - x, x, cur)
            cur.pop()

    gen(n, n, [])
    return str(ans)

assert solve("6\n") == "132"
assert solve("1\n") == "0"
assert solve("2\n") == "1"
assert solve("3\n") == "4"
assert solve("4\n") == "10"

 ## 特殊なケース

 のために`n = 1`、唯一の形状は`(1)`。 2 番目の行がないため、アルゴリズムはこれを拒否します。 これにより、LIS はあるものの、それを 2 つの素な LIS に分割できない順列をカウントすることができなくなります。 

のために`n = 2`、有効な形状は次のとおりです。`(1,1)`。 フックの長さは、`2`そして`1`、したがって、タブローの数は`2! / 2 = 1`。 二乗すると 1 つの順列が得られます。これはまさに減少する順列です。 

大型の場合`n`、最初の行が長く、2 番目の行が短いパーティションは無視されます。 例えば、`(5,1)`最も長く増加するサブシーケンスに長さがあるため、寄与できません`5`、ただし長さの 2 つの素な部分列`5`最初の 2 行を合わせて少なくとも次の内容を含める必要があります。`10`細胞。 形状条件は、個々の順列を検査することなくこれを捕捉します。
