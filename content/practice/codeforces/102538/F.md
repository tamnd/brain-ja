 ## 解決策
 ## 問題の理解

 モンスターのラインナップがあります。 モンスター`i`から始まる`h[i]`健康ポイント。 各ターンで、生きているモンスターを攻撃し、その体力を減らすことができます。`a`、または順番を飛ばしてください。 対戦相手は常に左端の生きているモンスターを攻撃し、その体力を次のように減らします。`b`。 私たちの攻撃のいずれかがモンスターを倒すたびに、1 ポイントを獲得します。 目標は、私たちが個人的に仕上げるモンスターの数を最大化することです。 

対戦相手は自由にターゲットを選択しないため、順序は重要です。 インデックスが小さいモンスターは、それが死ぬまでその後のモンスターをすべてブロックするため、モンスターが受ける相手の攻撃の数は、前のモンスターの決定に依存します。 このプロセスを考えるのに役立つのは、ターンのシミュレーションとしてではなく、利用可能な動きのバランスとして考えることです。 敵が攻撃するたびに、今後のキルを準備する時間が与えられますが、モンスターに攻撃を費やすたびに 1 つの移動が消費されます。 

制約`n <= 300000`ターン数に比例する作業を実行するシミュレーションは除外されます。 健康値は最大で`10^9`, そのため、攻撃の総数は膨大になる可能性があります。 アルゴリズムは、すべてのモンスターを定数または対数の回数だけ処理する必要があり、これは貪欲なソリューションまたはデータ構造ベースのソリューションを指します。 

よくある間違いは、モンスターを独立して扱うことです。 たとえば、同じ攻撃力と体力の​​モンスターが 3 体いる場合、`1 1 1`、すべてのモンスターを独立して決定する戦略では、3 つすべてを殺せると考えるかもしれません。 実際には、モンスターを 1 匹倒した後でも、相手はこちらの攻撃の間にターンを得ることができ、利用可能な先手アドバンテージは限られています。 The correct answer is`2`。 

もう一つの間違いは、初動の利点を忘れていることです。 入力あり`3 1 1`そして健康`2 2 2`、正解は`3`。 勝利の戦略は、モンスターの体力が 1 つ残るまで待ち、対戦相手が除去する前にモンスターを終わらせることです。 最初の動きを通常の相手ターンとして扱うと、この可能性が失われます。 

## アプローチ

 直接的なアプローチは、選択肢をシミュレートすることです。 モンスターごとに、私たちは攻撃をかけてそれを倒すか、それとも相手に任せるかを決定します。 すべての選択の後、戦いをシミュレーションし、勝利を数えます。 考えられるあらゆる戦略が検討されているため、これは正しいですが、モンスターごとに 2 つの選択肢があります。`2^n`可能性。 シミュレーションコストを考慮する前に、これは不可能になります。`n`数十万に達します。 

重要な点は、攻撃の正確な順序を知る必要がないということです。 どのモンスターを倒したいかを決めるとします。 選択した 1 つのモンスターに対して、必要以上にそれを攻撃する理由はありません。 させて`r`モンスターがもう 1 回の攻撃で倒される状態に達するまでの最小ヒット数です。 このモンスターに対する最適なヒット数はまさに`r + 1`。 

の式は、`r`対戦相手の攻撃サイクルに応じて残りの体力を調べることで得られます。 すべての健康値を 1 つ減らした後、最小値が必要になります。`r`次のような:```
(h - r * a) mod b < a
```値は次のとおりです。```
r = floor(b * (h mod a) / a)
```モンスターが私たちによって殺されたかどうかを決定した後、その効果を利用可能な手の数の変化として表現できます。 こちらが殺さなければ相手は消費する`h`それに対する攻撃。 仕留めれば、相手の動きとこちらの動きの差がまた一つの価値になります。 この選択を、すべてのモンスターが対戦相手に任せられるベースラインと比較します。 

モンスター用`i`、 させて`y[i]`それは、それを無視するのではなく殺すことを選択したことによって引き起こされる変化です。 できるだけ多く選択する必要があります`y[i]`すべてのプレフィックスを有効に保ちながら、可能な限り値を設定します。 これは古典的な貪欲な選択の問題になります。 モンスターを左から右にスキャンし、選択されたすべての値をヒープに保持し、接頭辞が不可能になった場合は、選択された最悪のモンスターを削除します。 最悪の除去が最大である`y[i]`より大きな値を削除すると、選択されたモンスターの数が最も少なくなる一方で制約が修正されるためです。

 ## アルゴリズムのチュートリアル

 1. すべてのモンスターの体力を 1 減らします。 これにより、健康状態に達するまでの殺害条件が変更されます`0`これにより、モジュラー計算がよりクリーンになります。 
2. すべてのモンスターについて、最後の殺害攻撃までの最小攻撃回数を計算します。 値は`r = (b * (h % a)) // a`。 
3. このモンスターを自分たちで倒した場合の利益を計算してください。 生きたままにしておくと、その貢献度は次のようになります。`h`。 私たちがそれを殺した場合、その貢献は次のようになります。```
b * ((h - r * a) // b) - (r + 1)
```これら 2 つの値の差は次のとおりです。`y`。 

1. 選択した合計を維持します`y`モンスターを左から右にスキャンしながら値を変更します。 Also maintain the current sum of all original`h`このプレフィックスの値。 
2. 現在の値を追加します`y`最大ヒープまで。 選択した変更が大きすぎてプレフィックス条件に違反する場合は、最大の変更を削除します。`y`山から。 ヒープには、最終的に殺すことを決めたモンスターが常に含まれています。 
3. ヒープに残っている要素の数が最大勝利数となります。 

不変条件は、すべてのプレフィックスを処理した後、プレフィックスの移動バランスを有効に保ちながら、そのプレフィックス内で可能な最大数の殺されたモンスターがヒープに含まれることです。 バランスが無効になった場合、除去されたすべてのモンスターは同じ制約をその分だけ減少させるため、最大のコストを除去するのが最適です。`y`最大値によりカウントの損失が最小になります。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n, a, b = map(int, input().split())
    h = list(map(int, input().split()))

    heap = []
    chosen_sum = 0
    prefix = 0

    for value in h:
        x = value - 1
        prefix += x

        r = (b * (x % a)) // a

        kill_value = b * ((x - r * a) // b) - (r + 1)
        y = kill_value - x

        heapq.heappush(heap, -y)
        chosen_sum += y

        if chosen_sum > prefix:
            removed = -heapq.heappop(heap)
            chosen_sum -= removed

    print(len(heap))

if __name__ == "__main__":
    solve()
```変数`prefix`すべてのモンスターを対戦相手に処理させる場合に保存された移動のベースライン数を保存します。 変数`chosen_sum`現在攻撃用に選択されているモンスターによって導入された修正の合計を保存します。 

Python のヒープは最小ヒープであるため、最大ヒープをシミュレートするために負の値が格納されます。 プレフィックス条件が失敗した場合、最大の`y`が削除されます。 ここは貪欲な選択が行われる唯一の場所です。 

表現`(x % a)`安全なので`a`と同じ大きさにすることができます`10^9`ですが、Python の整数はオーバーフローしません。 開始時に 1 を引くことも必要です。 これがないと、ちょうど 1 ヘルス ポイントから始まるモンスターが正しく処理されません。

# helper: run solution on input string, return output string

import sys
import io
import heapq

def run(inp: str) -> str:
    old = sys.stdin
    sys.stdin = io.StringIO(inp)

    n, a, b = map(int, sys.stdin.readline().split())
    h = list(map(int, sys.stdin.readline().split()))

    heap = []
    chosen_sum = 0
    prefix = 0

    for value in h:
        x = value - 1
        prefix += x
        r = (b * (x % a)) // a
        y = b * ((x - r * a) // b) - (r + 1) - x

        heapq.heappush(heap, -y)
        chosen_sum += y

        if chosen_sum > prefix:
            chosen_sum += heapq.heappop(heap)

    sys.stdin = old
    return str(len(heap))

assert run("1 10 1\n1\n") == "1"
assert run("4 5 10\n100 100 100 100\n") == "4"

 ## 特殊なケース

 ヘルスポイントが 1 つだけあるモンスターは、オフバイ 1 エラーを起こしやすい場所です。 のために：```
1 10 1
1
```答えは`1`。 健康を変換した後、`h - 1`、モンスターには価値がある`0`。 式は次のようになります`r = 0`、つまり1回の攻撃で十分です。 

すべてのモンスターの健康状態が等しい場合でも、アルゴリズムは対戦相手によって課された順序を尊重する必要があります。 のために：```
3 1 1
1 1 1
```すべてのモンスターを選択すると、プレフィックス条件に違反します。 ヒープは最も役に立たない選択を削除し、2 つのモンスターを残します。 

攻撃力が大きく異なる場合、直接シミュレーションすることは不可能です。 のために：```
4 5 10
100 100 100 100
```ターン数は膨大ですが、モジュラー計算により最適な選択肢が即座に決定されます。 ヒープは決定のみを追跡し、個々の攻撃は追跡しません。
