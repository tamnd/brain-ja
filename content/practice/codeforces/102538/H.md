 ## 解決策
 ## 問題の理解

 左右に同じ数の頂点を持つ 2 部グラフがあります。 正しい頂点が順序付けられ、`i`- 番目の左の頂点が最初の頂点に接続されています`a[i]`右の頂点。 タスクは、このグラフ内にいくつの異なる頂点単純サイクルが存在するかを数えることです。エッジのセットが異なる場合、2 つのサイクルは異なるものとみなされます。 答えは必須です`998244353`。 

制約により許可されるのは、`n`構造化された 2 部グラフでも指数関数的な数のサイクルが含まれる可能性があるため、サイクルを直接列挙することは不可能です。 アン`O(n^3)`ソリューションはすでに大きすぎますが、`O(n^2)`動的プログラミングのアプローチは、注意深く実装すれば C++ と Python で 2,500 万の遷移が実現可能であるため、快適に適合します。 

主な問題は、サイクルが独立したオブジェクトではないことです。 適切な順序で頂点をスキャンすると、部分的に構築されたサイクルが複数のパスに分割される可能性があります。 アルゴリズムは、正確なエンドポイントではなく、そのようなオープン パスがいくつ存在するかだけを記憶する必要があります。 この情報を失うと、誤ったカウントが発生します。 

左の頂点と右の頂点が 1 つずつある小さなグラフは、有用な境界ケースです。 入力```
1
1
```エッジは 1 つ含まれていますが、サイクルは含まれていないため、答えは次のようになります。`0`。 繰り返される接続をサイクルとしてカウントする不注意なソリューションでは、誤って返される可能性があります。`1`。 

もう 1 つの重要なケースは、2 行 2 列の完全な 2 部グラフです。```
2
2 2
```4 つの頂点すべてを使用するサイクルが 1 つだけあります。 答えは`1`。 エッジ セットの代わりに有向トラバーサルをカウントするソリューションでは、同じサイクルが各方向で 1 回ずつ、2 回カウントされます。 

最後の注意が必要なケースは、多くの頂点が同一の近傍を持つ場合です。 例えば：```
3
3 3 2
```には 7 つのサイクルがあります。 繰り返されるプレフィックスにより多くの重複する可能性が生じるため、すべての左頂点を個別に処理すると、後でマージされるチェーンの組み合わせが見逃されます。 

## アプローチ

 ブルートフォース手法では、頂点のサブセットを生成し、各サブセットが単純なサイクルを形成しているかどうかを確認し、有効なものをカウントします。 チェック自体は多項式ですが、サブセットの数は指数関数的です。 と`2n`頂点、検索空間はおおよそ`2^(2n)`、値が小さい場合でも使用できなくなります。`n`。 

グラフ構造は、問題についてより適切に考える方法を提供します。 左側の頂点は右側のプレフィックスにのみ接続されているため、すべての頂点を自然な構築順序に従って並べ替えると、すべての左側の頂点が前のすべての右側の頂点に接続されます。 これはまさに、元の建設プロセスで説明されている状況です。 

頂点をスキャンしているときに、将来のサイクルの選択されたエッジのみを保持することを想像してください。 サイクルが終了する前に、選択されたエッジがいくつかの互いに素なチェーンを形成します。 順序付けの特性により、これらのチェーンはすべて同じ交互の形状になります。 頂点の正確な数は重要ではなく、頂点の数だけが重要です。 

させて`dp[j]`現在の頂点の接頭辞を処理して取得する方法の数になります。`j`オープンチェーン。 右の頂点は未使用にすることも、新しいチェーンを開始することもできます。 左の頂点は、既存の 2 つのチェーンの端を接続して 2 つのチェーンをマージしたり、唯一残ったチェーンを閉じて完全なサイクルを作成したりできます。 

ブルートフォース手法は、考えられるすべてのサイクルを直接探索するため機能します。 サイクル数が多すぎるため失敗します。 すべての未完成の構造が同じ形状であるという観察により、状態全体をチェーンの数に圧縮することができ、問題を二次動的計画法に還元できます。

 ## アルゴリズムのチュートリアル

 1. 値を並べ替える`a[i]`グラフを一連のものとして表示します。`2n`イベント。 連続する左の頂点の間に、使用可能になった右の頂点を挿入します。 この変換の後、すべての左の頂点は、その前に表示されるすべての右の頂点に接続されます。 
2. メンテナンス`dp[j]`、現在のプレフィックスを処理して正確に残す方法の数`j`オープンチェーン。 最初はチェーンがないので、`dp[0] = 1`。 
3. 右頂点を処理するときは、それを無視するか、含めます。 これを含めると、前の頂点がこの新しい右側の頂点に接続できないため、新しい開いたチェーンが作成されます。 
4. 左の頂点を処理するときに、2 つの既存のチェーンをマージできます。 あれば`j`頂点を追加する前のチェーンには、`j * (j - 1)`接続する 2 つのチェーンの端を順序立てて選択します。 状態は次から減少します`j`に鎖で繋ぐ`j - 1`鎖。 
5. 左の頂点は、残りの 1 つのチェーンを閉じることもできます。 頂点を追加する前の現在のチェーン数が 1 になるたびに、新しいサイクルが完了するため、次のように追加します。`dp[1]`答えに。 
6. ダイナミック プログラミング カウントでは、サイクルの 2 つの方向が異なるものとして扱われます。 これには、単一のエッジ ペアの単なる平行移動である長さ 2 のサイクルも含まれます。 長さ 2 の寄与を削除し、残りのカウントを 2 で割ります。 

機能する理由: プレフィックスを処理した後、未完了のサイクル コンポーネントはすべて交互のチェーンになります。 将来の頂点ではすべてのチェーンが同一の動作をするため、構築を続行するために必要な唯一のプロパティは、存在するチェーンの数です。 これらのチェーンを拡張または閉じるためのすべての可能な方法は、まさに 1 つの遷移によって表されます。 最後の分割では、チェーンを順序付けされたオブジェクトとして保存することによって導入された人為的な向きを削除します。 

## Python ソリューション```python
import sys

input = sys.stdin.readline

MOD = 998244353

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    a.sort()

    dp = [0] * (n + 3)
    dp[0] = 1

    ans = 0

    # Remove length-two cycles during the final normalization.
    for x in a:
        ans = (ans - x) % MOD

    prev = 0

    for x in a:
        # Insert right vertices that appear before this left vertex.
        for _ in range(prev + 1, x + 1):
            for j in range(n, 0, -1):
                dp[j] += dp[j - 1]
                if dp[j] >= MOD:
                    dp[j] -= MOD

        # Close a single chain.
        ans += dp[1]
        if ans >= MOD:
            ans -= MOD

        # Merge two chains using the current left vertex.
        for j in range(1, n + 1):
            add = dp[j] * j * (j - 1)
            add %= MOD
            dp[j - 1] += add
            if dp[j - 1] >= MOD:
                dp[j - 1] -= MOD

        prev = x

    ans %= MOD
    ans = ans * ((MOD + 1) // 2) % MOD
    print(ans)

if __name__ == "__main__":
    solve()
```ソートされた配列は、各左頂点の前に新しい右頂点が表示される瞬間を表します。 変数`prev`は以前のプレフィックスの長さを保存するため、新しく出現した右側の頂点のみが処理されます。 

配列`dp`右側の頂点を追加すると、逆の順序で更新されます。 これにより、新しく追加された 1 つの頂点が同じトランジション内で複数回使用されることが防止されます。 

マージ遷移では、`j * (j - 1)`2 つの異なるチェーンを選択する必要があるためです。 チェーンのエンドポイントを数えるときは順序が重要であるため、係数は単純な組み合わせ値ではありません。 

開始時の答えの調整により、2 頂点の閉じた構造が削除されます。 2 のモジュラ逆数による最後の乗算により、実際のサイクルごとに 2 つの可能な方向によって引き起こされる重複したカウントが削除されます。

## テストケース```python
import sys
import io

MOD = 998244353

def solution(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))
    a.sort()

    dp = [0] * (n + 3)
    dp[0] = 1
    ans = 0

    for x in a:
        ans = (ans - x) % MOD

    prev = 0
    for x in a:
        for _ in range(prev + 1, x + 1):
            for j in range(n, 0, -1):
                dp[j] = (dp[j] + dp[j - 1]) % MOD

        ans = (ans + dp[1]) % MOD

        for j in range(1, n + 1):
            dp[j - 1] = (dp[j - 1] + dp[j] * j * (j - 1)) % MOD

        prev = x

    return str(ans * ((MOD + 1) // 2) % MOD)

assert solution("1\n1\n") == "0"
assert solution("2\n2 2\n") == "1"
assert solution("3\n3 3 2\n") == "7"
assert solution("4\n1 1 1 1\n") == "0"
assert solution("5\n5 5 5 5 5\n") == "101"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1 / 1`|`0`| サイクルのない最小のグラフ |
 |`2 / 2 2`|`1`| 基本的な 4 頂点サイクルと方向補正 |
 |`3 / 3 3 2`|`7`| 複数の重複するサイクル |
 |`4 / 1 1 1 1`|`0`| 左の頂点が右の頂点に十分に接続できない |
 |`5 / 5 5 5 5 5`|`101`| 多くのチェーン マージを含む密なグラフ |

 ## 特殊なケース

 最小のグラフの場合:```
1
1
```アルゴリズムは右の頂点と左の頂点を 1 つずつ作成します。 右側の頂点は 1 つの開いたチェーンを作成しますが、左側の頂点は、サイクルに十分なエッジを含むチェーンのみを閉じることができます。 正規化後も結果は残ります`0`。 

完全な 2 行 2 列のグラフの場合:```
2
2 2
```動的プログラミングにより、最初の左頂点の前に 2 つのチェーンが作成されます。 左の最初の頂点はそれらをマージし、1 つのチェーンを残します。 左から 2 番目の頂点がそれを閉じて、1 サイクルを追加します。 最後の除算では、重複した向きが削除され、正解が残ります。`1`。 

繰り返される近隣の場合:```
3
3 3 2
```同じプレフィックス接続が複数回出現します。 状態圧縮はこれを処理します。これは、左の各頂点が未完成のチェーンがいくつ存在するかのみを考慮し、どの右の頂点がそれらを作成したかを考慮しないためです。 マージ トランジションでは、考えられるすべてのエンドポイント選択がカウントされ、完全な答えが生成されます。`7`。
