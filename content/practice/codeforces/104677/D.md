 ## 解決策
 ## 問題の理解

 このグラフは、無向橋によって接続された島の集合を表しています。 すべての橋には 2 つの属性があります。橋を通過するには常に 1 歩しかかかりません。また、明るさの値もあります。 各クエリから、動物はある島から出発し、島 1 に到達したいと考えています。 

すべての動物の最初の目標は純粋に幾何学的なものです。動物は常に橋の数が最小限のルートを選択するため、エッジ数の点で最短のパスだけが問題となります。 それらの最短ルートのうち、選択は動物の色によって異なります。 白い動物は、通過するエッジに沿った輝度値の合計が可能な限り最大のルートを好みますが、黒い動物は可能な限り最小の輝度値の合計を好みます。 

したがって、すべてのクエリについて、島 1 までの最短距離と、その最短距離の制約の下で達成可能な最良の明るさの合計という 2 つの値を報告する必要があります。 

制約により、線形または線形に近い解が即座に強制されます。 最大 50 万のノードと 100 万のエッジでは、クエリごとのグラフの走査は不可能です。 クエリごとに 1 つのダイクストラを使用するだけでも遅すぎます。 この構造は、すべてのエッジが距離に正確に 1 を寄与するため、最短経路構造がエッジの重みから独立していることを強く示唆しています。 これにより、問題は重み付けされていない最短パス グラフでの作業に軽減され、一度構築すれば再利用できるようになります。 

複数の最短パスが存在する場合、微妙な問題が発生します。 単純なアプローチでは、最初に最短距離を計算し、次に明るさを最適化する 2 番目の検索を個別に実行する可能性がありますが、明るさの決定はすべての最短距離近傍ノードの中からどの次のステップのノードが選択されるかによって決まるため、これは失敗します。 もう 1 つの失敗モードは、最短距離の制約を無視して、局所的に最適な輝度エッジを貪欲に選択することです。これにより、無効なより長いパスが容易に生成される可能性があります。 

## アプローチ

 まず効率を無視する場合、最も直接的なアイデアは、すべてのクエリ ノードからノード 1 までの最短パス検索を実行し、距離だけでなく状態の一部として輝度の合計も追跡することです。 各クエリでは最大 100 万のエッジを持つグラフを探索する必要があり、最悪の場合、およそ 10^11 の演算が必要になるため、これはすぐに実行不可能になります。 

より構造化された観察は、すべてのエッジの走査コストが同じであるという事実から得られます。 グラフは、ノード 1 からの BFS 距離によって階層化できます。距離がわかったら、ノードからの有効な最短パスは常に、距離 d のノードから距離 d-1 のノードに移動する必要があります。 これにより、距離を短縮しないすべてのエッジが削除されます。 

これにより、グラフが BFS レベルで定義された有向非循環構造に変換されます。 この構造では、すべてのノードの答えは、ルートに 1 層近い隣接ノードにのみ依存します。 これにより、BFS 順序に関する動的プログラミングの問題が発生します。 明るさの最適化は単純な繰り返しになります。白い動物の場合は、すべての有効な次のステップで最大値を取得し、黒い動物の場合は最小値を取得します。 

まず、ノード 1 からの BFS を使用してすべての最短距離を計算します。次に、すべての状態がより短い距離の状態にのみ依存するため、1 からの距離の増加順に輝度値を計算します。 各エッジは DP の意味で 1 回だけ緩和され、線形の複雑さが得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとの総当たり検索 | O(Q · (N + M)) | O(N + M) | 遅すぎる |
 | レイヤー上の BFS + DP | O(N + M) | O(N + M) | 承認済み |

 ## アルゴリズムのチュートリアル

 問題全体をノード 1 に根付かせ、そこから外側に向けてすべてを構築します。 

1. ノード 1 から開始して BFS を実行し、最短距離を計算します。`dist[u]`すべてのノードに対して。 これが機能するのは、すべてのエッジが距離に関して同じ重みを持っているためであり、BFS は最小ホップ カウントを正確に見つけます。 
2. BFS の実行中に、通常どおり隣接リストも保存します。 明るさは最短経路が決定された後にのみ関係するため、明るさについてはまだ何も決定していません。 
3. 2 つの配列を作成します`best_white[u]`そして`best_black[u]`これは、最短パス制約の下でノード u からノード 1 までの最適な明るさの合計を保存します。 
4. ノード 1 で基本ケースを初期化します。距離はゼロであり、横断するエッジがないため、両方の値はゼロです。 
5. ノード 1 からの距離が増加する順序でノードを処理します。この順序により、ノード u を処理するときに、すべてのノード v が次の条件を満たすことが保証されます。`dist[v] = dist[u] - 1`すでに計算されています。 
6. 各ノード u について、すべての隣接ノード v を次のように調べます。`dist[v] = dist[u] - 1`。 これらはまさに、最短経路で許可される次のステップです。 
7. このようなエッジ (u、v) ごとに、候補となる輝度値を次のように計算します。`z + best_white[v]`または`z + best_black[v]`最適化されるクエリの種類に応じて異なります。 白についてはすべての候補の最大値を取得し、黒については最小値を取得します。 
8. これらの計算値を DP 配列に保存します。 
9. 各クエリノードに対して、出力`(dist[d_i], best_color[d_i])`。 

この順序付けが機能する主な理由は、最短パスによってすべてのステップで距離が厳密に減少するためです。 これにより、DP 依存関係グラフの循環が防止され、各状態がすでに計算された状態のみに依存することが保証されます。 

## なぜ機能するのか

 BFS はノードをレイヤーに分割し、すべての有効な最短パスが厳密にレイヤー k からレイヤー k-1 に移動します。 これは、どのノードの部分問題も、厳密に小さな部分問題にのみ依存することを意味します。 DP 遷移では、最短パス DAG 内のすべての可能な先行ノードが考慮されるため、すべての有効な最短パスが 1 回だけキャプチャされます。 すべての最短パスがこの DAG で表され、無効な長いパスは含まれないため、これらの遷移にわたって計算された極値は、すべての最短パスの中で正確に最適な明るさになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

n, m = map(int, input().split())
adj = [[] for _ in range(n + 1)]

for _ in range(m):
    x, y, z = map(int, input().split())
    adj[x].append((y, z))
    adj[y].append((x, z))

dist = [-1] * (n + 1)
dist[1] = 0
q = deque([1])

while q:
    u = q.popleft()
    for v, _ in adj[u]:
        if dist[v] == -1:
            dist[v] = dist[u] + 1
            q.append(v)

order = [[] for _ in range(n + 1)]
for i in range(1, n + 1):
    if dist[i] != -1:
        order[dist[i]].append(i)

INF = 10**30
best_white = [0] * (n + 1)
best_black = [0] * (n + 1)

maxd = max(dist)

for d in range(maxd + 1):
    for u in order[d]:
        if u == 1:
            continue
        best_w = -1
        best_b = INF

        for v, z in adj[u]:
            if dist[v] == dist[u] - 1:
                best_w = max(best_w, z + best_white[v])
                best_b = min(best_b, z + best_black[v])

        best_white[u] = best_w
        best_black[u] = best_b

q = int(input())
for _ in range(q):
    d, col = input().split()
    d = int(d)
    if col[0] == 'W':
        print(dist[d], best_white[d])
    else:
        print(dist[d], best_black[d])
```BFS は、単一パスで正確な最短距離を計算します。 レイヤーをグループ化すると、ノード リスト全体を並べ替えることなく、依存関係の順序でノードを処理できるようになります。 各ノードの DP ステップは、前の BFS 層につながるエッジのみを検査し、最短パス制約の下での正確性を保証します。 

よくある間違いは、BFS 自体中に両方の DP 配列を計算しようとすることです。 BFS では、ノードが最初に検出されたときにすべての親状態が確定していることが保証されないため、これは失敗します。 距離の計算と DP 順序を分離することで、この問題は完全に回避されます。 

## 実用的な例

 ### トレース例 1

 ノード 3 が 2 に接続し、2 が 1 に接続し、3 から 1 に直接接続する追加の代替エッジがある小さなチェーンを考えてみましょう。 

| ノード | 距離 | 選択された親 | ベストホワイト | ベストブラック |
 | --- | --- | --- | --- | --- |
 | 1 | 0 | - | 0 | 0 |
 | 2 | 1 | 1 | 5 | 5 |
 | 3 | 1 | 1 | 8 | 8 |

 ノード 3 の場合、複数の最短ルート (同じ距離に存在する場合は直接または 2 経由) があっても、より短い距離の近隣ノードのみが考慮されます。 DP は、有効な最短遷移の中で最高の明るさをキャプチャします。 

これは、アルゴリズムが BFS ツリー構造への遷移を正しく制限していることを示しています。 

### トレース例 2

 ノード 4 には 2 つの最短パス隣接ノード 2 および 3 があります。 

| ノード | 距離 | 近所の人からのベストホワイト | 最終ベストホワイト |
 | --- | --- | --- | --- |
 | 2 | 1 | ベース | 3 |
 | 3 | 1 | ベース | 7 |
 | 4 | 2 | 最大(1+3, 2+7) | 9 |

 この計算により、アルゴリズムが最短パスの一意性を想定しておらず、すべての有効な先行パスを正しく集約していることが確認されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N + M) | BFS は距離を 1 回計算し、各エッジは DP 遷移中に最大 1 回チェックされます。 
| スペース | O(N + M) | 隣接リストと距離と DP 値の配列 |

 線形の複雑さは、5×10^5 ノードと 10^6 エッジの制限内に問題なく収まります。 メモリ使用量は、アプローチに関係なく必要な隣接ストレージによって支配されます。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque

    n, m = map(int, input().split())
    adj = [[] for _ in range(n + 1)]

    for _ in range(m):
        x, y, z = map(int, input().split())
        adj[x].append((y, z))
        adj[y].append((x, z))

    dist = [-1] * (n + 1)
    dist[1] = 0
    q = deque([1])

    while q:
        u = q.popleft()
        for v, _ in adj[u]:
            if dist[v] == -1:
                dist[v] = dist[u] + 1
                q.append(v)

    order = [[] for _ in range(n + 1)]
    for i in range(1, n + 1):
        if dist[i] != -1:
            order[dist[i]].append(i)

    INF = 10**30
    best_white = [0] * (n + 1)
    best_black = [0] * (n + 1)

    for d in range(max(dist)):
        for u in order[d]:
            if u == 1:
                continue
            bw = -1
            bb = INF
            for v, z in adj[u]:
                if dist[v] == dist[u] - 1:
                    bw = max(bw, z + best_white[v])
                    bb = min(bb, z + best_black[v])
            best_white[u] = bw
            best_black[u] = bb

    q = int(input())
    out = []
    for _ in range(q):
        d, c = input().split()
        d = int(d)
        if c[0] == 'W':
            out.append(f"{dist[d]} {best_white[d]}")
        else:
            out.append(f"{dist[d]} {best_black[d]}")
    return "\n".join(out)

## 特殊なケース

 重要なエッジ ケースの 1 つは、複数の最短パスが存在するにもかかわらず、極度の明るさをもたらすのは 1 つだけである場合です。 アルゴリズムは、すべての近傍を明示的にチェックすることでこれを処理します。`dist[v] = dist[u] - 1`候補パスを見逃さないようにします。 たとえば、ノードの最短パス DAG に 2 つの親がある場合、両方とも最大または最小遷移に独立して寄与します。 

グラフに最短パスの一部ではないサイクルが含まれている場合、別のエッジ ケースが発生します。 これらのエッジは厳密な距離減少条件を満たしていないため、無視しても問題ありません。 これにより、より長いパスが誤って含まれることが防止されます。 

最後のエッジ ケースは、ルート ノード自体です。 ノード 1 にはルートへの発信要件がないため、両方の DP 配列で明示的にゼロに初期化する必要があります。 近傍から計算しようとすると、誤って負の値または未定義の値が導入されてしまいますが、直接初期化することで正確さが保証されます。
