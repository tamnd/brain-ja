 ## 解決策
 ## 問題の理解

 このタスクでは、単純な分割シナリオについて説明します。 人には決まった数のピザのスライスと友人のグループがあります。 スライスはすべての友人にできるだけ均等に分配され、均等に分配できないものは未使用のままになります。 

入力は 2 つの整数で構成されます。最初の整数は利用可能なピザのスライスの数を表し、2 番目の整数はピザを共有する友人の数を表します。 出力では 2 つの量を記述する必要があります。 1 つ目は均等に分割した後に各友達が受け取るスライスの数、2 つ目は分配されずに残るスライスの数です。 

制約は両方の値で 10^9 に達します。これは、分布をスライスごとにシミュレートするアプローチが遅すぎることを直ちに示します。 最大 10^9 の反復にわたるループは、1 秒の制限の下では時間内に終了しません。 ソリューションでは、算術演算を使用して結果を一定時間で計算する必要があります。 

スライスの数が友人の数よりも少ない場合、微妙なエッジケースが発生します。 たとえば、スライスが 2 つでフレンドが 5 人いる場合、各フレンドはスライスを取得せず、すべてのスライスは未使用のままになります。 もう 1 つの例外的なケースは、スライスが均等に分割される場合 (3 人の友人間で 9 スライスなど)、何も残らない場合です。 どちらの場合も、整数演算を超えた特別な分岐を行わずに正しく処理する必要があります。 

## アプローチ

 直接シミュレーションのアプローチでは、友人間でラウンドロビン方式で一度に 1 つのスライスを割り当てます。 これにより、スライスがなくなるまで分散が継続されます。 概念的には単純ですが、最悪のケースではスライスごとに 1 回の反復が必要となり、最大 10^9 の演算が発生しますが、これは実行可能な制限をはるかに超えています。 

重要な観察は、分布が純粋に均一であるということです。 すべての友人は、スライスの合計を友人の数で割った整数部分を正確に受け取ります。 残りは均等に割り当てることができないものです。 これにより、プロセスが繰り返しのシミュレーションから単一の算術除算に変換されます。 

ブルート フォースは分散プロセスを明示的にモデル化するため機能しますが、スライスの数が大きくなると失敗します。 商と剰余のみが問題であるという観察により、問題は整数の除算とモジュロ演算に帰着し、どちらも定数時間で計算可能です。

 ## アルゴリズムのチュートリアル

 1. 2 つの整数、スライスの数とフレンドの数を読み取ります。 これらは、リソースの合計と、形成する均等なパーティションの数を表します。 
2. 整数除算を使用して、各友達が受け取るスライスの数を計算します。 これにより、使用可能なスライスを超過することなく、可能な限り最大の均等な割り当てが取得されます。 
3. モジュロ演算を使用して残りのスライスを計算します。 これは、均等に分配した後の残りを直接表します。 
4. 商と余りを最終結果として出力します。 

各ステップの背後にある推論は、割り算の数学的構造に関連付けられています。 整数の除算は自然に均等な分割をエンコードし、モジュロは均等に分割できないものをキャプチャします。 

### なぜ効果があるのか

 不変条件は、配布後の`x`均等にスライスします`N`友人の場合、割り当てられたスライスの合計は、次の最大倍数である必要があります。`N`を超えないもの`x`。 整数の除算を乗算して戻すと、まさにこの倍数が得られます。`N`。 剰余は、この最大の割り切れる部分を差し引いた後に残るものであり、これがまさにモジュロの計算内容となります。 どちらの操作も元の数値を正確に分解するため、結果が正しい分布から逸脱することはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

x, n = map(int, input().split())

each = x // n
leftover = x % n

print(each, leftover)
```このソリューションは入力を 1 回読み取り、すぐに 2 つの算術演算を実行します。 整数の除算演算子`//`これは、スライス全体のみを分散するという考えと一致します。 モジュロ演算子`%`この割り当て後に何が残るかを計算します。 

算術演算によって分配ロジックが完全にエンコードされるため、ループや条件分岐は必要ありません。 演算の順序は簡単で、Python が大きな値を自然に処理する整数演算を保証する以外に境界の問題はありません。

## テストケース```python
import sys, io

def solve():
    x, n = map(int, sys.stdin.readline().split())
    print(x // n, x % n)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from contextlib import redirect_stdout
    import io as _io
    out = _io.StringIO()
    with redirect_stdout(out):
        solve()
    return out.getvalue().strip()

# provided samples
assert run("5 2\n") == "2 1", "sample 1"
assert run("9 3\n") == "3 0", "sample 2"

# custom cases
assert run("1 2\n") == "0 1", "fewer slices than friends"
assert run("10 1\n") == "10 0", "single friend gets everything"
assert run("1000000000 2\n") == "500000000 0", "large equal split"
assert run("7 3\n") == "2 1", "general remainder case"
```| テスト入力 | 期待される出力 | 検証内容 |

 ## 特殊なケース

 入力など、スライス数がフレンド数より少ない場合`1 5`、整数除算の結果はゼロです。つまり、友人はスライスを受け取りません。 モジュロ演算は元の数値を返します。これは、何も配布されていないことを正しく反映しています。 

友達が1人の場合など`10 1`の場合、除算によりその 1 人の友人のすべてのスライスが得られ、剰余はゼロになります。 これにより、リソース全体が特別な処理なしで正しく割り当てられていることを確認できます。 

スライスが均等に分割されるとき、たとえば、`8 4`、整数除算は友人ごとの正確なシェアを生成し、モジュロはゼロを返します。 これは、算術分解自体以外に残りの処理が必要ないことを示しています。 

値が大きい場合など`10^9 2`の場合でも、Python は任意のサイズの整数を処理できるため、操作は引き続き正しく動作します。 計算は一定時間継続し、入力の大きさによって性能が低下することはありません。
