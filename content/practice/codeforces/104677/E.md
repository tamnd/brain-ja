 ## 解決策
 ## 問題の理解

 大きな長方形の画面内で移動する長方形の DVD ロゴをシミュレートしています。 ロゴ自体には幅と高さがあるため、その動きは、サイズが縮小された長方形内で移動するように制約されている小さな長方形の左下隅を追跡することと同じです。$(W-A) \times (H-B)$。 

ロゴは指定された位置から開始され、固定方向ベクトルで移動します。$(x, y)$単位速度で。 壁に当たるとビリヤードの球のように反射します。これは、入射角と反射角が等しいことを意味します。 私たちはこの動きを段階的にシミュレートするように求められているわけではありません。 代わりに、位置と速度方向の両方が再び初期状態と正確に一致する最初の正の時間を決定する必要があります。 

重要な問題は、反射によって方向が変わるため、軌跡が長方形内で単純に直線的ではないことです。 ただし、この動きは幾何学的な意味で周期的です。 問題は最小時間を見つけることになります$T > 0$システムはまったく同じ状態に戻ります。 

の制約$W, H, A, B$は小さいことから、シミュレーションではなく幾何学的または数論的推論が意図されていることが示唆されます。 方向ベクトルの成分$x, y$大きくすることもできますが、速度は 1 単位/秒に固定されているため、速度の大きさではなく方向のみを定義します。 

微妙な問題は、ロゴが領域を占有するため、ロゴの左下隅が全画面境界ではなく縮小された境界に達すると衝突が発生することです。 これはよくある間違いの原因です。$W, H$代わりに直接$W-A, H-B$。 

もう 1 つの微妙な点は、位置と速度の方向の両方を一致させる必要があることです。 同じ位置に戻るだけでは十分ではありません。 モーションはサイクル後に方向に反映される可能性がありますが、そのような状態は無効です。 

エッジ ケースは、方向成分の 1 つがゼロの場合に発生します。 もし$x = 0$、動きは純粋に垂直方向であり、水平方向の制約は無関係になります。 同じことが対称的に当てはまります。$y = 0$。 単純なシミュレーションや単純な周期計算は、このような縮退したケースでは機能しなくなることがよくあります。 

最後に、出力形式が特殊です。実数全体を出力するのではなく、実数の最初の有効数字 6 桁を出力します。$T$。 これは、数値精度を注意深く維持し、先頭の桁に影響を与える浮動小数点エラーを回避する必要があることを意味します。 

## アプローチ

 ブルートフォースのアイデアでは、モーションを 1 秒ごとに (または小さな時間ステップで) シミュレートし、位置を更新して境界で反映します。 各ステップで壁の衝突と方向の変化が計算されます。 これは概念的には単純ですが、周期が非常に長くなる可能性があり、さらに重要なことに、実際の衝突時間は一般に非合理的であるため、失敗します。 たとえ小さな精度誤差であっても累積すると、正確な等価検出の信頼性が低くなります。 

重要な観察は、平面を展開することで反射を除去できるということです。 パスを反映する代わりに、座標系全体を反映します。 これにより、動きは鏡面四角形の無限グリッド内の直線に変わります。 この展開された空間では、ロゴは次の速度に比例して直線に沿って移動します。$(x, y)$。 

x 座標と y 座標が縮小された長方形内の元の位置に戻り、各方向の反射回数が同じ方向になるという 2 つの条件が同時に成立すると、システムは同じ状態に戻ります。 展開された表現では、これは、両方の軸に沿った変位がそれぞれの周期の公倍数であるという条件に変換されます。 

これにより、共通の時間を見つけるという問題が軽減されます$T$直線運動は、各軸に 1 つずつ、2 つの独立したモジュラー制約を満たすようになります。 これらの制約は、方向ベクトルと長方形の寸法から導出される比率を使用して x と y の周期を同期させる、線形ディオファントス条件のペアになります。

 ## アルゴリズムのチュートリアル

 1. 作業用長方形を有効領域に置き換えます。$(L_x, L_y) = (W-A, H-B)$。 これは、ロゴの左下隅のすべての有効な位置を表します。 
2. 速度の大きさを計算する$s = \sqrt{x^2 + y^2}$。 実際の速度成分は次のとおりです。$\left(\frac{x}{s}, \frac{y}{s}\right)$。 保管しております$s$比率比較ではキャンセルされるため、今のところは象徴的です。 
3. 展開されたグリッドで同じ状態に戻るには、x と y の変位が両方とも の整数倍である必要があることに注目してください。$2L_x$そして$2L_y$、 それぞれ。 したがって、次のことを要求します。$$\frac{x}{s}T = 2L_x k, \quad \frac{y}{s}T = 2L_y m$$いくつかの整数の場合$k, m > 0$。 
4. 排除する$T$そして$s$2 つの式を同等にすると、次のようになります。$$\frac{2L_x k}{x} = \frac{2L_y m}{y}$$これにより、問題は比例制約に対する整数解を見つけることに帰着します。 
5. これをディオファントスの等式として書き直します。$$k \cdot (2L_x y) = m \cdot (2L_y x)$$2 つの係数の最大公約数を計算して、次の最小の正の整数解を見つけます。$k$そして$m$。 
6. 悪化したケースに対処します。 もし$x = 0$、動きは純粋に垂直方向であり、y 次元のみが周期を決定します。 同様に、$y = 0$、x のみが重要です。 
7. 1回$k$（または$m$) が決定されたら、次を計算します。$$T = \frac{2L_x k}{x/s} = \frac{2L_x k s}{|x|}$$絶対値を使用して時間の確実性を確保します。 
8.変換$T$十分な精度で文字列に変換し、最初のゼロ以外の数字から始まる最初の 6 つの有効数字を抽出します。 

### なぜ効果があるのか

 展開変換は、反射を長方形のミラーリングされたコピーにわたる平行移動に変換します。 この空間では、軌道は直線であり、元の状態に戻ることは、同じ向きで元の構成にマッピングし直す格子点に着地することに正確に対応します。 gcd 構造は、独立した x と y の周期間の最小の同期を見つけて、位置と速度の両方を同時に揃えることを保証します。 すべての反射は展開されたグリッド内のパリティとしてエンコードされるため、両方の座標を一致させることで完全な状態の等価性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import math

def first_six_digits(x):
    s = f"{x:.15f}"
    if '.' in s:
        s = s.rstrip('0').rstrip('.')
    s = s.replace('.', '')
    i = 0
    while i < len(s) and s[i] == '0':
        i += 1
    if i == len(s):
        return "0"
    return s[i:i+6]

def solve():
    W, H = map(int, input().split())
    A, B = map(int, input().split())
    x0, y0 = map(int, input().split())
    x, y = map(int, input().split())

    Lx = W - A
    Ly = H - B

    if x == 0:
        s = abs(y)
        T = (2 * Ly * math.sqrt(x*x + y*y)) / abs(y)
        print(first_six_digits(T))
        return

    if y == 0:
        s = abs(x)
        T = (2 * Lx * math.sqrt(x*x + y*y)) / abs(x)
        print(first_six_digits(T))
        return

    a = 2 * Lx * y
    b = 2 * Ly * x

    g = math.gcd(abs(a), abs(b))
    k = abs(b) // g

    s = math.sqrt(x*x + y*y)
    T = (2 * Lx * k * s) / abs(x)

    print(first_six_digits(T))

if __name__ == "__main__":
    solve()
```実装は展開平面縮小の直後に行われます。 整数部分が小さい場合、または末尾のゼロが表示される場合、浮動小数点書式設定だけでは初期の精度が低下する可能性があるため、書式設定用のヘルパーを使用すると、先頭の有効数字が失われないことが保証されます。 gcd ステップは 2 つの軸周期を同期し、最終的な式は選択された整数解から時間を再構築します。 

方向の 1 つの座標がゼロになるような縮退の場合には注意が必要です。 このような場合、動作は 1 軸の周期系に縮小され、ディオファンティーン同期ステップは不要になります。

 ## 特殊なケース

 重要なエッジケースは、モーションが軸に沿って配置されている場合に発生します。 方向ベクトルが$x = 0$、展開された定式化では x サイクルが無限であるため、gcd ベースの同期全体が壊れます。 そのような状況では、正しい動作は、x 次元を完全に無視して、y モーションから直接垂直周期を計算することです。 アルゴリズムは、gcd 計算の前に分岐することでこれを処理し、ゼロによる除算が発生しないようにします。 

別の特殊なケースが発生するのは、$W-A$または$H-B$は非常に小さく、特に 1 に等しい。このような場合、反射は非常に頻繁に発生しますが、周期が速度投影の小さな整数倍になるため、展開された表現は依然として機能します。 gcd ステップは、大きさではなく整数のジオメトリのみに依存するため、有効なままです。 

最後の微妙なケースは、方向ベクトルが大きいにもかかわらず正規化されていない場合です。 速度は 1 に固定されているため、スケーリングは$(x,y)$方向は変わりませんが、慎重に扱わないと中間演算に影響します。 比率と gcd 計算のみを使用すると、スケーリングの不変性が保証されるため、最終時間は、時間の大きさに関係なく正確なままになります。$(x,y)$。
