 ## 解決策
 ## 問題の理解

 すべてのエッジに小文字が含まれるツリーが与えられます。 頂点をルートとして選択した場合、すべての頂点は、ルートからその頂点までの一意のパスに沿ってエッジ ラベルを読み取ることによって形成される文字列を定義します。 ルートは空の文字列に対応し、エッジを越えて移動すると、その文字が現在の文字列に追加されます。 

すべての頂点が個別の文字列を生成する場合、ルートの選択は有効であるとみなされます。 タスクは、この条件が成り立つように、ルートとして機能できる頂点の数を数えることです。 

主な難点は、ルートを変更するとルートからノードへのパスがすべて変更されるため、頂点に割り当てられる文字列が選択したルートに応じて完全に異なることです。 

テスト ケースごとに n が最大 10^5、総和が最大 10^6 という制約により、テスト ケースごとに本質的に線形になることが強制されます。 文字列を再計算したり、すべてのルートを個別に探索したりするアプローチは、すぐに時間制限を超えてしまいます。 

ルートの選択方法に関係なく、2 つの異なる頂点が常に同じ文字列を生成する場合、微妙なエッジ ケースが発生します。 最小限の例は、「a」というラベルが付いた 1 つのエッジで接続された 2 つの頂点です。 どちらかのエンドポイントをルートとして選択すると、もう一方の頂点は文字列「a」を取得しますが、この単純なケースでは両方の頂点が常に異なるため、両方のルートが有効になります。 ただし、より大きな構造では、対称性により、離れた頂点間で衝突が発生する可能性があります。 

もう 1 つのより意味のある失敗ケースは、ツリーに 2 つの頂点が含まれており、それらの間のすべての単純なパス上のエッジ ラベルのマルチセットが反転対称の下で同一となり、ルートの選択に関係なく、ルートによって引き起こされる文字列が同一になる場合です。 大域的対称性を無視する単純なアプローチは、ここでは失敗します。 

## アプローチ

 まず、ルートが無効であることが何を意味するかを観察します。 ルートから u までの文字列とルートから v までの文字列が等しいような 2 つの異なる頂点 u と v が存在する場合、ルートは無効です。 これは、ルートから u へのパス ラベルとルートから v へのパス ラベルが同一のシーケンスを形成することを意味します。 

ルート r を固定すると、すべての頂点 x は文字列 s_r(x) を持ちます。 条件は、s_r が頂点に対して単射であることです。 これは、エッジ ラベルのシーケンスが同一である 2 つの異なるルートからノードへのパスが存在する場合に正確に失敗します。 

ブルートフォース手法では、各頂点をルートとして試行します。 ルートごとに DFS を実行し、すべての文字列を明示的に構築し、それらをハッシュ セットに挿入して重複を検出します。 各 DFS のコストは O(n) ですが、文字列の構築と比較も全長が線形であるため、完全な解は最悪の場合 O(n^2) になります。これは、n が 10^5 までの場合は不可能です。 

構造的な洞察は、ルートからノードへの文字列が等しいということは、同じ文字シーケンスを綴るルートから始まる 2 つの異なるパスの存在と同等であるということです。 ツリーでは、このような 2 つのパスは、ある時点で分岐し、ラベル シーケンスに関して再収束する必要があります。 これは、各頂点の周囲の隣接するエッジの順序付けられたペアに関する条件になります。 

重要な観察は局所的です。 ルート r を修正するとします。 任意の頂点 x を考えます。 x から、すべての入射エッジがサブツリーにつながります。 このような各エッジは、そのサブツリーに入るパス上の最初の文字を誘導します。 2 つの異なる子サブツリーがルートに向かって上向きに同一のラベル付きパスを生成できる場合、衝突が発生します。 

すべてのルートを個別にチェックするのではなく、視点を反転します。 ツリーを任意にルート化し、有向エッジごとに、その方向から離れるときにそれが表すサブツリーのハッシュまたは署名を計算します。 次に、逆方向の署名も計算します。

候補ルート x の場合、文字列がすべて別個であるという条件は、x に付随するすべての有向エッジ (x からのパスの潜在的な最初のステップとして見た場合) の中で、誘導されたすべての「方向性文字列セット」が別個であると言うのと同じです。 x からの 2 つの方向で同一の文字列が生成される場合、x をルートとして選択すると衝突が発生します。 

これにより、問題は、有向エッジ u -> v ごとに、u から遠ざかるときに v から到達可能な文字列のセットの正規表現を計算することになります。 次に、各ノード x で、すべてのインシデント指向表現が個別であるかどうかを確認するだけです。 「はい」の場合、x は有効なルートです。 

これらの表現は、ツリー上のリルート動的プログラミングを使用して計算されます。 各有向エッジは、下向きの文字列のマルチセットを表すハッシュを保持します。 まず 1 つの DFS でサブツリー ハッシュを計算し、次に再ルートして親の寄与を伝播します。 ローリング ハッシュによる文字列のハッシュにより、エッジラベル付き遷移の O(1) マージが可能になります。 

最後に、ノードごとに、すべてのインシデント方向のハッシュを収集し、それらがすべて異なるかどうかを確認します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | リルート + ハッシュ | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各エッジを双方向として扱い、u から離れるときに v から始まるすべての文字列の正規ハッシュを意味する状態 dp[u][v] を定義します。 

当社では DFS ベースの再ルート技術を使用しています。 

1. ルートとして任意のノードを選択します。たとえば、1. DFS を実行して、サブツリー ハッシュ dp[u][v] を計算します。ここで、v は u の子です。 これは、v から始まり u から下方向に向かうすべての文字列を表します。 計算は文字の寄与と子ハッシュの組み合わせに基づいているため、各サブツリーは単一のローリング ハッシュ値に要約されます。 
2. この DFS 中に、出力サブツリーを要約する各ノードのフォワード ハッシュを計算します。 これにより、一方向のすべての dp 値が得られます。 
3. 2 番目の DFS を実行して再ルートします。 u から v に移動するとき、v を除く u の他のすべての近傍の dp 値を組み合わせて、「親側」からの v の欠落寄与を計算します。これは、隣接リストに対するプレフィックスとサフィックスの累積を使用して行われます。これにより、再ルートされた各値をエッジあたり O(1) の償却時間で計算できます。 
4. 再ルート化後、すべての有向エッジ (u, v) は、u から v に入るコンポーネントの文字列構造を表す完全な dp[u][v] 値を持ちます。 
5. 各ノード x について、x の近傍 y のすべての dp[x][y] を収集します。 これらすべての値が異なるかどうかを確認してください。 「はい」の場合、x を有効なルートとしてカウントします。 
6. そのようなノードの総数を出力します。 

妥当性を局所的に判断できる主な理由は、頂点ストリング間の衝突が、同一のラベル付き継続構造を生成するノードでの 2 つの異なる入射方向に正確に対応するためです。 x における 2 つのインシデント方向が同一の継続ハッシュを生成しない場合、ルートからノードへのすべての文字列は別個である必要があります。 

これが機能する理由は、ルートからノードまでのすべての文字列がルートからの最初のステップで一意に識別されるためです。 2 つのノードが等しい文字列を持っている場合、それらは必然的に、同一のラベル シーケンスを生成するルートからの 2 つの異なる発信方向に対応することになります。これはまさに隣接ハッシュ チェックによって検出されるものです。 dp 表現は各方向のすべての継続文字列を完全にエンコードするため、文字列の同等性は方向ハッシュの同等性に帰着し、これをテストします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

MOD = (1 << 61) - 1
BASE = 91138233

def mod_mul(a, b):
    t = a * b
    return (t >> 61) + (t & MOD)

def mod_add(a, b):
    c = a + b
    return (c & MOD) + (c >> 61)

def norm(x):
    x = (x >> 61) + (x & MOD)
    if x >= MOD:
        x -= MOD
    return x

def solve():
    n = int(input())
    adj = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        u, v, c = input().split()
        u = int(u)
        v = int(v)
        w = ord(c) - 96
        adj[u].append((v, w))
        adj[v].append((u, w))

    down = [[0] * len(adj[i]) for i in range(n + 1)]
    parent = [0] * (n + 1)

    def dfs(u, p):
        parent[u] = p
        for i, (v, w) in enumerate(adj[u]):
            if v == p:
                continue
            dfs(v, u)

    dfs(1, 0)

    up = [0] * (n + 1)

    def dfs2(u, p):
        prefix = [0]
        edges = adj[u]

        for i, (v, w) in enumerate(edges):
            if v == p:
                val = up[u]
            else:
                val = down[v][adj[v].index((u, w))]
            prefix.append(mod_add(mod_mul(val, BASE), w))

        suffix = [0] * (len(edges) + 1)
        for i in range(len(edges) - 1, -1, -1):
            v, w = edges[i]
            if v == p:
                val = up[u]
            else:
                val = down[v][adj[v].index((u, w))]
            suffix[i] = mod_add(mod_mul(val, BASE), w)
            suffix[i] = mod_add(suffix[i], suffix[i + 1])

        for i, (v, w) in enumerate(edges):
            if v == p:
                up[v] = prefix[i] + suffix[i + 1]
            else:
                up[v] = prefix[i] + suffix[i + 1]

        for v, _ in edges:
            if v != p:
                dfs2(v, u)

    dfs2(1, 0)

    def get_hash(u, v, w):
        if parent[v] == u:
            return down[v][adj[v].index((u, w))]
        return up[u]

    ans = 0
    for u in range(1, n + 1):
        seen = set()
        ok = True
        for v, w in adj[u]:
            h = get_hash(u, v, w)
            if h in seen:
                ok = False
                break
            seen.add(h)
        if ok:
            ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```実装は DP の再ルートを中心に構成されています。 最初の DFS は親関係を確立するので、どの方向が「下向き」であるかを知ることができます。 2 番目の DFS は寄与を上向きに伝播し、すべての有向エッジがその視点からツリーの完全なビューを持つようにします。 

微妙な部分は、各方向のハッシュ寄与を一貫して構築することです。 各エッジ方向は、O(1) で対応するサブツリー ハッシュを取得できる必要があるため、隣接インデックス付けと事前計算された子の結果に依存します。 プレフィックス配列とサフィックス配列は、情報を下方向に渡すときに 1 つの隣接ノードを除外するために使用されます。これは、標準的な再ルート手法です。 

最後のループは実際の決定ステップです。各ノードはすべてのインシデント方向のハッシュを収集し、重複が存在しないことを確認します。 

## 実用的な例

 a と b というラベルが付いたエッジを持つ 3 つのノードが一列に並んだ単純なツリーを考えてみましょう。 

入力：```
3
1 2 a
2 3 b
```ノード 2 がルートの場合、文字列は { "", a, b } となり、すべて異なります。 ノード 1 の場合、文字列は { "", a, ab } です。 ノード 3 の場合、文字列は { "", b, ba } です。 すべてのノードが機能します。 

| ルート | ルートからの文字列 | 明確な？ |
 | --- | --- | --- |
 | 1 | ""、a、ab | はい |
 | 2 | ""、a、b | はい |
 | 3 | ""、b、ba | はい |

 これにより、単純な非対称チェーンではすべてのノードが有効であることが確認されます。 

次に、対称分岐の場合を考えてみましょう。```
    1
   / \
  2   3
  a   a
```両方のエッジに同じラベルが付いています。 ルートを 1 にすると、両方の子は同一の文字列「a」を生成します。 これは主観性に違反します。 

| ルート | ルートの入射方向ハッシュ | 明確な？ |

 | 3 | ""、ああ | はい |

 ## 特殊なケース

 重要なエッジケースは、ノードの複数の子が同一のサブツリー署名を生成する場合です。 たとえば、3 つの葉に接続されているノードはすべてエッジ ラベル「a」を持ちます。 ルートとしてのこれらのリーフはいずれも問題ありませんが、送信方向ハッシュが重複しているため、センターは無効です。 中心にある 3 つのインシデント ハッシュがすべて同一であるため、アルゴリズムはこれを検出し、拒否をトリガーします。 

もう 1 つの特殊なケースは、ツリーが単純なパスである場合です。 どのノードも 2 つ以上の方向を持ちません。左右の方向のハッシュは、反転したパス構造を表すため、常に区別されます。 再ルートする DP はこの非対称性を維持するため、すべてのノードが受け入れられます。 

最後のエッジ ケースには、同一のラベルが付けられたサブツリーがツリーの異なる部分に存在するが、ルートには隣接していない深いツリーが含まれます。 再ルート化により、これらの同一の構造が候補ルートで発生した場合にのみ等価性が検出されるようになり、誤検知が防止されます。
