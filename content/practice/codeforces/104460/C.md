 ## 解決策
 ## 問題の理解

 数字 0、6、8、9 のみからなる文字列が与えられます。操作は 1 つだけ実行します。つまり、連続するセグメントを選択し、それを反転し、180 度の回転ルールを使用してその反転したセグメント内のすべての数字を置き換えます。このルールでは、0 は 0 に、8 は 8 にマッピングされ、6 と 9 は相互に交換されます。 

選択したセグメントの外側では、文字列は変更されません。 セグメント内では順序が逆になり、各桁が変換されます。 

このタスクは、空ではないセグメントを選択し、この操作を 1 回だけ適用することによって、異なる完全な文字列が何個取得できるかをカウントすることです。 

文字列の長さはテスト ケースごとに最大 10^6、合計の長さは最大 10^7 にすることができ、部分文字列の二次列挙は直ちに除外されます。 どのようなソリューションも、テスト ケースごとに本質的に線形であるか、最悪の場合でも線形である必要があります。 

微妙な点は、選択された異なるセグメントが同じ最終文字列を生成する可能性があることです。 これは 2 つの方法で起こります。 まず、変換がセグメントに何も影響を及ぼさない場合、つまり反転および回転操作の下でセグメントが不変である場合、そのようなセグメントはすべて元の文字列を生成します。 次に、2 つの異なるセグメントが同じ変更された文字列を生成した場合、変更された位置と変更されていない位置の間に一貫した重複が必要になりますが、これはここでの同一性の場合にのみ発生します。 したがって、実際の重複は、文字列を変更しないままにする操作からのみ発生します。 

素朴なアプローチでは、すべての O(n^2) セグメントを列挙し、毎回変換された文字列を構築し、それをハッシュ セットに挿入します。 この規模ではすべての部分文字列を構築するだけでもコストがかかりすぎ、各変換のセグメント長は線形であるため、これはすぐに失敗します。 

## アプローチ

 ブルートフォースの見方は簡単です。 すべてのペア (l、r) について、部分文字列を抽出して反転し、桁の回転を適用して、文字列のコピーに書き戻します。 各結果は比較またはハッシュされます。 これは正しいですが、セグメントごとに O(n) のコストがかかり、最悪の場合には合計作業量が O(n^3) になり、これは完全に実行不可能です。 

重要な点は、実際には最終的な文字列を構築する必要がないということです。 2 つの操作が同じ結果を生成する場合のみ理解する必要があります。 何も行わないセグメントを除き、ほとんどすべてのセグメントが固有の出力を生成します。 

したがって、問題は、重要な変更を生成するセグメントの数を数えることと、すべての些細なセグメントが 1 つの結果 (元の文字列) に崩壊するという事実を考慮することに帰着します。 

セグメントを反転および回転してまったく同じシーケンスが生成される場合、セグメントは操作によって変更されません。 この条件は、文字列の変換バージョンを導入し、条件を整列されたインデックスに対する単純な等価性チェックに変えることで、よりきれいに書き直すことができます。 再定式化すると、変更されていないセグメントは、整列された 2 つの文字列が完全に一致する正確な間隔になり、一定の実行をカウントすることになります。

 ## アルゴリズムのチュートリアル

 180 度回転する数字のヘルパー変換を定義します。 inv(x) を 0→0、8→8、6↔9 とします。 u[i] = inv(s[i]) となる 2 番目の文字列 u を作成します。 

また、u を逆にして ur を取得します。 このステップでは、セグメント反転の効果を単純な前方比較と調整します。 

次に、セグメント [l, r] について推論します。 演算後、セグメントは reverse(inv(segment)) になります。 セグメントは、元の文字列とセグメントごとに一致する場合にのみ変更されません。 

これにより、[l, r] のすべてのインデックス i について、s[i] が ur[i] に等しくなければならないという直接的な位置合わせ条件が生じます。 したがって、変更されていないセグメントとは、s と ur が 1 文字ごとに同一である位置に完全に含まれる間隔です。 

### ステップ

1. s のすべての文字に桁回転を適用して u を構築します。 これは、まだ逆転することなく 180 度の変化を捉えています。 
2. ur を u の逆として構築します。 これにより、変換された位置が元のインデックスと位置合わせされるため、比較はインデックスごとになります。 
3. s[i] == ur[i] の場合は eq[i] が true、それ以外の場合は false となる配列 eq を構築します。 これにより、対称条件が成立する位置がマークされます。 
4. eq をスキャンし、それを連続する真の値の最大の連続セグメントに分割します。 このような各セグメントは、選択された [l, r] が完全に内側にある領域を表し、操作後も変更されません。 
5. 連続する真値の長さ L のセグメントについて、L(L+1)/2 間隔をカウントします。 これをすべてのセグメントで合計して、変更されていない操作の数を取得します。 
6. 部分文字列の合計を n(n+1)/2 とします。 すべての部分文字列が 1 つの操作に対応します。 ステップ 5 でカウントされたすべての部分文字列によって、元の文字列が生成されます。 他のすべての部分文字列は、個別の変換された文字列を生成します。 
7. 最終的な答えは、total_substrings −Changed_substrings + 1 です。 

### なぜ効果があるのか

 変換は決定的であり、選択したセグメントにのみ依存します。 セグメントが変更されていない場合、最終的な文字列のどこにも変更は加えられません。 このような操作はすべて、同じ結果、つまり元の文字列に折りたたまれます。 少なくとも 1 つの位置を変更するセグメントは、そのセグメントに固定された固有の相違パターンを作成し、両方が変更されていない限り、異なるセグメントは同一の完全な文字列を生成できません。 ur との等価構造により、変更されていないセグメントがインデックス的に完全に一貫していることが保証されるため、eq での実行のカウントはすべての衝突を完全に捕捉します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    inv = {'0': '0', '8': '8', '6': '9', '9': '6'}
    
    for _ in range(T):
        s = input().strip()
        n = len(s)

        u = ''.join(inv[c] for c in s)
        ur = u[::-1]

        eq = [0] * n
        for i in range(n):
            if s[i] == ur[i]:
                eq[i] = 1

        total = n * (n + 1) // 2

        good = 0
        i = 0
        while i < n:
            if eq[i]:
                j = i
                while j < n and eq[j]:
                    j += 1
                L = j - i
                good += L * (L + 1) // 2
                i = j
            else:
                i += 1

        print(total - good + 1)

if __name__ == "__main__":
    solve()
```このコードは、セグメント条件がインデックスの一致における単純な等価性チェックになるように、逆変換された文字列とその逆を構築します。 の`eq`array は問題を連続したランの検索に圧縮し、ランの長さの算術演算により部分文字列を列挙する必要がなくなりました。 

ここでよくある間違いは、これを Manacher のアルゴリズムを使用した回文計数問題として直接処理しようとすることです。 この条件は、中心拡張対称ではなく、固定アライメント上の点ごとの等価に帰着するため、これは不要です。

 ## 特殊なケース

 重要なエッジケースは、文字列全体が変換下で不変である場合です。 たとえば、808 は反転および回転後にそれ自体にマッピングされます。 この場合、考えられるすべてのセグメントが元の文字列を生成するため、答えは 1 に集約されます。すべての位置が s[i] == ur[i] を満たし、単一の全長ランが生成されるため、アルゴリズムはこれを検出します。 

別のエッジ ケースは、0689 など、一致する位置がまったくない場合に発生します。ここで、eq にはゼロのみが含まれるため、不変セグメントは存在しません。 すべての部分文字列は個別の変換文字列に寄与し、答えは total_substrings + 1 になります。適切な合計はゼロであるため、アルゴリズムはこれを自然に処理します。 

最後の微妙なケースは、eq が複数の実行に分割される 0 6 0 6 パターンなどの交互一致です。 各実行は独立して処理され、部分文字列は不変のままで誤った境界を越えることができないため、それらの寄与は干渉しません。
