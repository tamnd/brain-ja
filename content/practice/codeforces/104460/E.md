 ## 問題の理解

 ライトの列を表すバイナリ配列が与えられ、各位置はオンまたはオフになります。 開始インデックスを選択し、固定長の連続セグメントを切り取る操作を実行できます。$L$。 すべての操作では常に同じものを使用します$L$、そして私たちは最大で申請することができます$k$そのような操作。 目標は、可能な限り最小のセグメント長を決定することです。$L$許可された操作回数内で、最初にオンになっているすべてのライトをオフにすることができます。 

重要な点は、各操作は長さに関しては適応せず、位置のみに適応するということです。 一度$L$は固定されており、唯一の自由はウィンドウをどこに配置するかだけであり、文字列内のすべてのものが最大でカバーできるかどうかを知りたいのです。$k$その長さの間隔。 

制約は十分に大きく、次のすべての選択肢に対する二次シミュレーションを実行できます。$L$すべての配置は不可能です。 以来$n$到達できる$2 \times 10^5$テストケースごとに合計が次の値に達します$2 \times 10^6$、テスト ケースごとにほぼ線形またはほぼ線形を目標にする必要があります。 これにより、候補ごとに操作をシミュレートしようとするアプローチが除外されます。$L$素朴な意味で。 

微妙な点は、カバレッジ以外の重複は問題にならないことです。 操作中に正確なオン/オフ状態をモデル化する必要はありません。 「1」を含むすべての位置が最大でもカバーされているかどうかのみ$k$間隔。 

よくある失敗例は、実装が前の操作ですでにどこまでカバーされているかを正確に追跡せずに貪欲な配置を試行した場合に発生します。 

たとえば、次のことを考えてみましょう。```
n = 5, k = 1
s = 10001
```もし$L = 3$、単純に貪欲な人は、最初の 1 をカバーするために 1 から始まる間隔を配置するかもしれませんが、最後の 1 は見逃してしまいます。 1 つの間隔では長さ 3 を超える 2 つの分離された領域をカバーできないため、正しい配置は失敗します。カバレッジの制限を正確に考慮しないアプローチは、実現可能性を誤って評価することになります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 固定の場合$L$、文字列を左から右にスキャンします。 まだカバーされていない「1」に遭遇するたびに、その位置から始まる演算を配置し、次の位置をカバーします。$L$細胞。 すべてがカバーされるか、超えるまで繰り返します$k$操作。 これは正しいです。できるだけ早く間隔を設定しても、将来の柔軟性が低下することはありません。 

問題は、1つをチェックすることです$L$かかります$O(n)$、そしてすべてを試してみます$L$1 から 1 までの値$n$につながる$O(n^2)$、これは大きすぎます$n = 2 \times 10^5$。 

重要な観察は、実現可能性が単調であるということです。$L$。 ある場合$L$最大でもすべてをカバーできれば十分です$k$操作、その後さらに大きな操作$L$また、各操作がより多くのセルをカバーし、必要な操作数が増加することがないため、これでも十分です。 これにより、答えを二分探索することができます。 

ここで問題は、修正の実現可能性をチェックすることになります。$L$、線形時間で貪欲に実行できます。 文字列をスキャンし、カバーされていない「1」を見つけるたびに、その位置から開始する間隔を置き、前方にスキップします。$L$。 使用される間隔の数は次と比較されます。$k$。 

この貪欲な実現可能性チェックと二分探索の組み合わせにより、効率的なソリューションが得られます。

 ## アルゴリズムのチュートリアル

 二分探索を使用して各テスト ケースを個別に解決します。$L$。 

1. 関数を定義する`can(L)`最大でもすべての「1」の位置をカバーできるかどうかをチェックします。$k$長さのセグメント$L$。 左から右にシミュレートし、最後に配置されたセグメントがどこまで到達するかを追跡します。 
2.内部`can(L)`、ポインタを維持します`i`文字列とカウンターをスキャンする`cnt`使用したセグメントの数。 ポジションに出会ったとき`i`まだカバーされていない「1」を使用してインクリメントします`cnt`範囲を拡張するように設定します`i`に`i + L - 1`。 
3. 次に、次のように移動して、このセグメントでカバーされるすべての位置をスキップします。`i`フォワード。 これにより、各セグメントが可能な限り早いカバーされていない「1」に貪欲に配置され、無駄なカバレッジが最小限に抑えられます。 
4. いつでも`cnt > k`、許可された操作数を超えたため、早期に停止して false を返します。 
5. 二分探索を実行します。$L$1から$n$。 中間点ごとに、次の呼び出しを行います。`can(mid)`。 可能であれば、より小さい値を試します。 それ以外の場合は増加します$L$。 
6. 最小値を出力します$L$誰のために`can(L)`trueを返します。 

貪欲な配置は固定に最適です$L$最初のカバーされていない「1」より後にセグメントを配置すると、必要なセグメントの数を減らすことができず、追加のカバーされていないセグメントが残るだけになる可能性があるためです。 

### なぜ効果があるのか

 正確さはカバレッジの不変条件に依存します。 各セグメントが配置された後、その右端までのすべての位置が完全に解決されます。つまり、将来の決定はそれらに依存しません。 カバーされていないすべての「1」は、その位置またはその前で少なくとも 1 つのセグメントを開始する必要があります。 貪欲戦略は常に可能な限り早い時点でこの要件を満たし、すでにカバーされている領域でセグメントが無駄にならないようにします。 したがって、生成されるセグメントの数は最小限になります。$L$により、実現可能性チェックが正確になります。 

実現可能性が単調なので$L$、二分探索オーバー$L$は有効であり、その組み合わせによりグローバル最小値が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can(s, n, k, L):
    cnt = 0
    i = 0
    while i < n:
        if s[i] == '1':
            cnt += 1
            if cnt > k:
                return False
            i += L
        else:
            i += 1
    return True

def solve():
    n, k = map(int, input().split())
    s = input().strip()

    lo, hi = 1, n
    ans = n

    while lo <= hi:
        mid = (lo + hi) // 2
        if can(s, n, k, mid):
            ans = mid
            hi = mid - 1
        else:
            lo = mid + 1

    print(ans)

if __name__ == "__main__":
    t = int(input())
    for _ in range(t):
        solve()
```機能`can`これは貪欲なカバレッジ プロセスを直接実装したものです。 重要な詳細は、「1」を押すとすぐに操作をコミットし、次のステップにジャンプすることです。$L$なぜなら、最適な解は一定の間隔を置いてその位置をカバーする必要があり、遅延すると後で余分な操作が発生する危険があるだけだからです。 

二分探索は標準的な方法で実装され、最小有効領域まで実行可能な領域を絞り込みます。$L$が見つかりました。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    def can(s, n, k, L):
        cnt = 0
        i = 0
        while i < n:
            if s[i] == '1':
                cnt += 1
                if cnt > k:
                    return False
                i += L
            else:
                i += 1
        return True

    def solve():
        n, k = map(int, input().split())
        s = input().strip()

        lo, hi = 1, n
        ans = n

        while lo <= hi:
            mid = (lo + hi) // 2
            if can(s, n, k, mid):
                ans = mid
                hi = mid - 1
            else:
                lo = mid + 1

        return ans

    t = int(input())
    out = []
    for _ in range(t):
        out.append(str(solve()))
    return "\n".join(out)

# already all zeros except one far

# all ones

# multiple segments needed
assert run("1\n6 2\n101010\n") == "3"
