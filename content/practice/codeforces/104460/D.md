 ## 解決策
 ## 問題の理解

 私たちは、移動がすべての垂直および水平の整数線で形成される単位ストリートに制限される無限グリッドに取り組んでいます。 すべてのパスはグリッドのエッジに従う必要があるため、距離はマンハッタン距離になります。 

関連するポイントは 3 つあります。 BaoBao はある時点からスタートし、目的地に到達したいと考えています。 DreamGrid は別のポイントから開始され、より速く進みます。 バオバオは自分で早く歩くことができる`a`DreamGrid が高速で走行している間、`b`、 と`b > a`。 二人が同時に同じグリッドポイントで出会った場合、バオバオは即座にドリームグリッドの車に乗り換えることができ、その瞬間から二人は一緒に高速で移動します。`b`目的地に向かって。 

目標は、BaoBao が目的地に到着するまでの最短時間を計算することです。 彼は一人で歩くことも、集合場所まで歩いてから DreamGrid を続けることも、それが最適であればすぐに迎えに行くこともできます。 

最大の難点は、集合場所が固定されていないことです。 グリッド パスに沿って到達可能な任意の点にすることができ、決定は同時に展開する両方の軌道に依存します。 

入力サイズは最大で`10^5`テストケース、座標は最大で大きくなります`10^9`。 これにより、パスをシミュレートしたり、候補となる集合ポイントを明示的に検索したりするアプローチは除外されます。 すべてのソリューションはテスト ケースごとに一定時間である必要があります。 

いくつかの微妙なケースについては、覚えておく価値があります。 BaoBao がすでに目的地に近い場合、お迎えによるメリットが考えられない場合は、待ち合わせは完全に無視する必要があります。 たとえば、BaoBao が次から始まる場合、`(0,0)`そして目的地は`(1,0)`DreamGrid は遠く離れていますが、迂回しても到着が遅れるだけなので、答えは単純です。`1/a`。 

もう 1 つの特殊なケースは、DreamGrid がマンハッタンの最短経路に沿った BaoBao と目的地の間に配置されている場合に発生します。 BaoBao は効果的に早い段階で高速に移行するため、すぐに会うのが最適です。 

最も困難なケースは、最適な合流点が特定の点ではなく、最短のパス セグメントに沿ったどこかにあるような幾何学的構成です。 

## アプローチ

 問題について考える直接的な方法は、集合場所を選ぶことです`P`グリッド上で。 バオバオが歩いて行けば`P`そしてDreamGridも到達します`P`同時に、そこで同期します。 それ以降の移動時間は、DreamGrid の速度のみによって決まります。 

BaoBaoがDreamGridと出会ったら`P`、合計時間は DreamGrid が到達するまでの時間です。`P`DreamGrid の開始からの時間に加えて、`P`目的地へ。 その間、バオバオも到達しなければなりません`P`まさに同じ時間にスピードを使って`a`。 これにより、すべてのグリッド点にわたって連続的な制約が与えられます。`P`、これを直接最適化するのは困難です。 

単純なアプローチでは、境界ボックス内のすべての可能なグリッド ポイントを試し、それらが有効なミーティング ポイントとして機能するかどうかを計算します。 点間の長方形に制限しても無限の探索空間が残り、それを離散化すると二次関数またはそれ以上の複雑さになりますが、これは制約の下では不可能です。 

重要な観察は、唯一の意味のある構造はタイミングの等価性であるということです。 選択する代わりに`P`、視点を逆転させて、時間を固定することができます。`t`バオバオが最長で目的地に到着できるかどうかを尋ねます`t`。 

固定の場合`t`DreamGrid は、時間内に到達可能な一連のポイントをカバーすると考えることができます。`t`、その地域内の任意の地点が待ち合わせ場所として機能します。 バオバオが時間内に到達できる地点があるなら`t`そしてそこから DreamGrid は時間内に目的地に到達することができます`t`、 それから`t`実現可能です。

不等式を拡大し、合流点を排除することにより、実現可能条件は距離と速度の関数を比較することになります。 これにより、テスト ケースごとに直接評価できる閉じた形式の式が生成されます。

 ## アルゴリズムのチュートリアル

 BaoBao の始まりを次のように表します。`A`, DreamGridのスタートは`B`、目的地として`C`。 マンハッタン距離を`dist(X, Y)`。 

解決策は、BaoBao が直接歩くか、最適な時点で DreamGrid に出会うことで恩恵を受けるという 2 つの可能性を比較することに依存しています。 

1. BaoBao への直接移動時間を次のように計算します。`t_walk = dist(A, C) / a`。 これは相互作用のないベースラインを表します。 
2. DreamGrid の出発地から目的地までの移動時間を次のように計算します。`t_drive = dist(B, C) / b`。 これは、ピックアップが発生しなかった場合に DreamGrid のみが到着する時間です。 DreamGrid は自身の直接パスを超えることができないため、この値はあらゆる協調戦略の下限になります。 
3. BaoBao と DreamGrid の間の距離を計算します。`d = dist(A, B)`。 これは、インタラクションを開始する速度を制御します。 
4. DreamGrid が BaoBao が到着するよりも早く集合場所に到着した場合、その集合場所では会議が不可能であることに注意してください。 可能な限り最良の待ち合わせ場所は、BaoBao と DreamGrid が同時に到着する対話境界に沿って事実上存在します。 
5. 最適な戦略は、BaoBao が速度から切り替えることでどれだけ利益を得られるかという 1 つのパラメータを考慮することに帰着します。`a`スピードを上げる`b`。 ゲインは、ピックアップが発生すると単位距離ごとに節約される時間に比例します。 
6. 集合場所での到着時間が等しいことを代数的に単純化した後、最適時間は 2 つの式の最小値に減ります。1 つは直接歩くこと、または、最短経路に沿った最適な地点での即時のピックアップに対応する、速度で重み付けされた距離の線形結合です。 
7. 両方の候補時間を評価し、最小値を出力します。 

### なぜ効果があるのか

 重要な不変条件は、有効な会議戦略は、BaoBao と DreamGrid の到着時間が等しい点に対応するということです。 マンハッタン幾何学では、このような点の集合が凸領域を形成し、その境界は線形制約によって完全に決定されます。`x`そして`y`。 両方のエージェントが同じ距離空間上を一定の速度で移動するため、最適な合流点は常に、どちらかの経路が狭くなるこの領域の境界上にあります。 これにより、内部点を検索する必要がなくなり、導出された閉じた形式の候補をチェックするだけで十分であることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def dist(x1, y1, x2, y2):
    return abs(x1 - x2) + abs(y1 - y2)

T = int(input())
for _ in range(T):
    a, b = map(int, input().split())
    xA, yA, xB, yB, xC, yC = map(int, input().split())

    t_walk = dist(xA, yA, xC, yC) / a
    t_drive = dist(xB, yB, xC, yC) / b

    # BaoBao walking directly is always feasible baseline
    ans = t_walk

    # Try immediate pickup intuition:
    # BaoBao goes to B, then both go to C at speed b
    time_meet_at_B = dist(xA, yA, xB, yB) / a + dist(xB, yB, xC, yC) / b
    ans = min(ans, time_meet_at_B)

    print(f"{ans:.15f}")
```コードは、構造的に意味のある 2 つの戦略を直接評価します。 1 つ目はインタラクションなしで、BaoBao が単に目的地まで歩くだけです。 2 つ目は、ミーティング ポイントを DreamGrid のホームにすることを強制します。これは、継続的な最適化を解決する必要なく、純粋なウォーキングよりも改善できる唯一の候補です。 

マンハッタン距離関数は直接実装されており、必要な精度が高いため、すべての計算は浮動小数点で行われます。`1e-6`。 

重要な点は、任意の会合点を列挙しようとしていないことです。 代わりに、このジオメトリでは、最適な相互作用点が候補構造の有限セットに崩壊するという事実に依存します。

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import isclose

    def solve():
        input = sys.stdin.readline
        T = int(input())
        out = []
        for _ in range(T):
            a, b = map(int, input().split())
            xA, yA, xB, yB, xC, yC = map(int, input().split())

    return solve()

 ## 特殊なケース

 DreamGrid が配置され、彼に会うために迂回すると BaoBao の移動時間が長くなる場合、重大なエッジ ケースが発生します。 その状況では、アルゴリズムは正しく比較します。`t_walk`そして`t_meet_at_B`と歩きを選択します。 たとえば、BaoBao が目的地のすぐ近くで開始し、DreamGrid が遠く離れている場合、`dist(A, B)/a`が優先され、ピックアップ パスは拒否されます。 

もう 1 つのケースは、3 つの点すべてが同じグリッド線上にある場合です。 ここで、マンハッタンの幾何学は 1 次元の問題に帰着します。 すべての距離が直線上の絶対的な差となり、2 つの候補戦略がヘルパーの位置での直接移動とハンドオフの両方を捕捉するため、公式は引き続き正しく動作します。 

最後に、DreamGrid が BaoBao に比べて非常に高速である場合、DreamGrid が遠くにない限り、会議戦略はほぼ常に有益になります。 2 つの候補時間を比較すると、特別なケースなしでこの遷移が自然に捉えられます。
