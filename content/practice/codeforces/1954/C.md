 ## 解決策
 ## 問題の理解

 文字列として表現された 2 つの非常に大きな整数が与えられ、どちらも同じ桁数を持ちます。 すべての数字は 1 ～ 9 なので、位置の影響や先頭のゼロの問題を複雑にするゼロはありません。 

許可される唯一の操作は、2 つの数値間の同じ位置にある桁を交換することです。 言い換えれば、任意のインデックス i について、ペアを維持することができます。`(x[i], y[i])`そのまま、または交換して次のようになります。`(y[i], x[i])`。 この決定はポジションごとに独立していますが、目標はグローバルです。両方の数値の最終的な数値が積を最大化することが必要です。`x * y`。 

重要な観察は、数字が大きい番号の文字列に配置されるか、小さい番号の文字列に配置されるかに応じて、各位置の寄与が異なるということです。 乗算は位置表記における桁の配置に影響されるため、後の桁よりも最初の (上位) 桁の方が重要です。 ただし、単一の数値を構築しているのではなく、積が両方に同時に依存する 2 つの数値を構築しています。 

この制約により、最大 1000 のテスト ケースと最大 100 桁の数値が許可されます。 これは、数値に対する二次または指数関数のアプローチでは遅すぎるため、テスト ケースごとに O(n) または O(n log n) の解が必要であることを直ちに示唆します。 

単純な間違いは、辞書編集的に個々の数値を常に最大化する必要があると想定することです。 一方の数値を改善すると、もう一方の数値が著しく損なわれる可能性があるため、これは失敗します。 

たとえば、ある位置に数字があるとします。`(9, 1)`。 それらをそのままにしておきます`(9, 1)`作る`x`局所的には大きいですが、`y`より小さい。 スワッピングが与える`(1, 9)`。 局所的には、どちらの決定も単独で検討した場合に明らかに優れているわけではありませんが、製品は両方に依存します。 これは、決定が対称的であり、慎重に選択される必要があることを示しています。 

もう 1 つの失敗例は、各数値の独立した桁の貪欲な最大化から生じます。`x`、誤って大きな数字を 1 つの数字にまとめてしまい、もう 1 つの数字を弱めすぎて積を減らしてしまう可能性があります。 

最も難しいのは、位置ごとに、ペアのどの配置が最良の全体的な乗算効果を生み出すかを決定することです。 

## アプローチ

 ブルートフォースアプローチはすべてを試みるでしょう`2^n`ポジションを交換する方法。 構成ごとに、結果として得られる 2 つの数値を計算し、それらを乗算します。 これは、各数字ペアの可能な割り当てをすべて調査するため、正しいです。 ただし、n が 100 までの場合、これは次のようになります。`2^100`テストケースごとに可能性がありますが、これは完全に不可能です。 

重要な洞察は、掛け算によって集中力ではなくバランスが得られることに気づくことから得られます。 積を桁ごとに拡張すると、ペアを交換します`(a, b)`は両方の数値の 1 桁の位置にのみ影響し、最終的な積への影響は、他の位置と比較したその局所的な選択にのみ依存します。 より正確には、各位置は 2 つの数値間での桁の分布方法に基づいて項に寄与し、交換はその寄与を局所的に変更するだけです。 

単一のポジションを独立して検討する場合、選択肢は 2 つだけです。`(x[i], y[i])`またはそれに交換します`(y[i], x[i])`。 グローバル割り当てはこれらの独立した二項選択の単なる組み合わせであるため、ポジション間の相互作用を考慮する必要はありません。 各ローカル決定により両方の数値に対する大きな桁の寄与がバランスよく増加すると、積は最大化されます。 

これにより、驚くほど単純なルールが得られます。各位置で、その位置で現在小さい数字を持つ数字に大きい数字が割り当てられるようにする必要がありますが、数字は位置間で独立しており、このレベルの推論では乗算にキャリー相互作用がないため、最適な戦略は一貫した貪欲なタイブレークに帰着します。つまり、数字のペアの対称性を最大限に保つ方法で、最初の数字が辞書編集的に 2 番目の数字より小さくならないようにペアの順序を維持します。 

標準の導出はさらに単純化されます。`x * y`、最も重要な異なる位置で両方の数値をできるだけ大きくする必要があり、交換は両方の数値にわたる大きな桁のバランスが改善される場合にのみ有益です。 最適な戦略は、両方の数値を可能な限り「揃える」ことです。これは、各位置で大きい桁を同じ数値に一貫して割り当てることによって達成されます (たとえば、大きい桁を常に同じ側に押し込むか、最初の差分パリティに基づく一貫したルールに従うなど)。 この貪欲な局所アラインメントにより、積が最大化されます。これは、不一致があると、より重要度の高いもう一方の因子のゲインが補償されずに一方の因子が減少するためです。 

クリーンな実装は、各桁のペアをソートして、常に大きい桁を`x`そしてそれより小さい`y`またはその逆も一貫しており、最大の成果を維持する全体的な一貫性に基づいて方向を選択します。 

実際、最も単純で最適な観察は、各位置に対して、結果の数値ができるだけ近くなり、両方が大きいままになるように数値を割り当てる必要があることです。これは、不均衡を最小限に抑える方法で位置ごとに数値を並べ替えることによって実現されます。 この貪欲なローカルペアリングは、位置の大きさを超えた位置間の依存関係が存在しないため、最適です。

 ## アルゴリズムのチュートリアル

 1. 数値を表す 2 つの文字列を読み取ります。 

各位置を独立して処理できるように、それらを数字の配列として扱います。 
2. 各インデックス i について、左から右に次のペアを考慮します。`(a, b) = (x[i], y[i])`。 

この立場で、スワップがグローバル製品を改善するかどうかを判断します。 
3. 2 つの可能な割り当てを比較します。`(a, b)`またはに交換します`(b, a)`。 

先頭の大きい桁が積を支配するため、可能な限り最初の数値が 2 番目の数値より小さくならない割り当てを選択します。 
4. 結果の文字列をそれに応じて構築します。 

それぞれの位置は独立して決定されますが、一貫性があり、2 つの数値間に不必要な非対称性が生じないようにします。 
5. 最後の 2 つの数値を出力します。 

### なぜ効果があるのか

 各桁の位置は、位置の重みを通じて乗算的に寄与します。 すべての桁が正であり、ポジション間にキャリーの相互作用がないため、1 つのインデックスでの交換は、他のインデックスでの決定の相対的な順序に影響を与えません。 これにより、各位置について、製品に対するより重要な影響に対する上位桁の寄与を最大化する配置を選択するという問題が軽減されます。 貪欲な調整により、ローカル スワップが他のより重要な位置で積を減らさずに積を増やすことができなくなり、グローバルな最適性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        x = list(input().strip())
        y = list(input().strip())

        a = []
        b = []

        for i in range(len(x)):
            if x[i] < y[i]:
                x[i], y[i] = y[i], x[i]
            a.append(x[i])
            b.append(y[i])

        print("".join(a))
        print("".join(b))

if __name__ == "__main__":
    solve()
```実装では、各テスト ケースが個別に処理されます。 すべての位置に対して、一貫した順序付けが適用されます。つまり、大きい数字が に入ります。`x`、小さいほど`y`。 これは、必要に応じて交換することで実装されます。 

Python の文字列は不変であり、連結を繰り返すと非効率になるため、文字のリストを使用します。 最後の結合により、出力が効率的に再構築されます。 

決定ルールはローカルですが、正確さは、許可される変換に関して各桁の位置が独立して寄与するという事実に依存します。

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

 ## 特殊なケース

 エッジ ケースの 1 つは、すべての桁がどの位置でも同一である場合です。`111...`そして`111...`。 この場合、スワップによってどの位置も変更されないため、どの出力も有効になります。 アルゴリズムが交換されることはありません。`x[i] < y[i]`等価性については false となり、正しさが維持されます。 

もう 1 つのエッジ ケースは、ある数値の桁が厳密に小さいものの、後の位置に大きな桁がある場合です。 例えば、`x = 219`、`y = 981`。 アルゴリズムは必要に応じてすべての位置でスワップし、`921`そして`189`。 各スワップは局所的に最適であり、最終的な配置により、より大きな桁が一貫して同じ側に割り当てられるようになり、積を減らす不必要な不均衡が回避されます。
