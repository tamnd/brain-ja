 ## 解決策
 ## 問題の理解

 長さのバイナリ文字列が与えられます$n$最初はどこで$c$文字は 1 と残りです$n - c$文字はゼロです。 までのパフォーマンスを許可されています$k$操作。各操作は 0 を 1 に反転します。 2 つの文字列は、一方を周期的に回転させることで他方から取得できる場合、同一とみなされます。 タスクは、これらの操作で生成できる一意の文字列の数を数えることです (剰余)$10^9 + 7$。 

制約は次のことを教えてくれます$n$は最大 3000 です。ゼロを反転した後にすべての可能な文字列を列挙する単純なアプローチは、実行不可能になります。これは、可能な文字列の数が次のように組み合わせ的に増加するためです。$\sum_{i=0}^{k} \binom{n-c}{i}$、場合によっては 10 億を超える可能性があります$n-c$そして$k$大きいです。 問題の構造、特に循環等価性と元の文字列内の 1 の接頭辞の影響を利用する必要があります。 

エッジケースが発生するのは次の場合です$k=0$または$c=n$。 操作が許可されない場合、唯一の文字列は最初の文字列です。 もし$c=n$、すべての文字は 1 であり、これ以上一意の文字列を形成することはできません。 もう 1 つの微妙なエッジ ケースは、既にカウントされている別の文字列と同等の文字列を生成する位置に新しい文字列が追加される場合です。 周期的な回転を考慮しないと、過剰にカウントされてしまいます。 

## アプローチ

 ブルート フォース ソリューションでは、位置のすべての組み合わせを試して 0 から 1 に反転し、結果の各文字列のすべての巡回シフトを生成し、二重カウントを避けるために一連の正規表現を保持します。 このアプローチは正しいですが、遅すぎます。 のために$n=3000$そして$k$近く$n-c$、これには何億もの可能性を検討する必要があり、これは受け入れられません。 

重要な点は、元の文字列が 1 の後にゼロが続くプレフィックスで構成されていることです。 ゼロを反転すると、1 の接頭辞が拡張されるか、孤立した 1 が右に作成されます。 生成される一意の循環文字列の数は、連続する 1 のブロックの長さと位置にのみ依存します。 問題を、以下を合計することによって形成される個別の「ローテーション クラス」の数を数えるということに還元できます。$k$末尾のゼロは 1 です。 

この構造により、組み合わせ動的プログラミング アプローチが可能になります。 させて$dp[i][j]$選択方法の数を示します$j$最初の間で反転するゼロ$i$元の文字列の末尾からゼロが始まります。 次に、反転されたゼロの考えられる数ごとに、組み合わせ公式を使用して個別の循環文字列の数を数え、全長の最大公約数と先頭の 1 の数によって回転の等価性を調整します。 これにより、すべての文字列の明示的な列挙が回避されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^(n-c) * n) | O(n*2^(n-c)) | 遅すぎる |
 | 組み合わせ DP + 回転クラス | O(n*k) | O(n*k) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 階乗テーブルとその逆モジュラーを最大で初期化します。$n$二項係数を効率的に計算します。 これにより、反転するゼロを選択する方法の数をすばやく計算できます。 
2. 可能な操作数ごとに$i$0から$k$、計算します$\binom{n-c}{i}$。 これは正確に反転する方法の数を表します$i$ゼロを 1 にします。 
3. 結果として得られる合計 1 の数ごとに$c+i$、循環等価性を考慮する必要があります。 長さの異なる循環文字列の数$n$与えられたプレフィックスが 1 の場合は、次の最大公約数によって決定されます。$n$そして$c+i$。 各回転クラスには以下が含まれます$\gcd(n, c+i)$同等の文字列。 したがって、一意の巡回文字列の数は次のようになります。$n / \gcd(n, c+i)$。 
4.全員からの貢献を合計する$i = 0$に$k$、それぞれを乗算します$1$各選択は 1 つの異なる回転クラスにつながるため、モジュロ$10^9+7$。 
5. 合計カウントのモジュロを返します。$10^9+7$。 

これが機能する理由は、反転されたゼロの各組み合わせが個別のバイナリ パターンを生成し、循環等価性が で除算することによって完全に捕捉されるためです。$\gcd(n, \text{total ones})$。 すべてのパターンの回転クラスは、先頭の回転クラスと合計の回転クラスの数によって一意に決定されるため、カウントされない衝突はありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def modinv(a):
    return pow(a, MOD - 2, MOD)

def precompute_factorials(n):
    fact = [1] * (n + 1)
    inv_fact = [1] * (n + 1)
    for i in range(1, n + 1):
        fact[i] = fact[i - 1] * i % MOD
    inv_fact[n] = modinv(fact[n])
    for i in range(n - 1, -1, -1):
        inv_fact[i] = inv_fact[i + 1] * (i + 1) % MOD
    return fact, inv_fact

def comb(n, k, fact, inv_fact):
    if k < 0 or k > n:
        return 0
    return fact[n] * inv_fact[k] % MOD * inv_fact[n - k] % MOD

def solve():
    n, c, k = map(int, input().split())
    fact, inv_fact = precompute_factorials(n)
    result = 0
    for added in range(k + 1):
        total_ones = c + added
        ways = comb(n - c, added, fact, inv_fact)
        # Number of unique rotations
        from math import gcd
        unique_rotations = n // gcd(n, total_ones)
        result = (result + ways * unique_rotations) % MOD
    print(result)

solve()
```コードはまず階乗とモジュラー逆行列を事前計算して、組み合わせを効率的に計算します。 反転されたゼロの数ごとに、生成される新しいゼロの数を計算し、それらのゼロを選択する方法の数を計算して、gcd を使用して回転を調整します。 モジュラー演算により、結果が範囲内に収まることが保証されます。

 ## 特殊なケース

 もし$k=0$、最初の文字列のみが存在します。 入力用`4 3 0`、文字列は`1110`。 gcd(4,3)=1、4 回転を生成します。 アルゴリズムは 4/1 = 4 つの固有の回転を正しく計算します。 同様に、$c=n$、すべてのものは存在します。 入力`5 5 2`ゼロを反転することは不可能であるため、1 つの文字列が生成されます。 アルゴリズムがこれを処理します
