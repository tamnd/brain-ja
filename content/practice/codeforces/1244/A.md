 ## 解決策
 ## 問題の理解

 ポリュカープは明日、講義の執筆と実技授業での描画の 2 種類の仕事があります。 講義にはペンを使用する必要があり、各ペンは乾くまでに限られた数の講義に使用できます。 実践的な授業では鉛筆を使用する必要があり、各鉛筆は使用できなくなる前に、一定数の授業で再利用できます。 

すべての講義と実技授業をカバーできるように、ペンと鉛筆を何本持っていくかを選択し、最大で収納できる筆箱にすべてを収めるのが課題です。$k$アイテムの合計。 ワークロード要件を満たすこととキャパシティ内に収まることの両方が不可能な場合は、失敗を報告する必要があります。 

各テストケースには講義の数が与えられます$a$、実践的な授業$b$、ペン容量$c$、鉛筆の容量$d$、合計ストレージ制限$k$。 有効なペアを出力します$(x, y)$どこ$x$ペンはすべての講義をカバーし、$y$鉛筆はすべての実技授業をカバーします。$x + y \le k$。 

重要な制約は、ペンと鉛筆は使用上は独立していますが、共有の容量制限によって結合されていることです。 この結合が問題を自明ではないものにしています。 

入力境界は小さく、すべての値は最大 100、最大 100 のテスト ケースです。 これにより、テスト ケースごとの一定時間よりも重いものは直ちに排除されます。 たとえ$O(k^2)$このアプローチは理論的には問題ありませんが、不要です。 

容量が小さいにもかかわらず、要件の 1 つによって多数の項目が強制される場合、微妙なエッジ ケースが発生します。 たとえば、次の場合$a = 10, c = 1$、その場合、少なくとも10本のペンが必要です。 もし$k < 10$、鉛筆が無関係でも答えは不可能です。 タイプごとの最小値を尊重せずに全体の実現可能性のみをチェックする単純なアプローチは、ここでは失敗します。 

柔軟性を考慮せずに、貪欲に合計項目を最小化しようとすると、別の問題が発生します。 有効なペアはどれでも受け入れられるため、最小化は不要であり、考えすぎたり、バランス戦略が間違ったりする可能性があります。 

## アプローチ

 ブルートフォース手法では、考えられるすべての数のペンが試行されます。$x$0から$k$、カバーできる講義の数を計算し、対応する数の鉛筆が存在するかどうかを確認します。$y$カバレッジ制約と容量制限の両方を満たします。 それぞれについて$x$、計算の実現可能性は定数時間であるため、合計の複雑さは次のようになります。$O(k)$テストケースごとに。 これは制約の下ですでに機能していますが、必要以上に複雑です。 

重要な点は、必要なペンの最小数が決まっていることです。各ペンはカバーをカバーします。$c$講義なので少なくとも必要です$\lceil a / c \rceil$ペン。 同様に、少なくとも必要なものは、$\lceil b / d \rceil$鉛筆。 これらの最小限必要な数を正確に取得した場合、残る唯一の問題は、それらが筆箱に収まるかどうかです。 そうでない場合、どちらのタイプを増やしても、固定された上限の下では項目を増やすことは決して実現可能性を高めることができないため、キャパシティの状況が悪化するだけです。 

これにより、問題は直接的な実現可能性チェックに減じられ、その後に必要な最小限の構成が出力されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(k)$テストごと |$O(1)$| 受け入れられるが不要 |
 | 最適 |$O(1)$テストごと |$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 必要なペンの最小数を次のように計算します。$x = \lceil a / c \rceil$。 各ペンは最大でもサポートするため、これによりすべての講義が確実にカバーされます。$c$講義。 
2. 必要な鉛筆の最小数を次のように計算します。$y = \lceil b / d \rceil$。 これにより、各鉛筆が最大でサポートするため、すべての実践的なクラスが確実にカバーされます。$d$クラス。 
3. かどうかを確認します。$x + y \le k$。 これにより、筆箱の制約が確実に満たされます。 
4. 条件が失敗した場合、出力$-1$なぜなら、最も効率的な選択肢であってもすでに容量を超えており、代替手段を選択しても使用量が増えるだけだからです。 
5. それ以外の場合は出力$x$そして$y$。 追加の項目は不要であり、この問題では有効な構成が許可されるため、この最小限の構成で十分です。 

### なぜ効果があるのか

 この構築では、ワークロード要件を満たしながら、各タイプのアイテムの数を可能な限り最小限に抑えます。 有効なソリューションでは、少なくともこれらの数のペンと鉛筆を個別に使用する必要があります。どちらかを減らすとすべてのタスクをカバーできないためです。 したがって、この最小限の構成でも容量を超えた場合は、再配置しても修正できません。 適合する場合、それは自動的に有効なソリューションになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    a, b, c, d, k = map(int, input().split())

    pens = (a + c - 1) // c
    pencils = (b + d - 1) // d

    if pens + pencils > k:
        print(-1)
    else:
        print(pens, pencils)
```計算では整数演算による上限除算が使用され、浮動小数点演算が回避されます。 各テスト ケースは独立して処理されます。 唯一の決定点は、実現可能性のチェックです。$k$、これはストレージの制約を直接反映します。

 | 測定 | 複雑さ | 説明 |

 制約は十分に小さいため、計算を繰り返すことさえ簡単です。 ソリューションはテスト ケースごとに一定時間で実行され、簡単に制限内で実行されます。 

## テストケース```python
import sys, io

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        a, b, c, d, k = map(int, input().split())
        pens = (a + c - 1) // c
        pencils = (b + d - 1) // d
        if pens + pencils > k:
            out.append("-1")
        else:
            out.append(f"{pens} {pencils}")
    return "\n".join(out)

# provided samples
assert solve("""3
7 5 4 5 8
7 5 4 5 2
20 53 45 26 4
""") == """2 1
-1
1 3"""

# minimum case
assert solve("""1
1 1 1 1 2
""") == "1 1"

# tight impossible
assert solve("""1
10 10 5 5 3
""") == "-1"

# exact fit
assert solve("""1
4 6 2 3 3
""") in {"2 2", "2 2".strip()}
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 1 1 1 2 | 1 1 | 自明でない有効な最小ケース |
 | 10 10 5 5 3 | -1 | 容量の関係で無理 |
 | 4 6 2 3 3 | 2 2 | タイトなパッキング境界 |

 ## 特殊なケース

 いつ$a$で割り切れない$c$、天井分割が必要です。 例えば、$a = 5, c = 2$与える$x = 3$。 整数の除算を調整せずに使用すると、誤って 2 が得られ、すべての講義をカバーできません。 

容量が必要な項目と正確に等しい場合、ソリューションはそれを受け入れる必要があります。 たとえば、次の場合$x + y = k$、それは依然として有効であり、平等性を拒否すると、正しい答えが誤って破棄されてしまいます。 

どちらかのとき$a = 0$または$b = 0$、そのカテゴリには項目が必要ないため、数式は引き続き正しく動作し、予想どおりにペンまたは鉛筆が生成されません。
