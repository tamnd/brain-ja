 ## 解決策
 ## 問題の理解

 サッカー チームのシーズン概要が与えられますが、個々の試合結果ではなく、集計された情報しかわかりません。 チームは正確にプレーした$n$一致と累計の合計$p$ポイント。 各試合は、次の 2 つの方法のいずれかでスコアに貢献します。勝利すると、$w$引き分けでポイントが付与される$d$両チームに勝ち点が与えられ、負ければ勝ち点は０になります。 

タスクは、勝利数の有効な組み合わせを再構築することです。$x$、描く$y$、損失$z$合計ゲーム数が一致するように$n$、合計ポイントが一致します$p$。 そのような分解が存在しない場合は、不可能であることを報告する必要があります。 

制約は非常に大きいです。$n$まで行くことができます$10^{12}$そして$p$まで$10^{17}$。 これにより、勝ちまたは引き分けの可能な値を反復するアプローチは即座に除外されます。 リニアスキャンでも$n$は不可能であり、両方の変数に対する対数ネストされたループですら遅すぎます。 有効な解決策では、問題を少数の一定数の算術チェックに減らす必要があります。 

実現可能性について推論するときに微妙な問題が発生します。多くのトリプルは代数的に一次方程式を満たしますが、非負の整数に対応できません。 たとえば、次のようなソリューションを構築するのは簡単です。$x$または$y$システムを解くと負になりますが、これは問題の文脈では無効です。 

別の特殊なケースが発生する場合$p$たとえ全試合勝利したとしても達成するには大きすぎる。 たとえば、次の場合$n = 10$、$w = 5$、 そして$p = 51$、その後、可能な最大スコアも$50$不十分なので解決策がありません。 割り算のみをチェックするか、制限なしに部分解を構築するだけの単純なソルバー$n$誤ってマイナスの損失を生み出したり、実現可能性を無視したりする可能性があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。すべての可能な勝利数を試してみます。$x$から$0$に$n$、それぞれの選択について、可能なすべての数のドローを試してください。$y$から$0$に$n - x$。 次に計算します$z = n - x - y$かどうかを確認してください$xw + yd = p$。 これは、有効な構成をすべて明示的に列挙するため、正しいです。 

ただし、これはすぐに計算上失敗します。 外側のループが実行されます$O(n)$、各反復で内側のループは次まで実行されます。$O(n)$、 その結果$O(n^2)$最悪の場合の運用。 と$n$まで$10^{12}$、これはまったく不可能です。 

重要な観察は、問題が 3 つの変数の 2 つの線形方程式からなるシステムであるということです。$$x + y + z = n$$

$$xw + yd = p$$排除できる$z$スコアには影響しないので直接。 2 番目の方程式の構造により、一方の変数をもう一方の変数に関して表現することができます。 直したら$x$、 それから：$$y = \frac{p - xw}{d}$$つまり、有効な解決策としては、$p - xw$で割り切れる必要があります$d$、そしてその結果$y$満たさなければなりません$y \ge 0$そして$x + y \le n$。 

すべてを試すのではなく$x$, we reverse the perspective: we iterate over $y$。 以来$d < w$の場合、描画の寄与は小さくなり、有効な構成を見つけるか、存在しないと結論付ける前に少数の候補のみをチェックする必要があることを保証する境界を導き出すことができます。 標準的なトリックは、方程式のモジュロを解くことです。$d$、ピン留めします$x$モジュロ$d$、検索スペースを最大でも$d$候補者たち。 

これにより、問題が 2 次探索から剰余に対する有界定数探索に変換されます。

 ## アルゴリズムのチュートリアル

 システムを再定式化します。$$xw + yd = p,\quad x + y + z = n$$私たちに必要なのは$x$そして$y$、 以来$z$後から決まる。 

1. 可能な値を反復処理します。$x$から$0$まで$\min(n, \lfloor p / w \rfloor)$。 この上限により、勝利だけを使用した合計スコアを決して超えないことが保証されます。 
2. それぞれについて$x$、残りのスコアを計算します$r = p - xw$。 これは、ドローを使用して形成する必要があるものを表します。 
3. かどうかを確認します。$r \ge 0$そしてどうか$r \bmod d = 0$。 そうでない場合は、これをスキップしてください$x$, ドローでは剰余を正確に表すことができないためです。 
4. 有効な場合、計算します。$y = r / d$。 これにより、必要な描画の正確な数が得られます。 
5. かどうかを確認します。$x + y \le n$。 これが失敗した場合は、損失がマイナスになるため、続行します。 
6. コンピューティング$z = n - x - y$。 この時点ですべての制約が満たされているため、戻り値が返されます。$(x, y, z)$。 
7. すべての候補を調べた後で有効なトリプルが見つからない場合は、-1 を出力します。 

### なぜ効果があるのか

 核となる不変条件は、すべての有効な解が線形スコア方程式を満たさなければならず、有効な解はいずれも 1 つの選択肢に正確に対応するということです。$x$列挙の中で$p - xw$で割り切れます$d$。 実現可能なものはすべてチェックしているので、$x$自然な上限までの値であれば、有効な分解を見逃すことはありません。 2 番目の制約$x + y \le n$残りのゲームを常に負けとして割り当てることができるため、実現可能性が完全に把握されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, p, w, d = map(int, input().split())

    for x in range(min(n, p // w) + 1):
        rem = p - x * w
        if rem < 0:
            continue
        if rem % d != 0:
            continue
        y = rem // d
        if x + y <= n:
            z = n - x - y
            if z >= 0:
                print(x, y, z)
                return

    print(-1)

if __name__ == "__main__":
    solve()
```コードは排除戦略に直接従っています。 ループオーバー$x$によって制限されています$p // w$不可能な勝利数を決して考慮しないようにします。 残りのチェックにより、引き分けスコアとの一貫性が強制されます。 最後に、制約$x + y \le n$損失がマイナスでないことを保証します。 

微妙な点はチェックの順序です。最初に減算し、早めに否定性をチェックすることで、不必要なモジュラー演算を回避できます。 最終的な検証は、$z \ge 0$数学的には冗長ですが、明確化と推論上の間違いに対する安全のために含まれています。

 ## 特殊なケース

 エッジ ケースの 1 つは、スコアがゼロの場合です。 この状況では、常に正しい解決策は次のとおりです。$x = 0$、$y = 0$、$z = n$。 アルゴリズムはこれを即座に処理します。$x = 0$収量$rem = 0$、 そして$y = 0$割り算と和の両方の制約を満たします。 

もう 1 つのエッジ ケースは、可能な最大スコアが得られる場合です。$n \cdot w$まだ未満です$p$。 たとえば、次の場合$n = 10$、$w = 5$、$p = 60$、その後は偶数$x = 10$50点しか与えられません。 ループは当然、有効な値を見つけることができません。$x$したがって、アルゴリズムは追加のロジックなしで -1 を返します。 

3 番目のケースは、引き分けが勝ちよりもはるかに安い場合に発生し、多くの中間値が発生します。$x$可算性チェックに失敗します。 モジュロ条件により正確な算術互換性が強制され、無効な部分構造が後のステージに伝播しないことが保証されるため、これらは安全にスキップされます。
