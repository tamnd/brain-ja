 ## 解決策
 ## 問題の理解

 2 つの素な整数間隔が与えられます。1 つは x の間隔、もう 1 つは y の間隔です。 具体的には、x は厳密に a より大きく、最大で c を選択する必要があり、y は厳密に b より大きく、最大で d を選択する必要があります。 タスクは、積 x・y が積 a・b で割り切れるようなペア (x, y) を選択できるかどうかを判断することです。 複数の有効なペアが存在する場合はどれでも許容されますが、存在しない場合は不可能であることを報告する必要があります。 

可分性条件は、より構造的な方法で書き直すことができます。 x・y を除算するには a・b が必要です。これは、a・b 内のすべての素因数が少なくとも同じ合計指数で x・y に出現する必要があると言うのと同じです。 x と y は範囲内で独立した選択であるため、問題は a・b の素因数を 2 つの有界変数に分散することになります。 

制約はすべてのエンドポイントに対して最大 10^9 で、テスト ケースは最大 10 個です。 これにより、単一の範囲に最大 10^9 の値を含めることができるため、範囲内の候補を列挙しようとする試みが排除されます。 どのソリューションも、エンドポイントでは算術推論のみを使用して、テスト ケースごとに対数時間または定数時間で機能する必要があります。 

一般的な失敗例は、境界に対する実現可能性をチェックせずに、因子を x または y に貪欲に割り当てようとしたときに発生します。 たとえば、a=6、b=10、c=7、d=11 の場合、x は (6,7] にあるため x=7、y は (10,11] にあるため y=11 である必要がありますが、7・11 は 60 で割り切れません。単純なアプローチでは、一方の側をローカルに調整しようとする可能性がありますが、制約には柔軟性がありません。

 もう 1 つの微妙な問題は、x=a または y=b の選択が役立つと想定していることです。 x>a と y>b は厳密に両方とも禁止されているため、構築は厳密に下限を超えて開始する必要があり、最も明白な因子共有戦略が削除されます。 

## アプローチ

 ブルートフォース解釈は簡単です。(a, c] のすべての x と (b, d] のすべての y を試して、x・y が a・b で割り切れるかどうかを確認します。これは正しいですが、完全に実行不可能です。各区間には最大 10^9 の値を含めることができるため、積空間は計算の限界をはるかに超えています。

 重要な観察は、実際にはペアを検索する必要がないということです。 区間によって制約された 2 つの数値への a・b の有効な因子分布は 1 つだけ必要です。 製品の観点から考えるのではなく、個別の可算性の制約に移行します。 

条件 a·b | x・y は、y によって補償されない a・b の素因数が x に十分に含まれていることを要求することと同じであり、その逆も同様です。 これを処理する簡単な方法は、数値の 1 つ (たとえば x) を強制的に a の倍数にすることです。 x が a で割り切れる場合、次のように書き換えることができるため、y が b で割り切れる場合に限り、x・y は a・b で割り切れます。 

x・yはa・bで割り切れます

 ⇔ (x/a)・(y/b) は整数です

 a|x と b|y を指定しました。 

これにより、タスクは、a で割り切れる (a, c] の x と、b で割り切れる (b, d] の y を見つけることになります) になります。問題は、そのような倍数が各区間に独立して存在するかどうかを確認することになります。

 ただし、この直接分割は必ずしも必要というわけではありません。 必要なのは因子の分布だけなので、代わりに両方の対称構造を試すことができます。x に a・b をすべて吸収させて y=1 に設定するか、y にすべてを吸収させて x=1 に設定します。ただし、これらは限界があるため無効です。 正しいリダクションはより簡単です。以下を選択して、a のすべての因子を x に、b のすべての因子を y に独立して配置しようとします。 

x = a より厳密に大きい a の最小倍数

 y = b よりも厳密に大きい b の最小倍数

 そしてそれらが範囲内にあることを確認します。 そうであれば、x は a の倍数、y は b の倍数であるため、条件は自動的に成立します。したがって、x・y は a・b の倍数になります。 

どちらの区間もそのような倍数を提供できない場合、その因子成分の割り切り要件を満たすことができないため、解は存在しません。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. x > a かつ x が a で割り切れる最小の整数 x を計算します。 これは、有効範囲内の最初の a の倍数候補です。 
2. x が c を超える場合、x を選択できないことがすでにわかっているため、この構造では解は存在しません。 
3. y > b かつ y が b で割り切れる最小の整数 y を計算します。これは、区間内の b の最初の倍数候補です。 
4. y が d を超える場合、y 側についても同様に失敗します。 
5. x と y の両方がそれぞれの境界内に存在する場合は、(x, y) を出力します。 

各ステップは、a の因数分解を x に、b を y に完全に割り当てれば、積の割り算が保証されるという考えによって推進されます。 独立した可算性を強制することにより、x と y 間のカップリングを回避します。 

### なぜ効果があるのか

 このアルゴリズムでは、x ≡ 0 mod a および y ≡ 0 mod b が適用されます。 これらの制約の下では、a の素因数分解が x に完全に含まれ、b の素因数分解が y に完全に含まれるため、x・y は自動的に a・b で割り切れます。 x と y は許容範囲内で独立して選択されるため、両方のモジュラー制約を満たす有効な構造は正しい解を生成します。どちらかの制約がその区間内に実現可能な代表を持たない場合、この構造の下では有効なペアは存在できません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def next_multiple(g, l):
    # smallest multiple of g strictly greater than l
    return ((l // g) + 1) * g

t = int(input())
for _ in range(t):
    a, b, c, d = map(int, input().split())

    x = next_multiple(a, a)
    y = next_multiple(b, b)

    if x > c or y > d:
        print(-1, -1)
    else:
        print(x, y)
```ヘルパー関数は、整数の除算を使用して、指定された基数の最初の倍数を厳密に下限を超えて計算します。 重要な詳細は、インクリメンタル検索を試行するのではなく、(l // g) + 1 を使用することです。これは、境界が大きい場合には遅すぎます。 

メイン ループは、これを a と b に個別に適用し、構築された値が許容範囲内にあるかどうかをチェックします。 構築後に x と y の間の相互作用は必要ありません。 

## 実用的な例

 a=3、b=4、c=10、d=15の場合を考えてみましょう。 

| ステップ | xの計算 | yの計算 | 結果 |
 | --- | --- | --- | --- |
 | 1 | 3 の次の倍数 > 3 は 6 | 4 の次の倍数 > 4 は 8 | (6, 8) |

 ここでは両方の値が範囲内にあり、6・8 は明らかに 12 で割り切れ、正確であることが確認されます。 

ここで、a=8、b=9、c=10、d=10の場合を考えてみましょう。 

| ステップ | xの計算 | yの計算 | 結果 |

 | 1 | 8 の次の倍数 > 8 は 16 | 9 の次の倍数 > 9 は 18 | x が c を超える |

 x をその区間内に配置できないため、y だけが実行可能であっても、有効なペアは存在しません。 

これらの例は、実現可能性が各軸で独立して決定されることを示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from sys import stdout
    out = []
    t = int(sys.stdin.readline())
    for _ in range(t):
        a, b, c, d = map(int, sys.stdin.readline().split())

        def nxt(g, l):
            return ((l // g) + 1) * g

        x = nxt(a, a)
        y = nxt(b, b)

        if x > c or y > d:
            out.append("-1 -1")
        else:
            out.append(f"{x} {y}")
    return "\n".join(out)

assert run("1\n3 4 5 7\n") == "4 6"

# custom cases
assert run("1\n2 3 3 5\n") == "-1 -1", "tight interval failure"
assert run("1\n5 7 20 50\n") != "", "feasible case exists"
assert run("1\n10 10 11 11\n") == "-1 -1", "no room for multiples"

 ## 特殊なケース

 重大なエッジ ケースの 1 つは、a または b の倍数のみが上限の外側にある場合です。 たとえば、a=5、c=9 の場合、a より大きい最初の有効な x は 10 であり、これはすでに制約に違反しているため、間隔が自明ではない場合でも x は存在しません。 アルゴリズムは 10 を正しく計算し、すぐに拒否します。 

もう 1 つのエッジ ケースは、a=10^9-1 や c=10^9 など、a と c が非常に近い場合です。 a が (a, c] 内の数値を除算しない場合、計算された次の倍数は c を超えてジャンプし、区間をスキャンせずに不可能であることを正しく通知します。

 最後のケースは、両方の間隔が大きいが、a=6、c=6 および b=4、d=100 など、1 つの塩基がすでに境界近くにある場合です。 x は厳密に 6 より大きい必要があるため、y には多くのオプションがあるにもかかわらず、x は 12 にジャンプして失敗します。 チェックが独立しているため、不必要な組み合わせを考慮せずに正しい拒否が保証されます。
