 ## 解決策
 ## 問題の理解

 私たちに与えられたグループは、$n$学生は正確に 2 つのチームに分けられなければなりません。 両方のチームが空であってはなりません。 下限もあるよ$k$、各チームには少なくとも次のものを含める必要があることを意味します。$k$学生たち。 各チーム内では、学生は準備運動のためにばらばらのペアを形成することが期待されており、これにより追加の構造的制約が課せられます。つまり、チームには偶数の学生が含まれていなければなりません。そうしないと、1 人の学生が一致しないままになってしまいます。 

したがって、このタスクは純粋に実現可能性のチェックであり、分割が存在するかどうかを判断します。$n = a + b$両方とも$a$そして$b$がポジティブ、両方とも少なくとも$k$、そして両方とも偶数です。 

制約は非常に大きく、$n$まで$10^9$。 これにより、分割の可能性に関する構築や調査が即座に除外されます。 有効な解決策では、問題を一定数の算術チェックに減らす必要があります。 

微妙だが重要なエッジ条件は、「空ではないチーム」と制約の間の相互作用です。$k = 0$。 たとえ$k = 0$、ステートメントでは依然として両方のチームが空でないことが必要であるため、各チームには少なくとも 1 人の生徒が必要であり、同時に各チームはペアリングを許可して、強制的に均等なサイズにする必要があります。 これは、チームごとの実際の下限が単なる上限ではないことを意味します。$k$、しかし少なくとも$1$、均一性と組み合わせます。 

単純な間違いは、両方の制約を正しく組み合わせずに、2 で割り切れるか、最小サイズのみを強制することです。 たとえば、次の場合$n = 4$そして$k = 3$可能であると誤って仮定する可能性があります。$4 \ge 2k$, しかし、両方のチームが少なくとも 3 であるを満たす均等な分割は存在しません。 

## アプローチ

 ブルートフォースアプローチでは、考えられるすべてのチームサイズを試します$a$から$1$に$n-1$、 セット$b = n - a$、両方が次の制約を満たすかどうかを確認します: 空ではない、少なくとも$k$、さらには。 これはすべてのパーティションを直接列挙するため正しく機能しますが、次の場合には非常に遅すぎます。$n$大きいです。 最悪の場合、それは実行されます$O(n)$チェック、それは不可能です$n$まで$10^9$。 

重要な観察は、意味のある候補は偶数だけであるということです。 両方のチームはペアに分割できる必要があるため、両方とも$a$そして$b$均等でなければなりません。 それはすぐに次のことを意味します$n$2 つの偶数の和は偶数であるため、それ自体は偶数である必要があります。 

偶数サイズに制限すると、偶数サイズを選択することが問題になります。$a$次のような:$a \ge k$、$b = n - a \ge k$、そして両方とも自動的に残る場合でも$n$は均等です。 

したがって、有効な最小チームサイズは次のとおりではありません。$k$、ただし、少なくとも次の最小の偶数$\max(k, 1)$、チームも空ではない必要があるためです。 実現可能な最小の偶数サイズを選択したら$L$、実現可能性の条件は、少なくとも割り当てられるかどうかを確認することになります。$L$学生を各チームに参加させるかどうか$2L \le n$。 

この問題は、定数時間の算術チェックに集約されます。

 ## アルゴリズムのチュートリアル

 すべての制約を 1 つの最小有効チーム サイズに変換し、そのような 2 つのチームがそのサイズに適合するかどうかを確認します。$n$。 

1. チームごとに必要な最小サイズを次のように計算します。$m = \max(k, 1)$。 これにより、教師の制約と、チームを空にすることができないという要件の両方が強制されます。 
2.ラウンド$m$最も近い偶数まで。 この値を呼び出します$L$。 もし$m$すでに均等になっており、$L = m$。 さもないと、$L = m + 1$。 これにより、各チームを内部でペアに分割できるようになります。 
3. かどうかを確認します。$n$は均等です。 奇数の場合は、すぐに「NO」を返します。2 つの偶数チームの合計は奇数にならないためです。 
4. かどうかを確認します。$n \ge 2L$。 これが当てはまる場合は、1 つのチーム サイズを次のように割り当てます。$L$そしてもう一つは$n - L$、両方とも均等になり、少なくとも$k$。 
5. 両方の条件が成立する場合は「YES」を出力し、そうでない場合は「NO」を出力します。 

ステップ 3 の背後にある理由は、パリティは加算時に保持されるため、2 つの偶数の合計は奇数の合計を生成できないということです。 ステップ 4 では、ペアリングの制約を満たした後でも、両方のチームを同時に満足させるのに十分な質量がまだあることを保証します。 

### なぜ効果があるのか

 このアルゴリズムは、実行可能なすべてのチーム サイズを可能な限り最小の有効な均等サイズに削減することにより、すべての有効なソリューションを特徴付けます。$L$。 有効なパーティションには少なくとも両方の部分が必要です$L$これより小さい値は、最小サイズに違反するか、ペアリングのパリティを壊すためです。 このような最小有効ブロックがすでに 2 つを超えている場合$n$、再分配は均等性または下限制約を破ることなく赤字を修正できません。 逆に、もし$2L \le n$、1 つのチームを次のようにすることで有効な分割を構築できます。$L$そしてパリティを維持するために残りを均等に分配します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
k = int(input())

m = max(k, 1)

if m % 2 == 0:
    L = m
else:
    L = m + 1

if n % 2 == 1:
    print("NO")
else:
    if n >= 2 * L:
        print("YES")
    else:
        print("NO")
```この実装は、派生した条件を直接反映します。 の計算$m = \max(k, 1)$空ではない要件を処理します。 四捨五入は$L$ペアリングの実現可能性を強制します。 パリティチェックオン$n$これは奇数の合計を即座に除外するため、必須であり、スキップすることはできません。 最後に、不等式$n \ge 2L$両方のチームがすべての制約を同時に満たせることが保証されます。

 ## 特殊なケース

 重要なエッジケースの 1 つは次のような場合です。$k = 0$。 最小要件が存在しないように見えても、チームは空ではない必要があるため、有効な下限は 1 になり、ペアリングを強制した後は 2 になります。$n = 4, k = 0$、アルゴリズムは次のように計算します。$m = 1$、 それから$L = 2$、そしてそれ以来$n = 4 \ge 4$の場合、2 と 2 の分割に対応する YES が返されます。 

別のエッジケースが発生する場合$n$奇数です。 例えば、$n = 7, k = 2$。 たとえ両方のチームが個別にサイズ制約を満たすことができたとしても、2 つの偶数の合計は奇数の合計にならないため、パリティにより分割は不可能になります。 アルゴリズムはこれを直ちに検出します。$n \% 2$チェック。 

さらに微妙なケースは次のような場合です。$k$に比べて大きい$n$。 例えば、$n = 10, k = 6$。 ここ$m = 6$、$L = 6$、 しかし$2L = 12 > 10$、そのため、各チームが個別に個別に制約を満たしている場合でも、アルゴリズムはケースを正しく拒否します。
