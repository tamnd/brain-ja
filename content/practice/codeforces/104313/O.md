 ## 解決策
 ## 問題の理解

 都市と双方向道路を表す無向接続グラフが与えられます。 一部の道路には特別な特性があります。そのような道路を削除するとグラフが切断される場合、その道路は高価であると考えられます。 高価な道路はどれも 1 単位分のコストが同じで、その他の道路はすべて無料です。 

旅は、グラフ内のウォークとして定義され、旅行者はどこからでも開始でき、任意の頻度で都市や道路を再訪問できます。唯一の要件は、すべての都市を少なくとも 1 回訪問することです。 目標は、旅行者がそのような散歩中に交通費のかかる道路を通過しなければならない回数を最小限に抑えることです。 

重要な点は、コストは都市への入場や全体的に使用される道路の数に関係するのではなく、具体的にはグラフ内の橋であるエッジを通過する回数に関係するということです。 

制約は最大 200,000 個の頂点とエッジに及ぶため、各エッジの使用後にウォークをシミュレートしたり接続を再計算しようとするソリューションは直ちに除外されます。 頂点またはエッジの数が 2 次であっても、アプローチは失敗します。 私たちは線形または線形に近いグラフ アルゴリズム、通常は前処理を伴う深さ優先検索のようなものを探しています。 

グラフにブリッジがまったく含まれていない場合、微妙なケースが発生します。 その場合、すべての道路は無料なので、横断方法に関係なく、答えはゼロになります。 もう 1 つの明らかではないケースは、グラフがすでにツリーになっている場合です。 そうなると、すべてのエッジが高価になり、問題はすべてのノードを訪問しながらツリーのエッジをトラバースする頻度を最小限に抑えることと同じになります。 

## アプローチ

 このタスクについて直接考える方法は、明示的なルートを計画していると想像することです。 都市間を移動するたびに、橋を渡った場合にのみ料金を支払います。 したがって、単純な考えは、すべての頂点を訪問し、橋を渡る回数を最小限に抑えるウォークを構築しようとすることです。 

強引な観点の 1 つは、問題を (現在のノード、訪問セット) のペアにわたる状態空間検索として扱うことですが、それは指数関数的に爆発的に増加し、明らかに不可能です。 

単純化して、グラフの構造のみを考慮していると言ったとしても、依然としてブリッジが避けられないボトルネックのように動作するという問題に直面しています。 すべてのブリッジの横断にはコストがかかりますが、エッジがブリッジになっていないグラフの最大領域内では移動は自由です。 これは、そのような各領域を単一のノードに圧縮することを示唆しています。 

これは重要な観察につながります。ブリッジではないエッジは二重接続されたコンポーネントの内側にあり、そのような各コンポーネントの内部ではコストをかけずに任意に移動できるということです。 二重接続された各コンポーネントを単一のノードに縮小した後、残りのすべてのエッジがブリッジになります。 結果として得られる構造はツリーであり、一般にブリッジ ツリーと呼ばれます。 

さて、問題は次のとおりです。エッジに沿った移動に 1 単位のコストがかかるツリーがあり、エッジの総トラバースを最小限に抑えながら、すべてのノードを少なくとも 1 回訪問するウォークが必要です。 

ツリー上では、慎重に選択したバックボーン パスに従わない限り、すべての頂点をカバーするウォークはエッジを複数回横断する必要があります。 標準的なアイデアは、深さ優先のトラバースを行うことです。つまり、すべてのエッジが 2 回トラバースされ、1 回は下り、もう 1 回は戻ります。 これにより、エッジ数の 2 倍のコストが発生します。 

ただし、単一のパスに沿った後戻りを避けることで、これを改善できます。 トラバースのメインスパインとして機能するツリー内のパスを選択した場合、そのパス上のエッジは 1 回だけトラバースできますが、すべての側枝は依然として 2 回トラバースされます。 このスパインが長くなるほど、2 回支払うエッジが少なくなります。 したがって、ツリー内の最も長い単純なパス、つまり直径が必要になります。

ブリッジ ツリーに k 個のノードがある場合、k から 1 を引いたエッジがあります。 最適なコストは、エッジの数の 2 倍からエッジの直径の長さを引いたものになります。

 ## アルゴリズムのチュートリアル

 1. 検出時間と低いリンク値を使用した深さ優先検索を使用して、元のグラフ内のすべてのブリッジを特定します。 v のサブツリーから u の祖先へのバック エッジがない場合、エッジ (u, v) はブリッジになります。 
2. ブリッジがわかったら、非ブリッジ エッジのみを使用して接続コンポーネントを構築します。 各コンポーネントは、内部に重要なエッジがないため、自由に移動できる領域を表します。 
3. 非ブリッジエッジに限定された DFS または DSU を使用して、各頂点にコンポーネント識別子を割り当てます。 これにより、縮小されたグラフ ノードが生成されます。 
4. コンポーネント u とコンポーネント v に属する 2 つの頂点間にブリッジがある場合は常に、コンポーネント u とコンポーネント v を接続してブリッジ ツリーを構築します。 
5. 2 つの幅優先探索を使用して、このツリーの直径を計算します。 まず、任意のノードから BFS を実行して、最も遠いノードを見つけます。 次に、 a から BFS を実行して、エッジの直径である最大距離を見つけます。 
6. k をコンポーネントの数、d をブリッジ ツリーの直径とする。 答えは、2 倍 (k マイナス 1) マイナス d です。 

この構造が機能する理由は、コンポーネント内ではコストなしで自由に移動できるため、コンポーネント間の遷移のみが問題となり、それらの遷移が各エッジに単位コストを持つツリーを形成するためです。 

### なぜ効果があるのか

 収縮後は、すべてのエッジがブリッジに正確に対応するため、すべての有償移動はコンポーネント間の移動に対応します。 有効なトラバーサルはすべて、すべてのノードを訪問するこのツリー上のウォークに対応します。 すべてのノードをカバーするツリー ウォークでは、選択した単純なパス上にあるエッジを除き、すべてのエッジを少なくとも 2 回使用する必要があります。このパスは、未訪問のブランチの接続を切断することなく 1 回通過できます。 単一の横断パスを最大化すると、総コスト (正確には直径) が最小化されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    n, m = map(int, input().split())
    g = [[] for _ in range(n)]
    edges = []
    
    for i in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append((v, i))
        g[v].append((u, i))
        edges.append((u, v))
    
    tin = [-1] * n
    low = [0] * n
    timer = 0
    is_bridge = [False] * m

    def dfs(v, pe):
        nonlocal timer
        tin[v] = low[v] = timer
        timer += 1
        for to, ei in g[v]:
            if ei == pe:
                continue
            if tin[to] != -1:
                low[v] = min(low[v], tin[to])
            else:
                dfs(to, ei)
                low[v] = min(low[v], low[to])
                if low[to] > tin[v]:
                    is_bridge[ei] = True

    dfs(0, -1)

    comp = [-1] * n
    comp_id = 0

    from collections import deque

    for i in range(n):
        if comp[i] == -1:
            q = deque([i])
            comp[i] = comp_id
            while q:
                v = q.popleft()
                for to, ei in g[v]:
                    if is_bridge[ei]:
                        continue
                    if comp[to] == -1:
                        comp[to] = comp_id
                        q.append(to)
            comp_id += 1

    if comp_id == 1:
        print(0)
        return

    tree = [[] for _ in range(comp_id)]
    for u, v in edges:
        cu, cv = comp[u], comp[v]
        if cu != cv:
            tree[cu].append(cv)
            tree[cv].append(cu)

    def bfs(start):
        dist = [-1] * comp_id
        dist[start] = 0
        q = deque([start])
        while q:
            v = q.popleft()
            for to in tree[v]:
                if dist[to] == -1:
                    dist[to] = dist[v] + 1
                    q.append(to)
        far = max(range(comp_id), key=lambda x: dist[x])
        return far, dist[far]

    a, _ = bfs(0)
    b, diameter = bfs(a)

    edges_tree = comp_id - 1
    print(2 * edges_tree - diameter)

if __name__ == "__main__":
    solve()
```実装は、標準の低リンク DFS を使用してすべてのブリッジを計算することから始まります。 再帰では、検出時間を注意深く追跡し、到達可能な最下位の祖先を伝播します。 バック エッジをバイパスできないエッジはブリッジとしてマークされます。 

その後、ブリッジ エッジを無視する BFS を実行することにより、頂点がコンポーネントにグループ化されます。 このステップにより、各コンポーネントが自由な動きの下で最大限に接続されることが保証されます。 

次に、圧縮されたグラフが隣接リストとして明示的に構築されます。 複数の元のエッジが同じコンポーネントのペアに接続している可能性があるため、BFS 直径の計算では重複は問題になりません。 

最後に、2 つの BFS パスでブリッジ ツリーの直径が計算されます。 答えは以前に導いた公式を使用します。 

## 実用的な例

 すでに 1-2-3 の 3 つのノードが一列に並んだツリーになっている小さなグラフを考えてみましょう。 

| ステップ | 現在のノード | アクション | コンポーネント数 |
 | --- | --- | --- | --- |
 | 開始 | 1 | ブリッジツリーの構築（グラフと同じ） | 3 |
 | BFS1 | 1 | 最も遠いノードが 3 であることを確認します。 3 |
 | BFS2 | 3 | 直径は 2 | 3 |

 ツリーには 2 つのエッジがあるため、答えは 2 * 2 マイナス 2、つまり 2 です。これは、完全なパスに沿って戻る必要がなく、1-2-3 を歩くことに相当します。 

ここで、リーフ 3-4 が取り付けられた三角形 1-2-3-1 を考えてみましょう。 

| ステップ | コンポーネントの構造 | ブリッジツリー |
 | --- | --- | --- |
 | 圧縮後 | サイクルが 1 つのコンポーネントになります | ノード A がノード B に接続されている |
 | 直径BFS | AとBの間 | 1 |

 ブリッジ エッジは 1 つだけであるため、k は 2、直径は 1 となり、コストは 2 * 1 マイナス 1 で 1 となります。 

これは、コストに寄与するのは橋だけであり、サイクルは完全に無料であることを示しています。 

## 複雑さの分析

 ## 特殊なケース

 ブリッジのないグラフは、コンポーネントの圧縮直後に処理されます。 すべての頂点は 1 つのコンポーネントに分類されるため、ブリッジ ツリーには 1 つのノードがあり、アルゴリズムはコスト 0 を返します。 

純粋な木は、橋の観点から見ると最も高価な構造物です。 すべてのエッジがブリッジ ツリーの一部となり、直径が正しく計算されることで、最長のパスを 1 回だけ通過できるようになり、コストが削減されます。 

単一のブリッジを含む非常に周期的なグラフは、すべての複雑さが 1 つの重要なエッジに集約されることを示しています。 圧縮ステップにより、ツリーフェーズの前にすべてのサイクルが確実に消失し、内部構造の過剰カウントが防止されます。
