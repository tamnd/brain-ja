 ## 解決策
 ## 問題の理解

 いくつかの独立したテスト ケースが与えられています。 各テスト ケースには、整数の配列と一連の操作があります。 各操作はパリティに基づいて配列を対象とします。1 つのタイプはすべての偶数要素に固定値を追加し、もう 1 つのタイプはすべての奇数要素に固定値を追加します。 すべての操作の後、配列の合計を報告する必要があります。 

主な難点は、配列は概念的にはクエリごとに変化するのに、配列そのものを出力するように求められるのではなく、配列の合計のみを出力するように求められることです。 この制約により、要素数と操作数の両方がテスト ケースごとに 100000 に達し、すべてのテストの合計が 200000 に制限されることが明確になります。これにより、各操作の後に合計を最初から再計算することは即座に除外されます。これは、おおよそ O(nq) になり、時間制限を数桁超えてしまうためです。 

考慮すべき自然なエッジケースは、パリティが動的に変化する場合です。 たとえば、すべての偶数に 1 を加えると、そのうちのいくつかが奇数になります。 単純なアプローチでは、この変化を考慮せずにカウントまたは合計を誤って更新しようとする可能性があります。 

次の小さな例を考えてみましょう。 

入力:

 n = 3、a = [1、2、3]

 クエリ: 偶数に 10 を足す

 正しい配列は[1, 12, 3]となり、合計は1回だけ10増加します(偶数要素が1つしか存在しないため)。 単純な間違いは、パリティ セットが固定されていると仮定し、時間の経過とともに要素がパリティ クラス間でどのように移動するかを追跡せずに、初期カウントを単に乗算することです。 これは、更新が蓄積されるとすぐに間違いになります。 

本質的な観察は、パリティが加算の下では安定しないため、インデックスの固定分割を維持できないということです。 代わりに、現在の偶数とオッズがいくつ存在するか、およびそれらの合計がどのように変化するかを追跡する必要があります。 

## アプローチ

 ブルート フォース ソリューションでは、各操作を直接シミュレートします。つまり、配列全体をスキャンし、各要素のパリティをチェックし、必要に応じて更新を適用し、合計を再計算します。 これは問題のステートメントを正確に反映しているため、正しいです。 ただし、各クエリのコストは O(n) で、q が 100000 までの場合、総作業量は O(nq) となり、最悪の場合、制限をはるかに超える 10^10 の演算に達します。 

重要な洞察は、実際にはどの時点でも完全な配列が必要ではないということです。 必要な情報は 3 つだけです。偶数要素の合計、奇数要素の合計、各グループに属する要素の数です。 これらの集計を維持すると、各操作は定時更新になります。 

すべての偶数要素に x を加算すると、すべての偶数要素が x ずつ増加するため、合計は x に偶数要素の数を乗算して増加します。 ただし、パリティは変更されます。その後、これらの偶数要素はすべて奇数になります。 したがって、それらのカウントと寄与の両方を偶数バケットから奇数バケットに転送する必要があります。 同じロジックが奇数の更新にも対称的に適用されます。 

これにより、問題は要素ごとのシミュレーションからグループごとの簿記に変換されます。

 | ブルートフォース | O(nq) | O(n) | 遅すぎる |
 | 最適 | O(n + q) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 プロセス全体を通じて、偶数要素の数、奇数要素の数、偶数要素の合計、奇数要素の合計の 4 つの値を維持します。

1. 配列を 1 回スキャンして、各要素を偶数または奇数に分類して初期化します。 それに応じてカウントと合計の両方を累積します。 これにより、配列全体の圧縮表現が得られます。 
2. 偶数と奇数の寄与の合計として初期合計を計算します。 この値は、各クエリの後に段階的に更新されます。 
3. 「すべての偶数要素に x を加算する」タイプのクエリの場合、最初に、この操作によって合計がどれだけ増加するかを計算します。これは、x に偶数要素の数を掛けたものです。 これは、すべての偶数要素が 1 回だけ増加されるためです。 
4. 総計を更新した後は、構造変更を反映する必要があります。 x を加算するとすべての偶数要素が奇数になるため、偶数バケット全体が奇数バケットに転送されます。 古い偶数の合計と偶数の x 倍を加算して奇数の合計を更新し、偶数の合計をゼロにリセットします。 
5. パリティ カウントも更新します。すべての偶数要素が奇数になるため、odd_count は Even_count だけ増加し、even_count は 0 になります。 
6. 「すべての奇数要素に x を追加」タイプのクエリの場合、対称ロジックを適用します。つまり、合計を x 倍の odd_count 倍に増やし、すべての奇数の質量を偶数バケットに移動し、それに応じてカウントを更新します。 
7. 各クエリの後に、現在の合計合計を出力します。 

正確さは、要素を 2 つの進化するグループに正しく分割し、各グループが現在の偶数またはオッズを完全に表すように維持することにかかっています。 

### なぜ効果があるのか

 どの時点でも、すべての要素は、現在の偶数値と現在の奇数値という 2 つの素なセットのいずれかに正確に属します。 各操作では、一様な変換が 1 つのセットのみに適用されます。 選択されたセット内のすべての要素は同一の増分を受け取るため、それらの相対パリティは一貫して反転し、どの要素も分割されたり、同じグループ内の他の要素と異なる動作をしたりすることはありません。 これにより、情報を失うことなく状態全体をカウントと合計によって要約することができ、すべての遷移でグループの合計とカウントが基になる配列と正確に一致するという不変条件が保持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, q = map(int, input().split())
        a = list(map(int, input().split()))

        even_cnt = 0
        odd_cnt = 0
        even_sum = 0
        odd_sum = 0

        for v in a:
            if v % 2 == 0:
                even_cnt += 1
                even_sum += v
            else:
                odd_cnt += 1
                odd_sum += v

        total = even_sum + odd_sum
        out = []

        for _ in range(q):
            typ, x = map(int, input().split())

            if typ == 0:
                total += x * even_cnt
                odd_sum += even_sum + x * even_cnt
                odd_cnt += even_cnt
                even_sum = 0
                even_cnt = 0
            else:
                total += x * odd_cnt
                even_sum += odd_sum + x * odd_cnt
                even_cnt += odd_cnt
                odd_sum = 0
                odd_cnt = 0

            out.append(str(total))

        print("\n".join(out))

if __name__ == "__main__":
    solve()
```このコードは、完全な配列ではなく、集約された情報を保持します。 初期化ループは要素をパリティ グループに分類します。 各クエリは合計を直接更新し、加算後のパリティ 反転を反映して、一方のグループからもう一方のグループへの完全な転送を実行します。 最も微妙な点は、x をグループに追加すると、そのグループ内のすべての要素のパリティが変更されるため、値を部分的に更新するのではなく、累積された合計とカウント全体を反対側のバケットに移動する必要があることです。 

合計の更新ではカウンターをリセットする前に古い状態を使用するように注意する必要があります。そうしないと、転送された質量が失われます。

 ## 特殊なケース

 繰り返しの操作により 1 つのパリティ グループが完全に崩壊するという特殊なケースが発生します。 たとえば、すべての偶数から開始して偶数に奇数の増分を適用すると、すべての要素がすぐに奇数バケットに移動されます。 

入力:

 n = 2、a = [2, 4]、クエリ (0, 1)

 初期状態:

 Even_cnt = 2、even_sum = 6

 操作後:

 すべての要素が奇数になります: [3, 5]

 このアルゴリズムは、合計を 2 * 2 = 4 で更新して 10 を与え、偶数状態全体を奇数状態に転送します。 カウンターさえもゼロになります。 すべての要素がパリティを均一に変更するため、表現の一貫性が保たれます。 

もう 1 つの微妙なケースは、複数の連続した操作がすでに空のパリティ グループをターゲットにしている場合です。 更新式ではカウントが使用されるため、ゼロを乗算することで不正なドリフトが発生せず、特別なケースがなくても状態が安定したままになります。
