 ## 解決策
 ## 問題の理解

 n 人の子供たちのグループが与えられ、それぞれがいくつかの栗を集め、それを 1 つの山に置きました。 順番の最初の子、サーシャが最初に栗を山に置きます。 次の子供たちは、前の子供の 2 倍の栗を寄付します。 したがって、貢献度は、サーシャの未知の金額 a から始まり、次に 2a、次に 4a と、n 番目の子まで続く等比数列を形成します。 

サーシャが計算した合計 m も与えられます。 タスクは、この合計が整数の開始値 a によって生成できるかどうかを確認し、可能であれば、a が何でなければならないかを決定することです。 

問題の構造により、合計の形式は非常に厳格になります。 固定 n の場合、合計は常に既知の定数の a 倍、つまり 1 + 2 + 4 + ... + 2^(n-1) になります。 これは、問題全体が、割り算のチェックと固定乗数からの単一の未知数の再構築に帰着することをすでに示唆しています。 

n ≤ 100 および m ≤ 10^18 という制約は、関係する値は大きくてもよいが、シーケンスの長さは短いことを示しています。 これにより、広範囲の値に対するシミュレーションの必要性が排除されますが、他の言語で慎重に扱わないとオーバーフローする可能性がある単純な算術演算を避けるよう警告されます。 Python ではこれは問題になりませんが、概念的な正しさは依然として重要です。 

m が幾何学和で割り切れない場合、微妙なエッジケースが発生します。 その場合、有効な a は存在しません。 もう 1 つの特殊なケースは、計算された a が 0 または負である場合ですが、m ≥ 1 であり、すべての項が a の正の倍数であるため、解が存在する場合は a も正でなければなりません。 

## アプローチ

 この問題を考える素朴な方法は、1 から m までの a のすべての可能な値を試し、n 項についてシーケンス a、2a、4a、... をシミュレートし、合計が m と一致するかどうかを確認することです。 すべての有効な構成が 1 つの a に正確に対応するため、これは原理的には正しいです。 ただし、各候補 a について n 項を計算し、最悪の場合は O(mn) 回の演算を行うことになります。 m が 10^18 までの場合、これは完全に不可能です。 

重要な観察は、a のシーケンスが線形であることです。 合計は次のように因数分解できます。 

S = a (1 + 2 + 4 + ... + 2^(n-1))

 括弧内の式は、n のみに依存する固定幾何学和です。 これにより、問題は可能なシーケンスの検索から単純な算術チェックに変換されます。つまり、乗数を計算し、m がそれで割り切れるかどうかを確認し、m をその乗数で割ったものとして a を復元します。 

唯一の微妙な点は、幾何学和を安全に計算することです。 n ≤ 100 であるため、合計 2^n は Python の整数の範囲内に十分収まりますが、一般に、浮動小数点演算に依存するのではなく、反復またはビット シフトを使用して計算する必要があります。

 ## アルゴリズムのチュートリアル

 数列の構造を利用して総和を書き換えます。 

1. スケーリングを除くすべての子の寄与に対応する幾何乗数 (1 + 2 + 4 + ... + 2^(n-1)) を計算します。 これは、1 から開始して 2 倍と加算を繰り返して反復的に構築できます。 
2. 実行値 cur を 1 から開始し、合計乗数 s を 1 から維持します。残りの n-1 個の子それぞれについて、cur を 2 倍にして s に加算します。 これにより、オーバーフローを考慮せずに 2 のべき乗の正確な合計が計算されます。 
3. s を計算した後、m が s で割り切れるかどうかを確認します。 割り切れない場合は、指定された合計を生成できる整数の開始値 a が存在しないため、答えは不可能です。 
4. 割り切れる場合は、a = m / s を計算します。 他のすべての貢献はその固定倍数であるため、これがサーシャの貢献の唯一の可能な値です。 
5. a とともに「success」を出力します。

### なぜ効果があるのか

 寄与のシーケンスは、まさに固定ベクトル (1、2、4、...、2^(n-1)) のスケーリングされたバージョンです。 有効な合計は、このベクトルによって生成された 1 次元格子上に存在する必要があります。 計算された合計 s はこのベクトルの正確な係数であるため、有効な合計は s と単一のスカラー a の積に等しくなければなりません。 すべての寄与は正の整数であるため、再構成には曖昧さがなく、割り算が実現可能性を完全に特徴づけます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    s = 1
    cur = 1
    for _ in range(n - 1):
        cur *= 2
        s += cur

    if m % s != 0:
        print("No")
        return

    a = m // s
    print("Yes")
    print(a)

if __name__ == "__main__":
    solve()
```このソリューションはアルゴリズムを直接反映しています。 このループは、他の言語ではオーバーフローする可能性がある数式に依存せずに幾何学和を構築します。 割り算チェックにより、再構築された開始値が整数であることが保証されます。 

よくある実装上の間違いは、指数処理におけるオーバーフローやオフバイワンエラーを考慮せずに、閉じた形式 2^n - 1 を直接使用しようとすることです。 反復的な構築により両方の問題が回避され、関係が明確になります。

 ## 特殊なケース

 重要なエッジ ケースは、n = 1 の場合です。乗数 s は単純に 1 であるため、任意の m が有効であり、a は m と等しくなければなりません。 ループが 0 回実行され、s が 1 のままであるため、アルゴリズムはこれを処理し、特別な処理を行わなくても正確さを維持します。 

もう 1 つのケースは、m が幾何学和で割り切れない場合です。 たとえば、n = 3 および m = 8 の場合、s = 7 となります。アルゴリズムは 8 % 7 ≠ 0 を計算し、このケースを直ちに拒否します。 これは、有効な合計が 7 の倍数の算術格子を形成するという構造上の制約と一致します。 

最後に、反復 2 倍化が浮動小数点演算や近似に依存しないため、n = 100 のような大きな n 値も安全に動作します。 各値は正確に計算され、上限であっても正確さが保証されます。
