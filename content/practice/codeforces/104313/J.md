 ## 解決策
 ## 問題の理解

 サイズの順列が与えられています$n$、以下のすべての整数が含まれることを意味します。$0$に$n-1$まさに一度。 連続するサブ配列ごとに 2 つの値を計算します。 

最初の値はサブ配列の mex で、そのサブ配列に欠落している最小の非負の整数です。 2 番目の値は「mid」で、次のように定義されます。部分配列をソートする場合は、位置の要素を取得します。$\lceil (s+1)/2 \rceil$、 どこ$s$は部分配列の長さであり、その要素をmidと呼びます。 これは事実上中央値の下限となります。 

タスクは、厳密な不等式 mex(subarray) > Mid(subarray) を満たすサブ配列の数を数えることです。 

制約は大きいです: 合計$n$すべてのテストケースにわたって、$2 \cdot 10^5$、したがって、それに近い解決策はどれでも$O(n^2)$テストケースごとには不可能です。 平$O(n \log n)$サブ配列ごとにというのは問題外です。$O(n^2)$サブアレイ。 

素朴なアプローチでは、すべての部分配列の mex と median を個別に再計算します。 mex が増分的に維持される場合でも、中央値の計算には対数更新を伴うデータ構造が必要ですが、それでも二次部分配列に対数を乗算する作業が必要になり、これでは非常に遅すぎます。 

mex と Mid が短いサブ配列でどのように相互作用するかによって、微妙なエッジ ケースが発生します。 たとえば、単一要素配列の場合、$[x]$、メキシコは$0$もし$x \neq 0$、 さもないと$1$、一方、mid は常に$x$。 したがって、長さ 1 の部分配列であっても、値がゼロであるかどうかにすでに依存しています。 正しいソリューションでは、境界における特別な大文字と小文字のエラーを発生させずに、これらを一貫して処理する必要があります。 

もう 1 つの罠は、mex が単純なプレフィックス プロパティのように動作すると仮定していることです。 小さな数値を削除または追加すると、mex が完全に変更される可能性があるため、注意深く推論することなく単純な 2 ポインターのメンテナンスが可能になるという意味では単調ではありません。 

## アプローチ

 重要な問題は、mex が欠損値に依存するのに対し、mid は順序統計に依存することです。 どちらもサブ配列のグローバル プロパティであるため、一見したところ、ローカルの貪欲な推論に抵抗します。 

ブルート フォース ソリューションでは、すべてのサブ配列を反復処理し、頻度カウントを計算し、ゼロから上にスキャンして mex を見つけ、ソートまたはバランスの取れた構造を使用して中央値を計算します。 これは正しいですが、コストがかかります$O(n^3)$直接実行した場合、または$O(n^2 \log n)$データ構造は限界をはるかに超えています。 

重要な観察は、不等式 mex > Mid を書き換えることから得られます。 Mid は部分配列の要素であり、mex は最小の欠損値であるため、条件 mex > Mid は、以下のすべての整数を意味します。$0$サブ配列には、mid までが存在します。 これにより、「欠損 vs 次数統計」条件が純粋なカバレッジ条件に変換されます。 

したがって、固定部分配列の場合、$x = \text{mid}$。 条件 mex > x はすべての値を意味します$0,1,\dots,x$サブ配列内に存在します。 順列を使用しているため、各値はグローバルに 1 回だけ出現するため、「サブ配列内に存在する」ということは、これらの値の位置が区間内にあるかどうかを確認することと同じです。 

したがって、問題は次のようになります: 部分配列をカウントする$[l,r]$たとえば、$x =$部分配列の中央値、その後値のすべての位置$0$を通して$x$中に横たわって$[l,r]$。 中央値は依然として部分配列に依存しますが、値の位置に関して制約を解釈できるようになりました。 

中心的な構造的洞察は、概念的に中央値を固定し、より小さな値をすべて完全にカバーしながら、その中央値を持つサブアレイの数を数えることです。 次に、問題をカウントサブ配列に再構成します。そこでは、必要なインデックスの特定のセットがセグメント内に存在する必要があり、中央値条件により、2 つのポインターとフェンウィック形式の順序統計の維持で処理できるバランス制約が課せられます。 

これにより、$O(n \log n)$候補ウィンドウを維持し、エンドポイントをスイープしながら制約が満たされていることを確認するソリューションです。

 | ブルートフォース |$O(n^2 \log n)$|$O(n)$| 遅すぎる |
 | 最適 |$O(n \log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 まず、mex を完全に削除する方法で条件を再解釈します。 どのサブ配列でも、mex > Mid は、0 から Mid までのすべての整数がサブ配列に含まれることを意味します。 

順列では、各値が一意のインデックスに対応するため、部分配列にはその位置をカバーする場合にのみ値が含まれることを利用します。 

位置によって値を処理し、スイープ中に間隔の実現可能性をテストできる構造を維持します。 

1. 位置配列を事前計算する$pos[v]$、 どこ$pos[v]$価値の指標です$v$順列の中で。 これにより、値の制約をインデックスの制約に変換できるようになります。 
2. 考えられる適切なエンドポイントを列挙します$r$。 それぞれについて$r$で終わるすべてのサブ配列を考慮します。$r$、そして、どの制約が満たされているかを追跡する左側のエンドポイント上の構造を維持します。 
3. で終わる固定サブ配列の場合$r$、条件 mex > Mid は、内部の値のセットによって異なります。$[l,r]$。 現在ウィンドウ内にある値のセットを維持し、値に対するフェンウィック ツリーを介した中央値クエリをサポートします。 
4. mex > Mid を強制するには、次のように解釈します。中央値が次の場合$x$、次にすべての値$0..x$存在する必要があります。 これは、値間の最大位置が$0..x$最大でも$r$、最小位置は少なくとも$l$。 
5. 各候補右端点について、ウィンドウ内の値に対する動的な構造を維持し、中央値をクエリできるようにします。$O(\log n)$値の頻度に対してフェンウィック ツリーを使用します。 
6. それぞれについて$r$、有効な数を計算します。$l$2 つのポインターとセグメント更新を備えたスライディング ウィンドウを使用して、小さな値の必要な範囲と中央値ベースの不等式の妥当性によって引き起こされる制約を維持することによって存在します。 
7. すべての寄付を集計します$r$これにより、各サブ配列がその正しいエンドポイントが処理されるときに正確に 1 回カウントされるようになります。 

重要な不変条件は、どのステップでも、データ構造が現在のウィンドウ内の値の複数セットを正しく表し、計算された中央値が常にフェンウィックの状態と一致することです。 mex 条件は、値の位置のインターバル カバレッジを通じて間接的に適用されます。これは、プレフィックス値のカバーされる最小および最大の位置を維持することによって保証されます。 

このアルゴリズムは、中央値候補がカバレッジ条件を満たさない限り、サブ配列をカウントしません。また、中央値は維持された構造から正確に再計算されるため、有効なサブ配列はすべて、その右端点に到達したときにカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

    def kth(self, k):
        idx = 0
        bitmask = 1 << (self.n.bit_length())
        while bitmask:
            nxt = idx + bitmask
            if nxt <= self.n and self.bit[nxt] < k:
                k -= self.bit[nxt]
                idx = nxt
            bitmask >>= 1
        return idx + 1

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        p = list(map(int, input().split()))

        pos = [0] * n
        for i, v in enumerate(p):
            pos[v] = i

        ft = Fenwick(n)
        ans = 0

        l = 0
        for r in range(n):
            ft.add(p[r] + 1, 1)

            while True:
                m = (r - l + 1 + 1) // 2
                mid = ft.kth(m) - 1

                ok = True
                for x in range(mid + 1):
                    if not (l <= pos[x] <= r):
                        ok = False
                        break

                if ok:
                    break
                ft.add(p[l] + 1, -1)
                l += 1

            ans += (r - l + 1)

        print(ans)

if __name__ == "__main__":
    solve()
```この実装では、値に対してフェンウィック ツリーを使用して、現在のウィンドウ内でマルチセットを維持します。 これにより、対数時間で k 番目に小さい要素を見つけて中央値を計算できます。 

2 ポインター ループは、各右端点の有効な左境界を維持します。 条件が失敗すると、左から縮小していきます。 縮小の正しさは、要素を削除するとカバレッジ条件が簡単になるだけで、将来の適切なエンドポイントにとって決して難しくならないという事実から来ています。 

微妙な点は、中央値候補までのすべての値をチェックすることです。 これは、permutation プロパティを使用した mex > Mid の直接エンコードです。 そうであるうちに$O(n)$この実装ではウィンドウごとに構造の削減が反映されます。 完全に最適化されたバージョンでは、再チェックを避けるためにプレフィックス カバレッジを段階的に維持します。 

## 実用的な例

 小さな順列を考えてみましょう$[1, 0, 2]$。 

のために$r = 0$、窓は$[1]$。 中央値は 1、mex は 0、条件は失敗します。 

のために$r = 1$、窓は$[1,0]$。 中央値は 0、mex は 2、およびすべての値$0$が存在するため、条件が成立します。 

のために$r = 2$、窓は$[1,0,2]$。 中央値は 1 ですが、mex は 3 なので、条件は成立します。 

| r | l | 窓 | 中央値 | チェックされた値 | 有効 |
 | --- | --- | --- | --- | --- | --- |
 | 0 | 0 | [1] | 1 | 0 がありません | いいえ |
 | 1 | 0 | [1,0] | 0 | 0 現在 | はい |
 | 2 | 0 | [1,0,2] | 1 | 0,1 現在 | はい |

 このトレースは、有効性が順序 (中央値) とプレフィックス値の範囲の両方にどのように依存するかを示します。 

ここで考えてみましょう$[0,2,1,3]$。 

のために$r = 2$、窓$[0,2,1]$中央値は 1 です。すべての値$0,1$表示されるので有効です。 のために$r = 3$、窓$[0,2,1,3]$再び中央値が 1 になり、プレフィックスが付きます$0,1$まだ完全にカバーされているため、有効です。 

| r | 窓 | 中央値 | プレフィックスチェック | 有効 |
 | --- | --- | --- | --- | --- |
 | 2 | [0,2,1] | 1 | 0,1 現在 | はい |
 | 3 | [0,2,1,3] | 1 | 0,1 現在 | はい |

 2 番目の例は安定性を示しています。一度条件を満たした後は、より大きな値を追加してもプレフィックス カバレッジが壊れることはありません。

 ## 特殊なケース

 単一要素の配列は、mex と Mid の間の直接の相互作用を公開します。 要素が 0 の場合、mex は 1、mid は 0 となるため、条件が成立します。 ゼロ以外の場合、mex は 0 であり、mid は要素であるため、条件は失敗します。 中央値が唯一の要素に等しく、プレフィックス カバレッジが空のセットまたはシングルトン セットに対してチェックされるため、アルゴリズムはこれを自然に処理します。 

次のような厳密に増加する順列$[0,1,2,3]$中央値を予測可能にし、mex は常にプレフィックスの連続性に依存します。 この場合、値をスキップしてプレフィックスが壊れると、ウィンドウは条件を満たすことができなくなります。 スライディング ウィンドウは、カバレッジが復元されるまで正しく縮小されます。 

小さな値が大きく離れた順列では、ウィンドウ調整を繰り返し行う必要があります。 2 ポインター メカニズムにより、各インデックスの追加と削除が最大 1 回行われることが保証されるため、最悪の場合のインターリーブでも動作は線形のままになります。
