 ## 解決策
 ## 問題の理解

 特定の日の平日がわかっている 1 つの月が与えられています。 その既知のアンカーは、1 から 31 までの曜日番号と、月曜日や日曜日などの曜日名で構成されます。 このアンカーを使用して、同じ月の別の日の曜日を決定する必要があります。 

問題の構造は本質的に線形カレンダーです。7 つのサイクルで毎日、曜日が 1 つずつ進みます。 2 つの日付の間で前後に移動するのは、日数の差のみに依存し、長さの違いや閏年などの月特有の性質には依存しません。 必要な唯一の操作は、数値オフセットを長さ 7 の巡回シーケンスのシフトに変換することです。 

制約は非常に小さく、日数は 31 で区切られています。これにより、複雑な前処理、広い範囲にわたるシミュレーション、またはデータ構造の必要性が即座に排除されます。 2 つの整数の差を計算し、モジュラー演算を適用するソリューションは、一定時間内であればすでに十分です。 

主なエッジケースは、平日サイクルでのラップアラウンド動作から発生します。 たとえば、既知の日が週の終わりに近く、ターゲット日が月の初めの場合、シフトはマイナスになります。 モジュロ 7 の正規化を忘れた単純な実装では、不正なインデックス付けが発生したり、負の配列アクセスが発生したりする可能性があります。 もう 1 つの微妙な問題は、平日の一貫した注文です。 曜日名とインデックスの間のマッピングがエンコードとデコードの間で矛盾している場合、結果は固定オフセットによって誤ってシフトされます。 

## アプローチ

 ブルートフォース解釈では、既知の日付から開始して日ごとにシミュレートします。 既知の曜日を a 日に割り当て、b までのすべての日を前方または後方に繰り返し、そのたびに曜日を増減します。 これは各ステップが決定的であるため機能しますが、最悪の場合、1 か月全体にわたって最大 31 ステップ移動します。 これはまだ簡単ではありませんが、概念的には不要なオーバーヘッドであり、境界が大きい場合には脆弱になります。 

重要な観察は、平日がサイズ 7 のサイクルを形成していることです。 それぞれの中間日をシミュレートする代わりに、b と a の間の正味変位のみが必要になります。 その変位は単純に (b − a) であり、平日のシフトは 7 を法とした値です。平日を整数に変換すると、答えは 1 つの算術式になります。 

これにより、問題全体が定数時間マッピングとモジュラー演算に削減され、反復が完全に排除されます。

 | ブルートフォース | O( | b − a | ) |
 | 最適 | お(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 この問題は、平日を循環数値システムに変換し、シフトを適用することで解決します。 

1. 各曜日に月曜日から時系列に 0 から 6 までの番号を割り当てます。 これにより、週の一貫した周期表現が作成されます。 
2. 既知のアンカー日 a とその曜日 s を読み取り、s を数値形式 cur に変換します。 
3. 対象日を読み取ります。 b.
 4. 差分 diff = b − a を計算します。これは、何日前に進むか (負の場合は後ろに進むか) を表します。 
5. diff mod 7 を使用してこの差を平日のシフトに変換し、常に 0 ～ 6 の範囲内に収まるようにします。 
6. このシフトを cur に追加し、再びモジュロ 7 を実行して、平日サイクル内に留まります。 
7. 結果の数値を曜日文字列に変換して出力します。 

### なぜ効果があるのか

平日システムは、長さ 7 の純粋なモジュラー サイクルです。 1 暦日の各増分は、平日スペースに 1 つのモジュロ 7 を追加することに対応します。 したがって、a 日から b 日への移動は、(b − a) 個の増分を適用することに正確に対応します。 この変位をモジュロ 7 で減らすと、シフトの同等クラスが維持されるため、7 日間の完全なサイクルは、最後の平日に影響を与えることなくキャンセルされます。 文字列とインデックス間のマッピングは全単射であるため、どの段階でも曖昧さは生じません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

days = {
    "Monday": 0,
    "Tuesday": 1,
    "Wednesday": 2,
    "Thursday": 3,
    "Friday": 4,
    "Saturday": 5,
    "Sunday": 6
}

rev = {v: k for k, v in days.items()}

def solve():
    parts = input().split()
    a = int(parts[0])
    s = parts[1].strip()

    b = int(input().strip())

    cur = days[s]
    shift = (b - a) % 7
    ans = (cur + shift) % 7

    print(rev[ans])

if __name__ == "__main__":
    solve()
```このソリューションでは、まず、曜日名と整数の間の固定全単射を構築します。これは、算術演算を実行するために不可欠です。 最初の行には数値と文字列の両方が含まれるため、入力は 2 つのステップで解析されます。 シフトの計算ではモジュロ 7 を使用して、週サイクル全体にわたる前進と後退の両方の正確性を確保します。 最終的に文字列に変換すると、マッピングが完了します。 

よくある実装上の間違いは、負の差異を正規化するのを忘れることです。 Python では、負のモジュロは引き続き正しく動作しますが、他の言語では、明示的に調整しない限り、インデックスが不正確になる可能性があります。

 ## 特殊なケース

 エッジ ケースの 1 つは、b が a より小さく、負の差が生じる場合です。 たとえば:

 入力:```
10 Friday
8
```ここで、金曜日はインデックス 4 に対応します。その差は 8 − 10 = −2 です。 モジュロ 7 を適用すると 5 が得られるため、金曜日から 5 ステップ前進します。 

金曜日(4) → 土曜日(5) → 日曜日(6) → 月曜日(0) → 火曜日(1) → 水曜日(2)

 出力は水曜日で、これは直接の逆方向カウントと一致します。 

もう 1 つのケースは、差がちょうど 7 の倍数である場合です。 

入力:```
15 Sunday
29
```差は 14、14 mod 7 = 0 です。曜日は変わりません。 これにより、週全体のサイクルが完全にキャンセルされ、何週間経過してもアンカーの平日が維持されることが確認されます。
