 ## 解決策
 ## 問題の理解

 整数の配列が与えられ、非常に特殊な操作を使用してそれを変更できます。 配列内の各位置は最大 1 回使用でき、位置 i を使用する場合は、その位置の値に i を掛けます。 私たちの目標は、配列自体を最大化または最小化することではなく、すべての配列要素の積を 2 の累乗で十分に割り切れるようにすることです。 

より具体的には、すべての要素の合計積に 2 の因数が少なくとも n 個含まれるようにします。これは、積を 2 で割る回数を追跡すると考えることができます。 各数値は 2 の因数の初期量に寄与し、許可された各演算により、選択したインデックスに応じてこの寄与が増加する可能性があります。 

入力には複数の独立したテスト ケースが含まれています。 各テスト ケースでは配列が与えられ、積の 2 のべき乗が少なくとも n になるように必要なインデックス操作の最小数を計算するか、すべてのインデックスを 1 回使用するだけでは不十分であると判断する必要があります。 

この制約は、n がテストごとに最大 100,000 まで大きくなり、テスト全体の合計が最大 200,000 になることを示唆しています。これにより、要素あたりの作業が非常に小さく、線形集計が使用されない限り、テストごとに 2 次または n log n のアプローチが除外されます。 どのソリューションも基本的に各テスト ケースを線形時間で処理する必要があります。 

いくつかの特殊なケースは、早期に切り分ける価値があります。 

最初の配列の積にすでに十分な 2 の因数がある場合、答えはゼロになります。 たとえば、n = 4 で配列が [8, 1, 1, 1] の場合、積にはすでに少なくとも 3 つの 2 の因数が含まれているため、演算は必要ありません。 

すべてのインデックスに演算を適用した後でも積が必要な 2 の累乗に達しない場合、答えは -1 でなければなりません。 これは、配列値がすべて奇数で、インデックスが 2 の十分な追加係数を提供しない場合に発生する可能性があります。 

単純な間違いは、寄与を追跡せずに操作を繰り返し適用したり、貪欲にインデックスを選択したりすることが正しさにつながると考えることです。 たとえば、最初に小さいインデックスを選択するのは無害に見えるかもしれませんが、インデックス値は 2 の累乗に寄与する値を直接制御するため、選択は全体的に最適である必要があります。 

## アプローチ

 直接的なブルート フォース アプローチでは、インデックスのすべてのサブセットを試し、演算の適用をシミュレートし、結果として得られる積の 2 の指数を計算します。 各サブセットについて、配列要素からの初期寄与を合計し、選択したインデックスからの寄与を追加します。 テスト ケースごとに 2^n 個のサブセットがあり、n = 40 の場合でもすでに大きすぎるため、これはすぐに実行不可能になりますが、ここでは n が 100000 に達します。 

重要な観察は、操作が 2 の指数の加算寄与にきれいに分離されていることです。 実際の値を追跡する代わりに、製品内に 2 の因数がいくつ存在するかのみを追跡します。 各配列要素は、その数値の 2 の指数に等しい固定量を提供します。 インデックス i を選択するたびに、i に 2 の指数を加算します。 

これにより、問題は「重み」が v2(i) であるインデックスのサブセットを選択することになり、必要な総赤字に到達することを目指します。 各インデックスは最大 1 回しか使用できないため、最小のアイテム数で目標を達成するために、固定の重みを持つアイテムを選択することが問題となります。 これは、各操作のコストは同じですが、異なるゲインが得られるため、最初に最大の v2(i) を持つインデックスを取得することで自然に解決されます。 

また、v2(i) が小さく、O(log n) によって制限されるという事実にも依存しているため、インデックスを指数でグループ化することで効率的なカウント戦略が可能になります。

## アルゴリズムのチュートリアル

 この問題を製品の 2 の累乗の追跡として書き直します。 初期寄与をすべての要素にわたる v2(ai) の合計とする。 少なくとも n に達する必要があります。 インデックス i に対する各操作では v2(i) が加算されます。 

1. すべての要素の v2(ai) を合計することにより、配列積内の 2 の因数の初期合計数を計算します。 これが予算の開始点となります。 
2. 追加の要素がいくつ必要か計算します。 現在の合計がすでに n に達しているかそれを超えている場合、操作は必要ないため、答えは直ちにゼロになります。 
3. 不足がある場合は、D を n から現在の合計を引いたものとして定義します。 これは、選択したインデックスから取得する必要がある 2 の累乗の正確な量です。 
4. 1 から n までのインデックス i ごとに、v2(i) を計算します。 同じ v2(i) を持つすべてのインデックスは寄与の点で交換可能であるため、この値でインデックスをグループ化します。 
5. これらのグループを v2(i) の降順で検討します。 次のグループに移動する前に、常に最上位のグループからできるだけ多くのインデックスを取得します。 選択された各インデックスは、残りの不足分を v2(i) だけ減らし、操作カウントを 1 つ増やします。 
6. 赤字がプラスでなくなったらすぐに停止します。 選択したインデックスの数が答えになります。 
7. すべてのインデックスを使用した後も赤字が依然として正の場合は、すべての演算から可能な最大の寄与さえも不十分であるため、-1 を出力します。 

それが機能する理由は、単調な交換引数に基づいています。 すべての操作のコストは等しいため、重要な唯一の要素は、各操作でどれだけ赤字が削減されるかです。 v2(i) 値は独立して固定されているため、寄与度の高いインデックスの代わりに寄与度の低いインデックスを選択すると、必要な操作の数が増えるだけです。 したがって、v2(i) でソートして貪欲に取得することが最適です。 グループ化構造により、明示的な並べ替えが必要なくなります。 指数ごとのカウントのみを集計します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def v2(x):
    return (x & -x).bit_length() - 1 if x else 0

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    base = 0
    for x in a:
        base += (x & -x).bit_length() - 1 if x else 0

    need = n - base
    if need <= 0:
        return 0

    cnt = [0] * (n + 1)
    for i in range(1, n + 1):
        cnt[(i & -i).bit_length() - 1] += 1

    ans = 0
    for w in range(n, -1, -1):
        if need <= 0:
            break
        take = min(cnt[w], (need + w - 1) // w if w > 0 else cnt[w])
        if w == 0:
            continue
        use = min(cnt[w], (need + w - 1) // w)
        need -= use * w
        ans += use

    if need > 0:
        return -1
    return ans

def main():
    t = int(input())
    out = []
    for _ in range(t):
        out.append(str(solve()))
    print("\n".join(out))

if __name__ == "__main__":
    main()
```この解決策は、完全な積の 2 の初期指数を計算することから始まります。これは、配列上のビット評価の合計にすぎません。 次に、不足分を計算し、考えられる各指数にどれだけのインデックスが寄与するかの度数表を作成します。 

重要な実装の詳細は、ソートを回避することです。 代わりに、各 v2(i) を持つインデックスの数を直接数えます。これは、一般的な制約では値の範囲が最大約 17 までにすぎないためです。 次に、より高いウェイトを最初に貪欲に消費します。 

重量ゼロの取り扱いには注意が必要です。 v2(i) = 0 のインデックスは欠損を減らすのにまったく役に立たないため、問題の構造でインデックスをカウントする必要がある場合を除き、無視されますが、実際にはカウントされません。

 ## 特殊なケース

 エッジ ケースの 1 つは、アレイがすでに要件を満たしている場合です。 このアルゴリズムは、インデックス処理の前に非正の赤字を計算し、ゼロを返すことによってこれを直ちに処理します。 

もう 1 つのエッジ ケースは、多くのインデックスの v2(i) がゼロに等しい場合です。 これらのインデックスは赤字の削減には寄与しないため、正確さに影響を与えることなく無視しても問題ありません。 これらは何の利益ももたらさないため、アルゴリズムが誤って使用することはありません。 

最後のエッジケースは、すべてのインデックスを使用しても必要な指数に達しない場合です。 その場合、すべての v2(i) の累積合計は不十分であり、貪欲なプロセスによりすべての有用なインデックスが使い果たされますが、不足分は正のままで、正しく -1 になります。
