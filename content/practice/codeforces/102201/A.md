 ## 解決策
 ## 問題の理解

 2 つの正の整数から始めます。`A`そして`B`、それぞれ最大 (10^{18}) です。 1 回の操作で、どちらかの値を 2 倍にしたり、一方の値をもう一方の値に加算したりすることができます。 目標は、操作の数を最小限に抑えることではありません。 最終的に 2 つの値が等しくなる、最大 5000 回の操作の有効なシーケンスを生成するだけで済みます。 

出力は一連の操作名です。 裁判官はこれらの操作をシミュレートするため、私たちのタスクは建設的です。つまり、常に十分な速さで終了する信頼性の高いプロセスを見つける必要があります。 

(10^{18}) という大きな上限により、都合よく選択された共通の値まで数値を増やそうとするアプローチが排除されます。 このような値は膨大になる可能性があり、可能性のあるターゲットに対する対数検索でさえ、許可される操作に自然に結び付けられるわけではありません。 5000 操作の制限は、目的のソリューションが単に最終的な終了に依存するのではなく、強力な減少手段を持つ必要があることも示しています。 

2 倍演算には有用な等価性が隠されています。 概念的に、私たちの現在の状態が次のようになっていると仮定します。`(A, B)`そして`A`は均等です。 出力してみると`B+=B`、実際の状態は`(A, 2B)`。 この実際の状態の両方の座標を 2 で割ると、次のようになります。`(A/2, B)`、両方の座標に同じ正の定数を乗算しても、同じ一連の加算演算と 2 倍演算によってそれらを等しくできるかどうかは変わりません。 したがって、2 つの数値間の比率の観点から、`B+=B`偶数を扱いましょう`A`まるで私たちが分けてしまったかのように`A`2 により、対称的に、`A+=A`概念的に偶数を分けてみましょう`B`2までに。 

これにより、主なエッジケースが得られます。 

入力用`5 5`、数値はすでに等しいため、正しい出力は次のようになります。`0`。 等価性をチェックする前に常に加算を実行する不注意な実装では、不必要な演算が生成され、ターゲットから遠ざかってしまう可能性さえあります。 

入力用`2 3`、概念的に分けることができます。`A`実行することで2までに`B+=B`、同等の正規化された状態を与える`(1, 3)`。 それから`B+=A`に相当する`(1, 4)`、 そして`A`2倍にして到達することができます`4`。 サンプルではまさにこのアイデアが使用されており、4 つの操作が生成されます。 小さい数値を大きい数値に加算するだけの不注意な実装では、2 の累乗を利用する代わりに、値が無限に増加する可能性があります。 

入力用`1 1`、答えはまたです`0`。 これにより、最初に数値がすでに等しいかどうかを確認せずに正規化ループに入る実装が捕捉されます。 

## アプローチ

 単純な総当たりアプローチでは、考えられるすべての操作を分岐として扱い、次の条件を使用して状態を検索します。`A == B`。 どの状態からでも 4 つの選択肢があるため、深さ 5000 までの検索は可能です。 

[
 1+4+4^2+\ドット+4^{5000}
 】

 候補演算シーケンス。最も深いレベルだけでも (4^{5000}) 個の可能性が含まれます。 積極的な枝刈りを行ったとしても、数値は際限なく増加する可能性があるため、有用な有限状態空間は存在しません。 このアプローチは完全に非現実的です。 

ブルート フォース検索には、便利な特性が 1 つあります。それは、すべての操作で肯定的な値が維持され、成功したすべてのパスが最終的に 2 つの等しい値に到達するということです。 問題は、膨大な数の選択肢を探索せずにそのような道を見つけることです。 

重要な観察は、2 倍を 2 による概念的な除算として使用できることです。 共通のスケーリング係数までの値を扱うことに決めたら、許可された 1 つの演算を使用して、すべての偶数を 2 で割ることができます。 これは、両方の数値から 2 の因数を繰り返し削除できることを意味します。 

最終的には両方の値が奇数になります。 それらが等しい場合、作業は完了です。 それ以外の場合は、`A < B`。 どちらも怪しいので、`A+B`は均等です。 出演します`B+=A`、ペアをに変更します`(A, A+B)`。 2 番目の値は偶数になったので、概念的には奇数になるまで繰り返し 2 で割ることができます。 

1 回除算した後の新しい 2 番目の値は次のようになります。 

[
 \frac{A+B}{2}。 
]

なぜなら`A < B`、これは厳密には以下よりも小さいです`B`。 さらに重要なのは、その差が少なくとも半分に減少することです。 

[
 \frac{A+B}{2}-A=\frac{B-A}{2}。 
】

 複数の除算が可能な場合、2 番目の値はさらに小さくなるため、差は少なくとも同程度減少します。 

したがって、両方の値が奇数で等しくない場合は常に、1 回の加算とそれに続くいくつかの除算により、それらの差が大幅に減少します。 初期の差は (10^{18}) 未満であるため、このような削減ラウンドは約 60 回しかあり得ません。 

同じ引数により、操作の総数に快適な制限も与えられます。 2 つの加算ラウンドの間で、各値は奇数になるまで 2 で除算されます。 正規化後は値が (10^{18}) を超えることはないため、1 ラウンドに必要な分割数は最大でも約 60 です。 合計は 5000 をはるかに下回っています。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(4^{5000})) 候補シーケンス | 検索パスごとに (O(5000))、全体的に指数関数的になる可能性 | 遅すぎる |
 | 最適 | (O(\log \max(A,B))) 削減ラウンド、対数正規化作業 | (O(\log \max(A,B))) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む`A`そして`B`。 それらがすでに等しい場合は、ゼロの操作を出力します。 変換の必要はありません。 
2. その間`A`偶数である、記録する`B+=B`概念的に置き換えます`A`による`A/2`。 記録された操作はもう一方の座標を 2 倍にするため、実際のペアは概念的なペアよりも公約数 2 で大きくなります。 平等の動作は、その共通のスケーリングによって変更されません。 
3. その間`B`偶数である、記録する`A+=A`概念的に置き換えます`B`による`B/2`。 これは、前のステップの対称バージョンです。 
4. 正規化された値が等しい場合は、停止します。 両方の値が奇数になったので、残りの不等状態は特に単純な構造になります。 
5. もし`A < B`、 記録`B+=A`。 概念的な価値は、`B`になる`A+B`、両方の入力が奇数であるため、これは偶数です。 
6. 新しいものを分割する`B`2つずつ繰り返して録音する`A+=A`あらゆる概念的な区分に対応します。 結果として生じる奇数`B`以前のものより小さいです`B`、2 つの値の間のギャップは少なくとも半分に減少しています。 
7. もし`B < A`、対称操作を実行します`A+=B`、分割を繰り返します`A`録音により2人まで`B+=B`。 
8. 2 つの概念的な値が等しくなるまで、正規化と加算のプロセスを繰り返します。 記録されたすべての操作を元の順序で出力します。 

不変条件は、両方の座標に同じ正の 2 乗を乗算するまでは、概念的なペアが常に実際のペアを表すということです。 このような共通のスケーリングは、許可される今後の一連の操作で座標を等しくできるかどうかに影響しません。 記録されたすべての操作は、対応する概念変換を実現する実際の操作そのものです。 両方の値が奇数で等しくない場合、小さい方を大きい方に加算すると、大きい方の値が均等になり、その後、概念上の除算によって差が少なくとも 2 分の 1 に減ります。 差は非負の整数であるため、このプロセスは最終的にゼロに到達する必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    a, b = map(int, input().split())
    operations = []

    while a != b:
        while a % 2 == 0:
            # Conceptually: a /= 2.
            # Real operation: double b, preserving the ratio.
            operations.append("B+=B")
            a //= 2

        while b % 2 == 0:
            # Conceptually: b /= 2.
            # Real operation: double a, preserving the ratio.
            operations.append("A+=A")
            b //= 2

        if a == b:
            break

        if a < b:
            # Both are odd here, so a + b is even.
            operations.append("B+=A")
            b += a
        else:
            operations.append("A+=B")
            a += b

    print(len(operations))
    sys.stdout.write("\n".join(operations))

if __name__ == "__main__":
    solve()
```の`operations`list には、出力する必要がある実際のコマンドが格納されます。 変数`a`そして`b`は、すべてのコマンドをシミュレートすることによって取得されたリテラル値ではなく、正規化された概念的な値として意図的に扱われます。 

いつ`a`が偶数の場合、コードはそれを 2 で割って記録します。`B+=B`。 実際の実行では、倍増します`B`生み出すだろう`(a, 2b)`。 これは概念的な状態のちょうど 2 倍です`(a/2, b)`したがって、2 つの表現は同じ比率と同じ将来の等価動作を持ちます。 

同じ理由が次の場合にも当てはまります`b`は偶数です。`A+=A`。 

両方の値が奇数になると、コードは小さい値を大きい値に加算します。 たとえば、次の場合`a < b`、操作`B+=A`変化`b`に`a+b`、これは偶数です。 次の反復では、すぐに除算ループに入り、2 の因数をすべて削除します。 

2 つの正規化ループの順序は、正確さにとって重要ではありません。 最初のループの後、`a`は奇数で、2 番目のループの後、`b`奇数です。 正規化中に 2 つの値が等しくなった場合、外側のループは不要な加算を実行する前に終了します。 

Python の整数はオーバーフローしないため、概念的な加算によって一時的に生成された値は安全です。 さらに重要なことは、2 つの奇数の値を加算し、その結果を少なくとも 2 で割った後の新しい値は最大でも以前の大きい値になるため、正規化された値は制限されたままであることです。

## テストケース

 出力は一意ではないため、テストでは生の出力文字列を 1 つの所定のシーケンスと比較すべきではありません。 代わりに、テスト ヘルパーは生成された操作を解析し、元の値でシミュレートし、最終的な値が等しいこと、および生成された操作が 5000 個以下であることを確認します。```python

import sys
import io

def solve():
    a, b = map(int, input().split())
    operations = []

    while a != b:
        while a % 2 == 0:
            operations.append("B+=B")
            a //= 2

        while b % 2 == 0:
            operations.append("A+=A")
            b //= 2

        if a == b:
            break

        if a < b:
            operations.append("B+=A")
            b += a
        else:
            operations.append("A+=B")
            a += b

    print(len(operations))
    sys.stdout.write("\n".join(operations))

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

def valid(inp: str, out: str) -> bool:
    a, b = map(int, inp.split())
    lines = out.strip().splitlines()

    if not lines:
        return False

    n = int(lines[0])
    if n < 0 or n > 5000:
        return False
    if len(lines) != n + 1:
        return False

    allowed = {"A+=A", "A+=B", "B+=A", "B+=B"}

    for op in lines[1:]:
        if op not in allowed:
            return False

        if op == "A+=A":
            a += a
        elif op == "A+=B":
            a += b
        elif op == "B+=A":
            b += a
        else:
            b += b

    return a == b

 ## 特殊なケース

 のために`5 5`、外装状態`while a != b`はすぐに偽になります。 操作リストは空のままなので、プログラムは次のように出力します。`0`。 初期状態はすでに目標を満たしているため、これがここで必要な唯一の正しい種類の動作です。 

のために`2 3`、最初の正規化では次のことがわかります。`A`は均等です。 番組の記録は`B+=B`そして概念的な状態を次のように変更します`(1,3)`。 両方の値が奇数で等しくないため、記録します。`B+=A`、与える`(1,4)`。 次の正規化は分割します`B`2回与える`(1,1)`。 実際のシーケンスは、`B+=B`、`B+=A`、`A+=A`、`A+=A`、そして実際の状態は次のように発展します。`(2,3)`に`(2,6)`、 それから`(2,8)`、 それから`(4,8)`、そして最後に`(8,8)`。 

のために`1 5`、どちらの値も奇数で始まります。 以来`1 < 5`、プログラムが実行する`B+=A`、概念的な状態を取得する`(1,6)`。 偶数の値を半分にすることができるようになり、`(1,3)`。 からの差は縮まりました`4`に`2`。 同じプロセスが変わります`(1,3)`に`(1,1)`。 これは、奇数のペアが正規化せずに小さい値を単純に加算し続ける必要がない理由を示しています。 

のために`1000000000000000000 999999999999999999`、数値は最大許容値であり、1 ずつ異なります。 どちらも奇数であるため、アルゴリズムは小さい値を大きい値に加算して、大きい値を偶数にします。 次に、概念的に 2 の因数を繰り返し削除します。 このようなラウンドごとに差は急激に減少し、正規化された値が元のスケールを超えることはありません。 したがって、大きな入力サイズは、オーバーフローや大きなターゲット値の検索を行わずに処理されます。 

のために`576460752303423488 1`、最初の数値は (2^{59}) です。 このアルゴリズムは、次を使用して 2 の累乗を一度に 1 つずつ削除できます。`B+=B`、概念的なものを減らします`A`(2^{59}) から`1`。 その後、2 つの値は等しくなります。 これにより、最も長い単純な正規化チェーンが実行され、操作リストが 5000 操作の制限をはるかに下回ったままであることが確認されます。
