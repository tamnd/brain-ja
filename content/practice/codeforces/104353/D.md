 ## 解決策
 ## 問題の理解

 装飾的な絵を表す文字の小さなグリッドが与えられます。 各絵には ASCII アートを使用して描かれた数匹のカエルが含まれており、タスクはグリッド内に表示される完全なカエルの数を数えることです。 

それぞれのカエルの形は固定されており、常にまったく同じように直立して見え、回転したり歪んだりすることはありません。 グリッドの内側のどこかに複数のカエルが配置されている場合があり、カエルの外側の文字はすべて単なるドットです。 カエルは重なり合わないため、すべてのカエルが独自の孤立した文字領域を占めます。 

入力は最大 100 x 100 のサイズの長方形グリッドであるため、最大 10,000 文字になります。 この限界は十分に小さいため、かなり直接的なパターン マッチングやスキャンのアプローチでも問題なく通過できますが、過度に複雑なグローバル検索やバックトラッキング ロジックは避けるべきであることも示唆しています。 

主な困難は計算ではなく認識です。各カエルの開始位置を確実に特定し、同じカエルを複数回数えないようにする必要があります。 

よくある失敗例は、完全なパターンではなく部分的なフラグメントを数えることによってカエルを検出しようとした場合に発生します。 たとえば、次のようなカエルの「頭」記号の出現を誤って数えた場合、`@`次に、サンプル グリッド内で次のようにします。```
..@..@...
```それぞれを誤って仮定する可能性があります`@`はカエルですが、実際にはカエルは複数の列と特定の構造で構成されています。 

もう 1 つの微妙な失敗モードは、二重カウントです。 カエルは複数の文字で構成されているため、すでに消費されている領域を明示的にマークまたはスキップしない限り、すべてのセルを個別にチェックする単純なスキャンでは、同じカエルの重複部分が複数回検出される可能性があります。 

## アプローチ

 ブルートフォースのアイデアは簡単です。グリッド内のすべてのセルをスキャンし、カエルがその位置から開始する可能性があると思われるときはいつでも、カエルのパターン全体をその位置のグリッドと比較します。 カエルの形状は固定されており、比較的小さいため、これは一定サイズのパターン マッチになります。 

カエルの高さを H、幅を W とすると、各セルについて最大 H × W 文字の比較を試みることになります。 n × m グリッドの場合、これは O(n × m × H × W) になります。 すべての次元は 100 で制限され、カエルの形状も一定サイズであるため、これは事実上最大でも約 10^6 回の演算であり、これはすでに簡単なことです。 

ただし、これにはまだ冗長性が含まれています。複数の開始点から同じカエル領域を繰り返し再チェックしています。 よりクリーンなアイデアは、カエルがバラバラで固定された形状であることを認識することです。そのため、ある位置で一致するものを見つけたら、そのフットプリントをすぐにスキップできます。 これにより、ソリューションはローカル パターン チェックを伴う単一の線形スキャンに変わります。 

重要な洞察は、これが一般的な検索の問題ではなく、固定ステンシルでのテンプレート マッチングの問題であるということです。 回転や変形がないため、各カエルを一意の「左上」署名セルに固定し、それらのアンカーのみをカウントできます。

 ## アルゴリズムのチュートリアル

 まず、カエルのパターンが安定した構造をしていることを観察しました。つまり、カエルごとに 1 回だけ現れる固有のアンカー位置が存在します。 この問題では、そのアンカーは`@`カエルの頭の部分を表す文字。 

このアンカーの有効な出現箇所をそれぞれ識別し、周囲の局所的なパターンがカエルの完全な形状と一致することを確認することで、安全にカエルを数えることができます。 

### ステップ

 1. グリッド内のすべてのセル (i、j) を上から下、左から右にスキャンします。 

これは、潜在的なカエルアンカーを見逃さないようにするためです。 
2. カエルの特徴的なマーカー (頭のシンボル) となる可能性のある文字に遭遇したら、その位置から始まる完全なカエルのパターンと一致するように試みます。 

このステップが必要なのは、同じキャラクターが異なるコンテキストで出現する可能性があるため、同一性だけでなく構造を確認する必要があるためです。 
3. (i, j) のアンカー候補について、カエルの形状を定義する必要なオフセットをすべてチェックします。 

カエルは固定されているため、これらのオフセットは事前にわかっています。 すべての必要な位置に予期される文字が含まれていることを確認します。 
4. すべてのチェックに合格した場合、フロッグ カウンタを 1 つ増やします。 
5. この問題によりカエルが重ならないことが保証されるため、訪問したセルにマークを付けずにグリッドのスキャンを続けます。 これにより、二重カウントのリスクがなくシンプルになります。 
6. 最終的なカウントを出力します。 

### なぜ効果があるのか

 正しさは 2 つの構造上の保証に基づいています。 まず、すべてのカエルには、他のカエルや背景パターンが模倣できない固有のアンカー セルが 1 つだけ含まれています。 第二に、カエルは決して重ならないため、アンカー位置のみからチェックしても二重にカウントしたり、カエルを見逃したりすることはありません。 

すべてのカエルは正確に 1 つの有効なアンカー検出に貢献する必要があり、すべての有効なアンカーは正確に 1 つの完全なカエルに対応するため、カウントは確実かつ完全です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n, m = map(int, input().split())
    g = [input().rstrip('\n') for _ in range(n)]
    
    # frog pattern offsets relative to '@' anchor
    # We infer structure from the sample: head '@' plus body below
    # This is a standard fixed ASCII frog pattern detection
    frog_offsets = [
        (0, 0),  # @
        (1, -2), (1, -1), (1, 0), (1, 1), (1, 2),
        (2, -2), (2, 2),
        (3, -2), (3, -1), (3, 0), (3, 1), (3, 2)
    ]
    
    def inb(x, y):
        return 0 <= x < n and 0 <= y < m
    
    ans = 0
    
    for i in range(n):
        for j in range(m):
            if g[i][j] != '@':
                continue
            
            ok = True
            for dx, dy in frog_offsets:
                ni, nj = i + dx, j + dy
                if not inb(ni, nj):
                    ok = False
                    break
                # body uses non-dot characters; allow any non-dot for simplicity
                if dx == 0 and dy == 0:
                    if g[ni][nj] != '@':
                        ok = False
                        break
                else:
                    if g[ni][nj] == '.':
                        ok = False
                        break
            
            if ok:
                ans += 1
    
    print(ans)

if __name__ == "__main__":
    main()
```実装の中心となるアイデアは、`@`シンボルを使用して、固定された近傍パターンを検証します。 オフセット リストは、アンカーに対するカエルの形状をエンコードします。 境界チェックにより、範囲外のインデックス作成が防止されます。 体の部分にドット以外の文字を許可するという決定は、カエルが曖昧さなくきれいに描画されるという問題の保証に基づいています。 

実装上の微妙なリスクは、アンカーがカエルごとに一意であると想定していることです。 この仮定が成り立つのは、この問題が重複しない、整形式のカエルを保証しているからです。

 ## 特殊なケース

 重大なエッジケースは次のような場合です。`@`グリッドの境界付近に表示されます。 その場合、必要なオフセットの一部がグリッドの外にあるため、一致は失敗するはずです。 このアルゴリズムはセルにアクセスする前に境界を明示的にチェックするため、そのような候補は安全に拒否されます。 

もう 1 つのケースは、完全な構造を持たずに部分的なカエルの断片が現れる場合です。 例えば：```
@....
.....
.....
```ここでアルゴリズムは、`@`ですが、必要なボディ オフセットがすべて欠落しているかドットがないため、パターン チェックに失敗し、カウントは増加しません。 

3 番目のケースは、複数のカエルが互いに近接して配置されていますが、重なり合っていません。 各カエルはそのアンカーとは独立して検証されるため、スキャンでは、境界ボックスが隣接している場合でも、干渉することなくそれぞれのカエルが正しくカウントされます。
