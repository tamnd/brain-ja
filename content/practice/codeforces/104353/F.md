 ## 問題の理解

 英語の小文字で構成される文字列が与えられているので、位置が 3 つ重なっている個数を数える必要があります。$(a, b, c)$指数が満足するように存在する$1 \le a < b < c \le n$、これらの位置の文字はすべて同一であり、インデックスは等差数列を形成します。$2b = a + c$。 

条件$2b = a + c$力$b$ちょうど中間点になるように$a$そして$c$したがって、すべての有効なトリプルは、中心の周りの対称位置にある 2 つの等しい文字を選択することによって決定されます。 言い換えれば、3 つの文字がすべて同じで、中央のインデックスが外側の 2 つのインデックスの中点である、長さ 3 の回文トリプルを探しています。 

入力サイズが大きい: 最大$10^5$テスト ケースあたりの文字数、およびすべてのテスト ケースの合計で最大 10,000 文字$n$によって制限される$10^5$。 これにより、二次方程式の解は即座に除外されます。$n$テストケースごとに、たとえ単一であっても$O(n^2)$合計入力を渡すとすでに遅すぎます。 目標は、テスト ケースごとに線形に近いか、すべてのテスト ケースを組み合わせて最大でも線形である必要があります。 

素朴な思考による微妙な失敗例は、算術制約を無視して問題を「同じ文字を 3 つ選択する」ものとして扱うことです。 たとえば、文字列では`aaaaa`、任意の 3 つを選択する方法の数`a`は$\binom{5}{3} = 10$、ただし、これらのトリプルのうちの一部のみが等間隔を満たします。 のような組み合わせだけなので、正解は小さくなります。$(1,3,5)$そして$(1,2,3)$そして$(3,4,5)$中間点の位置合わせを満たすものは有効ですが、次のような任意のトリプルは有効です。$(1,2,5)$は無効です。 これは、周波数カウントだけでは不十分であることを示しています。 

もう 1 つのエッジ ケースは、文字列に文字が非常にまばらに出現する場合です。たとえば、`abacada`。 文字が複数回出現する場合でも、ほとんどのトリプルは対称な等差数列を形成しないため、出現を任意に組み合わせることができません。 

## アプローチ

 ブルートフォースアプローチでは、すべてのペアが列挙されます。$(a, c)$、計算する$b = (a + c) / 2$、それが整数であり、それらの間にあるかどうかを確認し、3 つの文字がすべて一致することを確認します。 これは正しいですがコストがかかります$O(n^2)$各ペアに対して一定の作業を実行するため、テスト ケースごとに実行されます。 と$n = 10^5$、これは次のようになります$10^{10}$実行可能な限界をはるかに超えた最悪の場合の操作。 

重要な観察は、中間点条件がエンドポイントを緊密に結合していることです。 任意のトリプルの観点から考える代わりに、中間のインデックスを固定します。$b$。 一度$b$が固定されている場合、条件によりペアを確認する必要があります。$(a, c)$その周りを対称的に。 必要です$a < b < c$、$str[a] = str[c] = str[b]$、 そして$a + c = 2b$。 これはつまり$a$そして$c$～から等距離にある$b$、つまり一定の距離に対して$d$かどうかを確認するだけです。$str[b-d] = str[b+d] = str[b]$。 これにより、各中心をスキャンして外側に拡張するという問題が軽減されますが、それでも有効な距離ごとに一定の作業が行われます。 

各センターで次のことに注目することで、さらに最適化できます。$b$、距離だけを考慮する必要があります$d$両側が文字列の内側に残るようにします。 すべてのそのようなチェックの合計数$b$は$\sum_b O(\min(b, n-b))$、つまり$O(n^2)$最悪の場合、アルファベットの制限を悪用することができます。 

文字は 3 つの位置すべてで一致する必要があるため、問題を文字ごとに分けることができます。 キャラクターごとに$ch$、それが出現するすべてのインデックスを収集します。 ここで問題は、このインデックス リスト内の長さ 3 の等差数列を数えるということです。 固定文字の場合、その位置が$p_1, p_2, \dots, p_k$、トリプルを数える必要があります$p_i, p_j, p_k$そのような$p_i + p_k = 2p_j$。 

これは、ソートされたリストでの古典的な「3 項の等差数列の数え方」問題です。 ミドルあたりのナイーブなツーポインターには依然としてリスクがある$O(k^2)$しかし、キーの対称性を利用することはできます: 各ペアについて$(i, k)$、中点を計算し、それがセット内に存在するかどうかを確認します。 メンバーシップ クエリにハッシュ セットを使用すると、各ペアがチェックされます。$O(1)$、与える$O(k^2)$最悪の場合は文字ごとに発生しますが、すべての合計なので$k$文字以上です$n$、最悪の場合はまだ変性します。 

ただし、視点を再度反転することもできます。エンドポイントを修正する代わりに、中間のインデックスを修正します。$j$各文字リスト内。 与えられた$p_j$、ペアを数えたい$i < j < k$そのような$p_i + p_k = 2p_j$。 からのオフセットの周波数マップを維持できます。$p_j$。 それぞれについて$i < j$、 定義する$d = p_j - p_i$が存在するかどうかを確認する必要があります。$k$そのような$p_k - p_j = d$。 事前に計算された距離にわたる接尾語頻度マップを使用すると、各中間値を文字リストごとの償却線形時間で答えることができ、全体的な結果が得られます。$O(n)$すべてのキャラクターにわたる解決策。 

これにより、問題は、文字ごとに、各距離が中心の左右に何回出現するかというカウントを維持し、中心を左から右に移動するときにこれらのカウントを更新することに変換されます。

 ## アルゴリズムのチュートリアル

 1. 文字列内の各文字のインデックスを個別のリストにグループ化します。 有効なトリプルは文字を混合できないため、これにより独立したサブ問題が分離されます。 
2. 各文字リストについて、最初に中心とみなされる位置を除くすべての位置を含む右側の頻度構造を構築します。 これにより、必要な対称距離に一致する将来の位置の数を高速に検索できます。 
3. リスト内の各位置を中間インデックスとして扱い、反復処理します。$j$、右側の構造から徐々に削除し、前の構造を左側の構造に追加します。 
4. 各中間ポジションについて、以前に確認されたすべての左ポジションを考慮します。$i$、距離を計算します$d = p_j - p_i$、どうかを確認してください。$p_j + d$右側に存在します。 成功した各一致は 1 つの有効なトリプルに貢献します。 
5. すべての文字にわたるすべての一致を累積し、合計を出力します。 

重要な考え方は、アルゴリズムは現在の中心を基準にして左右に分割されたペアのみをカウントするため、中央の要素を処理するときにすべての有効なトリプルが 1 回だけカウントされるということです。 

### なぜ効果があるのか

 すべての有効なトリプル$(a, b, c)$中間のインデックスによって一意に識別されます$b$。 加工時$b$、 両方$a$そして$c$パーティションの反対側にあることが保証されています。$a$左側の構造にあり、$c$正しい構造になっています。 距離条件により、次のことが保証されます。$c$まさにそのミラーリングされたものです$a$その周り$b$。 中間点がアクティブなときにすべてのペアが正確にチェックされるため、トリプルが見逃されたり二重にカウントされたりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, s = input().split()
        n = int(n)

        pos = [[] for _ in range(26)]
        for i, ch in enumerate(s):
            pos[ord(ch) - 97].append(i + 1)

        ans = 0

        for arr in pos:
            m = len(arr)
            if m < 3:
                continue

            # right set initially contains all positions except first
            right = set(arr[1:])

            for j in range(1, m - 1):
                mid = arr[j]

                # move current mid from right to "processed"
                if mid in right:
                    right.remove(mid)

                # count pairs (i, j, k)
                for i in range(j):
                    d = mid - arr[i]
                    if mid + d in right:
                        ans += 1

        print(ans)

if __name__ == "__main__":
    solve()
```実装ではまずインデックスを文字ごとに区切ります。これにより、同一の文字を持つ有効なトリプルのみが考慮されるようになります。 中心となるアイデアは、各文字グループ内の可能な中間位置をそれぞれ反復処理することです。 

内側のループは、以前に発生したすべての要素を潜在的な左端点としてチェックします。 各左端点について、対称的な右端点が直接計算されます。 セットは、一定時間内に正しいエンドポイントの存在をテストするために使用されます。 

主な微妙な点は、右側の構造の正確さを維持することです。 これは、現在の中央の厳密に右側のインデックスを表す必要があります。そのため、カウントする前に現在の中央を削除します。 これにより条件が強制されます$a < b < c$。 

## 実用的な例

 ### 例 1:`abcabc`キャラクターごとにポジションをグループ化します。`a: [1,4]`、`b: [2,5]`、`c: [3,6]`。 

各グループを個別に処理します。 それぞれは 2 回しか出現しないため、どのグループもトリプルを生成できません。 答えは0のままです。 

これは、頻度だけでは不十分であることを裏付けています。 少なくとも 3 つのオカレンスと正しい間隔が必要です。 

### 例 2:`aaaaaa`ポジションは`[1,2,3,4,5,6]`。 

中間位置を 1 つずつ処理します。 

| 中間インデックス | 左の位置 | 確認された距離 | 有効なトリプルが追加されました |

 ## 特殊なケース

 のような文字列の場合`aaaaa`、アルゴリズムは各中間点を個別に処理します。 たとえば、中央のインデックス 3 では、左は`[1,2]`そして右側には次が含まれます`[4,5]`。 左からの距離は 2 と 1 で、どちらも右側に対応するものがあり、3 を中心とする 2 つのトリプルが生成されます。これにより、対称性が保たれるトリプルのみが正しくカウントされ、距離チェックが失敗するために (1,2,5) のような無効な組み合わせがカウントされることが回避されます。 

次のような疎な繰り返しを含む文字列の場合`abacada`、各文字グループは独立して処理されます。 キャラクターについて`a`位置で`[1,3,5,7]`、距離ミラーが正しく寄与する中点中心のチェックのみ。 このアルゴリズムでは異なる文字が混在することはないため、誤検知は発生しません。
