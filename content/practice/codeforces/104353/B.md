 ## 解決策
 ## 問題の理解

 この問題のプロセスは、1 日目から始まる数日間の長いタイムラインによって推進されます。毎日、zy は午前中に固定金額 (5 単位) を Belmaxi に送金することになっています。 このルーチンからの唯一の逸脱は、特定の日に、zy が送金を忘れることです。 

7 日ごとに行われる週次チェックもあり、常に 1 日目が木曜日、毎日 7k+1 も木曜日になるように調整されます。 毎週木曜日の終わり (具体的には 7k+1 日目、23:59) に、Belmaxi はその木曜日で終わる連続 7 日間を振り返り、zy がそれらすべてに正常に送金したかどうかを確認します。 7 日間すべてが「支払われた」場合、Belmaxi は zy に 50 単位の報酬を与えます。 そうでなければ、その木曜日には何も起こりません。 

入力により、合計日数 n と、zy が支払いを忘れた日数のソートされたリストが得られます。 タスクは、Belmaxi の純利益を計算することです。Belmaxi の観点からは、報酬が支払われるため、支払いが成功するたびに +5 が寄与し、毎週の完璧な 7 日間の連続は -50 に寄与します。 

重要な課題は、n が 10^16 に達する可能性があるため、毎日繰り返すことが不可能であることです。 代わりに、まばらな失敗日のみが問題となります。 

7 日間のウィンドウがどのように重なるかによって、微妙な特殊なケースが発生します。 1 日逃しただけで、週ごとに複数の報酬が同時に失われる可能性があり、逆に、長期にわたって成功を収めると、すべてが対象となる複数の重複する 7 日間の期間が作成される可能性があります。 

たとえば、n = 14 でミスがなかった場合、両方の週で報酬が生成されます。 正味は 14 * 5 − 2 * 50 = 70 − 100 = −30 です。 重複しない週のみをチェックする単純なアプローチでは、2 番目の報酬を逃してしまいます。 

もう 1 つのエッジ ケースは、毎週のウィンドウの境界付近でミスが集中する場合です。 7 日目のミスは最初のウィンドウにのみ影響しますが、8 日目のミスはアライメントに応じて 7 日目で終了するウィンドウと 14 日目で終了するウィンドウの両方に影響します。 

これらのオーバーラップと巨大な n により、問題は、毎日繰り返すことなく、固定長 7 のスライディング ウィンドウ内で何日欠落するかを推論することになります。 

## アプローチ

 ブルート フォース ビューでは、毎日 1 から n までシミュレートして、zy が支払ったかどうかをマークし、毎日、最後の 7 日間のウィンドウが完了したかどうか、およびその日が木曜日のチェックポイントであるかどうかを計算します。 これは概念的に機能します。サイズ n の配列を維持し、欠落している日を埋め、毎日のスライディング ウィンドウの合計を計算します。 

ただし、n が 10^16 になる可能性があるため、これは直ちに不可能です。そのため、配列を反復処理することはおろか、配列を保存することさえ不可能です。 たとえ n が 10^6 にすぎなかったとしても、7 日間のウィンドウ合計を単純に再計算すると O(n) 以上になりますが、それでも許容可能です。 ここで、n はすべての per-day メソッドを破棄します。 

重要な観察は、報酬の構造は、木曜日に終了する 7 日間の各セグメントが完全に「クリーン」であるかどうかのみに依存するということです。 木曜日は 7 日ごとに発生するため、これらのセグメントはエンドポイントの点では互いに関連していませんが、内容は重複しています。 日数をシミュレーションするのではなく、視点を変えます。欠席した日が、それが影響する週のウィンドウ数に決定的に影響します。 

それぞれの欠落日 ai は、最大 7 つの連続する木曜日終了ウィンドウに影響します。これは、1 日は、終点がその後 6 日以内にある 7 日間ウィンドウに正確に含まれるためです。 これにより、日ではなく週の圧縮インデックスに対する範囲カウントを使用して、影響を受ける週に対する欠落日の寄与を処理できるようになります。 

各週を、日 [7k-6, 7k] に対応するインデックス k として扱うことができます。 ai 日のミスは、7k-6 ≤ ai ≤ 7k となるようにすべての k に影響を及ぼします。これは、k 値の小さな整数範囲に変換されます。 毎日繰り返すのではなく、週インデックスの差分配列を使用して、各週のミス数を累積します。 すべてのミスを処理した後、ミス数が 0 の場合にのみ、週は 50 を寄与します。

これにより、問題はクリーンな週と収入の合計日数を数えることになり、どちらも O(x) で計算できます。

 ## アルゴリズムのチュートリアル

 まず、タイムラインを丸 1 週間という観点から再解釈します。 各週 k は、7k−6 から 7k までの日のセグメントに対応し、報酬の評価にはエンドポイントの 7k 日のみが重要です。 報酬は、そのセグメントの 7 日間すべてが支払われたときに発生します。 

次に、完了した週の合計数 W = n // 7 を計算します。W * 7 を超えて残った日数は完全なチェック ウィンドウを形成せず、報酬には無関係です。 

私たちは、各週の間隔内に何日の欠席が含まれるかを追跡する構造を維持しています。 欠落日ごとに各週を個別にマークするのではなく、各欠落日 ai を影響を受ける週のインデックスの範囲に変換します。 7k−6 ≤ ai ≤ 7k の場合、日 ai は k 週にあります。これは k ∈ [(ai + 6) // 7, (ai // 7)] と同等です。 週の整数範囲にわたる差分配列を使用して、そのような週のすべてのミス数を増分します。 

すべての欠落日を処理した後、第 1 週から第 W 週にわたってスイープし、欠落のプレフィックス合計を累積します。 ミスがゼロの毎週は 50 の報酬に貢献し、毎日ミスを除いて常に基本収入 5 に貢献します。 

最後に、拠出金を結合します。総収入は 5 * (n − x)、総支払額はクリーンな週数の 50 倍になります。 

### なぜ効果があるのか

 各週の報酬は、欠落した日が 7 日間の間隔内にあるかどうかによってのみ決まります。 日から週のインデックスへの変換では、この条件が正確に維持されます。これは、欠落した日がその間隔を含む一連の週に正確にマップされるためです。 差分配列により、各週ですべての寄与が正しく集計され、このカウントを超えて連続しない週間隔の間に相互作用が存在しないことが保証されます。 これにより、プレフィックスの蓄積後、毎週がクリーンかそうでないかが正しく分類されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n, x = map(int, input().split())
        a = list(map(int, input().split())) if x else []

        # total base income from successful payments
        total_income = 5 * (n - x)

        W = n // 7  # number of full weeks that can produce rewards

        diff = [0] * (W + 3)

        for day in a:
            # compute affected week range [L, R]
            L = (day + 6) // 7
            R = day // 7

            if L <= R:
                if L <= W:
                    diff[L] += 1
                    if R + 1 <= W:
                        diff[R + 1] -= 1

        clean_weeks = 0
        cur = 0
        for i in range(1, W + 1):
            cur += diff[i]
            if cur == 0:
                clean_weeks += 1

        total_reward = 50 * clean_weeks
        out.append(str(total_income - total_reward))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```中心となる変換は、日インデックスから週インデックスへの変換です。 数式`(day + 6) // 7`そして`day // 7`影響を受ける週の範囲を定義します。 +6 シフトにより、境界に近い日であっても、その日が含まれる 7 日間のウィンドウに正しく反映されます。 

差分配列により、欠落日ごとに影響を受ける各週を明示的にマークすることが回避されます。 潜在的に O(7x) 個の位置を更新する代わりに、各ミスは O(1) 個の更新のみに寄与し、最後のスイープで実際のカウントが解決されます。 

基本収入の計算`5 * (n - x)`報酬とは関係なく、欠落日がない日は常に 5 単位の支払いを 1 回だけ提供するため、安全です。 

## 実用的な例

 n = 15 でミスが 7 日目と 8 日目にあるサンプルを考えてみましょう。 

まず、W = 15 // 7 = 2 週間を計算します。

 | 7 | 2 | 1 | 第 2 週に適用されます |
 | 8 | 2 | 2 | 第 2 週に適用されます |

 処理後、影響を受けるのは第 2 週目のみです。 

私たちは何週間も掃除します:

 | 2 | 1 | いいえ |

総収入 = 5 * (15 − 2) = 65

 合計報酬 = 50 * 1 = 50

 答え = 15

 これは、間違った週を二重にカウントすることなく、重複するミス範囲がどのように正しく蓄積されるかを示しています。 

ここで、完全にクリーンなケース、つまり n = 14、x = 0 を考えてみましょう。 

W = 2。 

| 週 | ミスカウント | クリーン？ |

 | 1 | 0 | はい |

これは、すべての有効な週次ウィンドウが独立して寄与し、ミスがない場合には重複する構造が干渉しないことを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(x + n/7) | 各ミスは O(1) に寄与し、その後数週間にわたって 1 回の線形スイープを行います。 
| スペース | O(n/7) | 週インデックスの差分配列 |

 この制約では、n は 10^16 まで許可されますが、x は 10^5 までのみ許可されます。 この解は x と n/7 のみに依存するため、十分に高速になります。 週レベルの集計のみが保存されるため、メモリは小さいままです。

 ## 特殊なケース

 主なエッジ ケースは、欠席日が 7 日目や 14 日目など、正確に週の境界線上にある場合です。7 日目に欠席がある n = 14 の場合、W = 2。欠席は L = 1、R = 1 にマッピングされるため、影響を受けるのは第 1 週のみです。 2 週目はクリーンなままであり、報酬も得られます。 これにより、境界マッピングが隣接する週に誤って波及しないことが確認されます。 

もう 1 つのエッジ ケースは、不完全な週が存在するタイムラインの終わり近くでミスが集中する場合です。 たとえば、n = 15 でミスが 15 日目にある場合、その日は式によれば 3 週目にありますが、W = 2 であるため、この日は完全に無視されます。 丸一週間だけが報酬に貢献するため、アルゴリズムはそれを安全に破棄します。 

最後の微妙なケースは、同じ週内に複数のミスがあった場合です。 n = 7 で 2、3、5 日目のミスの場合、それらはすべて第 1 週にマッピングされ、プレフィックスの合計により、ミスが発生した回数に関係なく、その週が非クリーンとして 1 回カウントされることが保証されます。
