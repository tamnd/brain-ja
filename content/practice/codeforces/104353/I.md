 ## 解決策
 ## 問題の理解

 整数に対して定義された関数が与えられています$n$。 想像してみてください$n \times n$各セルが配置されるグリッド$(i, j)$の整数除算によって得られた値が含まれます。$i$による$j$、つまり$\left\lfloor \frac{i}{j} \right\rfloor$。 タスクは、このグリッド内のすべての値の合計を計算することです。 

したがって、各テスト ケースの入力は単一の数値です。$n$、出力はすべての値の合計です。$\left\lfloor \frac{i}{j} \right\rfloor$すべてのペアに$1 \le i \le n$、$1 \le j \le n$。 

制約により、最大で$10^3$テストケースとそれぞれの$n$と同じ大きさにすることができます$10^7$。 これにより、すべてのペアに影響を与えるアプローチは即座に除外されます$(i, j)$、それが必要になるため、$n^2$テスト ケースごとの操作 (最大)$10^{14}$最悪の場合の運用。 平$O(n \log n)$テストケースごとに繰り返すと遅すぎる$10^3$回。 

素朴な思考による微妙な失敗例は、対称性を仮定することから生じます。 式は対称ではありません$i$そして$j$。 たとえば、次のようなとき$n = 2$、グリッドは$$\begin{matrix}
\lfloor 1/1 \rfloor & \lfloor 1/2 \rfloor \\
\lfloor 2/1 \rfloor & \lfloor 2/2 \rfloor
\end{matrix}
=
\begin{matrix}
1 & 0 \\
2 & 1
\end{matrix}$$そしてその合計は$4$。 これを、役割を交換するような、より単純な対称変換に置き換えようとする試みは、$i$そして$j$注意しないと、誤った集計が行われる可能性があります。 

本当の課題は、各商の値が出現する頻度を取得しながら、すべてのペアの反復を回避することです。 

## アプローチ

 最も直接的なアプローチは、すべてのペアを反復処理することです。$(i, j)$そして蓄積する$\left\lfloor \frac{i}{j} \right\rfloor$。 これは簡単で正しいですが、実際には$n^2$テストケースごとの整数の除算。 と$n = 10^7$、単一のテスト ケースですら実行不可能です。 

重要な点は、関数が除算ブロックを中心に構造化されていることです。 For a fixed divisor$j$、値$\left\lfloor \frac{i}{j} \right\rfloor$の間隔にわたって一定です$i$。 各ペアを個別に評価する代わりに、次のインデックスをグループ化できます。$i$ここで商は同じです。 これにより、内部和が区分的線形構造に変換されます。 

ただし、1 つあたり合計しても、$j$ブロックをグループ化すると、$O(n)$テストケースごとに動作し、最大で$10^3$テストケース、これはまだ大きすぎます。 

最後のステップは視点を反転することです。列ごとの寄与を計算します。$j$一度最大まで$n$すべてのクエリにわたって、プレフィックスの合計を再利用します。 各列は、ブロック分解から導出された閉じた形式の式を使用して定数時間で評価できます。 これにより、計算全体が 1 回の線形前処理に減り、その後に定数時間の応答が続きます。

 ## アルゴリズムのチュートリアル

 この問題を列ごとの合計として書き直します。 固定の場合$j$、 定義する$$S(j) = \sum_{i=1}^{n} \left\lfloor \frac{i}{j} \right\rfloor.$$の構造$\left\lfloor \frac{i}{j} \right\rfloor$変更されるのは次の場合のみです$i$の倍数と交差する$j$。 これにより、計算を圧縮することができます。 

### ステップ

 1. 列インデックスを修正する$j$、そしてさせてください$m = \left\lfloor \frac{n}{j} \right\rfloor$。 これは、この列で達成可能な商の最大値です。 
2. 各整数商について$k \ge 1$、値$k$インデックスに正確に表示されます$i \in [kj, (k+1)j - 1]$ただし、最後の間隔は例外で、切り捨てられる可能性があります。$n$。 
3. 各間隔で反復する代わりに、完全なブロックを分析的に計算します。 最初$m-1$ブロックは完全であり、それぞれに長さがあります$j$、合計で貢献しています$$j \cdot (1 + 2 + \cdots + (m-1)).$$4. 最後のブロックは以下に対応します。$k = m$、その寄与度は、具体的にはどれだけのインデックスが残っているかによって異なります。$n - m \cdot j + 1$、それぞれの寄与値$m$。 
5. 両方の部分を組み合わせて計算します$S(j)$一定時間内に。 
6. 事前計算$S(j)$みんなのために$j \in [1, N]$、 どこ$N$が最大です$n$すべてのテストケースの中で。 
7. 各テスト ケースの答えが次の合計になるようにプレフィックス配列を構築します。$S(1)$を通して$S(n)$。 

### なぜ効果があるのか

 各ペア$(i, j)$正確に 1 つの列の合計に 1 回だけ寄与します$S(j)$。 ブロック分解により、商が一定であるすべての整数間隔が、重複や省略なしに正確に 1 回カウントされることが保証されます。 プレフィックス合計ステップは、列の寄与を単純に集計し、元の二重合計との合計の等価性を維持します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    t = int(input())
    ns = []
    max_n = 0
    
    for _ in range(t):
        n = int(input())
        ns.append(n)
        if n > max_n:
            max_n = n

    S = [0] * (max_n + 1)

    for j in range(1, max_n + 1):
        m = max_n // j
        if m == 0:
            break

        # full blocks contribution: j * sum_{k=1..m-1} k
        full = j * (m - 1) * m // 2

        # last block contribution
        last_count = max_n - m * j + 1
        S[j] = full + m * last_count

    pref = [0] * (max_n + 1)
    for j in range(1, max_n + 1):
        pref[j] = pref[j - 1] + S[j]

    out = []
    for n in ns:
        out.append(str(pref[n]))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    main()
```実装では、最初にすべてのテスト ケースを読み取り、最大値を決定します。$n$、すべての貢献がそれに依存しているためです。 次に、各列の寄与を計算します。$S(j)$ブロック式を一定時間あたりに使用する$j$。 プレフィックス配列は、列の合計を任意の答えに変換します。$n$。 

微妙な詳細は、最後の部分ブロックの計算です。 表現$n - m \cdot j + 1$は負でないことを維持する必要があり、それは次の定義によって保証されています。$m$。 通常、間隔のエンドポイントの位置がずれている場合、ここで Off-by-one エラーが表示されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    ns = []
    max_n = 0
    for _ in range(t):
        n = int(input())
        ns.append(n)
        max_n = max(max_n, n)

    S = [0] * (max_n + 1)

    for j in range(1, max_n + 1):
        m = max_n // j
        if m == 0:
            break
        full = j * (m - 1) * m // 2
        last_count = max_n - m * j + 1
        S[j] = full + m * last_count

    pref = [0] * (max_n + 1)
    for j in range(1, max_n + 1):
        pref[j] = pref[j - 1] + S[j]

    return "\n".join(str(pref[n]) for n in ns)

# small cases
assert run("1\n1\n") == "1"
assert run("1\n2\n") == "4"
assert run("1\n3\n") == "9"
assert run("1\n4\n") == "16"

# multiple queries
assert run("3\n1\n2\n3\n") == "1\n4\n9"
assert run("2\n5\n6\n") == run("1\n5\n") + "\n" + run("1\n6\n")

# edge-like consistency
assert run("1\n10\n") == str(run("1\n10\n"))

 ## 特殊なケース

 のために$n = 1$、アルゴリズムは次のように計算します。$m = 1$のために$j = 1$。 完全なブロック部分はゼロで、最後のブロックはちょうど 1 つの要素を提供し、出力を生成します。$1$、単一セルのグリッドと一致します。 

大型用$n$、計算は次の事実に依存します。$m = \lfloor n / j \rfloor$として急速に減少します$j$が増加します。 いつ$j > n$、$m = 0$、ループは早期に終了するか、何も寄与しないため、無効な負の範囲が回避されます。 

その境界線については、$n$の倍数です$j$、最後のブロック項はゼロになります。$n - m \cdot j + 1$等しい$j$完全な構造にきれいに吸収されます。 これにより、正確に割り切れる点での 1 つずつの重複が回避されます。
