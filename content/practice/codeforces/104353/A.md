 ## 問題の理解

 ターゲット文字列が与えられています`S`そして`k`箱。 各ボックス`i`制約文字列が付属しています`T_i`。 私たちは分割しなければなりません`S`正確に`k`連続するピース、空のピースを許可する、`i`-th 部分は、残りの接尾辞の接頭辞です。`S`ステップで`i`また、次の部分文字列も`T_i`。 すべてのボックスを処理した後、`S`消費しなければなりません。 

箱に入れたピースの長さを表すと`i`として`b_i`、タスクは有効な分割を見つけるだけでなく、シーケンスを最小化する分割を選択することです。`(b_1, b_2, ..., b_k)`辞書順に。 

したがって、最初のボックスの長さが最も重要です。 すべての有効な方法の中で、可能な限り最小の方法が必要です`b_1`。 そして、その中でできるだけ小さいものを、`b_2`、 等々。 

重要な構造観察は、次のステップです。`i`、現在残っている接尾辞の接頭辞を選択しています。`S`ただし、選択したプレフィックスは内部のどこかに出現する必要があります`T_i`。 の部分文字列でなければならないため、`T_i`残りの接頭辞も`S`、重要なのは長さの接頭辞かどうかだけです`L`残りのサフィックスは`T_i`。 

したがって、各ステップは基本的に次のとおりです。後でプロセス全体を実行可能に保つために、可能な限り短いプレフィックス長を選択します。 

制約は厳しく、すべてのテスト ケースにわたる文字列の合計長は最大です。`2 × 10^6`、そしてそれぞれ`T_i`大きくなる可能性があります。 これにより、すべての分割点を試行したり、ステップごとに部分文字列チェックを単純に再計算したりするアプローチは除外されます。 

素朴なアプローチでは、各ボックスで長さを増やそうとします。`0, 1, 2, ...`、各候補について、それが次の部分文字列であるかどうかを確認します。`T_i`、その後、残りの部分が再帰的に検証されます。`S`まだ分​​割できます。 各ステップが考えられるすべてのカット長にわたって分岐し、大きな文字列内の部分文字列チェックによってコストが倍増するため、これはすぐに指数関数的になります。 

貪欲な直感が微妙に失敗するケースは、将来の実現可能性を考慮せずに、常に可能な限り長い有効なプレフィックスを取得するか、常に最短のプレフィックスを取得する必要があると仮定することです。 この制約はグローバルです。短いプレフィックスでは後のボックスが不可能になる可能性がありますが、長いプレフィックスでは有効な継続が維持される可能性があります。 辞書編集の目的では、慎重なバランスが求められます。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. の部分文字列かどうかを迅速にチェックできるようにする情報を事前計算します。`S`指定された場所に表示されます`T_i`。 標準的な方法は、すべての文字列のローリング ハッシュを計算し、部分文字列のハッシュ セットを保存することです。`T_i`必要な長さまで。 重要な部分は、「このプレフィックスは次の場所に存在しますか?」と答えることができることです。`T_i`」ほぼ一定の時間で。 
2. ポインタから始める`pos = 0`で`S`。 施工させていただきます`b_1`を通して`b_k`順次。 
3. ボックスごとに`i`から`1`に`k`、可能な限り小さいものを選択しようとします`b_i`。 から始めます`len = 0`そしてそれを増やします。 
4. 候補の長さごとに`len`かどうかを確認します。`S[pos:pos+len]`の部分文字列です`T_i`。 そうでない場合は、増加し続けます`len`。 最初の有効な`len`合格したものが次のように選択されます`b_i`。 
5.固定後`b_i`、私たちは前進します`pos += b_i`次のボックスに進みます。 
6. すべてのボックスを処理した後、`pos`等しい必要があります`|S|`、問題ステートメントによって解決策が存在することが保証されます。 

私たちが常に実行可能な最小のものを選択する理由`len`各ステップでは、辞書編集上の順序が比較されます。`b_1`まず、初期のポジションの増加がその後のすべての選択を支配します。 

### なぜ効果があるのか

 この構築は辞書順に貪欲に行われます。 ステップで`i`、すでに修正されていると仮定します`b_1 ... b_{i-1}`すべての有効な補完の中で可能な限り小さくなるようにします。 のために`b_i`、より大きな選択をすると、後の値に関係なく、辞書編集上の順序がすぐに悪化するため、実現可能性のみを考慮します。 

すべての実現可能な値の中で、`b_i`最小値を選択すると、残りのサフィックスが完成する可能性が保たれます。これは、この問題により、少なくとも 1 つの完全なパーティションが存在することが保証され、有効な解決策は、実現可能性を損なうことなく、以前のセグメントの長さを決して増加させない解決策に変換できるためです。 これは、前のセグメントを縮小すると、残りの文字が後のボックスに移動するだけであり、それぞれのセグメントが`T_i`制約はローカルで独立しているため、実現可能性は各セグメントが部分文字列として存在するかどうかのみに依存し、位置調整を超えた以前の消費パターンには依存しません。 

したがって、それぞれを貪欲に最小化すると、`b_i`in order は、辞書編集的に最小の有効なシーケンスを生成します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_hashes(s, base=91138233, mod=10**9+7):
    n = len(s)
    h = [0] * (n + 1)
    p = [1] * (n + 1)
    for i in range(n):
        h[i + 1] = (h[i] * base + (ord(s[i]) - 96)) % mod
        p[i + 1] = (p[i] * base) % mod
    return h, p

def get_hash(h, p, l, r, mod=10**9+7):
    return (h[r] - h[l] * p[r - l]) % mod

def solve():
    k, n = map(int, input().split())
    T = input().split()
    S = input().strip()

    hs, ps = build_hashes(S)

    # precompute substring hashes of S for fast prefix queries
    def s_hash(l, r):
        return get_hash(hs, ps, l, r)

    pos = 0
    res = []

    for i in range(k):
        t = T[i]
        ht, pt = build_hashes(t)

        # store all substring hashes of t
        seen = set()
        m = len(t)
        for l in range(m):
            cur = 0
            for r in range(l, min(m, l + len(S) + 1)):
                cur = (cur * 91138233 + (ord(t[r]) - 96)) % (10**9 + 7)
                seen.add(cur)

        best = 0
        # try smallest prefix length
        for length in range(len(S) - pos + 1):
            if s_hash(pos, pos + length) in seen:
                best = length
                break

        res.append(best)
        pos += best

    print(*res)

def main():
    t = int(input())
    for _ in range(t):
        solve()

if __name__ == "__main__":
    main()
```コードは現在の位置を維持します。`S`各ボックスを順番に処理します。 それぞれについて`T_i`、メンバーシップが次のプレフィックスをチェックするように、部分文字列ハッシュのセットを事前計算します。`S`すぐに答えることができます。 次に、プレフィックスの長さを小さいものから大きいものまでスキャンし、最初の実行可能なものを選択します。 

微妙な点は、現在のサフィックスのプレフィックスをチェックするだけでよいことです。`S`、すべての部分文字列ではありません。 これにより、異なる部分の結合を回避できます。`S`各ステップを独立させます。 

正確かどうかは、プレフィックスの長さが適切に機能するかどうかに依存します。`T_i`、それは直接定義します`b_i`、残りのサフィックスは次のボックスでも同様に処理されます。

 ## 特殊なケース

 重要なエッジ ケースは、多くの連続するボックスで空の部分文字列が許可される場合です。 このようなシナリオでも、アルゴリズムは、後の一致を有効にするために必要な場合にのみ文字を消費する必要があります。 貪欲スキャンは常に優先するため、これを確実にします。`b_i = 0`もし`""`は有効な部分文字列です`T_i`。
