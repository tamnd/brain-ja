 ## 解決策
 ## 問題の理解

 非常に大きな数直線上のセグメントのコレクションが与えられます。 各セグメントは、両端を含む、端点間のすべての整数点をカバーします。 異なるセグメントは任意の方法で重なり合う可能性があります。それらは、素になったり、入れ子になったり、同一になったり、部分的に交差したりする可能性があります。 

課題は、単一地点でのカバレッジを見つけることではなく、カバレッジの世界的な分布を理解することです。 k の考えられるすべての値について、正確に k 個のセグメントによってカバーされる整数位置の数を計算する必要があります。 

言い換えれば、数直線に沿ってスイープし、すべての整数座標で、その整数座標をカバーしているセグメントの数を数えることを想像すると、カウント 1 が生成される座標の数、カウント 2 が生成される座標の数、などを n まで知りたいとなります。 

制約は設計の選択を強制するものです。 最大 200,000 のセグメントと 10^18 ものエンドポイントがあるため、すべての整数点を明示的に検査する余裕はありません。 このスケールでは座標空間が実質的に制限されていないため、座標を反復するアプローチは直ちに実行不可能になります。 個々の点ではなく、適用範囲の変更という観点から推論する必要があります。 

一般的な障害モードは、座標を圧縮せずにポイントごとまたは単位間隔ごとのカバレッジをシミュレートしようとすることから発生します。 たとえば、セグメント [0, 3]、[1, 3]、[3, 8] の場合、すべての整数に対する単純なスイープはこの小さな入力で機能しますが、間隔が 10^18 に及ぶ場合は不可能です。 もう 1 つの微妙な間違いは、間隔を一貫性なく半開きとして扱うことです。 エンドポイントは包括的であるため、カバレッジは r ではなく l と r + 1 で正確に変化します。 

## アプローチ

 ブルートフォースのアイデアは簡単です。少なくとも 1 つのセグメント内にある整数座標ごとに、それをカバーするセグメントの数をカウントし、そのカウントによってインデックス付けされた周波数配列をインクリメントします。 概念的には、セグメントごとに、それがカバーするすべてのポイントをマークし、ポイントごとのグローバル カウンタを維持します。 

これは論理的には機能しますが、パフォーマンスではすぐに壊れます。 1 つのセグメントは最大 10^18 の整数にわたる可能性があるため、1 つの間隔でも不可能な作業が必要になる場合があります。 観察されたエンドポイントのみに限定しようとしても、カバレッジがイベント ポイント間でのみ一定であり、イベント ポイントでは必ずしも一定ではないという問題に依然として直面します。 

重要な観察は、カバレッジ数がセグメント境界でのみ変化するということです。 数直線上の 2 つの連続する「イベント位置」の間では、アクティブなセグメントの数は一定です。 したがって、すべての整数点について考えるのではなく、問題を範囲が変わらない範囲に圧縮します。 

これはスイープ ラインのアイデアにつながります。各セグメントを 2 つのイベントに変換します。1 つは l でカバレッジを増加させ、もう 1 つは r 以降でカバレッジを減少させます。 これらのイベントを並べ替えることで、行を昇順に処理し、現在のアクティブなセグメント数を維持できるようになります。 あるイベント位置から次のイベント位置に移動するたびに、セグメント数はギャップ全体にわたって固定されたままになるため、そのギャップの長さをそのカウントの答えに加算できます。 

これにより、問題はポイントごとのカウントから間隔ごとの集計に軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(合計カバーポイント) | O(1) から O(n) | 遅すぎる |
 | スイープライン | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各セグメントを 2 つの境界イベントに変換します。1 つはセグメント終了後にカバレッジを増加させ、もう 1 つはカバレッジを減少させます。 次に、これらのイベントを位置ごとに並べ替えます。 

実行中の変数を維持します`active`現在スイープ位置をカバーしているセグメントの数を表します。 また、ソートされたイベント位置を順番に繰り返し処理します。 

1. 各セグメント [l, r] を 2 つのイベントに変換します。l では +1 を追加し、r + 1 では -1 を追加します。 このエンコードにより、セグメントは r を通じて寄与し、r + 1 から寄与を停止するため、包含区間の正確性が保証されます。 
2. すべてのイベントを座標順に並べ替えます。 カバレッジの変更を左から右の順序で処理する必要があるため、並べ替えが必要です。 
3.初期化`active = 0`空の結果配列`ans`サイズ n + 1。 
4. 前の座標を追跡しながら、ソートされたイベントを反復処理します。`prev`。 個別の座標ごとに`x`、最初に次のセグメントを検討します。`prev`に`x - 1`。 この領域全体では、アクティブなセグメントの数は一定であるため、この範囲内のすべての整数点が寄与します。`ans[active]`。 
5. ギャップを考慮した後、すべての更新を座標に適用します。`x`、調整中`active`それに応じて。 
6. 移動`prev`に`x`そして続けます。 
7. すべてのイベントを処理した後、それ以上のギャップは残りません。 

重要な正確性のポイントは、イベントが発生しない安定した領域にのみカウントを割り当て、各整数ポイントが正確に 1 回、そしてその真のカバレッジ値で正確にカウントされることを保証することです。 

### なぜ効果があるのか

 スイープ ラインは、2 つの連続するイベント座標間でセグメントが開始または終了しないという不変条件を維持します。 したがって、アクティブなセグメントのセットは、その間隔全体にわたって一定です。 すべての整数点はまさに 1 つのそのような間隔に属し、その定数値を使用してその全長を計算するため、各点は正しい周波数バケットに 1 回だけ寄与します。 エンドポイントを +1 シフトすることで、境界で二重にカウントすることなく包括性が確実に処理されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    events = []
    
    for _ in range(n):
        l, r = map(int, input().split())
        events.append((l, 1))
        events.append((r + 1, -1))
    
    events.sort()
    
    ans = [0] * (n + 1)
    
    active = 0
    prev = None
    
    i = 0
    m = len(events)
    
    while i < m:
        x = events[i][0]
        
        if prev is not None and prev < x:
            length = x - prev
            ans[active] += length
        
        delta = 0
        while i < m and events[i][0] == x:
            delta += events[i][1]
            i += 1
        
        active += delta
        prev = x
    
    print(*ans[1:])

if __name__ == "__main__":
    solve()
```このソリューションは、セグメントのエンドポイントを差分配列スタイルのイベントにエンコードします。 重要な詳細は、デクリメント イベントに r + 1 を使用することです。これにより、包括的なカバレッジと半開間隔処理が調整されます。 並べ替えグループはすべて同じ座標で変更され、同じ位置にある中間状態がアクティブ カウントに誤って影響を与えないように、先に進む前にグループを集計します。 

ギャップの処理`length = x - prev`実際にカバレッジが蓄積される場所です。 これは整数点が「カウント」される唯一の場所であり、prev から x - 1 までのすべての整数を正しくカウントします。 

## 実用的な例

 ### 例 1

 入力:```
3
0 3
1 3
3 8
```私たちはイベントを構築します:

 (0, +1)、(4, -1)、(1, +1)、(4, -1)、(3, +1)、(9, -1)

 並べ替え:

 (0, +1)、(1, +1)、(3, +1)、(4, -2)、(9, -1)

 | ステップ | × | 前へ | | 前にアクティブ セグメントの長さ | 貢献 | | 以降にアクティブになります
 | --- | --- | --- | --- | --- | --- | --- |
 | 1 | 0 | - | 0 | - | - | 1 |
 | 2 | 1 | 0 | 1 | 1 | ans[1] += 1 | 2 |
 | 3 | 3 | 1 | 2 | 2 | ans[2] += 2 | 3 |
 | 4 | 4 | 3 | 3 | 1 | ans[3] += 1 | 1 |
 | 5 | 9 | 4 | 1 | 5 | ans[1] += 5 | 0 |

 最終的な答え:

 k=1→6、k=2→2、k=3→1

 このトレースは、カバレッジが整数ごとに明示的に計算されないことを示しています。 代わりに、イベント座標間の各安定領域は、その長さによって重み付けされた単一の寄与に圧縮されます。 

### 例 2

 入力:```
3
0 0
2 2
4 4
```イベント:

 (0, +1)、(1, -1)、(2, +1)、(3, -1)、(4, +1)、(5, -1)

 | ステップ | × | 前へ | アクティブ | 長さ | 貢献 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 0 | - | 0 | - | - |
 | 2 | 1 | 0 | 1 | 1 | ans[1]+=1 |
 | 3 | 2 | 1 | 0 | 1 | ans[0]+=1 (後で無視されます) |
 | 4 | 3 | 2 | 1 | 1 | ans[1]+=1 |
 | 5 | 4 | 3 | 0 | 1 | ans[0]+=1 |
 | 6 | 5 | 4 | 1 | 1 | ans[1]+=1 |

 k=0 を無視した場合、結果は次のようになります。 

k=1 → 3、k>=2 → 0

 これは、孤立点が連続する整数間の単位長間隔としてどのように動作するかを強調しています。

    input = sys.stdin.readline

    events = []
    for _ in range(n):
        l, r = map(int, input().split())
        events.append((l, 1))
        events.append((r + 1, -1))

    active = 0
    prev = None

            delta += events[i][1]
            i += 1
        active += delta
        prev = x

    return " ".join(map(str, ans[1:]))

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、セグメントが単一の点に縮退する場合です。 入力の場合:```
1
5 5
```イベントは (5, +1) と (6, -1) になります。 アルゴリズムは、区間 [5, 5] を 5 と 6 の間の単位長の寄与として扱います。アクティブ カウントはちょうどその区間で 1 になるため、ans[1] は 1 増加し、ちょうど 1 つの整数点がカバーされるという事実と一致します。 

複数のイベントが同じ座標を共有する場合、別のエッジ ケースが発生します。 例えば：```
2
1 3
3 5
```座標 3 では、1 つのセグメントが終了し、別のセグメントが開始されます。 先に進む前に各座標ですべてのデルタを集約するため、遷移はアトミックに処理されます。 間隔 [1, 3] に使用されたアクティブ カウントは正しく、次の間隔は中間的な破損のない更新されたアクティブ カウントで始まります。
