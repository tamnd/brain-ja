 ## 解決策

 ## 問題の理解

 サイクルを含む可能性のある無向接続グラフが与えられます。 2 つの特別な頂点を選択することができます。$s$そして$t$, グラフを見てから。 これらのエンドポイントが修正されたら、次のすべての単純なパスを考慮します。$s$に$t$。 通路（エッジ）は、そこから到達するあらゆる可能な方法がある場合に「クリティカル」であるとみなされます。$s$に$t$そのエッジを使用する必要があります。 目標は選択することです$s$そして$t$そのようなクリティカルエッジの数が最大化されるようにします。 

ここでのクリティカルエッジとは、まさにあらゆるものに存在するエッジのことです。$s$-に-$t$パス、つまり削除すると切断される$s$そして$t$。 したがって、固定ペアの場合$(s,t)$、これら 2 つの頂点を分離するという意味でブリッジであるエッジを数えます。 

制約は次のとおりです$3 \cdot 10^5$頂点とエッジ、つまりそれに近いもの$O(n^2)$あるいは$O(nm)$すぐには無理です。 線形または線形に近いグラフの走査が必要であり、どのソリューションもブリッジ ツリーや DFS ローリンク値などの構造分解に依存する必要があります。 

素朴なアプローチでは、すべてのペアを試します$(s,t)$、そのペアにとってどのエッジが避けられないかを計算し、最大値を取得します。 すでに失敗しています。$O(n^2)$ペア。 ペアを固定してパス構造上のブリッジを計算したとしても、$O(n+m)$、合計は$O(n^3)$最悪の場合。 

より微妙な問題は、サイクルのあるグラフに現れます。 たとえば、単純な三角形の場合、$1-2-3-1$、どのペアにもブリッジがまったくないため、答えはゼロです。 しかし、追加のサイクル エッジが 1 つあるほぼツリーのようなグラフでは、「ツリー エッジ」に関する単純な推論は、すべてのツリー エッジが常に適切な候補であると誤って仮定する可能性がありますが、これは誤りです。選択したエンドポイントに応じてサイクルが完全にバイパスできるためです。 

## アプローチ

 主な困難は、グラフ全体のブリッジを要求されるのではなく、選択した頂点のペアに関連するブリッジを要求されることです。 これは、グローバル ブリッジでは不十分であることを直ちに示唆しています。注目を特定のペアに限定すると、グラフ全体の非ブリッジ エッジでさえ避けられなくなる可能性があるからです。 

ブルートフォース手法で修正する$s$そして$t$次に、DFS ベースのブリッジ検索ロジックを実行し、エッジ間のすべてのパス上にどのエッジがあるかを判定します。 これは、各エッジを削除し、エッジ間の接続を確認することでシミュレートできます。$s$そして$t$、原価計算$O(m)$エッジごとに。 と$m$エッジと$O(n)$エンドポイントの選択肢が増えると、これは実現可能な限界をはるかに超えて爆発的に増加します。 

重要な観察は、視点をエッジから構造に移すことです。 最大の 2 エッジ接続コンポーネントをすべて 1 つのノードに圧縮すると、結果として得られる構造は、一般にブリッジ ツリーまたはブロック ツリーと呼ばれるツリーになります。 このツリーのすべてのエッジは、元のグラフではブリッジです。 元の 2 つの頂点間のパスは、このツリー内の対応するコンポーネント間の一意のパスに対応します。 したがって、間に避けられないエッジの数は、$s$そして$t$は、ブリッジ ツリー内のコンポーネント間のパス上のツリー エッジの正確な数です。 

したがって、問題は次のようになります。ブリッジ ツリーを構築し、その中で 2 つのノードを選択して、エッジの数に関してそれらの間の距離を最大化します。 それはまさに木の直径です。 

したがって、最適な戦略は、DFS ローリンク値を使用してすべてのブリッジを計算し、コンポーネントをコントラクトし、ツリーを構築し、2 つの BFS/DFS パスを使用してその直径を計算することです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(nm)$それより悪い |$O(n+m)$| 遅すぎる |
 | 最適(ブリッジツリー+直径) |$O(n+m)$|$O(n+m)$| 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは 3 つの概念的な段階に進みます。 

1. グラフに対して DFS を実行して、各頂点の検出時間と低リンク値を計算します。 エッジ$(u,v)$ローリンク値が次の場合に限り、ブリッジとしてマークされます。$v$の発見時間よりも厳密に大きいです$u$DFS ツリーのエッジを通過するとき。 これにより、どのサイクルにも属さないエッジが正確に識別されます。 
2. ブリッジ情報を使用して、2 番目の DFS または BFS を実行して、すべての頂点にコンポーネント ID を割り当てます。ただし、ブリッジ エッジをまたぐことは許可されません。 ブリッジを使用せずに接続された頂点の最大セットはすべて、新しい構造内の 1 つの収縮ノードになります。 
3. 各ノードがコンポーネントであり、すべてのブリッジが 2 つのコンポーネント間のエッジとなる新しいグラフを構築します。 このグラフはツリーであることが保証されています。 
4. この木の直径を計算します。 任意のノードを選択し、BFS を実行して最も遠いノードを見つけ、その最も遠いノードから再度 BFS を実行して最大距離を計算します。 この距離が答えです。 

直径が答えに対応する理由は、$s$そして$t$元のグラフでは、ブリッジ ツリーで 2 つのコンポーネントを選択することと同じであり、それらの間の一意のパス上のすべてのエッジは、元のグラフで使用する必要があるブリッジになります。 

機能する理由: 元のグラフのすべてのサイクルは、単一の縮小コンポーネント内に完全に含まれているため、コンポーネント内のエッジは、コンポーネントの異なる部分にある 2 つの頂点間で避けられません。 強制エッジはコンポーネント レベルでグラフを切断する必要があり、これがまさにブリッジ エッジを表します。 縮小すると、構造はツリーになり、ツリー内の最も長い単純なパスにより、エンドポイント間のすべてのルートに必須のエッジの数が最大になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

n, m = map(int, input().split())
g = [[] for _ in range(n)]

edges = []
for i in range(m):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    g[u].append((v, i))
    g[v].append((u, i))
    edges.append((u, v))

tin = [-1] * n
low = [-1] * n
timer = 0
is_bridge = [False] * m

def dfs(u, pe):
    global timer
    tin[u] = low[u] = timer
    timer += 1
    for v, ei in g[u]:
        if ei == pe:
            continue
        if tin[v] == -1:
            dfs(v, ei)
            low[u] = min(low[u], low[v])
            if low[v] > tin[u]:
                is_bridge[ei] = True
        else:
            low[u] = min(low[u], tin[v])

dfs(0, -1)

comp = [-1] * n
cid = 0

def dfs2(u, c):
    stack = [u]
    comp[u] = c
    while stack:
        x = stack.pop()
        for y, ei in g[x]:
            if comp[y] == -1 and not is_bridge[ei]:
                comp[y] = c
                stack.append(y)

for i in range(n):
    if comp[i] == -1:
        dfs2(i, cid)
        cid += 1

tree = [[] for _ in range(cid)]
for i, (u, v) in enumerate(edges):
    if is_bridge[i]:
        cu, cv = comp[u], comp[v]
        tree[cu].append(cv)
        tree[cv].append(cu)

def bfs(start):
    from collections import deque
    dist = [-1] * cid
    dist[start] = 0
    dq = deque([start])
    far = start
    while dq:
        x = dq.popleft()
        for y in tree[x]:
            if dist[y] == -1:
                dist[y] = dist[x] + 1
                dq.append(y)
                if dist[y] > dist[far]:
                    far = y
    return far, dist[far]

if cid == 1:
    print(0)
else:
    a, _ = bfs(0)
    _, ans = bfs(a)
    print(ans)
```ローリンク値を使用する DFS は、すべてのブリッジ エッジを線形時間で計算します。 2 番目の DFS は、2 つのエッジで接続された各領域を圧縮し、コンポーネントを割り当てるときにブリッジを通過しないようにします。 結果のグラフにはブリッジ エッジのみが含まれ、ツリーが形成されます。 BFS ルーチンは、2 つのパスでこのツリーの直径を計算します。 

微妙な点は、再帰の深さが Python のデフォルトの制限を超える可能性があるため、制限を増やす必要があることです。 もう 1 つの詳細は、コンポーネントを形成するときにブリッジ エッジが使用されないようにすることです。 そうしないと、縮小されたグラフにサイクルが誤って表示されてしまいます。

 ## 特殊なケース

 次のような純粋なサイクルでは、$1-2-3-1$、すべての頂点は、単一の 2 エッジ接続コンポーネント内にあります。 ブリッジ検出ではエッジがマークされないため、縮小されたグラフには 1 つのノードがあり、BFS はゼロを返します。これは、どのペア間にもエッジが避けられないという事実と一致します。 

木ではすべての端が橋です。 ブリッジ ツリーは元のグラフと等しいため、アルゴリズムはツリーの直径を計算することになります。 BFS は、エンドポイントの選択に対応する最長パスを正しく検出します。$s$そして$t$最も遠い 2 つの葉として。 

尾部のあるサイクルなどの混合グラフでは、尾部のエッジのみがブリッジになります。 コンポーネントの圧縮により、直径の計算前にサイクルが崩壊することが保証され、エンドポイント間で実際には避けられない内部サイクル エッジの過剰カウントが防止されます。
