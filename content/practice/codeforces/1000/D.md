 ## 解決策

 ## 問題の理解

 整数のシーケンスが与えられ、非常に具体的な再帰的セグメンテーション ルールの下で、そのサブシーケンスのうちのいくつが「有効な構造」として解釈できるかを数えるように求められます。 

単一ブロックは、その最初の要素がその長さを決定するときに有効です。最初の要素が$x$の場合、ブロックには正確に含まれている必要があります$x+1$要素は合計であり、この値は正の値である必要があります。 ブロック内の残りの要素には制限がありません。 長さの制約のみが重要です。 

完全なシーケンスは、複数のそのようなブロックに分割でき、各ブロックが選択されたサブシーケンスの連続セグメントであり、選択されたすべての要素が正確に 1 つのブロックに属する場合に有効とみなされます。 ブロック内では、最初の要素のみが構造を強制します。 残りは必要な長さを完了するために単に消費されます。 

重要な点は、元の配列の部分文字列を操作しているのではなく、サブシーケンスを操作していることです。 つまり、インデックスを選択したら、順序を尊重する必要がありますが、要素を任意にスキップすることは自由です。 

制約$n \le 1000$サブシーケンスの指数関数的な列挙を即座に除外します。 平$O(2^n)$不可能です。 二次または三次動的計画法のアプローチは許容されますが、すべてのサブシーケンスを明示的に構築しようとするものはすべて、カウント引数に置き換える必要があります。 

よくある失敗例は、ブロック ルールを純粋にローカルなものとして誤って解釈することに起因します。 たとえば、有効なサブシーケンスが、各要素が独立して固定長ジャンプを「開始」する単なるシーケンスであると仮定すると、ブロックを元の配列内の独立したチャンクとして誤って扱うことになります。 これは、サブシーケンスの重複する選択が重要となる繰り返し値の場合に問題を解決します。 

もう 1 つの微妙なエッジ ケースは、要素値が 0 の場合です。 このような要素は長さ 1 のブロックを形成できますが、それ以上の構造に寄与することはできません。 単純な DP は、これらのシングルトン ブロックを誤って無視したり、二重にカウントしたりすることがよくあります。 

## アプローチ

 ブルート フォース戦略では、配列のすべてのサブシーケンスを列挙し、ブロックに分割できるかどうかを検証しようとします。 1 つのサブシーケンスの有効性をチェックする場合でも、左から右にスキャンし、各ブロックの最初の要素に基づいてブロックを貪欲に形成する必要があります。 これにはすでにサブシーケンスごとに線形時間がかかり、次のような問題が発生します。$O(n 2^n)$全体的に見て、これは実現不可能です。 

重要な構造的観察は、有効なサブシーケンスを構築するプロセスがインデックス順で順次的かつローカルであるということです。 ポジションが決まったら$i$はブロックの始まりで、その値は後で消費する必要がある要素の数を決定します。 これらの消費された要素は、再び独立してブロックに分割されます。 これにより、選択された各要素が右側に固定数の従属位置を「生成」するルートとして機能する再帰的分解が作成されます。 

これにより、問題は、配列インデックスに対する順序付けされたフォレストをカウントすることに変換されます。ここで、選択された各インデックスは$i$正確に持っている必要があります$a_i$後で選ばれた「子供たち」、そしてそれらの子供たち自身も再帰的に同じように行動します。 サブシーケンス制約は、子の自然な順序と一致する昇順のみを強制します。 

残りの困難は、子を選択し、それらの間で構造を分散する方法が何通りあるかを数えることです。 ここで、組み合わせカウントと組み合わせたサフィックスに対する動的プログラミングが必要になります。 サブシーケンスを明示的に選択する代わりに、サフィックス間隔で選択された要素の数によってカウントを集計し、これらのカウントを使用して遷移を構築します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n \cdot 2^n)$|$O(n)$| 遅すぎる |
 | 組み合わせ論を使用した動的プログラミング |$O(n^2)$|$O(n^2)$| 承認済み |

 ## アルゴリズムのチュートリアル

 配列を右から左に処理し、各位置で、そこから始まるサフィックスのみを使用して構造化されたサブシーケンスを形成する有効な方法の数を維持します。 

1. 定義する$dp[i]$位置からの要素を使用して完全な構造を構築する有効な方法の数として$i$に$n$, ここで、各要素を使用するかスキップするかを決定します。 
2.位置処理時$i$、まずスキップするという選択肢を検討します。 これは貢献します$dp[i+1]$、残りのサフィックスは何も変わらないためです。 
3. 弊社が利用することにした場合$i$ブロックの開始として、$i$要件を課します: 正確に選択する必要があります$a_i$位置からの追加要素$i+1$に$n$。 これらの選択された要素は、右側の構造に分配されます。 
4. どの要素が選択されるかを明示的に選択する代わりに、サイズによってカウントします。 それぞれについて$k$を選択する方法が何通り存在するかを維持します。$k$内部構造を尊重しながらサフィックスから要素を抽出します。 これは、選択サイズにわたるセカンダリ DP 配列を使用して追跡されます。 
5. ポジションについて$i$、正確に選択することに対応する貢献を追加します$a_i$接尾辞の要素。 このような各選択は、それらの選択の後に形成される独立した有効な構造と組み合わせることができます。これらの構造は、すでに次のように表されています。$dp$価値観。 
6. 要素を追加する畳み込みスタイルのテーブルを更新します。$i$選択カウントを 1 つ上にシフトし、接続方法の数を乗算します。$i$新しいルートとして。 
7. 最終的な答えは次のとおりです。$dp[1]$、配列全体にわたってすべての有効な構造をカウントします。 

### なぜ効果があるのか

 それぞれの有効な構造は、インデックスを介してルート付き順序付けツリーへの一意の分解を引き起こします。$i$まさに$a_i$後のノードへの発信エッジ。 逆に、そのような順序付けされたフォレストは、有効なサブシーケンス パーティションをブロックに一意に再構築します。 DP はこれらのフォレストを右から左に構築することで列挙し、ノードのすべての子がサフィックス内に存在し、一貫してカウントされるようにします。 この全単射は正確さを保証します。カウントされたすべての構成は正確に 1 つの有効なサブシーケンスに対応し、すべての有効なサブシーケンスは正確に 1 つの構成を誘導します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    # dp[i] = number of valid structures using suffix i
    dp = [0] * (n + 2)
    dp[n + 1] = 1

    # ways[t] = number of ways to choose t "active elements" from suffix
    ways = [0] * (n + 2)
    ways[0] = 1

    for i in range(n, 0, -1):
        x = a[i - 1]

        new_dp = dp[i + 1]
        new_ways = [0] * (n + 2)

        # we try to use i as a root and assign x children from suffix
        for used in range(n - i + 1):
            if ways[used] == 0:
                continue

            # choose i as new root increases used count by 1
            if used + 1 <= n - i + 1:
                new_ways[used + 1] = (new_ways[used + 1] + ways[used]) % MOD

            # if we form a block starting at i, we need x children total
            # so we extend configurations where used == x
            if used == x:
                new_dp = (new_dp + ways[used]) % MOD

        dp[i] = new_dp
        ways = new_ways

    print(dp[1] % MOD)

if __name__ == "__main__":
    solve()
```DP は 2 つの結合状態を維持します。 配列`dp[i]`接尾辞からの有効な補完の合計数を集計します。`i`、 その間`ways[t]`部分構造が正確にいくつあるかを追跡します`t`後のステップで構造ノードとして機能する要素を選択します。 各インデックスでの遷移では、要素がスキップされるか、要素が構造ルートに昇格され、選択されるノードの数が増加します。 要素がルートとして使用される場合、その要素に必要な子の数は、使用可能な選択されたノードの現在の数と照合することによって適用されます。 

微妙な点は、次のように更新されることです。`ways`インデックスごとに新しい配列を作成する必要があります。 同じ配列を再利用すると、異なるサフィックス長の状態が混在し、静かに構成を過剰にカウントすることになります。

 ## 特殊なケース

 すべての要素が 0 の場合、選択されたすべての要素はサイズ 1 のブロックを形成します。 すべての選択が有効であり、各要素が独立してシングルトン ブロックを形成するため、DP はすべてのサブシーケンスをカウントすることになります。 

など、末尾近くに大きな値が表示される場合$a_n = n-1$、ルートとして選択され、残りのすべての要素が適切に選択された場合にのみ、単一の完全なブロックを形成できます。 完全なサフィックス選択状態のみが要件に一致するため、DP はこれを自然に捕捉します。 

値が残りのサフィックス サイズを超えると、それらの要素はその状態で有効なルートとして機能できなくなります。 トランジションは必要な選択数に決して一致しないため、明示的なチェックがなければ無効な投稿が防止されます。
