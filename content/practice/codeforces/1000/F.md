 ## 解決策
 ## 問題の理解

 静的配列と多くの独立したクエリが与えられます。各クエリは、配列の連続セグメントを検査し、そのセグメント内に 1 回だけ出現する値を返すように求めます。 そのセグメントにそのような値が存在しない場合、答えはゼロになります。 

各クエリについて考えるのに役立つ方法は、配列のウィンドウを取得し、そのウィンドウ内のすべての個別の値を頻度によって分類することです。 このタスクは、頻度をグローバルにカウントすることではなく、選択した間隔内で少なくとも 1 つの値が頻度を正確に 1 つ持つかどうかを検出し、そうであればそれらの値のいずれかを返すことです。 

この制約により、クエリごとに周波数を最初から再計算する必要がなくなります。 最大 500,000 個の要素と 500,000 個のクエリがある場合、各クエリ範囲をスキャンするだけでも、最悪の場合、およそ 10^11 の操作が必要になります。これは、Python または C++ で処理できる 3 秒の制限をはるかに超えています。 

重要なエッジケースは、セグメント内のすべての要素が少なくとも 2 回繰り返される場合です。 For example, in the segment`[1, 1, 2, 2]`、複数の値が表示されても有効な答えは存在しません。 もう 1 つの微妙なケースは、配列全体に多数の一意の値が存在するが、クエリ間隔によってそれらがカットされ、その間隔内で単一の値が何も残らない場合です。 

単純な間違いは、グローバル頻度を事前に計算し、グローバルな一意性がローカルな一意性を意味すると仮定することです。 たとえば、`[1,2,1]`、 価値`2`グローバルに一意ですが、クエリ内にあります`[1,1,2]`、ウィンドウによって状況が変わります。 グローバルな頻度では十分ではありません。 

もう 1 つのよくある落とし穴は、クエリごとにスライディング ウィンドウを独立して維持しようとすることです。 クエリは任意であり、オフラインで順序付けされていないため、より高度なクエリ順序付け技術を適用しない限り、一貫した償却構造は得られません。 

## アプローチ

 直接的なアプローチでは、ハッシュ マップまたは配列を使用して各クエリ間隔の頻度を計算します。 これは正しいです。文字通り、範囲内の出現をカウントし、カウントが 1 つだけの値を選択するからです。 ただし、各クエリのカウントを再計算するには、クエリごとに最大 O(n) のスキャンが必要となり、合計で O(nq) の複雑さになりますが、これは実行不可能です。 

問題の構造は、グローバル情報を前処理し、クエリ全体で再利用する必要があることを示唆しています。 重要な観察は、値が最も近い値に出現することによってのみ有効な答えとなるということです。 位置ごとに、同じ値の前後の出現場所がわかれば、その位置が特定の間隔内で唯一の出現であるかどうかを判断できます。 

具体的には、インデックス i は、その範囲内でその値が唯一出現する場合、クエリ [l, r] に対する有効な応答となります。 つまり、前回の出現は厳密に l より前であり、次の出現は厳密に r の後にあります。 したがって、各クエリは、これら 2 つの境界条件を満たす [l, r] 内のインデックス i を見つけることになります。 

O(n) で前後の出現配列を事前計算できますが、残りの課題は、両方のエンドポイントに依存する条件の範囲クエリに効率的に応答することです。 ここで、セグメント ツリーまたはバイナリ インデックス構造と組み合わせたクエリに対する分割統治が自然になります。各位置を候補の有効性ウィンドウに寄与するものとして扱い、有効なインデックスが範囲内に存在するかどうかをクエリします。 

これを実装するきれいな方法は、クエリ エンドポイント制約ごとに「アクティブ化時間」の昇順に位置を処理することですが、この問題のより標準的な解決策は、オフラインの分割統治です。クエリを中間点で再帰的に分割し、中間点を越える有効な出現を追跡する構造を維持し、各位置が O(log n) レベルで考慮されるようにします。 

代わりに、よりシンプルで標準的な CF ソリューションを使用できます。次の出現境界によって決定される候補「一意の出現」に対するフェンウィック ツリーを維持しながら、右端点を増加させることで位置を処理します。 各インデックス i は、クエリに対して現在有効である場合、位置 i の重み 1 に寄与し、存在を検出するために範囲合計クエリをサポートします。 

これにより、各インデックスを範囲アクティブ化間隔に変換し、アクティブなインデックスがクエリ範囲内にあるかどうかを回答するという問題が軽減されます。

 ## アルゴリズムのチュートリアル

1. すべての位置 i について、a[i] の前の出現インデックスを計算します。 存在しない場合は、0 を保存します。これにより、値がどこまで左にあるかを繰り返す前に知ることができます。 
2. a[i] の次の出現インデックスを計算します。 存在しない場合は、n+1 を格納します。 これにより、値が繰り返される前に、値が一意のままであることがわかります。 
3. 位置 i は、prev[i] < l ≤ i ≤ r < next[i] を満たす任意の区間 [l, r] 内の値の一意の代表であることに注目してください。 これにより、周波数条件が間隔にわたる幾何学的条件に変換されます。 
4. 各インデックス i をクエリ空間上のアクティベーション四角形として解釈します。これは、左エンドポイントが (prev[i], i] にあり、右エンドポイントが [i, next[i]) にあるすべてのクエリに対して有効です。 四角形を明示的に列挙することはありません。 代わりに、1 次元にわたるスイープを使用します。 
5. クエリを適切なエンドポイントで並べ替えます。 右境界制約 r < next[i] に関して現在有効なインデックスの構造を維持しながら、右端点の昇順で位置を処理します。 
6. ポジション全体にわたってフェンウィック ツリーまたはセグメント ツリーを維持します。 位置 i を処理するとき、位置 i を構造体のインデックス i に挿入し、next[i] での削除もスケジュールします。これにより、将来のクエリの一意の要素として機能できなくなると非アクティブになります。 
7. 各クエリ [l, r] について、r までの処理後、[l, r] にわたる範囲の合計をクエリします。 合計が正の場合、その範囲内で値 1 を持つインデックスを検索し、その a[i] を出力します。 それ以外の場合は 0 を出力します。 

主要な実装の詳細は、ツリーが現在有効な候補であるインデックスを格納し、有効性が完全に次回出現の制約によって定義されるのに対し、重複する競合位置で重複が同時にアクティブになることはないため、クエリは構築によって暗黙的に前の出現の正確性を保証することです。 

### なぜ効果があるのか

 各値は、出現順にソートされた、互いに素なインデックスのチェーンに表示されます。 アルゴリズムは常に、次の重複の前に境界付けられたセグメント内で一意の出現となる資格がある値ごとに 1 つの代表を正確に保持します。 インデックス i がアクティブな場合、次の出現境界までセグメント内に同じ値が他に出現しないことが保証されます。 したがって、アクティブな代表を 1 つだけ含むクエリは、その間隔内で 1 回だけ発生する値に対応し、そのような代表はすべて有効な回答になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    q = int(input())

    nxt = [n] * n
    prv = [-1] * n

    last = {}
    for i in range(n):
        v = a[i]
        if v in last:
            prv[i] = last[v]
        last[v] = i

    last.clear()
    for i in range(n - 1, -1, -1):
        v = a[i]
        if v in last:
            nxt[i] = last[v]
        last[v] = i

    queries = []
    for i in range(q):
        l, r = map(int, input().split())
        queries.append((r - 1, l - 1, i))

    queries.sort()

    bit = [0] * (n + 2)

    def add(i, v):
        i += 1
        while i <= n:
            bit[i] += v
            i += i & -i

    def sum_(i):
        s = 0
        i += 1
        while i > 0:
            s += bit[i]
            i -= i & -i
        return s

    def range_sum(l, r):
        if l > r:
            return 0
        return sum_(r) - sum_(l - 1)

    # active positions by next boundary
    buckets = [[] for _ in range(n + 1)]
    for i in range(n):
        buckets[nxt[i]].append(i)

    active = [False] * n

    ptr = 0
    for r, l, idx in queries:
        while ptr <= r:
            for pos in buckets[ptr]:
                active[pos] = True
                add(pos, 1)
            ptr += 1

        if range_sum(l, r) == 0:
            print(0)
        else:
            lo, hi = l, r
            ans = 0
            while lo <= hi:
                mid = (lo + hi) // 2
                if range_sum(l, mid) > 0:
                    ans = mid
                    hi = mid - 1
                else:
                    lo = mid + 1
            print(a[ans])

def main():
    solve()

if __name__ == "__main__":
    main()
```最初の前処理パスのビルド`prv`、各値の最後の出現を追跡し、2 番目のビルドが行われます。`nxt`、次の発生を追跡します。 これらの配列は、インデックスがセグメント内で一意の代表として機能するかどうかを判断するために必要な唯一の情報です。 

フェンウィック ツリーは、次に出現するインデックスが現在の処理境界をまだ超えている一連のインデックスを維持します。 クエリの右ポインタを進めるたびに、その位置をすべてアクティブにします。`nxt[i]`は現在の位置と等しくなります。これらの位置は、その時点またはその前で終了するクエリの安全な候補となるためです。 

各クエリについて、フェンウィック ツリーの範囲合計により、候補が存在するかどうかが検出されます。 存在する場合、範囲にわたるバイナリ検索により 1 つの有効なインデックスが特定され、そのインデックスがその値に変換されます。 

プレフィックスの合計が正になると、右限界を拡張しても正の値を維持し、単調性が保証されるため、二分探索は安全です。

問い合わせ用`[2, 6]`、このウィンドウ内のアクティブな候補は、部分配列内に 1 回だけ出現する値に対応します。`[1, 2, 3, 2, 4]`。 以下の表に候補チェックを示します。 

| インデックス | 値 | 範囲内でアクティブ | 有効な貢献 |
 | --- | --- | --- | --- |
 | 1 | 1 | はい | いいえ (2 回表示されます) |
 | 2 | 2 | はい | いいえ (2 回表示されます) |
 | 3 | 3 | はい | はい |
 | 4 | 2 | はい | いいえ (重複は構造体によって処理されます) |
 | 5 | 4 | はい | はい |

このトレースは、正確さが、すべてを列挙するのではなく、少なくとも 1 つのアクティブなシングルトンを識別することに依存していることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n + q log n) | 各インデックスはフェンウィック ツリーに一度挿入され、各クエリは対数演算を実行します。

## 特殊なケース

 のようなケース`[7,7,7,7,7]`大域的な周波数だけでは不十分であることを示しています。 1 要素よりも長いサブ配列内で孤立したオカレンスがないため、すべてのインデックスは失敗します。 アルゴリズムは、各インデックスを配列内の次の出現箇所に割り当てることでこれを処理し、すべての位置を候補として即座に無効にします。 

単一要素配列の場合`[42]`、 両方`prv`そして`nxt`は範囲外であるため、インデックスは常にアクティブであり、インデックスに対するすべてのクエリはその値を返します。 

で`[1,2,1,2,1,2]`、すべての値は密にインターリーブされているため、1 よりも長い間隔内で唯一の出現であるという条件を満たすインデックスはありません。 フェンウィック ツリーは、意味のあるクエリ間隔に対してゼロ以外の範囲合計を蓄積することはなく、一貫してゼロを生成します。
