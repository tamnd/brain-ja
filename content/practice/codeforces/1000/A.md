 ## 問題の理解

 T シャツ サイズの 2 つのマルチセットが与えられ、それぞれのサイズが$n$。 最初のマルチセットは昨年印刷されたラベルを表し、2 番目は今年のターゲット構成を表します。 各リスト内の順序は重要ではなく、各正確な文字列が何回出現するかだけが重要です。 

文字列内の単一の文字を繰り返し選択し、それを任意の大文字のラテン文字に置き換えることによって、昨年のリストを変更することができます。 このような 1 文字の変更には 1 秒かかります。 文字を挿入したり削除したりすることはできないため、最終的な文字列はすべて元の長さを維持する必要があります。 

タスクは、最小の文字置換総量で最初のマルチセットを 2 番目のマルチセットに変換することです。 

制約$n \le 100$これは、それぞれが非常に短い文字列 (「XS」、「XXXL」などの T シャツのサイズ) を最大 100 個扱うことを意味します。 これは、すべてのペアにわたる二次比較ですら小さいことをすぐに示唆していますが、問題の構造により、さらに単純なことが可能になります。文字列の位置ではなく、文字列間の一致数のみを考慮します。 

素朴な誤解は、これをシーケンスのアライメントの問題として扱ったり、リストの順序で貪欲に変換をシミュレートしようとしたりすることです。 リストには順序がないため、これは失敗します。そのため、マルチセット全体にわたってペアリングを最適に選択する必要があります。 

複数の同一のソース文字列が異なるコストの異なるターゲット文字列と一致する場合、微妙なエッジ ケースが発生します。 たとえば、複数の「XS」があり、「S」と「XXS」の両方が必要な場合、不注意な固定ペアリング戦略により、次善の方法でそれらが割り当てられる可能性があります。 正しいソリューションでは、ローカルではなくグローバルにコストを最小限に抑える必要があります。 

## アプローチ

 強引なアイデアは、各ソース文字列をターゲット文字列に割り当て、一方を他方に変換するコストを計算し、その後、可能なすべての一致を試みることです。 これは、両側がサイズを持つ重み付けされた 2 部マッチング問題になります。$n$。 すべての順列を単純に列挙すると、次のようになります。$n!$可能性があり、順列ごとの計算コストさえも$O(n)$、につながる$O(n! \cdot n)$、でもそれは不可能です$n = 20$。 

重要な観察は、文字列のアイデンティティが小さく、構造化されていることです。 有効なサイズ パターンは少数しかなく、あるサイズを別のサイズに変換するコストは、文字ごとの不一致によってのみ決まります。 個々の文字列について考えるのではなく、各サイズのカウントを集計し、最初のマルチセットの余剰文字列を 2 番目のマルチセットの不足文字列と照合します。 

これにより、問題は過剰な発生のバランスをとることに変わります。 サイズごとに、最初のリストに 2 番目のリストよりも頻繁に出現する場合、余分な文字列が発生します。 出現が少ない場合は、需要に貢献します。 次に、余剰文字列と需要文字列を組み合わせます。2 つの文字列間のコストは、単純にそれらのハミング距離になります。 

以来$n \le 100$、黒字グループと赤字グループの間のすべてのペアごとの変換コストを計算し、最初に最小コストを貪欲に一致させることができます。これは、各文字列変換が独立しており、操作間に共有構造がないため最適です。

 ## アルゴリズムのチュートリアル

 1. 両方のリストで各サイズの出現数を数えます。 

これにより、問題は順序依存から頻度比較に変換されます。これは、リストがマルチセットであるため有効です。 
2. サイズごとに、ソース数とターゲット数の差を計算します。 

正の値は、他の型に変更する必要がある余剰文字列を表します。 負の値は、必要な文字列が欠落していることを表します。 
3. 2 つのリストを作成します。1 つはすべての余剰文字列を含み、もう 1 つはすべての必須文字列を含みます。 

変換コストを測定できるように、カウントを実際の文字列に明示的に展開します。 
4. すべての余剰文字列とすべての必要な文字列について、一方を他方に変換するコストを、異なる文字の数として計算します。 

これは、必要な交換の数を反映しています。 
5. 現在利用可能な最も安価な変換を常に選択することで、余剰文字列と必要な文字列を貪欲にペアリングします。 

各ペアリングは、ローカル コストを最小限に抑えながら、マルチセット間の 1 つの不一致を解決します。各文字列は 1 回だけ使用されるため、この貪欲な選択によって競合が発生することはありません。 
6. 選択したすべてのペアの合計コストを累積します。 

### なぜ効果があるのか

 各操作は 1 つの文字列を独立して変更し、変換間に相互作用はありません。 特定の余剰文字列が特定のターゲット文字列になる必要があると決定すると、コストは固定され、他の割り当てとは独立します。 問題は、2 つの同じサイズのセット間で一致する最小コストを見つけることに帰着します。$n \le 100$、すべてのペアごとのコストを評価し、最小コストで貪欲にペアリングすることで、より複雑なマッチング機構を必要とせずに最適性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def dist(a, b):
    # compute number of differing positions
    m = len(a)
    return sum(a[i] != b[i] for i in range(m))

n = int(input())
a = [input().strip() for _ in range(n)]
b = [input().strip() for _ in range(n)]

from collections import defaultdict

ca = defaultdict(int)
cb = defaultdict(int)

for x in a:
    ca[x] += 1
for x in b:
    cb[x] += 1

surplus = []
need = []

for k in set(list(ca.keys()) + list(cb.keys())):
    if ca[k] > cb[k]:
        surplus.extend([k] * (ca[k] - cb[k]))
    elif cb[k] > ca[k]:
        need.extend([k] * (cb[k] - ca[k]))

costs = []
for i in range(len(surplus)):
    for j in range(len(need)):
        costs.append((dist(surplus[i], need[j]), i, j))

costs.sort()

used_i = set()
used_j = set()
ans = 0

for c, i, j in costs:
    if i not in used_i and j not in used_j:
        used_i.add(i)
        used_j.add(j)
        ans += c

print(ans)
```コードはまず入力を周波数マップに圧縮し、次に不一致の項目のみを抽出します。 ネストされたループは、余剰文字列と必要な文字列の間で考えられるすべてのペア コストを構築します。 これらのコストをソートし、有効なペアを貪欲に選択することで、完全な 2 部グラフにわたる最小コストのマッチングが実装されます。 

セット`used_i`そして`used_j`各文字列が 1 回だけ使用されるようにして、無効な再利用を防ぎます。 以来$n \le 100$、$O(n^2 \log n)$選別ステップは完全に安全です。

 ## 特殊なケース

 エッジ ケースの 1 つは、複数の同一の文字列が両側に存在するが、必要なパートナーが異なる場合です。 たとえば、複数の同一の「XS」文字列を異なるターゲット サイズに変換する必要がある場合があります。 アルゴリズムは、一致プロセスで各出現を個別のノードに拡張することでこれを処理するため、各コピーは独立して処理されます。 

もう 1 つのケースは、すべての弦の周波数がすでにバランスされているものの、構造が内部的に一致していない場合です。 カウントが一致した場合でも、アルゴリズムはペアごとの変換コストを正しく計算し、頻度が等しいことが誤ってゼロコストを意味しないことを保証します。 

最後に、一方の側のみに余剰エントリがある場合、ペアリングはすべての余剰文字列とすべての必須文字列の間の直接一致に縮退します。 すべての要素は 1 回だけ使用する必要があり、個別の不一致を最小限に抑える以外に総コストを削減できる代替構造がないため、貪欲な選択は引き続き機能します。
