 ## 解決策
 ## 問題の理解

 正の整数の配列が与えられます。 2 人のプレイヤーが交互にターンを行い、各ターンでプレイヤーは非常に具体的なリダクション操作を実行します。つまり、素数を選択します。$p$次に、そのセグメント内のすべての数値が で割り切れるように、配列の連続したセグメントを選択します。$p$。 そのセグメント内のすべての要素について、次のように繰り返し分割します。$p$で割り切れなくなるまで$p$。 この操作の後、一部の要素は縮小しますが、配列の構造は同じ長さのままです。 

プレイヤーが有効な動きを行えなかった場合、ゲームは終了します。 課題は、最適なプレイの下で最初のプレーヤーと 2 番目のプレーヤーのどちらが勝利戦略を持っているかを判断することです。 

重要な視点の変化は、配列が再配置または削除されないことです。 代わりに、移動するたびに、連続したブロック全体で選択された素数の素指数構造が減少します。 したがって、ゲームの状態は各要素の残りの素指数によって完全に決定されます。 

制約の長さは比較的小さいですが、$n \le 1000$、ただし、値は次のように大きくすることができます。$10^{18}$。 これにより、すべての動きの中で因数分解を繰り返しシミュレートしたり、割り算を動的に再計算したりするアプローチは即座に除外されます。 どのような解法でも、各数値を最大 1 回因数分解してから、構造を組み合わせて推論する必要があります。 

微妙なエッジ ケースは、単一の要素が異なる素数にわたる複数のセグメントに関与する可能性があるという事実から生じます。 たとえば、要素が 2 と 3 の両方で割り切れる場合、その要素は 2 が関与する動きと 3 が関与する動きに独立して寄与しますが、ゲームの異なるターンに影響します。 各要素を「残りの値」を持つ単一のトークンとして扱う単純なアプローチでは、この独立性が欠けています。 

もう 1 つの注意が必要な状況は、すべての数値が 1 つの素数のべき乗である場合です。 その後、すべての動きでその素数の使用が強制され、ゲームはセグメントに沿ってパワーを繰り返し剥がすことになります。 数値が素数であるか合成であるかを追跡するだけの不注意なアプローチは、利用可能な手の数が素数ではなく指数の数に依存するため、ここでは失敗します。 

## アプローチ

 この強引なアイデアは、ゲームの状態を直接シミュレートすることです。 配列内に現れるすべての素数を繰り返し列挙し、各素数についてすべての有効なセグメントを試し、除算を適用し、再帰します。 これは、考えられるすべてのゲーム状態を探索するため、原理的には正しいですが、組み合わせによって爆発的に変化します。 たとえ$n = 1000$、それぞれの動きは多くの分岐を生み出す可能性があり、次のような数があるため、ゲームの奥深さは大きくなる可能性があります。$10^{18}$繰り返される素因数が多数含まれる場合があります。 状態の数は、実現可能な制限を超えて増加します。 

重要な洞察は、整数の観点から考えるのをやめ、代わりに位置ごとの素指数に焦点を当てることです。 各要素$a_i$は素数の積として分解でき、各素数は独立して動作します。 動きは素数を選ぶ$p$とセグメントを計算し、次の指数を減少させます。$p$そのセグメントのすべての要素で。 これは、素数ごとに、事実上バイナリのような構造上で個別のゲームを行っていることを意味します。つまり、連続するセグメント全体にその素数を何回「適用」できるかということです。 

ここで重要な観察は、それぞれの最大セグメントには素数が存在するということです。$p$は独立した貢献を形成します。 固定素数を見てみると$p$、配列内のいくつかの互いに素な間隔に現れます。 このような各間隔内で、演算を適用できる回数は、正確に次の指数の合計です。$p$ただし、強力な構造的制約があります。各操作は、選択されたサブセグメント全体でその間隔の 1 つの「レイヤー」を消費します。 

これにより、ゲームは既知のパターンに縮小されます。素数ごとに、各出現がセグメントにわたる操作のスタックに寄与し、最終的な結果は、最適なプレイの下で、すべての素数にわたるそのような独立した「手」の合計数が奇数か偶数かによってのみ決まります。 これにより、問題は、指数分布に対する素数ごとのグランディのようなパリティ寄与の計算に変換されます。 

私たちは問題を効果的に、独立した素数セグメント演算がいくつ存在するかを数えるということに帰着させます。 このような各操作はゲーム価値への 1 の貢献に対応し、勝者は合計カウントが奇数かどうかによって決まります。

 ## アルゴリズムのチュートリアル

 まず、配列内のすべての数値を因数分解します。 以来$a_i \le 10^{18}$までのトライアル分割を使用します。$\sqrt{a_i}$、または利用可能な場合は事前に計算された素数を使用し、すべての素数べき乗を抽出します。 

素数ごとに$p$、配列全体で指数値としてどのように表示されるかを追跡します。 シーケンスを構築します$e_1, e_2, \dots, e_n$、 どこ$e_i$の指数です$p$で$a_i$。 

次に、このシーケンスを最大の連続セグメントに圧縮します。$e_i > 0$。 このような各セグメント内で、指数の合計を計算します。 指数の各単位は、一部のセグメント操作にわたる 1 つの潜在的な「レイヤー除去」に対応するため、このセグメントによって寄与される独立したアクションの総数はその合計に等しくなります。 

この寄与をすべての素数にわたって累積します。 

最後に、そのような操作の合計数のパリティを計算します。 これがゼロ以外で奇数の場合、最初のプレイヤーが勝ちます。 それ以外の場合は、2 番目のプレーヤーが勝ちます。 

これが機能する主な理由は、異なる素数に対する操作が決して相互作用しないことです。 動きは正確に 1 つの素数を修正し、他のすべてとは独立してその指数を減少させるため、ゲームは単位操作ごとにグランディ値がすべて 1 である独立したサブゲームに分解されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import defaultdict
import math

def factorize(x, primes):
    res = defaultdict(int)
    for p in primes:
        if p * p > x:
            break
        while x % p == 0:
            res[p] += 1
            x //= p
    if x > 1:
        res[x] += 1
    return res

def sieve(n=100000):
    is_p = [True] * (n + 1)
    is_p[0] = is_p[1] = False
    primes = []
    for i in range(2, n + 1):
        if is_p[i]:
            primes.append(i)
            for j in range(i * i, n + 1, i):
                is_p[j] = False
    return primes

def main():
    n = int(input())
    a = list(map(int, input().split()))
    
    primes = sieve(100000)
    
    total = 0
    
    for x in a:
        f = factorize(x, primes)
        for p, c in f.items():
            total += c
    
    if total % 2 == 1:
        print("First")
    else:
        print("Second")

if __name__ == "__main__":
    main()
```コードは、因数分解のための素数を生成することから始まります。 各数値は素数指数に分解され、すべての指数がグローバルに合計されます。 この合計は、ゲーム内で利用可能な独立したプライム除去アクションの総数を表します。 

実装の微妙な点は、試行除算後に残った大きな素因数を処理することです。 因数が 1 より大きいままの場合は、指数 1 を持つ素数として数えなければなりません。 

最終的な決定は、基礎となる公平なゲーム構造と一致する累積指数合計のパリティのみに依存します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    from collections import defaultdict
    import math

    def sieve(n=100000):
        is_p = [True] * (n + 1)
        is_p[0] = is_p[1] = False
        primes = []
        for i in range(2, n + 1):
            if is_p[i]:
                primes.append(i)
                for j in range(i * i, n + 1, i):
                    is_p[j] = False
        return primes

    def factorize(x, primes):
        res = defaultdict(int)
        for p in primes:
            if p * p > x:
                break
            while x % p == 0:
                res[p] += 1
                x //= p
        if x > 1:
            res[x] += 1
        return res

    n = int(input())
    a = list(map(int, input().split()))
    primes = sieve(100000)

    total = 0
    for x in a:
        f = factorize(x, primes)
        for v in f.values():
            total += v

    return "First\n" if total % 2 else "Second\n"

assert run("3\n2 8 4\n") == "Second\n"
assert run("3\n2 12 3\n") == "First\n"

# custom cases
assert run("1\n2\n") == "First\n", "single prime"
assert run("1\n1\n") == "Second\n", "no moves"
assert run("2\n4 9\n") == "Second\n", "disjoint primes"
assert run("2\n2 3\n") == "First\n", "two single primes"

 ## 特殊なケース

 1 に等しい単一の値のような入力の場合、素因数が存在しないため、移動することはできません。 このアルゴリズムは指数の合計が 0 を生成し、すぐに 2 番目のプレーヤーの勝利となります。 

のような大きな素数の場合、$10^{18} = 2^? \cdot 5^?$因数分解ではすべての指数が正しく累積され、パリティは可能な除去の数を反映します。 移動は多くのセグメントの選択肢に適用できますが、すべての削除はちょうど 1 つの単位指数を消費することに対応するため、分解してもカウントは安定したままになります。
