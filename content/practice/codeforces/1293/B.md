 ## 解決策
 ## 問題の理解

 ゲームは、以下から始まるプロセスとして見ることができます。`n`対戦相手を攻撃し、それらの一部を除去するラウンドを繰り返しトリガーします。 各ラウンドで、`s`相手はまだゲーム中で、まさに`t`そのうちの 2 人が現在の問題に不合格となり、JOE が獲得します`t/s`ドルとそれら`t`排除されたプレイヤーは永久に削除されます。 残り`s - t`次のラウンドに進みます。 

重要な自由は、次の期間に限り、各ラウンドで何人の対戦相手が失敗するかを決定できることです。`0`そして現在の生存者数。 対戦相手がいなくなるとプロセスは終了します。 

目標は、JOE が獲得する合計金額を最大化する一連の消去を選択することです。 

制約`n ≤ 100000`これは、ラウンド間で敗退を分配する可能なすべての方法をシミュレートしようとするソリューションは実行不可能であることを意味します。 以下の選択肢に対する素朴な検索`t`各状態で分岐が大きくなり、すぐに指数関数的に増加します。 考えられるすべての残りの状態に対する二次動的計画法でさえ遅すぎます。 

出力は実数であるため、最大で次のような合計を計算する安定した方法も必要です。`n`分数項。 

正確さには、いくつかのエッジの状況が重要です。 いつ`n = 1`、対戦相手は 1 人だけであり、唯一意味のあるアクションは 1 ラウンドで敵を排除し、報酬を与えることです。`1/1 = 1`。 複数のラウンドや分割を誤って想定する推論はここで破綻します。 別の微妙な失敗例は、一度に多くの敵を排除することが有益であると想定した場合に現れます。 たとえば、すべてを取ると、`n`すぐに報酬が得られる`n/n = 1`、局所的には良いように見えますが、将来のラウンドは完全に無視されます。 

## アプローチ

 ブルートフォースビューは各状態を扱います`s`選択肢として: どれかを選択してください`t`から`1`に`s`、 得`t/s`、に移動します`s - t`。 これにより決定木が形成されます。 原理的には正しいですが、各状態が最大で分岐するため爆発的に増加します。`s`可能性があり、中程度の場合でも膨大な数のシーケンスが発生します。`n`。 

重要な単純化は、エリミネーションを複数のラウンドに分割した場合と、それらを 1 つにグループ化した場合に報酬がどのように蓄積されるかを比較することで得られます。 ある状態だとします`s`私たちは排除します`k`反対者。 1ラウンドで行うと、`k/s`。 代わりに、別々のラウンドでそれらを 1 つずつ排除すると、貢献度は次のようになります。`1/s + 1/(s-1) + ... + 1/(s-k+1)`、分子はそのままで各分母が減少するため、厳密には大きくなります。`1`。 

これは、エリミネーションを大きなバッチに集中させることは、単一のエリミネーションに分散させるよりも常に悪いということを意味します。 したがって、最適な戦略が強制されます。すべてのラウンドで、敵を 1 人だけ排除します。 

それが修正されると、プロセスは決定的になります。 から始まる`n`、私たちは行きます`n-1`、 それから`n-2`、などまで`1`、逆数の単純な合計を累積します。

 ## アルゴリズムのチュートリアル

 ### 最適な戦略

 1. から始める`s = n`そして報酬総額`ans = 0`。 これは、まだゲームに参加している対戦相手の数と蓄積されたお金を表します。 
2. 各ステップで、対戦相手を 1 人だけ排除することを決定します。`t = 1`。 これは可能な限り最小の非ゼロ消去であり、これより大きなバッチは、より大きな分母を使用することになるため、最適とは言えません。 
3. 報酬を追加する`1/s`答えに。 これは、対戦相手が 1 人だけ除外されることを反映しています。`s`残り。 
4. 減少`s`ちょうど 1 人の対戦相手が排除されたため、1 つずつです。 
5. まで繰り返します。`s`ゼロになります。 その時点ですべての対戦相手が排除され、プロセスは停止します。 

### なぜ効果があるのか

 中心となるプロパティは、サイズの削除を分割することです。`k`の中へ`k`separate single eliminations always increases total reward because each subsequent fraction uses a smaller denominator. これにより、強制的な構造が作成されます。あらゆる最適解は、答えを減らすことなく、ラウンドごとに対戦相手を 1 人だけ除去するものに変換できます。 Under this structure, the sequence of states is uniquely`n, n-1, ..., 1`, したがって、報酬の総額は固定され最大になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input().strip())

ans = 0.0
for i in range(1, n + 1):
    ans += 1.0 / i

print(ans)
```実装では次から高調波合計を直接計算します。`1`に`n`。 上向きまたは下向きの反復は同等です。 ここで合計します`1/i`明確にするために。 

重要な点は、浮動小数点除算を使用することです。 要求される精度は次のとおりですので、`1e-4`、標準の倍精度累積で十分です。`n`まで`10^5`。

## テストケース```python
import sys, io

def solve():
    n = int(sys.stdin.readline())
    ans = 0.0
    for i in range(1, n + 1):
        ans += 1.0 / i
    print(ans)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    from contextlib import redirect_stdout
    import io as sio
    out = sio.StringIO()
    with redirect_stdout(out):
        solve()
    sys.stdin = old_stdin
    return out.getvalue().strip()

# provided samples
assert abs(float(run("1")) - 1.0) < 1e-9

# custom cases
assert abs(float(run("2")) - (1 + 1/2)) < 1e-9
assert abs(float(run("3")) - (1 + 1/2 + 1/3)) < 1e-9
assert abs(float(run("10")) - sum(1/i for i in range(1, 11))) < 1e-9
assert abs(float(run("100000")) > 0)  # sanity check
```| テスト入力 | 期待される出力 | 検証内容 |

 | 1 | 1 | 最小限のケース |

 | 3 | 1.8333… | 多段階累積 |

 ## 特殊なケース

 いつ`n = 1`、アルゴリズムは加算を 1 回だけ実行します`1/1`。 異なる消去サイズ間で少なくとも 1 つの「選択」を想定するアプローチは、分岐がまったくないため、ここでは失敗します。 

いつ`n`など大きいです`100000`、合計はゆっくりと増加し、多くの小さな部分的な寄与に依存します。 消去シーケンスを明示的にシミュレートしようとする方法では、時間制限を超えてしまいますが、高調波の合計は線形で安定したままになります。 

浮動小数点の精度を考慮する場合、累積順序は必要な許容誤差での正確さに大きな影響を与えませんが、整数の除算や不適切なキャストが混在すると、結果がすぐに壊れてしまいます。
