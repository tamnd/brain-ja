 ## 解決策
 ## 問題の理解

 各テスト ケースは、一連の「選択肢」を記述します。 n 個の間隔があり、i 番目の間隔から、許容範囲内にある整数を 1 つ選択する必要があります。 すべての間隔に対してこれを実行すると、長さ n の配列が得られます。 目標は、この配列に 0 から始まる連続した負でない小さい整数をできるだけ多く含めて、最初に欠落している整数 (MEX) ができるだけ大きくなるようにすることです。 

MEX は、選択した値のどこかにすべての整数 0、1、2 などを正常に配置できるかどうかによってのみ決まります。 x を配置できなかった場合、後で何が起こるかに関係なく、答えは x になります。 

制約は大きく、すべてのテスト ケースにわたる間隔の合計数は 10^6 に達する可能性があります。 これにより、すべての候補 MEX およびすべての間隔の割り当てをネストされた方法でシミュレートしようとするアプローチは直ちに除外されます。 テスト ケースごとの n の二次関数は存続しません。 

微妙な難点は、各間隔が固定値ではなく、柔軟な範囲に対応していることです。 これは、値を位置に照合するのではなく、間隔系が 0 から始まる整数の接頭辞を「カバー」できるかどうかを判断することを意味します。 

単純な間違いは、各間隔に可能な限り最小の値を貪欲に割り当てて MEX を計算できると考えることです。 値の選択はグローバルに調整する必要があるため、これは失敗します。 

たとえば、間隔 [0, 1]、[0, 1]、[1, 1] を考えてみましょう。 貪欲なローカル割り当てでは、0、0、1 が選択され、最適な MEX 2 が与えられる可能性があります。 しかし、代わりに [0, 0]、[0, 1]、[1, 1] を使用した場合、貪欲なローカル選択により、後の値の実行可能性が誤ってブロックされる可能性があります。 実際の制約は、各数値 k が、その値に使用できる少なくとも 1 つの区間によって「サポート」できるかどうかです。 

## アプローチ

 ブルート フォース ビューでは、候補 MEX m を試し、0 から m − 1 までのすべての値をカバーする個別の間隔を割り当てることができるかどうかを尋ねます。固定された m の場合、すべての間隔を繰り返しスキャンし、必要な各値を、それを生成できる何らかの間隔に割り当てて、間隔が再利用されないようにします。 

これは、値 0…m−1 と間隔の間の 2 部マッチングとしてモデル化できます。ここで、l_i ≤ value ≤ r_i の場合にエッジが存在します。 各 m に対する単純なマッチングの試行では、各実行可能性チェックが繰り返し間隔をスキャンして再割り当てするため、最悪の場合 O(n²) のコストがかかります。 

重要な観察は、構造の一致を明示的に考慮する必要がないということです。 私たちが気にするのは、各整数 k が、より小さい値を満たした後でもまだ「利用可能な」間隔でカバーできるかどうかだけです。 これは、値を 0 から上へ貪欲にスイープすることを示唆しています。 

k を固定し、0 から k までのすべての値が確実に達成可能であることを確認しようとする場合、最良の戦略は常に、各値をカバーできる最も早い終了間隔に割り当てることです。ただし、すべての間隔は同等のリソースであり、存在することだけが必要であるため、より単純な条件が生じます。各 k について、以前の割り当てをブロックせずに k 専用にできる間隔が存在するかどうかを知る必要があるだけです。 これは、どれだけの間隔が「使用可能」であるかを昇順にチェックすることになります。 

正しい変換は、値を昇順に処理し、それらをカバーできる間隔に貪欲に割り当て、常にカバーできる最小の正しいエンドポイントを持つ間隔を優先することです。 これは、間隔の可用性を使用して、0、1、2、... を順番に貪欲に一致させることができるかどうかを確認することと同じです。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。

1. すべての間隔を右のエンドポイントで降順でない順に並べ替えます。 これにより、値 k を割り当てようとするときに、常に最も早く終了する間隔が最初に考慮され、後の値に対する柔軟性が確保されます。 
2. 間隔にわたるポインタと、これまでに割り当てに成功した値の数 (0 から開始) を維持します。 
3. 0 から始まる各整数 k に対して、次のように割り当てを試みます。 

左端が ≤ k で、右端が ≥ k であるスキャン間隔を選択し、まだ使用されていないそのような間隔を 1 つ選択します。 そのような間隔が存在しない場合は停止します。 現在の k は MEX です。 

k をカバーする間隔にこだわる理由は、MEX が k を超えるためには、k が最終構造のどこかに出現する必要があるためです。 
4. 選択した間隔を使用済みとしてマークし、k + 1 に移動します。 
5. 失敗するか、n までのすべての値が割り当てられるまで続行します。 

より効率的な実装では、最初から繰り返しスキャンする必要がなくなります。右のエンドポイントの増加順に間隔をスイープし、k に到達するたびにどの間隔がそれをカバーできるかがすでにわかっていることを保証するデータ構造 (または貪欲なポインター ロジック) を維持します。 

### なぜ効果があるのか

 核となる不変条件は、値 k − 1 を処理した後、それぞれが {0, 1, …, k − 1} で個別の値を生成できる k 個の個別の間隔を選択したことです。 現在の k をカバーできる最小の実行可能な間隔を常に割り当てるため、より小さい値をサポートできる唯一の間隔を消費することはありません。 これにより、将来の実現可能性が最大限に維持されます。 

ある値 k で、まだ使用されていない k をカバーする間隔が見つからない場合、k を生成する可能性のあるすべての間隔がすでに以前の値に「費やされ」ているか、k をまったくカバーしていないため、再代入によってこれを修正することはできません。 これにより、k が真の MEX になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        segs = [tuple(map(int, input().split())) for _ in range(n)]

        # sort by right endpoint
        segs.sort(key=lambda x: x[1])

        used = 0
        idx = 0
        import heapq
        heap = []

        ok = True

        for mex in range(n + 1):
            # push all intervals that can cover current mex
            while idx < n and segs[idx][1] < mex:
                idx += 1

            while idx < n and segs[idx][0] <= mex:
                heapq.heappush(heap, segs[idx][1])
                idx += 1

            # remove unusable intervals (already too small right endpoint)
            while heap and heap[0] < mex:
                heapq.heappop(heap)

            if not heap:
                print(mex)
                ok = False
                break

            heapq.heappop(heap)
            used += 1

        if ok:
            print(n)

if __name__ == "__main__":
    solve()
```実装の重要な部分は、可能な MEX 値をスイープすることです。 ヒープには、現在の値をカバーできる可能性のあるすべての間隔が保存されます。 各 k について、右端が小さすぎる間隔を破棄し、有効な間隔を 1 つ選択して k を「割り当て」ます。 これにより、各間隔が最大 1 回、常に可能な限り最も制限された方法で使用されることが保証されます。 

よくある実装上の間違いは、区間 [l, r] は r までの値しか提供できないため、k が r を超えると永久に役に立たなくなることを忘れていることです。 そのため、期限切れの間隔は積極的に破棄されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque

    def solve():
        t = int(input())
        out = []
        import heapq
        for _ in range(t):
            n = int(input())
            segs = [tuple(map(int, input().split())) for _ in range(n)]
            segs.sort(key=lambda x: x[1])

            idx = 0
            heap = []
            ans = 0

            for mex in range(n + 1):
                while idx < n and segs[idx][1] < mex:
                    idx += 1
                while idx < n and segs[idx][0] <= mex:
                    heapq.heappush(heap, segs[idx][1])
                    idx += 1
                while heap and heap[0] < mex:
                    heapq.heappop(heap)
                if not heap:
                    ans = mex
                    break
                heapq.heappop(heap)
            else:
                ans = n
            out.append(str(ans))
        return "\n".join(out)

    return solve()

# disjoint gaps
assert run("1\n3\n0 0\n2 2\n4 4\n") == "1", "gap at 1"

## 特殊なケース

 重要なエッジ ケースの 1 つは、区間に 0 が含まれない場合です。この場合、0 を生成できる区間がないため、アルゴリズムは k = 0 ですぐに失敗します。たとえば、最初に必要な値がすでに不可能であるため、区間 [1,2]、[2,3] では MEX = 0 が生成されます。 

もう 1 つの微妙なケースは、多くの間隔が重なり合っているものの、すべての端点が小さい場合です。 たとえば、間隔 [0,1]、[0,1]、[0,1]、[0,1] では、MEX は最大 2 まで許可されます。アルゴリズムは、これらの間隔を k = 0 および k = 1 で繰り返し消費し、残りのすべての間隔が 2 より前に終了するため、k = 2 で失敗します。 

最後のエッジケースは、単一の大きな間隔が多数の狭い間隔と並んで存在する場合です。 貪欲な戦略では、狭い間隔が最初に消費され、可能な限り最大の k に対して広い間隔が残されます。 これは不可欠です。 この順序を逆にすると、柔軟性が誤って無駄になり、最終的な MEX が減少します。
