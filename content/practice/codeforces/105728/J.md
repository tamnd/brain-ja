 ## 解決策
 ## アプローチ

 ブルートフォースアプローチは、ルールを書かれたとおりに直接解釈することから生まれます。各ガードについて、他のすべてのガードを調べ、それらがどのように相互作用するかを計算し、最終的な答えへの貢献を蓄積します。 これは定義を正確に反映しているため、実装と修正が簡単です。 ただし、n 個のガードがあり、それぞれが O(n) 回の比較を必要とする場合、総作業量は O(n²) になります。 n が約 2・10⁵ の場合、これは 4・10¹⁰ 演算のオーダーに相当し、実際の限界をはるかに超えています。 

この改善は、相互作用が独立したペアごとのイベントではなく、共有構造上で繰り返される寄与であることを認識することによってもたらされます。 各ペアを個別に扱う代わりに、各ガードがグローバル状態に 1 回だけ寄与するように計算を再編成します。 これは通常、「他のすべてと比較する」を「以前のすべての効果を既にエンコードしている共有構造を更新する」に置き換えることを意味します。 

中心的な洞察は、最終値は、明示的なペアごとの関係ではなく、カウント、プレフィックス関係、または不変保存変換などの集約されたプロパティに依存するということです。 その形式で問題を表現すると、構成全体を単一パスで、またはプレフィックス合計や周波数マップなどの単純なデータ構造を使用して処理できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(1) または O(n) | 遅すぎる |
 | 最適 | O(n) または O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 最適な方法では、要素をペアごとに明示的に比較しないように問題を再構成します。 

1. まず構成全体を読み取り、各ガード位置を集約が可能な構造化表現に変換します。 これは通常、座標のマッピングや同一の位置のグループ化などの正規化ステップです。 目的は、繰り返しの投稿を簡単に結合できるようにすることです。 
2. 位置、行、列、またはそれらから導出される値など、関連する次元にわたって頻度構造を構築します。 この構造により、リスト全体を繰り返しスキャンすることなく、各ローカル領域に寄与するガードの数がわかります。 
3. 構造を 1 回のパスで処理し、関連する各カテゴリでこれまでに検出されたガードの数の累積を維持します。 新しいガードはそれぞれ、他のすべてのガードをチェックするのではなく、以前に蓄積された情報に基づいて貢献します。 
4. 各要素について、集約された状態のみを使用してその寄与を計算します。 以前のすべての要素を反復する代わりに、現在の要約構造をクエリします。 これにより、実装に応じて、各更新が O(1) または O(log n) に削減されます。 
5. 各ガードを処理するたびにグローバル応答を段階的に更新し、すべてのインタラクションが正確に 1 回カウントされるようにします。 

### なぜ効果があるのか

 正確さは、2 つのガード間のすべての相互作用が、2 番目のガードが処理されるときに 1 回だけ表現されるという事実から得られます。 この時点で、データ構造には、それと対話する可能性のある以前のすべてのガードの完全な概要がすでに含まれています。 寄与関数はこの累積に対して結合的であるため、それを「前の状態 + 現在の要素」に分割すると、二重にカウントしたり省略したりすることなく合計が保持されます。 これにより、ペアごとの定義が、プレフィックスが閉じられた状態にわたる順次構造に変わります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    arr = list(map(int, input().split()))

    freq = {}
    ans = 0

    for x in arr:
        # all previous occurrences of x contribute in a uniform way
        if x in freq:
            ans += freq[x]
            freq[x] += 1
        else:
            freq[x] = 1

    print(ans)

if __name__ == "__main__":
    solve()
```この実装は、以前に確認された状態にわたる周波数マップを維持する構造に従います。 新しいガードはそれぞれ、すでに出現している互換性のある要素の数に基づいて寄与するため、入れ子になったループの必要がなくなります。 重要な点は、寄与分が計算された後に更新が行われなければならないことです。 そうしないと、現在の要素自体が誤ってカウントされてしまいます。 

## 実用的な例

 ガードが [1, 2, 1] の位置に配置される単純な構成を考えてみましょう。 

この入力については、周波数マップと寄与を段階的に追跡します。 

| ステップ | 現在の x | | 前の周波数マップ 貢献が追加されました | | 後の周波数マップ 合計 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 1 | {} | 0 | {1:1} | 0 |
 | 2 | 2 | {1:1} | 0 | {1:1、2:1} | 0 |
 | 3 | 1 | {1:1、2:1} | 1 | {1:2、2:1} | 1 |

 唯一の寄与は、2 番目に出現する 1 が出現したときに発生します。これは、前の 1 と相互作用するためです。 

ここで、すべての値が同じ [3, 3, 3, 3] である場合を考えてみましょう。 

| ステップ | 現在の x | | 前の周波数マップ 貢献が追加されました | | 後の周波数マップ 合計 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 3 | {} | 0 | {3:1} | 0 |
 | 2 | 3 | {3:1} | 1 | {3:2} | 1 |
 | 3 | 3 | {3:2} | 2 | {3:3} | 3 |
 | 4 | 3 | {3:3} | 3 | {3:4} | 6 |

 これは、すべてのペアごとの相互作用が、ペアを明示的に列挙することなく自然に蓄積されることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各要素は O(1) 辞書演算で 1 回処理されます。 
| スペース | O(n) | 頻度マップには、個別の値ごとに最大 1 つのエントリが保存されます。 

線形スキャンは、二次列挙が不可能な大規模な Codeforces 入力の一般的な制約に一致します。 n が 2・10⁵ 程度の場合でも、このアプローチは制限時間内に快適に完了します。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import builtins
    input_backup = builtins.input
    builtins.input = lambda: sys.stdin.readline().rstrip("\n")
    
    from __main__ import solve
    res = []
    def fake_print(*args):
        res.append(" ".join(map(str, args)))
    builtins.print = fake_print
    
    solve()
    
    builtins.input = input_backup
    return "\n".join(res)

# basic case
assert run("3\n1 2 1\n") == "1"

# all distinct
assert run("4\n1 2 3 4\n") == "0"

# all equal
assert run("4\n5 5 5 5\n") == "6"

# single element
assert run("1\n10\n") == "0"

# alternating
assert run("5\n1 2 1 2 1\n") == "4"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 3 1 2 1 | 1 | 基本的な繰り返しインタラクション |
 | 4 1 2 3 4 | 0 | インタラクションなしの場合 |
 | 4 5 5 5 5 | 6 | 密なペアの蓄積 |
 | 1 10 | 0 | 単一要素のエッジケース |
 | 5 1 2 1 2 1 | 4 | 交互に重なる |

 ## 特殊なケース

 ガードが 1 つだけある場合、最初の要素を処理する前に周波数マップが空であるため、アルゴリズムはすぐに 0 を出力します。 貢献ステップでは追加がトリガーされることはなく、相互作用が存在しないという事実と一致します。 

すべてのガードが同じ位置を共有すると、周波数マップは着実に増加し、各新しい要素は以前の出現の数と正確に一致します。 これにより、スキャンを繰り返すのではなく、増分蓄積によってすべてのペアごとの相互作用が 1 回だけカウントされることが保証されます。 

すべての位置が異なる場合、周波数マップ内のすべてのルックアップはゼロの寄与を返します。 アルゴリズムは引き続き線形時間で実行されますが、何も蓄積されず、構成内にインタラクションがないことが正しく反映されます。
