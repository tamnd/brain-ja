 ## 解決策
 ## 問題の理解

 2D 平面上の一連の点が与えられます。 タスクは、単一の円上に 4 つの点の異なるグループがいくつあるかを数えることであり、これは、選択した 4 つの点すべてを境界が通過する円が存在することを意味します。 

入力は単なる座標のリストです。 出力は 1 つの数値、つまり 4 つの点が共円となるようなインデックスの 4 倍の数です。 

制約は小さく、最大 300 ポイントです。 これは、慎重に実装されれば、およそ 3 次時間よりも悪いものを即座に除外します。 すべての 4 倍数を O(n^4) 列挙すると、最悪の場合でも約 80 億の組み合わせをチェックすることになりますが、これは最適化された C++ でもすでに限界に達しており、Python では大きすぎます。 O(n^3) メソッドでも注意が必要ですが、各ステップが定数または対数である場合は許容されます。 

正確さには、いくつかのエッジの状況が重要です。 

すべての点が 1 つの円上にある場合、4 つの点のすべての組み合わせが有効です。 たとえば、n = 5 で、すべての点が同じ円上にある場合、答えは C(5, 4) = 5 です。ランダムなトリプルをチェックするだけの単純なアプローチや、円がまれであると仮定する単純なアプローチでは、この極端なクラスタリングのケースを見逃してしまいます。 

偶然の円構造を持たずに一般的な位置に配置された点など、4 つの点が共円でない場合、答えはゼロでなければなりません。 計算された半径の浮動小数点の等価性に依存する方法では、精度ノイズにより誤った一致が生成されてはなりません。 

もう 1 つの微妙なケースは、複数の異なるトリプルが同じ円を定義する場合です。 円ごとにグループ化せずに各 4 つを個別にカウントする方法では、オーバーカウントが大きくなります。 

## アプローチ

 直接的なアイデアは、4 つの点のセットをすべて列挙し、それらが共通の円上にあるかどうかを確認することです。 4 つの点が与えられると、行列式条件または角度ベースのチェックを使用して共周期性のテストを行うことができますが、これをすべての 4 倍体に対して行うと O(n^4) となり、n = 300 の場合でも遅すぎます。 

構造を利用する必要があります。つまり、円は同一線上にない 3 つの点によって一意に決定されます。 これにより、視点は「4 倍体を確認する」から「同じ円上にある点の数を数える」に変わります。 

同一線上にない点を 3 つ取得すると、それらは正確に 1 つの円を定義します。 その円にセットの s 点が含まれている場合、それらの s 点のいずれか 3 つが同じ円を再構成するため、その円は C(s, 3) 個の異なるトリプルに寄与します。 

これにより、キーの再パラメータ化が行われます。 4 回転数を直接数える代わりに、定義円ごとにグループ化された 3 回転数を数​​えます。 各円に属するトリプルの数がわかれば、その円上にあるポイントの数を取得し、そこからその円が寄与する 4 倍の数を計算できます。 

トリプルに対するブルート フォースは O(n^3) で実行されます。 n = 300 の場合、これは約 2,700 万回の反復となり、これは実現可能です。 主な課題は、同じ円を定義するすべてのトリプルを確実にグループ化することです。これには、正確なまたは慎重に正規化された演算による円 (中心と半径) の安定した表現が必要です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 幾何学的なチェックを使用した 4 回転でのブルート フォース | O(n^4) | お(1) | 遅すぎる |
 | トリプルを列挙し、円でグループ化する | O(n^3) | O(n^3) | 承認済み |

 ## アルゴリズムのチュートリアル

 次に、点のすべてのトリプルを、それらを通過する円の正規表現に変換し、各円に対応するトリプルの数を集計します。

1. 点 (i、j、k) のすべてのトリプルを繰り返します。 点が同一線上にある場合は、有効な円を定義しないため、それらの点をスキップします。 
2. 有効なトリプルごとに、外接円を計算します。 これは、3 つの点を通過する一意の円の中心とその半径を計算することを意味します。 中心は垂直二等分線の交点を使用して見つけることができ、半径は中心から 3 つの点のいずれかまでの距離です。 
3. このサークルをハッシュ可能なキーに変換します。 実際には、これは、中心座標と二乗半径を正規化された有理形式、または慎重に丸められた十分に正確な浮動表現で表現することを意味します。 
4. 各サークルキーをそれを生成したトリプルの数にマッピングする辞書を維持します。 すべてのトリプルを処理した後、このディクショナリ内の各値は、同じ円上にあるトリプルの数と等しくなります。 
5. トリプルカウント m の各円について、その円上にある点の数を計算します。 s から 3 つの点を選択するとトリプルが生成されるため、恒等式 m = C(s, 3) が得られます。 この三次関係を解いて を求めます。 
6. s がわかったら、C(s, 4) を答えに追加します。これは、その円上の点の 4 つごとに 1 つの有効なセットが含まれるためです。 

正しさは、4 つの同円点の各セットが正確に 1 つの円内に完全に含まれているという事実に依存するため、円グループから再構成するときに正確に 1 回カウントされます。 

### なぜ効果があるのか

 有効な 4 つの同円点はすべて、一意の円上にあります。 その円は列挙ステップで正確に C(s, 3) のトリプルを提供しますが、同一直線上にない 3 つの点が円を一意に定義するため、他の円は同じトリプルを生成できません。 これにより、円とグループ化されたトリプルの間に 1 対 1 のマッピングが作成され、C(s, 3) から s を再構築すると、C(s, 4) の計算に必要なすべての組み合わせ情報が保存されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import defaultdict
from math import gcd

def norm_frac(a, b):
    if b < 0:
        a, b = -a, -b
    g = gcd(abs(a), abs(b))
    return (a // g, b // g)

def circumcircle(p1, p2, p3):
    x1, y1 = p1
    x2, y2 = p2
    x3, y3 = p3

    d = 2 * (x1*(y2 - y3) + x2*(y3 - y1) + x3*(y1 - y2))
    if d == 0:
        return None

    x1s, y1s = x1*x1 + y1*y1, x2*x2 + y2*y2, x3*x3 + y3*y3

    cx_num = (x1s * (y2 - y3) + x2s * (y3 - y1) + x3s * (y1 - y2))
    cy_num = (x1s * (x3 - x2) + x2s * (x1 - x3) + x3s * (x2 - x1))

    cx = norm_frac(cx_num, d)
    cy = norm_frac(cy_num, d)

    # radius squared from first point
    # keep as fraction
    dx = x1 * d - cx_num
    dy = y1 * d - cy_num
    r2_num = dx*dx + dy*dy
    r2_den = d*d
    r2 = norm_frac(r2_num, r2_den)

    return (cx, cy, r2)

def C4(s):
    return s * (s-1) * (s-2) * (s-3) // 24

def C3(s):
    return s * (s-1) * (s-2) // 6

def solve_s(m):
    s = 3
    while C3(s) < m:
        s += 1
    return s

n = int(input())
pts = [tuple(map(int, input().split())) for _ in range(n)]

cnt = defaultdict(int)

for i in range(n):
    for j in range(i+1, n):
        for k in range(j+1, n):
            c = circumcircle(pts[i], pts[j], pts[k])
            if c is not None:
                cnt[c] += 1

ans = 0
for m in cnt.values():
    s = solve_s(m)
    ans += C4(s)

print(ans)
```実装の中核はトリプル列挙です。 外接円の計算では行列式ベースの公式を使用します。これにより、線形システムを明示的に解くことが回避され、すべてが代数的に保たれます。 

辞書キーは円を一意に表す必要があります。 そのため、中心と半径の 2 乗は、換算された分数として保存されます。 正規化に一貫性がない場合、異なる円が誤って結合されたり、同一の円が分割されたりして、どちらもカウントが中断されます。 

再構成ステップでは、恒等式 m = C(s, 3) を使用します。 s は最大 300 であるため、単純な線形探索で十分であり、3 次方程式を明示的に解く必要がなくなります。 

## 実用的な例

 ### 例 1

 正方形を形成する 4 つの点を考えてみましょう。 これら 4 つの中のすべてのトリプルは同じ円を定義するため、その円では m = C(4, 3) = 4 となります。 

| ステップ | 値 |
 | --- | --- |
 | 円 s 上の点の数 | 4 |
 | トリプルの数 m | 4 |
 | 回答 C(s,4) への貢献 | 1 |

 これにより、4 つの点すべてが 1 つの円にグループ化され、正確に 1 つの有効な 4 つ組に寄与することが確認されます。 

### 例 2

 1 つの特別な円のみにちょうど 5 つの点が含まれるような点の場合、次のようになります。 

| ステップ | 値 |
 | --- | --- |
 | s | 5 |
 | m = C(5,3) | 10 |
 | 貢献度 C(5,4) | 5 |

 これは、4 つ以上の点を持つ 1 つの円がどのように複数の 4 つに寄与するかを示しています。

 ## 特殊なケース

 縮退のケースは、3 つの点が同一線上にある場合に発生します。 その状況では、外接円の計算によりゼロの行列式が生成されます。 アルゴリズムはそのようなトリプルを明示的にスキップし、グループ化構造を破壊しないようにします。 

もう 1 つのエッジ ケースは、複数の円が存在するが、共通のサブセット内の多くの点を共有する場合です。 各トリプルは正確に 1 つのサークル キーに割り当てられるため、重複するサブセットはカウントに干渉せず、各サークルは依然として独自のトリプルから独立して再構築されます。 

最後に、座標が大きいか、またはほぼ同一線上にある場合、数値安定性が重要になります。 縮小分数表現を使用すると、浮動小数点の丸めによって 2 つの同一の円が別個のものとして扱われることがなくなり、すべての入力にわたって正確さが維持されます。
