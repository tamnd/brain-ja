 ## 問題の理解

 各ノードが文字ラベルを持つグラフ上の有向プロセスが与えられます。 「旅」とは、まさに、$l$訪問したノード。 どのノードから開始してもよく、各ステップはエッジに沿って隣接するノードまで移動します。 ノードにアクセスすると、その文字が連結されて、次の長さの文字列が形成されます。$l$。 考えられる長さのすべての散歩の中で$l$を見つけるように求められます。$k$-辞書編集順で 番目に小さい文字列。訪問したノードのシーケンス内のいずれかの位置で 2 つのウォークが異なる場合、2 つのウォークは異なるものとみなされます。 

主な困難は、1 つの有効なウォークを生成することではなく、天文学的な規模のウォークのセットを列挙せずに順序付けることです。 中程度のグラフであっても、歩行数は次のように指数関数的に増加します。$l$、再訪問が許可されており、グラフにサイクルが含まれる可能性があるためです。 制約$k \le 10^{18}$これは、候補を明示的に列挙することができず、プレフィックスを効率的にカウントすることに依存する必要があることを示しています。 

入力グラフが切断されている可能性があります。これは、一部の開始点が特定の長さに対して無効であることを意味します。 単純なアプローチでは、すべてのノードから DFS を試行し、次の長さのすべての文字列を収集しようとします。$l$、並べ替えます。 これは、たとえ小さな分岐因子でも指数関数的な数のウォークを生成するため、すぐに失敗します。 2 番目の素朴な試みは、州に対して DP を実行することです。$(node, remaining\_length)$、しかしそれは次のことにつながります$O(n \cdot l)$状態は、両方の場合に大きすぎます。$n$そして$l$できる$2 \times 10^5$。 

グラフが高度に接続されている場合、たとえばいくつかのノード上の完全なグラフなど、微妙なエッジ ケースが発生します。 たとえ$n = 10$、長さの歩行の数$l = 200000$はすでに、切り捨てのない明示的なカウント方法を超えています。 もう一つの問題は、いつ$k$可能な歩行の総数を超えています。この場合、正しく出力する必要があります。`"Impossible"`部分的な工事ではなく。 

## アプローチ

 ブルートフォースのアイデアは簡単です。長さのすべての歩行を列挙します。$l$、文字列を構築し、並べ替えます。 すべての文字列が判明すると、辞書編集上の順序が明確に定義されるため、これは概念的には正しいです。 障害点は明らかです。単一ノードからのウォーク数はおおよそ次のように増加します。$d^l$、 どこ$d$平均的な程度です。 小さいものでも$d = 2$、これは実行不可能になります$l = 2 \times 10^5$。 

より構造化されたアイデアは、問題をプレフィックスに関するカウントの問題として扱うことです。 すべてのノードについて計算できれば$u$そして残りの長さ$t$、長さの歩行の数$t$から始める$u$、その後、貪欲に答えを構築できます。各ステップで、文字の辞書編集順に近傍を試し、その寄与をから差し引きます。$k$目的のウォークを含むブランチが見つかるまで。 

中心的な障害は、これらのカウントを計算することです。 すべての州の完全な DP は大きすぎますが、実際にはそれを超える正確な数は必要ありません。$k$。 値を超えると$k$、キャップを付けることができます。 この観察によって問題が変わります。正確に数えるのではなく、範囲内の値のみを伝播します。$[0, k+1]$。 多くの部分問題はしきい値を超えると崩壊するため、この枝刈りにより効率的な計算が大幅に減少します。 

次に、状態の結果をキャッシュします$(u, t)$。 各状態は 1 回計算され、その値には上限があります。 構築中、これらの上限付きカウントを繰り返しクエリして、どの出力エッジを取るかを決定します。

 ## アルゴリズムのチュートリアル

 現在のノードと残りの長さを維持しながら、左から右に貪欲に答えを構築します。 

1. すべてのノードの隣接リストを宛先ノードの特性によって事前にソートします。 これにより、隣接するものを順番に探索すると、結果の文字列に辞書編集的な順序が自動的に得られます。 
2. 関数を定義します$count(u, t)$長さの歩行の数を返します$t$ノードから開始$u$、ただし、で切り捨てられます$k+1$。 ブランチが以下よりも小さいかどうかを区別するだけでよいため、この切り捨ては不可欠です。$k$、に等しい$k$、またはそれ以上。 
3. 機能$count(u, t)$は再帰的に計算されます。 もし$t = 1$の場合、現在のノード自体が有効な長さ 1 のウォークを形成するため、答えは 1 になります。 それ以外の場合は、すべての近傍を合計します$v$の$u$、追加$count(v, t-1)$, しかし、すぐに合計額に上限を設けます。$k+1$。 メモ化により、各状態が 1 回だけ計算されることが保証されます。 
4. k 番目の文字列を構築するには、文字のソート順に考えられるすべての開始ノードを考慮して、最初の位置を反復処理します。 各候補ノードについて$u$、計算します$count(u, l)$。 この値が少なくとも$k$、私たちは選択します$u$スタートとして。 それ以外の場合はデクリメントします$k$そして続けます。 
5. 開始ノードを修正した後、後続の各位置に対して同じアイデアを繰り返します。 現在のノードで$u$そして残りの長さ$t$、文字順に近傍を繰り返します。 隣人ごとに$v$、計算します$count(v, t-1)$。 もし$k$がこのカウントより大きい場合は、それを減算してスキップします。 それ以外の場合は、次の場所に移動します$v$そして続けます。 
6. いずれかのステップで有効な遷移が存在しない場合、構築は失敗し、出力が出力されます。`"Impossible"`。 

正確さは単一の不変条件に依存します。つまり、すべてのステップで、$k$現在のプレフィックスのすべての有効な補完の中でのランクを表し、$count(u, t)$プレフィックスの選択によって補完のスペースを正しく分割します。 常に検索スペースのサブツリー全体を辞書編集順に減算するため、残りの$k$常に目的のブランチに正確に対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    n, m, l, k = map(int, input().split())
    s = input().strip()

    g = [[] for _ in range(n)]
    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    for i in range(n):
        g[i].sort(key=lambda x: s[x])

    from functools import lru_cache

    K = k

    @lru_cache(maxsize=None)
    def dp(u, rem):
        if rem == 1:
            return 1
        total = 0
        for v in g[u]:
            total += dp(v, rem - 1)
            if total > K:
                return K + 1
        return total

    start = -1
    cur_k = K

    for u in range(n):
        cnt = dp(u, l)
        if cnt >= cur_k:
            start = u
            break
        cur_k -= cnt

    if start == -1:
        print("Impossible")
        return

    res = [s[start]]
    u = start
    rem = l

    while rem > 1:
        rem -= 1
        found = False
        for v in g[u]:
            cnt = dp(v, rem)
            if cur_k > cnt:
                cur_k -= cnt
            else:
                res.append(s[v])
                u = v
                found = True
                break
        if not found:
            print("Impossible")
            return

    print("".join(res))

def main():
    T = int(input())
    for _ in range(T):
        solve()

if __name__ == "__main__":
    main()
```この解決策は、歩行数をカウントするが、カウントが超過するとすぐに停止するメモ化された DP に依存しています。$k$。 これにより、密なグラフの暴走が防止されます。 次に、貪欲な構築はこれらのカウントを消費して、目的の辞書編集ランクに直接移動します。 

実装の微妙な詳細は、次によるキャッシュです。$(u, rem)$。 メモ化を行わないと、貪欲降下中にクエリを繰り返すと、同じ部分問題が何度も再計算され、非常に遅くなります。 もう1つの重要な詳細は、金額が超過した場合の早期終了です。$k$これにより、算術演算が制限され、オーバーフローの問題が回避されます。
