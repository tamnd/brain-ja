 ## 解決策
 ## 問題の理解

 アリスは正確に得点します`a`彼女はプレーするたびに得点しますが、ボブは正確に得点します`b`彼がプレーするたびにポイントを獲得します。 ある程度のゲーム数が経過すると、合計スコアは等しくなります。 タスクは、両方のプレイヤーが持つことができる最小のプラスのスコアを見つけることです。 

アリスが遊ぶなら`x`回、彼女のスコアは`a * x`。 ボブが遊ぶなら`y`回、彼のスコアは`b * y`。 最小の正の整数が必要です`c`どちらも`a`そして`b`分ける`c`。 言い換えれば、問題は次の最小公倍数を求めることです。`a`そして`b`。 

両方の入力値は最大でも`10,000`。 可能なすべてのスコアを直接検索すると、次のような結果が得られます。`100,000,000`これは、1 秒の制限の下では線形検索を望ましくないものにするのに十分な大きさです。 問題の構造により、代わりに定数時間の算術解が得られます。 この範囲内の 2 つの値の最大の最小公倍数は最大で`10,000 * 9,999 = 99,990,000`。 

不注意な実装が露呈する可能性のある小さなケースがいくつかあります。 入力用`1 1`、答えは`1`, なぜなら、両プレイヤーはすでにゲームごとに 1 ポイントを獲得しているからです。 から検索を開始する実装`a + b`最小限を逃してしまいます。 入力用`1 10000`、答えは`10000`、すべての正の倍数であるため、`10000`も割り切れます`1`; 間違った式を使用して 2 つの値を対称的に扱うと、より大きな結果が生成される可能性があります。 入力用`4 6`、答えは`12`、 ない`24`、 なぜなら`12`はすでに両方の値で割り切れます。 これにより、入力の共有係数を削除するのではなく、単純に入力を乗算するアプローチが捕捉されます。 

## アプローチ

 単純な総当たりソリューションでは、どちらかが両方で割り切れるスコアが見つかるまで、可能なスコアを生成できます。`a`そして`b`。 たとえば、次のように始めます。`1`、各整数が次のとおりであるかどうかをテストできます。`c`満足する`c % a == 0`そして`c % b == 0`。 より小さい正の値はすべてすでに拒否されているため、最初のそのような値が必ず答えになります。 

このバージョンの問題は、検索範囲が非常に大きくなる可能性があることです。 のために`a = 10000`そして`b = 9999`、答えは`99,990,000`したがって、からのすべての整数をチェックします`1`答えが必要とする`99,990,000`繰り返し。 各反復は単純ですが、これは必要以上に手間がかかります。 

1 つの入力の倍数のみを考慮することで、検索を小さくすることができます。 テストしたら`a`、`2a`、`3a`、など、次でも割り切れる最初の倍数`b`は最小公倍数です。 答えはせいぜい`100,000,000`そして`a`少なくとも`1`、これにはまだ約まで必要になる可能性があります`100,000,000`反復のとき`a = 1`したがって、これは最もクリーンな解決策でもありません。 

重要な観察は、次の共通部分です。`a`そして`b`二度数えてはいけません。 させて`g = gcd(a, b)`。 製品`a * b`～のあらゆる要素が含まれています`a`そして`b`で表される要因ですが、`g`両方に登場します。 製品を次の値で割ると、`g`重複した部分を正確に削除し、最小公倍数を求めます。`lcm(a, b) = a * b / gcd(a, b)`。 

ブルート フォースは、両方の割り算特性を持つ最初の数値を検索するため機能しますが、2 つの入力間の算術関係を無視するため失敗します。 それらの共通因子が最大公約数で特定できるという観察により、同じ答えを直接計算することができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(lcm(a, b)) | お(1) | 最悪の場合は遅すぎる |
 | 最適 | O(log(min(a, b))) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む`a`そして`b`、アリスとボブがゲームごとに獲得するポイント数。 
2. コンピューティング`g = gcd(a, b)`ユークリッドアルゴリズムを使用します。 gcd には、両方のスコア値に共有される因子が正確に含まれています。 
3. コンピューティング`a * b // g`。 これは最小公倍数です。`a`そして`b`すべての因子を結合しますが、gcd で除算すると、2 回含まれた因子が削除されます。 
4. 結果の値を出力します。 これは、両方で割り切れる最小の正のスコアです。`a`そして`b`, したがって、両方のプレイヤーは整数のゲーム数を使用してそれに到達できます。 

### なぜ効果があるのか

 しましょう`g = gcd(a, b)`。 書けます`a = g * x`そして`b = g * y`、 どこ`x`そして`y`は互いに素である。 以来`x`そして`y`共通の因数がない場合、両方の入力に必要なすべての因数を含む最小の数は次のようになります。`g * x * y`。 置き換える`x = a / g`そして`y = b / g`与える`(a / g) * b`、まさにその通りです`a * b / g`。 この値は両方で割り切れます`a`そして`b`、また、公倍数には同じ必要な因数が含まれている必要があるため、これより小さい正の公倍数は存在しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def gcd(a, b):
    while b:
        a, b = b, a % b
    return a

a, b = map(int, input().split())

g = gcd(a, b)
answer = a * b // g

print(answer)
```の`gcd`関数はユークリッド アルゴリズムを実装します。 各反復で、ペアは`(a, b)`に置き換えられます`(b, a % b)`。 この変換では公約数のセットは変化せず、2 番目の値は最終的にゼロになります。 残りの最初の値は gcd です。 

gcd を計算した後、コードは次のように評価します。`a * b // g`。 ここでは整数の除算が正確に行われます。`g`両方を分割します`a`そして`b`、したがって、必然的に製品を分割します。 Python の整数もオーバーフローしませんが、ここでの最大の中間積は`100,000,000`ともかく。 

可能なスコアをループすることはないため、答え自体に関係する境界条件や、1 つ違いの問題はありません。 入力は正であることが保証されているため、gcd も正となり、ゼロによる除算は発生しません。 

## 実用的な例

 ### サンプル 1

 のために`a = 2`そして`b = 3`、2 つの値には次のような共通因数はありません。`1`。 

| | b | gcd(a, b) | a * b | 答え |
 | --- | --- | --- | --- | --- |
 | 2 | 3 | 1 | 6 | 6 |

 gcd は`1`したがって、重複した要素を製品から削除する必要はありません。 両方で割り切れる最小のスコア`2`そして`3`は`6`。 アリスはその後に到着します`3`ゲーム中、ボブはその後ゲームに到達します`2`ゲーム。 

### サンプル 2

 のために`a = 4`そして`b = 6`、値は次の係数を共有します。`2`。 

| | b | gcd(a, b) | a * b | 答え |
 | --- | --- | --- | --- | --- |
 | 4 | 6 | 2 | 24 | 12 |

 製品`24`共有因子をカウントします`2`2回。 gcd で割ると重複が削除され、`12`。 アリスが届く`12`後`3`ゲームをしてボブがそれに到達した後`2`ゲーム。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(log(min(a, b))) | ユークリッド アルゴリズムは、ペアをより小さい剰余に繰り返し置き換えます。 |
 | スペース | お(1) | 一定数の整変数のみが保存されます。 |

 With both inputs at most`10,000`、ユークリッド アルゴリズムはほんの数回の反復しか必要としません。 このソリューションは 1 秒の制限時間内に簡単に収まり、使用するメモリは 64 MB の制限に比べて無視できます。 

## テストケース```python
import sys
import io

def solve(inp: str) -> str:
    data = inp.split()
    a, b = map(int, data)

    x, y = a, b
    while y:
        x, y = y, x % y

    return str(a * b // x) + "\n"

def run(inp: str) -> str:
    return solve(inp)

# Provided samples
assert run("2 3") == "6\n", "sample 1"
assert run("4 6") == "12\n", "sample 2"

# Minimum-size inputs
assert run("1 1") == "1\n", "minimum values"

# One value divides the other
assert run("1 10000") == "10000\n", "one divides the other"

# Equal values
assert run("10000 10000") == "10000\n", "equal maximum values"

# Maximum answer in the allowed input range
assert run("9999 10000") == "99990000\n", "maximum LCM"

# Shared factors, catches incorrect multiplication
assert run("12 18") == "36\n", "shared factors"

print("All tests passed.")
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1 1`|`1`| 最小サイズの入力と可能な最小の答え |
 |`1 10000`|`10000`| 以下に等しい値`1`一方の入力がもう一方の入力を分割する場合 |
 |`10000 10000`|`10000`| 許可される最大の入力を含む等しい値 |
 |`9999 10000`|`99990000`| 制約内の最大の答えの境界 |
 |`12 18`|`36`| 製品を返品するのではなく、共有要素を正しく削除します。 

## 特殊なケース

 のために`1 1`、gcd は`1`、したがって、式は次のようになります`1 * 1 / 1 = 1`。 このアルゴリズムは、答えがどちらの入力よりも大きい必要があるとは想定しておらず、可能な限り最小の正のスコアを正確に返します。 

のために`1 10000`、ユークリッド アルゴリズムは次のように計算します。`gcd(1, 10000) = 1`。 結果は`1 * 10000 / 1 = 10000`。 すべての整数は次で割り切れるため、これが機能します。`1`したがって、ボブが到達できる最初のプラスのスコアは、すでにアリスにとって有効なスコアです。 

のために`4 6`、gcd は`2`。 式は次のようになります`4 * 6 / 2 = 12`。 のみを使用した不用意な実装`a * b`戻るだろう`24`、これは公倍数ですが、最小値ではありません。 gcd で除算することで、まさに重複した要素が削除されます。 

のために`9999 10000`、gcd は`1`, したがって、削除する要素はありません。 製品は`99,990,000`これは最小公倍数であり、答えが指定された上限に近くなる可能性があることも示しています。`100,000,000`。 このアルゴリズムは、何百万もの小さな候補スコアを反復処理することなく、この境界を直接処理します。
