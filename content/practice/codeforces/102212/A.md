 ## 問題の理解

 このタスクは意図的に単純です。1 行には 2 つの整数が含まれます。`a`そして`b`、プログラムはそれらを加算して得られた整数を出力する必要があります。 値は正、ゼロ、または負の場合があるため、演算は非負の値の特別な処理ではなく、通常の符号付き整数の加算になります。 

境界が十分に小さいため、演算自体は簡単です。 各入力値は次の範囲にあります。`-1,000,000,000`そして`1,000,000,000`, したがって、それらの合計は次の間にあります。`-2,000,000,000`そして`2,000,000,000`。 どちらかの数値の大きさに依存するアルゴリズムは必要ありません。 一定量の作業で十分であり、Python の整数型はオーバーフローすることなく指定された範囲内のすべての値を表すことができます。 

主なエッジ ケースは、符号と境界値から得られます。 たとえば、入力の場合`50 -26`、正しい出力は次のとおりです。`24`。 両方の値が正であると仮定する不用意な解決策は、負のオペランドを誤って処理する可能性があります。 入力あり`-1000000000 -1000000000`、正しい出力は次のとおりです。`-2000000000`したがって、実装では符号と完全な大きさの両方を保持する必要があります。 同様に、`1000000000 1000000000`生産しなければならない`2000000000`、オーバーフローの可能性がある言語で不必要に狭い整数型を使用する実装をキャッチします。 

ゼロも単純な境界ケースです。 入力用`0 7`、答えは`7`、そしてのために`-5 0`、答えは`-5`。 ゼロには特別なアルゴリズム分岐は必要ありません。これは、この問題における有益な観察の 1 つです。 

## アプローチ

 文字通りの総当り的な手法では、加算を繰り返しの増分として扱う可能性があります。 から始まる`a`、正の値で表される単位ごとに 1 つの増分を実行できます。`b`、または負の数で表される単位ごとに 1 つ減分します。`b`。 これは正しいです。各操作で現在の値が 1 だけ変更されるため、必要な数の操作を行った後の結果は次のようになります。`a + b`。 問題は操作回数です。 たとえば、追加`1,000,000,000`10 億回の反復が必要となり、最悪の場合、第 2 オペランドの大きさは次のようになります。`1,000,000,000`。 それはあきらめます`1,000,000,000`これは、Codeforces の 1 秒の制限が対応できる範囲をはるかに超えています。 

問題の構造から、はるかに簡単な観察が得られます。 要求されている操作は、プログラミング言語によってすでに直接サポートされています。整数の加算により、一定時間で目的の結果が計算されます。 隠れた検索スペースや処理する配列はなく、利用する必要がある複数のテスト ケース間の関係もありません。 

この総当り方式は、加算を一度に 1 ユニットずつ再構築するため機能しますが、ユニットの数が 10 億にも達する可能性があるため失敗します。 必要な演算自体が基本的な整数演算であるという観察により、2 つの入力値を解析した後、タスク全体を 1 つの加算に減らすことができます。

 ## アルゴリズムのチュートリアル

 1. 1 つの入力行から 2 つの整数を読み取ります。 これらは空白で区切られているため、行を分割すると 2 つの値が直接得られます。 
2. コンピューティング`a + b`。 これはまさに要求された数学的量であり、Python は符号付き整数の算術演算を直接処理します。 
3. 結果の整数を出力します。 値を整数として出力すると、結果が負の場合でも符号が保持されます。 

### なぜ効果があるのか

 唯一維持される値は、解析された 2 つのオペランドの正確な数学的合計です。 加算演算では 2 つの入力値がそれらの算術和に置き換えられるため、結果の値は問題で必要な量と正確に一致します。 近似、反復、変換が含まれないため、エラーを引き起こす可能性のある中間状態は存在しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    a, b = map(int, input().split())
    print(a + b)

if __name__ == "__main__":
    solve()

内部`solve`、`map(int, input().split())`2 つのテキスト値を Python 整数に変換します。 負の数は自動的に処理されます。`int`したがって、個別の符号解析は必要ありません。 

表現`a + b`必要な計算のみを実行します。 Python の整数には任意の精度があるため、可能な最大の結果であっても、`2,000,000,000`、正確に表現されています。 off-by-one エラーが発生する可能性のあるループ、配列インデックス、または境界条件はありません。 

問題には整数のペアが 1 つだけ含まれているため、読み取るテスト ケースのカウントや複数のケースにわたるループはありません。 の`if __name__ == "__main__"`ガードは単純に作る`solve()`ファイルが正常に実行されたときに実行されます。 

## 実用的な例

 サンプル 1 の場合、入力には 2 つの正の整数が含まれています。 

| ステップ |`a`|`b`|`a + b`|

 計算された値は次のとおりです。`5 + 9 = 14`、プログラムは次のように出力します`14`。 これは通常の正の整数の場合を示しています。 

サンプル 2 では、2 番目のオペランドは負です。 

| ステップ |`a`|`b`|`a + b`|

 負号は Python が解析するときに保持されます。`-26`、そして通常の符号付き加算は次のようになります`50 + (-26) = 24`。 これは、アルゴリズムが混合符号に対する特別なケースを必要としないことを確認します。

## 特殊なケース

 混合符号の場合`50 -26`両方のトークンを符号付き整数として解析し、評価することによって処理されます。`50 + (-26)`を生成します。`24`。 負の符号はすでに整数値の一部であるため、加算と減算を区別するための分岐は必要ありません。 

可能な限り最小のオペランドの場合、入力は`-1000000000 -1000000000`は 2 つの負の整数として解析されます。 加算により生成されるのは、`-2000000000`、これはまさに最小許容額です。 Python の整数表現はこの境界でオーバーフローしません。 

可能な最大のオペランドの場合、`1000000000 1000000000`生成する`2000000000`。 このアルゴリズムは、小さい値の場合と同じ単一の加算を実行するため、特別な上限分岐や 1 によるオフ条件はありません。 

正確なキャンセルについては、次の点を考慮してください。`-1000000000 1000000000`。 2 つのオペランドは大きさが等しく、符号が反対であるため、加算すると次のようになります。`0`。 これにより、実装が入力値を絶対的な大きさとして扱うのではなく、両方の符号を正しく保存しているかどうかがチェックされます。 

ついに、`0 7`与える`7`、 その間`-5 0`与える`-5`。 ゼロを追加すると他のオペランドは変更されないため、ゼロには特別な処理は必要ありません。これはまさに直接整数加算演算の計算内容となります。
