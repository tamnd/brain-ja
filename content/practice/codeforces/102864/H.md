 ## 問題の理解

 この問題のシーケンスは元の配列だけではありません。 指定された配列から開始`a^(0)`、プレフィックス合計演算を繰り返し適用します。 1回の申し込みの後、`a^(1)`はプレフィックス合計配列です。 再度申請を行った後、`a^(2)`はプレフィックスの合計です`a^(1)`、 等々。 クエリは範囲の合計を要求します。`a^(k)`一方、更新では元の配列の単一要素が変更されます。`a^(0)`。 

繰り返されるプレフィックス合計の効果を確認する直接的な方法は、組み合わせを使用することです。 本来の価値`a_j^(0)`後の地位に貢献する`a_i^(k)`係数あり`C(i-j+k-1, k-1)`いつ`j <= i`。 範囲クエリは、もう 1 つのレベルでプレフィックス クエリとして書き直すことができます。`sum(l, r, k) = a_r^(k+1) - a_(l-1)^(k+1)`。 

したがって、タスクは、`(k+1)`元のシーケンスのポイント更新後の - 番目のプレフィックス シーケンス。 

この制約は、クエリのたびに変換された配列全体が再構築されないように設計されています。 配列の長さは`10000`、ただし操作数は次の値に達します`200000`、だから、`O(n)`すべての更新またはクエリの操作には、約 20 億の操作が必要になります。 小さい配列サイズをより慎重に使用し、変更のたびにすべての位置に触れないようにする必要があります。 

不注意な実装は簡単に壊れてしまうケースがいくつかあります。 1 つ目は、最初の位置から始まるプレフィックスを照会することです。 例えば：```
Input
1 1
5
1
2 1 1
```答えは`5`。 を使用した解決策`l-1`ゼロを正しく処理しないと、無効なインデックスにアクセスすることになります。 

もう 1 つの危険なケースは、クエリの前に更新が行われる場合です。 例えば：```
Input
2 2
1 2
2
1 1 3
2 1 1
```更新後、最初の要素は次のようになります。`4`。 2 つのプレフィックス操作後のシーケンスは次で始まります。`4`、したがって、答えは次のとおりです`4`。 元の配列を更新するだけで、それより上位のプレフィックス レベルがすべてそれに依存していることを忘れるソリューションは失敗します。 

最後の共通の問題はモジュラー減算です。 たとえば、右側のプレフィックス値が左側のプレフィックス値よりも小さい場合、法は`998244353`、印刷前に減算を正規化する必要があります。 

## アプローチ

 ブルート フォース手法は文字通り定義に従います。 更新のたびに変更されます`a^(0)`そしてプレフィックス合計演算を再構築します`k`回。 1 つのレベルの再構築を最適化したとしても、`O(n)`、合計費用は`O(nk)`アップデートごとに。 と`n`そして`k`どちらも等しい`10000`、このあたりです`10^8`1 回の更新では操作が遅すぎます。`200000`クエリ。 

重要な観察は、最終的なクエリ値が元の配列で線形であることです。 位置での単一ポイントの更新`p`の値を変更します`a_x^(k+1)`あらゆる人にとって`x >= p`による：`q * C(x-p+k, k)`。 

加算値のシーケンスは、シフトされた二項シーケンスです。 以来`n`だけです`10000`、平方根分解を使用できます。 可能なすべての変換値をグローバルに維持する代わりに、元の位置を小さなブロックに分割します。 

各ブロックは、そのブロック内のすべての安定した値のすべての寄与をすべてのプレフィックス位置に格納します。 ポイントの更新は、保留中の変更としてブロック内に一時的に保存されます。 クエリは、保存されたブロックの寄与と保留中の変更を組み合わせます。 ブロックに多くの保留中の変更が蓄積されている場合、それらの変更を適用し、その影響を再計算することによってブロックを再構築します。 

これにより、再構築コストとクエリ コストのバランスが取れます。 ブロックサイズが近いと`22`およびリビルドしきい値に近い`450`どちらの部分も、クエリあたり数百の操作にとどまります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 更新ごとに O(nk) | O(n) | 遅すぎる |
 | ブロック分解 | O(sqrt(n) + しきい値) 償却 | O(n平方(n)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 係数を事前計算する`C(k+d, k)`あらゆる可能な距離に対して`d`。 位置が更新を受け取るたびに同じ係数が使用されます。`p`位置に影響を与える`x`距離だけを通って`x-p`。 
2. 元の配列をブロックに分割します。 ブロックごとに配列を構築します`contribution`どこ`contribution[x]`このブロックの安定した値がどの程度貢献するかを保存します`a_x^(k+1)`。 寄与度は次の式から計算されます。`a_x^(k+1) = sum(j <= x) C(x-j+k, k) * a_j^(0)`。 

1. すべての新しいポイント更新を保留中の変更として対応するブロックに保存します。 1 回の更新が多くの位置に影響を与えるため、寄与配列をすぐには変更しません。 
2. クエリに答えるには、まず、`(k+1)`- 番目のプレフィックス値`r`そして`l-1`。 すべてのブロックについて、その位置に保存されている寄与を追加します。 次に、事前に計算された二項係数を使用して、そのブロックの保留中の更新を直接処理します。 
3. ブロック内の保留中の更新の数が選択した再構築制限に達すると、すべての保留中の変更をブロックの実際の値に適用し、その寄与配列を再構築します。 これにより、直接保留中の計算の数が制限されます。 

なぜ効果があるのか:

 ブロックによって保存される寄与は、そのブロック内のすでに組み込まれているすべての値の効果の正確な合計です。 すべてのクエリが数学的寄与を明示的に追加するため、保留中の更新が失われることはありません。 再構築では、同じコントリビューションが保存されている場所のみが変更されるため、クエリによって返される値は変更されません。 答えは二つの違いなので`(k+1)`-th プレフィックス値、すべての範囲クエリは正しく応答されます。 

## Python ソリューション```python
import sys
from array import array

input = sys.stdin.readline

MOD = 998244353

def solve():
    n, k = map(int, input().split())
    a = [0] + list(map(int, input().split()))

    w = [1] * (n + 1)
    inv = [1] * (n + 2)
    for i in range(1, n + 2):
        inv[i] = pow(i, MOD - 2, MOD)

    for d in range(n):
        w[d + 1] = w[d] * (k + d + 1) % MOD * inv[d + 1] % MOD

    block_size = 22
    rebuild_limit = 450
    block_count = (n + block_size - 1) // block_size

    values = [a[:]]
    blocks = []
    pending = [[] for _ in range(block_count)]

    def rebuild(b):
        left = b * block_size + 1
        right = min(n, left + block_size - 1)
        cur = array('I', [0]) * (n + 1)
        for pos in range(left, right + 1):
            val = a[pos]
            if val:
                for x in range(pos, n + 1):
                    cur[x] = (cur[x] + val * w[x - pos]) % MOD
        blocks[b] = cur

    blocks = [None] * block_count
    for b in range(block_count):
        rebuild(b)

    def get_prefix(x):
        if x <= 0:
            return 0
        ans = 0
        for b in range(block_count):
            ans += blocks[b][x]
        for b in range(block_count):
            for pos, delta in pending[b]:
                if pos <= x:
                    ans += delta * w[x - pos]
        return ans % MOD

    out = []
    m = int(input())

    for _ in range(m):
        t, x, y = map(int, input().split())
        if t == 1:
            b = (x - 1) // block_size
            a[x] = (a[x] + y) % MOD
            pending[b].append((x, y))
            if len(pending[b]) >= rebuild_limit:
                for pos, delta in pending[b]:
                    a[pos] = a[pos] % MOD
                pending[b].clear()
                rebuild(b)
        else:
            ans = get_prefix(y) - get_prefix(x - 1)
            out.append(str(ans % MOD))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```係数配列`w`は再帰を使用して構築されます。`C(k+d+1,k) = C(k+d,k) * (k+d+1)/(d+1)`。 

これにより、組み合わせを繰り返し計算することが回避されます。 すべての算術演算が以下で実行されるため、モジュラー逆関数が使用されます。`998244353`。 

の`rebuild`関数は、1 つのブロックの保存された寄与を構築します。 ブロック内の各要素は、後のすべてのプレフィックス位置に寄与し、これは次の式と一致します。`(k+1)`- 番目の接頭辞。 

クエリ関数は最初に、事前計算されたブロックの寄与を使用します。 残りの違いはまだ再構築されていない更新に起因するため、それらは同じ二項係数式を使用して直接適用されます。 

更新操作では、元の値のみが変更され、デルタが記録されます。 保留リストが大きくなると、再構築によりそれらの変更が永続的なブロック構造に移動されます。 すべての値は剰余として保持されます`998244353`、最終的な答えには減算も含まれます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n / B + T) * m + n^2 / B) 償却 | クエリはブロックと保留中の更新をスキャンしますが、再構築は多くの更新が行われた後にのみ行われます。

 ここ`B`はブロックサイズであり、`T`は再構築のしきい値です。 選択した値を使用すると、操作の数は制限内に収まります。`n`だけです`10000`また、高価な再構築はほとんど行われません。
