 ## 解決策
 ## 問題の理解

 棚には M 個の製品が一定の順序で配置されています。 各製品には重量と価値があります。 Longlong はその順序でのみ棚に沿って移動できるため、彼が選択した商品は元のシーケンスのサブシーケンスを形成する必要があります。 

ショッピング カートの最大重量は N です。特別なルールとして、最初の商品以降に選択されたすべての商品は、その直前に選択された商品よりも重くあってはならないということです。 つまり、選択した製品の重みが g1、g2、g3 である場合、それらは g1 >= g2 >= g3 を満たす必要があります。 合計の重みが N を超えないすべての有効な選択肢の中で、可能な最大の合計値が必要です。 

制限は小さく、N と M は両方とも最大 100 です。追加の次元を 1 つ備えた通常のナップザック ソリューションで十分ですが、考えられるすべてのサブセットを列挙するアプローチは不可能です。 製品が 100 個ある場合は、制限時間内に調査できる範囲をはるかに超えて、2^100 通りの選択肢が作成されます。 

いくつかの詳細が誤った答えを引き起こす可能性があります。 最初に選択した製品には以前の重量制限がないため、任意の重量を設定できます。 例えば：```
5 2
5 10
1 1
```どちらの製品も選択できるため、正解は 11 です。 以前の重みを誤って初期化するソリューションでは、最初の積が拒否されたり、空の状態の使用に失敗したりする可能性があります。 

もう 1 つのケースは、より重い製品が後で登場する場合です。```
5 3
1 10
3 100
2 5
```ウェイト 3 と 2 を選択すると、正解は 105 になります。ウェイト 1 の商品は、棚の順序を変更できないため、その前に選択できません。 通常のナップザックの変形のように、製品を重量で分類するソリューションでは、別の問題が解決され、無効な結果が生成されます。 

最後のエッジケースは、何も選択しないことです。```
1 1
1 7
```製品が適合しているため、答えは 7 です。 容量がゼロの場合、答えは 0 になるため、動的プログラミングでは常に空の選択を保持する必要があります。 

## アプローチ

 最も直接的な方法は、製品の可能なすべてのサブセットを試すことです。 サブセットごとに、選択したインデックスが元の順序を維持しているかどうか、重みが増加していないか、合計重みがカートに収まるかどうかを確認します。 この方法は、考えられるすべての選択肢が検査されるため正しいですが、2^M 個のサブセットがあります。 M = 100 の場合、最悪のケースでは約 1.27 × 10^30 のチェックが必要になりますが、これは不可能です。 

有益な観察は、将来はすでに処理された製品からの 2 つの情報のみに依存するということです。 現在の総重量を知る必要があるのは、どのくらいの容量が残っているかを決定するためです。また、最後に選択した製品の重量を知る必要があるのは、次の製品が許可されるかどうかを制御するためです。 

これにより、問題は動的プログラミングに変わります。 製品を左から右にスキャンしながら、使用容量と最後に選択した重量のあらゆる組み合わせに対して最適な値を維持します。 製品を処理するとき、製品をスキップして古い状態を維持するか、製品の重量が以前に選択した重量を超えない場合はその製品を使用します。 

最初に選択した製品には以前の重量がないため、特別な処理が必要です。 考えられるすべての製品重量よりも大きい特別な前の重量で空の状態を表し、任意の製品を最初の製品として選択できるようにします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^M × M) | お(お) | 遅すぎる |
 | 最適 | O(M × N × 101) | O(N × 101) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 動的プログラミング テーブルを初期化します。`dp[c][w]`総重量を使用して、シェルフの一部のプレフィックスを処理した後に達成可能な最大値を表します`c`、最後に選択した製品に重みがある`w`。 特別な状態`w = 101`これまで何も選択していないことを表します。 

初期状態は`dp[0][101] = 0`なぜなら、製品を取得する前はカートの重量がゼロであり、最初の製品には制限がないからです。 

1. すべての製品を左から右に処理します。 重量のある現行品の場合`g`そして価値観`s`、この製品をスキップするオプションを表す現在の状態のコピーを作成します。 

選択した製品は、棚の連続セグメントではなく、サブシーケンスである必要があるだけであるため、スキップを考慮する必要があります。 

1. 既存のすべての状態について、現在の製品を試してみます。 現在の状態に以前の重みがある場合`w`そして`g <= w`、商品を追加することができます。 新しい容量で状態を更新します`c + g`そして新しい最後の重量`g`。 

最後に選択した重みは次のようになります。`g`なぜなら、将来のすべての製品は、最後に追加された製品と比較する必要があるからです。 

1. すべての製品が処理された後、最終使用容量や最後に選択した重量に関係なく、答えはすべての有効な状態の最大値になります。 

なぜ効果があるのか:

 動的プログラミング状態には、将来の決定に必要な情報が正確に保存されます。 同じプレフィックスを処理し、同じ使用容量と最後に選択した重量を持つ 2 つの異なる選択は、残りのすべての製品に対して同じ可能性があります。 このうち大きい方の値だけを保持しても最適解を取り除くことはできません。 各遷移では、製品に対する 2 つの選択肢のみが考慮され、許可されている場合はそれをスキップするか選択するため、すべての有効なサブシーケンスが表現されます。 すべての状態の最終的な最大値が、最も有効なショッピング プランです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    N, M = map(int, input().split())
    items = [tuple(map(int, input().split())) for _ in range(M)]

    NEG = -1
    dp = [[NEG] * 102 for _ in range(N + 1)]
    dp[0][101] = 0

    for g, s in items:
        new_dp = [row[:] for row in dp]

        for weight in range(N + 1):
            for last in range(102):
                if dp[weight][last] == NEG:
                    continue
                if g <= last and weight + g <= N:
                    new_dp[weight + g][g] = max(
                        new_dp[weight + g][g],
                        dp[weight][last] + s
                    )

        dp = new_dp

    ans = 0
    for weight in range(N + 1):
        for last in range(102):
            ans = max(ans, dp[weight][last])

    print(ans)

if __name__ == "__main__":
    solve()
```実際の製品の重みは 1 ～ 100 であり、インデックス 101 は空の選択用に予約されているため、テーブルには 102 個の可能な以前の重みがあります。 値`NEG`到達できない状態をマークし、無効な遷移が使用されるのを防ぎます。 

すべての製品について、コードはテイクトランジションを適用する前に古いテーブルをコピーします。 これにより、1 回の反復で同じプロダクトを複数回使用することがなくなります。これは、0/1 ナップザックが前の層から状態を更新するのと同じ理由です。 

条件`g <= last`重量非増加要件を強制します。 空の状態は、`last = 101`, したがって、最初の製品はどれでも受け入れられます。 更新前に容量チェックが行われるため、カート制限を超える状態がテーブルに入るのを防ぎます。 

可能な最大合計値は 10000 のみであるため、すべての値は Python 整数内に簡単に収まります。

import sys
import io

def solve_case(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    N, M = map(int, input().split())
    items = [tuple(map(int, input().split())) for _ in range(M)]

    NEG = -1
    dp = [[NEG] * 102 for _ in range(N + 1)]
    dp[0][101] = 0

    for g, s in items:
        new_dp = [row[:] for row in dp]
        for w in range(N + 1):
            for last in range(102):
                if dp[w][last] != NEG and g <= last and w + g <= N:
                    new_dp[w + g][g] = max(
                        new_dp[w + g][g],
                        dp[w][last] + s
                    )
        dp = new_dp

    return str(max(max(row) for row in dp)) + "\n"

 ## 特殊なケース

 最初のエッジケースの場合:```
5 2
5 10
1 1
```初期状態は`(capacity = 0, last = 101)`。 5 が 101 未満であるため、最初の製品を選択でき、容量 5、最後の重量 5、および値 10 の状態が作成されます。1 が 5 未満であるため、2 番目の製品を続けることができ、最終的な答え 11 が作成されます。特別な空の状態により、最初の製品を制限しないことができます。 

注文のエッジケースの場合:```
5 3
1 10
3 100
2 5
```最初のプロダクトの後の最良の状態の最後の重みは 1 です。2 番目のプロダクトの重みは 3 であるため、その状態に従うことはできません。 アルゴリズムは依然として空の状態を維持し、2 番目の製品が最初の選択肢になることを可能にします。 2 は 3 より小さいため、3 番目の商品がそれに続くことができます。答えは 105 となり、元の棚の順序が尊重されます。 

選択の余地のない境界の場合:```
0 1
1 7
```到達可能な状態は空のカートのみです。 製品を追加すると重量 1 が作成され、制限を超えるため、製品は容量条件を満たしません。 残りの最大値は 0 であり、これが正しい結果です。
