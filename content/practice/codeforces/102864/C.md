 ## 解決策
 ## 問題の理解

 初期配列があります`A`一意の値とターゲット配列を持つ`B`、また固有の値を持ちます。 操作では 1 つの位置を選択し、その現在の値を別の整数に置き換えますが、配列は操作ごとにすべての値を異なる値に保つ必要があります。 タスクは、変更される操作の最短シーケンスを出力することです。`A`の中へ`B`。 

値がすでに正しい位置には触れる必要はありません。 困難は、現在別の場所に保存されている値を必要とする位置から発生します。 必要な値が占有されている場合、プロセス中に重複した値が禁止されているため、直接書き込むことはできません。 

すべての配列の合計サイズは 200 万要素に達する可能性があるため、二次関数によるアプローチは不可能です。 10 万の位置を含む単一のテスト ケースであっても、配列を繰り返し検索したり、多くの可能な選択肢をシミュレートしたりする必要はありません。 線形時間に近い解決策が必要です。 

いくつかのケースでは、簡単に誤って処理されてしまいます。 すべての位置がすでに正しい場合、答えは操作ゼロです。 例えば：```
A = [5, 7]
B = [5, 7]
```正しい出力は空のシーケンスです。 サイクルのヘルパー操作を常に作成するソリューションは、ここでは間違っています。 

より微妙なケースは、閉じたサイクルです。```
A = [1, 2]
B = [2, 1]
```答えは 2 つの操作ではあり得ません。 最初の位置を次のように変更します`2`違法であるため`2`はまだ存在します。 一時的な値が必要なため、最小操作は 3 回です。 

もう 1 つの重要なケースはチェーンです。```
A = [1, 2, 3]
B = [2, 3, 4]
```正しい最小値は 3 回の操作です。 最後の位置は次のようになります。`4`まず、解放する`3`、その後、前の位置は次のようになります。`3`、そして最終的に最初の位置になることができます`2`。 このチェーンを逆の順序で処理すると失敗します。 

## アプローチ

 直接的なアプローチでは、既に最終値に変更できる位置を繰り返し見つけて、その操作を実行します。 そのような位置が存在しない場合は、一時的な値を検索して依存関係を解消することができます。 すべての操作は値を永続的に配置するか、将来の操作のための余地を作成するため、この考えは正しいです。 

問題は、単純な実装では利用可能なポジションを検索し続けることです。 最悪の場合、長さの長い依存関係チェーンが発生する`n`アレイのほぼ全体を何度も強制的にスキャンすることができます。 と`n = 100000`、これは近づくことができます`O(n^2)`許容範囲をはるかに超えた作業です。 

重要な観察は、間違った位置が依存関係のグラフを形成しているということです。 それぞれの間違った位置には、現在の値から必要な値までのエッジがあります。 両方の配列のすべての値は一意であるため、すべての値には最大 1 つの出力エッジと最大 1 つの入力エッジがあります。 すべてのコンポーネントはパスまたはサイクルのいずれかです。 

パスには、別の間違った位置で現在必要とされていないターゲット値の終点があります。 このようなコンポーネントを最後から逆方向に解決できます。 サイクルには自由な値がないため、サイクルを解除するには追加の一時値が 1 つ必要です。 すべての間違った位置には少なくとも 1 つの操作が必要であり、すべてのサイクルには正確に 1 つの追加操作が必要であるため、この構造は最適です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. のすべての値からマッピングを構築します。`A`その位置に。 あらゆるポジションについて、`A[i]`とは異なります`B[i]`、現在保持しているポジションへの依存関係を作成します`B[i]`その立場も間違っているなら。 

この依存関係グラフは、どの値が相互にブロックするかを正確に説明します。 
2. すべての間違った位置の入力次数を計算します。 入力次数が 0 の位置はチェーンの開始点です。 

これらは現在必要な値が欠落しているコンポーネントであるため、一時的な値は必要ありません。 
3. チェーンの開始ごとに、依存関係ポインターに従い、位置を順番に保存します。 チェーンに沿って逆の順序で操作を出力します。 

チェーンの最後の要素は、すぐに変更できる唯一の要素です。 以前の各操作は、必要な値が解放された後に可能になります。 
4. チェーンを処理した後、残っている未訪問の間違った位置はすべてサイクルに属します。 

初期配列に存在しない値を一時的な値として選択します。 サイクルの場合、最初の位置を一時的な値に移動し、他のすべての値を最終位置に回転させてから、一時的な値を残りの最終位置に移動します。 
5. これらの手順で作成されたすべてのオペレーションを出力します。 

機能する理由: すべての間違った位置は少なくとも 1 回は変更されるため、どの解決策もベースとして間違った位置の数よりも少ない数を使用することはできません。 チェーンには自由端が含まれているため、位置ごとに 1 回の操作で正確に解決できます。 すべてのターゲット値がサイクル内で占有されるため、新しい値を導入しない限りサイクルを解決することはできません。 このアルゴリズムは、そのようなサイクルごとに 1 つの追加操作を正確に追加し、不必要な変更を作成しないため、操作の数は最小限に抑えられます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans_all = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        pos = {x: i for i, x in enumerate(a)}

        wrong = [False] * n
        for i in range(n):
            if a[i] != b[i]:
                wrong[i] = True

        nxt = [-1] * n
        indeg = [0] * n

        for i in range(n):
            if wrong[i] and b[i] in pos and wrong[pos[b[i]]]:
                nxt[i] = pos[b[i]]
                indeg[nxt[i]] += 1

        ops = []
        visited = [False] * n

        for i in range(n):
            if wrong[i] and indeg[i] == 0:
                cur = i
                path = []
                while cur != -1 and not visited[cur]:
                    visited[cur] = True
                    path.append(cur)
                    cur = nxt[cur]

                for x in reversed(path):
                    ops.append((x + 1, b[x]))

        temp = 1000000000
        used = set(a)
        while temp in used:
            temp -= 1

        for i in range(n):
            if wrong[i] and not visited[i]:
                cycle = []
                cur = i
                while not visited[cur]:
                    visited[cur] = True
                    cycle.append(cur)
                    cur = nxt[cur]

                ops.append((cycle[0] + 1, temp))

                for j in range(len(cycle) - 1, 0, -1):
                    ops.append((cycle[j] + 1, a[cycle[j - 1]]))

                ops.append((cycle[0] + 1, b[cycle[0]]))

        ans_all.append(str(len(ops)))
        for x, y in ops:
            ans_all.append(f"{x} {y}")

    sys.stdout.write("\n".join(ans_all))

if __name__ == "__main__":
    solve()
```辞書`pos`任意の値の所有者に一定時間のアクセスを与えます。 依存関係配列`nxt`正しい位置にはすでに最終値が含まれており、移動する必要がないため、間違った位置の間でのみ構築されます。 

最初のトラバースはパスを処理します。 逆の順序は重要な詳細です。最後の位置を変更すると、前の位置で必要とされた値が解放されます。 

サイクル処理では、元のセット以外の 1 つの一時的な値が使用されます。 最初の移動により、サイクルの開始値が配列から削除され、ローテーションが有効になります。 最後の移動により、一時的な値の保持者が目的地に復元されます。 

実装内のすべてのインデックスは、回答に格納される場合にのみ、0 ベースから 1 ベースに変換されます。 依存関係構造がすでに変換全体をキャプチャしているため、アルゴリズムは実際の配列を変更する必要はありません。 

## 実用的な例

 対象:```
A = [1, 2]
B = [2, 1]
```依存関係サイクルは次のとおりです。 

| ステップ | 現在のコンポーネント | 操作 |
 | --- | --- | --- |
 | 1 | 1 -> 2、2 -> 1 | 位置 1 は一時的になります |
 | 2 | 値 1 は無料です | 位置 2 が 1 になります |
 | 3 | 一時的に元の 1 を保持します。 位置 1 は 2 になります |

 空きエンドポイントがないため、追加の操作が表示されます。 トレースにより、サイクル規則が確認されます。 

のために：```
A = [1, 2, 3]
B = [2, 3, 4]
```依存関係チェーンは次のとおりです。 

| ステップ | 処理された位置 | 操作 |
 | --- | --- | --- |
 | 1 | 位置 3 | 3 が 4 になります |
 | 2 | 位置 2 | 2 が 3 になります |
 | 3 | 位置 1 | 1 が 2 になる |

 トレースは、パスが逆方向に処理される理由を示します。 各操作により、次の位置に必要な値が作成されます。

 ## 特殊なケース

 すでに解決されている配列の場合、次のようになります。`A=[5,7]`そして`B=[5,7]`、すべての位置が正しいとマークされています。 グラフのエッジは作成されず、答えは空のままになります。 

サイクルのために`A=[1,2]`、`B=[2,1]`、両方の位置に入力エッジと出力エッジがあるため、チェーン開始は存在しません。 残りのコンポーネントはサイクルとして検出され、一時的な操作を 1 つだけ受け取ります。 

チェーン用`A=[1,2,3]`、`B=[2,3,4]`、最後のポジションには入ってくるエッジがありません。`4`は存在しません。 それがチェーンの開始点となり、収集されたパスを逆にすることで唯一の正当な操作順序が生成されます。 

を含む配列など、一時的な候補値がすでに存在する場合`1000000000`の場合、実装は未使用の整数が見つかるまで候補を減らします。 これにより、一時的な移動が合法に保たれます。
