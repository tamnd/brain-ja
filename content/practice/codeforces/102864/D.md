 # 問題の理解

 すべての頂点に 1 つの値が割り当てられたツリーがあります。 指定された 2 つの頂点 p と q について、それらの間の一意のパス上のすべての頂点を調べ、割り当てられたすべての値を掛け合わせて、その積のオイラーの合計関数を計算する必要があります。 積は非常に大きくなる可能性があるため、998244353 を法とする結果のみが必要です。 

重要なのは、製品自体は必要ないということです。 数値が素因数分解として記述されている場合、オイラー関数は出現する素数とその合計指数にのみ依存します。 素因数分解の場合

 [
 x=\prod p_i^{e_i}
 ]

 私たちは持っています

 [
 \phi(x)=\prod p_i^{e_i-1}(p_i-1)。 
]

 頂点の数は最大 100,000 です。多くのパスを通過したり、高価な方法で値を繰り返し因数分解したりするソリューションは、2 秒の制限に収まりません。 頂点の数が線形に近い解決策が必要です。 各色は最大 1000000 であるため、考えられるすべての素因数の前処理が可能です。 

パスにはすべての頂点を含めることができるため、処理する必要がある情報の量も O(n) です。 有益な観察は、クエリが 1 つだけであるということです。 重光分解や重心分解などの重木アルゴリズムは必要ありません。 

いくつかの特殊なケースでは、単純な実装が壊れる可能性があります。 パスに頂点が 1 つだけ含まれている場合、答えはその単一色の合計になります。 例えば：```
1 1 1
1
```積は 1 で、答えは 1 です。すべての素数寄与が p-1 の係数を持つと仮定する式では、誤ってゼロが生成されます。 

もう 1 つの問題は、素因数の繰り返しです。 考慮する：```
2 1 2
4 4
1 2
```パス積は 16、つまり (2^4) なので、答えは (2^3(2-1)=8) になります。 素数が出現するかどうかのみを記録し、その指数を無視するアプローチでは、間違った結果が計算されます。 

3 番目のケースは、異なる頂点が同じ素数に寄与する場合です。 例えば：```
3 1 3
6 10 15
1 2
2 3
```積は 900、つまり (2^2 3^2 5^2) で、答えは (2\cdot3\cdot5=30) となります。 オイラー関数は非素数の乗算ではないため、ノードごとに因数を個別にカウントし、個々の合計を乗算すると失敗します。 

## アプローチ

 直接的なアプローチは、まず p から q までのパス上の頂点を見つけ、それらの色を乗算してから合計を計算することです。 パスには 100,000 の頂点を含めることができ、色は 1000,000 にすることができるため、プロダクト自体は数十万の桁を持つことができます。 整数として保存することは不可能です。 

ブルート フォースのより良いバージョンでは、積が係数カウントとして保持されます。 各色を因数分解し、パス上に現れるすべての素数の指数を加算できます。 最終的な答えはこれらの合計指数にのみ依存するため、これで十分です。 

残りの問題は、多くの数値を素早く因数分解する方法です。 各色ごとに試行分割すると遅すぎます。 最大色は 1000000 のみであるため、ふるい法を使用して最小の素因数テーブルを構築できます。 その後、各因数分解により、現在の数値の最小の素因数が繰り返し削除されます。 

ツリーへのクエリは 1 回だけなので、パスの検索も簡単です。 p からの深さ優先検索では、q に到達するまですべての頂点の親を保存できます。 親ポインターをたどると正確なパスが再構築されます。 ツリー構造により、より高度なパス クエリ技術が不要になります。 

答えが 1 つのパスのノードにのみ依存するため、総当たりのアイデアが機能します。 巨大な産物を直接表現しようとすると失敗します。 素数指数で十分であるという重要な観察により、タスク全体がパス回復と高速因子カウントに減らされます。

 | 最適 | O(n + max(c) log log max(c) + 合計因子数) | O(n + 最大(c)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 1000000 までのすべての数値に対して最小の素因数配列を構築します。これにより、試行除算を繰り返すことなく、すべての色の値を素数に分解できます。 
2. p から DFS を実行し、各ノードの親を保存します。 q が見つかったら停止します。 ツリーには 2 つの頂点間に単純なパスが 1 つしかないため、q から p に戻る親チェーンはまさに必要なパスです。 
3. 復元されたパスをたどります。 すべての頂点カラーについて、最小の素因数テーブルを繰り返し使用して素因数を抽出し、その指数を周波数マップに追加します。 
4. 答えを 1 から始めます。合計指数 e を持つすべての素数について、答えに (p^{e-1}(p-1)) モジュロ 998244353 を掛けます。これにより、オイラーの公式が完全なパス積に直接適用されます。 

なぜ効果があるのか:

 ツリー内の頂点の各ペアには正確に 1 つのパスがあるため、パスの再構築ステップは正しいです。 因数をカウントするステップは正しいです。数値の乗算により素指数が加算されるため、すべての頂点からの指数を合計すると、パス積全体の因数分解が得られます。 最後の乗算では、オイラーのトーティエント関数の定義がその因数分解に適用されるため、すべての素数は結合された指数とともに 1 回だけ寄与します。 

## Python ソリューション```python
import sys
from collections import defaultdict

input = sys.stdin.readline

MOD = 998244353
MAXC = 1000000

def solve():
    n, p, q = map(int, input().split())
    colors = list(map(int, input().split()))

    graph = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        graph[u].append(v)
        graph[v].append(u)

    spf = list(range(MAXC + 1))
    for i in range(2, int(MAXC ** 0.5) + 1):
        if spf[i] == i:
            for j in range(i * i, MAXC + 1, i):
                if spf[j] == j:
                    spf[j] = i

    parent = [-2] * n
    parent[p - 1] = -1
    stack = [p - 1]

    while stack:
        u = stack.pop()
        if u == q - 1:
            break
        for v in graph[u]:
            if parent[v] == -2:
                parent[v] = u
                stack.append(v)

    cnt = defaultdict(int)
    cur = q - 1
    while cur != -1:
        x = colors[cur]
        while x > 1:
            prime = spf[x]
            cnt[prime] += 1
            x //= prime
        cur = parent[cur]

    ans = 1
    for prime, exp in cnt.items():
        ans = ans * pow(prime, exp - 1, MOD) % MOD
        ans = ans * (prime - 1) % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```ふるいは最小の素因数テーブルを作成します。 課題`spf[x] = x`では、最初にすべての数値が素数として扱われ、次に合成数値が発見された最小の約数によって更新されます。 

DFS には深さ情報やサブツリー データは必要ありません。 クエリでは 1 つのパスが要求されるため、先行ファイルのみが記録されます。 検索後、q から`parent`すべてのパスの頂点を 1 回だけ訪問します。 

因子カウントループは、繰り返される因子を注意深くカウントします。 たとえば、色が 8 の場合、ループは 2 を 1 回だけの出現として扱うのではなく、3 回抽出します。 

最後のループでは、合計の公式を直接適用します。 Python の整数はオーバーフローしませんが、値を小さく効率的に保つために、各演算の後にモジュラー乗算が引き続き使用されます。

 ## 特殊なケース

 単一の頂点パスの場合、DFS はターゲットをすぐに見つけ、親チェーンにはその頂点のみが含まれます。 色が 1 の場合、因子カウンターは空のままであるため、答えは 1 のままで、(\phi(1)) と一致します。 

2 つの色が 4 に等しいパスなど、素数べき乗が繰り返される場合、アルゴリズムは (\phi(4)\times\phi(4)) を計算しません。 代わりに、結合因数分解 (2^4) を作成し、必要な演算である (\phi(16)=8) を計算します。 

同じ素数がいくつかの異なる色で表示されるパスの場合、周波数マップは最終的な式が適用される前にそれらの寄与をマージします。 これにより、オイラー関数が任意の因数に対して乗算的であると仮定するというよくある間違いを回避できます。
