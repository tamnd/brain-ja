 ## 解決策
 ## 問題の理解

 タスクは、模擬酒場の戦いの結果を予測することです。 各プレイヤーは最大 7 つのミニオンの列を所有します。 戦闘は、各列の左側から右側への交互の攻撃で構成されます。 攻撃者はそのプレイヤーの攻撃サイクルの現在の位置によって選択されますが、ターゲットはすべての生きている敵ミニオンの中からランダムです。 

唯一のランダム性は、特定の擬似ランダム ジェネレーターによって制御されます。 すべての戦闘の前に誰が最初に攻撃するかを決定し、すべての攻撃の前にどの敵のミニオンが攻撃されるかを決定します。 ボブには勝者そのものは必要なく、ちょうど 10,000 回のシミュレーションを実行した後のアイアンヘッドの勝利数だけが必要です。 

考えられる 4 つのミニオンは、機械の卵、機械のドラゴン、機械の見習い、およびカドガーです。 卵は死ぬとドラゴンを生み出します。 見習いたちは、最初に死んだ2人の友好的な機械の手先を覚えており、死後にそれらを再現します。 カドガーは味方召喚を2倍にする永続的なオーラであり、複数のカドガーを使用すると効果が倍増します。 

入力には最初のランダム シードが含まれており、その後に 2 人のプレイヤーの左から右のミニオン リストが続きます。 出力は、対戦相手がミニオンを持っていないのに、アイアンヘッドがまだミニオンを持っているシミュレーションの数です。 

基板サイズの制限が、シミュレーションが実用的である主な理由です。 各陣営は常に 7 つのミニオンしか持てないため、戦闘状態は小規模です。 効果により多くの召喚を作成できますが、ボードキャップにより余分な召喚はすぐに削除されます。 ランダム ジェネレーターがすべての選択肢を修正するため、1 つの戦闘を実行する際に可能性を探索する必要はありません。 したがって、総作業量は、考えられる戦闘状態の数ではなく、10,000 のシミュレーションによって制限されます。 

難しいのはシミュレーションの数ではなく、ルールを忠実に再現することです。 よくある間違いは、死亡するたびにインデックスによって次の攻撃者を決定することです。 実際のルールは最後の攻撃者に基づいています。ミニオンが攻撃した後、次の味方の攻撃は現在の循環順序でその右側のミニオンから始まります。 もう 1 つのよくある間違いは、新しい召喚がカドガーをトリガーする可能性があり、すぐに挿入する必要があることを考慮せずに、断末魔を 1 つずつ解決することです。 

たとえば、入力が次のようになっているとします。```
1
1 0
1 1
```卵が死ぬと再び攻撃することはできません。 不用意に実装すると、元のインデックスが保持されたまま、存在しないミニオンが動作し、ランダムなシーケンスと最終的な答えが変更される可能性があります。 

別の例は次のとおりです。```
1
2 0 3
2 0 0
```見習いが死亡すると、最も早く死亡した味方の機械的ミニオンを召喚しなければなりません。 卵が 1 つだけ早く死んだ場合、ドラゴンは 1 つだけ作成されます。 常に 2 つの記憶されたミニオンを期待する実装では、追加のユニットが作成され、別の戦闘が生成されます。 

## アプローチ

 直接的な解決策は、すべての戦闘を説明どおりに正確にシミュレートすることです。 強引な解釈では、考えられるランダムな選択肢をすべて列挙し、考えられるすべての結果を計算します。 すべての戦闘はランダムな結果の順序によって完全に決定されるため、これは正しいですが、それは爆発的に増加します。 複数の攻撃があり、それぞれに複数のターゲットが考えられるため、考えられる分岐の数はすぐに実行可能な制限をはるかに超えてしまいます。 

有益な観察は、ステートメントがすでにランダム ソースを提供しているということです。 起こり得るすべての戦闘を予測する必要はありません。 審査員のシミュレーションと同じ順序でランダム ジェネレーターを使用するだけで済みます。 戦闘の 1 回の実行は、シードが固定された後の決定的なプロセスです。 ボードは小さいため、現在のミニオン リストを維持し、死亡効果を直接処理するだけで十分です。 

すべての分岐がシミュレートされるため、ブルート フォースは機能しますが、分岐係数が大きくなると失敗します。 裁判官が固定ジェネレーターを使用したモンテカルロ シミュレーションのみを要求しているという観察により、不可能な検索を 10,000 回の線形シミュレーションに置き換えることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 攻撃数は指数関数的に増加 | O(ミニオンの数) | 遅すぎる |
 | 最適 | O(10000 × 攻撃回数) | O(ミニオンの数) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 2 つの初期ボードを保存し、グローバル ランダム シードを初期化します。 シミュレーションが相互に影響を与えてはいけないため、各戦闘の前にボードをコピーします。 
2. すべてのシミュレーションで、モジュラス 2 でランダム ジェネレーターを呼び出し、最初のプレーヤーを選択します。 ジェネレーター シーケンスは必要なシミュレーションの一部であるため、これは他のランダム呼び出しの前に実行する必要があります。 
3. 各プレイヤーの現在の攻撃ポインタを維持します。 プレイヤーが攻撃すると、そのポインタから開始して次の生きているミニオンを見つけます。 そのミニオンが攻撃した後、円形の順序で攻撃者の後の位置にポインタを移動します。 
4. 対戦相手の現在のボード サイズに等しいモジュラスでランダム ジェネレーターを呼び出してターゲットを生成します。 両方のミニオンに同時にダメージを与えます。 体力がゼロになったミニオンをすべて除去します。 
5. 死亡を直ちに処理します。 卵の場合はドラゴンを作成します。 見習いの場合は、死亡した最初の 2 つの友好的な機械ミニオンを再現します。 現在生きているカドガーをカウントすると、すべての召喚額が倍増します。 
6. 召喚されたミニオンを正しい側から挿入します。 ボードに既に 7 体のミニオンがいる場合は、追加の召喚を無視してください。 一方の側にミニオンがなく、保留中の効果がなくなるまで攻撃サイクルを続けます。 
7. アイアンヘッドのみにミニオンが生き残っている場合は、答えに 1 を追加します。 10,000 回のシミュレーションがすべて完了するまで繰り返します。 

機能する理由: すべてのシミュレーションは、説明されている戦闘とまったく同じ状態遷移に従います。 ランダム ジェネレーターは、ゲームがランダム性を使用する 2 つの場所でのみ呼び出されるため、すべてのターゲットと最初の攻撃者が必要なシーケンスに一致します。 死亡処理は将来の見習い効果に必要な情報を保存し、ボード制限により維持された状態が実際の戦闘と同一であることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

SIMS = 10000

class Minion:
    def __init__(self, t):
        self.t = t
        if t == 0:
            self.atk, self.hp, self.mech = 0, 5, True
        elif t == 1:
            self.atk, self.hp, self.mech = 8, 8, True
        elif t == 2:
            self.atk, self.hp, self.mech = 2, 2, False
        else:
            self.atk, self.hp, self.mech = 0, 0, False

def make_board(a):
    return [Minion(x) for x in a]

def main():
    global seed
    seed = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    board_a = make_board(a[1:])
    board_b = make_board(b[1:])

    def rnd(m):
        global seed
        seed = (seed * 22695477 + 1) & 0xffffffff
        return seed % m

    def battle(x, y):
        boards = [x, y]
        dead_mechs = [[], []]
        ptr = [0, 0]

        def kadgars(side):
            return sum(1 for z in boards[side] if z.t == 3)

        def summon(side, typ, count, pos):
            count *= 2 ** kadgars(side)
            for _ in range(count):
                if len(boards[side]) < 7:
                    boards[side].insert(pos, Minion(typ))
                    pos += 1

        def remove_dead(side):
            changed = True
            while changed:
                changed = False
                i = 0
                while i < len(boards[side]):
                    if boards[side][i].hp <= 0:
                        m = boards[side].pop(i)
                        changed = True
                        if m.mech:
                            dead_mechs[side].append(m.t)
                        if m.t == 0:
                            summon(side, 1, 1, i)
                        elif m.t == 2:
                            need = dead_mechs[side][:2]
                            p = i
                            for t in need:
                                summon(side, t, 1, p)
                                p += 1
                    else:
                        i += 1

        first = rnd(2)
        turn = first

        while boards[0] and boards[1]:
            side = turn
            if not boards[side]:
                turn ^= 1
                continue

            if ptr[side] >= len(boards[side]):
                ptr[side] %= len(boards[side])

            start = ptr[side]
            while boards[side] and boards[side][ptr[side]].hp <= 0:
                ptr[side] = (ptr[side] + 1) % len(boards[side])
                if ptr[side] == start:
                    break

            if not boards[side]:
                break

            attacker = boards[side][ptr[side]]
            enemy = side ^ 1
            if not boards[enemy]:
                break

            target = rnd(len(boards[enemy]))
            defender = boards[enemy][target]

            attacker.hp -= defender.atk
            defender.hp -= attacker.atk

            old = ptr[side]
            if boards[side]:
                ptr[side] = (old + 1) % len(boards[side])

            remove_dead(side)
            remove_dead(enemy)
            turn ^= 1

        return bool(boards[0]) and not boards[1]

    ans = 0
    for _ in range(SIMS):
        if battle([Minion(z.t) for z in board_a],
                  [Minion(z.t) for z in board_b]):
            ans += 1
    print(ans)

if __name__ == "__main__":
    main()
```この実装により、戦闘が外側のシミュレーション ループから分離されます。 これにより、ある戦闘でミニオンの状態が別の戦闘に漏洩するのを防ぎます。 

ランダム関数はシードを次のようにマスクします。`0xffffffff`すべての乗算の後。 Python の整数は自動的にオーバーフローしませんが、元のジェネレーターは符号なし 32 ビット演算を使用します。 

デスハンドラーは死んだミニオンがなくなるまでボードを繰り返しスキャンします。 これが必要なのは、断末魔がすぐに別のミニオンを生成する可能性があり、同じ浄化フェーズ中に複数の効果が発生する可能性があるためです。 

攻撃ポインタは、リスト インデックスとは独立して格納されます。 攻撃後、循環順序ルールに従って次の位置から次の攻撃が開始されます。 ポインタを進めた後に死んだミニオンを削除すると、死んだ攻撃者が誤って再び攻撃することを避けることができます。

 ## 特殊なケース

 ミニオンが次のターンの前に死亡した場合、攻撃ポインタはそれをスキップする必要があります。 入力の場合:```
1
1 0
1 1
```卵は破壊されると攻撃できなくなります。 アルゴリズムはクリーンアップ中にそれを削除するため、次の攻撃者は残りの生きているミニオンから選択されます。 

以前に味方の機械ミニオンが 1 体だけ死亡した後に機械見習いが死亡した場合、その 1 体のミニオンのみを再作成する必要があります。 保存された死亡リストは機械的なミニオンが死亡したときに追加され、召喚コードは存在する最初の 2 つのエントリのみを使用します。 

複数のカドガーが生きている場合、召喚倍率は指数関数的に増加します。 この実装では、各召喚イベントの前に現在のすべてのカドガーがカウントされるため、2 つのカドガーで 1 つの卵が死亡すると、2 つではなく 4 つのドラゴンが作成されます。 

召喚がボードスロットの7つを超える場合、余分なコピーは消えます。 召喚機能は、戦闘ルールに合わせて、すべてのミニオンを挿入する前にボードのサイズをチェックします。
