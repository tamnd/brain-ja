 ## 解決策
 ## 問題の理解

 整数の配列が与えられ、非常に特殊なリソース システムを使用してそれを変更できます。 いずれかの要素の増加ごとに 1 コインのコストがかかり、いずれかの要素の減少ごとに 1 コインが与えられます。 コインゼロから始めるので、コイン数が決してマイナスにならないように、一連の操作のバランスを取る必要があります。 

目標は、ターゲット配列を直接構築することではなく、残りの要素を理想と呼ばれる特別な構成に変換できるように、どの要素を保持するかを決定することです。 理想的な配列には 2 つのプロパティがあります。すべての値が少なくとも 2 であり、任意の 2 つの異なる要素が互いに素であるということです。 

また、変換を行う前に要素を削除することもできますが、残りの要素をコイン ルールに基づいて理想的な構成に変換できるように、削除する要素をできるだけ少なくしたいと考えています。 

コイン システムが重要なのは、合計額を変えることなく要素間で価値を効果的に再分配できるからです。 すべての増分は、他の場所での前または同時の減分によって賄われる必要があるため、配列の合計は変換中に不変です。 

これにより、問題は、総和が変わらないことを考慮しながら、すべて少なくとも 2 の互いに素なペア整数にシフトできるサブセットを選択することに変わります。 

配列サイズが小さい場合、微妙なエッジケースが発生します。 要素を 1 つだけ保持する場合、gcd 条件は空虚に true となるため、少なくとも 2 に達する限り、任意の単一の値を常に理想的な値にすることができます。これは、すでに少なくとも 2 の値から開始するため常に可能です。これにより、単一要素のサブセットが常に有効になります。これにより、ペアごとの制約をあまりにも積極的に適用しようとする単純な推論が破綻することがよくあります。 

素数や連続する整数のような固定ターゲットを構築する必要があると仮定すると、別の失敗モードが現れます。 たとえば、保持されるすべての数値が個別の素数にならなければならないと考えるのは厳密すぎるため、多くの値を 2 を超える連続する整数などの同じ複合フリー構造に変換するなどの有効な変換を見逃します。 

本当の困難は、コイン保存変換の下で実際にどのような構造が達成可能であるかを特定することです。 

## アプローチ

 強引なアイデアは、配列のすべてのサブセットを試すことです。 サブセットごとに、理想的な配列に変換できるかどうかを確認します。 つまり、合計がサブセットの現在の合計と一致するように、すべて少なくとも 2 でペアごとに互いに素である値の割り当てが存在するかどうかを判断する必要があります。 コインの仕組みを使って自由に価値を移動できるため、唯一の制約は、そのようなターゲットのマルチセットが同じサイズと合計で存在するかどうかです。 

単純化して値を貪欲に割り当てることができると仮定しても、サブセットの数は指数関数的であるため、このアプローチは n が 4e5 までの時点ですぐに失敗します。 

重要な点は、gcd 制約が非常に制限的であるということです。 選択したすべての数値のペアごとの gcd を 1 にしたい場合、特に、選択した 2 つの異なる数値を除算できる素数はありません。 これは、各素因数が最終サブセットの最大 1 つの要素に出現できることを意味します。 

これは構造の再定式化につながります。選択された各数値はいくつかの素数を「要求」する必要があり、2 つの数値が素因数を共有することはできません。 合計を保持しながら値を自由に変換できるため、元の値の実際の数値的同一性は、一意に割り当てる「余裕のある」小さな素数によってのみ重要になります。 

標準的なトリックは、十分な柔軟性があれば、少なくとも 2 のすべての数値を個別の素数の積に変換できることと、コイン システムでは合計が維持される限り価値の再分配が可能であることに気づくことです。 私たちを制限するのは規模ではなく、異なるプライム「スロット」が利用できるかどうかです。

したがって、問題は、要素のそれぞれに個別の素数表現を割り当て、総和に関して実現可能性を確保できるように、要素の最大数を選択することに帰着します。 

素数は増大するため、最適なパッキング戦略は、可能な限り小さい個別の素数をできるだけ多くの要素に割り当てることです。 最小の素数は 2、3、5、7、11 などです。 k 個の最小素数を割り当てるコストはそれらの合計に近似し、これを選択した要素から得られる合計と比較します。 

したがって、問題は次のようになります。k 個の最小素数の合計が選択したサブセットの合計以下になるように最大の k を選択し、k もサブセット サイズによって制限されます。 

配列をソートし、プレフィックスの合計を計算し、最大のサブセットから順に実現可能性をチェックすることで、できるだけ多くの要素を維持しようと貪欲に試みます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | サブセットに対するブルート フォース | O(2^n · n) | O(n) | 遅すぎる |
 | プレフィックス + 素数を使用した貪欲な | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 大きい値を最初に保持することを考慮して、配列を降順に並べ替えます。 これは、素数構造を割り当てるために利用可能な合計を最大化するのに役立ちます。 
2. ソートされた配列のプレフィックスの合計を計算します。 最初の k 要素を保持する場合、各接頭辞は合計の「予算」を表します。 
3. 最初の n 個の素数とそれらの接頭辞の合計のリストを事前計算します。 これは、k 個の互いに素なスロットを割り当てるために必要な最小コストを表します。 
4. n から 1 までの考えられる k ごとに、最大の k 要素の合計が少なくとも最初の k 個の素数の合計であるかどうかを確認します。 そうであれば、k 個の要素を保持することが可能です。 
5. そのような k の最大値を返し、n からその値を引いた値を削除数として出力します。 

素数の前置和と比較する理由は、k 対の互いに素数の有効な構築には少なくとも k 個の異なる素数「単位」が必要であり、そのような k 個の単位を実現する最も安価な方法は最小の素数を使用することであるためです。 

### なぜ効果があるのか

 不変条件は、サイズ k の理想的な構成は素因数の k 個の素因数セットをエンコードする必要があり、そのような各セットには少なくとも 1 つの異なる素数によって決定される最小可能な「コスト」があるということです。 素数は gcd 構造の既約構成要素であるため、使用可能な最小の素数を割り当てると、最小合計要件が達成されます。 コイン操作では、価値の任意の再分配が可能ですが、合計額は維持されるため、実現可能性は、この最小限のプライムコストプロファイルに対する純粋な予算の比較に限定されます。 これにより、貪欲条件が k に対して当てはまる場合、有効な変換が存在し、変換が失敗した場合、値を再配置しても不十分な合計を補うことができないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def sieve_primes(n):
    limit = 200000  # enough for prefix sizes up to 2e5
    is_prime = [True] * (limit + 1)
    is_prime[0] = is_prime[1] = False
    primes = []
    for i in range(2, limit + 1):
        if is_prime[i]:
            primes.append(i)
            if len(primes) >= n:
                break
            for j in range(i * i, limit + 1, i):
                if j <= limit:
                    is_prime[j] = False
    return primes

t = int(input())
max_n = 0
tests = []
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    tests.append((n, a))
    max_n = max(max_n, n)

primes = sieve_primes(max_n)
prime_ps = [0]
for p in primes:
    prime_ps.append(prime_ps[-1] + p)

out = []

for n, a in tests:
    a.sort(reverse=True)
    pref = [0]
    for x in a:
        pref.append(pref[-1] + x)

    ans = 0
    for k in range(1, n + 1):
        if pref[k] >= prime_ps[k]:
            ans = k
    out.append(str(n - ans))

print("\n".join(out))
```コードは最初に各配列を並べ替えて、サイズ k の候補サブセットが k 個の最大の要素であると想定します。これにより、利用可能な合計が最大化されます。 プレフィックス合計配列を使用すると、その合計を一定時間で計算できます。 

次に、それを最小の素数の接頭辞の合計と比較します。これは、k 個の互いに素な数を構築するための最小要件として機能します。 ループは実行可能な最大の k を見つけます。その答えは、削除する必要がある要素の数です。 

よくある落とし穴は、配列内で実際の素数を構築しているわけではないことを忘れていることです。 gcd 分離要件の下限モデルとして素数のみを使用します。

 ## 特殊なケース

 エッジ ケースの 1 つは、すべての要素が同一で小さい場合 (2 が多数など) です。 この場合、値は個別に有効ですが、gcd 条件により、理想的な配列内にペアが共存できなくなります。 素数のプレフィックス合計が追加要素ごとに利用可能なバジェットをすぐに超え、ソリューションがほぼすべてを削除することを余儀なくされるため、アルゴリズムはこれを反映しています。 

もう 1 つのエッジ ケースは、配列に単一の要素が含まれる場合です。 サイズ 1 では gcd 制約がなくなるため、アルゴリズムでは常に k = 1 が許可されるため、削除は必要ありません。 少なくとも 2 の値は最初の素数のコストを超えるため、プレフィックスの比較は当然パスします。 

3 番目のケースは、値が大きいものの少ない場合です。 たとえ数字が巨大であっても、制限は数値的なものではなく構造的なものです。 最終的には素数コストの増加が支配的となるため、大きな値は、gcd プロパティを直接変更するためではなく、より多くの要素をサポートするのに十分な合計を増加させる場合にのみ役立ちます。
